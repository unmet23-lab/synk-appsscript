# 2026-09-09 계정별 영상 — 독립 제작본

이 entry는 이번 콘텐츠 원고의 7개 영상만 등록한다. 기존 `src/Root.tsx`, 리드크루 클립·기업 소개 영상, 공용 킷을 수정하지 않는다.

## 입력과 출력

- 문안: `docs/홍보물/계정별콘텐츠_20260909/콘텐츠원고.json`의 해당 `items[].scenes`.
- 브랜드 값: 기존 `영상/src/킷/색.ts`·`폰트.ts`를 직접 참조.
- 그림: SYNK는 현행 마케팅실행 킷의 무실땀 펠트 원본을 사용하고, 사업명의 고유색·스티치는 유지한다. 봉투·책·가위는 검수된 `_개선/*-2.5.png`를 직접 복사한다. 소개서 그림은 원본 본문을 보존하고 로고만 갱신한 `_개선/지면스냅샷/`을 쓴다. 나침반은 기존 공방 AVIF를 쓴다.
- 음악: 기존 `영상/BGM만들기.js`로 이번 전용 폴더에 만든 30초·60초 자체 연주곡. 외부 곡 발췌나 실제 방송 녹음이 아니다.
- 납품: 해당 계정 폴더의 `video.mp4`·`자막.srt`.
- 근거: `_검토/영상_*` 로그·원천 명세·자막 JSON·인코딩 프레임·검증 JSON.

## 명령

저장소 루트에서 실행한다. 묶음 프레임 제작에는 `sharp`가 필요하다. Codex 번들 Node 패키지 경로를 `NODE_PATH`로 연결하거나 현재 Node가 해석할 수 있게 준비한다.

```powershell
node 영상/계정별굽기.cjs --prepare
node 영상/계정별굽기.cjs --check
node 영상/계정별굽기.cjs --still --id 03-lab-tiktok --scene 1
node 영상/계정별굽기.cjs --render
```

- `--scene`은 0부터 센다. 정적 프레임은 해당 장면 시작 1초 뒤를 확인한다. `--second 3`으로 같은 장면의 3초 시점, 특히 문서 확대를 확인한다.
- `--render --resume`은 원고·컴포넌트·킷·렌더러·사용 자산의 원천/복사본·오디오·MP4 해시가 모두 같은 성공본만 보존한다. 원천과 준비 사본이 다르면 `--prepare`가 필요하다는 오류로 멈춘다.
- `--verify --id …`는 입력 해시가 일치하는 기존 성공 렌더 로그와 MP4만 다시 검사한다. 수정 전 MP4를 새 입력의 증거로 인증하지 못한다.
- 동시성 2로 순차 렌더한다. 다른 제작 작업과 CPU 사용을 먼저 조율한다.

## 연출 판단과 검수 경계

일반 장면은 짧은 등장과 더 짧은 퇴장을 쓰며, 소품은 자리를 잡은 뒤 멈춘다. 실제 펠트·스티치 로고를 쓰고 본문은 깨끗한 기존 서체를 유지한다. 투명 소품의 윤곽이나 그림자를 둥근 마스크로 자르지 않는다. LAB 역할 세 개는 같은 글자 크기로 다루며, 긴 몽골어 역할 목록은 원문 단어 그대로 세 줄로 배치한다.

04·06은 소개서 전체를 보여준 뒤 실제 제목·설명·실물 영역을 확대한다. 05는 원고가 지목하는 실물 영역을 확대한다. 확대는 승인 지면 PNG를 자른 창이며 새 문장이나 가상 UI를 만들지 않는다. 읽을 동안에는 정지한다. 07·09의 문안·세 칸 명칭도 원고 그대로 유지한다.

01은 별도 감상물이다. 원고의 선택에 따라 화면 문구·추가 캐릭터 동작·카메라 이동 없이 방과 곡만 남긴다. 라디오의 방송 설정을 수정하지 않는다. 일반 모션 스킬의 반복 등장·모든 정지화 확대 규칙보다 이 감상물의 목적과 기존 라디오 원칙을 우선한 예외다.

글꼴 파일 해시·자원 로딩·텍스트 안전 영역·파일 최신성·길이·코덱·오디오 트랙·음량 수치는 기계 검사다. 완성 MP4에서 추출한 프레임은 사람이 별도로 확인한다. 음량 수치 측정을 실청취나 음악적 평가로 표현하지 않는다. 본문 자막은 음성 받아쓰기가 아니라 원고에 대응하는 화면 자막이다. 01의 `[Instrumental music]`은 소리 설명이며 가사가 아니다.
