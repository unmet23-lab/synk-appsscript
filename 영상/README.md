# 영상 — Remotion 프로젝트와 공용 도구

2026-09-22에 옛 리드크루·카운트다운 대본을 현재 제작 입력에서 제외했다. 해당 원고를 자동으로 읽어 영상을 등록하던 경로는 폐기했다. 새 콘텐츠를 제작하거나 검수했다는 뜻은 아니다.

새 제작은 각 콘텐츠 프로젝트의 원문·입력 데이터·독립 entry에서 이어간다. 다른 프로젝트의 영상이나 자산을 덮어쓰지 않는다. 공통 작업 기준은 [AI 운영 원칙](../docs/AI_운영원칙.md)을 따른다.

## 콘텐츠별 실행

기존 독립 프로젝트의 예는 다음과 같다. 해당 프로젝트의 실제 원문·자산·입력값을 확인하고 필요한 entry만 연다.

| 프로젝트 | 입구 | 자료 |
|---|---|---|
| yuhobuilds 제작여정 1편 | `src/yuhoJourney01/entry.tsx` | [프로젝트 안내](src/yuhoJourney01/README.md), `types.ts`, 실제 음성·타이밍 입력 |
| SHIFT 제작 과정 | `src/shiftProcess20260921/entry.tsx` | 같은 폴더의 `Film.tsx`, `timing.json`, `Cover.tsx` |

`영상` 폴더에서 실행하는 예:

```bash
npx remotion studio src/shiftProcess20260921/entry.tsx
npx remotion compositions src/shiftProcess20260921/entry.tsx
```

렌더할 때는 프로젝트 entry와 그 entry가 등록한 컴포지션 ID를 직접 지정하고, 출력 경로와 필요한 props는 그 프로젝트의 제작 자료를 따른다. 기본 `굽기.js`는 `src/index.ts`만 대상으로 하므로 독립 프로젝트의 렌더를 대신하지 않는다.

## 기본 컴포지션과 공용 도구

`src/Root.tsx`에는 기존 `fb-first-teaser`, `logo-check`, `font-check-loaded`, `font-check-bare`를 보존했다. 이 목록에 남아 있다는 사실은 콘텐츠 승인이나 발행 완료를 뜻하지 않는다.

저장소 루트에서 기본 목록을 확인한다:

```bash
node 영상/굽기.js --목록
```

기본 컴포지션의 기존 실행 방식은 `node 영상/굽기.js <컴포지션ID> [출력파일명]`이다. 이 경로는 공용 소리표·자산을 준비한 뒤 발행검사, 렌더 결과 확인, MP4 소리 크기 보정과 소스 해시 기록을 수행한다. 빈 목록 준비는 콘텐츠 검사가 아니다.

| 위치 | 역할 |
|---|---|
| `src/킷/` | 승인된 색·폰트·소리를 Remotion에서 사용 |
| `src/클립/` | 기존 공용 컴포넌트·타입·템플릿. 옛 대본의 자동 등록은 제거됨 |
| `src/시험/` | 폰트·로고 표시 확인 |
| `자산모으기.js` | 승인 자산을 `public/`에 복사 |
| `소리어휘.js` | 공용 소리표의 원본과 생성 함수 |
| `굽기.js`, `프레임뽑기.js`, `마스터.js` | 기본 컴포지션 렌더·프레임 확인·소리 크기 보정 |
| `public/`, `out/`, `node_modules/` | 자산 사본·로컬 출력·설치된 의존성. git 제외 |

색·서체·마스코트의 원본 위치는 [DESIGN](../DESIGN.md)에서 확인한다. 원본을 고친 경우 해당 프로젝트가 쓰는 자산 사본도 확인한다. 렌더 종료 코드와 파일 생성만으로 서체·자막·구도·소리가 맞는지 알 수 없으므로, 완성 파일과 실제 프레임을 확인한다. 몽골어를 포함하는 콘텐츠에서는 Өө·Үү 등 해당 글자와 번역도 확인한다.

## 폐기된 경로

- `clip-*`, `count-*`와 그 표지는 기본 목록에서 제거했다. `굽기.js`에서 이 ID나 `--전량`, `--가이드`, `--준비끝`을 사용하면 자산 생성·검사·렌더 전에 종료 코드 2로 중단한다.
- `대본읽기.js`는 옛 Markdown 원고를 읽지 않는다. 기본 명령과 옛 `--검사` 명령은 폐기 안내 후 종료 코드 2로 끝나며, 콘텐츠 검사·생성을 수행하지 않는다.
- `src/클립/생성/대본클립들.ts`와 `카운트다운들.ts`는 기존 도구의 타입 호환을 위해 빈 배열로만 유지한다. `Root.tsx`는 이 목록을 가져오지 않으므로, 오래된 생성물이 남아 있어도 기본 컴포지션으로 등록되지 않는다.

호환 파일을 준비하거나 빈 상태를 확인할 때만 아래 명령을 사용한다. 성공은 빈 목록 유지보수 결과이며 콘텐츠나 렌더의 검증 결과가 아니다.

```bash
node 영상/대본읽기.js --빈목록
node 영상/대본읽기.js --빈목록 --검사
```

기존 영상 출력, 새 프로젝트, 공용 템플릿과 승인 자산은 이번 원고 초기화에서 삭제하지 않았다. 이전 출력이 남아 있어도 새 콘텐츠로 다시 제작한 결과로 취급하지 않는다.
