# Atlas 순간 맞춤 — 콘텐츠가 그 사람에 맞춰 움직이게 하는 방법

2026-10-02 · Claude 해답 · 격리 작업본 `SYNK-worktrees/atlas-live-20261002`(가지 `claude/atlas-live-20261002`)에서 구현·시험·실제 Chrome 검증을 하고, 같은 날 GPT 해답과 대조한 뒤 메인 작업본에 합쳤다(커밋하지 않음, §8·§9). 운영 배포와 실제 사람에게 나타난 효과는 아직이다.

## 0. 요청과 한 줄 답

사용자 요청: 엔진 8종을 모두 읽고 지금 회사(한국어 교육 기업이 아니라 **개인화 엔진 기업**)에 맞게 최신인지 점검하고, 발전까지 자율로 진행한다. 20~60대 누구나 게임·학습·공부·상담에서 Atlas를 쓰면 확실히 도움이 되어야 한다. 지금은 설계만 있고 콘텐츠가 사람에 맞춰 실제로 움직이지 않으니, 그 방법을 찾아 모든 콘텐츠에 붙인다. 같은 질문을 받은 GPT와 다른, Claude 나름의 해답을 적용한다.

**한 줄 답.** 콘텐츠는 바꿀 수 있는 것(속도·종류·도움)을 **쉬운 것부터 어려운 것 순서의 손잡이**로 선언하고, Atlas는 **응답 하나마다 그 사람에게 맞게 손잡이 하나를 한 칸씩** 돌린다. 판과 판 사이에서 "다음에 무엇을"만 고르던 엔진에, 판 안에서 "지금 얼마나"를 맞추는 층을 더했다.

| 시간 축 | 무엇을 맞추나 | 담당 |
|---|---|---|
| 순간(응답 하나) | 속도·보기 수·문항 난도·판정 폭·도움 시점 | Core `flow.js`, Temper `temper-flow.js`, Vellum `vellum-flow.js` **(이번에 구현)** |
| 회차(한 판) | 무엇을 연습할지, 오늘 컨디션, 다음에 물어볼 한 가지 | Core `learning.js`(기존)·`ask.js`(이번), 허브의 오늘 컨디션(이번) |
| 생애(여러 날) | 지난번에 맞춘 데서 이어 하기, 오래 쉬다 오면 가볍게, 다른 게임에서 혼자 해낸 기록으로 시작점 정하기 | Trail 기록(기존) + 콘텐츠별 순간 맞춤 기억(이번) |

## 1. 진단 — 왜 지금은 콘텐츠가 움직이지 않았나

1. **판 사이에서만 골랐다.** `learning.js`는 다음 문항·다음 코스를 고르는 추천기다. 판 안의 값은 모두 고정이었다. 주문 폭주는 누구에게나 손님 42초 대기·10초 간격·최대 3명, 말의 리듬은 고른 난이도의 판정 폭 그대로였다. 처음 하는 사람과 익숙한 사람이 같은 판을 받았다.
2. **콘텐츠가 엔진에 "무엇을 바꿔도 되는지" 알릴 계약이 없었다.** `engine.js`의 조절 항목(levers)은 있었지만 편지 연습 하나만 등록했고, 그것도 판 시작 때 한 번 정했다.
3. **엔진이 한국어 듣기·읽기에 묶여 있었다.** `learning.js`와 `trail.js`가 `listening|reading`만 받았고 Strata 마디 종류도 언어용뿐이었다. 상담·업무·생활 같은 다른 분야 콘텐츠는 엔진을 쓸 수 없었다.
4. **설계만 있고 구현이 없었다.** [아틀라스 설계 §11](아틀라스_설계.md#11-단계와-현재-상태)의 작업 난이도(§5-2), 묻기(§5-1), 도움 줄이기(§5-4), 오늘 컨디션(§8-3), 시뮬레이션·안전장치(§7-1·7-2)가 모두 "미착수"였다.
5. **사람마다 다른 기준이 하나로 고정돼 있었다.** "막힘"은 누구에게나 40초였다. 천천히 꼼꼼히 읽는 사람은 일찍 끼어들고, 빠른 사람은 늦게 도움을 받는다.

## 2. 엔진 8종 점검 — 지금 회사에 맞는가

같은 날 앞선 다른 작업이 8종의 코드 결함(세션 주체 변조, 같은 문항 계열 반복 추천, 제외 근거 집계 등)을 고쳤다([엔진 상향 설계 §0-4](엔진8종_상향설계_v3.md#engine-review-20261002)). 이 표는 그 위에서 **지금 회사(개인화 엔진 기업)와 목표(누구나, 어떤 콘텐츠든, 판 안에서 맞춤)에 맞는가**를 본다.

| 엔진 | 지금 실제 코드가 하는 일 | 지금 회사 기준으로 오래되었거나 맞지 않은 점 | 이번에 한 일 | 남은 일 |
|---|---|---|---|---|

여덟 엔진 모두 "학원·학생·강사·몽골"을 기본 대상으로 쓴 문장이 설계 곳곳에 남아 있다. 회사 정체성은 철학 정본 v3.0(2026-10-02, 다른 세션)에서 "개인화 엔진 기업"으로 바뀌었고, 엔진 문서는 이 문서와 [엔진 상향 설계](엔진8종_상향설계_v3.md)·[아틀라스 설계](아틀라스_설계.md)의 해당 절에서 그 방향을 가리키도록 고쳤다. 과거 학원 운영용 U·D 항목은 LAB 학원 맥락의 계약으로 그대로 둔다.

## 3. 해답 — 순간 맞춤 계약

### 3-1. 콘텐츠가 선언하는 것

```js
// 주문 폭주 점심 러시 (experiences/order-rush/learning.mjs)
export const FLOW_RUSH = { id: 'order-rush.rush', version: 1, target: 0.75,
  items: { levels: [1, 2, 3], weight: 2 },             // 한 잔 기본 → 조건 있는 주문 → 두 잔 주문
  knobs: [
    { id: 'patience',   kind: 'pace', label: '손님이 기다리는 시간', values: [60, 54, 48, 42, 36, 30], start: 3 },
    { id: 'spawnEvery', kind: 'pace', label: '손님이 오는 간격',     values: [15, 13, 11, 10, 8, 7],  start: 3 },
    { id: 'queueMax',   kind: 'pace', label: '한 번에 기다리는 손님', values: [2, 3, 4], start: 1, weight: 1.5 }] };
```

- 값은 **쉬운 것부터** 적는다. `start`가 콘텐츠의 원래 값이다. 처음 오는 사람은 정확히 여기서 시작한다.
- `kind`: `content`(무엇을 묻나), `pace`(시간 압박), `support`(도움). `follows: 'declared'`는 본인이 고른 값만 따른다(글자 크기·움직임).
- `target`은 "조금 어렵지만 해낼 수 있는" 성공 정도다(기본 0.75). 연습 위주는 0.8, 도전 위주는 0.7처럼 콘텐츠가 정한다.

### 3-2. 엔진이 하는 일

- **두 감당력을 따로 본다.** 내용을 얼마나 감당하는지와 시간 압박을 얼마나 감당하는지를 따로 추정한다. 시간이 모자라 놓친 것(시간 초과·제한 시간 끝에 겨우 맞힘)과 내용이 어려워 틀린 것을 구분해서, 그 쪽 손잡이를 돌린다. 그래서 나이를 묻지 않고도 "시간은 넉넉히, 내용은 어렵게"(천천히 꼼꼼한 사람)와 "빠르게, 내용은 쉽게"(빠르지만 실수가 잦은 사람)가 갈린다.
- **응답 하나에 손잡이 하나, 한 칸.** 내려야 할 때는 바로 내리고(큰 칸부터), 올릴 때는 작은 칸부터 천천히 올린다. 올린 뒤에는 두 번 쉬고, 내린 손잡이는 두 번 안에 다시 올리지 않는다(Temper 검사). 쉼은 실제로 답한 응답으로만 센다. 건너뛰거나 소리가 안 나온 응답은 쉼이 아니다.
- **혼자 해낸 정답에서만 올린다.** 틀린 답·시간이 지난 답·도움받은 답 뒤에는 다른 쪽이 준비돼 보여도 올리지 않는다. 올렸다가 다음 답에서 바로 내려올 자리라면(한 칸이 큰 손잡이에서 추정이 겨우 넘었을 때) 올리지 않고 더 분명해질 때까지 기다린다. "성공했는데 쉬워졌다"는 일이 거의 사라졌다(§4-1).
- **연달아 혼자 해내면 한 단계 올려 본다.** 네 번 연속이면 한 칸 올리되, 그 단계에서도 목표 가까이 해낼 수 있다고 추정될 때만이다. 한 번 틀리면 바로 돌아온다(설계 §5-2의 "연달아 해내면 한 단계 올리고, 연달아 막히면 내린다").
- **도움을 받은 정답으로는 절대 올리지 않는다.** 도움을 줄이는 건 세 번 연속 혼자 해냈을 때 먼저 묻고, 받아들이면 한 칸만 바꾼다. 거절하면 14일 동안 다시 묻지 않는다(설계 §5-4).
- **건너뛰거나 기술 문제로 못 한 응답은 증거가 아니다.** 소리가 재생되지 않았거나 화면을 떠난 경우는 아무것도 바꾸지 않는다. 손님을 놓친 것은 시간 압박 신호일 뿐 언어 오답이 아니다.
- **본인이 정한 것이 늘 이긴다.** "정해진 속도"를 고르면 원래 값 그대로, 손잡이를 직접 고정하면 그 값 그대로다. 비교용 기본 회차도 원래 값으로 진행한다. 이런 판은 지난번에 맞춰 둔 자리를 지우지 않는다. 다시 맞춤으로 돌아오면 그 자리에서 이어 가고, 그 판의 답은 추정에만 반영된다.
- **이어서, 가볍게.** 콘텐츠마다 지난번에 맞춘 값을 이 기기에 남겨 다음 판에 이어 간다. 14일 넘게 쉬다 오면 한 단계 가볍게 시작하고 다시 빨리 맞춘다(쉰 날을 세거나 말하지 않는다).
- **"피곤해요"인 날은 더 어렵게 하지 않는다.** 그 판에서는 어떤 손잡이도 올리지 않고 도움 줄이기 권유도 쉰다([구현 명세 §4-9](아틀라스_구현명세.md)). 목표를 조금 높여 시작하므로 필요하면 한 칸 가볍게 연다. 시작 문장도 "오늘은 더 어렵게 하지 않을게요"처럼 지키는 약속만 말한다. 쉽게 해 달라고 고른 날은 시간 목표와 내용 목표를 같은 비율로 높인다. 같은 답이면 평소보다 시간 압박이 높아지는 일이 없다(무작위 응답 240가지로 시험).
- **다른 게임의 기록으로 시작점을 정한다.** 처음 하는 콘텐츠라도 다른 게임에서 같은 학습 항목을 도움 없이 해낸 기록이 있으면 한 단계 위에서 시작한다(Core 학습 요약을 그대로 읽음).

### 3-3. 기록과 증거의 경계

- 학습 증거(무엇을 혼자 해냈나)는 그대로 Trail이 기록한다. 순간 맞춤을 켜도 끄도 Trail의 기록이 똑같다는 것을 시험으로 고정했다(`tests/atlas-game-flow.test.js`).
- 순간 맞춤의 값은 점수·급수·실력 판정이 아니다. 화면에는 "손님이 조금 더 여유 있게 기다려요"처럼 **무엇을 바꿨는지만** 말한다.
- 엔진 입력에는 인구통계 칸이 없다. `Flow.start`는 정해진 일곱 가지 외의 입력을 받으면 거부한다.
- 각 문항을 낼 때의 설정은 결정 기록(`decision.made`의 후보 사본)에 남아 나중에 다시 볼 수 있다. 콘텐츠별 기억에는 추정값·손잡이 위치·최근 응답 시간 20개만 있다(이름·답·글 없음, 동기화 안 함, 기록 지우기에 함께 지워짐).
- 외부 AI 호출은 없다. 사용자가 늘어도 비용이 늘지 않는다.
- 기록 지우기는 다른 탭에 열려 있던 판도 되살리지 못한다. 순간 맞춤 기억은 학습 기록의 세대 값을 따라가고, 지우기 전에 시작한 판의 저장은 버린다. WORLD 계정 안에서는 열려 있는 판의 모든 호출이 계정 확인을 거친다.

### 3-4. 상담에서는 — 결과를 바꾸는 질문만

`ask.js`는 남은 질문마다 "어떤 답이 나오면 결정이 바뀌는가"를 미리 계산한다. 바뀌는 질문 중 가장 크게 바뀌는 하나만 묻고, 어떻게 답해도 같은 질문은 건너뛴다(설계 §5-1, 명세 §4-4). 결정 함수는 콘텐츠의 것을 그대로 쓴다. 실험실에서 공개 중인 [AI 컴퓨터 맞춤 추천](마케팅/맞춤도구/computer/)의 실제 계산(`rules.js`)에 붙여 확인했다. "AI와 대화·문서 + 내 컴퓨터에 AI 설치"를 고른 사람에게는 "지금 컴퓨터 유무·예산"이 추천을 바꾸지 않아 건너뛰고, 남은 질문 6개 중 4개에만 답하면 "맥 미니 · 램 16GB · SSD 1TB"가 나왔다(`experiences/atlas-lab/qa/lab-smoke.json`). Atlas 세션에는 `Ask.fromAtlas`가 가상 사건으로 `decide()`를 다시 돌려 같은 일을 한다.

### 3-5. 새 콘텐츠가 붙는 법(몇 줄)

```js
const coach = SynkLearning.createGame({ gameId: 'my-game', storage: localStorage });
const live = coach.live(MY_SPEC, { skillIds: ['ko.reading.detail'], words: MY_WORDS });   // 시작
applySettings(live.settings().values); say(live.intro().line);                       // 지난번 값·오늘 컨디션 반영
const pick = live.pick(candidates);                       // 무엇을(학습 우선순위) × 얼마나(순간 맞춤 난도)
const pid = live.present(itemOf(pick.selected));          // 설정이 결정 기록에 남는다
const out = live.answer(pid, { correct, assessable }, { pressure: usedTime / limit });   // 학습 증거 + 순간 맞춤
if (out.change) { applySettings(out.settings.values); say(out.line); }
live.end();                                               // 다음 판을 위해 저장
```

학습 항목이 없는 콘텐츠(조작 게임, 상담 화면)는 `SynkLearning.Flow.start({ spec, now })`와 `run.observe(...)`를 바로 쓴다. 막힘 기준은 `live.stuck()`, 도움 줄이기는 `live.offerLessHelp()`·`acceptLessHelp()`·`declineLessHelp()`다.

### 4-1. 가상 사람 평가(30회 평균, `node tools/flow-evaluate.js`)

후반 30번 응답 중 "그 사람이 실제로 해낼 수 있는 정도"가 목표 ±0.15 안에 있었던 비율이다. 행동으로만 설명한 가상 사람이며, 실제 사람의 학습 효과·만족의 증거가 아니다. 전체 표는 [flow-evaluate.json](엔진/순간맞춤_20261002/flow-evaluate.json).

| 가상 사람 | 점심 러시 맞춤 | 정해진 구성 | 말의 리듬 맞춤 | 정해진 구성 |
|---|---|---|---|---|
| 처음이라 천천히, 그러나 정확하게 | 98% | 0% | 99% | 0% |
| 빠르지만 실수가 잦은 | 97% | 100% | 100% | 100% |
| 이미 익숙한 | 92% | 0% | 99% | 0% |
| 하면서 빠르게 느는 | 89% | 66% | 100% | 100% |
| 내용은 알지만 시간에 쫓기는 | 98% | 0% | 100% | 0% |
| 오랜만에 다시 온 | 93% | 100% | 95% | 100% |
| 지금은 많이 어려운 | 0% | 0% | 0% | 0% |

- 정해진 구성이 맞는 사람은 한 유형뿐이다. 맞춤은 처음 값이 맞지 않는 사람에게 0%를 90% 안팎으로 바꾼다. 점심 러시에서 손님을 놓친 횟수는 "시간에 쫓기는 사람" 47.9회 → 3.7회, "천천히 정확한 사람" 30.3회 → 2.8회다.
- 처음 값이 이미 맞는 사람은 가끔 한 단계 위를 시도하는 만큼 3~7%p 손해를 본다. 시간 제한 없는 한가한 오픈(문항 3단계뿐)에서는 최대 10%p다(`order-rush.practice`, 검토 전 17%p). 대신 실력이 늘면 따라 올라간다.
- **성공했는데 되돌린 횟수**(올린 손잡이를 두 응답 안에, 성공한 답 뒤에 다시 내림. 60응답당): 점심 러시 0.33~0.97회 → 0.03~0.20회, 한가한 오픈 0.23~1.17회 → 0~0.03회. 같은 시드로 검토 전 엔진과 나란히 돌린 값이다.
- 맞바꾼 것: "하면서 빠르게 느는 사람"은 점심 러시에서 94% → 89%다. 올릴 때 더 분명한 근거를 기다리는 만큼 빠른 성장을 한두 응답 늦게 따라간다. 한가한 오픈에서는 이 사람도 97% → 99%로 올랐다.
- "지금은 많이 어려운 사람"은 가장 쉬운 설정도 어렵다(바닥 도달 60회 중 60회). 엔진이 더 쉬운 콘텐츠를 권해야 할 자리를 보여 주는 신호로 실험실에 표시하고, 주문 폭주는 결과 화면에서 한가한 오픈을 권한다.
- 모든 경우에 한 번에 한 칸만 움직였고, 도움을 받은 정답 뒤에 올린 적이 없다.

### 4-2. 독립 검토에서 나온 것과 고친 것

구현 뒤 읽기 전용 검토 에이전트에게 맡겼다. 지적은 모두 시험으로 재현한 뒤 고쳤고, 고친 것마다 결함 심기 항목을 더했다.

| 등급 | 지적 | 고친 것 |
|---|---|---|
| P1 | "피곤해요"인 날 시간 목표는 그대로이고 내용 목표만 높아져서, 같은 답에도 평일보다 손님 대기 시간이 **더 빨리** 줄었다(평일 6번째, 피곤한 날 4번째 응답). 바뀐 것이 없어도 "오늘은 손님이 천천히 와요"가 나왔다 | 피곤한 날은 그 판에서 아무것도 올리지 않고 도움 줄이기도 묻지 않는다(명세 §4-9). 쉬운 날·어려운 날은 두 목표를 같은 비율로 움직인다. 시작 문장은 지키는 약속만 말한다 |
| P2 | 순간 맞춤이 다른 문항을 고르면 화면의 추천 이유·집중 기술이 원래 1순위 문항의 것이었다 | 고른 문항으로 이유·기술·근거를 다시 계산한다 |
| P2 | "정해진 속도" 판이나 손잡이를 직접 고정한 판이 끝나면 맞춰 둔 자리가 원래 값으로 덮였다 | 그런 판은 맞춰 둔 자리를 그대로 두고 추정만 배운다. 직접 고정한 손잡이 때문에 추정이 깎이던 것도 고쳤다 |
| P3 | 건너뛴 응답도 "올린 뒤 두 번 쉬기"의 쉼으로 셌다 | 실제 답만 센다 |
| P3 | 다른 탭에서 기록을 지워도 열려 있던 판이 기억을 다시 써 넣었다 | 학습 기록의 세대 값을 따라 버린다 |
| P3 | WORLD 계정 안에서 열린 판의 메서드는 계정 확인을 건너뛰었다 | 열린 판의 모든 호출을 같은 확인으로 감쌌다 |
| P3 | 말의 리듬에서 길게 누르는 노트를 일찍 떼거나 누른 채 일시정지한 것을 판정 폭 부족으로 셌다 | 판정 폭과 관계없는 일이라 근거로 쓰지 않는다 |
| P3 | 주문 폭주에서 틀린 컵을 고치는 사이 손님이 떠난 것을 시간 압박으로 넘기지 않았다 | 시간 초과로 넘긴다(틀린 서빙은 이미 오답으로 셌으므로 두 번 세지 않는다) |
| P3 | 실험실의 "엔진이 맞추려는 성공 정도"가 실제로는 추정값을 보여 줬다 | "맞추려는 성공 정도 75% · 지금 설정에서 예상하는 성공 정도"로 나눴다 |
| P3 | 허브에서 기록을 지운 뒤 오늘 컨디션 표시가 남았다 | 지운 뒤 다시 그린다 |

검토 뒤 스스로 더한 것: 틀린 답 뒤에는 다른 쪽도 올리지 않기, 바로 되돌아올 자리로는 올리지 않기, 연속 성공의 한 칸은 목표 가까이 해낼 수 있을 때만. 세 가지 모두 같은 30회 평가로 전후를 비교해 넣었다.

## 6. 지키는 원칙

- 나이·성별·국적으로 짐작하지 않는다. 그 사람이 고른 것과 실제로 한 것만 쓴다(철학 v3.0 §1·§3·§5와 같은 선).
- 순간 맞춤과 평가를 나눈다. 바뀐 값은 점수·급수·실력 판정으로 보이거나 쓰이지 않는다.
- 언제든 끌 수 있고, 끈 것을 되살리지 않는다. 바뀔 때는 무엇을 바꿨는지만 정직하게 말한다.
- 빠진 날·못한 것을 꺼내지 않는다. 쉰 날은 세지 않는다.
- 무료로 도는 부분은 AI를 부르지 않는다.

## 9. GPT 해답과 대조

같은 요청에 GPT는 [엔진 8종 원본·소비처 검토](엔진8종_상향설계_v3.md#engine-review-20261002)와 [싱크 타운 FT10·FT51 실행 연결](../experiences/synk-town/qa/RESULTS.md)을 냈다. 그 전에 같은 흐름에서 [모든 사용자를 위한 개인화 기반](SYNK_전사용자_개인화_기반_20261002.md)과 `atlas/personalization.js`도 만들었다.

| 관점 | GPT 해답 | Claude 해답(이 문서) |
|---|---|---|
| 무엇이 사람에 맞춰 움직이나 | 마을 세계가 기억하고 반응한다. 내가 만들고 놓은 자리를 NPC가 알아보고 다음 방문의 말과 행동이 달라진다. 본인이 고른 설정(글자 크기·설명량·움직임·도움 방식·소리·시간)을 제품마다 적용한다 | 판 안의 난도·속도·도움이 응답마다 한 칸씩 움직인다. 상담은 결과를 바꾸는 질문만 묻는다 |
| 시간 축 | 방문과 방문 사이, 미리 고른 설정 | 응답 하나, 그리고 판과 판 사이 이어 하기 |
| 담당 엔진 | Trail(생활 사실·인지)·Vellum(반응 고르기)·Loom(표현·전달 확인), Core 개인화 어댑터, 8종 결함 수정 | Core(순간 맞춤·묻기)·Temper(검사·가상 사람)·Vellum(사람마다 다른 막힘·바뀐 이유 한 줄), Trail·Strata 분야 일반화 |

**겹치거나 부딪히는 곳은 없었다.** 같은 엔진 파일을 고친 부분은 GPT의 수정이 이 가지의 기준선에 이미 들어 있었고, 두 해답 모두 "생활 행동이나 맞춤 값을 학습 실력의 근거로 쓰지 않는다", "나이·성별을 입력으로 받지 않는다"는 경계를 같은 방식으로 지킨다. 합친 메인에서 두 쪽 시험이 함께 통과한다.

**서로 채워 주는 것.** GPT 해답은 엔진이 맞게 도는지(결함 수정)와 세계가 나를 기억하는 느낌을 만들었다. 이 해답은 사용자가 지적한 "콘텐츠가 판 안에서 움직이지 않는다"를 직접 해결하고, 어떤 콘텐츠든 몇 줄로 붙는 공통 계약과 안전장치를 만들었다. 둘 다 실제 사람의 효과는 아직 모른다.

**다음 고리 — 고른 설정을 순간 맞춤의 약속으로.** `personalization.js`의 표시 설정을 각 콘텐츠의 `declared`로 넘기면 두 해답이 한 흐름이 된다. 아직 두 모듈을 함께 쓰는 콘텐츠가 없어서 연결 코드는 만들지 않았다. 첫 소비처가 생길 때 아래 대응으로 붙인다.

| `personalization.js`에서 고른 것 | 순간 맞춤에서 |
|---|---|
| `support: 'step'`(단계별 도움) | `support` 손잡이를 가장 도움이 많은 칸에 고정 |
| `support: 'independent'` | `support` 손잡이를 가장 도움이 적은 칸에 고정 |
| `support: 'choose'` | 고정하지 않음(도움 줄이기는 묻고 받아들일 때만) |
| `textSize`·`motion`·`explanation` | 콘텐츠의 `follows: 'declared'` 손잡이 값으로 그대로 |
| `minutes`·`goal`·`experience`·`audio` | 회차 고르기의 몫(`experiences.js`의 시간·목표, `learning.js`의 `audioAvailable`). 순간 맞춤에는 넘기지 않음 |
