## 2. 🔴 결함 2건 — 이번 v9.82가 수리

### 2-1. 결석 신고를 보내면 아무것도 돌아오지 않는다 (P-ACK)
- 학부모가 폼 제출 → 시트에 행 → **끝**. 접수됐는지, 선생님이 아는지, 알림이 안 갈 건지 아무 표시 없음.
- v9.34 다듬기 감사에서 `[보류] P-ACK` 로 이미 지목됐던 항목 — 이번 12번 지시로 상환.
- **수리** = 학부모 행 `결석신고HTML`(DQ121) 카드: 접수 확인 ✅(10분 내)·오늘/예정/지난 구분·다음 수업일 칩·작동 3줄(몽골어 병기). 10분 스위프가 갱신하되 **내용이 바뀔 때만 기입**(자정 리셋은 기존 출퇴근 리셋과 같은 묶음이라 Glide update 순증 ≈ 0).

### 2-2. 다자녀 학부모의 결석 신고는 조용히 버려진다
- 현 폼: `student_id = User's parent_of` 자동 바인딩. parent_of가 `SYNK-001,SYNK-002`면 그 문자열이 통째로 기록됨.
- 엔진 3곳(미출석 제외 `notifyParents`·강사 브리핑 `absenceByClass`·오늘의 반)은 **정확 일치 매칭** → 전부 불발. 학부모는 "알렸다"고 믿는데 그날 "안 왔어요" 메일이 감.
- 우리 아이 탭도 **첫 자녀만** 표시(`split(',')[0]` — v9.48 설계 한계, 카드 열이 행당 1벌이라 구조적).
- **수리**: ①폼 "자녀" 필드를 **Choice**(profiles, `user_id is included in User's parent_of`, value=user_id)로 재조립 → 다자녀도 정확한 1명 선택, 외자녀는 선택지 1개 ②`preflightGlide`에 absence_notice student_id 무결성 검사 신설(쉼표 포함·미매칭 sid 경고) — 같은 사고의 회귀 장치 ③우리 아이 둘째 자녀 표시는 **미해결로 명시**(행당 카드 1벌 구조를 바꿔야 해 개원 전 우선순위 아님 — 현재 다자녀 가정 0가정이면 실피해 0, 등록 시점에 재론).

## 3. 🟡 제안 2건 (코드 이번 커밋 제외 — 유호님 판단 대기)

### 3-3. 문의 답변 루프 — "보낸 문의가 어디 갔는지"가 앱에 없다
- 현재: 학부모 제출 → 원장 아침 브리핑·주간 리포트에 뜸 → 원장이 시트에서 상태 '처리완료' → **학부모는 모름**.
- 제안(코드 0, Glide 조립만): 문의 탭을 폼 단독 → **화면(내 문의 컬렉션 + 문의 버튼)** 으로 — 컬렉션 Filter `student_id is User's parent_of`, 상태 칩(접수/처리완료) 노출. 원장이 시트 '답변' 열을 쓰면 상세에 표시(열 1개 추가 필요 시 코드 1줄).
- 판정: 개원 전 필수 아님(문의 빈도 미검증). 결석 카드 조립 때 여력 있으면 함께.

### 3-4. 주간 다이제스트 언어 — 학부모 제1언어는 몽골어다
- 유일한 정기 메일인데 본문이 한국어, 몽골어는 꼬리 요약 1줄. 다듬기 v934 백로그 #22로 이미 지목·미실행.
- 미출석 메일(v9.28)이 확립한 "몽골어 본문 + 한국어 괄호" 패턴을 다이제스트에 적용하면 됨.
- 이번 커밋에서 뺀 이유: 문안 전체가 몽골어 신규 작성이라 **원어민 검수 게이트**를 거쳐야 함(내 몽골어는 구조적 약점 — 지침 §모델 라우팅). 유호님이 승인하면 다음 트랙에서 문안 초안+검수 큐로.
