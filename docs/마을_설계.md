# SYNK TOWN · 싱크 타운 — 내 집과 우리 마을

**2026-10-01 명칭 확정:** SYNK WORLD 안에서 생활하고 주민과 소통하며 집·가게·관계·이야기를 발전시키는 마을 콘텐츠의 이름은 **SYNK TOWN**, 한국어 표기는 **싱크 타운**이다(사용자 「싱크 타운으로 하자」). 메인 화면의 학습·미니게임에서 배운 한국어를 실제 생활과 이야기에 사용하는 중심 콘텐츠다. TOPIK 1급+ 해금 조건(§1-2)과 아주 쉬운 시작·활동에 따른 발전(§6-8)을 유지한다. 개별 마을의 고유 이름은 별도로 정한다.

**2026-10-02 BM 확정:** 싱크 타운은 **일부 체험 무료 + 정액제 + 선택 상품**으로 제공한다. TOPIK 1급+는 체험·유료 이용 모두에 필요한 학습 조건이며, 본격적인 이용에는 정액 이용권이 추가로 필요하다(§1-3). 체험 범위·기간·가격·상품 구성의 구체적인 [상품 설계안](디자인/싱크타운_생활경제와_상품_설계.md)을 후속 작성했다. 상용 확정·결제 구현은 별도다. [BM 정본](BM_목록.md#synk-town-bm).

**2026-10-02 행동과 세계 변화 설계:** 플레이어의 선택이 NPC의 실제 행동·공간·후속 의뢰·다음 만남에 남도록 [상세 정본](싱크타운_행동과_세계변화_설계.md)과 [생활 사건집](디자인/싱크타운_생활사건_설계.md)을 연결했다. 아래 관계 조건은 대화 횟수 중심에서 함께한 사건 중심으로 갱신했다. 선택별 결과, 반복·소진, 저장·취소, 체감 확인은 상세 정본을 따른다. 후속 승인한 [편안한 체감의 여섯 보완](싱크타운_행동과_세계변화_설계.md#comfort-result)도 적용한다. 현재 방문의 결과 확인, 개인 배치 미리보기·되돌림, 편안한 종료·재개, 장면 사이 개인화, 성장에 따른 편의를 기존 화면에 연결한다. 설계 반영이며 실제 NPC 플레이·계정 복원·학생 효과의 완료를 뜻하지 않는다.

## 1. 만들려는 것

**2026-10-01 사용자 결정:** 마을의 생활형 콘텐츠와 NPC 소통은 메인 화면의 **TOPIK 1급+ 통과 후 해금**한다. 자세한 범위와 입장 조건은 §1-2를 따른다. 아래의 마을 플레이는 해금 이후의 경험이다.

앱을 열면 **메인 화면**이 나오고, **내 집과 우리 마을**은 거기서 따로 들어가는 곳이다(§1-1). 들어가면 **내 집** 안이다. 내가 고른 마스코트가 같이 살고, 창밖으로 지금 마을의 하늘이 보인다. 문을 열고 나가면 **우리 마을**이다. 마을에는 집이 열여섯 채 있고 그중 하나가 내 집이다. 마을에는 **주민**(할머니, 분식집 사장님, 편의점 알바생, 이장님 등)이 살고, 계절이 바뀌고 날씨가 변한다. 학습자는 주민과 한국어로 이야기하고, 부탁을 들어주고, 편지를 받으면서 주민과 가까워진다. 주민의 말은 전부 그 학습자의 눈높이에 맞추고, 그 학습자가 약한 부분을 연습할 수 있게 고른다. **이 모든 것을 혼자서 할 수 있다.** 나머지 열다섯 이웃은 함께 산다는 따뜻한 느낌을 주는 정도다.

학습자가 이곳에 머무는 이유는 기능이 아니라, 내가 없는 동안에도 시간이 흐르는 아름다운 세계여야 한다. 이곳에 산다는 느낌은 나를 아는 주민에게서 나온다.

### 1-1. 앱에서의 위치: 메인 화면이 중심이고, 마을은 따로 들어가는 곳이다 (2026-09-20 사용자 결정)

- 학습 앱으로서 이 앱의 정체성은 **「TOPIK 4급까지 재밌게 따게 해 주는 앱」**이다. 마을은 그 과정의 일부다.
- 앱을 열면 **메인 화면**이 나온다. 메인 화면은 한글을 모르는 사람부터 중급 학습자까지 **누구나 쓰는 학습의 중심**이다. 이미 준비한 기능이 모두 여기에 있다. 한글 단계, 초급 문장 모음, 매일 말하기, 교정 답장, 복습, 모의시험, 「나에 대해 아는 것」, 내 마스코트의 한마디와 하루에 하나 묻기다. 메인 화면의 구성은 따로 설계한다(§20).
- 메인 화면에 **내 집과 마을로 들어가는 입구**가 따로 있다. 앱을 쓰는 시간 전부를 마을 안에서 보내게 만들지 않는다.
- **2026-10-02 사용자 결정 — 급수별 중심 경로:** 미니게임은 TOPIK I(1~2급) 준비를 맡고([공통 학습 기준](미니게임_TOPIK_I_학습기준.md)), **3~4급은 싱크 타운이 중심 경로**다. 메인 화면에는 시험 형식 연습(모의시험·쓰기 등)을 남겨, 마을에 들어가지 않는 학습자도 3~4급 준비를 이어 갈 수 있게 한다. 09-20의 「TOPIK 4급까지의 학습 과정은 마을 없이도 끊기지 않는다」는 이 범위로 바꾼다. 싱크 타운이 체험+정액제(§1-3)라 3~4급의 중심 경로는 유료 범위에 들어가므로, 메인 시험 형식 연습 중 무엇을 무료로 둘지는 BM에서 따로 정한다(미정).
- 그래서 오늘 과제, 교정 답장, 기록 같은 **핵심 기능은 메인 화면에 둔다.** 집 안의 책상, 우편함, 액자는 같은 기능으로 들어가는 **또 하나의 입구**일 뿐이고 유일한 입구가 아니다(§3-1).
- 메인 화면과 마을은 아틀라스로 연결된다. 마을에서 자동 채점된 결과는 메인 화면에서 어떤 과제를 낼지 정하는 데 쓰인다. 메인 화면에서 익힌 것은 마을에서 드러난다(간판이 읽히고, 이모티콘이 열리고, 주민의 말도 학습자의 수준을 따라 달라진다). 한쪽만 써도 손해가 없다.
- 마을의 대사는 **아주 쉬운 단어·짧은 한 문장**에서 시작한다. 1급과 2급은 모두 초급이며, 급수 태그만으로 대사를 고르지 않는다. 실제 활동에서 확인한 단어·문형·이해와 표현에 따라 조금씩 넓힌다(§6-8). 한글 단계의 학습은 메인 화면에서 제공한다(§1-2).
- 마을 안에서는 **혼자 하는 콘텐츠가 전부 메인**이다. 열여섯 명은 함께 사는 따뜻함을 느끼는 정도로만 둔다(§13).

### 1-2. 마을 게임의 해금 조건 (2026-10-01 사용자 결정)

**메인에서 기초 학습 → TOPIK 1급+ 통과 → 마을의 생활형 콘텐츠·NPC 소통에 대한 학습 잠금 해제** 순서로 제공한다. 한국어 안내와 대화가 많은 마을에 너무 일찍 들어와 진행하지 못하는 일을 막기 위한 조건이다. 여기서 통과는 **메인 화면에 있는 앱 내부의 TOPIK 1급+ 단계 통과**를 뜻한다. 공식 TOPIK 성적표 제출이나 학원 레벨의 자기 신고로 대신하지 않는다. 통과 점수·문항·평가 방식은 해당 학습 단계에서 정하며 이 문서에서 새로 만들지 않는다. 통과 후의 무료 체험·정액 이용 범위는 §1-3을 따른다.

| 콘텐츠 | TOPIK 1급+ 통과 전 | 통과 후 |
|---|---|---|
| 메인의 한글·기초 한국어와 학습용 미니게임 | 학습 가능. 각 게임의 기존 선행 학습 조건을 따른다 | 계속 이용 가능 |
| 마을의 생활형 게임: 농사·채집·제작·가게 운영·집 꾸미기 등 | 무료 체험·유료 이용 모두 플레이 잠금 | 무료 체험에 포함된 구간 또는 확인된 정액 이용권의 범위에서 플레이 가능 |
| 마을 NPC 소통: 대화·주문·부탁·심부름·편지·관계 이야기 등 | 무료 체험·유료 이용 모두 플레이 잠금 | 무료 체험에 포함된 장면 또는 확인된 정액 이용권의 범위에서 플레이 가능 |

게임을 작은 미니게임으로 나눠도 **마을 생활·NPC 소통에 속하면 같은 조건**을 적용한다. 메인 학습용 미니게임과 메인 마스코트의 학습 안내는 이 잠금에 포함하지 않는다. 마을 안에서 같은 학습 기능을 이용하는 입구가 잠겨도 메인 화면에서는 계속 이용할 수 있다. 3~4급의 중심 경로는 마을이며, 마을에 들어가지 않는 학습자도 메인의 시험 형식 연습으로 3~4급 준비를 이어 갈 수 있다(§1-1, 2026-10-02).

**입구와 진행 설계**

- 메인의 마을 카드에는 잠금과 **「TOPIK 1급+를 통과하면 열려요」**를 표시한다. 누르면 **「TOPIK 1급+ 배우러 가기」**로 해당 학습 단계에 안내한다. 학습자의 안내 언어로도 뜻을 이해할 수 있게 준비한다.
- 통과 기록을 확인하면 같은 카드에서 **「마을 들어가기」**를 제공한다. 이미 통과한 학습자는 처음부터 열린 상태로 본다. 통과 기록은 학습자별로 보존하며, 쉬었다 오거나 복습에서 틀렸다는 이유로 다시 잠그지 않는다.
- 버튼 표시뿐 아니라 마을 입장·활동 시작·NPC 장면 시작에서 같은 조건을 확인한다. 직접 링크나 저장된 진행을 열어도 미통과 상태에서 플레이·관계 진행·생활 보상이 시작되지 않아야 한다. 확인 중이거나 본인의 통과 기록을 확인할 수 없으면 잠금을 유지하되 메인 학습은 이용할 수 있게 한다.
- 해금 후에도 짧은 문장·그림·되묻기·반복 듣기 등 초급 지원을 유지한다. 통과했다고 모든 마을 대사를 이해할 수 있다고 가정하지 않는다. 다른 사람의 통과 기록으로 내 마을이 열리지 않아야 한다.
- 2026-10-02 BM 반영: 통과 후에는 무료 체험과 정액 이용권도 확인한다(§1-3). 정액 이용권이 없다는 이유를 한국어 미통과로 표시하지 않고, 이미 확인된 학습 통과 기록을 지우지 않는다.

**현재 반영 범위:** 사용자 후속 답변 「현재는 설계에 반영하면 돼」에 따라 설계만 변경한다. 2026-10-01 확인한 SYNK-talk 주작업본과 `atlas2-talk-20260918` 작업본에는 이 메인 단계와 마을 생활·NPC의 연결 화면이 없다. 실제 통과 기록의 저장·조회 계약, 입장 검사와 플레이 검증은 새 화면·게임을 연결할 때 구현한다. 기존 공간 시안이나 옛 게임을 바꿔 앱의 해금 구현이 완료된 것으로 취급하지 않는다.

### 1-3. 무료 체험과 정액 이용권 (2026-10-02 사용자 결정)

싱크 타운의 수익 구조는 **일부 체험 무료 + 정액제 + 선택 상품**이다. 기존의 마을 전체 무료 기준을 변경하며, API 없는 생활·대화 콘텐츠도 정액 상품에 포함할 수 있다. 상품과 비용의 정본은 [BM 목록 BM-10](BM_목록.md#synk-town-bm)이다.

- **무료 체험:** TOPIK 1급+ 통과 후 첫 쉼터 네 경로와 각 첫 후속·재방문 결과를 제공하는 [구체안](디자인/싱크타운_생활경제와_상품_설계.md#products)을 작성했다. 유한한 첫 챕터이며 기간 카운트다운·네 경로 완수 의무를 두지 않는다. 출시 전 범위 검증은 별도다.
- **정액제:** 학습 통과와 별도로 확인된 이용권의 기간·범위 안에서 본격적인 마을 콘텐츠를 제공한다. 체험 이후의 유료 범위와 포함 콘텐츠를 결제 전에 알 수 있어야 한다.
- **선택 상품:** 가구·장식·마스코트 코스튬 등의 추가 구매다. 구매가 정액 이용권이나 학습 통과를 대신하지 않으며, 정액제의 기본 생활·학습을 진행하기 위한 추가 구매를 요구하지 않는다.
- **진행 판정:** 입장·활동·NPC 장면 시작과 직접 링크·진행 복원에서 학습 통과와 해당 체험·정액 권한을 함께 확인한다. 앱이 보낸 결제 주장만으로 권한을 인정하지 않는다. 조회·캐시·오프라인 확인 기한은 [상품 권한 검증안](디자인/싱크타운_생활경제와_상품_설계.md#expiry)을 따른다. 실제 API·저장·복원 구현은 별도다.
- **이용권 종료:** 학습 통과·관계·생활 성과·구매 소유 내역과 유료 이용 가능 여부를 구분한다. 이용권 종료만으로 기존 기록을 지우지 않는다. 기본 공간과 기록/소유 관리, 확정 작업 수령과 새 유료 활동 중지, 재구독 복원은 [만료 설계안](디자인/싱크타운_생활경제와_상품_설계.md#expiry)에 정했다.

이번 결정은 과금 구조에 한정한다. 무료 체험의 기간, 구독 가격·기간·갱신 방식, AI 코칭 구독과의 통합, 선택 상품 목록과 결제 UI는 아직 확정하지 않았다. 메인 학습·미니게임의 목표 급수나 캐릭터 레벨도 이번 결정으로 새로 정하지 않는다.

## 2. 지킬 원칙

- **모든 콘텐츠를 혼자서 할 수 있다.** 다른 사람이 있어야만 열리는 콘텐츠는 없다. 이웃이 아무도 오지 않는 마을도 아름답고 할 일이 있다.
- **사람끼리는 채팅하지 않는다.** 이웃과는 정해진 한국어 이모티콘, 몸짓, 정해진 한마디로만 소통한다(사용자 09-20). 직접 쓴 글이 다른 사람에게 그대로 보이는 곳을 만들지 않는다.
- 비교, 등수, 개인별 숫자, 연속 기록, 벌칙이 없다. **오지 않은 사람과 오지 않은 날이 드러나지 않는다.** 불 꺼진 집이나 「오랜만이네, 왜 안 왔어」처럼 서운함을 드러내는 표현을 만들지 않는다. 한번 쌓인 것은 줄어들지 않는다. 주민과의 관계, 읽을 수 있게 된 간판, 도감, 꾸밈이 그렇다.
- 주민은 꾸짖지 않는다. 학습자가 높임 수준에 맞지 않게 말하면 그 주민다운 말투로 다정하게 알려 준다. 틀려도 관계는 나빠지지 않는다.
- **마을은 일부 체험 무료 + 정액제 + 선택 상품으로 제공한다**(사용자 2026-10-02, §1-3). 보기 없이 내 말로 답하는 처리도 API 없이 설계하되, 무료 체험·정액 이용권의 범위에서 제공한다([대화 설계](대화_설계.md)). 주제 제한 없는 AI 대화는 별도의 AI 사용 한도 안에서 제공하며, 마을 정액제와의 통합 여부는 [BM 목록](BM_목록.md#synk-town-bm)에서 정한다.
- **기본 콘텐츠는 실행 중 AI를 호출하지 않도록 설계한다**(§16). 글과 소리는 미리 제작하고, 그중에서 선택하거나 빈칸을 채워 개인화한다. 장면 안에서 직접 답하는 기능도 이 범위에 포함한다. 주제 제한 없는 AI 대화는 구독 한도 안에서 제공한다. 직접 쓴 편지의 답장까지 API 없이 제공할지는 [대화 설계](대화_설계.md) §17의 미결정 사항이다.
- 주민은 **플레이어가 직접 알려 준 사실, 자신이 받은 물건·함께한 일, 직접 목격하거나 세계 안의 정해진 경로로 전달받은 공개 사건**만 기억한다. 비공개 대화와 학습 약점은 다른 주민에게 공유하지 않는다. 기억은 「이웃 수첩」(§7)에서 확인·제외할 수 있고, 민감한 내용(건강, 가족, 돈, 연애)과 다른 사람에 대한 이야기는 기억하지 않는다. [인지·저장 기준](싱크타운_행동과_세계변화_설계.md#state)을 따른다.
- 움직임은 작고 잔잔하게 한다. 화면이 흔들리거나 배경이 어긋나게 따라 움직이는 연출은 쓰지 않는다. 생동감은 빛, 색, 소리, 계절, 날씨로 낸다. 움직임 줄이기 설정에서는 모든 장면이 정지 그림만으로도 이해되어야 한다.
- 소리는 학습자 본인이 정한다. **마을 소리와 SYNK 음악은 따로 켜고 끈다.** 학습자가 끈 소리를 앱이 다시 켜지 않는다. 녹음 중에는 어떤 소리도 나지 않는다.
- 대사는 TOPIK 1급+ 통과 후에도 학습자의 눈높이에 맞춘 한국어로 쓴다. 입장 전의 기초 학습과 보조 언어 안내는 메인 화면에서 제공한다(§1-2 · §6-7). 발음은 평가하지 않는다(엔진 v3 D11).
- 주민은 실제 사람인 척하지 않는다. 어디까지나 이 세계 안의 주민이다. AI가 답하는 자유 대화에는 AI가 답한다는 사실을 표시한다.
- 학습자의 이름은 기기 안에서만 쓴다. 주민이 이름을 부르는 대사의 빈칸은 기기에서 채운다.

## 3. 공간의 구조

### 3-1. 내 집: 나와 마스코트의 공간

집 안의 물건 하나가 기능 하나에 해당한다. 책상, 우편함, 액자, 달력, 수첩은 **메인 화면에 있는 같은 기능으로 들어가는 또 하나의 입구**다(§1-1. 이 기능들은 메인 화면에 속한다). 집에서만 할 수 있는 것은 마스코트와 함께 사는 것, 주민이 찾아오는 것, 창문과 소리, 꾸미기, 집 안 심부름이다.

| 물건 | 하는 일 | 관련 설계 |
|---|---|---|
| 내 마스코트 | 맞이하는 인사 · 오늘 과제를 고른 이유 한 줄 · 하루에 하나 묻기 · **고르는 대화와 조립 대화**(§6) · 막혔을 때 한 번 도움을 제안하기 | 아틀라스 §5-1 · §8 · §8-5 |

| 우편함 | 교정 답장(일반 학습자에게는 「AI가 본 것」이라고 표시한다) · **주민과 마스코트의 편지**(§12) | 공개판 §5 |
| 액자 | 처음 해낸 일 · 어제의 나 · 한 달 전의 나와 지금의 나를 나란히 듣기 · 엽서 | 아틀라스 §8-6 |

꾸미기는 **정해진 위치별로 바꾸는 방식**에서 시작한다 [제안]. 벽, 바닥, 창틀, 책상, 조명, 화분, 액자처럼 정해진 위치마다 가지고 있는 것 중에서 고른다. 자유 배치는 나중에 연다. 꾸밈 아이템은 두 종류다. 하나는 상점에서 사는 것이고, 다른 하나는 **해낸 일과 깊어진 관계로만 얻는 것**이다. 뒤의 것은 팔지 않는다(§7의 주민에게 받은 선물, §14).

### 3-2. 집 밖: 대문과 마당

집 안은 나만의 공간이고, 학습 기록은 집 밖으로 나가지 않는다. 대문, 마당, 문패(별명)는 내가 꾸며서 이웃에게 보여 주는 부분이다. 집 안은 집들이(§13)로 초대한 곳만 이웃에게 보인다.

### 3-3. 마을: 장소는 배경, 주민, 상황 한국어로 이루어진다

### 3-4. 늘려 가는 순서: 집부터

사용자 09-20: 「마을보다 내 집에서 할 수 있는 컨텐츠를 딴딴하게 제대로 만들면서 하나하나 늘려가야 해.」 그래서 주민과의 소통도 **집 안에서 먼저** 시작한다. 마스코트와의 대화, 편지, 찾아오는 주민, 창밖의 방송이 그것이다. 마을 지도는 그다음이고, 장소와 주민은 한 번에 하나씩 늘린다. 버전별 범위는 §17에 있다.

## 4. 배경 — 머물 이유

### 4-1. 한국의 계절과 절기

마을의 달력은 한국의 것이다. 스물네 절기(입춘 · 경칩 · 청명 · 하지 · 처서 · 상강 · 동지 …)마다 꽃 · 시장의 먹을거리 · 주민의 옷 · 소리가 조금씩 바뀐다. 남반구의 학습자도 한국의 계절을 본다 — 「지금 한국은 가을이에요」가 매일 눈에 보인다. 날짜는 **표에 적어 둔 것만** 쓴다(음력 명절을 계산으로 지어내지 않는다 — 아틀라스 §8-7과 같은 선). 표의 해가 지나면 계절의 기본 모습으로 돈다.

### 4-2. 시간의 빛 — 내 시간 (필수)

낮과 밤은 보는 사람의 시간이다. 새벽 안개 · 아침 · 낮 · 노을 · 푸른 저녁 · 등불 켜진 밤 · 깊은 밤(마을이 잠든다). 밤에는 창마다 따뜻한 불이 들고 별과 달이 뜬다. 달의 모양은 달력을 따른다(추석에는 보름달). **마을의 시계는 보는 사람의 것이고 달력은 한국의 것이다.** 이웃과 내가 보는 시간이 달라도 서로의 화면을 보지 않으므로 어긋남이 드러나지 않는다.

### 4-3. 마을의 날씨 — 많이, 아름답게

서울의 실제 날씨를 따르지 않는다(사용자 09-20). 마을은 **자기 날씨**를 가진다.

- 날씨는 계산으로 정한다 — 마을과 한국 달력의 날짜로 씨앗을 만들고, 계절마다 다른 비율표에서 뽑는다. 인터넷 조회도 AI도 없다. **같은 마을의 열여섯은 같은 날 같은 날씨를 본다**(「오늘 우리 마을에 첫눈이 왔어요」). 하루 안에서도 두세 번 바뀐다.
- 종류를 많이 둔다 [제안]: 맑음 · 구름 · 흐림 · 안개 · 이슬비 · 비 · 소나기와 그 뒤의 무지개 · 장마(여름에 며칠 이어지는 비) · 눈 · 함박눈 · **첫눈**(그 겨울의 첫 눈은 마을의 작은 사건이다) · 진눈깨비 · 꽃비(봄에 날리는 꽃잎) · 낙엽비(가을) · 아지랑이 · 서리 내린 아침 · 눈이 쌓인 다음 날 · 비 갠 뒤의 물웅덩이 · 유난히 붉은 노을 · 별이 많은 밤 · 은하수 · 보름달.
- 흔한 날씨 · 그 계절의 날씨 · 드문 날씨로 나눈다. 드문 날씨는 「오늘은 어떤 하늘일까」를 만들지만, **놓쳤다고 알리지 않고** 다시 온다. 본 하늘은 도감에 남는다(§14).
- 날씨는 그림만 바꾸지 않는다. 주민이 있는 자리(비가 오면 평상 대신 처마 밑) · 주민의 말(「비 오는 날엔 부침개지」) · 심부름(「우산 좀 갖다줘」) · 이장님 방송 · 집 안의 분위기(창의 빗방울 · 따뜻한 조명) · 그날의 날씨 표현(「비가 그치다」 · 「눈이 쌓이다」 · 「쌀쌀하다」)이 같이 바뀐다.
- 천둥은 소리로만 부드럽게 낸다. 번쩍이는 빛을 쓰지 않는다.

### 4-4. 소리 — 따로 켜고 끈다

- 마을 소리: 기와에 떨어지는 빗소리 · 풍경 · 시장 · 개구리 · 매미 · 귀뚜라미 · 눈 밟는 소리 — 계절 · 날씨 · 시간 · 장소를 따른다.
- SYNK 음악: 회사가 권리를 가진 곡만 앱 안에 싣는다 **[사용자: 곡과 권리]**. 유튜브 방송을 앱 안에서 배경으로 트는 방식은 쓰지 않는다.
- **둘은 따로 켜고 끈다**(사용자 09-20 「각각 온오프 기능은 확실하게」). 집의 소리 상자와 마을의 평상에서 한 번에 닿는다. 설정은 기기에 남고, 끈 소리를 어떤 맞춤도 되살리지 않는다.
- **머무는 모드**: 평상(마을)이나 창가(집)에 앉으면 화면이 조용해지고 소리만 흐른다. 앱을 켜 둔 채 공부하는 배경이다. 이때는 움직임을 더 줄이고 화면을 어둡게 해 전지를 아낀다.

### 4-5. 배운 만큼 색이 드는 마을

처음의 마을은 실이 덜 놓인 자수 같다. 마을 사람들이 익힌 만큼 간판이 또렷해지고 색이 채워진다 — 한글 단계의 「간판이 읽히기 시작한다」를 마을 전체로 넓힌 것이다. **개인의 숫자는 어디에도 없고, 든 색은 빠지지 않는다.** 혼자 있는 마을도 자기가 배운 만큼 색이 든다.

### 4-6. 엽서

지금 이 빛과 날씨의 마을(또는 내 집의 창가)을 엽서 한 장으로 남긴다. 그 사람의 눈높이의 한국어 한 줄이 곁들여진다(틀에서 나온다 — 「오늘 우리 마을에 첫눈이 왔어요」). 액자에 걸리고, 밖으로 공유할 수 있다. 엽서에는 별명 · 이웃 · 학습 기록이 들어가지 않는다.

<a id="4-7-그리는-법과-무게-제안"></a>
### 4-7. 화면 구성과 자산 용량 [제안]

- 한 장면은 장소의 기본 배경, 계절별 이미지 4종, 공용 절기 소품, 시간대별 색과 조명, 공용 날씨 효과를 **겹쳐서 표시**한다. 장소·계절·시간·날씨의 모든 조합을 별도 이미지로 만들지 않는다.
- 비와 눈의 양은 기기 성능에 맞춘다. 성능이 낮으면 입자 수를 줄이고, 움직임 줄이기 설정에서는 정지된 색감과 소리만 남긴다. 앱이 백그라운드로 가면 애니메이션을 멈춘다.
- 첫 설치는 가볍게 한다. 장소의 그림은 그 장소가 열릴 때, 와이파이에서 받는다. 받은 것은 기기에 남아 오프라인에서도 열린다.
- 자산은 승인된 펠트의 결을 따르고 구운 자산만 쓴다([DESIGN](../DESIGN.md)). 구운 글자(간판)는 표준 글꼴과 대조한다(한글 단계 설계의 규칙 그대로).

## 5. 주민 — 마을에 사는 사람들

이 절은 주민 시스템의 개요다. 10개 영역·약 120개 항목의 설정서, 상황별 대사 선택, 행동 표현, 주민의 일과와 이야기, 첫 주민 세 명의 설정, 모바일 검증 계획은 [주민 설계](주민_설계.md)에 둔다. 세계명은 **싱크 월드(SYNK WORLD)**, 배경은 **100~200년 뒤의 한국**으로 정해졌다(사용자 2026-09-20, 주민 설계 §3). 마을 이름과 개별 주민의 사연은 제안 단계다.

### 5-1. 주민 카드

주민마다 기본 설정을 요약한 카드를 만든다. 마스코트의 [가이드 정본](캐릭터/가이드_정본.md)처럼 대화 장면(§6), 편지와 방송을 만드는 기준 자료로 사용한다.

| 칸 | 뜻 |
|---|---|
| 누구 | 부르는 말(「할머니」 · 「사장님」) · 나이대 · 하는 일 · 사는 곳과 일하는 곳 |
| 겉과 속 | 첫인상과 그 뒤의 반전 하나(마스코트 셋과 같은 방식 — 전부 착하기만 한 주민은 기억에 남지 않는다) |
| 나에게 쓰는 말 · 내가 써야 하는 말 | 말의 높이(§5-4) |
| 말하는 방식 | 자주 쓰는 어미 · 감탄사 · 입버릇 · 문장 길이 · 말하는 속도 · 하지 않는 표현 |
| 이야깃거리 | 그 주민이 잘 아는 분야(음식 · 날씨 · 옛이야기 · 학교 · 서류 …) |
| 가르치는 것 | Strata의 마디 묶음 — 상황(주문 · 부탁 · 거절 · 사과)과 문법(높임 · 반말 · 수와 단위 …) |
| 하루 | 시간대마다 있는 곳(§8) · 계절과 날씨에 따라 달라지는 것 |
| 긴 이야기 | 관계가 가까워지면 시작되는 주민별 이야기와 진행 조건(§7) |
| 하지 않는 것 | 꾸짖기 · 비교 · 서운해하기 · 연애의 말 · 개인 정보를 캐묻기 · 돌아오라고 조르기 |

### 5-2. 첫 주민들 [제안 · 이름과 생김새는 사용자]

| 주민 | 나에게 쓰는 말 | 내가 써야 하는 말 | 말의 결 | 가르치는 것 |
|---|---|---|---|---|
| 평상의 할머니 | 다정한 반말(「밥은 먹었어?」) | 높임말(「-어요」에 「-시-」) | 느리고 짧다 · 속담 · 옛이야기 | 인사 · 안부 · 음식 · 날씨 · 높임 |
| 우체부 | 「-습니다」와 「-어요」 | 「-어요」 | 또박또박 · 날짜와 주소 | 편지 · 택배 · 날짜 · 수 |
| 이장님 | 방송의 말투 | 「-어요」 · 「-습니다」 | 알림의 짜임(§9) | 안내 방송 · 행사 |
| 분식집 사장님 | 빠른 「-어요」 | 「-어요」 | 빠르다 · 관용구 · 줄임말 | 주문 · 값 · 추천 |
| 편의점 알바생(또래) | 「-어요」 → 말을 놓은 뒤 반말 | 같다 | 요즘 말 · 일상 이야기 | 수 · 계산 · 말 놓기 |
| 동네 아이 | 어른에게 하는 「-어요」 | 반말 | 쉬운 낱말 · 질문이 많다 · 끝말잇기 | 쉬운 설명 · 반말 · 낱말 놀이 |
| 주민센터 직원 | 「-습니다」 | 「-습니다」 · 「-어요」 | 정확하고 공손하다 | 서류 · 번호표 · 안내문 |
| 고양이 | 말이 없다 | — | 흉내 내는 말(야옹 · 살금살금 · 꾸벅꾸벅) | 소리와 모양을 흉내 내는 말 |
| 마스코트 둘 | — | — | 가이드 정본 그대로 | §11 |

처음에는 **할머니 · 우체부 · 이장님**(집 안에서 만난다 — 찾아오고, 편지를 가져오고, 창밖에서 방송한다)으로 시작하고, 마을이 열리면 분식집 사장님 · 알바생 · 고양이가 온다. 그 뒤로 한 번에 한 명씩 는다.

### 5-3. 생김새 — 지난 반려에서 배운 것

주민의 그림은 「다 똑같이 생겼다 · 표현력이 약하다」로 반려된 적이 있다 **[확인]**. 그래서 주민을 그리기 전에 다음을 조건으로 둔다 [제안].

- 그림자(윤곽)만 봐도 누구인지 갈린다 — 몸의 크기 · 자세 · 늘 지니는 물건(할머니의 부채 · 우체부의 가방 · 사장님의 앞치마).
- 주민마다 표정과 몸짓이 다섯 가지 이상이다(맞이함 · 웃음 · 놀람 · 생각 · 다정히 알려 줌). 시무룩함 · 화 · 실망의 그림은 만들지 않는다.
- 같은 틀에 색만 바꾼 그림을 쓰지 않는다. 두 주민의 그림이 서로 얼마나 같은지를 재서, 지난번처럼 닮으면 팩이 열리지 않는다.
- 구운 뒤 마지막에 눈으로 보는 것은 **[사용자]**다.

<a id="5-4-말의-높이--누구에게-말을-거느냐가-난이도다"></a>
### 5-4. 상대에 맞는 높임말 연습

주민마다 나이와 관계에 맞는 말투를 설정해, 상대에 따라 높임말과 반말을 구분하는 연습을 제공한다.

- 할머니에게 반말로 답하면 할머니가 웃으며 알려 준다 — 「아이고, 할머니한테는 ‘먹었어요’ 해야지.」 벌이 아니고, 사이가 줄지 않으며, 맞는 말을 한 번 따라 해 볼 수 있다.
- 이 고르기는 검수된 **말의 높이 문항**으로 구성한다. 대표 능력·첫 응답·새로운 문항 여부·도움·음성 전달·조작 오류를 확인한 관측만 해당 강도로 반영한다. 정답을 보고 따라 고르거나 익숙한 문항을 반복한 결과를 새로운 독립 수행으로 승격하지 않는다(§15). 교정의 오류 유형 「높임」 · 「공손성」이 가리키는 마디를 연습하되 현재 Strata에 없는 항목은 별도 교육 검수·구현 대상으로 둔다.
- 누구에게 말을 걸지는 본인이 고른다. 아틀라스는 권할 뿐이다 — 창밖에 할머니가 보이고, 문을 두드리고, 편지가 온다.

### 5-5. 말 놓기 [제안]

또래인 알바생과는 「-어요」 말투로 시작한다. 관계가 가까워지면(§7의 셋째 단계) 「우리 말 편하게 할까요?」라고 묻는다. 받아들이면 이후 대화에서 반말을 쓰고, 거절하면 기존 말투를 유지한다. 나중에 다시 선택할 수 있다. 서로 동의하고 말을 놓는 상황을 통해 반말을 듣고 쓰는 연습을 한다.

<a id="6-대화--한-토막"></a>
## 6. 주민과 나누는 짧은 대화 장면

답변 방식, API 없는 입력 분석, 준비한 대사 조합, 규칙에 따른 교정, 제작량과 검증 방법은 [대화 설계](대화_설계.md)에서 자세히 다룬다.

<a id="6-1-토막의-모양"></a>
### 6-1. 대화 장면의 구성

주민과 한 번 대화하는 장면은 **3~7차례 주고받는 길이**로 만든다. 주민의 대사는 말풍선으로 보여 준다. 음성으로 듣는 기능은 §9에서 목소리 방식을 정한 뒤 제작한다.

각 장면에는 주민, 학습 수준, 목표 학습 항목(Strata의 마디), 계절·날씨·시간·장소 조건, 필요한 친밀도와 입력값(§6-4), 대화 순서와 마무리 대사를 기록한다. 장면이 끝난 뒤 저장할 기억, 관계 변화와 선물도 지정한다 [제안]. 수준은 TOPIK 1급+를 통과한 초급·3~4급부터 만들고 5~6급은 나중에 추가한다.

<a id="6-2-내-차례의-네-가지"></a>
### 6-2. 답변 방식과 말하기 연습

| 방식 | 무엇 | AI | 채점 |
|---|---|---|---|
| **고르기** | 두세 개의 한국어 답 가운데 고른다. 보기는 전부 옳은 한국어이고 **뜻이 다르다**(「네, 먹었어요」 / 「아직요」) — 고른 답에 따라 이야기가 갈리고, 어떤 답은 기억이 된다. 말의 높이를 고르는 보기가 섞일 때만 맞고 틀림이 있다(§5-4) | 0 | 말의 높이 문항만 |
| **조립** | 낱말 조각을 맞춰 답을 만든다. 조사와 어미의 조각에 헷갈리는 짝이 섞인다 | 0 | 자동 — 받아들이는 답의 묶음과 견준다 |
| **말하기** | 고르거나 만든 문장을 소리 내어 말한다. 발음은 판정하지 않는다 — 내 소리와 본보기를 나란히 들을 수 있을 뿐이다 | 0 | 없다(했다는 사실만 남는다) |
| **내 말로** | 보기 없이 직접 쓰거나 말한다 — 장면의 주제 안에서. 기기 안의 계산이 알아듣고 미리 지어 둔 말을 엮어 답한다([대화 설계](대화_설계.md) §6 · §7) | **0** | 검증된 규칙과 관측 조건을 충족한 근거만 반영(§15) |
| **AI와 자유 대화** | 주제를 정하지 않고 주민과 대화한다 | 있다 — 구독 사용 한도 안에서만 | AI의 교정은 약한 근거 |

도움이 많은 쪽에서 적은 쪽으로 순서가 있다 — 고르기 → 조립 → 빈칸만 내 말로 → 내 말로 → (구독) AI와 자유 대화. 혼자 해낸 결과가 이어지면 아틀라스가 한 단계 적은 도움을 **권하고 묻는다**(아틀라스 §5-4 그대로 — 강제로 줄이지 않고, 본인이 정한 방식이 앞선다).

### 6-3. 되묻기 — 모를 때 쓰는 말이 곧 배울 말이다

답변 차례마다 **「다시 말해 주세요」, 「천천히 말해 주세요」, 「무슨 뜻이에요?」** 버튼을 둔다. 주민은 같은 말을 다시 하거나, 더 쉬운 문장과 그림으로 설명한다. 버튼에 적힌 문장도 실제 대화에서 쓸 수 있는 표현이다. 도움을 쓴 차례는 오답이 아니라 도움받은 수행으로 기록한다. 반복해서 도움이 필요하면 Atlas가 더 쉬운 수준의 장면을 제안한다. 「그만할래요」도 항상 제공하고, 중간에 나가도 주민은 「그래, 또 와」라고 인사한다.

### 6-4. 빈칸과 기억 — 「나를 안다」

- 대사에는 {이름}, {하는 일의 분야}, {좋아하는 음식}, {반려동물}, {다가오는 일}, {지난번에 고른 답} 같은 빈칸을 둘 수 있다. 예: 「지난번에 {음식} 좋아한다고 했지? 오늘 시장에 좋은 게 나왔더라.」
- 빈칸은 **학습자 본인이 말했거나 선택한 정보**로만 채운다. 「나에 대해」 카드, 달력과 대화에서 얻은 값을 사용하며, 자유 입력 원문 대신 허용된 값 목록의 키를 저장한다. 필요한 정보가 없는 장면은 선택하지 않는다.
- **기억은 주민마다 따로다.** 할머니에게 한 말은 할머니가 안다. 주민끼리 내 이야기를 옮기는 연출은 처음에는 두지 않는다 — 챙김이 감시로 읽히는 자리다.
- 약속은 지킨 쪽만 말한다. 「내일 또 올게요」를 고르고 다음 날 오면 「온다더니 왔네!」가 나오고, 오지 않은 날은 아무 일도 없다.
- 이름은 기기에서 채운다. 서버로 보내는 대화 결과와 AI 입력에는 이름을 포함하지 않는다.

<a id="6-5-어느-토막을-낼까--아틀라스가-고른다"></a>
### 6-5. Atlas가 대화 장면을 고르는 순서

먼저 §1-2의 TOPIK 1급+ 통과와 §1-3의 무료 체험·정액 권한을 확인한다. 현재 세계 상태·NPC 인지·물건·일과·관계와 실제 표현 가능한 동작을 충족하는 장면만 남긴다. **플레이어가 방금 선택한 일의 결과와 이미 한 약속을 먼저 연결**하고, 그 안에서 복습·보충·새 표현을 연습할 수 있는 언어 변형과 도움을 고른다. 필요한 입력과 쉬운 대안이 없으면 적합한 대체 장면을 찾는다. 다음 추천은 생활 목표·필요한 학습·최근 사건 계열을 함께 고려하며, 대사만 바꾼 동일 의뢰를 새로운 사건으로 세지 않는다. 같은 기록 상태와 정책에서 시드는 동률만 가른다. [구체 선택 순서와 소진 처리](싱크타운_행동과_세계변화_설계.md#freshness)를 따른다.

<a id="6-6-토막은-어떻게-짓나--한-번-짓고-스스로-걸러진다"></a>
### 6-6. 대화 장면 제작과 품질 검사

- 주민 설정, 목표 학습 항목, 수준, 사용 조건과 빈칸 규칙을 바탕으로 **대화 장면을 미리 제작**한다. 한국어 콘텐츠를 여러 나라 학습자가 함께 사용한다.
- 배포 전에 어휘·문법 수준(Strata), 주민 설정과 높임 수준의 일관성, 보기의 문법과 채점 표시, 학습자를 탓하거나 민감한 정보를 캐묻는 대사, 기존 장면과의 중복을 검사한다. 문법과 채점은 정답 근거와 실제 표시를 대조하고 판단이 어려운 문항은 보류한다. 이 검사는 학습 정확도와 캐릭터 설정에 한정한다.
- 배포 후에는 완료율, 되묻기 비율과 「이 말이 이상해요」 신고로 품질을 확인한다. 문제가 있는 장면을 자동으로 제외하는 조건은 아틀라스 §7-2를 따른다. Prism의 결과로 난이도를 조정하고, 제공할 장면이 부족하면 이를 운영 지표로 알린다.
- 자동 채점은 기존 데이터 계약을 따른다. 기기가 정답 여부를 임의로 확정하지 않고, 표시한 보기와 선택 결과를 기록한다. 보기 순서는 시드로 섞고, 항목별 검증 기록과 유효성을 관리한다.
- 초기 제작량은 주민 1명·수준 1개당 40장면으로 제안한다. 주민 3명·수준 4개라면 약 500장면이다. 실제 1차 지원 수준과 제작 범위는 대화 설계 §12와 맞춰 정한다.

### 6-7. 입장 전의 기초 학습과 해금 후의 도움

한글 단계와 TOPIK 1급+ 미통과 학습자는 메인 화면의 기초 학습·미니게임을 이용한다. 그림과 소리, 한두 마디의 대화 연습과 필요한 보조 언어는 메인 학습 장면에서 제공한다. 마을 주민과의 실제 대화·관계·생활 활동은 §1-2의 통과 후 시작한다. 기존 「한글 단계에 있는 사람도 마을 주민을 만난다」는 설계는 2026-10-01 결정으로 변경됐다. 해금 후에는 쉬운 한국어·그림·반복 듣기·되묻기로 지원한다.

<a id="language-growth"></a>
### 6-8. 플레이어와 함께 발전하는 말·주민·생활 (2026-10-01 사용자 결정)

TOPIK 1급+는 입장 조건이다. **마을의 첫 경험은 아주 쉬운 말로 시작하고, 플레이어의 실제 활동에 따라 여러 주민과 콘텐츠가 함께 발전한다.** 1급·2급 분류 안에도 부담이 다른 말이 있으므로 첫 장면의 난도를 급수만으로 정하지 않는다. 구체적인 대사 제작·단계별 예시·진행 근거는 [대화 설계 §3-1](대화_설계.md#language-evolution)이 정본이다.

- 첫 만남·생활 안내·보기·힌트·반응은 한 번에 짧은 문장 하나와 뜻·행동 하나로 시작한다. 기본 단어와 문형을 중심으로 쓰고, 낯선 단어는 먼저 그림·물건·소리로 소개한다. 따뜻함과 주민의 개성은 쉬운 말과 실제 행동으로도 전달한다.
- 메인 학습과 마을 활동에서 **무엇을 이해하고 표현했는지, 다른 장면에서도 쓸 수 있는지, 도움을 받았는지**를 참고한다. 새로운 단어·문법·과제 조건·입력 부담을 동시에 늘리지 않는다. 익힌 수량을 다른 주민의 주문에 적용하는 식으로 한 가지씩 넓힌다.
- 주민의 대사·부탁·후속 이야기뿐 아니라 심부름·가게·편지·방송·안내·마스코트 도움도 같은 개인 학습 요약을 참고한다. 듣기·읽기·말하기의 확인은 구분하고, NPC별로 아는 사연과 기억은 보존한다.
- 완료한 생활 활동은 주민의 행동·물건 사용·집과 가게의 모습·새 이야기로 돌아온다. 생활 성과와 한국어 숙련은 별도로 확인한다. 높은 호감·접속 일수·수확량만으로 말이 어려워지지 않는다.
- 막히면 같은 뜻을 더 쉽게 나누고 도움을 늘린다. 관계·생활 성과·마을 해금은 유지하며, 쉬운 활동을 계속 고를 수 있다. 공동 마을이 발전해도 다른 학습자의 성과 때문에 내 언어 난도가 오르지 않고 새로 온 플레이어도 쉬운 시작을 받는다.

## 7. 사이 — 깊어지는 것이 말로 보인다

**2026-10-02 설계 갱신:** 관계는 대화 횟수·날수로 올리지 않는다. 익숙함, 함께한 사건의 신뢰, 서로 아는 사실을 구분하고 **호칭·행동·맡기는 일·남는 물건**으로 표현한다. 단계별 진입 조건의 정본은 [사건에 따라 깊어지는 관계](싱크타운_행동과_세계변화_설계.md#relationships)다.

| 단계 | 실제 근거 | 주민에게서 달라지는 것 |
|---|---|---|
| 처음 만남 | 함께한 장면 없음 | 쉬운 인사·선택 |
| 얼굴을 아는 사이 | 첫 만남 완료 | 알아보는 몸짓·허용한 호칭·기본 부탁 |
| 함께한 일이 있는 사이 | 해당 NPC와 생활 사건 해결 | 결과를 실제로 사용하고 관련 이야기를 이어 감 |
| 서로 맡기는 사이 | 다른 맥락의 사건과 NPC의 실제 도움·보답 | 해결 방법을 맡김. 방문·말 놓기는 별도로 선택 |
| 오래 이어가는 사이 | 긴 이야기의 한 갈래 완료와 이어갈 교류 선택 | 기념물·새 생활 계획·다음 이야기의 동료 역할 |

- 도움받은 완성도 함께한 일로 인정한다. 한국어 정오·구매·반복 납품·접속량으로 신뢰를 대신하지 않는다. 쉬거나 거절해도 관계·완료 성과를 내리지 않으며 이름이나 개인 취향을 알려 주지 않아도 진행할 수 있다.
- **이웃 수첩**(내 집): 만난 주민마다 한 쪽 — 그 주민이 좋아하는 것 · 같이 나눈 이야기 · 그 주민이 나에 대해 아는 것. 그 사람의 눈높이 한국어로 적혀 읽을거리가 된다. 아는 것의 줄마다 「잊어 주세요」가 있고, 누르면 그 주민의 줄에서 다시 나오지 않는다.
- 주민에게 받은 선물은 집에 장식할 수 있다. 이런 선물은 판매하거나 연속 접속 보상으로 지급하지 않는다.

## 8. 주민의 하루

- 주민마다 시간표가 있다 — 새벽 · 아침 · 낮 · 오후 · 저녁 · 밤에 어디에 있나. 주중과 주말이 다르고, 계절과 날씨가 덮어쓴다(비가 오면 처마 밑 · 한여름 낮에는 그늘 · 첫눈 오는 날에는 모두 나와 있다). 계산으로 정해지고 서버를 부르지 않는다.
- **어느 시간대에 와도 그날 적어도 두 주민을 만날 수 있다.** 주민마다 두 개 이상의 시간대에 서로 다른 자리에 있다. 늘 밤에만 오는 학습자에게는(확인된 시간대의 습관 — 아틀라스 §4-2의 `trait`) 밤의 자리가 더 채워진다 — 포장마차 · 마루에서 부채질하는 할머니 · 군고구마.
- 가게가 닫혀 있으면 문에 **쪽지**가 붙어 있다 — 「잠깐 자리 비웁니다. 3시에 돌아와요.」 읽을 수 있는 실제 안내문이고, 한 번 눌러 답하는 확인(「언제 돌아와요?」)은 실용문 읽기의 자동 채점 문항이다. 쪽지 · 간판 · 차림표 · 버스 시간표 · 분리수거 안내가 마을의 읽을거리다.
- 마을의 작은 사건이 있다 — 장날 · 첫눈 · 새 이웃의 도착 · 마스코트 셋의 소동(§11). 그날 들어온 사람만 보지만, 놓쳤다고 알리지 않는다.
- 시간표·영업시간은 배경 생활과 실용문 읽기의 재료다. 이미 완성한 일의 핵심 효용·필수 후속을 보기 위해 특정 현실 시간이나 날씨에 다시 오게 하지는 않는다. [현재 방문의 결과 확인](싱크타운_행동과_세계변화_설계.md#comfort-result)에 맞춰 실제 가능한 이용 장면·방문 대안을 준비하며, 공유 날씨나 다른 이웃의 시간을 바꾸지 않는다.

## 9. 이장님 방송

「아, 아. 주민 여러분께 알려 드립니다.」 하루에 한 번, 마을의 스피커에서 난다. 집 안에서는 창밖에서 들려오고, 누르면 제대로 듣는다.

- **짜임**은 시험의 안내 방송과 같다 — 여는 말 → 무엇 · 언제 · 어디서 · 주의할 것 → 맺는 말(「이상입니다」). TOPIK 듣기의 안내 방송 유형과 EPS의 안내를 생활로 듣는다.
- **내용**: 계절과 절기 · 오늘의 날씨 · 생활의 알림(장날 · 분리수거 · 단수 · 버스 시간이 바뀜) · 안전(빗길 · 눈길 · 더위 · 추위) · 행사와 명절의 준비 · 새 이웃(「새 이웃이 오셨습니다」 — 이름을 말하지 않는다).
- 같은 알림을 **눈높이 셋**으로 둔다 — 짧고 느린 것(그림 카드와 함께) · 보통 · 자연스러운 빠르기.
- 듣고 나서 한두 번 누르는 확인이 **있을 수 있다**(「무엇을 하라고 했나요?」 — 그림에서 고른다). 자동 채점되는 듣기 근거다. 「다시 듣기」와 「글로 보기」는 늘 있고, 쓰면 도움받은 수행으로 남는다. 확인은 건너뛸 수 있다.
- 방송의 시작·날씨·생활 안내·마무리 문장과 음성을 미리 제작한다 [제안]. 마을·날짜·날씨·달력을 바탕으로 그날 쓸 부분을 조합한다. 수준별 안내 문장은 60~100개로 시작한다. 실행 중 AI 호출은 없애되 제작·배포 비용은 별도로 계산한다.
- 목소리 **[사용자]**: 주민의 소리는 「확정된 하나의 목소리」 원칙([한글 단계 설계](한글단계_설계.md) §10)과 만난다. 주민마다 다른 목소리를 둘지(듣기 시험은 여러 사람의 목소리다), 말풍선과 비언어 소리로 두고 문장만 하나의 목소리로 들려줄지를 정해야 한다. 정하기 전에는 소리를 굽지 않는다.

## 10. 심부름

첫 만남을 마친 주민은 기본 부탁을 할 수 있다. 관계가 깊어지면 해결 방법을 맡기거나 함께 계획하는 의뢰로 넓힌다(§7). 「우체국 옆 꽃집에 이것 좀 갖다줘요.」처럼 쉬운 심부름부터 시작하고 [퀘스트의 선택·거절·후속 상태](싱크타운_행동과_세계변화_설계.md#quests)를 따른다.

| 종류 | 예 | 익히는 것 |
|---|---|---|
| 자리 찾기 | 「우체국 옆 꽃집」 | 옆 · 앞 · 뒤 · 건너편 · 사이 · 왼쪽과 오른쪽 |
| 수와 단위 | 「사과 세 개, 우유 두 병」 | 고유어 수 · 개 · 병 · 마리 · 장 |
| 값과 셈 | 「만 원 줄게, 거스름돈 받아 와」 | 한자어 수 · 값 |
| 때 | 「세 시까지」 · 「점심 먹고 나서」 | 시각 · 순서의 말 |
| 말 전하기 | 「사장님한테 내일 못 간다고 전해 줘」 → 「할머니가 내일 못 오신대요」 | 전하는 말(간접 인용) · 높임 |
| 차례 | 「먼저 은행에 들렀다가 …」 | -고 나서 · -다가 |
| 쪽지 | 장 볼 것을 적은 쪽지를 읽고 간다 | 읽기 · 물건 이름 |

- **흐름**: 부탁을 듣는다(다시 들을 수 있다) → 되물을 수 있다(「몇 개요?」 — 되묻는 말도 고르는 한국어다) → 간다(장소를 누른다) → 그곳에서 말하거나 고른다 → 돌아오면 고맙다는 말과 작은 것(재료 · 간직하는 물건 · 새 이야기).
- **잘못 가도 벌이 없다.** 그곳의 주민이 알려 준다 — 「꽃집은 우체국 옆이에요.」 그 말이 힌트이고, 다시 가면 된다.
- 생활 완료는 실제 도착·물건·전달로 확인한다. 한국어 학습 근거는 새 표현인지, 도움·재청취·시각 단서·조작 실패가 있었는지와 대표 능력을 함께 확인한 뒤 따로 남긴다. 자동으로 생활 완료를 판정했다고 독립적인 한국어 수행이 되는 것은 아니다.
- 심부름은 **틀 × 마을의 지도 × 겨냥하는 마디**로 계산해 만든다(AI 호출 없음). 아틀라스가 그 사람의 복습할 마디와 약한 마디를 겨냥한 틀을 고른다.
- 앱이 먼저 권하는 심부름은 자동 말걸기 하루 한 번 예산을 함께 쓴다. 플레이어는 직접 의뢰 목록을 열어 다른 일을 고를 수 있다. 수락하지 않은 추천이 밀린 목록이 되지 않으며, 이미 수락한 약속은 현재 상태와 연기·그만두기 선택을 유지한다.
- **집 안 심부름**: TOPIK 1급+ 통과 후 허용된 마을 장면에서 마스코트가 부탁한다 — 「책상 위에 있는 컵 좀 줘.」 해금 전에는 메인 기초 학습의 별도 연습·미리보기로 제공하며 마을 생활 상태·관계를 진행하지 않는다.

## 11. 마스코트 셋

- 내가 고른 마스코트는 **내 집에 함께 산다.** 오늘 과제를 추천한 이유를 설명하고, 하루에 하나 질문하며, 학습자가 알려 준 일정과 「나에 대해 아는 것」 수첩을 함께 확인한다. 주민과의 대화에서 막히면 「힌트 볼래?」라고 한 번 도움을 제안한다(아틀라스 §8-5).
- 마스코트와도 §6의 짧은 대화 장면을 진행한다. 선택한 답은 허용된 범위에서 「나에 대해」의 이해 항목 후보와 다음 과제의 소재가 된다(아틀라스 §8-4).
- 다른 두 마스코트는 **이웃**으로 등장한다. 셋의 「사고 → 허세 → 수습」 관계를 3~4개의 장면으로 만들어 광장·분식집·집 앞에서 며칠에 걸쳐 보여 준다. 내 마스코트는 집에서 「오늘 광장에서 봤어?」라고 이야기를 이어 갈 수 있다. 이런 이야기는 계절별로 미리 제작한다.
- 마스코트는 말풍선과 비언어 소리로 말한다(가이드 정본). 마스코트의 말에 목소리 합성을 쓰지 않는다.
- 학습자가 거는 말에는 예산이 없다. 하루에 하나라는 예산(아틀라스 §8-9)은 **앱이 먼저 거는 말**에만 걸린다.
- 혼잣말 511문구의 몽골 소재는 그 나라의 학습자에게만 나오게 하고(판정표), 새 줄은 빈칸이 있는 줄로 짓는다.

## 12. 편지와 방문

- **편지**: 우체부가 내 집 우편함에 넣는다. 보내는 이는 내 마스코트 · 아는 사이가 된 주민 · 이장님(행사의 초대장) · 우체국(택배 안내 — 실용문)이다. 그 사람의 눈높이로 적힌 읽을거리이고, 편지는 시험의 읽기에 나오는 글의 한 가지다.
- 하루에 많아야 한 통이다. 읽지 않은 편지가 있어도 재촉하지 않고, 답하지 않아도 주민은 서운해하지 않는다.
- **답장 방식**은 빈칸 선택, 문장 조립과 직접 쓰기를 검토한다. 직접 쓴 편지에 AI가 답한다면 다음 날 아침 배달하고 AI 사용 한도 안에서 처리하는 안이다 [제안]. 답장, 교정 내용과 기억 후보를 함께 만들되, 기억은 학습자 확인을 거친다. 배치 처리 비용은 실제 모델 요금으로 계산한다. API 없는 답장을 제공할지와 무료 체험·정액 포함 범위는 대화 설계 §17과 BM-10에서 검토하며 아직 정해지지 않았다.
- **문 두드림**: 집에 있을 때 주민이 찾아온다 — 반찬을 가져온 할머니 · 택배를 든 우체부. TOPIK 1급+ 통과 후 허용된 집 장면에서 주민을 만나는 길이다. 앱이 먼저 거는 말의 하루 예산 하나를 같이 쓴다.
- 교정의 답장은 지금처럼 우편함에 온다. 일반 학습자에게는 「AI가 본 것」으로 표시한다(공개판 §5).

## 13. 열여섯 — 같이 사는 온기

**사용자 결정(2026-09-20)**: 「싱글플레이로 전부 다 메인컨텐츠를 구성하는 게 내 목표랑 일치해. 16명은 그저 온기를 느끼는 느낌 정도면 될 것 같아.」 **혼자 하는 것이 전부 메인이고, 열여섯은 「같이 사는 온기」다.** 그만큼 주민을 정교하게, 많이 만든다(§5 · §20). 까닭은 아래와 같다.

- 사람끼리는 채팅이 없으므로(§2) 깊은 대화 · 기억 · 사이는 주민에게서만 나올 수 있다.
- 온라인 학습자는 시간대와 접속 빈도가 다를 수 있다. 이웃이 접속하지 않아도 주민과의 콘텐츠를 충분히 이용할 수 있어야 한다.
- 주민과의 말은 눈높이에 맞고, 말의 높이가 다양하고, 자동으로 채점되어 아틀라스로 돌아온다. 같은 수준의 학습자끼리는 그것이 어렵다.
- 그래서 **모든 것이 혼자서 완결되고, 이웃은 더해진다.** 실제로 친구인 학원의 반에서는 같은 장치가 저절로 더 따뜻하게 쓰인다. 이웃의 장치가 머무름과 배움에 좋은지는 결과를 보고 키운다.

**가벼운 장치 [제안 · 전부 정해진 말]**

| 장치 | 무엇 |
|---|---|
| 이웃의 집 | 꾸민 대문 · 마당 · 문패(별명)가 보인다 |
| 한국어 이모티콘 | 마스코트 그림 + 짧은 한국어(안녕하세요 · 수고했어요 · 화이팅 · 고마워요 · 잘 자요 · 대박). **배운 표현이 이모티콘으로 열린다.** 받은 것은 본인만 본다 |
| 문 앞 선물 | 기른 꽃 · 만든 반찬을 정해진 한마디와 함께 두고 간다 |
| 집들이 | 집을 꾸미고 이웃을 초대한다. 초대한 곳만 보인다. 손님은 휴지와 세제를 들고 오고(한국의 집들이), 방명록에는 이모티콘과 정해진 한마디를 남긴다 |
| 같이 색이 드는 마을 · 명절 | §4-5 · §14 |
| 마을 라디오 사연함 | 짧은 사연을 틀과 조립으로 써서 넣으면, 밤에 진행자 주민이 골라 읽어 준다. 마을에 하루 한 번만 처리한다(열여섯이 나눠 쓴다). 직접 쓴 글은 그대로 나가지 않는다 |
| 같이 있기(맨 뒤 · 온기의 크기로만) | 같은 때에 들어와 있으면 서로의 마스코트가 보이고 몸짓과 이모티콘으로 인사한다. 평상에 나란히 앉아 각자 공부한다 |

- **묶는 법**: 수준의 띠가 비슷하고, 활동하는 때가 조금 겹치며, **나라는 일부러 섞는다** — 공통의 말이 한국어뿐이다. 빈집은 「올 이웃의 자리」이고, 새 이웃은 기차역으로 도착해 환영의 이모티콘을 받는다. 조용해진 마을의 사람에게는 같이 이사할지를 묻는다(본인의 선택 · 집과 사이와 기록은 같이 간다). 친구를 내 마을의 빈집으로 부를 수 있다. 학원의 반은 그 반이 그대로 한 마을이다.
- **안전**: 이웃에게 보이는 것은 별명 · 집 밖의 꾸밈 · 마스코트와 옷 · 이모티콘 · 정해진 한마디뿐이다. 실명 · 사진 · 연락처 · 직접 쓴 글 · 학습 기록 · 나라와 나이는 보이지 않는다. 별명은 걸러 내고, 신고와 차단이 있다(차단하면 그 이웃의 인사와 선물이 보이지 않는다). 공개판의 기준은 「다른 사람의 **학습 자료와 개인 정보**가 보이지 않는다」로 고친다.

## 14. 공부와 성취

- **장소마다 상황 한국어**(§3-3): 분식집과 카페의 상황 말하기 · 주민센터와 은행과 병원의 실용문 읽기 · 우체국의 격식 있는 글이 판정표의 재설계가 들어갈 자리다. 직접 말하고 쓰는 부분의 AI 교정은 몫 안에서만 열리고, 고르기와 조립은 0원이다.
- **학교는 모의시험장이다.** EPS를 먼저, TOPIK을 다음에 연다(모의시험의 설계는 따로 쓴다). 시간과 점수는 그 안의 「실전 모드」에서만 보인다.
- **도감**: 계절마다 마을에 나타나는 꽃 · 물고기 · 곤충 · 먹을거리, 그리고 **본 하늘**(첫눈 · 무지개 · 은하수)을 모은다. 낱말 · 그림 · 소리가 같이 쌓이고 줄지 않는다. 몇 개 가운데 몇 개 같은 숫자를 보이지 않는다.
- **명절**: 설날 · 정월대보름 · 단오 · 추석 · 한글날 · 김장 · 동지. 마을이 며칠 전부터 바뀌고(주민의 말 · 방송 · 시장), 준비는 하고 싶은 사람만 한다. 모자라면 주민이 채운다. **아무도 오지 않아도 잔치는 열린다.** 그 학습자의 나라의 날에는 내 마스코트가 집에서 인사 한 줄을 건넨다.
- **꾸미기는 두 갈래다**(2026-09-20 사용자): 가구와 코스튬은 **고정가 상점**에서 판다([BM 목록](BM_목록.md) BM-6 — 가게는 걸어 들어가는 곳이고 주민이 물건을 권하지 않는다). 주민이 주는 간직하는 물건(§7) · 심부름 · 도감 · 명절의 물건은 **팔지 않고** 배움과 사이로만 얻는다. 옛 숙제 포인트와 옷 가게의 동전 · 흥정은 보류다.

## 15. 아틀라스와의 연결

| | |
|---|---|
| 입력 정보 | 복습할 항목과 자주 어려워하는 항목, 본인이 알려 준 생활 소재와 일정, 확인된 접속·도움 선호, 학습 수준, 친밀도, 최근 대화, 계절·날씨·시간 |
| 개인화할 내용 | 확정 생활 사건과 NPC 인지를 바탕으로 행동·후속 의뢰·전달 방식을 고르고, Core가 언어와 도움을 조정한다. 구체 책임과 현재/추가 구현은 [세계 변화 정본](싱크타운_행동과_세계변화_설계.md)·[구현 계약](아틀라스_구현명세.md#town-world-contract)에 둔다. 자동 말걸기 하루 한 번, 소리·움직임 선택을 유지한다 |
| 돌아가는 결과 | 생활 사건·관계 근거·반응 전달과 언어 학습 관측을 구분한다. 자동 채점만으로 강한 근거로 승격하지 않고 새 문항·대표 능력·도움·음성 전달·조작 오염을 확인한다. AI 교정은 검수 전 약한 근거다 |
| 습관 요약 | 세부 차례마다 전송하지 않고 완료한 대화의 결과를 요약한다. 자주 대화하는 주민, 접속 시간, 답변 방식과 되묻기 사용 등을 다룬다. 학습자에게 설명할 수 있고 실제 도움을 바꾸는 정보만 이해 항목으로 등록한다(구현 명세 §3-2). 구체적인 이벤트 단위는 대화 설계 §14와 맞춘다 |
| 개선과 검증 | 장면별 결과로 콘텐츠를 관리한다(§6-6). Prism은 모국어 집단별 난이도를 분석하고, 새 버전은 Temper의 `마을` 시나리오로 검증한다 |

엔진별 역할은 Strata(학습 항목과 주민 콘텐츠 연결), Core(학습 항목·답변 방식·심부름 선택), Vellum(주민·마스코트의 대사·편지·이모티콘), Loom(공간·계절·빛·날씨 표현), Reed(환경음·음악·방송), Trail(관계·수첩·도감·엽서 기록), Temper(결과 검증과 콘텐츠 관리), Prism(항목·장면의 난이도와 초기 수준 분석)이다. 필요한 기능을 구현할 때 해당 엔진의 공통 기능부터 확인한다.

생활 사건과 NPC의 인지·반응·보상은 [마을 서비스 계약](아틀라스_구현명세.md#town-world-contract)으로 별도 설계한다. 기존 Atlas 이벤트나 도움 설정 API에 임의 필드를 넣지 않는다. 생활 완료는 활동 단위로 확정하고, 학습 관측은 도움과 응답의 순서를 보존한다. 실제 계약 판·DB 변경·계정 왕복은 구현 단계에서 검증한다.

**기본 마을 콘텐츠는 무료 체험·정액제 모두 실행 중 AI 호출 없이 이용할 수 있게 만드는 것이 목표다.** 위 비용은 초기 추정이며 실측한 운영비가 아니다. 공용 콘텐츠를 재사용해 제작비를 나눌 수 있지만, 개발·미술·한국어 검수·운영 인건비와 사용자 증가에 따른 서버·저장·배포 비용을 함께 계산한다. 정액제의 수익성은 [BM-10](BM_목록.md#synk-town-bm)의 상품 범위를 정한 뒤 검증한다.

## 17. 판의 범위와 인수 기준

2026-09-20 사용자: 「1~2주 동안은 이 계획에 대한 디테일한 설계만 진행하자. 구현은 지금 할 필요 없어 보여.」 아래의 판은 만들 때의 순서이고, 지금은 설계만 한다(§20).

| 판 | 담는 것 |
|---|---|
| 집 1판 | 내 집 — 창문(계절 · 시간의 빛 · 날씨) · 소리 둘의 켜고 끄기 · 책상 · 우편함 · 액자 · 달력 · 수첩 「나에 대해 아는 것」 · 집 안의 낱말. 내 마스코트와의 고르는 대화와 조립 대화 · 마스코트의 편지 · 집 안 심부름 |
| 집 2판 | 문 두드림(할머니 · 우체부) · 주민의 편지와 틀 답장 · 이장님 방송(창밖) · 사이의 단계 · 이웃 수첩 · 자리별로 바꾸는 꾸미기 · 엽서 |
| 마을 1판 | 대문 밖 첫 생활 구간인 [찻집 앞 작은 쉼터](디자인/싱크타운_첫생활구간_설계.md#routes) · 개인 화단과 짧은 산책길 · 필요한 공방/온실 장면 · 생활 제작·메뉴·발견·주민 사연의 네 입구와 개인 완결 · 주민의 하루 · 머무는 모드. 기존 평상·분식집·편의점·마스코트 이웃 소재는 이 첫 구간에 필요한 것부터 연결하고 장소 수를 먼저 늘리지 않는다. |
| 마을 2판 | 첫 생활의 다른 역할·편해지는 작업·주민의 보답·후속 이야기 · 열여섯의 가벼운 장치(이웃의 집 · 한국어 이모티콘 · 문 앞 선물)와 선택적 C08 공동 기여 · 배운 만큼 색이 드는 마을 · 첫 명절 |
| 그 뒤 하나씩 | 장소와 주민(우체국 · 주민센터 · 시장 · 학교 · 도서관 · 기차역) · 말 놓기 · 집들이 · 도감 · 라디오 사연함 · 자유 대화와 직접 쓰는 편지(유료가 열린 뒤) · 같이 있기(맨 뒤) |

마을 1판의 기술 출발은 C01/C02의 사건·표현·복원 검증이다. 그다음 네 입구를 각각 재료 마련부터 현재 이용·재방문까지 완결해야 생활 구간이 완성된다. 내 집부터 탄탄히 만든다는 방향은 유지하며, 첫 쉼터가 준비되기 전에 마을 전체를 채우는 순서로 해석하지 않는다. 세부 인수 기준은 [첫 생활 구간](디자인/싱크타운_첫생활구간_설계.md#acceptance)을 따른다.

0. **마을에 들어가지 않은 학습자도 막히지 않는다** — 메인 화면만으로 한글 단계에서 TOPIK I(1~2급) 준비까지 이어지고, 3~4급은 메인의 시험 형식 연습으로 준비를 이어 갈 수 있다(3~4급의 중심 경로는 마을, §1-1 2026-10-02). 마을에 들어가지 않았다고 막히거나 재촉받는 자리가 없다.
1. 다른 사람이 0명인 마을에서 모든 콘텐츠가 끝까지 된다.
2. AI 호출이 0인 설정에서 이용 권한이 허용한 집 1판부터 마을 2판까지의 기본 콘텐츠가 전부 돈다. 무료 체험·정액 범위는 §1-3으로 확인하고, 자유 대화와 직접 쓰는 편지는 AI 기능 권한·몫이 없으면 조용히 닫혀 있고 닫혀 있다고 탓하지 않는다.
3. 화면 · 알림 · 주민의 줄 어디에도 점수 · 등수 · 개인의 숫자 · 연속 기록 · 「왜 안 왔어」가 없다(팩 전체를 훑는 시험). 사이 · 간판 · 도감 · 꾸밈은 한국어 실수·결석·도움 사용·거절 때문에 자동으로 줄지 않는다. 플레이어가 직접 물건을 옮기거나 철거하면 현재 공간은 그 선택대로 바뀌고 과거 성취는 기록에 남는다.
4. 같은 마을·한국 날짜에는 같은 날씨가 나온다. 같은 학습자·날짜·주민과 동일한 기록·정책에서는 같은 장면을 선택한다. 내려받은 대화·날씨·주민 일과는 검증된 오프라인 권한 범위에서 작동하고, 잠정 생활 사건과 서버 확정 상태·공동 변경을 구분한다([저장 기준](싱크타운_행동과_세계변화_설계.md#persistence)).
5. 필요한 입력값이 없는 장면은 선택하지 않는다. 주민은 본인이 받거나 본 일, 학습자가 공유한 사실, 정해진 경로로 전달된 공개 사건만 안다. 「잊어 주세요」로 제외한 내용은 이후 대사나 늦게 완료된 처리에서 복구되지 않아야 한다.
6. 서버의 대화 결과, 이해 데이터와 AI 입력에 학습자 이름을 넣지 않는다.
7. 높임말을 요구하는 상황에서 반말을 고른 테스트 결과가 올바른 학습 항목과 연결되고, 그 항목을 연습할 대화와 심부름에 반영되는지 확인한다. 되묻기는 도움받은 수행으로 기록한다.
8. 되묻기 세 버튼과 「그만할래요」가 모든 내 차례에 있다. 중간에 떠나도 다음 방문에 불이익이 없다.
9. 제공하는 모든 대화 장면이 §6-6의 다섯 검사를 통과해야 한다. 검증하지 않은 장면이 노출되면 테스트가 실패한다. 신고와 결과 지표에 따라 문제 장면을 제외하는 기능도 검증한다.
10. 어느 시간대에 열어도 그날 적어도 두 주민을 만날 수 있다.
11. 움직임 줄이기에서 모든 장면이 정지 그림으로 뜻이 통한다. 화면이 흔들리는 연출이 없다. 마을 소리와 음악이 따로 꺼지고, 끈 소리가 어떤 경우에도 다시 나지 않는다. 녹음 중에는 0이다.
12. 두 주민의 그림이 서로 얼마나 같은지 재는 검사를 지난다(§5-3). 구운 간판과 쪽지의 글자가 표준 글꼴과의 대조를 지난다.
13. 이웃에게 보이는 것이 §13의 목록뿐이다 — 다른 계정으로 들어가 실명 · 직접 쓴 글 · 학습 기록 · 나라가 보이지 않음을 확인한다. 차단한 이웃의 인사와 선물이 보이지 않는다.
14. 한글 단계·TOPIK 1급+ 미통과 학습자는 마을 생활·NPC 플레이를 시작할 수 없고, 잠금 이유와 메인 학습으로 가는 길을 이해할 수 있다. 통과 후 첫 NPC 장면은 쉬운 한국어·그림·반복 듣기·되묻기로 끝낼 수 있는지 확인한다.
15. 첫 설치의 크기와 낮은 기기의 그리기 속도가 정한 값 안이다(값은 실기기에서 잰 뒤 정한다 — §19).
16. `마을` 시뮬레이션에서 자동으로 생성한 입력만으로 관계 상태, 개인화 선택, 결과 전달과 문제 장면 제외가 작동하는지 확인한다. 이는 실제 학습자의 경험 검증과 구분한다.
17. 메인의 TOPIK 1급+ 통과가 마을 입구·생활 활동·NPC 소통의 학습 잠금을 함께 해제하며 재접속·다른 기기에서도 같은 학습자의 확인된 통과 기록을 적용한다. 무료 체험·정액 이용권은 §1-3으로 따로 확인한다. 미통과·확인 중에는 직접 링크·진행 복원에서도 생활 보상과 NPC 관계 진행이 발생하지 않는다.
18. 통과 계정에서 미통과 계정으로 바꾸면 잠금 상태가 분리된다. 공식 시험 성적·자기 신고 레벨·마을 재화·구독·다른 사람의 진행으로 이 조건을 대체하지 않는다.
19. 통과 전에도 메인의 한글·기초 한국어·학습용 미니게임을 이용할 수 있고, 한글 길·간판 미리보기가 마을 입장의 우회 경로가 되지 않는다. 통과 후 쉬었다 오거나 복습에서 틀려도 학습 잠금을 다시 걸지 않는다. 유료 콘텐츠의 이용 가능 여부는 현재 체험·정액 권한으로 확인한다.
20. 해금 직후 모든 주민과 생활 콘텐츠의 첫 안내·보기·힌트·반응이 아주 쉬운 시작을 제공한다. 동일 급수라도 알려진 단어·문형이 다른 두 플레이어에게 맞는 쉬운 대안이 제공된다.
21. 플레이어가 다른 장면에서 확인한 이해·표현이 여러 주민과 과제에 일관되게 반영된다. 다음 표현은 한 가지씩 넓어지고, 생활 성과·호감·공동 시설 성장만으로 언어 난도가 오르지 않는다. 막히거나 쉽게 돌아와도 기존 성과와 해금을 유지한다.
22. 학습 통과와 체험·정액·선택 상품 권한을 각각 확인한다. 결제한 미통과 학습자는 마을을 시작할 수 없고, 통과했지만 정액 이용권이 없는 학습자는 정해진 무료 체험 범위만 이용한다. 직접 링크·진행 복원·계정 전환에서도 유료 장면·보상이 우회되지 않는다. 만료만으로 통과·관계·성과·구매 소유 내역을 지우지 않으며, 상품 계약에 따른 복원과 이용 범위를 검증한다.
23. [행동과 세계 변화의 인수 기준](싱크타운_행동과_세계변화_설계.md#acceptance)을 적용한다. 같은 출발의 다른 선택이 실제 행동·후속 의뢰를 바꾸고, 재접속·철거·거절·후보 소진·공동 시설 변경에서도 일관되게 이어져야 한다. 자동 시험과 학생의 원인 체감·새로움 관찰은 별도로 확인한다.

24. 완성한 쓸모를 현재 방문에서 선택해 확인하고, 추가 부탁의 수락·거절 없이 종료할 수 있다. 배치 미리보기·직전 개인 배치 복구, 개인 대화/제작의 중단·재개, 장면 경계의 개인화, 성과와 판매 재고의 분리를 [여섯 보완 인수 기준](싱크타운_행동과_세계변화_설계.md#acceptance)으로 검사한다.

## 18. 사용자 확인이 필요한 자리

메인 화면의 구성과 마을 입구의 모습(§1-1) · 주민의 이름과 생김새(§5-3 — 지난 반려) · **주민의 목소리**(§9) · 첫 마을의 생김새(산골 · 바닷가 · 한옥 마을 · 도시의 골목 가운데 하나를 정말 아름답게) · SYNK 음악의 곡과 권리 · 별명의 규칙과 나이의 기준(공개판 §8-1의 「만 14세 이상」은 한국 법 기준이다) · 돈에 관한 자리는 [BM 목록](BM_목록.md) §9 · 사이의 단계와 날씨의 비율 같은 수치 · 새 사건의 어휘와 계약의 개정 · 구운 자산을 마지막에 눈으로 보는 일.

## 19. 확인하지 못한 것

- 낮은 값의 안드로이드에서 겹쳐 그리기와 비 · 눈의 속도, 앱의 그리기 도구로 무엇을 쓸지 — 실기기에서 잰다.
- 첫 설치의 크기와 장소별로 나눠 받기의 방식(지금 앱의 자산은 전부 함께 실린다).
- 이모티콘과 별명만 있는 앱에 두 스토어가 요구하는 신고 · 차단의 가장 작은 범위(애플 심사 지침 1.2).
- 나라마다 다른 미성년의 기준 — 스무 나라의 목록이 정해진 뒤에 본다.
- 음력 명절의 날짜표(몇 해 치를 적어 둘지).
- 마스코트의 옷이 이웃에게 어떻게 보일지, 마을에서 「나」를 무엇으로 그릴지(내 마스코트와 같이 걷는 모습 [제안]).
- 옛 설계(옷입히기 · 살아있는 자리 · 앱 재설계)의 「내 방」과 반 명단을 전제로 한 문장 — 이 문서를 넣을 때 가리키는 말을 단다.

## 20. 2026-09-20에 정리한 설계 작업

당시 논의한 주제 목록이다. 아래 번호를 현재 작업의 필수 순서나 구현 대기로 사용하지 않는다. 각 주제의 후속 결정과 실제 구현은 연결된 담당 문서·코드에서 확인한다.

1. **앱의 뼈대** — 메인 화면의 구성(글자를 모르는 사람 · 초급 · 중급이 각각 무엇을 보나) · 마을 입구 · TOPIK 4급까지의 길.
2. **한글을 모르는 사람의 길** — 메인 화면의 한글 단계·학습용 미니게임과 간판·문패 미리보기. 마을의 생활·주민 소통은 TOPIK 1급+ 통과 뒤에 잇는다(§1-2).
3. **정과 문화의 장치** — 따뜻한 감정 · 한국의 정 · 한국의 문화를 겪게 하는 장치를 많이(사용자 09-20 「이런 장치가 정말 많이 필요해」).
4. **주민** — [주민 설계](주민_설계.md)(2026-09-20 첫 판: 설정서 양식 · 말 고르기 · 표현 · 세계(싱크 월드) · 이스터에그 · 첫 주민 셋). 남은 것: 다음 주민들(이장님 · 우체부 · 아이 · 고양이 …)의 설정서 · 마을 연대기의 달력 · 세계의 옛이야기.
5. **주민의 기억과 반응** — [행동과 세계 변화](싱크타운_행동과_세계변화_설계.md)·[생활 사건 8개](디자인/싱크타운_생활사건_설계.md)·[첫 생활 구간](디자인/싱크타운_첫생활구간_설계.md)·[상태와 전달 계약](아틀라스_구현명세.md#town-world-contract)을 설계했다. 다음은 C01/C02의 실제 동작·저장·재방문 공통 검증 뒤 첫 쉼터의 네 경로를 각각 완결하고, 플레이어가 자기 선택의 결과를 알아보는지 관찰하는 일이다.
6. **대화 상세** — [대화 설계](대화_설계.md)에 답변 방식, API 없는 입력 분석, 대사 조합, 규칙 교정과 평가 계획을 작성했다. 초기 콘텐츠의 주민·수준·상황별 목록과 주민별 대사 예시를 추가해야 한다.
7. **배경의 설계** — 첫 마을의 생김새 · 장소별 장면 · 절기표 · 날씨표 · 소리 목록(굽기를 맡길 수 있는 크기까지).
8. **심부름 · 방송 · 편지 · 쪽지의 규격과 목록.**
9. **[BM 목록](BM_목록.md)을 이어서 채운다** · **모의시험(EPS 먼저 · TOPIK 다음)** — 메인 화면 쪽의 설계.
10. 확정된 설계를 담당 원문과 구현에 반영하고, 옛 문서의 참조를 해당 원문으로 연결한다.
