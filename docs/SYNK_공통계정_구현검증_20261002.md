# SYNK 공통 계정 — 2026-10-02 구현과 검증

> 10-02 구현·합성 검증의 보존 기록이다. 아래 ‘현재’, 미설정·미배포·Mac 산출물 부재와 운영 전 순서는 당시 범위를 뜻하며, 이미 끝난 운영 설정을 다시 적용하라는 지시가 아니다. 후속 공개·설치·실계정 결과와 Workspace 명칭은 [플랫폼 계정·연결 원문](SYNK_플랫폼_계정과_연결_설계.md), [desktop](../desktop/README.md), [공통 웹](../experiences/synk-account/README.md)에서 확인한다. 당시 AI 20회 제한을 현재 전체 시험 금액 한도나 튜터 활성 상태로 읽지 않는다([AI 호출·비용 원문](SYNK_WORLD_AI_효율화_20261002.md)).

사용자 요청: 하나의 SYNK ID를 공통 기반으로 두고 장기 운영 제안을 실제 코드에 적용한다. 같은 날 후속 요청으로 **SYNK 플랫폼은 설치형 런처, 그 아래 ① SYNK 사내 메신저 ② SYNK WORLD는 독립 클라이언트**로 계층과 실행 형태를 명확히 했다. WORLD의 미니게임·Town·숙제·AI 코칭은 내부 콘텐츠다. Atlas는 인증을 맡지 않고 허용된 학습 근거를 해석한다.

현재 상태는 **로컬 구현·합성 통합 검증**이다. 운영 DB·인증 설정·결제·공개 배포는 변경하지 않았다. 원작업본의 다른 변경을 보존했으며 이 작업으로 커밋·push하지 않았다.

## 실제 적용한 흐름

```text
공통 로그인(기존 Supabase Auth + Code/PKCE)
  → 구현한 인증 소비 경로: 플랫폼 계정 화면 / SYNK WORLD
  → 검증된 인증 주체 ↔ 서버 내부 SYNK ID
  → 계정·소속·이용권 / 학습 기록 연결 동의
  → WORLD 호스트의 계정별 저장과 오프라인 전송 대기
  → 미니게임·맞춤 읽기의 원본 관측 사건
  → 서버 소유권·동의 판·중복·사건 관계 검증
  → 다른 기기의 같은 계정이 복원 → Atlas의 다음 추천
```

미니게임은 WORLD 호스트에서 학습 API를 받아 쓰며 게임별로 로그인하지 않는다. 단독 체험 주소의 기기 기록은 자동으로 계정에 가져오지 않는다. 기존 도움 선호 `atlas-memory`에 수행 데이터를 끼워 넣지 않았다.

## 후속 요청 — 플랫폼과 두 독립 클라이언트

SYNK 플랫폼을 설치한 뒤 WORLD와 사내 메신저를 각각 설치·실행·업데이트하는 구성이 최신 사용자 요구다. **플랫폼·WORLD·메신저 세 실행물 모두 Windows와 macOS를 제작 대상으로 확정**했다. 공통 SYNK ID를 사용하되 각 클라이언트는 별도 앱 식별자·데이터 저장 경로·세션과 서비스별 권한을 갖는다. `experiences/synk-account/platform.html`은 이 방향의 웹 개발 미리보기이며 설치형 런처·클라이언트 패키지·실제 업데이트 검증을 대신하지 않는다. 두 OS의 패키지 생성·서명·설치·실행 검증은 각각 기록한다. 메신저 이름 **SYNK WORK는 제안이며 미확정**이다.

웹 개발 미리보기의 검색·필터·정렬·라이브러리 담기/빼기·즐겨찾기·배움/업무 컬렉션·최근 열기·새 소식·다운로드 상태·앱 상세·설정 관리는 로컬 구현했다. 시작 주소 `http://127.0.0.1:4280/`는 플랫폼으로 연결하며 기존 미니게임 허브는 `/learning-hub/`에 유지한다. 소스는 [platform.html](../experiences/synk-account/platform.html), [platform.mjs](../experiences/synk-account/src/platform.mjs), [library.mjs](../experiences/synk-account/src/library.mjs), [platform.css](../experiences/synk-account/platform.css)다. 기능과 실행 안내는 [브라우저 플랫폼 README](../experiences/synk-account/README.md), [화면 참고 자료와 적용 범위](SYNK_플랫폼_계정과_연결_설계.md#플랫폼-화면-구성과-참고-범위)는 담당 설계에 둔다.

저장되는 UI 설정은 `synk.platform.device-library.v1`의 현재 기기 전용이며 계정 서버나 SSO의 여러 기기 동기화가 아니다. 최근 열기는 웹 페이지 열기/클라이언트 실행 요청 이력이며 게임 플레이·성취 기록으로 표시하지 않는다. 라이브러리 담기는 설치·구매·회사 권한 부여가 아니다. 설치 상태는 데스크톱이 검증한 결과만 사용하고 공개 배포 채널이 없을 때 가짜 다운로드 진행률·설치 완료를 표시하지 않는다.

**후속 플랫폼 검증:** [2026-10-02 QA 기록](../experiences/synk-account/qa/platform-20261002.json)에 계약/정적 서버 시험 **19개 통과·실패 0**, 4개 번들과 승인 자산의 `--check` 일치를 기록했다. CUA 브라우저에서 담기·즐겨찾기·컬렉션·새로고침 후 유지·협업 검색·빈 컬렉션·설치 안내·설정 초기화·좁은 화면의 설정 진입·새 소식 대화창을 확인했다. 1440/390/320px 화면 검수에서 가로 넘침·깨진 그림을 확인하지 않았고 콘솔 오류·경고 목록은 비어 있었다. 저장 실패 뒤 체크 표시가 저장 상태와 어긋나거나 실행 성공 안내가 기록 저장 실패를 덮던 문제를 수정했다. 좁은 화면에서 사라지던 설정 입구는 항상 보이는 footer 링크로 보완했다.

브라우저의 설정 내보내기는 다운로드 이벤트 대기가 시간 초과되어 **실제 파일 저장 완료를 검증하지 못했다**. 데스크톱의 별도 합성 JSON 내보내기 확인과 혼동하지 않는다. 플랫폼·WORLD·메신저의 Windows 개발 패키지와 macOS 빌드 경로, 아키텍처별 산출물·실행·내보내기 증거는 [desktop README](../desktop/README.md)를 정본으로 사용한다.

**앞선 데스크톱 패키지 확인:** Windows x64·ARM64 각각 세 앱, 총 **설치 파일 6개**를 생성했다. 데스크톱 시험 **13개 통과**, 최종 패키지의 코드·CPU·브랜드 아이콘·앱 간 실행 해시 일치를 확인했다. Windows x64의 숨김 Electron 창에서 세 화면과 WORLD의 레이싱 iframe 문서 로드, 플랫폼·WORLD의 합성 JSON 다운로드를 확인했다. 로컬 4280/4191 서버가 필요한 서명 없는 개발판이며 설치 프로그램 실행·설치 후 앱 간 실행·ARM64 실기기 실행은 미검증이다. Mac Intel·Apple Silicon 빌드 설정과 비활성 CI 템플릿은 준비했으나 이 Windows 호스트의 심볼릭 링크 권한 부족으로 **Mac 산출물은 생성하지 못했다**. Mac 빌드·서명·설치·실행 및 정식 SSO·공개 업데이트 연결이 남아 있다. [패키지 검사 결과](../desktop/artifacts/package-verification.json)

기존 로컬 사내 메신저(`tools/company-messenger/`, `127.0.0.1:4191`)의 회사 계정과 권한은 유지한다. 후속으로 현재 회사 비밀번호를 확인해 SYNK ID를 명시적으로 연결하는 코드를 추가했다. 운영 인증 설정·콜백 등록·4191 운영 반영은 완료하지 않았으며, 플랫폼 진입로·로컬 SSO 구현과 운영 완료를 구분한다. 회사 직원의 메신저 이용 권한은 학원 교직원 역할과 별도로 검증해야 하며, 이메일 일치로 기존 메신저 계정을 SYNK ID에 자동 병합하지 않는다. 메신저 대화·파일과 WORLD 학습 원본을 자동 공유하거나 기존 계정 내보내기 범위에 포함시키지 않는다. 아래 294개 시험과 Android 번들 기록은 앞선 공통 계정 구현의 검증이며 설치형 플랫폼이나 메신저 SSO를 검증한 수치가 아니다.

## 후속 요청 — 모바일·PC·웹 공통 로그인

2026-10-02 후속 요청으로 플랫폼·WORLD·사내 메신저의 개발 대상을 **Android·iOS·Windows·macOS·웹**으로 확정했다. 공통 SYNK ID·제품별 권한을 유지하고 환경별 로그인 클라이언트와 세션을 구분한다. PC의 런처/두 독립 클라이언트 구조를 유지하며 모바일에서는 반응형 앱 입구와 홈 화면 추가, 기존 WORLD 네이티브를 연결한다. 지원 대상에 포함했다는 사실은 모든 네이티브 패키지·스토어 출시·실제 기기 검증의 완료를 뜻하지 않는다.

**WORLD 네이티브 인증 감사·보완:** 기존 `synktalk://oauth/callback`과 Expo Code/PKCE·state, SecureStore, 갱신/로그아웃 소비를 확인했다. OAuth 토큰이 회전한 뒤 `/auth/v1/user`가 429/5xx를 반환하면 유효한 저장 자격을 삭제하던 경로를 재현했다. 일시 장애로 분류하고 회전한 refresh 자격을 사용자 조회보다 먼저 보존하며, 재시도에서는 유효한 대기 access로 본인 확인을 다시 한다. 대기 access가 만료되면 가장 최근 refresh를 사용한다. 본인 확인 전에는 사용할 수 있는 계정 세션을 만들지 않는다.

정확한 callback의 scheme/authority/path와 단일 code/state, PKCE verifier를 확인하며 잘못된 native/web 주소·중복 callback 값·URL 토큰을 거부한다. 로그인 화면을 닫거나 계정이 바뀐 뒤 돌아온 응답은 계정을 복구하지 못하게 했다. 변경은 SYNK-talk의 `src/인증API.js`, `src/SYNK로그인.js`, `lib/world-oauth.js`, `tests/synk-auth-session.test.js`, `tests/world-oauth.test.js` 다섯 파일이다. 현재 dirty 원본을 복사한 격리 작업본에서 검증하고 기준 지문을 대조한 뒤 원작업본에 통합했다. 통합 후에는 인증 서버 설정의 불필요한 하위 경로도 거부해 잘못된 token/authorize 주소를 만들지 않게 했으며 해당 helper 시험 5개를 통과했다.

검증 명령은 `node --test tests/synk-auth-session.test.js tests/world-oauth.test.js tests/인증API.test.js tests/사건통로.test.js tests/기기비우기.test.js tests/atlas-session-storage.test.js`이며 **59개 통과·실패 0**이다. 기존 저장 회귀의 첫 5개는 격리 작업본에 원본 의존 파일 두 개가 빠져 `ENOENT`로 종료했으며, 파일을 복사한 뒤 위 명령 전체를 다시 실행해 통과했다. Android/iOS/web의 Babel JSX 변환도 통과했다. 이는 실제 인증 서비스·Android/iOS 실기기·스토어 빌드 검증이 아니다. 공식 동작 근거는 [Expo 인증 안내](https://docs.expo.dev/guides/authentication/)를 참고했다.

**웹 저장 경계:** 기존 Talk 웹 미리보기는 SecureStore를 대신할 인증 지속 저장이 없고 전송 대기 역시 메모리 범위다. 이번에 그 저장 구조 전체를 바꾸지 않았다. 실제 공통 웹 흐름은 `experiences/synk-account/client.html`과 WORLD의 계정/동의 revision별 호스트를 사용한다. 플랫폼·WORLD의 web manifest와 iOS 홈 화면 아이콘을 연결했다. 회사 메신저의 명시적 SYNK ID 연결·모바일 웹 후속은 [공통 웹 README](../experiences/synk-account/README.md)와 [회사 SYNK ID 안내](마케팅/온라인마케팅지도/engagement/company/SYNK_ID.md)를 따른다. 모바일 홈 화면 추가는 네이티브 패키지·푸시·오프라인 전체 지원 완료의 증거가 아니다.

**후속 통합 검증:** 중앙 계정/모바일 관련 **115개(스키마 25·서버 31·모바일 인증 59) 통과**, 실패 0을 원작업본에서 확인했다. `lib/synk-auth.js`의 OAuth client→product 등록부와 제품 헤더 대조, `lib/synk-server.js`의 메신저 최소 계정 조회·현재 세션 폐기, `20261002120000_synk_messenger_identity_c16.sql`과 L0 합본을 반영했다. 메신저 자격으로 WORLD 학습 API·학습 내보내기·다른 서비스의 계정 변경을 사용할 수 없다. 이 등록부는 회사 직원 권한을 대신하지 않으며 회사 서버의 별도 권한 검사를 유지한다.

**로그아웃의 로컬/서버 결과 분리:** 계정 화면이 서버 철회 성공을 기다려야만 로컬 로그아웃 함수를 부르던 경로를 고쳤다. `account-view.mjs`의 현재 제품·현재 세션 행·전체 종료는 호스트에 종료 범위를 전달한다. 브라우저·중앙 계정·데스크톱 호스트가 로컬 종료와 서버 철회를 각각 처리하며, 서버가 오프라인이어도 로컬 자격을 정리하고 서버 종료 미확인을 안내한다. 다른 기기를 종료하는 조작은 현재 기기 로그아웃으로 바꾸지 않았다. 브라우저 저장 삭제 실패, SDK 로컬 저장 부재를 확인하지 못한 경우, `refreshRevoked:false`, 전체 종료의 기존 앱 보호 미확인을 성공으로 숨기지 않는다. 철회 대기 중 다른 탭에서 들어온 새 계정을 이전 요청이 지우지 않는 것도 확인했다.

웹의 중간 25개 시험 뒤 로그아웃 회귀를 추가한 37개를 통과했고, 아래 정상 갱신 보존 회귀 3개를 더해 최종 **40개(웹 패키지 38·정적 서버 2) 통과**, 실패 0을 확인했다. 명령은 `node --test experiences/synk-account/tests/*.test.mjs tests/learning-hub-server.test.js`이며 최종 `build`/`--check`도 통과했다. [로그아웃·갱신 DOM·실제 클라이언트 시험 15개](../experiences/synk-account/tests/account-logout.test.mjs)는 실제 `client.mjs` 번들, `mountPortal`, 설치된 공식 Auth SDK의 서버 503 시 로컬 저장 제거를 실행한다. 별도의 화면 미리보기는 실제 서버를 바꾸지 않았다고 안내하며 브라우저 fixture의 게임 수를 현재 여섯 개로 맞췄다. 위 115개와 40개는 이전 294개·플랫폼 19개·데스크톱 13개의 후속 실행 묶음이며 과거 숫자와 합산하지 않는다. 실제 계정·Mac/iOS 실기기·운영 배포 검증은 아니다.

**정상 인증 갱신 중 학습 유지:** 데스크톱 main의 정상 갱신은 같은 `sessionGeneration`으로 `restoring`을 알린다. 이미 열린 계정 뷰가 그 세대에 속하고 오류가 없으면 기존 WORLD 호스트와 게임 iframe을 유지해 토큰 갱신 때문에 게임이 재시작되지 않게 했다. 갱신 뒤에도 iframe 객체·게임 주소·학습 호스트·요청 guard가 그대로임을 VM에서 확인했다. 새 세대·다른 계정·로그아웃·철회/오류에서는 이전 호스트와 iframe을 폐기하는 검사를 유지한다. 최종 40개 시험 뒤 재빌드/check를 통과했고, 실제 HTTP로 제공되는 번들의 SHA-256 일치는 [데스크톱 웹 연결 검증](../desktop/artifacts/desktop-web-contract.json)에 기록했다.

**이번 데스크톱 후속:** 데스크톱 시험 **31개 통과**, 플랫폼·WORLD·메신저 세 앱의 Windows DPAPI 자격 보관 검사를 확인했다. Windows **0.2.0 x64·ARM64 각각 세 앱, 개발 설치 파일 총 6개**를 생성하고 패키지·해시 검증을 통과했다. 기존 0.1 패키지는 보존했다. 현재 `authConfigured:false`이며 운영 OAuth 설정이나 실제 계정 로그인을 완료한 상태는 아니다. 서명·설치 프로그램 실행·설치 후 앱 왕복·ARM64 실기기 검증은 남아 있다. **Mac 산출물은 아직 없다.** 최신 근거와 OS별 제한은 [desktop README](../desktop/README.md) 및 [패키지 검사 결과](../desktop/artifacts/package-verification.json)를 따른다. 회사 메신저는 별도 최종 관련 7개 파일 **77개 통과·실패 0**을 확인했다. 브라우저 메모리 refresh 회전·장애 복구·만료 후보 재갱신, 회사 세션과 기기 자격의 종료, 실제 desktop main과 UI의 최초 로그인 상태 전환을 합성 HTTP/VM에서 검사했다. 휴대폰 390px의 직원 로그인·SYNK ID 연결 안내를 임시 DB 서버에서 CUA로 확인하고 서버를 종료했다. 운영4191과 실제 회사 자료는 변경하지 않았다. 장기 비활성 뒤 데스크톱 회사 재로그인이 필요한 경계는 [회사 SYNK ID 안내](마케팅/온라인마케팅지도/engagement/company/SYNK_ID.md)에 기록했다. 이번 검증 묶음·설정 상태·소스 지문은 [통합 QA JSON](../experiences/synk-account/qa/unified-auth-20261002.json)을 따른다.

- 최종 공통 엔진/동기화/호스트/정적 서버 **45개 통과**, 실패·건너뜀 0. 저장 공간 실패·20,000사건 한도·같은 ID 원본 충돌 이후에는 완료 표시를 거두고 연결을 차단한다. [실행 기록](../experiences/synk-account/qa/atlas-integration-final.txt)

- 전체 Android 프로덕션 JS 번들 생성 통과: **2,066모듈·101자산**. 새 native 의존성이 있으므로 앱 버전 **0.2.0**으로 올렸고 기존 0.1.0 runtime용 OTA로 내지 않는다. APK 빌드·설치·실기기 SSO 검증은 아니다.

## 운영으로 넘길 때의 순서

1. 별도 검증 프로젝트에서 마이그레이션·Edge 함수와 정확한 공개 설정을 적용한다. 기존 인증 통로 전체 기기 차단은 관련 함수 재배포 후 `SYNK_ACCOUNT_GUARD=1`로 연다. 개별 기기 해제의 즉시 차단은 새 공통 API 범위이며 옛 경로의 같은 보장을 주장하지 않는다.
2. Supabase OAuth 서버, 플랫폼/WORLD의 등록 클라이언트, 브라우저/네이티브 콜백과 인증 UI를 설정한다. 공급자의 OAuth 서버는 현재 beta 안내이므로 운영 도입 판단과 복구·철회 인수 확인이 필요하다. [공식 안내](https://supabase.com/docs/guides/auth/oauth-server/getting-started)
3. 새 네이티브 빌드와 브라우저에서 동일 실계정으로 로그인·학습·종료·오프라인·재전송·다른 기기 복원·계정 전환·철회를 확인한 뒤 `learningSync`를 소수부터 연다. 기본 정책에서는 꺼져 있다.
4. 실구매/환불·삭제 처리·운영 복구 절차와 장기 기록 규모를 별도로 인수한다. Town 실제 장면, 숙제/AI 코칭이 미니게임의 근거를 소비하는 연결과 학생 효과 검증도 이어서 완성한다.

현재 서버가 원본 사건 구조와 소유권을 검증하지만, 클라이언트가 보낸 언어 정오를 시험 성적처럼 독립 채점한 것은 아니다. 추천용 연습 관측과 시험/보상 자격 판정은 구분한다.
