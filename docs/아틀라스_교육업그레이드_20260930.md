## 2. 새 게임이 엔진을 쓰는 법

레이싱처럼 문항이 빠르게 이어지는 게임도 같은 순서로 쓴다. 채점은 게임이 하고, 엔진은 기록·도움 정책·집계만 맡는다. 외부 AI 호출은 0이다. 게임은 기기에 두 가지를 저장한다: 지난 판까지의 **기록**과, 진행 중인 판에서 쌓는 **미결 기록**이다.

1. **판을 시작할 때** `history = Trail.openHistory(기록, 미결 기록)`
   - 처음 하는 학습자면 기록으로 `{ records: [], partial: false }`를 넘긴다.
   - 이 기기에 기록이 없는 기존 계정이면 `{ records: [], partial: true }`를 넘긴다. 다른 기기에서 본 문항을 알 수 없으므로 혼자 해낸 것으로 세지 않는다.
   - 그 밖에는 지난번에 저장한 값을 넘긴다. 읽기에 실패했거나 깨진 값이면 ‘모름’으로 열리고, 그 판에서는 혼자 해낸 것으로 세지 않는다.
   - 미결 기록은 지난번 판이 끝나기 전에 앱이 꺼졌을 때 남은 것이다. 본 문항으로 함께 센다.
2. **문항을 낼 때** `practice = Core.createPractice({ session, decision, map, task, assess, firstExposure: history.firstExposure(task.itemKey) })`
   - `task = { id, version, itemKey, tags, concepts }`. `itemKey`는 문항 내용의 고정 지문이다. `concepts`는 Strata 마디 id이고, 첫 번째가 그 문항의 대표 학습 항목이다. 없으면 `[]`를 넘긴다.
   - `assess(응답)`은 `{ verdict: 'correct'|'incorrect'|'unassessed'|'skipped', errorTags }`를 돌려준다. 채점을 모르는 답은 `unassessed`로 둔다.
3. **막히면** `Vellum.offerCue({ support, elapsedMs, misses, offered, declined, hasCue, stuck })`가 참일 때 권한다.
   - 한 문항에 한 번만 권한다(`offered`). 한 번 거절하면 그 판에서는 더 권하지 않는다(`declined`, 설계 §8-5).
   - ‘먼저 혼자 해 보기’를 고른 학생에게는 권하지 않는다.
   - 무엇을 막힘으로 볼지(`stuck`)는 게임마다 정한다. 화면에 시계를 띄우지 않는다.
   - 힌트를 보여 주면 `practice.delivered({ id: 'stuck', level: 'cue', contentRef })`를 부른다. 기록에 실패하면 그 문항은 이후 답이 있어도 기록하지 않는다(도움받은 답이 혼자 푼 답으로 둔갑하지 않게).
4. **답을 내거나 정답을 보여 준 직후** `practice.submit(응답)`으로 답을 기록하고, `practice.met()`을 미결 기록에 바로 덧붙인다. 판 도중에 앱이 꺼져도 다음에 이 문항을 ‘이미 본 문항’으로 안다. 응답 원문은 기록에 들어가지 않는다.
5. **판이 끝나면**
   - `summary = Trail.summarize(session.events(), { ...session.state(), decisions: [decision.id] })`로 **이번 판만** 정리한다. 같은 앱 실행에서 판을 여러 번 해도 앞 판을 다시 세지 않는다.
   - `Trail.growth(summary, history)`가 학생에게 알려 줄 사실을 돌려준다(판을 시작할 때 연 `history`를 쓴다).
   - `next = Trail.remember(history, summary)`가 값을 돌려주면 그것을 기록으로 저장하고 미결 기록을 비운다. `null`이면 기록을 읽지 못한 경우이니 원래 저장값을 그대로 둔다.
   - 필요하면 `Temper.measure(summary)`로 센다.
6. **결과 화면에서는** `Vellum.reviewOpen({ verdict, support, retried, hasCue, unsure })`가 무엇을 바로 열지 정한다.
   - 기본은 정답과 해설을 바로 보여 준다.
   - ‘하나씩 살펴보기’·‘먼저 혼자 해 보기’를 고른 학생에게는 힌트부터 보여 준다.
   - 다시 쓴 문항은 결국 정답으로 끝나고, 맞힌 문항은 아무것도 열지 않는다.

교육 앱에서는 `atlasGameSession(학생번호, '<게임 id>')`로 세션을 얻는다. 화면용 훅 `use아틀라스게임`은 지금 편지 연습·서류 관문만 받는다(계정에 저장하는 도움 방식이 `atlas/preferences.js`에 경험마다 등록돼 있다). 새 게임이 도움 방식을 계정에 저장하려면 그 표에 게임을 더한다. 위 흐름 전체를 talk `tests/atlas-practice.test.js`가 실제 세션 통로로 확인한다. 한 판, 두 판 연속, 판 도중 종료, 새 기기, 계정 전환을 다룬다.

저장하는 기록에는 문항마다 `{ itemKey, conceptIds, at, verdict }` 네 칸만 있다. 응답 원문, 도움 글, 학생 식별값은 넣지 않으며, 다른 칸이 섞인 기록은 읽지 않는다.

## 2-1. 선택 ID와 화면 노출 조회 — 2026-10-07 로컬 계약

게임은 기존 `coach.answer(pid, { correct, assessable, ... })`에 선택적으로 `choice: { selectedId, correctId }`를 더할 수 있다. 두 값은 원고에 고정된 보기 ID이고, 영문·숫자로 시작하는 1~80자의 영문·숫자·`_ . : -`만 허용한다. 응답 텍스트·학생 식별값·임의 추가 필드는 넣지 않는다. `Core.createPractice`를 직접 쓰는 소비처는 `practice.submit(response, { choice })`로 같은 메타데이터를 전달한다.

선택 ID는 `practice.attempted` 사건, Trail의 원문 요약행, `coach.answer` 반환값에 복사되어 남는다. 문항 키·원고 판은 연결된 presentation의 `itemKey`·`taskVersion`을 사용한다. 채점은 기존 `correct`/`assess`가 계속 맡으며 ID 두 개의 같고 다름으로 판정·도움·반복·독립 수행 자격을 바꾸지 않는다. 같은 시도 번호의 재전송은 처음 기록을 그대로 돌려준다. 선택한 오답을 학생의 오개념으로 진단하지 않는다. 선택 ID를 넣지 않은 과거 사건·호출은 그대로 읽는다.

최근 원문 사건의 선택 상세는 기기 재개와 계정 동기화에 보존한다. 오래된 완료 문항을 압축한 기존 원장은 정오·도움·노출·최근 집계만 남기므로 그 구간의 선택 상세를 복원하지 않는다. 선택 ID를 무한히 기기에 저장하지 않는다. 동기화하는 계정은 서버가 받아 돌려준 사건만 압축하므로 서버 원문에는 선택 상세가 남는다. 서버에 보내지 않은 과거 기기 압축 기록을 계정 기록으로 올리지 않는 경계도 유지한다.

`coach.exposure(itemMetadata)`는 `{ seen: true | false | null }`을 돌려주는 읽기 전용 조회다. 같은 `itemKey` 또는 `familyKey`의 화면 제시·응답·정답 공개가 있으면 압축된 제시 이력까지 포함해 `true`다. 미관측이고 저장 가능한 이력이 완전하면 `false`, 미관측이지만 이력이 불완전하거나 읽기/저장을 보장할 수 없으면 `null`이다. 답 없이 닫은 문항도 처음 보여 주는 문항으로 표시하지 않는다. 이 화면 노출 조회를 추가하면서 기존 Trail의 독립 응답 자격 정책은 바꾸지 않았다. WORLD는 같은 계정·수행 가드 아래 이 조회를 전달하고 끝난 수행은 접근을 거절한다.

이 계약은 로컬 구현·회귀 시험 범위다. 생성 게임 묶음·서버 사본 반영, 실제 화면 왕복과 운영 배포는 각각 따로 확인한다. 과거 선택 상세가 생겼거나 실제 학생의 전이·학습 효과가 검증됐다는 뜻은 아니다.

## 2-2. 의도적으로 연결한 새 문항의 결과 — 2026-10-07 로컬 계약

`coach.recheck(sourceAttemptId, targetAttemptId)`는 소비처가 오답·도움 뒤 확인용으로 고른 두 실제 응답을 읽기 전용으로 비교한다. 단순히 시간상 뒤에 나온 정답을 이전 오답과 연결하지 않는다. 입장 검사·바람길 별도 듣기 확인·Town 읽기·레이싱은 회차 안에서 의도적으로 배정한 새 문항에만 이전 응답 ID를 전달한다. 연결 관계를 별도 사건으로 저장하거나 재접속 뒤 자동 복원하지 않는다.

결과는 `independent-correct`, `independent-incorrect`, `assisted-correct`, `assisted-incorrect`, `unavailable` 중 하나다. 사용자에게는 다른 새 문항을 도움 없이/도움을 보고 맞혔는지 또는 틀렸는지를 표시한다. 두 응답과 필요한 제시·완료 원문, 시간 순서, 같은 게임·원고 판·영역·난도·응답 형식·매체를 확인한다. 대상은 다른 문항·문항군의 첫 화면 노출과 첫 응답이어야 한다. 도움 없는 정답을 출발점으로 삼거나 같은 문항 재시도를 새 확인으로 세지 않는다.

최근 원문이 압축되어 필요한 사건이 없거나 이력을 읽고 저장할 수 없을 때, 기록이 불완전하거나 시간 관계가 맞지 않을 때는 `unavailable`이다. WORLD는 기존 계정·수행 가드로 전달하므로 수행이 이미 끝난 뒤의 조회는 거절할 수 있다. 소비처는 조회 실패를 성공 문구로 바꾸지 않는다. 응답의 최초 정오·도움·반복 판정, 학습 집계와 추천 정책은 바뀌지 않는다.

`correctionObserved`와 `correctionEventIds`는 두 문항 사이에 정답 공개 사건이 기록됐는지만 뜻한다. 글을 실제로 읽었는지, 해설 때문에 배웠는지의 증거가 아니다. 모든 반환에 `learningEffectClaim: false`를 둔다. 공통 조회는 동일한 세부 규칙·문형까지 보장하지 않으며 소비처가 후보를 좁힌다. 같은 영역이더라도 규칙·문형이 다른 문항을 같은 오답의 교정 효과로 집계하지 않는다. 실제 학생의 효과 검증과 장기적인 교정 전후 추적은 별도다.
