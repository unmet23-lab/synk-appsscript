- 고침: 비밀값이 보일 수 있는 화면은 DOM을 변수에 받아 알려진 비밀값을 지운 뒤 필요한 상태만 출력한다. 값 자체는 관찰한 입력/textarea에서 읽어 저장소 밖 설정 파일에만 저장한다. 노출된 토큰은 로컬 설정에서 제거했으며 사용자 직접 교체 완료 후 새 값이 이전 값과 다른지 확인해 저장한다. 기존 인증정보 교체의 최종 동작은 브라우저 도구의 사용자 직접 처리 규칙을 따른다.
- 다시 확인: 10-17 사용자가 교체 완료를 알린 뒤 새 토큰이 이전 값과 다른 것을 확인해 출력 없이 저장했다. 전용 설정6항목·실제 Cloud 읽기 인증·ngrok 기동, 공개 HTTPS의 Chrome 로그인·메신저 직접 주소 실시간 수신을 확인했다. 최초 설정이 아닌 새 토큰으로 실행했다.

### Codex Chrome 확장이 로컬 파일 업로드를 차단한다
- 증상: 10-17 `fileChooser.setFiles`가 ChatGPT 확장의 「파일 URL에 대한 액세스 허용」이 필요하다고 종료했다.
- 원인: 해당 Chrome 확장에 로컬 파일 읽기 설정이 꺼져 있었다.
- 고침: 검증된 업로드 사본을 먼저 준비한 뒤 유호님이 확장 세부정보에서 설정을 켰다. 확장 재연결로 브라우저 ID가 바뀌면 새 목록의 같은 프로필·같은 탭을 다시 연결하고, 업로드 단추를 누르기 전에 filechooser 이벤트를 받는다.
- 다시 확인: v22 보존본 76,595바이트 업로드 완료를 화면에서 확인하고 실제 재다운로드 SHA256까지 원본과 대조했다. 계정·설정·크기가 다른 다음 작업에는 그 조건을 다시 확인한다.

### Drive 검색 결과에 파일명과 무관한 자료가 섞인다
- 증상: 10-17 원본 파일명을 검색했는데 본문 관련 자료가 섞였고, OR로 파일명을 묶은 검색은 필요한 묶음이 되지 않았다. 파일 미리보기 주소는 빈 화면이기도 했다.
- 원인: 기본 검색은 제목만 제한하지 않으며 미리보기 화면의 즉시 로드도 보장되지 않는다.
- 고침: 기존 부모 폴더 또는 검색 화면의 「제목만」 필터로 대상 이름·위치를 확인했다. 클릭 직후 결과는 한 박자 늦을 수 있어 다음 선택 전에 갱신된 결과를 읽었다.
- 다시 확인: 제목만 검색으로 첫 퀴즈와 이름이 같은 그림의 실제 상위 폴더가 둘째 편임을 확인해 원본 대체에서 제외했다. 내려받은 파일은 별도로 보관 당시 SHA256과 대조한다.

Claude의 인터넷 작업은 앱 안 브라우저가 기본이고, 막힐 때(구글 로그인 팝업 등)와 크롬에만 로그인된 사이트(SNS 게시 포함)만 크롬에서 한다. GPT는 크롬에서 한다(10-18, [AI 운영 원칙 · 공식 하네스](../AI_운영원칙.md#공식-하네스)). 올리기·예약·공개·결제·약관 동의는 그 요청에서 분명히 승인받은 범위로만 하고, 로그인·가입·인증서 서명·보안 확인(CAPTCHA)은 유호님이 한다([비용과 권한](../AI_운영원칙.md#비용과-권한)). Suno 곡을 고르고 박자에 맞춰 자르는 방법은 [만족 사례 장부](../마케팅/제작양식/만족사례_장부.md) S16·S17이 정본이다. 여기는 크롬 확장·웹 화면·게시 API가 예상과 다르게 움직인 함정이다. 가려진 창·확장 새 창 문제는 [시험·화면 확인](시험_화면확인.md#화면-확인)에도 있다. 틀은 [README](README.md)를 따른다.

## 크롬 확장 공통

### 기존 연결도 확장 업데이트 요구가 나오면 더는 조작할 수 없다
- 증상: 10-18 PULSE 기존 링크를 열고 계정 로그인까지 진행하던 중 팝업 클릭이 `Input.dispatchMouseEvent` 시간 초과로 실패했다. 이후 브라우저 도구가 `Please update the ChatGPT extension in Google Chrome to the latest version to continue.`를 반환했다.
- 원인: 도구가 확장 업데이트를 요구한 것은 확인했다. 팝업 시간 초과의 직접 원인과 설치 버전 차이는 확인하지 못했다.
- 고침: 막다른 길 — 게시를 성공으로 처리하지 않고, 검증한 HTML·SHA-256·기존 주소를 실행별 폴더에 보존했다. 사용자에게 ChatGPT Chrome 확장 업데이트와 기존 게시 계정 로그인을 요청했다. 업데이트 완료와 재연결은 아직 확인 전이다.
- 다시 확인: 연결이 복구되면 기존 주소·게시 계정부터 확인하고 같은 주소를 갱신한 뒤 실제 링크의 공유·문의·스와이프를 확인한다. 이번 준비 기록은 `.tmp/qa-runs/pulse-casting-publication-20261018T072139468Z-11220-xmrTGa/result.json`이며 원격 쓰기·라이브 검증은 모두 false다.

### Claude 계정을 바꾸면 크롬 확장이 끊긴다
- 증상: 10-18 10:39 Claude 데스크톱 앱 계정을 바꾼 직후 Claude in Chrome 도구 호출 3번(10:40·10:45·10:46)이 모두 `NoExtensionConnectedError`(「No Chrome extension connected after discovery」)로 실패했다. 10:48에 확장이 다시 붙은 뒤에야 풀렸다. 유호님 말로는 계정을 옮길 때마다 되풀이된다.
- 원인: 앱은 크롬 연결 주소(`wss://bridge.claudeusercontent.com/chrome/<계정 ID>`)를 지금 로그인한 앱 계정으로 정한다. 크롬 확장은 앱과 따로 claude.ai 계정에 로그인돼 있어서, 앱 계정만 바뀌면 확장은 이전 계정 쪽에 남는다. 근거는 앱 로그 `%LOCALAPPDATA%\Claude\logs\main.log`의 `[claude-in-chrome]` 줄과 같은 시각의 `[account]` 줄이다.
- 고침: Claude는 앱 안 브라우저를 기본으로 쓴다(앱의 일부라 계정을 따라간다). 크롬은 앱 안 브라우저에서 막힐 때와 크롬에만 로그인된 사이트에서만 쓰고, 그때 확장이 안 붙으면 유호님께 크롬 사이드 패널의 Claude 확장을 지금 앱 계정으로 다시 로그인해 달라고 한다.
- 다시 확인: 계정을 바꾼 뒤 `main.log`에서 `Connecting to bridge` 주소의 계정 ID가 새 계정 폴더(`claude-code-sessions\<계정 ID>\…`의 `Loaded N persisted sessions` 줄)와 같은지 본다. 앱 안 브라우저의 사이트 로그인은 계정별 폴더가 아니라 공용 `Partitions\launch-preview-cowork-shared` 하나로 보여 계정을 바꿔도 남을 것으로 보이지만, 계정 전환 뒤 실제로 남는지는 아직 확인하지 않았다.

### 앱 안 브라우저 창이 닫혔다 다시 열리면 ChatGPT 로그인이 사라진다
- 증상: 10-18 유호님이 앱 안 브라우저에서 ChatGPT(unmet23)에 로그인했고, 다음 턴에 시험용 GPT 초안까지 저장됐다. 그다음 턴 시작에 `tabs_context`가 `browserOpen: false`였고, `preview_start`(결과 `reused: false`)로 다시 열자 `/api/auth/session`에 사용자가 없었다. 앞서 「비필수사항 거부」로 닫은 쿠키 안내도 다시 떴다.
- 원인: 미확정. 공용 파티션의 `Cookies` 파일은 이 일 직후에도 시각이 바뀌어 디스크에 쓰이고 있었다. 쿠키 이름·만료를 직접 보려던 조회는 자동 모드 분류기가 자격 증명 탐색으로 막아 보지 못했다.
- 고침: 로그인이 필요한 사이트 작업은 창을 닫지 않고 한 번에 끝내도록 유호님께 부탁한다. 다시 풀리면 크롬으로 넘긴다(「막힐 때」). 로그인 여부는 화면 대신 그 사이트의 세션 응답(ChatGPT는 `/api/auth/session`의 `user.email`)으로 본다. 다시 로그인한 뒤에는 같은 창에서 GPT 게시·마이그레이션까지 끝났다(10-18).
- 다시 확인: 로그인한 뒤 창을 일부러 닫았다 열고 `/api/auth/session`의 `user`가 남는지 본다. 남으면 이번 일은 다른 원인(파티션이 다른 새 창 등)이다.

### 앱 안 브라우저 창이 가려져 있으면 화면이 몇 초 늦게 그려진다
- 증상: 10-18 `tabs_context`가 「Browser pane is currently hidden」일 때 chatgpt.com 편집 화면을 열자 스크린샷이 검은 화면이었다(로그인된 상태, 본문 글은 4초 뒤 `innerText`로 읽힘). 「만들기」를 눌러도 다음 스크린샷에 창이 없어 클릭이 안 먹은 줄 알았는데, 다른 곳을 한 번 더 누른 뒤 찍자 공유 창이 떠 있었다. 콘솔에는 `AbortError: Transition was skipped`가 남았다.
- 원인: 가려진 창은 배경 페이지처럼 그리기가 늦게 돈다(`visibilityState`는 `visible`로 나와 믿을 수 없다). 클릭 자체는 들어간다.
- 고침: 클릭 뒤 스크린샷만 보고 「안 눌렸다」고 판단하지 않는다. `[role=dialog]`나 바뀐 글을 JS로 읽어 확인하고, 2~4초 기다려 다시 찍는다. 같은 단추를 연달아 누르지 않는다(게시·마이그레이션은 두 번 눌리면 안 된다). 유호님께 무언가를 부탁할 때만 Ctrl+Shift+B로 창을 띄워 달라고 한다.
- 다시 확인: 캡처용 화면은 `resize_window`로 창보다 작은 크기(폭 800)를 주면 1:1로 찍힌다. 창보다 크게 주면(1280×860) 800 폭으로 줄여 찍혀 글자가 흐리다. `computer` `zoom`은 그 영역을 PNG로 잘라 준다(확대가 아니라 자르기). 다 찍으면 `preset: desktop`으로 되돌린다.
- 두 번째(10-18 12:1x, Gemini 77yuhbs): 같은 세션에서 한 시간 넘게 Gemini 이미지 대화를 이어 쓰다가, 턴이 끝나고 다음 턴에 `navigate`가 `reused: false`로 창을 새로 열자 로그아웃 상태(「로그인」 단추, 모드 3.5 Flash-Lite, 대화 주소가 `/app`으로 튕김)였고 그 창에서 넣어 둔 `localStorage`도 비어 있었다. 쿠키만이 아니라 저장소 전체가 새 파티션처럼 비었다. 앱 안 브라우저로 로그인 사이트 작업을 할 때는 한 턴 안에 끝내거나, 턴을 넘길 때 로그인이 풀릴 수 있다고 미리 말씀드린다.

### 앱 안 브라우저에서는 그림 파일을 페이지에 넣을 길이 없다
- 증상: 10-18 Gemini 이미지 대화에 참고 사진 6장을 넣으려 했다. 앱 안 브라우저 도구에는 `file_upload`가 없다. 우회도 모두 막혔다: 페이지 JS에서 cloudfront 주소 `fetch`는 「Failed to fetch」, `<img crossOrigin>` 로드는 오류(Gemini CSP), `window.open`은 팝업 차단(null), 윈도우 클립보드에 파일 목록(`SetFileDropList`)을 올리고 `computer key ctrl+v`를 눌러도 `paste` 이벤트가 오지 않았다. 입력창에 `innerHTML`을 넣는 것도 TrustedHTML로 막힌다.
- 원인: 앱 안 브라우저는 파일 선택 창·붙여넣기 명령을 다루지 않고, 대상 사이트의 CSP가 외부 주소에서 그림을 가져오는 길을 막는다.
- 고침: 참고 사진이 이미 첫 메시지에 붙어 있는 Gemini 대화를 열어 그 대화에 이어서 요청한다(「Use the first four photos attached to my first message …」, 「a brand-new image, not an edit of your previous image」). 같은 장면·사람이 잘 이어졌다. 새 참고 사진이 꼭 필요하면 크롬(확장 `file_upload`)으로 넘긴다. 긴 지시문은 `insertText`·붙여넣기 이벤트로 넣으면 문단 사이 줄바꿈에서 잘리니, `.ql-editor`의 자식을 지우고 문단마다 `<p>`(`textContent`)와 빈 `<p><br></p>`를 만들어 붙인 뒤 `input` 이벤트를 보낸다. 받기 단추(「원본 크기 이미지 다운로드」)는 그림에 마우스를 올려야 화면 안 좌표가 생기니, 그림 윗부분이 보이게 스크롤한 뒤 `find` 참조로 누른다. 받은 파일은 잠깐 GUID `.tmp`였다가 `Gemini_Generated_Image_*.jpg`로 이름이 바뀐다.
- 다시 확인: 같은 대화에서 4b·5a·5b·7·6 시작·끝 6장을 1536×2752로 받았다(10-18).

### 확장이 붙은 프로필에 그 사이트 로그인이 없다
- 증상: 유호님은 「로그인 다 했어」라고 했는데 확장 탭의 facebook.com은 로그인 화면이었다(10-03).
- 원인: 옛 노트북 크롬에 프로필이 여섯 개 있었고, 그중 둘이 같은 이름 「유호」였다. SNS 로그인은 한쪽(`Profile 2`)에만 있었는데 확장은 로그인이 없는 다른 쪽(`Default`)에 붙어 있었다. 두 프로필 모두 확장이 깔려 있어 같은 브라우저처럼 보였다.
- 고침: 게시를 시작하기 전에 확장 탭에서 그 사이트의 로그인 상태부터 본다. 로그인이 없으면 로그인된 프로필 창(`chrome.exe --profile-directory="<폴더 이름>" <주소>`)에서 사이드 패널을 열어 확장을 그쪽에 붙인다. 로그인 여부는 쿠키 이름과 만료만 읽어서 확인하고, 값은 읽지 않는다.
- 다시 확인: PowerShell `(Get-Content "$env:LOCALAPPDATA\Google\Chrome\User Data\Local State" -Raw | ConvertFrom-Json).profile.info_cache`로 프로필 폴더와 이름을 본다. 10-17 새 노트북에는 `Profile 1 = 유호` 하나뿐이다.

### 뒤로 열린 탭·가려진 창에서는 게시 화면이 멈춘다
- 증상: 확장이 만든 탭에서 스크린샷이 30초 시간 초과로 끊긴다. 크롬이 다른 앱에 완전히 가려지면 유튜브 예약 날짜 팝업이 열리지 않고, 인스타 만들기는 영상을 넣어도 다음 단계로 넘어가지 않는다(10-07·10-13). Flow 캡처도 30초씩 멈췄다.

### 대화에서 Argon을 골라도 기존 예약의 집행 모델은 확인되지 않는다

- 고침: 1440×900 이상 넓은 창에서 한다. 칸은 `find` → `form_input`으로 채운다(React 상태까지 바뀐다). 가사 칸을 비우면 연주곡이 된다.
- 다시 확인: 「More Options」 요약에 넣은 값이 보이는지 본다.

### 처음 Create를 누르면 「사람인지 확인하십시오」가 뜬다
- 증상: Cloudflare 확인 창이 뜨고 생성이 멈춘다(10-13).
- 원인: 처음 생성할 때 Suno가 봇 검사를 건다. 창이 가려져 있으면 확인도 진행되지 않는다.
- 고침: AI가 누르지 않는다. 유호님께 크롬 창을 앞에 띄우고 눌러 달라고 한다. 한 번 통과하면 다음 생성은 바로 됐다.
- 다시 확인: 통과한 뒤 두 번째 Create에서 확인 창이 다시 뜨는지 본다.
- 10-18 앱 안 브라우저: 구글 로그인은 같은 화면에서 넘어가 돼서 77yuhbs로 들어갔지만, Create 뒤 Cloudflare Turnstile 확인을 유호님이 눌러도 「또 확인하라」가 끝없이 되풀이됐다(Create 단추는 계속 돌기만 하고 곡은 생기지 않음, 청구 없음). 앱 브라우저의 사용자 에이전트에 `Claude/2.x … MSIX`가 붙는다. 우회(에이전트 바꾸기 등)는 하지 않는다 → **Suno 만들기는 크롬에서만 한다.** 앱 브라우저에 걸린 만들기는 다른 주소로 옮겨 끊어 둔다(나중에 통과해 곡이 겹치지 않게).

### 내려받지 않고 곡 소리를 재려 하면 음원 주소가 막힌다
- 증상: cdn 음원을 fetch하면 CORS로 막힌다. 스트림 m4a는 `decodeAudioData`나 `<audio>`로 풀리지 않는다. cdn1 주소를 curl로 받으면 403 MissingKey다(10-07·10-13).
- 원인: 음원 주소에 서명이 필요하고, 플레이어는 MSE blob으로 곡을 튼다.
- 고침: 플레이어의 `<audio crossOrigin=anonymous>`에 `createMediaElementSource`와 ScriptProcessor를 연결한다(스피커로는 내보내지 않는다). 곡마다 30초씩 재서 BPM과 박 선명도를 견준다. 곡 줄의 재생 단추는 `[role=button][aria-label^="Play "]`다. 다운로드 횟수는 쓰지 않는다.
- 다시 확인: 곡 목록에서 그 선택자로 재생 단추가 잡히는지 본다.

### 플레이어 소리로 잰 첫 박이 반 박 어긋난다
- 증상: 플레이어 소리로 잰 첫 박이 받은 WAV와 0.25초(반 박) 어긋났다. 뒷박에 맞춰져 있었다(10-13).
- 원인: 모른다. 스트림 시작 지연으로 보인다.
- 고침: 박 위치는 받은 WAV로 다시 잰다. 저역(150Hz) 킥 어택을 박마다 재서 격자를 잡고, 이음매는 킥 앞의 조용한 틈에 둔다.
- 다시 확인: 같은 곡을 두 방법으로 재서 첫 박 시각을 견준다.

### 내려받을 때 횟수가 더 줄거나 Download 메뉴가 보이지 않는다
- 증상: 다운로드 창에서 형식 여러 개가 함께 골라져 있다. 앱을 다시 켜면 로그인이 풀리거나 다른 계정으로 로그인되어, 곡 ⋯ 메뉴에 Download가 보이지 않는다(10-13).
- 원인: 형식은 여러 개를 함께 고를 수 있다. Download·Publish·Move to Trash는 곡 주인 계정에만 나온다.
- 고침: 형식은 하나만 남기고 「Unlock & Download」를 누른다(곡당 한 번 차감되고, 같은 곡은 다시 받아도 줄지 않는다). 받기 전에 왼쪽 메뉴의 프로필 이름이 곡 주인과 같은지 본다. 표지 위의 ↓ 단추는 음원이 아니라 그림을 받는다. 생성 한 번(2곡)에 10크레딧이 든다.
- 다시 확인: suno.com/account에서 받기 전과 후의 남은 다운로드 수를 견준다.

### 받은 WAV가 GUID 이름의 `.tmp`로 남는다
- 증상: Claude 앱 안 브라우저에서 받은 WAV가 다운로드 폴더에 GUID 이름의 `.tmp`로 남고, 이름이 바뀌지 않았다(10-13). 10-17 크롬(확장 탭)에서는 `MORU 여름 B 펑크.wav`처럼 곡 이름 그대로 받혔다.
- 원인: 모른다. 앱 안 브라우저의 받기 처리 탓으로 보인다.
- 고침: 크롬에서 받는다. 어디서 받았든 ffprobe로 길이와 형식을 확인하고, `ffmpeg -v error -i <파일> -f null -`로 끝까지 풀리는지 본 뒤 복사한다. WAV는 「Preparing…」에서 3분 넘게 걸릴 수 있다(10-17 2분 24초 곡, 받은 파일 48kHz 16비트 스테레오 27.6MB). 창을 닫지 말고 다운로드 폴더에 파일이 생길 때까지 기다린다.
- 다시 확인: 받은 뒤 다운로드 폴더의 새 파일 이름을 본다.

### 스타일에 「120 BPM」이라고 써도 다른 빠르기로 나온다
- 증상: 「120 BPM, 4/4」를 적은 v6 연주곡(B1)을 받은 WAV로 재니 약 122.0 BPM이었다(10-17, 방법에 따라 121.93~122.05). 120 BPM 격자에 맞춘 콘티는 한 마디(2초 = 48프레임)가 곡과 0.03초씩 어긋난다.
- 원인: Suno가 스타일의 BPM을 지시로 받지 않고 분위기 낱말처럼 다룬다.
- 고침: 곡을 고른 뒤 WAV로 BPM을 다시 재고, 콘티를 곡에 맞추거나 곡을 늘인다. 10-18 B1은 `ffmpeg -af atempo=0.9833245`로 늘여 119.93 BPM(마디 2.001초)이 됐다. BPM은 `Documents/synk-vendor/harin-iced-coffee-h3-20261017/음악/tempo_precise.py`(곡 전체 64·128박 지연 자기상관)로 잰다. 같은 폴더 `beat_grid.py`(킥 어택 ±40ms 짝짓기 선형 맞춤)는 늘인 판에서 120.35·반 박 어긋난 위상을 냈으니 BPM·위상의 정본으로 쓰지 않는다. atempo는 끝을 13ms쯤 덜 늘인다(146.035초 예상 → 146.022초).
- 다시 확인: `tempo_precise.py`로 원본과 늘인 판을 같이 재서 BPM 비율이 늘인 비율과 같은지 본다(10-18 121.98 → 119.925, 비율 0.98315 대 0.98332).

### 곡이 끝나면 플레이어가 다음 곡을 저절로 튼다
- 증상: 페이지 안에서 곡을 차례로 재려고 `ended`에 다음 곡을 걸었더니, 앞 곡 기록 끝에 다음 곡 앞부분이 섞였다. 다음 곡 단추도 찾지 못했다(10-17).
- 원인: 플레이어가 목록의 다음 곡을 바로 튼다. 그 곡 줄의 단추 이름이 「Play …」에서 「Pause …」로 바뀌어 `[aria-label^="Play "]`로 잡히지 않는다. `playbackRate`는 곡이 바뀔 때마다 1로 돌아간다.
- 고침: `ended`가 오면 기록 이름부터 비우고, 기록은 `currentTime`이 크게 줄어드는 자리로 자른다. 단추는 「Play」와 「Pause」 둘 다 찾는다. 배속은 `playing` 이벤트에서 다시 건다. 2배속으로 걸어도 스트리밍이 따라가지 못해 실제로는 1.6배쯤이다.
- 다시 확인: 곡 하나가 끝난 직후 플레이어 표시 곡이 바뀌는지 본다.

### 만들기 화면의 「섹션 교체」가 조용히 실패한다
- 증상: 후보가 30초쯤 「생성 중」으로 떴다가 사라졌다. 세 번 모두 같았고, 목록 거름 때문도 아니었다(10-07).
- 원인: 모른다.
- 고침: 곡 ⋯ → 편집 → 「편집기에서 열기」(Song Editor Beta)에서 그 구간만 다시 부르게 하면 바로 된다. 편집기의 시간 칸에는 값을 입력할 수 없으니 선택 손잡이를 끌어 맞춘다(1px가 약 0.07초다. 3px 미만으로 끌면 무시되니 크게 갔다가 되돌아온다). 경계는 목소리가 비면서 드럼 타격 바로 앞인 자리로 잡고, 구간은 10초 이상으로 한다. 「가사 대체」에는 원곡에 적힌 가사가 아니라 실제로 부른 대로 넣는다(10-07 모음 줄은 표기 두 번, 노래 네 번).
- 다시 확인: 편집기에서 손잡이를 2px만 끌어 시각이 바뀌지 않는지 본다.

### 구간을 고친 후보를 원곡에 이으면 이음매가 튄다
- 증상: 편집기에서 받은 후보를 원곡에 그대로 이으면 이음매에서 소리가 튄다(10-07).
- 원인: 후보는 원곡의 16.6초부터 끝까지를 새로 그린 소리라서 위상이 다르고, 박자도 ±10ms 흔들린다(한 후보는 점점 느려져 0.03초 늦었다).
- 고침: 고친 구간만 원곡에 끼운다. 이음매마다 바로 옆 맥락으로 시각을 따로 맞추고, 25ms 등전력으로 교차하고, 크기는 서서히 맞춘다. 고르기 전에 반복 사이 음색 거리, 가사 힌트 없는 받아쓰기, 박자 흔들림, 이음매 튐을 잰다. 10-07 스크립트는 옛 노트북의 `synk-vendor/hangul-songs/vowel-dance-fix-20261007/`에 있었고, 새 노트북에는 없다.
- 다시 확인: 이음매 앞뒤 50ms 파형을 겹쳐 본다.

## Google Flow

### 「AI 크레딧 추가」 띠를 누르면 결제다
- 증상: 크레딧이 모자라면 「AI 크레딧 추가」 띠가 뜬다(10-07).
- 원인: 구독에 든 크레딧 밖의 결제로 이어지는 단추다.
- 고침: 누르지 않는다. 크레딧은 아바타 메뉴에서 본다. 10-07 1회 비용은 Omni 1.1 Flash 360p 8초 6(720p 12), Veo 3.1 Lite 10, Fast 20, Quality 100(8초 고정)이었다. 한국에서는 오른쪽 아래 워터마크를 끌 수 없다.
- 다시 확인: 생성 전후 아바타 메뉴의 크레딧을 견준다.

### 시작·끝 그림을 고르는 창의 목록이 열린 직후 다시 정렬된다
- 증상: 위치를 보고 누르면 엉뚱한 그림이 골라진다(10-07).
- 원인: 창이 열린 직후 목록이 최근 순으로 다시 정렬된다.
- 고침: 「애셋 검색」에 파일 이름을 쳐서 고른다. 모델·9:16·x1 같은 생성 설정은 프롬프트 칸 아래 칩에 있다. 참고 그림을 넣는 「소재」 방식(프롬프트 칸의 + → 그림 → 「프롬프트에 추가」)에서는 검색칸이 잡히지 않은 채로 글자를 치면 페이지 단축키가 눌려 보기 방식이 바뀌니 검색칸을 먼저 누른다. 이미 넣은 그림은 그 목록에서 빠진다.
- 다시 확인: 검색으로 고른 그림 이름이 미리보기에 뜨는지 본다.

### 결과 플레이어를 보기 어렵고, 그리드에서 같은 좌표가 다른 것을 연다
- 증상: 결과가 작은 캔버스(1080×1920) 플레이어에 나온다. 그리드로 돌아와 아까와 같은 좌표를 누르면 이미지 편집기나 도구 페이지가 열린다(10-07).
- 원인: 보기를 바꿀 때마다 배치가 바뀐다.
- 고침: 캔버스를 `position:fixed; right:0; height:100vh`로 키우고, 타임라인 눈금을 눌러 시각을 옮긴 뒤 확대해서 찍는다. 그리드로 돌아오면 화면을 다시 찍고 나서 누른다.
- 다시 확인: 그리드로 돌아온 뒤 찍은 화면에서 누를 칸의 위치를 다시 본다.

### 내려받은 파일이 다운로드 폴더에서 남의 파일과 섞인다
- 증상: 1080p 업스케일이 끝나면 `%USERPROFILE%\Downloads`에 제목 이름으로 저절로 떨어진다. 그 폴더에 다른 세션의 파일도 있다(10-07).
- 원인: 720p(원본)는 바로, 1080p는 업스케일(몇 분)이 끝난 뒤 브라우저 다운로드 폴더로 받는다. 목록 보기의 「일괄 다운로드」는 `다운로드.zip`으로 떨어진다.
- 고침: 업스케일은 한 번에 하나씩 하고, 내 제목의 파일만 옮긴다.
- 다시 확인: 옮기기 전에 다운로드 폴더 파일의 시각과 제목을 본다.

### 클립을 나눠 뽑으면 같은 사건을 클립마다 다시 연기한다
- 증상: Omni 1.1로 장면을 여러 클립으로 나눠 뽑자, 클립마다 넘어지는 장면이 새로 나왔다. 옆얼굴에서는 머리가 짧은 다른 사람이 됐다. Veo 3.1 Quality는 시작 그림에 없는 건물을 다른 「SYNK」 고층 빌딩으로 지어냈고, 「시간이 멈춘다」는 지시를 지키지 않았다(10-07).
- 원인: 모델이 클립마다 지시문 전체를 새로 연기하고, 그림에 없는 것은 지어낸다.
- 고침: 한 사건은 한 클립에만 두고, 다음 클립은 그 결과 상태에서 시작하게 쓴다. 멈춤은 편집에서 프레임 정지로 만들고, 건물은 시작 그림에 있는 상태에서 다가가게 한다. 영상 모델 선택은 [만족 사례 장부](../마케팅/제작양식/만족사례_장부.md)와 [제작 도구 선택](../마케팅/콘텐츠_제작방식_v2_20261002.md#video-tool-selection)을 따른다.
- 다시 확인: 나눠 뽑은 클립을 이어 보고 같은 동작이 되풀이되는지 본다.

## 특허로 웹작성(상표 출원서)

### 지정상품이 빈 채로 닫힌다
- 증상: 상품을 검색해 고르고 「적용」을 눌렀는데 지정상품 표가 비어 있다(10-05).
- 원인: 지정상품 넣기는 세 단계다. 검색(`srchGoods()`) → 상품 세목에서 골라 지정 상품으로 보내기(`addItem()`) → 「지정상품 추가」로 아래 표에 옮기기. 그다음에 「적용」을 눌러야 한다.
- 고침: 세 단계를 다 거친 뒤 「적용」을 누른다.
- 다시 확인: 「적용」 전에 아래 표에 줄이 있는지 본다.

### 상품 검색 결과가 80개에서 끊긴다
- 증상: 검색 결과가 80개까지만 나온다(10-05).
- 원인: 특허로 검색이 결과 수를 80개로 자른다.
- 고침: 정확한 이름으로 검색한다. 유사군 상자(예: S0101)를 고르면 그 유사군만 나온다.
- 다시 확인: 넓은 낱말로 검색해 결과 수를 본다.

### 다른 등록상표에 쓰인 서비스 이름이 고시명칭이 아니다
