# 현장 노트 · 브라우저·게시

> 판: Chrome 155(10-17 새 노트북은 프로필 「유호」 하나, 폴더 이름 `Profile 1`) · Claude in Chrome 확장 · Meta Business Suite·인스타그램 웹·유튜브 스튜디오 · YouTube Data API v3(`tools/sns-발행.js`·`tools/lib/sns-publisher.js`) · suno.com · flow.google.com · 특허로 웹작성
> 마지막 확인: 2026-10-17(크롬 프로필·`alert` 지우기·확장 파일 한도·로컬 연결 화면·발행 도구 문구를 새 노트북에서 다시 봄. 화면 항목 대부분은 10-03~10-13 옛 노트북 실측이라 쓰기 전에 「다시 확인」부터)
> 쓴 AI: Claude Code(Claude Opus 5.5) — 10-03~10-14 Claude 메모에서 옮김(10-17 2차)

인터넷 작업은 GPT와 Claude 모두 크롬에서 한다([AI 운영 원칙 · 공식 하네스](../AI_운영원칙.md#공식-하네스)). 올리기·예약·공개·결제·약관 동의는 그 요청에서 분명히 승인받은 범위로만 하고, 로그인·가입·인증서 서명·보안 확인(CAPTCHA)은 유호님이 한다([비용과 권한](../AI_운영원칙.md#비용과-권한)). Suno 곡을 고르고 박자에 맞춰 자르는 방법은 [만족 사례 장부](../마케팅/제작양식/만족사례_장부.md) S16·S17이 정본이다. 여기는 크롬 확장·웹 화면·게시 API가 예상과 다르게 움직인 함정이다. 가려진 창·확장 새 창 문제는 [시험·화면 확인](시험_화면확인.md#화면-확인)에도 있다. 틀은 [README](README.md)를 따른다.

## 크롬 확장 공통

### 확장이 붙은 프로필에 그 사이트 로그인이 없다
- 증상: 유호님은 「로그인 다 했어」라고 했는데 확장 탭의 facebook.com은 로그인 화면이었다(10-03).
- 원인: 옛 노트북 크롬에 프로필이 여섯 개 있었고, 그중 둘이 같은 이름 「유호」였다. SNS 로그인은 한쪽(`Profile 2`)에만 있었는데 확장은 로그인이 없는 다른 쪽(`Default`)에 붙어 있었다. 두 프로필 모두 확장이 깔려 있어 같은 브라우저처럼 보였다.
- 고침: 게시를 시작하기 전에 확장 탭에서 그 사이트의 로그인 상태부터 본다. 로그인이 없으면 로그인된 프로필 창(`chrome.exe --profile-directory="<폴더 이름>" <주소>`)에서 사이드 패널을 열어 확장을 그쪽에 붙인다. 로그인 여부는 쿠키 이름과 만료만 읽어서 확인하고, 값은 읽지 않는다.
- 다시 확인: PowerShell `(Get-Content "$env:LOCALAPPDATA\Google\Chrome\User Data\Local State" -Raw | ConvertFrom-Json).profile.info_cache`로 프로필 폴더와 이름을 본다. 10-17 새 노트북에는 `Profile 1 = 유호` 하나뿐이다.

### 뒤로 열린 탭·가려진 창에서는 게시 화면이 멈춘다
- 증상: 확장이 만든 탭에서 스크린샷이 30초 시간 초과로 끊긴다. 크롬이 다른 앱에 완전히 가려지면 유튜브 예약 날짜 팝업이 열리지 않고, 인스타 만들기는 영상을 넣어도 다음 단계로 넘어가지 않는다(10-07·10-13). Flow 캡처도 30초씩 멈췄다.
- 원인: 확장이 만든 탭은 뒤로 열리고, 가려진 창과 함께 `visibilityState`가 hidden이 된다. 숨은 탭은 화면을 그리지 않고, `setTimeout`도 1분 단위로 늦춰진다.
- 고침: 시작하기 전에 크롬 창을 화면 앞에 띄워 달라고 부탁하고, 확장이 연 탭은 유호님께 한 번 눌러 달라고 한다. 계속 멈추면 같은 주소를 새 탭으로 연다. 같은 만들기를 두 탭에서 열면 둘 다 진행되니 하나는 바로 닫는다. 유호님이 입력하는 중에는 computer-use `open_application`으로도 크롬을 앞으로 가져오지 못한다.
- 다시 확인: 그 탭에서 `document.visibilityState`가 `visible`인지 본다.

### 네이티브 확인 창이 뜨면 스크린샷·JS가 모두 멈춘다
- 증상: 특허로 웹작성 화면을 열 때와 상표유형 「적용」을 누를 때 스크린샷·JS가 시간 초과로 끊겼다(10-05).
- 원인: `alert`·`confirm` 같은 네이티브 창이 떠 있는 동안 페이지가 멈춰서 확장(CDP)이 아무것도 못 한다.
- 고침: 유호님께 크롬에서 그 창을 닫아 달라고 한다. 무언가를 고르는 창이면 창의 문구부터 받는다. 창을 막으려고 `window.alert`·`confirm`을 덮어썼다면 `delete`로 되돌리지 않는다. Window의 이 함수들은 객체 자체 속성이라 지우면 네이티브 함수까지 사라진다. 원래 참조를 저장해 두었다가 대입으로 되돌리거나, 처음부터 덮어쓰지 않는다. 이미 사라졌으면 화면을 새로 열고 처음부터 채운다.
- 다시 확인: 빈 페이지에서 `window.alert=function(){}; delete window.alert; typeof window.alert`가 `undefined`이면 그대로다(10-17 헤드리스 크롬 155에서 재현).

### 확장 JS 한 번이 45초에서 끊긴다
- 증상: 특허로 검색을 JS 반복으로 돌리면 45초에 끊긴다. 끊긴 뒤에도 페이지 안에서 반복이 계속 돌거나 중간에 멈춘다(10-05).
- 원인: Claude in Chrome의 JS 실행 한 번에 시간 상한이 있고, 상한에 걸려도 페이지 안의 반복은 멈추지 않는다.
- 고침: 한 번에 2~4개씩 나눠 부른다.
- 다시 확인: `await new Promise(r=>setTimeout(r,50000))`가 시간 초과로 끝나는지 본다.

### 파일 올리기 단추를 누르면 시스템 파일 창이 열린다
- 증상: Business Suite 「동영상 추가」나 Flow 「미디어 업로드」를 누르면 네이티브 파일 창이 뜬다. 확장은 이 창을 다루지 못한다(10-07·10-13).
- 원인: 단추를 누를 때 `type=file` 입력을 그때 만들어 `click()`한다. 이 입력은 문서에 붙지 않아서 `find`로도 잡히지 않는다.
- 고침: 누르기 전에 `HTMLInputElement.prototype.click`을 바꿔 두면, 창을 열지 않고 file 입력을 잡아 문서에 붙일 수 있다. 이 입력을 `find`로 잡아 `file_upload`로 넣는다(여러 장도 한 번에 된다). 넣은 뒤에는 원래 함수로 되돌린다.
- 다시 확인: 가로채기를 건 뒤 단추를 누르고, `document.querySelectorAll('input[type=file]').length`가 늘었는지 본다.

### 확장 파일 올리기는 한 번에 10MB 미만이다
- 증상: 47초 1080×1920 영상(약 20MB)이 `file_upload`로 들어가지 않는다. 9.8MB는 통과했다(10-07·10-13).
- 원인: Claude in Chrome의 `file_upload`는 한 번에 넣는 파일 크기의 합이 10MB 미만이어야 한다.
- 고침: 10MB가 넘으면 6.7MB 조각을 임시 file 입력 세 개에 하나씩 넣고 페이지 안에서 합친다. 합친 파일의 sha256을 원본과 대조한 뒤 원래 파일 칸에 넣는다(10-07 유튜브·인스타 모두 성공).
- 다시 확인: `file_upload` 도구 설명의 크기 줄(10-17 「under 10 MB」).

### 로그인 단추가 띄운 팝업 창을 확장이 보지 못한다
- 증상: Business Suite 로그인 화면의 「Facebook/Instagram으로 계속하기」, Apps Script 승인 팝업을 확장이 보지도 누르지도 못한다(10-03·10-16).
- 원인: 따로 뜨는 팝업 창은 확장이 붙은 탭 묶음 밖에 있다. Claude 앱 안 브라우저는 구글 로그인 팝업(`window.open`) 자체를 막는다(10-03 Typecast 키 받기).
- 고침: 그 단추는 누르지 않는다. 로그인과 승인은 유호님이 크롬에서 직접 한다. 크롬에서도 팝업이 막히면 주소창 오른쪽의 팝업 차단 아이콘에서 「항상 허용」을 고른다. 로그인이 필요한 사이트는 처음부터 크롬에 연다(PowerShell `Start-Process chrome -ArgumentList '<주소>'`).
- 다시 확인: 팝업이 뜬 뒤 확장 탭 목록(`tabs_context_mcp`)에 그 창이 없는지 본다.

### 로컬 연결 화면을 `localhost`로 열면 403이다
- 증상: 키를 붙여 넣는 로컬 연결 화면(`voice-connection.cjs`)이 `localhost:<포트>`에서 `Host rejected`로 거부된다.
- 원인: 이 서버들은 Host 머리글이 정확히 `127.0.0.1:<포트>`인지 검사한다.
- 고침: `http://127.0.0.1:<포트>`로 연다. 키를 받을 외부 사이트와 같은 크롬 창에 열면 복사와 붙여넣기를 한 창에서 끝낼 수 있다.
- 다시 확인: `rg -n "Host rejected" docs/마케팅 -g voice-connection.cjs`(10-17 여러 판에 같은 검사가 있음).

### claude.ai 로그인 화면은 임시 프로필 헤드리스 크롬에서 보안 확인에 멈춘다
- 증상: 10-17 영상 「전」 장면용으로 `chrome.exe --headless=new --user-data-dir=<임시> --screenshot=<파일> https://claude.ai/login`을 찍었더니 「claude.ai 보안 확인 수행 중」 화면만 나왔다.
- 원인: Cloudflare 봇 확인이 헤드리스 브라우저를 막는다. 우회하지 않는다.
- 고침: 로그인된 화면(왼쪽 아래 계정 메뉴의 「로그아웃」, 설정 → 사용량)은 확장 새 탭에서 찍었다. 메일은 찍기 전에 JS로 앞부분만 남기고(`이름@···`), 왼쪽 아래 이름 줄은 잘라 냈다. 로그인 화면 자체는 찍지 않았다.
- 다시 확인: 같은 명령으로 찍은 그림에 「보안 확인 수행 중」이 보이는지 본다.

## Meta(Business Suite·인스타그램 웹)

### 인스타 웹에서 프로필 링크와 댓글 고정을 바꿀 수 없다
- 증상: 웹 프로필 편집에서는 소개글만 바뀌고, 링크 칸에는 「링크 수정은 모바일에서만 가능」이 뜬다. 웹 댓글 메뉴에는 「고정」이 없다(삭제·취소뿐, 10-03·10-07).
- 원인: 인스타 웹에서 이 기능을 열어 두지 않았다.
- 고침: 링크 변경과 댓글 고정은 처음부터 유호님 휴대폰 앱에서 할 일로 안내한다. 예약은 웹 만들기 마지막 화면의 「콘텐츠 예약」 스위치로 된다.
- 다시 확인: 웹 프로필 편집의 링크 칸 문구.

### 인스타 만들기 창에서 Escape를 누르면 게시물 삭제를 묻는다
- 증상: 「게시물을 삭제하시겠어요?」가 뜬다(10-07).
- 원인: 만들기 창은 Escape를 창 닫기(= 쓰던 게시물 버리기)로 받는다.
- 고침: 「취소」를 누른다. 캡션 끝 해시태그의 자동 완성 목록도 Enter나 Esc로 닫지 말고, 편집기 밖 제목을 눌러 닫는다.
- 다시 확인: 만들기 창에서 Escape를 누르면 같은 물음이 뜨는지 본다.

### 캡션이 두 번 들어가거나 줄 수가 원문과 맞지 않는다
- 증상: `execCommand`로 넣은 캡션이 늦게 반영되어 타이핑과 겹치면서 두 번 들어갔다. 넣은 캡션을 `innerText`로 원문과 대조하면 빈 줄이 두 번씩 세어진다(10-07·10-13).
- 원인: 편집기가 입력을 늦게 반영한다. 또 문단마다 div를 써서 `innerText`가 빈 줄을 두 줄로 돌려준다.
- 고침: 확장 `type`은 한 번만 쓰고, 편집기 안의 문단(div)을 원문 줄과 하나씩 대조한다.
- 다시 확인: 넣은 뒤 편집기 안 div 개수와 원문 줄 수를 견준다.

### 릴스 만들기에 AI 표시·번역·표지 칸이 없다
- 증상: Business Suite 릴스 만들기에는 게시 위치, 지금/예약, 재생 목록, 설문, 자동 자막, 리믹스, 공개 범위 칸만 있다(10-13).
- 원인: 웹 만들기 화면에 그 칸이 없다. 표지 칸이 없어서 영상의 첫 화면이 그대로 표지가 된다.
- 고침: AI 표시가 필요하면 휴대폰 앱에서 한다. 표지로 쓸 그림은 영상 첫 화면에 둔다.
- 다시 확인: 릴스 만들기 화면의 칸 목록.

### 「게시물 게시 중」이 5분 넘게 돈다
- 증상: 「공유하기」를 누른 뒤 「게시물 게시 중」이 5분 넘게 계속 돈다(10-13 인스타·페북 교차 게시).
- 원인: 게시는 이미 끝났는데 화면이 늦게 바뀐다.
- 고침: 다시 누르지 않는다. Business Suite `latest/posts/published_posts` 목록에 「교차 게시됨」이 떴는지, 인스타 프로필 릴스 탭에 새 릴스가 있는지 확인한다. 인스타 `api/v1/users/web_profile_info`는 바로 429가 나니 거듭 부르지 않는다.
- 다시 확인: 게시 목록에 새 줄이 생겼는지 본다.

## 유튜브

### 스튜디오에서 바꾼 채널로 다른 세션이 댓글을 달 수 있다
- 증상: 계정 전환으로 다른 채널을 골라 둔 채로 끝내면, 다른 세션이 그 채널 이름으로 댓글을 달 수 있다(10-07).
- 원인: 구글 계정 하나에 채널 19개가 묶여 있고, 다른 세션도 같은 크롬 로그인을 쓴다. 고른 채널이 어디까지 남는지는 확인하지 못했다.
- 고침: 작업이 끝나면 원래 채널로 되돌린다.
- 다시 확인: 스튜디오 오른쪽 위의 채널 이름.

### 하루 API 한도에 걸려 올리기가 중간에 멈춘다
- 증상: 하루에 영상 4편과 자막을 올리다가 넷째 영상의 자막 업로드가 `403 … exceeded your quota`로 멈췄다. 영상은 비공개로 올라갔지만 자막·재생목록·예약이 빠졌고, 결과 파일의 state는 `partial`이 됐다(10-10).
- 원인: YouTube Data API 한도는 프로젝트 전체에 하루 10,000 단위다. 업로드가 가장 많이 쓰고 자막도 많이 쓰며, 상태를 읽을 때도 단위가 든다. 한도는 태평양 자정(서머타임 때는 한국 16:00, 아닐 때는 17:00)에 풀린다.
- 고침: 공개 시각이 가까운 것부터 올린다. 4편째부터는 한도를 넘을 수 있다고 미리 말하고, 상태 읽기는 꼭 필요한 만큼만 한다. 멈추면 새로 올리지 않는다. `tools/sns-발행.js --발행`은 partial 항목을 일부러 다시 올리지 않는다(같은 영상이 또 생기지 않게). 빠진 자막·재생목록만 `.tmp/hangul-mascot-video-20261006/youtube/yt_resume_partial.cjs <계획> <항목> --근거 "…"`로 채우고, 그다음 평소처럼 공개·예약한다.
- 다시 확인: `rg -n "재발행하지 않습니다" tools/sns-발행.js`(10-17 46행), `ls .tmp/hangul-mascot-video-20261006/youtube/yt_resume_partial.cjs`(10-17 있음).

### 비공개로 돌리거나 예약을 푼 직후 읽으면 옛 예약이 남아 보인다
- 증상: `videos.update?part=status`에 `privacyStatus: private`만 싣고 `publishAt`은 빼서 보냈는데, 직후 `videos.list`에는 옛 `publishAt`이 그대로 보였다. `yt_helper.cjs private`의 PUT 응답도 옛 값을 돌려줄 때가 있다(10-10·10-13).
- 원인: 읽기 쪽 반영이 늦다. 약 1분 뒤 다시 읽으니 「예약 없음」이었다.
- 고침: 같은 PUT을 거듭 보내지 않는다. 1분쯤 지나서 `yt_get.cjs <id>`로 다시 읽어 확인한다.
- 다시 확인: 예약을 푼 직후 한 번, 1분 뒤 한 번 읽어 결과를 견준다.

### 합성 표시(containsSyntheticMedia)가 API 읽기에 나오지 않는다
- 증상: 합성 표시를 켠 영상도 `videos.list`의 `status.containsSyntheticMedia`가 undefined다(10-13).
- 원인: 이 칸은 읽기 응답에 들어 있지 않다.
- 고침: 읽은 값에 기대지 말고, 필요한 영상은 PUT에 `true`를 직접 싣는다(`tools/lib/sns-publisher.js`는 합성 표시를 켜면 `true`를 싣는다). 켜졌는지는 공개 뒤 시청 페이지의 「변경되었거나 합성된」 표시로 확인한다. 번역 제목(`part=localizations`)은 발행 도구가 보내지 않으니 따로 PUT한다.
- 다시 확인: `rg -n "localizations" tools/lib/sns-publisher.js`가 비어 있으면 번역 제목은 여전히 따로 보내야 한다(10-17 비어 있음).

## Suno

### 좁은 창에서는 만들기가 조용히 실패한다
- 증상: 창 폭이 좁으면 만들기 양식이 팝업으로 바뀌고, 클릭이 엇나가 생성이 되지 않는다. 오류도 뜨지 않는다(10-13).

- 다시 확인: 「More Options」 요약에 넣은 값이 보이는지 본다.

### 처음 Create를 누르면 「사람인지 확인하십시오」가 뜬다
- 증상: Cloudflare 확인 창이 뜨고 생성이 멈춘다(10-13).
- 원인: 처음 생성할 때 Suno가 봇 검사를 건다. 창이 가려져 있으면 확인도 진행되지 않는다.
- 고침: AI가 누르지 않는다. 유호님께 크롬 창을 앞에 띄우고 눌러 달라고 한다. 한 번 통과하면 다음 생성은 바로 됐다.
- 다시 확인: 통과한 뒤 두 번째 Create에서 확인 창이 다시 뜨는지 본다.

### 내려받지 않고 곡 소리를 재려 하면 음원 주소가 막힌다
- 증상: cdn 음원을 fetch하면 CORS로 막힌다. 스트림 m4a는 `decodeAudioData`나 `<audio>`로 풀리지 않는다. cdn1 주소를 curl로 받으면 403 MissingKey다(10-07·10-13).
- 원인: 음원 주소에 서명이 필요하고, 플레이어는 MSE blob으로 곡을 튼다.
- 고침: 플레이어의 `<audio crossOrigin=anonymous>`에 `createMediaElementSource`와 ScriptProcessor를 연결한다(스피커로는 내보내지 않는다). 곡마다 30초씩 재서 BPM과 박 선명도를 견준다. 곡 줄의 재생 단추는 `[role=button][aria-label^="Play "]`다. 다운로드 횟수는 쓰지 않는다.
- 다시 확인: 곡 목록에서 그 선택자로 재생 단추가 잡히는지 본다.

### 플레이어 소리로 잰 첫 박이 반 박 어긋난다
- 증상: 플레이어 소리로 잰 첫 박이 받은 WAV와 0.25초(반 박) 어긋났다. 뒷박에 맞춰져 있었다(10-13).
- 원인: 모른다. 스트림 시작 지연으로 보인다.
- 고침: 박 위치는 받은 WAV로 다시 잰다. 저역(150Hz) 킥 어택을 박마다 재서 격자를 잡고, 이음매는 킥 앞의 조용한 틈에 둔다.
- 다시 확인: 같은 곡을 두 방법으로 재서 첫 박 시각을 견준다.

### 내려받을 때 횟수가 더 줄거나 Download 메뉴가 보이지 않는다
- 증상: 다운로드 창에서 형식 여러 개가 함께 골라져 있다. 앱을 다시 켜면 로그인이 풀리거나 다른 계정으로 로그인되어, 곡 ⋯ 메뉴에 Download가 보이지 않는다(10-13).
- 원인: 형식은 여러 개를 함께 고를 수 있다. Download·Publish·Move to Trash는 곡 주인 계정에만 나온다.
- 고침: 형식은 하나만 남기고 「Unlock & Download」를 누른다(곡당 한 번 차감되고, 같은 곡은 다시 받아도 줄지 않는다). 받기 전에 왼쪽 메뉴의 프로필 이름이 곡 주인과 같은지 본다. 표지 위의 ↓ 단추는 음원이 아니라 그림을 받는다. 생성 한 번(2곡)에 10크레딧이 든다.
- 다시 확인: suno.com/account에서 받기 전과 후의 남은 다운로드 수를 견준다.

### 받은 WAV가 GUID 이름의 `.tmp`로 남는다
- 증상: Claude 앱 안 브라우저에서 받은 WAV가 다운로드 폴더에 GUID 이름의 `.tmp`로 남고, 이름이 바뀌지 않았다(10-13). 크롬에서는 아직 확인하지 않았다.
- 원인: 모른다.
- 고침: ffprobe로 길이와 형식을 확인하고, `ffmpeg -v error -i <파일> -f null -`로 끝까지 풀리는지 본 뒤 복사한다.
- 다시 확인: 크롬으로 받은 첫 WAV의 파일 이름을 본다.

### 만들기 화면의 「섹션 교체」가 조용히 실패한다
- 증상: 후보가 30초쯤 「생성 중」으로 떴다가 사라졌다. 세 번 모두 같았고, 목록 거름 때문도 아니었다(10-07).
- 원인: 모른다.
- 고침: 곡 ⋯ → 편집 → 「편집기에서 열기」(Song Editor Beta)에서 그 구간만 다시 부르게 하면 바로 된다. 편집기의 시간 칸에는 값을 입력할 수 없으니 선택 손잡이를 끌어 맞춘다(1px가 약 0.07초다. 3px 미만으로 끌면 무시되니 크게 갔다가 되돌아온다). 경계는 목소리가 비면서 드럼 타격 바로 앞인 자리로 잡고, 구간은 10초 이상으로 한다. 「가사 대체」에는 원곡에 적힌 가사가 아니라 실제로 부른 대로 넣는다(10-07 모음 줄은 표기 두 번, 노래 네 번).
- 다시 확인: 편집기에서 손잡이를 2px만 끌어 시각이 바뀌지 않는지 본다.

### 구간을 고친 후보를 원곡에 이으면 이음매가 튄다
- 증상: 편집기에서 받은 후보를 원곡에 그대로 이으면 이음매에서 소리가 튄다(10-07).
- 원인: 후보는 원곡의 16.6초부터 끝까지를 새로 그린 소리라서 위상이 다르고, 박자도 ±10ms 흔들린다(한 후보는 점점 느려져 0.03초 늦었다).
- 고침: 고친 구간만 원곡에 끼운다. 이음매마다 바로 옆 맥락으로 시각을 따로 맞추고, 25ms 등전력으로 교차하고, 크기는 서서히 맞춘다. 고르기 전에 반복 사이 음색 거리, 가사 힌트 없는 받아쓰기, 박자 흔들림, 이음매 튐을 잰다. 10-07 스크립트는 옛 노트북의 `synk-vendor/hangul-songs/vowel-dance-fix-20261007/`에 있었고, 새 노트북에는 없다.
- 다시 확인: 이음매 앞뒤 50ms 파형을 겹쳐 본다.

## Google Flow

### 「AI 크레딧 추가」 띠를 누르면 결제다
- 증상: 크레딧이 모자라면 「AI 크레딧 추가」 띠가 뜬다(10-07).
- 원인: 구독에 든 크레딧 밖의 결제로 이어지는 단추다.
- 고침: 누르지 않는다. 크레딧은 아바타 메뉴에서 본다. 10-07 1회 비용은 Omni 1.1 Flash 360p 8초 6(720p 12), Veo 3.1 Lite 10, Fast 20, Quality 100(8초 고정)이었다. 한국에서는 오른쪽 아래 워터마크를 끌 수 없다.

### 시작·끝 그림을 고르는 창의 목록이 열린 직후 다시 정렬된다
- 증상: 위치를 보고 누르면 엉뚱한 그림이 골라진다(10-07).
- 원인: 창이 열린 직후 목록이 최근 순으로 다시 정렬된다.
- 고침: 「애셋 검색」에 파일 이름을 쳐서 고른다. 모델·9:16·x1 같은 생성 설정은 프롬프트 칸 아래 칩에 있다. 참고 그림을 넣는 「소재」 방식(프롬프트 칸의 + → 그림 → 「프롬프트에 추가」)에서는 검색칸이 잡히지 않은 채로 글자를 치면 페이지 단축키가 눌려 보기 방식이 바뀌니 검색칸을 먼저 누른다. 이미 넣은 그림은 그 목록에서 빠진다.
- 다시 확인: 검색으로 고른 그림 이름이 미리보기에 뜨는지 본다.

### 결과 플레이어를 보기 어렵고, 그리드에서 같은 좌표가 다른 것을 연다
- 증상: 결과가 작은 캔버스(1080×1920) 플레이어에 나온다. 그리드로 돌아와 아까와 같은 좌표를 누르면 이미지 편집기나 도구 페이지가 열린다(10-07).
- 원인: 보기를 바꿀 때마다 배치가 바뀐다.
- 고침: 캔버스를 `position:fixed; right:0; height:100vh`로 키우고, 타임라인 눈금을 눌러 시각을 옮긴 뒤 확대해서 찍는다. 그리드로 돌아오면 화면을 다시 찍고 나서 누른다.
- 다시 확인: 그리드로 돌아온 뒤 찍은 화면에서 누를 칸의 위치를 다시 본다.

### 내려받은 파일이 다운로드 폴더에서 남의 파일과 섞인다
- 증상: 1080p 업스케일이 끝나면 `%USERPROFILE%\Downloads`에 제목 이름으로 저절로 떨어진다. 그 폴더에 다른 세션의 파일도 있다(10-07).
- 원인: 720p(원본)는 바로, 1080p는 업스케일(몇 분)이 끝난 뒤 브라우저 다운로드 폴더로 받는다. 목록 보기의 「일괄 다운로드」는 `다운로드.zip`으로 떨어진다.
- 고침: 업스케일은 한 번에 하나씩 하고, 내 제목의 파일만 옮긴다.
- 다시 확인: 옮기기 전에 다운로드 폴더 파일의 시각과 제목을 본다.

### 클립을 나눠 뽑으면 같은 사건을 클립마다 다시 연기한다
- 증상: Omni 1.1로 장면을 여러 클립으로 나눠 뽑자, 클립마다 넘어지는 장면이 새로 나왔다. 옆얼굴에서는 머리가 짧은 다른 사람이 됐다. Veo 3.1 Quality는 시작 그림에 없는 건물을 다른 「SYNK」 고층 빌딩으로 지어냈고, 「시간이 멈춘다」는 지시를 지키지 않았다(10-07).
- 원인: 모델이 클립마다 지시문 전체를 새로 연기하고, 그림에 없는 것은 지어낸다.
- 고침: 한 사건은 한 클립에만 두고, 다음 클립은 그 결과 상태에서 시작하게 쓴다. 멈춤은 편집에서 프레임 정지로 만들고, 건물은 시작 그림에 있는 상태에서 다가가게 한다. 영상 모델 선택은 [만족 사례 장부](../마케팅/제작양식/만족사례_장부.md)와 [제작 도구 선택](../마케팅/콘텐츠_제작방식_v2_20261002.md#video-tool-selection)을 따른다.
- 다시 확인: 나눠 뽑은 클립을 이어 보고 같은 동작이 되풀이되는지 본다.

## 특허로 웹작성(상표 출원서)

### 지정상품이 빈 채로 닫힌다
- 증상: 상품을 검색해 고르고 「적용」을 눌렀는데 지정상품 표가 비어 있다(10-05).
- 원인: 지정상품 넣기는 세 단계다. 검색(`srchGoods()`) → 상품 세목에서 골라 지정 상품으로 보내기(`addItem()`) → 「지정상품 추가」로 아래 표에 옮기기. 그다음에 「적용」을 눌러야 한다.
- 고침: 세 단계를 다 거친 뒤 「적용」을 누른다.
- 다시 확인: 「적용」 전에 아래 표에 줄이 있는지 본다.

### 상품 검색 결과가 80개에서 끊긴다
- 증상: 검색 결과가 80개까지만 나온다(10-05).
- 원인: 특허로 검색이 결과 수를 80개로 자른다.
- 고침: 정확한 이름으로 검색한다. 유사군 상자(예: S0101)를 고르면 그 유사군만 나온다.
- 다시 확인: 넓은 낱말로 검색해 결과 수를 본다.

### 다른 등록상표에 쓰인 서비스 이름이 고시명칭이 아니다
- 증상: 10-03에 준비한 서비스 이름 10개 중 4개(브랜드마케팅업 등)가 특허로 검색에 정확히 나오지 않았다.
