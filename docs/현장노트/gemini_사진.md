## 화면 자동화

### 「Pro로 다시 실행」이 사라졌다
- 증상: 10-18 한강2126 얼굴 시험에서 생성 그림 아래 「다시 실행」을 누르니 메뉴가 「맞춤설정」·「다시 시도」 둘뿐이었다. 「다시 시도」는 같은 모델로 다시 뽑는다.
- 원인: 앱 화면이 바뀌었다. 모드 메뉴가 「3.5 Flash-Lite · 3.8 Flash · 3.1 Pro · 4 Argon」 + 「사고 수준(최저가·보통·최고가)」 하위 메뉴로 나뉜다.
- 고침: 프로 판은 새 대화를 열어 모드 메뉴에서 「3.1 Pro」를 고르고 같은 참조·같은 지시문으로 보낸다. 2.1은 「4 Argon」 + 「사고 수준 → 최고가」.
- 다시 확인: 보내기 전 모드 단추 aria-label이 「현재 Pro 모드 사용 중」 또는 「현재 Argon 최고가 모드 사용 중」인지.

### 비율 메뉴는 좌표가 자꾸 바뀌어 JS 클릭이 낫다
- 증상: 참조를 올리거나 글을 넣은 뒤 비율 단추·메뉴가 아래로 밀려(화면 밖 y 779까지), 미리 잰 좌표로 누르자 9:16 대신 1:1·3:4가 골라졌다(10-18 두 번).
- 원인: 첨부 미리보기와 글 길이만큼 입력 상자가 커진다. 메뉴 항목은 `input-companion-item` 요소다.
- 고침: 비율 단추(`innerText`가 `9:16` 같은 button)를 JS로 `scrollIntoView` 뒤 `click()`, 메뉴가 뜨면 `input-companion-item` 가운데 글자가 「9:16」인 것을 JS `click()`. 모드 메뉴는 실제 클릭(좌표)으로 했고, 첫 클릭이 툴팁만 띄울 때가 있어 페이지가 뜬 뒤 2초 더 기다린다.
- 다시 확인: 보내기 직전 `[...document.querySelectorAll('button')].map(b=>b.innerText.trim()).filter(t=>/^\d+:\d+$/.test(t))`가 원하는 비율인지.

### 파일 올리기는 세션이 읽을 수 있는 폴더의 파일만 된다
- 증상: `file_upload`에 `Videos\…` 경로를 주자 「only files this session is allowed to read can be uploaded」로 거절됐다.
- 원인: Claude in Chrome 확장은 세션 작업 폴더·스크래치패드 같은 허용 폴더의 파일만 올린다.
- 고침: 올릴 참조를 스크래치패드로 복사(ASCII 이름, 긴 변 1,400~1,600px JPEG)해서 그 경로로 올린다.
- 다시 확인: 올린 뒤 `[aria-label="첨부파일 닫기"]` 수(2초 뒤에 센다 — 바로 세면 0으로 나온다).

### 새 대화를 열 때마다 사고 수준이 기본으로 돌아간다
- 증상: /images를 새로 열면 모드 단추가 「Argon」(기본)이다. JS로 「사고 수준 → 최고가」를 눌러도 한 번에 안 먹을 때가 있다(10-17 B11은 기본으로 생성됐다).
- 원인: 사고 수준이 대화마다 정해지고, 하위 메뉴가 열리기 전에 누르면 무시된다.
- 고침: 모드 단추의 aria-label에 「최고가」가 들어갈 때까지 메뉴 열기 → 「사고 수준」 → 「최고가」를 최대 세 번 되풀이한다. 10-18 한강 v40: 창 크기가 작업 중에 1077↔1463으로 바뀌어 미리 잰 좌표 클릭이 빗나갔는데, JS `click()` 대신 그 요소 가운데 좌표로 `pointerdown → mousedown → pointerup → mouseup → click`을 차례로 dispatch하면 모드 메뉴·「사고 수준」·「최고가」·「업로드 및 도구」가 모두 열리고 눌렸다(각 사이 1.2초). 같은 방식으로 결과 그림에 `pointerover/mouseover/mouseenter/mousemove`를 보내 겹쳐 뜨는 「원본 크기 이미지 다운로드」 단추를 나오게 한 뒤 위 순서로 누르면 좌표 없이 받아졌다(대화마다 한 번씩, K14·K15부터).
- 다시 확인: 보내기 직전 `[aria-label^="모드 선택 도구 열기"]`의 aria-label에 「최고가」가 있는지 읽는다.
- 10-19 21시: 사고 수준 메뉴 이름이 「최저가 · 보통 · 최고가」에서 「낮음 · 보통 · 높음(매우 철저함)」으로 바뀐 화면이 섞여 나왔다(같은 날 앞 대화는 옛 이름). 「최고가」만 찾는 고리는 세 번 돌고도 「Argon」에 머물렀다 → `/^\s*(최고가|높음)/`로 찾고, 확인도 aria-label에 「최고가」나 「높음」(「현재 Argon 높음 모드 사용 중」)이 있는지로 본다.

### 새 /images 입력창: 비율은 「가로세로 비율」 펼침 단추, 첨부는 칩 그림으로 확인한다
- 증상: 10-19 21:50 `/u/4/images`(하린 5a 시작 그림)에서 위 항목의 비율 단추 고리(`innerText`가 `9:16` 같은 button)가 빈손이었다. 참조 6장을 올린 뒤에는 `[aria-label="첨부파일 닫기"]`가 0개로 나왔지만, 화면에는 칩 6장이 붙어 있었고 보낸 `user-query` 안 img도 6개였다.
- 원인: 새 입력창(같은 날 오전에 만난 배포)에서 비율이 입력 상자 아래 「가로세로 비율 ⌄」 펼침 단추로 바뀌었다. 첨부 칩의 닫기 단추 이름도 바뀐 것으로 보인다.
- 고침: 비율은 이렇게 맞춘다.
  1. innerText에 「가로세로 비율」이 든 button을 pointer 순서(위 사고 수준 항목)로 눌러 펼친다.
  2. innerText가 `9:16`으로 시작하는 항목을 같은 방식으로 누른다.
  3. 단추 aria-label이 「가로세로 비율, 9:16」으로 바뀌었는지 본다.
  첨부는 스크린샷의 칩 수로 보고, 보낸 뒤 `user-query img` 수로 다시 확인한다. 사고 수준 메뉴는 첫 고리에서 「최고가」 항목을 못 찾았고 둘째 고리에서 「최고가 매우 철저함」으로 찾았다(1.2초 간격, 세 번 고리면 된다).
- 다시 확인: 보내기 직전 비율 단추 aria-label이 「가로세로 비율, 9:16」인지 본다. 보낸 7초 뒤에는 주소가 `/app/<id>`이고 `user-query img`가 참조 장 수(6)인지 본다. 10-19 밤 한 번에 통과했고, 결과 그림은 40초 안에 나왔다.

### 참조 사진을 올릴 파일 입력이 read_page에 안 잡힌다
- 증상: read_page(interactive)에 이미지 입력이 없고, 전체 트리는 길어서 메뉴 부분이 잘린다.
- 원인: `input[type=file][accept="image/*"]`는 「업로드 및 도구」 메뉴를 연 뒤에야 생기고, 메뉴 깊은 곳에 숨어 있다.
- 고침: 메뉴를 연 뒤 그 입력에 aria-label을 달고 `document.body.prepend(input)`으로 맨 앞에 옮긴다. 그러면 새로 연 페이지의 read_page(depth 1)에서 ref_1로 잡혀 file_upload가 된다. 올린 뒤 입력은 `display:none`으로 숨긴다. 같은 페이지에서 read_page를 두 번째 부르면 ref 번호가 이어지니 결과를 보고 쓴다.
- 다시 확인: 올린 뒤 `[aria-label="첨부파일 닫기"]` 단추가 장 수만큼 있는지.

### 페이지가 늦게 뜨거나, 오래 기다리는 JS가 끊기며 지시문이 사라진다
- 증상: /images를 열고 10초 넘게 모드 단추가 없었다. 생성을 45초 넘게 기다리는 JS가 「CDP sendCommand "Runtime.evaluate" timed out after 45000ms」로 끊긴 뒤, 페이지가 새 채팅(/app)으로 돌아가 지시문이 지워지고 참조만 남았다(10-17 B13 첫 시도, 보내지지 않음).
- 원인: 페이지 초기화가 느린 때가 있고, 확장의 JS 실행 한도가 45초다.
- 고침: 모드 단추는 최대 20초 기다리는 고리로 찾고, 생성 대기는 computer wait 10초 여러 번 + 30초 안에 끝나는 짧은 JS 확인으로 나눈다. 끊겼으면 /images를 다시 열고 처음부터 한다.
- 다시 확인: 보낸 뒤 주소가 `/app/<대화 id>`로 바뀌는지.

### JS로 보내기 단추를 누르면 글이 빠진 채 참조 사진만 간다
- 증상: 10-18 지유 A3에서 `execCommand('insertText')`로 지시문을 넣고 바로 JS `send.click()`을 하자, 보낸 말에 글이 비어 있고 참조 4장만 갔다. 결과는 지시와 상관없는 「가을 카페」 사진이었다. find로 받은 ref를 클릭해도 창 높이가 바뀐 탭에서는 옆의 마이크 단추가 눌린 적이 두 번 있었다.
- 원인: 편집기에 넣은 글이 앱 상태에 반영되기 전에 보냈다(추정). ref 클릭은 좌표로 바뀌어 눌려 창 크기가 다르면 빗나간다.
- 고침: 글을 넣고 1.5초 기다린 뒤 편집기에 커서를 끝으로 두고 실제 키 Enter(computer key `Return`)로 보낸다. 업로드 → 글 넣기 → Enter → 확인을 한 묶음으로 돌릴 수 있다.
- 다시 확인: 보낸 뒤 `user-query`의 글자 수가 지시문 길이(1,300자 안팎)이고 그 안의 img가 4개인지 읽는다.

### 글을 넣자마자 실제 Enter를 눌러도 빈 새 채팅으로 튕긴다
- 증상: 10-18 한강 v40 K04 첫 시도·K08 첫 시도에서 insertText와 Enter를 한 묶음에 붙여 바로 눌렀더니, 주소가 `/images`에서 대화 id 없는 `/app`으로 바뀌고 「무엇을 도와드릴까요?」 화면에 참조 사진만 남았다. 글은 지워졌고 아무것도 보내지지 않았다(이미지 칩도 사라짐). 같은 묶음으로 보낸 K07은 됐다.
- 원인: 위 항목과 같이 넣은 글이 앱 상태에 반영되기 전에 Enter가 들어간 것으로 보인다(추정). 빈 글 + 첨부로 Enter를 받으면 일반 채팅으로 넘어가는 듯하다.

- 고침: 1차 클립의 마지막 프레임(720×1280)을 864×1536으로 키워 올리고 「Edit this photo. Keep everything exactly as it is … Change only one thing: add fine beads of condensation …」로 보내자, 시작 그림과의 어긋남이 3화소(1536 폭) 안인 그림이 나왔다(전체 평균 차 6.6). 첫 판 물방울은 폰에서 안 보일 만큼 옅어, 같은 대화에 다음 컷 접사(물방울 잔, `A_키_3_시작.jpg`)를 붙이고 「the same density and size of clear water beads … as in that photo」로 다시 보내자 폰 크기에서도 보였다(얼음 · 구도 그대로, 평균 차 7.4). 밀도 · 질감은 낱말보다 맞출 그림을 주는 쪽이 확실하다. 그날은 Fable 판정으로 같은 물방울을 시작 그림(빈 잔)에 넣는 쪽을 골랐고(어긋남 7화소), 5a 시작 그림도 확정 그림을 「Change only the wind」로 고쳐 얼굴 · 손 · 구도를 지켰다.
- 다시 확인: 고친 그림을 원래 그림과 위상 상관으로 겹쳐 어긋남(화소)과 평균 차를 재고, 얼굴 · 손을 나란히 확대해 본다.

### 「바람에 들린 차양 술」을 시키면 찢어진 천이 된다
- 증상: 10-20 하린 5a 시작 그림(머리만 바람에 날리게 고친 판)을 같은 대화에서 「차양 앞 끝의 스캘럽 천만 바람에 들려 펄럭이게, 차양 틀 · 천장은 그대로」로 고치자, 앞 끝이 여러 갈래로 찢겨 늘어진 천 조각처럼 그려졌다. 폭풍에 망가진 차양으로 읽혀 쓰지 않았다.
- 원인: 확인 못 함. 이어진 천이 접히고 들리는 모양 대신 「펄럭이는 조각」을 그린 것으로 보인다.
- 고침: 차양 움직임은 정지 그림에 넣지 않고 영상 모델 글에 맡긴다. 머리카락처럼 가벼운 것만 정지 그림에서 날린다.
- 다시 확인: 고친 그림에서 차양 가장자리가 끊김 없이 이어진 한 장의 천인지 확대해서 본다.

### 카메라 반대쪽으로 숙인 절(뒤에서 본 절)을 새 구도로 그리게 하면 옆 구도가 된다
- 증상: 10-19 한강 P7 라운지 절을 「그의 오른쪽 뒤 30~35도에서, 얼굴은 안 보이게」로 새로 그리게 하자 두 번 다 카메라가 그의 옆으로 갔다. 첫 번째는 1번 참고(옆 구도 K36 4판)에 끌려 절 45도·옆얼굴, 두 번째는 뒷모습 그림을 1번으로 바꾸고 옆 구도 그림을 뺐는데도 옆 구도에 아치 너머로 찍혀 절 방향이 더 흐려졌다.
- 원인: 사람이 카메라 반대쪽으로 숙이면 얼굴·상체가 안 보이는데, 모델이 「절하는 사람」을 보여 주려고 옆이나 앞으로 돌려 그리는 것으로 보인다(추정). 예전 K35 1판도 「뒤에서 본 절」 글에 그가 카메라 쪽으로 절해 「반대」가 됐다.
- 고침: 이미 그 카메라인 그림(여기서는 그가 면접관을 마주 보고 선 뒷모습 K34)을 첫 사진으로 두고 「카메라·방은 그대로, 자세만 90도 절」로 고치면 한 번에 됐다(K35 5판). 장소를 바꾼 짝 그림(매치컷)은 그 결과를 첫 사진으로 두고 「카메라·자세 그대로, 장소만」으로 바꾼다(K36 8판, 윤곽이 포개짐).
- 다시 확인: 두 그림을 반투명으로 겹쳐 발·다리·가방 윤곽이 포개지는지, 얼굴이 보이는 각도가 아닌지 본다.

### 앞 컷과 같은 카메라로 다음 순간을 그리게 하면 새 대화 생성은 카메라가 돌아간다
- 증상: 10-19 저녁 한강 K03(어깨빵 직후 넘어짐)을 K01b 8판(옆에서 본 투샷, 뒤 난간이 가로로)을 Image 1로 주고 「the same camera side … keep exactly that place」라고 새로 생성하자, 사람 좌우는 맞았지만 카메라가 45도쯤 비스듬해져 난간이 오른쪽 앞에서 뒤로 빠졌다(K03 5판).
- 원인: 새 생성은 참고 그림을 「장소·인물 참고」로만 쓰고 구도는 다시 짠다(위 「같은 방을 새 카메라 자리에서」와 반대 방향의 같은 결).
- 고침: 앞 컷을 고칠 그림으로 두고 「Edit the first attached photo (Image 1). Keep exactly the same camera position and height, … Pull the camera back just enough to fit the whole action. Change only the moment - …」로 순간만 바꾸면 카메라·배경이 그대로 남았다(6판). 이때 화면 밖이던 것(그의 신발)은 새로 그리며 틀릴 수 있어 같은 대화에서 「신발만 흰 운동화로」를 한 번 더 했다.
- 다시 확인: 두 컷을 나란히 놓고 배경의 수평선·난간 선이 같은 높이·같은 기울기인지.
- 10-19 밤 더: 이렇게 앞 컷에서 이어 그린 그림은 앞 컷의 잘못(까몽이 가방 옆면, 뿌연 하늘)도 그대로 물려받는다 — 고칠 때 이어진 컷을 같이 고친다. 물건을 「옮겨 달라」면 하나가 더 생길 수 있다(K03 8판: 공중에 하나 + 가슴 끈에 하나) → 같은 대화에서 「exactly ONE …, keep the one …, remove the second …」로 하나만 남기면 됐다.

### 「다른 사람으로 보이게」 고칠 때 얼굴을 두라고 쓰면 얼굴이 남는다
- 증상: 10-19 한강 인사 ① 몽골 여자가 접수원과 같아 보인다는 Fable P1을 「her face, her smile … keep; change only her look(머리·옷)」으로 고쳤더니 머리·옷만 바뀌고 얼굴은 그대로였다. 유호님 메모는 「접수원과 얼굴이 똑같아」였다.
- 원인: 같은 대화 고침은 「keep」에 적힌 것을 지킨다. 얼굴을 keep 목록에 넣었다.
- 고침: 「Change only who she is: she must be a clearly different woman …, not the same face with a new hairstyle」처럼 사람 자체를 바꾸라고 쓰고, 얼굴형·머리·피부 등 다르게 보일 곳을 적은 뒤 「Her face must not resemble the receptionist in any way」를 붙이면 한 번에 다른 사람이 됐다(포즈·로봇 팔·사무실은 그대로).
- 다시 확인: 비교할 사람(접수원)과 나란히 놓고 1초 안에 다른 사람으로 읽히는지 본다.

### 같은 대화에서 카메라를 크게 옮겨 달라면 같은 그림이 다시 나온다
- 증상: 10-18 건물 정면 3/4 그림을 고친 대화에서 「같은 건물을 강 위 60m 드론에서」라고 보내자, 답 글은 「항공 사진입니다」인데 그림은 앞 그림과 사실상 같았다(회색 평균 차 5.1).
- 원인: 대화 안 편집은 앞 그림의 구도를 지키려 한다(추정).
- 고침: 층 추가·소품 바꾸기처럼 구도를 지키는 고침만 같은 대화에서 하고, 시점이 바뀌는 그림은 새 대화를 열어 앞 결과를 참조 1번으로 넣는다.
- 다시 확인: 받은 그림을 앞 그림과 겹쳐 차이를 잰다(5 안팎이면 같은 그림).
