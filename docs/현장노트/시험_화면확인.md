## node --test와 CI

### 파이프로 받은 `node --test` 출력에 요약 줄이 없다
- 증상: `node --test … 2>&1 | grep '^# (tests|pass|fail)'`가 아무 줄도 못 잡는다. 실패 몇 개만 보이고 총 수·통과 수가 없어 시험이 다 돌았는지 모른다(10-17).
- 원인: Node 24는 파이프에 쓸 때도 TAP이 아닌 보고기를 쓴다.
- 고침: `node --test --test-reporter=tap --test-reporter-destination=<파일> <시험들>` 뒤 `grep -E '^# (tests|pass|fail|skipped)' <파일>`, 실패는 `grep '^not ok' <파일>`과 그 뒤의 `location:`·`error:`로 본다.
- 다시 확인: `node --test tests/AI토큰장부.test.js 2>&1 | grep -cE '^# (tests|pass|fail)'`가 0, tap 보고기 파일에는 `# tests 4`가 있다(10-17).

### 이 저장소의 CI는 전체 시험을 돌리지 않는다
- 증상: GitHub Actions가 초록이거나 「skipped」인데 정리 커밋이 깨뜨린 시험 21개가 10-03까지 쌓여 있었다.
- 원인: 10-18 복구 전 `.github/workflows/syntax-check.yml`은 비공개 저장소에서 저장소 변수 `SYNK_SELFHOSTED=on` + 자체 리눅스 러너가 있을 때만 돌았다(08-18 「돈 안 쓴다」 결정). push마다 skipped였으며, SYNK-talk의 별도 CI와 혼동하면 안 된다.
- 고침: 10-18 자동시험 복구 요청에 따라 Actions 예산 $0·한도 도달 시 사용 중단·결제수단 없음을 실제 예산 화면에서 확인한 뒤 `SYNK_HOSTED_CI=on` 선택을 더했다. 토큰 권한은 `contents: read`, 시험 출력은 명시적 TAP과 러너 임시 파일을 쓴다. 무료 포함량 소진은 실패/제한으로 남기고 유료로 자동 전환하지 않는다. 공용 작업본에서 실패하면 먼저 남의 미커밋 변경과 겹치는지 본다. 로컬 CI 모사는 `node tools/test-ci.js`(UTC·빈 홈·Windows), 실제 Linux 결과는 GitHub 실행으로 구분한다.
- 다시 확인: `gh variable get SYNK_HOSTED_CI`와 `gh run view <실행 ID> --json status,conclusion,jobs`에서 실제 실행·단계별 결과를 본다. 이 워크플로는 루트 `tests/*.test.js`와 명시한 저장소 보존 시험만 실행하며 `.cjs`·`.mjs`·하위 제품 시험 전체를 대신하지 않는다.

### Atlas 전체 동기화 직후 WORLD life가 다시 오래된 사본으로 나온다
- 증상: 10-18 학습 소스의 깨끗한 작업본에서 `sync-atlas --all --local`을 한 번 실행했지만 바로 이어진 검사에서 WORLD life가 실패했다.
- 원인: life 번들은 생성된 profile core를 읽는데 기존 실행 순서가 life → account → profile core여서 life가 이전 core를 담았다. Talk 동기화 시험에는 문법상 유효하지 않은 가짜 JS 번들도 남아 있었다.
- 고침: profile core를 먼저 생성하고 유효한 JS 시험 자료로 고쳤다. 최신 커밋의 정본으로 사본·번들을 다시 생성하고, 과거 스냅샷의 helper 목록은 현재 실제 import에 맞췄다.
- 다시 확인: `tests/atlas-copy-set.test.js`와 `tests/sync-atlas.test.js` 19/19, `check:atlas:local` 통과. 옛 core를 둔 뒤 동기화 한 번으로 core와 life가 일치하며 정본 `atlas/`·`strata/`는 변경하지 않는다. 실제 Linux 결과는 [백엔드 검증 기록](../_ops/qa/backend-upgrade-20261018/result.json)을 본다.

### 루트 시험이 데스크톱 빌드 도구를 import만 해도 요구한다
- 증상: 10-18 실제 GitHub Linux 실행의 `build-member-activity.test.js`가 `Cannot find module 'electron-builder'`로 실패했다. 루트 의존성만 설치한 환경이며 1,772개 중 이 한 건만 실패했다.
- 원인: `desktop/tools/package.cjs`가 파일을 읽자마자 빌드 도구를 불러와, 동결 패키지 영수증 검사에도 실제 빌드 의존성이 필요했다.
- 고침: `electron-builder`는 실제 패키징 `main` 안에서만 불러온다. 검증·설정 함수는 파일 import만으로 쓸 수 있고 실제 빌드는 기존 도구를 그대로 쓴다. CI에 Electron 전체를 추가 설치하지 않는다.
- 다시 확인: 데스크톱 의존성 없는 영수증 시험 2/2, 실제 설치된 빌드 의존성을 연결한 관련 시험 34/34. GitHub 실행 결과는 [백엔드 검증 기록](../_ops/qa/backend-upgrade-20261018/result.json)의 `integration.ciRepair`를 본다. 실제 앱 빌드는 실행하지 않는다.

### 실제 키를 자동으로 읽는 도구가 시험 중에 실제 키를 보낸다
- 증상: 가짜 API 서버 흐름 시험에서 도구가 보안 폴더의 실제 Typecast 키를 가짜 서버로 보냈고, 단언 실패 문구에 그 값이 찍혀 대화 기록에 남았다(10-07, 밖으로 나가지는 않았지만 키 교체를 권함).
- 원인: 「보안 폴더 키 파일 자동 연결」 기능이 시험 모드에서도 켜져 있었다.
- 고침: 키를 읽는 코드를 더할 때 시험 환경 변수(가짜 API 주소 등)가 있으면 끄는 조건을 같이 넣는다. 단언은 키 값이 아니라 개수·길이만 본다. 시험 출력은 pass/fail 줄만 거른다.
- 다시 확인: 실제 키 파일이 있는 PC에서 시험을 돌리기 전에 그 끄는 조건을 grep으로 찾는다.

### 희소 파일 시험이 디스크가 찬 날 ENOSPC로 실패한다
- 증상: `client-delivery-archive.test.mjs`의 「bounded size rejects oversized sparse files」가 ENOSPC로 실패한다(10-14 C: 여유 1.1GB).
- 원인: 한도(2GB)+1바이트로 `truncate`하므로 NTFS에서 2GB 넘는 여유가 있어야 한다.
- 고침: 회사 전체 시험 전에 여유를 보고 2GB 미만이면 먼저 알린다. ENOSPC 실패는 꾸러미 탓으로 적지 말고, 여유를 확보한 뒤 그 파일만 다시 돌려 기록한다.
- 다시 확인: `df -h /c`의 여유가 2GB를 넘는 상태에서 그 시험 파일만 돌려 통과하는지.

### 몇 ms 사이 같은 크기로 덮어쓴 파일의 시각이 그대로다
- 증상: 「preflight 뒤 바뀐 파일」 시험이 Windows에서 30번 중 3번 실패한다(`Missing expected rejection`, 10-13).
- 원인: 원본 기록과 덮어쓰기가 5~8ms 간격이면 NTFS가 같은 mtime/ctime을 찍고 크기·ino도 같아 stat 서명이 그대로다. 다른 프로그램 때문에 타이머 해상도가 1/8/15.625ms로 바뀌어 재현이 들쭉날쭉하다.
- 고침: 변경 감지를 시험할 때는 원본을 `utimes(path, old, old)`(60초 전)로 과거로 돌린 뒤 진짜로 덮어쓴다(같은 관용구 `delivery-file-inspection.test.mjs`). 원인 재현은 `--import` 로더 훅으로 `node:fs/promises`의 mtimeMs/ctimeMs를 16ms·1s 단위로 내려서 한다.
- 다시 확인: 1s로 내리는 훅을 걸면 옛 시험이 10/10 실패하고 고친 시험은 통과한다.

### `node --test tests/`처럼 폴더를 넘기면 시험이 하나도 안 돈다
- 증상: 데스크톱 전체 시험을 `node --test tests/`로 돌리자 요약이 「tests 1 · fail 1」이고 실패 이름이 `tests`였다(10-18, Node 24).
- 원인: 인자로 준 폴더를 시험 파일 하나로 실행하려다 실패한다. 폴더 안을 찾지 않는다.
- 고침: 셸 글롭으로 파일을 넘긴다: `node --test tests/*.test.*`(데스크톱 68개 파일, 858개 시험). 실패가 나오면 이번 변경이 없는 깨끗한 판(`git archive HEAD <폴더> | tar -x -C <임시>`)에서 같은 파일을 돌려 원래 깨진 것인지 가른다.
- 다시 확인: 요약의 tests 수가 수백이다. 10-18 master에서는 development-catalog·renderer-personalization·renderer-state·native-logout-provider의 6개가 이번 변경과 상관없이 원래 실패했다.

### 회사 업무실 화면을 실제 회사 자료 서버로 보면 안 된다
- 증상: 로컬 4191 업무실은 공용 작업본 코드와 실제 회사 자료로 돈다. 거기서 로그인하거나 바꾸면 실제 자료가 바뀐다.
- 원인: 개발 서버와 실제 자료가 한 서버에 붙어 있다.
- 고침: company 폴더에서 `node verify-workspace-fixture.mjs`를 백그라운드로 띄워 `%TEMP%/synk-workspace-review-*`의 임시 DB·가상 계정으로 본다(주소·계정 JSON이 표준 출력에 나온다, 비밀번호는 대화에 옮기지 않는다). 그래프 데모는 `demo-service.mjs`의 `createDemoDataset({directory:<임시>/demo})`로 그 임시 폴더에만 만든다. 강제로 끄면 정리가 돌지 않아 임시 폴더가 남으니 직접 지운다. 메신저 iframe이 열리면 실시간 연결 때문에 Playwright `networkidle`이 화면마다 30초씩 걸린다 — `domcontentloaded` + 고정 대기로 찍는다.
- 더 쓴 요령(10-10~10-13):
  - 로그인 자동 완성 상태는 헤드리스 Chrome에서 CDP `CSS.forcePseudoState`에 `autofill`을 주면 `:autofill`·`:-webkit-autofill`이 맞는다. 브라우저 기본 자동 완성 바탕은 생기지 않으니 필요하면 CSSOM `style.setProperty(…, 'important')`로 흉내 낸다(페이지 CSP가 `addStyleTag`를 막는다). 높은 대비는 Playwright `forcedColors: 'active'`로 잰다.
  - 휴대폰 메신저(390px)에서 「전체채팅」 분류를 누르면 서랍이 닫히고 그 분류의 첫 방이 열린다. 다른 방을 고르려면 `#mobile-menu`로 서랍을 다시 연다.
  - 합성 프로젝트가 많이 필요하면 GPT 확인용 서버의 preview-data를 SQLite `VACUUM INTO`로 복사해 쓴다(돌고 있는 서버를 건드리지 않는다). 코드를 공용 작업본과 따로 고칠 때는 「company만 실제 사본 + 나머지는 junction」 거울을 `.tmp/`에 만든다(`.tmp/client-desk-signal-20261013/make-mirror.cjs`). 거울의 쓰기 함정은 [git 노트 · 사본(거울)](git_줄끝_잠금.md#사본거울의-junction-폴더를-타고-시험패치가-공용-작업본에-쓴다)을 본다.
  - 교사 로그인 「내 수업」(2반×16명)은 `qa/verify-workspace-care-browser.mjs`(옆 저장소 SYNK-talk의 합성 학급)로 본다. 출력 환경 변수는 위 「공용 증거」 항목대로 준다.
- 다시 확인: 확인용 서버의 주소가 4191이 아니고, 끈 뒤 `%TEMP%/synk-workspace-review-*`가 남지 않았다.

## 화면 확인

### 가려진 창에서는 SYNK 게임이 스스로 멈춘다
- 증상: 앱 미리보기 창이 다른 창 뒤에 있으면 자바스크립트로 돌린 게임 흐름이 45초 뒤 시간 초과로 끝나고 음성도 안 난다. CSS 전환이 멈춘 채 찍히거나 캡처가 시간 초과된다.

- 증상: TypeScript 시험용 `node_modules` junction을 통해 원본 패키지에 쓰기가 전달됐다. 실행용 링크를 없앤 뒤에도 실제 MXC에서는 컴파일용 junction 생성이 `EPERM`으로 막혔다. JSON 키 존재만 확인한 시험도 변경 값 소비로 인정됐다.
- 원인: 컴파일과 실행 의존성이 원본 연결 또는 링크 생성 권한에 기대고 있었으며, JSON Proxy의 `has`와 실제 값 `get`을 같은 근거로 셌다.
- 고침: 컴파일·실행의 링크를 모두 없애고 필요한 import·타입·JSX 의존성만 파일 수·용량을 제한한 사본으로 준비한다. 사본 변경과 경로 탈출을 검사하고, JSON은 실제 변경 값 소비 및 값 변이 대조를 요구한다. 화면 근거는 고정된 `.tmp/synk-validation-preview/<실행>/browser-*`만 작업본 내부에 허용하고 후보 파일 공급에서 `.tmp` 전체를 차단한다.
- 다시 확인: 데이터 검증 32/32. 링크 생성을 전부 `EPERM`으로 거절하는 순수 TS·React TSX 양성, 원본 패키지 marker 불변, 의존성 쓰기·경로 탈출·키 존재만 확인하는 시험의 보류를 확인했다. 최종 MXC에서도 TypeScript·JSON 사전 검사와 최종 검증을 통과했다. 시험은 `tests/hermes-synk-validation-data.test.cjs`, 이전 재현은 `.tmp/hermes-multilang-20261018/review-runtime/`, 최종 근거는 `.tmp/hermes-multilang-20261018/verification.json`.

### 변경하지 않은 JSON 스키마가 CRLF 차이로 변경 판정을 받는다
- 증상: 실제 MXC의 사전 검사에서 기존 스키마가 `JSON_SCHEMA_CHANGE_REVIEW_REQUIRED`로 보류됐다. 작업 입장 snapshot과 작업본의 스키마는 줄끝만 달랐다.
- 원인: 변경하지 않은 스키마를 원시 바이트로 비교하면서 CRLF/LF 차이까지 내용 변경으로 처리했다.
- 고침: 기존 스키마의 동등성 비교에만 CRLF를 LF로 정규화한다. 그 밖의 바이트·공백·키 순서·제약 변경은 그대로 변경으로 판정하며 스키마 완화로 우회하지 않는다.
- 다시 확인: 데이터 검증 32/32에 줄끝만 다른 기존 스키마의 허용과 실제 내용 변경의 보류가 포함된다. 구현은 `validation-data.cjs`의 `schemaLineBytes`. 최종 MXC의 JSON 스키마·변경 값 소비도 통과했다. 근거 `.tmp/hermes-multilang-20261018/verification.json`; 앞선 실패·줄끝 조정 영수증은 별도로 보존했다.

### MXC에서 Chrome은 실행되지만 후보 HTTP 프록시 연결이 실패한다
- 증상: 실제 MXC의 브라우저 사전 검사에서 `ERR_PROXY_CONNECTION_FAILED`가 발생했다. Chrome 프로세스는 실행됐지만 `127.0.0.1` HTTP 프록시를 통한 후보 페이지 접속이 막혔다.

- 다시 확인: 화면 검증 15/15. 프록시 HTTP listener를 닫아도 PC·모바일의 실제 DOM·변경 CSS 선언 효과·입력·클릭·스크린샷이 통과했다. 최종 실제 MXC `synk-5ebf1264df44`도 사전 검사·5형식 최종 검증을 통과하고 10-18 19:21:54 KST에 8개 파일을 자동 통합했다. PC·모바일의 `playwright_route_fulfill`·후보 HTTP 요청 0을 확인했다. 근거 `.tmp/hermes-multilang-20261018/verification.json`; 새 프로세스의 검증·통합 재호출도 원본·후보·영수증·HEAD·인덱스 변경이나 native 재실행 없이 통과한 근거는 `replay-verification.json`. 앞선 실패 샘플은 보존 manifest 2개로 남겨 성공 기록과 분리했다. 이는 검사 fixture의 실제 실행 결과이며 미감·실기기 사용 결과와 구분한다.
