# 현장 노트 · 시험·화면 확인

> 판: Node 24.20 `node --test` · Playwright(Codex 런타임에 든 것) + 설치된 Chrome · Windows 11 NTFS
> 마지막 확인: 2026-10-17
> 쓴 AI: Claude Code(Claude Opus 5.5) — 09-30~10-17 Claude 메모에서 옮김

시험·화면 확인을 「통과」로 잘못 읽거나, 시험이 공용 작업본의 남의 증거를 덮은 함정이다. 틀은 [README](README.md)를 따른다.

## node --test와 CI

### 파이프로 받은 `node --test` 출력에 요약 줄이 없다
- 증상: `node --test … 2>&1 | grep '^# (tests|pass|fail)'`가 아무 줄도 못 잡는다. 실패 몇 개만 보이고 총 수·통과 수가 없어 시험이 다 돌았는지 모른다(10-17).
- 원인: Node 24는 파이프에 쓸 때도 TAP이 아닌 보고기를 쓴다.
- 고침: `node --test --test-reporter=tap --test-reporter-destination=<파일> <시험들>` 뒤 `grep -E '^# (tests|pass|fail|skipped)' <파일>`, 실패는 `grep '^not ok' <파일>`과 그 뒤의 `location:`·`error:`로 본다.
- 다시 확인: `node --test tests/AI토큰장부.test.js 2>&1 | grep -cE '^# (tests|pass|fail)'`가 0, tap 보고기 파일에는 `# tests 4`가 있다(10-17).

### 이 저장소의 CI는 전체 시험을 돌리지 않는다
- 증상: GitHub Actions가 초록이거나 「skipped」인데 정리 커밋이 깨뜨린 시험 21개가 10-03까지 쌓여 있었다.
- 원인: `.github/workflows/syntax-check.yml`은 비공개 저장소에서 저장소 변수 `SYNK_SELFHOSTED=on` + 자체 리눅스 러너가 있을 때만 돈다(08-18 「돈 안 쓴다」 결정). 지금은 push마다 skipped다. SYNK-talk의 CI는 push마다 전체 `npm test`를 돈다 — 두 저장소가 다르다.
- 고침: 파일·문서를 지우거나 토큰·생성기를 바꾼 뒤에는 `node --test --test-reporter=tap tests/*.test.js > <결과>`를 직접 돌려 `not ok`를 전후로 견준다. 공용 작업본이라 남의 작업 중인 파일 때문에 실패할 수 있으니, 실패한 시험이 읽는 파일이 `git status`에 걸리는지부터 본다. 로컬 CI 흉내는 `node tools/test-ci.js`(UTC·홈 폴더 없음, 리눅스는 못 흉내 냄). 비공개 저장소에 GitHub 호스팅 실행을 새로 붙이지 않는다(계정 전체 분 한도). 자체 러너를 다시 세울 때는 `bash tools/러너설치.sh --확인`부터 본다.
- 다시 확인: `gh run list --workflow syntax-check.yml -L 3 --json conclusion --jq '.[].conclusion'`이 skipped면 그대로다(10-17 skipped).

### 실제 키를 자동으로 읽는 도구가 시험 중에 실제 키를 보낸다
- 증상: 가짜 API 서버 흐름 시험에서 도구가 보안 폴더의 실제 Typecast 키를 가짜 서버로 보냈고, 단언 실패 문구에 그 값이 찍혀 대화 기록에 남았다(10-07, 밖으로 나가지는 않았지만 키 교체를 권함).
- 원인: 「보안 폴더 키 파일 자동 연결」 기능이 시험 모드에서도 켜져 있었다.
- 고침: 키를 읽는 코드를 더할 때 시험 환경 변수(가짜 API 주소 등)가 있으면 끄는 조건을 같이 넣는다. 단언은 키 값이 아니라 개수·길이만 본다. 시험 출력은 pass/fail 줄만 거른다.
- 다시 확인: 실제 키 파일이 있는 PC에서 시험을 돌리기 전에 그 끄는 조건을 grep으로 찾는다.

### 희소 파일 시험이 디스크가 찬 날 ENOSPC로 실패한다
- 증상: `client-delivery-archive.test.mjs`의 「bounded size rejects oversized sparse files」가 ENOSPC로 실패한다(10-14 C: 여유 1.1GB).
- 원인: 한도(2GB)+1바이트로 `truncate`하므로 NTFS에서 2GB 넘는 여유가 있어야 한다.
- 고침: 회사 전체 시험 전에 여유를 보고 2GB 미만이면 먼저 알린다. ENOSPC 실패는 꾸러미 탓으로 적지 말고, 여유를 확보한 뒤 그 파일만 다시 돌려 기록한다.
- 다시 확인: `df -h /c`의 여유가 2GB를 넘는 상태에서 그 시험 파일만 돌려 통과하는지.

### 몇 ms 사이 같은 크기로 덮어쓴 파일의 시각이 그대로다
- 증상: 「preflight 뒤 바뀐 파일」 시험이 Windows에서 30번 중 3번 실패한다(`Missing expected rejection`, 10-13).
- 원인: 원본 기록과 덮어쓰기가 5~8ms 간격이면 NTFS가 같은 mtime/ctime을 찍고 크기·ino도 같아 stat 서명이 그대로다. 다른 프로그램 때문에 타이머 해상도가 1/8/15.625ms로 바뀌어 재현이 들쭉날쭉하다.
- 고침: 변경 감지를 시험할 때는 원본을 `utimes(path, old, old)`(60초 전)로 과거로 돌린 뒤 진짜로 덮어쓴다(같은 관용구 `delivery-file-inspection.test.mjs`). 원인 재현은 `--import` 로더 훅으로 `node:fs/promises`의 mtimeMs/ctimeMs를 16ms·1s 단위로 내려서 한다.
- 다시 확인: 1s로 내리는 훅을 걸면 옛 시험이 10/10 실패하고 고친 시험은 통과한다.

### 회사 업무실 화면을 실제 회사 자료 서버로 보면 안 된다
- 증상: 로컬 4191 업무실은 공용 작업본 코드와 실제 회사 자료로 돈다. 거기서 로그인하거나 바꾸면 실제 자료가 바뀐다.
- 원인: 개발 서버와 실제 자료가 한 서버에 붙어 있다.
- 고침: company 폴더에서 `node verify-workspace-fixture.mjs`를 백그라운드로 띄워 `%TEMP%/synk-workspace-review-*`의 임시 DB·가상 계정으로 본다(주소·계정 JSON이 표준 출력에 나온다, 비밀번호는 대화에 옮기지 않는다). 그래프 데모는 `demo-service.mjs`의 `createDemoDataset({directory:<임시>/demo})`로 그 임시 폴더에만 만든다. 강제로 끄면 정리가 돌지 않아 임시 폴더가 남으니 직접 지운다. 메신저 iframe이 열리면 실시간 연결 때문에 Playwright `networkidle`이 화면마다 30초씩 걸린다 — `domcontentloaded` + 고정 대기로 찍는다.
- 더 쓴 요령(10-10~10-13):
  - 로그인 자동 완성 상태는 헤드리스 Chrome에서 CDP `CSS.forcePseudoState`에 `autofill`을 주면 `:autofill`·`:-webkit-autofill`이 맞는다. 브라우저 기본 자동 완성 바탕은 생기지 않으니 필요하면 CSSOM `style.setProperty(…, 'important')`로 흉내 낸다(페이지 CSP가 `addStyleTag`를 막는다). 높은 대비는 Playwright `forcedColors: 'active'`로 잰다.
  - 휴대폰 메신저(390px)에서 「전체채팅」 분류를 누르면 서랍이 닫히고 그 분류의 첫 방이 열린다. 다른 방을 고르려면 `#mobile-menu`로 서랍을 다시 연다.
  - 합성 프로젝트가 많이 필요하면 GPT 확인용 서버의 preview-data를 SQLite `VACUUM INTO`로 복사해 쓴다(돌고 있는 서버를 건드리지 않는다). 코드를 공용 작업본과 따로 고칠 때는 「company만 실제 사본 + 나머지는 junction」 거울을 `.tmp/`에 만든다(`.tmp/client-desk-signal-20261013/make-mirror.cjs`). 거울의 쓰기 함정은 [git 노트 · 사본(거울)](git_줄끝_잠금.md#사본거울의-junction-폴더를-타고-시험패치가-공용-작업본에-쓴다)을 본다.
  - 교사 로그인 「내 수업」(2반×16명)은 `qa/verify-workspace-care-browser.mjs`(옆 저장소 SYNK-talk의 합성 학급)로 본다. 출력 환경 변수는 위 「공용 증거」 항목대로 준다.
- 다시 확인: 확인용 서버의 주소가 4191이 아니고, 끈 뒤 `%TEMP%/synk-workspace-review-*`가 남지 않았다.

## 화면 확인

### 가려진 창에서는 SYNK 게임이 스스로 멈춘다
- 증상: 앱 미리보기 창이 다른 창 뒤에 있으면 자바스크립트로 돌린 게임 흐름이 45초 뒤 시간 초과로 끝나고 음성도 안 난다. CSS 전환이 멈춘 채 찍히거나 캡처가 시간 초과된다.
- 원인: 창이 가려지면 `document.hidden`이 되고, 게임은 `visibilitychange`에서 일시정지한다. 브라우저도 가려진 탭의 타이머를 늦춘다.
- 고침: 실제 플레이 확인은 격리된 헤드리스 Chrome으로 한다: `require.resolve('playwright', { paths: [path.join(process.env.USERPROFILE, '.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules')] })` → `chromium.launch({ channel: 'chrome', headless: true, args: ['--autoplay-policy=no-user-gesture-required'] })`. 보기: `experiences/order-rush/qa/atlas-smoke.cjs`. 녹화·시연 영상도 헤드리스 창과 게임 소리만 찍는다.
- 다시 확인: 헤드리스에서 `document.visibilityState`가 `visible`이고 게임 시계가 흐른다.

### 개발 플랫폼 창의 원격 디버깅 포트를 다른 세션이 브라우저로 쓴다
- 증상: `npm run dev:platform -- --remote-debugging-port=9333`으로 띄운 개발 창이 꿀팁 사이트 페이지로 바뀌어 있었고, 그 상태에서 구독 화면 요청이 `UNTRUSTED_SENDER`로 거절됐다. 창이 다른 창 뒤에 있으면 `Page.captureScreenshot`도 멈춘다(10-17).
- 원인: 다른 세션의 CDP 스크립트가 같은 9333에 붙어 그 창을 페이지 캡처용 브라우저로 `Page.navigate`했다(`Get-NetTCPConnection -RemotePort 9333`에 그 세션의 node가 붙어 있었다). 플랫폼 화면이 아닌 페이지에서 온 IPC는 본체가 거절한다(정상 동작). 캡처는 창이 가려져 `document.hidden`이면 그리지 않아 기다린다.
- 고침: 세션마다 겹치지 않는 포트로 띄운다(예: `--remote-debugging-port=9455`, 스크립트는 `CDP_PORT`로). 같은 데이터 폴더로는 개발 창이 하나만 뜨므로 다시 띄우기 전에 그 포트에 붙은 연결부터 본다. 창을 앞으로 꺼낼 때는 같은 명령으로 한 번 더 실행하거나(앱이 두 번째 실행을 받아 창을 보임), user32 `ShowWindow(최소화 6 → 되살리기 9)`를 쓴다. 확인은 캡처 대신 `Runtime.evaluate`로 화면 글자·`synkDesktop.subscriptions.snapshot()`을 읽는다.
- 다시 확인: `http://127.0.0.1:<포트>/json`의 url이 `synk-desktop://platform/index.html`이고, `document.hidden`이 false다.

### 휴대폰 흉내 캡처에서 가로 넘침이 숨는다
- 증상: 영어판 긴 버튼 문구가 320~430px 화면 밖으로 나갔는데 `scrollWidth > innerWidth` 검사는 「이상 없음」이었다(09-30 홈페이지).
- 원인: 휴대폰 흉내(`isMobile`) Chrome은 가로 스크롤 대신 페이지 전체를 축소하고 `innerWidth`도 같이 늘린다. 실제 휴대폰도 같아서 사용자는 글자가 작아진 페이지를 본다.
- 고침: 휴대폰 폭 검사에 `innerWidth > visualViewport.width + 1`(축소됨)을 꼭 넣는다. 원인 요소는 `isMobile:false`로 같은 폭을 열어 `getBoundingClientRect().right > innerWidth`인 가장 깊은 요소로 찾는다. 화면 좌표로 픽셀을 재는 스크립트는 `innerHeight` 대신 `visualViewport.height`를 쓴다. `white-space:nowrap`을 줄 때는 영어 번역 길이를 먼저 본다.
- 다시 확인: 넘치는 요소를 일부러 넣은 페이지에서 `innerWidth > visualViewport.width`가 참이 된다.
