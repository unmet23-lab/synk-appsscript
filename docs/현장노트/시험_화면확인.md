### push 뒤 syntax-check 실행이 줄줄이 cancelled로 끝난다 (2026-10-19)
- 증상: 10-19 밤 계정판 3차 커밋 셋(`724fe663c`·`69950a3b7`·`33de840a4`)을 올린 뒤 세 커밋의 syntax-check가 모두 cancelled였다. 그 뒤로도 다른 세션이 1~2분마다 올려 `9c906b35c`·`44b71394b`·`609742d03`·`33de840a4` 실행이 잇달아 cancelled로 끝났다.
- 원인: `.github/workflows/syntax-check.yml`이 `concurrency: syntax-${{ github.ref }}`·`cancel-in-progress: true`라 master에 새 push가 오면 돌던 실행을 끊는다. 실행 하나가 몇 분 걸려 바쁜 때는 끝까지 도는 실행이 드물다. cancelled는 실패가 아니지만 내 커밋의 판정도 아니다.
- 고침: 내 커밋을 품은 뒤 커밋의 실행 가운데 끝까지 돈 것으로 판정한다 — `gh run list --branch master --workflow syntax-check.yml --json databaseId,headSha,conclusion`에서 고르고 `git merge-base --is-ancestor <내 커밋> <headSha>`로 품었는지 본다. 기다릴 때는 최신 실행을 따라가며 success·failure만 끝으로 치고 cancelled면 다음 실행으로 넘어가는 루프를 상한을 두고 뒤에서 돌린다. 그동안 내 변경을 읽는 시험은 손으로 돌려 둔다(문서만 바꿨으면 `rg -l "<문서 파일명>" tests`로 찾은 루트 시험 — 10-19 결정·설계·트랙을 읽는 9개 122/122).
- 다시 확인: `MSYS_NO_PATHCONV=1 git show origin/master:.github/workflows/syntax-check.yml | grep -A2 concurrency`가 `cancel-in-progress: true`면 아직 그대로다.

### 갱신일을 날짜로 박은 키 순서 시험이 매달 며칠씩 빨갛다 (2026-10-20)
- 증상: 10-20 아침 master CI가 문서만 바꾼 커밋들에서 `tests/크레딧실행.test.js` 「첫 턴에 크레딧 부족이면 … 다음 키로」 하나로 실패했다(`['aaaa','bbbb']` 대신 `['bbbb']`). 코드는 10-19 초록 판과 같았고 로컬에서도 세 번 다 실패했다.
- 원인: `tools/lib/클로드키.js`는 「다음 갱신일이 가장 가까운 키」부터 쓰는데, 시험은 가짜 키 A·B의 갱신일을 20일·25일로 박아 두었고 `작업돌리기`가 기준 시각을 받지 않아 실제 시계로 셌다. 매달 20일 0시가 지나면 A의 다음 갱신이 다음 달로 넘어가 24일까지 B가 먼저 골라진다. 같은 순서를 보는 `tests/클로드키.test.js`는 처음부터 `지금`을 고정해 넘겨 괜찮았다.
- 고침: 처음에는 시험의 갱신일을 오늘에서 셌다(`며칠뒤일(1)`·`며칠뒤일(5)`, `6ac63d964`). 그래도 시험이 날짜를 센 순간과 실행기가 시각을 읽는 순간 사이에 자정이 끼면 틀릴 수 있어, `작업돌리기`·`중계`가 옵션 `지금`을 클로드키의 `키고르기`·`소진표시`·`기록남기기`에 넘기게 했다(안 주면 실제 시각 — 동작 그대로). 시험은 지난 날 `new Date(2025, 2, 10, 12)`을 줘서, 주입이 빠지면 풀림·기록 시각 단언이 늘 깨진다. 날짜에 기대는 시험은 기준 시각을 넣는다.
- 다시 확인: `node --test --test-reporter=tap tests/크레딧실행.test.js` 8/8. 주입 없는 옛 실행기에 지금 시험을 돌리면 3·6번이 깨진다(10-20).
- 덧붙임(10-20 Claude): 시험 파일을 통째로 다른 날짜에서 돌리려면 `tests/lib/날짜옮기기.cjs`를 넣는다 — Git Bash에서 `SYNK_FAKE_TODAY=2026-09-20 NODE_OPTIONS="--require=$(cygpath -m "$PWD")/tests/lib/날짜옮기기.cjs" node --test --test-reporter=tap tests/크레딧실행.test.js`, 자정을 넘기며 보려면 `SYNK_FAKE_TODAY=2026-09-19T23:59:59.400`. 인자 없는 `new Date()`·`Date.now()`만 옮겨지고 시험 프로세스와 node 자식까지 같은 시계로 들어가며(처음 센 차이를 `SYNK_FAKE_TODAY_OFFSET`으로 물려줌), CI처럼 보려면 `TZ=UTC`를 더한다(Git Bash는 `UTC`·`EST5EDT` 같은 꼴만 노드에 넘기고 `America/New_York`처럼 `/`가 든 이름은 빼 버린다 — 다른 시간대는 [윈도우 셸](윈도우_셸.md) 「Git Bash의 시각과 시간대를 믿지 않는다」). 고치기 전 판(`git archive f52a9441c`)은 20·24일과 10-20에만 1개 실패하고 1·19·25·28·31일은 8/8, `지금`을 넣은 판은 서울·UTC × 날짜 10개와 자정 직전 시작 5개 모두 8/8이었다. 날짜는 지난달에서 고른다(31일은 8월 31일) — 미래로 옮기면 실행기 잠금이 `Date.now() - mtime`으로 나이를 재서 「같은 작업이 겹쳐 돌지 않는다」가 `Missing expected rejection`으로 따로 깨진다(10-24·11-20, 제품 고장 아님).

### 파이프로 받은 `node --test` 출력에 요약 줄이 없다
- 증상: `node --test … 2>&1 | grep '^# (tests|pass|fail)'`가 아무 줄도 못 잡는다. 실패 몇 개만 보이고 총 수·통과 수가 없어 시험이 다 돌았는지 모른다(10-17).
- 원인: Node 24는 파이프에 쓸 때도 TAP이 아닌 보고기를 쓴다.
- 고침: `node --test --test-reporter=tap --test-reporter-destination=<파일> <시험들>` 뒤 `grep -E '^# (tests|pass|fail|skipped)' <파일>`, 실패는 `grep '^not ok' <파일>`과 그 뒤의 `location:`·`error:`로 본다.
- 다시 확인: `node --test tests/AI토큰장부.test.js 2>&1 | grep -cE '^# (tests|pass|fail)'`가 0, tap 보고기 파일에는 `# tests 4`가 있다(10-17).

### 몇 ms 사이 같은 크기로 덮어쓴 파일의 시각이 그대로다

### CI에서 실패한 시험을 `git archive HEAD` 사본으로 돌리면 통과한다 (2026-10-19)

- 다시 확인: `git merge-base --is-ancestor <CI 커밋> HEAD`가 실패하면 HEAD로는 그 CI를 재현할 수 없다.

### 휴대폰 흉내 캡처에서 가로 넘침이 숨는다
- 증상: 영어판 긴 버튼 문구가 320~430px 화면 밖으로 나갔는데 `scrollWidth > innerWidth` 검사는 「이상 없음」이었다(09-30 홈페이지).
- 원인: 휴대폰 흉내(`isMobile`) Chrome은 가로 스크롤 대신 페이지 전체를 축소하고 `innerWidth`도 같이 늘린다. 실제 휴대폰도 같아서 사용자는 글자가 작아진 페이지를 본다.
- 고침: 휴대폰 폭 검사에 `innerWidth > visualViewport.width + 1`(축소됨)을 꼭 넣는다. 원인 요소는 `isMobile:false`로 같은 폭을 열어 `getBoundingClientRect().right > innerWidth`인 가장 깊은 요소로 찾는다. 화면 좌표로 픽셀을 재는 스크립트는 `innerHeight` 대신 `visualViewport.height`를 쓴다. `white-space:nowrap`을 줄 때는 영어 번역 길이를 먼저 본다.
- 다시 확인: 넘치는 요소를 일부러 넣은 페이지에서 `innerWidth > visualViewport.width`가 참이 된다.

### `overflow-x:clip`으로 가린 넘침은 scrollWidth에 안 잡히는데 전체 캡처는 넓어진다
- 증상: 10-19 PATH 시안에서 화면 끝까지 닿는 막대를 `:after{left:-100vmax;right:-100vmax}`로 그렸다. `scrollWidth`는 1440 그대로였는데 Playwright `fullPage` 캡처가 2840px 폭으로 나왔다.
- 원인: `html,body{overflow-x:clip}`이 사용자 스크롤은 막지만 레이아웃 넘침 자체는 남는다. 캡처는 그 넘침까지 포함한 크기로 찍는다. 휴대폰에서 확대·축소로 그 넘침이 보일 위험도 있다.
- 고침: 끝까지 닿는 바탕은 `box-shadow:0 0 0 100vmax #fff` + `clip-path:inset(0 -100vmax)`, 아래 선은 `border-image:linear-gradient(...) 0 0 1 0 / 0 0 1px 0 / 0 100vmax`(바깥으로 뻗는 테두리 그림)로 바꿨다. 둘 다 그림 넘침이라 레이아웃 폭을 만들지 않는다.
- 다시 확인: 같은 화면의 `fullPage` 캡처 폭이 창 폭(1440)과 같다.

### 번역으로 글이 길어지면 같은 폭 칸 안에서 넘친다 — 화면 전체 넘침 검사로는 안 잡힌다 (2026-10-20 Claude)
- 증상: 화면 언어 1판 후보를 영어·몽골어로 열자 PC·가로 태블릿 홈의 지름길 알약 「복습 일정」이 「Review Schedule」·「Давтлага Хуваарь」가 되어 알약 밖으로 넘쳐 잘렸다. `scrollWidth > innerWidth`와 열린 판 요소 검사는 모두 「넘침 없음」이었다.
