### 바탕화면에 둔 파일이 화면에 안 보인다
- 증상: `%USERPROFILE%\Desktop`에 둔 결과물을 유호님이 「왜 안 보이지」라고 한다(09-27).
- 원인: 이 PC의 바탕화면은 OneDrive 폴더로 옮겨져 있다. 그 OneDrive는 10-05부터 무료 용량이 차서 다른 기기로 올라가지도 않는다.
- 고침: 바탕화면 경로는 손으로 쓰지 않고 PowerShell `[Environment]::GetFolderPath('Desktop')`로 받는다. 둔 뒤 그 경로에 실제로 있는지 보고, 안내에도 전체 경로를 적는다. 다른 기기로 건넬 때는 OneDrive를 믿지 않는다.
- 다시 확인: `[Environment]::GetFolderPath('Desktop')`가 `$env:USERPROFILE\Desktop`과 다른지 본다. PC를 바꾸면 위치가 달라질 수 있다.

### 세션 공유 미러가 예약 작업 목록을 덮어 모든 계정의 예약이 사라진다

- 원인: 앱은 계정에 로그인할 때마다(`main.log`의 `[CCDScheduledTasks] Reset` → `Initialized`) 그 계정 폴더의 예약 목록을 다시 쓰고, 처음 로그인한 계정에는 빈 목록을 쓴다. 세션 공유가 이 파일까지 「최근 것이 이김」으로 맞추면 빈 목록 하나가 모든 계정의 예약을 지운다. 이번에는 v1(junction) 때 앱이 목록 저장을 거부한 일(`Failed to save scheduled tasks: Refusing non-directory …`, 10-17 11:21·11:28)이 겹쳐, 14:44 계정 전환 때 비었다.

### 세션 공유의 「껐다 켜기」 알림이 한 번도 뜨지 않았고, 같은 계정 재로그인을 빈 목록으로 오인했다 (2026-10-19)

- 원인: 셋이다. ① 같은 사용자 재로그인 때 앱은 `[LocalSessionManager] Initialization succeeded — … existingSessions=95` 다음에 `Loaded 0 persisted sessions`를 쓴다. 이미 메모리에 있어 새로 읽은 것이 0개라는 뜻인데, 스크립트는 「0개를 읽음」만 보고 빈 목록으로 판단했다. ② 알림용 PowerShell을 `spawn(…, {detached:true})`로 띄워 콘솔이 없어서 스크립트가 한 줄도 돌지 않았다(아래 「Node의 detached로 띄운 PowerShell·CLI에 창이 생기지 않는다」). 그래서 「알림이 뜨면 껐다 켜세요」라던 안내가 실제로는 한 번도 닿지 않았다. ③ 「Loaded N」 줄의 경로를 `\S+?`로 찾아, 사용자 이름에 공백이 있으면(`C:\Users\Hong Gildong\…`) 그 줄을 아예 못 읽었다(Fable 검수에서 찾음).
