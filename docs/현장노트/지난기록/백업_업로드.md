### 정상 OneDrive 목적 폴더도 ReparsePoint다
- 증상: 10-17 모든 reparse 경로를 막은 첫 필터가 실제 OneDrive 복사 목적지까지 차단했다.

- 고침: 원본 쪽 cloud·링크는 계속 차단한다. 사용 중인 OneDrive 목적 루트 안에서만 정확한 cloud 태그를 허용하고 junction·symlink·알 수 없는 태그는 막는다. 기존 cloud 사본의 내용을 비교 목적으로 내려받지 않는다. 인증 기능 소스(`auth-settings.js` 등)는 이름만 보고 자격증명으로 제외하지 않고 내용 검사도 적용한다.
- 다시 확인: 실제 OneDrive 목적 경로를 메타데이터만 읽어 원본 모드 차단·신뢰 목적 모드 허용을 확인했다. 격리 시험의 junction 차단과 `.ts` 바이너리·인증 소스 판정을 함께 확인한다. 이 검사는 실제 클라우드 복사·동기화 완료의 증거가 아니다.
- 옮긴 까닭(2026-10-20, 도구): `이어하기꾸러미.js`가 정확한 cloud 태그만 목적지로 허용하고 junction·symlink는 막는다(코드·시험 확인)

### 영수증을 몇 초마다 다시 쓰는 단계가 코드 없는 오류로 끝난다 (2026-10-19)
- 증상: 위 고침 뒤에도 18:56·19:15 예약 적용 실행의 묶음 단계가 암호화한 임시 파일(192MB)까지 만든 뒤 `detailCode` 없이 실패했고, 19:26 확인 실행의 보호 소스 단계도 160줄째에서 `PROTECTED_SOURCE_INVENTORY_UNAVAILABLE`(코드 꼴이 아닌 오류)로 멈췄다. 같은 묶음 단계를 영수증 없이 직접 돌리면 127초 만에 성공했다.
- 원인(직접 잡지 못함): 두 단계 모두 몇 초마다(선행 커밋마다·보호 소스 줄마다) 영수증을 「임시 파일 → 이름 바꾸기」로 다시 쓴다. - 고침: `GitHub백업.cjs`에 `replaceFile`(그 세 오류만 최대 20번, 약 9.5초 기다리며 다시)을 두고 GitHub·Git 묶음·보호 소스의 영수증 쓰기가 같이 쓴다. 원인을 다음에는 볼 수 있게 Git 묶음의 git 실패는 `GIT_<명령>_FAILED`/`_TIMEOUT`, gh 호출은 `GITHUB_API_FAILED`/`_TIMEOUT`, 그 밖의 오류는 `SYSTEM_<코드>`와 `failedRepository`를 남기고, 보호 소스도 `PROTECTED_SOURCE_SYSTEM_<코드>`를 남긴다. 출력 원문은 남기지 않는다(`9718dfa7f`). `onedrive-backup.cjs`의 `writeJson`은 다른 세션의 미커밋 수정이 얹혀 있어 아직 그대로다(heartbeat 쓰기만 그 세 오류를 넘긴다).
- 다시 확인: `tests/GitHub백업.test.cjs`·`tests/Git보관묶음.test.cjs`에 시험 2개를 더했고 백업 Node 시험 95개가 통과했다. 실패한 두 묶음의 임시 암호문 `.git-bundle-staging/2c0111d9-…enc`·`07e0fe7b-…enc`(각 192MB)는 지우지 않고 남겨 두었다. 같은 실패가 다시 나면 `git-bundle-status.json`의 `detailCode`·`failedRepository`부터 본다.

### 공개 원격이면 Git 묶음이 실행마다 전체 이력(6.9GB)이 된다 (2026-10-19)
- 증상: SYNK-appsscript를 당분간 공개로 바꾸기 전 확인에서, `Git보관묶음.cjs`가 공개 원격의 미게시 이력을 선행 커밋 없는 완전 bundle로 만든다는 것을 봤다. 공용 master는 1~2분마다 커밋이 쌓여 GitHub 백업(2시간마다)이 돌 때마다 묶을 머리가 바뀌므로, 실행마다 master 전체 이력(`git rev-list --objects --disk-usage master` 6,877MB)을 새로 묶어 25Mbps로 약 38분씩 올리게 된다.
- 원인: 공개 원격에는 고정 ref를 쓰지 않는 대신 「공개 가지가 나중에 바뀌어도 복원되게」 조상 이력 전체를 담도록 짰다(10-18). 작은 공개 저장소에서는 괜찮았지만 이력이 큰 저장소를 공개하면 커진다.
- 고침: 공개 원격도 원격 ref가 가리키는 커밋을 빼고 안 올린 몫만 묶는다. 경계의 선행 커밋은 원격에 쓰지 않고 그 커밋에 닿는 공개 ref 이름만 영수증에 `public: true`로 적고, 확인할 때마다 지금 원격 ref에서 닿는지 `rev-list <선행> ^<원격 끝>…`으로 다시 본다. 행 종류대로 확인하므로 다시 비공개로 돌려도 그대로 통한다. 원격에 ref가 하나도 없을 때만 예전처럼 완전 bundle이다. 복원은 공개 저장소를 clone한 뒤 그 안에서 한다([Git 자산 보관](../../_ops/github-storage/README.md)).
- 다시 확인: 이 저장소의 안 올린 머리 125개에서 원격 끝 559개를 빼고 `git rev-list --objects --disk-usage --stdin`으로 재면 약 145MB(커밋 295개)다. `tests/Git보관묶음.test.cjs`의 「public unpublished heads … only what the public origin lacks」·「prerequisite rows are checked by their kind」가 고치기 전 판에서 실패하고 고친 판에서 통과한다(백업 시험 31/31).
- 옮긴 까닭(2026-10-20, 도구): `Git보관묶음.cjs`가 공개 원격 ref 이후 몫만 묶는다(코드·시험 확인)
