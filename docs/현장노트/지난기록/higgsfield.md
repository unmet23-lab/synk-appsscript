## 계정·잔액·제출에서 (2026-10-20)

### 홈을 바꿔 로그인한 계정 폴더가 지워지지 않는다
- 증상: 회원판 AI 구독 계정판 개발 창에서 Higgsfield 새 계정 로그인이 5분 시간 초과로 끝난 뒤(승인 안 하면 CLI가 5분에 끝나 「로그인을 마치지 못했어요」), 지워져야 할 계정 폴더가 남았다. 그 폴더를 Electron의 Node `fs.rmSync`로 지우면 EPERM이었다(10-17).
- 원인: CLI가 브라우저를 열 때 Windows가 바뀐 홈 안에 `AppData\Local\Microsoft\Windows\INetCache`(숨김·시스템, `Content.IE5` junction)·`INetCookies`를 만든다. 로그인 프로그램이 막 끝난 그 순간에는 무언가 이 캐시 폴더를 잡고 있어 한 번에 지우기가 실패했다. 같은 모양을 만들어 지우면 일반 Node·Electron Node 모두 지워져, 모양이 아니라 잠깐 잡힌 것이다.
- 고침: `desktop/src/ai-subscriptions.cjs`의 `removeFolder`가 한 번에 지우기 → 아래부터 하나씩(링크는 따라 들어가지 않고 링크만) → 1초 간격으로 10번 더 지운다. 계정 「지우기」에서 로그인 파일·캐시 폴더까지 지워지는 시험을 붙였다.
- 다시 확인: 개발 창에서 「새 계정 연결」 뒤 브라우저가 열리면(INetCache 생김) 「로그인 취소」 → 계정 폴더가 1초 안에 없어진다(10-17 15:29 실측 0.5초).
- 옮긴 까닭(2026-10-20, 도구): `desktop/src/ai-subscriptions.cjs`의 `removeFolder`(628행)가 재시도로 지우고 `desktop/tests/ai-subscriptions.test.cjs`에 시험이 있다 — 계정판 「지우기」를 쓰면 다시 걸리지 않는다

## MiniMax H3에서 (2026-10-20)

### 시작·끝 그림과 참고 그림을 같이 주면 422로 거절된다 (견적은 통과한다)
- 증상: `minimax_h3`에 start_image(+end_image)와 image_references를 함께 넣자 「start_image/end_image cannot be mixed with reference media」 422로 거절됐다. 같은 조합의 `get_cost` 견적은 20·8크레딧으로 통과했다(10-18 하린 아이스커피, 접수 전이라 0크레딧).
- 원인: H3는 Wan 3.0처럼 「시작·끝 그림 방식」과 「참고 그림 방식」 가운데 하나만 받는다. 견적(get_cost)은 이 조합을 검사하지 않는다.
- 고침: 컷 단위는 시작 그림만(키프레임에 얼굴이 이미 있다), 장면 전환을 잠그려면 시작 + 끝 그림만, 여러 키프레임·얼굴 사진을 같이 쓰려면 시작 그림 없이 참고 그림만 넣는다. 입력 조합은 견적이 아니라 실제 제출로 확인한다(거절은 청구되지 않는다). H3 지시문에도 프리셋 추천(「3D RENDER」·「IN THE DARK」)이 끼어들어 0건이 되니 `declined_preset_id`를 같이 넣는다.
- 다시 확인: 제출 결과에 작업 ID가 오고 `transactions`에 그 값만큼 찍힌다.
- 옮긴 까닭(2026-10-20, 옛 판): 10-18 「영상 모델 네 가지」 결정으로 힉스필드 MiniMax H3(클라우드)는 안 쓴다 — 로컬 H3(ComfyUI)와는 다른 길

### 4초 주문은 이유 없이 실패한다 (5초부터 된다)
- 증상: 10-18 하린 아이스커피에서 `minimax_h3` 4초 주문 5건(시작 그림만, 얼굴 없는 뒷모습 컷 포함)이 2~4분 뒤 이유 표시 없이 failed·8크레딧 환불이었다. 같은 형식의 5초(컷 7)·6초(탐침)는 성공했다. `job_display`에는 오류 문구가 없고 `type`이 video가 아닌 image로 찍혔다.
- 원인: 모델 설명은 4~15초(기본 5)인데 4초 길이가 지금 제대로 처리되지 않는 것으로 보인다. 그림·지시문·검열 문제는 아니었다(같은 지시문·그림을 5초로 바꾸자 성공).
- 고침: H3는 5초 이상으로 낸다(5초 10크레딧). 편집에서 쓰는 길이가 짧아도 5초로 뽑아 잘라 쓴다.
- 다시 확인: 같은 지시문·시작 그림 4건(4a·4b·5a·1)을 5초로 다시 내서 completed를 받았다(결과 길이 5.17초, 1440×2528).
- 옮긴 까닭(2026-10-20, 옛 판): 같은 결정으로 힉스필드 `minimax_h3`는 안 쓴다(로컬 H3는 5초 한 컷). 브리프_콘티_v4.md 246행이 이 제목을 가리킴

## Kling에서 (2026-10-20)

### kling_video_edit가 이유 없이 실패한다
- 증상: 480×854 입력 셋이 이유 표시 없이 failed(환불)였다(10-07). 10-11 밤에는 720×1280 입력으로 10번 넣었는데 전부 failed였다(소리 트랙을 넣어도, 얼굴 사진을 빼도).
- 원인: 480p 입력은 받지 않는 것으로 보인다. 10-11 실패의 원인은 못 찾았다(막다른 길).
- 고침: 720×1280로 키워 넣고, 2초 미만 구간은 앞→뒤로 이어 3초 이상으로 넣는다. 바꾼 물건 둘레의 머리를 새로 그리니 처음부터 사람 기준 사진(같은 장면 얼굴 정지컷)을 같이 넣는다. 결과는 24fps에 길이가 조금 달라 원래 길이로 늘린 뒤 `minterpolate`로 30fps에 맞추고 소리는 원본에서 가져온다. 지금 영상의 부분 수정은 유호님 결정에 따라 Seedance로만 하고, 도구를 바꿀 때는 먼저 말한다(FLUX 영상 편집은 재질 차이로 막혔다). `hf_mult_replace_object`는 입력이 4~30초여야 한다.
- 다시 확인: 짧은 시험 구간 하나로 접수·완료되는지 본다.
- 옮긴 까닭(2026-10-20, 옛 판): Kling은 쓰지 않고 영상 부분 수정은 Seedance로만 한다는 결정이 있고, 메모도 이 기록을 「예전 기록(참고만)」으로 둠
