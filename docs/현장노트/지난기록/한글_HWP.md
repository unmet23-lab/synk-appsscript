# 현장 노트 · 한글(HWP) 공식 양식 · 지난 기록

> [한글_HWP](../한글_HWP.md)에서 2026-10-20에 옮긴 항목이다(글은 그대로, 상대 링크만 이 폴더에 맞춤). 도구가 이제 자동으로 막아 주거나(도구), 지금은 안 쓰는 옛 PC·판·절차 이야기거나(옛 판), 다시 오지 않을 한 번의 일(한 번)이다. 같은 증상을 다시 겪으면 그 항목을 원래 파일의 맞는 절로 되돌리고 고친다.

## 설치·실행에서 (2026-10-20)

### HWP를 다룰 길을 못 찾아 LibreOffice·Word로 돌아간다
- 증상: 10-14 이전 GPT 세션이 HWP 양식을 LibreOffice·Word로 우회하다가 「HWP 미완성」으로 남겼다.
- 원인: 옛 노트북에는 한컴오피스 2024와 COM `HWPFrame.HwpObject`가 있었는데 찾아보지 않았다. 파이썬에는 pywin32가 없어서 파이썬으로는 COM을 부를 수 없다.
- 고침: 한컴오피스가 있으면 PowerShell `New-Object -ComObject HWPFrame.HwpObject`로 부른다. 새 노트북에는 설치하지 않으니(10-17), 읽기는 위 「한컴 없이 읽기」의 도구로 하고 LibreOffice·Word로 돌아가지 않는다.
- 다시 확인: `Test-Path "Registry::HKEY_CLASSES_ROOT\HWPFrame.HwpObject"`(10-17 새 노트북 False), `python -c "import win32com"`(10-17 ModuleNotFoundError).
- 옮긴 까닭(2026-10-20, 옛 판): 옛 노트북 한컴 COM 길 이야기 — 새 PC에는 한컴이 없고 설치하지 않는다(10-17). 오늘 길은 「한컴 없이 읽기」 절이라 first 요약에 「LibreOffice·Word로 우회하지 않는다」를 옮겨 적었다

### COM 만들기가 80080005로 실패한다
- 증상: `New-Object -ComObject HWPFrame.HwpObject`가 80080005로 실패한다(10-14).
- 원인: 한글을 처음 실행할 때 2분 넘게 걸려서 COM 생성이 그 전에 시간 초과로 끝난다.
- 고침: 한글 앱을 한 번 띄워 끝까지 켜지게 둔 뒤 다시 부른다.
- 다시 확인: 한글을 켜 둔 상태에서 COM 생성이 몇 초 안에 끝나는지 본다.
- 옮긴 까닭(2026-10-20, 옛 판): 한컴오피스 2024 COM 길 — 새 PC에는 한컴·`HWPFrame.HwpObject`가 없다

### 파일을 열 때마다 접근 허용 창이 뜬다
- 증상: COM으로 파일을 열 때마다 파일 접근 보안 창(접근 허용/모두 허용)이 떠서 작업이 멈춘다(10-14).
- 원인: 한글의 파일 접근 보안이 인스턴스마다 묻는다.
- 고침: 한글 인스턴스 하나를 작업 서버(`hwp_server.ps1`, `jobs` 폴더를 지켜보며 작업을 받음)로 살려 두고, 그 인스턴스에서 「모두 허용」을 한 번 누른다. 누르는 것은 computer-use에 한글 2024를 허가해서 했다.
- 다시 확인: 작업 서버로 파일 두 개를 연달아 열어 두 번째에 창이 안 뜨는지 본다.
- 옮긴 까닭(2026-10-20, 옛 판): 한컴 COM 작업 서버(`hwp_server.ps1`) 길 — 새 PC에서 안 쓴다

### 새 작업이 RPC 0x800706BA로 실패한다
- 증상: 세션이 끊긴 뒤 새로 넣은 작업이 RPC 0x800706BA로 실패한다(10-14).
- 원인: 백그라운드 작업 서버가 살아남아 새 작업을 가로챈다. 도구가 띄운 pwsh의 명령줄은 인코딩되어 있어서 프로세스 이름이나 명령줄로는 찾을 수 없다.
- 고침: 작업 서버를 띄운 시각으로 pwsh 프로세스를 찾아 끈 뒤 다시 띄운다.
- 다시 확인: `Get-Process pwsh | Select-Object Id,StartTime`에서 작업 서버를 띄운 시각의 프로세스가 하나뿐인지 본다.
- 옮긴 까닭(2026-10-20, 옛 판): 한컴 COM 작업 서버(`hwp_server.ps1`) 길 — 새 PC에서 안 쓴다

### 시작 화면 광고 창을 닫으려다 서식 썸네일을 연다
- 증상: 광고 창의 닫기 자리를 눌렀는데 아래 서식 썸네일이 열렸다(10-14).
- 원인: 광고 창이 늦게 뜬다. 찍은 화면에서는 광고가 아직 없었는데 누르는 순간에 떠 있거나, 그 반대였다.
- 고침: 화면을 다시 찍어 광고 창이 있는지 본 뒤에 누른다.
- 다시 확인: 누르기 직전 화면에 광고 창 닫기 단추가 보이는지 본다.
- 옮긴 까닭(2026-10-20, 옛 판): 한컴오피스 2024 화면 조작 — 새 PC에서 안 쓴다

## 양식 채우기에서 (2026-10-20)

### 검토 PDF가 한 장에 두 쪽씩 나온다
- 증상: 한글로 저장한 PDF가 한 장에 양식 두 쪽씩 들어 있다(10-14).
- 원인: 양식의 인쇄 방식이 PrintMethod=4(모아 찍기)로 되어 있다.
- 고침: 제출할 HWP는 그대로 두고, 검토용 PDF만 settings.xml의 PrintMethod를 0으로 바꾼 사본에서 뽑는다.
- 다시 확인: HWPX 안 `settings.xml`의 PrintMethod 값을 본다.
- 옮긴 까닭(2026-10-20, 옛 판): 한글이 PDF로 찍을 때(PrintMethod=4) 나는 일 — 한컴이 없는 새 PC에서는 만나지 않는다

## 한컴 없이 HWP 고치기에서 (2026-10-20)

### `tools/hwp읽기.py`가 HWP 표 머리 행에 표 제목을 칸처럼 끼워 보였다
- 증상: 10-19 같은 원고의 HWP와 HWPX를 읽어 견주니 HWP 쪽만 매출 표 머리 행이 `| 순번 | 목표시장(고객) | < 매출 실적 > | 제품·서비스 | …`처럼 나왔다. HWPX 쪽은 표 제목을 아예 적지 않았다.
- 원인: HWP 표 제목(캡션)은 `TABLE` 레코드 앞의 `LIST_HEADER`(+문단)에 들어 있는데, 읽기 도구가 그것까지 칸으로 셌다. 그 `LIST_HEADER`의 8바이트째 값(캡션 자리, 2 = 위)이 칸 주소 자리라서 「0행 2열」로 읽혔다. HWPX 쪽은 `<hp:caption>`을 건너뛰었다.
- 고침: 10-19 도구를 고쳤다. 칸은 `TABLE` 레코드 뒤의 `LIST_HEADER`부터 세고, 표 제목은 두 형식 모두 `(표 제목) …` 한 줄로 적는다(위·왼쪽이면 「[표 …]」 바로 아래, 아래·오른쪽이면 마지막 행 뒤. HWP는 캡션 `LIST_HEADER` 8바이트째 값의 아래 두 비트 0 왼쪽·1 오른쪽·2 위·3 아래, HWPX는 `side` 속성). `--표없이`에서는 같은 자리에 글로 적는다.
- 다시 확인: `.tmp/restart-hwp-20261019/work/v62.hwp`와 `out/v62.hwpx`를 읽어 `diff -w`로 견주면 그림 자리 한 줄(HWPX 쪽 `[[IMG1]]`·`[[IMG2]]`)만 다르고, 매출 표 머리 행이 `| 순번 | 목표시장(고객) | 제품·서비스 | …`로 시작하는지 본다(10-19 확인, `--표없이`도 같음).
- 옮긴 까닭(2026-10-20, 도구): 10-19 `tools/hwp읽기.py`를 고쳐 표 제목을 `(표 제목) …` 한 줄로 적는다 — 도구를 쓰면 다시 걸리지 않는다

### 원문자 번호가 든 공고문에서 `tools/hwp읽기.py`가 출력하다 멈췄다
- 증상: 10-19 한국문화관광연구원 공고문 HWP를 읽자 글을 다 뽑은 뒤 `UnicodeEncodeError: 'utf-8' codec can't encode characters … surrogates not allowed`로 멈췄다. `--out`으로 파일에 써도 같고, `-I`로 돌리면 `PYTHONIOENCODING`도 먹지 않는다.
- 원인: HWP 본문은 UTF-16이라 BMP 밖 글자(이 공고문은 󰊱·󰊲 같은 사용자 정의 영역의 원문자 번호)가 대리 문자 두 개로 따로 들어온다. 파이썬 글에 짝이 갈라진 채 남아 UTF-8로 쓸 수 없었다.
- 고침: 10-19 도구를 고쳤다. 쓰기 전에 `text.encode('utf-16', 'surrogatepass').decode('utf-16', 'replace')`로 짝은 한 글자로 합치고, 짝 없는 대리 문자만 �로 바꾼다.
- 다시 확인: `python -I -X utf8 tools/hwp읽기.py .tmp/contests-20261019/forms/kcti_notice/kcti_공고문.hwp`가 끝까지 나오고 「󰊱 공모 개요」처럼 번호가 붙어 보이는지 본다(10-19 확인).
- 옮긴 까닭(2026-10-20, 도구): 10-19 `tools/hwp읽기.py`가 쓰기 전에 대리 문자 짝을 합치도록 고쳐졌다
