## talk 함수(Supabase)에서 (2026-10-20)

### `원격배포.js … --적용`이 「배포할 함수 디렉터리를 달라」로 멈춘다
- 증상: 10-17 talk PR #8(배포 전 원격 대조) 뒤 `node tools/원격배포.js supabase/functions/auth --적용`이 함수 경로를 줬는데도 「배포할 함수 디렉터리를 달라」로 끝났다.
- 원인: 위치 인자를 고를 때 `i !== 확인자리 + 1`로 `--차이확인` 값 자리를 뺐는데, `--차이확인`이 없으면 확인자리가 -1이라 0번(맨 앞의 함수 경로)이 빠졌다.
- 고침: talk PR #10에서 `확인자리 >= 0`일 때만 빼게 고쳤다. 그 전 판이면 `--적용`을 함수 경로 앞에 둔다(`node tools/원격배포.js --적용 supabase/functions/auth`).
- 다시 확인: `node tools/원격배포.js supabase/functions/auth --적용`이 사전 대조 결과(⛔ 차이 + `--차이확인` 값)까지 간다.
- 옮긴 까닭(2026-10-20, 도구): talk PR #10에서 도구를 고쳤다. 그 전 판에서만 걸린다.

### pg_dump를 `pg_restore -l`에 같이 흘리면 덤프가 쓰기 실패로 끝난다
- 증상: `pg_dump -Fc | tee … | pg_restore -l`에서 pg_dump가 `could not write to output file: Invalid argument`, tee가 141(SIGPIPE)로 끝났다(10-17).
- 원인: `pg_restore -l`은 앞쪽 목차만 읽고 바로 끝나 파이프를 닫는다.
- 고침: 목차 확인 쪽 파이프의 쓰기 오류는 무시하고 덤프 흐름은 끝까지 읽는다(`talk백업.js`가 Node에서 그렇게 나눠 흘린다). 덤프가 끝까지 되는지는 `pg_dump … | wc -c`로 따로 본다.
- 다시 확인: 셸에서 같은 파이프를 돌리면 `PIPESTATUS`가 `1 141 0`이다.
- 옮긴 까닭(2026-10-20, 도구): `talk백업.js`가 Node에서 덤프와 목차 확인을 나눠 흘려 막는다.

## synk.im(synk-policy)에서 (2026-10-20)

### SYNK-website의 dist를 올리면 라이브에만 있던 남의 작업이 되돌아간다
- 증상: 브랜치의 `dist/*.html`을 그대로 복사하면 그 사이 라이브에 올라간 다른 작업(아틀라스 진입, PATH 로고 간격, 질문 답)이 되돌아간다.
- 원인: synk.im은 synk-policy `origin/main`이 그대로 서빙된다. 홈페이지 원고 저장소 SYNK-website(기본 가지 `codex/company-conversations`, master·main 없음)의 `dist/`는 라이브의 정본이 아니다. 다른 세션·GPT가 공개본을 직접 고치거나 원고만 고친 일이 있어, 원고 빌드·커밋된 dist·공개본이 셋 다 다르다.
- 고침: 공개 후보는 「공개본 + 내가 바꾼 파일만」(또는 「공개본 + (손대지 않은 원고 빌드 → 내 빌드)의 차이」 3방향)으로 만든다. 바꾸지 않은 파일·토큰은 공개본 값 그대로 둔다. 페이지는 통째로 덮지 말고 바뀐 섹션만 id로 옮겨 심는다. synk-policy 로컬 클론은 작업본으로 쓰지 않고 객체 저장소로만 쓴다: 별도 인덱스 `read-tree origin/main` → `hash-object -w --no-filters` → `update-index --cacheinfo` → `write-tree` → `commit-tree -p origin/main` → `git push origin <커밋>:refs/heads/main`. 커밋 직전에 `fetch`해 `origin/main`이 그대로인지 다시 본다. 10-19부터 이 순서는 `tools/공개.js`가 한다(3방향은 `--기준폴더 <손대지 않은 원고 빌드>`, 공개본보다 늦은 기준은 `--기준 <커밋>`).
- 다시 확인: `git ls-remote origin main`이 새 커밋이고, 후보에서 내 변경을 뺀 나머지가 공개본과 같다.
- 옮긴 까닭(2026-10-20, 도구): 10-19부터 `tools/공개.js`가 「공개본 + 내 파일」 3방향·별도 인덱스 커밋·fetch 재확인을 한다(최근 공개 16개 재현에서 15개가 blob까지 같았다).

### 공개본 번들을 고치면 `platform.html`의 `?v=`도 같이 바꿔야 한다
- 증상: 10-18 GPT 0.4.24부터 `account/platform.html`이 `./dist/platform.js?v=…`·`./benefits.css?v=…`로 부른다. 번들만 바꿔 올리면 주소가 그대로라 이미 받아 둔 브라우저·CDN이 옛 번들을 계속 쓸 수 있다. 같은 날 공개본이 한 시간 안에 두 번(`b45319c` 17:50 → `cb7005c` 18:03) 바뀌어, 만들어 둔 후보의 바탕이 낡았다.
- 원인: `?v=`는 그 파일 sha256 앞 12자다(`1ee4ff043b3f`·`35983c432263`·`f597f9b68d34`로 확인). `platform.css`·`member-insight.css`에는 아직 `?v=`가 없다. GPT는 공개본 번들을 직접 고쳐 짧은 간격으로 올린다.
- 고침: 번들을 바꾸면 `sha256sum account/dist/platform.js | cut -c1-12`로 `platform.html`의 `?v=`를 같이 바꾼다(`benefits.css`도 같다). 10-19부터 `tools/공개.js`가 바뀐 파일을 부르는 공개 파일의 토큰을 같이 바꾼다(e9cf357을 번들·CSS만 넣어 재현하면 `platform.html`까지 blob이 같다). 토큰 없이 부르는 `platform.css`·`member-insight.css`는 「토큰 없이 부르는 곳」으로 알린다. 커밋 직전 `fetch` 뒤 바탕 파일 셋(번들·CSS·HTML)의 blob이 후보를 만든 공개본과 같은지 보고, 다르면 새 공개본 위에서 같은 바꾸기(정확히 한 번 나오는 원문만 바꾸는 스크립트)를 다시 돌린다. 후보에 HTML이 들면 `check.mjs`의 route가 `text/html`로 돌려줘야 한다(아니면 Playwright가 「Download is starting」으로 멈춘다).
- 다시 확인: 공개 뒤 `curl https://synk.im/account/platform.html | grep -o 'platform.js?v=[0-9a-f]*'`가 공개 번들 sha256 앞 12자와 같다(10-18 synk-policy `e9cf357`).
- 옮긴 까닭(2026-10-20, 도구): `tools/공개.js`가 바뀐 파일을 부르는 `?v=` 토큰을 같이 바꾼다(e9cf357을 번들·CSS만 넣어 재현하면 `platform.html`까지 blob이 같다).

### 캐시 토큰 `?v=`를 다시 계산하면 안 바꾼 파일까지 바뀐다
- 증상: 깨끗한 빌드의 `?v=` 토큰이 공개본과 많이 달라 안 바꾼 페이지까지 바뀐 것으로 나온다.
- 원인: 공개본의 `?v=`는 작업본 파일을 그대로 해시한 값이 아니다(배포 시점이 제각각이고, 저장소는 LF·작업본은 CRLF). WORLD 진입 페이지와 게임 index의 `?v=`는 빌드가 붙이지 않는 공개 때 손질이다.
- 고침: 바뀐 파일만 새 값(예: sha256 앞 12자리, 또는 `?v=<작업>-<날짜>`)을 붙이고, 올리지 않는 파일은 공개본 값 그대로 쓴다. HTML은 통째로 덮지 말고 토큰 줄만 바꾼다. `tools/공개.js`(10-19)는 올리는 파일의 토큰을 같은 파일 공개본 값으로 맞춘 뒤, 바뀐 파일을 부르는 토큰만 새 값으로 바꾼다 — 해시 토큰은 같은 길이 sha256(공개본은 거의 12자, care만 64자), 이름 토큰은 12자(또는 `--토큰 <값>`). 공개본 해시 토큰은 대상의 지금 내용과 안 맞는 것도 많다(19개 — CRLF 작업본으로 잰 값, 옛 판의 값, `?v=20260911` 같은 날짜) — 맞는지는 보지 않고 따라 바꾼다. 대신 어느 파일도 부르지 않는 css·js·데이터 파일은 고치지 않고 알린다: v10 뒤로 안 쓰는 루트 `app.js`·`en/app.js`·`sites.js`·`site-bar.js`·`en/sites.js`가 그렇다(10-19 `git grep`으로 부르는 곳 0, `site-bar.js`의 주석 낱말뿐). 데이터 모듈의 슬래시 없는 참조(`tutor-profiles.mjs`의 `"marin-기본.webp?v=…"`, 소비자가 `assets/tutors/`를 붙임)는 같은 이름 파일이 8개라, 공개본 토큰 해시가 내용과 맞는 하나(`tutors/marin-기본.webp`)를 대상으로 본다 — 맞는 것이 하나가 아니면 고치지 않고 알린다. 이름 토큰은 따라 바꾼다: 11617ab 재현에서 WORLD 진입 페이지 셋의 `/world/app-shell.mjs?v=motion-20261017`을 올렸는데, 실제 공개는 app-shell.mjs를 바꾸고도 그대로 뒀다. 그대로 두려면 `--토큰안함`.
- 다시 확인: `git diff --numstat -- '*.html'`이 파일마다 `1 1`이다.
- 옮긴 까닭(2026-10-20, 도구): `tools/공개.js`가 올리는 파일의 토큰을 공개본 값에 맞추고 바뀐 파일을 부르는 토큰만 바꾼다. 도구 알림(「토큰 없이 부르는 곳」·안 쓰는 파일)의 뜻은 이 항목이 설명하니 지난 기록에서 찾게 한다.

### 폐기 앱을 지운 설치본이 창을 열기 전에 멈춘다 (2026-10-18)
- 증상: Windows/Mac 빌드는 끝났지만 실제 네이티브 실행 QA는 시간 초과였고 기본 창이 생성되지 않았다.
