## 크롬 확장 공통에서 (2026-10-20)

### 확장이 붙은 프로필에 그 사이트 로그인이 없다
- 증상: 유호님은 「로그인 다 했어」라고 했는데 확장 탭의 facebook.com은 로그인 화면이었다(10-03).
- 원인: 옛 노트북 크롬에 프로필이 여섯 개 있었고, 그중 둘이 같은 이름 「유호」였다. SNS 로그인은 한쪽(`Profile 2`)에만 있었는데 확장은 로그인이 없는 다른 쪽(`Default`)에 붙어 있었다. 두 프로필 모두 확장이 깔려 있어 같은 브라우저처럼 보였다.
- 고침: 게시를 시작하기 전에 확장 탭에서 그 사이트의 로그인 상태부터 본다. 로그인이 없으면 로그인된 프로필 창(`chrome.exe --profile-directory="<폴더 이름>" <주소>`)에서 사이드 패널을 열어 확장을 그쪽에 붙인다. 로그인 여부는 쿠키 이름과 만료만 읽어서 확인하고, 값은 읽지 않는다.
- 다시 확인: PowerShell `(Get-Content "$env:LOCALAPPDATA\Google\Chrome\User Data\Local State" -Raw | ConvertFrom-Json).profile.info_cache`로 프로필 폴더와 이름을 본다. 10-17 새 노트북에는 `Profile 1 = 유호` 하나뿐이다.
- 옮긴 까닭(2026-10-20, 옛 판): 옛 노트북 크롬의 같은 이름 프로필 6개에서 생긴 일이다. 새 노트북은 프로필 「유호」 하나뿐이라(머리 판 줄·항목 끝에도 적힘) 이 어긋남이 없다.

## claude.ai 페이지(Artifact 게시)에서 (2026-10-20)

### 대화에서 Argon을 골라도 기존 예약의 집행 모델은 확인되지 않는다
- 증상: 10-17 Gemini Task의 기존 예약 편집에는 이름·계획·주기·종료·활성 항목만 있고 모델 선택은 없었다. 연결 대화의 모드를 Flash에서 4 Argon으로 바꾼 뒤 예약 집행 모델 변경을 요청했지만, Gemini Schedules 도구는 예약 객체에 모델 필드가 없어 조회·지정 변경할 수 없다고 응답했다.
- 원인: 확인한 예약 편집 화면에는 모델 설정이 노출되지 않았고, 대화가 사용한 Schedules 도구도 모델 필드를 지원하지 않는다고 응답했다. [공식 모델 문서](https://support.google.com/gemini/answer/18648722)는 선택한 모델이 같은 대화에 유지된다고 설명하지만 예약 실행의 상속 방식은 명시하지 않는다. 작업 설정·사용량 한도 화면에서도 예약 기본 모델이나 자동 모델 선택 스위치를 찾지 못했다.
- 고침: 막다른 길 — Argon을 선택한 별도 대화에 일회성 시험 예약을 만들었다. 「지금 실행」은 지정 문구 응답과 Argon 선택을 유지했으나, 실제 10-17 21:35 자동 실행(`ran on 10월 17, 9:35 PM`) 뒤에는 같은 대화의 모델 표시가 Flash로 바뀌었다. 시험 예약은 완료됨으로 이동했고 운영 예약4건은 활성이다. Task 응답의 사고 단계·더보기에는 응답별 사용 모델 상세가 없어 Flash 표시를 서버 추론 모델 메타데이터로 확대하지 않는다. 다만 대화 선택만으로 예약 Argon 고정을 확인할 수 없다는 실제 반례이므로 「지금 실행」 성공을 자동 실행 모델의 검증으로 대신하지 않는다.
- 다시 확인: 같은 예약의 모델 필드와 실제 시각 자동 실행 뒤의 응답별 모델 표시가 제공되는지 본다. 시험 대화는 `https://gemini.google.com/app/7e34a76583536120`, 화면 증거는 `.tmp/gemini-schedules-20261017/Argon_자동예약후_Flash표시.jpg`다. Antigravity 공식 CLI의 명시적 모델 실행은 대안 후보지만 계정 인증 공유와 기존 Docs 전달 확인이 먼저다([AI CLI 노트](../AI_CLI.md#agy가-어느-계정으로-도는지-설정-파일-표시가-틀린다)).
- 옮긴 까닭(2026-10-20, 옛 판): Gemini 앱 예약 4개는 10-18 12:12 일시중지, 서버 공식 CLI 타이머(`gemini-4-argon-high`)로 옮겨 갔다(tools/argon-schedules/README.md). 앱 예약의 모델 확인 문제는 그 길과 함께 끝났다.

### 긴 예약 계획을 fill하면 기존 내용과 새 내용이 섞인다
- 증상: 10-17 예약 계획의 rich text 입력칸에 약22,000자 본문을 `.fill()`로 넣자 기존 내용 일부가 남고 새 본문의 끝부분이 앞쪽에 섞였다.
- 원인: 해당 입력칸에서 `.fill()` 결과가 전체 교체되지 않은 것을 확인했다. 편집기 내부에서 섞인 구체 원인은 확인하지 못했다.
- 고침: 계획 입력칸에 초점을 둔 뒤 Control+A·Backspace로 비우고, 클립보드의 일반 텍스트를 붙여 넣었다. 입력 직후 전체 본문을 줄바꿈만 정규화해 원문과 대조한 뒤 저장했다.
- 다시 확인: 저장한 예약을 다시 열고 계획 전체를 원문과 대조한다. 10-17 교정에서는 입력 직후와 저장 후 재열기 모두 줄바꿈 정규화 전체 비교가 일치했다. 처음·끝 일부가 맞거나 저장 표시가 뜬 것만으로 완료 처리하지 않는다.
- 옮긴 까닭(2026-10-20, 옛 판): 일시중지된 Gemini 앱 예약의 계획 입력칸 이야기다. 지시문은 지금 tools/argon-schedules/ 파일에 있어 이 칸을 고칠 일이 없다.
