## 한도와 돈

### ZeroGPU 남은 한도는 API로 초 단위로 읽힌다 — 결제 화면을 열 필요가 없다 (2026-11-02 Claude)
- 증상: 10-14에는 「남은 할당량은 API로 안 나온다」로 알고 크롬 결제 화면 `data-props`의 `zeroGpu.current`를 돌리기 전후로 읽었다.
- 원인: `GET https://huggingface.co/api/spaces/zero-gpu/quota`(토큰 헤더)가 `{"base":2400,"current":<남은 초>,"resetsAt":…,"overquotaUsed":<넘쳐 쓴 초>}`를 준다. huggingface_hub 2.4의 `get_zero_gpu_quota` · `hf spaces zero-gpu quota`가 이 끝점을 부르는 것이고, 1.29에서도 같은 끝점이 열린다(시스템 파이썬은 여러 도구가 같이 써서 2.x로 올리지 않았다). OAuth 토큰은 `read-billing` 범위가 있어야 하는데 이 PC 로그인은 된다. 차감은 실제 GPU 초 × 크기 배수(xlarge 2배)이고(10-17 조건 7.5초 → 14.8초, 생성 109초 → 218.1초), `resetsAt`은 그 창의 첫 사용 24시간 뒤다. 다 쓰면 선불 잔액에서 자동으로 빠진다(10분 $1).
- 고침: `python -X utf8 tools/허깅페이스.py 한도`로 본다. `부르기`는 부르기 전에 읽고 다른 세션의 예약을 빼서 모자라면 부르지 않고(끝 코드 2), 부른 뒤 `overquotaUsed`가 늘면 멈춤을 건다(끝 코드 3, `풀기 --확인`으로 푼다).
- 다시 확인: `python -X utf8 tools/허깅페이스.py 한도`의 남은 초가 결제 화면의 「ZeroGPU n/40 minutes」와 맞는다(11-02 2,385초 = 0.2/40분).

### 선불 잔액·Inference·Jobs 쓴 돈은 토큰으로 안 읽힌다 — ego에서 결제 화면을 읽는다 (2026-11-02 Claude)
- 증상: `/api/settings/billing`·`/api/settings/billing/usage`는 404, `https://huggingface.co/settings/billing`은 토큰을 줘도 302(로그인 화면)였다. `/api/whoami-v2`는 `isPro` · `canPay`(카드 있음) · `billingMode: prepaid`만 준다.
- 원인: 결제 화면은 브라우저 로그인 쿠키로만 열린다.
- 고침: ego(허깅페이스 로그인)로 `settings/billing`을 열고 `[data-props]`에서 `creditsBalanceUsd`(선불 잔액) · `subscriptionIncludedCreditsUsd`(PRO에 딸린 월 몫) · `usage.inference.usedNanoUsd` · `usage.jobs.usedMicroUsd` · `usage.zeroGpu.overquota.billedSeconds`를 읽는다. 11-02: 잔액 $2 = 딸린 몫 $2, 자동 충전 「-」(꺼짐), 11월 Inference $0 · Jobs $0 · 넘침 0초, 비공개 저장 0.35GB/1TB. 이 화면에는 주소 · 카드 끝자리가 같이 있으니 기록에 옮기지 않는다.
- 다시 확인: 같은 화면의 「Credits $n」과 `creditsBalanceUsd`가 같다.

### 두 Space를 나란히 부르면 한도지키기의 장마다 「쓴초」가 서로 섞인다 — 남은 초가 잠깐 늘기도 한다 (2026-11-03 Claude)
- 증상: 11-03 「제2의 나」 오픈 모델 견주기에서 두 줄(Qwen 나이 · LongCat 나이)을 나란히 돌리자 사용 기록의 「쓴초」가 525.2 · 405.0 · -100.5처럼 나왔고, 남은 초가 884 → 1115로 잠깐 늘었다가 다시 줄었다.
- 원인: 한도지키기는 부르기 전후의 남은 초 차이를 그 호출의 몫으로 적는데, 나란히 도는 다른 호출의 차감이 그 사이에 끼어든다. 서버는 부를 때 duration × 배수를 먼저 잡았다가 끝나면 덜 쓴 만큼 돌려주는 것으로 보인다(남은 초가 늘어난 순간).
- 고침: 나란히 돌릴 때는 장마다 「쓴초」를 읽지 않고, Space가 재서 돌려주는 GPU 초와 줄 전체의 전후 남은 초 차이로 적는다. 장마다 차감을 재야 하면 한 줄로 돌린다.
- 다시 확인: 한 줄로 돌린 FireRed 나이 셋은 장마다 80.1~92.4초(GPU 39.9~40.7초 × 2 + 약 10초)로 고르게 나왔다.

## Space 찾기와 부르기

### 남의 Space의 예상초는 실제 쓴 초가 아니라 duration 최댓값으로 잡는다 (2026-11-02 Claude)
- 증상: 11-02 목소리 떼기 Space는 `@spaces.GPU(duration=120)`인데 실제로 깎인 것은 12.1초였다.
- 원인: 서버는 부를 때 남은 한도가 함수가 적은 duration만큼 되는지 보고 GPU를 내준다(Upsampler SeedVR2 Space 주석 「the request is checked against the visitor's remaining quota」). 남은 초가 그보다 적으면 잔액이 있을 때 넘침으로 갈 수 있다. duration은 숫자(`120`), 괄호 없음(기본 60초), 함수(`duration=_duration` — 인자로 셈, 대개 `min(상한, …)`)의 셋이다.
- 고침: `python -X utf8 tools/허깅페이스.py 살펴보기 <space>`가 Space 저장소의 `.py`에서 `@spaces.GPU` 줄과 duration 함수 몸을 뽑아 준다 — 그 최댓값을 [Space 목록](../../tools/lib/허깅페이스_space.json)의 「예상초」에, `size="xlarge"`면 「배수」 2로 적는다. 목록에 없는 Space는 `--예상초`를 줘야 부른다.
- 다시 확인: `살펴보기 hugging-apps/bs-roformer-leap-audio-separator`의 duration이 `@spaces.GPU(duration=120)`.

### hf spaces search는 ZeroGPU를 걸러도 엉뚱한 Space를 섞고, cp949로 죽는다 (2026-11-02 Claude)
- 증상: `hf spaces search "background removal" --filter zerogpu`가 캡션 · 업스케일 Space를 앞에 두었고, `--json`을 파이썬으로 받아 찍자 `UnicodeEncodeError: 'cp949'`(제목의 `—`)로 멈췄다.
- 원인: 의미 검색이라 낱말이 비슷한 설명을 고른다. 윈도우 콘솔 기본 인코딩이 cp949다.
- 고침: `HfApi().list_spaces(search="<낱말>", sort="likes", limit=60, expand=["runtime","likes","lastModified"])`에서 `runtime.hardware`가 `zero`로 시작하고 `stage == "RUNNING"`인 것만 고른다. 파이썬은 `-X utf8`(또는 `PYTHONIOENCODING=utf-8`)으로 돌린다.
- 다시 확인: `search="rmbg"`가 `briaai/BRIA-RMBG-2.0`을 맨 앞에 준다.

### whisper가 음악만 있는 소리에 「Thank you for watching!」을 지어낸다 (2026-11-02 Claude)
- 증상: 11-02 목소리를 떼어 낸 바탕 소리를 `hf-audio/whisper-large-v3`로 받아쓰자 한국어 쇼츠인데 「Thank you for watching!」이 나왔다.
- 원인: whisper는 말이 없는 구간에도 학습 자료에 흔한 맺음말을 지어낸다(잘 알려진 버릇).
- 고침: 바탕에 말이 남았는지 볼 때는 원래 말(이번엔 한국어 문장)이 나오는지만 보고, 그 맺음말 하나는 「말 없음」으로 읽는다. 떼어 낸 목소리 쪽 받아쓰기가 원고와 맞으면 떼기가 된 것이다.
- 다시 확인: 같은 바탕 소리를 다시 받아써 같은 한 줄만 나오는지 본다.

### 목소리 떼기·받아쓰기는 허깅페이스 먼저, 남은 것만 로컬로 돈다 (2026-11-02 Claude)
- 증상: 11-02 유호님 「가능한것들은 전부 먼저 허깅페이스 gpu 먼저 사용하고나서 남은걸 로컬로」. 그 전에는 집 GPU가 바쁠 때만 세션이 기억해서 ZeroGPU로 넘겼고, 공용 GPU 줄에서 LoRA 학습 뒤로 10분 넘게 기다린 일이 10-31 · 11-01에 있었다. 같은 날 로컬 Demucs CPU(가장 낮은 우선순위)는 PC가 바빠 4초 클립에 68초 걸렸다.
- 원인: 하루 2,400초는 안 쓰면 사라지는데, 넘기는 판단이 세션마다 달랐다.
- 고침: `python -X utf8 tools/허깅페이스.py 목소리떼기 <출력폴더> <입력…> --남에게보내도됨`은 입력마다 BS-RoFormer로 떼고(영상 파일도 소리만 뽑아 올린다), 몫 밖 · 멈춤 · Space 두 번 잇단 실패면 남은 것만 로컬 Demucs로 넘긴다 — 공용 GPU 줄(`차례.py gpu 돌리기 목소리떼기-허깅페이스밖 …`)로 서고, `--cpu`면 줄 대신 낮은 우선순위 CPU. 결과 이름은 로컬 도구와 같은 `<이름>_목소리.wav` · `<이름>_바탕.wav`(44.1kHz 스테레오)이고 엔진은 `떼기기록.json`에 남는다. `받아쓰기 <파일…> --남에게보내도됨`은 whisper-large-v3 먼저(16kHz 모노로 줄여 올림), 남은 것은 이 프로세스를 낮은 우선순위로 내려 로컬 faster-whisper large-v3 CPU로. `--남에게보내도됨`이 없으면 둘 다 처음부터 로컬이다. 결과가 달라지는 일(얼굴 업스케일 · 그림 생성)은 이 명령에 넣지 않는다.
- 다시 확인: 11-02 실측 — 쇼츠 영상 그대로 떼기 왕복 20.3초 · 한도 10.3초, 받아쓰기 7.8초(원고와 같음), 표시 없는 받아쓰기는 로컬로 감, `--로컬만 --cpu` 떼기는 엔진 「로컬 Demucs htdemucs_ft CPU」. 몫 밖에서 공용 GPU 줄로 넘어가는 길은 11-03 01:54~02:51에 실제로 걸어 봤다 — `--로컬만` 떼기가 번호표 `목소리떼기-허깅페이스밖-<pid>`를 받고, LoRA 학습 · 학습 사슬 동안 「틈에 끼지 않는다」며 기다렸다. 학습 사슬이 그날 18시 무렵까지 이어져 차례를 받아 GPU로 도는 데까지는 못 보고 내렸다(`차례.py gpu 내려놓기 <이름>`으로 번호표도 치움 — 프로세스만 끄면 번호표가 줄에 남는다).

### 블렌더 렌더는 Space와 같은 설정을 로컬에도 걸어야 섞어 그려도 같은 그림이다 (2026-11-03 Claude)

### 편집 모델 공식 데모(Qwen · FireRed)는 「지시문 다시 쓰기」로 사진과 글을 알리바바 DashScope에 보낸다 — 복제하지 말고 우리 app.py로 (2026-11-03 Claude)

### 20B 편집 모델(Qwen-Image-Edit 계열 bf16 57.7GB)을 우리 ZeroGPU Space에 올리면 첫 호출이 「NVML_SUCCESS == r INTERNAL ASSERT FAILED」로 죽는다 — xlarge 조각으로 (2026-11-03 Claude)

### LongCat-Image-Edit은 글이 512토큰을 넘으면 멈추고, 따옴표 안 글은 그림에 글자로 쓰려 한다 (2026-11-03 Claude)
- 증상: GPT에 넣은 지시문(기준 약 560 · 나이 약 790토큰, Qwen2.5 토크나이저)을 그대로 넣을 수 없었다. diffusers 0.39 `LongCatImageEditPipeline`은 `tokenizer_max_length = 512`이고, 넘으면 잘라 내기 전 경고 줄의 `len(len(all_tokens))`가 TypeError를 낸다. 옷장 지시문의 `"comma hair"`처럼 따옴표가 있으면 그 구간이 따로 인코딩된다.
- 원인: LongCat은 따옴표 안 글을 글자 단위로 인코딩해 그 글을 그림에 쓰는 장치가 있다(모델 카드 「텍스트는 따옴표로 감싸라」, `split_quotation`). 낱말 속 아포스트로피는 `[a-zA-Z]+'[a-zA-Z]+`만 보호해서 `Image 1's`처럼 숫자 뒤 아포스트로피는 다른 아포스트로피와 짝을 지으면 그 사이가 인용으로 잡힌다. Qwen 계열 편집 파이프라인은 1024토큰까지 받고(`max_sequence_length` 기본 512라 1024를 넘겨 줘야 한다) 이런 장치가 없다.
- 고침: LongCat 몫은 같은 뜻의 512토큰 안 짧은 판을 쓰고(`오픈모델/굽기.py`의 `짧게`), 따옴표를 빼고, 숫자 뒤 아포스트로피를 피한다(「the camera angle of Image 1」).
- 다시 확인: 같은 파일의 `split_quotation`을 지시문에 돌려 인용 구간이 0개이고, Qwen2.5 토크나이저로 512 아래인지(11-03 짧은 판 기준 408~413 · 나이 498~503).
