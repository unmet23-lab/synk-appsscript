# Temper 개입 로그 규격 v1.1 — 개입 시점의 근거

> 2026-09-13 · [엔진 7종](엔진7종_상향설계_v3.md)의 Temper 발전안과 현재 talk 코드에 연결한다. 과거 “여섯 엔진 중 유일한 개원 전 마감물”·고정 생산자 수·종결 서사는 제거했다. 아래는 현행 원본 기록 요구이며 결과변수·실험 설계·새 개입 종류의 구현 완료를 뜻하지 않는다.

## ⓪ 목적

**개입을 기록할 때 그 순간의 학생 상태와 선택 근거를 함께 남긴다.** 후속 성과는 원본으로 다시 계산할 수 있지만, 당시 상태·선택 규칙·개입 ID가 없으면 나중에 그 선택을 재현하기 어렵다. 첫 실제 개입이 발생하는 통로에서 준비한다.

## ① 상태와 개입의 고리

| 칸 | 의미 |
|---|---|
| `estimator_version` | 상태 계산기의 판 |
| `estimator_confidence` | 현재 상태 계산에서는 표본 충분도; 정확도 확률과 구분 |
| `evidence_refs` | 계산에 쓰인 원본 사건 참조 |
| `policy_ver` | 그 개입을 고른 선택 규칙의 판 |
| `intervention_id` | 후속 관측을 이을 개입 고리 |

- 대상은 `intervention.delivered`와 그 개입이 낳은 `task.assigned`다. 학생 자신의 제출·응답에 빈 상태 칸을 일괄 추가하지 않는다.
- 배정은 `intervention_id`로 원 개입의 상태를 참조할 수 있다. 같은 상태를 복제해서 정본을 둘로 만들지 않는다.
- 상태 계산 실패 시 과제 전달은 기본 동작으로 진행할 수 있다. 모르는 상태는 null과 실패 사유로 남기며 완비율에서 누락을 센다.
- 개입 행이 없는 게임 배정과 개입을 동반한 배정을 구분한다. null을 채우기 위해 가짜 개입을 만들지 않는다.

## ② 생산자와 경계

현재 생산 경로와 예외는 talk `supabase/functions/deliver`·`deliver-one`·`deliver/생성모드`, `lib/이벤트검증.js`, `tests/개입스탬프.test.js`를 함께 확인한다. 생산자 수·행번호를 이 문서에 고정하지 않는다.

`functions/events`는 학생 사건 통로이며 서버 개입 사건을 학생이 위조해 만들 수 없게 한다. 라디오 승격은 그 승격표에 허용된 학생 사건만 낸다. `companion` 등 새 소비면이 실제 학습 개입을 만드는 날 해당 생산자·개입 근거·후속 소비를 함께 연결한다. 모든 표정·인사·감상에 개입 사건을 강제하지 않는다.

## ③ 기존 검증과 실제 계수

- talk `tests/개입스탬프.test.js`는 개입 생산자·상태 칸·배정 고리·서버 사건 경계를 확인한다. 현재 목록은 코드에서 관리한다.
- `tools/성과계기판.js`는 delivered 전체를 완비/미비로 나눠 런타임 상태 계산 실패를 확인한다. 코드 검사 통과만으로 실제 행 완비를 선언하지 않는다.
- `lib/성과회수.js`는 개입 이후 실제 열람·후속 수행을 계산한다. 계산을 호출한 것, 다음 처방이 바뀐 것, 실제 학습 효과를 구분한다.

## ④ 재도전과 관측

`retry_of`는 실제 재도전의 이전 사건을 가리킨다. 오프라인 재전송도 당시의 고리를 유지하고, 첫 제출·미상·제출하지 않은 세션을 재도전으로 만들지 않는다. 앱 멱등키를 그대로 사건 ID처럼 저장하지 않고 서버에서 실제 사건 고리로 해석한다.

배정과 제출의 연결, 교정 화면의 재발화 표시 조건은 각각 해당 계약·소비자가 정한다. 개입을 본 관측은 `content.viewed.parent_event_id`가 원 개입의 사건을 가리키며 `intervention_id`와 혼동하지 않는다.

## ⑤ 계약과 다음 발전

다섯 칸은 기존 계약에 있다. 이 문서의 설명 정리가 새 필드나 계약판을 만드는 것은 아니다. 새 개입 유형·결과변수·사전 분석·강사 확인을 넣을 때는 [엔진 7종](엔진7종_상향설계_v3.md)의 Temper 절과 실제 계약·마이그레이션을 함께 맞춘다.

09-13 코드 대조: `deliver`의 `회수요약` 호출은 존재한다. `lib/성과회수.js`의 강등(`degraded`) 분리 소비와 결과를 다음 선택에 돌려주는 경로는 아직 확인되지 않았다. 구조화된 실험·결과변수 구현을 이 규격 완료로 대신하지 않는다.
