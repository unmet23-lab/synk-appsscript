# 첫 로그인 — 마스코트 추천과 학습 개인화 추가 설계

> 2026-09-09 · 기능 추가 방향은 이번 사용자 요청. 아래 문항·계산·저장·연결 방식은 그 요청을 구체화한 **설계 제안**이다. 앱 구현·배포·설문 타당성·학습 효과를 확인한 문서가 아니다.
> 연결: [앱 재설계](앱재설계_v2.md) · [가이드 정본](캐릭터/가이드_정본.md) · [엔진 7종](엔진7종_상향설계_v3.md) · [세 층 합류](세층합류_설계_v1.md).

## 1. 학생에게 무엇이 달라지는가

학생은 몽글·까몽·마린 중 마음에 드는 선생님을 바로 고를 수 있다. 고르기 어려우면 짧은 질문으로 원하는 도움을 먼저 고르고, 그 답에 가까운 마스코트를 추천받는다. **같은 답이 첫 과제의 힌트와 첫 교정 답장의 설명 순서에도 쓰인다.** 이후 실제 연습에서 무엇이 도움이 되었는지를 따로 쌓아 다음 도움을 조정한다.

이 기능의 이름은 학생 화면에서 **「나에게 맞는 친구 찾기」**로 제안한다. 내부에서는 ‘첫 학습 선호 설문’으로 부른다. 성격검사·능력검사·고정 학습유형 판정으로 운영하지 않는다. 설문은 학생이 직접 말해 주는 중요한 출발 자료이며, 행동 관찰·수행 결과·목표·교실 관찰과 함께 개인화를 이룬다.

## 2. 첫 화면 흐름

학원 발급 계정으로 첫 로그인 → 기존 시작 절차 → **마스코트 선택: ① 몽글 ② 까몽 ③ 마린** → 직접 선택 또는 공통 추천 버튼 → 질문 → 추천 이유와 학습 설정 → 학생 최종 선택 → 첫 과제.

- 추천 표식과 **「나에게 맞는 친구 추천받기」** 버튼을 세 카드 아래 공통 영역 한 곳에 둔다. 어느 한 캐릭터에 미리 추천 배지를 붙이지 않는다. 추천 결과가 생긴 뒤 해당 카드에 표시한다.
- 기존 소개 카드와 「이야기 더 보기」를 재사용한다. 설문을 건너뛴 학생도 세 캐릭터와 학습 기능을 이용할 수 있다.
- 시작 안내 제안: “어떤 도움을 받고 싶은지 골라 주세요. 답은 친구 추천과 학습 안내에 써요. 나중에 바꿀 수 있어요.” 실제 저장·소비·수정 기능이 함께 구현된 뒤 표시한다.
- 한 화면에 한 질문, 뒤로 가기·진행 위치·나중에 하기. 모든 질문에 「상황마다 달라요」와 「지금은 건너뛰기」를 제공한다. 둘은 서로 다른 응답이며 특정 캐릭터의 점수로 바꾸지 않는다.
- **핵심 6문항**으로 첫 추천과 도움 설정을 얻는다. 소재·목표 2문항은 첫 과제 진입에서 선택적으로 받으며, 기존 시작 질문에 답한 값이 있으면 다시 조사하지 않고 확인·수정만 한다.
- 한국어 초안은 설계 검토용이다. 실제 초급 학생의 시작 화면은 이해할 수 있는 몽골어가 기본이며 번역 대조와 원어민 확인이 필요하다. ‘1분 완성’ 같은 소요 시간은 실제로 읽혀 보기 전까지 표시하지 않는다.

## 3. 캐릭터와 도움 설정의 관계

| 마스코트 | 현재 정본의 성격 | 추천할 때 설명할 관계 |
|---|---|---|
| 몽글 | 해맑은 호기심, 함께 시도하고 기뻐함 | 함께 시작하고 함께 기뻐하는 반응 |
| 까몽 | 허세 속 겁과 의리, 장난스럽게 주고받으며 챙김 | 장난과 재미있는 주고받기가 있는 반응 |
| 마린 | 원칙·임무·완수 확인, 무표정 속 다정함 | 할 일과 다음 행동을 짚어 주는 반응 |

근거는 가이드 정본 §2·§2-0·§2-7이다. 셋 다 선생님이자 응원하는 존재다. 까몽을 침묵형으로 되돌리거나 마린을 특정 성별용으로 만들지 않는다. 캐릭터의 고유 성격과 말투는 유지하며, **그 캐릭터가 전달하는 수업의 도움 순서·양·힌트 시점은 학생별로 달라질 수 있다.**

예를 들어 마린을 추천받아도 학생이 몽글을 고르면 몽글과 시작한다. “오늘 할 일부터 보기”나 “예문부터 보기”라는 선호는 몽글에게도 적용한다. 캐릭터를 바꿔도 학습 기록·성장·선호를 초기화하지 않는다. 외형이 좋아서 골랐다는 사실만으로 코칭 선호를 확정하지 않는다.

## 4. 문항 초안과 쓰임

아래는 앱 안내 문장이다. 캐릭터의 직접 대사가 아니다. 선택지마다 정답·좋은 학생·나쁜 학생이 생기지 않게 한다.

| 번호 | 질문 | 보기 초안 | 직접 쓰는 곳 |
|---|---|---|---|
| Q1 | 공부를 시작할 때 어떤 도움이 좋아요? | 함께 시작하기 / 재미있는 도전으로 시작하기 / 오늘 할 일부터 보기 | 마스코트 추천 |
| Q2 | 같은 문장을 다시 연습할 때 어떤 반응이 좋아요? | 같이 다시 해 주기 / 장난을 섞어 분위기 바꾸기 / 다음에 할 행동 짚어 주기 | 마스코트 추천 |
| Q3 | 연습을 마쳤을 때 어떤 반응이 좋아요? | 함께 신나 하기 / 재미있게 말을 주고받기 / 해낸 일과 다음 걸음 보기 | 마스코트 추천 |
| Q4 | 새 표현을 배울 때 무엇부터 볼까요? | 짧은 예문 / 뜻과 이유 / 먼저 해 볼 짧은 문제 | 설명을 보여 주는 순서 |
| Q5 | 내 말의 교정 결과를 어떻게 볼까요? | 한 부분씩 보고 나머지 펼치기 / 전체 목록을 보고 골라 보기 / 내가 궁금한 부분부터 보기 | 교정 답장을 펼치는 순서와 단위 |
| Q6 | 힌트는 언제 볼까요? | 시작하기 전에 / 스스로 한 번 해 본 뒤 / 내가 누를 때 | 연습에서 힌트를 제안하는 시점 |
| Q7·추가 | 첫 연습은 어떤 장면이면 좋아요? | 친구와 대화 / 학교생활 / 노래·영상 이야기 / 아직 모르겠어요 | 첫 연습의 소재; 기존 관심사 답이 있으면 확인 |
| Q8·추가 | 한국어로 먼저 해 보고 싶은 일은 무엇인가요? | 수업에서 질문하기 / 일상 대화하기 / 시험 문제 풀기 / 아직 고르는 중이에요 | 가까운 학습 목표; 기존 목표 답이 있으면 확인 |

Q1~3의 첫째·둘째·셋째 보기는 각각 몽글·까몽·마린의 정본 성격과 연결한다. Q4~8은 마스코트 점수에 넣지 않는다. ‘예문을 선호함’을 시각형, ‘힌트부터’를 낮은 실력으로 바꾸지 않는다. Q8은 가까운 연습 목표이며 기존 유학·진로 목표를 덮어쓰지 않는다.

Q5는 전체 오류 수집·교정 내용·평가 기준을 유지한 채 **보여 주는 순서만** 바꾼다. 말하는 도중의 실시간 교정 기능을 약속하지 않는다. Q6의 ‘한 번’은 실제 문제 시도이고 화면 체류시간이 아니다. 진단·시험에서 힌트를 허용하는 결정도 아니다. 연습에 제공한 도움은 실제 노출·요청·사용과 답의 관계를 남겨, 도움받은 답을 독립 실력으로 세지 않는다.

## 5. 추천 규칙과 결과 화면

최초 규칙은 설명 가능한 동일 비중으로 둔다. Q1~3에서 고른 캐릭터별 보기 수를 센다. **한 후보를 가리키는 유효 답이 2개 이상일 때 그 후보를 추천한다.** 이는 초기 화면 규칙이며 검사 정확도·성격 진단의 통계적 기준이 아니다. 비슷한 질문에 답했다고 독립 증거가 그만큼 늘었다고 해석하지 않는다.

- 동점, 셋을 한 번씩 선택, 유효 답 부족이면 단일 우승자를 만들지 않는다. 해당 후보의 반응을 나란히 보고 학생이 고르도록 한다. 모두 모름이면 세 소개 카드로 돌아간다.
- 결과는 이름과 **답에서 나온 이유 두 개**, 바뀔 학습 설정을 보여 준다. “적합도 97%”나 “당신은 마린형 인간”은 표시하지 않는다.
- 예시: “함께 시작하고, 함께 기뻐하는 반응을 골랐어요. 몽글과 먼저 만나 보세요.” 아래에는 “학습 안내는 예문부터 보여 드려요”처럼 실제로 적용할 설정만 놓는다.
- 행동은 「이 친구와 시작하기 / 다른 친구 보기 / 답 바꾸기」. 추천 수락은 추천 정확도나 학습 효과의 증거가 아니다.
- 명시적 선택 없이 몽글을 자동 확정하지 않는다. 추천 규칙·문항 순서가 바뀌면 판을 남기고, 과거 추천을 당시 규칙으로 재현할 수 있게 한다.

## 6. 설문에서 엔진까지의 연결

**원답 → 현재 선호 → 이번 도움 선택 → 실제 제공한 도움 → 학생의 반응·후속 수행 → 다음 도움**을 하나의 연결로 만든다.

| 단계 | 설계할 동작 | 완료 증거 |
|---|---|---|
| 모였나 | 학생 원답, 실제 본 문항·보기·순서·언어·판, 추천과 최종 선택을 연결해 저장 | 재로그인·다른 기기에서 현재 선택 복원; 중복 전송해도 한 응답 |
| 닿았나 | 최신 유효 선호가 자동으로 과제·답장 선택기에 도달 | 사용한 응답 ID와 선호 판을 읽기 기록에서 추적 |
| 달라졌나 | 같은 학습 목표에서 Q4~6에 따라 예문·힌트·교정 표시 순서가 달라짐 | 답만 바꾼 합성 학생 쌍에서 예상한 출력 차이와 실제 화면 |
| 학생에게 돌아갔나 | 첫 과제·답장에서 고른 방식을 보고 수정할 수 있음 | 실제 첫 흐름, 설정 변경 후 다음 출력에 반영 |

**Core/Atlas**는 학생의 선언·관찰·도움 결과를 구분해 현재 필요한 도움을 고르는 중심을 맡긴다. **Loom**에는 선택된 캐릭터와 화면에 필요한 최소 설정을, **Vellum**에는 설명·교정의 표현 설정을 전달하는 설계를 붙인다. 전체 설문 원답을 모든 엔진에 복제하지 않는다. 다른 엔진으로 확대할 때는 그 엔진이 무엇을 바꾸는지부터 정한다.

첫 소비자는 **힌트 제안 순서와 교정 답장 표시 선택기**로 좁힌다. 기존 과제 생성이 꺼진 수준이나 제공하지 않는 소재가 있으면 해당 범위를 자동으로 확장하지 않는다. 공통 교육 목표·필수 연습·정답·교정의 정확도는 같은 기준을 유지한다. 선호가 없는 축은 표준 안내를 사용하고 미응답을 특정 선호로 저장하지 않는다.

## 7. 저장할 원본과 현재 설정

다음은 개념 항목이며 현행 서버에 이미 존재하는 열·이벤트라는 뜻이 아니다. 구현 때 계약과 연결한다.

| 구분 | 남길 내용 | 해석 |
|---|---|---|
| 원답 | 응답 ID, 문항 ID·판, 언어·보기 ID와 순서, 고른 보기/모름/건너뜀, 시각·출처, 이용 범위 | 학생이 그때 직접 고른 사실 |
| 계산 결과 | 원답 참조, 규칙판, 점수·유효 답 수·근거 문항, 동점/응답 부족, 추천 후보 | 규칙으로 계산한 추천 |
| 최종 선택 | 학생이 확정한 캐릭터, 추천 노출 여부, 변경·대체한 선택 참조 | 실제 함께할 캐릭터 |
| 현재 선호 | 축별 최신 유효 선언, 출처 응답, 적용 상태, 수정·철회·재확인 상태 | 현재 도움에 사용할 설정 |
| 제공·결과 | 과제/답장/시도 참조, 선택 규칙판, 실제 제공한 도움·노출, 학생 반응, 이후 독립 시도 | 무엇을 제공했고 어떤 결과가 관측됐는가 |

현재 캐릭터 선택과 명시적으로 고른 표시 설정은 학생이 변경·사용 중지할 때까지 유지한다. 30일이 지났다고 자동 삭제하거나 매일 새 선언을 만들어 오래된 설문을 신선한 관측처럼 보이게 하지 않는다. 목표·소재는 현재 시즌·상황의 범위를 함께 저장하고 기존 목표 갱신 흐름으로 다시 확인한다. 최근 행동 관찰의 시간 창은 별도로 유지한다.

원답·추천·현재값을 한 칸으로 덮어쓰지 않는다. 한 응답에서 선택 기록과 선호 기록이 함께 파생되면 같은 원천 ID로 연결하고 두 증거로 세지 않는다. 서버 저장 성공을 확인한 뒤 완료로 표시하며 응답 손실·중복 전송·기기 변경·동시 수정의 복구 규칙을 둔다. 캐릭터의 기기 캐시는 서버의 현재 유효 선택으로 동기화한다.

과거 추천을 재현할 때는 답이 발생한 시각과 서버가 그 답을 알게 된 적재 시각을 함께 적용한다(`as_of`, `ingested_as_of`). 나중에 들어온 수정이 과거 판단에 섞이지 않게 한다. 선호 수정·취소·표준 설정 복귀·이용 철회를 구분하며, 최신 값을 철회했다고 옛 선호를 자동으로 되살리지 않는다. 설문 한 번의 여러 문항·파생 기록·추천 수락으로 사람 이해의 근거 수를 부풀리지 않는다.

「앞으로 이 답을 사용하지 않기」는 이후 개인화와 파생 캐시에서 해당 답을 제외한다. 전체 이용 철회·삭제는 기존 동의 계약에 따라 원본과 파생 관계를 따라 처리한다. 원본 이력 보존을 철회·삭제 거절의 이유로 쓰지 않는다. 외부 모델에는 학생 식별 정보나 불필요한 설문 원문을 보내지 않으며, 첫 추천 계산에는 외부 모델 호출이 필요 없다.

## 8. 앞으로 실제로 배우는 과정

**학생별로 배우는 과정:** 첫 답은 명시 선호다. 연습 중 실제 힌트 이용, 수정 시도, 학생이 선택한 설명 방식, 새로운 문제에서 혼자 해낸 결과를 구분해 쌓는다. 선언과 관찰이 다르면 곧바로 “학생의 실제 성격”으로 덮어쓰지 않고, 학생에게 다른 도움 방식을 선택할 기회를 준다. 접근성·직접 설정을 행동 점수로 조용히 해제하지 않는다.

추천이 애매하거나 학생이 원할 때는 **같은 내용의 답장을 두 방식으로 보여 주는 짧은 비교**를 제공한다. 처음부터 필수 체험 문제를 늘리지 않고 첫 답장 뒤에도 열 수 있게 한다. 비교에서는 캐릭터 외형·정답·학습 목표를 통제하고 실제 본 순서와 고른 방식을 남긴다. 편한 쪽을 골랐다는 결과 역시 선호이며 장기 기억 효과는 아니다. 후속 추정 확인은 기존 되묻기 한도와 흐름을 사용한다.

처음 추천한 방식만 계속 보여 주고 그 반응을 다시 추천의 증거로 삼지 않는다. 무엇을 보여 주었는지의 분모를 남기고, 학생이 원하면 다른 방법을 경험할 수 있게 한다. 가이드 정본 §8-3의 관찰기/적응기 구분을 유지하고, 추천 때문에 더 노출된 소재의 반응을 자연 관심사로 다시 집계하지 않는다.

**회사 엔진이 배우는 과정:** 허용된 기록에서 ‘원한 도움 → 제공한 도움 → 반응 → 후속 독립 수행’ 사례를 모아 추천 규칙을 평가하고 발전시킨다. 단순 저장이나 프롬프트에 넣는 것과 실제 모델 재학습은 별도 단계다. 훈련이 필요한 단계에서는 용도 허용·비식별 처리·철회 계보를 확인하고, 학습용 자료와 평가용 자료를 학생/시점 기준으로 분리해 같은 출처로 효과를 부풀리지 않는다. 설문 제출만으로 외부 모델 훈련에 자동 편입하지 않는다.

추천 수락률과 첫 과제 진입은 **사용성 지표**다. 도움 없이 새 문제를 푸는 결과·후속 기억은 **학습 지표**다. 전후 정답률만으로 추천이 원인이라고 단정하지 않으며, 일반적인 진도 상승과 과제 차이를 분리한 평가를 설계한다. 아직 실제 학생 자료로 이 추천의 정확도·효과를 검증하지 않았다.

고정 학습유형에 수업을 맞추면 더 잘 배운다는 근거는 부족하고 선호는 상황에 따라 달라질 수 있다. 이 점 때문에 본 설계는 선호와 수행을 분리한다. 근거: [EEF Learning styles](https://educationendowmentfoundation.org.uk/education-evidence/teaching-learning-toolkit/learning-styles), 원문 확인 2026-09-09, 해당 검토 갱신 2025-10. 이는 일반 연구 근거이며 SYNK 학생의 실측이 아니다.
