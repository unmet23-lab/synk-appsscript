## 0. 한 장 요약

### 0-1. 판정 분포 (구판 81행 전수 + 신설 22)

| 판정 | 뜻 | 건수 |
|---|---|---|
| **이관** | 새 앱(SYNK-talk)에 다시 짓는다 | **20** |
| **압축** | 축소·통합해 새 앱에 짓는다 | **27** |
| **미이식** | 새 앱에 안 짓는다 (AS·Glide 코드는 파일럿 게이트 뒤 소각) | **11** |
| **낙하산 유지** | 새 앱에 안 짓고 AS·시트 층에서 계속 (운영·자동화) | **23** |
| | 구판 소계 = 20+27+11+23 | **81** |
| **신설** | 엔진 설계에서 나온 새 기능 | **22** |

- 판정은 **주판정 1개**만 센다. 「승격」 등은 부기(비고)로 적어 집계가 검산 가능하게 했다.
- 「미이식」은 지금 지운다는 뜻이 아니다 — 개원(2027-02)까지 낙하산은 그대로 돌고, 소각은 파일럿 게이트 뒤다(§9).

### 0-3. 「뇌」 표기 규약 — 전 기능 공통 칸

모든 유지·압축·신설 기능에 「데이터 → 뇌」를 단다. 뇌 4부품(코어엔진 §4): **①지식 그래프 ②학습자 모델 ③오류·교정 말뭉치 ④AI 게이트웨이**.
**먹임**=데이터를 만들어 뇌에 넣는다 · **소비**=뇌에서 꺼내 쓴다 · **역할필수**=뇌 기여가 없어도 역할 축(관리·운영/학생관리/출석·능률/신뢰)에 없으면 안 되는 것.
🔴 **셋 다 아니면 존재 이유가 없다 → 미이식.** 이 자를 81행 전부에 댔다.

### 0-4. 다섯 회로 — 이 문서의 분석 축

| 회로 | 정의 | 죽으면 |
|---|---|---|
| **C1 먹이는 회로** | 학생이 한국어를 생산해 ③말뭉치·②학습자가 쌓이는 입구 전부 | 3년차 회화봇 원료 0 — 핵심 등식 붕괴 |
| **C2 주는 회로** | 뇌가 학생·강사·학부모에게 되돌려주는 개인화(④ 경유) | 수집이 「받는 게 없는 노동」이 되어 C1이 멈춤 |

| **C4 운영층** | 뇌를 안 먹여도 역할 필수(법적 기록·돈·접수·신뢰·안전) | 학원이 안 돈다 |
| **C5 계약층** | 위 넷이 같은 모양으로 흐르게 하는 배관(이벤트 계약·동의·비식별·강등) | 3년차에 조인이 안 된다 |

구판과 갈리는 구조 판정 2개: **C3(라벨)를 독립 회로로 승격**(teacher_gold의 유일 입구가 Glide였다 — §5) ·
**C2의 화폐를 임의 화폐(포인트·랭킹)에서 학습 데이터 시각화로 교체**(§6).

### 6-3. 🔴 리스크 — 정직하게

1. **훅 약화가 수집기를 멈출 수 있다.** 1:1 교체는 설계상의 답이지 검증된 답이 아니다. **실학생 0(개원 2027-02)이라 「게임화가 실제로 얼마나 오게 했는가」의 실측이 회사에 하나도 없다** — 압축 손실의 크기는 추정이고, 그 추정의 신뢰도를 높게 말하지 않는다.
2. **데이터 시각화는 임의 화폐보다 느리게 움직인다.** 급수는 몇 주에 한 번 움직인다 → 게이지를 **급수(느림)+태그 해소(중간)+기여일수(매일)** 3층으로 겹쳐 매일 움직이는 층을 반드시 하나 둔다.
3. **「모아서 산다」 유인 소멸**(스토어 미이식) → 실물 보상(과잠·굿즈) 자격을 도달·기여 데이터 자동 판정으로 재배선(학18 · §12-5).
4. **경쟁 훅 소멸**(랭킹 미이식) → 완화 ①학부모 푸시가 등원·제출을 민다(⚠수강생 연령 구성이 정본에 없어 「보호자 압력」 효과는 가설이다 — §11) ②미제출은 강사 오늘체크에 떠서 사람이 민다.
5. **되켜기는 스위치가 아니라 재구현이다.** 미이식하면 talk에 그 코드가 없다 — 보존되는 것은 설계·데이터 스키마·게이트 문구지 화면이 아니다. 그래서 소각을 게이트 뒤로 미루고 데이터 구조는 지우지 않는다(§9).

## §10. 【도전안】 — 통념을 깬 방향 대안 (본문과 분리해 읽으세요)

> **「1년차의 진짜 제품은 학생 앱이 아니라 강사용 라벨링 콘솔이다 — M2 라벨 트랙을 M1과 병렬 2트랙으로 지금 시작하라.」**

실학생은 2027-02에 온다. 강사는 그 전에 있다. 말뭉치의 가치 상한은 데이터 양이 아니라 **라벨 품질**이고, 라벨은 학생 없이도 시작할 수 있다(기존 hw_feedback·교재 문장·데모 크루·AI 배치 과거 출력). 개원 날 「채점표를 가진 학원」으로 시작하는 것 — 경쟁자가 돈으로 못 사는 자산이다. 학생 표면은 최소(말하기 1화면+학부모 1화면)로 열고 나머지는 낙하산이 감당한다.

**정직한 반론 4(스스로 친 것)**: ①강사 채용 시점이 유일한 차단자(계약 전이면 라벨할 사람이 없다) ②과거 첨삭 데이터 양을 재보지 않았다 ③🔴**대표성 한계 — 실학생 0이므로 현 hw_feedback은 리허설·데모 산출이다. 그것으로 만든 채점표는 실학생 오류 분포를 대표하지 못한다**(개원 후 실데이터 라벨로 갱신 필수) ④학생 앱이 얇은 동안 학생은 말하기=talk / 나머지=Glide **두 앱을 병행**하게 된다 — 낙하산 기간의 실사용 마찰이다.
**적용 조건**: 개원까지 남은 기간이 M3 전체를 못 담는다고 판정될 때, 또는 라벨 선축적의 가치를 유호님이 인정할 때(§12-4).
