## 7. 대개편 판정안 요약

**① 삭제 (내 판정안 — 유호님 확정 대상)**
1. 노션 동기화 코드 일체(기결정 — `syncToNotion_`·`NOTION_*`) — **즉시 가능**
2. 스토리북(synk_stories + 생성 배치) — 꺼져 있고 로그 0
3. 대형 연출 카드 4종 코드·열(BG·BH·BI·BJ) — 이미 화면 제거·계산 스킵
4. 진행바 T·게이트문구 CD 열 — 화면 미배치 중복
5. `lecture_views.한줄요약` 문항 — write-only(C-2, 또는 읽기 배선 신설 중 택1)
6. `_보류_두뇌_웹화면.js` — 보류 사유 문서만 남기고 소각
- ⚠ 리그·월드레이드는 삭제가 아니라 **꺼짐 유지** — 복귀 게이트(개원 첫 시즌 실측·유호 재판정)가 걸려 있다.

**② 재설계 확정(제품방향 위반 — 대조감사 그대로)**: A-1 AIQ 평생1행 · A-2 ai_daily 야간삭제(소급불가 2건 최우선) ·
B-1 voice 오류태그 · B-2 교실 기록 2종 편입 · B-3 급수 키 · C-3 mastery upsert→append · C-4 대량 출구 신설 ·

## 8. 도전안 (별도 라벨)

**「삭제로 시작하는 대개편」을 뒤집어라 — 대개편의 첫 삽은 기능 정리가 아니라 데이터 계약 동결이다.**
실측이 말하는 것: 지울 만한 것은 이미 다 꺼져 있고(스위치 4종+CARD_OFF), 남은 삭제 후보의 유지비는 ~0이다.
반면 지금 라이브에서 **매일 데이터가 실제로 새고 있다**(AIQ·ai_daily — 소급 불가). 순서를 "삭제→재설계→API"가 아니라
**"수집 6시트 스키마 v2 동결(=새 앱 API의 데이터 계약 그 자체) → 그 계약 위에 화면·기능 재배치 → 삭제는 마지막 청소"**로.
이러면 대개편과 새 앱 API 설계가 두 작업이 아니라 한 작업이 된다 — 시트든 Supabase든 같은 계약을 읽는다.
