# AI 마켓 첫 개발 묶음

2026-11-10. 구현 전 설계. 아래 검증과 공개 증거가 생기기 전에는 운영 완료로 표시하지 않는다.

## 요청과 경계

사용자 요청: 회원가입, 글 작성·저장, 댓글·관심 글, 판매자 프로필, 서비스 등록을 실제로 만든다. idk의 문의 분석·전문가 추천·견적·프로젝트 관리와 외부 모집 발송은 계속 보류한다. 기존 시범판은 보존하고 새 실제 서비스는 `experiences/ai-market/`에 만든다.

GPT의 기획·화면 작성은 이 채팅의 직접 승인 “이번 작업은 GPT가 기획·화면까지 진행해”에 따른다. 11-10 기존 공식 검수 통로의 실제 호출이 `Not logged in`으로 실패했고, 사용자가 “이번 작업은 독립 GPT 검수로 진행”을 승인했다. 이번 묶음의 Fable 설계·최종 검수와 Claude 백엔드 검수를 독립 GPT 검수로 대체한다. 아르곤 화면 검수와 권한·저장·화면·배포 검사는 유지한다. 이 예외는 다른 작업에 적용하지 않는다. 구매·결제·내부 채팅·파일 업로드·외부 연락 자동화는 이번 묶음에 없다. 예시 판매자와 원고를 실제 회원·게시글로 자동 이관하지 않는다.

## 사용 흐름

1. 비회원도 공개 글·판매자·서비스를 검색하고 읽는다. 데이터가 없으면 실제 빈 상태와 첫 작성 행동을 보여준다.
2. 가입·로그인은 기존 중앙 SYNK ID에서 진행하고 마켓으로 돌아온다. 이메일 확인·복구·Google 로그인은 기존 계정 포털의 실제 제공 범위를 따른다. 마켓에 별도 비밀번호를 저장하지 않는다. 기존 OAuth 흐름의 5분 만료와 이메일 확인을 구분한다. 확인이 늦거나 다른 브라우저에서 끝난 경우 마켓의 “가입 확인을 마쳤어요 · 로그인 이어가기”에서 새 OAuth를 시작한다. 이미 검증된 flow의 취소·교환 실패만 마켓 실패 안내로 돌아오고, 검증되지 않은 state의 복귀 URL은 신뢰하지 않는다.
3. 로그인한 사용자가 공개 닉네임과 소개를 정한다. 중앙 이름·이메일을 공개 닉네임으로 자동 복사하지 않으며 중앙 계정의 이메일·소속·기기·세션은 공개하지 않는다. 공개 프로필이 없으면 PROFILE_REQUIRED로 작성 단계에 안내한다. 판매자 정보가 없는 서비스 생성도 SELLER_REQUIRED로 안내한다.
4. 글을 작성하고 게시한다. 본문은 일반 텍스트로 표시하고 실행 가능한 HTML을 허용하지 않는다. 본인 글을 수정·삭제할 수 있다.
5. 다른 회원이 댓글을 쓰고 관심 글에 저장한다. 관심 글은 본인에게만 보이고 다른 세션에서도 복원된다.
6. 회원이 판매자 소개·분야·사례 링크를 작성하고 서비스를 등록한다. 글 아래에는 글 작성자 본인의 공개 서비스만 연결한다. 동일 분야의 다른 서비스는 별도 탐색 영역으로 구분한다.
7. 서비스에는 제공 내용·결과물·포함/제외·가격 안내·공개 문의 URL을 적는다. 서비스 등록을 전문성 인증으로 표시하지 않는다. 서비스에서 작성자의 사례로 돌아갈 수 있다.

## 기존 기반과 연결 선택

- 외부 회원 인증은 회사 서버의 `customer-identity.mjs`를 재사용한다. 내부 메신저의 `/api/setup`, `/api/join`은 직원·초대 계정이므로 사용하지 않는다.
- 기존 인증 쿠키의 Path는 `/api/customer`다. 새 API는 `/api/customer/ai-market/` 아래에 두어 직원 세션이나 다른 경로의 쿠키 정책을 넓히지 않는다.
- `server.mjs`에서 새 마켓 라우터를 기존 `customerRoutes`보다 먼저 처리한다. 기존 라우터는 모르는 고객 경로를 404로 종료한다.
- 기존 로그인 시작에 서버가 정한 복귀 경로를 결합한다. 허용값은 기존 `/consultation/`와 새 `/ai-market/`뿐이다. 클라이언트가 보낸 임의 URL로 이동하지 않는다. 기본값과 기존 상담의 성공·실패 이동은 보존한다.
- 인증된 사용자의 `synkUserId`가 마켓 소유권의 기준이다. 글·댓글·판매자·서비스 요청 본문에서 사용자 ID를 받지 않는다.
- `Store`의 SQLite 연결·transaction을 재사용하고 `ai_market_` 접두사 테이블을 추가한다. 기존 회사·상담 데이터를 이관하거나 덮지 않는다. 모든 데이터는 서버 디스크에 저장하며 브라우저 메모리·localStorage를 원장으로 쓰지 않는다.
- 고객 인증의 다섯 운영 설정과 실제 OAuth 등록 상태는 공개 전에 확인한다. 미설정이면 가입 버튼을 성공처럼 표시하지 않고 이유를 알려준다. 실제 인증을 통과하지 않은 테스트 모드를 운영 서버에 넣지 않는다.
- 로그아웃은 기존 POST `/api/customer/logout`을 재사용한다. 로컬 로그아웃과 중앙 폐기 실패를 구분하고 화면은 성공한 로컬 로그아웃 직후 회원 전용 정보와 CSRF를 비운다. 로그인 세션의 최소 식별자만 `/session`에 응답하며 공개 작성자명은 마켓 프로필에서만 가져온다.

## 데이터

| 테이블 | 주요 필드·불변 조건 |
|---|---|
| ai_market_profiles | user_id PK, display_name, bio, revision, created_at, updated_at. 공개 필드만 응답 |
| ai_market_posts | id PK, author_id FK, kind(question/case/discussion), category, title, body, revision, created_at, updated_at, deleted_at |
| ai_market_comments | id PK, post_id FK, author_id FK, body, revision, created_at, updated_at, deleted_at. 삭제 글에는 새 댓글 금지 |
| ai_market_bookmarks | user_id + post_id 복합 PK, created_at. 목록은 본인에게만 제공하며 삭제 글은 숨김 |
| ai_market_sellers | user_id PK/FK, headline, description, categories JSON, portfolio_url, revision, timestamps. 자기 소개이며 검증 배지 없음 |
| ai_market_services | id PK, seller_id FK, category, mode(learn/digital/commission), title, description, deliverables, includes, excludes, price_text, contact_url, revision, timestamps, deleted_at |

공개 목록은 페이지 크기를 제한하고 날짜+ID로 안정적으로 정렬한다. 검색은 매개변수 바인딩으로 처리한다. 본문·제목·링크·분류·페이지 값을 서버에서 제한한다. 수정은 현재 revision을 요구하고 충돌이면 409로 돌려 기존 입력을 보존한다. 프로필·판매자 최초 PUT은 revision=0, 이후 갱신은 현재 revision을 쓴다. 삭제는 본인 확인 뒤 표시를 해제하며 타인의 자료를 지우지 않는다. 삭제된 행의 stale PATCH와 삭제된 부모의 댓글 접근을 거절한다. 글·댓글·서비스 생성에는 요청 UUID와 정규화 입력 해시를 저장하고 사용자+동작+UUID 유일성을 DB로 강제한다. 응답 유실 뒤 같은 요청을 재전송하면 동일 결과를 반환하고, 같은 UUID로 내용을 바꾼 요청은 409로 거절한다.

## API 계약 초안

공통 접두사는 `/api/customer/ai-market`. JSON 오류에는 코드와 사용자 메시지를 제공한다. 목록의 공개 응답과 회원 전용 응답을 구분하며 인증·오류 응답은 no-store다.

| 경로 | 동작 |
|---|---|
| GET /session | 로그인 가능 여부·현재 사용자·CSRF·자기 프로필. 외부 비공개 계정 정보 없음 |
| POST /login | 중앙 SYNK ID 인증 시작, 복귀 경로는 서버가 마켓으로 고정 |
| GET /posts | q/category/kind/cursor. saved 필터는 로그인 필요 |
| POST /posts | 현재 회원의 글 게시 |
| GET /posts/:id | 공개 글·작성자·공개 댓글·작성자의 공개 서비스 |
| PATCH /posts/:id, DELETE /posts/:id | 작성자와 revision 검사 |
| POST /posts/:id/comments | 현재 회원의 댓글 작성 |
| GET /posts/:id/comments | 공개 댓글의 후속 페이지 |
| PATCH /comments/:id, DELETE /comments/:id | 댓글 작성자와 revision 검사 |
| GET /posts/:id/bookmark, PUT /posts/:id/bookmark, DELETE /posts/:id/bookmark | 현재 회원 관심 상태 조회·멱등 설정·해제. 공개 글 응답과 분리 |
| GET /profiles/:id, PUT /profile | 공개 프로필 조회 / 자기 프로필 작성·수정 |
| GET /sellers/:id, PUT /seller | 판매자 조회 / 자기 판매자 프로필 작성·수정 |
| GET /services, GET /services/:id | 공개 서비스 탐색·상세 |
| POST /services, PATCH /services/:id, DELETE /services/:id | 자기 판매자 계정의 서비스 등록·수정·게시 해제 |

쓰기 요청은 같은 Origin, 실제 인증 세션, CSRF를 확인한다. 본문 읽기 뒤 다시 인증하고 동일 주체·현재 세션을 확인한 뒤 동기 transaction으로 저장한다. 본문 전송 중 로그아웃·계정 전환·세션 폐기가 발생하면 저장하지 않는다. 로그인과 글·댓글 쓰기는 요청량을 제한한다. URL은 자격정보 없는 HTTPS만 허용하고 외부 링크에는 noreferrer/noopener를 적용한다. 서버가 외부 링크의 내용을 가져오지 않는다.

## 화면과 파일

- `experiences/ai-market/index.html`, `app.mjs`, `style.css`: 실제 서버 데이터를 읽는 반응형 화면. 커뮤니티 / 서비스 / 내 활동 / 프로필을 중심으로 구성한다. 오류·빈 결과·로딩·로그인 만료를 구분하고 저장 실패 시 입력을 유지한다.
- `company/ai-market-store.mjs`: 테이블·검증·소유권·조회·transaction. `company/ai-market-routes.mjs`: HTTP 계약·인증·CSRF·호출 제한.
- `company/customer-identity.mjs`, `customer-routes.mjs`: 허용 복귀 경로를 인증 흐름에 묶고 콜백에서 사용. 직원 인증은 바꾸지 않는다.
- `company/server.mjs`: 라우터와 정적 파일 연결. 현재 고객·직원 경로의 회귀 시험을 포함한다.
- `company/Dockerfile`, `Dockerfile.dockerignore`: 마켓의 브라우저 파일을 정확히 COPY·허용 목록에 포함한다. 배포 이미지에서 HTML·JS·CSS·폰트의 존재와 실제 응답 바이트를 확인한다. 기존 정적 파일 제공과 self CSP를 재사용하며 인라인 스크립트·스타일·외부 API 호출을 추가하지 않는다. host static set을 선택할 경우 `deploy/static/policy.json`에도 정확한 브라우저 파일만 등록한다.
- `company/ai-market-store.test.mjs`, `ai-market-routes.test.mjs`, 기존 고객 인증 시험: 임시 DB·합성 계정·로컬 HTTP를 사용한다.
- 검수 도구가 GPT 화면을 일괄 거부하는 기존 정책이 있다. 이번 직접 승인만 `ai-market-first-bundle-20261110` taskId·정확한 경로로 표현한다. 화면은 아르곤+독립 GPT 최종, 백엔드는 독립 GPT로 검수한다. 해시 사슬, 실제 검수 응답, P0/P1 조건은 그대로 유지한다. 이를 검수 생략으로 구현하지 않는다.

위 `company/`는 `docs/마케팅/온라인마케팅지도/engagement/company/`를 뜻한다.

## 검증과 완료 조건

1. 가입·로그인: 중앙 포털의 실제 신규 회원 경로와 마켓 복귀를 확인한다. 모의 OAuth 시험만으로 실제 가입 완료를 주장하지 않는다.
2. 저장: A가 글·댓글·관심·판매자·서비스를 저장하고 서버 재시작 및 새 브라우저 세션에서 다시 읽는다.
3. 소유권: B가 A의 글·댓글·프로필·서비스를 바꾸지 못하며, B의 관심 글은 A에게 노출되지 않는다. 비회원 쓰기·타 Origin·CSRF 누락·폐기 세션도 거부한다.
4. 연결: A 글의 서비스 영역에 B 서비스가 작성자 상품으로 섞이지 않는다. 삭제·게시 해제된 자료는 공개 탐색과 관심 목록에서 숨긴다.
5. 실패: 서버 오류·네트워크 유실·409 충돌·로그인 만료·중복 저장 시 입력을 보존하고 결과를 오인시키지 않는다.
6. 모바일/접근: 1440·390 폭에서 가입→글→댓글/관심→판매자→서비스 경로, 초점 이동, 키보드, 글자/입력, 가로 넘침, 콘솔·요청 오류를 확인한다.
7. 회귀: 기존 상담 로그인 복귀·직원 인증·다른 고객 API가 유지되는지 시험한다.
8. 이번 직접 승인에 따라 설계 독립 GPT, 화면 아르곤/독립 GPT 최종, 백엔드 독립 GPT 검수와 적용 경로 검사를 마친다. 검수한 후보와 배포 바이트를 대조하고 공개 주소에서 확인한다.
9. 외부 모집·의뢰 전송·idk 기능·결제 호출이 추가되지 않았음을 변경 파일과 실제 요청으로 확인한다.

독립 GPT 설계 검토(11-10, auth_integration_audit)는 배포 포함·가입 지연 복구·생성 멱등의 P1 3건을 지적했다. 위 설계에 모두 반영했고 구현·시험에서 같은 항목을 추적한다. 원문 SHA와 검토 범위는 작업 QA의 `design-review-gpt.md`에 보존하며 최초 실패한 Claude 호출을 통과로 바꾸지 않는다.

## 벤치마킹과 출시 구분

기존 [조사 근거](벤치마킹.md)의 GPTers 경험 공유, Fiverr 분야 탐색, 사례→서비스 연결 가설을 사용한다. 사용자 반응의 표본 한계도 유지한다. 기능 구현이 수요·매출·판매자 참여를 증명하지 않는다. 초기 공개 글·서비스는 사용자가 실제로 작성한 자료만 취급하고 기존 20편 초안은 자동 공개하지 않는다.

첫 묶음의 실제 기능과 공개 운영 확인을 완료한 뒤에도 판매자 모집·초기 콘텐츠 게시·결제 출시는 별도 상태로 보고한다. 외부 발송은 사용자의 보류 결정이 유지된다.
