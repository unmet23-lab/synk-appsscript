## 먼저 볼 것

사례를 보던 사람이 그 결과를 만든 사람에게 **배우기·자료 구매·맞춤 의뢰** 중 하나로 이어지는 서비스다. 문제부터 제출한 사람에게는 운영자가 조건을 확인하고 적합한 전문가를 제안한다. 계약은 구매자가 범위와 견적을 비교한 뒤 선택한다.

## 이번에 이어가는 범위 · idk와의 구분

2026-11-09 채팅 간 중복을 확인한 뒤 사용자가 계속 진행하도록 했다. 이 채팅은 **커뮤니티·사례·판매자·상품 탐색**을 보완한다. 기존 요청서·후보 비교·내 작업 화면은 검토 자료로 남기고, 문의·견적·진행 관리의 추가 개발은 idk와 역할을 정할 때까지 보류한다. 아래의 장기 거래·정산 구상은 새 구현 지시가 아니다.

| 구분 | AI 마켓 | 가칭 idk |
|---|---|---|
| 고객의 시작 | 사례를 읽고 자신에게 필요한 자료·강의·제작자를 고른다 | 무엇이 필요한지부터 상담하고 해결 방법을 제안받는다 |
| 핵심 가치 | 경험과 작업 증거를 보고 제공자를 비교하는 발견·거래 공간 | 요구사항 정리, 전문가 구성, 견적 제안과 완성까지의 관리 |
| 이번 채팅 담당 | 원고 검색·관심 글, 관련 주제의 서비스 탐색, 판매자가 설명할 정보 | 문의 분석·전문가 섭외·견적·프로젝트 관리의 별도 구현을 늘리지 않는다 |
| 아직 정하지 않은 것 | 실제 판매자·구매자 운영, 직접 거래의 계약·결제 | 두 서비스의 계정·운영·수익 배분을 합칠지 여부 |

고객은 사례를 읽은 뒤 직접 배울지, 자료를 사용할지, 제작을 맡길지 고른다. 서비스 상세에서는 결과물·포함/제외·사용권을 보고 제작자의 사례로 돌아갈 수 있어야 한다. 제공자를 정하기 어렵거나 여러 분야의 도움을 묶어야 할 때 idk 상담으로 이어주는 것은 **후속 연결안**이다. 모든 구매를 idk로 보내거나 마켓을 강의 사이트로 한정하는 결정은 아니다.

후속 연결을 구현한다면 원본 글 ID·선택 상품 ID·원하는 도움·사용자가 확인한 상황 요약만 초안에 이어 준다. 연락처·고객 파일·비공개 대화는 자동으로 넘기지 않는다. 실제 수신 경로와 공유 동의를 정하기 전에는 idk로 전송하지 않는다. 동일 의뢰에 두 서비스의 수수료를 자동으로 겹쳐 붙이는 안도 확정하지 않았다.

**이번 내부 시범판에서 확인할 동선:** `퀴즈 검색 → 원고 읽기 → 관심 글 담기 → 직접 배우기 → 같은 분야의 코칭 예시 → 상품 조건 → 제작자 사례`. 내부 원고와 합성 상품은 작성자·판매자가 일치한다는 증거가 없으므로 ‘같은 주제의 예시’로만 연결한다. 관심 글은 현재 창의 메모리에만 유지하며 새로고침하면 초기화된다.

이번 단계에서는 검색·필터·관심 글과 세 가지 도움 방식의 연결이 실제로 동작하는지 확인한다. 이후 실사용 검증에서는 최근 과제가 있는 사람에게 사례 하나를 찾아 다음 행동을 고르게 하고, 고른 이유·막힌 지점·설명이 더 필요한 조건을 기록한다. 가입 수·구매 전환·사용자 만족을 시범판 동작만으로 인정하지 않는다. 모집 문안의 외부 발송 보류는 유지한다.

## 첫 출시의 범위

장기 범위는 AI 광고·강의·도구·콘텐츠·업무 활용 전반이다. 첫 거래는 세 분야에서 모집한다.

| 분야 | 구매자가 원하는 결과 | 첫 제안 단위 | 계약 전에 확인할 것 |
|---|---|---|---|
| 광고·콘텐츠 | 제품·브랜드를 설명하는 결과물 | 숏폼 1편, 이미지 묶음, 기존 영상 변형 | 사용할 매체, 길이·비율, 권리, 수정, 원본 파일 |
| 강의·코칭 | 자신의 일에 적용하는 능력 | 개인 코칭 1회, 팀 워크숍, 실습 피드백 | 수강자 수준, 시간, 결과물, 준비 계정, 녹화 |
| 자동화·개발 | 반복 업무 한 구간의 연결 | 업무 진단, 단일 흐름 구축 | 연동 권한, 입력·출력, 오류 대응, 월 운영비, 인수인계 |

처음에는 국내 성인 이용자·원화 거래를 가정한다. 맞춤 의뢰와 실시간 교육의 운영을 먼저 검증하고, 검증된 템플릿·디지털 상품을 같은 사례에 연결한다. 모든 AI 도구를 직접 제공하거나 대규모 강의 플랫폼부터 만드는 일정은 잡지 않는다.

기존 SHIFT의 강사 연결 조건과 PULSE의 제작 가격·판매 준비 단계는 그대로 별도 원문을 따른다. 이 문서의 수수료 가설을 기존 계약에 적용하지 않는다.

## 사이트 구조와 핵심 동선

상단 메뉴는 **발견 / 커뮤니티 / 서비스 / 내 작업**이다. 의뢰 작성은 항상 찾기 쉬운 주 행동으로 둔다. 운영 화면은 실제 서비스에서 운영 권한이 있는 계정에만 제공한다.

| 화면 | 방문자가 확인할 내용 | 이어지는 행동 |
|---|---|---|
| 홈·발견 | 분야별 결과, 해결 과정, 누구에게 맞는지 | 사례 열기 / 내 문제 적기 |
| 커뮤니티 | 사례·질문·실패 기록·자료, 작성자와 광고 관계 | 질문 / 제작자 보기 / 관련 서비스 |
| 사례 상세 | 문제·제약·진행 과정·확인된 결과·안 된 점·출처 | 배우기 / 자료 보기 / 유사 작업 의뢰 |
| 제작자 | 본인 역할, 직접 만든 사례, 제공 범위, 가용 일정, 거래 후기 | 상품·코칭 / 맞춤 의뢰 |
| 서비스 상세 | 구매 후 받는 것, 제외 항목, 총액, 기간, 수정, 사용권 | 조건 확인 / 요청서 작성 |
| 의뢰 요청 | 목적, 산출물, 예산 또는 상담, 기한 또는 협의, 자료·권한 | 요약 확인 → 공유 범위 선택 → 접수 |
| 후보 비교 | 적합 이유, 사례, 가격 범위, 일정, 확인할 조건 | 질문 / 제안 요청 / 선택 |
| 내 작업 | 합의된 범위·결제·메시지·납품·수정·검수·분쟁 | 다음 행동 한 가지 |
| 판매자 등록 | 전문 분야·제공 방식·가격 기준·직접 작업·참여 의사 | 운영 검토 요청 |
| 운영 | 누락 요청, 후보 검토, 미응답, 신고, 정산 보류 | 담당 배정 / 이유 기록 / 조치 |

예: 교육 퀴즈 제작 사례를 본 학원 운영자가 제작 과정을 읽는다. 직접 만들고 싶으면 실습 코칭, 편집 가능한 틀이 필요하면 자료 상품, 시간이 없으면 자신의 수업용 제작을 선택한다. 어느 경로에서도 같은 설명을 다시 쓰지 않도록 사례 ID와 선택한 목적을 요청서에 이어 준다.

완료된 거래를 사례로 올리는 것은 선택이다. 구매자의 후기 동의와 작업물 공개 동의를 분리하고, 공개하지 않아도 거래를 완료할 수 있다. 후기에는 검증된 거래 표시를 붙이고 추천·댓글 숫자를 거래 실력으로 환산하지 않는다.

## 추천 설계

처음은 운영자가 확인하는 추천이다. AI는 추후 요청의 빠진 정보 정리·분류·후보 설명을 돕는다. 판매자 채택과 계약을 자동 확정하지 않는다. 실제 LLM 연동은 기존 Atlas의 해당 기능과 권한을 재사용한다.

1. **필수 조건:** 분야, 제공 방식, 판매자 참여·검토 상태. 조건을 못 맞추면 후보로 내지 않는다.
2. **성립 조건:** 납기·예산·사용권·보안 요건. 불일치는 제외하고, 미확인은 확인 대기다.
3. **비교 자료:** 직접 작업 증거, 유사 산출물, 구체적인 제안, 최근 응답과 가용 일정.
4. 처음에는 최대 3곳을 이유와 함께 제안한다. 숫자를 채우려고 부적합한 사람을 넣지 않는다.
5. 후보가 없으면 범위·일정·예산 중 어떤 조건을 조정할지 요청자에게 설명한다. 응답을 보장하지 않는다.

광고 상품은 추천 순위와 분리하고 광고임을 표시한다. 개인 연락처·고객 원본 자료는 공개 요청에 싣지 않는다. 후보에게 보내는 비공개 요청 요약은 요청자가 검토한 뒤 공유한다.

시범판의 추천은 합성 판매자 데이터와 명시한 조건만 쓰는 동작 예시다. 실명 후보는 시범판에 입점 판매자로 넣지 않는다.

## 수익 모델과 비용 가설

**초기:** 완료·확정된 거래에 판매자 수수료 12%를 가정한다. 기본 가입·글쓰기·상품 등록·견적 제출은 무료, 구매자 별도 플랫폼 이용료는 없는 안이다. 실제 약정 전 가격 가설이며 부가세 포함 표시·과세 구분은 계약 구조 확정 때 정한다.

**후속:** 반복 거래와 업무 도구 수요가 확인되면 판매자 도구 구독 월 29,000원을 시험한다. 무료 판매자의 핵심 수주 기능을 막거나 유료 순위를 실력처럼 표시하지 않는다. 기업 프로젝트 관리비는 별도 범위·견적·계약으로 정한다.

시범판 운영 화면의 계산은 **환불되지 않은 완료 거래, 부가세 제외 관리 손익** 기준이다. 판매자가 받는 실제 정산액은 과세·원천징수·PG 약정에 따라 별도 산정한다.

| 기준 시나리오 | 입력 가정 |
|---|---:|
| 완료 거래 1건 | 1,000,000원 |
| 플랫폼 수수료율 | 12% |
| 결제·지급 비용 예산 | 거래액의 3.5% |
| 건당 문의·분쟁 대응 원가 | 15,000원 |
| 회수하지 못하는 비용 충당 가정 | 거래액의 1% |
| 월 고정비 예산 | 3,000,000원 |
| 고객 획득비 | 기본 0원, 별도 입력 |

기준값의 건당 수수료 매출은 120,000원, 건당 공헌이익은 60,000원이다. 고정비 300만원을 메우는 데는 같은 조건의 완료 거래 50건이 필요하다. 실제 견적·수요·예측 매출이 아니다. 비용률에는 결제·환불·지급의 실제 계약 조건을 반영해야 하고, 취소 주문에 이미 들어간 상담 비용도 분모에 포함해 다시 계산한다.

만원대 자료와 백만원대 맞춤 작업을 같은 건당 원가로 섞지 않는다. 디지털 상품은 별도 모델로 검증한다. 보관금·판매자에게 지급할 금액은 플랫폼 수익이나 자유롭게 쓸 운영 자금으로 계산하지 않는다.

월 300만원은 집행 승인이 아니다. 운영 인건비 200만원, 서비스·보관·알림 30만원, 회계·약관 검토 30만원, 예비 운영비 40만원으로 나눈 계획값이다. 개발 외주·광고·법률 검토의 실제 견적은 별도로 받고 지출 전 승인한다. 이번 작업은 유료 API·결제·구독을 실행하지 않는다.

## 운영 인력과 첫 4주

| 책임 | 처음 맡을 역할 | 산출물 |
|---|---|---|
| 제품·운영 총괄 | 운영자 1명, 실명 배정 전 | 요청 검토·후보 확인·대응 이력 |

| 정산·개인정보 | 승인된 담당자만 | 거래 대사·정산 근거·접근 이력 |
| 개발·유지 | 정해진 담당자 | 오류 대응·백업·변경 검증 |

1주차에는 이 시범판과 모집 문안을 검토하고, 승인된 대상에게 고객 문제 인터뷰 5~10건과 판매자 인터뷰 5~10건을 진행한다. 2주차에는 실제 요청을 운영자가 직접 정리해 후보 제안과 견적 비교가 되는지 본다. 돈을 받는 시험은 사업자·계약·결제 준비가 끝난 뒤에만 한다. 3주차에는 필요한 수정과 운영 시간을 기록하고, 4주차에 거래 유형 하나를 먼저 출시할지 결정한다. 날짜는 참여 회신·법무·PG 심사에 따라 바뀌는 작업 순서이지 출시 약속이 아니다.

첫 인터뷰에서 질문할 것은 최근 실제 문제, 지금 해결하는 방법, 지출 경험, 필요한 결과물, 결정권자·기한이다. “이런 서비스가 있으면 쓰겠나요?”라는 호감만으로 수요를 인정하지 않는다.

확인 지표는 원문이 있는 유효 요청 수, 참여·가용성을 확인한 판매자 수, 후보 제안을 수락한 요청 수, 견적 선택·계약 수, 완료·환불·분쟁 수, 건당 실제 운영 시간과 공헌이익이다. 재방문·좋아요는 별도 참고 지표다. 첫 5~10건은 방향을 고치는 표본이며 시장 전체 전환율로 발표하지 않는다.
