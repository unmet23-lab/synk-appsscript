최초 회귀 시험의 기존 로그아웃 요청 503 실패는 보존했다. 새 라우터를 해당 URL에서만 await하도록 고쳐 기존 로그아웃 회귀와 전체 101건을 통과했다. 독립 검수가 지적한 비동기 경계 뒤의 세션 폐기 가능성은 마지막 await 뒤에 동기 현재성·CSRF 검사를 넣고 경계 회귀 시험으로 확인했다.

공용 origin의 서버 clock 연결과 별도 Workspace 검수 정책을 보존해 통합한 뒤, 제품 101·AI 마켓 검수 정책 45·Workspace 검수 정책 53을 함께 실행해 199/199를 통과했다. 이는 UI 회귀 11건과 별도 실행이며 동일 시험의 반복 통과를 새 시험으로 더하지 않는다. 수정된 UI 3파일 SHA와 최종 글·서비스 1440/390 캡처를 묶어 검토했고 해당 구간의 오류·실패 fetch·가로 넘침은 0이었다.

브라우저 시험 중 제목을 잘못 예상한 대기·초기화 버튼 두 개의 선택자 모호성·뷰포트 변경 뒤 포인터 위치 불일치는 실제 화면을 다시 관찰하고 올바른 제목·고유 선택자·키보드로 확인했다. 원래 실패 기록을 제품 통과 기록으로 덮지 않았다. 시험·캡처·검수 원문은 비공개 QA 보관 대상으로 관리한다.

아래는 이전 **준비 시범판**의 검증 기록이다. 이 시범판의 합성 데이터·메모리 저장·디자인 검토 결과를 실제 저장형 앱의 검증과 합산하지 않는다.

## 검토 범위

내부 기획·문서·운영자 검토 화면이므로 AI 운영 원칙의 내부 도구·문서 자체 점검 범위를 적용한다. 이번 작업의 GPT 작성 예외는 사용자가 이 채팅에서 승인했다. Fable·Claude 제품 배포 검수를 받았다고 표시하지 않는다. 고객용 제품을 구현·배포할 때는 해당 조건을 따로 충족한다.

디자인 맹검 1차는 대표 화면 4장 모두 기각이었다. 반복 안내·알약 모양 단추·정적인 설명 구역·모바일 입력 위치·기본 계산 양식에 대한 지적을 확인했다. 사례를 고르면 연결 행동이 바뀌는 첫 화면, 입력에 집중한 요청서, 구분자가 있는 비용 입력, 열고 읽는 운영 검토 항목으로 수정했다. 가상 데이터·전송 없음 표시는 유지하되 겹치는 안내를 줄였다.

수정한 4장의 두 번째 맹검도 **4장 모두 기각**이었다(홈 3, 모바일 홈 3, 모바일 요청서 2, 운영 4점). 실제 작업물의 시각적 제시 부족, 중복 의뢰 버튼·화살표, 일부 글줄과 입력 표현, 계산기 조작 가능성의 표현이 남은 지적이다. 기능 검증 통과와 디자인 검토 통과를 구분하며, 이 화면을 최종 디자인으로 승인됐다고 보고하지 않는다. 원문은 비공개 꾸러미 `화면/디자인검토_1차.md`·`디자인검토_2차.md`에 보존한다.

미확인 작업물이나 참여자를 실제 실적으로 채우지 않고, 가상 데이터·발송 보류·비용 가정 표시는 유지한다. 일반적인 스크롤 화면의 뷰포트 밖 잘림은 실제 가로 넘침·입력 접근 실패와 구분했다. [미학 맹검 도구](../../tools/미학맹검.js)의 “기각이면 지적대로 고치거나 다시 뽑아 한 번 더 보고, 그래도 기각이면 그 사실과 함께 보인다” 절차에 따라 결과를 고지하고 내부 검토 초안으로 전달한다. 실제 미디어 선택·사용권 확인과 후속 디자인은 사용자 검토 뒤의 일이다.

관련 시험을 직접 실행할 때 지면폰트 ⑦은 기존 지면 34벌의 git 밖 서체 산출물이 이 워크트리에 없어 실패했다. 바로올리기·관련시험 도구가 워크트리에 적용하는 `CI=1` 환경으로 해당 파일을 다시 확인해 11개를 통과했다. 진단에는 그 34벌을 읽지 못했다고 남으며, 이 시범판의 내장 서체는 실제 브라우저에서 별도로 확인했다. 추적 서체 누락을 제외 목록에 넣거나 관문을 끄지 않았다.

## 남겨 둔 실행

- 사용자 결정으로 고객·판매자 모집의 외부 발송은 보류한다.
- 실제 고객 문제 원문·판매자 참여·가용 일정·검증된 거래 후기는 아직 없다.
- 사례 미디어와 권리는 게시 전에 확인하고, 사용자가 고른 원고부터 실제 게시를 준비한다.
- 운영 사업자·계약·법무·세무·PG 심사·정산 시험은 실제 거래 출시 단계의 일이다.
- 최종 서비스명·가격·게시·고객용 구현을 이번 준비 시범판의 확정으로 간주하지 않는다.
