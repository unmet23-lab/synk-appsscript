# 거래와 커뮤니티 운영 초안

2026-11-09 · 계약서로 배포하거나 결제에 적용하기 전, 사업자·역할·세무·PG 조건을 반영해 검토할 문안이다. 아래 응답 시간과 운영 기간은 제안값이다.

## 계약의 당사자

외부 판매자의 상품은 판매자와 구매자가 계약하고 플랫폼은 중개하는 구조를 기본안으로 둔다. 플랫폼이 직접 제공하는 SYNK 상품은 판매 주체를 따로 표시한다. 상품·주문·영수증에 계약 당사자와 문의·분쟁 창구를 일관되게 표시한다. “중개이므로 책임이 없다”라는 포괄 문구를 사용하지 않는다.

통신판매중개자 고지, 사업자 판매자 신원 확인·제공, 불만·분쟁에 대한 조치 등을 실제 화면과 절차에 반영해야 한다. 개인 판매자는 사업자 판매자와 확인·정보 제공 방식을 구분해 검토한다. 근거: [전자상거래법 제20조~제20조의4, 2026-07-21 시행본](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=0&chrClsCd=010202&efYd=20260721&joNo=001700&lsiSeq=282793&urlMode=lsInfoP).

기존 PULSE·SHIFT 계약을 이 신규 플랫폼 약정으로 자동 변경하지 않는다. 미성년자·해외 판매자·해외 결제는 첫 시범 운영의 거래 범위에서 제외하는 안이며 공개 약관을 만들 때 실제 운영과 일치시킨다.

## 주문에 남길 공통 합의

주문 번호, 계약 당사자, 총 결제금액·세금 표시, 산출물과 제외 항목, 제공·납품일, 구매자 제공 자료·권리, 승인 담당자, 수정 범위·횟수, 검수 방법, 취소·환불 기준, 사용권·원본 인도, 유지·지원 기간을 결제 전에 같은 문서로 확인한다. 이후 범위나 가격이 바뀌면 변경 제안과 양측 승인을 기록한다. 메시지에 적힌 제안은 수락 전 계약 확정으로 표시하지 않는다.

| 구분 | 맞춤 제작·개발 | 강의·코칭 | 디지털 자료 |
|---|---|---|---|
| 구매 전 | 납품 형식·분량·기능·기간·수정·권리 합의 | 대상 수준·일정·시간·인원·학습 결과·준비물 | 미리보기·파일 구성·버전·호환 환경·라이선스 |
| 제공 시작 | 합의된 기획 승인과 착수 기록 | 확정 일정과 입장 안내 | 다운로드·접근 권한 제공 기록 |
| 완료 증거 | 납품 파일·기능 확인·구매자 검수 | 실제 진행·제공 시간·자료 전달 | 파일 접근·무결성·약속한 구성 |

| 공개 사례 | 고객·권리자의 별도 동의 | 수강자·화면·녹화 별도 동의 | 미리보기와 재배포 범위를 명시 |

맞춤 제작의 기본 수정 횟수는 판매자가 상품마다 제시하고 견적에 고정한다. 무제한 수정 약속은 만들지 않는다. 구매자가 답하지 않았다는 이유만으로 짧은 기간 뒤 자동 완료·지급하는 기능은 첫 운영에서 넣지 않는다. 납품 3영업일 뒤 운영자가 확인 요청을 보내고, 미응답 건은 기록과 약정에 따라 별도 처리하는 안이다.

## 취소·환불 문안 초안

“취소를 원하시면 주문 내 문의로 알려 주세요. 제공이 시작됐는지, 어떤 부분이 제공됐는지, 합의한 결과와 다른 점이 있는지를 확인해 적용 법령과 주문 조건에 따라 처리합니다. 판매자는 일률적인 ‘맞춤 상품 환불 불가’ 또는 ‘다운로드 후 모든 환불 불가’를 적용하지 않습니다. 표시·광고나 계약 내용과 다른 결과물에 관한 권리는 별도로 보장합니다.”

제작 진행률을 판매자 주장만으로 공제하지 않는다. 단계별 납품·승인 증거와 합의 금액을 확인한다. 용역·디지털콘텐츠의 청약철회 제한, 미제공 부분, 주문 제작 예외, 불일치·하자 구제는 각각 적용 요건이 다르므로 거래 유형별 사전 고지·동의와 검토가 필요하다. 법정 권리를 줄이는 기간·비율은 임의로 확정하지 않는다. 근거: [전자상거래법 제17~18조](https://www.law.go.kr/LSW/lsInfoP.do?ancYnChk=0&chrClsCd=010202&efYd=20260721&joNo=001700&lsiSeq=282793&urlMode=lsInfoP).

## 정산과 대사

결제 승인, 환불, 구매 확정, 지급 예정, 지급 요청, 실제 지급 성공을 서로 다른 상태로 관리한다. 실패·취소·중복 응답을 기록하고 같은 주문의 지급을 중복 실행하지 않는다. 운영자는 주문별 구매자 결제·환불·수수료·판매자 지급 예정·실제 지급을 대사한다. 분쟁 건은 이유·담당자·검토 기한을 남긴다. 판매자 잔액을 플랫폼 현금 매출로 잡지 않는다.

정산 주기는 PG와 판매자 계약 후 확정한다. “즉시 입금”, “전액 보호”, “에스크로” 같은 표현은 실제 계약 기능과 확인 증거가 있을 때만 쓴다. 판매자가 지급 정보를 입력하는 화면은 별도 보호 경로로 마련한다.

토스페이먼츠의 지급대행은 지급을 수행하며, 판매자와 정산 데이터 관리는 플랫폼에 남는다. 월·건별 비용과 계약 조건은 실제 견적을 받아 비용 모델에 반영한다. [공식 지급대행 정책](https://www.tosspayments.com/blog/articles/30365). 테스트 환경에서 확인할 수 없는 정산·KYC 범위가 있고 라이브 지급대행 요청에는 비용이 생길 수 있으므로 개발 시험과 실제 지급 시험을 분리한다. [공식 테스트 안내](https://docs.tosspayments.com/guides/v2/get-started/environment).

## 판매자 약정에 들어갈 문장

- 본인 또는 적법한 권한이 있는 작업만 포트폴리오로 제출한다. 직접 한 역할과 외주·공동 제작 범위를 밝힌다.
- 제안한 범위·일정·수정·지원·추가 비용을 구매 전에 명확히 적고 변경은 동의를 받는다.
- 고객 제공 자료는 해당 주문 수행에만 사용하며, 모델 학습·포트폴리오 공개·재판매는 별도 동의 없이 하지 않는다.
- 생성 AI 도구·소스·음원·초상·상표의 사용 조건을 확인한다. 결과물의 저작권 성립이나 독점 권리를 일괄 보장하지 않고 이전 가능한 권리·이용허락 범위를 구체적으로 적는다.
- 결제·취소·수수료·정산·분쟁 절차에 동의한다. 수수료 기준액·세금·환불 시 처리·공제 항목은 계약에서 확인한다.
- 신고·분쟁에 사실과 증거로 답하고, 조치에 이의가 있으면 재검토를 신청할 수 있다.
- 운영자가 추천한 사실이 품질 보증이나 자격 인증을 뜻하지 않는다. 전문 자격이 필요한 작업은 별도 확인한다.
- 약관 변경은 적용 시점과 기존 주문에 미치는 영향을 고지하며, 진행 중 주문에 불리한 조건을 소급 적용하지 않는다.

이 문장은 계약 목차와 검토용 조문이다. 실제 상호·사업자 정보·적용일·관할·책임 한도·세무 처리가 확정되면 전문가 검토를 거쳐 정식 약관에 합친다.

## 개인정보와 AI 처리

| 자료 | 처음 필요한 범위 | 접근·공개 |
|---|---|---|
| 이용자 연락 | 연락 방법 하나, 표시 이름 | 계정 소유자·접수 담당. 공개 글에서 제외 |
| 요청 내용 | 목적·산출물·예산 범위·기한 | 기본 비공개. 후보에게 보내기 전 구매자가 요약 확인 |
| 고객 파일 | 견적·수행에 필요한 최소 범위 | 선택한 당사자에게만 제한. 공개 링크 금지 |
| 판매자 확인 | 사업 형태·본인·지급 요건 | 승인된 심사·정산 담당, 가능하면 PG 보호 경로 |
| 거래 이력 | 약정·납품·환불·지급 증거 | 법적 의무·처리 목적에 따른 보유·파기표 필요 |
| 후기·사례 | 표시 이름·공개 동의한 부분 | 게시 동의와 광고 사용 동의를 분리 |
| AI 처리 | 필요한 요청 요약 | 공급자·국외 이전·보유·학습 사용 설정을 확인한 뒤 적용 |

실제 처리방침에는 처리자, 목적·항목·근거·보유기간, 위탁·제3자 제공·국외 이전, 권리 행사, 안전조치, 책임자와 변경 고지를 채운다. 미정 항목을 그대로 둔 문서를 서비스에 게시하지 않는다. 홍보 수신·사례 공개는 선택이며 기본 해제한다. 삭제 요청을 받으면 법정 보존 자료와 즉시 삭제 가능한 자료를 구분해 처리 사실을 기록한다. 작성 기준: [개인정보보호위원회 안내서 목록의 2026년 처리방침 작성지침](https://pipc.go.kr/np/cop/bbs/selectBoardList.do?bbsId=BS217&mCode=I030010000). 세부 보유기간은 사업 구조와 적용 법령을 확인해 확정한다.

이 시범판은 서버 전송·실제 회원 등록·파일 업로드·AI 전송을 하지 않는다. 입력은 열린 화면 안에만 있고, 사용자가 선택하면 자신의 기기에 JSON 파일로 내려받는다. 실제 연락처·고객 자료를 시범판에 넣지 않는다.

## 커뮤니티 규칙과 신고

사례는 문제·과정·직접 수행한 역할·확인한 결과·실패·출처를 구분한다. 생성물은 생성 AI 사용 사실을 표시하고, 고객 작업·개인 연습·가상 예시를 구분한다. 외부 원작을 소개할 때는 링크와 자신의 짧은 해설을 사용하며 전문·이미지·강의 자료를 허락 없이 옮기지 않는다.

관련 서비스 연결은 글 아래 정해진 자리에서 허용한다. 답변을 가장한 무관한 홍보, 같은 글 반복, 허위 후기·성과·자격·협찬 은폐는 조치한다. 운영자 자신의 상품도 동일한 규칙을 따른다.

신고는 사유·대상·증거를 받고 접수 사실을 안내한다. 권리 침해·개인정보 노출은 우선 검토하고, 필요한 범위의 임시 숨김과 증거 보존을 한다. 당사자에게 설명·반론 기회를 주고 처리 이유와 이의 제기 경로를 알린다. 평일 1영업일 내 첫 답변을 목표로 운영하되 이를 24시간 실시간 대응 보장으로 표시하지 않는다.

## 이용자에게 안내할 질문과 답변

- **AI 도구를 몰라도 요청할 수 있나요?** 지금 겪는 문제와 받고 싶은 결과부터 적습니다. 운영자가 필요한 조건을 정리합니다.
- **추천받으면 바로 계약되나요?** 아닙니다. 일정·가격·권리·작업 범위가 적힌 제안을 비교하고 구매자가 선택합니다.
- **예산이나 날짜를 몰라도 되나요?** 미정으로 제출할 수 있습니다. 후보에게 보내기 전에 운영자가 협의할 조건을 확인합니다.
- **사례를 올리려면 판매자가 되어야 하나요?** 사례·질문 공유는 누구나 할 수 있는 안입니다. 판매 기능은 별도 검토 후 활성화합니다.
- **좋아요가 많은 사람이 먼저 추천되나요?** 사례의 직접 수행 범위와 요청 조건을 우선 확인합니다. 인기 숫자만으로 실력을 인증하지 않습니다.
- **고객 작업을 공개해야 하나요?** 아닙니다. 후기·이름·작업물 공개는 각각 필요한 동의를 받고, 비공개로도 거래를 마칩니다.
- **자료를 구매하면 되팔 수 있나요?** 상품에 적힌 이용허락 범위를 확인해야 합니다. 구매만으로 재판매·저작권 이전이 자동 허용되지는 않습니다.
- **시범판에서 작성하면 접수되나요?** 현재 화면은 작성·비교를 해 보는 내부 시범판입니다. 내려받은 파일을 제외하면 입력은 이 창 안에만 있고 실제 등록·발송·결제가 없습니다.
