# SYNK 대용량 자산 보관과 제작

> 2026-09-10 유호님 지시: Google Drive 5TB를 앞으로 적극 활용하고, 큰 마스코트 자산부터 이동해 노트북 공간을 확보한다.

- 고해상도 원본·과거 후보·완료 결과는 회사 Google Drive에 보관한다. 승인본과 후보의 상태는 이동으로 바꾸지 않는다.
- 현재 제작 코드·회사 정본·자산 설명·확인값·작은 배포 자산은 로컬/Git에 둔다. 편집·렌더링에 필요한 큰 파일만 작업 중 로컬에 가져온다.
- 기존 자산 목록에 이름·용도·승인 출처·Drive 위치·SHA-256 확인값을 연결한다. 큰 원본을 새 작업 사본마다 통째로 복제하지 않는다.
- 파일이 많은 고해상도 원본은 원래 상대경로와 확인값을 담은 ZIP으로 보관할 수 있다. 필요한 원본만 정확한 기존 경로로 복원하며, 작은 실제 배포 자산은 계속 로컬에 유지한다.
- 원격 업로드 및 다시 읽기 검증 후 로컬 공간을 회수한다. 복사 성공만으로 원격 업로드 완료를 선언하지 않는다.
- 동기화된 G: 파일 삭제는 클라우드 삭제로 이어진다. 로컬 공간 회수 때문에 G: 원본을 삭제하지 않는다. 미전송 자료가 있을 수 있는 Drive 캐시를 수동으로 지우지 않는다.
- 기존 제작 경로를 확인한다. 대용량 원본을 필요할 때 복원하는 절차를 연결하고, 자산이 없어 대체 표현으로 바뀌는 것을 정상으로 보고하지 않는다.
- 사용 중인 AI 모델·UE 프로젝트·렌더 캐시·Git 저장소 전체는 로컬 제작 공간에 둔다. 종료된 작업 사본과 재생성 가능한 임시 파일은 보존 필요성을 확인한 뒤 정리한다.
- 새 강제 훅이나 예약을 추가하지 않는다. 기존 제작·납품 절차에 보관 위치와 실제 완료 증거를 남긴다.

- 목록·확인값·진행 증거: [`_ops/마스코트_Drive이관_20260910/`](./_ops/마스코트_Drive이관_20260910/)
- 완료: 고해상도 PNG/JPG/WebP 6,353개를 76개 ZIP으로 보관하고, Drive에서 다시 읽은 크기와 SHA-256을 모두 확인했다.
- 로컬 회수: 6,352개, 30,097,763,805바이트(28.031GiB). 최초 목록 뒤 수정시각이 바뀐 1개는 현재 작업 보호를 위해 로컬에 남겼다.
- 앱용 AVIF와 JSON 등 1,895개는 로컬에 유지한다. 전송용 ZIP과 임시 파일은 모두 정리했다.
- 기계 판독 완료 기록은 [`MIGRATION-COMPLETE.json`](./_ops/마스코트_Drive이관_20260910/MIGRATION-COMPLETE.json)이다.

## 원본이 필요한 작업

옷의 앱용 AVIF와 JSON 설명은 로컬에 유지한다. PNG 원본을 읽는 표정·누끼·틀맞추기·라디오 의상 작업은 `tools/mascot_originals.py` 또는 `tools/lib/마스코트원본.js`를 통해 필요한 파일을 먼저 복원한다. 연결된 제작 도구는 보관 목록도 “이미 만든 원본”으로 인식하므로, 원본이 로컬에 없다는 이유로 유료 생성을 다시 시작하지 않는다.

저장소 루트에서 직접 복원할 때는 다음 명령을 사용한다.

```text
python -B tools/drive-mascot-archive.py restore "GPT_표정_누끼_틀/실제파일명.png"
python -B tools/drive-mascot-archive.py restore-many "상대경로1.png" "상대경로2.png"
python -B tools/drive-mascot-archive.py restore-prefix "GPT_표정_누끼"
```

정확한 상대경로는 `옷_manifest.json`과 `pack-plan.json`에서 찾는다. 복원 도구는 Drive ZIP에서 해당 파일을 읽고 SHA-256이 같은지 확인한 뒤 기존 경로에 쓴다. 기존 파일은 덮어쓰지 않는다. 여러 파일 복원은 목록에 없는 경로가 하나라도 있으면 쓰기 전에 전부 거절하며, 폴더 복원은 필요한 총용량과 512MiB 여유 공간을 먼저 확인한다. 네트워크·Drive 연결이 없으면 원본 복원이 필요하다고 알리고 해당 제작을 보류한다. 작은 대체 이미지로 몰래 바꾸지 않는다.
