# SYNK 작업의 연결 구조

> 현행 구조 · 2026-09-21. 공통 기준은 [AI 운영 원칙](AI_운영원칙.md), 필요한 보조 도구는 [AI 스택 가이드](AI_스택_가이드.md)에 있다. 날짜가 붙은 설치·호출 기록은 현재 인증이나 연결 상태를 증명하지 않는다.

## 책임과 자료의 흐름

[문서 지도](문서_지도.md)에는 자료의 위치가, [트랙](_ops/트랙.md)에는 진행 중인 일의 남은 항목이 있다. 작업 순서는 이번 요청에 맞게 정한다.

작업 분담·재개·검토·예약은 현재 공식 앱·CLI가 맡는다. SYNK의 공유 자산은 코드·제품 설계·확정된 결과이며, 각 하네스의 판단·모델 선택·설정을 하나의 자체 실행기로 통일하지 않는다. 아래는 문서와 작업본의 연결, 남아 있는 선택 도구의 범위다.

### 공동 문서와 최신 상태

2026-09-21부터 GPT와 Claude는 각 저장소의 `AGENTS.md`를 공동 입구로 쓴다. `CLAUDE.md`에는 `@AGENTS.md`만 두어 같은 원문을 읽는다. 운영·설계 원문은 SYNK-appsscript, 앱 계약은 SYNK-talk, 홈페이지 원문은 SYNK-website에 유지하고 [공통 문서 지도](문서_지도.md)로 연결한다. 문서를 거대한 한 파일로 합치거나 모델마다 복사하지 않는다.

| 정보 | 함께 읽고 고치는 위치 |
|---|---|
| 공통 작업 방식 | [AI 운영 원칙](AI_운영원칙.md) |
| 제품·Atlas·마을·브랜드의 현재 설계 | [문서 지도](문서_지도.md)가 연결한 담당 원문 |
| 확인된 결과와 이어 할 일 | [트랙](_ops/트랙.md)의 해당 항목과 실제 결과 파일 |
| 사용자가 확정한 방향 | 담당 설계와 [결정](_ops/결정.md)의 근거 |
| 도구별 특수 기능 | 각 도구의 설정·스킬. 제품 설계의 별도 사본으로 사용하지 않는다. |

예를 들어 한 작업에서 NPC의 공통 능력을 Atlas에 추가하면 코드·담당 설계·검증 결과를 남긴다. 다음 작업은 그 원문을 읽고 콘텐츠에 연결한다. 어느 모델이 설계·구현·검토할지는 그때의 요청과 위임 범위로 정한다.

**같은 작업 폴더에서 저장한 파일은 바로 공유되지만, 이미 진행 중인 대화의 이해까지 자동 갱신되는 것은 아니다.** 이어받을 때 관련 파일을 다시 읽으며, 이전 세션의 지침이 남아 있으면 새 세션에서 시작하거나 현재 `AGENTS.md`·공통 원문을 다시 읽도록 요청한다. 로컬 파일에 접근하지 못하는 일반 웹 채팅에는 이 연결이 자동 적용되지 않는다.

별도 worktree는 다른 작업본이다. 공통 기준은 이 컴퓨터의 `C:/Users/q1212/Documents/SYNK-appsscript`에서 확인하되, 구현·시험은 선택한 작업본을 기준으로 한다. 커밋되지 않은 변경과 상대 경로를 확인하고 필요한 변경만 통합한다. `tools/session-freshness.js --json`은 필요할 때 쓰는 수동 조회이며 파일 복제·병합·원격 최신성을 보장하지 않는다.

2026-09-21 Codex의 자동 상태 조회 등록, Claude의 별도 Git 상태줄, GitHub의 자동 Claude 검수·합의 집계를 해제했다. 자동 상태 조회의 옛 훅 진입도 은퇴해 남아 있는 호출에서 문맥을 주입하지 않는다. 기존 세션의 주입 원인이 캐시인지는 단정하지 않으며, 등록 제거·명령 동작·실행 중인 세션의 반영은 구분한다. 보안·데이터·제품 계약 검사와 앱 연결은 보존한다. 조사·복구 위치는 [협업 장치 정리](_ops/협업장치_정리_20260921.md)에 있다.

자체 `codex-build`·`codex-review`의 신규 AI 실행은 은퇴한다. 기존 기록의 조회·처분과 제품 도구의 호환 의존성은 남긴다. [GPT 정본](GPT_정본.md)의 기술 계약이나 모델 허용 목록은 공식 앱에서 하는 새 작업에 적용하지 않는다. 업데이트를 따라가기 위한 별도 실행·검수 시스템을 다시 만들지 않는다.

공식 동작 확인(2026-09-21): [Claude Code 문서](https://code.claude.com/docs/en/memory#agentsmd)는 v2.1.277부터 조건에 따라 `AGENTS.md`를 직접 읽고, 기존 `CLAUDE.md`가 있을 때는 그 파일을 우선하는 기본 동작을 설명한다. `@AGENTS.md` 가져오기도 계속 지원하므로 이 연결을 사용한다. [OpenAI Docs](https://learn.chatgpt.com/docs/agent-configuration/agents-md)는 Codex가 실행을 시작할 때 지침을 구성한다고 설명한다. 확인한 로컬 버전은 Claude Code 2.1.278·Codex CLI 0.153.4이며, 모든 앱·웹 채팅의 자동 동기화를 확인했다는 뜻은 아니다.

## 연결·중단·재개

### 운영 홈의 확인 범위

[운영 홈](http://127.0.0.1:8790)은 담당 원문과 공식 하네스의 작업 상태를 읽어 보여 주는 로컬 화면이다. 업무 내용의 새 정본이 아니고, 실행을 지휘하거나 모델 호출을 중계하지도 않는다. 담당 원문을 갱신하면 화면이 열려 있는 동안 30초마다 다시 읽는다. 화면에서 만든 요약을 원문에 다시 쓰지 않는다.

운영 홈 서버가 실행 중일 때 Claude 작업 상태를 공식 CLI로 30초마다 조회하는 구현이 있다. Codex 작업을 30분마다 조회하던 예약 `synk`는 2026-09-21 확인 시 이미 PAUSED였으며 그대로 두었다. 과거 캐시가 있다는 이유로 현재 조회 중이라고 보지 않는다. Gemini를 쓰는 Antigravity CLI는 아래의 상태 전달 기능으로 연결한다. 채널 성과는 `tools/채널성과.js`가 쌓는 기록의 요약([채널 성과](마케팅/채널성과.md))을 마케팅 칸에서 읽는다. 매출은 아직 연결하지 않았다. 조회가 실패하거나 자료가 없으면 확인 불가로 표시한다. 파일 수정·응답 종료를 게시·배포·사업 완료로 표시하지 않으며 서버는 모델을 호출하지 않는다.

운영 홈은 선택해서 여는 조회 화면이며 공식 작업 화면을 대신하지 않는다. 유지·확장은 실제 사용 효용이 있을 때만 한다. 새 모델 선택·업데이트는 각 공식 제품의 설정과 실제 제공 상태를 따른다. 제품 API의 모델과 과금 계약은 담당 코드에서 관리한다.

### 실행 환경

#### Antigravity 작업 상태

공식 [statusLine](https://antigravity.google/docs/cli/statusline/) 기능은 상태가 바뀔 때마다 `tools/operations-home/antigravity-status.js`에 메타데이터를 보내고, 운영 홈이 이를 읽는다. 회사 저장소와 Git에 등록된 작업 사본의 상태만 받는다. 임시로 저장하는 것은 대화 식별자, 작업 폴더, 모델, 작업 상태, 승인 대기, 백그라운드 작업 수, 수신 시각, 그리고 창이 살아 있는지 확인하는 데 쓰는 프로세스 식별값이다. 이메일, 대화 내용, 대화 기록 경로, 인증 정보는 저장하지 않는다. 이 전달 때문에 모델 호출이나 실행 승인이 늘어나지 않는다.

수신기는 이 컴퓨터의 `~/.gemini/antigravity-cli/settings.json`에 있는 `statusLine` 설정으로 실행된다. 기본 상태줄도 함께 표시되고, 수신에 실패해도 작업은 막히지 않는다. 설정을 바꾼 뒤에는 새 Antigravity 명령창을 열어 연결을 확인한다. 화면에는 실제로 받은 모델 이름을 표시할 뿐 모델을 바꾸지 않는다.

명령창이 살아 있는지와 받은 상태를 함께 확인한다. 창이 닫혔거나, 프로세스가 재사용되었거나, 생존 확인에 실패한 경우는 진행 중으로 표시하지 않는다. `idle`은 입력을 기다리는 상태이지 업무 완료가 아니다. 상태를 받지 못했으면 연결 설정이 되어 있는지와 실제로 받았는지를 구분해서 표시한다. Gemini 웹 대화, Antigravity 데스크톱 앱 전체, 비대화 실행은 이 상태줄로 확인하는 범위에 들어가지 않는다.

#### 공식 실행 경로

설치, 로그인, 실제 호출, 업무 품질은 각각 다른 상태다. 현재 환경의 공식 앱, CLI, 커넥터를 확인하고 기존 인증을 다시 쓴다. Codex와 Claude의 기본 작업·서브에이전트·재개 기능을 먼저 쓰고, 특정 하네스의 옛 도구 이름이나 숨은 훅을 공통 규칙으로 삼지 않는다.

Antigravity를 비대화로 실행할 때는 PATH에 있는 `agy`를 먼저 쓴다. Windows에서 찾지 못하면 공식 설치 위치를 확인한 뒤 실제 작업 사본을 넘긴다.

```powershell
$agyCommand = Get-Command agy -ErrorAction SilentlyContinue
$agyBin = if ($agyCommand) { $agyCommand.Source } else { Join-Path $env:LOCALAPPDATA 'agy\bin\agy.exe' }
if (-not (Test-Path -LiteralPath $agyBin)) { throw 'Antigravity CLI를 찾지 못했습니다.' }
& $agyBin --add-dir (Get-Location).Path -p '<구체 목표와 완료 조건>' --output-format json
```

로컬 작업에는 연결된 컴퓨터가 필요하다. 원격 화면 제어와 클라우드 실행은 구분한다. 작업을 이어받게 할 때는 작업 사본, 브랜치, 커밋, 커밋하지 않은 변경 범위, 현재 실행 상태, 시험, 남은 일을 넘긴다. 브라우저와 로컬 프로세스는 다른 하네스로 자동으로 옮겨지지 않는다. 문서만 고쳐 놓고 실행 중인 작업의 권한이나 상태가 바뀌었다고 말하지 않는다.
