# SYNK 작업의 연결 구조

> 현행 구조 · 2026-09-10. 작업 원칙은 [AI 운영 원칙](AI_운영원칙.md), 기존 도구 사용법은 [AI 스택 가이드](AI_스택_가이드.md)에 있다. 날짜별 설치·모델·호출 기록은 현재 인증·연결 상태의 증명이 아니다.

## 책임과 자료의 흐름

사용자 요청 → 주담당 → [업무별 현재 원문](문서_지도.md)의 관련 절·승인 자산 → 제작·독립 작업 → 실제 결과 검증 → 요청된 게시·배포 → [남은 일](_ops/트랙.md).

작업본·제작물·게시물의 최신 확인과 인계는 [운영 원칙](AI_운영원칙.md), 매체별 실물 검증은 [명품 기준](명품_기준_v1.md)을 따른다. 자동 훅·중앙 큐·기억이 대신 확인했다고 가정하지 않는다.

## 연결·중단·재개

### 운영 홈의 확인 범위

[운영 홈](http://127.0.0.1:8790)은 담당 원문과 공식 하네스의 작업 상태를 읽는 로컬 화면이다. 업무 내용의 새 정본·실행 지휘자·모델 중계기가 아니다. 담당 원문을 한 번 갱신하면 화면은 열린 동안 30초마다 다시 읽는다. 생성된 요약을 다시 원문에 쓰지 않는다.

Claude 작업 상태는 공식 CLI로 30초 간격 조회한다. Codex는 이 작업에 연결한 공식 예약으로 30분마다 최근 작업을 조회하며, 45분 넘게 갱신되지 않으면 지연으로 표시한다. Gemini를 쓰는 Antigravity CLI는 아래 공식 상태 전달 기능으로 연결한다. 매출·채널 성과는 아직 연결하지 않았다. 조회가 실패하거나 자료가 없으면 확인 불가로 남기며, 파일 수정·응답 종료를 게시·배포·사업 완료로 바꾸지 않는다. 서버는 모델을 호출하지 않는다. Codex 예약 조회는 기존 구독의 사용량을 쓴다.

새 업무는 기존 공식 하네스에서 수행한다. 운영 홈은 특정 모델판을 고정하거나 제공자 기능을 공통 규격으로 축소하지 않는다. 새 모델의 선택·자동 업데이트 여부는 각 공식 제품의 설정과 실제 제공 상태를 따른다. 기존 제품 API의 모델·과금 계약은 담당 코드에서 유지한다.

### 실행 환경

#### Antigravity 작업 상태

공식 [statusLine](https://antigravity.google/docs/cli/statusline/)이 상태 변경 때 `tools/operations-home/antigravity-status.js`에 전달하는 메타데이터를 운영 홈에서 읽는다. 회사 저장소와 Git에 등록된 작업 사본만 받으며, 대화 식별자·작업 폴더·모델·작업 상태·승인 대기·배경 작업 수·수신 시각과 창 생존 확인용 프로세스 식별값을 임시 저장한다. 이메일·대화 내용·대화 기록 경로·인증 정보는 저장하지 않는다. 이 전달은 모델 호출이나 실행 승인을 추가하지 않는다.

이 기계의 `~/.gemini/antigravity-cli/settings.json`에 있는 `statusLine` 설정이 수신기를 실행한다. 기본 상태줄을 함께 유지하며, 수신 실패가 작업을 차단하지 않는다. 설정 변경 후 새 Antigravity 명령창에서 연결을 확인한다. 화면에는 실제 받은 모델 이름을 표시하며 모델을 바꾸지 않는다.

명령창이 살아 있는지와 받은 상태를 함께 확인한다. 창 종료·프로세스 재사용·생존 확인 실패는 현재 진행으로 표시하지 않으며, `idle`은 입력 대기이지 업무 완료가 아니다. 상태 수신이 없으면 연결 설정과 실제 수신을 구분해서 표시한다. Gemini 웹 대화·Antigravity 데스크톱 전체·비대화 실행은 이 상태줄의 확인 범위에 포함하지 않는다.

#### 공식 실행 통로

설치·로그인·실제 호출·업무 품질은 다른 상태다. 현재 환경의 공식 앱·CLI·커넥터를 확인하고 기존 인증을 재사용한다. Codex·Claude의 네이티브 작업·서브에이전트·재개를 우선하며 특정 하네스의 옛 도구 이름이나 숨은 훅을 공통 계약으로 두지 않는다.

Antigravity 비대화 실행은 PATH의 `agy`를 우선하고, Windows에서 없으면 공식 설치 위치를 확인한 뒤 실제 작업 사본을 전달한다.

```powershell
$agyCommand = Get-Command agy -ErrorAction SilentlyContinue
$agyBin = if ($agyCommand) { $agyCommand.Source } else { Join-Path $env:LOCALAPPDATA 'agy\bin\agy.exe' }
if (-not (Test-Path -LiteralPath $agyBin)) { throw 'Antigravity CLI를 찾지 못했습니다.' }
& $agyBin --add-dir (Get-Location).Path -p '<구체 목표와 완료 조건>' --output-format json
```

로컬 작업은 연결된 기계가 필요하며 원격 화면 제어와 클라우드 실행을 구분한다. 재개에는 작업 사본·브랜치·커밋·미커밋 범위·현재 실행 상태·시험·남은 일을 넘긴다. 브라우저·로컬 프로세스가 다른 하네스로 자동 이전되지 않으며, 문서 개정만으로 실행 중인 작업의 권한이나 상태가 바뀌었다고 주장하지 않는다.
