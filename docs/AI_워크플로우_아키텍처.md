>
> **확인 범위:** 지침 적용·로컬 설정·도구 시험은 아래 실행표로 구분한다. 세 모델의 절대 지능 순위, 모든 계정 혜택, 기업 성과는 이번 시험으로 입증하지 않았다. Google은 사용자가 현재 Pro로 정정했고 브라우저 실제 응답을 확인했다. 이후 사용자가 로컬 인증을 마쳤으며, 창을 닫은 뒤 새 Antigravity 실행에서 모델 목록 조회와 비대화 답변을 각각 1/1회 확인했다. 운영은 구독 우선이며, 기존 API까지 전부 구독에 포함된 것은 아니다.

## 1. 왜 Codex를 기본 창구로 선택했나

이번 선택은 “GPT가 Claude보다 더 똑똑하다”는 주장이 아니다. 현재 유호님이 사용하는 Codex에는 작업 공간, 내부 병렬 작업, 브라우저, 파일 제작, 이미지 생성, 연결 도구, 재개·예약 통로가 이미 있다. 이 창구가 판단의 전달만 맡으면 그 기능을 쓰기 전에 별도 지휘 계층이 생긴다.

따라서 **Codex는 조사·설계·제작·검증·통합·납품을 모두 할 수 있는 주담당**으로 바꿨다. 어려운 판단을 혼자 독점하지 않고 Claude에 목적·원본·완료 조건을 넘겨 깊게 다루게 한다. Gemini에는 관찰 자료와 출처를 맡긴다. 기본 기능을 복제하는 새 중앙 지휘 프로그램은 만들지 않았다. Codex의 작업·병렬 에이전트·외부 도구·예약은 공식 지원 범위에서 활용한다. [Codex 기능](https://learn.chatgpt.com/docs/features), [병렬 에이전트](https://learn.chatgpt.com/docs/agent-configuration/subagents)

Claude Code도 직접 시작한 작업의 주담당이 될 수 있다. 이 경우 Claude가 통합까지 맡고, 설치된 공식 Codex 플러그인으로 구현·검증을 연결한다. **주담당은 하나, 사용할 능력은 셋**이다. 사용자가 다른 창에 내용을 복사하는 절차는 기본 흐름에 없다.

권장 배치가 모델의 능력 제한은 아니다. GPT도 어려운 설계를 하고 Claude도 코드를 만들며 Gemini도 구현할 수 있다. 차이는 “누가 못 하느냐”가 아니라 “이 작업에서 어디에 추가 판단을 쓰면 가장 이득인가”다.

## 2. 전체 구조

```text
유호님 요청
   ↓
현재 주담당 — 기본 Codex / Claude에서 직접 시작하면 Claude
   ├─ 목표·완료 증거·정본 확인
   ├─ 직접 수행 + 필요한 독립 작업만 병렬 분업
   │    ├─ Claude: 깊은 설계·철학·브랜드·반론
   │    ├─ GPT/Codex: 구현·시험·계산·앱/파일·통합
   │    └─ Gemini/Antigravity: 조사·원본 관찰·Google·언어 대조
   ├─ 실제 산출물·출처·시험 결과 대조
   └─ 통합 → 실제 사용/반영 확인 → 결과·남은 일 보고

공통 기반: 철학 / 제품 방향 / 엔진 설계 / 브랜드 토큰 / 자산 원본 / 결정
작업 조율: 각 제품의 기본 작업·재개·분리 작업 사본·예약 기능
학생 서비스: 기존 서버 API·데이터 계약·운영 비용 정책 (별도 층)
```

원본은 저장소에 둔다. 모델마다 철학·자산·기억을 통째로 복제하지 않는다. 모델이 바뀌어도 회사의 판단 근거와 산출물이 남는다. 기본 문서는 짧게, 세부 자료는 해당 업무에서 필요한 부분만 읽는다.

## 3. 세 제품의 강점을 실제 업무에 배치

아래는 이번 회사 제작에 관련된 주요 능력의 활용 지도다. 모든 판매 기능을 무조건 활성화했다는 뜻은 아니다. 계정·지역·제품 화면·도구 연결 여부를 확인한 기능만 실행한다.

| 능력 | 우선 사용할 자리 | 연결·확인 방법 |
|---|---|---|
| 복잡하고 애매한 문제의 긴 판단 | Claude: 기업·제품·교육·브랜드 설계 | 목표·관련 원본·완료 기준을 전달. 고정된 사고 순서를 강요하지 않음 |
| 실행을 동반한 긴 작업 | 현재 주담당 Codex 또는 Claude | 파일·도구·시험·재개를 같은 작업 안에서 연결 |
| 병렬 탐색·구현·독립 검토 | 각 하네스의 기본 서브에이전트 | 독립 범위를 나누고 결과를 기다려 통합. 모든 일이 A/B 대상은 아님 |
| 코드·수치·데이터 변환 | Codex | 실행 가능한 시험, 계산 재현, 결과 파일과 원본 대조 |
| 깊은 조사·많은 출처 대조 | Gemini의 조사 기능 + 주담당 원문 확인 | 링크·발행일·사건일·근거 구간을 함께 받음 |
| 긴 문서·이미지·영상·음성의 관찰 | 해당 입력을 받는 Gemini 제품 | 페이지·장면·시각·관찰과 해석을 분리. CLI가 앱의 모든 입력을 지원한다고 가정하지 않음 |
| Google 문서·Drive·Notebook 계열 자료 | 실제 연결된 Gemini/Google 기능 | 공개 검색 대신 연결된 원문 사용. 권한이 없으면 없는 것으로 표시 |
| 브랜드 문장·철학의 경험화 | Claude + SYNK 브랜드/철학 정본 | 추상적 칭찬이 아니라 학생에게 보이는 문장·행동·마무리로 번역 |
| 몽골어·다국어 의미 대조 | Gemini와 별도 검토 | 원문·역번역·어색한 구간 제시. 모델 동의가 원어민 검증을 뜻하지 않음 |
| 이미지·영상·문서 제작 | 현재 사용 가능한 생성 도구·전문 스킬 | 승인 자산·토큰·실물 렌더를 연결. 생성 버튼 성공이 납품 성공은 아님 |
| 브라우저·업무 앱 조작 | 현재 연결된 주담당의 도구 | 기존 로그인 재사용, 저장 후 재조회. 도구마다 접근 가능한 표면이 다르며 Windows 조작 스킬은 터미널·인증 화면 자동 조작을 허용하지 않음 |
| 기억·압축·재개 | 각 하네스 기본 기능 + 저장소 정본 | 기억은 탐색 단서. 실제 결정·파일을 다시 대조. 별도 기억 복제기 없음 |
| 반복 업무·상태 추적 | 기본 예약·작업 기능 | 목적·일정이 있는 요청만 예약. 변화 없으면 조용히, 의미 있는 변화만 알림 |
| 다른 서비스 연결 | 설치된 스킬·MCP·플러그인 | 필요한 연결만 사용. 모든 플러그인 설치나 모든 계정 권한 부여는 하지 않음 |

Claude 공식 문서는 Fable 5.1을 긴 자율 작업·애매한 문제 조사에 맞는 모델로 소개한다. 그러나 계정에 따라 usage credits(별도 사용 크레딧)가 필요하며, 비대화 호출은 별도 동의창 없이 소비할 수 있다고 명시한다. 따라서 “Max이므로 최상위 호출이 전부 추가 비용 없다”고 가정하지 않았다. 이번 실제 독립 검토는 Max 인증을 확인한 **Opus 5**로 수행했다. 타사보다 무조건 지능이 높다는 비교 시험은 하지 않았다. [Claude 모델 설정·과금 주의](https://code.claude.com/docs/en/model-config)

Google의 현행 구독 안내는 Gemini 앱, Deep Think, Spark, Flow, Gemini Notebook, Google 앱, Jules, Antigravity 등 서로 다른 제품의 혜택을 소개한다. 이 기능들은 하나의 CLI 명령으로 전부 호출되는 묶음이 아니다. 업무에 맞는 제품 표면을 사용한다. [Google AI 구독](https://gemini.google/subscriptions/)

이번 실제 Google 운영 기준은 **Pro**다(사용자 09-09 정정). 위의 전체 제품 지도에서 Ultra 전용 기능·한도는 현재 사용 가능으로 세지 않는다. Ultra는 사용자가 준비되었다고 알릴 때 계정의 실제 지원·포함량을 확인해 반영한다. 구조를 새로 만들거나 미리 상향 결제하지 않는다.

## 4. 9월 9일 기준 놓치면 안 되는 변경

### 개인 Google 구독의 명령 실행 통로는 Antigravity

오래된 Gemini CLI 안내를 그대로 따라가면 개인 Pro·Ultra 로그인 경로에서 막힌다. Google의 2026-09-02 갱신 공지는 2026-06-18부터 해당 개인 로그인 요청을 중단하고 Antigravity로 이전하도록 명시한다. 이번에는 공식 설치 스크립트를 읽고 **Antigravity CLI 1.1.27**을 설치했다. 기존 명령 별칭과 PATH(명령 탐색 경로)는 바꾸지 않았다. [Google 공식 종료 공지](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals), [Antigravity 설치](https://antigravity.google/docs/cli/install/)

설치 경로:

```text
C:\Users\q1212\AppData\Local\agy\bin\agy.exe
```

개인 구독의 실제 연결은 이 도구의 공식 Google 로그인으로 한다. 기존 제품 API 코드나 Gemini 서버용 키를 이 로그인으로 치환하지 않는다. 비대화 호출은 저장된 인증을 재사용하지만 인증이 없으면 실패한다. 성공 판정은 종료 코드뿐 아니라 응답 내용·상태·도구 거절까지 확인한다. [Antigravity 비대화 실행](https://antigravity.google/docs/cli/headless)

09-09 후속 확인: 사용자가 표시된 로컬 창에서 최초 설정을 진행하고 창을 닫았다. 그 뒤 `agy models`가 종료 코드 0으로 모델 목록을 반환했고, 새 `agy -p` 실행이 추가 로그인 없이 `status: SUCCESS`, `response: SYNK_AUTH_OK`, `num_turns: 1`을 반환했다. 따라서 최초 로컬 인증과 저장된 인증 재사용은 확인됐다. 이 한 줄 시험은 실제 조사·파일 수정·도구 권한·구독 잔량까지 검증한 것은 아니다. 명령은 PATH에 등록하지 않았으므로 위 실행 파일의 전체 경로를 사용한다.

### 모델·추론 수준을 오래된 프로젝트 파일로 고정하지 않음

Codex 설정은 일반적으로 명령줄, 신뢰된 프로젝트 설정, 사용자 설정 등 우선순위가 있다. 프로젝트의 오래된 값이 앱에서 고른 기대와 충돌할 수 있으므로 현재 파일을 확인했다. 작업 중 다른 세션에서 프로젝트의 오래된 추론 수준 덮어쓰기를 제거했고, 현재 프로젝트 파일은 Exa 연결만 남아 있다. 이를 이번 작업이 삭제한 것으로 집계하지 않았다. [Codex 설정 우선순위](https://learn.chatgpt.com/docs/config-file/config-basic)

앞서 질문한 Ultra의 경우 설정에서 “표시할 수준”을 체크한 것과 현재 작업이 그 수준으로 실행되는 것은 다르다. 모델의 지원 여부와 실제 작업 설정을 함께 봐야 한다. 이번 작업은 화면 체크만으로 Ultra 실행을 확정하지 않았고, 계정의 최상위 설정을 임의로 바꾸지도 않았다. 오래된 상주 모델 목록과 역할 제한을 없애는 데 집중했다.

### 구독과 API 비용은 다른 층

유호님이 개인 구독으로 회사를 만드는 업무와, 학생들이 호출하는 제품 서버는 다르다. 개인 구독의 포함량·한도와 API 사용료는 구분한다. 구독이 소진되었다고 자동으로 새 유료 API·크레딧 구매·자동충전을 붙이지 않는다. Claude는 개인 구독 인증을 다른 사용자를 위한 중계 서버로 쓰는 방식도 제한한다. [OpenAI 가격·사용량](https://learn.chatgpt.com/docs/pricing), [Claude 사용 조건](https://code.claude.com/docs/en/legal-and-compliance)

**현재 전체가 구독만으로 돌아가는 것은 아니다.** 추가 청구가 실제 발생했다는 뜻이 아니라, 구독과 별도인 기존 호출 경로가 코드에 남아 있다는 뜻이다. 이번 점검에서는 아래 API를 실행하거나 과금 설정을 바꾸지 않았다.

| 구분 | 확인한 통로 | 비용 판단 |
|---|---|---|
| 회사 제작의 기본 통로 | Codex·Claude Code·Antigravity 공식 계정 로그인 | 실제 플랜 포함량 우선. 모든 모델·기능·사용량이 무제한인 것은 아님 |
| 기존 조사·검수 | `tools/몽골어대조.js`, `tools/codex-review.js`, `tools/lib/제미나이호출.js` | Gemini API 경로가 남아 있고 `tools/모델정책.js`의 기본 용도는 Vertex 경로인 `돈`. 개인 구독 호출로 계산하지 않음 |
| 기존 이미지·영상·음악 제작 | `tools/lib/이미지굽기.js`, `tools/옷GPT굽기.js`, `tools/홍보영상굽기.js`, `tools/홍보음악굽기.js` | Vertex·OpenAI 등의 API 사용료/크레딧과 별도 서비스 혜택 확인 필요. 로컬 영상 조립·일부 로컬 음성 추론과 구분 |
| 학생 운영 서비스·외부 제작 서비스 | `엔진_두뇌.js`, `엔진_콘텐츠AI.js`, Higgsfield 등 | 서버 AI 호출·인프라·외부 서비스는 세 LLM의 개인 구독과 별개 |

### 항상 현재 근거로 조사하고, 발전한 기본 기능을 활용

후속 요청을 반영해 저장소 `GEMINI.md`, 개인 `~/.gemini/GEMINI.md`, 공통 `docs/AI_운영원칙.md`에 최신 조사 기준을 적용했다. 조사 시점의 날짜를 기준으로 실제 검색·1차 원문 확인·최신 수정/폐기/후속 문서 대조를 수행하고 발표일·사건일·효력일을 나눈다. 검색 요약·학습지식만으로 최신이라고 말하지 않으며 접근이 안 되면 최신 확인 불가와 남은 범위를 밝힌다. 과거 날짜를 지정한 요청만 그 시점을 따른다. 다른 모델에 조사를 맡길 때도 같은 기준을 전달한다.

회사 철학·자산·완료 조건은 유지하되 사고 순서·도구 선택·옛 모델 버전을 고정하지 않는다. 현재 공식 기능·계정 지원·구독 포함 여부를 확인하고 네이티브 업데이트를 활용한다. 대표 실제 작업의 산출물·오류·소요 시간으로 개선을 확인하며, 최신 모델이면 언제나 품질이 오른다고 보장하지 않는다. 이를 위한 새 훅·상시 감시·별도 스케줄러는 추가하지 않았다.

## 5. 회사 철학·엔진·자산을 하네스에 입힌 방식

모델 지침 세 개가 공통 운영 원칙 한 파일로 연결된다. 그 파일이 작업별 정본을 안내한다. 값과 자산을 지침 안에 재작성하지 않았으므로 변경 때 여러 사본이 갈라질 위험을 줄였다.

| 회사의 자산 | 실제 연결 | 업무에서 쓰는 방식 |
|---|---|---|
| 철학 | `docs/SYNK_철학.md`, `docs/제품방향.md` | 새로운 기능·문장·경험이 누구에게 어떤 변화를 만드는지 판단 |
| 엔진 7종 | `docs/엔진7종_상향설계_v3.md` §0·관련 절 | Core(Atlas), Loom, Vellum, Trail, Prism, Temper, Reed의 해당 설계·계약·실행 증거를 연결 |
| 마스코트 원본 | `docs/디자인_토큰.json` → `tools/lib/마스코트자산.js` | 현재 정본 경로를 가져와 사용. 임의 새 마스코트로 대체하지 않음 |
| 브랜드·시각 | `DESIGN.md`, 토큰, `synk-design` | 색·서체·재질·공식 자산과 승인된 실물 기준 |
| 학생 접점 말투 | `synk-brand` → `synk-content` | 기능 설명·숙제·퀴즈·DM·영상 문장을 같은 목소리로 연결 |
| 명품 품질 | `docs/명품_기준_v1.md` | 기능뿐 아니라 실제 읽힘·보임·사용·마무리를 확인 |
| 회사별 브랜딩 | `docs/명품브랜딩_v2.md`, `docs/명품마케팅_회사별_v1.md` | 회사별 고객·약속·표현을 구분하고 승인 소개서·로고와 대조 |
| 결정·지속 작업 | `docs/_ops/결정.md`, `docs/_ops/트랙.md` | 결정과 AI 추천을 구분하고, 현재 작업의 결과·잔여 상태로 재개 |

엔진 설계도는 “이미 전부 구현됨”의 증거가 아니다. 이번 변경은 **회사를 만드는 AI의 운영층**이다. 학생 서비스의 데이터 스키마·채점·모델 API·엔진 실행 코드를 바꾸거나 배포하지 않았다. 엔진 업무가 들어오면 설계 → 저장 → 실제 소비 → 사용자 경험의 연결을 확인한다.

철학 전체를 모든 질문에 주입하거나 모든 작업 앞에 검문을 세우지는 않는다. 대신 중요한 판단을 할 때 필요한 근거를 읽고 결과물에 반영한다. 명품 기준은 추가 승인 단계가 아니라 실물의 완성도를 판단하는 기준으로 사용한다.

## 6. 실제 작업은 이렇게 돌아간다

다음은 복합 작업의 예시다. 필요한 역할만 사용하며, 단순 작업은 주담당이 직접 완료한다. 아래 순서가 모든 요청에 세 모델을 강제하는 관문은 아니다.

### A. 기업 소개·브랜딩·마스코트 산출물

1. 주담당이 사용 목적·대상·완성 형식과 브랜드 정본을 확인한다. 빠진 사소한 값은 합리적으로 정한다.
2. Claude가 철학을 고객에게 보이는 약속·서사·문장으로 구체화한다. 큰 대외 확정본만 독립 접근을 비교한다.
3. GPT가 실제 문서·웹·슬라이드·영상 제작을 진행한다. Gemini가 필요하면 경쟁 자료·장면·다국어 의미를 확인한다.
4. 승인 마스코트·토큰·서체를 사용했는지, 실제 크기와 화면에서 읽히는지 직접 확인하고 수정한다.
5. 요청한 형식과 파일을 남기고, 발행이 요청에 포함되어 있으면 해당 범위로 반영·재확인한다.

### B. 엔진 기능·앱 개발

1. 해당 엔진 설계·계약·현재 코드·관련 시험을 읽는다.
2. 복잡한 구조 선택이면 Claude가 설계·실패 가능성을 판단하고 GPT가 구현 가능성을 독립 대조한다.
3. 독립 구현은 기본 병렬 작업과 분리 작업 사본을 사용한다. 같은 파일은 수정 소유자를 나눈다.
4. 관련 시험, 실제 입력부터 저장·엔진 소비까지, 실패 때의 사용자 경험을 검증한다.
5. 주담당이 자신의 변경만 통합·커밋·push한다. 배포가 요청 범위에 있을 때 기존 배포 스킬로 반영을 확인한다.

간단한 버그 수정에 설계자·검토자 세 명을 자동으로 붙이지 않는다. 반대로 중요한 데이터 변경을 “테스트가 초록”이라는 이유만으로 충분하다고 보지도 않는다.

### C. 교육 콘텐츠·몽골어·시장 조사

1. 현재 제공 범위·교육 목표·말투 기준을 정본에서 읽는다.
2. Gemini가 넓은 자료와 원본 근거를 정리하고, Claude가 교육적 의미와 문장 경험을 만든다.
3. GPT가 구조화·파일화·계산·중복·형식·앱 연결을 검증한다.
4. 중요한 최신 사실은 원문을 독립 확인하고, 몽골어는 의미 대조와 아직 검증하지 못한 부분을 분리한다.
5. 근거 없는 합격 보장·수치·상품 약속을 확정 문안에 넣지 않는다.

### D. 장시간·반복 운영

목적과 일정이 정해진 반복 요청은 하네스의 기본 예약 기능에 넣는다. 실행 결과와 후속 요청은 원래 작업에서 이어받는다. 변동이 없으면 알림을 늘리지 않고 완료·실패·사용자 행동이 필요한 때만 알린다.

이번 요청에는 반복할 구체 업무와 일정이 없으므로 임의의 매일 작업·상시 감시를 만들지 않았다. **예약 통로 사용 원칙을 적용한 것과 예약이 실제 실행 중인 것은 다르다.** 로컬 예약은 컴퓨터와 앱이 켜져 있어야 하며, 클라우드 실행은 로컬 파일에 자동 접근하지 않는다. 상시 가동 서버가 필요해지면 그때 목적·비용·접근 자료를 분리해 설계한다. [Codex 예약 작업](https://learn.chatgpt.com/docs/automations)

## 7. 사용자 개입을 줄이는 운영 방식

- 이미 받은 목표·권한으로 진행할 수 있는 준비·설치·편집·시험·커밋·요청 범위의 배포는 반복 승인받지 않는다.
- 로그인된 브라우저·앱·공식 CLI 인증을 재사용한다. 도구로 가능한 클릭·파일 처리·확인을 사용자에게 떠넘기지 않는다.
- 여러 계정 중 실제 구독 계정을 모르는 경우에는 계정 식별처럼 결과가 달라지는 선택만 묻는다. 다른 작업은 계속 진행한다.
- 본인 인증·CAPTCHA·새 결제·실제 서비스 권한 승인은 없앴다고 약속하지 않는다. 필요한 행동 하나만 안내한다.
- 작업 한도·서비스 장애가 나면 「요청·완료 조건·한 것·남은 것」과 결과 경로를 남기고, 다른 주담당이 인수를 확인한 뒤 통합 책임을 넘긴다.
- 오류 없는 종료 코드, 모델의 “완료했다”는 말, 검토자 동의 수만으로 완료를 선언하지 않는다. 실제 파일·시험·화면·재조회를 확인한다.

이 구조가 지향하는 자동화는 **일반 실행을 스스로 끝내는 것**이다. 어떤 계정·서비스·상황에서도 사람 개입이 영원히 0회라는 보장은 아니다. 하네스 보호 기능을 끄는 것으로 로그인 권한이나 업무 능력이 늘어나지는 않는다.

## 11. 후속 적용 — Claude 기억색인과 세션 최신 상태 (2026-09-09)

### 기억은 보존하고 진입 색인만 줄였다

Claude의 개인 `MEMORY.md`를 **33,696바이트에서 9,956바이트로** 줄였다. 현재 158줄이며 기존 고유 기억 링크 **125/125개**를 보존했다. 기억 낱장은 수정·삭제하지 않았다. 변경 전 색인은 같은 개인 기억 폴더의 `index-archive/2026-09-09-MEMORY.md`에 보관했고, 원본과 보관본의 SHA256 일치를 확인했다. 과거 색인은 현행 지침으로 다시 읽지 않도록 구분했다.

이유는 기억 자동 로딩이 처음 200줄 또는 25KB 중 먼저 도달하는 범위까지만 읽기 때문이다. 줄 수만 적어도 파일이 크면 뒷부분이 잘릴 수 있다. 기억은 찾아갈 지도이고, 현재 작업 완료 여부는 실제 파일·Git·관련 트랙으로 확인한다. [Claude 공식 기억 문서](https://code.claude.com/docs/en/memory)

### 자동화한 범위

`tools/session-freshness.js` 한 개가 현재 커밋, 로컬 기준 커밋, 앞섬·뒤처짐, 추적 파일 차이 수, 공통 지침 작업파일 해시를 짧은 알림으로 만든다. 같은 Git 저장소의 작업 사본만 대상으로 삼고 다른 저장소에서는 출력하지 않는다. 파일명·커밋 제목·개인 기억·사용자 질문·대화 본문·계정 정보는 알림에 싣지 않는다.

이 도구는 **최신 상태를 알아차리게 하는 연결**이지 자동 병합기가 아니다. 네트워크 조회, 파일 수정, 자동 커밋·push, 상시 감시, 새 AI 호출을 하지 않는다. 외부 Git 필터 실행을 피하고, 조회 실패나 시간 초과가 나도 작업을 차단하지 않는다. Claude/Codex 명령 연결의 제한 시간은 3초이며, 정상 조회는 독립 검토에서 약 0.32초였다. 매 작업 성능을 보장하는 수치는 아니다.

세 모델의 진입 지침과 공통 운영 원칙에는 다음을 반영했다.

- 시작·재개와 중요한 수정 직전에 현재 작업 사본과 기준을 확인한다.
- 다른 세션의 완료 소식을 받으면 관련 파일을 실제로 다시 읽는다.
- 끝낸 일의 기존 트랙 줄과 결과 증거를 그 자리에서 갱신한다. 세션 종료까지 미루지 않는다.
- 자동 알림이 없으면 같은 조회 도구를 직접 실행한다.
- 원격 최신 정보가 필요하면 별도로 fetch 후 비교하고, 다른 작업 사본이나 미커밋 변경을 자동 덮어쓰지 않는다.

이미 끝난 일을 다시 만드는 문제는 「알림 → 관련 파일·트랙 재확인 → 완료 증거 확인」으로 줄인다. AI의 지침 준수를 100% 보장하거나 모든 실행 중 대화에 즉시 기억을 방송하는 시스템이라고 주장하지 않는다. 당시 점검한 나머지 작업 사본 10/10개가 기준보다 44~913커밋 뒤에 있었으며, 일부는 고유 작업도 있어 그대로 보존했다.
