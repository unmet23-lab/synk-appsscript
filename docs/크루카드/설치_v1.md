# 크루카드 웹앱 — 설치·배포 절차 v1 (2026-08-04)

> 정본 코드 = repo `crewcard/` 4파일 · 회귀 = `tests/크루카드.test.js`
> 이 웹앱은 **메인 Apps Script와 완전 분리**된 별도 프로젝트다(메인 doPost는 상담AI 점유 + HtmlService 전역 노출 리스크 — `상담AI.js` doGet 머리말 참조).

## 무엇이 되나
- **한 장의 HTML이 3개 입구를 겸한다**: ①현장 태블릿(로컬 파일) ②원격 링크(구글폼 대체) ③몽골어판(`?lang=mn`)
- 제출 → 상담 스프레드시트 `crew_cards` 탭에 1행(182컬럼) + **Serial `SL-YYYYMMDD-NNN` 자동 채번** 회신
- 방어: 허니팟(hp)·일일 300건 상한·본문 100KB·셀 2,000자·락 채번·doGet 무부작용

## 유호님 클릭 절차 (최초 1회 · 약 10분)

### STEP 1 — 프로젝트 만들기
1. 브라우저에서 `script.new` 접속 (Apps Script 새 프로젝트)
2. 왼쪽 위 「제목 없는 프로젝트」 클릭 → **`SYNK 크루카드`** 로 이름 변경

### STEP 2 — 파일 4개 넣기
> 파일이 커서(HTML 각 200KB) 복붙이 힘들면, 이 단계는 제가 clasp로 대신할 수 있습니다(승인만 주시면 됨).
1. 기본 `Code.gs` 내용 전체 지우고 → repo `crewcard/크루카드.js` 내용 붙여넣기
2. 왼쪽 「파일 +」 → **HTML** → 이름 `카드_kr` → 내용에 `crewcard/카드_kr.html` 붙여넣기
3. 같은 방법으로 `카드_mn` ← `crewcard/카드_mn.html`
4. 왼쪽 톱니(프로젝트 설정) → 「appsscript.json 매니페스트 표시」 체크 → `appsscript.json`을 repo `crewcard/appsscript.json` 내용으로 교체

### STEP 3 — 웹앱 배포
1. 오른쪽 위 「배포」 → 「새 배포」 → 톱니에서 **웹 앱** 선택
2. 설명: `crewcard v1` / 실행 계정: **나** / 액세스 권한: **모든 사용자**
3. 「배포」 → 권한 승인(스프레드시트 접근) → **웹 앱 URL 복사** (`https://script.google.com/macros/s/…/exec`)

### STEP 4 — 카드에 전송 주소 박기
- `카드_kr`·`카드_mn` 두 HTML의 아래 줄을 찾아 URL을 붙여넣는다 (파일당 1곳):
  ```
  window.SYNK_ENDPOINT = window.SYNK_ENDPOINT || '';
  ```
  → `|| ''` 의 따옴표 안에 STEP 3의 URL 붙여넣기 → 저장 → 「배포」→「배포 관리」→ 연필 → 버전 「새 버전」→ 배포
- (repo 쪽 두 벌도 같은 값으로 — 저에게 URL만 주시면 4벌 전부 제가 반영합니다. 테스트가 두 벌 불일치를 기계로 잡습니다.)

### STEP 5 — 동작 확인 (2분)
1. 웹 앱 URL 접속 → 한국어 카드가 뜨는지 / `URL?lang=mn` → 몽골어 카드
2. 몽골어 카드 07페이지 「Таны K.」의 **Таны**가 세리프(Cormorant)로 보이는지 육안 1회 ← 코드 검증은 끝났고 자형만 남음
3. 이름·연락처·개인정보 동의 채우고 「제출하기」 → 화면에 `SL-…` 번호가 뜨면 성공
4. 상담 스프레드시트에 `crew_cards` 탭이 생기고 1행 들어왔는지 확인

## 운영 메모
- **입구 배포**: 원격 접수는 웹 앱 URL을 그대로 공유(페이스북 DM·홈페이지 버튼). 현장 태블릿은 같은 URL을 북마크 — 로컬 파일도 되지만 URL 한 벌 운영이 단순하다.
- **응답 유실 방어**: 카드가 모든 응답을 기기(localStorage)에 자동저장한다 — 전송 실패해도 새로고침해도 남아 있고, 다시 「제출」만 누르면 된다.
- **Serial**: 시트가 정본(같은 날짜 최대값+1, 행 삭제에도 역행 없음). 제출 전 카드에 보이는 번호는 임시 표시고, 제출 응답의 번호가 진짜다.
- **재제출**: 같은 사람이 다시 제출하면 새 행이 쌓인다(v1 정책). 상담사가 최신 행 기준으로 본다.
- 한도 조정: `크루카드.js` 상단 `DAILY_CAP`(기본 300).
