## 운영 메모
- **입구 배포**: 원격 접수는 접수 주소를 그대로 공유(페이스북·홈페이지 버튼). 현장 태블릿도 같은 주소 북마크 — URL 한 벌 운영이 단순하다.
- ⛔**HTML 파일 사본을 접수 입구로 쓰지 않는다** (2026-08-04 유호님 확정·바탕화면 사본 폐기). 사본은 카드가 바뀌어도 **조용히 낡는다** — 실제로 바탕화면 2장이 05:24 판에 멈춰 있었고, 그 판은 9분 뒤 [v9.160]이 고친 **「제출 버튼이 아예 안 먹던」** 상태였다(`</script>` 조기 종료로 스크립트 전체 사망). 사본은 「눈으로 훑어보기」 전용이고, 접수는 라이브 주소 한 벌뿐이다.
  - 바탕화면엔 `.url` 바로가기 2개만 둔다 — `SYNK 크루카드 · 접수 (한국어).url` / `· 접수 (Монгол).url`(`?lang=mn`). 바로가기는 라이브를 가리키므로 낡지 않는다.
- **응답 유실 방어**: 모든 응답이 기기(localStorage) 자동저장 — 전송 실패·새로고침에도 남고, 「제출」만 다시 누르면 된다.
- **Serial**: 시트가 정본(같은 날짜 최대값+1). 제출 응답의 번호가 진짜다.
- **재제출**: **제출은 여러 번, 사람은 한 행** — [v9.168]·[v9.169]로 확정(아래 「남은 결정」 해소). 동일인 키 = 이름(공백 제거) + 연락처(숫자만·`+976`/`00` 정규화). 미착수 행만 덮고, 착수 이후(상담완료·반배정·앱편입·보류·취소)는 한 칸도 안 덮는다.
- **코드 수정 시**: repo `crewcard/`에서 고치고 테스트 통과 후 `clasp push --force` → `clasp deploy --deploymentId AKfycbzzrNG2L1RUX93BN9pUHtrBM0q2cWucLtvD2smQsLz6mj9WPgoqn7xtq4oyFfMg-6ZLhQ` (같은 ID = 같은 URL 유지). 새 배포를 새로 만들면 접수 주소가 갈라진다 — 금지.
- 한도: `크루카드.js` `DAILY_CAP`(기본 300). 남용 시 새 배포로 URL 교체가 대응 절차.
