03 / SEE THE DIFFERENCE

설정을 바꾸면, 도움이 달라져요.

현재 공통 Atlas 코드를 이 파일 안에서 직접 실행해요. 편지 연습에서 도움을 바꾸는 작은 사례입니다.

어떤 도움이 편한가요?

지금 시간이 얼마나 있나요?

복원 모의 체험에서는 도움 방식만 이어지고, 지금의 여유 시간은 기본으로 돌아와요.

SHARED ATLAS CODE · LOCAL DEMONSTRATION

    이 체험의 범위: 실제 공통 판단 코드와 선호 복원 변환을 사용하지만, 서버·로그인·실제 계정 저장에는 연결하지 않아요. 정식 앱 화면도 아니에요. 파일을 닫으면 체험 상태가 초기화됩니다. 전체 장기 기억이 완성됐다는 시연으로 보지 마세요.

    현재 로컬에 구현한 연결

    다음에도 내 도움 방식으로

    1. 사용자가 편지 연습에서 도움 방식을 고릅니다.
    2. 서버가 계정·현재 동의를 확인하고, 선택한 방식만 저장합니다.
    3. 다음 실행에서 읽어 기존 Atlas 판단에 넣습니다.
    4. 점검을 한 항목씩 보여 주거나 먼저 혼자 쓰도록 바뀝니다.
    5. 사용자가 바꾸거나 기본 안내로 돌아갈 수 있습니다.

    관련 로컬 시험 336개 통과 기록. 배포용 검사 일부·실제 DB 동시성·두 실기기 검증은 남아 있습니다.

    앞으로 만들 목표 경험

    내가 가꾼 정원을 알아보는 주민

    1. 게임이 내가 실제로 심고 가꾼 사실을 확인합니다.
    2. Trail이 시간·기여·누가 아는 사실인지 이어 줍니다.
    3. Core는 선호와 한국어 수준에 맞는 도움을 고릅니다. Strata는 연습할 표현의 지도를 제공합니다.
    4. Vellum이 근거 있는 말을 준비하고 Loom·Reed가 행동과 소리로 표현합니다.
    5. Temper가 전달과 이후 반응을 확인합니다. Prism의 집계 활용은 허용 조건과 충분한 자료를 갖춘 뒤입니다.

    설계 사례예요. 16인 마을·NPC 장기 관계·실제 물건 사용까지 구현됐다는 뜻은 아닙니다.

    04 / WHAT TO BUILD NEXT

    다음 개발을 고르는 순서

    모든 엔진을 한꺼번에 완성하기보다, 작은 경험을 끝까지 연결하면서 공통 능력을 키워요.

    FIRST · 기존 앱의 공통 기반

    기억이 정말 이어지는지

    1. 첫 선호 기억의 배포 검사를 마치고 리허설 서버에 연결합니다.
    2. 두 기기에서 저장·복원·정정·동시 수정·로그아웃을 확인합니다.
    3. 기존 앱에 SYNK 홈·공통 계정·내 기록·콘텐츠 입구를 마련합니다.

    바로 다음 기술 작업은 첫 기억의 실제 왕복 확인이에요. 이번 지도 제작에서는 배포하지 않았어요.

    NEXT · 실제 두 콘텐츠 연결

    기억이 도움이 되는지

    1. 두 번째 콘텐츠에서 같은 설정을 다시 하지 않아도 되게 합니다.
    2. 안내·힌트·난도가 실제로 더 잘 맞는지 확인합니다.
    3. Strata의 첫 학습지도를 만들고 학습 근거를 연결합니다.

    계정이 같다는 이유만으로 모든 기록을 자동 공유하지 않아요.

    THEN · 검증된 경험 확장

    다음 콘텐츠도 나를 알도록

    1. 효용이 확인된 기억만 사용자가 허용한 범위로 확장합니다.
    2. PC 게임과 설치·업데이트 관리가 늘면 전용 런처를 붙입니다.
    3. 자체 상점과 큰 커뮤니티는 실제 필요에 맞춰 확장합니다.

    사용자가 승인한 플랫폼 3단계에 따른 순서예요. 런처가 첫 기억 연결의 선행 조건은 아니에요.

    개발 방식: 원하는 경험을 정하기 → 담당 Atlas 엔진과 기존 능력 확인 → 필요한 공통 능력 발전 → 게임·앱에 연결 → 실제 경험 확인 → 다음 콘텐츠에서 재사용.

    Atlas와 게임 엔진은 어떻게 달라요?

    Atlas는 누구에게 어떤 도움과 경험을 줄지 연결해요. Unity·Unreal은 3D 공간, 빛, 물리, 기기 실행을 맡아요. Loom의 장면 표현 기술이 있어도 고품질 3D 월드 전체가 자동 완성되는 것은 아니에요.

    Trail과 Strata는 왜 따로 있나요?

    Trail은 ‘이 사람이 어떤 길을 걸었나’, Strata는 ‘배울 내용이 어떻게 이어지나’를 맡아요. 내 학습 이력과 한국어 지도의 내용은 서로 다른 자료예요.

    Prism과 Temper는 왜 따로 있나요?

    Prism은 여러 사례에서 출발점을 제안하고, Temper는 제공한 도움이 이후 결과와 어떻게 연결됐는지 확인해요. 제안하는 역할과 검증하는 역할을 구분해요.

    매번 AI를 호출하나요?

    현재 Atlas 공통 판단 코드는 모델을 호출하지 않아요. 선택·기록·기본 반응은 일반 로직으로 처리할 수 있어요. 생성형 대화가 필요한 곳은 별도로 호출하므로, 기능별 비용과 제한을 설계해야 해요.

    기억을 오래 쌓으면 저절로 좋아지나요?

    오래된 정보보다 현재의 목표와 정정이 중요해요. 관측한 사실과 추정, 사용자가 직접 말한 것을 구분하고, 오래된 상황은 다시 확인해야 해요. 실제 도움 개선은 따로 측정해야 합니다.

    기본값 복귀와 삭제는 같나요?

    첫 선호 기억의 ‘기본 안내로 되돌리기’는 이전 선택을 다음 판단에 쓰지 않는 기능이에요. 원본 학습 장부 전체를 물리적으로 지우는 기능은 아니며, 전체 기억 관리·삭제는 후속 범위예요.

    05 / EVIDENCE & READING GUIDE

    어디까지 확인한 지도인가요?

    현재 저장소의 설계·코드·소비처와 기존 시험·배포 기록을 읽어 정리했습니다. ‘배포 기록이 있다’는 말은 과거 기록의 확인이며, 오늘 실제 서버와 사용자 계정을 모두 다시 점검했다는 뜻은 아닙니다. 신규 기능의 준비 상태와 기존 운영 기능을 구분해 읽어 주세요.

    표현의 뜻
    • 설계 준비: 역할과 만들 방법이 문서에 있음.
    • 코드 확인: 실제 구현을 읽었음. 배포 여부는 별도.
    • 연결 확인: 화면·서버·도구에서 해당 기능을 호출하는 경로가 있음.
    • 배포 기록: 특정 버전·환경의 배포 또는 QA 기록이 있음.
    • 미확인: 증거가 없어 완료 여부를 단정하지 않음.
    현재 기준 문서와 작성 범위

      이 파일은 2026-09-21의 설명용 스냅샷입니다. 제품 코드와 자동으로 동기화되지 않습니다. 변경 후에는 근거를 다시 대조해 갱신해야 합니다.

      각 엔진의 ‘확인한 근거’에서 파일과 해당 부분을 볼 수 있어요. 이 컴퓨터의 원본 경로를 연결했으므로 다른 컴퓨터에서는 링크가 열리지 않을 수 있지만, 지도 설명과 체험은 인터넷 없이 동작합니다.
