## 1. 3종 — 역할은 배타적이다

| | 서체 | 담당 문자 | 기본 웨이트 | 라이선스 |
|---|---|---|---|---|
| **TF·01 · KR** | **SUIT Variable** | 한글 **전용** | 본문 500 · 헤드/워드마크 800 | OFL · sun-typeface · 2021 |
| **TF·02 · EN** | **Inter Tight** | 라틴 + **키릴(몽골어)** | 본문 500 · 헤드 700 | OFL |
| **TF·03 · MONO** | **DM Mono** | 시스템 라벨 · 코드 · 판번호 | **500**(글리프) · **300**(슬래시) | OFL |

🔑 **워드마크는 이 표가 정하지 않는다** (2026-08-18 · 구 「TF·03 담당 = 워드마크」 삭제).
로고 워드마크의 서체·웨이트·자간은 **`docs/발표물/_브랜드킷.md` §3 도형 정본**을 따른다
(v2 = Inter Tight `700` / 자간 `−4`). 이 줄이 없던 동안 정본 둘이 서로 다른 말을 했고 —
여기는 「워드마크 = DM Mono(모노스페이스)」, 실물 로고는 그로테스크 — **실물이 규칙보다 뒤에
나왔으므로 로고가 이긴다**가 판정이었는데 2주간 이 줄만 안 고쳐져 있었다.

역할 분리의 근거 — SUIT는 한국어 UI 본문용으로 만들어진 기하학적 산세리프(모던·지적, Pretendard의 대안), Inter Tight는 tight tracking과 낮은 x-height로 SUIT와 나란히 섰을 때 같은 결을 만든다. DM Mono는 격자 위에 자란 서체라 "SYNK는 구조를 다루는 서비스"를 폰트 하나로 전달한다.

## 2. 폰트 스택 — 순서가 3언어를 자동 분기시킨다

```css
--synk-font:      'Inter Tight','SUIT Variable',system-ui,-apple-system,'Apple SD Gothic Neo','Malgun Gothic',sans-serif;
--synk-font-mono: 'DM Mono',ui-monospace,SFMono-Regular,Consolas,monospace;
```

**Inter Tight를 SUIT보다 앞에 둔다.** 브라우저 폰트 폴백은 문자(글리프) 단위로 동작한다 — 앞 폰트에 그 글자가 없으면 다음 폰트로 넘어간다. 따라서 한 문장에 3언어가 섞여도:

- `Сайн байна уу` → Inter Tight (키릴 보유)
- `SYNK LAB` → Inter Tight (라틴 보유)
- `안녕하세요` → Inter Tight에 한글이 없음 → **SUIT Variable**

즉 **CSS 한 줄로 유호님의 역할 분리가 자동 실현된다.** 순서를 뒤집어 SUIT를 앞에 두면 SUIT가 가진 라틴 자형이 먼저 잡혀 Inter Tight가 영영 안 쓰인다 — **순서를 바꾸지 말 것.**

**트래킹 — 산세리프는 조이고, 모노는 벌린다.** 부호가 반대라는 게 핵심이다.

| | 트래킹 |
|---|---|
| 본문(SUIT·Inter Tight) | **`-0.02em`** |
| 헤드·태그라인 | **`-0.04em`** (Inter Tight 지정 범위 -.02 ~ -.05em) |
| **DM Mono 라벨(짧은 것)** | **`+0.02em`** |
| **DM Mono 라벨** | **`+0.02em` ~ `+0.24em`** — 짧은 대문자 라벨일수록 크게 벌린다 |

DM Mono에 산세리프의 음수 트래킹을 그대로 쓰면 격자 느낌이 뭉개진다. **모노는 글자 사이가 벌어져야 "구조를 다루는 서비스"로 읽힌다.**

### 몽골어 광학 보정 — 같은 pt로 짜면 몽골어가 작아 보인다

실측(2026-08-01): **Inter Tight 소문자 높이 = SUIT 한글 높이의 0.679배.** 몽골어는 `Өнөөдөр`처럼 첫 글자만 대문자이고 나머지는 소문자라, 소문자 높이가 곧 체감 크기다. 한글과 **같은 `font-size`로 나란히 두면 몽골어만 위축돼 보인다.**

**규칙 — 몽골어가 한국어와 대등하거나 주인공인 자리에서는 몽골어에 1.04배를 준다.**

```css
--synk-mn-scale: 1.04;   /* 한글과 동등 병기 시 몽골어 span에만 */
.mn { font-size: calc(1em * var(--synk-mn-scale)); }
```

- **적용** — 캐러셀 1장(몽골어가 주인공), 앱 UI의 몽골어 라벨·버튼, 3언어 혼합 한 줄, 교재 학습 지시문.
- **미적용** — 몽골어를 각주 위치로 의도적으로 줄이는 자리(디자인 컨셉 정본 §병기 위계 "0.6배·회색"). 이미 작게 쓰는 곳에 보정을 겹치지 않는다.

## 3. 웨이트 — 헤드는 800으로 통일한다

한 요소에는 `font-weight` 하나만 걸리는데 유호님 지정은 헤드가 **SUIT 800 / Inter Tight 700**으로 갈린다. 한글이 섞인 헤드에서 700을 쓰면 SUIT가 지정보다 얇아지므로 **헤드 기본값은 800**으로 잡는다(Inter Tight 800도 지정 웨이트 범위 안이다). **영문·몽골어 전용 헤드에 한해 700 허용.**

| 자리 | weight |
|---|---|
| **태그라인** | **SUIT 900** / Inter Tight 500 (§3-1) |
| 헤드·워드마크 | **800** (영문/몽골어 전용 헤드는 700 허용) |
| 강조·라벨 | 600 |
| 본문·UI 기본 | **500** |
| 캡션·보조(몽골어 병기 등) | 400 |

### 3-1. 태그라인은 헤드와 다른 층이다 (유호님 확정)

> **"3언어로 각각의 자연스러운 어투로 존재한다. 한국어는 SUIT 900의 무게로 격조를, 영어는 Inter Tight 500의 소문자 침착함으로, 몽골어는 같은 뼈대의 키릴로 이어진다. 셋은 번역이 아니라 형제다."**

| 언어 | 서체·웨이트 | 조판 |
|---|---|---|
| 한국어 | **SUIT 900**(Heavy) | 헤드(800)보다 **한 단계 위**. 태그라인에만 쓰는 최대 무게 |
| 영어 | **Inter Tight 500** | **소문자**로 짠다(대문자·전대문자 금지) — 무게로 세우지 않고 침착함으로 세운다 |
| 몽골어 | Inter Tight 500 | 영어와 같은 뼈대. §2 광학 보정 1.04배 적용 |

**한국어만 900으로 올리고 영어·몽골어는 500에 두는 것이 의도다** — 셋을 같은 무게로 맞추면 형제가 아니라 번역문이 된다. 카피도 마찬가지로 **번역하지 않는다**(각 언어에서 따로 쓴다 — 디자인 컨셉 정본 §언어 규칙 「번역 금지」와 같은 원칙).

SUIT는 가변 폰트(100~900)라 9웨이트 전부 파일 하나로 커버된다 — 웨이트를 늘려도 로드 비용이 늘지 않는다.

## 4. 금칙 — 어기면 글자가 깨진다

1. **DM Mono에 몽골어·한글을 절대 넣지 않는다.** DM Mono의 실제 서브셋은 `latin` · `latin-ext` **뿐**이다(2026-08-01 google/fonts METADATA.pb 실검증). 키릴·한글 글리프가 아예 없어 몽골어를 넣으면 통째로 다른 폰트로 폴백돼 워드마크가 무너진다. → **DM Mono는 로마자·숫자·기호에만.**
2. **DM Mono를 본문에 쓰지 않는다**(유호님 확정). 시스템 라벨·코드·판번호 전용 — **로고 워드마크는 위 🔑 대로 이 서체가 아니다.**
3. **Pretendard · Noto Sans KR · KoPubWorld돋움을 새로 쓰지 않는다.** 구 지정 폐기.
4. 3종 밖의 폰트를 추가하지 않는다. 위계는 폰트 수가 아니라 **웨이트·크기**로 만든다. — **유일한 예외 = §4-1.**

### 4-1. 유일한 예외 — Part 06 K-Culture 예약 서체 (유호님 2026-08-05 확정)

크루카드 **Part 06 「당신의 K.」/「Таны K.」 면**은 **일부러 다른 서체를 쓰는 특별면**이다. 금칙 4의 유일한 예외이고, **그 면 밖으로 나가면 그대로 위반**이다.

| 서체 | 담당 | 쓰이는 곳 |

| **Fraunces** | 라틴 에디토리얼 이탤릭 "K." | kr · mn 공통 |
| **Gowun Batang** | 한글 명조 헤드라인 「당신의」 | kr 주 · mn 폴백 |
| **Cormorant** | 몽골 키릴 헤드라인 「Таны」(Ө·Ү) | mn 전용 |

**쓰는 통로는 CSS 변수 둘뿐이다** — `--kc-serif`(라틴) · `--kc-serif-head`(헤드라인). 흩어진 6곳이 각자 스택을 적던 것을 이 둘로 좁혔다. 통로를 벗어나면 기계가 막는다:

- `tools/브랜드렌더린트.js` — `.kc-page`·`.kc-card` 조상 밖에서 렌더되면 「키트 밖 서체」로 센다.
- `tests/브랜드폰트.test.js` — `--kc-*` 선언 안에서만 화이트리스트를 통과시킨다.

> 🔴 **이 조항이 왜 있는가** — 2026-08-05 에 이 세 서체가 **금칙 4를 근거로 통째로 지워졌다**(91e7963 → 3d6aac2 로 복원). 지운 쪽이 틀린 게 아니다. 예약이 **카드 파일 주석에만** 살아 있었고 정본에는 예외가 없어서, **정본을 성실히 따를수록 지우게 되는 상태**였다. 주석은 정본이 아니다 — **예외는 예외를 적은 곳에서만 살아남는다.**

## 5. 몽골 키릴 — 왜 Inter Tight인가 (2026-08-01 실측)

「SUIT와 결이 맞는 몽골어 서체」를 별도로 찾아봤고, **결론은 Inter Tight 유지**다. 근거 3겹:

**① SUIT에는 키릴이 아예 없다.** 브라우저 글리프 실측 결과 SUIT Variable은 기본 키릴 `А`조차 없다. 몽골어를 SUIT로 쓰는 선택지는 존재하지 않는다 — 반드시 별도 서체가 필요하다.

**② 후보 중 광학적으로 SUIT에 가장 가깝다.** 같은 100px 기준 실측:

| 후보 | 대문자/한글 높이 | **소문자/한글 높이** | 몽골어 단어 폭 |
|---|---|---|---|
| **Inter Tight** ✅ | **0.901** | **0.679** (최대) | **412** (최소) |
| Manrope | 0.889 | 0.667 | 437 |
| Golos Text | 0.864 | 0.654 | 442 |
| Geologica | 0.864 | 0.617 | 463 |

몽골어는 `Өнөөдөр`처럼 첫 글자만 대문자라 **소문자 높이가 곧 체감 크기**다. Inter Tight가 가장 크고(한글에 가장 근접) 동시에 가장 좁아, 폭이 한정된 Glide 카드에서 줄바꿈이 가장 적다.

**③ 몽골 현지가 실제로 쓰는 계열이다.** 주요 서비스 사이트 CSS 직접 실측:

| 사이트 | 성격 | 실사용 서체 |
|---|---|---|
| Khan Bank | 최대 은행 | Segoe UI + **Inter** |
| Storepay | BNPL·Framer 디자인 주도 | **TT Hoves**(유료) · Gilroy · Inter |
| Unitel | 통신 대기업 | Roboto · Open Sans · **Manrope** |
| Toki | 슈퍼앱(마케팅 페이지) | Roboto |

몽골 프리미엄 브랜드는 **TT Hoves·Gilroy 같은 유료 키릴 그로테스크**를 쓰고, 무료권의 사실상 표준은 **Inter 계열**이다. Inter Tight는 Inter의 공식 자매 패밀리이므로 현지 친숙도를 그대로 가져간다.

> **판정** — 유료 키릴(TT Hoves급)로 올라가는 선택지는 **기각**한다. 비용이 들고, SUIT와 결이 맞는다는 보장도 없으며(위 ② 수치를 다시 재야 한다), 무엇보다 SYNK의 무기는 서체 구매력이 아니다. **현지 프리미엄과 같은 급의 완성도는 폰트값이 아니라 조판 규율(§2 광학 보정 1.04배 + §3 웨이트 통일)에서 나온다.**

### ⚠ "키릴 지원"이라도 몽골어가 깨지는 폰트가 있다

몽골 키릴은 러시아 키릴에 **`Өө`·`Үү` 두 글자가 추가**된 체계다. 이 둘이 없으면 몽골어에서만 글자가 폴백돼 깨진다. 실측에서 실제로 걸러진 것:

| 서체 | 기본 키릴 | `ө` `ү` | 판정 |
|---|---|---|---|
| Onest | 있음 | **없음** | ❌ 몽골어 실격(러시아어는 가능) |
| Wix Madefor Text | 있음 | **없음** | ❌ 몽골어 실격 |
| Inter Tight · Manrope · Golos Text · Geologica | 있음 | 있음 | ✅ |

**새 서체를 검토할 땐 "Cyrillic 지원"을 믿지 말고 `ө`·`ү`를 직접 찍어본다.** 검사 도구 = `docs/tools/_mn_font_probe.html` (브라우저로 열면 후보별 글리프 유무와 SUIT 대비 광학 비교가 나온다).

   - ⚠ **웨이트마다 파일을 따로 올려야 한다 — 가변 폰트는 한 웨이트로만 잡힌다.** 실측: Inter Tight 가변 `.ttf` 1개를 올렸더니 Canva가 「Inter Tight Regular」 **단일 스타일**로만 읽었다(SUIT·DM Mono는 static 파일이라 웨이트별로 정상 인식). 그 상태로는 영문 헤드 700이 **synthetic bold**(자형을 억지로 두껍게)로 떨어진다.

### 가변 폰트에서 웨이트별 static 파일 뽑기 (Inter Tight 해법)

`google/fonts`에는 Inter Tight의 static이 없고, fontsource의 woff2는 **서브셋이 쪼개져 있어 몽골 키릴이 빠진다.** 정답은 가변 원본에서 직접 인스턴스를 뽑는 것이다:

```bash
python -m pip install fonttools brotli
python -m fontTools.varLib.instancer --update-name-table "InterTight-Variable.ttf" wght=500 -o "InterTight-Medium.ttf"
```

🔴 **`--update-name-table`을 빠뜨리면 안 된다.** 이 옵션이 없으면 웨이트 축만 고정되고 **폰트 내부 이름표는 원본 그대로 남는다.** 실제로 처음에 빠뜨렸더니 Canva에 4개가 전부 **「Inter Tight Regular」라는 같은 이름**으로 올라가, 굵기는 다른데 목록에서 구분이 불가능했다(전량 삭제 후 재작업). 옵션을 주면 `Inter Tight / Medium / SemiBold / Bold`로 이름이 붙고 **Canva가 한 패밀리 아래 4스타일로 묶는다.**

2026-08-01 실행 결과 — 400·500·600·700 4개 생성, **전부 2504 글리프로 가변 원본과 동일**하고 `U+04E8/04E9 Өө` · `U+04AE/04AF Үү`가 모두 보존됨을 `getBestCmap()`으로 검증했다. 이름표도 `name` 테이블에서 직접 확인했다. **새 웨이트가 필요하면 이 방법을 쓴다 — 서브셋 woff2를 받아오면 몽골어가 조용히 사라진다.**

> 참고 — 400/700은 `family=Inter Tight` + `sub=Regular/Bold`로, 500/600은 `family=Inter Tight Medium/SemiBold`로 붙는다. 이는 오류가 아니라 폰트 표준(RIBBI)이다 — 한 패밀리에는 Regular·Bold·Italic·BoldItalic 4스타일만 들어갈 수 있어 나머지 웨이트는 별도 패밀리명을 갖는다. Canva는 이를 알아서 묶어준다.
2. **기본 폰트로 대체**(Pro가 아닐 때의 차선). Inter Tight → **`Inter`**(같은 설계자·같은 골격이라 결이 거의 유지된다, 트래킹만 `-0.02em`). DM Mono → Canva에 없으므로 다른 모노스페이스. **한글은 대안이 없다** — SUIT를 대신할 폰트가 카탈로그에 없으므로, 한글이 들어가는 디자인은 Canva 밖에서 만들거나 Pro로 올라가야 한다.

✅ **Inter Tight static 4종 업로드 완료**(2026-08-01) — 이제 Canva에 **3패밀리 12스타일**이 있다: `Inter Tight`(Regular·Medium·SemiBold·Bold) · `SUIT`(400·500·600·800·900) · `DM Mono`(Light·Regular·Medium). 영문·몽골어 헤드가 synthetic bold를 벗어났다.

**로컬 파일 업로드 우회법** — 브라우저 파일 업로드 도구는 로컬 경로를 전부 거부한다(Desktop·스크래치패드·폴더 승인 후에도). 해결: **CORS 허용 로컬 HTTP 서버 + 페이지 컨텍스트에서 fetch → File → `input.files` 주입.**

```bash
# 폰트 폴더에서
node -e "const http=require('http'),fs=require('fs'),p=require('path');http.createServer((q,s)=>{const f=decodeURIComponent(q.url.replace(/^\//,''));s.setHeader('Access-Control-Allow-Origin','*');try{const b=fs.readFileSync(p.join(process.cwd(),f));s.writeHead(200,{'Content-Type':'font/ttf'});s.end(b)}catch(e){s.writeHead(404);s.end()}}).listen(8901)"
```

```js
// Canva 업로드 모달을 연 상태에서 페이지 컨텍스트 실행
const files = [];
for (const n of ['InterTight-Regular.ttf', /* … */]) {
  const b = await (await fetch('http://localhost:8901/' + n)).blob();
  files.push(new File([b], n, {type:'font/ttf'}));
}
const dt = new DataTransfer(); files.forEach(f => dt.items.add(f));
const input = document.querySelector('input[type=file]');
input.files = dt.files;
input.dispatchEvent(new Event('change', {bubbles:true}));
```

`http://localhost`는 브라우저가 신뢰 출처로 취급해 HTTPS 페이지에서도 mixed content로 막히지 않는다. **끝나면 서버를 반드시 내린다.**

⚠ **색은 이 문서 소관이 아니다.** 브랜드 색 정본은 현재 **킷 23색**(v10 Crew Dossier 19 + 06 Slate 2 + 07 Lime Family 2 — 개정 이력은 `docs/디자인_컨셉_정본_v1.md`)이고 Canva 브랜드 키트(`kAHO4v46jZ4`)에 입력돼 있다(⏳07 Lime Family 스와치 1개 미등록). **색 hex의 기계 판독 원천은 `docs/디자인_토큰.json` 하나다**(v1.8에서 단일화 — 구 원천 `_archive/브랜드_색상키트_원본_…html`은 기록 보관용, 인용 금지). 팔레트 도구 `docs/tools/synk_palette.html`은 사람이 보는 화면으로만 쓴다.

## 7. 로드 경로 (2026-08-01 실검증)

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/sun-typeface/SUIT@2/fonts/variable/woff2/SUIT-Variable.css">
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter+Tight:wght@300..800&family=DM+Mono:wght@300;400;500&display=swap">
```

- SUIT CDN은 `font-family:'SUIT Variable'`, `font-weight:100 900` 단일 woff2(200KB 미만)로 응답하는 것을 확인했다.
- Inter Tight는 `cyrillic` · `cyrillic-ext` 서브셋을 포함한다(실검증) — 몽골어 `ө` `ү` 안전.

**CDN을 못 쓰는 자리** — 「SYNK 집필 규범」 부록 발표물 프롬프트의 자기완결 HTML, 아티팩트(CSP가 외부 호스트 차단), 인쇄 조판. 이 경우 **폰트 파일을 로컬 임베드하거나 폴백 스택으로 내려간다.** CDN 실패 시 한글은 시스템 고딕, 라틴은 system-ui로 떨어지므로 레이아웃은 유지되고 결만 약해진다 — 치명적이지 않다.

### 🔴 스택 이름만 바꾸면 아무 일도 일어나지 않는다

**`CARD_FONT`의 값을 3종 스택으로 바꾸는 것만으로는 브랜드 폰트가 적용되지 않는다.** 학생 휴대폰에 SUIT·Inter Tight가 설치돼 있을 리 없으므로, 웹폰트를 **로드하지 않으면 전부 폴백**된다(한글은 시스템 고딕, 라틴은 기기 기본). 에러도 안 나고 화면도 그럴싸해서 **"교체 완료"로 착각하기 딱 좋다.**

구 스택이 이 문제를 안 겪은 건 `Noto Sans KR`이 **안드로이드 기본 한글 폰트**라 우연히 설치돼 있었기 때문이다. 새 3종엔 그런 행운이 없다.

**문제** — `CARD_FONT`는 `'<div style="' + CARD_FONT + …'` 형태로 쓰이는 **style 속성 값**이라, 그 안에 `@import`나 `<link>`를 넣을 수 없다.

**해법** — 로드용 상수를 따로 만들어 카드 앞에 붙인다. `CARD_ANIM`이 이미 `<style>` 블록을 카드에 넣어 라이브에서 작동하므로(v9.43~) 같은 경로가 열려 있다.

```js
const CARD_WEBFONT = '<style>' +
  '@import url("https://cdn.jsdelivr.net/gh/sun-typeface/SUIT@2/fonts/variable/woff2/SUIT-Variable.css");' +
  '@import url("https://fonts.googleapis.com/css2?family=Inter+Tight:wght@300..800&display=swap");' +
  '</style>';
```

붙이는 자리 = `'<div style="' + CARD_FONT` 패턴 **39곳**(2026-08-01 기준, 전부 동일 형태라 일괄 치환 가능). 중첩 카드에서 `@import`가 여러 번 나와도 같은 URL은 브라우저가 한 번만 받으므로 무해하다.

✅ **검증 완료(2026-08-02)** — `<style>` 안의 `@import`가 통과해 웹폰트가 실제로 렌더된다(§8 적용 지도와 같은 근거: 인코딩 바이트 일치 + canvas `measureText` 음성대조 + `cyrillic-ext` 서브셋 다운로드 확인). 막혔을 때의 대안(`@font-face` base64 인라인 — 용량 큼 / Glide 앱 테마 폰트 설정)은 **지금은 불필요**하지만, 로더 경로를 바꿀 때를 대비해 기록으로 남긴다.
