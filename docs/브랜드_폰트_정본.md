# SYNK 브랜드 폰트 정본

> 현행 2026-09-10 정리. 모든 새 산출물의 기본 서체는 SUIT Variable·Inter Tight·DM Mono다. 예외는 §4-1의 지정 면과 §2의 낫표 두 문자에 한정한다. 색·재질은 [DESIGN](../DESIGN.md), 로고는 [현재 승인 로고](로고_중립색_정본_v1.md)를 따른다.

폰트 이름을 적은 것과 실제로 그 폰트가 그려진 것은 다르다. 소스·파일·로드·실제 글리프·최종 출력까지 확인한다.

## 1. 3종 — 역할은 배타적이다

| 서체 | 역할 | 기본 굵기 |
|---|---|---|
| SUIT Variable | 한글 | 본문 500, 헤드 800 |
| Inter Tight | 라틴·키릴·몽골어 | 본문 500, 전용 헤드 700 |
| DM Mono | 시스템 라벨·코드·판번호 등 모노 역할 | 글리프 500, 슬래시 300 |

워드마크의 형태·재질·굵기를 이 표로 재조립하지 않는다. 승인된 로고 파일·완성 조합과 `tools/lib/로고정본.js`가 담당한다.

## 2. 폰트 스택 — 순서와 광학 보정

화면의 본문 스택은 `SYNK Bracket → Inter Tight → SUIT Variable → 시스템 폴백`이다. 실제 CSS는 [디자인 토큰](디자인_토큰.json)의 폰트 값과 [토큰 CSS](tools/synk-tokens.css)를 소비한다.

Inter Tight를 SUIT 앞에 둔다. 글리프별로 라틴·키릴은 Inter Tight, 한글은 SUIT가 맡도록 하는 순서다. SUIT를 앞에 두면 그 안의 라틴 글자가 먼저 선택된다. DM Mono는 별도 모노 역할에만 지정한다.

| 자리 | 자간 |
|---|---|
| 본문 산세리프 | -0.02em |
| 헤드·태그라인 | -0.04em; Inter Tight 지정 범위 -0.02~-0.05em |
| 짧은 DM Mono 라벨 | +0.02em |
| DM Mono 대문자 라벨 | +0.02~+0.24em 범위에서 길이에 맞춤 |

산세리프의 음수 자간을 모노에 그대로 적용하지 않는다.

### 낫표 「 」 — 두 문자만 교정

`SYNK Bracket`은 U+300C·U+300D 두 글리프만 맡는 별칭이다. 넷째 본문 폰트가 아니며 다른 문자로 범위를 넓히지 않는다.

- 화면: 토큰의 `@font-face` 별칭이 OS 한국어 폰트에서 해당 두 글자를 사용한다.
- 인쇄/PDF: [SYNKBracket-Regular.ttf](브랜드_폰트/SYNKBracket/SYNKBracket-Regular.ttf)를 임베드한다. 현재 `docs/tools/브랜드폰트_임베드.py`의 `FACES`에 등록되어 있다.
- 가족 이름을 Inter Tight로 덮어쓰면 본문 폰트까지 대체될 수 있다. 별칭과 두 문자 범위를 유지한다.
- 낫표를 « »로 일괄 치환하지 않는다. 서로 다른 표기의 의미를 보존한다.

### 몽골어 광학 보정

몽골어가 한국어와 동등하거나 주인공인 자리에는 `--synk-mn-scale:1.04`를 사용한다. 몽골어 span에만 적용하고 주변 한글까지 확대하지 않는다.

캐러셀 표지·몽골어 버튼·3언어 혼합 줄·학습 지시문 등 해당 자리에 적용한다. 의도적으로 작은 각주에 보정을 중첩하지 않는다. 몽골어를 언제나 한국어의 작은 각주로 낮추는 규칙은 아니다.

## 3. 웨이트 — 본문·헤드·태그라인을 나눈다

| 자리 | 굵기 |
|---|---|
| 한글이 섞인 헤드 | 800 |
| 영문·몽골어 전용 헤드 | 700 허용 |
| 강조·라벨 | 600 |
| 본문·UI 기본 | 500 |
| 캡션·보조 | 400 |

실제 사용하는 굵기의 파일이나 가변 축이 로드되어 있어야 한다. 합성 볼드나 가까운 굵기로 대체된 화면을 지정 폰트 적용 완료로 세지 않는다.

### 3-1. 태그라인은 헤드와 다른 층

| 언어 | 서체·굵기 | 표현 |
|---|---|---|
| 한국어 | SUIT 900 | 태그라인의 최대 무게 |
| 영어 | Inter Tight 500 | 소문자, 전대문자로 바꾸지 않음 |
| 몽골어 | Inter Tight 500 | 같은 뼈대의 키릴, 1.04배 광학 보정 |

세 언어를 같은 굵기의 직역문으로 맞추지 않는다. 의미를 공유하되 각 독자에게 자연스러운 말과 조판으로 편집한다.

## 4. 금칙과 예외

- DM Mono에 한글·키릴·₮·№를 맡기거나 일반 본문에 사용하지 않는다. 해당 글리프는 Inter Tight·SUIT의 담당으로 나눈다.
- Pretendard·Noto Sans KR·KoPubWorld돋움을 새 본문 서체로 도입하지 않는다. Noto 기반의 낫표 두 문자 조각은 §2의 한정 예외다.
- 분위기를 바꾸려고 새 폰트를 추가하지 않는다. 승인 폰트의 크기·굵기·자간·간격으로 위계를 만든다.
- 시스템 폴백이 그럴듯하게 보인다는 이유로 로드 누락을 통과시키지 않는다.

### 4-1. 유일한 특별면 — Part 06 K-Culture 예약 서체

크루카드 Part 06 ‘당신의 K.’/‘Таны K.’ 면에만 허용한다.

| 서체 | 담당 |
|---|---|
| Fraunces | 라틴 에디토리얼 이탤릭 K. |
| Gowun Batang | 한글 헤드라인 ‘당신의’, 몽골어판의 지정 폴백 |
| Cormorant | 몽골 키릴 헤드라인 ‘Таны’, Ө·Ү 포함 |

통로는 `--kc-serif`·`--kc-serif-head`이며 일반 페이지로 확장하지 않는다. 기본 3종 규칙을 이유로 이 면의 승인 예외를 제거하지도 않는다. 적용 범위는 `tests/크루카드.test.js`·`tests/브랜드폰트.test.js`·`tools/브랜드렌더린트.js`의 현재 규칙과 함께 확인한다.

## 5. 몽골 키릴과 실제 글리프

몽골어는 Inter Tight로 유지한다. ‘Cyrillic 지원’ 표기만 믿지 말고 Өө(U+04E8/04E9), Үү(U+04AE/04AF)를 실제 파일과 최종 화면에서 확인한다. ₮·№·화살표 등 원고의 실제 기호도 함께 검사한다.

부분 woff2를 가져올 때는 필요한 `cyrillic`·`cyrillic-ext`와 기호가 들어 있는지 확인한다. 확장자나 패밀리 이름만으로 전체 글리프 보존을 보장하지 않는다. [몽골어 확인 지면](tools/_mn_font_probe.html)은 비교용이며 새 폰트 도입의 자동 승인 통로가 아니다.

## 6. 원본 파일과 정적 굵기 제작

원본과 라이선스는 [브랜드 폰트 폴더](브랜드_폰트/)에 있다. SUIT의 정적 OTF·가변 woff2, Inter Tight의 정적 TTF, DM Mono TTF, 낫표 조각과 각각의 OFL 원문을 보존한다. 외주·인쇄 전달에는 해당 라이선스를 함께 제공한다. 빌드 입력을 개인 바탕화면이나 계정 업로드 상태에 의존시키지 않는다.

새 정적 굵기가 필요한 경우 가변 원본에서 인스턴스를 만든다. 기존 파일로 충분하면 다시 만들지 않는다.

```text
python -m fontTools.varLib.instancer --update-name-table "InterTight-Variable.ttf" wght=500 -o "InterTight-Medium.ttf"
```

`--update-name-table`을 유지하고 결과의 굵기 축·내부 이름표·cmap을 확인한다. Өө·Үү 등 필요한 글리프가 보존되어야 한다. 모든 정적 굵기가 같은 Regular 이름으로 남거나 부분 서브셋으로 키릴이 빠진 파일을 정상 인수하지 않는다.

## 7. 현재 로드·임베드 통로

| 산출물 | 실제 폰트를 넣는 방식 |
|---|---|
| 자립형 HTML·아티팩트의 SUIT | [브랜드폰트 모듈](../tools/lib/브랜드폰트.js)이 저장소 `SUIT/SUIT-Variable.woff2`를 산출물 안에 임베드 |
| 생성기가 있는 HTML | 생성기가 모듈을 호출하도록 하고 다시 빌드. 출력만 고치면 다음 빌드에서 사라질 수 있음 |
| 손 HTML | `node tools/lib/브랜드폰트.js --심기 <파일.html>`. 원고로 되돌릴 때만 `--원고로` 사용 |
| 네트워크를 허용하는 화면의 Inter Tight·DM Mono | 현재 환경이 허용하는 Google Fonts 또는 로컬 제공 파일. 실제 요청·글리프 확인 |
| 인쇄·PDF | [임베드 도구](tools/브랜드폰트_임베드.py)의 원본 파일·`FACES`로 필요한 글리프를 서브셋해 자립형 출력 생성 |

`font-family`는 로더가 아니다. SUIT를 이름만 적거나 폐기된 CDN 처방으로 호출한 상태를 완료로 보고하지 않는다. 네트워크·콘텐츠 보안 정책·오프라인 조건을 고려해 전달 환경에서 실제 로드가 되는지 본다.

인쇄 원고의 `/*@FONTS@*/`에 임베드 도구가 폰트를 넣는다:

```text
python docs/tools/브랜드폰트_임베드.py <src.html> <out.html> --pdf <out.pdf>
```

현재 인쇄 도구의 정적 SUIT 가족명은 `SUIT`, 웹 가변 파일의 가족명은 `SUIT Variable`이다. 이 이름을 확인 없이 서로 치환하지 않는다. `FACES`가 제공하는 굵기와 실제 원고가 요구하는 굵기를 맞춘다. 낫표 조각도 인쇄 파일에 함께 싣는다.

기존 엔진 카드·접수 폼·측정 지면의 로더 예외는 `tests/지면폰트.test.js`의 현재 제외 사유와 소비 코드를 확인한다. 예외를 새 산출물에 복제하거나, 이 문서 정리를 기존 라이브 카드의 재검수로 세지 않는다.

## 8. 산출물별 확인

- 웹·앱: 실제 한글·몽골어·라틴 문장과 기호, 굵기, 줄바꿈, 작은 글자의 읽힘을 확인한다.
- 자립형 HTML: 파일 안에 필요한 폰트가 있고 전달 환경에서 외부 자원 없이 읽히는지 확인한다.
- 인쇄/PDF: 임베드 폰트와 실제 글자를 연결해 확인한다. 폰트 이름 목록에 존재하는 것만으로 해당 문자를 그렸다고 하지 않는다.
- 영상·SNS: [DESIGN](../DESIGN.md)의 제작 통로에서 현재 폰트를 소비하고 최종 프레임·이미지 크기로 확인한다.

## 9. 기존 검사와 완료 기록

`tests/브랜드폰트.test.js`는 정본·기본 서체·스택·로드 등 현재 코드에 구현된 범위를, `tests/지면폰트.test.js`는 지면의 실제 임베드·외부 호출·예외를 확인한다. Part 06은 크루카드 시험과 렌더 린트로 범위를 확인한다.

검사에 더해 브라우저의 실제 렌더 폰트나 글리프 확인, PDF 임베드와 문자의 연결, 최종 크기의 읽힘을 본다. 필요하면 의도적으로 폴백시킨 비교로 검사가 누락을 구분하는지 확인한다.

결과에는 바꾼 원천·반영한 산출물·검사·실물 확인 범위를 남긴다. 과거의 ‘전파 완료 N건’이나 현재 MD 개정을 모든 웹·앱·PDF의 적용 완료로 보고하지 않는다.
