# SYNK 브랜드 폰트 정본

> **v1 · 2026-08-01 · 유호님 확정** — SYNK가 만드는 **모든** 산출물(앱 카드·웹·발표물·교재·SNS·문서)은 이 3종만 쓴다.
> 구 지정(Pretendard · Noto Sans KR · KoPubWorld돋움)은 **폐기**. 회귀는 `tests/브랜드폰트.test.js`가 기계 차단한다.

## 1. 3종 — 역할은 배타적이다

| | 서체 | 담당 문자 | 기본 웨이트 | 라이선스 |
|---|---|---|---|---|
| **TF·01 · KR** | **SUIT Variable** | 한글 **전용** | 본문 500 · 헤드/워드마크 800 | OFL · sun-typeface · 2021 |
| **TF·02 · EN** | **Inter Tight** | 라틴 + **키릴(몽골어)** | 본문 500 · 헤드 700 | OFL |
| **TF·03 · MONO** | **DM Mono** | 워드마크 · 시스템 라벨 · 코드 | 500 | OFL |

역할 분리의 근거 — SUIT는 한국어 UI 본문용으로 만들어진 기하학적 산세리프(모던·지적, Pretendard의 대안), Inter Tight는 tight tracking과 낮은 x-height로 SUIT와 나란히 섰을 때 같은 결을 만든다. DM Mono는 격자 위에 자란 서체라 "SYNK는 구조를 다루는 서비스"를 폰트 하나로 전달한다.

## 2. 폰트 스택 — 순서가 3언어를 자동 분기시킨다

```css
--synk-font:      'Inter Tight','SUIT Variable',system-ui,-apple-system,'Apple SD Gothic Neo','Malgun Gothic',sans-serif;
--synk-font-mono: 'DM Mono',ui-monospace,SFMono-Regular,Consolas,monospace;
```

**Inter Tight를 SUIT보다 앞에 둔다.** 브라우저 폰트 폴백은 문자(글리프) 단위로 동작한다 — 앞 폰트에 그 글자가 없으면 다음 폰트로 넘어간다. 따라서 한 문장에 3언어가 섞여도:

- `Сайн байна уу` → Inter Tight (키릴 보유)
- `SYNK LAB` → Inter Tight (라틴 보유)
- `안녕하세요` → Inter Tight에 한글이 없음 → **SUIT Variable**

즉 **CSS 한 줄로 유호님의 역할 분리가 자동 실현된다.** 순서를 뒤집어 SUIT를 앞에 두면 SUIT가 가진 라틴 자형이 먼저 잡혀 Inter Tight가 영영 안 쓰인다 — **순서를 바꾸지 말 것.**

**트래킹** — 본문 `-0.02em`, 헤드 `-0.04em`. (Inter Tight 지정 범위 -.02 ~ -.05em, SUIT도 이 구간에서 결이 맞는다.)

### 몽골어 광학 보정 — 같은 pt로 짜면 몽골어가 작아 보인다

실측(2026-08-01): **Inter Tight 소문자 높이 = SUIT 한글 높이의 0.679배.** 몽골어는 `Өнөөдөр`처럼 첫 글자만 대문자이고 나머지는 소문자라, 소문자 높이가 곧 체감 크기다. 한글과 **같은 `font-size`로 나란히 두면 몽골어만 위축돼 보인다.**

**규칙 — 몽골어가 한국어와 대등하거나 주인공인 자리에서는 몽골어에 1.04배를 준다.**

```css
--synk-mn-scale: 1.04;   /* 한글과 동등 병기 시 몽골어 span에만 */
.mn { font-size: calc(1em * var(--synk-mn-scale)); }
```

- **적용** — 캐러셀 1장(몽골어가 주인공), 앱 UI의 몽골어 라벨·버튼, 3언어 혼합 한 줄, 교재 학습 지시문.
- **미적용** — 몽골어를 각주 위치로 의도적으로 줄이는 자리(디자인 컨셉 정본 §병기 위계 "0.6배·회색"). 이미 작게 쓰는 곳에 보정을 겹치지 않는다.

## 3. 웨이트 — 헤드는 800으로 통일한다

한 요소에는 `font-weight` 하나만 걸리는데 유호님 지정은 헤드가 **SUIT 800 / Inter Tight 700**으로 갈린다. 한글이 섞인 헤드에서 700을 쓰면 SUIT가 지정보다 얇아지므로 **헤드 기본값은 800**으로 잡는다(Inter Tight 800도 지정 웨이트 범위 안이다). **영문·몽골어 전용 헤드에 한해 700 허용.**

| 자리 | weight |
|---|---|
| 본문·UI 기본 | **500** |
| 강조·라벨 | 600 |
| 헤드·워드마크 | **800** (영문/몽골어 전용 헤드는 700 허용) |
| 캡션·보조(몽골어 병기 등) | 400 |

SUIT는 가변 폰트(100~900)라 9웨이트 전부 파일 하나로 커버된다 — 웨이트를 늘려도 로드 비용이 늘지 않는다.

## 4. 금칙 — 어기면 글자가 깨진다

1. **DM Mono에 몽골어·한글을 절대 넣지 않는다.** DM Mono의 실제 서브셋은 `latin` · `latin-ext` **뿐**이다(2026-08-01 google/fonts METADATA.pb 실검증). 키릴·한글 글리프가 아예 없어 몽골어를 넣으면 통째로 다른 폰트로 폴백돼 워드마크가 무너진다. → **DM Mono는 로마자·숫자·기호에만.**
2. **DM Mono를 본문에 쓰지 않는다**(유호님 확정). 워드마크·시스템 라벨·코드 전용.
3. **Pretendard · Noto Sans KR · KoPubWorld돋움을 새로 쓰지 않는다.** 구 지정 폐기.
4. 3종 밖의 폰트를 추가하지 않는다. 위계는 폰트 수가 아니라 **웨이트·크기**로 만든다.

## 5. 몽골 키릴 — 왜 Inter Tight인가 (2026-08-01 실측)

「SUIT와 결이 맞는 몽골어 서체」를 별도로 찾아봤고, **결론은 Inter Tight 유지**다. 근거 3겹:

**① SUIT에는 키릴이 아예 없다.** 브라우저 글리프 실측 결과 SUIT Variable은 기본 키릴 `А`조차 없다. 몽골어를 SUIT로 쓰는 선택지는 존재하지 않는다 — 반드시 별도 서체가 필요하다.

**② 후보 중 광학적으로 SUIT에 가장 가깝다.** 같은 100px 기준 실측:

| 후보 | 대문자/한글 높이 | **소문자/한글 높이** | 몽골어 단어 폭 |
|---|---|---|---|
| **Inter Tight** ✅ | **0.901** | **0.679** (최대) | **412** (최소) |
| Manrope | 0.889 | 0.667 | 437 |
| Golos Text | 0.864 | 0.654 | 442 |
| Geologica | 0.864 | 0.617 | 463 |

몽골어는 `Өнөөдөр`처럼 첫 글자만 대문자라 **소문자 높이가 곧 체감 크기**다. Inter Tight가 가장 크고(한글에 가장 근접) 동시에 가장 좁아, 폭이 한정된 Glide 카드에서 줄바꿈이 가장 적다.

**③ 몽골 현지가 실제로 쓰는 계열이다.** 주요 서비스 사이트 CSS 직접 실측:

| 사이트 | 성격 | 실사용 서체 |
|---|---|---|
| Khan Bank | 최대 은행 | Segoe UI + **Inter** |
| Storepay | BNPL·Framer 디자인 주도 | **TT Hoves**(유료) · Gilroy · Inter |
| Unitel | 통신 대기업 | Roboto · Open Sans · **Manrope** |
| Toki | 슈퍼앱(마케팅 페이지) | Roboto |

몽골 프리미엄 브랜드는 **TT Hoves·Gilroy 같은 유료 키릴 그로테스크**를 쓰고, 무료권의 사실상 표준은 **Inter 계열**이다. Inter Tight는 Inter의 공식 자매 패밀리이므로 현지 친숙도를 그대로 가져간다.

> **판정** — 유료 키릴(TT Hoves급)로 올라가는 선택지는 **기각**한다. 비용이 들고, SUIT와 결이 맞는다는 보장도 없으며(위 ② 수치를 다시 재야 한다), 무엇보다 SYNK의 무기는 서체 구매력이 아니다. **현지 프리미엄과 같은 급의 완성도는 폰트값이 아니라 조판 규율(§2 광학 보정 1.04배 + §3 웨이트 통일)에서 나온다.**

### ⚠ "키릴 지원"이라도 몽골어가 깨지는 폰트가 있다

몽골 키릴은 러시아 키릴에 **`Өө`·`Үү` 두 글자가 추가**된 체계다. 이 둘이 없으면 몽골어에서만 글자가 폴백돼 깨진다. 실측에서 실제로 걸러진 것:

| 서체 | 기본 키릴 | `ө` `ү` | 판정 |
|---|---|---|---|
| Onest | 있음 | **없음** | ❌ 몽골어 실격(러시아어는 가능) |
| Wix Madefor Text | 있음 | **없음** | ❌ 몽골어 실격 |
| Inter Tight · Manrope · Golos Text · Geologica | 있음 | 있음 | ✅ |

**새 서체를 검토할 땐 "Cyrillic 지원"을 믿지 말고 `ө`·`ү`를 직접 찍어본다.** 검사 도구 = `docs/tools/_mn_font_probe.html` (브라우저로 열면 후보별 글리프 유무와 SUIT 대비 광학 비교가 나온다).

## 6. Canva 운용

**Canva 기본 폰트 카탈로그에 3종이 있는지는 이 세션에서 확인하지 못했다**(비로그인 접근이 403으로 막힌다). 지어내지 않고 미확인으로 둔다. 확실한 경로는 아래 둘:

**유호님 확정(08-01) = 1번 경로.** 업로드용 파일 7종을 `Desktop\SYNK_브랜드폰트\`에 받아뒀다(SUIT 4웨이트 `.otf` · Inter Tight 가변 `.ttf` · DM Mono 2웨이트 `.ttf` + 각 OFL 원문 + 비개발자용 안내문). ⚠ git 밖이므로 지우면 다시 받아야 한다 — 출처는 아래 §7 CDN과 같은 저장소다.

1. **Brand Kit에 직접 업로드**(권장·Canva Pro 필요). 3종 모두 **OFL**이라 업로드·상업 사용에 법적 문제가 없다. 브랜드 키트 1개당 500개까지 올라간다.
   - ⚠ Canva는 **`.woff2`를 받지 않는다.** `TTF` · `OTF` · `WOFF`로 올려야 한다. SUIT CDN이 주는 건 woff2이므로 **GitHub 저장소의 정적 TTF/OTF**를 받아야 한다.
   - ⚠ 웨이트마다 **파일을 따로** 올려야 한다(가변 폰트 1개로 9웨이트가 안 된다). 실사용 웨이트인 **400·500·600·800** 4개만 올리면 충분하다.
2. **기본 폰트로 대체**(Pro가 아닐 때). Inter Tight가 목록에 없으면 **`Inter`로 대체**한다 — 같은 설계자·같은 골격이라 결이 거의 유지되고, 트래킹만 `-0.02em`로 좁혀주면 된다. SUIT를 대체할 만한 한글 폰트는 Canva 기본에 마땅치 않으므로 **한글이 들어가는 디자인은 업로드 경로를 쓰는 편이 낫다.**

## 7. 로드 경로 (2026-08-01 실검증)

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/sun-typeface/SUIT@2/fonts/variable/woff2/SUIT-Variable.css">
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter+Tight:wght@300..800&family=DM+Mono:wght@300;400;500&display=swap">
```

- SUIT CDN은 `font-family:'SUIT Variable'`, `font-weight:100 900` 단일 woff2(200KB 미만)로 응답하는 것을 확인했다.
- Inter Tight는 `cyrillic` · `cyrillic-ext` 서브셋을 포함한다(실검증) — 몽골어 `ө` `ү` 안전.

**CDN을 못 쓰는 자리** — 「SYNK 발표물 제작 프롬프트」의 자기완결 HTML, 아티팩트(CSP가 외부 호스트 차단), 인쇄 조판. 이 경우 **폰트 파일을 로컬 임베드하거나 폴백 스택으로 내려간다.** CDN 실패 시 한글은 시스템 고딕, 라틴은 system-ui로 떨어지므로 레이아웃은 유지되고 결만 약해진다 — 치명적이지 않다.

### 🔴 스택 이름만 바꾸면 아무 일도 일어나지 않는다

**`CARD_FONT`의 값을 3종 스택으로 바꾸는 것만으로는 브랜드 폰트가 적용되지 않는다.** 학생 휴대폰에 SUIT·Inter Tight가 설치돼 있을 리 없으므로, 웹폰트를 **로드하지 않으면 전부 폴백**된다(한글은 시스템 고딕, 라틴은 기기 기본). 에러도 안 나고 화면도 그럴싸해서 **"교체 완료"로 착각하기 딱 좋다.**

구 스택이 이 문제를 안 겪은 건 `Noto Sans KR`이 **안드로이드 기본 한글 폰트**라 우연히 설치돼 있었기 때문이다. 새 3종엔 그런 행운이 없다.

**문제** — `CARD_FONT`는 `'<div style="' + CARD_FONT + …'` 형태로 쓰이는 **style 속성 값**이라, 그 안에 `@import`나 `<link>`를 넣을 수 없다.

**해법** — 로드용 상수를 따로 만들어 카드 앞에 붙인다. `CARD_ANIM`이 이미 `<style>` 블록을 카드에 넣어 라이브에서 작동하므로(v9.43~) 같은 경로가 열려 있다.

```js
const CARD_WEBFONT = '<style>' +
  '@import url("https://cdn.jsdelivr.net/gh/sun-typeface/SUIT@2/fonts/variable/woff2/SUIT-Variable.css");' +
  '@import url("https://fonts.googleapis.com/css2?family=Inter+Tight:wght@300..800&display=swap");' +
  '</style>';
```

붙이는 자리 = `'<div style="' + CARD_FONT` 패턴 **39곳**(2026-08-01 기준, 전부 동일 형태라 일괄 치환 가능). 중첩 카드에서 `@import`가 여러 번 나와도 같은 URL은 브라우저가 한 번만 받으므로 무해하다.

⚠ **미검증** — Glide Rich Text(WebView)가 `<style>`은 렌더하는 것이 확인돼 있으나, 그 안의 `@import`까지 통과하는지는 **라이브에서 확인하지 않았다**. 배포 후 실제 카드에서 한글 자형이 바뀌었는지 눈으로 확인할 것. 막히면 대안은 `@font-face`를 base64로 인라인(용량 큼) 또는 Glide 앱 테마 폰트 설정.
