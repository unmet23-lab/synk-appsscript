# SYNK 브랜드 폰트 정본

> 2026-10-17 정리. 기본 서체는 SUIT Variable·Inter Tight·DM Mono다. 승인 예외는 §2의 낫표 두 문자와 §4의 지정 범위에서 관리한다. 색·재질은 [DESIGN](../DESIGN.md), 로고는 [현재 승인 로고](로고_중립색_정본_v1.md)를 따른다.

폰트 이름을 적은 것과 실제로 그 폰트가 그려진 것은 다르다. 소스·파일·로드·실제 글리프·최종 출력까지 확인한다.

## 1. 3종 — 역할은 배타적이다

| 서체 | 역할 | 기본 굵기 |
|---|---|---|
| SUIT Variable | 한글 | 본문 500, 헤드 800 |
| Inter Tight | 라틴·키릴·몽골어 | 본문 500, 전용 헤드 700 |
| DM Mono | 시스템 라벨·코드·판번호 등 모노 역할 | 글리프 500, 슬래시 300 |

워드마크의 형태·재질·굵기를 이 표로 재조립하지 않는다. 승인된 로고 파일·완성 조합과 `tools/lib/로고정본.js`가 담당한다.

## 2. 폰트 스택 — 순서와 광학 보정

화면의 본문 스택은 `SYNK Bracket → Inter Tight → SUIT Variable → 시스템 폴백`이다. 실제 CSS는 [디자인 토큰](디자인_토큰.json)의 폰트 값과 [토큰 CSS](tools/synk-tokens.css)를 소비한다.

Inter Tight를 SUIT 앞에 둔다. 글리프별로 라틴·키릴은 Inter Tight, 한글은 SUIT가 맡도록 하는 순서다. SUIT를 앞에 두면 그 안의 라틴 글자가 먼저 선택된다. DM Mono는 별도 모노 역할에만 지정한다.

| 자리 | 자간 |
|---|---|
| 본문 산세리프 | -0.02em |
| 헤드·태그라인 | -0.04em; Inter Tight 지정 범위 -0.02~-0.05em |
| 짧은 DM Mono 라벨 | +0.02em |
| DM Mono 대문자 라벨 | +0.02~+0.24em 범위에서 길이에 맞춤 |

산세리프의 음수 자간을 모노에 그대로 적용하지 않는다.

### 낫표 「 」 — 두 문자만 교정

`SYNK Bracket`은 U+300C·U+300D 두 글리프만 맡는 별칭이다. 넷째 본문 폰트가 아니며 다른 문자로 범위를 넓히지 않는다.

- 화면: 토큰의 `@font-face` 별칭이 OS 한국어 폰트에서 해당 두 글자를 사용한다.
- 인쇄/PDF: [SYNKBracket-Regular.ttf](브랜드_폰트/SYNKBracket/SYNKBracket-Regular.ttf)를 임베드한다. 현재 `docs/tools/브랜드폰트_임베드.py`의 `FACES`에 등록되어 있다.
- 가족 이름을 Inter Tight로 덮어쓰면 본문 폰트까지 대체될 수 있다. 별칭과 두 문자 범위를 유지한다.
- 낫표를 « »로 일괄 치환하지 않는다. 서로 다른 표기의 의미를 보존한다.

### 몽골어 광학 보정

몽골어가 한국어와 동등하거나 주인공인 자리에는 `--synk-mn-scale:1.04`를 사용한다. 몽골어 span에만 적용하고 주변 한글까지 확대하지 않는다.

캐러셀 표지·몽골어 버튼·3언어 혼합 줄·학습 지시문 등 해당 자리에 적용한다. 의도적으로 작은 각주에 보정을 중첩하지 않는다. 몽골어를 언제나 한국어의 작은 각주로 낮추는 규칙은 아니다.

## 3. 웨이트 — 본문·헤드·태그라인을 나눈다

| 자리 | 굵기 |
|---|---|
| 한글이 섞인 헤드 | 800 |
| 영문·몽골어 전용 헤드 | 700 허용 |
| 강조·라벨 | 600 |
| 본문·UI 기본 | 500 |
| 캡션·보조 | 400 |

이 표는 일반 지면의 기본값이다. 최근 승인된 [플랫폼 시그널](디자인/플랫폼_시그널/README.md)과 [WORLD 시그널](디자인/월드_시그널/README.md)은 제목 680·카드 제목 650·강조 600·라벨 550·본문 450 등 각 제품 규격을 따른다. 일반 헤드 800을 이유로 제품의 글자 위계를 되돌리지 않는다. `SYNK Latin`·`World Latin`·`World SUIT`·`World Mono`는 해당 제품에서 기존 서체를 제공하는 별칭이며 새 브랜드 서체가 아니다.

실제 사용하는 굵기의 파일이나 가변 축이 로드되어 있어야 한다. 합성 볼드나 가까운 굵기로 대체된 화면을 지정 폰트 적용 완료로 세지 않는다.

### 3-1. 태그라인은 헤드와 다른 층

| 언어 | 서체·굵기 | 표현 |
|---|---|---|
| 한국어 | SUIT 900 | 태그라인의 최대 무게 |
| 영어 | Inter Tight 500 | 소문자, 전대문자로 바꾸지 않음 |
| 몽골어 | Inter Tight 500 | 같은 뼈대의 키릴, 1.04배 광학 보정 |

세 언어를 같은 굵기의 직역문으로 맞추지 않는다. 의미를 공유하되 각 독자에게 자연스러운 말과 조판으로 편집한다.

## 4. 금칙과 예외

- DM Mono에 한글·키릴·₮·№를 맡기거나 일반 본문에 사용하지 않는다. 해당 글리프는 Inter Tight·SUIT의 담당으로 나눈다.
- Pretendard·Noto Sans KR·KoPubWorld돋움을 새 본문 서체로 도입하지 않는다. Noto 기반의 낫표 두 문자 조각은 §2의 한정 예외다. 판매 지면 문장 속 가상 브랜드 이름의 한자 · 가나만 Noto Sans KR로 떨어지게 두는 글리프 예외는 §10-2(이름 갈래)에 있다.
- 분위기를 바꾸려고 새 폰트를 추가하지 않는다. 승인 폰트의 크기·굵기·자간·간격으로 위계를 만든다. 이 줄과 §1~§3은 SYNK 회사 화면 · 판매 지면의 규칙이다 — 광고 · 포트폴리오 영상 속 가상 브랜드 글자와 판매 썸네일의 큰 글은 [§10](#work-lettering)을 따른다.
- 시스템 폴백이 그럴듯하게 보인다는 이유로 로드 누락을 통과시키지 않는다.

### 4-1. 기존 특별면 — Part 06 K-Culture 예약 서체

크루카드 Part 06 ‘당신의 K.’/‘Таны K.’ 면에만 허용한다.

| 서체 | 담당 |
|---|---|
| Fraunces | 라틴 에디토리얼 이탤릭 K. |
| Gowun Batang | 한글 헤드라인 ‘당신의’, 몽골어판의 지정 폴백 |
| Cormorant | 몽골 키릴 헤드라인 ‘Таны’, Ө·Ү 포함 |

통로는 `--kc-serif`·`--kc-serif-head`이며 일반 페이지로 확장하지 않는다. 기존 승인 산출물의 예외를 보존하는 항목이다. 크루카드 운영 코드와 `tests/크루카드.test.js`는 2026-10-02 옛 학원 시스템 정리에서 제거됐다. 남은 서체 경계는 `tests/브랜드폰트.test.js`·`tools/브랜드렌더린트.js`의 실제 적용 범위에서 확인하며, 삭제된 시험이 현재 검사한다고 안내하지 않는다.

### 4-2. WORLD 이야기 해설

2026-10-15 사용자 요청으로 WORLD 이야기의 해설에만 **Noto Serif KR**를 사용한다. 친구 대사와 UI는 SUIT 계열을 유지한다. 구현은 `experiences/brand-opening/world-ui.css`의 `World Story Serif`, 파일은 `assets/NotoSerifKR-story.woff2`와 같은 이름의 JSON·OFL 기록이다. `tools/build-world-story-font.mjs`가 이야기 글자만 부분 폰트로 만든다. 다른 본문이나 광고로 적용 범위를 넓히지 않는다.

확정·구현·남은 실기기 확인은 [이야기 화면 인계](_ops/WORLD이야기화면_디테일_인계_20261015.md)의 해당 기록에서 확인한다. 이 예외를 문서에 반영한 것이 공개 배포 확인을 뜻하지는 않는다.

### 4-3. PULSE 고객 앱 시사실 판

2026-11-05 유호님이 고객 앱 방향으로 시사실(A)을 고르셨다. 이 앱의 제목과 준제목에만 **Noto Serif KR 300**을 쓰고, 본문 · 단추 · 입력은 SUIT, 숫자 표기는 DM Mono 그대로다. 파일은 `public/pulse-app/assets/NotoSerifKR-300.woff2`(KS X 1001 한글 2,350자 · 영숫자 · 낫표 등 기호, 298KB). 프로젝트 이름처럼 손님 글도 이 글꼴로 그리고, 2,350자 밖 글자는 시스템 명조로 떨어진다. 라틴은 명조가 아니라 SUIT로 그린다(`SX Latin`). 원문은 Windows의 `NotoSerifKR-VF.ttf`이고 OFL이다. 기준은 [시사실 판](디자인/플랫폼_시그널/README.md#pulse-film-20261105).

## 5. 몽골 키릴과 실제 글리프

몽골어는 Inter Tight로 유지한다. ‘Cyrillic 지원’ 표기만 믿지 말고 Өө(U+04E8/04E9), Үү(U+04AE/04AF)를 실제 파일과 최종 화면에서 확인한다. ₮·№·화살표 등 원고의 실제 기호도 함께 검사한다.

부분 woff2를 가져올 때는 필요한 `cyrillic`·`cyrillic-ext`와 기호가 들어 있는지 확인한다. 확장자나 패밀리 이름만으로 전체 글리프 보존을 보장하지 않는다. [몽골어 확인 지면](tools/_mn_font_probe.html)은 비교용이며 새 폰트 도입의 자동 승인 통로가 아니다.

## 6. 원본 파일과 정적 굵기 제작

원본과 라이선스는 [브랜드 폰트 폴더](브랜드_폰트/)에 있다. SUIT의 정적 OTF·가변 woff2, Inter Tight의 정적 TTF, DM Mono TTF, 낫표 조각과 각각의 OFL 원문을 보존한다. 외주·인쇄 전달에는 해당 라이선스를 함께 제공한다. 빌드 입력을 개인 바탕화면이나 계정 업로드 상태에 의존시키지 않는다.

새 정적 굵기가 필요한 경우 가변 원본에서 인스턴스를 만든다. 기존 파일로 충분하면 다시 만들지 않는다.

```text
python -m fontTools.varLib.instancer --update-name-table "InterTight-Variable.ttf" wght=500 -o "InterTight-Medium.ttf"
```

`--update-name-table`을 유지하고 결과의 굵기 축·내부 이름표·cmap을 확인한다. Өө·Үү 등 필요한 글리프가 보존되어야 한다. 모든 정적 굵기가 같은 Regular 이름으로 남거나 부분 서브셋으로 키릴이 빠진 파일을 정상 인수하지 않는다.

## 7. 현재 로드·임베드 통로

| 산출물 | 실제 폰트를 넣는 방식 |
|---|---|
| 자립형 HTML·아티팩트의 SUIT | [브랜드폰트 모듈](../tools/lib/브랜드폰트.js)이 저장소 `SUIT/SUIT-Variable.woff2`를 산출물 안에 임베드 |
| 생성기가 있는 HTML | 생성기가 모듈을 호출하도록 하고 다시 빌드. 출력만 고치면 다음 빌드에서 사라질 수 있음 |
| 손 HTML | `node tools/lib/브랜드폰트.js --심기 <파일.html>`. 원고로 되돌릴 때만 `--원고로` 사용 |
| 폴더째 올리는 공개 웹 페이지의 SUIT(synk.im 도구·PULSE 등) | 정본과 같은 사본을 페이지 옆 `assets/fonts/SUIT-Variable.woff2`에 두고 `<link rel="preload" … as="font" type="font/woff2" crossorigin>` + `@font-face`로 싣는다. `--심기`는 HTML을 830KB 넘게 키워 느린 망의 첫 화면을 늦춘다(10-21 실측 0.7→4.5초, [현장 노트](현장노트/배포_공개.md#synkimsynk-policy)) |
| 네트워크를 허용하는 화면의 Inter Tight·DM Mono | 현재 환경이 허용하는 Google Fonts 또는 로컬 제공 파일. 실제 요청·글리프 확인 |
| 인쇄·PDF | [임베드 도구](tools/브랜드폰트_임베드.py)의 원본 파일·`FACES`로 필요한 글리프를 서브셋해 자립형 출력 생성 |

`font-family`는 로더가 아니다. SUIT를 이름만 적거나 폐기된 CDN 처방으로 호출한 상태를 완료로 보고하지 않는다. 네트워크·콘텐츠 보안 정책·오프라인 조건을 고려해 전달 환경에서 실제 로드가 되는지 본다.

인쇄 원고의 `/*@FONTS@*/`에 임베드 도구가 폰트를 넣는다:

```text
python docs/tools/브랜드폰트_임베드.py <src.html> <out.html> --pdf <out.pdf>
```

현재 인쇄 도구의 정적 SUIT 가족명은 `SUIT`, 웹 가변 파일의 가족명은 `SUIT Variable`이다. 이 이름을 확인 없이 서로 치환하지 않는다. `FACES`가 제공하는 굵기와 실제 원고가 요구하는 굵기를 맞춘다. 낫표 조각도 인쇄 파일에 함께 싣는다.

기존 엔진 카드·접수 폼·측정 지면의 로더 예외는 `tests/지면폰트.test.js`의 현재 제외 사유와 소비 코드를 확인한다. 예외를 새 산출물에 복제하거나, 이 문서 정리를 기존 라이브 카드의 재검수로 세지 않는다.

## 8. 산출물별 확인

- 웹·앱: 실제 한글·몽골어·라틴 문장과 기호, 굵기, 줄바꿈, 작은 글자의 읽힘을 확인한다.
- 자립형 HTML: 파일 안에 필요한 폰트가 있고 전달 환경에서 외부 자원 없이 읽히는지 확인한다.
- 인쇄/PDF: 임베드 폰트와 실제 글자를 연결해 확인한다. 폰트 이름 목록에 존재하는 것만으로 해당 문자를 그렸다고 하지 않는다.
- 영상·SNS: [DESIGN](../DESIGN.md)의 제작 통로에서 현재 폰트를 소비하고 최종 프레임·이미지 크기로 확인한다.

## 9. 기존 검사와 완료 기록

`tests/브랜드폰트.test.js`는 등록된 소비 코드의 기본 서체·스택·로드를, `tests/지면폰트.test.js`는 해당 지면의 임베드·외부 호출·예외를 확인한다. Part 06의 남은 예약 서체는 브랜드 폰트 시험과 렌더 린트가 확인하는 범위다. 두 시험이 WORLD를 포함한 모든 제품의 폰트와 최근 예외까지 전수 검증한다고 해석하지 않는다.

검사에 더해 브라우저의 실제 렌더 폰트나 글리프 확인, PDF 임베드와 문자의 연결, 최종 크기의 읽힘을 본다. 필요하면 의도적으로 폴백시킨 비교로 검사가 누락을 구분하는지 확인한다.

결과에는 바꾼 원천·반영한 산출물·검사·실물 확인 범위를 남긴다. 과거의 ‘전파 완료 N건’이나 현재 MD 개정을 모든 웹·앱·PDF의 적용 완료로 보고하지 않는다.

## 10. 작품 · 광고 · 썸네일의 글자 — 회사 화면 규칙과 나눈다

> 2026-11-08 정리. 유호님이 10-18부터 11-06까지 여러 편에서 되풀이해 짚은 「자막 · 폰트가 AI 슬롭 · 촌스럽다」를 한 곳에 모았다. 그 말씀과 좋다고 하신 판은 크몽 세션 모음에 있고, 근거 결정은 [결정 표](_ops/결정.md) 10-29 「영상 글자 방법」 · 11-05 크몽 썸네일 둘 · 11-06 「강조 글」 · 11-06 「霜の肌理」 · 11-07 「매진 임박 썸네일」 행이다.

### 10-1. 범위

| 자리 | 따르는 규칙 |
|---|---|
| SYNK 회사 화면 · 판매 지면(사이트 · 앱 · 크몽 메인 · 상세 · 소개서 · 썸네일의 분류 줄 · 고지 칩) | §1~§4 그대로. 판매 지면 큰 제목은 승인된 크몽 메인 값 SUIT 700 · 자간 −.035em · 낱말 하나만 색(11-03 「너무 좋아」) |
| 광고 · 포트폴리오 · SNS 편의 영상 위 글자, 가상 브랜드 로고 · 라벨, 판매 썸네일의 큰 글 | 이 절. 회사 화면의 「헤드 800」을 작품 안으로 끌고 오지 않는다. 새 글꼴은 이름 · 강조 글 갈래의 원고(그 편 로고 · 라벨)에만 쓴다 — 말자막 · 정보 정리는 10-2에 적은 글꼴 그대로 |

### 10-2. 글자 네 갈래 — 갈래마다 만드는 법이 다르다

| 갈래 | 무엇 | 만드는 법 | 하지 않는 것 |
|---|---|---|---|
| 말자막 | 대사 · 내레이션을 받아 적은 글 | 아래 어두운 상자에 한 화면 한 문장, 핵심 낱말 하나만 색(11-03 「세 편에 넣기」 판). 얼굴 · 제품을 덮지 않는다 — 드라마는 [드라마 장면 정본](디자인/드라마_장면/README.md). 글꼴은 한글 SUIT · 라틴 · 키릴 Inter Tight, 감성 편은 명조 + 가는 고딕(10-29 — 값은 [10번 C4](마케팅/PULSE_포트폴리오_제작준비_20261012/video/자막시안_20261103/remotion/src/p10/P10.tsx): Noto Serif KR 500 · 44px + 자간 넓은 영문 대문자 22px, 그림 안 아래, 글자 뒤 넓고 옅은 타원 어둠 32%, 숫자는 SUIT, 11-08 「C4로 가」). 통로는 HTML 조판 → 크롬 투명 PNG(10-29) 또는 크몽 세 편을 구운 [Remotion 자막](마케팅/PULSE_포트폴리오_제작준비_20261012/video/자막시안_20261103/remotion/)이고, 가림은 점검표 5번 가림검사로 잰다 | 흰 굵은 글자 + 검은 테 · 그림자, 석 줄 이상 빽빽한 자막 |
| 강조 글 | 제품 옆 · 끝 카피, 장면 뒤 큰 낱말, 「번쩍」 같은 소리말 | 그 편 콘셉트의 그림 언어로 만든다 — 장면 안 실재 물건 · 재질 CG(전광판 · 도장 · 병 · 빛), 또는 직접 그린 글자 + 박에 맞춘 움직임 · 소리 한 방. 실제 장면 위 시안 둘 이상을 먼저 보인다. 못 그리면 글을 빼고 말로 한다 — [슬롭 점검표 24번](마케팅/제작양식/광고영상_슬롭점검표.md) | 글꼴로 친 문장 한 줄 + 페이드, 기성 효과(글로우 · 그라데이션 · 3D 돌출 · 반짝이 · 「피 글자」), 펠트 3D 글자(10-29 「진짜 별로」) |
| 브랜드 이름 · 끝 로고 | 가상 브랜드의 워드마크, 영상 끝 이름 | 그린다 · 묶는다 — 글자 원고(글꼴 윤곽을 다듬거나 조판)를 그림 엔진에 첫 참고로 넣어 장면과 한 장으로 굽거나(첨벙댕 튜브 로고, [장부 S43](마케팅/제작양식/만족사례_장부.md)), 로고타입으로 묶어 작게 · 효과 없이 둔다(霜の肌理 — 작은 「の」 + 로마자 한 줄, 섞인 크기의 글자 사이는 열 투영으로 재서 맞춘다). 이름부터 어감 · 상표(03류 · 전 류) · 현지어를 본다. 명조 로고는 제품 · 끝 화면 · 썸네일 로고 자리에만 쓰고, 문장 · 카드 제목 속 이름은 본문 고딕으로 쓴다(11-06 Fable — 한 카드만 명조면 글꼴이 대체된 것처럼 읽힌다). SUIT에 없는 한자 · 가나는 그 글자만 Noto Sans KR로 떨어지게 둔다(unicode-range 한자 · 가나, 크몽 상세 11-06) — §4가 막는 본문 서체 도입이 아니라 글리프 예외다 | 넓게 벌린 대문자 석 줄 + 작은 부제(점검표 22번), 한글 이름을 기성 글꼴로 크게 친 제목 |
| 정보 정리 | 장소 · 날짜 · 차례 숫자 · 가격처럼 읽을 정보 | 한 체계로 맞춘다 — 작은 머리줄 · 칩 · 큰 숫자처럼 위계를 크기 · 색 · 자간으로(10-31 「차분하고 세련된 느낌」). 작품 안 패러디 그래픽(홈쇼핑 가격 배지 · 주문 번호)은 장면 안 물건으로 본다 | 굵기만 올려 위계를 만드는 것 |

### 10-3. 판매 썸네일(크몽 · 숨고 등)

- 틀은 네 편이 같다: 왼쪽 판 540 + 사진 세 칸, 위 두 줄(분류 · 이야기 한 줄, SUIT 800 46 / 52~56px, 자간 −.045 / −.05em — §2 헤드 −.04em과 다른 11-05 t3 · t4 승인값), 왼쪽 아래 고지 칩 「가상 브랜드로 만든 자체 작품 · 길이」(SUIT 600 27~28px).
- 큰 글(작품 이름 · 한 낱말 카피)은 10-2의 강조 글 · 브랜드 이름 규칙으로 만든다 — t1 霜の肌理 로고타입, t2 「매진 임박」 LED 전광판 CG, t3 실제 앱 아이콘 + 이름, t4 튜브 CG 로고. 큰 글을 SUIT로 쳐서 사진 위에 얹지 않는다(11-07 맹검에서 옛 t2가 「글꼴을 그대로 얹은 슬롭 자리」로 꼴찌).
- 사진 칸은 자막 없는 원본 프레임에서, 가장 매력적인 얼굴 · 웃음이 나는 순간으로 고른다. 앞니 틈처럼 폰 크기에서 눈에 걸리는 장면은 뺀다.

### 10-4. 순서와 검수

1. 말 · 그림으로 되면 글을 넣지 않는다. 넣으면 위 네 갈래 가운데 무엇인지 먼저 정한다. 10-29의 「그 편에 필요한 종류 하나」는 한 화면 기준으로 읽는다 — 한 편에 말자막과 끝 이름이 같이 있는 것은 괜찮고, 한 화면에 갈래 둘 이상을 겹치지 않는다.
2. 실제 장면 위 시안 둘 이상 → 휴대폰 크기(가로 360px) 낱장 + 실제 놓일 자리(나란히 · 끝 프레임) 맹검. 묻는 것: 2초 안에 읽힌 글자, 어디가 싸 보이나, 기성 글꼴을 얹은 티, 같은 자리 벤치마크 끝 프레임과 견주면 어떤가. B급 · 패러디 편(홈쇼핑 카드 · 스티커 글자)은 「일부러 한 것으로 읽히나, 대충 만든 것으로 읽히나」를 따로 묻는다. 묻는 통로는 [미학 맹검](../tools/미학맹검.js)(점검표를 붙여 묻는다).
3. 고르신 뒤 본편. 완성본 · 작업 중 · 콘티는 점검표 「쓰는 법」대로 같은 짜임까지 같이 고친다([결정 표](_ops/결정.md) 11-04). 다만 유호님이 보시고 채택하신 판(「이 판으로 바꿔」 · 「이대로 좋아」)과 이미 걸린 게시물을 다시 만드는 것은 말씀 뒤에 한다.
4. 글자 CG도 그 편의 그림 엔진 하나로 굽는다 — [결정 표](_ops/결정.md) 11-08 「한 편 한 엔진」: 광고 · 포트폴리오 · 공모전은 Gemini 나노바나나, 애니메이션 · 펠트 · 마스코트 편은 GPT 2.6. 그 결정 앞부터 굽던 편은 그 편 엔진으로 마치고(글자 CG도 같은 엔진), Gemini가 막혀도 GPT로 옮기지 않는다([AI 광고영상 제작 규칙](마케팅/제작양식/AI광고영상_제작규칙.md) 순서 4). 10-2의 GPT 2.5 사례(첨벙댕 튜브 로고 · 크몽 t2 전광판)는 그 규칙 앞(11-05 · 11-07)에 만든 것이라 방법(글자 원고를 첫 참고로)만 가져다 쓴다.
