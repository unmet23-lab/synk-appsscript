> 이전 설계·심문·견적 가정·판정표는 [개정 전 원문](https://github.com/unmet23-lab/synk-appsscript/blob/8b80a507168d/docs/가져가는것_설계_v1.md)에서 확인한다. 현재 제작 절차로 반복하지 않는다.

## 0. 적용 기준

[철학](SYNK_철학.md), [철학 적용 기준](철학_적용기준.md), [제품방향](제품방향.md), [AI 운영 원칙](AI_운영원칙.md)이 목적·제품·데이터 사용을 정한다. 시각 표현은 [DESIGN](../DESIGN.md)과 [Loom 실시간 장면 표현 기준](Loom_실시간장면_표현기준.md)을 따른다. 애니메이션을 지원하는 화면·영상은 해당 표현 기준을 적용하고, 인쇄물은 정지 장면으로 만든다.

이 문서는 개인 기록의 귀속·학생 인쇄물·제작 규격을 유지한다. 학생 원본의 내부 보관, 본인에게 전달, 회사 비식별 집계, 훈련·평가, 공개는 용도가 다르다. 각 용도의 동의·철회·반출 범위를 적용한다. 과거의 학생 수·고정 마감·도구 미구현 선언은 현재 상태로 쓰지 않는다.

# A. 싱크 포트폴리오

## 1. 목적과 범위

포트폴리오는 학생이 배우며 남긴 말·선택·작품·변화를 자기 기록으로 가져가는 것이다. 개인 원본을 회사 집계나 홍보 자료로 자동 전환하지 않는다. 본인 기록의 반환과 허용된 회사 비식별 활용은 각각의 계약에서 판단한다.

기존 화면에 기록을 되돌리는 구조와 종이·파일 출력이 구현 출발점이다. 과거 특정 통합 포트폴리오·5년 로드맵 화면의 기각을 모든 새 화면·개인 기록 표시의 영구 금지로 확대하지 않는다. 현재 제공 범위와 졸업 뒤 이용 조건은 제품방향과 [엔진 7종의 Trail](엔진7종_상향설계_v3.md)에서 확인한다.

## 2. 무엇이 모이나

### 2-a. 기존 학습 기록과 그날의 순간

이미 있는 학습 원본은 담당 저장소에서 읽고 필요한 파생을 계산한다. 같은 원본을 이 문서 때문에 별도 수집하지 않는다. 사진·작품처럼 사건 당시 담아야 남는 재료는 순간 원본으로 관리한다.

### 2-b. 신호와 원천

| 재료 | 원천 | 기록에서의 쓰임 |
|---|---|---|
| 숙제 원문·교정·칭찬·다음 미션 | `hw_feedback` | 학생 원문과 교정을 구분한 문장·피드백 |
| 처음과 최근 문장 | `growthMap` 등 현재 성장 쌍 계산 | 같은 학생의 전후 병치. 해당 계산의 실제 간격 조건 적용 |
| 퀴즈·대화 | `quiz_log`·`talk_log` | 실제 참여·발화 기록. 학생 인쇄 금칙은 §9-b |
| 목소리 | `voice_log`의 원본 참조 | 본인 파일 묶음. 원본 음성 처리 계약 적용 |
| 자기 선언의 변천 | `self_declare_log` | 당시 선언과 변경 이력 |
| 시즌 목표·회고 | SYNK-talk `season_compass`·`season_review` | 학생 선언과 이후 회고 병치 |
| 출석 | `attendance` | 당시 반 귀속·도장 그리드 |
| 해낸 일·급수 | `achievements` 등 해당 사실 원천·`academic_log` | 실제 해낸 일·도달 사실. 등수로 배열하지 않음 |
| 월간 리포트·카드 | `report_cards`·`synk_cards` | 인쇄면·도감 |
| 떠남·이후 결과 | `exit_log`·`outcome_log`·`trajectory` | Trail의 본인 기록·결과 계약 |

원천이 존재한다는 사실은 학생 자료가 채워졌거나 출력기가 자동 연결됐다는 증거가 아니다. 출력에 들어간 실제 재료와 빠진 칸을 확인한다.

### 2-c. 그날의 순간 — portfolio_moments

실행 정본은 [Code.js](../Code.js)의 `PORTFOLIO_MOMENTS_HEADERS`다. 현재 14열의 순서와 의미를 보존한다. 위치로 읽는 소비자가 있으므로 기존 열을 재배열하지 않으며 확장은 소비자·기존 데이터 이관과 함께 한다.

| 열 | 현재 의미 |
|---|---|
| `moment_id` | 원본 Drive 폴더 ID. 같은 순간의 멱등 키 |
| `session_key` | `사건일\|반\|차시` |
| `사건일` | 폴더 이름의 사건 날짜. 적재일과 구분 |
| `반`·`차시` | 폴더의 반 키·차시 |
| `종류`·`한줄` | [contents_순간.js](../contents_순간.js)의 종류와 사람이 남긴 설명 |
| `기간키` | 실제 시즌 시작 키 또는 `비시즌`. 임의 시즌을 지어내지 않음 |
| `미디어` | JSON 배열 `[{원본:file_id, 사본:file_id\|'', 종류:'사진'\|'영상', 이름}]` |
| `원본폴더`·`사본폴더` | 원본과 배치 계정 소유 사본 폴더 ID. 현재 소비의 정본은 사본 |
| `적재일` | 배치 적재 시각 |
| `상태` | `정상`·`미분류:<사유>`·`추가`, 필요시 ` · 축소실패` |
| `공개범위` | 현재 값 `반`. 인터넷 공개 설정을 뜻하지 않음 |

행은 추가 방식으로 적재한다. 같은 `moment_id`의 마지막 행이 반·차시·종류·설명·상태의 현행값이며 미디어는 모든 행의 합집합이다. 새 원본 `file_id`만 추가하므로 재실행으로 같은 파일을 중복 수집하지 않는다. 이 보존 규칙이 정정·동의 철회에 따른 필요한 파기를 막지는 않는다.

### 2-d. 학생 개인에 어떻게 붙나 — 얼굴도 이름도 안 쓴다

순간은 반 단위로 담고, 개인 귀속은 사건일과 `attendance.class_snapshot`을 연결한다. 현재 `profiles.class_name`으로 과거 기록을 다시 붙이지 않는다. 스냅샷이 빈 행은 귀속을 추정하지 않는다. 반 출석은 특정 크루 프로젝트 참여를 증명하지 않는다.

현재 `ATTENDANCE_HEADERS`는 `id·student_id·timestamp·method·class_snapshot` 5칸이다. 기존 시트의 열 증분은 `헤더보정_`이 맡는다. 지연 백필은 기록 시점 사이 반 이동을 정확히 복원하지 못할 수 있으므로 출석 확정 시점 저장과 같은 증거로 취급하지 않는다.

이 수집 경로는 얼굴 인식·이름 태깅·학생별 사진 폴더를 추가하지 않는다. 반 공유 사진을 학생에게 전달할 때는 함께 찍힌 사람의 동의 범위를 별도로 확인한다.

## 3. 사건 당시 남기는 재료

### 3-a. 목록

첫 나침반 답·첫날 손글씨·작품·무대·발표·촬영·물건 전달·졸업 순간은 당시 원본이 필요하다. 리포트·카드·증서·기록장은 보존된 재료로 다시 만들 수 있다. 학사 시즌과 크루 운영 주기는 각 정본을 따르며 같은 주기로 가정하지 않는다. 나침반은 실제 열린 시즌을 사용한다.

### 3-b. 폴더 입력과 실패 처리

폴더 문법은 `YYYY-MM-DD - 반 - N차시 - 종류 - 한 줄`이다. 구분자 ` - `를 유지한다. `momentPrepFolders_`가 수업 폴더를 준비하고, 담당자는 미디어와 사건 설명을 남긴다. 반복 전사·인화·학생별 조립을 불필요하게 늘리지 않는다.

`momentSweep_`는 파싱 실패도 `미분류`로 남기고 미디어를 보존한다. 폴더 이름을 고치면 같은 순간에 정상 행을 추가한다. 오늘판·주간 보고의 미분류와 순간 미수집 알림은 실제 출석이 있던 반을 분모로 삼는다. 수업이 없었던 반을 누락으로 세지 않는다.

### 3-c. 영상

영상은 순간 폴더에서 원본 그대로 복사한다. 현재 수집 구현이 영상의 앱 재생·외부 공개까지 제공하는 것은 아니다. 본인에게 파일을 전달하는 범위와 공개·제삼자 전달 권한을 구분한다. 공개 URL 없이 표시할 수 있는 승인된 접근 제어가 생겨도 이 문서의 과거 화면 금지를 영구 제약으로 쓰지 않는다.

### 3-d. 용량과 사본

사진은 Drive 썸네일의 긴 변 2,000px 통로를 사용한다. 이 API는 JPEG q80을 보장하지 않는다. 축소에 실패하면 원본 복사와 `축소실패` 상태를 남긴다. 배치는 원본을 삭제하지 않고 4.5분 실행 예산 안에서 처리한 뒤 다음 실행에서 이어받는다.

원본 폴더 `SYNK_순간`와 배치 계정 소유 `SYNK_순간_사본`을 구분한다. 실제 잔여 용량·접근 권한·사본 생성 결과를 확인하며 과거 무료 용량과 연간 사용 추정을 오늘의 잔량으로 쓰지 않는다. 신규 저장 구독은 현재 지출 권한을 따른다.

## 4. 학생에게 돌아가는 자리

### 4-a. 현재 소비자와 확장

`Code.js calcAll`은 최근 순간을 걸어온 길 `BY`에, 오늘 적재된 순간을 오늘의 알림 `BX`에 반영한다. 미분류는 학생에게 내보내지 않는다. 성장 문장 병치와 SYNK-talk의 나침반·회고는 해당 실제 소비자를 확인한다.

### 4-b. 표현 계약

순간 개수·포트폴리오 완성률을 학생 간 비교나 채워야 할 과제로 만들지 않는다. 개인 사진을 표시할 때 공개 Drive 링크를 만드는 것으로 접근 제어를 대신하지 않는다. 새 화면·통합 기록의 필요성은 현행 제품과 실제 경험으로 판단한다.

## 5. 졸업할 때 무엇으로 나가나

### 5-a. 세 가지로 나간다

| 제공 형태 | 현재 범위 |
|---|---|
| ① 싱크 기록장 | A5 제본 원고. `tools/기록장조판.js` 구현 |
| ② 내 것 한 벌 | 사진·목소리 등 본인 자료의 파일 묶음. 실제 대상·동의·전달 경로 확인 |
| ③ 명예 졸업생 카드 | 자기 기록을 계속 보는 방향. 계정·학습 이용·무료 케어 조건은 현재 Trail·제품 계약 |

전체 학습 잠금을 졸업 카드의 일괄 조건으로 강제하지 않는다. 조판 도구 구현은 졸업 모드 배포·실제 파일 전달·평생 운영의 검증을 대신하지 않는다.

### 5-b. 기록장에 무엇이 들어가나 (6시즌 = 기준선이지 고정값이 아니다)

표지(이름·재원 기간·급수), 여는 쪽(첫 나침반·손글씨), 시즌별 2쪽(목표·회고·순간·해낸 일), 처음/최근 문장, 출석 도장, 이달의 카드, 닫는 쪽의 미래 답과 학생이 적을 빈 줄, 선배 카드 안내로 구성한다. 문안 정본은 [contents_증서.js](../contents_증서.js)의 `RECORD_BOOK_SAY`다.

실제로 걸은 시즌 수만큼 스프레드가 늘어난다. 6시즌·24~32쪽은 설계 기준선이며 모든 학생의 재원 기간·최종 쪽수를 고정하지 않는다.

### 5-b-2. 채움 사다리

시즌당 2쪽은 사진 수와 무관하게 유지한다. 반 공유 사진은 스프레드당 최대 1장이다. 빈자리는 그 학생의 목표·회고·한 일·고쳐 쓴 문장·카드 등 고유 재료로 채운다. 실제 재료가 없으면 빈칸을 남기고 채워야 할 칸으로 보고한다. 사진 수·결석이 책 두께나 비교 등급이 되지 않게 한다.

### 5-c. 전달과 공개

개인 기록은 종이·본인 계정·직접 전달 파일을 기본 경로로 삼는다. 학생 자료를 공개 Drive 링크나 공개 포트폴리오 URL로 자동 전환하지 않는다. 현재 리포트 PNG의 메일 첨부와 내부 Drive 참조도 구분한다. 로컬 파일을 건넸다는 이유로 서버 보관본이 자동 삭제됐다고 말하지 않는다.

외부 서명 파일 발급은 Trail의 구체적인 발급·취소·수신처 계약을 따른다. 학생 실물의 홍보는 [철학 적용 기준 §4](철학_적용기준.md#4-대외-사용과-근거)를 따른다. 기존 공유 링크의 회수 상태는 별도 실물 확인 대상이다.

## 6. 구현과 소비자

### 걸음 1 — 순간 수집과 되돌림

`Code.js`의 헤더·`momentLine_`·`calcAll`, [엔진_폼리포트.js](../엔진_폼리포트.js)의 `momentSweep_` 계열, [엔진_운영배치.js](../엔진_운영배치.js)의 오늘판·주간 보고, [엔진_셋업확장.js](../엔진_셋업확장.js)의 트리거·골격이 구현돼 있다. 트리거 선언과 실제 실행·학생 도달은 따로 확인한다.

### 걸음 2 — 카드 인쇄와 과잠 지급

`printMonthlyCards`의 A4 인쇄·시트 메뉴, 과잠 지급일·태그·목표 카드 분기가 구현돼 있다. 월간 통합 접이 봉투 전체와 동일한 완료로 보지 않는다(§10).

### 걸음 3 — 시즌 증서와 크루

[tools/증서조판.js](../tools/증서조판.js)와 `contents_증서.js`가 시즌 A5·수료 A4를 만든다. `portfolio_moments`만으로 프로젝트명·참여크루·공개일을 채울 수 없으므로 `crew_projects`를 자동 파생한 것으로 쓰지 않는다. 폐기된 Glide 폼의 정리를 현재 앱 제작의 선행 승인으로 반복하지 않는다.

### 걸음 4 — 나란히 보기

SYNK-talk의 `src/회고화면.js`·`src/나침반API.js`와 현재 서버 계약에서 지난 선언·회고의 실제 연결을 확인한다. 서버 전용 자료를 클라이언트 직접 조회로 바꾸지 않는다.

### 걸음 5 — 졸업 벌

[tools/기록장조판.js](../tools/기록장조판.js)의 기록장과 증서조판의 수료증은 구현돼 있다. 본인 실제 자료 연결·졸업 모드·수신자 전달은 각 실행 증거를 확인한다. 새 조판 도구 발주나 과거 졸업일 대기를 되풀이하지 않는다.

### 6-b. 개인 반환과 다른 용도

본인 데이터를 동의된 개인 서비스로 되돌리는 일과 회사 훈련 승격은 별도 경로다. 훈련 승격을 기다리느라 개인 반환을 멈추지 않는다. 사진·음성·다른 학생이 포함된 자료는 학습 텍스트 동의와 자동으로 같아지지 않는다.

# B. 손에 남는 물건

## 7. 접점별 물건 지도

상담·체험·등록·수업·월간 기록·시즌·기념·졸업에 어떤 물건이 필요한지 실제 제공물로 정한다. 품목별 규격은 §11-a에 남긴다. 상점 판매물과 기본 제공물의 권리·가격·포인트 조건은 [포인트 경제](포인트경제_재설계_v1.md)와 현재 제공 안내에서 확인한다. 상점 ST15 포토북과 기록장의 유료·무료 경계를 이 문서만으로 새로 확정하지 않는다.

## 8. 웰컴 키트

설계 구성은 기록 홀더(A4 수납), 첫 나침반 종이, 우리 반 카드와 체험 때 쓴 이름표다. 첫 나침반 종이는 기념물이며 답의 입력은 앱의 실제 나침반 통로에서 한다. 강사가 종이 전부를 나중에 옮겨 적는 절차를 기본 운영으로 추가하지 않는다.

상점 물건의 무료 지급·새 실물 와펜 발주를 이 구성에서 자동 확정하지 않는다. 종이의 재질 표현은 현행 DESIGN을 따르고 실제 펠트 소재와 인쇄 표현을 구분한다.

## 9. 수료증 · 시즌 증서

### 9-a. 구조

시즌 증서는 A5, 수료증은 A4, 기록장은 A5 제본이다. 정규 과정의 6시즌·12개월은 기준선이고 증서조판은 실제 `시즌수`·`개월수`를 채운다. 생성 가능한 문안과 실제 수료 자격을 혼동하지 않는다. 발급 자격은 현재 학사·제품 조건으로 확인한다.

### 9-b. 문안

실제 출력 문안은 `contents_증서.js`의 `CERT_SEASON`·`CERT_COMPLETION`·`CERT_DEED_SAY`·`CERT_BLANK`에서 가져온다. 문서에 예전 연도·호칭·초안을 복제하지 않는다. 시즌 증서는 함께 걸은 기간과 실제 한 일을, 수료증은 처음/지금 문장을 담는다. 재료가 없으면 지어내지 않는다.

학생 인쇄물에는 점수·정답률·정답 개수·등수·석차·평균·상위 비율·다른 학생과의 비교·난도 라벨·승급/미달 통지를 넣지 않는다. 항목을 개수순·난도순으로 정렬하지 않는다. 금칙 목록의 실행 정본은 [tools/발표물린트.js](../tools/발표물린트.js)의 `STUDENT_BANNED`이며 `data-synk-print="학생"` 표식이 있는 지면에 적용한다. 사업 문서의 정당한 수치까지 같은 금칙으로 막지 않는다.

### 9-c. 디자인 방향

현재 토큰·폰트·로고를 소비한다. 시즌 구분은 색과 패턴을 함께 쓰며 흑백 출력에서도 읽혀야 한다. 현재 증서의 기본 실은 코랄이며 `--시즌색`은 비교할 수 있는 옵션이다. 이 문서 정리가 옵션을 기본 적용하거나 디자인 채택을 새로 확정하지는 않는다.

## 10. 리포트 봉투 · 태그 · 포장

### 10-a. 현재 인쇄 경로

`printMonthlyCards`는 발간월 카드 그리드를 A4 가로 HTML로 만들고 가능한 경우 PDF도 만든다. 시트 메뉴 `menuPrintMonthlyCards`가 연결돼 있다. PDF 변환 실패를 HTML 저장 성공과 구분한다. 이 함수는 반별 학생 사진·리포트가 모두 포함된 봉투 생성기는 아니다.

### 10-b. 월간 봉투 — A4 접이 설계

설계는 A4 접이 한 장 안에 이름·한 줄의 겉면, 리포트, 62mm 카드 절취면, 동의된 순간 사진을 담는 것이다. 반 단위 출력으로 전사·재단·인화·별도 봉입 손을 줄인다. 현재 카드 인쇄의 구현과 이 통합 봉투의 실제 생성·배부를 구분한다. 완성 여부·접힘·반당 배부 시간은 실제 출력으로 확인한다.

### 10-c. 굿즈 태그와 지급 상태

`JACKET_HEADERS`의 지급일, `jacketEnsureHeaders_`, `jacketStampGiven_`과 태그·목표 카드·오늘의 알림 소비자가 구현돼 있다. 상태는 걷는 중/자격 도달 후 미지급/지급완료를 구분하며 이미 받은 학생에게 계속 전달 예정이라고 표시하지 않는다.

현재 지급일은 배치가 지급완료를 처음 본 날에 빈칸에만 기록한다. 실제 전달 시각을 직접 측정한 값과 구분한다. 태그 문안은 `contents_증서.js`에서 소비한다.

### 11-b. 색

### 11-c. 전 품목 공통 규격

인쇄 지면은 용지 크기·여백을 `@page`에 명시하고 배경색 유지·인쇄용 표시 숨김을 적용한다. 외부 이미지·폰트 CDN에 의존하지 않는 자립형 원고와 임베드 폰트를 사용한다. 색만으로 정보를 구분하지 않는다. 빈 재료는 `CERT_BLANK` 등 실제 문안 규약으로 표시하고 채워야 할 칸을 모은다.

### 11-d. 수량 · 단가

발주는 현재 제공 범위·실제 수요·견적에 근거한다. 과거 좌석·손익분기·예상 인원을 자동 발주 수량으로 쓰지 않는다. 신규 비용은 이미 받은 지출 권한을 따르며 견적 조사·원고·시안 제작을 미확정 예산 때문에 일괄 중단하지 않는다.

### 11-e. 몽골어

현재 문안 뱅크의 빈 `mn`은 검수된 번역이 아니다. 실제 배부 대상 언어의 문안을 준비하고 확인한다. 과거 검수자 인원·채용 마감은 현재 사실로 유지하지 않으며 다른 규격·한국어 조판까지 막는 전역 대기로 쓰지 않는다.

### 11-f. 실제 인쇄

PDF 생성, 현지 프린터의 급지·여백·양면·색, 제본·절취·접힘 품질은 별도 확인이다. 복사지 규격만 맞는다고 모든 프린터의 출력 성립을 보장하지 않는다.

# C. 현재 확인과 이력

## 13. 일정

이 문서에 과거 D-day·개원일·졸업일을 복제하지 않는다. 필요한 제작·실물 검증 일정은 현재 운영 일정과 실제 제공 시점에 맞춘다.

## 14. 제품 선택과 운영 권한

### 14-a. 기존 번호의 현재 의미

③ 기록장/ST15 제공 조건, ④ 수료 발급 조건, ⑤ 시즌 실 색은 현재 제품·학사·실물에 연결한다. 이미 구현된 ⑥ 과잠 소비자를 다시 착수 승인 대기로 두지 않는다. ⑦ 크루 귀속은 §6 걸음 3의 실제 재료 한계를 따른다.

⑨ 순간 폴더는 배치 계정 소유 사본을 사용하는 구현이 있다(§3-d). Workspace 이전을 이 구현의 선행 조건으로 강제하지 않는다. ⑧ 인쇄 예산과 ⑩ 유료 저장 등 새 지출은 현재 권한·견적에 맞춰 별도로 판단한다.

### 14-b. 실행

현재 요청 범위에서 조사·원고·검증을 진행하고, 실제 인증·지출·외부 공개에 필요한 권한만 구체적 결과를 기준으로 확인한다. 과거 클릭 안내와 판정 열 개를 사용자에게 다시 넘기지 않는다.

## 15. 미확인 범위

### 15-d. 실제 적용 때 확인할 것

현재 실제 학생 자료의 연결·반 공유 사진 동의·개인 파일 수신 확인, 통합 월간 봉투 출력, 현지 인쇄 견적·제본·배부 품질은 각 작업의 실물 증거로 확인한다. 이 문서 정리에서 배포·발주·학생 전달을 새로 수행하지 않았다. 확인하지 않은 항목이 관련 없는 엔진 발전 전체를 막는 규칙은 아니다.

## 16. 이전 판정표

과거 심문·답이 필요한 열 가지·완료 전 발주 순서는 상단 Git 원문에 남긴다. 현재 문서에 중복 대기로 유지하지 않는다. 실제 보호 계약과 아직 필요한 제품 선택은 위 해당 절에서 관리한다.
