## 경험과 범위

사용자가 ‘하나씩 살펴보기’를 고르면 계정에 저장한다. 같은 계정으로 다음 실행을 시작하면 그 방식을 불러와 실제 점검 항목을 한 칸씩 보여 준다. ‘먼저 혼자 해 보기’로 고치면 점검을 접은 상태로 시작한다. ‘기본 안내로 되돌리기’는 이전 선언을 적용하지 않는 새 기록이며 원본 학습 기록 전체 삭제가 아니다.

화면은 불러오는 중·저장 중·확인 완료·다른 기기 변경·실패를 구분한다. 실패한 저장을 성공처럼 표시하지 않는다. 이번 집중 목표·여유 시간·흐름에 대한 응답은 세션에만 두며 글·음성·원본 대화를 이 기억에 담지 않는다. 계정 없는 체험은 기존 세션 경험을 사용한다.

계약은 c16의 기존 `preference.stated`를 사용한다. 차원은 `atlas.letter.support`와 `atlas.documents.support`, 표면은 `atlas_settings`, 선택은 `choose|step|independent|default`로 제한하며 새 사건 종류·DB 마이그레이션은 없다. 지원 목록과 실제 콘텐츠 workspace의 연결은 공통 원본에서 명시한다. 모르는 콘텐츠를 편지 범위로 자동 처리하지 않는다. 세부 요청·응답·오류는 talk `docs/C0_API계약.md` §4-7이 정본이다.

## 지켜야 하는 동작

- 계정 식별과 접근 권한은 서버가 확인한다. 클라이언트가 보낸 학습자 번호로 조회하지 않는다.
- 첫 읽기가 성공해야 계정 저장을 시작한다. 구 서버나 불량 응답을 빈 기억으로 간주하지 않는다.
- 같은 요청 재전송은 중복 저장하지 않는다. 저장 결과가 불명확할 때 원래 사건·비교 조건을 유지한다.
- 두 기기의 수정은 직전 revision을 비교한다. 오래된 선택을 최신 설정 위에 자동으로 덮지 않는다.
- 기본 안내로 되돌린 뒤에도 revision을 남겨 옛 요청이 이전 선택을 되살리지 않게 한다.
- 로그아웃·계정 변경 후 늦게 도착한 읽기/갱신 결과가 새 계정의 도움이나 전송을 바꾸지 않게 한다.
- 동의가 철회되면 읽기·쓰기를 막고, 재동의 때 이전 동의의 설정을 자동으로 이어 쓰지 않는다.
- 임시 시간·목표·응답을 보존하면서 도움 선호만 복원한다. 기기 시계 오차 때문에 임시 설정 만료가 멈추지 않게 한다.
- Atlas 설정은 기존 일반 성향 추정의 선호·확신도 근거에 섞지 않는다.

## 검증과 남은 일

로컬 시험은 공통 모듈, 실제 클라이언트 API와 서버 함수의 합성 왕복, 앱 세션 복원과 실제 판단, 인증 갱신 경계, 기존 관련 동작을 검증한다. 합성 왕복에서는 SQL과 인증 게이트웨이만 대역이다. 실제 PostgreSQL 잠금·운영 서버·두 실기기 검증과 같지 않다.

원격 배포·운영 DB 변경·스토어 빌드·신규 결제는 실행하지 않았다. 실제 리허설 SQL 검증은 아래 후속 기록처럼 롤백으로 끝냈다. 이 범위에서는 모델 API 호출이 추가되지 않는다.

실제 스키마의 UUID·동의 FK·멱등 unique 제약과 기존 trigger를 읽고 새 SQL과 대조했다. SQL 대역은 트랜잭션을 JavaScript 큐로 직렬화하므로 두 기기 CAS 시험 통과를 PostgreSQL advisory lock 실측으로 보고하지 않는다. 앱 화면의 첫 렌더와 실제 도움 판단은 자동 시험으로 확인했으며 네이티브 화면 조작·시각 품질 검증은 수행하지 않았다.

배포 시에는 `events`·신규 `atlas-memory` 외에 바뀐 공통 집계를 동봉하는 `deliver`·`deliver-one`·`progress`·`teach`, 검증기 사본을 동봉하는 `radio-promote`도 함께 검토해야 한다. 기존 배포 도구는 커밋된 HEAD를 읽는다. 신규 파일이 아직 미커밋이라 기존 `tests/원격배포.test.js`의 6건은 그 보호 조건으로 실패했으며, 도구를 우회하거나 약화하지 않았다. 별도로 **현재 원문**을 실제 동봉 변환기로 변환해 모든 `.mjs`를 import하는 시험은 통과했다. 커밋과 배포를 준비할 때 HEAD 기반 검사를 다시 실행해야 한다.

다음 순서는 배포 가능한 묶음을 검토해 리허설 API에 연결하고, 실제 로그인·계정 변경·두 기기의 충돌·재실행을 확인하는 것이다. 두 번째 콘텐츠의 로컬 연결은 아래 후속 범위까지 구현했으며 학습자가 도움을 이어 쓰며 편해지는지는 별도로 확인한다. 원본 기록의 물리 삭제·장기 학습 수행 요약·전체 서비스의 공유 허용 UI·전체 SYNK 계정과 홈은 별도 미완료 작업이다.

**종료 시 커밋 후 재확인:** talk `46af8c4`에 이번 기억 기능·공동 안내를 커밋하고 `tests/원격배포.test.js`를 다시 실행했다. **19개 중 18개 통과, 1개 실패**다. 새 파일이 HEAD에 없어서 발생했던 동봉 실패는 해소됐다. 남은 실패는 166행의 ‘작업본과 HEAD가 같으면 통과’ 시험으로, 해당 시험이 읽는 `계약/수집_교정_계약.json`에 별도 작업의 미커밋 변경이 있어 발생한다. 그 변경과 기존 스테이징 배포 장부를 보존했으며 테스트를 통과시키려고 계약을 덮어쓰거나 보호 검사를 약화하지 않았다. 실제 배포 전에 관련 계약 작업과 배포 묶음을 함께 정리하고 다시 검사한다.

## 2026-09-21 후속 — 두 번째 콘텐츠와 실제 저장소 검증

G4 서류 관문의 **제출 후 되돌아보기**를 두 번째 소비처로 연결했다. `atlas/experiences.js`의 공통 어댑터가 해설 표시 범위를 정하고 실제 기존 G4 화면이 소비한다. 기본은 모두 펼치기, `step`은 한 항목부터 다음 해설·전체 펼침을 선택, `independent`는 해설을 원할 때 여는 방식이다. 문제·정답·채점·풀이 순서는 바꾸지 않는다.

G4 설정의 ‘편지 연습의 도움 방식을 여기에도 쓰기’는 명시적인 **한 번 가져오기**다. 누르기 전에는 편지 선호를 조회하거나 적용하지 않는다. 누른 뒤에는 현재 계정·동의 안의 편지 선호를 읽고 서류 관문의 별도 차원에 저장한다. CAS는 서류 관문의 revision을 쓰며 충돌하면 덮어쓰지 않는다. 편지 선호가 없으면 기존 서류 설정을 유지하고 직접 선택을 안내한다. 이후 어느 한쪽의 변경·기본 안내 복귀가 다른 쪽으로 퍼지지 않는다. 계정 없는 미리보기에서는 가져오기와 계정 저장을 제공하지 않는다.

로컬 확인 범위:

- 공통 원본 4개 시험 파일 **42/42 통과**, talk 관련 **22개 시험 파일 통과**. 기존 계정·동의·계약·편지·서류 제출 회귀를 포함한다.
- 실제 클라이언트 API·서버 함수·Atlas 판단을 연결한 두 콘텐츠 여정에서 명시적 가져오기, 재실행 복원, 독립 변경·기본 안내 복귀, 다른 계정 분리, 대상 CAS 충돌, 동의 철회, source 부재, 응답 유실 후 같은 사건 재전송을 확인했다. 이 여정의 SQL·인증 게이트웨이는 여전히 대역이다.
- 기존 G4 React 화면의 실제 렌더에서 `step`은 첫 해설만, `independent`는 열기 버튼만, 기본은 모든 해설을 표시한다. 작성한 문장은 보존되며 풀이 화면은 기존 문항 그대로다. 이는 네이티브 터치·레이아웃이나 두 실기기 시험을 대신하지 않는다.
