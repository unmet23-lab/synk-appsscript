# 앱 로드맵 근거 감사 — 내 집, 생활, 주민, 16명의 마을

2026-09-21. 현재 설계 문서와 저장소의 시제품 코드·기존 검수 기록을 대조했다. 이번 감사에서는 엔진을 실행하거나 전체 테스트·실서비스·실제 휴대폰 검증을 하지 않았다. 아래 미래 경험은 출시 기능 소개가 아니라 사용자 관점의 제작 로드맵이다.

## 먼저 구분할 상태

- **확정한 방향:** RPG·몬스터 퀴즈 전투는 기각했다. 미래 한국의 아름다운 생활 공간, 농사·채집·제작·가게·꾸미기, 좋아하는 활동을 통한 발전, 구체적인 NPC 성과 인정, 정원 16명, 혼자 완결, 간단한 모바일 조작을 지향한다.
- **실제 로컬 시제품:** 브라우저의 16개 집 배치·한 캐릭터 이동·세 카메라 비교·내 집 외관 색과 장식 선택·기기 내 저장이 있다. 남산 산책 시제품과 Unity 비교 프로젝트가 별도로 있다. 이 사실을 앱의 완성된 마을이나 16인 온라인 서비스로 합산하지 않는다.
- **앞으로 구현할 경험:** 농사·채집·제작 경제, 실제 가게 운영, 주민 생활·대화·관계·성과 인정, 계정별 집과 물건 보존, 16인 동시 접속·마을 배정·이동·공동 편집은 설계 단계다.
- **앱 연결 범위:** 현재 `SYNK-talk/src` 파일명 검색에서 마을·농사·채집·가게 화면은 확인하지 못했다. 기존 `docs/마을_설계.md:22–25`도 앱 내 집·마을과 NPC 대화 화면의 부재를 기록한다. 파일명 검색만으로 저장소 전체에 관련 기반 코드가 전혀 없다고 단정하지 않는다.
- **효과:** 재미·한국어 실력 향상·실제 휴대폰 발열·접속 유지 효과는 검증 전이다. TOPIK 취득 보장이나 모든 학습 과정의 출시 완료로 표현하지 않는다.

## 기능별 사용자 경험

### 1. 원할 때 들어가는 내 집과 마을

- **사용자 행동 → 앱 반응 → 가치:** 메인 화면에서 내 집 입구를 선택한다 → 마스코트가 있는 집과 창밖 마을로 들어간다 → 공부할 때와 쉬면서 한국어를 만날 때를 스스로 고른다.
- **세부:** 핵심 학습의 주인은 메인 화면이다. 마을을 한 번도 이용하지 않아도 배움이 이어지는 방향이다. 집의 책상·우편함·액자는 핵심 기능으로 가는 또 다른 입구다.
- **상태:** 앱 내 집 입구·실내 생활은 계획. 브라우저 시제품의 바깥 집 배치와 구별한다.
- **근거:** `docs/마을_설계.md:14–20,68–84,395–403`.

### 2. 내 취향을 담는 집과 정원

- **사용자 행동 → 앱 반응 → 가치:** 벽 색·조명·화분·마당의 분위기를 고른다 → 선택이 공간에 남고 다음 방문에도 이어진다 → 작은 집도 자기만의 장소가 된다.
- **세부:** 자리별 교체부터 시작하고 추천 조합·배치 미리보기·취소를 제안한다. 자유 배치의 범위는 확정 전이다. 가까이에서는 펠트와 마감, 멀리서는 집과 풍경의 구도를 보는 방향이다. 배우기 전에도 기본 공간이 아름다워야 한다.
- **상태:** 시제품은 외관 색 세 가지·마당 장식 세 가지와 로컬 저장까지. 실내 가구 배치·소유권·계정 저장·상점·실제 구매는 미구현.
- **근거:** `docs/마을_설계.md:86–90`; `docs/디자인/마을_플레이경험과_준비사항_20260921.md:30–34,62–68`; `experiences/dokkaebi-express/src/village/model.js:149–158,186–190`; `experiences/dokkaebi-express/qa/village/RESULTS.md:22–24,35–36`.

### 3. 물건이 학습과 기록으로 이어지는 집

- **사용자 행동 → 앱 반응 → 가치:** 책상·우편함·액자를 누른다 → 오늘 할 일·교정의 답장·이전에 해낸 일을 보여 준다 → 메뉴를 찾아다니는 대신 익숙한 공간에서 배움과 추억을 만난다.
- **세부:** 집 안 물건의 이름·소리를 듣고, ‘책상 위 컵’ 같은 짧은 심부름으로 위치 표현을 써 보는 안이다. 액자에는 첫 성취나 엽서, 수첩에는 나와 주민에 대해 확인할 수 있는 내용을 둔다. 같은 학습은 메인에서도 접근해야 한다.
- **상태:** 집 안 상호작용으로의 연결은 계획. 기존 학습 기능의 존재와 집에 연결한 사실을 구분한다.
- **근거:** `docs/마을_설계.md:70–84,297–314,399–400`.

### 4. 내 모습과 성취를 간직하는 꾸밈

- **사용자 행동 → 앱 반응 → 가치:** 옷을 고르거나 주민과 함께한 일을 마친다 → 몽글의 외형이 달라지고, 그 일의 기념품을 집에 둘 수 있다 → 나의 취향과 경험이 눈에 보이는 기록이 된다.
- **세부:** 몽글은 팔 없는 정체성을 유지한다. 구입한 외형과 관계·성취로 얻는 간직할 물건을 구분하고, 구입했다고 더 큰 존경이나 학습 실력을 주지 않는 방향이다. 같은 옷을 입고 여러 기기·마을에서 보이는 연결은 후속이다.
- **상태:** Unity 비교 프로젝트에 망토·조끼·베레모와 의상 변경 코드가 있다. 계정 옷장·보유품·다른 참가자에게 동기화·관계 기념품 지급은 미구현.
- **근거:** `docs/마을_설계.md:82,86,273–275`; `docs/디자인/마을_NPC_성과인정_설계_20260921.md:56–62`; `experiences/namsan-urp/README.md:3–5,35–39`; `experiences/dokkaebi-express/art-direction/village-20260919/CORE-HANDOFF.md:27–39`.

### 5. 좋아하는 활동으로 이어지는 성장

- **사용자 행동 → 앱 반응 → 가치:** 농사·꾸미기·장사·주민 이야기 중 하고 싶은 일을 고른다 → 서로 다른 경로로 재료와 보상, 새로운 선택을 얻는다 → 모든 일을 매일 끝내야 한다는 부담 없이 자기 생활을 만든다.
- **세부:** 농사를 좋아하면 품종과 정원, 꾸미기를 좋아하면 가게 수입으로 기본 재료를 구하는 식의 대안이다. 모든 경로를 똑같게 만들지는 않는다. 돈·집의 크기·관계·한국어 숙련은 별도로 다룬다.
- **상태:** 방향은 사용자 승인, 세부 보상·경제·활동 간 대안은 설계. 균형이나 재미가 검증된 시스템은 아니다.
- **근거:** `docs/디자인/마을_플레이경험과_준비사항_20260921.md:18–24,74–76,95–99`.

### 6. 기르는 재미가 사용처로 이어지는 농사

- **사용자 행동 → 앱 반응 → 가치:** 텃밭에 다가가 오른쪽 물 주기·수확을 선택한다 → 거둔 작물이 판매·요리·선물·주문 재료가 된다 → 같은 수확으로 어떤 다음 경험을 만들지 고른다.
- **세부:** 직접 조준하는 반복 조작을 줄인다. 가까워졌다는 이유로 저절로 수확하지 않는다. 작물·수량·요청의 한국어를 이해한 선택이 남아야 한다. 작물 성장 시간·미접속 결과·재료 가격은 미확정이다.
- **상태:** 농사 기능과 수확물 경제는 계획. 최신 오른쪽 다중 행동 UI도 문서 설계다.
- **근거:** `docs/디자인/마을_플레이경험과_준비사항_20260921.md:38–42,76,96`; `docs/디자인/미래한국_마을_풍경.md:61–71`.

### 7. 아름다운 산책이 발견과 채집으로

- **사용자 행동 → 앱 반응 → 가치:** 주민의 단서를 듣고 길을 걷는다 → 장소에 맞는 꽃·식재료·공예 재료를 발견한다 → 풍경을 보는 일이 생활의 새로운 가능성으로 이어진다.
- **세부:** ‘다리 옆’, ‘비가 그친 뒤’ 같은 위치·날씨 표현을 실제 길과 연결한다. 발견물을 화분이나 선물, 제작 재료로 쓸 수 있다. 특정 현실 시간에만 필수 재료를 얻도록 강요하지 않는 안이다. 시즌 도감은 확장 후보다.
- **상태:** 남산 걷기와 한국어 발견 지점은 로컬 시제품. 채집 인벤토리·계절 재료·도감·생활 경제는 계획.
- **근거:** `docs/디자인/마을_플레이경험과_준비사항_20260921.md:40–42`; `docs/마을_설계.md:297–314`; `experiences/dokkaebi-express/art-direction/namsan-walk-20260919/README.md:5,11–12,55`.

### 8. 만든 물건이 실제 생활에 쓰이는 제작

- **사용자 행동 → 앱 반응 → 가치:** 주민이 부탁한 수량·색·재료를 이해하고 만든다 → 그 의자에 주민이 앉거나 새 잼이 메뉴에 오른다 → 완성 버튼 너머의 변화를 눈으로 확인한다.
- **세부:** 재료·순서·조건을 이해하는 생활 과제다. 반복 제작마다 무관한 한국어 퀴즈를 붙이지 않는다. 직접 만든 것·산 것·재료를 도운 사람을 구별한다. 실제 동작이 없는 칭찬 문구만으로 구현됐다고 보지 않는다.
- **상태:** 제작·가구 이용·주문 결과 반영 모두 계획.
- **근거:** `docs/디자인/마을_플레이경험과_준비사항_20260921.md:44–52`; `docs/디자인/마을_NPC_성과인정_설계_20260921.md:23–30,56–60`.

### 9. 내 메뉴와 분위기가 있는 가게

- **사용자 행동 → 앱 반응 → 가치:** 찻집의 메뉴·좌석·차양을 정하고 손님을 응대한다 → 주문과 후기가 다음 선택으로 이어지고 공간이 달라진다 → 장사는 반복 클릭보다 내 가게를 키우는 재미가 된다.
- **세부:** ‘따뜻한 차 두 잔’, ‘덜 달게’부터 재고가 없을 때 대안 권하기까지 난도를 달리한다. 초급의 보기·문장 틀과 중급의 설명을 함께 설계한다. 보조 NPC의 기본 영업은 제안이며 오프라인 수입·직원·회계 전체는 확정하지 않았다.
- **상태:** 가게 화면·영업 경제·NPC 주문은 계획. 첫 구간은 작은 메뉴·재고·손님 반응으로 제한하는 제안이다.
- **근거:** `docs/디자인/마을_플레이경험과_준비사항_20260921.md:48–52,84,96,105`.

### 10. 각자의 하루와 사연이 있는 주민

- **사용자 행동 → 앱 반응 → 가치:** 평상·분식집·공방의 주민을 만난다 → 날씨와 시간, 주민의 성격과 이전에 나눈 일에 따라 다른 장면이 열린다 → 다시 보고 싶은 이웃이 생긴다.
- **세부:** 관계는 공개 점수나 정답률 대신 부르는 말·방문·이야기·간직할 물건으로 나타내는 안이다. 비싼 선물만 반복해 이야기를 여는 흐름을 피한다. 쉰 날 때문에 관계를 깎거나 죄책감을 주지 않는 방향이다. 문에 붙은 영업 쪽지와 차림표도 읽을거리가 된다.
- **상태:** 주민의 일상·관계·대화는 계획. 기존 마스코트 문구·표정 기반이 마을 NPC 생활 전체를 뜻하지 않는다.
- **근거:** `docs/마을_설계.md:263–282`; `docs/주민_설계.md:8–24,99–133,223–230`; `docs/디자인/마을_플레이경험과_준비사항_20260921.md:56–60`.

### 11. 내 한국어로 참여하고 막히면 도움받는 대화

- **사용자 행동 → 앱 반응 → 가치:** 고르기·문장 조립·빈칸·장면에 맞는 내 말 중 편한 방식으로 답한다 → 어려우면 다시 듣고 보기로 돌아가거나 주민이 확인해서 묻는다 → 틀릴까 봐 멈추기보다 대화를 이어간다.
- **세부:** 말하기·키보드·낱말 서랍을 제안한다. 음성 인식은 보낸 글을 먼저 확인·수정하게 하고 발음 점수로 판단하지 않는다. 주제 안의 대화와 주제 제한 없는 유료 AI 자유 대화는 다르다. 모든 말을 이해하는 NPC를 약속하지 않는다.
- **상태:** 마을 대화 화면은 계획. 기존 전사 준비와 일반 대화 능력 완성을 구별한다. 기본 대화를 규칙·검수 콘텐츠로 처리하는 목표는 운영 비용 전체가 0이라는 뜻이 아니다.
- **근거:** `docs/대화_설계.md:8–18,23–46,142–161,191–208`.

### 12. 내가 한 일을 말과 행동으로 알아보는 주민

- **사용자 행동 → 앱 반응 → 가치:** 작물을 전하거나 쉴 자리를 꾸민다 → 그 일을 실제로 아는 주민이 음식을 만들거나 의자에 앉고, 나중에 관련된 보답을 한다 → ‘좋아하는 일을 했더니 이 마을에 의미가 생겼다’고 느끼게 한다.
- **세부:** 농사·채집·제작·꾸미기·장사·대화의 성과를 다르게 인정한다. 구체적인 말·실제 사용·다음 만남의 기억·취향에 맞는 보답·의견 묻기·공간의 흔적·개인 편지·공동 기여의 구분을 제안한다. 공개 소개 여부는 선택한다.
- **상태:** 사용자 승인 방향, 상세 설계 단계. 실제 마을 사건 저장·NPC별 인지·반응 이력·동작 연결은 미구현이다.
- **근거:** `docs/디자인/마을_NPC_성과인정_설계_20260921.md:7–17,21–52,56–85,89–103`.

### 13. 주민이 아는 나를 직접 확인하기

- **사용자 행동 → 앱 반응 → 가치:** 이웃 수첩을 열어 나눈 이야기와 주민이 아는 내용을 본다 → 잘못된 이해를 고치거나 잊어 달라고 한다 → 친밀함을 쌓으면서도 나에 관한 기억을 조정할 수 있다.
- **세부:** 방문하지 않은 주민이 비공개 집 안을 아는 식의 과도한 기억을 피한다. 배운 수준을 조정하는 정보와 주민이 말할 수 있는 개인 사실은 구분한다. 활동 횟수만 보고 고정된 성격·취향을 단정하지 않는다.
- **상태:** NPC 수첩과 장기 관계 기억은 계획. 09-21에 별도로 구현한 Atlas 도움 방식의 첫 계정 기억을 마을의 모든 성과·주민 기억으로 확대하지 않는다. 성과 인정 문서의 예전 ‘세션 Map뿐’ 설명은 작성 당시 확인 범위다.
- **근거:** `docs/마을_설계.md:59,274`; `docs/대화_설계.md:30,191–194`; `docs/디자인/마을_NPC_성과인정_설계_20260921.md:17,56–60,75–85`.

### 14. 생활 속에서 만나는 한국 문화

- **사용자 행동 → 앱 반응 → 가치:** 차림표를 읽고 주문하거나 집들이·명절·편지 장면에 참여한다 → 상황에 맞는 높임말·수량·시간·선물을 써 본다 → 단어를 외우는 것과 한국에서 실제로 쓰는 장면이 연결된다.
- **세부:** 미래의 풍경 속에서도 일상 한국어를 사용한다. 분식집·시장·우체국·도서관 등은 확장 후보이며 모두 첫 출시 범위가 아니다. 생활에서의 성공과 독립적인 한국어 이해를 구분하고, TOPIK 형식 연습은 따로 연결해야 한다.
- **상태:** 문화 장면과 학습 연결은 설계. 효과 검증 전이며 TOPIK 취득이나 전 지역 구현을 약속하지 않는다.
- **근거:** `docs/마을_설계.md:94–110,281,297–314,346–351`; `docs/주민_설계.md:28–36,119–123`; `docs/디자인/마을_플레이경험과_준비사항_20260921.md:78–86`.

### 15. 열여섯은 함께 살아가는 온기

- **사용자 행동 → 앱 반응 → 가치:** 같은 마을의 집과 마당을 둘러보고 정해진 인사를 건넨다 → 이웃의 꾸밈·몽글·몸짓·한국어 이모티콘을 만난다 → 혼자 할 일은 충분하면서도 같은 곳에 사는 느낌을 얻는다.
- **세부:** 정원 16명은 활동 시작에 필요한 인원이 아니다. 자유 입력을 다른 사람에게 전달하는 채팅은 제외한다. 문 앞 선물·정해진 한마디·초대한 공간의 집들이·같이 앉기는 후보이며 동시 접속은 후속 단계다. 나라가 달라도 같은 공간에서 각자의 언어 지원을 받는 방향이다.
- **상태:** 현재 16개 집 시제품, 실제 연결자는 한 로컬 캐릭터다. `connected:false`, `onlineCount:null`이며 16인 접속·계정·마을 서버가 없다.
- **근거:** `docs/마을_설계.md:53–55,335–355`; `docs/공개판_설계.md:17–23`; `experiences/dokkaebi-express/src/village/model.js:45–61`; `experiences/dokkaebi-express/qa/village/RESULTS.md:35–36`.

### 16. 내 공간과 공동 공간을 구분하기

- **사용자 행동 → 앱 반응 → 가치:** 자신의 정원을 꾸미거나 허용된 공용 정원 작업을 고른다 → 개인 성취와 공동 변화를 각각 남긴다 → 다른 사람이 먼저 했다고 내 이야기나 공부가 사라지지 않는다.
- **세부:** 집 안과 보관함은 개인 공간, 공용 정원과 광장은 별도 권한이 필요하다. 누가 편집·취소·복구할지, 공동 기여를 어떻게 보존할지는 후속 설계다. 마지막 버튼을 누른 사람만 인정하지 않는다. 다른 사람에게 학습 기록·실명·연락처가 보이는 흐름은 두지 않는다.
- **상태:** 권한·보존 원칙 설계. 서버 소유권·초대·차단·공동 편집 구현 완료 아님.
- **근거:** `docs/마을_설계.md:90,355`; `docs/디자인/마을_플레이경험과_준비사항_20260921.md:68–70,97`; `docs/디자인/마을_NPC_성과인정_설계_20260921.md:58–62`.

### 17. 일반 학습자의 마을 이동과 학원 반

- **사용자 행동 → 앱 반응 → 가치:** 일반 학습자는 조용해진 마을을 옮기고 싶을 때 이동을 선택한다 → 주 1회 활성 마을로 옮길 기회를 제공하는 방향이다 → 고립된 마을에 계속 남아야 하는 부담을 줄인다.
- **세부:** 학원생은 실제 학원의 16명 반 구성이 고정되고 자율 이동이 없다. 교사 출석·수업 관리 권한을 일반 마을에 붙이지 않는다. 개인 집·취향·관계·학습 기록을 이어갈 방향이지만 공용 기여·이전 NPC 관계·활성 마을의 정의·주간 기준은 더 정해야 한다.
- **상태:** 웹 시제품에는 일반/학원 모드별 정책 안내만 있다. 7일은 임시 가정이며 실제 이동 기능·서버 권한 확인·반 편성이 없다. 기존 학원 관리 기능 자체의 운영 검증은 이번 범위 밖이다.
- **근거:** `docs/공개판_설계.md:17–23`; `docs/디자인/마을_플레이경험과_준비사항_20260921.md:70`; `experiences/dokkaebi-express/src/village/model.js:161–184`; `experiences/dokkaebi-express/art-direction/village-20260919/CORE-HANDOFF.md:62–70`.

## 문서 사이의 경계·충돌

1. **자유 채팅:** `마을_설계.md:54,335–355`의 사용자 확정은 사람끼리 자유 채팅 없이 이모티콘·몸짓·정해진 말이다. 09-21 플레이 경험의 방문 인사·채팅은 제안이므로 확정 방향을 덮지 않는다. 웹의 직접 입력 말풍선도 이 화면에서만 보이는 옛 시제품이다. 로드맵은 정해진 인사로 작성한다.
2. **처음부터 아름다운 세계:** `마을_설계.md:141`의 배운 만큼 색이 드는 구상과 09-21 플레이 경험 `:30`의 처음부터 아름다운 세계가 있다. 회색 세계를 학습 노동으로 해금한다고 홍보하지 않는다. 학습에 따른 작은 흔적과 기본 풍경의 완성도를 후속 통합해야 한다.
3. **낮·밤의 기준:** `마을_설계.md:118–126`는 현지 시간의 낮·밤과 같은 마을·날짜의 날씨를 제안한다. 미래 풍경 문서 `:136`는 시간·강수를 공유하는 기술안을 말한다. 최종 기준은 조정이 필요하다. 자연스러운 낮·밤·날씨라는 방향만 제시하고 전 세계 16명이 같은 빛을 동시에 본다고 확정하지 않는다.
4. **표현 방식:** `마을_설계.md:149–152`의 겹친 2D·미리 만든 그림 제안과 최신 3D 고품질 시제품 비교를 구별한다. Unity 또는 Unreal, 한 방식으로 전 제품을 확정했다고 말하지 않는다.
5. **Atlas의 현재 범위:** NPC 성과 인정 문서 `:81`의 세션 상태 설명은 작성 당시 사실이다. 이후 도움 방식 한 가지의 계정 기억이 만들어졌어도 NPC의 성과·관계·다른 서비스 장기 기억까지 완성된 것은 아니다.
6. **기본 AI 비용:** 규칙 기반 기본 대화의 ‘AI 호출 0’은 설계 목표다. 서버·저장·동기화·콘텐츠 제작까지 인원이 늘어도 비용이 0이라는 홍보로 확대하지 않는다.
7. **공식 이름과 예시:** 싱크월드는 주민 설계에서 확정 이름이다. 이음, 바람꽃, 2240년 한강, 첫 주민의 이름·나이·가게와 정원 사례는 출시 확정 정보로 쓰지 않는다.
8. **배제한 것:** RPG·몬스터 퀴즈 전투·NPC 연애·공개 성적 경쟁·농부 같은 직업 고정·필수 동시 접속·매일 전 활동 숙제는 이 로드맵에 넣지 않는다.

## 먼저 완성해 볼 단위

제안된 첫 구간은 내 집·작은 텃밭·공방·찻집·공용 정원과 소수 주민이다. ‘부탁을 이해하기 → 기르기/찾기/사기 중 재료 마련 → 제작 → 메뉴나 공간 변화 → 주민의 실제 행동과 말 → 내 집을 바꿀 보상’을 한 번 끝까지 연결한다. 농사를 고르지 않은 경로도 끝나야 한다. 그다음 실제 휴대폰 조작·읽기·발열, 새로운 상황의 한국어 이해, 실제 여러 계정의 공유 상태를 각각 검증한다. 기능 개수나 캐릭터 16개 배치만으로 완료 판정을 하지 않는다.
