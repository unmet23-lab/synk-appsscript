0. 먼저 철회합니다. 이 지면의 낮 판에서 제가 「우리 자가 아예 안 세는 규칙 넷」이라고 적었습니다 — ㅎ 섞임·구개음화·유음화·ㄴ덧남. 틀렸습니다.

tools/발음밀도.js 의 머리말만 읽고 본문을 안 읽었습니다. 본문을 여니 갈래가 일곱으로 이미 서 있고(겹받침·연음·비음화·유음화·격음화·경음화·구개음화) 그중 셋을 다 세고 있었습니다. 실제로 못 세던 것은 아래 ①에서 실측으로 찾아낸 한 자리뿐이었습니다.

결론. 일곱 갈래를 다 돌려 고친 것 하나 · 되는 것 하나 · 문 앞에서 막힌 것 넷 · 값이 낮은 것 하나로 갈렸다.

고친 것 — 우리 발음 자가 「않습니다」·「싫소」 같은 자리를 0으로 세고 있었다. es-hangul 을 옆에 대서 찾았고 고쳤다. 시험 7/7 · 발음 관련 전량 40/40 통과, 커밋 a590751bd.

뒤집힌 판정 둘 — ⓐ es-hangul 을 「정본으로 붙인다」고 했는데, 실제로 돌려 보니 틀린 소리를 낸다(「문장」을 [문짱]으로). 정본이 아니라 가끔 대는 자로만 쓴다. ⓑ 엔진 타입 검사가 결함 하나를 잡은 줄 알았는데 거짓 경보였다(다른 파일에 있는 함수를 못 찾은 것).

① 발음 자 — 구멍 하나를 찾아서 메웠다

이번 일의 가장 큰 소득이다. 순서대로 적는다 — 중간에 자를 두 번 갈아 끼웠다.

메운 자리 — 표준 발음법 12항 4호 고쳤다

ㅎ 계열 겹받침(ㄶ·ㅀ) 뒤에 ㅅ 이 오면 된소리가 난다. 고치기 전까지 이 자리가 전부 0이었다:

않습니다[안씀니다] · 많습니다[만씀니다] · 싫소[실쏘] · 옳소[올쏘] · 괜찮습니다[괜찬씀니다]

ㅎ 홑받침은 원래 잡혔다(「좋소[조쏘]」). 겹받침 둘만 빠져 있었다. 학생이 초급에서 가장 많이 쓰는 「~않습니다」가 여기 걸린다.

es-hangul 판정이 뒤집혔다 정본 탈락 가끔 대는 자로는 유지

toss/es-hangul ★1,870 · 2.4.0 · 스크래치패드에 설치해 실제로 돌림

먼저 좋은 소식. 우리 자를 352줄의 우리 문안에 대고 나란히 돌린 결과:

합계 352 = 일치 263 + 놓침 33 + 헛셈 0 + 둘 다 0건 56
총량: 우리 자 963건 · es-hangul 이 바꾼 글자 1,711자

헛셈 0 이 이 검사에서 가장 값 있는 수다 — 우리 자가 없는 것을 있다고 세지 않는다는 뜻이다.

그리고 나쁜 소식. 놓친 33건을 갈라 보니 대부분 es-hangul 이 틀린 것이었다. 직접 넣어 본 것:

까닭. 된소리 규칙 하나(24항)가 원래는 「말의 줄기 + 꼬리」에만 붙는 것인데(안고→안꼬), es-hangul 은 그것을 이름씨와 띄어쓰기 너머까지 밀어 붙인다. 그래서 「문장」이 [문짱]이 된다.

⇒ 처음에 나온 「우리 자의 포착률 36.5%」라는 수는 거짓이었다. 못 본 219곳 중 대부분이 남의 오류였다.

그래서 어떻게 쓰나. 정본으로는 못 쓴다. 하지만 옆에 대는 자로는 값이 있다 — 이번에 진짜 구멍 하나를 그렇게 찾았다. 저장소에는 안 넣었다(정본이 아니라서). 다시 세우는 법은 docs/_ops/발음자_교차검사_2026-09-03.md 에 적었다.

가는 길에 자를 두 번 갈아 끼웠다 기록

남기는 까닭은 다음에 같은 함정을 안 밟기 위해서다.

  • 1회차 — 두 글자 조각(「력입」·「식입」·「작일」)을 es-hangul 에 넣었다. 낱말이 아닌 것에 규칙이 돌아 결과가 통째로 못 쓰게 됐다. ⛔ es-hangul 은 낱말·문장 단위로만 넣는다.
  • 2회차 — 「연음인가 덧남인가」를 뒤 글자 첫소리로 갈랐더니 「일이→이리」 같은 정상 연음이 덧남으로 분류됐다. 자를 「앞 글자 받침이 사라졌는가」로 바꿔서 풀었다.

② 엔진 타입 검사 — 파일을 한 글자도 안 고치고 돌렸다

엔진 여덟 벌에 형 표시가 0개라 「올리기 전에 잡아주는 자가 없다」고 적었던 자리다. 실제로 검사를 붙여 봤다.

145건 나왔고, 진짜 결함은 0이었다 값은 다른 데 있다

어떻게 붙였나. 엔진 파일에 // @ts-check 를 넣지 않았다. 설정 파일 하나만 스크래치패드에 두고 저장소 파일을 가리켰다 — 배포집합을 한 바이트도 안 건드린다. 검수 도장이 무효화되지 않는다.

가장 크게 뜬 경보가 거짓이었다. 「prefillTemplateOf_ 를 못 찾는다」 — 없는 함수를 부르는 줄 알았는데 엔진_폼리포트.js:698 에 있었다. Apps Script 는 파일이 달라도 한 살림이라 정상이다.

남는 값. 결함 사냥용으로는 값이 낮다. 대신 주석과 코드가 어긋난 것을 잡는다 — 교재연동.js:701 의 주석 한 줄이 잘못 쓰여 있어 도구가 「필수 칸이 빠졌다」고 오해한다. 고치면 세 건이 같이 사라진다. 다음 배포 창에 함께 처리할 자리다(배포집합이라 지금 손대면 검수 도장이 갈린다).

  • 고른 것 — gh search repos 로 열여섯 갈래, gh api repos/{레포} 로 별·마지막 손질 날짜, gh api …/contents 로 소스 원문.
