깃허브 정찰 — 우리 「자」의 구멍에 맞는 것

이틀 전 정찰(docs/깃허브_정찰_0901.html)은 「최근 올라온 것」을 훑어 목소리 둘로 끝났다. 이 지면은 축이 다르다 — 지금 우리가 쓰는 자가 스스로 못 한다고 적어 둔 자리를 먼저 세우고, 거기에 맞는 물건을 찾았다.

결론. 열여섯 갈래를 뒤져 지금 붙일 것 하나, 때가 되면 붙일 것 셋, 고를 자리 다섯을 골랐다. 나머지는 「없다」로 닫혔다.

가장 큰 소득은 es-hangul 하나다. 우리 tools/발음밀도.js 가 머리말에 스스로 「이 수는 하한이다」라고 적어 둔 그 자리를, 표준 발음법 조항을 하나씩 함수로 짜고 조항마다 시험을 붙여 둔 물건이 정확히 메운다. 이 자의 수가 발음 규격 §2-1 의 낱말 11 배치 근거라, 자가 바뀌면 근거를 다시 재게 된다.

워크트리·다세션 쪽은 붙일 것이 없다가 답이었다 — 이미 우리 자작 장치가 같은 일을 하고, 남의 것보다 최신이다. 이건 실패가 아니라 세어 본 결과다.

① 지금 붙일 것 하나 — 발음 자의 구멍

우리 자가 「못 센다」고 스스로 적은 자리에, 그것을 세는 물건이 서 있다.

왜 믿을 만한가. 남이 대충 짠 게 아니다. 국어의 표준 발음법 조항을 하나씩 따로 파일로 짰고, 파일마다 시험(.spec.ts)이 붙어 있다. 소스에서 직접 센 목록이다:

⇒ 그러므로 이 수는 하한이다. 실제 밀도는 이보다 높다.
무엇이 바뀌나
지금 자가 아예 안 세는 소리 규칙이 넷이다 — ㅎ 섞임 · 구개음화 · 유음화 · ㄴ덧남. 이 넷이 들어오면 발음 규격 §2-1 의 밀도 수(TOPIK 3축 55건 · 경음화 17 = 31%)가 다시 계산된다. 낱말 11 을 그 수로 골랐으니, 근거를 다시 재는 일이 된다.

talk 앱(Expo·타입스크립트)에 바로 붙는 것들 — getChoseong(초성만 뽑기 = ㅅㅋㄹ 로 검색) · josa(을/를·이/가 자동) · disassemble(자모 쪼개기 = 손글씨·타자 채점) · romanize(로마자).
안 재봤다
우리 기계에 안 깔아봤다. 09-01 정찰은 후보를 전부 설치해 실제로 돌려 판정했는데, 이번은 소스를 읽은 데까지다. 붙이기 전에 우리 낱말 11 로 두 자를 나란히 돌려 대조하는 것이 다음 걸음이다.

② 이미 쥔 것의 안 켠 부분

새로 들이는 게 아니라, 쓰고 있는 물건에 스위치가 하나 더 있는 경우다.

⑤ 우리 쪽에서 고칠 것 — 남의 물건이 아니라 지금 우리

정찰을 돌다 우리 것을 재게 됐다. 셋 다 이 기계에서 센 수다.

㉠ 엔진 24,811줄에 형 표시가 0개

실측
grep -c "@param" Code.js 엔진_두뇌.js → 0 · 0. 엔진 여덟 벌 합계 24,811줄.
무슨 뜻
「이 칸에는 숫자가 들어온다 / 글자가 들어온다」를 적어 둔 곳이 한 줄도 없다. 그래서 「글자가 와야 할 자리에 빈 것이 왔다」 같은 실수를 올리기 전에 잡아 주는 자가 없다 — 라이브에서 터져야 안다.
고치는 법
파일 맨 위에 // @ts-check 한 줄, 함수 위에 @param 주석. Apps Script 는 이걸 그냥 주석으로 보고 넘긴다 — 라이브는 한 글자도 안 바뀐다. 대신 편집기와 검사기가 미리 잡는다. 위험 없이 한 파일씩 늘릴 수 있다.
첫 걸음
가장 자주 터지는 한 벌부터. 후보 = 엔진_수집.js(1,342줄 · 가장 작고 데이터가 드나드는 곳).

㉡ 발음 자를 「하한」에서 「정본」으로

①의 es-hangul 을 붙여 tools/발음밀도.js 와 나란히 돌려 대조한다. 두 수가 갈리는 낱말이 곧 지금 자가 놓치는 자리다. 갈리는 것이 없으면 그것도 답이다(자가 이미 충분하다).

⑥ 「없다」와 「안 재봤다」 — 다른 말이다

세어 본 결과 「없다」

  • 최근에 새로 올라온 것 중 우리 갈래 — 한국어 학습 최고 1★ · Claude Code 워크플로 최고 8★. 값 0. 09-01 판정과 같다.
  • 몽골어 — 이번에도 최고 3★(giellalt/lang-khk · 할하 몽골어 분석기). 09-01 의 「전용 도구 사실상 0건」 그대로다.
  • Apps Script — 별 높은 것은 여전히 전부 프록시 우회로다. 엔진에 쓸 것 0건. 09-01 판정 그대로. 단 「오래 서 있는 것」 축에서는 셋이 있다 — oshliaer/google-apps-script-awesome-list(★2,066) · googleworkspace/apps-script-oauth2(★1,747 · 구글 공식) · enuchi/React-Google-Apps-Script(★1,527). 셋 다 지금 우리 엔진이 필요로 하는 것은 아니다.

정말 안 재본 것

  • es-hangul 을 우리 기계에 안 깔았다. 소스를 읽은 데까지다.
  • echogarden 의 한국어 정렬 품질.
  • ts-fsrs 안에 최적화기가 들어 있는지 — 저장소 구조가 달라 소스를 못 열었다(경로 404). 별도 파이썬 패키지가 있는 것은 확인했다.

무엇으로 쟀나

  • 후보 찾기 — gh search repos <낱말> --sort stars 로 열여섯 갈래(fsrs · hangul · korean pronunciation · korean g2p · claude-code hooks · claude code plugin marketplace · agent skills · claude code subagents · git worktree manager · mutation testing javascript · google apps script · supabase rls testing · blender · remotion · expo supabase · mongolian language).
  • 최근 것 따로 — --created=>2026-07-01 로 한 번 더(위 ⑥의 「없다」가 여기서 나왔다).
  • 실물 확인 — gh api repos/{레포} 로 별·마지막 손질 날짜·열린 이슈. gh api repos/{레포}/contents/… 로 소스 원문(es-hangul 조항 파일 목록과 주석은 여기서 그대로 옮겼다).
