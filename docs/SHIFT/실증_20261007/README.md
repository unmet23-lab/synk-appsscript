# SHIFT 한 업무 실증과 반복 공급

2026-10-07. 첫 고객·업무와 두 번째 고객·업무는 **미정**이다. 이 자료는 실제 입력을 받을 준비를 마친 측정 도구이며, 실제 고객 실증·효과·수익성·판매 준비의 증거가 아니다. 계약·가격·기간·합격 기준은 임의로 정하지 않았다.

[실증 계산표](../../../outputs/01a10c3d-cfe1-7c40-a1db-eea42c604fd6/shift-evidence-20261007/SHIFT_한업무_실증과_반복공급_20261007.xlsx)는 고객 1과 2를 같은 구조로 기록한다. [SHIFT BM 정본](../../마케팅/SHIFT.md#shift-bm)의 한 업무 도입·운영, 반복 공급 확인, 이후 API·라이선스 확장 순서를 따른다. 기존 사업모델 PDF·Word·전체 BM 계산표를 대체하지 않는다.

## 실제 입력과 실행 순서

1. 계산표를 업무별 작업본으로 복사한다. `업무범위`에서 고객과 한 업무, 사용자 완료 결과, 비교그룹 ID, 업무·자료 버전, 측정 시작·종료일을 정한다. 대상·제외 조건, 배정 방법, 완료·실패·중단·오류의 판정과 시간 측정 경계를 먼저 작성한다. 인수·지원·권한·보관·삭제와 담당·종료 조건·비용 한도도 실제 합의 내용을 적는다.
2. `시행기록`에 기존 방식과 개인화 방식의 시행을 한 행씩 기록한다. 시행 ID는 중복하지 않고 고객·비교그룹·업무 버전·날짜를 맞춘다. 비식별 대상 ID와 확인 가능한 근거를 사용한다. 실패와 중단도 기록하며, 측정하지 않은 값은 빈칸으로 둔다. 조건 밖 시행은 삭제하지 않고 제외 사유를 남긴다.
3. `원가기록`에 준비·자료 정리·설정·연결·검수·수정·지원·영업 시간, 전체 모델 호출 경로의 비용과 서버·저장·백업·외주·공통비 배분을 기록한다. 대표 시간도 빠뜨리지 않는다. 시간단가가 미정이면 빈칸으로 둔다. 확인한 0만 0으로 입력한다. 빠진 비용까지 확인한 뒤 `업무범위`의 원가 기록 완료 여부를 완료로 바꾼다.
4. 두 번째 고객을 적용할 때 `재사용기록`에 같은 능력·모듈의 기존 버전, 그대로 또는 수정 재사용, 신규 개발, 변경 이유와 품질 확인을 적는다. 각 항목은 고객 2의 같은 책임 분류에 해당하는 원가 기록 ID 하나를 연결한다. 시간·금액을 이 시트에 중복 입력하지 않는다. 한 항목에 여러 작업이 있으면 해당 항목 단위의 원가 기록으로 합쳐 근거에서 상세를 연결한다.
5. `요약`의 분모·측정 누락·관찰 차이·기록된 원가를 확인하고 `판단기록`에 인수와 다음 공급 판단을 남긴다. 조건이 다른 전후 결과를 인과효과로 주장하지 않는다. 고객 2의 작업시간 감소도 업무·규모·지원·품질이 달라지면 재사용 효과로 확정하지 않는다.

## 계산의 의미

- 완료율의 분모는 결과가 확인된 완료·실패·중단 시행이다. 미측정·제외·입력확인은 별도로 표시한다. 시간·오류·사람 전환은 각각 값이 측정된 시행을 분모로 쓴다. 요약의 측정 시행 수를 결과 집계 수와 함께 읽는다.
- 평균 시간은 확인한 0분을 포함하고 누락은 0분으로 바꾸지 않는다. 오류 비율은 오류가 하나 이상 있었던 시행 수 ÷ 오류 수가 측정된 시행 수이다. 사람 전환은 해당 여부 0/1을 사용한다.
- 비교 기간 밖, 비교그룹·업무 버전 불일치, 중복 시행 ID, 필수 식별·근거 누락은 집계하지 않고 입력확인으로 표시한다. 한 고객의 한 비교그룹·한 업무 버전을 집계한다. 여러 업무·그룹은 별도 작업본을 사용한다.
- 경제 원가는 `(시간 × 시간단가 + 비노동 현금) × 고객 배분율`이다. 현금 원가는 `(노동 현금 + 비노동 현금) × 고객 배분율`이다. 노동 현금과 시간 가치를 같은 원가에서 이중 차감하거나 두 원가를 합산하지 않는다. 직원·외주 등 노동 단가는 실제 고용·계약 부담 기준을 맞춘다.
- 요약의 원가는 **집계 가능한 기록의 합계**다. 기록 완료 확인 전에도 보이므로 전체 비용이 확정됐다는 뜻이 아니다. 전체 원가 기록이 확인되고 미완성 원가 행이 없을 때만 매출 대비 잔액을 계산한다. 수금·세금·상각·자금 조달을 모두 반영한 확정 회계 순이익이나 현금 흐름표는 아니다.
- 고객 2 재사용 비율은 집계된 능력·모듈 기록 중 그대로 또는 수정 재사용한 개수의 비율이다. 복잡도 가중치·개발비 절감률·품질 향상을 대신하지 않는다. Atlas 공통·전문 모듈·고객 설정·연결·제품 호스트의 책임을 따로 기록한다.
- 시행·원가는 각 60행, 재사용은 25행까지 계산한다. 더 많은 행이 필요하면 검증한 수식·범위를 함께 확장한다. 현재 범위 아래에 기록만 추가하면 요약에 포함되지 않는다.

## 검증과 보존

`qa/tests.json`은 계산 모델에 합성 입력을 넣고 복원한 검사 기록이다. `qa/native-excel.json`은 실제 Microsoft Excel에서 읽기 전용으로 열고 합성 입력을 바꿔 재계산한 기록이다. 합성 입력은 원본에 저장하지 않았다. 실제 입력 칸 1,797개가 모두 공란임을 확인했다. 실제 고객 실증은 미실행이다.

전체 6개 시트의 15개 범위를 일반 크기로 렌더해 확인했다. 수식 오류·잘린 입력 설명은 없으며, 선택 목록·입력 칸·계산 결과·미확인 표시를 확인했다. [최종 검증 보고](qa/report.json)에 결과·출력 SHA와 확인 범위를 남긴다.

`build.mjs`는 빈 입력용 전달본을 다시 만드는 제작 원본이다. 실제 입력을 담은 작업본에 재생성을 실행하지 않는다. 이전 BM PDF·Word·통합 계산표, SHIFT BM 정본, Atlas 코드는 수정하지 않았다. 유료 AI·외부 접촉·실제 고객 운영·배포는 실행하지 않았다.
