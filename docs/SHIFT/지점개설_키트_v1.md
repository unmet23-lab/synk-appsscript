# 지점 개설 키트 v1 — 목차 (SHIFT 직원이 첫 설치다)

> **상태**: 목차 초안 · 2026-09-02 · 유호 채택(한 차원 지면 S3) · 정본 = `docs/SHIFT/설계_v1.md` §3-①·§1-C · 실물은 채용 전
> ⚠ **시제** — 키트는 아직 «목차»다. §1 은 지금 학원 하네스에 **있는 것의 실측**이고, §2 부터는 지을 것이다.
> 자리 규칙(S3) — 납품 코드가 생기기 전에는 새 저장소를 안 판다. 키트는 `docs/SHIFT/` 에 산다. 판이 오르면 옛 판은 그 자리에서 지운다.

## 0. 한 줄

지점 개설 키트 = **지점·법인을 하나 열 때 복제되는 것 전부**에 이름과 판 번호를 붙인 물건이다 — 하네스 · 장부 · 자 · 브랜드 킷 · 자동화 한국 법인판 · 첫 30일.
판 번호가 붙는 순간 테라포밍(정본 §1-C 「같은 구조를 복제한다」)은 «유호님이 매번 하는 일»에서 «꺼내서 설치하는 물건»이 된다. 일은 사람이 나가면 사라지고, 물건은 남는다(정본 §3-① 「다음 사람이 같은 자리에 선다」).
**첫 설치 = 한국 법인의 첫 직원(첫 제자 · 2027)** 이다. 그가 설치하는 장면이 곧 v1 의 검수다 — 설치가 안 되면 키트가 덜 된 것이지 사람이 모자란 게 아니다.

## 1. 이미 있는 것 (실측 09-02)

지점에 «무엇을 해 주는가» 한 줄씩. 수는 이 기계에서 `ls` 로 센 것이다.

**하네스** — 훅 스크립트 9(`.claude/hooks/*.js`) · 이벤트 5(PreToolUse·UserPromptSubmit·Stop·SessionEnd·SessionStart) · 가드 4 · 규칙 4(`.claude/rules`) · 스킬 16(`.claude/skills`) · 에이전트 2(builder·reviewer)

| 것 | 지점에 해 주는 것 |
|---|---|
| clasp-guard (가드) | 라이브에 닿는 길을 `/deploy` 하나로 묶는다 — 직원이 손으로 배포 못 한다 |
| git-scope-guard (가드) | 커밋 범위를 못 박는다 — 남의 파일이 실수로 안 섞인다 |
| credential-guard (가드) | 비밀번호·키 화면에서 AI 가 손을 뗀다 — 자격증명은 사람 손 |
| voice-guard (가드) | 대외 글의 말투를 규칙으로 막는다 — 지점 접점판 표가 필요하다(§2) |
| decision-catch | 대표가 확정한 말을 그 자리에서 결정.md 로 보낸다 |
| turn-end-ledger · session-end-ledger | 공용 장부 미커밋을 짖고, 세션이 어떻게 끝났는지 적는다 |
| review-runs | 세션 밖에서 돈 검수 결과를 세션 첫머리에 세운다 |
| philosophy-card | 판단 정본의 게이트 문장(이벤트에 직접 안 걸림 · rot-check·codex-review 안에서 이름이 보인다) |
| SessionStart 의식 | 도구 5 를 같이 돌린다 — 기억데려오기 · 결정 · rot-check · 모델정찰 · ai스택점검 |
| 규칙 4 | 경로를 만질 때만 실리는 규칙 — 코드·굽기·지면·장부. 지점은 자기 경로 규칙을 새로 쓴다 |
| 스킬 16 · 에이전트 2 | 배포·닫기·브랜드·콘텐츠·디자인·영상의 손순서 · builder/reviewer 역할 |

**장부** — 결정.md(무엇을 정했나 · 유일 정본) · 트랙.md(무엇이 남았나 · 색인 · 절 ≤5KB) · CLAUDE.md(규칙만) · 기억(토픽 파일 + `tools/기억데려오기.js` 가 새 기계에 데려온다) → 지점: 「대표가 뭐라 했더라」가 파일 하나로 답이 된다.

**자** — rot-check(조용한 부패를 한 번에 훑는다) · doc-graph(정본→파생 엣지 · 낡은 문서 찾기) · memory-graph(기억 그래프 · 끊긴 링크) · 이해대장(철학 부록 A 를 한 장으로) · 인용검사(`파일:줄` 인용이 거짓인지) → 지점: 문서가 썩는 것을 사람이 아니라 자가 잡는다.

**검수** — codex-review(이종 벤더 적대 검수) · ai스택점검(세 벤더 역할이 «실제로 도는가») → 지점: 대표가 안 봐도 두 번째 눈이 있다.

**브랜드 킷**(이름만) — `DESIGN.md` · `docs/디자인_토큰.json` · `tools/lib/로고정본.js` · `tools/lib/마스코트자산.js` → 지점의 모든 지면이 같은 얼굴.

**산출 통로** — `tools/운영자료.js`(대표가 눈으로 보는 산출물을 바탕화면 폴더로) · `tools/lib/loom.js`(어느 지면이든 같은 부품·여백·재질의 CSS) → 지점: 만든 것이 «보이는 자리»로 간다.

도구 수 — `tools/*.js` 123 · `tools/lib/*.js` 30(실측 09-02). 정본 §3-① 의 「자동화 41종」은 학원 엔진(Apps Script) 배치 수라 이 수와 다른 자다 — 여기서 다시 안 셌다.

## 2. 한국 법인용으로 한 벌 더 지을 것

학원 하네스에 없는 것. 목록이지 설계가 아니다.

- 계약 — 고객사 계약서 초안 · 서명 통로 ⚠ 미조사
- 견적 — 「그 자리에서 나오는 견적」(정본 §3-① 장면) 생성 틀
- 회의록 — 「회의 끝 5분 뒤 회의록」 틀 · 녹음 동의 문구 ⚠ 미조사
- 제안서 — 「3시간 제안서」 틀 · 브랜드 킷 SHIFT 판
- 세금계산서·청구 — 발행 통로 ⚠ 미조사
- 근태·급여 — 직원 1명분 ⚠ 미조사
- 고객사 장부 — 파이프라인 · 졸업생 = 10년 뒤 고객사 명단(정본 §3-⑥)
- 촬영 동의 계약 셋 — 촬영 동의 · 초상권 · 퇴사 후 기존 영상 처리(정본 §3-②) ⚠ 미조사
- 대외 톤 규칙 — voice-guard 의 «고객사 접점» 표(학생 접점 표는 그대로 못 쓴다)
- 법인 정체 — 이메일 서명 · 명함 · 문서 머리(계정 자리는 `shift-account-ledger` 가 쥔다)
- CLAUDE.md 한국 법인판 — 역할 · 안전 넷 · 장부 자리를 법인 말로

## 3. 키트에서 «빼는» 것

학생 데이터가 흐르는 층은 **전부** 뺀다. 까닭 둘 — 영상 공개선 ③(`docs/SHIFT/영상_공개선.md` · 「시스템의 속은 대외에서 펼치지 않는다」) · 안전선(학생 식별 데이터는 밖으로 안 나간다).

- `엔진_*.js`(수집 · 성향 판정) · `contents_*.js`
- Supabase 데이터·콘솔 접근 · 학생 시트(구글 시트 원장) · outcome_log · trajectory
- 발음 데이터 · 숙제→성향 추출 · 상담 AI 대화층
- 기억 중 학생·학부모가 나오는 토픽

빠지는 것이 곧 해자다 — 키트는 «돌리는 법»이지 «속»이 아니다. 한국 법인 직원은 학원 학생과 접점이 없으니 만질 이유도 없다.

## 4. 설치 순서 — 첫 제자 첫 30일

카메라는 촬영 계약 셋(정본 §3-② · 공개선 8) 서명 «뒤»에만 켠다. 고객 회신 원문·돈은 어느 주에도 안 찍는다(공개선 7·10).

| 주 | 설치되는 것 | 찍는 것 | 끝에 혼자 돌리는 것 |
|---|---|---|---|
| 0(채용 날) | 촬영 계약 셋 서명 | 없음 | — |
| 1 | 하네스(훅·가드·규칙) · CLAUDE.md 법인판 · 장부 셋 빈 판 · 기억 통로 | 「첫 설치」 — Claude Code 창(공개선 2) | 세션 열고 `/close` 로 닫기 · 결정 한 줄 적기 |
| 2 | 브랜드 킷 · 산출 통로 · 회의록·제안서 틀 | 「회의 뒤 5분 회의록」 | 회의록·제안서 초안을 혼자 낸다 |
| 3 | §2 한 벌(견적·계약 초안·고객사 장부) · 검수 자(codex-review·rot-check) | 「견적이 그 자리에서」 | 견적 내고 검수 돌리기 |
| 4 | 첫 고객 접점(정본 §3-④) | 「고객이 겪는다」 — 결과물만 | 한 고객사를 회의→회의록→제안→견적까지 |

30일이 끝났는가의 자 = **대표 없이 하루를 돌렸는가**(연락 0 · 산출물 1 이상). 이 자가 v1 의 검수다.

## 5. 판 규칙

| 판 | 설치자 | 때 |
|---|---|---|
| v1 | SHIFT 직원(한국 법인 첫 직원) | 2027 |
| v2 | 몽골 지점 위임 | ≈2028(개원 후 운영 1년 · 정본 §1-C) |
| v3 | 베트남 | 베트남에서 정보 수집 뒤 |

판마다 무엇이 바뀌는가는 **여기서 안 정한다** — 언어 · 학생 데이터 층(v2 부터 지점이 학생을 가진다 — §3 의 「빼는 것」이 그때 어떻게 되는가) · 법인 격. v2 가 열릴 때 v1 설치 기록이 답의 재료다.
판 하나 = 파일 하나. v2 가 서면 이 파일이 v2 가 된다(옛 판은 git 이력이 쥔다).

## 6. 안 재본 것

- 하네스가 «다른 사람 기계»에서 도는가 — 훅이 그 사람 커밋에서 걸리는가 · `기억데려오기.js` 는 누구의 기억을 데려오는가. ⚠ 안 재봤다.
- Claude Code 좌석·비용 · 저장소 쓰기 권한(저장소는 PUBLIC — 읽기는 되고 쓰기는 별도). ⚠ 안 쟀다.
- 「자동화 41종」 중 학원 전용이 몇이고 법인으로 옮길 것이 몇인가. 안 셌다.
- 첫 제자 채용 시점 · 급여 · 계약 문안. ⚠ 미조사.
- 30일이 맞는 길이인가 · 4주 표의 순서가 맞는가. 첫 설치가 잰다.
- 학원 하네스의 한국어 이름 도구(예 `결정.js`)를 그대로 쓰는가, 법인 말로 바꾸는가. 안 정했다.
