## 0. 축 — 운영 탄력을 무엇으로 재는가

**운영 탄력 = ①유호님이 개입해야 하는 비율 × ②개입 한 건당 걸리는 시간.**
학생이 늘어도 이 곱이 안 늘어야 탄력이다. 둘 다 재고 둘 다 내린다.

| | 지금 상태 | 근거 |
|---|---|---|
| ① 개입률 | **100%** | 챗봇 미가동 · 상담 로그 0건 |
| ② 개입당 시간 | **사실상 무한** | 유호님이 몽골어를 못 읽고 못 쓴다 |

②가 무한이면 ①을 아무리 낮춰도 곱은 안 줄어든다. **그래서 순서가 「봇 성능」이 아니라 「인계 회로」부터다.**

## 1. 🔴 실측 — 탄력이 새는 진짜 자리 3곳

### ① 인계가 유호님 언어 장벽에서 끊긴다 (최우선)

`상담AI.js:316` `상담_인계알림_()`:

```js
adminMail('[SYNK] 🙋 상담AI 인계 요청', '사유: ' + 사유 + '\n세션: ' + 세션 +
  '\n\n학부모 질문:\n' + String(사용자말).slice(0, 500) + '\n\n메신저에서 직접 답변해 주세요.');
```

- 학부모 질문이 **몽골어 원문 그대로** 간다. 번역 없음.
- 처방이 **"메신저에서 직접 답변해 주세요"** — 유호님이 몽골어로 답을 못 쓴다.
- 유호님이 답장을 보낼 **통로가 코드에 없다.** 상담AI는 봇→학부모 단방향이고, 사람은 메신저 앱으로 직접 들어가야 한다.

**결론: 인계는 되는데 처리가 안 된다.** 어떤 도구(ManyChat·인스타 자체 AI·상담AI)를 골라도 이 지점은 동일하게 막힌다.

> ✅ **[v9.185] 해소** — 인계 메일이 한국어 번역 + 답변 초안 3개(한·몽 병기) + **클릭 1회 발송 링크**를 담는다
> (`상담_인계알림_`·`상담_인계초안_`·`상담_초안발송_` · 게이트 = URL키 fail-closed·1회성·24시간 창). 남은 것 = 몽골어 초안 품질의 원어민 검수(주기 감수 묶음).

### ② 인스타그램 DM을 아예 못 받는다

`상담AI.js:102` — `b.object === 'page'`(페이스북)만 처리한다.
Meta 공식 문서상 인스타 DM 웹훅은 **`object: "instagram"`**으로 온다. 우리 코드는 `null`을 반환하고 **조용히 버린다**(오류도 로그도 없다).

> 안쪽 구조(`entry[].messaging[].sender.id`)는 페북과 동일 → 분기 추가는 작다.
> 단 **발송 토큰·권한이 별개**다(`instagram_manage_messages` · `pages_messaging`).
>
> ✅ **[v9.185] 해소** — `object:'instagram'` 분기 + IG 계정ID 잠금 + IG 토큰 분리(페이지토큰 폴백) + 퀵리플라이·postback 수신.
> 남은 게이트 = Meta 앱 검수(`instagram_manage_messages`) — 유호님 몫(설치 정본 STEP 6).

### ③ 답할 수 있는 질문이 절반뿐이다

`docs/자주묻는질문_정본.md` 실측 — 학부모 16문 + 학생 9문 중:

| | 수 | 비고 |
|---|---|---|
| ✅ 지금 답 가능 | **13** | 아이스브레이커·FAQ에 쓸 재료는 충분 |
| ⛔ 답하면 안 됨 | **8** | 수강료·주소·무료체험·형제할인·환불·보강·대상연령·반배정 |

챗봇 지식 블록 40개 중 **15개가 「미확정」**(`grep "확정:" contents_상담AI.js`).
⛔ 8개가 하필 **학부모의 첫 질문**이다. **없는 가격은 어떤 도구도 답하지 못한다.**

## 2. 도구 판정 — 택일이 아니라 3층

### 실조회로 확인한 Meta 네이티브 기능 (2026-08-04)

| 기능 | 상한 | 비용 | 위치 |
|---|---|---|---|
| 인스타 앱 FAQ | **4개** | 0 | 인스타 앱 |
| 아이스브레이커 API | **4개** ("maximum of 4 questions") | 0 | API · 데스크톱 미지원 |
| 퀵리플라이 | **13개**, 각 20자, 평문만 | 0 | API |
| 제네릭 템플릿 | 캐러셀 **10장**, 카드당 버튼 3 | 0 | API · 🎯디자인 자리 |
| Custom Keywords(댓글→DM) | **5키워드**·대소문자 구분 정확일치·**15분 지연** | 0 | Business Suite **데스크톱 전용** |
| 인스타 자체 AI (AI Auto Replies) | — | 0 | 🔴**결격** |
| 팔로우 조회 `is_user_follow_business` | — | 0 | User Profile API |

**🔴 인스타 자체 AI가 우리에게 결격인 이유** — Meta 자기 문서에 명시: **영어로 훈련**됐고, "AI가 만든 메시지는 정확하지 않거나 부적절할 수 있다". 지식 원천이 **인스타·스레드에 올린 콘텐츠**라 우리 가격표·시간표 정본을 넣을 자리가 없다. 몽골어로 상담하고 없는 숫자를 절대 지어내면 안 되는 학원에 정확히 반대 방향이다.

**✅ 팔로우 게이트는 우리도 된다** — ManyChat 전용 기능이 아니다. `GET /<IGSID>?fields=is_user_follow_business`로 boolean이 온다. 상담AI에 직접 붙일 수 있다.

### Meta가 강제하는 규칙 (도구 무관 · 설계 제약)

- **24시간 창** — 상대가 마지막으로 보낸 지 24시간 안에만 자유 전송. 밖은 승인 태그 필요.
- **댓글→DM은 댓글당 자동 DM 1통**, 7일 이내. 그 **첫 DM은 텍스트 전용**(버튼·퀵리플라이·첨부가 API에서 거부된다).
- 자동화는 **상대가 먼저 말을 걸었을 때만**. 콜드 DM 금지.

### 판정: ManyChat은 지금 사지 않는다

유호님이 지금 필요한 것(FAQ 나열·댓글→DM·팔로우 체크)은 **네이티브가 무료로 주거나 우리 코드로 된다.**
ManyChat이 진짜 이기는 자리는 둘뿐:

1. 댓글→DM의 정교함 — 퍼지 매칭("price"가 "pricing"도 잡음)·클릭 추적·15분 지연 없음·rate cap에서 큐잉
2. **Meta 앱 검수 우회** — 검수가 반려·지연되면 ManyChat을 **배관으로만** 쓰고 두뇌는 상담AI에 두는 우회로

비용은 월 $15~45(AI 애드온 $29 별도). 진짜 비용은 그게 아니라 **ManyChat GUI를 유호님이 만들고 유지한다**는 것 — 근무의 46%가 이미 콘텐츠 편집인 사람에게 도구가 하나 더 는다. 상담AI는 AI가 짜고 AI가 고친다.

## 3. 4단계 로드맵

### Phase 0 — 이번 주 · 무료 · 유호님 손 10분 · **봇 상태와 무관**

**목적은 성능이 아니라 「재기」다.** 지금 DM이 주당 몇 개 오는지 아무도 모른다(상담 로그 0건 · FAQ 정본 스스로 "이 질문 목록은 실측이 아니라 가설"이라고 표시).

- 인스타 FAQ 4개 + 페북 FAQ 4개 — **채널별로 다르게**
- 인스턴트 리플라이(첫 DM 자동 인사) + 부재중 메시지

**아이스브레이커 4칸 배치안** (FAQ 정본이 이미 학부모/학생으로 갈라져 있어 그대로 쓴다):

| 페북 = 학부모 | 인스타 = 학생 |
|---|---|
| 매주 몽골어로 자녀 리포트가 갑니다 (Q7) | 재밌어요? (S1) |
| 한 반에 몇 명인가요 (Q4·정원 16) | 앱에서 뭐 해요? (S2) |
| 언제 문을 여나요 (Q3·2027-02-11) | 저 하나도 모르는데 괜찮아요? (S3) |
| 상담 신청하기 | 한국인 선생님이랑 말해요? (S7) |

> 같은 4칸인데 채널당 적중률이 두 배가 된다. 학부모에게 "재밌어요?"는 낭비고, 학생에게 "리포트"는 관심 밖이다.

**게이트: 없음. 지금 당장 가능.**
**재는 것: 주당 DM 수 · 질문 분포 · 채널 비율.** Phase 1 이후 설계의 입력값이다.

---

### Phase 1 — 인계 회로를 사람이 쓸 수 있게 ← **진짜 1번**

②(개입당 시간)를 무한에서 유한으로 내린다. 이게 없으면 뒤의 모든 자동화가 무의미하다.

1. 인계 메일에 **한국어 번역**을 붙인다 (학부모 원문 + 번역 병기)
2. **답변 초안 3개를 한국어로** 같이 보낸다
3. 유호님이 고르면 → 봇이 몽골어로 발송
4. **24시간 창 상태를 메일에 표시** — 창이 닫혔으면 그렇게 알린다
   (창 계산·`MESSAGE_TAG` 처리 로직은 `만족도팩.js`에 **이미 있다** — 재사용)

**핵심 전환: 유호님이 답을 「쓰는」 게 아니라 「고른다」.** 개입당 시간이 분 → 초.

**재는 것: 인계율**(`상담로그` 시트에 '인계' 열이 **이미 있다**) · 인계당 처리 시간.

---

### Phase 2 — 인스타 배선 + 버튼·카드층

1. `상담_정규화_`에 **`object === 'instagram'` 분기** 추가 (§1-②)
2. `상담_전송_`에 **퀵리플라이 + 제네릭 템플릿** 지원 추가 (현재 `message:{text}`만)
3. **팔로우 게이트** — `is_user_follow_business` 조회

**게이트: Meta 앱 검수**(`pages_messaging` + `instagram_manage_messages`). 검수 전엔 관리자·테스터에게만 답장이 간다 → **광고 켜기 전에 신청해야 한다.**

---

### Phase 3 — 지식 복리 (여기서부터 탄력이 붙는다)

- 유호님이 인계에서 답한 것 → **지식 블록으로 승격**(초기엔 수동, 반복되면 자동)
- **성공 기준 = 「같은 질문에 두 번 답하지 않는다」**
- 상담로그 실측으로 **FAQ 정본의 질문 목록을 교체**(가설 → 실측)

> 문서를 다 쓰고 봇을 붙이는 통념 대신, 봇을 먼저 열고 못 답한 질문의 답을 지식으로 굳힌다.
> 문서화가 별도 프로젝트가 아니라 평소 답변의 부산물이 된다.

---

### Phase 4 — 상담이 등록으로

- 인계·상담 → **크루카드 접수 웹앱**(이미 라이브)으로 연결
- `leads` → 학생ID 자동 발급(이미 있음)

## 4. 브랜드 키트 — 어디에 들어가고 어디에 안 들어가는가

🔴 **DM 텍스트에는 폰트를 지정할 수 없다.** SUIT·Inter Tight·DM Mono가 DM 말풍선 안에서 렌더링되는 일은 없다 — 상대방 폰 기본 폰트로 나간다. **ManyChat을 사도 동일하다. "매니챗이 더 예쁘다"는 착시고, 둘 다 같은 Meta 포맷으로 나간다.**

브랜드가 실제로 들어가는 자리는 넷:

| 자리 | 적용 범위 | 만드는 곳 |
|---|---|---|
| **제네릭 템플릿 카드 이미지** | 🎯 폰트·색 **100%** — 유일하게 다 들어감 | 코드 통로 `tools/lib/loom.js` + `tools/시안굽기.js` |
| 프로필 사진 · 하이라이트 커버 | 색 · 워드마크 | 코드 통로 (같음) |
| **말투 · 보이스** | 게임화 세계관 · "실패" 금칙 | 🎯 **상담AI가 이기는 자리** |
| 아이스브레이커 4개 문구 | 톤 | Business Suite |

세 번째가 중요하다 — 고정 문구로는 브랜드 보이스를 못 싣는다. "기획 → 도전 → 다시 → 완성" 같은 말투는 **대본 밖 질문에 답할 때** 살아나고, 그게 정확히 ManyChat이 막다른 길로 보내는 자리다.

## 5. 🔥 도전안 — 가장 싼 상담은 일어나지 않는 상담이다

통념: "DM 자동화 도구를 잘 골라 자동화율을 올린다."
**뒤집기: 자동화는 「온 DM」을 처리한다. 안 오게 하는 게 더 싸다.**

✅ 13개 답 가능한 질문을 **하이라이트 · 고정 게시물 · 링크인바이오**에 박는다.

- 비용 **0** · 24시간 창 **없음** · 몽골어 검수 **1회로 영구 확정** · Meta 검수 **불필요**
- 자동화율(①)을 올리기 전에 **분모 자체를 줄인다**

**그리고 Meta 규칙이 오히려 이 방향을 강제한다** — 댓글→DM의 첫 메시지는 텍스트 전용에 1통뿐이라 화려한 걸 담을 수 없다. 그러니 그 1통은 "열어보고 싶게 만드는 한 문장 + 링크"여야 하고, **브랜드는 링크 너머에서 터진다**(크루카드 접수 웹앱 — 이미 라이브 · 브랜드 키트 100% · 진짜 폰트가 렌더링되고 데이터가 우리 시트에 쌓인다).

> DM 안에서 예쁘게 만들려고 싸우지 말고, **예쁜 곳으로 데려온다.**
