## 0. 사용자가 정한 목적

Core는 별도 출시 앱이 아닌 회사 내부 엔진이다. 한 사람을 이해하고, 그 사람에게 맞는 로드맵과 배움을 제공하며, 실제로 도움이 된 방법을 다음 경험에 반영한다. 첫 교육 대상은 몽골 학생의 한국어 학습이다. 회화·유학·직업별 학습과 내부 도구에서도 필요한 부품을 재사용한다.

목적은 **개인 이해 → 로드맵 → 학습 → 실제 도움 확인**이다. 현재 제품의 완성을 우선하면서 공통 부품을 함께 발전시킨다. “SYNK.MD”는 회사의 뇌라는 비유이며 학생 기억을 Git 파일에 담으라는 뜻이 아니다.

## 1. 구성 — 코어와 내부 관리 화면

- **코어:** 회사 지식·학습 원본·개인화를 연결하고 제품이 필요한 맥락을 꺼내 쓴다.
- **관리 화면:** 사람이 지식의 출처·관계·판본을 읽고 고친다. 현재 방향은 시트 편집과 옵시디언처럼 연결을 볼 수 있는 화면이다. 학생 원본을 일반 지식 화면에 함께 노출하지 않는다.

## 2. 공통 엔진의 값

검증된 지식과 개인화 개선을 여러 제품이 재사용한다. 잘못된 지식도 함께 퍼질 수 있으므로 출처·판본·발행 상태와 회수 경로를 둔다. 공통 부품 수정과 각 제품의 실제 반영을 구분한다.

## 3. 현재 기반

<a id="core-atlas-ownership"></a>
### 3-1. Atlas 안에서 Core가 소유하는 구현

Atlas는 [기존 8개 엔진의 총칭](아틀라스_설계.md#atlas-engine-ownership)이다. 다음 판단 계산은 경로가 `atlas/`여도 Core의 담당 원본이다(2026-10-02 책임 정리).

| 현재 원본 | Core가 발전시킬 부분 | 연결 경계 |
|---|---|---|
| [engine.js](../atlas/engine.js) | `understand`의 이해 요약, `decide/choice`의 선택 계산 | `createSession`·사건 검증/추가는 공통 호출 입구. `practice.*`의 계보 검증은 Trail에 위임 |
| [education.js](../atlas/education.js), [learning.js](../atlas/learning.js) | 문항 근거 연결·수행 요약·학습 필요와 후보 우선순위 | Strata의 내용 지도와 Trail의 수행 근거를 읽고, Vellum이 안내를 표현. 추천 점수는 공식 급수·교육 효과가 아님 |
| [work.js](../atlas/work.js) | 본인이 밝힌 업무 조건의 정규화·사람이 선택한 팀의 조건 대조 | 회사 호스트가 인증·공유·저장 담당. LAB 학생 기록과 결합하지 않음 |

`game-learning.js`·`game-browser.js`·`learning-sync.js`는 엔진과 게임·저장 호스트를 잇는 연결 코드다. 연결 수정만 했으면 그 범위로 보고한다. NPC의 사실에 맞는 말·행동 선택은 Vellum, 경험·정정·전달의 시간 연결은 Trail, 실제 표현은 Loom/Reed의 담당 원문을 발전시킨다. Core에 모든 기능을 모으지 않는다. 현재 경로와 공개 이름의 호환성을 유지하며, 기능을 분리할 필요가 생겼을 때만 실제 호출·시험을 함께 옮긴다.

**2026-10-02 구현 점검:** 공통 회차는 생성 시 주체·작업공간·사업 범위를 복사해 고정한다. 호출자가 계정 전환에 같은 입력 객체를 재사용해도 기존 회차의 소유자가 바뀌지 않으며, 반환된 상태·사건·결정을 수정해도 내부 기록에 반영되지 않는다. `learning-priority-3`는 후보의 문항 ID·`itemKey`와 함께 `familyKey`를 비교해 보기만 바뀐 같은 문항 계열의 연속 추천을 줄인다. 이력은 추천 한 번에 한 번 색인하며 겹치는 세 식별자는 같은 노출 한 번으로 센다. 조작·시각 유도·체험·음성 또는 저장 실패 등 제외 사유가 있는 응답은 도움을 받고 맞혔더라도 한국어 수행 성공으로 요약하지 않는다. 실제 수행 근거·형식별 진단·급수 미추정 기준은 그대로 유지한다. [회귀 시험](../tests/atlas-core-boundaries.test.js)은 소유 범위 고정·같은 계열 회피·제외 사유 처리를 확인하며 실제 학생 효과를 측정한 것이 아니다.

<a id="common-personalization-foundation"></a>
### 3-2. 모든 사용자를 위한 공통 개인화 계약 — 2026-10-02

학생·교사·기업 실무자·제작 고객·일상 도구 이용자가 재사용하는 원본은 [atlas/personalization.js](../atlas/personalization.js)다. **Core의 순수 어댑터**이며, 판단은 기존 [engine.js](../atlas/engine.js)의 `createSession().plan`으로 실행한다. 아홉 번째 엔진·중앙 개인정보 저장소·LLM 실행기를 추가한 것이 아니다. 회사 방향과 학생·교사에게 돌려주는 구체적인 도움은 [전사용자 개인화 기반](SYNK_전사용자_개인화_기반_20261002.md)에 둔다.

현재 어댑터 스키마는 `core-personalization-1`, Core 선택 정책은 `atlas-2.4.0`이다. 이전 `atlas-1.0.0`·`2.0.0`·`2.1.0`·`2.2.0`·`2.3.0` 사건도 읽지만 새 결정은 새 정책판으로 기록한다. CommonJS는 `require('./atlas/personalization')`, 브라우저는 `engine.js` 뒤에 모듈을 읽어 `SynkAtlasPersonalization`을 사용한다. 제품 사본은 원본을 복사하며 제품마다 같은 선택 로직을 다시 만들지 않는다.

| 계약 | 현재 구현과 제품 호스트의 책임 |
|---|---|
| 개인과 이용 맥락 | `scope = {personId, productId, contextId, domain}`. 같은 사람이라도 제품·맥락·사업이 다른 프로필이나 사건을 전달하면 거부한다. 식별자는 호스트가 권한을 확인하여 정하며 이름·연락처를 이 모듈에 넣지 않는다 |
| 공통 제품 범위 | Core에 `SYNK` 도메인을 추가했다. 기존 `LAB`·`SHIFT`·`PATH`·`PULSE`를 유지한다. `SYNK`는 플랫폼 등 공통 제품의 별도 범위이며 모든 사업 자료를 합칠 권한이 아니다 |
| 직접 선택하는 값 | 목표 `goal`, 시간 `minutes`, 익숙함의 자기보고 `experience`, 원하는 도움 `support`, 현재 소리 환경 `audio`, 글자 `textSize`, 설명량 `explanation`, 움직임 `motion`. 나이·성별·진단·고정 성격·추정 능력을 받거나 대신 추론하지 않는다 |
| 최소 수집·미응답 | `createProfile`은 값이 없는 `new` 상태로 시작한다. 미응답을 답변으로 저장하지 않는다. 표시 기본값은 별도 계산하며 기본값에 자기보고 출처를 붙이지 않는다. 무응답·건너뛰기에도 기본 후보를 고를 수 있고 근거는 `cold-start`, 신뢰도는 `unknown`으로 반환한다 |
| 동의·출처 | `updateProfile(profile, {values, consent:true}, at)`로 명시 동의한 범위만 기억한다. 값별 출처는 `self-declared`, 신뢰도는 `declared`, 입력 시각과 revision을 보존한다. 이 표기는 사실·실력의 측정 확률이 아니다. 저장 동의가 없으면 선택은 임시이며 반환 사건 배열은 비어 있다 |
| 수정·철회·삭제 | 값 수정, 개별 값의 `null` 삭제, `clearProfile`의 `skip`·`disable`·`delete`를 지원한다. 전체 철회·삭제는 값과 출처를 비우고, 삭제나 재동의 때 generation을 나누어 과거 사건이 되살아나지 않게 한다. 호스트는 저장된 이전 값·사건도 교체·삭제해야 하며 최소 revision 표식 자체를 삭제 이행으로 대신하지 않는다 |
| 실제 선택 | `selectPersonalization({profile, scope, candidates, experienceId, events, at})`가 Core 결정·사건·추천 이유·출처·표현 설정을 반환한다. 후보에는 ID·시간·진행량·목표·소리 필요 여부·허용 경험·지원 도움 방식만 받으며 고객 원문 등 추가 자료는 거부한다. 분야별 후보와 그 뜻은 제품이 제공한다 |
| 선호와 실행 조건 | 정확한 시간 상한, 소리 사용 불가, 후보의 `supports`와 명시 도움 방식의 일치를 우선한다. TOPIK 목표가 같아도 ‘먼저 혼자’는 단계별 안내 전용 후보에 밀리지 않는다. 실행 가능한 후보가 없으면 `unavailable`이며 가짜 대체 활동을 만들지 않는다 |
| 후속 의견 | 실제 추천 사용을 확인하여 `recordCompletion`을 기록한 뒤 `recordFeedback`을 연결한다. `helpful`·`not_fit`·`too_much`·`want_more`는 자기보고다. 최신 `not_fit` 대상에 실행 가능한 대안이 있으면 다음 Core 선택은 다른 방법으로 바뀌며, 없으면 이유 `feedback.no_alternative`를 남긴다. 의견을 교사 평가·학생 실력·효과 측정으로 승격하지 않는다 |
| PULSE 경계 | 제작 고객이 밝힌 목표·시간·설명 선호는 사용할 수 있다. 기존 PULSE의 개인 행동 관측 금지는 유지하며 이 어댑터의 사용 완료·개인 의견 학습 통로도 PULSE에서는 거부한다 |

현재 직접 소비처는 [플랫폼 개인화 연결](../desktop/renderer/personalization.mjs)과 [교사·학생 로컬 모델](../experiences/teacher-world/model.mjs)이다. 플랫폼은 `SYNK / anonymous-local / platform / launcher`의 기기 내 설정으로 제품 목록·추천과 표현을 바꾼다. 교사·학생 모델은 신뢰한 로컬 역할·개인 범위에서 수업안·연습 방식에 연결하고, 조회 때마다 새 결정을 만드는 대신 저장·사용 확인·의견 같은 변경 시 결정과 사건을 갱신한다. 교사 자신의 설정과 담당 학생의 수행 자료는 서로의 성향 자료로 합치지 않는다.

Trail의 문항 출처·도움·첫 노출, Strata의 내용 지도, Vellum의 도움과 이유 표현, Temper의 수행 검증은 각 담당 계약을 유지한다. 공통 설정이 한국어 정답 기준을 바꾸거나 레이싱 조작·리듬 타이밍을 언어 실력으로 바꾸지 않는다. 회사 집계·모델 훈련·다른 제품의 공유 동의도 이 설정 동의에서 자동으로 얻지 않는다.

검증은 [공통 개인화 시험](../tests/atlas-personalization.test.js) 20개와 기존 Atlas·Strata·동기화를 합한 **204/204 로컬 회귀시험**이다. 서로 다른 명시 목적, 같은 목적의 역할 독립성, 시간·소리·도움 조건, cold start, 범위 침범, 원문 추가, 철회 뒤 과거 사건, PULSE, 사용 뒤 실제 추천 변경을 확인했다. **정식 가입·운영 계정 동기화·전 제품 반영·공개 배포·실사용자 효과까지 완료한 것은 아니다.** 운영 계정에 연결할 때는 서버 인증·목적별 동의·동시 수정·저장 실패·삭제 전파를 해당 제품 계약으로 구현하고 별도 검증한다.

## 4. 아키텍처와 방법 선택

| 부품 | 맡는 일 |
|---|---|
| 지식 그래프 | 출처·유효범위·관계가 있는 회사 지식을 검색 |
| 학습자 모델 | 학생의 수준·약점·선택·목표와 현재 상태를 근거로 계산 |
| 오류·교정 말뭉치 | 원문과 교정·검수·용도·계보를 연결 |
| AI 게이트웨이 | 맥락 검색, 입력 조립, 모델 호출, 실패 시 기본 동작 |

원본은 통제 가능한 저장소에 두고 모델은 교체 가능한 부품으로 둔다. 지식은 검색하여 넣는 방식을 기본으로 하며, 일반론을 무조건 쌓지 않고 회사에 필요한 내용·모델이 반복해 틀리는 내용·대외 약속을 우선한다.

벡터 검색·지식 저장 방식·파인튜닝·숙련도 추정법을 과거 규모나 벤더 상태로 영구 금지하지 않는다. 대표 과제의 품질·회수 가능성·데이터와 평가 자료·운영 부담을 확인해 선택한다. 특정 모델명·문항 수·고정 호출 순서는 [AI 운영 원칙](AI_운영원칙.md)과 현재 모델 정책에 맡긴다.

모델 API 호출과 비밀키는 서버에 둔다. 기존 Apps Script의 관리자 전역 함수를 학생용 화면에 열지 않으며, 새 관리·게이트웨이 화면은 권한이 분리된 서버 통로로 구현한다.

## 5. 구현 우선순위

**2026-09-19 전면 재설계:** [아틀라스 설계](아틀라스_설계.md)는 학습 경험과 환경 변화를 기록하고, 현재 상태를 계산해 다음 도움을 고른 뒤 결과를 다시 반영하는 구조다. 학습 기록, 이해 요약, 결정 묶음을 이 과정에서 함께 사용한다. LAB의 학습 기록 저장은 제품의 승인된 저장 통로가 맡고, Trail은 경험의 시간 관계를 연결한다. Core는 그 기록으로 학습자의 현재 상태와 판단 근거를 요약하고 다음 경험을 고른다. 계정이 없는 이용자의 사건 기록은 기기에 저장한다. 배울 내용의 구조는 여덟째 엔진 [Strata](Strata_설계.md)가 관리한다. LAB의 대표 경험부터 완성하되, 다른 사업의 고객·관객에게 학생 모델을 일괄 적용하지 않는다. 개인에게 맞추는 일과 선택 방법 자체를 개선하는 일은 구분하며, 둘 다 자동으로 진행할 수 있도록 설계한다.

1. 첫 실제 입력 전에 원본·당시 문항·선택·개입 ID·시각·기준판이 남도록 한다.
2. 소비자가 자동으로 읽고 다음 과제·답장·도움이 달라지는 경로를 제품과 함께 완성한다.
3. 검증된 부품을 다른 제품으로 확장하고 실제 결과로 개선한다.

E0·E1·E2·E3는 옛 계획을 찾는 이름이다. “E0는 코드 0줄”, “파생은 만들지 않는다”, 특정 연차·첫 시즌이 지나야 착수한다는 문장은 현재 개발의 금지 조건이 아니다. 파생은 재계산 가능하게 유지하며, 성능상 저장이 필요하면 원본·기준판·무효화 경로와 함께 설계한다.

지식 원천 이관은 손편집 원본, 이관 전 스냅샷, 소비자 전환과 복구 경로를 함께 다룬다. 운영 중인 상담 답변의 원천을 문서만 바꾸고 교체 완료라고 하지 않는다.

## 6. 데이터·동의·원본 경계

- 학생 식별 데이터는 Git이나 외부 모델 입력에 두지 않는다. 비식별 원문은 허용 범위에서 활용하되 문장 속 이름·학교·날짜·소수 집단 맥락도 확인한다.
- 학생 원본 음성을 전사·교정으로 대체하거나 임의 표본화하지 않는다. 보관·사용·철회·파기는 현행 동의와 데이터 계약을 함께 따른다. 보존은 정정·철회·파기를 막는 절대 불변이 아니다.
- 동의 절차는 간략한 현재 통로를 재사용한다. 개인 서비스·회사 집계·훈련·평가·공개를 자동으로 같은 용도로 합치지 않는다. 실제 동의·권한·서비스 보호 절차는 유지한다.
- 원본 행의 신분을 `privacy_class` 같은 값으로 바꾸지 않는다. 회사 집계는 별도 비식별 산출물이고 훈련·평가 승격과 철회는 별도 사건이다(부록 A-10).

상세 경계는 [철학 적용 기준 §3](철학_적용기준.md#3-데이터와-엔진의-상세-경계)과 talk 동의·L0 계약을 따른다.

## 7. 지식 관리

현재 선택은 시트 편집면과 서버가 읽는 지식 인덱스의 분리다. 지식 노트의 출처·발행·회수·판본을 함께 관리한다. 관리 화면이나 저장 매체를 발전시킬 때는 이 요구와 실제 운영을 기준으로 판단하며 과거 기각 제목 자체를 금지 목록으로 쓰지 않는다.

## 8. 관련 정본과 결정

제품 목적은 [제품방향](제품방향.md), 회사 목적은 [철학](SYNK_철학.md), 화면은 [DESIGN](../DESIGN.md), 실행은 [AI 운영 원칙](AI_운영원칙.md), 남은 일은 [트랙](_ops/트랙.md)에 둔다. 관리 화면 형태·몽골 학생의 한국어 학습이라는 뜻·성향 확인 사건은 이미 결정된 내용이며 다시 승인 대기로 올리지 않는다.

## 9. 회사가 배우는 재료

| 재료 | 보존할 맥락 |
|---|---|
| 지식 | 출처·유효범위·판본·관련 링크 |
| 운영 경험 | 상황·선택·이유·결과 |
| 선호와 선택 | 보여준 후보·추천·순서·실제 선택·건너뜀·물었는지 여부 |
| 학습 원본 | 문항과 제시판·응답·도움 여부·시각·검수 출처 |
| 호출·개입 | 모델·프롬프트 판·인용한 원문 판·선택 규칙·후속 관측 고리 |

분류는 필요한 기록을 찾는 지도다. 모든 분류마다 새 시스템·테이블을 만들 의무는 없다. 새 필드는 계약과 생산자·소비자를 맞추고, 재계산할 수 있는 파생은 필요 시 구현한다.

시트 퀴즈의 과거 보기 판정: 보기 없는 주관식과 보기 누락을 구분한다. 원문 안의 보기는 `①②` 마커로 추출하며 dash를 구분자로 쓰지 않는다. 응답 시점의 문항 스냅샷·판본은 별개 요구다. 오래된 시트 실측을 현재 문항의 완전성 증거로 삼지 않는다.

## 10. 학습자 모델 — 사실·추정·학생 확인을 가른다

리듬·끈기·자기인식·피드백 수용·관심과 목표는 출발점이다. 축의 현재 목록과 계산은 talk `lib/학습자상태.js`를 따른다. 축 개수·과거 무자료 상태를 확장의 상한으로 삼지 않는다.

### 기록 규격

| `source_kind` | 의미 |
|---|---|
| `explicit` | 학생이 직접 말하거나 선택한 사실 |
| `teacher` | 강사·검수자가 확인한 내용 |
| `observed` | 직접 관측한 행동·결과 |
| `inferred` | AI 추정; 사실로 저장하지 않음 |

추정에는 `estimator_confidence`·`evidence_refs`·`estimator_version`과 유효 시점을 연결한다. 학생 확신도 `confidence`, AI 추정 신뢰도, 검수자 신뢰도를 합치지 않는다. 현재 talk `학습자상태`의 `estimator_confidence`는 표본 충분도이며 정확도 확률이 아니다. 원신호는 보존하고 성향은 **현재 상태와 근거**로 다시 계산한다. 오래된 목표나 한 판의 행동을 고정 성격으로 만들지 않는다.

과거 개입을 평가할 때 상태 계산은 `as_of ≤ intervention.delivered.occurred_at`를 지키고 `ingested_as_of`도 고려한다. 미래에 들어온 자료로 그때의 선택을 설명하지 않는다.

### 묻기와 되돌려주기

관찰로 알 수 있는 것은 활동에서 얻고, 목표·제약·직접 선호는 필요한 순간에 묻는다. [첫 로그인 개인화](첫로그인_마스코트추천_개인화_설계_v1.md)의 선택 설문은 09-09 채택된 현재 방향이다. 옛 “설문 0·가입 5~7문항”을 상한으로 적용하지 않는다.

학생의 확인은 `estimate.responded` 사건을 더한다. 원래 추정 행의 `user_confirmed` 열을 뒤집지 않는다. “아니야”로 부정한 주장에 해당하는 지표는 다음 생성 재료에서 빼되 원관측과 정정 이력은 남긴다. 코드 원천은 `lib/성향확인.js`·`lib/과제요약.js`·`functions/progress`다. 현재 상한은 해당 코드의 `하루상한`에서 읽는다(09-13 확인: 두 장). 목표 자기 신고 `goal.responded`는 별개 사건이다.

### 개인화가 효과 있었나

**학생 상태 → 고른 지도 방식 → 실제 전달·반응 → 후속 수행**을 개입 ID와 시각으로 잇는다. 현재 성과 창과 관측 규격은 talk `lib/성과회수.js`가 정한다. `content.viewed.parent_event_id`가 실제로 본 개입 사건을 가리킨다. `미도래`·`표본0`을 효과 0으로 바꾸지 않고 길이가 다른 창을 단순 차감하지 않는다.

성과 계산과 다음 선택에 대한 되먹임은 다르다. 09-13 코드 대조에서 `deliver`는 `회수요약`을 호출하지만 계수는 응답에 실리는 단계다. 다음 선택의 실제 변화와 `degraded` 개입 분리 소비는 추가 구현·검증이 필요하다. 개입-효과 짝의 회사 훈련 이용에는 [엔진 도달](엔진도달_설계.md) 경로 B를 적용한다.

## 부록 A — 계약으로 내려가는 요구

**A-0. 원천:** 필드·필수값·값목록·스키마 판은 수집·교정 계약과 talk L0·C0·마이그레이션이 정한다. 아래 설명을 별도 물리 계약으로 쓰지 않는다.

1. **A-1 이름공간:** 학생 원본과 학습 데이터는 권한을 가진 `engine.*`에 둔다. 지식 인덱스와 학생 원본의 공개 범위를 분리한다.
2. **A-2 서버 호출:** API 키는 서버에만 두고 앱 인터페이스·오류·버전 정책을 계약으로 유지한다.
3. **A-3 외부 처리:** 식별자와 비식별 학습 원문, 원본 음성의 승인 통로를 구분한다(§6).
4. **A-4 기본 동작:** 엔진 실패 시에도 제품이 기본 동작을 제공한다. 해당 행에는 `degraded`·`generation_outcome`을 남기고 AI 성공 성과와 구분한다.
5. **A-5 지식 회수:** 출처·갱신일·유효범위·발행/회수 상태를 둔다. 철회한 지식은 다음 소비에서 제외한다. 첫 RAG 사용부터 인용 당시 내용을 재현할 수 있어야 한다. 제안 규격은 `cited_refs`에 노트 ID와 `content_hash`, 관계에 `{from,to,kind}`를 두는 것이며 실제 형태는 지식 계약에서 확정한다.
6. **A-6 철회 전파:** 원본과 파생·산출물·데이터셋·모델 계보를 따라 해당 철회를 처리한다.
7. **A-7 평가:** 훈련과 독립된 평가셋으로 모델·프롬프트 변경을 판단한다. 분모와 기준판은 talk `evals/픽스처.json`·평가 도구에서 읽고 합성 결과를 학생 효과로 부르지 않는다.
8. **A-8 스키마 판:** 수집 행에 `schema_ver`를 남긴다. Apps Script `SCHEMA_VER`와 계약 버전의 일치를 기존 계약 검사로 확인하며 과거 행의 미상 판을 지어 채우지 않는다.
9. **A-9 실제 사용 준비:** 첫 실제 데이터 전에 운영 환경의 복구·백업·접근·왕복을 확인한다. 특정 요금제의 과거 기능을 영구 유료 전환 의무로 옮기지 않는다. 신규 지출은 AI 운영 원칙을 따른다.
10. **A-10 원본 고리:** 아래 요구를 유지한다.
    - **선택:** 제시 후보·순서·추천·선택·바꿈·지연·건너뜀·당시 맥락을 기록한다. `previous_selection`·`reason_asked`는 추가 구현 후보이며 기존 계약 필드로 단정하지 않는다.
    - **반응:** 무반응은 응답 행 부재, “무시”는 학생의 명시적 응답이다. 늦은 응답을 임의 기한으로 영구 무응답 처리하지 않는다.
    - **기준과 고리:** `skill_id`, 개입 ID, 당시 문항·인용판, 발생/적재 시각을 보존한다. 멱등 범위와 충돌 처리는 L0·C0를 따른다.
    - **용도:** 원본은 개인용, 회사 집계는 별도 비식별 산출물, 훈련·평가 승격은 `data_use.granted`, 철회는 `data_use.revoked`로 다룬다. 행 자격 플래그로 대체하지 않는다.
