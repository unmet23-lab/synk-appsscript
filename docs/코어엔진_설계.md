>
> E0 코드 0줄·고정 연차·과거 모델 사정·끝난 승인 대기와 재제안 금지는 현행 지침에서 제거했다. 원본과 계약을 지키며 현재 요청·새 근거로 방법을 발전시킨다. 구술·검토 경위는 [정리 전 고정판](https://github.com/unmet23-lab/synk-appsscript/blob/f657502b1c85/docs/코어엔진_설계.md)에 남아 있다.

## 0. 사용자가 정한 목적

Core는 별도 출시 앱이 아닌 회사 내부 엔진이다. 한 사람을 이해하고, 그 사람에게 맞는 로드맵과 배움을 제공하며, 실제로 도움이 된 방법을 다음 경험에 반영한다. 첫 교육 대상은 몽골 학생의 한국어 학습이다. 회화·유학·직업별 학습과 내부 도구에서도 필요한 부품을 재사용한다.

목적은 **개인 이해 → 로드맵 → 학습 → 실제 도움 확인**이다. 현재 제품의 완성을 우선하면서 공통 부품을 함께 발전시킨다. “SYNK.MD”는 회사의 뇌라는 비유이며 학생 기억을 Git 파일에 담으라는 뜻이 아니다.

## 1. 구성 — 코어와 내부 관리 화면

- **코어:** 회사 지식·학습 원본·개인화를 연결하고 제품이 필요한 맥락을 꺼내 쓴다.
- **관리 화면:** 사람이 지식의 출처·관계·판본을 읽고 고친다. 현재 방향은 시트 편집과 옵시디언처럼 연결을 볼 수 있는 화면이다. 학생 원본을 일반 지식 화면에 함께 노출하지 않는다.

## 2. 공통 엔진의 값

검증된 지식과 개인화 개선을 여러 제품이 재사용한다. 잘못된 지식도 함께 퍼질 수 있으므로 출처·판본·발행 상태와 회수 경로를 둔다. 공통 부품 수정과 각 제품의 실제 반영을 구분한다.

## 3. 현재 기반

| 기반 | 실제 확인할 원천 |
|---|---|
| 시트 지식과 상담 맥락 | `엔진_두뇌.js`·`상담AI.js`·두뇌지식 운영 원천 |
| 학습 수집·교정 | `엔진_수집.js`·`엔진_콘텐츠AI.js`·`교재연동.js`와 수집·교정 계약 |
| 앱 상태·과제·답장 | talk `lib/학습자상태.js`·`lib/오늘과제.js`·`lib/과제요약.js`·`supabase/functions/deliver` |
| 개입과 후속 관측 | talk `lib/성과회수.js`·`tools/성과계기판.js` |
| 학생의 정정 | talk `lib/성향확인.js`·`lib/동의율.js`·`supabase/functions/progress` |

파일 존재·합성 시험·운영 배포·실제 수혜는 각각 확인한다. 예전 “학생 0명”이나 “소비자 0”는 오늘의 상태를 대신하지 않는다.

## 4. 아키텍처와 방법 선택

| 부품 | 맡는 일 |
|---|---|
| 지식 그래프 | 출처·유효범위·관계가 있는 회사 지식을 검색 |
| 학습자 모델 | 학생의 수준·약점·선택·목표와 현재 상태를 근거로 계산 |
| 오류·교정 말뭉치 | 원문과 교정·검수·용도·계보를 연결 |
| AI 게이트웨이 | 맥락 검색, 입력 조립, 모델 호출, 실패 시 기본 동작 |

원본은 통제 가능한 저장소에 두고 모델은 교체 가능한 부품으로 둔다. 지식은 검색하여 넣는 방식을 기본으로 하며, 일반론을 무조건 쌓지 않고 회사에 필요한 내용·모델이 반복해 틀리는 내용·대외 약속을 우선한다.

벡터 검색·지식 저장 방식·파인튜닝·숙련도 추정법을 과거 규모나 벤더 상태로 영구 금지하지 않는다. 대표 과제의 품질·회수 가능성·데이터와 평가 자료·운영 부담을 확인해 선택한다. 특정 모델명·문항 수·고정 호출 순서는 [AI 운영 원칙](AI_운영원칙.md)과 현재 모델 정책에 맡긴다.

모델 API 호출과 비밀키는 서버에 둔다. 기존 Apps Script의 관리자 전역 함수를 학생용 화면에 열지 않으며, 새 관리·게이트웨이 화면은 권한이 분리된 서버 통로로 구현한다.

## 5. 구현 우선순위

1. 첫 실제 입력 전에 원본·당시 문항·선택·개입 ID·시각·기준판이 남도록 한다.
2. 소비자가 자동으로 읽고 다음 과제·답장·도움이 달라지는 경로를 제품과 함께 완성한다.
3. 검증된 부품을 다른 제품으로 확장하고 실제 결과로 개선한다.

E0·E1·E2·E3는 옛 계획을 찾는 이름이다. “E0는 코드 0줄”, “파생은 만들지 않는다”, 특정 연차·첫 시즌이 지나야 착수한다는 문장은 현재 개발의 금지 조건이 아니다. 파생은 재계산 가능하게 유지하며, 성능상 저장이 필요하면 원본·기준판·무효화 경로와 함께 설계한다.

지식 원천 이관은 손편집 원본, 이관 전 스냅샷, 소비자 전환과 복구 경로를 함께 다룬다. 운영 중인 상담 답변의 원천을 문서만 바꾸고 교체 완료라고 하지 않는다.

## 6. 데이터·동의·원본 경계

- 학생 식별 데이터는 Git이나 외부 모델 입력에 두지 않는다. 비식별 원문은 허용 범위에서 활용하되 문장 속 이름·학교·날짜·소수 집단 맥락도 확인한다.
- 학생 원본 음성을 전사·교정으로 대체하거나 임의 표본화하지 않는다. 보관·사용·철회·파기는 현행 동의와 데이터 계약을 함께 따른다. 보존은 정정·철회·파기를 막는 절대 불변이 아니다.
- 동의 절차는 간략한 현재 통로를 재사용한다. 개인 서비스·회사 집계·훈련·평가·공개를 자동으로 같은 용도로 합치지 않는다. 실제 동의·권한·서비스 보호 절차는 유지한다.
- 원본 행의 신분을 `privacy_class` 같은 값으로 바꾸지 않는다. 회사 집계는 별도 비식별 산출물이고 훈련·평가 승격과 철회는 별도 사건이다(부록 A-10).

상세 경계는 [철학 적용 기준 §3](철학_적용기준.md#3-데이터와-엔진의-상세-경계)과 talk 동의·L0 계약을 따른다.

## 7. 지식 관리

현재 선택은 시트 편집면과 서버가 읽는 지식 인덱스의 분리다. 지식 노트의 출처·발행·회수·판본을 함께 관리한다. 관리 화면이나 저장 매체를 발전시킬 때는 이 요구와 실제 운영을 기준으로 판단하며 과거 기각 제목 자체를 금지 목록으로 쓰지 않는다.

## 8. 관련 정본과 결정

제품 목적은 [제품방향](제품방향.md), 회사 목적은 [철학](SYNK_철학.md), 화면은 [DESIGN](../DESIGN.md), 실행은 [AI 운영 원칙](AI_운영원칙.md), 남은 일은 [트랙](_ops/트랙.md)에 둔다. 관리 화면 형태·몽골 학생의 한국어 학습이라는 뜻·성향 확인 사건은 이미 결정된 내용이며 다시 승인 대기로 올리지 않는다.

## 9. 회사가 배우는 재료

| 재료 | 보존할 맥락 |
|---|---|
| 지식 | 출처·유효범위·판본·관련 링크 |
| 운영 경험 | 상황·선택·이유·결과 |
| 선호와 선택 | 보여준 후보·추천·순서·실제 선택·건너뜀·물었는지 여부 |
| 학습 원본 | 문항과 제시판·응답·도움 여부·시각·검수 출처 |
| 호출·개입 | 모델·프롬프트 판·인용한 원문 판·선택 규칙·후속 관측 고리 |

분류는 필요한 기록을 찾는 지도다. 모든 분류마다 새 시스템·테이블을 만들 의무는 없다. 새 필드는 계약과 생산자·소비자를 맞추고, 재계산할 수 있는 파생은 필요 시 구현한다.

시트 퀴즈의 과거 보기 판정: 보기 없는 주관식과 보기 누락을 구분한다. 원문 안의 보기는 `①②` 마커로 추출하며 dash를 구분자로 쓰지 않는다. 응답 시점의 문항 스냅샷·판본은 별개 요구다. 오래된 시트 실측을 현재 문항의 완전성 증거로 삼지 않는다.

## 10. 학습자 모델 — 사실·추정·학생 확인을 가른다

리듬·끈기·자기인식·피드백 수용·관심과 목표는 출발점이다. 축의 현재 목록과 계산은 talk `lib/학습자상태.js`를 따른다. 축 개수·과거 무자료 상태를 확장의 상한으로 삼지 않는다.

### 기록 규격

| `source_kind` | 의미 |
|---|---|
| `explicit` | 학생이 직접 말하거나 선택한 사실 |
| `teacher` | 강사·검수자가 확인한 내용 |
| `observed` | 직접 관측한 행동·결과 |
| `inferred` | AI 추정; 사실로 저장하지 않음 |

추정에는 `estimator_confidence`·`evidence_refs`·`estimator_version`과 유효 시점을 연결한다. 학생 확신도 `confidence`, AI 추정 신뢰도, 검수자 신뢰도를 합치지 않는다. 현재 talk `학습자상태`의 `estimator_confidence`는 표본 충분도이며 정확도 확률이 아니다. 원신호는 보존하고 성향은 **현재 상태와 근거**로 다시 계산한다. 오래된 목표나 한 판의 행동을 고정 성격으로 만들지 않는다.

과거 개입을 평가할 때 상태 계산은 `as_of ≤ intervention.delivered.occurred_at`를 지키고 `ingested_as_of`도 고려한다. 미래에 들어온 자료로 그때의 선택을 설명하지 않는다.

### 묻기와 되돌려주기

관찰로 알 수 있는 것은 활동에서 얻고, 목표·제약·직접 선호는 필요한 순간에 묻는다. [첫 로그인 개인화](첫로그인_마스코트추천_개인화_설계_v1.md)의 선택 설문은 09-09 채택된 현재 방향이다. 옛 “설문 0·가입 5~7문항”을 상한으로 적용하지 않는다.

학생의 확인은 `estimate.responded` 사건을 더한다. 원래 추정 행의 `user_confirmed` 열을 뒤집지 않는다. “아니야”로 부정한 주장에 해당하는 지표는 다음 생성 재료에서 빼되 원관측과 정정 이력은 남긴다. 코드 원천은 `lib/성향확인.js`·`lib/과제요약.js`·`functions/progress`다. 현재 상한은 해당 코드의 `하루상한`에서 읽는다(09-13 확인: 두 장). 목표 자기 신고 `goal.responded`는 별개 사건이다.

### 개인화가 효과 있었나

**학생 상태 → 고른 지도 방식 → 실제 전달·반응 → 후속 수행**을 개입 ID와 시각으로 잇는다. 현재 성과 창과 관측 규격은 talk `lib/성과회수.js`가 정한다. `content.viewed.parent_event_id`가 실제로 본 개입 사건을 가리킨다. `미도래`·`표본0`을 효과 0으로 바꾸지 않고 길이가 다른 창을 단순 차감하지 않는다.

성과 계산과 다음 선택에 대한 되먹임은 다르다. 09-13 코드 대조에서 `deliver`는 `회수요약`을 호출하지만 계수는 응답에 실리는 단계다. 다음 선택의 실제 변화와 `degraded` 개입 분리 소비는 추가 구현·검증이 필요하다. 개입-효과 짝의 회사 훈련 이용에는 [엔진 도달](엔진도달_설계.md) 경로 B를 적용한다.

## 부록 A — 계약으로 내려가는 요구

**A-0. 원천:** 필드·필수값·값목록·스키마 판은 수집·교정 계약과 talk L0·C0·마이그레이션이 정한다. 아래 설명을 별도 물리 계약으로 쓰지 않는다.

1. **A-1 이름공간:** 학생 원본과 학습 데이터는 권한을 가진 `engine.*`에 둔다. 지식 인덱스와 학생 원본의 공개 범위를 분리한다.
2. **A-2 서버 호출:** API 키는 서버에만 두고 앱 인터페이스·오류·버전 정책을 계약으로 유지한다.
3. **A-3 외부 처리:** 식별자와 비식별 학습 원문, 원본 음성의 승인 통로를 구분한다(§6).
4. **A-4 기본 동작:** 엔진 실패 시에도 제품이 기본 동작을 제공한다. 해당 행에는 `degraded`·`generation_outcome`을 남기고 AI 성공 성과와 구분한다.
5. **A-5 지식 회수:** 출처·갱신일·유효범위·발행/회수 상태를 둔다. 철회한 지식은 다음 소비에서 제외한다. 첫 RAG 사용부터 인용 당시 내용을 재현할 수 있어야 한다. 제안 규격은 `cited_refs`에 노트 ID와 `content_hash`, 관계에 `{from,to,kind}`를 두는 것이며 실제 형태는 지식 계약에서 확정한다.
6. **A-6 철회 전파:** 원본과 파생·산출물·데이터셋·모델 계보를 따라 해당 철회를 처리한다.
7. **A-7 평가:** 훈련과 독립된 평가셋으로 모델·프롬프트 변경을 판단한다. 분모와 기준판은 talk `evals/픽스처.json`·평가 도구에서 읽고 합성 결과를 학생 효과로 부르지 않는다.
8. **A-8 스키마 판:** 수집 행에 `schema_ver`를 남긴다. Apps Script `SCHEMA_VER`와 계약 버전의 일치를 기존 계약 검사로 확인하며 과거 행의 미상 판을 지어 채우지 않는다.
9. **A-9 실제 사용 준비:** 첫 실제 데이터 전에 운영 환경의 복구·백업·접근·왕복을 확인한다. 특정 요금제의 과거 기능을 영구 유료 전환 의무로 옮기지 않는다. 신규 지출은 AI 운영 원칙을 따른다.
10. **A-10 원본 고리:** 아래 요구를 유지한다.
    - **선택:** 제시 후보·순서·추천·선택·바꿈·지연·건너뜀·당시 맥락을 기록한다. `previous_selection`·`reason_asked`는 추가 구현 후보이며 기존 계약 필드로 단정하지 않는다.
    - **반응:** 무반응은 응답 행 부재, “무시”는 학생의 명시적 응답이다. 늦은 응답을 임의 기한으로 영구 무응답 처리하지 않는다.
    - **기준과 고리:** `skill_id`, 개입 ID, 당시 문항·인용판, 발생/적재 시각을 보존한다. 멱등 범위와 충돌 처리는 L0·C0를 따른다.
    - **용도:** 원본은 개인용, 회사 집계는 별도 비식별 산출물, 훈련·평가 승격은 `data_use.granted`, 철회는 `data_use.revoked`로 다룬다. 행 자격 플래그로 대체하지 않는다.
