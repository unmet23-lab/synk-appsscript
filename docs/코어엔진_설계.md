## 1. 【설계안】 정의 — 두 부분

**SYNK 코어 엔진 = ① 코어 층 + ② 내부 관리 프로그램.**

1. **코어 층**: 회사의 모든 지식·학습 데이터·학생 개인화가 한 곳에 쌓이고 서로 연결되어, 모든 SYNK 앱의 AI 기능이 「무엇을 아는가(지식) × 이 학생을 아는가(개인화)」를 여기서 꺼내 쓴다.
2. **내부 관리 프로그램(비출시)**: 유호님·직원이 그 두뇌를 열어 보고 기르는 옵시디언형 화면. 유호님 원문의 「옵시디언같은 프로그램」·「완전 교육적인 느낌」이 사는 자리다(UI는 브랜드 킷·이모지 절제·「명품 앱」 지향 정본 적용). 형태 답은 §8-1 【확정】(시트 + 화면만 옵시디언 느낌) — 세부 해석(열람=별도 웹 화면)은 【설계안】 · §8-1.

## 2. 【설계안】 왜 엔진인가 (유호님 논리를 구조로)

- **앞으로 나올 모든 앱 = 엔진 활용처**(학원 운영 앱 **포함** — 유호님 정정 2026-08-06: 활용처를 단정으로 미리 닫지 않는다). 챗봇 품질 = **지식 × 개인화** — 앱마다 따로 만들면 N번 만들고 N번 낡는다.
- 엔진 하나에 모으면 지식 1건 추가·개인화 1단계 개선이 **모든 앱에 동시에** 반영된다 — 5·10·20년 복리. 「엔진이 발전하면 앱들이 다같이 발전한다」의 기계적 실체.
- ⚠같은 배선은 **틀린 지식 1건도 전 앱에 동시 전파**한다 — 그래서 회수(무효화) 경로가 계약 조항이다(부록 A-5).

| 층 | 내용 |
|---|---|

**게이트웨이 전제 승격 (2026-08-05)**: 외부 모델 병용(앤트로픽·오픈AI API)은 유호님 3차 원문으로 【확정】(§0) — 어댑터 구조의 세부는 여전히 【설계안】.

**적재 기준 (엔진 전체 원칙 — 지식 그래프에도 적용)**: 넣는 것 = ①우리만 가진 것(오류·교정 기록·실학생 데이터) ②모델이 틀리는 것 ③대외 약속(FAQ·방침). **모델이 이미 아는 일반론(문법·교수법 등)은 넣지 않는다** — 차별점 0에 검색 노이즈만 늘린다(기존 판정 승계).

**원칙 3 (기존 확정 승계)**
1. **데이터는 AI가 아니라 저장소에** — 모델·벤더는 갈아끼우고 데이터는 안 움직인다.
2. **지식 주입 = 검색(RAG)** — 파인튜닝 아님(틀린 지식을 못 지운다 · 기존 판정 유지).
3. **엔진이 죽어도 앱은 돈다** — 프로즈로 끝내지 않고 계약 조항으로 내림(부록 A-4).

**게이트웨이 실행 위치**: 서버측만 — Supabase Edge Function(권장) 또는 **별도** Apps Script 프로젝트. 현 AS 프로젝트의 doPost 확장은 **불가**(상담AI가 점유 + HtmlService 전역 노출 사고 이력).

## 6. 【설계안】 안 하는 것 (경계)

- 별도 출시 ✗ — 회사 내부 엔진(유호님 명시).
- 지금 구현 착수 ✗ — E0는 계약 조항뿐. 앱이 항상 우선(🚫선행 구축 유지).
- 벡터 RAG ✗ — 단 **원 판정의 조건 그대로**: 지식 총량이 컨텍스트 상한 안일 동안이다. **상한을 넘는 시점 = 이 금지의 자동 해제 조건**(그때 재판정 — 조건 없는 영구 금지로 읽지 말 것). 해제되더라도 **벡터(pgvector)는 색인이지 정본이 아니다** — 원본은 일반 테이블에 그대로 두고 임베딩은 **언제든 재생성 가능**해야 한다(2026-08-05 2차 검토 채택).
- 「학습시킨다=파인튜닝」 프레임 ✗ · 멀티테넌트 ✗ (기존 🚫 유지).
- **학생 개인정보(학습자 모델·말뭉치)는 어느 안에서도 git에 두지 않는다** — 규칙 자체는 §7에 있었으나 **「기각 종결·근거 보존용」 문단 안에 묻혀** 있어 여기로 꺼낸다(2026-08-05 · 정본은 이 줄). ⚠**「SYNK.MD」는 유호님의 비유지 만들 파일 이름이 아니다**(§0·§8-2) — 그 이름의 파일을 실제로 만들더라도 들어가는 것은 **교육 철학·스키마 정의·기억 승격 규칙·개인정보 원칙·검수 기준·모델 선택 규칙**이고, **학생 기억은 권한·버전을 가진 DB(Supabase `engine.*`)에** 있다. 비유를 파일로 구현하는 순간 삭제 요구(git 이력에 영원히 남음)·열람권(전교생 노출)·비용(매 호출마다 전량 적재)이 동시에 깨진다.
- 이름 짓기는 지금 안 한다 — **내부 코드명 「코어 엔진」으로 E1까지 고정**(코드 0줄 물건의 이름은 되돌림 비용 0 · 대외 명칭이 되는 순간 상표 트랙과 얽히므로 그때 유호님 결정).
- ⚠법적 전제(새 결정 아님·이미 결정큐 최상단): 개인화·말뭉치 활용은 **동의 v18.9 개정(제3자 제공·몽골어 병기)** 이 전제 — 실학생 동의 시작 전이 마지막 기회(소급 불가).
- **【확정 2026-08-05】 동의 처리 = 전 버전 그대로·최대한 간략하게 · 음성 원본 보존 = 무제한** — 유호님 원문: "음성원본보존 무제한이고 동의처리방식은 전 버전으로 최대한 간략하게만들어". 따라서 🚫**동의 세분화**(외부 검토문의 서비스/개인화/연구·모델개선/마케팅 4분리) · 🚫**음성 원본 보존기간 단축·표본화**(08-04 확정 재확인) — **둘 다 재제안 금지.** 기존 확정 [동의 속도=유호님 몫]과 같은 축이다: 권한·동의·철회 설계로 속도를 늦추지 않는다(법적 책임=유호님). 위 v18.9 개정은 **이미 결정된 별건**이라 이 간략화 대상이 아니다(제3자 제공 조항 1건 · 항목을 늘리는 일이 아니다).

## 7. 【도전안·기각 종결】 지식층 정본을 「마크다운 + git」으로, Supabase는 인덱스로

**안**: 지식 노트의 정본을 DB가 아니라 마크다운 파일+git(별도 저장소의 **지식 전용 볼트**)으로 두고, Supabase에는 검색용 인덱스만 적재. 옵시디언과 동형(파일=노트·`[[링크]]`=그래프)이라 옵시디언 실물이 관리 화면이 될 수 있고, 모든 개정이 git 이력으로 남는다. 근거 실물 = 회사 AI 메모리가 이 구조로 실운영 중.

**⚠정직한 경고 — 이 안은 기존 확정 3건과 충돌한다(채택하려면 유호님이 명시적으로 해제해야 한다)**:
1. 「Obsidian=정본 뷰어로 축소 · 제2두뇌 금지」(ai-stack 확정) 2. 「유호 직접 편집 볼트 = 미커밋 상주 사고 경로라 금지」(노션 대체 트랙) 3. 현 볼트는 memory 폴더 위라 파일 만드는 코어 플러그인을 일부러 꺼 뒀고, 그 동기화 트랙(synk-memory)은 세션이 안 만지는 자산이다 — 그래서 **별도 볼트**가 전제다.
그리고 「관리창 비용 0원」이 아니다 — 열람권·발행 게이트(어느 노트가 봇에 실리나)·다국어·학생 데이터 경계는 어느 안에서든 만들어야 하고, 그것이 관리창 비용의 본체다. 학생 개인정보(학습자 모델·말뭉치)는 어느 안에서도 git에 두지 않는다(**→ 정본은 §6으로 승격** — 이 줄은 근거 보존용 원문이라 두 곳이 갈리지 않게 참조만 남긴다).

### 성향 5축 — 설문 0, 전부 행동에서 파생

| 축 | 무엇으로 재나 | 지금 상태 |
|---|---|---|
| ① **리듬** | 제출 시각·간격·마감 대비 여유 | ✅ **이미 공짜** (`created_at`) — 계산만 붙이면 된다 |
| ② **끈기** | 틀린 뒤 재시도하나 넘어가나 · 어려운 문항 이탈 | 🔴 없음 |
| ③ **자기인식** | **확신도 vs 정답률 격차**(확신했는데 틀림 = 착각형 · 맞았는데 불안 = 과소평가형) | ⚠ 퀴즈만 (`QUIZ_LOG` 실측) |
| ④ **피드백 수용** | AI·강사 교정을 채택·무시·수정했나 | 🔴 **최대 빈 곳** — 「발전 방향 지도」의 핵심 재료가 통째로 없다 |
| ⑤ **관심·목표** | 고른 주제·진로 문항 | ⚠ trajectory(v9.181/183)에 일부 |

5축은 유호님 문장을 기계로 옮긴 것이다 — 「단점 파악」=②③④, 「발전 방향 지도」=④⑤, 「나를 안다」=①~⑤의 시간축.

### 🔑 기록 규격 — 사실·관찰·추정을 섞지 않는다 (2026-08-05 2차 검토 채택 · **이 절의 최대 소득**)

「라벨은 파생으로만」(원칙 1)은 **방향**이었고, 그것을 지키는 **실물**이 이 규격이다. 개인화 정보 한 건에는 출처 등급이 붙고, 등급이 신뢰 순위를 정한다.

| 출처 등급 (`source_kind`) | 예 | 신뢰 |
|---|---|---|
| `explicit` 학생의 명시적 선택 | "교정은 부드럽게 해주세요" | 높음 |
| `teacher` 교사·검수자 확인 | 강사가 「받침 발음 반복 오류」 확인 | 높음 |
| `observed` 직접 관찰 | 최근 10문제 중 조사 오류 6회 | 중간~높음 |
| `inferred` AI 추정 | 짧은 문제를 선호하는 것으로 추정 | **낮음 — 사실처럼 저장 금지** |

추정에는 반드시 동반 필드: `confidence`(0~1) · `evidence_refs`(근거 이벤트 ID) · `estimator_version`(추정 알고리즘 버전) · `valid_from` / `expires_at`(**오래된 정보는 시간에 따라 신뢰가 감소한다** — 8개월 전 목표를 오늘의 사실로 쓰지 않는다) · `user_confirmed`(학생이 확인했나 — 확인되면 `explicit`로 승격).

→ 이 규격이 있어야 **잘못 파악한 성향을 고칠 수 있고, 새 알고리즘으로 전체 상태를 다시 계산할 수 있다.** 없으면 추정이 사실 행세를 하며 굳는다.

### 【설계안】 원칙 4 — 설계의 본체

1. **원신호를 저장하고, 성향 라벨은 파생으로만.** 「이 학생은 끈기 없음」을 원본 행에 박으면 **틀린 낙인이 굳는다** — 라벨은 언제나 재계산 가능해야 하고, 판정 규칙이 바뀌면 과거까지 다시 계산된다. 저장하는 것은 *행동*이지 *판정*이 아니다.
2. **성격이 아니라 「현재 상태 + 근거」로 쓴다** *(2차 검토 채택)*. 🚫**고정형 라벨 금지** — 「시각형 학습자」·「의지가 약한 학생」·「소극적인 성격」. 특히 **시각형/청각형 학습 스타일에 맞춰 가르치면 효과가 좋아진다는 이론은 근거가 충분하지 않다**(2024 메타분석은 스타일 매칭보다 *여러 방식을 제공하는 쪽*을 지지 — 검토문 인용이라 「~로 보인다」 수준으로 받되, **방향은 우리 원칙 1과 같아 채택**). 대신 이렇게 쓴다: *"최근 30일간 예문을 먼저 보여줬을 때 완료율이 높았다 · 문법 설명을 길게 하면 이탈이 늘었다 · 본인이 고른 선호는 「짧게 설명 후 바로 연습」 · 조사는 낮고 발음 유창성은 안정 · 현재 추정 신뢰도 0.68, 근거 12건."*
3. **묻지 말고 떨어지게 — 단 관찰로 못 얻는 것만 묻는다.** 성향은 행동에서 떨어뜨리고(말과 행동은 다르다), **목표·가능 시간·기기·언어 같은 제약**은 관찰로 알 수 없으니 **가입 시 5~7문항까지만** 묻는다. 그 뒤로는 수업 흐름 안의 미세 선택만 — 선택 질문을 자주 띄우면 학생이 피로해진다.
4. **새 동의 항목을 만들지 않는다.** §6 유호님 확정(동의 = 전 버전·최대한 간략) 준수 — 기존 「학습 데이터 수집·개인화」 범위 안에서만 설계한다.

**⚠ 방금 기각된 것과 축이 다르다**: §9의 🚫「학습 후보 자격 플래그」는 *행을 판정하는 메타 열*이었고, 이것은 **학생 데이터 그 자체**(유호님 직접 지시)다. 「열을 늘리지 마라」의 근거로 이 절을 막지 않는다.

### 【도전안】 성향은 되돌려줄 때 정확해진다

봇이 추정한 성향을 학생에게 **보여주고 「맞아 / 아니야」를 받는다.** ①추정 라벨이 **학생이 확인한 라벨**로 승격된다(얻을 수 있는 최고 품질) ②*"이 봇은 나를 안다"* 는 체감은 정확한 추정이 아니라 **맞춰보고 확인받는 상호작용**에서 온다 — 유호님이 말한 「선생님 같은 느낌」의 실체가 이것이다 ③수집 비용 0. §9 ③ 선호 레코드의 미기록 구멍(「이유」)을 학생 축에서 채우는 통로이기도 하다.

### 🔗 개인화가 「효과 있었나」를 아는 유일한 배선 (2차 검토 채택)

**학생 상태 → AI가 고른 지도 방식 → 학생 반응 → 즉시 성과 → 1·7·30일 뒤 유지 성과.** 이 고리가 없으면 아는 것은 *"이 학생은 영상을 좋아한다"* 에서 멈추고, 있으면 *"영상을 좋아하지만 **예문 뒤 직접 말하게 했을 때 장기 기억이 더 좋다**"* 까지 간다. **성향 수집이 취향 수집으로 끝나느냐, 지도 능력이 되느냐가 여기서 갈린다** — 유호님이 말한 「발전 방향까지 지도」는 앞쪽이 아니라 뒤쪽이다.

소급 불가 지점은 하나: **AI가 고른 지도 방식에 ID가 있어야** 나중에 성과를 붙일 수 있다. 성과 계산은 늦게 해도 되지만, 그때 이어붙일 **개입 ID와 시각**은 그 순간에만 남길 수 있다.

### 🎓 「잘 안다」는 느낌의 실체 4가지 (2차 검토 채택 · 개인정보를 많이 아는 것이 아니다)

①**지난 약속을 기억한다** ②**반복되는 약점을 근거와 함께 알아챈다** ③**그날의 상태에 맞게 난이도를 조정한다** ④**지도 후 실제로 발전했는지 다시 확인한다**. 봇의 말로 옮기면: *"지난 세 번의 연습에서 「은/는」과 「이/가」를 자주 바꿔 썼어요. 오늘은 설명을 길게 하지 않고, 지난번에 잘 맞았던 짧은 비교 문제 세 개부터 해볼까요?"* — **근거(세 번·지난번 잘 맞았던)가 문장에 들어 있는 것**이 핵심이다. 이 한 문장을 만들려면 §10의 원신호·개입 ID·성과 연결이 전부 필요하다. **E2 학습자 모델의 수용 기준으로 쓴다.**

### 【한 수 더】 확신도 1열을 숙제·talk로 확장

퀴즈에만 있는 `확신도`를 다른 수집 경로에 **같은 이름으로** 넣으면 축 ③이 전 경로에서 켜진다 — 새 개념 0, 학생이 답하는 UI도 이미 있다(재사용). 열 1개로 축 하나가 켜지는 자리는 여기뿐이다.

### 시점 — 왜 지금인가 · 무엇을 지금 안 하는가

계약에만 박는다(부록 A-10) · 실물은 SYNK-talk과 함께 · **E0 코드 0줄 불변**. **학생 0명인 지금이 손실 0으로 스키마를 넓힐 마지막 창**이고, 개원(2027-02-25) 뒤에는 안 박아 둔 축이 **영원히 빈 채로** 쌓인다(소급 불가 — 행동은 지나가면 재현되지 않는다).

**🔑 지금/나중을 가르는 기준선 = 「원본 증거는 지금, 파생 상태는 나중」.** 원본이 있으면 파생은 **언제든 다시 계산되지만**, 원본이 없으면 파생을 **영원히 못 만든다**. 그래서 2차 검토문이 제시한 4계층 중 **A(원본 증거)와 그 메타데이터만** 지금 계약에 박고, **C(학습자 상태)·D(개입·성과 집계)는 테이블조차 지금 만들지 않는다** — 유일한 예외가 위 「개입 ID」다(성과를 나중에 이어붙일 고리라 그 순간에만 남길 수 있다).

**🚫 2차 검토문에서 안 받은 것 (재제안 금지)**
- **`consent_ledger` 별도 테이블** — 동의는 행 단위 `consent_ver`로 이미 기록된다. 유호님 §6 확정(**동의 = 전 버전 그대로 최대한 간략**)이 우선이다.
- **「검수 통과 행만」 품질 관문** — 유호님이 §9에서 기각한 자격 플래그와 같은 축(🚫). *단 **평가셋**(A-7)은 별건으로 살아 있다* — 행에 자격 열을 붙이는 것과, 평가용 표본을 따로 고르는 것은 다르다.
- **C·D 계층 테이블 지금 신설**(`learner_skill_state`·`misconceptions`·`memory_items`·`interventions`·`outcomes` 등) — 🚫V3식 선행 구축 재상륙. 위 기준선대로 파생이라 늦어도 된다.
- **Knowledge Tracing 모델**(베이지안·딥러닝 숙련도 추정) — 학생 0명·근거 이벤트 0건. 데이터가 쌓인 뒤 **설명 가능한 단순 모델부터**(검토문도 같은 권고).

5. **지식 레코드 규격**: 출처·갱신일·**유효범위(대상 도메인 — E3 지식팩 경계의 씨앗)** 필수 + **회수(무효화) 1회가 전 소비자에 즉시 반영**되는 배선(틀린 답 방치가 유일한 치명 실패 — 기존 판정 승계). **지식 시트 필수 열 = 현 `두뇌지식` 헤더(대상·주제·확정·내용·출처·갱신일)에 유효범위·회수/발행 플래그를 더한 것** — E1 시트 신설 때 이 열로 시작한다. 회수 판정은 시트→DB 동기 주기에 얹지 않는다 — 소비자(게이트웨이)가 회수·발행 플래그를 실시간으로 본다(「즉시」가 동기화 지연에 걸리는 순간 이 조항이 죽는다).

8. **행 단위 스키마 버전** *(2026-08-05 **유호님 확정** — 원문 "넣어" · 「동의·출처만」의 대상이 아님을 판정: 사람이 하는 일이 0이라 「동의 간략」과 축이 다르다 · 🚫제거 재제안 금지 · 소급 불가)*: 수집 행에 `schema_ver` 1열 — 계약 파일의 `버전`(현 `c2`)을 **행이 스스로 들고 있게** 한다. 계약 파일에는 버전이 있지만 **데이터 행에는 없다**(실측: `엔진_수집.js` 헤더 상수에 `model`·`prompt_ver`·`audio_ref`·급수는 있고 `schema_ver`는 없음). 3·4년차에 한 시트 안에 c1·c2·c3 행이 섞이면 어느 규격인지 행이 말하지 못하고, 변환기를 쓰려 해도 대상을 못 고른다 — **불변식 1(「4년 호환」)을 지키는 유일한 기계 장치**이고, 과거 행은 영원히 빈칸이라 지금 박는 것 말고 방법이 없다.

10. **학습자 모델 신호** *(§10 · 유호님 지시 2026-08-05 + 2차 외부 검토 채택 · 소급 불가)* — 다섯 조각:
    - **① 선택의 흔적**: `재시도차수`(같은 문항 몇 번째 시도) · `교정반응`(AI·강사 교정을 **채택/무시/수정** 중 무엇으로 처리) · `확신도`(퀴즈 밖 경로로 확장).
    - **② 선택 로그 — 최종 선택 하나만 저장하면 부족하다**: `options_shown`(제시된 선택지 전부) · `position`(표시 순서) · **`recommended_option`(AI가 무엇을 추천했나)** · `selected_option` · `changed_selection`(바꿨나) · `latency_ms`(고르기까지 걸린 시간) · `skipped`(건너뛰었나) · 당시 맥락(목표·실력·기기·시간대). **AI 추천과 표시 순서를 안 남기면 학생의 선호와 「우리가 밀어준 것」이 영원히 구분되지 않는다** — 편향된 데이터로 개인화를 학습하게 된다. §9 ③ 선호 레코드의 학생 축 쌍둥이(새 개념 아님).
    - **③ 추정 메타 7종**(§10 기록 규격): `source_kind`(explicit·teacher·observed·inferred) · `confidence` · `evidence_refs` · `estimator_version` · `valid_from` · `expires_at` · `user_confirmed`. **AI 추정을 사실처럼 저장하지 않는다.**
