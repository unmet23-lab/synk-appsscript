## 1. 【설계안】 정의 — 두 부분

**SYNK 코어 엔진 = ① 코어 층 + ② 내부 관리 프로그램.**

1. **코어 층**: 회사의 모든 지식·학습 데이터·학생 개인화가 한 곳에 쌓이고 서로 연결되어, 모든 SYNK 앱의 AI 기능이 「무엇을 아는가(지식) × 이 학생을 아는가(개인화)」를 여기서 꺼내 쓴다.
2. **내부 관리 프로그램(비출시)**: 유호님·직원이 그 두뇌를 열어 보고 기르는 옵시디언형 화면. 유호님 원문의 「옵시디언같은 프로그램」·「완전 교육적인 느낌」이 사는 자리다(UI는 브랜드 킷·이모지 절제·「명품 앱」 지향 정본 적용). 형태 답은 §8-1 【확정】(시트 + 화면만 옵시디언 느낌) — 세부 해석(열람=별도 웹 화면)은 【설계안】 · §8-1.

## 2. 【설계안】 왜 엔진인가 (유호님 논리를 구조로)

- **앞으로 나올 모든 앱 = 엔진 활용처**(학원 운영 앱 **포함** — 유호님 정정 2026-08-06: 활용처를 단정으로 미리 닫지 않는다). 챗봇 품질 = **지식 × 개인화** — 앱마다 따로 만들면 N번 만들고 N번 낡는다.
- 엔진 하나에 모으면 지식 1건 추가·개인화 1단계 개선이 **모든 앱에 동시에** 반영된다 — 5·10·20년 복리. 「엔진이 발전하면 앱들이 다같이 발전한다」의 기계적 실체.
- ⚠같은 배선은 **틀린 지식 1건도 전 앱에 동시 전파**한다 — 그래서 회수(무효화) 경로가 계약 조항이다(부록 A-5).

## 3. 【설계안】 이미 갖고 있는 원형 — 0에서 시작이 아니다

| 원형 (지금 실운영 중) | 엔진에서의 자리 |

| AI 메모리 시스템 — 마크다운 노트 + `[[링크]]` + 역링크 자동 생성 | 옵시디언형 지식 그래프의 **원형** — 회사가 이미 이 방식으로 돈다 |
| 상담AI 지식층 — 시트 `두뇌지식` 탭 · 열람권 화이트리스트 · 출처+갱신일 표기 · 벤더 교체 어댑터 | E1 지식층·AI 게이트웨이의 씨앗 (합류 절차는 §5 E1 — 함부로 안 옮긴다) |

**적재 기준 (엔진 전체 원칙 — 지식 그래프에도 적용)**: 넣는 것 = ①우리만 가진 것(오류·교정 기록·실학생 데이터) ②모델이 틀리는 것 ③대외 약속(FAQ·방침). **모델이 이미 아는 일반론(문법·교수법 등)은 넣지 않는다** — 차별점 0에 검색 노이즈만 늘린다(기존 판정 승계).

**원칙 3 (기존 확정 승계)**
1. **데이터는 AI가 아니라 저장소에** — 모델·벤더는 갈아끼우고 데이터는 안 움직인다.
2. **지식 주입 = 검색(RAG)** — 파인튜닝 아님(틀린 지식을 못 지운다 · 기존 판정 유지).
3. **엔진이 죽어도 앱은 돈다** — 프로즈로 끝내지 않고 계약 조항으로 내림(부록 A-4).

**게이트웨이 실행 위치**: 서버측만 — Supabase Edge Function(권장) 또는 **별도** Apps Script 프로젝트. 현 AS 프로젝트의 doPost 확장은 **불가**(상담AI가 점유 + HtmlService 전역 노출 사고 이력).

## 7. 【도전안·기각 종결】 지식층 정본을 「마크다운 + git」으로, Supabase는 인덱스로

> **기각 종결 (2026-08-05)**: §8-1 답(편집=시트 · 화면만 옵시디언 느낌)으로 이 안은 소멸 — 충돌 3건의 해제가 더는 필요 없다. **🚫재제안 금지 대상 = 지식 정본을 마크다운+git에 두는 안 · 옵시디언을 편집 관리창으로 쓰는 안**(읽기 전용 뷰어 보조 통로는 별건 — §8-1 도전안 · E1 검토). 기록=memory `core-engine-obsidian`. 아래 본문은 근거 보존용.

**⚠정직한 경고 — 이 안은 기존 확정 3건과 충돌한다(채택하려면 유호님이 명시적으로 해제해야 한다)**:

### 🔑 기록 규격 — 사실·관찰·추정을 섞지 않는다 (2026-08-05 2차 검토 채택 · **이 절의 최대 소득**)

「라벨은 파생으로만」(원칙 1)은 **방향**이었고, 그것을 지키는 **실물**이 이 규격이다. 개인화 정보 한 건에는 출처 등급이 붙고, 등급이 신뢰 순위를 정한다.

| 출처 등급 (`source_kind`) | 예 | 신뢰 |
|---|---|---|
| `explicit` 학생의 명시적 선택 | "교정은 부드럽게 해주세요" | 높음 |
| `teacher` 교사·검수자 확인 | 강사가 「받침 발음 반복 오류」 확인 | 높음 |
| `observed` 직접 관찰 | 최근 10문제 중 조사 오류 6회 | 중간~높음 |
| `inferred` AI 추정 | 짧은 문제를 선호하는 것으로 추정 | **낮음 — 사실처럼 저장 금지** |

추정에는 반드시 동반 필드: `estimator_confidence`(0~1 — 🔴 계약 이름이 이것이다: 학생이 스스로 매기는 `confidence`(라벨 축 · quiz_log 실물)·검수자의 `reviewer_confidence` 와 **세 축을 일부러 갈랐다** · A-0 · 2회차 판정 ⑤ — 여기 `confidence` 라 적혀 있던 것이 학생 자기인식 값에 AI 추정치를 싣게 만드는 자리였다) · `evidence_refs`(근거 이벤트 ID) · `estimator_version`(추정 알고리즘 버전) · `valid_from` / `expires_at`(**오래된 정보는 시간에 따라 신뢰가 감소한다** — 8개월 전 목표를 오늘의 사실로 쓰지 않는다) · `user_confirmed`(학생이 확인했나 — 확인되면 `explicit`로 승격 · **물리는 열 뒤집기가 아니라 사건**이다: `estimate.responded`(c13 · source_kind=explicit) 를 «더하고», 파생 상태(학습자상태 확인축)가 그것을 읽어 재계산된다 — append-only 라 추정 행을 고치지 않는다 · 아래 「되돌려줄 때」 절).

→ 이 규격이 있어야 **잘못 파악한 성향을 고칠 수 있고, 새 알고리즘으로 전체 상태를 다시 계산할 수 있다.** 없으면 추정이 사실 행세를 하며 굳는다.

### 【설계안】 원칙 4 — 설계의 본체

1. **원신호를 저장하고, 성향 라벨은 파생으로만.** 「이 학생은 끈기 없음」을 원본 행에 박으면 **틀린 낙인이 굳는다** — 라벨은 언제나 재계산 가능해야 하고, 판정 규칙이 바뀌면 과거까지 다시 계산된다. 저장하는 것은 *행동*이지 *판정*이 아니다.
2. **성격이 아니라 「현재 상태 + 근거」로 쓴다** *(2차 검토 채택)*. 🚫**고정형 라벨 금지** — 「시각형 학습자」·「의지가 약한 학생」·「소극적인 성격」. 특히 **시각형/청각형 학습 스타일에 맞춰 가르치면 효과가 좋아진다는 이론은 근거가 충분하지 않다**(2024 메타분석은 스타일 매칭보다 *여러 방식을 제공하는 쪽*을 지지 — 검토문 인용이라 「~로 보인다」 수준으로 받되, **방향은 우리 원칙 1과 같아 채택**). 대신 이렇게 쓴다: *"최근 30일간 예문을 먼저 보여줬을 때 완료율이 높았다 · 문법 설명을 길게 하면 이탈이 늘었다 · 본인이 고른 선호는 「짧게 설명 후 바로 연습」 · 조사는 낮고 발음 유창성은 안정 · 현재 추정 신뢰도 0.68, 근거 12건."*
3. **묻지 말고 떨어지게 — 단 관찰로 못 얻는 것만 묻는다.** 성향은 행동에서 떨어뜨리고(말과 행동은 다르다), **목표·가능 시간·기기·언어 같은 제약**은 관찰로 알 수 없으니 **가입 시 5~7문항까지만** 묻는다. 그 뒤로는 수업 흐름 안의 미세 선택만 — 선택 질문을 자주 띄우면 학생이 피로해진다.
4. **새 동의 항목을 만들지 않는다.** §6 유호님 확정(동의 = 전 버전·최대한 간략) 준수 — 기존 「학습 데이터 수집·개인화」 범위 안에서만 설계한다.

**⚠ 방금 기각된 것과 축이 다르다**: §9의 🚫「학습 후보 자격 플래그」는 *행을 판정하는 메타 열*이었고, 이것은 **학생 데이터 그 자체**(유호님 직접 지시)다. 「열을 늘리지 마라」의 근거로 이 절을 막지 않는다.

### 🔗 개인화가 「효과 있었나」를 아는 유일한 배선 (2차 검토 채택)

**학생 상태 → AI가 고른 지도 방식 → 학생 반응 → 즉시 성과 → 1·7·30일 뒤 유지 성과.** 이 고리가 없으면 아는 것은 *"이 학생은 영상을 좋아한다"* 에서 멈추고, 있으면 *"영상을 좋아하지만 **예문 뒤 직접 말하게 했을 때 장기 기억이 더 좋다**"* 까지 간다. **성향 수집이 취향 수집으로 끝나느냐, 지도 능력이 되느냐가 여기서 갈린다** — 유호님이 말한 「발전 방향까지 지도」는 앞쪽이 아니라 뒤쪽이다.

소급 불가 지점은 하나: **AI가 고른 지도 방식에 ID가 있어야** 나중에 성과를 붙일 수 있다. 성과 계산은 늦게 해도 되지만, 그때 이어붙일 **개입 ID와 시각**은 그 순간에만 남길 수 있다.

    - **⑤ 개인화 3관문**(A-3 확장) — **관문은 유지하되 「행의 신분을 바꾸는 열」로는 만들지 않는다**(2026-08-05 정정): 원안의 `privacy_class` enum 3등급은 **§9 유호님 기각(「이 행을 훈련에 써도 되나」를 말하는 열은 넣지마)과 글자 그대로 부딪친다** — 값 하나가 문자 그대로 `training`이었다. 이 조항은 그 기각 **뒤에** 쓰인 AI 설계안이라 기각을 넘지 못한다(다른 세션 `local_8f792d12`의 c3 계약 지적 · 채택). **해소 = 열을 없애도 관문은 선다**: ①**원본 이벤트는 언제나 개인용**(신분 열 없음 — append-only와도 정합) ②**회사 통계는 원본의 신분을 바꾸는 게 아니라 별도의 비식별 집계 산출물** ③**훈련 승격은 행이 아니라 사건**(`data_use.granted` 이벤트/`dataset_item`). 유호님께 다시 여쭐 필요가 없어진다 — 실물은 SYNK-talk `docs/L0_데이터계약.md` §6-2(v1.1 · f3eba7e). **↓아래 ⏳줄은 이 정정으로 해소된다**(결정큐에서 내린다 — 그 줄은 보류 경위의 근거 보존용으로 남긴다 · 원 작성 세션 `local_8f792d12`).
      - 🔴**⏳유호님 확정 대기 — M0 동결에서 보류(2026-08-05)**: 이 조각만 §9의 유호님 기각(*"동의·출처만 넣어. 「이 행을 훈련에 써도 되나」를 말하는 열은 넣지마"* · 재제안 금지)과 **글자 그대로 부딪친다** — 값 하나가 문자 그대로 「훈련 데이터」다. 그리고 A-10은 그 기각 **뒤에** 쓰인 AI 【설계안】이라 기각을 넘지 못한다(유호님 확정 > 내 설계안). 그래서 계약 `c3`에는 **필드로 넣지 않고** `보류_유호확정대기`에 뒀고, 회귀가 몰래 편입되는 것을 막는다. 경계 판정 절차는 **A-8이 이미 밟은 그것**(물어서 "넣어"를 받았다) — 같은 방식으로 확정을 받는다. ⚠판정이 「넣지 마라」로 나와도 **3관문 원칙 자체는 A-3 조항으로 살아 있다**(행에 붙는 열이 아니라 경로 규칙으로).

    성향 **라벨**은 이 원신호에서 계산하는 **파생**이며 **원본 행에 쓰지 않는다**(재계산 보장 · 낙인 고착 방지 — §10 원칙 1·2). 이벤트 봉투는 `event_id`·`occurred_at`(발생)과 `ingested_at`(수집)**을 나누고**·`correlation_id`(한 수업 흐름)·`idempotency_key`(중복 저장 방지)를 갖는다 — 오프라인 제출·재시도가 있는 앱에서 이 넷이 없으면 같은 사건이 두 번 세어진다. **멱등 규약의 정본은 여기가 아니다(09-02 · 2회차 판정 ⑧ · 1회차 ③으로 닫힌 지적의 세부)**: 유일성 범위 = `(learner_id, idempotency_key)` 복합(talk `docs/L0_데이터계약.md` §2 — 전역 유일이면 두 학생이 같은 키를 만드는 날 뒤 제출이 조용히 거부된다) · 같은 키 + **다른 내용** = `functions/events` 가 `request_hash` 로 갈라 `IDEMPOTENCY_CONFLICT`(retryable:false) → 앱 `src/사건통로.js` 가 새 키로 **한 번** 재전송(삼키지 않는다 · 새 키로도 충돌하면 모르는 고장) · 같은 키 + 같은 내용 = `duplicate`(정상 재전송) · 동시 삽입 승자 = unique 제약(먼저 커밋한 행) · 하루 1회 사건(`estimate.responded`·`goal.responded`)은 부분 유일 색인이 늦은 쪽을 duplicate 로 접는다(G11) · 사건 순서 = `occurred_at`(발생 · 기기 시계를 못 믿으니 «오늘» 판정은 `ingested_at` — 1회차 ④) · 상태 계산은 `occurred_at ≤ as_of` 와 `ingested_at ≤ ingested_as_of` 둘 다 자른다. 규격 버전은 **A-8 `schema_ver`와 같은 것**(따로 만들지 않는다). 자체 규격으로 가되 **나중에 xAPI·Caliper로 변환 가능한 모양**은 유지한다(지금 구현 ✗ — 명명·구조 수준의 제약만). 동의는 **새 항목 없이** 기존 「학습 데이터 수집·개인화」 범위 안(§6 확정).
