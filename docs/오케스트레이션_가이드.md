# SYNK 오케스트레이션 가이드 — Codex ↔ Claude 두 창 쓰는 법

> 유호님용 운영 설명서. **이 한 장만 지키면 두 창을 왔다 갔다 해도 작업이 안 망가진다.**
> 세팅한 날: 2026-07-13 · 대상: SYNK-appsscript 저장소

---

## 한 줄 요약

**Codex가 만들고 → Claude가 검사하고 → 한 창에서만 배포한다. 작업마다 역할을 바꾼다.**

---

## 1. 두 창의 역할

```
┌─────────────────┐        ┌─────────────────┐
│   Codex 창       │        │  Claude Code 창  │
│   = 만들기(구현)  │        │   = 검사(리뷰)    │
│                 │        │                 │
│ 코드 짜고 커밋만  │───────▶│ 방금 커밋을 읽고   │
│ (배포는 안 함)    │  diff  │ 문제만 짚어줌      │
│                 │◀───────│ (코드는 안 고침)   │
└─────────────────┘  지적   └─────────────────┘
        │                          │
        └──── 리뷰 통과하면 ────────┘
                    ▼
          한 창에서만  /deploy
```

- **다음 작업은 역할을 바꾼다** — Claude가 만들고 Codex가 검사. 이렇게 하면 한쪽이 놓친 실수를 반대쪽이 잡는다.
- 같은 기능을 두 창이 동시에 만들지 않는다(시간·비용만 2배).

---

## 2. 매 작업 4단계

1. **한 창(예: Codex)에 시킨다** — "○○ 기능 만들어줘". Codex가 코드를 짜고 **커밋만** 한다(배포 안 함).
2. **다른 창(Claude)에 검사시킨다** — `방금 커밋 리뷰해줘`. Claude가 바뀐 부분만 읽고 문제·판정을 알려준다(코드는 안 건드림).
3. **고칠 게 있으면** 만든 창(Codex)에 다시 시켜 반영한다.
4. **한 창에서만** `/deploy` → 라이브 반영 끝.

---

## 3. 절대 규칙 3개 (이것만 지키면 안 망가진다)

1. **같은 파일을 두 창에서 동시에 편집하지 않는다.**
   한 번에 한 창만 편집. 창을 바꾸기 전에 앞 창의 작업을 **커밋**해두면 안전하다.
2. **배포(`/deploy`)는 리뷰가 끝난 뒤, 한 창에서 딱 한 번.**
   두 창이 각자 배포하면 라이브(실제 앱)가 서로 덮어써진다. Apps Script 라이브는 딱 하나뿐이다.
3. **손으로 `clasp push` 치지 않는다.** 배포는 무조건 `/deploy`로만.

---

## 4. 자동으로 지켜주는 안전장치 (이미 다 깔림)

유호님이 실수해도 아래가 자동으로 막아준다. 안심하고 쓰셔도 된다.

| 안전장치 | 무엇을 막나 |
|---|---|
| **커밋 훅**(pre-commit) | 구문이 깨진 코드는 **커밋 자체가 안 된다**. 깨진 채로 배포될 일이 없음 |
| **배포 승인 질문** | `git push`·`clasp push`·설치 명령은 실행 전에 **한 번 물어본다** |
| **비밀파일 차단** | `.env`·자격증명 파일은 AI가 **읽지 못하게** 막힘 |
| **리뷰어(reviewer)** | 검사 담당은 **코드를 못 고친다**(읽기 전용). 검사하다 실수로 망가뜨릴 일 없음 |
| **`/deploy` 파이프라인** | 배포 전에 구문검사 + 안전 불변식 테스트 + 오염 확인을 자동으로 돈다 |
| **세션보드**(`docs/세션보드.md`) | 두 창이 같은 파일을 만지는지 서로 알 수 있게 기록 |

---

## 5. 뭔가 이상해졌을 때 (복구법)

**당황하지 말 것. 아직 배포 전이면 100% 안전하다** — git이 지난 커밋을 전부 보관한다.

- **"작업이 꼬인 것 같다"** → 아직 `/deploy` 안 했으면 라이브는 멀쩡하다. 그냥 멈춰라.
- **되돌리고 싶다** → Claude 창에 이렇게 말한다:
  - `지금 상태 보여줘, 뭐가 바뀌었어?`
  - `마지막 정상 커밋으로 되돌려줘` (커밋 안 한 변경만 사라지고, 커밋된 건 다 안전)
- **라이브(실제 앱)가 이상하다** → Claude 창에: `직전 커밋으로 라이브 되돌려줘`. git 이력에서 마지막 정상본을 다시 배포해준다.
- **두 창 작업이 섞인 것 같다** → Claude 창에: `git status 확인하고 내 작업만 분리해서 커밋해줘`.

> git 명령을 직접 칠 필요 없다. **말로 시키면 된다.** 모르는 명령을 직접 입력하지 말 것.

---

## 6. 절대 하면 안 되는 것

- ❌ 두 창에서 **동시에 배포**
- ❌ 리뷰 **없이** 바로 배포
- ❌ 손으로 `clasp push`
- ❌ 모르는 git 명령 직접 입력 (→ 대신 Claude 창에 말로)
- ❌ 같은 파일 두 창 동시 편집

## 나중에(안정된 뒤) 확장할 것

- **Claude가 Codex를 자동 호출**하는 오케스트레이션 — 지금은 손으로 두 창 조정. 익숙해지면 도입.
- **워크트리 분리** — "긴 작업을 한 창에 맡기고 다른 창에서 딴 작업"을 동시에 하고 싶어질 때만.

두 가지 다 지금은 불필요하다. 지금 세팅(순차 핸드오프)이 솔로 운영엔 가장 단순하고 안전하다.
