# BM 통합설계 — 운영 계획 계산 엔진

이 폴더에는 운영 계획의 계산 엔진과 근거 조사만 남아 있다. 회사 BM 문서는 비공개 보관함의 `SYNK-보관함/BM_심화/` 하나만 쓴다. 2026-11-14에 유호님이 「앞으로 bm관련해서는 이 심화버전만 사용해 나머지는 다 삭제해주고」라고 하셨다. BM_심화는 이 폴더의 `results.json`을 읽어 운영 계획 층을 만든다.

## 남아 있는 것

| 파일 | 하는 일 |
|---|---|
| `inputs.mjs` | 운영 계획의 가정이 모두 있다. 숫자는 여기서만 고친다. |
| `model.mjs` | 계산 규칙이다. 직접 실행하면 `results.json`을 다시 쓰고 결과 표를 콘솔에 찍는다. 다른 파일에서 불러올 때는 파일을 쓰지 않는다. |
| `results.json` | 모든 달과 모든 가정의 계산 결과다. BM_심화와 시험이 이 파일을 읽는다. |
| `조사/` | 근거 조사 일곱 편이다. 시장 깔때기, 울란바토르 현지 조사, 베트남 조사, 셋째 나라 비교, WORLD 학습자, SHIFT 강의 강사료, 기존 결정 정리가 있다. |

엔진의 WORLD 값 가운데 일부는 지운 옛 BM 목록 6절과 BM-1 「돈 계산」 줄(09-22 계산)에서 왔다. 시장 몫 방식의 `online.worldB2C`는 옛 6-2 표의 12개월째와 36개월째 월 매출이다. 그 곡선을 구독자 수로 바꿔 보이는 `worldNetPerSubKRW`는 BM-1 「돈 계산」 줄의 ㉯ 값이다. 운영 계획과 세 지표의 `netKRW`와 `netKRWGlobal`은 옛 6-1의 섞음과 BM-1 「돈 계산」 줄에서 왔다. 그 절은 2026-11-14에 지웠고, 지우기 직전 판은 git 기록의 `docs/BM_목록.md`에 있다. 이 값을 바꿀 때는 그 판에서 가정을 꺼내 BM_심화에 먼저 적는다.

## 다시 계산하는 법

1. `inputs.mjs`에서 가정을 고친다.
2. 저장소 뿌리에서 `node docs/유지비_BM/BM_통합설계_20261018/model.mjs`를 실행한다. 검산이 실패하면 종료 코드가 1이 된다. 「recalc1110 글의 전제」로 시작하는 실패는 계산이 틀렸다는 뜻이 아니다. 글이 기대는 사실이 바뀌었다는 뜻이므로, 그 사실을 쓰는 글(정직원 조건, SHIFT 사업·BM, 트랙, 비공개 BM_심화 16절)을 다시 본다.
3. `node --test tests/bm-premium.test.mjs`로 시험한다.
4. 비공개 보관함의 BM_심화를 다시 만든다. 사업계획서의 숫자도 이 결과에 맞춘다.
