# SYNK 글쓰기 기준

읽는 사람이 한 번에 이해하고, 다음 문장까지 자연스럽게 읽을 수 있도록 쓴다

홈페이지, 앱, 철학과 운영 문서, 소개서, 게시물, 안내문, AI의 답변과 작업 보고에 함께 적용한다. 글의 목적과 독자에 따라 말투와 길이를 조절하며, 모든 글을 같은 형식으로 만들지는 않는다.

## 쓰기 전에

누가 읽는지, 무엇을 알아야 하는지, 읽은 뒤 무엇을 할 수 있어야 하는지부터 정한다. 답을 묻는 사람에게는 답을 먼저 주고, 설명이 필요한 사람에게는 이해에 필요한 맥락을 함께 준다. 행동을 요구할 필요가 없는 글에 질문이나 참여 요청을 억지로 붙이지 않는다.

회사와 제품의 뜻은 [철학 정본](SYNK_철학.md), 고객과 제공물은 [마케팅 정본](마케팅_정본.md)에서 확인한다. 문장 흐름과 문장부호는 이 문서를 공통 기준으로 삼고, 문서별 구성과 세부 편집은 [집필 규범](정본/SYNK/SYNK%20집필%20규범.txt)의 관련 절을 참고한다. 학생용 글은 `synk-brand`와 [캐릭터 정본](캐릭터/가이드_정본.md)을 함께 읽는다. 예전 문서의 사업명·수치·사례를 현재 사실로 복사하지 않는다.

## 문장은 뜻을 따라 잇는다

한 문장에는 중심 생각 하나를 담되, 서로 붙어 있어야 이해되는 원인과 결과를 잘게 끊지 않는다. 앞 문장에서 생긴 궁금증을 다음 문장이 풀어 주도록 쓴다. 같은 주어나 같은 어미를 연달아 반복하면 문장을 합치거나 말의 순서를 바꾼다.

짧은 문장만 이어 놓으면 말이 뚝뚝 끊기고, 모든 내용을 한 문장에 넣으면 관계가 흐려진다. 짧고 긴 문장을 내용에 맞게 섞고, 뜻이 바뀌는 곳에서 문단을 나눈다. 줄바꿈으로 문장의 연결을 대신하지 않는다.

| 다듬기 전 | 다듬은 뒤 |
|---|---|
| 파일을 확인했습니다. 수정했습니다. 다시 검사했습니다. 문제가 없습니다. | 파일을 수정한 뒤 다시 검사했고, 같은 문제가 생기지 않는 것을 확인했습니다. |
| 저장이 안 됐어요. 연결이 끊겼어요. 다시 해 주세요. | 연결이 끊겨 저장하지 못했어요. 인터넷 연결을 확인한 뒤 다시 저장해 주세요. |
| 신청 가능 여부 확인을 진행해 주세요. | 신청할 수 있는지 확인해 주세요. |
| 배움·경험·성장·가능성을 연결합니다. | 배운 것을 직접 해 보고, 그 경험을 바탕으로 다음 목표를 정합니다. |

예시는 문장 연결을 보여 주기 위한 것이다. 실제 결과나 제품 기능을 확인하지 않은 채 예문 그대로 쓰지 않는다.

## 마침표는 자리에 맞게 쓴다

모든 줄 끝에 마침표를 붙이지 않는다. 제목과 버튼처럼 눈으로 구분되는 짧은 문구는 마침표 없이 끝낸다. 여러 문장이 이어지는 본문에서는 문장 경계가 분명하도록 마침표를 쓴다. 마침표를 덜기 위해 서로 다른 문장을 띄어쓰기만으로 이어 붙이지 않는다.

| 자리 | 기본 방식 | 예 |
|---|---|---|
| 제목, 소제목, 메뉴, 버튼 | 끝 마침표 생략 | 오늘의 연습 / 저장하기 |
| 짧은 상태 안내, 한 줄 설명 | 마침표 없이 자연스럽게 마무리 | 저장했어요 / 다음에 이어서 할 수 있어요 |
| 표의 짧은 항목, 나열형 목록 | 끝 마침표 생략 | 설치 확인 완료 |
| 설명 문단, 여러 문장으로 된 안내 | 문장 사이에 마침표 사용 | 저장하지 못했어요. 연결을 확인한 뒤 다시 시도해 주세요. |
| 짧은 대화 답변 | 한 문장으로 끝나는 문단의 마지막 마침표는 생략 가능 | 네, 이 기준으로 다듬겠습니다 |
| 질문 | 답이 필요한 질문에 물음표 사용 | 어느 시간대가 편하세요? |

같은 역할의 항목은 표기를 맞춘다. 한 화면이나 목록에서 이유 없이 마침표 유무를 섞지 않는다. 긴 설명이 필요한 항목은 별도 문단으로 풀어 쓴다.

가운뎃점 `·`, 빗금 `/`, 화살표 `→`도 말을 대신해 반복하지 않는다. 짧은 이름을 나열하거나 실제 순서를 보여 줄 때만 쓰고, 본문에서는 ‘와’, ‘하고’, ‘한 뒤’처럼 관계가 드러나는 말로 잇는다. 느낌표와 말줄임표는 감정이나 망설임이 꼭 필요한 자리에서만 쓴다.

주소, 파일명, 코드, 소수점, 버전 번호의 점은 문장부호 정리 대상이 아니다. 원문 인용과 법정·계약 문구, 승인된 고유 표기는 임의로 고치지 않는다. 한국어 학습 예문은 가르치는 문법과 문장부호를 정확히 유지하고, 다른 언어는 해당 언어의 관습을 따른다.

## 익숙하고 구체적인 말로 쓴다

누가 무엇을 하는지 보이게 쓴다. ‘제고’, ‘도모’, ‘진행’, ‘제공’ 같은 말이 겹치면 실제 행동으로 풀어 쓴다. 전문 용어가 필요하면 처음 나오는 자리에서 뜻을 설명하고, 내부 파일명이나 시스템 이름은 독자의 이해와 선택에 도움이 될 때만 드러낸다.

추상적인 가치를 연달아 나열하기보다 실제 상황이나 행동으로 설명한다. 구체적으로 보이게 만들려고 없는 사례나 수치를 지어내서는 안 된다. 차이를 설명할 필요가 있을 때만 비교하고, 매 문단을 ‘A가 아니라 B’라는 구도로 만들지 않는다.

강조는 핵심에만 둔다. 문장마다 굵게 표시하거나 목록으로 바꾸지 않는다. 설명은 문단으로 잇고, 나란히 비교할 내용은 표로, 실제 순서는 번호 목록으로 쓴다.

## 말투는 읽는 사람에게 맞춘다

| 글의 자리 | 말투와 내용 |
|---|---|
| 홈페이지와 소개서 | 처음 온 사람이 하는 일과 제공물을 이해하도록 차분하고 구체적으로 설명 |
| 앱과 알림 | 지금 상태와 다음 행동을 쉬운 말로 안내 |
| 학생과 캐릭터의 말 | 학습 수준과 인물의 성격에 맞추되, 학생을 낮춰 보거나 재촉하지 않기 |
| 철학과 운영 문서 | 핵심 뜻, 판단 근거, 적용 범위를 정확하게 연결 |
| 대화와 작업 보고 | 질문의 답이나 실제 결과를 먼저 말하고, 필요한 근거와 남은 일만 덧붙이기 |

친근함을 만들려고 유아어, 과한 감탄, 상투적인 칭찬을 덧붙이지 않는다. 한 글 안에서는 호칭과 높임말을 유지하되, 대사와 설명처럼 역할이 다른 부분은 구분한다.

## 다듬은 뒤 확인한다

완성한 글을 처음 읽는 사람의 입장에서 처음부터 끝까지 이어 읽는다. 주어를 되찾느라 되돌아가거나 문장 사이의 관계를 추측해야 한다면 그 부분을 다시 쓴다. 같은 말이 반복되거나 한 줄마다 멈추는 느낌이 들면 중복을 덜고 문장을 잇는다.

제목과 짧은 안내에 붙은 불필요한 점을 덜어낸 뒤, 본문에 필요한 문장 경계는 남아 있는지 확인한다. 화면에 들어가는 글은 실제 크기에서 읽어 보고, 좁은 칸에 맞추려고 중요한 조건을 빼지 않는다.

마지막으로 원문과 대조해 주체, 조건, 약속, 수치, 시제가 달라지지 않았는지 확인한다. 계획한 것, 구현한 것, 게시한 것, 실제로 확인한 것을 구별한다. 문장이 부드러워져도 사실의 범위는 그대로여야 한다.
