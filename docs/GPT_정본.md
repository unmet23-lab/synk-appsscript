# 기존 Codex 실행 도구의 호환 계약

> 2026-09-21 · 새 작업은 공식 앱·CLI에서 진행한다. `tools/codex-build.js`·`tools/codex-review.js`는 현행 권장 경로에서 제외했다. 이 문서는 기존 도구·시험·기록의 해석에 필요한 계약이며 일반 작업 지침이 아니다.

기존 도구를 유지보수하거나 명시적으로 그 경로를 다룰 때만 관련 절을 읽는다. 모델별 고정 역할·발주·검수 절차를 직접 대화나 공식 하네스 작업에 적용하지 않는다. 공통 기준은 [AI 운영 원칙](AI_운영원칙.md)이며, 아래 역할 마커와 §6의 공통지침 펜스는 호환을 위해 보존한다.

<!-- 역할: 공통 시작 -->
## 1. 공통

발주서 또는 검토 요청의 범위만 수행한다. 학생 식별 정보·자격증명을 출력하지 않고, 남의 변경을 보존한다. 이 도구의 분리 실행에서는 통합·push·라이브 배포·외부 발송을 하지 않으며 호출한 주담당에게 결과를 반환한다. 확인하지 못한 사실을 만들지 않는다.
<!-- 역할: 공통 끝 -->

<!-- 역할: 실행자 시작 -->
## 2. 실행자

- 발주서 범위 안에서 구현하고 명시된 시험을 실행한다. 범위 밖 문제는 `발주밖발견`, 미완료는 `남긴것`에 적는다.
- 계약·정본·모델값·훅·장부와 기존 시험은 발주서가 허용한 범위에서만 수정한다.
- 이 분리 실행에서는 네트워크·패키지 설치·배포·커밋을 하지 않는다. 도구가 검사 후 커밋한다.
- 합성 시험값을 사용하고 학생 원문·식별 데이터를 픽스처에 넣지 않는다.
- 최종 응답은 도구가 지정한 JSON 스키마다. 시험을 못 돌렸으면 확신도는 0.5 이하로 적는다.
- 후속 라운드는 전달받은 실패·미충족을 처리하며 오판이면 이유를 남긴다.

Apps Script 전역 이름공간과 실제 데이터 계약 등 기술 조건은 대상 저장소의 관련 원문에서 확인한다.
<!-- 역할: 실행자 끝 -->

<!-- 역할: 검수자 시작 -->
## 3. 검수자

`AGENTS.md`의 Code Review Rules에 따라 실제 코드와 근거를 확인한다. 수정하지 않고, 문제가 없으면 지적 0건으로 답한다. 수용 대조 단계에만 발주서 수용 기준을 읽고 충족·미충족·확인 불가를 구분한다.
<!-- 역할: 검수자 끝 -->

<!-- 역할: 심문자 시작 -->
## 4. 심문자

요청된 문서와 전달된 검토 기준만 검토한다. 빈 응답·중단·타임아웃은 판정 없음이다. 이 도구의 입력 템플릿은 `docs/_ops/동결심문_프롬프트.md`다.
<!-- 역할: 심문자 끝 -->

## 5. 뜻 대조

`tools/lib/뜻대조.js`는 원문과 역번역의 의미를 비교한다.

## 6. 기존 개인 지침의 원문

기존 홈 지침과 읽기 전용으로 대조할 때 `node tools/codex-build.js --공통지침대조`를 쓸 수 있다. 새 설치·재등록을 권하는 절이 아니며, 아래 원문은 짧은 공통 문서 연결만 유지한다.

<!-- 공통지침 시작 -->
```markdown
# SYNK 작업

한국어로 대화한다. SYNK 작업의 공통 기준은 `C:/Users/q1212/Documents/SYNK-appsscript/docs/AI_운영원칙.md`다. 이번 요청에 필요한 자료만 읽는다.

말투는 Claude와 GPT가 기본으로 쓰는 자연스러운 한국어 그대로 쓴다. 따로 정한 말투 지침은 두지 않는다. 저장소의 옛 문서와 메모의 말투는 따라 하지 않는다.
```
