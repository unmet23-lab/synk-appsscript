# 솔리오 사무실에서 직원에게 일 맡기기

회원이 사무실에서 Claude Code 또는 GPT(Codex)를 고르고 한 건의 업무를 보낸다. 요청 원문, 진행 상태, 최종 답을 같은 방에서 다시 볼 수 있다. 11월 20일 결정에 따라 개발 PC에서 두 제공자의 기본 로그인으로 확인한다. 일반 설치판에서 맡기기를 켜는 시점은 두 회사의 사용 정책 답을 받은 뒤다. [사무실 설계](구현설계.md#solio-office-assignment)

## 회원이 하는 일

이 PC에서는 시작 메뉴의 ‘솔리오 사무실 (개발판)’을 연다. 처음에는 솔리오에 로그인하고 ‘직원 사용’을 누른 뒤 사무실을 선택한다.

사무실 그림에서 직원을 누르면 그 직원과 부서가 선택되고 요청 입력란이 열린다. 키보드로 직원 목록을 골라도 된다. 직원이 아직 보이지 않으면 입력란 위에서 Claude 또는 GPT를 고른다. 부서가 없으면 회원별 사무실 작업 폴더를 쓴다. 등록된 부서에서 맡기면 그 부서의 폴더와 역할을 쓴다. ‘이어서 맡기기’를 누르면 같은 직원과 대화에서 다음 일을 시작한다.

맡기면 요청이 바로 목록에 생긴다. 기다림, 진행 중, 터미널 확인, 완료, 중단 또는 실패를 구분한다. 마지막 답은 줄바꿈을 유지해 평문으로 보여 준다. 바쁜 동안 다음 요청을 작성해도 먼저 맡긴 일의 답이 도착한다. 완료한 답은 방을 나갔다 오거나 앱을 다시 열어도 남는다. 실패나 로그인 필요 상태에는 원인과 가능한 다음 행동이 보인다. 회원의 명시적인 재시도만 새 실행을 시작한다.

## 본체와 두 공식 도구

기존 사무실의 회원 및 로그인 회차 확인과 신뢰된 플랫폼 창 IPC를 그대로 쓴다. 개발판에서는 업무 목록을 읽고 제출, 취소, 재개, 공식 터미널 열기, 회원이 붙여넣은 답 보관을 할 수 있다. 요청을 보낼 때 화면은 담당자, 요청, 부서나 이전 업무의 번호와 중복 제출을 막는 번호를 보낸다. 본체가 현재 회원과 권한, 실행할 도구와 폴더를 결정한다. 도구가 보낸 최종 답은 본체에서 확인한다.

Codex는 기본 ChatGPT 로그인으로 공식 app-server에 연결한다. 솔리오에서 시작한 스레드와 차례의 마지막 답, 정상 완료 상태를 함께 확인한다. 파일 쓰기 등 권한 질문이 오면 본체는 해당 차례를 중단한다. 회원은 사무실에서 공식 터미널을 열고 `/status`로 계정을 확인한다. 업무 카드의 이어가기 문구를 직접 붙여넣어 보내면 그 계정에 이전 대화도 함께 전달된다. 별도 터미널은 각 차례를 실행한 계정을 솔리오에 알려 주지 않는다. 이 경우에는 회원이 그 창에서 원하는 답을 복사해 원래 업무 카드에 붙여넣고 ‘답 보관’을 누른다. 직접 옮긴 답은 앱을 다시 열어도 같은 카드에서 읽고 복사할 수 있다.

Claude Code는 업무 폴더에서 기본 구독 로그인을 확인한다. 로그아웃 상태면 요청을 보관하고 로그인이 필요하다고 알려준다. 로그인한 회원에게는 공식 대화형 콘솔을 연다. 회원이 도구 사용을 승인하는 곳도 이 콘솔이다. 요청을 보내기 직전에 같은 구독 계정인지, 별도 Console 프로필이나 API 키를 지정한 환경인지 확인한다. 이 검사를 실행하지 못해도 요청을 막는 기능이 있는 Claude Code 2.1.295 이상을 사용한다. [Claude Code 인증](https://code.claude.com/docs/en/authentication) · [제출 훅의 실패 처리](https://code.claude.com/docs/en/hooks#block-the-action-when-a-hook-fails)

요청을 보내기 전에 같은 업무 폴더와 설정에서 사용자 메시지 없이 연결을 시험한다. Claude Code가 이번 실행의 확인값을 돌려주지 않으면 원문은 사무실에 보류한다. 실제 터미널은 업무마다 새로 만든 식별 문구로 시작한다. 해당 터미널에서 계정과 제출을 확인한 뒤 업무 원문과 부서 역할을 공식 제출 훅의 추가 문맥으로 전달한다. [Claude Code 명령행](https://code.claude.com/docs/en/cli-reference) · [Claude Code 제출 훅](https://code.claude.com/docs/en/hooks#userpromptsubmit-decision-control)

이번 요청의 답과 공식 세션 기록을 대조한다. 같은 요청에서 답이 끝난 뒤 다른 작업을 요구한 훅이 없고 차례가 종료된 경우 완료로 저장한다. 내부 도우미의 응답은 공식 세션에 적힌 작성자와 원래 업무의 도우미 번호가 일치할 때 잇는다. Claude가 답을 보냈으나 완료를 확인할 수 없으면 ‘완료 확인 전 답’으로 먼저 보여 준다. 카드는 그 본문과 현재 업무 상태를 함께 보여 준다. 도구 사용 승인이 필요하면 확인 전 답을 읽으면서 공식 창을 열 수 있다. 창을 닫거나 앱을 다시 열어도 저장된 글을 읽을 수 있다. 인증 오류와 한도, 답 없는 종료에는 원인을 표시한다.

일반 업무는 공식 CLI의 기본 로그인과 이미 허용된 MCP 도구를 따른다. GPT 직원의 메일 검색에는 회원이 솔리오에 직접 연결한 업무용 메일함을 쓴다.

## GPT 직원에게 메일 찾기를 맡길 때

개인 Windows 개발판에서는 사무실에서 GPT 직원을 고르고 Gmail 옆의 ‘연결’을 누른다. Google 화면에서 사용할 메일 주소를 직접 고르고 읽기 권한을 허용한다. 다른 주소를 쓰려면 기존 연결을 해제한 뒤 새 주소를 고른다. Outlook 앱 등록은 나중에 진행하기로 했다.

예를 들어 “지난주 받은편지함에서 이번 달 예산 관련 메일 찾아줘”라고 맡기면 솔리오는 이 PC의 달력을 기준으로 바로 전 주 월요일부터 일요일까지 받은 메일에서 이번 달 예산을 찾는다. 카드에서 검색 기간과 각 메일의 제목, 보낸 사람, 날짜, 짧은 미리보기를 읽고 원문을 열 수 있다. “같은 기간에 이번엔 계약서만 찾아줘”라고 이어서 맡기면 기간을 유지하고 검색어를 바꾼다. 각 메일함에서 최대 열 건을 보여 주며 확인하지 못한 범위를 카드에 표시한다.

자동 모드에서 GPT 직원은 메일을 언급한 요청을 읽고 어디에서 무엇을 찾아야 하는지 판단한다. “메일로 받은 견적서 찾아줘”는 사서함에서 찾고, “Gmail 사용법을 웹에서 찾아줘”는 웹 자료를 찾는 일반 업무로 맡길 수 있다. 처음부터 메일 검색이나 일반 업무를 골라도 된다.

검색할 곳이나 기간이 분명하지 않으면 솔리오가 메일함을 열기 전에 업무 카드에 조건을 보여 준다. 같은 카드에서 검색어, 보낸 사람, 기간, 편지함, 계정, 첨부 여부를 고치고 검색할 수 있다. 검색 전에 앱을 닫아도 다시 열면 원래 제안과 지원하지 않는 조건을 확인할 수 있다. 두 메일함 중 한 곳에서 문제가 생기면 다른 쪽의 결과를 먼저 보고 실패한 쪽만 다시 검색할 수 있다. 후속 업무에는 앞서 검색한 계정 중 지금도 연결된 메일함을 쓴다.

이전 검색에서 쓴 Gmail과 Outlook을 다시 지정했는데 한 계정의 연결이 바뀌었다면, 솔리오는 그 주소를 카드에 표시하고 기다린다. 회원이 남은 계정으로 검색을 진행하면 결과에도 이번에 제외한 주소가 남는다.

요청의 기간을 정할 수 없으면 카드에서 시작일이나 종료일을 입력한다. 전체 기간을 보려면 ‘기간 제한 없이 검색’을 직접 선택한다. 지원하지 않는 조건을 빼기로 했다면 검색이 끝난 뒤에도 카드에서 그 조건을 확인할 수 있다.

요청에 나온 이름이 찾을 메일의 발신자인지 불분명하면, 카드에서 원문과 제안한 이름을 함께 보여 준다. 회원은 그 사람을 발신자로 지정하거나, 그 인용을 제외하거나, 다른 발신자를 직접 입력할 수 있다. 편지함이 불분명할 때도 같은 방법으로 고른다. 선택한 뒤 검색을 누르면 나머지 조건과 함께 적용한다.

“받은편지함과 보낸편지함에서 견적 메일 찾아줘”라고 하면 두 폴더에 있는 메일을 모아 보여 준다. 보관 처리한 수신 메일까지 찾으려면 “받은 메일 전체에서 찾아줘”라고 요청한다. [Gmail 검색 조건](https://support.google.com/mail/answer/7190) · [Outlook 폴더별 메일 조회](https://learn.microsoft.com/en-us/graph/api/user-list-messages?view=graph-rest-1.0)

“첨부파일이 있는 견적 메일만 찾아줘”라고 하면 카드의 검색 조건에 첨부파일 여부가 표시된다. 첨부파일 이름이나 내용까지 확인해야 하면 카드에서 요청을 조정할 수 있다. Outlook에서는 본문에 넣은 그림만 있는 메일을 일반 첨부파일로 세지 않는다. [Gmail 검색 연산자](https://support.google.com/mail/answer/7190) · [Microsoft의 메일 검색 조건](https://learn.microsoft.com/en-us/graph/search-query-parameter#use-search-on-message-collections)

일반 메일 검색에서 GPT가 받는 내용은 회원이 입력한 요청이다. 솔리오 본체가 Gmail API와 Microsoft Graph에서 메일을 찾아 원문 링크와 미리보기를 카드에 표시한다. 연결을 이어 가는 토큰과 카드에 보관한 검색 결과는 해당 Windows 사용자의 암호화 저장소를 쓴다. 회원이 연결을 해제하면 새 검색을 멈추고 이미 보관한 카드는 다시 읽을 수 있다. [Gmail 검색](https://developers.google.com/workspace/gmail/api/guides/filtering) · [Outlook 메일 검색](https://learn.microsoft.com/en-us/graph/search-query-parameter#use-search-on-message-collections)

견적 담당에게 답장 초안까지 맡기고 싶으면 같은 사무실의 ‘미회신 견적 문의 넘기기’를 선택한다. 메일 담당이 문의를 찾고 견적 담당이 해당 문의를 읽어 초안을 쓴다. [두 직원의 견적 문의 인계](견적문의_인계.md)

Google 계정을 고른 뒤 테스트 사용자만 이용할 수 있다는 메시지가 나오면, 운영자가 Google Auth Platform의 ‘대상’에서 선택한 주소를 테스트 사용자로 추가한다. [Google의 대상 및 테스트 사용자 설정](https://developers.google.com/workspace/guides/configure-oauth-consent)

개발판 운영자는 메일 전용 데스크톱 클라이언트를 등록한다. Google은 Gmail API, 사용자 확인과 읽기 권한을 쓴다. Microsoft는 개인 계정과 조직 계정을 받는 공개 클라이언트로 등록하고 모바일 및 데스크톱 반환 주소에 `http://localhost`를 넣는다. 메일 API에는 위임 권한 `User.Read`와 `Mail.Read`를 쓰고, 갱신을 위해 `offline_access`를 요청한다. 운영자 등록 설정은 `%LOCALAPPDATA%/synk/solio-office-dev/office-access/mail-oauth-clients.json`에서 제공한다. 최상위 `gmail`에는 `clientId`와 발급받은 `clientSecret`, `outlook`에는 `clientId`를 넣는다. [Google 데스크톱 앱 등록](https://developers.google.com/identity/protocols/oauth2/native-app) · [Microsoft 데스크톱 앱 등록](https://learn.microsoft.com/en-us/entra/identity-platform/scenario-desktop-app-registration)

## 보존과 경계

회원별 Office 폴더의 tasks.json에 업무를 기록하고, 마지막 답은 업무 번호별 파일에 원자적으로 저장한다. 업무는 512건까지 보관한다. 긴 답은 최대 524,288자까지 저장하며 상한을 넘으면 화면에 원인을 표시한다. 저장에 실패하면 기존 일을 보존하고, 방을 다시 읽을 때 받은 답의 저장을 다시 시도한다. 부서가 없는 회원의 작업 파일은 개발판의 OfficeWork 아래에 둔다. 요청을 먼저 저장한 뒤 프로세스를 시작한다. 중복 누름과 늦은 이벤트는 실행 번호로 구분한다. 앱을 닫거나 로그아웃하면 현재 실행을 중단한다. 다시 열면 대기 중이던 일은 회원이 직접 재개한다. 부서 폴더는 저장된 번호로 찾는다. 화면의 결과는 평문이다.

Claude의 확인 전 답도 업무별 파일에 보관한다. 새 본문을 먼저 저장하고 업무 목록이 새 파일을 가리킨 뒤 이전 본문을 정리한다. 다음 작업의 권한을 기다리거나 앱을 닫아도 마지막 본문을 보존한다. 회원이 진행 중인 업무를 직접 취소하면 임시 본문은 지우고 요청 원문은 남긴다. 옛 개발판이 다른 GPT 터미널에서 가져온 답 파일은 그대로 보존한다. 그 업무의 카드에는 회원이 직접 옮긴 글만 표시한다.

한 Windows 사용자 안에서 공식 터미널은 기본 CLI에 저장된 대화를 함께 볼 수 있다. 승인한 회원 한 명을 Windows 사용자 폴더의 `synk/solio-office-dev/office-access`에 보관한다. 솔리오의 앱 데이터 폴더를 바꾸거나 다른 회원에게 보기 권한을 줘도 직원 사용자는 그대로다.

‘이어서 맡기기’는 처음 답한 Claude 또는 GPT 계정을 확인한 뒤에만 이전 대화를 연다. GPT는 현재 선택한 개인 또는 회사 워크스페이스도 대조한다. 확인에는 대화마다 다른 지문을 쓴다. 계정이나 워크스페이스가 달라지거나 옛 개발판에 그 기록이 없으면 기존 답을 읽거나 새 업무를 맡길 수 있다. GPT의 별도 터미널에서는 회원이 현재 계정을 직접 확인한다.

## 비교 근거와 확인

Windows에서 시험용 솔리오 회원으로 사무실을 열고, 이 PC의 기본 ChatGPT 로그인으로 실제 답을 받았다. ‘맡기기’를 두 번 눌러도 실행은 한 번이었다. 앱을 완전히 닫았다가 다시 열어 같은 업무의 요청과 답을 확인했다. 최종 개발판의 GPT 직원에게 임의의 단어를 답하게 한 뒤 같은 대화에 새 요청을 보냈다. 두 번째 요청에 단어를 적지 않아도 첫 답을 정확히 기억했다. 파일 쓰기 승인은 격리된 폴더에서 모의 모델을 연결한 공식 Codex로 시험했다. 공식 터미널에서 이번 한 번을 허용한 뒤에 파일이 생겼다.

Claude 기본 계정 연결은 나중에 하기로 했다. 실제 로그아웃 상태에서 사무실이 원문을 보존하고 로그인 안내를 표시하는 것을 확인했다. 별도 격리 환경에서 이 PC에 설치된 공식 Claude Code에 로컬 시험 응답을 보냈다. 요청 원문과 최종 답이 일치했고, 터미널은 약 61초 뒤 입력 대기를 알렸다. 개인 Claude 구독의 실제 모델 응답은 로그인한 뒤 확인할 수 있다.

합성 데이터로는 취소, 계정 변경, 저장 실패와 복구, 부서 없음과 삭제, 결과 도착 중의 한글 초안과 문자 그대로의 HTML 표시를 시험했다. 일반 설치판에서는 직원 실행 경로가 닫힌 것도 확인했다.

Windows 사무실 화면에서 시험용 Gmail과 Outlook을 연결한 뒤 이 PC의 실제 GPT 직원에게 “지난주 받은편지함에서 견적 메일 찾아줘”라고 맡겼다. 11월 9일부터 15일까지 찾은 두 메일을 같은 카드에서 읽고 각각의 원문 단추를 눌렀다. 앱을 다시 열었을 때 같은 결과와 원문 단추를 사용할 수 있었다. 메일 전용 Google 앱은 실제 계정 선택 화면까지 확인했다. 개인 메일함은 회원이 앱에서 직접 고른다.

Gmail만 설정한 시험에서도 같은 요청으로 Gmail 메일 한 건을 찾았다. 앱을 다시 열었을 때 새 검색 없이 원래 카드에서 같은 메일의 원문을 열 수 있었다.
