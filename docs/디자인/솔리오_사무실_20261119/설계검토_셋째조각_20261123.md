## 1. 도구 없는 길(D1)과 둘째 조각 위에 얹기

D1은 맞다. 입력이 두 도구에서 같아지고, 숨은 지시가 쓸 도구가 없으며, 울타리를 코드로 지킨다. 다만 「분기 하나」와 5.3은 지금 코드와 맞지 않는다.

- **[P1-1] 매주 줄이 조용히 멈춘다(5.2 다섯째 줄, 5.3).**
  - 읽는 중에 앱을 끄면 `rows()`가 `running`을 `interrupted/RESTART`로 바꾼다(office-tasks.cjs 191~208). `resume`은 `paused`만 받는다(777~779). 5.3의 「쉬던 줄을 다시 시작」은 기다리던 줄에만 통한다. 돌던 줄은 `weeklyState.taskId`가 끝난 줄을 가리킨 채 남는다.
  - 로그아웃하면 `schedulePark`가 `paused/AUTH_CHANGED`로 바꾼다(803~806). 복구는 `paused`를 건너뛰고(199), `recovered`는 프로세스에 한 번이라(188, 210) 다시 로그인해도 그대로다.
  - 「지금 읽기」가 기다리던 중에 앱을 끄면 `paused/RESTART`로 남는다. 손님이 그 물음을 안 누르면 5.2의 「이미 기다리는 읽기 · 말 없음」에 걸려 매주 읽기가 영영 서지 않는다.
  - 고침: 매주 줄은 다시 잇지 않는다. `due()`가 매번 `taskId` 줄의 실제 상태를 보고, `queued`(허가 있음)나 `running`이 아니면 그 줄을 닫고 자리가 유효할 때 새 줄을 세운다. 「기다리거나 도는 중」에서 `paused`는 뺀다. 그러면 `rows()`에는 「매주 기능 줄은 `paused` 대신 `interrupted`」 한 줄만 든다.
- **[P1-2] 읽은 파일과 업무 줄 사이에서 바뀜이 사라진다(2.2의 7, 2.3, 4.2).**
  - 차례: `run`이 `reads/…json`을 쓴다 → `finish`가 tasks.json을 쓰기 전에 앱이 꺼지거나, 쓰기가 실패하거나, 손님이 취소한다(598~599) → 줄은 `interrupted`가 된다 → 다음 읽기는 방금 쓴 파일(3만 원)과 견줘 「지난번과 같습니다」라고 말한다. 5만→3만 알림은 한 번도 보이지 않는다. 「취소하면 아무것도 쓰지 않는다」도 깨진다.
  - 4.2의 읽은 파일에 `changes`가 없다. 화면이 무엇으로 바뀜 카드를 그리는지도 정해지지 않았다.
  - 고침: 읽은 파일에 `changes`와 `baseline`(견준 읽기)을 넣고, 기계 상태 파일에 「아직 안 본 바뀜」을 둔다. 기능 줄과 느낌표는 읽은 파일에서 그린다. 업무 줄의 `answer`는 사본이다.
- **[P2-1] 손댈 곳은 여섯 자리이고 8절에 `office-task-store.cjs`가 빠졌다.**
  - `submitFeature`, 사양 만들기(546), 런타임 분기, `finish`(624~632는 `result.answer`가 있어야 완료), 복구, `publicTask`다.
  - `baseTask`(store 44~63)가 `feature`를 화면에 주지 않아 「이어서 맡기기」를 가릴 수 없다. Codex 길은 `hooks.session`(office-task-codex.cjs 383)이 줄에 `sessionId`를 적어, 이어 맡기면 `submit` 286행을 통과한 뒤 `thread/read`에서 `SESSION`으로 죽는다.
  - 런타임 `run`은 분기 앞에서 `native(spec.provider)`(128)를 부른다. 기능 분기의 자리를 정해 둔다.
- **[P2-2] 기능 읽기가 부서 폴더에 묶인다.** `submit`과 `pump`가 `context()`로 부서 폴더를 확인하고 `entry.cwd!==ctx.cwd`면 `FOLDER`로 닫는다(436~442, runtime 64~71). 부서 폴더가 외장 디스크에 있거나 옮겨지면 폴더를 쓰지 않는 읽기도 실패한다. 기능 줄은 수용 인원만 받게 한다.
- **[P2-3] 「구독 한도를 같이 따른다 · 0%면 기다린다」(0절 3, 5.2 끝)는 지금 참이 아니다.** 런타임은 `officeCapacity`에 구독 값을 넘기지 않는다(runtime 122, office-model.mjs 383 주석). 0%에서 「지금 읽기」는 돌다가 `LIMIT`으로 실패한다.
- **[P2-4] 업무 512건 상한(store 16, tasks 283).** 정리하는 코드가 없다. 매주 줄과 재시도 줄이 쌓여 상한에 닿으면 손님의 평소 맡기기까지 `STORAGE_FULL`이 된다. 끝난 기능 줄은 부서마다 최근 몇 건만 남긴다.
- **[P2-5] 수용 인원이 하나인 PC.** 켜자마자 선 매주 읽기(최대 20분)가 자리를 잡아 손님의 첫 일이 기다린다(444). 쪽마다 AI 제한 시간을 두고, 손님 일이 서면 매주 읽기가 물러나는 규칙을 둔다.

## 2. 두 도구 호출

- **[P1-3] Codex: `mailTurn`을 쪽마다 다시 쓰면 아홉째 쪽에서 죽는다.**
  - `turns`는 8개가 차면 `MAIL_PLAN`을 건다(office-mail-rpc.cjs 47). 지금은 인스턴스 하나에 `ask` 한 번뿐이다(office-mail-plan.cjs). 쪽은 13개까지다(4.1).
  - `active`가 앞 차례 번호로 남아 새 차례의 소식을 버린다(45).
  - 실패 코드가 `MAIL_PLAN`, `MAIL_TIMEOUT`이라 경쟁사 카드에 메일 말이 뜨고 5.2의 재시도 목록에도 없다.
  - 고침: `schemaTurn`은 차례마다 상태를 새로 잡고 코드를 인자로 받는다. 연결 하나에 스레드 여럿으로 갈지 쪽마다 서버를 띄울지도 정한다(`servers()` 확인이 `ask`마다 돈다).
- **[P1-4] Claude: 구독으로 도는지 확인이 실행과 어긋난다(돈).**
  - `readSubscriber`는 `--setting-sources user`로 `auth status`를 본다(office-task-claude-hook.cjs 16). 2.4의 실행은 `--setting-sources project`다.
  - 둘째 조각은 실행 안에서 훅으로 실제 환경을 다시 본다(같은 파일 55행 주석, office-task-claude.cjs 47, 55). 무인 실행에는 그 확인이 없다. 관리 설정이 API 키나 Bedrock을 넣는 PC에서는 매주 읽기가 구독 밖 요금으로 나갈 수 있다.
  - 고침: `--output-format stream-json`으로 첫 `system/init`의 `apiKeySource`, `tools`, `mcp_servers`를 보고 어긋나면 바로 죽인다. Codex 길의 `servers(client,threadId)` 확인과 같은 꼴이다. 시험도 인자 목록 확인으로 끝내지 않는다.
- **[P2-6] 2.4에 빠진 것.**
  - 쪽 글을 넘기는 길. 인자로 넘기면 Windows 명령줄 길이에 걸리고 프로세스 목록에 보인다. 표준 입력으로 넘긴다.
  - `--model`. 손님 기본이 큰 모델이면 기준 3이 깨진다.
  - 프로세스 제한 시간과 자식까지 죽이기.
  - 결과가 `is_error`이거나 한도 문구일 때 `LIMIT`, `LOGIN`으로 가르는 법. 가르지 않으면 모든 쪽이 `no_answer`인 「완료」가 된다.
  - 「매번 새 임시 폴더」는 `~/.claude.json`에 폴더 항목을 쌓을 수 있다. 고정된 빈 폴더 하나를 쓴다.
- **[P3-1] 이 PC의 Claude Code는 2.1.323까지만 확인했다(`--help`가 응답하지 않았다).** 지을 때 확인할 것은 넷이다.
  - `--disallowedTools "mcp__*"`가 유효한 꼴인지.
  - `--strict-mcp-config`가 claude.ai 커넥터도 막는지.
  - `--tools ""`에서 `--json-schema`의 구조 출력이 나오는지, `--max-turns 3`이 넉넉한지.
  - `--bare`는 구독 로그인을 읽지 않으니 쓰지 않는다.

## 3. 쪽 읽기 울타리

- **[P2-7] 주소 대역.** 빠진 것은 `0.0.0.0/8`, `::`, `::ffff:`로 싼 IPv4, `100.64/10`, `198.18/15`, 멀티캐스트, NAT64다. A와 AAAA 답 전부를 본다. 포트는 80과 443만 받는다.
- **[P2-8] 읽는 수단을 못박는다.** Electron `net`이나 기본 세션은 쿠키와 시스템 프록시를 탄다. node `https`에 직접 만든 `lookup`을 쓰고, 프록시 환경 값이 있으면 읽지 않는다.
- **[P2-9] 크기는 압축을 푼 뒤의 3MB다.** 피드 XML은 엔티티를 펴지 않는 파서로 읽는다.
- **[P2-10] 글자 집합.** 한국 쇼핑몰과 게시판에는 EUC-KR이 흔하다. 정하지 않으면 글이 깨져 「원」을 못 읽고 모든 칸이 비는 놓침이 된다. 9절 시험에도 없다.
- **[P2-11] robots.txt.**
  - 넘겨진 뒤의 호스트와 길, `<link rel="alternate">` 피드에도 다시 본다.
  - robots.txt 자체도 같은 울타리로 읽는다.
  - 4xx는 허락, 5xx와 시간 초과는 막음으로 정한다.
  - 피드와 robots 읽기도 2초 간격과 20분 셈에 넣는다.
- **[P2-12] 20분.** 쪽 13 × (15초 + AI 100초)는 20분을 넘는다. 넘겼을 때 읽은 쪽을 쓸지 버릴지 정해지지 않았다.
- **[P2-13] 주소를 넣을 때의 읽기.** 4.1은 이름을 쪽 제목에서 짐작한다고 하고 종류는 첫 읽기에서 정한다고 한다. 더하기에서 읽는다면 업무 줄 밖의 읽기다(확인 지점, 계정 묶음, 간격이 없다). 한쪽으로 정한다.
- **[P3-3]** 손님이 붙인 주소의 쿼리 토큰이 list.json과 로그에 그대로 남는다.

## 4. 근거 문구, 숫자, 견주기 — 깨지는 입력

- **[P1-5] 배송 조건에는 뒤바뀜 막이가 없다(4.4, 시안 322행도 같다). 거짓 알림이 난다.**
  - 쪽 글: 「배송비 3,000원 · 5만 원 이상 무료 · 정기배송은 2만 원 이상 무료 · 도서산간 추가 배송비 5,000원」. 1주에 AI가 「5만 원 이상 무료」를, 2주에 「정기배송은 2만 원 이상 무료」를 고르면 「무료 배송 기준을 5만 원에서 2만 원으로 낮췄습니다」가 뜬다. `fee`도 3,000과 5,000 사이를 오간다.
  - 1주 「5만 원 이상 구매 시 무료 배송」, 2주에 배지 「무료배송」을 고르면 `freeOver:0`이 되어 「모든 주문을 무료로 보내기 시작했습니다」가 뜬다.
  - 「5만 원 미만 구매 시 배송비 3,000원」(미만 꼴)은 4.3의 꼴에 없다.
  - 고침: 값과 같은 막이(지난 숫자가 이번 쪽의 배송 문맥 숫자에 있으면 바뀜 아님)를 둔다. 기준 없는 「무료」는 비움으로 읽는다. `freeOver:0`은 「전 상품」이나 「조건 없이」가 문구에 있을 때만 준다.
- **[P1-6] 값: D3은 가장 흔한 내림을 놓치고, 50개 자르기는 거짓 알림을 만든다.**
  - 놓침: 「39,000원」이 「정가 39,000원 → 할인가 29,000원」으로 바뀌는 것이 보통의 세일이다. 지난 값이 쪽에 남아 영영 알리지 않는다(기준 2).
  - 거짓: `pricesSeen`은 오름차순 50개다. 값이 80개인 목록 쪽에서 지난 값 89,000원이 잘려 「없다」가 되고, AI가 다른 값을 고르면 알림이 난다.
  - 고침: 「값이 다르고 (지난 값이 이번 쪽에 없다 또는 새 값이 지난 쪽에 없었다)」로 바꾼다. 이번 쪽은 메모리의 전체 집합으로 보고, 지난 쪽 집합은 넉넉히(예 300개) 저장한다. AI가 이미 있던 다른 값을 고른 뒤바뀜은 양쪽에 다 있어 여전히 걸러진다.
- **[P1-7] 새 글 제목: HTML 게시판에서 거짓 「새 글」.**
  - 게시판 한 쪽은 15~20줄인데 칸은 10개다. AI가 주마다 다른 열 줄을 고르면 4주째에 「앞 세 번에 없던」 옛 글이 새 글이 된다.
  - 제목 끝의 댓글 수 「[3]→[4]」, 「N」 표시, 「[마감]」 머리말도 새 글이 된다.
  - 고침: 피드가 없으면 코드가 고리 글 후보를 뽑고 AI는 그 안에서만 고른다. 견줌 열쇠는 글의 고리 주소다. 「앞 세 번」 대신 쌓아 둔 본 글 집합(상한 500)을 쓴다.
- **[P1-8] 하나도 못 읽은 읽기가 「같습니다」가 되고 자리를 쓴다(4.4, 4.5, 5.1).** 켠 직후 네트워크가 붙기 전이거나 절전에서 깬 순간이면 모든 쪽이 `timeout`이다. 표에는 「바뀜 없음」 문장뿐이고 자리는 `done`이 되어 한 주를 건너뛴다. 읽은 쪽이 없거나 절반 아래면 「이번에는 읽지 못했습니다」로 적고 자리를 쓰지 않은 채 다시 한다.
- **[P2-14] 그 밖의 입력.**
  - 「문구의 마지막 값」: 「12,000원 (100g당 1,200원)」은 1,200, 「29,000원 적립 290원」은 290이 된다. 진짜 내림이 와도 숫자가 틀린 문장이 나간다. 원 단위가 붙은 가장 큰 판매가 문맥을 고르는 규칙이 필요하다.
  - JSON-LD: `offers`가 배열이거나 `AggregateOffer`일 때, `@graph`에 `Product`가 여럿일 때, 통화가 원이 아닐 때의 고르는 법이 없다. JSON-LD가 정가만 담는 쇼핑몰에서는 AI를 부르지 않아 할인가 변화를 놓친다. 구조 자료 값도 쪽 글 값 집합과 견줘 확인한다.
  - 쪽 정체: 손님이 주소나 종류를 고쳤을 때, 단종 상품이 다른 길로 넘겨질 때(`finalUrl` 바뀜) 옛 값과 견줘 거짓 내림이 난다. 견줌 기준을 새로 잡는다.
  - 문구 확인: NFC, 폭 없는 글자, `&nbsp;`, 굽은 따옴표를 양쪽에서 같게 접지 않으면 맞는 문구가 버려진다.
  - 12개 보관: 13주 넘게 막힌 쪽은 「마지막으로 제대로 읽은 값」이 지워진다. 쪽마다 마지막 좋은 값을 상태 파일에 따로 둔다.
- 1절 기준 1의 「쌍 50개」는 지은 사람이 만든 합성 쌍이면 자기 확인이 된다. 12절의 공개 쪽 스무 개를 두 도구로 두 번씩 읽어 녹화한 쌍을 넣는다.

## 5. 매주 읽기의 때

- **[P1-9] 켜는 순간 바로 한 번 더 읽는다(5.1).** 자리는 「지금보다 앞선 가장 가까운 정한 때」라 늘 과거에 있다. 「아직 안 읽었으면 세운다」와 만나면, 첫 읽기 직후 「켜기」를 누르자마자 읽기가 한 번 더 선다. 요일이나 시각을 바꿀 때와 기능을 다시 붙일 때도 같다. 켜거나 바꾼 때를 적고 그 뒤의 자리만 센다.
- **[P2-15] 실패 재시도.**
  - `LIMIT`은 30분 뒤에도 실패한다. 다시 차는 때까지 미룸으로 돌린다.
  - `LOGIN`, `NO_CLI`, `FOLDER`, `WRITE`, `STORAGE_FULL`, `MAIL_*`의 갈 곳이 없다.
  - `finish`의 결과를 기능이 아는 길이 없다. P1-1의 `due()` 대조로 푼다.
- **[P2-16] 틱 자리.** main.cjs 349행의 2분 틱은 구독 판 파일이 없으면 첫 줄에서 돌아간다. 그 안에 `due`를 넣으면 구독 방을 안 이은 손님에게 D6의 「몰라서 미뤘습니다」도 적히지 않고 「다음 읽기 월 09:00」만 남는다. 13절의 「조용히 돌지 않았다」 그대로다. `due`는 그 조건 밖에 두고, 「켜기」에서 구독 값이 없으면 그 자리에서 말한다.
- **[P3-4]** 자리 열쇠가 시간대 없는 글자다. PC 시계나 시간대가 바뀌면 같음 비교가 한 번 더 읽게 한다. 차례로 견준다. 자리 직전의 「지금 읽기」가 그 자리를 채운 것으로 칠지도 정한다.
- **[P3-5]** 20%를 재는 값이 「기본 로그인」 계정의 것인지 확인이 필요하다. 구독 방은 여러 계정을 잇는다(D9). subscription-*.cjs는 읽지 못했다.

## 6. 저장과 계정

부서 번호는 무작위(office-store.cjs 263~268)라 D8의 남는 파일이 새 부서에 붙지 않는다. 계정 폴더 구조도 맞다. `commitFile`(store 75)을 다시 쓰면 된다.

- **[P1-10] list.json 덮어쓰기(3.3, 4.1).** 손님의 목록과 기계의 `weeklyState`가 한 파일에 있다. 읽기가 도는 20분 사이에 손님이 주소를 더하면, 끝날 때 읽기가 시작 때의 사본에 `weeklyState`를 얹어 써서 새 주소가 사라진다. 순서가 반대면 `done`이 지워져 한 번 더 읽는다. 손님 파일(`list.json`)과 기계 파일(`state.json`)로 가르고, 한 줄 서기 안에서 읽고 고쳐 쓴다.
- **[P2-17] 그 밖의 저장.**
  - 파일 이름 `<읽은 때>.json`에 `:`가 들어가면 Windows에서 만들 수 없다. `20261123T000211Z-<taskId>` 꼴로 정한다.
  - 깨진 list.json을 빈 목록으로 갈아 쓰지 않는다는 규칙이 없다.
  - 「기록 지우기」와 도는 읽기가 겹칠 때의 차례가 없다.
  - 「마케팅부」라는 이름으로 줄이 서는 것이 만들 때 한 번인지 이름을 볼 때마다인지 정해지지 않았다. 이름을 바꾸면 줄과 매주 읽기가 말없이 사라질 수 있다.

## 7. 화면

원인 넷 가운데 「시작하는 자리」와 「결과가 꼬리표」는 시안이 피했다. 나머지는 덜 닫혔다. 시안은 코드로만 읽었고 띄워 보지 않았다.

- **[P1-11] 「대응 맡기기」가 경쟁사 글을 도구 있는 세션에 넣는다(시안 361~365, 권한).** 맡기는 글에 가게 이름과 쪽 이름(쪽 제목에서 짐작), 새 글 제목(160자)이 그대로 들어간다. 이 글은 부서 폴더에서 손님 도구와 MCP를 쓰는 평소 업무가 된다. D1이 막은 숨은 지시가 이 길로 들어온다. 숫자와 손님이 고친 이름만 문장에 넣고 제목은 「신뢰할 수 없는 자료」 JSON으로 싸며, 보내기 전에 손님이 글을 본다. 답이 어디에 서는지도 없다. Claude면 공식 콘솔 창이 뜨는데 화면은 「맡았습니다」에서 끝난다.
- **[P2] 처음 쓰는 사람.** 가장 흔한 첫 입력은 가게 첫 화면 주소다. 값이 수십 개라 엉뚱한 값을 적거나, 스마트스토어와 쿠팡은 robots나 스크립트로 「읽지 못함」이 된다. 더하기 직후 「이 쪽에서 읽을 수 있는 것」을 보여 주고, 상품이 여럿이면 「상품 쪽 주소를 넣어 주세요」로 이끈다. 「쪽」이라는 말은 낯선이시험에서 따로 본다.
- **[P2] 시안에 없는 모습.** 바뀜과 같음 화면에 「지금 읽기」, 매주 끄기와 때 바꾸기, 가게 빼기가 없다(470, 480, 501행은 처음과 미룸에서만 그린다). 실패, 기다림, 이름과 종류 고치기, 기록 지우기, 「읽지 못한 쪽」 묶음(CSS만 있다), 부서 안쪽 기능 줄도 없다. 앱에 옮기기 전에 시안에 먼저 그린다.
- **[P2] 6.2 표와 시안이 다르다.** 표는 검은 방의 흰 글과 30px이고, 시안은 흰 종이에 검은 글과 검은 알약, 28~42px이다. 흰 종이 판은 사업계획서에서 미학 맹검 네 장이 모두 기각됐다(README 90행). 경쟁사 시안의 맹검 기록이 없다.
- **[P2] 움직임과 자료.** 「찾은 값이 쪽 줄 끝에 앉는다」는 쪽마다의 값이 읽는 중에 화면에 와야 한다. 2.3의 진행은 글 한 줄뿐이고 결과는 끝에 한 번 쓴다. 진행에 `{쪽, 상태, 값}`을 싣든지 시안을 고친다.
- **[P3]** `.back`, `.quiet`, 「쪽 열기」의 아래 선(67, 108, 153행)은 밑줄로 읽힌다. `.handed`의 왼쪽 굵은 선과 옅은 바탕(111행)은 흔한 생성물 꼴이다. 유호님 취향에 비춰 확인한다.

## 8. 기능의 꼴

대체로 맞고, 쪽 읽기와 `schemaTurn`은 지원사업 공고에 그대로 쓴다.

- 모자람: 영수증 `{summary, readId, changes}`가 경쟁사 전용이다. `{summary, ref, alert}`로 넓힌다. 블로그 글이나 SNS 반응은 도구와 승인이 드는 평소 업무이니, `makeTask`가 무인 기능 실행과 평소 맡기기 가운데 무엇을 내는지 가른다. 기능 알림은 구현설계 7절의 알림 셋에 없는 넷째다.
- 지나침: 기능이 하나인데 `features.json`, 「기능 더하기」 화면, 이름으로 자동 붙이기를 다 짓는다. 첫 판은 목록과 채널만 두고 붙이기 화면은 둘째 기능 때로 미룬다.

## 짓기 전에 고칠 것

1. 매주 줄은 다시 잇지 않고 `due()`가 줄 상태를 대조해 닫고 새로 세운다. 「기다리는 중」에서 `paused`를 뺀다(P1-1).
2. 읽은 파일에 `changes`와 `baseline`, 상태 파일에 「안 본 바뀜」을 두고 화면은 그것으로 그린다(P1-2).
3. `schemaTurn`은 차례마다 상태를 새로 잡고 실패 코드를 인자로 받는다(P1-3).
4. Claude 실행은 `system/init`의 `apiKeySource`, `tools`, `mcp_servers`를 확인하고, 계정 확인의 설정 출처를 실행과 맞춘다(P1-4).
5. 배송 조건에 뒤바뀜 막이를 두고 `freeOver:0`의 조건을 좁힌다(P1-5).
6. 값 규칙을 양쪽으로 보는 식으로 바꾸고 값 집합을 자르지 않는다(P1-6).
7. 새 글은 코드가 뽑은 후보와 고리 주소, 쌓아 둔 집합으로 견준다(P1-7).
8. 못 읽은 읽기의 문장과 자리 처리를 정한다(P1-8).
9. 켜거나 바꾼 때 앞의 자리는 세지 않는다(P1-9).
10. `list.json`과 `state.json`을 가르고, 파일 이름에서 `:`를 뺀다(P1-10, P2-17).
11. 「대응 맡기기」 글에서 경쟁사 글을 자료로 싸고, 보내기 전에 보이며, 답이 서는 자리를 정한다(P1-11).
12. 울타리 표에 주소 대역, 압축 푼 크기, 글자 집합, robots 세부, 읽는 수단을 더한다(P2-7~11).
13. 2.4에 표준 입력, 모델, 제한 시간, 한도 가르기, 고정 빈 폴더를 더한다(P2-6).
14. 8절에 `office-task-store.cjs`를 넣고, 부서 폴더 의존, 512건 정리, 구독 값 넘기기, 틱 자리를 정한다(P2-1~4, P2-16).
