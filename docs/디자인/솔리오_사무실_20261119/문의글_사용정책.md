# 사무실 사용 정책 문의 글 (2026-11-19, 보내기 전 초안)

유호님 11-19 「문의 글 쓰기」에 따라 썼다. 솔리오 사무실의 둘째 조각(솔리오가 Claude Code와 Codex를 실행)을 내기 전에 Anthropic과 OpenAI에 보낼 글이다. 아직 보내지 않았다. 유호님이 11-20에 「문의는 전부 개발하고 맨 마지막에 하자」고 정하셨다. 세 조각을 다 지은 뒤에 보낸다. 그때 창구와 약관을 다시 읽고 글을 지은 모습에 맞춰 고친다. 까닭은 [구현 설계](구현설계.md) 10절과 17절에 있다.

## 보내기 전에 유호님이 채우실 것

- 글 속의 `[ ]` 칸: 보내는 사람 이름, 회사 이름 표기, 답을 받을 메일.
- 솔리오를 돈을 받고 파는지. OpenAI 글의 넷째 물음이 여기에 달려 있다. 지금은 「정해지지 않았다」고 썼다.
- 동시에 일하는 수의 기본값. 글에는 설계의 첫 값(16코어 32GB PC에서 여덟)을 썼다.

## 보낼 곳

11-20에 두 창구를 직접 열어 보았다. 둘 다 처음 생각한 꼴이 아니다.

- **Anthropic.** [법률 및 준수](https://code.claude.com/docs/en/legal-and-compliance) 쪽의 contact sales 링크는 <https://claude.com/contact-sales>로 간다. 그 쪽에는 양식이 없다. 「영업팀은 500석 이상 도입이나 BAA 같은 복잡한 계약만 돕는다」고 적혀 있고, 길은 둘이다. 「채팅 시작하기」(Claude 계정으로 로그인해서 묻는 창구, 필요하면 영업팀으로 이어 준다고 한다)와 [고객지원 센터](https://support.claude.com/en/)다. 채팅은 유호님의 Claude 계정으로 하는 것이라 유호님이 직접 하시거나, 유호님 계정으로 넣어도 된다고 하신 뒤에 한다. 사람에게 닿지 않을 수 있다.
- **OpenAI.** [Sign in with ChatGPT 약관](https://openai.com/policies/sign-in-with-chatgpt-terms/) 쪽에는 문의 주소가 없다. 조사에서 나온 partnercomms@openai.com은 이 쪽에서 확인되지 않았다. 확인되지 않은 주소로는 보내지 않는다. 쪽에 있는 길은 「세일즈 문의」(<https://openai.com/contact-sales/>)와 [도움말 센터](https://help.openai.com/)다. 어느 길로 보낼지는 유호님이 정한다.

## 11-20에 OpenAI 약관을 직접 읽고 안 것

- OpenAI에는 다른 앱이 손님의 ChatGPT 요금제를 쓰게 하는 공식 길이 있다. Sign in with ChatGPT의 「ChatGPT 플랜 사용」이고, 개발 도구(`sign-in-with-chatgpt-devkit`)가 공개돼 있다. 사무실은 이 로그인을 넣지 않고 손님의 Codex를 실행하므로 이 약관이 바로 적용되지는 않는다. 다만 OpenAI가 바라는 길이 이쪽일 수 있다. 글의 둘째 물음이 이것이다.
- 그 길의 조건은 사무실이 하려는 것과 거의 겹친다. 요청은 손님의 PC에서, 그 손님을 위해서만 난다. 사용 한도를 비켜 가게 돕지 않는다. 백그라운드 사용은 미리 분명한 동의를 받는다. 그리고 손님이 돈을 내거나 유료판으로 올리지 않아도 자기 요금제를 쓸 수 있어야 한다.
- 마지막 조건 때문에, 솔리오가 유료가 되더라도 사무실의 맡기기를 유료판에만 두면 이 길과 어긋난다. 글의 넷째 물음이 이것이고, 답과 상관없이 값 매기기를 정할 때 알아 둘 일이다.

## 11-19에 Anthropic 원문을 다시 읽고 안 것

구현 설계 10.1보다 조금 더 분명해졌다. 설계에도 옮긴다.

- 제품 안에서 Claude Code를 미리 설치하거나 실행하려면 상용 약관에 동의하고 조건 둘을 지켜야 한다.
- 조건 하나: Claude Code를 고치지 않고, 들어 있는 로그인 방법을 빼거나 막지 않는다.
- 조건 둘: 손님의 사용량을 대신 내거나 되팔거나 중개하지 않는다. 손님은 자기 API 키나 자기 구독 로그인으로 직접 인증하고, 사용량은 손님에게 청구된다.
- 구독 요금제의 한도는 한 사람의 평범한 사용을 전제로 한다고 적혀 있다.

사무실은 조건 둘을 모두 지킨다. 그래서 남은 물음은 금지냐 허락이냐보다 좁다. 상용 약관 동의를 어떻게 하는지, 그리고 여러 세션을 동시에 돌리는 것과 매주 무인으로 돌리는 것이 「평범한 사용」에 드는지다.

## Anthropic에 보낼 글

```
Subject: Permitted-use question — a desktop app that shows and launches the user's own Claude Code

Hello,

I am [name] at [company], a small company in Korea. We make SOLIO, a Windows desktop app for
solo business owners and developers who work with several AI coding tools at once. We are
adding a feature that involves Claude Code and would like to confirm it fits your terms
before we release it. The legal and compliance page of the Claude Code docs points
authentication questions to this form.

What the feature does

Stage 1 (view only). If the user turns it on, SOLIO adds HTTP hook entries to the user's own
Claude Code settings file (Notification, Stop, PostToolUse, SessionStart, SessionEnd,
SubagentStart, SubagentStop). The hooks post to 127.0.0.1 on the same PC. SOLIO shows each
session's state, for example that a session asked for permission three minutes ago. Nothing
leaves the PC. In this stage SOLIO does not start Claude Code.

Stage 2 (launch). When the user types a task, SOLIO opens a console window on the user's PC
and starts the claude binary that the user installed and signed in to themselves, in a folder
the user chose. It passes the task as the prompt, a --settings value with the same hooks, and
a short --append-system-prompt. Permission prompts are answered by the user in Claude Code's
own window. One optional feature runs claude -p once a week with a narrow tool allowlist
(reading public web pages and writing one result file).

What SOLIO does not do

- It has no sign-in screen for Claude and never reads, stores, or transmits credentials or
  tokens.
- It does not bundle, modify, or wrap the Claude Code binary, and does not remove or restrict
  any sign-in method.
- It does not use the Agent SDK with subscription credentials and does not route requests.
- It does not pay for, resell, or meter Claude usage. Usage is billed to the user's own plan.
- It limits how many sessions it starts at once, based on the PC's CPU and memory and on the
  plan's remaining usage. The default on a 16-core, 32 GB PC is eight, and it drops to one
  when little plan usage is left.
- In the interface it says in plain text that a task runs with Claude Code. It does not use
  the Claude Code or Anthropic names or logos in product or feature names.

Questions

1. Does Stage 2 count as running Claude Code in our product, as described in the section on
   offering Claude Code in products? If so, is agreeing to the Commercial Terms of Service and
   meeting the two listed conditions sufficient, and how should a company like ours agree to
   them?
2. In that setup, may end users authenticate with their own Pro or Max subscription?
3. The page says plan limits assume "ordinary, individual usage". Is it consistent with that
   for one user to run several sessions in parallel on their own PC, each started by the user?
   Is there a number of parallel sessions you would not consider ordinary?
4. Is the weekly unattended claude -p run acceptable under the user's subscription, or should
   scheduled runs use an API key?
5. Do you have any concern with Stage 1, where an app adds hook entries to the user's
   settings file with the user's consent and removes them when turned off or uninstalled?
6. Is this sentence acceptable in our interface: "Runs with Claude Code installed on this PC.
   Usage comes from your Claude plan."

We will not release Stage 2 until we hear from you. Thank you for your time.

[name]
[company]
[reply email]
```

## 두 글이 말하는 것 (우리말)

두 글의 짜임은 같다.

1. **누구인지.** 한국의 작은 회사이고, AI 도구 여럿을 함께 쓰는 1인 기업과 개발자를 위한 Windows 앱 솔리오를 만든다.
2. **기능이 하는 일.** 첫 단계는 보기만 한다. 손님이 켜면 손님 PC 안에서 세션 상태를 받고, 아무것도 PC를 떠나지 않는다. 둘째 단계는 손님이 일을 적으면 손님이 직접 설치하고 로그인한 도구를 손님 PC의 콘솔 창에서 띄운다. 승인은 그 도구의 창에서 한다. 매주 한 번 무인으로 공개된 웹 쪽을 읽는 기능이 하나 있다.
3. **하지 않는 일.** 로그인 화면이 없고 로그인 값을 읽거나 보관하거나 보내지 않는다. 도구를 고치거나 묶어 넣지 않는다. 사용량을 대신 내거나 되팔거나 재지 않는다. 동시에 띄우는 수를 묶는다. 이름과 로고를 제품과 기능 이름에 쓰지 않는다.
4. **묻는 것.**
   - 이렇게 실행해도 되는지, 되려면 무엇에 동의해야 하는지.
   - 손님이 자기 구독으로 인증해도 되는지(Anthropic), Sign in with ChatGPT 프로그램에 들어가야 하는지(OpenAI).
   - 여러 세션을 동시에 돌리는 것이 요금제가 전제하는 사용에 드는지.
   - 매주 무인 실행을 구독으로 해도 되는지, API 키를 써야 하는지.
   - 솔리오가 유료여도 되는지(OpenAI).
   - 화면에 쓸 설명 문장이 괜찮은지.
5. **맺음.** 답을 받기 전에는 둘째 단계를 내지 않는다.
