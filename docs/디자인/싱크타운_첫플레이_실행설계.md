# 싱크타운 첫 플레이의 공간과 실행 설계

2026-10-08 착수, 10-09 상세 보완. 내 집에서 나와 찻집의 자리를 바꾸고, 주민의 이용을 보고, 집으로 돌아오는 첫 생활의 제작 명세다. [첫 생활 원고](싱크타운_첫생활구간_원고.md), [메인 구현 준비](싱크타운_메인콘텐츠_구현준비.md), [NPC 자율생활](싱크타운_NPC자율생활_설계_20261008.md)을 구체적인 공간·입력·취소·복원으로 연결한다. 아래는 이번 상세 설계에서 채택하는 제작안이며 실제 코드·계정 연결·미술의 완료와 구분한다.

첫 연결은 H00→FT00→FT10→선택한 FT51→귀가다. 열 가지 생활의 전체 범위는 그대로 유지하며, 이 경로는 첫 구현 인계 단위다. 무료 첫 챕터의 다른 세 경로는 기존 원고대로 독립적으로 들어간다.

## 1 첫 공간의 확정 편성

첫 배경은 **미래 서울의 강변을 바라보는 낮은 주거 골목**으로 잡는다. 멀리 수변 보행교와 수상 교통의 움직임, 가까이 처마·나무 받침·낮은 화단을 둔다. 현재 서울의 특정 장소가 실제로 이렇게 개발된다고 설명하지 않는다. 공간 감각은 [미래 한국 풍경](미래한국_마을_풍경.md)을 따른다. **2026-10-09 사용자 변경 확정:** 조작은 WASD·방향키, 모바일 가상 조이스틱, 표준 게임패드로 직접 걷는 자유 연속 이동과 캐릭터 추적 시점을 기본으로 한다. 대상 가까이에서 E·상호작용 버튼·게임패드 A로 생활을 연다. 이전 바닥 탭 이동과 장소 메뉴의 순간이동은 기본 조작에서 폐기하며, 이동·근접만으로 문답을 자동 시작하지 않는다. 이 변경은 구현 기준이며 실제 조작·휴대폰 검증 완료를 뜻하지 않는다.

| 공간 ID | 고정 구성과 연결 | 허용 자리와 이동 | 첫 플레이의 기능 |
|---|---|---|---|
| home | 창문, 낮은 탁자, 방석, 생활 수첩, 출입문 | `home-window`와 `home-table` 중 방석 한 자리. 두 자리에서 문까지 통로 항상 유지 | 창가에서 쉬기 또는 탁자 곁에서 쉬기. 배치 생략하고 바로 외출 가능 |
| lane | 집 문→쉼터 입구의 짧은 길, 강변 조망, 처마 연결 | 출입문·쉼터 입구는 겹치지 않는 대기 자리. 판매대·소품 배치 금지인 통로 띠 유지 | 산책·목적지 취소. 길을 읽기 시험으로 만들지 않음 |
| shelter | 찻집 처마, 기본 의자 1개, 서빙대, 바깥 빈 자리, 안내판 받침 | 기존 `garden/garden-right/eaves-left/eaves-right`, 안내판 `entrance-left/entrance-right`를 유지. 좌표는 구현 때 실제 길찾기 망에 대응 | 바깥 차양 또는 처마 자리. 뒤의 T02·T01에서도 같은 물건과 자리를 이용 |
| workshop-edge | 쉼터와 이어진 공방 앞 작업대 | `workshop-demo`와 구경 자리 분리. 안쪽 공방 전체 탐험 불필요 | 공방 주인의 제작 시범과 첫 차양 만들기 |

이 편성의 기본 소유는 개인 방석 1개·고정 탁자 1개·기록 수첩 1개다. 첫 집 생성 때 `home-starter:v1` 지급 이력으로 한 번만 준비하고 판매·분해·코인 교환은 없다. 초기 상태가 확인되지 않은 로딩 화면에서 먼저 지급하지 않는다. FT10 차양과 재료는 기존 지급·소유 계약 그대로 별도다. 찻집 의자·서빙 잔·안내판은 주민 비품이며 집으로 가져갈 수 없다.

처음에는 창가에 방석이 놓여 있다. 위치의 차이는 **강을 바라보며 쉬기 / 탁자 곁에서 기록 보기**로 바로 보인다. 기록은 어느 자리에서도 열 수 있어 가구 배치가 기능 잠금이 되지 않는다. 창가는 실제 조명·날씨를 사용하고 밤에 햇살을 보았다고 말하지 않는다. 날씨 데이터가 없으면 마지막 확인 상태를 중립적으로 표시한다.

## 2 집의 실제 원고와 물건

마스코트는 선택한 캐릭터 한 명만 나온다. 말은 말풍선으로, 소리는 기존 비언어 소리 원칙으로 표현한다. 새 TTS·인물 목소리를 붙이지 않는다. 아래 원고는 [캐릭터 정본](../캐릭터/가이드_정본.md)의 몽글의 함께하는 질문, 까몽의 자기 취향, 마린의 짧은 보고를 구분한다. 마스코트를 숨긴 경우 같은 기능과 일반 행동 목록만 남는다.

| 장면 | 실제 행동과 화면 문구 | 마스코트 말풍선 또는 대안 | 선택 뒤 남는 것 |
|---|---|---|---|
| H00.01 맞이 | 문 앞을 비워 둔 채 창문·방석·문을 차례로 한 번 바라봄. 설명 팝업 없음 | 몽글 “우리 여기서 쉬어 볼까?” / 까몽 “이 몸은 창가가 좋겠어.” / 마린 “휴식 지점 확인.” | `[둘러보기] [밖으로 가기] [쉬기]`. 반응 없이 이동해도 진행 가능 |
| H00.02 자리 | 방석 가까이 목록 `[자리 바꾸기]`. 창가/탁자 곁 실루엣을 같은 크기로 비교 | 요청한 도움만 몽글 “여기는 강이 보여! 저기도 볼까?” / 까몽 “이 몸은 여기서 강을 보겠어.” / 마린 “창가. 강이 보인다.” | `[창가] [탁자 곁]`은 초안. `[여기에 놓기]`가 같은 방석의 위치를 변경. 취소는 이전 위치 |
| H00.03 외출 | 키·조이스틱·게임패드로 문까지 직접 걷는다. 문 근처에서 E·상호작용 버튼의 `[마을로 나가기]`를 선택 | 문에는 일반 이름표 “마을로”. 추가 캐릭터 대사를 요구하지 않음 | 문까지 자동 이동하거나 장소 메뉴로 순간이동하지 않음. 실제 출입은 확인된 위치·권한으로 수행 |
| H00.04 귀가 | 방석의 현재 배치와 수첩을 보여 줌. 수첩 목록 `[이번 생활 보기]` | 몽글 “우리 만든 자리, 다시 볼까?” / 까몽 “난 그 자리가 마음에 들더라.” / 마린 “함께 만든 자리. 기록 확인.”는 마스코트가 FT10 결과를 동행해 실제 본 경우만 | 동행하지 않았다면 대사 없이 수첩을 가리킴. A 수첩 “찻집 밖에 그늘을 만들었어요.” / B “의자를 안으로 옮겼어요.” |
| H00.05 마침 | `[쉬기]`면 방석 위 휴식 자세. `[그만하기]`는 기존 앱 종료 흐름 | 몽글 “같이 조금 쉬자.” / 까몽 “이 몸도 쉬어야겠어.” / 마린 “휴식 시작.” | 자동 후속·숙제 제안 없음. 진행 중 작업은 마지막 확정 지점 유지 |
| H00.06 복귀 | 집과 현재 수첩 복원. 미완 장면이 실제 있으면 `[하던 일 보기]` | 기본 무언 맞이. 부재 기간을 평가하거나 밀린 일을 말하지 않음 | `[집에 있기] [밖으로 가기]`. 미완 장면이 없으면 계속 버튼을 만들지 않음 |

H00.04의 ‘함께 만든’ 말은 FT10 바깥 제작을 동행해 본 경우에만 쓴다. 안쪽 이동은 몽글 “우리 옮긴 자리, 다시 볼까?”, 까몽 “난 옮긴 자리가 좋더라.”, 마린 “의자 이동. 기록 확인.”로 갈라 쓴다. 다른 NPC에게만 알려진 기억을 마스코트가 가져오지 않는다. 수첩은 플레이어 자신의 확정 사실을 표시하므로 동행 유무와 무관하게 볼 수 있다.

## 3 첫 경로의 세 입력 방식

아래 의도는 고르기·조립·주제 안 직접 답하기에서 같은 초안으로 모인다. 직접 답하기는 아래와 같은 검수 표현과 정해진 의도만 처리한다. 알 수 없는 문장에는 “이 뜻인가요?”와 가능한 그림을 보여 주며 **긍정 확인 전 상태를 바꾸지 않는다**. 음성 입력은 준비된 장치에서만 같은 텍스트 의도로 들어오며 필수는 아니다.

| 차례 | 고르기 | 조립 낱말과 직접 답하기 예 | 반대 표현과 확인 | 취소·도움 |
|---|---|---|---|---|
| H00 자리 | 창가 / 탁자 곁 | 창가에·놓을래요 / “탁자 옆에 놓을게요” | “창가 말고 탁자 옆이요”→탁자 초안. `[이 자리에 놓기]` | “그대로 둘래요”→초안 폐기. 두 시야 미리보기 |
| FT00 할 일 | 자리 / 메뉴 / 식물 / 이야기 / 산책 | 자리를·만들어요 / “자리를 바꿔 볼래요” | “차 말고 자리요”→자리 입구. 없는 경로를 이름만 보고 실행하지 않음 | “둘러볼게요”→미수락. 기존 결과 그대로 |
| FT10 안과 밖 | 밖 / 안 | 밖에·놓을래요 / “안이 좋아요” | “밖 말고 안이요”→안 초안. “안에는 안 놓을래요”→밖인지 보류인지 그림 확인 | `[다시 고르기]`. 안/밖 그림 비교 |
| FT10 재료 받기 | 만들기 / 다시 고르기 | 같이·만들어요 / “지붕을 만들래요” | “아직 안 만들어요”→지급 없음. “재료만 볼게요”→보기만 | 최초 2목재·1천 표시 후 수령/진행 확인. 이미 받은 경우 잔량만 표시 |
| FT10 색 | 초록 / 노랑 | 초록으로·만들어요 / “노란색이 좋아요” | “초록 말고 노랑이요”→노랑 견본. 색 선택만으로 소비 없음 | 물건 두 견본, 색 이름 없이 그림 선택 가능 |
| FT10 제작 | 만들기 / 돌아가기 | 이 색으로·만들어요 / “이걸 만들게요” | 실제 색·재료2+1·결과1을 보여 주고 `[만들기]`. “만들 수 있어요?”는 질문 | 도움 시 공방 주인이 시범, 소비·권리는 동일 |
| FT10 배치 | 현재 갈래의 두 유효 자리 | 여기에·놓아요 / “길 옆에 놓을래요” | “여기 말고 저기”는 지시 대상 불확실→두 자리 표시. `[여기에 놓기]` | 통로 침범은 확정 불가, 물건 보존. 대안도 사용자 확인 |
| FT51 그림 | 의자 / 차 | 의자 그림을·놓아요 / “차 그림이 좋아요” | “글씨 말고 그림으로요”→그림 종류를 다시 묻기. 임의 기본값 확정 없음 | 그림 예시. 글 이해를 먼저 요구하지 않음 |
| FT51 위치 | 입구 왼쪽 / 입구 오른쪽 | 길 옆에·놓아요 / “오른쪽이요” | 그림·목표 현재 좌석·표지 위치를 한 화면에서 `[여기에 놓기]` | `[그만두기]`는 기존 표지 복원. 새 표지를 복제하지 않음 |
| 끝과 귀가 | 앉기 / 둘러보기 / 집으로 | 집으로·가요 / “여기 더 있을래요” | “집에 안 갈래요”→머무름. “집이 어디예요?”→길 보기 | 길 보기만으로 이동·장면 종료하지 않음 |

실제 입력 시험에는 위의 긍정·부정·질문·지시 대상 불명확 예를 각각 포함한다. 이들은 언어 시험의 정답 자료가 아니라 **게임이 동의를 잘못 해석하지 않는지** 확인하는 제품 사례다. 도움·보기 사용 여부로 물건·관계 결과가 줄지 않는다.

## 4 명령과 중단의 인계표

기존 명령 이름은 [core.mjs](../../experiences/synk-town/core.mjs)에서 확인한 개발판 것이다. `HOME_*`, `GRANT_STARTER`, `USE_RESULT`는 이번 설계용 제안 이름이며 현재 API에 존재한다고 표시하지 않는다. 새 명령이 필요하면 Town과 계정 호스트에서 검증하며 Atlas의 학습 API로 우회하지 않는다.

모든 변경은 **현재 본인·권한·contentVersion·예상 revision·대상 개체/자리**를 검증한 뒤 하나의 원자적 결과로 확정한다. 같은 commandId/내용 재전송은 최초 응답을 반환하고, 같은 ID 다른 내용은 거절한다. 오래된 revision에는 현재 배치와 비교를 보여 주고 새 확인을 받는다. 실패·재시도를 처음 지급의 새 이유로 쓰지 않는다.

| 단계 | 확인할 대상과 명령 | 확정 결과 | 직전·직후 중단과 취소 |
|---|---|---|---|
| 집 만들기 | 계정의 첫 집 부재를 서버가 확인, `HOME_INIT` | home-starter:v1 한 벌, 기본 창가 위치 | 응답 단절은 같은 요청 조회. 로딩 실패를 새 집 부재로 처리하지 않음 |
| 집 자리 | `HOME_PREVIEW`는 초안, `HOME_PLACE`는 방석 개체와 슬롯 | 같은 방석 위치·homeRevision만 변경 | 이전 위치 복구 가능. 제작·학습·첫 보상 없음 |
| 출입 | `HOME_EXIT/HOME_ENTER`, 문과 목적 공간 | 위치·재개점, 세계 소유 변경 없음 | 길 도중 종료는 안전한 길 노드 또는 집 문 앞에서 재개. 목적지 취소로 자동 귀가하지 않음 |
| 안/밖 | `CHOOSE`는 갈래 초안만, `NEXT`는 다음 단계 | 갈래·지원 묶음. 재료는 아직 없음 | `CANCEL`로 기존 배치. 이미 받은 재료는 회수하지 않음 |
| 첫 재료 | FT10.02A 명시 만들기 선택의 `GRANT_STARTER` | 기존 최초 지급 이력에 목재2·천1, 한 번 | 지급 뒤 중단이면 그대로 보관. 안 갈래로 바꿔도 새 지급·현금 교환 없음 |
| 제작 | `COLOR`는 초안. `CRAFT`는 현재 색과 잔량 확인 | 목재2·천1 소비, 개인 차양1 생성, 공방 주인의 실제 공동 제작 인지 | 직전 취소는 소비0. 직후에는 차양 보관 상태로 재개하며 재소비 없음 |
| 배치 | `PREVIEW_SLOT`→`PLACE`, 의자/차양 현재 권리와 길 확인 | placementRevision, 현재 가구 위치, NPC 이용 계획 후보 | 직전 취소는 현재 배치 유지. 직후 복귀는 새 배치. 사용되지 않은 상태를 손님 이용 완료로 만들지 않음 |
| 실제 이용 | NPC가 확보한 경로로 이동·착석·서빙하는 권한 있는 계획의 `USE_RESULT` | 실제 같은 자리의 이용·서빙 사건, FT10 해당 결과 완료 | 경로 막힘/자리 회수면 이용 완료0·대안 재계획. 종료 뒤 같은 결과를 다시 보더라도 사건 한 번 |
| 이용 표현 | 기존 `ACK` 계열, reactionId·장소revision·적용 단계 확인 | 관람 전달만 확정 | 화면 숨김·중단·옛 배치 반응 ACK는 거절. 완료/지급을 되돌리지 않음 |
| 안내판 | `SIGN_START/NEXT/PICTURE/PREVIEW/PLACE` | 같은 주민 비품의 그림·위치·현재 자리 참조 | `SIGN_CANCEL`은 종전 표지. 확정 후 자리 변경이면 같은 표지를 새 자리에 재연결 |
| 안내 이용 | 손님이 실제 그림을 보고 현재 자리를 찾은 `USE_RESULT` | `FT51.completed` 한 번, 그림을 본 손님 인지 | 자리 없음이면 대체 안내, 이미 폐기된 그림의 현재 이용 주장0 |
| 회수·재배치 | `REMOVE/REARRANGE/SIGN_REMOVE` | 소유 차양은 개인 보관, 주민 비품은 원래 관리 범위. 과거 사건은 유지 | 진행 중 임시 예약 해제·의존 경로 재계획. 첫 보상·첫 재료·전시물 복제 없음 |
| 휴식·종료 | `SIT/LEAVE/VISIT` 의미 재사용 | 마지막 확정 단계·미관람 결과·현재 지원 선택 유지 | 종료는 거절/실패가 아님. 돌아온 횟수로 새 이야기 자동 해금 없음 |

**현재 코드와 다른 두 지점:** 개발판 `CHOOSE`는 밖을 선택하는 순간 재료를 지급하며 `PLACE`는 자리 이용 사실까지 즉시 만든다. 첫 메인 구현에서는 위 표대로 지급은 FT10.02A의 명시 선택으로, 자율생활의 이용 완료는 권한 있는 NPC 실행 결과로 분리한다. 기존 코드 시험의 통과를 이 새 동작의 검증으로 세지 않는다. 단, 이용 **사실**과 화면의 **관람 ACK**는 계속 별개다. 카메라를 다른 데로 돌렸다는 이유로 실제 끝난 NPC 행동을 취소하거나 사용자에게 관람을 강제하지 않는다.

## 5 권한의 제공처와 돌아갈 화면

Town 입구는 **기존 SYNK ID 공통 계정 서비스의 WORLD 이용권**을 단일 권한 제공처로 사용한다. 내부 TOPIK 1급+는 기존 Core·Strata의 확인된 수행 근거로 산출된 통과 기록을 이용권 제공처가 검증해 읽는다. Town 자체 채점기나 별도 로그인을 만들지 않는다. 현재 학생용 [Town 브리지](../../experiences/teacher-world/town-bridge.mjs)는 반 소속·공유 동의를 함께 요구하므로 일반 개인 생활 호스트와 분리하는 구현이 필요하다.

인계할 응답의 의미 필드는 `synkUserId, accessRevision, verifiedAt, learningPass, freeContentIds, activeLifePass, ownedCosmetics, settlementClaims, offlineValidUntil`이다. `learningPass`는 통과·미통과·확인 불가를 구분하며 값이 없다고 미통과로 판정하지 않는다. 이는 현재 응답 스키마의 존재 주장이 아니라 **WORLD 계정 어댑터가 제공해야 할 설계 계약**이다. 실제 전송명은 계정 서비스 정본에 함께 등록한다. 새 권한을 토큰이나 무료/정액 화면의 로컬 플래그로 만들어내지 않는다.

| 상태 | 보여 줄 문구와 이동 | 허용 / 보존 | 차단 |
|---|---|---|---|
| 확인 중 | “생활 기록을 확인하고 있어요.” / WORLD로 | 기존 캐시를 새 기록으로 덮지 않음 | 새 생활·관계·재화 명령 |
| 로그인 필요 | “같은 SYNK ID로 이어 갈 수 있어요.” / 기존 계정 입구 | 본인 재로그인 전 개인 집 노출 없음 | 익명 자료를 계정에 자동 귀속 |
| 확인된 내부 미통과 | “기초 학습을 마친 뒤 마을에 들어갈 수 있어요.” / 기존 메인 학습 | 서버에 있는 과거 기록 보존. 구매는 통과 대체 불가 | 마을 직접 링크·NPC 관계 진행 |
| 통과 기록 확인 불가 | “학습 기록을 확인하지 못했어요.” / 다시 확인·WORLD로 | 마지막 확인 기록 보존. 이미 유효한 오프라인 권한만 그 범위대로 사용 | 미통과 판정·기록 초기화·자기 신고 통과 |
| 통과·무료 가능 | “첫 생활을 시작해요.” / 내 집 | H00·첫4경로·각 첫후속과 이미 허용된 기본 생활 | 정액 전용 새 사건·새 공급 |
| 통과·생활권 유효 | 내 집 또는 선택한 실제 재개점 | 제공 목록 안의 새 이야기·반복 생활. 학급 소속 불필요 | 아직 미제작인 콘텐츠를 이용권만으로 노출 |
| 생활권 만료 | “만든 것과 기록은 그대로 있어요.” / 내 집·기록·결과 받기 | 무료 생활, 소유 꾸미기, 만료 전 서버 확정 작업의 수령/정리. 기존 경제 계약 재사용 | 새 유료 작업·공급·관계 회차 시작 |
| 연결 확인 실패 | “연결을 확인하지 못했어요.” / 다시 확인·허용된 오프라인 생활 | 유효한 오프라인 범위와 마지막 확정 기록 | 빈 집 초기화·임의 새 권한·추정 정산 |
| 교사 공유 철회 | 개인 생활로 복귀, 공유 설정에서 상태 표시 | 개인 집·소유·관계 보존 | 철회 뒤 교사에게 학습/생활 자료 새 전송 |
| 계정 변경·세션 종료 | 기존 화면 닫고 계정 입구 | 이전 계정 대기 명령은 그 계정에만 묶어 보존 | 새 계정으로 옛 요청 전송·옛 집 잔상·응답 적용 |

오프라인 기간은 [경제 정본의 범위](싱크타운_생활경제와_상품_설계.md#expiry)를 그대로 쓴다. `offlineValidUntil`은 이용권 종료보다 늦게 새 유료 작업을 허용할 수 없다. 서버에 확정된 준비의 수령 권리와 아직 확정되지 않은 잠정 명령은 구별한다. 입구·복원·명령·직접 링크 모두 같은 판정을 사용한다.

## 6 기존 생활 기록의 이관 범위

첫 연결은 기존 FT10/51 기록을 지우지 않는다. 원본의 `scope/schema/revision/events/commands/materialsGranted/inventory/goals/sign`을 보존하며, 새 집과 NPC 장면의 기본값만 추가한다. 기존 이벤트의 ID·인지 대상·사건 순번을 바꾸어 ‘더 좋은 이야기’로 복원하지 않는다.

| 기록 종류 | 처리 결정 | 사용자에게 보이는 결과 |
|---|---|---|
| preview-local 합성 개발 기록 | 운영 계정으로 반입하지 않음. 기존 개발판에 유지 | 계정의 새 집에는 시험 물건/통과/코인이 생기지 않음 |
| local-linked 기기 기록 | 확인된 주인·서버 이력이 없으면 자동 병합하지 않음. 원본 유지·내보내기 가능 | “이 기기의 체험 기록”으로 구분. 계정 저장 완료로 표시하지 않음 |
| account-linked의 서버 확인 기록 | 기존 learnerId와 synkUserId 연결을 서버가 검증하고, 출처 지문·원본 revision·이관판으로 멱등 이관 | 차양·배치·안내판·첫 지급 이력 유지. 새 집 H00만 한 번 준비 |
| 같은 계정의 정식 Town 기록이 이미 있음 | 새 계정 기록을 기준으로 기존본과 차이를 제시. 덮어쓰기·재고 합산 자동 실행 없음 | 각각의 기록을 보존하고 선택 복구 작업으로 분리 |
| 잘못된 scope·깨진 이력·지원하지 않는 새 판 | 이관 중지, 원본 격리 보존, 복구 안내 | “기록을 확인해야 해요.” 빈 집·초기화 완료로 속이지 않음 |

기존 개발판의 완료 사실은 해당 판의 완료 이력으로 보존한다. 새 NPC 자율생활이 실제 실행된 것처럼 새 `USE_RESULT`를 만들어 옛 이벤트를 보강하지 않는다. 이후의 새로운 이용은 새 계약으로 한 번 기록한다. 이관 도중 중단하면 준비한 원본 지문으로 다시 확인하고, 검증·커밋·이관 완료 표식을 한 트랜잭션으로 묶어 반쪽 상태를 노출하지 않는다.

## 7 제작자가 먼저 따라갈 정적 리허설

아래는 문서의 입력·결과를 대조한 사례이며 실행 테스트 결과가 아니다. 구현 후 같은 입력으로 실제 화면·저장·복귀 증거를 남긴다.

| 사례 | 입력과 중간 상태 | 설계상 기대 결과 |
|---|---|---|
| FP01 빠른 외출 | H00 설명을 열지 않고 문→안 자리→배치→주민 이용 | 재료0소비, 이동한 의자 이용, 귀가 가능. 방석 꾸미기·학습 과제 선행 없음 |
| FP02 밖을 보다가 취소 | 밖 미리보기→다시 고르기→안 | 재료 지급0. 기존 코드와 수정 지점이 명확함 |
| FP03 받은 뒤 중단 | 밖 만들기 선택→재료2+1 지급→종료→다시 | 최초 지급 이력 유지, 잔량2+1에서 시작. 접속당 지급 없음 |
| FP04 제작 직후 연결 단절 | 초록 차양 제작 확정→응답 단절→같은 commandId 조회 | 차양1·재료0. 다시 만들거나 새 색으로 조용히 바꾸지 않음 |
| FP05 쓰기 전에 치움 | 배치→NPC 이동 중 회수→관람 ACK 도착 | 옛 이용 완료/ACK 거절. 차양 보관, 현재 경로로 재계획. 이미 끝난 과거 사건은 보존 |
| FP06 보고 있지 않음 | 배치→NPC가 실제 이용→카메라는 집 쪽→종료 | 이용 사실/완료 유지, 관람은 미전달. 재방문에서 현재 상태의 결과를 보고 새 보상 없음 |
| FP07 안내판 수정 | FT51 의자그림 배치→자리 이동→차그림 미리보기 취소 | 표지는 새 자리로 연결되고 확정 그림은 의자 유지. 손님 기억은 실제 본 그림만 |
| FP08 초급 생활 숙련자 | 짧은말·시범 도움 유지→배치와 안내판 방향 직접 결정 | 결정권 동일, NPC는 고정/시범 역할만. 한국어 자동 승급·역할 박탈 없음 |
| FP09 반 없는 계정 | 확인된 통과+무료권한+학급없음→집 복원 | 개인 생활 가능. 교실 브리지 조건을 가져오면 실패하는 인수 사례 |
| FP10 만료와 계정 전환 | 유료 승인 작업 중 만료→수령권 확인→다른 계정 로그인 | 승인 결과는 원계정에만 남고 새 계정 화면에 옛 집/수령을 섞지 않음 |
| FP11 지원 변경 | 제작 초안에서 쉬운말→확장 설명→다시 쉬운말 | 초안·색·자원 불변. 설명을 다시 들었다고 수락/언어 성공 없음 |
| FP12 기존 기록 복원 | 계정 확인된 schema1 FT51완료 이관→재시도 | 기존 사건·재료·표지 그대로, home-starter1벌, 이관1회. 옛 사건에 새 NPC 기여를 덧붙이지 않음 |

첫 구현에 넘길 공간·소유·원고·세 입력·취소·권한 상태·이관 범위는 이 문서로 정한다. 남는 제작 작업은 실제 자산과 장면 데이터, 계정 어댑터·새 명령·저장 이관 구현, 모바일 조작·성능·플레이 관찰이다. 정확한 카메라 거리·3D 실행 기술·그래픽 자산의 최종 얼굴·음성은 실행 비교와 별도 제작으로 확정하며, 이 설계안의 품질을 실기기 검증으로 포장하지 않는다.
