# 학생 관리 — 지점 · 재학생 · 학생 한 명의 길 (설계, 2026-11-27)

> 이 표는 11월 27일의 계획이다. 진행과 남은 일은 [트랙](../../_ops/트랙.md)이 잇는다.

## 1. 목적

유호님 11-27: 「지금 사업계획서에 관리를 좀 중시했으니까 학생 출결 (lab,path) 등등 사업계획서 기반해서 연동한다음에 타국에있는 지점에서도 국내에있어도 이 앱으로 전체적인 학원 관리와 한국 현재 유학생 관리, 이런거 전부 할수있도록 만들어줘. … 관리에 충실히 신경쓴다고했는데 그게 좀 부족해.」

계획서(11-26 개선본)에서 이 기능이 사실로 만들 문장은 다섯이다.

| 계획서 자리 | 문장 | 이 설계에서 맡는 곳 |
|---|---|---|
| 표 1 「출결·체류 관리」 | 운영 앱: 출결 관리, TOPIK 만료일 자동 추적 → 만료 전 4급 갱신까지 관리 | 반 출결 · TOPIK은 [출결 · TOPIK 설계](../학원운영_출결_TOPIK_20261127/설계.md)가 맡고, 이 설계는 지점으로 묶어 한 화면에서 본다 |
| 그림 1 ③ 정착·관리 | 운영 앱 + 정착 멘토: TOPIK 만료일 자동 추적 · 4급 갱신, 주거 · 커뮤니티 안착 | 재학생 기록(대학, 비자, 체류 만료, 멘토, 대학 출석률)과 만료 알림 |
| 2-2 | 울란바토르 직영 어학원(평일 TOPIK, 주말 K-드라마 회화, 영어) · 입국 후 정착 멘토 | 지점 「울란바토르 직영」과 「한국 · 정착」 |
| 그림 7 · 표 4 | 울란바토르 → 하노이 → 타슈켄트 | 지점 표에 나라 · 시간대를 두어 새 지점은 행 하나로 연다 |
| 표 5 「해외 지점 적자 · 관리 공백」 | 대표 이동 시 현지 원장 책임제 · 운영 앱 일일 점검으로 공백을 막는다 | 지점별 오늘 출결과 알림을 한 화면에서 매일 본다 |

실학생은 아직 0명이다. 이번 판의 목표는 실제 반과 계정 구조로 동작하는 화면을 운영에 올리고, 지어낸 이름의 시험 반으로 확인하는 것이다.

## 2. 쓰는 사람과 흐름

| 사람 | 하는 일 |
|---|---|
| 울란바토르 교사 · 원장 | 지점 칩에서 「울란바토르」를 고르고, 오늘 반마다 출결을 찍는다. 연속 결석 학생을 본다. |
| 한국 담당 · 정착 멘토 | 「한국 · 정착」 지점의 기수 반에서 재학생의 대학 · 비자 · 체류 만료일 · 대학 출석률을 넣고, 만료 알림을 처리한다. |
| 대표(관리자) | 「전체 지점」에서 지점별 오늘 출결, 알림 수, 학생 한 명의 길 단계별 수를 본다. |

화면은 워크스페이스 왼쪽 메뉴 「회사」 묶음의 **학생 관리** 한 장이다(시작 세션의 붙임 시안 짜임을 따른다).

1. **머리.** 제목, 지점 칩(전체 지점 · 열린 지점들 · 「지점 미정」은 그런 반이 있을 때만), 날짜(기본은 고른 지점 시간대의 오늘, 전체는 서울).
2. **요약(12절부터 문장 한 줄).** 오늘 출석(출석 + 지각 / 기록한 학생), 연속 결석(3회 이상), 체류 만료 알림, TOPIK 만료 알림. 0이면 0으로 보인다.
3. **출결.** 반마다 한 줄(반 이름, 지점, 출석 막대, 결석 · 지각 수). 출결을 찍는 곳은 출결 · TOPIK 세션이 만드는 LAB 반 화면의 「오늘 출결」 띠 하나다. 이 화면은 줄마다 「반에서 출결 찍기」로 그 반을 연다(11-27 그 세션과 나눔: 출결 · TOPIK 표 · 저장 경로 · 반 출결 띠는 그쪽).
4. **만료 알림 · 재학생.** 알림이 있는 학생을 급한 순서로 한 줄씩: 이름, 반 · 지점, 칩(체류 만료 D-n, TOPIK n급 만료 D-n, 출석 n%, 멘토). 줄을 누르면 학생 카드.
5. **학생 카드(12절부터 목록 안에 펼침).** 학생 한 명의 길(어학원 재원 → 유학 수속 → 입국 · 정착 → 한국 재학, 지금 단계 표시), 재학 기록 편집(단계, 대학, 과정, 비자 종류, 체류 만료일, 입국일, 멘토, 대학 출석률과 기준일, 메모 200자), TOPIK 대표 성적과 만료일 보기(넣기는 반 화면의 TOPIK 칸).
6. **학생 한 명의 길.** 단계별 학생 수 네 줄. 줄을 누르면 그 단계 학생만 아래 목록에 남긴다.

알림 기준(서울 날짜 기준, 응답에 기준일을 함께 준다):

- **체류 만료:** 120일 안이면 「연장 신청 열림」, 30일 안이면 「급함」, 지났으면 「만료」. 체류기간 연장은 만료 4개월 전부터 만료일까지 신청할 수 있다는 대학 국제처 안내를 따랐다(전남대 · 삼육대 안내).
- **TOPIK 만료:** 출결 · TOPIK 설계와 같다(90일 · 30일 · 만료, 대표 성적 기준).
- **출석 낮음:** 최근 수업 30회 가운데 기록이 5회 이상이고 출석률(출석 + 지각) / (출석 + 지각 + 결석)이 70% 아래, 또는 멘토가 넣은 대학 출석률이 70% 아래. 70%는 유학생 체류 연장 심사에서 흔히 말하는 기준이라 기본값으로 두고 화면에 기준을 적는다(법무부 원문은 확인하지 못했다).
- **연속 결석:** 출결 · TOPIK 설계와 같다(3회).

외부 알림(메신저 · 문자 · 보호자 연락)은 이번 판에 넣지 않는다.

## 3. 데이터 (중앙 Supabase `engine`, 마이그레이션 c19)

출결 · TOPIK의 c18(SYNK-talk `0f61524`, 배포 전) 위에 쌓는다. 회사 서버 SQLite에는 학생 자료를 두지 않는다.

```sql
create table engine.synk_branches (
  branch_id uuid primary key default gen_random_uuid(),
  branch_key text not null unique check (branch_key ~ '^[a-z][a-z0-9-]{1,39}$'),
  display_name text not null check (char_length(display_name) between 1 and 40),
  country_code text not null check (country_code ~ '^[A-Z]{2}$'),
  time_zone text not null check (char_length(time_zone) between 3 and 60),
  kind text not null check (kind in ('academy','settlement')),
  opens_on date, active boolean not null default false, sort_order smallint not null default 0,
  created_at timestamptz not null default now()
);
-- 씨앗 넷: ulaanbaatar(MN · Asia/Ulaanbaatar · academy · 켜짐), korea(KR · Asia/Seoul · settlement · 켜짐),
--         hanoi(VN · Asia/Ho_Chi_Minh · academy · 꺼짐 · 2028-09-01), tashkent(UZ · Asia/Tashkent · academy · 꺼짐 · 2029-09-01)
create table engine.synk_class_branches (
  class_id uuid primary key references engine.classes(class_id),
  branch_id uuid not null references engine.synk_branches(branch_id),
  set_by uuid not null references engine.staff(staff_id),
  revision integer not null default 1, updated_at timestamptz not null
);
create table engine.synk_learner_stay (
  stay_id uuid primary key default gen_random_uuid(),
  learner_id uuid not null unique references engine.learners(learner_id),
  synk_user_id uuid not null, sharing_revision integer not null,
  stage text not null check (stage in ('academy','path','arrived','enrolled')),
  university text not null default '' check (char_length(university) <= 80),
  program text not null default '' check (char_length(program) <= 80),
  visa_kind text check (visa_kind in ('D-2','D-2-1','D-4','D-4-1')),
  stay_expires_on date, entered_on date,
  mentor_staff_id uuid references engine.staff(staff_id),
  university_attendance smallint check (university_attendance between 0 and 100),
  university_attendance_on date,
  note text not null default '' check (char_length(note) <= 200),
  recorded_by uuid not null references engine.staff(staff_id),
  revision integer not null default 1, idempotency_key text not null, fingerprint text not null,
  created_at timestamptz not null, updated_at timestamptz not null
);
```

- 세 표 모두 RLS만 켜고 정책과 클라이언트 권한이 없다. 함수(`synk-classroom`)만 읽고 쓴다.
- 지점은 **반의 이름표**다. 접근을 정하지 않는다. 지금처럼 `staff_classes`가 정한다.
- 재학 기록은 TOPIK과 같은 동의 범위다. 행마다 계정과 그때의 공유 판을 적고, 읽을 때는 지금 계정 · 공유 판이 같고 공유를 켠 뒤에 쓴 행만 보인다. 범위가 바뀐 옛 행은 그 학생에게 다음에 쓸 때 지운다.
- 삭제: 계정이 `deleted`가 되면 c18이 넓힌 `synk_teaching_account_deleted` 트리거 함수가 재학 기록도 지운다(함수 본문을 c19에서 `create or replace`로 한 줄 넓힌다). cascade는 두지 않는다.
- 상한: 한 학생 재학 기록 1행. 지점 표는 운영 SQL로만 늘린다(이번 판에 지점 만들기 화면은 없다).

## 4. 권한과 개인정보

- **범위:** 교사 · 원장은 자기에게 배정된 반(`staff_classes`)만 본다. 그래서 「지점 직원은 자기 지점만」은 그 지점 반에만 배정하는 것으로, 「관리자는 전체」는 모든 반에 배정하는 것으로 된다(출결 · TOPIK 설계 9절의 원장 배정과 같은 규칙, 새 역할 값 없음).
- **지점 정하기:** 그 반에 배정된 교사 · 원장이 반의 지점을 고른다. 이름표라 권한을 넓히지 않는다. 꺼진 지점은 고를 수 없다.
- **동의:** 유호님 11-27 「공유 켠 학생만」(결정 11-27)과 같다. 계정을 잇고 반 공유를 켠 학생만 재학 기록 · 출결 · TOPIK을 쓰고 본다. 공유를 켜지 않은 학생은 명단에 「공유 꺼짐 · 기록 안 함」으로만 보인다.
- **멘토:** 그 학생의 반에 배정된 직원 가운데서만 고른다.
- **처리방침:** 「SYNK 계정과 학습 기록」 절에 출결 · TOPIK 문구와 함께 「학원 지점, 재학 대학 · 과정, 비자 종류, 체류 만료일, 입국일, 담당 멘토, 대학이 알려 준 출석률」을 더해 운영 반영 **전에** 공개한다. 스위치는 출결 · TOPIK과 같은 `SYNK_CLASS_RECORDS_ENABLED` 하나다.
- 저장소에는 실학생 자료를 적지 않는다. 시험 반과 화면 확인은 지어낸 이름만 쓴다.

## 5. 서버 경로

중앙 `synk-classroom`(교사 · 원장, 쓰기는 POST만):

| 경로 | 동작 |
|---|---|
| `/api/teacher/stay` | `action` `save`(판 대조, 멱등 키) · `delete` |
| `/api/teacher/class-branch` | `action` `set`(`branchId`, 판 대조) |
| `/api/teacher/overview`(기존 GET) | 200 응답에 `branches`(켜진 지점과 반이 매달린 지점), 반마다 `branch`, 학생 줄마다 `stay` · `attendanceRate`, 맨 위 `students`(기준일, 단계별 수, 알림 셋과 수)를 붙인다 |

모듈은 `lib/synk-classroom-students.js` 하나로 둔다(동봉 `class-students.mjs`). `index.ts`가 `withStudentRecords(withClassRecords(운영 서비스))`로 감싼다. 출결 · TOPIK 모듈과 운영 묶음은 고치지 않는다. 붙이기가 실패하면 감싸기 전 응답을 그대로 준다.

회사 서버(`teaching-service.mjs`)의 `routes`에 반 범위 둘(`stay`, `classBranch`)을 더한다(`attendance` · `topik`은 출결 · TOPIK 세션 커밋 `8602c50e55`가 더한다). 브라우저 교사 다리(`experiences/synk-account/src/messenger-teacher.mjs` · `classroom-client.mjs`)의 허용 목록에도 둘을 더해 `teaching-host.js`를 다시 묶는다.

**화면 겉:** 유호님은 지금 워크스페이스 화면을 「프론트가 최악」이라 하시고 시안 셋(세션 「워크스페이스 출결·TOPIK 화면 시안 셋」) 가운데 고르신 뒤 바꾸라고 하셨다(출결 · TOPIK 세션 11-27 전언). 학생 관리 화면도 고르신 시안의 겉을 따른다. 고르시기 전에는 기능만 지금 겉(시안 3 노란 결)으로 짓는다.

**중앙 배포:** 출결 · TOPIK c18과 이 c19를 한 번에 묶어 올린다. 순서는 유호님 답 뒤에 그 세션과 맞춘다. 회사 메뉴 「학생 관리」는 `teaching` 또는 `path` 기능이 있는 직원에게 보이고, `/api/teaching/` 관문도 둘 중 하나면 지나게 한다(실제 자료 범위는 중앙의 반 배정이 정한다).

## 7. 시험 계획

- 중앙(PGlite 실제 마이그레이션 c1…c19): 지점 정하기(배정 안 된 교사 거절, 꺼진 지점 거절, 판 충돌 409), 재학 기록(공유 끈 학생 거절, 반 밖 멘토 거절, 날짜 범위, 판 충돌, 멱등 재전송 · 같은 키 다른 내용 409, 지우기), 동의 범위(공유 끄면 안 보임, 다시 켜면 옛 행 안 보임, 다음 쓰기에서 옛 행 지움), 계정 삭제 트리거, 개요 붙이기(배정된 반만, 학생 계정으로 부른 응답에는 안 붙음, 스위치 꺼짐 · 표 없음이면 감싸기 전과 같음), 출석률 · 알림 경계(120 · 30 · 0일, 70%, 기록 5회 미만).
- 회사 서버: `teaching-service.test.mjs`에 새 경로 넷의 반 범위와 교사 확인, `/api/teaching/` 관문의 `path` 허용, 메뉴 노출.
- 화면: 가짜 교사 다리로 로그인 전 · 스위치 꺼짐 · 자료 있음 세 상태, 지점 칩 거르기, 「반에서 출결 찍기」가 그 반을 엶, 학생 카드 저장 → 다시 불러오기 → 그대로, 충돌 안내, 390 · 1440 캡처와 콘솔 오류 0.

## 8. 참고한 것

## 10. Fable 설계 검토 반영 (11-27)

판정은 「고쳐서 짓기」였다. 위 절과 다르면 이 절이 맞다.

- **공유를 끄면 바로 지운다(P1).** 공유를 끄거나 판 · 계정이 바뀌거나, 반에서 빠지거나 반을 옮기면 DB 트리거 둘이 재학 기록을 그 자리에서 지운다. 다음 쓰기를 기다리지 않는다.
- **반을 옮기면 기록이 끊긴다(P1).** 공유가 반 단위라서 지금은 옮긴 반에서 공유를 다시 켠 뒤 다시 넣는다고 화면에 적었다. 옮길 때 기록을 이어받는 동의를 둘지는 유호님께 여쭐 일로 남긴다(9절 남은 조각).
- **날짜 고르기를 뺐다(P1).** 회사 중계가 개요에 날짜를 받지 않는다. 대신 서버가 반마다 지점 시간대의 오늘(`branchToday`)을 센다. 요약의 기준일은 서울이라고 화면에 적는다.
- **비자 세부 종류(P2):** D-2-1~D-2-8, D-4-1 · D-4-7.
- **대학 출석률 알림은 D-4만(P2).** 학위 과정(D-2)의 연장 심사는 성적이 기준이다. 반 출석률 알림은 모든 학생에게 건다.
- **개요 시간 예산(P2):** 반 묶음을 한 번에 읽고, 문장마다 2초 · 전체 3초를 넘기면 붙이지 않고 원래 응답을 준다.
- **c18 체크섬 확인(P2):** 계정 삭제 함수를 다시 쓰기 전에 출결 · TOPIK 판의 체크섬을 본다. 적용 후 확인에 다섯 표 지우기와 트리거 둘을 넣었다. 재학 기록의 계정 칸은 계정 표를 참조하고 판 번호는 0보다 크다.
- **PATH 관문은 열지 않는다(P3).** `/api/teaching/` 관문과 메뉴는 지금처럼 LAB 수업 기능(`teaching`)에만 둔다. 한국 담당 · 정착 멘토는 회사에서 LAB 역할을, 중앙에서 그 기수 반의 교사 배정을 받아 쓴다. 4 · 5절의 `path` 관문 문장은 이 줄로 바뀐다.
- **「배정된 반 n개 기준」:** 전체 지점 화면에 배정된 반 수를 적어 대표가 빠진 반을 놓치지 않게 했다.

## 11. 구현 중 더한 것 (11-27)

- **계정에서 학습 동의를 끄면 바로 지운다.** GPT 1회차 GA1: 반 공유 행은 다음에 반을 열 때 바뀌므로, `synk_accounts`의 학습 동의 · 학습 판 · 상태가 바뀌면 그 계정의 재학 기록을 트리거로 바로 지운다.
- **고치기 · 지우기는 기록 id와 판을 함께 본다.** 지우고 다시 만든 기록이 1판으로 돌아가도 옛 화면이 덮지 못한다.
- **화면은 틀과 그리기로 나눴다.** 유호님 11-27(출결 · TOPIK 세션 전언): 시안 셋을 먼저 보시고 마음에 드는 것이 없으면 노란 화면으로 간다. 그래서 `students.js`(자료 · 동작 · 보기 자료)와 `students-view.js`(겉)를 나눠, 고르신 시안은 그리기 파일과 `students.css`만 바꿔 입힌다.
- **처리방침에 더할 항목:** 학원 지점, 재학 대학 · 과정, 비자 종류, 체류 만료일, 입국일, 담당 멘토, 대학이 알려 준 출석률, 메모(200자). 출결 · TOPIK 항목과 함께 공개한 뒤 `SYNK_CLASS_RECORDS_ENABLED`를 켠다.
- **지운 기록은 늦게 온 요청으로 되살아나지 않는다.** GPT 3회차 GA3: 첫 저장 요청 키의 해시를 원장 표(`synk_learner_stay_requests`, 학생 자료 없음 · 30일 뒤 지움)에 남겨, 지운 뒤 같은 키로 다시 온 요청은 `REQUEST_ALREADY_HANDLED`로 거절한다.
- **계정 삭제 함수는 고치지 않는다.** 재학 기록은 계정 상태가 active가 아니게 되면 계정 트리거가 지운다. 그래서 c19는 출결 · TOPIK 판(c18)의 체크섬이나 함수 본문에 묶이지 않는다.
- **TOPIK 알림과 연속 결석은 아래 층과 같은 규칙이다.** Fable 설계 검토(11-27): TOPIK은 유효한 4급 이상 가운데 가장 늦게 만료되는 성적, 없으면 대표 성적이다. 연속 결석은 반의 최근 수업 60회에서 센다. 시험이 아래 층(`learnerTopik` · `absentStreak`)과 같은 답인지 대조한다.
- **적용 뒤 확인은 정의 글자 그대로 맞춘다.** 범위 트리거 셋은 `pg_get_triggerdef` 전체, 그 함수 셋은 공백을 줄인 본문의 해시로 조각 확인과 전체 사후 검사가 같은 값을 쓴다.
- **검수의 한계 잣대(Fable 설계 검토 11-27).** 계속 P1로 받는 것은 다섯 가지다: 동의가 끝난 학생의 기록이 읽히거나 저장됨, 배정이 풀린 교사에게 읽힘, 지운 기록이 30일 안의 재전송으로 되살아남, 옛 판이 최신 기록을 덮음, 권한이 열리거나 트리거 · 함수가 조각과 달라도 검사가 통과함. 그 밖의 드문 경우는 켠 뒤 `student records read skipped` 횟수, 409 코드별 횟수, 주 1회 알림 수 대조로 잰다.
- **못 붙인 개요는 따로 알린다.** 스위치가 켜졌는데 시간 예산 · 실패로 학생 기록을 붙이지 못하면 중앙이 `studentsUnavailable`을 붙이고, 화면은 「아직 열리지 않았어요」가 아니라 「불러오지 못했어요」와 다시 불러오기를 보인다. 앞서 읽은 학생 자료는 덮지 않는다.
- **PC 앱.** 교사 다리 허용 목록에 `stay` · `classBranch`를 더했다(다음 PC 앱 판에 실린다). 옛 판 PC 앱에서는 저장 단추를 막고 「업데이트하거나 브라우저에서 저장해 주세요」를 보인다.
- **지점은 바꿀 수 있다.** 지점이 정해진 반에도 고르기가 남고, 바꿀 때 한 번 묻는다. 닫힌 지점에 매달린 반은 그 지점을 「닫힌 지점」으로 보인다.
- **회사 로그인이 풀리면 바로 지운다.** 로그아웃 · 세션 만료로 로그인 화면이 되면 열린 학생 카드와 학생 자료를 지운다.

## 12. 시안 3 「한 장」 겉 (11-27)

유호님이 시안 3을 고르셨다(「오케이 시안 3으로 가자」). 학생 관리는 `docs/디자인/워크스페이스_출결TOPIK_20261127/3-한장.html`의 `#students`를 따른다. 색 · 글자 · 모양 값은 반 출결 · TOPIK 띠(`workspace-overview.css`의 `--att-*`)와 같다.

- **왼쪽.** 지점 젤리 알약, 큰 날짜, 문장 요약(찍은 반의 출석, 챙길 학생 수, 가장 급한 한 명), 오늘 반 목록이다. 요약 넷 상자는 없앴다. 「반에서 출결 찍기」 먹 단추는 아직 안 찍은 첫 반에만 두고, 나머지 반은 옅은 단추나 결석 · 지각 수로 둔다.
- **오른쪽 「챙길 차례」.** 알림을 종류마다 한 줄로 푼다. 연속 결석, 낮은 출석, 이미 지난 만료는 「지금」에 두고, 체류와 TOPIK은 끝나는 날의 달별로 둔다. 단계 젤리 알약이 목록을 거른다. 알림이 없는 학생은 「알림 없는 학생 보기」로 펼친다. 공유를 끈 학생은 이름만 한 줄로 적는다.
- **학생 카드는 연 줄 아래에 펼쳐진다.** 대화 상자를 없앴다. 저장으로 알림이 바뀌어 줄이 옮겨 가면 카드도 같은 학생의 새 줄을 따라간다. 다시 그려도 쓰던 칸, 초점, 커서 자리가 남는다.
- **쓰던 칸이 있으면 닫기 전에 묻는다.** 대화 상자가 아니므로 다른 줄, 지점, 단계를 누르거나 Esc · 닫기를 누를 수 있다. 저장하지 않은 칸이 있으면 한 번 묻고, 거절하면 그대로 둔다. 저장하는 동안에는 닫지 않는다.
- **초점.** 카드를 접으면 연 줄로 돌아간다. 문장 속 이름을 누르면 「챙길 차례」의 그 줄이 펼쳐지고 초점이 그리로 간다.
- **단계 이름.** 「PATH 수속」을 「유학 수속」으로 적는다(맹검 「설명 없는 PATH」 지적). 중앙 값(`path`)은 그대로다.
