# 펠트 부품 · 화면의 누르는 부품을 실제 펠트로

> **2026-10-05 유호님: 그림은 이미 구독 중인 ChatGPT로 만든다 — OpenAI API 유료 호출로 굽지 않는다.** ChatGPT로 로그인한 Codex CLI의 그림 만들기(`codex exec ... -i 참고.jpg`, 결과는 `~/.codex/generated_images/`)로 흰 바탕 한 판을 굽고 아래 「오리기」 도구로 오린다. 첫 사례: 한글 단계 자음 그림 연상(`experiences/hangul-stage/README.md` 「자음 그림 연상」). 아래의 `tools/펠트부품GPT굽기.js`(API)는 예전 굽기 기록이다.

> 2026-10-02 사용자 확정. 납작한 체크 원을 가리키며 “이런 단순한것들도 있잖아. 마감을 신경써줬으면 좋겠어. 실제 펠트 질감으로 GPT 2.5 IMAGE를 이용해서 뽑아서 사용해줘. 이거 말고도 모든 부분을 최대한 펠트질감 퀄리티 비싸게 보여야하잖아.” 적용한 레슨 화면을 보고 “확실히 전보다 훨씬 괜찮다. … 이 방식또한 저장해줘.” GPT와 Claude가 같은 원문을 쓴다.

## 언제 쓰나

학생·사용자가 보는 화면에서 **누르는 부품과 큰 색 면**에 쓴다. 대상은 앱 화면, 미니게임, 맞춤 도구, 웹 지면이다. SNS 판에 단추·배지가 필요할 때도 같은 부품을 쓴다.

| 쓰는 곳 | 펠트 부품 | 쓰지 않는 곳 |
|---|---|---|
| 단추(주 행동), 보기·선택 타일, 정답·번호 배지, 칩, 꼬리표, 게임 재료·아이템 아이콘 | 펠트 판·원·조각을 그대로 깐다 | 지문·설명처럼 오래 읽는 면(깨끗한 종이로 둔다) |
| 머리 면·아래에서 올라오는 판 같은 큰 색 면 | 펠트 결 조각을 곱게 깔고 같은 색을 옅게 덮는다 | 글자 바로 뒤를 거친 결로 채우기 |

앱(SYNK-talk)은 2026-08-20 확정한 다크 단일 테마(양모 밤, 코랄은 녹음 버튼에만)를 아직 지킨다. 이 부품을 앱에 넣을지, 넣는다면 그 원칙을 어떻게 바꿀지는 사용자가 정한다(→ [시안](../앱시안_20261002/README.md)).

## 원칙

1. **실제 펠트.** 부품은 GPT Image 2.5(`gpt-image-2.5-sunburst`)로 구운 니들 펠트 사진이다. 납작한 CSS 원·단추·두꺼운 윤곽을 그대로 내지 않는다. CSS로 펠트 질감·그림자를 흉내 내지 않는다.
2. **브랜드 펠트와 같은 재질.** 승인된 펠트(몽글 본체, 펠트 노트북)를 참조로 주고, 필요한 부품을 **한 판에 함께** 굽는다. 따로 구우면 실·빛·털 결이 부품마다 달라진다.
3. **글자는 굽지 않는다.** 숫자·문구는 화면 글자로 얹는다(20개국 번역, 접근성, 선명도).
4. **읽는 면은 종이, 펠트는 만지는 곳.** 한 화면의 주인공은 하나다. 마스코트는 흔들거나 떠다니지 않고 한 번 붙은 뒤 표정만 컷으로 바꾼다.
5. **마감을 먼저 본다.** 사용자에게 보이기 전에 아래 점검표를 휴대폰 크기 실제 화면에서 확인한다.

## 만드는 순서

1. **판 정하기:** [`tools/펠트부품GPT굽기.js`](../../../tools/펠트부품GPT굽기.js)의 `판들`에 새 판을 더한다(부품 목록·색·모양을 영어로, “글자 없음” 유지). 지금 판은 `UI`(배지·판·칩·꼬리표·결)와 `재료`(주문 폭주 재료 6개)다.
2. **굽기:** `node tools/펠트부품GPT굽기.js --판 <이름> --유료-api [--크기 1536|2048]`. 결과는 `raw/`(git 제외)와 [`생성기록.json`](생성기록.json)에 남는다. 한 판 참고값 약 60~80원. 여러 판을 한꺼번에 돌리거나 다시 굽기가 많아지면 먼저 사용자에게 수량과 예상 비용을 묻는다.
3. **오리기:** `python tools/펠트부품_오리기.py raw/<판>.png assets/<폴더> 이름1,이름2,… --시트 확인.jpg`(판 위 순서: 위→아래, 왼쪽→오른쪽). 몸통은 흰색과의 색 거리와 **털의 결**로 잡아 안쪽 구멍을 채운다(흰 털 부품도 안 깨진다). 그다음 펠트와 바닥 그림자 사이에 딸려 온 **흰 판을 걷고**, 가장자리의 «털 + 흰 바탕» 픽셀을 반투명 털로 되돌리고(색 있는 펠트는 색 성분, 검은 펠트는 밝기로 잰다), 바닥 그림자는 남은 펠트 모양으로 새로 만든다. 알파는 무손실 webp(손실 알파는 바깥에 흰 네모가 살아난다). 2026-10-02 이전 방식으로 오린 부품은 `--고치기 <입력> <출력>`으로 같은 처리를 한다(캔버스 크기 그대로, 1536 판 재료는 `--배율 0.75`).
4. **늘이기:** 단추·타일처럼 폭이 변하는 판은 가운데를 좌우 반전으로 이어 실제 비율(약 5.6:1, 칩 3:1)로 늘린 `*-long.webp`를 만든다. 9칸으로 잘라 반복하면 가운데에 이음매 줄이 보였다(2026-10-02). 도구: `python tools/펠트판_늘이기.py <입력> <출력> --비율 5.6 [--높이 132 --품질 88]`(반전 짝을 여러 번 끼워 8:1 같은 넓은 판도 만든다, 웹 사본은 색만 손실·알파 무손실). 큰 면의 결은 판 가운데를 잘라 `tex-*.webp`로 둔다.
   배너·커버처럼 넓은 면은 `tex-*`로 반복 무늬가 없는 넓은 판을 만든다: `python tools/펠트결_넓히기.py assets/배경/tex-cream.webp assets/배경/wide-cream.webp --크기 2560x1440 --배율 0.82`. 2×2 거울 타일(`seam-*`)을 큰 면에 깔면 결의 얼룩이 거울로 되풀이돼 마름모 무늬가 보였고, 조각을 90° 돌리면 사선 결이 엇갈려 짠 천처럼 보였다(2026-10-02 프로필 배너). CSS는 `url(wide-*.webp) center/max(2560px,100%) auto no-repeat`로 깔아 판 크기와 상관없이 결의 크기를 같게 둔다.
5. **확인 시트:** 어두운 바탕·종이색 바탕·브랜드 색 바탕에 얹은 시트(`--시트`)로 가장자리(흰 테·번짐·구멍·잘림)를 본다. 흰 판은 밝은 바탕에서는 그림자처럼 보여 놓치고 어두운 바탕에서만 드러난다. 한눈에 보기는 [`펠트부품_시트.jpg`](펠트부품_시트.jpg).

## 화면에 쓰는 법

```css
/* 주 행동 단추: 코랄 펠트 판 한 장. 판에 두께가 있으니 CSS 윤곽·아래 테두리는 넣지 않는다 */
.cta{border:0;min-height:60px;color:#fff;font-weight:800;text-shadow:0 1px 1px rgba(120,30,20,.35);
  background:url(assets/ui/slab-coral-long.webp) center/100% 100% no-repeat;filter:drop-shadow(0 8px 10px rgba(150,50,35,.22))}
.cta:active{transform:translateY(3px);filter:drop-shadow(0 3px 4px rgba(150,50,35,.22))}   /* 눌림 = 3px 내려앉기 */
/* 보기 타일: 크림 판, 고르면 연코랄 판 */
.opt{border:0;background:url(assets/ui/slab-cream-long.webp) center/100% 100% no-repeat}
.opt.right{background-image:url(assets/ui/slab-blush-long.webp)}
/* 번호·정답 배지: 빈 펠트 원 위에 화면 글자, 정답은 체크 배지 */
.num{width:34px;height:34px;display:grid;place-items:center;background:url(assets/ui/badge-cream.webp) center/contain no-repeat}
.check{width:40px;height:40px;background:url(assets/ui/badge-check.webp) center/contain no-repeat}
/* 큰 색 면: 결은 곱게, 같은 색을 옅게 덮어 글자 뒤를 차분하게 */
.head{background:linear-gradient(rgba(249,104,89,.38),rgba(249,104,89,.38)),url(assets/ui/tex-coral.webp) 0 0/190px 190px,#f96859}
```

- 그림 경로를 CSS 변수(`--x:url(...)`)에 넣어 다른 문서에서 `var()`로 쓰면 그 문서 기준으로 풀려 조용히 안 그려진다. 경로는 쓰는 문서 기준으로 적는다.
- 펠트 부품 위 글자는 대비를 확인한다(코랄 판 위 흰 글자는 굵게 + 옅은 그림자).
- 쿠션 판(`assets/cushion/`)은 가장자리가 부풀어 평평한 면이 판 상자보다 작다(위 빛받이 약 5%, 아래 옆면 약 19%). 글자는 그 면 가운데에 두고 양옆은 판 폭의 10%쯤 비운다. 번호처럼 따로 붙는 것은 면을 차지하지 않게 모서리에 단 크림 단추로 뺀다 — 2026-10-06 유호님이 말 랠리 시안을 보고 「둥글게 바뀌면서 면적이 작아졌잖아. 글씨 배치를 이 면적에 맞게」. 판은 쓰는 상자 비율로 늘여(`펠트판_늘이기.py`) 모서리·옆면이 찌그러지지 않게 한다.
- 실제 적용 예: [레슨 화면 시안](../앱시안_20261002/lesson/after/index.html), [주문 폭주 시안](../앱시안_20261002/order-rush-kit/).

**흰 테 검사.** 2026-10-02 사용자가 입장 검사 짐 칸(`slab-cream` 사본)을 보고 「니가 마감 실수한것같네」라고 짚었다. 흰 바탕 사진에서 오릴 때 펠트와 바닥 그림자 사이의 흰 바탕(사진의 접지 그림자 언저리)이 알파 255로 남아, 어두운 바탕에서 판 아래·오른쪽에 흰 띠가 보였다(637×320 판 아래쪽에서 약 16px). 키트의 판·원·조각·재료 29개가 모두 걸렸다(2.2~11.4%).
- 재는 법: `python tools/펠트부품_오리기.py --검사 <파일·폴더 …>`(재료는 `--배율 0.75`). 바깥(알파<128)과 이어진 «채도≤15·밝기≥180·불투명 픽셀로 낸 5×5 표준편차≤6.5·고주파 결≤0.9» 불투명 픽셀의 비율이다. 0.5%를 넘으면 `걸림`. 크림·흰 펠트(크림 판·우유병·각설탕)는 빛 받은 털도 매끈해 보여 밝기 236 넘는 픽셀은 세지 않는다(판은 그늘이라 실측 95%가 234 이하). 결을 보지 않는 옛 기준은 흰 털을 판으로 잘못 세어 참고값으로만 함께 찍는다.
- 고친 결과: 29개 모두 0~0.15%. 전후는 [`확인시트/`](확인시트/)의 어두운 바탕·종이 바탕 시트에 있다. 고치기 전 파일은 `raw/흰띠정리_20261002_원본/`(git 제외)에 저장소와 같은 경로로 두었다.
- 사본 맞추기: 키트를 고치면 사본과 함께 **사본을 다시 복사한 곳**까지 찾는다. 크기를 줄인 사본은 해시가 달라서, 옛 판 해시(위 백업 폴더)로 한 번, 부품 이름으로 한 번 찾고 `--검사`로 확인한다. 같은 날 빈칸 베기가 고치기 전의 입장 검사 kit을 복사해 배지 3개가 옛 판으로 남아 있었다. 전달 ZIP·QA 캡처·시연 영상이 옛 판을 품고 있으면 다시 묶거나 다시 찍는다.
