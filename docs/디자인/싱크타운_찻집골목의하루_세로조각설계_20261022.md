## 0. 한눈에

**증명할 것.** 처음 온 사람은 10~15분 안에, 다시 온 사람은 첫 화면에서 아래 셋을 자기 말로 설명할 수 있어야 한다([구현 대조](research/town-review-20261021/IMPL_구현대조.md) §8).

1. **마을이 나 없이도 산다.** 시간과 날씨에 따라 주민이 자기 일을 하고, 서로 돕고, 그 흔적이 남는다.
2. **내 선택이 남는다.** 내가 놓은 자리를 주민이 습관으로 쓰고, 내가 같이 고친 물건과 같이 정한 새 차가 다음 날에도 있다.
3. **마을이 나에게 맞춰진다.** 내가 주로 오는 시간대의 자리가 채워지고, 주민의 말이 내 한국어 수준에 맞는다.

**만드는 것.** 마을 런타임 층 넷(마을 시계 · 주민 일과와 계획 · 콘텐츠 데이터와 검사기 · 나눠 저장하는 세이브)과, 그 위에서 바로 체감되는 넷(마음 한 줄 · 작은 필요 카드 · 전해 듣기 · 찻집 주문 손맛). 범위는 이미 있는 네 장소(집·찻집·공방·온실)와 세 주민(찻집 주인·공방 주인·연구원)이다. 새 장소·새 3D 미술은 없다.

**하지 않는 것.** 새 장소·새 주민·새 3D 미술, 이웃 16명과 공유 마을, 경제·코인, 펫·낚시·버스·농사, 열 가지 생활의 나머지, 목소리 녹음, 결제, 입장 권한을 주는 길(학습·개인화 다리의 몫).

**사흘 쉬고 저녁에 들어온 30초(이 조각의 판).** 찻집 앞, 내가 만든 정원 자리에 공방 주인이 앉아 쉬고 있다(습관, §6-5). 비가 와서 찻집 주인은 바깥 쟁반을 처마 밑으로 들였고, 다가가면 이름 아래에 「손목이 시큰해서 안쪽만 열었어요」가 보인다(마음 한 줄 — 행동이 바뀐 때만, §7, L2 판). 온실에서는 연구원이 젖은 관찰판을 들고 말릴 자리를 찾는다(작은 필요 카드 R2 — 다가가면 「같이 볼래요?」, §8). 집에 오면 마을 소식 「공방 주인이 찻집 쟁반 받침을 새로 맞춰 줬대요.」가 한 줄 있다(전해 듣기, §9, L3 판). 누구도 「오랜만이에요」라고 하지 않는다.

**착수 순서(§17).** W0 시험 기반 → W1 시계·자리·난수 → W2 세이브 나누기와 맥박 줄이기 → W3 일과표와 계획기(14초 대본 교체) → W4 자기 상태와 마음 한 줄 → W5 카드·쌍·전해 듣기 → W6 부재 따라잡기와 습관 → W7 시간대 빛과 비 → W8 찻집 주문 손맛 → W9 대화 한 장면과 학습 어댑터 → W10 원고 제작(W3부터 나란히) → W11 인수.

## 2. 기술 선택

점검 §9 마지막 문단의 판단(웹 three.js 유지, 구운 빛은 하루 네 시각을 여러 벌 구워 섞기, 세이브는 사건 단위)에서 시작했다. 바꾼 것은 2-2의 빛 하나이고, 이유를 적는다.

### 2-1. 렌더러는 웹 three.js 그대로

이 조각이 증명할 것은 렌더러가 아니라 「마을 런타임 층」이다. 런타임 층(시계·계획·결산·카드·전해 듣기)은 렌더러와 상관없는 순수 함수로 쓰므로 나중에 엔진을 바꿔도 남는다([구현 대조](research/town-review-20261021/IMPL_구현대조.md) §4-6). Unity 전환안은 공용 작업본의 미추적 문서에만 있고 실물 휴대폰 근거가 0건이라, 지금 바꿀 근거가 없다. 실물 휴대폰 측정(§15-6)에서 기준 기기가 목표에 크게 못 미치면 그때 다시 본다.

### 2-2. 시간대 빛 — 한 벌 굽기 + 두 몫 보정으로 시작하고, 여러 벌은 근거가 생기면

**바꾼 판단.** 첫 조각은 지금 WORLD 기본인 구운 마을 **한 벌**에 시간대 보정을 얹는다. 네 시각 여러 벌 굽기는 인수 결과로 필요할 때 더한다.

**근거.**
- 구운 재질은 이미 빛을 두 몫으로 나눠 갖고 있다. 텍스처 알파에 「해가 직접 비춘 몫」이 들어 있고, 셰이더가 그 몫에만 그림자를 곱한다(`experiences/synk-town/day-district.mjs:38~55`). 그래서 하늘 몫(1 − 알파)과 해 몫(알파)에 시간대별 색·세기를 따로 곱하면, 새로 굽지 않아도 새벽의 푸른 기운, 한낮, 노을빛, 해 진 뒤의 어둠을 낼 수 있다.
- 여러 벌 굽기의 비용이 이 조각에는 크다. 동네 전체 구운 판은 휴대폰 첫 진입에 +5.33MB, 풀린 GPU 텍스처가 20.3MB다([구현 대조](research/town-review-20261021/IMPL_구현대조.md) §3). 네 벌이면 내려받기가 네 배이고, 두 벌을 섞는 동안에는 GPU 메모리가 두 배다. 실물 휴대폰 근거는 아직 0건이다.
- 한 벌 보정으로 못 내는 것은 아침·저녁에 그림자 방향이 바뀌는 것뿐이다. 이것이 체감에 중요한지는 관찰(§15-6의 「지금 몇 시쯤 같아요?」)로 확인한다.

**판정 기준.** 관찰 참가자의 80% 이상이 네 구간을 맞히면 한 벌을 유지한다. 못 미치면 아침·저녁 두 시각을 더 굽고(점검 §9의 여러 벌 섞기), 섞는 동안의 fps를 다시 잰다. v20(실시간 빛) 판은 해의 방향·색·세기와 하늘빛을 시각마다 바꾼다.

### 2-3. 계산은 같은 함수, 확정은 서버

- 런타임 층은 **기기와 서버가 같은 ESM 모듈**을 쓴다. 지금 talk 묶음이 `experiences/synk-town` 원천을 묶어 쓰는 길(`SYNK-talk`의 `tools/synk-town-build.js`) 그대로다.
- 시드는 서버가 정한 마을 날짜·생활일·구간 시작 때의 명령 판(`cmdRev` — 플레이어 명령만 올리는 판, §14-4)에서 만든다. 결산이나 읽기는 이 판을 올리지 않으므로 누가 언제 읽었는지가 결과를 바꾸지 않는다. 기기 시계는 쓰지 않고, 서버 시각과의 차이만 기억해 예측에 쓴다.
- **서버는 틱을 돌리지 않는다.** 요청이 올 때마다 「마지막으로 결산한 때부터 지금까지」를 같은 함수로 결산한다(게으른 결산, §14-4). 그래서 상시 서버 비용이 없고, 계산량은 부재 기간이 아니라 결산 상한(7일)에 묶인다.
- 세계를 바꾸는 결과는 서버가 확정한다. 주민끼리의 일(카드 혼자·둘이 해결, 쌍 장면)은 서버가 결산하며 확정하고, 플레이어가 끼는 일(카드 참여·찻집 주문·대화)은 명령으로 받아 확정한다. 기기는 같은 함수로 미리 그린다. 지금의 직접 걷기(서버 권위 + 브라우저 예측, `walk.mjs`)와 같은 꼴이다. 두 기기가 같은 서버 상태를 받으면 같은 결과를 그린다.

### 2-4. 결정성 규칙

| 규칙 | 이유 |
|---|---|
| 난수는 32비트 정수 연산만 쓰는 생성기(`sfc32`류)와 문자열 해시로 만든다. `Math.random`을 쓰지 않는다 | 브라우저·Node·talk 실행 환경에서 같은 값 |
| 가중치는 정수(천분율)로 적고, 고르기는 정수 누적합으로 한다 | 소수 합의 반올림 차이가 기기마다 결과를 가르지 않게 |
| 상태값(기운·할 일·어울림·마모)은 정수 | 같은 이유 |
| 계산 함수는 시각을 숫자(서버 epoch ms)로만 받는다. `Date`의 지역 시간·`Intl`·로캘 함수를 쓰지 않는다 | CI는 UTC·리눅스, 유호님 PC는 KST·윈도우다 |
| 한국 시각은 UTC+9 고정으로 계산한다 | 한국은 서머타임이 없다 |
| 사용자 시간대는 기기가 알린 오프셋을 서버가 「시간대 바뀜 사건」으로 기록하고, 계산은 그 기록만 쓴다(§4-6) | 기기 ICU 판이 달라도 같은 결과 |

## 3. 세 주민 — 하루·마음·서로의 사이

### 3-1. 공통

- 화면 이름은 역할명(찻집 주인·공방 주인·연구원)이다. 최종 이름·외형·목소리는 미정이고, 한말순·오미자·윤슬을 이 역할로 바꿔 쓰지 않는다(NPC:383). 아래 성격·취향·바람·관계는 [주민 관계 원고](싱크타운_주민관계와_연속생활_원고.md#cast)(관계:22~24·44~46)에서 가져왔고, 하루·기상·취침·마음의 재료는 이 문서가 새로 정한다.
- 셋 다 플레이어에게 `-어요`로 말한다. 이름을 아는 근거가 없으면 호칭을 생략한다. 말 놓기·집 방문은 이 조각에 없다(관계:37).
- 10-22 결정에 따라 셋에게도 **자기 삶의 가벼운 기복**이 있다(주민:112). 기복의 재료는 몸(손목·찬 손·졸음), 날씨, 자기 일의 고민(새 메뉴·밀린 주문·긴 설명)이다. 플레이어를 향한 서운함과 화·실망 표정은 없다(G4·G10).
- 성격은 대사만이 아니라 **수치 몇 개**로도 드러난다(아래 「성격 배수」). 같은 규칙을 써도 세 사람이 다르게 산다.

### 3-2. 찻집 주인

> 「차는 처음 따를 때 향이 제일 좋아요.」 손님이 말을 계속 걸지 않아도 편하게 머무는 찻집을 바라는 사람. 손님 요청은 척척 정리하는데, 정작 자기는 앉아 쉬는 데 서툴다.

| 항목 | 내용 |
|---|---|
| 좋아함 | 차를 처음 따를 때의 향, 손님이 각자 편하게 머무는 자리(관계:22) |
| 잘함 / 서툶 | 손님 요청을 정리해 준비하기 / 혼자 앉아 쉬기(관계:22) |
| 바람 · 목표 | 말을 계속 걸지 않아도 편한 찻집 · GOAL-C1 쉬는 손님과 지나가는 손님의 동선 나누기(관계:44) |
| 하루(평일) | 05:30 일어나 온실에서 첫 잎을 따고 잔을 데운다 → 낮에는 손님 맞기로 바쁘다 → 저녁에는 공방에 차 한 잔을 가져다주고, 처마 밑에서 겨우 한 잔 마신다 → 밤에는 등을 켜고 「밤 찻집」을 열어 차림표를 손본다 → 23:30 잔다 |
| 주말 | 낮 손님이 더 많다(할 일 +1). 쉬는 날은 없다 — 찻집 주문(§11)이 어느 날에도 열려야 해서다(G9) |
| 마음의 재료 | 비 오는 날 손목이 시큰하다 · 손님이 몰리면 말이 짧아진다 · 쉬는 게 서툴러 기운이 많이 빠져야 앉는다 · 새 메뉴를 고민한다 · 잎 통이 비어 간다 · 첫 차 향이 좋으면 기분이 좋다 · 내일 비가 오면 바깥 비품을 미리 들인다 |
| 성격 배수 | 쉬기 문턱이 기운 25(다른 둘은 30) · 손님 맞기 가중치 ×1.2 · 영업 중에는 졸지 않는다 |
| 말맛 | 짧고 부드럽다. 「잠깐만요」「여기요」. 손님 앞에서는 한 문장, 둘만 있을 때 한 문장 더 |

### 3-3. 공방 주인

> 흔들리는 물건은 한눈에 알아보지만, 자기가 만든 물건 이야기는 쑥스러워 잘 못 하는 사람. 바람이 통하는 조용한 점심 자리를 좋아한다.

| 항목 | 내용 |
|---|---|
| 좋아함 | 손때가 남은 도구, 바람이 통하는 조용한 점심 자리(관계:23) |
| 잘함 / 서툶 | 흔들림·막힌 배치 찾기 / 자기 물건의 사연 설명하기(관계:23) |
| 바람 · 목표 | 만든 물건을 이웃이 다른 방식으로 오래 쓰는 것 · GOAL-W1 점심 도구 정리를 끝내고 조용히 쉬기(관계:23·45) |
| 하루(평일) | 05:00 공방 불을 켜고 도구를 손질한다 → 낮에는 주문 작업, 점심에는 바람 통하는 자리에서 쉰다 → 저녁에는 이웃 물건을 살펴보러 골목을 돈다 → 21:30 잔다 |
| 휴무(수요일) | 쉬는 날에도 다섯 시면 눈이 떠진다. 오전엔 온실까지 산책하고, 낮엔 찻집에 오래 앉아 있다 |
| 마음의 재료 | 아침이 쌀쌀하거나 비가 오면 손이 차서 천천히 한다 · 큰 주문이 밀린다 · 조용히 쉬고 싶다 · 새 도구가 손에 안 익는다 · 흔들리는 걸 보면 못 지나친다 · 비 갠 뒤 문턱이 미끄럽다 |
| 성격 배수 | 주민 물건의 마모가 문턱의 70%를 넘으면 「살펴보기」 가중치 ×1.5 · 손님이 많은 자리의 쉬기 가중치 ×0.5 |
| 말맛 | 셋 중 가장 짧다. 「여기 어때요?」「잠깐 쉬어요」. 반말·관용구를 쓰지 않는다(원고:15) |

### 3-4. 연구원

> 같은 잎의 빛과 그림자를 비교하는 걸 좋아하는 사람. 발견은 많은데 한 번에 다 말하고 싶어 해서, 「관찰 하나만」을 연습하는 중이다.

| 항목 | 내용 |
|---|---|
| 좋아함 | 같은 잎의 빛과 그림자 비교, 남이 남긴 관찰 그림(관계:24) |
| 잘함 / 서툶 | 관찰 사실·출처 확인 / 한 번에 너무 많이 설명하기(관계:24) |
| 바람 · 목표 | 잠깐 보고도 발견 하나를 말할 수 있는 작은 전시 · GOAL-R1 긴 설명 대신 관찰 하나(관계:24·46) |
| 하루(평일) | 08:00 일어나 온실에 물을 주고 잎을 본다 → 낮에는 찻집 앞에서 잎을 비교하고 그림을 펼친다 → 저녁에는 찻집 처마 밑에서 관찰 기록을 정리한다 → 밤에는 온실에서 밤에 피는 꽃과 별을 본다 → 01:00 잔다 |
| 휴무(일요일) | 10:00까지 늦잠 · 낮엔 찻집에서 오래 기록을 쓰고 공방을 구경한다 |
| 마음의 재료 | 밤새 관찰한 다음 날 아침은 졸리다 · 새 발견에 들뜨면 설명이 길어진다 · 관찰판이 비에 젖는다 · 밤에 꽃이 핀다 · 낙엽이 진 날은 「오늘의 잎」을 고른다 · 내일 맑으면 관찰 준비를 한다 |
| 성격 배수 | 하루 「그림 펼치기」가 세 번을 넘으면 카드 R3 · 들뜬 날 관찰·보여 주기 ×1.5 |
| 말맛 | 길어지려다 스스로 끊는다. 「그러니까… 하나만요」. 학술어를 쓰지 않는다(원고:16) |

### 3-5. 서로의 사이

셋은 이미 알고 지내는 이웃으로 시작한다(관계:26). 사이는 내려가지 않는다. 「작은 의견 차이」는 다툼이 아니라 둘이 함께 풀어 가는 주제이고, 풀릴 때마다 대사가 한 걸음 바뀐다(§9-1).

| 쌍 | 가까운 점 | 작은 의견 차이 (풀어 가는 단계 0~2) | 함께하는 일 · 쌍 장면 |
|---|---|---|---|
| 찻집 주인 × 공방 주인 | 공방은 흔들리는 물건을 바로 알아보고, 주인의 차를 좋아해 받침을 고쳐 준다. 주인이 못 쉬면 「오늘은 제가 안내할게요」(관계:22~23) | **쉬는 법** — 공방은 쉬라 하고 주인은 못 쉰다. 단계가 오르면 주인이 「오늘은 좀 앉을게요」라고 먼저 말한다 | PAIR01 쟁반 받침 맞추기(관계:353) · 차 가져다주기 |
| 공방 주인 × 연구원 | 공방은 긴 설명을 어려워하지만 그림 받침을 만들어 준다. 연구원에게 공방은 「여기부터 보여 주세요」라고 솔직하게 말해 주는 이웃(관계:23~24) | **설명의 길이** — 단계가 오르면 연구원이 먼저 「밝은 쪽 한 장만요」라고 한다 | PAIR02 관찰판 받침 각도(관계:361) |
| 연구원 × 찻집 주인 | 설명이 길어 차가 식곤 한다. 주인은 연구원에게 「향을 이야기로 바꿔 주는 이웃」(관계:22·24) | **향이 먼저냐 설명이 먼저냐** — 단계가 오르면 연구원이 말하기 전에 향부터 맡는다 | PAIR03 향 먼저 맡기(관계:369) |

### 3-6. 손님

- 3D에 이미 있는 손님 셋을 찻집 배경 손님과 찻집 주문(§11)의 손님으로 쓴다. 손님은 마을 주민이 아니라 지나가는 사람이라, 기억·관계를 갖지 않는다.
- 단골 `visitor-tea-reader`(책을 가져온 손님)는 차 향과 창밖 풍경을 좋아하고, 선택지가 한꺼번에 많으면 주문을 못 정한다(관계:14~16). 처음 주문한 차를 「늘 마시던 것」으로 기억한다(§11-5). 이것은 손님 자신의 취향이지 플레이어에 대한 기억이 아니다.

## 4. 마을 시계

### 4-1. 세 가지 시각

| 시각 | 무엇에 쓰나 | 계산 |
|---|---|---|
| **내 시각**(사용자 시간대) | 빛, 주민 일과의 구간 | 서버 시각 + 그 순간 유효한 사용자 오프셋(§4-6) |
| **생활일** | 하루 유형(평일·주말·휴무), 하루 상한(카드·전해 듣기), 습관 | 내 시각 기준 05:00에 시작해 다음 날 05:00에 끝난다. 밤 구간(21:00~05:00)이 자정을 넘어도 같은 생활일이다. 생활일 번호는 줄지 않는다(§4-6) |
| **한국 날짜** | 계절, 날씨, 마을 소식의 날짜 | 서버 시각 + 9시간의 날짜 |

정본의 「개인 빛과 개인 일과는 사용자 시간대, 달력과 계절·날씨는 한국 날짜」(NPC:321, 마을:183)를 그대로 따른다.

### 4-2. 네 구간과 「만날 수 있는 시각」

| 구간 | 내 시각 | 빛(구운 판 보정의 기준점) | 일과 |
|---|---|---|---|
| 아침 | 05:00~11:00 | 05:00 새벽 안개 → 08:00 아침 | 공방 05:00·찻집 05:30 시작, 연구원 08:00 합류 |
| 낮 | 11:00~17:00 | 12:00 한낮 | 셋 다 |
| 저녁 | 17:00~21:00 | 17:30 노을 → 19:30 푸른 저녁 | 셋 다, 공방 21:30 취침 |
| 밤 | 21:00~05:00 | 21:00 등불 밤 → 00:00 깊은 밤 | 찻집 23:30·연구원 01:00 취침 |

- 이 조각의 단위는 네 구간이다. 나중에 여섯 칸(새벽·아침·낮·오후·저녁·밤, R1)으로 나눌 때는 일과표가 「칸 → 없으면 구간」 순서로 찾게 해서 데이터를 버리지 않는다.
- **「어느 시간대에 와도 두 주민」(마을:524, NPC:321)의 해석.** 정본 §4-2에는 「깊은 밤(마을이 잠든다)」(마을:183)도 있다. 세 사람이 사람답게 자면서 하루 24시간 내내 둘 이상이 깨어 있을 수는 없다. 그래서 이 조각은 **만날 수 있는 시각 05:30~23:30에는 언제나 둘 이상**, **깊은 밤 23:30~05:30에는 정본대로 마을이 잠든다**(연구원이 01:00까지 밤 관찰)로 정한다. 밤에 자주 오는 사람의 마을은 밤 자리가 더 채워진다(공방 주인이 23:00까지 밤 깎기를 해서 21:30~23:00에 셋, 연구원이 02:00까지 밤 관찰 — §10-3). 공방 주인은 다음 날도 05:00에 일어나야 아침의 두 주민이 지켜지므로 23:00보다 늦추지 않는다. 이 해석은 결정을 바꾸지 않으며 §15-1의 시뮬레이션으로 지킨다.

기상·취침으로 본 덮임(평일):

| 시각 | 05:00 | 05:30 | 08:00 | 21:30 | 23:30 | 01:00 |
|---|---|---|---|---|---|---|
| 깨어 있는 주민 | 공방 | 공방·찻집 | 셋 | 찻집·연구원 | 연구원 | 없음 |

일요일은 연구원이 10:00에 일어나도 05:30~10:00에 공방·찻집 둘이 있다. 수요일(공방 휴무)에도 공방 주인은 05:00에 일어난다.

### 4-3. 하루 유형

`평일`(월~금) · `주말`(토·일) · `휴무`(공방 수요일, 연구원 일요일 — 휴무가 주말보다 앞선다). 찻집 주인은 휴무가 없다. 요일은 생활일의 날짜로 정한다. 행사일은 이 조각에 없고 덮어쓰기 칸만 비워 둔다.

### 4-4. 날씨 두 가지

**종류:** 맑음 · 비. 같은 마을·같은 한국 날짜면 같은 날씨다(마을:189). 마을 씨앗(`villageSeed`)은 서버가 계정 마을을 만들 때 정한 무작위 값이고 계정 ID에서 만들지 않는다. 학원 반 마을 소속이면 그 반 마을의 씨앗을 써서 같은 반이 같은 날씨를 본다.

**하루 꼴.** 한국 날짜로 다섯 꼴 가운데 하나를 고른다. 하루 안에서도 바뀐다(마을:189). 시각은 한국 시각이다(같은 마을의 열여섯이 같은 순간에 같은 하늘을 보게).

| 꼴 | 한국 시각의 날씨 |
|---|---|
| 맑은 날 | 맑음 00~24 |
| 비 오는 날 | 비 00~24 |
| 오후 비 | 맑음 00~13 · 비 13~20 · 맑음 20~24 |
| 아침 비 갬 | 비 00~10 · 맑음 10~24 |
| 저녁 소나기 | 맑음 00~17 · 비 17~19 · 맑음 19~24 |

**계절별 가중치(천분율, 〔초기값〕).** 계절은 한국 날짜의 달로 정한다(봄 3~5, 여름 6~8, 가을 9~11, 겨울 12~2).

| 계절 | 맑은 날 | 비 오는 날 | 오후 비 | 아침 비 갬 | 저녁 소나기 |
|---|---|---|---|---|---|
| 봄 | 600 | 100 | 120 | 100 | 80 |
| 여름 | 450 | 200 | 120 | 100 | 130 |
| 가을 | 650 | 90 | 100 | 100 | 60 |
| 겨울 | 800 | 60 | 50 | 60 | 30 |

겨울의 비는 눈이 들어오면 눈으로 바꾼다. **내일 날씨도 계산으로 미리 안다**(주민:83). 주민의 마음 한 줄(「내일 비 온대요」)과 내일의 이야기 카드(§8-5)가 이것을 쓴다.

### 4-5. 덮어쓰기 순서

`수락한 약속 > 행사 > 날씨 > 휴무 > 계절 > 기본`(R1). 이 조각에서 실제로 쓰는 층은 약속(플레이어가 수락한 카드·찻집 일, 쌍 약속, 합의 자리) · 날씨(비 → 대안 자리) · 휴무 · 기본이다. 비어 있는 층(행사·계절)도 순서 자리는 코드에 둔다.

**예외 하나.** 약속이 날씨보다 앞서도, 약속 자리가 비를 못 피하는 자리이고 비가 오면 그 약속은 `rainAlt`의 처마 자리로 옮겨 지키고, 그런 자리가 없으면 다음 맑은 구간으로 미룬다. 주민이 비를 맞으며 앉아 있지 않게 하려는 것이다(§15-1 「비 오는 동안 바깥 자리에 앉은 주민 0」).

### 4-6. 시간대가 바뀌면(여행·서머타임)

- 기기는 들어올 때마다 지금 오프셋(분)을 알린다. 서버는 마지막 기록과 다르면 「시간대 바뀜」을 **다음 구간 경계부터** 유효하게 기록한다. 이미 결산한 일을 다시 만들지 않는다(NPC:321).
- 생활일 번호는 줄지 않는다. 오프셋이 뒤로 가서 같은 생활일이 두 번 생길 수 있으면, 내 시각이 원래 생활일 끝을 지날 때까지 지금 생활일을 이어 쓴다. 그래서 시간대를 바꿔 카드·하루 상한을 더 받을 수 없다.
- 오프셋은 −12:00~+14:00 안의 15분 단위만 받는다. 기록은 최근 넷만 둔다.

## 6. 일과표와 계획기 — 14초 대본을 바꾼다

지금 주민 일과는 방문마다 처음부터 도는 14초짜리 고정 대본이다(공방 3초 도구 정리 → 5초 걸어서 찻집 → 4초 대화 → 2초 귀가, `day.mjs:37`·`:52~54`·`:169~199`·`:234`). 이것을 「주민 × 하루 유형 × 구간 → 활동 묶음과 가중치」 데이터와, 그 데이터로 구간마다 할 일을 짜는 계획기로 바꾼다.

**물건을 옮기는 원형.** 물건의 자리는 그 물건을 마지막으로 옮긴 원형이 정한다. 카드 C2·R1·R2의 「비품·판이 바깥」은 이 표로 판정한다.

|---|---|
| `prep-cups` | 쟁반 → 준비대 |
| `serve` | 쟁반 → 손님이 앉은 자리(바깥 자리면 바깥). 다음 `prep-cups`가 준비대로 거둔다 |
| `deliver-tea` | 쟁반 → 공방 문가, 돌아올 때 같이 가져온다 |
| `bring-in` | 바깥 자리에 있는 찻집 비품(쟁반) → 처마 자리 |
| `show-drawing` | 관찰판 → 그림을 펼친 찻집 자리(바깥 자리면 바깥) |

### 6-2. 일과표 형식

```json
{ "npc": "cafe-owner", "dayKind": "weekday", "band": "evening",
  "awake": { "from": "17:00", "to": "21:00" },
  "pool": [
    { "archetype": "serve",       "spot": "cafe.seats",       "weight": 300 },
    { "archetype": "deliver-tea", "spot": "workshop.door",    "weight": 200 },
    { "archetype": "prep-cups",   "spot": "cafe.prep",        "weight": 250 },
    { "archetype": "eaves-tea",   "spot": "cafe.eaves",       "weight": 250 } ],
  "rainAlt": { "cafe.seats": "cafe.eaves", "workshop.door": "workshop.bench" },
  "openToPair": ["workshop-owner", "researcher"],
  "minDistinctPlacesPerDay": 3 }
```

- `cafe.seats`·`cafe.eaves`처럼 묶음 이름을 쓰면 계획기가 그 묶음 안에서 비어 있는 자리를 고른다.

- 칸마다 활동 셋 이상, 주민마다 하루 서로 다른 장소 셋 이상이 하한이다(R2·R10). 장소 셋은 표만으로도 대부분 채워지지만, 계획기가 「저녁 구간이 시작될 때 그날 간 장소가 셋보다 적으면 안 간 장소의 활동에 ×3」으로 보장한다.

### 6-4. 계획기 — 구간마다 할 일을 짠다

계획기는 매 프레임 고르지 않는다(NPC:87). 구간이 시작될 때, 그리고 구간 안의 **결정 시점**(날씨가 바뀔 때, 카드가 생길 때, 플레이어가 주민을 예약했다가 놓아줄 때)에만 남은 시간을 짠다. 같은 입력이면 같은 계획이 나온다.

```text
plan(주민 r, 생활일 d, 구간 b, 구간 시작 상태 S, 구간 시작 명령 판 c):
  표 = 일과표[r][하루유형(d, r)][b]        ← 수락한 약속·휴무를 먼저 적용(§4-5)
  t = max(구간 시작, 기상), 끝 = min(구간 끝, 취침)
  난수 = 생성기(해시(마을 씨앗, "plan", d, b, r, c))      ← c는 명령만 올리는 판(§14-4)
  고정 항목을 먼저 넣는다: 수락한 약속, 이 구간에 잡힌 쌍 장면(§9-1), 카드의 혼자·둘이 해결(§8-3)
  t < 끝인 동안:
    기본 후보 = 표.pool ∪ 습관 항목(§6-5)
    더한 후보 = 날씨가 부르는 것(맑은 아침 첫 조각의 처마 밑 한 잔, 내일 비가 오는 날 저녁의 비품 들이기,
                비 오는 동안 바깥 활동의 처마 판) ∪ 상태가 부르는 것(기운 문턱 아래의 졸기)
                ∪ 카드가 부르는 것(카드의 혼자 길, 이웃 일 뒤의 쉬기)
    쓸 수 있음 = 자리가 비어 있고 주민 예약과 겹치지 않음(0/1)       ← 날씨는 여기에 넣지 않는다
    기본 점수 = 가중치 × 쓸 수 있음 × 습관 배수 × 성격 배수 × 반복 배수      (기본 후보만)
    고른 점수 = 기본 점수 × 날씨 배수 × 상태 배수 × 카드 배수              (기본 후보 + 더한 후보)
      · 날씨 배수: 비 오는 동안 바깥 자리 ×0, 쌀쌀한 아침(비 오는 아침·겨울 아침)의 작업 ×0.5, 내일 맑은 날 저녁의 관찰판 정리 ×2
      · 상태 배수: §7-1 / 카드 배수: §8과 이웃 일(받침을 고쳐 받음·차를 받음) / 반복 배수: 최근 세 원형과 같으면 ×0.5, 바로 앞과 같으면 0(쉬기·졸기 제외)
    u = 난수.다음()                          ← 한 번 뽑은 u로 두 목록에서 같이 고른다
    고른 것 = 고른 점수의 정수 누적합에서 ⌊u × 그 총합 / 2³²⌋의 자리
    기본 것 = 기본 점수의 정수 누적합에서 ⌊u × 그 총합 / 2³²⌋의 자리
      · u는 32비트 정수 하나, 배수는 천분율 정수(×1.5 = ×1500 ÷ 1000, 나머지 버림)로 곱한다(§2-4)
    마음 = 고른 것 ≠ 기본 것(원형이나 자리)이고, 고른 것이 날씨·상태·카드로 커졌거나(더한 후보 포함)
           기본 것이 날씨·상태·카드로 작아졌을 때만. 이유는 그 배수(§7-3)
    길이 = 원형 길이 범위에서 난수로, 이동 시간 = 자리 사이 걷는 거리 / 걷기 속도
    조각 = { 시작 t, 끝 t+이동+길이, 원형, 자리, 원인, 마음 }
    상태 S에 원형의 변화를 잠정 반영, t = 조각 끝
```

결정 시점(날씨 바뀜·카드 생김·예약 해제)에 남은 시간을 다시 짤 때는 난수를 `해시(마을 씨앗, "replan", d, b, r, c, 구간 시작부터 지난 분, 결정 사건 ID)`로 새로 만든다. 언제 누가 읽었는지와 상관없이 같은 계획이 나온다.

- **조각(segment)** 하나가 「주민이 이 시간에 이 자리에서 이 일을 한다」이다. 화면은 지금 시각의 조각에서 위치·자세를 보간하고, 화면 밖 주민도 같은 조각으로 계산한다(NPC:137·435).
- **예약.** 플레이어가 주민과 무엇을 시작하면(카드 참여·찻집 주문·대화·첫 하루 장면) 그 주민의 그 시간을 예약한다. 예약이 끝나면 계획기가 그 시각부터 남은 구간을 다시 짠다. 놓친 조각은 몰아서 다시 하지 않는다(NPC:341). 지금 core의 바쁨 깃발(`cafeBusy`·`workshopBusy`, `core.mjs:121~170`)은 이 예약 표로 바꾼다.
- **우선순위.** 이 계획기는 NPC 실행 우선순위의 5단계(배경 생활) 안에서만 고른다. 0~4단계 후보(무효 예약 해제, 진행 중인 사용자 상호작용, 방금 발의한 행동, 주민끼리 약속, 먼저 제안하는 도움)가 있으면 그것이 먼저다(NPC:91~98).
- **막힘.** 같은 자리로 가는 길이 두 번 막히면 자기 기본 자리의 정지 대안으로 끝낸다(NPC:397).
- **잠.** 취침 시각이 되면 주민은 자기 집 쪽으로 걸어가 사라진다. 잠은 원형이 아니라 「없음」이고, 기상 때 기운을 채운다(§7-1).

### 6-5. 내 흔적 → 습관 → 일과

- **습관 후보 자리**는 둘이다. ① FT10에서 플레이어가 만든 자리(`placement`), ② 첫 하루의 조율 합의(`day.agreement` — 공방의 쉼과 연구원 그림의 합의, LS01.3에 대응)가 정한 자리.
- 주민이 그 자리에서 실제로 앉은 조각을 **서로 다른 두 일과 기회**(다른 구간이나 다른 생활일)에 마치면 습관이 생긴다(생활재미:289, NPC:390 「실제 앉은 이용만 습관 근거」). 그 주민의 해당 구간 일과표에 「그 자리에서 쉬기/기록 쓰기」를 가중치 300으로 넣고, 이 항목에만 습관 배수 1.5를 붙인다(R8).
- **다음 날로 잇기.** 조율 합의가 끝나면 다음 낮 구간에 공방 주인이 그 자리에서 한 번 쉬는 것을 「수락한 약속」으로 넣는다(덮어쓰기 최상위). 「오늘 정한 자리를 내일 공방 주인이 실제로 쓴다」가 첫 방문 다음 날 바로 보인다. 첫 하루 장면에서 합의대로 실제로 앉은 것(지금 `day.agreement`의 이용)을 첫 이용으로 세므로, 다음 날의 이용이 두 번째가 되어 습관이 선다. 그날 비가 와서 그 자리가 비를 못 피하면 약속은 §4-5의 예외대로 처마 자리로 옮기거나 다음 맑은 구간으로 미룬다.
- 자리가 사라지면(플레이어가 회수) 습관 항목을 바로 빼고, 지난 이용 기록은 남긴다. 부재로는 습관이 줄지 않는다(G3).

## 7. 주민 자기 상태 셋과 마음 한 줄

### 7-1. 세 가지 상태 〔초기값〕

| 상태 | 범위 | 하루 시작 | 줄어듦 | 늘어남 | 행동에 주는 영향 |
|---|---|---|---|---|---|
| 기운 | 0~100 | 기상 때 max(지금 값, 80). 다만 **자기 삶의 밤샘** 다음 날은 45(연구원이 카드 R4 「밤에 피는 꽃」으로 01:00을 넘겨 관찰한 날) | 일 원형 −1~−2(§6-1) | 쉼 원형 +4~+12 | 30 미만(찻집 주인 25 미만)이면 쉬기 ×3·졸기 후보(가중치 300)가 더해지고, 일 원형 ×0.5 |
| 할 일 | 0~5 | 주민마다 아래 | 주민마다 아래 | 주민마다 아래 | 4 이상이면 「바쁜 날」 표현, 쌍 ×0.5, 쉼 ×0.5 |
| 어울림 | 0~100 | 기상 때 지금 값과 60의 가운데로 | 혼자 보낸 구간 −10 | 쌍 장면·이야기 +15, 손님 +2(구간당 +10까지), 플레이어와 함께 +15(구간당 한 번) | 40 미만이면 이웃 찾아가기(살펴보기·차 가져다주기·이야기)·쌍 ×2 |

**할 일은 주민마다 뜻이 다르다.** 찻집 주인은 「기다리는 손님」이다 — 배경 손님이 도착할 때마다 +1(구간마다 시드로 평일 2~5명·주말 4~8명, 낮에 가장 많다), 손님 맞기를 마칠 때 −1. 공방 주인은 「밀린 주문」이다 — 생활일 시작 때 시드로 0~2, 주에 한 번 시드로 정한 날에 큰 주문이 들어와 +2, 주문 작업 두 번 마칠 때마다 −1(카드 W4는 이 값이 4 이상일 때 생기는 결과다). 연구원은 「정리할 관찰」이다 — 관찰·별 보기 두 번마다 +1, 관찰판 정리·기록 쓰기 마칠 때 −1. 상한은 5다.

- 상태는 화면에 숫자로 보이지 않는다(G2). 몸짓(하품·기지개·빠른 걸음)과 마음 한 줄로만 보인다.
- 이 값은 학습·관계·보상 판정에 쓰지 않는다(R3, NPC:285).
- 대화 설계의 「그날 기분」(기분 좋은 날·바쁜 날·졸린 오후, 대화:229)은 날짜 씨앗만으로 정하지 않고 이 상태에서 온다 — 바쁜 날은 할 일 4 이상, 졸린 오후는 기운 30 미만, 기분 좋은 날은 `first-aroma`·`pair-glad`·`with-player-glad` 같은 좋은 일. 10-22 결정(주민 자기 삶의 기복)을 따른 바뀜이다.

### 7-2. 플레이어 탓이 생길 수 없게(G4)

- 플레이어의 부재·무응답·거절·지나침은 세 값을 바꾸지 않는다. 먼저 제안을 지나쳐도(`passed`) 주민은 자기 목적을 이어 간다(NPC:210·253).
- 플레이어와 함께한 일은 좋은 쪽으로만 바꾼다: 어울림 +15, 할 일 −1~−2(찻집 일을 도왔을 때), 기운은 바꾸지 않는다.
- 플레이어 때문에 생긴 일과 — 습관 자리 쓰기, 밤 습관으로 생긴 밤 깎기·늦은 관찰 — 는 기운·할 일을 깎지 않는다(`night-carve`의 기운 0, 밤 습관으로 늘어난 연구원 관찰 시간의 기운 0). 기상 기운을 45로 낮추는 밤샘도 주민 자기 카드(R4)로 늦게 잔 날뿐이고, 밤 습관으로 늘어난 시간은 기상 기운에 들어가지 않는다. 그래서 「어젯밤 늦게까지 있었더니 졸려요」 같은 말이 플레이어의 습관에서 나올 길이 없다.
- 기상 때 어울림이 60 쪽으로 돌아가는 것은 모든 사람에게 똑같이 일어나는 시간 효과다. 「부재 = 가만히 있음」 시험(§15-2)이 이것을 확인한다.

### 7-3. 마음 한 줄 — 행동을 바꿀 때만

**언제 생기나.** 계획기가 조각을 고를 때 같은 난수 u로 「고른 것」과 「기본 것」을 같이 구한다(§6-4의 의사코드가 정본이다). 기본 점수에는 가중치·습관·성격·반복까지만 들어가고, 고른 점수에는 거기에 날씨·상태·카드 배수와 그것들이 부르는 후보가 더해진다. 둘의 원형이나 자리가 다르고, 그 차이가 날씨·상태·카드에서 왔을 때(고른 것이 그 배수로 커졌거나 더한 후보이거나, 기본 것이 그 배수로 작아졌을 때)만 마음이 행동을 바꾼 것이고 그 조각에 마음 한 줄이 붙는다. 이유는 그 배수다. 둘 이상이면 `날씨 > 몸(기운) > 일(할 일) > 이웃(어울림) > 자기 일·이웃 일(카드)` 순이다. 습관·성격·반복 때문에 바뀐 것은 마음이 아니라서 붙이지 않는다(그 차이는 기본 점수에 이미 들어 있다).

**어떻게 보이나.** 플레이어가 그 주민의 근접 반경(2.15m, 지금 걷기 판정) 안에 들면 이름 아래에 작은 그림과 한 줄이 뜬다. 말풍선이 아니라 이름표 아래 글이고, 대답을 요구하지 않는다. 같은 주민이 같은 이유로 같은 생활일에 다시 행동을 바꾸면 줄은 다시 띄우지 않는다(행동만 보인다). 판은 읽기 자리의 안정 수준(§13-1)을 따르고, 「무슨 뜻이에요?」를 누르면 그 줄만 한 단계 아래 판과 그림으로 다시 보인다.

**이유 목록(주민마다 여덟 + 공통 하나).** 줄은 L2 판 예다(연결 하나, 8어절 안). 괄호는 그 이유를 만드는 장치다.

## 8. 작은 필요 카드

새 필요가 다시 생기지 않으면 원고를 다 본 마을은 쉬기만 한다(점검 §2-2, D2a B-2). 작은 필요 카드는 **실제 세계 상태**(마모·날씨·계절·주민 상태)가 계기가 되어 검수된 해결 틀로 이어지는 장치다. 「소모된 원고를 다시 붙이기」가 아니라 「검수된 조각을 세계 상태로 고르기」이고, 원인이 기록되므로 「일부러 쟁반을 다시 기울이지 않는다」(NPC:262)와 부딪치지 않는다(점검:71).

### 8-1. 형식

```json
{ "id": "C1", "owner": "cafe-owner", "title": "쟁반이 기울어요",
  "trigger": { "kind": "wear", "object": "cafe-tray", "threshold": 18 },
  "window": { "bands": ["morning", "day", "evening"], "needsAwake": ["cafe-owner"] },
  "cooldownLifeDays": 3, "familiarAfter": 3,
  "paths": {
    "self":   { "archetype": "prep-cups", "result": "shim-paper", "rewearAt": 9 },
    "pair":   { "partner": "workshop-owner", "scene": "PAIR01", "result": "shim-wood" },
    "player": { "scene": "PAIR01.join", "choices": ["inside", "outside", "near", "clear"],
                "result": "shim-wood+player-choice" } },
  "trace": { "object": "cafe-tray", "field": "shim" },
  "news": "cafe.news.C1", "tomorrowPreview": "cafe.tomorrow.C1" }
```

### 8-2. 계기

- **마모 — 주민 물건만.** 사용 횟수는 그 물건을 쓰는 원형을 **주민이** 마칠 때만 오른다(§6-1의 「마모」 칸). 플레이어가 한 일(찻집 주문의 잔·쟁반 포함)은 마모를 올리지 않는다. 그래서 「네가 써서 흔들린다」가 원인 사슬에 생길 수 없다(G4). 플레이어가 만든 자리·안내판·방석은 마모 자체가 없다(점검:71, 마을:117 「한번 쌓인 것은 줄어들지 않는다」).

  | 물건 | 주인 | 보이나 | 문턱 〔초기값〕 | 카드 |
  |---|---|---|---|---|
  | 쟁반(`cafe-tray`) | 찻집 주인 | 지금 소품 | 18 | C1 |
  | 잎 통 | 찻집 주인 | 보이지 않음 — 흔적은 「오늘의 차」 | 24 | C3 |
  | 도구 | 공방 주인 | 보이지 않음 | 20 | W5(새 도구로 바꾼다) |
  | 받침(`workshop-support`) | 공방 주인(연구원이 그림을 펼칠 때 씀) | 지금 소품 | 15 | W1 |

- **날씨:** 비가 시작되는 순간(그때 그 주민의 비품이 바깥 자리에 있으면), 비가 그치는 순간.
- **계절:** 계절의 첫 생활일, 가을이면 비 온 다음 날 아침의 낙엽.
- **주민 상태:** 할 일 4 이상, 기운 문턱.
- **차례:** 정해진 주기에 시드로(예: 7생활일마다 ⅓).

### 8-3. 해결 틀 고르기 · 상한

**카드의 상태 기계.** 세계 저장의 `cards[ID].status`는 아래 값 가운데 하나다(§14-2).

| 상태 | 뜻 | 다음 |
|---|---|---|
| `idle` | 계기를 기다림 | 계기 성립 + 하루 상한·쿨다운 통과 → `triggered`(그 시각을 `triggeredAt`으로 남긴다) |
| `triggered` | 필요가 생김. 주인의 다음 조각 경계까지 해결을 기다린다(길어도 10분). 예외는 첫 C4 하나 — 플레이어가 열 때까지 머문다(§8-4) | 그 사이 플레이어가 수락 → `withPlayer` · 경계에 닿음 → `resolving`(첫 C4는 넘어가지 않음) |
| `withPlayer` | 「나와 함께」 진행 중 | 마침 → `resolved` · 중단 → `paused` |
| `paused` | 수락 뒤 중단. 「하던 생활」로 남는다(NPC:212). 주민 몸은 자기 일과로 돌아간다 | 플레이어가 다시 엶 → `withPlayer` |
| `resolving` | 둘이·혼자로 해결 중(계획기의 고정 항목) | 조각을 마침 → `resolved` |
| `resolved` | 흔적을 세계에 반영, 사건을 남김 | 곧바로 `cooldown` |
| `cooldown` | 쿨다운 생활일까지 | 끝 → `idle` |

같은 카드를 세 번 넘게 겪으면 `familiar` 표시가 붙는다(아래 「익숙한 생활」). 「나와 함께」 제안의 발급·전달·수락은 먼저 말 걸기 원장(`issued → delivered → accepted/deferred/declined/passed`, NPC:208~210)이 따로 기록하고, 카드 상태는 수락됐을 때만 바뀐다.

**해결 틀 고르기.**

1. **나와 함께.** 카드가 `triggered`이고, 플레이어가 같은 장소에 있고, 카드에 이 길이 있고, 먼저 말 걸기 예산이 남고(보통 최근 유효 15분 2회·3분 간격, 활발 4회·90초, 조용히 0 — NPC:173), 이번 방문에 같은 카드 계열을 거절하지 않았으면 → 기기가 다음 안전 경계에서 보내는 경계 신호(§14-3) 안에서 서버가 제안을 발급하고, 카드 주인이 비차단 신호로 「같이 할래요?」를 한 번 건넨다(몸짓 8초·한 줄 20초, NPC:229). 방문 뒤 첫 45초·대화와 입력 중·배치 초안 중에는 건네지 않는다는 기존 규칙도 그대로다(NPC:227·232). 플레이어가 먼저 그 주민에게 말을 걸어 카드를 열면 예산을 쓰지 않는다(NPC:193).
2. **둘이 / 혼자.** **플레이어가 있든 없든** 주인의 다음 조각 경계에 닿을 때까지 수락이 없으면 그 시각에 해결을 시작한다(지나침·나중에·거절도 같다). 짝이 깨어 있고 예약이 없고 기운 40 이상이고 그 쌍의 같은 장면 쿨다운이 지났으면 「둘이」, 아니면 「혼자」다. 둘 다 되면 시드로 둘이 600 : 혼자 400, 짝의 어울림이 40 미만이면 둘이 ×2. 해결 시각이 플레이어 유무와 상관없으므로 「부재」와 「가만히 있음」이 같은 결과를 낸다(§15-2).
3. **부재 따라잡기 중**에는 1이 없다(R9).

- **상한:** 주민당 생활일 2장, 마을 전체 생활일 4장(R5의 「주민당 1~2장, 마을 3~5장」 안). 카드마다 쿨다운(기본 3생활일). 상한에 걸리면 다음 생활일로 미룬다 — 마모 카드는 문턱을 넘은 채 기다린다.
- **결과가 다르다.** 혼자 = 임시 해결(종이를 접어 괴기 — 문턱 절반에서 다시), 둘이 = 단단한 해결 + 쌍 기록·합의 + 마을 소식, 나와 함께 = 플레이어가 고른 방식(자리·방향·재료)이 남는 해결 + 플레이어와의 확정 사건(카드 주인과 짝만 안다). 셋 다 따뜻하게 끝나고, 혼자 해결은 실패가 아니다(NPC:78).
- **익숙한 생활.** 같은 카드를 세 번 넘게 겪으면 수첩에 「익숙한 생활」로 적고 새 경험으로 세지 않는다(G8, 행동:160).
- **수락 뒤 중단**은 그 카드만 「하던 생활」로 남긴다. 주민 몸은 자기 일과로 돌아가고, 플레이어가 다시 열면 이어 간다(NPC:212·253).

### 8-5. 내일의 이야기 카드 (이 조각의 선택 항목)

Steam 추천 6위(Paralives 이야기 카드·RimWorld 이야기꾼)를 작은 필요 카드 위에 얹는다. W5의 끝에 시간이 되면 넣고, 없어도 조각은 완결된다.

- **언제:** 저녁·밤 구간에 집에 들어와 문 앞 쪽지를 열거나 「쉬기」를 고를 때, 두 장까지 보인다.
- **후보:** ① 내일 날씨로 생길 카드(내일 비 → C2·R2, 비 갠 뒤 → W3·R1) ② 쿨다운이 내일 끝나는 카드 ③ 사흘 넘게 안 나온 쌍 장면. 장마다 미리 보기 한 줄 — 「내일은 비가 온대요. 연구원이 관찰판을 걱정하고 있어요.」
- **고르면:** 다음 생활일에 그 카드의 계기 창이 먼저 열리고 「둘이·나와 함께」 가중치 ×2. 날씨·계절 카드는 조건이 맞는 첫 구간에 생긴다. 마모 카드는 실제 마모가 문턱 −3에 닿으면 생긴다 — 원인이 기록된 실제 상태라는 원칙(점검:71)을 지키려고 문턱을 없는 일로 넘기지 않는다. 고르지 않은 쪽은 그날 생기지 않는다. 그래서 카드는 「어제 일에서 이어지고 실제로 다른 결과를 낸다」(Steam §5 6위).
- **안 골라도** 기본 편성이 돈다. 고르지 않은 것에 결과 차이·알림이 없다(G3).

## 9. 주민 쌍 상태와 공개 사건 전해 듣기

### 9-1. 쌍 상태

```json
{ "pair": ["cafe-owner", "workshop-owner"],
  "families": { "PAIR01": { "count": 2, "lastLifeDay": 20746 },
                "chat":   { "count": 5, "lastLifeDay": 20748 } },
  "agreements": { "trayShim": "wood", "trayUse": "inside" },
  "friction": { "topic": "rest-vs-work", "step": 1 },
  "lastMet": { "lifeDay": 20748, "band": "day" } }
```

- 쌍 장면이 끝나면 `families`·`agreements`를 고친다(관계:137~141의 「주민끼리 달라지는 관계」를 세 쌍 모두로 넓힌 것).
- **편성:** 구간마다 두 사람이 깨어 있고 예약이 없는 쌍이 후보다. 가중치 300 × 어울림 배수(§7-1) × (풀어 가는 단계가 2 미만이면 1.2). 쌍 장면(PAIR·카드의 둘이)은 마을 전체 생활일 셋까지, 같은 쌍의 같은 계열은 2생활일 쿨다운. 가벼운 이야기(`chat`)는 쌍마다 구간 하나까지.
- **작은 의견 차이**(§3-5)는 관련 카드가 「둘이」로 풀릴 때 단계가 하나 오른다(최대 2). 내려가지 않는다. 단계마다 그 쌍의 대사가 바뀐다 — 쉬는 법 0단계 「좀 쉬어요.」「괜찮아요, 금방 끝나요.」 → 2단계 「오늘은 좀 앉을게요.」「네, 제가 볼게요.」
- 같은 계열을 세 번 넘게 보면 「익숙한 생활」(G8).

### 9-2. 무엇이 「공개 사건」인가

- **퍼지는 것:** 주민끼리 공개 장소에서 한 일 — 카드의 「혼자·둘이」 해결, 쌍 장면의 결과, 새 차(둘이로 정해진 것 — 혼자 길은 보류라 새 차가 생기지 않는다), 계절의 일(오늘의 잎·밤꽃).
- **퍼지지 않는 것:** 플레이어가 들어간 모든 일(카드의 「나와 함께」, 찻집 주문, 대화 장면, 첫 하루의 장면들), 플레이어의 집·자리·습관, 학습 기록, 주민의 몸 이야기(손목·졸음은 본인이 마음 한 줄로 말할 뿐이다). 정본의 「주민끼리 내 이야기를 옮기는 연출은 처음에는 두지 않는다」(마을:472)와 「건강 … 기억하지 않는다」(마을:122)를 그대로 따른다.
- 물건과 차림표 같은 **세계 상태**는 누구나 볼 수 있다. 플레이어와 함께 정한 새 차라도, 그 뒤 찻집에 간 주민은 차림표를 보고 「새 차가 있네요」라고 안다(상태를 본 것). 누가 맛을 봤는지는 모른다.

### 9-3. 퍼지는 길

세 길 모두 **`public: true`인 사건만** 대상이다(§14-2 사건의 `public`). 플레이어가 든 사건은 그 사건의 당사자 주민의 지식에만 `private`로 남고, 같은 장소에 있던 다른 주민도 목격으로 알지 않는다(G6).

1. **목격:** 공개 사건이 확정되는 순간 같은 장소에 있던 주민 → `direct`(장소 단위로 판정, NPC:340).
2. **쌍 만남:** 쌍 장면·이야기가 끝날 때 각자 상대가 모르는 공개 사건 가운데 가장 최근 것 하나를 전한다 → `heard(from)`. 주민당 생활일 2건까지(R7). 상대가 그 사건의 당사자면 전하지 않는다.
3. **마을 소식:** 생활일이 바뀔 때(내 시각 05:00) 지난 생활일의 공개 사건 가운데 소식 ○인 것을 2건까지(눈에 보이는 흔적 > 새 차 > 합의 순) → 모든 주민 `broadcast`. 플레이어는 집 문 앞의 쪽지(화면 글이고 3D 모형이 아니다)와 수첩에서 읽는다. 쪽지에는 최근 셋만 **날짜 없이** 보이고(날짜로 비운 기간을 셈하게 하지 않는다, G3) 나머지는 수첩으로 접힌다. 이장님 방송은 이장님 배역과 목소리가 정해진 뒤로 미룬다.

주민마다 아는 공개 사건은 최근 16건만 들고 있다. 오래된 것은 사건 기록(§14-2)에만 남는다.

### 9-4. 본 것과 들은 것을 가르는 말

판은 다리 사다리를 따른다(§13-1). 간접 인용(`-대요`·`-다고 해요`)은 L3부터라, L1·L2는 작은 그림(눈 = 본 것, 귀 = 들은 것, 쪽지 = 마을 소식)과 연결 하나로 출처를 가른다.

| 앎 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|
| 본 것 | 「공방 주인이 받침을 고쳤어요.」 + 눈 그림 | 「제가 봤는데, 공방 주인이 받침을 고쳤어요.」 | 「공방 주인이 받침을 만지더니 이제 안 흔들려요. 제가 옆에서 봤어요.」 | 「아까 보니까 공방 주인이 받침을 새로 맞추고 있더라고요. 잔을 여러 개 올려도 이제는 기울지 않을 텐데요.」 |
| 들은 것 | 「공방 주인이 받침을 고쳤어요.」 + 귀 그림 | 「공방 주인한테 들었는데, 받침을 고쳤어요.」 | 「공방 주인 말로는 받침을 새로 맞췄대요. 이제 안 흔들린대요.」 | 「공방 주인이 받침을 새로 맞췄다고 하더라고요. 직접 보지는 못했지만, 이제 쟁반이 기울지는 않을 거예요.」 |
| 마을 소식 | 「찻집에 새 차가 있어요.」 + 쪽지 그림 | 「소식에서 봤는데, 찻집에 새 차가 있어요.」 | 「마을 소식을 보니까 찻집에 새 차가 나왔대요.」 | 「마을 소식에 찻집 새 차 이야기가 있더라고요. 맛은 아직 못 봤지만, 향이 좋다고 하던데요.」 |

- L3부터의 간접 인용은 들은 말을 생활에서 읽는 자리다(마을 §10 심부름의 간접 인용과 같은 줄기).
- 이 말은 플레이어가 그 주민에게 말을 걸었을 때 인사 변형으로만 나온다. 먼저 말 걸기 예산을 쓰지 않고, 같은 사건은 주민마다 한 번만 말한다.

## 10. 부재 따라잡기와 접속 시간대 습관

### 10-1. 결산 — 돌아온 순간 한 번

```text
settle(세계 W, 지금 now):                       ← §14-4의 게으른 결산과 같은 함수
  시작 = W.결산 시각
  now − 시작 > 7일이면:
      시작 = now − 7일
      주민 상태를 생활일 시작 기본값(기운 80 · 할 일 1 · 어울림 60)으로 맞춘다
      ← 7일보다 앞의 날은 계산하지도 쌓지도 않는다(R9)
  시작 → now의 구간마다:
      계획(§6-4) → 조각 결과(상태·마모) → 카드 계기와 해결(「나와 함께」 없음)
      → 쌍 장면 → 목격·전해 듣기 → 생활일이 바뀌면 마을 소식
  남기는 것: 물건 상태·흔적, 마모, 카드, 쌍, 주민 지식, 마을 소식, 습관 — 결과만
  남기지 않는 것: 조각마다의 걷기·자세(언제든 다시 계산할 수 있다)
```

- 계산량은 7일 × 4구간 × 세 주민, 구간마다 조각 20~40개다. 한 번에 몇 ms로 예상하고 §15-4에서 잰다. 부재 동안 서버는 주민을 돌리지 않는다.
- 부재 중에는 「나와 함께」 길이 없다. 플레이어의 미완 선택과 수락한 개인 이야기는 멈춰 있다(`player-decision`, NPC:331). 감사·부탁·「기다렸다」를 만들지 않는다(NPC:342~344).

### 10-2. 「그동안 달라진 것」

- **언제:** 새 방문이 시작될 때(30분 넘게 비운 뒤, `presence.mjs:4`) 결산이 남긴 사건이 있으면. 없으면 아무것도 띄우지 않는다. 「아무 일도 없었어요」도 쓰지 않는다.
- **몇 줄:** 1~3줄(점검:74·206), 주민 한 명당 한 줄. 첫 줄 하나를 크게 보이고 나머지는 열어 보는 목록이다(행동:181 「지금 중요한 결과 하나와 선택해서 보는 목록」).
- **고르는 순서:** ① 지금 화면에 흔적이 남은 일(받침·관찰판·오늘의 차·새 차) ② 플레이어가 만든 자리를 주민이 쓴 일(습관) ③ 쌍의 의견 차이가 한 걸음 풀린 일. 같은 순위면 최근 것.
- **꼴:** 결과를 지금 상태로 말한다 — 「공방 주인이 찻집 쟁반 받침을 새로 맞춰 두었어요.」 「연구원 관찰판에 오늘의 잎이 걸려 있어요.」 「내가 만든 정원 자리에서 공방 주인이 쉬어 갔어요.」
- **금지 말:** 「며칠」「오랜만」「동안」「만에」「그사이」「기다리」「보고 싶」「왜 안」「이제야」「덕분에」. 판의 제목 「그동안 달라진 것」은 정해진 화면 글이고, 줄 안에는 기간 말을 쓰지 않는다. 같은 목록을 원고 검사기(§16-3)와 원칙 시험(§15-2)이 쓴다.

### 10-3. 접속 시간대 습관 — 마을 안 신호

다리 설계와 맞춰 Atlas 이해 항목(trait)으로 옮기지 않고 마을 원장 안의 신호로 둔다(다리 §10-5). 이해 항목에는 학습자에게 설명할 수 있고 실제 학습 도움을 바꾸는 정보만 올리는데, 이 신호는 마을의 자리만 채운다. 마을 §8의 「아틀라스 §4-2의 `trait`」는 이 뜻으로 읽는다(마을:524의 10-22 표시).

- **기록:** 최근 30생활일 동안 생활일마다 「그날 첫 방문이 시작된 구간」 하나만 둔다. 시각·날짜 원문이 없고, 30칸 고리라 크기가 고정이다(G7).
- **판정:** 한 구간이 3번 이상이고 전체의 60% 이상이면 그 구간이 습관이다. Atlas 성향 규칙(근거 3 이상부터 사용, 30일 유효, 아틀라스:217~219)과 같은 값이다.
- **끄기:** 수첩 설정에 한 줄 — 「내가 자주 오는 때에 맞춰 마을 자리를 채워요」 · 끄기. 끄면 그 자리에서 고리를 지우고 더 쌓지 않으며(`habits.visitBandsOff: true`), 다음 구간부터 기본 일과로 돌아간다. 다시 켜면 빈 고리에서 새로 센다.
- **쓰임:** 그 구간의 자리를 더 채운다. 밤이면 공방 주인이 23:00까지 밤 깎기, 연구원이 02:00까지 밤 관찰, 밤 찻집 가중치 ×1.5(마을:524 「밤의 자리가 더 채워진다」). 아침이면 연구원이 06:30에 일어나 이슬을 본다. 낮·저녁은 이미 셋이 있어 바꾸지 않는다.
- **하지 않는 것:** 주민 대사에 드러내지 않는다(「늘 밤에 오네요」 없음). 학습·관계·보상에 쓰지 않는다. 늘어난 일과는 주민 기운을 깎지 않는다(G4).

## 11. 찻집 주문 손맛

### 11-1. 무엇이 재미이고, 지금과 무엇이 다른가

Steam 전수 조사에서 생활형 전체 최고 평가를 받은 묶음은 **손님 말을 듣고 취향대로 만들어 내는 반복**이다(Creature Kitchen 하한 99.48%, Papa's Freezeria 99.09%, Steam:48·51·60). 생활 재미 설계의 손맛 정의도 「두 요청을 기억하고 역할을 나눠 매끄럽게 제공하기」다(생활재미:123).

| 지금(LS02.2, `bazaar.mjs`) | 이 조각 |
|---|---|
| 차/물 × 단맛 없음/있음. 온도 축이 없다(bazaar:89·231) | 차 셋 × 온도 둘 × 단맛 셋 |
| 정답이 하나(bazaar:17·22) | 요청한 축만 맞으면 모두 정답. 일부러 틀린 답을 두지 않는다(10대:393) |
| 요청표가 탁자에 계속 놓인다(bazaar:309) | 요청을 다 들으면 말풍선이 접힌다. 언제든 다시 열 수 있고, 다시 열면 「다시 말해 주세요」로 기록된다. 결과는 같다(10대:16, 관계:241) |
| 미리보기 → 확정 | 손으로 만든다 — 잔 → 차 → 꿀 → 「다 됐어요」 → 들고 가서 낸다. 미리보기·확정은 초급·움직임 줄이기의 대안으로 남는다 |
| 회차 한 번(bazaar:186) | 찻집이 열린 구간이면 언제든 「다음 손님」. 반복 생활이고 새 이야기로 세지 않는다(G8) |

이 조각은 10대:19의 「새 패널·미니게임 조작을 카드마다 늘리지 않는다」를 찻집 주문(T04)에 한해 바꾼다. 그 규칙은 10-08 설계안이고 사용자 확정이 아니며, 점검 §3의 처방이 이 변경을 제안했다.

### 11-2. 음료와 요청

- **축 셋:** 차(보리차 · 유자차 · 「오늘의 차」 — 카드 C3가 바꾸고, C4 뒤에는 새 차가 더해진다), 온도(따뜻하게 · 차갑게), 단맛(안 달게 = 꿀 0 · 조금 달게 = 1 · 달게 = 2).
- **요청은 꼭 맞춰야 하는 축만 적는다.** 나머지 축은 무엇이든 정답이다. 「따뜻한 유자차 주세요」 → 차 = 유자차, 온도 = 따뜻하게, 단맛 = 아무것.
- 두 손님의 요청은 적어도 한 축이 다르다. 요청은 시드(생활일·구간·주문 번호)로 정해서, 같은 주문을 두 기기에서 열어도 같다.
- **수준별 요청 틀** 〔다리 — 사다리는 §13-1〕:

| 수준 | 축 | 예 |
|---|---|---|
| L1 | 하나(한 문장, 이음 없음) | 「유자차 주세요.」 「따뜻한 거 주세요.」 「안 단 거 주세요.」 |
| L2 | 둘(연결 하나) | 「추우니까 따뜻한 유자차 주세요.」 「보리차가 있으면 차갑게 주세요.」 「저도 같은 걸로 하는데, 차갑게 주세요.」 |
| L3 | 셋(두세 문장, 간접 인용·3급 문형) | 「친구가 여기 유자차가 맛있다고 해서요. 따뜻하게, 꿀은 조금만 주세요.」 「아까 단 걸 많이 먹는 바람에요. 보리차로, 안 달게 주세요.」 |
| L4 | 셋(서너 문장, 양보·추측) | 「유자차가 좋기는 한데, 너무 달면 향이 덜 날 텐데요. 꿀은 조금만 넣어 주세요. 따뜻하게요.」 「저도 앞사람이랑 같은 걸로 할게요. 따뜻한 게 좋기는 하지만 오늘은 더워서요. 차갑게 부탁해요.」 |

「같은 걸로」 같은 가리키기는 L2부터 쓴다(다리 세션 10-22 답: 「같은 걸로」·「아까 말한」·`-보다`·`-는 것 같아요`는 L2). 앞 손님의 요청을 기억해야 풀리는 자리라, 기억하는 손맛이 읽기 과제와 겹친다. 「같은 걸로」는 앞 손님이 정한 축을 그대로 받고, 뒤에 붙은 말이 그 가운데 한 축을 바꾼다. L1에서도 기억은 쓴다 — 접힌 요청 쪽지를 보지 않고 만들면 된다.

판이 높아도 학습 기록은 TOPIK I 능력(`ko.reading.detail`·`ko.reading.negation`)에만 남는다. L1 판은 난도 1, L2·L3·L4 판은 난도 2다(§13-2). L3·L4 판의 찻집 주문은 생활 맥락에서 말을 넓혀 쓰는 연습이고, TOPIK II 근거는 시험 꼴 문항에서만 쌓는다.

### 11-3. 상태 기계

`arriving → listening(A) → listening(B) → making ⇄ serving → reacting → seated → done`. 어느 때나 `ownerTakes`(「주인이 맡아요」)와 `stopped`(「그만할래요」 — 주인이 마저 낸다)로 끝낼 수 있다.

| 상태 | 화면 | 다음 |
|---|---|---|
| arriving | 손님 둘이 들어와 한 명은 서빙대 앞, 한 명은 뒤의 기다리는 자리에 선다. 두 요청을 한꺼번에 띄우지 않는다(10대:477) | 손님 A가 말한다 |
| listening | 손님 말풍선(수준 판본)과 되묻기 세 단추. 다 읽으면 말풍선이 손님 머리 위 작은 쪽지로 접힌다 | B 차례 → making |
| making | 서빙대 앞 손 조작(11-4). 만든 잔은 쟁반에 놓인다. 순서는 자유 | 잔을 들고 손님에게 → serving |
| serving | 손님 앞에서 E를 누르거나 손님을 누른다 | reacting |
| reacting | 요청 축이 다 맞으면 「딱 좋아요」와 함께 앉을 자리로 간다 — 플레이어가 만든 자리가 있으면 그 자리가 먼저. 하나라도 다르면 다른 축 하나만 부드럽게 말한다(「조금 더 따뜻하면 좋겠어요」). 잔은 쟁반으로 돌아오고 아무것도 소비되지 않는다 | 다 맞으면 seated, 아니면 making |
| seated → done | 두 손님이 앉아 마신다. 찻집 주인 할 일 −2, 어울림 +15(플레이어와 함께한 어울림은 구간당 한 번까지, §7-1) | 「다음 손님」 또는 끝 |

한 손님에게 두 번 다시 만들어도 맞지 않으면 찻집 주인이 「제가 해 볼까요?」를 한 번 묻는다. 받아들이면 주인이 만들어 낸다. 벌점·재료 소모·시간 제한이 없다(생활재미:118·121, 10대:14·129).

주문을 열 때 찻집 주인이 다른 조각(온실의 잎 따기 등)을 하고 있으면, 그 조각을 끊고 찻집으로 돌아온다(예약, §6-4). 플레이어가 오래 기다리지 않게 하려는 것이고(G9), 끊긴 조각은 몰아서 다시 하지 않는다.

### 11-4. 손으로 만들기

| 조작 | 터치 | 키보드 | 게임패드 |
|---|---|---|---|
| 잔 고르기(따뜻한 잔/찬 잔) | 잔을 눌러 쟁반으로 | 1·2 | 왼쪽 묶음 |
| 차 고르기(통 셋) | 통을 잔으로 끌거나 누르기 | 3·4·5 | 오른쪽 묶음 |
| 꿀 | 숟가락을 0~2번 누른다. 누를 때마다 잔 위 숟가락 그림이 는다 | H | Y |
| 다 됐어요 | 단추 | Enter | A |
| 다시 만들기 | 잔 비우기 단추 | Backspace | B |

- **미리보기·확정 대안**(설정 「간단히 만들기」 또는 움직임 줄이기): 손님마다 미리 만든 잔 그림 2~3개 가운데 하나를 고르고 「이대로 낼게요」를 누른다. 결과와 반응이 같고, 기록에는 `mode: preview`만 남는다.
- 3D에 새 미술을 더하지 않는다. 잔·쟁반은 지금 소품이고, 차·꿀 조작은 화면 아래 손 조작 판(지금 화면 문법의 2D)에서 그린다.

### 11-5. 단골의 「늘 마시던 걸로요」

- 단골 `visitor-tea-reader`는 첫 만남 뒤 주문 넷에 하나꼴로 손님 A로 온다. 처음 받은 음료를 「늘 마시던 것」으로 기억한다(10대:126 「오늘도 같은 걸로 할까요?」, 상태 `stablePreference`).
- 다음부터 L2 이상이면 「늘 마시던 걸로요.」라고만 한다. 접힌 쪽지를 열면 처음 요청이 보인다(「다시 말해 주세요」로 기록). L1이면 차 이름을 다시 말한다.
- 이것은 손님 자신의 취향이고 플레이어에 대한 기억이 아니다. 다른 주민에게 퍼지지 않는다(G6).

### 11-6. 결과가 남는 곳

- **세계:** 그 방문 동안 앉은 손님, 찻집 주인의 할 일·어울림, 단골의 `stablePreference`. 새 차·오늘의 차가 다음 주문에 나온다.
- **플레이어와의 사건:** 「찻집 일을 같이 했다」 — 찻집 주인만 안다. 같은 생활일에 여러 번 해도 사건은 하나로 묶는다. 반복으로 관계를 올리지 않는다(NPC:138).
- **학습 기록:** 요청 하나가 과제 하나다(§13-2). 관계·보상은 도움 사용과 상관없이 같다.
- **마모:** 플레이어가 쓴 잔·쟁반은 마모를 올리지 않는다(§8-2).

## 12. 되묻기 세 단추가 있는 대화 한 장면 — 「새 차 맛 좀 봐 줄래요?」

### 12-1. 장면

- 카드 C4의 「나와 함께」 길이다. 주민 설계 §7에서 확정된 기복 「나에게 기댄다 — 새 메뉴의 맛을 봐 달라」(주민:124)를 찻집 주인에게 옮겼다. 찻집 주인이 먼저 제안하거나(먼저 말 걸기 예산), 차림표 앞에서 서성이는 주인에게 플레이어가 먼저 말을 건다(예산을 쓰지 않음).
- 세 차례다(마을:447의 3~7차례 가운데 가장 짧은 꼴). 보기는 모두 옳은 한국어이고 뜻이 다르다(마을:456). 고른 답에 따라 새 차의 단맛이 정해지고, 다음 구간부터 손님이 그 차를 주문한다.
- 차례마다 「다시 말해 주세요」「천천히 말해 주세요」「무슨 뜻이에요?」와 「그만할래요」가 있다(마을:466, 대화:37).

### 12-2. 원고 — C는 찻집 주인, P는 플레이어의 보기

판(L1~L4)은 다리 설계의 수준 사다리(§13-1)를 따른다. 무료 첫 챕터의 대화 장면이라 네 판을 다 두고, 판끼리 차례 수와 결과 키가 같다(다리 §3-4·§10-1).

**T1 — 제안**

| 판 | C | P |
|---|---|---|
| L1 | 새 차 마셔 볼래요? | [네, 좋아요] [향 먼저요] |
| L2 | 새 차를 만들었는데 맛 좀 봐 줄래요? | [네, 마셔 볼게요] [향부터 맡아 볼게요] |
| L3 | 요즘 새 차를 만들고 있거든요. 손님한테 내기 전에 맛 좀 봐 줄래요? | [네, 한번 마셔 볼게요] [먼저 향부터 맡아 볼게요] |
| L4 | 손님들한테 내놓기 전에 누가 먼저 맛을 봐 주면 좋겠다 싶었어요. 제 입에는 괜찮은데, 남이 마시면 또 다를 테니까요. 한 잔 드셔 볼래요? | [좋아요, 한 잔 마셔 볼게요] [마시기 전에 향부터 맡아 봐도 돼요?] |

「향 먼저」를 고르면 향 맡는 몸짓과 C의 짧은 반응(L1 「향 먼저, 좋아요.」 · L2 「향부터 맡으면 더 좋아요.」 · L3 「향부터 맡는 손님은 처음이에요. 좋네요.」 · L4 「향부터 맡아 주는 손님은 드문데, 그렇게 마셔 주면 고맙죠.」)이 있고 T2로 간다. 이 반응은 차례로 세지 않는다.

**T2 — 맛 묻기**

| 판 | C | P |
|---|---|---|
| L1 | 너무 달아요? | [달아요] [좋아요] [향이 좋아요] |
| L2 | 꿀을 많이 넣었는데 너무 달아요? | [조금 달아요] [딱 좋아요] [향이 좋아요] |
| L3 | 맛이 어때요? 꿀을 좀 많이 넣은 것 같기도 해서요. | [조금 단 것 같아요] [이대로 딱 좋아요] [향이 정말 좋아요] |

| 갈래 | 판 | C | P |

- ㄱ의 「제가 넣어」는 §11-4의 꿀 숟가락 조작 하나로 이어지고, 넣은 양이 새 차의 단맛이 된다. ㄴ의 「손님한테」는 바로 다음 찻집 주문의 손님 A가 새 차를 주문하게 한다.
- 「그만할래요」의 답은 차례마다 같다 — L1 「네, 또 와요.」 · L2 「그래요, 또 와요.」 · L3 「괜찮아요. 생각나면 또 와요.」 · L4 「괜찮아요. 언제든 생각나면 들러요.」
- 다리 설계의 알려 주기 장면 ② 「무슨 차 좋아해요?」(다리 §6)는 이 장면에 넣지 않는다. 취향 기억은 이웃 수첩의 「잊어 주세요」와 함께 있어야 하는데, 수첩은 이 조각에 없다(§18).

### 12-3. 되묻기 세 단추와 「그만할래요」

장면 안에서 판을 내리는 것은 본인이 누른 되묻기뿐이다. 진행 중인 장면을 자동 개인화로 바꾸지 않는다(대화:356, 다리 §3-3·§10-3 `onHelp`).

| 단추 | 하는 일 | 습관 요약의 칸(§13-2) |
|---|---|---|
| 다시 말해 주세요 | 같은 줄을 다시 띄우고 핵심 낱말에 밑줄을 긋는다. 같은 줄에서 두 번 누르면 세 번째로 보이는 줄은 한 단계 낮은 판이다. 목소리가 정해지면 다시 듣기 | `repeat` |
| 천천히 말해 주세요 | 수준은 그대로 두고, 같은 줄을 마디로 끊어 하나씩 띄운다. 목소리가 정해지면 느리게 듣기. 단추 글은 실제로 쓰는 말이라 바꾸지 않는다 | `slower` |
| 무슨 뜻이에요? | 그 줄을 곧바로 한 단계 낮은 판으로 다시 보인다(같은 차례 번호의 아래 판에서 찾는다). L1에서는 그림 카드(잔·꿀 숟가락·향)와 짧게 나눈 줄. 다음 차례는 원래 판으로 돌아간다 | `meaning` |
| 그만할래요 | 「그래요, 또 와요.」(L2) 뒤 장면을 닫는다. 막힘으로 세지 않는다. 카드는 「하던 생활」로 남아 언제든 이어 할 수 있고, 주인은 자기 일을 한다(NPC:212) | 장면 끝 기록 |

- 같은 장면에서 낮은 판으로 다시 보인 일이 두 번째가 되면(「무슨 뜻이에요?」 두 번, 또는 그것과 같은 줄 「다시」 두 번의 합) 남은 차례도 낮은 판으로 이어 간다. 이것이 「내린 장면」이다. 다음 장면은 다시 안정 수준으로 시작한다.
- 장면 결과는 「막힘 없는 장면」·「도움 한 번 장면」·「내린 장면」 셋 가운데 하나이고, 장면이 끝날 때 `closeScene`이 사다리 상태를 고친다(§13-1). 계정 학습 기록은 바뀌지 않는다.
- 되묻기 사다리(대화:185~197)는 다섯 걸음이지만, 이 장면은 고르기 장면이라 세 단추만 쓴다. 보기가 이미 있으므로 「보기 볼래요」는 뺀다.
- 버튼 목록이 문서마다 셋으로 갈려 있다(마을:466 / 원고 `[다시 듣기][뜻 보기][보기로 답하기][나가기]` / talk `repeat·slower·meaning·choices·stop`, D2b P2-5). 이 조각은 마을:466의 세 문장을 쓴다. 단추 글 자체가 배울 말이기 때문이다.

### 12-4. 결과

- 새 차의 단맛: ㄱ → 조금 달게(또는 플레이어가 직접 넣은 꿀), ㄴ → 달게, ㄷ → 달게 + 찻집 주인의 `with-player-glad` 한 번.
- 차림표에 새 차가 오른다(흔적). 플레이어와 함께 정한 일이라 마을 소식에는 오르지 않는다(G6). 그 뒤 찻집에 간 주민은 차림표를 보고 새 차가 있다는 것만 안다(§9-2).
- 이 장면은 학습 근거를 만들지 않는다. 보기가 모두 옳은 고르기라서다. 장면이 끝날 때 한 번 습관 요약을 마을 원장에 남긴다(대화:350, 다리 §10-4, §13-2).

## 13. 계정 학습 기록과 주고받는 어댑터 하나

`town/learning-adapter.mjs` 하나가 들어오는 쪽(어느 판으로 보일까)과 나가는 쪽(학습 사건·습관 요약 보내기)을 맡는다. 수준 사다리·판정 규칙·어댑터 계약은 학습·개인화 다리 설계(`docs/디자인/싱크타운_학습개인화다리_설계_20261022.md`, 10-22 초안, 그쪽 Fable 검수 전)의 §3·§4-3·§10이 정한다. 이 절의 〔다리〕 값은 그 초안을 그대로 옮긴 것이다. 그쪽이 바뀌면 같이 고친다(§18).

### 13-1. 들어오는 것 — 이 장면을 어느 판으로 보일까 〔다리〕

- **입력:** WORLD 코치(`world-home`)의 학습 요약(TOPIK I+II 합친 지도, skill마다 `levels[난도].formats[응답 꼴].status` — 읽기만 한다), 사다리 상태, 본인 설정(「늘 쉬운 말로」·자리 고정), 오늘 컨디션.
- **수준 사다리 L1~L4는 말의 부담을 잰다.** 급수 판정이 아니고 목표 급도 입력이 아니다(다리 §3-1).

| 수준 | 한 차례의 말 | 연결·문형 | WORLD 문항 난도와의 짝 |
|---|---|---|---|
| L1 | 한 말풍선에 짧은 문장 하나, 뜻 하나, 5어절 안 | 이음 없음, 부정은 「안」 | TOPIK I 난도 1 |
| L2 | 이유·조건·순서 하나를 붙인다, 8어절 안 | `-아서`·`-(으)니까`·`-(으)면`·`-고 나서`·`-는데` 가운데 하나. 「같은 걸로」·「아까 말한」·`-보다`·`-는 것 같아요`도 이 단계(다리 세션 10-22 답) | TOPIK I 난도 2 |
| L3 | 두세 문장, 문장마다 10어절 안 | 간접 인용(`-다고 하다`·`-대요`), `-는 바람에`, `-더니` 같은 3급 문형 | TOPIK II 난도 1 |
| L4 | 서너 문장, 문장마다 14어절 안 | 양보(`-기는 하지만`·`-더라도`), 추측(`-(으)ㄹ 텐데`), 설명·의견 같은 4급 문형 | TOPIK II 난도 2 |

- **자리:** 읽기·듣기 두 자리를 따로 둔다. 이 조각은 글만 있어 읽기 자리만 쓴다. 말하기·쓰기 자리는 첫 판에 없다.
- **사다리 상태**는 마을 원장(세계 저장, §14-2)에 둔다. 학습 기록이 아니고, 주민 대사의 조건으로 쓰지 않는다(다리 §10-2).

  ```json
  "languageLadder": { "rule": "town-ladder-r1",
    "reading": { "stable": "L2", "source": "placement", "easedStreak": 0, "smoothStreak": 3,
                 "lastOffer": null, "fixed": false, "at": "…" } }
  ```

- **첫 수준(배치, 다리 §4-3):** 「내 위치」에는 급수가 없으므로, 자리마다 Trail의 첫 답(처음 보는 계열, 진단 포함)으로 고른다 — L4는 L3 조건에 더해 TOPIK II 난도 2에서 3개 이상 2/3, L3은 그 자리의 TOPIK II에서 3개 이상 2/3, L2는 TOPIK I 난도 2에서 3개 이상 2/3 또는 그 자리의 TOPIK I에서 6개 이상 5/6, 나머지는 L1. 첫 대화 전에 내 마스코트가 한 번 「처음 이야기는 이 말로 해 볼까요?」[이대로][더 쉬운 말로]를 묻고(L1이면 묻지 않음), 고른 것이 안정 수준이 된다. `evidenceComplete`가 아니면 L1에서 시작하고 메인 근거로 넓히기를 제안하지 않는다(다리 세션 10-22 답 — 다리 문서에 아직 없으면 그쪽에 맞춘다). 이미 중급인 사람이 1급 장면부터 지나가지 않게 하는 것이 이 배치의 목적이다(점검 §5).
- **장면 안 내림(`onHelp`):** §12-3. 본인이 누른 되묻기에만 답한다.
- **장면 뒤(`closeScene`):** 결과는 「막힘 없는 장면」(낮은 판으로 다시 보인 일 없음)·「도움 한 번 장면」·「내린 장면」 셋이다. 같은 자리의 장면끼리만 센다 — 막힘 없음이면 `smoothStreak` +1·`easedStreak` 0, 도움 한 번이면 둘 다 0, 내린 장면이면 `easedStreak` +1·`smoothStreak` 0. `easedStreak`가 2가 되면 안정 수준을 한 단계 내리고(L1 아래로는 없음, 알림 없음) 0으로 돌린다. 안정 수준이 바뀌면(내림·넓히기 수락·본인 선택) 두 값을 모두 0으로 돌린다(다리 계약).
- **넓히기는 제안만:** 다음 장면 경계에서 내 마스코트가 「말을 조금 더 넓혀 볼까요?」라고 묻는다(주민이 묻지 않는다). 조건은 둘 가운데 하나 — (가) WORLD 요약에서 지금 L 띠의 서로 다른 능력 두 칸이 같은 응답 꼴로 `recent-independent`(대화 고르기는 `single-choice`, 찻집 주문은 `cup-compose`) (나) 같은 L에서 막힘 없는 장면 다섯 번 연속. 찻집 주문 장면은 L3부터 (나)만 쓴다 — 찻집 주문 기록이 TOPIK I 능력에서 그치기 때문이다(§13-2). 넓힌 수준은 그 자리(읽기) 전체에 적용한다. 본인이 고정했을 때·오늘 컨디션이 낮을 때·거절한 지 7일이 안 됐고 새 근거가 없을 때·그날 이미 물었을 때·이미 L4일 때는 묻지 않는다.
- **입력이 아닌 것:** 관계 단계·호감, 생활 완료·코인, 접속 일수·시간, 목표 급, 결제(다리 §3-3).
- **선택기**는 기기의 결정적 함수이고 시드를 쓰지 않는다 — `pickSceneLevel({ channel, ladder, summary, settings, today, scene }) → { level, offer, why }`, `onHelp(…) → { lineLevel, sceneLevel }`, `closeScene(…) → ladder'`(다리 §10-3). 진행 중인 장면에는 새 요약을 적용하지 않는다(구현:943).
- **찻집 주문도 장면이다.** 두 손님의 요청을 읽는 한 장면으로 보고 `onHelp`·`closeScene`을 똑같이 쓴다.
- **장면이 아닌 한 줄**(마음 한 줄·전해 듣기·마을 소식·인사·일과 한 줄)은 읽기 자리의 안정 수준 판으로 보인다. 그 줄에서 「무슨 뜻이에요?」를 누르면 그 줄만 한 단계 아래 판과 그림으로 다시 보이고, 사다리 상태는 바꾸지 않는다. 이것은 이 조각이 다리 계약을 한 줄 글에 적용한 방식이다(다리 세션에 알림).
- 수준은 **글의 판만** 바꾼다. 생활 결과(손님 반응·관계·카드·새 차)는 어느 판이든 같다(다리 §3-4).

### 13-2. 나가는 것 — 찻집 주문은 기존 `practice.*`, 대화 장면은 습관 요약만 〔다리〕

| 타운의 일 | 어디로 | 채우는 값 |
|---|---|---|
| 찻집 주문의 요청 하나를 보임 | 계정 학습 기록 — Trail `practice.presented` | decisionId·taskId·taskVersion·itemKey·firstExposure는 WORLD 연습 사건과 같은 꼴(itemKey `synk-town.tea.<frameId>.<valueKey>.v1`). conceptIds에는 요청 틀의 문법 항목과 **반드시 skillId를 넣는다**(trail:83). measure는 Trail 검사기 여섯 칸 전부(trail:81~83) — skillId **`ko.reading.detail`만**(요청에 부정이 있으면 `ko.reading.negation`), modality `reading`, difficulty — **L1 판 1, L2·L3·L4 판 2**, familyKey `synk-town.tea.<frameId>.v1`, audioRequired false, confounded(요청 말풍선에 정답을 가리키는 그림이 함께 있으면 true) — 그리고 responseFormat `cup-compose` |

| 찻집 주문의 장면 결과 | 마을 원장 | 위와 같은 습관 요약(`answerMode`는 `make` 또는 `preview`) — `closeScene`이 사다리 상태를 고친다 |

- **찻집 주문은 TOPIK I 능력에만 기록한다**(다리 계약, 그쪽 Fable 검수로 바뀐 값). L3·L4 판이라도 `ko2.*`에 넣지 않는다. Core는 능력마다 대표 상태를 응답 꼴을 가리지 않고 고르므로(learning:44~51), 찻집 주문이 `ko2.reading.detail`에 들어가면 TOPIK II 문항을 풀지 않은 사람의 「내 위치」 TOPIK II 칸이 「혼자 해냄」이 된다. TOPIK II 근거는 시험 꼴 문항에서만 쌓는다.
- `cup-compose`는 이미 `RESPONSE_FORMATS`에 있고(learning:5) `unassessed`·`skipped`는 Trail 판정 값에 있다. 새 필드·새 어휘를 더하지 않는다(구현:778 「현재 `practice.*`·`signal.observed`에 임의의 마을 필드를 추가」하지 않음).
- familyKey를 요청 「틀」 단위로 묶는다. 값만 바꾼 틀은 한 계열이라 여러 번 해도 독립 근거는 하나다(learning:13~16, TOPIK4:110 「같은 대본은 하나로」). TOPIK 문항의 family와 겹치지 않게 `synk-town.`을 앞에 붙인다.
- 독립 판정은 Trail 규칙 그대로다 — 도움 없이 첫 노출에서 맞힌 것만 독립이고(trail:134~142), 도움받은 성공은 「도움받은 수행」이다(마을:466).
- 생활 속 확인·집 책상에서 푸는, WORLD 문항 체계에 등록된 타운 맥락 문항은 WORLD 연습과 같은 기록 길을 쓴다(다리 §10-4). 이 조각에는 그런 문항이 없다.
- **보내는 때:** 서버가 명령과 같은 트랜잭션에서 사건을 확정하고 바깥 상자(outbox, §14-2)에 넣는다. 계정 학습 기록으로의 소비는 event ID로 멱등이다(구현:791). 습관 요약은 사건 갈래(§14-2)에 남는다.

### 13-3. 개인정보와 금지

- 이름·자유 입력 원문·주민 기억·생활 기억을 보내지 않는다(구현:785·787). 「찻집 일을 같이 했다」 같은 생활 사건을 학습 성공으로 바꾸지 않는다(구현:787).
- 관계·보상·세계 변화는 수준·도움 사용·맞고 틀림과 상관없이 같다(구현:1018, 10대:16). 손님의 즉시 반응(「딱 좋아요」·「조금 더 따뜻하면 좋겠어요」)은 과제의 피드백이고 생활 결과가 아니다(§11-3, 다리 계약과 같은 문장).
- 학습 기록을 주민에게 알리지 않고 주민 대사의 조건으로 쓰지 않는다(G6).

### 13-4. 다리 설계와 맞춘 것

10-22에 다리 세션과 값을 맞췄다. 이 조각이 처음 둔 가정(L1·L2 → 난도 1 같은 대응, 「내 위치」 급수로 첫 수준, 대화 장면도 `practice.*`로 보내기)은 다리 초안에 따라 위처럼 바꿨다.

1. 사다리 L1~L4의 정의·어절 상한·WORLD 난도 짝 — 다리 §3-1.
2. 첫 수준은 Trail 첫 답으로 자리마다 — 다리 §4-3.
3. 장면 안 내림·장면 뒤 내림·넓히기 제안 — 다리 §3-3·§10-3.
4. 찻집 주문의 `practice.*` 매핑과 검수 전 `unassessed`, 대화 장면의 습관 요약 — 다리 §10-4. 그쪽 Fable 검수로 찻집 주문은 TOPIK I 능력에만 기록하고(L3·L4도 `ko.*`, 난도 L1 = 1·그 밖 = 2), measure 여섯 칸을 모두 채우며, conceptIds에 skillId를 넣는 것으로 바뀌었다(§13-2). L3부터의 찻집 주문 넓히기는 타운 근거만 쓴다(§13-1).
5. 접속 시간대 습관은 Atlas 이해 항목이 아니라 타운 안 신호 — 다리 §10-5, 이 문서 §10-3.

이 조각이 다리 세션에 알린 적용 둘 — 장면이 아닌 한 줄은 그 줄만 내리고 사다리를 바꾸지 않는다(§13-1), 「무슨 차 좋아해요?」는 이웃 수첩이 생길 때 넣는다(§12-2). 다리 초안이 그쪽 검수로 바뀌면 이 절과 §10-3·§11-2·§12·§16을 같이 고친다.

### 14-3. 요청 네 가지의 비용

| 요청 | 하는 일 | 비용 |
|---|---|---|
| **맥박**(1초) | 임대만 읽고 쓴다(창·소유·fence·유효 플레이 누적 U). 세계를 읽지도 검증하지도 않는다. 응답은 `{fence, owner, serverNow}` 100바이트 안 | 기록 크기와 상관없이 일정. 마을 시간은 시계로 흐르므로 맥박이 세계를 밀 필요가 없다 |
| **경계 신호**(안전 경계마다, 20초에 한 번까지) | 기기가 같은 함수로 「지금 안전 경계다」(조각 경계 도착·장소에 들어섬·대화나 조작 창을 닫음·카드가 `triggered`가 됨)를 알 때 보낸다. 서버는 한 트랜잭션에서 임대의 U를 읽고 → 세계를 결산하고 → 먼저 말 걸기 후보를 예산·선호·fence·`contactKey`로 검사해 발급(`issued`)을 기록한다(NPC:208). 응답은 발급한 제안 하나 또는 없음 | 몇 분에 한 번. 세계 크기와 결산 상한에 묶인다 |
| **들어오기·읽기** | 세계 한 덩이를 읽어 결산하고, 바뀐 것이 있으면 세계를 쓰고 사건을 덧붙인다. 응답은 세계 요약과 「그동안 달라진 것」 | 세계 크기(내용 수)와 결산 상한(7일)에 묶인다 |
| **명령** | 세계를 잠가 읽고(예상 명령 판 비교) → 결산 → 명령 적용 → 세계 쓰기 + 사건 덧붙이기 + 바깥 상자, 한 트랜잭션(구현:791). 응답은 바뀐 부분 | 같은 이유로 일정 |

지금 C1 접점이 맥박의 `advanceLife` 안에서 발급되는 것(`life.mjs:143~157`, `core.mjs:186~198`)은 경계 신호 안으로 옮긴다. 예산·간격·조용히·같은 원인 한 번 같은 규칙은 그대로다.

- 검증은 명령이 건드린 것만 한다. 세계 전체의 불변식 검사도 크기가 내용 수에 묶여 일정하다. Trail 사실 전체를 요청마다 다시 읽지 않고, 대사 고르기에 필요한 사실은 주민 지식 고리와 사건 기록의 색인으로 찾는다.
- 기존 모듈(첫 하루·C1·가판)의 짧은 타이머(시범 2초·리허설 3초·준비 3초)는 맥박으로 밀지 않고 「시작한 U」 도장으로 바꾼다. 다음 명령이 `U − 시작 U`로 단계를 판정한다.

### 14-4. 게으른 결산과 두 기기 일치

- **판이 둘이다.** `cmdRev`는 플레이어 명령이 확정될 때만 하나 오르고, 명령의 예상 판 비교와 시드에 쓴다. `writeSeq`는 저장할 때마다 오르는 내부 순번이고 시드에 쓰지 않는다. 결산은 `cmdRev`를 올리지 않는다. 그래서 결산이 언제, 몇 번 일어났는지(=누가 언제 읽었는지)가 계획을 바꾸지 않는다.
- 세계는 「진행 중 구간」(`current`)을 갖는다 — 구간 시작 명령 판(`planCmdRev` = 그 구간이 시작되기 직전까지 확정된 마지막 명령의 `cmdRev`), 구간 시작 때 주민 상태, 그 구간의 예약. 이 셋과 시드로 그 구간의 조각이 모두 정해진다. 구간 시작 시각 뒤에 확정된 명령은 그 구간의 `planCmdRev`를 바꾸지 않는다.
- `settle(W, now)`: `current`의 구간 끝이 now 이전인 동안 그 구간을 마치고(조각 결과·카드·쌍·전해 듣기 반영), 다음 구간을 연다(`planCmdRev` = 그 시각까지의 `cmdRev`, 주민 상태 복사). 부재가 7일을 넘으면 §10-1대로 자른다.
- 플레이어 명령이 구간 중간에 오면 먼저 결산하고, 명령이 예약을 만들면 `current.reservations`에 넣는다. 구간을 마칠 때 예약 시간은 「함께한 일」 조각으로 바뀐다.
- 결산은 한 번에 하나 나눠서 하나 같아야 한다 — `settle(settle(W, t1), t2) = settle(W, t2)`. 시험으로 고정한다(§15-3).
- 기기는 서버 응답의 세계와 서버 시각 차이로 같은 함수를 돌려 지금 장면을 그린다. 두 기기가 같은 세계를 받으면 같은 그림이다. 기기 예측과 서버 결과가 다르면 안전한 순간에 서버 쪽으로 맞추고, 그 차이를 결정성 오류로 기록한다.
- 기기는 결과를 보내지 않고 명령만 보낸다. 서버가 자기 세계로 같은 함수를 돌리므로 기기를 조작해 결과를 만들 수 없다.

### 14-5. 크기 한도와 접기

- **세계:** 목표 64KB, 검사 상한 256KB. 넘으면 저장을 막지 않고 운영 경고를 낸다(내용 데이터 오류의 신호). 8MB 행 상한은 문제가 아니게 된다.
- **사건:** 30생활일이 지난 공개 사건은 주민 지식 고리에서 이미 빠졌으므로 생활일별 개수로 접는다. 플레이어와의 사건(기억·관계의 근거)은 지우지 않는다. 같은 일의 반복은 생활일당 하나로 묶으므로(§11-6) 이것도 내용 수에 묶인다.
- **기존 배열:** `day.emitted`·`day.history`·`life.history`·`life.contacts`·`bazaar.emitted`·`support.presentations`(지금 1만 한도)는 W2에서 최근 N개 + 종류별 개수로 접고, Trail 사건은 사건 갈래로 옮긴다.

### 14-6. 옮기는 법 — 덧붙이는 이관

- 새 갈래(임대·세계·사건·바깥 상자)는 새 저장 자리로 만든다. 지금의 한 덩어리 행은 건드리지 않고 읽기 전용으로 둔다. 처음 들어온 계정은 그 행에서 세계를 한 번 만들어 새 자리에 쓴다. 기존 데이터를 지우거나 덮지 않으므로 되돌릴 수 있다.
- 옛 행을 지우거나 바꾸는 정리는 따로 하는 운영 변경이고, 그때 유호님 확인을 받는다([운영 원칙](../AI_운영원칙.md#비용과-권한) 「기존 데이터를 지우거나 덮는 운영 변경」).
- 로컬 미리 보기 서버(`experiences/synk-town/server.mjs`)도 같은 네 갈래를 파일로 쓴다.

## 15. 시험과 인수

### 15-1. 결정적 시뮬레이션 — 30생활일 × 마을 씨앗 100

`tools/town-sim.mjs`가 마을 씨앗 100개 × 30생활일을 시간대 넷(UTC+9·+8·+7·−5)과 플레이어 모습 다섯(안 옴 / 매일 30분 무작위 구간 / 밤에만 / 7일 비우고 돌아옴 / 매일 와서 카드·주문을 다 받음)으로 돌리고 보고서를 `experiences/synk-town/qa/` 아래에 남긴다.

| 지표 | 기준 |
|---|---|
| 만날 수 있는 주민 수 | 05:30~23:30의 모든 분에 둘 이상(100%). 깊은 밤은 0 이상, 밤 습관 마을은 02:00까지 하나 이상 |

| 일과표 칸의 활동 수 | 셋 이상(데이터 검사) |

**가상 학습자(다리 계약, 다리 §9).** 플레이어 모습 다섯과 따로, 읽기 실력 r이 다른 가상 학습자 셋을 같은 30일 × 씨앗 100으로 돌려 수준 사다리를 잰다 — r = 1.2 / r = 3 / r = 1이면서 「무슨 뜻이에요?」 확률이 두 배인 사람. 판 L(L1 = 1 … L4 = 4)의 한 줄에서 「무슨 뜻이에요?」를 누를 확률은 L − r가 0 이하면 3%, 0~1이면 25%, 1을 넘으면 60%다. 같은 줄의 「다시」는 그 절반, 「그만할래요」는 장면마다 2%다. 넓히기 제안을 받아들일 확률은 (L+1) − r가 0 이하면 80%, 0~1이면 40%, 1을 넘으면 10%다. 잴 것은 넷이다 — 안정 수준이 r ± 0.5에 닿기까지 걸린 장면 수, r보다 1 넘게 높은 판으로 본 장면의 비율, 제안 거절 비율, 판이 없어 내려간 횟수. 사다리 값(두 번 이어지면 내림·다섯 장면·7일)은 이 결과로 다시 잰다.

### 15-2. 원칙 시험 — 「부재」와 「가만히 있음」은 주민에게 같다

- 같은 씨앗에서 ① 7일 비운 플레이어와 ② 그 7일 동안 날마다 낮 구간에 접속은 했지만 아무것도 하지 않고 모든 제안을 지나친 플레이어를 돌린다. ②는 집과 골목에만 머물고 찻집 주인과 같은 장소에 머물지 않는다(머물면 플레이어 몫인 첫 C4가 생겨 그 표시가 달라진다, §8-4). ①과 ② 모두 첫 방문은 이미 마친 뒤라 첫 C4는 둘 다 같은 상태에서 시작한다. 주민 상태·카드·쌍·지식·마을 소식이 바이트 단위로 같아야 한다. 부재가 주민에게 아무 영향을 주지 않는다는 증명이다(G3·G4). 이 비교가 성립하는 근거는 둘이다 — 카드 해결 시각이 플레이어 유무와 상관없이 주인의 다음 조각 경계이고(§8-3), 낮 구간의 습관은 일과를 바꾸지 않는다(§10-3). 먼저 말 걸기 원장(발급·지나침 기록)은 플레이어 쪽 기록이라 비교에서 뺀다.
- 습관의 효과는 따로 본다: 밤에 접속한 플레이어의 마을은 밤 조각(공방 밤 깎기·연구원 늦은 관찰)과 그 조각이 낳은 쌍 장면만 달라지고, 주민 상태의 나쁜 쪽 변화는 0이다.
- ③ 매일 온 플레이어와 ① 7일 비운 플레이어가 8일째 받는 대사·관계 단계·보상의 **서운함·벌점 차이가 0**이어야 한다(점검 §2-4 처방 10). 확인은 셋이다 — 대사 고르기 함수가 읽는 값에 부재 관련 값(마지막 방문·방문 수·비운 날 수)이 없음을 접근 추적으로 확인한다, ①이 받은 모든 줄이 금지 말 검사를 통과한다, 관계 단계·보상은 줄지 않는다(마을:117). 매일 온 사람이 함께한 일이 더 많아 생긴 좋은 차이(관계 단계·`with-player-glad`)는 벌점이 아니다.
- 상태 변화의 원인 기록에서 플레이어가 원인인 나쁜 쪽 변화가 0이다(G4).

### 15-3. 결정성 · 두 기기 · 결산 결합

- 같은 입력이면 같은 출력: `TZ=UTC`·`Asia/Seoul`·`America/Los_Angeles`, Node와 헤드리스 브라우저에서 시뮬레이션 결과의 해시가 같다.
- 결산 결합: t2 − t0 ≤ 7일이면 아무 t1(t0 < t1 < t2)에 대해 `settle(settle(W, t1), t2) = settle(W, t2)`. 7일을 넘는 부재는 §10-1의 자르기가 정의이고, 부재 중에는 요청이 없다는 것이 자르기의 전제다(다른 기기에서 읽었다면 그것은 부재가 아니다). 그래서 7일을 넘는 경우는 「한 번에」 결산의 결과만 시험한다.
- 읽는 때와 횟수: 같은 명령 흐름에 읽기·경계 신호를 서로 다른 때에 0번·1번·여러 번 끼워 넣어도 결산 결과가 같다(`cmdRev`만 시드에 들어가므로, §14-4).
- 두 기기: 무작위 명령 흐름을 기기 A가 보내고 기기 B가 읽은 뒤의 예측이 서버 결산과 같다.
- 시간대 바뀜: 오프셋을 바꿔도 이미 결산한 사건이 다시 생기지 않고 생활일 번호가 줄지 않는다.

### 15-6. 사람이 보는 인수

- **실물 휴대폰**(유호님 손, 이미 있는 같은 와이파이 중계 `experiences/synk-town/qa/blender-merged-20261018/phone-preview.mjs`): 기준 기기(갤럭시 S25급·아이폰 15급)와 중저가 안드로이드 한 대로 10분 걷기. 네 구간 각각과 비를 켠 상태에서 fps 중앙값·1% 낮은 값, 발열, 첫 화면까지 시간을 잰다. 처음 목표 〔초기값〕은 기준 기기 중앙값 45 이상·1% 낮은 값 30 이상, 중저가 중앙값 30 이상, 와이파이에서 첫 화면 8초 안이다. 처음 잰 값으로 기준을 다시 정한다.
- **참가자 3~5명 관찰**(유호님이 모집, `experiences/synk-town/qa/DAY-PLAYTEST.md` 양식): 운영 권한을 손으로 넣지 않도록 로컬 미리 보기 서버와 휴대폰 중계로 한다. 한 사람이 두 번 한다(첫날 15분, 하루 뒤 다른 구간에 15분). C4의 첫 회는 첫 방문에 찻집에서 생기므로(§8-4) 대화 장면도 첫날 볼 수 있다. 관찰을 빨리 하려고 로컬 미리 보기 서버에 시각을 앞당기는 스위치(`--clock +1d` 같은 꼴)와 카드를 바로 세우는 스위치(`--card C4`)를 W0에 둔다 — 운영에는 없다. 묻는 것 — 「내가 없을 때 주민이 무엇을 하던가요?」 「저 주민은 왜 거기 있었어요?」 「내가 고른 것이 무엇을 바꿨어요?」 「지금 몇 시쯤 같아요?」(빛 판정, §2-2) 「손님 주문을 기억해서 만든 게 어땠어요?」.
- **통과:** 참가자의 60% 이상이 주민 행동 하나를 이유와 함께 설명하고, 60% 이상이 다시 왔을 때 달라진 것을 스스로 짚고, 탓·재촉을 느꼈다는 사람이 0이다. 빛은 §2-2의 80% 기준으로 판정한다. 점검 §9는 6~8명을 권했으므로, 3~5명에서 기준을 넘지 못하면 사람을 늘려 다시 본다.

### 16-2. 같은 뜻을 수준별로 찍어 내는 틀

원고 ID는 `<주민>.<종류>.<열쇠>.<번호>` 한 꼴로 쓴다(마음은 `cafe-owner.mood.rain-wrist.1`, 카드 줄은 아래처럼). 검사기가 한 규칙으로 걸 수 있게 하려는 것이다.

```json
{ "id": "workshop-owner.card.C1-pair.1", "npc": "workshop-owner", "kind": "card-pair",
  "when": { "card": "C1", "path": "pair" }, "meaning": "받침으로 쟁반 수평을 맞춰 주겠다",
  "slots": [], "levels": {
    "L1": "여기 받침을 넣어요.",
    "L2": "얇은 받침을 넣으면 안 흔들려요.",
    "L3": "쟁반이 자꾸 기운다고 해서 와 봤어요. 얇은 받침을 하나 끼우면 안 흔들릴 거예요.",
    "L4": "쟁반이 기우는 건 바닥이 조금 패서 그래요. 얇은 받침을 끼워 두면, 잔을 여러 개 올리더라도 기울지 않을 거예요." },
  "from": ["공방 주인 · 잘함: 흔들림 찾기"], "once": false }
```

네 판은 뜻 태그·빈칸·말하는 주민이 같아야 한다. 빈칸은 허용 값 목록의 키만 채운다(마을:471). 근거 설정 항목(`from`)을 적는다(주민:68).

### 16-3. 제작 길 — 제작 때 AI 초안 → 자동 검사 → 검수

1. **제작 때 AI 초안.** Claude가 주민 표(§3)·수준 규격(§13-1)·뜻 태그로 L2를 먼저 쓰고, 같은 뜻으로 L1·L3·L4를 찍어 낸다. 실행 중 AI가 아니라 제작 도구다(G5).
2. **자동 검사**(`tools/town-lines-check.mjs`, CI의 `town-content`):
   - **수준 검사** — 다리 §3-4대로 L1·L2는 Strata의 TOPIK I 낱말·문형 층(`strata/maps/topik-i.json`의 문법 항목)과 자동으로 대조하고, L3·L4는 Strata에 TOPIK II 낱말·문형 층이 아직 없으므로 AI 2중 검수 기준의 「어휘·문형 단계」 항목을 원고에도 같은 방식으로 쓴다. 길이 상한은 다리 §3-1대로 L1 한 문장 5어절·L2 연결 하나 8어절·L3 두세 문장에 문장마다 10어절·L4 서너 문장에 문장마다 14어절이다. 한 단계 위 판은 새 부담을 하나만 늘린다.
   - **금지 말** — §10-2의 기간 말, 탓·서운함(「때문에 못」「서운」「실망」), 플레이어를 향한 재촉(「빨리」「어서 와요」), 묻지 않는 주제(결혼·연애·몸무게·생김새·돈벌이, 주민:26). 「그동안 달라진 것」 줄에서는 예외 없이 막는다. 다른 주민 대사에서는 걸린 줄을 사람이 확인하고, 플레이어와 상관없는 쓰임(「제가 쉬는 동안」)만 허용 목록에 올린다.
   - **설정 일관성** — 높임(`-어요`), 주민별 금지(공방 주인 반말·관용구, 연구원 학술어 — 원고:15~16), 취향 모순(주민:69).
   - **판본 일치** — 네 판의 뜻 태그·빈칸이 같다.
   - **중복·구분** — 같은 주민 안 같은 줄 0. 이름을 가려도 세 주민이 구분되는지(주민:70)는 표본으로 본다.
3. **검수.**
   - 주민 대사(마음·카드·전해 듣기·인사·일과·대화): Fable이 말맛·자연스러움·탓 없음·수준을 보고 고친다.
   - 찻집 주문 요청과 반응(채점되는 읽기 과제): 학습 문항 규칙대로 1차 Opus → 2차 아르곤의 AI 두 겹 검수(운영 원칙 역할 표, 결정 10-21). 기존 게임 문항 길(`tools/topik-review.mjs` 준비 `--기존` → 판정)을 쓰고, 통과한 요청 틀부터 학습 기록의 판정이 `unassessed`에서 `correct`·`incorrect`로 바뀐다(§13-2). 요청 틀의 검수 꼴은 다리 계약대로 블라인드 풀이(요청을 읽고 축마다 값을 적어 정답 집합과 대조)이고, 오답 매력도는 보지 않으며, 정답 유일성은 「축마다 답이 하나인가」로 본다. 기준 판 이름은 `rubric-compose-r1`이고, 검수 도구에 이 판을 더하는 일은 다리 설계의 착수 순서에 있다.
   - 유호님은 말맛 표본만 본다 — 주민마다 10줄, 찻집 주문 5줄, 대화 장면 L2 전체로 약 40줄(D2a F-4).
4. **목소리.** 이 조각은 글만이다. 목소리가 정해지면(마을:538) 듣기 판과 「천천히」 음성을 더한다.

## 18. 열린 것과 임시 값

1. **〔다리〕 학습·개인화 다리 값**(§13) — 수준 사다리, 첫 수준, 장면 안·뒤의 내림과 넓히기, 찻집 주문의 `practice.*` 매핑, 대화 장면의 습관 요약, 접속 시간대 습관의 자리는 10-22 다리 초안(§3·§4-3·§10)에 맞췄다. 그 초안은 그쪽 검수 전이라, 바뀌면 이 문서의 §10-3·§11-2·§12·§13·§16을 같이 고친다.
2. **취향 기억(「무슨 차 좋아해요?」)** — 다리 §6의 알려 주기 장면 ②. 이웃 수첩의 「잊어 주세요」가 생길 때 넣는다(§12-2).
3. **「깊은 밤」 해석**(§4-2) — 정본의 「어느 시간대에 와도 두 주민」(마을:524)과 「깊은 밤(마을이 잠든다)」(마을:183)을 맞춘 설계 판단이다. 결정을 바꾸지 않으며, 마을:524에 10-22 표시를 달았다.
4. **빛 한 벌 보정**(§2-2) — 관찰의 80% 기준으로 여러 벌 굽기 여부를 정한다.
5. **찻집 주문의 손 조작**(§11-1) — 10-08 설계안의 「카드마다 조작을 늘리지 않는다」를 T04에 한해 바꾼다. 미리보기·확정은 대안으로 남는다.
6. **목소리** — 미정. 이 조각은 글만이다.
7. **공유 마을** — 이 조각 밖이다. 계산 함수가 마을 씨앗과 세계 범위를 입력으로 받게 해서, 나중에 반 마을이 같은 계산을 쓸 수 있다. 같은 주민이 개인 마을과 공유 마을에 함께 있는 문제는 그때 정한다(D2a P1-6).
8. **입장 권한을 주는 길** — 다리 설계의 몫이다(점검 §6-1, 다리 §5). 이 조각의 관찰은 로컬 미리 보기로 한다.
9. **모든 〔초기값〕** — 시뮬레이션·실물 휴대폰·관찰로 다시 정한다.

낱말 풀이 — **세로 조각:** 작은 범위를 처음부터 끝까지 실제로 돌게 만든 한 조각. **생활일:** 내 시각 05:00부터 다음 날 05:00까지의 하루. **구간:** 하루를 넷으로 나눈 아침·낮·저녁·밤. **조각(segment):** 주민이 한 시간 동안 한 자리에서 하는 한 가지 일. **결산:** 마지막으로 확정한 때부터 지금까지 일어난 일을 같은 함수로 계산해 결과만 남기는 것. **게으른 결산:** 서버가 시간마다 돌리지 않고 요청이 올 때 한 번에 하는 결산. **맥박:** 화면이 1초마다 보내는 접속 신호. **임대:** 지금 어느 창이 마을을 쓰고 있는지의 짧은 기록. **바깥 상자(outbox):** 다른 체계로 보낼 사건을 잠시 담아 두는 곳. **시드:** 같은 값이면 같은 「우연」이 나오게 하는 씨앗 값. **결정적 함수:** 같은 입력이면 늘 같은 결과를 내는 계산.
