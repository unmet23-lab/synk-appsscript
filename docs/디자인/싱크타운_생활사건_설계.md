# 싱크타운 생활사건 설계

2026-10-02. 플레이어가 한 일이 NPC의 실제 행동과 생활 공간을 바꾸고, 다음 방문의 다른 선택으로 이어지도록 만드는 첫 여덟 사건의 제작 명세다. 콘텐츠 기획·한국어 제작·미술·게임 구현 담당자가 같은 원인과 결과를 만들기 위해 사용한다. 사용자의 요청에 따른 **설계 출발값이며 재미·학습 효과 검증 전**이다. 구현·배포·플레이 테스트 완료를 뜻하지 않는다.

공통 상태·관계·반복 조절·저장의 정본은 [행동과 세계 변화 설계](../싱크타운_행동과_세계변화_설계.md#scope)다. [성과를 인정하는 원칙](마을_NPC_성과인정_설계_20260921.md)은 NPC가 무엇을 왜 알아보는지 설명한다. 이 문서는 그 규칙으로 제작할 **구체적인 사건과 결과**를 정한다. 주민의 고유 이름·외형·목소리는 별도 자산 제작에서 정하고 여기서는 역할명으로 식별한다.

**2026-10-02 연결 설계 승인:** 생활 제작·작은 가게·주민 사연·발견 정원을 [첫 생활 구간 ‘찻집 앞 작은 쉼터’](싱크타운_첫생활구간_설계.md#scope)로 연결한다. 이 사건집의 C01~C08과 후속 A/B는 유지하며, 재료를 얻는 앞단계와 네 입구의 완결 조건은 새 정본을 따른다. 아래 연결은 구현 결과나 별도 보상 팩의 추가를 뜻하지 않는다.

## 첫 생활 구간에 연결하는 방식

| 입구 | 연결할 사건 | 첫 생활 구간에서 확인할 결과 |
|---|---|---|
| 생활 제작 | C02의 자리 개선 + C05의 제작·전달·사용 규칙 | 고른 자리나 가구를 주민이 실제로 사용한다. 공방의 원래 가구 의뢰까지 함께 완료한 것으로 처리하지 않는다. |
| 작은 가게 | C03의 작물과 메뉴, 필요한 주문 상황에는 C07 | 실제 마련한 재료의 메뉴를 제공하고 남은 기록을 확인한다. 주문 변경 C07을 모든 메뉴의 필수 단계로 넣지 않는다. |
| 발견 정원 | C04의 발견·관찰/표본·전시 규칙 | 온실 전시와 연구원의 실제 확인만으로 완결한다. 쉼터 화분은 별도 준비물로 마련하는 선택이며, 온실 의뢰와 쉼터의 대상·완료를 구분한다. |
| 주민 사연 | 새 정본의 두 주민 협의·실제 이용 장면 | 두 주민의 바람을 듣고 쉼터로 오기/공방에 차 가져가기처럼 합의한 쉬는 방식이 달라진다. 개인 이야기이며 C06의 집 초대 완료·허용을 대신하지 않는다. |

- [네 입구](싱크타운_첫생활구간_설계.md#routes) 중 하나만 선택해도 본인의 생활 구간을 끝낼 수 있다. 다른 분야의 수행, C01의 우산 도움, C06의 집 초대, C08의 공동 행사를 완료 조건으로 묶지 않는다.
- 원형과 통합 화면에서 **같은 실제 완료는 같은 사건 기록**을 참조한다. 이름·장소 표시를 바꿔 최초 성과·기념품을 다시 지급하지 않는다. 다른 대상에 실제 새 일을 했다면 그 대상·소유·사용 이력으로 구분하되, 원형 의뢰를 수행하지 않았는데 자동 완료하지 않는다.
- 작물·채집물·제작 재료의 획득과 소비·중단은 [재료와 생산 과정](싱크타운_첫생활구간_설계.md#materials)을 따른다. 미보유 재료를 연결 연출로 만들거나 관찰 기록을 소모 재료로 바꾸지 않는다. 사건집에는 같은 수량·시간 값을 복사하지 않는다.
- [Atlas 연결](싱크타운_첫생활구간_설계.md#atlas)과 [인정과 보답](싱크타운_첫생활구간_설계.md#recognition)은 생활 선택·실제 결과와 언어 수행을 나누어 적용한다. 작업 편의는 성장의 공통 보답이며, 공동 행사는 완결 뒤 본인이 고르는 후속이다.

## 제작에 적용할 공통 기준

- 각 사건은 TOPIK 1급+ 통과와 해당 체험·정액 이용 권한을 확인한 뒤 시작한다. 생활의 선택과 결과는 언어 난도와 독립한다. 쉬운 한국어로도 모든 생활 갈래를 고를 수 있으며, 같은 갈래를 선택한 초급·중급 플레이어에게 생활 결과와 기본 보답의 차등을 두지 않는다. [학습 연결](../싱크타운_행동과_세계변화_설계.md#learning).
- 아래 상태 이름은 사건 제작을 위한 **논리 항목**이다. 기존 Atlas 이벤트·DB에 이미 있는 필드라는 뜻이 아니다. 공통 [상태](../싱크타운_행동과_세계변화_설계.md#state)·[저장](../싱크타운_행동과_세계변화_설계.md#persistence) 계약에 맞춰 어댑터를 구현한다. 완료 사건의 과거 사실과 지금 사용 가능한 물건·공간을 따로 보존한다.
- 반응은 `proposed → eligible → queued → delivered`로 진행하며 때가 지난 반응은 `expired`, 철거·근거 정정·명시적 취소·동의 철회는 `cancelled`로 처리한다. 서버가 완료를 기록한 것만으로 NPC 반응을 보았다고 하지 않는다. 실제 화면·동작·필요한 대사가 표시됐다는 확인 뒤에만 `delivered`로 남긴다. 플레이어가 없는 동안의 변화는 다음 자연스러운 만남에서 현재 상태에 맞게 전달한다. [표현](../싱크타운_행동과_세계변화_설계.md#presentation).
- 후속 의뢰 ID는 아래 사건 ID에 A/B를 붙인다. 유효한 선행 결과가 있으면 `available`, 플레이어가 제안 화면을 실제로 보면 `offered`, 수락하면 `accepted`, 첫 수행을 시작하면 `active`, 완료하면 `resolved`다. 나중에는 `deferred`, 거절은 `declined`, 필요한 대상·동의가 사라지면 `invalidated`로 처리한다. 다시 제안할 조건은 각 사건에 적는다. [의뢰](../싱크타운_행동과_세계변화_설계.md#quests).
- 앱이 먼저 말을 거는 예산은 **하루 한 번**이다. 사건이 여러 개 생겨도 예산을 각각 받지 않는다. 대기 반응을 로그인 직후 연달아 재생하지 않고, 플레이어가 물건·NPC·생활 기록을 열면 관련된 결과 하나를 보여 준다. 완료 뒤에는 결과를 보고 그대로 쉬거나 나갈 수 있다. A/B 후속 후보는 `available`로만 남기고 추가 부탁을 자동으로 이어 보여 주지 않는다. 플레이어가 기존 행동 목록·수첩에서 다음 일을 직접 골랐을 때 제안하며, 둘을 모두 숙제로 주지 않는다.
- 첫 성과를 알아보는 반응·기념 보답은 같은 사건의 재전송·재배치·취소 복구로 다시 지급하지 않는다. 반복 가능한 생활은 유지하며, 새 의미는 실제 새 목표·달라진 용도·다른 결과에서만 만든다. 아래 소진 대안은 다른 표현의 같은 칭찬으로 채우지 않는다. [신선함](../싱크타운_행동과_세계변화_설계.md#freshness).
- NPC의 독자적인 목표는 플레이어가 돕지 않아도 안전하게 이어진다. 거절·연기 때 대체 계획을 실제로 실행하되 그 일을 플레이어의 공로로 기록하지 않는다. 자기 선택으로 만든 변화가 눈에 보이면서도 주민의 생계나 행복을 책임져야 하는 부담은 주지 않는다.
- 대사와 학습 태그는 제작 예시다. 태그는 필요한 어휘·문형·이해/표현 목표를 나타내며 공식 TOPIK 급수 인증이 아니다. 번역·그림·되묻기 사용은 생활 완료를 막지 않고, 독립적인 언어 수행 여부만 따로 남긴다.

## 완성의 만족과 부담을 함께 확인하는 기준

2026-10-02 후속 설계를 아래 여섯 기준으로 모든 사건에 적용한다. 별도 설정 화면이나 새로운 보상 체계를 더하지 않고, 기존 행동 목록·배치 편집·수첩·대화 안에서 작동하게 한다. 구체 정책의 정본은 각 행의 연결 문서다.

| 기준 | 사건집에서 지킬 제작 계약 |
|---|---|
| [현재 방문에서 쓸모 확인](../싱크타운_행동과_세계변화_설계.md#comfort-result) | 실제 완료 뒤 현재의 날씨·NPC 일과·사용 가능 물건에 맞는 핵심 이용 장면을 같은 방문 안에 제공한다. 특정 현실 시각·다음 비·다음 접속을 기다려야만 쓸모를 처음 볼 수 있는 구간은 배포하지 않는다. 다음 방문의 변화는 여운을 더한다. 관람·카메라 이동을 강제하거나 종료를 막지 않는다. 넘기거나 나가도 확정된 완료·보답은 보존하고, 나중에 기존 대상/기록에서 현재 상태에 맞는 이용을 자발적으로 볼 수 있다. 없었던 이용·방문을 편지·도우미의 안내·원격 회상으로 만들어 내지 않으며, 보지 않은 장면을 전달 완료로 기록하지 않는다. |
| [선택을 이해하고 바꾸기](../싱크타운_행동과_세계변화_설계.md#comfort-choice) | 확정 전 선택별 물건·동작 차이를 그림과 쉬운 한 문장으로 보여 주고, 소비·대여·반환 가능 범위를 같은 자리에서 알린다. 개인 배치는 저장 직전 유효 배치로 되돌릴 수 있도록 대상·위치·방향을 보존한다. 되돌리기는 본인 소유물의 현재 권한·revision을 확인하며 타인의 공용 편집, 이미 소비한 재료·거래·보상·과거 사건 전체를 취소하지 않는다. 영향받는 동선·용도·진행 의뢰는 확정 전에 해당 대상에서 보여 준다. |
| [완성하고 편히 끝내기](../싱크타운_행동과_세계변화_설계.md#comfort-finish) | 핵심 결과와 보답을 받은 뒤 새 일을 수락·거절해야 나갈 수 있게 하지 않는다. 후속 A/B는 기존 목록에서 자발적으로 고른다. 잠깐 머물기·감상·그만하기는 정상적인 마무리이며 학습 실패나 관심 부족으로 기록하지 않는다. |
| [끊겨도 하던 곳에서 잇기](../싱크타운_행동과_세계변화_설계.md#comfort-resume) | 선택 갈래, 확정된 준비물·완료 부분, 미확정 입력, 현재 대화 차례와 도움 설정을 구분해 보존한다. 복귀 시 기존 행동 목록에서 ‘무엇을 하던 중인지·남은 한 행동’을 보여 주고 마지막 유효 지점으로 잇는다. 저장 실패·변경 충돌은 실제 확정 상태를 다시 읽으며, 사라진 대상의 소비·대사를 재생하지 않는다. 자유 입력 초안은 기존 기기·계정 보관 경계를 따른다. |
| [개인화가 진행을 흔들지 않기](../싱크타운_행동과_세계변화_설계.md#comfort-adaptation) | 진행 중인 장면의 의미·언어 변형·보기·입력 방식은 고정하고 자동 난도·도움 조정은 다음 장면 경계에 적용한다. 플레이어가 요청한 보기·뜻·다시 듣기·입력 방식 변경은 즉시 반영한다. 중단 중 새 학습 기록이 생겨도 돌아온 장면을 갑자기 어렵게 바꾸지 않는다. 물건·권한이 무효가 된 경우는 난도 조정과 구분해 사실과 가능한 다음 행동을 안내한다. |
| [성장할수록 생활이 편해지기](../싱크타운_행동과_세계변화_설계.md#comfort-growth) | 완료한 배치·레시피 해금·개인 소유·관계·기념 기록은 추가 의뢰나 반복 납품 없이 남는다. 재료가 필요한 새 제작·반복 영업은 별도 선택이며, 기본 공간을 원상 복구시키거나 NPC가 새 숙제를 요구하는 방식으로 성과를 유지시키지 않는다. 반복 입력은 이미 확인한 조건을 다시 선택하게 하지 않고 필요한 새 차이만 묻는다. 가격·수입·소모·NPC 조달의 경제 수치는 경제·상품 설계에서 정한다. |

| C06 | 내 공간의 이용 방식을 정하기 | 초대받은 방식으로 쉬거나 식물 구경하기 | 조용한 찻자리 / 방문 정원 |
| C07 | 손님의 불편과 주문 변경 해결 | 원하는 음료를 가능한 조건에서 받기 | 대체 메뉴 단골 / 미리 준비하는 주문 |
| C08 | 주민 행사를 내 선택으로 준비하기 | 함께 쉬는 작은 행사를 부담 없이 열기 | 조용한 전시 산책 / 차와 이야기 모임 |

<a id="C01"></a>
## C01 우산과 마른 길

**플레이어 목표:** 비 때문에 처마에서 기다리는 우체부를 돕고, 내 도움이 다음 만남에 남는 경험을 한다. 우체부는 편지를 마저 전달하고 자기 배달 도구를 정리하고 싶어 한다.

**선행과 실제 완료:** 비가 오는 개인 사건 장면이며 우체부의 해당 배달은 아직 출발 전이다. 바로 이어서 우산을 들고 출발하거나 처마 길을 이용할 수 있는 일과·경로를 확인한 뒤 제안한다. 우산 갈래는 플레이어가 소유한 대여 가능한 우산의 인도가 확정됐을 때, 길 안내 갈래는 연결된 처마 길의 안내를 우체부가 받아 경로가 확정됐을 때 완료한다. ‘도와줄게요’라는 대사만으로 완료하지 않는다.

| 선택 | 실제 결과 |
|---|---|
| 우산을 빌려준다 | 우산의 소유는 플레이어에게 남고 대여 상태가 된다. 우체부가 그 우산을 펴서 열린 길로 출발한다. 플레이어의 우산과 주민 기본 우산의 외형을 구별한다. |
| 처마가 이어진 길을 알려 준다 | 우산은 이동하지 않는다. 우체부는 안내된 처마 길로 돌아가며 젖지 않는 길의 작은 안내 표시가 개인 기록에 남는다. |
| 나중에 돕는다 / 돕지 않는다 | `deferred` / `declined`. 우체부는 배달소의 공용 우산을 받아 출발한다. 플레이어의 도움·선물·신뢰 사건은 만들지 않는다. 다음 비 때 플레이어가 ‘비 오는 날 돕기’를 직접 열면 새 배달의 제안을 볼 수 있다. |

**저장할 현재 상태와 인지:** 배달 사건·선택 갈래·우산의 플레이어 소유권·대여 대상·인도 확정 여부·우체부의 실제 이동 경로·반환 확정 여부·플레이어가 본 출발/반환을 남긴다. 대여는 사용을 잠시 맡기는 상태이며 NPC에게 소유권을 넘기지 않는다. 우체부의 인지 근거는 직접 받은 우산 또는 직접 들은 길 안내다. 다른 NPC에게는 자동 전파하지 않는다.

**즉시와 다음 방문:** 즉시는 우산 펼치기 또는 처마 길로 이동하기다. 그 동작이 실제로 보인 뒤 출발 반응을 `delivered`로 기록한다. 배달 완료가 확정되면 우산은 자동 반환하고 인벤토리의 대여 표기를 해제한다. 완료 전에도 메인의 기본 소유물 관리에서 ‘우산 돌려받기’를 요청할 수 있다. 반환은 날씨·우체부와의 만남·유료 마을 입장·현재 구독 여부를 조건으로 삼지 않는다. 다음 자연스러운 만남에서는 이미 반환한 사실에 맞는 짧은 인사 또는 안내한 길로 들어오는 행동을 보여 주며, 이 연출을 볼 때까지 우산을 붙들지 않는다. 다음 접속이 맑아도 “오늘도 비네요”라고 말하지 않고 지난 도움만 짧게 언급한다.

**후속 의뢰 두 갈래:** `C01A`는 우산 반환 또는 안내 길 사용 확인 후 우체부가 필요로 하는 우산꽂이 자리를 함께 고르는 일이다. 확정 배치 뒤 같은 방문에 우체부가 공용 우산을 꽂아 보관하고 다음 비에는 그 우산을 꺼낸다. `C01B`는 플레이어가 산책을 원할 때 편지를 젖지 않게 건네는 전달 경로를 고르는 일이다. 정한 경로의 실제 배달 장면을 현재 날씨에 맞춰 보면서 끝나며 비를 기다리지 않는다. 두 갈래는 가구 만들기와 길 찾기로 경험이 다르다. 둘 다 고르지 않으면 우체부는 기존 보관함·기본 경로를 쓴다.

**취소와 변경:** 출발 전이며 인도가 아직 확정되지 않았다면 취소로 우산 예약을 풀고 출발 반응을 `cancelled`로 한다. 이때는 대여·도움 완료를 기록하지 않는다. 이미 인도가 확정됐다면 출발 전이라도 ‘대여 후 반환’으로 처리하고, 대여의 과거 사실을 지우지 않는다. 반환 확정 시 플레이어가 다시 사용할 수 있도록 대여 표기를 해제하고 NPC는 필요하면 공용 우산으로 바꾼다. 비가 그쳐 빗속 연출의 조건이 사라지면 미전달 비 전용 대사·우산 사용 반응은 `cancelled`로 하고, 반환과 보존할 과거 사실은 별도로 처리한다. `expired`는 정해진 전달 기한이 종료된 경우에만 쓴다. 안내 길이 공사 등으로 막히면 길 이용 반응은 `cancelled`, 관련 후속 의뢰는 `invalidated`로 처리한 뒤 공용 우산 경로를 제시한다.

**반복과 소진:** 동일 배달 사건에서는 출발·감사·반환을 각각 한 번 전달한다. 매 비마다 같은 첫 감사나 선물을 지급하지 않는다. 두 후속을 본 뒤에는 우체부가 선택한 도구·길을 계속 사용하는 풍경이 기본이다. 새 질문은 플레이어가 다른 길을 실제로 열었거나 직접 배달 활동을 선택했을 때만 생긴다.

**학습과 원인 흔적:** 태그는 요청, 수여, 위치, 경로다. 쉬운 대사는 “우산 있어요?”, “여기요”, “이 길로 가요”, “고마워요”다. 확장 대사는 배운 경우에만 “이 길로 가면 비를 피할 수 있어요”로 바꾼다. 생활 기록의 ‘내 우산을 빌려줬어요’ 또는 ‘처마 길을 알려줬어요’와 실제 우산/경로를 연결한다.

**반대행동 테스트:** 우산을 빌려주지 않고 길만 안내했는데 플레이어 우산을 쓰면 실패다. 인도 확정 전 취소인데 감사·대여가 남거나, 인도 확정 후 반환인데 대여 사실까지 사라지면 실패다. 비가 그친 뒤 미전달 빗속 반응이 실행되거나 `expired`로 처리되면 실패다. 다음 방문을 놓치거나 구독이 만료돼도 소유권이 유지되고 기본 소유물 관리에서 반환할 수 있어야 한다. 같은 반환 요청을 재전송해도 우산 복제·소유 이전·기념 반응 중복은 없어야 한다.

<a id="C02"></a>
## C02 비를 피하는 찻집 자리

**플레이어 목표:** 찻집에서 비를 피하며 기다릴 자리를 만들고 손님이 실제로 이용하는 모습을 본다. 찻집 주인은 출입구를 막지 않으면서 손님을 편하게 맞고 싶어 한다.

**선행과 실제 완료:** 주인이 개선을 부탁했고 플레이어가 편집할 수 있는 찻집 앞 구역이 있다. 차양은 비를 가리는 면·도달 가능한 대기 자리·막히지 않는 출입 경로가 모두 유효해야 한다. 처마 좌석은 덮인 구역 안의 사용 가능한 좌석과 출입 경로를 확인한다. 저장된 배치가 기능 검사를 통과한 시점에 완료하며 미리보기는 제외한다.

**첫 생활 구간 연결:** 차양·좌석에 필요한 물건은 [재료 마련과 제작](싱크타운_첫생활구간_설계.md#materials)에서 실제 확보한 뒤 이 배치 판정으로 잇는다. 같은 배치를 통합 구간에서도 보았다는 이유로 C02의 완료·보답을 다시 만들지 않는다.

| 선택 | 실제 결과 |
|---|---|
| 바깥에 작은 차양과 대기 자리를 둔다 | 비 오는 날 손님이 차양 아래에서 기다리고 주인이 바깥 창구에서 음료를 건넨다. |
| 기존 처마 안쪽으로 좌석을 옮긴다 | 새 차양 없이 안쪽 좌석을 쓴다. 주인이 출입구 대신 좌석 옆으로 음료를 가져간다. |
| 연기 / 거절 | 주인은 안쪽 기본 대기 자리를 사용한다. 플레이어 성과는 기록하지 않는다. 개선 메뉴를 플레이어가 다시 열 때만 미완 제안을 볼 수 있다. |

**저장할 현재 상태와 인지:** 배치 개정 번호·선택 갈래·사용 가능한 보호 자리·이동 경로·주인의 확인 방문·손님 이용 이력을 남긴다. 주인은 직접 자기 가게의 배치를 확인하고, 손님은 실제 이용한 뒤에만 그 편리함을 안다. 전체 주민에게 “네가 가게를 고쳤더라”를 배포하지 않는다.

**즉시와 다음 방문:** 완료 직후 주인이 새 동선을 걸어 확인하고 손님 한 명이 앉거나 기다린다. 맑은 날에는 실제 차양의 그늘 또는 처마 자리에서 쉬는 모습을, 비 오는 날에는 젖지 않는 대기 모습을 같은 방문 안에 보여 준다. 현재 빛에서 그늘이 생기지 않는 배치라면 그늘 효과를 꾸며 내지 않고 새 좌석·서빙 동선의 실제 쓸모를 보여 준다. 배치가 보이고 해당 동작이 표시되면 반응을 전달 완료로 한다. 다음 방문에는 현재 날씨에 맞는 일상 이용이 이어지며 비를 조작하거나 기다리게 하지 않는다.

**후속 의뢰 두 갈래:** `C02A`는 사용 확인 뒤 주인이 차양/처마 아래에 놓을 음료 받침대를 부탁한다. C05의 실제 제작·사용 방식으로 연결하고 가구 종류만 이 사건용으로 제작한다. `C02B`는 손님의 요청을 듣고 대기 자리 안내 그림을 고르는 일이다. 완료하면 손님이 새 안내를 보고 출입구 대신 정한 자리로 이동한다. 플레이어는 기능 개선 또는 안내 꾸미기를 선택한다.

**철거와 변경:** 배치 미리보기에서 주인의 이동선·앉을 자리·비를 가리는 면과 영향을 받는 의뢰를 해당 대상에 표시한다. 문이 막히면 저장 전에 “여기로 못 가요”와 가능한 빈자리를 보여 준다. 본인이 편집할 권한이 있는 배치는 직전 유효 배치로 되돌릴 수 있다. 확정 뒤 차양을 철거하거나 좌석을 옮기면 현재 사용 가능 상태를 다시 계산한다. 비를 가리지 못하면 “비를 피할 수 있어요” 대기 반응은 `cancelled`, 물건 이용을 전제로 한 미완 후속은 `invalidated`다. 이미 이룬 개선 경험과 받은 기념품은 보존한다. 주인은 기본 실내 자리를 사용한다. 다시 설치해도 동일 목표의 첫 성과를 재발행하지 않는다.

**반복과 소진:** 첫 사용 장면은 한 번, 이후는 조용한 반복 이용이다. 두 후속이 끝나면 새 의뢰를 억지로 만들지 않는다. 새 레이아웃을 확정했을 때만 기존 동선과 달라진 실제 이용을 보여 주며, 색만 바꿨다면 새 구조 공로를 주지 않는다.

**학습과 원인 흔적:** 태그는 장소, 불편, 원인·결과, 대안이다. 쉬운 대사는 “여기 앉아요”, “여기는 안 젖어요”, “문 앞은 비워요”로 제작한다. 확장은 “밖에 자리가 생겨서 문 앞이 편해졌어요”다. ‘내가 바꾼 자리’ 보기에서 기존/현재 배치를 겹쳐 보여 주고 실제 이용 장면으로 이어 준다.

**반대행동 테스트:** 출입구를 막은 배치는 완료되지 않아야 한다. 차양을 없앴는데 비 속 손님이 차양 아래처럼 움직이면 실패다. 처마 좌석 갈래를 골랐는데 바깥 창구 영업이 바뀌면 실패다. 도움을 써서 안내를 이해해도 생활 개선은 동일하게 인정한다.

<a id="C03"></a>
## C03 작물이 찻집 메뉴가 되는 날

**플레이어 목표:** 내가 마련한 작물이 실제 메뉴가 되고 손님에게 제공되는 모습을 본다. 찻집 주인은 받은 재료에 맞춰 팔 수 있는 메뉴를 정하고 싶어 한다.

**선행과 실제 완료:** 첫 제작판의 작물은 딸기로 두고 주인이 제공한 레시피의 딸기 재료 칸을 충족하는 소량 메뉴 의뢰를 사용한다. 첫 전달 묶음 안에서 실제 첫 제작과 시식 장면에 사용할 몫을 확보하며, 그 쓸모를 보려고 추가 납품을 요구하지 않는다. 재료의 소유·출처·전달이 확정되고 주인이 선택한 레시피로 첫 음료/곁들임을 제작한 상태를 완료로 삼는다. 재료를 들고 대화만 한 상태는 완료가 아니다. 구매 재료도 이용할 수 있으나 직접 재배 공로는 기록하지 않는다.

**첫 생활 구간 연결:** 딸기를 심고 거두거나 다른 경로로 마련하는 앞단계는 [작물과 재료 계약](싱크타운_첫생활구간_설계.md#materials)으로 잇는다. 이미 전달·제조한 묶음을 통합 구간의 재료로 복제하지 않고 같은 출처·소비·첫 시식 기록을 참조한다.

| 선택 | 실제 결과 |
|---|---|
| 생과일 차로 낸다 | 차림표에 생과일 차가 추가되고 주인이 과일을 넣는 제조 동작을 한다. 해당 과일이 있는 동안 그 메뉴를 쓴다. |
| 잼으로 만들어 곁들인다 | 잼 병이 진열되고 빵·차와 함께 내는 메뉴가 추가된다. 보관 재료를 쓰는 제조 동작이 생긴다. |
| 일부를 내 집에 남긴다 / 나중에 / 거절 | 실제 전달분만 이용한다. 필요한 분량이 없으면 주인은 기존 메뉴를 유지하고, 새 메뉴 의뢰는 연기 또는 거절로 남긴다. 미제공 재료를 소모하거나 메뉴가 먼저 열리지 않는다. |

**저장할 현재 상태와 인지:** 재료 묶음의 출처·제공한 몫·레시피 갈래·첫 제조·첫 시식 몫·현재 메뉴의 제공 가능 상태·품절 여부를 기록한다. 영업 재고와 레시피 해금·함께 만든 메뉴의 진열/기념 기록을 분리한다. 주인은 수령과 제조로 알고, 손님은 메뉴를 먹은 사실만 안다. 플레이어가 재배 사실을 공유하기로 선택한 경우에만 메뉴 설명에 그 사실을 덧붙인다.

**즉시와 다음 방문:** 선택한 메뉴의 그림·진열물·제조 동작이 함께 바뀌고 확보한 첫 시식 몫으로 플레이어와 손님에게 실제로 제공한다. 이 같은 방문의 장면으로 메뉴의 쓸모를 처음 확인한다. 중간에 나가면 아직 제공하지 않은 첫 시식 상태를 보존하고 다음에 그 자리에서 이어 간다. 이미 제공한 몫은 관람을 넘기거나 재개했다는 이유로 다시 만들지 않는다. 다음 방문의 반복 주문은 재고가 있을 때만 생긴다. 재료가 없으면 영업 차림표는 ‘준비 중’으로 바꾸되, ‘함께 만든 메뉴’의 진열·레시피와 기념 기록은 남기고 주인은 기존 기본 메뉴로 영업한다. 품절을 복구 과제로 자동 등록하거나 납품 알림을 보내지 않는다. 완성 사실을 기록했다고 재료나 판매 수입이 무한히 생기지 않는다.

**후속 의뢰 두 갈래:** `C03A`는 플레이어가 재배를 계속하고 싶을 때 다른 제공 가능한 작물로 맛을 비교하는 시식 자리다. 재료 두 종류의 차이를 손님에게 보여 주면 끝난다. `C03B`는 가게·꾸미기를 원할 때 새 메뉴의 설명과 진열 방식을 고르는 일이다. 완료하면 주문판과 주인의 소개 동작이 바뀐다. 특정 활동을 택하지 않아도 원래 메뉴 성과는 보존한다.

**취향 변경과 취소:** 수령 전 취소는 재료를 이동시키지 않는다. 수령 후 아직 제작하지 않은 재료의 반환은 주인과 확인한 미사용분에 한해 처리하고, 사용한 분량을 복제하지 않는다. 메뉴를 생과일 차에서 잼으로 바꾸면 새 제작·재료 상태를 확인한 뒤 현재 메뉴만 바꾼다. 지난 메뉴 이력은 남지만 ‘현재 판매 중’ 대사는 새 상태를 따른다.

**반복과 소진:** 같은 레시피의 반복 납품은 플레이어가 운영 목록에서 직접 선택한 생활 거래로만 처리하고 첫 시식·첫 메뉴 선물은 반복하지 않는다. 메뉴를 만드는 첫 성과와 레시피·진열·관계의 유지는 납품을 계속하는 조건에 묶지 않는다. 두 후속을 본 뒤에는 익숙한 단골의 선택과 실제 품절/재개만 보여 준다. 새 작물이나 새 용도 없이 재료 이름만 무작위로 바꾼 의뢰를 연속 생성하지 않는다. NPC 조달 범위·판매 수입·재료 소모량은 경제·상품 설계의 운영값으로 별도 확정하며 이 사건집에서 임의의 무한 공급이나 수익을 만들지 않는다.

**학습과 원인 흔적:** 태그는 재료, 수량, 선택, 비교, 설명이다. “딸기예요”, “차로 만들어요?”, “잼으로 해요”, “맛있어요”를 쉬운 대사로 둔다. 확장은 배운 표현으로 “바로 마시는 차와 오래 두는 잼 중에 골라 주세요”처럼 문장을 나눠 제공한다. 메뉴의 작은 ‘만든 이야기’에는 플레이어의 실제 제공 방식만 남기고 직접 제작/구매를 구분한다.

**반대행동 테스트:** 재료를 전달하지 않은 계정에 메뉴·시식 공로가 열리면 실패다. 구매 재료에 “네가 기른”이 나오면 실패다. 같은 전달 사건을 다시 보내도 재료 소모·메뉴 보상은 한 번이다. 재료가 소진됐는데 계속 제조되거나 납품을 거절해 관계가 줄어들어도 실패다.

<a id="C04"></a>
## C04 발견한 식물을 기록하는 방법

**플레이어 목표:** 산책 중 발견한 식물이 온실이나 관찰 기록에 남도록 기여한다. 연구원은 서식 모습을 해치지 않고 식물의 계절 변화를 비교하고 싶어 한다.

**선행과 실제 완료:** 연구원에게서 게임 안의 조사 장소와 채집 가능한 대상을 소개받는다. 표본 갈래는 채집 허용된 게임 물건의 인도와 온실 배치가 확정돼야 한다. 관찰 갈래는 지정 식물을 현장에서 관찰하고 게임 안의 관찰 카드가 연구원에게 전달돼야 한다. 사진 업로드·실제 식물 채집은 요구하지 않는다.

**첫 생활 구간 연결:** 발견 단서부터 획득·보관까지는 [채집과 관찰 계약](싱크타운_첫생활구간_설계.md#materials)으로 잇는다. 관찰 카드는 기록이며 채집물·작물 재료가 아니다. 관찰만 했으면 원래 식물은 남고, 쉼터에 놓을 실물이 필요하면 별도로 실제 마련해야 한다. 같은 발견을 온실과 쉼터에서 소개해도 최초 발견 보답을 반복하지 않는다.

| 선택 | 실제 결과 |
|---|---|
| 허용된 표본을 온실에 옮긴다 | 온실 선반에 식물이 생기고 연구원이 그 식물을 돌본다. 원래 장소에는 해당 채집 상태를 반영한다. |
| 식물은 두고 관찰 기록을 가져온다 | 원래 장소의 식물이 유지되고 온실에는 관찰 카드가 놓인다. 연구원이 다음 관찰 경로를 지도에서 확인한다. |
| 더 살펴보기 / 나중에 / 거절 | 조사 수첩에서 나중에 다시 시작할 수 있다. 연구원은 다른 일반 자료로 일을 이어가며 플레이어의 발견 표본·기록을 만들지 않는다. |

**저장할 현재 상태와 인지:** 발견 대상·확인 장소·기록/표본 갈래·실제 전달·온실 슬롯·원래 장소 상태·공개 기여명 동의를 저장한다. 연구원은 받은 것만 알며 목격하지 않은 탐색 경로를 말하지 않는다. 공개 이름 표시는 기본으로 넣지 않고 플레이어가 허용한 별명만 사용한다.

**즉시와 다음 방문:** 온실의 빈자리가 표본 또는 관찰 카드로 바뀌고 연구원이 그 대상을 실제로 확인해 물을 주거나 준비된 비교 카드 옆에 놓는다. 전시와 이용을 같은 방문에 확인하며 새 계절을 기다리지 않는다. 다음 방문에는 현재 돌봄이나 추가로 준비된 관찰 자료를 비교한다. 최초 발견 안내와 실제 전시가 표시되어야 전시 반응을 전달 완료로 한다. 표본 돌봄과 기록 보존은 연구원의 기본 일이며 플레이어에게 물 주기 출석 의무가 생기지 않는다.

**후속 의뢰 두 갈래:** `C04A`는 식물을 남겨 둔 곳 또는 게임이 준비한 동일종 관찰 지점에서 잎의 변화를 살펴보는 산책이다. 계절이 맞지 않으면 이미 준비한 비교 카드로 완료할 수 있어 현실의 특정 날짜를 기다리지 않는다. `C04B`는 온실을 좋아하는 플레이어가 표본/카드의 안내 그림과 배치를 고르는 일이다. 완료 뒤 방문 NPC가 그 앞에 멈춰 관찰한다.

**변경과 취소:** 공개 소개를 철회하면 이름을 지우고 익명 자료로 남긴다. 표본을 돌려놓기로 결정하면 온실의 실물은 사라지고 연구 기록으로 바뀌며, 이미 본 발견 사실은 보존한다. 전시를 아직 보여 주지 않았는데 다른 형태로 바꾸면 이전 반응을 `cancelled`로 하고 새 형태만 전달한다. 관련 후속은 현재 표본/기록을 대상으로 다시 제시한다.

**반복과 소진:** 같은 발견 지점의 재방문은 새 최초 발견으로 인정하지 않는다. 표본→반환→재채집으로 기념품을 늘릴 수 없다. 두 후속 후에는 계속 관찰하거나 이미 아는 식물을 조용히 볼 수 있다. 다음 신선한 사건은 다른 서식 조건·실제 새 식물·기존 식물의 새로운 관찰 결과가 준비됐을 때만 제공한다.

**학습과 원인 흔적:** 태그는 장소, 특징, 비교, 순서다. 쉬운 대사는 “꽃이 있어요”, “여기서 봤어요”, “여기에 둘까요?”다. 확장은 “꽃은 두고 기록만 가져왔어요”처럼 선택의 결과를 설명한다. ‘내가 찾은 것’에는 실제 발견 위치와 온실의 해당 표본/카드를 연결한다.

**반대행동 테스트:** 관찰만 선택했는데 식물이 채집되면 실패다. 연구원에게 전달하기 전에 온실에 전시되거나 공개 동의 없이 이름이 붙어도 실패다. 전시 철회 후 NPC가 빈자리에 물을 주면 실패다. 다른 플레이어가 이미 전시했어도 내 관찰·학습 수행을 완료로 대신해서는 안 된다.

<a id="C05"></a>
## C05 공방에서 쓰는 가구

**플레이어 목표:** 내가 만든 가구가 장식품을 넘어 공방의 일을 실제로 바꾸는 모습을 본다. 공방 주인은 자주 쓰는 도구를 빨리 꺼내거나 손님의 물건을 보기 좋게 놓고 싶어 한다.

**선행과 실제 완료:** 주인이 사용 가능한 공방 구역을 정하고 플레이어가 제작 또는 재료 마련을 선택한다. 제작 완료·소유/인도·배치·NPC 접근과 사용할 동작이 모두 유효한 가구만 완료로 인정한다. 구매 가구를 제공하는 대안은 허용하되 제작 기록과 구분한다.

**첫 생활 구간 연결:** [재료 선택부터 완제품까지](싱크타운_첫생활구간_설계.md#materials)를 실제로 거쳐 이 전달·사용 규칙을 적용한다. 쉼터용 제작과 공방 원형은 대상과 사용 목적을 구분하고, 같은 가구 인스턴스의 제작·이동을 새 원형으로 복사해 재료·기념품을 늘리지 않는다.

| 선택 | 실제 결과 |
|---|---|
| 도구를 넣는 낮은 수납대를 만든다 | 주인이 상자까지 왕복하던 대신 수납대에서 도구를 꺼내 작업한다. 주변의 오래된 도구 상자는 정리된다. |
| 손님 물건을 놓는 전시 선반을 만든다 | 완성품이 선반에 놓이고 손님이 물건을 살펴본다. 주인은 작업대 위를 비우고 선반에서 물건을 건넨다. |
| 만들기 대신 마련해서 전달 / 연기 / 거절 | 마련한 물건의 실제 출처로 기록한다. 연기·거절이면 주인은 기존 상자·작업대를 계속 사용하며 플레이어가 도와준 것으로 말하지 않는다. |

**저장할 현재 상태와 인지:** 제작/구매 출처·가구 인스턴스·사용 슬롯·선택 용도·확정 배치·주인의 실제 사용 이력을 둔다. 주인은 받은 가구와 용도를 알며, 손님은 실제로 본 선반만 안다. 제작 사실을 공유하지 않은 손님에게 제작자를 자동 소개하지 않는다.

**즉시와 다음 방문:** 주인이 수납대에서 도구를 꺼내거나 선반에 완성품을 놓는다. 사용 동작과 대상 가구가 실제로 보인 뒤 반응을 전달 완료로 한다. 다음 방문에도 선택한 용도의 동선·작업 자세를 유지한다. 빈 선반을 보는 시간에는 “물건이 가득하네요”처럼 과거 상태를 말하지 않는다.

**후속 의뢰 두 갈래:** `C05A`는 정리된 도구의 이름표를 함께 붙이는 일이다. 완료 후 주인이 해당 도구를 찾을 때 이름표를 가리킨다. `C05B`는 공방에서 배운 구조로 내 집의 작은 선반을 만드는 일이다. 완료하면 내 집에서 실제 수납/전시 대상으로 사용할 수 있다. 어느 갈래든 다른 후속의 공로·완료는 자동 지급하지 않는다.

**철거와 변경:** 배치 확정 전 주인이 손을 뻗고 도구/전시물을 놓을 위치와 동선을 미리 보여 주며 “여기서 꺼내요”와 “여기에 보여요”로 용도 차이를 알린다. 아직 전달하지 않은 개인 가구의 배치는 직전 유효 배치로 되돌릴 수 있다. 이미 NPC에게 전달한 가구는 소유·반환 조건을 확인한 새 변경으로 처리하며 개인 편집 취소로 강제 회수하지 않는다. 가구를 돌려받거나 옮기면 주인의 사용 슬롯을 해제하고 기존 도구 상자/작업대로 돌아간다. 대기 중인 사용 반응은 `cancelled`, 해당 가구가 필요한 미완 의뢰는 `invalidated`로 한다. 이름표·전시 용도 변경은 현재 기능에 맞게 다시 붙이고 이전 첫 제작 경험은 유지한다. 실제 전달 전 취소한 물건은 플레이어 보관함에 남는다.

**반복과 소진:** 같은 가구의 재배치·색 변경을 새 제작 성과로 세지 않는다. 사용 동작은 생활 배경으로 반복할 수 있지만 감사와 선물은 반복하지 않는다. 두 후속 이후에는 다른 용도를 플레이어가 선택하거나 주인의 실제 새 작업이 준비될 때만 추가 제작을 제안한다.

**학습과 원인 흔적:** 태그는 용도, 위치, 요청 조건, 설명이다. “여기에 넣어요”, “이 선반을 써요”, “찾기 쉬워요”로 시작한다. 확장은 “손님 물건을 여기에 두니까 작업대가 넓어졌어요”를 쉬운 두 문장으로도 제공한다. 공방의 물건 정보에서 누가 어떤 방식으로 마련했고 지금 어디에 쓰는지 볼 수 있다.

**반대행동 테스트:** 전시 선반을 골랐는데 도구 수납 동작만 바뀌면 실패다. NPC가 가구를 관통하거나 접근 불가능한 가구를 완료로 처리하면 실패다. 구매품을 직접 제작으로 칭찬하거나 철거 후 공중에서 물건을 꺼내도 실패다.

<a id="C06"></a>
## C06 내 공간에 초대하는 방식

**플레이어 목표:** 내가 고른 분위기의 공간을 만들고, NPC가 그 의도를 이해해서 알맞게 머무는 경험을 한다. 초대받은 주민은 조용히 차를 마시거나 식물을 구경하고 싶어 하며, 두 이용 목적을 플레이어에게 먼저 알려 준다.

**선행과 실제 완료:** 개인 공간에 사용 가능한 좌석 또는 관찰할 식물이 있고, 플레이어가 공간 용도와 방문 범위를 확정한다. 선택한 용도의 동작이 가능한 배치 저장과 **그 NPC에 대한 방문 허용**까지 확인해야 방문 준비가 완료된다. 미적 점수나 꾸밈 구매액으로 판정하지 않는다. 첫 생활 구간의 집 밖 쉼터 협의·이용은 이 개인 집 초대와 별개이며, 쉼터의 첫 편집도 개인 이야기 범위다. 쉼터 이용 동의로 집 방문을 허용하거나, 집 초대 동의를 쉼터의 공개 소개·공동 이용 동의로 확장하지 않는다.

| 선택 | 실제 결과 |
|---|---|
| 조용한 찻자리로 초대한다 | 주민은 정한 좌석에서 잠깐 차를 마신다. 먼저 긴 대화를 시작하지 않으며 찻잔과 차를 내려놓는 행동을 한다. |
| 식물을 함께 보는 정원으로 초대한다 | 주민은 정한 관찰 경로로 이동해 식물 앞에 멈춘다. 플레이어가 눌렀을 때 식물 하나에 관해 이야기한다. |
| 혼자 쓰기 / 다음에 초대 / 초대 거절 | 개인 공간의 완성과 꾸밈은 그대로 인정한다. NPC 방문·목격·관련 보답을 만들지 않는다. 조명·식물 배치를 발전시키는 C06B는 공간 편집기에서 직접 시작할 수 있다. 플레이어가 초대 설정을 다시 열 때만 방문 사건을 시작한다. |

**저장할 현재 상태와 인지:** 공간 용도·배치 개정·사용 가능 좌석/관찰 경로·허용한 NPC·공개 범위·실제 방문과 이용을 둔다. 초대장을 받은 것과 실제 방문한 것을 구분한다. NPC가 방문하기 전에는 내부 장식·색을 보았다고 말하지 않는다.

**즉시와 다음 방문:** 초대할 때 기존 행동 목록에서 ‘지금 초대’와 ‘다음에 초대’를 고를 수 있다. 지금 초대는 그 주민이 현재 하던 일을 짧게 마치거나 다른 NPC에게 인계할 수 있는 개인 일과 장면과 함께 제작한다. 같은 방문 안에 일을 마침→집까지 이동→선택한 찻자리/관찰 경로 이용이 실제로 이어져야 하며, 가게와 집에 동시에 존재시키거나 현실의 영업 종료 시각을 기다리게 하지 않는다. 필요한 일과·이동·이용 장면의 준비와 현재 실행 가능 여부를 제안 전에 확인한다. 장면이 없거나 이동이 불가능하면 ‘지금 초대’를 열어 무한 대기시키지 않으며 제공 가능한 사건으로 배포하지 않는다. 진행 도중 조건이 바뀌면 현재 상태를 저장하고 혼자 쓰기·나중에 잇기로 끝낼 수 있다. 다음에 초대는 플레이어가 나중에 목록에서 직접 재개하는 선택이며 특정 날짜 출석 약속을 만들지 않는다. 초대 표시·도우미 안내·원격 회상만으로 실제 방문과 목격을 기록하지 않고, 실제 이용을 본 뒤에만 “여기 좋아요” 반응을 전달 완료로 한다. 첫 실제 방문 뒤에는 작은 화분 하나를 개인 보답으로 둔다. 색 취향을 알려 주지 않았으면 준비된 기본 색 중 본인이 고르게 하며 이 보답은 첫 방문 사건에 한 번 귀속한다. 관람을 넘기거나 종료해도 이미 확정된 방문 사실·보답은 보존하고, 아직 일어나지 않은 방문은 미방문으로 남긴다. 이후 방문에는 허용과 사용 가능 상태에 맞춰 같은 용도로 조용히 머문다. 혼자 쓰기에서는 플레이어가 직접 앉거나 식물을 살펴보며 현재 공간의 쓸모를 누리고 NPC 방문은 만들지 않는다.

**후속 의뢰 두 갈래:** `C06A`는 실제 방문한 주민이 자신의 창가도 비슷하게 꾸미고 싶다며 화분/찻자리 배치를 함께 고르는 일이다. 완성하면 주민의 집 또는 가게 창가가 바뀐다. `C06B`는 내 공간을 다른 계절에도 쓰고 싶은 플레이어가 조명 또는 식물 배치를 고르는 일이다. **NPC 초대·방문을 선행 조건으로 두지 않는다.** 개인 공간의 용도와 유효한 배치를 저장하면 C06B가 `available`이 되고, 공간 편집기의 ‘내 공간 더 꾸미기’에서 직접 제안을 열어 수락할 수 있다. 혼자 쓰기와 초대 거절 상태에서도 동일한 조명·식물 제작 재료와 완료 결과를 제공한다. 완성하면 밤의 찻자리 또는 새 관찰 동선이 생긴다. 같은 취향을 다른 공간에 적용하거나 내 공간을 발전시키는 선택이다.

**취향 변경과 취소:** 방문 허용 철회는 아직 오지 않은 방문과 관련 반응을 `cancelled`로 한다. 이미 본 사실은 역사로 남되 이후 방문·내부 정보 사용은 현재 공개 범위를 따른다. 찻자리를 정원으로 바꾸면 현재 동작을 다시 계산하고 미방문 초대는 새 목적을 확인한 뒤만 진행한다. 좌석을 치우면 주민은 앉지 않고, 새 초대를 플레이어가 고르기 전까지 대체 방문을 강요하지 않는다.

**반복과 소진:** 첫 방문과 의미 있는 용도 변경만 별도 사건이다. 화분을 조금 옮겼다는 이유로 매번 집들이·선물을 반복하지 않는다. 두 후속 이후에는 NPC의 익숙한 이용 자체가 보상이며, 더 많은 반응을 원하면 플레이어가 현재 물건을 눌러 이야기한다. 새로운 방문 사건은 새 용도 또는 다른 초대 목적이 생겼을 때만 열린다.

**학습과 원인 흔적:** 태그는 초대, 허락, 선호, 공간 설명이다. “들어오세요”, “여기 앉아요”, “꽃을 봐요”, “지금은 혼자 있을래요”의 쉬운 대안을 둔다. 확장은 자신의 공간 의도를 한 문장씩 설명한다. 방문 기록에는 실제 방문 날짜와 이용 방식만 보이며, ‘내가 조용한 찻자리로 초대했어요’에서 해당 좌석으로 갈 수 있다.

**반대행동 테스트:** 혼자 쓰기를 골랐는데 주민이 방문하거나 비공개 장식을 알아보면 실패다. 혼자 쓰기·초대 거절·초대 철회 뒤에도 공간 편집기에서 C06B를 시작하고 조명/식물 배치를 완성할 수 있어야 한다. 방문하지 않은 NPC가 C06A를 제안하거나 C06B 완료를 목격한 것처럼 말하면 실패다. 조용한 찻자리 선택 뒤 긴 대화를 강제하면 실패다. 초대를 철회한 다음 기기에서도 방문이 시작되면 실패다. 언어 도움의 크기에 따라 방문의 따뜻함이나 보답이 달라져도 실패다.

<a id="C07"></a>
## C07 바뀐 주문에 답하는 가게

**플레이어 목표:** 원하는 재료가 없는 손님의 주문을 조율하고 그 해결이 다음 방문에 남게 한다. 손님은 오늘 마실 수 있는 음료를 원하지만, 원래 메뉴를 다음에 받는 것도 선택할 수 있다.

**선행과 실제 완료:** 첫 제작판은 딸기 음료를 원하는 손님에게 딸기가 없고 따뜻한 차는 제공 가능한 상태로 시작한다. 조건은 게임 속 메뉴 취향으로 한정한다. 플레이어가 해결안을 제시하고 손님이 동의한 뒤, 해당 음료를 실제 건네야 주문이 완료된다. 다음 준비 계획의 합의는 `active`로 남기고 이후 실제 제공 때 `resolved`로 바꾼다. 재고 없는 메뉴의 전달·대체에 동의하지 않은 주문을 성공 처리하지 않는다.

| 선택 | 실제 결과 |
|---|---|
| 지금 만들 수 있는 대체 음료를 권한다 | 손님이 동의한 음료를 받아 그 자리에서 마신다. 이후 이 손님에게 대체 메뉴를 다시 제안할 선택지가 생긴다. |
| 원래 메뉴를 준비해서 부른다 | 준비 메모가 남는다. 플레이어가 재료를 마련해 ‘준비됐어요’를 선택하면 손님이 현재 들른 마을 구역에서 짧은 볼일을 마치고 가게로 와 실제로 받는다. 같은 접속에서 마칠 수도, 그만두고 다음 접속에 이을 수도 있다. 현실 시각·재접속 횟수를 제공 조건으로 삼지 않는다. |
| 취소를 받는다 / 나중에 응대 / 의뢰 거절 | 손님은 기존 다른 가게를 이용하거나 기본 메뉴를 고른다. 플레이어를 탓하지 않고, 해결 성과·단골 변화는 만들지 않는다. 같은 미완 주문을 로그인마다 다시 요구하지 않는다. |

**저장할 현재 상태와 인지:** 주문 사건·원래 조건·재고 개정·플레이어 제안·손님의 동의·실제 제공 또는 준비 계획·현재 준비 가능 여부·다음 방문 처리 여부를 둔다. 손님은 자기 주문에 관한 내용만 안다. 대체 음료를 한 번 수락했다고 영구 취향으로 확정하지 않는다.

**즉시와 다음 방문:** 대체 갈래는 선택한 음료를 건네고 마시는 모습을 보여 준다. 준비 갈래는 읽을 수 있는 메모를 걸고 손님이 그 계획을 확인하며, 실제 준비를 마치면 같은 방문 안에 손님이 받아 마실 수 있게 한다. 이미 다른 기기에서 제공한 주문은 다시 제조하지 않는다. 다음 방문의 재주문에서는 실제로 동의했던 메뉴를 후보로 보여 주고 플레이어가 고른 기본 응대를 보조 NPC에 맡길 수 있다. 아직 준비하지 않고 쉬기로 했다면 손님이 다른 메뉴를 편히 고른다. 이는 NPC의 기본 운영이며 플레이어가 원래 주문을 해결한 것으로 기록하지 않는다. 원래 메뉴를 나중에 받겠다는 합의가 남으면 준비 의뢰는 `deferred`, 손님이 그 주문을 더 원하지 않으면 `invalidated`로 둔다. 어느 쪽도 학습 실패나 관계 하락이 아니다.

**후속 의뢰 두 갈래:** `C07A`는 같은 상황을 줄이도록 대체 가능한 메뉴 둘을 묶어 작은 안내판을 만드는 일이다. 손님이 안내판을 보고 선택하는 행동이 생긴다. `C07B`는 미리 준비하기를 좋아하는 플레이어가 가게의 재료 보관 자리를 정리하는 일이다. 완료 뒤 주인이 실제 그 자리에서 재료를 꺼내 준비한다. 후속의 품목·장소는 이번 해결 방식에 맞춰 제시한다.

**주문 변경과 취소:** 손님 또는 플레이어가 제공 전 메뉴 변경을 확정하면 이전 제공 반응을 취소하고 새 동의·재고를 검사한다. 재료가 사라지면 준비 중으로 유지하며 ‘준비됐어요’는 실행되지 않는다. 중단한 준비를 재개할 때는 현재 주문 필요·손님 동의·재고를 다시 확인하며, 없어진 옛 주문을 그대로 제공하지 않는다. 이미 사용한 재료·제작물의 실제 상태는 보존해 다시 차감하거나 원재료로 복제하지 않는다. 계획을 취소하거나 주문이 무효가 되면 미제공 주문·후속 의존성을 닫고, 소비 전의 예약 재료는 기존 소유자에게 풀어 준다. 이미 제공한 기록을 취소로 되돌려 재료를 복제하지 않는다.

**반복과 소진:** 동일 손님의 같은 주문 해결은 하나의 사건이다. 단순 재주문은 일상 거래이며 매번 특별 감사나 새 단골 공로를 만들지 않는다. 두 후속을 본 뒤에는 운영을 보조 NPC에 맡기거나 메뉴를 실제 변경할 수 있다. 새로운 갈등은 아직 겪지 않은 조건의 검수된 주문이 있을 때만 제공한다.

**학습과 원인 흔적:** 태그는 부정, 대안, 동의, 일정, 조건이다. “딸기가 없어요”, “차는 있어요”, “차로 할까요?”, “다음에 주세요”를 쉬운 장면으로 나눈다. 확장은 대안의 차이와 준비 이유를 설명하게 한다. 주문 메모에서 ‘없던 재료→내가 권한 메뉴/준비 계획→손님의 선택’을 볼 수 있다.

**반대행동 테스트:** 손님이 동의하지 않았는데 대체 음료를 성공으로 건네면 실패다. 다음 준비를 골랐는데 즉시 음료가 생기거나 오지 않았다고 관계가 줄면 실패다. 재고 갱신 전 두 기기에서 같은 재료를 각각 사용하면 실패다. 한 번의 수락만으로 NPC가 “늘 이걸 좋아해요”라고 말해도 실패다.

## C08 주민 행사를 함께 계획하기

**플레이어 목표:** 마을의 작은 행사를 내 선택으로 바꾸고 내가 맡은 부분을 주민이 알아보게 한다. 행사 담당 주민은 이웃과 쉬는 시간을 만들고 싶어 하며, 참석·분담 인원이 적어도 행사를 열 준비가 있다.

**선행과 실제 완료:** 행사 담당자가 작은 공용 구역과 안전한 기본 행사안을 마련했다. 개인 이야기의 준비 역할은 혼자 전부 수행하거나 NPC에게 일부를 부탁해 끝낼 수 있다. 선택한 개인 기여의 물건/메뉴/안내가 실제 행사안에 반영되고 본인의 맡은 역할이 확정돼야 개인 의뢰가 완료된다. 다른 사람의 완료로 내 역할·한국어 수행을 대신하지 않는다.

| 선택 | 실제 결과 |
|---|---|
| 조용한 전시 산책을 준비한다 | 정해진 전시 구역에 식물·생활 작품과 안내가 놓인다. NPC는 멈춰 관찰하고 짧게 이야기하며, 진행자가 이동 경로를 안내한다. |
| 차와 이야기 모임을 준비한다 | 휴식 구역에 좌석·메뉴가 놓이고 NPC가 차를 건네며 자리에 앉아 이야기를 나눈다. 준비한 메뉴가 실제로 제공된다. |
| 일부만 맡기 / 연기 / 거절 | NPC가 남은 기본 준비를 마친다. 플레이어는 맡아서 완료한 몫만 인정받고, 아무것도 맡지 않아도 손님으로 올 수 있다. 미접속을 탓하거나 행사를 취소하지 않는다. |

**저장할 현재 상태와 인지:** 공용 행사 회차·각 구역의 확정 행사안·슬롯별 편집 권한·참여자별 실제 역할·개인 이야기의 선택·준비물 소유/사용·행사 배치 개정·개인에게 전달한 인정 이력을 둔다. 담당 NPC는 자신에게 제출된 기여를 알고, 이용 NPC는 실제 경험한 구역만 안다. 공개 기여 표시는 선택이며 마지막 완료자에게 전체 공로를 주지 않는다.

**공유 구역의 선택 충돌:** 한 회차에 전시 구역과 휴식 구역을 함께 둘 수 있게 제작한다. 각 플레이어에게 작은 준비 슬롯을 배정하고 NPC가 놓은 임시 기본물을 본인의 기여로 교체할 수 있게 한다. 다른 사람이 먼저 끝내도 내 슬롯을 소진시키지 않는다. 플레이어는 자신의 슬롯에서 두 역할 중 하나를 고르며 다른 사람의 확정 슬롯을 덮어쓰지 않는다. 동일 슬롯의 중복 제출은 인벤토리 소모 전에 막고 현재 배치를 다시 보여 준다. 개인 선택은 마을 전체를 혼자 뒤집지 않으며, 혼자 참여하면 NPC가 남은 구역의 기본안을 채운다. 열여섯 명 동시 접속·출석·실시간 대화는 필요하지 않다. 여러 기여를 한 화면에 모두 움직이게 만들 필요는 없고 가까운 구역의 실제 이용을 보여 준다.

**즉시와 다음 방문:** 완료한 몫이 행사 준비 공간에 먼저 나타나고 담당자가 그 물건을 실제로 사용해 보며 작은 준비 모임을 연다. 전시는 담당 NPC가 관찰 경로를 걷고, 차 모임은 준비된 몫으로 차를 받아 앉는다. 같은 방문에 혼자서도 내가 준비한 것의 쓸모를 보고 옆에서 쉬거나 종료할 수 있다. 준비 모임은 실제 열린 개인 장면으로 기록하고 아직 열리지 않은 공용 본행사에 참석한 것처럼 처리하지 않는다. 공용 행사는 이웃이 있는 경우 온기를 더하며 현실 날짜·동시 접속을 핵심 결과 확인 조건으로 삼지 않는다. 다음 방문에 마을이 평소로 돌아가도 기념물·개인 기록은 남는다. 실제로 함께 차를 마시지 않은 플레이어에게 ‘함께 차를 마셨지’라고 하지 않는다.

**후속 의뢰 두 갈래:** `C08A`는 행사에서 쓴 전시물/휴식 물건을 주민의 일상 공간으로 옮기는 일이다. 완료하면 그 주민이 새 자리에서 계속 사용한다. `C08B`는 다음에 열고 싶은 모임의 목적을 정하고 안내 한 장을 준비하는 일이다. 전시 산책 또는 차 모임 중 다른 역할을 고를 수 있으며 다음 회차의 개인 준비 목표가 된다. 두 후보는 준비 모임의 이용 장면을 끝낸 뒤 목록에만 남긴다. 플레이어가 혼자 앉아 쉬거나 떠날 때 정리 의뢰·다음 행사 질문을 이어 붙이지 않으며, 본인이 맡지 않은 정리는 NPC가 기본 일과로 한다. 이전 회차 참여가 다음 회차의 출석 의무를 만들지 않는다.

**취소와 변경:** 행사 배치 확정 전에는 자기 슬롯의 계획을 바꾸거나 미사용 재료를 회수할 수 있다. 확정 후 공용 행사가 진행 중이면 다른 이용자의 구역을 지우지 않고, 다음 정리 시점에 개인 물건 반환·역할 변경을 처리한다. 공개 소개 철회는 표시만 제거하고 기여 사실·소유권은 유지한다. 행사 종료로 지나간 축하 대사는 `expired`, 아직 수행 가능한 물건 이전은 `available`로 남긴다. 마을 이동 시 개인 기여·기록은 가져가되 옛 공용 행사 배치를 새 마을에 복제하지 않는다.

**반복과 소진:** 한 회차·한 역할의 기여와 보답은 한 번만 처리한다. 행사 사진/기록 열람은 언제든 가능하지만 새 칭찬 사건을 만들지 않는다. 두 후속 이후에는 다른 역할을 직접 선택하거나 준비된 새 주제의 행사에 참여할 수 있다. 주제·용도 변화 없이 같은 행사에 새 이름을 붙여 의무 일과로 돌리지 않는다.

**학습과 원인 흔적:** 태그는 역할, 계획, 순서, 부탁, 공지다. 쉬운 대사는 “꽃을 놓아요”, “저는 차를 준비해요”, “여기에 앉아요”, “같이 쉬어요”다. 중급은 상충하는 요구를 요약하고 행사 이유·안내를 작성할 수 있지만, 언어 난도와 무관하게 전시/휴식 두 갈래를 고를 수 있다. 개인 행사 기록은 ‘내 역할→실제로 놓인 물건/메뉴→이용 장면’으로 연결한다.

**반대행동 테스트:** 다른 사람이 전시를 끝냈다고 내가 준비하지 않은 역할·학습까지 완료되면 실패다. NPC가 대신 준비한 부분을 “네가 전부 만들었다”고 하면 실패다. 동시에 같은 슬롯을 바꿔 둘 다 재료가 소모되거나 마지막 완료자가 전체 선물을 받으면 실패다. 혼자 들어온 계정에서 행사 준비와 참여가 끝나지 않거나 불참 후 관계가 줄어도 실패다.

## 제작 완료를 확인할 결과물

각 사건 묶음에는 두 생활 갈래와 거절/연기 흐름, 현재 상태별 대사·쉬운 대안, 실제 사용 동작과 대상 자산, 후속 의뢰 A/B, 철거·동의 철회·취소 장면, 원인 흔적 화면, 위 반대행동의 재현 입력과 예상 결과를 함께 담는다. 필요한 사용 동작이나 대체 상태가 없으면 해당 사건을 제공 가능한 콘텐츠로 등록하지 않는다. NPC 대사만 준비된 상태는 사건 제작 완료가 아니다.

### 여덟 사건의 부담 검사

아래는 기존 반대행동 검사에 추가할 예상 결과다. 자동 검사는 상태의 일관성을 확인하고, 학생에게는 설명 없이 완성·중단·복귀·다른 선택을 해 보게 하여 만족과 부담을 별도로 관찰한다. 설계 문구가 있다는 이유로 스트레스가 없다고 판정하지 않는다.

| 사건 | 추가로 재현할 상황 | 통과할 경험 |
|---|---|---|
| C01 | 도움 확정 직후 중단, 다른 시간에 복귀, 우산 반환 후 후속 목록을 열지 않음 | 실제 대여·반환과 남은 한 행동만 복원. 보지 않은 빗속 사용을 봤다고 만들지 않고 현재 가능한 인사/반환 상태를 제공. 우산꽂이의 첫 보관은 다음 비를 기다리지 않음. 추가 일을 고르지 않아도 물건을 돌려받고 끝낼 수 있음 |
| C02 | 맑은 낮·밤에 각각 완성, 의자를 막힌 자리로 미리 옮김, 직전 배치로 되돌림 | 같은 방문의 좌석·서빙 등 실제 쓸모가 보임. 그늘·비 보호를 사실과 다르게 표현하지 않음. 막힌 동선은 확정 전에 보이며 되돌린 뒤 사용 가능 상태가 복원됨. 재료·기념품 중복 없음 |
| C03 | 첫 제작 뒤 종료, 첫 시식 이어 하기, 이후 장기 미납품·영업 품절 | 첫 시식을 위해 추가 재료를 요구하지 않음. 현재 영업 재고와 이미 완료한 레시피·진열·기념 기록은 구분. 품절을 숙제로 만들지 않으며 기본 영업이 플레이어의 납품 의무로 바뀌지 않음 |
| C04 | 현재 계절의 기록만 전달, 다음 계절을 기다리지 않고 종료·복귀 | 온실에서 실제 사용한 표본/카드를 같은 방문에 봄. 완료 뒤 물 주기·추가 발견을 요구하지 않음. 다시 오면 전달한 것과 남은 한 선택만 이어지고 NPC가 기본 돌봄을 함 |
| C05 | 수납/전시의 미리보기 비교, 전달 전 배치 되돌림, 전달 후 회수 시도 | 도구 꺼내기와 전시의 차이를 확정 전에 이해. 개인 배치만 되돌리며 이미 이전된 소유·소비·거래를 되감지 않음. 완료한 가구는 새 제작 의뢰 없이 계속 사용됨 |
| C06 | 늘 같은 밤 시간에 지금 초대, 이동 장면 누락, 초대 도중 중단·관람 넘기기, 혼자 쓰기·C06B 진행 | 같은 방문에 NPC 일과 종료와 이동·사용이 일치. 준비되지 않은 초대로 무한 대기하지 않음. 재개 때 실제 방문한 부분·보답만 복원하고 미관람을 전달 완료로 꾸미지 않음. 혼자 쓰기도 공간을 직접 이용하고 발전시킬 수 있으며 다른 NPC 초대·새 부탁 없이 마칠 수 있음 |
| C07 | 준비 합의 뒤 중단, 손님의 다른 메뉴 선택 후 재개, 재료 마련 뒤 같은 접속에 제공, 응답 중 타기기 학습 갱신 | 현재 주문·동의·준비 메모·도움이 이어짐. 남은 합의는 연기, 없어진 필요는 무효로 구분하고 옛 주문의 중복 제공·재료 재차감을 막음. NPC 기본 운영을 플레이어 해결로 기록하지 않음. 손님의 실제 수령을 현실 시각까지 미루지 않음. 읽던 문장·보기는 바뀌지 않고 본인이 요청한 도움은 즉시 적용. 완료 뒤 새 주문을 자동 수락하지 않음 |
| C08 | 혼자 준비 후 옆에서 쉬기, 공용 행사 전에 종료, 후속을 고르지 않고 복귀 | 준비 모임의 실제 이용이 완결됨. 정리·다음 행사 의뢰를 자동으로 요구하지 않음. 공용 행사 참석을 꾸며 내지 않으며 자기 기여·기념물이 남고 이웃의 참여가 필요하지 않음 |

모든 사건에서 읽는 중·응답 중·배치 중의 자동 언어/도움 변경을 주입하고, 선택 갈래와 현재 조작이 유지되는지 검사한다. 다음 장면에서는 새 학습 요약을 반영할 수 있지만 사용자가 직접 고른 도움은 우선한다. 결과 관람을 넘기거나 종료해도 입력·카메라를 강제로 붙잡지 않고 확정된 완료·보답이 남는지, 나중에 본인이 결과 보기를 골라도 재료·보답을 복제하지 않는지 검사한다. 서버에서 확정되지 않은 완료를 복귀 설명이 성공으로 바꾸지 않는지도 함께 확인한다.

첫 구현에서는 C01과 C02를 각각 끝까지 만들어 **도움→현재 변화→다음 방문→후속 선택→변경/취소→기억 보존**의 공통 처리를 검증한다. 이어서 [찻집 앞 작은 쉼터](싱크타운_첫생활구간_설계.md#scope)를 재료 마련부터 생활 결과까지 연결한다. C01/C02의 단독 기술 검증만으로 재배·채집·제작을 포함한 생활 순환이 완성됐다고 판정하지 않는다. C03~C08의 정의를 미루거나 NPC 수를 먼저 늘리는 순서도 아니다.

통합 구간에는 [별도 인수 기준](싱크타운_첫생활구간_설계.md#acceptance)을 적용한다. 네 입구 각각에서 하나만으로 끝내기, 다른 분야로 자발적으로 바꾸기, 원형/통합 화면 사이의 중복 완료·보상 방지, 관찰 기록과 채집물 구분, 개인 집 초대와 쉼터 동의 분리를 확인한다. 사건별 상태 판정은 [공통 인수 기준](../싱크타운_행동과_세계변화_설계.md#acceptance)을 유지하며, 학생의 성취·학습·부담 체감은 실제 플레이 관찰로 따로 확인한다.
