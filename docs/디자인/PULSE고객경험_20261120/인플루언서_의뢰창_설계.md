# PULSE 인플루언서 광고 의뢰 창 — 설계 (2026-11-21)

## 1. 목적과 범위

유호님 11-21 「일단 우리 AI 캐스팅북에 있는것들로 몇명 채워줘. 내가 직접 교체할게」. 원래 요청(11-20)은 「pulse를 이용하고나면 우리 마케팅 서비스를 자연스럽게 이어지게 … 인플루언서들 리스트 만들어서 광고 의뢰 주는 창도 별도로 만들어서 연동」이다. 결정 표 「[PULSE 고객 경험 · 정하실 것 넷의 답]」 ①이 11-16 「크리에이터·파트너십 광고 세팅」 기각을 이 창에 한해 바꿨다.

만드는 것은 셋이다.

1. **손님 창**: PULSE 손님이 자기 프로젝트의 영상을 어느 채널에 실을지 고르고 의뢰를 보낸다. 보낸 뒤에는 의뢰가 어디까지 왔는지 본다.
2. **담당자 칸**: 직원 의뢰 화면(desk)에서 그 프로젝트의 의뢰를 보고 단계를 옮긴다.
3. **채널 명단 화면**: 대표(관리자)가 채널을 넣고 고치고 빼며, 손님에게 이 창을 보일지 켠다.

만들지 않는 것: 채널과의 계약 · 정산 · 게시물 숫자 자동 수집, 손님 결제(결제는 지금처럼 크몽에서 따로), 마케팅 성과 리포트와의 합침.

## 2. 지금 있는 것 (코드에서 확인)

- 「마케팅 성과」 칸(11-16)이 같은 자리의 본보기다. 스위치 `marketing`(pulse-features.mjs, 기본 끔, 관리자만 바꿈), 별도 문서 종류 두 개(pulse-marketing.mjs), 직원 경로(pulse-marketing-routes.mjs, Origin · CSRF · 몸통을 다 읽은 뒤 세션 재확인 · 감사 기록), 손님 방 자료의 `features.marketing`(server.mjs `customerStateWithFeatures`), 손님 쪽 지연 import(app.mjs `loadMarketingView`), 머리 단계 줄 끝 링크(film-views.mjs `roomRail` foot)와 방 아래 입구 줄(views.mjs `marketingEntry`).
- 직원이 리포트를 올리는 화면과 스위치를 켜는 화면은 없다. 지금은 API로만 한다.
- 손님 쓰기는 `/pulse/api/studio`(customerMutate, pulse-requests.mjs FIELDS · STAFF_ONLY · CUSTOMER_ONLY 허용 목록)와 `/pulse/api/action`(문의)로 한다. 프로젝트 문서에 쓰는 손님 동작은 client-notifications.mjs가 직원 알림을 만든다. 별도 문서 종류에 쓰면 알림이 저절로 생기지 않는다.
- 직원이 올린 그림을 손님이 보는 길은 프로젝트에 묶인 것뿐이다(작업 소식 `purpose: progress`, 인물 판). 프로젝트와 무관한 전역 그림 길은 없다.
- 캐스팅북 모델 그림은 정적 파일(`./assets/casting/*.webp`, casting-catalog.mjs)이고 서버도 이 카탈로그를 import한다.
- 이 저장소는 공개다. 실제 채널의 이름 · 사진 · 값은 저장소에 두지 않는다.

## 3. 자료

### 3-1. 채널 명단 (전역, 별도 문서 종류 `pulsePeopleRoster`, id `main`)

명단 한 문서에 칸 최대 60개. 칸마다:

| 칸 | 꼴 | 뜻 |
|---|---|---|
| id | `ch_` + 8자 | 서버가 만든다 |
| name | 1~40자 | 채널 이름 |
| platform | instagram · youtube · tiktok · blog | |
| handle | 0~60자 | @이름(선택) |
| url | https 주소, 0~300자 | 채널 주소(선택). 손님에게 「채널 보기」로 연다 |
| topics | 1~3개, 정한 목록에서 | food(푸드 · 카페) · beauty · fitness(운동) · home(살림 · 요리) · daily(일상) · outdoor(캠핑 · 여행) · fashion · tech · pet · kids |
| audience | 0~80자 | 누가 보는지 한 줄 |
| followers · avgViews | 0 이상의 정수, 선택 | 비우면 손님 화면에 숫자를 쓰지 않는다 |
| prices | `{post, review}` 원 단위 정수, 선택 | 비우면 「값은 채널과 확인한 뒤 알려 드려요」 |
| image | `{asset}`(캐스팅북 정적 경로 허용 목록) 또는 `{media}`(아래 3-3) | 대표 사진 |
| samples | 0~3개, image와 같은 꼴 | 채널 분위기 그림 |
| virtual | 참/거짓 | 가상 인물 채널이면 손님 화면과 게시물에 「가상 인물」 표시 |
| example | 참/거짓 | 예시 칸. 손님이 고를 수 없다(3-2) |
| active | 참/거짓 | 거짓이면 손님 화면에 없다 |

처음 명단(서버가 문서가 없을 때 읽는 기본값, 저장하면 그때부터 문서): 캐스팅북 모델 여섯. 하린(F02, food · daily, 카페 카운터 · 딸기 라떼), 유나(F01, beauty, 화장대 · 립스틱), 채원(F07, fitness, 강변 러닝), 소연(F05, home · food, 아침 주방 · 요리), 민재(M04, daily, 원룸 · 택배), 준호(M05, outdoor, 캠핑장 아침). 모두 `virtual:true · example:true`, 숫자와 값은 비운다. 이름 옆 플랫폼은 instagram. 그림은 캐스팅북 대표 사진과 장면 사진(이미 공개된 정적 파일). 창업자 기반 모델(M03)은 넣지 않는다.

### 3-2. 예시 칸을 손님이 고를 수 없는 까닭

예시 칸은 실제 채널이 아니다. 스위치를 켠 뒤에도 예시 칸에는 고르기 대신 「예시 채널」 표시만 둔다. 유호님이 실제 채널로 바꾼 칸(example 끔)부터 고를 수 있다. 고를 수 있는 칸이 하나도 없으면 의뢰 칸 대신 「채널을 준비하고 있어요. 열리면 이 방에서 먼저 알려 드려요」를 보인다. 직원이 손님 방을 미리 볼 때는 예시 칸도 고르는 모습까지 보이되 보내기는 막는다.

### 3-3. 명단 그림

관리자가 올리는 전역 그림. PNG · JPG · WebP, 한 장 2MB, 명단 전체 180장(칸 60 × 대표 1 + 장면 2). 서명 검사는 studio-media.mjs `receiveStudioMedia`를 쓴다. 손님은 진행 중인 프로젝트의 손님 세션이 있을 때만 `/pulse/api/people/media/<id>`로 받는다(공개 주소가 아니다). 명단에서 빠진 그림은 다음 저장 때 지운다.

### 3-4. 의뢰 (프로젝트 문서 `studio.people`)

의뢰는 프로젝트에 묶이고 손님 동작이라 직원 알림 · 일지 · revision이 지금 길로 돈다. 프로젝트마다 의뢰 최대 10건, 열린 의뢰(보냄~게시)는 1건.

| 칸 | 꼴 |
|---|---|
| id · createdAt | 서버 |
| channels | 1~5개. 보낼 때의 이름 · 플랫폼 · 값을 복사해 둔다(명단이 바뀌어도 의뢰는 그대로) |
| tasks | post(우리 영상 올리기, 늘 포함) · review(직접 찍은 후기도 함께, 선택) |
| reuse | none · d30 · d90 (올라간 게시물을 우리 광고에도 쓰기) |
| note | 0~500자 |
| status | sent → checking(담당자 확인) → accepted(채널 수락) → posted(게시) → done(결과), 또는 closed(거둠 · 거절) |
| posts | posted 때 게시물 주소 1~5개(https) |
| result | done 때 한 줄 0~300자 |
| closedBy · closedWhy | 손님이 거두면 customer, 담당자가 닫으면 staff와 까닭 |

손님 동작(CUSTOMER_ONLY): `people_request`(새 의뢰), `people_cancel`(sent일 때만). 직원 동작(STAFF_ONLY): `people_status`(다음 단계로, posted는 posts 필수, done은 result 필수), `people_close`(까닭 필수). 손님 알림 제목: 「담당자가 인플루언서 광고 의뢰를 확인했어요」, 「채널이 광고를 맡기로 했어요」, 「채널에 광고가 올라갔어요」. 직원 알림 제목: 「고객이 인플루언서 광고를 의뢰했어요」, 「고객이 인플루언서 광고 의뢰를 거뒀어요」.

## 4. 손님 창

- 자리: 방 탭 `people`. 입구는 셋. 머리 단계 줄 끝 링크 「인플루언서 광고」(SYNK 작품 · 마케팅 성과 옆), 방 아래 입구 줄(마케팅 입구와 같은 꼴 — 821~1000px에서 foot가 숨으므로), 끝맺음 카드의 「다음 편 묻기」 위 한 줄 「이 영상을 다른 채널에도 실어 보세요」.
- 보이는 때: 스위치 `people`가 켜졌고 프로젝트가 결제 확인 뒤(make 단계부터)일 때. 의뢰가 이미 있으면 스위치가 꺼져도 그 의뢰의 진행 화면은 보인다(손님이 보낸 것을 잃지 않게).
- 화면(무대 판 결, 넓은 화면 두 단, 휴대폰 한 단):
  - 머리: 「이 영상, 누구 채널에 실을까요?」 · 「값과 포함된 것을 먼저 보고 고르세요. 남길 말과 피할 말은 의뢰서에 적으신 그대로 채널에 전해요.」
  - 왼쪽 명단: 「이 제품에 맞는 채널」(의뢰서 업종 → topics 짝: food→food · daily, beauty→beauty · daily, fashion→fashion, living→home · daily, app→tech · daily, place→daily · food · outdoor, brand→전부)을 먼저, 그 아래 「다른 채널」. 거르개 칩(전체 · 주제들). 줄마다 대표 사진 · 이름 · 플랫폼 · 주제 · 누가 보는지 · 숫자(있을 때만) · 값 한 줄 · 「가상 인물」 · 「예시 채널」 표시 · 장면 그림 석 장(있을 때) · 고르기.
  - 오른쪽 「광고 의뢰」: 고른 채널(빼기), 맡길 일(올리기 기본 · 후기 함께), 우리 광고에도 쓰기(안 써요 · 30일 · 90일), 한마디, 값 합계(고른 칸 모두 값이 있을 때만 숫자, 아니면 「확인한 뒤 알려 드려요」), 「의뢰 보내기」. 아래 작은 글: 「결제는 게시물을 확인하신 뒤에 해요」, 「채널 게시물에는 「광고」 표시가 붙어요」(가상 인물 칸을 고르면 「가상 인물」 표시도).
  - 후기 · 2차 활용의 값은 아직 정하지 않았다(결정 11-16 · 11-18 「마케팅 서비스는 값을 정하지 않았다」). 칸에 값이 없으면 숫자를 지어내지 않는다.
  - 보낸 뒤: 같은 자리에 진행 줄(보냄 · 담당자 확인 · 채널 수락 · 게시 · 결과)과 보낸 내용, 게시물 주소, 결과 한 줄. sent일 때 「의뢰 거두기」. 끝나거나 닫힌 의뢰는 「지난 의뢰」로 접고 새 의뢰를 쓸 수 있다.
- 나눈 말 일지에 의뢰 사건 줄(보냄 · 확인 · 수락 · 게시 · 결과 · 닫힘)을 더한다.
- 다국어: 손님 글은 `t()`와 `i18n/en.mjs`. 채널 이름 · 한 줄은 직원이 쓴 그대로.
- 무대 판 문법(낮 판 data-day는 방에만 — 이 창은 마케팅 칸처럼 방 밖 화면이다). CSP 안(style 속성 없음). 새 모듈 `people-view.mjs`는 지연 import하고 server.mjs 정적 허용 목록 · sw.js RUNTIME에 더한다. 새 글자가 첫 화면 글꼴 조각 밖이면 `tools/build-pulse-fonts.py`를 다시 돌린다.

## 5. 담당자 칸 (desk)

- desk 오른쪽 `desk-side`에 `progressBlock`과 같은 꼴의 「인플루언서 광고 의뢰」 칸. 열린 의뢰 한 건을 크게(고른 채널 · 맡길 일 · 2차 활용 · 한마디 · 손님이 본 값), 다음 단계 단추 하나(「확인했어요」 → 「채널이 수락했어요」 → 「게시물 주소 넣기」 → 「결과 한 줄 쓰기」), 「닫기(까닭)」. 지난 의뢰는 접는다.
- 제작 보드의 「답할 문의」 셈처럼, sent 상태 의뢰는 그 프로젝트 칸에 「인플루언서 의뢰」 꼬리표로 보인다(돌봄 값 `careOf`에 더함).

## 6. 채널 명단 화면 (대표)

- 자리: 직원 머리 띠(제작 보드 · 운영판 · 고객 브랜드 옆) 「채널 명단」. 관리자만 보이고 쓴다. 지연 import `people-roster-view.mjs`(직원 화면, `// i18n-skip`).
- 칸 목록(대표 사진 · 이름 · 플랫폼 · 주제 · 예시 · 가상 · 켜짐), 칸 고치기 시트(3-1의 칸, 그림 올리기), 새 칸, 빼기(한 번 더 묻기), 순서 위아래.
- 맨 위 스위치 「손님에게 이 창 보이기」 — `/api/settings/pulse-features`의 `people`를 바꾼다(관리자, CSRF, 감사). 고를 수 있는 칸(예시 아님 · 켜짐)이 0이면 켤 때 「고를 수 있는 채널이 없어 손님에게는 준비 중으로 보여요」라고 알린다.
- 「손님 화면 미리 보기」: 고른 프로젝트 없이 예시 업종(음료)으로 손님 창을 그린다(보내기 막힘).
- 서버 경로: GET `/api/pulse-people`(관리자), POST `/api/pulse-people/roster`(전체 저장, 판 번호로 덮어쓰기 충돌 409), POST `/api/pulse-people/media`(그림 하나), 감사 `pulse-people-roster-saved`. 손님 경로: GET `/pulse/api/people`(스위치 켬 · 손님 세션 · 진행 중 프로젝트, 손님용 칸만 — example 칸 포함, active 거짓 빼고, 내부 메모 없음), GET `/pulse/api/people/media/<id>`.
- 몸통 한도 · Origin · CSRF · 몸통 다 읽은 뒤 세션 재확인 · 데모 요청 거절은 pulse-marketing-routes.mjs와 같게.

## 7. 파일

- 새로: `pulse-people.mjs`(명단 정규화 · 기본 명단 · 손님용 보기 · 그림 목록), `pulse-people-routes.mjs`, `public/pulse-app/people-view.mjs`(손님 창), `public/pulse-app/people-roster-view.mjs`(대표 화면), 시험 넷(서버 명단 · 경로 · 의뢰 동작 · 화면).
- 고침: `pulse-features.mjs`(people), `pulse-requests.mjs`(FIELDS · CUSTOMER_ONLY · STAFF_ONLY · 정규화), `client-notifications.mjs`(제목 다섯), `server.mjs`(선택 모듈 연결 · 경로 · 정적 허용 목록 · 손님 방 features), `public/pulse-app/` app.mjs · api.mjs · views.mjs · room-view.mjs(roomTab · careOf · journalModel) · film-views.mjs(foot · 끝맺음 한 줄) · desk-view.mjs · film.css · i18n/en.mjs · sw.js, 고정 시험(스위치 deepEqual, foot 바이트).
- 서버를 바꾸므로 검수는 GPT(백엔드)와 카본(화면) 뒤 Fable 최종이다.

## 8. 검토자에게 묻는 것

1. 의뢰를 프로젝트 문서(`studio.people`)에 두는 것이 맞나, 마케팅처럼 별도 문서 종류가 맞나. 프로젝트 문서에 두면 알림 · 일지 · revision이 지금 길로 돌지만 문서가 커지고 revision이 오른다.
2. 명단 그림을 전역 그림 저장소로 새로 두는 것(3-3)이 맞나. 더 작은 길(그림 주소만 받기, 캐스팅북 정적 그림만 허용)로 첫 판을 내고 나중에 올리기를 더하는 편이 나은가.
3. 예시 칸을 손님에게 보이되 고를 수 없게 하는 것(3-2)이 맞나, 아예 숨기는 것이 맞나. 유호님은 「몇명 채워줘. 내가 직접 교체할게」라고 하셨다.
4. 보이는 때(make 단계부터, 보낸 의뢰는 스위치가 꺼져도 보임)가 맞나.
5. 진행 단계 다섯과 「결제는 게시물을 확인하신 뒤」 문구가 지금 크몽 결제 흐름과 어긋나는 데가 있나.
6. 이 크기를 한 번에 만들지, 나눌지(예: ① 명단 · 스위치 · 손님 창 보기 → ② 의뢰 동작 · desk 칸 → ③ 그림 올리기). 나눈다면 첫 조각만으로 유호님이 「직접 교체」할 수 있어야 한다.

## 9. 설계 검토 반영 (Fable 5.2, 11-21)

### 조각 ① — 지금 만든다

- **명단과 스위치**: `pulse-people.mjs`(명단 정규화, 기본 여섯 칸), 문서 `pulsePeopleRoster`, 스위치 `people`(pulse-features.mjs, 기본 끔). 관리자 경로는 GET `/api/pulse-people`, POST `/api/pulse-people/roster`(판 번호가 다르면 409, 감사 `pulse-people-roster-saved`)다. 몸통 한도 · Origin · CSRF · 몸통을 다 읽은 뒤 세션 재확인 · 데모 거절은 마케팅 경로와 같다.
- **그림**: 캐스팅북 정적 그림 허용 목록(가상 인물 칸만)과 그림 없음(이름 첫 글자)뿐이다. 바깥 그림 주소와 올리기는 받지 않는다(P1-1 · P1-2, 물음 2).
- **예시 칸은 손님에게 숨긴다**(물음 3). `features.people`은 스위치가 켜졌고 고를 수 있는 칸(켜짐 · 예시 아님)이 하나 이상일 때만 참이다. 손님 경로 GET `/pulse/api/people`도 그때만 답하고, 아니면 404다.
- **실제 채널로 바꿀 때의 검사**(P2): `example:false`로 저장하는 칸은 채널 주소(https)가 있어야 한다. `virtual:false` 칸에는 캐스팅북 그림을 받지 않는다.
- **손님 창은 읽기 전용**이다. 명단, 거르개, 「이 제품에 맞는 채널」 먼저, 값은 있으면 보이고 없으면 「값은 채널과 확인한 뒤 알려 드려요」. 줄마다 「이 채널로 물어보기」가 나눈 말 일지의 묻기 칸에 채널 이름을 채운 글을 넣는다. 보내기는 지금의 문의 길이라 직원 알림 · 일지 · 돌봄 값이 서버 변경 없이 돈다. 「광고」 · 「가상인물」 표시 규정은 원문을 확인하지 않았으므로 손님 화면에 규정을 단정하는 글을 쓰지 않는다. 가상 인물 칸에는 「가상 인물」 이름표만 단다.
- **보이는 때**: 결제 확인 뒤(make 단계부터) 스위치가 켜져 있을 때. 체험 · 예시 화면에는 없다.
- **입구 셋**: 머리 단계 줄 끝 「인플루언서 광고」, 방 아래 입구 줄(마케팅 입구와 같은 꼴), 끝맺음 카드의 한 줄.
- **대표 화면**: 직원 머리 띠의 「채널 명단」(관리자만). 칸 목록, 고치기 시트, 새 칸, 빼기, 순서, 예시 · 가상 · 켜짐, 스위치 「손님에게 보이기」, 손님 화면 미리 보기(예시 칸 포함, 묻기 막힘).
- 서버를 바꾸므로 검수는 GPT(백엔드) · 카본(화면) 뒤 Fable 최종이다.

**구현(11-22).** 위 범위대로 만들었다. 검수에서 바뀐 규칙은 넷이다.

- 채널 주소의 길이는 저장할 꼴(인코딩한 주소)로 1000자까지 잰다. 한글 주소가 인코딩으로 길어져 저장 뒤 명단 전체가 깨지던 문제를 막았다.

- 「이 채널로 물어보기」는 묻기 칸이 비었거나 앞 단추가 채운 글이 그대로일 때 새 채널 글로 바꾼다. 손님이 고친 글은 그대로 둔다.
- 캐스팅북에서 빠진 그림은 그 칸의 그림만 비우고 명단은 살린다.
