# PULSE 고객 방 무대 판 · 담당자 보고와 소통 — 운영 설계 (2026-11-20)

유호님 11-20 「이 결로 진행」에 따라 [무대 판 시안](README.md#무대-판-11-20-유호님-짜임-살려-다시)을 운영 화면으로 옮기는 설계다. 만들기 전에 설계 검토를 받는다. 경로는 회사 폴더 `docs/마케팅/온라인마케팅지도/engagement/company/` 기준이고, 고객 앱은 그 아래 `public/pulse-app/`이다.

## 1. 목적

- **손님:** 방에 들어오면 첫 화면에서 세 가지를 안다. 누구 차례인지, 오늘 무엇이 나왔는지, 언제 받는지.
- **담당자:** 답할 문의와 소식이 밀린 손님을 한눈에 보고, 한 자리에서 보고하고 답한다.
- **결:** 만드는 날은 밝은 작업실이고, 보는 날은 불 꺼진 시사실이다. 지금 운영 판은 방까지 모두 검은 시사실 판(11-05 결정)이다. 이번에 방만 밝은 작업실로 바꾼다.

## 3. 조각과 순서

| 조각 | 내용 | 서버 | 검수 |
|---|---|---|---|
| A0 | 손님 방의 낮 판 바탕: 색 토큰, 선반과 인화지, 낮 판을 켜고 끄는 자리, 시험 정리 | 없음(캐시 판만 올림) | 고객 화면 행(카본 → 최종) |
| A1 | A0 위에 담당자 한마디, 받으실 날, 강조 구절, 「다음 편 묻기」 | 없음 | A0과 한 묶음으로 검수 |
| B1 | 담당자: 돌봄 값, 제작 보드의 꼬리표와 순서, 문의 알림이 여는 탭, D-day | 없음 | 내부 도구라 시험과 자기 점검 |
| B2 | 담당자: 의뢰 확인 화면의 「문의와 답」, 소식 쓰기 창의 미리 보기 | 없음 | 내부 도구라 시험과 자기 점검. A 뒤에 싣는다 |
| C | 독촉 알림: 평일 아침 담당자에게 「답할 문의 N건, 소식 없이 M일째」 | 새 타이머 | 이번에 만들지 않는다. B를 쓴 뒤 정한다 |
| D | Workspace 「고객 관리」에서 새 흐름 손님을 제작 보드로 보내는 링크 | 없음 | 이번에 만들지 않는다 |
| E | 인플루언서 광고 의뢰 창 | 새 기능 | 만들지 않는다. 명단을 누구로 시작할지 정하신 뒤 따로 설계한다 |

A0 → A1 → B1 → B2 순서로 만든다. A0과 A1은 한 판에, B1은 같은 판이나 다음 판에 싣는다. 응답 시간 약속 문구와 의뢰서 칸 정리는 답을 받지 않아 넣지 않는다.

아래 4절과 5절은 설계 검토 전의 글이다. 검토 뒤 바뀐 것은 9절 표에 있고, 어긋나면 9절이 맞다.

## 4. 조각 A — 손님 방

### 4-1. 바꾸지 않는 것

서버 동작과 `/pulse/api/*`, `roomState`와 `roomModel`의 판단, `data-room-go` · `data-room-do` · `data-form` · `data-journal-*` 이름, 폼과 필드 이름, 일지의 짜임과 동작, 1차안 · 방향 · 영상 확인 · 납품 칸 · 완성 광고 · 마케팅 성과 · 옛 탭의 결, 직원 화면. 승인받은 화면 글은 낱말 그대로 둔다.

### 4-2. 낮 판을 켜는 자리

- `roomView`(`film-views.mjs:334`)의 뿌리만 `class="sx-room is-day"`가 된다. `.sx-room`을 함께 쓰는 다른 화면(마케팅 성과 `views.mjs:378`, 옛 현황 `:452`, 문의만 있는 영상 화면 `:609`, 납품 `:629`, 완성 광고 `:656`, 방향 화면)은 그대로 어둡다.
- `mountRoom`(`film-views.mjs:454`)이 뿌리에 `.sx-room.is-day`가 있으면 `html`에 `sx-day`를 붙이고, `unmount`에서 뗀다. 앱(`app.mjs:141`)과 예시(`demo-film.mjs`)가 같은 `mountRoom`을 쓴다. 다른 화면을 그릴 때 남지 않게 `mountScreens`(`app.mjs:123`)도 방이 없으면 뗀다.
- 색 토큰은 `html` 전체가 아니라 두 범위에서만 바꾼다: `.sx-room.is-day`와 `html.sx-day:not(.is-staff) .app-header`. 대화상자, 알림 토스트(`.notice`), 연결 끊김 띠, 불러오는 중은 지금 값 그대로 두되 밝은 바탕에서 묻히지 않게 `html.sx-day`일 때 먹색 면으로 바꾼다.

```css
.sx-room.is-day{--sx-ink:#1d1d1f;--sx-dim:rgba(29,29,31,.72);--sx-faint:rgba(29,29,31,.5);--sx-rule:#E2DED9;--sx-acc:#F2573F;background:#fff;color:var(--sx-ink)}
html.sx.sx-day,html.sx.sx-day body{background:#fff;color-scheme:light}
```

- 방 구역(`film.css:712-831`)과 일지 구역(`:1242-1370`)에 굳은 색(`#000`, `#0a0a0a`, `rgba(244,241,234,…)` 등)이 있다. 낮 판 절을 `film.css` 끝에 따로 두고 그 굳은 색만 덮는다. 기존 규칙은 고치지 않는다.
- 머리의 로고는 밝은 바탕용 승인 로고로 바꾼다. 지금 파일(`assets/request/logo-paper.webp`)은 미색 글자라 흰 바탕에서 안 보인다. 승인 로고 파일을 `assets/request/`에 더하고 `server.mjs` 공개 목록과 `sw.js` 목록에 한 줄씩 넣는다.

### 4-3. 글자와 강조

- 방 제목(`.sx-display`)은 낮 판에서 본문 고딕 800, 자간 −0.045em이다(시안과 같은 값). 명조 300은 어두운 화면에 남는다.
- 강조는 코랄 한 구절이다. 상태 글 표(`ROOM_COPY`와 `copyBase`)의 줄에 `mark`(강조할 구절)를 적고, 그리는 자리에서 번역한 제목 안에 번역한 `mark`가 들어 있을 때만 감싼다. 없으면 강조 없이 그린다. 제목 글 자체는 바꾸지 않는다.
- 코랄은 그 구절, 「저희 차례」 점, 받으실 날의 숫자 세 곳에만 쓴다. 단추는 먹색 면 하나다.

### 4-4. 선반과 인화지

오른쪽 큰 칸(`.sx-room-screen`)을 밝은 벽과 선반으로 바꾼다. 마크업은 지금 함수(`roomScreen`, `roomPreviewScreen`)가 내는 것을 그대로 쓰고 CSS로 인화지처럼 세운다. 기울기와 순서는 `:nth-child` 규칙으로 준다(CSP 때문에 style 속성을 쓰지 않는다).

| 지금 자료 | 선반 위 모습 |
|---|---|
| 작업 소식 그림 1~4장(`.sx-room-files`, `img.sx-q-fill`) | 인화지를 한 장씩 세운다. 그림 비율은 그대로(높이 고정, 폭은 그림대로). 아래에 「작업 중인 화면이에요 · 완성본이 아니에요」와 「소식 보기」 |
| 도착한 영상(`video[data-room-film]`) | 큰 인화지 한 장. 소리 없이 돌고, 누르면 영상 확인으로 간다. 재생 표를 단다 |
| 완성 사진(`.sx-room-files.is-shots`) | 인화지 여러 장 |
| 장면 이미지 컷(`.sx-room-cuts`, 12컷까지) | 흰 밀착 인화지 한 장에 격자 |
| 글 콘티(`.sx-room-word`) | 대본 종이 한 장 |
| 모델 제안, 고른 방향, 맞춤 인물 | 큰 인화지 한 장. 「다른 모델 보기」 덮개는 벽 색 |
| 없음(`is-no-screen`) | 지금처럼 왼쪽 글과 일지 두 단 |

- 캡션(`.sx-room-cap`)은 그림 위에 얹지 않고 선반 아래에 둔다.
- 넓은 화면에서 오른쪽 칸은 지금처럼 화면 높이에 붙어 있다. 휴대폰과 세로 화면에서는 글 아래로 내려가고 인화지는 가로로 민다.
- 들어올 때 인화지가 한 장씩 8px 올라와 선다(80ms 간격). 움직임 줄이기면 바로 선다. 큰 이동과 반복 움직임은 넣지 않는다.

### 4-5. 담당자 한마디

- `roomModel`에 `word`를 더한다. 저희 차례일 때, 차례가 넘어온 뒤(`turnSince`) 올라온 소식 가운데 가장 최근 것의 `{id, at, text}`다. 그림이 없는 소식도 고른다. 지금 `news`(그림이 있는 최근 소식)는 그대로 둔다.
- 방 왼쪽의 안내 글 아래에 인용으로 그린다. 담당자 이름(`manager`)과 시각을 붙인다. 넉 줄이 넘으면 접고 「더 보기」로 제자리에서 편다.
- 일지의 같은 소식 줄은 글을 다시 적지 않고 머리 줄과 「지금 화면」 표만 둔다. 지금 인용 줄이 쓰는 방식(`isHere`)과 같다.

### 4-6. 받으실 날

- `roomModel`에 `due`를 더한다. 결제를 확인했고 `payment.dueDate`가 있고 상태가 납품 · 끝이 아닐 때만 `{date, changed}`다. 그 밖에는 없다(날짜를 약속하지 않은 손님에게 보이지 않는다).
- 방 왼쪽에 한 줄로 그린다: 「3일 뒤 · 11월 23일 월요일에 받으세요」. 남은 날은 한국 시각 오늘 기준이다. 오늘이면 「오늘」, 지났으면 남은 날 없이 날짜만 적는다. 담당자가 고친 날이면 「담당자가 다시 정한 날」을 붙인다.
- 아래 의뢰서 요약의 「받으실 날」 줄은 그대로 둔다.

### 4-7. 끝맺음

- 끝맺음 칸(`doneCard`)의 셋째 줄 옆에 「다음 편 묻기」 단추를 둔다. 누르면 일지를 열고 묻기 칸에 「같은 모델로 다음 편을 이어 만들고 싶어요.」를 채운다. 보내기는 손님이 누른다.
- 마케팅 숫자를 약속하는 글과 인플루언서 입구는 넣지 않는다.

### 4-8. 바뀌는 파일

- `public/pulse-app/film-views.mjs`: `roomView`(뿌리 클래스, 한마디, 받으실 날, 강조 구절), `journalView`(지금 화면 표), `doneCard`, `mountRoom`.
- `public/pulse-app/room-view.mjs`: `roomModel`의 `word` · `due`, 상태 글 표의 `mark`.
- `public/pulse-app/film.css`: 끝에 낮 판 절.
- `public/pulse-app/app.mjs`: `mountScreens`에서 `sx-day` 떼기, 「다음 편 묻기」 처리.
- `public/pulse-app/i18n/en.mjs`: 새 글.
- `public/pulse-app/demo-film.mjs`: 예시 자료에 한마디와 받으실 날.
- `public/pulse-app/assets/request/`: 밝은 바탕용 로고. `server.mjs` 공개 목록, `public/pulse-app/sw.js` 목록과 판.
- 시험: 새 `pulse-room-day.test.mjs`, 고칠 것은 `pulse-room-one` · `pulse-room-rebuild` · `pulse-progress-screen` · `pulse-journal` · `pulse-customer-copy` · `pulse-film-screens` · `pulse-i18n-*`.

## 5. 조각 B — 담당자

### 5-1. 돌봄 값 한 곳

`room-view.mjs`의 직원 구역에 `careOf(p, now)`를 둔다. 제작 보드와 의뢰 확인 화면이 같은 값을 쓴다.

- `asks`: 답하지 않은 손님 문의 수. 손님이 쓴 `support` 글 가운데, 사람이 쓴 직원 답(손님에게 보이는 글, 자동 안내 제외)보다 뒤에 왔고 처리 표시(`resolved`)가 없는 것.
- `askSince`: 그 가운데 가장 오래된 글의 시각.
- `quiet`: 저희 차례일 때, 손님에게 마지막으로 닿은 일(올린 소식, 사람이 쓴 직원 답, 차례가 넘어온 때) 뒤로 지난 평일 수. 토요일과 일요일은 세지 않는다. 공휴일은 보지 않는다.
- 영상 의견은 지금 흐름(의견 묶음과 처리 상태)이 맡으므로 세지 않는다.

### 5-2. 제작 보드

- 카드(`staffCard`, `views.mjs:153`)에 꼬리표 둘: 「답할 문의 2 · 3시간째」, 「소식 없이 평일 2일째」(2일부터).
- 줄 세우기: 「우리 차례」 칸은 답할 문의가 있는 건이 맨 위(오래된 문의 먼저), 다음은 지금처럼 D-day 순. 손님 차례 칸에서도 답할 문의가 있는 건은 맨 위로 올린다.
- 머리 숫자에 「답할 문의」를 더한다.
- D-day는 새 흐름에서 결제를 확인한 뒤에는 `payment.dueDate`를 먼저 쓴다.

### 5-3. 의뢰 확인 화면의 「문의와 답」

- 오른쪽 단 맨 위에 손님 문의와 답을 최근 것부터 보이고(답하지 않은 문의에 표), 아래에 답 칸을 둔다. 보내기는 지금 API(`POST /api/client-projects/:id/messages`, 손님에게 보임)다. 붙인 사진은 지금 주소로 보인다.
- 의뢰서가 있는 프로젝트에서 문의 알림을 누르면 의뢰 확인 탭이 열린다.

### 5-4. 소식 쓰기 창의 미리 보기

- 창(`views.mjs:821`) 오른쪽에 「손님 방에 걸릴 모습」을 둔다. 고른 그림과 쓴 글로 조각 A의 선반과 한마디를 그대로 그린다(같은 함수와 같은 CSS, 작게).
- 글이나 그림을 바꾸면 미리 보기가 따라 바뀐다. 저장과 올리기 동작은 그대로다.

### 5-5. 바뀌는 파일

`room-view.mjs`(`careOf`, `staffBoard`), `views.mjs`(`staffCard`, `picker`, 소식 창), `desk-view.mjs`(「문의와 답」), `app.mjs`(답 보내기, 알림 탭), `staff.css` · `slate-screens.css`. 시험은 새 `pulse-care.test.mjs`와 `pulse-staff-board` · `pulse-progress-screen` 고침.

## 6. 시험 계획

- **함수 시험:** 상태마다 `roomView`의 낮 판 마크업(뿌리 클래스, 한마디, 받으실 날, 강조 구절, style 속성 없음, 기존 `data-*` 이름 그대로). `careOf`의 경우들(자동 안내만 달린 문의, 처리 표시, 주말, 손님 차례).
