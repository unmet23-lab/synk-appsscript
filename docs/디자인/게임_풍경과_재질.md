## 현행 확정 — 2026-10-09

**SYNK WORLD는 ‘몽글다운 형태에 실제 재료의 촉감과 빛을 입힌 3D 세계’를 공통 그래픽 방향으로 삼는다.** 사용자가 사실적이고 만지고 싶은 질감을 요청하고 3D 공간·2D 표면 정보의 역할을 확인한 뒤, 「오케이 그럼 앞으로 우리 synk world 앱은 이렇게 그래픽 방향을 잡자」고 확정했다.

2026-10-09 후속 품질 요구: 현재 홈보다 한 단계 높은 그래픽, **최소 기존 레이싱 미니게임 이상의 품질**을 목표로 한다. 현재 시제품을 완성 미술로 확정하지 않고, 모델·옷·재료·조명·공간·움직임을 함께 높인다. [2차 비교안과 본 제작 기준](../../experiences/synk-world-home/scene-assets/graphics-v2/README.md)에 구현 후보와 남은 정식 자산·실기기 검증을 구분했다.

- **플레이어 몽글:** 승인된 몽글의 얼굴·색·팔 없는 실루엣을 유지한다. 입체적인 몸과 의상, 봉제선·섬유·옷 두께·접촉 그림자로 실제 인형 같은 촉감을 표현한다. 몽글의 3D화를 이유로 팔·손을 추가하거나 얼굴을 임의로 바꾸지 않는다.
- **재료:** 몽글은 펠트, 옷은 니트·면·가죽, 생활 소품은 나무·돌·도자기·유리 등 각 재료에 맞는 형태·요철·거칠기·빛 반응을 쓴다. 가까운 자연물이나 세계 전체를 펠트로 통일하지 않는다. 공통 색·형태·조명 기준으로 한 세계의 인상을 유지한다.
- **공간:** 이동·회전·착용·상호작용하는 공간과 물체는 3D를 중심으로 만든다. 미래 한국의 산·건물도 입체적으로 구성할 수 있다. 가까운 곳은 촉감과 두께, 먼 곳은 큰 형태·빛·안개·대기 원근으로 깊이를 표현한다. 이전의 ‘회화적인 원경’은 2D 배경 그림이나 붓 표현을 의무화하는 현행 기준이 아니다.
- **3D와 2D의 역할:** 3D 모델에 표면 정보를 담은 2D 텍스처를 사용하는 것은 정상적인 3D 제작 방식이다. 실루엣·옷 두께·큰 주름은 입체 형태로, 작은 결은 표면 정보로 표현한다. 자막·버튼·설명 카드·목록은 읽기와 조작에 맞는 2D UI를 쓰며 기존 펠트 UI 마감 기준을 적용한다. 모든 화면 요소를 실시간 3D로 만들 필요는 없다.
- **콘텐츠와 보상:** 홈·옷장·미니게임·싱크 타운·사진은 같은 캐릭터와 코스튬 자산·착용 상태를 공유하는 방향으로 설계한다. 미니게임에서 획득한 동일 아이템이 타운에서도 유지되어야 한다. 한국어 초급 노래·캐릭터 영상도 같은 자산과 미술 기준을 활용하되 영상은 사전 렌더링할 수 있다. 학습 UI나 기존 실사 콘텐츠까지 모두 3D 캐릭터로 대체하는 결정은 아니다.
- **코스튬 제작:** 승인된 기준 몸·뼈대와 부착 위치를 먼저 정하고 의상·장식을 모듈로 추가한다. 옷에 가려진 몸, 조합별 충돌, 동작 중 뚫림을 검수한다. 기본 자산을 따로 만든다고 조합 검수가 없어지는 것은 아니다.
- **모바일과 PC:** 휴대폰 주력, Galaxy S25·iPhone 15 기본형을 품질 검증 기준으로 삼는다. 모바일은 지속 성능·발열·읽힘·조작을 함께 확인하고, PC는 같은 미감에서 조명·그림자·식물·해상도를 확장한다. 가까운 옷장과 먼 타운 캐릭터의 세부 표현을 조절한다. 실제 FPS·메모리 한도와 최소 지원 OS는 실기기 검증 전 확정값으로 쓰지 않는다.

이번 확정은 **SYNK WORLD 앱 내부 콘텐츠의 공통 미술 방향**이다. 아래의 2026-09 그림·2.5D·시제품 기록보다 우선하며, 회사 홈페이지와 다른 브랜드를 일괄 개편하는 결정은 아니다. 기존 자산·구현 기록은 보존한다. Unity + URP·Blender·공식 CLI 구성은 [2026-10-09 제작 조사](../../output/synk-world-graphics-research-20261008/report/src/content/report/engineering-text.js)의 기술 권고로 구분한다. 이번 문서 반영은 엔진 설치·전체 이관·완성 3D 자산·실기기 검증·배포 완료를 뜻하지 않는다.

### 메인 화면 발전 기준 — 2026-10-09 사용자 채택

후속 사용자 정정: **“그래픽도 방향이 맞다는거지 아직 만족스럽다는 절대 아니야.”** 홈 v2는 미술 방향의 참고이며 현재 완성도 만족·최종 품질 승인이 아니다. 기본 홈·첫 방문/보상/재방문·공통 캐릭터/코스튬 연결을 진행하면서 조형·천의 두께와 주름·섬유 크기·공간의 재료와 빛을 한 단계 더 개선한다. 설치형 앱은 코드 준비와 검사를 진행하되, 사용자가 이번 범위를 **코드·브라우저 검증까지**로 정했으므로 Unity 설치/로그인·실물 기기 검증은 준비 상태와 남은 조건을 구분한다.

사용자가 [휴대폰·PC 메인 화면](../../experiences/synk-world-home/README.md)을 확인한 뒤 「훨씬 괜찮네. 고생했어. 앞으로 이 방향을 발전시키는거로 하자」고 확정했다. **캐릭터 중심 홈을 후속 프런트 작업의 기준으로 삼아 발전시킨다.**

- 3D 몽글과 생활 공간을 홈의 중심에 두고, 만지고 싶은 재질·부드러운 빛·여백 있는 UI를 유지한다.
- 휴대폰의 세로 구성·하단 탐색을 우선하고, PC는 같은 콘텐츠를 넓은 장면·왼쪽 탐색으로 구성한다.
- 미니게임·옷장·싱크 타운·한국어 노래 영상이 하나의 홈에서 자연스럽게 이어지도록 발전시킨다. 같은 아이템의 획득·착용·생활 공간 사용은 공통 보상 설계에 맞춰 연결한다.
- 현재 구현과 최종 화면 캡처를 비교 기준으로 보존하며, 재질·움직임·상호작용·휴대폰 마감을 점진적으로 높인다. 이번 채택은 화면과 그래픽 발전 방향에 대한 승인이다. 시제품 몽글을 최종 마스터 모델로 확정하거나 Three.js를 본 제작 엔진으로 확정한 것은 아니다.

## 이전 방향과 제작 기록 — 2026-09

2026-09-19 사용자가 비교 시안 2번의 시원한 풍경을 좋아했고, 먼 풍경은 그 회화적 표현을 유지하며 가까운 부분만 펠트로 만들도록 방향을 확정했다. 이후 같은 그래픽으로 한국어 게임을 요청했다.

### 당시 방향과 후속 기록

2026-09-21 그래픽 설정 확정: 사용자에게는 **`균형`(발열·성능 등 최적화 우선) / `경험`(그래픽 품질 우선)** 두 가지 선택지만 제공한다. 시점의 ‘넓게 보기 / 가까이 보기’와 독립적으로 선택한다. 모바일 기본값 ‘균형’과 기기별 내부 설정은 설계 제안이며 구체 성능은 검증 전이다. [풍경 원문의 그래픽 설정](미래한국_마을_풍경.md)에 확정 범위와 제안을 기록했다.

2026-09-21 이동·시점 최신 후속: 사용자는 **바닥 한 번 탭으로 걸어가기**를 선호하고, **충분히 먼 시점을 기본으로 가까운 시점도 선택**하는 구성을 제시했다. 두 시점에서 오른쪽 근접 행동 목록을 그대로 유지하는 방향을 권한다. 시점 명칭·거리·각도·전환·읽힘·편안함의 세부는 [풍경 원문](미래한국_마을_풍경.md)에 제안으로 기록했다. 먼 시점의 멀미 부재나 실기기 성능을 보장하는 결정은 아니다.

2026-09-21 모바일 조작 후속 확정: 물 주기·수확·채집·NPC 대화는 대상을 직접 터치할 필요 없이 **가까이 가면 오른쪽 위의 고정 영역에 행동 목록이 자동 표시되고, 원하는 줄을 눌러 실행**한다. 여러 대상·행동이 겹치면 각각 여러 줄로 함께 나열한다. 기존 작물·NPC 직접 탭과 단일 대상 자동 선택 제안을 대체한다. 자동 수확·원거리 자동 이동까지 확정한 것은 아니다. [풍경 원문의 조작 설계](미래한국_마을_풍경.md)에 대상 구별·목록 스크롤 등의 세부 제안과 구현 상태를 구분했다.

2026-09-21 그래픽 후속: 사용자는 Satisfactory 다음으로 **Planet Coaster 2의 그래픽도 선호 후보**로 제시했다. 단일 원작 화풍을 확정하지 않고 미래 한국·펠트·높은 마감 품질을 유지한다. **모바일이 주 플레이 플랫폼**이므로 간단한 조작과 3D 화면 움직임의 편안함을 함께 설계한다. 이동·시점에 대한 이후 사용자 선호는 위 최신 후속을 따르며 [풍경 원문](미래한국_마을_풍경.md)에 근거·한계와 함께 기록했다.

2026-09-21 최신 확정: 사용자는 **RPG를 기각**하고, **정원 16명의 마을에서 NPC 커뮤니티·농사·채집·제작·꾸미기·관리하고 성장시키는 재미**를 강화하는 방향을 요청했다. 특정 Steam 게임을 채택한 것은 아니며, [생활·경영 게임 조사](마을_생활경영_스팀조사_20260921.md)에서 참고할 작품과 구조를 비교한다. 앞서 논의한 몬스터·한국어 퀴즈 전투는 현재 개발 요구가 아니다. 기존 그래픽 방향과 시제품·원본은 보존한다.

2026-09-21 후속 확정: 미래 한국의 풍경은 **PC와 모바일의 크로스플랫폼**을 목표로 한다. PC에서는 실제처럼 느껴지는 높은 그래픽 품질을 우선하고 모바일은 표현을 조정하며, 장소마다 낮·밤·비·눈이 자연스럽게 바뀌도록 설계한다. 가까운 펠트·팔 없는 몽글의 승인은 유지한다. 원경의 회화적 감동을 입체 공간으로 옮기는 방법과 PC·모바일별 표현은 [미래 한국 마을 풍경의 최신 후속](미래한국_마을_풍경.md)에 추천안과 확정 사항을 구분해 기록했다. 최종 엔진과 자연물의 재질 비율은 아직 확정하지 않았다.

PC는 현존 최상위급 GPU를 기준으로 삼아도 되는 **홍보 중심의 최고 시각 품질**, 모바일은 **실제 구동 가능한 최상의 품질**이라는 후속 우선순위를 반영한다. PC 이용자가 많지 않을 것이라는 말은 사용자 예상이며 측정 결과가 아니다. 16인 마을을 줄이거나 폐기하는 결정은 없으며, 실시간 플레이와 홍보용 영상 출력의 품질·성능은 구분해 검증한다.

같은 날 사용자는 **가까운 몽글의 마감과 넓은 풍경의 품질을 살리고, 멀리서 구별되지 않는 미세한 계산을 줄여 조명·재질에 여유를 쓰는 최적화**를 승인했다. 특히 PC의 제작 기준으로 적용한다. 꾸미기 자산의 재질·조명 기준을 함께 두고, 16인 인원수를 줄이기 전에 이 방식으로 개선한다. 구현 시에는 거리별 표현의 갑작스러운 변화·깜빡임과 접사 품질을 확인한다. 세부 승인과 구현 해석은 [미래 한국 마을 풍경](미래한국_마을_풍경.md)에 기록했다.

2026-09-19 확정 후 유지하는 풍경 방향: 모든 풍경은 **100~200년 뒤 한국의 대표 명소**로 재해석한다. 같은 남산도 크게 변화한 아름답고 찬란한 모습으로 만든다. RPG 기각 이후에도 장소·시대·재질 방향은 유지하며, 사용자 결정과 첫 창작안은 [미래 한국 마을 풍경](미래한국_마을_풍경.md)에 구분해 기록했다.

- 먼 하늘·산·구름·절벽·폭포: 넓은 여백, 겹쳐지는 색면, 대기 원근과 섬세한 붓 표현. 펠트 섬유나 천 질감을 화면 전체에 덧씌우지 않는다.
- 가까운 땅·나무·바위·꽃·플레이 소품: 실제 섬유, 절단면의 두께, 재료 간 접촉 그림자. 펠트의 발견은 가까운 곳에 집중한다.
- 원경이 첫인상과 공간감을 맡는다. 큰 근경 나무나 UI가 중요한 산·하늘·폭포를 모두 가리지 않게 한다.
- 따뜻한 빛과 회청·보라 산의 색 관계를 유지한다. 원경과 근경의 광원은 함께 맞춘다.
- 몽글의 얼굴·종 모양 몸·물결 밑단을 유지한다. 사용자는 2026-09-19 기존 몽글 컷이 풍경에서 떠 보인다며 이 게임에 맞춘 재제작을 요청했다. 게임 전용 파생형은 숲의 광원과 재질, 좌우 시점·접지·착지에 맞춘다. **팔은 없는 컨셉**이라는 후속 정정을 우선한다. 이동과 소품 사용을 위해 팔·손을 추가하지 않는다.
- Neva는 사용자가 든 풍경 표현의 참고다. 장면·캐릭터·음악·원본 게임 자산을 복제하라는 지시가 아니다.

이 지침은 이번에 이어가는 풍경 중심 게임의 방향이다. 기존 회사 홈페이지, 다른 학습 게임이나 모든 브랜드 장면을 일괄 변경하는 뜻은 아니다.

## 풍경 감상 중심의 다른 게임

2026-09-19 사용자는 아름다운 배경과 드림코어처럼 보는 즐거움이 큰 콘텐츠를 확장하고, 같은 방향으로 다른 한국어 액션 게임을 요청했다.

- [꿈결의 정원](../../experiences/dokkaebi-express/dream.html): 구름 바다의 유적, 거울 호수, 거대한 달이 뜬 정원 세 장면. 더블점프·공중 대시로 탐험하며 높이·순서·사이의 한국어 단서에 맞는 빛을 깨워 출구를 연다.
- 먼 장면의 여백과 규모가 화면을 주도하고, 가까운 발판·나무·문·종·꽃은 실제 섬유가 보이는 펠트다. 몽글은 승인된 팔 없는 게임 전용 v2를 쓴다.
- 현재는 Canvas 2D의 배경 그림·수면 부분 움직임·안개·시차·접지 표현이다. 배경 전체를 여러 깊이로 재구축하거나 PBR 재질을 구현했다는 뜻은 아니다.
- 완주 후 풍경 감상 모드에서 세 장면을 선택할 수 있다. 모바일 배경 크기·해상도 조절과 작은 화면 조작 배치를 별도로 적용했다.
- [원본과 프롬프트](../../experiences/dokkaebi-express/art-direction/dream-garden-20260919/README.md), [검증 범위](../../experiences/dokkaebi-express/qa/dream/RESULTS.md). 로컬 구현이며 공개 배포·실제 휴대폰 성능·학생 학습 효과는 별도 검증 대상이다.

## 직접 걸어 다니는 3D 마을

2026-09-19 사용자는 같은 재질 방향으로 16명 반의 마을을 체험하고, 마을 시점·따라가기 시점·두 시점 전환형 세 안 모두를 비교하도록 요청했다.

- [바람꽃 마을](../../experiences/dokkaebi-express/village.html): 실제 메시로 만든 팔 없는 몽글과 16개 집, 광장·게시판·연못·풍경 쉼터. 가까운 물체는 펠트 PBR, 먼 산과 호수는 새로 생성한 파노라마다.
- 같은 마을의 카메라만 세 방식으로 비교한다. 내 집 색 3종·장식 3종, 이동·달리기·점프, 한국어 자기 말풍선을 포함한다. 새 게임용 3D 몽글이며 전역 캐릭터 원본을 교체하지 않는다.
- 시각·게임 구현과 실제 반·마을·계정·교사 관리의 연결은 담당 원문에서 이어간다. 모델별 담당은 고정하지 않는다. 일반 사용자의 주 1회 활성 마을 이동과 오프라인 학원생의 고정 구성은 [코어 인계](../../experiences/dokkaebi-express/art-direction/village-20260919/CORE-HANDOFF.md)에 구분했다.
- [원본·전체 프롬프트](../../experiences/dokkaebi-express/art-direction/village-20260919/README.md), [검증 기록](../../experiences/dokkaebi-express/qa/village/RESULTS.md). 로컬 시제품이며 실제 16인 접속·채팅·교사 출석·꾸미기 구매·공개 배포는 연결하지 않았다. 세 시점의 최종 선택과 이 3D 실물의 디자인 승인은 사용자 비교 후에 정한다.
