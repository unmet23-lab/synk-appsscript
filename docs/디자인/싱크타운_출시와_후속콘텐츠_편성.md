# 싱크타운 출시 후보와 후속 콘텐츠 편성

2026-10-09. 열 가지 생활 전부를 유지하면서 **첫 실행 시험, 전체 출시 후보, 원고 소진 뒤 생활, 첫 후속 묶음**을 구분한다. 출시일·정기 업데이트 주기·결제 상품 확정이 아니다. 아래 편성은 제작할 범위이며 실제 자산·게임 실행·플레이 검증이 완료된 목록과 분리한다.

정본: [열 가지 생활 카드](싱크타운_10대생활콘텐츠_제작설계_20261008.md#map) · [첫 플레이](싱크타운_첫플레이_실행설계.md#space) · [첫 생활 원고](싱크타운_첫생활구간_원고.md#reading) · [주민 연속 원고](싱크타운_주민관계와_연속생활_원고.md#verification) · [재방문 원고](싱크타운_재방문_콘텐츠와_원고.md#coverage) · [경제·권한](싱크타운_생활경제와_상품_설계.md#expiry) · [공연](싱크타운_공연과_생활학습_설계_20261008.md#performance-scope).

| ASSIST-TEST / 생활 비서 확장 | [ASST01~05](../마을_설계.md#world-life-assistant). 기존 가이드에 생활 선택·재료/제작·버스·재개·한국어 도움을 연결 | 실제 상태 차이가 답과 입구를 바꿈. 정보 부재·조용히·거절·권한과 직접 실행 경계를 확인. 새 별도 AI 비서 엔진이 아님 |

제작 단위는 사용자에게 순서대로 모두 끝내라고 주는 코스가 아니다. TEST가 작다고 LAUNCH 범위를 줄이지 않고, FOLLOW를 추가했다고 LAUNCH 미완료를 미루지 않는다. FOLLOW-01 뒤 새 팩·새 주민·새 공간·새 통화는 자동 추가하지 않는다. **2026-10-09 사용자가 명시한 버스·한국 명소 여행·지역 재료·펫·비서·낚시는 별도 확장 설계로 추가**하며, 그 요청을 다른 미승인 공간·상품 추가의 근거로 넓히지 않는다.

**집계 원칙:** LS01.1/02.1/03.1은 FT10/20/30의 실제 사건을 재사용한다. LS 12회차를 FT와 합쳐 12개 신규로 세지 않는다. RETURN 두 원형은 LS01.4/LS03.4 실행에 포함되고 BG6은 반복 일과다. RV24는 별도 문제를 다루는 24개 원고이며 실제 사건이 LS와 겹치면 `sourceEventId` 하나로 집계한다. T01~10은 놀이 구조 10종이고 장편 10편이라는 뜻이 아니다. P01/M01의 A/B·지원판·곡 배열은 작품 편수를 늘리지 않는다.

**주민/장소 의존성:** 첫 고정 생활 배역은 찻집 주인·공방 주인·연구원이다. 책을 가져온 손님과 회차 동행자는 방문객 원고이며 새 장편 주민이 아니다. FT40 공방 갈래의 찻집 영업을 맡는 보조 배역은 기존 FT40 원고의 실행 의존성으로 포함한다. 보조 역할·차·운반 경로가 없을 때 E1 장소 변경을 제공하지만, 그것만으로 FT40 B가 제작됐다고 보고하지 않는다. 정본의 역할을 누가 표현할지는 승인 자산 배역에 대응해야 하며 기존 한말순·오미자·슬을 이름만 바꿔 대역으로 넣지 않는다.

FT40/54는 찻집·공방의 초대 전달/자리 변경으로 끝나며 **BRIDGE-G/M/S나 기존 11장편의 본문이 선행이 아니다.** 따라서 CONNECTION-01의 제작 순서를 뒤에 두어도 첫 사연 경로를 잠그지 않는다. 원형 사건 C01~08·후속 A/B 16개는 설계 은행으로 보존하고 위 실제 원고에서 재사용한 사건만 실제 제공 목록에 센다. 나머지 원형의 제목만으로 대본과 실행이 끝났다고 표시하지 않는다.

## 3 열 가지 전부가 포함됐다는 실제 증거

이 표는 대표 증거 위치다. 대표 한 장면만으로 같은 카드의 다른 A/B·중단·동의 조건을 생략하지 않는다. 각 카드의 전체 계약이 통과해야 그 구조를 제공 목록에 표시한다.

| 구조 | 현재 방문에서 보여야 할 행동 | 다음 생활에서 읽을 실제 흔적 | 주된 원고·계약 |
|---|---|---|---|
| T01 일과·이야기 | 공방 주인의 자기 일/휴식이 있고 내가 고른 방향대로 사용 | 유효 자리와 아는 사건에 맞는 다음 일과 | LS01, BG, NPC 자율생활 |
| T02 즉각 반응 | 같은 물건을 놓고 돌리면 NPC 경로/시선/이용이 달라짐 | 현재 개정과 과거 완료를 구별 | FT10, RV01/11, T02 |
| T03 모임 연속극 | 개인 선택 때문에 다음 모임의 역할·순서가 다름 | 실제 합의·참여자 인지 | LS01~03, RV12/17 |
| T04 추천 | 현재 요청을 듣고 실제 메뉴/컵/제공 방법을 바꿈 | 이번 목적·실제 제공, 고정 취향으로 단정하지 않음 | FT20/52, LS02, RV16 |
| T05 기억·보답 | 실제 도운 NPC가 준비/역할을 맡거나 쉴 자리를 내줌 | 원인 사건을 아는 같은 NPC의 후속 행동 | RETURN01/02, LS01.4/03.4 |
| T06 발견과 집 | 발견 기록 참조와 실제 소유 화분을 구분해 집에서 봄 | 같은 개체·기록 출처, 표본 소유 세탁0 | FT30/53, T06, RV20 |
| T07 동행·손님 | 동행/자리에서 보기, 실제 허용한 집 초대/쉼터 대안 | 동행 범위·장소 동의·실제 관람 | T07 전체, RV12/17, C06의 재사용 계약 |
| T08 준비·생장 | 승인 준비는 큐의 실제 착수 후, 성장은 같은 화분 단계로 진행 | 복귀해 완료물은 남고 다음 선택은 내가 함 | T08 A/B, 경제 순차 큐, RV20 |
| T09 작은 장터 | 진열·역할·두 손님 요청을 직접 바꾸고 마침 | 비판매 관람과 실제 판매/소유/정산 분리 | T09 전체, LS02.3, RV13/18, RQ |
| T10 주민 제안·발전 | NPC의 실제 필요에서 개인 기능/배치 선택과 사용 시험 | 바뀐 기능이 다음 주민 사용 후보로 남음 | T10 A/B, LS01/03, RV14/24 |

개인 마을에서 열 가지를 모두 완결할 수 있어야 한다. 공유 마을의 동의/예약/공용 NPC 계약은 정본 범위대로 따로 확인하며 개인 화면의 성공을 최대 16인 동기화 증거로 대신하지 않는다. 공유 기능을 표시하는 출시에는 그 실제 검증도 필요하다. ‘친구가 있어야 뒤 이야기 진행’으로 첫 출시의 생활 완결을 바꾸지 않는다.

<a id="bus-expansion"></a>
### 4-1 정시 버스와 지역별 외출 확장

사용자 요청으로 마을 정류장의 고정 시간 버스와 용산(남산)·이태원·성수·전주 등의 목적지를 준비한다. 상세 정본은 [마을 §4-9](../마을_설계.md#town-bus)다. 기존 LAUNCH-01의 열 가지 생활을 교체하거나 네 목적지 전체를 첫 출시 완료 기준에 자동 합산하지 않는다.

**제작 제안:** 첫 생활의 이동·저장 기반을 재사용해 BUS-TEST의 정류장↔임시 목적지 왕복을 먼저 검증한다. 이후 남산 한 구역을 첫 마감 후보로 삼고 다른 지역은 각각 놀이·주민·미술·귀가가 준비된 뒤 연결한다. 배차 간격·첫 지역 확정·출시 편성·실제 작업 일정은 미정이며, 버스의 공통 시스템과 목적지별 제작량을 따로 센다. 문서 반영을 운행 구현·목적지 플레이·실기기 검증 완료로 보고하지 않는다.

**2026-10-09 목적지 전용 재료 추가:** 지역에서만 얻은 소재를 마을의 생활 제작·조리·꾸미기에 연결한다. [지역 재료 공급·레시피·소유 계약](싱크타운_생활경제와_상품_설계.md#regional-materials)에 4지역/8재료 후보를 두고, 첫 구현은 왕복이 준비된 한 지역의 1재료→1완성물→실제 사용/저장으로 제안한다. 재료명·공급량·가격·최종 제작 분량은 설계안이며, 기존 LAUNCH-01이나 버스 첫 시험에 후보 8종 전체를 자동 합산하지 않는다.

### 4-2 펫·생활 비서·낚시 — 세 콘텐츠 모두 설계, 구현은 후속

2026-10-09 사용자가 「셋다 추가하자. 설계만 지금 해줘」라고 요청했다. 셋의 전체 행동 범위와 기존 생활/여행 연결을 설계에 포함한다. 기존 열 가지 생활 카드·LAUNCH-01은 보존하고 확장 콘텐츠의 첫 출시 포함 범위·가격·종·수량·일정은 별도 결정한다. PET/ASST/FISH 각5개는 **제작 흐름 참조 ID**이며 15개 장편 이야기나 구현 완료 편수가 아니다.

| 후속 제작 순서 제안 | 먼저 확인할 생활 | 확장할 조건 |
|---|---|---|
| 1 생활 비서 기본 | 현재 생활·재료/제작·이어 할 단계·한국어 도움을 실제 준비된 상태에서 안내 | 버스는 BUS-TEST의 실제 시간표가 준비된 뒤 같은 ASST03에 연결. 미준비 상태를 실제 운행처럼 안내하지 않음 |
| 2 펫 집 생활과 산책 | PET01~03, 한 종·한 마리·기본 돌봄 비품·집과 기존 동네 동선 | 같은 `petId`·자리·신호·종료/귀가/재개가 유지되면 PET04 사진/발견, BUS 준비 뒤 PET05 여행 |
| 3 낚시의 핵심 조작 | FISH01, 한 물가·한 임시 어종·당기기/풀기·놓아주기·도감·정지 | 손맛·모바일 입력을 확인한 뒤 FISH02 다른 움직임/수역과 FISH03 전시. 어종/서식 정보는 별도 검수 |
| 4 기존 생활과 함께 쓰기 | 준비된 여행/지역 재료·펫 동행·비서의 현재 상태 안내·낚시 기록을 연결 | 수조 소유·부품 공급·실제 모델·포획 공급·레시피가 확인된 뒤 FISH04/05. 펫 침구/장식도 소비·사용까지 별도 확인 |

각 콘텐츠를 혼자서 독립적으로 즐길 수 있어야 한다. 펫이 있어야 낚시하거나, 모든 낚시를 끝내야 비서 도움을 받거나, 여행 전용 재료를 모아야 기본 돌봄을 하는 선행을 만들지 않는다. 실제 통합 검증은 펫을 집에 두기/무동행, 비서 닫기/조용히, 낚시 놓아주기/보관, 버스 실패/귀가, 두 기기 소유 충돌과 앱 종료 사례를 포함한다. [경제·소유 계약](싱크타운_생활경제와_상품_설계.md#pet-fishing-economy), 모바일/PC의 실제 표현·기기 인수는 후속 작업이다. **이번에는 문서만 변경하며 실행 코드·자산·설치 앱을 구현하지 않는다.**

<a id="NEXT01"></a>
### NEXT01 두 이름이 붙은 받침

**작은 의견 차이:** 공방 주인은 RV11의 기존 제목인 ‘작은 받침’이라는 이름을 남기고 싶다. 연구원은 실제로 보니 ‘작은 무대’처럼 보인다고 한다. 누구 말이 정답인지 맞히는 문제가 아니라 **만든 이의 이름과 보는 이의 해석을 함께 다루는 구경**이다. 해당 받침과 도안은 공방 소유. RV14에서 연구원 전시로 바꿨다면 전시 전체를 되돌리지 않고 공방의 기존 보기 자리에서 이 한 물건만 본다. 변경 대상은 현재 공방 받침 개체에 묶인 `workshop-caption-slot`의 설명 판본이며, RV14의 연구원 전시 슬롯·설명·배치는 건드리지 않는다.

| 단계 | 실제 대사·선택 | 현재 실행과 근거 |
|---|---|---|
| 1 | 공방 주인: “이건 ‘작은 받침’이라고 불렀어요.” 연구원: “저는 작은 무대처럼 보여요.” | 실제 같은 받침과 두 NPC의 지금 발화를 기록한다. RV11 제목을 보존하며 그때 듣지 않은 주민의 지식을 소급하지 않는다. |
| 2 | 공방 주인: “제가 지은 이름도 남았으면 좋겠어요.” 연구원: “보는 생각이 달라도 괜찮겠지요?” | NPC 둘이 자기 바람을 말하고 플레이어 쪽으로 물건을 돌려 본다. |
| 3 | A `[이름 하나에 이야기 둘을 붙여요]` / B `[두 이름을 번갈아 보여 줘요]` | A는 ‘작은 받침’ 제목 아래 만든 이/보는 이의 작은 카드 두 장. B는 같은 두 이름 카드 중 현재 앞에 둘 것을 고르고 다음은 직접 뒤집어 본다. 모두 원래 이름·작가 표시는 남김. 미리보기만이다. |
| 4 | `[이렇게 할게요] [다시 볼게요] [지금은 그대로 둘게요]` | 확정 뒤 이 받침의 `workshop-caption-slot`에 제목/카드 구성을 적용한다. 물건 이름의 소유 원장·RV14 연구원 전시·다른 장소 명칭을 덮지 않는다. |
| 5A | 공방 주인: “제가 만든 이유도, 다르게 본 이야기도 있네요.” | NPC가 제목→자기 사연→연구원 해석 순으로 실제 가리킨다. |
| 5B | 연구원: “이쪽에서 보면 다른 이름이 먼저 보이네요.” `[한 번 뒤집어 볼게요] [그대로 볼게요]` | 플레이어 선택으로 같은 양면 카드의 현재 면을 바꾸고 NPC는 실제 보이는 면만 읽는다. 자동 타이머 없음. |
| 6 | `[이 소개로 둘게요] [오늘만 볼게요]` | 기본 유지 동의가 있으면 현재 전시 설명 설정 보존. 오늘만은 기존 설명 복원. 실제 관람 완료와 현재 설정은 분리한다. |

**후속 생활:** `captionMode=one_title_two_views/two_titles`, `currentFace`, `keepCaption`과 두 NPC의 실제 인지를 남긴다. LIFE-A2에서 같은 받침을 소개할 때 A는 역할별 두 설명을, B는 현재 앞면을 사용한다. 철거/설정 복원 뒤 “두 이름이 붙어 있어요”라고 말하지 않는다. 공개 범위는 해당 개인 전시이며 다른 주민이 자동으로 별명을 알지 않는다.

**쉬운 지원/확장:** 두 이름은 글을 읽지 않아도 원래 물건 그림/작은 무대 그림으로 고를 수 있다. 공방 주인은 카드 한 장씩 실제 위치를 시범한다. 확장 표현은 “만든 이름은 남기고, 보는 사람의 생각을 옆에 붙이고 싶어요.” NPC가 사용자의 긴 발화를 필수로 기다리지 않는다. **보류·거절:** 기존 이름/현재 전시 유지, 연구원은 자기 수첩에 자기 해석만 남긴다. 플레이어 기여/공개는 없다. **중단:** 확정 전 초안과 실제 개정을 구분, 확정 후 카드 면·동의 읽기, 관람 전이면 과거 반응을 재지급하지 않고 남은 관람만 제안. 6의 유지/오늘만 선택 전에 종료하면 현재 적용 상태와 `pendingChoice`를 보존한다. ‘오늘만’ 복원도 현재 슬롯 개정을 확인하여 다른 기기의 이후 편집을 덮지 않고 새 확인을 받는다. **판정:** A/B에서 소개 순서·상호작용이 다르고 원래 저자·소유를 보존해야 한다. 언어 능력으로 별명 결정권을 차등하면 실패다.

### NEXT02 오늘의 메뉴와 오래 남길 메뉴

**작은 의견 차이:** 연구원은 함께 만든 메뉴의 이야기를 먼저 보여 주고 싶고, 사장님은 처음 오는 손님이 지금 고를 메뉴부터 찾으면 좋겠다고 한다. **FT52에서 현재 메뉴/공동 기록을 이미 정확히 구분하는 계약은 그대로다.** 구분이 안 되는 버그를 새 사건으로 만들지 않는다. 이번 새 회차의 목표는 두 주민의 소개 우선순위를 듣고 **실제 안내 위치와 손님이 보는 순서**를 정하는 것이다. 품절 복구·새 메뉴 제작은 요구하지 않는다.

| 단계 | 실제 대사·선택 | 현재 실행과 근거 |
|---|---|---|
| 1 | 연구원: “함께 만든 그림부터 보여 주면 어떨까요?” 사장님: “저는 지금 고를 메뉴를 먼저 찾게 해 드리고 싶어요.” | 연구원이 실제 FT20/52 기록을 확인한 뒤 자기 의견을 말한다. 사장님과 다른 소개 목적이며 같은 메뉴에 대한 과거 지식을 지우지 않는다. |
| 2 | 재고 있음: 사장님 “이 메뉴도 지금 준비돼 있어요.” / 없음: “이 그림은 기록으로 두고, 주문은 기본 메뉴에서 고를 수 있어요.” | 기존 FT52의 정확한 현재/기록 구분을 확인한다. 이 장면은 주문·제공을 수락하지 않는다. |
| 3 | A `[지금 고를 메뉴를 앞에 보여요]` / B `[함께 만든 메뉴를 전시해요]` | A는 현재 가능한 메뉴 그림이 앞, 지난 메뉴는 옆의 기록 자리. B는 공동 메뉴 그림을 전시하고 ‘함께 만든 메뉴’라는 검수 표식, 실제 주문 안내는 기존 차림표 위치를 유지. 두 곳 모두 통로를 비우는 미리보기다. |
| 4 | `[이렇게 할게요] [다시 볼게요] [지금은 그대로 둘게요]` | 슬롯·현재 재고 판본을 재확인한 뒤 비품 그림/설명 위치만 확정. 음식·코인·조리 재료 변화0. |
| 5A | 사장님: “주문은 앞에서, 함께 만든 이야기는 옆에서 볼 수 있어요.” | 연구원이 실제 앞 안내를 보고 주문 위치를 짚은 뒤 옆 기록을 본다. 구매/시식 없음. |
| 5B | 연구원: “이 그림은 함께 만든 메뉴의 기록이군요.” 사장님: “마실 것을 고를 땐 차림표를 보여 드릴게요.” | 실제 기록을 관람하고 현재 주문 위치를 따로 안내한다. 없는 메뉴를 제공했다고 하지 않는다. |
| 6 | `[여기까지 볼게요] [기록을 조금 더 볼게요]` | 실제 두 표시의 용도 확인으로 완료. 재입고·판매 의뢰를 자동 붙이지 않는다. |

**후속 생활:** `menuDisplayPurpose=current_offer_first/shared_memory`, 실제 `recipeRecordId`, 안내 슬롯과 `stockRevision`을 분리한다. A에서 앞 메뉴가 품절되면 현재 안내의 선택 가능 목록만 갱신하고 공동 기록은 옆에 그대로 남긴다. B의 기록은 재고0이어도 유지되며 실제 주문 가능성으로 읽지 않는다. 사장님의 소유 비품 위치 변경은 허용된 개인 설명 슬롯에만 적용한다.

**쉬운 지원/확장:** ‘지금 고르기’는 현재 차림 그림, ‘함께 만든 기록’은 수첩 그림과 각 장소의 실물 시범으로 구분한다. 확장 “예전에 같이 만든 메뉴는 여기에 남기고, 지금 주문할 메뉴는 앞에서 고르게 해요.” **보류·거절:** 기존 FT52 표시를 유지하고 사장님이 현재 메뉴를 직접 알려 준다. 원래 표시가 허위 제공 약속이 되지 않게 기본 영업의 품절 표시는 거절과 무관하게 정확히 유지한다. **중단:** 미리보기 뒤 재고가 달라져도 기록을 삭제하지 않고 현재 선택 가능 목록을 다시 보여 준다. 확정 후에는 최신 안내/과거 기록의 목적을 각각 복원한다. **판정:** 무재고·무코인 상태에서도 이 장면을 완결하고 음식/정산을 만들지 않아야 한다. 그림을 지워야 품절을 해결하는 구조면 실패다.

### NEXT03 연구원도 자기 관찰을 하러 가요

**작은 의견 차이:** 공방 주인은 잠깐만 안내를 받고 싶고 연구원은 지금 정한 자기 관찰을 마치러 가고 싶다. 플레이어가 둘의 일정 전체를 책임지는 대신 **짧은 안내를 맡거나 스스로 보는 방식으로 바꾸는 한 선택**을 한다. 누구도 급하게 답하도록 재촉하지 않는다. 연구원의 자기 관찰은 플레이어의 동의가 없어서 실패하는 이야기가 아니다.

| 단계 | 실제 대사·선택 | 현재 실행과 근거 |
|---|---|---|
| 1 | 공방 주인: “여기 한 군데만 보고 갈 수 있을까요?” 연구원: “저도 저쪽 화분을 보려고 해요.” | 현재 공방의 짧은 구경 의도와 연구원의 실제 가능한 자기 관찰 목표를 보여 준다. 임의의 새 급한 의뢰를 만들지 않는다. |
| 2 | 연구원: “이 안내 카드는 두고 갈 수 있어요. 어떻게 볼까요?” | 연구원 소유 기본 카드와 현재 같은 대상만 제시. 플레이어 비공개 기록은 쓰지 않는다. |
| 3 | A `[제가 한 곳을 안내할게요]` / B `[각자 보고 함께 비교해요]` | A는 내가 고른 한 지점→공방의 관람, B는 같은 장소의 두 보기 자리→공방이 하나/내가 하나 선택해 자기 보기. 연구원은 두 계획의 짧은 시범을 먼저 한다. 미리보기다. |
| 4 | `[이렇게 볼게요] [다시 볼게요] [그냥 둘러볼게요]` | 전자는 관람 자리·기본 카드 예약 후 실행하며 연구원은 자기 관찰 계획의 실제 목적지로 이동한다. 경로·자기 관찰 자리 예약이 불가하면 현재 가능한 자기 기본 자리에서 관찰한다. 그냥 둘러보기는 의뢰/안내 공로 없이 자유 관람, 연구원은 같은 자기 일과를 이어 간다. 어느 경우도 연구원 귀환을 사용자 완결 조건으로 삼지 않는다. |
| 5A | `[이 부분을 봐요]` / 공방 주인 “여기부터 보니 찾기 쉽네요.” | 사용자가 고른 실제 잎/꽃 부분을 공방이 확인. 언어 입력은 타일로 충분하고 연구원이 미리 보여 준 도움을 독립 발화로 세지 않는다. |
| 5B | 공방 주인: 실제 전체 보기면 “저는 전체를 봤어요”, 실제 세부 보기면 “저는 이 잎을 봤어요.” `[같은 부분을 봤어요] [저는 이 부분을 봤어요]` | 실제 각자 본 지점만 비교한다. 잎 대신 꽃을 고른 실제 대상일 때만 꽃 대사로 바꾼다. 자기 시점은 직접 고르며 다른 발견을 해야 성공하는 조건이 없다. |
| 6 | 공방 주인: “짧게 보고도 충분했어요.” `[여기까지 할게요] [혼자 더 볼게요]` | 실제 한 지점 안내 또는 각자 보기·비교가 끝나면 완료. 연구원의 귀환은 완료 조건이 아니다. |

**후속 생활:** `tourCoverage=player_one_stop/parallel_view`, 실제 관람자/역할/대상을 저장한다. 연구원은 이때 현장에 없으면 안내 내용을 모른다. 다음에 사용자가 기본 카드 자리에서 `[어떻게 봤는지 알려 줄게요]`를 직접 고르고 실제 전달했을 때만 “한 곳씩 나눠 봤군요” 또는 “한 곳을 안내했군요”라고 답한다. 전달하지 않아도 생활 완료·관계·기존 권리는 같다. LIFE-C2의 다음 요청에서 이 방식을 선택할 수 있으나 자동으로 안내자 역할에 고정하지 않는다.

**쉬운 지원/확장:** 연구원이 떠나기 전 현재 카드의 한 지점을 실제로 짚고 한 행동만 시범한다. 추가 도움은 검수된 카드/정지 보기로 제공하여 연구원 NPC를 동시에 두 장소에 복제하지 않는다. 확장 “연구원은 하던 일을 하세요. 저는 여기 한 곳을 안내할게요.” **보류·거절:** 공방 주인은 기본 카드로 혼자 잠깐 보고 떠나며 플레이어 도움으로 기록하지 않는다. 연구원은 자기 일과를 유지한다. **중단:** 플레이어의 수락한 핵심 안내/비교는 자동으로 끝내지 않는다. NPC의 자기 관찰은 별도 배경 사실로 진행할 수 있지만 플레이어 없는 동안 안내 기여·관람 ACK를 만들지 않는다. 복귀 때 현재 가능한 NPC/대상으로 같은 회차를 잇거나 보류한다. **판정:** 두 갈래에서 공방 동선·사용자 역할이 달라야 하고, 아무도 연구원의 복귀를 기다려야만 종료할 수 없어야 한다.

**이번에 더 늘리지 않는 범위:** FOLLOW-02 이후의 새 장면 수·공개 순서·업데이트 주기, 기존 11장편 전체 원고, 새 주민 이름/외형/음성·추가 공간 제작은 이 세 원고의 완료 근거가 아니다. 해당 작업이 필요하면 실제 플레이에서 어느 취향의 어떤 새 문제가 필요한지와 제작 가능 분량으로 다음 유한 묶음을 정한다. 이 항목은 열 가지 전체 출시 후보의 기존 미완료를 뒤로 넘기는 예외가 아니다.
