# 싱크타운 출시와 후속 콘텐츠 편성 — 추가 요청 범위

2026-10-09. 사용자가 추가한 버스·한국 명소 여행·지역 전용 재료·펫·생활 비서·낚시의 제작 범위를 기록한다. 기존 열 가지 생활과 출시 후보(LAUNCH-01)를 교체하지 않으며 출시일·가격·최종 제공 분량은 미정이다. 전체 출시 원고와 구현 준비의 공용 초안은 담당 세션에서 이어 작성한다. 이번 커밋은 이 추가 요청의 설계만 분리해 보존한다.

<a id="units"></a>
## 1 추가 콘텐츠의 제작 단위

| 제작 단위 | 포함 범위 | 완료라고 할 수 있는 근거 |
|---|---|---|
| BUS-TEST / 지역별 외출 확장 | [정시 버스·명소 여행](../마을_설계.md#town-bus). 우선 정류장↔목적지 하나의 왕복 시험, 이후 용산·남산/이태원/성수/전주를 지역별 제작 | 버스 시간·직접 승차·지역 이동·귀가·저장/복구를 먼저 확인. 각 목적지 자산·놀이·실행은 따로 확인하며 첫 출시 포함 범위는 미정 |
| PET-TEST / 펫 생활 확장 | [PET01~05](../마을_설계.md#town-pets). 첫 시험은 한 종·한 마리의 첫 만남/돌봄/산책, 이후 발견/사진/여행 동행 | 같은 펫의 소유·행동·귀가·재개와 안전한 돌봄을 확인. 목록의 행동 이름만으로 애니메이션·동행 구현 완료라고 하지 않음 |
| ASSIST-TEST / 생활 비서 확장 | [ASST01~05](../마을_설계.md#world-life-assistant). 기존 가이드에 생활 선택·재료/제작·버스·재개·한국어 도움을 연결 | 실제 상태 차이가 답과 입구를 바꿈. 정보 부재·조용히·거절·권한과 직접 실행 경계를 확인. 새 별도 AI 비서 엔진이 아님 |
| FISH-TEST / 낚시 생활 확장 | [FISH01~05](../마을_설계.md#town-fishing). 첫 시험은 한 자리·한 임시 어종의 조작/놓아주기/기록, 이후 어종/수역/전시/수조/조리 | 입력·포획·처리·도감·소유·중단/재개를 실제 확인. 생태 데이터·수조·레시피·지역 전용 공급은 준비한 범위만 개방 |

## 4 기존 생활과 확장 콘텐츠의 제작 경계

<a id="bus-expansion"></a>
### 4-1 정시 버스와 지역별 외출 확장

사용자 요청으로 마을 정류장의 고정 시간 버스와 용산(남산)·이태원·성수·전주 등의 목적지를 준비한다. 상세 정본은 [마을 §4-9](../마을_설계.md#town-bus)다. 기존 LAUNCH-01의 열 가지 생활을 교체하거나 네 목적지 전체를 첫 출시 완료 기준에 자동 합산하지 않는다.

**제작 제안:** 첫 생활의 이동·저장 기반을 재사용해 BUS-TEST의 정류장↔임시 목적지 왕복을 먼저 검증한다. 이후 남산 한 구역을 첫 마감 후보로 삼고 다른 지역은 각각 놀이·주민·미술·귀가가 준비된 뒤 연결한다. 배차 간격·첫 지역 확정·출시 편성·실제 작업 일정은 미정이며, 버스의 공통 시스템과 목적지별 제작량을 따로 센다. 문서 반영을 운행 구현·목적지 플레이·실기기 검증 완료로 보고하지 않는다.

**2026-10-09 목적지 전용 재료 추가:** 지역에서만 얻은 소재를 마을의 생활 제작·조리·꾸미기에 연결한다. [지역 재료 공급·레시피·소유 계약](싱크타운_생활경제와_상품_설계.md#regional-materials)에 4지역/8재료 후보를 두고, 첫 구현은 왕복이 준비된 한 지역의 1재료→1완성물→실제 사용/저장으로 제안한다. 재료명·공급량·가격·최종 제작 분량은 설계안이며, 기존 LAUNCH-01이나 버스 첫 시험에 후보 8종 전체를 자동 합산하지 않는다.

<a id="pet-assistant-fishing"></a>
### 4-2 펫·생활 비서·낚시 — 세 콘텐츠 모두 설계, 구현은 후속

2026-10-09 사용자가 「셋다 추가하자. 설계만 지금 해줘」라고 요청했다. 셋의 전체 행동 범위와 기존 생활/여행 연결을 설계에 포함한다. 기존 열 가지 생활 카드·LAUNCH-01은 보존하고 확장 콘텐츠의 첫 출시 포함 범위·가격·종·수량·일정은 별도 결정한다. PET/ASST/FISH 각5개는 **제작 흐름 참조 ID**이며 15개 장편 이야기나 구현 완료 편수가 아니다.

| 후속 제작 순서 제안 | 먼저 확인할 생활 | 확장할 조건 |
|---|---|---|
| 1 생활 비서 기본 | 현재 생활·재료/제작·이어 할 단계·한국어 도움을 실제 준비된 상태에서 안내 | 버스는 BUS-TEST의 실제 시간표가 준비된 뒤 같은 ASST03에 연결. 미준비 상태를 실제 운행처럼 안내하지 않음 |
| 2 펫 집 생활과 산책 | PET01~03, 한 종·한 마리·기본 돌봄 비품·집과 기존 동네 동선 | 같은 `petId`·자리·신호·종료/귀가/재개가 유지되면 PET04 사진/발견, BUS 준비 뒤 PET05 여행 |
| 3 낚시의 핵심 조작 | FISH01, 한 물가·한 임시 어종·당기기/풀기·놓아주기·도감·정지 | 손맛·모바일 입력을 확인한 뒤 FISH02 다른 움직임/수역과 FISH03 전시. 어종/서식 정보는 별도 검수 |
| 4 기존 생활과 함께 쓰기 | 준비된 여행/지역 재료·펫 동행·비서의 현재 상태 안내·낚시 기록을 연결 | 수조 소유·부품 공급·실제 모델·포획 공급·레시피가 확인된 뒤 FISH04/05. 펫 침구/장식도 소비·사용까지 별도 확인 |

각 콘텐츠를 혼자서 독립적으로 즐길 수 있어야 한다. 펫이 있어야 낚시하거나, 모든 낚시를 끝내야 비서 도움을 받거나, 여행 전용 재료를 모아야 기본 돌봄을 하는 선행을 만들지 않는다. 실제 통합 검증은 펫을 집에 두기/무동행, 비서 닫기/조용히, 낚시 놓아주기/보관, 버스 실패/귀가, 두 기기 소유 충돌과 앱 종료 사례를 포함한다. [경제·소유 계약](싱크타운_생활경제와_상품_설계.md#pet-fishing-economy), 모바일/PC의 실제 표현·기기 인수는 후속 작업이다. **이번에는 문서만 변경하며 실행 코드·자산·설치 앱을 구현하지 않는다.**
