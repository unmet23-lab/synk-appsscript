# 솔리오 「내 PC 진단」 설계 (2026-11-23, 11-24 Fable 설계 검토 반영)

솔리오는 켠 PC를 먼저 진단하고, 그 결과로 기능마다 무엇을 켜고 무엇을 권할지를 PC마다 다르게 정한다. 이 PC에서 안 되는 것도 숨기지 않고 말한다.

## 1. 왜

- 유호님 11-23: 「앱을 켜고 나면 사업계획서를 쓰고, 어떤 LLM 조합을 쓸지 정하고, 그다음으로 할 건 내 PC 진단 같은 걸 해야 할 것 같아. 그래야 그 PC에 맞는 솔루션을 제대로 줄 수 있다.」 「그 사용자의 PC의 한계를 파악하고 개개인의 PC마다 전부 다 지원해 주는 게 달라야 해.」
- 같은 날 바로 앞 말씀: 원클릭 판에 C: 드라이브만 보인다. D:를 주로 쓰거나 C: · D:를 함께 쓰는 사람은 불만이 많을 것이다.
- 11-19 사무실 말씀: 「PC 진단해서」, 「아이디마다 CPU랑 RAM에 맞춰서 인원 분배나 최대 수용 가능 인원을 설정해 줬으면 좋겠어」([사무실 README](../솔리오_사무실_20261119/README.md#이-pc의-수용-인원)).
- 지금은 이 PC의 값을 기능마다 따로 읽는다. 사무실은 코어와 메모리를 읽는다. 백업 엔진은 배터리 · 절전 · 종량제 회선 · 고정 드라이브 · 원본 폴더 · AI 도구 설정을 읽는다. 손님은 솔리오가 자기 PC를 어떻게 보고 무엇을 맞췄는지 한곳에서 볼 수 없다. 원클릭 판처럼 한 값만 골라 보이는 곳도 있다.

## 2. 흐름에서의 자리

1. 사업계획서(사무실 기획부)
2. LLM 조합: 부서마다 쓸 AI 도구(Claude Code · Codex)와 그 구독
3. **이 PC에 이렇게 맞췄습니다**: 진단 결과와 맞춘 것, 바꾸기
4. 맞춘 기능 켜기: 백업 보호 시작, 공간, 사무실 수용 인원

진단은 앱을 처음 켠 화면에서 시작한다. 그 화면에 「이 PC의 사양을 읽습니다. 이 PC 밖으로 보내지 않습니다.」 한 줄을 둔다. 몇 초면 끝나고 PC를 바꾸지 않는다. 결과를 보이는 차례는 유호님이 정하신 대로 셋째다. 둘째 단계는 이미 잰 값을 쓰고, 숫자 옆에 까닭 한 줄을 붙인다(예: 「이 PC에서는 여덟이 함께 일합니다. 논리 코어 16개와 메모리 32GB를 보고 정했습니다.」). 셋째 단계의 이름을 「진단」이 아니라 결과로 지은 까닭은, 둘째 단계가 이미 진단 값을 보였기 때문이다.

## 3. 재는 것

PC를 바꾸지 않고 읽기만 한다. 관리자 권한이 필요한 값은 재지 않는다. 오래 걸리는 읽기(아래 「느림」)는 첫 화면을 막지 않고 뒤에서 채운다.

| 갈래 | 재는 값 | 누가 · 어떻게 |
|---|---|---|
| 저장 | 드라이브마다 글자 · 종류(고정 · 이동식 · 네트워크) · 파일 시스템 · 크기 · 남은 공간 | **PC 앱**이 PowerShell 한 번으로 `[System.IO.DriveInfo]::GetDrives()`를 읽는다. 엔진이 없는 새 손님도 잰다 |
| 저장 | 드라이브의 연결(PC 안 · USB 따위)과 SSD · HDD | **엔진**의 `internal_disk`(`\\.\C:`를 권한 없이 열어 `IOCTL_STORAGE_QUERY_PROPERTY`의 BusType · 탐색 지연). 엔진이 없으면 「모름」 |
| 저장 | 문서 · 바탕 화면 · 다운로드 · 사진이 놓인 드라이브 글자와 OneDrive 안인지 | 엔진 `folders.rs`. 글자와 참 · 거짓만 넘긴다 |
| 저장 | 드라이브마다 지난 14일 증가 속도와 정한 선 | 엔진의 하루 공간 훑기(보호를 시작한 뒤) |
| 처리 | 논리 코어 수 · 메모리 전체와 지금 빈 양 | PC 앱 `os.cpus()` · `os.totalmem()` · `os.freemem()`. 메모리는 GB로 반올림한 뒤 문턱과 견준다(16GB PC는 15.7GB쯤으로 읽힌다). 프로세서 이름은 화면에 쓰지 않아 읽지 않는다(11-24) |
| 처리 | 그래픽 장치 수와 가장 큰 그래픽 메모리 | PC 앱이 디스플레이 장치 하위 키를 모두 읽어 `HardwareInformation.qwMemorySize`의 가장 큰 값을 쓴다. 지금 있는 장치(`Win32_VideoController`)와 맞춘다. 내장 그래픽도 2GB쯤을 알리므로 「전용」이라고 쓰지 않는다. 장치 이름은 읽지 않는다. 느림 |
| 전원 | 노트북인지 | `PowerDeterminePlatformRoleEx`(휴대형인지)와 `GetSystemPowerStatus`의 배터리 표식을 함께 본다. USB로 꽂은 UPS만 있는 데스크톱을 노트북으로 잡지 않는다 |
| 회선 | 종량제인지, Wi-Fi인지 유선인지 | 엔진 `power.rs`의 회선 비용과 `IsWlanConnectionProfile`. Wi-Fi 이름은 읽지 않는다(위치 권한을 건드린다) |
| 화면 | 화면 크기와 배율 | PC 앱 `screen.getPrimaryDisplay()` |
| 운영체제 | Windows 판 · 빌드 · ARM인지 | 레지스트리. x64 앱은 ARM PC에서도 `process.arch`가 `x64`라 `PROCESSOR_ARCHITECTURE` 레지스트리나 `IsWow64Process2`로 읽는다 |
| 도구 | Claude Code · Codex · Gemini CLI가 깔렸는지와 로그인 흔적이 있는지, VS Code · Cursor · Node · Python · Git · WSL이 있는지 | 실행 파일이 있는지만 본다(실행해서 판을 묻지 않는다). 로그인은 자격 파일이 있는지만 보고 내용은 읽지 않는다 |

**보이는 드라이브.** Windows는 USB 외장 하드와 Google Drive 같은 가상 드라이브도 「고정 드라이브」로 알린다. 이 PC의 G:(Google Drive)는 FAT32로 보이고 크기와 남은 공간이 C:와 같다. 다음은 드라이브 칸으로 세우지 않는다.
- 파일 시스템이 NTFS · ReFS · exFAT이 아닌 것(가상 드라이브)
- 다른 글자와 같은 볼륨을 비추는 것(볼륨 일련번호가 같음, `subst`)
- 32GB 아래인 것(제조사 복구 파티션). 이런 드라이브는 늘 「선 아래」라 맨 앞 경고 칸이 된다
- 이동식(USB 메모리 · SD)과 네트워크 드라이브는 칸으로 세우지 않고 「내 PC」 판에 「재지 않음」과 까닭만 쓴다

엔진은 11-24부터 공간 훑기를 NTFS · ReFS · exFAT 드라이브에서만 하고, 비우기는 PC 안 디스크의 NTFS · ReFS에서만 한다. 외장 · USB · 가상 드라이브와 연결을 읽지 못한 드라이브는 비우지 않는다(SPACE_DESIGN 10장 「외장 드라이브의 파일을 지우지 않는다」).

**재지 않는 것.** 파일 이름과 내용, 방문한 사이트, 설치한 프로그램 전체 목록, 하드웨어 일련번호와 `MachineGuid`.

**두는 곳.** 진단 결과는 이 PC의 솔리오 앱 자료 폴더에만 둔다. 서버로 보내지 않는다. 같은 아이디라도 PC마다 따로 기억하는 것은 이 자리가 PC마다 따로 있기 때문이다. 엔진이 넘기는 값은 솔리오 상태 파일(`status.json`)이 아니라 따로 둔 `solio/pc.json`에 쓴다. 상태 파일은 AI 도구에 동의 없이 답하는 `protection_status`가 그대로 싣기 때문이다. `pc.json`은 MCP 도구 목록 밖에 두고, 계약 README와 `mcp.rs` 시험에 그렇게 적는다. 사무실 직원(Claude Code · Codex)에게 일을 맡길 때 진단 값을 지시문에 넣지 않는다. 오류 보고와 로그에도 진단 값과 프로세서 · 그래픽 카드 이름을 싣지 않는다. 화면에는 수와 종류만 쓴다. 경로는 엔진 창처럼 손님 PC 안의 화면에서만 펼친다.

## 4. PC마다 달라지는 것

조건이 맞으면 오른쪽처럼 켜거나 권한다. 값마다 「기본」과 「손님이 정함」 표식을 둔다. 손님이 정한 값은 다시 진단해도 덮지 않는다. 공간의 정한 선이 이미 이 꼴(`set: true`)이다.

### 4.1 PC 앱이 정하는 것

| 기능 | 이런 PC에서 | 이렇게 한다 |
|---|---|---|
| 공간 | 보이는 드라이브가 둘 이상 | 원클릭 판에 드라이브를 모두 보인다(5.1) |
| 공간 | C:가 정한 선 아래이거나 14일 안에 닿고, 다른 드라이브가 넉넉함 | 「새 프로젝트와 다운로드는 D:에 두면 C:가 덜 찹니다」를 한 번 권한다. 폴더 옮기기는 Windows 설정을 여는 길만 안내하고 솔리오가 옮기지 않는다. C:와 D:가 한 디스크의 두 파티션이어도 같다 |
| 공간 | 첫 공간 훑기가 아직 끝나지 않음 | 「드라이브가 크고 파일이 많으면 첫 훑기가 여러 날 걸립니다」라고 쓴다. 엔진은 이미 모든 드라이브를 낮은 우선순위로 하루 5분씩 훑는다 |
| 사무실 | 코어 · 메모리 | 수용 인원 규칙 그대로다(논리 코어 둘마다 한 사람, 메모리 4GB마다 한 사람, 적은 쪽). 진단의 기본값과 손님이 직접 정한 수는 사무실이 지금 쓰는 저장 자리에 함께 둔다 |
| 사무실 | 지금 빈 메모리가 2GB 아래 | 새 직원은 기다린다(사무실 규칙 그대로). 「내 PC」 판의 메모리 줄에 지금 빈 양을 함께 쓴다 |
| LLM 조합 | Claude Code · Codex가 없음 | 그 도구를 고르면 설치와 로그인을 먼저 안내한다. 솔리오가 로그인을 대신하지 않는다(사무실 README 「사용자 구독으로 실행하는 방식」) |
| 화면 | 메모리 8GB 이하이거나, 전용 그래픽 메모리가 없는 노트북 | 구 그림을 가벼운 판으로 띄운다. 앱을 켤 때 한 번만 정하고 까닭을 쓴다. 전원선을 꽂고 뽑을 때마다 바꾸지 않는다 |
| 화면 | 화면이 작거나 배율이 커서 원클릭 판이 한 단으로 쌓임 | 드라이브 칸을 한 줄 막대로 줄인다(5.1) |

로컬 모델을 권하는 줄은 넣지 않는다. 솔리오에는 아직 로컬 모델을 돌리는 길이 없다. 그래픽 값은 재 두고 「내 PC」 판에 값만 보인다. 실제로 붙일 도구와 모델을 정할 때 이 표에 다시 넣는다.

### 4.2 엔진이 정하는 것(엔진 설계 변경으로 따로 올린다)

PC 앱이 셈한 기본값을 엔진에 넘기는 요청은 지금 계약에 없다(`space-setting`은 줄이는 쪽만 받는다). 아래는 엔진이 진단 값으로 스스로 정하고, 솔리오는 그 결과를 읽어 「그래서 이렇게 맞췄습니다」만 쓴다. 엔진 1단계 설계(STAGE1 4.2)의 변경으로 올리고, 계약을 바꿀 때는 계약 README대로 GPT 솔리오 세션과 같이 바꾼다.

| 기능 | 이런 PC에서 | 이렇게 한다 | 지금 엔진 |
|---|---|---|---|
| 백업 | 문서 · 바탕 화면이 D:나 OneDrive로 옮겨져 있음 | 그 자리를 원본 기본값으로 잡는다 | 원본 고르기가 이미 알려진 폴더 자리를 읽는다. 기본값으로 잡는지 확인한다 |
| 백업 | 외장 하드에 원본이 있음 | 연결됐을 때만 백업한다. 빠진 동안은 「연결되면 이어서 합니다」 | 없음 |
| 백업 | 노트북 | 배터리 30% 아래일 때 쉰다 | 이미 그렇다. 바꾸지 않는다 |
| 백업 | 종량제 회선 | 쉰다 | 이미 그렇다 |
| 공간 | 외장 · 가상 드라이브 | 훑지 않거나 비우지 않는다 | 11-24에 넣었다(3절) |
| 공간 | 외장 하드가 빠져 있음 | 지난번에 본 드라이브를 보고서에 「지난번에 본 드라이브」로 싣는다 | 없음(드라이브 기록에 지난 30일 값이 있다) |

## 5. 보이는 법

### 5.1 첫 조각 — 드라이브를 모두 보인다

원클릭 판의 드라이브 칸을 보이는 드라이브 수에 맞춘다. 판은 왼쪽 드라이브 칸과 오른쪽 네 줄의 두 단이라, 칸을 나란히 늘리지 않는다.

- 하나면 지금 칸 그대로다.
- 둘 이상이면 가장 빠듯한 드라이브를 지금 크기 그대로 첫 칸에 두고, 나머지는 그 아래 한 줄 막대로 둔다. 한 줄에 글자 · 크기 · 남은 공간 · 정한 선이 있는 가는 막대가 있다.
- 넷 이상이면 셋째부터 「드라이브 n개 더」로 접고 누르면 편다.
- 차례: 정한 선 아래인 드라이브 → 정한 선에 며칠 뒤 닿는지가 짧은 드라이브 → 글자 차례. 지금 코드처럼 남은 바이트로 견주면 작은 드라이브가 늘 앞에 와서 쓰지 않는다.
- 정한 선이 없는 드라이브(깨진 보고서에서만 생긴다): 막대에 선을 그리지 않고 예측 글 대신 「정한 선을 아직 받지 못했습니다」.
- 크기를 읽지 못한 드라이브(BitLocker로 잠긴 따위): 칸을 세우지 않고 마지막 줄에 「읽지 못한 드라이브 1개」. 엔진 보고서에 그 수를 싣는 칸이 없어 둘째 조각(PC 앱이 드라이브를 직접 잼)과 함께 넣는다.
- 접힌 뒤 문장 「다만 남은 공간이 정한 선보다 적습니다」에 드라이브 글자를 넣는다(「다만 D:의 남은 공간이 …」). 둘 이상이면 「C: · D:」.
- 「다른 드라이브 1개는 정한 선보다 넉넉합니다」 문장은 없앤다.
- 03 공간 줄의 「많게는 …」은 이 조각에서 합계 그대로 둔다. 드라이브별 몫은 나중 조각에서 넣는다. 그때도 본체는 후보 경로의 첫 글자 하나만 읽어 드라이브별로 더하고 경로는 버린다. 2판에서는 임시 묶음과 「정한 선 아래 드라이브의 빌드 폴더」만 센다. 엔진의 비우기 결과는 드라이브별이 아니므로 「비웠습니다」 문장은 합계 그대로다.
- 보고서가 없을 때(보호 시작 전): 3절의 PC 앱 값으로 드라이브와 크기 · 남은 공간을 보이고 정한 선과 예측만 비운다. 이것은 둘째 조각(`pc-profile.cjs`)이 들어온 뒤부터다. 그 전에는 지금 빈 칸 글 그대로다.
- 본체의 보고서 요약이 `drive` · `otherDrives` 대신 `drives[]`를 넘긴다. 방 모델, 판 그리기, 원클릭 시험과 [원클릭 설계](../솔리오_원클릭_20261123/PC앱_옮기기.md)를 함께 고친다.

### 5.2 「이 PC에 이렇게 맞췄습니다」 판

흐름의 셋째 단계와 설정에서 여는 한 장이다.

- 맨 위 한 문장: 「이 PC는 16코어 · 메모리 32GB 노트북입니다. 드라이브 둘(C: 953GB, D: 1.9TB)을 씁니다.」
- 그 아래 갈래마다 한 줄: 저장 · 처리 · 그래픽 · 전원 · 회선 · 화면 · 도구. 줄마다 잰 값과 「그래서 이렇게 맞췄습니다」를 함께 쓴다. 예: 「노트북이라 배터리가 30% 아래면 백업을 쉽니다.」
- 이 PC에서 안 되는 것은 솔리오가 실제로 주는 기능에 대해서만 쓴다. 예: 「사무실에서는 두 사람까지 함께 일합니다. 메모리가 8GB입니다.」, 「USB 메모리와 네트워크 드라이브는 재지 않습니다.」
- 판 아래에 「다시 진단」 단추가 있다.

### 5.3 기능 안에서

기능마다 진단이 정한 값 옆에 까닭을 짧게 둔다. 사무실 수용 인원 줄의 「논리 코어 16개와 메모리 32GB를 보고 정했습니다」 꼴이다.

## 6. 다시 재는 때

- 앱을 켤 때: 가벼운 값(드라이브 목록 · 메모리 · 화면)을 PC 앱이 다시 읽는다. 「느림」 값은 하루 한 번이다.
- PC 안 드라이브가 늘거나 빠졌을 때, 메모리 · 그래픽 카드가 바뀌었을 때: 「이 PC가 바뀌었습니다」를 알리고 기본값을 다시 셈한다. 외장 하드를 꽂고 뽑는 일에는 알리지 않는다. 손님이 정한 값은 그대로 둔다.
  - 11-24 둘째 조각은 메모리와 그래픽 메모리만 알린다. PC 앱 값만으로는 USB 외장 하드도 「고정 드라이브」라 PC 안 드라이브와 가를 수 없다. 드라이브의 바뀜은 엔진의 연결 값(4번 조각)이 들어오면 넣는다. 알림 자리는 설정 방의 「이 PC」 줄(「바뀜」)과 판 맨 위 둘째 문장이고, 판을 열어 보면 지운다.
- 「다시 진단」을 눌렀을 때: 전부 다시 잰다.

## 7. 지원하지 않는 PC

- 32비트 Windows: PC 앱 꾸러미가 x64뿐이라 깔리지 않는다. 내려받기 쪽이 「64비트 Windows가 필요합니다」라고 미리 말한다. 진단 판의 몫이 아니다.
- ARM Windows: 앱과 엔진이 x64라 에뮬레이션으로 돈다. 진단 판에 「느릴 수 있습니다」를 쓴다. 실제 동작은 ARM PC를 구해 잰 뒤 정한다.
- 회사 PC에서 PowerShell이 막힌 경우: PowerShell로 읽는 값(드라이브 목록, 그래픽)은 「읽지 못함」으로 두고 엔진 값이 있으면 그것을 쓴다.
- Mac: 백업 엔진이 아직 Windows뿐이다. 진단은 Mac 판 PC 앱을 낼 때 같은 표로 다시 짠다.

## 8. 짓는 차례

1. **드라이브를 모두 보이기(5.1)**: 유호님이 바로 불편해하신 것이라 먼저 낸다. 조건은 둘이다. 보이는 드라이브 걸러내기(3절)를 솔리오 쪽에서 하고, 드라이브별 몫 문장은 넣지 않는다. 엔진 보고서에는 이미 모든 고정 드라이브가 있고, 11-24부터 가상 드라이브는 빠진다. 화면 검수(카본 → Fable)를 거쳐 다음 PC 판에 싣는다.
2. **PC 앱의 진단 값(`pc-profile.cjs`)**: 사무실의 `office-capacity.cjs`를 넓힌다. 드라이브 목록 · 종류 · 걸러내기, 처리 · 그래픽 · 전원 · 화면 · 운영체제 · 도구.
3. **「이 PC에 이렇게 맞췄습니다」 판**.
4. **엔진의 `solio/pc.json`**: 연결 종류 · SSD · HDD · 원본 폴더 자리 · 회선, 지난번에 본 드라이브. 계약 변경이라 GPT 솔리오 세션과 같이 한다. 엔진 판을 낼 때 함께 싣는다.
5. **엔진 쪽 기본값(4.2)**: 엔진 설계 변경으로 따로 올린다.
6. **흐름에 넣기**: 사업계획서 → LLM 조합 → 이 PC에 이렇게 맞췄습니다. 사업계획서는 지금 「일 맡기기」가 켜진 판에서만 보인다. 흐름의 첫 단계로 둘지는 사업계획서를 정식 판에 실을지(유호님이 써 보고 정하신다)와 함께 정한다.

### 8.1 둘째 · 셋째 조각에서 지은 것(11-24, 유호님 「응, 지어」)

- 본체 `desktop/src/pc-profile.cjs`: 3절의 PC 앱 몫을 PowerShell 두 번(가벼운 값 1~2초, 그래픽 2~3초)과 Node 값으로 읽어 `userData/solio/pc-profile.json`에만 둔다. 앱을 켜고 8초 뒤 가벼운 값을 읽고, 판을 열 때 10분 넘은 값은 다시 읽는다. 그래픽은 하루 한 번이다. 보이는 드라이브 걸러내기는 원클릭 판과 같은 함수(`solio-oneclick.cjs` `pickDrives`)를 쓴다.
- 판 `desktop/renderer/pc-fit-model.mjs`: 설정 방의 「이 PC」 줄의 「내 PC 진단 보기」로 연다(흐름에 넣기는 6번). 판과 단추 이름은 유호님 말씀대로 「내 PC 진단」이다. 맞춰 주는 기능이 없는 계정에도 맞는 이름이라 5.2의 「이 PC에 이렇게 맞췄습니다」 대신 쓴다(Fable 다시 검수 r3). 맨 위 두 문장과 갈래 여덟 줄(저장 · 처리 · 그래픽 · 전원 · 회선 · 화면 · 운영체제 · 도구)이다. 「돌아가기」와 Esc는 설정 방의 그 단추로 돌아온다.
- 원클릭 판: 보호 중인데 엔진의 첫 공간 보고서가 아직 없으면 PC 앱이 잰 드라이브로 칸을 세우고, 정한 선과 예측은 비운다(5.1).
- 4.1 표에서 지금 판이 「맞췄습니다」라고 쓰는 것은 실제로 하는 일뿐이다: 원클릭 판의 드라이브, 사무실 수용 인원(`officeCapacity`), 업무 백업 엔진의 배터리 · 절전 · 종량제 쉼. C:가 빠듯할 때의 권함은 엔진의 정한 선을 판이 받지 않아 PC 앱 값으로 본다(C:의 남은 공간이 32GB와 크기의 10% 가운데 큰 쪽보다 적고, 다른 드라이브가 100GB 넘게 그리고 C:의 세 배 넘게 남았을 때). 단추는 Windows 설정의 「새 콘텐츠를 저장할 위치」(`ms-settings:savelocations`)만 연다.
- 사무실과 원클릭(업무 백업)은 지금 볼 계정에만 열려 있다. 그 밖의 계정에게 판은 잰 값만 보이고 그 기능의 「그래서」 문장을 쓰지 않는다. 전원 · 회선 줄은 업무 백업을 볼 계정에만 둔다. 사무실에서 수를 직접 정했으면 판도 그 수를 쓴다(Fable 최종 검수 solio-pcfit-screen-20261124 F1 · F4).
- 아직 짓지 않아 판에 쓰지 않는 것: 가벼운 구 판(10절), 빈 메모리 2GB 아래에서 새 직원이 기다리기(사무실 실행에 아직 없다), 좁은 화면에서 드라이브 칸을 한 줄 막대로 줄이기, 드라이브 바뀜 알림(6절).

## 9. 시험

진단 값을 꾸며 넣는 PC 견본으로 4절 표를 줄마다 시험한다. 화면은 견본마다 원클릭 판과 5.2 판을 캡처해 검수에 싣는다.

| 견본 | 모습 |
|---|---|
| 가벼운 노트북 | 4코어 · 8GB · 내장 그래픽 · C: 256GB 하나 · 배터리 · Wi-Fi |
| 두 드라이브 데스크톱 | 8코어 · 16GB · 전용 그래픽 메모리 8GB · C: 512GB · D: 2TB HDD · 문서가 D:로 옮겨짐 |
| 개발 노트북 | 16코어 · 32GB · C: 1TB · 외장 하드 2TB · WSL · Claude Code와 Codex |
| D:를 주로 쓰는 PC | C: 128GB가 거의 참 · D: 1TB에 개발 폴더와 다운로드 |
| 가상 · 복구 드라이브가 있는 PC | C: · Google Drive G:(FAT32, C:와 같은 크기) · 복구 파티션 20GB |
| 이동식만 꽂힌 PC | C: 하나 · USB 메모리 · 네트워크 드라이브 |
| 드라이브 다섯 | C: · D: · E: · F: · 외장 하나, 둘이 선 아래 |

이 PC(24코어 · 64GB · C: 953GB · D: 1.9TB · Google Drive G:)의 실제 값으로도 한 번 재 본다. 실제 값의 캡처와 기록은 공개 저장소에 올리지 않는다. 사양과 볼륨 이름이 남기 때문이다. 저장소에는 견본 캡처만 올린다.

## 10. 확인할 것

- 엔진이 11-24 전까지 G:(Google Drive)를 실제로 훑었는지. 훑었다면 하루 5분을 그 드라이브가 먹었다. 보호를 시작하지 않은 이 PC에는 기록이 없다.
- 표준 사용자 계정과 회사 PC에서 3절 읽기가 되는지(이 PC는 관리자 그룹의 낮춘 권한으로만 쟀다). `Get-PhysicalDisk`는 7초쯤 걸려 쓰지 않는다.
- 가벼운 구 판(지금 그래픽이 없을 때 쓰는 2D 판)을 진단 값으로 고르는 길.
- 그래픽 카드를 꽂고 뽑을 때 6절 「바뀌었습니다」가 뜨는지.
- 진단 결과를 건너뛸 수 있게 할지: 기본은 건너뛸 수 있고, 건너뛰어도 기본값은 진단으로 맞춘다(Claude 제안).
