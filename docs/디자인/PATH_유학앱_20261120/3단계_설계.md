# PATH 유학 앱 3단계 설계 — 내 길과 계정 저장

2026-11-22, Claude. 유호님 「3단계 시작」. Fable 5.2 설계 검토(P0 1 · P1 6 · P2 17 · P3 4)를 반영한 판이다(맨 아래 「설계 검토와 반영」).

## 목적과 나눔

기획서의 3단계는 「내 길(서류, 기한, 수수료 세 번), 물어보기와 상담원 넘기기」이고, 끝난 모습은 「계정에 저장되고 담당자가 서류를 확인한다」다. 정하실 일이 남아 있어 셋으로 나눈다.

- **3-1a(이번):** 고른 과정 하나의 서류와 기한을 보여 주는 「내 길」, 학생 스스로의 「준비했어요」. 1 · 2단계처럼 이 탭에만 저장한다(서버로 새 개인정보를 보내지 않는다).
- **3-1b(유호님이 개인정보 저장을 정하신 뒤):** 내 조건 · 넣은 날 · 내 길을 계정에 저장하는 계정 문서 2판. 아래 「계정 문서 2판」에 고친 설계를 둔다.
- **3-2(유호님이 수수료 · 담당자 · 파일을 정하신 뒤):** 수수료 세 번, 물어보기와 「상담원에게 넘기기」, 담당자의 서류 확인과 파일 받기. 「담당자가 서류를 확인한다」는 3-2가 끝나야 채워진다.

## 3-1a 범위

1. **과정 고르기.** 대학 자세히에 「이 과정으로 준비하기」(aria-pressed)를 둔다. 고른 과정은 하나다. 누른 상태에서 다시 누르면 그만한다. 다른 과정을 고르면 앞 과정의 「준비했어요」 가운데 새 과정과 그 비자 묶음에 없는 것은 지운다(지우기 전에 「앞 과정의 표시 n개를 지워요」를 알린다).
2. **내 길 화면.** 오늘 탭 아래 화면이다. 고른 과정의 서류를 내는 때에 따라 세 묶음으로 보인다: 「원서와 함께(대학)」, 「합격 뒤(대학)」, 「비자(KVAC 몽골)」. 묶음 머리에 출처와 「2027학년도 전기 요강 기준」 같은 판 표시(원광대 학부는 「(안)」, 원광대 한국문화교육센터는 2026학년도 판)를 적는다. 진행 줄은 묶음마다 따로 센다.
3. **날짜.** 내 길에 그 과정의 날(원서 접수 차수와 서류 기한)을 2단계 날 줄 그대로 보인다(「내 길에 넣기」, 「달력에 넣기」). 그래서 「내 길에 넣기」로 넣은 날이 「내 길」 화면에서도 보인다.
4. **오늘 화면의 내 길 카드.** 고른 과정이 있으면 카드와 상관없이 「다가오는 날」 위에 둔다: 과정 이름, 원서 묶음 n/N, 가장 가까운 날, 열기.

## 서류 자료

서류는 과정마다 요강에서, 비자는 KVAC 몽골 쪽에서 직접 읽어 적는다(아래 「서류 목록」, 자료는 `docs-data.mjs`). 확인하지 못한 것은 적지 않는다.

```js
{
  id: 'jbnu-ug-transcript',          // 과정 id로 시작, 전체에서 하나
  stage: 'apply' | 'admitted' | 'visa',
  name: L('…', '…'),                 // 영어 화면에도 요강의 한국어 표기를 함께 보인다
  from, when, note: L | null,        // 받는 곳 · 유효 기간이나 발급 기한 · 원본 · 번역 · 아포스티유 같은 조건
  unclear: L | null,                 // 요강이 둘로 읽히는 곳
  only: null | { cond: L },          // 출처가 「해당자만」이라고 적은 서류. cond는 원문 조건 문장
  topikHolder: true?                 // 「가진 사람만」(원광대 학부 어학 증빙). TOPIK 「없음」을 넣은 사람에게만 접는다
}
```

- **접는 것은 출처가 「해당자만」이라고 적은 서류뿐이다.** 필수 서류는 내 조건과 상관없이 늘 보인다(전북대 학부 · 전주대 학부의 어학 증빙은 모두에게 필수). 해당자만인 서류는 빼지 않고 「해당하는 사람만」 접힘에 원문 조건과 함께 둔다(포트폴리오 · 외국인등록증 같은 줄도 여기에).
- **졸업 · 졸업 예정.** 요강이 「졸업(예정)증명서」 한 줄로 적은 곳은 한 줄로 두고, 학력에 따라 메모만 고른다. 둘로 나뉜 곳이 생기면 학력을 넣지 않았을 때 둘 다 보이고 하나로 센다.
- **진행 줄.** 묶음마다 「n/N 표시」로 센다. 접힌 서류는 세지 않는다. 비자 묶음에는 합격 뒤에 받는 서류(표준입학허가서, 사업자등록증 사본)가 있어 「대학에서 받아요」를 붙인다. 원서 묶음이 다 차면 「원서 서류를 다 표시했어요」와 함께 「해당하는 사람만 n개, 요강이 둘로 읽히는 곳 n개는 따로 확인하세요」, 요강 링크를 둔다(접수처 주소를 모르는 과정이 있어 원서 단추는 두지 않는다).
- **같은 서류의 다른 조건.** 대학의 잔고 증명과 KVAC의 예치 · 거래내역서는 명의 · 기한 · 부수가 다르다(원광대는 본인 명의 · 1개월 · 2부, KVAC는 본인이나 부모 · 14일). 합치지 않고 서로 가리키는 메모를 둔다.
- **물을 곳.** 요강이 둘로 읽히는 곳에는 「대학에 먼저 물어보세요」와 요강에 적힌 공식 문의처(대학 국제교류 부서의 공식 연락처)를 출처와 함께 둔다.
- **요강이 바뀌면.** 서류마다 조건을 고친 날(`changedAt`)을 둘 수 있게 하고, 학생의 표시가 그보다 앞이면 「조건이 바뀌었어요. 다시 확인하세요」를 붙인다(첫 판에는 고친 날이 없다).
- **검사.** 출처 · 확인한 날이 없거나, 실제로 싣는 과정이 아니거나, id가 겹치면 공개 묶음을 만들지 않는다(2단계 채널 글과 같은 관문). 확인한 지 90일이 지나면 묶음 머리에 다시 확인하라고 띄운다.

### 서류 기한을 날로

원서 마감과 서류 마감이 다른 과정이 있다(전주대 2차 원서 12-11 · 서류 도착 12-18, 전북대 학부 2차 원서 11-20 · 서류 11-27, 사본을 낸 졸업예정자의 원본 2027-02-19). 이 날들은 2단계 「대학 소식」 글의 날 목록에 함께 넣는다.

- **id는 차수에 매단다:** `univ-<과정>-<차수 시작 날>-docs`. 원본 제출은 `univ-<과정>-<차수 시작 날>-originals`. 기한 날짜가 바뀌어도 id는 그대로라 넣어 둔 학생은 「날짜가 바뀌었어요」를 본다. 다른 차수의 시작 날과 겹치지 않는다.
- **날 이름에 대상과 기준을 넣는다:** 「2차 서류 도착 기한(2차 원서를 낸 사람만 · 대학 도착 기준)」, 「원본 · 졸업 서류 제출(사본을 냈거나 졸업예정자)」. 몽골에서 보내면 여러 날이 걸린다는 메모를 둔다.
- **맨 위 글을 고를 때 서류 기한은 세지 않는다.** 원서가 끝난 차수의 서류 기한이 채널 맨 위 글이 되어 「아직 지원할 수 있다」로 읽히지 않게 한다. 내 길은 「원서 접수 끝남」과 「이미 냈다면 서류 도착 11-27」을 함께 보인다.

## 3-1a 저장(이 탭)

- 1단계 탭 저장(`synk-path-study-v1`)에 `target`(고른 과정)과 `docs`(`[{ id, doneAt }]`, 예순 개까지)를 더한다. 주인 규칙도 그대로다: 손님 것은 로그인한 계정이 이어받고, 로그아웃 · 세션 만료 · 다른 계정이면 지운다.
- 서류 자료에서 사라진 id의 표시는 남겨 두되 세지 않는다. 한도에 닿으면 조용히 실패하지 않고 화면에 알린다.
- 넣는 자리의 안내는 2단계 문장(「넣은 날은 이 탭에만 있어요. 탭을 닫거나 로그아웃하면 사라지니…」)과 같은 결로 「표시는 이 탭에만 있어요…」를 둔다.
- 「준비했어요」는 학생 자신의 표시다. 화면에 「내가 표시한 것이에요. 대학이나 KVAC가 확인한 것이 아니에요」를 적는다.

## 계정 문서 2판(3-1b, 정하신 뒤)

설계 검토의 P0 · P1을 반영한 판이다. 짓는 것은 유호님이 개인정보 저장을 정하신 뒤다.

- **검사기는 받은 판 그대로 돌려준다.** `validatePathDocument`는 1판과 2판을 모두 받되 1판은 지금과 바이트가 같게, 2판은 정한 키 순서로 새로 지어 돌려준다(저장소가 jsonb라 키 순서가 바뀌고, 응답 유실 재확인과 앱의 비교가 문자열로 견준다). 1판 → 2판 올려 읽기는 따로 둔 `upgradePathDocument`로 하고 앱만 부른다. 서버는 부르지 않는다.
- **서버(SYNK-talk `synk-path`)를 먼저 올린다.** 새 규칙: 저장된 문서의 원문 판 번호가 2인데 들어온 원문이 1판이면 409 `PATH_DOCUMENT_UPDATE_REQUIRED`. 서버 시험: 1판 저장 뒤 저장 값과 응답이 `version: 1`이고 지금 배포된 1판 검사기를 통과함, 2판 위 1판 쓰기는 판 번호가 맞아도 409. 런타임은 올린 커밋의 깨끗한 사본에서 묶고 커밋 번호를 남긴다.
- **범위 상수는 과정 자료를 끌지 않는 파일에 둔다.** 검사기가 `study-data.mjs`를 끌면 과정 자료를 고칠 때마다 서버 런타임이 낡는다.
- **손님 → 계정.** 손님 조건은 계정이 불러와졌고, 보낼 것이 남지 않았고, 충돌이 아닐 때만 「이 탭에서 넣은 조건과 날을 계정에 저장할까요?」를 묻는다. 물음에 저장할 값(급수, 성적, 돈, 날 n개)을 보이고 「지우기」도 둔다. 서버가 받은 것을 확인한 뒤에만 탭을 비운다. 「비어 있다」는 조건 · 넣은 날 · 고른 과정 · 서류 표시가 모두 없을 때다. 계정에 이미 있으면 「이 탭에서 넣은 것은 쓰지 않고 지워요」를 한 번 알리고 지운다.
- **공용 기기.** 로그아웃 · 세션 만료 · 계정 바뀜 때 탭의 조건 자료를 지운다(1단계 규칙 그대로).
- **계정에 쓸 수 없을 때 탭 대안을 두지 않는다.** 연결 끊김과 저장 실패는 지금 동기화가 초안을 보관했다가 다시 보낸다(「아직 계정에 올라가지 않았어요」). 충돌이나 불러오기 실패 때는 준비 글처럼 조건 · 서류 표시의 고침을 막고 「계정 상태를 먼저 풀어 주세요」를 보인다.
- **1판 초안의 충돌.** 1판 초안은 1판으로 나가 서버가 409로 막는다. 앱은 「준비 글은 이 초안, 조건과 서류 표시는 계정 것」으로 합쳐 다시 보낸다. 2판 초안끼리의 충돌 화면에는 「조건 · 넣은 날 · 서류 표시도 함께 바뀌어요」를 적는다.
- **손님 문서의 `study`는 늘 비운다.** 손님 조건은 탭 저장에 둔다.
- **알림과 지우기.** 로그인한 사람이 처음 넣는 자리에 무엇이 저장되는지, 누가 보는지(본인만, 담당자 열람은 3-2 전에는 없음), 어디서 지우는지 한 번 알린다. 「계정의 유학 준비 자료 모두 지우기」를 내 정보에 둔다. 확인 문장에 「이 탭의 복구 사본과 내려받은 백업 파일에는 남아요」를 적는다. 백업 내려받기 안내에도 성적과 돈이 들어간다는 줄을 더한다.
- **옛 탭.** 새로 고치지 않은 1판 탭은 2판 문서를 받으면 오류가 된다(옛 앱은 고칠 수 없다). 2판 앱은 409 `PATH_DOCUMENT_UPDATE_REQUIRED`를 「새로 고쳐 주세요」로 잇는다. 시험의 「미래 판」은 3으로 올린다(`account.mjs`의 `version > 1`도).
- **되돌리지 않는다.** 2판 문서가 생긴 뒤에는 앱이나 서버를 1판으로 되돌리지 않고 앞으로 고친다.

## 화면

- 결은 1 · 2단계와 같이 `.sx` 아래 시안 2판이다. 인라인 스타일 없음, 고리 · 구멍 · 빽빽한 점 무늬와 큰 움직임 없음.
- 내 길: 뒤로, 과정 표지(1단계 과정 표지), 「준비 중인 과정」, 과정 이름, 내는 법 · 전형료 한 줄, 날짜(원서 차수 · 서류 기한, 날 줄), 세 묶음(묶음마다 진행 줄, 판 표시, 출처), 「해당하는 사람만」 접힘, 저장 안내, 학생 표시 안내, 약속 문장.
- 서류 줄: 이름(영어 화면에는 요강의 한국어 표기를 작게 함께), 받는 곳, 기한, 메모, 「요강에서 두 가지로 읽혀요」 상자, 「준비했어요」(aria-pressed, 화면에 안 보이는 글로 서류 이름을 붙임). 누르면 진행 줄이 그 자리에서 바뀌고 초점은 단추에 남는다.
- 고른 과정이 없으면 내 길은 「대학 탭에서 과정을 골라 주세요」와 대학 탭 단추를 보인다.

## 시험 계획(3-1a)

- 서류 자료: 검사(출처, 확인한 날, 겹친 id, 싣지 않는 과정, 묶음 · 접두사), 과정마다 세 묶음(학부 D-2 · 어학 D-4-1), 「해당자만」만 접힘, 필수 어학 증빙은 급수 0이어도 보임, 「가진 사람만」은 급수 0에게만 접힘, 서류 기한 날 id가 차수에 매달려 기한 날짜를 바꿔도 그대로.
- 맨 위 글이 서류 기한을 고르지 않음. 넣어 둔 서류 기한의 날짜가 바뀌면 「날짜가 바뀌었어요」.
- 저장: 고르기 · 그만하기 · 다른 과정(앞 표시 정리와 알림), 표시 넣기 · 빼기, 예순 개 한도, 옛 저장값(칸 없음), 주인 규칙(로그아웃 · 다른 계정에서 지움, 손님 → 로그인 이어받음), 「조건 모두 지우기」가 표시를 남김.
- 내 길: 묶음마다 n/N, 「준비했어요」 뒤 초점과 알림, 다 찼을 때 문장, 고른 과정이 없을 때, 접수 끝난 과정의 날 문장, 오늘의 카드(카드 넷 모두).
- 브라우저: 폭 다섯 × 한국어 · 영어로 내 길 · 대학 자세히 · 오늘의 넘침, 깨진 그림, 실패 요청, 콘솔 오류, 잘림 0.

## 지킬 선

- 서류와 기한은 요강과 KVAC에서 직접 읽은 것만 쓴다. 학생 표시는 확인이 아니다.
- 3-1a는 새 개인정보를 서버로 보내지 않는다. 파일을 받지 않는다. 저장소는 공개라 실제 학생 자료를 커밋하지 않는다.
- 입학, 비자를 약속하지 않는다.
- 앱 공개는 카본 → Fable 화면 검수를 거친다. 3-1b의 서버 배포는 GPT 백엔드 검수를 거치고 서버를 먼저 올린다.

## 유호님이 정하실 것

1. **(3-1b) 개인정보 저장.** 로그인한 학생의 한국어 급수 · 성적 · 준비한 돈 · 학력 · 고른 과정 · 서류 표시를 계정(서버)에 저장할지. 저장한다면 synk.im 개인정보 처리방침에 이 항목을 더해야 하고, 학생이 몽골에 살고 고3(미성년)이 많아 국외 저장과 미성년 동의도 함께 확인한다.
2. **(3-2) 수수료 세 번의 금액과 돌려받는 조건.** 언제, 얼마를, 어떤 경우에 돌려주는지. 화면에 그대로 나간다.
3. **(3-2) 상담원과 담당자.** 「상담원에게 넘기기」와 학생 서류를 보고 「확인됨」을 다는 사람이 누구인지.
4. **(3-2) 파일 받기.** 여권 · 성적표 · 잔고 증명을 앱에서 받을지, 받는다면 얼마 동안 두는지.
