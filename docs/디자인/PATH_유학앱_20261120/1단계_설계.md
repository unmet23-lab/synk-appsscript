# PATH 유학 앱 1단계 설계 — 내 조건과 대학

> 상태: 설계 검토 전(2026-11-21). 유호님이 시안 2판을 보고 「네, 2판으로」라고 하셨다. [기획](README.md)의 「만드는 순서」 1단계를 실제 앱(`experiences/path-app`)에 넣는 설계다.

## 목적

학생이 로그인 없이 자기 조건(한국어, 성적, 준비한 돈, 학력)을 넣으면 과정마다 조건이 맞는지와 모자란 것을 본다. 유학원에 묻지 않아도 「나는 어디에 지원할 수 있나, 무엇이 모자라나, 한 해에 얼마가 드나」를 스스로 확인하게 하는 첫 조각이다.

## 범위

**하는 것**

1. 자료 모듈: 공식 조건 규칙(출처, 기준일, 확인한 날이 붙는다)과 과정 목록(지금은 예시).
2. 조건 대조기: 내 조건과 과정을 받아 조건마다 맞음, 부족, 확인 필요를 내는 순수 함수.
3. 화면 넷: 내 조건, 대학 목록, 대학 자세히, 나란히 보기. 시안 2판의 결로 짓는다.
4. 탭에 「대학」을 더한다. 오늘 화면에 「내 조건으로 갈 수 있는 대학」 입구를 하나 둔다.
5. 공개 묶음 도구와 미리보기 서버가 승인한 그림 자산(대학 그림 셋)을 싣게 한다.

**하지 않는 것(뒤 단계)**

- 계정 문서(`synk.path-app` 1판)는 바꾸지 않는다. 서버 함수와 문서 계약을 함께 바꿔야 해서 3단계(내 길)에서 2판으로 올린다.
- 채널, 내 길, 서류, 수수료, 생활, 취업, 부모님 화면, 물어보기.
- 투그릭 환산. 환율의 출처와 갱신 방법이 정해진 뒤에 넣는다.
- 「이 대학으로 준비 시작」. 고른 대학을 저장하는 일은 3단계다.
- 기존 화면(오늘, 찾기, 내 준비, 도움, 내 정보)의 결 바꾸기. 단계마다 그 화면을 새 화면으로 갈 때 바꾼다. 1단계 동안은 새 화면 넷만 2판 결이고 틀(머리 막대, 탭)은 그대로다.

## 사용자 흐름

1. 오늘 화면(해외 준비 카드)이나 탭에서 「대학」으로 간다.
2. 조건을 아직 안 넣었으면 대학 목록 맨 위에 「내 조건을 넣으면 맞는 곳을 알려 줘요」 판이 뜬다. 조건 없이도 목록과 자세히는 볼 수 있고, 대조 칸은 「확인 필요」로 나온다.
3. 내 조건에서 한국어 급수(없음, 1~6급), 고등학교 성적(0~100%), 준비한 돈(만 원), 학력(졸업, 졸업 예정, 아직 아님)을 넣는다. 넣는 즉시 「지금 조건으로 N곳」과 갈 수 있는 길 둘(어학 과정 먼저, 바로 학부)이 바뀐다.
4. 대학 목록에서 과정마다 「내 조건 4개 중 N개 맞음」을 본다. 「조건이 맞는 곳」, 「어학 과정」, 「학부」로 거른다.
5. 대학 자세히에서 조건마다 필요한 것과 내 것을 나란히 보고, 한 해에 드는 돈(등록금, 기숙사, 생활비, 내 급수의 장학금)을 본다. 급수를 올리면 얼마가 줄어드는지도 본다.
6. 두세 곳을 「비교」에 담아 나란히 본다.

## 자료

### `study-data.mjs`

```js
export const RULES = [  // 공식 조건. 화면에 나가려면 출처, 기준, 확인한 날이 모두 있어야 한다
  { id: 'finance-d2-local', kind: 'finance', visa: 'D-2', region: 'local', won: 16000000,
    status: 'in-force',            // 'in-force' | 'announced'(계획 발표, 시행일 미정)
    basis: '2023-07-03',           // 시행일 또는 발표일
    inCurrentGuide: true,          // 지금 쓰는 공식 안내에서 같은 값을 직접 읽었는가. false이면 대조를 「확인 필요」에 둔다
    source: { title: {ko, en}, url: 'https://www.moj.go.kr/…' }, checkedAt: '2026-11-21' },
  // finance-d2-metro 2,000만, finance-d4-local 800만, finance-d4-metro 1,000만
  // finance-proof-mn: 몽골에서 신청할 때 잔고 증명서는 신청일 기준 14일 안에 발급, 금액은 30일 넘게 유지(안내 글로만 보인다)
  // finance-topik4-waiver: status 'announced' (2026-10-07 발표, 면제 계획). 대조에는 쓰지 않고 안내 글로만 보인다
];
export const PROGRAMS = [  // 과정. 협약 전에는 모두 example: true
  { id: 'example-a-ug', example: true, name: {ko, en}, place: {ko, en}, region: 'local',
    level: 'undergraduate',        // 'language' | 'undergraduate'
    visa: 'D-2', majors: {ko, en}, image: 'univ-a',
    requires: { education: 'highschool', gradePct: 70, topik: 3 },
    costs: { tuition: 6400000, dorm: 1800000, living: 6000000 },
    scholarship: [ { topik: 3, tuitionRate: 0.3 }, { topik: 4, tuitionRate: 0.5 } ],
    applyOpens: '2027-01-21', certified: false,
    source: null, checkedAt: null } // 예시는 출처가 없다. 실제 과정(example: false)은 출처와 확인한 날이 꼭 있어야 한다
];
export function validateStudyData(rules, programs)  // 위 약속을 어기면 던진다. 모듈을 읽을 때 한 번 돌린다
export function staleItems(rules, programs, now, days = 90)  // 확인한 날이 오래된 항목 목록
```

- 재정 조건은 과정마다 적지 않고 `visa`와 `region`으로 `RULES`에서 찾는다. 규칙이 바뀌면 한 곳만 고친다.
- 「교육부 인증 대학」 표시(`certified`)는 예시 과정에서는 화면에 내지 않는다. 실제 명단과 대조한 과정에만 낸다.
- 날짜가 지난 `applyOpens`는 화면에서 「일정 확인 필요」로 바뀐다. 남은 날은 오늘 날짜로 센다.
- 확인한 날이 90일을 넘긴 규칙은 `rulesAt(rules, now)`가 `stale` 표시를 붙이고, 대조기는 그 금액으로 판정하지 않는다.
- 예시 과정의 금액, 일정, 입학 조건은 만든 값이다. 앱 README의 보관 기준(「예시의 금액 · 마감 · 비자 조건을 만들지 않는다」)에 따라 **공개판에는 예시 과정을 싣지 않는다.** `programsFor(programs, publicWeb)`가 공개판에서 예시를 걸러 내고, 실을 과정이 하나도 없으면 대학 탭과 오늘의 입구가 나오지 않는다. 미리보기(로컬)에서는 예시가 「예시」 표와 함께 보인다.
- 장학금 단계는 과정의 필요 급수보다 낮을 수 없다. 성적 조건 0은 「성적 조건 없음」이다.

### 내 조건(`study-profile.mjs`)

```js
{ v: 1, topik: null|0..6, gradePct: null|0..100, fundsWon: null|0..200000000,
  education: null|'graduated'|'expected'|'none', compare: [programId…] /* 최대 3 */ }
```

- 순수 함수 `normalizeProfile(raw)`(틀리면 빈 조건), `setField(profile, key, value)`(범위 밖이면 던진다).
- **저장:** `sessionStorage`의 새 열쇠 `synk-path-study-v1` 하나에 둔다. 손님 자료와 같은 정책이다(탭을 닫으면 사라지고 `localStorage`는 쓰지 않는다). 계정 문서와 섞지 않으며 서버로 보내지 않는다.
- **주인:** 저장값에 주인(`guest` 또는 계정 ID)을 함께 적는다. 같은 계정이면 새로 고침 뒤에도 남는다. 손님이 넣은 조건은 로그인한 계정이 이어받는다. 주인이 다른 계정이거나, 로그아웃 · 세션 만료로 손님이 되면 지운다. 시작할 때는 계정 상태가 정해지기 전이라 주인이 다르면 감추기만 하고, 정해진 뒤에 지운다. 주인 표시가 없거나 깨진 저장값은 버린다.
- 내 정보의 「이 탭의 자료 지우기」도 함께 지운다. 내 조건 화면에 「조건 모두 지우기」가 있다(로그인한 사람도 쓴다).
- 저장이 막힌 환경에서는 화면 안에서만 기억하고 「새로 고치면 사라져요」라고 알린다. 성공한 것처럼 보이지 않는다.
- 화면에 「이 조건은 이 탭에만 저장돼요. 계정에는 저장되지 않고, 탭을 닫거나 로그아웃하면 사라져요.」를 적는다. 내 정보의 저장 방식 칸에도 같은 뜻을 적는다.

## 조건 대조기(`match.mjs`)

```js
matchProgram(profile, program, rules) → {
  items: [ { key: 'education'|'grade'|'topik'|'finance', status: 'ok'|'lack'|'check',
             need: {…}, mine: {…}, gap: number|null, rule: RULE|null } ],   // 늘 이 순서로 넷
  okCount, canApplyAcademically,  // 성적과 한국어가 둘 다 'ok'
  fits                            // 성적과 한국어가 맞고, 넣은 조건 가운데 '부족'이 없다
}
countFit(profile, programs, rules, topik?) → number|null   // 성적이나 한국어를 안 넣었으면 null(세지 않는다)
programCost(profile, program) → { tuition, dorm, living, scholarship, total, nextLevel: {topik, total}|null }
routes(profile, programs, rules) → { languageFirst: {status, count}, direct: {status, count, topikGap} }
```

판정 규칙

| 조건 | 맞음 | 부족 | 확인 필요 |
|---|---|---|---|
| 학력 | 졸업, 졸업 예정 | 아직 아님 | 안 넣음 |
| 성적 | 내 % ≥ 필요 %. 필요 %가 0이면 늘 맞음 | 내 % < 필요 % | 안 넣음 |
| 한국어 | 내 급수 ≥ 필요 급수. 필요 급수가 0이면 늘 맞음 | 내 급수 < 필요 급수 | 안 넣음(필요 급수가 0이 아닐 때) |
| 재정 | 준비한 돈 ≥ 규칙 금액 | 준비한 돈 < 규칙 금액 | 안 넣음, 맞는 규칙을 못 찾음, 규칙을 현행 안내에서 확인하지 못함, 확인한 지 90일이 넘음 |

- 「지금 조건에 맞는 곳」은 `fits`인 과정 수다. 성적과 한국어를 둘 다 넣어야 세고, 하나라도 비면 숫자 대신 「성적과 한국어를 넣으면 맞는 곳을 알려 줘요」를 낸다(안 넣어서 0으로 보이지 않게). 넣은 학력이나 돈이 부족하면 빼고, 안 넣은 학력과 돈은 봐준다. 머리 숫자와 「조건이 맞는 곳」 거르기는 `countFit` · `fits` 한 기준을 쓴다.
- 과정이 모두 예시인 동안에는 「대학 N곳」이라고 쓰지 않고 「N개의 예시 과정이 지금 조건에 맞아요 (예시 3개 중)」이라고 쓴다.
- 장학금은 내 급수 이하에서 가장 높은 단계의 비율을 등록금에 곱한다. 급수를 안 넣었으면 0이다.
- `nextLevel`은 내 급수보다 높은 단계 가운데 가장 가까운 것으로 다시 계산한 합계다. 없으면 `null`이다.
- 결과는 판정이 아닌 대조다. 화면마다 「입학이나 비자를 약속하지 않아요. 마지막 판단은 대학과 출입국이 해요.」를 둔다.

## 화면

시안 2판의 해당 화면(내 조건, 대학, 대학 자세히, 나란히 보기)을 따른다. 달라지는 점만 적는다.

- **틀:** `TABS`에 `univ`를 `today` 다음에 넣는다(여섯 탭). 320px에서 넘치지 않는지 잰다. `cond`, `univDetail`, `univCompare`는 `univ` 탭의 아래 화면이다.
- **결의 범위:** 새 화면은 `<div class="sx">` 안에 짓고 2판의 색(청금석, 버터, 메도우, 코랄), 알약 단추, 그림 판을 `.sx` 아래에만 적용한다. 기존 화면의 CSS는 건드리지 않는다.
- **인라인 스타일 금지:** 공개 CSP가 `style-src 'self'`다. 그림 자리, 막대 길이는 클래스와 속성 선택자로만 한다.
- **입력:** 한국어와 학력은 누르는 단추 묶음(`aria-pressed`)이고, 누른 뒤 같은 단추로 초점이 돌아온다. 성적과 돈은 글 입력(`type="text" inputmode="numeric"`)이다. 치는 동안 칸은 다시 그리지 않고, 칸 아래 글과 결과 자리(`#sx-cond-result`)만 바꾼다. 읽을 수 없거나 범위 밖인 값은 던지지 않고 칸 아래 글로 알리며 조건은 그대로 둔다.
- **시안에서 뺀 것:** 「3급까지 가는 길 보기」(채널 글 연결), 대학 자세히의 지어낸 모집 요강 출처 줄, 「원룸 14곳」 · 「몽골 선배 12명」과 생활 화면 연결. 뒤 단계의 일이다.
- **말:** 한국어와 영어 둘 다 쓴다. 예시 과정에는 「예시」 표를 붙이고 목록 위에 「협력 대학은 준비 중이에요. 지금 보이는 과정은 자리를 보이려고 넣은 예시예요.」를 둔다.
- **그림:** 대학 그림 셋(`univ-a`, `univ-b`, `univ-c`, webp 960px)을 `experiences/path-app/assets/`에 둔다. `alt`는 빈 값이다(이름이 바로 옆 글에 있다). 가로세로 값을 준다. 그림 이름의 승인 목록은 `study-data.mjs`의 `IMAGE_IDS` 하나이고 서버와 공개 묶음 도구가 함께 읽는다. 공개 묶음은 공개판에 싣는 과정이 쓰는 그림만 싣는다.
- **오늘 화면:** 해외 준비 카드일 때 「다음 한 걸음」 상자 아래에 한 줄 입구를 둔다. 예시만 있는 동안에는 「예시 과정으로 내 조건 맞춰 보기」다. 다른 구역은 그대로다.
- **읽기 전용일 때:** 조건은 계정 자료가 아니라서 `LOCKED_ACTIONS`에 넣지 않는다. 계정 문서가 있고 편집만 막힌 경우에 조건 대조를 쓸 수 있다. 계정 자료를 불러오는 중이거나 실패해 내 정보로 돌려보내는 경우, 첫 실행을 마치지 않아 탭이 없는 경우에는 닿지 않는다.

## 시험 계획

- `study-data.test.mjs`: 규칙마다 출처(https), 기준, 확인한 날이 있다. 예시가 아닌 과정에 출처가 없으면 던진다. 과정의 `visa`와 `region`에 맞는 재정 규칙이 꼭 있다. `staleItems`가 날짜를 넘긴 항목만 낸다.

## 지킬 선

- 입학, 비자, 장학금을 약속하지 않는다. 예시의 금액과 조건을 실제처럼 보이지 않게 「예시」를 붙인다.
- 공식 조건은 출처와 확인한 날 없이 화면에 나가지 않는다. 「계획 발표」와 「시행 중」을 구분한다.
- 조건(성적, 준비한 돈)은 탭 밖으로 나가지 않는다. 기록, 통계, 주소에 넣지 않는다.
- 실제 대학 이름은 협약이나 공개 요강 확인 전에는 쓰지 않는다.

## 실제 과정: 대학이 공개한 모집 요강(2026-11-21, 유호님 「공개 요강으로」)

대학 탭의 첫 실제 자료를 대학이 공개한 모집 요강에서 옮겼다. 협약 대학이 아니므로 화면에 「협력」이라고 쓰지 않는다.

| 과정 | 옮긴 문서 | 접수 |
|---|---|---|
| 전북대학교 학부 | 2027학년도 전기 학부 외국인특별전형 모집요강(2026. 9.) | 3월 입학은 2026-11-20에 끝남 |
| 전북대학교 한국어학당 | 한국어학당 누리집의 연수과정 안내와 수업료 인상 공지(2026-09-09) | 봄학기 2026-11-30 ~ 12-25 |
| 원광대학교 학부 | 2027학년도 1학기(3월) 외국인 학부 신(편)입학 모집요강 | 1차 2026-11-23 ~ 11-27, 2차 12-28 ~ 12-31 |
| 원광대학교 한국문화교육센터 | 2026 한국문화교육센터 모집요강 | 봄학기 2026-12-01 ~ 12-24 |
| 전주대학교 학부 | 2027학년도 전기 외국인 신 · 편입학 특별전형 모집요강 | 2차 2026-12-01 ~ 12-11, 3차 2027-01-04 ~ 01-13 |

- **고른 까닭:** [정착관리 기획](../../PATH_정착관리/README.md)의 시범 상대 후보에 전주권 대학과 원광대가 적혀 있다. 유호님이 다른 대학을 정하시면 바꾼다.
- **확인한 방법:** 대학마다 조사를 따로 맡겨 요강 PDF와 누리집 쪽을 내려받게 했고, 등록금 · 한국어 조건 · 접수일 · 장학금 · 기숙사비는 내려받은 원문에서 Claude가 다시 직접 읽었다. 출처 링크와 확인한 날이 과정마다 화면에 나온다.
- **넣지 않은 것:** 전주대학교 한국어학당. 수업료가 누리집(130만 원)과 2025학년도 요강(1,350,000원)에서 다르고 2027년 일정이 아직 없다.
- **자료 꼴에 더한 것:** 실제 과정은 지어낸 건물 그림을 쓰지 않는다(`image: null`, 색 판과 도시 이름 표지). 대학이 안내하지 않은 비용은 `null`로 두고 합계에 넣지 않으며 「확인된 비용의 합」이라고 쓴다. 장학금은 비율 또는 금액(`won`)으로 적는다. 접수 차수가 여럿이면 `applyRounds`에 적고, 끝난 접수는 「접수 끝남」으로 보인다. `partner`가 참인 과정이 있을 때만 「협력 대학」이라고 쓴다.
- **예시와의 관계:** 실제 과정이 하나라도 있으면 미리보기와 공개판 모두 실제 과정만 보인다. 예시 셋은 시험과 「실제 과정이 없을 때」의 길로 남는다.
- **요강과 다르게 계산한 곳:** 원광대 입학 장학금은 요강에 기간이 없어 첫 학기 등록금으로만 계산했다. 전북대 TOPIK 5급 장학금은 수업료2의 50%라 인문 계열 금액(820,500원)으로 적었다. 등록금은 가장 낮은 계열(인문 · 사회) 기준이고 다른 계열 금액은 글로 적었다.
- **다시 확인할 때:** 요강은 학기마다 바뀐다. 과정의 `checkedAt`이 오래되면 운영 화면에서 알리는 일은 뒤 단계에 있다. 지금은 접수 차수가 모두 지나면 「접수 끝남」으로 보인다.
- 시험 155개 통과. 브라우저 104개 경우(폭 넷 × 언어 둘 × 화면 열셋)에서 가로 넘침, 깨진 그림, 실패 요청, 새 콘솔 오류 0. 캡처는 [캡처/실제과정](캡처/실제과정/)에 있다.

## 검토에서 봐 주었으면 하는 것

1. 내 조건을 계정 문서에 넣지 않고 탭 저장으로 두는 것이 1단계로 맞는가.
2. 「N곳」을 성적과 한국어만으로 세는 것이 학생에게 오해를 주지 않는가.
3. 새 화면만 2판 결이고 틀과 기존 화면은 옛 결인 상태로 공개해도 되는가, 아니면 공개를 2단계 뒤로 미뤄야 하는가.
4. 그림 자산을 공개 묶음에 싣는 방식에 빠진 위험이 있는가.
