# PATH 상담 넘기기와 Workspace 상담함 설계 (3-2a)

2026-11-27, Claude. 유호님 「설계 시작」(PATH 앱과 Workspace 연동을 여쭌 뒤). [3단계 설계](3단계_설계.md)의 3-2 가운데 「상담원에게 넘기기」를 Workspace에 잇는 부분이다. 수수료 세 번과 파일 받기(3-2b)는 이 설계에 넣지 않는다. Fable 5.2 설계 검토(P0 0 · P1 6 · P2 8)를 반영한 판이다(맨 아래 「설계 검토와 반영」).

## 한 문장

학생이 PATH 앱에서 「상담원에게 넘기기」를 누르면, 고른 내용의 사본과 질문이 Workspace의 「PATH 상담함」에 한 건으로 들어온다. PATH 담당 직원은 그 건에 답하고, 서류마다 안내한 것을 표시한다. 학생은 PATH 앱의 「내 상담」에서 답과 표시를 본다.

## 지금 상태

- PATH 앱의 학생 자료(`path-study`)는 SYNK-talk의 Supabase(싱가포르)에 있고, 본인 토큰으로만 읽힌다. 직원이 읽는 길은 없다.
- Workspace 회사 서버(서울)는 자기 SQLite에 자료를 둔다. PATH 소속 역할(counselor · operations · manager)은 이미 있지만, PATH 업무는 직원이 손으로 적는 `companyWork`뿐이다.
- 홈페이지 문의 폼의 「PATH · 유학·취업 연계」 문의만 Workspace 「문의 접수」(관리자만)에 들어온다.
- 정직원 조건(10-23 결정)은 PATH 상담 담당이 결과를 약속하지 않고, 서류는 사실대로 다루고, 상담 기록은 회사 시스템에 남긴다고 정했다.

## 구조: 학생이 보낸 사본을 Workspace가 원본으로 쥔다

| | 고른 길 | 버린 길 |
|---|---|---|
| 자료가 가는 길 | 학생이 넘기기를 누를 때 PATH 앱이 고른 항목의 사본을 Workspace에 직접 보낸다(PULSE 의뢰서와 같은 결) | Workspace가 서버 키로 Supabase의 `path-study`를 읽는다 |
| 까닭 | 학생이 보낸 것만 직원에게 간다. Supabase의 닫힌 규칙(본인만)을 그대로 둔다 | 모든 학생 문서를 읽을 수 있는 키가 회사 서버에 생긴다. 동의는 「본인만 봄」이었다 |

- **상담 건의 원본은 Workspace SQLite다.** 학생의 `path-study`는 바뀌지 않는다. 학생이 나중에 조건을 바꿔도 건에 든 사본은 보낸 때의 것이다. 다시 보내면 새 사본이 같은 건에 더해지고, 최근 사본 셋만 남긴다.
- **로그인은 하나로 둔다.** PATH 앱은 이미 학생의 SYNK ID 토큰을 쥐고 있다. Workspace에 학생용 경로 `/api/path-student/*`를 새로 두고 그 토큰(Bearer)을 받는다. 고객 쿠키 경로(`/api/customer`)와 접두사를 나눠, 고객 세션과 직원 세션 확인보다 먼저 끝낸다.
- **토큰 확인.** 먼저 주소별 요청 한도, 토큰 꼴, 만료, 발급자, `client_id`(PATH 앱 클라이언트)를 서버 안에서 본다. 이것을 통과한 토큰만 중앙 `synk-account`에 물어 계정이 `active`이고 현재 세션이며 철회되지 않았는지 확인한다(고객 상담 `verify()`와 같은 조건). PATH 앱과 고객 상담은 둘 다 제품이 `platform`이라 `client_id`로만 갈린다. 두 방향(고객 상담 토큰으로 PATH 경로, PATH 토큰으로 고객 상담 경로)이 모두 거절되는지 시험한다.
- **학생 토큰을 쥐지 않는다.** 회사 서버는 받은 Bearer를 확인에만 쓰고 저장하거나 로그에 남기지 않는다. 그 토큰은 `path-study` 전체를 읽을 수 있기 때문이다.
- **CSRF와 CORS.** 학생 경로는 쿠키를 읽지 않고 `Access-Control-Allow-Credentials`를 주지 않는다. 그래서 CSRF 토큰은 두지 않는다. CORS는 `https://synk.im` 하나만 열고, OPTIONS와 오류 답에도 같은 머리말을 싣는다. PATH 앱 공개 묶음의 CSP `connect-src`에 Workspace 출처를 더한다.
- **로그인 없는 상태 묻기.** `GET /api/path-student/status`는 `{ open: true|false }`만 답한다. 앱은 이것으로 넘기기 단추를 보일지 정한다. 답을 못 받으면 지금처럼 hello@synk.im을 보인다.

## 학생 화면 (PATH 앱)

### 넘기기

「물어보기」(머리 막대)와 「내 길」 카드 아래에 「상담원에게 넘기기」를 둔다. 누르면 한 장짜리 화면이 열린다.

1. **나이.** 만 14세 미만 · 14~17세 · 18세 이상 가운데 고른다. 14세 미만이면 넘기기를 쓸 수 없고 「보호자가 hello@synk.im으로 물어봐 주세요」를 보인다. 서버도 같은 값을 다시 검사한다.
2. **보낼 것 고르기.** 내 조건(한국어 · 성적 · 준비한 돈 · 학력), 고른 과정, 서류 표시, 넣은 날. 칸마다 체크하며 처음에는 모두 켜져 있다. 빈 칸은 보이지 않는다. 비교 목록과 끈 채널은 보내지 않는다.
3. **물어볼 말.** 1,000자까지. 「여권번호, 등록번호, 비밀번호는 쓰지 마세요」를 칸 위에 적는다. 보내기 전에 앱이 몽골 등록번호와 여권번호 꼴을 찾아 `[가림]`으로 바꾼다. 서버도 같은 검사로 다시 가린다. 되돌릴 원래 값은 어디에도 두지 않는다.
4. **답받을 말.** 한국어 · 몽골어 · 영어 가운데 하나.
5. **동의.** 아래를 적고 「동의하고 보내기」를 눌러야 보낸다. 14~17세는 「보호자가 함께 읽고 동의했어요」를 더 눌러야 단추가 열린다.
   - 보내는 것: 고른 칸, 물어볼 말과 이어지는 대화, SYNK ID, 표시 이름, 로그인한 메일.
   - 보는 사람: SYNK PATH 상담 담당과 PATH 책임자, SYNK 대표.
   - 두는 곳: 한국 서울의 SYNK 회사 서버(몽골 밖). 회사 서버의 매일 백업에는 지운 뒤에도 최대 38일 남았다가 사라진다.
   - 번역: 답받을 말이 한국어가 아니면, 학생 글과 담당자 답이 Claude(Anthropic, 미국)를 거쳐 옮겨진다. Anthropic은 이 글을 AI 학습에 쓰지 않는다.
   - 보관: 끝난 상담은 90일 뒤 지운다. 언제든 「이 상담 지우기」로 바로 지울 수 있다.
   - 약속하지 않는 것: 입학 · 비자 결과. SYNK 담당자의 안내는 대학이나 KVAC의 확인이 아니다.
6. **보내기.** 보낸 뒤 「받았어요. 담당자가 답하면 이 앱에 표시해 드려요」를 보이고 「내 상담」으로 간다.

동의 기록은 사본마다 `{ v, at, age: 'adult' | 'minor', guardian, lang, fields }`로 남긴다. `fields`는 그때 고른 칸이다. 다시 보낼 때도 같은 동의 화면을 거친다.

학생 한 사람에게 열린 건은 하나만 둔다. 열린 건이 있으면 「상담원에게 넘기기」는 그 건에 이어 쓰기가 된다.

### 내 상담

오늘 탭에 「내 상담」 카드가 생긴다. 열린 건이 있는 학생만 Workspace에 묻는다. Workspace가 답하지 않으면 카드만 「지금 불러오지 못했어요」로 둔다.

| 상태 | 학생에게 보이는 말 |
|---|---|
| 받음 | 담당자가 곧 봐요. 보통 이틀 안에 답해요 |
| 보는 중 | ○○ 담당자가 보고 있어요 |
| 답 왔음 | 새 답이 있어요 |
| 끝남 | 상담이 끝났어요. 다시 물어볼 수 있어요 |

- 대화는 시간 순서의 글 목록이다. 학생과 담당자만 쓴다. 번역된 글에는 「번역」 이름표를 달고, 펼치면 원문이 보인다.
- 담당자의 서류 표시는 「내 길」의 그 서류 줄에도 보인다. 파일을 받기 전이라 담당자는 서류를 직접 보지 않는다. 그래서 표시는 한 일 그대로 쓴다. 「담당자가 이 서류를 안내했어요」 또는 「담당자가 다시 확인해 달래요」와 한 줄이다. 그 아래에 「대학이나 KVAC의 확인이 아니에요」를 늘 붙인다.
- 「이 상담 지우기」는 건 전체(사본 · 대화 · 표시)를 바로 지운다. 누르기 전에 「내 길의 담당자 표시도 함께 사라져요」를 알린다.

## 직원 화면 (Workspace 「PATH 상담함」)

- **누가 보나.** PATH 소속의 역할을 직접 검사한다(`path` 기능 검사로 끝내지 않는다).
  - counselor: 자기에게 배정된 건을 보고 쓴다.
  - manager: 모든 건을 보고 쓰고 배정을 바꾼다.
  - 회사 주인: manager와 같다.
  - operations, 다른 회사 관리자, 보기 전용(viewer) 계정: 보지 못한다.
- **목록.** 문의 접수와 같은 「목록 + 상세」 꼴로 둔다. 새 건 · 보는 중 · 답함 · 끝남으로 나누고, 답을 기다린 날수를 함께 적는다.
- **상세.** 학생이 보낸 사본(보낸 날 표시), 물어본 말, 대화, 서류 목록이 있다. 서류 목록은 PATH 앱의 `docs-data.mjs`를 그대로 읽어 학생 화면과 같은 이름 · 출처를 보인다. 서류마다 「안내했어요」 · 「다시 확인해 주세요」와 한 줄을 단다. 직원 글도 학생 글과 같은 가리기를 거친다.
- **번역.** 학생이 몽골어나 영어로 쓴 글은 한국어 번역을 원문과 함께 보인다. 담당자가 한국어로 쓴 답은 학생의 말로 옮긴 초안을 담당자가 보고 보낸다. 번역 전에 서버가 번호를 다시 가린다.
- **하지 않는 것.** 직원은 학생 사본을 고치지 못한다. 학생 대신 대학이나 KVAC에 내지 않는다. 화면 머리에 「입학 · 비자 결과를 약속하지 않아요. 학생과의 연락은 이 상담함에서만 해요」를 둔다.
- **연 기록.** 직원이 건을 열 때마다 누가 언제 열었는지 건 밖의 기록에 남긴다. manager와 회사 주인이 본다.

### 상태와 담당

| 일 | 바뀌는 것 |
|---|---|
| 학생이 넘기기 | 새 건 `new`, 담당은 상담함 설정의 기본 담당자(없으면 회사 주인) |
| 담당자가 건을 엶 | `new` → `reviewing` |
| 담당자가 답을 보냄 | `answered`. 학생이 읽으면 읽은 때를 남긴다 |
| 학생이 새 글 | `answered` → `reviewing` |
| 담당자나 학생이 끝냄 | `closed`. 학생이 다시 물으면 새 건이다 |
| 담당자 계정이 꺼지거나 PATH 소속에서 빠짐 | 그 사람의 열린 건은 기본 담당자에게 돌아간다 |

### 할 일과 알림

- 새 건과 학생의 새 글은 담당자의 「오늘 할 일」에 내용 없이 링크만 뜬다.
- 학생 알림은 앱 안 표시가 먼저다. 메일은 중앙이 받아들인 토큰에 메일이 있을 때만 그 주소로 보낸다. 학생이 주소를 적지 않는다. 메일에는 「새 답이 있어요」와 앱 링크만 넣고, 한 시간 안에 온 답은 한 통으로 묶는다.

## 자료

`pathCases` 문서 한 건(Workspace `documents`). 본문은 문의 접수처럼 `store.encrypt`로 싸서 둔다. 밖에는 SYNK ID, 상태, 담당, 판 번호, 마지막 학생 확인 시각만 둔다.

```json
{
  "id": "pc_…",
  "student": { "synkUserId": "…", "name": "표시 이름", "email": "토큰의 메일 | null" },
  "state": "new | reviewing | answered | closed",
  "ownerId": "직원 id",
  "lang": "ko | mn | en",
  "snapshots": [{ "at": "…", "consent": { "v": 1, "at": "…", "age": "minor", "guardian": true, "lang": "mn", "fields": ["topik", "target", "docs"] }, "profile": { "topik": 3, "target": "jbnu-ug", "docs": {} } }],
  "messages": [{ "id": "요청 번호", "at": "…", "from": "student | staff", "staffId": null, "text": "…", "original": "번역 전 글 | null" }],
  "docMarks": { "<서류 id>": { "mark": "guided | recheck", "note": "…", "staffId": "…", "at": "…" } },
  "readAt": null,
  "revision": 7,
  "closedAt": null
}
```

- 사본은 전용 검사기 `path-case-shape.mjs`로 본다. `study-shape.mjs`의 칸 범위를 가져다 쓰되, 고른 칸만 있어도 받고 `compare` · `channelsOff` · `consent.base`는 받지 않는다. 앱과 서버가 함께 쓴다.
- 글은 1,000자, 건 하나의 글은 100개, 사본은 최근 셋, 건 크기는 512KB로 묶는다. 넘기기는 학생 한 사람이 하루 5번, 글은 하루 30개까지다.
- 글 더하기는 판 번호 조건 없이 서버가 끝에 잇고, 요청 번호로 같은 글이 두 번 들어가지 않게 한다. 배정 · 상태 · 표시 바꾸기는 판 번호 조건부로 한다.
- 글 한도에 닿아도 직원의 답 하나와 끝내기는 된다. 학생에게는 「글이 많아 새 상담으로 이어 주세요」를 보인다.
- 「열린 건 하나」는 건을 만드는 트랜잭션 안에서 SYNK ID로 확인한다.

## 보관과 지우기

- 학생이 「이 상담 지우기」를 누르면 바로 지운다.
- 끝난 건은 90일 뒤 지우고 14일 전에 앱 안에 알린다(PULSE 의뢰 기록과 같은 기간). 180일 동안 아무도 쓰지 않은 열린 건도 끝내고 같은 규칙을 따른다.
- 학생이나 보호자가 hello@synk.im으로 지워 달라고 하면, 회사 주인이 상담함에서 지운다. 문의 접수의 지우기처럼 확인 번호를 받는 두 단계로 한다.
- 건을 지운 뒤 회사에는 내용 없는 줄 하나(만든 날, 끝난 날, 담당, 글 수)를 남길지 유호님이 정하신다(아래 4).
- 처리방침에 「PATH 상담」 문단을 더한다. 사본이 몽골에서 한국(서울)으로 가는 것, 번역이 미국의 Anthropic을 거치는 것, 백업 기간을 적는다.

### 계정을 지운 학생

중앙의 계정 삭제는 DB 예약이 한다. 회사 서버는 그 소식을 받지 않고, 관리자 토큰은 사람의 로그인에 묶여 예약 일에 쓸 수 없다. 그래서 좁은 질문 하나를 새로 둔다.

- 중앙 `synk-account`에 `account-liveness` 동작을 더한다. 몸은 SYNK ID 최대 100개이고, 답은 ID마다 `present` · `leaving` · `gone` 가운데 하나뿐이다. 이름과 메일은 싣지 않는다.
- 인증은 이 용도만의 HMAC 열쇠로 한다. 시각과 서명을 머리말에 싣는다(중앙이 Workspace에 가입을 알릴 때 쓰는 꼴의 반대 방향). Supabase 서버 키는 쓰지 않는다.
- Workspace는 매일 한 번, 마지막 학생 확인이 24시간을 넘은 건을 묻는다.
- `gone`이면 건, 할 일, 알림 대기를 지운다. `leaving`(삭제 요청 뒤 유예 7일)이면 직원 화면에서 숨기고 메일을 멈춘다. 학생이 삭제를 취소하면 되돌린다.
- 모르거나 실패하면 지우지 않는다. 한 번에 `gone`이 3건 또는 20%를 넘으면 지우지 않고 관리자에게 알린다.

## 스위치

- Workspace의 `PATH_CASES_ENABLED`가 정확히 `true`일 때만 새 건과 새 글을 받는다.
- 꺼져 있어도 학생의 읽기와 지우기, 보관 정리, 계정 삭제 정리는 늘 돈다. 이미 온 답을 읽고 건을 지울 수 있어야 하기 때문이다.
- 켜기 전에는 허용 목록(`PATH_CASES_ALLOW`)의 계정만 넘기기를 쓴다. 유호님 계정으로 실제 왕복을 먼저 확인한다.

## 지킬 선

- 입학 · 비자를 약속하지 않는다. 담당자 표시는 안내한 것이고, 대학이나 KVAC의 확인이 아니다. 「봤어요」는 파일을 받은 뒤(3-2b)에만 쓴다.
- 파일은 받지 않는다. 학생이 글에 여권번호나 등록번호를 쓰면 앱과 서버가 가린다.
- 학생과 직원의 연락은 상담함에서만 한다(정직원 조건의 「학생 1:1 연락은 회사 계정」).
- 회사 서버는 학생 Bearer를 저장하거나 기록하지 않는다.
- 저장소는 공개다. 실제 학생 건은 시험 자료로 쓰지 않는다.

## 만드는 순서

1. SYNK-talk: `synk-account`의 `account-liveness`와 HMAC 열쇠. 시험을 먼저 쓴다.
2. Workspace 서버: `path-cases.mjs`(자료 · 상태 · 권한 · 한도 · 가리기 · 연 기록), `/api/path-student/*`(학생), `/api/path-cases/*`(직원), 보관 정리와 계정 정리 예약, 번역 부르기.
3. Workspace 화면: 「PATH 상담함」 목록과 상세, 오늘 할 일 연결.
4. PATH 앱: 넘기기 화면, 내 상담 카드, 내 길의 서류 표시, CSP. 스위치가 꺼져 있으면 지금 화면 그대로다.
5. 처리방침 문단.
6. 검수: 중앙과 Workspace 서버는 GPT 백엔드 검수, 두 화면은 카본 → Fable 화면 검수. 중앙 → 회사 서버(스위치 꺼짐) → 앱 순서로 올린다.

## 유호님이 정하실 것

1. **지금 상담을 받는 사람.** PATH 상담 담당은 2027년 초에 뽑는다. 그 전에 들어오는 건은 유호님(회사 주인)이 받는 것을 추천한다. 학생 화면의 「보통 이틀 안에 답해요」도 이 기준이다. 다른 사람이 받는다면 Workspace에 PATH counselor로 등록한다.
2. **몽골어 상담.** 학생 글은 한국어 번역과 원문을 함께 보시고, 한국어로 쓰신 답은 Claude가 옮긴 초안을 보고 보내시는 것을 추천한다. 학생에게는 동의 화면에서 번역 처리를 알린다.
3. **넘기기를 여는 때.** 서버와 화면을 지은 뒤 스위치를 꺼 둔 채 올리고, 유호님 계정으로 왕복을 확인한 다음 켜시는 것을 추천한다.
4. **지운 상담의 흔적.** 학생이 지운 뒤 회사에 내용 없는 줄(만든 날, 끝난 날, 담당, 글 수)을 1년 남길지. 추천은 남기는 것이다. 정직원 조건의 「상담 기록은 회사 시스템에」를 지키면서 학생 자료는 남지 않는다. 남긴다면 동의 화면과 처리방침에 적는다.

이 설계에 넣지 않은 3-2의 나머지 둘(수수료 세 번, 파일 받기)은 따로 정하신 뒤 이어서 설계한다.

## 설계 검토와 반영(2026-11-27, Fable 5.2)

P0 0건 · P1 6건 · P2 8건. 모두 반영했다.

- P1-1 동의와 실제 열람: 보내는 것에 이름 · 메일 · 대화를 넣고, 관리자 열람을 회사 주인으로 좁히고, 백업 기간을 적었다.
- P1-2 번역: 동의에 Anthropic(미국)을 적고, 양방향 번역과 원문 함께 보이기, 서버 재가리기를 넣었다.
- P1-3 스위치: 새 건과 새 글만 막는다.
- P1-4 「봤어요」: 파일 전에는 「안내했어요」 · 「다시 확인해 주세요」로 쓴다.
- P1-5 계정 삭제 정리: `account-liveness`와 HMAC 열쇠, 대량 삭제 막기를 넣었다.
- P1-6 operations: PATH 소속 역할을 직접 검사하고 viewer를 뺐다.
- P2: CSP · CORS와 접두사 분리, 사본 전용 검사기와 암호화, 여권번호 가리기와 서버 재가리기, 한도 정리와 요청 번호, 상태 전이 표와 떠난 담당자, 토큰 사전 검사와 Bearer 비저장, 메일은 토큰의 주소만, 나이 셋과 사본마다 동의.
