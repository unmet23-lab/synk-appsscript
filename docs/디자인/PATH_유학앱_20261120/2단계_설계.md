# PATH 유학 앱 2단계 설계 — 채널과 「내 길에 넣기」

> 상태: 설계 검토 반영(2026-11-21). 유호님이 1단계 공개 뒤 「2단계 시작」이라고 하셨다. [기획](README.md)의 「만드는 순서」 2단계(채널과 채널 글, 「내 길에 넣기」 — 끝난 모습: 글의 기한이 오늘 화면에 뜬다)를 실제 앱(`experiences/path-app`)에 넣는 설계다. 화면 결은 시안 2판의 채널 · 채널 글 화면을 따른다. 설계 검토는 Fable 5.2가 사용량 한도(11-27 08시 초기화)라 Opus 5.5가 대신 봤다(아래 「설계 검토와 반영」).

## 목적

학생이 유학원에 묻지 않고 한국 유학 소식을 주제별로 읽는다. 글마다 공식 출처와 확인한 날이 붙는다. 글 아래 「내게 해당되나요?」가 내 조건을 기준과 나란히 보여 준다. 시험이나 접수 날을 「내 길에 넣기」로 넣으면 오늘 화면의 「다가오는 날」에 그 날이 남은 날과 함께 뜬다.

## 범위

**하는 것**

1. 자료 모듈 `channel-data.mjs`: 채널, 글, 검사. 글마다 요점 셋, 출처, 확인한 날, 상태(공식 일정 · 안내 또는 계획 발표)가 있다.
2. 「대학 소식」 글은 손으로 옮기지 않고 `study-data.mjs`의 실제 과정 접수 차수에서 만든다. 날의 id는 차수의 시작 날로 만든다(`univ-<과정>-<시작 날>`). 차수를 끼우거나 빼도 다른 차수의 id가 바뀌지 않는다.
3. 화면 둘: 채널(맨 위 큰 글 하나, 채널 목록, 채널 하나를 누르면 그 채널 글 목록), 채널 글(요점 셋, 출처, 「내게 해당되나요?」, 날 목록과 「내 길에 넣기」, 공식 접수처 링크).
4. 오늘 화면: 넣은 날이 하나라도 있으면 카드와 상관없이(유학 준비 · 유학 중 · 취업 준비 · 카드 없음) 「다가오는 날」을 둔다. 「새 소식」 두 편은 유학 카드에만 둔다.
5. 아래 탭에 「채널」(영어 News)을 오늘 다음에 더한다. 손으로 쓴 글이 하나 이상 있을 때만 연다(`CHANNEL_ON`). 대학 탭 스위치와 따로 둔다.
6. 저장: 1단계의 탭 저장(`sessionStorage` `synk-path-study-v1`)에 `dates`와 `channelsOff`를 더한다. 판 번호(v1)는 그대로 두고, 이 칸이 없던 옛 저장값은 빈 목록으로 읽는다.
7. 날마다 「달력에 넣기」(.ics 내려받기). 서버에도 기기 저장소에도 남기지 않고 학생 휴대폰 달력의 알림을 얻는다. 앱 안 브라우저에서 내려받기가 막히면 그 날의 날짜와 이름을 복사할 수 있게 둔다.
8. 공개 묶음 도구(`tools/prepare-path-app-public.mjs`)가 채널 자료를 검사한다. 틀린 글이면 묶음을 만들지 않는다.

**하지 않는 것(뒤 단계)**

- 계정 문서에 넣은 날 저장하기. 계정 문서(`synk.path-app` 1판)는 칸 목록을 정확히 맞춰 보는 계약이라 칸만 더할 수 없다. 3단계(내 길)에서 2판으로 올릴 때 조건, 비교, 넣은 날을 함께 옮긴다. 그때까지 넣은 날은 이 탭에만 있다(화면이 넣는 자리마다 그렇게 말한다).
- 알림(푸시, 메일, 텔레그램).
- 글을 쓰고 고치는 운영 화면(6단계), 확인한 날이 차기 전에 깨우는 예약(후속).
- 글이 없는 채널(한국 생활, 취업, 선배 이야기, 부모님 방)의 글. 목록에 「글을 모으는 중」 한 줄로 모은다.
- 「이 글에 대해 묻기」(물어보기는 3단계), 대학별 방(협약 뒤), 몽골어(6단계).

## 사용자 흐름

1. 오늘 화면의 「새 소식」이나 아래 탭 「채널」로 들어온다.
2. 채널 화면 맨 위에 지금 가장 가까운 날이 있는 글이 크다. 날이 있는 글이 없으면 새로 올린 글이다.
3. 글을 열면 요점 셋과 출처를 읽는다. 「내게 해당되나요?」는 기준과 내 값을 나란히 쓴다. 조건을 안 넣었으면 무엇을 넣으면 보이는지 쓴다.
4. 날이 있는 글은 날마다 「내 길에 넣기」 단추(`aria-pressed`, 이름은 그대로)와 「달력에 넣기」가 있다. 넣으면 「이 탭의 다가오는 날에 넣었어요」라고 알린다. 지난 날은 넣을 수 없다.
5. 오늘 화면의 「다가오는 날」은 넣은 날을 가까운 순으로 보인다. 머리에 「이 탭에만 있어요」를 한 줄 둔다. 줄마다 날짜(접수 기간이면 「12월 1일~11일」), 이름, 어느 글에서 넣었는지, 「시작 D-n · 마감 D-n · 오늘」(영어는 「n days left」). 누르면 그 글로 간다. 지난 날은 끝에 「지난 날」로 접는다.

### 글 한 편의 꼴

```js
{
  id: 'topik-…',                 // 소문자 · 숫자 · 붙임표, 글 전체에서 하나
  channel: 'topik',
  status: 'official',             // official(공식 일정 · 안내) | announced(계획 발표, 시행일 미정)
  title: L('…', '…'),
  points: [L(…), L(…), L(…)],     // 셋, 두 언어 모두 300자 안
  note: L(…),                     // 없을 수 있다. 바뀐 일정은 여기에 「○월 ○일에서 ○월 ○일로 바뀜(확인 ○일)」
  source: { title: L(…), url: 'https://…' },
  checkedAt: '2026-11-21', postedAt: '2026-11-21',
  dates: [{ id, kind, start, end?, label: L(…), url?: 'https://…', cancelled?: true }],
  forYou: null | 'topikExam' | 'finance' | 'gksGrade' | 'program',
  programId?: '…',                // forYou가 program일 때
  criteria?: { … },               // gksGrade의 기준(출처는 이 글의 source)
  action: null | { label: L(…), url: 'https://…' }   // 공식 접수처. 요강에서 직접 읽은 접수처만
}
```

- `kind`: `apply`(접수 기간, start와 end), `exam`(시험 · 면접 같은 하루), `result`(발표), `deadline`(마감 하루). 하루짜리는 `start`만 쓴다.
- 날짜는 한국 날짜(UTC+9)로 센다. 몽골 현지 날짜로 정해진 일정은 그 날 이름 끝에 「마감 시각은 원문 확인」을 붙인다.
- 취소된 날은 지우지 않고 `cancelled: true`로 남긴다(넣어 둔 학생이 취소를 본다).
- 확인한 지 90일이 지난 글은 머리에 「확인한 지 90일이 지났어요. 날짜는 공식 안내에서 다시 확인하세요」를 띄운다. 90일 · 지난 날 같은 날짜에 따라 바뀌는 조건은 검사에 넣지 않는다(검사가 날이 지나 저절로 깨지지 않게).
- 「대학 소식」 글: 요점은 접수 차수, 필요한 한국어, 「공개 요강에서 옮겼고 협약 대학이 아님」이다. 과정 자료에 접수처 주소가 없으므로 `action`은 없다(원광대 학부는 방문 · 우편 접수다). 대신 「과정 자세히 보기」로 1단계 대학 자세히 화면에 잇는다. 예시 과정은 만들지 않는다.

### 넣은 날(탭 저장)

- `dates: [{ id, start, end }]` — 넣을 때 본 그 날의 시작 · 끝(하루짜리는 end가 start와 같다). 화면은 늘 지금 자료의 날짜를 쓰고, 넣을 때 본 날과 다르면 「날짜가 바뀌었어요(전에 본 날 ○월 ○일)」와 「확인했어요」 단추를 붙인다. 「확인했어요」는 저장한 시작 · 끝을 지금 날로 바꾼다.
- 자료에서 사라진 날(id를 못 찾음)은 저장값에 남겨 두고 「다가오는 날」 끝에 「글에서 빠지거나 바뀐 날 n개」와 「목록에서 지우기」를 한 줄 둔다. 잠시 내린 글이 돌아오면 다시 보인다.
- 한도 서른 개. 넣을 때 서른 개면 지난 날과 사라진 날부터 정리하고, 그래도 차면 넣지 않고 「다가오는 날이 서른 개라 더 넣을 수 없어요. 지난 날을 지운 뒤 넣어 주세요」라고 알린다.
- `channelsOff`: 오늘 화면의 새 소식에 보이지 않을 채널. 단추 이름은 「오늘 화면에 보이기」(`aria-pressed`). 알림을 약속하지 않는다.
- 「조건 모두 지우기」는 조건만 지운다(비교 · 넣은 날 · 채널 설정은 남김). 「이 탭의 PATH 데이터 지우기」와 주인 바뀜은 모두 지운다. 날만 넣은 손님이 로그인해도 넣은 날을 이어받는다(1단계 `hasData`가 날도 센다. 오늘 입구가 쓰는 `isEmptyProfile`은 조건만 본다).

### 「내게 해당되나요?」 규칙

순수 함수 `forYou(post, view)`가 기준과 내 값을 나란히 쓴다. 「맞아요 · 모자라요」 같은 판정 말 대신 기준, 내 값, 차이를 쓴다. 카드 끝에 1단계와 같은 「이 결과는 입학이나 비자를 약속하지 않아요」를 둔다.

| 규칙 | 읽는 것 | 쓰는 것 |
|---|---|---|
| `topikExam` | 그 글의 `result` 날(없으면 검사가 막음), 실제 과정의 접수 끝 날 | 아직 끝나지 않은 접수 하나에 한 줄: 「전주대학교 학부 3차(2027년 1월 13일 마감): PBT 제108회, IBT 제16회, PBT 제109회」(마감 전에 나오는 성적). 끝에 「성적표를 언제까지 내야 하는지는 과정마다 달라요.」 처음 설계는 성적마다 접수를 늘어놓았으나 같은 이름이 세 번 되풀이되어 화면 확인 뒤 접수마다 한 줄로 바꿨다 |
| `finance` | 준비한 돈, `RULES`의 D-2 · D-4 지방 · 수도권 금액(`firm`인 것만), 잔고 증명 방법 | 「어학연수(D-4) 지방 800만 원 · 수도권 1,000만 원, 유학(D-2) 지방 1,600만 원 · 수도권 2,000만 원. 내 값 1,200만 원.」 금액은 본문에 다시 적지 않고 `RULES`에서만 읽는다. `firm`이 아니면 금액을 비교하지 않는다. 계획 발표(TOPIK 4급 면제)는 「계획 발표」로 따로 쓰고 대조에 쓰지 않는다 |
| `gksGrade` | 성적 평균, 글의 `criteria`(기준 평균과 다른 길) | 「기준: 평균 80% 이상(또는 …). 내 값: 82%.」 |
| `program` | 그 과정과 내 조건의 대조(1단계 `matchProgram`) | 「내 조건 4개 중 3개 맞음」과 과정 자세히 링크(1단계와 같은 말) |

## 화면

- 결은 1단계와 같이 `.sx` 아래 시안 2판이다. 인라인 스타일을 쓰지 않는다. 고리 · 구멍 · 빽빽한 점 무늬와 큰 움직임을 쓰지 않는다.
- 채널: 머리, 맨 위 큰 글(채널 색 판과 채널 이름 표지 — 1단계 실제 과정 표지와 같은 결), 채널 목록(줄 하나가 채널 글 목록을 여는 단추이고, 「오늘 화면에 보이기」는 그 줄 밖의 따로 단추다), 「새 글」 수(올린 지 14일 안인 글), 「글을 모으는 중: 한국 생활, 취업, 선배 이야기, 부모님 방」 한 줄.
- 채널 글: 뒤로, 채널 이름과 올린 날, 상태(계획 발표면 표시), 제목, 요점 셋, 바뀐 일정 메모, 출처 줄, 「내게 해당되나요?」 카드, 날 목록(날마다 이름, 날짜, 남은 날, 「내 길에 넣기」(화면에 안 보이는 글로 날 이름을 붙임), 「달력에 넣기」), 공식 접수처 단추(새 탭, 「접수는 본인이 직접 해요」).
- 날짜 칸 「12월 / 3」과 「D-12」는 화면 읽기에서 「12월 3일, 12일 남음」으로 읽힌다.
- 오늘: 「다가오는 날」(머리 한 줄 「이 탭에만 있어요. 탭을 닫으면 사라지니 달력에도 넣어 두세요」), 「새 소식」 두 편(유학 카드).

## 시험 계획

- 자료: 글마다 출처 · 확인한 날 · 상태 · 요점 셋(두 언어 300자 안). 날의 꼴과 순서(start ≤ end), 날 id가 손 글과 자동 글 전체에서 하나뿐. 주소가 모두 https. `forYou` 이름이 목록 안이고 규칙에 필요한 자료(`result` 날, `programId`, `criteria`)가 있음. 대학 소식 글 수와 날이 실제 과정의 접수 차수와 같음. 차수를 끼우거나 빼도 다른 날의 id가 그대로. 검사가 `now`를 400일 뒤로 두어도 통과.
- 공개 묶음: 틀린 글이면 묶음 실패.
- 넣은 날: 넣고 빼기, 지난 날 넣기 막음, 서른 개 한도와 정리, 모르는 id 남김과 지우기, 옛 저장값(칸 없음), 「조건 모두 지우기」가 날을 남김, 「이 탭의 PATH 데이터 지우기」 · 주인 바뀜이 지움, 날만 넣은 손님의 로그인 이어받기, 바뀐 날 표시와 「확인했어요」.
- 다가오는 날: 카드 넷(유학 준비, 유학 중, 취업 준비, 카드 없음)마다 오늘 화면에 보임. 가까운 순, 시작 전 접수의 「시작 D-n」, 한국 날짜 경계(몽골 밤 11시 반), 지난 날 접기, 취소된 날.
- 「내게 해당되나요?」: 규칙마다 조건을 넣기 전과 뒤, 한국어 · 영어. `finance`의 수도권 금액, 기준과 같은 금액, `stale` 규칙, `inCurrentGuide=false` 규칙.
- 접근성: 받기 · 넣기 단추를 누른 뒤 초점이 남고 알림이 읽힘, 같은 이름 단추가 없음, 채널 글을 연 채 언어 바꾸기.
- 브라우저: 폭 다섯(320 · 360 · 390 · 768 · 1440) × 한국어 · 영어로 채널 · 채널 글 · 오늘의 넘침, 깨진 그림, 실패 요청, 새 콘솔 오류 0. 탭 글자마다 `scrollWidth ≤ clientWidth`, 768 머리 막대.

## 지킬 선

- 글의 사실과 날은 공식 쪽에서 직접 읽은 것만 쓴다. 확인하지 못한 것은 쓰지 않는다.
- 접수는 공식 접수처로 연결한다. 앱이 대신 접수하지 않는다.
- 입학, 비자, 장학금 선발을 약속하지 않는다. 「내게 해당되나요?」는 대조이지 판정이 아니다.
- 계획 발표는 시행 중인 제도처럼 쓰지 않는다(`status: 'announced'`와 「시행일 미정」).
- 사기 주의 글은 공식 기관이 공고한 것만 쓴다. 공고에 이름이 없는 업체를 지목하지 않는다.
- 협약 전에는 「협력 대학」이라고 쓰지 않는다.

## 설계 검토와 반영(2026-11-21, Opus 5.5가 Fable 5.2 대신)

P0 없음, P1 넷, P2 열여섯, P3 여섯. 위 본문에 반영했다.

- P1: 다가오는 날을 카드와 상관없이 오늘 화면에 둠. 대학 소식 날 id를 차수 순번이 아닌 시작 날로. 채널 자료 검사를 공개 묶음 관문에. 돈 대조에 지방 · 수도권 금액과 `firm` 규칙.
- P2: 넣는 자리마다 「이 탭에만」, 사라진 날 남김과 알림, 시작 · 끝 모두 저장과 「확인했어요」, 취소 표시, 시작 전 접수 표기, 「다시 확인하는 중」 약속 문장 고침(1단계 포함), 글 상태(계획 발표), 판정 말 대신 기준과 내 값, GKS 기준을 글 자료에, 대학 소식의 접수처 단추 뺌, 「받기」를 「오늘 화면에 보이기」로, 채널 탭을 손 글이 있을 때만, 접근성, 320 폭 시험(영어 탭 이름 「Channels」가 320에서 칸을 꽉 채워 「News」로 함), 1단계 코드와 부딪히는 곳, 사기 주의 지킬 선.
- 검토 의견 「탭 저장이 충분한가」: 계정 저장은 3단계의 2판 올리기를 서버까지 당겨야 하고, 기기 저장은 손님 자료를 기기에 남기지 않는 원칙과 맞지 않는다. 그래서 탭 저장을 두고 넣는 자리마다 알리며, 달력에 넣기(.ics)로 학생 휴대폰에 남길 길을 준다. 이 한계를 유호님께 보고한다.
- 뒤로 미룬 것: 확인한 날이 차기 전에 깨우는 예약(서울 하루 앱의 `tools/path자료만료.mjs`처럼)은 후속이다.
