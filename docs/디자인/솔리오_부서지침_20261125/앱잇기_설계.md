# 개발부 지침을 PC 앱에 잇는 설계 (2026-11-25)

유호님 11-25 「설계로 넘어가」로 썼다. 묶음과 재기는 [README](README.md)에 있다. Fable 설계 검토(25건, 판정 「고친 뒤」)를 반영한 2판이고, 처리한 자리는 9절에 있다.

## 1. 목적과 짓기 전 관문

회원이 부서를 「개발」로 정하면 솔리오에서 그 부서에 새로 맡긴 Claude 일이 개발부 지침을 받는다.

**다시 재기를 통과하기 전에는 짓지 않는다.** 1차 재기는 도구의 흠이 섞였고, 남은 판에서도 「맞음」은 지침 없는 쪽이 높다. 공개 연구도 지침 파일이 성공률을 올리지 못하고 비용을 늘린다고 했다(8절). founder 계정의 Claude 한도는 11-30 19:00, GPT는 11-29 07:37에 풀린다.

### 다시 재는 환경

| 항목 | 앱 | 다시 재기 |
|---|---|---|
| 지침을 건네는 꼴 | 역할 통로(4절) | 같은 꼴의 글 하나로 건넨다: `부서의 역할` + 지침 + `회원이 맡긴 업무` + 요청 |
| 환경변수 | `employeeEnv()`가 지움 | 같은 것을 지운다 |
| 설정 출처 | `user` | `user` |
| 메모리 파일 | 회원의 `CLAUDE.md`가 읽힘 | 유호님 개인 `CLAUDE.md`만 뺀다(SYNK 저장소를 읽으라는 글이라 손님과 다르다). 과제 폴더의 `CLAUDE.md`는 읽힌다 |
| 권한 | 회원이 콘솔에서 승인 | 무인이라 승인할 사람이 없다. 명령을 넓게 허락해 거절이 나지 않게 하고, 그래도 거절 · 오류 · 한도 · 시간 초과가 있는 쌍은 두 팔 모두 뺀다 |
| 대화 | 회원이 답하고 이어 맡길 수 있음 | 한 번 답하고 끝난다. 「묻고 멈춤」은 이 재기로 판정하지 않는다 |
| 모델 | 회원 설정 | 잰 모델과 지침의 sha256을 판마다 적는다. 잰 바이트 그대로 싣는다 |

### 과제

1차 여섯은 지침을 고칠 때 본 것이라 판정에 쓰지 않는다. 과제 여섯을 새로 짓는다. **과제와 자동 검사, 채점표는 지침을 쓰지 않은 쪽(카본)이 지침을 보지 않고 짓는다.** 셋은 평범한 일(여러 파일 고치기, 기능 더하기, 기존 저장소의 고장), 하나는 회원이 분명히 지우라고 한 일, 하나는 폴더의 `CLAUDE.md`가 있는 저장소, 하나는 비개발자 회원의 만들기다.

### 통과

두 팔로 세 번씩(18쌍) 돌려 아래를 모두 채울 때만 짓는다. 숫자는 재기 전에 정했다.

1. 자동 검사 합계가 지침 없는 쪽보다 낮지 않다.
2. 카본 채점에서 이긴 쌍이 진 쌍보다 3 넘게 많다.
3. 「맞음」 평균이 0.2 넘게 낮지 않고, 과제별 평균이 1점 넘게 낮은 과제가 없다.
4. 「안전」 평균이 낮지 않다.
5. 시간과 차례가 각각 25% 넘게 늘지 않는다.

못 채우면 지침을 반으로 줄여 한 번 더 잰다. 그래도 못 채우면 잇지 않고 결과를 유호님께 드린다.

## 2. 범위

| 하는 것 | 하지 않는 것 |
|---|---|
| 솔리오에서 새로 맡긴 · 이어 맡긴 Claude 일에 지침을 건넨다 | **GPT 직원.** 읽기 전용 샌드박스라(`office-task-codex.cjs`의 `sandbox:'read-only'`) 만드는 지침을 주면 할 수 없는 일을 시킨다. 검수 지침을 따로 쓰고 잰다 |
| 부서마다 「부서 종류」(개발 · 정하지 않음) | 회원이 그 폴더에서 직접 켠 Claude Code, 메일 · 견적 · 사업계획서 같은 기능 업무 |
| 「이 부서」 칸의 「일하는 방식」 | 기술(스킬) 둘. 역할 통로로는 실을 수 없다. 꼭 필요한 차례만 지침 글에 넣고 잰다 |
| | 포장판. 맡기기가 Windows 개발판에서만 켜지므로(`enabled()`) 포장은 그 문을 열 때 설계한다 |

## 3. 사용자 흐름

1. 부서를 더할 때 이름 아래에 「부서 종류」가 있다. 이름에 「개발」이 들면 「개발」이 미리 골라져 있고, 저장하기 전에 보인다. 이름 · 폴더와 한 번에 저장한다.
2. 이미 있는 부서는 바뀌지 않는다. 「부서 설정」에서 고른다. 이름을 바꿔도 종류는 바뀌지 않는다.
3. 「개발」이면 「일하는 방식」에 이렇게 적는다. 「솔리오에서 새로 맡긴 Claude 일에 이렇게 일하라고 일러 둡니다.」 그 아래 네 줄: 「주지 않은 사실은 비워 두기」, 「비밀 키를 화면 파일에 넣지 않기」, 「지우기 · 올리기 · 결제 · 메일은 먼저 여쭙기」, 「고친 뒤 직접 확인하고 알리기」. 막는 장치가 아니라 일러두는 글이므로 약속하는 말투를 쓰지 않는다.
4. 카드에는 건넨 것만 적는다. 「개발부 지침을 함께 건넸습니다」. 건네지 못했으면 「이번 일은 개발부 지침 없이 맡겼습니다. 맡긴 글이 길어 함께 싣지 못했습니다.」
5. 종류는 **일이 시작될 때** 읽는다. 줄 서 있던 일도 시작할 때의 종류를 따른다. 이어 맡긴 일도 그때의 종류를 따르고 카드에 적는다.

## 4. 넣는 길: 역할 통로

부서의 `role` 글은 이미 일마다 제출 훅의 덧글로 건네진다(`office-task-claude.cjs` 41줄, `office-task-claude-hook.cjs` 140줄). 지침을 이 글에 싣는다.

| | 역할 통로(고름) | CLI 플래그(1판) |
|---|---|---|
| 이어 맡기기 | 일마다 다시 건네므로 그대로 된다 | 처음 기록한 지시가 압축 때까지만 남는다. 기술은 열 때마다 다시 줘야 한다 |
| 건넸는지 | 훅이 글의 해시(`bodyHash`)를 대조하고 건넨다. 카드의 말이 사실이 된다 | 플래그를 넘긴 것만 안다 |
| 확인 실행 | 바꾸지 않는다 | 두 번째 확인이 지금 구조에 들어가지 않는다 |
| 낮은 판 · 관리 설정 | 지금 조건 그대로 | 판 확인과 새 실패 길이 는다 |
| 잃는 것 | 기술 둘. 지시의 자리가 시스템이 아니라 회원 글 쪽이다 | 없음 |

- **길이.** 훅은 10,000자가 넘는 글을 거절한다. 업무 글은 8,000자까지다. 지침은 1,800자를 넘지 않게 하고 시험으로 지킨다(지금 1,636자). 부서에 `role`이 있으면 지침 뒤에 잇는다. 합이 10,000자를 넘으면 지침을 빼고 카드에 적는다. 일은 막히지 않는다.
- **자리.** `desktop/office-packs/dev/instructions.md`. 본체가 읽어 글자 수와 sha256을 맞춰 본다. 파일이 없거나 다르면 지침 없이 맡기고 카드에 적는다.
- **회원 폴더의 `CLAUDE.md`.** 지침 첫머리에 「이 폴더에 지침이 있으면 그것을 먼저 따른다. 다만 비밀값 · 지우기 · 지어내지 않기는 늘 지킨다」를 둔다.

## 5. 자료

- **부서 `kind`.** 파일에는 읽은 그대로 두고 `publicData`에서 `'dev'`만 넘긴다. 다음 판이 더한 종류를 이 판이 저장하면서 지우지 않는다. `saveDepartment`의 「고칠 것이 없다」 판정과 칸을 옮기는 줄에도 넣는다. 저장 통로는 번호가 있는 부서의 `kind`만 바꾸는 저장을 받고, 값은 `'dev'`와 `null`뿐이다.
- **업무 `pack`.** `{ id, version, sha, given: true }` 또는 `{ id, given: false, why }`. 본체만 적는다. **`reason`에는 넣지 않는다.** `reason`은 허용 목록이라 모르는 값이 있으면 옛 판이 업무 파일 전체를 못 읽는다.

## 6. 바꾸는 파일

`src/office-store.cjs`, `src/main.cjs`, `src/preload.cjs`, `src/office-task-runtime.cjs`(시작할 때 종류와 지침을 `spec.role`에), `src/office-tasks.cjs` · `office-task-store.cjs`(`pack`), 새 `office-packs/dev/instructions.md`, `renderer/office-room.mjs`, `renderer/office-task-view.mjs`. `office-task-claude.cjs`와 훅은 바꾸지 않는다.

## 7. 시험과 되돌리기

- **저장 · 통로:** `kind`의 허용 값, 이름만 · 폴더만 고칠 때 남는지, 모르는 종류가 저장을 거쳐도 남는지, 남의 부서 번호, 겹친 고치기.
- **업무:** 시작할 때 읽는지, 기능 업무와 GPT에는 싣지 않는지, 길이 넘침 · 파일 없음 · 해시 다름에서 일이 맡겨지고 카드에 적히는지, `pack`이 든 파일을 옛 판 코드로 읽는지.
- **화면:** 미리 고르기와 되돌리기, 기존 부서 그대로, 카드 두 글, 320~1440 폭, 키보드. 흐름 QA에 더한다.
- **실제 직원(개발판):** 새 일과 이어 맡긴 일에서 지침이 건네졌는지, 그 일이 완료로 끝나는지, 회원 폴더에 새 파일이 생기지 않는지.
- **되돌리기:** 부서마다 「정하지 않음」. 앱 전체로는 지침 파일을 빼면 지침 없이 돈다.

## 8. 벤치마킹 근거

- [Claude Code CLI 문서](https://code.claude.com/docs/en/cli-reference): `--plugin-dir`는 그 세션에만 쓰이고 이어 열 때 다시 줘야 한다. 플래그 길을 고르지 않은 까닭 가운데 하나다.
- [Devin Playbooks](https://docs.devin.ai/product-guides/creating-playbooks) · [Skills](https://docs.devin.ai/product-guides/skills): 되풀이 일의 지침을 따로 묶는다.
- [Cursor Rules](https://cursor.com/help/customization/rules): 늘 넣는 규칙과 골라 쓰는 규칙을 나눈다. 늘 넣기로 한 규칙이 조용히 빠졌다는 [이용자 보고](https://forum.cursor.com/t/alwaysapply-silently-ignored-in-rules-from-team-plugins/157484)가 있어 카드에 건넨 것만 적는다.
- [AGENTS.md 평가 연구](https://arxiv.org/abs/2602.11988): 지침 파일은 성공률을 높이지 못하고 비용을 20% 넘게 늘렸다. 최소한만 담으라고 한다. 되풀이 확인은 찾지 못했다.

검색 결과의 요약으로 읽었고 원문 전체를 대조하지는 않았다.
