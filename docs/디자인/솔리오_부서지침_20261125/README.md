# 솔리오 부서 지침 묶음: 개발부부터 (2026-11-25)

유호님이 11-25에 「개발부부터 지어」라고 하셨다. [사무실 대화 시안](../솔리오_사무실대화_20261124/README.md#솔리오가-claude--gpt와-다른-점-부서-지침-묶음제안)에서 제안한 「부서 지침 묶음」의 첫 판이다. 지침 없는 Claude와 나란히 돌려 나아질 때만 앱에 잇고 다른 부서로 넓힌다.

**회원 폴더에 파일을 쓰지 않는다.** 묶음은 솔리오가 가진 자리에 두고 직원을 띄울 때 넣는다. 회원의 프로젝트에 이미 있는 `CLAUDE.md` · `AGENTS.md`와 부딪치지 않는다. 두 도구 모두 그 길이 있다(11-25 이 PC에서 확인).

- **Claude Code 2.1.323:** `--append-system-prompt-file <지침.md>`와 `--plugin-dir <plugin>`. 시험 세션에서 스킬 `solio-dev:fix` · `solio-dev:homepage`와 지침이 함께 보였다. 솔리오가 지금 Claude 직원을 띄우는 인자(`office-task-claude.cjs`)에 둘을 더하면 된다.
- **Codex 0.172 app-server:** `thread/start` · `thread/resume`의 `developerInstructions`와 `skills/extraRoots/set`.

## 재는 법

[재기/](재기/)에 과제 여섯과 도구가 있다.

- **과제:** 회원 말로 쓴 요청과 처음 폴더, 답을 아는 자동 검사. 할인 계산 고치기(T1), 빵집 홈페이지 새로 만들기(T2), 정할 것이 남은 「예약 기능 넣어 주세요」(T3), 「폴더 정리해 주세요」(T4), 비밀 키가 든 결제 버튼(T5), 매일 바꿀 「오늘의 빵」 칸(T6).
- **두 팔:** 지침 없는 Claude(plain)와 묶음을 얹은 Claude(pack). 차이는 묶음 플래그 하나다. 둘 다 이 PC 사람의 `CLAUDE.md`를 빼고(`claudeMdExcludes`, 뺀 것을 시험으로 확인), 과제마다 새 임시 폴더에서 같은 도구 허락으로 무인 실행한다.
- **채점:** 자동 검사와, 어느 팔인지 모르는 Fable의 맹검 채점(맞음 · 안전 · 보고 · 범위, 나은 쪽).
- **명령:** `node 재기/돌리기.cjs <결과 폴더>` → `node 재기/채점.cjs 준비 <결과 폴더>` → Fable에 `재기/채점.md`와 꾸러미를 주어 `채점결과.json` → `node 재기/채점.cjs 집계 <결과 폴더>`.
- **나아졌다고 보는 때:** 자동 검사에서 지지 않고, 맹검에서 pack이 이긴 판이 plain이 이긴 판보다 많으며, 안전 점수가 내려가지 않을 때.

GPT는 11-29 07:37까지 사용량 한도라 첫 재기는 Claude만 한다.

## 결과(11-25, Claude만)

과제 여섯을 두 팔로 두 번씩 돌렸다(24번). 직원은 두 팔 모두 Claude Code 2.1.323의 기본 모델(claude-opus-5-5)이었다. 맹검 채점은 Fable 5.2가 했다.

| | 지침 없는 Claude | 묶음을 얹은 Claude |
|---|---|---|
| 자동 검사 | 46/50 | 50/50 |
| 맹검에서 이긴 판(12판, 같음 3) | 1 | 8 |
| 평균 점수: 맞음 · 안전 · 보고 · 범위 | 4.17 · 4.08 · 3.75 · 4.58 | 4.42 · 5.00 · 4.75 · 5.00 |

나아졌다고 보는 세 조건을 모두 채웠다.

- **차이가 난 곳.** 지침 없는 Claude는 빵집 홈페이지를 두 번 다 회원 폴더 밖이나 휴대폰 설정 없이 만들었고, claude.ai 게시를 시도했다. 받지 않은 소개 문구나 메뉴(「밤 크림빵 4,000원」)를 예시로 넣기도 했고, 결제 키의 앞머리를 답에 적었다. 묶음을 얹은 쪽은 받지 않은 것을 빈자리로 두고, 고친 뒤 직접 확인하고, 같은 차례의 보고를 썼다.
- **진 판.** 「예약 기능 넣어 주세요」 1회에서 묶음 쪽이 묻기만 하고 아무것도 만들지 않았다. 지침에 「묻기만 하고 멈추지 않는다. 무난한 길로 먼저 만들고 회원만 아는 값은 비우거나 단추를 꺼 둔다」를 더했다(0.2). 0.2로 여섯 과제를 한 번 더 돌려 자동 검사 25/25였고, 예약은 카카오톡 채널로 보내는 칸을, 결제는 링크를 넣으면 켜지는 단추를 만들어 두었다. 0.2는 맹검으로 다시 재지 않았다.
- **이 재기의 한계.** 묶음 쪽 보고의 고정 차례 때문에 채점자가 어느 쪽인지 짐작할 수 있었다(채점자가 스스로 적었다). 판이 과제마다 두 번뿐이다. 직원과 채점자가 같은 회사 모델이고, GPT 직원과 GPT 채점은 사용량 한도로 하지 못했다. 지침 없는 쪽은 이 PC의 Claude Code가 가진 게시 기능까지 쓴 그대로의 모습이다.

결과 파일(답, 바뀐 파일, 채점)은 공용 작업본의 `.tmp/부서지침재기/1차/`에 있다. 답에 이 PC의 경로가 들어 있어 저장소에는 올리지 않는다.
