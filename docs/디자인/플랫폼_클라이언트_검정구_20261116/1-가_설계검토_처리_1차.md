[1-가 구현 설계](1-가_구현설계.md)의 origin `767dcbf7c5` 판을 Fable 5.2 검수자가 검토했다(맡긴 세션이 띄움). 판정은 「고쳐서 다시 검토」이고, P0 없음, P1 다섯, P2 열둘, P3 열둘이었다. 검토 전문은 공용 작업본의 `.tmp/pc-client-orb-step1a-20261116/fable-설계검토-1.md`(git 밖)에 있다. 아래는 지적마다 설계를 어떻게 고쳤는지다. 「자리」는 고친 판 설계의 절이다.

## P1

P1 다섯은 이 세션이 코드에서 다시 확인했다. 모두 검토의 말이 맞았다.

| 번호 | 지적 | 확인한 코드 | 처리 | 자리 |
|---|---|---|---|---|
| P1-1 | 앱에서 설치기로 넘어갈 때 아래에 남은 앱 창이 없다. `completeInstall()`은 창이 다 닫힌 뒤의 `will-quit` 안에서 돈다 | `main.cjs` 171~182행, `platform-update.cjs` 191~209행, `LIFECYCLE.md`의 0.4.10 기록 | 앱 밖의 프로세스로 「가림막」을 띄운다. 받아 둔 설치 파일을 모양만 그리는 방식(`--curtain`)으로 켜고, 앱 창 바로 아래에 놓는다. 앱 창이 닫히면 가림막이 드러난다. 설치기를 띄우는 차례(초안 보호가 끝난 뒤 `will-quit`에서)는 그대로 둔다. 끝내기가 취소되면 가림막이 끝난다. 켜 둔 동안의 업데이트는 끝내기 전에 앱 창 안에서 받기 끝 장면으로 들어간다 | 2절 「앱에서 설치기로: 가림막」 |
| P1-2 | `--synk-arrival` 인자가 새 앱 해시 고르기(`arguments.Length==0`)와 「startup bypass」 단언에 부딪치고, 피드 확인 건너뛰기는 관문 우회다 | `AutoUpdateEngine.cs` 232~235행, `Tests.cs` 476행 | 인자를 쓰지 않는다. 도착은 설치기가 쓰는 「도착 쪽지」 파일로 알린다. 새 앱을 켤 때의 인자는 지금처럼 비고, 해시 고르기와 476행은 그대로다. 쪽지는 구의 시작 자세만 바꾸고 피드 확인은 언제나 돈다 | 6절 |
| P1-3 | 트레이에서 다시 열 때와 숨은 채 시작할 때의 관문 길이 없다. 첫 장 알림의 시간 제한도 없다 | `main.cjs` 217~232행과 417행, `desktop-preferences.cjs` | 관문의 세 길(처음 켤 때, 다시 열 때, 숨은 채 시작)마다 보이는 창을 표로 정했다. 다시 열 때는 숨어 있던 앱 창을 바로 보이고 확인은 뒤에서 한다. 숨은 채 시작은 시작 창을 띄우지 않는다. 첫 장 알림이 3초 안에 오지 않으면 그냥 보인다. 숨은 채 시작이면 알림이 와도 보이지 않는다 | 2절 「관문이 도는 세 길」, 「시작 창에서 앱 창으로」 |
| P1-4 | `--window=`를 넘기는 판과 받는 판의 차례가 없다. 설치기는 인자가 꼭 셋이어야 하고, 손 업데이트 길은 하나여야 한다 | `Program.cs` 126~151행, `platform-update-handoff.cjs` 6행 | 자동 업데이트와 손 업데이트의 인자는 바꾸지 않는다. 창 자리와 장면 값은 「넘김 쪽지」로 넘긴다. 새 인자는 가림막 방식 하나이고, 가림막을 켜는 앱 쪽과 받는 설치기 쪽을 같은 판에 싣는다. 그 뒤의 설치기는 계속 받아야 한다. 가림막을 띄우지 못하면 앱은 가림막 없이 지금처럼 넘긴다 | 2절 「판 사이의 차례」, 7절 ③ |
| P1-5 | 「지난번 설치를 되돌렸는지 아직 확인하지 못했어요」로 막힌 상태의 안내가 사라진다 | `AutoUpdateEngine.cs` 204~206행, `InstallTransaction.cs` 13~18행 | READY 전 실패를 둘로 갈랐다. 막힌 상태는 설치기 창에 기록과 함께 남기고 맨 위에 둔다. 조용한 업데이트에서도 띄운다. 그 밖의 실패만 설치기 창을 닫고 앱에 맡긴다 | 2절 가림막 7번, 5절 설치기 표 |

## P2

| 번호 | 지적 | 처리 | 자리 |
|---|---|---|---|
| P2-1 | 켜 둔 동안의 업데이트에 장면이 없고, 앱 크기의 맨 위 창이 다른 일을 덮는다 | 앱 창이 앞에 보이면 끝내기 전에 얼굴이 받기 끝 장면으로 들어간다(2초 상한). 앞에 보이지 않으면(숨음, 최소화, 다른 창 뒤, 숨은 채 시작) 조용한 업데이트로 창을 띄우지 않는다. 맨 위 창은 막힌 상태의 설치기 창 하나뿐이다. 트레이가 끝낼 때 숨은 창을 보이는 일은, 초안이 없을 때만 조용히 하는 것으로 풀었다 | 2절 「켜 둔 동안의 업데이트」, 「조용한 업데이트」, 10절 1 |
| P2-2 | Mac의 「받았습니다」 장면과 사람이 손써야 풀리는 실패가 저절로 사라진다 | Mac의 손으로 옮기기는 저절로 넘기지 않고 기다린다. 「쓰던 판 열기」로 넘어가거나, 판이 맞지 않아 쓰던 판을 열 때는 앱 안에 한 줄이 남는다. 그 줄의 자리는 새 얼굴 시안에서 정한다 | 5절 공통 규칙, 시작 창 표 |
| P2-3 | 단계 표에 자동 업데이트의 「설치 파일 준비」와 다시 설치의 백업이 빠졌다. 21초에는 앞 판 확인과 깔린 파일 해시가 없다 | 표에 준비(70~78%)를 넣고, 다시 설치의 몫을 따로 적었다. 21초가 무엇을 빼고 잰 값인지 적었다 | 3절 |
| P2-4 | 「지금」 서술 넷이 코드와 다르다 | 확인 중 글은 이미 보이지 않고 바탕은 이미 검정이라고 고쳤다. 7절 ①은 창 옵션 한 줄과 구 바꾸기로 줄이고, 화면 낭독기 글은 남긴다고 적었다. 「앱이 안 꺼짐」은 실패 창이 남는 줄로 따로 뺐다. `UPDATE_HANDOFF_INVALID`가 지금 「온전하지 않아요」로 나오는 것을 적고 코드마다 문장을 나눴다. 「켤 때 이미 받아 둔 경우가 많다」는 「끝내기가 취소됐거나 미뤄진 때뿐」으로 고쳤다 | 2절 「지금 흐름」, 3절, 5절, 7절 |
| P2-5 | GPU 속도는 상수로 구운 줄인 셰이더로 쟀다 | 그 한계를 1절에 적고 확인 안 함에 올렸다. 실제 설치기는 값을 모두 실행 중에 받는다. 도는 도중 가속이 꺼지면(`TierChanged`) CPU 판으로 바꾼다 | 1절, 확인 안 함 |
| P2-6 | READY를 첫 장 뒤로 미루는 데 상한이 없다 | READY는 지금 그대로 둔다. 빈 틈은 가림막이 덮으므로 첫 장을 기다리지 않는다. 잠긴 화면과 끊긴 원격 세션은 확인 안 함에 올렸다 | 2절 가림막 9번, 확인 안 함 |
| P2-7 | 설치기 새 창의 창 종류와 닫는 자리가 없다 | 창 넷(시작 창, 앱 창, 가림막, 설치기 창)의 테두리, 닫기의 뜻, 단추를 표로 정했다. 설치기 창은 `AllowsTransparency`를 끄고, 최대화는 작업 영역 크기로 하고, 둥근 모서리를 청한다 | 2절 「창의 종류와 닫기」 |
| P2-8 | 실패 기록을 읽어 한 줄 더하는 조건이 없다 | 판 번호와 시각이 이번 되돌림과 맞을 때만 읽고, 단계 값으로 문장을 고른다. 기록의 글과 경로는 그대로 보이지 않는다 | 5절 공통 규칙 |
| P2-9 | 시작 창의 다리는 인자 없는 다섯 동작으로 고정돼 있다 | 시각과 움직임 종류는 본체가 정해 두 창에 준다. 더하는 동작(창 단추, 첫 장 알림)도 인자 없는 동작으로만 두고, 시험과 설치본 검사기의 목록을 함께 고친다 | 2절 「시작 창에서 앱 창으로」, 8절 |
| P2-10 | 조용히 넘길 확인 실패의 범위가 없다 | 확인 단계의 인터넷 실패(`UPDATE_NETWORK_FAILED`, `UPDATE_TIMEOUT`)만 조용히 넘긴다. 서명, 피드 형식, 피드 주소, 믿을 수 없는 주소는 실패 장면을 보인다. 어느 쪽이든 마지막 확인 실패를 설정의 업데이트 줄에 남긴다 | 5절 공통 규칙, 시작 창 표 |
| P2-11 | 도착 뒤의 시작 값과 실패 장면이 모습을 미리 굳힌다 | 아래 「모습을 미리 굳힌 곳」의 일곱을 모두 풀었다 | 아래 |
| P2-12 | 시험과 캡처 계획에 빈 곳이 있다 | 아래 「시험과 캡처」의 열을 모두 넣었다 | 8절, 9절 |
