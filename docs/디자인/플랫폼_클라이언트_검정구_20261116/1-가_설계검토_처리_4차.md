# 1-가 구현 설계 · 설계 검토 4차 처리 (2026-11-17)

[1-가 구현 설계](1-가_구현설계.md)의 origin `b5cc97f93` 판을 Fable 5.2 검수자가 네 번째로 검토했다(맡긴 세션이 띄움). 검토 범위는 좁혔다. 표시를 놓는 규칙, 3차의 P2 셋, 3차 고침으로 새로 들어온 규칙이다. 판정은 **「통과」**다. P0과 P1은 없다. 3차의 P1과 P2 셋은 모두 풀렸다. 그래서 설계 검토는 여기서 멈춘다.

검토는 새 P2 둘과 새 P3 열하나를 구현할 때 지킬 것으로 넘겼다. 다시 검토하지는 않는다. 다만 P2 둘은 「이 규칙 없이 지으면 코드 검수에서는 P1」이라고 적혀 있어, 구현을 시작하기 전에 설계 본문에 규칙으로 적었다(맡긴 세션의 요청). 검토 전문은 공용 작업본의 `.tmp/pc-client-orb-step1a-20261116/fable-설계검토-4.md`(git 밖)에 있다. 앞선 처리는 [1차](1-가_설계검토_처리_1차.md), [2차](1-가_설계검토_처리_2차.md), [3차](1-가_설계검토_처리_3차.md)에 있다.

맡긴 세션은 앞서 조용한 업데이트를 떼자고 했던 의견을 거두었다. 새 P2 둘이 모두 장치 1에서만 나왔고 무거운 지적이 아니기 때문이다. 지금 설계대로 간다.

## 구현할 때 주의할 자리

검토는 앱이 60초 안에 꺼지지 않은 끝이 엔진의 `try` 밖(`AutoUpdateEngine.cs` 243행)에서 던져져 엔진의 `catch`를 타지 않는다고 짚었다. 그래서 표시를 지우는 코드는 두 군데에 있어야 빠지는 끝이 없다. 엔진이 앱을 켜기 바로 앞과, `Program.cs`에서 엔진을 기다린 자리가 끝난 곳이다. 이것을 장치 1의 「지우는 자리는 두 군데다」로 적었다.

## 검토의 「돌려 보지 않은 것」

검토가 돌려 보지 않은 것 가운데 설계의 「확인 안 함」에 없던 넷을 더했다. 두 번째 실행이 0으로 끝나는지, 표시를 지운 뒤 설치기가 켠 앱이 단일 실행 잠금을 잡기까지 걸리는 시간, 박동이 파일 시각을 고치는 순간에 지우기가 실패하는지(그때 파일을 어떤 공유로 여는지), 요청 파일을 쓰는 순간에 설치기가 읽으면 쓰기가 실패하는지다. 「앱이 준비되기 전에 띄울 수 있는 알림 상자」는 상자를 뺐으므로 적지 않았다.

검토는 「되돌린 뒤 표시를 지운 직후 사람이 켠 앱이 먼저 뜨는 틈」을 그대로 두는 판단이 맞다고 봤다. 밟으면 자동 재시도가 한 번 더 돌 뿐이고 막히지 않는다. 검토가 든 두 길 가운데 「표시를 실행 파일 해시 뒤, 프로세스를 띄우기 바로 앞에서 지운다」는 값이 싸서 놓는 차례에 넣었다.
