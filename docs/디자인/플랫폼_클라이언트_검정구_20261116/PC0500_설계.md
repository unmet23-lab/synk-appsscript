# PC 0.5.0 설계 — 트레이 바로가기, 설정 방 Enter 실패, 옛 화면 거두기 (2026-11-20)

PC 0.5.0은 검정 구 2단계의 남은 일을 한 판에 싣는다. 0.4.99는 다른 세션이 트레이 대기 메모리 개선판으로 11-20에 먼저 냈다. 남은 일은 [트랙](../../_ops/트랙.md)의 「SYNK 플랫폼 PC 클라이언트 2단계 · 솔리오 안쪽」 줄 ①~④다. 이 글은 ②와 ④를 짓기 전의 설계이고, Fable 설계 검토를 받은 뒤 짓는다([검수 판정표](../../AI_운영원칙.md#review-rules) 「큰 기능」 행, 「땜질을 멈추는 때」).

| 남은 일 | 이 판에서 |
|---|---|
| ① 솔리오 「계정 건강」 화면 | master `105ff658b8`에 이미 있다. 화면 검수가 641~1000px의 펼친 줄 고침을 함께 본다. 방문자 분석과 구독 줄의 641~900px 칸 틈 2px는 옛 런처 CSS를 거둘 때 함께 없앤다(4절) |
| ② 숨은 시작에서 트레이에 앱 바로가기가 없다 | 1절. 설계를 바꾼다 |
| ③ 설정 방 칸에서 Enter 저장이 실패하면 초점이 저장 단추에 남는다 | 2절 |
| ④ 옛 런처 화면과 펠트 그림을 거둔다 | 4절 |

## 1. 트레이 바로가기

### 1.1 지금

- Windows 트레이 메뉴는 「SYNK Platform 열기」, 앱 바로가기, 「완전히 종료」다(`desktop/src/platform-tray.cjs`).
- 앱 바로가기는 화면이 정해서 보낸다. `convenience.mjs`의 `refresh()`가 즐겨찾기와 최근 앱으로 목록을 만들어 `synk:tray-shortcuts`로 보낸다. 구 얼굴이 보이는 동안에는 `launcher.mjs`의 `trayFilter`가 「따로 설치한 앱을 바로 실행」(`orbRunnable`, `getAppAction(id).action==='launch'`)만 남긴다.
- 그 규칙에 맞는 앱은 지금 Workspace(`messenger`) 하나다. WORLD와 PATH는 `UNLISTED_APP_IDS`라 목록에 들지 않고, PULSE는 `pulse-app`, 내 수업은 `teacher-preview`, 플레저와 운세는 `public-web`이다.
- 0.4.98부터 트레이로 숨은 채 켜지면 주 창을 만들지 않는다(트레이 대기 352 → 53 MiB, [LIFECYCLE](../../../desktop/LIFECYCLE.md#windows-tray-first-open)). 화면이 없으니 목록을 보낼 쪽이 없고, 처음 열기 전까지 메뉴에 바로가기가 없다(결정 11-19 알려진 한계).

### 1.2 되돌린 시도와 P1 넷

`d41609473c`는 본체가 화면이 마지막으로 보낸 목록을 계정마다 파일에 기억했다가 숨은 시작에서 다시 걸었다. 엔진 검수 `pc-0498-engine-20261119-h`의 GPT P1 넷으로 `3e4ff278a8`에서 되돌렸다.

| 번호 | 지적 | 뿌리 |
|---|---|---|
| GA1 | 복원한 항목을 누르면 Platform 창만 열리고 Workspace 실행 요청이 사라진다. 화면이 설치 목록을 다 읽기 전에 미룬 요청을 받아 버렸다 | 실행을 화면에 맡겼다 |
| GA2 | 계정 정보를 다시 읽는 동안 화면이 보낸 빈 목록이 기억을 덮는다 | 화면이 만든 파생값을 진실로 저장했다 |
| GA3 | 권한이 끝난 앱도 숨은 시작에서 나타난다 | 기억한 값을 지금 권한으로 다시 보지 않았다 |
| GA4 | 판을 올린 뒤 첫 숨은 시작에는 기억이 없어 여전히 빈다 | 기억은 한 번 열어야 생긴다 |

넷 모두 같은 뿌리다. 목록의 진실이 화면에 있는데 본체가 그 파생값을 들고 있으려 했다.

### 1.3 정한 것

**본체가 메뉴의 앱 줄을 지금 아는 사실로 직접 만든다.** 화면은 더 이상 목록을 보내지 않는다. 본체는 숨은 시작에서도 이 사실들을 이미 갖고 있다.

1. **줄이 서는 조건.** 아래가 모두 참일 때 「SYNK Workspace」 한 줄이 선다.
   - 트레이가 켜져 있다(Windows, Platform, 검사 실행 아님).
   - 본체가 화면에 주는 로그인 값(`accountStatus()`, 묶음 로그인 가림을 투영한 값)이 `signedIn`이고 `library.status==='ready'`이며 `library.appIds`에 `messenger`가 있다. 이 값은 서버 계정 응답을 본체가 투영한 것이고(`library-access.cjs`), 권한 기한도 이때 잰다.
   - 이 PC에 Workspace가 설치돼 있다. 메뉴용으로는 설치 표시 파일과 판 번호만 보는 가벼운 확인(`probe`)을 쓴다. 실행 파일의 해시는 누를 때 실행이 본다.
2. **바뀌는 때.** 설치 생명주기의 `onChange`는 설치 파일 준비와 실행 뒤에만 오고, Workspace가 설치되거나 지워진 것은 알리지 않는다(검토 D2). 그래서 다음 때마다 명시해 다시 만든다.
   - 로그인 상태가 바뀔 때(`publishAuthState`). 로그아웃이나 권한 없음이면 설치 확인을 기다리지 않고 그 자리에서 줄을 뺀다.
   - 주 창이 보이거나 초점을 받을 때, 트레이 실행 뒤.
   - 설치 생명주기의 `onChange`. 준비 진행처럼 몰려 오므로 0.3초 묶어 한 번만 본다.
   - 트레이가 켜져 있는 동안 10분마다. 확인은 설치 표시 파일과 판 번호만 읽어 가볍다. 숨어 있는 동안 따로 설치하거나 지운 것을 늦어도 10분 안에 따라간다.
   - 비동기 확인은 차례 번호로 묶어 마지막 것만 쓴다. 같은 입력이면 메뉴를 다시 걸지 않는다.
   - 창이 없으면 `onChange`에서 `getClients()`를 부르지 않는다. 모든 앱의 실행 파일을 해시하기 때문이다(검토 D4).
3. **누를 때.** 본체가 지금 값으로 위 조건을 다시 보고, 맞으면 `requireSuite(()=>installations.launch('messenger'))`로 바로 실행한다. Platform 창은 열지 않는다. 구 얼굴의 Workspace 공간도 같은 실행(`company-entry-destinations.cjs`의 `'/'`)을 쓴다.
   - 조건이 그새 바뀌었거나(로그아웃, 권한 끝, 다시 읽는 중) 실행이 실패하면 Platform 창을 연다(`requestPlatformWindow()`). 누름이 말없이 사라지지 않는다.
   - 끝내는 중(`quittingRequested`)이면 아무것도 하지 않는다. 실행이 도는 동안 다시 누르면 받지 않는다. 이 표시는 `try/finally`로 푼다.
   - 실행은 해시 때문에 1초 넘게 걸린다. 해시를 마치고 띄우기 바로 앞에서 계정 세대(`sessionGeneration`)와 조건을 다시 보고, 바뀌었으면 띄우지 않고 Platform 창을 연다(`installations.launch`에 띄우기 앞 확인을 넘긴다, 검토 D6).
6. **숨은 시작에서 로그인 복원이 일시 실패하면 본체가 다시 잇는다(검토 D1).** 창이 없는 동안 로그인 값이 `error`이고 다시 시도할 수 있으면, 화면의 「다시 불러오기」와 같은 `accountRequest('load')`를 5초에서 시작해 두 배씩, 5분까지 늘려 가며 부른다. Windows 로그인 직후 망이 붙기 전에 자동 시작하는 것이 이 기능의 주 경로라서다. 주 창이 생기면 멈춘다(화면이 맡는다). 로그인되거나 다시 시도할 수 없는 실패면 멈춘다.
4. **즐겨찾기와 최근 앱은 트레이에서 쓰지 않는다.** 구 얼굴에는 즐겨찾기를 정하는 자리가 없고(옛 라이브러리 화면은 4절에서 거둔다), 지금 규칙으로 남는 앱은 Workspace 하나다. 그래서 「즐겨찾기나 최근에 연 Workspace」 대신 「이 계정이 이 PC에서 열 수 있는 Workspace」로 바꾼다. 즐겨찾기하지 않은 직원에게도 줄이 선다. 바뀌는 동작이라 끝 보고에 적는다.
5. **기억 파일을 두지 않는다.** 저장하는 파생값이 없으니 GA2와 GA4가 생길 자리가 없다. GA3은 줄을 세울 때와 누를 때 지금 권한을 보아 막는다. GA1은 실행을 화면에 넘기지 않아 막는다.

### 1.4 치르는 것과 남는 한계

- 계정 정보를 다시 읽는 1초 남짓 동안(`accountRequest('load')`가 `librarySource`를 비운다) 줄이 잠깐 빠진다. 그때 메뉴를 열면 줄이 없고, 그 전에 연 메뉴에서 누르면 Platform 창이 열린다.
- 권한 기한(`valid_until`)이 지나는 순간에는 알림이 없어 메뉴가 다음 로그인 상태 변화까지 남을 수 있다. 누르면 지금 권한으로 다시 보므로 실행되지 않고 Platform 창이 열린다.
- Platform이 숨어 있는 동안 Workspace를 따로 설치하거나 지우면 다음 변화까지 메뉴가 늦다. 지운 경우는 누를 때 실행이 막고 Platform 창이 열린다.
- 트레이에서 연 실행은 최근 앱 기록(`recordLaunch`)과 이용 기록(`memberActivity.trackLaunch`)에 남지 않는다. 구 얼굴의 Workspace 공간 실행도 남기지 않는다(검토 D9).
- 숨어 있는 동안 서버에서 권한을 거두거나 새로 준 것은 다음 계정 읽기(창을 열 때나 복원 때)까지 모른다. 기한(`valid_until`)은 누를 때마다 다시 잰다. 앱 이용 권한은 길잡이일 뿐이고 Workspace는 자기 로그인을 따로 확인한다(검토 D3).
- 실행이 실패해 Platform 창을 열 때 까닭을 따로 보이지 않는다. 화면에 실행 요청을 다시 넘기면 GA1의 길로 돌아가기 때문이다. 창에서 구의 Workspace 공간을 누르면 그 길이 까닭을 보인다(검토 D7).
- 계정 읽기가 실패하면 다음 성공까지 줄이 없다. 지금 동작과 같다(검토 D8).

### 1.5 바꾸는 파일

- `desktop/src/platform-tray.cjs`: `setShortcuts`를 `setApps(ids)`로 바꾼다. 받는 이름은 `TRAY_APPS`의 열쇠만이고, 누르면 `onLaunchApp(id)`를 부른다. 「SYNK Platform 열기」와 「완전히 종료」는 그대로다.
- `desktop/src/installations.cjs`, `client-lifecycle.cjs`: 해시 없이 설치 표시 파일과 믿는 판 번호만 보는 `probe(id)`를 더한다.
- `desktop/src/main.cjs`: 설치 생명주기를 `createWindow` 밖의 `ensureInstallations()`로 옮긴다(숨은 시작에서도 만든다). `syncTrayApps()`와 `launchFromTray(id)`를 더한다. `synk:tray-shortcuts` 통로를 없앤다.
- `desktop/src/preload.cjs`: `setTrayShortcuts`를 없앤다.
- `desktop/renderer/convenience.mjs`, `launcher.mjs`: `refresh()`의 목록 보내기와 `trayFilter`를 없앤다. 명령 메뉴의 즐겨찾기 표시(`trayShortcuts`)는 그대로 쓴다.
- 시험: `platform-tray.test.cjs`, `desktop-convenience.test.cjs`, `platform-startup-handoff-order.test.cjs`에 새 동작을, 흐름 시험 9번의 트레이 단정을 바꾼다. 검사 도구(`orb-face-fixture.cjs`, `convenience-native-smoke.cjs`)의 가짜 다리에서 `setTrayShortcuts`를 뺀다.

### 1.6 시험 계획

- 숨은 시작: 창 없이 로그인 상태가 준비되면 메뉴에 「SYNK Workspace」가 선다. 권한이 없거나, 로그아웃이거나, 묶음 로그인이 가려졌거나, 설치돼 있지 않으면 서지 않는다. 판을 올린 뒤 첫 숨은 시작에도 선다(기억이 없어도).
- 복원 일시 실패: 창 없이 다시 이어 로그인되면 줄이 선다. 창이 생기면 다시 잇기가 멈춘다.
- 갱신: 창 focus와 10분 확인에서 설치·삭제를 따라간다. 준비 진행이 몰려도 메뉴는 한 번 건다. 로그아웃하면 확인을 기다리지 않고 바로 빠진다. 창 없이 실행한 뒤 `getClients()`를 부르지 않는다.
- 실행이 던져도 다음 누름을 받는다. 해시 도중 계정이 바뀌면 띄우지 않는다. 설치 표시는 맞는데 해시가 틀린 설치에서는 창이 열린다.
- macOS와 Workspace 클라이언트에서는 트레이가 없어 아무것도 하지 않는다.
- 실기: 판을 낸 뒤 숨은 시작 8초의 프로세스 메모리가 0.4.98 값(약 55MiB) 언저리인지 본다.
- 누름: 조건이 맞으면 창을 만들지 않고 실행한다. 누를 때 권한이 끝났거나 로그아웃이면 실행하지 않고 창을 연다. 실행이 실패해도 창을 연다. 끝내는 중이면 아무것도 하지 않는다. 두 번 눌러도 실행은 한 번이다.
- 다시 읽기: 다시 읽는 동안 줄이 빠지고, 끝나면 돌아온다. 저장 파일이 생기지 않는다.
- 순서: 늦게 끝난 앞 확인이 새 확인의 결과를 덮지 않는다.
- 화면: 화면은 `synk:tray-shortcuts`를 부르지 않는다(preload에 없음).

## 2. 설정 방 칸에서 Enter 저장이 실패할 때의 초점

### 2.1 지금

`orb-face-view.mjs`의 Enter 처리는 칸에서 Enter를 누르면 그 묶음의 `data-enter` 단추로 초점을 옮긴 뒤 누른다(`e5639ec8ff`). 초점을 옮기는 까닭은 칸에 초점이 있으면 1분 장면의 다시 짓기를 미루기 때문이다. 저장에 성공하면 묶음이 접혀 초점이 제자리를 찾는다. 실패하면(입력 검사, 본체 거절) 칸은 남는데 초점은 저장 단추에 있어, 고쳐 쓰려면 Shift+Tab을 눌러야 한다(화면 `pc-stage2-2-screen-20261119-k` P2).

### 2.2 정한 것

- Enter로 누를 때 그 줄 열쇠, 칸 이름, 단추의 동작과 인자를 적어 둔다.
- 그 줄 안쪽을 다시 지은 뒤 초점이 아직 그 단추(또는 다시 지은 같은 단추)에 있고 단추가 바쁘지 않으면(`aria-disabled`가 아님) 일이 끝난 것이다. 그때 같은 이름의 칸이 아직 보이면 초점을 그 칸으로 돌리고 글 끝에 둔다. 칸이 없으면(묶음이 접혔으면) 그대로 둔다.
- 초점이 다른 곳으로 갔으면 적어 둔 것을 버린다.
- 성공했는데 칸이 남는 줄(단축키 「적용」)도 칸으로 돌아간다. `e5639ec8ff` 전의 동작(「초점은 같은 칸으로 돌아간다」)과 같다.
- 흐름 시험 18-5에 실패 뒤 초점이 칸에 있는지를 더한다.
- 적어 둔 것은 그 단추에서 초점이 떠날 때(되돌리는 중이 아닐 때), 다음 키 누름과 포인터 누름에서 버린다. 그리기 없이 끝난 일 뒤 1분 장면이 초점을 끌어오지 않게 한다(검토 D10).
- 바쁜 표시를 먼저 그리지 않는 일은 결과 글보다 먼저 칸으로 돌아갈 수 있다. 그때도 알림 줄의 글은 고쳐 쓰인다(검토 D11, 후속).
- 구독 줄(`data-svc`)에는 열쇠가 없어 적어 두지 않는다. 그 줄 안쪽에 Enter 칸이 있으면 옛 동작이 남는다(검토 D12, 후속).

## 4. 옛 런처 화면과 펠트 그림 거두기

### 4.1 지금

11-20에 `desktop/renderer`를 읽어 확인한 것이다.

- **사람에게 보이는 옛 화면은 내 계정 하나다.** 내 계정 방의 마을 기록과 연습 기록 내려받기가 `openLegacy('account')`로 연다(2단계 둘째 조각 설계 14절 D4). 이 길은 남긴다.
- **나머지 일곱 보기(내 홈, 라이브러리, 솔리오, 회원 혜택, 맞춤 정보, 설치·업데이트, 설정)는 보이는 길이 없지만 얼굴 밑에서 돈다.** 계정마다 기억한 길(`synk-platform-route-v1`), 주소의 해시, 포털의 `onOpenPurposeTarget`·`onEnsureEnteredView`가 `showView`를 부른다. 기억한 길이 맞춤 정보나 내 계정이면 보이지 않는 화면이 개인 자료를 읽는다.
- **옛 CSS가 얼굴 줄에 샌다.** `launcher.css`의 `.rows`(346행, 위 테두리), `.rows .row`(347행, 틈 24px와 높이 60px), 900px 아래의 `gap:2px`(605행)가 얼굴의 `.rows .row`에도 걸린다. 트랙 ①의 「641~900px 칸 틈 2px」가 이것이다.
- **펠트 그림이 실려 나간다.** `desktop/assets/launcher`의 그림 20.6MB 가운데 연결 실패 화면(`src/connection-content.cjs`)이 쓰는 `synk.svg`·`button.webp`와 글꼴, `engine.js`·`personalization.js`만 남은 화면이 쓴다. 나머지는 옛 보기만 쓰거나 아무도 쓰지 않는다.
- **옛 보기에만 있는 메모 편집기 셋이 있다.** 내 홈의 「이 PC 메모」(`member-home.mjs`), 계정 라이브러리의 계정 메모(`platform-continuity.mjs`), 옛 PULSE 요청 초안(`pulse-client.mjs`)이다. 0.4.95부터 얼굴에서 닿는 길이 없다. 쓰던 글 확인(나가기 대화상자, 조용한 업데이트 판단)과 설정 방의 「쓰던 글 되살리기」는 이 편집기들을 지키려고 있다.

### 4.2 정한 것

1. **index.html은 얼굴과 내 계정이 쓰는 것만 남긴다.** 남기는 것은 아이콘 모음(sprite), `.launcher` 안의 `main`과 `#view-account`, `#toast`, `#leave-dialog`, `#portal-entry`, 창 막대 틀(template)이다. 제목 줄(주 메뉴, 계정 단추, 프로필 메뉴, 옛 창 단추), 옛 보기 일곱, 상태 줄, 계정 · 놀이 · 맞춤 대화상자를 뺀다. `.launcher`는 남긴다. 내 계정이 그 안에 서고, 설치본 검사기(`verify-windows-startup-native.cjs`)가 그것이 inert인지 본다.
2. **launcher.mjs는 얼굴의 호스트로 줄인다.** 남기는 것은 로그인 흐름(상태, 다시 읽기, 로그인, 가입, 취소, 다시 확인, 계정 바꾸기, 로그아웃), 계정 생명주기, 앱 권한과 설치 상태(포털 콜백의 WORLD · PATH 길이 쓴다), 포털 호스트와 얼굴, 얼굴의 창 막대, 방 다리(`orbRoomOptions`), 내 계정 화면, 알림(toast), 쓰던 글 확인의 틀, 맞춤 표시(글자 크기 · 설명 · 움직임 값), 밤낮 값(내 계정 화면의 색)이다.
   - `showView`는 내 계정만 연다. 기억한 길과 주소 해시는 더 따르지 않는다. 포털이 부르는 `onOpenPurposeTarget('solio' | 'home')`과 `onEnsureEnteredView`는 화면 없이 「됐다」고 답한다. WORLD와 PATH 갈래(설치된 앱 실행, 공개 웹 열기)는 그대로다.
   - PC에서만 쓰던 옛 모듈을 지운다: `member-home.mjs`·`.css`, `pulse-client.mjs`·`.css`(그것만 쓰는 자료 파일 포함), `subscriptions.mjs`·`.css`(옛 구독 판. 얼굴은 `subscriptions-model.mjs`와 다리를 쓴다), `platform-continuity.mjs`·`.css`, `update-view.mjs`, `convenience.css`. 웹 계정 화면이 가져다 쓰는 파일(`benefits.mjs`, `solio.mjs`, `member-insight*`, `world-phone.mjs`, `account-page.mjs`, `town-records-card.mjs`, `portal-*`, `member-*-controller.mjs` 등)은 지우지 않는다. PC가 가져오지 않을 뿐이다.
3. **convenience.mjs는 얼굴이 쓰는 것만 남긴다.** 알림 설정(설정 방의 「알림」), 데스크톱 설정 알림(닫기 버튼 값), 화면 확대 키(Ctrl과 +, −, 0. 설정 방이 이 키를 안내한다), 창이 뒤로 갔을 때의 표시(`data-background`, 얼굴 움직임을 멈춘다), 앱 설치 파일 소식의 알림이다. 명령 메뉴, 알림함, 옛 설정 묶음, 단축키 대화상자, 앱 메뉴, Alt 화살표, 기억한 길은 뺀다. 모두 얼굴이 보이는 동안 막혀 있던 것이다.
4. **메모 편집기 셋은 옛 보기와 함께 거둔다.** 이 PC에 남은 자료(`localStorage`)는 지우지 않는다. 0.4.95부터 닿는 길이 없던 것이고, 다시 보일 자리가 필요하면 내 계정 방의 「내 데이터」에 새 꼴로 짓는다(후속). 지킬 편집기가 없으니 설정 방의 「쓰던 글 되살리기」 줄을 뺀다. 본체의 암호화 보관(`draft-recovery.cjs`)은 남겨 기한이 지난 것을 지운다. 쓰던 글 확인의 틀(나가기 대화상자, 조용한 업데이트 판단, 로그아웃 확인)은 남긴다. 지금은 지킬 글이 없어 묻지 않는다.
5. **CSS.** `launcher.css`는 색 값, 전역 초기화, 단추, 제목, 설정 줄(내 계정), 대화상자와 알림, 창 막대만 남긴다. `.rows`와 `.rows .row` 규칙이 빠지므로 얼굴 줄은 자기 규칙만 받는다. 트랙 ①의 2px 틈이 함께 없어진다. 얼굴 줄의 틈 · 높이 · 테두리를 1440 · 960 · 873 · 768 · 640 · 390에서 빼기 전후로 견준다. `convenience.css`의 창이 뒤로 갔을 때 규칙은 `orb-face.css`로 옮긴다.
6. **그림.** `desktop/assets/launcher`에서 남은 화면이 쓰지 않는 그림을 지운다. 글꼴, `engine.js`, `personalization.js`, `synk.svg`, `button.webp`는 남긴다. WORLD · Workspace 설치기 포스터를 다시 만드는 `installer/art/poster.html`이 읽는 `world-book.avif`·`laptop.webp`는 `desktop/installer/art`로 옮긴다(앱 묶음에는 실리지 않는다). 그림 목록이 겹친 세 곳(`tools/build-renderer-assets.cjs`, `assets/launcher/sources.json`, `tests/renderer-personalization.test.cjs`)을 함께 고친다. 설치기의 펠트 포스터는 WORLD · Workspace 설치기가 쓰므로 이번에 두지 않는다(옮기기 설계 「켜짐부터 열림까지」 정한 것 8).
7. **시험과 검사 도구.** `renderer-auth.test.cjs`는 로그인 흐름과 얼굴 호스트를 보는 시험을 남기고 옛 보기를 단정하는 시험을 뺀다. 지운 모듈의 시험을 지운다. 옛 보기만 여는 개발용 검사 도구(native smoke 열여덟 남짓)를 지운다. 흐름 시험(`orb-face-browser-qa.cjs`)과 설치본 검사기는 그대로 돌아야 한다.

### 4.3 위험과 막이

| 위험 | 막이 |
|---|---|
| `launcher.mjs`가 얼굴을 붙이기 전에 옛 DOM id를 30곳 넘게 찾는다. 하나라도 남으면 얼굴이 붙지 않아 검은 창만 남는다 | 지운 id를 찾는 줄을 모두 지운다. 새 index.html로 `launcher.mjs`를 올려 얼굴이 붙는지 보는 시험을 둔다. 흐름 시험 세 판(main · nowebgl · nocanvas)과 대역 빌드의 설치본 검사기를 돌린다 |
| 계정 생명주기의 그리기 훅이 던지면 `syncAuth`가 끊겨 얼굴이 로그인 상태를 못 받는다 | 남는 참여자만 등록한다. 계정 바뀜 · 로그아웃 시험을 남긴다 |
| 로그아웃과 가입이 옛 대화상자 id(`#sign-out`, `#account-dialog`)에 기댄다 | 두 길을 대화상자 없이 다시 쓴다. 얼굴의 로그아웃 · 가입 · 다시 확인 시험을 남긴다 |
| `.rows .row`를 빼면 얼굴 줄이 달라진다 | 여섯 폭 캡처를 빼기 전후로 견주고, 달라진 곳은 의도(2px 틈 없어짐)인지 본다 |
| 웹 계정 화면이 PC 화면 파일을 가져다 쓴다 | 웹이 쓰는 파일은 지우지 않고, `node tools/check-account-bundles.js`로 웹 묶음이 그대로인지 본다 |
| 지운 파일이 공개 후보에서 「없어진 파일」이 된다 | 판 준비 도구가 지운 파일을 따로 단언하게 고친다 |

### 4.4 시험 계획

- 새 index.html로 `launcher.mjs`를 올리면 얼굴이 붙고, 옛 보기 id를 찾지 않는다.
- 기억한 길과 해시가 있어도 내 계정 말고는 아무 보기도 그리지 않고, 맞춤 정보 · 내 계정 요청을 보내지 않는다.
- 내 계정 방의 마을 기록 · 연습 기록 내려받기가 옛 내 계정을 열고, 「돌아가기」로 돌아온다.
- 얼굴의 로그아웃, 모든 곳에서 로그아웃, 가입, 저장된 로그인 다시 확인, 계정 바꾸기가 된다.
- 화면 확대 키, 창이 뒤로 갔을 때 움직임 멈춤, 앱 설치 파일 소식 알림이 된다.
- 설정 방에 「쓰던 글 되살리기」 줄이 없다.
- 흐름 시험 세 판, 1440과 390을 포함한 여섯 폭 캡처, 콘솔 오류 0, 실패 요청 0.
- 웹 계정 묶음 검사 통과, 데스크톱 시험 전체 통과.
