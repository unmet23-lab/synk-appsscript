## 한 줄 원칙

**어두운 틀 위에 떠 있는 밝은 종이 판.** 틀(위 막대·주요 공간·계정)은 플랫폼과 같은 검은 바탕과 유리 캡슐, 오래 읽는 업무 내용은 흰 판에 큰 한글 제목·모노 라벨·1px 선·검은 알약 선택으로 조용하게.

## 왜 이렇게 바꿨나

- 이전 화면은 남색 펠트 막대, 분홍·코랄 펠트 단추와 칩, 크림 면, 제목마다 붙은 펠트 스티커가 한 화면에 섞여 정보보다 장식이 먼저 보였다.
- 업무 화면 레퍼런스에서 밝은 화면과 어두운 화면의 반응이 비슷했고(Light 1,277K · Dark 1,080K), 메신저의 정석도 어두운 메뉴 + 흰 대화다. 그래서 틀은 플랫폼처럼 어둡게, 본문은 읽기 좋게 밝게 나눴다.
- 플랫폼 앱(싱ㅋ 시그널 2)에서 「워크스페이스」 포스터는 검은 면 + 옅은 청금석 큰 글자다. 로그인 화면의 큰 문구와 수치 강조에 같은 짝을 쓴다.

### 서체

SUIT(본문·큰 한글 800~900, 자간 −0.045~−0.055em), DM Mono(영문 라벨·숫자, 10.5~11px, 자간 .14~.16em 대문자), Inter Tight 700(라틴 이름). DM Mono는 **띄어쓰기를 뺀 범위만**(`Signal Mono`) 불러와 한글이 섞인 라벨이 벌어지지 않게 한다. 한글 라벨에는 모노를 쓰지 않는다.

## 부품

- **틀**: 위 막대 68px(로고 + `WORKSPACE` 알약 · 가운데 검색 캡슐 · 플랫폼과 계정 캡슐). 계정은 이름 첫 글자 동그라미에 무지개 테. 왼쪽 주요 공간은 내용 높이만큼의 유리 세로 캡슐이고 고른 곳은 흰 알약.
- **본문 판**: 틀 위에 둥근 흰 판이 떠 있다. 세부 메뉴가 있으면 왼쪽 칸(옅은 판)과 한 장으로 붙는다. 메신저·내 수업처럼 따로 그려지는 영역도 판과 같은 모양으로 맞춘다.
- **페이지 머리**: `● WORKROOM`처럼 모노 눈썹 → 44px 큰 한글 제목 → 15px 설명. 눈썹은 화면 종류(`data-view`)에서 CSS로 붙여 JS를 건드리지 않는다.
- **단추**: 주 행동은 검은 알약(46px), 손을 올리면 청금석 바깥 테. 보조는 1px 선 알약. 펠트 판 그림을 깔지 않는다.
- **고르기**: 옅은 판 위의 검은 알약(세그먼트). 세부 메뉴·대화 목록의 고른 줄도 검은 알약. 탭은 밑줄 2px.
- **숫자판**: 상자를 따로 띄우지 않고 1px 세로선으로 이어 붙인 계기판. 「지금」 숫자 한 칸만 워크스페이스 면(검정 + 옅은 청금석).
- **상태**: 점 + 글자 칩(연결됨 초록, 준비 중 버터, 안 읽음 코랄 숫자).
- **입력창**: 둥근 판(24~28px), 쓰는 동안 옅은 무지개 테. 보내기는 검은 동그라미.
- **빠른 검색**: 어두운 유리 HUD. 구역 라벨은 모노 대문자.
- **로그인**: 운영은 3판(2026-10-13 공개 해시·1440/864/390 화면 확인). 이전 2판은 좁은 폭에서 입력만 남았으며 [2판 조사](조사_20261010.md#login-v2)에 근거를 보존한다. 3판은 플랫폼 앱 상세와 같은 문법 — 책상 위 떠 있는 판 안에 Workspace 포스터(검은 면 + 파란 펠트 노트북 + 옅은 청금석 「워크스페이스」)와 로그인을 나란히 둔다. 입력·SYNK ID 알약·`OR`·흰 알약 들어가기는 2판을 그대로 쓴다. 아래 [3판](#signal-login-v3-20261013).
- **아이콘**: 24px 격자 1.8px 선의 기존 SVG. 주요 공간·설정의 펠트 스티커는 선 아이콘으로 바꿨다. 마린은 그대로 둔다.

## 새 화면을 더할 때

1. 마크업은 기존 부품 클래스(`.btn`·`.btn.primary`·`.segmented`·`.field`·`.page-heading`)를 쓰면 시그널이 그대로 입혀진다.
2. 새 화면 종류가 생기면 `signal.css`의 페이지 머리 눈썹 줄에 `data-view` 이름을 더한다.
3. 펠트 판 그림·스티커를 단추·칩·제목에 다시 깔지 않는다. 브랜드 색 면은 워크스페이스 면(`#17181C` + `#C5D6F5`) 하나만 쓴다.

## 9판 — 10-11 뒤에 붙은 화면 맞추기 (2026-10-12)

> 유호님이 PATH 면접실을 보고 「이거 마치면 synk workspace도 한번 이 방식대로 디자인 업그레이드 시켜줘」. 10-10 시그널(7·8판)은 운영 중이고, 그 뒤 GPT가 붙인 화면 — 특히 작업실 「고객 관리」(PULSE 고객 프로젝트) — 이 크림·파스텔 바탕, 베리색 한글 눈썹, 펠트 질감 단추, 28px 제목, 기본 셀렉트, 왼쪽 꺾쇠+크림 섹션 머리, 안내 문단마다 다른 바탕색(파랑·초록·연두·보라·베이지)으로 갈라져 있었다. `public/signal.css` 끝에 9판 구역을 덧붙여 같은 문법으로 맞췄다. JS·HTML·서버는 바꾸지 않았다.

- **고객 관리 머리:** 다른 작업실 화면과 같은 위계 — 작은 회색 눈썹(PULSE 베리 점 하나) → 44px/850 제목 → 15px 설명. 숫자 세 칸은 위아래 1px 선과 세로선으로 나눈 계기판(34px/800, 숫자 폭 고정).
- **목록:** 흰 카드 + 1px 선, 고른 카드는 검은 테 하나(크림·코랄 테 없음).
- **선택한 프로젝트:** 크림 판 대신 흰 판 + 1px 선(반경 22). 단계는 점 + 글자 칩. 사실 세 칸은 작은 계기판. **「지금 할 일」만 워크스페이스 면(검정 #17181C + 옅은 청금석 눈썹)에 흰 알약 단추** — 화면에서 하나뿐인 강조.
- **접는 섹션:** 1px 선 흰 판(반경 18), 머리는 16px/800 제목 + 회색 요약, 꺾쇠는 오른쪽 하나. 열린 머리도 흰 바탕.
- **안내 문단:** `-note`·`-notice`·`-empty`로 끝나는 안내는 모두 옅은 면(#F5F5F4) + 1px 선 한 가지. 오류만 옅은 코랄.
- **주의 표시:** 단계와 관계없이 확인할 일은 버터 점 하나.
- **초점:** 프로젝트를 고르면 개요 판으로 초점이 옮겨지는데, 마우스·손가락으로 고를 때는 두꺼운 파란 테를 그리지 않고 키보드일 때만 청금석 2px(`:focus-visible`).
- **공통 입력:** 아직 시그널을 입지 않은 기본 셀렉트에 꺾쇠·46px·반경 14, 체크 상자는 잉크 색. 휴대폰(700px 이하)은 16px.
- **트렌드·레퍼런스:** 글자만 남던 머리 단추 넷을 선 알약으로, 「준비된 제작 양식 / 참고 자료」는 분할 캡슐로.
- **제작 도구:** 파란 「이미지·영상 선택」 칸을 선 알약으로.
- **이미 7판이 !important로 칠하던 것**(`.cd-button` 흰 알약, `.cd-primary` 검은 알약, `.cd-tag` 칩)은 색을 다시 정하지 않고 크기·손 올림만 더했다. 「지금 할 일」 단추만 한 단계 더 구체적인 선택자로 흰 알약.

- **셈:** 엔진 `content-engine.mjs` 208 · 유형 자료 `content-catalog.json` 74 · 화면 `benchmark.js` 3 · 엔진 시험 26, 짝 311개(18~24). 엔진이 만드는 사람이 읽는 글(시나리오 19개 — 주제만·다 채움·개인화·개인 참고·회사 벤치마크 셋·제작 여정·유형 열 개와 각각의 내려받기 글)에서 「~니다」 든 글 505 → 0, 합성 계정 서버 1440·390 29화면의 「~니다」 842 → 0. `benchmark.js`의 합니다체는 [마케팅 글](#marketing-copy-20261020)이 먼저 바꿔 여기서는 영문 머리표 둘과 「적은 근거」 머리만 바꿨다.
