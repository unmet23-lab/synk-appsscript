# 고객 관리 기능 검수 — 무엇을 남기고, 합치고, 뺐나 (2026-10-13)

> 유호님 「지금 이 제공하는 기능들 … 전부 니가 리라이팅해줘. gpt판이라 말투가 좀 어색하네. 그리고 … 클라이언트의 편의성, 그리고 영상 작업자들의 편의성을 위해 … gpt가 추가해준건데 이것들이 정말로 필요한 기능들을 잘 만든건지 제대로 검수 및 보완하면서 업그레이드하거나 압축해줄래?」
> 대상은 Workspace 「고객 관리」(제작자 쪽 PULSE 고객 프로젝트 데스크)의 구역 15개와 머리 패널, 그 뒤의 서버 모듈이다. 결과는 [11판](README.md#signal-v11-20261013)에 반영했다.

## 어떻게 봤나

세 갈래로 조사했다. ① 화면 글 1,337줄과 구역·API·의존 목록(`client-*.js` 21개), ② GPT가 `WORKSPACE.md`·`WORKSPACE_QA.md`에 적어 둔 기능별 의도와 미해결, ③ 고객 쪽 PULSE 앱 화면과 서버 투영(`customerView`)에서 제작자 기능이 고객에게 어떻게 보이는지. 판단 잣대는 넷이다.

1. **고객이 겪는 실패를 막는가.** [PULSE 고객 조사](../플랫폼_시그널/조사_20261013_PULSE고객.md)에서 반복된 실패: 승인 뜻을 모름, 알림이 안 옴, 의견이 조금씩 나옴, 납품물 받기가 어려움, 공들인 브리프가 무시됨, 기다림.
2. **제작자가 매일 쓰는 손을 줄이는가.** 설정을 켜고 항목을 채워야 돌아가는 기능은 손을 늘린다.
3. **같은 정보·행동이 다른 곳에 이미 있는가.**
4. **기록·권리로 남겨야 하는가.**

조사에서 나온 사실 두 가지가 판정의 바탕이다. GPT 문서의 모든 기능은 **직원 쪽 불편**(누락·반복 입력·원문 찾기·놓친 기한)에서 출발했고, 고객이 겪는 문제를 출발점으로 쓴 문장은 없었다(승인 원문은 10-08 「아이디어 훌륭하다. 이거 전부 진행하자」 한 줄). 그리고 같은 문제를 두 번 푸는 쌍이 아홉이었다: 납품 준비↔규격 점검, 시작 설정↔내 양식, 할 일 묶기↔단계별 화면, 진행 안내↔각 구역의 복사 문구, 사용 조건↔만료↔사용 구분, 수령·마감↔완료 기록↔ZIP, 후속 연락↔다시 볼 날짜, 일정 점검↔기한 겹침, 알림 자리 네 곳.

## 글은 어떻게 다시 썼나

- 화면 쪽 문구 860개와 서버 쪽 문구 1,227개를 전부 다시 썼다. 「~을 확인해 주세요」로 끝나던 글의 28%가 사라졌고, 합니다체·해요체 혼용을 해요체 하나로 맞췄다.
- 시스템 말(점검 설정·비교 기준·투영·판정·버전 한도)을 사람 말로 바꿨다. 예: 「기존 착수 점검을 설정한 뒤 필수 자료와 확정사항을 확인해 주세요」 → 「「시작 준비」에서 자료 챙기기를 켜 주세요」, 「입력한 남은 작업일 기준 예상 완료일이 합의한 전달일 안에 있습니다. 내부 계산값이며 완료를 보장하지 않습니다」 → 「이대로 가면 전달일 안에 끝나요. 남은 작업일로 어림한 거예요」.
- 상태는 두세 단어로: 내 차례 · 고객 차례 · 검토자 차례 · 고치는 중 · 끝남 · 기다리는 중 · 받았다고 함.
- 오류는 원인 + 다음 행동 한 문장: 「그사이 바뀐 게 있어 저장하지 못했어요. 쓰던 글은 그대로 보관했고 최신 내용을 불러왔어요」.
- 단추는 동사 하나: 저장 · 되돌리기 · 복사 · 열기 · 넣기 · 고객에게 보이기.
- 고객 화면(PULSE 앱)의 글은 손대지 않았다 — 같은 날 다른 세션이 작업본을 고치는 중이다. 아래 「고객 쪽에서 본 것」에 넘길 것을 적었다. 다만 서버가 고객에게 내려 주는 값은 일부 바뀌었다: 상태 이름(`CLIENT_WORKFLOW_STATUS` · 마감 상태)과 「고객에게 보낼 글」(사용 안내 · 수령 요청 · 진행 안내문)은 제작자가 복사해 보내는 글이라 같이 고쳤고, 창구 이름은 PULSE 앱이 쓰는 「후속 문의」로 맞췄다.

글은 `.tmp/client-desk-signal-20261013/v11/maps/*.json`(옛 문장 → 새 문장 짝)으로 적용했고, 같은 짝을 시험 파일에도 넣었다. 고객 관리 클라이언트·서버 시험 970개 중 968 통과, 2 건너뜀, 실패 0. 화면은 [11판](README.md#signal-v11-20261013)의 캡처로 확인했다.

### 검수 뒤 고친 것 (Fable 읽기 검수, 10-13 저녁)

P0·P1은 없었고 P2 다섯을 고쳤다. ① 문의(support)에도 「고치는 중 · 더 고쳐야 함」이 붙던 것 → 문의는 「답하는 중」, 단추는 「답하기 시작 · 답변 끝내기」(수정 요청은 「고치기 시작」). ② 사용 기간 알림 제목이 「끝나 가요」인데 본문은 「이미 지났어요」이던 모순 → 지났으면 제목도 「기간이 지났어요」. ③ 마감 요약의 ISO 시각·「대기」 → 한국 시간·「아직」. ④ 고객에게 복사해 보내는 글: 파일을 안 골랐을 때 제작자용 「줄 파일을 고르고 사용 안내를 적어 주세요」가 섞이던 것을 뺐고, 제목·승인 시안이 두 번 나오던 것을 한 번으로, 「준비했습니다」를 「보내 드려요」로, 창구 이름을 「후속 문의」 하나로. ⑤ 기다릴 기간 안내 「1~30일」 → 입력 범위와 같은 「0~30일」. 화면 글도 열한 군데 손질했다: 「자료 챙기기 켜기 · 일정 지켜보기」(한다체 제거), 「필요한 자료 적기」, 「기획 확정 전」(0차 대신), 바뀐 것 카드의 겹말·중복 단추, 「수정 요청이 아닌 장면 의견」, 「어디로」(누가 보나 대신), 「고객에게 보이는 다음 할 일」, 납품의 「승인한 시안 · 라벨」 가운뎃점, 「이미 보낸 최종본 있음」, 마감의 「기다릴 기간」·「자기 화면에서」, 사용 조건의 겹치는 상태 글 제거와 요약 「아직 안 본 것 · 기간 지난 것 · 쓰면 안 되는 것 · 근거 없는 것」, 기록 카드 머리 「합의한 내용과 담당」, 초대 링크 「쓸 수 있음」, 시작 준비 요약은 자료 챙기기를 껐을 때도 세 카드를 보이게. P3 둘(일정 상자 열림 복원 순서, 접수 원문 카드 캡처)은 그대로 둔다.

## 고객 쪽에서 본 것 (다음 판으로 넘김)

고객 PULSE 앱은 `/pulse/api/*`만 쓰고 서버가 `customerView`로 걸러 준다. 그래서 사용 조건·사용 구분·일정·후속 연락·진행 안내·납품 파일 검사는 고객에게 보이지 않는다(맞다). 반대로 아래는 고쳐야 한다.

1. **제작자용 문장이 고객에게 보인다.** 착수 확정사항의 「희망 일정과 별도로 프로젝트에 합의한 전달일을 기록해 주세요」(이번에 서버 문구는 고쳤다), 변경 항목 이름 「핵심 약속·기대 행동·게재 채널」(고객 양식은 「기억하게 할 메시지 하나」).
2. **고객 본인에게 3인칭으로 말한다.** 「고객 확인 대기」「고객 확인 완료 N개」.
3. **승인 단추가 켜져 있는데 서버가 거절한다.** 이전 시안 의견이 새 시안에 연결되지 않았으면 409. 고객 화면은 workflow를 받지 못해 「내 차례」로 보인다.
4. **고객 알림이 빠진 곳.** 납품 규격 확인 요청, 의견 분류, 준비 자료, 고친 장면 확인 대기에는 고객 알림이 없다(`client-notifications.mjs`가 「PULSE 기획」 동작만 읽는다). 「제작자의 답변」 알림은 대화가 있는 05가 아니라 06으로 간다.
5. **장면 확인 경로가 세 갈래, 보낸 의견이 두 번 나옴, 문의 창구 이름이 셋.**
6. **「먼저 고쳐서 저장해 주세요」가 확인을 막는다.** 확인 요청 중인 설계를 고객이 고쳐 저장하면 확인 요청이 지워지는데 안내가 없다.

이 여섯은 PULSE 고객 조사의 제안 1·9·11(들어오기·승인·알림)과 같은 줄에 있다. 고객 앱 작업이 끝나면 그 세션의 기록 위에 얹는다.

## 코드에서 본 것

- `resolve` 처리 코드는 있지만 그 단추를 만드는 곳이 없다(죽은 코드).
- 규격 검사 카드의 PULSE 링크만 같은 탭에서 열려 쓰던 납품 입력을 잃을 수 있다(다른 PULSE 링크는 새 탭).
- 기록 폼의 fieldset 하나에 legend가 둘이다.
- 모듈마다 `GET /api/client-projects`를 따로 부르고, 서로를 갱신하는 목록을 손으로 골라 둬서 모듈마다 다르다.
- 서버 `pulse-app`·`server.mjs`는 다른 세션이 고치는 중이라 이번에 손대지 않았다.
