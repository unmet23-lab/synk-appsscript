# 싱크타운 10대 생활 콘텐츠 제작 설계

> 2026-10-08 · 사용자 확정: Steam 조사에서 제안한 열 가지를 모두 설계한다. **1순위 재미, 2순위 사용자가 주인공이라고 느끼는 숙련도별 주민 행동, 3순위 TOPIK에 도움이 될 수 있는 학습**이다.
> 열 가지의 설계 범위와 위 우선순위는 확정이다. 아래 장면·배치·수량·시간은 제작 및 검증안이다. 전부 구현·출시됐거나 재미·교육 효과가 검증됐다는 뜻은 아니다.

담당 연결: [생활 재미와 성장](싱크타운_생활재미와_성장콘텐츠_설계_20261008.md) · [NPC 자율생활](싱크타운_NPC자율생활_설계_20261008.md) · [Steam 조사](싱크타운_Steam생활게임_TOP10_조사_20261008.md) · [첫 생활 원고](싱크타운_첫생활구간_원고.md) · [경제와 상품](싱크타운_생활경제와_상품_설계.md).

## 1. 열 가지를 만드는 공통 약속

플레이어는 **무엇을 할지 정하고, 직접 바꾸고, 자기 결정 때문에 달라진 주민 행동을 보는 사람**이다. 쉬기·구경하기를 골라도 자리·시점·참여 정도를 본인이 정하며, NPC가 그 선택을 존중한다.

- 먼저 학습 평가와 정답 보상을 빼도 해보고 싶은 생활 행동을 만든다. 그다음 NPC가 내 행동을 알아보고 되돌려 주는 장면을 붙인다. 마지막으로 그 생활에 필요한 언어를 골라 학습 연습으로 연결한다.
- 모든 카드의 `30~90초`는 한 번 직접 해보는 분량의 가설이다. 제한 시간이 아니며, 듣기·읽기·시범·고민·휴식에 시간 감점을 두지 않는다.
- 모든 주요 생활은 혼자 완결된다. 선택적 공유 장면에서도 다른 사용자 응답을 핵심 이야기의 필수 조건으로 삼지 않는다.
- 그림·짧은 말·다시 듣기·시범을 사용해도 결과·존중·선택권은 같다. 한국어를 어렵게 말한 사람에게만 더 좋은 집·깊은 우정·큰 결정을 주지 않는다.
- 인사·도움·동행·보답은 대사로만 처리하지 않는다. 어디로 이동하고, 어떤 물건을 쓰고, 무엇을 맡고, 언제 기다리는지 화면에 나타나야 한다.
- **실제 좌석·비품 수:** 첫 쉼터의 기본 의자는 1개다. T01의 마주 보기/나란히 쉬기, T02의 두 명 시험 등 장면이 실제로 요구하는 좌석 수만큼 현재 소유가 확인된 NPC 비품과 자리·사용자를 함께 예약한다. 부족하면 순차 이용·서서 보기·다른 유효한 개인 공간 중 원래 의도를 살릴 수 있는 대안을 **사용자가 선택**하게 하고, 두 명 착석을 원하면 필요한 좌석이 확보된 장면을 선택할 수 있게 한다. 대안을 두 명 착석 완료로 기록하지 않는다. 물건 자동 복제·플레이어 집 소유 증가·필수 영업 비품 장기 점유는 없다. 같은 세계의 같은 개체를 생활·동행·공연이 동시에 대여하지 않으며, 비품은 종료·취소 때 원래 보관으로 돌려놓고 실제 끝낸 사건만 남긴다.
- 이동은 2026-10-09 확정한 [WASD·방향키/모바일 조이스틱/게임패드 직접 걷기](싱크타운_첫플레이_실행설계.md)를 따르고, 근접 후 E·상호작용 버튼·게임패드 A로 행동 목록을 연다. 새 패널·미니게임 조작을 카드마다 늘리지 않는다. 정밀 조작 대신 허용 자리·미리보기·확정으로 완결할 수 있다.
- 카드의 `A/B`는 취향과 결과가 다른 동등한 갈래다. 각각 현재 방문에서 선택 차이를 보여 주며, 한쪽을 학습 정답이나 숨은 고득점 경로로 만들지 않는다.
- 카드의 `거절`은 같은 의도의 재권유를 닫는다. 다음 카드의 다른 주민을 보내 같은 부탁을 우회하지 않는다. 참여하지 않은 일에 플레이어 공로·언어 성공을 기록하지 않는다.
- **열 가지 모두 학습 체크·정답 제출 없이 생활을 완결한다.** 생활 완료·취향 선택·감상 자체를 언어 성공으로 기록하지 않는다. 자연스러운 대화에서 실제로 이해하거나 표현한 수행은 기존 검수 과제·영역·도움·시각 단서·첫 응답 등의 조건을 충족한 범위에서 관측할 수 있다. 별도 평가·훈련은 사용자가 선택해 열며, 관측 가능한 항목이 없어도 생활을 그대로 끝낸다.

## 2. 열 가지의 대응과 서로 다른 즐거움

| ID | 도입하기로 한 내용 | 생활에서 직접 느끼는 즐거움 | 앞선 설계와 연결 |
|---|---|---|---|
| T01 | 주민 일과·개인 이야기 | 익숙한 사람의 다른 면을 발견하고 함께 보낼 시간을 선택 | 주민 일과·LS01 |
| T02 | 작은 행동에 즉시 반응 | 놓고·돌리고·비교하면서 공간의 반응을 발견 | FT10·배치 사용 시험 |
| T03 | 주민 모임 연속극 | 다음 이야기가 궁금하고 내 선택이 모임의 관습을 바꿈 | LS01·LS03 |
| T04 | 손님 취향에 맞는 추천 | 요청을 알아가며 나만의 조합과 접객 방식을 찾음 | FT20·FT52·LS02 |
| T05 | 함께한 일을 관계로 기억 | 받기만 하던 도움을 나누고 나도 돌봄받음 | 관계 기억·보답 |
| T06 | 발견한 것이 집을 변화시킴 | 밖에서 찾은 이야기를 내 공간으로 가져옴 | FT30·FT53·LS03 |
| T07 | 주민 동행·손님 맞이 | 길과 소개 순서를 정하고 친구와 다른 풍경을 봄 | 동행·집 초대 |
| T08 | 돌아오면 반가운 준비·생장 | 내가 시작한 준비가 다음 생활의 재료가 됨 | FT20 재배·경제 준비 작업 |
| T09 | 작은 장터 | 진열·분담·추천을 바꾸며 한 차례의 가게를 운영 | LS02·판매/이야기 재고 분리 |
| T10 | NPC 아이디어·공동 발전 | 내가 고른 방향이 동네의 쓰임과 사람의 동선을 바꿈 | LS01/03의 공간 변화 |

T01~T10은 제작 분류다. `T01 완료 → T02 해금` 같은 필수 숙제 순서로 쓰지 않는다. 한 장면이 여러 카드를 만족할 수 있지만 새 장면 수·보상·완료를 열 번 중복 계산하지 않는다.

기존 교육 원고에도 T01 같은 번호가 있으므로 문서·제작표에서 생활 카드는 `life:T01`, 학습 과제는 `learning:<pack>:T01`처럼 범위를 구분한다. 이는 제작 참조 규칙이며 현행 API의 식별자를 임의 변경한다는 뜻은 아니다.

## 3. T01 — 공방 주인의 쉬는 한 시간

**플레이어의 즐거움:** 늘 공방에 있던 주민에게 조용히 쉬고 싶은 면이 있음을 발견하고, 나와 함께할 방식이나 혼자 쉴 자리를 고른다. 친해질수록 내 취향도 주민의 일과에 반영된다.

- **시작 조건:** 기본 만남 후 **내가 먼저 같이 쉬자고 제안**하거나 공방 주인의 실제 휴식 계획과 만날 때. 자리에 없으면 현재 장소 안내와 직접 신청하는 만남 대안이 있으며 특정 현실 시각에 접속할 필요는 없다.
- **30~90초 직접 행동:** 창가/쉼터 두 곳을 걸어 보며 소리와 풍경 비교 → 내 자리를 선택 → 컵 또는 읽을거리 위치 놓기 → 함께 쉬기/각자 쉬기 정하기. 배치가 부담되면 기본 자리를 그대로 사용한다.
- **A — 같이 쉬기:** 마주 보는 자리를 골라 차를 나눈다. 주민이 작업 중 발견한 재미있는 모양을 보여 주고, 플레이어가 이어 볼 소재를 고른다.
- **B — 각자 쉬기:** 나란한 자리를 고르고 각자 읽을거리를 놓는다. 주민은 긴 대화를 멈추고 조용히 함께 머문다. 깊은 관계가 반드시 긴 대화를 뜻하지 않는다.
- **거절:** “오늘은 혼자 있을게요.”를 고르면 주민은 자기 기본 휴식을 한다. 플레이어를 따라오거나 쉬는 장소를 가로막지 않는다.
- **즉시 반응:** 내가 먼저 앉은 방향에 맞춰 주민이 유효한 다른 좌석을 고르고, 마주 보기/나란히 보기의 자세가 달라진다.
- **현재 방문:** A는 발견 물건을 실제 펼치고, B는 읽을거리를 정리해 서로 방해하지 않는 간격을 만든다. 나는 자리 이동·중단·조용히 있기를 계속 선택할 수 있다.
- **재방문:** 전에 함께 쉰 실제 장소가 남아 있으면 그곳을 휴식 후보로 삼는다. “같이 앉아도 괜찮아요?”라는 신호 뒤 수락하면 합류한다. 옛 선택을 영구 성격으로 고정하지 않는다.
- **언어 지원과 생활 숙련:** 짧은 말 사용 시 주민이 두 자리로 이동해 직접 차이를 보여 주고 한 번씩 묻는다. 넓은 표현을 선택하면 자신의 휴식 이유를 설명하고 내 제안을 기다린다. 이미 자리 운영을 해본 플레이어에게는 언어 수준과 무관하게 모임 배치도 맡길 수 있다.
- **상태·자원:** `restPlan`, `seatReservation`, `sharedRestEvent`, `quietPreference`를 구분한다. 차는 NPC 배경 비품이며 내 판매 재고가 아니다. 쉬었다고 시간당 코인·학습 점수를 지급하지 않는다.
- **실패·복귀:** 의자가 철거되면 옆 자리/기본 쉼터를 다시 고른다. 중단 전 확정한 휴식 사실만 보존하고 보지 않은 개인 사연은 다음 선택 앞에서 기다린다.
- **반복과 장기 변화:** 함께 쉬는 장소 → 취미를 한 가지 알게 됨 → 내가 정한 모임에 주민이 자기 물건을 가져옴으로 확장한다. 모든 방문에 사연을 새로 고백하지 않는다.
- **필요 원고·동작:** 첫 휴식, 조용한 동석, 취미 발견, 자리 없어짐, 다시 만남의 다섯 상황 원고; 이동·양보·앉기·물건 펼치기·정리하기. 각 배역의 승인 몸체 동작으로 제작한다.
- **설계 인수:** 설명을 읽지 않은 플레이어가 “내가 조용히 있고 싶어서 이 주민도 말을 줄이고 옆에서 쉬었다”를 실제 행동으로 알아볼 수 있어야 한다.

대사 예: “여기서 쉬어도 될까요?” → `[같이 이야기해요] [같이 조용히 쉬어요] [오늘은 혼자요]`. 세 선택을 관계의 우열로 채점하지 않는다.

**두 사람의 자리:** T01 A/B 모두 각자의 실제 좌석이 필요하다. 첫 쉼터에서는 기본 의자와 찻집의 별도 시험 의자 한 개를 예약해 쓸 수 있으며, 이는 아래 T02의 시험 의자와 **같은 개체 풀**이다. T02가 사용 중이면 새 의자를 생성하지 않고 가능한 다른 자리/시간을 고른다. 임시 두 번째 의자가 반환된 뒤의 재방문에는 현재 확보한 좌석에서만 함께 쉬는 행동을 한다.

## 4. T02 — 움직이면 달라지는 내 쉼터

**플레이어의 즐거움:** 물건을 돌리고 놓으며 예상한 사용과 실제 사용의 차이를 발견한다. 완성 화면을 받는 데서 끝나지 않고 작게 바꿔 다시 시험하는 놀이가 된다.

- **시작 조건:** 이용 가능한 기본 쉼터와 배치 권한. FT10 완료 결과가 있으면 재사용하고, 새로 차양을 제작해야만 시작하는 구조는 피한다.
- **30~90초 직접 행동:** 좌석 방향 두 가지 미리보기 → 컵 받침/관찰 카드 중 놓을 물건 선택 → 내가 직접 앉거나 NPC에게 시험 이용 제안 → 시선·통로를 보고 한 가지 수정.
- **A — 풍경 보기:** 의자를 바깥으로 향하게 놓는다. 주민이 그 방향으로 앉아 쉬고 지나가는 새나 잎을 함께 바라보는 장면이 열린다.
- **B — 이야기 나누기:** 의자를 마주 보게 놓는다. 주민이 서로 얼굴을 향하고 중앙의 컵·카드를 번갈아 사용하는 장면이 열린다.
- **거절:** 시험 이용을 요청하지 않고 혼자 꾸밀 수 있다. NPC 방문이 배치 완료의 필수 조건이 아니며, 내 공간은 이미 사용할 수 있다.
- **즉시 반응:** 놓을 자리의 통로·접근 방향이 보이고, 확정한 물건의 방향·그늘·작은 소리가 변한다. 임시 미리보기를 실제 완성 사실로 말하지 않는다.
- **현재 방문:** 초대받은 NPC가 실제 경로로 와서 앉고 물건을 이용한다. 놓을 곳이 불편하면 멈춘 위치와 필요한 여백을 짧게 보여 준다.
- **재방문:** 남아 있는 배치에 따라 풍경 보는 사람/이야기하는 조합이 달라진다. 옮기거나 회수한 물건은 더 이상 과거 위치에서 사용하지 않는다.
- **언어 지원과 생활 숙련:** 초급 표현에서는 NPC가 이용 위치를 한 곳씩 보여 준다. 확장 표현에서는 두 용도의 차이를 말하고 내가 비교할 시간을 준다. 배치 숙련자는 시험 순서와 주민 역할을 정하며 쉬운 말 그대로 기획할 수 있다.
- **상태·자원:** `layoutRevision`, `objectOwner`, `seatUse`, `previewIntent`를 구분한다. 배치 변경은 소유 물건 이동이며 복제·새 제작·새 보상이 아니다.
- **실패·복귀:** 길 막힘은 확정 전 안내한다. 이용 중 수정은 점유 해제 후 수행하고, 중단하면 확정 배치로 복귀한다. 개인 배치 되돌리기는 판매·소비를 되돌리지 않는다.
- **반복과 장기 변화:** 날씨·손님 수·모임 목적에 따라 같은 물건이 다른 쓰임을 갖는다. 반응이 새로운 이유 없이 같은 칭찬만 반복되면 새 콘텐츠로 세지 않는다.
- **필요 원고·동작:** 바깥/마주 보기, 통로 막힘, 이용 거절, 바뀐 자리 알아봄의 다섯 상황; 회전 미리보기·길 표시·착석·시선 전환·실물 사용. 정지 화면 대안도 같은 사실을 전달한다.
- **설계 인수:** 대사 없이도 두 배치가 다른 생활을 만든다는 것을 구별하고, 플레이어가 자기 목적에 맞춰 다시 바꾸고 싶어야 한다.

대사 예: “밖을 볼까요, 같이 앉을까요?” → 실제 의자 방향을 비교한다. “정답이에요” 대신 주민이 보고 있는 대상과 누구와 대화하는지를 보여 준다.

**첫 쉼터의 의자 수와 두 명 시험:** FT10의 기본 의자는 1개다. 방향 미리보기는 같은 의자 한 개를 두 상태로 보여 주며 두 개를 지급하지 않는다. 두 명이 앉는 A/B 사용 시험에는 찻집 소유의 **별도 시험 의자 1개**를 기존 영업 필수 의자와 분리해 편성하고 `objectId/owner/loanReservation`을 확인한다. 사용자가 시험을 수락한 회차 동안만 두 번째 허용 좌석을 함께 예약하며 자기 집 소유물·판매 재고가 되지 않는다. 시작 전에 두 좌석과 시험 의자를 모두 확보할 수 있어야 A/B 시험을 제안한다. 자원이 막히면 혼자 방향을 미리 보는 방식 또는 가능한 시점의 두 명 시험을 고를 수 있고, B를 몰래 A로 바꾸지 않는다. 시험 종료·거절·앱 종료에는 두 번째 의자가 NPC 보관으로 돌아가며 첫 의자의 확정 방향은 남는다. 다음 방문의 두 명 이용은 같은 비품을 다시 예약할 때만 표현하고 없는 두 번째 의자에 NPC를 앉히지 않는다. 시험 의자의 소유·보관 위치는 새 장식 지급이 아니라 T02의 준비 비품 1개로 제작표에 포함한다.

<a id="T03"></a>
## 5. T03 — 우리 모임의 다음 이야기

**플레이어의 즐거움:** 자기 목적이 다른 두 주민을 알아가며 다음 만남을 궁금해한다. 플레이어가 고른 모임 방식이 다음 회차의 문제·역할·습관을 바꾼다.

- **시작 조건:** 내가 기본 쉼터에 모임을 신청하거나, 공방 주인과 연구원이 관찰 카드의 쓰임을 두고 작은 의견 차이를 보일 때 참여. FT/LS 기존 사실을 읽고 이미 해결한 시작 장면을 다시 처음으로 만들지 않는다.
- **30~90초 직접 행동:** 두 주민의 물건 구경 → 그림/짧은 글 카드 순서 바꾸기 → 시험 관람 한 차례 → 내가 이어 보고 싶은 소재나 다음 역할 선택.
- **A — 그림 모임:** 내가 큰 그림을 앞에 두고 관람 순서를 정한다. 연구원은 짧은 설명을 준비하고 공방 주인은 전시 받침을 맡는다.
- **B — 질문 모임:** 내가 질문 카드 두 장을 고르고 쉬는 자리를 정한다. 연구원은 질문을 기다리고 공방 주인은 실제 물건을 가져와 함께 비교한다.
- **거절:** 두 주민은 기본 그림을 펼쳐 자기 대화를 마친다. 내 후속 초대는 보류되고, 다음에 신청하면 실제로 본 사실만 짧게 이어 준다.
- **즉시 반응:** 주민이 내가 정한 순서의 첫 대상 앞으로 이동하고 설명 또는 질문을 시작한다. 내 선택과 무관하게 동일 컷신이 재생되지 않는다.
- **현재 방문:** 말수 적은 관객을 택하면 주민이 먼저 발언을 강요하지 않는다. 내가 관람 위치·보고 싶은 대상·잠시 멈춤을 정하고, NPC는 그쪽으로 물건을 보여 준다.
- **재방문:** 그림 모임에서는 새로운 전시 소재를, 질문 모임에서는 다른 주민의 질문을 가져온다. 전 회차 선택을 실제 준비물과 역할로 회수한다.
- **언어 지원과 생활 숙련:** 짧은 말에서는 한 주민씩 발화하고 대응 물건을 보여 준다. 확장 표현에서는 서로의 이유를 한 번 더 주고받되 필요하면 쉬운 요약으로 돌아간다. 모임 숙련자는 전체 순서를 맡거나 관객으로 쉴 수 있다.
- **상태·자원:** `episodeId/version`, `branch`, `seenFacts`, `propAssignment`, `hostRole`을 기록한다. 같은 회차 재관람은 새 관계·보상·최초 학습 노출이 아니다.
- **실패·복귀:** 두 주민 중 한 명이 다른 작업에 예약되면 개인 회차 시작 전 대안을 알린다. 참여 중 이탈은 다음 선택 앞에 저장하고 핵심 결말을 부재 중 대신 확정하지 않는다.
- **반복과 장기 변화:** 첫 모임 → 서로의 서툰 점 발견 → 플레이어 방식으로 시도 → 새 참여자와 역할 바꾸기의 연속 사건을 쓴다. 단순 대사 교체를 새 회차라고 하지 않는다.
- **필요 원고·동작:** 공통 도입과 그림/질문 각각의 결과, 각 갈래 후속, 불참 시 NPC끼리 마무리; 둘 사이 시선·대화 차례·대상 옮김·시험 관람·플레이어에게 자리 양보.
- **설계 인수:** 플레이어가 다음 회차에서 “저 물건과 저 역할은 지난번 내가 정한 방식 때문에 생겼다”를 짚을 수 있어야 한다.

[공연과 생활 학습](싱크타운_공연과_생활학습_설계_20261008.md)으로 확장할 때도 관람 위치·이어 볼 장면·참여 정도가 생활 선택으로 남아야 한다. 공연 도중 정답 팝업을 기본 흐름으로 삽입하지 않는다.

<a id="T04"></a>
## 6. T04 — 오늘 이 손님에게 맞는 한 잔

**플레이어의 즐거움:** 취향을 알아가면서 오늘의 사정에 맞는 조합을 추천한다. 같은 손님도 다른 기분·동행자·목적으로 찾아와 늘 같은 물건만 주는 선물 반복이 되지 않는다.

- **시작 조건:** 기본 찻집에서 내가 손님 맞기를 고르거나 허용된 도움 제안을 수락. 검수된 요청 두 종류를 준비한다. FT20 지원 음식/이야기 준비분과 판매용 운영 재고를 구분하고 재배를 필수 선행으로 삼지 않는다.
- **30~90초 직접 행동:** 향·따뜻함·단맛 견본 비교 → 손님의 현재 요청 한 가지 확인 → 준비 가능한 두 조합 중 결정 → 잔과 자리 지정 → 실제 제공.
- **A — 편히 쉬는 한 잔:** 따뜻하고 향이 약한 준비된 메뉴를 조용한 자리에 낸다. 손님은 천천히 마시고 자기 읽을거리를 펼친다.
- **B — 함께 비교하는 한 잔:** 같은 요청을 만족하는 다른 메뉴를 향 비교 자리에서 소개한다. 손님이 동행자와 향을 비교하고 내가 고른 설명 대상에 반응한다.
- **거절:** 오늘은 손님으로 머물거나 기본 메뉴를 NPC에게 부탁한다. 손님 이야기·기본 환대가 닫히지 않고 영업 압박을 주지 않는다.
- **즉시 반응:** 색·김·잔 배치와 시음 몸짓이 달라진다. 요청에 맞지 않는 미리보기에는 불쾌한 벌점 대신 다시 확인할 부분을 보여 준다.
- **현재 방문:** 손님이 선택한 자리에서 실제 마시고 상황에 맞게 쉬거나 비교한다. 찻집 주인은 내가 맡지 않은 안내·준비 부분을 실제 수행한다.
- **재방문:** 지난 주문은 기억하되 “오늘도 같은 걸로 할까요?”로 확인한다. 이번에는 동행자·날씨 등 준비된 다른 필요를 제시할 수 있고 기존 취향을 지우지 않는다.
- **언어 지원과 생활 숙련:** 초급은 손님이 요청을 한 항목씩 말하며 해당 견본을 가리킨다. 확장 표현은 두 조건과 이유를 묶어 말한다. 생활 숙련자는 두 손님의 역할 분담을 조정하며 짧은 표현으로도 전체 운영을 맡는다.
- **상태·자원:** `currentRequest`, `stablePreference`, `batchSource`, `servingState`를 분리한다. FT20 손님 한 몫 제공 완료와 플레이어 자기 몫 시음·관람 완료를 혼동하지 않는다.
- **실패·복귀:** 제공 전 의도 확인과 수정은 소비가 없다. 제공한 몫은 한 번만 소비한다. 재고가 없으면 기본 메뉴/비판매 시연 대안을 안내하고 무료 음식 무한 생성을 하지 않는다.
- **반복과 장기 변화:** 한 손님 추천 → 동행자 두 요청 → 나만의 소개 방식 → 손님이 다른 사람을 소개하는 후속. 어려운 주문이 더 큰 애정 보상을 주지 않는다.
- **필요 원고·동작:** 두 유효 추천, 요청 재확인, 동행자 등장, 품절 대안, 지난 취향 확인; 견본 보기·시음·잔 전달·착석·소개 역할 분담.
- **설계 인수:** 요청을 다시 듣거나 그림을 쓴 사람도 자기 추천이 손님의 현재 행동을 바꿨다고 느껴야 한다.

대사 예: “따뜻한 걸 마시고 싶어요. 너무 달지 않으면 좋겠어요.” → `[향이 약한 차] [덜 단 과일차] [다시 물어보기]`. 두 메뉴의 유효 조건을 원고에 명시한다.

<a id="T05"></a>
## 7. T05 — 이번에는 이웃이 나를 도와주는 날

**플레이어의 즐거움:** 내가 해준 일을 NPC가 기억해 내 생활에 도움을 돌려준다. 보답의 종류와 시점을 내가 정하고, 혼자 하고 싶은 일은 계속 내 몫으로 남긴다.

- **시작 조건:** 해당 주민이 실제로 참여하거나 본 공동 사건과 보답 가능한 기능. 제안자 한 명의 `sourceEvent`와 `npcKnowledge`를 먼저 확인하고, 그 주민이 할 수 있는 A/B 두 도움 방식을 편성한다. 단순 친밀도 수치·구매액·다른 주민에게만 한 비공개 행동으로 열지 않는다.
- **30~90초 직접 행동:** 내가 하던 꾸미기/준비 작업에서 맡을 부분 지정 → NPC에게 보조 한 부분 요청 → 함께 시험 → 유지/수정/내가 마저 하기 선택.
- **A — 작업 도와주기:** 제안한 주민이 지금 내 작업의 보조 한 부분을 맡는다. 공방 주인이 제안자라면 받침을 고정하고 나는 전시 방향을 정한다. 내 판단과 직접 배치가 완성의 핵심으로 남는다.
- **B — 쉬는 동안 준비해주기:** 같은 제안자가 자기 비품으로 내가 고른 휴식 자리를 준비한다. 공방 주인이라면 이동 가능한 자기 받침과 읽을거리 놓을 자리를 정리한다. 나는 장소·배치 방향·함께할 방식을 정하며 내 재고를 허락 없이 쓰지 않는다.
- **거절:** “이번에는 혼자 해볼게요.”를 고르면 주민이 물러나 자기 일을 한다. 보답 약속이 의뢰 빚이나 죄책감으로 남지 않는다.
- **즉시 반응:** 선택한 보조 역할의 자리로 실제 이동하고 준비 동작을 시작한다. 내가 조작 중이면 중단시키지 않고 안전한 경계에서 기다린다.
- **현재 방문:** NPC가 맡은 한 부분을 끝내며 플레이어의 마지막 선택을 기다린다. “다 해놨어요”로 내 핵심 행동을 없애지 않는다.
- **재방문:** 완료한 상호 도움은 다음 분담에서 근거가 된다. 주민이 내가 전에 맡은 부분을 기억하고 어떤 일을 맡을지 먼저 물어본다.
- **언어 지원과 생활 숙련:** 초급에게 NPC는 역할 그림을 놓고 자기 할 부분을 시범 보인다. 확장 표현에서는 이유와 순서를 확인한다. 숙련 플레이어에게는 도움을 줄이거나 다른 부분을 맡는 선택을 제공하며 존중은 동일하다.
- **상태·자원:** `sourceEvent`, `npcKnowledge`, `offeringNpcId`, `helpOffer`, `agreedRole`, `completedContribution`을 분리한다. 두 갈래는 같은 제안자와 그 제안자의 원인 사건을 참조한다. NPC 자기 비품과 플레이어 자원을 구분하고 소비 동의 없이 보답을 실행하지 않는다.
- **실패·복귀:** 경로·도구가 막히면 일시 정지하고 대안을 고른다. 도움 수락 직후 종료돼도 확정 기여만 유지하며 완료 대사·관계 증가를 먼저 발급하지 않는다.
- **반복과 장기 변화:** 같은 선물을 계속 받아내는 대신 배치 보조·손님 안내·발견 정리처럼 실제 가능한 보답이 바뀐다. 내가 계속 봉사해야 친절을 유지하는 구조는 피한다.
- **필요 원고·동작:** 원인 사건별 감사 참조, 도움 두 종류, 거절 존중, 막힘 대안, 공동 완료; 도구 대기·지지·운반의 승인 표현·내 입력 기다리기·양보.
- **설계 인수:** 플레이어가 누가 나를 어떻게 도왔는지 실제 작업 결과로 설명할 수 있고, 자기 결정과 마지막 행동이 남아 있어야 한다.

대사 예: “지난번에 자리를 같이 정했지요. 오늘은 제가 받침을 봐드릴까요?”는 실제 사건과 현재 가능한 행동이 있을 때만 쓴다.

**제안자별 두 방식:** 공방 주인은 `내 배치 중 받침 고정 / 내가 쉬는 자리의 자기 받침·읽을거리 준비`, 찻집 주인은 `내 접객 중 쟁반·잔 준비 보조 / 내가 고른 휴식 자리의 자기 쟁반·잔 정리`, 연구원은 `내 전시 중 카드 비교·고정 보조 / 내가 쉬는 자리에서 볼 자기 관찰판 준비`를 맡는다. 각각 준비된 물건·동작·허용 위치가 있는 조합만 제안하며, 동등한 두 방식이 가능한 개인 장소 또는 기본 자리로 연결한다. 한 방식이 현재 막히면 제안 전에 가능한 자리/시점을 보여 주고 사용자가 고르게 한다. 모르는 다른 주민을 대신 보내거나 한 갈래를 한국어 수준 때문에 없애지 않는다. 비품은 사용 뒤 원래 NPC 보관 위치로 돌아가며 선물·판매 재고가 되지 않는다.

**반대 사례:** 공방 주인과만 비공개 공동 작업을 마친 뒤 B를 고르면 공방 주인이 자기 비품으로 휴식을 돕는다. 찻집 주인·연구원에게 그 사건의 감사·보답·기억이 생기면 실패다. 같은 공방 주인에게 A를 고르면 내 작업 중 보조가, B를 고르면 휴식 준비가 실제로 달라져야 한다.

## 8. T06 — 산책에서 찾은 것이 우리 집의 이야기가 됨

**플레이어의 즐거움:** 작은 발견을 관찰하거나 데려와 자기 공간의 분위기를 바꾼다. 희귀품 추첨보다 어디서 어떻게 발견했고 누가 알아보는지가 기억에 남는다.

- **시작 조건:** 기본 산책길과 관찰 가능한 대상. A는 개인 발견 기록과 집의 기본 기록 표시 자리를 사용한다. B는 이미 소유권이 확정된 FT30의 별도 선물 화분 또는 제작 화분을 사용한다. 기존 FT30의 온실 표본을 집으로 회수하는 권한은 만들지 않으며 모든 식물을 마음대로 채집할 수 있는 것으로 바꾸지 않는다.
- **30~90초 직접 행동:** 흔적 두 곳 중 관심 장소 선택 → 잎의 모양·빛·그늘 비교 → 집에서 표시할 관찰 기록 또는 그 발견을 계기로 꾸밀 소유 화분 선택 → 집의 진열/화단 위치 미리보기.
- **A — 이야기 전시:** 관찰 그림을 내 독서 자리의 기본 표시판에 놓는다. 같은 `discoveryId`의 기록을 표시하는 것이며 새 판매 카드·채집물·최초 발견을 만들지 않는다. 초대한 연구원이 그림을 보고 실제 출처를 확인하고, 방문객은 그림이 잘 보이는 자리에서 구경한다.
- **B — 작은 생태 자리:** 별도로 받은 선물 화분이나 제작한 내 화분을 적합한 자리에 놓는다. 산책에서 고른 색·모양·자리 용도를 참고해 꾸미되 그 화분이 산책에서 채집한 바로 그 표본이라고 말하지 않는다. 주민이 향·그늘 등 해당 화분의 검수된 속성을 이용하며, 성장 가능한 대상만 승인된 생장 규칙을 따른다.
- **거절:** 그 자리에서 보고 돌아온다. 발견 기록만 원하면 남길 수 있고, 채집하지 않았다고 불완전·손해로 표시하지 않는다.
- **즉시 반응:** 대상의 특징을 직접 가까이 보고, 집 미리보기에서 그 물건이 바꾸는 시선·색·자리 용도를 비교한다.
- **현재 방문:** 확정한 물건이 실제 집에 남고, 초대에 동의한 NPC만 들어와 그 자리로 이동한다. 사적 집 배치가 자동으로 동네에 알려지지 않는다.
- **재방문:** 집의 현재 용도에 맞는 방문 이유가 생긴다. 그림이 남으면 관찰 이야기를, 화분이 자랐으면 그 변화만 알아본다. 회수한 대상을 현재 전시라고 말하지 않는다.
- **언어 지원과 생활 숙련:** 초급은 NPC가 같은 특징을 가까이 가리키고 짧게 비교한다. 확장 표현은 발견 장소와 이유를 물으며 내 설명을 기다린다. 집 꾸미기 숙련은 전시 순서·방문 동선을 바꾸며 언어 수준과 분리한다.
- **상태·자원:** `discoveryId`, `observationSource`, `homeRecordDisplay`, `inventoryObject/owner/source`, `homePlacement`, `invitationScope`를 구분한다. 기록의 표시 위치와 실물의 유일한 배치를 별도로 저장한다. 온실 표본·별도 선물 화분·제작 화분의 개체 ID를 혼합하지 않으며 같은 표본 반환·재채집은 새 최초 발견/보상이 아니다.
- **실패·복귀:** 소유 화분이 없거나 선물을 받지 않았으면 재료 없는 A로 완결할 수 있다. 미수령 FT30 선물이 실제 남아 있으면 받기를 선택할 수 있지만 T06 진입만으로 지급하지 않는다. 설치 조건이 맞지 않으면 소유물은 보관하고 다른 자리를 고른다. 다른 기기 배치와 충돌하면 현 소유·판본부터 확인한다.
- **반복과 장기 변화:** 개별 발견 → 취향별 묶음 → 내 전시 방식 → 다른 주민과 관찰 교환으로 확장한다. 도감 100%를 집 성장의 필수 조건으로 두지 않는다.
- **필요 원고·동작:** 기록 표시/소유 화분 두 갈래, 비채집, 집 초대, 기록과 화분 각각의 출처 소개, 대상 회수; 관찰 시선·소유 화분 이동·그림 표시·집 입구 대기·전시 관람.
- **설계 인수:** 플레이어가 “저 길에서 본 것을 기록으로 두었어요” 또는 “그 발견을 보고 내 화분을 이렇게 꾸몄어요”라는 서로 다른 출처와 집의 쓰임을 NPC 행동에서 확인해야 한다.

발견 이름을 맞히는 퀴즈를 집 소유 조건으로 쓰지 않는다. 관찰·배치 완료는 언어 성공이 아니며 실제 읽기/설명 수행은 §1의 검증 조건으로만 관측한다. 별도 연습을 열지 않아도 기록 전시와 집 꾸미기를 마친다.

**표본·기록의 반대 사례:** FT30 표본이 온실에 있는 상태에서 T06 B를 고르면 집에는 별도 소유 화분만 이동하고 온실 표본은 그대로 남는다. A는 같은 발견 기록의 표시를 집에 추가하되 온실 실물·카드 관리 위치나 새 보답을 바꾸지 않는다. 집 표시를 끄면 그 표시만 사라지고 개인 수첩 기록은 유지한다. 집으로의 이전 허가가 없는 온실 표본은 집 배치 후보에 나오지 않으며, 사유 공간에 초대하지 않은 주민은 그 배치를 알지 못한다.

## 9. T07 — 내가 안내하는 산책과 손님 맞이

**플레이어의 즐거움:** 익숙한 길을 다른 취향의 주민과 다시 보고, 자기 집에서 보여 줄 순서를 정한다. NPC의 능동 반응이 있어도 목적지와 초대 범위는 내가 결정한다.

- **시작 조건:** 내가 먼저 산책/집 초대를 제안하거나 주민 제안을 수락하며, 관계·현재 동행 가능한 일정·개인/공유 예약을 확인한다. 가까운 산책과 집 방문을 분리하고 동행 수락을 집 출입 동의로 확대하지 않는다.
- **30~90초 직접 행동:** 경유지 두 곳 중 첫 장소 선택 → 직접 걸어가기 → 관심 물건 보여 주기 → 쉬거나 다음 장소 결정 → 집 앞에서 초대/배웅 선택.
- **A — 발견 산책:** 내가 관찰 지점을 먼저 고르고 연구원이 특징을 확인한다. 연구원이 먼저 발견한 작은 단서를 알려도 갈지 말지는 내가 정한다.
- **B — 집에서 맞이:** 내가 자리를 준비하고 보여 줄 물건 두 개의 순서를 정한다. 방문객은 그 순서로 이동해 물건을 이용하거나 질문한다.
- **거절:** 이번에는 혼자 걷거나 집 앞에서 배웅한다. NPC는 기본 귀가 경로를 쓰며 집 문을 따라 들어오지 않는다.
- **즉시 반응:** 동행자는 내 속도와 정지에 맞춰 멈추고, 앞을 막지 않는 위치로 이동한다. 길이 갈라지면 정해 둔 목적지를 확인한다.
- **현재 방문:** 내 관심 대상 옆에서 적절히 기다리거나 돕고, 내가 이동을 재개하면 따라온다. 스스로 다음 장소로 뛰어가 장면을 먼저 끝내지 않는다.
- **재방문:** 함께 본 실제 장소를 기억해 다른 시간/용도의 산책을 제안한다. 집은 매번 허용된 방문 범위를 확인하고 방문객이 마음대로 재입장하지 않는다.
- **언어 지원과 생활 숙련:** 초급에게는 목적지 한 곳씩 가리키며 방향 전환 전 기다린다. 확장 표현은 두 경유지의 차이를 설명하고 내가 순서를 정하게 한다. 안내 숙련자는 경유·휴식·역할을 직접 기획하고 초급 표현으로도 같은 권한을 갖는다.
- **상태·자원:** `companionReservation`, `routeIntent`, `followState`, `visitConsent`, `privateSceneScope`를 둔다. 공유 NPC 몸체는 한 예약만 수행하며 개인 장면 전환을 명시한다.
- **실패·복귀:** 주민이 다른 역할 중이면 “지금은 가게를 봐요. 준비 뒤에 같이 갈까요?”와 가능한 다른 만남/주민/혼자 가기를 제시한다. 길 막힘은 정지→현재 길 재계산→대체 만남 자리 확인 순서다. 이탈·취소 시 예약을 해제하고 NPC는 실제 귀가한다. 재접속 뒤 동행을 자동 재개해 추적하지 않는다.
- **반복과 장기 변화:** 같은 길도 연구원은 생태, 공방 주인은 물건 쓰임에 반응한다. 친해지면 손님이 자기 물건을 가져오는 방문이 생기되 내 집 구조를 허락 없이 바꾸지 않는다.
- **필요 원고·동작:** 동행 제안, 경유 확인, 막힘 대안, 집 앞 동의, 배웅, 지난 산책 참조; 따라가기·옆으로 비키기·기다리기·관찰·문 앞 정지·귀가.
- **설계 인수:** 가구를 옮기고 멈추고 집 초대를 취소해도 동행자가 자연스럽게 대응하며, 진행의 주도권이 내게 있다고 느껴야 한다.

동행자는 모든 일을 대신 해결하는 도구가 아니다. 내가 발견하고 정한 것을 확인·보조하고 자기 관점을 보태는 이웃이다.

## 10. T08 — 내가 시작해 둔 준비가 반겨주는 귀환

**플레이어의 즐거움:** 떠나기 전에 고른 화분이나 준비물이 돌아올 때 달라져 있다. 밀린 노동을 처리하는 대신 그 결과를 오늘 어디에 쓸지 선택한다.

- **시작 조건:** A는 내가 이미 소유한 성장 가능한 장식 화분, B는 개인 모임 장면에서 공방 주인이 소유하며 대여 가능한 받침을 사용한다. 공유 공방의 필수 비품을 장기 잠그지 않는다. 승인 전에 대상 개체·소유·세계 범위·준비 판본·진행 방식·대기 순서와 예상 완료·배치/대여 조건을 보여 준다. A는 독립 자연 성장, B는 경제 원문의 순차 보조 작업이며 준비된 판본이 없는 대상은 후보에 넣지 않는다.
- **30~90초 직접 행동:** A의 기존 화분 또는 B의 대여받침 선택 → 위치·준비 결과와 기다릴 순서 확인 → 성장 시작/작업 예약 승인 → 전후 모습 미리보기 → 다른 생활 또는 쉬기 선택. 돌아온 뒤에는 같은 물건의 사용처를 직접 정한다.
- **A — 내 공간에 사용:** 이미 가진 장식 꽃 화분을 창가/쉼터에 놓아 꽃봉오리에서 꽃이 핀 모습으로 키운다. 초대한 주민이 현재 성장과 공간 용도를 알아보고 그 옆에서 쉰다. 같은 개체의 외형 단계만 바뀌며 새 화분·딸기·판매 재료가 생기지 않는다.
- **B — 함께 쓸 준비:** 공방 주인에게 자기 소유의 대여받침 하나를 모임용으로 준비해 달라고 요청한다. 주민이 받침을 정리하고, 나는 준비 완료 후 빌려 배치·소개 순서를 정한다. 소유권은 공방 주인에게 남으며 판매·분해·재료화할 수 없다.
- **거절:** 화분은 내 보관함에 두거나 받침은 NPC의 대여 보관에 둔 채 오늘은 산책만 한다. 준비 결과는 사라지지 않고 수령 독촉·관계 차감이 없다.
- **즉시 반응:** 승인된 대상 물건과 실제 단계를 보여 준다. A는 성장 중, B는 앞선 작업이 있으면 순서를 기다리는 상태이며 주민이 아직 받침을 손질한다고 말하지 않는다. 승인 전 잠정 작업은 준비가 확정됐다고 표현하지 않는다.
- **현재 방문:** 기다리지 않고 다른 생활을 한다. NPC 자기 준비는 자기 재고로만 진행하며 내 이름의 이야기 결말·판매를 대신 확정하지 않는다.
- **재방문:** 현재 결과 하나를 먼저 보여 준다. 내가 직접 고른 사용처로 옮기면 주민이 그 물건을 실제 이용한다. 한 달 부재를 한 달치 요구로 되돌려주지 않는다.
- **언어 지원과 생활 숙련:** 초급은 NPC가 전후 상태와 다음 사용처를 실물로 보여 준다. 확장 표현은 준비 목적·사용 순서를 묻는다. 생활 숙련자는 여러 준비의 역할을 조율하지만 기다림을 오래 했다고 숙련·언어가 상승하지 않는다.
- **상태·자원:** `approvedAt`, `enqueuedAt`, `startedAt`, `dueAt`, `preparationKind`, `preparationVersion`, `objectId/owner/worldScope`, `advanceBasis`, `offlineCompletion`, `readyState`, `preparationAllocationId`, `loanReservationId`, `loanState`를 분리한다. 시간 권위는 서버다. B는 경제 원문의 순차 보조 작업 목록 한 몫을 사용한다. 승인 작업의 비품 배정과 복귀 후 인도를 위한 임시 대여 예약은 별개다. A는 NPC 보조·재료 소모·산출이 없는 개체의 자연 성장으로 따로 관리하며 아래의 동시 성장 상한을 지킨다.
- **실패·복귀:** 통신 중단은 마지막 확정 상태로 복원한다. 성장/예약 승인이 불명확하면 같은 요청 ID로 확인하고 재차 소비하지 않는다. 시계 변경·중복 접속으로 착수·성장·산출을 재발급하지 않는다. 대기 취소는 B의 미착수 예약만 해제하며 이미 시작한 성장·완료 결과를 처음으로 되감지 않는다.
- **반복과 장기 변화:** 작은 화분 → 장소에 맞는 모음 → 주민과 나눈 쓰임으로 확장한다. 접속 유지·매일 수확·연속 출석을 새 이야기의 조건으로 삼지 않는다.
- **필요 원고·동작:** 승인/대기/성장/완료/보관/사용의 상태별 문구, 장기 부재 환영; 화분 놓기·꽃의 성장 단계·받침 정리·대여/반환·실제 이용. 긴 오프라인 연출을 몰아 재생하지 않는다.
- **설계 인수:** 잠깐과 오래 쉬고 돌아온 사용자 모두 손실 없이 결과를 알아보고 다음 생활을 스스로 선택할 수 있어야 한다.

`elapsed-server-time`은 준비와 성장만 진행시킨다. 중요한 초대·개인 이야기의 선택·함께하는 완결은 `player-decision`으로 남긴다.

**A의 완료 조건 검증안:** `ornamental-bloom-v1`은 성장 가능한 기존 화분을 유효한 개인 자리에 놓고 호스트가 시작을 승인하면 `startedAt = approvedAt`, `dueAt = startedAt + 300초`로 같은 `objectId`를 꽃 핀 단계로 바꾼다. NPC 노동을 맡기지 않는 독립 자연 성장이므로 보조 작업 순차큐에는 넣지 않는다. 이 판의 동시 진행 상한은 계정의 장식 화분 3개이며, 이동/보관/재접속으로 진행 슬롯·시각·단계를 초기화하지 않는다. 한 개체의 같은 성장 판본은 한 번만 진행하고 완료 후 추가 재료·수확·새 소유물·코인·관계 진전을 발급하지 않는다. 완료한 화분은 그대로 이용하고 네 번째 동시 성장은 기존 성장 완료 뒤 본인이 시작한다. 기존 작물의 3칸·FT20 첫 수확은 해당 경제 규칙으로 별도 관리하며, 장식 성장 경로로 제작·수확 작업을 우회하지 않는다.

**B의 완료 조건 검증안:** `display-stand-ready-v1`은 같은 받침의 소유·회차 예약과 보조 작업 목록의 남은 몫을 확인해 `approvedAt/enqueuedAt`를 확정한다. 경제 원문의 최대 3개 순차큐를 그대로 사용하며 승인과 착수는 다르다. 호스트는 앞선 작업의 실제 완료와 해당 주민·도구·자리의 실행 가능 여부를 확인한 뒤 한 번 `startedAt`를 확정하고 `dueAt = startedAt + 180초`로 정한다. 앞선 일이 아직 끝나지 않았으면 예약 후 180초가 지나도 준비 완료가 아니다. 승인 전 보이는 예상 완료는 앞선 대기 시간을 포함하며, 조건이 바뀌면 현재 대기 이유를 알리고 임의로 완료하지 않는다. 준비 완료 시 동일 개체를 `대여 준비 완료`로 바꾸고 실제 인도·모임 시작은 플레이어가 돌아와 선택한다. 반환하면 NPC 대여 보관으로 복귀하며 부재를 연체·분실·자동 인도 실패로 만들지 않는다. A의 300초와 B의 180초는 각 판본의 시험값이고 기존 운영 제작의 5분을 대체하지 않는다.

**B의 준비 배정과 실제 대여:** 승인된 작업의 `preparationAllocationId`는 개인 회차의 NPC 소유 받침을 준비 대상으로 지정한 지속 배정이다. 화면을 닫아도 이 승인 작업과 준비에 필요한 비품 배정은 보존하며, 길·좌석·화면 표시 등 더 이상 필요 없는 임시 점유는 해제한다. 준비가 끝나면 같은 받침을 NPC의 준비 완료 보관 위치에 두고 완료 결과를 보존한다. 이때 플레이어 인벤토리·`loanState`에 인도 완료를 만들지 않는다. 복귀 후 `[빌리기]`를 직접 고를 때 현재 소유·개체·준비 판본·허용 배치·원승인에 따른 수령 권리를 다시 확인해 임시 `loanReservationId`를 만들고 인도를 확정한다. 만료 전 승인 작업의 완료·수령과 착수한 사건의 현재 결과까지는 경제 정본의 만료 규칙으로 보존하며, 현재 이용권은 그 뒤 새 유료 활동을 시작할 때 확인한다. 인도 전에 중단하면 그 임시 대여 예약만 해제하고 NPC 보관의 준비 완료 결과는 남긴다. 이미 인도한 대여는 기존의 실제 반환·회수 계약으로 닫으며 화면 종료를 소유권 이전이나 물건 삭제로 처리하지 않는다.

**기존 작물과의 구분:** FT20 첫 화단의 120초는 모종 1개를 심어 딸기 1묶음을 한 번 수확하는 경로다. 이를 A의 화분 성장이나 B의 받침 준비 산식으로 사용하지 않는다. 기존 보답 화분을 새로 발급하거나 첫 수확·이야기 지원물을 판매 재료로 바꾸지 않는다. 반복 생산은 별도 경제 원고의 입력·산출·권한을 그대로 따른다.

**추가 인수 사례 1:** FT20 모종을 심고, 시각 t=0에 A의 장식 화분 성장과 5분 운영 보조 작업 하나를 각각 시작한다. B 받침은 그 작업 뒤에 같은 t=0에 예약한다. 다른 실행 방해가 없을 때 FT20은 물 주기 없는 120초에 수확 가능, A는 300초에 꽃 핀 상태, B는 앞선 작업이 끝난 300초에 착수하여 480초에 준비 완료다. 180초에 재접속해도 B는 대기 중이어야 한다. 화분 이동·보관·중단·다른 기기 재접속 후에도 각 시각과 개체를 보존한다. 이미 보조 작업 3개가 있으면 B를 네 번째로 예약할 수 없으며, A의 독립 성장으로 그 보조 작업을 완료시키지 않는다. 장식 화분 3개가 성장 중이면 네 번째는 기존 성장 완료 전 시작되지 않는다. 결과는 출처가 남은 딸기 1묶음, 동일 소유 화분의 성장 단계, NPC 소유 동일 받침의 대여 상태로 구분되고 화분 추가 생성·받침 소유권 이전·무료 지원물 판매 전환·동일 작업 재지급은 0이어야 한다.

**중단 시점별 추가 확인:** B 승인 직후 종료해도 준비 작업은 유지되지만 임시 길·좌석 점유는 풀린다. 준비 완료 뒤 아직 빌리지 않았다면 받침은 NPC 보관에 있고 대여·인도 완료는 없다. `[빌리기]` 뒤 인도 확정 전에 종료하면 임시 대여 예약만 풀리고 같은 준비물을 다시 선택할 수 있다. 인도 확정 뒤 종료했다면 실제 대여 사실을 보존하고 기존 반환 경로를 따른다. 네 경우를 같은 ‘예약 해제’나 ‘대여 완료’로 합치면 실패다.

## 11. T09 — 내가 꾸리고 이웃이 거드는 작은 장터

**플레이어의 즐거움:** 물건 수량보다 가판의 분위기·소개 방식·역할 분담을 바꾸며 손님 맞이가 달라지는 것을 본다. 마을 전체 생산을 혼자 떠안지 않는다.

- **시작 조건:** 내가 기본 진열 자리에서 장터 열기를 선택한다. 이야기 장터는 비판매 준비분, 판매 장터는 유효한 판매 계약과 현재 판매 가능한 자기 재고·정산 몫·권한을 별도로 확인한다.
- **30~90초 직접 행동:** 진열 순서와 이야기/판매 목적 선택 → 한 품목 미리 소개 → NPC에게 안내/준비 중 한 역할 요청 → 두 손님의 다른 요청 처리 → 내가 마무리 시점 결정.
- **A — 조용한 시음 자리:** 소량의 두 메뉴를 비교해 소개한다. 찻집 주인이 준비를 맡고 손님은 앉아 천천히 반응한다.
- **B — 구경하며 고르는 자리:** 그림·전시물을 먼저 배치하고 가판을 따라 둘러보게 한다. 공방 주인이 진열을 보조하고 손님은 물건의 쓰임을 물어본다.
- **거절:** 손님·구경꾼으로 참여하거나 가판을 닫는다. 주민 가판은 기본 운영을 이어가고 내 불참으로 장터가 실패하지 않는다.
- **즉시 반응:** 내가 정한 진열 방향으로 손님이 접근하고, 안내 담당 NPC가 맞이 위치로 이동한다. 손님이 보지 못하는 진열은 실제 시선으로 알아볼 수 있다.
- **현재 방문:** 나는 소개·제공·배치 중 선택한 부분을 직접 한다. NPC는 맡은 일을 실제 수행하고, 혼잡하면 입장/자리/순서를 조정할 여유를 준다. 반응속도 벌점은 없다.
- **재방문:** 물건의 실제 이용은 인도·소유 사실에 맞춰 보여 준다. 지난 소개의 기억은 별도로 실제 관람·전달 사실에 맞춰 남긴다. 구매하지 않고 구경만 한 손님도 자신이 듣거나 본 부분은 기억할 수 있다. 다음에는 다른 용도·동행자 요청이 생길 수 있으며 모든 손님이 자동 단골이 되지 않는다.
- **언어 지원과 생활 숙련:** 초급은 손님이 한 요청씩 실물을 가리키고 NPC가 긴 설명을 나눠 맡는다. 확장 표현은 비교·추천·변경 요청을 다룬다. 장터 숙련자는 전체 분위기와 역할을 정하며 말 길이로 운영권을 제한하지 않는다.
- **상태·자원:** `stallMode`, `stockSource`, `reservedOrder`, `npcRole`, `delivery`, `settlement`을 분리한다. 첫 체험·이야기 지원물 판매 금지와 기존 정산 한도를 유지하고 현행 미니게임 코인과 합치지 않는다.
- **실패·복귀:** 소개 중 취소는 소비하지 않는다. 제공 뒤 종료는 인도·정산 여부를 원장으로 확인하며 다시 팔지 않는다. 품절은 기본 가판/전시 전환으로 이어지고 재입고를 강요하지 않는다.
- **반복과 장기 변화:** 차 소개 → 그림과 물건 합동 가판 → 다른 주민의 취미를 초청한 작은 장터로 확장한다. 매출 순위·마감 몰아치기·전 품목 완판이 성공 조건은 아니다.
- **필요 원고·동작:** 두 운영 방식, 두 손님 요청, 역할 분담, 품절·취소·배웅, 물건 사용 후속; 진열·접근·안내·실제 인도·거스름 없는 정산 확인·정리.
- **설계 인수:** 플레이어가 운영 방식을 바꿨을 때 손님 동선과 NPC 역할이 달라지고, 코인을 적게 벌어도 한 차례 생활을 완결했다고 느껴야 한다.

장터 준비와 마무리는 같은 방문에서 끝낼 수 있다. 접속 시간을 늘리기 위해 다음 현실 장날까지 기다리게 하지 않는다.

**추가 인수 사례 2:** 소개를 듣고 물건을 받지 않은 손님은 다음에 그 소개를 기억하되 물건을 쓰거나 구매했다고 말하지 않는다. 소개를 듣지 않고 포장 물건만 받은 손님은 실제 받은 물건을 사용할 수 있지만 지난 설명을 들었다고 말하지 않는다. 물건 인도와 소개 인지를 각각의 사실로 검증한다.

## 12. T10 — 주민의 제안으로 내가 바꾸는 동네

**플레이어의 즐거움:** 주민이 실제 생활의 필요를 발견해 제안하고, 나는 어떤 동네를 만들지 결정한다. 완성 기념 대사 이후에도 사람들이 바뀐 공간을 다르게 사용한다.

- **시작 조건:** 현재 세계에 실제 불편/새 용도 후보가 있고 준비된 시설 기능·공간 권한이 있을 때. 없는 문제를 만들거나 플레이어 진행을 강제하기 위해 기본 서비스를 고장내지 않는다.
- **30~90초 직접 행동:** 비 오는 날 현재 자리 둘러보기 → 필요한 기능 두 가지 비교 → 위치 미리보기 → 내가 맡을 작업 선택 → NPC들과 사용 시험 → 최종 용도 확정.
- **A — 조용한 처마 자리:** 빗소리를 들으며 쉬는 공간을 정한다. 공방 주인은 준비된 차양 설치를 돕고 찻집 주인은 실내외 서빙 경로를 나눈다.
- **B — 함께 보는 작은 전시:** 같은 허용 구역을 관찰 모임 자리로 쓴다. 연구원은 전시 사실을 준비하고 공방 주인은 받침을 맡으며 나는 동선을 정한다.
- **거절:** 지금의 공간을 유지한다. 주민은 기존 실내/기본 쉼터 대안을 사용하고 “발전을 막았다”는 불이익을 주지 않는다. 내 요청으로 제안 목록을 다시 열 수 있다.
- **즉시 반응:** 주민이 문제 위치와 자기 맡을 부분을 실물로 보여 주고, 내가 선택한 기능에 따라 가져오는 도구·자료가 달라진다.
- **현재 방문:** 내 배치·사용 시험·마지막 선택이 있어야 개인 프로젝트가 완결된다. NPC가 자기 자원과 작업으로 기여하며 내게 재료 수집 전부를 넘기지 않는다.
- **재방문:** A는 비/휴식 때 머무는 경로, B는 관람·산책 때 들르는 경로가 열린다. 기능을 바꾸거나 철거하면 이에 의존하는 새 계획도 대안으로 이동한다.
- **언어 지원과 생활 숙련:** 초급은 NPC가 두 결과를 시험해 보여 주고 짧은 말·그림으로 최종 결정을 받는다. 확장 표현에서는 다른 주민의 이유를 함께 설명한다. 생활 숙련자는 계획을 처음부터 제안하며 초급 한국어라도 최종 방향을 정한다.
- **상태·자원:** `needEvidence`, `proposalId`, `projectScope`, `contributions`, `facilityRevision`, `dependentPlans`를 기록한다. 개인 공간 변화와 공유 공공시설 권한을 구분하고 한 사람의 개인 분기로 공용 지형을 덮어쓰지 않는다.
- **실패·복귀:** 예약 충돌은 내 초안·소유물을 보존하고 현 상태에서 다시 고른다. 중단된 설치는 확정 단계부터 이어가며 기여·소모를 반복 계산하지 않는다. 날씨가 달라지면 실내 시험/모형으로 이어갈 수 있다.
- **반복과 장기 변화:** 불편 해결 → 새 사용 습관 → 다른 주민의 방문 목적 → 공간 재해석의 흐름을 쓴다. 무한 기술 트리·출석 기부·시설 레벨 숫자만으로 발전을 대체하지 않는다.
- **필요 원고·동작:** 실제 필요 제시, 기능 두 갈래, NPC 자기 기여, 공동 사용 시험, 유지/철거 대안, 바뀐 일과; 현장 관찰·도구 준비·설치 보조·경로 변경·모임 이용.
- **설계 인수:** 완성 후 설명창을 닫아도 플레이어가 자기가 고른 방향 때문에 달라진 주민 동선·이용·모임을 최소 한 가지 알아볼 수 있어야 한다.

NPC는 검수된 시설·행동 범위 안에서 제안한다. 구현하지 않은 기능을 즉석으로 발명했다고 말하거나 자동 생성된 제안만으로 세계를 변경하지 않는다.

## 13. 열 가지를 연결하되 플레이어의 하루를 빼앗지 않기

한 연결 예는 `T06 산책 발견 → T08 집에서 성장 → T02 배치 사용 시험 → T07 이웃 초대 → T04 차 추천 → T03 작은 모임 → T05 도움받기 → T09 장터 → T10 새 공간 → T01 바뀐 일과`다. 이 순서는 전체 시스템을 검수하기 위한 예이며 사용자에게 따라야 할 코스로 내보내지 않는다.

어느 지점에서도 오늘 끝낼 수 있다. “차가 준비됐으니 장터도 해야 해요”처럼 다음 콘텐츠를 자동 수락하지 않는다. 오늘의 시작 화면은 점수·밀린 의뢰보다 내가 고를 생활과 현재 달라진 공간을 먼저 보여 준다.

**장기 변화의 의미:** 새 원고가 없더라도 내 배치·용도·초대·역할을 바꾸면 실제 생활이 달라질 수 있어야 한다. 기본 일과는 반복을 허용하고, 새 개인 이야기는 실제 작성한 분량만 제공한다. 같은 일상 반복을 새 장편이라고 표시하지 않는다.

**제작 우선순위의 적용:** 첫 연결 묶음에서는 짧은 생활을 직접 해보고 싶게 만드는지, 내 선택을 NPC 행동에서 알아볼 수 있는지를 먼저 판정한다. 이 둘이 실패한 장면에 학습 문항을 추가해서 통과시키지 않는다. 열 가지 모두 이 기준으로 제작하며 순서를 나눴다는 이유로 설계 범위를 줄이지 않는다.

## 14. 원고·상태·화면에 넘길 제작 계약

각 카드는 다음의 한 묶음으로 제작한다. 아래는 작성·구현할 산출물의 기준이며 이미 준비된 자산 수가 아니다.

| 산출물 | 반드시 담을 것 | 탈락시키는 예 |
|---|---|---|
| 장면 원고 | 시작 사실, A/B/거절, NPC 자기 목적, 내 직접 행동, 현재 결과, 후속 | 긴 대사 뒤 두 선택이 같은 컷신으로 수렴 |
| 반응 원고 | 즉시/현재 방문/재방문 행동과 그 행동의 원인 사건 | “고마워요”만 달라지고 위치·역할은 같음 |
| 지원판 | 같은 의도·선택·보상을 유지하는 짧은/확장 표현, 실물·그림·시범 | 초급판만 관객, 확장판만 기획자 |
| 동작 명세 | `bodyProfile`, `actionVariant`, 대상 개체, 접근/점유, 시작·중단·끝 | 팔 없는 몽글에 팔 추가, 허공의 물건 사용 |
| 상태 전이 | 초안→권한/예약→확정→표현 전달, 중단·철거·재전송 처리 | 대사 재생으로 재고·관계·학습 성공 확정 |
| 선택적 학습 | 실제 필요한 표현과 과제 영역, 도움/시각 단서 기록, 생활과 분리 | 공연 취향·꾸미기 선택을 언어 정답으로 기록 |

Town은 세계·소유·진행 권위를 갖고 기존 Core·Trail·Vellum·Loom·Reed·Strata·Temper 책임을 재사용한다. 이 카드들을 위해 별도 판단 엔진이나 런타임 자유 생성 NPC를 신설하지 않는다.

## 15. 열 가지 전체의 검수 조건

1. 각 카드에서 학습 평가와 정답 보상을 빼도 플레이어가 직접 고르고 바꾸는 행동과 서로 다른 A/B 결과가 남는다. 대화와 이야기 자체의 재미는 그대로 살린다.
2. 초급+생활 숙련, 상급+생활 초보, 깊은 관계+짧은 표현, 새 관계+넓은 표현에서 결과·권한·존중을 섞지 않는다.
3. 각 카드의 즉시/현재/재방문 반응이 현재 세계·NPC 인지·실제 참여 사실에 맞고, 제거된 물건·미참여 사건을 참조하지 않는다.
4. 거절·구경·조용히·도움·중단이 정상적인 생활이며 손실·자동 재권유·학습 강제 팝업이 없다.
5. T03/T07/T10에서 NPC가 장면을 이끌어도 사용자의 핵심 선택과 직접 행동은 남고, 동행·공간·사생활 경계는 지켜진다.
6. T04/T08/T09의 입력·산출·인도·판매 출처가 한 번만 확정되고, 부재 중 개인 선택·무한 수익·학습 성공이 생기지 않는다.
7. 직접 관찰에서 플레이어가 다시 해보고 싶은 생활, 자기 선택 때문에 달라진 행동, 다음에 하고 싶은 일을 설명한다. 체류 시간만으로 재미를 입증하지 않는다.
8. 그 뒤에 실제로 수행한 듣기·읽기·표현 연습 영역을 확인한다. 선택형 응답을 발화 능력, 생활 완료를 TOPIK 성적 향상으로 바꾸지 않는다.

이 문서는 **열 가지 전부의 제작 설계**다. 아래 §16은 각 대표 장면의 실제 지원 원고다. 이를 향후 모든 회차의 대본이나 완성 자산으로 세지 않는다. 최종 이름/외형·애니메이션·음성·경제/공유 구현·기기 성능·학생 재미와 교육 효과 검증은 이후 제작 결과로 확인한다.

## 16. 열 장면의 실제 한국어와 주민 행동

이 절은 T01~T10의 A/B·자원·기억 계약을 바꾸지 않고, 구현자가 **무슨 말을 언제 하고 어떤 행동을 멈추거나 넘길지** 사용할 수 있는 대표 원고를 붙인다. 따옴표 안은 실제 대사, 나머지는 제작 지시다. 캐릭터의 이름·외형은 기존 주민 캐스팅을 따른다.

### 16-1. 지원·역할·관계를 섞지 않는 적용 규칙

- `짧게`와 `넓게`는 같은 사실을 전달하는 표현판이다. 계정의 TOPIK 급수·게임 레벨·친밀도가 아니며 도움 요청을 우선한다. 짧은 표현판의 질문은 **한 문장씩** 보여 주고 해당 대상·선택을 먼저 처리한 뒤 다음 문장으로 간다. 표 안의 문장 여러 개를 한꺼번에 읽거나 동시에 여러 질문으로 내보내지 않는다.
- 생활 역할은 `같이 시범 / 한 부분 맡기 / 내가 기획` 중 본인이 고른다. 표현판과 독립이므로 **짧게 + 내가 기획**, **넓게 + 같이 시범**도 그대로 성립한다. 생활 숙련 근거는 역할 제안의 참고이고 권한 잠금이 아니다.
- 관계는 실제 함께한 사건을 회수하는 도입·마무리에만 붙인다. 새 주민에게는 현재 사실로 시작하고, 기존 주민이라도 `sourceEvent + npcKnowledge`가 없으면 “지난번처럼”을 붙이지 않는다. 아래 지원을 사용했다고 관계가 얕아지거나 보상·결말이 달라지지 않는다.
- 망설임은 무응답만으로 진단하지 않는다. 표의 망설임 대사는 `[천천히 볼게요]`·`[아직 못 골랐어요]`를 사용자가 고른 경우의 응답이다. 가만히 있는 동안 NPC는 안전한 대기 자세를 유지하고 재촉·자동 확정·힌트 팝업을 하지 않는다.
- 오해 행은 **서로 다른 의도가 확인된 경우의 수습**이다. 인식이 불확실하면 “○○을 원한 건가요?”로 먼저 확인한다. 짧은 답·입력 인식 실패·시각 단서 사용을 학습자의 오류로 단정하지 않는다. 자유 제안은 검수된 의도·가능한 계획으로 확인될 때만 실행하고 모르는 요구를 이해한 척하지 않는다.
- `[다시 말해 주세요] [보여 주세요] [잠깐 쉴게요] [그만할게요]`는 고정 행동 목록에서 계속 접근할 수 있다. 다시 말하기는 같은 사실·선택을 반복하고, 시범은 NPC 비품/미리보기로만 수행한다. 사용자 소유물 소비·선택 확정·기여 발급을 시범으로 대신하지 않는다.
- 중단은 확정 상태와 미결정을 구분한다. 재개 대사는 현재 권한·물건·NPC 예약을 다시 확인한 뒤 말한다. 공유 장면에서의 개인 지원은 자막·개인 안내·별도 리허설로 제공하며 한 사람의 망설임 때문에 다른 참여자의 몸체·계획·회차를 멈추지 않는다. 공용 계획 변경에는 [NPC 공동 행동 계약](싱크타운_NPC자율생활_설계_20261008.md)의 해당 참여자 동의가 먼저다.
- 표의 재개 대사는 **그 선택과 단계가 실제로 확정된 사례의 문구**다. Town이 저장한 `선택 갈래 / 실제 대상 / 완료한 행동 / 미결정 행동`에 맞는 검수 문구를 고른다. 예를 들어 T02가 마주 보는 배치라면 “의자는 밖을 보고 있어요”를 쓰지 않고 “의자는 서로 보고 있어요”를 쓴다. 대상이 사라졌거나 판본이 충돌하면 “자리가 바뀌었어요. 지금 가능한 곳을 다시 볼까요?”로 전환한다. 대응 원고가 없으면 사실을 추측해 조합하지 않고 “하던 일을 확인했어요. 여기서 이어 볼까요?”와 현재 확인된 선택 목록만 제시한다.
- 아래 장면은 모두 언어 정답·연습 완료 없이 끝난다. 표현의 난도·시범 횟수·쉬는 시간에 생활 보상 차등을 두지 않는다. 실제 자연 대화의 언어 근거는 [대화 설계](../대화_설계.md)의 검증 범위에서만 별도로 관측한다.

### 16-2. T01 · 같이 말할 때와 같이 조용할 때

|---|---|---|
| 짧게 | “같이 쉴까요?” → 수락 뒤 “이야기할까요?” / “조용히 있을까요?” | 공방 주인이 마주 보는 두 자리와 나란한 두 자리를 하나씩 보여 준다. 선택 전 앉지 않고 플레이어가 먼저 자기 자리를 정한다 |
| 넓게 | “차를 마시며 오늘 만든 모양을 볼 수도 있고, 나란히 앉아 각자 읽어도 좋아요. 오늘은 어떻게 쉬고 싶어요?” | 작업 모양과 읽을거리를 각각 자기 받침에 올려 비교한다. 사용자가 고른 쪽만 꺼내고 다른 것은 정리한다 |
| 망설임 | “두 자리부터 볼까요? 앉는 건 나중에 정해도 돼요.” | 두 위치를 보는 동안 통로 밖에 대기한다. 선택 표시가 없으면 어느 자리도 플레이어 몫으로 확정하지 않는다 |
| 오해 확인 | 사용자가 “같이, 말은 말고요.”라고 뜻을 분명히 하면 “함께 조용히 쉬고 싶은 거군요. 옆에 앉을게요.” | 이야기 물건을 펼치기 전 멈추고 나란한 자리로 미리보기를 바꾼다. 이미 확정한 자리 변경이면 먼저 동의를 받는다 |
| 능숙한 제안 | “먼저 그림을 보고, 그다음 조용히 있을까요?” → “좋아요. 그림은 여기 두고, 다 보면 읽을거리를 꺼낼게요.” | 사용자가 `[이제 조용히]`를 고르는 경계에서 그림을 접고 읽을거리를 펼친다. 시간 경과만으로 사용자의 감상을 끝내지 않는다 |
| 다시·시범 | “이쪽은 서로 보며 앉아요. 저쪽은 같은 곳을 봐요.” | 요청한 자리 하나에만 잠시 앉아 시선을 보여 준 뒤 비킨다. 시범 착석은 함께 쉰 사건이 아니다 |
| 휴식·거절·재개 | 휴식 “여기서 천천히 쉬어요.” / 혼자 “알겠어요. 저는 저쪽에서 쉴게요.” / 재개 “창가 자리를 골랐어요. 같이 앉을까요, 자리를 바꿀까요?” | 조용히 선택에는 추가 사연을 중단한다. 나가면 자리 점유를 풀고, 재개 시 현 좌석을 다시 확보한다. 철거됐다면 “그 자리는 옮겨졌네요. 여기와 저기 중 어디가 좋을까요?” |

**생활 역할 차이:** 첫 시범은 주인이 물건 두 개를 놓고 나는 자리를 정한다. 한 부분 맡기에서는 나는 읽을거리를 놓고 주인은 자기 컵만 정리한다. 내가 기획하면 나는 두 사람의 방향·시작 활동·전환을 정하고 주인은 정한 순서를 따른다. 친한 사이여도 조용히 있기를 대화 부족으로 해석하지 않는다.

### 16-3. T02 · 내가 돌린 의자를 실제로 써 보기

| 상황 | 실제 주민 대사 | 눈앞에서 하는 행동·사용자 결정 |
|---|---|---|
| 짧게 | “밖을 볼까요?” / “서로 볼까요?” → 선택 뒤 “여기 앉아 볼까요?” | 공방 주인이 바깥쪽/마주 보는 방향을 한 번씩 미리 보여 주고, 사용자가 배치를 확정한 뒤 시험 이용 수락을 받는다 |
| 넓게 | “밖으로 돌리면 잎이 잘 보이고, 마주 놓으면 가운데 카드를 함께 볼 수 있어요. 먼저 어느 쪽을 시험할까요?” | 같은 기본 의자 한 개의 방향을 미리 본다. 두 명 시험을 수락했을 때만 별도 예약한 NPC 시험 의자를 놓는다. 확정 전에는 기존 배치가 그대로 남는다 |
| 망설임 | “둘 다 미리 볼 수 있어요. 지금 자리도 그대로 쓸 수 있고요.” | 사용자 요청에 따라 미리보기만 전환한다. 현재 배치를 낮은 평가로 표시하지 않는다 |
| 오해 확인 | “의자를 더 놓는 게 아니라, 이 의자만 돌리는 거예요. 돌려 볼까요?” | 같은 `objectId`에 회전 표시를 보여 주고 확인을 기다린다. 새 물건 구매·제작을 시작하지 않는다 |
| 능숙한 제안 | “먼저 앉아 보고, 컵은 나중에 놓을게요.” → “좋아요. 먼저 앉아 볼게요. 컵 자리는 비워 둘게요.” | NPC는 시험 착석만 하고 장식 배치를 건드리지 않는다. 사용자가 `[이제 컵 놓기]`를 고르면 자리에서 비켜 준다 |
| 다시·시범 | “이 길로 와서, 이쪽으로 앉아요.” | 실제 진입 경로를 한 번 걸어 본다. 막히면 그 지점에서 멈추고 “여기가 좁아요. 의자를 이쪽으로 옮겨 볼까요?”라며 유효 미리보기 한 곳을 제시한다 |
| 휴식·거절·재개 | 휴식 “놓은 건 그대로 둘게요.” / 거절 “혼자 써 보세요. 저는 작업대로 갈게요.” / 재개 “의자는 밖을 보고 있어요. 컵부터 놓을까요, 앉아 볼까요?” | 시험 이용 거절이면 NPC가 떠난다. 미확정 미리보기는 닫고 확정 배치만 유지한다. 재개 때 NPC는 새 시험 초대 전 들어오지 않는다 |

**생활 역할 차이:** 시범에서는 NPC가 진입 경로를 보여 준다. 한 부분 맡기에서는 사용자가 배치하고 NPC가 지정 물건만 시험한다. 기획에서는 사용자가 `앉기→카드 보기→나가기`의 시험 순서를 정한다. 어느 경우에도 NPC의 사용 완료가 사용자의 배치 확정을 대신하지 않는다.

### 16-4. T03 · 두 주민이 다른 방식으로 같은 발견을 소개하기

| 상황 | 실제 주민 대사 | 눈앞에서 하는 행동·사용자 결정 |
|---|---|---|
| 짧게 | 공방 “그림부터 볼까요?” / 연구원 “먼저 물어볼까요?” | 동시에 묻지 않는다. 공방이 그림을 펼친 뒤 비키고 연구원이 질문 카드 두 장을 놓는다. 사용자가 그림/질문 방식과 첫 대상을 정한다 |
| 넓게 | 연구원 “그림을 먼저 보면 모양을 알기 쉬워요. 질문부터 받으면 궁금한 것을 바로 볼 수 있고요. 오늘 모임은 어떻게 열까요?” | 이유를 말할 때 각각의 실제 자료를 가리킨다. 공방은 선택 후 받침을 세우거나 비교 물건을 가져온다 |
| 망설임 | “첫 장면만 둘 다 볼까요? 모임은 아직 시작하지 않을게요.” | 그림 한 장 보기와 질문 한 개 듣기를 별도 시범으로 보여 준다. 본 시범을 본편 완료·새 회차로 세지 않는다 |
| 오해 확인 | 사용자가 “그림도 질문도 보고 싶어요.”라고 확인하면 “그림으로 시작하고, 질문도 받을까요?” | 처음에 선택하는 것은 모임 방식임을 짚는다. 두 경로 모두 질문·그림을 배제하지 않되, 첫 물건과 주도 역할은 선택한 방식으로 유지한다 |
| 능숙한 제안 | “그림 두 장을 먼저 보고, 마지막에 질문해요.” → 공방 “첫 두 장은 제가 놓을게요.” / 연구원 “저는 마지막에 질문을 받을게요.” | 두 주민이 같은 확인 계획을 보고 순서대로 이동한다. 준비되지 않은 세 번째 전시물은 발명하지 않는다 |
| 다시·시범 | “그림 보기.” → 그림 앞으로 이동 / “궁금한 것 묻기.” → 연구원이 질문 카드 옆 대기 | 요청한 부분을 한 주민이 설명하고 다른 주민은 말을 멈춘다. 준비된 질문을 고르거나 말하지 않고 보는 선택도 남긴다 |
| 휴식·거절·재개 | 휴식 “다음 그림은 조금 뒤에 볼게요.” / 불참 “저희끼리 먼저 펼쳐 볼게요. 보고 싶으면 말해 주세요.” / 재개 “첫 그림까지 봤어요. 다음 그림을 볼까요?” | 개인 회차는 다음 선택 앞에서 정지한다. 불참 시 NPC 기본 장면만 이어지고 사용자 후속 선택은 확정하지 않는다. 공유 회차는 개인 이탈로 중지하지 않는다 |

**생활 역할 차이:** 시범에서는 두 주민이 차례·대상을 보여 준다. 한 부분 맡기에서는 사용자가 첫 카드만 정하고 NPC가 합의한 나머지를 맡는다. 기획에서는 사용자가 전체 준비된 카드 순서·역할을 정한다. 관계 후속은 실제 본 회차·선택·기여만 연결한다.

### 16-5. T04 · 같은 조건에 맞는 두 잔을 다른 방식으로 내기

이 대표 요청은 **따뜻함 + 너무 달지 않음**이다. A의 향이 약한 차와 B의 덜 단 과일차는 둘 다 이 조건을 충족하는 검수 메뉴로 편성한다. 하나를 일부러 틀린 답으로 만들지 않는다. `stablePreference`와 오늘 요청을 섞지 않는다.

| 상황 | 실제 주민 대사 | 눈앞에서 하는 행동·사용자 결정 |
|---|---|---|
| 짧게 | 손님 “따뜻한 차가 좋아요.” → 확인 뒤 “많이 달지 않으면 좋아요.” | 찻집 주인은 온도·단맛 견본을 하나씩 보여 준다. 두 유효 메뉴는 같은 크기의 선택으로 남긴다 |
| 넓게 | 손님 “오늘은 따뜻한 걸 마시고 싶어요. 너무 달지만 않으면 향이 약한 차도, 과일차도 좋아요.” | 손님은 메뉴를 바로 가져가지 않고 사용자의 추천·자리 지정을 기다린다. A는 읽을거리를, B는 비교용 향 견본을 펼친다 |
| 망설임 | 주인 “견본부터 봐도 돼요. 손님께 한 번 더 물어볼까요?” | 본 음식을 소비하지 않는 설명용 견본만 연다. 손님은 대기 자리로 이동하고 불쾌·시간 초과 반응을 하지 않는다 |
| 오해 확인 | 차가운 메뉴 미리보기와 의도가 확인되면 손님 “오늘은 따뜻한 걸 원해요. 이 두 잔은 따뜻하게 준비할 수 있어요.” | 제공 전 온도 속성을 다시 보여 준다. 미리보기 취소는 재고를 줄이지 않는다. 이미 전달된 몫을 무료 반복 제공으로 되돌리지는 않는다 |
| 능숙한 제안 | “먼저 향을 보고, 조용한 자리에서 마셔요.” → 손님 “좋아요. 향을 본 뒤 저쪽에 앉을게요.” / 주인 “저는 잔을 준비할게요.” | 사용자가 소개하고 주인은 준비만 한다. 설명이 끝났다고 사용자가 신호하면 손님이 고른 자리로 이동한다 |
| 다시·시범 | 손님 “따뜻하게요. 덜 달게요.” / 주인 “저는 잔을 놓을게요. 메뉴와 자리는 골라 주세요.” | 요청만 짧게 반복한다. 시범은 빈 시연 잔으로 하며 실제 한 몫 제공은 사용자가 메뉴·제공을 확정한 뒤 한다 |
| 휴식·거절·재개 | 휴식 “제공 전이니 잠깐 쉬어도 돼요.” / 거절 “오늘은 손님으로 쉬세요. 주문은 제가 받을게요.” / 재개 “차는 골랐고, 아직 드리지 않았어요. 이 자리에 낼까요?” | NPC 기본 서비스와 사용자 몫 제공을 분리한다. 재개 시 실제 이미 제공했다면 “차는 전해 드렸어요. 손님을 배웅할까요?”로 바꿔 중복 소비를 막는다 |

**생활 역할 차이:** 시범은 온도·단맛을 한 항목씩 확인한다. 한 부분 맡기에서는 사용자가 추천만 맡고 주인이 준비한다. 기획에서는 사용자가 소개→자리 이동→제공 순서를 정한다. 짧은 말로 이 전체 순서를 정해도 손님은 동일하게 따른다.

<a id="support-T05"></a>
### 16-6. T05 · 기억하는 주민이 내 일을 거들기

대표 제안자는 공방 주인이다. 아래 표의 **“받침을 같이 놓았지요”는 해당 공방 주인이 참여·인지한 실제 받침 공동 배치 사건이 있을 때만** 쓴다. FT10의 차양 제작 사건만 있으면 도입을 “지난번에 차양을 함께 만들었지요”, 실제 자리 공동 조율 사건이면 “지난번에 자리를 같이 정했지요”로 바꾼다. 원인 사건·행동·참여 주민이 어느 도입에도 맞지 않으면 이 감사 제안을 열지 않는다. 찻집 주인·연구원 변형은 §7의 각자 가능한 비품·일로 치환하고 다른 주민의 비공개 사건을 인용하지 않는다.

| 상황 | 실제 주민 대사 | 눈앞에서 하는 행동·사용자 결정 |
|---|---|---|
| 짧게 | “지난번에 받침을 같이 놓았지요.” → “오늘은 제가 도울까요?” → 수락 뒤 “받침을 잡을까요?” / “쉴 자리를 준비할까요?” | 승인된 지지 동작을 짧게 보여 주거나 자기 읽을거리 받침을 가리킨다. 사용자의 물건을 임의로 옮기지 않는다 |
| 넓게 | “지난번에 받침을 같이 놓았지요. 오늘은 제가 받침을 고정해 드릴 수도 있고, 쉬는 동안 제 비품으로 읽을 자리를 준비할 수도 있어요. 어떤 도움이 좋을까요?” | 도입은 위 원인 사건별 문구로 고른다. 두 도움의 물건·허용 자리를 먼저 보여 주고 실제 가능한 A/B를 확인한 뒤 제안한다 |
| 망설임 | “도움이 필요한 부분만 골라도 돼요. 지금 안 받아도 괜찮고요.” | 도구를 내려놓고 작업 범위 밖으로 물러난다. 감사를 요구하거나 보답 기한을 만들지 않는다 |
| 오해 확인 | 사용자가 “전부 해 준다는 거예요?”라고 물으면 “방향은 직접 골라 주세요. 저는 받침이 움직이지 않게 도울게요.” | NPC 역할과 사용자 마지막 선택을 각각 표시하고, NPC는 지지 위치에만 선다 |
| 능숙한 제안 | “제가 방향을 정할 때만 고정해 주세요.” → “알겠어요. 시작할 때 알려 주세요. 방향을 정하면 비킬게요.” | 시작 신호 뒤 고정, 사용자 확정 뒤 해제한다. 사용자 작업을 앞질러 완료하지 않는다 |
| 다시·시범 | “저는 받침을 고정해요. 방향은 골라 주세요.” | NPC 비품으로 지지→사용자 방향 선택 자리→해제 세 동작을 보여 준다. 시범을 보답 완료로 기록하지 않는다 |

**생활 역할 차이:** 시범을 원하면 공동 동작을 한 단계씩 한다. 익숙하면 NPC는 합의한 시작/끝 신호만 기다린다. 기획을 원하면 사용자 작업 순서에 보조 구간을 끼워 넣는다. 도움을 적게 받는 것이 관계 성장의 필수 조건은 아니다.

### 16-10. T09 · 두 손님이 서로 다른 것을 궁금해하는 장터

대표 이야기 장터의 첫 손님은 “여기서 맛을 보고 싶어요”, 둘째 손님은 “먼저 어떤 물건인지 보고 싶어요”라고 요청한다. A/B 어느 운영 방식에서도 두 손님을 만날 수 있다. A는 착석·설명 후 구경으로, B는 구경 후 시음 자리 안내로 순서가 달라진다. 이야기 준비분은 판매 재고가 아니다.

| 상황 | 실제 주민 대사 | 눈앞에서 하는 행동·사용자 결정 |
|---|---|---|
| 짧게 | 주인 “앉아서 맛볼까요?” / 공방 “구경하며 고를까요?” → 역할 선택 뒤 “어느 일을 맡을까요?” | A의 좌석과 B의 진열 경로를 각각 보여 준다. 사용자가 방식·맡을 일을 정한 뒤 손님 한 명씩 접근한다 |
| 넓게 | 주인 “앉아서 두 맛을 소개해도 좋고, 먼저 그림과 물건을 둘러본 뒤 차를 권해도 좋아요. 저는 준비를 맡을까요, 손님 안내를 맡을까요?” | NPC는 합의한 한 역할만 맡고 사용자 역할을 남긴다. 두 요청을 한꺼번에 띄우지 않고 현재 손님 뒤에 실제 대기 자리를 둔다 |
| 망설임 | 손님 “먼저 구경하고 있을게요. 준비되면 알려 주세요.” | 현 허용 구경 경로를 걷거나 자리에 앉는다. 주문 타이머·줄 이탈 벌점·불만 표정을 만들지 않는다 |
| 오해 확인 | 둘째 손님에게 즉시 제공하려 하면 “지금은 물건 설명부터 듣고 싶어요. 이건 어디에 쓰나요?” | 실제 인도 전 확인하고 소비를 멈춘다. 주문·소개·인도가 서로 다른 사실임을 유지한다 |
| 능숙한 제안 | “제가 소개할게요. 앉고 싶은 손님을 안내해 주세요.” → 주인 “좋아요. 설명을 다 들은 손님부터 자리로 모실게요.” | 주인은 소개 중인 손님을 끌고 가지 않고 사용자 완료 신호 뒤 동선을 바꾼다. 공방은 확정된 진열만 유지한다 |
| 다시·시범 | 첫 손님 “여기서 맛보고 싶어요.” / 둘째 손님 “먼저 구경하고 싶어요.” | 요청한 손님만 다시 말한다. NPC의 안내 시범은 자리 이동만 하고 실제 제공·판매·정산을 확정하지 않는다 |
| 휴식·거절·재개 | 휴식 “새 손님은 잠깐 받지 않을게요.” / 종료 “여기까지 열고 정리할까요?” / 재개 “첫 손님에게는 전했어요. 두 번째 손님은 설명을 기다리고 있어요.” | 중단 경계에서 신규 주문을 닫고 이미 인도한 사실·정산을 보존한다. 품절이면 “이건 지금 없어요. 전시만 보거나 다른 가판을 볼까요?”로 전환하고 무료 재입고하지 않는다 |

**생활 역할 차이:** 시범은 한 손님·한 요청·한 제공을 나눠 본다. 한 부분 맡기에서는 소개 또는 준비만 직접 한다. 기획에서는 사용자가 진열·입장·역할을 정한다. 긴 한국어·매출·빠른 처리로 운영권이나 주민의 애정을 차등 지급하지 않는다.

| 짧게 | 공방 “여기서 쉴까요?” / 연구원 “함께 그림을 볼까요?” | 현재 허용 구역의 두 쓰임을 각각 시험한다. 차양 자리에서는 주인이 앉고, 전시 자리에서는 연구원이 자료 앞에 선다 |

| 망설임 | “오늘은 두 모습만 봐도 돼요. 지금 자리 그대로 두어도 괜찮아요.” | 기본 서비스를 계속 쓰게 두고 자원·설치를 확정하지 않는다. 결정을 안 했다고 공간을 비워 버리지 않는다 |
| 오해 확인 | “마을 전체를 바꾸는 건가요?” → 개인 범위이면 “지금은 이 개인 장면의 자리만 바꿔요. 함께 쓰는 광장은 그대로예요.” | 변경 범위를 눈앞 경계와 미리보기로 보여 준다. 공유 프로젝트라면 변경권·동의가 확인되기 전 확정하지 않는다 |
| 능숙한 제안 | “전시는 안쪽에 놓고, 입구는 비워 주세요.” → 연구원 “자료는 안쪽에 놓을게요.” / 공방 “저는 입구 길부터 시험할게요.” | 현재 준비된 전시 갈래 안의 배치 제안으로 확인한다. NPC 둘이 안쪽 전시·입구 통과를 실제 수행하고 사용자의 최종 확정을 기다린다 |
| 다시·시범 | “여기는 쉬는 자리예요. 여기는 그림 보는 자리예요.” | 선택한 후보를 한 번 실제 이용한다. 철거·설치 비용을 시범에 쓰지 않고 기존 상태로 돌아온다 |
| 휴식·거절·재개 | 휴식 “설치는 여기서 멈추고 도구를 치울게요.” / 유지 “좋아요. 지금 자리로 계속 써요.” / 재개 “받침은 놓았고, 전시 방향은 아직 안 정했어요.” | 개인 프로젝트는 확정 단계만 보존한다. 사용 시험 뒤 확정되면 A는 쉬는 경로, B는 관람 경로를 실제 다음 계획에 연결한다. 철거되면 옛 경로 대신 기본 실내/쉼터로 이동한다 |

**생활 역할 차이:** 시범은 두 기능의 사용 차이를 본다. 한 부분 맡기에서는 사용자가 용도·마지막 배치를 정하고 주민이 승인 보조를 한다. 기획에서는 사용자가 처음부터 허용된 도구·동선·분담을 정한다. NPC가 제안을 이해한 것과 세계 변경 명령이 승인된 것은 별도다.
