# 솔리오 사업계획서 검토 화면 새 시안

솔리오 사무실 기획부의 「사업계획서」 작업 화면을 다시 그린 시안이다. 유호님이 11-26에 흰 종이를 뺀 초안을 보시고 「전보다는 확실히 좋아졌는데 조금 더 트렌디하고 세련되고 기능적으로 간편했으면 좋겠어. 아직 조잡함이 꽤 남아있네」라고 하셨다.

- 원고: [검토화면.html](검토화면.html). 누르면 실제로 동작한다.
- 올린 것: [아티팩트](https://claude.ai/artifact/5wanXxQ95qetFqBajKp4ac). `node 아티팩트판.cjs <나갈 파일>`로 굽는다.
- 앱에는 옮기지 않았다.

## 계획서가 없을 때: 직접 쓰기(11-26 더함)

유호님 11-26 「만약에 사업계획서 없으면 직접 작성하는 칸이 있어야할것같아」, 「부족한부분은 … "사업계획서 작성 및 평가 기능" 세션에서 가져오면 돼」. 그 세션의 [쓰기 시안](../솔리오_사업계획서_첫화면_20261123/README.md)에서 일곱 물음과 솔리오의 안내를 가져와 이 시안의 「한 번에 하나」 짜임에 맞췄다.

- 놓는 자리 아래 「계획서가 아직 없으면 · 직접 쓰기」. 쓰다 나가면 「쓰던 계획서가 있습니다 · 이어서 쓰기 n / 7」로 바뀐다.
- 쓰는 화면은 물음 하나와 쓰는 칸 하나다. 위에 일곱 막대, 장 이름, 큰 물음이 있다. 칸 위에서 솔리오가 그 장이 왜 필요한지 해요체로 말한다. 숫자가 필요한 장(1 · 3 · 5 · 7)에 숫자가 없으면 「숫자를 하나 넣으면 훨씬 잘 믿어요」라고 한다. 예시는 칸 안의 흐린 글이다.
- 「다음」(Ctrl+Enter), 「이 장 건너뛰기」(막대가 점선으로 남는다), 「나중에 쓰기」(쓴 데까지 저장).
- 다 쓰면 「사업계획서 초안이 생겼습니다」. 놓는 자리에 `사업계획서_초안.docx`가 들어가고, 아래에 일곱 장의 첫 문장과 「고치기 · 채우기」가 있다. 「읽기」를 누르면 파일을 놓았을 때와 같은 검토로 이어진다.
- 직접 쓴 초안의 검토는 쓴 글 그대로 본다. 비운 장은 「○○이 비어 있어요」로 묻는다. 회사 자료가 있으면 그 자료로 채운 문장을 「이렇게 채우기」로 내고, 없으면 「직접 쓰기」로 그 자리에 쓴다. 회사 자료가 없으면 자료와 맞춰 보는 메모는 나오지 않는다.
- 심사위원 셋의 점수와 심사 무대는 가져오지 않았다. 화면 하나가 더 늘어나서 넣을지 여쭙는다.

## 짓기 전에 적은 것

1. **한 문장:** 파일을 놓으면 직원이 고칠 곳을 한 번에 하나씩 묻는다.
2. **강조 순위**
   - 놓기: 책상 위의 구, 맨 위 한 문장, 놓는 자리. 평가 기준과 직원은 놓는 자리 안의 알약으로 물러선다.
   - 고칠 곳: 지금 고칠 문장, 구가 하는 말, 「이렇게 고치기」. 앞뒤 문장은 흐리게 물러선다.
   - 끝: 고친 수, 저장.
3. **참고**

| 참고 | 가져온 것 |
|---|---|
| [솔리오 첫 팀 고르기](../솔리오_첫계정고르기_20261121/README.md)(유호님 「너무 훌륭해 깔끔하다」) | 검정 방, 구운 장면 한 장과 문장 하나 |
| [사업계획서 쓰기 시안](../솔리오_사업계획서_첫화면_20261123/README.md)(「프론트 느낌은 깔끔하고 좋은데」, 흰 종이 뺌) | 책상 장면 그림, 구의 눈, 마스코트만 해요체 |
| [참고 사이트 장부](../참고사이트/README.md) Attio · 채널톡 | 할 일을 한 칸에 모은 입력 자리 |
| 장부 Linear · Superhuman | 바뀐 것만 하나씩 보는 검토, 자판으로 넘기기 |
| 장부 Recent 「Agent Status」 · 「Liquid Stepper」 | 진행 상태를 글 하나로, 단계는 가는 막대로 |

4. **움직임마다 알게 되는 것**

| 움직임 | 알게 되는 것 |
|---|---|
| 구의 눈이 마우스와 파일을 본다 | 여기에 놓으면 된다 |
| 읽는 동안 눈이 종이를 좌우로 본다, 막대가 찬다 | 어디까지 읽었는지 |
| 고치면 문장이 흐려졌다가 새 문장으로 바뀐다 | 무엇이 어떻게 바뀌었는지 |
| 막대 한 칸이 초록으로 찬다 | 몇 곳이 남았는지 |

## 앱에 옮길 때 정할 것

- 직원의 말을 해요체 한 문장으로 받으려면 지시문을 고쳐야 한다. 지금 AI는 합니다체로 답한다.
- 한도가 풀리는 때(11월 30일 저녁 7시)는 Claude가 보내는 한도 글에서 읽어야 한다. 「GPT로 읽기」는 직원 고르기를 바꿔 다시 읽는 것이다.
- 읽는 중의 막대는 지금 앱이 아는 만큼(묶음 몇 번째)만 찬다.
- 「같이 쓰기」의 물음은 앱에서 항목마다 여럿일 수 있다. 시안은 하나씩 물었다.
- 예시 계획서와 메모는 11-23 시험 계획서와 그때 GPT 직원이 낸 것이다. 11-26에 쓰기의 일곱 장에 맞춰 나눴고, 빈 장의 장 이름과 비즈니스 모델 문장은 더했다. 구의 말은 다듬었다.
- 쓰기 안내는 쓰기 시안의 말을 줄인 것이다. 쓰기 시안은 「심사위원」이 읽는다고 하고, 이 시안은 「직원」이 읽는다고 한다. 앱에서는 쓰기와 검토가 한 기능이므로 한 말로 맞춘다.
- 빈 장을 회사 자료로 채우는 문장은 지금 앱의 메모에 없는 일이다. 지시문에 「빈 장은 회사 자료에 있는 값으로만 채운다」를 더해야 한다.
