# 싱크타운 생활 경제와 상품 설계

2026-10-02. 사용자의 전체 설계·원고 작성 요청에 따른 **제작·검증안**이다. 무료 체험+정액제+선택 상품이라는 구조는 기존 결정이며, 이 문서의 새 수량·속도·가격·정산 한도는 시험할 출발값이다. 출시 가격·청구 정책·실제 결제·운영 수익성을 확정하거나 런타임을 구현한 기록이 아니다.

[첫 생활 구간](싱크타운_첫생활구간_설계.md#scope), [재료와 첫 레시피](싱크타운_첫생활구간_설계.md#materials), [BM-10](../BM_목록.md#synk-town-bm), [사건·소유·저장 계약](../아틀라스_구현명세.md#town-world-contract)을 이어 쓴다. 첫 챕터의 유한 준비와 그다음 반복 운영을 구분하고, 이미 지급한 재료·성과를 새 경제로 중복 지급하지 않는다.

## 1 플레이와 경제의 경계

- 네 입구 중 하나만 골라도 완결한다. 무료 첫 챕터에는 생활 제작·메뉴·발견·주민 사연을 **모두** 열되 전부 할 의무는 없다. 각 경로의 첫 결과, 다음 방문의 기억, 재료 없는 후속 하나까지 포함한다.
- 첫 준비물과 언어 도움, 기본 접근성, 핵심 결과 관람을 별도 구매 조건으로 만들지 않는다. TOPIK 1급+ 통과를 결제·재화로 대신하지 않는다.
- 이후의 반복 운영은 선택이다. 납품을 쉬거나 돈을 쓰지 않아도 집·레시피·기념·관계가 무너지지 않는다. NPC는 기본 생활을 계속한다.
- 채집·재배를 하지 않아도 주민 돕기·관찰·재료 구입으로 원하는 활동을 고를 수 있다. 돈을 얻으려고 모든 경로를 순회할 필요는 없다.
- 실제 돈, 생활 재화, 학습 근거를 분리한다. 보유 재화·가게 매출·작물 수량이 TOPIK 급수·호감·언어 난도를 올리지 않는다.

## 2 생활 코인의 역할 — 새 검증 단위

내부 계산에는 **생활 코인 C**를 쓴다. 학생 화면에는 ‘마을에서 모아 쓰는 돈’이라고 설명하고, 미니게임 잔액과 구별할 수 있도록 **‘타운 생활 코인’**으로 표시하는 안을 쓴다. 이름과 그림은 출시 전 브랜드 검수 대상이다. 옛 숙제 포인트·옷 가게의 보류된 동전을 복구하는 결정이 아니다.

**2026-10-08 현행 미니게임과의 경계:** [플랫폼 계정 정본](../SYNK_플랫폼_계정과_연결_설계.md)의 콘텐츠별 재화 원칙을 따른다. 한 로그인은 재화 통합이 아니다. 현재 [미니게임 공통 코인](../../experiences/play-common/README.md)은 같은 브라우저 출처의 로컬 컬렉션이며 개인 계정·다른 기기 동기화 지갑이 아니다. 이 문서의 Town 코인은 계정 원장으로 구현할 설계안이다. 두 잔액을 자동 합산·교환·이관하지 않고, 현행 미니게임 완주 코인을 Town 재료비나 상품 권한으로 읽지 않는다. 지갑 화면에는 획득처·사용처·저장 범위를 함께 적으며, 계정 연결만으로 기존 로컬 잔액의 주인을 확정하지 않는다.

| 구분 | 정하는 규칙 |
|---|---|
| 획득 | 반복 생활 의뢰의 확정 정산. 접속·광고 시청·연속 출석·한국어 정답률로 지급하지 않음 |
| 사용 | 운영 재료와 플레이로 얻는 기본 꾸밈. 첫 이야기의 필수 재료·도움은 코인이 없어도 제공 |
| 실제 돈과 관계 | 코인 충전·현금 환전·유료 외형과 교환·다른 플레이어에게 송금하지 않음 |
| 개인과 공유 | 계정의 개인 잔액. 마을 이동·기기 변경·구독 갱신으로 초기화하지 않음. C08 공동 기여는 허용된 물건과 별도 사건으로 처리 |
| 첫 운영 준비금 | 반복 운영 팩을 처음 열 때 20C를 한 번 지급. 재구독·재설치·경로 변경으로 재지급하지 않음 |
| 잔액 부족 | 재료 없는 주민/관찰 의뢰, 첫 이야기의 한정 준비물, 소유 공간 이용을 안내. 돈을 빌려 음수가 되거나 실제 돈을 요구하지 않음 |
| 원장 | 지급·구매·예약·소모·산출·정산을 원인 ID와 연결. 클라이언트의 잔액 주장이나 화면 재생으로 지급하지 않음 |

개인 재화 수치는 필요한 구매·제작 화면에서만 보여 준다. 친구의 잔액·수입 순위·부유함 배지를 만들지 않는다. NPC가 코인 부족을 조롱하거나 상품을 권하지 않는다.

## 3 공급표와 유한한 첫 준비

### 첫 무료 챕터 — 기존 값 보존

| 준비물/생산 | 수량과 조건 | 판매·반복 제한 |
|---|---|---|
| 개인 화단·물뿌리개·공방 도구 | 최초 한 번, 내구도/수리비 없음 | 도구를 재료나 코인으로 환전하지 않음 |
| 딸기 모종·바로 쓸 딸기 | 모종 1개+딸기 1묶음 | 모종에서 첫 수확 1묶음. 제공/재배 출처를 구분 |
| 첫 작물 | 심은 뒤 120초, 물 주기 한 번은 남은 시간 최대 30초 단축 | 이미 지난 시간보다 앞서 완료시키지 않음. 미접속 중 성장, 시듦/손실 없음. 한 모종에서 한 번 수확 |
| 목재·천 | 손질 목재 2개+천 1개 | 차양 한 세트 또는 보관. 기존 좌석 이동은 소모 없음 |
| 기본 조리분 | 최초 제공 딸기와 최초 수확분을 쓰는 **두 제작분까지만** | 차/잼 한 제작분은 2인분. 선택 변경·시식 다시 보기로 조리분 재생성 금지 |
| 관찰 지점·화분 | 개인 표본 1개 또는 관찰 기록. 첫 전시 보답 화분 1개 | 표본·관찰 카드·보답 화분은 별개. 관찰/표본 양쪽에 같은 보답, 반환/재채집으로 재지급 금지 |

첫 지원물·그 산출물은 재판매·플레이어 거래에 쓰지 않는다. 보유·미사용·이미 소비한 몫을 계정에서 확인한 뒤 남은 권리만 이어 준다. 첫 챕터 종료와 구독 갱신은 지급 초기화가 아니다. 차/잼 두 제작분을 다 써도 첫 메뉴·기념·재료 없는 후속을 누릴 수 있다.

### 구독의 반복 운영 팩 — 검증값

| 재료 | 구입값 | 다른 공급 경로 | 반복·시간 기준 |
|---|---:|---|---|
| 딸기 1묶음 | 3C | 모종 1개를 2C에 구입해 재배 | 운영 모종은 10분 뒤 1묶음. 물 주기 한 번은 남은 시간 최대 2분 단축. 첫 무료 작물의 120초 규칙과 별도 |
| 손질 목재 1개 | 2C | 산책의 개인 채집 지점 | 자연 공급은 아래 보관형 몫 안에서만 발생. 사유 시설·이웃 물건을 채집하지 않음 |
| 천 1개 | 2C | 신규 이야기의 한정 준비물 | 이야기 지원 천은 이야기용이며 판매용 제작과 구분 |
| 조리 기본분 1회 | 1C | 첫 챕터의 한정 두 제작분 | 반복 운영의 우유/물·빵·기본 용기 등을 묶은 게임 단위. 실제 식품 원가의 주장 아님 |
| 빈 화분 1개 | 1C | 첫 전시 보답은 완성 화분으로 별도 | 구입분을 사용한 화분 제작과 보답을 혼합하지 않음 |
| 꽃 소재 1개 | 3C | 산책의 개인 채집 지점 | 위치·종류가 준비된 소재만 공급. 실제 희귀 식물 채집 지식으로 안내하지 않음 |

운영 화단은 기본 3칸이다. 심기마다 모종 1개를 소비하고 작물은 한 번만 수확한다. 다 자란 작물은 기다리며 시들지 않는다. 동시에 3칸만 자라므로 오프라인이 길어져도 한 번에 3묶음을 넘겨 만들어 내지 않는다. 새로운 모종은 본인이 심을 때만 소비한다. 재배를 싫어하면 같은 재료를 바로 구입할 수 있다.

개인 채집의 자연 공급은 **정액 권한이 있는 7일당 목재 2개+꽃 소재 1개**를 보관형 몫으로 준비한다. 최초 운영 개방에 같은 한 묶음을 주고, 미사용 몫은 최대 두 묶음까지 보관한다. 실제 대상에서 채집할 때만 인벤토리로 옮긴다. 자정 출석·먼저 접속한 사람·다른 계정의 채집과 무관하다. 가득 찬 동안 새 몫을 쌓지 않으며 미수령 경고·소멸 푸시를 보내지 않는다. 무료 첫 표본 지점과 이 반복 공급 지점을 구분한다.

공급 주기는 계정별 운영 시작과 누적 정액 유효 시간을 기준으로 서버가 계산한다. 만료 중에는 새 몫을 쌓지 않고 남은 몫을 보존한다. 재구독은 첫 몫이나 주기 기준을 새로 만들지 않는다. 현금 결제로 성장 시간·화단 수·채집 몫을 늘리는 상품은 이 판에 넣지 않는다.

## 4 제작·판매·기본 영업

### 반복 레시피와 재료 출처

| 제작물 | 입력 | 산출 | 사용처 |
|---|---|---|---|
| 차/잼 곁들임 한 묶음 | 딸기 1묶음+조리 기본분 1회 | 2인분 | 직접 시식·선물·정해진 판매 의뢰 중 선택 |
| 작은 받침 | 목재 1개+천 1개 | 받침 1개 | 내 공간 배치·주민의 허용 자리·제작 의뢰 |
| 작은 꽃 화분 | 꽃 소재 1개+빈 화분 1개 | 화분 1개 | 내 공간·허용된 선물·제작 의뢰 |
| 첫 차양의 재배치 | 이미 소유한 차양 1개 | 같은 개체의 새 배치 | 새 차양·새 첫 보상이 생기지 않음 |

재료에는 수량과 함께 출처·판매 가능 여부·아직 정산받지 않은 구입 원가를 보관한다. 모종 구입 원가는 해당 첫 수확물에만 옮긴다. 채집 재료의 구입 원가는 0C다. 소비된 입력의 원가는 산출물에 한 번만 옮기며 원재료와 완제품에 동시에 남기지 않는다.

첫 체험/이야기 지원물처럼 판매 금지 입력이 하나라도 들어간 완성물은 판매 금지다. 판매 목적을 고른 화면에서는 판매 가능한 재료만 제안한다. 목적 없이 혼합할 때는 확정 전에 ‘이 재료로 만들면 팔 수 없어요’를 보여 주고 보관·선물 용도로 만들지 직접 고르게 한다. 출처를 지운 뒤 판매하거나 분해·재조합으로 제한을 세탁하지 않는다.

### NPC가 사들이는 범위

첫 운영판은 시장 가격 경쟁 대신 **준비된 소량 주문을 정산하는 방식**이다. NPC 주문의 물건·수량·조건·수령 장소를 먼저 보여 준다. 완료와 동시에 전달한 산출물을 한 번 차감하고 재료비 정산+작업 보상을 한 번 지급한다. 이미 주거나 소비한 물건을 다시 팔지 않는다.

- 구입 원가 정산은 실제로 소비한 판매 가능 입력의 미정산 원가이며, 이 판의 표준 레시피당 최대 4C다. 서버의 구입 기록과 원가 이전 이력을 근거로 한다.
- 작업 보상은 **완료 의뢰당 3C**다. 재료를 직접 기르거나 사 온 경우, 도움을 사용하거나 독립적으로 이해한 경우 모두 같다.
- 재료 없는 주민 돕기·관찰 정리 의뢰도 실제 생활 조건을 수행하면 3C다. 단순 대화 열기·로그인·같은 완료 다시 보기에는 지급하지 않는다.
- 판매 의뢰에는 발급·예약·실제 인도 ID가 있고 플레이어의 거래는 개인 NPC 범위에서 끝난다. 플레이어끼리 거래, 경매·가격 흥정은 이 판에서 열지 않는다.
- 손님이 소비하는 표준 2인분/제작물의 내부 판매값은 8C로 놓고, 플레이어 정산은 최대 7C다. 남는 최소 1C는 NPC 운영 몫이다. 이는 게임 장부 값이며 회사의 실제 매출이 아니다. 상품·계절 가격 변동이나 무한 손님 수요를 만들지 않는다.

예: 구입 딸기 3C+기본분 1C로 만든 음료는 7C를 받아 **순수입 3C**다. 모종 2C+기본분 1C로 만든 음료는 6C를 받아 같은 순수입 3C다. 재배의 보상은 직접 기른 작물이 쓰이는 출처·공간·성취에 있으며 농사를 해야 코인을 더 버는 구조로 만들지 않는다. 목재 채집으로 입력 원가가 줄면 정산액도 줄고 작업 보상은 같다.

### 판매 정산 한도와 일상 이용

반복 운영 첫 개방 때 **정산 가능한 생활 의뢰 16회**를 준비한다. 이후 정액 유효 시간 168시간마다 16회를 채우며 미사용 잔여를 포함한 상한은 32회다. 이 한도를 제작·가게·관찰·주민 돕기가 공동 사용한다. 경로별 순회 보너스·출석 보너스는 없다. 정산 전 예약은 최대 3회이며 취소하면 그 몫을 돌려준다.

이 수치는 유한한 NPC 수요와 재화 발행량을 검증하기 위한 값이다. 화면에는 남은 유료 플레이 횟수처럼 표시하지 않고 주문을 정산하려는 자리에서만 ‘이번에 정산할 수 있는 일’을 안내한다. 이미 발급·예약한 일은 공급 몫이 바뀌어도 사라지지 않는다. 미사용분 소멸을 재촉하지 않는다.

정산 몫이 없어도 소유 공간 이용·꾸미기·산책·검수된 기본 대화·이미 열린 이야기·언어 도움을 막지 않는다. 재료가 있는 자유 제작은 가능하지만 판매 계약 없이 만든 것을 NPC가 무한 매입하지 않는다. 무료 체험과 첫 이야기에는 이 판매 한도를 소비시키지 않는다.

### NPC 기본 운영과 플레이어 영업의 분리

기본 차림표·기본 좌석·기존 영업은 주민의 생활 배경이다. 플레이어가 납품하지 않아도 유지하지만 플레이어 장부에 코인·재료를 지급하지 않는다. 플레이어 메뉴는 자기 재고가 있는 동안만 실제로 제공한다. 품절되면 함께 만든 진열·레시피·기념은 남고 기본 메뉴가 보인다.

기본 영업의 차 한 잔을 플레이어 인벤토리로 무한 회수하지 못하게 한다. 약속된 시식 몫, 구입/제작한 소유물, NPC의 배경 비품을 구분한다. 추가 판매·새 제작은 선택 목록에서 본인이 시작하고 자동 납품 알림을 보내지 않는다.

첫 원고와 재방문 원고에서 사용하는 **이야기 준비분**은 다음과 같이 등록한다. 모두 판매·코인 정산 대상이 아니며, 실제 제공 시 한 번 소비한다. 잔·접시는 NPC 소유 비품으로 회수하고 음식과 별도 개체로 관리한다.

| 원고 | 한정 준비분 | 사용·재생 경계 |
|---|---|---|
| 첫 사연 FT40와 첫 후속 FT54 | 각 사건에 기본 차 2잔, 해당 두 주민용 | FT20의 플레이어 첫 조리분 2회와 별도인 NPC 이야기 준비분. A/B 변경·재접속으로 다시 지급하지 않음 |
| 재방문 RV04 | 음료 1인분+곁들임 1인분 | 기본은 NPC 이야기 준비분. 플레이어 메뉴를 쓰기로 명시 선택한 경우 해당 실제 재고만 예약·소비하고 같은 제공 몫의 NPC 준비분은 사용하지 않음 |
| 재방문 RV05 | 기본 음료 1인분+곁들임 1인분, 플레이어 한 사람용 두 구성의 제공 세트 | 제안 전에 둘 다 확보하며 RV04 손님 몫과 별도다. 선택한 장소에서 함께/차 먼저의 실제 전달 순서를 적용하고 각각의 제공을 한 번 소비한다. 거절/연기는 미사용 몫 보존, 다시 보기로 새 소유 재고를 만들지 않음 |

| 재방문 RV17 | 기본 음료 2인분, 플레이어와 연구원 각 1인분 | 쉼터/허용된 집·역할 A/B 모두 같은 두 제공 몫. 한 잔 전달 뒤 중단하면 남은 한 잔만 재개. 집 초대 철회로 공급·소비 초기화 없음 |
| 주민 연속극 LS02.2 | 책을 보는 손님 향 있는 차 1잔+동행 손님 물 1잔, 합계 2몫 | A/B는 두 잔을 함께 준비/물 먼저 전달 뒤 사용자 신호로 차 전달하는 순서만 다름. 물2잔 뒤 차를 추가하는 3몫이 아님 |
| 주민 연속극 LS02.3 | 기본 시음 음료 최대 2인분 | 조용한 시음/향 비교에서 실제 제공할 선택만 예약. 그림 메뉴 전시로 마치면 제공0. 판매 전환은 이 준비분을 쓰지 않고 별도 유효 판매 의뢰·판매 가능 재고로 처리 |
| 주민 연속극 LS02.4 | 사용자와 함께 쉬는 주인용 기본 음료 최대 2인분 | 역할 교환·각자 쉼에서 실제 수락한 제공만 소비. 제공 없는 역할 관람 대안은 소유 음식·판매 재고를 생성하지 않음 |

준비분의 키는 계정+원고 사건 인스턴스+제공 몫이다. 같은 사건의 장면 ID를 새로 발급해 공급을 반복하지 않는다. 아직 제공하지 않은 몫은 재개할 수 있으며, 이미 완료한 장면의 다시 보기는 과거 기록으로 표시한다. RV04·RV05는 음료와 곁들임을 각각 확인하고, 차만 받은 뒤 중단하면 차를 다시 소비하지 않은 채 남은 곁들임만 재개한다. 종료·자리 변경 때 미제공 몫의 자리 예약은 해제할 수 있지만 같은 사건의 준비분 자체는 보존한다. 이후 일상 영업의 배경 차와 플레이어가 새로 받을 수 있는 소유 음식은 구분한다. 첫 무료 음식의 남은 양은 **제공·시식 가능량**이며 판매 재고로 표시하지 않는다.

LS02.2~.4는 서로 다른 실제 후속 회차를 승인할 때 각각 한 번 `storyAllocationId`를 만든다. 별도 원고 이름·A/B·새 `sceneInstanceId`로 동일 회차를 다시 승인해 몫을 늘리지 않는다. LS/RV/FT가 같은 실제 사건을 참조하면 **정본 `sourceEventId`에 배정된 같은 준비분**을 공유하며 원고 ID별로 이중 발급하지 않는다. 모두 NPC 이야기 준비분이므로 플레이어 인벤토리·포장·판매·재료로 전환할 수 없다. 제공 전 취소는 그 회차의 미사용 배정으로 되돌리고 제공 뒤 취소는 소비 사실을 보존한다. 필요한 준비분을 실제 확보하지 못하면 수락 전에 제공 없는 전시/역할 관람 대안임을 알리고 선택받거나 그 제공 회차를 보류한다. 음식을 받지 않은 장면을 제공 완료로 기록하지 않는다.

## 5 보관·예약·중복 방지

생활 재료·음식 재고·가구·기념·구매 외형을 기존 보관함에서 나눈다. 기본 보관함을 유료로 확장해야 첫 경험이나 이야기 보답을 받는 구조로 만들지 않는다. 첫 지원물·기념·구매 외형은 전용 보관 영역에 남긴다. 반복 소모품의 검증판 상한은 종류·동일 출처별 999개다. 초과 산출이면 제작 확정 전에 알리고 입력을 소비하지 않는다.

같은 재료라도 체험 지원/이야기 지원/구입/운영 채집의 출처와 원가가 다르면 장부에서 합쳐 지우지 않는다. 학생 화면은 총량을 보여 주되 사용하는 화면에 이번 소비분과 판매 가능 여부를 함께 표시한다. 예약분은 다른 제작·판매에 중복 사용하지 못한다.

제작은 입력 예약→현재 revision 검사→소모+산출 확정→표현 순서다. 판매는 주문·실제 인도·산출물 차감+재료비/작업 보상 확정을 한 거래로 처리한다. 작업 보상 키는 계정+발급 의뢰 ID이며 장면 재생·다른 기기·재전송으로 다시 지급하지 않는다. 실제 API·DB는 [기술 계약](../아틀라스_구현명세.md#town-world-contract)에 맞춰 구현할 대상이다.

가구 이동·직전 개인 배치 복구는 코인을 다시 받는 거래가 아니다. 현재 소유·권한·revision을 검사하고 허용된 복구는 별도 비용 없이 제공한다. 이미 소비된 음료·판매한 물건을 되돌리기로 복제하지 않는다. 타인의 공동 시설·거래는 개인 복구 대상이 아니다.

## 6 도구와 편의의 성장

| 시점 | 제공하는 편의 | 바뀌지 않는 것 |
|---|---|---|
| 처음부터 | 대상에 맞는 도구 자동 선택, 길·대상 강조, 큰 단추, 다시 듣기·쉬운 말, 소리/움직임 설정 | 도움·접근성을 성취 보상이나 유료 상품으로 잠그지 않음 |
| 한 레시피를 실제로 완성한 뒤 | 같은 레시피 다시 만들기에서 이전 선택을 불러오고 이번 재료/수량만 확인 | 새 주문 조건·현재 원가·보유량은 다시 확인. 자동 정답 판정 없음 |
| 기본 생활 정리의 한 역할을 완료한 뒤 | 본인이 신청하면 최대 3개의 확정 작업을 순서대로 맡기는 작업 목록 | 정산 몫·재료·공간을 먼저 예약하고 원래 소비·산출을 그대로 적용 |
| 같은 종류 화단을 다룬 뒤 | 준비된 개인 화단 최대 3칸을 한 번에 수확 | 칸별 실제 성장 완료·원가·수확 ID를 확인. 수량·성장 속도 보너스 없음 |

일괄 조작이 필요한 접근성 사용자는 성장 조건 전에도 같은 편의를 사용할 수 있다. 주민에게 작업을 맡겼다는 이유로 학습 관측의 정답·독립 수행을 만들지 않는다. 초보·숙련자 모두 직접 조작과 보조를 오갈 수 있고 후속 이야기를 계속 더 어려운 주문으로만 채우지 않는다.

오프라인 보조는 종료 전에 서버가 수락한 작업 목록 **최대 3개**만 처리한다. 표준 운영 제작은 작업당 5분을 검증값으로 두며, 준비한 입력과 산출만 소모·생성한다. 새로운 의뢰·구매·손님·작업을 보조가 스스로 이어 붙이지 않는다. 오프라인 시간이 하루든 한 달이든 그 목록을 넘는 수익은 없다. 즉시 처리·더 많은 예약·빠른 성장 판매는 하지 않는다.

**예약과 착수의 구분:** 순차 목록은 승인 `approvedAt`, 대기 등록 `enqueuedAt`, 실제 착수 `startedAt`, 완료 예정 `dueAt`를 분리한다. 등록은 재료·몫·공간을 예약하는 것이며 작업을 시작했다는 뜻이 아니다. 호스트는 앞선 작업의 실제 완료와 실행 주체·도구·자리의 가능 여부를 확인한 뒤 `startedAt`를 한 번 확정하며, `dueAt = startedAt + 해당 작업 판본의 소요 시간`이다. 승인 전 예상 완료에는 앞선 대기를 포함한다. 실행 조건이 아직 안 맞으면 대기 이유를 표시하고 시간이 지났다는 이유만으로 완료시키지 않는다. 미접속 중에는 이미 승인된 목록만 이 순서로 진행한다. 취소된 미착수 작업은 예약을 풀고, 완료한 앞 작업이나 재전송된 착수를 새 작업으로 세지 않는다.

[T08의 받침 준비](싱크타운_10대생활콘텐츠_제작설계_20261008.md#T08)도 이 목록 한 몫을 사용하고 실제 착수부터 180초를 센다. 5분 제작 뒤에 예약하면 실행 조건이 계속 유효할 때 그 제작이 끝난 뒤 180초에 준비된다. T08의 장식 화분은 이미 소유한 같은 개체의 외형만 한 번 바꾸는 자연 성장이라 이 보조 작업 목록과 별도다. 그 판본의 동시 성장 상한 3개를 지키고 물건·재료·코인 산출, NPC 보조 작업 완료, 기존 수확 한도 증가를 만들지 않는다. 기존 FT20의 첫 작물과 운영 화단의 3칸도 각 재배 규칙대로 독립 진행하며 순차 보조 목록의 추가 제작 몫으로 환산하지 않는다.

T08의 승인 작업에 배정한 NPC 비품은 준비 완료와 NPC 보관까지 유지할 수 있는 지속 배정이며, 화면 종료 때 해제하는 임시 대여·길·좌석 예약과 구분한다. 준비 완료만으로 인도·소유 이전은 일어나지 않는다. 실제 대여를 고르면 현재 조건을 다시 확인하고 별도 인도 예약을 확정한다. 인도 전 중단은 그 임시 예약만 풀고 준비 결과를 보존하며, 이미 인도된 대여의 반환·회수 규칙은 그대로 따른다.

## 7 재화 검산과 세 이용 패턴

생활 재화와 회사 매출을 섞지 않는다. 생활 장부의 검증식은 다음과 같다.

```text
판매 정산액 = 실제 소비한 판매 가능 재료의 미정산 구입 원가(최대 4C) + 3C
한 의뢰의 순수입 = 판매 정산액 - 그 의뢰의 입력 구입 비용 = 3C
재료 없는 생활 의뢰 순수입 = 3C
기말 잔액 = 기초 잔액 + 정산액 + 최초 지급 - 재료 구입 - 선택 꾸밈 구입
운영 첫 개방 후 W개의 7일 몫이 열린 경우 누적 작업 보상 ≤ 48C × W
```

마지막 식에서 W=1은 최초 16회 몫이다. 이후 유효 정액 168시간마다 W를 1 늘린다. 미사용분 보관 상한 때문에 실제 지급은 더 적을 수 있다. 한 기간에 이월분까지 32회를 완료하면 작업 보상은 최대 96C지만 앞 기간에 미사용한 몫을 쓴 것이며 누적 상한을 늘리지 않는다. 최초 20C는 계정에서 한 번만 더한다. 원가 정산은 이익이 아니며 구입 원가가 입력에 실제로 남아 있을 때만 인정한다.

플레이로 얻는 기본 꾸밈의 검증 가격은 작은 안내 그림/기본 색 조합 6C, 기본 화분 배치 세트 12C, 기본 벤치 18C다. 구매는 선택이며 다음 이야기·학습·물건 보존의 필수 소비처로 만들지 않는다. 소유한 기본 가구의 재배치·복구는 무료다. 유료 스타일과 같은 사용 기능을 기본 품목으로 제공한다.

| 7일 이용 예시 | 실제 정산 | 재료 구입 | 순수입 | 선택 소비 예시 | 20C로 시작한 기말 잔액 |
|---|---:|---:|---:|---:|---:|
| 짧게 2번: 재료 없는 일 2회+구입 재료 요리 2회 | 2×3+2×7=20C | 2×4=8C | 12C | 기본 화분 세트 12C | 20+20−8−12=20C |
| 보통 4번: 재료 없는 일 2회+구입 재료 요리 3회+직접 재배 요리 3회 | 2×3+3×7+3×6=45C | 3×4+3×3=21C | 24C | 벤치 18C+안내 그림 6C | 20+45−21−24=20C |
| 오래 6번: 재료 없는 일 4회+구입 재료 요리 6회+직접 재배 요리 6회 | 4×3+6×7+6×6=90C | 6×4+6×3=42C | 48C | 벤치 2개 36C+화분 세트 12C | 20+90−42−48=20C |

표는 소비를 강요하는 계획이 아니다. 아무것도 사지 않으면 각각 32/44/68C를 보유한다. 전부 주민 돕기나 관찰 의뢰를 고르는 사람도 4/8/16회에 같은 12/24/48C를 얻는다. 남은 코인·재료·정산 몫을 공개 경쟁으로 비교하지 않는다.

제로 잔액에서도 재료 없는 운영 의뢰를 완료해 3C를 얻을 수 있다. 정산 몫까지 소진했으면 새 발행을 기다리는 동안 기본 생활·이미 열린 이야기·소유 공간을 이용한다. 새 이야기의 필수 준비는 그 사건의 판매 금지 한정 준비물로 제공하므로 이 상태가 학습·이야기 진행의 결제 압박이 되지 않는다.

이 모델은 재료비 환급과 균일 작업 보상을 가진 한정 주문 경제다. 자유시장·플레이어 거래·무제한 오프라인 영업을 추가하려면 별도로 공급·소비·부정 이용을 재계산해야 한다. 현재 계산 통과가 장기 균형·재미·서버 비용 검증을 뜻하지 않는다.

무료는 며칠 카운트다운이 아닌 **계정별 유한 첫 챕터**다. 중단·기기 변경·오래 쉬기 때문에 첫 결과를 볼 권리가 사라지지 않는다. 완료한 경로를 다시 보면 이미 가진 결과를 읽고 같은 첫 지급·수확·시식 재고를 다시 만들지 않는다. 각 경로의 첫 결과와 후속을 다 누린 뒤에도 기본 생활은 반복할 수 있다.

정액 상품의 검증 이름은 ‘싱크타운 생활권’, 가격 가정은 **1개월 7,900원**, 선택 외형은 작은 소품 묶음 1,900원·테마 세트 3,900원이다. 국가별 가격·세금 포함 표기·기간 계산·청구 주기·자동 갱신은 출시 전 결제 정책으로 확정할 사항이다. 이 숫자를 승인된 판매가나 실제 스토어 값으로 표시하지 않는다. 첫 공개 후보는 한 등급이며 연간 할인·희소성 타이머·회전 추첨 판매는 넣지 않는다.

선택 외형은 배치 기능·수입·학습 결과가 기본 물건과 같다. 기본 물건으로도 충분한 찻자리·정원을 완성할 수 있게 조합을 제작한다. 주민 보답·도감·함께 만든 기념품은 판매 목록에 넣지 않는다. 과금 전용 인사·더 따뜻한 대우·광고 시청 보상으로 구매를 압박하지 않는다.

정액 상품은 실제 이용 가능한 콘텐츠 목록과 갱신 내역을 보여 준다. 아직 제작하지 않은 TOPIK 4급 과정 전체, 끝없는 사연, 매달 새 팩 제공을 구매 약속으로 쓰지 않는다. 현재 콘텐츠 제공 설계는 첫 네 경로와 각 기본 후속, [반복 운영 네 방식](#repeat-orders), [재방문 팩 RV01~24](싱크타운_재방문_콘텐츠와_원고.md#scope) 전부를 포함한다. 기존 ‘전체 후속 최소 8개’만으로 이 확장 팩 전체가 준비됐다고 판정하지 않는다. 콘텐츠 수만 채우는 이름 바꾸기 납품·A/B·언어 지원판은 별도 새 편수가 아니다.

현재 재방문 원고는 **24편 작성, 취향별 8편, 구현·사용자 검증 미확인**이다. 실제 출시 포함 목록은 각 원고·현재/후속 동작·권한/저장·접근성 검증이 통과한 제공량을 그대로 표시하고, 이 문서의 목표량을 출시 가능 수로 바꾸지 않는다. 한 취향에 새 8편, 세 취향 전체에 24편인 유한 팩이므로 모든 사람에게 24회 또는 30회 모두 새 경험을 준다고 계산하지 않는다([소진 편성](싱크타운_재방문_콘텐츠와_원고.md#coverage)). 출시 시점·가격·업데이트 주기는 이 상세 설계만으로 확정하지 않는다.

### 오프라인 권한 확인 기한 — 검증값

내려받은 유료 콘텐츠를 새로 진행할 수 있는 확인 기한은 **마지막 서버 권한 확인 시각+72시간과 해당 이용권 만료 시각 중 이른 때**다. 예를 들어 구독이 20시간 뒤 끝나면 오프라인 기한도 20시간이며 72시간이 더해지지 않는다. 계정·상품·콘텐츠 범위·확인 시각·만료 시각을 함께 저장하고 이 값은 클라이언트가 연장하지 않는다. 단말 시각의 역전이나 확인 근거의 훼손으로 기한을 신뢰할 수 없으면 새 유료 진행은 연결 확인을 기다리되 소유물·기록을 지우지 않는다.

이 72시간은 **새 유료 진행의 확인 기한**이다. 이미 확정한 제작·심기·인도·대여의 산출/반환 의무에는 새 만료를 붙이지 않는다. 그 결과는 서버에서 계속 보존하며 다음 연결에서 정산·수령할 수 있다. 장기 단절 뒤에도 내려받은 소유 공간 열람·기본 산책/대화·무료 첫 챕터의 권리를 초기화하거나 재지급하지 않는다. 없는 자산이나 확인하지 못한 다른 기기 변경은 꾸며 보여 주지 않는다.

기한 안의 오프라인 선택도 **로컬 잠정 진행**이다. 확정 재고에서 실제 차감하거나 산출·코인으로 확정하지 않고, 임시 예약·예상 결과를 ‘대기 중’으로 구분한다. 해당 기기의 화면에서는 같은 잠정 재료를 두 작업에 쓰지 않도록 묶지만 서버 소유권을 확보했다고 주장하지 않는다. 새 정산·구매·코인 지급·공동 제출은 항상 연결 후 서버 확인이 필요하다. 이미 서버가 예약한 최대 3개 작업과 오프라인 잠정 작업을 합쳐 3개를 넘겨 줄 세우지 않는다.

재연결 때 원래 선택 시각의 주장만으로 소급 승인하지 않고 현재 권한·소유·원가·revision·예약을 확인한다. 만료됐다면 앞서 서버가 확정한 작업과 정리 권한만 처리하며, 새 미확정 유료 작업은 완료로 만들지 않는다. 충돌하면 잠정 변경만 되돌리고 이미 확정된 다른 기기의 결과를 보존한다. 반복 생산과 권한 원장은 서버 시간으로 계산하며 기기 시각 변경으로 수확·정산 몫·구독 기간이 늘지 않는다.

### 생활권·선택 상품 정보 원고

상품 소개 제목: **싱크타운 생활권**

소개: “새 이야기와 생활을 이어 가요. 재배하고 만들거나, 주민을 돕고 마을을 살펴볼 수 있어요. 그림과 다시 듣기 같은 도움도 함께 이용해요.”

포함 안내: “이용할 수 있는 장소와 이야기를 먼저 확인해 주세요. 자유 AI 대화와 선생님 첨삭은 이 상품에 자동으로 포함되지 않아요.”

가격 검증 화면: “1개월 7,900원 — 내부 검증용 예시” / 비활성 단추 `상품 준비 중`.

실제 청구 연결 후 사용할 요약 틀: “오늘 {{실제 청구액}}이 결제돼요. 이용 기간은 {{시작일}}부터 {{종료일}}까지예요.” 자동 갱신형으로 확정된 상품에만 “다음 결제는 {{다음 청구일}}, {{다음 청구액}}이에요. {{관리 경로}}에서 확인할 수 있어요.”를 추가한다. 비갱신형으로 확정됐다면 “자동으로 다시 결제되지 않아요.”를 사용한다.

**상품별 기간·실제 표시 가격·자동 갱신 여부·관리 경로·권한 복원 정책 중 하나라도 확정되지 않으면 결제 단추를 활성화하지 않는다.** 두 문구를 섞거나 빈칸을 둔 채 청구하지 않는다. 이 원고는 소비자 법이나 특정 스토어 규정의 충족을 주장하지 않으며 출시 전 결제·법무 검토가 별도다.

선택 상품 제목 예시: “햇살 찻자리 꾸밈”. 소개: “창틀·방석·작은 장식의 모양을 바꿔요. 기본 가구와 쓰임은 같아요.” 상품 정보에는 실제 구성 수·적용할 슬롯·소유/복원·가격을 표시한다. 미리보기는 무료이며 닫으면 원래 배치로 돌아간다. 중복 소유품은 다시 살 수 있게 방치하지 않고 `가지고 있어요`로 표시한다.

## 12 회사 비용 검증표 — 매출 예측과 구분

가상 재료를 유한하게 관리하는 것과 회사가 손익을 내는 것은 다른 계산이다. 아래는 기록할 비용과 산식의 **내부 예제**이며 실제 원가·전환율·스토어 수수료의 확인값이 아니다. 선택 상품 매출을 기본 생활권의 손실을 덮는 필수 가정으로 넣지 않는다.

```text
가격 가정 P = 7,900원/1개월
청구액 중 비용·환불·세금 등 보수적 예비율 r = 30% (실제 정책/요율 아님)
유료 1명 월 변동비 가정 V = 900원
유료 1명당 무료 이용자 4명, 무료 1명 월 변동비 가정 F = 100원
유료 1명 월 환산 유입 비용 가정 A = 700원
1명당 기여액 = P×(1-r)-V-4×F-A = 3,530원
월 고정 제작·운영비를 6,000,000원으로 가정하면 필요 유료 수 = 올림(6,000,000/3,530) = 1,700명
```

실제 상품 결정 전에는 제작·미술·한국어 검수·QA·고객 지원의 고정비와 서버·저장·음원/자산 전송·결제/환불의 변동비를 기록해 위 가정에 대입한다. 기본 실행의 AI 호출 0을 전체 운영비 0으로 계산하지 않는다. 실제 기여액이 0 이하라면 이용자를 늘려 해결한다고 말하지 않고 콘텐츠 공급·비용·가격안을 다시 검토한다. TOPIK 성과나 결제 전환은 계산표로 입증하지 않는다.

## 14 반복 의뢰 네 종류의 발급부터 재발급까지

2026-10-09 보강. 기존 3C 작업 보상·실제 미정산 원가 최대 4C·정산 몫 16/32·동시 예약 3개·표준 제작 5분을 실제 생활 원고에 연결한다. **RQ01 메뉴 / RQ02 관찰 / RQ03 제작 / RQ04 주민 돕기**의 네 템플릿이며 각 두 변주는 다른 수행을 즐기는 재사용 원고다. 이를 새 이야기 8편이나 RV24편의 추가로 계산하지 않는다. 통화·가격·공급 한도·이용권을 새로 만들지 않는다.

### 공통 발급·정산 계약

| 단계 | 호스트가 확인·확정할 것 | 사용자에게 보일 상태 |
|---|---|---|
| 후보 보기 | 해당 템플릿·현재 NPC 필요/대상·권한·지원판. 아직 재료/정산 몫을 예약하지 않음 | 실제 물건·일·수량·목적·작업 3C·예상 원가 반환을 먼저 설명 |
| 수락 | 같은 계정의 `acceptCommandId`와 발급 세대 `offerRevision`으로 한 `requestId`만 생성. 현재 대상·정산 몫·예약 3개 한도 확인. 동시에 같은 대상의 다른 의뢰 금지 | `[이 일을 할게요] [다른 일을 볼게요] [지금은 쉴게요]` |
| 입력 예약 | 필요한 실제 판매 가능 로트와 미정산 원가, NPC 비품의 소유/개정·작업 자리를 확인. RQ01/03은 판매 가능 완제품을 쓰거나 유효 입력을 예약하는 두 경로를 배타 선택 | 재료 없으면 구입/재료 없는 의뢰/쉬기 중 본인이 선택. 체험 지원물을 몰래 소비하지 않음 |
| 수행 | 아래 실제 행동·단계 증거와 산출을 확인. 제작 확정은 소비+산출 1회, 도움/언어 수행은 별도 | 미확정 상태는 ‘확인 중’. NPC 도움은 같은 품질·보상 |
| 인도/작업 확인 | RQ01/03은 대상 물건·수량·수령 NPC·원가 출처, RQ02/04는 실제 관찰/준비 완료. 오래된 개정은 현재 상태를 읽어 재선택 | 마지막 `[건넬게요]` 또는 `[이 결과로 마칠게요]` 전에 실제 결과와 정산 내용 표시 |
| 정산 확정 | `accountId+requestId`를 유일 보상 키로, 완료·필요 몫 소비·인도/재고 차감 또는 준비/관찰 결과·원가 정산·3C 원장을 한 거래로 확정 | ‘완료’와 확정 금액. 네트워크 응답 유실은 같은 ID 조회, 새 의뢰로 재지급하지 않음 |
| 현재 결과 보기 | 실제 수령/사용/준비 사실을 현재 세계에 표현. 반응 ACK는 완료 거래와 분리 | 결과를 보고 쉬거나 나갈 수 있음. 다음 주문 자동 시작 없음 |

`requestId`, `acceptCommandId`, `offerRevision`, `demandCycleId`, `sourceObjectIds`, `costBasisIds`, `deliveryId`, `settlementId`는 **구현할 논리 필드**이며 현재 DB/API 지원을 주장하지 않는다. 원고를 새로 연 횟수·손님 대사·클라이언트 시계는 발급 원인이 아니다. 재시도는 같은 수락 명령 ID, 다른 기기의 동시 수락은 같은 발급 세대의 승자 한 요청을 반환한다. `demandCycleId`는 아래 실제 필요·원고 판본·현재 대상과 묶이며 완료한 같은 필요를 새 ID로 세탁하지 않는다.

### 후보 수와 피로 방지의 시작값

- 직접 `[생활 의뢰 보기]`를 열면 명시 취향에 맞는 후보 최대 2개, 전체 표시 최대 3개다. `새 정산 가능 의뢰`와 `보상 없는 익숙한 생활`을 같은 보상처럼 섞지 않는다. 보상 없는 생활은 별도 기존 행동 목록에서 고른다.
- 수락한 미완료 의뢰는 전체 최대 3개다. **같은 템플릿도 실제로 서로 다른 수요·산출물·수령 몫이면 개별 수락하여 이 한도 안에 예약할 수 있다.** RQ01의 서로 다른 표준 2인분 주문 3개는 기존 §10의 4C 입력×3·5분 순차 제작×3 사례를 그대로 쓴다. 같은 `demandCycleId` 또는 이미 예약된 같은 입력/대상은 다른 NPC·기기·템플릿으로 중복 발급하지 않는다. 미완료 수요를 닫지 않고 같은 수요를 다시 제시하면 기존 요청으로 돌아간다.
- 새 필요가 있어도 **완료 직후 자동 의뢰 0개**, 현재 세션에서 거절한 템플릿 자동 재권유 0개다. 사용자가 직접 목록을 다시 열거나 `[같은 일을 다시 해 볼게요]`를 고를 때만 다음 유효 필요를 확인한다. 세션을 바꿔도 지속 ‘먼저 권하지 않기’ 설정은 유지한다.
- RQ02/04는 실제 다른 관찰 목적/새로 사용을 마친 비품이 있어야 재발급한다. 정산 몫이 남았다는 이유만으로 빈 과제·새 고장·새 오염을 만들지 않는다. 같은 일을 바로 반복하고 싶은 경우 현재 목적·입력이 실제 마련된 RQ01/03을 직접 선택할 수 있으나 판매 수요와 공통 한도를 그대로 소비한다.
- NPC 수요 판본은 메뉴 2개·관찰 2개·제작 2개·도움 2개로 시작한다. 후보 조합은 현재 검수된 이 8개 안에서만 선택하고 이름·시간·소품을 곱해 수백 개 새 의뢰라고 세지 않는다. 동일 판본을 자발적으로 반복하는 것은 허용하되 자동 추천은 가능한 다른 판본을 먼저 보여 준다. 이 표시 개수·피로 값은 실제 플레이로 조정할 가설이다.

<a id="RQ01"></a>
### RQ01 손님 두 사람에게 실제로 내는 작은 메뉴

**발급 원인:** 플레이어가 `[메뉴 의뢰 보기]`를 연다. 사장님에게 준비된 개인 주문 `demandCycleId`가 있고 표준 2인분을 받을 수 있는 식탁/포장 보관 공간, 현재 정액 권한·정산 몫이 있을 때 제안한다. 첫 무료/이야기 음식과 구분되는 **운영 주문**이다. 수락하면 같은 주문을 다른 기기에서 중복 발급하지 않는다.

| 순서 | 실제 대사·선택 | 행동·상태 |
|---|---|---|
| 1 | 사장님: “손님 두 분께 낼 메뉴가 필요해요. 차 두 잔이나 잼 곁들임 두 개를 준비할 수 있어요.” `[차를 만들게요] [잼 곁들임을 만들게요] [보유 메뉴를 볼게요]` | 이번 수요가 두 메뉴 모두 허용하는 주문임을 먼저 표시. 한 가지를 확정하면 해당 2인분만 예약. |
| 2 | “재료비는 실제 쓴 만큼, 일을 마치면 3코인이에요.” `[이 재료로 할게요] [구입을 볼게요] [나중에 할게요]` | 딸기 1묶음+기본분 1회 또는 동일한 판매 가능 2인분의 개체/원가를 확인. |
| 3 | 차: `[과일을 넣어요] → [물을 섞어요]` / 잼: `[과일을 담아요] → [곁들임에 올려요]` | 검수된 조리 동작 또는 NPC 보조. 직접 수행의 단계 완료와 승인된 표준 제작 시각을 확인한 뒤 2인분 산출. 5분은 기존 제작 검증값이며 그동안 다른 생활·종료 가능. |
| 4 | 사장님: “두 분 몫이 준비됐어요. 여기로 건넬까요?” `[건넬게요] [아직 보관할게요]` | 전자는 현재 2인분 인도+차감+원가/3C+정산 몫을 한 번 확정. 후자는 자기 산출물과 미완료 주문 보존. |
| 5 | 사장님: “이 메뉴는 제가 손님께 낼게요.” `[쓰는 모습을 볼게요] [이제 쉴게요]` | 실제 차는 두 잔 서빙, 잼은 두 접시 놓기. 관람 건너뛰어도 확정 정산 유지. |

**입력·산출·원장:** 구입 딸기 3C+기본분 1C면 입력 4C, 실제 2인분 산출, 인도 때 7C, 순수입 3C다. 구입 모종 출처 딸기 2C+기본분 1C면 6C 정산, 순수입 3C다. 한 인분을 이미 시식했다면 같은 완제품으로 2인분 주문을 완료할 수 없다. 판매 금지 로트 혼합은 차단하고 무료 대안을 판매 재고로 바꾸지 않는다.

**중단·재개:** 제작 전 취소는 입력·몫 예약 해제. 제작 뒤 취소는 소비를 돌리지 않고 자기 2인분 보존, 주문 예약만 해제한다. `[건넬게요]` 뒤 응답 유실은 같은 `deliveryId/requestId`로 확정 거래를 조회한다. 미확정이면 자기 재고, 확정이면 NPC 재고이며 두 곳에 동시에 존재하지 않는다. 복귀: “메뉴는 준비됐어요. 아직 건네지 않았어요.” 또는 “이미 건넸고 정산도 끝났어요.”

**재발급·변주:** 기존 주문 종료·정산 가능 몫·현재 수령 공간 확인 뒤 직접 새 주문을 고를 때 새 수요 세대를 연다. 각 수요는 한 표준 2인분이며 무한 손님·자동 판매는 없다. 같은 차/잼 변주는 알려진 작업임을 표시한다. 첫 메뉴 성과·단골 관계를 매 주문 지급하지 않는다. **언어 지원:** 실물 2인분 강조/한 단계 시범과 기다림; 확장 “두 분이 나눠 드실 수 있게 차 두 잔을 준비했어요.” 도움이 원가/보상을 바꾸지 않는다.

### RQ02 지금 본 모습과 지난 기록을 구분하기

**발급 원인:** 연구원이 현재 관찰 대상과 자기가 남긴 지난 기록을 가지고 있고, 아직 이 목적의 작업이 확인되지 않은 `observationCycleId`가 있다. 관찰 목적은 `꽃의 위치 비교` 또는 `같은 대상의 두 시점 정리` 두 판본이다. 개인 수첩 공개·표본 채집·새 발견을 요구하지 않는다.

| 순서 | 실제 대사·선택 | 행동·상태 |
|---|---|---|
| 1 | 연구원: “지금 보이는 모습을 제 기록과 같이 정리해 주실래요? 재료는 필요 없어요.” `[현재와 지난 모습을 볼게요] [두 시점을 정리할게요]` | 실제 가능한 목적만 제시하고 사용 기록·현재 대상·3C를 보여 준다. |
| 2 | “이쪽은 지금 화분이고, 이쪽은 지난 그림이에요.” `[가까이 볼게요] [전체를 볼게요] [같이 보여 주세요]` | 현재 대상의 두 관찰 지점 또는 현재/과거를 실제 확인. 소리·움직임 없는 정지 대안도 동일. |
| 3 | A `[이 자리는 같아요] [이 자리는 달라요]` / B `[전체 다음 가까이] [가까이 다음 전체]` | A는 실제 상태와 대조해 시범으로 수정 가능. B는 실제 본 순서를 고르고 각 기록을 연결한다. 언어 정답과 생활 확인은 분리. |
| 4 | 연구원: “지금 확인한 내용이 이 카드예요.” `[이 결과로 마칠게요] [다시 볼게요]` | 확인한 사실·대상 개정·관찰 단계가 유효하면 기록 연결+작업 완료+3C+정산 몫을 한 거래로 확정. |
| 5 | 연구원: “제 안내에서 지금과 지난 모습을 구별해 놓을게요.” | NPC가 실제 기록을 분리해 놓는다. 플레이어의 카드 공개/아이템 지급은 없다. |

**입력·산출·원장:** 플레이어 입력 재료 0, 판매 물건 0, 연구원 작업 기록 1개, 정산 3C다. 같은 내용이더라도 현재 실제 확인이 새 목적에 필요한 경우만 새 관찰 작업이 된다. 단순 열람·장면 다시 보기·장치 시각 변경은 새 필요가 아니다.

**중단·재개:** 마지막 현재 대상 확인과 개정을 보존한다. 대상이 바뀌면 “관찰 대상이 달라졌어요. 지금 모습으로 다시 확인할까요?”로 동의를 받고 같은 의뢰의 결과를 갱신한다. 이미 정산한 과거 관찰은 고쳐 덮지 않는다. 완료 전 취소는 몫 반환·개인 임시 메모 보존, 확정 후 재전송은 동일 3C 거래 조회다.

**재발급·변주:** 이전 의뢰 종료 뒤 **해당 화분 배치/성장 개정이 실제 달라짐** 또는 **연구원이 실제 새 안내 준비를 시작해 두 시점 구성이 필요해짐**이 있어야 새 필요를 등록한다. 사용자가 이전 배치를 A→B→A로 되돌린 것만으로 동일 판본·동일 사실을 다시 정산하지 않으며 `(목적 판본, 대상, 비교 사실 fingerprint)`의 이미 처리된 필요는 제외한다. 같은 정보로 다섯 번 열어도 첫 거래 한 번이다. 새 필요가 없으면 “지금 정리할 기록은 없어요. 그냥 보셔도 좋아요.” **언어 지원:** 현재/지난 그림을 교대로 가리키고 기다림; 확장 “지난 기록과 자리는 같고, 꽃이 핀 부분은 달라요.”

<a id="RQ03"></a>
### RQ03 실제 용도가 있는 작은 받침 한 개

**발급 원인:** 공방 주인에게 기존 개인 소량 주문 중 `도안 받침` 또는 `찻집 진열 받침` 한 개를 납품할 수요가 있다. 현재 수령 보관칸·해당 용도 슬롯·정산 몫을 확인한다. 이미 사용 중인 플레이어 가구를 망가뜨려 새 의뢰를 만들지 않는다.

| 순서 | 실제 대사·선택 | 행동·상태 |
|---|---|---|
| 1 | 공방 주인: “작은 받침 하나를 쓸 곳이 있어요. 그림을 세울까요, 물건을 놓을까요?” | 이번 수요에서 가능한 두 쓰임의 미리보기. 결과는 같은 표준 받침 1개이며 기능 차등 판매가 아니다. |
| 2 | `[목재와 천으로 만들게요] [보유 받침을 볼게요] [나중에 할게요]` | 판매 가능한 목재 1+천 1 또는 실제 보유 받침1 중 배타적으로 예약한다. 소유 기본 가구를 자동 선택하지 않는다. |
| 3 | `[받침을 맞춰요] → [천을 고정해요]` / `[함께 만들어 주세요]` | 실제 두 단계 또는 NPC 보조와 표준 제작 완료를 확인. 입력 소비+받침 1개를 한 번 확정한다. |
| 4 | 공방 주인: “이 받침을 제가 받아 써도 될까요?” `[건넬게요] [제 집에 둘게요]` | 건네기는 소유 이전+재고 차감+원가/3C+몫 확정. 집에 두기는 의뢰 취소·몫 반환 후 자기 개체 보존, 정산 없음. |
| 5 | 공방 주인: “이렇게 쓰려고 했어요.” | 도안 갈래는 그림 세우기, 진열 갈래는 자기 물건 놓기. 플레이어가 보지 않아도 인도 확정만으로 지급은 유지한다. |

**입력·산출·원장:** 구입 목재2C+천2C이면 입력4C/산출1개/인도7C/순수입3C. 보관형 채집 목재0C+구입 천2C면 인도5C/순수입3C. 이야기 지원 천이 들어가면 판매 불가이고 이 수요에 인도할 수 없다. 인도 뒤 배치 철거는 NPC 보관으로 옮길 뿐 플레이어에게 판매 물건을 반환하거나 정산을 되감지 않는다.

**중단·재개:** 제작 전 취소는 입력/몫 해제, 제작 뒤 취소는 자기 받침 보존, 인도 응답 유실은 같은 거래 조회. 실제 수령 공간이 사라지면 입력·완성물 유지 후 해당 요청 보류 또는 취소를 고른다. 복귀: “받침은 만들었어요. 누구 물건으로 둘지 아직 정하지 않았어요.” **재발급·변주:** 이전 종료 뒤 다른 실제 수령 수요 슬롯이 있고 사용자가 직접 새 의뢰를 선택해야 한다. 수령 가구 보관이 가득 차면 새 수요를 만들지 않는다. 같은 받침을 NPC가 되팔아 플레이어가 재납품하는 경로는 없다. **언어 지원:** 실제 도구·한 단계 시범, 확장 “그림이 보이도록 세워 쓸게요.”

### RQ04 주민이 다음 일을 편하게 시작하도록 준비하기

**발급 원인:** 공방/찻집에서 실제 사용을 마쳐 돌아온 NPC 비품 묶음이 있고 아직 다음 사용 준비가 안 된 `kitUseCycleId`가 있다. 판본은 **공방 도구 묶기**와 **찻집 빈 잔 쟁반 준비** 두 가지다. 플레이어의 기본 도구·기존 RV 준비 방식이 고장나거나 매일 초기화되는 일이 아니다.

| 순서 | 실제 대사·선택 | 행동·상태 |
|---|---|---|
| 1 | 공방 주인: “쓰고 돌아온 집게와 연필을 다음 작업에 쓰기 좋게 둘까요?” / 사장님: “돌아온 빈 잔을 쟁반에 준비해 주실래요?” | 실제 반환된 비품 2개와 보관 자리, 3C를 보여 준다. 없는 물건·고장은 만들지 않는다. |
| 2 | A `[한 번에 꺼내게 모아요]` / B `[쓰는 순서대로 나눠요]` | 두 결과 미리보기. 확정 전에는 이동하지 않는다. |
| 3 | `[이렇게 준비할게요] [다시 고를게요]` | A는 같은 비품을 한 받침/쟁반에, B는 유효한 두 준비 칸에 배치한다. NPC 도움을 요청하면 하나를 시범하고 나머지를 고를 때까지 기다린다. |
| 4 | NPC: “다음에는 이렇게 꺼낼 수 있어요.” `[이 결과로 마칠게요] [다시 볼게요]` | 실제 같은 비품/용도/배치 개정 확인 후 ready상태+작업완료+3C+정산 몫을 한 번 확정. |
| 5 | NPC: “이제 제 일은 제가 이어갈게요.” | 가능한 실제 다음 작업에서 준비한 방식으로 꺼내 쓴다. 당장 다음 작업이 없으면 준비된 물건을 보여 주며 쓰는 장면은 꾸며내지 않는다. |

**입력·산출·원장:** 플레이어 재료0/판매 물건0, NPC 소유 비품2개가 같은 개체로 준비됨, 정산3C. 이 원고를 수행하지 않아도 NPC는 자기 기본 준비를 해 일과를 이어 간다. 그 자기 해결은 플레이어 보상이 아니다. 기존 RV02/RV06 선호를 기본 미리보기에 반영할 수 있지만 과거 RV 완료를 새 작업으로 세지 않는다.

**중단·재개:** 임시 비품 예약은 화면 종료 때 풀되 확정한 배치·부분 작업은 보존한다. 재개할 때 같은 비품이 NPC에 의해 사용됐다면 이전 준비 결과를 현재라고 하지 않고 남은 실제 과업 재확인/무보상 취소를 고른다. 완료 거래 뒤 NPC가 비품을 꺼내도 완료는 보존한다. **재발급·변주:** 이 묶음을 NPC가 실제로 사용하고 반환한 새 `kitUseCycleId`가 있어야 다시 후보가 된다. 사용자가 준비를 풀고 다시 모으거나 A/B를 왕복해도 새 사용 사실이 없으므로 재지급0. NPC 사용을 빨리 돌리라는 의뢰·시간 보상은 없다. **언어 지원:** 두 비품과 목적지 강조·한 동작 시범, 확장 “한 번에 가져가려면 같이 놓고, 차례로 쓰려면 나눠 놓아요.”

### 어디서만 얻고 어디서 쓰는가

- 원재료의 공급처는 등록한 목적지의 공방·시장·허용된 채집 지점으로 한정한다. **마을의 일반 가게·홈 자동 생산·버스 탑승 보상에서 같은 원재료를 공급하지 않는다.** 도안은 배운 뒤 남고, 가져온 원재료는 마을에서도 보관·소비할 수 있다. 지역 전용은 획득처를 뜻하며 제작 장소를 해당 지역에만 가두지 않는다.
- 채집을 좋아하지 않는 플레이어에게도 같은 지역 안에서 제작 도움·구입 등 해당 재료의 실제 대안을 준비한다. 한국어 정답·랜덤 희귀 확률·연속 출석·특정 날 한 번의 운행을 재료 획득 조건으로 쓰지 않는 안으로 시험한다. 직접 방문해 고르고 행동한 재미가 중심이다.
- 첫 현지 체험의 소량 준비분과 반복 운영 공급을 구분한다. 체험 준비분은 계정+지역+체험 사건의 최초 한 번이며 §3/4의 지원물처럼 판매 금지 출처를 유지한다. 같은 지역 재방문으로 반복 획득할 수 있는 운영 공급은 개인별 유한 공급으로 설계하고 수량·보관형 몫·재공급 간격·가격은 경제 검산 뒤 정한다. 버스 편·앱 재시작·새 장면 ID가 공급을 초기화하지 않는다.
- 지역 특수 재료는 기존 기초 목재·천·딸기·꽃을 전부 대체하지 않는다. 기본 생활은 마을 재료로 완결하고, 지역 재료는 새로운 외형·질감·메뉴·제작 갈래를 더한다. 기본 이야기·관계·언어 도움을 여러 지역 재료 수집에 묶지 않는다.
- 현지에서 얻은 소재를 집에서 재배·복제해 동일 지역 원재료를 무한 생산하는 규칙은 추가하지 않는다. 화분·장식의 성장 표현과 원재료 공급은 구분한다. 플레이어 거래·경매·새 화폐는 기존 범위대로 열지 않으며, 판매 의뢰는 실제 수요와 정산 설계가 준비된 완성물만 별도로 등록한다.

### 기존 생활에 연결하는 레시피·실물 결과 — 시험 후보

| 후보 레시피 | 확정 전에 보여 줄 입력 | 산출·사용 | 연결 |
|---|---|---|---|
| RC-N01 야경색 받침 | 손질 목재 1+천 1+RM-N01 1 | 야경색 받침 1개를 집/허용된 쉼터에 놓고 컵과 함께 실제 사용 | 기존 작은 받침의 지역 마감 변형, T02·T06 |
| RC-I01 향신료 차 | RM-I02 1+조리 기본분 1 | 2인분. 현재 재고를 써 시식·허용된 선물/메뉴 제공 중 선택 | T04·LS02 계열의 새 메뉴 후보. 기존 이야기 준비분과 구분 |
| RC-S01 재생유리 화병 | RM-S01 1+공방의 등록된 기본 부품 1세트 | 화병 1개, 현재 소유 꽃 장식을 꽂거나 빈 화병으로 배치 | T02·T06·T08 |

수량은 레시피 검증용 가설이다. RC-S01/RC-J01의 기본 부품은 **공급·가격·소유·소비가 등록돼야 할 새 입력**이며 기존 조리 기본분으로 대신하거나 무료 무한 부품으로 생성하지 않는다. 준비 전에는 완성 레시피로 노출하지 않는다. 나머지 네 재료의 전체 레시피도 실제 산출물·입력표를 작성한 뒤 연결한다. 완성된 아이템을 다시 배치·시식 장면 재생하는 것은 새 제작·새 보상이 아니다.

재료 차이는 실제 3D 결과에서 읽혀야 한다. 한지는 빛의 확산과 종이 결, 재생유리는 색·빛 반사, 직조천은 짜임과 두께, 안료는 칠한 표면으로 표현하는 안을 시험한다. 작은 화면에서도 차이를 알아볼 대표 부분부터 제작하고 PC에서는 같은 아이템의 표현 품질을 확장한다. 모양·색·무늬를 고르는 것과 새 소유물을 만드는 거래를 구분한다.

주민은 실제 보여 준 완성물·함께 제작한 사건을 근거로 물건을 사용하거나 다음 활용을 제안한다. 가방 속 재료나 플레이어의 미공개 여행을 자동으로 안다고 말하지 않는다. 처음부터 주민 공용 가구를 자동 교체하지 않고 허용된 개인 배치/명시한 공동 기여를 따른다. 완료의 핵심은 재료 숫자보다 **내가 여행에서 가져온 것이 내 생활에 쓰이는 모습**이다.

### 원장·실패 복구와 제작 범위

§5의 기존 재고·예약·제작 계약을 확장한다. 소재 정의에 `materialId / sourceRegionId / allowedSourceIds`를, 획득분에 `grantId / sourceEventId / allocationId / quantity / costBasis / saleAllowed`를 둔다. 계정·현재 지역·허용 행동·남은 공급 몫·현재 권한을 호스트가 확인한 뒤 한 번 지급한다. 지역에 도착했다는 클라이언트 주장이나 사진 기록만으로 재료를 지급하지 않는다.

소비+산출은 같은 거래로 확정하고, 판매 금지 입력/미정산 원가의 전파와 완성물의 공통 아이템 ID를 보존한다. 여행에서 받은 재료를 귀가 때 새로 지급하지 않는다. 현지 획득이 이미 확정된 뒤 보관 한도·연결 유실로 표시/수령이 지연되면 그 **같은 지급분**을 보관 대기·조회로 복구하며 재방문을 새 획득으로 세지 않는다. 소비 확정 뒤 실패는 같은 산출물로 복원하고 원재료까지 함께 환급하지 않는다. 만료·오프라인·두 기기 충돌은 §9를 따르며 기존 소유 재료와 산출물을 지우지 않는다.

**첫 구현 후보:** BUS-TEST 왕복 뒤 남산 재료 1종 → RC-N01 1개 → 집 배치·실제 사용·NPC 반응 → 앱 종료/재개까지 연결한다. 네 지역/8종을 모두 첫 시험이나 기존 LAUNCH-01 완료 조건으로 자동 편입하지 않는다. 신규 재료 공급·코인 순환·완성물 모델·레시피·현지 원고는 각각 제작할 작업이며 현재는 설계 반영이다.

검수할 것: 현지에서만 새 지급, 현지 획득 대안, 동일 사건/버스 편/재접속 중복0, 두 기기 공급·재료 이중 소비0, 준비분 판매 제한 보존, 충분한 입력 없이 제작0, 보관 한도 초과 때 손실0, 귀가/만료 뒤 소유 보존, 기본 생활의 여행 강제0, 모바일에서 완성물의 재료 차이와 실제 사용 확인. 실제 구현·트랜잭션·기기 시험은 후속이다.

## 16 펫·생활 비서·낚시의 공급과 소유 — 2026-10-09 설계 추가

사용자가 세 콘텐츠의 추가와 **현재는 설계만** 진행하도록 요청했다. 플레이 정본은 [펫](../마을_설계.md#town-pets)·[생활 비서](../마을_설계.md#world-life-assistant)·[낚시](../마을_설계.md#town-fishing)다. 아래는 기존 재고·원장·권한·소비 계약에 붙일 설계이며 새 결제·데이터베이스·API 구현 완료가 아니다.

### 돌봄 비품과 제작 후보

- 펫의 기본 입양·돌봄에는 유료 필수 물품을 두지 않는 안이다. 기본 먹이·물·그릇·휴식은 **돌봄 비품**으로 처리하고, NPC 이야기 음식·플레이어 조리 재고·판매 재료와 구분한다. 먹이 주기를 반복해 물건·코인을 추출하지 않으며 펫이 미접속 때문에 죽거나 관계·소유가 줄어드는 경제를 만들지 않는다.
- 입양은 계정의 같은 수락 사건에 하나의 `petId`를 부여하며 현재 허용된 소유 슬롯도 같은 거래에서 확인한다. 첫 시험은 한 마리 동행이며 여러 종의 수집·슬롯·판매는 미정이다. 실제 소유 펫의 이름·장식·함께한 기록과 현재 장면의 표현을 분리하고 계정 교체 때 타 계정 펫을 보여 주지 않는다.
- 펫 장식/침구는 현재 소유 재료로 만드는 선택 확장이다. 플레이어용 코스튬과 동물용 외형의 아이템 ID·슬롯을 구분한다. 지역 재료의 제한은 제작 뒤에도 전파한다. 비서가 같은 레시피를 안내해도 입력을 예약/소비하거나 상품을 구매한 것으로 처리하지 않는다.

| 후보 레시피 | 입력의 시험안 | 산출·사용 | 구현 전 준비할 것 |
|---|---|---|---|
| RC-P01 작은 펫 잠자리 | 손질 목재 1+천 1. 지역 변형은 천 대신 RM-I01 1을 쓰는 별도 레시피 판 | 잠자리 1개. 위치·무늬 선택과 실제 펫의 휴식 | 실제 모델·허용 자리·펫 동작. 기본 돌봄 비품을 회수하거나 효율 차등을 두지 않음 |
| RC-F01 작은 관찰 수조 | RM-S01 1+§15에서 공급 등록할 공방 기본 부품 1세트 | 수조 1개. 허용 생체를 수용 한도 안에서 배치 | 성수 재료/부품의 공급·원가·소유와 수조 수용량. 생물은 제작 입력이 아니라 별도 소유 개체 |
| RC-F02 생선 메뉴 | 조리 가능으로 등록한 어종의 소유 재료 1+조리 기본분 1 | 2인분을 시험값으로 두고 시식·허용된 제공에 사용 | 해당 어종의 조리 상태·입력/산출·표현·검수. 생태/실제 조리 정보는 별도 검증 |

후보를 완성 레시피처럼 먼저 노출하지 않는다. RC-P01의 일반/지역 변형은 같은 입력을 두 번 쓰지 않고, RC-F01에 생물을 넣거나 꺼내는 것은 새 수조 제작이 아니다. 수조는 공급·가격·산출이 준비되기 전까지 관찰 기록/전시 경로로 대체한다. 새 물고기 메뉴/펫 제작물의 NPC 판매는 실제 주문·원가·정산을 따로 준비한 뒤 등록하며 기존 RQ의 보상액을 자동 증액하지 않는다.

### 포획·발견·소유의 원장

| 대상 | 남길 사실 | 중복·소비 경계 |
|---|---|---|
| 낚시터/어종 정의 | `siteId`, `regionId`, `speciesId`, 허용 공급 지점·보관/조리 허용·판본 | 일반 어종과 지역 전용 어종을 구분. 지역 공방 소재는 낚시 보물 상자 공급에 넣지 않음 |
| 개인 낚시 시도 | `fishingSessionId`, 활성 입력·정지/재개·호스트 상태·현재 revision | 준비→진행→정지 또는 포획 확정. 오래 켜 두기·앱 종료·클라이언트 시계 변경으로 포획하지 않음 |
| 포획과 발견 | `catchId`, 실제 포획 시도·어종·장소·시각, `discoveryId` | 같은 시도에는 같은 포획, 같은 어종의 첫 발견에는 같은 발견 키. 도감 기록만으로 실물 재고를 만들지 않음 |
| 포획 처리 | `catchId`의 놓아주기/생체 보관/허용 조리 재료 인계 중 하나 | 결과 선택을 현재 revision에서 한 번 확정. 응답 유실 때 같은 처리 반환. 생체 보관과 재료 인계로 수량을 이중 지급하지 않음 |
| 수조/요리/기증 | 현재 소유 생물/재료의 개체·수량·사용처 | 수조 배치는 개체 위치 변경, 요리는 입력 소비, 기증은 소유 이전. 같은 개체를 동시에 소비/기증/전시 소유하지 않음 |

보관 가능한 포획은 개인별 유한 공급과 현재 수용량을 확인한다. **처음은 관찰·놓아주기·도감부터** 검증하고 보관/재료 공급량·보관형 적립·재공급 간격·어종별 판본은 검산 뒤 정한다. 관찰/놓아주기에는 코인·판매 재고를 발행하지 않으므로 기존 판매 정산 몫을 소비시키지 않는다. 공급 몫이 없는 때에는 보관 불가를 시작 전에 알리고 기록 중심으로 낚시할지 고르게 한다. 미접속 적립·종별 무한 공급·자동 NPC 매입은 도입하지 않는다.

화면이 가려지거나 연결이 끊기면 활성 조작을 멈추며 호스트가 마지막 확정 시도와 정지 상태를 보존한다. 종료 직전 정지/입력을 확인하지 못해 시도를 안전하게 재개할 수 없으면 미확정 시도를 준비 단계로 돌리고 도구·기존 소유를 보존한다. 이미 포획 확정된 `catchId`는 결과 선택 앞에서 이어 준다. 닫기/다시 시작으로 첫 발견·보관 몫·산출물을 재지급하지 않는다. 보관 한도 초과나 만료 상태에서는 이미 확정한 포획의 정리 권한과 기존 소유 관리로 안전하게 끝내고 다른 물건을 버리거나 추가 결제하게 하지 않는다.

물고기를 놓아주는 기록과 소유물의 폐기는 다르다. 수조에서 기르던 개체를 놓아주려면 해당 개체의 소유 해제를 직접 선택하고 결과를 확인한다. 단순 수조 배치 되돌림·장면 재생·비서 추천은 이 결정을 대신하지 않는다. 생체를 조리 재료로 전환하는 규칙은 종별 허용·사용자 선택·소유 이동이 준비된 뒤에만 열며 관찰 수조의 개체를 자동 조리에 제안하지 않는다.

### 권한·확인 범위

새 타운 생활·낚시·여행은 기존 TOPIK 해금과 무료/정액 권한 범위를 따른다. 무료 체험에서 제공할 펫 만남/돌봄·첫 낚시의 양, 선택 외형의 가격·상품은 미정이다. 기본 마스코트 학습 안내와 허용된 현재 화면의 사용 도움은 펫 입양·낚시 성과·추가 비서 상품 구매로 잠그지 않는다. 이미 소유한 펫·재료·수조·기록은 만료/재설치로 지우지 않고 §9의 기존 소유물 관리·확정 작업 정리를 이어 쓴다.

후속 검사: 두 기기의 입양/포획/처리/소비 동시 요청, 포획 뒤 응답 유실, 정지와 장력 입력 충돌, 구역 이동·귀가 중 펫 복원, 수조↔보관 이동, 조리와 기증 경합, 공급 부족·보관 초과·만료·오프라인, 비서 안내와 실제 원장 일치. 현재는 이 검사의 **설계**이며 서버 거래 시험이나 펫·낚시 플레이 완료 기록이 아니다.
