## 2026-09-21 최신 확정: RPG 기각, 마을의 생활·커뮤니티·경영

사용자는 **RPG 방향을 기각**했다. 현재 개발 방향은 같은 소속 정원 16명의 미래 한국 마을에서 **NPC와의 커뮤니티 활동, 농작물 키우기, 채집, 제작, 꾸미기, 관리하고 성장시키는 재미**를 즐기는 생활·경영 경험이다. 앞서 논의한 몬스터·한국어 퀴즈 전투·전투 보상은 현재 요구가 아니다. 과거의 시제품·이미지·제작 기록은 보존하며, 기각된 기획을 구현할 작업으로 되살리지 않는다.

사용자는 Steam에서 만족도가 높고 유명한 관련 게임들을 2026-09-21 기준으로 조사해 참고할 작품과 재미의 구조를 찾도록 요청했다. RollerCoaster Tycoon은 관리하고 키우는 재미를 설명하기 위한 예시다. 특정 게임 채택, 규칙의 일괄 이식, 놀이공원 제작은 아직 확정하지 않았다. 비교 자료와 제안은 [마을 생활·경영 Steam 조사](마을_생활경영_스팀조사_20260921.md)에 별도로 둔다.

후속으로 사용자는 재배·채집·NPC 관계·집과 마을 발전이 어떻게 연결되는지와 재미·만족을 위해 준비할 것을 상세히 요청했다. [플레이 경험과 제작 준비 제안](마을_플레이경험과_준비사항_20260921.md)에 접속부터 생활·성장·재방문까지의 예시를 정리했다. 구체 NPC·가게·경제·부재 규칙은 제안이며 확정 기능이나 구현 결과가 아니다.

사용자는 이어 **각자 좋아하고 잘하는 활동으로 집과 마을을 발전시키는 방향을 승인**하고, **NPC가 플레이어별 성과를 이해해 다양한 방식으로 성취감을 느끼게 하는 설계**를 요청했다. [NPC 성과 이해와 인정 설계](마을_NPC_성과인정_설계_20260921.md)에 말·행동·공간 변화·보답·기억·선택적 소개와 Atlas 연결을 구체 제안으로 기록했다. 실제 NPC나 장기 기억 구현 완료를 뜻하지 않는다.

다음 기존 방향은 유지한다.

- 장소는 남산·한강·부산 등 **100~200년 뒤 한국의 명소**이며, 낮·밤·비·눈이 자연스럽게 변한다.
- 같은 소속의 **정원 16명**이 언제든 들어오는 마을이다. 활동마다 16명 전원 접속이나 협동을 요구하지 않으며, 혼자서도 NPC와 생활 활동을 즐길 수 있게 한다.
- 한국어를 재미있게 배우는 앱의 목적은 유지한다. 생활 활동에 한국어를 연결하는 구체안은 [Steam 조사 문서의 후속 교육 설계 제안](마을_생활경영_스팀조사_20260921.md)에 두며, 구현·학습 효과를 검증한 상태는 아니다.
- **팔 없는 펠트 몽글**, 아름다운 풍경과 가까운 재질, 의상·액세서리 표현을 유지한다.
- **PC는 홍보 중심의 최상위 시각 품질**, 모바일은 실제 구동 가능한 최상의 품질을 목표로 한다. 체감 차이가 작은 계산을 줄여 풍경·빛·재질에 여유를 쓰는 승인된 최적화 원칙을 유지한다.

이 변경은 현재 제품 방향과 문서 명칭의 수정이다. 아래 날짜별 구현·설치·성능 기록은 해당 시점의 기록이며 현재 실행 상태를 새로 확인한 결과가 아니다. 엔진 실행·빌드·렌더·서버 구현은 이번 조사 작업에 포함하지 않는다.

## 2026-09-21 최신 후속: Planet Coaster 2 참고와 모바일의 간단한 조작

사용자는 Satisfactory 언급 뒤 **Planet Coaster 2의 그래픽도 좋아 보인다**며 의견을 요청했다. 따라서 Satisfactory만을 고정된 최종 비교 기준으로 단정하지 않는다. 높은 그래픽 완성도 요구는 유지하고, Planet Coaster 2는 새 시각 후보로 함께 검토한다. 화풍·엔진·최종 성능 기준은 아직 결정하지 않았다. 아래 Satisfactory 항목은 바로 앞선 요청의 기록이다.

이어 사용자는 **주 플레이 플랫폼은 모바일**이며, 조작을 간단하게 만들고 3D 멀미를 우려한다고 밝혔다. PC의 홍보용 고화질 방향과 함께 모바일의 읽기·조작·지속적인 화면 안정성을 실제 플레이의 우선 조건으로 둔다.

### 사용자 확정: 그래픽 선택지는 ‘균형’과 ‘경험’ 두 가지

2026-09-21 사용자는 그래픽 설정을 **`균형` / `경험` 두 가지 선택지로만 제공**하도록 정했다. 균형은 발열·성능 등 최적화를 우선하고, 경험은 그래픽 품질을 우선한다. 사용자에게 저·중·고·울트라 등의 추가 화질 등급을 함께 노출하는 구성은 현재 방향이 아니다.

| 그래픽 선택 | 우선순위 | 화면 설명 제안 |
|---|---|---|
| 균형 | 발열·소모 전력과 안정적인 성능을 고려한 지속 플레이 | 발열과 성능을 고려해 편안하게 플레이해요. |
| 경험 | 해당 기기에서 구현 가능한 높은 그래픽 품질 | 풍경과 빛, 재질을 더 풍부하게 즐겨요. |

모바일 최초 실행의 기본값은 ‘균형’을 제안한다. ‘경험’에서도 눈에 보이지 않는 계산을 줄이는 기존 최적화 원칙을 유지하며, 기기별로 조명·그림자·반사·재질 세부·효과·렌더 해상도 등 내부 설정을 조정한다. 구체 수치·프레임 목표·발열·배터리 차이는 실기기 측정 전 미확정이고, 이 명칭이 현재 성능 달성이나 발열 해소를 보장하지 않는다.

그래픽 선택은 앞서 논의한 **‘넓게 보기 / 가까이 보기’ 시점 선택과 독립적**이다. 네 조합 모두 같은 월드·대상·날씨 상태·행동 목록·학습과 보상 규칙을 사용하도록 설계한다. 균형에서도 넓은 풍경의 구도와 색, 몽글·대상의 식별 가능성, 한국어와 UI의 읽힘을 우선 보존한다. 현재 반영은 설계 문서이며 실제 그래픽 설정 UI·렌더링 구현은 진행하지 않았다.

### 2026-09-21 이동·시점 후속: 바닥 탭 이동, 먼 시점 기본과 가까운 시점 선택

사용자는 **가고 싶은 바닥을 한 번 누르면 걸어가는 이동 방식**을 선호한다고 확인했다. 시점은 너무 가깝지 않게 최대한 멀리서 보는 느낌을 원하며, **먼 시점을 기본으로 두고 가까운 시점도 취향에 따라 선택**하는 구성을 제시하며 의견을 요청했다. 이 방향을 바탕으로 두 거리의 3인칭 시점을 권한다. 정확한 거리·높이·각도와 최종 화면은 실기기 비교 전 미확정이다.

- 기본 ‘넓게 보기’: 몽글 주변의 길·텃밭·건물과 넓은 풍경이 함께 보이는 먼 시점. 몽글을 구분할 수 있는 표식과 목적지 표시를 두며, 카메라의 방향·기울기를 안정적으로 유지한다. 멀리 보기 위해 바닥만 보이는 각도로 고정하거나 몽글과 길이 구별되지 않을 만큼 축소하지 않는다.
- 선택 ‘가까이 보기’: 몽글의 펠트·의상·꽃·시설 마감을 볼 수 있는 가까운 3인칭 시점. 첫인칭이나 강제 자유 회전을 기본 전제로 추가하지 않는다. 바닥 탭 이동과 오른쪽 행동 목록은 동일하게 유지한다.
- 전환과 유지: 화면의 간단한 전환 버튼으로 선택하고 설정을 기억하는 방안을 제안한다. NPC 대화나 채집 때문에 사용자가 고른 시점을 강제로 바꾸지 않는다. 전환 중 회전·긴 이동 연출을 피하고 움직임 감소 설정에서는 전환 애니메이션을 생략한다.
- 입력과 범위: 목적지 탭은 길찾기·도착점 표시·취소를 갖추고, 오른쪽 목록을 누른 입력이 바닥 이동으로 전달되지 않게 한다. 행동 목록은 카메라에 보이는 모든 물체가 아니라 **몽글이 실제 상호작용할 수 있는 근처 대상**을 기준으로 한다. 다른 사용자의 시점과 독립적으로 선택한다.

가까운 시점에 대한 사용자의 멀미 우려는 기록하되 먼 시점을 무조건 안전하다고 표시하지 않는다. 화면에는 거리 선택을 뜻하는 ‘넓게 보기 / 가까이 보기’를 제안하고, 카메라 흔들림·자동 회전·시야각 변화·전환 효과를 두 시점 모두에서 별도로 줄인다. 두 거리의 편안함은 실제 이동·읽기·날씨 장면에서 확인해야 한다. 먼 시점에서 더 많은 물체가 보이는 부하도 모바일에서 함께 측정한다. 현재 반영 범위는 설계 기록이며 게임 화면 구현·실기기 검증은 진행하지 않았다.

### 사용자 확정: 가까이 가면 오른쪽 고정 영역에 행동 목록 표시

사용자는 물 주기·수확·채집과 **NPC 대화 모두에서 대상 자체를 직접 터치하지 않고, 행동 가능한 대상 가까이 가면 화면 오른쪽 위에서 시작하는 고정 영역에 해당 행동 버튼이 자동으로 나타나는 방식**을 요청했다. 예: 마른 작물 근처에서는 `[물 주기]`, 익은 작물 근처에서는 `[수확하기]`, 채집 가능한 물체 근처에서는 `[채집]`, NPC 근처에서는 `[대화하기]`. 사용자는 해당 버튼을 눌러 행동한다. 이 요구는 이전의 ‘작물·NPC 직접 탭’ 제안보다 우선한다.

같은 범위에 대상이나 가능한 행동이 여러 개 있으면 **오른쪽 고정 영역에 선택지를 여러 줄로 함께 나열**한다. 시스템이 하나만 골라 숨기는 방식으로 만들지 않는다. 같은 종류의 채집물도 각 대상을 구별해 선택할 수 있어야 한다. 예: `꽃집 주인 — [대화하기]`, `토마토 — [수확하기]`, `산딸기(왼쪽) — [채집]`, `산딸기(오른쪽) — [채집]`이 함께 표시된다. 대상별 다중 목록과 NPC 적용은 사용자 후속 확정이다.

퀘스트 자동 이동 UI는 위치와 편리함을 설명하는 비유로 이해한다. 근접만으로 자동 수확하거나 퀘스트를 자동 수행하는 기능을 이 행동 목록의 요구에 포함하지 않는다. 이동·시점은 위 후속의 바닥 탭 이동과 두 거리 선택 방향을 따른다.

구현 시 다음 세부를 제안한다. 각 줄에 대상 이름과 행동을 함께 표시하고, 선택한 실제 대상은 은은하게 강조한다. 같은 이름의 대상은 위치 설명이나 표식 등으로 구별한다. 조금 움직일 때마다 줄 순서가 바뀌지 않게 유지하고, 손가락이 닿은 줄의 대상·행동은 입력 완료까지 고정한다. 다른 사용자가 먼저 수확했거나 범위를 벗어났으면 상태를 갱신하되, 사라진 줄의 자리에 들어온 다른 대상에게 이전 입력을 적용하지 않는다. 목록이 길어지면 화면을 덮지 않는 높이 안에서 세로 스크롤하고, 추가 항목이 있음을 표시한다.

목록은 오른쪽 위의 같은 자리에서 아래로 펼쳐지며 기기의 화면 잘림 영역·상단 메뉴·채팅과 겹치지 않게 배치한다. 행동을 마치거나 대상을 벗어나면 해당 줄을 갱신하고, 가능한 행동이 없으면 목록을 숨긴다. 실제 버튼 크기·여백·한 번에 보이는 줄 수는 휴대폰에서 확인할 세부다. 이번 확정은 조작 설계에 반영했으며 게임 코드·실기기 구현 완료를 뜻하지 않는다.

### 그 밖의 모바일 조작 제안 — 사용자 확정 전

- 위 두 시점 모두 이동과 시점 회전을 동시에 조작할 필요가 없게 한다. 과도한 추적 지연이나 작은 이동마다 출렁이는 동작은 피한다.
- 사용자가 선호한 바닥 탭 이동과 별도로 산책용 가상 스틱 하나를 선택 대안으로 둘 수 있다. 작물·채집물·NPC의 직접 터치는 필수가 아니며, 가까이 가면 위에서 확정한 오른쪽 행동 목록으로 조작한다.
- 도구는 선택한 행동에 맞춰 자동으로 든다. 수확 연타는 범위 선택 후 실행으로 줄일 수 있다. 어떤 작물·수량·재료를 고를지 같은 한국어 과제의 핵심 판단은 자동화하지 않는다.
- 꾸미기는 별도 모드에서 물건 선택→위치 지정→필요하면 회전→확정으로 구성한다. 지면 부착·배치 보조·미리보기·취소·되돌리기를 제공한다. 공동 구역은 서버 권한·저장 검증을 거치며 개인 편집 때문에 마을 전체 시간을 멈추지 않는다.
- 대화 중 내 캐릭터와 카메라는 멈추고, 문장은 고정된 읽기 영역에 표시한다. 글자 확대·음성 반복·문장 단위 진행·선택적 번역을 제공한다. 글을 읽는 도중 다른 사용자의 말풍선·자동 카메라 연출이 가리지 않게 한다.
- 기본 동선 자체에서 풍경이 아름답게 보이도록 구도를 만든다. 전망대 등의 ‘풍경 보기’는 선택 기능으로 두고, 더 낮고 넓은 시점이나 자유 시점을 제공할 수 있다. 자동 회전·강제 이동 연출은 기본으로 삼지 않으며 전환 생략과 원래 시점 복귀를 제공한다.

### 화면 움직임과 확인할 한계

[Microsoft XAG 117](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/117)에 따라 자동 카메라 이동, 흔들림, 시야각과 움직이는 배경의 영향을 고려한다. 기본값에서 걸음에 따른 상하 출렁임·카메라 흔들림·모션 블러·달릴 때 시야각 확대를 제외하고, 수동 시점 감도·줌·움직임 감소 설정을 마련하는 안을 제안한다. 급격한 회전·확대와 벽에 부딪힐 때의 카메라 도약도 실제 동선에서 확인해야 한다. 모든 사용자의 멀미가 사라진다고 보장하지 않는다.

[Microsoft XAG 107](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107)을 참고해 연타·오래 누르기·동시 입력·복잡한 제스처에 단순한 버튼 대안을 제공한다. 줌이나 회전에 두 손가락 입력을 쓰더라도 버튼 대안을 남긴다.

모바일은 정지 화면만 비교하지 않고 지원 대상 실기기에서 이동·대화·꾸미기·날씨 변화·16인 밀집을 확인한다. 프레임의 일관성과 장시간 발열도 함께 측정한다. 초보자·화면 움직임에 민감한 사람을 포함한 사용성 검증 전이며, 특정 30/60fps 수치만으로 편안함을 보장하지 않는다. 카메라·조작 차이는 PC와 모바일의 공유 월드·게임 판정과 분리해 설계한다. 이번 후속은 문서 설계만 진행했다.

## 2026-09-21 앞선 요청: Satisfactory를 최소 PC 시각 목표로 지정

사용자는 **PC 버전이 최소한 Satisfactory 정도의 그래픽 완성도를 갖추기를 원한다**고 밝혔다. 이는 현재 시제품 품질의 승인이나 성능 달성 보고가 아니라 앞으로의 최소 시각 목표다. 공장·외계 행성의 화풍이나 생산 시스템을 그대로 채택하는 결정은 아니다. 미래 한국의 찬란한 풍경과 팔 없는 펠트 몽글은 유지한다. 참고 원작: [Satisfactory 공식 Steam 상점](https://store.steampowered.com/app/526870/Satisfactory/?l=english).

실제 제작에서는 풍경의 깊이·환경 밀도·빛과 대기·가까운 재질·이동 중 표현 안정성을 나눠 비교하는 방안을 제안한다. 특정 엔진 설치나 정지 이미지 한 장으로 달성을 판단하지 않는다. 같은 장소의 시간·날씨 변화, 장식과 캐릭터가 모인 상태, 실제 PC 해상도·프레임·하드웨어 조건의 확인이 필요하다. 모바일은 별도의 실기기 품질 목표를 갖는다.

사용자는 추천한 다섯 모티브(Stardew Valley, Fields of Mistria, My Time at Sandrock, Farm Together 2, Parkitect)를 함께 적용할 수 있는지와 한국어 교육에 어색한 부분이 있는지 검토를 요청했다. 다섯 게임 전체 채택은 확정하지 않았다. 현재 제안은 같은 농사·재료·NPC·시설·저장 체계를 공유하는 생활 흐름으로 통합하고, 주문·대화·의뢰·역할 조율·주민 후기에서 한국어를 실제로 사용하게 하는 것이다. 상세 비교와 교육 검증 조건은 [조사 문서 후속](마을_생활경영_스팀조사_20260921.md)에 기록한다.

## 2026-09-21 후속: PC 고화질과 동적 시간·날씨

사용자는 모든 배경을 남산·한강·부산 등 **100~200년 뒤 한국의 명소**로 만들겠다는 방향을 재확인했다. 각 장소에서 낮·밤·비·눈이 자연스럽게 변하고, 그림에서 느꼈던 감동을 실제로 존재하는 듯한 공간에서 경험하는 것이 목표다. 출시 플랫폼은 **PC와 모바일의 크로스플랫폼**이며, PC의 높은 시각 품질을 우선하고 모바일은 기기에 맞는 표현 차이를 허용한다. 앞선 시제품의 품질은 여전히 최종 기준이 아니다.

같은 날 후속으로 사용자는 **PC를 주로 홍보에 활용하고 이용자는 많지 않을 것으로 예상**한다고 밝혔다. 현존 최상위급 그래픽카드를 기준으로 삼아도 되며, PC는 폭넓은 사양 대응보다 현재 구현 가능한 최상의 사실감과 아름다움을 우선한다. 모바일은 실제 구동 가능한 범위에서 최상의 품질을 목표로 한다. 이는 품질 우선순위의 확정이며, 특정 장비 구매·GPU 대여·무거운 제작 재개를 요청한 것은 아니다.

사용자는 16인 마을이 이 품질을 방해하는지 판단을 요청했다. **16인 구성을 폐기하거나 인원수를 줄이라는 결정은 없었다.** 현재 권고는 16인을 유지하고, 같은 화면에 모인 캐릭터·의상·펠트·그림자·장식의 부하를 측정하는 것이다.

### 사용자 승인: 체감 품질에 계산을 집중하는 최적화

사용자는 위 논의의 최적화 방식을 캡처로 다시 제시하며 환영한다고 했고, 특히 PC에서 사용자 만족도를 높일 것으로 예상했다. **눈에 보이는 차이가 작은 계산을 먼저 줄여 확보한 여유를 더 좋은 풍경·조명·재질에 사용하는 방식**을 제작 기준으로 승인했다. 만족도 향상은 사용자 기대이며 실제 측정 결과는 아니다.

- 가까이 보이는 몽글은 섬유·눈·의상 마감을 충분히 살린다.
- 멀리 있는 캐릭터는 화면에서 구별되지 않는 미세한 섬유 계산을 줄인다.
- 꾸미기 아이템은 아름다움을 유지하면서 재질과 조명 사용 기준을 정한다.
- 넓은 풍경을 구성하는 산·도시·하늘의 품질을 별도로 유지한다.
- 16인 인원수를 줄이기 전에 위 방식으로 불필요한 계산을 정리한다.

실행 시에는 거리뿐 아니라 화면에 보이는 크기와 접사·확대 시점을 함께 고려하고, 캐릭터와 의상의 식별 가능한 형태·색을 보존한다. 표현 단계가 전환될 때 형태가 갑자기 튀거나 섬유·그림자가 깜빡이는지, 줄인 요소가 반사·그림자를 통해 풍경에 영향을 주는지도 확인한다. 같은 시점의 화면과 이동 영상을 비교해 아름다움·움직임의 안정성·성능을 함께 판단하는 것이 이 승인 방향의 구현 해석이다. 구체적인 거리·세부 수준·프레임 목표는 실측 전 미확정이다.

이번 승인은 최적화 방향에 대한 것이며, 최종 엔진 선택·실제 구현 완료·발열 이후 무거운 제작 작업 재개를 뜻하지 않는다.

### 현재 추천안 — 최종 엔진 선택 전

- PC의 동적 조명·반사·대기와 정밀한 환경 표현을 우선 비교할 엔진으로 Unreal Engine 5를 권한다. 2026-09-21 확인한 [5.8 공식 발표](https://www.unrealengine.com/news/unreal-engine-5-8-is-now-available)의 정식 기능과 실험 기능은 구분한다. Unity를 폐기하거나 두 엔진의 비교를 완료했다는 뜻은 아니다.
- 풍경의 구도·색·지형의 겹침을 콘셉트에서 먼저 정한 뒤, 실제 이동 동선과 여러 시점으로 확장한다. 빛과 재료는 물리적으로 설득력 있게 표현하되 아름다운 미래 한국의 창작적 구성을 유지한다. 높은 해상도·후처리·엔진 교체만으로 품질을 보장하지 않는다.
- 가까운 펠트와 팔 없는 몽글은 기존 승인 방향이다. 사실감을 높인다는 이유로 이 정체성을 삭제하지 않는다. 원경의 회화적 감동을 정지 그림 한 장에 고정할 필요는 없으며, 시차와 시간·날씨에 반응하는 입체 풍경으로 옮기는 방법을 제안한다. 자연물에 적용할 펠트의 범위와 사실적 재료의 비율은 시각 비교가 필요한 미확정 세부다.
- 플레이어가 다가가는 근경·중경은 입체 구조로 제작한다. 접근하지 않는 먼 배경에는 단순화한 3D와 깊이별 그림을 혼합할 수 있다. 특정 빛이 그려진 배경은 낮·밤·비·눈 변화에 그대로 대응하지 못하므로 상태별 자산 또는 재조명 가능한 표현이 필요하다.
- 비는 입자뿐 아니라 흐린 하늘·젖는 표면·웅덩이·차양 아래의 건조함·소리·점진적인 마름까지, 눈은 내리는 모습과 쌓임·녹음까지 별도로 설계한다. 같은 소속 16명이 공유하는 시간·날씨 상태와 각 기기의 시각 효과 품질을 분리한다.
- [Unreal 모바일 렌더링 기능표](https://dev.epicgames.com/documentation/unreal-engine/rendering-features-reference)상 일반 모바일 경로는 Nanite·Lumen·볼류메트릭 구름을 지원하지 않는다. 모바일용 모델·재질·조명·하늘 표현을 처음부터 함께 준비한다. 공간·이동·장비·게임 판정은 공통으로 유지하며 화질 설정만 낮추는 작업으로 보지 않는다.
- 3D Gaussian Splatting과 신경망 렌더링은 비교 연구 후보로 둔다. 2026년 [NVIDIA TRON 연구](https://research.nvidia.com/labs/sil/projects/tron/)는 재조명·재질 편집과 대화형 렌더링을 제시하지만, 확인 당시 코드는 공개 예정이었다. 이 연구가 16인 크로스플랫폼 게임의 날씨·충돌·아바타·저장까지 검증한 상용 엔진이라는 뜻은 아니다.

### 16인과 PC 최고 품질을 함께 설계하는 방법 — 제안

- 일반적인 네이티브 실행에서는 각 기기가 자기 카메라의 화면을 렌더링한다. 서버는 위치·행동·장비 식별자·공유 날씨 등 필요한 상태를 동기화하고, 화면의 세부 표현은 기기별로 계산한다. 16명이 접속했다고 한 기기가 16명분의 전체 화면을 렌더링하거나 모바일의 화질로 PC를 낮춰야 하는 것은 아니다. [Unreal 네트워킹 공식 설명](https://dev.epicgames.com/documentation/en-us/unreal-engine/networking-overview-for-unreal-engine).
- 다른 캐릭터의 애니메이션·의상·섬유·그림자·반사와 사용자 배치 소품은 추가 GPU·CPU·메모리 비용을 만든다. 특히 레이 트레이싱에서는 변형되는 고밀도 캐릭터와 털의 처리 비용이 클 수 있다. 보이는 크기에 맞춘 세부 수준, 가까운 섬유의 정밀 표현, 장식과 재질의 제작 기준을 함께 둔다. [레이 트레이싱 성능 가이드](https://dev.epicgames.com/documentation/en-us/unreal-engine/ray-tracing-performance-guide-in-unreal-engine).
- PC 최고 화질의 실시간 탐험, 모바일 실제 플레이, 같은 자산을 활용한 홍보용 영상·스틸 출력을 구분한다. Unreal Path Tracer와 Movie Render Queue를 활용하는 영상 출력은 고품질 후보이며, 그 결과를 16인 실시간 플레이 성능으로 보고하지 않는다. 재질·물·대기의 표현 차이도 별도 확인한다. [Path Tracer 공식 설명](https://dev.epicgames.com/documentation/en-us/unreal-engine/path-tracer-in-unreal-engine).
- PC의 4K 출력·30fps 화질 우선과 별도 60fps 설정, 모바일의 지속 가능한 30fps와 상위 기기 60fps는 비교 목표의 예시다. 사용자 승인 사양이나 현재 달성 수치가 아니다. 실제 내부 렌더 해상도·업스케일링·프레임 생성 여부를 함께 기록하고, 최상위 GPU에서도 프레임·메모리 한도를 확인한다.
- 시간·강수·적설 상태는 공유하되 게임에 영향 없는 빗방울·섬유·잎사귀 각각을 서버에서 동기화하지 않는다. 이동 경로·충돌·상호작용 결과는 기기 사이에 일치하도록 설계한다. 같은 카메라·장소에서 1/8/16명, 서로 다른 의상과 장식, 야간·비·눈을 비교해 병목을 판단한다.
- 일인용 그래픽 시안과 함께 최소한의 네트워크 시험도 초기에 진행한다. 최종 미술이 끝난 후 처음 멀티플레이를 붙이는 순서를 기본 계획으로 삼지 않는다. 현재 문서는 설계 제안이며 실제 서버·16개 세션의 성능이 구현 또는 검증된 것은 아니다.

첫 비교 단위로 남산 전망 구간 하나를 제안한다. 같은 공간에서 걷기·시점 회전·근접 재질과 맑은 낮·노을·밤·비·눈을 비교하고, PC 실제 실행 화면과 모바일 실기기 결과를 각각 확인한다. 정지 렌더와 실시간 플레이 품질, 16개 캐릭터의 렌더링 부하와 실제 16개 세션의 동기화 시험도 구분한다. PC 최소·권장 사양, 목표 해상도·프레임, 모바일 지원 하한은 측정 전 미확정이다.

이번 후속은 방향 기록과 기술 조사다. 모델 제작·엔진 실행·렌더·빌드를 재개하지 않았다. 발열 이후의 무거운 작업 중단과 후속 제작 요청 대기 상태는 유지한다.

## 사용자 확정 방향

사용자는 **모든 풍경을 100~200년 뒤 한국의 대표 명소로 디자인**하고 싶다고 했다. 같은 남산도 지금과 크게 달라진 모습을 아름답고 찬란하게 표현한다. 원문의 ‘한국의 마스코트 장소’는 문맥상 한국을 대표하는 장소·명소로 이해했다. 이 풍경 방향을 처음 논의할 때의 RPG 기획은 2026-09-21 기각됐으며, 장소와 시각 품질 방향은 마을의 생활·경영 경험으로 이어간다.

- 장소의 출발점은 한국의 실제 명소다. 산·해변·강·거리·건축물 등을 미래의 탐험 공간으로 재해석한다.
- 시대 범위는 지금에서 100~200년 뒤다. 2026년 기준 2126~2226년이며, 게임 전체를 한 연도로 고정하는지는 아직 결정하지 않았다.
- 아름다운 배경과 높은 그래픽·질감 품질을 우선한다. 가까운 재질의 펠트 표현, 멀리 펼쳐지는 회화적 풍경은 앞선 승인 방향을 유지한다.
- 팔 없는 몽글의 형태는 유지한다.
- 후속 사용자 요구: 각 명소는 **같은 소속의 정원 16명만 함께 돌아다니는 전용 월드**다. 정해진 수업/행사 시간이 아니라 언제든 들어가 함께 탐험할 수 있어야 한다. 의상·액세서리 커스터마이징은 이동하는 캐릭터에 그대로 적용되고 다른 소속원에게도 보여야 한다.
- 3D 남산 시제품을 본 뒤 사용자는 그래픽과 캐릭터 재질·전체 마감이 목표보다 크게 부족하다고 지적했다. **현재 산책의 그래픽은 최종 품질 기준으로 승인되지 않았다.** 원래 콘셉트처럼 아름다운 공간이 목표이며, ‘100배’라는 표현은 계량한 성능 배수가 아니라 큰 품질 도약 요구로 기록한다.

이 결정은 미래 한국 마을의 장소·풍경 방향이다. 기존 회사 웹사이트·브랜드·이미 만든 미니게임 전체를 일괄 변경하라는 결정으로 확장하지 않는다.

## 구체화 제안

아래는 이번 방향을 구현하기 위한 창작 제안이다. 특정 건축·색·지역 목록을 사용자가 승인한 것으로 기록하지 않는다.

### 장소마다 남길 단서와 큰 변화

각 지역에서 ‘여기가 어디인지 느끼게 하는 단서’와 ‘100~200년의 변화를 보여 주는 공간 구조’를 함께 정한다. 단서는 산과 해안선, 건축의 실루엣, 돌과 식생, 지역의 빛일 수 있다. 기존 건물을 모두 그대로 보존해야 한다는 규칙은 아니다.

미래의 변화는 건물 장식뿐 아니라 사람이 걷는 높이, 자연과 도시의 관계, 전망과 이동 경로, 재료와 조명에 드러나게 한다. 숲의 산책길·강의 정원·해안의 구조물·천문 공간은 서로 다른 구도로 만든다.

| 지역 창작안 | 장소를 알아보는 단서 | 미래 공간의 제안 |
|---|---|---|
| 남산 · 하늘정원 | 숲으로 덮인 산과 서울타워의 실루엣, 도시를 바라보는 전망 | 숲 사이 여러 높이에 이어진 정원과 얇은 전망 구조물, 반투명한 빛의 지붕, 넓어진 도시의 녹지 |
| 경주 첨성대 · 별의 들판 | 첨성대의 돌 실루엣과 낮은 지평선 | 옛 관측의 기억을 둘러싼 거대한 천문 정원, 밤의 지면과 하늘을 잇는 별빛 길 |
| 부산 광안리 · 물빛 정원 | 해변과 교량의 긴 선, 열린 바다 | 파도와 빛에 반응하는 해양 정원과 반투명 구조물, 수평으로 펼쳐지는 산책 공간 |
| 제주 성산일출봉 · 바람 정원 | 화산 지형의 윤곽, 검은 돌, 일출 | 절벽의 결을 따르는 탐방로와 바람에 반응하는 정원, 새벽빛이 통과하는 얇은 구조물 |

**과거 제안 기록 — 2026-09-21 RPG 기각으로 전투 관련 제안은 현재 계획에서 제외한다.** 당시에는 다음 내용을 제안했으나 구현 요구나 승인 사항으로 이어가지 않는다.

> 한국어 성공으로 안개가 걷히거나 새 길과 전망이 열리는 전투 보상을 제안한다. 지역별 위치·방향·날씨·대화의 한국어를 활용하되, 아름다운 풍경에 접근하는 기회를 실제 한국어 급수 하나로만 제한하지 않는 방향을 권한다. 전투 규칙·콘텐츠·성장 방식의 세부는 아직 기획 단계다.

현재 생활·경영 경험에서 한국어와 활동·성장을 연결하는 방식은 별도로 설계한다.

### 재질과 빛

- 가까운 풀·꽃·상호작용 소품은 섬유와 두께, 접촉 그림자가 보이는 펠트다. 지역마다 형태와 색·밀도를 달리한다.
- 물과 유리 등은 각각의 반사·투과 특성을 살린다. 펠트 방향을 모든 재료를 같은 표면으로 만드는 규칙으로 해석하지 않는다.
- 원경은 공기와 빛의 층, 넓은 하늘, 지역 고유의 지형으로 거리감을 만든다. 가까운 섬유 표현을 멀리까지 확대하지 않는다.
- 미래 남산의 따뜻한 새벽은 첫 시안의 선택이다. 모든 지역을 같은 노을과 같은 색으로 고정하지 않는다. 밤도 별과 물의 빛으로 찬란하게 표현할 수 있다.

## 2026-09-19 실제 3D 산책 구현

**「남산, 빛이 머무는 곳」**을 별도 `namsan.html`에 구현했다. 현재 로컬 빌드 주소는 `http://127.0.0.1:5194/namsan.html`이다. 팔 없는 몽글로 돌담정원 → 구름다리 → 하늘정원을 연속해서 걷고, 시점을 돌리거나 풍경 보기로 안내를 숨길 수 있다. 세 장소에 꽃·위치·조사에 관한 쉬운 한국어 문제를 배치했고, 오답 뒤 요청하는 힌트와 정답 설명을 제공한다.

걷는 길·언덕·다리·전망 건축·가까운 나뭇잎과 꽃·몽글은 실제 3D 메시다. 세밀한 하층 식생과 일부 중경 나무는 공간에 고정한 교차 투명 이미지 면을 사용한다. 먼 서울은 새로 제작한 파노라마와 곡면 배경으로 표현했다. 따라서 화면에 보이는 도시 전체를 걸어 다니는 오픈월드나 완성된 몬스터 전투 RPG는 아니다. 원래 콘셉트의 세부 형상을 그대로 복제한 것도 아니다.

가까운 펠트 재질·부드러운 접촉 그림자·따뜻한 아침빛·먼 산과 도시의 공기감을 한 장면에서 연결했다. 투명 유리 안내판은 화면 가장자리로 작게 배치했다. 휴대폰 조이스틱·점프·달리기, 좁은 화면의 아래쪽 문제 패널, 화면 배율 상한·그림자 축소·느린 프레임에 대한 해상도 조정·동작 줄이기 대응을 포함한다.

전체 자동 시험 94개(새 산책 모델 12개), 프로덕션 빌드, 실제 브라우저 정상 이동 완주·오답/힌트/정답·완료·시점 회전·PC 및 휴대폰 크기 화면을 확인했다. 실제 iPhone/Android의 장시간 성능·발열·멀티터치, 학습 효과는 측정하지 않았다. 공개 배포·서버·반 관리·결제와 연결하지 않았다.

## 시제품 피드백 이후의 제작 방향 — 제안

위 산책의 동작 검증과 사용자의 시각 품질 평가는 별개다. 현재 코드는 기능·공간 실험 자료로 보존하며, 같은 방식으로 지역을 늘린다고 목표 그래픽에 도달한다고 보지 않는다. 아래 제작 방법·엔진·수치 목표는 제안이며 사용자 확정 사항이 아니다.

원래 남산 그림의 핵심은 입체적인 산과 정원이 겹치는 중경, 높이 차이가 큰 전망 건축, 식생의 자연스러운 밀도와 빈 공간, 빛·그림자·안개가 분리하는 거리다. 지금의 단순한 지형/반복 형상·공유 재질·이미지 식생에 고해상도 질감과 후처리만 추가해서 같은 결과를 보장할 수 없다.

- 정밀하게 제작한 근경 모델과 재질을 실제 게임용으로 정리한다. 몽글은 팔 없는 형태를 유지하며 섬유 결·가장자리의 부드러운 반사·눈·바닥 접촉·변형을 함께 조정한다. 각 의상은 몸 변형에 맞는 구조와 관통 방지 검증이 필요하다.
- 꽃·돌담·수목·전망 건축은 목표 구도에 맞춰 제작하고, 거리별 간소화 모델과 압축 텍스처를 준비한다. 먼 산과 도시는 그림을 활용할 수 있지만, 다가갈 대상과 시차가 필요한 중경은 입체 구조로 만든다.
- 고정 환경의 조명 일부를 미리 계산하고, 캐릭터와 주요 움직임은 실시간 조명·그림자로 연결하는 방식을 검토한다. 모바일은 섬유 전부를 털 모델로 계산하기보다 표면 질감과 선택적인 윤곽 표현을 조합한다.
- 지역은 소속 전용 월드 안에서 이동하는 여러 구역으로 나누어 필요한 부분만 불러오는 방식을 제안한다. 모든 한국 명소를 한 번에 메모리에 올리는 거대한 무중단 지도를 기본 전제로 삼지 않는다.
- 기존 Babylon.js에서도 품질 개선 여지는 크다. 설치형 모바일 게임을 장기 중심으로 삼으면 Unity URP 네이티브 빌드를 비교 후보로 둔다. 엔진 교체만으로 미술 품질이 생기지 않으며 이번 요청에서 교체를 확정하거나 실행하지 않는다.

다음 검증 단위로 **30~60초 걸을 수 있는 전망 구간 하나, 몽글 한 모델, 의상 두 벌과 액세서리**를 제안한다. 콘셉트와 비슷한 시점의 실제 게임 화면, 가까운 재질, 시점 회전, 이동 중 의상, 실물 휴대폰의 프레임·메모리·발열을 함께 비교한다. 16개 캐릭터 렌더링 부하 시험과 실제 16개 접속 세션의 네트워크 시험도 분리한다. 해당 검증 전에는 그림과 동일한 360도 실시간 품질, 모든 휴대폰에서 같은 성능, 자동 제작만으로 최종 상용 미술 품질을 달성한다고 약속하지 않는다.

동시 접속·소속 검증·장비 소유·저장·재접속은 [코어 연결 메모](../../experiences/dokkaebi-express/art-direction/village-20260919/CORE-HANDOFF.md)의 후속 요구로 연결한다. 현재 남산에는 이 서버 기능이 구현되지 않았다.

## 2026-09-19 후속 결정: Unity URP와 Unreal 5 비교 구현

사용자는 설치형 Unity URP 시험을 요청한 뒤 **Unreal 5 버전도 함께 구현해 비교**하도록 요청했다. 위의 ‘엔진 교체 미확정’은 최종 제품 엔진 선택에 대해서는 유지되지만, 두 엔진의 별도 시험 제작은 현재 승인된 작업이다.

[엔진 비교 현황](../../experiences/namsan-engine-comparison.md), [Unity 프로젝트](../../experiences/namsan-urp/README.md), [Unreal 프로젝트](../../experiences/namsan-unreal/README.md)에 파일과 실행 절차를 연결했다. 같은 정원 FBX·팔 없는 몽글·의상·섬유 질감·원경 파노라마를 사용하며 두 엔진의 재질·조명과 모바일 설정을 별도로 구성한다. High/Mobile 정원은 각각 869,762/235,764삼각형으로, 보행면·재질을 유지한 모델 감축과 FBX 왕복 확인을 마쳤다.

**현재는 자산과 프로젝트 소스 준비 단계다.** Unity Editor 설치 오류와 Windows 권한 확인, Unreal 본체 설치·로그인·C++ 도구 준비가 남아 있어 두 엔진의 실제 컴파일·화면·플레이·휴대폰 성능을 검증하지 못했다. Blender 검토 렌더를 게임 엔진 실행 결과로 간주하지 않으며 목표 미술 품질 달성이나 최종 엔진 선택을 선언하지 않는다. 기존 웹 시제품과 다른 작업은 보존했다.
