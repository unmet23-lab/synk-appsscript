# 싱크타운 재방문 콘텐츠와 원고

2026-10-08 보강. ‘찻집 앞 작은 쉼터’의 첫 생활과 첫 후속을 경험한 뒤, 본인이 고른 활동을 계속할 수 있게 만드는 재방문 원고다. **기본 장면 24개, 취향별 이야기 묶음 3개**를 작성했다. 기존 RV01~09와 확장 RV10~24를 합한 원고 수이며 선택 A/B·언어 지원·다시 보기는 추가 편수로 세지 않는다. 상태·대사·선택·동작을 함께 제작할 원고이며, 어휘·음성·동작의 최종 검수, 구현, 실제 학생의 재미·학습 효과 확인은 완료되지 않았다.

## 1 범위와 제작 수량

| 묶음 | 현재 문서의 역할 | 수량을 읽는 방법 |
|---|---|---|
| [첫 생활 설계](싱크타운_첫생활구간_설계.md)와 [첫 원고](싱크타운_첫생활구간_원고.md#followups) | 네 입구와 각 입구의 첫 후속. C02B·C03B·C04B·사연의 자리 변경을 담당 | 유한한 첫 체험 묶음. 실제 상품 노출은 체험·정액 권한으로 확인하며 이 문서에서 다시 지급하지 않음 |
| [기존 사건집](싱크타운_생활사건_설계.md) | C01~C08과 후속 A/B 16개의 원형·완료 조건 | 기존 16개를 전부 새 대사까지 완성한 수량으로 세지 않음. 이 문서는 원형 ID·보상을 바꾸지 않음 |
| 이 문서 RV01~RV09 | 첫 후속 이후의 정액 이용 범위에서 직접 고르는 재방문 팩 | 초급 기본 원고 9개. 선택 A/B·도움·정지 표현·확장 역할을 각각 다른 새 장면으로 부풀리지 않음 |
| [확장 RV10~RV24](#continued-stories) | 기존 각 묶음의 세 장면 뒤, 같은 취향으로 고를 수 있는 실제 후속 다섯 장면씩 | 추가 원고 15개. 각 묶음 총 8개, 전체 24개. LS01·주민쌍 원고·첫 경로·공연은 이 합계에 넣지 않음 |

네 경로를 모두 경험해야 이 팩이 열리는 것은 아니다. 제작·사연 입구의 첫 후속 중 하나를 완료하면 묶음 A, 메뉴 입구의 첫 후속을 완료하면 묶음 B, 발견 입구의 첫 후속을 완료하면 묶음 C를 시작할 수 있다. 한 묶음의 세 장면만 골라도 이야기가 끝난다. 다른 묶음은 해당 첫 경로를 본인이 고른 뒤에 잇는다. 농사·음성 입력·자유 작문·선택 상품 구매는 어느 묶음의 선행 조건도 아니다.

주민 사연만 원하는 사람은 첫 사연과 그 후속 뒤 **RV01→RV02→RV03**을 그대로 이어 간다. 세 장면에서 물건을 나르고 준비하고 정리하는 것은 주민의 실제 행동이며, 플레이어는 바람을 듣고 방법을 선택한다. 직접 가구 제작·배치 조작을 선행으로 요구하지 않는다. 제작을 좋아하는 사람은 같은 허용 범위에서 미리보기·배치를 직접 다룰 수 있지만 더 좋은 관계 보답을 받지 않는다.

| 이야기 묶음 | 장면 | 실제로 이어지는 변화 |
|---|---|---|
| A. 함께 쓰고 다시 쉬는 자리 | RV01 도안 보기 → RV02 작업 준비 → RV03 끝난 뒤의 자리 | 그림을 보는 방식, 도구 준비 방식, 일이 끝난 뒤의 주민 행동이 연결됨 |
| B. 차를 건네고 돌려받는 사이 | RV04 건네는 방법 → RV05 내가 손님인 날 → RV06 잔이 돌아갈 곳 | 손님 응대 방식, NPC에게 받는 도움, 식기 보관과 다음 서빙 동선이 연결됨 |
| C. 나비와 함께 보는 정원 | RV07 실제 발견 → RV08 꽃 사이 비행 → RV09 관찰하는 사람의 길 | 관찰 사실, 꽃과 나비의 실제 위치, 주민의 산책과 안내 방식이 연결됨 |

RV03/RV06/RV09 뒤에는 각각 RV10~14/RV15~19/RV20~24가 후보가 된다. 확장의 마지막 장면 뒤에는 익숙해진 생활을 그대로 누릴 수 있다. 다음 이야기가 아직 없으면 새 의뢰가 있는 것처럼 표현하지 않는다. 공동 행사는 C08의 별도 후속이며 이 팩을 끝내기 위한 조건이 아니다.

## 2 모든 원고에 적용할 계약

- [세계 변화 정본](../싱크타운_행동과_세계변화_설계.md)의 개인 이야기·실제 인지·저장·반응 상태를 따른다. 첫 쉼터의 개인 편집 슬롯만 바꾸며 공용 지형·날씨·다른 계정의 배치를 바꾸지 않는다. 주민 간 전달도 화면에 나온 전달 또는 확정된 사건 근거가 있어야 한다.
- 대상·이전 갈래·현재 배치·재고·NPC 역할을 확인한 뒤 `available`이 된다. 기존 목록을 직접 열었을 때 `offered`, 수락 뒤 `accepted/active`, 실제 완료 조건 확정 뒤 `resolved`다. 뒤 장면은 후보로만 남고 자동으로 이어 시작하지 않는다. 자동 말걸기 하루 한 번 예산을 추가로 받지 않는다.
- 미전달 반응은 실제 렌더·정지 대안 확인 뒤에만 `delivered`다. 무효 대상·철거·동의 철회는 `cancelled`, 명시된 전달 기한 종료만 `expired`다. 시작 전 거절은 `declined`, 진행을 쉬면 `deferred`, 선행 대상·허용이 사라지면 `invalidated`로 구분한다. 실제 완료와 관람은 별도로 저장한다.
- 모든 내 차례에 **‘다시 보여 주세요 / 쉬운 말로 / 나중에 할게요 / 그만할게요’**를 둔다. 선택 타일만으로 완료하며 음성·텍스트는 선택이다. 시간 제한·실패음·오답 재료 손실은 없다. ‘다시 보여 주세요’는 기존 물건·행동을 가리키며 정답을 본 수행은 도움 사용으로 남긴다.
- 자동 언어 조정은 다음 장면 경계에서만 한다. 지금 읽는 문장·보기·선택 갈래는 학습 갱신으로 바꾸지 않는다. 사용자가 요청한 도움은 즉시 적용한다. 도움·거절·느린 응답 때문에 물건 품질·주민의 따뜻함·생활 결과를 낮추지 않는다.
- 표의 ‘선택’은 사용자에게 보일 실제 문구다. A/B 표시는 제작용이다. 실제 선택 전에는 두 결과의 그림을 나란히 보여 준다. 수락 전 미리보기는 재료·관계·배치를 바꾸지 않는다. 아무 말 없이 나가도 이미 확정한 상태는 남긴다.
- 자원은 [생활경제와 상품](싱크타운_생활경제와_상품_설계.md)을 따른다. 이 팩은 무료 기본 도구와 주민의 기존 소품을 재사용한다. 식음료는 실제 재고 또는 경제 계약으로 등록한 해당 이야기 준비분을 예약·소비하며, 없으면 기본 대안까지 확보한 뒤 제안한다. 원고 재생은 무한 음식·재료·수입을 만들지 않는다. 반복 생산의 수량·가격·시간은 여기서 추가하지 않는다.
- 주민 소유 소품은 개인 이야기의 사용 슬롯에 놓일 뿐 플레이어의 판매 가능한 소유물이 되지 않는다. 사용을 중단하면 기존 보관 자리로 되돌아간다. 원래 플레이어 소유물·차양·화분을 쓸 때는 실제 소유와 허용을 확인하고 복제하지 않는다.
- 결과는 같은 방문에 선택해서 볼 수 있다. 카메라·관람·종료를 강제하지 않는다. 떠났으면 다음에 실제 상태를 확인해 이어 보여 주며, 없었던 이용을 회상·편지로 만들지 않는다. 완료 뒤 추가 부탁·정리 노동은 자동 제시하지 않는다.
- 아래 ‘확장 역할’은 본인이 더 참여하고 싶을 때의 다른 역할이다. 접속 수·생활 성취 때문에 자동으로 중급 역할에 넣지 않는다. 같은 역할에 쉬운 선택 대안도 제공한다. 첫 장면의 문장만 길게 바꿔 새 콘텐츠라고 세지 않으며, 동일 생활 결과의 보상을 다시 지급하지 않는다.
- 제작용 논리 상태는 기존 API 필드의 존재를 뜻하지 않는다. 필요한 어휘·문형·듣기 음원·관측 항목이 검수되기 전에는 Strata 숙련의 확정 증거로 보내지 않는다. 생활 완료·도움 사용·독립 언어 수행은 나눠 기록한다.

## 3 묶음 A — 함께 쓰고 다시 쉬는 자리

<a id="RV01"></a>
### RV01 공방의 그림을 같이 보는 방법

**선행·목표:** 제작 또는 주민 사연의 첫 후속 완료. 공방 주인은 자신이 그린 물건의 그림을 사장님에게 보여 주고 싶고, 사장님은 차를 건네는 통로를 비워 두고 싶다. 기존 안내판 C02B를 다시 만드는 과제가 아니다. 작업 도안을 실제로 보고 이야기하는 새 용도를 정한다.

**자원·완료:** 공방 소유의 도안 한 장과 접이 받침, 찻집 기존 탁자를 사용한다. 둘 중 고른 도안 보기 슬롯이 유효하고 공방 주인과 사장님이 실제로 그림을 확인해야 완료다. 플레이어의 목재·천은 소비하지 않는다. 장면을 제안하기 전에 두 주민의 짧은 이동·영업 보조를 준비한다.

| 순서 | 말과 선택 | 화면의 실제 행동 |
|---|---|---|
| 1 | 공방 주인: “제가 그렸어요. 같이 볼까요?” / 선택: ‘볼게요’ · ‘나중에 볼게요’ | 공방 주인이 실제 도안을 펼친다. 미수락이면 원래 작업대로 돌아간다. |
| 2 | 사장님: “저는 이 길로 가요. 여기는 비워요.” | 음료를 들고 지나갈 기존 길을 한 번 보여 준다. |
| 3 | 공방 주인: “그림을 어디에 둘까요?” / A ‘세워서 봐요’ · B ‘탁자에 펴요’ · ‘지금은 안 할래요’ | A는 길 옆 받침에 세운 모습, B는 탁자 한쪽에 펼친 모습을 미리 보여 준다. 둘 다 통로를 비운다. |
| 4A | 공방 주인: “여기 세울게요.” / 선택: ‘좋아요’ · ‘다른 곳을 볼게요’ | 확정 뒤 도안을 세우고 두 주민이 앞에 서서 가리킨다. |
| 4B | 공방 주인: “탁자에 놓을게요.” / 선택: ‘좋아요’ · ‘다른 곳을 볼게요’ | 확정 뒤 도안을 펼치고 두 주민이 탁자 양쪽에서 그림을 살펴본다. |
| 5 | 사장님: “그림이 잘 보여요. 차도 지나갈 수 있어요.” / 선택: ‘같이 볼게요’ · ‘이제 쉴게요’ | 사장님이 비워진 길로 차를 나른다. 완료 뒤 다음 부탁은 띄우지 않는다. |

**현재·다음 방문:** `plan_view=standing/table`, 대상 슬롯·배치 개정, 두 주민의 확인 사실을 저장한다. A는 짧게 서서 설명하는 자리, B는 앉아서 도안을 비교하는 자리로 사용한다. 사용 가능한 때 공방 주인이 실제 도안을 가져오며 항상 펼쳐 둔다고 가정하지 않는다. 그림이 치워진 때는 빈 받침/탁자를 그림으로 칭찬하지 않는다.

**도움·확장 역할:** 기본 태그는 위/옆, 놓다, 보다, 길이다. ‘세워요’에는 세운 그림, ‘펴요’에는 펼친 그림을 바로 보여 준다. 선택 확장에서는 플레이어가 두 주민의 조건을 정리하는 배치 제안자가 된다. 사장님: “차를 들고 지나는 길이 필요해요.” 공방 주인: “그림 두 곳을 번갈아 가리키고 싶어요.” 입력 예: “탁자에 펴고 길은 비워요.” / 쉬운 대안: ‘탁자’+‘길 비우기’. 두 조건을 확인한 뒤 같은 유효 배치로 실제 이용하며, 독립적인 조건 통합 수행만 따로 관측한다.

**중단·변경·반복:** 복귀 문구는 “그림을 놓던 중이에요. 자리를 확인해요.” 도안 미확정 배치와 마지막 선택을 보존한다. 탁자가 치워졌으면 이전 미리보기를 취소하고 현재 가능한 받침을 고른다. ‘그만할게요’면 주민이 도안을 공방에 보관한다. 재개·A/B 변경은 소유물이나 최초 성과를 복제하지 않는다. RV02는 목록에서만 열린다.

**확인:** 통로가 막혔는데 주민이 관통하거나, 도안을 꺼내지 않았는데 두 주민이 봤다고 말하거나, C02B 안내판 완료를 다시 지급하면 실패다.

<a id="RV02"></a>
### RV02 다시 꺼내기 쉬운 작업 준비

**선행·목표:** RV01 완료. 공방 주인은 다음에 도안을 보여 줄 때 필요한 도구를 한꺼번에 찾고 싶다. 플레이어는 손이 많이 가는 준비를 자신에게 맞게 정한다. 이름표를 붙이는 C05A와 달리 **준비 동작과 보관 방법**이 바뀐다.

**자원·완료:** 공방의 기존 연필·집게·작업 받침을 쓴다. 모든 계정에 기본 도구 선택과 접근성 도움은 이미 제공한다. 여기서 얻는 것은 선택한 준비 묶음의 저장이며 도구 사용권 해금이 아니다. 준비 방식 저장 후 공방 주인이 그 방식으로 실제 도구를 꺼내 도안 옆에 놓으면 완료다.

| 순서 | 말과 선택 | 화면의 실제 행동 |
|---|---|---|
| 1 | 공방 주인: “다음에도 이 그림을 볼 거예요. 도구를 같이 둘까요?” / ‘정해 볼게요’ · ‘지금처럼 둘게요’ | 실제 연필과 집게를 기존 상자에서 꺼낸다. |
| 2 | 공방 주인: “연필하고 집게가 있어요.” / A ‘받침에 같이 놓아요’ · B ‘필요할 때 꺼내요’ | A는 한 받침을 꺼내는 동작, B는 기존 수납에서 필요한 것만 고르는 동작을 비교한다. |
| 3A | 공방 주인: “받침 하나만 가져오면 돼요.” / ‘이렇게 쓸게요’ · ‘다시 고를게요’ | 실제 도구를 받침에 넣고 도안 보기 자리까지 한 번에 가져온다. |
| 3B | 공방 주인: “필요한 것만 꺼낼게요.” / ‘이렇게 쓸게요’ · ‘다시 고를게요’ | 플레이어가 도안 고정/그리기를 고르면 집게/연필만 꺼낸다. 도구를 매번 전부 다시 고르게 하지 않는다. |
| 4 | 공방 주인: “다음에는 이렇게 준비할게요.” / ‘그림을 볼게요’ · ‘이제 쉴게요’ | 선택한 준비 방식으로 실제 도안 사용을 한 번 보이고 끝낸다. |

**현재·다음 방문:** `tool_prep=tray/on_demand`, 준비할 도구 묶음, NPC 보관 위치와 마지막 사용을 저장한다. 다음 도안 보기에서 A는 받침 하나, B는 이번 용도에 필요한 도구만 준비한다. 도구 소유는 공방에 남는다. 반복 생활의 준비 입력이 줄어든 것이 성취이며 다음 방문마다 선물을 주지 않는다.

**도움·확장 역할:** 기본은 같이/하나/필요하다. 그림을 선택하면 해당 도구가 강조되고 도움을 쓴 수행으로 남는다. 확장에서는 플레이어가 작업 설명자가 된다. 공방 주인: “그림을 고정할 때와 선을 그릴 때 필요한 것이 달라요. 준비 방법을 알려 주세요.” 입력 예: “고정할 때는 집게만 꺼내요. 그릴 때는 연필을 더 가져와요.” / 쉬운 대안: 작업 그림별 도구 두 칸 선택. 확인된 두 용도에 맞게 실제 준비가 바뀐다.

**중단·변경·반복:** 복귀는 “도구 준비 방법을 고르고 있어요.” 확정 전에는 기존 방식, 확정 후에는 저장한 방식부터 시작한다. 준비 중 끊겼으면 같은 도구 인스턴스를 읽고 새 도구를 지급하지 않는다. 언제든 기존 공방 행동 목록에서 방식을 바꿀 수 있다. RV03은 직접 선택할 후보로 남는다.

**확인:** 기본 도구·쉬운 도움을 RV02 보상으로 잠그거나, 자동 준비를 학생의 한국어 정답으로 기록하거나, 받침을 플레이어의 판매 재고로 넣으면 실패다.

<a id="RV03"></a>
### RV03 그림을 본 뒤에도 쉴 수 있게

**선행·목표:** RV02 완료. 공방 주인은 도안 보기를 마치면 일을 이어가고, 사장님은 그 자리를 다시 쉼터로 쓰고 싶다. 플레이어에게 치우는 일을 맡기지 않고 **끝난 뒤 무엇이 남을지** 두 주민과 정한다.

**자원·완료:** RV01의 도안·받침과 RV02의 도구만 쓴다. A는 도안과 도구를 공방으로 모두 가져가고, B는 길을 막지 않는 세운 도안만 짧은 구경 대상으로 남기며 도구는 공방으로 가져간다. 두 주민이 계획을 확인하고 실제 보관·좌석 이용이 끝나야 완료다. B가 현재 배치에서 불가능하면 A와 ‘현재 자리에서 다른 위치 보기’를 제공하며 억지로 세워 두지 않는다.

| 순서 | 말과 선택 | 화면의 실제 행동 |
|---|---|---|
| 1 | 사장님: “이제 여기서 쉬고 싶어요.” | 도안 보기 작업이 실제 끝난 탁자/받침을 가리킨다. |
| 2 | 공방 주인: “도구는 제가 가져갈게요. 그림은 어떻게 할까요?” / A ‘그림도 가져가요’ · B ‘그림만 남겨요’ · ‘나중에 정해요’ | A는 비워진 쉼터, B는 안전한 받침의 그림과 비워진 좌석을 미리 보여 준다. |
| 3A | 공방 주인: “다음에 볼 때 다시 가져올게요.” | 도구와 도안을 실제 보관하고 사장님이 빈 자리에 앉는다. |
| 3B | 공방 주인: “그림은 여기 둘게요. 도구는 가져가요.” | 그림만 남기고 도구를 보관한다. 사장님은 그림을 가리지 않는 좌석에서 쉰다. |
| 4 | 사장님: “이제 쉬어요.” / ‘여기 있을게요’ · ‘산책할게요’ | 쉬는 행동 또는 자유 이동으로 끝난다. 정리 확인 버튼·다음 일 질문은 없다. |

**현재·다음 방문:** `after_work=clear/view_only`와 실제 보관·좌석 상태가 남는다. 다음 도안 보기를 자발적으로 시작하면 RV02 준비 방식으로 꺼내고, 끝나면 RV03 방식으로 주민이 정리한다. 이는 주민에게 맡긴 기본 동작이며 매 접속에 작업을 새로 시작하지 않는다. B의 도안 보관을 철회하면 공방으로 돌려보내고 현재 관람만 닫는다.

**도움·확장 역할:** 기본은 가져가다/남기다/쉬다. 그림과 도구를 각기 가리켜 구별한다. 확장에서는 플레이어가 두 역할의 순서를 조율한다. 사장님: “탁자는 쉬는 데 쓰고 싶어요.” 공방 주인: “아직 그림을 보고 싶은 주민이 있어요.” 입력 예: “도구는 먼저 가져가고, 그림은 옆에 세워요.” / 쉬운 대안: ‘도구→공방’·‘그림→옆 받침’. 현재 유효한 옆 받침이 없는 경우 그 제안을 정답으로 강요하지 않는다.

**중단·변경·반복:** 복귀는 “그림을 본 뒤의 자리를 정하고 있어요.” 실제 보관이 끝난 물건을 다시 거두지 않는다. 미합의 상태에서 끝내면 공방 주인이 기존 기본 방식으로 물건을 보관하며 플레이어의 선택 성과는 만들지 않는다. 첫 세 장면은 여기서 완결하고 RV10은 본인이 고를 별도 후속이다. 이후 도안 보기·준비·쉼은 자발적인 익숙한 이용이며 새 퀘스트가 아니다.

**확인:** 플레이어가 나가려고 할 때 청소 의뢰를 자동으로 띄우거나, 공방에 보관된 도구가 쉼터에도 존재하거나, 이 묶음 완료로 집 방문 동의를 켜면 실패다.

<a id="pack-b"></a>
## 4 묶음 B — 차를 건네고 돌려받는 사이

<a id="RV04"></a>
### RV04 함께 건넬까, 나누어 건넬까

**선행·목표:** 메뉴 경로의 첫 후속 C03B 완료. 사장님은 음료와 곁들임을 손님에게 편하게 건네고 싶다. 만든 메뉴가 현재 준비되어 있으면 사용하고, 품절이면 사장님의 기본 메뉴를 사용하는 제안임을 먼저 말한다. 품절 복구 납품을 요구하지 않는다.

**자원·완료:** 해당 장면에서 실제 제공할 음료·곁들임, 기존 쟁반과 잔을 경제 계약으로 확보한다. A는 쟁반에 함께, B는 음료를 먼저 건네고 곁들임을 이어 놓는다. 주문과 제공 방식에 손님이 동의하고 실제 음식이 전달돼야 완료다. 안내판 C03B·C07A 제작과 별개의 **건네는 동작**을 정한다.

| 순서 | 말과 선택 | 화면의 실제 행동 |
|---|---|---|
| 1 | 사장님: “차하고 간식이 있어요. 건네 볼까요?” / ‘해 볼게요’ · ‘물어볼게요’ · ‘지금은 안 할래요’ | 실제 제공 가능한 메뉴를 놓는다. 기존 내 메뉴가 없으면 “오늘은 가게의 기본 차예요.”를 먼저 표시한다. |
| 2 | 손님: “저는 여기서 먹어요. 둘 다 괜찮아요.” / A ‘쟁반에 같이 드려요’ · B ‘차를 먼저 드려요’ | 현재 손님의 동의를 확인한다. 한 번의 수락을 영구 취향으로 저장하지 않는다. |
| 3A | 사장님: “같이 가져갈게요.” | 두 제공분을 쟁반에 올려 손님 자리로 옮긴다. |
| 3B | 사장님: “차 먼저 드릴게요. 간식도 가져올게요.” | 음료를 실제 건넨 뒤 곁들임을 같은 자리로 가져온다. 서빙 중 사용자에게 타이밍 조작을 요구하지 않는다. |
| 4 | 손님: “잘 받았어요.” / ‘편히 드세요’ · ‘저도 쉴게요’ | 손님이 실제 받은 것을 이용한다. 먹는 연출을 끝까지 봐야 보상을 받지는 않는다. |

**현재·다음 방문:** `service_style=tray/tea_first`, 현재 주문의 동의·재고 소비·제공 완료·본 동작을 분리한다. 다음에 같은 구성의 동의된 주문이 있을 때 선택한 방식을 제안하며 플레이어가 기본 응대로 유지할지 바꿀지 결정한다. 모든 손님에게 같은 취향을 전파하지 않는다.

**도움·확장 역할:** 기본은 같이/먼저/차/간식. 쟁반과 두 번의 전달 그림을 비교한다. 확장에서는 플레이어가 주문 확인자가 된다. 손님: “차는 지금 받고, 간식은 앉은 뒤에 받고 싶어요.” 입력 예: “차를 먼저 드리고, 자리에 앉으면 간식을 드릴게요.” / 쉬운 대안: ‘차 먼저’→‘앉기’→‘간식’. 이 조건을 선택한 실제 주문에만 적용하고 배경 타이머를 만들지 않는다.

**중단·변경·반복:** 복귀는 “차는 드렸어요. 간식만 남았어요.”처럼 실제 제공 단계 하나를 말한다. 둘 다 미제공이면 “건네는 방법을 고르던 중이에요.”다. 손님 요구가 바뀌면 미제공 반응을 취소하고 현재 동의와 남은 재고를 다시 확인한다. 제공한 음료를 취소로 돌려받아 재고로 복제하지 않는다. RV05는 선택 후보다.

**확인:** 품절인 내 메뉴를 제공했다고 말하거나, 중단 뒤 이미 건넨 차를 다시 차감하거나, 다른 기본 메뉴 제공을 내 레시피 공로로 세면 실패다.

<a id="RV05"></a>
### RV05 오늘은 내가 손님

**선행·목표:** RV04 완료. 사장님은 함께 정한 응대를 플레이어도 누리게 하고 싶다. 플레이어는 이번에는 준비하는 사람이 아니라 원하는 방식으로 받아 쉬는 사람이 된다. 농사·새 조리·선택 상품 구매를 추가로 요구하지 않는다.

**자원·완료:** 경제 계약에 등록된 이번 이야기의 **음료 한 몫과 곁들임 한 몫, 두 구성으로 된 플레이어용 제공 세트**를 제안 전에 실제 확보한다. RV04에서 이미 소비한 손님 몫을 가져오거나 복제하지 않는다. A는 쉼터 자리에서 받고, B는 공방 앞의 기본 휴식 자리에서 받는다. B는 집 방문이 아니며 공방 영업 동선과 보조 운영이 가능한 현재 장면에서만 제안한다. ‘함께’는 두 구성을 쟁반에 담아 전달하고, ‘차 먼저’는 음료 뒤 곁들임을 전달한다. 각각의 실제 제공을 저장하며 두 구성의 수령이 확정되면 완료다. 앉아 있거나 끝까지 먹어야 하는 의무는 없다.

| 순서 | 말과 선택 | 화면의 실제 행동 |
|---|---|---|
| 1 | 사장님: “이번에는 제가 드릴게요. 어디서 쉴까요?” / A ‘여기서 쉴게요’ · B ‘공방 앞에서 쉴게요’ · ‘지금은 안 마실래요’ | 현재 사용 가능한 두 자리를 그림으로 보여 준다. ‘안 마실래요’는 보류이며 관계를 낮추지 않는다. |
| 2 | 사장님: “차하고 간식은 이렇게 드릴까요?” / ‘지난 방법이 좋아요’ · ‘바꿔 볼게요’ | 이번 제공 세트와 RV04에서 실제 선택한 전달 방식을 그림으로 보여 준다. 그 사실을 모르면 ‘지난 방법’ 문구를 쓰지 않는다. |
| 3A | 사장님: “여기로 가져올게요.” | 쉼터 자리로 실제 이동해 제공한다. |
| 3B | 사장님: “공방 앞에 가져갈게요.” | 준비된 보조 운영을 확인하고 공방 앞 기본 자리로 이동해 제공한다. 공방 주인이 받았다고 대신 기록하지 않는다. |
| 4 | 사장님: “편히 쉬어요.” / ‘고마워요’ · ‘잠깐 볼게요’ · ‘이제 갈게요’ | 조용히 쉬기·관찰·종료 중 선택한다. 마시기·감사 문구 입력을 관계 보상의 관문으로 두지 않는다. |

**현재·다음 방문:** `rest_delivery=tea_area/workshop_front`, 이번 음료·곁들임 각각의 제공·사용한 잔의 위치·받은 도움을 기록한다. 선택한 휴식 장소를 고정 성격으로 추정하지 않는다. 다음 방문에는 그 자리의 기존 소품·한 번 함께한 기억이 남고, 새 음료나 곁들임이 접속마다 자동 생성되지는 않는다. 다음 제공은 정한 경제·이용 조건 안에서 본인이 요청한다.

**도움·확장 역할:** 기본은 여기/공방 앞/받다/쉬다. 장소 그림과 실제 길로 확인한다. 확장에서는 플레이어가 요청자 역할로 조건을 함께 전한다. “일하는 길은 비우고, 문 밖에서 잠깐 쉴게요.” 사장님: “문 밖 자리로 가져갈까요?” / ‘네, 그 자리요’·‘아니요, 쉼터로 갈게요’. 쉬운 대안은 장소+‘길 비우기’ 선택이다. 주민이 조건을 확인한 뒤 유효한 자리에서 실제 제공한다.

**중단·변경·반복:** 복귀는 모두 미제공이면 “차 받을 자리를 골랐어요.”, 음료만 제공했으면 “차는 받았어요. 간식이 남았어요.”, 둘 다 제공했으면 “이 자리에서 차와 간식을 받았어요.”다. 자리나 동선이 무효면 미제공 이동을 취소하고 다른 기본 자리 또는 나중에 받기를 제공한다. 실제 수령 전 종료는 남은 제공분 예약을 보존/해제하는 경제 계약에 따르고 완료를 위조하지 않는다. RV06은 물건과 실제 제공 완료가 확인된 뒤 본인이 고른다.

**확인:** 감사 응답을 하지 않았다고 보답을 취소하거나, 공방 앞 선택을 개인 집 초대로 해석하거나, 곁들임 재고 없이 ‘함께/차 먼저’의 완결을 보여 주거나, 재관람 때 제공한 음식을 새로 지급하면 실패다.

<a id="RV06"></a>
### RV06 다음에도 잔을 편하게 쓰도록

**선행·목표:** RV05의 실제 제공 완료. 사장님은 자기 잔을 다시 사용할 수 있게 정리하고, 공방 주인은 일하는 길을 비우고 싶다. 플레이어는 설거지·반납 심부름을 맡는 대신 **주민이 자동으로 처리할 보관 방식**을 정한다. RV05에서 공방 앞을 고르지 않았어도 사장님의 기존 손님용 잔을 놓을 수 있는 공방 측 기본 슬롯을 함께 확인한다. 플레이어가 그곳에서 마셨다고 말하지 않는다.

**자원·완료:** 찻집 소유의 기존 잔·기존 쟁반을 사용한다. A는 사용 뒤 사장님이 찻집으로 회수하는 방식, B는 공방 앞 허용된 잔 보관칸에 찻집 소유 잔을 두고 사장님이 기본 관리하는 방식이다. 실제 잔의 위치와 관리 역할이 한 번 확정·수행돼야 완료다. 첫 방문의 플레이어 음료를 다시 만들지 않는다.

| 순서 | 말과 선택 | 화면의 실제 행동 |
|---|---|---|
| 1 | 사장님: “잔은 제가 정리해요. 다음에는 어디에 둘까요?” | 실제 있는 잔과 두 보관 위치를 보여 준다. 원래 자리의 이용 이력은 있는 경우에만 언급한다. |
| 2 | 공방 주인: “이 칸은 비어 있어요. 길은 비워 주세요.” / A ‘가게로 가져가요’ · B ‘이 칸에 두어요’ · ‘지금처럼 쓸게요’ | B의 빈칸과 이동 경로를 실제 확인한다. |
| 3A | 사장님: “제가 가게로 가져갈게요.” | 잔을 쟁반에 올려 찻집의 실제 보관 위치로 옮긴다. 다음 제공은 그 위치에서 출발한다. |
| 3B | 사장님: “여기에 두고 제가 살필게요.” | 잔을 공방 앞 칸에 보관하고 공방 주인이 옆 통로를 지나간다. 다음 유효한 제공 때 사장님이 이 칸의 잔을 사용한다. |
| 4 | 공방 주인: “지나가기 편해요.” / ‘좋아요’ · ‘이제 갈게요’ | 플레이어에게 정리 과제를 남기지 않고 끝낸다. |

**현재·다음 방문:** `cup_return=shop/local_slot`, 실제 잔 인스턴스·찻집 소유·허용 슬롯·관리 NPC를 저장한다. 잔이 수거되거나 슬롯 허용이 철회되면 현재 보관은 찻집 기본 위치로 돌아간다. 과거 도움은 남지만 비어 있는 칸의 잔을 꺼내지 않는다. 기본 관리는 무료 도구로 NPC가 수행하고 플레이어의 접속·납품에 의존하지 않는다.

**도움·확장 역할:** 기본은 가져가다/두다/비다/길. 확장에서는 플레이어가 관리 역할을 확인하는 조율자다. 공방 주인: “여기에 두어도 되지만 저는 씻을 수 없어요.” 사장님: “제가 정리하고 다시 가져올 수 있어요.” 입력 예: “보관은 공방 앞에 하고, 정리는 사장님이 해 주세요.” / 쉬운 대안: 장소 그림+사장님 역할 선택. 합의 뒤 실제 소유·관리 역할은 그대로 보존한다.

**중단·변경·반복:** 복귀는 “잔의 보관 자리를 정하고 있어요.” 이동 완료 여부를 먼저 읽고 이미 옮긴 잔을 또 생성하지 않는다. 보류·거절이면 사장님이 기본 회수하고 별도 성과는 만들지 않는다. 나중에 본인이 방식을 바꾸면 동일 잔의 새 이동으로 처리한다. 첫 세 장면은 여기서 완결하고 RV15는 본인이 고를 별도 후속이다. 반복 주문은 준비된 운영 팩이나 기존 기본 생활을 따른다.

**확인:** 주민 소유 잔이 플레이어 인벤토리에서 팔리거나, 미반납 때문에 주민이 재촉하거나, 하나의 잔이 두 보관함에 존재하면 실패다.

<a id="pack-c"></a>
## 5 묶음 C — 나비와 함께 보는 정원

<a id="RV07"></a>
### RV07 잎에 앉은 작은 손님

**선행·목표:** 발견 경로의 첫 후속 C04B 완료. 연구원은 기존 식물 자리에서 실제 보이는 나비의 모습을 기록하고 싶다. 새로운 채집 요구가 아니라 **살아 있는 관찰 대상의 실제 행동**을 남기는 사건이다. 이 원고용 나비·앉기·날기·정지 대안이 준비된 콘텐츠만 등록한다. 현재 표현할 수 없으면 장면을 열지 않으며 특정 현실 날씨를 기다리게 하지 않는다.

**자원·완료:** 기존 수첩과 연구원 소유 관찰판을 쓴다. 나비를 포획·아이템화하지 않는다. A는 잎에 앉은 모습을, B는 꽃 사이로 움직이는 모습을 실제 확인하고 **해당 관찰 카드를 개인 수첩에 기록하면 완료**다. 온실 전시는 별도 선택이며 전시하지 않아도 같은 완료·후속을 얻는다. 같은 나비의 다른 보기로 최초 발견 보답을 반복하지 않는다.

| 순서 | 말과 선택 | 화면의 실제 행동 |
|---|---|---|
| 1 | 연구원: “여기 봐요. 나비가 있어요.” / ‘볼게요’ · ‘나중에 볼게요’ | 나비가 실제 잎에 앉아 있거나 현재 유효한 정지 상태를 보여 준 뒤 말한다. 빈 잎을 가리키지 않는다. |
| 2 | 연구원: “어떤 모습을 볼까요?” / A ‘앉은 모습을 봐요’ · B ‘날아가는 모습을 봐요’ | A는 잎을 가까이 보는 고정 시점, B는 준비된 짧은 비행 경로 또는 정지 연속 그림이다. 빠른 대상 추적 입력은 없다. |
| 3A | 연구원: “잎 위에 앉았어요.” / ‘잎 위에 있어요’ · ‘다시 보여 주세요’ | 현재 잎과 나비가 함께 보이는 관찰 기록을 남긴다. |
| 3B | 연구원: “꽃 쪽으로 가요.” / ‘꽃으로 가요’ · ‘다시 보여 주세요’ | 실제 끝난 이동의 출발·도착을 기록한다. 방향을 틀리게 고르면 다시 가리킬 수 있다. |
| 4 | 연구원: “수첩에 남겼어요. 어디서 볼까요?” / ‘제 수첩에만 둘래요’ · ‘온실에서도 볼래요’ | 개인 수첩 기록으로 완료하고, 온실을 선택한 경우에만 개인 온실에도 전시한다. 어느 선택도 공동 공개 동의가 아니다. |
| 5 | 연구원: “다음에도 조용히 볼 수 있어요.” / ‘조금 더 볼게요’ · ‘이제 갈게요’ | 머물기 또는 종료. 새로운 나비 의뢰를 자동으로 붙이지 않는다. |

**현재·다음 방문:** `butterfly_observation=perched/flight`, 실제 관찰 동작·지점·기록 공개 범위·연구원의 직접 확인을 저장한다. 나비가 현재 없는 때에는 카드만 남고 “지금 여기 있어요”라고 하지 않는다. 다음 실제 관찰은 준비된 현재 상태에서만 시작한다. 기록 열람은 새 발견이나 재관찰 수행으로 세지 않는다.

**도움·확장 역할:** 기본은 잎/꽃/위/가다/보다. 관찰 대상을 둘로 나누어 가리키고 재생 대신 정지 상태로 뜻을 확인할 수 있다. 확장에서는 플레이어가 기록 작성자가 된다. 연구원: “앉아 있을 때와 움직일 때 무엇이 달랐나요?” 입력 예: “처음에는 잎 위에 있었고, 뒤에는 꽃 쪽으로 갔어요.” / 쉬운 대안: 실제로 본 순서 그림 두 장 배치. 하지 않은 관찰은 문장 예시로 채워 넣지 않는다.

**중단·변경·반복:** 복귀는 “나비를 본 모습을 기록하던 중이에요.” 실제로 본 단계까지만 복원한다. 새 접속의 현재 나비가 없으면 이미 확인한 기록을 마무리하거나 현재 가능한 다른 관찰을 본인이 고른다. 과거 영상을 새 현재 관찰로 기록하지 않는다. 전시 철회는 개인 기록을 지우지 않고 사용 범위만 바꾼다. RV08은 목록에서 고른다.

**확인:** 관찰 카드가 나비·식물 아이템으로 바뀌거나, 나비가 없는데 발견 완료되거나, 개인 수첩만 선택해서 완료·RV08이 막히거나, 소리·움직임을 껐다고 관찰 결과가 줄어들면 실패다.

<a id="RV08"></a>
### RV08 꽃 사이에 남기는 길

**선행·목표:** RV07의 실제 관찰과 개인 수첩 기록 완료. 온실 전시·공개 공유는 선행 조건이 아니다. 연구원은 직접 함께 관찰한 나비가 꽃 사이를 이동하는 모습을 보기 쉽게 구성하고 싶다. 플레이어는 식물을 새로 기를 필요 없이 연구원이 이미 가진 꽃 화분의 배열을 고른다. 화분 배치와 준비된 게임 속 나비 경로의 연결만 규정하며 실제 생태 연구 효과로 홍보하지 않는다.

**자원·완료:** 연구원 소유의 기존 꽃 화분과 개인 이야기의 허용 슬롯을 쓴다. A는 화분을 길게 이어 나비가 두 끝 사이를 이동하게 하고, B는 가까이 모아 한 구역에서 여러 꽃을 오가게 한다. 유효 배치와 해당 나비의 실제 이동 확인이 있어야 완료다. 단순 배치 저장만으로 관찰한 행동을 만들지 않는다.

| 순서 | 말과 선택 | 화면의 실제 행동 |
|---|---|---|
| 1 | 연구원: “이 꽃들은 제가 기른 거예요. 자리를 바꿔 볼까요?” / ‘바꿔 볼게요’ · ‘지금처럼 둘게요’ | 연구원 소유 화분을 보여 준다. 플레이어가 기른 꽃이라고 말하지 않는다. |
| 2 | 연구원: “어떻게 놓을까요?” / A ‘길게 놓아요’ · B ‘가까이 모아요’ · ‘나중에 할게요’ | 두 배치와 대응하는 나비 이동 그림을 비교한다. 길·접근을 막는 위치는 저장 전에 알려 준다. |
| 3A | 연구원: “꽃을 따라 저쪽까지 가네요.” | 유효 배치 뒤 나비가 실제 연속된 꽃 지점을 이동한다. |
| 3B | 연구원: “여기서 꽃을 바꿔 앉네요.” | 유효 배치 뒤 가까운 꽃들 사이에서 실제 이동·앉기를 한다. |
| 4 | 연구원: “이 자리에서 볼 수 있어요.” / ‘여기서 볼게요’ · ‘전 자리로 돌릴게요’ · ‘이제 갈게요’ | 관찰 위치에 머물거나 직전 유효 개인 배치로 되돌린다. 보지 않은 동작을 봤다고 하지 않는다. |

**현재·다음 방문:** `flower_route=line/cluster`, NPC 소유 화분의 허용 배치·나비의 현재 이용 슬롯·관찰 사실이 남는다. A는 넓은 이동을 볼 수 있는 구성, B는 가까이 머무는 관찰 구성이 된다. 다음 방문의 실제 나비가 없어도 화분 배치와 과거 기록은 유지하며 나비 출석을 플레이어의 의무로 만들지 않는다. 다음 장면 RV09는 나비 출현 자체가 아니라 유효한 배치·관찰 계획을 전제로 한다.

**도움·확장 역할:** 기본은 길게/가까이/여기/저기. 확장에서는 플레이어가 관찰 계획자가 된다. 연구원: “한자리에서 보고 싶은 사람과 걸으며 보고 싶은 사람이 있어요.” 입력 예: “앉아서 보려면 모아 놓고, 걸으며 보려면 길게 놓아요.” / 쉬운 대안: ‘앉기→모으기’·‘걷기→길게’ 연결. 둘 중 본인이 실제 적용할 계획을 확인하고 배치에 반영한다.

**중단·변경·반복:** 복귀는 배치 전이면 “꽃 자리를 고르고 있어요.”, 배치 후 관찰 전이면 “꽃은 놓았어요. 움직이는 모습을 볼까요?”다. 현재 나비 이용이 불가능해졌으면 관찰을 나중에 보거나 배치 성과만 유지할 수 있고 관찰 완료는 미확정으로 남긴다. 소유자 허용 철회·슬롯 충돌 때는 NPC 기본 자리로 복구하며 화분을 지급품으로 바꾸지 않는다. 배열 변경으로 최초 발견 보답을 다시 주지 않는다.

**확인:** 플레이어 꽃 재고가 소모되거나, 배열과 무관한 경로만 재생되거나, 관찰을 완료하지 않았는데 RV07의 새 발견 수가 늘어나면 실패다.

<a id="RV09"></a>
### RV09 사람도 조용히 볼 수 있는 길

**선행·목표:** RV08의 유효 배치와 실제 관찰 완료. 연구원은 사장님에게 관찰 자리를 안내하고 싶고, 사장님은 차를 건네는 길을 비워 두고 싶다. 플레이어는 이번에 구경하는 사람에서 **관찰하는 사람의 이동을 정하는 안내자**가 된다. 첫 온실 안내판 C04B의 그림을 다시 고르는 일이 아니다.

**자원·완료:** 기존 좌석·기존 산책길·연구원 소유의 검수된 기본 관찰 카드를 사용한다. RV07에서 개인 수첩만 선택한 카드를 사장님에게 자동 공개하지 않는다. 플레이어 카드의 전시를 선택했다면 허용한 범위에서 그 카드를 사용할 수 있으며, 기본 카드의 출처를 플레이어의 관찰 공로로 바꾸지 않는다. A는 한 관찰 지점에서 조용히 보게 하고, B는 기존 길의 두 관찰 지점을 순서대로 걷게 한다. 실제 두 주민의 이동·안내가 유효한 경로로 끝나면 완료다. 현재 나비가 없으면 이미 기록된 관찰 카드임을 밝히고 현재 꽃 배치와 함께 안내할 수 있다. 없었던 나비 목격을 만들지 않는다.

| 순서 | 말과 선택 | 화면의 실제 행동 |
|---|---|---|
| 1 | 연구원: “이 자리를 알려 주고 싶어요. 같이 볼까요?” / ‘제가 알려 줄게요’ · ‘오늘은 구경할게요’ · ‘나중에 할게요’ | 현재 꽃 배열과 가능한 안내 경로를 보여 준다. ‘구경’은 주민의 기본 안내를 보고 끝내며 플레이어 안내 공로를 만들지 않는다. |
| 2 | 사장님: “차가 지나가는 길은 비워 주세요.” / A ‘여기서 함께 봐요’ · B ‘이 길을 따라 봐요’ | 한 지점 관찰과 두 지점 이동을 비교한다. 둘 다 서빙 동선을 침범하지 않는다. |
| 3A | 플레이어 선택 문구: “여기서 꽃을 봐요.” / 연구원: “제가 본 모습도 여기 있어요.” | 주민 둘이 유효 관찰 지점에 머물고 실제 카드/꽃을 본다. 나비가 있으면 현재 동작, 없으면 기록임을 표시한다. |
| 3B | 플레이어 선택 문구: “여기를 보고, 저쪽으로 가요.” / 연구원: “이 길로 걸어요.” | 주민들이 첫 지점에서 확인한 뒤 두 번째 지점으로 이동한다. 도달하기 전 다음 지점 목격은 기록하지 않는다. |
| 4 | 사장님: “길도 편하고 꽃도 보여요.” / ‘같이 있을게요’ · ‘이제 혼자 볼게요’ · ‘갈게요’ | 주민은 본인이 맡은 안내를 마치고 기본 일과로 돌아간다. 혼자 보기를 고르면 대화를 이어 걸지 않는다. |

**현재·다음 방문:** `garden_tour=single_stop/two_stops`, 개인 경로 개정·두 주민이 실제 본 대상·기록과 현재 목격의 구분을 저장한다. A는 짧은 머무름, B는 두 지점 안내가 가능한 상태가 된다. 연구원의 관찰 안내를 본인이 다시 요청하면 이 경로를 쓰며, 로그인 때 자동으로 주민 무리를 소환하지 않는다. 공개 공유·C08 행사·집 방문으로 전파하지 않는다.

**도움·확장 역할:** 기본은 먼저/다음/여기/길. 확장에서는 플레이어가 짧은 안내문 작성자가 된다. 연구원: “오늘 꽃은 볼 수 있지만 나비는 지금 없어요. 지난 기록과 구별해서 알려 주세요.” 입력 예: “꽃은 이 길에서 볼 수 있어요. 나비는 지난 관찰 카드에 있어요.” / 쉬운 대안: ‘지금 꽃’·‘지난 나비 기록’ 두 안내 타일. 현재 나비가 실제 보이는 경우에는 그 조건에 맞는 원고를 사용한다. 추가 글쓰기를 해야 생활 완료가 되는 것은 아니다.

**중단·변경·반복:** 복귀는 “첫 자리는 봤어요. 다음 자리로 갈 수 있어요.”처럼 실제 이동 단계만 안내한다. 길이 막혔으면 진행 중 경로를 무효로 하고 기존 유효 지점 하나로 마무리하거나 나중에 잇게 한다. 이미 본 대상의 관찰 보상을 다시 주지 않는다. 첫 세 장면은 여기서 완결하고 RV20은 본인이 고를 별도 후속이다. 이후 혼자 보기·기록 열람·기존 안내 요청은 편안한 반복으로 남는다.

**확인:** 사장님이 듣지 않은 연구원 정보를 알고 있거나, 지난 카드를 현재 나비 목격으로 기록하거나, 혼자 보기를 골랐는데 후속 대화가 따라오면 실패다.

<a id="coverage"></a>
## 6 5·10·30회는 소진을 확인하는 검사 편성이다

접속 횟수는 후보 해금·관계·보상 조건이 아니다. 아래는 **해당 첫 경로와 첫 후속을 마친 계정**에서 재방문 팩만 검사하는 편성이다. 1회는 검사자가 정한 한 생활 세션이며 실제 접속·현실 날짜·의무 일일 과제가 아니다. 같은 방문에 여러 장면을 끝내거나 쉬어도 된다. 익숙한 생활을 사이에 배치해 변화가 실제 남는지도 살피며 새 원고를 늦게 주려고 강제 쉬는 시간을 넣지 않는다.

| 검사 유형 | 강제하지 않는 활동 | 검사에 쓸 새 원고 순서 | 5회 시점 | 10회 시점 | 30회 시점 |
|---|---|---|---|---|---|
| 제작·꾸미기 또는 주민 사연만 원하는 사람 | 농사·메뉴·자유 말하기·다른 묶음. 직접 제작도 필수 아님 | RV01 → 02 → 03 → 10 → 11 → 12 → 13 → 14 | 새 4개+익숙한 이용 1회. 새 4개 남음 | 새 7개+익숙한 이용 3회. 새 1개 남음 | 새 8개+익숙한 이용 22회. 새 원고 0개 |
| 메뉴를 좋아하고 말하기·농사를 원치 않는 사람 | 음성·작문·재배·제작 | RV04 → 05 → 06 → 15 → 16 → 17 → 18 → 19 | 새 4개+익숙한 이용 1회. 새 4개 남음 | 새 7개+익숙한 이용 3회. 새 1개 남음 | 새 8개+익숙한 이용 22회. 새 원고 0개 |
| 발견·관찰만 고르는 사람 | 제작·판매·집 공개·음성·다른 묶음 | RV07 → 08 → 09 → 20 → 21 → 22 → 23 → 24 | 새 4개+익숙한 이용 1회. 새 4개 남음 | 새 7개+익숙한 이용 3회. 새 1개 남음 | 새 8개+익숙한 이용 22회. 새 원고 0개 |
| 여러 활동과 주민 사연을 고르는 사람 | 특정 경로 강제 없음. 검사 계정은 세 첫 후속을 준비함 | [§11의 실제 30세션 편성](#static-rehearsal) | 새 4개+익숙한 이용 1회. 새 20개 남음 | 새 8개+익숙한 이용 2회. 새 16개 남음 | 새 24개+익숙한 이용 6회. 새 원고 0개 |

단일 취향의 검사 편성은 `새1 → 새2 → 익숙한 이용 → 새3 → 새4 → 새5 → 익숙한 이용 → 새6 → 새7 → 익숙한 이용 → 새8` 뒤 기존 생활을 고른다. 익숙한 이용은 A의 도안 준비/관람/전시 변경, B의 자발적 찻자리/빈 잔 시범/조용한 이용, C의 현재 꽃 관찰/기록 열람/안내를 뜻한다. 무료 음료·관계·코인 재발급이 아니다. A/B를 모두 보는 재플레이·확장 역할·언어 변형을 새 편수로 세지 않는다. 다른 취향으로 바꾸라고 소진 알림으로 설득하지 않는다.

이 산출은 원고 수와 선행 그래프를 기준으로 한 **정적 편성 계산**이다. 실제 플레이 시간을 재거나 재미·신선함을 확인한 결과가 아니다. 출시 콘텐츠 등록 목표는 이 팩의 **24개 원고 전부와 연결된 현재/후속 동작**이며 실제 제공 수는 구현·원고 검수·접근성·저장 검증이 통과한 목록으로만 공개한다. 지금은 작성 24/구현·사용자 검증 미확인이다. 한 취향에는 8개, 여러 취향 전체에는 24개라는 유한량이며 30회 모두 새로운 사건이라는 약속은 할 수 없다. 구독 기간·업데이트 주기는 실제 후속 제작량과 [상품 계약](싱크타운_생활경제와_상품_설계.md)을 확인해 정한다.

후보가 끝났을 때 기존 행동 목록에는 현재 가능한 ‘자리 바꾸기 / 쉬기 / 관찰 기록 보기 / 기존 생활 다시 하기’를 보여 준다. 제약 때문에 가능한 일이 없으면 없는 새 일을 추천하지 않는다. 쉬는 동안 관계·기념 기록·소유물이 줄지 않으며, 종료 뒤 밀린 새 의뢰를 자동 생성하지 않는다.

## 7 제작 묶음과 검사

각 RV 장면은 원고·A/B·보류/거절·현재 대상 상태·실제 동작·정지 대안·도움·재개 문구를 함께 납품한다. 현재 초안에는 대사와 논리 상태가 있으나 실제 나비·도구·서빙·이동 동작, 그림, 음원, 현지화, 게임 저장 어댑터는 별도 제작 대상이다. 이름·목소리는 주민 정본의 역할을 따른다. 원고 작성 수와 검수 통과 수, 구현 수, 실제 학생에게 확인한 수를 같은 숫자로 보고하지 않는다.

| 검사 | 비교할 입력 | 통과할 결과 |
|---|---|---|
| 선행과 상품 | 한 경로만 완료, 다른 묶음 미완, 체험 끝·정액 만료 | 자기 묶음만으로 8개 원고 가능. 새 구독 장면은 권한 확인. 완료 기록·소유물 회수는 기존 계약 보존 |
| 원형 중복 | C02B/C03B/C04B에서 들어오기, 사건집·통합 화면·재방문 화면 재진입 | 동일 실제 사건·보답을 재지급하지 않음. 기존 16후속의 미작성 원고를 완료 팩으로 세지 않음 |
| 의미 있는 차이 | RV 각 A/B/거절을 같은 초기 상태에서 비교 | 보관·배치·역할·서빙·비행·안내 경로 중 정한 실제 차이가 남고, 거절을 플레이어 공로로 만들지 않음 |
| 인지와 관람 | 이동 전 종료, 정보 미전달, 카드만 관람, 결과 연출 넘기기 | NPC가 실제 받은 사실만 기억. 확정 완료와 미관람을 분리. 과거 기록을 현재 목격으로 바꾸지 않음 |
| 자원과 소유 | 품절, 응답 유실, 중복 재개, 주민 소품 회수 | 현재 재고만 소비. 한 번 소비·한 번 제공. NPC 소품의 개인 판매·복제 없음 |
| 편안한 진행 | 농사 거부, 음성 끔, 도움 사용, 오래 쉬기 | 선택 입력과 기본 자원으로 같은 결과. 관계 하락·납품 강제·정리 의무·밀린 알림 없음 |
| 개인화 안정성 | 대사 읽는 중 새 학습 기록, 수동 도움, 취향 정정 | 현재 장면 유지, 요청 도움 즉시. 다음 장면만 조정하며 희망 경로를 지우지 않음 |
| 개인 범위 | 집 초대 미허용, 공개 소개 거부, 다른 마을·다른 계정 | 개인 쉼터의 실제 기록만 반영. 집 방문·공동 행사·다른 주민의 인지를 자동 확장하지 않음 |
| 소진과 추천 | 위 네 유형의 5/10/30회 편성 | 남은 새 원고 수가 표와 일치. 없는 장면·단순 인사 변형을 새 콘텐츠로 추천하지 않음 |

학생 관찰에서는 대사를 많이 읽었는지보다 **내가 무엇을 바꿨는지 알아보는지, 주민의 도움을 받았다고 느끼는지, 다음 일을 스스로 고르는지, 끝낼 때 새 숙제가 남는 느낌이 없는지**를 확인한다. 쉬운 말·그림으로 원인을 가리킬 수 있게 하며 말하기를 평가의 필수 방식으로 두지 않는다. 자동 상태 검사와 이 관찰을 모두 마친 뒤에야 실제 전달 품질을 보고한다.

## 8 이미 아는 주민과 다른 일을 해 보는 후속 15장면

이 확장은 **관람자의 관점·함께하는 역할·소개하는 목적·주민이 이후 쓰는 방식**을 바꾼다. 각 취향에서 처음 세 장면 뒤 다섯 장면을 순서대로 고를 수 있다. 순서는 사실의 선행이지 방문 횟수·대기 일수 조건이 아니다. 하나를 마친 같은 방문에 다음 후보를 직접 골라도 된다. 중간에 그만해도 각 장면의 생활은 완결한다.

**공통 실행 원고:** 시작에는 `[해 볼게요] [나중에 할게요] [이번에는 안 할래요]`, 내 차례에는 `[다시 보여 주세요] [쉬운 말로] [그만할게요]`, 끝에는 `[조금 더 있을게요] [이제 갈게요]`를 제공한다. 거절 때 NPC는 아래 기본 대안을 실행하고 플레이어의 선택·기여로 저장하지 않는다. 기본 선택은 타일만으로 충분하다. 확장 문장은 같은 의도의 선택적 표현 예다. 도움은 실제 두 결과를 보여 주며 관계·보상·선택권을 줄이지 않는다. NPC 이동/물건 조작은 `active-world-time, offlineCompletion=blocked`, 선택은 `player-decision, blocked`다. RV20의 선택적 성장만 기존 T08 경과 시간 계약을 읽는다. 모든 장면은 개인 마을 안에서 실행한다.

**완료·인지:** 각 RV는 독립 `sourceEventId`와 실제 `completedContribution`을 남긴다. `knowledgeEvidence`에는 직접 참여/허용된 전달/실제 관람을 기록한다. LS01~03·PAIR01~03·RETURN01~02와 같은 실제 회차를 재연하면 해당 사건을 참조하고 새 RV 완료·새 이야기 수로 중복 계산하지 않는다. 아래 원고는 첫 자리 협의/첫 주문/첫 전시/첫 보답 다음의 다른 목적과 결과를 지정한다. 이 원고가 관계 점수·단계 숫자를 발급하지 않는다. NPC는 자기가 아는 사건만 회수하고 개인 수첩·집 초대 범위를 자동 공개하지 않는다.

<a id="RV10"></a>
### RV10 그림을 처음 보는 손님

**원인·목표:** RV03 완료 뒤 공방 주인이 도안을 처음 보는 연구원에게 보여 주고 싶다. 연구원은 이 도안의 쓰임을 아직 모른다. 설명부터 듣거나 먼저 상상하는 **관람의 순서**를 정한다. RV01의 도안 위치 결정과 별개다. 도안·받침은 공방 소유다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 공방 주인: “이 그림, 어떻게 보이나요?” 연구원: “창문 같기도 해요.” | 연구원이 실제 도안을 처음 본다. 도안은 구멍이 있는 작은 받침 그림이며 두 해석이 보이는 판본을 쓴다. |
| 2 | A `[쓰는 모습을 먼저 봐요]` / B `[생각을 먼저 들어요]` | A는 공방 주인이 기존 모형을 시범, B는 연구원이 그림의 구멍·받침 부분을 짚는다. 맞히기 퀴즈가 아니다. |
| 3 | A 공방 주인: “여기에 물건을 올려요.” / B 연구원: “밖을 보는 창인 줄 알았어요.” | A는 받침 사용 확인, B는 해석 그림과 실제 용도를 나란히 보고 차이를 확인한다. 의견을 오답으로 지우지 않는다. |
| 4 | 공방 주인: “다음에도 이렇게 보여 줄까요?” `[이 방식으로 보여 줘요] [이번만 해요]` | 실제 한 번의 관람으로 완료, 이후 방식 저장은 선택이다. |

**현재·후속:** `first_view=demo/guess_first`와 실제 본 부분만 남는다. 다음 요청 관람의 질문/시범 순서가 달라지고 RV11은 들은 해석을 읽는다. **지원·확장:** “먼저 써 봐요/먼저 말해 봐요”, “설명 전에 어떻게 보이는지 들어 보고 싶어요.” NPC가 실제 순서를 바꾼다. **중단·대안:** “그림은 봤어요. 쓰는 모습을 볼까요?”처럼 마지막 확인부터 잇는다. 거절이면 공방 주인의 기본 시범이며 플레이어 참여 완료는 아니다. **이미 도안을 아는 상태의 작성된 변주:** 제목은 ‘알고 다시 보는 그림’, 1의 연구원 대사는 “쓰임을 알고 보니 구멍이 눈에 들어와요”, 2의 선택은 `[시범부터 다시 봐요] [모양부터 비교해요]`, 3B는 “그림만 보면 창문처럼도 보여요”다. 같은 도안·두 순서·같은 완료를 쓰고 이전 지식을 지우거나 없는 판본을 생성하지 않는다. 두 변주를 한 편으로 센다. **검사:** 연구원이 보지 않은 의견을 말하거나 B를 오답으로 고치면 실패다.

<a id="RV11"></a>
### RV11 제목을 가렸다가 열어 보기

**원인·목표:** RV10 완료. 공방 주인이 서로 달랐던 해석에서 **그림을 발견하고 나중에 이름을 확인하는 구경**을 떠올린다. RV10의 같은 도안과 ‘작은 받침’ 제목 카드, 가림판은 공방 소유다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 공방 주인: “제목을 먼저 볼까요, 나중에 볼까요?” | 열린 제목과 덮인 제목을 미리 보여 준다. |
| 2 | A `[제목을 보고 찾아봐요]` / B `[그림을 보고 제목을 열어요]` | 플레이어가 제목 또는 그림의 관심 부분 하나를 선택한다. 읽기 평가가 아니다. |
| 3 | 연구원: A “이름을 보니 받치는 곳이 먼저 보여요.” / B “구멍이 먼저 눈에 들어오네요.” | 고른 순서대로 시선을 옮기거나 제목을 연다. RV10에 연구원이 실제 ‘창문’ 해석을 말한 근거가 있는 경우에만 B를 “창문처럼 보였던 구멍이 눈에 들어오네요”로 회수한다. 기존 지식+시범 갈래에 없던 발화를 회상하지 않는다. |
| 4 | 공방 주인: “오늘 전시는 이 순서로 볼 수 있어요.” `[그대로 둘게요] [원래대로 둘게요]` | 유효한 개인 전시 설정과 관람 한 번으로 완료. |

**현재·후속:** 실제 관람한 `viewed_order`와 현재 전시의 `reveal_order`를 분리한다. `[그대로 둘게요]`는 고른 순서, `[원래대로 둘게요]`는 기존 제목 공개 순서로 현재 전시를 복원한다. RV12는 과거 관람 갈래가 아니라 현재 `reveal_order`를 읽는다. **지원·확장:** 카드 앞/뒤 시범, “먼저 그림, 그다음 이름”, “이름을 가리고 눈에 들어오는 부분부터 골라요.” **중단·대안:** 제목을 연 단계와 마지막 선택 보존. 소품 회수 시 현재 슬롯을 재확인하고 완료/소유 복제 없이 다시 선택한다. 거절이면 기본 제목 공개 전시. **검사:** A/B의 실제 순서가 같거나 제목 맞히기를 요구하면 실패다.

<a id="RV12"></a>
### RV12 이번 구경에는 나를 초대해 주세요

**원인·목표:** RV11 완료. 공방 주인이 이 전시를 즐기는 **관람 초대**를 한다. 첫 도움의 RETURN 보답 재지급이나 LS03 관찰 산책과 달리 RV11 전시의 구경 역할을 고른다. 집 초대 동의는 필요 없다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 공방 주인: “오늘은 제가 안내할게요. 어디부터 볼까요?” | 공방 앞 개인 관람 자리와 기존 쉼터를 보여 준다. |
| 2 | A `[같이 걸으며 볼게요]` / B `[여기서 보여 주세요]` | A는 플레이어가 첫 지점을 선택하고 NPC가 짧은 길을 동행, B는 쉴 자리를 고르면 NPC가 같은 도안을 가져온다. |
| 3 | 공방 주인: “당신이 고른 방식으로 보여 드릴게요.” | RV11 방식이 현재 유효하면 실제 적용. 철회됐으면 현재 동의를 다시 확인한다. |
| 4 | `[제가 한 곳 골라 볼게요] [조용히 볼게요]` / 공방 주인: “천천히 보세요.” | 관심 부분 선택/조용한 관람과 NPC 안내가 실제 끝나면 완료한다. |

**현재·후속:** `visit_role=walk_guest/seated_guest`, 초대 수락·본 도안만 저장한다. 요청할 때 같은 방식의 익숙한 관람을 할 수 있다. **지원·확장:** 가까이 가져오기/한 지점씩 안내, “순서는 제가 고를게요. 설명은 부탁해요.” **중단·대안:** 마지막 관람 지점에서 잇고 종료 때 NPC는 일과로 복귀한다. 집까지 따라가지 않는다. 거절이면 “보고 싶을 때 불러 주세요” 뒤 자기 전시 정리. **검사:** 초대를 받으면 자동 의뢰나 집 방문 허용이 생기면 실패다.

### RV13 팔지 않아도 재미있는 이야기 가판

**원인·목표:** RV12 완료. 공방 주인이 RV10의 도안과 기존 완성 받침을 함께 보여 주려 한다. 플레이어는 **그림→실물 또는 실물→그림**의 소개 순서를 연출한다. LS02의 메뉴 가판과 대상·행동이 다르며 판매/코인/재료 마련은 없다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 공방 주인: “그림하고 완성된 물건을 같이 보여 주고 싶어요.” | NPC 소유 두 물건과 ‘구경하는 자리’를 보여 준다. |
| 2 | A `[그림부터 보여요]` / B `[물건부터 써 봐요]` | 플레이어가 진열 순서를 정한다. 장터를 원치 않으면 같은 구성을 공방의 한 손님에게 보여 준다. |
| 3 | 연구원: “이 그림이 이 물건이 됐군요.” | A는 도안 확인 뒤 받침 사용, B는 받침 사용 뒤 도안의 대응 부분을 찾아 가리킨다. |
| 4 | 공방 주인: “준비는 제가, 소개 순서는 함께 골랐어요.” `[여기까지 볼게요] [다시 써 볼게요]` | 실제 순서대로 구경하면 완료. 물건 인도·매출·코인은 0이다. |

**현재·후속:** `showcase_order=drawing_first/use_first`, 장소·실제 소개 인지를 저장한다. RV14의 전시 다음 쓰임에 연결한다. **지원·확장:** 실물 두 개를 차례로 가리키기, “완성된 물건을 써 보고 그림에서 달라진 점을 찾아요.” **중단·대안:** 진열 초안 보존, 임시 점유 해제, NPC 물건 회수. 거절이면 기본 전시. **검사:** 관람객을 구매 단골로 기록하거나 장터 장소를 강제하면 실패다.

<a id="RV14"></a>
### RV14 전시가 끝난 뒤의 새 쓰임

**원인·목표:** RV13 완료. 연구원이 이미 끝난 공방 전시 자리에 자기 그림을 잠깐 보여 주고 싶다고 제안한다. **현재 개인 전시를 남길지, 다음 전시에 빌려줄지** 선택한다. LS01의 조용함/설명 충돌과 달리 사용이 끝난 전시의 승계다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 연구원: “이 자리에 제 관찰 그림을 보여 줘도 될까요?” | 공개 허용된 연구원 기본 그림을 보여 준다. 내 수첩은 가져오지 않는다. |
| 2 | A `[우리 전시를 남겨요]` / B `[다음 그림을 보여 줘요]` | A는 현재 전시, B는 공방 도안 보관 뒤 같은 허용 슬롯에 연구원 그림이 놓이는 **미리보기**다. 현재 배치는 아직 바꾸지 않는다. |
| 3 | A 연구원: “제 그림은 온실에서 보여 줄게요.” / B 공방 주인: “제 도안은 여기 보관해 둘게요.” | 예정 보관 위치와 사용 모습을 미리 보여 준다. 아직 이동·이용 완료를 저장하지 않는다. |
| 4 | `[이렇게 쓸게요] [아직 바꾸지 않을게요]` | 전자는 현재 권한·개정을 재확인한 뒤 실제 이동·전시 이용으로 완료. 후자는 초안을 버리고 기존 전시를 유지하며 이 교체 사건은 미완료다. |

**현재·후속:** `exhibit_use=workshop/guest_research`와 개정이 남아 공방 관람/연구원 안내 일과를 후보화한다. 실제 방문이 없는데 방문했다고 회상하지 않는다. **지원·확장:** 두 전시 미리보기, “이번에는 빌려주고 다음에는 우리 그림을 다시 꺼내요.” **중단·대안:** 확정 전 기존 전시, 확정 후 현재 개정 복원. 허용 철회는 NPC 물건 보관과 이전 유효 배치 복원. 거절이면 현재 전시. **검사:** 다른 취향의 관찰을 먼저 완료하게 하거나 과거 관계를 지우면 실패다. 묶음 A의 새 원고는 RV14까지다.

<a id="RV15"></a>
### RV15 같은 차, 서로 다른 쉬는 방법

**원인·목표:** RV06 완료. 공방 주인은 도안을 보며 쉬고 싶고 연구원은 꽃을 보며 쉬고 싶다고 말한다. LS02의 두 주문 조건과 달리 **주문 뒤 각자 쉬는 방식**을 정한다. 잔은 NPC 배경 비품이며 플레이어 시식/판매 재고가 아니다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 공방 주인: “그림을 잠깐 보고 싶어요.” 연구원: “저는 꽃이 보이면 좋겠어요.” | 두 사람이 실제 볼 수 있는 방향을 짚는다. |
| 2 | A `[같이 앉고 방향을 달리해요]` / B `[각자 보고 다시 만나요]` | A는 두 좌석 방향, B는 도안/꽃 지점으로 나뉘었다 중앙으로 돌아오는 동선을 보여 준다. |
| 3 | 사장님: “잔은 제가 옮길게요.” `[이렇게 쉬어요] [다시 볼게요]` | 플레이어가 확정하면 NPC가 자리/동선과 잔 이동을 실행한다. |
| 4 | A 공방 주인: “그림이 잘 보여요.” / B 공방 주인: “그림을 보고 왔어요.” 연구원: “꽃도 잘 보여요.” | A는 좌석 이용, B는 실제 본 대상과 합류를 확인하면 완료. 실제로 보지 못한 대상은 대사에서 제외한다. |

**현재·후속:** `tea_break=shared_directions/short_separate`가 이 두 주민의 요청 휴식 구성으로 남는다. **지원·확장:** NPC가 자리·대상을 번갈아 시범, “따로 보고 돌아와서 함께 쉬어요.” **중단·대안:** 이동 전/개별 지점/합류를 나눠 저장한다. 길이 막히면 유효한 같은 장소 좌석으로 대체 제안. 거절이면 각자 기본 자리. **검사:** 개인 합류를 오프라인에 자동 완료하거나 차를 새로 만들게 하면 실패다.

<a id="RV16"></a>
### RV16 맛이 아니라 오늘의 쓰임을 추천해요

**원인·목표:** RV15 완료. 연구원은 익숙한 음료를 “앉아서 천천히” 또는 “들고 조금 걸으며” 마시고 싶다고 현재 목적을 말한다. 플레이어는 **컵과 실제 동선까지 맞춰 추천**한다. 실제 기본 음료 1인분은 경제 원문의 RV16 한정 준비분이며 LS02의 첫 메뉴/주문 변경과 별도 사건이다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 연구원: “오늘은 천천히 앉아 있고 싶어요.” `[골라 볼게요] [같이 골라 주세요]` | 이 회차의 현재 의도를 다시 확인할 수 있다. 도움을 골라도 다음 선택권은 남는다. |
| 2 | A `[잔에 담아 자리에서 마셔요]` / B `[뚜껑 컵으로 걸어 봐요]` | B는 “조금 걸어도 괜찮아요?”를 확인한다. 현재 앉기 목적이면 연구원이 “오늘은 앉을래요”라고 말하고 플레이어가 `[컵은 그대로, 앉아서 마셔요]` 또는 A를 고른다. |
| 3 | 사장님: “음료를 준비했어요.” `[건넬게요] [함께 건네 주세요]` | 동의한 컵으로 음료 1인분을 한 번 제공한다. NPC 비품 컵은 소유 지급이 아니다. |
| 4 | 연구원: “이렇게 마시니 편하네요.” | 동의한 좌석/짧은 걷기를 실제 실행하면 완료. 거절된 계획은 성공 칭찬하지 않는다. |

**현재·후속:** `requested_purpose`, `confirmed_service`, `servedPortionId`와 실제 이용을 저장한다. 다음 자발적 반복에서는 연구원이 걷기를 직접 요청하는 작성된 변주도 쓴다. 변주를 새 이야기로 세지 않는다. **지원·확장:** 잔/뚜껑 컵과 좌석/길 시범, “앉아서 보실 거면 이 잔이 편해요. 걸으려면 뚜껑 컵을 드릴게요.” **중단·대안:** 제공 전 예약 해제, 제공 후 같은 제공 사실과 남은 이용만 복원. 거절이면 기본 주문, 플레이어 완료는 없다. 다시 보기는 기록만 보여 주고 음료를 지급하지 않는다. **검사:** 거절된 추천을 선호로 학습하거나 중복 제공하면 실패다.

<a id="RV17"></a>
### RV17 함께 준비하되 내가 맡을 만큼만

**원인·목표:** RV16 완료. 사장님이 플레이어와 연구원의 **준비부터 정리까지 역할을 나누는 찻자리**를 제안한다. LS02의 가판 주인 교환과 별개다. 기본 장소는 기존 개인 쉼터이고 집 방문은 현재 유효한 별도 초대·실내 슬롯이 있을 때만 선택적으로 허용한다. 집 동의가 없어도 같은 장면을 끝낸다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 사장님: “작게 차려 볼까요? 차는 제가 준비할게요.” | RV17 기본 음료 두 인분과 NPC 비품 두 잔·좌석을 확보한 뒤 제안한다. |
| 2 | A `[저는 자리를 고를게요]` / B `[저는 손님으로 쉴게요]` | A는 두 유효 배치 중 선택하면 NPC가 운반, B는 NPC가 준비한 두 쉴 자리 중 하나를 고른다. |
| 3 | 연구원: “저는 잔을 가져갈게요.” `[함께 시작해요] [아직 기다려요]` | 역할·자리 준비 뒤 사용자가 시작하면 두 음료를 실제 제공한다. |
| 4 | 사장님: “정리는 저희가 할게요.” `[함께 있을게요] [이제 쉴게요]` | 실제 제공·이용으로 완료. 정리 확인·후속 노동을 붙이지 않는다. |

**현재·후속:** `gathering_role=place_choice/guest`, 장소·동의·실제 제공을 남긴다. 다음 모임에서 지난 역할을 제안할 수 있으나 고정 성격으로 추정하지 않는다. **지원·확장:** NPC 역할을 그림과 시범으로 제시, “자리는 제가 정할 테니 차와 정리는 부탁해요.” **중단·대안:** 미제공 준비분 보존, 일부 제공 뒤에는 남은 몫만 잇는다. 집 동의 철회는 쉼터 대안을 다시 고르며 자동 이동/입장하지 않는다. 거절이면 NPC 자기 휴식. **검사:** 손님 역할에서 따뜻함·선택권이 줄거나 쉼터 경로가 잠기면 실패다.

<a id="RV18"></a>
### RV18 물건보다 쓰는 장면을 보여 주는 가판

**원인·목표:** RV17 완료. 사장님이 빈 잔·쟁반으로 **도구를 만져 보는 구경**을 준비한다. LS02의 차 맛/향 나눔과 달리 음식·돈 없이 사용 동작을 즐긴다. 공방 주인은 보고 싶고 연구원은 직접 써 보고 싶다고 말한다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 사장님: “오늘은 잔을 건네는 모습을 보여 주고 싶어요.” | ‘구경하는 자리’ 표기와 빈 잔 두 개, NPC 쟁반을 보여 준다. |
| 2 | A `[손님이 써 볼 수 있게 놓아요]` / B `[저는 시범, 설명은 부탁해요]` | A는 플레이어가 진열하고 연구원이 빈 잔을 쟁반에 얹는다. B는 플레이어가 시범 순서를 고르고 사장님이 설명한다. |
| 3 | 공방 주인: “저는 먼저 볼게요.” 연구원: “한 번 들어 봐도 돼요?” `[차례로 봐요] [옆에서 함께 봐요]` | 두 손님의 요청대로 접근/점유를 분리한다. 속도·손재주 평가는 없다. |
| 4 | 사장님: “보는 방법이 달랐네요.” `[여기까지 할게요] [더 구경할게요]` | 두 관람 방식의 실제 수행과 비품 회수로 완료. |

**현재·후속:** `tea_showcase=hands_on/demonstration`과 각 손님이 실제 본/해 본 사실만 남긴다. 장터를 원치 않으면 찻집 카운터에서 같은 행동·결과로 진행한다. **지원·확장:** 한 손님씩 요청·시범, “구경할 분은 여기, 직접 써 볼 분은 다음 차례예요.” **중단·대안:** 현재 비품과 손님 차례 보존, NPC 일과 복귀 허용. 거절이면 기본 진열. **검사:** 구경을 구매·정산·언어 성공으로 저장하거나 빈 잔을 소유 지급하면 실패다.

<a id="RV19"></a>
### RV19 오늘 가게를 어떤 분위기로 쓸까요

**원인·목표:** RV18 완료. 같은 개인 찻자리에서 **한 가지씩 이야기하기와 조용히 자기 일 하기** 중 오늘 용도를 정한다. NPC 기분 악화·요일·납품·정산 조건은 없다. 첫 자리 협의가 아니라 이곳의 익숙한 손님들이 고르는 이번 이용 방식이다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 사장님: “이야기를 나눌까요, 조용히 쉴까요?” | 두 방식의 짧은 주민 동작을 미리 보여 준다. |
| 2 | A `[한 가지씩 이야기해요]` / B `[말없이 각자 쉬어요]` | A는 공개된 기본 생활 그림 하나를 고르고 순서대로 가리킴, B는 그림 보기/그냥 쉬기 중 하나를 고르고 NPC는 자기 활동을 한다. |
| 3 | A 연구원: “저는 이 꽃이 기억에 남아요.” / B 사장님: “필요하면 불러 주세요.” | A는 실제 공개된 그림만 사용하고 B는 그 자리의 새 질문·인사 접근을 닫는다. |
| 4 | `[오늘은 이렇게 있을게요] [다른 방식으로 바꿀게요]` | 실제 이용과 현재 선택으로 완료. 다음 접속에 모임을 자동 시작하지 않는다. |

**현재·후속:** `tea_mode=one_topic/quiet_use`, `modeScope=this_use`를 저장한다. 지속 기본값은 `[다음에도 먼저 이 방식을 보여 주세요]`를 직접 고를 때만 남긴다. **지원·확장:** 이야기/조용히 두 그림, “오늘은 조용히 쉬고 다음에 이야기하고 싶어요.” NPC의 접근·동작이 실제 바뀐다. **중단·대안:** 종료하면 현재 모임 닫기, 기록 보존. 거절이면 기본 영업. **검사:** 조용히 뒤 관계 질문을 반복하거나 전 마을 접근 설정을 바꾸면 실패다. 묶음 B의 새 원고는 RV19까지다.

<a id="RV20"></a>
### RV20 같은 화분의 다른 모습

**원인·목표:** RV09 완료. 같은 식물의 이전 기록과 현재 모습을 비교한다. 첫 보답 화분의 유효 기록이 있으면 **같은 자기 개체**를 선택하고, 없으면 연구원이 직접 남긴 기본 화분 기록·현재 NPC 화분을 쓴다. 온실 표본을 집 물건으로 이전하지 않는다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 연구원: “같은 화분인데 달라진 곳이 있을까요?” | 실제 이전 기록과 현재 개체. 기록 없는 개체에는 지난 모습을 꾸며 넣지 않는다. |
| 2 | A `[달라진 부분을 가까이 봐요]` / B `[전체 모양을 나란히 봐요]` | A는 실제 꽃/잎 부분, B는 이전/현재 전경. 변화 없음도 “아직 같아요”로 기록한다. |
| 3 | 연구원: “이 기록은 그때, 이 모습은 지금이에요.” `[지금 모습을 남겨요] [한 번 더 봐요]` | 비교한 시점·개체·차이/같음을 개인 기록에 저장한다. 최초 발견 보상은 없다. |
| 4 | `[여기서 볼게요] [집의 내 화분을 볼게요]` | 집 갈래는 실제 자기 화분일 때만. NPC 화분이면 온실/개인 기록으로 같은 완결이다. |

**현재·후속:** `comparisonSource`, 두 기록 ID와 `changedFeatures/unchanged` 저장. 선택적 새 성장은 T08 동일 화분 300초 계약을 쓰며 RV20 완료 조건이 아니다. **지원·확장:** 지난 그림/지금 물건을 교대로 가리킴, “잎은 비슷하고 꽃이 핀 부분이 달라요.” **중단·대안:** “기록은 골랐어요. 지금 모습을 볼까요?”로 잇는다. 대상 회수 때 비교 보류, NPC 대상으로 바꾸기는 별도 확인. 거절이면 연구원의 자기 기록 정리. **검사:** 새 화분 지급·강제 성장 대기·표본 소유 이전이 생기면 실패다.

<a id="RV21"></a>
### RV21 가까이 보니 다른 것, 멀리 보니 다른 것

**원인·목표:** RV20 완료. 연구원이 작은 부분만 보던 습관을 바꿔 **같은 화분의 부분과 전체를 오가는 관찰 놀이**를 제안한다. 첫 전시 방식 결정과 달리 같은 개체를 두 시점에서 찾는다. 사실 설명은 검수된 대상 데이터만 쓴다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 연구원: “저는 자꾸 작은 부분만 보네요. 어디서 볼까요?” | 가까운 시점과 전체 시점의 정지 미리보기. 꽃이 없는 둥근잎 화분도 유효하다. |
| 2 | A `[멀리 보고 하나를 골라요]` / B `[하나를 보고 전체를 찾아요]` | 현재 실제 있는 잎을 기본으로 고르고, 꽃이 있을 때만 꽃 선택도 제공한다. 두 시점에서 같은 개체를 연결한다. |
| 3 | 연구원: 잎 “전체에서 보니 이 잎이 여기 있네요.” / 꽃이 실제 있을 때 “전체에서 보니 이 꽃이 여기 있네요.” | 실제 현재 위치를 짚는다. 꽃·줄·배열이 없는데 대사로 만들지 않는다. 카메라 강제 이동은 없고 보기 전환은 플레이어 선택이다. |
| 4 | `[이 보기 방식을 남겨요] [이번만 볼게요]` | 실제 두 시점 확인으로 완료, 보기 방식 저장은 선택. |

**현재·후속:** `observation_view=wide_detail/detail_wide`, 같은 개체·배치 개정 저장. **지원·확장:** 정지 그림 두 장과 동일 개체 강조, “전체에서 자리를 찾고 가까이 보니 잎이 보여요.” **중단·대안:** 도중 배치가 바뀌면 현재 위치를 다시 확인하며 과거 위치를 지금이라고 말하지 않는다. 거절이면 연구원 기본 관찰. **검사:** 움직임 끄기/시점 확대가 완료·선택권을 줄이면 실패다.

<a id="RV22"></a>
### RV22 이번에는 연구원이 질문해요

**원인·목표:** RV21 완료. 연구원이 플레이어가 **이번에 보고 싶은 것**을 물어 실제 관찰 준비를 맡는다. 지식 정답·고정 취향 평가가 아니라 사용자가 NPC 행동을 지휘하는 생활이다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 연구원: “무엇을 보고 싶어요? 제가 자리를 준비할게요.” | 세부 보기 받침과 화분 주위가 보이는 기존 좌석을 제시한다. |
| 2 | A `[작은 부분을 자세히 봐요]` / B `[화분과 주위를 함께 봐요]` | NPC가 관찰판을 가까이 가져오거나 전체 보기 자리로 안내한다. 잎을 기본 대상으로 하고 실제 꽃이 있을 때만 꽃도 고를 수 있다. |
| 3 | 연구원: “생각한 모습과 맞나요?” `[맞아요] [다른 쪽을 볼게요]` | 수정하면 실제 두 유효 위치 중 다시 고른다. 짜증/감점 없음. |
| 4 | 연구원: “제가 먼저 고르지 않으니 이런 모습도 보네요.” | 확정 자리에서 실제 대상 관람으로 완료. |

**현재·후속:** `player_observation_intent=detail/context`, NPC 준비·이용 사실을 저장하고 RV23의 구경 목적에 연결한다. **지원·확장:** 두 결과 시범 후 기다림, “잎을 가까이 보고 싶어요. 판은 이쪽으로 가져다주세요.” 꽃을 실제 고른 경우에만 잎을 꽃으로 바꾼다. **중단·대안:** 준비만 완료했다면 관람 완료를 만들지 않는다. 거절이면 연구원 자기 관찰. **검사:** 선택과 무관하게 NPC가 같은 자리로 가거나 언어 정답을 자동 만들면 실패다.

<a id="RV23"></a>
### RV23 기록 속 작은 부분을 실제로 찾아요

**원인·목표:** RV22 완료. 공방 주인이 연구원 기본 기록에서 본 작은 잎 모양이 실제 어디인지 궁금해한다. LS03의 첫 전시 관람/보답 산책이나 RV09의 동선 안내와 달리 **기록 속 단서를 현재 개체와 연결하는 구경**이다. 개인 기록은 허용 없이는 쓰지 않는다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 공방 주인: “이 작은 부분은 어디에 있나요?” | 실제 전달받은 기본 그림을 든다. 전달이 없으면 연구원이 지금 먼저 보여 준다. |
| 2 | A `[전체를 보고 가까이 가요]` / B `[작은 부분부터 찾아가요]` | 플레이어가 첫 단서를 고른다. A는 현재 전체→세부, B는 세부 기록→동일 현재 개체 위치. |
| 3 | 연구원: “다음 자리는 제가 안내할게요.” `[함께 갈게요] [여기서 볼게요]` | 짧은 이동 또는 같은 NPC 화분의 유효 관찰 자리 운반으로 잇는다. |
| 4 | 공방 주인: “그림의 이 부분이 여기였군요.” `[같이 볼게요] [여기까지 볼게요]` | 실제 기록과 현재 대상 연결 확인으로 완료. 나비 출현·현실 날씨는 불필요. |

**현재·후속:** `reveal_walk=overview_first/clue_first`, 현재 대상·실제 동행자 지식만 저장한다. **지원·확장:** 두 지점 정지 대안·NPC 운반, “이 모양을 보고 지금 화분에서 같은 곳을 찾아봐요.” **중단·대안:** 단계별 확인 보존. 대상이 없어지면 과거 기록 열람 또는 현재 관람 보류를 고른다. 과거 열람은 현재 관람 완료를 대신하지 않는다. 거절이면 연구원의 기본 안내. **검사:** 과거 그림을 현재 목격으로 저장하거나 걷기를 강제하면 실패다.

<a id="RV24"></a>
### RV24 다음 사람을 위해 남길 한 장

**원인·목표:** RV23 완료. 연구원이 지금 만든 **단서→실물 보기 방식**을 다른 방문객에게도 제공하자고 제안한다. 플레이어는 기록 공개 범위와 개인 관찰 슬롯의 용도를 정한다. 사적 수첩을 내놓지 않아도 같은 완결이다.

| 차례 | 실제 말·선택 | 동작과 확정 |
|---|---|---|
| 1 | 연구원: “다음 사람도 이렇게 보면 좋겠어요. 무엇을 남길까요?” | 연구원 기본 안내 카드와 내 수첩의 비공개 상태를 보여 준다. |
| 2 | A `[혼자 찾는 자리를 남겨요]` / B `[함께 보는 안내를 남겨요]` | A는 혼자 단서 찾기, B는 NPC가 순서대로 안내하는 자리의 **미리보기**. 내 카드 사용도 별도 범위 선택의 초안이며 이때 공개하지 않는다. |
| 3 | A 연구원: “필요할 때 불러 주세요.” / B 연구원: “설명은 제가 맡을게요.” | A의 혼자 보기와 B의 안내를 미리 보여 준다. 실제 관람·전달 인지는 아직 기록하지 않는다. |
| 4 | `[이 용도로 쓸게요] [아직 바꾸지 않을게요]` | 전자는 현재 동의·슬롯·대상 개정을 확인한 뒤 용도/공개 범위를 확정하고 실제 한 번 사용하여 완료. 후자는 초안과 미확정 공개를 버리고 현재 자리 유지, 새 완료는 없다. |

**현재·후속:** `garden_use=solo_clues/guided_clues`, 개정·카드 출처·범위·실제 안내 인지 저장. **지원·확장:** 혼자/NPC 안내 미리보기, “제 기록은 비공개로 두고 안내는 연구원 그림으로 해 주세요.” **중단·대안:** 동의·대상 개정 재확인, 철회 카드는 전달 후보에서 제외한다. 거절이면 현재 관찰 자리 유지. **검사:** 비공개로 완료가 막히거나 공용 정원을 바꾸면 실패다. 묶음 C의 새 원고는 RV24까지다.

## 10 새 이야기와 익숙한 생활을 배치하는 규칙

새 이야기는 사용자가 다음 생활을 고를 때 **현재 대상·선행 사실·권한·취향·NPC 예약이 유효한 미완료 장면**에서만 제안한다. 조용히·거절/보류 범위·완료 직후 쉬기와 [NPC 접근 예산](싱크타운_NPC자율생활_설계_20261008.md#approach)을 우선한다. 원고가 늘어도 접근 예산은 늘지 않는다.

1. 하던 일 이어가기/특정 활동을 직접 골랐으면 그 요청이 첫 후보다. 미완료 원고로 가로채지 않는다.
2. ‘다음 생활’에서는 명시 취향의 **새 이야기 1개 / 현재 달라진 모습 1개 / 익숙한 생활 1개**, 합계 최대 3개 중 실제 가능한 것만 기존 목록에 둔다. 없는 종류는 비우고, ‘다른 것 보기’에서 나머지 유효 후보를 볼 수 있다.
3. 새 이야기 기본 순서는 선행 깊이가 낮은 미완료→명시 취향 일치→현재 현장에서 가능→동률일 때 원고 ID 순이다. 언어 수준은 지원판만 고르고 생활 선택을 지우지 않는다. 시작 때 고른 판본·대상·갈래는 중간에 다시 추첨하지 않는다.
4. 같은 완료 사건의 감사·편지·접근은 하나의 반응 근거로 합친다. [§12-2의 계정 단위 최근 이력과 판정식](#repeat-history)에서 마지막 두 유효 이용의 `storyFamily`와 `canonicalActivityId`가 **둘 다 같은 경우** 추천칸에는 현재 취향 안의 다른 **실제 결과가 있는** 목적을 우선하되 직접 고른 반복은 막지 않는다. 로그인·장소 이동·같은 장면의 별칭으로 최근 이력을 초기화하지 않는다. 다른 목적의 새 후속은 같은 계열이라는 이유로 숨기지 않는다. 두 번은 피로 검증 출발값이고 해금/관계 수치가 아니다.
5. 거절한 같은 회차·같은 의도는 `declined`로 보존하고 사용자가 해당 생활의 `[다시 해 볼게요]`를 직접 고르기 전에는 새 세션에서도 재제안하지 않는다. 추가로 현재 세션에서는 그 `storyFamily`의 다른 회차 자동 접근도 제외한다. 여기서 현재 세션은 [NPC 접근 원장](싱크타운_NPC자율생활_설계_20261008.md#approach-ledger)의 논리 `visitId`이며, §11의 편성 검사 세션·앱 새로고침 횟수와 다르다. ‘이 활동 먼저 말 걸지 않기’는 해제할 때까지 유지하고 보류는 목록에만 남긴다. 다른 NPC·대사 변형으로 이 제한을 우회하지 않는다. 앱 밖 먼저 말걸기와 앱 안 접근은 각 접점의 정본 예산을 각각 적용하며 같은 사건을 다른 접점으로 재권유하지 않는다.
6. A/B 변경은 현재 이용의 편집이다. 과거 완료·소유·제공·인지 기록을 덮어쓰지 않는다. 말투·손님 교체·카메라만 바꾼 반복을 새 이야기로 표시하지 않는다. 원고가 소진되면 ‘새 이야기’ 표식을 빼고 실제 기존 생활만 남긴다.

### 상태가 변하는 때와 멈추는 때

| 실제 계기 | 바뀌는 상태·행동 | 보존·복귀 표현 |
|---|---|---|
| RV14 전시 교체 확정 | 개인 전시 개정. 공방 관람 대신 연구원 안내 후보 | 옛 도안 보관·함께한 기록 유지. “지금은 연구원 그림을 놓았어요.” |
| RV19 이번 조용히 선택 | 그 찻자리 새 질문 중지·NPC 자기 활동 | 전 마을 설정/영구 취향 불변. “오늘은 조용히 쉬고 있어요.” |
| T08 승인 성장 완료 | 같은 개체 외형 단계. RV20에서 현재/과거 비교 가능 | 개인 관람/언어 완료는 없음. 물건을 직접 열면 “화분 모습이 달라졌어요.” |
| NPC 실제 자리 사용 | 그 이용 근거와 다음 일과 후보 | 관람 ACK·다른 NPC 인지 자동 추가 없음 |
| 비/야간에 야외 이용 불가 | 실내/정지 보기 대안·현재 동선 | 현실 날씨/낮 접속 대기 강제 없음. 대안의 실제 대상을 기록 |
| 오랜 부재 뒤 복귀 | 승인 준비/성장 결과와 현재 개정 확인 | 사연 자동 완결·부재 서운함·밀린 부탁 없음. “하던 일은 여기 남아 있어요.” |
| 전시 철거·공개 철회 | 관련 사용/전달 후보 취소, 자기 보관/기본 카드 대안 | 과거 사실·완료 보답 유지. “지금은 이곳에 전시가 없어요.” |

유한 원고와 현재 세계를 조합하며 무한 생성 NPC·새 경제 발행·별도 Atlas 엔진은 없다. 재료 소비/정산 반복은 [RQ01~04 실제 의뢰](싱크타운_생활경제와_상품_설계.md#repeat-orders)를 따른다.

## 11 30세션 정적 리허설과 제공량

세 묶음의 첫 후속을 준비하고 모두 같은 개인 세계에서 수행하는 검사다. 아래는 **원고·선행·상태를 대조한 책상 리허설**이며 런타임 실행·재미 관찰 결과가 아니다. 한 행은 한 생활을 고른 검사 세션이다. 소유 화분이 없으면 RV20의 NPC 기본 화분, 집 초대가 없으면 RV17 쉼터, 장터를 원치 않으면 RV13/18 공방·카운터를 써도 행 수·완료 조건이 같다.

| 세션 | 실제 선택 | 누적 새 원고 | 다음에 확인할 현재 변화 |
|---:|---|---:|---|

## 12 원고가 끝난 뒤에도 고를 수 있는 생활

단일 취향의 8편 또는 세 묶음 24편을 다 봤다는 것은 이 팩의 **새 사건 원고가 소진됐다는 뜻**이다. 집·주민·물건을 초기화하거나 보상 의뢰로 빈자리를 채우지 않는다. 같은 대사를 재생하는 ‘지난 이야기 보기’와 현재 세계에서 실제로 쓰는 ‘익숙한 생활’을 나눈다. 전자는 과거 기록이며 후자의 배치·역할·사용 결과만 현재 상태를 바꾼다.

### 12-1 실제 차이가 남는 익숙한 이용 9종

아래 `LIFE-*`는 기존 동작의 호출을 묶는 제작용 식별자다. 새 이야기 ID·새 최초 보상·새 관계 단계를 만들지 않는다. NPC 비품은 원래 소유·대여·현재 허용을 확인한다. 구독 만료 뒤에는 경제 정본의 소유 공간·기록·기본 생활 범위만 남고 **새 유료 활동과 그 활동의 NPC 예약**은 시작하지 않는다. 무료 첫 챕터·기본 도움에 필요한 유효 NPC 예약까지 막는 규칙이 아니다. 아래에서도 권한에 맞는 현재 이용만 보여 주며 미제작 동작을 ‘계속 할 수 있는 일’로 표시하지 않는다.

### 12-2 최근 이력·취향 변경·세션 변경의 정확한 뜻

피로 처리는 **추천 순서**를 위한 것이며 활동 횟수 제한·새 원고 해금·관계 평가가 아니다. Town이 이미 가진 확정 사건과 전달 사실을 최소한으로 참조한다. 아래 필드는 설계용이며 현재 계정 DB에 존재한다는 뜻은 아니다.

| 항목 | 기록할 때와 식별 기준 | 보존·소비 범위 |
|---|---|---|
| `recentLifeUse` | 사용자가 명시적으로 시작한 뒤 실제 행동 또는 요청 관람이 전달된 한 이용의 `useId`, `canonicalActivityId`, `storyFamily`, `sourceEventId`, 완료/중단·현재 결과. 미리보기만 열고 닫기는 제외 | 계정+개인 세계에서 마지막 20개 유효 이용 참조. 같은 이용 재개/다른 기기 조회/ACK 재전송은 한 항목 갱신. 배경 NPC 자기 일과는 넣지 않음 |

**순서 결정:** 직접 고른 활동→명시한 현재 취향→지속 기본 취향→유효 후보 정렬이다. 직접 고른 활동도 소유·권한·동의·현재 대상 검사를 통과해야 하지만 반복 피로 때문에 거절하지 않는다. 수동 도움/숙련 변화는 이 순서를 바꾸지 않는다.

**피로 가설을 적용하는 계산:** 최근 유효 이용 두 개를 `u[-1]`, `u[-2]`라 할 때 `u[-1].storyFamily == u[-2].storyFamily` **그리고** `u[-1].canonicalActivityId == u[-2].canonicalActivityId`가 동시에 성립해야 반복 목적을 뒤로 배치한다. 같은 계열의 서로 다른 목적을 두 번 선택했다면 적용하지 않는다. 적용할 때도 자동 기본 추천에서 그 같은 목적만 뒤로 보내고 현재 명시 취향의 다른 목적, 없으면 현재 달라진 모습/기록/쉬기를 먼저 보여 준다. 아직 안 본 새 후속을 같은 계열/NPC라는 이유로 숨기지 않고 직접 선택 메뉴에서는 기존 반복이 계속 보인다.

**미선택 후보의 일회 정렬:** `canonicalActivityId+해당 회차·의도`로 같은 후보를 식별한다. 후보별 `lastFatigueConsumedOfferSeq` 이후 실제 보인 새 미선택 목록 3개가 있고 그 사이 해당 후보를 직접 선택하지 않았을 때 다음 명시 목록에서 한 번 뒤로 배치한다. 그 목록이 실제 표시되면 해당 순번까지를 소비 포인터에 저장하고 일회 표식을 닫는다. 이후에는 **그 순번 뒤의 새 노출 3개**를 모아야 다시 발동하므로 목록1·2·3→4에서 한 번 정렬 뒤 목록2·3·4로 다시 발동하지 않는다. 직접 선택은 미선택 묶음을 닫으며 기록을 싫어함/낮은 능력으로 해석하지 않는다. 이는 영구 숨김·취향 낙인·재권유 허용이 아닌 정렬이다. 유효한 다른 후보가 없으면 공백을 새 의뢰로 채우지 않는다.

추천의 `recentLifeUse/recentOffer`는 **계정+개인 세계**의 현재 생활 맥락이다. 자동 접근 예산·거절·동시 말걸기 제어는 **NPC 정본의 계정 전체 세계 통합 원장**을 먼저 통과한다. 세계를 바꿔 추천 맥락이 달라져도 새 접근 예산이나 거절 해제는 얻지 않는다.

최근 두 번/20개/12개/세 목록은 첫 플레이 관찰용 수치다. 생활 이용의 시작·결과 전달을 확인하지 않은 화면 열기 횟수, 백그라운드 시간, 앱 재실행을 ‘생활했다’로 세지 않는다. 새로운 원고 버전도 같은 사건 계열의 최근 이력을 무조건 지우지 않는다. 과거 기록 삭제/마이그레이션에 별도 정책이 필요하더라도 그것을 지급·새 이야기·거절 해제 사유로 쓰지 않는다.
