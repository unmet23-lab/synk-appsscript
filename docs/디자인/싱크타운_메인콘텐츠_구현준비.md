# SYNK TOWN 메인 콘텐츠 — 설계 보완과 구현 준비

2026-10-08. 사용자 요청: 미니게임 다음으로 SYNK WORLD의 중심 콘텐츠인 SYNK TOWN 설계도를 점검하고, 부족한 설계를 보완한 뒤 구현을 준비한다.

**판정: 기존 생활 장면을 재사용할 수 있으며, 첫 플레이의 공간·원고·입력·권한·이관은 [상세 실행 설계](싱크타운_첫플레이_실행설계.md)로 구체화했다. 실제 구현과 출시 준비는 별도다.** 첫 생활·재방문·학습 원고를 연결하는 작업이며, 아래 최초 점검에서 드러난 빈틈은 담당 상세 원문과 함께 읽는다. 문서 작성·정적 검토의 완료를 실제 생활 재미나 전체 게임 출시의 완료로 쓰지 않는다.

이 문서는 [마을 설계](../마을_설계.md)의 구현 준비 작업지다. 세계·주민·경제·교육의 담당 정본을 대체하지 않는다. **아래 첫 빌드 편성, 새 집 장면, 제작 순서는 보완 제안**이다. 기존 사용자 확정과 코드에서 확인한 사실은 별도로 표시한다. 이번에는 문서만 보완하며 새 게임 코드·이미지·음성·결제·배포를 만들지 않는다.

**10월 8일 후속 사용자 확정:** 열 가지 도입 경험 모두를 **생활 재미 1순위 → 사용자 주인공·숙련도별 체감 주민 행동 2순위 → 학습 3순위**로 설계한다. 담당 문서는 [전체 기준](싱크타운_생활재미와_성장콘텐츠_설계_20261008.md), [열 가지 제작 카드](싱크타운_10대생활콘텐츠_제작설계_20261008.md), [NPC 실행 규칙](싱크타운_NPC자율생활_설계_20261008.md), [공연과 학습](싱크타운_공연과_생활학습_설계_20261008.md)이다. 아래 첫 빌드 편성은 단계적 구현을 위한 작업지이며 전체 설계 범위를 첫 집·쉼터만으로 줄이지 않는다.

## 1 들어와서 할 일과 다시 올 이유

플레이어에게 줄 가치는 **“내가 좋아하는 생활을 한국어로 해 보고, 그 선택을 기억하는 주민과 내가 바꾼 공간으로 돌아오는 것”**이다.

- 처음: 이미 보기 좋은 내 집에서 쉬거나 작은 선택을 한다. 마을로 나가면 원하는 일 하나를 고른다.
- 하는 동안: 뜻을 알아듣고 부탁을 확인하거나, 내 취향을 말하고 물건을 만들고 놓는다. 도움을 받아도 같은 생활 결과가 남는다.
- 끝: 주민이 그 결과를 실제로 쓰는 모습을 본다. 귀가하거나 그 자리에 머무를 수 있다.
- 다시: 내 배치와 사건을 그대로 만나고, 원하면 그 경험에서 이어지는 다른 역할을 맡는다. 결석 복구 노동이나 밀린 의뢰는 없다.

**한국어가 쓰이는 순간과 한국어 능력을 확인하는 순간을 구별한다.** “밖이 좋아요”는 취향 선택이며 정답이 없다. 안내문에서 요청 장소를 이해하는 것은 별도로 검수한 언어 과제일 수 있다. 클릭·가구 소유·주민의 감사만으로 이해도나 급수를 올리지 않는다.

## 4 내 집에서 시작하는 첫 세 번의 방문 — 보완 원고

### 첫 빌드의 공간과 할 일

**내 집 한 실내 → 짧은 연결 길 → 찻집 앞 쉼터 → 내 집**을 먼저 잇는다. 집에는 마스코트, 창문과 쉬는 자리, 기존 기본 물건의 배치 선택, 생활 기록을 보는 자리를 둔다. 집 1판·2판 전체 완성을 뜻하지 않는 첫 연결 범위다. 집 안 설정·기록 보기를 마쳐야만 밖으로 나갈 수 있는 구조는 만들지 않는다.

| 새 원고 ID | 실제 장면과 대사 제안 | 선택·남는 것·중단 |
|---|---|---|
| H00.01 도착 | 내 마스코트가 맞이한다. 대사는 선택한 마스코트의 정본으로 제작하고 새 공통 말투·음성을 붙이지 않는다. 창밖에 길과 하늘이 보인다 | `[집 둘러보기] [밖으로 가기] [쉬기]`. 어느 것도 출석·학습 성공이 아님 |
| H00.02 내 자리 | 처음부터 보유한 기본 물건을 창가의 두 허용 자리에서 미리 본다 | `[여기에 놓기] [그대로 두기]`. 취향 선택. 새 재화 지급·보상 없음. 취소하면 기존 배치 유지 |
| H00.03 문 | 문 가까이 가면 고정 행동 목록에 `[밖으로 가기]`가 나타난다 | 찻집의 FT00으로 연결. 집 조작을 생략해도 진행 가능. 지도 전체 탐험을 요구하지 않음 |
| H00.04 귀가 | 생활을 끝내고 돌아오면 내 배치가 남아 있다. 생활 기록에서 이번 확정 결과를 볼 수 있다 | FT10이면 만든 자리, FT51이면 현재 안내 그림을 사실대로 표시. 기록 열람으로 새 가구·감사·보상 발급 없음 |
| H00.05 편안한 끝 | 내 자리에서 풍경을 보거나 앱을 닫는다 | 새 의뢰 팝업·자동 학습 시작 없음. 마을 소리와 음악의 기존 끄기 선택 유지 |
| H00.06 다시 | 현재 배치와 마지막 확정 생활을 복원한다 | `[하던 일 계속] [집에 있기] [밖으로 가기]`. 미완 일이 없으면 ‘계속’ 대신 실제 가능한 일만 표시 |

H00의 실제 물건·배치·선택 마스코트별 말풍선은 [집 상세 원고](싱크타운_첫플레이_실행설계.md#home-script)로 채웠다. 이 표는 장면 요약이다. 시작·재개 화면의 ‘밖으로 가기’ 선택은 문 쪽으로 갈 목적만 정하고, 실제 입장은 문 근처의 행동 목록에서 실행한다. 집 장식을 공개하거나 NPC를 집 안으로 자동 초대하는 기능은 포함하지 않는다. 창밖 풍경·날씨는 실제로 받은 세계 상태만 사용한다.

### 방문별 편성

| 방문 시나리오 | 플레이어가 겪는 일 | 보고 싶은 체감 | 다른 선택도 허용 |
|---|---|---|---|
| 첫 방문 | 집 → FT00 → 고른 첫 생활 한 경로 → 주민의 이용 → 귀가/머무르기 | ‘내 선택 때문에 이것이 생겼다’고 알아봄 | 집에서 쉬기, 산책, 중단. 결과를 보려면 네 경로를 모두 해야 하는 조건 없음 |
| 두 번째 방문 | 남은 집과 생활 결과 → 같은 경로의 첫 후속을 직접 선택 → 다른 사용 모습 | ‘전에 한 일을 여기서 기억한다’ | 기존 자리 이용만 하고 종료. 미관람 결과를 새 사건으로 세지 않음 |
| 세 번째 방문 | 무료 범위의 배치/방식 변경·기존 결과 이용 또는 다른 무료 입구. 권한과 구현이 준비됐으면 해당 RV | 새 재료 이름 이상의 다른 역할을 원하게 되는지 | 다른 활동 강요 없음. RV가 준비되지 않았으면 새 이야기로 표시하지 않음 |

이는 **테스트 순서**다. 방문 2회·3회가 해금 조건이 아니며 한 번에 후속까지 해도 된다. 첫 결과를 10~15분 안에 볼 수 있는지는 제작·관찰 가설로 삼는다. 화면에 시간 제한을 넣거나 도움을 쓴 사람의 진행을 실패 처리하지 않는다. FT40은 이동·전달이 길어질 가능성이 있어 실제 소요를 별도로 잰다.

첫 연결 빌드는 이미 있는 FT10→FT51을 먼저 쓴다. 무료 첫 챕터 완성 판정은 FT20·FT30·FT40과 각 첫 후속까지 모두 독립적으로 완결한 뒤에 한다. 한 경로 빌드에 다른 세 경로의 작동하지 않는 시작 버튼을 노출하지 않는다.

## 5 첫 등장인물과 관계를 만드는 방식

| 첫 빌드 역할 | 기존 원문/구현 | 첫 연결에서 맡을 일 | 이후 제작 |
|---|---|---|---|
| 내 마스코트 | 선택한 캐릭터 정본 | 집의 맞이·쉬기·요청한 도움. NPC 대신 모든 말을 설명하지 않음 | 고르기·조립·직접 답하기의 검수된 집 대화 |
| 찻집 주인 | FT00/10/20/40, 현재 `cafe-owner` | 플레이어의 자리 선택을 알고 실제 서빙함. 알아보는 이유는 같은 사건 | 첫 부탁 이후 주인이 플레이어를 돕는 장면과 자기 사연 |
| 손님 | 현재 `guest` | 자리에 앉고 판을 읽고 이동함 | 단역과 관계를 맺는 주민의 구분. 모두에게 장편을 붙이지 않음 |
| 공방 주인 | FT10.02A/03A, FT40/54 원고 | 첫 바깥 자리의 제작 안내부터 등장. 현행 코드에서 생략된 이 배역·장면을 자산표에 포함 | 두 주민 사연에서 자신의 바람·동의·보답·다음 사건 |
| 연구원 | FT30/53 원고 | 발견 경로를 만들 때 합류 | 관찰·전시·반환과 서로 다른 다음 역할 |

첫 연결의 역할형 주민을 할머니·분식집 사장님·슬로 임의 교체하지 않는다. 첫 연결에서는 `cafe-owner / workshop-owner / researcher`와 찻집 주인·공방 주인·연구원 호칭으로 구분한다. 이들의 성격·관계·행동은 [주민 관계 원고](싱크타운_주민관계와_연속생활_원고.md)로 구체화하고, 기존 주민 설정서와 장편은 별도의 후속 연결로 보존한다. 최종 얼굴·목소리는 자산 제작에서 확정한다. 현재 곰·사슴 그림은 주민 캐스팅의 확정 근거가 아니다.

**관계는 호감 숫자보다 다음 행동으로 보인다.** FT10의 함께한 일은 기본 부탁과 사실에 맞는 감사로 남고, FT51에서는 안내 역할을 맡는다. 더 깊은 관계를 만들 때는 새로운 맥락의 사건과 NPC의 실제 보답 원고를 함께 준비한다. 매일 같은 감사·선물을 반복해 장편을 열지 않는다.

장편의 `이야기 ID / 첫 진입의 선행 사건 / NPC가 아는 근거 / NPC 보답 / 완결 사건 / 다음 관계 표현 / 별도 동의` 대응은 [주민 관계 원고](싱크타운_주민관계와_연속생활_원고.md)에서 읽는다. ‘가까운 사이’ 같은 옛 이름을 단계 번호로 치환하지 않는다. 장편 완료가 관계의 결과인 경우 그 장편 시작에 동일 완료 상태를 요구하면 안 된다. 말 놓기·집 방문은 각각 별도의 선택이며, 공동 사건이 끝났다고 자동 동의하지 않는다.

## 6 실제로 알아듣는 대화를 준비하기

첫 출시는 [대화 정본](../대화_설계.md)의 고르기·조립·주제 안 직접 답하기를 충족해야 한다. 첫 코드 시험에서 버튼만 연결한다면 ‘선택 입력 시제품’으로 표시하고 대화 전체 구현으로 세지 않는다. 실행 중 AI가 대신 이해하는 방식으로 바꾸지 않는다.

FT10의 안/밖 선택으로 먼저 준비할 입력표:

| 입력 의도/예시 | 처리 제안 | 생활 상태를 바꾸는 때 |
|---|---|---|
| `밖이 좋아요` / `밖에 놓을래요` | 밖 갈래 초안을 보여 줌 | 위치·소모를 확인한 명령 확정 때 |
| `안에 놓을게요` / `안이 좋아요` | 처마 안 갈래 초안을 보여 줌 | 같은 확정 규칙 |
| `밖 말고 안이요` | 긍정·부정과 최종 대상을 확인해 안 초안 | ‘밖’ 낱말이 있다는 이유로 밖을 실행하지 않음 |
| `안에는 안 놓을래요` | 장소의 ‘안’과 부정의 ‘안’을 구분. 대상을 확신하지 못하면 그림 두 개로 확인 | 확인 전 명령·소비 없음 |
| `아직 안 할래요` / `나중에요` | 보류하고 현재 배치를 유지 | 보류 기록만. 진행·언어 실패·관계 차감 없음 |
| `어디가 좋아요?` / 알 수 없는 표현 | 설명 또는 두 결과 보기로 돌아감 | 질문을 수락으로 처리하지 않음 |
| `다시요` / `뜻을 보여 주세요` | 요청한 도움 제공 | 생활 결과 동일, 등록 과제라면 도움 기록 별도 |

위 예시는 인식기가 구현됐다는 뜻이 아니다. 첫 연결의 실제 대화 차례별 **허용 의도·표현·조립 낱말·반대 표현·확인·취소·도움**은 [세 입력 대응표](싱크타운_첫플레이_실행설계.md#input-table)에 작성했다. 상태 확정과 저장은 [명령·중단표](싱크타운_첫플레이_실행설계.md#commands)로 잇는다. 채집·제작·전달·초대에는 잘못 이해한 한 번의 말로 소모·공개·동의를 확정하지 않는다.

NPC 음성은 원고·캐스팅·제작 경로를 정한 뒤 제작한다. 소리 없이 읽는 생활 진행을 허용하되 음성이 없는 장면을 듣기 학습으로 보고하지 않는다. 기기 음성 입력이 지원되지 않아도 키보드·단어 선택판으로 직접 답하기, 고르기·조립을 사용할 수 있어야 한다. 자유 답변용 단어 선택판을 정답 조립 문제와 혼동하지 않는다. 마스코트의 말풍선·비언어 소리 원칙은 유지한다.

## 7 원고를 실행 가능한 장면으로 넘기기

새 범용 퀘스트 엔진을 먼저 만들지 않는다. 현재 Town의 콘텐츠 규칙과 Trail·Vellum·Loom 계약을 재사용하고, 두 번째 경로에서도 반복되는 부분만 공통화한다. 다음 열을 첫 구현 장면의 제작표에 채운다.

| 묶음 | 반드시 적을 값 |
|---|---|
| 정체와 원문 | `contentId`, `contentVersion`, 원형 사건 ID, 원고 앵커, 분기·단계·선택 ID |
| 시작 가능성 | 선행 사건, 현재 NPC/물건, 개인/공유 범위, 학습 해금, 콘텐츠 권한 |
| 입력 | 고르기·조립·직접 답하기의 의도, 확인·보류·취소·도움 |
| 확정 | 명령 ID, 기대 revision, 예약/소모/생성/인도, 완료 조건, 중복 방지 |
| 표현 | 실제 쓰는 자산, NPC 이동·자세, 정지 대안, 해당 NPC의 인지 근거, 관람 확인 |
| 학습 | 평가 없음 또는 검수된 과제/skill/family, 최초 응답, 도움·노출·음성 전달 조건 |
| 재개 | 마지막 확정 단계, 잠정 초안, 취소 범위, 미관람 결과, 다음 후보 |
| 제작 상태 | 원고 작성 / 내용 검수 / 자산 준비 / 저장 연결 / 실제 화면 / 학생 관찰 |

필드명은 **제작표 제안**이며 기존 API의 필드라고 간주하지 않는다. 생활·학습·상품 소유의 원장을 한 상태 문자열에 합치지 않는다. 바뀐 콘텐츠 판으로 재개할 때 같은 사건을 두 번 지급하거나 완료 단계를 되돌리지 않도록 이관 규칙을 포함한다.

### C03와 FT20의 완료 기준 정리

| 상태 | 사실 | 다음에 허용되는 일 |
|---|---|---|
| 재료 마련/전달 | 실제 소유·출처·전달량이 확정됨 | 가능한 양만 제조 |
| 제조 확정 | 같은 제작 배치에서 차/곁들임이 만들어짐 | 남은 몫 제공. 이것만으로 첫 메뉴 생활 경로 전체를 완료하지 않음 |
| 손님 제공 확정 | 같은 배치의 손님 1인분이 제공됨 | FT20 첫 공동 시식의 생활 결과 완료, FT52 후보 허용 |
| 이용 모습 관람 | 이미 확정된 제공 사실을 사용자가 화면에서 봄 | 전달 이력만 기록. 새 재료 소비·관계 보상·후속 해금의 추가 조건 아님 |
| 다음 방문 | 남은 몫/품절/기념 메뉴가 현재 장부와 일치 | 이어 제공 또는 기본 메뉴. 과거 시식을 새 판매로 만들지 않음 |

플레이어가 자기 몫을 다 먹을 필요는 없다. 제조 뒤 종료했다면 다음 접속에서 제공 단계부터 이어 간다. C03의 별도 입구와 FT20은 같은 원형 사건·배치·소비를 참조한다. 단계별 내부 이름은 구현 때 정하되 위 의미를 바꾸지 않는다.

## 8 개인 생활을 WORLD 계정에 잇기

기존 [계정 설계](../SYNK_플랫폼_계정과_연결_설계.md)의 SYNK ID를 쓴다. Town 전용 로그인이나 별도의 TOPIK 시험 시스템을 만들지 않는다. 내부 1급+ 판정은 기존 Strata 지도·시험 형식 연습과 연결하고, 확인된 권한은 공통 계정의 이용권 제공처에서 읽는 방향을 따른다.

| 서로 다른 조건 | 쓰는 곳 | 잘못 묶으면 안 되는 것 |
|---|---|---|
| 본인 계정과 생활 저장 권한 | 집·소유·개인 사건 복원 | 교사 반에 들어 있어야만 개인 마을 소유 가능 |
| 확인된 내부 TOPIK 1급+ | 생활·NPC 입장과 활동 시작 | 게임 점수·자기 신고·구매로 대체 |
| 무료 챕터/정액/상품 권한 | 해당 장면과 상품 범위 | 통과 기록 삭제, 종료된 구독을 새 학습 실패로 표시 |
| 교실 연결·학습 공유 동의 | 해당 교사의 과제와 허용 학습 결과 공유 | 개인 NPC 사연·생활 취향 자동 공유, 철회 시 개인 소유 삭제 |

현재 브리지의 학생별 분리·중복 명령·revision 검사는 재사용할 근거가 있다. 그러나 반 소속·공유 동의를 정식 Town 생활의 유일한 입장 조건으로 가져오면 일반 사용자가 들어갈 수 없으므로 이 경계를 분리해야 한다. 교사 연결 철회와 개인 계정 저장 동의 철회는 별개로 처리한다.

첫 구현의 [권한 제공처·상태별 입구](싱크타운_첫플레이_실행설계.md#account-state)와 [기존 기록 이관 범위](싱크타운_첫플레이_실행설계.md#migration)를 작성했다. 확인 실패를 빈 집·새 게임으로 표시하지 않는다. 명령·복원·직접 링크에서도 같은 검사를 적용한다. 만료·오프라인 처리는 [경제 정본](싱크타운_생활경제와_상품_설계.md#expiry)의 범위만 사용한다.

## 9 미니게임에서 배운 말이 생활에 쓰이는 연결

생활 도중 미니게임 클리어를 새 관문으로 요구하지 않는다. 뜻 도움은 현재 장면에서 바로 쓰고, 사용자가 별도 연습을 원하면 메인 학습·지원하는 게임으로 이동한 뒤 원래 자리로 돌아온다.

| 생활 장면 | 생활에서 사용하는 말 | 평가와 복습을 연결할 때 | 복귀 보존 |
|---|---|---|---|
| FT10 자리 선택 | 안/밖·여기·옮겨요 | 선호에는 정답 없음. T07 등 위치 읽기 원고를 검수 후 별도 과제로 연결 | 고른 갈래·제작한 물건·확정 자리 |
| FT20 만들기/제공 | 먼저/다음·하나/둘·주세요 | T03/T09 등 순서 원고. 실제 지원 후보가 있는 게임에만 연결 | 제작 배치·출처·이미 제공한 몫 |
| FT30 관찰 | 옆/잎·같아요/달라요 | 그림 관찰은 독립 듣기 아님. 검수된 위치/세부 과제로 따로 확인 | 식물/카드의 위치와 소유 |
| FT40 약속 전달 | 여기/저기·같이·지금/나중 | T02/T08의 변경 이해를 참고하되 실제 장면과 가상 연습 자료를 구별 | 누구에게 어디까지 전달했는지·현재 제안 |
| 기존 안내문 읽기 | 세부·부정·순서 | 현행 18문항과 Core 후보·정확한 지정 목표 재사용 | 읽기 결과와 생활 사실 분리 |

T번호는 **제작 원고**이며 지금 호출 가능한 런타임 문항 ID가 아니다. 연결할 때 실제 등록된 `itemKey/familyKey/skillId`·권한·원고 판을 확인한다. 지원 후보가 없으면 관련 없는 게임을 억지로 추천하거나 ‘맞춤 연습 준비 완료’라고 표시하지 않는다.

왕복 요청에는 본인·원래 콘텐츠/사건/단계·revision·학습 목표를 연결한다. 복귀 때 최신 생활 상태를 다시 읽어 다른 기기에서 끝난 일을 반복하지 않는다. 연습을 포기하거나 틀려도 생활 선택과 관계는 남고, 새 문항의 도움 없는 수행만 그 조건에 맞는 학습 근거로 쓴다.

**TOPIK 준비에서의 역할:** 첫 연결은 초급의 위치·세부·부정·순서 이해를 생활 맥락에서 쓰는 데 초점을 둔다. 3~4급 중심 경로를 완성하려면 기존 24단원 지도에서 중급 듣기·읽기·자료 이해·쓰기의 원고, 평가, 기록 소비를 별도로 연결해야 한다. 첫 집·쉼터 완성이나 18문항 통과를 4급 대비 완성으로 표시하지 않는다. 학습 효과는 실제 학습자의 새 상황 수행으로 따로 확인한다.

## 10 재화와 오래 즐길 분량

현재 미니게임 공통 코인은 같은 브라우저 출처의 로컬 컬렉션이다. Town 생활 코인은 계정 원장 기반의 경제 **설계안**이다. 기존 플랫폼 정본에 따라 자동 합산·교환·이관하지 않는다. Town 화면은 ‘타운 생활 코인’, 미니게임 화면은 기존 공통 코인의 용도를 분명하게 설명하는 안을 쓴다. 최종 이름·아이콘은 별도 검수한다.

첫 연결 빌드는 FT10/51의 한정 재료·기존 보상 규칙으로 충분하다. 경제 화면을 먼저 늘리지 않는다. 제작·메뉴·주민 도움·관찰 각각의 **발급→행동→산출→정산→재발급**은 [RQ01~04 실제 의뢰 원고](싱크타운_생활경제와_상품_설계.md#repeat-orders)로 채웠다. 수익 수치만 맞추고 반복 행동의 재미가 같다고 가정하지 않는다.

정액제 제공 범위는 전체 장면 수뿐 아니라 각 취향에서 시작할 수 있는 장면으로 확인한다. [취향별 제공량과 제작표](싱크타운_재방문_콘텐츠와_원고.md#production), [30세션 정적 리허설](싱크타운_재방문_콘텐츠와_원고.md#static-rehearsal)에 원고·실행·실제 길이·다음 제작분을 구분한다. 반복 관람·A/B·문장 길이 변경을 새 이야기 수에 더하지 않는다. 체험판 제작과 정액 서비스 출시의 완료 조건을 분리한다.

## 11 풍경과 모바일 조작의 구현 준비

[풍경 정본](미래한국_마을_풍경.md)의 생활·공간 방향과 [2026-10-09 공통 3D 그래픽 방향](게임_풍경과_재질.md#world-graphics-20261009)을 적용한다. **조작은 2026-10-09 사용자의 직접 걷기 변경 요청을 우선하며 아래 기준으로 정정한다.** RPG·전투 방향을 다시 열지 않는다. 미래 한국의 입체 공간에 몽글의 펠트와 물건별 실제 재료의 촉감·빛을 표현한다. Galaxy S25·iPhone 15 기본형의 지속 플레이를 기준으로 삼고 PC에서는 같은 미감의 품질을 확장한다. 현재 개발 장면은 세계 상태 검증 자산이며 최종 그래픽 목표를 달성한 결과가 아니다. 조작 기준 변경 자체를 구현·검증 완료로 세지 않는다.

- WASD·방향키, 모바일 가상 조이스틱, 표준 게임패드의 왼쪽 스틱·방향 패드로 자유롭게 연속 이동한다. 바닥/장소 탭으로 목적지에 순간이동하는 기본 조작은 폐기한다. 화면·입력 방식에 따라 조작을 바꿔도 같은 위치·충돌·경계 규칙을 따른다.
- 캐릭터를 따라오는 추적 시점을 기본으로 하고 동네 전체를 보는 시점을 별도로 선택할 수 있게 한다. 시점과 그래픽 ‘균형/경험’을 구별하며, 생활을 열 때 강제 줌·자동 회전을 넣지 않는다.
- 대상 가까이에서 E·고정 상호작용 버튼·게임패드 A로 생활 행동 목록을 연다. 근접·이동만으로 문답을 자동 시작하지 않으며, 여러 대상·행동을 임의로 하나만 남기지 않는다. 목록의 대상·행동·revision은 입력 동안 고정해 누르던 줄이 다른 대상의 행동으로 바뀌지 않게 한다.
- 대화창·입력란을 사용하는 동안과 창 초점 상실·백그라운드 전환 시 걷기 입력을 멈춘다. UI 조작이 걷기로 흘러가지 않아야 한다. WebGL을 사용할 수 없는 환경의 텍스트 대안은 명시적으로 구별하고, 그 대안을 직접 걷기 검증으로 세지 않는다.
- 화면 UI는 [펠트 부품](펠트부품/README.md)을 따른다. 다중 행동 목록·긴 대사·소리 끔·움직임 감소를 휴대폰 크기와 실기기에서 확인한다.

첫 성능 시험 공간은 집·길·쉼터와 첫 등장인물만 포함한다. 320/390px 화면 배치와 별도로 실제 Galaxy S25·iPhone 15에서 이동→대화→배치→재입장, 발열·프레임·메모리·로딩·읽기 편안함을 기록한다. 장시간 시험은 같은 장면을 반복하면서 수행한다. 엔진 구성은 최신 기술 조사 권고와 실제 제작 선택을 구분하고, 수치 목표는 실기기 결과로 확정한다. 정지 그림이나 데스크톱의 휴대폰 화면 크기만으로 성능·멀미를 통과 처리하지 않는다.

각 행은 A/B/거절, 같은 결과의 쉬운 지원/확장 지원, 확정 직전/직후 중단, 다음 방문을 확인한다. 공유 기능이 있는 행은 두 사용자가 같은 몸체·자리를 요청하는 경우도 추가한다. 기능의 저장 검사만 통과하고 화면의 인과가 보이지 않으면 그 행은 미완료다. 반대로 화면을 꾸몄어도 상태·소유·인지가 틀리면 미완료다. 완성 분량은 이 행 수가 아니라 실제 제작·검증된 장면 수로 기록한다.

먼저 구현할 공통 기능은 `생활 선택 → 유효한 반응 계획 → 예약/단계 확정 → 현재 화면 → 재방문` 한 줄을 끝까지 잇는다. 이후 카드별 새 동작을 붙이되 **NPC가 실제로 걷고 기다리고 물건을 쓰는 부분**을 대사 선택으로 대체하지 않는다. 장면별 입력·자산·상태 값은 제작 시 이 표의 담당 기능으로 배정하고, 기존 API 확장이 필요한 경우 해당 엔진 정본과 소비처에 함께 반영한다. 이 표는 새 하네스·별도 총괄 엔진의 설계가 아니다.

**상세 설계에서 채운 것:** [첫 공간·집 물건·H00 원고·FT10/51 입력과 명령·계정 상태·저장 이관](싱크타운_첫플레이_실행설계.md), [첫 배역과 관계 사건](싱크타운_주민관계와_연속생활_원고.md). 다음은 이 명세를 실제 장면 데이터와 코드로 옮기는 일이다. 세 입력 전체와 장면별 인식 검증은 첫 출시 전에 충족한다. **최종 자산·실행 전 확인할 것:** 첫 풍경의 실제 미술, 역할명으로 구분한 주민의 최종 얼굴·목소리, 3D 실행 경로와 대상 기기의 성능. 가격·모든 주민의 장편·16인 공동 공간의 세부를 첫 연결 시제품의 선행 조건으로 늘리지 않는다.
