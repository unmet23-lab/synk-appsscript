# 시안 A의 방을 고객 앱에 옮기는 설계 — 2판 (2026-11-24)

유호님 11-24 「A로 진행」에 이어 「방(2판) 설계를 지금 시작」하라고 하셨다. 1판(입장과 들어가는 순간)은 [옮기기_설계.md](옮기기_설계.md)에 있고 06시 묶음에 올라간다. 이 문서는 그 뒤의 방이다. 시안: [A.html](A.html)의 `#pick` · `#images`. Fable 설계 검토(11-24, 「고쳐서 구현」 · P1 7 · P2 14 · P3 3)를 반영했다. 처리는 끝 절에 있다.

## 목적

방에 들어온 손님은 지금 볼 것 하나와 단추 하나만 본다. 고르는 일은 그림 아이콘으로 접고, 「추천대로 맡기기」를 주 단추로 둔다. 기능은 지우지 않고 아이콘 · 서랍 · 판 안으로 옮긴다.

## 바탕을 어둡게 하는 까닭

지금 방은 11-20에 밝은 「낮 판」으로 바뀌었다(유호님 「이 결로 진행」, 판 81). 시안 셋 가운데 밝은 작업실은 C였고, 유호님은 어두운 방의 A를 고르셨다. 방향 고르기 · 글 콘티 · 장면 이미지 · 영상 확인 화면은 지금도 어둡다. 방만 밝아서 흐름이 검정 → 밝음 → 검정으로 오간다(1판 Fable 설계 검토 P2 8). 그래서 방도 A의 검정으로 옮기고 `data-day` · `sx-day`를 거둔다.

낮 판에서 더한 내용은 남긴다. 담당자 한마디는 담당자 말 색(옅은 판)으로, 받으실 날은 왼쪽 판 맨 아래로 간다. `data-day`에 걸려 있던 같은 소식 접기(`tidyEcho`), 재생 표 자리, 주소창 색은 새 방 뿌리 속성(`data-room-a`)에 다시 건다. 제목의 다홍 강조 구절(`TITLE_MARKS`)은 거둔다. A의 색 역할에서 다홍은 「새로 도착」 표시에만 쓰기 때문이다.

## 나눠 올리기

방 화면이 그리는 상태는 열다섯이고(방향 고르기 제외), 방 마크업을 맞추는 시험이 스무 파일이 넘는다. 세 묶음으로 나눈다. 묶음마다 카본 · Fable 최종 검수와 회사 묶음을 따로 거친다.

| 묶음 | 바꾸는 것 | 그대로 두는 것 |
|---|---|---|
| ① 방 틀과 머리 | 새 머리(모든 방 화면), 의뢰서 서랍(모든 방 화면), 「더 보기」 차림, 방 화면(`roomView`) 열다섯 상태를 왼쪽 판 + 오른쪽 무대로, 어두운 바탕, 예시(`demo=film`). 1판 후속(휴대폰 발판 줄과 쪽 번호) | 방향 고르기 · 글 콘티 · 장면 이미지 · 영상 확인의 속(머리와 서랍만 새것) |
| ② 방향 고르기(영상 전 확인 1/3) | 아이콘 다섯 + 「추천대로 맡기기」, 무대가 곧 모델 고르기, 판(sheet) | 보내는 양식과 서버 |
| ③ 글 콘티(2/3) · 장면 이미지(3/3) | 컷 띠(고른 컷만 넓어짐), 컷마다 「좋아요 · 고칠 곳」, 1차안의 나눈 말을 서랍으로 | 보내는 동작, 환불 안내 확인 창 |

①이 먼저다. 모든 화면이 새 머리와 서랍을 쓰고, ①이 들어가야 흐름이 한 결(검정)이 된다. ①만 나간 동안 방향 · 1차안 · 영상 화면은 새 머리에 옛 속이다. 머리의 「의뢰서」와 「나눈 말」은 그 화면들에서도 동작해야 한다(아래 서랍).

## ① 방 틀과 머리

### 머리

| 자리 | 지금 | 바꾼 뒤 |
|---|---|---|
| 왼쪽 | 로고, 프로젝트 이름 단추, 「접수 번호 P-…」 | 로고, 프로젝트 이름 단추(`data-room-go="room"` 그대로). 접수 번호는 의뢰서 서랍으로 |
| 가운데 | 단계 단추 다섯(글자 줄) + 줄 끝 입구 셋(SYNK 작품 · 마케팅 성과 · 인플루언서 광고) | 다섯 칸 막대 + 지금 단계 이름. 줄 끝 입구 셋은 「더 보기」로 |
| 오른쪽 | 「나눈 말」, 「앱 설치」, 「알림 n」, 언어 메뉴(글자 링크) | 아이콘 단추 셋: 「의뢰서」, 「나눈 말」(새 말 수 · 답할 되묻기 점 그대로), 「더 보기」 |

**다섯 칸 막대.** 칸마다 지금 단추 그대로다(`sx-step` · `is-now` · `data-room-go="request|check|draft|make|review"` · 잠금 규칙 · `aria-current`). 단계 이름 글도 단추 안에 직접 글자로 둔다. 자동 안내 시험(`pulse-auto-reply-facts`)이 단추 안 글로 단계 이름을 뽑기 때문이다. 넓은 화면에서는 글자를 CSS로 감추고(글자 크기 0, 화면 읽기는 그대로 읽음) 단추 바탕으로 막대를 그린다. 막대 옆에 지금 단계를 말로 한 번 더 쓴다(「방향과 모델 확인」처럼, 맹검 11-24). 이 글은 꾸밈이라 화면 읽기에서 뺀다(`aria-hidden`). 영어 821~1000px에서 머리 가운데가 좁으면 이 글을 먼저 감춘다(캡처로 확인).

**「더 보기」 차림.** 누르면 아래로 작은 목록이 펼쳐진다(`aria-expanded`). 바깥을 누르거나 Esc면 닫히고 단추로 초점이 돌아간다. 열림은 `s.moreOpen`에 둔다. 머리(`#header-actions`)는 `render()`와 앱 설치 안내가 통째로 다시 쓰기 때문이다. 목록:

- SYNK 작품(지금 조건)
- 마케팅 성과(지금 조건: 스위치가 켜진 손님, 단계와 상관없이)
- 인플루언서 광고(지금 조건)
- 내 모델(스위치 `myModels` 켜짐, 지금 방 아래 줄과 같은 조건)
- 알림 n(누르면 지금 알림함. 닫으면 초점은 「더 보기」 단추로)
- 앱 설치(PC 앱 창이면 뺌)
- 언어(허락 언어가 둘 이상일 때)

알림 · 마케팅 성과 · 인플루언서 광고에 새 것이 있으면 「더 보기」 아이콘에 다홍 점을 단다. 다시 그린 뒤 초점 되살리기는 차림이 닫혀 있으면 「더 보기」 단추에 초점을 둔다.

**휴대폰.** 머리 한 줄은 로고 · 프로젝트 이름(말줄임) · 아이콘 셋이다. 다섯 칸 막대와 단계 이름은 그 아래 얇은 한 줄로 간다.

**예시(`demo=film`).** `exampleHead`도 같은 머리를 쓰고 오른쪽은 「의뢰서」 · 「나눈 말」 둘이다. 예시는 앱 머리 듣개(`app.mjs`의 `roomCustomer()` 조건)에 닿지 않으므로 `demo-film.mjs`가 같은 서랍 열기 · 닫기를 단다. 세 묶음 모두 `demo-film.mjs`를 함께 고친다.

**옛 프로젝트(의뢰서 없음).** 옛 머리와 옛 화면을 그대로 둔다. 새 짜임의 CSS는 새 방 뿌리(`.sx-room[data-room-a]`)와 새 머리 클래스 안에서만 건다. 옛 현황 · 묻기 · 납품 · SYNK 작품 화면이 같은 `.sx-room-hero` · `.sx-room-left` · `.sx-room-screen`을 쓰기 때문이다.

**다시 그린 뒤 초점.** 같은 `data-room-go` 값이 머리와 방 안에 함께 있다. 초점이 머리에 있었으면 머리에서 먼저, 방 안에 있었으면 방 안에서 먼저 찾는다(지금은 늘 방 안 먼저).

### 의뢰서 서랍

나눈 말과 같은 서랍 틀이다(넓은 화면 오른쪽 400px, 휴대폰 아래 시트, `role=dialog aria-modal`, 형제 inert, 가림막, Esc, 연 단추로 초점). 두 서랍은 동시에 열리지 않는다.

- **그리는 곳:** 방 · 방향 · 1차안 · 영상 확인 · 작품 · 마케팅 · 인플루언서, 손님 방 화면 모두. `main` 밖 한 자리(`#room-brief`)에 그리고 듣개(「고치기」 `data-room-do="edit"`, 「자료 더 보내기」 `data-room-file`, 번호 복사 `copy-number`)는 `app.mjs` 한 곳에서 받는다. 지금은 방 화면의 `mountRoom`만 이 듣개를 단다.
- **안:** 맨 위 접수 번호와 복사 단추, 의뢰서 칸, 받은 자료, 준비 칸(바뀐 내용 · 준비 자료 · 납품 규격 — 있을 때).
- **여는 길:** 머리 「의뢰서」, 단계 막대의 첫 칸(`goRoom('request')`), 준비 칸 단추(`showRoomPaper(name)` — 서랍을 열고 그 칸으로 굴린다), 지난 결정 아이콘 줄의 의뢰서 칩.
- **열림 상태:** `s.briefOpen`(+ 굴릴 칸)에 두어 실시간 다시 그리기 뒤에도 열린 채다.
- **write 상태:** 의뢰서가 아직 없으므로 「의뢰서」 아이콘과 첫 칸은 지금처럼 의뢰서 쓰기를 연다.
- **준비 칸이 폼이다.** 400px 서랍과 390 시트에서 쓸 수 있는지 캡처로 확인한다. 못 쓰면 준비 칸만 서랍 대신 방 왼쪽 판 아래에 지금 모양으로 둔다.

접수 번호는 크몽 결제 안내(「접수 번호를 보내 주시면」)가 요구한다. 결제 상태의 왼쪽 판 결제 카드(세 걸음, 복사 단추 그대로)와 이 서랍 맨 위에 둔다. 되묻기가 열린 채 결제 요청이 온 방(ask가 pay보다 앞선다)은 결제 카드가 없으므로 서랍이 번호를 보이는 자리다.

### 방 화면의 짜임

A처럼 왼쪽 판(넓은 화면 34%, 최소 340px)과 오른쪽 무대로 나눈다. 휴대폰은 무대가 위(화면 높이의 40%), 판이 아래다.

**왼쪽 판(위에서 아래로).** 알림 상자 → 차례 줄 → 제목 → 이끄는 글 → 담당자 한마디(옅은 판) → 지난 결정 아이콘 줄 → 상태 카드(되묻기 답 칸 · 결제 · 끝맺음 · 모델 제안 · 고른 방향 · 인물 · 준비 칸 안내) → 주 단추 → 마케팅 성과 · 인플루언서 광고 입구 칩(지금 입구 조건) → 받으실 날(판 맨 아래).

**자동 안내가 읽는 마크업은 글자 하나 바꾸지 않는다.** `<p class="sx-kicker sx-turn"><i class="is-you|(빈 값)|is-done">`, `<h1 class="sx-display" data-room-title>`, `<p class="sx-body sx-room-lead" data-room-in>`, 그리고 상태마다 문구(`ROOM_COPY` · `copyBase`).

**차례 줄의 점 색.** 클래스를 더하지 않고 지금 클래스와 `.sx-room[data-state]`만으로 정한다.

| 경우 | 상태 | 점 |
|---|---|---|
| 손님 차례, 새로 도착 | script · images · review · deliver · model | 다홍 |
| 손님 차례, 도착한 것 없음 | write · ask · pay | 미색 |
| 저희 차례 | check · redirect · prepare · prepare-images · make · revise | 연두 |
| 끝 | done | 점 없음 |

**지난 결정 아이콘 줄.** 의뢰서, 모델(얼굴), 방향(방향 그림), 글 콘티, 장면 이미지, 결제를 칩으로 보인다. 사진 상품은 의뢰서 · 모델 · 첫 장 · 결제다.

- 의뢰서 칩은 의뢰서 서랍을 연다.
- 모델 · 방향 칩은 고른 방향 카드(지금 `chosenCard`)를 왼쪽 판에 편다.
- 지금 판의 글 콘티 · 장면 이미지 칩은 1차안 화면(`data-room-go="draft"`)을 연다.
- 장면 이미지 판이 온 뒤의 글 콘티 칩은 열 판이 없다(`draftModel`이 마지막 판만 준다). 누를 수 없는 「확인함」 표시로 둔다.
- 아직 오지 않은 것은 누를 수 없는 표시(「다음」, 「쓰는 중」)다.

**무대.** 올린 판(시안 · 최종본)이 있으면 어떤 상태든 그것을 먼저 건다(지금 규칙, 시험 `pulse-room-preview-priority`). 없으면 상태마다 아래 표, 표의 그림이 없거나 못 받으면 대체 순서(아래)를 따른다.

| 상태 | 차례 | 무대 |
|---|---|---|
| write | 손님 | 입장의 복도(멈춘 채, 영상 없이). 주 단추 「의뢰서 쓰기」 |
| check · redirect · prepare · make | 저희 | 소식 그림이 있으면 그 그림과 「작업 중인 화면이에요 · 완성본이 아니에요」. 없으면 고른 모델 한 명이 걷는 띠 |
| prepare-images | 저희 | 확인한 글 콘티의 컷 카드(읽기만). 지금 방이 보이는 글 콘티 요약을 잇는다 |
| ask | 손님 | check와 같다. 답 칸은 왼쪽 판 상태 카드(지금 `askList`)로 둔다. 문구 「아래 칸만 채워 주시면」과 서버 자동 안내가 이 자리를 가리킨다 |
| model | 손님 | 아래 「모델 제안」 |
| pay | 손님 | 고른 모델의 띠(사진 상품은 확인한 첫 장). 왼쪽 판에 결제 카드 |
| script | 손님 | 주 단추 「글 콘티 보기」. 무대는 고른 모델의 띠 |
| images | 손님 | 주 단추 「장면 이미지 보기」. 무대는 그 판의 컷 띠(읽기만, 모든 컷) |
| revise | 저희 | 의견을 보낸 판의 컷 띠(읽기만). 글 콘티 판이면 컷 카드 |
| review · deliver | 손님 | 시안 · 최종본 포스터(`roomPreviewScreen`). 누르면 영상 확인 화면 |
| done | 끝 | 최종본 포스터. 왼쪽 판에 끝맺음 카드(「다음 편 묻기」) |
| 인물 차례(어느 상태든) | 손님 | 맞춤 인물 그림 한 장 |

**무대 대체 순서.** 고른 모델의 걷는 띠 → 받은 자료의 첫 사진 → 방향 그림 → 앱에 있는 모델 장면 그림(`model-scene-<id>.webp`) → 멈춘 복도. 1판 복도에 없는 모델(M03)이면 걷는 띠 대신 앱의 모델 사진을 쓴다. synk.im 그림을 못 받으면 다음 순서로 넘어간다. 무대를 접지 않는다(지금 `is-no-screen`은 거둔다).

**무대 띠는 다시 그려도 이어 걷는다.** `render()`가 `main`을 통째로 바꾸므로, 같은 모델의 띠면 새 마크업에 옛 띠 노드를 옮겨 끼운다(띠에 `data-hall-key`).

**값이 모자란 곳.** 무대와 지난 결정 줄이 쓸 값을 `roomModel`(`room-view.mjs`)에 더한다. 고른 모델 id, 결제 상태의 확인한 첫 장, make · prepare-images · revise의 판 요약이다. 지금 `draft`는 네 상태에서만 채워진다.

### 모델 제안(model 상태)

사진 상품의 옷 · 머리 고르기도 이 상태다.

- 무대: 복도에 제안 모델이 가운데. 후보는 지금 모델 벽과 같은 모든 모델이다. M03은 앱의 사진으로 선다(영상 없음).
- 띠를 누르면 가운데로 올 뿐 정해지지 않는다(1판 복도와 같다). 지금 벽은 누르는 순간 보낸다.
- 주 단추: 가운데가 제안 모델이면 지금 `model-accept`(「이 모델로 할게요」), 다른 모델이면 「{이름}으로 바꿀게요」(지금 벽의 `data-room-model` 값으로 `answer_model`).
- 「말로 알려 주세요」 양식(`model-say`)은 왼쪽 판 모델 카드 아래에 그대로 둔다.

### 판 아래로 가던 것

- 의뢰서와 받은 자료, 준비 칸: 의뢰서 서랍.
- 「이 기기 기억하기」 안내: 지금 칸 그대로(안내 글 「여러 사람이 쓰는 컴퓨터라면 넘어가 주세요」, 「이 기기 기억하기」 · 「괜찮아요」). 넓은 화면은 무대 아래 띠, 휴대폰은 왼쪽 판 끝. 차림 한 줄로 줄이지 않는다(누르면 30일 기억되는 인증이다).
- 내 모델 줄: 「더 보기」의 내 모델.
- 「SYNK가 만든 다른 광고 보기」: 「더 보기」의 SYNK 작품과 같아 뺀다.

### 나눈 말

방 안에 늘 펼쳐 두던 칸(column)을 거두고 서랍 하나로 모은다(지금 drawer 방식). 읽음 표시는 서랍을 열 때 남긴다. 담당자 한마디(`roomWord`)는 왼쪽 판에 서므로 새 말을 놓치지 않는다. 서랍에서는 같은 소식을 한 줄로 접는 `is-said`를 쓰지 않는다. 1차안 화면의 왼쪽 단 나눈 말(side)은 ③에서 서랍으로 바꾸고, 영상 확인 화면은 세 묶음 뒤에도 side로 남는다.

## ② 방향 고르기

### 왼쪽 판

- 차례 줄 「내 차례 · 방향과 모델 확인」(2판째면 「다시 보내 드린 안」).
- 제목: 추천 안이 있으면 「추천대로 맡기시겠어요?」, 없으면 「두 안 가운데 골라 주세요」(안이 셋 이상이면 「안 가운데 골라 주세요」).
- 이끄는 글: 「{모델}이 나오는 「{방향}」으로 추천드려요. 바꾸고 싶은 것만 눌러 고르세요.」 그 아래 보는 방향의 한 문장(`sentence`)을 한 줄. 「추천대로」를 누르는 손님도 방향 내용을 보고 누른다.
- 담당자 한 줄(`lead`)은 옅은 판.
- 아이콘 줄: 모델(얼굴) · 방향(그림) · 옷 · 머리(옷 · 머리 줄을 그리는 의뢰만, 지금 규칙) · 한마디. 누르면 무대에 그 판이 열린다. 바꾼 칸은 테두리가 바뀐다(고른 칩은 테두리만, A 색 역할).
- 주 단추 아래 작은 줄에 값 · 받으실 날 · 수정 횟수(`termsOf`), 자리 안내, 「자세히」(포함 안내 여덟 칸 판).
- 서버 자동 안내의 방향 문구(「두 방향 중 하나를 골라 주세요」)는 그대로 둔다. 추천을 맡기는 것도 하나를 고르는 일이라 맞다.

### 주 단추

「추천대로 맡기기」는 「화면에 보이는 처음 값을 그대로 보낸다」는 뜻이다. 처음 값이 추천과 다르면 처음부터 「이대로 정하기」다.

| 경우 | 주 단추 | 처음 화면 |
|---|---|---|
| 처음 고름, 추천 안이 있음, 아무것도 바꾸지 않음 | 「추천대로 맡기기」 | 무대에 추천 안의 제안 모델 |
| 한 칸이라도 바꿈 | 「이대로 정하기」 + 옆에 방향 이름 | 그대로 |
| 추천 표시가 없음(2회차 제안에 흔함) | 「이대로 정하기」 + 옆에 방향 이름 | 방향 판을 먼저 연다(뒤로 가기 기록은 넣지 않는다). 첫 안을 추천처럼 내세우지 않는다 |
| 앞서 고른 적이 있음(고른 방향 · 서버에 남은 모델 · 같은 모델의 옷 · 머리 · 덧붙인 말) | 「이대로 정하기」 | 지난 고름을 처음 값으로 |

**처음 값.**
- 보는 안: 지금 순서(화면 상태 → 고른 안 → 추천 안 → 첫 안).
- 모델: 서버에 남은 고름(`castingOf(의뢰, castingSelection).modelId`)이 있으면 그것, 없으면 제안 모델. 서버 고름은 후보 맨 앞에 넣는다(후보 넷 밖이어도 띠에 선다).
- 옷 · 머리: 같은 모델로 앞서 고른 값(지금 규칙), 없으면 맡김.
- 덧붙인 말: 고른 상태면 채워 둔다.

**보내는 것.** 지금 양식 `data-form="direction-pick"`과 숨은 칸(optionId · modelId · outfit · hair · note), `answer_direction` 그대로다. 옷 · 머리 칸은 줄을 그리는 의뢰(`d.looks`)일 때만 보낸다(지금 규칙). 보내는 값은 늘 화면에 보이는 값이다. 한마디 칸은 판 안에 있어도 `form="…"` 속성으로 이 양식에 묶고, 쓰는 동안 `s.directionUi.note`에도 둔다(다시 그리기에 지워지지 않게).

### 무대

- **모델이 있는 의뢰:** 후보(서버 고름 → 제안 모델 → 같은 결의 모델, 최대 넷)를 1판 복도와 같은 띠로 세운다. 저절로 넘기지 않고 고른 사람이 가운데에서 걷는다. 띠를 누르면 그 사람으로 바뀐다(「이 모델로 바꿔 장면 이미지에서 보여 드려요」 한 줄). 가운데 띠가 곧 큰 사진이라 「크게 보기」는 따로 두지 않는다.
- **모델이 없는 의뢰(`noModel`):** 보는 방향의 그림을 무대 가득. 「미리 움직여 보기」(`data-dp-frame`에 영상, `data-dp-film="taste"`, 소리 있음)와 「비슷한 작품 보기」(`data-dp-film="work"`)를 무대 아래 단추로.
- **맞춤 인물 · 전용 인물:** 그 인물 그림 한 장. 옷 · 머리 아이콘은 그리지 않는다(지금 규칙).

### 판(sheet)

무대 위에 열리는 판 다섯: 방향, 옷, 머리, 한마디, 자세히.

- **방향 판:** 안마다 카드(그림 · 이름 · 문장 · 흐름 · 왜 · 「미리 움직여 보기」 · 「비슷한 작품 보기」 · 「추천」 또는 「다른 안」). 맨 아래 「둘 다 아니에요」(마지막 판이면 「모두 아니에요」)를 누르면 판 안이 지금 `direction-neither` 양식(필수 이유 칸, 「다시 제안받기」 · 「담당자와 이야기하기」, 「돌아가기」)으로 바뀐다.
- **옷 · 머리 판:** 「담당자에게 맡기기」(추천) + 세 가지. 결정 11-10 그대로.
- **한마디 판:** 덧붙일 말 200자.
- **자세히 판:** 포함 안내 여덟 칸(메일이 켜져 있으면 알림 칸 하나 더).

**판의 동작.**
- 넓은 화면: 무대 오른쪽을 덮는 판(무대의 띠는 그 뒤에 남는다). 모달이 아니다. Esc나 「닫기」로 닫고 판을 연 아이콘으로 초점이 돌아간다.
- 휴대폰: 화면 아래에서 올라오는 시트(`role=dialog aria-modal`, 형제 inert, 가림막).
- 휴대폰 뒤로 가기: 손님이 열 때 기록 한 칸을 넣고 뒤로 가기는 시트만 닫는다. 단추 · 보내기 · 제안 바뀜으로 닫히면 넣은 기록을 뺀다(1판 상영 창과 같은 방식, `film-home.mjs` `close()`). 저절로 여는 판(추천 없는 2회차)은 기록을 넣지 않는다.
- Esc 차례: 확인 창(`<dialog>`) → 나눈 말 · 의뢰서 서랍 → 「더 보기」 → 판.
- 열린 판은 `s.directionUi.sheet`에 둔다. 실시간 다시 그리기 뒤에도 열린 채다. 보낸 뒤 비운다(지금 규칙).

## ③ 글 콘티 · 장면 이미지

A의 `#images` 짜임을 둘 다에 쓴다.

### 왼쪽 판

차례 줄(「내 차례 · 글 콘티 확인」 · 「내 차례 · 장면 이미지 확인」 · 사진 「첫 장 확인」), 제목은 지금처럼 「광고가 남길 한 문장」, 담당자 note는 옅은 판, 지난 결정 아이콘 줄(모델 칸에 「다른 모델로 바꾸기」 — 지금 조건 그대로, 누르면 지금 `recast` 창), 주 단추, 받으실 날.

**주 단추.** 왼쪽 판 단추는 늘 누를 수 있다. 강조만 옮긴다. 컷을 다 보기 전에는 무대의 컷마다 「좋아요」가 면 단추이고 왼쪽 판 단추는 테두리 단추다. 다 보면 왼쪽 판 단추가 면 단추가 된다. 글: 고칠 곳이 있으면 「고칠 곳 n개 보내기」(`send`), 없으면 지금 문구(「이대로 장면 이미지 만들기」 · 「이대로 제작 시작」 · 「이 첫 장대로 진행」, `approve`). 장면 이미지와 사진의 승인은 지금처럼 확인 창(아직 안 본 컷 수, 결제 흐름이면 환불 안내 확인 칸)을 거친다.

### 무대

- **장면 이미지:** 컷 띠. 고른 컷만 넓고 나머지는 좁은 띠다. 고른 컷의 크기는 비율(`data-ratio` 값 '9:16' · '16:9' · '1:1')로 정한다. 넓은 화면은 높이에서 폭을, 휴대폰은 폭에서 높이를 정한다(390에서 16:9를 높이로 정하면 넘친다). 아래 줄에 컷 번호 · 초 · 내용 · 말 · 화면 글자, 「좋아요」 · 「고칠 곳」, 고칠 곳 칸. 「좋아요」를 누르면 다음 컷으로 넘어간다(움직임 줄이기면 바로). 「차례로 보기」(`play`)는 무대 위 단추.
- **글 콘티:** 같은 띠에 그림 대신 글 카드(컷 번호 · 초 · 화면 내용 · 말 · 화면 글자). 지금 listbox · option 짜임과 `data-cut`은 그대로 둔다.
- **사진 상품:** 장이 하나면 무대 가득 한 장, 둘 이상이면 같은 띠(「{n}번째 장」, 아직 확인하지 않은 장 수를 확인 창에 그대로).
- **잠긴 판:** 확인을 마친 판은 「이 판은 확인을 마쳤어요.」, 의견을 보낸 판은 「…반영하고 있어요」를 이끄는 글 자리에. 「좋아요 · 고칠 곳」과 주 단추를 거두고, 컷마다 보낸 표시는 남긴다. 차례 줄은 지금 방의 차례를 따른다(확인을 마친 판을 다시 열면 결제처럼 손님 차례일 수 있다). 「저희 차례」는 의견을 보낸 판에만 쓴다.
- 좌우 화살표로 컷을 옮긴다(글 칸에 초점이 있으면 받지 않는다). 컷별 반응과 의견, 빈 의견이면 보내기를 막고 그 컷으로 가는 규칙은 지금 `drafts` 맵 그대로.

**나눈 말.** 1차안 화면의 왼쪽 단(side)을 서랍으로 바꾼다.

「글 콘티」라는 말이 카페 사장님께 낯설다는 맹검 지적(11-24)은 이름을 바꾸지 않고 이끄는 글로 푼다. 「광고가 남길 한 문장과 컷마다 들어갈 말을 글로 먼저 보내 드려요.」 단계 이름은 메일 · 담당자 화면과 같이 쓰므로 여기서 바꾸지 않는다.

## 움직임과 소리

1판 복도 규칙을 그대로 쓴다. 띠는 손이 닿거나 키보드 초점이 있으면 멈추고, 숨은 탭 · 움직임 줄이기 · 데이터 절약 · load 전에는 영상 없이 그림만 둔다. 몸 전체가 도는 움직임은 넣지 않는다. A의 셔터 · 딸깍 소리는 넣지 않는다(지금 앱에 소리 설정이 없고, 누를 때마다 소리가 나면 사무실에서 곤란하다).

## 데이터와 서버

서버와 API는 바꾸지 않는다. 양식 이름(`direction-pick` · `direction-neither` · `ask` · `recast` · `model-say`), 동작(`answer_direction` · `answer_model` · `submit_draft_review` · `approve_draft` · `confirm-delivery`), 상태 계산(`roomState` · `ROOM_COPY` · `roomRoute`)도 그대로다. 화면이 쓸 값만 `roomModel`에 더한다.

- model 상태에서 띠를 눌러도 보내지 않고 주 단추가 보내는지
- 기기 기억 안내에 「괜찮아요」가 있는지
- 다시 그린 뒤 초점이 머리에 남는지, 서랍 둘이 동시에 열리지 않는지

**②:** `pulse-direction-client`, `pulse-casting-looks-client`, `pulse-room-followups`, `pulse-film-screens`를 고친다. 더할 것:
- 주 단추 네 경우
- 「추천대로 맡기기」가 화면에 보인 값(덧붙인 말 · 옷 · 머리 · 모델)을 그대로 보내는지
- 서버 고름 모델이 후보 넷 밖이어도 띠 맨 앞에 서는지
- 추천 없는 2회차, 모델 없는 의뢰, 맞춤 인물 무대
- 열린 판과 한마디 글이 다시 그리기 뒤에 남는지
- 휴대폰 뒤로 가기가 판만 닫고, 단추로 닫으면 기록이 남지 않는지
- Esc 차례

**③:** `pulse-request-client`(`sx-draft` 접두), `pulse-film-screens`(글 콘티 한 장), `pulse-photo-review-client`, `pulse-journal`(1차안 side를 서랍으로)을 고친다. 더할 것:
- 비율 셋의 컷 크기(넓은 화면 · 390)
- 잠긴 판에서 단추가 없고 보낸 표시가 남는지, 차례 줄이 방의 차례를 따르는지
- 빈 의견이면 보내기를 막는지(지금 규칙)
- 사진 한 장 · 여러 장

**눌러 보기(묶음마다):** 실제 회사 서버(127.0.0.1)로 해당 상태들을 1440 · 390에서 찍는다. ①은 check · ask · model · pay · make · review · done, 사진 상품, 모델 없는 의뢰, 의뢰서 서랍(준비 칸 폼 포함), 영어 1000px 머리. 넘침 · 깨진 그림 · 콘솔 오류 0, 서비스 워커 설치 성공. 캡처는 고친 뒤 코드로 찍은 것만 검수에 넘긴다(1판 후속 Fable 지적).

## 위험

- **마크업을 맞추는 시험이 많다.** 상태 계산 · 양식 · 동작 이름은 그대로 두고 그리는 자리만 바꾼다. 자동 안내가 읽는 마크업은 바꾸지 않는다.
- **나눈 말을 서랍으로 모으면 새 말을 덜 본다.** 담당자 한마디가 왼쪽 판에 서고 「나눈 말」 아이콘에 새 말 수가 붙는다. 열면 읽음이 남는다.
- **①만 나간 동안** 방향 · 1차안은 새 머리 · 서랍에 옛 속이다. 방향 화면은 아래 의뢰서 칸도 그대로 있고, 1차안 · 영상은 나눈 말이 왼쪽 단이다. 아이콘 동작은 서랍 덕에 모든 화면에서 같다.
- 되돌리기는 회사 묶음의 앞 판으로.
