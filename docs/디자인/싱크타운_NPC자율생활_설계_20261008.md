# 싱크타운 NPC 자율생활 — 목적이 있는 주민과 시간이 남기는 변화

> 2026-10-08 · 사용자 요청에 따른 **설계안**. 주민이 먼저 돌아다니고, 서로 만나고, 플레이어에게 부탁하고 실제로 돕는 생활을 강화한다. 새 정책값·콘텐츠 수량·성능 예산은 검증안이며 구현·출시·학생 효과를 뜻하지 않는다.
> 담당 원문: [주민](../주민_설계.md) · [대화](../대화_설계.md#language-evolution) · [행동과 세계 변화](../싱크타운_행동과_세계변화_설계.md) · [Town 세계 계약](../아틀라스_구현명세.md#town-world-contract). 이 문서는 그 원칙을 자율생활 실행 규칙으로 구체화한다.
> **같은 날 후속 사용자 확정:** 1순위는 생활 콘텐츠의 재미, 2순위는 사용자가 주인공으로 체감하는 숙련도별 주민 행동, 3순위는 TOPIK에 도움이 되는 학습이다. 열 가지 생활 방향을 모두 설계 대상으로 유지한다. 아래 행동 수치·원고·제작 순서는 이 우선순위를 실행하기 위한 제안이다.

## 1. 플레이어가 다시 마을을 걷고 싶은 이유

**내가 만든 장소를 주민이 자기 이유로 쓰고, 그곳에서 다른 주민과 일이 생기고, 이번에는 그 주민이 나를 도와준다.** 이 연결이 핵심이다. 인사 문장과 이동 애니메이션을 늘리는 것만으로 살아 있는 마을이 되지는 않는다.

- 내가 쉼터를 만들면 공방 주인이 점심에 쉬고, 찻집 주인이 차를 가져오고, 연구원이 거기서 관찰 카드를 펼친다.
- 처음에는 내가 부탁을 듣지만, 함께한 일이 생기면 주민이 내 작업을 발견하고 “받침을 고정해 드릴까요?”라며 실제 역할을 맡는다.
- 같은 장소라도 시간·날씨·주민끼리의 약속·내가 선택한 용도에 따라 누가 무엇을 하는지가 달라진다.
- 한국어가 아직 쉬운 단계여도 이 생활에 참여한다. 말의 길이와 도움을 맞추며 결과·환대·주민의 개성을 줄이지 않는다.
- 플레이어가 참여하지 않은 만남도 시작과 끝이 있고 흔적이 남는다. 모든 주민이 내 입력만 기다리는 상태를 없앤다.

### 1-1. 주민의 일과보다 먼저 정할 사용자 경험

제작은 **내가 해 보고 싶은 생활 → 내가 한 선택 → 주민이 눈앞에서 다르게 하는 행동 → 그 일이 남긴 변화 → 자연스럽게 사용하는 한국어** 순서다. NPC가 화면 밖에서 정교하게 계산되어도 이 연결이 보이지 않으면 사용자 반응형 생활의 완성으로 보지 않는다. NPC의 독립 생활은 내 선택을 알아보고 받아들일 마을의 맥락을 만든다.

장면마다 `사용자가 결정하는 것 / 그 선택으로 NPC가 바꾸는 것 / 사용자가 확인하는 순간 / 계속하거나 끝내는 방법`을 먼저 쓴다. 그 뒤 적합한 언어 항목을 연결한다. 학습 문항을 많이 넣기 위해 모임·공연·산책을 끊거나, 연습을 통과해야 주민의 환대와 보답을 받게 만들지 않는다. 언어 기록을 남기지 않는 관람·꾸미기도 완결된 생활이다.

주인공이라는 뜻은 모든 주민이 칭찬하거나 명령을 따르는 것이 아니다. 공방 주인은 통로를 막는 설치에 다른 배치를 제안하고, 찻집 주인은 개점 중 긴 동행 대신 끝난 뒤의 시간을 제시할 수 있다. 주민의 이유를 짧은 말과 실제 행동으로 보여 주고 사용자가 다른 방법·다른 주민·보류를 고른다. 거절과 의견 차이는 관계 벌점이 아니다.

조용히 보는 사용자도 주인공이 될 수 있다. 내가 선택한 관람 자리로 공연 시야가 열리고, 주민이 그 자리를 비켜 주며, 내가 고른 앙코르나 준비한 전시물이 다음 장면에 반영된다. 대답·공연 참여·앵콜 선택을 하지 않고 끝까지 구경할 수도 있다. 이때 주민들이 나를 무대에 끌어들이거나 내가 고르지 않은 공로를 만들지 않는다. 단순 근접·무응답으로 외향성·취향·한국어 능력을 추정하지 않는다.

## 2. 현재 기반과 이번에 추가할 책임

[현행 FT10·FT51](../../experiences/synk-town/README.md)은 자리·안내판 선택, 순차 주민 이용, 현재 배치에 맞는 반응과 재방문을 제공하는 로컬 제작판이다. 제한된 네 자리의 턴 방식이며 실시간 경로 탐색·다중 NPC 예약 경쟁·자율 일과는 아직 아니다.

| 담당 | 이번 설계의 입력 → 출력 | 확정하지 않는 것 |
|---|---|---|
| Town 제품 규칙 | 세계·공간·NPC 목표·수락한 일 → 일과 후보, 예약, 이동, 사건 확정 | 언어 능력을 생활량으로 추정하지 않음 |
| Core | 허용된 학습 근거·명시 선호·사용 가능한 후보 → 이해 가능한 표현/도움 제안 | NPC 위치·소유·관계·수락을 확정하지 않음 |
| Vellum | Town이 허용한 행동/근거·검수 원고 → 시점·대사·몸짓 후보 | 후보 선택을 실제 행동·전달로 만들지 않음 |
| Trail | Town 확정 사건·인지 경로·전달 → 원인과 후속 조회 | 게임 실행·보상 지급·인증을 맡지 않음 |
| Loom | 허용된 경로·배치·장면 → 움직임/정지 표현과 표시 확인 재료 | 경로 가능성·주민 이용 사실을 스스로 만들지 않음 |
| Strata | 검수된 언어 항목·선행·판본 → 장면의 학습 연결 | 관계 단계·생활 숙련·학습 성공을 판정하지 않음 |

이는 기존 [8개 엔진의 경계](../엔진8종_상향설계_v3.md#engine-contract-boundaries)를 사용한다. Town 내부 생활 규칙을 구현하며 별도 Atlas 판단 엔진·범용 에이전트 하네스는 만들지 않는다. 기본 플레이의 런타임 AI 호출은 0이다.

현행 `vellum-life.js`는 검수 후보의 조건·인지·revision·첫 전달을 검사하고 우선순위와 ID로 고른다. 아래 목표 지속성·일과·예약은 아직 그 API에 없다. Town이 해당 후보와 실행 계획을 준비하고, 공통 표현 능력을 확장할 때만 담당 계약을 개정한다. `trail-life.js`의 고정 사건 필드에 NPC 일정·개인 원문을 임의 추가하지 않는다.

## 3. 주민 한 명에게 필요한 실행 자료

성격 120항목 전체를 매 틱 계산하지 않는다. 설정에서 검수한 **행동 원형과 상황별 원고**를 만들고, 현재 상황에 맞는 것을 고른다. 아래 필드는 신규 제작 계약 제안이며 기존 API 필드가 아니다.

| 자료 | 필수 내용 | 사례 |
|---|---|---|
| 고유 목적 | 이루고 싶은 일·우선하는 가치·서툰 일·도움 줄 수 있는 일 | 찻집 주인: 손님이 편하게 머물기, 색 맞추기는 서툼 |
| 생활 일과 | 시간대별 기본 장소·행동, 날씨/휴무 대안, 멈출 수 있는 단계 | 개점 준비 → 서빙 → 점심 쉼 → 정리 |
| 단기 목표 | 계기, 현재 필요한 것, 성공 조건, 유효 기간, 대안 | 비를 피해 찻잔을 말릴 자리 찾기 |
| 관계별 지식 | 직접 본 사건·허용된 전달·함께한 약속·철회 | 공방 주인은 직접 제작에 참여한 쉼터만 알아봄 |
| 행동 원형 | 준비 → 이동 → 작업 → 마침, 필요한 자리·도구·상대 | 차 준비 → 쉼터로 이동 → 내려놓기 → 함께 쉬기 |
| 사회적 관계 | 주민별 함께하는 일·서로 부탁할 것·작은 의견 차이 | 연구원은 관찰 설명, 공방 주인은 거치대 제작 |
| 표현 묶음 | 같은 의도/결과의 쉬운 말·확장 말·몸짓·무음 대안 | “여기를 고정할게요.” / “움직이지 않게 받침을 고정할게요.” |
| 사용자 반응 계획 | 실제 원인·사용자 선택·행동 담당자·즉시/방문/재방문 변화·확인할 접점 | 내가 그늘 자리를 고르면 주민이 그 자리로 차를 옮기고 다음 모임에도 사용 |
| 현재 실행 | 계획 ID·단계·예약·현재 위치·중단 사유·재개 조건 | 못을 박기 전은 중단 가능, 보유물 인도 중에는 확정 후 마침 |

`npcIdentity`, `worldScope`, `personalEpisode`, `knowledgeRefs`, `planRevision`을 구분한다. 한 주민의 공통 설정과 특정 플레이어와의 사연을 같은 전역 상태에 저장하지 않는다.

행동 원형에는 `bodyProfile`과 승인된 `actionVariant`를 연결한다. 몽글·까몽에게 팔·손을 추가하지 않으며, 몽글의 몸 기울임·밑단 움직임과 승인된 도구 거치로 같은 작업을 표현한다. 마린과 주민은 각자 승인된 몸체를 따른다. 주민 전체를 팔 없는 형태로 가정하지 않는다. 외형이 미정인 첫 배역 원고는 받침 고정·고개/몸 인사처럼 신체를 강제하지 않는 역할로 쓰고, 표현 자산이 없는 동작은 실행 후보에서 제외하거나 같은 사실의 정지 대안을 제공한다([형태 기준](../캐릭터/가이드_정본.md), [몽글 치수 정본](../캐릭터/마스코트_치수_정본_v1.md)).

## 4. 일과보다 목표가 앞서는 순간

기본 일과는 주민이 아무것도 하지 않고 멈추지 않게 하는 바탕이다. 그 위에서 **작은 필요 → 해결 시도 → 타인과 조율 → 결과**가 생긴다. 배고픔·피로 같은 필요는 NPC 행동 다양화에만 쓰며 플레이어가 돌보지 않아 생기는 피해·관계 하락으로 연결하지 않는다.

| 목표 계열 | 생기는 조건 | 실제 변화 |
|---|---|---|
| 자기 생활 | 시간대·날씨·검수된 개인 취미 | 볕 좋은 자리에서 손질하다 비가 오면 처마로 이동 |
| 진행 중 일 | 유효한 수락/주문/공동작업 | 맡은 판을 완성하고 실제 인도 |
| 이웃과 약속 | 두 NPC의 호환 일과·관계 원고 | 점심 차 모임, 공방의 작은 수리, 관찰 장소 소개 |
| 플레이어 도움 | 현재 작업과 도움 허용·가능한 역할 | 재료를 소비하지 않고 판의 받침을 고정해 줌 |
| 새로운 부탁 | 현재 생활 문제·쉬운 참여 경로·활동 선호 | 메뉴판 위치를 같이 정하거나 직접 가져오는 방법 제시 |
| 발전하는 계획 | 앞 사건 완료·주민의 다음 바람 | 자리 → 차 모임 → 작은 전시의 서로 다른 역할 |

NPC는 해결할 수 있는 작은 일을 스스로 해결한다. 자기 해결과 플레이어 참여는 다른 흔적을 남긴다. 내가 거절하면 주민이 기본 거치대를 만들 수 있고, 함께하면 내가 고른 모양과 공동 제작 기억이 남는다. 거절을 실패 결말로 만들지도, 참여한 선택을 아무 차이 없는 것으로 만들지도 않는다.

## 5. 후보 선정·계획·실행의 순서

1. Town이 현재 범위·권한·물건·동선·NPC 인지·이용권·콘텐츠 판을 읽는다.
2. 고유 일과, 미완 약속, 현재 필요, 이웃 만남, 플레이어 접점에서 행동 후보를 만든다.
3. 불가능한 후보를 먼저 제외한다. 학습 기록이 부족해도 쉬운 대안이 있는 생활은 남긴다.
4. 아래 우선순위의 가장 높은 **실행 가능한 계층**을 고르고, 같은 계층에서 최근 반복·일과 밀림·목표 지속성을 비교한다. 학습 후보의 점수로 생활 의도와 확정된 반응 순서를 덮지 않는다.
5. NPC·대상 자리·도구·필요한 상대를 한 계획으로 예약한다. 실패하면 대안 또는 자기 일과로 돌아간다.
6. 이동 시작·도착·행동 확정 경계에서 revision과 조건을 다시 확인한다. 매 프레임 새 목표를 고르지 않는다.
7. Town이 실제 사건을 확정하고, Trail 인지·Vellum 표현·Loom 장면을 이어 보낸다. 표시 ACK는 별도다.
8. 마친 단계·남은 약속·현재 장소를 보존하고 다음 결정 시점까지 같은 목적을 유지한다.

| 우선순위 | 선택할 행동 | 끼어들기 규칙 |
|---|---|---|
| 0 | 무효 예약 해제·중복 인도 방지·막힌 통로에서 비키기 | 새 의뢰보다 우선. 확정 중 거래는 원자적 마침 뒤 처리 |
| 1 | 진행 중인 사용자 상호작용·수락한 공동 작업·이미 약속한 핵심 결과 | 새 접근·배경 장면·학습 권유가 가로채지 못함 |
| 2 | 사용자가 방금 발의한 행동과 그 선택에 약속된 주민 반응 | 장면의 다음 안전 경계에서 응답. 이미 시작한 원자적 단계는 끝낸 뒤 반영 |
| 3 | 유효한 NPC끼리 약속·지금 마쳐야 하는 자기 일 | 이미 수락한 약속을 새 호출로 무시하지 않음. 사용자에게 가능한 시간·대안을 보임 |
| 4 | 주민이 먼저 제안할 도움·초대·새 생활 | 사용자의 현재 의도·선호와 맞고 접근 예산이 남을 때. 자동 수락 없음 |
| 5 | 새 NPC 만남·배경 변형·기본 일과·휴식 | 사용자가 개입하지 않아도 생활 지속. 화면을 장악하거나 새 질문을 강제하지 않음 |

같은 조건의 동률은 세계/개인 범위·목표 주기·콘텐츠 판을 포함한 시드로 재현한다. 시드는 사실·친밀도·언어 수준을 만들지 않는다. 일반 일과가 계속 밀리면 잠시 새 접근 후보를 닫고 자신의 일을 마친다. 플레이어가 NPC에게 계속 말을 걸면 공동작업 뒤 기본 서비스를 제공할 대체 창구를 두고 다른 주민 전체를 정지시키지 않는다.

계획은 `candidate → reserved → moving → acting → completed`로 진행하고, 각 단계에서 `suspended / cancelled / invalidated`를 구분한다. 모든 행동 원형은 중단 가능한 경계와 최대 대기·대안·예약 만료를 가진다. 실행 실패를 조용히 무한 재시도하지 않는다. 계획 ID·단계 ID·세계 범위가 같은 재시도는 같은 결과로 돌아가며, 재개 때 이미 확정한 단계를 새 사건으로 만들지 않는다.

### 5-1. 사용자 발의·주민 발의·배경 생활의 반응 계획

세 종류는 동일한 NPC 실행 계약을 사용하되 사용자의 주의를 요구할 권한이 다르다. 제작표에 아래 세 시점의 결과를 연결한다. 재방문 변화는 모든 행동에 새 이야기를 붙이라는 뜻이 아니라, 이미 남은 결과를 주민이 실제로 다시 사용하는지를 정하는 칸이다.

| 발의 | 선택 순서와 주의 예산 | 즉시 보이는 반응 | 현재 방문의 결과 | 재방문에서 회수할 기억 |
|---|---|---|---|---|
| 사용자 발의 | 실행 가능한 사용자 요청을 새 접근·배경 변형보다 앞에 둠. 새 접근 횟수로 차단하지 않음 | NPC가 내 선택을 확인하고 해당 물건을 보여 주거나 목적지 쪽으로 몸을 돌림 | 내가 고른 자리로 이동·역할 분담·관람 흐름을 실제 변경 | 해당 NPC가 아는 완료 사실에 따라 같은 자리 이용·약속한 도움·이어 할 역할 |
| 주민 발의 | 현재 의도에 맞는 이유가 있을 때 §8의 접근 상한 안에서 한 명만 제안. 거절하면 끝냄 | 수락 전에는 이유를 보이는 비차단 신호만, 수락 뒤 내 선택에 반응 | 주민의 목적과 내 방식이 함께 들어간 공동 결과 | 함께한 사실을 기억하고 다음에는 다른 역할로 보답. 미수락 초대를 기억 공로로 만들지 않음 |
| 배경 생활 | 앞의 상호작용을 덮지 않는 여유 범위. 응답 요구 없음 | 자기 작업과 NPC 관계를 알아볼 수 있는 동작 | 실제 사용 흔적·이웃 간 해결. 내가 참여하면 그 순간부터 사용자 발의로 재계획 | NPC들의 사건만 지속. 플레이어가 본 것·도운 것으로 기록하지 않음 |

**반응 계획 예산 제안:** 한 선택에는 대표 반응 한 묶음을 먼저 보이고 부수 반응은 그 뒤 안전 경계로 분산한다. 한 화면에서 여러 NPC가 각자 확인 질문을 보내지 않으며, 같은 원인으로 같은 주민이 대사·편지·방문을 중복 발급하지 않는다. 지금 보여 줄 수 없는 핵심 결과는 상태로 보존하고 다음 가능한 접점에 한 번 전달한다. 화면 밖 실제 이용이 있었다면 돌아와 그 흔적을 볼 수 있지만, 이를 화면 안에서 이미 봤다는 ACK로 바꾸지 않는다.

‘대표 반응 한 묶음’은 발화 한 줄이라는 뜻이 아니다. 주민이 고개를 돌리고 고른 소품을 가져와 놓는 하나의 인과 장면이다. 가까운 주민들은 실제로 길을 비켜 주거나 자리로 이동할 수 있지만 새 대화를 동시에 열지 않는다. 배경 행동 수를 높이기보다 선택한 대상의 반응이 읽히는지 먼저 확인한다. 정확한 동시 동작·대기 시간은 휴대폰 실측과 사용자 관찰로 정한다.

### 5-2. 주민의 반응 근거와 전달 사실

신규 Town 제작 계약의 `reactionPlan`은 `causeEventId`, `playerIntent`, `actorIds`, `knowledgeRefs`, `supportMode`, `effectRefs`, `visibleCue`, `deliveryState`, `revisitHook`를 연결한다. 기존 Trail·Vellum API에 이 이름을 임의로 넣는 것이 아니라 Town에서 관리할 설계 자료이며, 연결 전 담당 계약을 검토한다.

- **행동 사실:** 누가 어떤 세계에서 무엇을 실제로 바꾸었는지 Town 확정 사건으로 남긴다. 사용자가 고른 장소와 NPC가 이용한 장소가 일치해야 한다.
- **인지 근거:** 반응하는 주민이 직접 보았는지, 함께했는지, 허용된 전달로 알았는지 분리한다. 다른 주민에게 학습 약점이나 개인 사건을 자동 공유하지 않는다.
- **사용자 신호:** 도움 요청·역할 선택·그만하기·이번에는 보기처럼 명시한 의도를 먼저 쓴다. 허용된 실제 수행은 해당 언어 항목의 지원을 고르는 근거이며 취향·성격을 만드는 근거가 아니다.
- **표시 사실:** 반응 후보 선택, 이동 시작, 작업 완료, 화면/소리 전달을 서로 다른 상태로 남긴다. 칭찬 대사가 보였다는 이유로 작업·관람·학습을 완료시키지 않는다.
- **다음 방문:** 완료된 사실과 여전히 유효한 배치에만 이어 붙인다. 배치가 바뀌면 옛 의자에 앉는 연출 대신 현재 상태에 맞는 이용 대안을 고른다. 원인을 찾을 수 없는 ‘네 덕분에’는 탈락시킨다.

## 6. 공간을 실제로 쓰는 주민

- 공간에는 걷는 연결점, 작업 자리, 앉는 자리, 대기 자리, 출입구를 구분한다. 장식이 놓인 것과 사용 가능한 것은 다르다.
- 계획은 `NPC + 목적 자리 + 필요한 도구 + 만날 상대`의 예약을 함께 얻는다. 둘이 서로의 자리를 잡고 기다리는 교착을 허용하지 않는다.
- 같은 의자는 한 명만 점유한다. 예약 기간 만료·계획 취소·접속 종료 처리 때 해제하며, 실제 행동 중에는 호스트가 갱신한다.
- 두 주민이 좁은 길에서 마주치면 통행 우선 규칙과 대기 지점으로 해결한다. 길을 막고 플레이어 입력을 요구하는 의뢰 연출을 금지한다.
- 목표 물건이 이동하면 새 위치로 경로를 다시 잡는다. 철거됐다면 현재 사용 계획을 취소하고 검수된 대안만 선택한다.
- 화면 안의 주민은 순간 이동하지 않는다. 화면 밖 이동도 연결된 장소와 경과 시간으로 설명 가능해야 한다.
- 성능을 위해 먼 주민을 생략해도 이용 결과의 계산은 같은 규칙을 쓴다. 카메라가 바라보는 곳에 보상을 더 만들지 않는다.
- 일상 이용은 반복 가능하지만 첫 감사·기념물·관계 진전은 원인 사건별 규칙을 따른다. 같은 의자 100회 이용으로 관계를 올리지 않는다.

## 7. NPC끼리 만나는 작은 장면

두 NPC의 만남은 하나의 검수된 장면 원형을 공유한다. 각자 상대를 향해 독립 대사를 골라 맥락이 깨지는 방식을 쓰지 않는다.

`제안 → 두 일과의 가능 시간 확인 → 함께 예약 → 각자 이동 → 인사/실제 행동 → 각자의 결과 기록 → 자기 일과 복귀`를 따른다. 한 명이 못 오면 취소·짧은 기다림·나중 전달 중 준비된 대안을 쓴다.

| 장면 | 플레이어가 지켜보면 보이는 것 | 참여하면 달라지는 것 |
|---|---|---|
| 찻집 주인 × 공방 주인 | 컵 받침이 흔들려 공방 주인이 받침을 고침 | 어느 자리에 둘지 제안, 내가 꾸민 쉼터에 놓임 |
| 공방 주인 × 연구원 | 관찰 카드가 바람에 날려 무게추를 시험 | 돌/나무 고르기, 전시 방식과 다음 관찰 역할 변화 |
| 연구원 × 찻집 주인 | 향이 다른 잎을 함께 살펴봄 | 차로 쓰는 식물과 관찰용 식물을 검수된 그림으로 구분 |

이름·음식만 바꾼 대화는 같은 장면 계열이다. `문제 / 역할 / 해결 방법 / 결과 / 관계 맥락` 중 실제 달라지는 항목으로 새 경험을 센다. 끼어들기 전에도 시작·작업·마침을 알아볼 수 있게 만들고, 참여하지 않아도 기본 생활은 이어진다.

플레이어가 가까이 오면 몸을 조금 열고 빈 자리를 만드는 정도로 참여 가능성을 보인다. 자동 퀴즈를 띄우지 않는다. `듣기 / 함께하기 / 지나가기`를 선택할 수 있으며, 소리 없는 관찰을 듣기 능력의 근거로 남기지 않는다.

## 8. 먼저 찾아오는 주민 — 능동성과 선택권을 함께

기존 ‘자동 말걸기 하루 한 번’ 고정은 이번 사용자 요청에 맞춰 **생활 접점별 조절 정책으로 교체하는 설계안**이다. 비차단 인사만 늘려 능동생활을 대신하지 않는다. 주민이 실제 다가와 함께할 일·도움·새 소식을 제안할 기회를 만든다.

| 접점 | 기본 표현 | 예산과 응답 |
|---|---|---|
| 배경 생활 | 일·휴식·NPC끼리 만남·물건 사용 | 플레이어 응답 요구 없음. 같은 장면 과다 반복은 별도 제한 |
| 알아봄 | 고개/몸 인사·짧은 인사·길 비켜 주기 | 카메라/조작 유지. 질문·의뢰를 붙이면 아래 접근 예산을 사용 |
| 능동 접근 | 근처까지 와서 이유 한 문장과 의사 표시 | 한 번에 한 명. 수락해야 대화/작업 시작 |
| 실제 도움 | 요청한 작업에서 역할 수행·약속한 물건 전달 | 이미 동의한 범위만 실행. 새로운 소모·배치 변경은 확인 |
| 완료 뒤 보답 | 함께 쉬기·앞으로 쓸 도구 제공·장소 소개 | 확정 결과를 먼저 충분히 보여 주고, 새 부탁은 자동 연결하지 않음 |

**선호:** `조용히 / 보통 / 활발하게`를 플레이어가 정한다. 접근을 지나친 횟수로 ‘내향형’ 같은 성향을 추정하지 않는다. 대화창 자동 열기·강제 카메라 이동은 모든 모드에서 0이다.

설정은 서로 다른 세 범위로 보존한다. **장기 ‘먼저 말 걸지 않기’**가 최우선이며 본인이 해제하기 전에는 새 플레이어 대상 발화·접근을 하지 않는다. 장면의 ‘이번에는 조용히’는 현재 상호작용의 추가 대사·새 접근을 줄이고 장면 종료 때 효력을 마치며 장기 설정을 바꾸지 않는다. 별도의 ‘오늘은 피곤해요’ 선택은 현재 방문의 부탁을 닫는다. 빈도 선호의 ‘조용히’는 본인이 바꾸기 전까지 새 접근 0인 지속 설정이다. 시간 경과·새 사건·재접속이 지속 설정을 자동으로 해제하지 않는다. 배경 생활·NPC끼리 장면은 이어지며, 사용자가 요청한 도움과 이미 수락한 일의 결과는 전달하되 새 부탁을 붙이지 않는다.

**첫 수치 검증안:** 보통은 최근 유효 플레이 15분의 롤링 구간에 능동 접근 최대 2회·주민 간 최소 3분, 활발은 최대 4회·최소 90초, 조용히는 새 접근 0회다. 구간과 최소 간격은 아래 §8-1의 같은 계정 누적시계로 계산하며 재접속·새 방문·기기 변경으로 초기화하지 않는다. 이는 목표 횟수가 아니라 상한이다. 실제 이유가 없으면 채우지 않는다.

- 유효 플레이는 앱 표시·조작 가능 상태이며 NPC에게 응답해야만 시간이 흐르는 방식은 아니다. 조용히 구경하거나 캐릭터를 움직이지 않는 시간도 포함한다. 제외하는 ‘정지’는 명시적인 일시정지·로딩/오류로 조작 불가·백그라운드이며, 무입력 길이만으로 사용자의 관심·피로·이탈을 추정하지 않는다.
- 수락한 작업·요청한 결과·사용자가 건 대화는 접근 상한 때문에 끊지 않는다. 새 의뢰를 ‘보답’으로 꾸며 상한을 우회하지 않는다.
- 대화·학습·쓰기, 배치/제작의 입력 도중에는 접근을 보류한다. 도움 후보는 도구 놓기·미리보기 닫기·배치 확정 뒤처럼 원고에 정한 안전한 경계에서 비차단 신호로 제안하고, 수락한 뒤 실제 역할을 맡는다. 작업 중 도움이 필요하다는 이유로 입력을 가로채지 않는다. 따라오기는 같은 장소의 짧은 접근까지만 허용하고 출구·집 안으로 추적하지 않는다.
- 지나치면 그 장소에서 같은 접점을 반복하지 않는다. “나중에”는 수첩에 보류하고 자동 재권유하지 않는다. “싫어요”는 같은 회차와 같은 의도의 재제안을 막는다.
- 완료 직후·귀가·쉬기 선택 뒤에는 새 접근을 닫는다. 사용자가 ‘다음 생활’이나 산책 재개를 선택하면 다시 후보를 연다.
- 활발 모드의 목표 체감은 **새 의뢰가 많음**이 아니라 도움받기·이웃 대화·함께 사용하기·다른 역할의 균형이다. 플레이어를 향한 모든 접촉을 납품 부탁으로 채우지 않는다.

<a id="approach-ledger"></a>
### 8-1. 접점의 범위와 계정 전체에서 한 번만 묻는 기록

**바뀌지 않는 규칙**은 먼저 정한다. 새 질문은 수락 전 비차단 신호 하나, 자동 대화창·카메라 전환 0, 같은 사건 재권유 0, 조용히/거절 범위 보존, 직접 호출에 정상 응답, 동의 없는 개인 이야기 완결 0이다. 아래 초·분·횟수는 첫 플레이 검증용 설정값이며 이 규칙을 완화할 권한이 아니다.

| 접점·명시 선택 | 실제 처리 | 계속 살아 있어야 하는 부분 |
|---|---|---|
| 보통/활발의 새 생활 초대 | 이 절의 Town 예산·현재 관심 접점·안전 경계를 통과한 한 후보만 접근 | 사용자가 아무 초대도 받지 않아도 일과·주민쌍·공간 이용 진행 |
| 지속 `조용히` 또는 `먼저 말 걸지 않기` | 새 접근 0. 장기 먼저 말걸지 않기는 새 개인 인사도 끔. 설정을 바꾸기 전까지 재접속/날씨/새 원고로 해제하지 않음 | 길 양보·자기 작업·NPC끼리 대화·사용자가 요청한 결과와 도움 |
| `[지금은 알아서 지내요]` | 현재 논리 방문의 새 생활 초대를 닫음. “좋아요. 저는 하던 일을 할게요.” 뒤 자기 일과로 복귀. 장기 선호는 바꾸지 않음 | 본인이 먼저 말 걸면 즉시 응답. 직접 요청 한 번은 새 접근 재개 동의가 아니며 `[이번 방문에 먼저 말 걸어도 돼요]`를 별도로 골라야 다시 열림 |
| `[이번에는 조용히]`·`[오늘은 피곤해요]` | 앞선 §8의 범위 유지: 전자는 해당 장면, 후자는 현재 방문의 부탁을 닫음. 실제 감정·건강 상태로 추론하거나 관계에 반영하지 않음 | 수락한 일의 현재 결과·필요한 확인·생활 종료. 새 부탁을 확인 문구에 붙이지 않음 |
| 사용자 발의·이미 약속한 결과 | Town 자동 접근 예산을 소비하거나 그 예산 소진으로 차단하지 않음. 현재 일정·동선·권한 확인은 그대로 | 도움·다시 말하기·하던 일 재개·직접 다음 생활 열기. 현재 회차에 필요한 응답과 별개의 새 제안은 구별 |
| Town 밖의 공통 질문·학습 안부·OS 알림 | [Atlas §8-8·8-9](../아틀라스_설계.md)의 공통 질문/알림 한도와 동의·시간 규칙 유지. Town 15분 한도를 앱 밖 발송권으로 사용하지 않음 | 이미 제공된 내용을 본인이 열어 보는 기능. 이 설계로 새 푸시나 연락 채널을 만들지 않음 |

**논리 방문과 누적시계:** Town의 `visitId`는 집·길·쉼터·개인 장면 사이에서 유지한다. 명시적인 WORLD 나가기/계정 로그아웃, 또는 서버가 확인한 **연속 30분의 비전경·연결 부재** 때 방문을 닫는 것을 초기값으로 둔다. 그 안의 앱 숨김·새로고침·재접속·기기 이동은 같은 방문이다. 다른 기기가 유효하게 Town을 이용 중이면 방문이 닫히지 않는다. 새 방문이어도 지속 선호·거절·보류·접근 이력은 보존한다. 방문이 닫히는 것은 이야기 실패·NPC 실망·선택 취소가 아니다.

`U`는 호스트가 서버 경과 시간으로 누적하는 **계정 전체의 유효 Town 플레이 초**다. 개인/공유 마을·장소·기기를 합쳐 동시에 1초까지만 늘고 기기 시각·두 기기의 시간 합으로 늘지 않는다. `U`에서 최근 구간은 `(U-900, U]`다. 각 자동 접근의 `issuedAtU`가 이 구간 안에 있으면 횟수에 포함하며 직전 접근과의 차이로 최소 간격을 확인한다. 따라서 실제 하루가 지났거나 앱을 10번 다시 열어도 유효 플레이가 흐르지 않았다면 예산이 새로 생기지 않는다. 이 시계는 질문의 상한에만 쓰고 시간대·날씨·식물 성장·NPC 일정·경제 시계는 §11과 각 원문의 서버 시간 계약을 그대로 따른다.

왼쪽 경계는 제외한다. 예를 들어 `issuedAtU=45`는 `U=944`에서 남고 `U=945`에서 창 밖으로 나간다. 모드 변경도 같은 이력을 읽는다. 활발에서 최근 900초에 3회를 쓴 뒤 보통으로 바꾸면 새 보통 예산 2회를 주지 않고, 기존 이력이 빠져 현재 창의 횟수가 2 미만이고 직전 발급 뒤 180초가 되었을 때만 가능하다. 조용히로 바꾸면 즉시 새 발급을 닫으며 이미 발급했어도 아직 전달하지 않은 접근은 안전 경계에서 취소한다. 다시 보통/활발을 켜도 옛 발급·거절·방문 시작 시각을 초기화하지 않는다. 이미 수락한 도움은 새 접근 취소와 구별해 합의한 범위로 이어 간다.

Town 호스트는 새 접근을 발급하는 전경 접점의 **짧은 전달 소유권**을 계정당 하나만 부여한다. 두 기기가 켜져 있으면 명시적으로 마지막에 Town을 연 접점으로 넘기고, 기존 소유권의 fence 판본을 올려 늦은 발급을 막는다. 이미 수락한 작업을 강제 종료하거나 그 NPC의 물리 예약을 두 기기에 복제하지 않는다. 소유권·호스트 연결을 확인할 수 없으면 새 자동 접근은 보류하고 내려받은 기본 표현과 본인이 여는 허용된 생활을 유지한다. 기기 A에서 받은 초대를 B에서 직접 이어 여는 것은 같은 사건의 사용자 요청이지 새 자동 접근이 아니다.

**같은 사건은 같은 제안이다.** Town이 `recipientId + canonicalCauseId + intentKey`의 `contactKey`를 만든다. `canonicalCauseId`는 원인 사건/회차를 가리키며 NPC 이름·대사 판본·기기·장소·앱 안/밖 채널을 바꿔 새 키를 만들지 않는다. 내용 판본 수정이 같은 부탁을 새 부탁으로 세탁하지 못하게 한다. 한 사건의 실제 다른 단계가 새 결정을 요구하면 별도 단계로 식별할 수 있지만, 이미 거절한 의도를 우회하는 단계로 편성하지 않는다. 다른 주민이 말하려면 인지 근거도 별도로 있어야 한다.

| 상태 전이·기록 | 발급·전달·응답의 의미 |
|---|---|
| `eligible → issued` | 호스트가 선호 판본·visitId·접근 예산·contactKey·전경 fence를 한 번 검증하고 예산 1회와 같은 키의 선제 접점 사용을 원자적으로 기록. NPC/접근 경로도 확보한 뒤 발급하며 실패한 사전 예약은 발급이 아님 |
| `issued → delivered / deliveryUnknown` | 실제 화면/소리 ACK가 있어야 전달. ACK가 없으면 보았다고 하지 않음. 다만 중복 방지를 위해 발급된 예산을 즉시 돌려주거나 다른 기기/채널로 재발급하지 않음. 사용자가 직접 열어 확인할 수 있음 |
| `delivered → accepted / deferred / declined / passed` | 수락·나중에·거절은 명시 입력. `passed`는 장소 이탈/새 활동 시작/표시 종료에 따른 **응답 없음**이며 거절·불만·능력 실패가 아님. 이 모두 같은 제안을 다른 NPC가 자동 재권유하는 근거가 되지 않음 |
| 미수락 뒤 NPC 자기 해결 | 그 NPC의 계획·기여만 남기며 사용자 참여·공로 없음. 수락한 개인 선택은 자기 해결로 대신 끝내지 않음 |
| 수락 뒤 중단 | 실행 계획의 미결정·실제 기여를 보존. 새 초대로 재발급하지 않고 본인이 하던 일을 열면 이어 감 |

미표시 예약은 접근 횟수가 아니다. `eligible`의 자원 예약만 했다가 화면이 닫히면 예약을 해제하고 발급 기록을 만들지 않는다. 반면 호스트가 `issued`와 예산을 확정한 뒤 표시 오류·전송 단절이 난 경우에는 전달·거절을 거짓 확정하지 않되 예산과 contactKey는 유지한다. 이를 즉시 환급해 다른 주민을 보내면 같은 사람에게 보였을 가능성이 있는 초대가 겹치므로, 자동 재발급하지 않고 사용자 요청으로만 확인한다. 다른 기기의 동시 발급·이전 fence의 늦은 표시·설정 변경과 경합하는 발급은 호스트의 현재 판본을 검사하고 한 번 확정된 동일 결과를 읽는다. 클라이언트의 '먼저 그린 뒤 기록' 순서를 허용하지 않는다. 이런 보수적 처리로 실제 보인 초대가 상한보다 적을 수 있지만 생활권리·도움·직접 시작은 줄지 않는다.

거절한 같은 회차·의도는 본인이 `[다시 해 볼게요]`를 고를 때까지 다른 방문에서도 자동 제외한다. 추가로 **현재 방문에서는 거절한 `storyFamily`의 다른 회차 자동 접근도 제외**한다([재방문 후보 계약](싱크타운_재방문_콘텐츠와_원고.md#continued-stories)). `나중에`는 수첩/직접 여는 목록에만 남고 자동 재권유하지 않는다. `passed`도 같은 contactKey의 선제 전달은 재시도하지 않지만, 다른 이유가 실제 생긴 다른 생활 후보는 기존 선호·예산 안에서 고를 수 있다. 지나침 횟수로 조용히 모드나 언어 난도를 자동 변경하지 않는다.

앱 밖 알림과 공통 접점도 같은 `contactKey`의 선제 접점 사용 여부를 확인한다. 앱 밖에서 이미 발급한 같은 초대를 Town 입장 때 또 말하지 않고, Town에서 거절한 제안을 앱 밖 알림으로 돌리지 않는다. 각 채널 자체의 승인·예산은 별도로 유지한다. 앱 밖 발급을 Town의 15분 접근 횟수로 환산하지 않으며, Town의 남은 횟수를 앱 밖 발송권으로 이전하지도 않는다. 공유하는 것은 같은 제안의 중복·거절 범위다. 이 중복 확인을 연결하지 못한 채널은 해당 Town 초대의 선제 발송 후보에서 제외한다. 개인 생활·학습 사연을 공유 NPC 몸체·잠금 화면에 공개하지 않는다. 기록에는 키·시각·상태·정책 판본·필요한 원인 참조만 두고 원문 대화나 감정 프로필을 추가하지 않는다.

### 8-2. 짧은 방문과 긴 방문의 후보·간격·끝맺음

| 초기 검증값 | 값과 적용 | 이 값이 바꾸지 않는 것 |
|---|---|---|
| 보통 | 최근 유효 900초 최대 2회, 직전 발급 뒤 유효 180초 이상 | 횟수를 채우려고 없는 일·급한 부탁을 만들지 않음 |
| 활발 | 최근 유효 900초 최대 4회, 직전 발급 뒤 유효 90초 이상 | NPC에게 모든 일을 맡겨야 하는 난도나 재료 납품량 증가가 아님 |
| 첫 선제 접점 | 논리 방문 진입 뒤 유효 45초 이상 + 첫 안전 경계 | 45초 미만 방문에는 새 초대가 없어도 됨. 사용자 호출·인사 답변·이미 약속한 결과는 기다리지 않음 |
| 단순 알아봄 | 같은 NPC의 대상 인사는 최근 유효 300초 1회, 계정 전경에서 최근 유효 60초 1회 이내 | 짧은 인사에 질문을 숨기지 않음. 길 양보·NPC 자기 동작은 이 인사 수에 포함하지 않음. 장기 먼저 말걸지 않기는 대상 인사 자체를 닫음 |
| 초대 몸짓·표시 | NPC가 사용자 앞에서 기다리는 연출은 최대 유효 8초, 접점 한 줄은 최대 유효 20초 뒤 닫음 | 수락 제한 시간 아님. 본인이 열어 읽는 상세·보기·다시 듣기에는 제한 없음. 닫혀도 같은 초대는 직접 여는 목록에서 현재 조건을 확인해 선택 가능 |
| 같은 종류의 새 요구 | 자동 접근 두 번 연속으로 재료·제작·운영 일을 새로 맡기는 의뢰를 내지 않음 | 의뢰 뒤에는 실제 도움·함께 이용·관람 초대 중 가능한 후보를 우선. 없으면 접근하지 않으며 사용자가 직접 연 의뢰는 제한하지 않음 |

예산이 남아도 **대화/학습/쓰기·배치 초안·제작 조작·공연 관람·시범 읽기·계정 복원 중**에는 새 초대를 발급하지 않는다. 창을 닫음·도구를 내려놓음·배치 확정처럼 준비된 안전 경계에서 다시 확인한다. 현재 결과의 대표 반응이 끝나기 전에는 다음 초대를 겹치지 않는다. 완료·귀가·쉬기를 선택하면 `exitOrRestGuard`를 두어 새로운 생활 제안을 닫고, 본인이 `[다음 생활]` 또는 산책 재개를 고른 뒤에만 그 경계를 다시 연다. 이는 지속 조용히/방문 한정 알아서 지내기/피곤해요를 해제하지 않는다. 닫힌 시간에 쌓인 후보를 한꺼번에 내보내지 않고 그때 참인 후보만 새로 평가한다.

새 접근 선정은 매 프레임 추첨하지 않는다. 사용자 안전 경계·실제 필요 발생·NPC가 기존 일을 마침·일과/날씨 경계에서 다음 순서로 정한다.

1. §5의 약속·직접 호출·기본 서비스가 먼저다. 남은 주민 발의 후보에서 현재 공간·인지·권한·자원·동의·접점 선호·중복 키를 확인한다. 학습 기록·호감 점수·무응답 횟수는 생활 후보를 잠그는 조건이 아니다.
2. 현재 사용자가 직접 연 생활과 관련된 **작업 도움** → 사용자가 만든 공간의 **함께 이용/기존 결과 소개** → NPC끼리 진행 중인 일을 **구경/함께하기** → **새 부탁** 순으로, 실제 이유가 있는 첫 유형을 고른다. 이미 약속한 결과 전달은 새 초대 예산 밖에서 먼저 처리하고, 결과 끝에 추가 부탁을 붙이지 않는다.
3. 같은 유형에서는 마지막으로 제안한 `storyFamily`와 같은 후보를 뒤로 보내고, 현재 장소에서 가능→실제 원인 발생이 앞선 것→안정된 원고 ID 순으로 고른다. 다른 계열이 없더라도 **원인·역할·결과가 실제 다른 작성된 후속**이면 기존 거절·중복 규칙 안에서 제안할 수 있다. 같은 일의 이름·주민만 바꾼 후보밖에 없으면 조용히 둔다. 이 순서는 새 자동 접점의 선택 규칙이며 [직접 여는 다음 생활 목록](싱크타운_재방문_콘텐츠와_원고.md)의 순서를 덮어쓰지 않는다.
4. 한 명·한 접점을 발급한 뒤 나머지 주민은 자기 목적을 이어 간다. 사용자 수락 시 현 예약·선택권을 다시 확인하고 실행으로 넘긴다. 그 사이 물건이 옮겨지거나 철거됐으면 “그 물건은 지금 여기에 없어요.”, 자리가 점유됐으면 “지금은 그 자리를 쓰고 있어요.”라고 실제 상태를 말한다. 이어 “다른 자리를 볼까요?”와 현재 유효한 대안을 주며 자동 대체·자동 수락하지 않는다.

| 현재 상황 | 한 번 보일 실제 원고와 몸짓 | 수락하지 않았을 때의 다음 행동 |
|---|---|---|
| 배치 확정 뒤 공방이 실제 보조 가능 | “받침을 고정해 드릴까요?” 도구를 내려놓고 통로 밖에 섬. `[같이 해요] [나중에요] [혼자 할게요]` | 8초 안의 접점 몸짓 뒤 자기 작업대로 돌아감. 접점 표시만 남아도 길을 막고 대답을 기다리지 않음. 본인이 목록을 열면 다시 현재 도움 가능 여부 확인 |
| 실제 새 배치를 주인이 이용할 준비가 됨 | 약속된 반응이면 “이쪽으로 차를 옮길게요.”와 실제 이동만. 새 동석 초대이면 “같이 앉아도 괜찮아요?”를 별도 contactKey·예산으로 제안 | 약속된 서빙은 동의 범위대로 실행하고, 새 동석에 답이 없으면 자기 기본 자리에서 쉼. 두 동작을 한 수락으로 합치지 않음 |
| 연구원과 공방이 실제 그림을 함께 보는 중 | 연구원이 플레이어를 향해 “그림을 같이 볼까요?”라고 허용된 한 번만 묻고 다시 그림 쪽으로 몸을 돌림 | 두 NPC는 기본 비교를 끝내고 판을 정리. 사용자가 본 것·기획한 것으로 쓰지 않음 |
| 현재 방문에서 알아서 지내기를 선택 | “좋아요. 저는 도구를 정리할게요.” 뒤 BG02의 도구 보관·휴식 | 다른 NPC의 새 초대도 닫고 기존 대상 작업만 이어 감. 사용자가 “같이 걸어요”라고 직접 요청하면 현재 가능한 경로를 정상 안내 |

20초 표시는 질문을 빨리 읽으라는 시험이 아니다. 본인이 말풍선·상세를 열면 그 시점부터 사용자 발의로 전환해 시간 제한 없이 읽고 선택한다. 이미 닫힌 신호를 놓쳤다는 경고·남은 시간·놓친 보상은 표시하지 않는다. 5분/20분/60분 방문의 접근 수는 이 규칙이 허용한 **최대값 이하**이며, 접근 횟수·수락률을 재미의 목표치나 NPC 친절 점수로 쓰지 않는다.

<a id="autonomy-without-response"></a>
### 8-3. 플레이어가 오래 구경만 해도 주민은 자기 일을 마친다

NPC 실행 상태와 사용자에게 응답을 부탁하는 상태는 분리한다. 새 초대의 `passed/deferred/declined`는 NPC 목적을 중지시키지 않는다. 한 번 받은 초대가 화면에 남아 있다는 이유로 NPC·의자·도구를 장기 예약하지 않는다. 사용자가 나중에 그 초대를 직접 열 때 다시 예약한다. 반대로 이미 수락한 개인 이야기의 핵심 선택은 사용자가 결정할 때까지 기다리되, NPC 몸체는 안전한 정지·임시 예약 반납 뒤 가능한 일과를 수행하고 복귀 요청 때 다시 확보한다. 개인 선택을 대신 끝내거나 동시에 같은 몸체로 두 일을 하지 않는다.

| 실제 배경 원인 | 응답 없이도 끝나는 자기 생활 | 화면에 남는 생동감과 막힘 대안 |
|---|---|---|
| 주인 자기 준비대에 빈 잔이 놓여 있음 | BG01: 잔 두 개 정렬→쟁반을 자기 안쪽 칸으로 이동→기본 서빙 자리 복귀 | 빈 통로·정돈된 쟁반이 남음. 놓을 곳 없으면 자기 보관으로 옮기며 플레이어 물건은 건드리지 않음 |
| 공방이 현재 자기 작업을 마침 | BG02: 도구 보관→예약 가능한 선호/기본 좌석으로 이동→실제 휴식 | 고개/몸을 펴고 쉬는 자세. 선호 자리 점유면 자기 기본 자리로 가고 사용자에게 비키라고 묻지 않음 |
| 연구원이 다음 공개 관람판을 준비해야 함 | BG03: 자기 기본 그림/허용 공개 기록의 실제 합의 형식으로 접기→표시 방향 확인→관찰 일과 | 그림 면과 설명 면의 상태가 바뀜. 해당 합의가 없으면 기본 한 장. 개인 기록 공개나 새 관람 ACK는 생기지 않음 |
| 두 주민의 공개 만남 조건이 실제 맞음 | PAIR01~03: 두 NPC·물건 예약→자기 해결/비교→각자 마침 | 서로 보는 방향·도구 이용·쪽지의 실제 전달이 바뀜. 상대가 바쁘면 작성된 혼자 해결로 끝내고 플레이어 호출로 강제 전환하지 않음 |
| 비·통로·현재 물건 상태가 실제 변함 | BG04/BG06: 자기 비품 회수 또는 길 비켜 주기→새 안전 자리에서 기존 일을 잇기 | 없는 의자에 앉지 않고 막힌 길에서 돌아옴. 같은 상태의 재계획 최대 2회 뒤 기본 정지 대안이라는 §14-1 규칙 유지 |
| 모든 현재 필요가 마무리됨 | 정리된 작업대 확인·쉬기·풍경 보기 중 원래 일과의 끝 자세 유지 | 눈·몸 방향·소품의 실제 위치로 일상 표현. 새 문제가 없으면 일부러 쟁반을 다시 기울이거나 기록을 흐트러뜨리지 않음 |

배경의 새 회차는 **실제 대상 상태 변화·기존 일과 경계·새 NPC 약속·사용자 요청**이 있을 때만 생긴다. 카메라 왕복·걸음 수·무응답 시간·앱 재시작은 새 필요가 아니다. 같은 휴식 중 작은 자세를 바꾸는 표현은 새 사건·새 관계·추가 방문 수로 기록하지 않는다. 화면 밖에서는 §12의 장소 단위 실행과 완료 시각만 계산하고, 복귀 때는 현재 상태를 보여 준다. 부재 기간만큼 연출·초대·감사를 몰아서 재생하지 않는다.

예를 들어 플레이어가 쉼터를 10분 동안 조용히 보고 있으면, 주인은 준비대를 정리하고 공방은 실제 일을 마친 뒤 쉬며 연구원은 준비된 판을 접을 수 있다. 가능한 두 주민은 공개 비교를 하고 각자 자리로 돌아간다. 이는 **조건이 있는 경우의 실행 사례**이며 10분마다 같은 만남을 강제로 생성하는 타이머가 아니다. 조용히 설정이면 플레이어 대상 초대 0인 채로 이 행동이 이어지고, 보통/활발이면 서로 다른 이유의 접점이 남은 예산 안에서만 나온다. NPC는 “대답이 없으니 서운해요”라고 말하거나 그동안의 관찰을 언어 성공·친밀도 상승으로 쌓지 않는다.

## 9. 부탁과 보답의 실제 내용

| 연결 | 플레이어의 역할 | NPC가 되돌려 주는 역할 | 남는 변화 |
|---|---|---|---|
| 쉼터 꾸미기 | 자리·용도 선택 | 공방 주인이 작업을 돕고 주인이 차를 준비 | 선택한 자리에서 실제 휴식 |
| 차 모임 준비 | 잔 수·자리 안내 또는 메뉴 선택 | 주민이 손님을 안내하고 정리를 분담 | 공동 모임 원고와 메뉴 기억 |
| 관찰 전시 | 발견 소개·그림/설명 선택 | 연구원이 내 발견을 확인하고 공방이 거치 방식 지원 | 출처가 있는 전시물과 다음 탐색 역할 |
| 비 오는 날 | 처마/실내 대안 결정 | 주민이 자기 소유 차양을 가져와 공동 공간 사용 | 맑은 날과 다른 이동·만남 |
| 내 작업의 막힘 | 도움 요청 또는 도움 제안 수락 | NPC가 설명·시범·함께 작업 중 하나 수행 | 같은 결과, 도움 사용은 학습 기록에 별도 |

보답은 필수 출석 보상이나 끊임없는 선물 지급일 필요가 없다. 전에 도움받은 주민이 이번에는 내가 하는 일의 일부를 맡는 것이 더 큰 생활 보상이다. ‘내가 대신 해 줬어’라는 말만 하고 결과가 없는 장면은 완료로 세지 않는다.

부탁마다 자가 해결·다른 NPC 협력·플레이어 참여 경로를 작성한다. 거절 후 자기 해결한 일은 그 NPC의 사건이다. 플레이어 공로·언어 정답·관계 진전을 생성하지 않는다. 이미 수락한 개인 이야기의 핵심 선택을 NPC가 오프라인 동안 대신 결정하지 않는다.

<a id="level-actions"></a>
## 10. 숙련에 맞춰 같은 주민과 더 깊이 생활하기

**언어 능력 / 생활 숙련 / 관계 / 접근 선호**를 분리한다. 언어는 듣기·읽기·표현 등 실제 수행, 생활 숙련은 해당 작업에서 맡아 본 역할, 관계는 함께한 사건과 NPC의 보답으로 남긴다. 접근 선호는 사용자가 직접 고른다. 화면에 표시할 게임 레벨이 생겨도 이 네 가지를 한 숫자로 대신하지 않는다.

한국어 지원이 달라질 때 **문장 길이만 바꾸지 않는다.** 눈앞의 물건 제시, 함께 시범, 기다리는 시점, 역할을 넘기는 시점, 사용자의 제안 뒤 바꾸는 동선과 분담까지 다르게 만든다. 아래는 네 가지 **협력 방식**이며 TOPIK 급수·친밀도·필수 승급 코스가 아니다. 쉬운 한국어로 기획하고 싶으면 ‘함께 기획’의 역할과 ‘쉬운 시작’의 표현 지원을 동시에 쓴다.

| 협력 방식 | 이 방식을 고르는 근거 | NPC가 실제로 다르게 하는 행동 | 사용자에게 남는 결정 | 동등하게 유지할 것 |
|---|---|---|---|---|
| 쉬운 시작 | Core 지원 요약상 해당 표현이 처음·도움 필요이거나 사용자가 시범·쉬운 도움을 요청 | 수락 뒤 가까이 와 물건 두 개를 보여 주고 한 동작을 함께 시범. 사용자의 선택까지 기다린 뒤 고른 물건만 이동 | 목적·장소·물건·마칠 시점. 그림으로 모임 전체를 정해도 됨 | 존중·공감·친절·보상·이야기 결말과 큰 활동 접근 |
| 익숙한 협력 | 해당 언어 기능 또는 생활 역할의 허용된 수행 근거가 있고 사용자가 일부를 맡겠다고 선택 | 모든 순서를 대신하지 않고 내 선택까지 기다림. 내가 정한 부분을 넘기고 자신의 담당 작업만 진행 | 어느 부분을 직접 할지, 도움을 다시 받을지 | 쉬운 표현·시범으로 돌아올 권리와 같은 생활 결과 |
| 제안을 넓히기 | 준비된 이유·조건 표현 또는 그림 계획을 사용자가 선택 | 내 제안을 확인한 뒤 자신의 동선·분담·준비물을 바꿈. 실행 불가한 제안은 실제 이유와 대안을 보여 줌 | 조건과 대안, 역할 교환, 제안 철회 | 높은 한국어를 이유로 더 친밀하거나 더 가치 있는 보상을 주지 않음 |
| 함께 기획 | 해당 생활의 계획 도구와 역할이 준비되어 있고 사용자가 기획을 선택 | 내 배치·순서에 맞춰 NPC들이 리허설하고 손님을 안내. 문제가 보이면 해당 지점에서 멈춰 의견을 구한 뒤 수정안 실행 | 공연 순서·장터 구성·손님 동선·분담과 최종 확정 | 한국어 초급도 그림·짧은 말·대리 설명으로 동일한 기획 가능 |

NPC 행동이 달라지는 직접 원인은 **사용자가 요청한 도움·선택한 역할·확인한 계획**이다. 허용된 한국어 수행 기록은 이해 가능한 안내와 지원 제안에 쓰며, 능력이 낮다는 이유로 물건을 빼앗아 대신하거나 높은 사람에게만 주도권을 주지 않는다. 생활 숙련은 반복 노동량이 아니라 다른 역할의 실제 완료 근거를 사용한다. 한국어가 높은 새 방문자에게 사적 고백·말 놓기·집 초대가 자동으로 열리지 않는다.

숙련도에 따른 체감 차이는 같은 의도의 상호작용 안에서 확인한다. 수량 표현을 처음 접하면 주민이 잔을 하나씩 나란히 놓아 보여 주고 각 선택을 기다린다. 익숙한 지원을 선택하면 수량 안내를 반복하지 않고 내가 정한 주문을 받아 준비대로 이동한다. 조건 표현을 사용할 준비가 되어 있고 내가 대안을 제시하면 주민이 그 대안에 맞춰 준비 순서까지 바꾼다. 듣기만 익숙하고 읽기는 처음인 경우에는 읽기 지원을 유지한다. 이 차이는 지원되는 언어와 명시한 도움 방식에 따른 것이며, 쉬운 말·그림으로 같은 주문과 대안을 정한 사람에게도 같은 생활 결과를 제공한다.

현재 도움을 유지하거나 늘릴 수 있다. 한 문제 정답·짧은 대화 성공·공연 관람·NPC 호감으로 자동 레벨업하지 않는다. 장면 안 지원 조절과 계정의 연습 수준 변경을 구분하고, 수준 변경은 [Core 수준 권유 계약](../아틀라스_구현명세.md#4-17-연습-수준과-올리기-권유-제안)의 근거·출처·본인/학원 권한을 따른다. 마을은 별도 승급기를 만들지 않고 Core의 제한을 완화하지 않는다. 대화 중 갑자기 난도를 올리지 않으며, 다음 장면에서 선택 가능한 제안으로 제공한다.

원고는 먼저 `생활 의도 + 선택 + 실제 행동 + 결과`를 고정한 뒤 쉬운 말/확장 말을 검수한다. 난도가 바뀌어 부탁 내용·보상·호칭의 동의가 달라지면 결함이다. 준비되지 않은 중급 지도·음성·평가기를 이미 지원하는 것으로 표시하지 않는다. 공연 감상에서 조건·순서·감정을 접할 수 있지만, 흥미로운 장면 자체를 언어 정답이나 TOPIK 효과로 기록하지 않는다.

### 10-1. 세 장면에서 확인할 실제 행동 차이

**A. 내가 바꾸는 찻집 자리.** 사용자가 창가 대신 그늘을 고른다. 처음이라 도움을 원하면 주인이 두 자리 앞에 차 받침을 놓아 비교하게 하고, 선택한 곳으로 자신의 차와 의자를 옮긴다. 익숙한 사용자가 직접 안내하겠다고 하면 주인은 앞서가지 않고 안내가 끝난 뒤 손님을 데려온다. 이유를 설명하거나 그림으로 햇빛을 표시하면 주인은 차양 방향과 자기 서빙 동선을 바꾼다. 다음 방문에는 그 자리가 사용 가능한 경우 그곳에서 쉬는 모습을 보인다. ‘한국어가 좋아졌네요’ 한 줄로 이 차이를 대신하지 않는다.

**B. 내가 정하는 작은 공연.** 그림 순서판으로 ‘빠른 곡 → 이야기 → 조용한 곡’을 고르면 언어 수준과 관계없이 기획자가 된다. 주민들은 그 순서로 짧게 리허설하고, 사용자가 고른 관람 자리의 시야를 비우며, 입구를 정한 쪽에서 손님을 안내한다. ‘다시 보여 줘요’ 요청에는 진행자가 첫 전환을 실제로 다시 보여 주고 기다린다. 더 넓은 표현으로 전환 이유를 조율하고 싶으면 같은 계획에 이유 설명을 추가한다. 공연을 보기만 선택하면 NPC가 설명 과제나 무대 참여를 강요하지 않는다. 다음 공연에 이전 순서를 재사용할지는 사용자가 고르며, NPC가 임의로 취향으로 굳히지 않는다.

**C. 나와 함께 준비하는 장터.** 사용자가 잎차와 관찰 그림을 한 진열대에 놓기로 한다. 쉬운 도움을 요청하면 연구원이 관찰용 그림과 마실 수 있는 차의 표시를 나란히 보여 주고 사용자가 배치를 고를 때까지 기다린다. 일부를 맡겠다고 하면 공방 주인은 진열대만 고정하고 상품 배치는 사용자에게 넘긴다. 비가 올 때 사용자가 실내 이전을 선택하면 주민들은 승인된 물건과 자기 소유 도구만 옮기고 손님 안내 역할을 교환한다. 현재 방문에는 실제 판매/제공·관람을 각각 기록하고, 다음 방문에는 함께 일한 NPC가 약속한 정리 도움을 준다. 장터 성과가 한국어 정답·개인 관계 점수로 일괄 변환되지 않는다.

## 11. 시간은 장면을 바꾸고, 참여는 역사를 바꾼다

| 시간 축 | 바뀌는 것 | 보존할 것 |
|---|---|---|
| 한 장면 | 이동·도착·작업·휴식·짧은 만남 | 이미 확정한 소모/인도, 진행 중 선택 |
| 마을의 하루 | 일과·날씨·열린 공간·만나는 조합 | 같은 시간 접속자도 핵심 활동을 할 대안 |
| 생활 사건 이후 | 자주 쓰는 자리·함께하는 사람·다음 역할 | 원인 사건, 플레이어 분기, NPC가 아는 범위 |
| 계절/콘텐츠 팩 | 풍경·행사·새 목적·새 주민의 진입 | 놓친 필수 이야기의 가치 있는 대체 경로 |

**개인 빛과 개인 일과는 사용자 시간대, 달력과 계절·날씨는 한국 날짜**라는 [마을 정본](../마을_설계.md)의 구분을 유지한다. 현재 시각은 호스트 시각을 바탕으로 허용된 사용자 시간대에 표시하며, 클라이언트 시계 변경이 생장·보답·계절 보상을 재발급하지 않는다. 시간대 변경은 개인 풍경/일과를 다시 고를 재료이지 완료 사건을 다시 만드는 근거가 아니다. 밤 이용자에게 낮 접속을 강요하지 않고 야간 변형 또는 언제든 신청 가능한 만남을 제공한다. 어느 시간대에도 적어도 두 주민을 만날 수 있다는 기존 기준을 유지한다.

공유 물리공간의 NPC 위치·일정·시설 점유는 공유 호스트가 정한 공용 일과가 권위를 가진다. 각자의 화면 빛은 사용자 시간대를 표현해도 공용 NPC를 서로 다른 자리에 두거나 서비스 가능 상태를 다르게 만들지 않는다. 개인화로 공유 날씨·다른 이웃의 시간을 바꾸지 않는다. 공용 NPC 대사는 개인의 낮/밤을 사실처럼 말하지 않고 공용 일정과 현재 행동을 참조한다.

세 가지 진행 기준은 **마을의 현재 시간 / 나와 주민의 이야기 / 작업과 생장**이다. 아래는 단계마다 필수로 작성할 추가 계약 제안이다.

| `advanceBasis` | 적용 단계와 시간 근거 | `offlineCompletion` |
|---|---|---|
| `active-world-time` | 이동·함께 수행하는 동작. 개인 장면은 활성 실행 시간, 공유 배경은 공유 호스트가 실제 실행한 시간 | 배경 자기 일과만 `allowed`; 개인 공동작업은 `blocked` |
| `elapsed-server-time` | 이미 승인한 화분 성장·준비 작업. 호스트 확정 시작 시각과 검수된 완료 조건 | 승인된 성장·준비만 `allowed`; 소모/완료를 반복 발급하지 않음 |
| `player-decision` | 초대 수락·개인 이야기 선택·역할 결정·함께하는 완결 | 항상 `blocked`; 플레이어가 다시 참여할 때 이어 감 |

각 단계는 `advanceBasis`, `offlineCompletion: allowed|blocked`, `completionPredicate`, `onResume`을 갖는다. 생장/준비가 완료돼도 다음 개인 선택을 자동 실행하지 않는다. `allowed`는 관람 ACK·언어 정답·관계 진전을 자동 생성할 권한이 아니다. 관계 변화는 규칙에 정한 실제 공동 사건·전달 근거로만 별도 확정한다. 완결이 사용자 선택을 포함하면 앞의 준비는 `elapsed-server-time`, 마지막 확인은 `player-decision`으로 분리한다.

소모된 원고를 무작위로 다시 붙여 ‘새 이야기’로 만들지 않는다. 기본 일과의 반복은 허용하며 사건 결과가 생활 습관으로 남는 것을 보여 준다. 자리 사용 시간이 바뀌고, 같이 쉬는 주민이 생기고, 다음 부탁의 역할이 바뀌어야 시간이 쌓이는 느낌이 난다.

## 12. 중단·화면 밖·미접속 처리

- **중단:** 마지막 확정 단계와 재개 위치를 저장한다. 준비/이동은 다시 계획할 수 있고 인도/보상은 사건 ID로 한 번만 확정한다.
- **화면 밖:** 장소 단위 계획과 완료 시각만 계산한다. 사용자와의 미수락 약속·관람 ACK·학습 성공은 만들지 않는다.
- **앱 숨김:** 화면 연출 시계는 멈춘다. 호스트에서 이어진 자율 일과와 새 확정 상태를 복귀 때 대조하고 옛 애니메이션을 몰아 재생하지 않는다.
- **미접속:** 시간 간격을 프레임별 시뮬레이션하지 않고 달력 경계와 의미 있는 사건만 요약한다. 일주일 쉬었다고 7일치 부탁·피로·감사를 쌓지 않는다.
- **내 생활 보존:** 미완 선택·완성 물건·관계·예약한 필수 이야기·약속한 보답은 보존한다. 결석으로 부패·실패·관계 감소를 주지 않는다.
- **돌아옴:** 현재 장면 하나, 미전달 핵심 결과 하나, 선택해서 여는 변화 기록을 제공한다. 실제로 없었던 ‘기다렸다’·‘네가 도와줬다’를 만들지 않는다.
- **오프라인 조작:** 검증 가능한 개인 임시 초안 범위만 허용한다. 공유 이동 예약·인도·보상은 서버 확정 전 완료로 표시하지 않는다.

NPC끼리의 공개 일상은 부재 중에도 진행할 수 있다. 개인 이야기의 중요한 고백·플레이어의 선택·함께하는 완결은 플레이어가 참여할 때 이어 간다. 지난 장면 다시 보기는 새 사건·보상·첫 노출이 아니다.

## 13. 개인 생활과 최대 16인 공유 마을

개인 마을의 주민 위치·사연·배치는 개인 세계 범위이며 개인 일과는 사용자 시간대를 따른다. 공유 마을의 물리적 주민 위치·시설 예약·공개 일정은 공유 호스트가 하나로 확정한다. 같은 NPC를 16개 클라이언트가 각자 서로 다른 좌석에 앉힐 수 없다. 개인 빛과 공유 일정의 구분은 §11을 따른다.

- 공유 장면의 공개 행동과 사건 의미는 같다. 개인별 한국어 표현·자막·도움은 같은 의미의 검수 판으로 제공한다.
- **한 사람이 예약한 대화/도움:** 물건 시범·기다림·역할 양도는 현재 예약자의 명시 선택으로 한 계획만 실행한다. 다른 사람에게도 같은 몸체·동작이 보이며, 다른 사람의 지원 설정으로 그 계획을 덮어쓰지 않는다. 다음 사용자는 현재 예약이 끝난 뒤 시작하거나 다른 주민/명시적인 개인 장면을 고른다.
- **여럿이 수락한 공동 생활:** 시작 전에 진행자·참가 역할·공동 행동 계획을 확정한다. 개인의 뜻 도움·자막·되묻기는 개인 접점에서 제공하고, 공동 동선·차례·시범·대기를 바꾸려면 진행자가 다음 안전 경계에서 변경안을 제시하고 영향을 받는 참가자의 명시 동의를 받는다. 동의 전에는 기존 계획을 유지한다. 혼자만 긴 시범을 원하면 별도 개인 연습/장면 또는 회차 뒤의 시범을 선택하며 다른 사람의 진행을 자동 정지시키지 않는다. 공동 신호가 필요한 공연은 [공연별 사전 계획](싱크타운_공연과_생활학습_설계_20261008.md#performance-scope)을 따른다.
- 개인 부탁·관계 기억·학습 기록은 수신자 전용 접점에서 다룬다. 개인 대화 중 NPC의 공용 몸체는 대화 중 상태를 보이되 내용을 공개하지 않는다.
- 공용 NPC 예약 대기에는 순번·가능한 대안과 취소를 둔다. 같은 사용자의 반복 예약으로 독점하지 못하게 한다. 시간 제한 수치는 실험으로 정한다.
- 개인 장편을 하려면 명시적인 개인 장면으로 전환한다. 공유 화면에 존재하지 않는 물건을 몰래 움직여 개인 결과를 연출하지 않는다.
- 공유 원고의 참가·기여·완료 조건은 역할별로 확정한다. 한 사람의 완료를 구경한 모두의 학습·개인 이야기 완료로 복사하지 않는다.
- 공유 기능 없이도 주요 생활을 혼자 완결한다. 개인/공유 원자성이 준비되지 않은 교차 소유·인도 기능은 제작 범위에 포함하지 않는다.

## 14. 세 주민이 함께 보내는 하루 — 제작 시나리오

첫 제작 배역은 [메인 구현 준비의 등장표](싱크타운_메인콘텐츠_구현준비.md#cast)를 따른다. **찻집 주인·공방 주인·연구원**은 역할명이며 아래는 연구원까지 확장했을 때의 검증 시나리오다. 현행 두 생활 코드에 세 명의 하루가 구현됐다는 뜻이 아니다.

| 때/조건 | 찻집 주인 | 공방 주인 | 연구원 | 플레이어가 얻는 차이 |
|---|---|---|---|---|
| 오전 개점 | 잔을 정리하다 흔들리는 받침을 발견 | 공방에서 수리 준비 | 관찰 산책, 찻집 앞 잎 비교 | NPC 목적이 눈에 보임. 말 걸지 않아도 생활 |
| 오전 만남 | 공방 주인에게 받침 수리 요청 | 가능 시간 합의 후 직접 가져와 수리 | 두 사람을 지나 인사하고 산책 계속 | NPC끼리 도움, 내가 없어도 작은 해결 |
| 플레이어 도착 | 나를 알아보고 차 준비를 마침 | 내가 만든 자리에서 잠시 쉼 | 관찰 카드를 펼칠 장소 탐색 | 지난 선택 때문에 주민이 쓰는 곳이 다름 |

| 점심 공동 만남 | 차를 실제 제공 | 수리한 받침 사용 | 바람에 날리는 카드 문제 제시 | 가까이서 듣거나 참여. 의뢰 자동 수락 없음 |
| 참여한 갈래 | 고른 자리로 차 이동 | 돌/나무 중 선택한 거치 방법 지원 | 고른 설명으로 전시 | 내 역할과 전시 방식이 남음 |
| 지나친 갈래 | 기본 찻집 일과 지속 | 기본 무게추를 자기 재료로 만듦 | 개인 관찰 노트로 정리 | 마을은 진행, 내 공로·소모·실패 없음 |
| 오후 비 | 처마 안으로 손님 안내 | 자기 물건만 안전한 곳으로 이동 | 실내 관찰로 전환 | 날씨가 장소와 만남 조합을 바꿈 |
| 저녁 귀가 | 허용된 완료 사실로 배웅 | 도구 정리 | 내일 관찰 후보만 준비 | 새 부탁 없이 끝냄. 다음 날 접속 의무 없음 |

다음 접속에는 내가 만든 전시만 해당 분기의 장소에 남고, 주민이 그것을 쓰는 일상이 이어진다. 같은 결과를 다시 지급하지 않는다. 새 단계는 전시를 관리하는 반복 납품 대신 ‘다른 주민에게 설명하기/다른 위치에서 관찰하기’처럼 역할이 달라질 때 연다.

### 14-1 실제 주민 원고와 자율행동 실행표

[주민 관계와 연속 생활 원고](싱크타운_주민관계와_연속생활_원고.md#cast)에 첫 고정 주민 3명과 연속 방문객 1명의 성격·취향·바람·관계, LS01~03 각 4회차, 주민쌍 3장면·보답 2종·배경 행동 6종을 작성했다. 첫 제작 화면의 이름은 찻집 주인·공방 주인·연구원이며 기존 한말순·오미자·슬을 이 역할로 치환하지 않는다. 같은 문서의 [기존 장편 연결](싱크타운_주민관계와_연속생활_원고.md#legacy)은 기존 11개 장편의 사건 기반 진입·인지·보답·완결을 연결하며 전체 장편 대본이 추가 완성됐다는 뜻은 아니다.

아래는 원고가 실제 자율생활 후보가 되는 계약이다. `cafe-owner`, `workshop-owner`, `researcher` 중 뒤의 두 ID는 신규 배역의 논리 식별자다. 표의 원고 ID는 현재 코드의 실행 함수 이름이 아니다. 첫 배치 슬롯과 이동 가능 구역은 [첫 플레이 실행설계](싱크타운_첫플레이_실행설계.md)를 따르고 온실·추가 상점은 해당 경로의 실제 제작 범위에서 연다.

한 목표 주기는 `need → attempt → use → rest/closed`다. 같은 물건·같은 상태에서 경로 재계획은 **최대 2회**를 초기 실행값으로 두고, 둘 다 막히면 자기 기본 자리의 정지 대안으로 끝낸다. 이 값은 모바일 시험 뒤 조정할 수 있으며 2회 실패를 플레이어 실패로 기록하지 않는다. 목표는 실제 대상 상태/예약 판본 변화, 일과 경계, 사용자 새 요청 때만 다시 후보화한다. 카메라 왕복·프레임 경과·재접속으로 같은 목표를 새 회차로 만들지 않는다.

플레이어가 개입하지 않은 기본 일과·NPC끼리 공개 만남은 세계 시간으로 끝날 수 있다. 수락한 개인 이야기의 장소 선택·역할·공동 마침은 `player-decision`에서 멈춘다. 경과 시간으로 완료할 수 있는 것은 승인된 준비/성장뿐이다. 원고의 ‘현재 방문 결과’는 같은 방문에서 볼 수 있는 경로를 둔다는 뜻이며 관람을 강제하거나 화면 밖 실행을 관람 ACK로 바꾸라는 뜻이 아니다.

## 15. 제작 묶음과 실제 체감의 인수 기준

첫 자율생활 검증 묶음은 [생활 재미 주설계 A](싱크타운_생활재미와_성장콘텐츠_설계_20261008.md#production)의 **LS01 핵심 4회차 + NPC 쌍 3장면 + 보답 2종 + 배경 행동 6종**과 같다. 이 묶음과 LS02·LS03 각 4회차의 실제 원고는 [주민 관계 원고](싱크타운_주민관계와_연속생활_원고.md#verification)에 작성했다. 핵심 12회차 중 3회차는 기존 FT10/20/30 재사용, 9회차는 새 후속이며 보답 원형을 사용한 회차를 별도 새 장면으로 더하지 않는다. 3개 배역의 일과·비 대안과 이 문서의 하루 사례·표현 변형도 새 이야기 수로 합산하지 않는다. 이는 원고 준비 상태이며 NPC 구현·출시 약속·검증된 플레이 분량이 아니다. 세 번째 배역의 실제 실행 전에는 기존 찻집·공방 경로로 같은 계약을 먼저 확인하고, 전체 설계 범위는 유지한다.

이 작은 묶음은 반응·예약·재방문 기억의 공통 계약을 먼저 확인하는 실험 순서다. **최종 설계 범위를 첫 세 NPC나 쉼터로 축소하지 않는다.** 주민 일과와 개인 이야기, 즉각 반응, 모임 연속극, 취향 추천, 관계 기억, 발견과 집 변화, 동행과 손님 맞이, 준비·생장, 장터, NPC 제안과 공동 발전의 열 가지 모두에 같은 사용자 중심 계약을 적용한다. 먼저 만들어 본 묶음이 통과해도 나머지 콘텐츠의 원고·행동·체감 검증이 끝난 것으로 세지 않는다.

| 반대 사례/고장 | 반드시 확인할 결과 |
|---|---|
| 플레이어가 10분 동안 아무 부탁도 받지 않음 | 주민의 일·NPC 만남·사용 흔적은 이어지고 정지 마을이 되지 않음 |
| 플레이어가 활발 모드에서 생활을 고름 | 인사뿐 아니라 접근·실제 도움·서로 다른 NPC 관계가 눈에 보임 |
| 쉬운 지원과 익숙한 지원에서 같은 자리 선택 | 시범·물건 제시·기다림·역할 양도 중 차이가 실제 행동에 나타나며 결과와 존중은 동등 |
| 초급 사용자가 그림으로 공연 전체를 기획 | NPC 리허설·관람 자리·손님 안내가 선택한 계획대로 바뀜. 높은 언어 수준 요구 0 |
| 같은 NPC에게 사용자 요청과 새 배경 변형이 동시에 생김 | 안전 경계와 기존 약속을 보존하며 사용자 요청에 먼저 응답. 이미 시작한 거래를 취소하지 않음 |
| 사용자가 조용한 관람을 선택 | 자리·시야·마침 선택이 반영되고 호출·퀴즈·무대 참여 강요 0. 관람을 한국어 정답으로 기록하지 않음 |
| 한 선택에 세 주민의 반응이 생김 | 대표 인과 장면이 먼저 읽히고 질문 중첩 0. 같은 원인 감사·편지·접근 중복 0 |

| 초급+깊은 관계 / 고급+첫 만남 | 각각 쉬운 깊은 생활 / 능력에 맞는 첫 만남. 관계와 언어 뒤섞임 0 |
| 세 NPC가 동시에 접근 가능 | 한 명만 접근. 나머지는 자연스럽게 자기 목적을 이어 감 |

| 장기 말걸지 않기·회차 조용히·빈도 조용히 설정 | 각각의 지속 범위 보존. 재접속·다른 NPC로 접근 제한 우회 0 |
| 같은 의자를 두 NPC가 요청 | 동시 점유 0. 한 명은 다른 자리·일과 선택, 교착 0 |
| 수리 도중 안내판 이동/철거 | 옛 좌표 사용·허공 작업 0. 단계에 맞는 재계획·예약 해제 |
| 도움 수락 직후 앱 종료·재전송 | 소모·인도·보답 중복 0. 마지막 확정 단계에서 복귀 |
| 한 주 부재·기기 시간 변경 | 관계 손실·필수 이야기 소실·몰아치는 부탁·날짜 보상 복제 0 |

모바일은 가까운 주민만 세부 경로·동작을 표현하고 먼 주민은 장소 단위로 계산한다. 결정은 시간 경계·사건·동선 변화에 반응하도록 하고 프레임마다 전원 후보 정렬을 하지 않는다. 프레임·메모리·전력·재개 비용의 합격 수치는 대상 기기 선정 후 실측으로 정한다.

실제 관찰에서는 ‘살아 있나요?’만 묻지 않는다. **내가 무엇을 해 보고 싶었는지, 무엇을 골랐는지, 그 선택 때문에 누가 어떻게 다르게 행동했는지, 다시 왔을 때 무엇이 남았는지**를 플레이어가 자기 말·그림 선택으로 짚는지 확인한다. 이어서 도움 방식이 이해와 주도권에 맞았는지 본다. 생활이 재미있고 반응을 체감한 뒤에 언어 연습 영역과 실제 수행 근거를 평가한다. 접근 빈도·초대 수락률·체류 시간만으로 재미나 학습효과를 주장하지 않는다.

## 16. 구현에 넘기는 원고와 검증 경계

주민별 목표/대안, 세 쌍 장면과 LS01~03의 실제 대사·분기·거절·중단·인지·결과는 [원고](싱크타운_주민관계와_연속생활_원고.md)에 연결했다. §14-1의 자원/실행표와 함께 콘텐츠 데이터로 옮길 때 현행 FT10/FT51의 확정/전달 분리를 유지한다. Town의 일과·예약·목표 실행은 이 원고의 실제 결과를 만드는 책임이며, Vellum 대사를 고르는 것만으로 완료하지 않는다.

현재 준비 범위는 **원고와 실행 가능한 설계 기준**이다. 언어/캐릭터의 최종 제작 검수·실제 NPC 구현·공유 호스트·휴대폰 체감·장기 콘텐츠 소진 검사는 남아 있다. 엔진 원본의 현재 API를 변경하기 전에는 소유 책임·판본·소비처 회귀를 별도로 대조한다. 확인되지 않은 재미와 효과를 설계 표의 개수로 합격 처리하지 않는다.
