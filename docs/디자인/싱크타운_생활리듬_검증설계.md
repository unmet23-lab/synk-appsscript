# 싱크타운 생활 리듬 검증 설계

2026-10-09. 주민이 살아 있는 느낌과 플레이어의 자유가 함께 유지되는지 확인한다. **먼저 다가오는 횟수가 많을수록 좋은 마을은 아니다.** 내가 고른 일을 방해하지 않으면서 주민의 목적·기억·변화가 보이고, 다시 들어왔을 때 하고 싶은 생활을 찾을 수 있어야 한다.

검사 대상은 [NPC 접근과 자율생활](싱크타운_NPC자율생활_설계_20261008.md#approach), [주민 관계](싱크타운_주민관계와_연속생활_원고.md#relationship), [재방문 편성](싱크타운_재방문_콘텐츠와_원고.md#pacing), [출시와 후속 편성](싱크타운_출시와_후속콘텐츠_편성.md)이다. 아래는 구현 시 사용할 검사와 플레이 관찰 계획이다. 참가자·실행 결과가 없는 현재 단계에서 실제 재미·성능·학습효과를 합격 처리하지 않는다.

## 1 고정할 권리와 조정할 수치를 나눈다

| 구분 | 처음부터 지켜야 하는 것 | 관찰 후 조정할 것 |
|---|---|---|
| 먼저 다가오기 | 대화창·카메라를 빼앗지 않음. 거절한 같은 부탁을 다른 주민·접점으로 반복하지 않음 | 접근 상한, 간격, 첫 제안 시점, 비차단 신호 표현 |
| 내가 시작하기 | 직접 연 활동·도움·관람은 자동 접근 예산으로 막지 않음 | 목록에서 익숙한 활동과 새로운 활동을 찾는 순서 |
| 관계 | 실제 사건과 해당 주민의 인지에 근거. 쉬운 한국어·관람·부재로 권리 차감 없음 | 회차 사이의 자연스러운 마무리와 다음 사건을 소개하는 방식 |
| 주민의 자율성 | 플레이어가 돕지 않아도 자기 소유·권한 안에서 기본 일과를 이어 감 | 눈앞에 보이는 이동·휴식·주민쌍 장면의 분포와 반복 간격 |
| 오래 즐기기 | 원고 수·반복·새 원고를 정확히 구분. 억지 출석·기다림·선물 노동으로 분량을 늘리지 않음 | 같은 생활을 다시 고를 때 달라지는 유효 대상·역할·현재 사용의 편성 |
| 복귀 | 승인한 준비와 확정 사실 보존. 사용자가 없는 동안 핵심 선택·사적 고백·관람을 생성하지 않음 | 현재 변화와 하던 일을 보여 주는 순서와 양 |

수치를 바꿀 때 이 권리를 완화하지 않는다. 예를 들어 마을이 조용하다는 반응에는 NPC끼리의 일과와 실제 물건 사용을 먼저 늘려 보고, 사용자에게 보내는 의뢰 수를 바로 늘리지 않는다. 이야기를 빨리 본 사람에게는 소진을 정확히 알리고 다음 제작분을 준비하며, 이미 있는 원고에 인위적인 대기일을 붙이지 않는다.

## 2 같은 출발에서 비교할 세계

실제 이용자 기록을 변형하지 않고 개발용 별도 계정·세계에서 다음 상태를 준비한다. 제작·배치·NPC 실행·전달을 각각 다른 사건으로 남겨, 검사 시작 전에 이미 완료한 것으로 꾸미지 않는다. 개발용으로 주입한 과거는 화면과 기록에 검사 자료임을 표시하며 실제 사용자의 경험으로 이관하지 않는다.

| 준비 상태 | 확보할 실제 조건 | 핵심 비교 |
|---|---|---|
| F0 첫 방문 | 기본 집과 FT10/51에 필요한 유한 자원, 과거 관계 없음 | 짧은 방문에도 자리를 보고 나갈 수 있는가 |
| F1 함께한 이웃 | 동일 FT10 자리·LS01.2 완료. 참여 A/B/관람 상태를 각각 따로 준비 | 같은 주민이 실제 기여에 맞는 말을 하는가 |
| F2 여러 유효 후보 | 서로 다른 현재 원인 사건과 가능한 주민/비품. 도움·모임·의뢰가 함께 후보 | 한 명만 접근하고 같은 사건을 겹쳐 말하지 않는가 |
| F3 조용한 생활 | 지속 조용히 또는 장기 먼저 말 걸지 않기. 두 설정은 구분 | 질문 없이도 일과·주민쌍·공간 이용이 보이는가 |
| F4 첫 원고 소진 | 단일 취향 RV 8편 완료와 혼합 RV 24편 완료를 별도 준비 | 같은 장면의 변형을 새 원고로 세지 않는가 |
| F5 준비 뒤 부재 | 승인한 유한 준비, 미확정 개인 선택, 아직 보지 않은 결과 | 복귀 시 무엇이 끝났고 무엇을 고를지 정확한가 |
| F6 현재 환경 변경 | 과거 전시/좌석을 철거하거나 다른 물건으로 교체. 과거 공동 사실은 보존 | 없는 물건을 현재 이용하거나 기억을 지우지 않는가 |
| F7 충돌과 공유 | 동일 계정 두 기기, 별도 개인/공유 범위, 예약된 단일 NPC | 중복 접근·두 몸체·타인 사연 노출이 생기지 않는가 |

한국어 지원은 같은 F1에 `짧은 말+전체 기획`과 `넓은 말+시범 요청`을 교차 적용한다. 언어 지원과 생활 역할이 같은 축으로 묶이지 않았는지 검사한다. 소리 끔·움직임 줄이기는 별도의 세계나 낮은 보상 판으로 만들지 않는다.

[실행 범위·결과](../../experiences/synk-town/qa/LIFE-C1.md), [코드 검사](../../experiences/synk-town/qa/life-runtime.json), [Chromium 실제 버튼 검사](../../experiences/synk-town/qa/life-ui.json)를 연결한다. 조용히/직접 선택, 접근 시간 경계·두 창 발급, 거절 후 복귀, 실제 역할과 미관람 기억, 현재 합의와 과거 기억 분리의 일부를 실행한 근거다.

### 2026-10-09 첫 하루 통합 근거

이후 [3D 첫 하루](../../experiences/synk-town/README.md)에 H00 방석/문→FT10/51→공방 도움/받침 준비→온실 조율→귀가/다음 외출을 연결했다. [최신 실행 기록](../../experiences/synk-town/qa/DAY.md)은 세 주민의 자기 일, 실제 주민쌍 교환, 시범/협력/기획의 다른 진행, 관람·위임의 역할 보존, 유효한 합의의 다음 이용, 승인한 한 건의 부재 중 준비를 검사한다. 기존 C1 자동 접근 원장을 재사용하며 공방·연구원의 새 자동 접근 예산은 만들지 않았다.

첫 하루의 버튼 검사는 §4의 실제 사람 관찰을 대신하지 않는다. 화면의 플레이 메모와 [실행용 관찰표](../../experiences/synk-town/qa/DAY-PLAYTEST.md)를 준비했으며 **참가자 0명, 실제 휴대폰 0대**다. 이후 로컬에서 직접 답한 읽기 기록으로 설명 방식을 제안하고 명시 수락하는 경로를 추가했다. 검증된 WORLD 계정 프로필 연결은 남아 있다. RH01~20 전체·LS 장편·열 가지 전체 완료 주장도 유지하지 않는다.

### 3-1 접근 상한의 정적 시각표

첫 자동 접근 대기 45초, 최근 유효 플레이 900초의 이동 구간 `(U-900, U]`에서 보통 최대 2회/간격 180초, 활발 최대 4회/간격 90초를 대조했다. `U`는 계정의 유효 플레이 누적 초다. 표의 출발 이력은 비어 있고 계속 안전 경계이며, 매번 서로 다른 유효한 제안 이유가 있다고 가정한다. 수락한 작업·쉬기·거절·입력 중 제안 제외가 들어가는 실제 플레이에서는 횟수가 더 적다.

| 모드 | 가장 이른 제안 시각 예시 | 5분까지 | 20분까지 | 60분까지 |
|---|---|---:|---:|---:|
| 보통 | U=45, 225, 945, 1125, 1845… | 2 | 4 | 8 |
| 활발 | U=45, 135, 225, 315, 945, 1035… | 3 | 7 | 16 |
| 조용히 | 제안 없음 | 0 | 0 | 0 |

이것은 위 초기 조건에서 가능한 **최대치**이고 주민을 그 시각마다 오게 하는 일정표가 아니다. 900초 고정 묶음을 교체하는 방식이 아니므로 899초와 900초 사이에 예산이 한꺼번에 생기지 않는다. 첫 제안 U=45는 U=945에서 구간 밖이 된다. 실제 이유가 없으면 모든 모드가 0회일 수 있다.

모드 변경도 같은 기록을 사용한다. 예를 들어 실제 제안이 U=45·225·315·405에 있었고 406부터 보통을 골랐다면, 다른 조건이 모두 충족돼도 다음 가능 시각은 **1215**다. 1125에는 315·405의 두 제안이 아직 구간에 남는다. 설정 변경·재접속·다른 기기 열기로 이를 0으로 초기화하지 않는다. 조용히에서 직접 요청한 도움은 이 자동 제안 횟수에 더하지 않는다.

위 산식은 문서 규칙만 사용하는 독립 계산으로 대조했다. 실제 Town 코드·서버의 시계·표시 확인·두 기기 경쟁을 실행한 결과가 아니며, 그 검증은 RH02~05에 남는다.

## 4 재미를 확인하는 첫 플레이 관찰

첫 연결 빌드와 최소 한 갈등/보답 장면이 실제로 작동한 뒤 **6~8명 규모의 형성 평가**를 출발안으로 삼는다. 이 인원은 통계적 효과 입증을 위한 표본이 아니다. 서로 다른 언어 도움 요구, 생활게임 경험, 짧게 이용/오래 머무르기 선호가 섞이게 하되 사람을 영구 유형으로 분류하지 않는다. 참가·기록 범위는 본인이 동의한 것으로 한정한다.

| 관찰 구간 | 안내와 준비 | 질문과 관찰 |
|---|---|---|
| 첫 방문 | “마을에서 하고 싶은 걸 골라 보세요. 언제 끝내도 됩니다.” 기본 조작만 설명 | 먼저 고른 행동, 원치 않은 개입, 나가기·도움 찾기, 끝난 뒤 자발적으로 하는 일 |
| 다른 선택 비교 | F1의 복제된 검사 세계에서 다른 역할/용도를 제공. 앞의 선택이 정답이라고 설명하지 않음 | “둘에서 달라진 게 있었나요?” 선택→실제 변화와 주민의 이유를 자기 말이나 그림으로 설명 가능한가 |
| 조용한 생활 | 사용자가 직접 조용히 선택하고 원하는 만큼 머묾 | 말이 없어도 주민이 무슨 일을 하는지 아는가. 공백을 편안함/지루함 중 무엇으로 느끼고 그 이유는 무엇인가 |
| 다시 방문 | 참가자가 실제로 끝낸 상태로 후속 방문. 개발용 소진 상태는 별도 검사 자료로 명확히 소개 | 무엇이 이어졌는지, 하고 싶은 게 남았는지, 새 원고 없는 표시를 이해하는지 |
| 마침 | 다음 일을 해야 한다는 암시 없이 종료 가능 | “다시 하고 싶은 것과 덜 하고 싶은 것은?” 계속 머문 시간 자체를 재미 점수로 쓰지 않음 |

개발용 검사 세계의 오래된 사건을 참가자가 직접 겪은 추억이라고 속이지 않는다. 같은 방문에서 빠르게 돌아오게 한 검사는 실제 장기 복귀 경험과 별도로 기록한다. 조용함을 싫어한다는 관찰 하나로 모든 사람의 접근 빈도를 올리지 않는다.

### 바꿀 근거를 남기는 최소 기록

검사별로 `testCaseId`, 가명 참가자 ID, `build/contentRevision`, 지원·역할·접근 설정, 시작 세계 참조, 실제 후보 이유/제외 이유, 제안·수락/거절·취소, 실행 결과, 인지 근거와 전달, 현재 변화, 자발적 다음 행동을 기록한다. 원문 음성·자유 대화·실명·민감한 개인 사연을 기본 수집하지 않는다. 학습 관측은 기존 Core 계약을 따르고 생활 만족 기록으로 대체하지 않는다.

비율을 적을 때 분모를 함께 쓴다. 예를 들어 “제안 8회 중 명시 수락 3회”와 “참가자 6명 중 2명이 같은 방해를 지적”은 다른 지표다. 무응답·앱 종료·지나침을 거절·언어 실패·지루함으로 자동 분류하지 않는다. 접근이 없던 세션은 수락률 0이 아니라 분모 0으로 둔다.

## 5 관찰 결과를 설계 변경으로 연결한다

| 확인한 문제 | 먼저 바꿀 것 | 그대로 지킬 것 |
|---|---|---|
| 왜 NPC가 왔는지 이해하지 못함 | 현재 대상과 이유 한 문장, 접근 전 실제 준비 동작 | 빈도를 올려 설명을 반복하지 않음 |
| 도와줬는데 다음 만남이 똑같음 | 해당 사건의 역할·물건·일과 변화가 실제 적용되는지 수정 | 친밀도 숫자/선물 횟수로 대신하지 않음 |
| 주민이 너무 자주 찾아옴 | 접근 간격·상한을 한 번에 한 항목씩 낮추고 같은 사례 재검사 | 직접 요청과 이미 수락한 결과는 유지 |
| 조용히에서는 마을이 죽은 느낌 | 현재 자원으로 가능한 NPC 자기 목표·주민쌍 행동·사용 흔적을 배치 | 플레이어 대상 질문 0 유지 |
| 선택이 많아 무슨 일을 할지 모름 | 직접 요청/하던 일 우선, 최대 3개 후보의 대상과 결과를 명확히 표현 | 나머지 가능한 활동의 직접 접근을 숨기지 않음 |
| 관계가 급격하게 변해 낯섦 | 실제 같이 한 일에 한정한 회상과 단계 마침, 개인 사연은 별도 듣기 선택 | 강제 대기일·출석·한국어 레벨 잠금 추가 없음 |
| 반복이 지루함 | 물건의 다른 실제 쓰임·역할 교환·현재 변화가 있는 후속을 제작 | 문장·손님 이름만 바꿔 신규 분량으로 계산하지 않음 |
| 새 원고를 다 본 뒤 할 일이 없음 | 현재 사용을 유지하고 준비된 후속 묶음의 제작 우선순위를 재검토 | 무한 원고/정기 업데이트 약속·재료 수급 노동으로 가리지 않음 |

권리·소유·거절·기억 오류는 한 사례라도 재현되면 해당 분기부터 수정한다. 체감 문제는 서로 다른 참가자 두 명 이상에게 같은 상황에서 반복되거나, 한 명에게 진행을 막는 뚜렷한 문제가 나타나면 수정 후보로 올리고 행동 근거를 다시 본다. 이는 작은 평가에서 문제를 놓치지 않기 위한 초기 기준이지 통계적 유의성이나 출시 합격률이 아니다.

변경은 `문제 장면 → 근거 → 바꾼 규칙/원고 → 영향받는 사례 → 재검사`로 남긴다. 한 번에 접근 빈도·대사·콘텐츠 보상을 모두 바꾸지 않아 무엇이 달라졌는지 알 수 있게 한다. 세션 길이·수락률을 최대화하는 것보다, 사용자가 원한 생활을 마치고 편하게 떠날 수 있는지를 우선한다.

## 6 다음 구현에서 받을 결과

첫 H00→FT10/51→귀가 연결 위에 LS01의 서로 다른 용도, 주민쌍 한 장면, 실제 보답 한 종류, 조용한 배경 일과를 붙여 이 리듬을 먼저 확인한다. 이 작은 검사 구간이 열 가지 전체·유료 출시 분량을 대체하지는 않는다.

받을 증거는 ①같은 시작에서 달라지는 실제 행동 ②중단/복귀·두 기기에서 보존되는 상태 ③조용히/거절 뒤 자기 일을 하는 주민 ④분량과 표시가 일치하는 후보 목록 ⑤참가자의 원인 이해와 방해 경험이다. 문서 대조는 이 검사의 준비이며 구현·실제 관찰 결과와 별도 기록한다.
