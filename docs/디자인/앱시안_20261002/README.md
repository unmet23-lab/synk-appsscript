# 앱·미니게임 키트 시안 (2026-10-02)

사용자 요청: “지금 미니게임 4개 있는데 이 중에 적용시켜봐줄수있어? 그리고 레슨화면도 한번 적용해서 전후차이를 보여줄래?”

SNS 제작 키트([README](../SNS키트/README.md))의 방식을 학생이 직접 보는 화면에 입혀 본 **시안**이다. 원본(앱 저장소 `SYNK-talk`, `experiences/order-rush`)은 고치지 않았다. 사용자가 보고 정하기 전이라 승인본이 아니다.

## 조사(2026-10-02, 오늘 방식 그대로)

2026년 학습 앱·캐주얼 게임 화면의 흐름에서 SYNK에 맞는 것만 골랐다.

| 흐름 | 근거 | 시안에 쓴 자리 |
|---|---|---|
| 눌리는 감각의 단추: 아래 두꺼운 테두리, 누르면 내려앉음 | Duolingo 디자인 분석([Blake Crosley](https://blakecrosley.com/guides/design/duolingo), [925 Studios 2026](https://www.925studios.co/blog/duolingo-design-breakdown)) | 키트의 펠트 두께 단추를 보기·행동 단추로 |
| 맞힐 때마다 짧고 분명한 반응(마이크로 피드백), 몇 분마다 작은 성취 | [Duolingo 경로 개편](https://blog.duolingo.com/new-duolingo-home-screen-design), [게이미피케이션 2026](https://yukaichou.com/gamification-examples/10-best-gamification-education-apps/) | 정답 도장, 답이 있던 낱말에 크레용 동그라미, 컨페티 한 번, 몽글 표정 컷 |
| 화면 장치를 게임 세계 안 물건으로(디제틱 UI) | [모바일 게임 UI 2026](https://pixune.com/blog/best-examples-mobile-game-ui-design/), [Sunstrike HUD](https://sunstrikestudios.com/en/blog/HUD_design_in_games/) | 읽기 지문을 ‘붙여 둔 안내문’으로, 카페 주문을 ‘주문 전표’로 |
| 큰 아이콘·적은 글자의 HUD | 같은 자료 | 미니게임 점수·콤보 칩 |

지키는 선: 마스코트는 흔들거나 떠다니지 않고 한 번 붙은 뒤 표정만 컷으로 바꾼다. 화면 흔들기·번쩍임은 쓰지 않는다. 한 화면에 손그림 하나, 장식 셋 이하.

## 1. 레슨 화면(앱 ‘맞춤 학습’)

- 전: 앱의 실제 컴포넌트 `SYNK-talk/src/맞춤학습화면.js`의 `맞춤학습내용`을 react-native-web으로 그대로 그렸다([before/](lesson/before/), `build.mjs`). 기록 저장·추천 엔진만 고정 데이터로 바꿨고, 문항은 실제 문항 `c09q4`(식당 안내)다.
- 후: 같은 문항·같은 문구로 만든 웹 시안([after/index.html](lesson/after/index.html)). `#start`·`#question`·`#answered`는 정지 화면, `#play`는 눌러서 해 볼 수 있다.
- 비교: [`lesson/비교/비교_레슨화면.jpg`](lesson/비교/비교_레슨화면.jpg)(시작·문제·정답 뒤), 휴대폰 390폭 2배로 찍음(`lesson/capture.mjs`).

| 무엇 | 지금 앱 | 키트 시안 v2 |
|---|---|---|
| 첫인상 | 검은 바탕에 글자만 | LAB 코랄 머리 면(펠트 결) + 몽글(흰 칼선)이 면에 걸쳐 앉음 |
| 시작 화면 | 글자와 단추만, 아래가 빔 | 연습 카드 + ‘이런 글을 읽어요’ 미리보기(다음 지문의 머리만 보이고 본문은 흐림) + 아래 고정 단추 |
| 지문 | 회색 상자 | 따뜻한 종이 안내문, ‘NOTICE · 식당 안내’ 꼬리표. 기울이지 않음 |
| 질문 | 글자 | 핵심어 ‘어디에서’에 형광펜 한 곳 |
| 보기 | 얇은 테두리 줄 | 가벼운 펠트 두께 타일(회색 윤곽 + 아래 4px), 누르면 3px 내려앉음 |
| 정답 뒤 | ‘정답’ 글자, 설명은 아래로 내려야 보임 | 정답 타일에 체크 배지, 지문의 ‘계산대’에 크레용 동그라미(답이 어디 있었는지), 몽글 표정이 눈웃음으로, 설명·다음 연습은 아래에서 올라오는 판 |
| 줄바꿈 | 낱말 가운데서 끊김(‘식/사’) | 낱말 단위로 끊음 |

v1에서 v2로(사용자 「마감이나 이런게 전체적으로 좀 아쉬운게 많이 보이네」): 기울어진 안내문 글자(키트 규칙 위반), 작은 화면에서 점선처럼 보이던 실땀, 납작한 노란 테이프, 글자 근처에 흩어진 컨페티, 무거운 검은 보기 테두리와 탁한 비활성 보기, 붙어 버린 여백, 잘린 몽글을 걷거나 고쳤다. 같은 교훈을 미니게임 시안에도 넘겼다. 키트 변수 안의 그림 경로(`url()`)가 쓰는 문서 기준으로 풀려 펠트 결·실땀이 조용히 안 그려지던 문제도 이때 찾았다.

**정해야 할 것:** 지금 앱은 다크 단일 테마 ‘양모 밤’과 “코랄은 녹음 버튼에만”(2026-08-20 확정, `SYNK-talk/src/테마.js`)을 지킨다. 이 시안을 앱에 넣으려면 그 원칙을 바꾸거나, 같은 구성을 다크 판으로 다시 맞춰야 한다. 앱 코드(React Native)로 옮기는 일은 채택 뒤에 한다.

## 펠트 부품(GPT Image 2.5, 2026-10-02)

사용자: “이런 단순한것들도 있잖아. 마감을 신경써줬으면 좋겠어. 실제 펠트 질감으로 GPT 2.5 IMAGE를 이용해서 뽑아서 사용해줘. … 모든 부분을 최대한 펠트질감 퀄리티 비싸게 보여야하잖아.” 그래서 납작한 CSS 원·단추를 실제 니들 펠트 부품으로 바꿨다.

- 굽기: `node tools/펠트부품GPT굽기.js --판 UI|재료 --유료-api`(모델 gpt-image-2.5-sunburst 고정). 승인된 펠트(몽글 본체·펠트 노트북)를 참조로 줘 같은 재질·빛으로 맞추고, 한 판에 여러 부품을 함께 굽는다. 글자는 굽지 않는다. 2판 참고값 합계 약 136원(UI 75원·재료 61원, `felt/생성기록.json`).
- 오리기: `python tools/펠트부품_오리기.py <판.png> <폴더> <이름들>`. 몸통은 색 거리와 털의 결로 잡고 안쪽 구멍을 채우며, 보풀은 흰 번짐을 색 계산으로 걷고, 바닥 그림자는 짙은 옅은 그림자로 바꾼다. 알파는 무손실 webp. rembg는 코랄 판 안쪽을 반투명하게 오려 쓰지 않았다.
- 늘이기: 단추·보기 타일은 펠트 판의 가운데를 좌우 반전으로 이어 5.6:1로 늘린 `*-long.webp`를 통째로 깐다(9칸 잘라 반복하면 이음매 줄이 보였다).
- 부품: [`felt/ui/`](felt/ui/)(체크 배지, 빈 원 배지 코랄·크림, 칩, 꼬리표, 단추·타일 판 코랄·크림·연코랄, 코랄·연코랄 결) · [`felt/재료/`](felt/재료/)(커피 원두·찻잎·우유·얼음·각설탕·눈송이). 한눈에: [`felt/펠트부품_시트.jpg`](felt/펠트부품_시트.jpg).
- 한계: 흰 바탕에서 구웠기 때문에 어두운 바탕에서는 털 가장자리가 옅게 빛난다. 다크 화면에 쓰려면 어두운 바탕에서 한 판을 따로 굽는다.
