## 좋음
- 웹용 판 일곱 장이 PC 원본과 같은 비율·알파 상자·바닥 여백(차이 0.016 이하)이라 바닥선이 같고, 측정한 최대 필요 크기가 모두 자연 크기 안이라 늘어나는 곳이 없다.
- 규칙 수치가 `launcher.css`와 같다(물건 공통 규칙, 첫머리 9/7/52/52%, 카드 바닥선 69%, 소개 머리 6/4%·min(36%,380px)·48%, 휴대폰 150px·62%, 큰 한글 세 크기, 어두운 칩 + LED, 흰 스티커 −2.5°, `01 / 06`, 뒤로 가기 44px). 사진에서도 PC와 같은 자리·크기·바닥선(밤·낮).
- 112화면 문제 0, 390 한 열 카드·소개 머리에서 칩이 물건을 가리지 않는다.
- 물건이 제 사업 색 면에서만 쓰인다 — 담을 수 있는 혜택 넷의 홈 바로가기, 라이브러리 카드, 관련 목록 썸네일까지.
- 새 가상 요소 큰 글자 세 곳 모두 `/ ""`, 소개 머리 h1에 서비스 이름 `sr-only`, 첫머리 그림 칸 `aria-hidden`.
- PC와 다르게 한 곳(본문 폭 기준 열 수, 카드 상자 `top:max(14%,48px)`, 본문 700px 아래 소개 머리 `top:68px`)은 바닥선을 지키며 타당하다.

1. 카드 라벨(`.benefit-kicker`) 무게가 선언한 550이 아니라 450으로 그려졌다 — 같은 파일의 `.benefit-copy>p`(450)가 선택자 무게에서 이겼다. PC는 550.

## P3
2. 구독 소개에 「라이브러리에 담기 / 즐겨찾기」 단추가 보이는데 구독은 기기 바로가기 목록에 없어 누르면 「저장하지 못했어요」라는 엉뚱한 안내가 난다(이번 diff 전부터).
3. `check.mjs`가 Playwright를 이 PC 절대 경로로 가져온다.
4. 성향 소개 물건만 `alt=""`, 나머지 다섯은 설명문(PC도 같음) — 메모.
5. 홈 바로가기 큰 글자(`platform.css` `.quick-card::before`)에 `/ ""`가 없어 화면 읽기에서 한 번 더 읽힌다(이번 변경 밖, 기존 코드).
6. 1440 플레저 카드의 물건–칩 3px는 호버(−1.5° + 4px 위로) 때 약 1.6px로 준다(계산값). 겹치지는 않는다. PC도 같은 규칙.

판정: **가볍게 다듬기** — P2 하나와 P3 2번을 고치면 그대로 둘 만하다.
