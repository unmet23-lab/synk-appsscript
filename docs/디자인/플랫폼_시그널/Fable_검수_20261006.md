## Claude 구현 기록

- **반영**: 홈페이지 H-1 사업 타일 포스터화, H-2 아틀라스 요약 빈칸, H-3 과정 카드, H-4 구역 번호, §5 아틀라스 페이지 밤 + 흰 종이 지도(회사 메인 요약 지도 포함)와 첫 화면 전환 바탕. 플랫폼 P-1 그림자 바닥, P-2 캡션 알약, P-4 휴대폰 바닥 막대, P-5 맞춤 띠 한 줄, P-6 자간 공식, P-7 메신저 청금석 빛, P-8 메신저 타일 선, P-9 중 「더 잘.」 흰 글자와 3분할 가운데 그림 위치.
- **구현에서 바꾼 것**: P-1은 lighten 덮개 대신 필터 사슬 `invert(1) brightness(1.3) brightness(.77) invert(1)`(= max(x, .23))을 곱하기 그림에 붙였다. 크롬 픽셀로 코랄 바닥이 74,31,27(면 색 30%)로 덮개와 같은 값이었고, 웹 플랫폼은 가상 요소가 이미 그레인·큰 글자에 쓰여 같은 방식을 썼다. 지도 회색은 아틀라스 디자인 시험의 무채색 목록에 있는 `#f4f4f5`를 쓰고, 시험 목록에 시그널 층의 밤 회색 다섯 값을 더했다. 과정 카드는 링크가 아니라 손을 올려도 들리지 않게 했다.
- **확인 뒤 반영(선택 2개)**: ① 메신저 물들이기 — Fable이 제안한 `hue-rotate(204deg)`는 회색 견본에서 색상 243°(보라)로 재어져, 밝기 구간 전체가 218~221°(청금석)로 유지되는 `grayscale(1) contrast(1.15) brightness(.6) sepia(1) hue-rotate(182deg) saturate(1.6)` + 불투명도 .62를 골랐다(밝은 곳이 잘려 분홍으로 틀어지던 원인). ② 회사 메인 타일 — 641px 이상에서 색 면 64%, 설명 `clamp(18px,1.5vw,21px)`.
- **하지 않은 ☆**: H-5 계기판 띠(HTML 필요), H-6 가로 스크롤 힌트, H-7 창업자 메뉴 규격, H-8 대화 카드 구 크기(스크립트), P-9 중 WORLD 포스터 그림 통일(그림 선택은 유호님 몫), P-10 같은 색 앱 교대(제안), P-11 줄 카드, P-12 GAME 01 썸네일 잘림. 600px 이하 두 칸 혜택 카드의 번호 알약은 스티커에 가려 숨겼다(Claude 추가).
- **확인**: 홈페이지 개인 빌드 `npm run check` 402/402, 9개 경로 × 1440·390 가로 넘침·오류 0, 글자 대비 기준 미달 0(이어보기 카드는 색 면 위라 측정 도구 오탐), 질문창 열기·답변·출처 창 정상, 첫 화면 ㅇ → 아틀라스 전환 흰 번쩍임 없음. 플랫폼 `node --test desktop/tests/*.test.cjs` 203/204(실패 1은 원래 있던 아틀라스 복사본 바이트 건), 화면 점검 87/87·혜택 19/19, 웹 플랫폼 시험 111/111, 외부 요청 0.

# 1. 판정

## 플랫폼(런처·웹 플랫폼): **B — 지금 판을 업그레이드**
- 방향이 맞다. 가운데 알약 메뉴, 한 글자 색 타일 목록, 사업 색 면 + 아주 큰 한글 포스터, 1px 계기판, 기울인 스티커, 떠 있는 상태 알약 — 전부 2026년의 다른 런처보다 젊고, 「싱ㅋ」 첫 화면과 같은 문법이다. 전후비교.jpg에서 촌스러움의 원인(펠트 판 단추·크림 바탕·장식 혼합)은 깨끗이 사라졌다.
- 남은 문제는 전부 「마감」이다: 이중톤이 순검정으로 떨어지는 것, 포스터 자간, 상태 알약이 내용을 덮는 것, 카드 번호 분모, 메신저 포스터의 무채색. 구조를 다시 짤 이유가 없다.

## 홈페이지(synk.im): **B — 지금 판을 업그레이드, 다만 「밤 전환」에서 「시그널 적용」으로 한 단 더**
- 새 판은 정확히 말하면 **공개 판의 구성을 토큰만 밤으로 뒤집고(signal-home.css 81줄) 메뉴·단추·로고 알약을 손본 것**이다. 홈페이지-전후비교.jpg의 좌우가 같은 구도인 이유다. 첫 화면(싱ㅋ·처마)은 그대로 훌륭하고 유리 메뉴·라벨+선·번호 열·점묘 구는 시그널과 맞지만, 둘째 화면부터는 플랫폼이 가진 「포스터·계기판·카드 체계」가 없어 **첫 화면과 본문이 다른 사이트처럼** 이어진다.
- 그래도 A(리디자인)는 틀린 답이다. 문구·구성은 오늘 승인됐고, 공개 판의 구성 자체는 9월에 검증된 것이며, 펠트 사진의 온기는 밤 바탕에서도 살아 있다. 다섯 페이지가 homepage.css 하나를 쓰므로 끝에 덧붙이는 층으로 **5~6가지 시그널 동작**(사업 타일 포스터화, 구역 머리 번호, 카드 3종 체계, 아틀라스 구역 정렬, 휴대폰 규칙)만 더하면 플랫폼과 한 몸이 된다. §4가 그 설계다.
- 창업자 페이지는 「편지」 톤으로 따로 가는 것이 맞고, 아틀라스는 §5에서 따로 판단했다.

# 6. 하지 말 것·위험

- 홈페이지 HTML 재배치·문구 수정 금지. 다섯 페이지가 `homepage.css`를 같이 쓰므로 변경은 끝 층에서만, 선택자는 페이지별 `body[data-site]`로 가둔다.
- 카드 사진까지 이중톤을 확장하지 않는다. 펠트 원색이 브랜드의 온기다. 이중톤은 포스터 자리에만.
- 스크롤 패럴랙스·자동 회전 구·흐르는 띠·자동 재생 금지(멀미 이력). 점묘 구의 빛 방향 전환도 손 올릴 때만, 200ms 이내.
- 유리 메뉴를 걷지 않는다. 밤 유리로 바뀐 지금 상태가 기준.
- 사업 색 값·바탕 2색 규칙 변경 금지. 이 문서의 「제안」(낮 바탕 진한 실, 같은 색 앱 교대, 타일 한글 글자)은 유호님이 정할 때까지 적용하지 않는다.
- 아틀라스를 밤으로 바꿀 때 전환 배경 2곳을 같이 바꾸지 않으면 번쩍인다(§5).
- 플랫폼 CSP(`img-src 'self' data:`, `font-src 'self'`)라 외부 글꼴·그림 불가 — 모든 제안은 CSS·내장 자산만. 시험이 id·data 속성에 기대므로 id 변경 금지, class 추가만.
- `color-mix`·`cqw`·`mix-blend-mode:lighten`은 Electron(Chromium)에서 문제없다. 공개 홈페이지는 iOS 16.1 이하에서 `color-mix`가 안 먹으니 lighten 덮개 색은 앱별 hex를 먼저 쓰고 `color-mix`를 뒤에 덮어쓴다(LAB #4B1F1B·SHIFT #12203C·PULSE #2E0C1C·PATH #192019·버터 #4A3B15·팝 #431C2D).
- 이중톤 덮개는 글자(z-index 2)보다 아래에 둔다. 위에 두면 검정 큰 글자가 면 색으로 올라와 대비가 죽는다.
- 홈페이지 밤 전환 뒤 공개본과 본문 대조(문구 변동 0)를 다시 확인한다 — 리디자인 기준은 공개 synk.im이다.
- 저장소 문서 이미지(홈페이지-휴대폰-390·회원혜택-밤·라이브러리-낮)는 지금 상태로 두면 유호님이 틀린 화면을 기준으로 판단한다. 업그레이드 뒤 반드시 다시 굽는다.
