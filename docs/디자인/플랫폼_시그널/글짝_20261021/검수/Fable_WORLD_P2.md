## 검수

`node tools/검수묶음.mjs`(이름 `world-p2-20261022`, 공용 작업본 `.tmp/검수/` 아래) — 바탕 `e0dead54f`, 바뀐 원천 14파일, 가져온 전·후 캡처 52장(ko·en·mn × 390·1440, 장마다 잰 값), WORLD 시험 TAP.

- **아르곤**(high, 묶음 A 코드 80KB·B 화면 19KB 둘 다 끝까지 읽음): 지적 0건. 주간 몫 10.9% → 10.7%.
- **Fable 최종**: 「그대로 공개 가능 — P0 0 · P1 0 · P2 2 · P3 4」. 아르곤이 못 본 둘은 diff 밖 경로를 따라가야 보이는 것이었다.
  - F1 [P2] 반영 — 로그인한 계정의 생활 진도 읽기가 실패하면 `prepareWorldTutor`가 입장 복구 창(「WORLD를 열지 못했어요 / 다시 불러오기」)을 띄우고 false를 돌려줘, 상태 줄이 「열린 창에서 골라 주세요」였다(고를 것이 없는 창). false 대신 `ENTRY_NOT_READY`를 던져 관문이 「다시 불러오기」를 적고 onError가 창을 띄운다. 리허설에서 생활 진도 요청만 503으로 막아 세 언어 × 390·1440 확인.
  - F2 [P2] 반영 — 첫 문장 놀이 「지금 입기」·대기 시트 「같은 요청 다시 보내기」가 409로 막히면 대기 시트와 토스트 「옷장을 다시 열고…」가 함께 떴다(옷장을 다시 열어도 저장 대기가 남아 입기가 막힌다). `msg.outfitConflict`를 옷장 상자와 같은 문장 — 대기 시트의 단추 「최신 차림 불러오기」를 누른 뒤 다시 입기 — 로(en·mn은 그 단추의 이름 그대로).
  - F3 [P3] 반영 — 몽골어 「내 계정 열기」가 두 꼴이던 것을 기존 홈 단추와 같은 «Миний бүртгэлийг нээх»로.
  - F4 [P3] 반영(재확인에서 판단을 고침) — 진도를 못 읽은 창의 「잠시 뒤 다시 열어 주세요」. 처음에는 계정 읽기 실패에도 이 상태가 난다고 보고 남겼는데, Fable 재확인대로 생활 진도 다리의 'unreadable'은 이 기기에 남은 복구 기록을 못 읽거나 호스트가 멈춘 때뿐이고 네트워크 실패는 'offline'이다(`life-progress-port.mjs` lifeStatus) — 기다려도 같다. 안내 줄은 계정 진도일 때만 홈의 「학습 기록 저장 확인하기」(이어 갈 기록 고르기 창)로 보내고, 손님은 고를 곳이 없어 사실(본문)만 둔다(`life-ui.mjs` ensureReadable).
  - F5 [P3] 반영 — 놀이 진도 충돌 창에서 고르기가 다시 충돌하면 토스트가 차림 글이었다 → 「다른 기기에서 놀이 기록이 바뀌었어요」(기존 번역 줄 `account.conflictNotice`).
  - F6 [P3] 후속 — 게임 멈춤 시트는 놀이 호스트의 멈춤(로그인 끝·계정 바뀜 등)을 모두 「로그인이 끝났어요」로 받는다. 호스트 띠 글(계정 포털 묶음에도 들어감)과 같은 전제라 코드별 문구는 그쪽과 함께 정한다.
- Fable 재확인: F1·F2·F3·F5 확인, 새 지적 0. F4는 재확인의 지적대로 고쳤다.
- 몽골어 검문은 Fable 반영분까지 `fable-01`·`fable-03`(문법 정상·맞춤법 의심 0).
