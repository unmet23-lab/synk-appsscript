§8재설계 안 — 접합점 하나를 열고, 그 위에 심판 한 층

안 A — 「접합점 하나」 (최소 변경 · 노트북 · 지금 착수 가능)

  • 여는 것: codex-review.js 의 codex() 한 함수를 검수자(벤더, 조준, 범위) 인터페이스로 열고, 구현을 셋 둔다 — codex(exec review --json --output-schema -c web_search="live" · 읽기 전용 3플래그 + 도구 8종 차단 그대로) · gemini(gemini -p … -o json --approval-mode plan --skip-trust · 키 파일 · stats.models 검산) · agy(유호님 픽 ㉮ 뒤 · 같은 모양). 장부 행에 벤더·모델(실제 서빙) 칸을 더한다.
  • 얹는 것: 합성 단계 — 벤더별 지적을 나란히 놓고 «둘 이상이 짚은 것 / 하나만 짚은 것»을 갈라 적는다(review-council 방식). 2회차일 때만 붙던 «합의 스탬프»가 «벤더 합의»로 되살아난다. 심판은 클로드(기억이 있는 쪽)이고 지적 자체는 이종이 낸다 — 「이종은 비교가 아니라 검사」 원칙 그대로.
  • 걷는 것: 구조화 2단계 호출(--output-schema 가 대신) · 밖의 사실 «손 통로» 중 «코드에 닿는 사실»(Codex 라이브 검색 반박 패스가 밖의사실.jsonl 에 행을 적는다 — 딥리서치 손 통로는 남긴다).
  • 안 건드리는 것: 배포 게이트의 내용 지문 · 종료코드 3분기(0/1/2) · 넷째 모양 방어(「못 봤다 징후 → 종료 2 · 장부에 안 적음」) · 안전 4종 · /deploy.

  • 틀릴 때의 모습: 벤더가 늘면 «지적 총량»이 늘어 처분 손이 는다(codex 미처분이 이미 31) — 그래서 합성이 «둘 이상 동의»를 앞에 세운다. 그리고 Gemini 무료 등급 250/일은 매 배포마다 쓰면 한 달에 닿을 수 있다(배포 81건/12일 실측) → 한도 도달을 «확인 불가»로 세운다.

안 B — 「노트북 없이」 (GitHub · 유호님 픽 ㉯)

  • PR 열림 → claude-code-action(Max 토큰 · /code-review --comment) + @codex review 자동 + run-gemini-cli 또는 CodeRabbit → 집계 잡이 «둘 이상 동의한 P0» 만 required status check 로. 배포는 여전히 노트북. 추가 결제 0.
  • 유호님 손이 드는 자리 셋(전부 로그인·인증): claude setup-token(어느 Max 계정에 묶을지) · Codex cloud ↔ GitHub 저장소 연결 승인 · AI Studio 키를 GitHub 시크릿에(또는 CodeRabbit 앱 설치).

안 C = A + B

배포 게이트는 안 A(노트북 · 장부 · 내용 지문)가 지고, PR 흐름은 안 B 가 «둘째 눈»으로 선다. 순서는 A → B. 이것이 권고 종착점이고, A 는 내 권한 안이다(모델 픽·제미나이 통로만 유호님).
