# 마스코트 동반자층 — 배선 설계 v1

> **v1 초안 · 2026-08-14.** 승인된 행동 설계(말할순간 v1.0 · 53+2줄 유호 전건 ○)를 실제 기능에 연결하는 설계다.
>
> **2026-09-05 — 가이드는 몽글 · 까몽 · 마린 세 명이다.** 이 연결 표의 「마스코트」는 **학생이 고른
> 가이드 한 명**을 뜻한다. 사용하는 계약과 데이터 경로는 가이드에 관계없이 같다. 그림 정본은
> `docs/캐릭터/정본_4K`이며 `tools/lib/마스코트자산.js`에서 경로를 관리한다(09-05 버전 갱신). 각 가이드의 말투는
> `docs/캐릭터/가이드_정본.md`.
> **기존 계약과 데이터 경로를 재사용해 새로 구현할 범위를 줄인다.** 08-14 코드에서 확인한 연결 위치는 아래 §1 표에 있다. §7은 당시 제안한 분할 순서다. 후속 구현은 현재 Talk의 `supabase/functions/companion/`·`docs/컴패니언_내부계약.md`와 해당 화면에서 확인한다.

## §1. 실측 — 이미 있어서 새로 안 짓는 것 (합류 지도)

| 필요한 것 | 이미 있는 실물 (SYNK-talk) | 합류 방식 |
|---|---|---|
| 발화 기록(기억층) | `intervention.delivered` 서버 사건 — `output_text`(AI가 실제로 한 말)·`cited_refs`·`model`·`prompt_ver`·`intervention_id`·`degraded`가 모두 계약에 있다 | **새 테이블 0.** 마스코트가 한 말을 이 사건의 행으로 남긴다. 학생별 최근 행을 조회해 같은 말을 반복하지 않는다 |
| 발화 표시 확인(관측) | `content.viewed` + `parent_event_id` — 계약 원문: 「`intervention.delivered` 의 추정을 **관측으로 확인하는 짝**」 | 말풍선이 실제로 열린 순간 앱이 보낸다. 네트워크 실패로 표시하지 못한 말을 전달 완료로 집계하지 않도록 기존 계약을 사용한다 |
| 답 저장(수집) | `preference.stated`(필수 3필드)·`source_kind`(explicit/teacher/observed/inferred)·앱의 유일한 쓰기 경로 `사건통로.js`→`events` Fn | 말할순간 §7-2의 기존 경로를 사용한다. 마스코트 층에 저장 코드를 추가하지 않는다(0줄) |
| 배달 구조 | `deliver`(전날 밤 pg_cron 배치)→큐→`tasks`(앱이 읽음)→빈 배열=정상 | 같은 구조로 마스코트 발화 배치를 만든다(§3). 큐·읽기·강등 방식을 재사용하되 별도 목적의 배치로 둔다 |
| 상태 계산 | `lib/학습자상태`(순수 함수·저장 안 함) — 「상태는 **개입을 낼 때 계산해 그 개입 사건에 스탬프**」(`estimator_version`·`evidence_refs` 기존 열) | S15(성향 타이밍)·S4(학생별 리듬)가 기존 경로 A를 사용한다. 마스코트가 이 lib를 처음 사용하는 기능이다 |
| 강사 기능 | `teach` Fn(역할 teacher·director) + `강사화면.js` | 강사판 A·C층에 필요한 큐 상태와 진행이 막힌 지점을 여기서 확인한다 |
| 두뇌 v0 | `상담AI.js`(Apps Script) — 지식→프롬프트 조립·모르면 인계·역번역 | **처리 구조를 재사용**하고 실제 실행 위치는 §4의 결정을 따른다 |

## §2. 발화 생성의 물리 — 「AI가 매번 새로」를 비용·지연 없이

모든 문장을 실시간으로 생성하면 표시 지연, 벤더 비용, 오프라인 처리 문제가 생긴다. 말풍선은 제때 떠야 하고, 비용은 확정된 캐싱·배치 방향 안에서 관리해야 한다. 호출할 수 없을 때는 오류 대신 조용히 있어야 한다. 따라서 **문장의 종류에 따라 생성 경로를 나눈다**:

| 통로 | 어떤 문장 | 물리 |
|---|---|---|
| **㉮ 로컬 정형** | 숫자·상태 문장 — T1·T2(3/5 진행)·T5·S1·S5·P5 등 최신 값이 필요한 문장 | 앱이 신호를 받아 즉시 조립한다. 여러 문장 상수와 최근 표시 기록으로 반복을 피한다. AI 왕복 0 |
| **㉯ 전야 굽기** | 관계·맥락 문장 — S4(어제 그 문장)·S17(말한 내용)·S20(힘든 날)·T3(주 마무리)·P3(첫 순간) 등 학생의 기록에 근거한 문장 | **전날 밤 배치**가 학생별 맥락으로 미리 생성 → `intervention.delivered` 행(payload에 후보 문장) → 앱이 아침에 큐로 받아 로컬 보관 → 조건에 맞는 순간 즉시 표시 + `content.viewed` → 사용하지 않은 문장은 그날 밤 삭제 |

- 사전 생성 배치는 과제 배달과 목적이 다르므로 `deliver`에 넣지 않는다. **같은 pg_cron 구조의 별도 배치**로 만든다. 벤더 호출은 이 배치 1회에 묶는다(cron 예산 안).
- **㉣ 구현**: 배치가 AI에 전달하는 맥락에는 이름·학생 코드가 없어야 한다(0). 프롬프트 조립부의 식별자 차단을 회귀 시험으로 확인한다. 이름은 앱이 표시할 때 넣는다(말할순간 공통 원칙 3).
- 사전 생성 실패나 첫날이라 문구가 없으면 **말하지 않는다**. `degraded=true` 강등 경로(deliver 선례)로 대신 출력하지 않는다(보조 원칙 ③: 마스코트의 실패 모드는 조용함).

## §3. 신호 지도 — 55줄의 트리거가 어디서 나나

| 원천 | 줄 | 물리 |
|---|---|---|
| **서버발**(배치·Fn이 이미 아는 것) | T1·T4·T8·T9·P2·P5·S4·S6·S19·S20·S21 | 전날 밤 배치가 신호를 계산해 문장을 생성한다(㉯). 앱은 적절한 순간에 표시한다 |
| **앱발**(그 순간 화면이 아는 것) | S1·S2(achieve)·S3·S5·T2·T5·T10·P행 열람류 | 로컬 트리거 → ㉮ 정형 문장 또는 사전 생성 문장 표시. 서버 왕복 0 |
| **문의**(실시간 대화) | B층 전체(T11~14·S10~12·P7~9) | 실시간 AI 왕복을 사용하는 유일한 경로. §4 두뇌 Fn에서 처리한다 |
| **수집 답** | S13·S22~25 답·T15 탭 | 기존 사건통로 → `events`(§5) |

읽기 요청만으로 사건을 만들지 않는다(tasks와 같은 방식). 실제 표시·열람 기록은 앱이 `content.viewed`로 따로 보낸다.

## §4. 두뇌 — 「하나」의 뜻과 물리 판정

**같은 지식과 성격의 정본을 사용하되 실행 프로세스까지 하나로 합치지는 않는다.** 지식(FAQ 정본+문서)과 성격(말투 규칙)의 원본을 한 곳에서 관리하면 어느 화면에서 만나도 같은 캐릭터로 답할 수 있다. 상담봇(Apps Script·Meta 웹훅)은 개통 작업 중이므로 **지금 옮기지 않는다**. 웹훅 주소를 바꾸면 Meta 심사에도 영향을 준다. 실행 환경의 통합 여부는 상담봇 개통·안정 뒤 별도로 결정한다.

앱의 B층(문의)을 실시간으로 처리할 **두뇌 Fn(가칭 `companion`)**을 새로 만든다:
- 입력: 역할·질문·현재 화면 이름(맥락). 역할은 토큰에서 읽으며 본문이 주장하는 역할은 신뢰하지 않는다(events와 같은 방식).
- 지식: **공개 범위 4개 항목(⏳유호)이 결정된 문서만 빌드에 포함한다**. `teach`의 `동봉.json`처럼 처리하며 실행 중에 repo를 읽지 않는다. FAQ 정본의 약속이 다른 문서보다 우선한다(말할순간 §7-2 지식 규칙).
- 답과 **출처 문서명을 함께 표시**하고 응답의 `cited_refs`를 채운다. 계약에서 RAG 도입 시점부터 채우기로 한 필드를 여기서 처음 사용한다.
- 모르면 지어내지 않고 담당자에게 인계한다(상담AI의 기존 처리 방식). 질문·답·출처·해결 여부를 기록해 문서에 빠진 내용을 찾는다(말할순간 §7-4). 이 Fn 자체의 감사 로그로 남긴다(teach의 감사 원장과 같은 방식).
- C0에 새 경로를 추가하는 작업이다. teach의 선례처럼 기존 경로를 확장하지 않고 별도 경로가 필요한 이유를 문서화한다. C0 계약 개정도 이 작업에서 담당한다.

## §5. 수집 합류의 물리

- **마스코트 값 상수는 한 곳에서 관리한다.** `stated_via`·`preference_dimension`은 허용 값 목록의 제약이 없는 자유 문자열이다(검증기 실측). 마스코트가 쓰는 값은 lib 상수 하나로 정의하고 화면·배치가 함께 사용한다. 계약 원문의 「같은 것이 열 가지 이름으로 쌓이면 축이 사라진다」를 막는 구현이다. 상수 외 문자열을 회귀 시험으로 검사한다.
- **S25(게임 재미)**: `preference.stated`(dimension=관심 계열 상수)·explicit을 사용한다. 기존 계약으로 처리하며 개정은 없다(0).
- **S24(이해됐어?)**: **c12에서 별도 항목을 신설한다**. `correction.responded`의 `learner_response`(채택/무시/수정)는 행동을 기록하는 필드이므로 자기보고 이해도를 넣으면 의미가 달라진다. 계약의 `stated_option` 신설 때처럼 다른 의미에는 별도 이름을 쓴다. c12는 마스코트 관련 변경만 담는다(c11의 라디오 단독 개정과 같은 방식). 후보 이름은 계약 작업에서 정하며, 이 문서에서는 이해도 자기보고와 `moment_id`(§6) 두 항목의 신설을 예정한다.
- **T15(강사 확인)**: 관찰 태그 연결(설계 확정·`teach` observe 경로 미구현)과 **함께 구현한다**. 강사 관찰의 입력 경로를 따로 만들지 않는다. source_kind=teacher.

## §6. 「어느 줄의 발화인가」 — 세기 오염을 막는 한 칸

S3의 『왔구나!』 같은 일상 인사도 `intervention.delivered`에 기록되므로, 이를 모두 학습 개입으로 집계하면 결과가 부정확해진다. 사건 이름은 유지하고 c12 payload에 **`moment_id`를 추가**한다. 값은 말할순간 표의 행 번호(T3·S4·P2)이며 집계할 때 이 필드로 구분한다. `submissions`에서 제출 외 행을 `event_type`으로 구분하는 기존 방식과 같다. **행별 표시 상한(주 1회 등)과 표에 없는 발화의 차단도 이 값으로 검사한다.** 표에 없는 moment_id는 검증기가 거절한다.

## §7. 착수 순서 — 무엇부터 (각 단계가 홀로 완결)

아래는 2026-08-14의 역할별 구현 제안이다. 당시 미구현·대기 표기를 현재 상태로 쓰지 않고, 이미 있는 기능과 최신 계약을 확인해 이어간다.

| 단계 | 내용 | 왜 먼저 | 선행 조각 |
|---|---|---|---|
| **1. 강사판** | 강사 화면 마스코트(㉮ 정형 T1~T5·T10) + 두뇌 Fn v0(B층 Q&A·동봉 지식·cited_refs·누락 지식 로그) | teach 큐에 필요한 신호가 이미 있다. 사용자 1~2명으로 말투·분량을 확인할 수 있다. 학생 0명이라 학생판에는 실제 사용 자료가 없다 | 강사 지식의 공개 범위·출처는 현행 컴패니언 내부 계약과 매니페스트에서 확인 |
| **2. 학생판** | ㉯ 전날 밤 사전 생성 배치 + c12(moment_id·이해도) + 수집 연결(S13·S22~25) + 관찰 태그 연결(T15) | 부트캠프의 실제 학생 사용으로 적절한 표시 빈도를 확인한다(말할순간 §5 「눈금은 실측으로」) | 1단계의 두뇌 Fn·c12 계약 작업 |
| **3. 학부모판** | 학부모 인증·화면 + 출결 신호 + P층 | 선행 작업이 가장 많다. 인증은 L0 §4를 확장하는 수준이다 | 학부모 계정·권한은 L0 계약, 출결 입력은 현행 출석 설계·코드에서 확인 |
| 상시 | 홈페이지·메신저의 프로필과 표정 컷은 코드 작업과 별도로 각 작업에서 병행한다 | | |

학부모 인증·출결의 미확정 정책을 이 문서에서 대신 결정하지 않는다. 현재 계약에서 실제로 남은 선택을 확인하며, 옛 대기 표만 보고 이미 확정된 내용을 다시 묻지 않는다.

## §8. 반박 1패스 기록 (수리 반영분)

1. `intervention` 사건의 의미가 넓어진다는 지적 → §6에서 사건 이름을 유지하고 moment_id로 구분하도록 반영했다.
2. 사전 생성하면 실시간 숫자가 오래된 값이 된다는 지적 → §2에서 숫자·상태는 ㉮ 로컬로, 관계·맥락은 ㉯ 사전 생성으로 분리했다. 문장을 AI가 만든다는 원칙은 유지하며 생성 시점을 앞당긴다. 맥락 문장의 최신성도 확인한다.
3. 학생 0명인데 학생판부터 만드는 순서에 대한 지적 → §7에서 기존 신호와 실제 사용자가 있는 강사판부터 구현하도록 반영했다.
4. 남은 결정: c12 이해도 항목 이름(계약 작업), 두뇌 Fn의 C0 등록 형식(구현 시 teach의 선례 참고), 학부모 ⓐⓑ(⏳유호).
