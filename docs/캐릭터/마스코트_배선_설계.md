# 마스코트 동반자층 — 배선 설계 v1

> **v1 초안 · 2026-08-14.** 행동 정본(말할순간 v1.0 · 53+2줄 유호 전건 ○)을 물리로 옮기는 설계다.
>
> 🔴 **2026-09-05 — 가이드가 셋이다**(몽글 · 까몽 · 마린). 이 배선 표의 「마스코트」는 **학생이 고른
> 가이드 하나**를 뜻하고, 합류 자리(계약·통로)는 가이드와 무관하게 같다. 그림 정본 =
> `docs/캐릭터/정본_4K`(주인 = `tools/lib/마스코트자산.js` · 09-05 판올림). 말투가 갈리는 규격은
> `docs/캐릭터/가이드_정본.md`.
> 설계의 지붕: **새로 짓는 것을 최소로 — 이미 있는 계약·통로에 «합류»한다.** 실측(08-14)으로 확인한 합류 자리가 아래 §1 표다. 코드는 이 문서 확정 뒤 §7 순서로 시작한다.

## §1. 실측 — 이미 있어서 새로 안 짓는 것 (합류 지도)

| 필요한 것 | 이미 있는 실물 (SYNK-talk) | 합류 방식 |
|---|---|---|
| 발화의 기록(기억층) | `intervention.delivered` 서버 사건 — `output_text`(AI가 실제로 한 말)·`cited_refs`·`model`·`prompt_ver`·`intervention_id`·`degraded` 전부 계약에 실재 | **새 테이블 0.** 마스코트가 한 말 = 이 사건의 행. 「최근에 한 말 다시 안 하기」 = 그 학생의 최근 행 조회 |
| 발화가 닿았나(관측) | `content.viewed` + `parent_event_id` — 계약 원문: 「`intervention.delivered` 의 추정을 **관측으로 확인하는 짝**」 | 말풍선이 실제로 열린 순간 앱이 보낸다 — 네트워크 실패가 「전달 완료」로 학습되는 것을 막는 자리까지 계약이 미리 팠다 |
| 답의 저장(수집) | `preference.stated`(필수 3필드)·`source_kind`(explicit/teacher/observed/inferred)·앱의 유일한 쓰기 통로 `사건통로.js`→`events` Fn | 말할순간 §7-2 그대로 — 마스코트 층은 저장 코드 0줄 |
| 배달의 패턴 | `deliver`(전날 밤 pg_cron 배치)→큐→`tasks`(앱이 읽음)→빈 배열=정상 | 같은 패턴으로 마스코트 발화 배치를 짓는다(§3) — 큐·읽기·강등의 형태를 베끼고 목적만 다르다 |
| 상태 계산 | `lib/학습자상태`(순수 함수·저장 안 함) — 「상태는 **개입을 낼 때 계산해 그 개입 사건에 스탬프**」(`estimator_version`·`evidence_refs` 기존 열) | S15(성향 타이밍)·S4(그 아이 리듬)가 이 경로 A를 그대로 쓴다 — 마스코트가 이 lib 의 **첫 소비자** |
| 강사 문 | `teach` Fn(역할 teacher·director) + `강사화면.js` | 강사판 A·C층의 신호(큐 상태·막힘)가 전부 여기 이미 있다 |
| 두뇌 v0 | `상담AI.js`(Apps Script) — 지식→프롬프트 조립·모르면 인계·역번역 회로 | **회로 설계를 승계**하고 물리는 §4 판정을 따른다 |

## §2. 발화 생성의 물리 — 「AI가 매번 새로」를 비용·지연 없이

실시간 생성은 셋 다 어긋난다: 지연(말풍선이 늦으면 죽은 캐릭터다) · 비용(벤더 과금 — 캐싱+배치 확정 방향) · 오프라인(못 부르면 침묵이어야 하는데 오류가 된다). 그래서 **문장의 성질로 두 통로를 가른다**:

| 통로 | 어떤 문장 | 물리 |
|---|---|---|
| **㉮ 로컬 정형** | 숫자·상태 문장 — T1·T2(3/5 진행)·T5·S1·S5·P5 류. 낡으면 안 되는 실시간 값 | 앱이 신호를 보고 그 자리에서 조립(변형 몇 벌 상수 + 기억 회전으로 반복 회피). AI 왕복 0 |
| **㉯ 전야 굽기** | 관계·맥락 문장 — S4(어제 그 문장)·S17(말한 내용)·S20(힘든 날)·T3(주 마무리)·P3(첫 순간) 류. 그 학생의 궤적에서 나오는 말 | **전날 밤 배치**가 학생별 맥락으로 미리 생성 → `intervention.delivered` 행(payload에 후보 문장) → 앱이 아침에 큐로 받아 로컬 보관 → 순간이 오면 즉시 표시 + `content.viewed` → 안 온 순간의 문장은 그날 밤 소멸 |

- 굽기 배치는 `deliver` 안에 끼우지 않는다(과제 배달과 뜻이 섞인다) — **같은 pg_cron 패턴의 별도 배치**로 세운다. 벤더 호출은 이 배치 1회에 묶인다(cron 예산 안).
- **㉣ 물리**: 배치가 AI에 주는 맥락에 이름·학생 코드 0 — 프롬프트 조립부에 식별자 차단을 회귀로 박고, 이름은 앱이 표시 시점에 끼운다(말할순간 공통 원칙 3의 기계 자리).
- 문구가 없으면(굽기 실패·첫날) 그 줄은 **침묵**이다 — `degraded=true` 강등 경로(deliver 선례)가 아니라 발화 자체를 안 한다(보조 원칙 ③: 마스코트의 실패 모드는 조용함).

## §3. 신호 지도 — 55줄의 트리거가 어디서 나나

| 원천 | 줄 | 물리 |
|---|---|---|
| **서버발**(배치·Fn이 이미 아는 것) | T1·T4·T8·T9·P2·P5·S4·S6·S19·S20·S21 | 전야 배치가 신호를 계산해 굽는다(㉯) — 앱은 받은 것을 순간에 맞춰 표시만 |
| **앱발**(그 순간 화면이 아는 것) | S1·S2(achieve)·S3·S5·T2·T5·T10·P행 열람류 | 로컬 트리거 → ㉮ 정형 or 구운 문장 소비. 서버 왕복 0 |
| **문의**(실시간 대화) | B층 전체(T11~14·S10~12·P7~9) | 유일한 실시간 AI 왕복 — §4 두뇌 Fn |
| **수집 답** | S13·S22~25 답·T15 탭 | 기존 사건통로 → `events`(§5) |

읽기는 사건을 만들지 않는다(tasks 선례) — 표시·열람의 기록은 앱이 `content.viewed` 로 따로 보낸다.

## §4. 두뇌 — 「하나」의 뜻과 물리 판정

**판정: 두뇌 하나 = 프로세스 하나가 아니라 «정본 하나»다.** 지식(FAQ 정본+문서)·성격(말투 규칙)의 정본이 한 곳이면 어느 창구에서 만나도 같은 존재다. 상담봇(Apps Script·Meta 웹훅)은 개통 트랙이 살아 있으므로 **지금 옮기지 않는다** — 웹훅 주소를 흔들면 Meta 심사 트랙이 같이 흔들린다. 물리 통합은 상담봇 개통·안정 뒤 별도 판정.

새로 서는 것 = **두뇌 Fn(가칭 `companion`)** — 앱 쪽 B층(문의)의 실시간 자리:
- 입력 = 역할(토큰에서 — 본문의 역할 주장은 안 믿는다, events 선례)·질문·현재 화면 이름(맥락).
- 지식 = **경계선 4칸(⏳유호)을 통과한 문서만 빌드 시 동봉**(teach 의 `동봉.json` 선례 — 실시간으로 repo 를 읽는 길은 없고, 동봉이 이 저장소의 정석이다). FAQ 정본 = 약속 층이 문서보다 우선(말할순간 §7-2 지식 규칙 그대로).
- 답 + **출처 문서명 병기** → 응답의 `cited_refs` 를 실제로 채운다 — 계약이 「자리만 내고 채우기는 RAG 도입일부터」라 적어 둔 그 자리의 **첫 실물**이다.
- 모르면 지어내지 않고 인계(상담AI 회로 승계) + 질문·답·출처·해결여부 로그 = 문서 빈칸 발견기(말할순간 §7-4). 로그의 자리 = 이 Fn 이 자기 감사로 남긴다(teach 의 감사 원장 선례).
- ⚠ C0 에 새 문을 내는 일이다 — teach 가 「왜 기존 문을 안 넓히고 새 문인가」를 문서화한 선례를 따르고, C0 계약 개정은 이 트랙이 진다.

## §5. 수집 합류의 물리

- **마스코트 값 상수 한 곳**: `stated_via`·`preference_dimension` 은 값목록 제약이 없는 자유 문자열이라(검증기 실측), 마스코트가 쓰는 값을 lib 상수 하나에 박고 화면·배치가 그것만 쓴다 — 「같은 것이 열 가지 이름으로 쌓이면 축이 사라진다」(계약 원문)의 기계 자리. 회귀가 상수 밖 문자열을 잡는다.
- **S25(게임 재미)**: `preference.stated`(dimension=관심 계열 상수) · explicit — 계약 그대로, 개정 0.
- **S24(이해됐어?)**: **c12 신설이 정공** — `correction.responded` 의 `learner_response`(채택/무시/수정)는 «행동» 축이라 자기보고 «이해도»를 태우면 뜻 넓히기다(계약의 `stated_option` 신설 판정과 같은 축 — 뜻이 다르면 이름을 가른다). c12 는 마스코트 조각만 싣는다(성격 다른 개정을 한 판에 안 묶는다 — c11 라디오 단독 선례). 후보 이름은 계약 트랙에서 정하되 이 문서는 「이해 자기보고 축 신설 + `moment_id`(§6)」 두 조각을 예고한다.
- **T15(강사 확인)**: 관찰 태그 배선(설계 확정·`teach` observe 경로 미구현)과 **한 벌로** 짓는다 — 따로 지으면 강사 관찰이 두 문으로 갈라진다. source_kind=teacher.

## §6. 「어느 줄의 발화인가」 — 세기 오염을 막는 한 칸

반박 패스가 잡은 공격: *「S3 『왔구나!』 같은 사교 발화가 `intervention.delivered` 에 실리면, 이 사건을 「학습 개입」으로 세는 미래 집계가 오염된다.»* — 유효하다. 처방은 사건 이름을 가르는 것(뜻 넓히기)이 아니라 **행 안의 한 칸**이다: c12 에 `moment_id`(말할순간 표의 줄 번호 — T3·S4·P2)를 payload 로 신설한다. 집계는 이 칸으로 거른다 — `submissions` 에 제출 아닌 행이 살고 `event_type` 으로 거르는 기존 판정과 같은 형태다. 덤: **줄별 상한(주 1회 등)의 기계 강제와 「말할 순간 표 밖 발화 금지」 회귀가 전부 이 칸 하나로 선다** — moment_id 가 표에 없는 값이면 검증기가 거절한다.

## §7. 착수 순서 — 무엇부터 (각 단계가 홀로 완결)

| 단계 | 내용 | 왜 먼저 | 선행 조각 |
|---|---|---|---|
| **1. 강사판** | 강사 화면에 마스코트(㉮ 정형 T1~T5·T10) + 두뇌 Fn v0(B층 Q&A·동봉 지식·cited_refs·빈칸 로그) | 신호가 전부 실재(teach 큐) · 사용자 1~2명 실측 가능 · 학생 0명이라 학생판은 재료가 없다 · 말투·분량의 실측장 | **경계선 4칸(⏳유호 — 유일한 차단자)** |
| **2. 학생판** | ㉯ 전야 굽기 배치 + c12(moment_id·이해 축) + 수집 합류(S13·S22~25) + 관찰태그 한 벌(T15) | 부트캠프(실학생)에서 빈도 눈금을 잰다 — 말할순간 §5 「눈금은 실측으로」 | 1단계의 두뇌 Fn·c12 계약 트랙 |
| **3. 학부모판** | 학부모 인증·화면 + 출결 신호 + P층 | 선행 조각이 가장 많다 — 인증은 L0 §4 확장급 | ⓐ학부모 계정 정책(⏳유호 — 학생 계정과 묶나 별도나) ⓑ출결 입력 방식(⏳유호 — 강사 체크·데스크·기기 중) |
| 상시 | 홈페이지·메신저 형상화(프로필+표정 컷)는 코드 무관 — 각 트랙에서 병행 | | |

**절단 명시**: 학부모 인증 설계와 출결 운영 방식은 이 문서가 정하지 않는다 — 각각 L0 확장·운영 설계의 몫이고, 위 ⓐⓑ 답이 오기 전에는 3단계가 안 선다(1·2단계는 그와 무관하게 완결).

## §8. 반박 1패스 기록 (수리 반영분)

1. **「intervention 뜻 넓히기」 공격** → §6 moment_id 로 처방(사건 이름은 안 넓히고 거르는 칸을 신설).
2. **「사전 굽기면 실시간 숫자가 낡는다」 공격** → §2 두 통로 분리로 처방(숫자·상태는 ㉮ 로컬, 관계·맥락만 ㉯ 굽기) — 「뭐라고=AI」 원칙을 「AI가 **미리**」로 정밀화한 것이지 후퇴가 아니다(신선함은 맥락 문장이 진다).
3. **「학생 0명인데 학생판부터?」 공격** → §7 순서로 처방(강사 먼저 — 신호 실재·실측 가능).
4. 미해소로 남긴 것: c12 의 이해 축 이름(계약 트랙 몫) · 두뇌 Fn 의 C0 등재 형식(구현 시 teach 선례로) · 학부모 ⓐⓑ(⏳유호).
