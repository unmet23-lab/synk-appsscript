## 1. 남은 일 — 결 수리분 재굽기 (⏳ 유호 시점 판단 대기)

`직물결` 무동작 수리(커밋 `f5918797`)가 **`직물결`을 쓰는 16곳 전부**에 닿는다.
지금 무엇이든 새로 구우면 **옆에 선 옛 판과 재질 규격이 갈린다** — 그래서 부분 굽기는 피한다.

실측한 변화폭 (1/255 초과 픽셀 비율):

| 대상 | 평균차 | 바뀌는 픽셀 |
|---|---|---|
| 다린천판 | 3.43/255 | 37.1% |
| 패턴지판 | 1.67/255 | 36.9% |
| 오브 Coral | 2.47/255 | 40.6% |

### 굽는 법 (범위를 유호님이 정하면 그대로 실행)

```bash
node tools/요소전량굽기.js --다시          # 요소 26종 · 약 2~3시간
node tools/오브굽기.js                      # 오브 26색 · 약 1시간 40분
node tools/오브시안.js                      # 시안 재생성(오브를 다시 구웠으면 필수)
```

- 전량(52장) = 약 4~5시간. **규격이 한 번에 맞는다** — 권장.
- 요소만(26장) = 약 2~3시간. 오브 받침만 결 없는 채로 남는다.
- 판 3종만 = 약 15분. 나머지 13곳이 불일치로 남는다.

⚠ 굽는 동안 다른 세션이 같은 GPU를 쓰면 둘 다 느려진다. 그리고 **굽기가 «정지»할 수 있다** —
털실진행바 1회차가 2시간 멈췄다(CPU 시간이 322초에서 한 시간 넘게 1초도 안 늘고 워킹셋 0MB).
끊고 재시도하니 58초에 성공했다. 오래 걸리면 «CPU 시간이 느는가»로 살아있는지 판정하고,
멈췄으면 그 프로세스만 끊는다. `요소전량굽기.js` 는 실패를 기록하고 다음으로 넘어가며,
이어굽기는 «파일이 있나»가 아니라 **«그 너비인가»**로 가르므로 그냥 다시 부르면 남은 것부터 잇는다.

## 3. 끝난 것 ② — 구도 잘림 수리 7종 (커밋 `02bff815`)

해상도가 오르자 가려져 있던 구도 결함이 드러났다. 전수 측정(가장자리 2px 띠에 내용이 닿는가)에서
무대 22종 중 10종이 잘려 있었다.

🔑 원인이 「카메라가 가깝다」가 아니었다 — **«중심»이 문제였다.**
아이콘을 1.5배 물렸더니 내용이 58×74% 인데 여백이 2.3% 였다(크기 탓이면 13% 가 남았어야 한다).
그래서 손을 둘로 나눴다 — **중심 보정 + 거리**.

값은 눈이 아니라 계산이다(명품 렌더 4계 ④): 저해상도 탐침(480px·16샘플)의 내용 bbox 를
화각(85mm·센서36 → 보이는 폭 `0.42326·d`)으로 월드 좌표에 되돌려 «중심 밀림»과 «채운 비율»을
얻고, 목표 84% 에 맞는 거리를 역산했다.

| 형태 | 중심 밀림 | 거리 | 진단 |
|---|---|---|---|
| 아이콘 | 위로 0.50 | 1.32배 | 중심이 주범 — 겹친 두 스쿼클이 둘 다 잘려 구도가 안 읽혔다 |
| 매듭 | 아래로 0.28 | 1.36배 | 중심 + 크기 — 로제트 아래 꼬리가 잘렸다 |
| 블랭킷 | 0 | 1.21배 | 순수 크기 — 털이 네 변을 넘어 «질감 접사»로 읽혔다 |
| 단추토글 | 0 | 1.42배 | 순수 크기 — 두 단추가 좌우로 잘려 나갔다 |
| 판 3종 | 오른쪽 0.44 | 1.49배 | 판 뒤 코랄 구슬이 오른쪽에서 잘렸다 |

⚠ 판 3종(패턴지·다린천·유리)은 **«대조 세트»라 카메라가 같아야 한다** — 한 판만 옮기면 그 비교가
무효가 된다. 셋에 같은 값을 주고 그 까닭을 코드에 못박았다.

검증: 잘림 0 · 여백 사방 7.4~8.1% · 폭·높이 중 큰 쪽이 84.0~84.7%.

**안 고친 것** — 스티치·털실진행바·페이지점(좌우 잘림 3종)은 «띠가 화면을 가로지르는» 것이
그 물건의 문법이다(자수 시안 띠 · 진행 바 · 점 열). 사고가 아니라 의도로 보고 둔다.

새 인자 `카메라배=` — 광축을 따라 뒤로 달리한다(구도 실측용 · 기본 1).
🔑 Y 만 늘리면 안 된다: 피치가 90°가 아닌 형태(아이콘 86°)에서 중심이 위로 밀린다.
조명은 월드 좌표라 카메라를 물려도 안 따라온다 — 구도«만» 바뀐다.

## 4. 끝난 것 ③(도구만) — 「직물결」 무동작 수리 (커밋 `f5918797`)

「다린천판만 재질이 안 보인다」로 시작했는데 **모든 매끈한 천 표면**의 문제였다.

두 번 헛짚었다 — 그 과정이 다음 사람의 시간을 아낀다:
1. 세기 8배(0.045→0.36) → 판 안 평균차 **0.045/255**. 안 먹는다.
2. 규모 25배(200→8) → 평균차 **0.0145/255**. 이것도 안 먹는다.
3. 셰이더 그래프를 블렌더에 직접 물었다 → **`Bump Distance = 0.001`**.

Bump 의 실효 왜곡 = **Strength × Distance × 기울기**인데 `직물결` 은 Distance 를 한 번도 설정하지
않아 블렌더 기본 0.001 이 곱해지고 있었다. 「민무늬는 도자기로 읽힌다(시안2027 실측)」며 만든
결이 **16곳 전부에서 한 번도 안 나오고 있었다.**

눈금 (다린천판 실측 · 상대 대비 = 국소 고주파 ÷ 평균 밝기 · 눈 문턱 ≈ 1%):

| Distance | 상대 대비 | 눈으로 |
|---|---|---|
| 0.001(옛) | 0.18% | 아무것도 안 보임 |
| 0.006 | 1.18% | 아직 종이 |
| **0.02** | **2.80%** | **눌린 부직포 — 채택** |
| 0.06 | 4.22% | 스터코(외벽 미장) — 기각 |

⇒ Strength 는 1.0 으로 열고 호출자 눈금 「세기」를 실제 깊이로 옮긴다(`결깊이배 = 0.44`).
16곳이 각자 적어둔 상대적 의도(종이 0.03 < 천 0.045 < 배경 0.085)가 그대로 살아난다.

**교훈 — 「값을 바꿨는데 안 변한다」면 그 손잡이가 배선됐는지부터 묻는다.**
같은 계열의 사고가 이번 세션에만 둘이었다: 디노이즈 가이드(기본값을 기본값으로 덮는 no-op ·
`오브굽기.js` 머리말)와 이 건. 둘 다 «렌더를 실제로 대조»해서만 잡혔다.

드러내는 각도·구도**의 문제라, 오브가 여섯 번 조율해 명품판을 세운 것과 같은 종류의 일이다.

## 6. 이 폴더의 규율

- 굽기 인자의 주인은 `tools/요소전량굽기.js` 하나다. 손으로 blender 를 부르지 않는다
  (그래서 해상도가 1152×24 + 900×1 로 갈려 있었다).

  하나로 묶어야 전후 대조가 정직해진다.
- 오브는 여기서 굽지 않는다. 정본은 `docs/캐릭터/오브공방_0821/`(26색·1800px)다.
