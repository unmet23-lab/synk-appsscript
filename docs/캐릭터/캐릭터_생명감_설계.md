# 캐릭터 생명감 설계 — 살아있는 반응과 기억

> 현행 v1.5 · 2026-09-13. 표정·몸짓·혼잣말의 기준이다. 장소와 기능은 [살아있는 자리](../살아있는자리_설계_v1.md), 성격·말투는 [가이드 정본](가이드_정본.md), 자산 경로와 어휘는 [마스코트 자산 코드](../../tools/lib/마스코트자산.js)가 맡는다. 모델·제작 도구·과거 심문 절차를 이 문서에서 고정하지 않는다.

## 0. 살아있는 반응

학생이 한 일에 제때 반응하고, 가끔 스스로 움직이며, 확인된 기억으로 그 학생을 챙긴다. 기본은 따뜻한 친구 같은 표정·몸짓이고 필요한 때 말을 건넨다. 장식의 양보다 실제 사건과 반응의 관계를 본다.

움직임 지원 매체의 Loom 결과물에는 [정원의 표현 기준](../Loom_실시간장면_표현기준.md)을 기본 적용한다. 정원의 국소 깜빡임·바람 사건·천과 스티치 말풍선은 현재 재사용 실물이다. 09-13 인사·바람에 맞춘 표정 상호작용은 다음 검토 사항이며 이 문서 정리로 새 표정이 구현된 것은 아니다.

## 1. 반응 원칙

1. **기본 반응과 대화를 나눈다.** 일상 반응은 표정·몸짓·빛과 가끔의 혼잣말로 전한다. 마스코트를 누르면 별도 안내 책·챗봇 층을 열 수 있다. ‘캐릭터는 대화하지 않는다’는 옛 포괄 금지는 사용하지 않는다.
2. **응원하되 평가하거나 재촉하지 않는다.** 자기 감정·동행·장난·확인된 기억은 전할 수 있다. 오류·미제출·결석 때문에 시무룩해지거나 죄책감을 주지 않는다. 성장·이해 표현은 [철학 적용 기준](../철학_적용기준.md)의 범위를 따른다.
3. **사용 중인 일을 방해하지 않는다.** 녹음 중에는 모션·표정 연출·혼잣말·소리를 멈춘다. 움직임 줄이기에서는 모션을 줄이되 정적 표정·글·기억과 기능을 유지한다. 고빈도 타이핑·스크롤마다 반응을 반복하지 않는다.
4. **사건 반응은 쉬는 상태로 돌아온다.** 인사·놀람·응원은 잠깐 나타났다가 돌아오고, 시간대·캐릭터 성격에 맞는 지속 상태는 별도로 둔다. 까몽의 낮·밤 습성과 마린의 렌즈 구조는 가이드 정본을 따른다.

## 1-a. 표정 전환의 재질 고정

**표정이 바뀌어도 같은 몸의 털은 그대로다**(유호님 확정 2026-09-09). 까몽·몽글·마린 모두, 의상 유무와 앱·라디오·영상 등 사용처에 관계없이 적용한다. 새 제작뿐 아니라 기존 표정 세트를 수정할 때도 같은 기준을 따른다.

- **공통 바탕 하나:** 같은 각도·자세에서 표정만 바꾸는 세트는 공통 털 바탕과 동일한 몸·의상·조명·크기·좌표·전체 알파(투명도)를 공유한다. 눈 뒤 바탕을 수리해야 한다면 한 번 만든 공통 바탕을 기본 표정까지 함께 쓰고, 승인 원본과 달라진 범위를 기록한다. 표정마다 얼굴·털·몸을 다시 생성하지 않는다.
- **기존 눈 구조만 국소 변화:** 캐릭터 정본에 실제로 있는 눈·눈꺼풀·렌즈 등의 변화만 좁은 윤곽 안에서 허용한다. 마린의 렌즈를 없는 눈꺼풀처럼 감기게 하거나, 기본에 없는 입·코를 새로 붙이지 않는다. **표정별 얼굴의 넓은 사각 영역을 복사해 미간·볼·이마 털까지 바꾸는 합성은 금지**한다.
- **변화 허용 영역을 먼저 좁힌다:** 실제 눈·눈꺼풀·렌즈 윤곽에 맞춘 마스크(바꿀 픽셀 영역)를 남긴다. 무손실 합성본과 실제 사용 크기의 무손실 검수본에서 그 밖 RGBA(색·투명도) 차이가 0인지 전 표정을 대조하고, 전체 알파도 동일한지 확인한다. 크기 변환 필터가 영향을 주는 최소 경계는 명시하되, 털 불일치를 통과시키려고 얼굴 전체로 검사 영역을 넓히지 않는다.
- **외곽 합성도 공통 처리:** 털 테두리의 배경색 잔여나 투명 경계 보정은 모든 표정에 동일한 고정 처리로 적용한다. 전환 결함을 전체 흐림(블러)·반투명화로 숨겨 털의 질감을 잃게 하지 않는다.
- **정지 컷과 반복 재생을 함께 본다:** 최종 사용본을 실제 사용 크기·배경에서 표정 전환 루프로 확인한다. 털결·얼굴 윤곽·의상·위치가 뛰거나 눈 잔상이 남지 않는지 보고, 손실 압축·방송에서의 결과도 무손실 픽셀 검사와 구분한다. 수치 통과만으로 자연스러움을 합격시키지 않는다.
- **몸짓은 별개다:** 고개 각도 변경·몸 기울임·호흡 등 의도한 움직임 자체를 금지하는 규칙은 아니다. 그 연출과 «표정만 교체»하는 자산을 구분해 검수하며, 표정 교체 때문에 털이 갈리는 현상을 몸짓으로 설명하지 않는다.

현재 확인된 수정 실물은 [까몽 / 여름 델 + 전설의 팻말 / 8표정](../_ops/의상라디오검수_20260909/털일관성/수정보고.md)이다. 다른 128차림과 몽글·마린의 기존 세트까지 수정·검수 완료한 것으로 확대하지 않는다. 이후 작업은 이 공통 기준을 적용하고 실제 확인한 캐릭터·차림·표정·사용처를 남긴다.

## 2. 반응 지도 — 사건과 표현

표정 어휘와 실제 사용할 컷은 디자인 토큰·마스코트 자산 코드에서 읽는다. 아래는 사건별 기본 연출이며 컷 수·퇴역 경로·옛 구현 줄 수를 복제하지 않는다. 새 표정·몸짓은 현재 목적과 승인 자산에 맞게 발전시킬 수 있다.

| 사건 | 기본 반응 | 말·조건 |
|---|---|---|
| 앱 켬·재회 | 반가운 표정, 작은 다가옴 | 확인된 기억이나 「오늘도 만났네!」 |
| 제출 수신 완료 | 기쁨·작은 축하 | 「보냈다!」 — 서버 수신이 확정된 뒤 |
| 다시 말하기 | 응원·앞으로 기울임 | 「다시! 같이!」 |
| 답장 열람·오류 남음 | 기쁨 또는 함께 들여다보는 집중 | 부정 평가·기죽이는 반응 없음 |
| 캐릭터 탭 | 놀람 뒤 기쁨·윙크 등 | 해당 캐릭터의 실제 표정 어휘 사용 |
| 한동안 입력 없음 | 가끔 두리번·작은 기울임·휴식 | 「음음~」 등 드문 자발 반응 |
| 녹음 | 정지 | 녹음 중 표시·소리 경계와 동기화 |
| 생애 첫 순간·진화·시즌 완주 | 별눈 등 특별 반응 | §2-1의 표시 조건을 충족할 때 |

### 2-1. 특별한 순간의 별눈

별눈은 현재 진화·생애 첫 제출/녹음/무오류·시즌 완주에 쓰는 특별 반응이다. 일상 기쁨은 눈웃음으로 표현한다. 별눈의 절제를 다른 표정 신규 추가 금지로 확대하지 않는다.

- 생애·시즌 첫 발생은 서버 사건으로 판별하고, 하루 표시 상한은 현재 1회다. 정확한 사건 목록과 상한은 실제 구현의 한 원천에서 관리한다.
- 녹음 중 발생한 축하는 다음 표시 기회로 넘긴다. 보이지 않은 축하를 표시 완료로 소비하지 않는다.
- 실제 표시 뒤 기본 표정으로 돌아온다. 지속 시간·몸짓 크기는 사용 크기와 재생으로 정하며 삭제된 v5 시연의 재등장이나 특정 실측 날짜를 기다리지 않는다.

## 3. 혼잣말과 기억

초급 한국어로 짧고 읽기 쉽게 말한다. 사건마다 되풀이하지 않으며 자발 혼잣말은 드물게 둔다. 평가어·등수·다른 학생과의 비교·재촉을 쓰지 않는다. 성장·이해를 점수나 숫자로 말하지 않는 기준과 시험 점수·가격 같은 사실 안내를 구분한다. 몽골어 문안은 실제 검수된 문안을 쓴다.

자기 감정·응원·동행·장난 외에 확인된 어제의 제출·편지 도착 등도 말할 수 있다. 사실 슬롯은 출처와 발동 조건이 있어야 하고, 오래된 재료에서 ‘어제·오늘·다음 주’를 지어내지 않는다. 확인되지 않은 성향은 사실처럼 단정하지 않는다. 학생을 향한 말의 비율 등 현재 상세 규격은 [철학 적용 기준](../철학_적용기준.md)과 `tools/혼잣말검사.js`를 읽는다.

## 4. 현재 보호 경계

- 표정만 바꿀 때 몸·털·의상·알파가 바뀌지 않도록 §1-a를 지킨다.
- 기록된 성장·관계의 누적을 결석·실패·시즌 변경 때문에 깎거나 초기화하지 않는다.
- 학생 식별정보·확인되지 않은 사정을 말풍선이나 외부 처리 입력에 노출하지 않는다.
- 혼잣말을 화면 밖 푸시 알림이나 녹음 중 음성으로 자동 확대하지 않는다. 소리는 사용처의 오디오 계약과 현재 승인 자산을 따른다.

## 5. 앱 구현 지도

형제 저장소 SYNK-talk의 `lib/마스코트생명.js`는 반응·재회·거리를, `src/마스코트.js`와 `src/마스코트몸.js`는 표시·몸짓을 맡는다. 자산 변환은 해당 저장소 `tools/마스코트변환.py`, 그림 원본 선택은 이 저장소 마스코트 자산 코드에서 시작한다. 현재 구현을 직접 확인하며 옛 ‘코드 0’이나 줄 수를 현황으로 읽지 않는다.

- 표정·몸짓 표시 계산은 로컬에서 즉시 한다. 생애 첫 순간·시즌 완주·제출 완료 같은 사실은 서버 사건을 사용한다.
- 혼잣말·재료 봉투가 실제 보였다는 관측은 기존 사건 통로의 `intervention.delivered`·`moment_id` 계약을 따른다. 반응 애니메이션 이력을 저장하지 않는 선택과 대사 노출 계약을 혼동하지 않는다.
- 녹음 시작·끝은 소리와 같은 경계를 사용한다. 말하기 화면의 상주 제한은 녹음 전 한시적인 과제 연기까지 금지하는 규칙이 아니다.
- 꼬리 종류·진화 단계처럼 소비할 재료가 필요한 반응은 생산자와 표시 위치를 함께 연결한다. 임의의 빈 필드를 먼저 추가하거나 과거 미구현 표로 기능 부재를 단정하지 않는다.

## 6. 확인

새 자산·연출에서 기본→사건→복귀, 실제 배경과 크기, 녹음·움직임 줄이기·오프라인·재회 경계를 확인한다. 표정 픽셀 검사는 §1-a, 제품 데이터 검사는 해당 계약과 관련 시험을 쓴다. 이미 통과한 판을 같은 근거로 반복 심문하거나 새 판정 대기를 자동 생성하지 않는다. 로컬 화면·앱 배포·실기기·학생 경험은 각각 확인한 범위로 보고한다.

## 7. 성장 뒤에도 살아있는 친구

세 축의 사실 누적과 유한한 몸 그림 단계를 구분한다. 현재 설계는 크기·맑기·빛이 줄지 않는 방향이고, 시즌의 흔적은 차림 카드·성과 옷·시즌 책 등으로 남긴다. 누적의 정의·단계·시즌 조건은 엔진 상향 설계의 Vellum U5에서 관리한다. 여기서 같은 숫자와 계산식을 복제하지 않는다.

몸 그림이 마지막 단계에 있어도 오늘 사건·기억·시간대·접촉에 반응해야 한다. 새 활동으로 이해가 늘면 다음 반응에 돌아가게 한다. 단계 수·문턱·기간은 실제 목적과 근거에 따라 개선할 수 있으며, 근거 없이 성장 사실을 깎거나 학생마다 다른 속도를 결함으로 만들지 않는다.
