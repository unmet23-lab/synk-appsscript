## 2. 발견한 결함

### 🔴 B. 「내 기록」 상세 — 남의 개인정보 노출
**증상**: 로그인 학생이 **DEMO-01(바야르)** 인데, 「내 기록」 상세 상단에
`SYNK-001 / 김재헌 / 이름_몽골 재헌 / class_name 정규반1 / 생일 1993-12-06` 이 뜬다.
바로 아래 기록실·플레이스타일 카드는 정상적으로 **바야르 본인** 데이터다 — 즉 위쪽 두 컴포넌트만 다른 사람을 가리킨다.

**정체**: Glide가 상세 화면을 만들 때 기본으로 얹는 `Title(user_id)` + `Fields` 컴포넌트가 지워지지 않았고,
이 둘이 로그인 행이 아니라 **profiles 첫 행(SYNK-001)** 을 참조하고 있다.
(memory `glide-remote-assembly`의 "Custom 페이지 직접 열 참조 = 첫 행"과 같은 계열)

**왜 중요한가**: 가이드 §10-B 권한 잠금의 `학생 상세 Fields에 개인정보 없는지` 항목 위반.
개원하면 **전교생이 같은 한 사람의 이름·몽골이름·반·생일을 보게 된다.**

**처치(클릭 3회)**: 「내 기록」 상세에서 `Fields` 우클릭 → Delete / `Title` 우클릭 → Delete.
(기록실 카드가 이미 제목 역할을 하므로 대체물 불필요.)

### 🟡 C. 화면 제목이 엉뚱한 값
| 화면 | 지금 제목 | 원인 |
|---|---|---|
| 스토어 | `-24` | Screen title이 잔액 열(AQ)에 물림 — 학생 포인트가 그대로 화면 제목이 됨 |
| 도감 상세 | `M02` | contents의 row id가 제목 |
| 내 기록 상세 | `SYNK-001` | 위 Title(user_id) |
| 홈 | (비어 있음) | 무해 |

**처치**: 각 화면 우측 패널 → NAVIGATION → `Title`을 고정 텍스트로(`스토어`·`도감`·`내 기록`).

### 🟡 D. 스토리북 날짜가 원시 문자열
소식 탭 스토리북 카드 Description에 `Mon Jun 01 2026 00:00:00 GMT+0800 (Ulaanbaatar Standard Time)`.
가이드 6-4는 `Description = 월`. 날짜 열이 Date로 인식돼 그대로 찍힌다(v9.68 강사 화면에서 고친 것과 같은 계열의 **화면 쪽** 잔여).
**처치**: 컬렉션 ITEMS DATA → Description을 월 텍스트 열로 교체(또는 Glide 날짜 포맷 지정).

## 3. §A — "빠져 보인" 카드 8장의 정체 (고칠 것 없음)

숨어 있던 것: 완료 배지 · 오늘의알림 · 전당배너 · 첨삭 · 목소리성장카드 · 필살기노트 · 최애 · 매치업.
전부 **"값이 있을 때만 보여라"** 로 설계된 카드다(가이드가 `is not empty` 조건을 명시한 항목들).
개원 전이라 출석·첨삭·평가 데이터가 없어 비어 있을 뿐, 배선은 살아 있다.
학생 1명이 하루만 실사용하면(출석 1회 + 숙제 1건) 완료 배지·알림·첨삭 3장이 즉시 살아난다.

## 4. 이번 점검이 확인하지 못한 것 (정직 표기)

- **컴포넌트 세부 설정**(필터 조건식·정렬·액션 배선)은 우측 패널을 열어야 하는데, 편집기 탭이 백그라운드
  (`visibilityState: hidden`)라 패널 탭 전환이 불안정해 **일부만** 확인했다.
  확인된 것: 홈 탭 표시조건(role=student) · hw_feedback 소스/제목/필드 매핑.
  미확인: 도감 잠금 필터의 실제 조건식 · 스토어 교환 액션의 point_logs 배선 · 랭킹 정렬 열.
  (렌더 결과가 전부 기대대로라 실제 위험은 낮다고 본다 — 잠금도 잔액 게이트도 눈으로 작동 확인.)
- **실제 배포 앱(학생 폰)** 이 아니라 편집기 프리뷰다. 유호님이 보신 화면이 실기기였다면 차이가 있을 수 있다.

**검증 = §4-9 ⑤가 요구하는 2계정 대조**:
`Viewing as` **DEMO-01(바야르)** 로 전환해 같은 화면을 다시 렌더 →
남의 정보 전부 사라졌고, 기록실 수치는 **바야르 본인 것**(최장 5일·106P·누적 216P)으로 나온다.
(수리 전 SYNK-001 계정에서는 1일·15P였으므로, 카드가 로그인 사용자를 정확히 따라간다는 증거.)

**중간에 잡은 오조작 1건**: `Title`을 지우려고 우클릭했을 때 우측 패널이 여전히 `Rich Text 기록실HTML`을
가리키고 있었다 — 그대로 Delete를 눌렀으면 **기록실 카드가 지워질 뻔**했다(07-23 실사고와 같은 구도).
메뉴를 닫고 좌클릭으로 선택→패널에서 `Title` 확인 후 다시 우클릭해 처리. **우클릭 전 패널 확인은 생략 불가**.

### ✅ C 화면 제목 — 2건 수리 · 1건은 **내 오진**
| 대상 | 처치 |
|---|---|
| 「내 기록」 상세 | NAVIGATION Title `user_id` → **Custom 고정 텍스트 `내 기록`**. 프리뷰 상단 `SYNK-001` 소멸 확인 |
| 도감 상세 | Title `content_id`(→`M02`) → **`value_ko`**. 이제 몬스터 이름이 제목(`스파키`)이라 상세 화면 정체성도 살아남 — 고정 텍스트보다 나은 선택 |
| ~~스토어 `-24`~~ | **오진 정정** — 스토어 화면 제목은 애초에 **비어 있었다**. `⚡ 내 포인트 / -24`는 가이드 6-3이 요구한 **잔액 표시 Title 컴포넌트**로 정상이다. 프리뷰가 이전 화면 잔재를 이어 그려서 상단 제목처럼 보인 것을 내가 화면 제목으로 오독했다 |

> **드롭다운이 남긴 증거**: 「내 기록」 상세의 Title 열 선택 목록이 **DEMO-01로 보는 중인데도** 미리보기 값을
> 전부 김재헌 것(`user_id SYNK-001`·`이름 김재헌`·`생일 1993-12-06`)으로 띄웠다. 첫 행 참조라는 §2-B의 진단이
> 화면이 아니라 **편집기 자체에서** 확인된 셈.

### ⏸ D 스토리북 날짜 — Glide 문제가 아니었다 (코드·시트 층)
컬렉션 설정은 **이미 옳다**(ITEMS DATA Description = `월`). 문제는 값 자체다.
- 코드는 정상: [`Code.js:7366`](Code.js:7366)이 `Utilities.formatDate(…,'yyyy-MM')` = **문자열 `"2026-06"`** 으로 쓴다.
- 구글시트가 그 문자열을 **날짜로 자동 해석**해 셀에 Date로 저장 → Glide가 `Mon Jun 01 2026 00:00:00 GMT+0800`으로 렌더.
- 같은 화면 `synk_cards`의 월은 `2026-06`으로 정상 표시 — **synk_stories의 `월` 열만** 오염.

**처방(둘 다 필요)**: ①발간 시 A열에 `setNumberFormat('@')`(텍스트 고정)을 걸어 재발 차단 ②이미 저장된 1행 정정.
**코드 변경 + `/deploy`가 필요한 사안**이라 이번 클릭 작업 범위 밖 — 유호님 판단 대기.
급하지 않은 근거: 현재 스토리북 데이터는 **1행뿐**이고 개원 전이라 열람자 0.

## 6. 2차 점검 — §4 미확인 항목 (같은 날 · 유호님 "필요하면 브라우저 열어서 해")

**1차에서 나온 첫 행 참조 결함이 다른 역할 화면에도 있는지**가 최우선이었다. 학부모가 남의 아이 정보를
보는 것은 학생 건보다 심각하기 때문. **결과 = 전부 정상.**

### ✅ 학부모 「우리 아이」 — 첫 행 참조 아님
- 계정 2개 대조(SYNK-P01·P02) → 둘 다 「김재헌」이 떠서 **한때 결함으로 의심**했으나,
  Title 바인딩이 **`User / 자녀이름`**(User profile 그룹 = 로그인 행 추종)으로 확인돼 정상.
  두 계정이 같게 보인 건 **P02의 `자녀이름` 열 값이 실제로 김재헌**이기 때문(테스트 계정 연결).
- **판별 규칙 확립**: 패널의 바인딩 표기가 `User / 컬럼`이면 안전, **`컬럼`(직접)이면 첫 행 참조 위험**.
  학생 「내 기록」 상세가 후자였다. 이 한 줄이 2계정 대조보다 빠르고 확실하다.
- ACTIONS = `Add action`만(Edit 액션 없음) ✅ · 학부모 몽골어 렌더 정상 ✅

### ✅ 스토어 「⚡ 포인트로 데려오기」 — 액션 전 열 정상
메모리 `glide-remote-assembly`의 **Add row 토큰 이어붙기 결함**(행이 쌓인 뒤 터지는 잠복형)을 겨냥해 전수:

| 열 | 값 | 판정 |
|---|---|---|
| log_id | (비움) | ✅ 밤 자동 채번 |
| student_id | `User / user_id` | ✅ |
| points | `음수가격` | ✅ |
| reason | `구매사유` | ✅ |
| given_by | `User / 이름` | ✅ |
| created_at | `Current date/time` | ✅ |

### ✅ 우회로 = 버튼에만 조건을 건다
카드는 조건을 못 걸지만 **버튼(액션)은 `Allow action when`으로 역할 조건을 걸 수 있다**.

| 완성 | 값 |
|---|---|
| **🌟 오늘의 MVP 왕관** | point_logs · student_id=`user_id`(탭한 학생) · points=**5** · reason=`오늘의 MVP` · given_by=`User / 이름` · created_at=Current date/time · **조건 `role is teacher`** |
| **⚡ 오늘의 시냅스 왕관** | 〃 · reason=`오늘의 시냅스` · 동일 조건 |

**실측 검증**: 강사(SYNK-T01) 프리뷰 → 버튼 노출 / 학생(DEMO-01) 프리뷰 → **버튼 없음 + 기록실 216P 본인 데이터**.

두 번째 버튼은 제목·points·reason·given_by·student_id가 이미 채워져 있어 조건만 걸면 됐다.

### ✅ 결정적 개선 — 조건은 **액션이 아니라 컴포넌트**에 건다
액션마다 `Allow action when`을 거는 방식으로 시작했으나, **Button Block 자체의 Options → VISIBILITY →

### 7-D. `created_at`의 진짜 원인 — Glide의 동명 열 자동 매핑 (08-01 확정)
그쪽 관측(`created_at` 토큰)과 내 관측(공란)이 갈렸던 이유가 풀렸다. **둘 다 맞았다** — 시점 차가 아니라 **내가 그 사이에 지웠기 때문**이다.

**Glide는 Add row 액션을 만들 때 같은 이름의 열을 자동으로 물린다.** `created_at` 칸에 `created_at` 토큰이 미리 들어가고, **Table을 profiles→point_logs로 바꿔도 남으며, 새 액션을 만들어도 매번 재현**된다. 그래서 🎯 집중력을 실제로 눌렀을 때 point_logs 행의 created_at이 **2026-04-21**(4개월 전)로 기록됐다.

**왜 치명적인가**: 밤 배치는 `Code.js:1998`에서 `if (r[1] && !r[5]) r[5] = now` — **비어 있을 때만** 채운다. 값이 들어차 있으면 덮지 않고 `연월`(G열)이 그 날짜 기준으로 계산돼 **그 포인트가 이번 달 랭킹·월간 스냅샷에서 조용히 빠진다.** 그쪽이 쓴 "공란이면 누락"과 내가 본 "오염이면 오분류"는 **같은 열의 두 실패 모드**이고, 안전한 쪽은 **공란**이다(배치가 정확히 채운다).

**현재 라이브 값**: 왕관 2종 = `Current date/time`(원래 정상) · 칭찬 4종 = **공란**(배치가 채움). 둘 다 정상 동작하며, 재검증으로 새 행(84)의 created_at이 빈칸으로 생성되는 것을 확인했다.

**⚠ 토큰 삭제법 정정**: 종전 기록의 "Glide 토큰은 지울 수 없다"는 **Add row 액션 값 칸에는 해당하지 않는다** — 칸 클릭 → `End` → `BackSpace` 1회면 토큰이 통째로 사라진다. 컴포넌트 재생성보다 훨씬 싸다. (단 **데이터 편집기 셀 값은 여전히 이어붙는다** — 78행 날짜를 고치려다 `2026-042026-08-…`이 됐다.)

**회귀 방지**: 새 Add row 액션을 만들 때마다 **`created_at` 칸이 비었는지 확인**한다. Table·points·reason만 보고 넘기면 놓친다.
