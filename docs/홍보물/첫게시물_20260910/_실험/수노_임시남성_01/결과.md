## 최종 사용자 승인과 앞으로의 품질 참고

2026-09-11, 사용자는 위 17.2초 완성본을 보고 **“너무 훌륭해. 앞으로도 이렇느낌으로 모든 작업할때 퀄리티 좋게 만들어주면 좋겠어. 꼭 기억해줘 그리고 커밋해줘”**라고 요청했다. 승인 실물의 SHA256은 `345283d20b41fa48dfc056b264cf702e236f1e71799d806dfb0482a63069f9ec`다.

- 실제 사용자 의사: 현재 완성본에 대한 긍정 평가와, 앞으로의 모든 작업에서도 이 수준의 품질을 이어가라는 요청이다.
- 다음 작업의 실행 해석: 배치와 여백의 균형, 서체 위계와 읽힘, 자연스러운 목소리와 편안한 음량, 지루하지 않은 호흡, 맥락 있는 연결, 마무리의 여운을 결과물의 목적과 타깃에 맞춰 함께 다듬는다. 실제 출력물을 확인하고 피드백을 반영하는 과정까지 책임진다.
- 적용 범위: 이 영상의 90px 이동·17.2초 길이·3.6초 엔딩·크림 패널·+4dB를 모든 작업의 고정값으로 삼지 않는다. 수노 남자 목소리는 계속 임시이며, 여자 DIVE 나나 선택은 유지한다. 전체 영상 교체·SNS 게시·본인 목소리 제작 완료로 확대하지 않는다.

## 후속 17.2초 엔딩 연장

사용자는 앞선 BGM 수정을 좋게 평가하면서 엔딩이 짧아 효과가 충분히 느껴지지 않는다고 말했다. 엔딩을 1초 연장하는 제안을 받은 뒤 “적용해서 17.2초로 해줘”라고 요청했다.

- 본문 0~13.6초와 음성·자막·배치는 유지했다. 엔딩은 13.6~17.2초, 총 3.6초다. 음악은 13.6~14.2초에 +4dB까지 완만하게 상승하고, 14.2~16.2초의 2초간 유지한 뒤 16.2~17.2초에 잦아든다. 로고·문구도 마지막 1초에 함께 사라진다. 배경의 느린 움직임은 늘어난 엔딩 길이에 맞췄다.
- 원곡에서 17.2초 구간을 다시 준비해 이전 14.8초 페이드가 남지 않게 했다. 기본 BGM 게인 −29.4dB를 유지했고, 기존 본문 배경음과 새 원본의 13.6초 이전 PCM이 동일함을 확인했다. 이미 잦아든 파일을 반복하거나 끝에 정지·무음 구간을 붙이지 않았다.
- 영상과 음악이 같은 시간을 쓰도록 `voice-trial-timing.json`을 Remotion과 음원 준비 스크립트에서 함께 읽는다. 전체 516프레임, 영상·오디오 모두 17.200초, 전체 디코딩 통과다. 0~13.5초 최종 디코딩 오디오가 직전 영상과 동일하고, 목소리 원본 SHA256도 동일하다. 유지 구간은 실제 +4.00dB, 전체 −22.69 LUFS·−8.90dBTP다.
- 최종 출력의 [본문](엔딩17초_본문.png), [엔딩 등장](엔딩17초_등장.png), [유지 구간](엔딩17초_유지.png), [사라지는 중](엔딩17초_사라짐.png), [마지막 프레임](엔딩17초_마지막.png)을 확인했다. 추가 1초 동안 로고가 유지되며 지정된 마지막 1초에 사라진다. 이 하네스의 직접 청취는 확인 불가이며, 연장본의 최종 청감은 사용자 판단이 남는다.

## 앞선 16.2초 엔딩 BGM 음량 수정

사용자는 마지막 엔딩에서 BGM 음량을 조금 키우면 고급스러운 느낌이 나지 않겠냐고 물은 뒤 이어서 진행해 달라고 요청했다. 기존 음악의 볼륨 곡선만 바꾼 비교 가능한 수정본을 만들었다.

- 엔딩이 시작되는 13.6초부터 0.7초에 걸쳐 BGM을 0→+4dB로 올렸다. 양 끝에서 변화 속도가 완만한 코사인 곡선을 사용했다. 14.3초에 +4dB에 도달하며, 기존 14.8~16.2초의 1.4초 페이드아웃은 유지했다. 엔딩 구간 전체 평균 진폭 기준 변화는 +3.44dB다.
- 기존 `public/bed.wav`에서 `public/bed-ending.wav`를 파생했다. 매번 원본 배경음에서 생성하므로 반복 실행해도 증폭이 누적되지 않는다. `수노음성시험.py`의 준비·최종 출력 경로와 `VoiceTrial.tsx`의 미리보기 참조를 함께 갱신했다. 목소리 원본에는 처리하지 않았고, 원본 WAV에서 한 번 AAC로 합쳤다.
- **실제 대조:** 배경음의 0~13.6초 PCM 샘플 동일, 최종 영상의 0~13.5초 디코딩 오디오 샘플 동일, 목소리 WAV SHA256 동일이다. 영상 스트림은 위치 조정본과 SHA256이 동일하다. 엔딩 BGM이 바뀌었으므로 전체 오디오 스트림 동일로 보고하지 않는다. 전체 디코딩 통과, 16.200초·−22.69 LUFS·−8.90dBTP이며 마지막 20ms 배경음은 −89.11dBFS RMS다.
- [당시 엔딩 화면](엔딩BGM_화면확인.png)을 확인했다. 기술 대조와 실제 청감은 구분하며, 이 하네스의 직접 청취는 확인 불가다. 이후 사용자는 소리는 좋지만 엔딩이 짧다고 평가했고, 위 17.2초 연장 요청으로 이어졌다. [당시 볼륨 설정](엔딩_BGM_설정_16초.json), [당시 전후 대조](엔딩_BGM_대조_16초.json), [당시 검사](검사_16초.json), [음량 수정 직전 검사](검사_엔딩음량수정전.json).

## 앞선 본문 중심 조정

- 이번 시험 영상의 다섯 본문 장면에서 제목·설명·이미지 및 문서 설명·파형·파형 설명·자막을 모두 90px 위로 이동했다. 첫인사 본문은 top 650→560px, 나머지 본문은 540→450px, 파형은 1040→950px, 자막은 bottom 328→418px다. 묶음 내부 간격·서체·자막 패널 크기와 표현은 유지했다.
- 상단 로고·장면 번호·하단 계정 표시는 화면 기준점으로 유지했고, 별도 구성인 엔딩은 유지했다. 기존 `balanced-portrait` 호출은 이번 시험본에서만 사용하며, 다른 첫 게시물의 기본 배치에는 영향이 없다.
- 최종 영상에서 [첫인사](위치조정_첫인사.png), [회사 소개](위치조정_회사소개.png), [노트](위치조정_노트.png), [봉투](위치조정_봉투.png), [파형](위치조정_파형.png), [엔딩](위치조정_엔딩.png)을 360×640으로 확인했다. 본문이 로고에 닿지 않고, 소품·설명·자막 사이 겹침이나 잘림이 없다. 파형 장면은 [원해상도 프레임](위치조정_파형_확인.png)도 확인했다.
- 위치 조정 전 영상의 AAC 음원을 재인코딩 없이 복사했다. 오디오 스트림 SHA256 동일, 전체 디코딩 통과, 16.200초·−22.69 LUFS·−8.90dBTP다. 장면 시간·자막 표시 시간·대본·파형 데이터도 유지했다. [현재 검사 기록](검사.json), [직전 검사 기록](검사_위치수정전.json).

## 앞선 자막 배경 수정

사용자는 자막 배경만 업그레이드할 방법을 물었고, 상단 선을 없애고 작은 곡률·얕은 그림자·일정한 크기를 갖춘 크림색 종이 패널 제안을 적용해 달라고 요청했다.

- `Captions.tsx`의 이번 시험본용 `balanced-portrait` 분기에만 적용했다. 기존 Paper 색과 Ink 기반 그림자를 사용하고, 패널을 780×176px·모서리 16px·안쪽 여백 세로 24px/가로 40px로 고정했다. 문장 길이가 바뀌어도 패널이 늘거나 줄지 않는다. 상단 가로선은 제거하고 매우 옅은 외곽과 얕은 그림자로 종이 두께를 표현했다.
- 자막 SUIT 42px/400·행간 1.45·자간 −0.02em, 원문 줄바꿈과 표시 시간, 본문·소품·엔딩 구성은 유지했다. 기존 음원 스트림을 재인코딩 없이 복사했으며 수정 전후 SHA256이 동일하다. 전체 디코딩 통과, 16.200초·−22.69 LUFS·−8.90dBTP다.
- 실제 출력에서 [첫인사 한 줄](자막배경_첫인사.png), [회사 소개 두 줄](자막배경_두줄.png), [긴 문장](자막배경_긴문장.png)을 360×640 축소 화면으로 확인했다. 글자 잘림·겹침이 없고 좌우 여백이 남는다. [원해상도 확인 화면](자막배경_확인.png)에서도 모서리·그림자·두 줄 여백을 확인했다. 수정된 배경의 사용자 감상은 아직 받지 않았다.

기존 배치 수정본은 비교용으로 보존했다. 최신 파일과 검사 기록은 위 링크 및 [검사.json](검사.json)을 따른다.

## 앞선 배치·타이포 수정

사용자는 앞선 영상을 “지루하지도 않고 그냥 딱 좋네”라고 평가한 뒤, 봉투 참고 이미지를 주며 요소가 위쪽에 몰려 있으니 내려 균형을 맞추고 폰트도 다듬어 달라고 요청했다. 앞선 호감을 배치까지 고정하는 승인으로 확대하지 않고 이번 수정에 반영했다. [받은 참고 이미지](요청_배치참고.png)

- 밝은 장면의 일반 본문 시작을 350→540px로, 소품 없는 첫 소개는 650px로 내렸다. 로고는 176→250px, 소품 위 여백은 34→112px(문서 장면 68px)로 조절했다. 봉투·노트의 중심이 화면 중앙보다 약간 아래로 오며 제목·소품·자막 사이에 공간이 고르게 이어진다.
- 한글 SUIT와 라틴 Inter Tight를 유지했다. 제목 첫 줄 66px/500, 핵심 줄 98px/800(첫 소개 이름 116px/800), 행간 1.2로 위계를 나눴다. 첫 줄 자간 −0.02em, 헤드 −0.04em은 현재 폰트 정본을 따른다. 본문 34px/500, 자막 42px/400·행간 1.45로 읽힘을 조절했다. 사용한 SUIT 400/500/800 파일은 기존 킷의 실제 로드 대상이다.
- 파형을 870→1040px로 내려 본문과 간격을 맞췄다. 엔딩 구성·장면 길이·자막 시간·대본은 유지했다. 첫 게시물의 공유 컴포넌트에 `balanced-portrait` 선택 옵션을 추가했고, 이번 시험본의 호출에서만 사용한다. 다른 영상은 기존 기본 옵션을 사용한다.
- **음원 비트스트림 동일 확인:** 수정 전 최종 영상의 AAC 트랙을 재인코딩 없이 복사했다. 원본과 수정본의 오디오 스트림 SHA256이 일치한다. 16.2초, −22.69 LUFS, −8.90dBTP도 동일하다. 이번에는 소리를 다시 생성하거나 보정하지 않았다.
- 최종 수정본의 [첫 장면](첫화면_수정.png), [회사 제작물](회사소개_수정.png), [노트](시도_수정.png), [봉투](공유_수정.png), [파형](파형_수정.png), [엔딩](엔딩_수정.png)을 360×640 실제 축소 화면으로 확인했다. 제목·소품·자막 겹침과 잘림이 없었고, 독립 봉투 프레임 검토에서도 실제 문제를 찾지 못했다. 사용자 최종 배치 선호 확인은 아직 받지 않았다.

현재 원본·코드 지문 및 오디오 동일성은 [검사.json](검사.json)에 있다. 원본 이미지는 변경하지 않았고, 기존 업로드 묶음·다른 영상·SNS 게시본은 이번 한 편 수정의 대상이 아니다.

## 처음 적용한 콘텐츠

- 출발 콘텐츠: [기존 05 SHIFT Instagram 소개](../../05-yuhobuilds-instagram/원고.json). `FirstScene`의 레이아웃·브랜드 서체·현재 SHIFT 로고와 회사 제작물·소품을 재사용했다. 기존 ‘독립 강사·소개 원고·문의’ 대본은 현행 SHIFT 방향 및 확보 음성과 맞지 않아, ‘AI와 회사를 만들며 시도하고 고치는 과정’의 짧은 소개로 바꿨다. 원본 05 파일은 수정하지 않았다.
- 음성: [A 음질 보정 v1](../../../../브랜드_목소리/20260910/수노_유호보컬/말하기_시험01/A_음질보정_v1.wav), 13.6초. 다운로드 한도 0인 현재 조건에서 이미 공식 확보한 음원을 사용했다. **새 대본의 수노 생성 시험이 아니라, 확보 음성의 기존 콘텐츠 적용 시험**이다. 말투·속도·음높이·음성 볼륨을 추가로 바꾸지 않았다.
- 화면: 0–2초 유호 소개 → 2–5.17초 AI와 회사 제작 → 5.17–7.17초 시도·수정 → 7.17–9.67초 방법 공유 → 9.67–13.6초 실제 음원 파형 → 13.6–16.2초 SHIFT 엔딩. 3초를 넘는 회사 소개는 실제 자료의 읽기, 파형 장면은 목소리 청취가 목적이며 안에서 자료 등장·파형 변화가 이어진다.
- `synk-intro`는 실제 LAB 소개서다. ‘직접 만든 LAB 소개서 · 제작 실물’로 표시했고 목소리 실험의 증거로 설명하지 않았다. 마지막 파형은 적용 음원 자체의 크기를 계산해 그렸다.
- 소리: 기존 SHIFT 배경음을 매우 작게 얹고 끝에서 부드럽게 줄였다. 다른 음성 공급자·추가 음성 생성·게시·결제는 하지 않았다. 여성 나나 음성은 이 남성 시험 영상에 넣지 않았다.

## 실제 확인

- 1080×1920, 30fps, 486프레임, **16.200초**, H.264/AAC 48kHz. 최종 평균 **−22.69 LUFS**, true peak **−8.90dBTP**. 전체 디코딩 통과.
- 최초 시험본 확인 화면: [첫 화면](첫화면.png), [시도](시도.png), [공유](공유.png), [장면 모음](장면검토.png), [엔딩](엔딩검토.png). 현재 배치 확인은 위 수정 섹션을 따른다. SYNK 무실땀과 SHIFT 사업명 파랑·실땀을 유지한 현행 로고를 사용했다.
- Remotion 중간 출력의 오디오가 원본보다 2,048샘플 늦게 들어간 것을 파형 대조로 찾아, 영상 스트림은 그대로 보존하고 원본 WAV에서 음원을 다시 한 번만 AAC로 합쳤다. 최종 음원 시작을 원본과 맞춰 대조했고 상관계수 0.99 이상을 확인했다. [검사와 최종 SHA256](검사.json), [입력 자산·복사 지문](원본명세.json).
- 자막은 기존 로컬 전사와 독립 단어 시간 확인을 사용했다. 이름은 앞선 원본 자동 전사에서 ‘요호’로 인식된 적이 있어 발음의 사람 확인이 남는다. 최종 문장 자막 뒤에도 전체 음원 13.6초를 보존했다.
- **직접 청취 확인 불가:** 이 하네스는 오디오 입력을 듣지 못한다. 자연스러움·잔향·마지막 신호와 자막의 실제 청감은 사용자 재생 판단이 남는다. 수치 검사를 청취 승인으로 표시하지 않는다.

## 제작 경로와 적용 범위

준비 스크립트 `영상/수노음성시험.py` → 기존 모듈을 소비하는 `영상/src/firstposts20260910/VoiceTrial.tsx` → 시험 폴더의 `render.mp4` → 준비 스크립트 `--finalize` → 최종 `video.mp4`. 독립 public 폴더에 필요한 자산과 폰트만 복사했다. 자막 JSON과 실제 입력 props를 함께 보관했다.

```powershell

```

남녀 선택은 기존 결정·현재 음성 설정·트랙·음성 시험 기록에 반영했다. 다른 첫 게시물·전체 업로드 묶음·SNS 게시본은 이번 한 편의 시험 대상이 아니며 교체하지 않았다. 본인 음성 원본 준비와 실제 본인 목소리 제작은 계속 남아 있다.
