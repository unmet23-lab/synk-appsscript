# 한 상품에서 꺼내는 고객 질문 지도

SYNK SHIFT · 03 콘텐츠지도 · v1.0 · 2026-09-09 · 편집 가능한 한국어 원본

이 자료의 서비스·질문·답변은 **가상 교육용 예시**입니다. 실제 고객이 물었다는 기록이나 조회·매출 성과가 아닙니다. 아래 질문을 ‘고객에게 받은 질문’이라고 공개하지 마세요.

## 1. 무엇이 남고, 어떤 순서로 쓰나요

한 상품에서 서로 다른 고객 질문 12개와 각 편에서 먼저 줄 답, 관련 자료, 다음 행동을 만듭니다. 12개 모두를 정해진 주기에 게시하라는 일정표는 아닙니다.

1. 상품 한 장에서 대상·상황·제공물을 가져옵니다.
2. 알아보기 전, 선택할 때, 사용한 뒤의 질문을 나눕니다.
3. 질문 하나에 본편만으로 쓸 수 있는 답 하나를 적습니다.
4. 더 필요한 자료가 있을 때만 해당 자료로 잇습니다.
5. 실제 반응이 생기면 질문의 표현과 전제를 개정합니다.

## 2. 채운 가상 예시 — 소개자료 편집 서비스의 12편

가상 상품: 처음 기관에 강의를 제안하는 독립 강사를 위한 소개자료 원고 정리. 소개자료 한 장과 읽는 순서·수정 안내를 남기며, 기관 섭외와 계약 성사는 포함하지 않습니다.

| 단계 | 고객이 가질 수 있는 질문 | 한 편의 제목 | 본문에서 먼저 줄 것 | 이어질 자료와 적용 |
|---|---|---|---|---|
| 알아보기 | 경력을 다 써야 하나요? | 첫 줄에서 경력보다 먼저 읽혀야 할 것 | 대상·실습·결과를 먼저 쓰고 관련 경력만 근거로 붙인 가상 예시 | 01 소개문: 자기 대상만 바꾸기 |
| 알아보기 | 여러 일을 어떻게 소개하나요? | 고객이 둘이면 첫 줄도 둘 | 개인 강사용과 기관 담당자용 첫 문장 두 개 | 01 소개문: 조건별 변형 선택 |
| 알아보기 | 무엇을 잘한다고 써야 하나요? | ‘전문적’ 대신 남길 것을 쓰기 | 모호한 형용사를 실제 결과물 이름으로 바꾸는 한 쌍 | 02 상품한장: 인수물 한 줄 고치기 |
| 알아보기 | 아직 실적이 없으면요? | 시연을 시연이라고 보여주는 법 | ‘가상 예시’ 표기와 실제 확인한 범위·미확인 범위의 구분 | 01 소개문: 판매 전 소개 예시 |
| 선택하기 | 소개서가 예쁘면 충분한가요? | 첫 화면에서 답해야 할 세 질문 | 누구의 수업인지·무엇을 해보는지·무엇이 남는지 점검 | 02 상품한장: 대상과 결과 대조 |
| 선택하기 | 어디까지 맡길 수 있나요? | 포함과 제외를 같은 페이지에 두기 | 원고 정리 포함/기관 섭외 제외를 나눈 완성 예시 | 02 상품한장: 자기 경계 두 줄 쓰기 |
| 선택하기 | 문의에 뭘 적으면 되나요? | 파일을 보내기 전에 적을 세 가지 | 대상·사용할 자리·원하는 결과라는 최소 문의 틀 | 04 문의답변: 초안 없이 질문하기 |
| 선택하기 | 급하면 바로 맡기면 되나요? | 필요한 날짜와 가능한 날짜는 다르다 | 요청 일정을 확인하되 가능 여부를 먼저 약속하지 않는 답변 | 04 문의답변: 일정 미확인 응답 |
| 사용한 뒤 | 자료를 받으면 뭘 확인하나요? | 받은 파일에서 가장 먼저 볼 세 칸 | 열리는지·합의한 내용인지·바꿀 곳이 설명됐는지 확인 | 02 상품한장: 완료 확인 다시 읽기 |
| 사용한 뒤 | 다른 고객에게도 써도 되나요? | 고객이 바뀌면 같이 바꿀 곳 | 대상만 바꾸고 실습 결과는 그대로 둔 오류와 수정 | 01 소개문 + 06 실습: 일관성 확인 |
| 사용한 뒤 | AI로 소개를 늘려도 되나요? | AI가 만든 문장에서 먼저 지울 약속 | 원본에 없는 실적·제공 범위를 표시하는 검토 예시 | 05 AI업무지도: 원본 대조하기 |
| 사용한 뒤 | 쓰다 막히면 어떻게 질문하나요? | ‘안 돼요’ 대신 막힌 칸을 알려주기 | 목표·시도·막힌 칸·원하는 도움의 짧은 질문 예시 | 소통 안내: 비식별 적용 질문 |

표의 제목은 제작 후보입니다. 실제 플랫폼 게시물·고객 질문·성과로 집계하지 않습니다.

## 3. 한 편을 완성하는 채운 원고

주제: 고객이 둘이면 첫 줄도 둘.

도입: “강사에게도, 교육 담당자에게도 같은 소개를 보내고 있나요? 두 사람이 확인할 것은 다를 수 있습니다.”

가상 예시 A: “처음 강의를 제안하는 독립 강사의 소개자료를 정리합니다.”

가상 예시 B: “교육 담당자가 검토할 수 있도록 수업의 대상·실습·준비 조건을 정리합니다.”

판단: “직함을 두 개 만든 것이 아니라 읽는 사람이 결정할 일을 나눴습니다. 실제로 맡지 않는 업무는 넣지 않습니다.”

즉시 실습: “자기 소개를 읽을 사람 둘을 적고, 각자가 먼저 알아야 할 한 가지를 써보세요.”

다음 도움: “「내 일을 설명하는 첫 문장」에는 소개를 나눠 쓰는 예시와 수정 원본이 있습니다.” 현재 파일은 [01_소개문.md](01_소개문.md)입니다. 공개용 안내에는 실제 자료가 열리는 경로를 확인한 뒤 연결합니다.

## 4. 내 것으로 바꾸는 수정 원본

```text
상품: 첫 강의 소개자료 정리 — 가상 예시
읽을 사람: 첫 기관 제안을 준비하는 독립 강사
고객의 단계: 알아보기
질문: 여러 일을 어떻게 한 번에 소개하나요?
답 하나: 읽는 사람이 둘이면 첫 문장도 나누고 실제 제공 범위를 맞춥니다.
보여줄 것: 개인 강사/기관 담당자용 첫 줄 두 개
직접 해볼 것: 읽는 사람 두 종류와 각자의 첫 질문을 적기
관련 자료: 01_소개문.md의 조건별 변형
선택적 다음 질문: 두 문장 중 어느 쪽에서 제공 범위가 헷갈리나요?
근거 상태: 가상 교육용 기획. 실제 문의·성과는 아직 없음.
```

자신의 상품으로 바꿀 때 제목부터 만들지 말고 질문·답·직접 할 일을 먼저 고칩니다. 한 편에 답이 둘이면 둘로 나누거나, 하나가 나머지의 조건임을 설명합니다.

## 5. 조건이 다르면 이렇게 바꿉니다

**새 독자가 많은 자리:** 용어를 몰라도 문제와 완성 예시가 이해되게 시작합니다. 앞선 영상을 봤다는 전제를 지웁니다.

**짧은 영상:** 질문 하나와 판단 하나를 완결합니다. 긴 본편의 결론을 숨긴 예고편만 만들 필요는 없습니다. 전용 기획과 본편 재구성 모두 가능합니다.

**캐러셀·검색 글:** 완성 예시 → 선택 이유 → 수정 원본 → 예외 → 점검으로 읽히게 합니다. 검색어 반복이나 작은 글씨로 원문 전체를 밀어 넣지 않습니다.

**후속 편지:** 이미 쓴 사람이 막힐 조건 하나를 다룹니다. 실제 질문이 아니라면 ‘예상 질문을 바탕으로 한 연습’이라고 밝힙니다. 기본 자료 열람과 구독 선택을 묶지 않습니다.

## 6. 오판을 막는 확인

- 제목만 다르고 같은 답을 반복하고 있지 않나요?
- 본편을 본 사람이 자료를 열지 않아도 한 가지를 적용할 수 있나요?
- ‘실제 문의’와 ‘우리가 만든 예상 질문’을 구분했나요?
- 질문과 자료가 같은 문제를 다루나요? 소개 팁 끝에 무관한 판매 안내를 붙이지 않았나요?
- 플랫폼마다 다른 역할이 있나요? 같은 원문을 복사한 횟수를 새 기획 수로 부풀리지 않았나요?
- 조회·저장·다운로드를 적용 성공이나 매출로 바꾸어 말하지 않았나요?

## 7. 쓰다가 막히면

**“질문이 떠오르지 않아요.”** 상품의 각 줄 옆에 ‘이게 나에게 맞나?’, ‘어디까지인가?’, ‘받고 나면 어떻게 쓰나?’를 적어보세요. 고객에게 직접 들은 질문인 척하지 않습니다.

**“모두 소개 이야기예요.”** 알아보기·선택하기·사용한 뒤에 질문을 다시 배치하세요. 마지막 단계에는 파일 수정·확인·예외 처리처럼 사용 행동을 넣습니다.

**“자료로 연결할 필요가 없어요.”** 본문에서 끝내도 됩니다. 추가 자료가 독자의 다음 일을 실제로 돕지 않으면 억지로 붙이지 않습니다.

**“반응이 적으니 주제를 버려야 하나요?”** 노출과 클릭뿐 아니라 읽은 사람의 상황이 맞았는지, 질문이 구체적인지, 적용할 답이 있었는지 분리해서 확인하세요. 표본과 조건 없이 원인을 확정하지 않습니다.
