## 3. 정적 29장과 실제 사용 크기

2차 레이아웃의 `_검토/미리보기/전체카드.png`에서 29장을 전수 조망했다. 별도로 02-04, 08-06, 14-01, 16-01, 19-01 업로드 JPG를 원본 크기로 확인했다. LinkedIn 13을 포함한 6개 대표 카드는 390px 폭 파생 이미지로 직접 보았다. 생성·원천 지문은 [사용크기/원천.json](사용크기/원천.json)에 있다.

- 관찰한 표제·본문·한몽 두 언어의 문장 끝에서 잘림·겹침·글자 대체 네모가 보이지 않는다. 390px 대표 카드에서도 주요 본문과 실습 줄이 읽힌다. 작은 바닥 표시는 출처/쪽수이며 그것에 실습 필수 조건을 숨기지 않는다.
- 1080×1350 4:5 카드와 Pinterest의 1080×1620 2:3 카드를 구분했다. JPG의 규격은 로컬 파일 확인이며 플랫폼에 실제 들어간 결과가 아니다.
- 책·봉투·노트 등 관찰된 소품의 몸체가 잘리거나 윗윤곽에 큰 파임이 생긴 현상은 보이지 않는다. 작은 소개서 전체를 강의 본문 대신 읽게 하는 구성은 별도 판정한다.
- 작성자의 자동 경계 검사와 독립 픽셀 관찰은 다르다. 29장 원본을 모두 100% 배율로 읽었다고 주장하지 않는다. 전수 접촉시트와 대표 원본·390px 검사를 병행했다.

## 4. PDF 6종, 22쪽 — 합격

PDF 스킬의 실제 페이지 렌더 검수를 적용했다. 작성자 표식 도구는 실행하지 않았다. 원본 6 PDF는 수정하지 않았고, Poppler로 105dpi PNG 22장을 생성했다. `[파일명]-[쪽].png` 및 6개 접촉시트는 `PDF_독립/`에 있다. 링크 제거 후 최신 PDF를 다시 렌더했고 최신 접촉시트 6장으로 22쪽을 다시 펼쳐 보았다.

직접 관찰: 22쪽 전수 접촉시트, 그중 01의 1쪽 / 03의 2쪽 / 05의 2쪽 / 06의 4쪽은 렌더 원본 크기로 추가 확인. 한글 깨짐·제목/본문 충돌·큰 잘림·빈 페이지 없음. 본문과 코드 형태의 편집 원문이 읽히며 03·05의 페이지를 넘는 표는 열 제목이 반복돼 대응을 잃지 않는다. 문단·목록의 정상적인 다음 페이지 이어짐을 내용 누락으로 판정하지 않는다. 휴대전화에 A4 전체를 축소한 상태에서도 모든 본문이 읽힌다는 보장은 아니며, PDF 읽기 크기/확대와 원본 MD 편집을 구분한다. 입력 가능한 PDF 양식은 아니다.

[원문대조.json](PDF_독립/원문대조.json)의 독립 자동 대조:

- MD 문장·표 셀 456단위에서 공백·구두점을 정규화해 PDF 추출 본문과 대조. 누락 0.
- 22쪽 각각 텍스트 존재. 페이지 바깥 문자 좌표 검사 0건.
- 추출 시 닫는 따옴표가 U+02BC로 보이는 차이는 부호로 처리했다. 문자·단어를 임의로 삭제해서 대조율을 높이지 않았다.
- pdfminer의 일부 FontBBox 누락 경고로 좌표 검사에 한계가 있다. 따라서 숫자 0만으로 모든 글리프 경계를 보증하지 않고 실제 Poppler 픽셀과 함께 판정했다.

## 5. 음성 도구 확인과 검수 경계

요청 시점의 설치 도구 목록에서 실제 공개 음성 파일 입력·전사 기능을 검색했으나 callable 전사 도구는 없었다. 공통 도구 출력형의 audio 블록이나 음성 통화 도구를 파일 전사 기능으로 오인하지 않았다. 외부 Gemini/유료 API로 우회 전송하지 않았다.

이후 루트/A가 별도 로컬 CPU faster-whisper 전사를 수행했다. 현행 `공개수업/음성/로컬전사명세.json`에는 offline=true, audioUploaded=false, humanListening=false, 원고를 프롬프트로 쓰지 않았음이 표시된다. 01의 자동 문자 대조 100%는 그 음성의 전사 비교 결과이지 전편의 발음·음색·자막 타이밍이 사람 청취로 모두 승인됐다는 뜻은 아니다. 독립 검토자가 직접 듣지 않은 파일을 청취 완료라고 표현하지 않는다.

### 23개 로컬 전사의 독립 의미 대조

루트의 후속 요청으로 본수업 18구간·클리닉 5구간의 자동 문자 차이 36곳을 전량 읽었다. [음성전사_독립대조.json](음성전사_독립대조.json)에 전사 파일·활성 WAV 지문과 현재 원고 일치 여부를 저장했다. 23개 모두 WAV 지문 일치, 비교 기준 내레이션이 현재 원고와 일치한다. 새 외부 모델 호출·음성 전송 없이 기존 결과만 읽었다.

- 가상 사례·현재 모집 아님·성과 미보장·실제 범위·학생/고객 식별자료와 공개 댓글 불필요·사람의 최종 확인이라는 핵심 명제는 유지된다. 새 성과 보장이나 핵심 부정의 반전은 발견하지 못했다.
- 숫자 표기(일인/1인, 세/3, 여섯/6), 조사, 축약(바꾸어/바꿔)은 이 맥락의 새 제공 약속이 아니다.
- ASR에는 `첫 칸 → 척하는`(04), `세 칸 → 색한`(08), `세 줄 → 3주`(13), `적어두세요 → 적어주세요`(18), `가상 초안 → 가상 초화`(클리닉02) 등이 있다. ASR 출력 텍스트를 그대로 공개 자막으로 사용하면 학습 용어와 행동 방향이 흐려진다. **자막은 검토된 정본 문장을 쓰고 ASR는 시점 정렬 근거로만 사용한다.**
- 18의 앞 문장에도 ‘개인 자료를 공개하거나 댓글을 남기지 않아도 실습은 끝납니다’가 유지되므로 제출 요구로 뒤집혔다고 단정하지 않는다. 다만 ‘적어두세요’의 실제 음성은 위 04·08·13·클리닉02와 함께 선택적 청취 확인 후보로 남긴다.
- 위 텍스트 차이만으로 음성이 실제 오발음했다고 단정할 수 없다. 자동 인식 오류와 발화 오류를 구분하기 위한 청취는 미완료다. 이 판정은 전사상 핵심 의미 검토 합격이며 모든 발음·음색·재생 타이밍의 사람 검수 완료가 아니다.

실제 동영상 프레임·음성 기술 검사·수동 청취·몽골어 사람 감수·계정 권한·공개 자료실 live 연결·업로드·독자 반응은 각각 별도 확인 항목이다. 자료 파일과 원고가 완성됐다는 사실을 공개 또는 성과로 확대하지 않는다.

## 6. 출고 도구의 독립 읽기 검사

A 요청으로 `출고도구.py` 전량을 읽고 명시적 출고 실행 없이 기본 dry-run과 순수 함수만 검사했다. 대상 SHA-256: `5253c64f75a3dad6d7ea216f67899697f993e4ad2b313779cd52b8052fd50bf3`.

- [출고도구_독립검사.py](출고도구_독립검사.py) 순수 검사 17개 통과. 생성 로그·검수 파일·실행 환경·숨김 파일·master 이미지 제외, 폴더 탈출과 `file://` 거부, 한글 HTML 안 정확한 계정 ZIP 링크만 제거하고 PDF 링크/다른 버튼 보존, 필수 영상 9개 계약을 확인했다.
- 기본 실행은 dry-run이며 `--출고`가 있어야 ZIP를 쓴다. 기존 파일 전체를 임의로 압축하지 않고 허용된 파일과 실제 의존 관계를 모은다. 계획 시점의 원천 SHA를 쓰기 직전/교체 전 다시 확인한다.
- UTF-8 파일명 플래그, 재개봉한 파일의 SHA, Windows 대소문자·정규화 충돌, ZIP 내부 링크·필수 영상 읽힘 검사 코드가 있다. 실제 ZIP 생성·재개봉 성공은 루트의 출고 실행 후 증거로만 인정한다. 독립 검토자는 해당 쓰기 함수를 실행하지 않았다.
- 당시 dry-run: 19계정·필수 영상 9개·전체 283파일. WAV·ASR JSON·실행 환경 파일 포함 0. 아직 생성 중인 `공개수업/수업.mp4`와 `공개수업/클리닉.mp4` 누락을 정확히 거부했다. 이는 완성 전 상태를 성공으로 넘기지 않는 동작이지 제작 실패 확정이 아니다.
- 업로드 조건 안내의 꾸러미 밖 내부 문서 링크 1개를 제거하고 검증한 공식 YouTube 원문 3개와 확인 범위 설명으로 바꿨다. Substack의 압축 표현도 이미지·영상 삽입 지원과 임의 HTML 미지원을 명확히 구분했다.

코드·순수 함수 확인 범위 차단 결함 없음. 최종 ZIP 20개 생성, 실제 추출 후 사용자 환경에서 열림, 최종 동영상 지문은 이 절의 완료 범위가 아니다.

## 7. 최종 영상 9개 — 독립 실물 검수 합격

B의 항목별 현재 입력 지문 재검사·동결 통보 후 독립 대조를 다시 수행했다. `renderSourceSha256`는 각 영상의 장면·자산·음성을 포함하므로 영상끼리 같은 값이어야 하는 전역 지문이 아니다. 각 영상이 자기 보고서·현재 원고와 일치하는지 검사했다.

- 직접 관찰: 숏폼 7편의 접촉시트 59프레임 + 본수업 36프레임 + 클리닉 10프레임, 총 대표 105프레임. 최종 재인코딩한 01·03·04 접촉시트를 다시 열었으며 나머지는 이미 본 최종 지문과 동일함을 대조했다.
- 본수업의 `frame-06/15/24/35`, 클리닉 `frame-02/06/09`는 큰 원본으로 추가 확인했다. 별도 상세 추출에서는 LAB 한몽 본문·가위/본문·수업의 긴 자막/여섯 칸/비보장/마지막 자막 등 6종을 더 보았다. 16개 상세 추출 파일이 모두 존재한다고 독립 검토자가 16개를 전부 읽었다고 하지는 않는다.
- 표제·본문·실습 칸·자막이 분리돼 읽힌다. 관찰한 프레임에서 잘림·중첩·대체 네모·큰 소품 윤곽 손상 없음. 가상 표시와 실제 제공 범위의 조건이 유지된다. PULSE 감상 01에는 학습·댓글 CTA가 끼어들지 않는다.
- 클리닉의 고친 문장은 원자료의 ‘소개문 초안 한 개를 작성하는 실습’과 일치한다. LAB 한몽 문장은 보존 원고와 일치하며 ASR의 ‘3주’ 같은 잘못 인식한 문구가 공개 자막으로 옮겨지지 않았다.
- 별도 상세 추출 중 03의 12초는 장면 시작 페이드의 빈 바탕이었다. 영상 결함으로 기각하지 않고, 검수 증거로 부적합하다고 알려 13초 한몽 본문 화면으로 재추출하게 했다. 새 13초 이미지를 직접 확인했다. 영상 자체·원고 변경 없음.
- `공개수업/표지.jpg`와 `클리닉-표지.jpg`도 실제 열어 제목·수업 범위·가상 표시가 읽히는 것을 확인했다.

[영상_독립지문.cjs](영상_독립지문.cjs) → [영상_독립지문.json](영상_독립지문.json): MP4 9개를 직접 해시 계산하고 ffprobe로 읽어 보고서의 지문·규격 및 현행 원고 SHA와 대조했다. 실제 `수업.srt`·`클리닉.srt`에서 번호·시간 줄을 제외한 모든 문장을 현재 정본 내레이션과 대조해 두 파일 모두 일치했다. 이 검사는 B의 자막 중간 JSON만 비교한 결과가 아니다.

긴 영상의 끝에서 0.25초 전 화면은 독립 검토자가 직접 재추출해 확인했다. 마지막 실습/자기 메모 안내가 온전하고 자막이 끝난 뒤에도 화면을 유지한다. 두 끝 화면은 `영상_독립끝/`에 있다. 음성 전체를 직접 청취하거나 모든 프레임의 움직임을 연속 재생해 확인했다는 뜻은 아니다.

## 8. 최종 전체 ZIP — 이름·출고목록 독립 합격

A가 실제 생성한 `마케팅실행_20260909_업로드꾸러미.zip`을 읽기 전용으로 열었다. 독립 검토자는 재출고·압축 해제를 실행하지 않았다. 파일 SHA-256을 직접 다시 계산해 `14c7fec34aefa6898c722f5ec94f87007957aae3c25193eba04ad445746df286`과 일치함을 확인했다.

[꾸러미_독립대조.json](꾸러미_독립대조.json)의 확인 결과:

- 293멤버 = 실제 파일 292개 + 출고목록 1개.
- MP4 9개, 번호순 `upload-XX.jpg` 29장, 긴 영상 포스터 2장. 별도의 계정 커버 19장이 있으며 이를 추가 콘텐츠 19편으로 세지 않는다.
- ZIP 중첩, 원시 WAV, ASR JSON, 실행 환경, 생성 로그 0개. 중복 이름, Windows 대소문자/정규화 충돌, 한글 이름의 UTF-8 플래그 누락 0개.
- 출고목록에 기록된 9개 영상의 `exportSha256`가 독립 검토한 최종 MP4 지문과 전부 일치한다.

이 절은 이름과 출고목록 및 ZIP 파일 자체 지문 확인이다. 독립 검토자가 ZIP 멤버 내용을 전량 재해시하거나 추출 후 모든 페이지를 브라우저에서 열었다는 판정은 아니다. A의 실제 재개봉·추출 검증과 루트의 사용자용 열기 확인은 각각 수행 증거로 구분한다. 공개 게시·계정 생성·웹 배포는 실행하지 않았다.
