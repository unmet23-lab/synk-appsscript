# 휴대용 ZIP 출고 도구 — 준비 검증

## 결과와 소유 범위

[출고도구.py](출고도구.py)를 작성했다. 이번 후속 작업에서 수정한 파일은 이 도구와 이 기록뿐이다. 원고·HTML 원본·제작물·계정·원격 파일을 수정하지 않았고, 커밋·push·외부 게시를 하지 않았다.

기본 실행은 파일을 쓰지 않는 dry-run(출고 예정 목록과 결함 확인)이다. 실제 생성은 ROOT가 영상 9개와 웹 QA를 마친 뒤 `--출고`를 명시해 실행한다. 이전 완료 기록이나 파일 존재만으로 실제 출고를 수행하지 않는다.

```text
python docs/홍보물/마케팅실행_20260909/출고도구.py --dry-run
python docs/홍보물/마케팅실행_20260909/출고도구.py --dry-run --list

# ROOT의 최종 출고 요청 뒤에만
python docs/홍보물/마케팅실행_20260909/출고도구.py --출고
```

## 출력 위치와 내용

- 계정별 ZIP: 이 패키지의 `packages/<19개 계정 id>.zip`.
- 전체 ZIP: 패키지 폴더 바깥의 `docs/홍보물/마케팅실행_20260909_업로드꾸러미.zip`.
- 개별 ZIP은 해당 계정의 업로드 JPG·영상·자막·제목·문안·대체텍스트·답변·안내와 관련 PDF·편집 MD를 담는다. MD가 다른 실습 MD로 이어지면 그 의존 파일도 포함한다. 전체 사이트를 계정 수만큼 복제하지 않는다.
- 전체 ZIP은 모아보기·계정 페이지·카드 화면·현재 참조 자산·CSS·실습 6종 HTML/PDF/MD/작성 화면·후속 도움·브랜드 사용 안내와 배치 PNG·정밀 SVG 2종·3840px 원본 PNG 2종·실행 적용·공개 수업 재생 파일과 실제 장면 표지 2종을 담는다.
- 승인 배치명세의 PNG 8종은 모두 포함하고 지문도 대조한다. 사용 안내 화면이 실제 표시하는 배경 확인 PNG는 웹 의존물로 포함한다. 내부 검수 화면 폴더 전체를 넣는 것이 아니다.

현재 폴더를 통째로 재귀 압축하지 않는다. 원고의 19개 계정과 제공자료 6종·승인 PNG 8종, 공개 경로 목록 및 실제 웹 연결이 파일 선택 기준이다. `assets`도 필요 파일만 선택한다.

## 휴대판 변환과 제외

전체 ZIP 안에 계정 ZIP 19개를 다시 넣지 않는다. 로컬 모아보기 HTML의 `packages/<id>.zip` 다운로드 `<a>`만 압축용 사본에서 제거한다. 계정 페이지 링크·실습 링크·본문·다른 버튼은 보존한다. 원본 HTML을 고치지 않는다. BOM이 있는 원본의 BOM도 유지한다.

출고 바이트가 달라지는 HTML은 원본 SHA-256와 변환 후 SHA-256를 각각 출고목록에 기록한다. 나머지 파일은 원본 바이트를 그대로 넣는다. ZIP 다운로드 버튼이 아닌 다른 파일 연결에 문제가 있으면 조용히 링크를 지우지 않고 출고를 거부한다.

제외: master PNG, 사진형 생성 원본, 원시 job JSON, 생성 prompt, `_runtime`, node_modules, 원천 `.source.wav`, ASR 원시 JSON, 내부 검수 스크린샷, 제작 스크립트, A/B 검토안, 그 밖의 관련 없는 미커밋 파일. `_검토/업로드조건.md`는 모아보기에서 실제 사용하는 공개 안내이므로 이 파일만 예외다.

ROOT의 최종 수록 지시에 따라 `브랜드킷/SYNK-Ink-정밀.svg`, `브랜드킷/SYNK-Paper-정밀.svg` 및 고해상도 인수용 `브랜드킷/SYNK-Ink.png`, `브랜드킷/SYNK-Paper.png`를 필수 수록한다. `공개수업/영상제작범위_읽어주세요.md`는 청취 확인 구간과 제작·게시 경계에 필요한 공개 안내이므로 이름의 ‘제작’ 제외 규칙보다 우선해 포함한다. 실제 영상 장면에서 추출하는 `공개수업/표지.jpg`, `공개수업/클리닉-표지.jpg`도 필수다. 다른 생성 원본이나 제작 기록은 자동 포함하지 않는다.

`제공자료/읽어주세요.md`는 A안·생성기·JSON 같은 내부 제작 링크를 포함하므로 기본 출고하지 않는다. 패키지 루트의 최종 `읽어주세요.md`를 출고 안내로 사용한다. 정밀 master 실물과 원천 음성은 원래 폴더에 보존한다.

## 거부 조건과 실제 출고 순서

1. 계정 19개·자료 6종·브랜드 PNG 8종 계약을 읽고 선택 파일·의존 파일을 정한다.
2. HTML/CSS/MD/SVG와 정적 fetch/import 참조에서 로컬 연결을 따라간다. 꾸러미 바깥 파일·제외된 내부 파일·누락 파일·절대 파일 경로가 있으면 거부한다.
3. 01·03·04·05·06·07·09 계정 영상과 본수업·클리닉, 총 9개 MP4가 존재하고 ffprobe로 재생 길이와 영상 스트림을 읽을 수 있어야 한다. 재생 길이/존재 검사가 화면·음성 내용 QA를 대신하지 않는다.
4. 의도한 출력 폴더 안의 새 임시 출고 경로에서 ZIP 20개를 만든다. 기존 완성 ZIP은 아직 교체하지 않는다.
5. 모든 ZIP을 다시 열어 항목 이름·중복·Windows 대소문자 충돌·경로 탈출·한국어 이름의 UTF-8 플래그·각 파일 SHA-256를 전량 대조한다.
6. 재개봉한 ZIP의 실제 HTML/CSS/MD 바이트에서도 로컬 연결 대상이 ZIP 안에 있는지 확인한다. 각 ZIP의 `출고목록.json`도 별도 해시로 대조한다.
7. 제작 원본이 도중에 바뀌지 않았는지 다시 확인한 뒤에만 지정 ZIP 위치로 옮긴다. 이 기록의 마지막에 실제 출고 시각·ZIP 항목 수·바이트·SHA-256를 남긴다.

전체 ZIP은 패키지 폴더 바깥에 있고, packages 폴더도 수록 경로가 아니다. 자기 자신이나 이전 ZIP을 다시 품는 구조를 사용하지 않는다. 임시 폴더의 정리 대상은 새로 만든 명시적 경로를 확인하며, 사용자 폴더를 재귀 삭제하지 않는다.

## 지금 실제 확인한 것

AST 구문 검사와 순수 함수 검사를 실제 실행했다. ZIP을 메모리나 디스크에 시험 생성하지도 않았다.

- 다운로드 앵커만 제거하고 다른 계정/전체 링크를 유지하는 예시 통과.
- BOM 보존, 한국어 percent-encoded 로컬 경로 복원 통과.
- 패키지 바깥 상대 경로·file URL·루트 절대 경로 3종 거부 확인.
- master·job·prompt·원천 WAV·ASR·실행 환경·검수 화면·제작 코드 등 제외 12종 확인.
- 공개 페이지·MP4·업로드 JPG·PDF·실습 HTML·배치 PNG 허용 6종 확인.
- 파일 목록 dry-run에서 오래된 `assets/labpage.webp`, `pulsepage.webp`, `shiftpage.webp`, `stitch.webp`와 master·원천 WAV·job·runtime이 수록 목록에 없음을 확인했다. 새 `labpage-neutral.webp`를 사용한다.
- 독립 담당은 도구 전량을 읽고 차단 결함이 없다고 보고했다. 별도 순수 함수 검사 17개를 실행했으며, 최종 필수 수록 예외 추가 후 작성 담당도 같은 검사 17개를 다시 실행해 통과했다. 이 검사는 ZIP 쓰기 함수를 실행하지 않았다.

마지막 준비 점검 시점의 수록 예정은 290개, 존재하는 선택 파일 합계는 177,535,551바이트였다. 이는 **아직 완성되지 않은 영상과 표지가 있는 시점의 계획값**이며 최종 ZIP 파일 수·크기가 아니다. 최종 실행은 현재 폴더를 다시 읽으므로 뒤에 완성하는 파일도 반영한다.

### 두 단계 실행과 원본 보존 확인

ROOT의 최종 실행 요청을 받은 뒤 실제로 다음을 수행했다. 실행 기준 HEAD는 `446b27e247f620301b497dfaf3f8cfc87cbc84b3`이며, 원고·영상·갤러리 동결 통보 뒤 출고했다.

1. 첫 `--출고`: ZIP 20개 전부 UTF-8 이름·각 항목 SHA-256·재개봉 로컬 링크 검사 통과. 첫 전체 ZIP은 293항목, 242,588,737바이트, SHA-256 `886a93ce1116c871e47e068fdf7ddae39f5d4d3f43d0ec3d881d8c0b81d1a306`이었다.
2. 기존 Node 런타임의 `NODE_PATH`로 `만들기.cjs`를 옵션 없이 실행했다. 기존 카드·PDF·영상의 재렌더는 하지 않았다. 첫 ZIP의 원본 지문과 비교해 최종 바이트가 달라진 파일은 `index.html` 하나였으며, 계정별 ZIP 버튼 19개가 추가됐다. 그 밖의 선택 파일은 불변이었다.
3. 두 번째 `--출고`: ZIP 20개를 새로 만들고 모두 재개봉 검증했다. 로컬 갤러리의 버튼 19개는 그대로 두고, 전체 ZIP용 HTML 사본에서 해당 버튼만 19개 제거했다. 최종 ZIP은 위 표의 지문이며 첫 출고판을 대체했다. 두 실행 모두 원천 변경 감지·검증 실패 없이 끝났다.

여기서 ‘원본 HTML은 수정하지 않음’은 **출고 도구의 휴대판 변환**을 뜻한다. 별도로 승인된 2단계 prepare가 로컬 갤러리에 다운로드 버튼을 생성한 사실과 구분한다. 코드·원고를 직접 고치거나 커밋·push·외부 전송하지 않았다.
