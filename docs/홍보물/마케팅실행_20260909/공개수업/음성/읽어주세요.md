## 현재 사용할 파일

- 본수업: [음성명세.json](음성명세.json)의 18장. 현재 말하기 합계 577.44초, 원고의 실습 정지 합계 37초입니다. 전환 여유를 제외하면 10분 14.44초이며 13분에 맞추려고 불필요하게 늘리지 않습니다.
- 클리닉: [클리닉_음성명세.json](클리닉_음성명세.json)의 5장. 말하기 합계 80.72초입니다. 실제 영상 길이는 제작자가 실습·전환 여유와 함께 정합니다.
- 목소리 샘플: [sample-kevin.mp3](sample-kevin.mp3), 14.8초. 본수업과 동일한 프리셋의 별도 시험 원고이며 본수업 첫 장을 대신하지 않습니다.

각 명세의 `wavFile`은 영상용 정상 WAV, `file`은 MP3 파생, `originalFile`은 서비스에서 받은 원천 WAV입니다. **현재 본수업 01은 `chapter-01-r2.wav`입니다.** 단순 파일명 나열로 이전 `chapter-01.wav`를 다시 선택하지 마세요.

## 무엇을 만들었나요

Higgsfield의 `qwen_audio_tts`, 한국어 `ko`, 기본 제공 목소리 Kevin을 사용했습니다. 사용자 목소리 복제·사칭이 아니며 새로운 목소리 모델을 학습하지 않았습니다. 실제 사용한 프리셋과 원고·입력 해시는 각 작업 명세에 있습니다. 기존 보유 크레딧으로 제작했고 신규 구독·결제·충전을 하지 않았습니다.

서비스 생성물은 샘플 1개, 본수업 최초 18개, 첫 장 발음 표기 개정 1개, 클리닉 5개입니다. 총 생성 파일 25개 중 현재 영상 활성 파일은 본수업 18개와 클리닉 5개, 합계 23개입니다. 샘플과 이전 첫 장은 성과나 추가 수업으로 세지 않습니다.

첫 장의 원고만 B 담당과 동기화하여 `SYNK SHIFT의`를 말하기용 `싱크 시프트의`로 바꿨습니다. 영상의 브랜드 로고와 사업 이름은 변경하지 않았습니다. 이 개정 전후 파일은 별도 이름으로 보존했습니다.

## WAV 원천과 정상본의 차이

서비스의 WAV 원천에는 전체 길이가 미정인 스트리밍식 헤더가 들어 있어 ffmpeg가 길이/패킷 경고를 냈습니다. 원천은 `.source.wav`로 보존하고, 영상용 `.wav`에는 정상 헤더를 붙였습니다. PCM(실제 소리 샘플) 바이트를 전량 비교해 같음을 확인했습니다. 음색·속도·소리 내용을 고친 것이 아닙니다.

정상 WAV는 PCM 16비트·24kHz·모노입니다. MP3는 이 정상 WAV에서 만든 파생본입니다. 원천 파일과 정상본·MP3의 SHA-256이 명세에 따로 있습니다.

## 실제 검사와 확인하지 못한 것

[음성기술검증.json](음성기술검증.json)은 현재 활성 23클립의 원고 해시, PCM 보존, 엄격 WAV 디코드, 재생 길이, 음량, 전사 입력 해시, 단어 시간 범위를 확인합니다. 영상 자막용 단어 시간 1,284개를 얻었습니다. 이 수치는 낱말을 사람이 정확히 들었다는 인증이 아닙니다.

로컬 CPU에서 이미 보관된 faster-whisper-small 모델을 실행했습니다. 외부로 오디오를 보내지 않았고, 예상 대본을 인식기에 힌트로 주지 않았습니다. 파일별 전사·단어 시작/끝 시각은 `전사-01.json`부터 `전사-18.json`, `전사-클리닉01.json`부터 `전사-클리닉05.json`에 있습니다. [로컬전사명세.json](로컬전사명세.json)과 [클리닉_로컬전사명세.json](클리닉_로컬전사명세.json)이 목록입니다.

단어 시각은 오디오에서 인식기가 추정한 값이며 사람이 일일이 맞춘 정렬이 아닙니다. 구현은 [faster-whisper 공식 사용 안내](https://github.com/SYSTRAN/faster-whisper)의 로컬 모델과 단어 시각 기능을 따랐습니다. 전사 문자 유사도는 음질·억양·학습 효과 점수가 아닙니다.

이 환경은 오디오 입력을 직접 듣는 기능을 지원하지 않습니다. 따라서 **청취 합격·사람 원어민 감수·억양 승인**을 표시하지 않습니다. 공식 Higgsfield Speech to Text도 모델 스키마는 보였지만 CLI가 `data` 타입 생성을 지원하지 않아 제출 전 실패했으며, 이를 성공한 전사로 기록하지 않았습니다. 실제 전사는 로컬 Whisper로 수행했습니다.

## 대본과 전사에서 확인한 차이

첫 장 개정본은 공백·문장부호를 제외한 문자 대조에서 대본과 일치했습니다. 18장과 클리닉 5장의 전사 차이를 읽어 가상 예시 표시, 성과 비보장, 실제 제공 범위, 개인정보 불필요, 사람이 원자료와 대조한다는 핵심 명제가 빠지지 않았는지 확인했습니다. 대본과 전사의 텍스트 비교이며 소리를 직접 듣고 확인했다는 뜻은 아닙니다.

남은 차이에는 `의/에`, `개/계`, `세/3`, `바꾸어/바꿔`처럼 발음·숫자 표기와 인식에 영향을 받는 것이 있습니다. 특히 본수업 04의 `첫 칸은→척하는`, 08의 `세 칸→색한`, 13의 `세 줄을→3주를`, 클리닉 02의 `초안은→초화는`은 청취로 재확인할 후보입니다. 실제 음성 오류인지 ASR 오류인지 이 비교만으로 단정하지 않습니다.

영상 자막은 승인 대본을 기준으로 쓰고, ASR의 잘못 인식된 철자를 그대로 정본으로 승격하지 않습니다. 숫자 ‘세 줄’을 ‘3주’로 바꾸어 표시하면 의미가 달라집니다. 인식된 시간은 참고하되 자막의 단어는 대본과 맞춥니다.

음량은 활성 파일 기준 RMS -15.91~-16.67dBFS입니다. 최대 크기의 표본은 본수업 15에 2개, 클리닉 04에 1개 있었습니다. ‘클리핑이 전혀 없다’고 보고하지 않습니다. 영상 인코딩에서는 소리의 여유 폭을 두고 최종 결과를 따로 확인합니다. 원천 소리는 그대로 보존합니다.

## 다시 만들거나 확인할 때

`음성만들기.cjs --sample`, `--chapters`, `--clinic`은 공식 CLI를 사용하는 생성 명령입니다. 기존 명세와 원고가 같으면 파일을 재사용하고, 같은 이름에서 원고가 바뀌면 조용히 덮어쓰지 않고 중단합니다. 현재 첫 장은 `--revision-01`이라는 명시적 개정 경로로 만들었습니다. 무심코 생성 명령을 반복하지 말고 현재 파일과 해시를 먼저 확인하세요.

`_runtime/Scripts/python.exe 로컬전사.py`는 본수업, `--clinic`은 클리닉, `--sample`은 샘플 전사입니다. 모델은 기존 로컬 캐시만 읽고, 결과 오디오 해시가 같으면 이미 완료한 전사를 재사용합니다. `node 음성검증.cjs`는 현재 활성 23클립을 대조합니다.

`_runtime/`은 전용 실행 환경이며 납품 ZIP·일반 독자 자료·저장소 커밋에서 제외합니다. `*-job.json`은 원고·모델·생성 파일의 기술 명세이지 독자용 교재가 아닙니다. 원시 응답 전체·계정 이메일·토큰·서명 URL은 이 명세에 보관하지 않았습니다. 이전 첫 장은 보존 파일이고 현재 활성 명세에 선택되지 않습니다.
