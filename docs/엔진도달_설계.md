# 엔진 도달 — 수집에서 실제 도움까지 v2.1

> 2026-09-13 · [철학 §2](SYNK_철학.md#2-맡은-목적의-마지막-단계까지-완성한다)에 맞춰 현재 요구와 코드 확인을 압축했다. 수집·개인화 기능은 **모였나 → 닿았나 → 달라졌나 → 누구에게**를 각각 확인한다. 홍보·안내·감상 전체에 수집을 강제하지 않는다. 필드·값목록은 [수집·교정 계약](../계약/수집_교정_계약.json), 상세 물리·API는 talk L0·C0 계약이 정한다.
## 1. 완성의 기준

수집한 원본이 자동으로 소비되고 약속한 과제·답장·도움에 실제 변화를 만들어야 한다. 저장소나 화면에서 행을 확인한 것만으로 엔진이 배웠다고 하지 않는다. 내부 운영을 개선하기 위한 기록은 운영자에게 돌아가는 실제 변화로 확인하고, 학생에게 주기로 한 도움을 내부 집계로 대신하지 않는다.

사람이 하는 판단과 시스템이 하는 전달을 구분한다. 교정 검수와 회사 훈련 승격 의사는 다른 판단이다. 검수 문(`functions/review`)은 교정 판정과 `promotion_intent`를 함께 기록할 수 있으나 강사 골든 문(`functions/teach`)의 확인을 훈련 승격으로 읽지 않는다. 사람의 승격 의사 뒤 산출물 생성·적재·계보 연결은 자동화 대상이다.

### 2-1. Apps Script 시트와 평가 자료

시트도 범위 안이다. `hw_feedback`·`quiz_log`·`talk_log`·`voice_log` 등 원본은 제품 소비자와 §8 장부를 함께 확인한다. 시트 제품 안에서 다음 첨삭·출제가 바뀌는 경로와 talk·회사 훈련에 연결되는 경로는 다르다.

`teacher_gold` → `골든픽스처_` → talk 평가 자료의 현재 통로는 사람이 실행하는 외부 발행이다. 이를 일반 자동 배치에 넣어 훈련 승격과 합치지 않는다. 필드 삭제만으로 문장 내부까지 비식별됐다고 보지 않고, 실제 학생 원문이 공개 저장소나 외부 입력에 나가기 전 현행 반출 규격을 확인한다. 통로 변경은 최신 요청의 권한과 용도·동의·평가 분리를 기준으로 판단한다.

## 3. 개인 서비스와 회사 훈련을 가른다

### 경로 A — 개인 서비스

학생의 데이터를 그 학생의 학습·개인화에 쓰는 경로다. 현재 동의 범위에서 사용하며 회사 훈련 승격을 선행 조건으로 붙이지 않는다.

- **입력:** 필드는 수집 계약, 사건→부품은 talk `lib/이벤트검증.js`, 실제 소비는 `lib/학습자상태.js`·`lib/성과회수.js` 등 실행 코드를 따른다.
- **계산:** 과거 개입의 상태는 `as_of ≤ intervention.delivered.occurred_at`로 자르고 늦은 적재도 고려한다. 미래 정보를 섞어 당시 선택을 정당화하지 않는다.
- **개입 기록:** 생산자가 `estimator_version`·`policy_ver`·`evidence_refs`·`estimator_confidence`와 `intervention_id`를 기록한다. 배정은 원 개입의 고리를 통해 상태를 참조할 수 있다([Temper 규격](Temper_개입로그_규격_v1.md)).
- **후속 관측:** `content.viewed.parent_event_id`와 후속 수행을 연결한다. 실제 창·관측·미도래 규칙은 talk `lib/성과회수.js`가 정한다.

### 경로 B — 회사 훈련·평가

```text
사람 검수와 별도 승격 의사
→ 비식별 불변 산출물 생성(redaction_ver·content_hash)
→ 산출물 저장 성공 뒤 data_use.granted
→ 훈련·평가 분리 데이터셋 조립
→ 소비 작업의 dataset_ver·model·eval 계보 기록
```

실행 자리는 talk `functions/review` 확정 뒷단이다. `promotion_intent=true`만으로 승격 완료로 세지 않는다. 비식별 규칙·산출물 저장·사건 발행·소비·철회가 함께 구현되어야 한다.

승격은 원본 `event_id`, `artifact_ref`, `content_hash`, `serializer_ver`, `redaction_ver`, 목적, 동의 근거와 확인 시각, 라벨 출처, 승인자·시각, `dataset_ver`를 연결한다. 전사·교정 텍스트 칸 자체가 비식별인 것은 아니다. 별도의 비식별 산출물만 해당 반출 대상으로 다룬다.

현재 승격 계약(talk `docs/발주_수집파이프라인.md` §4): 원본 `event_id`당 승격 한 번, 재판정은 미승격 항목에만 허용, 훈련/평가 분리는 학생·문항 계보의 묶음 단위다. 검수자가 train/eval을 골라 같은 원본이 양쪽에 들어가게 만들지 않는다. 실패 사유를 남기고 `data_use.revoked`를 원본·산출물·데이터셋·모델 계보에 전파한다.

### 3-1. 축별 용도

| 축 | 개인 서비스 | 회사 훈련·평가 |
|---|---|---|
| 음성·글 | 발음·교정·난이도·다음 과제 | 허용된 원문↔교정 쌍과 원본 참조·전사·세그먼트·수집 맥락. 원본 음성은 승인 통로 별도 |
| 성향·습관 | 학생에게 맞는 도움 | 개인 성향을 그대로 반출하지 않고 허용된 비식별 집계 사용 |
| 개입-효과 | 어떤 도움이 통했나 | 경로 B의 승격·평가 분리·철회 그대로 적용 |

### 3-2. 마감과 분모

`due_at`·`due_ver`는 이미 계약에 있는 당시 마감과 규칙판이다. 물리는 배정의 `submissions` 행, 제출률 분모는 `task.assigned` 사건을 따른다. `daily_activity.expected`는 파생 캐시이며 분모 원천으로 바꾸지 않는다. 과거 마감을 현재 시간표로 지어 채우지 않는다.

## 4. 기존 도달 검사

앱 사건의 생산자와 소비자 목록은 talk `lib/이벤트검증.js`에 둔다. 도달값은 `{도달: [{경로, 부품, 소비자}, …]}` 또는 미구현 사유다. 실제 사건 목록과 수는 계약과 코드에서 읽는다.

### 4-1. 검사가 확인하는 범위

기존 검사는 생산자가 선 사건의 소비자 누락, 지목한 파일·부품의 부재, 기존 미도달 증가를 잡는다. 파일 문자열 검사를 통과했다는 사실만으로 실제 런타임 호출·출력 변화·수신까지 확인된 것은 아니다. 새 중앙 장부·훅·검사 관문을 이 문서에서 추가하지 않는다.

## 5. 계기판 — 단계별 계수

수집→처리→검수→승격→산출물→실제 소비를 고유 원본 사건 수와 지연, 분모로 구분한다. 학생×축 상태와 승격 건수를 하나의 비율로 나누지 않는다.

현재 talk `tools/성과계기판.js`는 개입→후속 관측과 승격 의사 대비 실제 발행의 격차를 계산한다. 그때의 16/0 같은 측정치를 현재 운영값으로 적지 않는다. 나머지 단계의 계수 존재와 실제 입력도 확인해야 한다. 기록을 읽어 표시한 것·내부 판단 변화·학생에게 돌아간 변화를 구분한다.

## 6. 개발을 막던 과거 조건

E0 코드 0줄, 학생이 없어서 소비자를 만들 수 없다는 조건, 파생 상태를 저장하는 기술의 영구 금지, 특정 모델·검색 방식 금지는 제거했다. 합성 입력으로 저장·소비·출력 변화를 먼저 확인할 수 있다. 실제 효과와 품질 문턱은 실제 자료로 따로 검증한다.

현재 계약의 데이터·동의·평가 분리와 명시적 범위는 유지한다. 이미 승인된 다음 단계에 과거 선택지를 다시 질문으로 붙이지 않는다.

## 7. 시트 이관

시트 원본을 이관할 때는 버전 관리된 어댑터와 계약된 서버 쓰기 통로를 사용한다. 원본 식별 고리·결정론적 멱등키·import manifest로 중복·누락·원천 대조가 가능해야 한다.

과거 행에 없는 `correlation_id`·`task_snapshot`을 지어 넣지 않는다. 서버 전용 이관 표기와 manifest의 결측 사유를 사용하고, 앱 입력의 우회로로 열지 않는다. 이관 행을 제출률·리듬 분모에 포함할지는 소비자가 명시하며 기본은 제외다. 이관용 예외는 해당 이관 범위에 한정한다. 새 데이터의 필수 계약을 느슨하게 만들지 않는다.

## 8. 시트층 — 코드에서 현재 연결을 읽는다

정본 = `엔진_셋업확장.js`의 `수집장부탭_()`·`수집도달_()`·`시트도달상한_()`. 검사·파생 = `tools/lib/시트도달.js`, 화면 = `tools/이해대장.js`.

09-13 로컬 도구 재측정: 전체 31종 = 제품 22 + 자산 4 + 미도달 5, 손 통로 2, 위반 0. 미도달은 `상담로그`·`voice_labels`·`voice_delivery`·`self_declare_log`·`consent_log`, 손 통로는 `teacher_gold`·`talk_index_log`다. 이는 코드 연결 목록의 판정이며 실제 학생 수·라이브 실행·효과 측정값이 아니다. 후속 작업은 도구로 다시 읽는다.

### 8-1. 발화 기회 → 조 편성

`talk_index_log`는 `assignGroups`가 조 편성 입력으로 읽는다. 원신호 횟수와 지수 비율의 방향·분모를 구분하며 미측정 시 기본 경로를 표시한다. 현재 메뉴 실행은 손 통로다. 관련 행동 검증 = `tests/발화퀄리티.test.js`.

### 8-2. 퀴즈 응답 → 다음 퀴즈

`퀴즈오답맵_` → `aiStudioBatch_`가 오답·찍어서 맞힘을 재출제 재료로 쓴다. 판정보류를 오답으로 만들지 않고 문항 스냅샷 누락을 별도로 센다. 강사 메모를 밀어내지 않도록 입력의 실제 소비 순서를 유지한다. 관련 검증 = `tests/퀴즈재출제.test.js`.

### 8-3. 음성 → 문법 관측

`masteryFromVoice_`는 전사 완료 시각을 기준으로 새 전사문을 읽는다. 실패 지점·같은 시각 묶음·재시도에서 누락이나 중복 근거를 만들지 않는다. 옛 음성 단독 도달 금지는 08-27 변경됐으며 현재 판정은 `교재연동.js`와 계약을 따른다. 전사가 학생 발화를 고칠 가능성과 발음 측정의 별도 원신호는 유지한다. 관련 검증 = `tests/말하기문법판정.test.js`.

### 8-4. 대화 → 자발적 문법 관측

`masteryFromTalk_`는 대화 원문을 읽어 문법 기록을 바꾼다. 직전 답장의 모방을 독립 습득으로 세지 않는 현재 판정과 포인터·재시도 규칙을 유지한다. 대화 이력을 읽는 것만으로 다음 도움의 효과가 확인됐다고 하지 않는다. 관련 검증 = `tests/대화문법판정.test.js`.

### 8-5. 퇴소 이력 → 복귀 학생의 재료

`복귀창_`은 복귀한 학생의 과거 약점·오답 창을 넓힌다. 현재 기록도 함께 읽고 너무 오래된 자료의 한계는 코드에서 관리한다. 이탈·결석을 학생 질책의 소재로 사용하지 않는다. 관련 검증 = `tests/복귀재료창.test.js`.

### 8-6. 성취 → 근거 있는 응원

`성취맵_` → `aiStudioBatch_`는 학생 자신의 성취를 응원 근거로 쓴다. 다른 학생과의 순위에서 나온 업적은 학생 문안 재료에서 제외한다. 명칭·뜻은 생산 상수를 공유하고 “그때는 했는데 지금은”이라는 질책으로 바꾸지 않는다. 관련 검증 = `tests/성취도달.test.js`.

### 8-7. 연결표와 수혜자

도달 행의 소비자·층·손 여부·회수 주기·대장 칸·수신자는 같은 코드 목록에서 파생한다. 실제 도는 주기와 누구에게 무엇이 달라지는지를 해당 흐름에서 확인한다. 표시용 문서를 보고 신규 수집이나 수혜자를 지어내지 않는다.

## 8-0. 분모와 원본 보호

수집 표식은 원본 성질과 실제 삭제·아카이브 경로를 보고 정한다. 파생 캐시·게임 상태·사람이 고치는 원장을 모두 append-only 수집으로 취급하지 않는다. 정당한 철회·아카이브는 원본 규격과 기존 기준선 갱신을 함께 따른다.

기존 래칫은 같은 분모에서 미도달을 가리려고 상한을 올리는 일을 잡는다. 수집 범위가 바뀌면 원천·소비자·미도달 사유를 함께 대조한다. 검사 통과를 실제 개선 증거로 대신하지 않는다.

이전 상세 구현 경위와 과거 수치는 [정리 전 고정판](https://github.com/unmet23-lab/synk-appsscript/blob/f657502b1c85/docs/엔진도달_설계.md)에 보존되어 있다.
