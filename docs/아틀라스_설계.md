# SYNK Atlas — 경험과 환경에 맞춰 발전하는 구조

> 2026-09-18 사용자 채택. 기존 시스템에 경험·환경 변화와 결과의 되먹임을 연결한다. LAB의 실제 경험을 먼저 완성하며, 다른 사업에 초개인화를 억지로 확대하지 않는다. 이 문서는 현재 재설계 원천이고 구현·배포·효과는 아래 상태에서 구분한다.

## 1. 목적과 적용 범위

아틀라스는 사람의 경험과 현재 조건을 이해하고, 그 사람이 선택한 방향에 맞춰 다음 경험을 조정하며, 결과로 다음 판단을 개선하는 공통 기술 구조다. 모르는 것을 고정 성향으로 만들지 않고, 사용자가 이해·목표·반영 범위를 고칠 수 있게 한다.

일곱 엔진을 모든 제품에 동시에 붙이는 제품 규격이 아니다. 기능이 필요한 실제 경험과 그 기능으로 바뀔 결과물이 먼저 있어야 한다.

| 사업 | 현재 재설계 적용 | 확장할 때의 조건 |
|---|---|---|
| LAB | 학습·게임·대화의 반복 경험을 중심으로 개인화 전체 흐름을 발전시킨다. 첫 구현은 교수 편지 게임 | 실제 기록과 도움의 결과가 다음 경험에 이어지고 사용자가 수정할 수 있어야 한다 |
| SHIFT | 필요한 제작·표현·지식 부품을 선택해 쓴다. 고객별 장기 기억이나 학생 모델을 기본으로 붙이지 않는다 | 반복 교육·장기간 쓰는 업무 도구 등 지속 사용이 있는 상품에서 필요와 수혜를 확인한다 |
| PULSE | 작품과 감상 자체의 완성도. Loom·Reed 등 필요한 제작·표현 기능을 쓴다 | 상호작용 작품에는 그 작품의 선택 상태를 쓸 수 있다. 개인 청취 추적·장기 감정 프로필로 확대하지 않는다 |
| PATH | 지원 서비스와 실제 준비 흐름을 먼저 구체화한다. 현 단계의 엔진 연결을 완료로 소개하지 않는다 | 장기 준비를 실제로 동행할 때 목표·조건·준비 변화와 기관 조건 갱신에 따라 계획을 조정한다 |

공통 기술 보유와 사업별 사용 여부는 별개다. LAB에서 검증된 기능을 가져갈 수는 있지만 공통화 자체를 다른 사업의 첫 제품 목표로 삼지 않는다. 사업 사이의 원본·프로필 자동 공유는 하지 않는다.

## 2. 두 가지 발전

**개인에게 적응:** 새 목표·환경·경험 → 현재 이해 갱신 → 다음 경험 선택 → 실제 제공 → 결과 확인 → 다음 선택.

**방법을 개선:** 허용된 여러 사례 → 비교 가능한 평가 → 새 후보 방법 → 기존 방법과 비교 → 검증한 변경 적용. 개인 응답 한 번을 보편적 효과나 모델 훈련 완료로 승격하지 않는다.

이 두 흐름은 별개다. 첫 구현의 선택 규칙은 판을 가진 결정론적 코드다. 사용자의 설정과 명시적 응답이 다음 선택에 반영되지만 가중치 자동 학습·모델 재훈련·인과 효과 검증을 구현했다고 뜻하지 않는다.

## 3. 이해의 구조

| 재료 | 조건 |
|---|---|
| 목표·선택 | 사용자 선언과 시스템 추천을 구분한다. 탐색 중도 유효한 상태다 |
| 경험·수행 | 해 본 것·혼자 수행한 것·도움을 받은 것을 구분한다. 완료·만족을 실력으로 바꾸지 않는다 |
| 현재 환경 | 적용 범위·시각·유효기간을 둔다. 오늘의 상황을 평생 성향으로 만들지 않는다 |
| 바깥 조건 | 실제 서비스에서 필요한 기관·업무·이용 조건만 출처·확인 시점과 함께 관리한다 |
| 불확실성 | 미관측·충돌·실패·추정을 구분한다. 답이 다음 선택을 바꿀 때 필요한 질문을 한다 |

최신 선언이 만료·제외되어도 오래된 선언을 몰래 부활시키지 않는다. 발생 시각과 시스템이 알게 된 시각을 함께 잘라 과거 판단을 재현한다. 제외·철회 후의 새 계산과 당시 판단 기록은 구분한다. 원본의 보존과 삭제는 현행 데이터 계약을 따른다.

## 4. 선택과 제공

선택은 지금 가능한 경험 후보를 대상으로 한다. 먼저 시간·소리 사용 등 실제 제약으로 후보를 거른 뒤, 목표·선호·관련 결과를 반영한다. 가능한 후보가 없으면 `unavailable`을 반환한다. 가능한 척하는 폴백을 만들지 않는다.

판단에는 선택판·경험 ID·후보 스냅샷·선택한 후보·근거 참조·대안·시각을 남긴다. 제공 화면이 실제로 소비한 판단을 완료 사건과 연결한다. 사용자 설정이 바뀌면 진행 중인 글·응답 원본은 보존하고 필요한 안내와 점검만 다시 구성한다. 아직 도착하지 않은 결과·이전 설정에 대한 비동기 응답은 현재 상태를 덮지 못하게 한다.

각 경험 어댑터는 다음을 명시한다.

1. 실제로 받을 수 있는 맥락과 허용 범위.
2. 바꿀 수 있는 요소: 진행량·순서·도움·표현·후속 경험.
3. 바꾸면 안 되는 원본·문항 조건·평가 의미.
4. 어떤 사건을 완료로 볼지와 어떤 결과를 관측할 수 있는지.
5. 수정·제외·실패 시의 기본 경험.

현재 `atlas/experiences.js`는 LAB 편지 게임 전용이다. 다른 사업명을 인수로 넣어 같은 모드를 반환하지 않는다.

## 5. 엔진 책임

| 엔진 | 이 흐름에서 맡는 책임 |
|---|---|
| Core | 유효한 근거로 현재 이해와 다음 선택을 계산 |
| Trail | 경험·목표·판단·정정의 시간 관계 |
| Temper | 실제 제공과 후행 결과를 연결하고 측정 가능 여부를 구분 |
| Prism | 허용된 집계에서 다른 조건과 반복 패턴을 비교 |
| Vellum | 필요한 질문·안내·수정과 되돌림을 사용자에게 전달 |
| Loom | 화면과 장면이 선택된 경험을 실제로 표현 |
| Reed | 해당 경험에 필요한 소리와 감상 품질 |

사용하는 엔진은 경험별로 정한다. 일곱 개 사용을 완료 조건으로 세지 않는다.

## 6. 첫 구현 계약

코드 정본은 `atlas/engine.js`이며 외부 모델·네트워크·암묵적 추적이 없는 순수 모듈이다. `tools/sync-atlas.js`가 talk와 홈페이지 소비 사본을 동기화하고 `--check`로 동일성을 확인한다. 원본 계정·글·음성·학생 식별자는 이 모듈의 입력이 아니다.

사건 공통부는 schema, id, scope(domain/workspace/subject), at, recordedAt이다. 현재 사건은 `context.set`, `decision.made`, `experience.completed`, `feedback.given`, `record.excluded`다. 이는 **별도 로컬 경험 계약**이며 기존 c16 `learning_events`에 새 어휘를 보내거나 서버 계약을 몰래 확장하지 않는다.

- context는 목표·현재 시간·도움 방식·소리 사용 가능 여부를 명시적으로 받는다. 아직 전체 생활 환경을 모델링한 것은 아니다.
- 완료는 존재하는 같은 범위의 판단과 연결한다. 피드백은 같은 범위의 실제 완료에 연결한다.
- 피드백은 자기보고이며 학습 효과가 아니다. 답을 바꾸면 같은 완료에 대한 최신 답을 소비한다. 미응답은 실패가 아니다.
- 현재 피드백 참고 창은 30일이며 설계값이다. 사용자 효과로 검증된 기간을 뜻하지 않는다.
- PULSE 범위의 행동·완료 피드백으로 개인 프로필을 추정하지 않는다. 이는 PULSE 제품이 구현됐다는 뜻도 아니다.
- 앱 어댑터는 실행 중 메모리에만 두며 계정 변경·로그아웃 때 폐기한다. 이전 세션의 핸들도 무효화한다.
- 홈페이지 체험은 기본 메모리이며 본인이 선택한 경우에만 같은 브라우저에 설정·판단·완료·응답을 저장한다. 글은 저장하지 않는다. 공용 기기와 저장 실패를 안내하며 기억 끄기·전체 비우기를 제공한다.

## 7. 대표 경험의 변화

편지 게임에서 목표는 먼저 살펴볼 항목과 안내를, 짧은 시간은 한 항목부터 보는 점검을, 도움 방식은 한 번에 보는 양과 점검을 여는 시점을 바꾼다. 모든 항목은 원할 때 열 수 있다. 더 해 보고 싶다는 응답은 다음 회차의 추가 표현 탐색에, 양이 많았다는 응답은 핵심부터 보는 흐름에 반영한다.

힌트·점검은 정답 미리 채우기나 가짜 점수가 아니다. 원문과 수정본, 문항 사실, 제출·수신 상태는 보존한다. 공개 체험의 완료와 학생 앱의 실제 제출은 서로 다른 완료 의미다.
