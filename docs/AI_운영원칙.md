# SYNK AI 운영 원칙

> 2026-10-10 사용자 확정. 이 문서에는 지금 규칙만 두고, 바뀐 경과와 근거는 [결정](_ops/결정.md)에 둔다. 현재 요청이 작업 범위를 정한다. AI의 역할과 작업 방식은 이 문서에서만 관리하고, AGENTS·메모는 여기를 링크로 가리킨다.

## 역할

누가 만들고 검수하는지는 이 문서가 정한다. 모델 버전·추론 수준·생성 도구는 [현재 모델·생성 도구](AI_계정과_크레딧.md#current-ai-settings), 계정과 승인된 대체 통로는 같은 문서의 해당 절 한 곳에서 관리한다. 역할 표·AGENTS·메모에 설정값을 복제하지 않는다. 설정을 바꿀 때는 담당 원문과 실제 설정을 함께 확인하고, 확인하지 못한 모델·추론 수준을 보장했다고 보고하지 않는다.

| 일 | 만듦 | 검수 기준 |
|---|---|---|
| 백엔드(서버·API·DB·회사 서버 배포·자동화 서버) | GPT 또는 Claude | 아래 검수 판정표의 백엔드 행 |

GPT에게는 백엔드(만들기·검수)를 맡기고, 그림 생성은 Claude가 승인된 구독 통로로 부른다. 헤르메스 텔레그램 개인 대화는 Claude가 맡는다. GPT 구독은 백엔드·그림 생성용으로 유지한다.

## 검수 판정표

2026-11-13 사용자 확정. 옛 「검수를 줄이는 다섯 가지」·「검수 효율 여섯 가지」·백엔드/화면 검수의 현재 조건을 이 표와 아래 공통 절차로 합쳤다. 옛 이름으로 연결된 문서도 여기의 현재 기준을 따른다. 현재 요청에서 구체적으로 지정한 담당·모델·검토 범위가 우선한다.

**적용 순서:** 변경의 영향과 위험 → 아래 표의 해당 행 → 재검수·배포 조건 순서다. 운영 데이터·인증·권한·돈·개인정보·삭제·마이그레이션·배포/검수 관문과 학생·교사·고객 화면은 필수 검수 대상이다. 화면과 서버가 섞이면 두 행을 모두 적용한다. 내부 도구(유호님·운영자 화면 포함)·CI·시험·문서만 바꾼 일은 관련 시험과 자기 점검으로 끝내되, 앞의 위험을 바꾸거나 지우기·덮어쓰기가 있으면 해당 검수를 받는다.

**작은 수정의 예외:** 표시용 오타·띄어쓰기 등 동작과 의미에 영향이 없는 정적 문구 수정만 먼저 반영하고 그 작업 끝 검수에 모을 수 있다. 수정 줄 수·파일 수·값 하나라는 이유로 분류하지 않는다. 인증·권한·돈·운영 데이터·개인정보·삭제·마이그레이션·배포/검수 관문, 실행 코드·조건·설정값·링크 목적지·사용자 동작을 바꾸는 수정은 한 줄이어도 이 예외를 쓰지 않는다. 화면의 정보·동작·접근성에 영향이 있거나 불명확하면 아래 표를 따른다.

### 재검수와 배포 후보

- P1은 사용자·운영 데이터가 정상 경로에서 밟는 기능 오류다. 운영 데이터 삭제·덮어쓰기, 인증·권한·돈·개인정보, 배포·검수 관문은 드문 입력도 P1이고 그 밖의 내부 도구·극단 입력 결함은 P2다. 재현되는 P0·P1을 고친 뒤 반영한다. P2·P3는 일반적으로 배포·공개를 막거나 재검수를 늘리는 이유가 아니며, 바로 처리할 수 없는 것은 후속으로 남긴다(그록 사슬의 예외는 표 참조).
- 다시 검수는 그 지적을 낸 검수자에게 고친 diff와 해당 지적만 한 번 보인다. 묶음을 통째로 새로 만들지 않고 P0·P1 없는 회차에서 멈춘다. 화면의 카본 P0·P1 수정은 `다시`로 카본·Fable에게 보내며, 카본은 묶음 글만 읽으므로 Fable의 실제 상태 확인 범위는 표의 파일·화면 전체를 유지한다. Fable이 낸 P0·P1은 같은 Fable에게 수정 확인을 받는다.
- 같은 곳에서 두 회차 연달아 P0·P1이면 땜질을 멈추고 설계부터 다시 본다. 같은 파일이 72시간 안에 세 회차 연달아 P0·P1이면 도구가 멈추며 Fable 설계 검토 뒤 잇는다.
- 배포 후보는 앞 공개본과 달라진 곳을 읽힌다. 검수 뒤 후보를 고쳤으면 `검수묶음.mjs 다시`로 같은 검수자에게 변경 diff와 지적을 보이고, 공개·배포 도구는 처음 검수부터 해시로 이어진 사슬 끝 후보와 최종 배포 바이트가 같은지 확인한다.
- P0·P1 없이 P2·P3만 고친 소스는 다음 판으로 넘긴다. 검수한 판을 그대로 배포하고, P2·P3 고침은 배포 뒤 올려 해당 영역의 다음 검수에 포함한다. `--함께올림`은 P0·P1 고침에 묶였거나 지금 공개본이 깨져 있을 때만 쓴다. 남의 커밋만 합쳐진 판(이 세션 고침 없음)은 `다시 --합침만`의 3방향 합침 대조로 잇고, [현장 노트](현장노트/AI_CLI.md)의 거절 조건을 지킨다.
- Fable은 남의 지적을 P0·P1 중심으로 확인하고 P2·P3는 5건까지 본다. 필수 검수를 보내지 않은 것은 한도·로그인 막힘이 아니다. 빈 답·잘못된 형식·빠진 항목·다른 입력에 대한 답·끝까지 안 읽힌 묶음의 0건은 통과로 세지 않는다. 실제 막힘 증거 없이 대체하거나 검수 증거를 요구하는 옛 관문을 우회하지 않는다. 도구의 대조 범위는 [관문·자동화](_ops/관문_자동화.md#review-gaps)다.

### 실행·보고와 기간 시험

- 검수자는 Claude가 기존 공식 통로로 직접 부른다. GPT·카본은 묶음마다 한 번씩 호출하고 묶음 나누기·보내기·입력 대조·기록·끝 보고 집계는 `node tools/검수묶음.mjs`가 한다. 유호님이 결과를 나르게 하거나 새 실행기를 만들지 않는다. 호출 모델·확인은 [현재 설정](AI_계정과_크레딧.md#current-ai-settings), 명령은 [AI CLI 현장 노트](현장노트/AI_CLI.md), Apps Script 반영은 [deploy 스킬](../.claude/skills/deploy/SKILL.md)을 따른다.
- 실제로 돈 검수만 끝 보고·트랙에 「GPT N건(반영 M)」·「카본 N건(반영 M) · Fable N건(반영 M)」·「설계 검토 Fable N건(반영 M)」으로 적는다. 대신한 검수자와 미반영 이유도 적고 P2·P3를 넘긴 것은 「후속」으로 표시한다.
- 학생·교사·고객 화면은 synk.im 공개 화면·WORLD·교사 앱·PULSE 고객 화면·계정/회원 화면·PC 앱을 포함한다. synk.im 공개 뒤에는 쪽별 기준 이미지 차이와 새 접근성(axe) 위반을 보고하고 새 치명 위반만 실패로 센다. 의도한 변경은 `node tools/공개.js 기준 --점검 <실행> <쪽…>`으로 해당 쪽만 기준을 바꾼다.
- Claude 서비스 백엔드의 카본 끝 판 추가 검수는 **2026-11-14까지의 시험이며 배포를 막는 추가 관문이 아니다.** 11-15부터 안내는 자동 중지한다. 끝 판 묶음에서 GPT가 놓친 재현 P0·P1과 추가 검수 시간을 확인해 유지 여부를 판단한다([현재 후속](_ops/트랙.md), [관문 표](_ops/관문_자동화.md)).
- 넓게 읽기·대량 치환·시험/로그 요약처럼 판단이 적은 하위 일은 Sonnet 하위 에이전트에 맡기고, 품질이 갈리는 판단·설계·화면 글·검수는 Opus·Fable을 유지한다.
- 여기 적은 것 말고 매 작업마다 두 모델 비교·승인을 더하지 않는다. 옛 고정 검수 모델·최대 추론 명령·별도 라이브 직전 절차를 필수 관문으로 되살리지 않는다. 큰 카본 검수 전에는 [계정과 크레딧](AI_계정과_크레딧.md#아르곤-계정)의 공용 몫을 확인하며 승인 밖 계정·모델·유료 경로로 대체하지 않는다.

## 모든 작업의 출발점 · 사용자 평가에 근거한 벤치마킹

GPT와 Claude 모두 **목적에 맞는 현존 최고 서비스의 장점 + SYNK의 개인화·학습 가치 → 더 나은 SYNK 콘텐츠·앱**을 공통 작업 방식으로 삼는다. 기획·구현·고도화·콘텐츠 제작에서 아래 조사를 필수로 수행하고, 그 결과로 무엇을 만들지 결정한다.

1. **목적을 먼저 확정한다.** 누구의 어떤 문제를 풀고 어떤 재미·편익·학습 경험을 줄 것인지, 이번 결과의 성공 기준을 파악한다. 목적이 같은 서비스·회사·콘텐츠와 인접 분야까지 조사 대상으로 잡는다. 생활 콘텐츠 앱이라면 교육 앱뿐 아니라 Steam 등의 생활 시뮬레이션 게임도 살핀다.
2. **현재 선도 서비스를 폭넓게 찾는다.** 조사일 기준 후보군을 훑고 이용·판매·조회 등 인기 지표와 평점·리뷰 수·최근 평가 등 만족도 지표를 함께 비교한다. 누적 인기와 최근 반응, 플랫폼·대상 사용자 차이를 구분해 목적에 맞는 최고 사례를 고른다. 유명한 회사나 익숙한 몇 개 사례만으로 결론내리지 않는다.
3. **기능과 사용자 반응의 원문을 수집한다.** 공식 제품·도움말·업데이트와 실제 사용 화면·플레이 자료에서 기능을 확인하고, 스토어 리뷰·커뮤니티·댓글의 최신 원문을 크롤링·열람한다. 검색 요약이나 회사 홍보만으로 끝내지 않는다. 반복되는 호평과 불만을 기능·사용 맥락별로 묶고, 최근 평가와 장기 평가를 대조한다. 출처 URL·확인일·평가 기간·표본 규모·선정 범위를 남긴다. 접근하지 못한 자료와 표본 조사를 전수조사로 보고하지 않는다.
4. **왜 좋은지 기능 단위로 설명한다.** ‘어떤 기능 → 어떤 사용자 경험 → 어떤 호평’인지 원문 근거와 연결한다. 흥행 규모만으로 개별 기능의 효과를 단정하지 않고, 사용자가 직접 밝힌 이유와 우리의 해석·가설을 구분한다. 불만에서는 개선 기회를 찾는다.
5. **장점에 SYNK의 색을 더해 설계·구현한다.** 가져올 장점과 바꿀 점을 정하고, 관련 Atlas 엔진의 개인화와 구체적인 학습 활동·피드백·성장 보상을 어디에 연결할지 정한다. 기능을 단순히 모으지 않고 원래 호평받은 재미·편의가 살아 있는 사용자 흐름으로 만든다. 아직 확인하지 않은 학습 효과는 가설로 둔다.
6. **실제 결과로 검증하고 갱신한다.** 벤치마킹에서 채택한 장점이 결과물에 구현됐는지 확인하고, 실제 사용·시청 반응으로 다음 개선을 정한다. 다른 AI의 작업을 이어받을 때도 조사 근거와 구현 결과를 함께 확인해 발전시킨다.

**SNS 편(10-28):** 위 2~5를 편마다 「검증된 원본 하나 → 그 뼈대(훅 자리 · 칸 수 · 박자 · 반전 · 끝 장치) + SYNK의 색」으로 한다. 여러 원본의 장점을 섞어 새 틀을 짓지 않고, 뼈대는 지키되 똑같이 베끼지 않는다(우리 색 · 그 계정에 남길 것 · 화면 짜임 · 끝 한마디는 우리 판단, [제작 절차 「오마주」](마케팅/기획장부/제작절차.md#homage)).

조사 결과는 해당 제품·콘텐츠의 기존 설계나 탐색노트에 **출처·사용자 반응 → 채택할 장점 → SYNK 적용 → 확인할 결과**로 짧게 연결한다. 별도 공통 보고서나 실행기를 늘리지 않는다. 이어 하는 수정은 기존 근거를 먼저 활용하되 최신성과 이번 변경의 관련성을 확인하고 부족한 범위를 추가 조사한다. 새 목적·핵심 기능·사용자 경험을 정할 때는 후보 조사부터 다시 수행한다.

## 공식 하네스

- 각자의 공식 앱·CLI에서 계획·도구·서브에이전트·재개·검토·예약 기능을 쓴다. 모델과 추론 설정은 그 제품의 실제 설정을 따르며 임의로 통일하거나 낮추지 않는다.
- 자체 LLM 실행기·중계·자동 모델 선택기·반복 검수기를 새로 만들지 않는다. 지금 쓰는 통로(검수 묶음·무인 실행 자격 고르기·구독 호출·GPT 손일 카드)는 공식 CLI를 한 번씩 부르는 것으로 유호님이 정한 것이고, 목록과 끄는 법은 [관문·자동화 한 장](_ops/관문_자동화.md)에 있다. 옛 자체 실행 절차와 훅을 새 작업의 선행 조건으로 되살리지 않는다.
- 스킬·커넥터·보조 도구는 필요한 것만 쓰고, 기존 기능으로 못 푸는 반복 문제와 실제 효과가 있을 때만 더한다. 제품 내부의 AI API와 학습 엔진은 작업용 하네스와 구분한다.
- 예약은 요청된 일이 있을 때만 만든다. 할 일 없이 큰 대화를 주기적으로 깨우지 않고, 단순 상태 확인은 AI 없는 조회·알림으로 한다.
- 세션 길이와 문맥 압축은 하네스에 맡긴다(2026-11-12 유호님 「내 규칙보다 난 클로드 하네스를 더 믿거든」). Claude 세션은 문맥 70만에서 하네스가 저절로 압축하고(`~/.claude/settings.json`의 `autoCompactWindow`), 쉬는 세션 압축 · 캐시는 기본값 그대로다. 문맥 길이를 까닭으로 새 세션에 넘기지 않으며, 정한 것 · 숫자 · 남은 일은 그때그때 파일에 남긴다. 결과를 기다릴 필요 없는 곁 세션은 띄운 뒤 떼고, 긴 작업 세션은 Opus로 · Fable은 검수와 판단에만 쓴다.
- 인터넷 작업(조사 열람·사이트 조작·로그인·연결 승인·게시·내려받기)은 Claude와 GPT 모두 ego(lite) 브라우저가 기본이다(2026-10-21). 에이전트는 `ego-browser` 스킬로 자기 작업 공간(Space)에서 일해 사용자 탭을 건드리지 않고, 앱 계정을 바꿔도 끊기지 않는다. 사이트 로그인도 ego에 한다. 네이버 블로그와 티스토리는 Aside(AI 브라우저)에서 한다(2026-10-26, 넣는 법은 [현장 노트](현장노트/브라우저_게시.md#asideai-브라우저)). **yuhokorean의 페이스북·인스타그램·틱톡 업로드도 Aside에서 한다**(2026-11-02 유호님 확정). 업로드 전에 대상 계정이 yuhokorean인지 확인해 기존 계정과 섞이지 않게 한다. ego에서 막힐 때만 앱 안 브라우저, 그다음 크롬(Claude in Chrome·Codex 크롬 확장, 프로필 「유호」)으로 넘어가고 까닭을 [현장 노트](현장노트/브라우저_게시.md#egolite)에 남긴다. 이 작업본 개발 서버의 미리 보기(`preview_start`)는 앱 안 브라우저 그대로이고, Edge는 쓰지 않는다.

- 네이버 관련 업로드는 Aside의 앞 세 프로필(Default·Profile 1·Profile 2)을 계정별 전용으로 사용한다(2026-11-07 유호님). CLI에서 프로필을 명시하고 실제 로그인 계정과 대상 블로그·채널을 확인한 뒤 진행한다. 계정과 프로필의 짝은 저장소에 적지 않으며, 로그인도 AI가 하고 비밀번호·인증 코드·2단계 인증 칸만 유호님이 한다(아래 「비용과 권한」, 2026-11-12).

## 같은 원문으로 이어가기

- `AGENTS.md`가 공동 입구이고 `CLAUDE.md`는 이를 가져온다. 제품 설계·코드·결과는 담당 원문 한 곳에서 고친다. 모델별 사본이나 별도 인수인계 양식을 늘리지 않는다.
- 이어받을 때 해당 원문·코드·현재 diff와 [트랙](_ops/트랙.md)의 관련 항목을 확인한다. 작업본 위치, 확인한 결과, 남은 일만 짧게 전달한다. 같은 폴더의 파일 공유가 대화·프로세스·미커밋 변경의 자동 동기화를 뜻하지는 않는다.
- 확정 내용은 담당 원문에 반영하고 [결정](_ops/결정.md)에는 근거를 남긴다. 과거 기록·메모의 역할표·말투·절차를 현재 지침으로 적용하지 않는다. 자연스러운 한국어를 사용하며 캐릭터 설정은 해당 캐릭터의 대사에만 적용한다.
- 보고나 기획에 남은 일·한계·다음 할 일을 적거나 이미 정한 듯한 것을 물으려면, 먼저 그 항목의 낱말(기능·편·도구 이름)로 결정 표를 찾는다(`rg -n "<낱말>" docs/_ops/결정.md docs/_ops/보관`). 정해진 것을 남은 일로 적거나 다시 묻지 않는다(2026-11-03).
- 다른 작업의 변경·원본을 보존한다. 동시 편집에서는 파일 범위를 확인하고, 별도 worktree의 변경은 필요한 것만 통합한다.
- 늘 읽히는 문서(AGENTS·이 문서·Claude 메모 목록)에는 지금 규칙만 둔다. 바뀐 경과·근거는 [결정](_ops/결정.md), 절차·실측은 담당 원문에 쓰고, 같은 규칙을 여러 곳에 풀어 쓰지 않고 링크로 가리킨다(2026-10-24 경량화).
- `node tools/바로올리기.js`는 그 push가 AGENTS를 11KB·이 문서를 35KB 너머로 키우거나 결정·트랙에 2KB 넘는 줄을 새로 넣으면 막지 않고 「크기 알림」을 보인다. 알림이 뜨면 경과는 결정 표로, 절차·실측은 담당 원문으로 옮겨 그 줄을 줄인다([관문·자동화 한 장](_ops/관문_자동화.md)).

## 비용과 권한

- 자격증명과 학생 식별 정보를 출력·공유하지 않는다. 신규 결제·구독·자동충전은 하지 않으며 한도·인증 문제를 다른 유료 경로로 자동 우회하지 않는다. 사용자가 정한 예외 통로(GPT 그림 굽기 보조 계정, 광고 콘티용 GPT 이미지 API(Pro 월 크레딧), 헤르메스 개인 대화의 Claude API 경로, Claude API 월 크레딧 키와 무인 작업 실행기, 헤르메스 클라우드 작업, Gemini 구독 대체)와 그 도구는 [AI 계정과 크레딧](AI_계정과_크레딧.md)에 있다.
- 개발용 구독과 제품 API 비용은 별개다. MVP의 AI 한도는 낮게 유지하고, 실제로 돈이 나가는 AI 시험·호출(충전 잔액·카드로 청구되는 키)은 실행 전 예상 비용을 알리고 승인을 받는다. 결제 수단 없는 조직의 Claude API 무료 크레딧으로만 도는 시험·호출은 돈이 아니므로 비용 때문에 묻지 않고 쓴 양만 보고한다(2026-10-21). 자동 충전이 꺼진 조직에서 GPT Pro 구독의 월 API 크레딧으로만 도는 광고 콘티 굽기도 같다(2026-10-29). 그 크레딧은 운영(talk 강사 도우미·헤르메스)과 나눠 쓰므로 큰 일괄은 나눠 보내고, 바닥나 운영이 멈출 것 같으면 먼저 말한다. 운영에서 그런 기능을 켜는 비밀값·기능 스위치 쓰기가 판정기에 막히면 그 한 줄만 여쭌다. 한도 상향도 확인한 뒤에 한다.
- 이미지는 GPT·Gemini 직접 서비스의 기존 월정액 경로를 우선하고 Higgsfield나 별도 과금 API로 임의 전환하지 않는다. 용도별 모델·생성 도구와 승인된 API 예외는 [현재 모델·생성 도구](AI_계정과_크레딧.md#current-ai-settings), 제작 방법은 [만족 사례 장부](마케팅/제작양식/만족사례_장부.md)를 따른다. 마스코트는 정본을 생김새 참고로만 넣어 장면과 한 장으로 새로 굽고 오려 얹지 않는다. 승인 얼굴·로고·원본을 보존하며, 모델 선택·확인이 안 되는 도구에서 특정 버전·추론 수준을 보장했다고 보고하지 않는다.
- Google Cloud 기본 결제 계정과 프로젝트 연결은 [돈장부](_ops/돈장부.json)의 `기본_구글클라우드_결제`에서 확인한다. 기존 서비스의 결제 이전·크레딧 종료 후 유료 전환까지 승인된 것으로 해석하지 않는다.
- **배포·공개는 맡은 작업의 마감으로 바로 한다(2026-10-21 사용자 확정).** Claude·GPT 모두 그 작업의 배포·공개(Apps Script 라이브, synk.im 공개, SYNK-talk 함수와 데이터·접근을 바꾸지 않는 마이그레이션(새 테이블·열·색인, 함수·뷰 코드), 회사 서버 릴리스와 바로 뒤 재무장, PC 앱 릴리스, 공개 저장소 push)를 따로 묻지 않는다. 그 경로의 표준 절차와 검사(시험·보안 검사·미리 보기·배포 점검·라이브 대조, 학생·교사·고객 화면과 운영 백엔드 반영은 위 검수 판정표의 화면·백엔드 행과 재검수·배포 조건까지)를 통과하면 반영하고, 끝 보고에 무엇을 어디에 올렸는지 적는다. synk.im은 `tools/공개.js`로만 올리고 synk-policy main에 직접 push하지 않으며, 공개 저장소 push는 SYNK-appsscript master·synk-tips 글·claude-session-share의 자기 작업만이다. 검사가 실패하거나 남의 미커밋이 배포물에 섞이면 승인할 일이 아니라 고칠 일이므로, 배포하지 않고 고치거나 보고한다. 매일 판 SNS 편(`docs/마케팅/<편>/게시/준비.json`에 판으로 적힌 계정·시각, 올리기 전 검사 「고칠 것」 0)은 2026-11-02부터 자체검수(장면 모아보기·음량·글·링크)를 통과하면 묻지 않고 모든 계정에 예약·게시한다(14시 「오늘 편 게시」 작업, 11-03부터 게시 뒤 고정 댓글·블로그 쇼츠 칸도). 계속 사용자에게 묻는 「정말 중요한 일」은 다음뿐이다: 그 밖의 SNS·유튜브 게시(준비.json 판에 없는 글·광고)와 이미 공개된 글의 삭제·비공개 전환·공개 전환, 메일·메시지·DM·댓글·지원사업 제출처럼 남에게 보내기, 실제로 돈이 나가는 일(결제·구독·가격표·과금 설정, 돈 주고 산 생성 크레딧의 큰 지출 — Claude API 무료 크레딧으로만 도는 호출은 돈으로 치지 않는다), 기존 데이터를 지우거나 덮는 운영 변경(DROP·TRUNCATE·DELETE·UPDATE, 열 바꾸기·이름 바꾸기처럼 데이터를 바꾸는 마이그레이션, 백업으로 덮기)과 되돌리기 어려운 삭제, 접근을 바꾸는 보안 설정(권한·GRANT·RLS 정책·방화벽·DNS·인증서·저장소 공개 범위), 공개하면 안 되는 내용(비밀값·학생 정보·미공개 특허·남의 개인정보)이 섞였을 수 있을 때. 준비·로컬 검증·실제 반영·사용자 효과를 구분하고 확인하지 않은 결과를 완료로 보고하지 않는다.
- 사용자가 꼭 보고 정해야 하는 일이 아니면 Claude가 판단해 집행하고 끝에 무엇을 왜 했는지 보고한다(2026-10-20 위임). 보안·운영 잡일(비밀값 점검과 보관, 열쇠 파일 권한, 접속이 막힌 원인 찾기, 서버·저장소 보안 패치)도 명령으로 되는 것은 사용자에게 넘기지 않는다. 사용자 손이 남는 것은 허락을 받아도 Claude가 하지 않는 일뿐이다 — 로그인·가입 화면의 비밀번호·인증 코드 입력, 휴대폰 2단계 인증, 계정 가입, 결제, 데이터 영구 삭제, 접근을 바꾸는 보안 설정(방화벽·권한 부여·2단계 인증·앱 권한 모드). 이것도 작업마다 명령 한 줄이나 클릭 한 번으로 묶어 한 번만 부탁하고 결과 확인은 Claude가 한다. **로그인 자체는 AI가 한다(2026-11-12 유호님 「앞으로 이런 로그인 전부 니가 해」).** 로그인 화면을 넘기지 않고 ego 구글 계정 고르기 · 계정 바꾸기 · CLI 로그인 주소까지 AI가 끝낸다. 유호님 손은 비밀번호·인증 코드·2단계 인증·CAPTCHA 칸이 실제로 뜨거나 처음 보는 앱이 새 권한을 달라고 할 때 그 한 칸뿐이다([방법](현장노트/브라우저_게시.md#로그인은-넘기기-전에-ego-구글-계정-고르기부터--비밀번호-없이-계정만-골라-console-계정을-바꿨다-2026-11-12-claude)). 유호님 시간을 쓰게 하는 비효율은 그 자리에서 길을 고치고 이 문서까지 바꾼다(같은 날 「…같이 발전하자」). 그 손일을 GPT에게 맡길 때는 `node tools/GPT인계.mjs 준비`로 Codex 앱에 붙여 넣을 카드를 만들어 클립보드에 올리고 `기다리기`를 백그라운드로 띄워 결과를 받는다(2026-10-22). 카드는 적힌 일만 하고 비밀번호·인증 코드·2단계 인증·캡차·결제 확인 화면에서 멈춰 사용자에게 한 줄로 넘기게 적는다. Claude가 GPT를 사람 없이 띄워 이런 일을 시키지는 않는다.

## 확인과 완료

변경에 관련된 빌드·시험·실제 화면만 확인한다. 문서·스타일 수정마다 전체 검사나 새 승인 절차를 만들지 않는다. 보안·데이터·제품 계약 검사는 유지하며, 읽지 못한 범위와 미확인 결과를 밝힌다. 결과 위치와 남은 일은 기존 트랙의 해당 항목에 짧게 남기고 같은 보고서를 다시 만들지 않는다.

### 배포 뒤 결함과 검수 효과

배포 뒤 재현된 P0·P1은 발견한 작업의 기존 QA·이슈·담당 원문에 `발견일 | 배포판/커밋 | 깨지는 동작·재현 근거 | 영향·등급 | 놓친 단계·원인(모르면 미확인) | 고침·재발 방지·확인 결과`로 남기고, 트랙에는 결과 위치와 남은 일만 연결한다. 비밀값·학생 정보 등은 공개 기록에 넣지 않는다. 별도 공통 보고서·새 승인 관문을 만들지 않는다.

검수 방식을 바꾸거나 기간 시험을 평가할 때는 지적 건수와 함께 배포 뒤 중대 결함, 재작업 시간, 검수 대기시간을 같은 기간·작업 범위로 대조한다. 재작업 시간은 수정·재시험에 든 시간, 대기시간은 요청부터 사용 가능한 검수 답까지의 시간이며 병렬 작업 시간을 단순 합산해 절감 시간으로 보고하지 않는다. 배포판 수·관찰 기간을 함께 적고 기록 없는 과거는 미측정으로 둔다. 보고된 결함이 없다는 이유만으로 실제 결함 0건·검수 효과를 단정하지 않는다. 유효한 지적 수·반영 수의 기존 보고도 유지한다.
