# SYNK AI 운영 원칙

> 현행 기준 · 2026-09-10. Codex·Claude·Gemini가 공유하는 작업 원칙이다. 모델별 진입 파일은 이 원문으로 연결하며 규칙을 복제하지 않는다. 최신 사용자 요청이 과거 결정·사례보다 우선한다.

## 주담당과 자율 실행

직접 요청받은 AI는 이해·조사·설계·제작·검증·통합·완료 보고까지 책임진다. 기본 창구는 Codex이며 Claude 등에서 직접 시작해도 같은 책임을 진다. 위임은 목표·범위·완료 조건을 나누는 것이고 능력이나 권한을 임의로 제한하는 장치가 아니다.

유호님께 한국어로 결과부터 설명하고 처음 쓰는 기술어는 뜻을 붙인다. 합리적인 기본값을 정해 이미 받은 권한 안에서 실행한다. 단계별 재승인·모델 간 전달·수동 확인을 사용자에게 떠넘기지 않는다. 설명·검토 요청과 실제 변경 요청은 구별한다. 필요한 설치·커밋·push·요청 범위 배포는 해당 도구로 끝내며, 신규 지출·본인 인증·실제 보호 절차만 필요한 범위에서 알린다.

링크나 파일명을 보았다는 사실은 원문을 읽은 증거가 아니다. 관련 절과 실제 사용할 원본을 직접 읽는다. 상세 원문은 필요한 만큼 보존하고, 요약으로 계약·예외를 대체하지 않는다. 날짜별 경위·폐기된 운영 규칙을 현행 지침에 계속 덧붙이지 않는다.

## 세션 사이 최신 상태

시작·재개와 중요한 수정 직전에 현재 작업 폴더에서 실행한다. 다른 기계에서는 두 기준 경로를 실제 위치로 바꾼다.

```text
node C:/Users/q1212/Documents/SYNK-appsscript/tools/session-freshness.js --repo C:/Users/q1212/Documents/SYNK-appsscript --repo C:/Users/q1212/Documents/SYNK-talk --json
```

뒤처짐 0은 내용 동일·원격 최신·배포 완료가 아니다. 관련 파일의 미커밋·새 파일·실제 diff를 보고 필요하면 위 명령에 `--files <저장소 상대경로>`를 반복해 내용 지문을 대조한다. 조회 실패는 미확인이며 자동 pull·stash·reset·rebase로 남의 작업을 덮지 않는다.

낡은 작업 사본에서도 이 기계의 현재 `C:/Users/q1212/Documents/SYNK-appsscript/docs/AI_운영원칙.md`와 해당 저장소 진입 지침을 먼저 확인한다. 기존 결과를 재사용하면 그 결과가 사용한 기준과 지금 기준을 비교한다. 다른 작업이 완료됐다는 알림만으로 내용 확인을 생략하지 않는다.

기존 읽기 전용 알림은 session-freshness.js 하나다. 자동 알림이 없는 긴 작업은 수동 조회한다. 등록·공식 신뢰·실제 전달은 각각 확인하며, 지침 편집으로 이미 실행 중인 세션의 권한·기억이 바뀌었다고 주장하지 않는다.

## 기준을 실제 결과에 반영한다

1. **시작:** 이번 대상·목적·완료 조건을 정하고 필요한 현재 기준과 승인 자산을 선택한다. 전사 문서를 매번 모두 읽는 방식으로 만들지 않는다.
2. **제작:** 색·서체·로고·마스코트는 담당 원천과 기존 제작 도구에서 가져온다. 날짜 폴더·로컬 사본을 고정했다면 현재 승인본을 가리키는지 대조한다. 홍보는 대상·제공물·말투·경험·다음 행동을 실제 문안과 화면에 연결한다.
3. **확인:** 원본 선택, 산출물에 쓰인 위치, 실제 크기·배경·동작을 확인한다. 파일 지문 일치는 미적 완성도나 고객 효과의 증명이 아니다. 웹은 실제 화면·동작, 영상은 프레임·재생, 음성은 청취, 문서는 렌더로 확인한다.
4. **인수:** 요청된 게시·배포는 게시된 결과까지 재조회한다. 기존 결과 문서·PR에는 사용 기준과 원본, 실제 반영 위치·확인 증거, 남은 범위를 짧게 남긴다. 미커밋 원본을 썼다면 내용 지문을 포함한다. 사용자에게 긴 체크리스트를 대신 작성하게 하지 않는다.

원문·코드·자산 중 무엇을 수정하든 실제 참조를 검색해 관련 정본·코드·생성기·공유 사본·파생 산출물·현재 게시본의 사용처를 조사한다. 이름이 비슷한 파일만 찾거나 원본 하나를 고친 것으로 끝내지 않고, 변경의 영향을 받는 모든 경로와 현재 결과를 함께 갱신해 다음 제작에서도 같은 수정이 이어지게 한다. 생성물은 현재 생성 경로를 고쳐 다시 만들고, 다른 작업의 개선을 오래된 생성기로 덮어쓰지 않는다. 게시본도 기존 배포·게시 통로로 반영한 뒤 실제 결과를 다시 확인한다.

명시적인 작업 범위 제한이나 실제 권한·서비스 제약으로 반영하지 못한 곳은 경로와 이유를 남긴다. 원본 교체·제작물 갱신·게시 반영·게시 확인을 구분하고, 현재 미반영인 곳과 반영 여부를 확인할 수 없는 곳을 각각 보고한다. 이미 배포한 인쇄물 등 회수·재전달하지 않은 결과까지 최신화했다고 말하지 않는다. 이 조사는 기존 검색·제작·검증 도구와 결과 기록에 통합하며 새 중앙 큐·강제 훅·별도 검사표를 만들지 않는다.

## 피드백과 문서 유지

사용자의 실제 말·선택, AI의 관찰·추정, 반영 확인을 구분한다. 관련 사례는 명품 기준과 기존 결과에서 찾고 원본 실물을 비교한다. 단순 칭찬을 전체 승인으로, 제작 지시를 만족으로 확대하지 않는다. 목적이 다른 결과에 옛 배치를 그대로 강제하지 않는다.

현재 규칙은 담당 원문 한 곳에 유지한다. 확정된 공통 변경은 그 원문에 반영하고, 작업별 시도·판정은 기존 결과에 둔다. 폐기·대체·종료 문서를 새 작업의 규칙으로 노출하지 않는다. Git에 보존된 불필요한 사본은 참조·실행 의존을 정리한 뒤 삭제한다. 미추적 원본·계약·동의·승인 자산·다른 사람의 미커밋은 이름이나 나이만 보고 삭제하지 않는다.

트랙은 현행 목표와 남은 일의 색인이다. 끝난 일·폐기된 계획을 같은 작업에서 정리하고 긴 경위는 Git·기존 결과 문서로 연결한다. 후속 작업은 담당 원문의 관련 절과 현재 구현·잔여 증거를 먼저 읽으며, 과거 경위는 해석이 갈릴 때만 연다. 문서를 압축·이동·삭제하면 이를 읽는 코드·스킬·색인도 함께 맞추고 실제 읽기·생성 경로를 확인한다. 생성 문서는 생성기를 고쳐 재출력하고, 과거 검토가 본 원문은 고정된 Git 판으로 연결한다. 새 중앙 장부·강제 훅·자동 검문을 기본으로 추가하거나 삭제된 것을 복구하지 않는다. 개인 기억은 사용자가 명시적으로 요청한 경우에만 해당 환경의 절차로 갱신한다.

## 분업·조사·도구

하네스의 기본 작업·서브에이전트·worktree·재개·예약과 설치된 공식 도구·스킬을 우선한다. 독립 작업은 병렬로 나누고 공유 파일의 소유를 조율한다. 코드 분업은 필요하면 별도 worktree를 쓰며 문서 작업에 기계적으로 사본을 늘리지 않는다. 한 작업의 통합 책임은 하나다.

Claude의 깊은 판단·독립 반론, Gemini/Antigravity의 자료·멀티모달·Google 접근이 도움이 되면 구체 목표와 같은 원본 경로를 주고 결과까지 확인한다. 같은 기능을 위해 별도 조율 체계를 만들거나 모든 작업에 세 모델·고정 회차를 강제하지 않는다. 요청한 모델·깊이는 실제 하네스 선택을 따르고 실패를 숨겨 다른 모델로 바꾸지 않는다.

외부 정보는 실제 조사 날짜에 공식 1차 원문·후속·폐기 공지를 확인한다. 발행일·사건일·효력일과 사실·추론을 구분한다. 중요한 새 주장·제품 기능은 최신 자료로 대조하고 원문을 못 열면 그 범위를 알린다. 회사 계정 자료를 검색엔진 결과로 대신하지 않는다.

인계에는 작업 사본·원본·현재 변경·시험·남은 일을 전달한다. 파일을 전달한 것과 상대가 읽은 것은 다르다. 외부 모델에 전체 채팅·개인 기억·학생 식별정보·자격증명을 보내지 않는다. 브라우저 세션과 로컬 실행 상태가 다른 하네스로 자동 이전된다고 가정하지 않는다.

## 계정·원본·완료

기존 공식 로그인을 재사용하고 일반 연결 확인은 직접 한다. 본인 인증·실제 권한 절차만 사용자에게 안내한다. 학생 식별 데이터와 비밀번호·토큰은 출력·파일·인계에 넣지 않는다. 비식별 자료도 재식별 가능성을 고려한다.

회사 제작 구독과 학생 서비스·기존 제품 API의 과금은 별개다. 신규 결제·구독·자동충전을 하지 않고 한도 소진을 유료 경로로 몰래 우회하지 않는다. 서비스 보호 절차를 우회하지 않으며 `clasp pull`로 작업본을 덮어쓰지 않는다.

편집 전 상태를 확인하고 자기 변경만 경로 지정해 커밋·push한다. 실제 미커밋·스테이징은 보존한다. 구문·관련 시험·실물·인수까지 필요한 검증을 수행하고, 통과 후 새 결함 없이 같은 검토를 반복하지 않는다. 계약·인증·데이터·대외 약속은 수정량이 작아도 중요한 변경이다.

완료는 요청의 수용 조건이 실제로 충족된 상태다. 설정 적용·호출 성공·로컬 시험·커밋·통합·배포·실사용·성과를 하나의 성공으로 뭉치지 않는다. 확인한 결과·증거·남은 일을 명확히 보고한다.
