## 모든 작업의 출발점 · 사용자 평가에 근거한 벤치마킹

GPT와 Claude 모두 **목적에 맞는 현존 최고 서비스의 장점 + SYNK의 개인화·학습 가치 → 더 나은 SYNK 콘텐츠·앱**을 공통 작업 방식으로 삼는다. 기획·구현·고도화·콘텐츠 제작에서 아래 조사를 필수로 수행하고, 그 결과로 무엇을 만들지 결정한다.

1. **목적을 먼저 확정한다.** 누구의 어떤 문제를 풀고 어떤 재미·편익·학습 경험을 줄 것인지, 이번 결과의 성공 기준을 파악한다. 목적이 같은 서비스·회사·콘텐츠와 인접 분야까지 조사 대상으로 잡는다. 생활 콘텐츠 앱이라면 교육 앱뿐 아니라 Steam 등의 생활 시뮬레이션 게임도 살핀다.
2. **현재 선도 서비스를 폭넓게 찾는다.** 조사일 기준 후보군을 훑고 이용·판매·조회 등 인기 지표와 평점·리뷰 수·최근 평가 등 만족도 지표를 함께 비교한다. 누적 인기와 최근 반응, 플랫폼·대상 사용자 차이를 구분해 목적에 맞는 최고 사례를 고른다. 유명한 회사나 익숙한 몇 개 사례만으로 결론내리지 않는다.
3. **기능과 사용자 반응의 원문을 수집한다.** 공식 제품·도움말·업데이트와 실제 사용 화면·플레이 자료에서 기능을 확인하고, 스토어 리뷰·커뮤니티·댓글의 최신 원문을 크롤링·열람한다. 검색 요약이나 회사 홍보만으로 끝내지 않는다. 반복되는 호평과 불만을 기능·사용 맥락별로 묶고, 최근 평가와 장기 평가를 대조한다. 출처 URL·확인일·평가 기간·표본 규모·선정 범위를 남긴다. 접근하지 못한 자료와 표본 조사를 전수조사로 보고하지 않는다.
4. **왜 좋은지 기능 단위로 설명한다.** ‘어떤 기능 → 어떤 사용자 경험 → 어떤 호평’인지 원문 근거와 연결한다. 흥행 규모만으로 개별 기능의 효과를 단정하지 않고, 사용자가 직접 밝힌 이유와 우리의 해석·가설을 구분한다. 불만에서는 개선 기회를 찾는다.
5. **장점에 SYNK의 색을 더해 설계·구현한다.** 가져올 장점과 바꿀 점을 정하고, 관련 Atlas 엔진의 개인화와 구체적인 학습 활동·피드백·성장 보상을 어디에 연결할지 정한다. 기능을 단순히 모으지 않고 원래 호평받은 재미·편의가 살아 있는 사용자 흐름으로 만든다. 아직 확인하지 않은 학습 효과는 가설로 둔다.
6. **실제 결과로 검증하고 갱신한다.** 벤치마킹에서 채택한 장점이 결과물에 구현됐는지 확인하고, 실제 사용·시청 반응으로 다음 개선을 정한다. 다른 AI의 작업을 이어받을 때도 조사 근거와 구현 결과를 함께 확인해 발전시킨다.

조사 결과는 해당 제품·콘텐츠의 기존 설계나 탐색노트에 **출처·사용자 반응 → 채택할 장점 → SYNK 적용 → 확인할 결과**로 짧게 연결한다. 별도 공통 보고서나 실행기를 늘리지 않는다. 이어 하는 수정은 기존 근거를 먼저 활용하되 최신성과 이번 변경의 관련성을 확인하고 부족한 범위를 추가 조사한다. 새 목적·핵심 기능·사용자 경험을 정할 때는 후보 조사부터 다시 수행한다.

## 공식 하네스

- 각자의 공식 앱·CLI에서 계획·도구·서브에이전트·재개·검토·예약 기능을 사용한다. 모델과 추론 설정은 해당 제품의 실제 설정을 따르며 임의로 통일하거나 하향 대체하지 않는다.
- 자체 LLM 실행기·중계·자동 모델 선택기·반복 검수기를 추가하지 않는다. 기존 자체 실행 절차와 훅을 새 작업의 선행 조건으로 되살리지 않는다.
- 스킬·커넥터·제품 보조 도구는 필요한 것만 쓴다. 도구 추가는 기존 기능으로 해결하지 못하는 반복 문제와 실제 효과가 있을 때로 한정한다. 제품 내부의 AI API와 학습 엔진은 작업용 하네스와 구분한다.
- 예약은 요청된 일이 있을 때만 만든다. 할 일 없이 큰 대화를 주기적으로 깨우지 않으며, 단순 상태 확인은 AI 없는 조회·알림으로 처리한다.

## 같은 원문으로 이어가기

- `AGENTS.md`가 공동 입구이고 `CLAUDE.md`는 이를 가져온다. 제품 설계·코드·결과는 담당 원문 한 곳에서 고친다. 모델별 사본이나 별도 인수인계 양식을 늘리지 않는다.
- 이어받을 때 해당 원문·코드·현재 diff와 [트랙](_ops/트랙.md)의 관련 항목을 확인한다. 작업본 위치, 확인한 결과, 남은 일만 짧게 전달한다. 같은 폴더의 파일 공유가 대화·프로세스·미커밋 변경의 자동 동기화를 뜻하지는 않는다.
- 확정 내용은 담당 원문에 반영하고 [결정](_ops/결정.md)에는 근거를 남긴다. 과거 기록·메모의 역할표·말투·절차를 현재 지침으로 적용하지 않는다. 자연스러운 한국어를 사용하며 캐릭터 설정은 해당 캐릭터의 대사에만 적용한다.
- 다른 작업의 변경·원본을 보존한다. 동시 편집에서는 파일 범위를 확인하고, 별도 worktree의 변경은 필요한 것만 통합한다.

## 비용과 권한

- 자격증명과 학생 식별 정보를 출력·공유하지 않는다. 신규 결제·구독·자동충전은 하지 않으며 한도·인증 문제를 다른 유료 경로로 자동 우회하지 않는다. 단, GPT 그림 굽기는 2026-10-17 사용자 결정으로 등록한 GPT 보조 계정 사이에서 한도에 막히면 자동으로 바꿔 쓴다(`tools/codex계정.js`). 본 계정(synk.yuh)은 백엔드와 한도를 같이 쓰므로 보조 계정이 모두 막혔을 때만 맨 마지막 예비로 쓴다. 헤르메스 텔레그램 접수 GPT는 2026-10-18 요청에 따라 Microsoft 계정 `q121235@outlook.com`의 독립 Hermes 로그인으로 쓰며, 다른 계정·유료 API로 자동 대체하지 않는다. GPT 세션도 앱 안의 그림 도구로 바로 굽지 않고 `codex exec` 대신 `node tools/codex계정.js exec <같은 인자>`(지시문은 표준입력)로 굽는다. Claude API도 2026-10-17 사용자 결정으로 Max·Team 플랜에 딸린 월 API 크레딧 계정 사이에서, 한 계정의 크레딧이 바닥나면(「credit balance is too low」) 다음 계정 키로 자동으로 바꿔 쓴다(`tools/lib/클로드키.js`, 키 목록·상태·사용 기록은 저장소 밖 `~/SYNK_보안/`). 갱신일이 가까운 계정부터 쓰고, 속도 제한(429)·서버 오류·결과를 모르는 호출은 다른 키로 넘기지 않으며 모델을 바꾸지 않는다. 키 목록에는 Max 계정마다 결제 수단·충전 잔액·자동충전 없이 새로 만든 Console 조직의 키만 넣는다(2026-10-18 사용자 결정). 충전 잔액이 있는 조직은 크레딧이 떨어져도 「잔액 부족」 없이 돈이 나가기 때문이다. Claude의 무인 작업(예약·헤르메스 /synk_claude)도 2026-10-18 요청에 따라 이 키부터 쓴다. `claude -p` 대신 `node tools/크레딧실행.js`로 띄운다(예약은 `작업 <이름>`, 헤르메스는 `중계 -- <같은 인자>`). 이것은 공식 CLI를 한 번 띄우면서 자격만 고르는 통로이고, 모델·인자를 바꾸거나 반복하지 않는다. 크레딧 키가 없으면 구독으로 돈다. 구독에 로그인된 PC에서는 키를 줘도 구독으로 청구되므로, 구독 로그인이 없는 전용 설정 폴더를 쓴다([현장 노트](현장노트/AI_CLI.md#claude-api)). 사용자가 헤르메스에서 클라우드를 지정한 작업(/synk_cloud)만 Managed Agents에서 크레딧으로 돌리고, 결과는 `claude/cloud-<작업 ID>` 브랜치로 받는다(한 번에 $15·120분 상한). 헤르메스 연결은 수정안을 얹은 뒤부터 적용된다([트랙](_ops/트랙.md)). Gemini도 2026-10-17 사용자 결정으로, 무료 API 문이 몫 상한(429)에 막히면 같은 모델·사고 수준으로 Google AI 구독 통로(agy에 로그인한 계정, 지금 Ultra)를 한 번 부른다(`tools/lib/제미나이호출.js`의 구독대체). 유료 Vertex로는 넘어가지 않고, CI와 대량 검문 도구는 기본으로 넘기지 않는다.
- 개발용 구독과 제품 API 비용은 별개다. MVP의 AI 한도는 낮게 유지하고, 유료 AI 시험·실제 호출은 실행 전 예상 비용을 알리고 승인을 받는다. 한도 상향도 확인 후 진행한다.
- 이미지는 GPT·Gemini 직접 서비스의 기존 월 정액제 경로를 사용한다. Higgsfield나 별도 과금 API로 전환하지 않는다. 단, 2026-10-13부터 사용자가 다시 정할 때까지 AI 영상·이미지 작업의 실사 정지컷(얼굴·AI 영상 시작 그림)은 [만족 사례 장부](마케팅/제작양식/만족사례_장부.md)대로 Higgsfield Nano Banana Pro로 만든다. 영상에 얹는 그림(마스코트 표정·소품·그림 개그)은 2026-10-13 사용자 결정으로 영상마다 그 편에 맞게 GPT 이미지 2.5(ChatGPT 구독 · Codex CLI)로 판에 구워 오리는 것이 기본이다(정본은 생김새 참고, `tools/펠트판_칸오리기.py`, 장부 S17). GPT 이미지의 사용자 지정값은 **GPT Image 2.5 Sunburst · max**이며, 선택할 수 없는 도구에서 이를 보장했다고 보고하지 않는다. 승인 얼굴·로고·원본을 보존한다.
- Google Cloud 기본 결제 계정과 프로젝트 연결은 [돈장부](_ops/돈장부.json)의 `기본_구글클라우드_결제`에서 확인한다. 기존 서비스의 결제 이전·크레딧 종료 후 유료 전환까지 승인된 것으로 해석하지 않는다.
- 배포·공개 게시·외부 발송은 현재 요청에서 승인한 범위로 실행한다. 준비·로컬 검증·실제 반영·사용자 효과를 구분하고 확인하지 않은 결과를 완료로 보고하지 않는다.

## 확인과 완료

변경에 관련된 빌드·시험·실제 화면만 확인한다. 문서·스타일 수정마다 전체 검사나 새 승인 절차를 만들지 않는다. 보안·데이터·제품 계약 검사는 유지하며, 읽지 못한 범위와 미확인 결과를 밝힌다. 결과 위치와 남은 일은 기존 트랙의 해당 항목에 짧게 남기고 같은 보고서를 다시 만들지 않는다.
