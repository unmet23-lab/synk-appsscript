# SYNK 작업의 공통 기준

> 2026-09-22 · 사용자의 현재 요청이 작업 범위를 정한다.

- 말투는 Claude와 GPT가 기본으로 쓰는 자연스러운 한국어 그대로 쓴다. 따로 정한 말투 지침은 두지 않는다. 과거의 말투 지침·금칙어·대체어 표와 이를 따르라는 메모는 폐기된 기록이다. 캐릭터 설정은 해당 캐릭터의 대사에만 적용한다.
- 공식 앱·CLI의 작업 분담·재개·검토·예약 기능을 먼저 쓴다. 각 도구의 모델 선택·설정·고유 기능을 유지하며, GPT·Claude의 역할이나 이중 검수를 고정하지 않는다. 과거 자체 실행·검토 도구를 일반 작업의 기본 경로로 사용하지 않는다.
- 지침은 원본 위치·SYNK의 제약·확인 방법만 짧게 유지한다. 자체 장치는 반복되는 실제 문제가 공식 기능·기존 도구로 해결되지 않을 때만 추가하고, 효과가 확인된 것만 남긴다. 정리의 목적은 Atlas·학습 콘텐츠·디자인·제품 검증에 집중하는 것이다.
- 과거 결정·사례·기억은 배경 자료다. 예전 작업 순서·모델 역할·말투 교본을 현재 요청에 자동 적용하지 않는다. 승인 자산·기존 엔진·제품 설계·채널별 대상과 언어는 보존하며, 캐릭터의 [가이드 정본](캐릭터/가이드_정본.md)은 캐릭터 대사에만 적용한다. 철학·설계 문서의 문체를 홈페이지·마케팅 문구에 강제하지 않는다.
- 디자인 작업에는 [디자인 명품화 기준](명품_기준_v1.md)을 기본 적용한다. 이는 시각·움직임·사용성·마감 기준이며 말투와 대사 패턴을 정하지 않는다. 새 화면·지면은 [펠트 스크랩북 양식](디자인/펠트스크랩북/README.md)에서 출발한다(2026-09-29 사용자 확정).
- 시청자·독자·사용자에게 보여주는 모든 작업은 먼저 “이걸 볼 이유가 무엇인가?”를 정한다. 정보와 재미·감정적 보상을 모두 준비하며, 쉽게 이해하고 배우는 즐거움도 포함한다. 목적에 맞는 친절한 설명·직관적인 표현·애니메이션·나레이션·소리·세부 마감을 실제 결과로 확인한다. 재미를 줄 아이디어가 막히면 제작 시점의 인기 릴스에서 우리 성격에 맞는 형식을 조사해 변형한다. [콘텐츠 공통 제작 기준](마케팅/콘텐츠_제작양식.md#시청자가-볼-이유부터)을 따른다(2026-09-27 사용자 직접 요청·후속 명확화).
- 콘텐츠와 이어지는 맞춤 추천 도구는 [맞춤 도구 제작 절차](마케팅/맞춤도구/제작절차.md)를 따른다. 만들기 전에 사전 탐색을 충분히 하고, 결정 요소마다 무엇인지·왜 필요한지·왜 비싼지·필요 없는 경우·함정·확인법을 팁으로 담아 사람마다 ‘의미 있음 / 차이 없음’을 골라 보여 준다. 추천은 가성비를 먼저 두고 ‘여유가 되면’을 따로 보여 준다(2026-09-27 사용자 직접 요청).
- 정보를 주는 콘텐츠는 그 정보를 한 사람의 조건으로 바꿔 주는 개인화 프로그램(맞춤 도구·맞춤 틀)을 기본으로 함께 만들고, 업로드도 그런 편을 먼저 한다. 정말 바꿀 조건이 없을 때만 공통 정보로 두고 이유를 남긴다. [개인화 프로그램이 기본값](마케팅/콘텐츠_제작양식.md#개인화-프로그램이-기본값--업로드도-이-편-먼저)을 따른다(2026-10-01 사용자 요청).
- SNS 콘텐츠의 표지·카드·썸네일·영상 위 글자와 영상의 움직임은 [SNS 제작 키트](디자인/SNS키트/README.md)에서 출발한다. 영상은 첫 프레임부터 보이고, 애니메이션과 장면 전환이 충분해야 한다. 밋밋한 영상은 내보내지 않는다(2026-10-01 사용자 요청).
- 다른 작업의 미커밋 변경·원본을 보존한다. 자격증명과 학생 식별 정보를 출력·공유하지 않는다. 신규 결제·구독·자동충전은 하지 않는다.
- 요청된 일을 실행하고 필요한 범위에서 확인한다. 확인하지 않은 실행·게시·효과를 완료로 보고하지 않는다.
- 사용자가 “아틀라스 엔진을 활용해줘”라고 하면 작업 목적에 맞는 엔진을 스스로 골라 기존 구현·자산·도구를 적용한다. 디자인·장면·움직임은 Loom부터 확인하며 필요한 엔진을 함께 쓴다. 게임·콘텐츠·NPC·개인화도 Atlas의 기존 공통 능력을 먼저 확인한다. 부족한 능력은 담당 엔진에서 발전시켜 결과물에 연결하고 실제 경험을 확인한다. 매번 엔진 선택을 되묻거나 여덟 엔진을 모두 붙이지 않는다. 상세는 [아틀라스 설계 §1-1](아틀라스_설계.md#1-1-콘텐츠를-만들며-공통-엔진을-발전시키는-개발-방식)과 [구현 명세 §9-1](아틀라스_구현명세.md#9-1-새-콘텐츠-요청을-엔진-발전으로-연결하기)에 둔다.
- 사용자가 다음 일을 맡기고 별도 우선 과제가 없으면 [SYNK 플랫폼 3단계](SYNK_플랫폼_계정과_연결_설계.md#4-브랜드-플랫폼을-만드는-순서--사용자-승인)의 다음 미완료 작업을 진행한다. 기존 앱의 홈·계정·기록·콘텐츠 입구 → 두 콘텐츠의 기억·도움 연결 → 필요할 때 런처·상점·커뮤니티 순서다. 현재 요청이 우선이며 자동 예약 지시는 아니다.

## 자료 위치

회사·제품은 [문서 지도](문서_지도.md), 로고·서체·마스코트는 [DESIGN](../DESIGN.md), 계정·채널은 [마케팅 정본](마케팅_정본.md)에서 이번 작업에 필요한 원문만 찾는다.

## GPT와 Claude가 같은 원문으로 이어가기

- `AGENTS.md`를 공동 입구로 쓰고 `CLAUDE.md`에는 `@AGENTS.md`만 둔다. 설계·계약·결과는 모델별 사본 없이 담당 원문에서 관리한다. 개인 기억·채팅 전체·도구 설정을 억지로 같게 만들지 않는다.
- 이어받을 때 관련 원문·코드와 [트랙](_ops/트랙.md)의 해당 항목을 읽는다. 이전 대화·상태 알림·같은 커밋 번호만으로 최신 내용을 안다고 판단하지 않는다.
- 확정 변경은 담당 원문에, 결과 위치·확인 범위·남은 일은 기존 트랙의 해당 항목에 짧게 남긴다. 제안과 확정, 로컬 구현과 배포를 구분하고 결과를 중복해서 복사하지 않는다.
- 동시 편집은 담당 범위를 나누고 현재 diff를 확인한다. 별도 worktree·다른 컴퓨터는 다른 작업본이며, 미커밋 변경이 자동으로 공유되지 않는다.
- 보안·데이터·제품 계약 검사는 유지한다. 옛 협업 훅·역할표·설치 절차를 파일이 남아 있다는 이유로 복원하지 않는다. 연결 범위와 현황은 [작업 연결 구조](AI_워크플로우_아키텍처.md#공동-문서와-최신-상태)에 둔다.
