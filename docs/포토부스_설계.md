# SYNK 오프라인 포토부스

> 2026-10-02 운영 범위 갱신: [현재 운영 기준](오프라인_공간설계/오프라인_운영기준_20261002.md)을 따른다. 대표 학생만 월1회 차감하는 조건을 유지한다. 사진실 앞 공용 음료 코너와 뒤 촬영은 소형 겸용 후보이며 무제한 다과/라운지를 추가하지 않는다. 실제 재학·예약/중복·오류 복구·사진 권한/삭제·다음 사용자 초기화를 검증한 뒤 제공한다. 공간상 무제한 자유 입실이나 자동 운영 완료로 안내하지 않는다.

> 2026-10-01 갱신 · 학생 월 1회 이용 및 대표 학생 차감, 앱 이름 SYNK WORLD는 사용자 확정. 별도 브랜드 플랫폼은 후속 정정에 따라 당분간 SYNK 플랫폼으로 칭한다. 중립 촬영 배경+승인 로고·마스코트가 있는 사진 프레임, 월별/시즌별 프레임 교체를 설계에 반영했다. 연결 방식과 세부 운영은 아래 제안이며, 포토부스 코드·실기기·운영 배포는 아직 없다.

## 1. 학생이 얻는 경험과 확정 기준

학원에서 친구와 사진을 찍고, SYNK 프레임에 담긴 기념사진을 가져간다.

- 학생마다 월 1회 촬영을 시작할 수 있다.
- 여러 명이 함께 찍어도 **촬영을 시작한 대표 학생 1명의 이용권만 사용**한다.
- 동반 친구의 이용권은 차감하지 않는다. 다른 친구가 대표가 되어 촬영할 때 다시 함께 나오는 것은 허용한다.
- 대표 학생의 이용권 사용은 사용자 확정이다. 촬영에 나온 사람 모두를 식별하는 방식으로 확대하지 않는다.
- 앱 또는 학생 계정과 연결해 편하게 구분하는 방향이다. 사용자는 엔씨소프트 PURPLE처럼 만들려던 회사 플랫폼을 연결 대상으로 다시 짚었다. 아래 QR 흐름은 구현 제안이다.
- 종이 인화+QR과 QR 전용 중 최종 선택, 인화 매수, 장비, 설치 크기, 예산은 미정이다.

근거: 사용자 “학생별로 월 1회 찍을수있게 제한”, 후속 선택 “촬영을 시작한 대표 학생 1명의 이용권만 사용”.

### 2026-10-01 공간과 결과물 브랜딩 반영

사용자가 운영 보완과 브랜드 경험 제안에 “전부 반영해줄래?”라고 요청했다. [방별 인테리어 §19](오프라인_공간설계/방별_인테리어_디자인_20260929.md#19-학생의-하루에-이어지는-브랜드-경험)와 [디자인북](오프라인_공간설계/인테리어_컨셉_20260929/디자인북.html)에 실제 읽을 문구와 프레임 구성 시안을 연결한다.

- **공간:** 촬영 배경은 중립으로 둔다. 앞 음료대의 물·컵·쓰레기와 뒤 사진 장비/인화지의 상판을 분리한다. 프레임 디자인이 촬영 면적이나 설치 가능 인원을 늘리지는 않는다.
- **교대·수거:** 반 교대 때 출입·화장실 접근을 먼저 비우고 선택적인 포토 이용은 혼잡 시간 밖으로 안내한다. 기다리는 사람을 복도나 상담실에 상시 수용한다고 계산하지 않는다. 앞 편의대 하부에 잔음료 수거통1개를 기존 컵 수거함과 나누어 두고, 직원이 관리 시간에 수거한다. 실제 용기 크기·유출·꺼낼 공간은 확인 전이며 사진 장비/인화지 위로 물통을 옮기지 않는다. 상세는 [하루 운영 §21~23](오프라인_공간설계/방별_인테리어_디자인_20260929.md#21-학생-등원부터-하원까지--같은-공간을-편하게-쓰는-실행안)을 따른다.
- **결과물:** 사진4칸이 중심이고 승인된 학원 로고·마스코트·촬영 날짜는 바깥 여백에 둔다. 학생 이름·계정 ID·학생번호는 넣지 않는다. 옛 ‘포토월에 로고·마스코트 필수’는 결과물과 조작 화면에서 브랜드를 보여주는 방식으로 정정한다.
- **선택:** 기본 프레임1종+월별 또는 시즌별1종의 구성으로 시작한다. 틀을 바꾸는 것으로 재촬영권을 추가하지 않으며 기존 월1회/대표만 차감을 유지한다. 실제 인화 규격·해상도·재단 여유는 프린터 또는 디지털 저장 규격을 정한 후 확정한다.
- **촬영 전 문구:** ‘이번 달 촬영권 1회’ → ‘대표 학생의 이용권 1회를 사용해요. 함께 찍는 친구의 이용권은 사용하지 않아요.’ → ‘이용권 사용하고 촬영 시작’ 순서로 설계한다. 이용 가능 여부는 서버 확인값을 표시해야 한다.
- **진행/완료 문구:** ‘촬영 진행 중’과 ‘이번 달 사용 완료’를 구분한다. 실제 결과물이 만들어지기 전에 완료로 표시하지 않는다. 오류 복구는 아래 §5의 같은 예약/세션을 따르고 중복 차감하지 않는다.
- **저장 안내:** 종이 인화+QR 또는 QR 전용 선택은 보류다. 결정·구현·실제 기기 검증 후 해당 방법만 안내한다. 디자인 시안에는 작동하지 않는 QR을 그려 놓거나 사진 저장 완료로 표시하지 않는다. 앱에서 개인 결과물 접근을 구현할 때 다른 학생의 사진이 노출되지 않게 한다.
- **공유:** 사진 다운로드/인화와 SNS 공개는 다른 행동이다. 자동 게시를 추가하지 않고 학생이 원하는 결과물을 가져가는 데서 기본 흐름을 끝낸다.

이 반영은 공간·화면·사진 결과물의 설계다. 월 이용권 서버, 부스 소프트웨어, SYNK WORLD 연결, 실제 촬영/인화는 별도 구현 단계다.

## 2. 회사 플랫폼 안의 학생 혜택 — 연결 제안

사용자가 2026-09-28 앱은 **SYNK WORLD**, 별도 브랜드 플랫폼은 당분간 **SYNK 플랫폼**으로 부르도록 정정했다. **Atlas(아틀라스)**는 기존 엔진 시스템 명칭으로 유지한다. PURPLE은 참고 모델이다. 두 제품의 구분은 [공통 플랫폼 방향의 최신 기준](SYNK_플랫폼_계정과_연결_설계.md#2026-09-28-명칭과-제품-구분--사용자-확정)을 따른다.

공통 SYNK ID 방향에 맞춰 포토부스를 SYNK 플랫폼의 ‘내 혜택 → 학원 포토부스’로 연결한다는 제안이다. SYNK WORLD에서도 같은 이용권 화면을 바로 열 수 있게 하면 학생이 촬영할 때 두 제품 사이를 찾아다니는 부담을 줄일 수 있다. 어디서 열어도 같은 서버 이용권을 사용한다.

- **SYNK 플랫폼:** 사용자가 SYNK의 여러 제품·콘텐츠와 공통 계정·기록·혜택을 여는 입구.
- **SYNK WORLD 앱:** 학습·이야기·게임·마을을 경험하는 별도 제품. 포토부스 이용권의 바로가기를 두는 것은 제안.
- **SYNK ID:** 같은 사람의 계정과 서비스 이용 권한을 연결하는 공통 기준. 전체 공통 계정 구현이 끝났다는 뜻은 아니다.
- **LAB 학생 연결:** 공통 계정에 학원 학생의 `learner_id`·소속·혜택 자격을 연결. 학원 세부 원장을 플랫폼 전체에 무조건 복제하지 않는다.
- **포토부스:** 서버에서 해당 학생의 월 촬영권을 확인하고 대표 학생의 사용 기록을 남기는 실제 공간 서비스.

지금 Talk에 있는 학생 계정은 재사용할 기반이다. 최종 사용 경험을 학습 앱의 독립 쿠폰으로 고정하지 않고, 회사 공통 계정에 연결 가능한 학생 혜택으로 설계한다. 추후 공통 계정으로 옮길 때도 기존 학생의 `learner_id`와 월 사용 기록을 유지해 새 이용권이 중복 생기지 않게 한다.

## 3. 권장 이용 흐름 — 제안

1. 포토부스 대기 화면에 짧은 시간만 유효한 QR을 표시한다.
2. 대표 학생이 자기 휴대폰으로 QR을 읽고, 로그인된 SYNK 플랫폼의 포토부스 혜택 화면 또는 같은 계정의 웹 화면을 연다. SYNK WORLD 안에서도 같은 흐름을 열 수 있게 하는 방안을 검토한다.
3. 부스 이름과 이번 달 남은 이용권을 보여준다. 학생이 ‘이용권 사용하고 촬영 시작’을 누른다.
4. 서버가 학생 자격·이번 달 사용 여부·부스 상태를 확인하고 그 학생과 부스에 촬영 세션 하나를 예약한다.
5. 해당 부스에서 프레임 선택 → 연속 촬영 → 사진 선택 → 네컷 완성을 진행한다.
6. 완성본을 제공하고 사용 완료로 기록한다. 인화를 도입하면 같은 결과물의 출력 단계를 붙인다.

학생 계정은 본인의 휴대폰에서만 로그인한다. 이 방식이면 부스에 별도 QR 스캐너를 추가할 필요가 없다. 앱을 열거나 웹 로그인 후 원래 부스 확인 화면으로 돌아오는 경로는 실제 휴대폰에서 검증해야 한다.

앱에는 ‘이번 달 촬영권 1회 / 사용 완료 / 진행 중’과 다음 이용 가능일을 보여주는 작은 화면을 추가한다. 휴대폰이 없을 때는 직원이 기존 학생 확인 절차로 같은 이용권을 대신 승인하는 방식을 제안한다. 직원 경로도 횟수 제한과 기록을 공유한다.

## 4. 현재 앱에서 재사용할 기반

2026-09-27 SYNK-talk 로컬 코드 확인이며 라이브 DB·학생 실데이터·배포 상태는 확인하지 않았다.

- 앱은 Expo, 인증·DB·서버 함수는 Supabase 기반이다.
- `engine.learners`의 `learner_id`가 학생의 내부 키이고, `auth_user_id`와 `student_code`가 연결되어 있다. 월 이용권은 **learner_id 기준**으로 묶는다.
- 기존 첫 등록 서버가 명부의 학생번호와 등록 연락처 일부를 확인해 로그인 계정을 연결한다. 학생번호만 입력해서 촬영을 여는 통로를 추가하지 않는다.
- 로그인된 인증 주체에서 서버가 학생을 찾는다. 휴대폰이나 부스가 보낸 임의의 학생 ID를 그대로 믿지 않는다.
- 현재 `lifecycle_status`는 `재학·종료·미상`을 담지만 기본값은 `미상`이며 확인한 `roster-ingest`는 이를 채우지 않는다. **로그인 가능 여부만으로 현재 재학생 혜택을 부여할 수 없다.** 시범 운영은 직원이 확인한 대상 명단, 정식 운영은 검증된 재학 상태 연결을 제안한다.
- 포토부스·월 촬영권 기능은 확인한 `src`, `lib`, `supabase` 범위에서 찾지 못했다. 별도 추가 개발이 필요하다.

## 5. 월 제한과 오류 처리 — 제안

| 항목 | 권장 규칙 |
|---|---|
| 월의 기준 | 학원 현지 시간의 달력 월. 매월 1일 새 1회, 미사용분 이월 없음. 시간대와 이월 여부는 운영 확정 전까지 제안 |
| 1회의 뜻 | 한 번의 촬영 세션. 연속으로 여러 컷을 찍고 네컷 완성본을 만드는 과정 전체. 촬영 컷 수·재촬영 허용 수는 미정 |
| 중복 사용 방지 | 서버에서 학생·혜택·연월당 사용 가능 권리를 하나로 관리. 두 휴대폰·두 부스의 동시 요청도 같은 권리를 원자적으로 예약 |
| QR | 부스·유효기간에 연결된 일회용 도전값. QR을 읽는 것만으로 차감하지 않으며, 사용 승인 후 재사용할 수 없음 |
| 차감 과정 | 사용 가능 → 예약/진행 중 → 완성본 생성 확인 후 사용 완료. 예약 중에는 다른 새 촬영을 시작할 수 없음 |
| 중단·오류 | 촬영 시작 전임이 확인된 취소만 예약 해제. 이미 촬영했거나 결과가 불명확하면 같은 세션 복구 또는 직원 확인. 앱 종료·부스 재부팅·예약 시간 경과만으로 이용권을 새로 주지 않음 |
| 인쇄 실패 | 완성본이 있으면 같은 사진만 재출력. 새 촬영권은 자동 지급하지 않음. 직원 복구는 사유와 처리 기록을 남김 |
| 통신 장애 | 신규 이용권 확인이 안 되면 새 촬영 시작을 보류. 진행 중 결과는 부스에 보존하고 복구 후 같은 세션으로 정산 |
| 월 경계 | 예약 당시 연월을 세션에 고정. 자정 이후 완료돼도 다음 달 권리를 대신 차감하지 않음 |

이용권 상태는 앱 화면이나 브라우저 저장소가 아니라 서버 DB가 결정한다. 등록된 부스만 촬영 명령과 완료 결과를 주고받으며, 기존 촬영 프로그램을 도입하더라도 자체 시작 버튼으로 이용권 확인을 우회할 수 없도록 연결을 검증한다.

## 6. 사진과 이용 기록

월 횟수 제한에는 대표 학생 키, 기준 연월, 부스·세션, 예약/사용/복구 상태와 시각을 사용한다. 동반 친구의 이름·계정·얼굴 인식은 이 기능에 필요하지 않다.

사진은 접근이 제한된 임시 저장소와 만료되는 다운로드 링크로 제공한다. 사진 보관 기간은 따로 정하며, 사진을 삭제했다고 월 이용 기록까지 초기화하지 않는다. 앱 앨범에 장기 보관하는 기능은 별도 선택 사항이다. 다음 이용자에게 이전 사진·학생 정보가 남지 않게 화면을 초기화한다.

## 7. 개발과 확인 순서

1. 혜택 대상과 현지 월 기준을 확정하고 현재 학생 계정 연결을 확인한다.
2. 서버 이용권·일회용 부스 연결·예약/완료/복구를 구현한다.
3. 앱에 이번 달 이용권과 QR 확인 화면을 연결한다.
4. 부스 프로그램에서 승인된 세션만 촬영할 수 있게 만든다.
5. 장비에서 실제 촬영·휴대폰 수령을 확인하고, 인화를 선택하면 실물 출력까지 확인한다.

필수 확인: 첫 이용 허용, 같은 학생 두 번째 이용 거절, 동반 친구 이용권 유지, 계정 복구 후 횟수 유지, 동시 요청 하나만 성공, 만료/재사용 QR 거절, 월 변경, 카메라·네트워크·인쇄 오류 후 복구, 비대상 학생 이용 거절, 다음 이용자에게 이전 사진이 보이지 않음.

현재 결과는 운영 기준과 연결 설계다. 코드 구현·앱 배포·장비 설치·실제 학생의 월 제한 검증은 아직 하지 않았다.
