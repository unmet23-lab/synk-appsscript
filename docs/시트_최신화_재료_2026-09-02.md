## 3. 압축 — 무엇을 줄일 수 있고, 무엇이 헛수고인가

### ✅ 줄일 것 = 빈 문자열 1,966개

### 🚫 헛수고 = ARRAYFORMULA 전환
웹 실측(2026): **1,000행 미만에서는 성능 차이가 없다.** 50,000행에서 개별 수식 45~90초 vs
ARRAYFORMULA 3~8초인데, **우리 시트는 데이터 2행**이다.
⇒ 「수식 1만개→40개」는 **지금 우리 규모에서 값이 0**이다. 안내문이 다른 규모를 전제하고 있다.

  오늘 고친 네 수식은 이미 그렇게 썼다.

## 7. ✅ 실행 결과 — 유호님이 「**ㄷ, ㄱ, ㄴ 가자**」로 셋 다 지시(09-02)

> 순서는 유호님이 정하셨다: **㉢(죽은 열) → ㉠(시간대) → ㉡(빈 문자열)**.
> 내가 낸 순서(㉠→㉢→㉡)와 첫 둘이 바뀌었을 뿐 뜻은 같다 — **지울 것을 알고 나서 지운다.**

### ㉢ 죽은 열 가리기 — **지울 열이 0개다**

「비어 있음」으로는 «죽은 열»과 «아직 안 채운 열»을 못 가른다(데이터가 2행뿐이라).
⇒ **자를 바꿨다: 「코드가 그 열 이름을 쓰는가」**로 갈랐다(데이터 양에 안 흔들린다).

```
104열 = 크루카드가 채움 79 + 다른 코드가 씀 25 + 아무 코드도 안 쓰는 열 0
```

⚠ 이 수를 내기까지 **자를 두 번 고쳤다**:
- `rg` 를 `execSync` 로 불렀더니 **전부 0** — 자가 고장난 것이었다(Node 가 직접 269벌을 읽게 고침).
- `\b` 가 한글에 안 통해 클래스 세기가 전부 0 → 속성값을 공백으로 쪼개 정확히 견줌.
- `s.includes(이름)` 이 「반」을 「반드시」에 물림 → **따옴표로 감싼 정확 문자열**로 재검.

### ㉠ 시간대 — **「오늘 접수」가 0 → 1 로 살아났다**

파일 → 설정 → 시간대를 **(GMT+08:00) 울란바토르**로. 확인: `NOW 2026-09-02 02:42 / TODAY 2026-09-02`.

### ㉡ 빈 문자열 청소 — **1,964개를 걷었고 진짜 값 71개는 안 다쳤다**

먼저 안전을 쟀다 — `5행 이하 진짜값 **0** / 5행 이하 COUNTA **1,964** / 3~4행 진짜값 **71**`.
⇒ 5행부터 496행까지 **잃을 것이 없다**. `A5:CZ496` 을 골라 **내용만** 지웠다(행은 남긴다 —
시트의 「행 삭제 금지」 규율에 안 걸리고 드롭다운·조건부 서식도 남는다).

| 자 | 전 | 후 |
|---|---|---|
| 전체 `COUNTA` (`A3:CZ496`) | 2,037 | **73** |
| **진짜 값** (`SUMPRODUCT((범위<>"")*1)`) | 71 | **71** ✅ 무손실 |
| 5행 이하 `COUNTA` | 1,964 | **0** ✅ |

🟡 **남은 빈 문자열 2개**는 3~4행(실데이터 행) «안»에 섞여 있어 골라내지 않았다. 1,966 → 2 = **99.9%**.

### 대시보드 — 음수가 사라지고 넷 다 「1건」

```
G63→총 접수 1건 | G64→반 배정 대기 1건 | G65→앱 미편입 1건 | G66→오늘 접수 1건
```
전엔 반 배정 대기 **−1**, 앱 미편입 **−492**, 오늘 접수 **0**이었다.
ZZ 통로시험 1건이 오늘 접수·반 미배정·앱 미편입 — **실물과 맞는다.**

### ✅ 곁들여 — **거짓을 적고 있던 안내문 두 줄을 고쳤다**

「최신화」가 겨눈 진짜 자리다. **오늘 내가 그 거짓을 믿고 헛걸음했으니 다음 세션도 똑같이 걸린다.**
낡은 문구가 든 셀을 셀 식으로 가려냈다(`REGEXMATCH` + `ADDRESS`) — **`사용안내!A24`·`A27` 둘뿐**.

| 셀 | 전 | 후 |
|---|---|---|
| `A24` | 「② **ARRAYFORMULA 최적화(수식 1만개→40개)**」 | ①③만 남기고 **「둘 다 아직 미착수(2026-09-02 확인)」** · ②는 「닫혔다: 수식이 0개라 줄일 것이 없다」 |

**이관 «때»의 기록**이지 현재 진술이 아니다. 지우면 역사가 사라진다 ⇒ **꼬리에 한 줄을 덧댔다.**

친 다음 `Home`+`Delete`로 앵커만 걷으면 들여쓰기가 남는다.

### ⚠ 이 과정에서 밟은 자 이야기 둘

  실물은 **496행**이었다. 「1000행쯤 되겠지」가 가정이었고, `Ctrl+End` 가 그것을 한 번에 답했다.

  `ADDRESS()&"→"&TO_TEXT()` 를 뽑으니 네 줄이 한 번에 나왔다. 화면 상태와 무관한 자다.

### 🔴 뒤늦게 잡은 것 — **「수식 0개」를 잰 자가 고장나 있었다**

청소를 마친 뒤 다른 탭을 재려다 드러났다. 대조군을 같이 돌린 것이 살렸다.

```
ISFORMULA(G63)            단일 셀  = TRUE   ← 내가 오늘 직접 고친 수식이 거기 있다
SUMPRODUCT(--ISFORMULA(G60:G70))  범위 = 0   ← 거짓
```

🔑 **`ISFORMULA` 는 범위를 받으면 배열로 안 펴진다.** `ARRAYFORMULA` 로 감싸도 마찬가지다.
⇒ 그 자는 **무엇을 재든 0을 낸다.** §1 의 「수식 셀 0」은 그 자가 낸 수다.

**그래서 두 가지를 다시 물었다.**

1. **내가 지운 것이 수식이었나?** — 안 건드린 실데이터 행으로 물었다:
   `3행 F=FALSE BG=FALSE BH=FALSE | 4행 F=FALSE … | 5행 F=FALSE …`
   ⇒ **아니다.** 「나이(자동)」·「학생ID」·「⚠위험신호(자동)」은 **Apps Script 가 «값»으로 채운다** —
   그래서 수식이 아니다. 앞뒤가 맞는다. **청소는 안전했다.**
2. **「ARRAYFORMULA 최적화는 불필요」 판정이 흔들리나?** — **아니다.** 그 판정을 떠받치는 것은
   「수식 0개」가 아니라 **「데이터가 2행」**이다(1,000행 미만은 성능 차이가 없다).
   근거 하나가 무너져도 결론은 선다.

⚠ **고장난 자가 낸 답이 우연히 참이었다.** 그래서 답은 그대로 두고 **자를 갈아 적었다** —
안 갈면 다음 사람이 그 자를 다시 집는다([[measurement-needs-its-instrument]]).

### 🟡 다른 탭에도 같은 병이 있다 — **재기만 했고 안 지웠다**

```
crew_cards 0 · crew_errors 0 · 반설정 0 · 학생카드 5 · 반별조회 320 · 수강납입 2,500
```

찍어 본 셀은 전부 `ISFORMULA=FALSE` 라 **수식이 반환한 빈 문자열이 아니라 값으로 박힌 것**으로 보인다.
다만 그 탭들의 구조를 안 봤고 **유호님이 고르신 범위는 상담데이터입력 하나**라 손대지 않았다.
🔑 **지우기 전에 물어야 할 것** = 그 탭들이 조회·계산 탭인데 수식이 정말 없나(있다면 지우면 깨진다).

## 8. 안 잰 것 (정직하게)

- **`AI()` 함수가 Business Starter 에서 실제로 도는가** — 메뉴 존재만 봤다.
- **다른 탭들의 빈 문자열을 «지워도 되나»** — 수를 세었고(§7 끝) 몇 셀은 수식이 아님을 봤지만,
  그 탭들의 «구조»는 안 봤다. 조회·계산 탭이라 수식이 어딘가에 있을 수 있다.
- **앱 schedule 연결** — 안내문이 「요청하세요」로 적어 둔 셋째 항목. 열지 않았다.
- **`onEdit` ID 발급기** — 미착수 상태만 확인했다.
