## 0. 한 줄 — 「수식 1만 개」는 **없었다**

시트 사용안내가 스스로 이렇게 적고 있다:

> 이관 직후 Claude에게: ① onEdit ID 발급기 ② **ARRAYFORMULA 최적화(수식 1만개→40개)** ③ 앱 schedule 연결

그래서 그 셋을 하러 갔는데, **실측하니 수식이 0개다.** ①②③은 「예정」으로 적힌 뒤 실행된 적이 없고,
②는 **애초에 할 것이 없다**(줄일 수식이 없다).

🔴 **진짜 병은 따로 있었다 — 빈 문자열 리터럴 1,966개.**

## 1. 실측 (2026-09-02 · 상담데이터입력 탭 · 시트 함수로 잼)

| 잰 것 | 값 | 자 |
|---|---|---|
| 수식 셀 (`A3:BZ500`) | **0** | `SUMPRODUCT(--ARRAYFORMULA(ISFORMULA(…)))` |
| `COUNTA` 가 «값»으로 세는 셀 (`A3:CZ600`) | **2,037** | `COUNTA` |
| 그중 **진짜 값** | **71** | `SUMPRODUCT((범위<>"")*1)` |
| ⇒ **빈 문자열 리터럴** | **1,966** (전체의 **96.5%**) | 위 둘의 차 |
| 헤더 열 (`2:2`) | **104** | `COUNTA` |
| 데이터 행 | **2** (김재헌 · ZZ 통로시험) | `COUNTA(A:A)` − 헤더 2 |
| 시트 시간대 | **(GMT-08:00) 태평양** | 파일 → 설정 |
| Apps Script 시간대 | `Asia/Ulaanbaatar` (GMT+8) | `appsscript.json` |

### 🔴 이것이 어제·오늘 사고의 뿌리다
`COUNTA` 는 빈 문자열을 «값»으로 센다. 그래서 **학생이 1명인데 `COUNTA(학생ID열)` = 492** 였고,
대시보드가 「반 배정 대기 **-1건**」·「앱 미편입 **-492건**」 음수를 유호님께 보이고 있었다.
(오늘 `SUMPRODUCT((범위<>"")*1)` 로 고쳤다 — 자를 바꿔 «증상»은 닫았지만 **원인인 1,966개는 그대로다.**)

## 3. 압축 — 무엇을 줄일 수 있고, 무엇이 헛수고인가

### ✅ 줄일 것 = 빈 문자열 1,966개
- 이걸 지우면 **`COUNTA`·`COUNTIF(,"")`·`COUNTBLANK` 가 전부 정직해진다.**
- 지금은 자를 바꿔 우회하고 있는데(`SUMPRODUCT`), **원인을 지우면 우회가 필요 없다.**
- 🔑 **이것이 이 시트에서 「압축」의 진짜 이름이다.**

### 🚫 헛수고 = ARRAYFORMULA 전환
웹 실측(2026): **1,000행 미만에서는 성능 차이가 없다.** 50,000행에서 개별 수식 45~90초 vs
ARRAYFORMULA 3~8초인데, **우리 시트는 데이터 2행**이다.
⇒ 「수식 1만개→40개」는 **지금 우리 규모에서 값이 0**이다. 안내문이 다른 규모를 전제하고 있다.
⚠ 다만 **범위를 못 박는 것**은 값이 있다(열 전체 `D3:D` → `D3:D2000`): 웹 실측 **40~60% 단축**.
  오늘 고친 네 수식은 이미 그렇게 썼다.

### 🟡 잴 것 = 104열 중 실제로 쓰는 열
진짜 값 71개가 2행에 흩어져 있다 ⇒ **평균 35열만 채워진다.** 나머지 70열이
「아직 안 채운 것」인지 「죽은 열」인지는 **안 갈랐다.**

## 6. 🔴 유호님이 고르실 자리

> 셋은 서로 독립이라 아무거나 먼저 해도 된다. **위험도 순으로 적었다.**

| | 할 일 | 값 | 위험 |
|---|---|---|---|
| **㉠** | **시간대를 울란바토르로** (파일→설정→시간대) | 시트의 **모든 날짜 판정**이 맞아진다 — 납입 예정·미납 빨간 행·이달 신규/퇴소·오늘 접수 | 낮음 · 되돌리기 한 칸 · **유호님 클릭 3번** |
| **㉡** | **빈 문자열 1,966개 청소** (Apps Script 한 번 · 진짜 값 71개는 안 건드림) | `COUNTA` 계열이 정직해진다 · 우회 수식이 필요 없어진다 · 앞으로 같은 사고가 안 난다 | 중간 · **운영 시트 대량 쓰기** · 되돌리려면 버전 기록 |
| **㉢** | **104열 중 죽은 열 가리기** (실제 쓰는 열 vs 안 쓰는 열) | 안내문 현행화 · 진짜 압축의 근거 | 낮음(재기만) · 그 뒤 «지울지»는 다시 판정 |

**내 판단 = ㉠ → ㉢ → ㉡.**
㉠은 지금 모든 날짜가 16시간 어긋나 있어 가장 급하고 가장 싸다.
㉢은 재기만 하는 일이라 위험이 없고, 그 결과가 ㉡의 범위를 정한다.
㉡은 마지막 — **무엇을 지울지 알고 나서** 지우는 것이 맞다(모르고 지우면 그게 다음 사고다).

⚠ **㉡ 은 되돌리기가 비싸다** — 시트 「행 삭제 금지」 규율이 있고, 대량 쓰기는 버전 기록으로만
  되돌린다. 그래서 ㉢ 뒤에 두었다.
