# SNS 검수형 자동발행 시스템 — 구현 기록

2026-09-10 KST. 콘텐츠 한 벌을 계정별로 변환·검사하고, 최종본 해시에 유호님 승인을 묶은 뒤, 공식 연결이 있는 채널만 발행하는 로컬 운영 도구를 만들었다. 글이나 영상이 바뀌면 기존 승인은 자동으로 무효가 된다.

## 이번에 실제로 만든 것

- `docs/마케팅/sns-계정.json`: 현재 20개 계정의 회사·채널·발행 방식·필수 설정을 한곳에 둔다. 비밀번호와 토큰은 넣지 않는다. 09-10 첫 게시물 묶음은 티스토리 추가 전 제작되어 19개 항목 그대로다.
- `tools/sns-자격.ps1`: 인증값을 평문 파일 대신 Windows 자격 증명 관리자에 `SYNK/SNS/...` 이름으로 저장·조회한다.
- `tools/sns-발행.js`, `tools/lib/sns-publisher.js`: 연결 점검, 발행 계획 생성, 해시 승인, 중복 방지, 발행 결과 기록을 맡는다.
- 직접 발행기: YouTube, Telegram, Pinterest, Facebook, Threads, LinkedIn, TikTok. Instagram은 승인된 HTTPS 미디어 호스트가 생기기 전까지 실패하도록 막았다.
- 수동 보조기: 네이버 블로그, 카카오톡 채널, 티스토리, Substack. 검수 파일을 정리하고 공식 편집 화면을 열어 최종 예약·게시만 사람이 한다.

```powershell
npm run sns:연결점검
node tools/sns-발행.js --계획 docs/research/sns-upload-20260910/첫게시물_발행계획.json
node tools/sns-발행.js --승인 <계획파일> --항목 <항목ID>
node tools/sns-발행.js --발행 <계획파일> --항목 <항목ID>
```

승인·발행 명령은 계획 안의 오류가 0개이고 계정 연결이 현재 유효할 때만 성공한다. 예약·업로드 결과는 외부 플랫폼 응답과 함께 기록하며, 로컬 파일 생성만으로 게시됐다고 보고하지 않는다.

## 유호님에게 남는 손

1. 게시하려는 최종본만 눈으로 확인하고 승인한다.
2. 처음 한 번만 각 플랫폼의 OAuth·본인 인증·앱 심사를 처리한다. 만료되거나 권한이 바뀐 때만 다시 한다.
3. 네이버·카카오·티스토리·Substack은 공식 편집기에서 예약 시간과 공개 대상을 확인해 최종 예약·게시한다.

그 밖의 계정별 변환, 파일명·비율·필수 필드 검사, 자막·썸네일 동봉, 승인 무효화, 중복 방지, 결과 기록은 도구가 맡는다.

## 티스토리 적용

09-10 유호님이 「AI가 게시용 완성본을 만들고 나는 붙여넣기·최종 검수만 한다」는 운영 조건으로 추가를 확정하고 `https://yuhobuilds.tistory.com/`을 개설했다. 티스토리는 공식 Open API를 2024년 2월 말까지 순차 종료했고 외부 API를 통한 글쓰기·수정·파일 첨부도 종료했으므로, 직접 발행 연결로 표시하지 않는다. [티스토리 공식 종료 공지](https://notice.tistory.com/2664), [공식 API 문서의 종료 안내](https://tistory.github.io/document-tistory-apis/)

자동화 도구에는 `shift-tistory`를 `manual-assisted`로 등록하고, `Tistory` 플랫폼 이름과 `본문.md` 필수 검사를 추가했다. 앞으로 AI가 제목·본문·이미지·대체텍스트·링크·분류·검색 설명까지 한 묶음으로 만든 뒤 승인 해시를 고정하고 공식 편집기를 연다. 유호님에게 남는 것은 공개 전 최종 확인과 게시 동작이다. 티스토리는 실제 회사 작업의 긴 과정 원문, 네이버는 국내 검색용 재구성, `synk.im`은 회사·상품 공식 정본으로 역할을 나눈다.
