## 1. 무엇이고 무엇이 아닌가

**2026-10-01 구현 상태:** `strata/maps/ko.json`(기존 기술 30·문법 91·오류 태그 23, 출처 해시 포함)과 `strata/index.js` 순수 조회(마디·선행·태그로·다음후보)가 있다. 정확 대응 8/미대응 15를 유지한다. 선행 관계는 0개이고, 문법 91개 중 62개(3~5급 문법 전부 포함)는 아직 어느 기술에도 묶이지 않았다. 급수로·목표로·일로/날로·길, 상황 마디, AI 초안은 아직 없다(한글 층은 10-03에 생겼다 — 아래 §3의 한글 층 줄). Core의 교육 어댑터가 문항에 적힌 마디와 정확 태그 연결을 학습 항목으로 쓰고, Trail·Temper가 그 마디 단위로 기록·집계한다. 게임 전면 재개발(10-01 사용자)로 G4 연결은 걷었다. 재생성은 `node tools/strata-build.js --check`로, 교육 앱 쪽 어긋남은 talk `tests/atlas-strata-drift.test.js`로 확인한다. [적용 결과와 보완](아틀라스_교육업그레이드_20260930.md)

개인에게 맞는 학습을 제안하려면 학습자의 현재 상태와 배울 내용의 구조를 함께 알아야 한다. 학습자에 대한 정보는 아틀라스의 이해 요약에서 관리한다. **Strata는 배울 내용을 관리한다.** 내용을 학습 항목으로 나누고, 먼저 배워야 할 내용·급수·목표와의 관계·오류 유형을 연결한다. 아래 함수와 코드에서 쓰는 `마디`는 이 학습 항목을 뜻한다.

**2026-10-02 분야 확장:** 회사가 개인화 엔진 기업으로 정체성을 다시 확인함에 따라 마디 종류에 분야와 무관한 `concept`·`topic`·`task`를 더했다. 상담·업무·생활 같은 비언어 콘텐츠도 같은 지도 형식으로 학습 항목을 둘 수 있다. 실제 비언어 지도는 그 콘텐츠를 만들 때 검수해서 추가한다([순간 맞춤](아틀라스_순간맞춤_20261002.md)).

**2026-10-02 추가 확인:** 미니게임의 TOPIK I 듣기·읽기 15개 연습 항목은 별도 원본 [topik-i.skills.json](../strata/topik-i.skills.json)에서 [topik-i.json](../strata/maps/topik-i.json)으로 생성한다. `node tools/build-game-learning.js --check`가 원본 해시와 게임용 공통 소비 사본의 일치를 확인한다. [game-browser.js](../atlas/game-browser.js)가 이 지도를 열고 Core의 형식·난이도별 요약과 추천에 전달한다. `ko.json`의 기술·문법 지도와 목적이 다른 자료이며 중급 전체 경로가 생긴 것은 아니다. [strata.test.js](../tests/strata.test.js)로 원본 재생성, 누락·순환·급수 역전 거부, 초안 선행의 비차단, 호출자 변경 격리를 확인했다. 현재 코드에 재현된 조회 오류는 없어 조회 모듈을 임의로 다시 나누지 않았다.

| Strata가 맡는 것 | 맡지 않는 것 |
|---|---|
| 학습 항목·관계·급수·난이도·콘텐츠 생성 자료 | 학생별 상태(아틀라스의 이해 요약에서 관리) |
| 과목마다 한 장의 지도(한국어 · 영어 · AI 활용 · 면접 준비) | 평가 기준과 채점(사람의 일) |
| 학생에게 그대로 보여 줄 수 있는 자료 | 집단 분포(Prism의 일 — Strata는 그 결과 중 **난이도 값만** 받는다) |

학습 항목을 구조화하되 학생에게 등급이나 순위를 매기는 데 사용하지 않는다. 엔진 이름은 `Strata`이며, 「배울 것의 지도」는 역할을 설명하는 표현이다.

## 3. 자료 모양 [제안]

과목별 학습 지도를 파일 하나에 저장한다. 제안 경로는 appsscript `strata/maps/<과목>.json`이며, 첫 파일은 `ko.json`이다. `atlas/`처럼 입출력과 계산을 분리하고, 사용하는 저장소에도 같은 방식으로 사본을 동기화한다.

```json
{
  "map_ver": "strata-ko-0.1.0", "subject": "ko", "built_at": "…", "sources": { "GRAMMAR_BANK": "<지문>", "skills": "<지문>", "tags": "<지문>" },
  "nodes": [
    { "id": "skill-ko-grammar-honorific", "kind": "skill", "label_ko": "높임 — -(으)시-·어휘 높임", "label_mn": null,
      "level": { "intro": 2, "basis": "grammar_bank" },
      "difficulty": { "authored": null, "measured": null, "n": 0 },
      "material": { "target_forms": ["-(으)시-"], "frames": [] } },
    { "id": "G211", "kind": "grammar_point", "label_ko": "…", "level": { "intro": 2, "basis": "grammar_bank" } },
    { "id": "sit-professor-email", "kind": "situation", "label_ko": "교수님께 메일 쓰기", "for_events": ["deadline"] },
    { "id": "sit-job-interview", "kind": "situation", "label_ko": "면접에서 자기소개하기", "for_events": ["interview"] },
    { "id": "sit-new-year-greeting", "kind": "situation", "label_ko": "새해 인사 나누기", "for_days": ["seollal", "tsagaan_sar"] }
  ],
  "edges": [
    { "from": "G211", "to": "skill-ko-grammar-honorific", "type": "part_of", "confidence": "authored" },
    { "from": "skill-ko-grammar-particle-topic", "to": "skill-ko-grammar-honorific", "type": "prerequisite", "confidence": "ai_draft", "reviewed": false }
  ],
  "links": {
    "tags":  [ { "tag": "높임:주체", "node": "skill-ko-grammar-honorific", "fit": "full" }, { "tag": "어미:연결어미", "node": null, "fit": "none" } ],
    "goals": [ { "goal": "study_abroad", "nodes": ["sit-professor-email", "skill-ko-grammar-honorific"] } ]
  }
}
```

- **id는 새로 짓지 않는다.** 기술은 `skill_id`, 문법은 `G###`을 그대로 쓴다. 상황만 `sit-…`로 새로 붙인다.
- **한글 층**(2026-09-19 추가): 마디 종류 `letter`(자모)·`syllable`(음절 꼴)을 둔다. 선행은 `authored`다 — 모음 → 자음 → 음절 → 쌍자음·이중모음 → 받침 → 낱말. 헷갈리는 짝(ㅓ/ㅗ · ㅈ/ㅊ/ㅉ 등)은 `contrasts_with`로 적고, 자료가 쌓이면 Prism이 모국어별 실제 분포로 `measured`를 단다(헷갈리는 짝은 모국어마다 다르다). 급수는 Lv1 안이며 `stage: "hangul"` 표시를 가진다 — 없는 급수(0급)를 지어내지 않는다. 아틀라스의 한글 단계가 이것을 읽는다([한글 단계 설계](한글단계_설계.md) · 구현 명세 §4-16). 소리로 가를 수 없는 짝(ㅐ/ㅔ 등)은 짝에 `by_ear: false`를 단다. **2026-10-03 첫 구현:** [strata/hangul.json](../strata/hangul.json)(원천) → `strata/maps/hangul.json`(`tools/build-hangul-stage.js`, LF 기준 해시). U1~U4 글자 22개가 `letter` 마디(`level: null` — 급수 밖이라 급수를 붙이지 않고 `unit`을 단다), 단원 순서가 `prerequisite` 85개(앞 단원의 각 글자 → 다음 단원의 각 글자), 짝이 `contrasts_with` 19개(한 짝에 한 줄, `bases: sound|shape`, `by_ear`)다. 음절은 마디로 두지 않고 글자에서 만든다. 능력은 `ko.hangul.sound`(듣기)·`ko.hangul.read`(읽기). 한국어 MVP [한글 단계](../experiences/hangul-stage/README.md)가 읽는다. 짝은 출발값이고 아직 `reviewed: false`다.
- 초급 풀의 문장(구현 명세 §4-15)은 지도 밖의 콘텐츠 파일이고 마디 id를 가리킨다. 지도는 문장을 담지 않는다.
- 마디 종류: `skill` · `grammar_point` · `expression` · `situation` · `letter` · `syllable`. 관계 종류: `part_of`(문법 코드 → 기술, DB `parent_id`와 같은 뜻) · `prerequisite`(먼저 알아야 함) · `contrasts_with`(헷갈리기 쉬운 짝).
- 상황 마디는 `for_events`(일의 종류 값목록 — 시험·면접·발표·여행·행사·마감)와 `for_days`(달력 표의 날)를 가질 수 있다. 아틀라스의 「미리 준비」와 「두 나라의 달력」이 이것을 읽는다(구현 명세 §4-7·§4-13). 연결이 없으면 그 장면은 조용히 일어나지 않는다 — 억지로 잇지 않는다.
- **목표 연결의 값 — 2026-10-02.** `links.goals`의 목표 값은 공개판 가입의 [「배우는 이유」 열 가지](공개판_설계.md#learn-reasons)(`culture`·`travel`·`people`·`life`·`study`·`work`·`career`·`exam`·`hobby`·`other`)를 쓴다. 이유마다 상황 마디 묶음을 잇는다. 예를 들어 `travel`은 길 묻기·주문·교통·숙소, `career`는 메일·회의 보고·전화·일정 조율, `people`은 안부·호칭·높임말 고르기, `life`는 주민센터·병원·은행·공공 안내문으로 간다. 위 자료 모양 예시의 `study_abroad`는 이 목록 이전의 이름이며 새 지도는 `study`를 쓴다. `other`이거나 이유를 고르지 않은 사람은 목표 연결 없이 고르게 연습한다. 목표 연결은 연습할 상황을 고르는 데만 쓰고 실력·급수·나이를 짐작하는 근거로 쓰지 않는다. 2026-10-02 현재 실제 지도 파일(`strata/maps/*.json`)에는 목표 연결이 아직 없고, 상황 마디와 예문은 앞으로 작성한다. **2026-10-03 구현:** TOPIK I 지도에 상황 마디 26개와 `links.goals` 일곱(culture·travel·people·life·study·work·career)을 넣었다. 원천은 `strata/topik-i.situations.json`이고, 이름과 순서는 계약 r1의 「상황」 칸 그대로다(시험이 같은지 본다). id(`sit-…`)는 계약 글자가 바뀌어도 그대로 두고, exam·hobby·other는 장면이 아니어서 잇지 않는다. 상황 마디는 `level: null`이고 능력·선행 관계를 갖지 않으며, Vellum 이유 한 줄의 빈칸(`when_ko`, 「주문할 때」)을 가진다. 묶음은 사용자가 승인한 계약이라 `authored`·`reviewed: true`다. 읽는 함수는 `forGoal(goal)`(위 `목표로`)이다. **2026-10-05 예문 층:** 상황 마디마다 그 자리에서 쓰는 말 세 개(78문장)를 지도와 나뉜 층으로 두었다. 원천은 `strata/topik-i.situation-examples.json`, 읽는 곳은 `strata/topik-i-examples.js`의 `situationExamples(map).examplesFor(상황 id)`다. 지도(`maps/topik-i.json`)와 게임 묶음에는 넣지 않아 지도 판(`map_ver`)이 바뀌지 않고, 예문을 보이는 곳(계정 요약)만 이 층을 읽는다. 일곱 문장은 게임 문항 글 그대로이고(주문 폭주의 주문 셋, 입장 검사의 안내문 셋, 바람길의 길 안내 하나 — `from`, 시험이 같은지 본다) 나머지는 초급 문형으로 새로 쓴 초안이다. 문장마다 지도의 문형 읽기(`topik-i-forms.js`의 `grammarIn`)가 읽은 문형을 함께 낸다(고르기와 검수의 실마리, 문형 읽기를 넘긴 호스트에게만 — 78문장 가운데 47문장에서 하나 이상). 모두 `ai_draft`이고, 교원이 확인한 문장은 원천의 `review.reviewed`에 id와 그 문장을 함께 적는다(확인은 그 문장에 묶여, 나중에 문장을 고치면 다시 초안이 된다). 예문은 연습의 장면만 보여 주며 실력·급수·난도를 바꾸지 않는다. 예문을 넣으며 문형 읽기가 잘못 읽던 것을 고쳤다 — 「모르겠어요」를 과거로(「했겠어요」는 과거로 남는다), 「안녕하십니까」를 -(으)니까로, 「더 주세요」「하나 주세요」「세 개 주세요」를 -아/어 주세요로 읽지 않는다(「사 주세요」「끝내 주세요」「차를 대 주세요」는 그대로 -아/어 주세요). 게임들의 문형 연결 표는 그대로다(시험으로 확인).
- 급수가 없는 마디는 `level: null`이다. 없는 급수를 지어내지 않고, 「없음」을 「범위 밖」과 합치지 않는다 **[확인: `lib/문법급수.js`의 원칙]**.
- 모든 관계와 연결에는 **근거의 종류**를 표시한다: `authored`(기존 정본) · `measured`(측정 자료) · `ai_draft`(AI 초안). 사람이 검토했으면 `reviewed: true`를 추가한다.
- `engine.skills`의 초기 데이터를 이 지도에서 생성한다. 지도는 원본이고 DB 표는 파생 자료다. 처음 전환할 때는 기존 문항 팩에서 만든 초기 데이터와 결과가 같아야 한다(§8).

## 4. 읽는 함수의 설계와 구현 경계

아래 한국어 이름·인자는 최초 설계 계약이다. 실제 호출은 `strata/index.js`의 export와 해당 지도 소비자를 따른다. 구현된 `forGoal`을 아직 없는 기능으로 세지 않으며, 설계된 모든 조회·경로·자동 갱신이 완성된 것으로도 읽지 않는다.

모두 같은 입력에 같은 결과를 반환하는 순수 함수로 만든다. 학생 자료를 받는 함수는 `다음후보`뿐이며, 아틀라스의 이해 요약에 담긴 항목만 받는다. 아래 함수명과 인자명은 기존 설계 식별자를 유지한다.

| 함수 | 돌려주는 것 | 지키는 것 |
|---|---|---|
| `마디(id)` | 마디 하나 | 없는 id는 `null` — 비슷한 것으로 메우지 않는다 |
| `선행(id, {최소믿음})` | 먼저 알아야 하는 마디들 | 믿음 등급으로 거를 수 있다 |
| `태그로(tag)` | 그 오류 유형이 가리키는 마디 또는 「대응없음」 | 23개가 빠짐없이 둘 중 하나로 나뉜다 |
| `급수로(level)` | 그 급에 도입되는 마디 · 급이 없는 마디 · 범위 밖 — **세 칸** | 세 칸을 합치지 않는다. 고르는 것은 소비자 몫이다 |
| `목표로(goal, level)` | 그 목표로 가는 길 위의 마디 | 목표를 평가하지 않는다 |
| `일로(kind)` · `날로(day)` | 그 일·그날에 맞는 상황 마디 | 없으면 빈 목록 — 비슷한 것으로 메우지 않는다 |
| `길(지금 마디들, 목표)` | 남은 마디를 선행 순서로 편 목록 | 순환이 있으면 오류 — 조용히 끊지 않는다 |
| `다음후보(줄들, 목표, {개수})` | 겨냥 후보와 각 후보의 `targets`(이해 줄 열쇠) | 같은 `map_ver`와 같은 줄이면 같은 결과 |

`다음후보`의 결과는 아틀라스의 학습 목표 선택 항목인 `core.aim`에 전달된다(구현 명세 §4-1). 지도가 비어 있으면 빈 목록을 반환하고, 아틀라스는 기존 선택 방식으로 동작한다.

## 5. 사람 손 없이 자란다

학습 지도는 기존 자료 조립, AI 초안, 자동 검증과 단계적 적용으로 갱신하도록 설계한다. 사람의 검토를 매번 기다리지 않아도 작동하되, 검토 결과가 있으면 관계의 근거에 추가한다([아틀라스 설계 §3](아틀라스_설계.md#3-자동-맞춤의-범위--옛-금지의-재검토)).

1. **기계 조립.** §2의 재료를 도구가 읽어 첫 판을 만든다. 같은 재료면 같은 지도가 나온다. 재료의 지문을 `sources`에 남긴다.
2. **AI 초안.** 비어 있는 곳 — 오류 유형 15개가 가리킬 마디, 선행 관계, 상황과 마디의 연결, 짓는 재료 — 을 AI가 **후보 판**으로 제안한다. 초안은 `ai_draft`로 표시되고 원본 지도를 덮지 않는다.
3. **자동 검증.** 후보 판은 아래를 통과해야 한다. 사람의 승인은 필수 단계가 아니다.
   - 선행 관계에 순환이 없다. 고아 마디가 없다.
   - 선행을 따라가면 급수가 내려가지 않는다(먼저 배우는 것이 더 높은 급이면 그 관계를 버린다).
   - 오류 유형 23개가 「이어짐/대응없음」으로 정확히 나뉜다. **억지로 잇지 않는다** — `fit: "full"`이 아니면 「대응없음」이다.
   - 기존 `authored` 관계를 뒤집지 않는다.
   - 모의 실험(구현 명세 §6-2)에서 후보 버전으로 전체 처리 과정을 실행했을 때 운영 지표가 나빠지지 않는다.
4. **부드러운 선행.** `ai_draft` 관계는 **막는 데 쓰지 않는다.** 겨냥 후보의 점수를 조금 낮추는 데만 쓴다. `authored`·`measured`이거나 사람이 본 관계만 「선행이 비었으니 아직 아니다」로 쓸 수 있다. 틀린 초안 하나가 학생의 길을 막지 못하게 하는 장치다.
5. **자료로 고친다.** 학생 자료가 쌓이면 Prism이 마디별 난이도와 「이 선행이 실제로 도움이 되는가」를 재서 `measured`로 올린다. 조건(독립 학생 수·표본)은 Prism의 규칙을 따른다. 그 전에는 `null`이다.
6. **단계적 적용과 복구.** 새 버전은 아틀라스의 규칙 버전과 같은 절차로 일부 대상부터 적용하고 전체로 확대한다. 지표가 급락하면 이전 버전으로 자동 복구한다. 지도가 바뀌면 실행 버전도 올린다.

강사나 콘텐츠 담당자가 관계를 검토해 `reviewed: true`로 표시하면, §5-4에 따라 선행 조건 판단에도 사용할 수 있다. 몽골어 이름(`label_mn`)의 원어민 검수도 별도로 기록한다. 검토 여부와 자동 갱신 가능 여부는 구분한다.

## 6. 누가 읽나

| 읽는 쪽 | 쓰는 것 |
|---|---|
| Core | `다음후보`로 겨냥을 고르고, `길`로 본인 목표까지 남은 것을 안다 |
| Vellum | 이유 한 줄과 질문에 쓸 **사람의 말**(`label_ko`·`label_mn`). 마디 id는 화면에 나오지 않는다 |
| Loom | 「내 지도」 — 자기가 지나온 마디가 채워지는 화면. **자기 것만** 보이고 다른 학생·평균·등수는 없다 |
| Trail | 어디까지 왔는지를 마디로 말한다 |
| Prism | 마디별 분포를 재서 난이도를 돌려준다 |
| Temper | 결과를 마디 단위로 잇는다 |
| 생성(AI) | 마디의 `material`(겨냥할 형태·예문의 틀)을 입력으로 받는다 |

## 7. 과목마다 한 장

과목별로 지도를 분리하고 조회 함수는 공통으로 사용한다. LAB의 한국어·영어와 회화·AI 활용·비자 면접 준비 과정에 각각 지도를 둘 수 있다. 다른 사업에서는 학생 자료 없이 Strata만 사용해 과정 안내나 교재 구성을 만들 수 있다. 새 과목을 추가할 때도 공통 처리 구조를 재사용한다.

바깥 기준(예: 국립국어원의 한국어 교육과정 자료)을 재료로 쓸 때는 출처·판·이용 조건을 확인하고 `sources`에 적는다. 이용 조건은 아직 확인하지 않았다.

## 8. 첫 판 만들기 — 인수 기준

| 단계 | 하는 일 | 끝났다는 증거 |
|---|---|---|
| ① 조립 | 도구(제안 `tools/strata-build.js`)가 §2의 1~6을 읽어 `strata/maps/ko.json`을 만든다 | 기술 30 · 문법 코드 91 · 오류 유형 23이 전부 들어 있고, 다시 돌려도 같은 파일이 나온다 |
| ② 대조 | 지도에서 생성한 `engine.skills` 초기 데이터와 기존 초기 데이터를 비교한다 | 기술 30개의 id·이름·영역이 글자까지 같다 |
| ③ 급수 | 마디의 급수가 `GRAMMAR_BANK`의 도입급과 같고, 축이 없는 마디는 `null`이다 | `lib/문법급수.js`의 기존 시험과 같은 답 |
| ④ 나눔 | 오류 유형 23개가 이어짐 8 · 대응없음 15로 나뉜다(지금과 같다) | `tests/태그기술표.test.js`와 같은 성질 |
| ⑤ 읽기 | §4의 함수와 시험 | 빈 지도에서 고리가 지금처럼 돈다 · 순환은 오류로 드러난다 · 같은 판과 같은 줄이면 같은 후보 |
| ⑥ 자라기 | §5의 2~4 — 후보 판과 자동 검증 | 일부러 넣은 순환·급수 역전·억지 연결을 검증이 잡는다 · `ai_draft` 선행이 후보를 막지 못한다 |

첫 판의 목표는 **새로 짓는 것이 아니라 한 자리에 모으는 것**이다. ④까지는 동작이 하나도 바뀌지 않아야 한다. 오류 유형 15개가 가리킬 마디를 만드는 일은 ⑥부터다.

## 9. 지키는 선

- 학생별 상태를 두지 않는다. 지도에는 개인정보가 없다.
- 평가 기준을 두지 않는다. 「이 마디를 익혔다」의 판정은 Strata의 일이 아니다.
- 뜻이 온전히 겹칠 때만 잇는다. 빈 연결은 비워 둔다.
- AI 초안은 막는 데 쓰지 않는다(§5-4).
- AI 초안 생성은 비용 안전장치의 한도 안에서 실행한다(구현 명세 §6-3). 한도를 넘으면 그날의 지도 갱신만 중단한다.
- 학생에게 보이는 것은 자기 지도뿐이다.
- 계약 JSON·`GRAMMAR_BANK`·문항 팩은 각자의 정본으로 남는다. Strata는 그것을 **읽어 모으고**, 거꾸로 덮어쓰지 않는다. 정본을 Strata로 옮길지는 첫 판이 돈 뒤에 정한다.

## 10. 상태

첫 판의 조립·나눔·읽기 일부는 코드와 지도 파일로 있다(§1의 2026-10-01 상태). DB(`engine.skills`) 생성·대조(§8 ②)와 §5의 자라기는 아직이다. 옛 퀴즈 팩(talk `contents/토픽퀴즈문항.js`)이 폐기되면 지금 그 파일에서 읽는 기술 표를 Strata의 원본으로 옮긴다. 2026-09-21 사용자 요청으로 현재 소개와 [엔진 8종 역할표](엔진8종_상향설계_v3.md#0-2-여덟-엔진의-역할)를 Strata를 포함한 여덟으로 통일한다. 표기 정리는 구현·배포나 상세 설계 전체의 승인을 뜻하지 않는다. 홈페이지의 여덟 엔진 소개는 09-19에 다른 세션이 게시했다(트랙 기록 기준 · 공개 `7b94794` · Strata는 「추가 예정」으로 표시) — 소개가 게시됐다는 것이지 이 엔진이 구현됐다는 뜻이 아니다. 이름의 몽골어 원어민 검수는 하지 않았다(몽골어 대사전 mongoltoli 자동완성에서 `страта`는 미등재였다).

**2026-10-03 읽기 게임 문항의 문형 연결:** 레이싱(13문항, 손으로)·빈칸 베기·입장 검사·이야기 교실 문항이 쓰는 문형을 `conceptIds`로 남긴다(교원 검수 전 초안). 연결은 `strata/topik-i-forms.js`가 읽는다. 빈칸은 정답과 빈칸 뒤 말로(`grammarOf`), 입장 검사는 손님을 판단하는 근거 규칙 문장으로(`grammarIn`), 이야기 교실은 누가·무엇을·어디에 뒤의 조사(`particleAfter`)와 부탁 문장으로(`grammarIn`) 읽는다. 문장에서는 TOPIK I 낱말 목록의 명사를 어미로 읽지 않는다(병원 뒤에, 1시간 후에, 편지만). 그래서 명사와 모양이 같은 동사는 놓친다(옷을 산 후에). 게임마다 연결표가 이 함수의 결과와 같은지 시험이 본다. 같은 날 추천도 검토 §4에 적힌 규칙대로 고쳤다. 놓친 문형·낱말은 능력 상태가 같은 후보 사이에서만 앞세우고, 다른 능력을 앞지르게 하지 않는다(`atlas/learning.js`, 게임 묶음 8개 새로 만듦). 정책판 `learning-priority-3`은 그대로다.
