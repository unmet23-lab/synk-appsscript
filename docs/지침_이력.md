## v7.12 (2026-08-04) — 라우팅은 훅보다 넓어야 한다 (v7.11 조항 정정)

유호님 지시(「훅 5종에도 등록층 검사 붙여줘」 — v7.11 제안 ①의 채택). 5종을 실측했더니 **구멍 2개가 더 있었다.**

- **구멍 ②: `git -C <경로> …`를 규칙 5개가 하나도 못 잡았다.** 전부 `\bgit\s+add\b`처럼 서브커맨드가 `git` 바로 뒤에 온다고 가정했는데, 실제로 상시 쓰는 형태가 `git -C <경로>`다(settings.json 권한 목록에도 그 형태가 잔뜩 있다). 처방은 **공용 접두사 `G`** — 전역 옵션(`-C <경로>`·`-c k=v`·`--no-pager` 등)을 흡수하는 정규식 조각 하나를 규칙 5개가 공유한다(호출부마다 고치면 다음 규칙에서 또 틀린다). `-C` 값은 ④⑤의 git 상태 조회 `cwd`로도 쓴다 — 안 그러면 남의 저장소 상태로 판정한다.

  🔑 **구현 전에 쟀다**(F047 전례) — PostToolUse 가 이 저장소에서 검증된 적이 없어, 탐침 훅으로 payload 를 먼저 실측했다(`tool_input.command` + `tool_response.stdout` 둘 다 온다). 안 쟀으면 훅을 다 짜고 나서 「출력이 안 온다」를 발견했을 자리다.
  🔴 **탐침이 남의 세션 호출을 물어 왔다** — 내 명령은 `git rev-parse` 였는데 탐침 파일엔 다른 세션의 `git status … git log origin/master..HEAD` 가 들어 있었다(그 트리엔 `Code.js`·`엔진_수집.js` 등이 미커밋). ①의 실측을 실시간으로 한 번 더 확인해 준 셈이고, **훅 상태 파일을 세션 공용 경로에 두면 마지막 세션이 이긴다**는 실례이기도 하다(`lib/handoff-store.js` 의 `safeId` 가 존재하는 이유와 같은 함정).
- **④ 반박이 잡은 거짓양성 1건 — 자기 언급 함정.** 증상 문구를 **출력 원문**에서 찾으면, git 이 성공 시 되뱉는 제목 줄(`[master 6c76663] feat: nothing to commit 을 잡는 훅`)에 걸려 **성공한 커밋이 빨개진다.** 이 저장소는 커밋 제목에 가드 이야기를 자주 쓰므로 실제로 터졌을 자리다. 처방 = 제목 줄(`^[<branch> <sha>]`)만 걷어내고 본다 — `commit A && commit B` 에서 B 만 비는 경우는 그대로 잡힌다. 「가드가 실작업을 벌주면 사람이 가드를 끈다」(F049) 계열.

- ↳ **미해소로 남긴 것**: 이 조항은 **기계로 못 옮긴다**(「사람에 관한 사실」을 훅이 판별할 수 없다). 프로즈가 맞는 자리라 판단했고, 재발하면 그때는 **대외 발송 직전 게이트**(발송 통로에 원본 대조 확인을 끼우는 층)로 올린다.
