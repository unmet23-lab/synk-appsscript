## 4-9. ⛔ 컬렉션/탭 만들 때마다 거치는 관문 4가지 (v947.1 신설 — 2026-07-24 전수 점검 회귀 장치)

> **왜 신설**: 07-23~24 전수 점검에서 **편집 권한 결함 13건**이 나왔다. 전부 "Glide 기본값을 안 껐다"가 원인이고, 구 가이드에 끄라는 지시가 없었다. 아래 4가지는 **컴포넌트를 만든 직후 그 자리에서** 처리한다. 나중에 몰아서 하면 반드시 빠진다.

### ① 탭 표시조건 — 만들자마자 즉시
새 탭은 **표시조건이 공백 = 전원 노출**로 태어난다.
- 실사고: 원장 「경영」 탭을 만들고 조건을 안 걸어 **학생 하단바에 경영 재무가 노출**됐다.
- 규칙: 탭을 만든 **다음 클릭**이 Options → Visibility → `role is <역할>`. 화면 내용보다 먼저.
- 값: `student` / `parent` / `teacher` / `director`. 학부모 폼처럼 민감하면 `role is parent` **AND** `user_id is not empty`로 이중.

### ② 컬렉션 add·edit·delete — 기본이 ON이다
Glide는 컬렉션을 만들 때 **add·edit을 켜서** 준다. 읽기 전용 카드면 전부 꺼야 한다.
- Actions 탭 → `Allow users to add / edit / delete items` 3종.
- **원본 데이터를 물고 있는 컬렉션은 특히 위험** — 실사고 목록:
  | 화면 | 소스 | 안 껐을 때 |
  |---|---|---|
  | 랭킹 | **profiles** | 학생이 **가짜 프로필 생성·타인 프로필 수정** ← 최고 위험 |
  | 도감 | **contents** | 학생이 문법·퀴즈·몬스터 **원본 콘텐츠 뱅크 편집** |
  | 소식 | notices·raid_story·synk_stories·synk_cards | 학생이 공지·스토리북 작성·수정 |
  | 랭킹 | achievements | 업적 조작 |
- **켜 두는 게 맞는 것**: 원장 폼(공지·칭호·전당·크루)의 add, 납부 원장(payments)의 add·edit. 그 외는 원칙 OFF.
- **고급 액션 모드**(스토어 등)는 토글이 아니라 **액션 슬롯**이다 — TITLE BAR의 `Show form screen(Add)`, 아이템의 `Show edit screen(Edit)`을 각각 휴지통으로 제거.

### ③ 상세 화면 Edit 버튼 — Title 컴포넌트에 숨어 있다
상세 화면 우상단 `✏️ Edit`의 정체 = **Title 컴포넌트의 `Show edit screen` 액션**.
- 제거: Title 선택 → ACTIONS → 그 항목 클릭 → CONFIGURE ACTION 우상단 **휴지통**.
- 학생·학부모 상세는 전부 제거(4건 실사고). 제거되면 ACTIONS에 `Add action`만 남는다.

### ④ Image 자동 오매핑 — 신규 컬렉션마다 확인
Glide가 **텍스트 열을 Image에 멋대로 매핑**해 빈 회색 박스를 만든다(누적 6건: 반 목록·문의함·출결·출퇴근·onboarding·경영계기판).
- ITEMS DATA의 Image를 보고, 텍스트 열이 들어가 있으면 **⋮⋮ → Clear value**.
- 반대로 `사진URL`·`image_url` 같은 **진짜 이미지 열이면 그대로 둔다**(명예의 전당·크루·스토어).

### 조립 후 자가 검증 (역할별 1회)
`Viewing as`를 **학생 계정**으로 바꾸고 하단바를 본다 → 학생 탭 5개(홈·도감·스토어·소식·랭킹)만 보이면 정상. 원장·강사·학부모 탭이 하나라도 보이면 ①이 빠진 것.
