# 싱크타운에서 내 행동으로 달라지는 생활

2026-10-02 설계. 플레이어가 선택하고 만든 일이 NPC의 행동, 공간, 다음 부탁과 이후 만남에 남도록 만드는 제작 기준이다. 학생은 좋아하는 생활을 계속하면서 자신의 영향과 한국어의 성장을 알아볼 수 있어야 한다.

사용자 요청은 “체감이 만들어지도록 필요한 부분을 전체적으로 설계”하는 것이다. **아래는 그 요청에 따른 설계안이며, NPC 동작·서버 저장·플레이 테스트를 완료했다는 뜻은 아니다.** 정책값은 검증할 출발값이고 효과 측정 결과가 아니다. 구체 NPC 이름·미술·목소리·상품 가격은 해당 정본의 미정 상태를 유지한다.

**2026-10-02 후속 반영:** 사용자가 승인한 여섯 보완 방향을 §8~§12에 포함했다. 완료한 보람을 현재 방문에서 확인하고, 선택과 개인 배치를 안심하고 바꾸며, 편하게 끝내고 이어 하고, 익숙한 생활을 지키면서 개인화하고, 성장한 만큼 편해지는 경험을 만든다. 새 화면을 늘리는 대신 기존 행동 목록·꾸미기·대화·이웃 수첩 안에서 처리한다. 세부 처리값은 구현·관찰로 확인할 설계값이다.

**2026-10-02 생활 콘텐츠 연결 반영:** 생활 제작·작은 가게·주민 사연·발견 정원을 [첫 생활 구간](디자인/싱크타운_첫생활구간_설계.md#scope)의 찻집 앞 쉼터로 연결한다. 원하는 입구 하나로 완결하고, 준비물 마련부터 실제 쓰임·다음 방문·다른 후속 선택까지 이어지게 설계한다. 재배·채집·제작의 과정과 수치는 그 문서, 엔진 입력과 실제 소비처는 [Atlas 연결 계약](아틀라스_구현명세.md#town-life-adapter)이 맡는다. 콘텐츠 선택 방향은 사용자 요청을 반영했으며 시간·수량·장면은 검증할 출발값이다.

읽는 순서는 이 문서의 공통 규칙 → [첫 생활 구간](디자인/싱크타운_첫생활구간_설계.md) → [생활 사건집](디자인/싱크타운_생활사건_설계.md) → [Atlas 구현 명세](아틀라스_구현명세.md#town-world-contract)다. 실제 장면·재방문·경제·학습·상품의 원고는 [제작 패키지](디자인/싱크타운_제작패키지.md)에서 이어 읽는다. [마을 설계](마을_설계.md)는 앱 안의 위치와 공간, [주민 설계](주민_설계.md)는 캐릭터, [대화 설계](대화_설계.md)는 한국어 입력과 도움을 맡는다. 사건별 수치와 대사를 여러 문서에 복사하지 않는다.

## 1 플레이어가 얻어야 할 경험

비 오는 날 기다릴 곳이 없다는 찻집 손님의 말을 듣는다. 나는 차양을 만들거나 기존 처마 아래 좌석을 마련하는 방법을 고른다. 차양을 선택하면 다음 비에 주민이 그 아래에서 기다린다. 좌석을 선택하면 주민이 앉아 쉬고 자리를 함께 쓰는 다른 부탁이 이어진다. 나중에 다른 방법도 선택할 수 있지만, 지금 무엇을 만들었는지와 그 결과는 분명하게 남는다.

이 경험은 다음 다섯 가지를 함께 만족해야 한다.

1. **원인이 보인다.** 무엇을 했기 때문에 변화가 생겼는지 플레이어가 알아볼 수 있다.
2. **결과가 실제로 다르다.** 중요한 선택은 NPC의 동작·이용 가능한 기능·공간·후속 활동 중 하나 이상을 바꾼다.
3. **다음 만남에 이어진다.** 재접속 뒤에도 결과와 약속이 남고, 같은 일을 처음 한 것처럼 되풀이하지 않는다.
4. **새로운 선택이 생긴다.** 예전 일을 인정하는 데서 끝나지 않고 달라진 생활에서 다음 목표가 나온다.
5. **학생이 주도한다.** 거절·연기·관심 변경·조용히 지내기를 선택해도 생활 성과가 사라지거나 죄책감을 받지 않는다.

모든 터치에 큰 반응을 붙이지 않는다. 물 주기 같은 반복 조작에는 물과 작물의 변화가 있으면 충분하다. 제작 완료·생활 문제 해결·이야기의 결정처럼 의미 있는 사건에는 눈에 보이는 결과와 이후 연결을 마련한다. NPC에게도 고유한 취향·일과·목표가 있어 같은 사건을 각자의 방식으로 받아들인다.

**제품 조건:** 메인 앱 내부 TOPIK 1급+ 통과 뒤에 생활과 NPC 경험을 시작한다. 일부 체험 무료·정액제·선택 상품의 범위를 따른다. 기본 생활과 반응은 검수된 콘텐츠와 규칙으로 실행하며 실행 중 AI 호출을 필수로 하지 않는다. 혼자서 모든 핵심 이야기를 완결할 수 있고, 16명 이웃은 함께 사는 느낌을 더한다. 사람끼리 자유 채팅은 제공하지 않는다.

## 3 무엇을 기억하고 무엇을 바꿀지

하나의 호감도나 플레이 시간으로 모든 것을 결정하지 않는다. 아래 상태는 용도와 소유 범위를 나눠 저장한다.

| 상태 | 무엇을 포함하나 | 바꾸는 근거 |
|---|---|---|
| 플레이어의 생활 목표 | 현재 하고 싶은 일, 선택한 해결 방법, 방문·소개 허용, 도움 선호 | 본인의 선택. 관측 추정은 확인 전까지 추천 후보로만 사용 |
| 개인 생활 상태 | 집 배치, 소유 물건, 가게의 메뉴·서비스, 개인 이야기 분기 | 실제 완료가 확인된 제작·배치·전달·선택 사건 |
| NPC의 고유 상태 | 성격, 취향, 바라는 일, 평소 일정, 지금 가능한 동작 | 검수한 캐릭터 설정과 현재 세계 상태 |
| NPC와 나의 관계 | 서로 아는 사실, 함께한 사건, 신뢰의 이유, 허용된 교류 | 해당 NPC가 직접 겪거나 정해진 경로로 알게 된 사건 |
| 퀘스트와 약속 | 해결할 문제, 선택한 방식, 진행, 연기·거절, 완료 결과 | 플레이어와 NPC의 확인된 선택 및 조건 충족 |
| 반응 전달 이력 | 어떤 사건을 누가 어떤 행동·대사로 실제 전달했는지 | 화면에서 표현을 마쳤다는 확인. 후보 선정만으로 기록하지 않음 |
| 공동 마을 상태 | 공개 시설, 허용된 공동 기여, 계절·시간·날씨 | 공동 공간 권한이 확인된 변경과 세계 달력 |
| 언어 학습 상태 | 영역별 이해·표현, 도움 사용, 새로운 상황의 독립 수행 | 학습 관측 계약. 납품·접속·호감으로 대신하지 않음 |

**과거 사실과 현재 상태를 구분한다.** “내가 의자를 만들어 줬다”는 함께한 사건으로 남아도, 의자를 철거했다면 현재 의자 사용은 불가능하다. 기억을 지워 달라는 선택은 해당 사실을 이용한 대사·추천·대기 반응에도 적용한다. 이미 지급한 소유물이나 필요한 거래 증빙을 지우는 행위와는 구분해 학생에게 설명한다.

개인 이야기는 개인 범위가 기본이다. 다른 사람의 선택 때문에 내 NPC 이야기가 완료되거나 내 언어 난도가 올라가지 않는다. 공동 시설에 참여했다면 실제 맡은 역할만 기록한다. NPC가 비공개 집·대화·학습 약점을 저절로 아는 연출은 만들지 않는다.

## 4 행동이 세계 변화가 되는 순서

### 중요한 사건의 제작 단위

사건 하나는 대사가 아니라 아래 묶음으로 제작한다. 사건집 C01~C08은 이 구조의 구체 사례다.

| 제작 항목 | 반드시 정할 내용 |
|---|---|
| 원인과 완료 판정 | 누가 무엇을 선택·전달·완성했는지, 미리보기와 실제 완료의 구별 |
| 시작 조건 | 필요한 소유물·공간·앞 사건·NPC 인지·학습 해금·이용권 |
| 의미 있는 선택 | 최소 두 해결 방법 또는 목표, 각각 달라지는 상태, 거절·연기 경로 |
| 즉시 결과 | 눈앞에서 바뀌는 행동·물건·메뉴·기능과 원인을 알 수 있는 짧은 표현 |
| 이후 결과 | 다음 적절한 만남의 행동, 유지할 흔적, 후속 의뢰 또는 새로운 선택 |
| 전달 조건 | NPC가 아는 이유, 실제 동작 가능 여부, 이미 보여 준 것과의 중복 |
| 변경과 복구 | 철거·반납·취향 변경·중단·이용권 종료·재접속 때의 상태 |
| 학습 연결 | 대표 능력, 필요한 표현, 쉬운 대안, 도움·관측 조건 |
| 검증 | 다른 선택의 결과, 원인이 없을 때 미발생, 재접속, 중복, 체감 확인 |

### 확정과 표현의 분리

처리는 **선택 확인 → 생활 사건 확정 → 현재 상태 반영 → 알고 있는 NPC의 반응 후보 → 전달 가능한 때 표현 → 전달 기록 → 다음 후보 갱신** 순서다. 학습 결과는 같은 활동에서 얻을 수 있으나 별도 관측으로 보낸다.

화면만 먼저 바꾸고 저장 실패를 숨기지 않는다. 상태가 확정돼도 NPC가 화면 밖에 있거나 동작할 수 없으면 그 표현은 대기한다. 핵심 효용을 확인할 경로는 [현재 방문의 결과 확인](#comfort-result)으로 마련하고, 특정 날씨·현실 시간까지 무기한 기다리게 하지 않는다. 완료한 행동을 못 봤다고 같은 선물이나 보상을 다시 주지 않는다. 보상 지급과 반응 전달은 별도 상태로 관리한다.

| 반응 상태 | 의미와 다음 처리 |
|---|---|
| `proposed` | 사건에 맞는 후보. 아직 인지·물건·권한을 통과하지 않음 |
| `eligible` | 현재 근거와 조건을 충족. 우선순위 비교 가능 |
| `queued` | 다음 자연스러운 장면에서 전달 대기. 실행 직전에 다시 조건 확인 |
| `delivered` | 실제 표현 완료 확인. 한 번만 할 감사·설명은 다시 전달하지 않음 |
| `expired` | 정해 둔 전달 기한이 지난 반응. 첫눈 인사의 시효가 끝나면 자연스럽게 종료. 기한 전이라도 날씨·물건·인지 조건이 없어졌다면 `cancelled` |
| `cancelled` | 철거·공유 철회·근거 정정 등으로 부적합. 잘못된 반응과 후속 후보를 취소 |

대기 중 새 사건이 생기면 현재 사실에 맞게 다시 고른다. 우산을 돌려받은 뒤 늦게 도착한 ‘우산을 쓰는 반응’은 실행하지 않는다. 이미 본 감사는 끝나도 우산을 실제 사용하는 일상 동작은 해당 소유·날씨 조건 안에서 계속 가능하다.

### NPC의 생활과 플레이어의 영향

NPC는 자신의 일을 계속하다가 가능한 시점에 반응한다. 손님을 응대하는 중이면 바로 따라오지 않고 일을 마친 뒤 방문하거나 편지로 이어 준다. 플레이어가 아무 일도 하지 않아도 기본 일과·날씨·마을 소식은 흐른다. 그중 플레이어의 영향이 있는 변화에는 원인 사건을 연결하고, 자연 발생한 일을 플레이어 공로로 말하지 않는다.

물건 이용은 접근 가능한 위치, 올바른 소유·배치, 동작 자산, 좌석 점유를 확인한다. 사용할 수 없으면 이동 경로를 재계산하거나 현재 가능한 행동으로 바꾸되 ‘사용했다’는 사실은 만들지 않는다. 대안이 없으면 반응을 미룬다.

<a id="relationships"></a>
## 5 관계는 함께한 사건으로 깊어진다

기존의 대화 횟수·날수만으로 친밀도를 올리는 규칙을 대체한다. 익숙함, 함께한 일에 대한 신뢰, 무엇을 서로 아는지는 구분한다. 학생에게 점수나 사람끼리의 순위를 보여 주지 않는다.

다음은 첫 제작에서 사용할 단계 조건이다. 시간·횟수 조건을 덧붙이지 않으며, 각 조건은 사건 ID와 허용된 관계 상태로 확인한다.

| 단계 | 진입 근거 | 생활에서 달라지는 것 |
|---|---|---|
| 처음 만남 | 아직 함께한 장면이 없음 | 쉬운 인사와 선택. 이름 공개 없이도 진행 가능 |
| 얼굴을 아는 사이 | 서로의 첫 만남을 완료 | 알아보는 몸짓과 본인이 허용한 호칭. 기본 부탁은 이 단계부터 가능 |
| 함께한 일이 있는 사이 | 그 NPC와 해결한 생활 사건 하나가 확인됨. 도움을 받아도 인정 | 그 결과를 실제로 이용하고 관련 이야기를 이어 감 |
| 서로 맡기는 사이 | 다른 맥락의 공동 사건을 추가로 해결하고, NPC도 도움·보답을 실제 전달 | 방법을 플레이어에게 맡기는 의뢰. 방문·말 놓기는 각각 별도 선택 |
| 오래 이어가는 사이 | 긴 이야기의 한 갈래를 완결하고 계속 이어갈 교류를 플레이어가 선택 | 개인 기념물, 다음 생활 계획, 후속 이야기의 동료 역할 |

마지막 단계는 접속 기간을 뜻하지 않는다. 오래 쉬어도 단계와 완료 성과를 내리지 않는다. 새로운 이야기 분기는 추가할 수 있으며 최고 단계가 더 어려운 한국어를 강제하지 않는다. 같은 사건 재전송·반복 납품·구매·대화만 반복하는 것으로 다음 단계를 채우지 않는다.

이름·개인 취향을 알려 주지 않아도 관계를 키울 수 있다. 취향에 맞는 선물 대신 함께한 사건을 기념하는 물건을 제공한다. 친절·성실함 같은 성격을 행동량으로 점수화하지 않는다.

NPC의 요청을 거절하면 다른 해결 방법을 찾거나 일을 보류한다. 플레이어에게 죄책감을 주거나 관계를 낮추지 않는다. 다만 **어떤 일을 함께했는지는 달라지므로** 이후 대사·사용하는 물건·관련 의뢰도 실제 이력에 맞게 달라진다.

<a id="quests"></a>
## 6 선택에 따라 달라지는 부탁과 이야기

각 이야기에는 NPC가 원하는 것과 해결할 생활 문제가 있다. ‘정답 선택’ 하나로 통과시키기보다 서로 다른 따뜻한 해결 방법을 준비한다. 선택으로 NPC가 불행해지는 벌칙은 만들지 않으면서 메뉴·공간 사용·역할·행사 모습·후속 부탁은 달라지게 한다. 결말의 큰 정서가 같아도 생활 결과와 다음 경험까지 같아서는 안 된다.

분기는 무한히 늘리지 않는다. **공통 시작 → 두세 해결 경로 → 경로별 흔적과 후속 활동 → 공통 다음 이야기**를 기본으로 한다. 다시 합쳐진 뒤에도 선택한 메뉴·방문 방식·기념물과 NPC가 아는 사실은 보존한다. 방법을 바꾸고 싶으면 필요한 현재 자원·공간을 확인해 변경 사건을 만들며 과거 도움의 기록을 지우지 않는다.

| 퀘스트 상태 | 플레이어 경험과 전이 |
|---|---|
| `available` | 조건이 맞는 후보. 아직 의뢰를 보여 주지 않음 |
| `offered` | NPC가 이유와 가능한 방법을 알려 줌. 수락 전 자원을 소비하지 않음 |
| `accepted` | 학생이 맡기로 선택. 필요한 자원이 있는지 확인 |
| `active` | 선택한 해결 경로를 진행. 다른 경로·연기·그만두기 허용 |
| `resolved` | 경로별 완료 조건과 실제 효과가 확정. 보상·후속 후보를 한 번 생성하되 후속을 자동 제안·수락하지 않음 |
| `deferred` | 지금 하지 않음. 원할 때 수첩에서 재개. 자동 재촉 없음 |
| `declined` | 이번 의뢰를 거절. 같은 의뢰는 학생이 다시 찾거나 상황이 실질적으로 바뀌기 전까지 재권유하지 않음 |
| `invalidated` | 대상 철거·권한/소유 변경 등으로 현재 경로 불가능. 사용 전 예약 자원 해제, 가능한 대안과 사실 안내 |

진행 중 그만두면 사용하지 않은 예약 자원은 돌려주고, 이미 만든 소유물·완료한 부분의 성과는 보존한다. 상대에게 이미 전달한 물건을 자동으로 회수하지 않는다. 경로별 반환 가능 범위를 수락 전에 보이게 한다. 마감은 서사적 상황에 쓰되 현실의 결석으로 필수 이야기를 잃게 하지 않는다. 계절이 지났다면 기록 읽기·다음 행사 준비 등 동일 능력과 가치가 있는 대체 경로를 제공한다.

퀘스트는 현재 가능한 생활 문제에서 고른다. 학습 약점이 있다는 이유만으로 그 NPC에게 없는 물건이나 아직 발생하지 않은 사건을 요구하지 않는다. 같은 능력을 연습할 수 있는 가게·정원·탐색의 대안이 있으면 학생이 고른 생활 목표를 우선한다. 부족한 콘텐츠를 다른 능력으로 채우고 원래 목표를 완료했다고 표시하지 않는다.

<a id="freshness"></a>
## 7 다시 와도 새로운 이유를 만드는 규칙

신선함은 무엇이 다른지로 구분한다. 날씨·시간·인사말만 바뀐 장면은 새로운 생활 사건으로 세지 않는다. 사건의 문제, 내가 맡는 역할, 선택 가능한 해결 방법, 실제 결과, NPC 관계 맥락 중 적어도 하나가 달라져야 새로운 경험 후보로 분류한다.

### 후보를 고르는 순서

1. 해금·이용권·실제 세계 상태·NPC 인지·언어 대안·표현 가능성을 먼저 확인한다.
2. 플레이어가 지금 선택한 일과 그 일의 즉시 결과를 우선한다.
3. 이미 한 약속의 이행과 아직 보지 못한 중요한 결과를 고른다.
4. 선택한 생활 목표의 다음 단계와 필요한 학습 기회를 비교한다.
5. 최근 경험과 의미가 다른 발견·주민의 생활·자유 활동을 보탠다.

각 후보에는 사건 계열, 이전 원인, 문제 유형, 해결 방식, 결과 유형, 최근 전달을 붙인다. 같은 계열의 장면을 NPC나 물건 이름만 바꿔 새 사건으로 세지 않는다. 시드는 같은 조건에서의 동률 선택에만 쓰며 무작위가 사실·이야기 순서를 바꾸지 않는다.

**첫 정책값:** 다음 추천에서는 최근 완료한 생활 사건 3개와 같은 문제·해결 조합을 뒤로 보낸다. 미해결 약속·플레이어가 직접 선택한 반복 활동은 이 제한보다 우선한다. 같은 사건을 알아보는 대표 NPC는 한 명으로 두고, 다른 NPC에게도 반응이 필요하면 실제로 다른 후속 행동 하나만 허용한다. 수치는 구현·플레이 테스트에서 조정하며 신선함의 입증으로 사용하지 않는다.

### 노출과 소진

| 플레이 이력 | 준비해야 할 새 경험 | 반복해도 괜찮은 일 |
|---|---|---|
| 첫 방문 | 짧은 행동 하나로 바로 바뀌는 물건이나 NPC 동작 | 조작 익히기·산책·기본 인사 |
| 첫 5회 정도의 방문 | 서로 다른 선택 결과, 다음 만남의 기억, 다음 목표의 발생을 한 번씩 경험 | 좋아하는 꾸미기·기본 영업 |
| 약 10회까지 | 두 생활 분야를 오가는 후속 사건, NPC에게 도움받기, 해결 방식 변경 | 이미 익힌 일을 편하게 즐기기 |
| 약 30회까지와 그 이후 | 완결한 이야기의 다른 역할·새로운 생활 문제·여러 NPC가 연결된 계획 | 유지하는 가게·정원·관계와 자발적 재플레이 |

방문 횟수는 관계 해금 조건이 아니라 **제작 분량과 반복을 검사하는 시나리오**다. 30회 내내 새 퀘스트를 주겠다는 상품 약속이 아니다. 사건집 8개만으로 장기 신선함이 충분하다고 판정하지 않는다. 실제 분기·방문 기록으로 어떤 회차에 후보가 소진되는지 확인하고 필요한 후속 팩을 제작한다.

후보가 소진되면 완료된 일을 새 부탁처럼 위장하지 않는다. 자유 생활, 본인이 고르는 재플레이, 다른 주민·활동 탐색을 제공한다. 새 이야기가 준비되지 않았다면 수첩에는 지금 즐길 수 있는 활동만 보여 준다. 구독 상품은 출시 전에 제공 범위·지속 업데이트의 실제 제작 가능량을 [BM-10](BM_목록.md#synk-town-bm)에 맞춰 정해야 한다.

### 변화가 한꺼번에 밀려오지 않게 하기

플레이어가 행동해서 생기는 즉시 피드백과, 앱이 먼저 말을 거는 일은 구분한다. 기존 자동 말걸기 하루 한 번 예산은 유지한다. 학생이 말을 걸거나 의뢰를 수락해 진행 중인 상호작용을 이 예산 때문에 끊지 않는다.

한 장면에서 눈에 띄게 소개하는 큰 변화는 하나를 기본으로 한다. 다른 변화는 다음 자연스러운 만남으로 미룬다. 오랜만에 돌아와도 누적된 감사·행사·선물을 팝업으로 연속 재생하지 않는다. 지금 중요한 결과 하나와 선택해서 보는 ‘그동안 달라진 것’을 제공한다. 날씨 인사처럼 시효가 지난 대사는 폐기하고, 실제 소유 보상과 약속은 사라지지 않게 별도로 보존한다.

<a id="presentation"></a>
## 8 내 행동의 결과를 알아보게 보여 주기

중요한 사건은 다음 세 시점의 표현을 설계한다.

| 시점 | 보여 줄 것 | 예 |
|---|---|---|
| 행동 직후 | 내가 바꾼 대상의 변화와 짧은 반응 | 차양이 펼쳐지고 사장님이 진열대를 옮김 |
| 다음 적절한 만남 | 변화가 생활에 쓰이는 모습 | 비 오는 날 그 아래에서 기다리는 손님 |
| 이후 이야기 | 결과를 이용하는 새 선택 | 그 공간에서 모임을 열지, 평소 쉼터로 둘지 선택 |

플레이어가 만든 물건은 선택한 색·모양·위치로 알아볼 수 있어야 한다. NPC가 다른 기본 물건을 쓰면서 플레이어가 만든 것처럼 말하지 않는다. 큰 변화에는 원인을 짚는 쉬운 한 문장을 붙일 수 있다. 설명을 읽지 않아도 동작과 공간에서 차이를 볼 수 있게 한다.

반응을 놓친 경우 다시 보기 가능한 수첩의 사건 항목으로 연결한다. 수첩은 기존 ‘이웃 수첩’ 안의 **함께한 일**을 확장한다. 날짜·구체 행동·현재 남은 결과·연결된 다음 선택만 보이며 원시 로그·엔진명·호감 점수·추천 가중치를 노출하지 않는다. 반복 알림 대신 학생이 원할 때 확인한다.

작은 화면에서는 기존 행동 목록에 지금 할 수 있는 일과 달라진 대상 하나만 강조한다. 강제 카메라 이동·여러 배지·대사와 성장 팝업의 동시 출현을 피한다. 이동 중 긴 글을 띄우지 않는다. 시각적으로 찾기 어렵다면 ‘보러 가기’를 선택할 수 있게 하며 강제로 이동시키지 않는다.

움직임 줄이기나 낮은 성능 기기에서는 ‘주민+내 의자에 앉은 상태’처럼 같은 사실을 나타내는 정지 장면을 제공한다. 소리를 끄거나 읽기 도움을 써도 사건과 보상은 같다. 자산이 없거나 표현이 실패했다면 전달 완료로 기록하지 않고, 같은 사실을 표현하는 검수된 대안이 있을 때만 대체한다.

학생의 반응도 다음 경험에 반영한다. ‘더 이야기하기’는 해당 대화를 확장하고, ‘지금은 조용히’는 현재 상호작용만 말 대신 행동·개인 기록으로 전달한다. 별도의 명시적 설정 ‘앞으로 먼저 말 걸지 않기’는 자동 인사를 중지하는 계정 선호로 저장하고 수첩에서 언제든 해제한다. 이 설정에서도 내가 말을 걸었을 때의 응답·물건의 실제 사용·수락한 의뢰의 진행은 유지한다. ‘이런 부탁은 쉬고 싶어요’ 역시 해당 계열 추천 제외를 명시적으로 선택한 경우에만 유지하고 해제할 수 있다. 침묵·짧은 체류·연결 종료·음성 실패를 성격이나 불만으로 자동 해석하지 않는다.

<a id="comfort-result"></a>
### 완성한 쓸모를 현재 방문에서 확인하기

중요한 사건마다 **현재 방문 안에서 플레이어가 원할 때 볼 수 있는 실제 효용 장면**을 하나 준비한다. 차양을 만든 직후에는 주인이 그 아래에 물건을 놓고 자리를 이용하고, 비 오는 날 손님이 모이는 모습은 이후의 추가 변화로 둔다. 새 메뉴는 첫 제작분을 실제로 내는 장면으로, 집 초대는 지금 방문 가능한 주민의 짧은 일과 마침과 이동으로 연결한다. 특정 현실 시각의 로그인·다음 비·반복 방문 횟수를 핵심 결과의 조건으로 삼지 않는다.

사건을 제작할 때 현재 조건에서 실행할 기본 장면과 조건별 대안을 함께 정한다. 개인 결과를 위해 공유 날씨를 바꾸거나, NPC를 두 장소에 동시에 놓거나, 하지 않은 사용을 편지·회상으로 했다고 꾸미지 않는다. 현재 상태와 같은 의미의 정지 표현은 허용하지만 과거 영상은 과거로 표시한다. 필요한 동작·상태·권한을 준비하지 못했다면 저장된 성과와 미전달 상태를 보존하고 준비 중임을 짧게 알린다. 출시 전에는 핵심 결과가 이 대기 상태에 계속 머무는 사건을 수정한다.

결과를 반드시 끝까지 보게 하지는 않는다. 기존 ‘보러 가기’로 직접 확인하고, 그냥 머물거나 종료할 수도 있다. 건너뛰어도 성과·보상은 보존하고 나중에 자발적으로 확인하게 한다. 화면 밖에서 일어난 결과를 플레이어가 봤다고 기록하지 않는다.

<a id="comfort-choice"></a>
### 선택의 차이를 알고 개인 배치를 되돌리기

중요한 선택은 쉬운 말과 작은 그림으로 **바뀌는 용도·필요한 재료·유지되는 것**을 먼저 보여 준다. 차양은 서서 기다리는 자리, 좌석은 앉아 쉬는 자리라는 차이를 알아볼 수 있게 한다. 이야기 전체의 결말을 설명하거나 선택마다 확인창을 띄우지는 않는다. 처음 쓰는 꾸미기 조작은 이미 아는 표현으로 미리 해 볼 수 있게 하고, 새 조작과 새 언어 부담을 동시에 추가하지 않는다.

배치 미리보기는 소유물·재료·관계·보상·퀘스트를 바꾸지 않는다. 놓기 전에 주민의 통로와 실제 사용 가능 여부, 진행 중 의뢰에 영향을 주는 대상을 표시한다. 저장 직전 현재 상태를 다시 확인하고, 상황이 달라졌으면 새 배치를 강제로 확정하지 않고 가능한 자리를 안내한다.

개인 공간의 직전 배치는 기존 소유물을 이용해 **‘되돌리기’**로 복원할 수 있게 한다. 대상의 위치·소유·관련 상태가 그대로일 때 별도 비용 없이 보정하고, 이미 다른 기기에서 바뀌었거나 물건을 전달·소비한 뒤에는 가능한 복원 범위를 알려 준다. 공동 공간의 다른 사람 변경이나 거래·보상을 함께 되감지 않는다. 과거 성취와 실제 NPC 인지·전달 이력은 유지한다. 배치 때문에 잠시 불가능해진 미완 의뢰는 조건을 다시 검사해 이전 진행에서 이어 가되 완료 보상은 다시 주지 않는다. 직전 편집의 복구를 추가 상품으로 판매하지 않으며, 이용권 만료 시에도 이 제한된 복구가 새 유료 편집을 열어 주지는 않는다.

<a id="comfort-finish"></a>
### 완성한 뒤 편하게 끝내기

한 사건은 **확정된 결과 → 주민의 실제 이용 또는 선택해서 보기 → 자유롭게 머물기·떠나기**로 끝맺는다. 후속 후보를 만들었다고 완료 대사 뒤에 새 부탁을 연속으로 붙이거나 다음 의뢰를 자동으로 제안하지 않는다. 학생이 기존 행동 목록이나 수첩에서 다음 일을 직접 열면 그때 `offered`로 바꾼다. 완료 화면을 닫으려는 사람에게 새 부탁의 수락·거절을 요구하지 않는다.

자동 말걸기 예산이 남아 있어도 이 마침표를 깨지 않는다. ‘지금은 쉬기’나 종료 뒤 같은 회차에 남은 자동 권유를 다시 시작하지 않고, 다음 회차에도 쌓인 부탁을 몰아주지 않는다. 별도 휴식 대시보드·완료 설문·강제 감상 시간을 추가하지 않는다. 저장 대기 여부는 작은 상태 표시로 알리고, 끝낸 일을 계속 붙잡아 두는 장치로 쓰지 않는다.

<a id="comfort-resume"></a>
### 멈췄다가 맥락을 잃지 않고 이어 하기

개인 대화·꾸미기·제작에는 중단 가능한 지점을 두고, 앱 전환이나 종료를 답변 실패로 처리하지 않는다. 읽기·대답·재청취 중에는 생활 UI의 답변 제한 시간을 두지 않는다. 이미 확정한 제작·재료·보상은 유지하고, 단순 미리보기·미제출 선택은 확정 상태와 구분한다. 중단한 사람이 자원을 무기한 점유하지 않도록 사용 전 예약은 해제하고, 재개할 때 현재 자원과 권한을 다시 확인한다. 공동 날씨·다른 이웃의 활동은 함께 정지하지 않는다.

돌아오면 기존 대화나 행동 목록에 **하던 일, 마지막으로 끝낸 부분, 지금 가능한 다음 행동**만 짧게 보여 준다. 한국어를 다시 읽고 들을 수 있으며, 긴 튜토리얼이나 완료한 과제를 반복하지 않는다. 대상이 철거됐거나 콘텐츠가 바뀌었으면 달라진 사실과 대안을 알리고 성과를 보존한다. 이용권이 끝났으면 기록·기존 소유물 회수는 유지하고 새 유료 활동은 권한에 맞게 처리한다.

재개용으로 계정에 남기는 것은 허용된 사건·장면·단계·선택 키다. 작성 중인 자유 입력과 음성은 기존 기기 전용·민감정보 처리 범위를 넓히지 않는다. 다른 기기에서는 저장된 단계부터 재개하되 로컬 초안까지 복원된다고 표시하지 않는다. 실제 전송·확정 여부가 불명확하면 확인 후 이어 가며, 같은 입력을 다시 보내도 재료와 보상이 중복 반영되지 않는다.

<a id="comfort-adaptation"></a>
### 개인화가 익숙한 생활을 지키게 하기

Atlas의 변화 한도·뒤집힘 억제·본인 설정 우선 원칙을 마을의 장면 경계에 적용한다. 시작한 장면의 목표·현재 문장·보기·입력 방식은 새 학습 기록이나 정책 갱신만으로 중간에 바꾸지 않는다. 자동 조정은 다음 장면부터 적용하며 익숙한 가게·동선·직접 선택한 활동의 입구는 유지한다. 학생이 요청한 도움·쉬운 말·소리·읽기 설정은 즉시 반영한다. 이 안정성 규칙으로 만료된 권한이나 철거된 물건까지 과거 상태로 고정하지는 않는다.

추천을 고치려면 현재 추천의 작은 메뉴에서 **‘오늘은 다른 일’과 ‘이런 일은 덜 추천’**을 구분한다. 앞의 선택은 이번 회차에만, 뒤의 선택은 명시한 사건 계열에만 유지한다. ‘덜 추천’은 순위를 낮추는 뜻이며, 직접 찾는 활동까지 숨기거나 기존 ‘이런 부탁은 쉬고 싶어요’의 추천 제외와 혼동하지 않는다. 추정 근거가 틀렸다면 ‘그때만 한 거예요’로 그 추정을 정정할 수 있다. 실제로 했던 사건·학습 기록을 지우는 동작으로 사용하지 않는다.

바뀌는 범위를 짧게 알리고 같은 자리에서 되돌릴 수 있게 한다. 추천 이유는 원할 때만 열며 설정 전체를 다시 입력하게 하지 않는다. 저장 실패를 성공한 선호 변경으로 표시하지 않고, 한 번의 행동·침묵·오답을 장기 취향으로 승격하지 않는다. 새 제어판을 만들지 않고 현재 추천 메뉴와 기존 수첩을 사용한다.

<a id="learning"></a>
## 9 생활의 성장과 TOPIK 준비를 함께 잇기

세계의 결과는 실제 생활 선택에서 나온다. 같은 의자를 만들었다면 초급자와 중급자 모두 NPC가 그 의자를 사용하는 결과를 받는다. 언어 상태는 그 사건을 이해하고 참여하는 방식에 반영한다. 학습이 어려웠다고 완성한 공간·관계·해금을 되돌리지 않는다.

| 같은 생활 주제의 확장 | 연습할 능력 | 지원과 다음 확인 |
|---|---|---|
| 의자 하나 놓고 주민을 초대 | 물건·위치·짧은 요청 | 그림과 한 문장. 다른 물건·장소에서 다시 확인 |
| 비 오는 날 주문·예약 변경 | 수량·시간·조건·부정의 듣기와 읽기 | 한 번에 새 부담 하나. 자막·재청취와 독립 이해를 구분 |
| 손님 후기와 공간 개선 | 이유·순서·핵심·여러 정보 연결 | 짧은 글에서 문단 전체로 확장. 다른 내용의 안내로 확인 |
| 주민 설문을 보고 행사 제안 | 자료 비교·원인 결과·의견과 근거·연결된 쓰기 | 짧은 안내문에서 자료 설명과 의견글로 확대. 새 자료의 독립 수행 확인 |

이는 4급 준비를 위한 콘텐츠 경로 설계이며 생활 단계와 공식 급수를 일대일 대응하지 않는다. TOPIK II는 듣기·읽기·쓰기를 평가하며, 자료 설명·의견 전개를 포함한 쓰기까지 별도로 준비해야 한다([공식 시험 안내](https://www.niied.go.kr/web/niied/contents/niied_topik), [공식 쓰기 안내](https://exam.topik.go.kr/nasdata/webnas/raonkeditordata/uploadId/2024/02/20240227_175504804_07236.pdf)). 말하기와 NPC 관계는 유용한 생활 경험이지만 공식 점수의 대체물이 아니다.

각 사건에 대표 학습 능력, 선수 표현, 처음 소개하는 표현, 응답 형식, 듣기 전달 상태, 도움, 변형 계열을 붙인다. 현재 Strata의 TOPIK I 듣기·읽기 범위에 없는 중급 담화·쓰기는 **추가 제작·교육 검수 대상**으로 표시한다. 존재하지 않는 마디나 쓰기 채점기를 현행 엔진에 이미 있는 것으로 넣지 않는다. TOPIK 4급 전체 교육과정·문항 은행의 완성은 이 생활 반응 설계와 별도 완료 항목이다.

엔진은 학생의 목표와 이용 가능한 사건을 먼저 확인하고, 그 안에서 소개·연습·간격을 둔 재확인을 배치한다. 좋아하는 활동만으로 어떤 능력이 비면 다른 활동의 대안을 제안한다. 거절해도 생활을 막지 않으며 준비 현황에는 미확인 영역을 남긴다. ‘모름’과 ‘약점’을 구분한다.

대사를 이해하지 못한 것과 이야기를 거절한 것을 구분한다. 자유 입력의 의도가 불확실하면 물건·선택지를 짚어 확인한 뒤 생활 상태를 바꾼다. 도움받아 완성한 사건도 동일한 생활 보상을 받되 학습에서는 도움받은 수행으로 남긴다. 처음 보는 다른 상황과 나중 회차의 수행으로 도움을 조정한다. 쓰기를 AI가 대신 완성했다면 학생의 독립 쓰기 증거로 세지 않는다.

생활 과정과 메인의 학습은 같은 능력 지도를 사용한다. 마을을 선택하지 않아도 메인의 4급 학습 경로는 유지한다. 마을을 주로 이용한 학생은 부족한 영역과 목표 시험 방식에 맞는 짧은 연습·모의평가를 집의 학습 자리 또는 메인에서 이어 간다. 기본 쓰기 지도·평가 기회의 상품 포함 범위를 명시하고, 추가 상품 구매만이 핵심 학습 진행의 유일한 방법이 되지 않게 한다.

<a id="comfort-growth"></a>
### 성장한 만큼 편해지는 생활

성공할 때마다 곧바로 주문과 관리할 일을 늘리지 않는다. 처음에는 그림·되묻기로 하던 일을 나중에는 새로운 손님의 같은 수준 요청에서 혼자 수행하고, 익숙한 생활을 편하게 즐기는 장면을 남긴다. 새 과제는 다른 역할과 선택의 확장으로 제공한다. 도움을 쓰지 않았다는 이유만으로 칭찬을 자동 재생하거나 도움을 숨기지 않으며, 실제 새 상황에서의 수행만 독립 학습 근거로 사용한다.

이미 익힌 반복 조작은 묶어서 처리하거나 주민의 기본 보조를 이용할 수 있게 제작한다. 이 편의가 학습 답안을 대신 완성한 수행은 학생의 숙달로 기록하지 않는다. 생활 속 의미를 이해하고 선택할 기회와 집중해서 쓰는 학습은 유지하되, 모든 수확·배치 뒤에 퀴즈·교정·설명을 붙이지 않는다.

**만든 성과를 유지하기 위한 상시 노동을 요구하지 않는다.** 레시피 해금·함께 만든 물건·가게의 기념 흔적과 현재 판매용 재고를 구분한다. 재료가 떨어져도 성취가 사라지거나 추가 납품을 해야만 과거 결과를 다시 확인하게 하지 않는다. NPC의 기본 운영과 플레이어가 선택한 추가 납품·특별 메뉴를 구분하며, 기본 조달·소비·수익·보조 처리량은 경제 명세에서 정한다. 무한 재료·무한 수익·선택 상품의 추가 구매를 편안한 기본 생활의 전제로 삼지 않는다. 원가와 공급 규칙이 미정인 상태를 완성된 영업 기능으로 표시하지 않는다.

<a id="persistence"></a>
## 10 저장과 이용 조건이 바뀌어도 이어지는 세계

| 상황 | 설계 동작 |
|---|---|
| 같은 사건의 재전송·화면 재진입 | 이미 확정한 상태·보상을 반환. 관계·선물·후속 의뢰를 중복 생성하지 않음 |
| 서버 저장 실패 | 저장 대기 또는 미확정을 명확히 표시. 다음 기기까지 기억한다고 말하지 않음 |
| 오프라인 플레이 | 내려받은 개인 콘텐츠와 검증 가능한 권한 범위에서 잠정 진행. 공유 변경·확정 지급은 연결 복원 뒤 검증 |
| 다른 기기에서 이어 하기 | 인증된 계정의 확정 사건·상태·전달 이력·선택을 함께 복원. 기기 로컬 기록을 다른 계정에 합치지 않음 |
| 동시에 두 기기에서 변경 | 대상 상태의 판을 확인. 충돌한 경로는 다시 읽고 현재 가능한 선택을 제시. 자원·선물 중복 금지 |
| 철거·반납·선택 변경 | 과거 기여는 보존하고 현재 동작·대기 반응·후속 퀘스트를 재검사 |
| 기억 제외·공유 철회 | 해당 NPC의 이후 언급·추천·미전달 반응에서 제외. 완료 소유와 이미 공유된 공용 시설의 범위를 구분해 안내 |
| 마을 이동 | 개인 소유·학습·개인 이야기 보존. 새 NPC는 실제 소개·공개된 사실만 알고 과거를 목격했다고 말하지 않음 |
| 공동 시설 변화 | 공용 결과는 모두 이용하되 기여와 관계·학습은 각자 기록. 마지막 클릭한 사람에게 공로를 몰지 않음 |
| 이용권 종료 | 학습 통과·기록·소유 보존. 접근이 막힌 반응은 유예하고, 무료 구간의 실제 가능한 반응만 선택 |

무료 체험은 **행동 → 보이는 결과 → 다음 만남의 기억** 한 묶음을 끝까지 경험할 수 있도록 구성한다. 이미 약속한 체험 결과를 보기 위해 결제가 필수인 구성은 피한다. 정확한 체험 분량·상품 가격·권한 종료 후 열람 범위는 BM의 상품 명세에서 정한다. 재구독 때는 유효한 약속을 복원하고 시효 지난 인사·감사 목록을 한꺼번에 틀지 않는다.

공동 공간은 편집 가능한 범위와 기여의 공개 여부를 표시한다. 기본은 각자의 집·가게·NPC 이야기에서 완결한다. 공용 시설의 완료는 개인 사건을 자동 해결하지 않고, 필요한 경우 ‘이미 있는 시설에 다른 역할로 참여’하는 대체 과제를 제공한다. 다른 사람의 부재나 참여 거절로 개인 이야기가 막히지 않는다.

구체 사건 필드·동시 변경·순서·전달 확인·저장 계층과 어댑터 계약은 [구현 명세](아틀라스_구현명세.md#town-world-contract)에 둔다. 개인정보 원문을 세계 사건 로그에 넣지 않고 계정과 NPC 인지 범위를 검증한다.

## 11 제작과 구현 순서

### 콘텐츠 팩의 구성

한 팩은 생활 문제, NPC 목표, 선택별 상태 변화, 실제 동작과 물건, 후속 활동, 쉬운 표현과 확장 표현, 반복·취소 규칙, 확인 시나리오를 함께 가진다. 대사만 준비한 팩을 생활 사건 완료로 세지 않는다. 각 팩의 제작표에는 다음 항목을 둔다.

- 사건 ID·판, 상태의 소유 범위, 필요한 앞 사건과 대상의 판.
- 선택별 현재 상태와 실제로 보이는 차이, 후속 사건의 참조, 조건 불충족 대안.
- NPC별 인지 근거·고유 목표·표현 방식, 동작 자산과 정지 표현의 대응.
- 언어별 쉬운 표현·도움·교육 검수 상태, 관측 가능한 대표 능력.
- 발생·제공·수락·확정·표현 완료·보상 지급을 구분한 기록.
- 이미 본 조합·원하지 않는 계열·오랜만에 복귀·후보 소진의 처리.
- 현재 방문에서 확인할 핵심 효용과 조건별 대안, 완료 뒤 후속 제안 없이 끝내는 지점.
- 선택의 차이·배치 미리보기·되돌림 범위, 중단할 때 보존할 단계와 해제할 예약.
- 장면 중 고정할 표현·조작과 사용자 도움의 즉시 반영, 추천 정정의 적용 범위.
- 편해진 생활을 확인할 장면, 유지보수 의무와 구분한 선택 운영·재고·성과 기록.

팩 배포 전 검사는 도달할 수 없는 분기, 없는 자산, 끝나지 않는 순환, 잠긴 콘텐츠로만 이어지는 필수 결과, 보상 중복, 같은 사건의 상충된 상태, NPC 설정과 맞지 않는 말을 찾는다. 원고와 언어 변형이 달라도 같은 생활 결과를 보존하는지 확인한다. 심각한 오류가 있는 팩은 새 선택에서 제외하고 진행 중 상태는 마지막 일관된 단계나 명시한 복구 경로로 옮긴다. 자동으로 완료 처리하지 않는다.

### 단계별 결과물

| 순서 | 만들 것 | 다음으로 넘어갈 근거 |
|---|---|---|
| 1 | 사건집 C01의 두 선택·거절·재방문까지 가는 상태 모델과 합성 자료 | 반대 선택, 원인 없음, 중복·취소에서 예상 상태가 정확함 |
| 2 | 실제 NPC·물건 동작·쉬운 대사·전달 확인을 한 장면에 연결 | 말과 화면 상태가 일치하고 플레이어가 원인을 확인할 수 있음 |
| 3 | 계정 저장·재접속·다른 기기·오프라인 복원 | 같은 사람의 상태가 이어지고 다른 계정과 섞이지 않음 |
| 4 | C02 등 두 번째 생활 사건에서 공통 기능 재사용 | 원본 판단기를 복사하지 않고 사건 재료·동작 어댑터만 바꿔 동작 |
| 5 | [첫 쉼터의 네 입구](디자인/싱크타운_첫생활구간_설계.md#routes)를 재료 마련·제작·사연·현재 이용·재방문까지 연결 | 제작·메뉴·발견·사연 중 하나만 골라도 완결. 재배·채집·제작 앞 과정의 소유·소비·중단이 실제 결과와 이어짐 |
| 6 | C01~C08의 분기와 첫 쉼터의 관계·편의·후속 연결, 5·10·30회 시나리오 | 반복·소진·관심 변경·공동 시설 상황이 처리되고 필요한 추가 팩 수가 드러남. C08은 개인 완결 뒤 선택 연결 |
| 7 | 실제 초급 학습자와 반복 방문 플레이 | [첫 구간의 체감 검사](디자인/싱크타운_첫생활구간_설계.md#acceptance)로 자기 변화·원인·다음 선택·자율성·언어 부담을 관찰하고 문제를 수정 |
| 8 | 중급 생활 역할과 TOPIK II 학습·평가 콘텐츠 확장 | 검수된 능력 지도·쓰기 피드백·새 자료 평가가 실제 콘텐츠에 연결 |

첫 사례를 작게 만드는 것은 전체 범위를 줄인다는 뜻이 아니다. 상태·표현·기억의 한 연결을 먼저 검증하고 나머지 생활 분야에 같은 기준을 적용하는 순서다. C01/C02의 공통 연결 검증만으로 농사·채집·가게 운영이 완성됐다고 하지 않는다. 첫 쉼터의 개인 완결을 확인한 뒤 공동 기능으로 넓힌다. 원가에는 원고·교육 검수·미술·애니메이션·음성·QA·저장·운영을 포함한다. 개인화 선택을 위해 매 행동마다 생성형 AI를 호출하지 않는다.

## 12 완료를 판단할 근거

### 설계와 구현 검사

| 확인 대상 | 비교할 상황 | 통과 근거 |
|---|---|---|
| 실제 인과 | 같은 출발·날씨·시간에서 선택 A와 B, 행동하지 않은 경우 | A/B의 물건·NPC 행동·다음 선택이 다르고 원인이 없으면 해당 변화 없음 |
| 언어와 세계 분리 | 동일한 생활 선택, 서로 다른 학습 수준·도움 사용 | 생활 결과는 같고 표현·지원·학습 관측만 달라짐 |
| NPC 인지 | 받은 주민·본 주민·모르는 주민 | 각자 아는 사실만 사용. 공개되지 않은 개인 사실을 말하지 않음 |
| 지속과 순서 | 재접속·다른 기기·늦은 결과·사건 중복 | 현재 상태·기억·보상·전달 이력이 일치하고 중복 없음 |
| 현재 물건 상태 | 설치→사용→철거, 빌림→반납 | 과거 기여는 남지만 불가능한 동작과 대기 반응은 실행되지 않음 |
| 관심과 거절 | 연기·거절·다른 활동·조용히 선택 | 관계 벌점·재촉 없이 다음 후보와 전달 방식이 바뀜 |
| NPC 고유성 | 같은 도움을 서로 다른 성격의 주민에게 제공 | 고유 목표·사용 방식에 맞는 반응. 같은 칭찬의 이름만 바꾸지 않음 |
| 의미 있는 새로움 | 최근 사건 목록이 다른 두 기록, 5·10·30회와 소진 | 문제·역할·결과가 달라진 후보 또는 정직한 소진 대안. 대사 변형을 새 사건으로 세지 않음 |
| 복귀와 알림 | 여러 사건을 못 본 채 장기 부재 | 현재 중요 결과 하나가 먼저 보이고 나머지는 선택해서 확인 |
| 공유와 상품 | 다른 이웃의 완료, 체험 종료, 정액 만료·재구독 | 개인 진행 보존, 허용 범위만 실행, 체험 인과 묶음은 완료 가능 |
| 전달과 성능 | 화면 이탈·자산 실패·정지 표현·소리 끔 | 전달하지 않은 반응은 완료로 세지 않고 같은 의미의 접근 가능한 표현 제공 |
| 학습과 효과 | 새 자료·도움·오디오 실패·나중 재확인 | 생활 완료와 독립 언어 수행을 구분. 게임 완료로 급수·효과를 선언하지 않음 |
| 현재 방문의 보람 | 늘 같은 시간대·맑은 날에만 방문, 바쁜 NPC, 결과 보기 건너뛰기 | 실제 조건에 맞는 핵심 효용을 현재 방문에서 선택해 확인할 수 있고, 보지 않아도 성과 유지. 없는 이용 사실을 생성하지 않음 |
| 안심하고 바꾸기 | 미리보기→저장→직전 배치 되돌림, 타기기 수정·소유 변경 | 미리보기 효과 0, 허용된 복구만 적용. 관련 미완 진행 재검사, 보상 재지급·공동 상태 덮어쓰기 없음 |
| 편안한 마침표 | 완료 직후 떠나기·머무르기·쉬기, 자동 말걸기 예산 잔여 | 추가 수락·거절·설문 없이 종료 가능. 후속은 직접 열기 전 available, 같은 회차 재권유 없음 |
| 중단과 재개 | 읽기·입력·제작 중 앱 전환, 저장 응답 유실, 권한 만료 | 마지막 확정 단계와 다음 행동을 짧게 복원. 확정/예약/초안 구별, 원문 누출·중복 소비·답변 시간 압박 없음 |
| 안정적 개인화 | 진행 중 타기기 학습 동기화·정책 갱신, 사용자 도움 요청, 추천 정정 | 자동 변화는 다음 장면. 직접 도움은 즉시. 오늘만/덜 추천/제외·되돌림 범위가 구분됨 |
| 편해지는 성장 | 같은 수준의 새 요청, 장기간 추가 납품 없음, 보조 처리 이용 | 실제 독립 수행과 자동 처리를 구분. 성과를 누리기 위한 복구 노동·강제 재고 보충 없음 |
| 생활 과정의 연결 | 첫 쉼터 네 경로를 각각 처음부터, 같은 계정에서 다른 경로 추가 | 각 경로의 재료 출처·실제 결과·현재 이용·다음 방문 연결. 다른 경로 강제·중복 보상·관찰 기록의 자원 변환 없음 |

### 학생에게 확인할 체감

첫 연구는 게임에 익숙한 사람과 익숙하지 않은 TOPIK 1급+ 학습자를 포함한 소규모 반복 방문 관찰로 시작한다. 인원과 모집은 실제 운영 계획에서 정하며, 작은 표본의 관찰을 전체 학습자의 효과로 확대하지 않는다. 초급 화면에서 읽을 수 있는지와 원인을 이해하는지를 함께 본다.

첫 행동 직후와 다음 방문에 **답을 알려 주기 전에** “무엇이 달라졌나요?”, “왜 그렇게 됐다고 생각해요?”, “다음에 무엇을 해 보고 싶어요?”를 묻는다. ‘내 행동 때문에 바뀌었죠?’처럼 정답을 유도하지 않는다. 말로 설명하기 어려운 초급자는 변화한 물건·행동을 가리키거나 그림을 고르게 하되 그 도움 조건을 기록한다.

재미·체감은 원인 파악, 기억의 정확성, 하고 싶은 다음 선택, 반복 피로, 과한 반응·재촉의 느낌으로 본다. 학습은 새로운 장면의 독립 수행과 지연 후 재확인, 목표 시험 방식의 평가로 따로 본다. 접속 시간·매출·클릭 수만으로 재미나 학습 효과를 판정하지 않는다.

여섯 보완은 ‘바뀐 점을 스스로 찾는가’, ‘꾸미기를 시도하다 망가질까 멈추는가’, ‘끝내려는데 새 일이 붙는가’, ‘돌아와서 하던 일을 알아보는가’, ‘추천을 고쳐 자기 활동으로 돌아오는가’, ‘성과를 유지하려고 의무적으로 일하는가’를 관찰한다. 이 질문을 플레이 중 매번 팝업으로 묻지는 않는다. 첫 관찰에서는 안내 없이 행동을 보고 자연스러운 종료 뒤 무엇이 편했고 어디서 막혔는지 묻는다. 조작 실패·언어 어려움·내용 소진·불편한 개입을 구분해 고친다.

설계상 주요 변화가 보이지 않거나 원인과 연결되지 않은 사례, 말과 실제 상태가 충돌한 사례, 거절 후 압박을 느낀 사례는 원인과 함께 남기고 다음 제작에서 수정한다. 모든 핵심 사례가 구현 검사에 통과하고 실제 관찰의 문제를 고친 뒤 다시 확인하기 전까지 ‘체감 검증 완료’로 표시하지 않는다. 자동 시험이 초록이라는 이유로 신선함이나 학습 효과까지 입증됐다고 보고하지 않는다.

## 13 이번 설계의 완료 범위

이 문서는 상태의 구분, 사건 처리, 관계와 분기, 새로움·반응 전달, 학습 연결, 저장·상품·공유의 경계, 제작과 검증 방법을 정한다. 첫 생활 구간은 네 콘텐츠의 준비→선택→실제 쓰임→재방문을 연결하고, 사건집은 개별 사례, 구현 명세는 데이터·처리 계약을 제공한다. 후속 승인에 따른 [제작 패키지](디자인/싱크타운_제작패키지.md)에 첫 체험과 재방문 원고, 생활 경제·상품 검증안, TOPIK 4급 대비 전체 단원 지도와 대표 창작 과제를 작성했다. 최종 교육 검수·미술/음성·출시 전체 문항은행·런타임·계정 연결·실학생 체감/학습 효과와 상용 수익 검증은 별도 제작·검증 단계다.
