# SYNK v9.30 안전 개선 1차

> 상태: `codex/safe-student-flow-hardening` 가지에서 검증 완료 · 라이브 미배포

## 이번 단계에서 완료한 것

1. **운영 브리핑 알림 유실 방어**
   - 알림을 큐에 넣는 작업과 아침 메일 발송을 같은 `ScriptLock`으로 보호한다.
   - 메일 한도 부족이나 발송 오류 때는 큐를 그대로 보존한다.
   - 발송 중 큐가 바뀌더라도 이미 발송한 앞부분만 제거하고 새 알림은 남긴다.

2. **야간 작업의 기존 안전 순서 보존**
   - 적대 검토에서 단순 순서 변경이 Glide가 만든 포인트 행의 빈 날짜를 놓쳐 중복 보상을 만들 수 있음을 확인했다.
   - 따라서 `calcAll → expandHwBatch → dailyGuard` 순서를 유지했다.
   - 숙제 보상의 즉시 화면 반영은 별도 원자성 설계와 함께 처리할 때까지 보류한다.

3. **재해복구 시트 구조 교정**
   - `profiles`, `teacher_checkins`의 재건용 제목을 실제 데이터 순서와 일치시켰다.
   - 실제로 실행할 수 없는 `setupTables`를 성공 단계에서 제외했다.
   - 한 단계라도 실패하면 `재건 완료`가 아니라 `재건 일부 실패`로 보고한다.

4. **자동 안전검사 추가**
   - `node --test tests/safety.test.js`
   - 현재 결과: 10개 통과, 실패 0개, 후속 작업 5개.
   - Code.js 구문, Apps Script 설정, 야간 순서, 브리핑 실패·동시 변경, 재건 구조를 검사한다.
   - GitHub Actions에서도 같은 검사를 실행한다.

## Glide 편집기 읽기 전용 점검 결과

- 앱 접근은 **Private**이고 사용자 표는 `profiles`다.
- `profiles.email` 열의 **Row Owner가 실제로 켜져 있음**을 열 메뉴에서 확인했다.
- 학생 미리보기에서 `profiles`와 Glide `Users` 화면이 보이며, 두 화면 모두 **추가·편집 허용** 상태다.
- 학생 홈에는 상태·기록 카드가 이어지지만, 맨 위에서 바로 수행할 숙제·퀴즈 행동은 보이지 않는다.
- 강사 계정으로 미리보기했을 때 `teacher` 화면의 표시 조건이 거짓으로 판정됐다.
- 학부모 계정에는 별도 자녀 화면이 보이지 않고 공용 탭만 남는다.
- `report_cards`는 현재 0행이며, 학생·학부모가 안전하게 함께 소유하도록 설계된 Row Owner 열은 확인되지 않았다.

## 이번 단계에서 의도적으로 보류한 것

- 숙제 일괄 지급의 부분 실패·동시 실행·자정 이후 복구
  - 정식 해법은 별도 처리로그와 전용 잠금, 원래 발생시각 보존이 함께 필요하다.
- 숙제 포인트와 자동 정정을 같은 야간 계산에 즉시 반영
- 학생·강사·학부모 화면의 탭·표시 조건·편집 권한 변경
- 성장 리포트의 `ANYONE_WITH_LINK` 공개 방식 교체
- 포인트 사유·금액·지급자 허용 규칙
- 레이드·월간 정산의 중간 실패 복구
- 월간 포인트 아카이브의 H열 태그 보존 문제
- 8,000줄 코드의 파일 분리

외부 화면 권한을 바로 바꾸면 현재 필요한 자기소개 수정이나 강사 업무까지 막을 수 있다. 숙제 처리도 한 줄 순서 변경으로 고치면 중복 지급 회귀가 생기므로, 위 항목은 별도 시험 시나리오와 함께 진행한다.

## 라이브 반영 전 통과 조건
