## 🚫 뷰포트 붕괴 (프리즈의 정체) — 예방 불가, 복구만 가능
`resize_window` 호출은 **절대 금지** — 뷰포트를 1440→784px·dpr 2로 오버라이드한다.
단, **호출하지 않아도 같은 붕괴가 스스로 일어난다**(07-22 실측: JS로 `innerWidth 784 / dpr 2` 확인).
- 원인 = Chrome MV3 **서비스워커가 캡처 도중 재시작되면서 device-metrics 오버라이드가 남는 것**. 직전에 `screenshot timed out` 또는 `extension disconnected mid-operation`이 뜬다.
- **`browser_batch`로 묶어도 막히지 않는다**(07-22 실증). 왕복이 줄어 빈도는 낮아지지만 예방책은 아니다. Ctrl+0 등 확대 단축키는 확장이 차단.
- 화면 자체는 멀쩡하다 — **캡처와 좌표 매핑만** 2배로 깨진다. 그래서 좌표를 반으로 나눠 우회하려는 시도는 금지(Stripe 오폭 사고의 경로).
- 신호 ①스크린샷이 좌상단만 2배 확대 ②`Page.captureScreenshot` 타임아웃 ③**`zoom` 액션이 "Region exceeds viewport boundaries (773x392)" 오류** ← 가장 확실한 탐지기
- 이 상태의 클릭은 **약 1.9배 어긋난다** — 실제로 `Data`(css x≈613)를 노려 클릭했는데 `Try Business`(x≈1255)가 눌려 **Stripe 결제 페이지 탭이 열렸다**.
- 복구 = **새 탭 생성 → 앱 URL 이동 → 옛 탭 닫기**(같은 탭 리로드로는 안 풀림). `tabs_create_mcp` 1회 + `browser_batch[navigate, wait, tabs_close_mcp, wait, 화면복귀 클릭들, screenshot]` 1회 = **2호출**로 끝낼 수 있다. Glide는 자동저장이라 작업 손실 없음.

## 좌표
- `computer`는 스크린샷 픽셀 좌표를 받는다. 창 크기가 수시로 바뀐다(1568×735 ↔ 1545×784 관측).
- **클릭 직전에 매번 스크린샷을 새로 찍는다.** 몇 스텝 전 좌표 재사용 = 오클릭.
- 확대된 스크린샷이 나오면 클릭하지 말고 다시 찍는다(대개 한 번 더 찍으면 정상 복귀).

## 입력 요령
- 데이터 편집기 셀: 한 번 클릭 후 타이핑하면 **첫 글자만 편집기를 열고 나머지가 유실**된다(→ "1"만 남음). **더블클릭 → 타이핑 → Tab** 이 유일하게 안정적. Tab은 다음 셀을 '선택'만 하므로 또 더블클릭.
- **Escape는 입력을 취소**한다(커밋 아님). 커밋은 Tab/Enter.
- 우측 패널 텍스트 입력에서 `ctrl+a`는 **문자 'a'가 그대로 입력**되는 경우가 있다 → 평범한 입력칸은 `triple_click`으로 전체 선택. 토큰형(`Text or @column`) 칸은 ctrl+a→Delete가 먹힌다.
- `navigator.clipboard.writeText`는 차단된다(조용히 실패). 그 뒤 Ctrl+V는 **유호님의 기존 클립보드**를 붙여넣으니 붙여넣기 전략은 쓰지 말 것.
- Glide는 aria 라벨이 거의 없어 `read_page` ref가 무용. JS로 rect 얻어 변환→`computer` 실클릭이 정석(JS `.click()`은 무시됨).
- 페이지 첫 로드가 자주 빈 화면(`document.body.innerText.length === 0`) — 30초 쉬고 navigate 재시도.
- `javascript_tool`은 `browser_batch` 안에서 권한 오류 → 단독 호출.

## ⚠️ Add row / Set column 액션 — 토큰 이어붙기 결함 (데이터 오염)
Glide는 Add row 액션을 만들 때 **모든 열을 "자기 이름 열" 토큰으로 자동 채운다**(이름←이름, 시각←시각 …).
여기에 원하는 값을 메뉴에서 고르면 **교체가 아니라 뒤에 덧붙는다** → 저장값이 이어붙는다.
- 2026-07-22 실측: 출퇴근 버튼이 `김재헌21김재헌21`, 시각은 `…602Z2026. 7. 22. 오후 8:02:54`로 기록됨.
- **표가 비어 있으면 앞 토큰이 빈값이라 멀쩡해 보인다** — 행이 쌓인 뒤 터지는 잠복 결함. 반드시 실제로 눌러보고 데이터 편집기에서 확인할 것.
- **제거법 = 칸 `triple_click`(전체 선택) → `ctrl+x`(Cut).** Delete/BackSpace 키는 이 환경 분류기가 차단하고, 이 메뉴엔 Clear value가 없다. 비운 뒤 원하는 토큰을 하나만 넣는다.
- ☠️ **`ctrl+x` 사고 주의 — 포커스가 칸에 없으면 "선택된 컴포넌트"가 잘린다.** 2026-07-23 실사고: Escape로 포커스가 풀린 상태에서 triple_click이 칸을 못 잡았고 ctrl+x가 **운영 탭 컴포넌트 6개를 통째로 삭제**했다(좌하단 Undo 1회로 전량 복구).
  - 규칙 ①`ctrl+x` 직전에 **칸이 파란 테두리로 포커스됐는지 스크린샷으로 확인**한다. ②ITEMS DATA(Title/Description/Meta/Image)는 ctrl+x 대신 **⋮⋮ → Clear value**를 쓴다(거기엔 메뉴가 있다). ctrl+x는 Clear value가 없는 **Add row 액션 값 칸**에서만.
  - 사고 나면 **좌하단 Undo(↩)** 가 즉시 복구한다 — 당황해서 다시 만들지 말 것.
- 순수 텍스트를 넣을 땐 `triple_click` → 그냥 타이핑하면 확실히 교체된다.
- **쓰지 않는 열(type·gps_lat·gps_lng·created_at 등)의 자동 토큰도 전부 Cut**할 것 — 안 그러면 직전 행 값이 복사된다.

## 화면 Source를 바꾸면 남는 잔재
탭의 Source만 교체하면 컬렉션은 따라오지만 **다음 2개가 옛 테이블을 가리킨 채 남는다**:
- **컬렉션 Title**(예: 소스를 today_board로 바꿔도 제목은 "attendance") — DATA > Title에서 직접 수정
- **Sort 칩**(예: "Sort by date in descending order" — 새 테이블에 `date`가 없어도 문구가 남음). 열면 실제 값은 `—`. 애매함을 없애려면 **Table order**로 명시(코드가 이미 의도한 순서로 시트를 쓰는 경우 특히).

## 🔁 헤더 잔재 재생성 표준 절차(Table)
Table을 만든 뒤 Source를 바꾸면 값은 재매핑되나 **헤더 라벨이 이전 소스 잔재**로 남는다(leads·kpi_metrics 실측: 지표/값/상태/기준-메모). 표준 복구:
1. Title 입력(제목 붙이면 헤더 편집 중 오조작 시 식별 쉬움)
2. COLUMNS의 각 열 오른쪽 **X로 4열(또는 전부) 삭제** — 같은 좌표 연타 가능(위 열이 지워지며 다음 열이 그 자리로 올라옴)
3. **Add item**으로 실열 재추가(위 규칙: 팝업 열닫 왕복). 재추가하면 Value·Header가 실열명으로 정상화.
- 대안: 애초에 List로 만들어 Source부터 바꾸면 헤더 개념이 없어 잔재도 없음(원장 읽기전용 표는 Table이 보기 좋아 Table 선호).

## 🗑 컴포넌트 삭제 — 우클릭 Delete는 "메뉴를 연 좌표의 항목"을 지운다

## 🔧 조건이 "표기는 맞는데 동작이 다르면" — 지우고 다시 만든다
2026-07-24 실사고: 「우리 아이」 탭이 `role is parent`인데 학부모 계정에서 계속 `visibility condition is false`. 데이터(role=parent, LEN=6)·설정 모두 정상이었고, **같은 조건의 「성장 리포트」는 정상 작동**했다 → 그 화면의 조건만 내부적으로 손상된 것.
- **처방: 조건 X로 삭제 → 정상 렌더 확인 → 동일 조건 재생성.** 재생성하면 정상 동작한다.
- 이 앱처럼 조립 중 **뷰포트 붕괴·Undo를 많이 겪은 경우** 조건이 깨질 수 있다고 가정할 것.
- 진단 순서(빠른 것부터): ①같은 조건을 쓰는 **다른 화면**이 되는지 비교 ← 가장 결정적 ②Data 탭에서 값 인식 확인 ③시트에서 `=LEN()`으로 비가시 문자 확인.

## ☠️ 탭이 백그라운드면 조립 불가 (2026-07-28 확립 — 스크린샷 타임아웃의 진짜 정체)
`Page.captureScreenshot timed out`이 반복되면 뷰포트 붕괴가 아니라 **탭이 hidden**일 수 있다. 판별: `document.visibilityState`.
- hidden이면 크롬이 렌더링을 멈춰 캡처가 영영 안 된다 → **배율(캡처폭÷innerWidth)을 잴 수 없어 클릭 좌표를 신뢰할 수 없다**. 실제로 컴포넌트를 노린 클릭이 빗나가 화면(SCREEN) 설정이 열렸다(다음 클릭이 STYLE에 적중하면 컴포넌트 전체 교체 사고).

- JS로 `getBoundingClientRect()`는 hidden에서도 읽히므로 "상태 파악"은 되지만 "클릭"은 안 된다. 상태만 기록하고 중단하는 게 정답.
- (07-28 2부 보강) **부팅 강행은 가능**: Glide가 hidden에서 스피너에 멈추면 `Object.defineProperty(document,'visibilityState',{get:()=>'visible'})`+`hidden→false`+`visibilitychange` dispatch로 부팅이 진행된다(실증 — 타이틀 로드까지 감). 즉 유호님 호출 전에 "부팅까지 미리" 해둘 수 있다. 그러나 캡처는 여전히 불가라 **조작은 블라인드가 되므로 하지 말 것**(이날 팝오버 3겹을 DOM 텍스트로 더듬다 중단이 정답이었음). 합성 이벤트는 요소별 복불복: 좌측 내비·컴포넌트 목록·프리뷰 카드는 pointer 시퀀스 dispatch(`__fire`)로 먹히고, 우측 패널 액션 행은 지연(수 초) 후 반영, More 버튼은 무시(React props의 `onClick` 직접 호출은 동작). 이 복불복 자체가 블라인드 금지의 근거다.

```js
t[Object.keys(t).find(k=>k.startsWith('__reactProps$'))].onClick({preventDefault(){},stopPropagation(){},nativeEvent:{},currentTarget:t,target:t,type:'click',button:0});
```

- 같은 텍스트가 프리뷰·좌측·팝업에 동시에 있으면 오클릭한다 → **조상에 `VIEW AS USER` 등 컨테이너 표식이 있는 것만** 고른다.
- 판정 재료: `.section-wrapper`(COMPONENTS 목록) · `[class*="SmartphoneInner"]`(프리뷰 렌더) · x>900 최대 div(우측 패널). 이 셋이면 "무엇이 조립됐나 + 실제로 그려지나 + 설정이 뭔가"가 다 나온다.

- ☠️ **함정: 드롭다운을 열면 option ref가 통째로 재생성되고, 첫 `find`는 stale ref를 준다.** stale을 클릭하면 아무 일도 안 일어나는데 **에러도 안 난다** — 선택이 그대로인 걸 모르고 ▶를 누르면 **직전 함수가 다시 실행**된다(08-01에 calcAll이 이렇게 한 번 더 돌았다. 멱등이라 무해했을 뿐).
- **정석: 드롭다운 클릭 → `find` → (첫 결과 무시) → `find` 재호출 → 결과 중 `(option)` 타입 ref 클릭 → `zoom`으로 드롭다운 라벨이 실제로 바뀌었는지 확인 → 그때만 ▶.** 확인 없이 ▶ 금지.
- ☠️ **`Escape`는 선택을 첫 항목(`rarityOf`)으로 되돌린다 — 상단 표시는 고른 함수 그대로라 화면으로 구별이 안 된다**(08-01 UI 트랙 실측: 두 번 오실행하고 「실행」 기록 화면에서야 발각). 항목 클릭 후 **Escape 없이 곧바로 ▶**. 재시도가 계속 `rarityOf`로 돌아오면 이 함정을 의심하고, 라벨이 안 바뀌면 **재시도를 멈춘다** — 반복하면 엉뚱한 함수가 실행된다(08-01에 `calcAll`이 이렇게 2회 실행됨).
- 🚫 **언더바로 끝나는 함수는 드롭다운에 아예 안 뜬다**(GAS private 규약). SYNK는 private 헬퍼에 `_`를 붙이는 관례라 **신규 배치·스위프 함수 대부분이 원격 실행 불가**다(`absenceFollowupNightly_`·`sweepAbsenceForm_`·`absenceSection_` 실측). 대안 = ①공개 래퍼를 통해 실행(`syncNotionNow`가 `syncToNotion_`을 부르는 방식) ②상위 트리거 함수(`nightJobs` 등)로 실행 — 단 무거운 배치 전체가 돌아 학부모 메일까지 나가므로 위험 ③**코드로 검증**: 빈 상태 첫 줄 가드(`if (!sh || sh.getLastRow() < 2) return`)가 있으면 크래시 경로가 없음을 정적으로 보장할 수 있다.
- 실행 결과는 하단 「실행 로그」 패널에 뜬다(screenshot으로 읽음). 무거운 함수도 20초 내외 — `wait`는 최대 10초라 2회 나눠 건다.
- 08-01 실적: `createAbsenceForm`·`calcAll` 원격 실행 성공. 검증은 편집기가 아니라 **gviz로 시트 원문 대조**가 확실하다: `docs.google.com/spreadsheets/d/<ID>/gviz/tq?tqx=out:html&sheet=<탭>&tq=select A,B,D,DR where D='teacher'` — `select`로 열을 좁히면 122열짜리 profiles도 한 줄로 읽힌다.

## ☠️☠️ 배율은 **매 스크린샷마다** `캡처폭 ÷ innerWidth`로 다시 잰다 — 캡처폭을 상수로 굳히면 전부 빗나간다 (2026-08-04 실측)
종전 메모의 「배율 = 캡처폭/innerWidth」는 맞는데, 08-04에 **캡처폭 1288을 세션 상수처럼 굳혀 쓰다가** 창이 바뀐 뒤 실제 캡처가 **1568**이 되어 모든 좌표가 **1.22배 어긋났다**.
- 증상이 「아무 일도 안 일어남」이라 원인이 안 보인다 — 클릭이 빈 곳에 떨어지거나 이웃 컨트롤을 누른다(우측 패널 탭을 눌렀는데 옆 탭이 열림, 입력칸을 눌렀는데 래퍼 div가 포커스됨). **오클릭보다 나쁜 건 「눌렸는데 아무 반응 없음」을 UI 버그로 오진하는 것**이다(08-04에 두 번 오진했다).
- 규칙: **스크린샷을 찍을 때마다 결과 문자열의 `(WxH)`를 읽어 그 값으로 배율을 갱신**한다. 창은 세션 중에도 바뀐다(1288×925 ↔ 1568×772 관측).
- 그래서 **좌표가 필요 없는 길을 먼저 찾는다** — 아래 `focus()` 항목.

## ✅ 우측 패널 입력칸은 **JS `focus()` → 실타이핑**이 가장 확실하다 (2026-08-04 확립)
좌표로 못 잡던 토큰 필드를 `el.focus()` 한 줄로 잡았다. **합성 클릭은 금지지만 `focus()`는 다르다** — 포커스만 옮기고 **입력은 진짜 키 이벤트**로 들어가므로 Glide가 정상 처리한다.
```js
const sc=[...sec.querySelectorAll('.section-content')][0];      // 그 행
const ce=sc.querySelector('[contenteditable]') || sc.querySelector('textarea');
ce.focus();                                                     // 이후 computer type
```
- 🔴 **필드가 두 종류다**: ①`tiptap ProseMirror` contenteditable(토큰형 — Title·Description·Empty message) ②`token-entry-input` **TEXTAREA**(화면 제목 Custom 등).
- ☠️ **tiptap 토큰 필드는 공백과 쉼표를 삼킨다** — `이 문장, 한 번만 봐 주세요` → `이문장한번만봐주세요`로 저장됐다. 문장을 넣어야 하면 **그 필드를 쓰지 말고** ①TEXTAREA형 필드(화면 제목) ②컴포넌트 자체를 다른 것으로 바꾼다.
- 기존 토큰 제거는 `End` → `BackSpace`가 여전히 유효하지만 **tiptap에서는 안 지워질 때가 있다**(토큰이 남고 뒤에 덧붙는다) — 그 경우 **컴포넌트를 지우고 다시 만드는 쪽이 싸다**.

## 🔴 「Edit 버튼」의 정체는 컬렉션 토글이 아니라 **Title 컴포넌트의 액션**이다 (2026-08-04 실측)
컬렉션 ACTIONS의 `Allow users to edit items`를 껐는데도 상세 화면 우상단에 `Edit`가 남아 있었다. 원인은 상세 화면 `Title` 컴포넌트의 **`Show edit screen`** 액션(종전 메모에 적혀 있던 것이 이렇게 물린다).
- **끄고 나서 프리뷰를 다시 보지 않으면 「잠갔다」고 잘못 보고하게 된다** — 권한 판정은 토글 상태가 아니라 **렌더된 버튼 유무**로 한다.
- Glide가 자동으로 얹는 `Title`은 **부제에 두 번째 열을 멋대로 물린다**(실측: `Subtitle = fb_id` — 내부 키가 강사 화면에 그대로 노출). Rich Text·Fields로 내용을 보여주는 화면이면 **Title 컴포넌트째 삭제**가 정답이고, 그러면 제목·부제·Edit 버튼이 한 번에 사라진다. 화면 제목은 **Options → NAVIGATION → Title → `Custom`**.

## 🧱 데이터 편집기 격자는 **canvas**다 — DOM도 ref도 없다 (2026-08-04 확립)
`read_page`·`find`·`getBoundingClientRect`가 **격자 안에서는 전부 무용**하다(헤더·셀·행번호 모두 canvas 픽셀). 좌우 패널은 DOM이지만 격자는 아니다.
- 따라서 **행 추가·셀 입력·행 삭제는 캡처 좌표가 유일한 경로**다. 스크린샷 예산을 아끼려면 **격자 일은 몰아서** 하고, 나머지(컴포넌트·바인딩·필터·토글)는 전부 DOM으로 끝낸다.
- 열 순서는 Glide 표시 순서 ≠ 시트 물리 순서다. **물리 위치는 gviz `select A,G,H`** 로 확인한다(열을 좁히면 122열짜리도 한 줄).
- 격자 좌표 기준점은 **행번호 칸**이다. 사이드바 폭이 세션마다 달라 좌표가 밀리니 매번 zoom으로 잰다(08-04: 353으로 짚었다가 사이드바를 눌러 다른 표로 튀었다 — 실제 gutter는 382였다).
- 행 선택 = **hover → 행번호 클릭**(체크박스로 바뀐다) → 우상단 **`Delete row(s)`** → 확인 팝업. 버튼 라벨이 `Delete row` / `Delete 2 rows`로 **선택 개수를 말해 준다** — 표에 행이 1개뿐이면 이 라벨만으로 대상이 확정되므로 캡처 없이도 안전하다.

## ⌨️ 셀 입력은 **더블클릭 → 2초 대기 → 타이핑** (08-04 실측·종전 절차 보강)
종전 메모의 「더블클릭 → 타이핑 → Tab」은 **대기가 빠져 있어 조용히 유실된다**(08-04: 3칸 연속 입력이 전부 사라졌고 화면상 흔적도 없었다).
- 편집기가 열렸는지는 **DOM으로 확인된다**: `document.querySelector('textarea.gdg-input')` — 이게 focus를 갖고 있으면 타이핑이 들어간다. 커밋 전에 `.value`를 읽어 **입력이 실제로 담겼는지 확인**하고 Enter/Tab.
- ☠️ **빈 셀에 `ctrl+a`를 쓰지 말 것** — 08-04에 문자 `a`가 그대로 들어가 `a원문이…`가 됐다(종전 경고의 재현). 값이 있는 셀을 덮을 때만 쓰고, 쓴 뒤엔 `.value`로 검사한다.
- `New row` 클릭이 **직전 입력값을 새 행에 복제**하는 경우가 있다(08-04 실측) — 추가 후 반드시 내용을 보고, 필요 없으면 지운다.

## 🧩 컴포넌트 추가·바인딩 (08-04 실측)
- **picker 타일은 좌표로 안 눌린다** — `find("Text Entry component tile in the add-component picker")` → **ref 클릭만** 동작(COMPONENTS `+`도 종전대로 ref).
- ⚠ **새 컴포넌트의 모든 바인딩이 첫 열(`id`)로 자동 매핑된다** — Choice의 `Write to`·`Values`·`Label`, Text Entry의 `Column`까지 전부. 그대로 두면 **사용자가 입력하는 순간 행의 `id`가 덮인다.** 「Add row 액션 토큰 자동 채움」과 같은 계열이지만 이쪽은 **덮어쓰기**라 더 위험하다.
- **Choice는 옵션 표가 필요하다** — 커스텀 값 입력 자리가 없다(Source 드롭다운 끝은 `User Profile`·`This item`뿐). `Data → + → Blank table`로 표를 만들면 **이름이 `protective-look` 같은 자동 생성 문자열이고 변경 UI가 없다** → 어느 문서에 그 표의 정체를 적어 둘 것.
- 우측 패널 탭은 컴포넌트일 때 **3개**(General·Options·Actions ≈ x 937·1069·1201), 화면일 때 **2개**(General·Options). **필터·정렬·가시성은 Options 탭**에 있다(General엔 없다).
- 토글은 hidden input이 아니라 **`toggle-switch___StyledDiv8`(w≈42)의 중심**을 눌러야 먹는다 — input rect(더 오른쪽)를 누르면 아무 일도 안 일어난다.

## ⏱ Glide → 시트 반영 속도가 컴포넌트마다 다르다 (08-04 실측)
**Choice는 즉시(≈5초), Text Entry는 1~2분 늦다.** 그 사이 앱 화면과 Glide 데이터에는 값이 있는데 **시트에는 없다** — 「안 써졌다」로 오진하기 딱 좋다.
- 판별법: Glide 헤더의 **`Search data`** 에 그 값의 일부를 넣어 행 수를 본다(맞는 말 → 1행 / 없는 말 → 0행으로 **먼저 캘리브레이션**할 것). Glide에 있으면 기록은 된 것이고 남은 건 동기화뿐.
- gviz는 캐시된다 — `cb=` 파라미터보다 **`tq=select A,G,H`처럼 쿼리를 바꾸는 쪽**이 확실히 새로 받는다.
