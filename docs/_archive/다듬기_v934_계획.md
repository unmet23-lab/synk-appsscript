## 핵심 판정 (유호님 질문에 대한 답)

**Q. 강사가 수업 중 앱을 만지는 시간이 과다한가?**
A. **터치 수 자체는 이미 적으나, 입력 창구가 5곳(포인트버튼·hw_batch·class_fuel·weekly_topics·출퇴근)으로 분산된 것이 문제. "수업 중 0~1터치" 재설계 확정:**
- **출석 = B안**: 수업 시작에 멀티선택 폼 1탭(attendance_batch 1행) → parentSweep(10분)이 attendance로 전개 → 등원알림·today_board·미등원경보(부활) 실시간 유지. 학생당 개별 출석 기각(월 600 update로 쿼터 파산).
- **마감 = 통합 폼 1탭**: weekly_topics 제자리 승격(열 추가) — 배운내용+문법태그+도달도+예외학생+숙제완료자+연료(선택). 밤에 expandLessonLog가 숙제 +10·연료·마스터리로 전개.
- **왕관 2종(MVP·시냅스) 즉시 버튼은 잔류**(수업 중 세리머니 가치, 선택적 1~2탭). dailyGuard가 안전망.
- **생일축하 버튼은 새 앱에서 미조립**(아침 자동지급과 항상 충돌하는 UI 함정 — 코드 무수정, 가이드 반영).
- 결과: 강사 하루 = 출근 1탭 · 수업시작 출석 1탭 · (선택) 왕관 · 마감 1탭 · 퇴근 1탭. 수업일당 update ~7건 → 3~4건.

**진화 게이트**: 뉴로→스파키(100P)는 무게이트(첫 진화 = 빠른 기쁨). 스파키→링커부터 5게이트 = 포인트 + 해당 단계 문법 12개 중 9개. 데이터 없으면 기존 포인트 진화(신규생 보호), 강등 금지, 반 태깅 60일 중단 시 게이트 자동 해제. 문구는 전부 긍정형("문법 N개만 익히면 진화!").

**이미지**: 라이브에 Canva 픽셀아트 40종 가동 중(A안) — 유호님 승인물이므로 코드가 함부로 교체하지 않는다. 신규 8종(투명배경·브랜드 팔레트, B안)은 setupPixelArt(적용 플래그 기본 false)로 준비만. replaceContentType E/G/H 보존 수리로 어느 쪽이든 증발 위험 제거.
