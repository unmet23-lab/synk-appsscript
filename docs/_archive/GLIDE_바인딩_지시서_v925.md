# SYNK → Glide 바인딩 지시서 (v9.26)

> **대상:** 유호 (SYNK LAB 원장) · Glide 에디터를 열고 그대로 따라 하는 실무 매뉴얼
> **범위:** ① 이미 데이터가 차 있는데 화면에 안 붙은 완성품 연결 · ② 데이터가 존재하는 신규 탭 제안 · ③ contents 몽골어(G열) 노출
> **전제:** `GLIDE_조립_마스터보드.txt`의 PHASE 0~3(시트 계산·컬럼 타입·로그인·역할)이 끝나 있어야 함. 이 문서는 그 다음 단계.
> **근거:** 모든 시트명·열 번호는 `Code.js`에서 실제 확인함(추측 없음). 열 표기는 `헤더(문자열 / 1-base 번호)` 형식.
> **v9.26 개정 사유:** 유호님 지시("학생 앱 기본=한국어, 몽골어는 보조·자유 토글 금지")에 따라 섹션 3의 기존 기본 권장(안 A 병기)을 폐기하고 **2축 차등 설계**를 새 기본으로 교체 + 최상단에 언어정책 잠금 규칙 추가.

## 🔒 언어 정책 잠금 규칙 (v9.26 · 위반 시 정책 파기)

> **이 박스는 섹션 3의 상위 규칙이다. 아래 4개 잠금은 유호님 확정 지시이며, 병렬 세션·미래 편집이 임의로 뒤집을 수 없다. 어긋나는 바인딩이 발견되면 그 바인딩을 즉시 제거한다.**

1. **학생 학습 콘텐츠 카드에 `몽골어(G열)`를 직접(raw) 바인딩 금지.** 학생이 보는 학습 '대상' 카드(어휘·문장·문법 = 도감·스토어·학습 텍스트)에 G열을 항상 노출하는 상시 병기는 금지한다. 몽골어 뜻은 오직 "뜻 보기" 탭 리빌(기본 off)로만 노출한다. — **위반 = 정책 파기.**
2. **퀴즈 D/G열 raw 바인딩 금지 (정답·해설 유출).** 퀴즈 데이터는 `문제|정답|해설` 파이프 포맷이라 D열(한국어)·G열(몽골어)을 Text에 그대로 붙이면 정답과 몽골어 해설이 통째로 노출된다. 코드의 `split('|')[0]` 보호는 강사 브리핑 메일에서만 동작하며 Glide 바인딩에는 적용되지 않는다. 학생 퀴즈를 앱에 노출할 경우 **Glide Split/Template 컬럼으로 '|' 앞부분만** 경유해야 한다. — **위반 = 정답 유출.**
3. **학생용 자유 언어 토글(구 안 B) 금지.** 학생이 앱에서 언어를 한 번 몽골어로 고르면 계속 몽골어로 남는 사용자 토글은 학생 역할에 만들지 않는다(유호님 우려 직결). 학부모는 역할 기반 자동 분기(몽골어 주)로 이미 완결 — 토글 불필요.
4. **학습 콘텐츠는 Glide 앱 크롬(시스템 UI) 언어 설정과 격리한다.** 앱 껍데기(탭바·Submit·로그아웃 등) 언어가 기기 언어를 따라가더라도, 학습 '대상' 텍스트는 항상 데이터(한국어 D열)로 관리해 크롬 언어에 흔들리지 않게 한다.

**운영·지시문 몽골어는 허용된다** — 내비·버튼·숙제 '지시문'·온보딩·도움말·안전 문구는 학습 대상이 아니므로 몽골어 노출이 정당하다(특히 A1~A2 초급 이탈 방어). 학습 '대상'과 '운영·지시문'을 구분하는 것이 이 정책의 핵심이다. 상세 설계는 섹션 3.

## 0. 용어·조작 3줄 요약 (Glide 실제 메뉴명)

- **Data editor(데이터 편집기):** 왼쪽 데이터 아이콘. 테이블(=시트탭)·컬럼을 본다. 컬럼 제목 클릭 → **Column type / Edit column**에서 타입 지정.
- **Layout(레이아웃) 편집기:** 가운데 폰 미리보기. 하단 **탭(+)** 추가, 화면에서 **Components(+)** 로 조각 올림. 각 컴포넌트마다 오른쪽 설정에 **Visibility(표시 조건)** 있음.
- **Collection(컬렉션):** 여러 행을 목록으로 보여주는 컴포넌트. 오른쪽 **Options → Filter / Sort / Search / In-app filter / Empty state**.
- **Rich text:** `<div>`·마크다운(`*기울임*`)을 렌더. HTML 카드는 반드시 이 타입. Text로 하면 태그가 글자로 깨짐.
- **Set Column / Add Row:** 버튼 액션. 학생이 값을 고르거나(대표몬스터) 강사가 행을 추가(포인트)할 때만.

> ⚠️ **쓰기(업데이트) 절약 원칙(마스터보드 U-1~U-7):** 이 문서의 섹션 1·2·3은 **전부 "읽기 전용 표시"** 라 Glide 업데이트를 먹지 않음. 화면 진입만으로 시트에 쓰는 설정(On-view Set Column, 방문 카운터)은 금지.

## 섹션 1 · 즉시 연결 (미바인딩 완성품)

> 데이터가 이미 계산돼 차 있는데 어느 화면에도 안 붙은 열들. **연결만 하면 끝.** 모두 학생/학부모/원장이 이미 보는 기존 탭에 컴포넌트 1개씩 추가하는 작업.
> 아래 4개(1-1~1-4)가 마스터보드 PHASE 2에서 타입만 지정되고 PHASE 4 화면 레시피엔 안 올라간 "진짜 미바인딩". 1-5·1-6은 보너스(선택).

같은 반에서 이번 달 함께 출석한 날이 가장 많은 "단짝" 카드(0건이면 '솔로 플레이' 유머 폴백까지 코드가 채움).

| 항목 | 내용 |
|---|---|
| 시트·열 | `profiles` → `시냅스케미 (BI / 61)` |

1. Data editor → `profiles` → `시냅스케미(BI)` 컬럼 제목 클릭 → Type이 **Rich text**인지 확인(아니면 마스터보드 2-8대로 지정).

4. `플레이스타일` 카드 밑으로 드래그해 위치 정리. 끝.

이번 주 우리 반 vs 상대 반 리그 대진 미리보기(부전='재정비 주간', 미발표=공란, 첫 대결='첫 만남'까지 코드가 처리).

| 컴포넌트 | **Rich text** |

### 1-3. 🗺️ 시냅스 여행 지도 — `app_state.여행지도HTML` (key/value 행)
스토리북이 다녀간 한국 12경에 도장이 찍히는 그리드(`n/12곳 정복`). `updateTravelMap_`이 `synk_stories`를 읽어 `app_state`에 상설 HTML로 저장. **마스터보드 2-14에서 타입만 언급되고 PHASE 4엔 안 붙은 완성품.**

| 항목 | 내용 |
|---|---|
| 시트·열 | `app_state` → `key='여행지도HTML'` 행의 `value` |
| 컴포넌트 | **Rich text** |
| 배치 | **신규 싱크 스토리 탭(섹션 2-1)** 상단이 가장 자연스러움. 학생 홈에도 가능. |
| 표시 조건 | 없음(스토리 0편이어도 '???' 12칸으로 채워짐) |

**가장 쉬운 방법 — app_state 기반 화면에 붙이기 (~4분)**
`app_state`는 key/value 한 줄짜리라, 그 값 하나만 붙이려면 **app_state를 소스로 하는 화면**에서 붙이는 게 제일 깔끔하다(원장 콕핏 4-D1에서 `리텐션레이더HTML` 붙인 방식과 **완전히 동일**).
1. 싱크 스토리 탭(섹션 2-1) 안에 **Container** 또는 별도 화면을 하나 두고 소스 = `app_state`.
2. 오른쪽에서 그 화면을 **Filter → `key` is `여행지도HTML`** 로 좁힘(행 1개만 남음).
3. **Components(+) → Rich text** → Content = `value`. 끝.

> 💡 학생 홈(profiles 기반)에 직접 얹고 싶으면: `profiles`에 Template 컬럼(고정값 `여행지도HTML`) → 그걸로 `app_state`에 **Relation** → **Lookup**으로 `value` 뽑기 → Rich text. 헬퍼 컬럼 3개라 초보에겐 번거로우니, **스토리 탭에 두는 걸 권장.**

### 1-7. 🌟 드림 한 줄 (학생 목표 노출) — `profiles.드림한줄 (CB / 80)` *(신규 · [v9.29])*
학생이 "내가 한국어를 배우는 이유/목표"를 한 줄로 직접 선언하고, 그 문장이 개인 여정 카드(`나의여정 BY / 77`) **최상단**에 `🌟 나의 목표: …` 로 노출된다. 기업 철학 "앱에서 목적 한 줄이 프로필에 노출"의 실현.

> ⚠️ **이 항목만 섹션 1의 예외 — 학생이 값을 쓰는 유일한 입력.** 나머지 섹션 1·2·3은 읽기 전용이지만, 이 열은 학생이 **Set Column으로 직접** 쓴다. 단 "가끔 한 번 저장"이라 마스터보드 U-4(드물게 바뀌는 값) 기준 허용. **원장/강사 전용인 `핵심비전(BA / 53)`과 절대 혼동 금지** — 그건 학생·학부모에게 노출하지 않는 케어용 열이고, 이 `드림한줄(CB / 80)`이 학생 자기선언 전용 신규 열이다.

| 항목 | 내용 |
|---|---|
| 시트·열 | `profiles` → `드림한줄 (CB / 80)` — **Text** (학생 소유 · calcAll·syncProfiles 어떤 배치도 덮어쓰지 않음, 헤더만 보장) |
| 입력 컴포넌트 | **Text Entry**(입력) → 대상 컬럼 `드림한줄` (= Set Column) |
| 노출 컴포넌트 | 이미 바인딩된 `나의여정 (BY / 77)` Rich text 카드가 자동으로 최상단에 표시(추가 작업 없음) |
| 배치 | 학생 홈/프로필 탭(4-A1), 본인 행 · Visibility = `role is student` |
| 표시 조건 | 입력칸: 학생 본인만. 카드 노출: 코드가 빈 값이면 "🌟 나의 목표를 적어보세요" 유도 문구로 자동 채움 |

**클릭 순서 — ① 입력칸 만들기 (~4분)**
1. Data editor → `profiles` → `드림한줄(CB / 80)` 컬럼이 보이는지 확인. (calcAll이 다음 실행에서 헤더를 자동 생성. 안 보이면 Apps Script에서 `calcAll` 1회 수동 실행하거나 CB1 셀에 `드림한줄` 직접 입력.) Type = **Text**.
2. Layout → 학생 홈(또는 프로필) 탭 → 하단 **Components(+) → Text Entry**(텍스트 입력).
3. 오른쪽 설정 → **Data / Column** = `드림한줄` 선택(입력이 이 열에 저장됨 = Set Column).
4. Placeholder(안내문구) = `🌟 나의 목표를 한 줄로 적어보세요` 입력.
5. 컴포넌트 **Visibility → role is student**(학생만 자기 목표를 편집).

**클릭 순서 — ② 여정 카드 노출 확인 (~2분)**
1. 학생 계정(또는 미리보기)에서 입력칸에 목표 한 줄을 써 저장.
2. 다음 `calcAll` 실행(자동 14시·22시 또는 Apps Script에서 수동 1회) 뒤 학생 홈의 **`나의여정(BY / 77)` 카드 최상단**에 `🌟 나의 목표: {내가 쓴 문장}` 이 뜨는지 확인.
3. 값을 지우면 다음 계산에서 카드가 `🌟 나의 목표를 적어보세요` 유도 문구로 자동 복귀하는지 확인.

> 💡 **타이밍:** 입력은 즉시 시트에 저장되지만, 카드(BY)는 `calcAll`이 다시 그릴 때 반영된다(하루 2회 자동). 즉시 확인하려면 Apps Script에서 `calcAll`을 한 번 돌린다.

## 섹션 3 · 몽골어(contents G열) 노출 — 2축 차등 설계 (v9.26 개정)

> `contents` 시트 구조: `콘텐츠ID(A) · 유형(B) · 이름(C) · 설명(D) · 이미지URL(E) · 순번(F) · 몽골어(G) · 영어(H)`.
> **G열(몽골어)** 은 `translateContents`·`injectMongolianContents`가 유형 `homework·quiz·braintip·quote·monster·season` 행을 채움. 별도로 `setupParentLabels`가 만든 **`유형='label'` 행**은 화면 라벨의 한/몽/영을 큐레이션해 둠(C=키, D=한국어, G=몽골어, H=영어). 이 label 행이 운영 UI 몽골어의 핵심 재료.
>
> **[v9.26 정책 전환] 구 "3안(안 A 병기 권장)" 폐기.** 구버전은 학생이 보는 학습 콘텐츠 카드에 몽골어(G)를 상시 병기하는 안 A를 기본 권장했으나, 이는 유호님 지시("학생 학습 화면에서 몽골어가 상시 노출되면 안 된다")와 정면 충돌한다. 아래 **2축 차등 설계**가 새 기본이며, "무엇을 어디에 붙이느냐"를 두 축으로 나눠 결정한다.

### 3-0. 판정 요약 — 왜 "블랭킷 숨김"이 아니라 "2축 차등"인가

- 학습 '대상'(어휘·문장·문법)의 몽골어 **상시** 노출은 한국어 몰입을 해친다 → 숨긴다(탭 리빌만).
- 그러나 운영·지시문(내비·버튼·숙제 지시문·온보딩·도움말·안전)은 학습 대상이 **아니다**. A1~A2 초급생·한글 미해득 신입에게 이것까지 한국어만 주면 첫 2~4주에 길을 잃고 이탈한다(코드가 신입 14~45일을 이탈 위험 신호로 추적 — 초기 이탈이 실제 KPI). → 운영·지시문 몽골어는 **허용**.
- 유호님이 우려한 "한번 몽골어로 두면 계속 몽골어"는 **자유 토글(구 안 B)을 학생에게서 제거**하면 원천 차단된다.
- 이 설계는 전부 "읽기 전용 표시" + Visibility 조건이라 **Glide 월 업데이트 소비 0**(마스터보드 U-1~U-7). 비용이 드는 유일한 길이 유호님이 원치 않는 학생 토글이므로, **교육적으로 옳은 선택과 비용상 최선이 일치**한다.

### 3-1. 축 1 — 콘텐츠 성격별 노출 규칙 (필드 축)

카드에 뭘 붙일지는 **그 텍스트가 '학습 대상'인지 '운영·지시문'인지**로 갈린다.

| 콘텐츠 성격 | 예시 (contents 유형) | 학생 화면 규칙 | G열 바인딩 |
|---|---|---|---|
| **학습 대상** (어휘·문장·문법) | 학습 텍스트·도감 설명·스토어 설명 | 한국어(D) 전용. 몽골어 뜻은 **"뜻 보기" 탭 리빌만**(기본 off) | ❌ raw 병기 금지 (잠금 규칙 1) |
| **운영·지시문** | `homework`(숙제 지시문)·`label`(UI 라벨)·온보딩·도움말·안전 문구 | 몽골어 허용 (초급 스캐폴딩) | ✅ 접이식/조건부 허용 (축 2 따름) |
| **퀴즈** | `quiz` (`문제\|정답\|해설` 포맷) | Split/Template로 '\|' 앞만 | ❌ D/G raw 금지 (잠금 규칙 2) |

**A) 학습 대상 카드 — 한국어 전용 + "뜻 보기" 탭 리빌 (~7분/화면)**

기본 화면엔 한국어만. 학생이 눌러야 몽골어 뜻이 나오는 접이식.
1. Data editor → `contents` → `몽골어(G)` Type = **Text** 확인.
2. 학습 대상 Collection의 **상세화면**을 연다(카드 본체 아님 — 상세에서만 리빌).
3. 상단: 기존 `설명(D)` Text(한국어)는 그대로 둔다. **여기에 몽골어(G)를 나란히 추가하지 않는다**(= 잠금 규칙 1).
4. 몽골어 뜻은 **접이식으로만**: 상세화면에 몽골어(G) Text를 1개 추가하되, 오른쪽 **Visibility → Add condition** 로 리빌 스위치를 건다. 초보 최단 경로:
   - `profiles`에 **User-specific 불리언 컬럼** `뜻보기`(기기별 저장 → 시트 안 건드림, 업데이트 0)를 만든다(Data editor → `profiles` → **Add column → User specific → Boolean**).
   - 학습 상세화면 상단에 **Switch(또는 버튼) 컴포넌트** → 대상 = `뜻보기`, 라벨 = "🇲🇳 뜻 보기".
   - 몽골어(G) Text의 **Visibility = `뜻보기` is `true`** **그리고** `몽골어 is not empty`.
5. 결과: 기본은 한국어 몰입, 학생이 "뜻 보기"를 눌렀을 때만 그 카드에서 몽골어가 뜬다. 화면을 나가면 기본 off로 돌아오게 두려면 User-specific 값을 켜둔 채 둬도 되고, 카드별로 두고 싶으면 이 스위치를 상세화면에만 배치한다.

> 💡 User-specific 불리언은 **학생이 언어를 "영구히" 바꾸는 게 아니라** "이 뜻 잠깐 볼래"에 가깝다 → 잠금 규칙 3(자유 토글 금지)에 저촉되지 않는다. 앱 전체 언어를 뒤집는 KO/MN 선택지는 만들지 않는다.

**B) 운영·지시문 카드 — 몽골어 허용 (~5분/화면)**

숙제 지시문(`homework` G열)·UI 라벨(`label` 행)·온보딩·도움말은 학습 대상이 아니므로 한국어 밑에 몽골어를 깔아도 된다(초급 스캐폴딩). 단 노출량은 축 2(레벨)로 조절.
1. 해당 지시문 카드/상세화면에서 기존 한국어 Text 아래 **Components(+) → Text** → Content = `몽골어(G)`.
2. **Visibility = `몽골어 is not empty`**(미번역 행 빈 줄 방지).
3. 축 2의 레벨 조건을 함께 건다(아래 3-2).

### 3-2. 축 2 — 레벨별 노출 (레벨 축)

같은 운영·지시문이라도 급수에 따라 몽골어 스캐폴딩을 다르게 준다. 초급은 많이, 중급 이상은 자동으로 뗀다.

| 급수 | 운영·지시문 몽골어 | 방식 |
|---|---|---|
| **A1~A2** (초급) | 접이식으로 노출(기본 접힘, "도움말 ⌄") | 아래 A |
| **B1+** (중급 이상) | 자동 숨김 | 아래 B (Visibility = 급수 Lookup) |

**전제:** `profiles`에 학생 급수 열이 있어야 한다(예: `급수` 또는 `레벨`). 없으면 유호님이 급수 열 위치를 확인해 알려주면 아래 조건의 대상 컬럼만 바꾸면 된다.

**A) A1~A2 — 접이식 몽골어 스캐폴딩 (~6분)**
1. 운영·지시문 몽골어(G) Text에 3-1-A와 같은 방식의 **User-specific 불리언 `도움말펼침`** + 스위치("도움말 ⌄")를 상단에 둔다(기본 off = 접힘).
2. 몽골어(G) Text **Visibility**에 조건 2개(AND):
   - `Signed-in user → 급수` **is one of** `A1, A2` (또는 `급수` **is not** `B1`/`B2`… 환경에 맞는 형식)
   - `도움말펼침` is `true`
3. 결과: 초급 학생이 "도움말 ⌄"을 펼쳤을 때만 몽골어 지시문이 뜬다.

**B) B1+ — 급수 Lookup 자동 숨김 (~4분)**
1. 위 A와 동일하게 몽골어(G) Text를 두되, **Visibility = `Signed-in user → 급수` is one of `A1, A2`** 만 건다(펼침 조건은 선택).
2. 급수가 B1 이상이면 이 컴포넌트가 **자동으로 사라진다**(Visibility 미충족) → 중급 이상은 몽골어 스캐폴딩을 자동으로 뗀다. 학생 조작·업데이트 0.

> 💡 급수 열이 Lookup/Relation으로만 존재하면(예: 반→급수) `profiles`에 급수 Lookup 컬럼을 1개 만들어 그걸 Visibility 대상으로 쓴다. Lookup은 읽기 전용이라 업데이트 0.

### 3-3. 학부모 — 몽골어 주(이미 완결, 재작업 불필요)

학부모 뷰(주간 리포트·오늘의 대화·축하 배너)는 `calcAll`이 몽골어를 주(主)로 하는 HTML을 직접 생성한다(Code.js). 별도 바인딩·번역 열이 필요 없다. 학부모가 콘텐츠 카드를 볼 때 몽골어를 원하면 **역할 기반 자동 분기**만 추가한다:
1. 같은 카드에 Text 2개: `설명(D)`(한국어)·`몽골어(G)`(몽골어).
2. 한국어 Text **Visibility = `Signed-in user → role` is `student`**(또는 teacher/admin).
3. 몽골어 Text **Visibility = `Signed-in user → role` is `parent`** **그리고** `몽골어 is not empty`.

> 학부모는 역할이 고정이라 토글이 필요 없다(잠금 규칙 3과 무관). 학생 역할에는 이 몽골어 Text를 **절대 노출하지 않는다.**

### 3-4. 퀴즈 — raw 바인딩 금지, Split/Template 필수 (잠금 규칙 2)

`quiz` 유형은 D/G열이 `문제 — 선택지|정답 — 해설` 포맷이라 Text에 그대로 붙이면 정답+해설이 노출된다. 현재 학생 홈 퀴즈 카드는 제거돼 있으나, 재도입 시:
1. `contents`(또는 quiz 소스)에 **Template/Split 컬럼**을 만들어 `|` **앞부분(문제·선택지)만** 추출한다(Data editor → Add column → **Split text** → Delimiter `|` → 첫 조각, 또는 Template로 재구성).
2. 학생 퀴즈 카드엔 이 **가공 컬럼만** 바인딩한다. D/G 원본은 절대 붙이지 않는다.
3. 학습 대상(문법 문제)의 몽골어 번역은 학생이 정답을 제출·확인한 **뒤에만** 노출(탭 리빌).

> **번역 품질 주의:** G열은 기계 초벌 번역(`translateContents`) 비중이 있다. 학습·지시문 몽골어는 **몽골어 가능한 크루 1회 검수** 권장(현재 몽골어 감수자 미정). label 행(L01~L15)·reason 행(R01~R09)은 이미 직접 큐레이션돼 검수 불필요.

### 3-5. Glide 앱 크롬(시스템 UI) 언어 — 유호님 확인 필요 *(추정 — 설정 확인 전제)*

유호님이 우려한 "한번 몽골어로 두면 계속 몽골어"는 콘텐츠 데이터가 아니라 **Glide 앱 자체의 다국어 기능(시스템 크롬: 탭바·Submit·로그아웃 등)** 레벨에서 발생할 가능성이 높다(추정 — 제공 파일만으로 on/off 확인 불가). Glide 다국어는 통상 기기 언어를 따라가고 선택을 기억한다.
- **최대 몰입을 원하면:** 앱 크롬 언어를 **한국어 고정**.
- **유호님이 허용한 "기본 작동 메뉴만 몽골어"를 원하면:** 크롬은 기기 언어를 허용하되, **학습 '대상' 텍스트는 위 3-1처럼 데이터(D열)로 관리**해 크롬 언어와 분리한다(잠금 규칙 4).
- 어느 쪽이든 학습 콘텐츠가 크롬 언어 설정에 흔들리지 않게 격리하는 것이 핵심.
- 👉 이 판단은 유호님이 Glide 편집기에서 **Settings → Languages(다국어)** 상태를 눈으로 확인해야 결정할 수 있다(체크리스트 참조).

## 부록 B · 선행 코드 작업이 필요한 항목 (요약)

바인딩만으로 안 되고 **Apps Script 코드가 먼저** 있어야 하는 것만 추림(그 외는 전부 Glide 조작으로 완료):

1. **스토리북 삽화 이미지** — `synk_stories`에 실제 `image_url` 열 없음(영문 프롬프트만 존재). 이미지 생성 + 열 추가·채움 코드 선행. (섹션 2-1)
2. **스토리북 본문 몽골어** — `synk_stories.본문(F)` 한국어 전용. 학부모용 몽골어 스토리 원하면 번역 열 코드 선행. (섹션 2-1)
3. **레이드 스토리 몽골어** — `raid_story.스토리(E)` 한국어 전용. 학부모 몽골어 뷰 원하면 번역 열 코드 선행. (섹션 2-3)
4. **학생 개인 리그/레이드 기여 수치** — 참여·승수는 내부 계산만 하고 `profiles`에 개별 열로 저장 안 함. 개인 "내 전적 숫자" 카드 원하면 profiles 열 추가 코드 선행. (섹션 2-2·2-3, 선택)

> 위 4건은 **없어도 각 탭이 완성됨**(텍스트 서사·집계 카드로 충분). 삽화·다국어·개인 수치는 "다음 버전" 후보.
