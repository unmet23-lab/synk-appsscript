# 엔진 추천 목표 — 추천·학생의 말·후속 관측 v1.1

> 2026-09-13 · [엔진 7종](엔진7종_상향설계_v3.md) Core U2·D6의 09-05 채택과 현재 c14 목표 응답 코드를 대조했다. 옛 승인 대기·성향 확인 카드에 목표를 얹는 별도 사건안·아침 저장 불가를 영구 조건으로 두던 문장을 정리했다. 필드·값목록은 [수집·교정 계약](../계약/수집_교정_계약.json)이 정본이다.

## 0. 목적

아침에 엔진이 추천한 것, 학생이 실제로 말한 목표, 밤의 자기 신고, 해당 문형의 후속 관측을 구분해 연결한다. “엔진이 고른 목표”를 “학생이 선언한 목표”로 기록하지 않는다. 학생은 추천과 다른 목표를 말하거나 바꿀 수 있다.

예: 엔진은 조사를 추천했지만 학생이 발음을 골랐다면 두 사실을 각각 남긴다. 밤에 “해냈다”고 답한 것과 실제 수행도 서로 다른 자료다. 과제에 해당 문형이 없거나 제출이 없으면 관측은 미측정이다.

## 1. 현재 실물과 남은 연결

| 조각 | 09-13 로컬 코드 대조 |
|---|---|
| 아침 추천 | Apps Script `circleMemberCard_`의 `shaky`·`next_one`, `printCircleSheets` 인쇄 경로가 존재 |
| 추천 당시 저장 | `goal_recommended` 생산자는 해당 Apps Script 경로에서 확인되지 않음. 인쇄 뒤 정확한 추천 스냅샷·ID 보존이 남음 |
| 밤 자기 신고 | talk `lib/목표확인.js`·`src/목표카드.js`·`functions/progress` → `goal.responded` 구현 |
| 자기 신고 소비 | talk `lib/학습자상태.js` ⑬목표축이 `goal.responded`를 읽음. 현재는 목표 내용 없는 자기 신고 |
| 학생이 말한 목표 | Core U2·D6이 강사 중계와 학생 앱 1탭 병행을 채택. `goal.stated`는 c17 예약 어휘이며 현재 유효 event_type/생산자와 구분 |
| 카드 횟수 | 성향 확인 `estimate.responded`의 `하루상한`과 목표 `goal.responded` 하루 1회는 별도 구현. 옛 “같은 하루 한 칸” 서사는 폐기 |
| 실제 사용 | 이번 문서 정리에서 라이브 DB·실제 학생 응답·수신·효과는 확인하지 않음 |

목표 응답의 현재 계약과 한계는 [교실 수집 목표 왕복](교실수집_목표왕복_설계_v1.md)을 따른다. `goal.responded`를 `estimate.responded`로 바꾸거나 같은 사실을 두 사건에 중복 저장하지 않는다.

## 2. 원신호를 가르는 기준

- 엔진 추천은 시스템이 고른 사실이다. 학생에 대한 관측이나 학생의 의사로 쓰지 않는다.
- 학생이 말하거나 누른 목표·응답은 `explicit`이다. 강사가 중계해도 발언 주체는 학생이며 직접 관찰한 강사 판단과 구분한다.
- “해냈다고 말했다”는 독립 수행의 증거가 아니다. 자기 신고 비율을 성실도나 성격 점수로 내보내지 않는다.
- 태그 부재·무응답·제출 없음·해당 문형 미등장을 성공·실패·의지 부족으로 채우지 않는다.

`source_kind`의 현재 값목록에는 `system`이 없다. 추천 저장의 위치와 사건 형태는 계약 개정에서 맞추며, 이 문서만으로 새 값을 유효하게 만들지 않는다.

## 3. 연결 설계

### 3-1. 엔진 추천 스냅샷

인쇄 성공 뒤 실제 나간 추천을 저장한다. 최소 연결은 추천 ID(`goal_id`), 학생·반·회차·날짜, 추천 태그, 실제 인쇄 문장, 선택 규칙판이다. 재제시를 구분하려면 `origin_goal_id`·`attempt_no`를 연결한다. 구체 저장 필드·원천은 구현 계약에서 확정한다.

이력 없는 첫날에는 없는 태그를 지어 넣지 않는다. 인쇄물의 식별자 제한은 유지하고 서버 내부 고리와 구분한다.

### 3-2. 학생이 말한 목표

Core U2·D6의 채택 방향은 강사 M2 중계와 수업 뒤 학생 앱 1탭을 병행하는 것이다. 후보 어휘는 `goal.stated`, `goal_tag`·`goal_text`·`channel`·`origin_goal_id`다. 통로는 `teacher_relay`와 `student_app`, 출처는 `explicit`로 구분한다. 학생의 말은 추천보다 우선하며, 추천 ID가 없을 때도 학생의 목표를 버리지 않도록 고리는 null을 허용한다.

목표 원문은 당시 그대로 내부에 남기고 외부 입력에는 현행 비식별 처리 규칙을 적용한다. 학생 문장 길이·태그·값목록은 c17 계약과 생산자·소비자에서 함께 맞춘다.

### 3-3. 밤 자기 신고와 관측

현재 `goal.responded`의 `response`·`class_date`·`card_version`을 유지한다. 목표 내용을 연결할 때는 당시 스냅샷 참조를 붙여 어느 추천 또는 선언에 대한 답인지 알 수 있게 한다. 문구만 바꿔 기존 답의 의미를 소급 변경하지 않는다.

해당 목표의 교정·수행 관측과 나란히 비교한다. AI 초안과 검수 확정, 자기 신고와 독립 수행, 실제 관측과 잴 수 없음을 구분한다. 문법이 관측되지 않았다고 성공이라 하지 않는다.

### 3-4. 반환

학생이 고친 목표와 응답은 다음 과제·답장에 이어져야 한다. “못 지킨 약속”을 추궁하거나 사람에게 “착각형” 같은 낙인을 붙이지 않는다. 새 화면 수나 옛 카드 수를 영구 상한으로 삼지 않고 기존 일상 흐름에서 부담 없이 반환한다.

## 4. 소급 불가 지점

아침 선택기는 그때까지 쌓인 자료를 읽는다. 밤에 같은 함수를 다시 실행하면 다른 추천이 나올 수 있으므로 재계산을 아침 기록 복원으로 쓰지 않는다. **추천 당시 ID·문장·기준판·시각**을 실제 추천이 발생하는 경로에 남긴다.

학생의 말도 실제 발생 시점의 통로가 필요하다. 추천 저장, 학생의 목표, 밤 응답이 따로 있는 상태를 완성된 왕복으로 보고하지 않는다.

## 5. 현재 유지하는 경계

수업 중 폰을 다시 켜거나 마무리 종이의 확인 동그라미를 회수하는 설계로 바꾸지 않는다. 그 범위와 수업 뒤 앱의 학생 1탭은 서로 다르다. 원본·동의·접근 규칙을 지키고, 무응답·“아직”에 벌·잠금·재촉을 붙이지 않는다.

## 6. 구현 위치

| 연결 | 담당 |
|---|---|
| 인쇄된 추천 저장 | Apps Script `circleMemberCard_`·`printCircleSheets`의 성공 경로 |
| 학생 목표 생산 | talk `functions/teach` 관찰 경로와 학생 앱 목표 카드 |
| 원산 분리·선택 | talk `lib/학습자상태.js` 목표축·`functions/progress`·과제/답장 소비자 |
| 밤 응답 | talk `lib/목표확인.js`·`src/목표카드.js`·`goal.responded` 계약 |
| 관측과 반환 | 교정·수행 원본 + 과제·답장·시즌 회고의 해당 소비자 |

두 저장소의 계약·생산자·소비자·관련 시험을 함께 맞춘다. 실제로 이은 단계만 완료로 표시한다.

## 7. 현재 결정과 재검토

09-02 이름을 엔진 추천 목표로 낮춘 결정은 당시 원본 부재를 정직하게 표시한 것이다. 09-05 Core U2·D6은 학생의 말을 받는 통로를 채택했다. 따라서 “이 기능은 학생의 말을 절대 받지 않는다”는 금지는 유지하지 않는다. 구현 전에는 이미 학생 목표가 수집된다고 표시하지 않는다.

옛 네 선택지의 단일 카드 배분·재제시 횟수·30일 후 리포트 고정값은 현행 계약과 발전 설계에 맞춰 판단할 설계값이다. 별도 승인 대기표로 복제하지 않는다. 통계 표본과 실제 도움이 충분한지는 출력의 주장에 맞게 확인하고, 학생 자기 신고를 성실도 수치로 내보내지 않는다.

## 8. 인수 조건

- **모였나:** 실제 인쇄 성공과 추천 저장이 짝을 이루고 학생의 말·밤 응답이 별도 원본으로 남는다.
- **닿았나:** 소비자가 당시 추천/선언을 읽으며 응답이 정확한 목표에 연결된다.
- **달라졌나:** 추천과 다른 학생 목표·부정 응답을 바꾸면 다음 과제나 답장이 의도대로 달라진다.
- **누구에게:** 학생이 그 변화를 실제로 받는다. 합성 왕복과 실사용·학습 효과는 구분한다.

## 9. 아직 확인할 것

추천 스냅샷 저장·`goal.stated` 활성 계약과 생산자·교정 관측 조인·목표 기반 실제 출력은 미완료다. 현행 목표 카드는 출석/수업일 대신 몽골 날짜 평일 근사를 쓰므로 휴일·주말반의 정확한 노출도 남아 있다. 몽골어 문구와 실제 카드 도달률은 실사용 전에 해당 검증을 이어간다.
