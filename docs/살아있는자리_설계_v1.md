# 살아있는 자리 — 앱 공간과 기능 설계

> 현행 기준 · 2026-09-13. 사용자가 09-05 확정한 ‘가능한 모든 기능을 살아있는 자리로’라는 방향을 구체화한다. 제품 계약은 [앱 재설계](앱재설계_v2.md), 행동은 [캐릭터 생명감](캐릭터/캐릭터_생명감_설계.md), 그림·움직임은 [Loom 표현 기준](Loom_실시간장면_표현기준.md)을 따른다. 아래 지도는 설계이며 각 화면의 배포·사용 완료를 뜻하지 않는다.

## §0. 목적과 현재 기준

학생이 자기 방의 책상에서 숙제하고 우편함에서 답장을 열며, 강사는 교무실에서 오늘 말 걸 아이를 찾고, 부모는 아이의 소식을 받는 자리다. 장소·사람·물건·빛과 실제 기능이 함께 반응하게 만든다. 처음 보는 사람이 상황·선택·다음 행동을 바로 알 수 있어야 한다. 공간 비유가 사용을 늦추면 더 단순한 도구로 만든다.

생명감과 편안함은 유지하면서 기능을 완결한다. 화면마다 인물·문·기록·시계를 억지로 새로 만들지 않는다. 같은 공간의 요소를 공유하고, 해당 없는 조건은 생략한다. 어떤 공간이든 저장·전송·구매·신고의 실제 상태를 연출로 가리지 않는다.

[몽글과 바람의 정원](../experiences/loom-living/README.md)에서 펠트 원본을 지키는 국소 깜빡임·바람·천과 스티치 말풍선이 구현됐다. 이를 다음 지원 매체에 재사용하며 옛 ‘펠트는 모두 정지·움직임 검증 0·12월 시연 전 보류’를 공통 선행 조건으로 쓰지 않는다. 이 로컬 실물은 학생 앱 전체의 구현·실기기 품질·학생 만족 증거와 구별한다.

## §1. 확인된 기억으로 챙긴다

소통의 재료는 실제로 수집하고 허용된 학생 이해에서 가져온다. 어제 한 일·편지 도착·확인된 성향·학생 목표·선택 당시 맥락을 알 때만 사용한다. 재료가 없으면 따뜻한 인사나 몸짓으로 만난다. 방문마다 새 개인정보·말풍선을 강제하지 않는다.

| 재료 | 사용 경계 |
|---|---|
| 이름·역할 | 해당 화면에서 허용된 수신자에게만 표시 |
| 제출·답장·첫 순간 | 실제 수신·열람·첫 발생 사건을 사용. 저장 전 축하나 관측 없는 완료 표현 금지 |
| 성향·선호 | `estimate.responded`의 확인과 `preference.stated`의 취향 선언을 구별. 추정을 사실로 단정하지 않음 |
| 시험·목표·삶 | 학생이 남긴 유효한 기록과 실제 날짜를 사용 |
| 옷·배경 선택 | 당시 가격·재고·잔액 등 선택 제약을 함께 보고 제약을 취향으로 배우지 않음 |
| 반의 함께한 날 | 그날 온 아이 중 과제를 낸 전원이라는 정의 사용. 이름·등수·타인과의 비교 없음 |
| 시간·날씨 | 서버와 동기화한 시각 사용. 계절만 보고 실제 날씨를 지어내지 않음 |
| 재회·힘든 날 | 재촉·죄책감·시무룩한 반응 없이 다시 만나거나 함께 들여다봄 |

전날 재료 봉투와 오늘 사건은 구별한다. 봉투의 `as_of`가 유효한 날에만 ‘어제·오늘·다음 주’를 사용하고, 배치 실패·오래된 오프라인 재료에는 날짜 없는 인사로 돌아간다. 오늘 제출·구매는 오늘 실제 사건으로 반응한다. 대사가 실제 표시됐다는 관측은 기존 companion 노출 사건 계약으로 남긴다.

기본 인사·배경 대사는 현재 템플릿과 확인된 재료로 표현하고, 안내 책은 승인된 학원 문답을 사용한다. 이 선택을 모든 대화·엔진에 적용하는 LLM 금지로 확대하지 않는다. 새로운 대화 기능은 현재 제품 목적·입력 경계·답의 근거·실제 품질에 따라 발전시킨다. 마스코트 기본 반응과 사용자가 열어 요청한 대화는 별도 층이다.

## §1-b. 공간을 확인하는 여섯 관점

| 관점 | 실제 확인 |
|---|---|
| 누가 있나 | 필요한 인물·마스코트가 그 자리에 맞게 반응하는가 |
| 어떻게 들어가나 | 이동이 읽히고 자주 하는 행동이 지연되지 않는가 |
| 무엇이 남나 | 편지·옷·기록 등 실제 결과를 다시 찾을 수 있는가 |
| 만지면 어떻게 되나 | 입력과 표정·몸짓·기능의 반응이 연결되는가 |
| 시간이 흐르나 | 시간·계절·새 소식이 필요한 위치에 반영되는가 |
| 나를 챙기나 | 확인된 기억과 현재 사정이 다음 경험을 바꾸는가 |

이 관점은 모든 화면에 여섯 장치를 강제하는 검문이 아니다. 처음 방문한 사람의 과제 찾기→제출→답장→다시 말하기 등 맡은 흐름으로 확인한다. 장면 전환 시간·동시 운동 개수·대사 상한은 해당 매체와 목적에 맞춰 조절하며, 정원의 바람 주기를 모든 문·버튼의 시간으로 복사하지 않는다.

녹음 중에는 연출·소리를 멈추고, 움직임 줄이기에서도 정보·정적 표정·기능은 남긴다. 같은 순간 말풍선·주요 연출이 겹쳐 읽기를 방해하지 않게 한다. 소리는 현재 승인 자산과 앱의 소리 우선순위를 사용한다. 특정 세 종·신규 네 종·고정 모델을 모든 새 장면의 한도로 두지 않는다.

## §2. 학생 — 내 방과 마을

| 자리 | 맡은 기능과 남는 것 | 실제 상태의 경계 |
|---|---|---|
| 내 방 | 오늘 과제, 일기장, 우편함 깃발, 기록 액자, 마스코트, 창밖 빛 | 현재 첫 흐름을 기준으로 자연스럽게 연결. 캐릭터 원본은 자산 코드 사용 |
| 책상 | 녹음·문장 낭독·제출·답장으로 이동 | 서버 수신 전은 전송 중/보관 중, 완료 뒤 편지 연출. 녹음 중 정지 |
| 안내 책 | 마스코트를 눌러 여는 1:1 학원 문답 | 현재는 승인 문답의 고르는 대화 가지. 없는 답은 지어내지 않고 문의 통로로 |
| 마을 길 | 가게·게임 자리 이동, NPC 인사 | 모든 이동마다 긴 애니메이션을 요구하지 않음 |
| 옷 가게 | 미리 입기·흥정·구매·회전 재고 | 서버 거래 확정 뒤 소유 표시. 동시 구매·응답 유실·가격표 변경은 구매 계약대로 |
| 옷장 | 보유 옷·배경 착용, 거울 | 현재 원본과 실제 보유 상태 사용. 시즌 차림 카드는 액자에 |
| 우편함 | 내 녹음·고친 문장·낭독·다시 말하기, 시즌별 편지 | 편지는 남고 열람 상태와 깃발 동기화. 최근 한 통만 보이는 구현을 완성으로 확대하지 않음 |
| 액자 | 어제의 나·함께한 날·시즌 차림 카드 | 시즌 카드는 한 곳에서 관리. 함께한 날 사진은 이름·등수 없이 해당 참석자 범위 사용 |
| 초원·하숙집·시장·사무실·복도 | 해당 게임의 NPC·물건·한국어 판단과 결과 | 게임 자체의 목적·계약과 실제 결과 확인 |

방·길·가게·한정판 달력은 같은 서버 기준 시각을 사용한다. 앱은 동기화한 시각으로 그리고, 재고 회전·출석·구매처럼 남는 사실은 서버 사건 시각으로 판별한다. 옷·배경·표정과 ‘내 마스코트’ 선택 규칙은 담당 제품·가이드 계약을 따른다.

## §3. 강사 — 교무실

| 자리 | 기능과 경계 |
|---|---|
| 교무실 책상 | 오늘 반·말 걸기 쪽지·검수 서류함으로 바로 연결. 현재 강사 챗봇 코드와 승인 지식을 재사용 |
| 교실 문 앞 | 출석 확인·말 걸기 가이드·개입 기록·수업 뒤 관찰. 교사가 실제 본 것을 먼저 쓰고 AI가 정리를 도움 |
| 담당 반 복도 | 담당 학생의 실력·사람·삶 지도와 근거 읽기. 기획자의 상담·수업료·가정 사정 서랍은 노출하지 않음 |
| 서류함 | 교정·게임 산출의 검수와 완료 상태 |
| 달력·나침반 | 시즌 시작과 학생 먼저→강사 다음의 회고 |

출석은 ‘온 날·안 온 날’ 표시와 내부 미입력·동기화 중을 구별한다. 미입력을 결석으로 만들지 않고 과제 없는 날을 미제출로 세지 않는다. 단순 인사·매일 첨삭까지 강사의 재승인을 요구하지 않는다.

## §4. 기획자 — 전체 운영

전체 학생 지도는 역할 권한으로 열고, 상담·결제·가정 사정의 기획자 서랍은 현재 운영 시트 범위를 유지한다. 옷 가게 운영·연습 판·발화 검수·문구 감수·비밀번호 같은 운영 기능은 명료한 도구 화면으로 둔다. 담당 반을 맡으면 강사 기능을 함께 제공한다.

연습 판은 합성 학생과 운영 데이터를 분리한다. 창고·빈 교실 장면을 다시 만드는 것을 기본 과제로 두지 않는다. 역할 권한과 데이터 경계를 실제 화면·API에서 함께 확인한다.

## §5. 부모 — 아이의 소식

| 자리 | 기능과 경계 |
|---|---|
| 현관 | 아이의 실제 차림과 주간 소식·안내 책. 부모 연결은 학생의 초대와 현재 제품 계약대로 |
| 달력 | 온 날·말한 날을 보여주되 미입력·과제 없는 날과 구분 |
| 우편함 | 월간 리포트와 이미 아이에게 전달된 소식 |
| 학원 문 앞 쪽지 | 결석·문의 신고, 학원 수신과 담당자 확인 상태, 실패·전송 중 구분 |

신고가 서버에서 확정되었으면 결석 긴급 알림을 보내지 않는다. 동기화 중을 미신고로 단정하지 않는다. 담당 강사에게 필요한 결석 안내가 이어지고 부모에게 수신 상태가 돌아가게 한다. 부모 화면에도 다른 학생의 등수·우열 비교를 넣지 않는다.

## §6. 자산과 제작

신규 자산 수량·4K 생성 모델·그림 장수는 실제 화면에 필요한 범위를 세어 정한다. 방·배경·가구·NPC·편지·액자·문 등은 현재 승인 자산을 먼저 찾아 조합하며 부족한 것만 제작한다. 과거 ‘40장대·75장·128차림’ 수량을 자동 재생성 명령으로 읽지 않는다.

### §6-b. 기존 원본을 먼저 연결한다

[DESIGN](../DESIGN.md)과 `tools/lib/마스코트자산.js`에서 승인본을 확인하고 `docs/공방/계획.json`·공용 자산·해당 제작 결과를 찾는다. 같은 이름의 날짜 폴더를 최신 원본이라고 가정하지 않는다. 표정은 공통 몸 위 눈 영역만 바꾸고 몸짓은 별도 연출로 확인한다. 장면 구현은 [Loom 표현 기준](Loom_실시간장면_표현기준.md)의 공통 시간·국소 변형·그림자·말풍선을 이어 쓴다.

숫자·게이지·메달 자산은 존재만으로 성장·이해 화면에 넣지 않는다. [철학 적용 기준](철학_적용기준.md)의 성장 표현 범위를 따르며, 가격·시험 점수의 사실 표시와 내부 운영 계산을 함께 금지하지 않는다.

## §7. 구현을 이어가는 순서

승인된 첫 흐름과 현재 코드에서 사용자가 맡긴 기능을 하나씩 완성하고 연결한다. 방→과제→제출→답장→다시 말하기의 접근성과 실제 상태를 먼저 확인하고 해당 작업에 필요한 가게·게임·강사·부모 기능으로 넓힌다. 09-04의 구현 늦춤이나 삭제된 시연·과거 판정 대기를 모든 후속 작업의 조건으로 삼지 않는다.

새 장면은 실제 크기·배경에서 깜빡임·입력·쉬는 상태·움직임 줄이기·녹음 경계를 확인한다. 연출만 완성되어 저장·구매·신고가 이어지지 않는 상태를 제품 완료로 세지 않는다.

## §8. 현재 상태를 확인할 곳

앱의 실제 화면·데이터·배포는 SYNK-talk의 현재 코드·계약과 [트랙](_ops/트랙.md)을 대조한다. 정원의 로컬 확인은 재사용 근거이며 모든 앱 화면·새 장면·학생 반응까지 검증했다는 뜻이 아니다. 인사·바람에 맞춘 새 표정은 제안 상태이고 이번 문서 압축에서 추가하지 않았다.

과거 역할별 자산 목록·구현 수량·심문 경위는 [정리 전 Git 판](https://github.com/unmet23-lab/synk-appsscript/blob/f657502b1c85/docs/%EC%82%B4%EC%95%84%EC%9E%88%EB%8A%94%EC%9E%90%EB%A6%AC_%EC%84%A4%EA%B3%84_v1.md)에 있다.
