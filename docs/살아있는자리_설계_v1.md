# 살아있는 자리 — 앱 공간과 기능 설계

> **현행 입구 · 2026-10-17:** WORLD는 [10-14 시그널 방향](디자인/월드_시그널/README.md#firstrun-town-20261014)의 펠트 첫 화면·우리 동네를 사용하며 우리 집의 3D 공간과 싱크타운은 각 소비 위치로 구분한다. 10-09의 전면 3D 우선안으로 현재 펠트 입구를 되돌리지 않는다. 실제 화면은 [WORLD README](../experiences/synk-world-app/README.md), 새 마스코트 장면 제작은 [AI 운영 원칙](AI_운영원칙.md)을 따른다.

> 경험 설계 · 2026-09-13. 사용자가 09-05에 확정한 ‘가능한 모든 기능을 살아있는 자리로’라는 방향을 구체적으로 정리한 문서다. 제품 계약은 [앱 재설계](앱재설계_v2.md), 캐릭터의 행동은 [캐릭터 생명감](캐릭터/캐릭터_생명감_설계.md), 그림과 움직임은 [Loom 표현 기준](Loom_실시간장면_표현기준.md)을 따른다. 아래의 공간 구성은 설계이며, 각 화면이 배포됐거나 사용되고 있다는 뜻이 아니다.

## §0. 목적과 현재 기준

아래 학원 학습 앱 설계에서 학생은 자기 방 책상에서 숙제를 하고 우편함에서 답장을 연다. 이 학생·강사·부모 모델을 회사 플랫폼·회사 메신저·모든 사업의 필수 구조로 적용하지 않는다. 강사는 교무실에서 오늘 말을 걸 아이를 찾고, 부모는 아이의 소식을 받는다. 장소·사람·물건·빛이 실제 기능과 함께 반응하게 만든다. 처음 보는 사람도 지금 상황, 고를 수 있는 것, 다음에 할 일을 바로 알 수 있어야 한다. 공간 비유 때문에 사용이 느려지면 더 단순한 도구 화면으로 만든다.

생명감과 편안함을 유지하면서 기능은 끝까지 완성한다. 화면마다 인물·문·기록·시계를 억지로 새로 만들지 않는다. 같은 공간의 요소는 함께 쓰고, 해당하지 않는 조건은 생략한다. 어떤 공간에서든 저장·전송·구매·신고의 실제 상태를 연출로 가리지 않는다.

[몽글과 바람의 정원](../experiences/loom-living/index.html)에서 펠트 원본을 그대로 유지한 채 국소 깜빡임, 바람, 천과 스티치 말풍선을 구현했다. 이 구현은 다음에 지원할 매체에서 재사용한다. 예전 규칙인 ‘펠트는 모두 정지·움직임 검증 0·12월 시연 전 보류’는 더 이상 공통 선행 조건으로 쓰지 않는다. 다만 이 로컬 구현이 학생 앱 전체의 구현, 실기기 품질, 학생 만족을 증명하는 것은 아니다.

## §1. 확인된 기억으로 챙긴다

학생과 소통할 때 쓰는 재료는 실제로 수집했고 사용이 허락된 학생 이해 정보에서만 가져온다. 어제 한 일, 도착한 편지, 확인된 성향, 학생의 목표, 선택할 당시의 맥락을 알고 있을 때만 쓴다. 재료가 없으면 따뜻한 인사나 몸짓으로 맞이한다. 방문할 때마다 새 개인정보나 말풍선을 꼭 넣어야 하는 것은 아니다.

| 재료 | 사용 경계 |
|---|---|
| 이름·역할 | 해당 화면에서 볼 권한이 있는 사람에게만 표시 |
| 제출·답장·첫 순간 | 실제로 받은 것, 열어 본 것, 처음 일어난 이벤트만 사용. 저장 전에 축하하거나 확인되지 않은 완료를 표현하지 않음 |
| 성향·선호 | 실제 제품에서 회원이 명시한 설정·선호와 확인된 관측을 구별하고 성격을 단정하지 않음. 옛 `estimate.responded`·`preference.stated`는 [성향 계약](성향추출_설계_v1.md)의 역사 사건이며 현재 생산자가 없음 |
| 시험·목표·삶 | 학생이 남긴 유효한 기록과 실제 날짜를 사용 |
| 옷·배경 선택 | 선택할 때의 가격·재고·잔액 같은 제약을 함께 보고, 제약 때문에 고른 것을 취향으로 학습하지 않음 |
| 반의 함께한 날 | 그날 온 아이 중 과제를 낸 전원이라는 정의를 사용. 이름·등수·다른 학생과의 비교는 넣지 않음 |
| 시간·날씨 | 서버와 동기화한 시각을 사용. 계절만 보고 실제 날씨를 꾸며 내지 않음 |
| 재회·힘든 날 | 재촉하거나 죄책감을 주거나 시무룩하게 반응하지 않고, 다시 만나거나 함께 살펴봄 |

전날 만든 이해 요약과 오늘 일어난 이벤트는 구별한다. 이해 요약의 `as_of`가 유효한 날에만 ‘어제·오늘·다음 주’ 같은 표현을 쓴다. 배치가 실패했거나 오프라인 재료가 오래됐으면 날짜가 없는 인사로 돌아간다. 오늘 한 제출·구매에는 오늘 실제로 일어난 이벤트로 반응한다. 대사가 실제로 화면에 표시됐다는 기록은 기존 companion 노출 이벤트 계약으로 남긴다.

기본 인사와 배경 대사는 현재 템플릿과 확인된 재료로 만들고, 안내 책은 승인된 학원 문답을 사용한다. 이 방식을 모든 대화와 엔진에서 LLM을 쓰지 말라는 규칙으로 넓혀 읽지 않는다. 새 대화 기능은 현재 제품의 목적, 입력 범위, 답의 근거, 실제 품질을 보고 발전시킨다. 마스코트의 기본 반응과 사용자가 직접 열어 요청한 대화는 서로 다른 층이다.

## §1-b. 공간을 확인하는 여섯 관점

| 관점 | 실제 확인 |
|---|---|
| 누가 있나 | 필요한 인물·마스코트가 그 장소에 맞게 반응하는가 |
| 어떻게 들어가나 | 어디로 이동하는지 알 수 있고, 자주 하는 행동이 느려지지 않는가 |
| 무엇이 남나 | 편지·옷·기록 등 실제 결과를 다시 찾을 수 있는가 |
| 만지면 어떻게 되나 | 입력하면 표정·몸짓·기능이 함께 반응하는가 |
| 시간이 흐르나 | 시간·계절·새 소식이 필요한 위치에 반영되는가 |
| 나를 챙기나 | 확인된 기억과 현재 사정이 다음 경험을 바꾸는가 |

이 여섯 관점은 모든 화면에 여섯 가지 장치를 다 넣으라는 점검표가 아니다. 처음 방문한 사람이 과제 찾기→제출→답장→다시 말하기처럼 그 화면이 맡은 흐름을 따라가 보며 확인한다. 장면 전환 시간, 동시에 움직이는 요소의 수, 대사 수의 상한은 매체와 목적에 맞춰 조절한다. 정원의 바람 주기를 모든 문·버튼의 시간에 그대로 복사하지 않는다.

녹음 중에는 연출과 소리를 멈춘다. 움직임 줄이기 설정에서도 정보, 정지된 표정, 기능은 그대로 남긴다. 말풍선과 주요 연출이 같은 순간에 겹쳐 읽기를 방해하지 않게 한다. 소리는 현재 승인된 자산과 앱의 소리 우선순위를 따른다. 특정 세 종류·새 네 종류·고정 모델을 모든 새 장면의 한도로 두지 않는다.

## §2. 학생 — 내 방과 마을

| 자리 | 맡은 기능과 남는 것 | 실제 상태의 경계 |
|---|---|---|
| 내 방 | 오늘 과제, 일기장, 우편함 깃발, 기록 액자, 마스코트, 창밖 빛 | 현재의 첫 흐름을 기준으로 자연스럽게 연결. 캐릭터 원본은 자산 코드의 것을 사용 |
| 책상 | 녹음·문장 낭독·제출·답장으로 이동 | 서버가 받기 전에는 전송 중/보관 중으로 표시하고, 완료된 뒤에 편지 연출. 녹음 중에는 연출 정지 |
| 안내 책 | 마스코트를 눌러 여는 1:1 학원 문답 | 지금은 승인된 문답 중에서 골라 가는 대화. 없는 답은 지어내지 않고 문의 경로로 안내 |
| 마을 길 | 가게·게임 장소로 이동, NPC 인사 | 이동할 때마다 긴 애니메이션을 요구하지 않음 |
| 옷 가게 | 미리 입기·흥정·구매·회전 재고 | 서버에서 거래가 확정된 뒤에 소유로 표시. 동시 구매·응답 유실·가격표 변경은 구매 계약을 따름 |
| 옷장 | 보유 옷·배경 착용, 거울 | 현재 원본과 실제 보유 상태를 사용. 시즌 차림 카드는 액자에 둠 |
| 우편함 | 내 녹음·고친 문장·낭독·다시 말하기, 시즌별 편지 | 편지는 계속 남고, 열람 상태와 깃발을 동기화. 최근 한 통만 보이는 지금의 구현을 완성본으로 보지 않음 |
| 액자 | 어제의 나·함께한 날·시즌 차림 카드 | 시즌 카드는 한 곳에서 관리. 함께한 날 사진은 이름·등수 없이 그날 참석한 사람의 범위만 사용 |
| 초원·하숙집·시장·사무실·복도 | 해당 게임의 NPC·물건·한국어 판단과 결과 | 게임마다 목적·계약과 실제 결과를 확인 |

방·길·가게·한정판 달력은 모두 같은 서버 기준 시각을 쓴다. 화면은 동기화한 시각으로 그리고, 재고 회전·출석·구매처럼 기록으로 남는 사실은 서버의 이벤트 시각으로 판단한다. 옷·배경·표정과 ‘내 마스코트’를 고르는 규칙은 담당 제품 계약과 가이드를 따른다.

## §3. 강사 — 교무실

| 자리 | 기능과 경계 |
|---|---|
| 교무실 책상 | 오늘의 반, 말 걸기 쪽지, 검수 서류함으로 바로 이동. 현재 강사 챗봇 코드와 승인된 지식을 재사용 |
| 교실 문 앞 | 출석 확인, 말 걸기 가이드, 개입 기록, 수업 뒤 관찰. 교사가 직접 본 것을 먼저 쓰고 AI는 정리를 도움 |
| 담당 반 복도 | 담당 학생의 실력·사람·삶 지도와 그 근거를 봄. 기획자만 보는 상담·수업료·가정 사정 서랍은 보여 주지 않음 |
| 서류함 | 교정·게임 결과물의 검수와 완료 상태 |
| 달력·나침반 | 시즌 시작, 그리고 학생이 먼저 하고 강사가 다음에 하는 회고 |

출석 화면은 ‘온 날·안 온 날’ 표시와 내부의 미입력·동기화 중 상태를 구별한다. 미입력을 결석으로 처리하지 않고, 과제가 없는 날을 미제출로 세지 않는다. 단순한 인사나 매일 하는 첨삭까지 강사가 다시 승인하게 하지 않는다.

## §4. 기획자 — 전체 운영

전체 학생 지도는 역할 권한이 있을 때 연다. 상담·결제·가정 사정을 담은 기획자 서랍은 당시 상담·결제·가정 사정의 접근 경계를 보존한다. 그 시트 생산 코드는 10-02 삭제됐으므로 현재 운영 화면으로 보지 않는다. 옷 가게 운영, 연습 모드, 발화 검수, 문구 감수, 비밀번호 같은 운영 기능은 알아보기 쉬운 도구 화면으로 둔다. 기획자가 담당 반을 맡으면 강사 기능도 함께 제공한다.

연습 모드에서는 가상 학생 데이터와 실제 운영 데이터를 분리한다. 창고나 빈 교실 장면을 다시 만드는 일은 기본 과제로 두지 않는다. 역할 권한과 데이터 경계는 실제 화면과 API에서 함께 확인한다.

## §5. 부모 — 아이의 소식

| 자리 | 기능과 경계 |
|---|---|
| 현관 | 아이의 실제 차림, 주간 소식, 안내 책. 부모 연결은 학생의 초대와 현재 제품 계약을 따름 |
| 달력 | 온 날·말한 날을 보여 주되, 미입력인 날·과제가 없는 날과 구분 |
| 우편함 | 월간 리포트와 이미 아이에게 전달된 소식 |
| 학원 문 앞 쪽지 | 결석·문의 신고. 학원이 받았는지, 담당자가 확인했는지 보여 주고 실패와 전송 중을 구분 |

부모의 신고가 서버에서 확정됐으면 결석 긴급 알림을 보내지 않는다. 동기화 중인 상태를 신고하지 않은 것으로 단정하지 않는다. 담당 강사에게는 필요한 결석 안내가 전달되고, 부모에게는 학원이 받았다는 상태가 돌아가게 한다. 부모 화면에도 다른 학생과의 등수·우열 비교를 넣지 않는다.

## §6. 자산과 제작

새 자산의 수량, 4K 생성 모델, 그림 장수는 실제 화면에 필요한 만큼을 세어서 정한다. 방·배경·가구·NPC·편지·액자·문은 소비 위치에 맞게 구성한다. 마스코트 새 장면은 10-14 이후 원본을 생김새 참고로 넣어 장면과 함께 새로 만들며, 원본 누끼를 장면 위에 얹는 방식으로 되돌리지 않는다. 비캐릭터 공용 부품은 목적에 맞게 재사용한다. 예전의 ‘40장대·75장·128차림’ 같은 수량을 자동으로 다시 생성하라는 지시로 읽지 않는다.

### §6-b. 정본 참고와 재사용 부품을 구분한다

[DESIGN](../DESIGN.md)과 `tools/lib/마스코트자산.js`에서 승인본을 확인하고, `docs/공방/계획.json`, 공용 자산, 해당 제작 결과를 찾는다. 이름이 같은 날짜 폴더가 있어도 그것이 최신 원본이라고 가정하지 않는다. 기존 장면의 국소 표정 편집은 그 장면의 재질·몸을 보존한다. 새 장면의 포즈·표정 제작은 현행 이미지 제작 원칙을 따르며, 눈 영역 편집만으로 제한하지 않는다. 장면을 구현할 때는 [Loom 표현 기준](Loom_실시간장면_표현기준.md)의 공통 시간, 국소 변형, 그림자, 말풍선을 그대로 가져다 쓴다.

숫자·게이지·메달 자산이 있다는 이유만으로 성장·이해 화면에 넣지 않는다. [철학 적용 기준](철학_적용기준.md)이 정한 성장 표현의 범위를 따른다. 다만 가격이나 시험 점수 같은 사실을 보여 주는 것과 내부 운영 계산까지 함께 금지하는 것은 아니다.

## §7. 구현을 이어가는 순서

승인된 첫 흐름과 현재 코드를 바탕으로, 사용자가 맡긴 기능을 하나씩 완성하고 연결한다. 먼저 방→과제→제출→답장→다시 말하기 흐름의 접근성과 실제 상태를 확인한다. 그다음 해당 작업에 필요한 가게·게임·강사·부모 기능으로 넓힌다. 09-04에 구현을 늦추기로 한 것, 삭제된 시연, 과거의 판단 대기를 모든 후속 작업의 조건으로 삼지 않는다.

새 장면은 실제 크기와 배경에서 깜빡임, 입력, 쉬는 상태, 움직임 줄이기, 녹음할 때의 처리를 확인한다. 연출만 완성되고 저장·구매·신고로 이어지지 않는 상태는 제품 완료로 보지 않는다.

## §8. 현재 상태를 확인할 곳

앱의 실제 화면·데이터·배포 상태는 SYNK-talk의 현재 코드·계약과 [트랙](_ops/트랙.md)을 대조해 확인한다. 정원을 로컬에서 확인한 것은 재사용할 근거일 뿐, 모든 앱 화면과 새 장면, 학생 반응까지 검증했다는 뜻이 아니다. 이 문서의 09-13 표정 제안과 이후 제작·공개된 화면을 구분한다. 현재 실물은 WORLD와 각 장면의 담당 README에서 확인하며, 이번 문서 정리에서는 미디어를 새로 만들지 않았다.

예전의 역할별 자산 목록, 구현 수량, 심문 경위는 [정리 전 Git 버전](https://github.com/unmet23-lab/synk-appsscript/blob/f657502b1c85/docs/%EC%82%B4%EC%95%84%EC%9E%88%EB%8A%94%EC%9E%90%EB%A6%AC_%EC%84%A4%EA%B3%84_v1.md)에 있다.
