## 0. 이게 왜 필요한가

녹음은 **v9.59부터 이미 수집되고 있었습니다**(목소리 폼 → `voice_log` → 성장 카드).
빠진 것은 **음성을 글자로 바꾸는 한 단계**였고, 그게 없어서 AI가 학생의 말을 읽을 수 없었습니다.
Claude API는 오디오를 받지 않으므로 이 단계는 다른 도구가 해야 하고, 그게 GCP Speech-to-Text입니다.

전사가 되면 바로 값이 나오는 곳:
- **목소리 타임랩스 카드** — 여태 "듣기 링크 두 개"였습니다. 링크는 눌러야 비교되고, 두 파일을 번갈아 듣는 학생은 거의 없습니다. 전사문이 붙으면 *"처음엔 이렇게 말했고, 오늘은 이렇게 말한다"*가 **눈으로 한 번에** 보입니다.
- 이후 AI 첨삭·발화 퀄리티 엔진과의 연결(전사 데이터가 실제로 쌓인 뒤 착수)

## 1. 왜 서비스 계정인가 (라이브를 지키는 선택)

Speech-to-Text는 `cloud-platform` 권한 토큰을 요구합니다. Apps Script 자체 토큰으로 그걸 받으려면
`appsscript.json`에 **OAuth 스코프를 명시**해야 하는데 — **그 순간 자동 추론이 꺼집니다.**

지금 이 프로젝트는 스코프를 한 줄도 적지 않고 추론에 맡기고 있습니다(SpreadsheetApp·DriveApp·FormApp·
DocumentApp·MailApp·ScriptApp·UrlFetchApp·Session). 여기서 하나라도 빠뜨리면 **매일 도는 트리거 10개가
한 번에 죽습니다.**

서비스 계정 방식은 `UrlFetchApp`만 씁니다(이미 가진 권한). **매니페스트를 건드리지 않으므로 라이브 리스크가 0입니다.**
회귀 테스트가 `appsscript.json`에 `oauthScopes`가 생기면 실패하도록 걸어 뒀습니다.

## 2. ▶ 유호님이 하실 일

### STEP 1 — GCP에서 API 켜기

1. 브라우저에서 **console.cloud.google.com** 접속 (Apps Script와 **같은 구글 계정**)
2. 상단 프로젝트 선택기에서 프로젝트를 고르거나 **새 프로젝트** 생성 (이름 예: `SYNK-STT`)
3. 상단 검색창에 **`Cloud Speech-to-Text API`** 입력 → 결과 클릭 → **[사용] / [Enable]** 버튼
4. **결제 계정 연결이 요구되면 연결합니다.** Speech-to-Text는 유료 API입니다(무료 사용량 구간이 있고, 그 이상은 사용한 만큼 과금). 정확한 단가는 GCP 콘솔의 요금 페이지에서 확인해 주세요 — 제가 숫자를 지어내지 않겠습니다.

> 💰 **비용 방어는 코드에 이미 있습니다.** 하루 최대 **30건**까지만 전사하고(`STT_DAILY_CAP`), 초과분은 다음 날로 넘깁니다. 실패한 파일은 **자동 재시도하지 않습니다** — 미지원 포맷 하나가 매일 밤 과금되는 걸 막기 위해서입니다.

### STEP 2 — 서비스 계정 키 만들기

1. GCP 콘솔 왼쪽 메뉴 → **API 및 서비스 → 사용자 인증 정보**
2. 상단 **[+ 사용자 인증 정보 만들기] → [서비스 계정]**
3. 이름 예: `synk-stt` → **[만들고 계속하기]**
4. 역할은 비워 두거나 **`Cloud Speech 클라이언트`**를 선택 → **[완료]**
5. 만들어진 서비스 계정을 클릭 → 상단 **[키]** 탭 → **[키 추가] → [새 키 만들기] → JSON** → **[만들기]**
6. **JSON 파일이 컴퓨터에 다운로드됩니다.** 메모장으로 열어 **전체 내용을 복사**합니다.

> ⚠ 이 JSON은 비밀번호와 같습니다. 메신저·문서에 붙여넣지 마시고, 아래 STEP 3을 마친 뒤 다운로드된 파일은 삭제하셔도 됩니다.

### STEP 3 — Apps Script에 키 넣기

1. Apps Script 편집기(SYNK_앱데이터) → 왼쪽 **⚙ 프로젝트 설정**
2. 아래로 스크롤 → **스크립트 속성** → **[스크립트 속성 추가]**
3. 속성 이름: **`GCP_SA_JSON`**
4. 값: STEP 2에서 복사한 **JSON 전체**를 그대로 붙여넣기 (`{` 로 시작해 `}` 로 끝나는 전부)
5. **[스크립트 속성 저장]**

### STEP 4 — 확인

1. 편집기 상단 함수 드롭다운에서 **`voiceSttStatus`** 선택 → **▶ 실행**
2. 실행 로그를 봅니다. **`3) Speech API 응답: 400 ✅`** 이면 성공입니다.
   - 400이 정상인 이유: 진단은 **빈 오디오**를 보냅니다. 인증·API가 정상이면 "오디오가 비었다"는 400이 옵니다.
   - **403** → API가 아직 안 켜졌거나 서비스 계정 권한 부족 (STEP 1·2 재확인)
   - **401** → 키가 거부됨 (STEP 3의 JSON이 잘렸는지 확인)
   - 그 외 → 로그의 **응답 원문**을 저에게 그대로 보내 주세요. 추측하지 않고 그걸 보고 판단하겠습니다.

이후 **매일 밤 23시** 교재연동 배치가 새 녹음을 자동 전사합니다.

## 3. 알려진 제약 (지어내지 않은 것만)

| 항목 | 내용 | 코드가 하는 일 |
|---|---|---|
| **길이** | 동기 API는 짧은 오디오용입니다(대략 1분) | 초과분은 API가 거부하고, 그 사유를 `voice_log` 「전사상태」에 원문 그대로 남깁니다 |
| **크기** | 인라인 전송 한도 10MB | 보내기 **전에** 걸러 과금을 피합니다 |
| **포맷** | **m4a(AAC)는 지원 목록에 없습니다.** flac·wav·mp3·ogg·webm·amr는 지원 | MIME으로 사전 차단. 실제로 어떤 포맷이 들어오는지는 **첫 실측 전엔 알 수 없습니다** |
| **인코딩 지정** | 잘못 지정하면 인식이 오히려 깨집니다 | 지정하지 않고 헤더 자동 인식에 맡깁니다 |

> ⚠ **가장 큰 미지수는 포맷입니다.** 학생이 폰으로 녹음해 폼에 올리면 아이폰은 m4a가 나올 가능성이 높습니다. 첫 실측에서 `미지원 포맷(audio/mp4)` 같은 실패가 몰리면, 대응은 **폼 안내에 "녹음 앱에서 mp3/wav로 저장" 문구를 넣거나**, 학생이 앱 내 녹음(webm)을 쓰도록 경로를 바꾸는 것입니다. 실측 결과를 보고 정하겠습니다 — 지금 추측으로 설계하지 않습니다.

## 4. 전사가 실패했을 때

`voice_log` 시트의 **「전사상태」** 칸에 사유가 그대로 남습니다. 원인을 고친 뒤 **그 칸을 비우면** 다음 밤에 다시 시도합니다(비우지 않으면 자동 재시도하지 않습니다 — 같은 오류로 과금이 반복되는 걸 막기 위해서입니다).

원장 메일로도 밤마다 요약이 갑니다: `[SYNK] 🎧 목소리 전사 N건 · 실패 M건` + 실패 사유 최대 5건.
