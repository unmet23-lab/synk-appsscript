# 미니게임 공통 학습 기준 · TOPIK I 1~2급 준비

2026-10-02 · 사용자 확정: “지금 만들고있는 모든 미니게임 기준을 토픽 1합격 기준으로 잡자.(1~2급)”

같은 날 후속 확정: 3~4급은 싱크 타운이 중심 경로이고, 메인 화면에는 시험 형식 연습을 남긴다([마을 설계 §1-1](마을_설계.md)). 미니게임은 TOPIK I까지를 맡는다.

같은 날 사용자 결정: **미니게임은 무료로 제공한다**(“미니게임도 무료로 하자”, 모든 나라 같음). 그래서 미니게임은 플레이 중 AI·서버 음성 인식을 부르지 않게 만든다. 근거와 비용 회수는 [BM 목록 §1](BM_목록.md#1-돈의-선)에 있다.

현재 제작 중인 한국어 레이싱·바람길·말의 리듬·주문 폭주·선생님이 돌아왔다·입장 검사·빈칸 베기·말 랠리와 앞으로 추가할 한국어 학습 미니게임의 공통 목표는 **TOPIK I 1~2급 합격에 필요한 듣기·읽기 능력 연습**이다. 각 게임은 장르의 재미를 유지하면서 서로 다른 이해 능력을 맡는다. 아래 게임별 강점은 현재 로컬 소스에 대한 분석이며 학생 대상 효과 검증 결과는 아니다.

## 1. 합격 목표와 게임 기록

TOPIK I은 듣기·읽기 두 영역을 평가한다. [국립국제교육원 공식 안내](https://www.niied.go.kr/web/niied/contents/niied_topik), 2026-10-02 확인.

| 시험 방식 | 총점 | 1급 | 2급 |
|---|---:|---:|---:|
| 종이 시험 PBT | 200점 | 80~139점 | 140~200점 |
| 컴퓨터 시험 IBT | 400점 | 121~235점 | 236~400점 |

이는 두 영역을 합산한 공식 시험 기준이다. 게임의 4/5 통과·O/X 정답률·서빙 성공·부탁 수행·메달·순위를 이 점수나 공식 급수로 환산하지 않는다. 합격 준비도를 확인하려면 별도의 듣기·읽기 평가에서 처음 보는 문항과 실제 시험에 맞는 구성·배점·시간을 사용해야 한다. 평가 도구가 구현·검수되기 전에는 합격 판정을 표시하지 않는다.

## 3. 1급 준비에서 2급 준비로 발전시키는 방향

다음은 제작용 단계 방향이다. 현재 게임 단계나 국립국어원 어휘 A/B를 공식 1급/2급 대응으로 간주하지 않는다. 개별 어휘·문형·문항의 목표 급수는 교원 검수 후 확정한다.

| 제작 방향 | 듣기 | 읽기 |
|---|---|---|
| 1급 준비의 기초 | 친숙한 생활 어휘, 짧은 질문/응답, 대상·수량·시간·장소, 단순 부탁 이해 | 기초 어휘와 조사·문형, 짧은 문장, 간단한 생활 안내의 정보 찾기 |
| 2급 준비로 확장 | 여러 문장이나 짧은 대화에서 핵심/세부 정보, 변경·부정·이유·순서·조건 이해 | 안내문·메모·짧은 문단의 내용 일치, 주제·이유·문맥·문장 순서 이해 |

초급 생활 화제와 실제 시험에서 요구하는 이해를 중심에 두고, 상위 급수의 어려운 어휘로 게임 난도를 대신하지 않는다. 리듬 노트 밀도·러너 속도·카페 주문 대기 수 등의 **조작 난도**와 어휘·문형·지문 길이·정보 수 등의 **언어 난도**를 따로 조절한다.

## 4. 모든 학습 미니게임의 제작 기준

1. **연습 영역과 능력을 명시한다.** 듣기/읽기 중 무엇을 입력으로 주고, 어떤 의미를 이해해야 성공하는지 정한다. 어휘 소리·표기 연결과 문장/대화 내용 이해도 구분한다.
2. **한국어 이해가 게임 행동에 연결되어야 한다.** 색·정답 위치·장애물만 보고 성공할 수 있는 부분은 학습 보조 장면으로 다루고 이해 평가로 집계하지 않는다.
3. **배우는 도움과 혼자 이해한 결과를 구분한다.** 듣기 자막·글로 보기·다시 듣기·해설은 학습에 제공하되, 도움 사용 여부와 최초 응답을 결과 해석에 함께 남긴다. 현재 없는 기록 기능은 후속 구현으로 관리한다.
4. **게임 성과와 한국어 이해를 나눈다.** 순위·콤보·타이밍·생존·서빙 점수와 의미 정오·미응답을 구분한다. 바람길의 타이밍 놓침처럼 이해와 조작이 섞이는 경우 단정적인 듣기 점수를 만들지 않는다.
5. **복습 뒤 새 표현으로 다시 확인한다.** 같은 답의 암기와 새 문장 이해를 나누고, 수량·시간·장소·대상·조건을 바꾼 문항을 준비한다. 즉시 확인과 다음 날 확인도 구분한다.
6. **게임 묶음 전체에서 듣기·읽기를 모두 다룬다.** 각 게임의 강점은 유지하고, 합격 준비 범위의 빠진 능력은 다른 과정이나 새 게임으로 보완한다.
7. **홍보는 구현된 연습을 설명한다.** “TOPIK I 듣기의 세부 정보 이해를 연습”처럼 영역·능력을 적는다. 공식 급수 대응·전 범위 충족·점수 향상·합격 보장은 실제 검수와 학생 평가 없이 표시하지 않는다.

## 5. Atlas 연결 판정 · 2026-10-02 코드 확인

사용자 요구: 학생이 무엇을 어려워하는지 확인하고 그 학생에게 필요한 게임·문항·도움을 추천한다. 듣기를 잘하는 학생에게 듣기만 반복시키지 않는다. 사람별 추천 결과를 미리 고정하지 않고 실제 학습 기록으로 다음 경험을 바꾼다.

**판정: 8개 엔진의 역할 분담은 이 목표에 맞지만, 현재 앱과 네 미니게임은 이 개인화 순환을 완성하지 못했다.** 엔진 전체를 새로 만들기보다 기존 Core·Trail·Temper를 보존하면서 TOPIK I 학습 지도, 관측에서 필요를 계산하는 부분, 계정 기록, 실제 게임 소비처를 연결해야 한다. 엔진 시험 통과나 파일 동기화는 학생에게 맞는 추천의 작동 증거가 아니다.

| 확인한 부분 | 현재 구현 | 개인화에 빠진 부분 |
|---|---|---|
| 공통 Core | `atlas/education.js`의 `diagnose`·`createPractice`: 문항 태그, 정오, 도움, 첫 시도 기록 | 진단은 `this-item-only`, `mastery: null`. 시도 기록을 듣기/읽기·세부 능력별 현재 필요로 바꾸는 공통 계산이 없다 |
| 공통 Atlas | `atlas/engine.js`는 외부에서 공급한 `need`·`due`로 선택을 바꿀 수 있다 | 네 게임의 수행에서 그 근거를 만들어 공급하지 않는다. `atlas/experiences.js`의 현재 후보는 편지 연습 중심이다 |
| Strata | 기술 30·문법 91·오류 태그 23을 조회한다 | 듣기/읽기별 의미 이해 능력, 게임 문항 대응, TOPIK I 범위·누락을 나타내는 지도가 없다. 기존 문법 마디만으로 듣기 능력을 대신할 수 없다 |
| Trail·Temper | 도움받은 답·반복 문항·새 문항의 독립 시도를 구분하고 학습 항목별 집계가 가능하다 | 계정 전체의 최근 학습 상태와 게임 사이 추천은 없다. `Trail.remember`의 최초 노출 4칸은 최근 수행 이력이 아니므로 그것만으로 학습 프로필을 만들 수 없다 |
| 앱 SYNK-talk | G1 편지/G4 서류의 도움 방식 저장·복원, 공통 엔진 사본과 연습 세션 시험이 있다 | 새 게임 UI의 교육 어댑터 소비가 없다. `lib/atlas-session.js`는 경험별 메모리 세션이고 계정 저장은 도움 방식에 한정된다. `lib/게임배정.js`의 요일·급수·해시 배정에는 새 게임의 부족한 능력 근거가 들어가지 않는다 |
| 한국어 레이싱 | `learning.js`의 브라우저 내 문항별 정오·복습, `campaign.js`의 다음 미통과 코스 | 계정·공통 능력 상태가 없다. 듣기에서 자막/글 보기/음성 실패가 정오와 함께 보존되지 않는다. 모든 코스 통과 뒤 추천은 마지막 코스로 고정된다 |
| 바람길 | `core.mjs`의 수행/타이밍 상태·회차 내 재출제 | 최고 거리·그래픽 설정만 기기에 저장한다. 시각 단서·조작 실수를 제외한 언어 관측과 회차를 넘는 학습 기록이 없다 |
| 말의 리듬 | `core.mjs`의 리듬과 O/X 의미 정오 분리·복습 | 기록이 회차 메모리에 머문다. 곡마다 문항 ID가 `q0`부터 반복되어 공통 기록에는 곡·내용 판을 포함한 고유 키가 필요하다 |
| 주문 폭주 | `core.mjs`의 첫 정오·시도 수·글 도움 여부 | 기록이 회차 메모리에 머문다. 첫 정답 수에는 도움받은 답도 포함되며, 음성 전달 실패와 순수 듣기 이해를 가를 기록이 필요하다 |

읽기 범위: 공통 `atlas/`·`strata/`, 위 네 게임의 소스, SYNK-talk의 Atlas 세션·게임 훅·배정·제출 경로. 공개판 전체·실제 학생 계정·서버 운영·모바일 플레이는 이번 검사 범위가 아니다. 이전 남산/도깨비 체험의 존재를 현재 TOPIK I 네 게임의 연결 근거로 사용하지 않는다.

재확인: 공통 엔진 관련 104시험 통과, talk 관련 56시험 통과, talk 사본 9개 바이트 일치, Strata 재생성 일치(121마디). 순수 모듈 재현에서 레이싱 전 코스 통과 후 듣기 문항에 오답을 넣어도 추천은 `challenge-12`; 주문의 글 도움 후 정답은 `firstCorrect`에 포함; 리듬 서로 다른 곡의 문항 ID가 반복됨을 확인했다. 이 검사는 기존 기능의 경계와 단절을 확인한 것이며 아래 설계의 구현·학습 효과를 검증한 것은 아니다.

## 6. 여덟 엔진이 맡을 연결

| 엔진 | 이 학습 순환에서의 책임 | 학생에게 달라지는 결과 |
|---|---|---|
| Strata | 검수된 문항을 영역·세부 능력·언어 난도·선행 내용·실제 제공 게임과 연결 | 필요한 능력을 연습할 수 있는 콘텐츠만 후보로 나온다. 없는 읽기 콘텐츠는 부족한 것으로 드러난다 |
| Core | 자격을 갖춘 관측에서 현재 연습 필요·확인 필요·복습 필요를 계산하고 다음 구성을 결정 | 듣기가 충분하고 읽기가 어려우면 읽기를 우선한다. 관측하지 않은 읽기는 약점으로 단정하지 않는다 |
| Trail | 제공·첫 응답·도움·재시도·노출·정정 이력의 계약과 해석을 맡고, 앱/서버 호스트가 인증·영속 저장·기기 동기화를 실행 | 게임을 바꾸거나 다시 들어와도 같은 학생의 기록이 이어진다 |
| Temper | 추천 전후의 새 문항·나중 재확인 결과를 당시 조건과 함께 비교 | 같은 답을 외운 결과 대신 새 표현에서도 이해했는지 확인한다 |
| Vellum | 결정 근거를 쉬운 말로 설명하고 학생의 선택·정정을 받는다 | “시간이 바뀐 안내를 다시 살펴볼까요?”처럼 이유와 다음 행동이 연결된다 |
| Loom | 추천·복습·도움과 조작 부담을 화면과 상호작용에 표현 | 학생이 추천을 실행하거나 다른 게임을 고르고 도움 양을 조절할 수 있다 |
| Reed | 듣기 자료의 제공·완료·실패·재청취 상태를 게임과 기록에 전달 | 소리를 못 들은 문제 때문에 듣기 약점이 생기지 않는다 |
| Prism | 충분한 실제 자료가 생긴 뒤 문항별 난도·선택지·대상 범위의 분포를 분석 | 특정 문항이나 게임이 부당하게 어렵게 측정되는지 고칠 수 있다. 현재 없는 집단 평균을 만들지 않는다 |

여덟 개를 매 응답마다 모두 호출할 필요는 없다. 첫 관통 연결은 **Strata → Core → 게임 → Trail → Core**, 결과 재확인은 Temper가 맡는다. Vellum·Loom·Reed는 그 흐름의 실제 전달을 담당하고 Prism의 집단 보정은 자료가 생긴 뒤 확대한다. 자세한 엔진 책임은 [아틀라스 설계](아틀라스_설계.md)와 [현재 공통 교육 API](아틀라스_교육업그레이드_20260930.md)를 따른다.

## 7. 지금 준비할 것과 학생마다 정할 것

**구현 설계안. 다음 항목이 코드에 반영됐다는 뜻은 아니다.** 사용자 요구인 학생별 순환을 만들기 위한 계약이며, 아래 세부 분류·정책값은 구현·문항 검수에서 확인한다.

| 미리 준비하는 공통 재료 | 플레이 시 학생 기록으로 정하는 것 |
|---|---|
| 정답·해설·음성·언어 난도를 검수한 문항과 새 표현의 변형 문항 | 이번에 연습할 능력과 문항, 게임, 분량 |
| 문항의 듣기/읽기와 세부 능력 태그, 문항 고유 키·판·변형 계열 | 짧은 확인이 필요한지, 보충이 필요한지, 복습 시점인지 |
| 도움·재시도·음성 실패·조작 실패를 기록하는 규칙 | 힌트·자막·재청취·조작 난도의 제공 방식 |
| 평가용과 연습용의 구분, 기록·정정·기본 경험 통로 | 본인 목표·시간·소리 사용 가능 여부를 반영한 다음 구성 |

학생이 올 때까지 이 기반을 미룰 필요는 없다. 반대로 학생의 듣기/읽기 비율과 코스 순서를 사람을 보기 전에 고정하지 않는다. 개인화 때문에 매번 AI로 새 정답과 보기를 생성할 필요도 없다. 첫 연결은 검수된 풀의 선택·조합으로 재현 가능하게 만들고, 적합한 재료가 없으면 다른 능력을 연습시킨 뒤 원래 능력을 채웠다고 표시하지 않는다.

### 7-1. 배울 내용의 공통 분류

듣기·읽기를 첫 축으로 나누고, 아래 세부 능력을 실제 문항에 연결한다. 이는 제작용 분류 초안이며 공식 TOPIK의 급수별 세부 평가표를 그대로 복제한 것이 아니다.

- 듣기: 낱말 소리·의미, 질문/응답, 시간·장소·수량 등 세부 정보, 부정·변경, 이유·조건, 행동 순서, 짧은 대화의 핵심.
- 읽기: 어휘 의미, 조사·문형, 문장 의미, 안내문·메모의 정보 찾기, 내용 일치, 이유·조건, 짧은 글의 주제·문맥·순서.
- 별도 축: 언어 난도(문형·어휘·길이·정보 수), 조작 난도(속도·입력·타이밍), 응답 형식(2지/3지/조합/행동), 소재·상황.

한 문항에 관련된 태그를 전부 붙여 그 전부를 틀린 능력으로 세지 않는다. 대표 측정 능력과 배경 지식을 나누고, 틀린 이유가 여러 가지일 수 있으면 해당 문항의 관측으로만 둔 뒤 구분 가능한 짧은 확인을 제공한다. O/X와 3지 선택, 카페 조합의 정답률을 같은 척도로 합쳐 영역 실력으로 표시하지 않는다.

### 7-2. 기록과 관측의 자격

기존 Atlas의 한 기록 통로를 확장하며 게임마다 별도 학습 프로필을 만들지 않는다. 현재 `practice.*` 허용 필드에 아래 내용 전부가 있는 것은 아니므로 **Trail·엔진 검증기·앱 세션·서버 수집 계약을 함께 개정**해야 한다.

| 기록할 사실 | 해석 규칙 |
|---|---|
| 인증된 계정 범위, 게임·회차·추천 결정, 문항/내용 판·변형 계열, 실제 표시된 영역·능력 | 인증은 호스트에서 해결하고 원문 응답·학생 식별값을 공통 저장 이벤트·프로필·공개 기록에 남기지 않는다. `submit(response)`가 채점 함수에 응답을 전달하는 현 계약은 유지한다. 듣기 연습이라는 출제 의도만으로 듣기 관측을 만들지 않는다 |
| 최초 노출 여부·최초 응답·의미 정오·미응답·재시도 | 같은 문제의 반복 정답과 처음 보는 문제의 수행을 구분한다. 읽을 수 없거나 다른 기기의 기록이 빠졌으면 노출 여부는 모름이다 |
| 자막/글 보기·힌트/정답 공개·추가 재청취의 시점 | 문항이 정한 기본 음성 제공 횟수와 학생이 요청한 추가 재청취를 구분한다. 도움 이후 정답은 보조된 연습으로 남긴다. 실패한 첫 응답을 정답 재시도로 덮지 않는다. 최초 응답 뒤의 도움은 앞선 응답을 소급 변경하지 않는다 |
| 음성 시작/완료/실패·중단·음소거, 실제 읽기 전환 | 음성이 전달되지 않았으면 듣기 실패로 세지 않는다. 글로 전환한 결과는 듣기 독립 성공으로 세지 않는다 |
| 입력 여부·타이밍·충돌·시각적 정답 단서·자동 시연 | 게임 점수와 분리한다. 언어 이해인지 조작인지 분리할 수 없으면 평가 불가로 남기고 다른 방식으로 확인한다 |
| 관측 시점·정책/지도 판·제외/정정·저장 완전성 | 최신 근거가 오래된 판단을 갱신하고 정정은 다음 추천에 반영되어야 한다. 같은 기록 재전송은 한 번만 센다 |

리듬에는 곡·문항 내용 판, 주문에는 주문 내용·변형, 바람길에는 지시 내용·변형, 레이싱에는 입력 모드·문항 내용 판을 포함한 안정적인 키가 필요하다. 보기 순서만 바꾼 문항을 새 문항으로 세지 않는다. 처음부터 공개 체험의 기기 기록을 특정 학생의 기록으로 자동 귀속하지 않는다.

계정 연결에서는 앱 재시작·로그아웃·학생 전환·다른 기기·오프라인 재전송·저장 실패를 검증한다. 현재 도움 방식 저장 API에 임의의 수행 payload를 끼워 넣지 않는다. 서버의 소유권·중복 처리·채점 검증과 실제 기기 왕복까지 통과해야 ‘앱 적용 완료’다. 다른 학생의 계정 정보나 답안을 테스트 자료로 출력하지 않는다.

### 7-3. 진단과 추천의 기준

학생별 상태는 영역 전체를 한 숫자로 묶기 전에 **능력 × 언어 난도 × 관측 조건**으로 본다. 상태와 함께 근거 문항·새 문항 수·응답 형식·도움 여부·최근 시점·기록 완전성을 보존한다. 표본 기준·유효기간·재확인 간격은 판이 있는 정책 설정으로 두고 합성 검증 후 실제 자료에서 조정한다. 아직 검증하지 않은 정답률 기준을 급수나 숙달 기준으로 확정하지 않는다.

**학습자에게 보이는 위치(2026-10-19 사용자 확정).** WORLD는 먼저 「TOPIK I 15개 항목: 혼자 해냄 n · 연습 중 n · 아직 n」 항목 지도를 보여 주고, 처음 보는 문항 15개 안팎의 짧은 진단으로 시작점을 정한다. 예상 급수는 TOPIK 형식(처음 보는 문항 · 실제 구성 · 시간 제한) 연습 근거가 쌓인 뒤에만, 「1급 근처 · 근거 30문항 · 갱신일」처럼 범위·근거 수·날짜를 붙여 보인다. 근거가 모자라면 「아직 판단하기 일러요」로 둔다. 위 §1의 원칙(게임 점수를 급수로 환산하지 않고 합격 판정을 하지 않음)은 그대로다. 근거: [결정 표](_ops/결정.md) 10-19 「WORLD 내 위치」.

| 상태 | 근거와 다음 행동 |
|---|---|
| 아직 확인하지 않음 | 기록 없음/표본 부족/낡은 근거. 쉬운 대표 새 문항으로 짧게 확인한다. 약점이라고 표시하지 않는다 |
| 보충 후보 | 최근 서로 다른 문항에서 반복된 유효 오답 또는 본인의 연습 요청. 좁은 능력을 다시 연습하고 새 표현으로 확인한다. 학생의 영구 특성으로 만들지 않는다 |
| 도움을 받으면 수행 | 자막·힌트·기본 제공을 넘는 추가 재청취 뒤 성공. 도움은 유지하되 이후 다른 문항에서 도움을 줄여 확인한다 |
| 최근 혼자 수행 | 적절한 난도의 서로 다른 새 문항에서 독립 수행이 충분함. 해당 연습 비중은 줄이고 다른 필요로 이동하되 간격을 둔 재확인을 남긴다 |
| 다시 확인할 때 | 이전 수행 뒤 시간이 지났거나 최근 결과가 상충함. 새 문항의 확인으로 상태를 갱신한다 |
| 평가할 수 없음 | 음성/입력/기록 실패, 시각 단서, 자동 시연 등. 약점 분모에 넣지 않고 전달·조작을 먼저 해결한다 |

추천 순서: ① 학생의 목표·시간·접근 조건·선택을 반영 → ② 확인된 필요, 미관측 범위, 복습 시기를 함께 대조 → ③ 실제 이용 가능한 문항과 게임에서 선택 → ④ 이유와 다른 선택을 제공 → ⑤ 결과를 기록 → ⑥ 새 표현/후속 회차로 다시 확인. 같은 약점에 계속 묶이지 않도록 확인 기회와 다른 범위의 탐색을 둔다. 듣기를 잘한다는 이유로 듣기를 영구히 없애지도 않는다.

가상 예: 듣기 세부 정보는 최근 새 문항에서 안정적으로 수행했지만 읽기 안내문의 변경 조건에서 반복 오류가 확인됐다면, 해당 읽기 문항이 있는 레이싱 코스와 짧은 보충을 먼저 제공한다. 읽기 기록이 없다면 같은 결론을 내리지 않고 읽기 확인부터 한다. 그날 소리를 사용할 수 없어서 읽기로 간 것은 환경에 따른 선택이며 듣기 약점이라는 뜻이 아니다. 카페 수량을 잘 처리한 기록만으로 전체 듣기를 잘한다고 확대하지 않는다.

게임 추천과 게임 안의 조정은 둘 다 필요하다. 게임 선택만 바꾸고 문항은 고정 순서라면 필요한 능력을 실제로 연습한다는 보장이 없다. 반대로 모든 게임에 읽기를 억지로 넣지 않는다. 듣기 중심 게임을 고른 학생에게는 장르를 유지한 연습을 제공하고, 앱의 다음 추천에서 부족한 읽기 과정으로 이어 준다.

### 7-4. 첫 구현과 완료 조건

1. **지도와 근거를 먼저 연결한다.** 현재 문항을 위 분류에 매핑하고 적합성·정답·변형 계열을 확인한다. 미지원/미검수 능력을 추천 후보에서 드러낸다. 레이싱의 듣기와 읽기, 리듬의 듣기를 첫 두 소비처로 삼아 같은 능력과 다른 영역의 재사용을 확인하는 순서를 제안한다.
2. **공통 판단과 기록을 만든다.** Strata 매핑·Trail 관측 계약·Core 필요 계산/선택을 담당 원본에 구현한다. 도움 방식과 문항 최초 노출 기록만으로 상태를 추정하지 않는다. 두 게임이 같은 함수를 사용하고 각 게임은 관측 가능한 사실과 실행 가능한 행동만 제공한다.
3. **학생 경험까지 잇는다.** 실제 진입·출제·제출·도움·결과·다음 추천에 어댑터를 연결한다. “추천” 문구나 엔진 import만 추가한 상태를 완료로 세지 않는다. 이후 바람길·주문 폭주도 조작/음성 오염을 구분해 같은 계약으로 연결한다.
4. **계정 왕복을 확인한다.** 서버에서 학습자 범위의 공통 요약을 복원하고 다른 게임/다른 기기에서도 다음 추천이 달라지는지 확인한다. 기기 한정 시제품과 계정 적용 완료를 구분한다.
5. **학습을 따로 검증한다.** 교원 검수([교원 검수 시트](교원검수/README.md) 한 장으로, 2026-10-05)와 처음 보는 듣기·읽기 평가, 일정 간격 뒤 재확인을 진행한다. 그 전에는 추천 기능 구현과 학생 학습 효과·TOPIK 합격 준비도 검증을 구분한다.

| 반드시 통과할 시나리오 | 관찰할 결과 |
|---|---|
| 듣기 강점/읽기 보충 학생과 읽기 강점/듣기 보충 학생 | 동일한 콘텐츠 풀에서 다음 추천과 실제 출제 영역이 다르고 이유가 기록과 맞는다 |
| 신규 학생 또는 읽기 기록이 없는 학생 | 약점 낙인 없이 짧은 확인을 제공한다 |
| 자막/힌트/정답을 본 뒤 정답, 같은 문항 반복 정답 | 독립 성공으로 상태를 올리지 않는다 |
| 음성 실패·시간 초과·충돌·자동 시연 | 한국어 오답으로 일괄 집계하지 않는다 |

| 다른 학생 로그인·앱 재시작·다른 기기·중복 재전송 | 학습자 격리와 복원, 중복 제외, 불완전 기록의 모름 처리가 유지된다 |
| 추천 거절·기록 정정·소리 사용 불가 | 다음 결정이 바뀌고 기본 플레이와 학생 선택이 유지된다 |
| 해당 능력의 검수된 문항이 없음 | 다른 능력으로 채운 척하지 않고 범위 부족과 대안을 알린다 |

## 8. 첫 감사의 반영 범위

2026-10-02 첫 검토는 **소스 감사·기존 시험 재확인·공통 제작/연결/인수 기준 보완**이었다. 그 시점에는 게임 런타임·계정 API·DB·화면·공개판을 변경하지 않았다. 같은 날 실제 적용 요청에 따른 후속 구현은 아래 §9다.

## 9. 실제 개인화 연결 — 2026-10-02 후속 구현

판정: 구조의 역할 구분은 사용할 수 있지만 기존 코드만으로는 개인화 경험이 만들어지지 않았다. **관측 → 좁은 학습 항목별 필요 → 이용 가능한 후보 → 실제 출제 → 다음 결과**를 공통 코드에 구현하고 소비처를 연결했다. 엔진 수를 채우는 일을 완료 조건으로 삼지 않는다.

### 9-3. 현재 정책과 실패 처리

- 정책 `learning-priority-3`는 최근 30일의 서로 다른 문항 계열 최대 12개를 읽고, 7일이 지난 근거를 재확인 후보로 둔다. 같은 관측 조건의 서로 다른 첫 응답 4개 이상에서 80% 이상이면 해당 범위의 최근 독립 수행으로 본다. 이는 **운영 추천용 초기값**이며 검증된 숙달·TOPIK 급수·합격 확률이 아니다. v3는 추천의 반복 회피에도 familyKey를 적용하며, 측정 제외 사유가 붙은 도움 정답을 성공으로 집계하지 않는다. 과거 결정에 저장된 정책판은 바꾸지 않는다.
- **능력 × 언어 난도 × 응답 형식**으로 판단한다. 리듬의 O/X, 레이싱/앱의 3지 선택, 주문 조합, 행동을 섞어 정답률을 만들지 않는다. 후보와 같은 형식의 근거로만 추천·다음 난도 준비를 계산하며 형식 미지정 과거 기록은 별도다. 언어 난도 1~3은 TOPIK 1~3급이 아니다. 읽기 기록이 없으면 약점이 아니라 확인할 범위다. 새 문항 수행이 충분히 나아지면 보충 우선순위가 내려가며 다른 영역으로 이동한다.
- 자막·힌트·정답·추가 재청취 뒤 성공, 같은 문항과 보기 순서 변형, 실제 음성 전달 실패, 조작/시각 단서, 자동 시연을 독립 수행에 합치지 않는다. 첫 오답과 재시도는 모두 남기고 이중 제출은 한 번만 센다. 뒤에 발생한 도움·음성 완료가 앞선 시도를 소급 변경하지 않는다.
- 손상된 기록을 빈 기록으로 덮지 않는다. 저장 불가·불완전 기록은 개인화 근거를 확정하지 않고 화면에서 알린다. 공유 기록 초기화는 이미 열린 문항 핸들도 무효화한다. 임의 응답 원문·학생 식별자는 공통 이벤트에 넣지 않는다.
- 문항 수와 검수 범위는 아직 작다. 문항 풀이 소진되면 반복 연습은 가능하지만 새 독립 근거가 늘었다고 세지 않는다. 운영 정책·문항 난도·응답 형식별 보정은 실제 자료와 교원 검수로 보완해야 한다.

### 9-4. 실행·검증과 남은 연결

로컬 실행: `node experiences/learning-hub/server.mjs` → `http://127.0.0.1:4280/`. 재빌드: `node tools/build-game-learning.js`; 정본 일치 검사: 같은 명령에 `--check`. 앱 갱신: `node tools/sync-atlas.js --consumer talk`.

자동 시험은 반대 수행 기록의 서로 다른 실제 추천, 도움·음성 실패·재시도·반복 제외, 다른 게임 재로드·공유 기록 복원, 계정 격리, 더 나은 후속 수행에 따른 추천 이동을 포함한다. 실제 브라우저의 소비처 검증과 정확한 시험 결과는 [실행 입구와 결과](../experiences/learning-hub/README.md), 각 게임 `qa/` 및 talk `docs/맞춤학습_로컬연결.md`에 둔다. 합성/자동 시험은 학생 효과 증명이 아니다.

같은 날 후속 요청으로 ①의 계정 서버 수집·소유권·사건 관계·중복 검증과 오프라인 재전송을 로컬 코드/마이그레이션으로 구현하고 합성 PostgreSQL 왕복을 확인했다. [공통 계정 구현과 한계](SYNK_공통계정_구현검증_20261002.md). 언어 정오의 서버 독립 채점과 시험 자격 판정은 포함하지 않는다. 운영 완료까지는 인증/DB 설정·배포, ② 인증한 두 실기기의 앱↔게임 복원, ③ Town 실제 장면·숙제·코칭의 관측 소비, ④ 문항/난도 검수·새 문항·지연 평가가 남는다. `atlas-memory` 도움 선호 API에 수행 데이터를 임의 삽입하지 않는다.

### 9-5. 엔진 검토 반영 — 2026-10-02

같은 날 검토에서 기록이 쌓일수록 문항 처리가 느려지던 문제를 고쳤다(400문항에서 문항당 85ms → 0.4ms). 레이싱 시연의 정답 노출과 재개 시 다시 듣기도 기록하게 했다. 공유를 끈 로그인 기기의 근거 누락, 게임 전환 때 계정 동기화가 멈추던 문제, 다른 기기 시계에 끌려가던 문제도 고쳤다. 학습 입구 목록은 실제 문항에 있는 능력·난도·형식만 쓰도록 시험으로 묶었다(`experiences/learning-hub/catalog.test.mjs`). TOPIK I 지도에는 문형 45개·낱말 2,000개 층을 붙였다. 문항이 `conceptIds`로 낱말·문형을 남기면 `summary().concepts`가 최근 놓친 내용을 알려 주고, 같은 능력 안의 추천이 그 내용을 조금 앞세운다. 상세·수치·남은 일은 [Atlas 엔진 검토](아틀라스_검토_20261002.md)를 따른다.

기기 저장 한도도 같은 날 고쳤다. 전에는 약 2,000문항에서 브라우저 저장이 차서 기록이 끊겼다. 이제 오래되고 끝난 문항은 판단에 필요한 것만 남긴 요약으로 줄여 저장한다. 1만 문항을 해도 저장이 약 0.9M자에 머물고(사파리 엔진의 한도는 약 5.2M자), 답 판정·학습 상태·추천은 원문을 다 둔 기록과 같다. 사파리 엔진(웹킷)에서 예전 방식은 2,227문항째에 저장이 실패했고, 바뀐 방식은 2,600문항에도 0.7M자였다. 서버와 동기화하는 계정은 서버가 받아서 돌려준 기록만 줄이므로 서버에는 전부 남는다. 상세는 [검토 §7](아틀라스_검토_20261002.md#7-기기-저장-한도-개편).

### 9-8. WORLD 홈의 활동 선택까지 확장 · 2026-10-13

Core의 기존 `atlas/learning.js`에 순수 `recommendActivities`와 활동 정책을 추가하고 `game-learning.js`의 기존 공개 어댑터로 노출했다. 실제 후보의 목표·소요시간 추정·소리·도움 조건, 문항 대상 목록, 제품의 예정 복습과 출처가 있는 최근 오답/도움 필요를 받는다. 실행 불가 후보를 먼저 제외하고 관측된 필요/예정 복습을 관심 일치보다 먼저 비교하며, 같은 우선순위 안에서는 명시 목표를 따른다. 본인이 목표를 지우면 목표 영향도 없어진다. 문항 내부의 기존 추천과 반복 회피 규칙은 재사용한다.

Vellum `activityReason`은 선택 이유를 학생에게 설명한다. 독립 성공 근거와 추천 사유의 도움/재확인 근거를 분리해, 도움 정답을 독립 숙련으로 읽지 않는다. 불완전한 Trail 기록은 능력 판단에 쓰지 않는다. 생활 복습의 날짜와 도움 사실은 `hostEvidence`로 구분하고 임의의 TOPIK skill 사건을 만들지 않는다. 이 변경은 Core·Vellum의 기능 확장이며 별도 엔진/LLM 하네스가 아니다.

WORLD의 `world-learning-plan.mjs`는 실제 생활 6팩·바람길·리듬·한글의 경로와 콘텐츠 메타데이터를 공급하고 중단 위치를 보존한다. `world-learning-profile.mjs`는 기존 Core Personalization의 동의·정정·삭제·판 충돌을 생활 계정 기록에 연결한다. 공통 계산과 제품별 수업·게임 화면을 분리하고, 실제 홈 추천→활동 시작→첫 응답/도움→예정 복습→다음 추천을 확인한다. 원문·벤치마킹·현재 검증은 [WORLD README](../experiences/synk-world-app/README.md)와 [생활 콘텐츠](../experiences/synk-world-app/LIFE-CONTENT.md)의 해당 날짜를 따른다.

TOPIK 관련 범위는 바람길의 짧은 지시 듣기, 리듬의 듣고 내용 확인, 생활 팩의 짧은 상황·응답 읽기 및 새 상황 복습이다. 한글 소리·글자는 입문 연습이다. 활동 소요시간과 추천 우선순위는 운영 초기 정책이며 실제 학생 효과·공식 급수·시험 전 영역 대비를 증명하지 않는다. 이번 범위는 로컬 소스·생성물·합성 계정/브라우저 검증이고 운영 배포·실기기 인수는 별도다.
