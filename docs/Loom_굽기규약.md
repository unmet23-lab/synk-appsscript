# Loom — 제작·재생성 규약

2026-09-13 · 다음 제작의 원천과 통로만 남긴다. 완료된 회차·비용·소요 시간·오류 서사는 [정리 전 원문](https://github.com/unmet23-lab/synk-appsscript/blob/8b80a507168d/docs/Loom_굽기규약.md)에 있다.

## 원본과 표현

- 승인 원본·색·재질·로고는 [DESIGN](../DESIGN.md), 의상 생성의 사용자 지정 모델은 [의상 제작 정본](캐릭터/의상제작_정본.md)을 따른다.
- 표정만 바꿀 때 공통 몸·옷·털·알파를 유지하고 변화 영역만 처리한다. [표정 기준](캐릭터/캐릭터_생명감_설계.md#1-a-표정-전환의-재질-고정)과 실제 크기 반복 재생으로 확인한다.
- 기존 결과를 먼저 확인하고 필요한 원인만 고친다. 재생성이 승인 원본보다 나을 것이라고 가정하지 않는다.
- 배경 제거는 몸·의상·잔털을 보존한다. [AI누끼.py](../tools/AI누끼.py) 등 현재 도구를 쓰되 밝은 몸 소실·이중 알파·잘림을 확인한다.
- 색 변환·조명·렌더는 대상의 승인 레시피와 비교한다. 옛 AgX·PBR Neutral 실험의 판정을 모든 새 재질의 영구 금지로 확대하지 않는다.

## 자산 제작과 변환

기존 3D 부품은 `룸굽기.js`·`룸장면.py`, 공방은 `요소굽기.py` 등 담당 제작기를 쓴다. 필요하면 `재굽기값.js`로 해당 원천 변경을 확인한다. 지원 플래그·출력 대상은 실행 코드에서 읽는다.

배치 변환은 `python tools/룸자산화.py`, 해당 키만 바꿀 때는 `--이름 <키>`를 쓴다. 몸·그림자의 공통 좌표·크롭, 실제 크기의 선명도·무게를 확인한다. 원본과 배치용 크기를 구분하고 옛 해상도·샘플 수를 전 자산의 고정값으로 쓰지 않는다.

번호·불릿의 자산·숫자 처리 범위는 `룸자산화.py`·`loom.js`가 정한다. 자수 숫자와 CSS 숫자를 중복하지 않는다. 유채 신호·칩·반복 부품의 역할은 DESIGN을 따른다.

## 생성기와 관리 산출물

공통 소스 변경 때 실제 소비 생성기·관리 출력을 갱신한다. 아래는 통로의 위치이며 매 작업마다 모두 실행하는 고정 순서가 아니다.

| 원천·산출물 | 재생성 통로 |
|---|---|
| HTML 원고·엔진 소개서 | `펠트문서.js --굽기 <원고> <출력>`, 해당 전량 작업은 `--전량` |
| 마크다운 문서 | `룸조판.js <원고> --지면 문서 --내놔 <출력>` |
| 기존 손 지면 | `지면얹기.js --적용` — Loom 구간만 갱신·고유 CSS 보존 |
| Loom 시연 | `tools/lib/loom.js --시연` |
| 부품·요소·화면·히어로 시안 | 해당 `*시안.js` |
| NPC·까몽 시트, 앱 감사·이해·작동 대장 | 해당 시트·대장 생성기 |
| 크루카드 | `크루카드굽기.js` 후 `크루카드사본.js`, 정본 → 사본 일치 |
| 발표·인쇄 PDF | `발표물빌드.js --pdf`와 관련 인쇄 검사 |
| 영상 공방 요소 | `영상/자산모으기.js` 후 해당 영상 출력 |
| 실시간 장면 | [현재 표현 기준](Loom_실시간장면_표현기준.md)과 장면별 빌더 |

`지면얹기.js` 쓰기 플래그는 `--적용`이고 `--제자리`는 없다. 관리 대상은 `지면방.js --분모`와 생성기의 실제 목록에서 확인하며 통로·지면 수를 문서에 고정하지 않는다. 스타일 생성과 이미지 생성의 영향 범위를 구분한다.

## 실행과 확인

로컬·기존 클라우드는 품질·현재 사용 조건에 맞춰 고른다. 과거 계정 버킷·장비·비용·무료 쿼터를 현재 조건으로 복사하지 않는다. 신규 지출·보호 절차는 [AI 운영 원칙](AI_운영원칙.md)을 따른다.

출력·원본/파생 관계·소비 위치를 확인한다. 종료 상태만으로 결과를 판정하지 않고 실패 시 부분 출력도 확인한다. 실행 성공·재현 검사·화면·배포·실사용은 구분한다.
