## §0. 목적과 현재 위치

학생이 배움·재미·추억·신선함을 얻고 자기 삶에 도움이 되는 경험을 만드는 것이 목적입니다. 학습·수집 기능은 **모였나 → 닿았나 → 달라졌나 → 누구에게**를 잇습니다. 음악·문화·안내·시각 표현은 그 자체의 쓸모와 경험으로 판단하며 모든 기능에 학생 수집을 강제하지 않습니다.

### §0-1. 학생에게 돌아가는 경험

과제·교정·일기·목표·성장 기록은 실제 행동과 말에 근거해 다음 도움으로 이어집니다. 학생이 자기 이해를 고치거나 반영에서 뺄 수 있어야 합니다. 쉬거나 빠진 날을 벌주지 않고, 자료가 적다는 이유로 성향을 꾸며내지 않습니다. 게임·마스코트·정원은 재미를 제공할 수 있으나 클릭·체류만으로 교육 효과를 단정하지 않습니다.

### §0-2. 일곱 엔진의 역할

| 엔진 | 역할 | 주요 연결 |
|---|---|---|
| Core | 원신호·이해·선택·과제·교정의 중심 | 접점·시간 이력·검증된 교안·성과 재료 |
| Loom | 재질·빛·배치·움직임·출력의 표현 | 승인 자산과 실제 장면 |
| Vellum | 학생·강사·부모에게 닿는 말과 행동 | 노출·반응·명시 선택·관찰 |
| Trail | 의도와 결과를 시간에 따라 연결 | 본인 기록과 내부 집계 |
| Prism | 조건과 분모가 있는 집단 분포 | 검증된 교안·과업 재료 |
| Temper | 어떤 도움 뒤 무엇이 달라졌는지 대조 | 개입·노출·후행 관측·사람 회고 |
| Reed | 소리·방송·함께 머무는 경험 | 실제 곡·장면·익명 방송 관측 |

이 역할은 발전의 상한이 아닙니다. 새 저장·도구·화면은 필요와 책임 경계를 설명해 설계하며 과거의 ‘새 파일·표·화면 0’으로 일괄 기각하지 않습니다.

### §0-3. 작업과 완료 기준

현재 요청에서 승인된 일을 수행하며 이미 채택한 D 선택을 다시 묻지 않습니다. 필요한 계약·권한·시험·소비자를 함께 반영합니다. 코드 존재·로컬 시험·DB 적용·배포·자연 실행·실제 수신·학생 효과는 각각 다른 증거입니다. 09-11의 특정 경로 미도달이나 09-13의 로컬 장면 승인을 엔진 전체의 실패·완료로 확대하지 않습니다.

## §1. 발전 판단 기준

- 실제 대상에게 도움이 되는지 확인합니다. 학습 기능은 수행 변화까지, 문화·표현은 경험의 질까지 봅니다.
- 원문·관측·교정·AI 추정·학생 확인·사람 판단을 구분합니다. 도움받은 산출을 독립 능력으로 승격하지 않습니다.
- 모델·렌더러·저장 방식은 교체 가능하게 만듭니다. 승인 정체성과 데이터 계약을 지키는 다른 방법을 허용합니다.
- 같은 입력·대상·기준시각·판에서 비교합니다. 합성 결과와 실학생 결과를 섞지 않습니다.
- 동의·철회·접근권한·예산은 실제 이용 범위에 적용합니다. 보존은 삭제·철회를 거절하는 규칙이 아닙니다.
- 기존 공식 도구와 통로를 먼저 사용하고 새 중앙 큐·강제 훅·고정 모델 순서를 기본으로 만들지 않습니다.

‘AI가 두 배 좋아지면 모든 기능이 두 배 커져야 한다’, ‘사람 판단은 반드시 한 클릭’, ‘모델 약점을 다루는 층은 전부 금지’는 공통 심사 기준에서 삭제했습니다. 학생 타인 비교 금지와 사실인 시험 점수·가격·내부 품질 비교는 [철학 적용 기준](철학_적용기준.md)의 범위를 따릅니다.

## §2. 외부 사례와 모델 조사

09-02~05의 제품·논문·벤더 비교는 [당시 조사](https://github.com/unmet23-lab/synk-appsscript/blob/f657502b1c85ce7a74b345029ea581fb32e92d14/docs/엔진7종_상향설계_v3.md#L516)에 보존합니다. 당시 가격·지원 여부·끝난 후보 선정은 현재 실행 조건이 아닙니다. 다시 조사할 때는 이번 기능의 질문·비교 입력·성공 조건을 먼저 정하고 공식 자료와 실제 출력으로 확인합니다. 다른 서비스의 성적을 SYNK의 효과로 인용하거나 모델 수·검토 회차를 채우기 위해 조사하지 않습니다.

## §3. 공유 구조와 계약

### §3-1. 원천과 파생

원신호는 출처·발생 시각·적재 시각·정정 계보를 갖습니다. 파생 상태·산문·집계는 입력 참조와 기준시각·계산판을 남겨 다시 계산합니다. 필요한 캐시·표·뷰는 목적·갱신·무효화·권한을 정의해 만들 수 있습니다. C/D 파생 저장 전면 금지는 유지하지 않습니다.

학생 식별 데이터는 승인된 저장·전달 경로만 사용합니다. 자유서술의 이름·기관·날짜 조합은 열 제거만으로 비식별화되지 않습니다. 외부 모델·도구·사람에 전달할 때 현재 데이터 계약을 따릅니다. 기존 승인 음성 처리와 새 발음 분석 반출은 별도 범위입니다.

### §3-2. 목표의 출처

엔진 추천과 학생 목표를 engine/student 원산으로 가릅니다. goal.stated는 학생 앱과 강사 전달을 함께 설계하며 명시 선언과 관측 행동을 섞지 않습니다. 최초 선언·수정·당시 선택을 재현합니다. [엔진 추천 목표](엔진추천목표_설계_v1.md)의 현재 통로와 미구현을 확인합니다.

### §3-3. Atlas의 층

원신호→구조화 이해→산문 요약→선택·되돌림을 구분합니다. 과거 산문을 새 관측으로 먹이지 않습니다. 학생판·강사판의 입력·권한을 나누고 제외·철회가 늦게 끝난 작업과 사본에도 반영되게 합니다.

### §3-4. 공유 계약

| 계약 | 생산자 → 소비자 | 유지할 조건 |
|---|---|---|
| 수집·교정 어휘 | 계약 → 엔진별 쌍 | JSON·DDL·검증기·파서·요청 판·양 저장소 동기. D1과 부록 |
| 학습자상태 | 원신호 → 과제·교정·회고·요약 | 명시/관측·도움 여부·결측 사유·두 기준시각 |
| intervention.delivered | 실제 개입을 확인한 서버 → Temper·회고 | 앱 노출/탭과 서버 사건 구분. 기본 task/companion/teacher_classroom |
| report.delivered | 실제 리포트 전달 → 회수 | D25의 별도 사건. 생성/전송/열람/종이 수령 분리 |
| atlas_summary | 원신호 → 학생판/강사판 | 파생 캐시·근거·시효·제외·철회. D7 |
| 과정·만짐·관심 | 화면 → 상태·표현·집계 | 당시 노출 분모·멱등성·0/미관측 구분 |
| 명시 선택·자기설명·수정 | 학생·강사 전달 → 해석 | 학생 말과 관측을 나란히 보존 |
| goal_used | 실제 생성 입력 → 성장·Trail | 목표 조회와 실제 사용을 구분 |
| 비식별 처리 | 원문 → 승인된 외부 호출 | 본문 식별 가능성·처리판·이용 동의 |
| 오늘의 한 가지 | 교정·복습 재료 → 카드·과제 | 같은 선택 정의·실제 써 보는 자리 |
| 접점 예산 | 각 접점 → 노출 | 묻기/제공/제출 절차 구분·동시 예약·해제·재시도 |
| 시즌 회고 | 학생 응답 기회 → 강사 판단 | 학생 자기판정·강사 verdict·통한 개입·실현. 미응답 null 진행 허용 |
| 모델·시험 결과 | 현행 정책 → 실행·비교 | 실제 모델·시험판·비용·실패·엔진/종류별 필터 |
| 자산·토큰 | 승인 원천 → 앱·영상·인쇄·방송 | 원본/파생·권리·실제 출력 검수 |
| 운영↔앱 읽기 | 승인 서버 통로 → 소비자 | 실패/빈 결과·권한·실제 도달 구분 |

공유 계약의 과거 개수나 예정 파일 이름을 고정 상한으로 삼지 않습니다. 삭제된 listen.session·개인 청취·곡 사이 개인 오답 수집은 되살리지 않습니다. 값목록의 정본은 실제 계약 파일입니다.

### §3-5. 함께 확인할 경계

- 선택 당시 재현은 occurred_at≤as_of와 ingested_at≤ingested_as_of를 함께 적용합니다. 늦은 자료를 넣은 재계산은 별도입니다.
- 계약·생산자·조회·API 변환·출력 소비자를 함께 확인합니다. 계약 파일 동일성은 실제 왕복 성공과 다릅니다.
- 배정·생성·전송·수신·노출·응답·후행 기회와 전체 대상 스냅샷의 분모를 구분합니다.
- 선택판·내용판·측정판·모델판과 실제 실행 조합을 남깁니다. 새 시험은 실제 깨질 수 있는 데이터·제품 동작을 검증합니다.
- 기존 예약·작업 도구를 재사용합니다. 과거 중앙 밤 사슬·큐·고정 심문 횟수는 의무가 아닙니다.

### §3-5-1. 관통 검증의 담당

[관통왕복 명세](관통왕복_명세.md)의 실제 검증점 이름과 구현을 따릅니다. V6~V9를 중복 재정의하지 않습니다. 상태·요약·질문·스타일·궤적·회고의 생성과 소비를 각각 확인하며 없는 소비자는 계획으로 남깁니다. 원격 배포판과 로컬 HEAD를 구분합니다.

## §4. SYNK Core — 이해하고 다음 도움을 고르는 중심

정본: [코어 엔진 설계](코어엔진_설계.md), [엔진 추천 목표](엔진추천목표_설계_v1.md), [엔진 도달](엔진도달_설계.md). 실제 구현은 엔진 파일들과 SYNK-talk의 계약·서버 함수에 걸쳐 있습니다. 09-11 검토의 특정 통로 0을 전체 수신 0으로 쓰지 않습니다. 현재 deliver의 회수 요약 호출·계수와 그 결과가 다음 선택을 바꾸는 되먹임은 별도로 확인합니다.

### §4-2. 발전 구조

과정·명시 선언·관찰을 뜻이 다른 재료로 쌓고 선택·교정·되돌림에 사용합니다. 모델 개선은 같은 원신호를 더 잘 읽고 실제 도움을 개선하는지로 확인합니다.

### §4-2-1. 근거 자격·관측·재판정 모듈 — 이번 특허 후보의 Core 귀속 (2026-09-12)

**소유 엔진은 SYNK Core입니다.** 같은 발화·원음·도움 사건을 어떤 기록 목적에 쓸 수 있는지 나누고, 보류를 풀 관측을 고른 뒤, 새 사실이 오면 관련 결과만 다시 계산하는 일은 Core의 기억·판단·재심 책임입니다. 이 모듈은 SYNK Atlas 안에서 다른 엔진이 사용할 근거를 준비하며 새 여덟 번째 엔진을 만들지 않습니다.

| 경계 | Core가 맡는 일 | 다른 엔진이 맡는 일 |
|---|---|---|
| 입력 | 원음·전사 후보·문항 조건·도움·응답·시점과 각 판본 | Trail은 더 긴 시간축, Vellum은 학생에게 닿는 표현을 제공 |
| 판단 | 용도·능력·시점별 근거 자격을 반영·보류·제외로 계산 | Loom은 이 판단을 계산하지 않음 |
| 관측 | 보류된 칸을 가를 다음 확인과 답 노출·시간 비용을 함께 선택 | 강사·학생 화면은 실제 확인 행동을 받음 |
| 재판정 | 새 관측의 의존 범위만 무효화하고, 유지할 효과와 거둘 효과를 나눠 다시 계산 | Temper·Prism은 허용된 출력만 각 평가에 사용 |
| 출력 | 근거 효과, 판단 이유, 앞뒤 판본, 변경 원인과 재현 지문 | Loom은 미팅 자료와 작업실에서 이를 읽히는 화면으로 표현 |

현재 실행 증거는 `tools/patent-studio/`의 **로컬 통제 시제품**입니다. 제품 학생 DB·Apps Script·Supabase 운영 경로에는 아직 연결·배포하지 않았습니다. 따라서 특허 검토 대상은 Core 전체나 “AI가 학생을 이해한다”는 넓은 말이 아니라, **용도·능력·시점별 자격 판정 → 확인 관측 선택 → 실제 관측 후 선택적 재판정**의 구체적인 처리 관계입니다.


### §4-3. U 항목

#### U1 과정 신호와 관찰 선택

- compose_meta, latency_ms, changed_selection, 이탈 시점까지 시간 등 실제 UI에서 생기는 신호를 생산자·검증기·소비자와 함께 잇습니다. question·goal·reply·quiz의 사건과 상태 소비자는 각각 확인합니다.
- 값·표본 수·empty_reason·노출 분모·질문 이력으로 관찰을 고릅니다. 관측 없음·계측 실패·해석 충돌을 구분하고 없는 관측을 학생 추측으로 채우지 않습니다.
- 붙여넣기 등 저작 신뢰는 제출 행의 해석 조건입니다. 성격 라벨로 올리지 않고 도움받은 산출과 독립 능력을 가릅니다.
- as_of·ingested_as_of와 실제 확인카드 예산을 지킵니다. 기존 계약 안에서 가능한 연결까지 전체 다음 판을 기다리게 하지 않습니다.

#### U2 학생·강사·엔진 목표의 출처

goal.stated의 goal_tag·비식별 goal_text(최대 50 code point)·channel(teacher_relay/student_app)·source_kind·origin_goal_id를 잇습니다. progress·M2·과제·Trail에서 학생 선언과 엔진 추천을 구분합니다. D6의 두 통로 채택을 새 승인 대기로 되돌리지 않으며 실제 구현 상태는 추천목표 정본에서 확인합니다.

#### U3 폐기한 앱 개인 청취

앱 재생기·listen.session·청취 리듬 수집은 접었습니다. 유튜브 방송으로 가는 링크·안내와 Reed의 소리 경험은 별도입니다. 개인 청취 수집을 사용자 재승인 없이 되살리지 않습니다.

#### U4 근거가 있는 산문 요약

- 원신호에서 학생판/강사판을 만들고 measured/interpreted·evidence_refs를 구분합니다. 강사 전용 observation.noted·teacher_classroom을 학생판의 개인 해석 근거에 흘리지 않습니다. 이전 요약을 다음 관측으로 입력하지 않습니다.
- atlas_summary는 파생 캐시입니다. 기본 시효 두 시즌, 개입 참조판의 재현 보관은 필요한 보호 범위에 한정하고 동의·철회·제외가 우선합니다. 개입에는 summary_ver/hash·as_of·ingested_as_of를 남깁니다.
- atlas.excluded는 문장·근거 참조에 걸고 제외 이전에 시작한 비동기 작업의 늦은 쓰기까지 막습니다. 제출·교정판과 당시 적재 범위로 재현합니다.
- 같은 모델·입력·시각·독립 평가분에서 기존 구조화 요약과 비교합니다. 합성 시험만으로 개인 이해 품질을 주장하지 않습니다. portfolio_moments 시트와 당시 출석 반 스냅샷은 실제 원천으로 구분합니다.

#### U5 선택과 성과 회수

- 초기 활성은 결정론, 후보는 섀도입니다. 개입 id·policy_ver·as_of 기반 시드와 후보 집합·확률·분기를 남겨 선택을 재현합니다.
- 배정→노출→제출/교정→후행 기회를 잇고 배정·노출·기회·채점 가능 관측의 분모를 나눕니다. 동일 후행 제출을 여러 개입의 독립 표본으로 부풀리지 않습니다.
- 후행 관측 없음은 실패가 아닙니다. 활성 정책·탐색 변경은 D4를 따릅니다. 회수 함수 호출과 다음 선택 변화는 별도 검증입니다.

#### U6 학생이 이해를 고치고 반영에서 빼기

corrected_value·atlas.excluded는 학생의 정정·제외 의사입니다. 원관측을 같은 사실로 덮어쓰지 않고 이후 요약·질문·선택에 반영합니다. 제외로 성장 세 축을 떨어뜨리지 않습니다. 원문 보존과 개인정보 삭제·철회는 별도 계약입니다.

key_takeaway의 프롬프트·파서·UI를 함께 바꾸고 학생 응답 기회→엔진 제안→강사 판단을 구분합니다. 동의율은 응답자 안의 비율이며 노출률·응답률을 함께 봅니다.

#### U7 모델을 같은 문제에서 다시 평가하기

공식 출시·현행 정책·실제 과업의 품질과 비용을 대조합니다. 감지·실행·완료·보류를 구분하고 소스 실패를 새 모델 없음으로 쓰지 않습니다. 엔진/평가 종류별 입력판·원문 계보·실제 실행 모델을 남깁니다. 실학생 원문은 공개 저장소·CI에 넣지 않습니다. 특정 모델·정해진 회차·중앙 밤 사슬은 의무가 아닙니다.

#### U8 실제 자료의 평가·훈련 전환

promote 의사와 해당 목적의 data_use 동의를 모두 확인합니다. 평가·훈련·공개는 별도 이용입니다. 비식별 처리판·검토한 내용 지문·원문 계보를 고정하고 실행 직전 재확인합니다. 철회는 파생·복사본·재복사 차단까지 전파합니다. 동일 학생·원문·재제출이 학습/평가분을 넘나들지 않게 묶습니다. 실제 자료가 생긴다면 이용 전 준비하며 ‘개원 전이니 자료 0’으로 미루지 않습니다.

#### U9 학생 생애와 긴 기억

learner_id를 지속 식별자로 두고 계정·입학·퇴소·마지막 완료 시즌을 잇습니다. 현재 상태의 짧은 창·요약 시효·승인된 장기 보관을 구분합니다. 과거 목표를 현재 목표로 덮지 않고 재가입 id를 max+1로 충돌시키지 않습니다. 다른 앱의 연결 이용과 진로 결과 집계는 해당 동의를 처음 쓰기 전에 확인합니다. 장기 보관 설계가 삭제·철회를 막지 않습니다.

## §5. SYNK Loom — 재질과 장면을 실제 출력으로

정본: [Loom 엔진](Loom_엔진_설계.md), [살아있는 재질](Loom_살아있는재질_설계_v1.md), [실시간 장면 표현 기준](Loom_실시간장면_표현기준.md), [배치 판단층](Loom_배치판단층_설계_v1.md).

#### U1 만짐의 세션 봉투

화면 사건 통로가 tap_n·stroke_ms·press_n·wake_n·first_at·last_at과 사분면 수를 세션 단위로 묶습니다. 마스코트 부품은 DB 쓰기를 맡지 않습니다. payload와 idempotency_key를 먼저 고정하고 저장/중복 ACK까지 보존해 재시도합니다. 계정 전환·기기 비우기 때 미전송 상태를 다룹니다. 관측한 0과 미관측 null을 구분하고 낱개 터치 이력·감정 추론을 만들지 않습니다.

#### U2 상황을 공유하는 움직임

- 앞으로 애니메이션을 지원하는 Loom 결과에 현재 장면 방식을 기본 적용합니다. 정적 전용 커버는 예외입니다. 모든 재질을 펠트로 바꾸거나 모든 버튼에 정원 바람 주기를 강제하지 않습니다. 인터랙티브와 영상 출력 경로를 구분합니다.
- 캐릭터·배경이 같은 바람·빛·사건을 읽고 시선 뒤 몸이 따라오며 휴식과 반응이 교대합니다. 원본 정체성·털 결·접지·카메라/지면의 안정감을 지킵니다.
- 정원 승인값은 15초 중 12초 정지·3초 바람(2초 최대, 마지막 1초 감쇠), 풀 뿌리 고정·최대 9 CSSpx입니다. 수동 바람은 즉시 시작하고 활성 중 재클릭은 연장하지 않습니다. 이 수치는 해당 장면의 값입니다.
- hidden·paused·reducedMotion 정지와 재개 첫 dt 폐기, 소리 옵트인, 녹음 간섭을 확인합니다. received는 새 교정 id의 도착이며 앱 배포 도착 화면을 트리거로 쓰지 않습니다.

#### U3 Patina와 자기 기록

자리·색·결 같은 명목적 흔적으로 경험을 표현하되 우열·양·타인 순위처럼 읽히지 않는지 실제 화면을 나란히 봅니다. as_of·ingested_as_of·recipe_ver·loom_ver·원천으로 당시 출력과 재계산을 가릅니다. 시간대 같은 개인 재료를 부모·강사 인쇄물에 확대하지 않습니다. 빠진 날 흔적을 깎지 않습니다.

#### U4 리포트·책·인쇄의 실제 전달

엔진_폼리포트.js의 월간 카드와 talk 시즌 재료를 승인 경계로 잇습니다. 학생판·강사판·부모판의 자료를 구분합니다. 생성·전송·앱 열람·종이 수령은 다른 증거이며 report.delivered에 전달 채널·확인 종류·리포트판을 남깁니다(D25). 재인쇄를 새 성과로 세지 않습니다.

#### U5 시각 품질 판단

승인 자산과 실제 사용자 선택을 근거로 후보를 비교합니다. 재질·정체성·접지·읽힘·반응형을 실제 출력에서 확인하고 모델 점수를 취향의 정답으로 만들지 않습니다. 원판의 색갈이·크롭은 같은 계보로 묶어 개발/독립 평가에 동시에 넣지 않습니다. 사람의 최초 판단은 모델 추천에 가리지 않게 하고 모델이 접은 후보도 표본 검수합니다. 판단 당시 이미지 내용·표시 크기를 남깁니다.

#### U6 도구 개선을 표현 품질로 연결

출시 정보의 읽기 성공·실패·출처 시각을 남깁니다. 같은 장면·자산·과업에서 신구 도구를 비교하고 실제 개선 경로를 갱신합니다. 403·파싱 실패를 변경 0으로 세지 않습니다. 기존 모델 정책·정찰·작업 도구를 재사용하고 새 고정 큐·밤 작업기를 의무화하지 않습니다.

#### U7 토큰·조판·렌더의 원천 일치

디자인_토큰.json·마스코트자산.js·tools/토큰빌드.js 등 담당 원천에서 파생합니다. 생성 파일 소유 목록을 명시하고 원천과 산출을 대조합니다. 대비는 실제 글자 크기·합성 배경에서 확인합니다. 형제 저장소가 없거나 대상 일부를 못 읽은 검사는 미확인/skip으로 표시합니다. 토큰 일치만으로 시각 품질을 선언하지 않습니다.

#### U8 2.5D 재사용과 3D 확장

원본·참조·권리·재질 정보를 자산에 연결합니다. 현재 깊이 격자·국소 마스크·알파 투영 그림자는 2.5D이며 진짜 3D 광선 물리·자동 완전 변환이 아닙니다. 필요한 캐릭터·소품은 실제 3D를 실험할 수 있습니다. 사진결만 허용·마스코트 참조 재생성 재론 금지·Expo 전 보류·실시간 전면 금지 같은 구현 독점은 삭제하고 승인 정체성과 실제 품질을 유지합니다.

## §6. SYNK Vellum — 말과 행동이 닿는 접점

정본: [세 층 합류](세층합류_설계_v1.md), [학생 일기](학생일기_설계.md), [캐릭터 가이드](캐릭터/가이드_정본.md), [엔진 도달](엔진도달_설계.md). 앱·강사·부모·공개 안내의 대상과 권한을 구분합니다. 모든 마스코트 발화를 사적 학습 원장에 연결하지 않습니다.

#### U1 노출과 반응, 명시 취향

topic.engaged는 실제 노출 event_id에 반응을 잇습니다. 같은 line_id의 반복 노출을 하나로 합치지 않고 반복 탭은 중복 제거합니다. 읽을 수 없는 노출·종료·네트워크 손실을 무시로 추정하지 않습니다. 가이드 선택은 preference.stated의 명시 취향입니다. 적응 노출 뒤 반응과 처음 균등 노출의 관찰 조건을 구분합니다. 선택 제약·도움 여부를 취향으로 학습하지 않습니다.

#### U2 첫 순간을 정확히 되돌리기

Amber의 first_kind·moment_id는 실제 첫 제출·첫 녹음·첫 무오류 같은 사건에서 만들고 learner_id×moment_id의 멱등성을 둡니다. 일별 노출 상한은 별도 날짜 키로 처리합니다. 응답 유실에도 동일 사건을 회복하며 부가 카드 실패가 제출을 실패시키지 않습니다. 자격·예산·녹음·동작 설정을 표시 직전에 확인하고 reducedMotion에서는 사실 문장을 제공합니다. 개인 성취를 부모에게 먼저 알리지 않습니다.

#### U3 근거가 있는 동반자 말

확인된 재료·명시 취향·목표로 템플릿 또는 승인된 생성 경로를 선택합니다. 노출 전 후보와 실제 전달을 구분하며 앱 노출 근거로 서버가 companion 개입을 기록합니다. output_text·cited_refs·생성판·두 기준시각으로 실제 말을 재현합니다. 공공 안내·회사 사이트·라디오 DJ가 비공개 학생 원장을 읽는다고 가정하지 않습니다. 학생과 부모에게 공유하는 개인 이해의 순서와 일반 운영 안내를 구분합니다.

#### U4 브랜드 말투와 정확성

현재 브랜드·캐릭터 정본과 실제 소비자를 함께 갱신합니다. 고정 금칙어 개수·모든 숫자 금지·특정 모델 셋 검토를 보편 규칙으로 만들지 않습니다. 같은 낱말이라도 근거 사건·시각·부정·‘처음’ 조건이 달라졌을 때 잘못된 성취·성향을 말하는지 검증합니다. 몽골어 검수는 학생 접점·무료 자체 채널·유료 광고 등 [철학 적용 기준](철학_적용기준.md)의 범위를 따릅니다.

#### U5 성장 세 축

크기=독립 수행 문법 항목의 누적 거리, 선명함=처음 해본 활동 종류, 빛=자기 목표가 실제 과제에 실린 제출일의 재료로 설계합니다. 단순 목표 조회를 goal_used로 찍지 않습니다. 결석·실패·반영 제외로 세 축이 떨어지지 않고 타인 비교·점수판으로 표현하지 않습니다. 실제 값·표시의 최신 정의는 [철학 적용 기준](철학_적용기준.md)과 앱 계약에서 가져옵니다. 공식 시험 점수·가격에 같은 숫자 금지를 확대하지 않습니다.

#### U6 짧은 자기설명

correction.responded 뒤 S26 보기 3개를 명시 응답으로 남기고 질문·제출·교정판에 연결합니다. 선택을 실제 오개념의 확정으로 승격하지 않습니다. 자유문을 추가하려면 비식별·언어·저장·소비 경로를 함께 설계합니다. 해당 주기·시간 예산과 하루 확인카드 예산을 조정하며 과거 ‘성향 하루 1회’를 재도입하지 않습니다. 질문의 노출과 응답을 같은 고리로 잇습니다.

#### U7 강사에게 돌아가는 도움

새 성공·최근 조용한 학생·부정한 이해 등 실제 근거로 손 카드 셋을 고르는 방향을 유지합니다. 관찰은 강사가 먼저 적고 AI는 구조화를 돕습니다. ‘말 걸었다’ 탭은 행위 기록이지 대화 효과가 아닙니다. teacher_classroom은 서버 사건이며 관찰과 개입의 멱등키를 구분합니다. 미선택을 아무것도 하지 않음으로 해석하거나 손 카드를 잔소리 목록으로 만들지 않습니다.

#### U8 화면에서 실제 수신까지

서버 생성→API 변환→화면 노출→선택·행동을 확인하고 실제 대상·권한·분모로 도달을 판정합니다. UI 파일 수·HTTP 성공은 수신의 대체값이 아닙니다. 안내·마케팅·문화 접점에 개인 학습 수집을 강제하지 않습니다. 구현·배포·미도달은 엔진 도달 정본과 실제 증거로 확인합니다.

#### U9 자발적인 일기

일기는 선택이며 빈 날은 결손이 아닙니다. 책상 위 일기장과 과제 종료 뒤 바로 가는 손잡이를 유지합니다(D29). diary.opened/written/acknowledged의 부모 관계·멱등키, input_lang·code_switch_spans의 원문 위치, 별도 job_kind·유일 제약·기존 워커 선별을 함께 바꿉니다. 언어 전환은 모르는 말 후보이지 문법 오류가 아닙니다. 원문 버전과 수정 가능한 화면의 스냅샷을 구분합니다. 구체 계약 아홉 자리는 학생 일기 정본을 따릅니다.

## §7. SYNK Trail — 의도와 결과의 긴 기록

정본: [궤적 원장 기록](궤적_원장기록_실행지.md), [학생 ID 종단](학생ID_종단_설계.md), [시즌 회고](시즌회고_설계.md), [엔진 도달](엔진도달_설계.md), SYNK-talk의 학생·생애·회고 계약. trajectory를 읽는 소비자와 이미 있는 진단·시즌 회고 전달은 구분합니다. 일부 미도달을 전체 학생 수신 0으로 쓰지 않습니다. 아래 trail-sync·my_trail의 확장 경로는 설계이며 현재 함수·뷰 적용은 별도 확인이 필요합니다.

#### U1 졸업·이탈·미상 구분

exit_log의 종료사유·종료일과 learners.lifecycle_status, 마지막 완료 시즌을 잇습니다. 헤더 이름으로 읽고 trajectory에 종료 세 열을 파생합니다. 빈 사유는 미상으로 유지하며 실제 사유 미상과 인제스트 실패를 구분합니다. 종료일의 텍스트 형식·월 키를 보존하고 learners↔trajectory의 같은 사람·같은 사실을 대조합니다. 종료사유의 장기 공백과 미상 비율을 운영에서 확인합니다.

#### U2 시즌마다 바뀌는 의도

season_compass·season_review의 최초 선언·수정·회고를 시간순으로 읽습니다. goal.responded explicit와 목표 과제 제출일수 observed를 분리하고 배정을 제출로 세지 않습니다. 전환 후 일치/불일치 등 추가 갈래는 기존 7갈래 의미를 보존하며 계약을 개정합니다. 발생·처음 적재·해석 변경 시각을 구분하고 월까지만 아는 날짜로 같은 달 안 선후를 단정하지 않습니다. 학생 응답 기회 뒤 미응답 null이어도 강사 판단은 진행할 수 있습니다.

#### U3 원문과 판이 있는 결과 해석

- outcome_log의 raw_text·source_channel·원천식별자·ingested_at에 outcome_verdict의 분류자·classifier_ver·confidence·extra_json을 잇습니다. form은 수집 경로이며 사실 확인 등급이 아닙니다.
- 한 사람의 여러 지원·도전을 가르고 동일 소식의 통로 간 중복을 제거합니다. 이의 제기를 특정 원문·해석에 연결해 재판정이 같은 오해를 되살리지 않게 합니다.
- 외부 분류 전 이름·연락처·기관·날짜의 식별 가능성을 제거합니다. 삶·목표·보장 판단은 사람이 맡고 모델 confidence는 실제 정확도로 검증합니다. 사람에게 판단이 필요한 초안과 이의 제기 경로를 제공합니다.
- 집계 동의 철회는 파생·사본·재판정에 반영합니다. 보존과 이용 허락을 구분합니다. 모델·통로 선택은 현재 권한·예산과 과업 검증을 따릅니다.

#### U4 평가와 재판정

같은 시험판에서 언어별·본인/타인·지원/합격·예정/완료를 나눠 평가합니다. 전체 정답률과 자동 채택한 답 중 정답률을 함께 봅니다. 실제 최종 평가분은 개발 자료와 분리합니다. 엔진 필터가 다른 엔진의 최신 점수를 덮지 않게 합니다. 새 판은 대상별 처리 완료·보류를 확인한 뒤 사용하며 중간 실패에서 이어 돌 수 있어야 합니다. 철거한 테스트 이름·개수의 복원을 목표로 삼지 않습니다.

#### U5 약속과 실제 결과

- 정규 오프라인 1년 과정 후 첫 TOPIK 4급 목표와 미달 시 앱 계정 6개월 온라인 케어, 개원 전 온라인 8주 약속은 [철학 적용 기준](철학_적용기준.md)과 상품 정본대로 각각 셉니다. 과거 ‘취득할 때까지 무기한’으로 확대하지 않습니다.
- exam.result의 doc_verify_no·verify_status·verified_at·announced_at을 강사 서버 사건으로 잇고 증명서·확인번호는 내부에 둡니다. 제보를 확인 급수로 세지 않습니다. 공식 성적과 모의시험 문항별 정오는 별도 계약입니다.
- 온라인 약속은 시작/끝 진단의 문항 은행·채점판·급수 경계·틀을 맞춰 비교하고 무료 연장 개시·종료와 완주 분모를 남깁니다.
- 외부 몽골 유학생 통계는 시장 배경이며 SYNK 성과율의 분모가 아닙니다. 재관측은 기한이 도래한 졸업생과 인정 관측 기간으로 셉니다. 급수·케어·미확인을 구분하고 분모 0을 성공으로 쓰지 않습니다.

#### U6 자기 기록과 내부 집계

- trail-sync는 사실별 원본을 존중하는 읽기 사본입니다. 급수 원본 exam.result를 오래된 시트 거울로 덮지 않습니다. 대상·내용·기준시각·제외 사유를 대조하고 불완전 결과로 마지막 정상 결과를 덮지 않습니다.
- my_trail은 current_learner_id() 등 실제 계정 매핑으로 본인 기록을 읽습니다. learner_id=auth.uid 직접 비교를 쓰지 않습니다. 강사 뷰도 담당 반·허용 열만 열며 원장 서랍의 상담·결제·가정 자료는 제외합니다.
- senior_paths는 동의된 확인 등급의 내부 집계입니다. 초기 셀 최소 n=5는 값 정본에서 관리하고 독립 학생 수·소수 집단 재식별을 함께 봅니다. 남의 결과 비교를 학생에게 전달하지 않습니다.
- V8a는 자기 시즌 이력이 교정 맥락에 실린 경우와 null인 경우를 확인합니다. trail_ref의 후속 카드 경로도 실제 소비자와 함께 검증합니다.

#### U7 졸업 뒤 자기 기록과 발급

학습 이용·무료 케어·졸업 카드 전환의 조건을 구분합니다. 자기 카드·계정·선택 복구 통로·근황 동의·미성년 보호를 설계하고 미응답을 재촉하지 않습니다. 서명 파일의 외부 발급은 D10의 구체 판단 범위입니다. 설계·로컬 검증을 막지 않되 개인키 보호·취소 목록·개인 자료 처리 경계·실제 수신처 확인을 갖춥니다. 검증 가능한 파일과 외부 기관이 실제 받아 준다는 주장은 다릅니다.

#### U8 정본과 파생의 최신화

완료한 기간·표 존재·옛 모델 이름 교정은 반복 작업 목록에서 삭제했습니다. 현재 정본·실제 출력·읽는 도구를 함께 갱신하고 과거판은 Git에서 확인합니다. 무조건 원문 병기·낱말 검사·즉시 커밋을 새 절차로 강제하지 않습니다.

## §8. SYNK Prism — 조건이 있는 분포와 교안 재료

개인 교정·과정 원신호에서 분포를 읽고 검증된 재료를 교안·과업에 돌려주는 설계입니다. 학원·과업·기간을 넘어 몽골어 화자 일반으로 주장하지 않습니다. [엔진 도달](엔진도달_설계.md), [철학 적용 기준](철학_적용기준.md)과 담당 데이터 계약에서 실제 집계·소비 상태를 확인합니다.

#### U0 산출의 대상·분모·권한

값·n·분모·판·출처·키 출처에 독립 학생 수·학생별 기여 편중을 함께 냅니다. 작은 집단과 제출 반복을 구분합니다. 학생·부모에게 집단 비교 설명을 전달하지 않되 교정·과업 재료로 바꿔 돕는 것은 허용합니다. 개인 원문·행은 공개 저장소에 넣지 않습니다. 새 중앙 등록층·강제 래칫을 기본으로 만들지 않고 실제 출력·권한 경계를 필요한 시험으로 검증합니다.

#### U1 관측 전에 가설 명시

가설의 방향·분자/분모·제외·실패 처리·비교 구간·반복 대조·조준 발동 조건과 등록 시점 증거를 남깁니다. 이미 자료를 본 분석은 사후 분석으로 표시합니다. 기기 발생 시각과 서버 적재 시각을 구분해 오프라인 제출이 선후를 뒤집지 않게 합니다. NIKL의 오류 위치 구성비와 기회 대비 오류 확률, 국적과 언어권을 구분합니다. 외부 자료의 현재 약관·권한을 확인하며 사전분포를 학생 사실이나 출제 초기값으로 넣지 않습니다.

#### U2 교정 편집에서 오류를 세기

- 원문·교정문 정렬, 편집태그→계약 오류태그 매핑, 자기보고 error_tags를 구분합니다. 기존 어휘를 몰래 재정의하지 않습니다.
- 태그마다 기회를 원문·교정·과업 조건 중 어디서 세는지 정합니다. 누락·대치·문체 교정·분석 실패를 다루고 기회 불명과 오류 없음을 구분합니다. 분석 실패는 제출 분모에 남깁니다.
- 정밀도·재현율·분석 실패·기회 완비율을 합성/실자료별로 냅니다. 합성 오류 생성과 correct 평가 통로는 별개입니다.
- 개발 정답은 최종 독립 평가에서 제외하고 동일 원문·재제출·화자 녹음의 계보를 묶습니다. 평가자는 모델 초안을 보기 전에 판정합니다.

#### U3 집계와 측정의 연속성

유형×급수×과업×시즌×출처 셀에 중복 제거 키·노출/기회 분모·저작 신뢰·독립 학생 수를 둡니다. 서로 다른 출처의 분모를 무리하게 합치지 않습니다. 교정 모델·태거·인식기가 바뀌면 같은 자료를 교차 측정해 도구 변화와 학생 변화를 가릅니다. 정밀도만을 고정 잡음 상한으로 쓰지 않고 측정 오차가 결론을 바꾸는지 봅니다.

재검수 supersedes·지연 도착·철회는 관련 셀과 사본까지 갱신합니다. 실행 이력이 없어 빈 것과 실제 셀 0을 구분합니다. 집계 코드·저장 자체를 개원 전이라는 이유로 금지하지 않습니다.

#### U4 빈칸이 다음 과업 재료를 바꾸기

관측 뒤 검증된 범위에서 낱말 교체·가중을 제안합니다. 확정된 축별 수·전체 수의 변경은 현재 결정 범위를 확인합니다. 조준/자연/카드 뒤 표본을 구분하고 같은 낱말·과업 형식의 공통 조건에서 비교합니다. 옛 활성 행을 비고만 바꿔 계속 소비하지 않게 합니다. 배정 뒤 목록을 바꿔도 늦은 제출은 당시 task_snapshot의 목표를 읽습니다. 분모·선택 제약을 복원할 수 없으면 개선 방향을 단정하지 않습니다.

#### U5 원음을 읽는 발음 평가

정렬용 텍스트의 당시 목표, 목표를 실제 발음했는지의 독립 판정, 정렬 실패를 나눕니다. 강제 정렬 성공은 목표 발음 성공이 아닙니다. 사람 귀와 인식기의 차이, 학생 소리와 기대 발음의 차이는 다른 수입니다.

새 발음 분석의 학생 원음 반출 제한과 승인된 기존 전사를 구분합니다. 내부 동의 성인 자료부터 실제 라벨 품질·target_absent·unjudgeable·실행량을 확인하고 미검증 값을 학생 능력으로 내지 않습니다. 특정 오픈 모델·WMI·밤 사슬은 필수 구현이 아닙니다.

#### U6 L1 관련 가설과 교차

편집태그·비식별 원문·교정에서 닫힌 원인 규칙 ID·근거 어절·미분류를 받습니다. 사람과 ID가 일치해도 몽골어 전이라는 인과를 확정하지 않습니다. 집단 쓰기/말하기 분포 차이를 같은 개인의 변화로 쓰지 않습니다. 교정 프롬프트의 관련 설명은 검증된 사전에서 파생하고 집단 낙인을 전달하지 않습니다. 합성 성적은 실자료 정확도의 상한이 아닙니다.

#### U7 평가 자료와 실제 실행 모델

기존 eval의 지원 함수·실행 모델 수집을 확인하고 후보 선택·허용 조합·배포판 차이·실패 기록을 필요한 범위로 추가합니다. 실자료는 promote∩해당 동의, 비식별 본문·분할 계보를 갖춘 비공개 평가분에 둡니다. 시트 수식 방어용 역소독은 본문 비식별화가 아닙니다. 모델 비용은 실제 호출량·현재 정책으로 정하며 Sonnet 급 등 고정 등급을 유지하지 않습니다.

#### U8 강사에게 닿는 교안 카드

관찰 확정 뒤 서버 응답→API 변환→완료 화면을 함께 잇습니다. 서버 응답은 수신·읽음의 증거가 아니며 카드 실패가 저장된 관찰을 실패시키지 않게 합니다. 재전송 중복과 카드가 다음 관찰에 영향을 주는 순서도 확인합니다.

반 단위 수신·선택판·내용판·근거 셀·전달/미전달 계약을 정합니다. learner_id 필수 사건을 임의 학생에게 붙이거나 반 인원만큼 복제하지 않습니다. 카드 없음 주는 표본 조건이 달라 인과 대조군이 아닙니다. 소수 반의 재식별과 이후 관찰의 확증 편향을 실제로 점검합니다.

## §9. SYNK Temper — 도움 뒤의 변화를 대조

정본: [개입 로그 규격](Temper_개입로그_규격_v1.md), SYNK-talk의 성과회수·회고·과제 선택 계약. 회수 계산의 존재와 선택·학생 되돌림의 변화는 별개이며 인과 효과와 관측 대조를 구분합니다.

#### U1 성공의 자와 입력 완전성

- 결과변수·기간·제외·결측 처리·기준선을 첫 해당 개입 전에 기록합니다. 나중에 바꾸면 새 측정판·사후 분석으로 표시합니다.
- 겨냥 태그의 30일 재출현을 재노출 기회와 함께 보고 대체 지표는 최종 교정 제출 단위 오류와 독립 수행을 구분합니다. 도움·저작 신뢰별 분모를 합치지 않습니다.
- learning_events만으로 충분하다고 가정하지 않습니다. corrections→submissions→원 사건, 본문 길이·과정 정보·전체 기준선 창을 조회부에서 공급합니다. 조회 상한·누락·잘림은 못잼입니다.
- occurred_at/as_of와 ingested_at/ingested_as_of를 함께 적용합니다. 개입 스냅샷을 소급 갱신하지 않고 대상·기준시각·선택판·측정판·심판판의 완료 분자/분모로 재심 완료를 셉니다.
- 30일 창 도래, 후행 표본 0, 미도래, 기준선 잘림을 분리합니다. 첫 시즌이라고 도래를 미리 0으로 정하지 않습니다. 측정 지문은 값뿐 아니라 상태 계산·저작 신뢰 등 실제 의존 동작을 포함합니다.

#### U2 개입 당시의 계약

expected_ver·shadow·intervention_choice·사람 확인 정보와 세 힘 태그의 저장 위치·값목록·누락 뜻·생산자·소비자를 함께 정합니다. actor_kind=teacher만으로 개입 종류가 기록되지는 않습니다. D1의 최초 moment_id 키/첫 값과 후속 값 확장을 구분합니다. 옛 개입·리허설에 당시 없던 판·점수를 소급 채우지 않습니다. JSON·검증기·DDL·생산자·소비자의 실제 판을 맞춥니다.

#### U3 교실에서 실제로 한 도움

강사 관찰과 개입은 다른 사건입니다. 같은 확정 요청에서 각각 재현 가능한 멱등키를 쓰고 parent_event_id 등으로 잇습니다. 동일 키로 한쪽이 사라지거나 재시도로 개입이 늘지 않게 동시성·중간 실패를 확인합니다.

개입 제안은 관찰 입력을 앞서 가르치지 않게 하고 미선택은 null입니다. 초안 변경률은 draft_modified=true/IS NOT NULL이며 원문 수정량·교육 품질과 다릅니다. 교실 행위와 회고의 ‘통했다’ 판단은 별개입니다. 수업 기준시각과 확정 시각을 혼동하지 않습니다.

#### U4 섀도 비교와 활성 정책

활성은 결정론, 후보는 골랐을 선택을 적는 섀도입니다. 활성 결과 동일성과 policy_ver 변경은 따로 확인합니다. 배정 확률의 겹침이 없으면 IPS/IPW 인과 추정을 하지 않습니다. 후보 활성·탐색 재개는 D4의 사람 판단 범위입니다. 비교 표본이 적다는 이유로 무단 탐색을 켜지 않으며 후보 준비를 두 시즌 날짜까지 일괄 막지 않습니다.

#### U5 강사 회고와 학생 사실 한 줄

학생 응답 기회 뒤 강사가 판단하고 기계 대조 표는 판단을 대신하지 않습니다. 미응답 null로 진행할 수 있습니다. 강사 verdict·통한 개입·실현과 원 사건을 따로 보존합니다.

학생에게 주는 지난 시즌 사실은 원 사건에서 검증하고 강사의 개입 선택만으로 ‘많았어’ 같은 빈도 주장을 만들지 않습니다. 미측·회색 자료는 학생 효과 문장으로 올리지 않습니다. 시즌 한정·타인 비교/유형 낙인/재촉 없이 Vellum의 해당 자리로 전달합니다.

#### U6 답장 품질과 후행 대조

같은 원문·맥락의 대안 답장을 비교하고 원문 단위 독립성을 지킵니다. 좋은 답 30개×나쁜 답 30개를 독립 900쌍으로 세지 않습니다. 교정 답장과 관찰 구조화의 평가 자격을 나누며 심판이 한국어·초급 도움에서 유효한지 확인합니다. 특정 0.5B 모델·설치 도구·고정 60건은 필수 경로가 아닙니다. 심판 점수는 학생 사실·학습 효과가 아니며 자격이 부족하면 미검증으로 남깁니다.

#### U7 자료가 제안하는 다음 정책

개입 건수와 별도로 독립 관측·학생 수·관측된 개입 갈래를 확인하고 동일 후행 관측을 공유한 개입은 묶습니다. 표본 조건을 충족한 셀에서만 후보를 만들며 없으면 없다고 표시합니다. 후보의 저장·재계산 방법은 목적·계보를 갖춰 발전시킬 수 있습니다. 실학생에게 무단 자동 활성하거나 시뮬레이션을 실제 효과로 섞지 않습니다. 이월효과·짧은 비교 창·선택 편향을 판단에 남깁니다.

## §10. SYNK Reed — 소리와 방송의 경험

정본: [Reed 설계](Reed_설계_v0.1.md), [라디오24 설계](라디오24_설계.md). 음악·장면에 머무는 쓸모로 평가하며 모든 소리를 개인 학습 수집에 종속시키지 않습니다.

앱 재생기·개인 청취 수집·곡 사이 개인 오답은 접었습니다. Suno 곡·결별 블록 편성과 최근 연속 디코딩·실시간 배경/눈 반응 송출은 현재 정본에서 확인합니다. [라디오 생동 완료보고](_ops/라디오생동_20260909/v2/완료보고.md)는 당시 28분 21초 FLAC PCM 연속 디코딩으로 반복 틈을 고친 증거입니다. 1시간 팩·-c copy·최장 6분·판정 전 변경 불가를 현재 제한으로 유지하지 않습니다.

#### U1 실제 재생한 곡과 관측 연결

프로세스 시작·재시작 앵커와 실제 적용한 pack_ver/schedule_ver, 목록·길이표·음원 고리를 남깁니다. 최신 파일판을 실행 중인 판으로 대신하지 않습니다. broadcast_segment의 겹치지 않는 구간과 봇 재발견을 구분합니다.

heartbeat null을 Number(null)=0으로 바꾸지 않고 앵커/관측 결측을 나눕니다. 곡 관측 단위는 같은 재생 구간의 유효한 시작·끝 쌍이며 heartbeat 행 수로 독립 표본을 늘리지 않습니다. 장시간 경계 오차와 재시작 전후 귀속을 실제 확인합니다.

#### U2 폐기한 앱 자습 재생기

개인 앱 재생기·listen.session은 현행 범위가 아닙니다. 사용자 재승인 없이 구현·수집을 되살리지 않습니다. 외부 방송을 듣는 길과 안내는 유지할 수 있습니다.

#### U3 폐기한 개인 청취 리듬

앱 청취 시간·내 자리 스위치에서 성향·집중띠를 수집하는 경로는 폐기했습니다. 다른 실제 관측·명시 취향의 발전까지 금지하는 뜻은 아닙니다.

곡·장르·블록·자연층·장면이 실제 송출에 적용됐는지 확인합니다. 목록 생성·적용·재시작은 다른 사실입니다. 편성판·음량·이음새·장시간 반복을 같은 출력으로 검수하며 고정 인코더 방식 대신 품질을 기준으로 개선합니다.

#### U5 폐기한 곡 사이 개인 오답

실제 지원하는 라디오·BGM·효과음·가이드 음성을 한 음량 정책으로 조정하고 중복 재생·덕킹·종료 콜백을 확인합니다. 학생 녹음 간섭을 막고 사용자가 그사이 끈 소리를 종료 뒤 되살리지 않습니다. 건너뛴 소리를 몰아 틀지 않습니다. 폐기한 앱 재생 카드·가짜 동료 불빛·개인 listened_s 조건은 제거했습니다.

#### U7 곡 반응과 다음 제작

동시 시청자 시작·끝 차이는 순감소이며 개인 이탈률·체류 효과가 아닙니다. 유입과 이탈의 상쇄 한계를 남깁니다. 지시에 쓸 때 장르·요일·시기·표본 조건·귀 채택을 함께 보고 지시 원문·모델·음원·권리를 잇습니다. 기존 곡을 기본 재료로 쓰고 새 생성·재시도 비용은 승인 범위·실제 상한을 따릅니다.

#### U8 재생·품질·변경의 증거

봇 실행·앵커·곡 귀속·음원 실재·이음새·음량·실제 송출을 구분합니다. 점수는 엔진·평가 종류·시험판으로 선택합니다. 모델·가격·편성 개선은 현재 쓰는 도구를 대상으로 확인하고 폐기한 Lyria 정찰·고정 주 4벌·옛 재심 가격을 의무로 남기지 않습니다.

2. 첫 개입·송출 전: 선택판·측정판·두 기준시각·멱등키·실제 재생판처럼 소급 불가한 값을 남깁니다.
3. 첫 소비 전: 권한·조회·변환·화면까지 연결하고 실패·빈 값·재시도를 확인합니다. 이미 있는 경로 개선을 전체 계약판까지 막지 않습니다.
4. 실제 분석 전: 가설·비교 범위·분모·제외·개발/평가 분할을 기록합니다. 사후 변경은 표시합니다.
5. 새 이용·외부 전달 전: 해당 동의·비식별·접근권한·철회와 예산을 확인합니다.
6. 효과 주장 전: 실제 수신·노출·후행 기회·학생 경험과 측정의 타당성을 확인합니다.

옛 20걸음·12월 날짜·고정 심문 회차는 [당시 순서](https://github.com/unmet23-lab/synk-appsscript/blob/f657502b1c85ce7a74b345029ea581fb32e92d14/docs/엔진7종_상향설계_v3.md#L5934)에 보존합니다. 현재 요청의 권한과 선행 조건을 그 일정으로 다시 잠그지 않습니다.

## §12. D 결정과 남아 있는 계약

D1~D29는 09-05 채택과 이후 정정을 찾는 식별자입니다. 이미 채택된 방향을 다시 승인 대기로 만들지 않습니다. 최신 사용자 지시·현재 정본이 우선하며 실제 지출·새 이용 동의·외부 발급 등 별도로 남은 판단은 그 구체 실행 범위만 확인합니다. 구현·배포 상태는 실제 파일과 운영 증거로 확인합니다.

### D1 계약 개정

(질문 키 `D_contract`)

어휘와 생산자·소비자를 함께 반영하는 방향은 채택됐습니다. 최초 관측 때만 남길 수 있는 필드, 기존 CHECK·파서·SCHEMA_VER·X-Contract-Ver·마이그레이션과 두 저장소 동기를 확인합니다. c17이라는 설계판이 현재 실배포판이라는 뜻은 아닙니다. 아래 부록은 필드·그릇 검토 목록이며 실제 허용 값은 계약 파일을 따릅니다.

**D1 별항 · 이용 동의** (질문 키 `D_consent`)

SYNK의 다른 앱에서 학습 기록을 이어 쓰는 목적과 진로 결과 비식별 집계 목적을 구분해 동의에 반영하는 방향은 채택됐습니다. 처음 실제로 이용하기 전에 해당 목적·대상·보관·철회 범위를 확인합니다. 과거 동의를 새 목적에 소급 적용하지 않으며, 이미 생긴 자료에 허락이 없으면 필요한 동의를 먼저 받습니다. 문구의 법적 충분성이나 실제 동의 수납은 이 문서 정리로 확인되지 않았습니다. ‘새 동의 항목 0’ 같은 보편 금지는 유지하지 않습니다.

### D2 앱 라디오

(질문 키 `D_radio`)

앱 재생기·listen.session·개인 청취 수집은 접었습니다. 외부 방송·소리 경험은 Reed 정본을 따릅니다.

### D3 만짐 생산자

(질문 키 `D_touch`)

화면 사건 통로가 세션 봉투를 쓰고 캐릭터 부품은 DB 쓰기를 맡지 않습니다. 실제 0/미관측과 전송 ACK·멱등성을 구분합니다.

### D4 정책과 섀도

(질문 키 `D_feedback`)

활성 결정론·후보 섀도·탐색 바닥 0%가 현재 선택입니다. 정책 활성은 사람 판단 범위이며 비교 부족 같은 재검토 사유는 무단 활성 허가가 아닙니다. 현재 요청의 코드·배포 권한을 모든 커밋 자동 라이브로 확대하지 않습니다. 후보 준비·방법 개선을 고정 날짜로 막지 않습니다.

### D5 동반자 발화

(질문 키 `D_voice`)

실제 근거·자리·노출 예산을 가진 발화와 S26 선택형을 유지합니다. 옛 슬롯 수를 전체 발화의 고정 상한으로 쓰지 않고 현재 세층합류·캐릭터·앱 정본을 따릅니다. 공개 안내와 개인 학습 대화의 데이터 경계는 다릅니다.

### D6 목표와 강사 관찰·개입

(질문 키 `D_teacher`)

학생 앱과 강사 전달을 함께 여는 목표 통로(ⓐ+ⓓ), 엔진 추천 목표의 원산 분리, 손 카드 셋의 방향은 채택됐습니다. 관찰은 사람이 먼저, AI 구조화 뒤 확인입니다. 화용 행동 표식뿐 아니라 실제 기회·예상 행동·반응·출처가 있어야 분모가 됩니다.

### D7 산문·제외·성장

(질문 키 `D_atlas`)

atlas_summary는 학생판/강사판 파생 캐시이며 기본 시효 두 시즌입니다. 개입 참조판 보존과 현재 반영 제외를 함께 처리합니다. 빛은 실제 과제 생성에 사용한 goal_used에 근거합니다. 학생의 부정으로 원관측을 조작하지 않고 해석·재사용에서 제외하며 개인정보 삭제·철회는 별도 우선 계약입니다.

### D8 방송 편성

(질문 키 `D_reed`)

후속 승인으로 발전한 현재 라디오24·Reed 정본을 따릅니다. 1시간 반복·기존 인코더·개인 낱말의 옛 선택지를 다시 묻지 않습니다. 실제 송출·이음새·반응으로 개선합니다.

### D9 Patina

(질문 키 `D_patina`)

명목적 흔적을 허용하되 실제 화면에서 우열로 읽히면 고칩니다. 근거·기준시각·출력판을 보존하고 학생 접점 전 나란히 비교합니다.

### D10 Trail의 자기 것·내부 것·외부 발급

(질문 키 `D_trail`)

본인 기록과 담당 강사의 허용 자료는 열고 남의 결과 집계는 내부에서만 씁니다. 초기 최소 셀 n=5와 동의·확인 등급을 지킵니다. 서명 파일의 실제 외부 발급·미성년 복구는 해당 시점의 구체 판단을 남깁니다. 사전 설계·로컬 검증까지 금지하지 않습니다.

### D11 Prism 관측과 발음

(질문 키 `D_prism`)

계약·계측·집계·조준 배선은 실제 자료를 쓰기 전에 준비합니다. 미검증 발음 라벨·집단 원인·효과를 학생 사실로 내지 않습니다. 새 발음 반출 제한과 승인된 기존 전사 통로를 가릅니다. 검증된 자료로 태그·상수·방법을 발전시킬 수 있습니다.

### D12 성과의 정의

(질문 키 `D_plan`)

겨냥 태그 재출현/기회, 대체 제출 지표, 도움 뒤 독립 수행을 구분합니다. 기준선·30일 창·누락 처리·독립 표본·측정판을 남깁니다. 초기 하한 30·회색 3·기준선 14일 등은 해당 측정 설계값이며 모든 기능의 영구 문턱이 아닙니다. 변경하면 판·비교 범위를 갱신합니다.

### D13 실험 비용과 권한

(질문 키 `D_money`)

승인 작업과 AI 운영 원칙 안에서 기존 계정·크레딧·도구를 활용합니다. 일회 실험·재시도 포함 상한, 상시 학생당 비용(D28), 신규 결제·구독·자동충전은 별개입니다. 옛 예시 달러·모델 등급을 실제 승인 예산으로 쓰지 않습니다. 예산 편의로 약속한 무료 케어를 취소하지 않습니다.

### D14 모델과 실행 통로

(질문 키 `D_model`)

현행 모델 정책·실제 계정의 공식 경로·과업 품질·비용을 사용합니다. 특정 모델 판·모델별 클릭·고정 심문 순서가 기술 선택을 막지 않습니다. 설정 파일과 실제 실행 모델·배포판 차이를 확인합니다.

### D15 실제 자료 평가분

(질문 키 `D_redaction`)

promote와 평가 목적 동의, 비식별 본문, 비공개 저장, 계보별 개발/최종 평가 분리를 지킵니다. 내부 저장 허가를 외부 평가·훈련·공개 허가로 바꾸지 않습니다. 실행 직전 동의와 철회를 재확인합니다.

### D16 몽골어 검수

(질문 키 `D_mn`)

대상·채널·위험에 따른 현행 철학 적용 기준을 따릅니다. 개인 이해·약속·평가를 기계 번역 품질만으로 내보내지 않습니다. 무료 자체 채널의 미검수 표시 허용을 유료 광고·민감 문안에 확대하지 않습니다. 옛 10~11월·발주 두 번을 독점 일정으로 남기지 않습니다.

### D17 실제로 필요한 사람 행동

(질문 키 `D_hands`)

필요한 본인 인증·새 지출·키 관리·귀와 판단은 실제 남은 항목만 확인합니다. 기존 로그인·도구 설정·읽기·준비는 직접 수행합니다. 끝난 토큰 연장·설치 클릭·옛 모델 라벨 작업을 반복시키지 않습니다.

### D18 정본 최신화

(질문 키 `D_canon`)

철학 v2·현재 실행·출력에 맞춰 문서를 갱신합니다. 다음 판까지 동결하거나 중복 보관 사본을 만들지 않습니다. 과거는 고정 Git판을 사용합니다.

### D19 제품의 목적

(질문 키 `D_goal_v2`)

현재 사람 중심 목적을 유지하면서 도움·재미·신선함·실제 수신자 변화를 확인합니다. AI 사용량·엔진 완성 개수가 제품 목표를 대신하지 않습니다.

### D20 사람 판단의 자리

(질문 키 `D_hands_count`)

사람이 목표·의미를 판단하고 AI가 정리·제안합니다. 한 클릭은 판단 품질의 기준이 아닙니다. 원문·초안·수정·기각을 검토할 수 있게 하되 매일 교정·인사까지 강사 승인으로 막지 않습니다. 내부 분석·자기 과거 비교·학생 타인 비교를 구분합니다.

### D21 성적 확인과 대외 주장

(질문 키 `D_verify`)

확인된 시험 사실과 제보·예상·미확인을 구분합니다. 문서 유효성·진위확인의 현재 공식 기준은 실제 확인·대외 사용 시 대조합니다. 보장·케어 판단과 외부 통계의 분모는 Trail U5를 따릅니다.

### D22 초급 과제와 실패 시 수업 지속

(질문 키 `D_beginner`)

초급 생성·예비 과제·시트 재출제에도 최초 개입부터 같은 출처·선택판·도움 여부를 남깁니다. 지연·실패에는 안내와 사용 가능한 과제로 이어지게 합니다. 예비 과제 뒤 늦게 끝난 생성은 두 번째 배정으로 보내지 않고 같은 개입·멱등키로 처리합니다.

### D23 리허설과 실제 학생

(질문 키 `D_pilot`)

합성 학생·강사 리허설은 기능 검증이며 실제 효과·감시감의 분모가 아닙니다. 옛 12월 일정은 역사입니다. 실제 자료 유입은 현재 운영 일정·최초 사건으로 확인하고 개원 전 판매가 앞설 수 있음을 반영합니다.

### D24 녹음과 움직임

(질문 키 `D_listening`)

녹음 간섭·성능·접근성은 실제 기기에서 검증합니다. 특정 애니메이션 기술·3D 전체를 금지하지 않습니다. 정지·reducedMotion·소리 옵트인·재개는 Loom 기준을 따릅니다.

### D25 리포트 전달

(질문 키 `D_report_event`)

별도 report.delivered를 사용하는 방향입니다. intervention_id·recipe_ver·loom_ver와 delivery_channel·confirm_kind·report_ver로 생성/발송/열람/실물 전달을 구분합니다. confirm_kind는 AI 판단의 사람 확인과 다릅니다.

### D26 시각 생성의 경계

(질문 키 `D_roomeye`)

승인 참조·정체성·권리·현재 도구 조건을 따릅니다. 옛 무료 티어 약관·모델명을 현재 사실로 고정하지 않고 실제 사용자 선택·품질을 검증합니다.

### D27 무대와 입체 표현

(질문 키 `D_stage`)

소품·접지·그림자·공유 동작의 발전을 유지합니다. 현재 2.5D와 실제 3D 실험을 구분하고 애니메이션 지원 Loom 결과의 기본 방식은 최신 표현 기준을 따릅니다.

### D28 학생당 상시 비용

(질문 키 `D_money_per_student`)

추가 AI 비용과 전체 운영비를 구분합니다. deliver·companion·요약·원인 분석·강사 가이드·일기 응답의 실제 사용량·재시도·모델별 단가로 잽니다. 분모는 재원뿐 아니라 무료 체험·졸업 뒤 케어 등 실제 서비스 이용 학생입니다. 옛 달러 추산은 확정 예산이 아닙니다. 상한 대응에서도 과제 흐름·약속한 케어를 유지합니다.

### D29 학생 일기의 자리

(질문 키 `D_diary_place`)

책상 위 일기장(B)과 과제 종료 직후 바로 가는 손잡이 방향이 채택됐습니다. 쓰는 곳·다시 보는 곳을 잇고 과제 흐름을 막지 않습니다. 현행 동선·계약은 학생 일기 정본을 따릅니다.

## §13. 폐기·완료 이력

끝난 후보·교정 서사·모델 심문 횟수·옛 일정은 현재 지침에서 삭제했습니다. 당시 사유가 필요하면 [정리 전 §13](https://github.com/unmet23-lab/synk-appsscript/blob/f657502b1c85ce7a74b345029ea581fb32e92d14/docs/엔진7종_상향설계_v3.md#L6963)을 확인합니다. 폐기한 앱 개인 청취나 승인되지 않은 학생 데이터 이용은 다른 기술의 발전 허용으로 되살리지 않습니다.

## §14. 확인할 결과

## §15. 기술과 조사를 다시 여는 기준

과거 기각한 모델·도구·저장·출력 기술은 현재 필요와 달라진 근거로 다시 검토할 수 있습니다. 당시 가격·지원·벤더 단점은 영구 금지의 근거가 아닙니다. 비교 입력과 성공 조건을 정해 실제 출력으로 확인하고 현재 정본을 갱신합니다.

[정리 전 조사](https://github.com/unmet23-lab/synk-appsscript/blob/f657502b1c85ce7a74b345029ea581fb32e92d14/docs/엔진7종_상향설계_v3.md#L7472)의 후보를 정해진 날짜에 자동 실행할 의무는 없습니다. 새 기술도 동의·대외 주장·예산 경계를 대신 통과시키지는 않습니다.

## §16. 남아 있는 실패 가능성

### 대가 ① — 실제 경험과 자료가 비는 경우

생성·네트워크·예산·배치 실패에도 과제를 받고 제출하는 길이 필요합니다. 예비 과제 배정 뒤 늦은 생성은 두 번째 배정으로 보내지 않고 같은 개입·멱등키로 처리합니다. 오프라인 사건 봉투와 오디오 파일 자체의 보존·재전송을 따로 확인합니다. 최초 실학생·개입은 실제 사건으로 판정합니다.

### 대가 ② — 잘못된 측정으로 초록이 되는 경우

대상 일부만 읽음·null→0·조회 상한·판 혼합·늦은 자료 누출·중복 교정/후행 관측은 거짓 성공을 만듭니다. 실제 데이터 경로의 긍정/부정 입력과 실패 처리를 확인하고 권한이 없으면 미확인으로 남깁니다. 새 강제 훅·검문 체계를 늘리는 것으로 대신하지 않습니다.

### 대가 ③ — 도움이 감시처럼 느껴지는 경우

나를 아는 말·만짐 흔적·강사 카드가 낙인·재촉·비교로 읽힐 수 있습니다. 실제 몽골어 문안과 학생 경험에서 확인합니다. 유호님 눈 검수와 합성 리허설은 학생 관계 판단이 아닙니다. 반영 제외를 첫 사용부터 제공하고, 제외 전 자료로 시작한 생성이 늦게 완료돼도 캐시·질문·답장·과제에 그 근거를 되살리지 않습니다.

### 세 문제가 서로 숨기는 경우

감시감→무응답→응답자만 남음→동의율 상승이 함께 일어날 수 있습니다. 동의율과 실제 노출/전체 대상·응답/노출을 함께 봅니다. 당시 대상 집합의 규칙판·기준시각·구성원 고리·분모를 남겨 미노출 대상이 사후에 사라지지 않게 합니다. 해시만으로 필요한 재현이 가능한지도 설계에서 확인합니다.

문서 정리는 실제 학생 자료 조회·배포·학습 효과 검증이 아닙니다. 각 U의 현재 구현은 담당 정본·계약·코드로 확인하고 그 요청 범위의 시험·통합·증거까지 완료합니다.
