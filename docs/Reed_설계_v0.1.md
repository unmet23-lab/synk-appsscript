# Reed — 음악·소리 엔진 설계

> 현행 코드·문서 대조 · 2026-10-08. 곡 선택·편성·소리 규격·다음 제작에 돌아오는 근거를 맡는다. 파일명의 v0.1은 기존 참조를 위해 유지한다. 여덟 엔진의 역할과 Atlas 연결은 [엔진 상향 설계](엔진8종_상향설계_v3.md), 목적과 데이터 경계는 [SYNK 철학](SYNK_철학.md)을 따른다.

## 0. 맡은 결과

Reed는 승인된 곡이 늘어날수록 감상 경험과 편성이 좋아지게 한다. 곡을 고르고 사용 판·음량·이음새를 관리하며, 방송·앱·작품의 목적에 맞는 소리를 연결한다. 음악과 감상 자체가 결과다. 학생 이해를 수집하지 않는다는 이유로 미완으로 세지 않는다.

- **현재 라디오 곡:** 09-08 확정에 따라 유호님이 제공한 Suno 승인곡을 쓴다. 후보·사용 원본은 [음악 자산 장부](음악자산_장부.md), 실제 방송 판은 [라디오24](라디오24_설계.md)의 적용 결과에서 확인한다.
- **현재 앱 경계:** 09-06 확정대로 앱 안 자습 재생기·개인 청취 수집은 접고 유튜브 라디오 링크·안내를 둔다. 곡 수나 학생 수가 늘었다는 이유만으로 개인 청취 수집을 자동 재개하지 않는다.
- **현재 시각 표현:** 움직임을 지원하는 Reed 결과물의 Loom 장면은 [움직임 지원 매체 기준](Loom_실시간장면_표현기준.md)을 적용한다. 라디오의 무언 DJ 선택을 다른 모든 음악·작품의 말소리 금지로 확대하지 않는다.
- **마지막 승인 결과:** 10-05의 [한옥 마당 복원·22곡 재개명](라디오/배경제목재수정_20261005/README.md)을 따른다. 같은 날 앞선 반딧불 들판과 첫 제목안은 사용자가 거절한 판이다. 이 기록은 당시 공개 확인이며 현재 수신·청취 증거는 아니다.
- **삭제한 경로:** 10-03 라디오 퀴즈·수집·학습 승격과 `라디오계기.js`를 제거했다. 음악 순서·송출·현재 곡 표시·화면 인사는 남아 있다. 개인 학습이나 집단 퀴즈 분석을 음악의 필수 기능으로 복원하지 않는다.

## 1. 곡과 판의 원천

| 관리할 것 | 필요한 내용 |
|---|---|
| 원본·선택 | 곡 식별자, 실제 원본, 장르·결, 후보·채택·은퇴 상태와 선택 근거 |
| 사용 판 | 편집·믹싱·규격화에 쓴 도구와 설정, 출력 경로, 원본과의 관계 |
| 소리 | 실제 길이·음량·피크·무음·이음새와 청취 결과 |
| 사용처 | 방송·앱·작품 중 어디에 어느 판을 적용했는가 |
| 제작 근거 | 다음 곡·편성을 바꾼 사용자 피드백과 관측 범위 |

생성 원본을 다시 똑같이 만들 수 없어도 원본 파일을 보존하면 편집·재출력은 가능하다. 재현 가능 범위를 적고, 재생성 불가를 곡 사용 금지나 수정 불가로 바꾸지 않는다. 별도 장부를 늘리지 않고 현재 장부와 제작 결과를 연결한다.

## 2. 엔진의 경계

| Reed가 맡는 것 | 연결하는 담당 |
|---|---|
| 곡 장부·편성·출력 판·소리 규격 | 생성 도구와 기존 제작 코드 |
| 작품·장면에 맞는 음악과 효과음 사용 | Loom 장면, Vellum 반응, 해당 제품의 소리 통로 |
| 집단 감상·운영 관측의 해석 | 라디오 수집·계기와 실제 청취 결과 |

캐릭터 성격·표정 원본은 [가이드 정본](캐릭터/가이드_정본.md), 송출·오버레이·채팅·복구는 [라디오24](라디오24_설계.md), 앱 녹음 중 무음과 오디오 우선순위는 앱 계약을 따른다. 모델·생성 도구는 [AI 운영 원칙](AI_운영원칙.md)에 따라 품질과 현재 통로로 선택한다. 과거 합성곡 개선 순서·모델 출시 대기를 새 곡 제작의 선행 조건으로 두지 않는다.

## 3. 편성

현재 승인된 곡 목록을 같은 결끼리 묶어 듣고, 블록 안에서는 밝기·음량이 갑자기 튀지 않게 잇는다. 09-08 실제 편성 결정은 차분 → 시티팝 → 전자 순의 묶음과 블록 안 어두움 → 밝음이었다. 실제 사용하는 목록과 생성기를 함께 확인하며 다른 장르 구성에 아홉 곡의 개수·비율을 복사하지 않는다.

곡 순서 원천은 SYNK-talk `lib/라디오곡차례.js`와 해당 방송 팩 제작 코드다. 곡 편성은 퀴즈·수집 의존성이 없는 순수 모듈이며, 삭제한 퀴즈용 `lib/라디오편성.js`를 요구하지 않는다. 현재 곡과 최종 제목은 실제 팩의 목록·시간표에서 확인한다. 시간대·장르·무대 전환이 개선되면 실제 재생으로 확인하고 해당 원천을 고친다. 모든 방송에 특정 다섯 시간대나 DJ 교대 횟수를 강제하지 않는다.

### 3-B. 반복과 곡 길이

반복 체감은 곡 길이·풀 크기·블록 순서·편집·감상 시간의 조합으로 확인한다. 옛 ‘방송곡은 모두 6분 이상’은 30곡 풀과 3시간 자습을 가정한 산수였으며 현재 승인된 짧은 Suno 곡과 실제 방송을 막는 고정 조건으로 사용하지 않는다. 자연음은 음악과 분리해 필요한 장면에서 조절하고 원곡을 덮거나 피로를 늘리지 않는지 듣는다.

## 4. 출력 품질

- 곡 간 음량·피크가 튀지 않고 의도하지 않은 무음·클릭·반복 경계 틈이 없어야 한다.
- 밝기·리듬·자연음 변화는 장면과 감상 목적에 맞게 잇는다. 모든 장르에 하나의 수치 목표를 강제하지 않는다.
- 신호 분석과 청취를 구분한다. 디코딩·파형 검사 통과만으로 편안함이나 작품성을 단정하지 않는다.
- 출력 방식은 현재 결과에 맞게 선택한다. 09-09 방송의 반복 틈은 원곡 PCM을 FLAC으로 보존하고 연속 디코딩하는 방식으로 수정했다. 옛 `-c copy` 전용 규칙이나 1시간 팩 고정은 현재 구현의 변경을 막는 규칙이 아니다.

## 5. 다음 제작에 돌아오는 근거

현재 사용 가능한 근거는 실제 송출 진척·장애/재시작 로그·공개 수신과 사용자 청취 피드백이다. 옛 heartbeat 원장·곡별 집단 분석 계산기는 삭제되어 현재 자동 집계 경로로 안내하지 않는다. 새로운 집단 관측을 도입한다면 목적·분모·구간·누락·허용 수신자를 먼저 정하고 `null`과 0명, 조용한 채팅과 관측 실패를 구분한다. 앱 개인 청취 시간·집중·감정·성향을 수집하거나 Core·Trail에 넘기는 계획은 현재 범위에 없다.

### 5-B. 해석의 한계

동시 시청자 변화는 개인의 체류·선호나 곡의 인과 효과를 증명하지 않는다. 유입·시간대·방송 장애·표본 크기를 함께 보며, 관측 횟수만으로 통계적 확실성을 선언하지 않는다. 근거가 부족하면 사용자 청취 피드백과 운영 사실을 남기고 추정은 추정으로 둔다. 지표 수집을 감상 작품의 공통 의무로 만들지 않는다.

## 6. 현재 실행 경로

| 대상 | 원천·증거 |
|---|---|
| 곡·사용 판 | [음악 자산 장부](음악자산_장부.md), 해당 팩 제작 결과 |
| 음악 순서·목록 생성 | SYNK-talk [라디오곡차례.js](../../SYNK-talk/lib/라디오곡차례.js)·[재생목록.js](../../SYNK-talk/bots/송출/재생목록.js) |
| 출력 진척·정체·복구 | [송출진척.js](../bots/오버레이/송출진척.js)·[겹쳐송출.js](../bots/오버레이/겹쳐송출.js) — 인코더 출력 시간과 서버 로그 |
| 방송·시각·소리 실제 반영 | [라디오24](라디오24_설계.md), [10-05 최종 복원·제목](라디오/배경제목재수정_20261005/README.md), [10-05 음원 복구](라디오/송출복구_20261005/README.md) |
| 소리·장면의 확장 계약 | [엔진 상향 설계](엔진8종_상향설계_v3.md)의 Reed |

곡 제목은 [현재곡.js](../bots/오버레이/현재곡.js)가 실제 인코더의 `out_time`으로 선택하고 [겹쳐송출.js](../bots/오버레이/겹쳐송출.js)가 오버레이에 전달한다. 브라우저 평가 호출이 반환되어도 `exceptionDetails`가 있으면 미전달로 두고 재시도한다. 시간표의 비유한 길이·잘못된 시각도 표시 전에 거절한다. [회귀 시험](../tests/현재곡.test.js)은 이 로컬 전달 경계를 확인하며, 실제 방송 수신·청취나 현재 라이브 정상 상태를 입증하지 않는다(2026-10-02).

## 7. 이어서 발전시키는 법

새 요청의 목적과 현재 승인 원본·실행 코드를 비교해 필요한 곡·편성·장면을 수정하고 실제 출력까지 확인한다. 끝난 이름 선정·장부 신설·합성곡 네 단계 개선을 다시 기다리지 않는다. 남은 운영·청취 확인은 [트랙](_ops/트랙.md)의 라디오 항목에서 찾는다. 10-05 공개 확인도 당시 증거이며 오늘의 정상 동작이나 장시간 무중단을 보장하지 않는다. 10-08은 로컬 회귀와 원문 대조만 수행했으며 새 송출·음원 변경·공개 청취 검증을 하지 않았다.

과거 산수·최초 제안과 판정 경위는 [정리 전 Git 판](https://github.com/unmet23-lab/synk-appsscript/blob/f657502b1c85/docs/Reed_%EC%84%A4%EA%B3%84_v0.1.md)에 있다.
