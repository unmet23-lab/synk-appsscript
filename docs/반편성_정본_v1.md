> 작성 2026-07-12 · **class_name(반 이름)의 단일 기준.** 상담데이터 입력시트·적성검사지·앱 프로필(profiles)·수업표가 전부 이 표를 따른다.
> 근거: 유호님 운영 계획(2026-07-12) — 평일 강사 3명(정규 담당 1 + 집중 담당 2), 주말 시간제. 코드는 v8.3에서 이미 이 15반 체계로 정합됨.

---

## ⓪ class_name 입력 규칙 (핵심 — 조잡함의 원인 제거)

- **class_name = 반 이름만.** 예: `정규반1`, `집중반3`, `주말정규반2`.
- **강사 이름·학생 이름을 붙이지 않는다.** ❌ `인우쌤(정규반1)` · `양유호(정규반1)` → ✅ `정규반1`
  - 이유: 앱 데이터(profiles)는 `이름`(2번 열)과 `class_name`(5번 열)이 **이미 별도 필드**다. 반 이름 칸에 사람 이름을 또 넣으면 중복·조잡. 코드도 반 이름만 기대한다(강사 이름을 붙이는 로직 없음 — 붙은 값은 전부 수동 입력).
  - 강사↔반은 아래 표처럼 **고정 매핑**이라 데이터에 강사 이름을 넣을 필요가 없다. 화면에 담당 강사를 보여주고 싶으면 표시할 때만 이 표를 참조해 붙인다.
- **번호는 신 체계만.** 구 번호(정규반5·8·10 등)는 폐기. 아래 15반 외의 이름은 쓰지 않는다.

## ② 코드 정합 (이미 반영됨 — 확인용)

Code.js v8.3에서 이 체계로 정합 완료. 확인된 동작:
- **트랙 판정**: class_name 문자열에서 `집중반` 포함 → 소수(정원 10) / `주말정규반` → 20 / `정규반1~4` → 20 / `주말집중반` → 10.
- **보스 HP(레이드)**: 정규반 560 · 집중반 280 · 주말정규반 360 · 주말집중반 180.
- 강사 이름을 class_name에 붙이는 로직 **없음**(스크린샷의 "쌤(...)"은 수동 테스트 입력값).

→ **코드는 수정 불필요.** 위 15개 이름만 정확히 쓰면 된다.

## ③ 데이터 정리 (남은 실무)

- **현재 SYNK_앱데이터 시트의 테스트 값**("인우쌤(정규반1)"·"수길형(정규반10)" 등)은 실제 학생이 아니라 샘플 → 실제 학생 등록 시 신 규칙으로 입력하면 자연히 대체됨. 지금 급히 고칠 필요 없음(원하면 그 6행만 위 이름으로 교체).
- **실제 학생의 class_name은 상담데이터 입력시트 → profiles 동기화로 채워진다.** 그러니 상담시트의 반 배정 칸에 위 15개 이름만(강사·학생 이름 없이) 넣으면 앱까지 깔끔하게 흐른다. 상담시트·적성검사지가 이미 신 체계면 정합 완료, 강사 이름만 안 붙었는지 확인.
