# 숙제 답변 «내용»에서 성향을 뽑는 통로 — 설계 정본 v1.0

## §0. 한 장면

바트가 숙제에 이렇게 쓴다 — 「주말에는 친구를 안 만나요. **저는 혼자 있을 때가 편해요.**」
지금 엔진은 이 문장에서 문법 오류만 본다. 「-을 때」를 맞게 썼는지는 알지만,
바트가 방금 **자기 이야기를 했다는 것**은 어디에도 안 남는다.
이 설계가 서면: 그 문장이 관찰 사건이 되고 → 다음 «오늘의 확인»이 바트에게 묻는다
「바트야, 혼자 보내는 시간이 편하다고 했지 — 맞아?」 → 바트가 「맞아」를 누르면
그 성향이 과제 생성의 [학생 상태]로 들어간다. **읽고, 되묻고, 그다음에 쓴다.**

## §1. 원칙 — 철학 정본에 빗댄 다섯 (전부 기존 확정에서 온다)

| # | 원칙 | 근거 |
|---|---|---|
| ① | **학생이 노는 자리에서 저절로** — 새 설문·새 입력 0. 숙제 답변은 이미 있다 | 철학 Ⅰ-3 ㉡ 「재미없는 설문으로 성향을 캐는 것은 우리 방식이 아니다」 |
| ② | **«말한 것»만 뽑는다 · «추정»하지 않는다** — 학생이 명시적으로 쓴 선호·관심·목표·자기서술만. AI가 문면 밖에서 기분·성격을 «짐작»한 것은 버린다 | 철학 Ⅲ-2 「모르는 것에 0을 넣지 않는다」 + §5 최신정보(감정 «추론» 규제·모델 편향 실증) |
| ③ | **증거 없는 항목은 없다** — 모든 관찰에 학생 원문 인용·날짜·출처가 붙는다. 인용을 못 붙이면 그 관찰은 폐기 | Ⅲ-2 둘째(오독은 아이에게 간다) · Ⅰ-9 ③ 실측이 판정한다 |
| ④ | **낙인 금지 — 사람에게 안 붙이고 개입에 찍는다** | 코어엔진 §원칙1 · 현행 스탬프 규율(A-1: deliver 가 상태를 저장 않고 개입 사건에 찍는다) 그대로 텍스트 파생에도 |
| ⑤ | **알아낸 것은 학생에게 돌려주고, 쓰기 전에 되묻는다** | 철학 Ⅱ-8 + **이미 지어 둔 확인축**(c13 `estimate.responded` — 시스템 추정을 학생이 맞다/아니다로 답한다) |

🔑 ⑤가 이 설계의 심장이다. LLM 추출은 틀릴 수 있다(§5) — 그 오류를 막는 가장 강한 장치는
검증 프롬프트가 아니라 **본인 확인**이고, 그 그릇(오늘의확인·부정 재노출 금지·하루 1회)은 08-22에 이미 섰다.
새로 짓는 것은 「그 확인 큐에 후보를 공급하는 통로」 하나다.

## §2. 무엇을 뽑나 — 축 넷 (ⓐ의 답)

전부 「학생이 문면에 명시적으로 쓴 것」만. 예문은 실제 판정 기준이다.

| 축 | 뽑는다 | 안 뽑는다(→버린다) |
|---|---|---|
| **선호** | 「저는 혼자 있을 때가 편해요」 「매운 음식을 좋아해요」 | 「비 오는 날 글이 짧다 → 우울한 듯」(추론) |
| **관심** | 「요즘 웹툰을 그려요」 「BTS 노래로 공부해요」 | 과제 주제를 그대로 되받은 문장(과제가 시킨 말) |
| **목표·꿈** | 「서울에서 디자인을 공부하고 싶어요」 | — (드림한줄과 합류 · §3-사건) |
| **자기서술** | 「저는 아침에 집중이 잘돼요」 「말하기가 제일 어려워요」 | 성격 유형화(「내향적」 같은 라벨 — 우리가 붙이는 순간 낙인) |

**정서는 별도 축으로 두지 않는다.** 학생이 명시적으로 쓴 감정 문장(「요즘 힘들어요」)은
자기서술로 담기되, ⚠ 개인화 «생성 입력»이 아니라 **강사 관찰 후보**(사람이 마음을 만나는 자리 — 철학 Ⅰ-4)로만 흐른다.
까닭 = §5-②: 감정을 다루는 자동 개입은 규제·윤리 양쪽에서 가장 미끄러운 자리고, 우리 철학에서도 그건 시스템이 아니라 사람 몫이다.

## §3. 누가 뽑고, 어떤 사건으로 내나 (ⓑⓒ의 답)

**뽑는 자 = 교정 파이프라인의 AI 가 겸한다**(별도 추출기 ✗).
- 교정 AI(talk `correct`)는 이미 답변 전문을 읽는다 — 같은 호출의 구조화 출력에 `관찰[]` 칸 하나를 더한다.
  **추가 호출 0 · 추가 비용 ≈ 출력 토큰 소량**(항목 없으면 빈 배열 — 대부분의 숙제가 빈 배열일 것이 정상이다).
- ⚠ 겸임의 값: 프롬프트에 일이 늘면 본업(교정 품질)이 흔들릴 수 있다 → 회전 평가에 「교정 품질 무저하」 축을 같이 잰다(§7).

**사건 = `preference.stated` 규격 «확장»**(새 사건 ✗ · c13→c14 판올림).
- 근거: 라디오 채팅발 `preference.stated`(빗소리·asmr)와 숙제 텍스트발 관찰은 **같은 인식 계급**이다 — 「학생이 스스로 말한 것」.
  갈래는 사건 종류가 아니라 `출처` 필드가 진다(관례 = mastery_log 의 출처 열).
- c14 초안(필드 추가만 — 기존 생산자는 그대로 유효):
  ```
  preference.stated {
    축: '선호'|'관심'|'목표'|'자기서술',
    값: <짧은 정규화 문구>,          // 예: "혼자 있는 시간이 편함"
    증거: <학생 원문 문장 그대로>,     // §1-③ — 없으면 검증기가 거절
    출처: 'radio' | 'hw_text',
    확인: '대기'|'맞다'|'아니다',      // §4 확인축 왕복의 착지
    hw_ref: <숙제 제출 id | null>
  }
  ```
- 🔴 **판올림 규율**: c13→c14 는 「계약 판을 올리는 손이 같은 커밋에서 착지판·SCHEMA_VER 를 고친다」 —
  그리고 이번 세션에 세운 **판 대조 가드**(`tools/계약동봉검사.js` 확장 · talk `배포빚.js` 착지판 대조)가 어김을 잡는다.

## §4. 흐름 — 읽고 → 되묻고 → 그다음에 쓴다

```
숙제 제출 → 교정 AI(겸임) → 관찰 후보(증거 포함)
    → 사건 preference.stated(확인:'대기')                 [저장: 사건 원장뿐 — 프로필 저장 ✗]
    → 오늘의확인 큐: 「…라고 했지 — 맞아?」                 [기존 c13 확인축 그릇 그대로 · 하루 1회 · 부정 재노출 금지]
    → 맞다  ⇒ 확인:'맞다' — 그때부터 과제요약 [학생 상태]에 합류(개입 사건에 스탬프 — 저장 ✗)
    → 아니다 ⇒ 확인:'아니다' — 폐기(재노출 금지 목록으로)
    → 무응답 ⇒ '대기' 로 남는다 — 「모르는 것은 모른다고 비워 둔다」(Ⅲ-2)
```
- **확인 전 관찰은 생성에 안 쓴다.** LLM 오추출이 학생에게 닿는 유일한 길목을 본인 확인이 막는다.
- **시효**: 확인된 성향도 마지막 확인에서 두 시즌(≈4달) 지나면 '대기'로 되내린다 —
  「바뀌었다는 사실 자체가 성장의 기록」(철학 Ⅱ-4). 되내림은 삭제가 아니라 재확인 후보 승격이다.
- **돌려주기 화면**(Ⅱ-8 「새 화면을 늘리지 않는다」): 새 지면 0 — ①오늘의확인(이미 있음) ②AI 답장 꼬리 한 줄
  (「네가 웹툰 좋아한다고 했지 — 오늘 과제에 그걸 넣어 봤어」) ③걸어온길 「나의 한 줄」(이번 세션 배선).

## §5. 최신정보 정찰(08-27) — 설계를 바꾼 것 둘, 확인만 한 것 하나

- ① **감정 «추론» 규제가 현실이 됐다** — EU AI Act 5조가 2025-02부터 **교육기관 내 감정 추론 AI를 금지**
  (근거 = 권력 비대칭·학생의 취약성. 몽골·한국은 적용 밖이지만 그 «까닭»은 우리 철학과 같은 방향).
  한국도 **AI 기본법이 2026-01-22 시행** — 고영향 AI 사업자 의무 체계가 섰고, SHIFT(한국 법인·자격 기관)가
  그 관할로 들어간다. ⇒ §2 「정서 축 없음 · 명시 문장도 사람 몫」은 취향이 아니라 이 방향의 선반영이다.
- ② **LLM 학습자 프로파일링의 편향 실증** — 2026 연구(Marked Pedagogies 계열)가 LLM이 학생의 최소 단서
  (이름 등)로 정체성을 «짐작»하고 그 짐작에 따라 태도를 바꾸는 것을 실증했다. ⇒ §1-②③(명시 문장만·증거 강제)
  + §4(본인 확인 전 사용 금지)가 그 처방이다 — 검증을 모델에게 맡기지 않고 학생에게 맡긴다.
- ③ **개인화 자체의 효과는 재확인** — 프로필 기반 재구성 텍스트를 학생이 선호한다는 RCT 계열 근거.
  방향은 맞다 — 우리 루프(성향→[학생 상태]→생성)는 이미 그 구조다. 이 설계는 그 루프의 «재료» 쪽 빈 칸만 채운다.

## §6. 비용 — 돈이 새로 들지 않는 구조

- 추출 호출 0(교정 겸임) · 확인 화면 0(기존 그릇) · 생성 합류 0(기존 [학생 상태] 통로).
- 순증 = 교정 출력 토큰 소량 + c14 판올림 손. **캐싱 트랙(개원 전)과 독립** — 프롬프트 순서를 안 만진다.

## §7. 남은 것 — 구현 순서는 유호님 판정 자리

⚠ 트랙이 못박은 대로 **「지금 트랙(§8-B 4회전)과 어느 쪽이 먼저인가」는 유호님 몫**이다.
제 추천 = **4회전(⑥정확성) 먼저, 이 통로는 그 다음** — 같은 파이프라인(교정·생성 프롬프트)을 두 손이
동시에 만지면 4회전 결과가 「규칙이 올렸나 추출이 흔들었나」로 흐려진다(캐싱을 미룬 것과 같은 까닭).

구현 조각(순서대로 · 전부 talk 쪽): ①c14 판올림(계약+검증기+착지판 — 가드 동행) ②교정 구조화 출력에
관찰[] 칸 ③오늘의확인 공급기(hw_text 갈래) ④과제요약 합류(확인:'맞다'만) ⑤평가 축 — 회전 채점표에
「교정 품질 무저하」 + 「관찰 정밀도(증거 인용이 실제 원문인가)」 둘.

## 못 재본 것 (정직하게)
- 관찰 항목의 실제 발생률(숙제 100건당 몇 건인가) — 실학생 0. 첫 달 실측으로 §2 기준을 조인다.
- 교정 겸임이 교정 품질을 실제로 깎는가 — ⑤축이 재기 전까지 가설.
- 몽골어 답변(키릴)에서의 추출 품질 — 맥락표본 C02 계열로 회전 때 같이 잰다.
