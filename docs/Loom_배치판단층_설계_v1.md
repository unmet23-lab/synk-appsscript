# Loom — 배치 판단층과 현재 조판 통로

2026-09-13 · 구현은 [룸조판.js](../tools/룸조판.js), 검사는 [룸조판.test.js](../tests/룸조판.test.js)다. 옛 구상·순서는 [정리 전 원문](https://github.com/unmet23-lab/synk-appsscript/blob/8b80a507168d/docs/Loom_배치판단층_설계_v1.md)에 남긴다.

## 0. 목적

원고의 제목·목록·인용·표와 배치 의도를 읽어 재현 가능한 문서 지면을 만든다. 모든 매체의 디자인 판단을 자동화한 도구는 아니다.

## 1. 층 위치

L4 지면과 L5 기존 점검 사이의 L4.5다. 재질·간격은 Loom, HTML 골격은 `펠트문서.js`, 대비는 `룸잉크.js`, 사용 확인은 `loom훅.js`, 관리 지면은 `지면방.js`가 담당한다.

## 2. 현재 동작

요청에 맞는 형식·출력 위치를 원고 머리말 또는 CLI에 기록하고 마크다운을 블록으로 바꾼다. 지원 힌트로 배치한 뒤 원고 구조·누락·대비·자립형 출력을 검사하고 필요한 등록과 산출물을 만든다.

사용자가 형식을 생략했어도 맥락에서 합리적으로 선택할 수 있으면 진행한다. CLI가 형식·출력 경로 누락을 오류로 내는 것은 호출자가 인자를 채워야 하는 계약이며 사용자 재승인 조건이 아니다.

```powershell
node tools/룸조판.js --규격
node tools/룸조판.js docs/_원고/원고.md --지면 문서 --내놔 docs/완성.html
node tools/룸조판.js --재현
```

예시 경로는 실제 작업 파일로 바꾼다. `--등재안함`은 기존 일회성 출력 옵션이다. 관리 산출물 여부와 기존 등록 계약을 따른다.

## 3. 덱과 다른 형식

현재 `규격들`의 구현은 `문서`다. 덱16x9·캐러셀·인쇄A4의 미구현 표시는 이 변환기의 지원 범위다. 필요한 발표·SNS·앱 작업은 DESIGN의 해당 통로를 쓰거나 도구를 확장한다. 지원하지 않는 형식을 조용히 다른 형식으로 출력하지 않는다.

## 4. 확장 범위

웹·앱·자유 배치·데이터 시각화는 해당 매체 제작기를 사용할 수 있다. 새 힌트는 의미·변환·오류 처리를 함께 정의한다. 임의의 힌트 개수 상한이나 기존 통로 밖 제작 금지를 두지 않는다.

## 5. 원천과 출력

원고 수정 뒤 생성물을 다시 만든다. HTML 원고는 엔진 소개서처럼 `펠트문서.js`를 사용한다. 지원 형식을 늘리면 실제 입력·출력과 관련 시험으로 확인한다.

## 6. 확인

글의 누락, 표·중첩 목록의 의미, 실제 창 크기·인쇄에서 잘림을 확인한다. 코드 검사와 읽기 좋은 배치의 완성을 구분한다.
