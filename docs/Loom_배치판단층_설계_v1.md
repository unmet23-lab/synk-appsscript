## 0. 한 문장

**원고를 던지면 지면이 선다.** 지금 Loom 은 「입히는 것」(CSS·재질·부품)까지 자동인데,
«어느 지면으로, 무엇을 어디에» 는 세션(AI)이 매번 손으로 정한다 — 그 판단을 통로로 옮긴다.
새 발명이 아니라 **counter 원리의 확장**이다: 「원고에 `<h2>` 만 써도 유리 원판 번호가 선다」
(= 의미를 적으면 물성이 붙는다)를 **「의미를 적으면 지면이 선다」**로 넓힌다.

## 1. 층 위치 — L4 와 L5 사이

| 층 | 무엇 | 어디 |
|---|---|---|
| L4 지면 | 프리셋 CSS 조각 | `loom.js` 지면들 |
| **L4.5 조판(신설)** | **원고 → 규격·구조·배치 판단 → 완성 HTML** | `tools/룸조판.js` |
| L5 강제 | 등록부·적색 게이트 | `지면방.js` |

🔑 **L5 와의 배선이 이 층의 숨은 값이다** — 새 지면이 «이 통로로» 태어나면 태어나는 순간
지면방에 등재된다. 오늘(09-01) 미분류 11 적색의 뿌리(「새 HTML 이 등록부 밖에서 태어난다」)가
구조적으로 준다.

## 2. 동작 — 다섯 걸음

```
node tools/룸조판.js 원고.md [--지면 문서|덱16x9|캐러셀|인쇄A4] [--내놔 docs/xxx.html]
```

① **규격** — `--지면` > 원고 머리말 `지면:` 순으로 읽는다. 둘 다 없으면 후보와 근거를
   **말하고 멈춘다**(조용한 추정 금지 — 추정이 틀리면 지면 전체가 틀린 옷을 입는다).
② **구조** — 마크다운 → 의미 마크업. `##`→절(원판 counter) · `1.`→순번 · `-`→불릿 ·
   `>`→인용부호 · 표→표 · `**굵은 수**`→히어로수 **후보**. 마크업을 손으로 짜는 일이 사라진다.
③ **배치 판단** — 두 겹으로 가른다:
   - **규칙이 서는 것은 코드가**: counter·율(단·켜·장)·부품 자동 훅. 결정론 = 재현 가능.
   - **갈리는 것은 «조판 힌트»가**: `<!--조판: 히어로-->` 같은 원고 주석이 이긴다. 힌트가 없고
     히어로수 후보가 여럿이면 **첫째만 취하고 나머지를 보고**한다(신호 1점 규율이 코드로 선다).
   🔑 AI 의 판단은 **원고의 힌트 주석으로 남긴다** — 판단이 코드 밖·세션 안에 살면 재현이 안 되고,
   원고에 살면 「원고가 정본」 게이트(재현 대조)가 그 판단까지 지킨다. 그리고 이 갈래 덕에
   **AI 가 좋아질수록 이 층도 좋아진다**(힌트를 더 잘 다는 것은 모델 몫 · 규칙은 안 늙는다).
④ **검증** — 룸잉크(부품 위 잉크 대비) + 율 사다리 + 자립형(외부 참조 0). 어기면 빨강으로 멈춘다 —
   «생성됐는데 나쁜» 지면이 통로를 통과하지 못한다.
⑤ **출력** — 완성 HTML + **지면방 등재까지**(미등재면 그 자리에서 한 줄 등재). `--재현` 으로
   「원고 → 같은 지면」 왕복이 검증된다(산출물 손 편집은 다음 재현이 exit 0 으로 되돌린다 — 기존 규율 그대로).

## 3. 덱(16:9) — 「PPT 규격 알아서」의 실물

유호님이 08-16 에 든 예시 그 자체인데 지면 프리셋 8종에 **슬라이드 규격이 없다**(발표물 01 덱은
손으로 짠 단품이다). 조판의 덱 모드:
- **장 끊기** = `##` 이 장의 경계(기본값). 한 장의 내용 밀도 상한은 율(장·켜 단위 높이 예산)로
  계산하고, 넘치면 **장을 자동으로 나누되 나눴다고 보고**한다(조용히 구겨 넣지 않는다).
- 표지·마무리 장은 관례로 자동(제목 머리말 → 표지 · 마지막 `## 끝` 또는 자동 꼬리).
- 첫 소비자 = 설명회 덱 갱신 · SHIFT 발표물(대외 노출 ④ 갈래와 만나는 자리).

## 4. 범위 — 무엇이 이 통로 «밖»인가

- **자유 배치 지면**(홈페이지 히어로·포스터류)은 밖이다 — 조판은 «흐름 지면»(문서·덱·캐러셀·인쇄)용.
  자유 지면은 기존 손 HTML + 펠트스킨 통로 유지. 억지로 넣으면 힌트 주석이 사실상 HTML 이 된다.
- **데이터 생성기**(이해대장.js·작동대장.js 등 «데이터→HTML»)는 v1 밖 — 입력이 원고가 아니라
  데이터다. 장기적으로 생성기가 조판을 소비할 수 있으나 그건 그 생성기 개정 때 판단.
- 앱 화면(talk)은 밖 — 그쪽은 §2-업 ⑤(앱 UI 반입) 트랙이 따로 진다.

## 5. 구현 순서 (각 보가 독립 납품)

1. **1보 = 문서 지면**(A4 흐름 · 검은 무대/낮) — 첫 소비자는 매일 태어나는 판정 재료 HTML
   (미분류 적색의 주 공급원이 첫 고객이 되는 것이 맞다). ②③④⑤ 골격 전부 + 규격은 문서 하나.
2. **2보 = 덱 16:9**(§3) — 장 끊기 판단이 이 보의 새 코드.
3. **3보 = 캐러셀 1080 정사각** — 지면방 보류 「괜찮아요」 캐러셀을 여는 열쇠(그 보류 조건이
   «1080 정사각 프리셋»이다).
4. **4보 = 힌트 어휘 확장** — 실사용에서 갈린 판단만 어휘로 승격(미리 어휘를 늘리지 않는다).

## 6. 대가 — 틀릴 때의 모습 (짓기 전에 적는다)

- **마크다운 방언**: 표·중첩 목록 등에서 변환이 조용히 다른 그림을 낼 수 있다 ⇒ ④검증에
  «구조 왕복»(원고 블록 수 == 지면 블록 수)을 넣고, 어긋나면 빨강.
- **힌트 주석이 늘어나 원고가 마크업이 되는 것** ⇒ 힌트 어휘를 «세는 분모»로 두고(시작 = 히어로 ·
  장끊기 둘뿐) 늘릴 때마다 이 문서를 개정한다 — 어휘가 열을 넘으면 이 설계가 틀린 것이다.
- **조판이 만든 지면과 손 지면의 공존기** — 같은 종류 지면이 두 통로에서 태어나면 갈린다 ⇒
  1보가 서면 판정 재료류의 «권장 통로»를 조판으로 선언하고(강제는 안 한다 — 이행기),
  지면방 등재 사유에 통로를 적는다.
