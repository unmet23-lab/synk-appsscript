## 0. 기업의 능력을 축적하는 경영 원칙

SYNK는 개인화 엔진 기업이라는 정체성을 유지한다. **대표 제품에서 고객 성과를 확인하고, 재사용할 능력을 Atlas와 전문 모듈에 축적하며, 연결 가치가 있는 제품으로 확장한다.** 앱 수·수집량·엔진 기능 수를 기업 역량의 성과로 대신하지 않는다. 좋은 기술 구조와 브랜드 신뢰·판매·운영 성과는 각각 확인한다.

### 0-1. 공통 능력과 전문 능력의 책임

| 구분 | 맡을 일 |
|---|---|
| SYNK 계정·제품 호스트 | 사용자 확인, 접근 권한, 동의와 사용 목적, 원본 저장, 수정·철회·삭제와 동기화. 기업 도입에서는 고객사 계정·기존 시스템과 연결하고 고객사·역할별 접근 경계를 관리 |
| Atlas 공통 능력 | 기존 Core·Loom·Vellum·Trail·Prism·Temper·Reed·Strata의 책임에 맞는 근거·맥락 판단, 선택, 표현, 기록과 평가의 재사용 |
| 분야별 전문 모듈 | 사주 역법, 여행 일정, 교육 과제처럼 분야의 지식·계산·필수조건·성공의 의미. 같은 전문 능력이 필요하면 여러 앱이 함께 사용 |
| 앱·기능 | 필요한 공통·전문 능력을 조합하고 실제 사용자 흐름·콘텐츠·전달·결과 확인을 연결 |

- 앱마다 엔진을 새로 만들거나, 앱의 규칙을 모두 Atlas에 넣지 않는다. 책임과 지식의 경계로 나누며 새 중앙 판단 엔진·자체 AI 하네스를 추가하지 않는다. 담당 원본은 [8개 엔진 안내](엔진8종_상향설계_v3.md#engine-owner-sources)를 따른다.
- 반복해서 필요한 능력은 공통화한다. 첫 적용에서 공통 능력 개선이 필요할 때도 범용 요건과 기존 소비처의 호환·검증 범위를 밝히고 진행할 수 있다. Atlas를 영구히 고정하거나 반드시 모든 엔진을 거치게 하지 않는다.
- 제품 계약·원본 근거·평가 기준은 특정 AI 모델과 분리한다. 모델이나 내부 구현을 바꿀 때 품질·비용·응답 시간과 기존 제품의 동작을 비교한다. 서버·서비스 분리는 독립 운영·확장·장애 격리의 실제 필요에 맞춰 정한다.
- 같은 계정이라도 사실·평소 선호·이번 상황·미확인 추정을 구분하고 사용 목적·출처·시점·정정 범위를 지킨다. 분야의 해석을 공통 사용자 사실로 자동 승격하지 않는다. 예를 들어 운세 풀이를 실제 성격이나 학습 능력의 근거로 옮기지 않는다.
- SYNK는 공통 고객 약속과 신뢰를, 각 브랜드·제품은 구체적인 고객 결과를, Atlas는 이를 뒷받침하는 능력을 설명한다. 현행 [비전](비전_정본.md)과 [브랜드별 역할](마케팅_정본.md)은 유지하며, 비전과 구현·출시·효과의 증거를 구분한다.

### 0-2. 신규 확장을 판단하는 네 기준

새 사업·제품·기능의 제안과 투자·운영 확대에서 아래 네 항목을 확인한다. 현재 확인한 근거와 가설·미확인을 구분하며, 분야에 맞는 비교 기준을 정한다.

| 기준 | 확인할 질문 | 남길 근거 |
|---|---|---|
| 고객 가치 | 누구의 어떤 문제를 해결하며, 기존 방법이나 기본 방식보다 무엇이 나아지는가? 개인화가 필요한 부분은 어디인가? | 과업 성공·이해·재미·반복 사용 등 해당 제품의 결과, 비교할 기본 방식과 실패 신호. 코드 시험과 실제 고객 효과를 구분 |
| 재사용 효과 | 어떤 공통·전문 능력을 이어 쓰거나 새로 축적하는가? 공통화 비용까지 포함해 다음 제작과 운영이 쉬워지는가? | 실제 소비처, 개발·검수·지원·운영 부담의 예상과 실측. 억지 공통화가 더 비싸면 독립 구현 또는 해당 없음의 이유 |
| 사업 연결 | 기존 고객·이용 흐름·판매 경로와 어떤 연결이 있는가? 연결이 약해도 독립적인 수요와 운영 근거가 있는가? | 도달 가능한 고객과 경로, 반복 사용·지불 또는 다른 사업 기여의 가설/실측, 담당과 비용·지원 부담·기존 업무에 미치는 영향 |
| 브랜드 일관성 | 고객이 SYNK 또는 해당 브랜드가 제공하는 이유와 약속을 이해할 수 있는가? | 사용자에게 설명할 가치, 기존 브랜드 역할과의 관계, 품질·근거 수준·기대의 충돌 여부. 모든 제품을 같은 경험으로 만들지는 않음 |

사업 연결을 즉시 매출이나 다른 앱으로의 강제 이동으로 판단하지 않는다. 재사용 효과를 모든 기능의 Atlas 편입이나 개인정보 공동 사용으로 판단하지 않는다. 개인정보 사용 권한은 기존 계약에서 별도로 확인한다. 네 항목을 임의 점수로 합산해 자동 합격시키지 않는다.

### 0-3. 작업 규모와 근거 수준에 맞춰 적용

| 적용 상황 | 기록과 판단 |
|---|---|
| 승인 범위 안의 기능 개선·수정 | 기존 작업 설명에 고객에게 달라지는 점, 사용할 능력과 책임, 확인 방법을 짧게 남긴다. 비용·운영·브랜드 영향이 달라지는 항목만 보완 |
| 새 앱·사업·큰 기능의 첫 실험 | 담당 제품 문서에 네 기준의 근거/가설, 작은 실험의 범위·담당·기간 또는 종료 조건·비용 한도를 기록. 실사용 근거가 아직 없어도 승인 범위의 무료 설계·구현·검증을 진행 |
| 투자·출시 규모·운영 범위 확대 | 이전 단계의 실제 결과를 네 기준과 비교하고 유지비·지원·고객 확보 부담까지 확인. 기존 결정 절차에서 확대 범위와 남은 불확실성을 명시 |

작업마다 별도 심사 조직·결재 단계·점수표·자동 차단기를 만들지 않는다. 기존 사용자 승인과 위임 안에서 실행하며, 이 원칙을 이유로 같은 허가를 다시 묻지 않는다. 비용·배포·외부 약속은 기존 운영 원칙과 해당 작업의 승인 범위를 따른다.

판단은 다음 중 하나로 짧게 남긴다.

- **실험 진행:** 고객 문제와 확인 방법을 정했고, 미확인 부분은 정해진 범위 안에서 검증한다.
- **확대 진행:** 이전 단계의 실제 결과와 감당할 운영 비용이 다음 범위를 뒷받침한다. 일부 가설이 남으면 영향과 다음 확인 조건을 명시한다.
- **범위 조정:** 가치가 있는 부분을 좁히거나 공통화·독립 구현·기존 기능 확장·외부 도구 활용 중 더 나은 방법으로 바꾼다.
- **보류 또는 종료:** 고객 가치의 근거가 약하거나, 운영 부담·브랜드 충돌 등 핵심 문제가 해결되지 않는다. 이유와 재검토 조건을 기록한다. 기존 사업의 종료는 자동 판정하지 않는다.

비교할 결과와 진행·중단 조건은 가능한 한 실험 전에 정한다. 제품별 수치·표본·기간이 필요한 경우 근거를 적고, 전사 공통 숫자를 임의로 강제하지 않는다. 실제 고객 검증이 아직 없는 로컬 MVP를 출시 효과나 사업성의 증거로 쓰지 않는다.

### 0-5. 이번 채택의 범위

사용자 근거: 2026-10-06 「‘앱마다 엔진을 추가한다’를 ‘필요한 전문 능력을 만들고 여러 앱이 조합한다’로 다듬겠습니다」에 동의한 뒤, 「그럼 이 방향을 실제 경영 원칙으로 채택해서 신규 확장에도 기준을 붙이자」고 요청했다. 위 네 기준과 실험·확대의 구분을 경영 원칙으로 채택하고, 기록 형식과 적용 규모는 그 결정을 실행하기 위한 운영 방식으로 둔다.

기존 승인 사업·고객 약속·무료 MVP 개발을 일괄 취소하거나 중단하는 결정이 아니다. 앞으로의 신규 제안과 추가 투자·운영 확대에 적용하고, 기존 제품은 관련 후속 작업에서 경계를 보완한다. 유료 AI 기능·시험의 유예 등 현행 비용 결정은 유지한다. 대표 제품의 투자 우선순위, 특정 사업의 출시·수익성, 현행 Atlas의 전문 규칙 분리 구현까지 이번에 확정·완료한 것은 아니다. 결과와 남은 일은 [결정](_ops/결정.md)과 [트랙](_ops/트랙.md)의 해당 항목으로 연결한다.

**같은 날 SHIFT 후속 확정:** 사용자가 별도로 사업·BM 범위를 **개인화 서비스 도입·운영 → 같은 유형의 반복 공급 검증 → API·엔진 라이선스 상품 확장**으로 좁혔다. 고객사별 자료·설정·기존 시스템을 연결하며 공통 능력을 재사용한다. 초기 도입비·정기 이용/운영료·추가 사용/개발비의 구조와 확대 기준은 [SHIFT 담당 원문](마케팅/SHIFT.md#shift-bm)에 둔다. 기존 계약·약속은 보존하고 신규 영업·개발에는 이 범위를 적용한다. 다른 브랜드의 사업 범위나 첫 고객·가격·출시를 정한 결정은 아니다.

## 1. 세 방향의 자리

회사별 목적과 미래는 [철학 정본](SYNK_철학.md)과 [비전 정본](비전_정본.md)을 따른다. 실전 리허설은 LAB의 배움·경험 경로 연구, SHIFT의 기업·기관 AI 교육·컨설팅, PATH의 유학·취업 준비에 적용하는 실물이다. 협동 이야기는 PULSE의 몰입과 감상 경험, 함께한 시간이 각자의 이야기로 이어지는 방향을 구체화한다. 이 문서는 세 발전 방향의 역할·순서를 정하며, SYNK의 개인화 엔진(Atlas)이나 LAB의 연구, SHIFT의 교육·컨설팅, PATH의 유학·취업 준비 전체를 이 세 실물로 한정하지 않는다. 아래의 역할·발전 순서와 실제 검증 상태는 각각 유지한다.

| 방향 | 책임과 목적 | SYNK에 남기는 것 | 이번 첫 실물 |
|---|---|---|---|
| 실전 리허설 | LAB·SHIFT의 교육·상품 역량. 배운 내용을 달라진 상황에 적용하고 수정·설명·다음 적용까지 연결한다. | 과제 설계, 교사 검토 근거, 반복 가능한 피드백 방식 | 가상 고객의 요구 확인→첫 제안→조건 변경→수정 이유→다른 고객 적용→검토 자료 내보내기 |
| 협동 이야기 | PULSE의 새로운 유료 작품 후보. 사람끼리 탐색·조작·대화하며 완결된 한 편을 즐긴다. 계약·청구·정산 명의와 권리는 [조직 정본](조직계보_정본_v1.md)과 실제 계약에서 확인한다. | 자체 이야기·음악·장면·상호작용 제작 도구와 다음 작품을 기다릴 이유 | 〈마지막 불빛〉: 펠트 해안 도시의 전원·방송 복원, 역할별 정보, 공동 선택과 함께 남긴 밤의 기록 |
| 접근성 | 전사 공통 제작·검수 역량. 내용을 이해하고 조작하고 감상할 통로를 넓힌다. | 명확한 설명·키보드 조작·동작 감소·소리 정보·검수 증거 | 접근성 감상실, 공통 조작 모듈, 실제 적용·미확인 범위를 나눈 검수 기록 |

1번과 3번을 별도 신사업·매출 성과로 부풀리지 않는다. 2번은 PULSE의 작품 사업으로 시작하며 별도 조직 신설은 실제 고객·작품·반복 구매를 확인한 뒤 판단한다. LAB의 기존 앱·개원·TOPIK 약속, SHIFT의 교육·컨설팅, PATH의 유학·취업 준비 방향과 기존 상품을 폐기하지 않는다.

## 2. 실전 리허설의 발전

첫 실물의 상대는 1인 기업 강의 수강생과 강사다. 장면을 읽기만 하는 자료보다 확인 질문, 자신의 제안, 조건 변화에 따른 수정 결과물, 다른 상황에 적용한 결과를 남긴다. 원래 입력과 수정 이유를 분리하며 자동 키워드 점수나 자격 인증으로 사람의 능력을 단정하지 않는다.

현재 예시는 허구이며 실제 고객 성공 사례가 아니다. 첫 버전은 이 브라우저에 저장하고 당사자가 검토 자료를 내려받는 독립 실습이다. LAB 학생 기록·기존 엔진·강사 계정으로 자동 전송한다고 약속하지 않는다. 실제 학생 학습으로 연결할 때는 [제품 방향](제품방향.md)의 원본·소비·도움·수혜자 계약과 학생 데이터 조건을 적용한다.

발전 순서는 내부 과제 적용→강사 총작업시간과 새 상황 적용 관찰→기수별 개선→교육 운영자가 반복 구매할 외부 상품의 검증이다. 외부 상품은 과제 설계·강사 기준 조정·기수 운영이 묶인 형태를 우선 검토한다. 가격·판매 개시·성과 보장은 아직 정하지 않았다.

기존 [직업체험 설계](SHIFT/VR직업체험_설계_v1.md)의 상황·과업·변화·보고 구조를 발전 재료로 쓴다. 기존 장기 VR 로드맵과 이번 성인 창업 실습을 같은 출시 상태로 표기하지 않는다. 무료 수동 역할 연습과 기존 제품보다 실제로 무엇이 나아졌는지를 확인한다.

## 3. PULSE 협동 이야기의 발전

### 작품 경험

친구들이 서로 다른 정보를 가지고 같은 장소를 탐색하고, 사물을 직접 조작해 문제를 풀고, 공동 결정과 끝맺음까지 이어지는 작품을 만든다. 초대→역할→탐색·복원→결정→함께 남기는 기록이 작품 안에서 이어져야 한다. 첫 작품은 2인 핵심 역할과 2인 선택 역할, 혼자 두 역할을 바꾸는 체험을 제공한다. 실제 플레이 시간·재미·재구매는 관찰 전 추정이다.

첫 안내는 무엇을 왜 어떻게 하는지 알려 주고, 진행 중에는 지금 할 일과 복원 상태를 보여 준다. 도움이 필요할 때 단계별 힌트를 펼칠 수 있게 한다. 자유 탐색은 사용자가 설명 없는 버튼을 임의로 누르게 두는 근거가 아니다. 2026-09-10 개정은 전차 전선 연결과 방송 수신이라는 두 조작을 두고, 역할별 정보를 말이나 선택적 공유로 조합하도록 했다. 단서 공유 개수·불필요한 수집을 진행 문턱으로 쓰지 않는다.

결말에는 선택으로 달라진 구체적 장면, 실제로 한 복원, 함께 남긴 문장이 이어져야 한다. 선택을 사람의 도덕성·실력 평가로 바꾸지 않는다. 소리는 이 작품의 필수 제작 요소이며 음악·환경·사물·행동과 결과의 소리를 경험에 맞춰 설계한다. 사용자가 음소거하거나 음량을 나눠 조절할 수 있고, 소리를 끄더라도 필수 정보는 화면과 글로 남는다.

작품명 〈마지막 불빛〉과 해안 도시 설정은 첫 제작안이다. 가짜 타이머·강제 댓글·학습 프로필 수집을 작품의 필수 경험으로 넣지 않는다. 시나리오 실행 도구와 협력 설계 방법은 LAB·SHIFT와 공유할 수 있지만 플레이 기록을 학생의 성격·학습 능력으로 자동 합치지 않는다.

### 펠트 그래픽의 품질 목표

사용자가 제시한 Unreal Engine 5·GTA VI는 그래픽의 야심과 공간 완성도에 대한 참고다. 특정 엔진 사용이나 그 작품과 동급의 제작 규모·성능을 달성했다는 주장이 아니다. 독창적인 도시·인물·사물로 만든다.

- 실제 섬유와 실땀을 느낄 표면, 둥근 재단면, 접촉 그림자, 가까이 보아도 유지되는 물성과 여러 거리의 깊이를 함께 설계한다. 펠트 재질의 구체적인 디테일과 공간 현실감을 더 높인다.
- 사용자가 좋게 본 하늘·전체 분위기의 몽환성을 더 발전시킨다. 영화적인 빛·안개와 직접 걷는 공간, 사물을 탐색할 이유를 연결한다. 펠트 무늬를 붙인 단순 상자로 완성 판정을 하지 않는다.
- 미술 기준 이미지, 실시간 3D 장면, 실제 플레이 화면의 품질을 각각 구분해 확인한다. 이미지 한 장의 품질을 실행 화면의 성능으로 보고하지 않는다.
- UI 색·서체·모션은 [디자인 정본](../DESIGN.md)을 따른다. 효과를 줄이거나 글로 살펴봐도 필수 정보와 선택이 남아야 한다.

### 조작과 상황 대화

실시간 AI 상황 대화는 2026-09-10 사용자가 요청한 개정 범위다. 작가가 정한 세계·장치·선택 위에서 현재 역할이 아는 정보와 진행 상황에 맞춰 대화하도록 한다. 코드·UI와 이 컴퓨터에서 실행하는 Qwen3 4B 모델을 통합하고 실제 한국어 생성·역할별 문맥을 확인했다. [실제 응답과 한계](https://github.com/unmet23-lab/synk-appsscript/blob/683e33fcdddc1f00a7eb6bc24d7a4200ceb8978a/experiences/20260909/qa/ai-runtime.md)(보존본)에 초기 실패와 교체 결과를 남겼다. 실제 대화의 재미·모순·기다림·공개 서비스 운영비는 별도로 평가한다. 모델이 준비되지 않아도 장소 힌트와 직접 조작으로 끝까지 진행할 수 있어야 한다.

WASD 이동·드래그 시점·가까운 사물 조사를 장면 개정의 기본 조작으로 삼고, 모바일과 키보드의 장소 버튼도 동등한 경로로 유지한다. 새 장면·음향·서사·대화를 합친 실제 플레이를 검수한 뒤 품질을 판단한다. 이전 장면의 60fps 근접 관찰이나 모의 AI 응답은 개정판의 성능·실제 대화 증거가 아니다. 장기적으로 작품별 이용권과 시리즈 판매를 검증하되 현재 결제·외부 서비스 운영을 완료로 표시하지 않는다.

## 4. 접근성을 전사 제작에 적용하는 방법

**2026-10-02 철학 v3.0 연결:** 회사의 목표가 20대부터 60대까지 남녀노소 누구나 Atlas로 확실히 도움을 받는 것이므로, 접근성은 덧붙이는 기능이 아니라 그 목표의 기본 조건이다. 큰 글자·대비·움직임 줄이기·소리 대안·쉬운 말은 나이로 정해 주지 않고 본인이 고르는 설정으로 제공한다([적용 기준 §0](철학_적용기준.md#all-users)).

현재 결과물의 목적에 맞는 항목을 골라 처음부터 적용한다. 공통 품질 기준의 [제출 검사표](명품_기준_v1.md#3-제출할-때-확인하는-것--공통-검사표-정본)와 [기존 자동 검사기](../tools/접근성검사.js)를 사용한다. 새 강제 훅·중앙 검문·전사 일괄 재제작을 만들지 않는다.

| 대상 | 제작 때 적용할 것 | 따로 확인할 것 |
|---|---|---|
| 웹·실습·게임 | 제목/구조/입력 이름, 키보드와 보이는 초점, 오류·진행 안내, 충분한 대비, 작은 화면, 움직임 감소 | 실제 조작, 보조 기술 사용, 당사자가 과업을 마칠 수 있는지 |
| 그림·3D 장면 | 정보의 목적에 맞는 대체 설명, 시각만으로 전달하는 필수 단서의 동등한 글 경로 | 설명이 관찰된 장면과 같은지, 중요한 정보 누락 여부 |
| 영상·소리 | 실제 대사와 필요한 비언어 소리 자막, 필요시 시각 정보 음성 해설, 정지·음량·재생 제어 | 시간·뜻 대조, 실제 청취, 전문 검수자와 이용자의 확인 |

자동 검사는 접근성 전체의 보증이 아니다. 브라우저 읽어주기와 사람이 검수한 녹음 음성 해설을 구분하고, 원천에 없는 소리를 실제 전사로 꾸미지 않는다. 외부 접근성 서비스 판매는 전문 검수자·당사자 참여와 수정 원가를 포함한 구매 수요가 확인될 때 검토한다.

## 5. 함께 쌓는 자산과 완료 기준

공유할 자산은 시나리오 규격, 역할·선택·상태를 이어 주는 도구, 승인된 시각 자산, 접근성 부품과 검수 방법이다. 고객 소유 납품물과 학생·플레이어의 개인 기록은 자동 공용 자산이 아니다. 회사 분담과 권리는 [조직 정본](조직계보_정본_v1.md)을 따른다.

첫 결과물의 완료는 정본 연결, 실제 작동, 실제 화면 확인, 재현 방법과 한계의 인수까지다. 다음 단계의 판단은 실습의 적용·강사의 작업시간, 작품의 완주·재구매, 접근성의 실제 이용 가능성을 각각 관찰한다. 이번 구현의 로컬 시험을 그 결과의 증거로 바꾸지 않는다.

후속 작업은 이 문서와 해당 결과물의 현재 소스·검증 기록을 읽는다. 이번 세 방향을 관련 작업에 반영하되 모든 업무에 세 기능을 억지로 붙이지 않는다. 남은 일은 [기존 트랙](_ops/트랙.md)에 연결하고 자세한 실행 기록은 결과물 곁에 둔다.
