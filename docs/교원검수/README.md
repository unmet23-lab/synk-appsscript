# 교원 검수 시트

교원이 확인할 것을 원본에서 그대로 뽑은 표 한 장이다. 파일은 [`교원검수시트.csv`](교원검수시트.csv), 만드는 도구는 [`tools/교원검수시트.js`](../../tools/교원검수시트.js)다. 2026-10-05 처음 만든 436줄에 최신 원고를 보완하여 2026-10-07에는 560줄이다. 원본이 바뀌면 생성 명령의 개수도 달라진다.

게임 문항·상황 예문·연결 초안은 모두 제작용 초안이다. 이 시트로 확인을 받기 전에는 어느 것도 「교원 검수 완료」라고 말하지 않는다. 검수자 섭외는 유호님이 한다.

## 무엇이 들어 있나

| 갈래 | 줄 수 | 무엇 | 교원이 보는 것 |
|---|---|---|---|
| 게임 문항 | 361 | 기존 여덟 게임과 Town 읽기 확인(빈칸 베기 37 · 입장 검사 안내문 13과 손님 50 · 선생님이 돌아왔다 9 · 주문 폭주 15 · 바람길 28 · 한국어 리듬 30 · 한국어 레이싱 주제 단계 24와 문장 코스·피날레 90 · 말 랠리 47 · Town 18) | 문장이 자연스러운가, 초급(TOPIK I 준비)에 맞는가, 정답이 하나뿐인가, 풀이가 맞는가 |
| 게임 글 | 26 | 「선생님이 돌아왔다」의 여는 글·사이 글·맺는 글 | 읽기 글로 자연스럽고 초급에 맞는가 |
| 상황 예문 | 78 | 배우는 이유가 이어지는 상황 26개마다 그 자리에서 쓰는 말 셋([Strata 예문 층](../Strata_설계.md)) | 그 자리에서 실제로 쓰는 말인가, 초급에 맞는가 |
| 게임↔상황 | 8 | 「이 게임의 연습이 곧 이 상황이다」 초안(주문 폭주 = 주문, 입장 검사 = 공공 안내문 읽기, 바람길 = 길 묻기·작업 지시 듣기)과 상황을 붙이지 않은 게임 넷 | 그 게임의 문장이 그 상황의 말인가, 빠진 연결이 있는가 |
| 문형→능력 | 87 | 초급 문형마다 이어 둔 능력과 단계 | 그 문형이 그 능력에 속하는가, 단계가 맞는가 |
| 중급 능력 | 13 | TOPIK II 단계에서 새로 나눈 듣기·읽기·쓰기 능력과 제작 단계(급수 아님) | 이렇게 나누는 것이 맞는가, 이름이 학습자에게 알맞은가, 빠진 능력이 있는가 |
| 중급 선행 | 25 | 중급 능력마다 먼저 익힐 능력(초안, 연습을 막지 않음) | 정말 먼저 익혀야 하는가, 빠진 선행이 있는가 |

「읽힌 문형」 칸은 지도의 문형 읽기가 그 문장에서 읽어 낸 문형이다. 검수의 실마리이고, 비어 있으면 읽기가 이름 붙이지 못한 것이다(틀렸다는 뜻이 아니다).

`-고 싶다`처럼 붙임표로 시작하는 칸은 앞에 빈칸 하나를 두고 쓴다. 그대로 두면 Excel이 수식으로 읽어 `#NAME?`로 바꾸고 그대로 저장한다(2026-10-05 Excel에서 121칸 확인). 읽을 때는 그 빈칸을 다시 뗀다.

## 오답 교정과 새 문항 연결 검수

같은 생성 명령으로 [`오답교정_새문항_검수부록.html`](오답교정_새문항_검수부록.html)도 만든다. 입장 검사·바람길 듣기 확인·한국어 레이싱 문장 코스와 피날레·Town 읽기의 **실제 보기별 교정문**, 원문 풀이, 규칙·문형 태그, 측정 항목, itemKey·familyKey를 담는다. 기본 CSV의 문항 번호와 부록 번호가 이어진다.

2026-10-07 준비 범위는 문항 170개, 오답별 교정 397개, 합성 대표 연결 48개다. 실제 선택 함수를 별도의 빈 메모리에서 실행하여 새 문항이 이어진 36개와 연결 불가·회차 끝 12개를 모두 남긴다. 네 활동 각각의 독립 정답·독립 오답·도움 후 정답·도움 후 오답 표시 문구도 실제 공통 `recheck`에서 추출한다. 실제 학생 기록과 학생 식별 정보는 없다.

교원은 선택한 답에 대한 교정이 원문과 맞는지, 새 문항의 목표·난도·읽기/듣기·응답형식이 같은지, 내용 태그가 달라진 쌍을 같은 규칙·표현 확인이라고 설명해도 되는지 확인한다. Entry의 글 전용 원고도 이 검수 대상이다. 원본 경로와 SHA-256으로 검수한 버전을 구분한다.

부록의 빈 검수란은 **인쇄해서 적거나 별도 작성본으로 복사**하는 용도이며, HTML 자체에 입력 저장 기능은 없다. 문항 승인·수정은 CSV의 같은 문항 번호에 적고, 교정문·연결 의견은 `문항/<활동>/<id>` 또는 `연결/<활동>/<id>`와 함께 별도 작성본에 적는다. 부록 작성 내용을 자동 반영하거나 교원 승인으로 집계하지 않는다. 생성본 HTML에 수작업 변경이 있으면 도구는 체크섬을 확인하여 교체를 거부한다. 작성본은 다른 이름으로 보존한다.

합성 연결은 기본 근무·코스의 대표 사례이며, 실제 이전 노출·목표 지정·선택 순서에 따라 달라진다. 모든 가능한 쌍의 목록이나 학생 학습 효과의 증거는 아니다. 부록 생성과 무료 시험 통과는 **검수 준비**이며 교원 검수 완료가 아니다.

Entry 부록은 연수 이후 기본 구성(`firstTime:false`)으로 끝 손님까지 24위치를 남겨 새 연결 16개다. 끝 4곳을 제외하면 16/20이며 같은 규칙·문형·목표는 15/20이다. [Entry 문항 여유 비교](../../experiences/entry-check/README.md)의 18/20은 네 근무지 모두 `firstTime:true`를 적용한 별도 합성 조건이므로 두 수치를 섞지 않는다.

실제 참여자가 정해지면 [학생 시험 준비물](학생시험_20261007/README.md)의 15~20분 진행표·빈 관찰표를 사용한다. 현재 참여자와 관측 결과는 0명/0건이다.

## 교원에게 넘기기

1. `교원검수시트.csv`를 Excel로 열거나, Google 스프레드시트에서 「파일 > 가져오기」로 올린다(글자는 UTF-8).
2. 교원은 줄마다 **확인** 칸에 `맞음` · `고침` · `빼기` 가운데 하나를 적는다. 고칠 때는 **고친 내용**에 바꾼 문장을, 이유는 **메모**에 적는다.
3. 새 문항은 **번호**를 비우고 **갈래**와 **내용**(필요하면 자리·정답·보기)을 적은 새 줄로 넣는다.
4. **번호**·**갈래**·**내용** 칸은 고치지 않는다. 번호로 원본을 찾고, 원문·정답/보기·풀이·자리·읽힌 문형이 원본과 달라진 줄은 확인으로 세지 않고 다시 확인할 칸을 알린다.
5. 돌려받은 파일은 **다른 이름으로** 둔다(예: `교원검수시트_검수자_1015.csv`). 저장소의 `교원검수시트.csv`는 늘 빈 시트다. 그 자리에 교원이 적은 파일이 있으면 도구가 다시 만들기를 멈춘다. 확인 미기입 새 제안 행과 추가 메모 열도 보존한다. 이번 준비 작업에서는 `--덮어쓰기`를 사용하지 않는다.

## 돌려받은 뒤

```bash
node tools/교원검수시트.js --읽기 <검수한.csv>
```

갈래별로 맞음·고침·빼기·아직을 세고, 고침·빼기·새 문항과 「시트를 만든 뒤 원본이 바뀐 줄」을 나열한다. 교원이 적은 것은 세지 못해도 버리지 않는다: 「확인」은 비었는데 고친 내용·메모가 있거나 내용을 직접 고친 줄, 같은 번호가 두 번 나온 줄, 「확인」 칸을 읽지 못한 줄을 따로 보인다. `맞음`인데 「고친 내용」이 적힌 줄은 확인이 아니라 고침으로 센다.

```bash
node tools/교원검수시트.js --읽기 <검수한.csv> --적용
```

`맞음`인 상황 예문을 예문 원천(`strata/topik-i.situation-examples.json`의 `review.reviewed`)에 id와 그 문장으로 적는다. 그 문장은 계정 요약에서 `reviewed: true`로 나간다. 확인은 그때의 문장에 묶인다 — 나중에 문장을 고치면 적힌 문장과 달라져 다시 초안이 된다. 자동으로 반영하는 것은 이것뿐이다. 고침·빼기·새 문항은 목록을 보고 원본에서 고친다.

| 갈래 | 고치는 원본 |
|---|---|
| 게임 문항·게임 글 | 각 게임의 문항 파일(`experiences/<게임>/content.mjs`·`core.mjs`·`story.mjs`·`instructions.mjs`·`listening-check.mjs`·`curriculum.js`·`campaign.js`·`finales.js`·Town `understanding.mjs`). 고친 뒤 그 게임의 시험을 돌린다(문형 연결 표가 문장과 같은지 본다) |
| 오답 교정·새 문항 연결 부록 | Entry `correction.mjs`·Runner `listening-check.mjs`·Racing `learning.js`와 `personalization.js`·Town `understanding.mjs` 및 해당 문항 원고. 교정 의견은 원본 담당자가 고치고 생성·검증을 다시 한다 |
| 상황 예문 | `strata/topik-i.situation-examples.json` |
| 게임↔상황 | `experiences/synk-account/src/atlas-words.mjs`의 `WORLD_GAMES` |
| 문형→능력 | `strata/topik-i.grammar.json` (고친 뒤 `node tools/build-game-learning.js`) |
| 중급 능력·중급 선행 | `strata/topik-ii.skills.json` (고친 뒤 `node tools/build-topik-ii.js`) |

원본을 고쳤으면 시트를 다시 만든다.

```bash
node tools/교원검수시트.js
```

## 지키는 것

- 시트는 원본이 아니다. 시트에만 고치고 원본을 그대로 두면 게임과 앱은 바뀌지 않는다.
- 검수는 문장과 연결이 맞는지 보는 일이다. 학생의 실력·급수 판정이나 학습 효과의 근거로 쓰지 않는다([미니게임 TOPIK I 학습기준](../미니게임_TOPIK_I_학습기준.md)).
- 시험(`tests/교원검수시트.test.js`)은 표의 모양과 읽기를 본다. 저장소의 시트가 지금 원본과 같은지는 강제하지 않고, 돌려받은 시트를 읽을 때 원본이 바뀐 줄을 가려 낸다.
