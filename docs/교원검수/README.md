# 교원 검수 시트

교원이 확인할 것을 원본에서 그대로 뽑은 표 한 장이다. 파일은 [`교원검수시트.csv`](교원검수시트.csv), 만드는 도구는 [`tools/교원검수시트.js`](../../tools/교원검수시트.js)다. 2026-10-05 처음 만들었다(436줄).

게임 문항·상황 예문·연결 초안은 모두 제작용 초안이다. 이 시트로 확인을 받기 전에는 어느 것도 「교원 검수 완료」라고 말하지 않는다. 검수자 섭외는 유호님이 한다.

## 무엇이 들어 있나

| 갈래 | 줄 수 | 무엇 | 교원이 보는 것 |
|---|---|---|---|
| 게임 문항 | 237 | 여덟 게임의 문항(빈칸 베기 37 · 입장 검사 안내문 13과 손님 34 · 선생님이 돌아왔다 9 · 주문 폭주 15 · 바람길 28 · 한국어 리듬 30 · 한국어 레이싱 주제 단계 24 · 말 랠리 47) | 문장이 자연스러운가, 초급(TOPIK I 준비)에 맞는가, 정답이 하나뿐인가, 풀이가 맞는가 |
| 게임 글 | 26 | 「선생님이 돌아왔다」의 여는 글·사이 글·맺는 글 | 읽기 글로 자연스럽고 초급에 맞는가 |
| 상황 예문 | 78 | 배우는 이유가 이어지는 상황 26개마다 그 자리에서 쓰는 말 셋([Strata 예문 층](../Strata_설계.md)) | 그 자리에서 실제로 쓰는 말인가, 초급에 맞는가 |
| 게임↔상황 | 8 | 「이 게임의 연습이 곧 이 상황이다」 초안(주문 폭주 = 주문, 입장 검사 = 공공 안내문 읽기, 바람길 = 길 묻기·작업 지시 듣기)과 상황을 붙이지 않은 게임 넷 | 그 게임의 문장이 그 상황의 말인가, 빠진 연결이 있는가 |
| 문형→능력 | 87 | 초급 문형마다 이어 둔 능력과 단계 | 그 문형이 그 능력에 속하는가, 단계가 맞는가 |

「읽힌 문형」 칸은 지도의 문형 읽기가 그 문장에서 읽어 낸 문형이다. 검수의 실마리이고, 비어 있으면 읽기가 이름 붙이지 못한 것이다(틀렸다는 뜻이 아니다).

## 교원에게 넘기기

1. `교원검수시트.csv`를 Excel로 열거나, Google 스프레드시트에서 「파일 > 가져오기」로 올린다(글자는 UTF-8).
2. 교원은 줄마다 **확인** 칸에 `맞음` · `고침` · `빼기` 가운데 하나를 적는다. 고칠 때는 **고친 내용**에 바꾼 문장을, 이유는 **메모**에 적는다.
3. 새 문항은 **번호**를 비우고 **갈래**와 **내용**(필요하면 자리·정답·보기)을 적은 새 줄로 넣는다.
4. **번호**·**갈래**·**내용** 칸은 고치지 않는다. 번호로 원본을 찾고, 내용이 원본과 달라진 줄은 확인으로 세지 않는다.

## 돌려받은 뒤

```bash
node tools/교원검수시트.js --읽기 <검수한.csv>
```

갈래별로 맞음·고침·빼기·아직을 세고, 고침·빼기·새 문항과 「시트를 만든 뒤 원본이 바뀐 줄」을 나열한다.

```bash
node tools/교원검수시트.js --읽기 <검수한.csv> --적용
```

`맞음`인 상황 예문의 id를 예문 원천(`strata/topik-i.situation-examples.json`의 `review.reviewed`)에 적는다. 그 문장은 계정 요약에서 `reviewed: true`로 나간다. 자동으로 반영하는 것은 이것뿐이다. 고침·빼기·새 문항은 목록을 보고 원본에서 고친다.

| 갈래 | 고치는 원본 |
|---|---|
| 게임 문항·게임 글 | 각 게임의 문항 파일(`experiences/<게임>/content.mjs`·`core.mjs`·`story.mjs`·`instructions.mjs`·`listening-check.mjs`·`curriculum.js`). 고친 뒤 그 게임의 시험을 돌린다(문형 연결 표가 문장과 같은지 본다) |
| 상황 예문 | `strata/topik-i.situation-examples.json` |
| 게임↔상황 | `experiences/synk-account/src/atlas-words.mjs`의 `WORLD_GAMES` |
| 문형→능력 | `strata/topik-i.grammar.json` (고친 뒤 `node tools/build-game-learning.js`) |

원본을 고쳤으면 시트를 다시 만든다.

```bash
node tools/교원검수시트.js
```

## 지키는 것

- 시트는 원본이 아니다. 시트에만 고치고 원본을 그대로 두면 게임과 앱은 바뀌지 않는다.
- 검수는 문장과 연결이 맞는지 보는 일이다. 학생의 실력·급수 판정이나 학습 효과의 근거로 쓰지 않는다([미니게임 TOPIK I 학습기준](../미니게임_TOPIK_I_학습기준.md)).
- 시험(`tests/교원검수시트.test.js`)은 표의 모양과 읽기를 본다. 저장소의 시트가 지금 원본과 같은지는 강제하지 않고, 돌려받은 시트를 읽을 때 원본이 바뀐 줄을 가려 낸다.
