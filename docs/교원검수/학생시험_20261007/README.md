# 학생 사용성·새 문항 확인 시험 준비

2026-10-07 · **실행 준비물. 참여자 0명, 미실행.** 모집·교원 검수·학생 결과·공개 배포를 완료한 자료가 아니다. 사람이 정해지면 아래 진행표와 빈 기록표로 한 사람씩 진행할 수 있다. 이 작업에서는 사람에게 연락하거나 GPT·Claude·Jev를 추가 호출하지 않았다.

확인할 것은 **자연 오답 또는 도움 받은 답 → 짧은 해설 확인 → 다른 같은 목표 문항의 첫 응답**과 그 과정의 사용성이다. 이번 회차에서 새 문제를 도움 없이 맞혔는지 보며, 한 번의 성공을 교정 효과·숙달·TOPIK 급수 상승으로 해석하지 않는다.

## 준비물과 범위

- [진행·관찰표.html](진행·관찰표.html): 교사/관찰자용 진행표와 빈 관찰표. 브라우저에서 열고 A4 세로로 인쇄하거나 화면에서 보며 종이에 기록한다. 학생에게 정답 자료를 먼저 보여 주지 않는다.
- [빈관찰표.json](빈관찰표.json): 참가자와 관측 배열이 비어 있는 기록 양식. 원본을 채우지 말고 `학생시험_P01_작성본.json`처럼 복사한 파일에 적는다. 빈 값은 `null`, 관측 없음은 빈 배열로 유지한다.
- 대상안: 한국어 초급 성인 학습자 **3~5명부터**, 아직 섭외·일정은 없음. 소규모 결함 발견용이며 모집 인원이나 표본 대표성을 확정한 것이 아니다. 미성년자를 포함할 별도 운영은 이 준비물에 포함하지 않았다.
- 한 사람 **15~20분**, 입장 검사 한 근무와 선택 활동 **하나**만. 기본 선택은 바람길의 별도 듣기 확인 3문제다. 준비된 WORLD 시험 연결이 있는 경우에만 Town 안내문 읽기 3문항으로 바꾼다. 네 게임 순회·레이싱 완주는 시키지 않는다.
- 참가자는 `P01` 같은 임의 코드만, 관찰자도 코드만 적는다. 이름·학생번호·연락처·학교·생년월일·정확한 나이·사진·음성·대화 녹취·계정 토큰은 기록하지 않는다. 메모는 관찰자의 짧은 행동 요약으로 남긴다. 실학생 로그인·기존 수업 기록·모델 서비스 전송은 사용하지 않는다.

## 시작 전: 시행자가 확인할 것

1. 담당 교사가 사용할 문항·정답·해설·선택 오답별 교정을 [교원 검수 시트](../README.md)와 [오답 교정·새 문항 검수 부록](../오답교정_새문항_검수부록.html)에서 확인한다. `맞음/고침/빼기`는 실제 사람이 작성한다. 수정 요청은 먼저 원고에 반영하고, 그날 사용할 버전을 기록한다. 게임 단계·태그는 제작용이며 공식 난도 표준이 아니다.
2. 시험 전용 새 브라우저 프로필/세션을 준비한다. 기존 개인·학생 프로필의 저장소를 지우지 않는다. 교사의 기능 확인과 참가자 수행도 서로 다른 빈 세션을 사용한다. 기기·화면 크기·소리 상태와 사용한 소스 버전/해시를 기록한다.
3. 저장소 루트에서 `node experiences/learning-hub/server.mjs`를 실행한다. 기본 주소는 [입장 검사](http://127.0.0.1:4280/entry-check/)와 [바람길](http://127.0.0.1:4280/korean-runner/)이다. 같은 origin을 유지한다. 이는 실행 주소 예시이며 현재 서버 구동·공개 배포 확인을 뜻하지 않는다. 포트를 바꾸면 두 주소와 기록표를 함께 바꾼다.
4. Entry는 ‘하늘 수영장’ 첫 자유 근무, 바람길은 입구의 **듣기 확인 3문제**를 사용한다. 90초 달리기는 이 시험에 넣지 않는다. 바람길의 MP3가 실제로 들리고 종료 후 보기가 열리는지 교사가 별도 세션에서 확인한다.
5. Town으로 바꾸려면 [기존 local-linked WORLD 연결 절차](../../../experiences/teacher-world/README.md)를 따라 시험 코드만 가진 가상 연결을 미리 준비한다. WORLD에서 Town을 열고 **읽기 확인 3문항**을 누른다. `/synk-town/linked.html`을 단독으로 열어 권한을 우회하지 않는다. 연결이 준비되지 않았으면 기본 바람길을 사용한다. 시험용 과제의 영역·난도·item/family 목록·총수를 적고 늘리지 않는다.
6. 참여자가 목적·기록 범위·그만둘 수 있음을 이해했는지 현장에서 확인한다. 참여하지 않거나 중단해도 불이익 없음을 말한다. 녹음·영상·외부 전송 없이 진행하며 작성본은 담당자의 제한된 로컬 위치에 보관한다. 보관 기간과 파기 시점은 시행자가 시작 전에 정해 기록한다.

소스가 바뀌면 이전 검수·이 문서의 예시를 새 버전에 자동 적용하지 않는다. 최신 원고와 실행판을 다시 대조한다. 부록이 아직 만들어지지 않았거나 변경 원고가 들어갔으면 해당 원고 파일을 교사와 직접 대조한다. 준비물의 완성과 인간 검수 완료는 별개다.

## 한 사람 진행표

| 경과 시간 | 할 일 | 관찰자 행동 |
| --- | --- | --- |
| 0~2분 | 목적·코드·기기·중단 안내 | “오늘은 화면과 설명이 이해되는지 봅니다. 모르면 도움을 써도 되고 언제든 그만해도 됩니다.” |
| 2~4분 | Entry 첫 근무 연수 | 조작을 익힌다. 연수에서 본 `pool-01/02`와 정답 공개를 노출·도움으로 적는다. |
| 4~11분 | Entry 첫 근무, 최대 6명 | 혼자 선택하게 기다린다. 자연 오답/도움 뒤 설명과 다음 문항을 관찰한다. 11분이 되면 미완료로 기록하고 쉬거나 다음 활동으로 간다. |
| 11~16분 | 바람길 **또는** Town 3문항 | 같은 목표의 새 문항 표시·첫 응답·도움·결과줄을 본다. 피곤하거나 원치 않으면 생략한다. |
| 16~18분 | 짧은 회고 | “다음에 무엇을 해야 하는지 알았나요?”, “틀린 답과 맞는 답의 차이를 알았나요?”, “설명 읽을 시간이 있었나요?”만 묻는다. |
| 18~20분 | 기록 확인·마침 | 누락을 `unknown/not_observed`로 남긴다. 시험 세션을 닫고 작성본을 보관한다. 다음 참가자는 별도의 빈 세션이다. |

시간은 진행 상한이며 언어 응답의 제한 시간이 아니다. 20분에 멈춘다. 게임 총수를 늘리거나 품절된 문항을 끼워 넣지 않는다. 쉬고 싶다는 말·불편함·소리 문제·연결 오류가 생기면 바로 중단하거나 쉬게 하고, 기술 문제를 언어 오답으로 적지 않는다.

## 오답이 나왔을 때: 유도하지 않고 관찰

1. 학생에게 일부러 틀리게 하거나 특정 보기를 고르게 하지 않는다. 정답을 맞힌 뒤 관찰을 위해 다시 오답을 찍게 하지 않는다.
2. 설명이 보이면 먼저 기다린다. “이 설명을 보고 다음으로 가 주세요” 같은 중립 진행 안내만 한다. 단어 뜻·번역·규칙 지목·정답 설명은 **교사 언어 도움**으로 별도 기록한다. 첫 응답 중 생각을 소리 내어 설명시키지 않는다.
3. 설명의 자동 소실/잘림, 읽기 중 다음으로 넘어감, 다시 듣기 요청, 다음 버튼을 찾는 데 막힌 횟수와 관찰된 시간을 적는다. 설명이 잠깐 보였다는 것과 학생이 이해했다는 것을 구분한다.
4. 제품이 의도적으로 **새 후속 문항**을 골랐을 때만 source/target 한 쌍으로 적는다. 가까이 나온 두 문항, 서로 다른 게임의 답, 같은 문항의 재정답을 임의로 연결하지 않는다. 영역·난도·형식과 다른 item/family인지 확인한다. Entry는 영역만 같고 안내 규칙이 달라질 수 있으므로 **같은 규칙/같은 영역만/미확인**을 따로 적는다.
5. 다음 첫 응답 전에 UI 힌트·글 보기·추가 재청취·교사의 언어 도움을 구분한다. 바람길의 실패한 첫 재생 재시도와 끝까지 들은 뒤 추가 재청취, 답한 뒤 복습 재생도 구분한다. 최초 판정을 재채점하지 않는다.
6. 결과줄과 사람이 본 사실이 일치하는지 적는다. 교사가 언어 도움을 줬는데 UI가 독립이라고 표시했으면 관찰표는 **도움 받은 수행**으로 남기고 불일치를 문제로 적는다. 외부 도움은 게임이 자동 감지하지 못한다. 답 전 노출을 확인할 수 없으면 새 문항 성공으로 세지 않는다.

모든 답이 독립 정답이거나 마지막/품절/범위 제한으로 새 후속 문항이 없으면 **교정 흐름 미관찰**이다. 시험 실패나 성공으로 채우지 않는다. 해당 학생의 사용성 관찰은 그대로 남긴다.

## 문항을 찾는 기준: 순번 대신 실제 ID

아래는 **교사 사전 대조용 예시**다. 추천 순서와 출현을 보장하지 않으며 학생에게 보여 주는 정답지가 아니다. 화면에 실제 나온 ID를 기록한다. `첫째 손님/2번 보기`만으로 문항이나 정답을 식별하지 않는다.

## 기록의 판정과 다음 결정

**분모를 먼저 남긴다.** 참가자 수, 활동 시작/완료/중단/생략 수, 자연 오답·도움 발생 수, 새 후속 문항 제안 수, 실제 시행 쌍 수, 새 노출·목표·도움이 확인된 쌍 수를 각각 센다. 같은 사람의 여러 답을 독립 참가자 수로 세지 않는다. 없거나 미확인인 것을 정답률 분모에서 조용히 빼지 않는다.

| 회차 신호 | 조건과 기록 |
| --- | --- |
| `independent-correct` | 의도적 다른 새 item/family, 같은 측정 목표·난도·형식, 첫 응답·기본 음성 완료(듣기), UI/교사 언어 도움 없음, 정답. **이번 새 문항에서 혼자 성공**까지만. |
| `independent-incorrect` | 위 노출·목표·도움 조건은 같고 첫 응답이 오답. 학생 문제로 단정하지 않고 원고/설명/조작을 다시 본다. |
| `assisted-correct/incorrect` | 새 문항에 답하기 전 UI 또는 교사 언어 도움 있음. 정오를 따로 남기며 혼자 성공에 합치지 않는다. |
| `unavailable` | 반복·목표 불일치·노출 미확인·음성/기록 실패·첫 응답 불명·ID 불명 등의 확인 부족. 사유를 남긴다. |
| `not_observed` | 자연 오답/도움 없음, 후속 미제안, 시간/피로/참여자 중단으로 쌍을 실제 수행하지 않음. 학습 성공/실패로 바꾸지 않는다. |

사용성은 시작·도장/이유 선택·설명 읽기·다음 버튼 찾기·중단/도움 요청을 **교사 조작 안내 없음/있음**으로 따로 센다. 말의 도움과 기기 조작 도움을 같은 항목으로 합치지 않는다. 설명을 읽은 시간은 참고 수치이며 이해/학습 점수가 아니다. 회고의 자가 보고도 실제 새 문항 응답을 대신하지 않는다.

- **즉시 멈추고 고칠 것:** 정답·풀이 모순 1건, 강제 진행으로 설명을 못 읽음 1건, 소리 실패를 오답으로 기록 1건, 이전 노출/교사 언어 도움이 있는데 독립 새 성공으로 보고되는 불일치 1건, 신원 정보 노출. 해당 조건의 교육 신호는 보류한다.
- **첫 소규모 후 수정 우선:** 같은 조작/설명 지점에서 서로 다른 2명이 막히거나 도움을 요청하면 그 지점을 먼저 고친다. 1명 사례도 버리지 않는다. 2명은 통계적 유의성 기준이 아닌 개발 우선순위다.
- **더 관찰할 조건:** 대부분 쌍이 없거나 품절·ID 미확인·도움으로 갈라지면 “잘 됐다” 대신 다음 판에서 해당 목표의 미노출 풀·기록·설명을 먼저 보완한다. 3~5명으로 모델 우열·학습 효과·급수 향상을 확정하지 않는다.

## GPT·Claude·Jev 후속 비교는 별도

이 시험은 **Core와 현재 작성된 해설**을 사용한다. [기존 실제 54개 비교](../../../tools/learning-blind/README.md)는 합성 이력의 후보/근거 선택 시험이며 교사 품질과 학생 효과가 미평가다. 이번 학생 기록을 그 모델들의 학습 결과로 붙이지 않는다.

후속 모델 비교를 설계할 때는 Core를 대조군으로 포함하고, 검수된 동일 후보·같은 목표·충분한 새 문항 수·동일 노출/도움 조건·같은 UI를 사용한다. 검토자는 모델명을 가린 자료로 보고 후보 순서 효과를 분리한다. 같은 학생에게 같은 문제를 세 모델로 되풀이하면 후속 응답이 새 문항이 아니므로 독립 정답 비교에 쓰지 않는다. 기존 개발 18사례와 별도 문항/사례를 준비하고, 제한형 후보 선택과 GPT/Claude의 자유 설명 생성은 별도 기능으로 평가한다. 실제 사용자 결과를 보려면 다른 미노출 동등 문항과 순서 배치를 사전 고정해야 한다. 이는 조건 정리이며 추가 호출·모델 원고 생성·제품 연결을 실행하지 않았다.
