# 발표물 브랜드 키트 — 현재 제작 기준

> 2026-09-10 정리. 발표·소개·인쇄의 적용 기준과 §3의 정밀 심볼 도형을 유지한다. 공통 디자인은 [DESIGN](../../DESIGN.md), 값은 [디자인 토큰](../디자인_토큰.json), 로고 선택은 [현행 로고 정본](../로고_중립색_정본_v1.md)을 따른다.

현재 규칙을 링크한 것과 기존 HTML·PDF를 갱신한 것은 다르다. 자립형 출력은 원본 토큰·현재 자산에서 다시 만들고 실제 결과를 확인한다.

## 0-b. 재질 — 펠트와 정보 판의 역할

장식의 중심은 승인된 펠트 실물이다. 납작한 단색·CSS 그림자를 승인 펠트의 대체품으로 보고하지 않는다. 승인 자산을 보존하고 실제 지면에서 크기·섬유·접지·읽힘을 확인한다.

정보 판은 [DESIGN §2](../../DESIGN.md#2-색마스코트재질)의 현재 역할대로 무광 천·유리·패턴지 중 선택한다. 유리는 뒤가 보여야 하는 판, 무광 천은 조용한 정보 바닥, 패턴지는 도안·계획의 결이다. 선택 가능한 판을 과거의 ‘판정 보류’로 되돌리지 않는다. 레진은 해당 Loom 문법의 히어로 1점에 한정한다. 본문 글자는 재질 없이 또렷하게 둔다.

## 1. 색 — 원천과 출력의 동기화

색값은 [디자인 토큰](../디자인_토큰.json)의 현행 역할에서 읽고 `tools/토큰빌드.js`와 실제 제작기의 소비 결과를 확인한다. 이 문서에 옛 색표·대비표·이관 대응표를 복제하지 않는다.

- 새 제작의 바탕·잉크·보조 정보·신호는 DESIGN과 토큰의 역할을 따른다. 과거 출력에 남은 퇴역 대기 무채를 새 기본값으로 복사하지 않는다.
- 밝은 바탕의 Coral 몸통은 면용이며 글자는 허용된 바탕의 Coral 3 또는 Ink의 굵기로 강조한다. Coral 면의 글자는 Ink다.
- 사업별 승인 로고색과 캐릭터 고유색을 일반 행동 신호와 혼동해 재칠하지 않는다.
- 한 지면의 주연·조연과 읽는 순서를 정한다. 골드·새 액센트를 임의로 더하지 않고 강조는 크기·굵기·여백으로 편집한다.
- 색이 바뀌면 원천→제작기→해당 HTML·PDF를 함께 대조한다. HEX 이름이나 과거 대비 수치만으로 실제 표시 결과를 판정하지 않는다.

자립형 HTML 안에 포함된 CSS는 배포 결과다. 값을 고치기 위해 출력물만 손으로 변경해 원천과 갈라지게 하지 않는다.

## 2. 서체 — 역할과 로드

[폰트 정본](../브랜드_폰트_정본.md)의 역할·순서·웨이트·예외를 따른다. 한글은 SUIT Variable, 라틴·키릴은 Inter Tight, 모노 역할은 DM Mono다. Inter Tight가 SUIT 앞에 오며 DM Mono에 한글·키릴을 넣지 않는다.

동등한 몽골어 병기는 1.04배 광학 보정을 따른다. 제목·본문 위계는 승인 폰트의 크기·굵기·간격으로 만든다. 인쇄/PDF의 실제 임베드와 글리프를 확인한다. 로고를 본문 폰트로 다시 조립하지 않는다.

## 3. 로고 — 사용처와 보존 도형

### 어느 자리에 무엇을 쓰나

[현행 로고 정본](../로고_중립색_정본_v1.md)의 완성 조합을 선택한다.

| 자리 | 사용 |
|---|---|
| 기업 소개·홍보에서 재질을 보여주는 로고 | 현행 사진형 펠트 킷의 단독 SYNK 또는 SYNK+사업명 전체 |
| 작은 인쇄·파비콘·정확한 도형·1도 인쇄 | 현행 정밀 SVG. 실제 크기에서 철자·윤곽을 확인 |
| 앱·내부 이름 | 실행 정본의 `syn<` |
| 내부 진행·로딩·도장·워터마크 | 실행 정본의 기호 `<`·도장. 뒤로가기 자리인 상단바 왼쪽에는 놓지 않음 |
| 별도 승인 심볼 | 아래 S1 도형 또는 승인된 고리·배지 원본을 해당 용도에 사용. 새 대외 기본 로고로 자동 승격하지 않음 |

대외 SYNK는 밝은 배경 Ink·어두운 배경 Paper다. 09-10 승인에 따라 SYNK 네 글자의 실땀만 제거하고 펠트 섬유·두께·그늘·형태를 유지한다. 사업명은 LAB 코랄·SHIFT 파랑·PULSE 베리와 기존 스티치를 유지한다. 내부 꺾쇠의 코랄 신호는 별도다. 작은 자리의 읽힘을 재질 과장보다 먼저 확인하고, 사업명이 어두운 바탕에서 흐려지면 밝은 패널에 전체 조합을 놓는다.

k의 솟음·자간·기존 도형을 유지한다. 벡터 `syn<`의 T4 꺾쇠와 단독 기호의 획은 다른 용도의 도형이며 두께를 임의로 통일하지 않는다. 신호도 이름과 같은 펠트 재질이다. `//`는 잉크의 저채도 표현이며 골드·새 액센트를 추가하지 않는다.

### 벡터 생성기의 표현 범위

도형·필터·광학 여백의 실행 원천은 `tools/lib/로고정본.js`다. 소비자는 모듈 또는 CLI `--json`으로 받는다. 발표물 슬롯은 `tools/로고주입.js`가 이 원천을 사용한다.

기존 벡터 생성기는 표시 폭 180px 미만에서 민판, 큰 자리에서 펠트판을 선택하는 문법을 가진다. 이는 그 벡터 표현의 기준이며 사진형 자산 전체를 민판으로 바꾸거나 모든 인쇄물에 같은 재질을 강제하는 규칙이 아니다. 실제 크기·배경·철자·섬유를 비교해 해당 자산을 선택한다.

특별판 알록과 대안은 실행 원천에서 받고 110px 미만에 쓰지 않는다. 일반 상시 마케팅의 기본으로 쓰지 않으며, 기존 승인된 큰 앱 스플래시의 상시 사용 예외는 해당 제품 범위에서 유지한다. 몸만 재칠해 다른 색의 보풀·그늘을 남기지 않는다.

### 정밀 심볼 도형 — 좌표 보존

아래 SVG 블록은 기존 승인 좌표·viewBox·획을 그대로 보존한 S1이다. 현재 기업 워드마크·사업명 조합의 대체품이 아니다. 소비자가 재작도하거나 viewBox 여백을 잘라 획·보풀을 손상시키지 않는다.

```html
<!-- S1 심볼 ~^^< (= s·y·n·k) · 어두운 바탕. 밝은 바탕은 stroke 를 Ink #2B2320 로 -->
<svg viewBox="0 0 240 110" role="img" aria-label="SYNK">
  <g fill="none" stroke="#FBF7F0" stroke-width="11" stroke-linecap="butt" stroke-linejoin="miter">
    <path d="M10 62 C17 50, 29 50, 36 60 C41 67, 48 67, 52 58"/>
    <path d="M68 68 L88 34 L108 68"/>
    <path d="M124 68 L144 34 L164 68"/>
    <path d="M228 22 L186 52 L228 82"/>
  </g>
</svg>
```

### 고리·배지·모션

승인된 고리·몽글 배지는 별도 실물 자산이다. 생성 경로는 `tools/룸굽기.js`의 해당 로고 부품이며, 사진형 워드마크는 [현행 킷](../홍보물/마케팅실행_20260909/브랜드킷/index.html)을 사용한다. 도구에 후보가 있다는 사실을 현재 사용 승인으로 세지 않는다.

고리 모션은 떨어진 두 실이 다가와 겹친 뒤 위아래로 엮여 연결되는 사건을 표현한다. 마지막이 승인 정지 심볼과 이어지게 하고, 형태 전체를 꿈틀거리게 만들지 않는다. 움직이는 판의 프레임별 그레인·자산 가장자리·알파·배경은 실제 재생으로 확인한다.

## 4. 모티프 — 시냅스 노드

여정·관문·연결은 SYNK의 동기화 의미와 이어지는 노드·링크로 표현한다. 미승인 게르 천창·문화 상징을 대외 인쇄물에 기본 적용하지 않는다.

## 5. 대상별 밀도

학부모·상담 자료에는 선택에 필요한 조건·근거·다음 행동을 충분히 제공한다. 국적이나 나이만으로 조밀함·미니멀 선호를 단정하지 않는다. 읽는 순서와 실제 크기를 확인하고 [명품 기준](../명품_기준_v1.md)의 가까운 승인 실물과 비교한다. 정보 본문에 디더·리소 같은 감성 표현을 강제로 적용하지 않는다.

## 6. 인쇄 규격 — 전 산출물 공통

- `@page { size: <용지>; margin: 0 }`, `print-color-adjust: exact`를 선언하고 실제 출력에서 머리말·URL·배경을 확인한다.
- 이미지·폰트·CSS를 포함한 자립형 1파일로 전달한다. 외부 CDN 의존을 남기지 않는다.
- 흑백 복사에서도 뜻을 알도록 색+패턴·문자를 함께 사용한다.
- 편집용 가이드선·설명은 인쇄면에 남기지 않는다.
- 미확정 필드는 작업본에서 비워 ‘채워야 할 칸’으로 관리한다. 공개본을 만들 때는 현재 계약과 확인한 값으로 채우거나 해당 내용을 제외한다.

## 7. 검사

`node tools/발표물린트.js docs/발표물/*.html` 등 기존 제작·검사 통로를 사용한다. 실제 검사 범위는 도구의 현재 코드를 따른다.

로고 원본·색·폰트·외부 자원·인쇄 규격의 기계 확인과 함께 실제 크기 렌더·줄바꿈·내용 밀도·흑백 읽힘을 본다. 문서 규칙을 최신화한 것, HTML/PDF를 재제작한 것, 전달·게시한 것을 구분해 기록한다.
