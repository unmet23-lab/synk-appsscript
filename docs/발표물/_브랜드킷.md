## 0-b. 재질 — 펠트 단독 (2026-08-20 유호님 확정)

- **글래시(체리 젤리 유리 재질)는 완전 기각** — 발표물·소개서 어디에도 넣지 않는다.

  요소 실물은 `tools/요소굽기.py` 산출물을 쓴다(2026-08-20 현재 8종+추가 굽는 중 ·
  `docs/캐릭터/퍼프로브_0819/`) — 재질을 손으로 새로 그리지 않는다.
- **펠트의 하한은 「명품」이다**(유호님 원문 08-20: 「대충 만든 펠트 저급한 느낌이 아니라
  지금처럼 여러 번 굽고 정말 만족스러운 명품 느낌의 펠트 재질로 — 꼭 이렇게」).
  집행급 렌더(입체 섬유·재굽기 반복·검수 통과)만 지면에 들어간다 — 납작한 단색 흉내·
  CSS 그림자로 때운 「펠트풍」은 펠트가 아니라 위반이다. 품질 축(§DESIGN.md 1
  「기능 좋고 디자인 트렌디한 명품」)의 재질판 집행이다.
- **PDF 로 나가는 소개서**는 §1 킷 색(08-18 무채 중성축)과 펠트 요소로 UI·UX 를 전부 꾸며 짓는다.
- **정보 판 재질은 ⏳판정 보류다**(유호님 08-20 「전부 다 제대로 만들고 나중에 결정」 —
  CSS 근사 시안에서는 패턴지와 유리가 같아 보였다 · 근사로는 못 가른다가 실측됐다).
  후보 = 반투명 판 **패턴지(재단지) vs 유리** · 카드·판 바닥 = **다린 무광 천**.
  셋 다 집행급(요소굽기)으로 지은 뒤 실물로 판정한다 — 판정 전까지 새 산출물이
  어느 쪽도 «확정»으로 인용하지 않는다. 패턴지 추천의 근거 셋(①글래시 모순 0
  ②한 세계 — 레진은 1점 액센트로 존속 ③위계 = 만든 것 펠트 / 받치는 것 종이·천)은 기록으로 남긴다.

(현행판에 있다 — 본문 절이 아니라 이력 표다). ⚠단 그 행은 FIELD 색 축이라
`#1A237E`·`#FFC400` 두 색의 대응은 거기 없고, `#3D5AFE`의 대응(KC Cool Blue)은

## 3. 로고 — 2026-08-04 유호님 확정

**메인 = `W5`(축약) + `W1`(풀).** 나머지는 자리에 맞춰 꺼내 쓰는 보조 라이브러리다.
전체 후보와 근거 = `docs/발표물/로고/후보시트.html` (브라우저로 열면 됨).

🔑 **로고는 그림이 아니라 글자다.** `syn<` = s·y·n·`<`, 심볼 = `~ ^ ^ <` 넉 자(= s·y·n·k).
전부 타이핑 가능한 글자라 **벡터 도형으로 다시 그렸다** — 외부 이미지 0건이라
자립형 1파일 규칙을 그대로 지키고, 인쇄에서 무한 확대해도 안 깨진다.

### 어느 자리에 무엇을 쓰나

| 자리 | 쓰는 것 | 왜 |
|---|---|---|
| 인쇄물 머리 띠 · 명함 · 앱 상단 · 도장 | **W5** (`syn<`) | 가장 깔끔하고 가로가 짧다. 기본값이다 |
| 표지 · 배너 · 챕터 간지 (가로 넉넉) | **W1** (`syn< //`) | 슬래시까지 들어가야 브랜드가 완성된다 |
| 위 둘을 **밝은 바탕**에 | W5-L · W3 | 슬래시 색만 바뀐다(아래 규칙 ②) |
| 정사각 자리 · 워터마크 · 앱 아이콘 | S1(어두움) · S4(밝음) | 심볼 단색 |
| 복사·팩스·1도 인쇄 | W6 | 색 없이 형태만으로 성립 |
| 가로로 긴 사인 · 이메일 서명 | L1 | 심볼 + 구분선 + 워드마크 |
| 인쇄물 머리 띠 풀 락업 | L3 | W5 + 「SYNK LAB」 + 슬로건 |

### 색 규칙 — 두 줄

① **`<`는 언제나 Coral `#F96859`** — 로고에서 유일한 신호다. 배경을 안 탄다.
   ⚠ 라이트에서 2.62는 **도형이라 기준 적용 제외**다. 코랄로 **글자**를 쓰는 자리라면 Coral 3 `#AE322A`.
② **`//`는 세 번째 색이 아니라 잉크의 저채도** — 다크 = Chalk 50%, 라이트 = Graphite 4 45%.
   구판은 배경 따라 골드↔블루를 갈아 끼웠는데, 그러면 로고가 3색이 되어 「2색 + 신호 1점」이 깨진다.
   신호를 `<` 하나로 남기니 **배경을 타는 문제 자체가 사라졌다.**

대비 실측(WCAG 상대휘도 · 후보시트가 페이지에서 직접 계산한다):

| | Graphite `#08090C` | Paper `#FBF7F0` |
|---|---|---|
| Chalk `#E4E4E7` | **15.69** ✅ | 1.19 ✗ 사라짐 |
| Coral `#F96859` | **6.78** ✅ | 2.75 — **면만**, 글자 ✗ |
| Coral 3 `#AE322A` | 3.12 — 24px↑ 만 | **5.98** ✅ 본문 글자까지 |
| Graphite 3 `#262626` | 1.32 ✗ 묻힘 | **14.17** ✅ |
| Graphite 4 `#373737` | 1.67 ✗ 묻힘 | **11.15** ✅ |

`syn` 글자색: 어두운 바탕 = **Chalk `#E4E4E7`** / 밝은 바탕 = **Graphite 3 `#262626`**(순검정 금지).
🔑 구 팔레트는 웜화이트 하나가 「바탕」과 「다크 위 글자」를 겸했다. 키트는 그 둘이 다른 색이다 —
바탕은 Paper, 다크 위 잉크는 Chalk. 일괄 치환하면 이 자리가 조용히 어긋난다(실제로 어긋났다).

### 도형 정본 — 복붙하지 말고 이걸 붙인다

각 HTML의 `<!-- LOGO SLOT -->` 자리에 아래를 넣는다. 좌표는 **한 곳에서만** 고친다 —
처음에 카드마다 path를 복붙했다가 심볼 간격을 넓히자 락업 두 개가 조용히 깨졌다.

```html
<!-- W5 축약 워드마크 · 어두운 바탕 -->
<svg viewBox="-8 -2 181 116" role="img" aria-label="SYNK">
  <text x="0" y="86" font-family="Inter Tight, system-ui, sans-serif"
        font-size="72" font-weight="600" letter-spacing="-1" fill="#E4E4E7">syn</text>
  <path d="M138 44 L112 66 L138 88 L150 88 L124 66 L150 44 Z" fill="#F96859"/>
</svg>

<!-- W1 풀 워드마크 = W5 + 슬래시. 「//」는 잉크의 저채도다 —
     어두운 바탕 fill="#E4E4E7" opacity=".5" / 밝은 바탕 fill="#373737" opacity=".45" -->
<!-- viewBox 를 "-8 -2 296 116" 으로 넓히고 아래 두 줄을 더한다 -->
<path d="M196 92 L216 40 L228 40 L208 92 Z" fill="#E4E4E7" opacity=".5"/>
<path d="M234 92 L254 40 L266 40 L246 92 Z" fill="#E4E4E7" opacity=".5"/>

<!-- S1 심볼 ~^^< (= s·y·n·k) · 어두운 바탕. 밝은 바탕은 stroke 를 #262626 로 -->
<svg viewBox="0 0 240 110" role="img" aria-label="SYNK">
  <g fill="none" stroke="#FBF7F0" stroke-width="11" stroke-linecap="butt" stroke-linejoin="miter">
    <path d="M10 62 C17 50, 29 50, 36 60 C41 67, 48 67, 52 58"/>
    <path d="M68 68 L88 34 L108 68"/>
    <path d="M124 68 L144 34 L164 68"/>
    <path d="M228 22 L186 52 L228 82"/>
  </g>
</svg>
```

⚠ **viewBox 여백을 깎지 말 것.** 획 두께(11)의 절반과 글자 사이드베어링이 여기 들어간다.
줄이면 `<`의 아래팔과 `s`의 왼쪽이 잘린다(실측으로 두 번 겪었다).

### 남은 것

- ⏳ **원본 벡터 파일(.ai/.svg)이 있으면 그게 가장 정확하다.** 지금 `syn`은 서체로 조판한
  것이라 Inter Tight가 없는 기기에서는 자형이 미세하게 달라진다.
  `<`·`//`·심볼은 순수 도형이라 이 문제가 없다.
- 🔴 **서체 정본과 충돌 1건** — 브랜드 폰트 정본은 「워드마크 = DM Mono」로 잠겨 있는데
  실제 로고는 모노스페이스가 아니라 그로테스크다. **실물 로고가 규칙보다 뒤에 나왔으니
  로고가 이긴다.** 폰트 정본의 그 줄은 「워드마크는 로고 정본을 쓴다」로 고쳐야 한다.

| 심볼·도장·워터마크 | 고리 — 양모 실 두 가닥 | 벡터(시안 캔버스) · 실물 촬영 후보 |

| 모션·영상 | 공명 — 플라이드 얀 | 모션 트랙(후속) |

- **렌더판의 통로는 하나다**: `node tools/룸굽기.js --굽기 로고꺾쇠` · `--굽기 로고배지`

## 5. 대상별 밀도 — 학부모물은 촘촘하게

디자인 컨셉 정본의 미해결 리스크: 몽골 학원 광고는 정보가 빽빽하고 화려해서,
흑백 여백 미학은 10~20대에겐 세련돼 보여도 **학부모에겐 「내용 없음」으로 읽힐 위험**이 있다.
처방은 규칙 3개는 유지하고 **밀도만 분리**하는 것이다.

- **학부모·상담 대면물(발표물 대부분)** = 밀도 높게. 여백으로 멋 부리지 않는다.
- SYNK FIELD 표현 모드(디더·리소 2도)는 이 인쇄물들에 **적용 제외**다
  (디자인 컨셉 정본 「적용 제외(불가침)」에 학부모 신뢰 문서 본문·몽골어 정보 화면이 명시).

## 6. 인쇄 규격 — 전 산출물 공통

- `@page { size: <용지>; margin: 0 }` — 여백 0으로 잠가 크롬이 머리글에 날짜·URL을 찍는 것을 차단.
- `print-color-adjust: exact` — 배경색을 인쇄에 살린다.
- 외부 링크·이미지·폰트 CDN **0건**(자립형 1파일).
- 흑백 복사 대비: 구분은 **색 + 패턴 이중 표기**. 색으로만 구분되는 정보를 만들지 않는다
  (몽골 현지에서 재복사될 것을 전제한다).
- 화면 편집용 표시(가이드선·설명)를 인쇄면에 남기지 않는다.
- 미확정은 지어내지 말고 「____」로 비우고, 산출물 끝에 「채워야 할 칸」으로 모은다.
