## 생성 범위와 방법

- 기존 `tools/발표물빌드.js`를 사용했다.
- 이 빌더에는 개별 파일 선택 인자가 없다. 기존 `SYNK_PRESENT_ROOT` 입력을 작업 폴더로 지정하고 상담 브로셔 원고 한 개만 넣었다.
- `node tools/발표물빌드.js --pdf`: 발표물 1종, 실패 0건.
- 동일 폴더를 대상으로 `node tools/발표물빌드.js --check`: HTML 원고·산출물·현재 Loom 주입 대조 통과.
- 검증한 HTML·PDF를 원래 `docs/발표물/03_상담브로셔_A4_12쪽.html`·`.pdf` 경로에 복사했다.
- 시작 전 발표물 최상위 파일의 SHA-256과 종료 시 파일을 대조했다. 달라진 파일은 이 원고·HTML·PDF 3개뿐이다. 새 QA 파일은 이 폴더에만 추가했다.

## 기존 문서에서 이어진 차이와 한계

### 현재 색상 키트 검사

`docs/tools/인쇄물_키트검사.py <해당 PDF> --pages 12`의 쪽수와 실제 사용 폰트 검사는 통과했다. 색상 검사는 원본 PDF와 새 PDF 모두 같은 이유로 실패했다.

- 기존 배경색 `#FBF7F0`가 현재 토큰에서 키트 밖 색으로 판정됨.
- 원본과 새 PDF 모두 38회 사용. 이번 수정에서 새로 생긴 색이 아니다.
- 요청 범위가 최신 디자인 변경을 제외하므로 이 배경색과 기존 디자인을 유지했다. 따라서 전체 키트 검사까지 통과했다고 보고하지 않는다.

### p11 편지 아이콘

기존 PDF의 편지 아이콘은 현재 원고에서 빌드되는 HTML의 내장 이미지와 달랐다. 재출력에서는 현재 HTML에 이미 들어 있던 이미지로 맞춰졌다. 이번 수정 전·후 HTML의 해당 이미지 데이터와 CSS는 같다.

- p11의 128×128 이미지: 전후 동일.
- p11의 256×256 편지 이미지: 기존 PDF와 새 PDF가 다름. `p11-image-comparison.json`에 지문을 남겼다.
- 따라서 p11에서 시각적으로 달라진 범위를 문단만이라고 표현하지 않는다. p11 외 11쪽은 픽셀 단위로 동일하다.
