## 1단계 · 데이터 준비 (앱 열기 전에, 시트에서 — ★이게 제일 중요)

앱은 시트를 비추는 거울입니다. 시트에 데이터가 비어 있으면 앱도 빕니다.

### 1-1. 학생 반 배정 (상담 스프레드시트에서)
- **상담 스프레드시트 → `상담데이터입력` 탭 → "반" 열**에 각 학생의 반 이름 입력.
- 값은 앱 시트 `schedule` 탭의 반 이름과 **글자까지 똑같이**: `정규반1` ~ `정규반15` (현재 시간표에 등록된 15개).
- 반영: 다음 날 아침 7시 자동. **지금 바로** 반영하려면 → Apps Script 편집기에서 `syncProfiles` 실행(방법은 2단계 참조).

### 1-2. 강사 담당 반 (앱 스프레드시트 `profiles` 탭에서 직접)
- 강사 행(role=teacher)의 **E열 class_name**에 담당 반 입력. 여러 반이면 쉼표: `정규반1,정규반2`
- 이걸 안 하면: 수업 전 브리핑 메일·미등원 통보가 그 강사에게 안 감.
- 안심: 매일 아침 동기화는 **비학생 행을 보존**하므로 직접 입력한 값이 지워지지 않습니다(코드 확인).

### 1-3. 학부모 ↔ 자녀 연결 (앱 `profiles` 탭에서 직접)
- 학부모 행(role=parent)의 **J열 parent_of**에 자녀 user_id 입력(예: `SYNK-001`).
- 이걸 안 하면: "우리 아이" 탭이 텅 빔.

## 2단계 · `preflightGlide` 1회 실행 (자동 점검 — 옛 "함수 7개 실행" 절차 대체)

### 실행 방법 (클릭 단위)
1. 앱 스프레드시트(SYNK_앱데이터) 열기 → 메뉴 **확장 프로그램 → Apps Script**
2. 상단 함수 드롭다운(▼)에서 **`preflightGlide`** 선택 → **▶ 실행**
3. 하단 "실행 로그"에 점검 리포트가 뜹니다:
   - **✅** = 정상 · **⚠** = 조치 필요(무엇을 어떻게 고칠지 한 줄씩 적혀 있음) · **ℹ** = 참고
4. ⚠를 해소하고 다시 실행 → **⚠ 0개가 되면 조립 시작**.

### preflightGlide가 자동으로 해주는 것
- 강사 폼용 시트·열 물리 생성(weekly_topics F~L·attendance_batch·hw_batch·absence_notice·inquiries·teacher_checkins 정규화)
- 온보딩 카드 4역할 세팅 · 전체 계산 1회(카드 열·반 통계 갱신) · app_state 중복 키 정리 · system_manifest 실측 갱신
- 그리고 **진단**: 반 미배정자·이메일 오류·자녀 미연결·시간표 불일치·콘텐츠 구멍·트리거 생존을 이름까지 짚어줌

### ⚠ 절대 실행하지 말 것 (이번 감사에서 확인된 지뢰)
| 함수 | 왜 위험 |
|---|---|
| **`bootstrapSynk`** | 내부의 setupSchedule이 **시간표를 기본값으로 리셋** → 유호님의 15반 커스텀이 날아감. 재해 복구 전용. |
| **`resetAllTriggers`** | 트리거가 누락됐다고 preflight가 알려줄 때만. 매월 1일 오전엔 금지(리포트카드 생성 중단). |

### 4-F. app_state — 원장 콕핏 (★방법 실증됨 2026-07-13)
key-value 세로 시트라 2단 계산 컬럼으로 꺼냅니다:
1. Glide 데이터 편집기에서 app_state 테이블에 **Query 컬럼**: `리텐션_q` = key is `리텐션레이더HTML`
2. **Single Value 컬럼**: `리텐션HTML_v` = First from 리텐션_q → value
3. 그 Single Value를 **Rich Text**에 바인딩. (**Lookup은 배열이라 안 붙음 — 반드시 Single Value**, 실증)
- 지금 존재하는 키: `리텐션레이더HTML` · `케어사각HTML`
- `경영리포트HTML` · `여행지도HTML`: 매월 1일 자동 생성. **지금 보고 싶으면** 편집기에서 `runExecReportNow` · `runTravelMapNow` 실행(v9.37부터 존재 — 옛 "래퍼 없음" 메모는 낡음).

### 5-A. 학생 (role = student)

- 홈 최상단 온보딩 카드(role=parent, 안내MN).

### 5-C. 강사 (role = teacher) — "수업 시작 1탭 → 수업 중 0~1탭 → 수업 후 1탭"
반 선택 네비게이션이 정본:
1. **반 목록 탭**(소스: class_stats — 반 이름·학생수·브리핑이 이미 반별 행) → 반을 탭하면
2. **반 상세 화면**: 그 반 카드(수업전브리핑 9·격파찬스 10·오늘체크 11·왕관밸런스 12·레이드카드 13 — Rich Text) + **학생 리스트**(profiles, Filter class_name=이 반 & role=student)
3. 그 화면 안의 액션 버튼: **출석폼**(attendance_batch)·**마감폼**(weekly_topics)·(선택) 숙제만(hw_batch)
- ⚠ 학생마다 개별 토글 금지(30명=30저장=쿼터 파산). 반드시 **멀티선택 Choice → 저장 1회**.
- ⚠ 필터는 "로그인 강사의 반" 고정이 아니라 **"선택한 반"** 기준(한 강사가 여러 반).
- **왕관 버튼 2종**(point_logs Add Row): reason 문자열을 **띄어쓰기까지 정확히** `오늘의 MVP` / `오늘의 시냅스` (points=10, student_id=선택 학생, given_by=본인). 다른 문구로 만들면 왕관 집계·중복 정정이 그 행을 못 알아봄.
- **생일축하 버튼 만들지 말 것** — 아침 7시 자동 지급(중복 시 밤 정정+메일).
- **출퇴근 탭**(teacher_checkins 폼) · **출결 보드**(today_board 읽기).
