# SYNK LAB 사업계획과 오프라인 운영 검수

> **현행화 전 검수 이력.** 이 문서의 원문 줄수·잔존 약속·조치 전 상태는 검수 당시 기록이다. 2026-10-02 사용자 요청으로 [현행 운영 기준](오프라인_운영기준_20261002.md)을 적용해 사업계획·교육/복지/학생안내·약관/FAQ·인력/예산 안내·공간/비품을 수정했다. 시설상 불가한 기본 서비스 약속은 삭제했고 무료 자습은 빈 교실 예약으로 변경했다. 새 매물·전체3D/CAD·확정 견적·근무/시간표·실기기 인수는 아직 미완료다. 아래 지적이 모두 실제 시공/운영에서 해결됐다는 뜻이 아니다.

2026년 10월 2일 검수. 전체 사업계획과 LAB의 교육·복지·인력·상품 원문을 최신 공간·촬영·개원 예산·코드 상태와 대조했다. 목적은 울란바토르에서 실제 학생을 받아 운영할 때 약속을 지키지 못하거나 자금이 부족해지는 지점을 찾는 것이다.

| 같은 준비현금 240백만₮를 쓸 때의 단순 비교 | 시설 계획액 | 시설만으로 생기는 차이 |

| 이전 설계 하한 | 291.1백만₮ | 51.1백만₮ |

### 5 학원 자동화와 실제 운영 도구의 경계

**현재 코드와 완료 표기의 충돌.** 사업계획 742~775줄은 상담·출결·부모 리포트·백업·과제·급여 평가·온라인 이수 등이 이미 자동 운영된다고 설명한다. 현재 `Code.js` 39~46줄은 학부모/교사용 화면을 제공하지 않으며, 53~87줄의 옛 학원 작업 함수는 트리거 정리로 끝난다. `.claspignore`의 Apps Script 배포 대상은 `Code.js`와 `엔진_synkbrief.js`뿐이다. 2026-10-02 학원 운영 코드 삭제를 과거 `[이미 돈다]` 표기에 반영해야 한다.

최소 운영에는 학생 식별·재학 상태·보호자 권한, 상품/납부/환불, 반과 시간표, 출결/인계, 혜택 지급, 상담 기록과 권한, 보고서 전달, 기록 백업·복구의 실제 처리 방식이 필요하다. 기존 학원 관리 서비스 또는 접근 제한된 최소 수기 운영으로 시작할 수 있는지 비교한다. 은퇴한 시스템 전체를 되살릴 필요는 없다. 교사 하루2분 행정과 부모 자동 보고를 전제로 인력을 줄이려면 실제 한 반의 일주일을 운영해서 업무 시간을 확인해야 한다.

**설계와 실제 기능을 구분할 항목.** 포토부스 원문3·31·68~69·104~112줄은 월1회·대표 학생만 차감 방향과 별도 코드/실기기/운영 검증 전을 명시한다. 로그인 계정이 있다는 사실만으로 재학생 혜택 자격이 확인되지는 않는다. 사진 삭제와 이용 횟수 초기화도 다르다.

현재 재학 확인, 같은 학생 중복 촬영 방지, 월 변경, 동시 요청, 기기/네트워크/인화 실패 복구, 사진 접근/만료/다음 사용자 초기화를 실제 부스에서 확인해야 한다. 수동 대안도 같은 월 사용 기록을 남기게 한다. 동반 친구의 이용권을 차감하거나 얼굴 인식으로 대상을 늘리지 않는다.

VR은 서서 움직이는 체험과 상담의 시간 분리가 필요하다. 실제 헤드셋·콘텐츠 이용권·안전 구역·감독·세척·충전·멀미 중단·다음 사용자 초기화를 인수해야 한다. 장비가 도면에 있다는 것으로 운영 완료를 보고하지 않는다. 개발이나 인수가 늦으면 공개 제공을 미루는 선택을 비교할 수 있지만 이번에 사용자 확정 혜택을 취소하지 않았다.
