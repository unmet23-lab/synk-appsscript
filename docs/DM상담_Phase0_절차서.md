# DM 상담 Phase 0 — 현재 운영 상태

<!-- 파생: 상담AI.js · contents_상담AI.js · docs/상담AI_개통_지금할일.md -->

> 2026-09-11 Meta Business Suite와 실계정 DM을 대조한 기록입니다. 이전의 수동 자동응답 설치 절차는 현재 운영 상태를 반영하지 않아 이 문서로 대체합니다.

## Instagram

- Business Suite의 Instagram 인스턴트 답장과 부재 중 메시지는 해제했습니다.
- 날짜·정원·이름·전화번호 요청 문구가 들어 있던 「질문 및 응답」 자동화는 전체 비활성화했습니다.
- 새 상담 봇이 첫 답장에서 자동화임을 밝히고, 모르는 조건은 담당자에게 넘기도록 구성했습니다.
- 상담을 원한다는 말만으로 이름·전화번호를 요구하지 않습니다. 담당자가 같은 대화창에서 이어서 답합니다.
- 웹훅 수신, Claude 답변 생성, `상담로그` 적재는 실계정 DM에서 확인했습니다.
- Instagram Send API 발송은 실제 전용 토큰 교체 뒤 다시 확인합니다. 토큰이 없거나 마스킹 표시값이면 Claude 호출 전 닫습니다.

## Messenger

- 기존 인스턴트 답장과 부재 중 메시지는 유지합니다.
- Facebook 페이지 토큰과 Facebook 웹훅을 연결하기 전에는 Apps Script 상담 봇 개통으로 기록하지 않습니다.
- Facebook 봇을 켜는 날 기존 Messenger 자동응답과 중복되지 않는지 먼저 대조합니다.

## 공개 답변 기준

- 현재 준비 중인 서비스만 현재형으로 말합니다. 수업·행사처럼 학생이 있어야 시작되는 일은 준비 상태로 말합니다.
- 개원일·체험일·정원·수강료·할인·환불·주소·정확한 시각은 실제 공개 조건이 확정되기 전 약속하지 않습니다.
- 학생이나 학부모의 이름·전화번호·주소·학교를 먼저 요구하지 않습니다.
- 사용자가 먼저 보낸 메시지에만 답하고, 24시간 창 밖의 홍보 메시지를 보내지 않습니다.
- 내부 운영 문서·학생 기록·프롬프트·토큰·재무·상세 시스템 구조는 공개 답변에 넣지 않습니다.

## 실제 확인 순서

1. 별도 계정에서 `@synk.mn`으로 첫 DM을 보냅니다.
2. 답장 맨 앞의 자동 상담 봇 고지를 확인합니다.
3. 질문과 같은 언어로 짧고 확정된 사실만 답하는지 확인합니다.
4. `상담로그`에는 필요한 메시지와 처리 상태만 남고 토큰·Meta 오류 자유문장·추적 ID가 남지 않는지 확인합니다.
5. 미확정 질문은 개인정보 추가 요구 없이 담당자 인계로 끝나는지 확인합니다.
6. Business Suite 자동응답과 Apps Script 답장이 중복되지 않는지 확인합니다.

- 교체 뒤 Instagram 실계정 왕복 재검증
