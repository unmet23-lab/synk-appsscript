# SYNK → Glide 바인딩 지시서 (v9.25)

> **대상:** 유호 (SYNK LAB 원장) · Glide 에디터를 열고 그대로 따라 하는 실무 매뉴얼
> **범위:** ① 이미 데이터가 차 있는데 화면에 안 붙은 완성품 연결 · ② 데이터가 존재하는 신규 탭 제안 · ③ contents 몽골어(G열) 노출
> **전제:** `GLIDE_조립_마스터보드.txt`의 PHASE 0~3(시트 계산·컬럼 타입·로그인·역할)이 끝나 있어야 함. 이 문서는 그 다음 단계.
> **근거:** 모든 시트명·열 번호는 `Code.js`에서 실제 확인함(추측 없음). 열 표기는 `헤더(문자열 / 1-base 번호)` 형식.

## 0. 용어·조작 3줄 요약 (Glide 실제 메뉴명)

- **Data editor(데이터 편집기):** 왼쪽 데이터 아이콘. 테이블(=시트탭)·컬럼을 본다. 컬럼 제목 클릭 → **Column type / Edit column**에서 타입 지정.
- **Layout(레이아웃) 편집기:** 가운데 폰 미리보기. 하단 **탭(+)** 추가, 화면에서 **Components(+)** 로 조각 올림. 각 컴포넌트마다 오른쪽 설정에 **Visibility(표시 조건)** 있음.
- **Collection(컬렉션):** 여러 행을 목록으로 보여주는 컴포넌트. 오른쪽 **Options → Filter / Sort / Search / In-app filter / Empty state**.
- **Rich text:** `<div>`·마크다운(`*기울임*`)을 렌더. HTML 카드는 반드시 이 타입. Text로 하면 태그가 글자로 깨짐.
- **Set Column / Add Row:** 버튼 액션. 학생이 값을 고르거나(대표몬스터) 강사가 행을 추가(포인트)할 때만.

> ⚠️ **쓰기(업데이트) 절약 원칙(마스터보드 U-1~U-7):** 이 문서의 섹션 1·2·3은 **전부 "읽기 전용 표시"** 라 Glide 업데이트를 먹지 않음. 화면 진입만으로 시트에 쓰는 설정(On-view Set Column, 방문 카운터)은 금지.

## 섹션 1 · 즉시 연결 (미바인딩 완성품)

### 1-3. 🗺️ 시냅스 여행 지도 — `app_state.여행지도HTML` (key/value 행)
스토리북이 다녀간 한국 12경에 도장이 찍히는 그리드(`n/12곳 정복`). `updateTravelMap_`이 `synk_stories`를 읽어 `app_state`에 상설 HTML로 저장. **마스터보드 2-14에서 타입만 언급되고 PHASE 4엔 안 붙은 완성품.**

| 항목 | 내용 |
|---|---|
| 시트·열 | `app_state` → `key='여행지도HTML'` 행의 `value` |
| 컴포넌트 | **Rich text** |
| 배치 | **신규 싱크 스토리 탭(섹션 2-1)** 상단이 가장 자연스러움. 학생 홈에도 가능. |
| 표시 조건 | 없음(스토리 0편이어도 '???' 12칸으로 채워짐) |

**가장 쉬운 방법 — app_state 기반 화면에 붙이기 (~4분)**
`app_state`는 key/value 한 줄짜리라, 그 값 하나만 붙이려면 **app_state를 소스로 하는 화면**에서 붙이는 게 제일 깔끔하다(원장 콕핏 4-D1에서 `리텐션레이더HTML` 붙인 방식과 **완전히 동일**).
1. 싱크 스토리 탭(섹션 2-1) 안에 **Container** 또는 별도 화면을 하나 두고 소스 = `app_state`.
2. 오른쪽에서 그 화면을 **Filter → `key` is `여행지도HTML`** 로 좁힘(행 1개만 남음).
3. **Components(+) → Rich text** → Content = `value`. 끝.

> 💡 학생 홈(profiles 기반)에 직접 얹고 싶으면: `profiles`에 Template 컬럼(고정값 `여행지도HTML`) → 그걸로 `app_state`에 **Relation** → **Lookup**으로 `value` 뽑기 → Rich text. 헬퍼 컬럼 3개라 초보에겐 번거로우니, **스토리 탭에 두는 걸 권장.**

### 1-7. 🌟 드림 한 줄 (학생 목표 노출) — `profiles.드림한줄 (CB / 80)` *(신규 · [v9.29])*
학생이 "내가 한국어를 배우는 이유/목표"를 한 줄로 직접 선언하고, 그 문장이 개인 여정 카드(`나의여정 BY / 77`) **최상단**에 `🌟 나의 목표: …` 로 노출된다. 기업 철학 "앱에서 목적 한 줄이 프로필에 노출"의 실현.

> ⚠️ **이 항목만 섹션 1의 예외 — 학생이 값을 쓰는 유일한 입력.** 나머지 섹션 1·2·3은 읽기 전용이지만, 이 열은 학생이 **Set Column으로 직접** 쓴다. 단 "가끔 한 번 저장"이라 마스터보드 U-4(드물게 바뀌는 값) 기준 허용. **원장/강사 전용인 `핵심비전(BA / 53)`과 절대 혼동 금지** — 그건 학생·학부모에게 노출하지 않는 케어용 열이고, 이 `드림한줄(CB / 80)`이 학생 자기선언 전용 신규 열이다.

| 항목 | 내용 |
|---|---|
| 시트·열 | `profiles` → `드림한줄 (CB / 80)` — **Text** (학생 소유 · calcAll·syncProfiles 어떤 배치도 덮어쓰지 않음, 헤더만 보장) |
| 입력 컴포넌트 | **Text Entry**(입력) → 대상 컬럼 `드림한줄` (= Set Column) |
| 노출 컴포넌트 | 이미 바인딩된 `나의여정 (BY / 77)` Rich text 카드가 자동으로 최상단에 표시(추가 작업 없음) |
| 배치 | 학생 홈/프로필 탭(4-A1), 본인 행 · Visibility = `role is student` |
| 표시 조건 | 입력칸: 학생 본인만. 카드 노출: 코드가 빈 값이면 "🌟 나의 목표를 적어보세요" 유도 문구로 자동 채움 |

**클릭 순서 — ① 입력칸 만들기 (~4분)**
1. Data editor → `profiles` → `드림한줄(CB / 80)` 컬럼이 보이는지 확인. (calcAll이 다음 실행에서 헤더를 자동 생성. 안 보이면 Apps Script에서 `calcAll` 1회 수동 실행하거나 CB1 셀에 `드림한줄` 직접 입력.) Type = **Text**.
2. Layout → 학생 홈(또는 프로필) 탭 → 하단 **Components(+) → Text Entry**(텍스트 입력).
3. 오른쪽 설정 → **Data / Column** = `드림한줄` 선택(입력이 이 열에 저장됨 = Set Column).
4. Placeholder(안내문구) = `🌟 나의 목표를 한 줄로 적어보세요` 입력.
5. 컴포넌트 **Visibility → role is student**(학생만 자기 목표를 편집).

**클릭 순서 — ② 여정 카드 노출 확인 (~2분)**
1. 학생 계정(또는 미리보기)에서 입력칸에 목표 한 줄을 써 저장.
2. 다음 `calcAll` 실행(자동 14시·22시 또는 Apps Script에서 수동 1회) 뒤 학생 홈의 **`나의여정(BY / 77)` 카드 최상단**에 `🌟 나의 목표: {내가 쓴 문장}` 이 뜨는지 확인.
3. 값을 지우면 다음 계산에서 카드가 `🌟 나의 목표를 적어보세요` 유도 문구로 자동 복귀하는지 확인.

> 💡 **타이밍:** 입력은 즉시 시트에 저장되지만, 카드(BY)는 `calcAll`이 다시 그릴 때 반영된다(하루 2회 자동). 즉시 확인하려면 Apps Script에서 `calcAll`을 한 번 돌린다.

## 섹션 2 · 신규 탭 제안 (스토리북 · 리그 · 레이드 · 업적 · 크루 프로젝트)

> **원칙:** 아래는 전부 **데이터가 이미 시트에 쌓이는** 것만 제안. 각 탭 끝에 **[선행 필요]** 로 "코드 작업이 먼저 있어야 하는 부분"을 분리 표기했다.
> **"여정" 탭은 신규 불필요:** 개인 여정은 `나의여정(BY / 77)`으로 이미 학생 홈(4-A1)의 대표 카드로 바인딩돼 있음 → 새 탭 만들지 말 것.

### 2-1. 📖 싱크 스토리 탭 (스토리북) — 학생·학부모 공용
매월 1일 `buildMonthlyStorybook_`이 지난달 실화를 12장 서사로 발간. **산출물 위치 = `synk_stories` 시트** (부록 A 참고). 여기에 `synk_cards`(이달의 카드)와 `여행지도HTML`(1-3)을 한 탭에 모으면 "우리들의 이야기" 허브가 된다.

**필요 시트·열**
- `synk_stories` : `월(A) · 호수(B) · 제목(C) · 챕터(D) · 챕터제목(E) · 본문(F) · 문법포인트(G) · 씬프롬프트(H)`
- `synk_cards` : `월(A) · student_id(B) · 카드HTML(C)`
- `app_state` : `여행지도HTML` (섹션 1-3)

**화면 구성(컴포넌트 트리)**
```
[탭] 📖 싱크 스토리  (Visibility: 학생·학부모 공통 / 원장도 열람 가능)
 ├─ Rich text  ← app_state 여행지도HTML        (1-3 방식 · 상단 지도)
 ├─ Collection ← synk_stories                  (스토리 본편)
 │    · 표시: 제목(C) / 챕터제목(E) / 본문(F)
 │    · 본문(F)은 카드 상세에서 Rich text로 (마크다운 *기울임* 렌더)
 │    · 문법포인트(G)는 본문 아래 작은 배지 Text
 │    · 씬프롬프트(H) 는 화면에 넣지 말 것 (원장 영상제작용 내부 데이터)
 └─ Collection ← synk_cards                     (이달의 트레이딩 카드)
      · 카드HTML(C) 를 Rich text로
```

**정렬 / 필터**
- `synk_stories` Collection → **Sort:** `월(A)` **내림차순**, 그 다음 `챕터(D)` **오름차순**(표지 0 → 에필로그 11 순 · 챕터값 0~11, 총 12장).

## 섹션 3 · 몽골어(contents G열) 노출 — 3안

> `contents` 시트 구조: `콘텐츠ID(A) · 유형(B) · 이름(C) · 설명(D) · 이미지URL(E) · 순번(F) · 몽골어(G) · 영어(H)`.
> **G열(몽골어)** 은 `translateContents`가 유형 `quote·braintip·homework·monster·season` 행을 초벌 자동 번역해 채움(이번에 대량 채워질 대상). 별도로 `setupParentLabels`가 만든 **`유형='label'` 행**은 화면 라벨의 한/몽/영을 큐레이션해 둠(C=키, D=한국어, G=몽골어, H=영어). 이 label 행이 언어 전환의 핵심 재료.
> 아래 3안 중 하나를 고르면 됨. **처음엔 안 A(병기) 권장**, 규모 커지면 안 C 또는 안 B로.

### 안 A. 한/몽 **병기**(항상 둘 다 표시) — 가장 쉬움
콘텐츠 카드(도감 4-A2·스토어 4-A3·숙제 등)에서 한국어 `설명(D)` 밑에 몽골어 `몽골어(G)`를 한 줄 더 깐다. 토글·사용자 상태 없음 → 조작 최소·업데이트 0.

**클릭 순서 (~5분/화면)**
1. Data editor → `contents` → `몽골어(G)` Type = **Text** 확인.
2. 해당 콘텐츠 Collection의 상세화면(또는 카드) 열기.
3. 기존 `설명(D)` Text 아래 **Components(+) → Text** 추가 → Content = `몽골어(G)`.
4. (선택) 몽골어 줄 색을 회색/작게 → 오른쪽 스타일에서 조정. G가 빈 행 대비 **Visibility = `몽골어 is not empty`** 걸어 두면 미번역 행에서 빈 줄 안 생김.

**장점:** 제일 단순·안전. **단점:** 화면이 살짝 길어짐.

### 안 C. **역할 기반 자동**(학부모=몽골어, 학생=한국어) — 권장 중간값
언어 선택 UI 없이, **role로 자동 분기**. 마스터보드 O-2의 "학부모=몽골어 우선" 방침과 일치.

**클릭 순서 (~8분/화면)**
1. 같은 카드에 Text 컴포넌트를 **2개** 둔다: 하나 Content=`설명(D)`(한국어), 하나 Content=`몽골어(G)`(몽골어).
2. 한국어 Text → **Visibility = `Signed-in user → role` is `student`** (또는 teacher/admin).
3. 몽골어 Text → **Visibility = `Signed-in user → role` is `parent`**.
4. G가 비었을 때 학부모가 빈칸 보는 것 방지: 몽골어 Text에 조건 하나 더 → `몽골어 is not empty`, 그리고 한국어 Text를 폴백으로 `몽골어 is empty`일 때도 보이게(조건 그룹).

**장점:** 학부모 화면이 자동으로 몽골어. 사용자 조작 0. **단점:** 한 사람이 두 언어를 오갈 순 없음(역할 고정).

### 안 B. **언어 전환 토글**(사용자가 선택) — 가장 유연
학생/학부모가 앱에서 언어를 한 번 고르면 그 값(KO/MN)에 따라 표시 전환.

**준비 — 언어 저장 위치 (택1)**
- (b1) **Glide User-specific 컬럼:** `profiles`에 User-specific 텍스트 컬럼(예: `표시언어`) 추가 → 기기별 저장, 시트 안 건드림(업데이트 0). **초보 권장.**
- (b2) **Set Column:** `profiles`에 일반 컬럼 `표시언어` → 버튼으로 `KO`/`MN` 저장. 시트에 남지만 "가끔 바꿈"이라 U-4 기준 OK.

**클릭 순서 (~15분)**
1. 위 (b1 또는 b2)로 `profiles.표시언어` 컬럼 마련.
2. 각 역할 홈 상단에 **Choice 컴포넌트**(또는 버튼 2개) → 값 `KO` / `MN` → 대상 = `표시언어`. (label 행 `L15 언어 / Хэл`를 버튼 라벨로 재사용 가능.)
3. 콘텐츠 카드에 Text 2개(한국어=`설명 D`, 몽골어=`몽골어 G`).
4. 한국어 Text **Visibility = `표시언어` is `KO`(또는 is empty=기본 한국어)**, 몽골어 Text **Visibility = `표시언어` is `MN`**.
5. (확장) **화면 라벨까지 전환**하려면 `유형='label'` 행을 Relation/Lookup으로 끌어와 `표시언어`에 맞춰 `한국어(D)`↔`몽골어(G)`↔`영어(H)` 표시. (라벨 15종은 이미 `setupParentLabels`로 채워져 있음 — 데이터 준비 완료, 바인딩만.)

**장점:** 한 사람이 자유 전환·다국어 완결. **단점:** 컴포넌트/조건이 가장 많음.

> **번역 품질 주의:** G열은 기계 초벌 번역(`translateContents`). 학습 콘텐츠(숙제·팁)는 **몽골어 가능한 크루 1회 검수** 권장(마스터보드·코드 주석 공통 경고). label 행(L01~L15)·reason 행(R01~R08)은 이미 직접 큐레이션돼 검수 불필요.

## 부록 B · 선행 코드 작업이 필요한 항목 (요약)

바인딩만으로 안 되고 **Apps Script 코드가 먼저** 있어야 하는 것만 추림(그 외는 전부 Glide 조작으로 완료):

1. **스토리북 삽화 이미지** — `synk_stories`에 실제 `image_url` 열 없음(영문 프롬프트만 존재). 이미지 생성 + 열 추가·채움 코드 선행. (섹션 2-1)
2. **스토리북 본문 몽골어** — `synk_stories.본문(F)` 한국어 전용. 학부모용 몽골어 스토리 원하면 번역 열 코드 선행. (섹션 2-1)
3. **레이드 스토리 몽골어** — `raid_story.스토리(E)` 한국어 전용. 학부모 몽골어 뷰 원하면 번역 열 코드 선행. (섹션 2-3)
4. **학생 개인 리그/레이드 기여 수치** — 참여·승수는 내부 계산만 하고 `profiles`에 개별 열로 저장 안 함. 개인 "내 전적 숫자" 카드 원하면 profiles 열 추가 코드 선행. (섹션 2-2·2-3, 선택)

> 위 4건은 **없어도 각 탭이 완성됨**(텍스트 서사·집계 카드로 충분). 삽화·다국어·개인 수치는 "다음 버전" 후보.
