# Loom — 살아 있는 재질의 연결

2026-09-13 · 동작의 기본값은 [움직임 지원 매체 표현 기준](Loom_실시간장면_표현기준.md)이다. 이 문서는 연결 범위를 다룬다. 완료된 영상 모델 실험은 [정리 전 원문](https://github.com/unmet23-lab/synk-appsscript/blob/8b80a507168d/docs/Loom_살아있는재질_설계_v1.md)에 남긴다.

## 0. 목적

배경·캐릭터·빛·재질이 같은 장면 안에서 살아 있게 만든다. 애니메이션 지원 위치는 기본 적용하고 정적 전용 위치에는 같은 표현의 정지 컷을 쓴다. 모든 요소의 상시 흔들림을 뜻하지 않는다.

## 1. 제작 갈래

| 출력 | 연결 |
|---|---|
| 웹 실시간 | [공통 시간·움직임](../tools/lib/loom-scene.mjs) → [웹 표시기](../tools/lib/loom-scene-webgl.mjs) |
| 앱 | SYNK-talk의 현재 화면·마스코트·모션·자산 변환기. [앱 반입](Loom_앱반입_설계_v1.md) 참조 |
| 영상 | 기존 Remotion 통로 또는 실제 장면 녹화 |
| 정적 전용 | 같은 자산·빛·구성의 대표 정지 컷 |

[몽글과 바람의 정원](../experiences/loom-living/README.md)은 현재 로컬 웹 실물이다. 앱·영상 전체가 같은 구현으로 교체됐다는 뜻은 아니다.

## 2. 동작의 역할

평소에는 카메라·지면을 고정하고 사건 때 해당 부위가 짧고 분명하게 반응한다. 식물은 바람에, 표정은 상황과 상호작용에 맞춰 움직인다. NPC 멘탈의 수치·게이지 비노출을 업로드·녹음·재생 등 모든 학생용 진행 안내 금지로 확대하지 않는다.

## 3. 구현 선택

공통 시간·이벤트와 매체별 표시기를 재사용한다. 새 모델·프레임 애니메이션·렌더러·앱 모션 도구가 필요하면 승인 원본과 실제 품질·성능을 대조한다. 과거 라이브러리 보류, 특정 영상 모델 실패, 물체 하나만 움직였던 실험을 새로운 제작의 제한으로 삼지 않는다.

표정만 바꿀 때는 [재질 고정](캐릭터/캐릭터_생명감_설계.md#1-a-표정-전환의-재질-고정)을 지킨다. 새로운 행동은 승인 참조·몸짓 규격을 따른다. 필요한 부위·접점을 움직이고 원본 전체의 왜곡으로 생명감을 대신하지 않는다.

## 4. 시간의 흔적

Patina는 사용의 흔적을 재질에 남기는 설계 방향이다. 실제 기록과 소비 화면이 연결됐는지 확인하며, 달력이 지났다는 이유로 성취·관계를 만들지 않는다. 학생 간 비교나 쉬었다 돌아온 학생의 손해로 바꾸지 않는다. 새 사용처는 현재 제품 요청에 맞춰 정한다.

## 5. 영상 연결

공방 요소는 이미 [영상/src/킷/공방.ts](../영상/src/킷/공방.ts)가 소비한다. `node 영상/자산모으기.js`가 원천을 영상 목록으로 변환하므로 자산 변경 뒤 필요한 목록·출력을 갱신한다. “영상에는 색·폰트만 갈 수 있다”는 옛 제한은 제거한다. 생성 영상은 정체성·재질·이음매·권리·실제 출력 품질을 확인하며 재생 영상과 실시간 상호작용을 구분한다.

## 6. 작업 단위

이번 요청의 장면·행동을 끝내고 공통 부분을 원천에 반영한다. 로딩 → 버튼 → 영상 → Patina의 고정 순서를 요구하지 않는다. 제작 자산·화면 연결·재생·배포·실기기 결과를 구분한다.

## 7. 확인

실제 크기에서 정지·최대 동작·복귀·깜빡임을 비교한다. 원본과 이동본의 겹침·윤곽 뭉개짐·접지 분리·배경 전체 이동을 확인한다. 정지·화면 숨김·움직임 줄이기·긴 중단 후 복귀를 검증한다. 목적 있는 사건 반응은 분명하게 보이고 평소에는 편안해야 한다.
