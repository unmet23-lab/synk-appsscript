## 2. 우리 일지가 «거짓 초록»이었다 — 이 세션이 고친 것

옛 1분 보고는 이랬다:

```
층 2746장 떴다 · 내보낸 것 5813 · 실패 0
```

세 수 다 **우리 쪽만 센다.** 유튜브가 굶고 있어도 「실패 0」이 나온다. 실제로 20시간 동안 그랬다.

새 보고는 ffmpeg 자신이 알려 주는 수를 같이 싣는다:

```
층 454장 떴다 · 내보낸 것 993 · 실패 0 · 실시간대비 0.843x · 버린장 0 · 겹친장 0
```

- **실시간대비** — 1.0 이면 실시간을 딱 지킨다. 0.9 면 10% 뒤처져 유튜브가 굶는다.
- **버린장 · 겹친장** — ffmpeg 이 스스로 버리거나 겹친 그림 수.

> 📌 이 자는 기억 `zero-is-a-success-face-taxonomy`(«0건»이 성공 얼굴 · 자를 먼저 의심한다)의 교과서 사례다. 「실패 0」이 20시간 동안 초록이었고, 그 20시간이 통째로 굶고 있었다.

## 3. 🔑 까닭을 어디까지 좁혔나

### ㉠ 인코딩은 아니다 — 갈라서 확인했다
그림 압축을 `veryfast` 에서 `ultrafast`(더 가볍게)로 바꿔 봤다. 결과:

| | 바꾸기 전 | 바꾼 뒤 |
|---|---|---|
| ffmpeg 기계 부담 | 80.9% | **54.9%** |
| 부하(1분) | 2.59 | **1.12** |
| **실시간대비** | 0.82x | **0.84x** |

**기계는 한참 한가해졌는데 방송 속도는 그대로다.** ⇒ 계산이 모자라서 뒤처지는 게 아니다.

### ㉡ 「박자를 거른다」로 보인다 — 코드를 읽은 소견
`bots/오버레이/겹쳐송출.js` 의 «흘려보내는 쪽» (지금 387~392줄):

```js
setInterval(() => {
  if (!마지막장 || 막힘 || ff.stdin.destroyed) return;   // ← 막히면 그냥 «건너뛴다»
  막힘 = !ff.stdin.write(마지막장);
  다시쓴것++;
}, Math.round(1000 / 뜨기));
```

ffmpeg 이 잠깐 못 받으면 `막힘` 이 켜지고, 그동안의 박자는 **밀리는 게 아니라 사라진다.**
그리고 ffmpeg 에는 `-framerate 10` 이라고 일러 뒀다 — **한 장을 0.1초로 친다는 약속**이다.
약속은 10장인데 8장만 주면, 방송 시각이 실제 시각의 **0.8배**로 흐른다.

🔑 **잰 값이 이 셈과 딱 맞는다** — 초당 8.0장 ÷ 10 = 0.80, 실측 실시간대비 0.82~0.88.
🔑 **버린장·겹친장이 0인 까닭도 여기다** — ffmpeg 은 «오지 않은 장»을 셀 수 없다. 그래서 자기 쪽 일지는 깨끗하다.

> ⚠ 이 ㉡은 **코드를 읽은 소견이지 실험으로 확정한 게 아니다.** 아직 안 재봤다 — 확정하려면 §6-갈래ⓐ 를 시늉 모드로 돌려 실시간대비가 1.0 에 붙는지 보면 된다.

### ㉢ 층 그림 뜨는 속도도 따로 모자란다 (초당 3.6장 / 목표 10)
크로미움이 화면을 뜨는 속도 자체가 목표의 3분의 1이다. 다만 코드가 «못 뜬 순간엔 직전 장을 다시 쓴다»고 되어 있어 이건 **화면이 뚝뚝 끊기는 문제**이지 굶는 문제와는 다른 자다. 굶는 쪽은 ㉡ 이 쥐고 있다. 둘을 섞어 읽지 말 것.

## 6. 다음 세션이 할 일 — 갈래 셋 (아직 하나도 안 재봤다)

> 셋 다 «실시간대비를 1.0 에 붙이는» 길이다. 시늉 모드로 재보고 고르면 된다(§7).

**갈래ⓐ — 박자를 안 거른다** (가장 작다)
`막힘` 이 켜져 있어도 `write` 를 부른다. Node 가 알아서 쌓아 준다.
- 좋은 점: 한 줄 고치면 된다. §3-㉡ 이 맞는지 바로 판정된다.
- 위험: 쌓이기만 하면 램을 먹는다. 쌓인 양에 상한을 두는 것이 같이 필요해 보인다.

**갈래ⓑ — 약속을 실물에 맞춘다** (가장 안전하다)
`-framerate 10` 을 실제로 되는 수(8쯤)로 낮추고 `--뜨기` 도 같이 낮춘다.
- 좋은 점: 뒤처짐이 원리상 0이 된다. 위험이 거의 없다.
- 잃는 것: 화면이 조금 더 뚝뚝해진다. 🔴 **유호님 멀미 이력이 있는 자리**(기억 `mascot-motion-makes-yuho-sick`) — 다만 «덜 움직이는» 쪽이라 반대 방향이다.

**갈래ⓒ — ffmpeg 이 스스로 채우게 한다** (가장 옳아 보이나 손이 많다)
들어온 그림에 «진짜 시계»를 찍고(`-use_wallclock_as_timestamps 1`) 모자란 장은 ffmpeg 이 겹쳐서 메우게 한다(`-vsync cfr`).
- 좋은 점: 우리가 몇 장을 보내든 방송은 실시간을 지킨다. 근본 처방이다.
- 위험: 소리와 그림이 어긋날 수 있다. 시늉으로 꼭 들어 보고 판정할 것.

### 곁다리 둘 (굶는 것과 별개 · 잊지 말 것)
- **🔴 방송 열쇠가 서버 일지에 찍혔다.** ffmpeg 이 죽을 때 내는 오류 문장에 주소 전체가 들어 있고(`Error closing file rtmp://…/live2/<열쇠>`), 우리 코드가 그걸 그대로 일지에 옮긴다. 코드 주석은 「열쇠는 안 찍는다」고 적혀 있는데 **이 길로 샌다.** 처방 = 일지에 찍기 전에 열쇠 자리를 가린다.
- **10:43:14 의 SIGKILL 은 까닭 미상.** 램 부족 흔적 0. 다시 나오면 그때 잡는다.
