### 밤에 걸 때 (유호님이 말씀하시면)

두 벌이 잇달아 돈다(몽글 46 → 까몽 46 · 표지도 같이).

```

node 영상/굽기.js --전량 --가이드 까몽    # 까몽 45편 + count-02 + 표지 46장
```

- **로그** = `C:\Users\q1212\AppData\Local\Temp\synk_릴전량_0907.log`
- **어디까지 왔나** = `grep -E "^── \[" <로그> | tail -1`
- **끝났나** = 로그 마지막의 `########## 끝` 줄. 각 벌의 끝에 「성공 N · 실패 M」이 찍힌다.
- **걸리는 시간** = 편당 약 100초 ⇒ 남은 84편이면 **약 2시간 20분**.
  ⚠ 콘센트를 뽑으면 훨씬 느려진다(memory `night-bake-needs-wall-power`).
- **열을 더 낮추려면** `영상/remotion.config.ts` 의 `setConcurrency(4)` 를 2로 내린다.

  2로 내리면 시간이 두 배쯤 된다.

### 죽었으면 어떻게 다시 거나
같은 두 명령을 다시 치면 된다. 이미 구운 편도 다시 굽지만 덮어쓰기라 해가 없다.
**낱개**로 다시 굽는 것도 된다: `node 영상/굽기.js clip-09-2`.
🔴 **두 벌을 동시에 돌리지 않는다** — 굽기는 매번 `src/클립/생성/*.ts` 와 `public/` 을 다시 쓰므로
서로를 덮는다.

### 🔑 왜 「4.5시간」이 「2시간 반」이 됐나
굽기.js 가 화면에 내는 초는 **렌더 시간만**이다. 벽시계로는 편당 157초였고 그 차 79초를 쫓아가니
**자산모으기가 98.7초**였다(안에서 `컷맞추기` 가 마스코트 눈 43장을 매번 다시 맞춘다).
편마다 되풀이할 까닭이 없어 `--전량` 이 준비를 한 번만 하도록 고쳤다(`58e3293fc`) — 편당 157초 → 102초.
🔑 **관문을 없앤 게 아니라 앞으로 옮긴 것이다.** 낱개로 부르면 예전 그대로 편마다 돈다.

### 🔴 다음에 곡을 갈 때 밟을 자리 넷

1. **곡을 아는 곳은 «두 곳»이다.** `영상/대본읽기.js` 의 `가이드결`(90클립이 여기서 난다)과
   `영상/src/클립/연출.tsx` 의 `배경음악`(기본값). 한쪽만 갈면 다른 쪽이 조용히 옛 곡을 깐다 —
   08-26 에 실제로 몽글 릴 10편이 그랬다.
2. **Suno 곡은 옛 곡보다 «작다».** 5.7dB·5.3dB 작아서 볼륨을 0.28 → 0.54 로 **올렸다.**
   「새 곡이 더 크겠지」는 틀렸다. 자 = `python tools/곡재기.py --창 18`.
3. **릴은 30초가 아니라 18초다**(540프레임÷30fps). 그래서 자에 `--창` 을 달았다 —
   «가장 꽉 찬 지점»의 답이 창 길이마다 다르다(따뜻_118: 30초 창 26.4초 → 18초 창 28.3초).
4. **자가 고른 시작점이 곡 끝에 붙었으면 의심한다.** 밝은_052 는 자가 30초를 골랐는데
   그 곡은 48초부터 사그라져 가장 긴 릴(19.1초)이 꼬리를 물었다. 16초로 물러서도 잃는 건 0.7dB뿐.

### 실물로 무엇을 쟀나 (「시켰다」와 「났다」는 다르다)
- **무엇이 깔렸나** — 산출물의 세기 곡선과 후보 곡들의 상관: 따뜻_118 **+0.479** 대 나머지 셋 −0.18~−0.03.
  까몽은 밝은_052 **+0.536** 대 나머지 −0.09~+0.01.
- **균형이 옛 판과 같나** — 마스터 게인이 지워지는 값(조용한 바닥 − 전체)으로 견줬다.
  몽글 새 −1.7dB(옛 다섯 −1.6~−1.8) · 까몽 새 −1.1dB(옛 셋 −0.9). 둘 다 제 옛 띠 안이다.
- **자막이 가운데로 섰나** — 프레임에서 회색 글자 픽셀의 왼끝·오른끝을 재서 화면 가운데(540)와 견줬다.
  🔑 문턱을 140 으로 좁혀야 한다 — 170 이면 뒤 펠트 판(밝기 162)이 섞여 «치우쳤다»는 거짓말이 나온다.
