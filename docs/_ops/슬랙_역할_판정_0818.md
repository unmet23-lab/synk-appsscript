## 3. 진단 — 텔레그램은 왜 0회였나 (같은 실패를 Slack에서 반복하지 않으려면)

「메신저가 텔레그램이라서」가 아니다. **배관이 3겹이고, 그 3겹이 전부 repo 밖에 있었다.**

```
결정 큐 발송  →  synk-memory GitHub Actions cron (매일 09:00 KST)
답변 수거     →  synk-memory GitHub Actions cron (30분마다)
메모리 동기화 →  유호님 노트북 작업 스케줄러 SYNK_MemoryPush (시간마다 · PC 켜져야 함)
```
(출처: `docs/AI_스택_가이드.md` §1-4 「결정 큐 클라우드」)

그리고 `CLAUDE.md`가 못박아 둔 사실: **GitHub Actions 소진 · 리셋 9/1.**
Actions 분(minutes)은 계정 단위로 합산되므로 `synk-memory`의 cron도 같은 지갑을 쓴다.

⚠ **직접 못 쟀다.** `synk-memory` 저장소가 이 세션에 없어 그 워크플로 로그를 열지 못했다.
그래서 이것은 **원인 후보 1개**이지 확정이 아니다(정본: 「N회 실패 = 원인 미특정의 신호」 — 층을 바꿔 후보를 특정한 데까지가 여기다).

**Slack 커넥터의 배관은 0겹이다** — cron도, 봇 토큰도, PC 켜짐도 없다. **세션이 도는 순간 직접 닿는다.**
세션은 실측상 매일 돈다(transcript 1,400+). 텔레그램을 죽인 의존이 **원리적으로 없다.**

## 4. 역할 후보 4개 — 판정

### ㉠ 유호님 → AI 「던지기함」 · ✅ **채택 권고 (도전안 — 통념과 반대 방향)**

수업 중에, 길에서, 자다 깨서 떠오른 것을 Slack 채널 하나에 그냥 던져 둔다.
다음 세션이 시작할 때 `slack_read_channel` 로 읽어 대기열·결정큐·메모리에 꽂는다.

**왜 이것이 먼저인가 — 세 가지가 전부 반대다:**

1. **지금 아예 없는 방향이다.** 시스템 전체가 AI→유호(결정큐·보고·인계문)로만 설계돼 있다.
   유호님이 떠올린 것을 넣을 자리는 **대화창뿐이고, 세션이 끝나면 사라진다.**
2. **실패가 원리적으로 불가능하다.** 배달이 아니라 **회수**라서, 읽는 쪽이 세션이다.
   ㉡은 유호님의 응답률에 걸려 있지만(내가 못 고친다), ㉠은 **유호님이 쓰고 싶을 때만 쓰면 되므로 안 쓰이는 날이 실패가 아니다.**
3. **인젝션 표면이 가장 낮다.** 유호님만 있는 private 채널이고, AI는 그것을 **재료로 읽을 뿐 명령으로 삼지 않는다.**

### ㉡ AI → 유호님 「결정 큐」 배달·회수 · ✅ 채택 (㉠ 다음)

88건을 Slack으로 민다. **단 전량이 아니라 「30초 안에 답이 나오는 것」만.**

큐 실물을 보면 그런 건이 실제로 다수다 — #41(Navy 채택할지) · #42(앱 아이콘을 마스코트로) · #43(파비콘 마크) ·
#46(마스코트 조항) · #84·85(주말반) · #87(칸바 Pro 끄기) · #88(밴드 세기 0/0.5/0.85 픽).
반대로 **#60~62(국제조세) · #74·76(폐업) · #71(계약서 금액)은 밀지 않는다** — 메신저에서 답할 무게가 아니고,
밀면 채널이 「못 읽는 곳」이 되어 ㉠까지 같이 죽는다.

### ㉢ 알림 수신함 (CI 적색 · PR · 배포 완료) · ❌ 기각

유호님은 폰으로 작업하지 않는다(11일 0회 실측 · F623). 노트북 앞에 계실 땐 세션이 직접 말한다.
알림은 **읽어도 아무 행동이 안 따르는 글**이라, 채널을 소음으로 채워 ㉠㉡의 신호를 덮는다.

### ㉣ 학생·강사·크루 접점 · ❌ 기각

몽골 현지 표준은 페이스북 메신저다(Slack 아님). 그리고 아직 **미개원 · 학생 0명 · 1인**이라 협업 대상이 없다.
철학 정본 ㉣(학생 식별 데이터를 밖으로 내보내지 않는다)에도 정면으로 걸린다.

## 5. 한 수 더 — 번호 타이핑을 통째로 없앤다

지금 결정큐는 유호님께 **「끝난 번호만 쓰시면 됩니다. 예) `3,7,12 완료`」**라고 안내한다(`결정큐_한장.md` 머리말).
88건 앞에서 번호를 찾아 타이핑하는 것은 **손일**이고, 철학 ㉡(사람 손을 늘리는 해법을 쓰지 않는다)에 걸린다.

**Slack에서는 결정 1건 = 메시지 1건으로 올린다**(묶어서 올리지 않는다).
유호님은 그 메시지에 **스레드 답글**만 달면 된다 — 어느 결정에 대한 답인지가 **자리로 확정**되므로 번호가 사라진다.
`slack_read_thread` 가 실재하므로 이건 지어낸 안이 아니라 있는 도구로 되는 안이다.
