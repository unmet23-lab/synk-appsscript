[P0] ㉢ 삶 이해(드림맵·나침반·시즌회고) 처리 AI의 전면 누락 — 학습 사슬 단절
- **문서 위치**: §3 [배치 — 서른다섯 자리], §4 [자리마다 채워야 하는 다섯 칸]
- **지적**: 판단 정본은 SYNK의 존재 이유를 「학생마다 추구하는 삶을 파악해 최적화된 로드맵을 연구하는 것」으로 정의하고, 이해 3층 중 ㉢을 삶 이해(나침반 3문항·드림맵 카드·시즌 회고)로 못 박았다. 그러나 35개 배치표 어디에도 학생의 비정형 드림맵 텍스트나 나침반 답변에서 삶의 지향·가치관·동기를 추출하고 시즌 회고 맥락으로 합성하는 자리가 없다. ㉠ 실력(23유형)과 ㉡ 사람(성향)만 일부 슬롯을 두고 정작 회사의 정체성이자 게이트 최상위인 ㉢ 삶 이해의 배선이 0개로 증발해 있어, 데이터가 모여도 엔진으로 닿지 않는 영구 결함 상태다.

[P0] 모델 버전·프롬프트 스냅샷 계약 부재 — 소급 불가 시계열 오염
- **문서 위치**: §2 ⑥번 자, §3 [아 · 시계열로 쌓이는 것 (35번)], §4 [자리마다 채워야 하는 다섯 칸]
- **지적**: ⑥번 자에서 모델 판 변경에 따른 시계열 왜곡을 경계하며 35번(발음·성향)을 후보로 내렸으나, 정작 §4의 필수 5칸(근거, 입력, 남기는 사건, 엔진 소비자, 독립 검수자) 규격에 **「추론 시점의 모델 버전 ID / 프롬프트 해시 / 생성 파라미터(온도 등)」 메타데이터 필드가 누락**되었다. 더구나 27번(채점·분류), 29번(뜻 대조), 30번(오류 23유형 태깅) 등 학생의 실력 시계열을 직접 결정하는 핵심 판정들이 ⑥번 자의 통제 밖인 '바 · 뒤에서 도는 판정'으로 빠져 있다. 모델 스냅샷 메타데이터가 DB에 함께 박히지 않고 쌓인 채점·태깅 이력은 향후 모델 업그레이드 시 척도 보정이 불가능해져 「어제의 그 학생과만 비교한다」는 철학을 소급 불가로 파괴한다.

[P0] §4 규칙과 §3 상태 표기의 정면 모순 — 조용한 선언 실패
- **문서 위치**: §3 [배치 — 서른다섯 자리] 표 전체, §4 [자리마다 채워야 하는 다섯 칸] 말미
- **지적**: §4는 "다섯이 다 차면 「확정」, 하나라도 비면 「후보」다. 지금 서른다섯 중 다섯 칸이 다 찬 것은 한 자리도 없다"고 명시했다. 그렇다면 §3의 모든 자리는 예외 없이 '후보'여야 마땅하나, 표에는 1, 3, 4, 5, 6, 7, 10, 11, 12, 13, 14, 16, 17, 22, 23, 24, 25, 29, 31, 32, 33, 34 등 무려 22개 자리가 버젓이 「확정」으로 박혀 있다. 스스로 세운 판정 게이트를 문서 스스로 정면 위반하고 있으며, 기준이 충족되지 않은 상태를 확정으로 둔갑시키는 조용한 허위 통과가 문서 전반을 지배하고 있다.

[P1] ⑤번 자(학생이 읽는 글)의 단일 LLM(클로드) 독점과 Fallback 부재 — 운영 정지 결함
- **문서 위치**: §2 ⑤번 자, §3 [마 · 학생이 읽는 것 (22~26번)], §8 질문 5번
- **지적**: 학생 경험 일관성을 이유로 22~26번을 클로드 단일 모델로 강제했으나, 이는 클로드 주간 쿼터 초과나 API 장애 발생 시 학생 앱의 모든 과제·퀴즈·피드백 생성이 동시에 멈추는 단일 장애점(SPOF)을 만든다. 문서 스스로 "페이블은 주간 몫의 절반까지만 쓸 수 있다"고 한계를 자인하면서도 쿼터 고갈 시의 대체 배관(Fallback)이나 큐잉 규칙을 일절 정의하지 않았다. 개원 후 사용량이 조금만 튀어도 학생 화면이 백지로 멈추는 치명적 실행 불능 상태를 낳는다.

[P1] §5 "한 번 드는 사람 손"의 기술적 허구 — 철학 정본 ㉡ 위반
- **문서 위치**: §5 [사람 손은 어디에 드는가]
- **지적**: 몽골어 검문 50문장, 본보기 과제 20벌, 채점 기준표 30건을 "한 번만 만들면 모델 판이 바뀔 때 다시 안 만든다"고 선언한 것은 LLM 벤치마킹 메커니즘에 대한 허위 전제다. 모델 판이 바뀌거나 시스템 프롬프트가 개정되면 과거의 50문항 기준표는 새로운 모델의 편향이나 경계 실패를 잡아내지 못하므로 지속적인 테스트셋 보강(Data Drift 대응)이 필수적이다. 비개발자 1인 원장이 주기적으로 골든셋을 재작성해야만 하는 구조를 '한 번'이라는 거짓말로 은폐하여, 철학 정본이 금지한 「사람 손을 늘리는 해법(미룬 결함)」을 문서화해 두었다.

[P1] 13번 배포 전 검수의 "둘째 눈 OFF" — 비개발자 1인 체제의 검증 파탄
- **문서 위치**: §3 [다 · 검사] 13번 배포 전 코드 검수
- **지적**: 13번 자리의 근거로 "지은 쪽이 정한다 / 확정 / ⚠ 둘째 눈이 꺼져 있다"로 명시했다. 비개발자 1인 원장 체제에서 코드를 생성한 AI가 스스로의 코드를 자가 승인(self-approval)하고 둘째 눈(교차 검증)을 꺼둔 채 엔진과 앱 배관을 배포하도록 허용하는 것은, 철학 정본 게이트 ④완결(배관이야말로 급소)을 무력화한다. 검증되지 않은 코드가 조용히 라이브 시트와 DB를 오염시키는 사고를 방지할 최소한의 안전장치가 파괴되어 있다.

[P2] 26번 즉각 피드백(되돌아가는 말) 후보 방치와 24·25번 확정의 학생 경험 주객전도
- **문서 위치**: §3 [마 · 학생이 읽는 것] 24, 25, 26번
- **지적**: 게임화 학습의 핵심이자 학생이 앱을 다시 열게 만드는 원동력은 문제를 푼 직후 주어지는 즉각적인 감정적 보상과 오답 반응(26번 되돌아가는 말)이다. 그러나 정작 학생이 매일 마주치는 26번은 "어디에도 안 적혀 있다"며 후보로 방치한 반면, 정적인 홍보 문안(24번)과 종이 증서(25번)는 확정으로 올려두었다. 판단 정본 ①기본 게이트(재미+신선함)에서 가장 멀리 있는 인쇄물·홍보가 우선되고, 학생이 매 순간 체감해야 할 게임적 상호작용 설계가 뒷전으로 밀려나 있다.

## 이 문서보다 나은 대안 구조 (1개)

**「단일 자리(Role) 나열식」을 폐기하고, 「데이터 수명주기 4단계(생성 → 노출 → 판정 → 축적) 계약 파이프라인」으로 재설계하라.**

35개 자리를 평면적으로 쪼개 모델 이름을 매기는 대신, 모든 일감을 4단계 파이프라인으로 통일하고 공통 메타데이터 계약을 강제한다:
1. **생성 단계 (과제·UI 문구)**: 주 모델(클로드) 장애 시 대체 모델(GPT/제미나이)로 즉시 전환 가능한 어조 가이드라인(Tone Guard) 규격 수립.
2. **노출 단계 (학생 상호작용)**: 생성된 텍스트와 함께 `prompt_version_id`를 앱 로컬/세션에 보존하여 상호작용 이벤트와 결합.
3. **판정 단계 (채점·23유형 태깅·성향·삶 추출)**: 판정 모델이 무엇이든 출력 스키마에 `[model_id, temperature, rubric_version, timestamp]` 저장을 의무화(⑤·⑥번 기준 통합).
4. **축적 단계 (이해 3층 대장 반영)**: 판정 결과가 A-1 이해 대장의 실력(㉠)·사람(㉡)·삶(㉢) 중 어느 필드로 직결되는지 매핑 계약이 입증된 일감만 프로덕션 배포 허용.

이 구조를 취하면 35개 자리마다 다섯 칸을 채우느라 문서가 모순에 빠지는 일을 막고, 모델이 교체되어도 학생의 이해 시계열 데이터가 영구히 보호된다.
