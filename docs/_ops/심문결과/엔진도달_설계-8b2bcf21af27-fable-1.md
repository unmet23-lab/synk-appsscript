## P0

**[P0] §3 적격 규칙과 §3-1 음성 반출이 정본 안에서 서로를 부정한다 — 「redaction 공정」의 정의·생산자·설계가 0**
§3은 「`redaction_ver`를 거친 별도의 불변 산출물**만** 반출 적격」을 경로 B 전체의 유일한 게이트로 세우면서, §3-1은 `audio_ref`(원음성)를 B 반출 목록에 굵게 박았다. 그런데 문서 스스로 인용한 상위 정본 L0 §4-5 ②-1은 「학생은 작문·음성에서 제 이름·전화·회사·주소를 말한다 — 열 목록으로는 못 푼다 · 🔴 남는다」로 내용층 비식별 불가를 못박았고(실측: `docs/L0_데이터계약.md:477-483`), 물리에는 `redaction_ver`·`redaction_result` 열만 있고 writer 0줄이다(L0_스키마.sql:449·3088). 음성에 대한 redaction이 무엇인지(이름 구간 삭제? 그러면 STT 정렬·발음 평가셋이 깨진다 / 그대로 두면 공정이 지우기로 한 것이 산출물에 남는다), 동의·NDA가 redaction을 대체하는지 문서 어디에도 없다 — v1을 「텍스트 3칸으로는 음성 평가셋을 못 만든다」고 때려 고친 바로 그 자리(§3-1)가, 자기 게이트(§3)로는 원리상 못 지나가는 채 얼어붙는다. ⑥ 구현 세션은 어느 쪽을 따라도 정본 위반이 된다.

## P1

**[P1] §3-2 마지막 줄이 코드·장부·자기 §2 표와 3중 모순 — 「task.assigned 는 여전히 {사유}」는 거짓**
실측: `lib/이벤트검증.js:383`은 `'task.assigned': 학습자모델()`(도달·경로 A·소비자 `lib/학습자상태.js`)이고, `학습자상태.js:87`의 `쓰는사건`이 task.assigned를 실제로 읽어 마감여유분을 계산하며, `functions/deliver/index.ts:327`이 런타임에 호출한다(08-09부터). 문서 §2 표(08-11 재실측)조차 ⑦ 소비자가 섰다고 적으면서 §3-2는 「읽는 소비자가 0 · 여전히 {사유}」로 남았다(리포 판 110행). 같은 절 머리말이 「정정 전에는 새 세션이 이 절을 남은 일로 잡았다(F260과 같은 병)」고 경고한 바로 그 병을, 동결로 정본에 새기게 된다.

**[P1] 「재검수로 teacher 행이 여러 개 생겨도 승격은 한 번」 — 승격 뒤 갱신된 라벨이 영원히·조용히 훈련에 못 간다**
§3의 멱등키 (원본 event_id, 목적) 유일 + 불변 산출물 + `supersedes` 계보(물리칸 실재)를 합치면: 승격이 발화한 뒤 재검수가 `corrected_text`를 고쳐도 키가 이미 소진돼 새 라벨은 반출 불가고, 이는 실패가 아니라서 `pipeline_jobs.last_error`에도 안 남는다. 검수화면 스스로 「수정 m이 엔진에 가장 값진 신호」라 적은(src/검수화면.js:24) 바로 그 데이터가 낡은 판으로 굳는 조용한 실패 방향인데, 문서엔 산출물 무효화·재승격 규칙이 0이다.

**[P1] 훈·평 혼입 차단이 필드 선언뿐 — 멱등키 설계가 같은 원본의 이중 승격(train+eval)을 합법화한다**
§3은 「목적(train·eval — 혼입 차단)」과 「훈련셋 ⟂ 평가셋 분리」를 적었지만, 키가 (event_id, 목적)별 유일이라 한 원본 사건이 train으로도 eval로도 각각 승격될 수 있고 이를 막는 배타성 불변식이 없다. 같은 원본이 양쪽에 들어가면 평가가 오염되고, 그 평가는 불변식 5의 「모델 갈아타기 시험지」 판정에 쓰인다 — 오염은 조용하고 판정은 소급이 안 된다.

**[P1] 승격 의사 적재(⑤ 운영 임박)와 granted 발행(⑥ 코드 0) 사이 시차 규칙 부재 — 발행 시점 동의 생존 재확인이 스펙에 없다**
검수 콘솔은 운영 배포만 남았고(메모리 「남은 ⑥=운영 배포」) `promotion_intent`는 즉시 쌓이기 시작하는데 ⑥은 코드 0이다. §3 사슬은 「산출물 저장 성공 후에만 granted 발행」과 적재물(consent_id·확인 시각)만 정하고, 뒤늦게 짓는 ⑥이 밀린 의사를 소화할 때 그 사이 철회된 동의를 재확인하라는 조항이 없다 — 문서가 v1의 최대 죄로 인용한 「어느 동의 아래 나갔는지 영원히 모른다」가 시간 축으로 다시 열린다. 의사의 유효기간·재확정 요건도 미정의다.

**[P1] 철회 전파는 요구만 있고 설계 0 — 그리고 §4 장부가 그 부재를 원리상 영원히 못 본다**
`data_use.revoked` 생산자는 수동 runbook SQL이고(장부 사유 실측), 엔진도달 장부의 revoked 칸은 「전파가 서면 그때 적는다」인 제어 사건 = 사유 처리라 영원히 안 빨개진다(§5도 granted 쪽에 대해 같은 맹점을 자인한다). ⑥·⑦을 전부 초록으로 세워도 철회가 산출물·데이터셋에 닿는 배선이 0인 채 어떤 검사도 안 깨진다 — 문서가 「철회가 엔진에서 효력을 잃는다」고 이름 붙인 사고의 기계 장치가 없다. 곁들여 「모델 계보까지 내려간다」의 모델층 의미(이미 학습된 가중치는 못 되돌린다 — 재학습? 폐기? 표기만?)가 미정의다.

**[P1] §7 「통로는 C0 하나」가 검증기의 무조건 필수와 충돌 — 과거 시트 행은 그 통로를 원리상 못 지난다**
실측: `검증()`의 ④공통필수(correlation_id 포함 — 널허용 아님)·⑤이벤트별필수(submission.created의 `task_snapshot` — 택1 아님)는 주체 server 모드에서도 그대로 강제된다(이벤트검증.js:512-526 · server가 여는 것은 허용목록·서버칸 검사뿐). hw_feedback 과거 행에는 앉음(correlation_id)도 「그때 본 판」 스냅샷도 없고, 지어 넣으면 절단문서 ①-7이 금지한 오염이며 검증기는 지어낸 값을 못 가려낸다(비어 있지만 않으면 통과 — 조용한 실패 방향). 문서의 처방(결정론적 멱등키+manifest)은 이 두 칸을 안 다룬다 — 경계 선언이 그 경계의 통과 불가능성을 안은 채 얼어붙는다.

## P2

**[P2] 경로 A 입력 열거가 실구현의 진부분집합 — 코드가 문서 밖에서 5종을 더 읽는다**
§3 경로 A 입력 목록에는 choice.selected·learner_response·confidence·latency_ms·retry_of_event_id·session.abandoned뿐인데, 실구현은 task.assigned·submission.created·correction.viewed(`학습자상태.쓰는사건`)와 intervention.delivered·content.viewed(`성과회수`)를 추가로 소비한다. 동결되면 「아무 문서도 규정하지 않는 소비」(렌즈 10)가 정본 공인 하에 5종 생긴다.

**[P2] §4가 규정한 장부 값 모양이 구현과 다르다**
문서: 「값 = {경로, 부품, 소비자} xor {사유}」. 코드: `{ 도달: [ {경로,부품,소비자}, … ] } xor { 사유 }` — 배열이고, 코드 머리말이 「단일 튜플로 두면 A/B 병기가 표현 안 돼 일부 배선만으로 전부 초록이 된다」는 이유까지 적어 의도적으로 갈랐다. 정본이 구현이 버린 모양을 계속 규정한다.

**[P2] 「측정 08-11」로 적은 좌표 2건이 이미 틀렸다**
`pushGoldenFixture_`(`엔진_수집.js:1188`) → 실제 **1211행**, `tests/수집.test.js:717` → 실제 **726행**. 같은 날짜 도장이 찍힌 채 어긋난 좌표는 「행 번호는 근거가 아니다」(CLAUDE.md)를 정본 스스로 어긴 것이고, 동결 순간부터 낡는 종류의 값이다(`tests/강사통로.test.js:226`은 정확했다 — 전수 낡음이 아니라 부분 낡음이라 더 못 믿게 된다).

**[P2] ④칸 「운영 배포·API 키는 미확인(추정)」은 과소 서술 — 키 부재는 확인된 사실이다**
