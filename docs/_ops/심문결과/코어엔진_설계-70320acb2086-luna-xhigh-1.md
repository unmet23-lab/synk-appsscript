동결 불가. 다음 결함은 문서 전문 안에서 바로 성립한다.

- [P0] `schema_ver`가 정본과 동기화되지 않는다 — §A-8은 계약 `c10`, 코드 상수 `c13`, 검증기 제거, 손수 갱신을 동시에 기록한다. 행에는 실제 payload 규격이 아니라 잘못된 판번호가 들어갈 수 있어 과거 행 변환·재계산이 불가능해진다.

- [P0] 계약만 있고 원본 증거 생산자가 없다 — §5는 E0 코드 0줄을 유지하고, §10 실행 초안은 `user_confirmed` 물리 구현 0·확신도 확장 구현 0으로 적고 있다. 학생 행동이 먼저 발생하면 빈 값과 미수집이 같은 모양이 되어 소급 복원이 불가능하다.

- [P0] 멱등성은 이름만 있고 실행 규칙이 없다 — §10의 `event_id`·`idempotency_key`에는 생성 주체, 유일성 범위, 충돌 시 처리, 재전송 판정, 동시 제출 규칙이 없다. 오프라인 재시도에서 중복 제출이 재시도로 세어지거나 실제 재시도가 사라질 수 있다.

- [P0] 시간 필드의 기준이 충돌한다 — §10은 리듬을 `created_at`으로 계산한다고 하면서 이벤트 봉투에서는 `occurred_at`과 `ingested_at`을 분리한다. 오프라인 업로드·기기 시간 차이에서 제출 시각, 지연, 마감 대비 여유가 잘못 기록되고 나중에 복원할 수 없다.

- [P0] 재시도와 교정 반응을 실제로 연결할 수 없다 — §A-10 ①의 재시도차수에는 안정적인 시도 그룹 ID, 문항 버전, 이전 시도 참조가 없다. `correction.viewed`는 봤다는 사실만 남길 뿐 채택·무시·수정과 수정된 학생 산출물을 특정 교정에 연결하지 못한다.

- [P0] 개입→성과 사슬이 명목상으로만 존재한다 — §10은 `intervention_id`와 `intervention.delivered`를 말하지만 개입 정의의 버전·대상 `skill_id`·전달 성공 확인·완료·건너뜀·성과 연결 ID가 없다. 따라서 즉시·1일·7일·30일 성과를 계산할 수 없고, 핵심 자산인 개입 효과 데이터가 끊긴다.

- [P0] 선택 로그가 당시 선택지를 재현하지 못한다 — §A-10 ②의 `options_shown`·`position`에는 안정적인 선택지 ID, 선택지 원문 스냅샷, 제시 묶음 ID, 화면·설정 버전이 없다. `changed_selection`과 `latency_ms`의 시작점도 정의되지 않아 학생 선호와 시스템이 유도한 선택을 구분할 수 없다.

- [P0] `task_snapshot`은 이름만 있고 완전성 보장이 없다 — §9와 §A-8은 스냅샷을 소급 매핑의 근거로 쓰지만 필드 구성, 직렬화 버전, 해시, 음성·번역·보기·채점 기준·교정 원문 포함 여부를 동결하지 않는다. 현재 문제 원문만 남아도 미래의 AI 생성 과제나 음성 과제는 학생이 실제 본 자극과 판정 조건을 재현할 수 없다.

- [P0] 기능별 수집 커버리지 표가 없다 — §4·§10은 여러 엔진 재료를 열거하지만 `기능→이벤트→필수 필드→엔진 부품→회수 시점` 매트릭스가 없다. 미시작·중도 이탈·전달 실패·계측 누락이 모두 “이벤트 없음”으로 합쳐져, 실패가 정상처럼 통과한다.

- [P0] 지식 회수 경로가 서로 모순된다 — §8-1은 시트를 편집면, Supabase를 기계 정본으로 두고 시트→DB 단방향 파생을 명시한다. 반면 §A-5는 회수·발행 플래그가 시트→DB 동기 주기와 무관하게 게이트웨이에 실시간 반영된다고 한다. 어느 저장소가 판정 원천인지와 원자적 반영 시점이 없으므로 회수된 지식이 계속 소비될 수 있다.

- [P0] 호출·인용 로그가 회수에 충분하지 않다 — §9와 §A-10 ⑤는 `cited_refs`·`model`·`prompt_ver` 정도만 요구한다. 호출 ID, 모델 실제 revision, prompt/input hash, 지식 인덱스 버전, 다중 호출·fallback 연결이 없어 특정 답변에 어떤 지식과 어떤 호출이 사용됐는지 재구성할 수 없다.

- [P0] 강등 경로가 학습 데이터 관점에서 정의되지 않았다 — §A-4는 엔진 무응답 시 기본 동작만 요구한다. 강등 결과를 개입으로 볼지, 실패로 볼지, 실패 사유·재시도·개입 ID를 어떻게 기록할지 없어 정상 응답과 강등 응답이 같은 모양이 된다.

- [P1] `skill_id`가 있어도 의미 보존 장치가 없다 — §A-10 ④에는 필수 여부, 미매핑·복합 스킬 처리, 폐기·대체 규칙, 정의 버전이 없다. 현재 매핑이 0인 상태에서 null이나 의미가 바뀐 동일 ID가 통과하면 이벤트를 엔진 부품에 안정적으로 연결할 수 없다.

- [P1] 파생 라벨과 학생 확인의 신분이 충돌한다 — §10은 라벨을 파생으로만 두겠다고 하면서 확인 답변이 `explicit`으로 승격된다고 한다. 확인 답변을 불변 원본 사건으로 남기는지 파생 상태를 직접 수정하는지, 기존 추정과 충돌·만료될 때 어떻게 재계산하는지가 정의되지 않았다.

- [P1] `source_kind`별 필수 규칙과 충돌 해결이 없다 — §10은 `inferred`에 confidence·evidence·estimator 버전을 요구하지만 `explicit`·`teacher`·`observed`의 필수 필드와 상충 증거 처리 규칙은 없다. 서로 다른 출처의 동일 주장에 어떤 근거가 소비되는지 기계적으로 판정할 수 없다.

- [P1] 평가셋 게이트의 분모가 갈린다 — §6은 100문항을 말하고, 같은 문서 후반은 102문항·미측정 76문항을 말하며 낡은 기록에는 74문항이 남아 있다. 어느 fixture 버전과 채점률·점수 기준으로 파인튜닝 조건 ②를 판정하는지 고정되어 있지 않아 자동 판정이 불가능하다.

- [P1] E0와 E2 상태가 충돌한다 — §5 보정문은 학습자상태·생성 트랙·FSRS 실물이 이미 섰다고 기록하지만 §6은 “지금 구현 착수 금지”, §5의 표는 E0 코드 0줄을 유지한다. E2 실물을 유지·확장해야 하는지 금지해야 하는지 문서만으로 결정할 수 없다.

- [P1] 닫힌 방향과 E3가 모순된다 — §0은 “직업별 설계 자동 구현”을 폐기하고 개인 이해→로드맵→학습 자동화로 축을 정정했다. 그러나 §5 E3는 직업 프로필에서 지식팩·프롬프트·평가셋을 자동 조립하며 “직업별 설계까지”라고 다시 적는다.

- [P1] 훈련 승격 사건의 계보 필드가 빠져 있다 — §9는 승격을 별도 사건이라고 하지만 §A-10은 `data_use.granted`와 `dataset_item` 이름만 남긴다. `artifact_ref`, `content_hash`, `serializer_ver`, `dataset_ver`, 라벨 출처, 승인자, 평가 참조, 제외·rollback 사건이 계약상 필수로 묶이지 않아 나중에 어떤 산출물이 어떤 데이터셋에 들어갔는지 재현할 수 없다.

- [P1] 학생에게 돌아오는 즉시 가치가 없다 — §10의 성향 확인 카드는 엔진용 질문만 제시하고, 학생이 그 답으로 당장 어떤 한국어 연습을 더 잘하게 되는지 설명하지 않는다. 이는 판단 정본 ①의 “실제로 말하거나 쓰게 만드는 도움”과 재미·신선함 게이트를 충족하지 못한다.

- [P1] 자기설명 게이트를 통과하지 못한다 — §10의 `?`·`??` 재사용안에는 첫 사용자를 위한 의미 설명, 답해야 하는 이유, 답한 뒤 무엇이 바뀌는지가 없다. 판단 정본 ⑤가 금지한 “만든 사람만 아는 화면”이 그대로 생긴다.

- [P1] 목표 맥락이 재현되지 않는다 — §A-10 ②는 당시 목표를 맥락으로 넣으라고 하지만 드림맵·나침반·시즌 회고의 버전 또는 snapshot ID가 없다. 목표가 바뀐 뒤에는 추천 당시 시스템이 어느 목표를 보고 있었는지 알 수 없다.

- [P2] E0에 미래 파생 설계를 과도하게 동결한다 — §9의 14분류, 5축, 선택 telemetry, 인과 성과 창, 봇 팩토리까지 포함됐지만 학생 데이터와 생산·검증 규칙은 아직 없다. 원본 사건에 필요한 최소 필드와 나중에 바꿀 파생 모델을 분리하지 않아, 미검증 개념이 앱 계약의 장기 부채가 된다.

이 문서보다 나은 대안 구조 1개:

`불변 원본 이벤트 봉투`와 `사건별 payload 계약`을 분리하고, 별도로 `콘텐츠·개입·선택지·목표 snapshot registry`를 둔다. 각 기능마다 `기능→이벤트→필수 필드→엔진 소비자→회수 시점` 매트릭스를 동결 게이트로 사용하며, 학습자 상태·성과·훈련 데이터셋은 이 원본에서 재계산되는 파생층으로만 둔다.
