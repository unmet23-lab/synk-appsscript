[P0] 미구현·미측정 상태를 ④✓로 위장한다 — §0은 `배포 빚 0`이라지만 §8에는 구멍 5개·원리상 26개가 남고, §11은 운영 Supabase 적용 상태가 미측정이라고 적었다. §3~§7의 도장은 모두 “예상”이다. 실제 저장·자동 읽기·이해 대장 증가를 확인하지 않은 ✓는 동결 시 실패를 통과로 만든다.

[P0] 읽기 기록이 실제 읽은 재료를 보존하지 않는다 — §3의 `life`와 `person`은 source만 있고 목표 문장, 무대 ID, 성향 축 목록, 상태 스냅숏 참조가 없다. `skill`도 skill ID만 있어 선택기 버전·후보 집합·당시 계산 입력을 재현할 수 없다. 목표나 상태가 바뀐 뒤에는 과제가 정확히 무엇을 읽었는지 복원할 수 없다.

[P0] E2의 두 판정 갈래를 하나의 source 값으로 눌러버린다 — §7은 E2가 급수 매핑과 FSRS 복습 근거라는 두 갈래라고 명시하지만 §3의 `skill.source`는 단일 문자열이다. 급수 필터와 FSRS due가 함께 작동한 경우 어느 규칙이 적용됐는지, FSRS 버전·파라미터·due 시각이 무엇이었는지 남지 않는다. 이후 ⓓ·E2 비교는 재현 불가능하다.

[P0] 학생이 고른 무대를 증명할 후보 사건이 없다 — §4는 후보 3~5개를 만들고 안 물은 후보는 저장하지 않는다고 한다. 그러나 후보 집합 ID, 후보 ID, 후보 원문 스냅숏, 생성 시점, 목표 버전이 정의되어 있지 않다. 첫 목표 답변은 다시 얻을 수 없으므로 `맞다` 사건만 남으면 학생이 무엇 중에서 골랐는지와 후보 품질을 영구히 복원할 수 없다.

[P0] `goal_used`라는 벤더 자기보고를 사실 판정자로 사용한다 — §4는 boolean 하나로 학생 화면의 “네가 고른 무대에서 가져왔어”와 빛 축을 결정한다. 파서는 자료형만 검사할 뿐 실제 문장이 무대를 반영했는지 검증하지 않으며, §11도 정확도가 미측정이라고 인정한다. 미검증 자기보고로 학생에게 설명하고 성과를 집계하는 것은 즉시 오염되는 경로다.

[P0] c15 판올림의 구버전·혼합 배포 계약이 없다 — §3은 기존 `task.assigned` payload가 `{ver:1}`이라고 하면서 nested `reads`를 추가하지만 payload 버전 승격과 구버전 재처리 규칙을 정하지 않았다. `event_draft`·finalize·due sweep·deliver와 두 저장소의 생산자·소비자가 한 번에 바뀐다는 보장도 없다. 혼합 배포에서 새 필드는 무시되거나 검증 거절되며, 어느 경우든 실패가 조용히 데이터 누락으로 바뀔 수 있다.

[P0] 멱등성·동시성·오프라인 재시도가 정의되지 않았다 — §4~§6에는 후보, 카드, 응답, 추정치의 안정 ID나 idempotency key, causation ID, 유일성 규칙이 없다. 카드 재전송이나 두 기기 동시 응답이 중복 사건을 만들면 §6의 “키별 마지막 답”이 중복을 정상 답처럼 접어버린다. 오프라인 응답의 재전송·순서 역전·실패 재개 규칙도 없다.

[P0] 실패와 “자료 없음”이 같은 모양이다 — §3의 `empty_reason`는 `사유`라는 열린 값과 예시만 있고 후보 생성 실패, 파서 거절, 카드 미예약, 전달 실패, 상태 만료를 구분하지 않는다. 실패 시 사건 자체가 남지 않아도 `no_stage_yet`나 무응답처럼 보일 수 있다. 그러면 읽기 커버리지와 ④ 도장이 실패를 누락한 채 통과한다.

[P0] 확정 무대의 생명주기와 현재값 접기가 없다 — §4~§5에는 여러 무대를 확정했을 때의 우선순위, 교체·철회 사건, `effective_from/to`, 시즌별 활성값, 중복 확정 처리 규칙이 없다. 16주 재확인은 성향 관에만 명시되어 무대의 만료 의미도 불명확하다. 시간이 지나면 동일한 사건 집합에서 서로 다른 현재 무대를 계산할 수 있다.

[P1] 하루 한 장 카드가 어떤 채널을 선택하는지 정의되지 않았다 — §5는 리듬·집중 시간·작성 과정·무대 후보가 한 장을 놓고 경쟁한다고 하면서 우선순위·무작위화·기아 방지·노출 사건을 정하지 않았다. `맞다/아니다`만 저장하면 “질문받지 않음”과 “거절함”을 분리할 수 없다. 실제 응답 뒤에 v2 우선순위를 정하는 것은 이미 잃은 라벨을 복구하지 못한다.

[P1] 동의율은 모델 평가 자가 아니다 — §6의 `맞다/(맞다+아니다)`에는 노출 수, 질문 문구 버전, 추정 가설 ID, 최소 표본, 신뢰구간이 없다. 쉬운 추정만 묻거나 문구를 바꿔도 점수가 올라가며, 마지막 답 접기는 과거 모델의 라벨을 소급 변경한다. 학생 자기보고가 참값이 아니라고 적어 놓고도 모델 교체 성적표의 둘째 축으로 사용하는 논리가 닫히지 않았다.

[P1] 읽기 커버리지의 분모가 실행 가능한 정의가 아니다 — §3은 분모를 “그 밤 생성 수”라고만 한다. 재시도, 취소, 전달 실패, 부분 생성, 시간대 경계, `task.assigned`와 실제 학생 노출의 차이를 정하지 않아 같은 사건도 집계자에 따라 다른 곡선이 나온다. 생성 실패를 분모에서 빼면 커버리지는 자동으로 부풀려진다.

[P1] ⓓ FSRS 비교표는 반사실 비교가 아니다 — §7은 고정 14일과 FSRS due를 같은 리뷰 열에서 나란히 보겠다고 하지만 동일 카드가 두 정책을 동시에 경험하지 않는다. 정책별 카드·학생 할당, 홀드아웃, 결과 관찰창이 없으면 차이는 스케줄러 효과인지 카드 구성·학생 선택 효과인지 분리할 수 없다. 비교표는 판정 재료가 아니라 관찰 목록에 머문다.

[P1] ①의 “실제로 쓸 한국어” 게이트가 없다 — §4의 후보 확정과 `goal_used`는 목표 장면이 문장에 들어갔는지만 가리킨다. 학생 급수에 맞는 난이도, 실제 발화 행위, 문법 겨냥, 자연성·정확성, 병원 상황의 적합성을 검증하는 필드나 판정기가 없다. 기존 `sentence/question` 텍스트 검문만으로는 “병원이라는 단어가 들어간 문장”을 실사용 한국어로 오인할 수 있다.

[P1] 되묻기가 재미가 아니라 설문이 된다 — §5의 새 채널은 하루 한 장의 `맞다/아니다` 응답을 늘리지만, 응답 직후 학생에게 돌아오는 보상·변화·선택의 결과가 없다. §4의 무대도 서너 번에 한 번만 쓰이므로 첫 응답이 왜 다음 행동을 개선하는지 학생이 볼 수 없다. 문서가 경고한 “확인이 설문이 되는 순간 재미 조건 붕괴”를 막는 실제 학생 경험 게이트가 없다.

[P1] ⑤ 자기설명이 한 줄과 각주로 축소됐다 — §1은 처음 본 사용자가 기능의 전체 그림과 재료 간 연결을 알아야 한다고 요구하지만, §4는 과제 머리 한 줄, §5는 증거 동봉, §6은 계기판 각주만 제시한다. 학생에게 왜 이 카드를 받았고 응답이 다음 과제·상태·회고에 어떻게 연결되는지는 정의되지 않았다. 만든 사람만 이해하는 내부 배관 설명이지 자기설명 계약이 아니다.

[P1] §9의 최신 근거 수치가 추적 불가능하고 일부는 1차 자료와 맞지 않는다 — 문서는 Khanmigo RCT를 `0.34SD`라고 적지만, 2026년 NBER 1차 연구는 ITT 기준 약 `0.06~0.08SD`, 적극 참여를 가정한 분석도 `0.14SD`로 보고하며 사용 빈도도 낮았다고 설명한다. [NBER 원문](https://www.nber.org/papers/w35620)과 다른 수치를 쓰려면 별도 연구의 표본·설계·DOI가 필요하다. 출처 없는 수치로 되묻기·협상형 OLM의 근거를 세우면 설계 판단이 오염된다.

[P2] “최신 정보”가 개원 시점까지 유지된다는 재검증 장치가 없다 — §9에는 연구명·버전·원문 링크·적용 범위·재검토 기한이 없다. 개원 예정일은 2027년인데 2026-09 정찰 결과가 그대로 남으면 어떤 근거가 폐기됐는지 판단할 수 없다.

이 문서보다 나은 대안 구조 1개: 기존 `learning_events` 안에서 `candidate_exposed → student_decided → task_assigned → delivered/submitted → outcome`의 사건 사슬로 분리한다. 각 사건에 `schema_ver`, 안정 ID, idempotency key, causation ID, snapshot_ref, producer version, 명시적 failure status를 필수화하고, 후보도 노출 사건으로 저장해 선택·거절을 연결한다. 과제 배정에는 세 층 각각의 실제 입력 참조와 선택 이유 배열을 남기고, 집계는 성공·실패·미노출을 분리한 사건만 사용한다.
