동결 불가.

1. [P0] 판본이 서로 다른 계약이다 — §0은 현행 c6, §4는 c9·c10, §8·§9는 c4를 정본처럼 쓴다. 현재 `계약/수집_교정_계약.json`은 c10·event_type 13종이므로 c4 DB와 c10 앱이 동시에 통과할 수 있다. §0·§3·§4-1·§8·§9.

2. [P0] 동결 대상 범위가 모순이다 — §0은 “엔드포인트 둘”이라고 하지만 실제로는 이벤트·업로드·조회 3종·인증 3종, 총 8개다. §10은 progress가 남았다고 하면서 §4-3은 구현 완료라고 해 승인 대상과 완료 상태를 판정할 수 없다. §0·§4·§10.

3. [P0] 왕복 6은 동결 증명이 아니다 — #1~4는 리허설, #5는 순수 함수 회귀, #6은 실제 만료가 아닌 모의 401이다. 실기기 음성, 실제 access/refresh token 폐기, Storage, RLS, 마이그레이션 재실행·중간 실패·롤백은 동결 게이트 밖이다. §7·§8.

4. [P0] 실행 가능한 이벤트 스키마가 없다 — 13개 event_type별 필수·null·금지·타입·참조 대상이 C0가 아니라 숨은 `lib/이벤트검증.js`와 산문에 분산돼 있다. `data_use.granted`, `exam.result`, `session.abandoned`, `content.viewed`가 빈 껍데기인지 유효 사건인지 문서만 읽고 판정할 수 없다. §4-1·§6.

5. [P0] 필드 정본과 API 예시가 이미 갈라졌다 — 요청에는 `session_id`·`content_id`·`task_schema_ver`가 있지만 현재 계약 JSON의 learning_events 필드 목록에는 없다. `/tasks`도 이 값을 내려주지 않으므로 앱이 보내면 미등록 필드 거절, 생략하면 콘텐츠·문항 판본 연결 소실이다. §3·§4-1·§4-3①.

6. [P1] 스냅샷 판본과 내부 키가 세 벌이다 — `payload.ver`, `task_snapshot.ver`, `task_schema_ver` 사이의 일치 규칙이 없다. `지시문`·`문항`·`보기`·`정답`·`호흡` 같은 한글 내부 키도 L0 영문 필드명 규칙과 충돌하며 JSON 구조가 검증되지 않는다. §4-1·§4-3①.

7. [P0] `schema_ver`가 실제 생산 규격을 거짓말한다 — 서버가 항상 현재 계약판을 찍으므로 c8 앱의 오프라인 행도 c10 행처럼 저장된다. `X-App-Ver`는 요청 로그용일 뿐 개별 이벤트에 결속되지 않아 혼합 큐의 실제 생산판을 복원할 수 없다. §3·§4-1·§6.

8. [P0] RLS를 우회한 직접 SQL이 단일 방어선이다 — `SUPABASE_DB_URL`의 postgres 연결은 PostgREST·RLS를 통과하지 않으며, 문서도 함수의 `where`가 유일한 방어선이라고 인정한다. events·uploads·progress·Storage 경로별 필수 소유자 조건과 전수 교차학생 테스트가 없어 한 쿼리 누락이 즉시 타학생 접근으로 이어진다. §1·§4-3.

9. [P0] 학생이 서버·교사 사건을 위조할 수 있다 — `/events`는 event_type 값목록만 말할 뿐 주체별 허용 사건을 정의하지 않는다. 학생 토큰으로 `task.assigned`·`intervention.delivered`·`exam.result`·`data_use.granted/revoked`를 보내도 막을 계약이 없다. §4-1·§4-4·§9.

10. [P0] “유일한 쓰기 통로”가 거짓이다 — §4-1은 모든 사건이 `/events`를 지난다고 하지만 배치 `deliver`가 `task.assigned`와 `submissions`를 직접 쓴다. 직접 writer가 동의·멱등·필드·배우자 참조 검증을 동일하게 거친다는 공통 ingest 계약이 없다. §1·§4-1·§4-3①.

11. [P0] 훈련 승격 사건이 이름뿐이다 — `data_use.granted/revoked`에 `artifact_ref`, `content_hash`, `serializer_ver`, `dataset_ver`, `redaction_ver`, 정확한 consent_id·검사 시각·승인자·철회 대상이 없다. 빈 사건만 남아도 물리적으로 정상 저장되므로 어떤 산출물이 어느 모델에 들어갔는지 재현·롤백할 수 없다. §4-1 payload·§9.

12. [P0] 이벤트가 엔진에 도달하지 않는다 — 현행 `엔진도달_설계.md`는 AI 1차, 사람 검수, 승격, 엔진 소비자 모두 0으로 기록하고 있다. C0는 적재를 동결하면서 수집→엔진 자동화 완료를 선언할 근거가 없다. §4-1·§8·§10.

13. [P0] 세션 폐기는 문장뿐이다 — reset은 `revoked_before`를 쓴다고 하지만 events·uploads·조회 3종이 매 요청 `session_alive()`를 확인해야 한다는 실행 계약이 없다. `verify_jwt`는 만료 전 access token을 폐기하지 않으며, §7-6도 실제 옛 토큰을 재지 않는다. §2·§4-5·§7.

14. [P0] `director` 인증이 공백이다 — §4-5는 director token을 요구하면서 §2에는 학생 인증만 있고 직원 역할 발급·폐기·갱신 계약이 없다. 이미 닫힌 “강사·원장·운영자 인증은 S1 밖” 결정과도 충돌한다. §4-5·§10.

15. [P0] 첫 등록 게이트가 4자리 비밀에 의존한다 — 공개 `student_code`와 10,000가지 `phone_last4`만으로 공격자가 비밀번호를 먼저 정할 수 있다. 학생별 5회 잠금만 있고 IP·기기·전역 속도 제한이 없어 전원 잠금 공격과 계정 선점이 가능하다. §4-4.

16. [P0] 동의 화면 요구가 닫힌 결정과 충돌한다 — §5·§7은 앱 안에서 동의 화면을 띄우라고 하지만 닫힌 결정은 S1 앱 동의 화면을 금지하고 운영자 통로로 정했다. 게다가 C0에는 동의 조회·생성 API가 없어 앱이 사전 게이트를 실행할 방법도 없다. §4-2·§5·§7.

17. [P0] 신뢰하지 않는 `occurred_at`이 동의 효력을 결정한다 — 미래 시각을 허용하면서 `agreed_at <= occurred_at`로 동의를 판정하므로 클라이언트가 사건을 미래로 미룰 수 있다. 서버 관측 시각·캡처 시각·허용 오차가 없고 “로그에만 남김”도 이벤트와 연결되지 않는다. §3·§4-1·§5.

18. [P0] 업로드가 사건에 결속되지 않는다 — `/uploads/sign` 요청에는 event_id·idempotency_key·task_ref·upload intent가 없는데 응답 경로는 아직 존재하지 않는 event_id를 전제로 한다. 서버가 업로드를 특정 사건에 한 번만 소비했는지 검사하지 않아 하나의 음성을 여러 제출에 붙이거나 다른 과제에 재사용할 수 있다. §4-2.

19. [P0] 업로드 실패가 영구 고아 파일을 만든다 — Storage PUT 뒤 events가 동의·계약·참조 오류로 거절되면 파일 삭제·재사용·고아 정리 절차가 없다. `state:"missing"`·`unmeasured`도 나중에 재측정하거나 불변 행을 보정할 통로가 없어 원본과 메타가 영구히 갈라진다. §4-2·§5.

21. [P0] 오프라인 큐가 계정에 묶이지 않는다 — A가 오프라인 상태에서 남긴 항목을 같은 기기에서 B가 로그인하면 서버는 토큰의 B를 기준으로 저장한다. 요청 본문에 learner_id를 넣지 않는 원칙만 있고 큐 소유자·로그아웃 시 격리·계정 전환 폐기 규칙이 없다. §2·§4-1·§7.

22. [P0] 멱등키 충돌이 데이터 손실로 위장된다 — 같은 `(learner, idempotency_key)`면 본문·음성·스냅샷이 달라도 원래 event_id를 duplicate로 반환한다. 서버 배치의 날짜 결정론 키까지 포함하면 같은 날 과제가 바뀌어도 새 사건이 조용히 기존 사건에 접힌다. §4-1.

23. [P0] 배정·개입과 최초 제출이 연결되지 않는다 — `/tasks`는 `task_id`와 `intervention.event_id`를 주지만 제출 요청은 task_id·intervention_id를 되돌려 보내지 않는다. 서버의 intervention_id 계승은 `retry_of_event_id`가 있을 때뿐이라 최초 제출의 성과를 어느 개입이 만들었는지 복원할 수 없다. §4-1·§4-3①.

24. [P0] `retry_of_event_id`가 결과 변수의 의미를 보장하지 않는다 — 계약은 해당 포인터가 실제 제출 사건인지, 교정이 확정·열람됐는지, 같은 학생인지, 날짜를 건넜는지 강제하지 않는다. `/progress`는 포인터만 있으면 교정 성과로 세며, 교정문 재제출은 오늘의 개입 B가 아니라 원 개입 A에 귀속된다. §4-1·§4-3①·③.

25. [P0] 스킬·목적 맥락이 제출까지 도달하지 않는다 — `/tasks` 응답에는 `skill_ids`, taxonomy 판, `content_id`, `task_schema_ver`가 없고 `skill_ids`는 빈 배열이 정상이다. `goal_snapshot`은 역사적 필드라고 설명하면서 key 존재 검사는 level에만 있어 누락과 실제 null을 구분하지 못한다. §4-1·§4-3①.

26. [P0] 빈 과제와 배치 장애가 같은 정상 응답이다 — `data:[]`가 무배정·첫날·배치 실패를 모두 뜻하고 앱은 고정 도입 과제를 띄운다. 동시에 `task_ref`가 없으면 제출하지 말라고 하므로 화면은 작동해도 첫 발화 기준선은 아무 오류 없이 소실된다. §4-3①·§7.

27. [P1] 교정 목록이 확정 교정만 보장하지 않는다 — `confirmed_at=created_at`으로 치환하면서 actor_kind별 확정 여부 필터가 없다. AI 초안이 텍스트와 태그를 갖고 있으면 학생에게 최종 교정처럼 노출될 수 있고, 반대로 “오류 없음”처럼 corrected_text가 빈 유효 판정은 목록에서 탈락한다. §4-3②.

28. [P1] progress 집계가 사건 의미를 검증하지 않는다 — 자유 JSON의 `attempt_no`를 숫자일 때만 읽고, `retry_of_event_id`는 실제 교정 관계인지 검사하지 않는다. assignment/system 사건과 클라이언트 시각도 첫 사건·일자 집계에 섞일 수 있어 “어제의 나”가 조용히 틀린다. §3·§4-3③.

29. [P0] 타학생 `correction_id` 오류가 재시도 가능한 서버 오류다 — 문서가 다른 학생 ID를 400이 아닌 서버 오류로 반환한다고 명시한다. §5의 5xx 재시도 규칙과 결합하면 영구 권한 오류가 큐를 계속 붙잡고 정상 배치까지 막는다. §4-1·§5.

30. [P0] 음성 규격이 아직 닫히지 않았다 — AGC·노이즈 억제 제어가 없고 실제 iOS/Android 두 기기 헤더 실측도 하지 않았는데 규격 밖 파일을 저장한다. §8 동결 조건에는 이 실측이 없어 첫 수집부터 되돌릴 수 없는 음성 신호 오염이 허용된다. §4-2·§8.

31. [P1] 음성 길이의 저장 위치가 갈라진다 — C0는 서버가 `capture_meta.server.duration_ms`만 채운다고 쓰지만 현재 소비자 계약은 `submissions.audio_duration_sec`라는 별도 열을 읽는다. 두 자리의 단위·복사 규칙·필수 쓰기가 없으면 봉투에는 값이 있어도 검수·게임·엔진에는 0으로 남는다. §4-2.

32. [P0] 웹 앱 통로가 없다 — 스택은 Expo native+web인데 음성 경로는 Android/iOS native `AudioStream`만 정의한다. 또한 `X-Contract-Ver`·`X-App-Ver` 같은 사용자 헤더를 요구하면서 OPTIONS/CORS 계약이 없고, 현행 Edge Function CORS 미구현 상태에서는 웹 왕복 자체가 불가능하다. §1·§3·§4-2.

33. [P1] 오류 계약이 서로 충돌한다 — `PAYLOAD_TOO_LARGE`는 retryable=false인데 앱 행동은 쪼개 재전송이고, `AUTH_EXPIRED`는 gateway의 평문 401 때문에 실제 봉투 코드가 없다. first-login의 `already:true` 성공과 이미 등록된 401도 동시에 정본으로 존재한다. §4-4·§5·§7.

34. [P1] 임시 상한을 동결 계약에 넣었다 — 이벤트 100건/1MB와 업로드 25MB를 “임의값·S1 실측으로 조정”한다고 적었다. 상한 변경 시 어떤 앱이 어떤 이유로 거절됐는지 판본·호환 규칙이 없어 소급 불가능한 배치 손실이 발생한다. §4-1·§4-2·§6.

35. [P2] 이미지 업로드는 연결된 소비자가 없다 — `/uploads/sign`은 `image`와 `image/` 경로를 열지만 events 요청에는 `image_ref`나 이미지 제출 스키마가 없다. 사용하면 영구 보존되는 연결 고리 없는 파일이고, 사용하지 않으면 C0에 불필요한 보안 표면만 남는다. §4-2.

이 문서보다 나은 대안 구조가 있으면 1개:

C0를 산문 문서가 아니라 `c10` 단일 기계계약으로 재구성한다. 이벤트별로 주체·인증·JSON 타입·필수/null/금지·동의·인과 참조·멱등 해시·writer·consumer를 한 매트릭스에 두고, 앱/서버 검증기·문서·픽스처를 그 매트릭스에서 생성해야 한다. 동결은 실제 Supabase/Auth/Storage·RLS·마이그레이션·native/web 왕복까지 같은 버전 묶음으로 통과한 경우에만 허용한다.
