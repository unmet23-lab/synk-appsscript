## 이 문서보다 나은 대안 구조 1개

**불변 실행 매니페스트 구조**가 낫다.

- `generation_batch_runs`에 그날 재적 전원의 결정 매니페스트를 한 번 저장한다: 학생별 `게임|기존|비대상|생성|조립실패`. 게임은 기존 결정대로 job·개입을 만들지 않되 매니페스트에는 남겨 전원 커버리지를 증명한다.
- 모든 수치는 매니페스트에서 파생하고, job은 정확히 한 run·날짜에 결속한다. 오케스트레이터는 완주할 때까지 같은 cron에서 멱등 재실행하며, 구제 실패는 예외를 올리지 않고 같은 트랜잭션에서 `오류` 행과 typed 결과를 커밋한다.
- 평가판은 실시간 roster와 분리한 고정 40사례로 둔다. 두 출력을 사례 한 행에 묶어 축별 AND를 파생하고, 원문→해시→파서 산출 결속을 검증하며 roster 분포는 다음 평가판 후보 보고에만 사용한다.
