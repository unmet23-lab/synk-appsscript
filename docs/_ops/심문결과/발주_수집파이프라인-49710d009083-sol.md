이 문서보다 나은 대안 구조 1개 — `원본 증거 → 검수 판정 → 승격 의사 → 불변 산출물 → 사용 승격 → 데이터셋 멤버십 → 실제 소비·성과`의 7단 append-only 계약으로 분리한다. `data_use.granted`는 정확한 검수 결정과 성공한 산출물만 가리키고 `dataset_ver`는 갖지 않으며, 별도 `dataset_item`이 split·group_id·dataset_ver를 들고 train/eval 상호배타를 강제한다. 작업 선점은 단일 SQL RPC+outbox로 처리하고, 재검수·제외·철회·롤백은 원본을 고치지 않는 후속 사건으로 남기며 모든 비동기 경계에서 철회를 재검사한다. 개인화는 별도 경로로 `intervention.delivered → content.viewed → 즉시·지연 성과`를 잇고, 마지막 성공 조건은 단순 조회가 아니라 소비 영수증과 실제 후속 개입 사용 기록으로 둔다.
