## 2. 실물이 「맞다」고 답한 것 (채택 6)

### ③ E2의 두 갈래를 하나의 source 값으로 눌러버린다 → **채택** 🔑 발음 규격과 같은 병

실물 `lib/읽기기록.js`:

```
skill: { source: 'rotation' | 'fsrs_due' | 'curriculum_intro', value: [...] }
```

설계 §7이 E2를 **두 갈래**로 못박았다 — 본체 = 급수→기술 매핑(후보 집합을 「거른다」) ·
둘째 갈래 = FSRS due(그 안에서 「고른다」). 이 둘은 **동시에 성립**하는데 `source`는 문자열 하나다.
급수 필터 위에서 회전이 돌면 `rotation` 인지 「급수필터+rotation」 인지 적을 칸이 없다.

🔑 **이 무늬를 어제 이미 고쳤다** — `docs/발음데이터_규격.md` 의 다축 표기(`P3;P9`)가 같은 병의 처방이다.
한 칸이 동시에 참인 축 둘을 지려다 하나를 버리는 자리.

**처방(싸다 · E2 열리기 「전」이라 값이 안 쌓였다)**: `skill` 을 `{filter, picker, value}` 셋으로 가른다 —
`filter: null|'level_map'` · `picker: 'rotation'|'fsrs_due'|'curriculum_intro'`. 지금 값은 전부
`{filter:null, picker:'rotation'}` 이라 **의미 손실 0**이고, E2가 나는 날 바뀌는 것은 여전히 값 하나다.

### ④ 학생이 고른 무대를 증명할 후보 사건이 없다 → **채택** (미시공 구간 — 지금이 제일 싸다)

계약 c15 절 실측: 무대 갈래는 `preference.stated` 확장으로 **어휘만** 섰고 「생산자(hw_text 추출기·
무대 파생)는 아직 0」 이다. 즉 §4는 **한 줄도 안 지어졌다** — 설계를 고치는 값이 지금 가장 싸다.

지적대로 후보 집합 ID · 후보 ID · 후보 원문 스냅숏 · 생성 시점 · 목표 판이 §4 어디에도 없다.
설계는 「안 물은 후보는 저장하지 않는다 — 다음 물을 때 다시 뽑는다」 로 **의도해서** 안 남기는데,
그 근거(「후보는 파생이지 자산이 아니다」)는 **후보 「품질」을 재려는 순간 무너진다** — §11이 스스로
「무대 후보의 발생 품질 실측 0」을 못 재본 칸에 적어 뒀으면서, 그걸 잴 재료를 안 남기는 설계다.

**처방**: 「저장하지 않는다」를 「**보여준 것만** 사건으로 남긴다」로 바꾼다(안 보여준 후보는 그대로 버린다).
⑩의 노출 사건과 **같은 한 벌**이라 따로 비용이 안 든다.

### ⑨ 확정 무대의 생명주기와 현재값 접기가 없다 → **채택** (같은 미시공 구간)

`effective_from/to` · 교체·철회 · 여러 무대의 우선순위 · 시즌 경계가 §4에 없다. 이벤트 소싱이라
**접는 규칙이 없으면 같은 사건 집합에서 서로 다른 현재 무대가 나온다.**

🔑 **처방은 지을 것이 없다 — 이미 있는 규율을 상속하면 된다.** `estimate.responded` 의
**「(축·키)별 마지막 답 접기」**(v14 · `lib/동의율.js` 가 그대로 진다)가 정확히 이 모양이다.
무대도 **(학생·시즌)별 마지막 '맞다'** 하나로 접는다. 새 칸 0 · 새 규칙 0.

### ⑫ 읽기 커버리지의 분모가 실행 가능한 정의가 아니다 → **채택**

실물 `읽기커버리지()` 의 분모 = **`event_type === 'task.assigned'` 인 행 수**. 설계 §3이 적은
「그 밤 생성 수」와 **다르다** — 생성이 실패해 행이 안 생기면 분모에서 조용히 빠지고 커버리지는
자동으로 부풀려진다.

✅ 다만 실물은 심문이 안 것보다 낫다 — `기록없음 = 총행수 - 기록있음` 을 **이미 갈라 낸다**
(옛 행·폴백 `{ver:1}` 행을 0으로 안 접는다 · Ⅲ-2 준수). 모자란 것은 셋째 갈래 하나다.

**처방**: 「생성 시도했으나 행이 없음」을 세는 갈래를 붙인다 — 분모를 **「시도 = 착지 + 미착지」**로.
이건 상시 규율 그대로다: **합계 = 갈래 + 갈래**, 좋은 0과 「안 재봤다」를 가른다.

### ⑬ ⓓ FSRS 비교표는 반사실 비교가 아니다 → **채택(상만 고친다)**

같은 카드가 두 정책을 동시에 겪지 않으므로 §7의 나란히 보기는 **관찰 목록**이지 판정 재료가 아니다.
지적이 옳다. ⓓ는 유호님 판정 자리라 이 설계가 대신 열지 않되, **차리는 상이 틀리면 판정이 오염된다.**

**처방**: §7 ⓓ 칸에 한 줄 — 「이 표는 「차이의 크기」를 못 준다. 정책을 가르려면 카드·학생 배정과
관찰창이 필요하고, 그 설계는 판정 카드의 본체다」. 표 자체는 **탐색용**이라 명기하고 남긴다.

### ⑱ (P2) 「최신 정보」의 재검토 기한이 없다 → **채택** (싸다)

§9에 연구명·판·원문 링크·적용 범위·재검토 기한이 없다. 개원은 **2027-02**인데 정찰은 2026-09다.
**처방**: §9 표에 열 하나(「재검토 기한」) + 각 줄에 1차 출처 링크. 기한 = 개원 3개월 전(2026-11).

## 3. 실물이 「이미 닫았다」고 답한 것 (부분 기각 5)

### ⑥ c15 판올림의 구버전·혼합 배포 계약이 없다 → **부분 기각**

계약 c15 절이 **명문으로 적어 뒀다**: 「②~④ `preference.stated` 확장 셋 … **전부 널허용 —
기존 생산자(라디오 승격기)는 그대로 유효**」 · 「새 사건 0 · 새 열 0 · CHECK 값 변경 0」.
혼합 배포에서 옛 생산자가 죽지 않는다는 것이 계약 층에 서 있다.
소비자 쪽도 `읽기커버리지()` 가 `reads` 없는 행을 **`기록없음` 으로 갈라** 센다(0으로 안 접는다).
⇒ 지적이 상상한 「조용한 데이터 누락」의 두 길목이 둘 다 막혀 있다.

**남는 것**: `reads` 자체는 널허용이 아니라 「없을 수도 있는」 칸이라 검증 ⑧ 거절 갈래가
어떻게 도는지는 **안 재봤다** → 아래 조건부로 넘긴다.

### ⑦ 멱등성·동시성·오프라인 재시도가 정의되지 않았다 → **부분 기각**

실측: `idempotency_key` 가 **lib 12벌**(게임로그·게임제출·교정로그·라디오승격·목표확인·보고서교정제출·
서류관문제출·성향확인·오늘과제·요청해시·이벤트검증·제출로그)과 **계약 본문**에 있다.
`확인사건()` 은 시그니처가 `(카드, 응답, {correlation_id, idempotency_key, occurred_at})` 로
**멱등키와 상관키를 필수 인자로 받는다.** 「두 기기 동시 응답이 중복 사건을 만든다」는 전제가 틀렸다.

**남는 것**: 오프라인 「순서 역전」의 규칙은 실제로 못 봤다 → 조건부.

### ⑧ 실패와 「자료 없음」이 같은 모양이다 → **부분 기각**

실물 `empty_reason` 값 넷: `not_target` · `no_goal_yet` · `state_error` · `no_axes`.
**`state_error` 가 정확히 「실패」 갈래다** — 설계 문서에 예시가 셋뿐이라 없어 보였을 뿐이다.

**남는 것(부분 채택)**: 어휘가 **열린 집합**이라 값록이 없다 — 다음 생산자가 새 문자열을
지어내면 집계가 조용히 갈린다. **처방**: 값록을 `읽기기록.js` 에 `Object.freeze` 배열로 두고
(정본 하나) 계약 c15 절이 그 파일을 지목한다. 새 저장 0.

### ⑤ `goal_used` 라는 벤더 자기보고를 사실 판정자로 쓴다 → **부분 기각**

지적 자체는 옳다(미검증 자기보고). 그러나 §11 「못 재본 것」이 **먼저 적어 뒀다**:
「goal_used 보고의 정확성 — 벤더 자기 보고라 회전 채점표로 재야 한다」. 즉 **모르는 것을 안다고
하지 않았다.** 게다가 실측: `goal_used` 는 계약에 **없다** — §10-5(유호님 판정 ②) 뒤라 미시공이다.

**처방(착수 조건으로 못박음)**: `goal_used` 를 학생 화면 문구(「네가 고른 무대에서 가져왔어」)에
쓰는 것은 **회전 채점표 표본이 서기 전까지 보류**한다. 빛 축·효과 분해(내부 자)는 그 전에도 쓴다 —
틀려도 학생에게 거짓말이 안 되는 자리다. 🔑 **가르는 선 = 「학생이 읽나」.**

### ⑭ ①의 「실제로 쓸 한국어」 게이트가 없다 → **부분 기각**

난이도 겨냥은 `lib/기술선택.js` 의 결정적 회전 + (E2 뒤) 급수 필터가 지고, 자연성·정확성은
프롬프트와 `과제검문.js` 가 진다 — **이 설계가 신설할 자리가 아니다**(§2 오해 ③이 이미 「형식
자유도는 범위 밖」으로 그은 선의 연장). 「병원이라는 낱말만 든 문장」 위험은 실재하나, 그것을
잡는 자는 **회전 채점표**(5회전 예약)이지 무대 설계가 아니다.

**남는 것**: §4에 그 지목 한 줄이 없다 → 한 줄 추가.

## 4. 🔴 심문이 못 본 것 — 실물에서 찾았다 (2건 · 둘 다 시공된 코드)

### ㉮ 확인 채널 셋 중 **둘이 영원히 안 물어진다**(기아) — 🔴 이번 판정 최대 수확

`lib/성향확인.js` 실물:

```
축후보들() = [...리듬후보들, ...작성과정후보들, ...집중띠후보들]   // 고정 순서
확인카드()  = 축후보들(...).find(({축,키}) => !부정.has(부정키(축,키)))
이력        = { 오늘답함, 부정키들 }                              // 서버가 주는 전부
```

- `.find()` 는 **첫 후보**를 집는다. 제외되는 것은 **'아니다'로 부정된 키뿐**이다.
- `lib/동의율.js` 가 스스로 적었다: 「**긍정 키는 재노출이 허용돼** 같은 (축·키)에 답이 여럿 쌓이고」.
- `리듬후보들` 은 성실한 학생에게 **거의 항상 성립**한다(여유제출: 중앙값>0 그리고 여유n≥2 · 반복제출:
  제출률 1 그리고 n≥2).

⇒ **성실한 학생은 매일 리듬 카드만 받는다.** '맞다'라고 답해도 그 키가 후보에서 안 빠지므로
`작성과정`·`집중띠` 는 **한 번도 안 물어진다.** §10-2 「확인카드 다축 일반화 시공 완료」는 참이지만,
**돌아가는 결과는 여전히 한 채널**이다.

🔑 이건 [[zero-is-a-success-face-taxonomy]] 의 교과서 사례다 — 자(§6 동의율)가 두 채널에서 영원히
`n=0` 을 내는데, 그 0은 「학생이 답을 안 했다」로 읽힌다. **실제로는 「한 번도 안 물었다」** 이다.
그리고 §6의 존재 이유(모델 교체 성적표)가 채널 셋 중 하나로만 서게 된다.

**소급 불가인가 — 그렇다.** 안 물은 날의 라벨은 영원히 없다(설계 §8-ⓐ가 스스로 적은 문장 그대로).
**학생 0명인 지금이 유일하게 공짜인 창이다.**

**처방(작다)**: `이력` 에 「축별 마지막으로 답한 날」을 얹고, `축후보들` 을 **「가장 오래
안 물은 축 먼저」**로 정렬한다. 고정 우선순위는 **동률 깨기**로 내린다. 16주 시효(성향추출 v1.0)는
그대로 — 이 정렬이 그 시효를 자연히 지킨다.

### ㉯ 「하루 카드 한 장」 규율이 **실물에서 이미 깨져 있다**

설계 §5 불변 규율: 「하루 1회 상한 그대로(채널이 늘어도 학생이 받는 것은 **하루 카드 한 장**)」.
실물 `progress/index.ts` 마지막 줄:

```
return 봉투(200, { ok:true, date, data, next_cursor:null, 오늘의확인, 오늘의목표 }, ver)
```

**둘이 같은 응답에 함께 실린다.** 각자 제 「오늘답함」을 따로 세므로(확인 = `estimate.responded` ·
목표 = `goal.responded`) 학생은 **하루에 카드 둘**을 받을 수 있다.

이건 버그가 아니라 **설계 문서가 실물보다 낡은 것**일 수 있다 — 그러나 §5가 그 규율의 근거로 든
것이 「확인이 설문이 되는 순간 ㉡의 재미 조건이 무너진다」(⑮가 찌른 바로 그 자리)라, **문면과
실물 중 어느 쪽이 참인지 정하지 않으면 ⑮를 판정할 수 없다.**

**처방**: 설계 §5를 실물에 맞춰 **「하루에 되묻기 성격의 카드는 최대 N장」**으로 고쳐 적고 N을 못박는다
(지금 실물 = 2). 규율의 정본이 **한 곳**이어야 다음 채널이 늘 때 셋째 장이 조용히 붙지 않는다
([[constant-known-in-two-places]]).

## 5. 나머지 (부분 채택 6)

### ① 미구현·미측정을 ④✓로 위장한다 → **부분 채택**

§0의 「배포 빚 0」과 §8의 「구멍 5」는 **다른 것을 세는 다른 자**다(전자 = 배포 격차, 후자 =
과정그림자 43자리 커버리지) — 그 둘을 모순이라 부른 것은 틀렸다.
그러나 **§3~§7의 도장이 전부 「④ 도장 「예상」」인 채 §0이 「시공 완료」로 읽히는 것**은 사실이고,
§1의 게이트 표가 스스로 「전부 「배선 도장」, 「돈다」 승급은 실학생 뒤(F207)」라 적어 둔 것과
§0 머리가 어긋난다. **처방**: §0 상태 줄에 「배선 ✅ / 「돈다」 미승급 — 실학생 뒤」를 갈라 적는다.

### ② 읽기 기록이 실제 읽은 재료를 보존하지 않는다 → **부분 채택** (셋 중 둘이 진짜)

| 층 | 실물이 남기는 것 | 판정 |
|---|---|---|
| `skill` | `value: [skill_ids]` **배열 전량** | 🚫 기각 — 심문이 「ID만」이라 했으나 그게 재료 전부다 |
| `life` | `{source:'season_goal'}` — **값 0** | ✅ 채택 — 목표 문장이 바뀌면 그날 무엇을 읽었는지 영영 모른다 |
| `person` | `{source:'behavioral_axes', axes: 축들.length}` — **개수만** | ✅ 채택 — 호출자가 `axes_used` 목록을 「갖고 있는데」 길이만 저장한다 |

`person` 은 `intervention.delivered` 의 `evidence_refs.axes_used` 로 **조인 복원 가능**하므로 완전
손실은 아니다(심문은 이 다리를 몰랐다). 그래도 같은 사실을 두 곳이 다르게 아는 모양이라
[[constant-known-in-two-places]] 에 걸린다 — **한 줄 고쳐 목록을 그대로 싣는 게 싸다.**
`life` 는 다리가 없다 → **진짜 손실.** **처방**: `life` 에 `goal_ref`(나침반 event_id) 한 칸.

### ⑩ 하루 한 장 카드의 채널 선택이 정의되지 않았다 → **부분 채택** (지적 절반은 틀렸다)

🚫 **우선순위는 있다** — `lib/성향확인.js:34` 「판정 우선순위 — 앞이 먼저다(더 구체적인 관찰 먼저:
리듬(제출 습관) → 작성과정(쓰는 손) → …)」. 근거까지 적혀 있다. 심문의 「미정의」는 틀렸다.
✅ **기아 방지는 없다** → 4절 ㉮로 승격(이 판정의 최대 수확).
✅ **「질문받지 않음」 vs 「거절함」** — `확인사건()` 은 **응답 때만** 만들어지고 노출 사건이 없다.
못 가른다는 지적이 맞다. **처방 = ④의 후보 노출 사건과 한 벌.**

### ⑪ 동의율은 모델 평가 자가 아니다 → **부분 채택** (셋 중 하나만 진짜)

| 지적 | 실물 | 판정 |
|---|---|---|
| 질문 문구 판이 없다 | `shown_text` 가 **학생이 본 문장 그대로** 행에 실린다 | 🚫 기각 — 판번호보다 낫다(원문 복원) |
| 최소 표본·신뢰구간이 없다 | 「표본 문턱 없음 — 값을 감추는 게 아니라 분모를 「같이」 낸다(F207)」 | 🚫 기각 — 근거 있는 확정이다 |
| **노출 수가 없다** | `확인사건` 은 응답 때만 — 분모에 노출이 없다 | ✅ **채택** |

쉬운 추정만 물어 점수를 올리는 길은 **노출 수가 서면 바로 보인다**(물은 축의 분포). ⑩과 한 벌.

### ⑮ 되묻기가 재미가 아니라 설문이 된다 → **부분 채택**

「응답 직후 보상이 없다」는 실물 미확인(앱 화면을 안 열었다 — `src/말하기화면.js:735` 에
확인 카드와 「확인뒤」 처리가 함께 넘어가므로 **뒤처리가 「있긴」 하다**).
✅ 진짜인 것은 **잴 자가 없다**는 쪽이다 — §5가 「확인이 설문이 되는 순간 ㉡의 재미 조건이
무너진다」를 규율로 세워 놓고 **그 붕괴를 감지할 자를 안 세웠다.** 노출 사건이 서면
「보여줬는데 안 답한 비율」이 곧 그 자다. **⑩·⑪과 같은 한 벌 — 셋이 한 처방으로 닫힌다.**

### ⑯ ⑤ 자기설명이 한 줄과 각주로 축소됐다 → **부분 채택**

§1 게이트 표는 ⑤를 「과제 머리 한 줄 · 증거 동봉 · 계기판 각주」로 적었다. 학생에게 **「이 답이
다음에 무엇을 바꾸나」**가 없는 것은 사실이고, 이건 상시 규율([[feature-self-explanation-mandate]])
정면이다. 다만 「내부 배관 설명」이라는 평은 과하다 — 각주 문면(「동의율은 정확도가 아니라 본인
확인의 비율이다」)은 **읽는 사람을 위한 것**이다.

**처방**: 확인 카드 응답 뒤 꼬리 한 줄 — 「이 답은 다음 과제의 결에 실려」. 새 화면 0.

### ⑰ §9의 근거 수치가 추적 불가능하고 Khanmigo 수치가 1차 자료와 안 맞는다 → **채택(문면)**

⚠ **NBER w35620 원문을 안 열었다** — 심문이 준 수치(ITT 0.06~0.08SD)의 진위는 **안 재봤다**.
그러나 판정에 그게 필요 없다: §9가 **출처·표본·설계 없이 `0.34SD` 한 수만 적었다**는 것이 이미
상시 규율 위반이다 — **수는 「자」와 함께 적는다**([[measurement-needs-its-instrument]]).

**처방**: 그 칸에서 수치를 **지운다**. negotiable OLM의 근거는 「방향」으로 충분하고, 수가 필요하면
1차 출처(표본·설계·ITT인지 TOT인지)를 붙여 다시 넣는다.

## 7. 대안 구조 제안 → **부분 채택**

심문의 대안(후보노출 → 학생결정 → 과제배정 → 전달·제출 → 결과 사건 사슬)은 **대부분 이미 있다** —
`task.assigned` · `intervention.delivered` · 제출 사건이 서 있고
`idempotency_key`·`correlation_id`·`schema_ver` 도 실물이다. **없는 고리는 하나뿐이다: 후보 노출 사건.**
그리고 그 하나가 ④·⑩·⑪·⑮ **넷을 동시에 닫는다.**

🔑 즉 이 심문 18건의 실질은 **처방 다섯**으로 접힌다:

1. **노출 사건 하나** — ④ 후보 · ⑩ 질문받음 · ⑪ 노출 분모 · ⑮ 설문화 감지
2. **기아 방지 정렬** — ㉮(최대 수확 · 소급 불가)
3. **`reads` 세 칸 손질** — ②(life goal_ref · person 축 목록) · ③(filter/picker 가르기) · ⑧(값록 동결)
4. **분모 갈래 하나** — ⑫
5. **문면 수리 다섯** — ①(도장 층 가르기) · ⑨(마지막 답 접기 상속) · ⑬(탐색용 명기) · ⑰(수치 삭제) · ⑱(재검토 기한)
