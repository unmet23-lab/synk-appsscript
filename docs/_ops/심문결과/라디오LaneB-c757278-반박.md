## 치명

### 1. 라디오 `!출석`·`!목표` 승격 행이 앱 숙제 제출률·완주율로 읽힌다
- 파일: talk `lib/라디오승격.js:236-254`(submission.created 갈래) + `lib/학습자상태.js:158-159, 197-220, 228-236`
- 리듬축은 `task.assigned`×`submission.created`를 시간 구간으로 짝짓는다. 승격 행은 event_type 이 같아 필터를 그대로 통과하고, task_type(라디오퀴즈·목표선언·자습체크인)을 보는 소비자가 한 곳도 없다.
- 재현(실행함): 배정 1건(due 16:00) + 라디오 자습체크인 승격 행(04:00) → `리듬={"제출률":1,"마감여유분_중앙":720,"지각":0,"n":1}` · `끈기={"완주율":1,"n":1}`. **앱을 한 번도 안 연 학생이 「숙제를 12시간 여유 두고 냈다」가 된다.** deliver 가 개입 행에 스탬프하므로 되돌릴 수 없다.
- 같은 파일이 작성과정.n 표본 제외로 이 계열을 이미 못박아 놨는데 새 생산자에 적용 안 함.
- 방향: 리듬·끈기축 입력을 앱 통로 task_type 으로 거르거나, 라디오 제출을 별도 축으로.

### 2. 앱 계약판만 c11 로 올라가 c10 DB 에 대해 전건 426
- 파일: talk `src/계약판.js:16` vs `functions/events/index.ts:197-202` · `functions/tasks/index.ts:162-167`
- 서버는 선언판 > db판 이면 `426 CONTRACT_VER_UNSUPPORTED, retryable:false`. 이 커밋은 「⛔ DB 적용 0」이라 적으면서 클라이언트 상수를 c11 로 올렸다 — **클라이언트가 서버보다 앞서는 첫 사례.** HEAD 로 Expo 빌드하면 과제 조회·사건 업로드 전건 실패.
- 방향: 앱 상수 승격을 마이그 적용 뒤 별도 커밋으로 떼거나, 순서 제약(마이그 먼저→앱 빌드)을 못박는다. ⚠ `tests/계약.test.js` 가 상수=계약 정본 lockstep 을 강제하므로 되돌리기만으로는 안 풀린다 — 검사 축(「계약 정본」 vs 「DB 착지 판」)의 판정이 필요.

### 3. 원장 jsonb 를 무검증으로 계약 칸에 복사한다 — 검증기는 그 결과를 거절한다
- 파일: talk `lib/라디오승격.js:181-195` + `functions/radio-promote/index.ts:145-175`(insert 경로에 `검증` 호출 0)
- 재현: `task_snapshot.보기=['이','에','를']`(문자열 배열) → 계획 통과, `selected_option:"undefined"`. 중복 id 보기 → 자리 2인데 첫째 보기 id. 둘 다 검증기(주체 server)는 거절하는 모양인데 Fn 은 검증을 안 지난다.
- quiz_round.task_snapshot 생산자(P3)가 아직 없어 모양 보증이 0 — learning_events 불변이라 오염은 정정 불가.
- 방향: 승격계획에서 보기 원소 모양·중복 id 검사(`스냅샷불량`) 또는 Fn insert 전 `검증` 통과.

### 4. `limit 5000` 굶주림 — 창이 차면 새 메시지는 영원히 승격되지 않는다
- 파일: talk `functions/radio-promote/index.ts:64-71`(order by sent_at asc limit 5000 · 되돌아보기 7일)
- 7일 창 명령이 5000건을 넘으면 매 실행이 가장 오래된 5000건만 집는다 → 전부 `이미승격`, 승격 0. 새 메시지는 창을 벗어날 때까지 안 집히고 벗어나면 소급 절차가 없어 **영구 손실**. 잘림 신호도 응답에 없다.
- 방향: 커서(마지막 sent_at+message_id) 진행 또는 잘림 플래그+「제외 100%=이미승격」 경고.

### 5. 시점 조회 넷 중 둘이 정렬 없이 「입력의 마지막 행」을 고른다
- 파일: talk `lib/라디오승격.js:95-103`(활성링크) · `:124-130`(카드찾기) — filter 후 [length-1], 정렬 없음(라운드찾기·유효동의는 정렬함). Fn 질의에도 order by 없음.
- 재현: 겹치는 링크 이력(해제 미래시각 예약·confirmed_at 백데이트 정정이면 겹침 발생 — 부분 유일 인덱스는 못 막음) → 행 순서에 따라 **사건이 남의 학생에게 붙고 그 학생의 consent·급수로 저장**. 카드도 동일.
- 방향: confirmed_at·shown_from 내림차순 정렬 후 첫 행 + 겹침 건수 분모 노출.

### 6. 원신호 상한 500 의 전제가 깨졌는데 상한을 안 봤다
- 파일: talk `functions/deliver/index.ts:86-88, 279`(order by occurred_at desc limit 500) + `lib/학습자상태.js` 쓰는사건 +3

- 방향: 사건 종류별 상한/창 분리 + 승격기에 명령별 하루 접기(선호·정서는 하루 마지막 선언).

### 7. 승격기를 부르는 것이 없다 — 배포해도 도달 0 유지
