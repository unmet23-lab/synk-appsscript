## 3. 🔴 밟으면 다치는 것 — 앞 세션들이 실제로 밟았다

| 함정 | 무늬 | 처방 |
|---|---|---|
| **파이프가 종료코드를 덮는다** | `... \| tee` 를 붙였더니 「확인불가(2)」가 셸에서 0 으로 나왔다 | 성패를 읽을 명령에 파이프를 붙이지 않는다 |
| **배경 명령의 「exit code 0」도 시험 값이 아니다** | 하네스가 알린 0 이 **마지막 명령** 값이었다. 🆕 이번엔 감시 루프 끝의 `[ $i -ge 90 ] && echo` 가 거짓이라 exit 1 이 났는데 실제로는 정상 종료였다 | **출력 파일을 열어 내가 `echo` 로 찍은 줄을 읽는다** |
| **`grep "^# tests"` 가 0줄을 낸다** | 이 노드 판의 요약 줄은 `ℹ tests` 다 | `grep -E "^ℹ (tests\|pass\|fail\|skipped)"` |
| 🆕 **「시험 수정 허용」은 범위를 안 넓힌다** | 그 절은 지문 대조만 열고 `허용경로들` 은 «범위» 절에서만 온다(`codex-build.js:176`). 픽스처를 옮기는 순간 라운드가 통째로 막힌다 | 시험 파일도 **«범위»에 같이 적는다** |
| 🆕 **생성물을 커밋에서 빼면 커밋 자체가 선다** | `pre-commit:165` 가 모든 커밋에서 `대장동봉검사.js` 를 부르고 그 방아쇠 목록에 생성기가 있다. 시험이 다 초록이어도 막힌다 | 생성기를 고치면 **같은 커밋에 화면을 담는다** |
| 🆕 **워크트리는 형제 저장소를 «찾는다»** | 「가지엔 형제 저장소가 없어 화면이 열화한다」고 적었다가 실측으로 틀렸다. `.git` 파일의 `gitdir:` 로 본체를 찾고 `형제저장소.형제경로()` 가 그걸 이미 읽는다 | 가지에서 그린 화면을 그대로 담아도 된다 |
| 🆕 **`--기각` 은 «틀린 지적»에만 쓴다** | 맞는 지적을 기각하면 재발 필터에서 영구히 사라진다 | 범위 밖이면 **`--대상아님`**. 사유에 **그 지적이 난 파일 이름을 반드시 짚는다**(안 짚으면 가드가 「키를 밀려 쳤다」로 막는다 · 실제로 막혔다) |
| 🆕 **Write 로 유니코드 줄바꿈을 글자 그대로 넣으면 파일이 쪼개진다** | 한 판에 두 번 밟았다. 편집기로는 멀쩡한 세 줄로 보이고 원인이 안 보인다. 셸 한 줄로 고치려다 더 망가뜨렸다 | 이스케이프로 적는다 · 이미 밟았으면 «파일로 쓴 스크립트»로 줄 단위 갈아끼우기 |
| **만드는 자리가 둘이면 재는 자가 한쪽만 본다** | 여러 판에서 나왔다 | 조립 자리를 하나로 못 박는다. **자가 진짜인지는 «끊어보기»로 잰다** |
| **벤더 한도 마커가 낡는다** | 「리셋 전」으로 막혔는데 실제로는 풀려 있었다 | `--한도무시` 한 번 |

🔑 **끊어보기를 이번에 네 번 했다.** 릴 대본 자에서 편 제목 자를 좁히니 시험 둘이 빨개졌고, 훅 판정을 끄니 또 둘이 빨개졌다. **자가 결함을 지키지 않는다는 것을 그렇게 확인한다.**

**굵은 것 셋** (전부 진짜였고, 안 잡혔으면 그대로 나갈 뻔했다)

1. **「시험 수정 허용」이 범위를 넓혀 주는 줄 알았다.** 안 넓힌다. 그대로 갔으면 픽스처를 옮기는 순간 라운드가 통째로 막혔다.
2. **내가 적은 기준 하나가 원리상 성립하지 않았다.** 「뿌리에 새 `.js` 가 생기면 시험이 빨개진다」고 적었는데, 범위가 glob 이라 파일 목록과 범위가 «같이» 늘어 그 단언은 언제나 통과한다. **아무것도 안 재면서 영원히 초록인 자**가 하나 더 설 뻔했다.
3. **생성물을 커밋에서 빼는 배치가 커밋 게이트와 정면으로 부딪혔다.** 게다가 내가 든 까닭이 실측으로 틀렸다(§3).

### 🔴 그리고 내 명세 하나가 라운드 «둘»을 태웠다

기준 41 을 「목록에 **한 줄만** 더해라」로 적었는데 화면의 새 입력은 **둘**이었다. 그래서 실행자가 둘째를 더하면 「범위 초과」로 걸리고, 빼면 「유지하라」로 걸렸다. **자가 싸운 것이 아니라 명세가 둘을 갈라 놓았다.**
⇒ 「N 개만」류 기준을 쓸 때는 **그 N 을 어떻게 세었는지 그 자리에 적는다.**
⇒ 검수가 앞뒤로 반대되는 지적을 내면 **실행자를 다시 태우기 전에 명세부터 고친다**(같은 워크트리에서 이어 도니 그 편이 싸다).

### 배운 것 다섯

- 🔴 **발주서를 고칠 때는 «정본을 다시 열어» 대조한다.**
- 실행자는 **철학 전문·기억·트랙·결정 이력·아는미완**을 못 받는다. 판단이 필요한 것은 발주서 안에서 끝낸다.
- 범위 안에 **이미 알려진 결함**이 있으면 `## 맥락` 에 적는다.
- **완주해도 끝이 아니다.** 가지를 읽고 합치는 것, 남은 검수 지적을 처분하는 것은 사람 몫이다.
- 🆕 **실행자가 「못 고치고 이름 대어 남긴」 것은 옳은 행동이다.** 이번에 기준 42 가 게이트 논리 변경을 막고 있어서 실행자가 P1 을 고치지 않고 남겼다. 「고쳤습니다」로 덮었으면 그 판을 못 찾았다.
