# SYNK NEXT 부서와 두 사업의 내부 개발 방향

> 내부 전용 · 대외 비공개 · 2026-10-12 사용자 채택. 부서명은 **SYNK NEXT**, 한국어 명칭은 **미래사업개발실**이다. 개인화 돌봄 AI 로봇과 AI 개인화 쇼핑 플랫폼을 첫 연구개발 사업으로 둔다. 현재는 방향과 범위를 정리한 단계이며, 제품 구현·현장 검증·협력 계약·출시는 별도다.

SYNK NEXT는 개인화 기술을 바탕으로 사람의 생활을 더 편리하게 만드는 새로운 시스템과 제품을 연구하고, 개발하고, 사업화하는 SYNK 내부 조직이다. 미공개 아이디어를 시제품과 실제 사용 검증으로 발전시키고, 제품의 가치와 운영 가능성을 확인한 뒤 공개·사업화를 준비한다.

## 부서 역할과 기존 조직의 관계

| 역할 | 담당할 일 | 남길 결과 |
|---|---|---|
| 사업 탐색 | 사용자의 불편, 현재 해결 방법, 기존 서비스의 장단점 확인 | 대상 사용자와 검증할 문제 |
| 제품 기획 | 핵심 경험, 개인화 범위, 공급·운영 방식과 수익 구조 설계 | 제품 범위와 첫 실험 계획 |
| 연구개발 | 필요한 AI·소프트웨어·하드웨어를 연결해 시제품 제작 | 실행 가능한 시제품과 기술 검증 |
| 현장 검증 | 실제 사용 가능성, 도움, 운영 부담과 비용 확인 | 사용자 근거와 개선·계속·중단 판단 |
| 사업화 준비 | 생산·공급·판매·유지보수·고객지원 체계 준비 | 출시 조건과 운영 인수 계획 |

공통 개인화 기술인 Atlas는 SYNK가 관리하고 NEXT는 필요한 공통 능력과 분야별 전문 기능을 조합해 신규 제품을 만든다. 구현에 들어갈 때는 [8개 엔진 담당 원문](../../엔진8종_상향설계_v3.md#engine-owner-sources)에서 재사용·개선할 범위를 확인한다. 사업마다 별도의 공통 엔진이나 중앙 AI 실행기를 신설하지 않는다.

LAB·SHIFT·PULSE·PATH의 기존 역할과 고객 약속은 유지한다. NEXT는 내부 연구개발 부서이며 별도 법인이나 다섯 번째 공개 판매 브랜드로 등록하는 결정은 아니다. SHIFT의 기업 대상 개인화 서비스 도입·운영과 연결할 부분, 완성된 제품의 판매·운영 담당은 사업화 시 정한다. 기존 SHIFT의 맞춤 구매·사용 지원과 NEXT의 자체 소비자 쇼핑 플랫폼은 각각의 제품 범위로 관리한다.

담당 인력·채용·법적 계약 주체·투자 예산은 아직 정하지 않았다. 사업별 첫 실험은 [신규 확장 기준](../../사업발전_정본.md#management-principles)에 따라 고객 가치, 기술 재사용, 기존 사업과의 연결, 브랜드 일관성을 확인한다.

## 개인화 돌봄 AI 로봇

### 목적과 사용자

돌봄을 받는 사람의 생활 습관과 필요한 도움을 이해하고, 요양보호사·가족과 함께 일상 돌봄을 지원하는 로봇을 개발한다. 장기 목표는 대화·생활 안내와 물리적 일상 지원을 함께 수행하는 것이다.

직접 사용자는 돌봄이 필요한 고령자이며, 함께 사용하는 사람은 요양보호사와 가족·보호자다. 초기 도입 고객은 협력이 가능한 돌봄 기관을 우선 검토한다. 실제 기관·대상자·현장 참여는 아직 확보하지 않았다.

### 제품 범위와 개인화

| 영역 | 개발 방향 |
|---|---|
| 의사소통 | 본인이 선택한 말투·음량·속도와 도움받는 방식 반영 |
| 생활 지원 | 생활 일정 안내, 대화, 요청 확인과 처리 상태 안내 |
| 인력 연결 | 수행할 수 없는 요청을 담당자에게 전달하고 수신·처리 여부 확인 |
| 돌봄 기록 | 동의한 범위의 요청·확인 사항을 정리해 인계 지원 |
| 물리적 지원 | 실내 이동과 정해진 가벼운 물건 전달 등 제한된 작업부터 개발 |

예를 들어 “안경 가져다줘”라는 요청을 이해하고, 지정된 장소의 안경을 전달하는 흐름을 검토한다. 찾지 못했거나 수행할 수 없을 때는 그 상태를 알리고 담당자에게 연결한다. 이 예시는 목표 경험이며 현재 구현된 기능이 아니다.

신체를 들어 옮기기, 투약 판단 등은 첫 시제품 범위에 넣지 않는다. 신체 접촉·이동을 포함하는 기능은 전문 검증과 현장 운영 조건을 별도로 정한다. 로봇이 담당자 호출을 보냈다는 사실과 사람이 실제로 대응했다는 사실을 구분한다.

### 첫 검증과 확대 조건

1. 돌봄 현장에서 반복되는 업무와 현재 작업시간·실패 상황을 확인한다.
2. 요청 전달 또는 물건 전달 등 **줄여줄 업무 한 가지**를 선정한다.
3. 소프트웨어 흐름을 먼저 검증하고, 실제 물리 작업은 이용 가능한 로봇과 협력 조건을 확인한 뒤 시험한다.
4. 작업 성공률, 사람의 개입 횟수, 로봇 관리까지 포함한 돌봄 인력의 총작업시간, 이용자의 편안함을 기존 방식과 비교한다.

실제 도움이 반복 확인되고 현장 관리 부담을 감당할 수 있을 때 지원 업무를 늘린다. 요청 누락이나 물리적 위험이 생기는 흐름은 중지·수정한다. 로봇 관리 때문에 총작업시간이 늘어나는 경우 원인을 확인하고 적용 범위를 줄인다. 표본·기간·통과 수치는 현장과 첫 업무를 정한 뒤 시험 전에 정한다.

수익 구조는 **기관 대상 기기 임대·유지보수와 소프트웨어 이용료**를 후보로 둔다. 기기 조달비, 수리·교체, 현장 지원 비용을 확인한 뒤 가격과 계약 형태를 정한다.

## AI 개인화 쇼핑 플랫폼

### 목적과 참여자

이용자의 취향·예산·생활 맥락을 이해하고 여러 판매자의 상품을 연결해 자신에게 맞는 구매를 돕는 플랫폼을 개발한다. 상품 발견·비교·구매·배송·교환과 반품·사용 후 피드백까지 전체 경험을 설계한다.

구매자는 자신의 조건에 맞는 상품을 찾는 사람이며, 판매자는 상품 정보·재고·배송·반품 조건을 제공하고 주문을 처리하는 사업자다. 플랫폼은 이용자의 선택과 거래를 연결하고, 구매 후 결과를 다음 추천에 반영한다. 첫 카테고리·판매자·거래 방식은 아직 정하지 않았다.

### 핵심 경험과 운영 기능

| 영역 | 개발 방향 |
|---|---|
| 개인화 홈 | 관심 분야·취향·예산에 맞춘 상품과 콘텐츠 구성 |
| 상황 기반 탐색 | “출퇴근에 쓸 가벼운 가방”처럼 목적과 조건으로 탐색 |
| 비교와 추천 | 적합한 이유, 맞지 않는 조건, 가격·배송·반품 조건을 함께 설명 |
| 구매 | 판매자·재고·옵션·최종 가격을 확인하고 주문·결제로 연결 |
| 구매 후 경험 | 배송 확인, 교환·반품, 실제 사용 만족도와 불만 이유 반영 |
| 판매자 기능 | 상품 속성·가격·재고 관리, 주문 처리, 성과 확인 |

같은 가방을 찾더라도 노트북 수납과 무게가 중요한 사람, 방수와 운동복 수납이 중요한 사람에게 서로 다른 비교 기준을 제공한다. 상품 정보를 확인할 수 없을 때는 적합성이나 재고를 추정해 확정하지 않는다.

**평소 취향, 이번 구매 목적, 선물받는 사람의 취향을 구분한다.** 이용자가 추천 기준을 확인·수정하고 이번 구매에는 적용하지 않을 수 있게 한다. 대화 없이 검색·필터·비교로 구매하는 경로도 유지한다. 구매·반품 이유는 사용자의 설명과 추정을 구분해 반영한다.

### 첫 검증과 확대 조건

1. 상품 정보의 신뢰성, 개인화가 필요한 정도, 공급·반품 조건 확보 가능성으로 첫 상품군을 고른다.
2. 한 상품군과 소수 판매자를 대상으로 탐색 → 비교 → 주문 → 배송 → 피드백 흐름을 설계한다.
3. 초기 시제품에서는 시험 상품·모의 주문으로 흐름을 확인한다. 실제 거래는 판매자 계약, 결제·정산, 배송·교환·반품·고객지원 담당을 정한 뒤 별도로 개시한다.
4. 일반 검색·필터 방식과 비교해 선택에 걸리는 시간, 조건에 맞는 선택, 추천 이유의 이해도를 확인한다. 실제 거래 단계에서는 구매 전환, 반품 사유, 사용 만족도와 재방문도 함께 본다.

추천 성능뿐 아니라 상품 정보 최신성, 주문 처리, 구매 후 만족과 운영 비용이 함께 확인될 때 상품군과 판매자를 늘린다. 구매 전환만 높아지고 부적합 구매·반품·불만이 늘어나면 추천 기준과 노출 방식을 수정한다. 검증할 표본·기간·통과 수치는 첫 상품군 선정 뒤 시험 전에 정한다.

수익 구조는 **거래 수수료**를 우선 검토하고 판매자용 유료 도구는 실제 수요를 확인한 뒤 추가한다. 수수료율·가격·광고 판매는 미확정이다. 광고를 도입할 경우 유료 노출임을 표시하고 개인화 적합성의 이유와 구분한다.

## 공통 개발 순서와 데이터 원칙

쇼핑 플랫폼의 작은 거래 흐름을 먼저 구현하는 순서로 준비하면서, 돌봄 로봇은 현장 업무와 하드웨어 협력 가능성을 함께 조사한다. 이번 문서 정리는 구현 착수·장비 구매·현장 시험·거래 개시를 수행한 기록이 아니다.

두 사업은 사람의 조건을 이해하고 피드백에 따라 도움을 개선하는 기술을 재사용한다. 돌봄 기록과 쇼핑 취향은 각각의 사용 목적·동의·접근 권한에 맞춰 관리한다. 같은 SYNK 계정을 쓰더라도 돌봄 정보를 쇼핑 추천이나 광고로 자동 전달하지 않는다. 사용자가 밝힌 사실·선호·이번 상황·미확인 추정을 구분한다.

| 단계 | 쇼핑 플랫폼 | 돌봄 로봇 | 다음 단계에 필요한 결과 |
|---|---|---|---|
| 문제 확인 | 첫 상품군과 구매 불편 조사 | 현장 반복 업무와 부담 조사 | 사용자 근거, 비교할 기존 방식 |
| 시제품 범위 확정 | 공급 자료와 모의 거래 흐름 | 지원 업무 한 가지와 장비 조건 | 담당, 범위, 종료 조건, 비용 한도 |
| 제한 검증 | 선택 경험·거래 운영 가능성 확인 | 실제 작업·개입·총부담 확인 | 실패 원인, 사용자 결과, 운영 비용 |
| 사업화 판단 | 판매자·결제·배송·고객지원 준비 | 기기 공급·유지보수·현장 지원 준비 | 출시 조건과 운영 담당 |

현재 확정되지 않은 것은 세부 담당자, 개발 일정, 비용 한도, 첫 상품군·판매자, 돌봄 현장·장비 협력사, 상품명·가격과 출시일이다. 무료 내부 설계와 조사부터 구체화하며 유료 AI 호출·장비 구매·외부 계약은 해당 실행 요청과 비용 기준을 따른다.

## 비공개 관리와 공개 전환

- 부서명·사업 내용·시제품·개발 기록은 내부 전용으로 유지한다.
- 홈페이지, 공개 지식 JSON, 공개 조직도, SNS, 영업 소개서, 대외 발표물에 포함하지 않는다. 내부 문서 링크도 공개 자료에 옮기지 않는다.
- 이 문서나 연결한 내부 기록을 공개 저장소·외부 공유 링크에 게시하지 않는다. 문서 변경을 자동 배포나 일괄 공개 작업에 포함하지 않는다.
- 협력사 전달, 공개 범위, 공개 제품명과 출시 시점은 사용자가 별도로 정한다. 연구개발 방향 채택을 외부 발표 승인으로 해석하지 않는다.
