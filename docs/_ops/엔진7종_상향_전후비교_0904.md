# 엔진 7종 상향 — 두 마무리의 차이와 최종 상향의 전후 (2026-09-04)

> **누가 읽나**: 유호님. **무엇인가**: 같은 설계 일을 Opus 5 세션이 마무리한 판과 Fable 5.1 울트라코드(여러 에이전트를 한꺼번에 돌리는 모드) 세션이 마무리한 판이 «어떻게 달랐나»(1부), 그리고 그 결과로 선 최종 설계가 «지금 시스템을 어디서 어디로» 올리나(2부). 1부의 자 = 눈가림 심사 51벌(`docs/_ops/엔진7종_상향_모델비교_0903.md`)과 과정 장부(`docs/_ops/엔진7종_상향_비교_0903/회전장부.json`). 2부의 자 = 정본 `docs/엔진7종_상향설계_v1.md`(Fable 판 · 09-04 정본 자리) 자체 — 정본이 「지금」과 「상향 뒤」를 절마다 갈라 적어 둔 것을 그대로 모았다. **정본은 아직 «제안»이다**(유호님 채택 전).

## 결론 먼저 — 세 줄

1. **두 마무리는 «잘하는 일이 정반대»였다.** Opus 판은 읽히고(읽힘 3.9 : 2.2), Fable 판은 재료를 다 담았다(깊이 4.7 : 3.6 · 빠짐 4.1 : 3.2 · 유호 판정 완성형 3.9 : 3.2). 심사 51벌은 26 : 25 로 Fable 판이 «간발» 앞섰고, 결론은 **「합친다 — 속은 Fable 판 · 겉은 Opus 판」**. 정본 자리는 Fable 판, Opus 판은 커밋 eb4d2cb24 에 보존, 가져올 것은 정본 머리 «합칠 것» 절.
2. **최종 상향은 «기록하는 시스템»을 «예측하고 되재는 시스템»으로 올리는 설계다.** 상향 항목 58 · 엔진 사이 계약 25 · 걸음 0~19 · 유호님이 정할 것 28 · 걷어내는 것 185항. 지금 도는 것과 없는 것을 절마다 «돈다 / 짓고 있다 / 없다»로 갈라 적었고, 「AI 가 두 배 똑똑해지면 같이 커지나」에 항목마다 정직하게 답했다(안 커지는 것은 규율·배관이라 적었다).
3. **유호님 앞에 걸린 것은 하나** — 합친 판(v2)을 «누가» 쓰나(A/B/C · 권고 = 역할로는 B · 모델은 유호님 픽). 마감 = 걸음 0(자 먼저 · 0원 · 제가 진행)이 끝나기 전.

## 1부. 두 마무리는 어떻게 달랐나 — Opus 5 세션 ↔ Fable 5.1 울트라코드 세션

### 1-1. 어떻게 시작됐나
같은 재료 59벌(독해 9 · 정찰 9 · 설계 21 · 심사 14 · 종합 7 · 반박 28 · 통합 1 — 전부 Fable 5.1 · 09-02~03)에서 두 갈래가 났다. Opus 5 로 열린 자율 세션이 인계문을 집어 **확인 없이** 마지막 두 단계(수리 둘 · 집필)를 Opus 로 돌렸고, 유호님이 09-03 13:45 에 「저 세션이 한 작업은 기억하고 기다리자. 지금 페이블 울트라로 하고 두 작업의 결과를 비교해보자」로 정하셨다. 그래서 두 판의 재료는 같고, 다른 것은 «Loom 수리·통합 수리 둘»과 «집필 이후»뿐이다 — 모델 비교가 성립하는 까닭.

읽는 법 — 비평 수가 Fable 쪽에서 큰 것은 «흠이 더 많았다»와 «비평이 더 많이 잡았다»를 못 가른다. 장부 비고: Fable 1회차가 Opus 판에서는 4회차에야 나온 것들(토큰 만료 09-06 · 파일럿 D · 개원 창 산수 · 기호 열쇠 · 16명 자)을 잡았다.

### 1-3. 결과물 — 무엇이 달랐나(심사 51벌 · 자 = 절 17 × 렌즈 3 · 1~5점)

**겉 — 읽히나.** Opus 판 3.9 · Fable 판 2.2. 줄 하나 평균 103바이트 ↔ 246바이트(2.4배). Opus 판은 장면이 먼저 온다 — 「07:40 알림을 열면 홈에 몽글이 있습니다. 학생은 잠결에 두 번 쓰다듬고 닫습니다」 · 낯선 말을 그 자리에서 푼다 — 「예비 풀〔빈손을 막으려고 미리 만들어 둔 숙제 묶음〕」. Fable 판은 결론 줄에 기술 낱말이 몰린다 — 소제목이 「mascot.touched 생산자(세션 집계 1행 · observed · tap_n=0 도 1행) + …」 · 가장 긴 줄 2,079자.

**속 — 판단 재료가 다 있나.** 깊이 Fable 4.7 · Opus 3.6 / 빠짐 4.1 · 3.2 / 유호 판정 완성형 3.9 · 3.2. Fable 판은 상향 항목마다 같은 일곱 줄(대가 / 닫을 것 / 자 / 효력 / 돈 / AI 두 배 자 / 유호님 자리 — 선택지 A/B/C 와 권고까지)이 붙는다. Opus 판은 「AI 가 두 배 똑똑해지면 이것도 커지나」 줄이 Prism 절 전체에 0줄, 절 안에 「유호님이 정할 것」이 0줄(§12 표로 미룸), 재료의 걷어내는 것 166항 중 37항만 남겼고, 실물 이름(저장소의 파일·함수 이름)을 「결과 원장」·「학습자 표」로 갈아 끼워 다음 세션이 못 찾는다 — 유호님 자 「내용을 버려서 쉬워지는 건 실패」·「바꾸지 않고 붙인다」에 걸린다.

**사실 — 저장소와 맞나.** 크기가 같다(틀린 자리 Opus ≈50곳 · Fable ≈46곳 · 심사가 되재 본 표본 325 · 383 중). 종류가 다르다 — Opus 판은 낡은 수·지어낸 셈·출처 오귀속(테스트 72→74 · 「스물여섯」 · 「정본 문구 그대로」가 실은 요약문), Fable 판은 없는 파일을 있는 시제로(lib/이름살균.js · lib/발화검문.js · tools/밤샘.js · 모델정찰.yml — 두 저장소에 0 · 절 여섯에 되풀이). 둘이 같이 밟은 것 다섯(「시트 수집면 27종」→28 · 「첫 울림 09-01」 · 「시트층이 서버에 안 닿는다」 · D33 09-06 · 08-14 「DB 쓰기 ✗」)은 판이 아니라 재료의 오류다.

**정지선 — 유호님께 무엇을 올렸나.** Opus 판은 정지선을 여섯 갈래로 넓혀 34개(통보형 · 값 확인까지 섞임), Fable 판은 넷(돈 · 모델 픽 · 소급 불가 · 유호 확정 충돌) + 달력 값 하나로 28개. 반대로 §12 «마감 순 표»(질문 · 갈래 · 권고 · 언제까지 · 안 정하면 잃는 것)는 Opus 판이 두 판 중 최고였다.

### 1-4. 심사 결론과 픽 — 무엇을 어떻게 했나
- **결론 = 「합친다」.** 판정 26 : 25 · 절 다수결 9 : 8(만장일치 Opus §0·§3·§12 · Fable §8·§9·§15) · 축 일곱 중 Fable 5 · Opus 2. 렌즈로는 정반대 — 「읽고 정할 수 있나」 Opus 14 : 3 · 「사실」 Fable 10 : 7 · 「깊이」 Fable 13 : 4.
- **픽 = 정본 자리에 Fable 판**(`docs/엔진7종_상향설계_v1.md` 로 이름을 옮김) · Opus 판은 커밋 eb4d2cb24 에 보존 · 정본 머리에 «합칠 것» 절(Opus 판에서 가져올 것 17절 + 둘 다 고칠 것 + Fable 판 스스로 고칠 것). 실제로 섞는 일은 다음 트랙.
- 🔴 **한계 하나를 그대로 적는다** — 심사도 종합도 Fable 5.1 이 했고 이긴 판도 Fable 판이다. 눈가림이었지만 문체로 알아챌 수는 있다. 그래서 «숫자»보다 «인용 근거»로 읽었고(받침 주장 넷을 제가 두 판 원문에서 직접 확인했다), 이종 모델 심사는 안 돌렸다.

## 2부. 최종 상향의 전후 — 정본이 「지금」과 「상향 뒤」를 어떻게 갈라 적었나

읽는 법 — 정본(`docs/엔진7종_상향설계_v1.md` · Fable 판)은 절마다 「지금」(돈다 / 짓고 있다 / 없다)과 「상향 뒤」(층 지도 · 상향 항목 U · 항목마다 대가 · 닫을 것 · 「AI 가 두 배 똑똑해지면 같이 커지나」 · 유호님 자리 · 효력·닫히는 문)를 갈라 적었다. 아래는 그것을 엔진 일곱 + 가로지르는 절(§3 한 시스템 · §0 장면 · §11 순서 · §12 판정 · §13 걷어내는 것 · §14 자 · §16 대가)로 다시 모은 것이다. 수·이름·D 번호·U 번호는 정본 그대로, 정본에 없는 것은 「문서에 없음」. 실물(파일·함수) 이름은 저장소 이름 그대로 두고 옆에 뜻을 달았다. **정본은 아직 «제안»이라, 아래 「상향 뒤」는 전부 «짓는다»의 시제다.**

### 2-14. §16 대가 — 셋
「상향 항목 58개의 failure_mode 를 묶으면 … 셋」.

2. **자가 틀려 거짓 초록** — 화이트리스트 누락·파서 0건을 «없다»로·래칫 미리 올림·판 다른 점수 대조·룸잉크(rgb 68,76,88 을 자가 못 봄). 닫을 것 = **걸음 6** ⓑ 합류 커밋에서 V1~V9 9/9 + 배달왕복 122 재실측(V6 없이는 판올림 금지) + 모든 새 자에 넷(범위 안 파일 수 > 0 · 양성 픽스처 1 · 무응답 = null · 마지막 성공 시각) · 걸음 0.
3. **학생이 감시로 느껴 관계가 깨진다** — 만짐·과정 그림자 몰래 쌓임 · 협상 카드 = 약점 목록 · Patina 비교 · 곡 사이 낱말 새어 나감. 닫을 것 = **걸음 4** 실기기 빌드 1회(귀검수 5 같은 날) 유호 눈 두 문항 「나란히 놓으면 누가 더 많이 했는지 보이나」(보이면 Patina 앱 축 철회 · D9) · 「이게 내 것인 줄 알겠나 / 지켜보는 느낌인가」 + 첫 실학생 뒤 2주 A/B · «빼기»를 첫 카드부터.
