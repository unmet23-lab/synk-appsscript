## 3. 발견 1건 — `운영자료.js` 걷기 루프의 비가역 부분 삭제

**옛 모양**

```js
console.log(`${집행 ? '🗑 ' : '[드라이런] '}${x.이름}  — …`);   // 로그가 **먼저**
if (집행) fs.rmSync(path.join(폴더, x.이름), { force: true });    // 행위가 **나중**
```

**결함 세 겹**

1. **로그가 행위보다 먼저다** — `rmSync` 가 던지면(Windows 에서 파일이 열려 있으면 EBUSY·EPERM 이 실제로 난다) 못 지운 그 파일까지 「🗑 걷었다」로 인쇄된다.
2. **지운 수를 안 센다** — 무조건 `return 0` 이라 중간에 죽어도 「몇 건 지웠나」의 분모가 통째로 없다(F207).
3. **try 밖이다** — 호출부 `:946` 의 try 는 갈래 계산만 감싼다. 던지면 프로세스가 그대로 죽고 앞의 N 건은 **이미 지워진 뒤**다. 그리고 `:1054` 는 **넣기 루프 안**에서 부르므로 이중 부분 적용(복사 일부 + 삭제 일부)이 된다.

**왜 F604 보다 나쁜가** — 삭제 대상이 저장소 **밖** 유호님 바탕화면이라 되돌릴 이력이 없다(F025).

**F604 와의 관계**: 축은 같고 **방향만 반대**다 — 저기는 했는데 「안 했다」, 여기는 안 했는데 「했다」. 그래서 부정 표기를 찾는 ㉠ 축으로는 원리상 안 걸린다.

**고친 것** ①행위 뒤에 찍는다 ②성공·실패를 갈라 **센다** ③한 건이 막혀도 나머지를 계속 시도한다(걷기는 멱등) ④분모를 함께 낸다 ⑤부분 적용이면 **종료코드 1**.

**대가(틀릴 때의 모습)** `rmSync({force:true})` 는 없는 파일에도 안 던진다 — 그래서 `지움` 은 「지웠다」가 아니라 **「지운 뒤 없다」의 수**다. 목록은 바로 위 `목록읽기` 가 방금 실측한 것이라 지금은 둘이 같지만, 남이 동시에 지우면 그 한 건이 «내가 지운 것»으로 셈해진다.

**닫은 것 1개** 무조건 `return 0` — 부분 삭제가 종료코드 0 으로 나가던 자리.

## 4. 🔴 안 한 것 — 명시한다 (F348)

부정 판정(「나머지는 괜찮다」)을 쓰려면 층을 전부 열어야 하는데, 안 열었다:

- **구조 축 32자리 중 손 판정한 것은 3자리뿐이다.** 나머지 29 는 **안 읽었다.** 대부분 산출물 굽기(재실행하면 되니 무해)로 *보이지만* 그건 판정이 아니라 인상이다.
- **정적 근사가 놓치는 모양 둘**: ①실패와 부정이 **다른 줄**에 나뉜 자리(㉠ 축) ②콜백을 변수에 담아 나중에 부르는 꼴(㉡ 축의 들여쓰기 근사).
- **`tests/`·`Code.js`·형제 저장소(SYNK-talk)는 분모 밖이다.**
- **장치화 안 했다** — 이 감사를 회귀로 굳힐지는 아직 판정 안 했다. 대가가 크다(거짓양성이 셀 자리 · 위 32건 중 29 가 미판정인 채로 린트를 켜면 따를 수 없는 경보가 된다 · F103).
