# PULSE 휴대폰 고객 검토와 설치 안내

2026-10-12. 사용자가 갤럭시·안드로이드를 지정했다. **모바일 개선의 운영 반영과 HA 재무장을 완료했다. 실물 갤럭시 설치·푸시 수신은 사용자가 지금 확인하기 어렵다고 답해 후속으로 미뤘다.** 서버 전환을 기다리라는 요청 뒤 사용자가 전환 완료와 작업 재개를 알렸다. 새 운영 PULSE와 HA 설정을 확인하고 모바일 변경을 합쳤다.

## 서버 전환 후 통합 검증

새 버전의 합성 고객/제작자로 실제 MP4 재생 → 8.9초 장면의 수정 의견 초안 → 취합 담당자 확인·제출 → 제작자 확인 → v2 MP4 업로드 → 고객에게 자동 도착 안내 → 명시적 최종 승인 → 제작자 자동 승인 알림·원래 요청 처리 완료를 확인했다. 360·390·412px 가로 넘침 없음, 44px 설치 버튼, 16px 입력 글자도 재확인했다. [통합 결과](workflow-r5.json), [Android 설치 안내](android-guide-r5.png). 실제 휴대폰 설치·OS 알림 수신 증거는 아니다.

**09:20 KST 운영 검증 완료:** 새 HA 보존 절차로 릴리스 `7aa6c79f811c…`를 배포 job `306f5896ccfd4832009ba6f7113ba037`로 반영했다. 공개 파일 **50/50** 일치와 양 노드·controller 런타임 검증 통과를 확인했다. 교체 전 데이터의 정확한 보존·원래 키·현재 스키마를 확인했다. 교체 후 세션 집계 한 항목은 달라 모든 세션 행의 바이트 동일성을 주장하지 않으며, 실제 고객 화면은 기존 초대 연결로 새로고침 후 계속 사용할 수 있었다. 첫 진입 때의 빈 서비스 명령 출력 문제는 실제 D-Bus 속성을 확인하는 검증으로 보완했다. **09:47:38 KST HA 재무장 완료:** 새 릴리스 백업·독립 다운로드/격리 복원과 자연 관찰 뒤 `armed=true`, A epoch5 단일 writer·B 대기, 두 복제본 healthy·공개 HTTPS200/ready를 확인했다. 기존 HA 런타임 4개를 유지했고 실제 `RECOVERED` 감시 루프 약 15.7초·재시작0을 인수했다. 기존 토큰 식별자 9개는 모두 남아 있고 1개가 추가돼 현재 10개다. 따라서 개수·집계가 이전과 같다고 기록하지 않는다. 이번 모바일 릴리스에서 새 강제 중단 시험은 하지 않았으며 이전 `30a195…` 장애 시험은 당시 증거로 보존한다.

## 구현

- 모바일에서도 `앱 설치 · 알림` 버튼을 항상 표시한다. Chrome·삼성 인터넷·iOS·메신저 내 브라우저를 구분해 실제 환경에 맞는 안내를 보여준다. 설치 이벤트가 제공될 때만 설치 프롬프트 버튼을 표시한다.
- 영상 바로 아래의 `이 장면에 의견`은 재생을 멈추고 0.1초 단위 시각을 담아 의견 입력란에 초점을 옮긴다. `승인 확인`은 승인 영역으로 이동할 뿐 승인하지 않는다.
- 모바일의 읽기 순서는 영상 → 새 의견·승인 → 기존 대화다. 긴 대화가 입력·승인 앞을 막지 않는다. 가로·세로 원본 비율을 유지하고 터치 버튼과 입력 글자 크기를 보완했다.
- 설치·알림 허용은 사용자 선택이다. 기존 고객 연결·권한·30일 기기 연결·푸시 보안과 비공개 자료 캐시 금지를 유지한다.

## 이전 r3·r4 단계의 확인 결과

운영 부모 `30a195652cd4…`의 고정 사본에서 모바일 수정만 분리했다. r3 `73dc88d9760fdd5ef5303e63170f056f258793b3c438b0d6da08b6ea6d6c209b`는 610파일 중 9파일 변경이며, 서버 변경은 공개 정적 파일 목록에 `install.mjs` 한 항목 추가뿐이다. 다른 작업의 kickoff·closeout·제작자 프로젝트 딥링크는 포함하지 않았다. HTTP 제공 회귀 검사와 기존 권한·프로젝트 검사 포함 **64/64 통과**했다. 이전 후보의 누락된 모듈 제공은 실제 브라우저에서 404로 발견해 수정했다.

실제 브라우저, 격리된 합성 고객·제작자로 확인했다. 실제 운영 고객에게 의견·승인을 보낸 시험이 아니다.

1. 360·390·412px에서 가로 넘침 없이 영상과 설치 버튼이 표시된다. 설치 버튼 높이 44px, 의견 입력 글자 16px. 기존 대화 20개가 있어도 새 의견 폼과 승인이 대화보다 앞에 있다.
2. 실제 15초 MP4 재생 중 `이 장면에 의견`을 눌러 11.3초를 자동 저장하고, 같은 내용·시각을 제작자 화면에서 확인했다.
3. 제작자가 실제 v2 MP4를 업로드하면 고객 화면에 새 시안 도착 안내가 자동 표시되고, 확인 중이던 이전 버전은 유지된다.
4. 제작자가 요청에 수정본을 연결하고 고객이 최신본 → 승인 확인 → 최종 확인을 거쳐 승인했다. 제작자에게 승인 기록이 자동 반영되고 원래 수정 요청은 처리 완료로 바뀌었다.
5. 세로 540×960·15초 영상은 412×844 화면에서 높이 약 608px로 제한되어 원본 비율을 유지한다. Android Chrome 사용자 에이전트로 실제 설치 안내 문구와 기기 알림 설정 → 알림함 버튼 동선을 확인했다.

처음 127.0.0.1 환경은 다른 로컬 작업과 쿠키가 겹칠 가능성이 있어 `pulse-mobile-*.localhost` 전용 호스트로 분리한 뒤 전체 왕복을 다시 확인했다. 로컬 fixture에서만 Host·Origin·Secure 쿠키를 처리하는 어댑터를 사용하며 운영 코드의 HTTPS·인증 정책은 바꾸지 않는다. 휴대폰 OS 키보드·설치·잠금 화면 알림 검증을 대신하지 않는다.

**이전 r4 검증:** `9b0770e84f6c207022cadc61ef589c4a4c5a98a93db14dfe843a6c0e2849b687`, 611파일·운영 부모 대비10파일. 초대 전환 회귀11개를 추가해 **75/75 통과**했다. 실제 브라우저에서 새 초대 → 해당 프로젝트 전환·주소에서 토큰 제거, 작성 중 이동 확인 → 취소 시 원래 프로젝트/초안 유지, 재시도 → 명시적 이동 확인 후 새 프로젝트 연결을 확인했다. 탭별 휴대폰 화면 모의 설정으로 360·390·412px의 문서 폭 일치·16px 입력·44px 설치 버튼·영상→의견/승인→대화 순서를 다시 확인했다. r3 이후에는 초대 전환과 관련 시험만 바뀌었다.

## 발견한 후속 문제와 남은 일

- 같은 고객 앱에서 다른 `#invite` 링크로 이동할 때 기존 프로젝트가 남던 문제는 r4에서 수정·검증했다. 처리 중 초대는 메모리에서 대기하고 로그아웃·권한 만료 때 취소한다. 초대 토큰을 저장소에 남기지 않는다.
- 새 HA 절차의 유지보수 CAS·배포 잠금·양 노드 소스/이미지·guard/node/plan 계약 갱신으로 운영 반영과 공개 파일 대조를 마쳤다. 예전 단일 서버 cutover는 사용하지 않았다.
- 새 릴리스의 백업·격리 복원·자연 관찰·현재 자료/역할 검증을 거쳐 HA 재무장을 완료했다. 재무장 도구도 격리 Linux Node 28개·Python 12개 검사를 통과했다. 실제 운영 활성화는 `final-mobile-v2-postcheck.json`의 통과 결과를 따른다.
- 실물 갤럭시의 초대 링크 → 홈 화면 설치 → 기기 알림 허용 → 앱 닫기 → 알림 수신·프로젝트 복귀는 사용자가 지금 확인하기 어렵다고 답해 후속으로 미뤘다. 재질문하지 않으며, 기존 PC 푸시 성공과 모바일 모의 화면으로 실물 검증을 대체하지 않는다.
