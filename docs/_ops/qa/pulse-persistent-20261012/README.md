# PULSE 고객 기기 연결 유지와 닫힌 앱 푸시 검증

사용자 요청: 앱을 닫아도 실제 알림이 오는지 시험하고, 고객이 12시간마다 다시 연결·알림 등록하는 불편을 개선한다. 실제 수신 허용은 사용자가 Edge 주소창의 알림 요청에서 직접 완료했다.

## 변경

- 알림을 명시적으로 켠 고객 기기만 HttpOnly 쿠키와 서버의 해시 토큰으로 30일 기억한다. 12시간 편집 세션은 자동 복원한다.
- 고객이 화면을 보며 프로젝트를 조회하거나 내용을 저장하면 연결 기간을 연장한다. 숨긴 탭 조회·SSE·기기 상태 조회·푸시 전송만으로는 연장하지 않는다.
- 초대 링크의 7일 기한은 새 연결에 적용한다. 이미 기억한 기기는 현재 프로젝트의 초대 revision으로 계속 확인한다.
- 연결 종료·알림 끄기·재초대·접근 철회·프로젝트 보관 시 연결을 차단한다. 알림만 끄면 현재 편집 세션은 원래 만료 시각까지만 유지한다.
- 기존에 직접 허용한 같은 브라우저의 구독만 새 방식으로 자동 이전한다. 계정이나 프로젝트가 바뀐 기기를 임의 등록하지 않는다.
- 권한 창이 응답하지 않으면 15초 뒤 버튼을 다시 사용할 수 있다. 등록 응답이 유실됐을 때 구독을 성급히 지우지 않고 서버 상태를 다시 확인한다.

## 근거와 시험 범위

기존 PULSE 협업·알림 비교를 재사용했다. 기술 근거는 [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)와 [Web.dev 사용자 구독](https://web.dev/articles/push-notifications-subscribing-a-user)에서 서비스워커 수신·명시 허용·구독 보관을 확인했다. Edge의 작은 종 아이콘은 [Microsoft 공식 설명](https://blogs.windows.com/msedgedev/2023/07/06/fighting-notification-spam-microsoft-edge/)을 참고했다. 푸시 서비스의 HTTP 수락, 서비스워커 실행, OS 알림 표시를 같은 결과로 취급하지 않는다.

후보 `9872f1eb38b21bbadaf4a9b96f72ed8aab0208dc408ddf1f5cbac0ba0d9fdb30`는 운영 부모 603개 파일에 이번 변경 10개만 합친 607개 파일이다. 공유 작업본의 다른 서버 변경은 포함하지 않았다. 운영 데이터 없이 Linux 격리 시험 **105/105**를 통과했다.

시간을 제어하는 합성 서버 시험에서 13시간 후 페이지를 열지 않은 상태의 모의 푸시 전송, 편집 세션 자동 복원과 기존 CSRF 유지, 8일 뒤 초대 만료와 기존 기기 접속, 31일 미사용 기기 만료를 확인했다. 연결 철회·알림 끄기·재초대·보관·등록 실패·응답 쿠키 유실·기존 구독 이전도 검사했다. 이는 실물 기기에서 13시간을 기다린 시험은 아니다.

동일 후보의 합성 브라우저 화면에서 30일 연결 안내, 15초 허용 대기 종료와 버튼 복구, 작성 중 의견 보존, 제작자 답변과 고객 의견의 자동 왕복을 확인했다. 두 화면의 콘솔 오류는 없었다. 로컬 fixture는 모의 푸시 전송기를 사용하므로 실제 OS 수신 증거로 세지 않는다. [후보 안내와 대기 종료](candidate-timeout.jpg).

## 실제 기기 시험

Windows 화면 제어는 현재 브라우저 주소를 신뢰할 수준으로 확인하지 못해 중단됐고, 같은 턴에서 재시도하지 않았다. 사용자가 Edge의 종 아이콘을 눌러 허용한 뒤 웹앱에서 `기기 알림 끄기`와 연결 완료 상태를 확인했다. OS 화면은 직접 자동 검사하지 못했으므로 아래 사용자의 구체적인 확인과 서버 기록을 구분한다.
