# 구조 점검 1회차 · 예약과 자동화 운영 (2026-11-14)

유호님이 「우리 전체 시스템을 점검하고 더 최고의 효율을 고민해서 워크플로우 아키텍쳐를 업그레이드하는 방법을 찾는 예약기능」을 원하셨다. 매주 도는 예약으로 걸기 전에 한 번 시험으로 돌린 회차의 기록이다. 다음 회차부터는 Claude 앱 예약 `synk-weekly-audit`이 [점검 절차](README.md)대로 돈다.

이번 회차는 2주(11-01~11-14)의 앱 예약 회차 152개를 쟀다. 재는 데 쓴 것은 회차의 대화 원문, 앱 로그(`%LOCALAPPDATA%\Claude\logs\main*.log`, 11-13 01:43부터만 남아 있었다), Windows 시스템 기록이다. 바깥 조사는 Claude Code 공식 문서와 변경 기록, GitHub 이슈를 원문으로 읽었다. 후보는 Fable 5.2가 반대편에서 검수했다(지적 9건, 모두 아래에 반영).

## 오늘 있었던 일, 손실이 큰 순서

1. **PC가 07:42부터 17:23까지 켜진 채 응답하지 않았다.** 시스템 기록에 07:42부터 서비스 응답 지연이 이어지고 08:41에 백신 프로세스가 죽었다. 08~16시 origin 커밋은 0개다. 17:23에 전원이 끊겼다(이벤트 6008). 메모리 고갈 이벤트는 없었다. 램은 63.4GB이고 멈추기 직전 Claude 프로세스 묶음은 25.7GB, 자식 프로세스 328개였다. 원인은 모른다. 07:00~07:23에 약 7GB짜리 회차 사본 셋이 함께 만들어진 디스크 부하일 수 있지만 짐작이다.
2. **재시작 뒤 끝난 옛 회차가 한꺼번에 깨어났다.** 17:30에 10개, 18:40에 12개가 깨어났고 동시에 도는 예약 회차가 13까지 올랐다.
3. **시각이 중요한 회차가 밀렸다.** 스레드 게시는 21:41(사람이 「지금 실행」), 수요 스캔은 22:06에 시작했다.
4. **21시 무렵 Fable 검수자와 대체 Opus 검수자가 둘 다 사용 한도로 바로 끝났다.** 계정 전체 한도가 차면 「Fable → Opus」가 듣지 않는다.

## 실측에서 알게 된 것

- 앱의 예약 동시 실행 한도는 3이다(앱 로그 `limit=3`). 서버에서 정해져 바꿀 설정이 없다. 앱이 세는 것은 「지금 턴을 돌고 있는 예약 회차」다. 로그의 `global_limit (active=N)` 312줄 가운데 305줄에서 턴 중인 회차 수와 N이 같았다.
- 이 한도는 새 회차를 띄울 때만 막는다. 「이어서」나 앱 재시작, 백그라운드 완료 알림으로 깨어난 회차는 막지 않는다.
- 자리가 꽉 찬 시간은 11-01~08에 하루 0~2.7시간이었고 11-09부터 하루 6.3~14.0시간이다. 07~09시와 15~22시에 꽉 차고 11~14시는 거의 비어 있다.
- 자리를 쓰는 쪽은 07시대와 15시대에 함께 뜨는 제작 회차 셋이다. 실제 일한 시간의 중앙값은 LAB 167분, synkbrief 187분, yuhobuilds 63분이다.
- 밀린 쪽은 짧고 시각이 중요한 예약이다. 스레드 게시가 11일 가운데 3일 늦었다(11-09 +130분, 11-12 +66분, 11-11 +9분).
- 턴 안에서 검수와 굽기 결과를 기다린 시간이 약 93시간으로 예약 회차가 실제 일한 363시간의 26%쯤이다. 한 번의 평균은 검수 6.9분, 굽기 4.4분이다.
- 예약 회차 세션이 276번 깨어났고 196번은 5분 안에 끝났다. 할 일이 없는지만 확인한 것으로 보인다(길이로 본 짐작).
- 기록상 실패는 0건이지만 38회차가 사용 한도에 걸렸고 17회차는 첫 턴에서 멈췄다. 가장 많은 것은 Fable 한도다. 11-13에 예약 지시문의 모델을 Opus로 고정한 뒤에는 11-13에 3회차, 11-14에 0회차다.
- 예약 지시문 열 개에 끝나고 스스로 보관하는 단계가 없었다. 보관되지 않은 예약 회차가 24개 있었다.
- 완료 알림은 쉬는 예약 세션을 거의 다 깨운다. 쉬는 세션에 온 알림 355번 가운데 339번이 2분 안에 턴을 열었다. 「예약 세션은 완료 알림으로 다시 깨어나지 않는다」는 11-05 규칙([작업 자리](../../예약작업_작업자리.md) 「일하는 동안」)의 전제와 맞지 않는다. 다만 앱이 재시작해 알림이 오지 않은 경우는 이 셈에 없다. 그 규칙은 이번에 고치지 않았다.
