## 이전 보류·도구 실패 이력

최초 도구 초기화는 `failed to write kernel assets: 지정된 경로를 찾을 수 없습니다. (os error 3)`로 실패했고, 사용자 요청으로 Claude 작업 동안 보류했다. [당시 설치 대조](current-preflight.json)와 [당시 미실행 상태](result-deferred-before-resume.json)를 보존했다. 이번 재개에서는 공식 Windows 도구가 초기화·실행됐으며 실제 정상 프로필 UI로 별도 증거를 확보했다. 사용자 입력 감지 후 새 관찰, 화면 밖 완료 버튼의 스크롤, 완료 상태 비교의 전환 버튼 역할 판정은 도구 관찰에 맞춰 수정했으며 제품 오류로 기록하지 않았다.

## 재검증 시 보존 순서

1. 계정 라이브러리를 연결한 뒤 **메모·계정 설정**에서 미완료와 완료 목록을 모두 확인한다. 미완료0개를 전체 메모0개로 해석하지 않는다. 메모 본문·이름·계정 식별자·인증 정보는 결과에 남기지 않는다.
2. **이전에 작성하던 메모/초안 복구** 후보, 미저장 입력, 전송 대기가 있다면 먼저 보관/저장을 완료하고 다시 조회한다. 정상 로그아웃은 암호화된 재시작 초안을 정리하므로 그대로 로그아웃하지 않는다.
3. 안전한 기준 상태를 확보한 뒤 **상단 계정 관리**의 로그아웃을 사용한다. 보호창이 나타나면 **돌아가서 저장**으로 복귀한다. 라이브러리의 작은 로그아웃·전체 덮어쓰기·기기 기록 옮기기·복구본 삭제는 이번 검증에서 사용하지 않는다.
4. 로그아웃 후 계정 기록 접근이 막히는지와 안내를 확인한다. 같은 계정으로 정상 로그인한 뒤 필요하면 **계정 라이브러리 연결 → 다시 불러오기**를 사용해 기존 전체/완료/복구 개수와 항목·상태 보존을 확인한다. 비밀번호·인증 코드는 사용자가 직접 입력하며 공유하지 않는다.

도구 직접 관찰과 사용자 보고를 구분한다. 원래 프로필 파일·금고·인증 정보를 다른 경로로 추출하지 않았다. 이전 [실사용 준비 문서](../platform-reinstall-20261010/acceptance/README.md)의 미실행 양식은 이력으로 보존한다.
