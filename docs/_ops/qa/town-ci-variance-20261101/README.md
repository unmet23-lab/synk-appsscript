# 싱크타운 처리 비용 시험의 CI 실행 편차 수정

2026-11-01. 범위는 `tests/town-fold.test.js`의 처리 비용 판정과 시험 도우미다. 서비스·게임 엔진·저장 형식은 바꾸지 않았다.

## 원인과 변경

기존 시험은 사건이 적을 때와 2,500개 이상일 때 각각 20회 실행의 **경과시간 평균 한 개**를 비교했다. 공유 러너가 다른 일을 처리하느라 이 프로세스를 실행하지 못한 시간도 계산량 증가로 판정했다. 실제 실패한 syntax-check 41293383390은 초반 4.46ms, 후반 13.47ms로 3배 문턱을 조금 넘었다. 당시 CPU·GC 계측은 없어 그 회차의 지연을 특정 OS 스케줄링 사건이나 GC로 단정하지 않는다. 같은 코드에 계산 없는 대기를 넣어 잘못 실패하는 경로를 재현했다.

- 양쪽 단계에서 20회 워밍업한 뒤, 20회씩 7개 표본을 얻는다. 현재 프로세스의 user+system CPU 시간 중앙값을 비교한다. 다른 프로세스의 대기시간은 제외하고 이 프로세스의 GC 스레드가 쓴 CPU는 포함한다. [Node 24의 CPU 사용량 정의](https://nodejs.org/docs/latest-v24.x/api/process.html#processcpuusagepreviousvalue).
- `late < max(5ms, early × 3)`의 문턱은 유지한다. 유효하지 않은 측정값은 실패한다. 2,500개 이상 사건·64KB 세계·256개 색인·응답/영수증 개수 검사도 유지한다.
- 각 표본의 CPU 시간과 경과시간을 모두 TAP 진단에 남긴다. 이 관문은 동기 메모리 처리의 CPU 증가를 검사한다. 실제 요청/디스크 지연 예산은 기존 `tools/town-bench.mjs`가 담당하며, CPU 수치를 사용자 응답시간으로 보고하지 않는다.
- `tests/cpu-batches.test.js`는 실제 대기와 CPU 부하를 각각 넣는다. 대기는 통과하고 계산량 증가는 실패해야 한다. 두 회귀와 기존 성장 시험은 `syntax-check`의 `tests/*.test.js`로 자동 실행된다. 통과할 때까지 재시도하거나 시험을 제외하는 경로는 추가하지 않았다.

## 로컬 검증

| 실행 | 결과 |
|---|---|
| 원래 성장 시험 단독 | 1/1 통과 |
| 원래 시험의 후반에 회당 20ms 대기 주입 | 예상대로 실패: 경과시간 2.80 → 30.79ms |
| 수정판의 같은 후반 대기 | 통과: CPU 중앙값 5.50 → 5.50ms, 후반 경과시간 30.83ms |
| 수정판의 후반에 실제 CPU 계산량 증가 주입 | 예상대로 실패: CPU 중앙값 4.70 → 31.25ms |
| 마을 시험 전체 + 새 회귀 2건, 파일 동시 실행 4 | 총 368건, 통과 367·실패 0·취소 0·조건부 제외 1 |

위 대기/계산량 주입본은 저장소 밖의 시험 사본에서만 실행했다. 마을 시험은 두 주입 시험과 동시에 실행했으며 성장 시험의 CPU 중앙값은 3.95 → 3.90ms였다. 조건부 제외 한 건은 `tests/town-scope.test.js`의 형제 Talk 범위 대조(S109)로, 기존 113건 관문의 로컬 경로에서 같은 커밋을 별도로 검증한다. 새 제외는 없다.

원래 실패 로그와 원본 시험, 주입한 사본, TAP 원자료는 저장소 밖 `SYNK-town-ci-variance/20261101/`에 보존한다. 커밋 후 완료 증거는 해당 커밋의 `syntax-check`·`wide-tests`·`conditional-qa` 결과 및 같은 폴더의 `completion.json`에서 대조한다. 운영 사본은 표준 올리기 경로로 반영하고 변경 파일의 Git blob 일치를 확인한다.
