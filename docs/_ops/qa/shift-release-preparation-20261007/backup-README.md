# SHIFT 운영 반영 준비 — 백업·복구 검증

2026-10-07. 이 문서는 **임시 합성 데이터의 백업·복구 검증**만 기록한다. 운영 데이터와 실행 중인 회사 서버는 건드리지 않았다.

아래 13개 결과와 소스 해시는 당시 실행 기록이다. 같은 날 원래 키 누락의 시작 보호와 복구 후보 대조를 추가했고 해당 시험의 키 누락 사례도 새 동작으로 갱신했다. 현재 후보의 실행 결과는 [후속 운영 검증](../shift-operational-acceptance-20261007/README.md)에 둔다.

기존 `backupWorkspace`로 회사 DB, 메신저 DB, 암호화 키를 함께 백업하고, 원본과 다른 새 폴더로 복사한 뒤 실제 로컬 HTTP 서버를 열어 합성 계정으로 로그인했다. 백업 전에 임시 회사·메신저 서버를 종료해 두 DB의 최종 시점을 맞췄다. 임시 DB와 키는 시험 종료 때 검증한 임시 경로 안에서 삭제했다. 개인정보 본문·암호문·키를 보고서나 로그에 출력하지 않았다.

- 신규 복구 통합시험 **7/7**, DB 경로 우선순위 시험 **4/4**, 기존 백업시험 **2/2**, 총 **13/13 통과**.
- 작성물, 개인화 조건, 원래 결정·완료 근거, 최근 실습 평가와 저장 시각이 복구 전후 같았다.
- 다른 계정의 삭제 기록은 본문과 암호문 필드가 없는 revision 2로 복원됐다.
- 복구 후 오래된 revision 1 저장·다시 켜기는 409로 거절됐다. 현재 revision 저장과 삭제는 성공하고, 다시 시작한 뒤에도 삭제가 유지됐다.
- 다른 사용자와 관리자 모두 조회 인자·본문의 소유자 지정이나 다른 사람의 모델 범위로 개인 기록을 읽거나 덮어쓸 수 없었다.
- 키를 빠뜨리거나 다른 32바이트 키로 복구하면 로그인은 가능해도 저장 내용을 읽는 요청은 500으로 실패했다. 오류 응답·로그에는 작성물이나 암호문이 없었고 원래 암호화 문서를 덮어쓰지 않았다.
- 백업 원본의 키가 없으면 기존 도구가 백업 폴더 생성 전에 중단했다. 두 복구 DB의 SQLite 무결성 검사도 통과했다.

## 회사 서버와 백업의 DB 대상 일치

운영 준비를 독립 검토하면서 기존 통합 설정과 `MESSENGER_DATA_DIR`가 함께 있을 때 회사 서버와 백업이 다른 메신저 DB를 선택하는 문제를 임시 DB 두 개로 재현했다. 서버는 기존 통합 설정을 먼저 읽었지만 백업은 환경 경로를 먼저 읽어, 다른 DB가 들어 있는 백업에 `COMPLETE`를 만들었다.

`workspace-backup.mjs`의 경로 선택 한 줄을 **명시적 실행 옵션 → 기존 통합 설정 → 환경 경로 → 기존 기본값**으로 맞췄다. 실제 HTTP 회사 서버가 시작해 선택한 DB와 종료 후 백업에 들어간 DB가 같은지, 네 우선순위 조합에서 각각 고유한 채널 기록으로 확인했다. 운영 DB나 서버를 변경한 것은 아니다.

## 코드 롤백과 과거 데이터 복구의 차이

**최신 DB와 맞는 키를 유지하는 복구**는 현재 작성물과 삭제 revision을 보존한다. 코드만 되돌릴 때도 최신 데이터를 유지하는 것이 기준이다. 다만 임의의 과거 코드가 최신 저장 형식을 읽을 수 있는지까지 이번 시험에서 증명한 것은 아니다.

**삭제 이전의 오래된 스냅샷을 복구하는 경우**에는 이후의 삭제가 그 DB에 존재하지 않는다. 실제 시험에서도 삭제한 작성물이 revision 1로 돌아왔고, revision 1을 가진 오래된 클라이언트 저장이 다시 수락됐다. 백업 `COMPLETE`는 스냅샷 생성 완료를 뜻하며 이후 삭제까지 보존됐다는 증거가 아니다. 과거 DB를 복구해야 한다면 트래픽을 열기 전에 이후 삭제·수정 사항을 대조하고 반영해야 한다. 이를 자동으로 재적용하는 기능은 현재 없다.

이 시험 당시 `Store`는 키 파일이 없으면 새 무작위 키를 만들었다. 후속 보완에서는 기존 회사 DB가 있는데 키가 없으면 키 재생성·DB 변경 전에 시작을 거부한다. 처음 빈 저장소의 초기 설정은 유지한다. 다른 32바이트 키는 시작만으로 일치를 확인할 수 없으므로 원래 DB와 함께 백업한 원래 키를 대조하고 본인 작성물 조회까지 확인해야 한다.
