# 문자 비교 JS 적용 후보 · Fable 검수 완료

2026-10-31 사용자 요청: “JS 개선판을 실제 영상 검사 도구에 적용해줘도될지 페이블 검수를 제대로 받아볼래?”

**Fable 판정: 적용 가능. P0 0 · P1 0 · P2 0 · P3 3건(후속 3, 반영 0).** 최초 기본 계정 호출은 `429 usage_limit_reached`로 처리 전에 차단됐다. 이후 사용자가 지정한 기존 Max 계정의 실제 로그인을 공식 `claude auth status --json`으로 확인하고, 그 프로필을 검수 자식 프로세스에만 지정해 실행했다. 실제 모델은 `claude-fable-5-1`, 추론 수준은 기존 설정과 같은 `xhigh`이며, 정상 종료 0·`is_error: false`·`end_turn`을 확인했다. 기존 구독 경로이고 추가 사용 크레딧은 쓰지 않았다.

[Fable 응답 원문](fable-review.md)은 수정하지 않고 보존했다. `tools/검수묶음.mjs 페이블받기`가 입력 해시·끝 표식·15개 검토 항목을 대조해 실제 지적 F1~F3을 받았다. 운영 함수에는 아직 적용하지 않았다.

## 준비한 것

- 별도 작업본 `text-compare-fable-review/SYNK-appsscript`에 실제 적용 후보 8개 파일을 준비했다. 공용·운영 코드에는 적용하지 않았다.
- 영상 검사 함수는 공유 JS 구현을 호출하고, Rust는 실험 전용으로 둔다. 같은 이름·동기 호출·결과 필드·길이 제한을 유지한다.
- 기존 함수를 고정한 독립 비교 기준을 추가했다. 운영 함수 교체 후 시험과 벤치마크가 개선판을 자기 자신과 비교하지 않도록 했다.
- 계산 범위 확대·삽입/삭제 이동과 실제 FFmpeg 합성 영상의 96%·95%·94% 경고 경계를 추가 확인했다.
- 적용 후보 시험 **12개 통과, 실패 0, 생략 0**. Fable도 같은 두 시험 파일을 직접 재실행해 같은 결과를 확인했다. 영상 검사 입구와 Rust/WASM 각각 134,514개 입력쌍을 이전 함수와 대조했다.
- 표준 `tools/검수묶음.mjs`로 변경·호출부·시험·21종 성능 원자료와 입력 해시를 묶었다. 묶음 이름은 `text-compare-js-fable-20261031`이다.

## Fable 제안과 처리

| 번호 | 등급 | 제안 | 처리 |
|---|---|---|---|
| F1 | P3 | 삽입·삭제 시험에 치환을 섞어 공통 앞뒤를 제거한 뒤에도 양쪽 문자열이 남는 경우를 확인 | 적용 판의 후속 시험으로 기록 |
| F2 | P3 | 길이 제한 오류 문구를 후보의 상수뿐 아니라 고정 기준선이 던지는 메시지와 직접 대조 | 적용 판의 후속 시험으로 기록 |
| F3 | P3 | 빈 입력 검사와 문자 비교에서 복제한 정규화 식을 같은 공유 함수로 정리 | 적용 판의 후속 정리로 기록 |

세 건 모두 현재 결과가 틀리는 재현 결함이 아닌 시험·유지보수 보완 제안이다. Fable은 적용을 막지 않는다고 판정했다. 검수받은 후보의 바이트는 유지했고, `처리` 명령으로 세 건 모두 「후속」과 이유를 기록했다.

## 검수 범위와 한계

Fable은 변경한 8개 파일 전체와 관련 호출부, 이전 코드, 시험 결과, 성능 원자료의 환경·방법·21행 결과를 확인했다. 성능 원자료의 개별 표본 배열 전체는 읽지 않았으며, 별도 임의 입력 실행은 하지 않았다. 따라서 새로 전체 성능을 측정했거나 모든 입력을 증명했다고 해석하지 않는다.

일부 해시 셸 명령은 셸 실행 권한 제한으로 거부됐다. 이를 Fable이 수행한 것으로 세지 않는다. 호출자가 검수 전후 **14개 파일 전체의 UTF-8/LF SHA-256**을 별도로 계산해 검수 묶음과 모두 일치함을 확인했고, WASM 지문과 공용 영상 검사 함수가 이전판 그대로인 것도 확인했다. 입력 해시는 `55749920780ba62a9449d8d252256585ae489e187f442fd142867024ab73f1ef`다.

## 로컬에 보존한 증거

아래 원자료는 공용 작업본의 이 폴더에 보존했다. 저장소의 QA 원자료 제외 규칙에 따라 공개 저장소에는 설명·Fable 응답 문서·트랙을 올리고, 원자료와 미적용 후보 작업본은 로컬에 둔다.

- `candidate.patch`: 아직 운영에 반영하지 않은 적용 후보 코드.
- `integration.tap`: 실제 후보의 12개 시험 결과.
- `fable-call-result.json`, `status.json`: 최초 기본 계정의 한도 차단과 당시 준비 상태. 과거 기록이므로 완료 상태로 덮어쓰지 않았다.
- `fable-rerun.txt`: Fable이 직접 재실행한 12개 시험 출력.
- `review-completed.json`: 실제 모델·종료 상태·재실행 결과·후보 해시 대조와 공식 응답 수신 확인.
- 원래 성능 비교는 [실험 보고서](../../../../tools/text-compare-bench/README.md)를 본다.

정식 검수 묶음과 전체 CLI 실행 기록은 공용 작업본 `.tmp/검수/text-compare-js-fable-20261031/`에 있다. `집계`는 Fable 3건(후속 3)을 확인했지만, 일반 백엔드 양식의 필수 GPT·Claude 별도 검수는 미실행이라 배포 조건은 미충족으로 표시한다. 이번 사용자 요청인 Fable의 적용 가능성 검토는 완료했으며, 이를 다른 검수자의 수행 증거나 운영 배포 증명으로 주장하지 않는다. 아르곤 검수도 수행하지 않았다.

## 남은 일

실제 운영 적용 단계에서 위 세 제안의 반영 범위를 정하고, 후보가 바뀌면 관련 시험과 해당 반영 경로의 필수 검증을 마친다. 현재 작업본은 검수받은 후보 그대로 보존한다. 이번에 올린 것은 검수 기록이며 운영 코드 변경은 없다.
