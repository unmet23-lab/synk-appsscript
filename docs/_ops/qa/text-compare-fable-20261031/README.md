# 문자 비교 JS 개선판 · 적용 기록

2026-10-31 사용자 요청: “JS 개선판을 실제 영상 검사 도구에 적용해줘도될지 페이블 검수를 제대로 받아볼래?”

2026-11-01 사용자 요청: “보완 제안 3개도 반영하고, 검증까지 마친 다음 JS 개선판을 실제 영상 검사 도구에 적용해줘.”

**JS 개선판을 영상 검사 도구에 연결하고 Fable 제안 3건을 모두 반영했다. 최종 관련 시험은 13개 통과, 실패 0, 생략 0이다.** 사전 Fable 판정은 적용 가능(P0 0 · P1 0 · P2 0 · P3 3건)이었으며, 아래는 그 판정 뒤의 보완과 검증 기록이다.

최초 기본 계정 호출은 `429 usage_limit_reached`로 처리 전에 차단됐다. 이후 사용자가 지정한 기존 Max 계정의 실제 로그인을 공식 `claude auth status --json`으로 확인해 검수했다. 실제 모델은 `claude-fable-5-1`, 추론 수준은 기존 설정과 같은 `xhigh`였고, 정상 종료 0·`is_error: false`·`end_turn`을 확인했다. 추가 사용 크레딧은 쓰지 않았다. [Fable 응답 원문](fable-review.md)은 수정하지 않고 보존했으며, `페이블받기`가 입력 해시·끝 표식·15개 검토 항목을 대조했다.

## 연결과 검증

- 별도 작업본 `text-compare-fable-review/SYNK-appsscript`에서 보완하고, 최신 origin에 비교 함수·관련 호출부의 추가 변경이 없음을 확인한 뒤 연결했다.
- 영상 검사 함수는 공유 JS 구현을 호출하고, Rust는 실험 전용으로 둔다. 같은 이름·동기 호출·결과 필드·길이 제한을 유지한다.
- 기존 함수를 고정한 독립 비교 기준을 추가했다. 운영 함수 교체 후 시험과 벤치마크가 개선판을 자기 자신과 비교하지 않도록 했다.
- 최종판에서 `node --test tests/text-compare-bench.test.mjs tests/영상사전검사.test.mjs` **13개 통과, 실패 0, 생략 0**. 영상 검사 입구와 Rust/WASM 각각 134,514개 입력쌍을 이전 함수와 대조했다. Fable이 직접 재실행한 것은 보완 전 12개 시험이며, 이번 13개 시험은 적용 작업에서 수행했다.
- 계산 범위 확대·삽입/삭제 이동 136쌍에 치환을 섞은 68쌍을 더했고, 혼합 입력은 양방향 모두 실제 거리가 `edits + 1`임을 고정 기준선과 함께 확인했다. 정규화로 길이가 늘어나는 NFKC 입력도 제한 오류를 이전판과 대조한다.
- 실제 FFmpeg 합성 영상의 96%·95%·94% 경고 경계, 빈 입력 차단, CLI 종료 코드, 완성본 접수·반복 접수·원본 변경 차단을 기존 시험으로 확인했다.
- 사전 검수 묶음 이름은 `text-compare-js-fable-20261031`이다. 이번 판에서 속도 전체를 새로 측정하지 않았으며 [성능 표](../../../../tools/text-compare-bench/README.md)는 10-31 최초 실측으로 유지한다.

## Fable 제안과 처리

| 번호 | 등급 | 제안 | 처리 |
|---|---|---|---|
| F1 | P3 | 삽입·삭제 시험에 치환을 섞어 공통 앞뒤를 제거한 뒤에도 양쪽 문자열이 남는 경우를 확인 | 반영: `tests/text-compare-bench.test.mjs`의 혼합 편집 68쌍, 양방향·거리 단언 |
| F2 | P3 | 길이 제한 오류 문구를 후보의 상수뿐 아니라 고정 기준선이 던지는 메시지와 직접 대조 | 반영: `errorFromBaseline`으로 이전판의 오류 이름·메시지와 직접 비교, 후보 상수 의존 제거 |
| F3 | P3 | 빈 입력 검사와 문자 비교에서 복제한 정규화 식을 같은 공유 함수로 정리 | 반영: 공유 `normalizeText`를 `prepare`와 영상 검사 빈 입력 확인이 함께 사용 |

세 건 모두 적용을 막지 않는 시험·유지보수 보완 제안이었다. 실제 수정과 시험 뒤 `처리` 명령으로 **Fable 3건(반영 3), 후속 0, 미정 0**을 기록했다. 반영 표시는 Fable이 새 코드를 다시 검수했다는 뜻이 아니다.

## 검수 범위와 한계

Fable은 변경한 8개 파일 전체와 관련 호출부, 이전 코드, 시험 결과, 성능 원자료의 환경·방법·21행 결과를 확인했다. 성능 원자료의 개별 표본 배열 전체는 읽지 않았으며, 별도 임의 입력 실행은 하지 않았다. 따라서 새로 전체 성능을 측정했거나 모든 입력을 증명했다고 해석하지 않는다.

일부 해시 셸 명령은 셸 실행 권한 제한으로 거부됐다. 이를 Fable이 수행한 것으로 세지 않는다. 호출자가 사전 검수 전후 **14개 파일 전체의 UTF-8/LF SHA-256**을 별도로 계산해 묶음과 모두 일치함을 확인했다. 사전 검수 입력 해시는 `55749920780ba62a9449d8d252256585ae489e187f442fd142867024ab73f1ef`다. 그 뒤 세 제안을 반영했으므로 이 해시를 최종 적용판의 해시라고 부르지 않는다.

## 로컬에 보존한 증거

아래 원자료는 공용 작업본의 이 폴더에 보존한다. 저장소의 QA 원자료 제외 규칙에 따라 공개 저장소에는 구현·설명·Fable 응답 문서·트랙을 올리고, 실행 원자료는 로컬에 둔다.

- `candidate.patch`: 10-31 사전 검수받은 후보 코드. 11-01 보완 전의 과거 기록이다.
- `integration.tap`: 실제 후보의 12개 시험 결과.
- `fable-call-result.json`, `status.json`: 최초 기본 계정의 한도 차단과 당시 준비 상태. 과거 기록이므로 완료 상태로 덮어쓰지 않았다.
- `fable-rerun.txt`: Fable이 직접 재실행한 12개 시험 출력.
- `review-completed.json`: 실제 모델·종료 상태·재실행 결과·후보 해시 대조와 공식 응답 수신 확인.
- `integration-20261101.tap`: 세 제안을 반영한 최종판의 13개 시험 출력.
- `application-20261101.json`: 최종 소스 지문과 반영 확인 상태. 운영 사본의 확인 결과는 이 파일로 구분한다.
- 원래 성능 비교는 [실험 보고서](../../../../tools/text-compare-bench/README.md)를 본다.

정식 검수 묶음과 전체 CLI 실행 기록은 공용 작업본 `.tmp/검수/text-compare-js-fable-20261031/`에 있다. 사전 검토에 쓴 범용 백엔드 양식은 별도 GPT·Claude 검수를 미실행으로 표시하며, 그 상태를 통과로 바꾸지 않았다. 실제 이번 반영은 내부 도구의 문자 계산·빈 입력 정규화·시험·벤치마크 연결이다. [운영 원칙](../../../AI_운영원칙.md#review-rules)의 다섯 가지 ④(내부 도구는 시험·자기 점검), ③ 및 여섯 가지 ⑥(P0·P1 없이 P3만 보완한 판은 반복 검수하지 않음)에 따라 관련 시험과 자기 점검으로 마감한다. Apps Script·회사 서버·회원 화면 배포나 운영 데이터 쓰기·삭제 경로를 바꾸는 작업이 아니다. 새 Fable·GPT·Claude·아르곤 검수를 수행했다고 주장하지 않는다.

## 반영 경로

`tools/바로올리기.js`로 구현·시험·기록을 같은 커밋에 올리고 공용·운영 사본에 따라간다. 그 사본의 코드 지문과 실제 영상 검사 시험을 확인한다. Rust 설치·빌드·WASM은 운영 경로의 의존성이 아니다. 이 범위의 보완 제안은 세 건 모두 반영했다.
