# 문자 비교 JS 적용 후보 · Fable 검수 대기

2026-10-31 사용자 요청: “JS 개선판을 실제 영상 검사 도구에 적용해줘도될지 페이블 검수를 제대로 받아볼래?”

**Fable 검수는 아직 받지 못했다.** 공식 Claude Code CLI에 `--model fable`을 지정해 기존 Max 구독으로 한 차례 요청했지만, `429 usage_limit_reached`로 모델 처리 전에 차단됐다. 응답이 안내한 초기화 시각은 **2026-11-02 12:00, Asia/Seoul**이다. 다른 모델·계정·유료 API로 대체하지 않았고, 검수 지적 수를 0건으로 기록하지 않았다.

## 준비한 것

- 별도 작업본 `text-compare-fable-review/SYNK-appsscript`에 실제 적용 후보 8개 파일을 준비했다. 공용·운영 코드에는 적용하지 않았다.
- 영상 검사 함수는 공유 JS 구현을 호출하고, Rust는 실험 전용으로 둔다. 같은 이름·동기 호출·결과 필드·길이 제한을 유지한다.
- 기존 함수를 고정한 독립 비교 기준을 추가했다. 운영 함수 교체 후 시험과 벤치마크가 개선판을 자기 자신과 비교하지 않도록 했다.
- 계산 범위 확대·삽입/삭제 이동과 실제 FFmpeg 합성 영상의 96%·95%·94% 경고 경계를 추가 확인했다.
- 적용 후보 시험 **12개 통과, 실패 0, 생략 0**. 영상 검사 입구와 Rust/WASM 각각 134,514개 입력쌍을 이전 함수와 대조했다. 이는 로컬 시험 결과이며 Fable 검수 결과가 아니다.
- 표준 `tools/검수묶음.mjs`로 변경·호출부·시험·21종 성능 원자료와 입력 해시를 묶었다. 묶음 이름은 `text-compare-js-fable-20261031`이다.

## 보존한 증거

- [적용 후보 패치](candidate.patch): 아직 운영에 반영하지 않은 코드다.
- [시험 TAP](integration.tap): 실제 후보의 12개 시험 결과.
- [Claude 호출 원문](fable-call-result.json): `is_error: true`, 처리 토큰 0, `modelUsage: {}`. `subtype: success`라는 필드만으로 성공으로 판정하면 안 된다.
- [상태·소스 해시](status.json): 준비한 입력 해시, 후보·의존 파일 14개의 상태, 기준선 일치와 공용 함수 보존 확인.
- 원래 성능 비교는 [실험 보고서](../../../../tools/text-compare-bench/README.md)를 본다.

정식 검수 묶음과 CLI 원본은 공용 작업본 `.tmp/검수/text-compare-js-fable-20261031/`에 있다. 이 묶음의 일반 백엔드 정책이나 다른 검수자의 수행 증거를 충족했다고 주장하지 않는다. 이번 요청은 Fable의 적용 가능성 검토이며 운영 적용·배포 증명은 아직 없다.

## 남은 일

안내된 초기화 이후 후보 파일·입력 해시가 그대로인지 확인하고 **Fable 검수를 실제로 받아야 한다.** 응답의 입력 해시·끝 표식·읽은 범위를 공식 `페이블받기`로 확인하고, 지적이 있으면 처리한 뒤 적용 여부를 보고한다. 자동 재개 예약은 만들지 않았고, 이 작업본은 검수 대기로 보존한다.
