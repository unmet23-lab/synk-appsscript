# 카본과 Neon 검수 맞대기 (2026-11-20)

유호님이 「맞대 봐」라고 하셔서 지난 검수 묶음을 Gemini 4 Neon에 다시 보내 카본과 비교했다. 결과를 보시고 「카본 유지」로 정하셨다([결정](../../결정.md) 11-20).

## 결론

- 코드와 설계 검수에서 Neon Extra High는 카본 High보다 못하지 않았다. 같은 묶음 넷에서는 조금 더 잡았고, 헛짚은 P1도 적었다.
- 차이는 표본이 작아 우연의 폭 안에 있다. 카본도 같은 묶음을 다시 보면 결과가 이만큼 흔들린다.
- Neon이 더 빠르지는 않았다. 토큰은 같은 묶음에서 24~65% 더 썼다.
- 그래서 바꿀 이득도, 바꿔서 잃는 것도 이번 실측에서는 뚜렷하지 않다.

## 같은 묶음 넷: Neon과 카본 재실행

두 모델 모두 지금 새로 돌린 답이다. 정답은 그때 GPT, 카본, Fable이 낸 P0·P1 가운데 실제로 고친 것 27건이다.

| | 온전히 잡음 | 일부만, 또는 P2 이하로 낮춰 잡음 | 놓침 |
|---|---|---|---|
| Neon Extra High | 20 | 4 | 3 |
| 카본 High 재실행 | 17 | 6 | 4 |

- 결함이 아니었던 P1(예전 카본이 낸 것) 하나를 카본 재실행은 다시 P1로 짚었고, Neon은 P2로 낮춰 짚었다.
- 정답에 없던 새 P1은 둘 다 한 건씩 냈고, 둘 다 실제 결함이었다.
- 예전 카본이 잡았던 14건을 다시 잡은 수는 Neon 13건, 카본 재실행 11건이다.

## Neon만 돌린 묶음 다섯

| | 온전히 잡음 | 일부만, 또는 P2 이하로 낮춰 잡음 | 놓침 |
|---|---|---|---|
| 예전 카본이 잡은 15건 | 9 | 3 | 3 |
| GPT나 Fable이 낸 7건 | 3 | 0 | 4 |

- 새 P1 넷 가운데 둘은 실제 결함이고, 둘은 묶음만으로 판단할 수 없었다.
- 서버 묶음 하나(`vk-naver-server-20261119-끝판`)에서는 실제 P1 둘을 모두 P2와 P3로 낮췄다. 우리 관문은 P0·P1만 막으므로, 이대로면 배포를 막지 못한다.

## 속도와 토큰

같은 묶음에서 걸린 시간(초)은 Neon 742·749·816·894, 카본 493·750·876·994였다. 두 모델이 동시에 돌았다.

## 방법

- 묶음 9개(백엔드·설계 5개, 화면 4개)를 바이트 그대로 agy로 보냈다. 지시와 답의 꼴도 검수 도구와 같다. Neon은 `gemini-4-neon-xhigh`, 카본은 `gemini-4-carbon-high`다.
- 채점은 Opus 하위 에이전트 셋이 했다. 어느 답이 어느 모델인지 가린 채, 묶음 원문을 근거로 정답 항목마다 잡았는지와 새 P1이 실제인지를 판정했다.
- 공식 지적표와 결과 파일은 건드리지 않았다. 실험 도구, 답, 판정은 공용 작업본의 `.tmp/neon맞대기/`에 있다(커밋하지 않음).

## 보지 못한 것

- 모델마다 한 번씩만 돌렸다.
- Gemini 웹 길(화면 캡처를 붙이는 검수, 그림 맹검, 몽골어 문법 채점, 딥리서치)은 시험하지 않았다.
- Neon이 사용 한도를 덜 쓰는지는 재지 못했다. 다른 세션도 같은 몫을 쓰고 있었다.
