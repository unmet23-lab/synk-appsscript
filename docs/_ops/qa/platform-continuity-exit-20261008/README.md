후속 승인: 새 동기화 버전의 공개·설치가 Claude 최종 검수429로 대기 중이라고 안내한 뒤, 사용자가 **「최종검수는 지금 안해도 되 나머지 이어서 해」**라고 직접 지시했다. 이번 후보의 최종 검수를 후행으로 미루고 나머지 반영·검증을 진행한다. 일반 검수 원칙은 유지하고 검수 완료로 표기하지 않는다. [결정 기록](../../결정.md)과 [단일 배포 담당 기록](../platform-account-audit-20261008/COMPLETION.md)을 따른다. 아래 미배포 문장은 이 승인 이전 후속 검증 시점의 범위다.

사용자의 「이어서 해」 요청으로 기존 공개 플랫폼의 실제 회원 흐름을 확인하고, 개발 중인 계정 라이브러리와 기존 종료 보호를 연결했다. 홈페이지·기존 설치본의 공개 완료와 이번 소스 수정의 반영 상태는 구분한다.

실제 승인된 회원으로 계정 저장을 켜고 QA 메모1개를 남겼다. 새로고침 뒤 복구, 별도 탭의 독립 로그인 뒤 복구, 두 번째 세션의 완료 표시를 첫 세션에서 다시 불러오기, 제품 로그아웃 완료 뒤 메모 미노출과 로그인 안내를 확인했다. 콘솔 경고/오류는 두 세션 모두0이다. [실계정 결과](live-library-account.json), [복구 화면](live-library-restored.png), [로그아웃 화면](live-library-signed-out.png).

## 실제 공개 회원 흐름

기존 공개 `https://synk.im/account/platform.html#home`에서 실제 SYNK ID 연결을 확인했다. 처음에는 제품 로그인 전이었으며 중앙 ID는 로그인되어 있었다. 계정 식별정보·이메일·기본 프로필 연결 화면을 보여 준 후 사용자의 「이어서 해」 승인으로 연결했다.

- 실제 공급자 인가·동의·callback을 거쳐 제품 화면의 **서버가 확인한 계정으로 연결했어요**를 확인했다.
- 내 홈에 **내 SYNK ID로 연결됐어요**가 표시되고, 새로고침 뒤 같은 상태가 복구됐다.
- **이 제품에서 로그아웃**으로 검증 세션을 종료한 뒤 완료 안내와 내 홈의 비회원 상태를 확인했다. 모든 제품의 로그인 종료는 누르지 않았다.
- 다시 로그인하면 기존 중앙 ID 연결을 통해 제품 계정이 복구되고 내 홈도 연결 상태로 돌아왔다. 최종 회원 홈 탭을 남겼다.
- 비밀번호·토큰을 읽거나 복사하지 않았고 기존 학습 동의·프로필·이용권·개인 기록을 수정하지 않았다. 계정 연결과 검증 세션 생성/종료만 실행했다. QA 기록에 실제 계정 식별값과 인가 query를 저장하지 않는다.

근거: [최종 회원 홈](live-member-home-final.png), [처음 확인한 회원 홈](live-member-home.png), [승인 화면](platform-account-consent.png). 실제 계정의 **새 platform-library 저장·실물 PC↔휴대폰 왕복은 이번 검사에 포함되지 않는다.** 계정 라이브러리의 서버 변경은 별도 출시 작업의 적용 전이다.

## 발견한 문제와 수정

`다음에 할 일` 입력은 저장 버튼을 누르기 전까지 view의 임시 메모리에만 있었다. notebook의 `pending`은 false이고 기기 임시저장/서버 쓰기도 없으므로 기존 notebook 종료 보호에 걸리지 않았다. PC 상단 로그아웃과 닫기 버튼 역시 기존 홈 메모만 검사했다.

- `platform-library-view.mjs`에 `hasUnsavedDraft / discardDraft / focusDraft`를 연결하고 저장 전 입력에도 `beforeunload` 보호를 적용했다.
- PC launcher의 기존 확인창이 홈 메모와 계정 이어쓰기 메모를 함께 검사한다. 계속 작성·Escape는 원문을 유지하고 입력란으로 돌아가며, 명시적 버리기는 임시 초안만 비운다.
- 저장 제출 뒤에는 기존 notebook의 미전송 보호가 이어지고 응답을 확인한 뒤 해제된다. 서버에 이미 저장한 메모는 버리기로 삭제하지 않는다.
- 실제 native 종료에서 `pagehide → notebook.suspend → onChange`가 닫히는 화면의 이미지를 다시 요청하던 오류를 재현했다. pagehide 동안 호스트 재렌더를 중단하되 notebook의 계정 화면 숨김은 유지하고, pageshow의 계정 재확인 후 초안을 다시 보여 준다. CSP는 약화하지 않았다.

## 출시 연결과 남은 범위

- 최종 `desktop/renderer/platform-continuity.mjs`: SHA-256 `6360f262c4405610dea05cc06e017afb59e042b88b800fe6b260ab0e7ffc6a18`.
