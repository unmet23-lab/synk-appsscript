## 구현과 검증

- 회사 백엔드는 SHIFT의 AI 강의·강사 에이전시·업무 자동화와 PATH 유학·취업을 구분한다. 옛 broad SHIFT 기관 문의는 원문을 읽어 판단할 별도 분류로 보존하고, 옛 SHIFT 유학 유형은 읽을 때 PATH로 해석한다.
- TOPIK4·울란바토르 학원·유학 상담의 실제 등록 표식과 유형이 함께 맞을 때만 등록으로 센다. 상품별 등록 건수·고유 이메일·중복 제출·검토 필요·재등록·유입별 수를 기존 접수함 API에서 계산한다. 종결·시험·개인정보 요청은 제외한다. 이메일은 앞뒤 공백과 대소문자만 정규화하며, 다른 이메일을 같은 사람이라고 추정하지 않는다. 유입별 고유 이메일을 합산하면 중복될 수 있다.
- 질문 없는 정상 신규 등록만 답장 검토 할 일 생성을 생략한다. 메모·재등록·알 수 없는 형식·누락 필드는 검토 대상으로 남기며 기존 할 일·상태·수정한 초안은 보존한다. 등록에 메모가 추가된 뒤에는 할 일이 하나 생기고, 이미 생성 중인 할 일의 영수증도 복구된다.
- DB 마이그레이션·기존 응답 수정·고객 연락·자동 답장·삭제는 하지 않는다. 새 순수 모듈 1개와 시험 1개, 기존 service·service test·server test 3개를 고쳤다.
- 변경 관련 41/41 시험 통과. 문의 삭제 등 앞선 변경이 포함된 회사 사슬 26의 정확한 로컬 후보 위에서도 문의 관련 6파일 84/84 통과(실패·건너뜀 0, 외부망 차단). 이는 실제 회사 서버 반영·종단 접수의 증거가 아니다.
