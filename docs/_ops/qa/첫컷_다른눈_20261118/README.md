# 첫 컷 판정을 다른 눈에게 넘긴 기록 — 2026-11-18

## 왜 바꿨나

11-18 저녁 유호님이 GPT 세션의 「AI 작업 환경 전반 진단」 결과를 Claude에게 진단받으셨다. Claude가 짚은 첫째 약점은 이것이었다. 첫 컷 관문은 질문지를 만들 뿐이고, 판정은 그 영상을 만든 세션이 스스로 「충족 · 다시 · 무관」을 적어 통과시켰다. 그날 실제 편 세 곳의 확인 기록 4건, 판정 38개 가운데 「다시」는 하나도 없었다. 방문1039 편은 관찰 칸에 「0.5초에 셈이 1,014」라는 문제를 적고도 판정은 「충족」이었다. 유호님이 「첫 컷 판정을 만든 세션 대신 맥락 없는 다른 눈이 하도록 고칠까요?」에 「응, 고쳐」라고 하셨다.

## 무엇이 바뀌었나

- [첫 컷 검사](../../../../tools/첫컷검사.py)가 판정을 직접 받아 온다. 제작 세션이 판정 파일을 쓰던 `--확인파일`(낯선이시험의 `--첫컷확인`)은 더 받지 않는다.
- 다른 눈은 빈 임시 폴더에서 프레임 그림과 주문 글만 받는다. 그림은 1초에 한 장이고 칸 높이가 480px다. 4초 이하 구간은 0.125초 간격 여덟 칸, 그보다 길면 0.25초 간격 네 칸이다. 예전 시트는 칸이 224px라 세로 영상의 인물 폭이 126px였다.
- 눈은 GPT 6.2(구독 Codex, [실행기](../../../../tools/lib/첫컷눈_gpt.js)) 하나다. 계정 몫이 모두 막히면 판정 없이 멈추고 통과로 치지 않는다. 처음에는 Claude Opus 5.5(`claude -p`)를 대체로 뒀으나, GPT 코드 검수가 구독 대체의 격리와 시간 초과 문제를 짚어 뺐다(아래 「코드 검수」).
- 주문은 컷표 틀 2면 해당 컷 줄과 바로 앞뒤 컷 줄(로컬 경로는 뺀다), 그 밖은 굽기 전에 정한 장면 주문(`--주문`, 낯선이시험은 `--첫컷주문`)과 영상 지시문(`--주문파일`)이다. 기획.md의 심사 답이나 자체 판정은 주지 않는다. [크레딧내기](../../../마케팅/PULSE_포트폴리오_제작준비_20261012/시댄스무제한/크레딧내기.py)는 판의 컷 이름과 지시문을 저절로 넘긴다.
- 다른 눈의 「다시」가 틀렸다고 보면 `--반박 "<열쇠>=<몇 초 칸에 무엇이 보이는지>"`로 열쇠마다 한 번 다툰다. 그 열쇠는 새 눈이 칸을 다시 보고 가린다. 두 번째 판정도 「다시」면 더 다툴 수 없고 컷을 고쳐 다시 받는다.
- 판정 기록(`<편>/첫컷검사/<열쇠>/확인.json`)에 판정한 눈, 막힌 눈과 까닭, 보낸 질문과 받은 답 파일이 남는다. 열쇠는 편 자리, 영상, 구간, 주문, 질문, 기준, 판정 기준으로 만든다. 「판정자」 값이 바뀌어 예전에 제작 세션이 스스로 적은 확인은 더 쓰이지 않는다.

읽은 것:

- 최종 기준에서 결함 컷은 막고 만족 사례 둘은 통과시켰다. 표본은 셋뿐이라, 다음 편들에서 반박으로 뒤집힌 「다시」 수와 유호님이 같은 지적을 다시 하신 횟수로 계속 잰다([트랙](../../트랙.md)).
- 결함 컷은 모든 회차에서 「다시」였다. 관찰은 매번 같은 곳을 짚었다(「1.425초에도 도시락이 손에 들려 있어 다음 컷의 책상 위 배치로 이어지는 내려놓기가 보이지 않는다」).
- GPT 6.2 max 눈은 엄하다. 처음에는 유호님이 만족하신 판까지 막았다. 원인은 셋이었다. 그림만으로 답할 수 없는 질문을 「다시」로 셌고, 지적 번호의 이름만 보고 뜻을 넓혔고(「화면 틀」 → 구도, 「글자 가림」 → 로고), 주문 세부의 작은 차이를 결함과 같은 무게로 봤다. 판정 기준을 이 셋에 맞춰 고쳤다.
- 한 번에 150~690초가 걸렸다. 질문이 많은 LAB · 광고 편이 길다.
- 기존 기계 멈춤 측정은 유호님이 「표정도 자연스럽고」라고 하신 S44를 0.0으로 쟀다. 이제 측정은 막지 않고 눈에게 볼 시각을 알려 준다.

## 코드 검수

크레딧내기가 사흘 사이 세 회차 연달아 P0 · P1을 받아 설계 관문이 걸렸다. Fable 주간 몫이 다 차서 Opus 5.5가 설계를 대신 봤다([설계 검토](설계검토_Opus대체.md)). 그 뒤 GPT 6.2가 코드를 읽기 전용으로 봤고(묶음 `첫컷-다른눈-20261118-b`, 1,807초), 13건을 짚었다. 고친 것은 이렇다.

- 낼 때의 지시문 지문을 받기 기록(`_받음.json`의 「소스」)에 남긴다. 영상을 기다리는 동안 지시문을 고쳤으면 첫 컷 검사가 멈춘다(GA1).
- 낯선이시험은 틀 2 편에 `--첫컷컷들`을 받아 넘긴다(GA2).
- 시험용 바꿔치기 변수에 `CODEX_BIN`을 더하고, 대소문자와 관계없이 지운다(GA3).
- 꼭 볼 질문을 확인하지 못했는데 「흠」으로 답하면 꼴이 틀린 답으로 돌려보낸다. 그 경우는 「다시」다(GA4).
- 기록 열쇠에 편 자리(공용 git 폴더와 저장소 안 경로)를 넣는다. 편 폴더를 기록째 복사한 새 편은 원래 편의 판정을 쓰지 못한다(GA5).
- 잠금을 같은 편 · 영상 · 구간에 건다. 반박 한 번 제한은 반박할 때마다 다른 주문의 기록까지 다시 읽어 따진다. 시험 눈이 쓴 기록과 답 파일과 맞지 않는 기록은 세지 않는다(GA7 · GA8).
- Claude 대체 눈을 뺐다. 구독으로 띄우면 사용자 설정과 훅이 붙고, 시간 초과 때 자식이 남았다(GA9의 Claude 쪽 · GA11).
- 앞 · 뒤 컷은 편집 순서로 바로 이웃한 줄이다. 같은 컷이 두 구간으로 이어 나오면 그 다른 구간이 뒤 컷이다(GA10).
- 컷표 줄의 파일 칸(시작그림 · 참고그림 · 목소리견본 등)과 상대 경로도 눈에게 주지 않는다(GA13).
- 시험 눈의 답 파일 첫 줄에 시험 표시를 넣어 지문에 묶는다. 실제 검사는 GPT가 쓴 답만 받는다. 기록의 「시험」 칸만 바꿔서는 실제 판정이 되지 않는다(GA6 일부).

고치지 않은 것과 까닭은 이렇다.

- GA6의 나머지(답 파일과 지문까지 함께 고쳐 쓴 기록): 판정 기록은 제작 세션이 쓸 수 있는 폴더에 있다. 이 관문은 실수와 자기 판정을 막는 것이지 일부러 꾸민 기록을 막는 것이 아니다. 서버 쪽 서명은 범위 밖이다.
- GA12(반박 근거에서 시각만 넘김): 만든 사람의 주장을 새 눈에게 주지 않으려고 일부러 정한 설계다.
- GA9의 GPT 쪽(실행 단계에서 도구와 파일 읽기를 막지 않음): 다른 그림 검수(`tools/lib/그림눈.js`)와 같은 읽기 전용 기준이다. 빈 임시 폴더에서 띄우고, 더 좁히는 일은 따로 한다.

### 재검수(묶음 `첫컷-다른눈-20261118-c`, 1,175초)

GPT가 고친 부분을 다시 봤고 9건을 짚었다. 새로 고친 것은 이렇다.

- 내기 도구가 지문을 잰 뒤 지시문을 다시 읽는 사이에 파일이 바뀌면, 기록과 실제 요청이 어긋난다. 이제 요청 글을 만든 뒤 지문을 한 번 더 재고, 다르면 내지 않는다(GA1).
- 「표시할 파일명은 final.mp4」처럼 띄어쓰기가 있는 문장은 파일 참조로 보지 않고 주문에 남긴다(GA2).
- 낯선이시험은 틀 2가 아닌 편의 `--첫컷컷들`을 첫컷검사를 부르기 전에 거절한다(GA3).
- 낼 때의 지문이 없는 판(웹에서 받은 판, 11-18 앞에 낸 판)은 지금 지시문으로 판정하지 않고 멈춘다. 웹에서 낸 판은 첫컷검사를 직접 돌린다(GA4).
- 실제 눈의 Node를 띄울 때 `NODE_OPTIONS` · `NODE_PATH`를 지운다(GA5).
- 「멈춤」과 「LAB 뜻풀이」에는 「흠」을 쓸 수 없다. 「컷」 · 「연기」의 「흠」도 관찰에 「읽을 수 없다」 같은 확인 못 한 말이 있으면 돌려보낸다(GA6).
- 반박 장부와 판정 잠금을 git 공용 폴더(`synk-첫컷`)에 둔다. 같은 저장소의 다른 작업 사본에서 쓴 반박도 한 번으로 센다(GA8).

남은 두 건(GA7: 답 파일까지 꾸민 기록, GA9: GPT 실행기의 파일 읽기)은 앞 묶음과 같은 까닭으로 고치지 않았다. 「반영 안 함」인 P1이 남아 있으면 검수 도구가 다음 재검수를 받지 않아서, 위 일곱 건은 시험(첫 컷 검사 17개, 낯선이시험 · 영상 입구 29개)으로만 확인했다.

## 11-24 만족 사례가 다시 막힌 까닭과 고친 것

11-24 [인물 시범](../첫컷_인물_20261123/README.md)에서 S55 C2와 S44가 둘 다 「다시」였다. 같은 날 꿈 무대 여학생용 2판 W1도 세 판 내리 「다시」였다. 관찰을 보면 까닭은 둘이다.

- **점검표 줄:** 11-23 점검표를 줄이며 #33과 #60의 「확인할 것」 앞부분에 「감정 칸의 컷이 넓은 구도면 걸린다」와 「앞빛 컷이면 역광 테가 있나」가 들어왔다. 11-18 5회차 때 이 자리에는 다른 글이 있었다. 눈은 이 문장을 결함으로 읽었다. S55는 허벅지까지 잡은 오디션 고정 구도를 #33으로, S44는 역광 테가 없는 앞빛을 #60으로 막았다.
- **판정 기준 글:** 박자를 얼마나 봐줄지와 「핵심 동작」이 무엇인지가 없었다. S55의 컷과 연기는 웃음이 3.0초 대신 3.5초에 꺼진 것, 슬레이트가 1.5초 대신 1.75초에 빠진 것, 4.6초 끝 박자가 4.8초 구간 밖으로 밀린 것을 「다시」로 셌다. W1 넷째 판은 0.2초 칸의 팔 높이와 먼 뒷모습의 시선 때문에 「다시」였다. 5회차는 같은 기준으로 S55를 「흠」으로 넘겼다. 눈의 판정이 회차마다 흔들리는 자리였다.

새 질문은 더하지 않고 [첫 컷 검사](../../../../tools/첫컷검사.py)의 문장을 이렇게 고쳤다.

- 「다시」의 핵심 동작은 이 컷이 이야기에서 맡은 일과 뒤 컷이 이어받는 상태다. 지적은 그 결함이 이 칸에 보일 때만 「다시」다.
- 「흠」에 작은 곁동작이 빠진 것, 1.5초 안쪽의 박자 차이, 빛을 넣었다.
- 지적은 이름에 적힌 결함을 「확인할 것」의 범위에서 본다. 「확인할 것」에 적힌 만드는 방법(…있나, …했나)은 따지지 않는다. 빛의 방향, 구도, 컷 크기 같은 연출 지적은 보여도 「흠」이다.
- 컷 · 연기 · 멈춤 · LAB 뜻풀이는 핵심 동작을 확인하지 못했을 때만 「다시」다. 숨이나 먼 인물의 시선처럼 정지 칸에 드러나지 않는 세부는 판정에서 뺀다.
- 「종전 지적」 질문은 되풀이를 판정 기준에 따라 「다시」나 「흠」으로 적게 했다. 컷표 주문 안내에는 칸 안의 박자도 0.7~1.5초 늦을 수 있다고 적었다.
