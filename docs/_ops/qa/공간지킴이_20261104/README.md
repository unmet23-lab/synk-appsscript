## 무엇을 하나

- 여유 30GiB 아래 `low`, 10GiB 아래 `critical`. 평소에 지우는 규칙은 그대로다.
- 점검 처음에 자기 프로세스의 CPU · 메모리 · I/O 우선순위를 일반으로 올린다(자식도 물려받음, 예약 설정은 그대로). 바닥이 아니어도 10분 넘게 끝나지 않거나 도는 동안 바닥으로 내려가면 그때 올린다.
- 점검마다 `%TEMP%` · 세션 임시 · `.tmp/.company-local-qa-*`를 24시간(`critical` 12시간), 통과한 조건부 시험 회차 안쪽을 3시간 기준으로 먼저 지운다. 떼어 내기 전후 확인 짜임은 그대로다.
- 세션 기록(`~/.claude/projects/*/<세션 ID>.jsonl`)이 그 시간 안에 바뀐 세션의 임시는 둔다. 기록을 못 읽으면 세션 임시는 평소 사흘 그대로다.
- 차례: 임시 → 빠른 사본 정리 → 릴리스 사본 → 시험 후보 → 서버 백업 암호문 → (그날 몫이면) 하루 한 번 사본 정리 → 캐시 · 원본. 한 단계가 막혀도 다음 단계를 한다.
- 텔레그램 한 통(MTProto 먼저, 못 보내면 hermes): 들어설 때 · `critical`로 내려갈 때 · 하루 넘게 이어질 때. 40GiB 위로 올라오면 구간을 닫는다. 곁 스레드에서 보내 정리를 붙잡지 않고, 막히면 Windows 알림, 둘 다 막히면 다음 점검이 다시 보낸다.
- 150GiB Windows 알림은 하루 한 번(바닥에서는 없음), 큰 자리 재기 없이. 통합 감시 「주의」는 30GiB 아래에서만 켠다.
- `critical`에서는 지우기 전 기록을 못 써도 지운다. 디스크가 가득 차면 기록이 막혀 아무것도 못 지우기 때문이다. 그 위에서는 지금까지처럼 기록을 못 쓰면 안 지운다.
- 조건부 시험 일꾼은 여유 15GiB 아래면 새 검사를 열지 않는다(전에는 2). 155분을 넘으면 기존 무소식 빨간불이 알린다.
- `latest.json` · `점검.log`에 `level` · `tookSec` · `priorityRaised` · `priorityRaisedBecause`를 남긴다.
