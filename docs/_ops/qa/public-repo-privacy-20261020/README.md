나.의 비용·영향:

- 커밋 번호가 거의 다 바뀐다. 원격이 닿는 24,803개 가운데 노션 CSV가 들어온 08-04 뒤 약 24,100개다. 결정 표·트랙·현장 노트·QA 기록에 근거로 적힌 커밋 번호가 모두 옛 번호가 된다.
- PR 참조 212개는 GitHub이 읽기 전용으로 잠가 force push로 못 바꾼다. GitHub 지원에 요청해야 PR 화면과 캐시된 화면에서 사라진다. 지원은 자격 증명 교체로 풀리지 않는 민감 정보만 돕는다고 안내한다.
- 이 PC의 공용 작업본·워크트리·다른 세션의 미푸시 커밋을 모두 새 이력 위로 옮겨야 한다. 옛 클론에서 한 번이라도 push하면 지운 값이 되살아난다. 그동안 다른 세션을 멈춰야 한다.
- 커밋·태그 서명과 닫힌 PR의 diff 화면이 사라진다.

### ② GitHub 비밀값 감시·push 보호 — 켰다(10-20 낮, 유호님 직접)

유호님이 저장소 설정(Settings → Advanced Security)에서 Secret Protection과 push 보호, 비공개 취약점 신고(Private vulnerability reporting)를 켰다. API로 `secret_scanning`·`secret_scanning_push_protection`과 `private-vulnerability-reporting`이 모두 enabled인 것을 확인했다(10-20 13:57). 공급자 외 패턴·유효성 확인은 꺼진 그대로다.

- 비용: 공개 저장소는 무료다(push 보호는 2023-05부터). 이 저장소를 비공개로 돌리면 개인 계정 저장소에서는 이 기능을 쓸 수 없다 — Team·Enterprise 조직의 Secret Protection이 있어야 한다.
- 하는 일: 구글·OpenAI·Anthropic·텔레그램처럼 형식이 알려진 키가 든 push를 GitHub이 받기 전에 막는다. 이미 있는 이력은 막지 않고 경보로 보인다. 공개 저장소에서 찾은 파트너 패턴은 GitHub이 늘 제공사에 알린다(설정 화면 안내).
- 주의: 시험용 가짜 키 꼴을 새로 넣거나 고친 push가 막힐 수 있다. 그러면 세션의 무인 push가 멈추고, 웹에서 이유(시험용·오탐·나중에 고침)를 골라 넘겨야 한다. 넘긴 기록은 남고 메일이 간다.
- 열린 경보 1건(§4 마지막 줄)은 바꿀 키가 아니다. 「Used in tests」로 닫을지는 유호님이 정한다 — 저장소 보안 상태를 바꾸는 일이라 말씀 없이 닫지 않는다.
- 다시 확인: `gh api repos/unmet23-lab/synk-appsscript --jq .security_and_analysis`, 경보는 `gh api repos/unmet23-lab/synk-appsscript/secret-scanning/alerts --jq '[.[]|{number,secret_type,state}]'`(값이 든 `secret` 필드는 고르지 않는다).
