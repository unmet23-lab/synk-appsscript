# WORLD · TOWN · Workspace 공통 데이터 검수

2026-10-09. 요청: 세 화면의 이동뿐 아니라 **같은 학생·반·마을의 실제 기록을 함께 사용하는지** 확인한다. 기존 검증의 50개 교사 화면 항목과 18개 학생 항목을 최신 3D 경로의 증거로 확대하지 않는다.

## 10-09 검수 시작 당시 판정

**이 검수 시작 시점에는 전체 연동이 완료되지 않았다.** 이후 서버·공개 연결 결과는 [운영 연결 후속 결과](../workspace-connect-20261009/README.md)와 [연결 마감 기록](../workspace-connect-close-20261010/README.md)을 따른다. 실제 교사·학생의 사용과 합성 검증 범위는 별도로 유지한다. 기존 학원용 WORLD·TOWN과 Workspace의 수업 기능은 동일한 수업 저장소를 이용하지만, 현재 최신 3D WORLD·TOWN 로컬 리허설과 공개 Workspace까지 하나의 운영 데이터로 이어지는 상태는 아니다.

| 경로 | 실제 데이터와 연결 | 검수 판정 |
|---|---|---|
| 학원용 WORLD → Workspace | `synk_user_id`로 개인 학습 기록을 찾고 `class_id`·`learner_id`·현재 공유 revision으로 교사에게 허용한다. 과제·관찰·케어는 기존 수업 서버를 직접 이용한다. | 로컬 구현·합성 왕복 검증됨. 운영 적용은 별도 |

| 최신 WORLD 첫 3문항 → 공통 학습 기록 | 검수 시작 시 `synk_world_v1_runs/state`에만 기록했다. 같은 계정이라도 공통 `synk_learning_events`에 없어서 교사 근거에 누락됐다. | 발견한 결함. 아래 수정·검증 기록을 따름 |

같은 계정 식별자를 쓰더라도 다른 DB·다른 저장 경로에서 실행하면 같은 자료가 되지 않는다. 회사 메시지·직원 자료를 학생 학습 테이블로 복사하는 방식도 사용하지 않는다. 공통 학생 계정과 현재 소속·권한을 기준으로 필요한 원본을 조회하는 것이 연결 기준이다.

## 이번에 수정한 결함

1. **최신 WORLD 첫 학습이 교사 근거에 도달하지 않음.** 완료 시 개인 학습 동의가 켜져 있으면 같은 계정의 공통 원장으로 연결한다. 1회 완료는 3응답 receipt이며, 기존 Strata 분류와 정확히 맞는 위치 읽기 1문항만 `ko.reading.detail`의 근거로 사용한다. 인사·요청 표현 2개는 미분류로 표시하고 약점 계산에 임의로 넣지 않는다. 반복된 같은 문항을 새 독립 문항으로 부풀리지 않는다.
2. **학습 원본 삭제 뒤 수업 쪽 평가 근거가 남을 수 있음.** WORLD의 3응답 파생 기록을 원본 이벤트에 외래 키로 묶고, 수업 JSON에 남은 학습 근거도 원본 이벤트의 현재 존재 여부를 확인한 뒤 투영한다. 원본을 지우면 평가 근거와 연결 요약도 사라진다. 원래 과제 제출 결과와 교사 관찰은 별도 이력으로 유지한다.
3. **공유 철회 뒤 늦게 도착한 응답이 학생 기록을 다시 표시함.** 부모 화면에서 확인한 최신 공유 상태보다 오래된 상세 응답을 거절하고, 학생별 캐시에서도 해당 공유 상태를 적용한다. 학습 공유와 Town 공유를 별도로 처리한다. 아래 실제 브라우저 재현과 최종 회귀 결과를 구분한다.

개인 학습 동의가 꺼져 있어도 첫 학습·참여 보상은 계속 동작한다. 동의 없이 완료한 과거 실행을 나중에 자동 수집하지 않는다. 새 migration은 `SYNK-talk/supabase/migrations/20261009233000_world_v1_learning_c16.sql`이며, WORLD와 수업 runtime을 함께 생성했다. **현재 실행 중인 4296 리허설 DB·프로세스와 운영 서버에 이 migration을 적용하거나 재시작하지 않았다.** 새 수정의 왕복 증거는 별도의 합성 공통 DB 시험이다.

### 교사 화면의 후속 반례

공유 철회 뒤 개요는 새 revision 3을 알고 있는데 늦은 상세 응답 revision 2가 WORLD 12건을 재표시하는 문제도 [실제 브라우저에서 재현했다](frontend/before-fix-confirmed-sharing-race.json). 처음 8개 검사가 통과한 실행은 자동 새로고침과 겹친 관찰이므로 최종 회귀의 대체 증거로 쓰지 않는다.

부모의 최신 공유 상태를 기준으로 오래된 상세 응답을 거절하고, 캐시에서는 해당 학생의 기록만 제거하도록 수정했다. 학습과 Town 공유판은 별도로 취급하며 다른 학생의 작성 중인 케어·다수 대상 과제의 남은 학생 결과를 보존한다. [호스트·상세·공유 모듈 단위 회귀](frontend/final-unit.json) **40/40**을 통과했다([전체 TAP](frontend/final-unit.tap), [읽기 검토](frontend-read-review.md)). 공유 모듈 8개는 이 40개에 포함되며 합산하지 않는다.

[최종 독립 브라우저 왕복](frontend/report.json)은 **18/18 통과**했다. 실제 WORLD UI에서 제출 응답을 잃은 뒤 재시도해도 같은 이벤트가 유지되고, 이미 열린 교사 개요·상세가 자동으로 갱신됐다. 공유 철회 후 최신 응답을 계속 지연시킨 상태에서 이전 응답 자체가 거절됨을 확인했다(보류 revision 4, 부모가 확인한 revision 5). B의 케어 초안을 보존하면서 A의 공유 기록은 명부에서 다시 열어도 보이지 않았고, Town만 철회했을 때는 학습 근거·케어 초안을 유지했다. 통신 차단/복구와 교사 담당 반 철회도 통과했다. 페이지·자산 오류와 예상 밖 외부 요청은 0이며, 관련 제품 원문 5개의 전후 해시가 동일하다.

강화 실행기를 보완하며 생긴 중간 실패는 최종 성공과 구분한다. iframe 재생성 뒤 이전 frame 참조, [자동 새로고침과 보류 요청 순서](frontend/qa-gate-order-timeout.json), [부모 개요 조작 뒤 상세창 스크롤](frontend/qa-dialog-viewport-timeout.json)을 검사 코드에서 수정했다. 기존 자동 갱신 주기는 변경하지 않았다. [최종 실행 기록](frontend/execution-audit.json)은 exit 0이며, 의도적 503 통신 차단을 포함한 실행 중 서버 출력 3줄도 보존했다. 최종 검사는 메모리 공통 DB와 합성 계정에 한정되며, 이전 케어 검수의 별도 학생 18개 검사와도 구분한다.

## 확인한 근거

- [서버 왕복·삭제·동의 검증](backend.md), [명령·38개 결과·원문 해시](backend.json): 합성 공통 DB에서 WORLD 완료→교사 근거, 교사 과제→WORLD 응답→교사 결과, 공유 철회·반 이동·원본 삭제·계정 삭제를 확인했다. 새 7개는 전체 38개에 포함되며 합산하지 않는다. 검증 후 9개 서버 원문·생성물의 현재 해시도 다시 대조했다.
- [서버 후속 독립 읽기 검토](backend-review.md): 동의·소유자·중복 완료·서버 채점 출처·삭제 연결을 검토했다. 별도 운영 시험이나 4296 재적용으로 표현하지 않는다.
- [공개 주소 읽기 전용 확인](public-read-only.json) 및 [마감 재확인](public-final-read-only.json): 비인증 HTTP 조회만 수행했다. 마감 시 5개 응답의 상태와 내용 해시가 최초 검사와 동일했다. `/api/teaching/status`의 401만으로 API가 없다고 단정하지 않는다. 새 정적 파일의 404와 공개 설정이 배포 미완료의 근거다.
- [현재 계정 회귀](account-regression.json): 현재 체크아웃에서 104/104 통과했다. 이전 케어 검증 당시 남았던 6개 실패와 시점이 다르며, 이번 감사가 계정 원문을 수정해 해결했다고 주장하지 않는다.
- [최종 케어 화면 회귀](care-regression/report.json): 제품 원문 확정 후 실제 Chromium·합성 2반 32명·일회용 SQLite·메모리 PGlite로 기존 50개 항목을 다시 확인해 50/50 통과했다. 반·학생 선택, 케어 저장/수정/완료, 담당 반 철회와 1440/1280/390/320 화면을 검사했다. 페이지·콘솔·자산·예상 밖 외부 요청 오류는 0개다. [실행·보존 대조](care-regression/execution-audit.json)에서 관련 19개 원문·실행기·runtime과 기존 케어 증거 14개 파일이 전후 동일함을 확인했다. 최신 3D Town이나 운영 DB 검증은 아니다.
- [최신 3D 실행 경로](modern-runtime.json): 실제 실행 중인 4296 WORLD는 `rehearsal:true, production:false`이며, 4288 TOWN preview의 입장 API도 실제 운영 접근을 허용하지 않는다. 현재 제공 중인 주요 브라우저 파일과 로컬 원문 해시를 대조했다. 기존 서버·계정·저장 파일은 수정하지 않았다.
- [생성물 대조](root-build-checks.json): 최종 제품 원문 확정 후 Workspace 교사 호스트, 계정 portal, PC continuity, WORLD·수업 runtime의 정식 대조 5개가 모두 통과했다. 생성된 WORLD runtime import도 확인했다. 원본과 달랐던 portal의 노트북 이미지 생성물은 정식 빌더로 갱신했다.
- [정적 제공 경로](static-host-tests.json) 6/6 및 [패키징 대조](container-source-checks.json): 새 공유 처리 모듈을 교사 독립 서버·학습 허브·Workspace에서 제공하고 Docker 이미지에 포함하도록 구성했다. Docker 정적 파일·서버 import 그래프 검사와 별도 모듈 포함 검증이며, 운영 이미지 배포 증거가 아니다.
- 이전 학원 경로의 실제 교사·학생 UI 근거는 [케어 검증 기록](../workspace-care-20261009/README.md)에 보존했다. 그 기록은 최신 3D 전체 연동이나 공개 배포의 증거가 아니다.

## 당시 전체 연결을 위해 남겨 둔 경계

1. 최신 WORLD가 실제 SYNK ID와 운영용 공통 학습 API를 사용하도록 연결하고, 첫 학습 기록의 동의·저장·교사 조회 왕복을 확인한다. 로컬 두 시험 계정을 실계정처럼 취급하지 않는다.
2. 최신 3D TOWN의 생활 호스트를 계정·반·마을 소속과 연결한다. 현재 개인별 JSON을 서버의 공식 반 활동으로 오인하지 않고, 별도 Town 동의 아래 수락한 활동 요약만 공통 수업 저장소에 전달한다. 동의 철회·학생 반 이동·두 계정·중복 명령·재접속도 왕복 검증한다.
3. 수업 DB migration·서버 함수·교사 OAuth 클라이언트/콜백·Workspace UI·PC 설치본을 일치시키고, 실제 교사와 학생으로 운영 왕복을 확인한다.

이번 검수는 운영 서버·운영 DB·실계정 기록을 변경하지 않았다. 로컬 소스 수정과 합성 시험은 공개 사용 완료와 구분한다.
