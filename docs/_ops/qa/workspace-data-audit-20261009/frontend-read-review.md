# 교사 상세의 공유판 역전 · 읽기 검토

2026-10-09. root/live_advice의 실제 Chromium 재현을 전제로 부모 교사 host와 상세 소비 코드를 읽었다. 이 문서의 코드는 읽기 검토이며, 실제 재현·수정 전후 화면 결과는 `frontend/report.json`의 해당 실행 기록을 따른다.

부모 개요는 학생의 공유 rev3/꺼짐을 확인했는데, 이미 진행 중이던 상세 rev2 응답이 늦게 반환돼 WORLD 활동 12건을 다시 표시했다. 당시 `teacher-workspace`의 요청 반환 후 확인은 반의 host epoch와 연결 상태에 한정됐으며, 상세 GET은 부모가 새로 알게 된 학생 공유판을 조건으로 쓰지 않았다.

**선택 학생의 host만 바꾸는 것으로는 충분하지 않다.** 같은 iframe의 비선택 학생 A는 whole-class cache에 예전 공유 기록이 남을 수 있다. 학생 명부 클릭은 새 요청 없이 `renderRoster`/`renderDetail`로 이동하므로, 이미 알려진 A의 철회 뒤에도 옛 근거를 즉시 표시할 수 있다.

최소 경계는 다음과 같다.

- 부모가 검증한 최신 명부·학습 공유판·계정 연결/철회 상태를 상세 GET의 반환 조건으로 확인한다. 학생은 같아도 낮은 공유판의 반환은 새 정보로 채택하지 않는다.
- 현재 선택 학생의 학습 접근이 바뀌면 해당 host를 닫거나 재확인한다. 비선택 학생 변경은 그 학생 cache·관련 제출/관찰/케어만 지우며, 학생 B의 별도 초안을 무조건 닫지 않는다.
- child는 명부 선택·렌더·쓰기 전에 부모의 최신 접근 정보를 확인한다. 변경 통지는 원래 iframe·정확한 origin·현재 host에 한정한다.
- Town은 별도 공유판이다. Town만 철회됐으면 Town 활동만 숨기며 공유된 학습·관찰/케어 초안은 유지한다.
- child가 먼저 더 높은 판을 확인한 경우 부모의 늦은 낮은 판으로 되돌리지 않는다. 같은 판에서 공유 꺼짐·연결 해제·철회는 닫는 쪽이 우선이다.

분담한 순수 `sharing-fence.mjs`는 입력 원본을 바꾸지 않고 `{workspace, changedLearnerIds, revokedLearnerIds, changedTownLearnerIds}`를 반환한다. 낮은 판 무시, 해당 학생의 민감 cache 제거, Town-only 보존, 명부 제거, 다수 대상 과제의 남은 학생/제출 보존을 단위 회귀 **8/8**로 확인했다. 부모/상세 코드의 실제 통합과 held 응답·명부 클릭·초안 보존의 전체 Chromium 왕복은 live_advice의 별도 결과를 확인해야 한다.
