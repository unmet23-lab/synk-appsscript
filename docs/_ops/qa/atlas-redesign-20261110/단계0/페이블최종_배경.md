# Atlas 재설계 단계 0(길 닦기) — Fable 최종 검수 배경

이 묶음은 이미 origin/master에 올라간 커밋 `4a798e51b`의 단계 0 경로만 보인다(바탕 `9394c1783` → 끝 `4a798e51b`). 그 사이 이 경로를 건드린 커밋은 `4a798e51b` 하나이고, 그 뒤 origin/master까지도 0이다. 잠금(`packages/atlas/package-lock.json`)은 도구가 기본으로 뺀다. 전체 기록은 묶음에 든 `docs/_ops/qa/atlas-redesign-20261110/단계0_계획.md`(§0~§9 계획 · §10 설계 검토 · §11 결과 · §12 달라진 것)이고, 정본은 `docs/아틀라스_재설계_20261110.md` §9 · §11 · §14다.

## 무엇을 왜

학습 엔진 Atlas를 옆에 새로 짓는 재설계의 단계 0이다. 두뇌 로직은 넣지 않고, 단계 1(지도와 태그) · 2(두뇌) · 3(기록과 저장)이 같은 저장소에서 서로 파일을 건드리지 않고 함께 갈 바닥만 깐다. 학습자가 느끼는 변화는 없어야 한다 — 공개본 동작이 한 글자도 안 바뀌는 것이 관문이다.

1. 새 패키지 `packages/atlas/`(ESM · private · 판 0.0.0 · 패키지 안 잠금, 루트 package.json · 잠금은 안 고침). 의존 ts-fsrs 5.4.2(정확한 판), 개발 의존 Biome 2.6.4 · esbuild 0.28.1. 모듈 자리 여섯은 계약 머리말 + `STAGE`만, `src/memory/fsrs.mjs`가 ts-fsrs를 부르는 유일한 자리, `src/record/events.mjs`가 사건 2판 이름표, `src/coach/`는 `ready`만 풀리는 빈 코치(메서드는 `NOT_IMPLEMENTED`).
2. 줄 수 상한 대신 검사 셋 — Biome 포맷터(폭 100) · 인지 복잡도 15 · 묶음 gzip 상한(`budget.json`, 상한은 설계값이라 실제 값에 맞춰 올리지 않는다). 관문 한 줄 `npm --prefix packages/atlas run check`, CI syntax-check에 패키지 설치와 「verify Atlas package」 단계. 옛 줄 수 단정은 거두고 파일 수 36 울타리 · 문서 150줄은 남겼다.
3. 빌드 `tools/build.mjs`(같은 커밋이면 같은 바이트, PC 경로가 남으면 멈춤, 제3자 코드 고지), 판 이름(`--release`일 때만 package.json 판, 그 밖은 `<판>-dev.<커밋7>`), `.gitattributes`로 패키지 글 파일 LF.
4. 입구 `loader/loader.js`(정적 import · export 없음) + `loader.mjs` — `ready`는 한 번만 정해지고 못 받으면 `LOAD_FAILED`(IMPORT · TIMEOUT 20초 · EDITION_MISMATCH · NO_BASE), ready 전 메서드는 `NOT_READY`, ready 전 `dispose` 허용, 같은 출처 위 창의 판을 따르고 엇갈린 판은 `SynkAtlas.conflicts`.
5. WORLD 공개 빌드 `checkReference`는 `/atlas/loader.js` · `/atlas/loader.mjs` 두 주소만 절대 주소 · `?v=` · `#` 없이 허용한다(참조 목록 · 빠짐 검사 전에).
6. 공개 길 `tools/publish.mjs`(단계 0에서는 돌리지 않음)는 공개 판 · 나무 = manifest · 필수 파일 · 공개본의 같은 판 폴더를 덮지 않는지 기계로 보고 `tools/공개.js` 명령을 찍기만 한다.
7. 계기 `src/health/`(묶음 받기 · 저장 · 추천) + `src/health/legacy.mjs`(지금 판 코치의 공개 표면만 감쌈) — 제품에는 붙이지 않았다(붙이면 공개본이 바뀐다).
8. 시제품 시험을 옮길 자리(README만)와 변형 실행기 `tools/mutants.mjs`.

## 관문의 증거(기록 §11)

패키지 check 통과(atlas.mjs gzip 1,572B · loader.js gzip 1,940B · unit 42 · build 12), CI syntax-check 실행 42789792705 성공(Linux). WORLD 공개 빌드 앞뒤 대조(`단계0/공개대조.cjs`) 6,256파일 sha256 모두 같음 · missing · publicToolNames · ok · 참조 수 1,377 같음(두 판의 `ok:false`는 바탕에 원래 있던 알림 둘). 실제 브라우저(CSP `script-src 'self'`)로 클래식 · 모듈 · 틀 · 없는 판 · 닫은 뒤 없는 판(처리되지 않은 거절 0)을 확인했다.

## 설계와 달라진 것(기록 §12, 설계서는 안 고침)

① 공개 판 = 「origin/master에 든 깨끗한 커밋 + package.json 판」(설계 §9의 「태그한 커밋」 대신 — 바로올리기가 꼬리표를 올리지 않는다). ② 계기는 모듈 + 진짜 지금 판 코치 시험까지, 축은 셋(묶음 받기를 더함). ③ 입구는 파일 둘 + 위 창 판 따르기.

## 특히 볼 곳

- 입구의 `ready` · `dispose` · 위 창 판 따르기 · `conflicts` 계약을 단계 4(제품 전환)가 그대로 쓸 수 있는가.
- 계기의 판정(`load-failed` · `save-streak` · `recommend-streak`)과 「다른 탭 잠금 대기는 실패가 아님」이 지금 판 코치의 실제 알림과 맞는가(`legacy.mjs`).
- 빌드 · 공개 길: 같은 커밋 같은 바이트, 공개 판 조건, 판 폴더를 덮지 않는 검사.
- 단계 1 · 2 · 3이 함께 고칠 자리(`src/index.mjs` · `events.mjs` · 변형 목록 · package.json 시험 명령)가 부딪치지 않게 되어 있는가, 공개본 동작이 그대로라는 관문 증거가 충분한가.
