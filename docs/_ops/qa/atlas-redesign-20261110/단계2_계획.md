# Atlas 재설계 단계 2 — 두뇌 (2026-11-10 계획)

> 정본 설계는 [아틀라스 재설계](../../../아틀라스_재설계_20261110.md) §3 · §1 표 · §11이다. 이 문서는 그 설계를 `packages/atlas/`에 옮기는 방법과, 시제품에 없던 것을 어떻게 메우는지를 적는다. 단계 0의 바닥은 [단계 0 기록](단계0_계획.md), 패키지 쓰는 법은 [README](../../../../packages/atlas/README.md).

## 0. 목적과 관문

설계 §3의 두뇌(기억 1판 · 난도 1판 · 고르기 1판 · 이유)를 순수 함수로 패키지에 짓고, 시제품 6판의 시험(장면 단정 46 · 임의 시험 둘 · 변형 64 · 가상 학습자)을 패키지 시험으로 옮겨 관문으로 건다.

관문(설계 §11): §1 표의 1~4 · 7, 가상 학습자 관문 1~7, `npm --prefix packages/atlas run check` 통과, 끝 판 엔진급 검수(Fable · 아르곤 · 아스트라). 공개본 · 제품 · `atlas/`는 건드리지 않는다(12/10까지 라이브는 지금 판).

## 2. 바깥 계약

### 2-1. 문항(단계 1의 문항 색인이 내는 꼴)

```
{ itemKey, familyKey, skillId, difficulty: 1|2|3, responseFormat, units: [주 단위, …], order, unknownOption?: boolean, audioRequired?: boolean }
```

이름은 지금 사건 꼴(`atlas/trail.js`의 `itemKey` · `measure.familyKey` · `skillId` · `responseFormat`)을 따르고, 설계의 `units`(지금의 `conceptIds`)만 새 이름이다. 시제품의 `id` · `kcIds`를 `itemKey` · `units`로 바꾼다.

### 2-2. 접기 사건(단계 3의 어댑터가 내는 꼴)

```
답           { kind: 'answer', id, at, item, answer: { correct, assisted, answerShown, unknown, assessable, target } }
도움만 봄    { kind: 'help',   id, at, item }
본인 말      { kind: 'say',    id, at, unit, say: 'known' | 'relearn' }
제외         { kind: 'exclude', id, at, ref, touches? }      touches = { units, skills }
옮겨 온 장부 { kind: 'carry',  id, at, families, after? }
```

- 근거 줄(단위): `{ id, at, grade }` 또는 `{ id, at, say }`. 만남(계열): `{ id, at, skillId, difficulty, responseFormat, grade, unaided, carried? }`. 서버 표의 근거 줄은 이 둘을 뽑을 수 있으면 된다(설계 §5-3의 열 목록이 이것을 덮는다).
- `foldServer(events)`가 돌려주는 요약: `{ memory: Map<단위, 상태>, ability: Map<능력, {theta, n, streak, lastAt}>, met: Map<계열, 첫 만남 시각> }`. 단위 상태는 「마지막 자리 앞의 상태(prev) + 마지막 자리(open)」와 계산값 · 만난 자리 수 · 놓친 자리 수 · `latestAt`(이어 접을 수 있는 꼴 — §5-3).

### 2-3. 고르기

- `startSession(learner, now, params, { more, length, newLimit, level, dayOffset })` — 판을 연다. `length`(판 길이)와 `newLimit`(한 판 새것 한도, 안 주면 판 길이의 3분의 1 · 최소 1 — 설계 §3-5; 판 길이도 없으면 `params.newPerSession`)은 제품이 준다. `dayOffset`은 기기 현지 시각과 UTC의 차이(분) — 하루 경계(현지 새벽 4시)에만 쓴다.
- `learner.log`(「낸 것」 기록) = `[{ at, review, units }]`. 단계 3이 요약의 최근 이틀 표 + 아직 요약에 안 든 내 제시로 채운다.
- `choose(candidates, learner, memory, now, { params, seed })` → 줄 목록(맨 앞이 고른 것). 줄: `{ item, tier, target, p, expected: { floor, memory, skill }, why: { code, slots, evidence }, arm: 'adaptive' | 'filler', idle, none, capped, breather, … }`.
- `present(learner, row)` · `record(learner, memory, item, answer, now)` · `say(learner, memory, unit, kind, now)` — 시제품 그대로.

## 3. 시제품에 없던 것 — 단계 2가 메운다

1. **끈질기게 틀리는 단위(§3-5).** 기준: 그 단위의 근거 줄을 접으며 자리마다 「놓친 정도 − 예상 놓침(1 − 그 자리 앞의 떠올릴 확률)」을 더한 값(놀람 합)이 출발값 2.0 이상이고 놓친 자리가 3 이상이면 `stubborn`. 단위 상태에 `surprise` · `stubborn`을 싣는다(접기의 순수 값이라 서버 · 기기 · 일괄 계산이 같게 센다 — `test/oracle/spec.mjs`도 같이 고친다). 다루기: ① 줄에 `stubborn: true`를 싣고 이유 근거에 남긴다 — 「힌트 먼저 · 설명 카드 · 다른 꼴」은 제품이 이 표시를 보고 한다(단계 4). ② 같은 단위를 묻는 문항 가운데 그 단위를 놓친 꼴과 다른 응답 꼴을 먼저 고른다. ③ 한 판에서 끈질긴 단위가 겨눈 단위인 문항은 판 길이의 5분의 1(최소 1)까지 — 넘는 것은 「하루 복습 상한에 걸려 미룬 단위」와 같은 자리(내지 않음의 셋째 까닭, 이름을 「복습 상한에 걸려 미룬 단위(하루 · 판 몫)」으로 넓힌다)에 둔다. 기준값 2.0 · 3 · 5분의 1은 가상 학습자 묶음에 「낱말마다 반감기가 아주 짧은 학습자」를 더해 정하고, 끄고 켠 결과를 표로 남긴다.
2. **자리 잡기(§3-3).** 처음 온 사람(그 능력의 답 수 0)의 θ 출발값을 「본인이 고른 연습 수준의 아래 끝 난도」로 둔다(`startSession`의 `level: { min, max }`). 그 범위 밖 문항은 제품이 후보에서 거른다. 첫 서너 문항의 사다리는 지금 걸음 규칙(답이 적을 때 크게)과 「예상 성공 0.8 근처」 고르기가 낸다 — 따로 사다리 코드를 두지 않는다. 장면 하나를 더한다(맞히면 오르고, 놓치면 내린다, 범위를 넘지 않는다).
3. **「모르겠어요」의 찍기 바닥(§3-4).** `unknownOption`이 있는 문항은 찍기 바닥을 절반으로.
4. **예상 확률의 세 항과 회차 구분.** `predict`가 `{ floor, memory, skill, p }`를 낸다. 회차는 이 단계에서 `adaptive`(0~2층 · 숨 고르기) · `filler`(3 · 4층)만 — 비교 회차 `baseline`은 단계 5.
5. **활동 고르기(§3-6).** `planActivities(activities, learner, memory, now, { facts })` — 활동마다 자기 후보의 `choose` 맨 앞 층과 할 것의 수를 보고 순위를 낸다. 사실(하던 것 · 한글 먼저 · 숙제 · 열 수 없음)이 순위를 앞지르는 규칙은 표 하나(`PLAN_FACTS`)에 둔다. 지금 `world-learning-plan.mjs`의 `hostReason` 80줄을 이 표로 옮기는 것은 단계 4(제품을 잇는 때)이고, 단계 2는 표의 틀과 일반 순위만 짓는다.
6. **설정이 후보를 먼저 거른다(§3-5 끝).** `filterCandidates(items, { audio, help, notNow })` — 소리 없는 자리에서 `audioRequired` 문항을 빼고, 「지금은 아니에요」 주제를 뺀다. 순수 함수 하나.
7. **근거(`evidence`).** `slots`는 문장에 들어가는 값(단위 · 며칠 만에 · 횟수), `evidence`는 그 값을 낸 기록의 원값(단위 상태의 `sittings` · `lapses` · `lastAt`, 능력의 `n` · `streak`, 난도의 `from` · `to`, `stubborn`). 시험은 `evidence`를 기록과 맞대고, `slots`를 `evidence`에서 다시 계산해 맞댄다.

## 8. Fable 설계 검토(11-10) — P1 3 · P2 9 · P3 9, 반영

판정: 「구조(모듈 나눔 · `src/fold/` 경계 · 이름 · check/gate)는 이대로, P1 셋과 빈칸을 계획에 적은 뒤 만든다」. 아래가 고친 계획이다(위 §1~§4보다 이 절이 앞선다).

| 지적 | 처리 |
|---|---|
| P1-1 `fsrs.mjs`에 `enable_short_term: false`가 없다 — ts-fsrs 기본은 켜짐이고 놓침 가지에서 w17 · w18로 안정도를 자른다. 기준이 같은 파일을 쓰면 못 잡는다 | 반영 — `FSRS_SETTINGS`에 넣고 build 시험으로 묶음. 기준(`test/oracle/spec.mjs`)은 `ts-fsrs`를 직접 부르고 자기 설정을 만든다. 변형 「짧은 간격을 켠다」를 더한다 |
| P1-2 자리 잡기 θ₀를 접기에 넣으면 서버(수준을 모른다)와 갈리고, 「아래 끝」이면 쉬운 문항을 여덟 번 받는다 | 반영 — θ₀는 **고르기의 선행값**이다. 접기 · 요약의 θ는 그대로 0에서 시작하고, `predict` · `choose`만 `θ_eff = θ + θ₀ / (1 + n)`을 쓴다. θ₀ = 고른 수준 범위의 **윗 끝** 난도의 로짓(`startSession`의 `level: { min, max }`). 장면: 넷 맞히면 오르고 한 번 놓치면 내린다 |
