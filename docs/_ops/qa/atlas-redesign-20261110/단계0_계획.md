# Atlas 재설계 단계 0(길 닦기) — 계획과 기록 (2026-11-10)

> 정본은 [아틀라스 재설계](../../../아틀라스_재설계_20261110.md) §9 · §11 · §14다. 이 문서는 단계 0을 만들기 전에 Fable 설계 검토에 보인 계획이고(§0~§9), 만든 뒤의 기록(§10~§13)이다. 단계 0은 두뇌 로직을 넣지 않는다 — 단계 1 · 2 · 3이 함께 시작할 수 있게 자리 · 검사 · 내보내는 길만 닦는다. 패키지의 쓰는 법은 [`packages/atlas/README.md`](../../../../packages/atlas/README.md)에 있다.

## 0. 목적과 관문

- **목적.** 새 엔진 `packages/atlas/`를 지을 바닥을 깐다. 단계 1(지도와 태그) · 2(두뇌) · 3(기록과 저장)이 같은 저장소에서 서로 파일을 건드리지 않고 함께 갈 수 있어야 하고, 줄 수 상한 없이도 코드가 간결하게 유지되는 검사가 처음부터 걸려 있어야 한다.
- **사용자 흐름.** 학습자가 느끼는 것은 없다(공개본 동작이 그대로다). 쓰는 사람은 단계 1~5의 구현 세션이다 — `npm --prefix packages/atlas run check` 한 줄로 포맷 · 복잡도 · 용량 · 시험을 보고, `node packages/atlas/tools/build.mjs`로 공개할 나무(`atlas/loader.js` · `atlas/<판>/`)를 얻는다.
- **관문.** 공개본 동작이 한 글자도 안 바뀐다 — 공개 빌드 산출물을 앞뒤로 대조해 보인다(§6 · §11). 관련 시험이 통과한다.
- **하지 않는 것.** `atlas/`의 지금 파일 고치기(결함 다섯 고침 세션의 몫), SYNK-talk 쓰기, synk.im 공개, 제품이 입구를 부르게 바꾸기(단계 4).

- **모듈 자리는 빈 입구만 둔다.** 각 폴더의 `index.mjs`는 그 단계가 채울 계약(입력 · 출력 · 지킬 것)을 머리 주석으로 적고 `STAGE`만 내보낸다. 두뇌 로직은 넣지 않는다.
- **의존.** `ts-fsrs` 5.4.2(08-22 확정 · SYNK-talk과 같은 판, 정확한 판으로 고정). 개발 의존은 `@biomejs/biome` 2.6.4(10-28에 나온 판 — 나온 지 2주가 지난 마지막 판)와 `esbuild` 0.28.1(루트와 같은 판).
- **잠금은 패키지 안에.** 루트를 npm 작업 공간으로 바꾸면 루트 `package-lock.json`이 크게 바뀌고 다른 세션의 잠금 고침과 부딪친다. `experiences/synk-account`처럼 패키지 안에 잠금을 두고 CI가 그 폴더에서 `npm ci --ignore-scripts`를 한 번 더 돈다. 루트 `package.json`은 고치지 않았다.

## 3. 묶음 하나로 내보내는 빌드와 공개 길

**빌드**(`tools/build.mjs`). esbuild로 `src/index.mjs`를 ESM 묶음 하나(`atlas.mjs`, 압축, 대상 es2020)로 묶고 판 이름을 `define`으로 찍는다. 같은 커밋이면 같은 바이트다(시험이 두 번 빌드해 견준다). 묶음에 이 PC의 경로가 남으면 멈추고, 묶음에 든 제3자 코드는 metafile에서 찾아 `LICENSES.txt`와 manifest의 목록으로 낸다(단계 0의 묶음에는 없다 — ts-fsrs가 들면 MIT 고지가 생기는 것을 시험이 본다).

```
<밖>/atlas/loader.js            입구(판 이름 한 줄)
<밖>/atlas/loader.mjs           ES 모듈 겉(판과 무관)
<밖>/atlas/<판>/atlas.mjs        엔진 묶음
<밖>/atlas/<판>/manifest.json    판 · 커밋 · 파일마다 sha256 · 바이트 · gzip 바이트 · 제3자 코드
<밖>/atlas/<판>/LICENSES.txt     제3자 코드의 고지(있을 때만)
```

- **판 이름.** 공개 판은 `package.json`의 판(`0.1.0` 꼴)이고 `--release`일 때만 낸다 — 이 패키지에 커밋하지 않은 고침이 없고, HEAD가 `origin/master`에 들었고, 판이 `0.0.0`이 아니어야 한다. 그 밖의 빌드는 `<판>-dev.<커밋 앞 7자>`(고침이 있으면 `.dirty`)라 공개 판과 섞이지 않는다. 설계서 §9의 「태그한 커밋」은 이 정의로 바꿨다(바로올리기가 꼬리표를 올리지 않아 다른 세션 · CI가 확인할 수 없다 — Fable 설계 검토 7, 트랙에 적음).

**입구**(`loader.js` · `loader.mjs`, 설계 §8 · §9). `loader.js`에는 정적 `import` · `export`가 없어 같은 파일을 클래식 스크립트로도(게임 · 드라마) ES 모듈로도(계정 셸) 부른다. 판 묶음은 동적 `import()`로 받는다.

- `SynkAtlas.coach(options)`는 곧바로 겉 코치를 돌려주고, `ready`는 판 묶음을 받아 진짜 코치를 만든 뒤 풀린다. **`ready`는 한 번만 정해진다** — 못 받으면 `code: 'LOAD_FAILED'`(`reason`: `IMPORT` · `TIMEOUT`(20초) · `EDITION_MISMATCH` · `NO_BASE`)로 거절하고, 다시 부르면 새로 받는다. `ready` 전 메서드는 `NOT_READY`로 던진다. 떠나는 화면은 `ready` 전에도 `dispose()`할 수 있다 — 묶음이 오기 전이면 코치를 만들지 않고, 만든 뒤 그 `ready` 전이면 붙이지 않고 닫는다(그 뒤 메서드는 `DISPOSED`).
- 같은 문서에 입구가 두 번 실리면 먼저 실린 판 하나만 돈다. 같은 출처의 위 창에 입구가 있으면 그 판을 따른다(WORLD 틀 안 게임과 위 창이 다른 판을 받지 않게 — Fable 설계 검토 3). 엇갈린 판은 `SynkAtlas.conflicts`에 남는다.
- 판 이름은 `loader.js`의 한 줄에만 있어서 **올리기는 새 폴더 + 입구 한 줄, 되돌리기는 입구 한 줄**이다.

**WORLD 공개 빌드의 허용**(`tools/build-world-app-public.mjs`의 `checkReference`). `/atlas/loader.js`와 `/atlas/loader.mjs` 두 주소만, 절대 주소로, `?v=` · `#` 없이 받는다(참조 목록과 「빠짐」 검사 전에 돌아간다 — payload에 없으므로). 토큰이 붙거나 상대 주소면 `atlas-entry-form`으로 막는다. 판 폴더(`/atlas/<판>/…`)와 `/atlas/`(소개 쪽) 같은 다른 주소는 지금처럼 「WORLD 밖」이다. 시험: `tests/world-public-atlas-entry.test.js`.

**공개 길**(단계 0에서는 돌리지 않는다). `tools/publish.mjs`가 공개 판인지, 나무가 manifest와 같은지, 공개본에 같은 판 폴더가 다른 바이트로 있지 않은지(판 폴더는 덮지 않는다 — Fable 설계 검토 8) 기계로 보고, 맞으면 `node tools/공개.js 올리기 --원본 <밖> atlas/<판>/… atlas/loader.js atlas/loader.mjs` 명령을 찍는다. `tools/공개.js`는 고치지 않았다. synk.im에는 이미 `/atlas/index.html`(Atlas 소개 쪽)이 있고 판 폴더 이름은 숫자로 시작해 겹치지 않는다.

**PC 앱과 Talk — 동봉할 자리**(정해 두기만). PC 앱은 `desktop/renderer/atlas/loader.js` · `desktop/renderer/atlas/<판>/` — `synk-desktop://`가 `/assets/` 밖의 주소를 `renderer/`에서 읽으므로(`desktop/src/native-content.cjs`) 웹과 같은 `/atlas/loader.js`가 통하고, `.mjs` MIME은 이미 있으며, 화면 CSP(`script-src 'self'; connect-src 'none'`)와 바깥 요청 차단 때문에 원격 입구는 못 쓴다. 판을 묶어 두는 검사는 **새로 짓는다** — `tools/lib/atlas-copies.js`의 미등록 사본 훑기는 `desktop/assets`까지만 보므로 `desktop/renderer/atlas/`는 밖이다(Fable 설계 검토 10). Talk 앱은 `SYNK-talk/lib/atlas/<판>/` + `sync-manifest.json`의 `edition`과 sha256, Talk 서버는 `supabase/functions/_shared/synk-atlas-<판>.mjs` 하나를 Talk `tools/synk-server-build.js`의 `OUTPUTS`에(머리에 sha256 — 지금 `_shared/synk-atlas.js` 방식). 표는 패키지 README에 있다.

## 4. 저장 실패 · 추천 실패를 세는 계기

- **제약이 셋이다.** 계기는 지금 판에 달아야 하고, `atlas/`의 지금 파일은 건드리지 않으며, 공개본 바이트가 바뀌면 안 된다. 제품 파일(호스트 · 게임)에 붙이면 생성 묶음과 공개 산출물이 바뀌고, master에 섞인 미공개 변경으로 남의 공개에 실려 나갈 수 있다.
- **그래서 단계 0은 「지금 판의 겉에 맞춘 계기를 만들고 진짜 지금 판 코치로 시험한 것」까지다.** 붙이는 것은 공개를 동반한다 — 12/1 동결 전에 지금 판에 붙이려면 결함 다섯을 공개하는 때 함께 싣는 것이 가장 싸다(트랙에 남김).
- `src/health/` — 묶음 받기(`load`) · 저장(`save`) · 추천(`recommend`)의 시도 · 실패 · 이어진 실패 · 처음과 마지막 실패 시각 · 코드(대문자 낱말만, 열여섯 가지 + OTHER)를 센다. 요약에 신원 · 문항 · 답 · 경고 문장이 없다. 「엔진이 꺼진」 판정은 `load-failed`(마지막으로 묶음을 못 받음) · `save-streak`(저장 세 번 이어서 실패) · `recommend-streak`(추천이 세 번 이어서 던짐).
- **다른 탭의 잠금 대기는 실패가 아니다**(Fable 설계 검토 1). 지금 판은 같은 이력의 쓰기 잠금을 다른 탭 · 틀이 쥐면 `storage-wait`(`STORAGE_BUSY`)를 내고 `storage.available`이 false가 된다 — 정상 경로다. 계기는 이것을 시도로도 실패로도 세지 않고 「기다리는 중」으로 두며, 저장이 되면(`storage-ready` · `append` …) 닫는다. `storage.available`은 관측으로만 남기고 판정에 쓰지 않는다. 추천의 `status: 'unavailable'`(조건에 맞는 문항 없음)도 실패가 아니라 따로 센다(Fable 설계 검토 9).
- `src/health/legacy.mjs` — 지금 판 코치(`atlas/game-learning.js`의 `createGame`)의 공개 표면만 읽는다: `syncPort.subscribe` 알림, `recommend` · `recommendActivities`의 던짐과 결과. 두 추천 메서드만 감싼 겉을 돌려주고 나머지는 지금 판 그대로 넘긴다. 엔진 묶음에는 들지 않는다.

## 8. 벤치마킹 근거

- 포맷터 · 복잡도: 큰 JS 프로젝트는 줄 수 대신 포맷터와 복잡도 상한을 쓴다. 인지 복잡도의 상한 15는 SonarSource의 기본값이고, Biome의 같은 규칙도 기본 15다(설치본으로 확인). 한 도구로 포맷과 복잡도를 함께 보고 바이너리 하나라 CI가 빠르다.
- 용량 상한: 라이브러리들이 묶음 압축 바이트를 CI에서 재는 관례(size-limit류)와 같다 — 줄이 아니라 사용자가 받는 바이트를 잰다.
- 판 고정 폴더 + 작은 입구: 바뀌지 않는 판 폴더는 캐시가 깨질 일이 없고, 바뀌는 것은 작은 입구 하나라 되돌리기가 한 줄이다(설계 §9). GitHub Pages가 캐시 머리를 못 바꾸는 한계 안에서 고를 수 있는 꼴이다.

## 9. Fable에게 물은 것

1. 계기(§4)를 제품에 붙이지 않고 「지금 판의 공개 표면에 붙는 모듈 + 진짜 지금 판 코치로 한 시험」까지만 하는 것이 맞는 선인가 → 맞는 선. 보고에 「지금 판의 겉에 맞춘 모듈을 만들었고 붙이는 것은 결함 다섯 공개 때」로 쓴다.
2. 옛 상한을 거둘 때 파일 수 36 · 문서 150줄을 남기는 것 → 둘 다 그대로.
3. 입구의 꼴 → 된다. 틀 · 위 창(3)과 실패 계약(2)을 더한다.
4. 판 이름과 판 폴더를 덮지 않는 규칙 → 좋다. 꼬리표를 미는 길(7)과 덮지 않기의 기계 검사(8)가 빠졌다.
5. 패키지 안 잠금 + CI 단계 하나, 루트 시험은 의존 없는 시험만 → 맞다. 단계 2에서 저절로 깨지는 구멍(5)을 막는다.
6. 단계 1 · 2 · 3이 부딪칠 자리 → 변형 목록 · 시험 받침 · `budget.json` · README · `biome.json`, 그리고 사건 2판 꼴(2와 3이 따로 정의할 위험이 가장 크다 — 계약 파일 하나를 단계 0에).
