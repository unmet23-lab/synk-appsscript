## 현재 적용 범위

로컬 구현과 격리 검증을 거쳐 운영에 배포했다. 기존 모델·스타일 기능과 공통 파일을 통합했으며 캐스팅 원문·자산·검증을 보존한다. 운영 변경은 배포와 지정 테스트 프로젝트의 기획 확인·선택·의견·승인·납품 시험으로 한정했다. 실고객 프로젝트 수정·외부 발송·유료 생성·현재 PC 앱 재설치·운영 데이터 자동 이관이나 삭제는 실행하지 않았다.

- 기획 확인 요청은 메시지·근거·행동 세 항목으로 판단한다. 나머지는 선택이고 생략한 기존 값은 보존한다.
- 결과물별 납품 규격과 버전 확인, 변경 이력, 최신 승인 시안의 최종 파일 연결을 제공한다.
- 기존 참고자료·파일로 표현 샘플을 준비하고 원하는 요소·피할 요소·이유를 저장한다.
- 시간별 의견을 고객 비공개 초안에 모아 취합자가 한 회차로 제출한다. 회차마다 제작자 알림은 한 개이고 개별 의견은 기존 수정본 처리 흐름으로 이어진다.
- 공개 장면과 임시 MP3/WAV 음원을 시간대로 재생한다. 별도 업로드한 실제 시험 영상은 5~10초 구간으로 검토한다. 흐름과 시험 장면의 확인 당시 내용을 각각 보존한다.
- 수정 의견의 오류 정정·합의 범위·방향 변경 분류와 범위·일정 설명을 고객과 공유한다. 횟수·비용·납기를 자동 확정하지 않는다.
- 입력 중인 행·영상 버전·확인 대상은 유지하고, 오래된 초안은 해당 양식만 비운 뒤 최신 내용으로 다시 작성할 수 있다.

## 자동 검사

[주요 테스트 결과](tests.txt): 116/116 통과. 기획·데모·규격·피드백·샘플/재생·기존 서버·모바일 검토·알림·UI 초안 처리를 포함한다.

[동시 캐스팅 통합 검사](casting-tests.txt): 추가 12/12 통과. 앞 결과와 테스트 파일이 겹치지 않는다.

[최종 초안 복구 검사](draft-ui-final.txt): 11/11 통과. 앞 116개에 포함된 UI 10개를 재검사하고 납품 규격의 이전 revision/행 초안 초기화 시험 1개를 추가했다. **중복을 제외한 관련 시험은 총 129개 통과**다. CSP 대응 스타일 수정 뒤 [납품·피드백 뷰 30개](view-regression.txt)도 재통과했다. 이 재검사는 총계에 다시 더하지 않는다.

병행 작업의 일정 화면이 공통 코드에 추가된 뒤 최신 서버로 다시 시작하고 [서버 통합 29개](final-integration.txt)를 재검사해 모두 통과했다. 접속·새로고침·콘티 장면 이동도 최신 브라우저에서 다시 확인했다. 일정 기능 자체의 전체 검증은 그 작업의 담당 범위다.

HTTP 검사는 실제 격리 서버·파일 업로드·고객/제작자 요청을 사용한다. 다음을 포함한다.

- 고객 초안의 직원 조회 경로 비공개, ACL·CSRF·Origin·역할·프로젝트/기능 버전 검사, 실패 시 저장본 불변.
- 규격 확인 → 수정 시 현재 확인 해제·이전 목록 보존 → 재시작 복원.
- 실제 MP4 시안 승인 → 최종 파일 등록·규격 연결 → 고객 다운로드 원본 bytes 일치. 다른 프로젝트/시안/옛 승인 파일 연결 거부.
- 의견 취합 → 기존 내부 검토 → 수정 시안 연결 → 고객 승인. 미해결 의견 또는 저장된 초안이 있는 동일 시안 승인 차단.
- 내부 파일 404 → 공개 200 → 공개 철회 404, 과거 기록에서 파일 주소 비노출.
- WAV Range 206·실제 bytes, 음원 백업 payload 일치·복원 검사·누락 원본 거부. 일반 납품 업로드의 WAV 거부는 유지.
- 장면 순서·문구·길이·소리·시험 구간 변경 뒤 기존 확인 재사용 차단, 확인 당시 스냅샷과 재시작 기록 유지.

실행 위치는 `docs/마케팅/온라인마케팅지도/engagement/company`다. `pulse-*.test.mjs` 중 위 기능 관련 파일과 `client-notifications.test.mjs`를 사용했다. 전체 저장소 검사를 실행한 결과는 아니다.

## 실제 브라우저 확인

CUA의 격리 로컬 서버와 가상 모루 프로젝트에서 직접 진행했다.

1. 고객의 기획 확인과 납품 규격 확인을 각각 저장하고 제작자에게 같은 상태가 표시됨을 확인했다.
2. 샘플의 색감 선호·편집 속도 회피·이유를 저장했다.
3. 이미지 네 장면과 WAV를 15초 재생해 마지막 장면/정지 및 3초 장면 이동을 확인했다. 오디오 요소의 실제 재생 상태와 재생 시간은 확인했으나 사람의 청취 품질 검수는 하지 않았다.
4. 실제 MP4 시험 구간 재생이 약 7초에서 멈추며 종료 안내를 표시했다. 흐름과 시험 장면을 따로 확인하고 이력에 남겼다.
5. 3초·11.5초 의견 두 개를 초안으로 저장해 1차로 취합 제출했다. 같은 시안의 승인 차단, 제작자 분류/범위/일정 저장을 확인했다.
6. 납품 행을 추가·입력한 뒤 다른 탭으로 이동해도 행 구조·입력이 유지됐다.
7. 320px에서 기획/규격표·표현 샘플·영상 검토, 390px에서 콘티 재생을 확인했다. 규격표 인라인 스타일이 CSP에 차단되어 생기던 페이지 넘침은 외부 CSS로 고쳤다. 수정 후 페이지 가로 넘침은 없고 표 내부에서만 스크롤한다. 실제 휴대폰 장치 시험은 아니다.
8. 최종 로컬 화면의 브라우저 오류 로그는 0건이다. 개발용 뷰포트 변경은 원상복구했다.

## 이어서 열기

검증 fixture 원천은 `pulse-production-fixture.mjs`다. 저장소 루트에서 `node docs/마케팅/온라인마케팅지도/engagement/company/pulse-production-fixture.mjs`로 별도 임시 데이터·로컬 포트를 만든다. 생성한 접속 정보는 실행 위치의 `.tmp/pulse-upgrade/ready.json`에서만 확인하며 공개 문서에 초대 토큰을 복사하지 않는다. 실제 계정이나 고객 기록은 사용하지 않는다.

제작자가 사용할 실사·음성·시험 영상은 별도로 준비해야 한다. 이번 검증 영상은 기존 가상 브랜드 모션그래픽이며 타이밍 음은 기능 시험용이다. 실제 사람의 얼굴 유지·연기·립싱크·목소리 품질과 고객 만족도·절감 시간은 검증하지 않았다. 기능 운영 반영은 완료했으며 준비 중인 샘플 자산 제작은 별도다.
