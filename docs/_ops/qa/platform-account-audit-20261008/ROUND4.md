# SYNK 플랫폼 계정·기록 4차 검수

2026-10-08. 후속 ‘이어서 해’ 요청으로 로그인 만료·계정 전환·재시도의 실제 소비처를 점검했다. [3차 결과](ROUND3.md)에 이은 로컬 개선이다. 공개 배포·새 설치본·실제 회원 자료 변경은 하지 않았다.

## 재현과 수정

| 재현한 문제 | 수정 |
|---|---|
| 개인 앱의 로그인 콜백에서 코드 교환이 일시 실패하면, 주소와 일회용 PKCE 기록은 이미 지워져 ‘다시 확인’이 새 로그인으로 돌아감 | 이미 검증한 교환 요청만 현재 탭 메모리에 보관해 재시도한다. 인증 서버·제품 설정이 바뀌거나 로그아웃/폐기하면 버린다. 서버가 재시도를 거절하면 새 로그인으로 연결한다. 코드 재사용 성공을 보장하거나 별도 영구 저장하지 않는다. |
| 최초 연결 실패가 재시도 가능한 상태인데도 앨범·리허설의 단추가 ‘로그인’으로만 표시됨 | ‘계정 연결 다시 확인’으로 표시하고 기존 요청 복구를 수행한다. |
| 설치형 계정 화면에서 전체 로그아웃 요청이 느리면 기존 화면과 WORLD·요청 응답이 살아 있음 | 요청 직후 화면과 요청 응답 반영을 차단한다. 저장소·서버 종료 결과는 main 프로세스의 결과로 별도 판단하며 새 로그인에 오래된 종료 결과를 적용하지 않는다. |
| 늦은 초기 authStatus가 새 계정을 덮거나, 로그인 취소 뒤 늦은 응답이 로그인 중 상태를 되살림 | main의 세션 세대와 이후 인증 이벤트·명시 동작 순서를 확인하여 오래된 응답을 무시한다. 정상적인 같은 세대 토큰 갱신에서는 WORLD를 유지한다. |
| 학습 연결 끄기 결과를 받지 못하면 WORLD가 닫힌 채 복구 입구가 없음 | 상태가 불명확한 동의는 잠그고 ‘학습 연결 상태 다시 확인’을 제공한다. 이 단추는 서버를 읽기만 하며 동의를 재전송하지 않는다. 확인한 실제 동의에 따라 연습을 복구한다. |
| 다른 기기 로그인 종료 후 전체 화면을 다시 구성하면서 현재 WORLD 게임도 닫음 | 동일 계정·동의 상태라면 계정 정보만 갱신하고 WORLD를 유지한다. 동의 revision이나 계정이 달라지면 새 상태로 다시 연결한다. 수업 연결은 기존 재조회·재생성 계약을 유지한다. |
| 운세의 동일 계정 세션 갱신이 실제 앱의 clearScreen을 호출하여 작성 중 메모·실천 체크를 지움 | 같은 계정이면 이전 요청만 무효화하고 화면 초안을 유지한다. 다른 계정과 로그아웃은 기존처럼 자료를 비운다. |
| 앨범·리허설의 pagehide가 notebook을 항상 폐기해 보존된 페이지로 돌아오면 편집이 계속 잠김 | 브라우저가 페이지를 보존할 때는 notebook을 일시 중지한다. 복원 후 같은 계정인지 읽기로 확인하고, 앱의 작성 중 폼과 문서 revision은 다시 적용하지 않는다. 확인 전과 오류·다른 계정에는 자료를 숨기고 전송을 막는다. 앨범의 재생은 멈추되 보존 복원에 필요한 원본 미리보기 URL은 유지한다. |

복원 중 초기 인증이 뒤늦게 끝난 경우에도 게스트 초안을 자동으로 계정 자료로 바꾸지 않는다. 확인된 계정으로 전환하는 단추와 기존 명시 확인을 거친다. 문서 revision을 조용히 최신 값으로 올리지 않으므로, 화면 밖에서 다른 기기가 수정했으면 기존 충돌 확인이 유지된다.

## 브라우저 확인

기존 [로컬 검수 서버](round2-browser.mjs)를 확장했다. 실제 `createProductAccount`·`createAccountNotebook`·`createAccountView`를 사용하고 인증·저장은 합성 응답과 메모리 저장만 사용한다.

- `/callback-retry`: 첫 교환 503 → ‘계정 연결 다시 확인’ → 두 번째 교환과 소유자 확인 → 계정 기록 연결. 별도 OAuth 이동 없이 복구됨을 확인했다.
- 320·390·1280 폭에서 넘침과 누락 이미지가 없고 콘솔 오류·경고 0. [PC](round4-callback-recovered-1280.png), [모바일](round4-callback-recovered-390.png).
- `/account-refresh`: 동의 끄기 실패 → WORLD 숨김·동의 확인 필요 표시 → 읽기 재확인 후 WORLD 복구. [실패 후 재확인 화면](round4-consent-retry-1280.png).
- 같은 경로에서 다른 기기의 종료 표시와 WORLD 유지도 확인했다. 정확한 host/iframe 동일성은 자동 시험으로 검증했다.
- `/callback-retry`의 합성 보존·복원 조작: 작성 중 폼을 입력 → 자료 숨김 → 같은 계정 읽기 확인 → 동일한 입력이 남고 편집 잠금이 해제되는 것을 확인했다. [모바일 초안 복원](round4-draft-resume-390.png). 이는 실제 모듈의 lifecycle 호출을 브라우저에서 확인한 결과다. IAB의 실제 링크 이동·뒤로가기는 새로 로드되어 BFCache가 적중하지 않았으며, 실제 브라우저의 persisted 왕복 완료로 판정하지 않는다. 앱의 persisted 이벤트 연결은 자동 시험에서 확인했다.

## 운영 경계

이번 검증은 로컬 코드와 합성 계정 경로다. 실제 OAuth 제공자가 이미 사용한 코드를 다시 수락한다는 보장은 없으며 재거부 시 새 로그인으로 진행한다. 설치형 검사는 합성 IPC이며 실제 Electron 기기 조작·새 패키지 인수와 구분한다. 공개 반영, 실제 회원 로그인과 인증한 두 실물 기기의 기록 왕복은 미실행이며 기존 실물 왕복 보류를 유지한다.

PATH 여행 앱은 현재 기기 동의 저장만 사용하는 별도 소비처다. 공통 계정 모듈의 `path` 지원을 해당 앱의 계정 연동 완료로 해석하지 않는다.
