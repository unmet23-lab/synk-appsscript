# 로그인·계정·기록 연동 2차 검수

2026-10-08 · 사용자의 ‘이어서 해’ 요청. 1차 수정과 공용 작업본의 별도 내 홈·플레저 변경을 보존하고, 연결 복구와 기록 보호를 이어서 보완했다. **로컬 구현·합성 검증이며 공개 배포·새 설치본·실제 회원 자료 변경은 하지 않았다.**

## 저장 상태 확인 보강

WORLD에 계정 저장 상태와 직접 재시도 버튼을 연결했다. 기존 학습 host·Atlas 동기화 모듈을 재사용하며 게임 프레임이나 진행 중인 연습을 다시 만들지 않는다. 기기 내 기록, 저장 대기, 통신 실패, 계정 저장 완료, 기기 저장 실패, 동의 철회로 중단된 연결을 구분한다. 대기 숫자는 동기화 모듈의 기록 건수이며 문항 수나 학습 효과가 아니다.

검토에서 두 상태를 추가 재현했다. 과거 기록 복구가 페이지 한도에 걸린 `synced / complete:false`는 완료로 표시하지 않는다. 개인 기억의 동의가 철회되어 host가 `stopped`가 되어도 연결 준비 상태로 돌아가지 않고 중단 안내를 유지한다. 실제 host·학습 엔진을 사용하는 `learning-status.test.mjs` 7개에서 재시도·중복 클릭·진행 화면 보존·로그아웃·기기 저장 실패·201페이지 읽기·동의 철회를 확인했다. 엔진 원본은 변경하지 않았다.

최종 묶음 **931개 통과**. 1차 검사 수에 누적 합산하지 않는다. 공용 작업본의 관련 기존 검사도 포함하며, 모든 항목을 이번에 새로 만든 검사라고 표시하지 않는다. 범위 지정 diff 검사도 통과했다.

실제 브라우저에서는 [합성 검수 서버](round2-browser.mjs)의 현재 계정 화면·실제 학습 엔진을 실행했다. 자료와 전송은 메모리의 합성 값만 사용하며 원격 서버·회원 계정에 연결하지 않는다.

- 연습 기록 생성→저장 통신 실패→미전송 기록 안내→연결 복구→직접 재시도→저장 완료를 확인했다. [실패 화면](round2-offline-390.png), [완료 화면](round2-synced-390.png).
- 실제 `client.mjs`를 묶어 설정 조회 503→‘연결 다시 확인’→설정 재조회 성공을 확인했다. 두 번째 합성 설정은 의도적으로 미등록 상태여서 준비 전 안내가 나타난다. 로그인 성공을 검증한 것이 아니다. [재시도 입구](round2-client-retry-390.png).
- 320·390·1280px DOM에서 가로 넘침이 없고 이미지 누락 0. 390px은 실제 캡처로 확인했으며 1280px은 DOM 측정만 완료했다. 검수 화면 콘솔 오류·경고 0. 임시 viewport 설정은 복원했다.
- 캡처 도구의 기본 배율 문제가 있어 CDP의 명시한 390×844 영역으로 다시 캡처했다. 잘못된 중간 캡처는 최종 증거로 쓰지 않는다.

합성 서버 재실행: 저장소 루트에서 `node docs/_ops/qa/platform-account-audit-20261008/round2-browser.mjs`, 브라우저 `http://127.0.0.1:4328/`. `/client.html?product=platform`의 첫 설정 요청만 503이며 서버를 다시 시작하면 초기화된다.

## 남은 범위

공개 반영과 설치본 갱신, 그 판본에서 실제 회원의 로그인·저장·충돌·종료 확인은 별도 출시 단계다. 기존 실물 PC↔휴대폰 왕복 검증 보류를 유지한다. 웹 바로가기를 계정에 동기화하거나 다른 앱의 개인 기록을 플랫폼 홈에서 수집하는 기능은 추가하지 않았다.
