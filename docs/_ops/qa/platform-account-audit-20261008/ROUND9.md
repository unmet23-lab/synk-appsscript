## 저장 응답 유실과 두 작성자의 충돌

실제 `createDocumentSync`를 합성 메모리 서버·저장소에 연결해 다음 경로를 별도로 확인했다. 이 범위에서는 추가 결함을 찾지 못했고 소스를 변경하지 않았다.

1. A 기록은 서버에 저장됐지만 응답이 끊김 → 화면은 저장 완료로 확정하지 않고 미전송 원문 보존.
2. B가 수정 → 충돌 안내 → B가 명시적으로 자기 기록을 선택한 뒤 저장.
3. A 재시도 → 다시 충돌, B 기록을 자동으로 덮지 않음.
4. A가 서버 기록을 선택 → B 기록 표시, A 원문 바이트는 임시기록과 복구 파일에 유지.

[재실행 스크립트](round9-lost-ack.mjs) · [결과 JSON](round9-lost-ack-proof.json). 서버 revision 2·저장 시도 4회, 외부 요청 0. 단위 테스트 수에 합산하지 않는다. 실제 두 브라우저나 두 실물 기기를 사용한 검증과 구분한다.

## 브라우저 확인

[루프백 QA](round9-browser.mjs)는 실제 가족 앨범 화면과 공통 계정 연결기에 합성 브리지를 붙이고 검수용 저장소를 분리한다. 운영 로그인이나 회원 자료를 사용하지 않는다.

- A 연결 실패 → **계정 연결 다시 확인** 대기 → **로그아웃** → B 인증 → 늦은 A 오류 완료.
- B의 기록과 **계정에 저장했어요** 안내가 이전 오류 전후 동일함을 확인. 이 안내는 합성 서버에서 읽은 B 저장본의 상태이며 이번 시나리오에서 새 쓰기는 0회다.
- B 이야기 상세 화면과 320·390·1280px에서 가로 넘침 없음. 수집 콘솔 오류·경고 0건.
- [화면](round9-account-isolation-1280.png) · [검증 값](round9-browser-proof.json).

`node round9-browser.mjs --guest`는 4329에서 기기 저장 완료를 지연시키는 합성 저장소를 사용한다. 실제 앱의 저장·로그인 전환·로그아웃 화면을 실행하며 실제 IndexedDB 지연을 유발한 검증은 아니다.

- 기기 보관 켜기 → 이야기 작성·저장 대기 → 합성 계정 로그인 → 기기 저장 성공 → **로그아웃**.
- 로그인 중에는 계정 기록을 유지하고 계정 쓰기는 0회. 로그아웃 뒤 최신 이야기 제목·본문·작성자 및 기기 보관 선택을 복원했다.
- 최종 수정본에서 320·390·1280px 가로 넘침 없음, 수집 콘솔 오류·경고 0건. [최신 기기 앨범 복원 화면](round9-guest-restored-1280.png) · [검증 값](round9-guest-browser-proof.json).

마지막 공통 계약 변경 후 A→B 전환을 다시 실행해 늦은 오류 전후 화면 동일함을 확인했다. 두 서버가 제공한 앱·공통 수첩·계정 연결기 3개씩은 [현재 원본과 바이트·해시 6/6 일치](round9-served-source.json)를 확인했다. 검수용 IndexedDB 삭제 완료와 임시 탭·4328/4329 서버 종료를 확인했으며 사용자 공개 플레저 탭은 유지했다.

실제 회원 인증·운영 저장·실제 녹음 장치·물리적 PC↔휴대폰 왕복·공개 반영은 이번 검증에 포함하지 않는다. 기존 실물 검증 보류를 유지한다.
