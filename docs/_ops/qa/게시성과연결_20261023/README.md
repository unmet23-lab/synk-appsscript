## 이후 게시가 끝났을 때

작업실 예약의 완료 결과는 `tools/작업실예약.js 상태 <편 폴더>`가 기존 `게시/게시결과.json`에 편ID·계정·작업ID·원고ID·플랫폼·게시물ID·주소를 함께 남긴다. 다른 작업ID의 결과는 덮지 않는다.

브라우저에서 게시하거나 예약한 뒤 URL이 생기면 **정확한 계정·원고·주소를 확인**하고 연결 목록을 만든다. 목록은 아래 모양의 배열이다. `편`은 `docs/마케팅/` 바로 아래 폴더 이름이고 `근거`는 실제로 읽은 저장소 상대 경로다.

```json
[{"주소":"실제 공개 주소","편":"기존 편 폴더","계정":"sns-계정.json의 키","구분":"콘텐츠","이유":"계정·원고·주소 확인 근거","근거":["docs/마케팅/기존 편 폴더/게시/게시글.md"]}]
```

`node tools/게시성과.js --연결목록 <목록.json>`으로 먼저 확인하고 `--실행`을 붙여 기록한다. 서버 등록이 없거나 계정이 다르면 멈춘다. 기존 연결을 다른 편으로 정정할 때만 목록에 `정정: true`를 명시한다. 같은 URL은 같은 게시물ID로 취급하므로 Instagram `/p/`와 `/reel/` 차이로 중복 기록하지 않는다.

같은 계정·같은 시각이라는 이유만으로 새 주소를 붙이지 않는다. 구분은 `콘텐츠`, `작품`, `운영시험`, `공개확인대기`다. 마지막 세 가지는 비교 표본에서 빼고 요약 하단에서 계속 보여 준다. 예약 URL을 연결해도 기존 `예약됨` 상태와 예약 시각은 유지한다. 같은 편의 다른 게시물은 `추가게시`에 보존하므로 기존 판을 덮지 않는다.
