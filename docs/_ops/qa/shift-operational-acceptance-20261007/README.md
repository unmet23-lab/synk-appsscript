# SHIFT 운영 인수와 고객 실증 준비

> 2026-10-07 후보의 준비·검증 이력이다. 아래 고정 모델·최대 추론 최종 검수 조건은 당시 작업 기록이며, 10-10 이후의 공통 선행 조건이 아니다. 새 작업은 [현행 AI 운영 원칙](../../../AI_운영원칙.md)과 현재 사용자 요청을 따른다.

2026-10-07. 사용자는 운영 검증, 첫 고객 한 업무의 효과·원가 측정, 두 번째 고객의 반복 공급 검증을 함께 진행하도록 요청했다. 실제 회사 서버·운영 환경·두 고객과 업무를 확인한 질문에는 **모두 미정**이라고 답했다. 이 기록은 지금 실행 가능한 보호·측정 도구와 로컬 검증을 완료한 결과이며 실제 배포·고객 실적이 아니다.

## 10-07 당시 실행 환경의 상태

기존 `127.0.0.1:4191`은 준비 완료 응답을 내지만 동기화 스크립트 요청은 404다. 공개 실습 스크립트 한 개의 해시만 현재 원본과 일치하며 서버 전체 판본은 일치를 입증하지 못했다. 기존 서버를 이번 후보의 운영 완료로 기록하지 않는다. `127.0.0.1`은 이 PC 안의 주소이고 실제 휴대폰의 공유 접속 주소가 아니다.

Docker·Podman은 없고 WSL의 Linux 배포판도 없다. 따라서 실제 Linux 이미지 빌드·컨테이너 실행은 미검증이다. 공식 Claude CLI는 버전만 확인했고 필수 검수는 실행하지 않았다. 당시에는 공개 전 Claude Opus 5.5 최대 추론 검수를 준비했으나 실행하지 않았다. 현재의 담당·검증 범위는 [AI 운영 원칙](../../../AI_운영원칙.md)과 사용자 요청을 따른다. 이후 회사 서버의 운영 상태는 [회사 운영 원문](../../../마케팅/온라인마케팅지도/engagement/company/CLOUD-OPERATIONS.md)에서 확인한다.

## 첫 고객을 정하면 실행할 순서

1. 실제 서버·HTTPS 주소·영구 데이터·운영 담당과 점검 시각을 정한다. 회사 두 DB와 원래 키·등록 로컬 첨부·계정 연결을 함께 유지한다.
2. 새로 정한 실행 대상과 현재 요청에 맞는 검증을 완료하고 실제 실행 환경에서 빌드·영구 저장·로그인/콜백을 확인한다. 반영 직전 쓰기를 중지하고 기존 도구로 최신 기준 백업을 별도 보존한다.
3. [복구 인수 도구](recovery-README.md)로 후보와 별도 최신 기준을 대조하고, 격리한 환경의 로그인·본인 기록·최신 수정·삭제 유지·재시작을 확인한다. 이후 실제 PC/휴대폰 왕복·충돌·끊김·삭제·계정 전환을 확인한다. 현재 실물 검사는 미실행이다.
4. 실증 계산표의 `업무범위`에서 고객1의 한 업무·완료 결과·비교그룹·버전·측정 기간·성공/실패/중단·인수/지원·자료 권한을 먼저 정한다. 가격·기간·합격 기준은 현재 미확정 입력이다.
5. 같은 조건의 기존 방식과 개인화 방식을 시행별로 기록한다. 실패·중단, 미측정·제외, 시간/오류/사람 전환의 측정 누락을 구분한다. 단순 전후 차이를 인과효과로 확정하지 않는다.
6. 자료 정리·도입·검수·수정·영업·지원·대표 시간과 모델·서버·저장·외주·공통비 배분까지 기록한다. 대표 시간 단가와 누락 비용이 미정이면 전체 원가 완료와 수익성 판단을 보류한다.
7. 고객2에 같은 능력·모듈을 적용하고 버전·변경 사유·기존 고객 적용·인수 근거와 해당 원가를 연결한다. 두 업무의 규모·조건·지원 차이도 비교한다. 반복 공급의 품질·작업시간·원가가 확인된 뒤 API·라이선스 확장을 판단한다.

## 복구의 정확한 경계

복구 대조 도구는 기준과의 일치를 검사하며 기준이 실제 최신인지 독립적으로 증명하지 않는다. 같은 과거 사본끼리도 일치할 수 있다. 쓰기 중지·최신 기준 확인은 실제 운영 근거로 확보해야 하며 성공 결과도 `productionTrafficAllowed=false`다.

과거 백업이 최신 기준과 다르면 자동 병합·삭제 재적용을 하지 않는다. 이후 수정·삭제를 해결할 근거가 없으면 운영 인수를 완료하지 않는다. 준비 폴더의 `PREPARATION_INCOMPLETE`는 작업상태 표식이며 현행 서버의 자동 접속 차단 장치가 아니다. 실제 네트워크 격리는 운영 환경에서 유지한다.

원래 키 누락의 시작 거부는 기존 DB를 보호하지만 다른 유효한 길이의 키가 원래 키인지는 별도 대조·복호화 확인이 필요하다. 코드 롤백 때도 최신 DB와 맞는 원래 키를 유지한다.

## 미실행과 미확정

이 10-07 준비 시점에는 운영 서버·HTTPS·데이터 위치, 첫 고객·두 번째 고객·업무가 미정이었다. 회사 내부 서버의 이후 구축을 외부 고객 실증 완료로 바꾸지 않는다. 실제 운영 DB 쓰기·백업/복구·서버 재시작·외부 배포·필수 공개 검수·실계정 로그인·물리적 두 기기·실고객 시행·매출·효과·수익성 측정은 미실행이다. 유료 AI·신규 결제·설치·고객 연락·커밋·push도 하지 않았다. 준비한 도구와 빈 계산표를 실제 운영 또는 판매 실적으로 쓰지 않는다.
