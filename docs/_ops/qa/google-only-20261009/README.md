# Google 로그인·가입 로직 · 문자 서비스는 출시 전 · 2026-10-09

사용자 「일단 구글로그인 로직이랑 기능만 만들어줘. 문자서비스는 나중에 출시직전에 할게」에 따른 **로컬 구현**이다. 운영 제공자·키·계정·공개 포털·설치본은 변경하지 않았다. 실제 Google 로그인 완료나 출시 완료를 뜻하지 않는다.

## 현재 흐름

Google로 계속하기 → Google 인증·복귀 확인 → 국가·만 나이·성별·개인정보 안내 확인 → 내부 SYNK 계정 생성 → 내 계정 또는 처음 요청한 런처 연결로 이어진다. 별도 아이디·비밀번호가 없고 성별 ‘응답하지 않음’을 선택할 수 있다. 학습 기록 저장은 별도 선택이며 기본 꺼짐이다. 기존 회원은 기존 SYNK 계정에 Google을 명시적으로 연결해 ID와 기록을 유지한다.

문자 인증 연기는 서버에서만 정한다. 중앙 `synk-account`의 환경 설정 `SYNK_GOOGLE_PHONE_VERIFICATION`이 정확히 `deferred`일 때만 연기하며 누락·다른 값은 기존 인증 필수 방식이다. 인증된 가입 조회는 `registration.phoneVerificationRequired`를 돌려주고 프런트엔드는 정확한 boolean false만 채택한다. 공유 공개 설정과 완료 요청에 우회 옵션을 추가하지 않았다.

연기 모드에서는 휴대폰 필드와 문자 요청을 사용하지 않는다. 서버는 실제 Google 인증과 국가·나이·성별·개인정보 확인을 검증한다. 실제 Auth의 번호 인증 증거가 없는 가입은 `phoneVerified:false`, `phoneVerificationDeferred:true`이며 인증 시각이 없다. 실제 증거가 있으면 그 성공 상태와 시각을 유지한다. 국가·나이·성별은 비공개 가입 정보이고 앱 프로필·Atlas 요약에 자동으로 섞지 않는다.

가입 재시도는 기존 ID·학습 선택·기록을 덮지 않는다. 계정 변경·로그아웃 뒤 늦게 끝난 가입/OTP 응답은 다음 계정을 이어 주거나 화면을 바꾸지 않는다. 이전 서버의 정책 키가 빠져도 기존 엄격 문자 인증 경로를 유지한다.

## 검증

- FE 관련 시험 **150/150 통과**: [실행 로그](auth-final.tap). 실제 포털의 문자 없는 가입과 가입 뒤 최초 런처 요청 자동 연결, 서버 정책 누락/위조형 값, 입력·동의 검증, 계정 전환 뒤 늦은 완료 차단을 포함한다.
- BE 관련10개 시험 **118/118 통과**: Google 등록23개 중 기존 엄격14개·신규 연기9개를 포함한다. 실제 PostgreSQL 마이그레이션·직렬화와 기존 계약 회귀를 확인했다. [서버 증거](backend-evidence.json), [실행 로그](backend-final.tap). 인증 원문과12개 소비처가 사용하는 생성 runtime5개는 바이트가 동일하다.
- 실제 Chromium **9개 시나리오 통과**, 화면12장: 320·390px 문자 연기 가입, 320·390·1280px 기존 엄격 가입·Google 비활성, 저장소 오류에서도 이메일 로그인. [결과](browser/result.json), [화면 확인](browser/visual-review.json).
- 실제 앱 진입점과 설치 Supabase SDK **2.117.2**의 합성 HTTP 경로: Google PKCE·nonce/verifier → 문자 없는 가입 POST1회 → 동일 SYNK ID 화면. 휴대폰 변경 PUT·OTP POST는 **0회**다. [결과](sdk-browser/result.json), [화면2장 확인](sdk-browser/visual-review.json).
- 브라우저의 새/변경9장을 직접 보고, 기존 검수본과 동일한5장은 PNG SHA로 연결했다. 모든 요청은 로컬 바이트·합성 응답으로 처리하거나 차단했다. 실계정·실Google·SMS·운영DB 요청은0이다.
- 동결한 로컬 소스·앱 번들·시험·화면의 바이트 대조는 [후보](candidate-manifest.json)와 [최종 대조](final-integrity.json)에 둔다. 공유 dist를 만들지 않는다.

이전 문자 인증 필수 후보와 공식 검수는 [이전 기록](../google-signup-20261009/README.md)에 보존했다. 이번 로컬 변경을 이전 공식 검수의 통과 범위로 확대하지 않는다. 공용 전체 시험에서 확인된 별도 플랫폼 URL 기대값 실패5개도 이번 관련 시험 통과로 덮지 않는다.

## 실제 사용과 출시 전 단계

실제 Google 사용에는 OAuth Client ID/Secret과 제공자·기존 회원 연결 설정, 정확한 운영 후보 검수·반영 및 실제 로그인/동일 ID 확인이 필요하다. 이번 작업은 이를 실행하지 않았다.

문자 서비스 가입·결제·발신 수단·실문자 검증은 출시 직전으로 미룬다. 기존 개발 가입자의 동일 ID에 번호 인증을 추가하는 경로와 모든 회원 앱의 출시 시 인증 제한도 그 단계에서 구현·검증한다. **설정을 다시 인증 필수로 바꾸는 것만으로 기존 개발 계정이 제한되지는 않는다.** 공통 원문을 동봉한 회원API10개·cleanup2개는 운영 반영 때 정확한 후보에서 함께 묶고 검수한다. 현재 generated runtime은 변경하지 않았다.

이전 [Google·SMS 설정 조사](../google-signup-20261009/GOOGLE-SMS-SETUP.md)와 [서버 소비처 목록](../google-signup-20261009/SERVER-CONSUMERS.md)은 출시 준비 참고 자료다. 사용자에게 문자 사업자 선택을 다시 요청하거나 문자 준비를 이번 로직 완성의 조건으로 삼지 않는다.
