# 발주 — Prism 비공개 산출 점검을 이해대장에 연결

> 판 v2 · 2026-09-09. 별도 발주 검토에서 확인한 범위 누락(화면 생성기와 기존 래칫 시험)을 보완했다. 인계_GPT자율주행_0908.md §5-1을 잇는다. 이번 완료 범위는 U0 점검 통로다. 집계 생산자·U4 출제 가중·U8 강사 카드는 아직 구현하지 않는다.

## 목표

기존 이해대장은 외부 JSONL 파일을 손으로 연결해야 산출을 잰다. 비공개 버킷을 읽어 **원문을 파일·로그에 남기지 않고 건수와 고정된 거절 사유만** 저장하는 내부 소비자를 세운다. 이해대장은 그 점검 기록을 읽는다. 명부의 허용과 실제 소비자를 같은 변경에 넣는다.

설계에서 정한 보관처는 learner-media/prism/까지다. 실제 산출 객체 이름·생산 주기는 아직 확인되지 않았다. 이름을 꾸미거나 없는 장부를 빈 장부로 만들지 않는다. 이번에는 명시적 갱신 명령 한 번 → 숫자 기록 → 대장 생성의 통로를 닫는다. 자동 예약·생산자 주기 연결과 실제 원격 왕복은 별도 미완으로 남긴다.

## 수용 기준

1. `tools/lib/prism산출요약.js`는 JSONL 문자열을 받아 기존 `tools/lib/prism계약.js`의 `검증(행)`으로 집계하는 순수 함수 `집계(내용)`와 저장된 점검 기록을 엄격히 검증하는 `기록검증(기록)`을 내보낸다. 기록검증 반환은 boolean 하나다. 집계에 문자열 아닌 값이 오면 입력을 담지 않은 고정문 TypeError를 던진다. 원문 검증 계약은 수정하지 않는다. 집계 반환은 `{입력, 완비, 거절, 사유}`뿐이며 사유는 `{고정사유이름: 정수}`다. 빈 줄 제외, 파싱 실패는 거절과 줄깨짐에 포함, 한 행의 여러 사유를 모두 센다. 입력은 변경하지 않는다.
2. 기존 `prism대장절.js`의 외부 파일 집계도 위 집계 함수를 쓴다. 세는 로직을 두 곳에 남기지 않는다. 환경변수 `SYNK_PRISM_산출`의 기존 우선순위와 빈 장부·읽기 실패·완비/거절 표시 의미는 유지한다. 원문·행 값은 내보내지 않는다.
3. 새 점검 기록의 허용 키는 `판`, `상태`, `측정시각`, `입력`, `완비`, `거절`, `사유`뿐이다. 판은 1, 상태는 `측정`/`미설정`/`실패` 중 하나, 측정시각은 유효한 UTC ISO 문자열 또는 null이다. 측정이면 시각과 비음수 안전 정수인 세 건수가 필요하고 입력=완비+거절이어야 한다. 미설정·실패에서는 세 건수는 null, 사유는 빈 객체다. 초기 미설정만 측정시각 null을 허용한다. 실패에도 시도 시각을 기록한다.
4. 기록검증은 알려지지 않은 키(최상위와 사유 모두), 잘못된 판·상태·시각·음수·소수·안전 정수 초과·사유 건수>거절·수 합계 모순을 거절한다. 허용 사유는 기존 계약이 실제로 반환하는 사유와 줄깨짐으로 제한한다. 검증 실패에는 입력 원문·임의 키·값을 출력하지 않는다. 거절>0이면 사유 건수 합계가 거절 이상이어야 하며 거절=0이면 사유는 비어 있어야 한다. 사유마다 분모는 거절이다.
5. `tools/prism산출동기화.js`는 CLI와 시험 가능한 비동기 함수 `prism_산출점검({객체, ref, 키, fetch구현, 시계})`를 내보낸다. require만으로 파일 쓰기·환경 로딩·네트워크가 일어나지 않는다. 함수는 `{종료코드, 기록}`만 반환하고 원문·URL·키·객체 경로·서버 응답·오류문·입력 행을 반환하지 않는다.
6. 함수의 객체는 `prism/` 아래 `.jsonl` 파일 한 개의 상대 경로다. 비어 있음, 절대경로, 역슬래시, 빈 토막, `.`·`..` 토막, 제어문자, `%`, `?`, `#`는 요청 전에 거절한다. ref는 소문자 영문·숫자 20자로 제한하고 키는 비어 있지 않은 문자열이어야 한다. 객체 미지정은 미설정, 그 밖 잘못된 구성은 실패다. 구성 실패 시 네트워크 호출 0회다.
7. 요청 주소는 검증된 ref로 조립한 `https://<ref>.supabase.co/storage/v1/object/authenticated/learner-media/<토막별 encodeURIComponent 객체>` 하나뿐이다. GET 한 번, Authorization Bearer 및 apikey 헤더, redirect:error, 30초 제한을 적용한다. 임의 URL·공개 URL·서명 URL·업로드·삭제·DB 변경·자동 재시도는 없다. fetch구현은 시험 주입용이며 기본값은 globalThis.fetch다.
8. 응답은 최대 8MiB까지만 메모리에서 읽고, Content-Length만 믿지 않는다. 스트림을 세면서 초과하면 취소하고 실패한다. 다운로드 도중 실패·시간 초과·잘못된 UTF-8·HTTP 비성공·404·리다이렉트 모두 실패 기록이다. 404를 0행으로 세지 않는다. 응답 본문과 Error.message는 로그·기록에 남기지 않는다. 응답 HTML은 JSONL 집계 전에 MIME으로 거절하되 JSONL·JSON·plain text·octet-stream과 MIME 미제공은 허용한다.
9. 성공 응답을 집계해 상태 측정 기록을 만든다. 입력>0이며 거절=0이면 종료코드 0, 거절>0이면 1이다. HTTP 성공의 빈 내용은 측정/입력0/완비0/거절0이되 종료코드 2이고 화면에 초록을 주지 않는다. 미설정·실패도 종료코드 2다. 기록검증에 실패한 반환을 저장하지 않는다.
10. CLI 인자는 `--출력 <숫자 점검 기록 경로>` 및 `--help`만 받는다. 기본 출력은 해당 저장소의 `docs/_ops/prism_산출점검.json`이다. CLI 입력 오류는 쓰기 없이 종료코드 2다. 객체 이름은 `SYNK_PRISM_OBJECT`에서만 읽고 비어 있으면 자격증명 파일도 열지 않고 미설정 기록을 쓴다. 객체 이름·키를 명령 인자에 받지 않는다.
11. 객체가 지정된 CLI만 기존 `.claude/hooks/lib/형제저장소.js`의 `형제경로()`로 talk을 찾고 `lib/자격증명.js`의 `파일읽기()`로 기존 ENV파일을 읽는다. process.env가 파일 값보다 우선한다. 프로젝트 ref는 SUPABASE_PROJECT_REF, 키는 SUPABASE_SERVICE_ROLE 또는 SUPABASE_SERVICE_KEY만 사용한다. ANON 및 관리 API 토큰으로 대체하지 않는다. 누락·읽기 실패는 익명 실패 기록으로 처리한다. 기존 환경 파일·형제 저장소는 수정하지 않는다. 새 환경 파일·키 사본·새 패키지는 만들지 않는다.
12. CLI는 원문을 임시 파일에도 쓰지 않는다. 오직 검증된 점검 기록만 UTF-8 JSON으로 저장한다. 저장 성공 뒤 출력은 상태 및 완비/입력·거절/입력 또는 고정된 미측정 안내뿐이다. 출력 경로도 로깅하지 않는다. 실패 갱신이 과거 성공 기록을 그대로 남기지 않도록 실패 기록으로 교체한다. 쓰기 실패면 이전 기록이 남을 수 있음을 고정문으로 명시하고 종료코드 2다. 인접 임시 파일에 쓰고 원자적으로 교체하며 자신의 임시 파일만 정리한다.
13. 명부의 기존 학생·학부모 두 항목을 유지하고 `tools/prism산출동기화.js`만 내부로 추가한다. 사유는 원문 비보관·점검 건수만 전달하는 실제 내부 소비자라는 뜻이다. `엔진_콘텐츠AI.js` 및 아직 없는 강사 카드는 등록하지 않는다.
14. 래칫 기본 범위는 기존 `*.js`와 새 내부 소비자의 **정확한 경로 한 개**다. 하위 tools 전체를 열지 않는다. 기본 검사에 소비자가 실제로 포함되며 그 파일의 prism_산출점검 참조가 센 수에 잡혀야 한다. 명부에서 이 항목을 빼거나 학생으로 바꾼 임시 픽스처에서는 종료코드 1이어야 한다. 기존 뿌리 JS 검사·미등록 차단·경로 제한은 유지한다.
15. 대장 부품은 기존 SYNK_PRISM_산출이 없을 때 `루트/docs/_ops/prism_산출점검.json`을 읽는다. 동봉 검사에서 쓸 `SYNK_PRISM_점검기록` 파일 경로가 있으면 기본 경로보다 우선한다. 지정된 파일을 못 읽으면 기본값으로 돌아가지 않는다. 기록 없음은 안 재봤다, 읽기·JSON·기록검증 실패는 못 쟀다로 구분하고 원문·경로·자유문을 HTML에 넣지 않는다.
16. 유효한 측정 기록은 기존 산출 건수·완비/전체·거절/전체·사유를 표시하고 측정시각과 ‘이 기록은 표시된 시각의 점검 결과다’라는 뜻을 함께 표시한다. 현재 시각을 읽어 판정하거나 재생성 때 측정시각을 바꾸지 않는다. 미설정과 실패는 숫자를 0으로 채우지 않고 빨간 경고를 보여준다. 빈 산출은 기존처럼 ‘0행, 초록이 아니다’를 표시한다.
17. 화면 안내에 새로 점검하는 명령 `node tools/prism산출동기화.js`와 이어 대장을 그리는 명령 `node tools/이해대장.js`를 쓴다. 두 번째가 첫 번째의 실패를 덮지 않도록, 새 점검 기록의 상태를 확인한다는 뜻을 적는다. 객체 설정과 자동 주기는 아직 생산자 연결 전이라는 사실을 명시한다. 이미 있는 디자인 CSS 변수만 쓴다.
18. 기본 점검 JSON은 초기 미설정 기록이다. 합성 숫자를 실측처럼 저장하지 않는다. 실제 비공개 버킷 객체는 이 발주에서 읽지 않는다. 외부 호출 시험은 모두 메모리의 가짜 응답으로 한다.
19. 대장동봉검사의 방아쇠에 새 요약 모듈과 기본 점검 JSON을 각각 한 번씩 추가한다. 명부·부품은 이미 있으므로 중복 추가하지 않는다. 입력 수를 ‘새 파일 몇 개뿐’이라는 식으로 제한하지 말고 생성기가 실제로 읽는 새 입력을 확인한다.
20. 동봉 검사는 점검 JSON의 커밋될 판을 기존 명부와 같은 방식으로 임시 파일로 넘긴다. 다만 색인에서 삭제·HEAD에도 없음은 작업본으로 되돌아가지 않도록 **존재하지 않는 임시 경로를 명시**한다. 부모의 SYNK_PRISM_산출 및 SYNK_PRISM_점검기록을 제거하고 커밋될 점검 기록 경로만 넘겨, 외부 원문 환경이 커밋 검사에 실리지 않게 한다. 기록의 색인/HEAD/삭제/부재를 각각 재는 회귀를 붙인다. 기존 명부 게이트의 의미는 바꾸지 않는다.
21. docs/이해대장.html을 새로 생성하여 같은 커밋에 담는다. 시험은 SYNK_대장_산출 임시 경로를 사용하고 실물 HTML·점검 기록을 변경하지 않는다. 점검 기록 없는 경우·초기 미설정·성공·전량거절·0행·실패·깨진 JSON·알 수 없는 사유·HTML 조각을 임시 픽스처로 검증한다.
22. 새 테스트는 ①정상 응답 ②계약 거절 ③빈 응답 ④404/인증실패 ⑤리다이렉트 옵션 ⑥타임아웃/스트림 실패 ⑦크기 초과 ⑧경로 우회 ⑨거짓 길이 헤더 ⑩원문/키/URL/오류문 비노출 ⑪성공→실패 갱신 ⑫기록 스키마 오염 ⑬명부 누락/학생 갈래 변경 ⑭동봉 판 선택을 실제 입출력으로 잰다. 비식별 합성 자료만 사용한다.
23. 원문 비노출 시험에는 정상 행의 값과 부가 키, 깨진 JSON, 예외문에 서로 다른 임의 센티널 문자열을 넣고 반환 객체·표준출력·표준오류·생성 JSON·생성 HTML 어디에도 나타나지 않음을 확인한다. 실패를 출력에서 숨기는 대신 고정된 실패 상태가 남아야 한다.
24. 사용자 코드 경로·라이브 기능은 바꾸지 않는다. 이번 완료를 ‘출제 가중 적용’이나 ‘강사 전달’로 보고하지 않는다. 실행자 보고에 모였나=숫자 점검 기록, 닿았나=이해대장, 늘었나=U0의 내부 점검 소비자, 누구에게=원장이라고 범위를 적고, 실제 원격 객체·생산 주기·자동 예약·U4/U8은 남긴것에 명시한다.
25. `tools/이해대장.js`의 Prism 부품 require/절 호출을 둘러싼 기존 catch는 오류 메시지 대신 고정된 ‘Prism 점검 결과를 만들지 못했다’ 안내를 내도록 고친다. 부품을 불러오다 발생한 예외도 HTML 비노출 시험의 범위다. 해당 파일의 다른 절은 수정하지 않는다. 기존 부품 예외 시험은 오류문 표시 단언을 고정 안내 표시·센티널 비노출 단언으로 바꾼다.
26. 기존 래칫 시험의 기본 뿌리 픽스처에는 참조가 없는 새 기본 소비자 파일을 추가하고, **기본 범위를 쓰는 시험만** 실제 범위 증가에 맞게 파일 수 기대치를 조정한다. `tests/prism계약.test.js`의 원문 계약 시험(현재 26~152줄)은 변경하지 않는다. 이 파일의 허용은 래칫 픽스처와 그 영향으로 변한 파일 수 단언뿐이다. `tests/prism래칫회귀.test.js`도 같은 한정이다. 명시 범위만 검사하는 시험에 일괄 +1하지 않는다. 새 필수 기본 파일이 없으면 확인 불가여야 하며, 이를 건너뛰어 초록으로 만드는 수정은 금지한다.
