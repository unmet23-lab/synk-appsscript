## 재현한 문제

### W01 · 직원 소속의 중복 정본 — 통합 전에 해결

진행 중인 직원 관리 작업은 `memberOrganization.brands`를 저장하고, 별도 회사별 초대·기능 작업은 `users.workspaceProfile.memberships`로 메뉴와 접근 가능한 기능을 계산한다. 두 작업본의 `organization.mjs`, `server.mjs`, `public/app.js`, `public/workspace.js`, `public/index.html`, 메뉴 시험이 겹친다.

두 실제 함수를 메모리 저장소의 합성 직원에 적용했다. 접근 프로필은 `LAB/teacher`, 직원 목록의 브랜드는 `PULSE`로 저장할 수 있었으며 결과는 **직원 목록 PULSE / 접근 소속 LAB / 제공 기능 teaching**이었다. 현재 라이브에서 발생했다고 확인한 오류가 아니라, 두 미배포 구현을 함께 사용할 때의 불일치 재현이다. 한쪽 저장이 다른 쪽을 갱신하거나 검증하지 않는다.

**통합 계약:** 소속과 회사별 역할의 정본은 초대·권한 프로필 하나로 두고 직원 목록은 같은 값을 읽는다. 직원 목록 전용 정보는 자유 형식 업무 역할·맡은 일로 제한한다. 소속 변경은 기존 권한 변경 절차로 연결하며, 단순 업무 설명 저장으로 접근 권한을 바꾸지 않는다. 기존 팀·개별 자료 권한과 미배정 계정 처리도 유지한다. 직원 명부 쪽 코드는 이 계약으로 수정했다. 소속을 별도 저장하는 입력을 거절하고, 권한 프로필 변경이 목록에 바로 반영되는 회귀 시험을 통과했다. 두 채팅의 담당 범위를 서로 바꾸거나 남의 미커밋을 합쳐 배포하지 않았다. 후속으로 초대·권한 원격 소스 `27c9602b38`을 포함한 `11804d505`와 합쳤고, 관리자 소속 수정→직원 명부 갱신을 실제 격리 브라우저에서 확인했다. 운영 배포는 두 기능의 배포 관문을 별도로 충족해야 한다.

### W03 · 상태 점검기가 실제 중첩 Git 폴더를 거절 — P2

[`tools/worktree-hygiene.js`](../../../tools/worktree-hygiene.js) 113~135줄은 경로를 `/`로 나눴을 때 빈 조각을 거절한다. Git은 `--porcelain=v1 -z --untracked-files=all`에서도 중첩 저장소를 `?? nested-repo/\0`으로 반환할 수 있다. 현재 공용 작업본 안의 `.codex/worktrees` 네 폴더가 정확히 이 형태다.

정식 `node tools/worktree-hygiene.js --json`은 `status: incomplete`, `reason: invalid-output`, 집계 null을 반환했다. 단일 합성 레코드 `?? nested-repo/\0`도 같은 실패다. 관찰기가 현재 작업본을 제대로 보고하지 못하는 문제이며 파일 삭제·Git 손상을 뜻하지 않는다. 고침은 **미추적 디렉터리 레코드만 허용하고 절대 경로·상위 경로 거절은 유지**, 파일 개수와 디렉터리 항목 수를 구별하는 것이다.

### W05 · 설치 측정 도구의 교차 드라이브 하드링크 — P2
