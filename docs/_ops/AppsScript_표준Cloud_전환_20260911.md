## 원격 인증·검증 경과

1. 사용자가 Desktop App 로그인 클라이언트 JSON을 다운로드했다. 새 표준 프로젝트·유형·localhost 콜백을 비밀값 출력 없이 검증하고 저장소 밖 전용 인증 폴더로 이동·바이트 동일성을 확인했다. 사용자 승인 뒤 **별도 clasp 로그인·계정 확인 완료**. 인증 URL 준비만으로 브라우저가 보인다고 안내했던 부분은 사용자 미표시 보고 뒤 정정했으며, 기존 요청이 실제 성공한 것을 확인해 중복 로그인하지 않았다.
2. 저장소 밖 전용 인증 폴더에 라이브와 같은 10개 권한의 인증용 매니페스트를 준비했다. 별도 `--auth` 파일과 `--user synk-appsscript-prod`를 함께 사용해 기본 clasp 로그인과 분리한다. 설치 clasp의 Windows 경로 구분자 오탐을 읽기 전용으로 재현해, 정규 Windows 경로로 바꾸고 권한 10개를 확인했다. 보호 검사를 끄지 않았다. 이 폴더에서 push/pull/deploy하지 않는다. 실제 로그인 명령·계정은 개인 런타임 README에만 둔다.
3. 원격 `rarityOf`의 실제 `response:1` 확인 완료. 함수는 메모리 상수에서 기본값 1을 반환하며 학생 표·메일·외부 API를 읽거나 쓰지 않는다.
4. `aiText_` 최소 합성 요청은 새 인증에서도 Google 실행 단계에서 거절됐다. 순수 계산 함수 `grammarStageOf_`도 HTTP 403 `PERMISSION_DENIED`였고 실제 토큰의 필요 권한은 모두 있었다. 비공개 함수 진입 제한과 부합하는 관측이며, Anthropic 거절·잔액 부족으로 단정하지 않는다. 이 두 원격 시도를 Anthropic 성공으로 세지 않는다.
5. 나머지 12종은 전환 후 실제 실행 미확인이다. 이미 완료한 1종과 구분하며 검증만을 위해 실업무 배치를 일괄 수동 실행하지 않는다.

Apps Script의 별도 Speech 받아쓰기는 전용 서비스계정 속성 부재·기존 권한 범위 문제로 원래부터 실제 가동 미확인이었다. 이번 전환으로 고쳤다고 보지 않으며 결제·Speech 권한을 임의 추가하지 않았다. Talk 키 통일은 후속 승인으로 완료했으며, 최신 품질판 배포·옛 키 폐기 판단 등은 [최신 검증 결과](AI_자동화_키통일_20260911.md)의 잔여를 따른다.

## 소유자 전용 연결 점검

- `엔진_계정점검.js`의 `aiConnectionCheck`는 인수를 받지 않는 고정 합성 점검이다. 활성 사용자·실행 계정·기존 `ADMIN_EMAIL`이 모두 일치해야 키와 통신에 접근한다. 익명·다른 계정·신원 확인 예외는 즉시 차단한다.
- 리허설 만료 속성이 빈 값으로라도 존재하면 수정·삭제 없이 중지한다. 고정 Anthropic Messages 주소, 현행 `AI_FEEDBACK_MODEL`, 출력 128토큰, 사고 꺼짐, HTTP 리디렉션 금지, 호출당 최대 1회·재시도 없음이다. 예약·자동 호출자는 추가하지 않았다. 소유자가 다시 실행하면 다시 과금될 수 있으며 총비용 상한 장치는 아니다.
- 학생 표·학생 문장·메일을 읽거나 쓰지 않는다. 실제 응답 모델·유한 숫자 토큰·합성 정답 일치 여부만 반환하며 키·원문 응답·사용자 이메일·오류 본문은 반환하거나 로그에 남기지 않는다. 결제 조직 헤더를 확인하는 기능은 아니다.
- 합성 보안 시험 24/24, 반출 경로 등록까지 관련 37/37 통과. 독립 검토도 실제 파일·모의 시험 24/24에서 수정이 필요한 결함 없음. 실제 다른 Google 계정·익명 실행은 별도 미확인이다.
- 첫 전체 CI 모사는 새 반출 경로 등록 누락·기존 주석 수 불일치를 발견해 함께 고쳤다. 같은 런에는 다른 작업의 기록 파일 변경 경고도 있었다. 다른 IG 작업·원격과 갈라진 로컬 Git 이력을 덮지 않도록 `origin/master` 기반 전용 worktree에서 이번 파일만 재검증한다.
- 전용 worktree의 전체 CI 첫 회차는 기존 상태 관측 시험의 1.7초 제한에서 1건 실패했다. 관련 3파일을 같은 UTC·빈 홈 환경으로 집중 재검증해 72/72 통과했고, 코드 수정 없이 전체 재실행도 **2,338건 중 통과 2,329·실패 0·skip 4·todo 5**였다. Windows 로컬 CI 모사 결과이며 원격 Linux CI와 구분한다. 배포 보안 검사도 통과했다.
- 기존 라이브 22파일을 Google 읽기 API로 재조회해 앞선 배포 자료와 **22/22 원문 바이트 동일** 확인. 메인 checkout 아래 별도 배포 자료는 그 22파일을 보존하고 점검 파일 추가·두뇌의 호출 수 주석만 변경한다. 다른 작업의 `상담AI.js`·`만족도팩.js` 변경은 이번 배포에 넣지 않는다.
- 코드·시험·전환 보고 5파일만 `dea2bf7913ed60265eb927683cd4838c75c5ed44`로 커밋하고 `origin/master`에 push했다. [대상 원격 CI 34527494194](https://github.com/unmet23-lab/synk-appsscript/actions/runs/34527494194)는 해당 SHA의 `syntax-check` 전체 성공이다. 기존 원격 CI 도구는 worktree 브랜치 이름으로 원격을 찾았으므로 master를 직접 조회해 SHA를 대조했다.

- 배포 후 Google API로 **HEAD와 고정 버전 48을 각각 재조회해 준비한 23파일과 23/23 원문 바이트 동일**, 추가·누락 0을 확인했다. 메인 전체 작업본과 동일하다는 뜻은 아니다. 메인 `배포판점검.js --라이브`는 다른 작업의 `상담AI.js`·`만족도팩.js` 미배포와 줄바꿈 차이, 원격에는 커밋했지만 메인 이력에는 아직 통합되지 않은 점검 파일을 표시했다. 이 차이를 없애려고 남의 변경을 함께 배포하지 않았다. crewcard는 HEAD·고정 34 모두 5/5 바이트 동일이며 이번 작업에서 배포하지 않았다.
