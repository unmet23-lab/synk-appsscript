## 0. 한 장 요약 — 세 문장

1. **엔진 코어 4부품(지식 그래프·학습자 모델·오류교정 말뭉치·게이트웨이)은 물리로 0개다.** `supabase/L0_스키마.sql` 전량에 그 테이블이 없다. 그래서 기능 문서의 「데이터 → 뇌」 칸은 **전부 계획이고 아직 배선이 아니다.**

## 3. 🔑 가장 중요한 발견 — 「자동이 아닌 것」이 옳은 자리가 하나 있다

`pushGoldenFixture_`(`엔진_수집.js:1177`)는 골든셋을 비식별 평가 픽스처로 조립해 SYNK-talk 저장소로 **실제로 보낸다**(v9.175). 그런데 `tests/수집.test.js:712`가 **배치에서 부르는 것을 회귀로 금지**한다:

> *"바깥으로 나가는 쓰기는 사람이 누를 때만 돈다 — 비가역 외부 쓰기가 승인 없이 도는 경로가 생긴다."*

이건 실수가 아니라 **CLAUDE.md 「비가역 외부 실행은 실행 직전 명시 승인」의 구현체**다. 유호님 새 지시와 정면으로 부딪치는 것처럼 보인다.

**부딪치지 않는다 — 두 규칙이 다른 층을 말한다.**

- 안전 규칙이 막는 것 = **저장소·시스템 밖으로 나가는 쓰기**(외부 발행).
- 골든셋이 거기 걸린 이유 = **엔진이 지금 다른 시스템에 살기 때문**(시트 → 남의 GitHub 저장소).
- 목표 구조에서 수집과 엔진은 **같은 Postgres 안**이다 → ⑥⑦은 외부 발행이 아니라 **내부 적재**(트리거·뷰)라 안전 규칙의 대상이 아니다.

**판정 2건**:
1. ⑥⑦을 뷰·트리거로 세우는 것은 안전 조항을 **어기는 게 아니라 피해 가는 것**이다.
2. 🚫 **골든셋의 손클릭은 고치지 않는다** — 지금 토폴로지에서 옳은 설계다. **자동 배치 편입 재제안 금지**(근거 = 위 회귀).

## 6. 발전시킬 것

1. **도달 장부**(설계 §4) — 「수집만 있고 도달 0」이 오늘부터 빨개진다. 지금은 그 상태가 초록이다. **가장 큰 지렛대이고 가장 싸다.**
2. **엔진 도달률 계기판**(설계 §6) — 「자동화됐다」를 선언이 아니라 실측으로. 분모와 함께.
3. **골든셋을 ⑥⑦의 첫 시험대로** — 이미 ⑤를 통과한 **유일한** 재료라, ⑥⑦이 서면 **당일 검증 가능한 표본이 이미 있다.** 새 데이터를 기다릴 필요가 없는 유일한 자리.
4. **사람 라벨 7종의 이관 우선순위**를 `강7 → 강6 → 강4` 순으로 — 이유는 「라벨 밀도」다(판정+교정+사유 3값 > 태그 1값 > 서술).

## 7. 정직한 한계

- 이 감사는 **저장소 실파일**을 잰 것이다. 라이브 시트의 **실제 행 수·적재 현황은 안 열어 봤다**(학생 0명 구간이라 판정에 영향 없음 · 열려면 유호님 시트 접근 필요).
- ④⑤의 「구현 0」은 **이 저장소·talk 저장소 기준**이다. n8n 워크플로가 유호님 계정에 따로 서 있다면 그건 여기서 안 보인다 — **확인 요청**(§8).
- 기능 104행 전부를 개별 판정하지 않고 **끊긴 지점으로 묶었다.** 개별 판정이 유용해지는 시점은 ⑥⑦이 선 뒤다(그 전엔 전부 같은 답이라 정보가 0이다).
