### §7-2. 종류 변화 — 층 일곱

규칙 조인 대조표 → 종단 «의도-결과» 데이터셋 + 다시 판정할 수 있는 판정 층.
커지는 자산은 원문 층(무엇을 말했나 · 어떤 사건이 왔나 · 영구)과 재판정 때 다시 묻는 «질문 목록»(extra_json)입니다.
판정 층은 그 질문의 «현재 답»입니다. 판(모델 + 프롬프트 지문)이 붙은 덧쌓기라 모델이 바뀌면 옛 판을 안 지우고 새 판을 더 붙입니다.
왼쪽(의도)은 입학 1점이 아니라 시즌마다 다시 선언한 시계열 + 「목표 실린 과제를 낸 날」 시계열이 됩니다.

층 일곱입니다. L0 → L6 순서로 «무엇이 어디에 쌓이나»입니다.
- L0 원천 = 전부 닿는 셋과 운영층이 걷는 것. Trail 은 헤더 이름으로 읽기만 · 신설 수집면 0.
- L1 원문 원장 = outcome_log(append-only · 원문 층 4칸 추가 · 원문은 절대 안 고칩니다).
- L2 판정 층 = outcome_verdict(신설 시트). 원장 행마다 N행이 붙습니다. 옛 판 행은 안 지웁니다.
  칸 = verdict_by∈{model,form,원장}(누가 판정했나) · classifier_ver(판 이름) · confidence(신뢰도) · extra_json(자유 추출).
- L3 의도 시계열 = 저장 시트 0 · 메모리 조인(읽을 때만 이어 붙이고 저장은 안 합니다).
- L4 파생 = trajectory(매일 재작성 · 17칸 유지 + «열 추가만») + topik_milestone(읽기 전용 거울).
- L5 자 = 시험지 60 · 엔진점수 「엔진」키 · 궤적상한_ 래칫 셋. 래칫 = 한 번 올린 기준을 못 내리게 잠그는 장치입니다.
  재심 발동 = 모델정찰.js «등재»(모델정책.js 지문 diff) → 시트층 야간 배치 채점(유호 방아쇠) → classifier_ver 사건.
- L5' 한 문 = trail-sync(edge function · 서버에서 도는 작은 함수 · roster-ingest 규약 · 같은 공유키 · 양방향).
- L6 소비자 두 계급.
  【자기 것】 engine.my_trail 뷰 → 시즌 회고 병치 왼쪽 + 명예 졸업생 카드 + correct [학생 맥락] 산문 V8a + OB3/VC 2.0 서명 파일 + 종이 번호 카드.
