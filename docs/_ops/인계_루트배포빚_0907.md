## ② 미는 법 — `/deploy` 절차 그대로

바꿀 코드가 없다(이미 다 커밋돼 있다). 그래서 **채번(5단계)은 건너뛴다.** 나머지는 순서대로 밟는다.

1. **오염 확인** — `git status` 전문(`--short` 금지 · rebase·merge 중을 감춘다). 배포집합 파일에 미커밋이 있으면 임자를 먼저 가른다.
2. **구문 + 시험** — `node --check` 전량 → `node tools/test-ci.js`. `fail` 0이 아니면 중단.
3. **`appsscript.json`** JSON 파싱 확인.
4. **보안** — `node tools/deploy-security-check.js`(기계 셋) → `node tools/보안검토과녁.js` → 나온 목록으로 `/security-review`.
   🔴 **과녁이 0건으로 나올 수 있다.** 지금이 그 자리다(채번 뒤에 배포가 끊겨서). 그때는 「검토할 것이 없다」가 아니라 **과녁을 손으로 준다**: `git diff 904a71f7f..HEAD -- Code.js "엔진_*.js" "contents_*.js"`.
   ⚠ `/security-review` 는 **커밋된 변경을 원리상 못 본다**(미커밋만 읽는다). 그 자리는 사람이 직접 읽고 「무엇을 셌는지」를 적는다.
5. **배포 검수** — `node tools/codex-review.js --commit dbdf7de4`.
   🔑 인자 없이 부르면 미커밋(남의 것)을 보고 「배포 파일 0건」으로 멈춘다. 도구가 그때 과녁을 알려 주니 그대로 따른다.
   ⚠ **포그라운드 셸에서는 죽는다**(5~30분). 백그라운드로 부르고 로그는 파일로 받는다.
   판정: **P0·P1 이 있으면 차단**이고, P2는 배포를 안 막지만 처분(고치기 또는 사유 붙인 기각)은 남는다.
6. **밀기** — `git push origin HEAD:master`(이미 돼 있으면 그대로 지난다).
7. **라이브** — `clasp push --force` → **`node tools/배포판점검.js --라이브`**.
   🔑 루트는 `@HEAD` 를 서빙해서 **push 가 곧 라이브**다(크루카드처럼 `clasp deploy` 를 또 찍을 필요가 없다).
   `--라이브` 를 빼면 라이브를 안 읽고 「안 쟀다」를 초록으로 낸다. 출력 끝 `🖈 도장` 확인.
8. **보고** — 커밋 해시 + 「깃허브·라이브 동기화 완료」. 트리거 시각(아침 7시·낮 2시·밤 10시)을 감안해 첫 실전 작동 시점을 함께 적는다.

## ③ 밟을 함정 넷

- **밀기만으로 안 끝나는 프로젝트가 있다** — 크루카드는 고정 버전을 서빙해서 `clasp deploy --deploymentId <기존 ID>` 까지 해야 움직인다. **루트는 아니다**(`@HEAD`). 프로젝트마다 다르므로 `--라이브` 로 되읽는 것이 유일한 자다.
- **저장소 전체 초록이 게이트 조건이다** — 남의 트랙 빨강 하나가 내 배포를 막는다. 09-07 새벽에 그런 빨강 둘을 치웠고(빈 파일 하나 · 안 쓰는 서체 이름 하나) **지금은 1685 통과 · 실패 0** 이다. 새로 빨개졌으면 임자를 가르고 먼저 초록을 만든다.
- **커밋 범위를 못 박는다** — `git commit -m "..." -- 경로들`. 이 저장소는 세션 예닐곱이 같은 작업본을 쓰므로 `add -A` 는 남의 미커밋을 함께 실어 보낸다.
- **커밋 메시지를 셸 치환으로 넣지 않는다** — 가드가 막는다. 파일로 써서 `git commit -F <파일>`.
