## 조사에서 확인한 문제

집필 규범에는 ‘알게 합니다 → 눈이 열립니다’ 같은 치환표, 부정어 금지와 고정 서사 순서가 있었다. 캐릭터 검사에는 문장부호와 학생에게 말 거는 비율까지 고정한 조건이 있었다. 실제 번역 도구가 voice-guard를 직접 불러 문체를 합격 조건으로 삼았다.

반면 voice-guard가 현재 전역 훅으로 등록돼 있다는 증거는 찾지 못했다. 파일 존재와 실행 중인 훅을 동일하게 보고하지 않는다. 모든 어색한 문장이 이 파일들 때문에 생겼다고 단정할 수 없으며, 사용자 표현을 과도하게 바꾼 응답 판단도 문제였다.

## 조사 범위와 남긴 것

운영 진입 문서, 철학·적용 기준·집필 규범·캐릭터 가이드, 제작 스킬과 연결 자료, 문체 검사 도구, 번역 경로, 모델 제작/검토 프롬프트, 첨삭·상담 엔진, SYNK-talk의 문구 생성 경로를 검색하고 관련 활성 파일을 읽었다. 모든 역사 문서와 모든 제품 프롬프트를 한 줄씩 읽었다는 뜻은 아니다.

기존 제작물의 문장, 과거 검수 결과·승인 기록, 캐릭터 성격과 시각 자산, 회사 목적과 개인화 구조는 일괄 삭제하지 않았다. 과거 자료에 남은 synk-brand 검수 기록은 현재 실행 조건이 아니다. 학습 급수별 어휘, 번역 언어, 응답 필드, 개인정보, 실제 서비스 상태·금액·보장·학습 사실을 지어내지 않는 조건은 보존했다.

현재 세션에 이미 전달된 지침은 파일 삭제로 소급해 지워지지 않는다. Codex 자체의 시스템·개발자 지침은 저장소 파일로 삭제할 수 없다. 남은 제품 전용 조건과 과거 문구까지 전부 제거했다고 주장하지 않는다.
