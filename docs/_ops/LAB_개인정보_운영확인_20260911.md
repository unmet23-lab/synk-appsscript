# LAB 개인정보 운영 확인 · 2026-09-11

이번 범위는 홈페이지 질문창 평가에서 이어진 기존 LAB 개인정보 고지와 실제 보호 동작, Meta 계정 상태 확인이다. 공개 지식 파일에 내부 운영 문서·학생 기록·자격증명을 넣지 않는다. 현재 단계와 미확인을 분리한다.

## 현재 사업자와 Meta

- 기존 게시 번호는 2026-09-03 발급 총사업자등록내역에서 폐업 표시를 확인했다. 사용자는 이번 대화에서 새 사업자등록증이 없다고 확인했다. 현행 홈페이지·챗봇·정책·공개 이전 시안의 번호를 제외하고 마케팅 정본도 맞춘다.
- 로그인된 Meta 비즈니스 정보는 인증되지 않음, 법적 이름·주소·전화·웹사이트 미입력, 연결 앱 없음이었다. 개발자 페이지도 등록 시작 상태였다. 보안 센터는 현재 단체 인증이 필요하지 않다고 안내하며 일반 인증 시작 단추가 없었다.
- 확인된 계정에서 인증 심사 제출·사업자 정보 저장·서류 업로드는 하지 않았다. 유료 Meta Verified는 구매하지 않는다. 개발자 가입, 앱 접근 심사, 비즈니스 인증은 서로 다른 절차다.
- 새 등록 이후 실제 상호·번호·등록 주소·연락처를 서류와 대조하고 해당 포트폴리오·앱의 필요한 인증 절차로 진행해야 한다. 이전 번호나 예정 법인으로 신청하지 않는다.

## 실제 처리와 수정 범위

| 대상 | 확인한 사실 및 이번 조치 | 완료로 확대하지 않는 범위 |
|---|---|---|
| 홈페이지 질문창 | 공개 자료를 브라우저에서 선택. 현행 사업자 안내와 개인정보 링크 수정 | 학생 데이터·상담 접수·생성형 모델 연결 없음 |
| 한국어·영어 정책 | Google 경로와 앱의 Supabase·OpenAI·Anthropic·Sentry 구분, 싱가포르 저장, 기기 녹음, 보호자 접근, 보관·철회 기준 교정 | 정책 편집은 기존 동의의 증거나 계정별 계약·법률 준수 인증이 아님 |
| 학생 개발 자료 반출 | 현재 목적별 명시적 동의를 검증할 구조가 없으므로 골든 평가자료와 증언의 외부 반출을 기본 차단 | 내부 수업 처리까지 삭제하지 않음. 과거 반출 사본 회수는 별도 |
| 음성 철회 도구 | 휴지통 성공한 파일의 행만 삭제. 실패·식별 불가·행 삭제 실패는 남겨 재시도. 결과는 처리 위치와 미처리 범위를 구분 | 실제 학생에 대한 삭제 요청을 실행한 것이 아님. 휴지통 이동은 영구 삭제가 아님 |
| 앱 오류 관측 | 전송 직전 허용 필드로 재구성. 메시지·추가정보·경로·첨부 등 자유문자 제외. 별도 네이티브·성능·리플레이 경로 비활성 | 이전 앱과 이미 보낸 오류 기록에 소급 적용되지 않음. 앱 배포·기기 도착 별도 |

실제 배포·시험 결과는 기업웹 제작결과의 이번 후속 기록과 SYNK-talk의 해당 검증 기록에 추가한다. 이 표의 코드 변경을 라이브 완료로 읽지 않는다.

## 열람·정정·철회·삭제 처리

1. 공개 이메일 창구에서 이용한 서비스와 요청 종류를 확인한다. 비밀번호·인증번호·다른 학생 자료를 받지 않는다. 본인 또는 정당한 대리인인지 필요한 최소 정보로 확인한다.
2. 확인된 학생과 처리 목적의 동의를 먼저 철회하고 관련 처리 중단을 확인한다. 일반적인 포괄 동의나 화면 체크를 별도 개발·공개 사용 동의로 승격하지 않는다.
3. 운영 환경 안에서 대상 목록을 만든다. Google 원본 Form 응답과 응답 시트, 보류 파일, voice_log, 음성 라벨·전달 기록, 첨삭·성장 자료, 보고서·메일, 앱 Storage·DB 원문·파생물, 이용 기기, 백업을 구분한다. 식별값과 원문은 공개 저장소·검토 꾸러미·다른 모델에 적지 않는다.
4. 기존 도구의 미리보기를 먼저 사용한다. `voiceWithdraw`는 Google의 동의·연결 파일·voice_log·성장 카드 네 위치를 다루는 부분 도구이며 원본 폼·모든 파생물까지 전수 삭제하는 도구가 아니다. 성공·실패 항목과 재시도 근거를 보존한다.
5. 앱은 서버 원문과 파생 자료, 사용자 기기의 녹음을 각각 확인한다. 현재 로그아웃으로 원본 녹음이 삭제되지는 않는다. 배포 중인 앱의 동작을 확인하지 않고 기기 삭제 완료를 통지하지 않는다.
6. 휴지통·백업·수탁자 사본은 원본 삭제와 구분한다. 법정 보존이 실제 적용되면 해당 항목·근거 법령·기간을 정책과 개별 안내에 명시하고 목적 외 사용을 제한한다. 보존 근거를 확인하기 전 임의로 학생 자료를 일괄 삭제하지 않는다.
7. 확인한 처리 결과, 남은 사본·사유·처리 일정만 답한다. 접수나 부분 삭제를 ‘7일 내 전체 영구 삭제 완료’라고 통지하지 않는다.

보관 종료 사건은 상담 종결, 해당 학습 계약 종료 또는 관련 동의 철회 중 먼저 도래한 때다. 미등록 무응답 상담의 종결 판단 및 정기 정리 실행은 실제 상담 담당 운영과 대조해야 한다. 종료 이후 성장 기록 보관은 별도 목적·기간·선택 동의가 필요하며 기존 동의에 소급하여 덧붙이지 않는다.

## 아직 확인해야 하는 조건

- 개별 국외 이전 고지: 실제 계정·계약에 맞는 수령자 연락처, 국가, 시점·방법, 항목·목적·기간, 거부 방법·영향. 일반 업체 약관을 계정별 설정 증거로 대체하지 않는다.
- Google 계정의 일반 소비자 서비스/Workspace 계약 구분, 실제 파일 소유·공유·보존 설정, Speech-to-Text 데이터 로깅 옵트인. Glide 이전 계정의 연결과 잔여 자료.
- OpenAI 프로젝트의 처리 지역, Anthropic 저장과 추론 지역·보관 예외, Sentry 요금제별 보관과 실제 앱 버전. 사용자의 새 유료 지역 설정이나 계약 변경은 이 작업에서 하지 않는다.
- 원어민이 이해할 수 있는 동의 고지와 법정대리인 권한 확인·증거. 정책 링크만 추가하거나 문구를 바꾸는 것은 재동의가 아니다.
- 실제 요청의 원본·파생·기기·백업 전수 삭제와 결과 확인. 이번에는 실학생 자료를 조회·삭제하지 않고 합성 데이터로 안전 동작을 시험한다.
- 몽골 법 제23조와 A/81 영향평가 적용 판단. 내부 평가 문서 작성, 국가인권위원회 제출·권고 수령은 별도 단계다.
