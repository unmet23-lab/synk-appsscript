### 왜 재염색이 싸구려로 보이나 (다시 꺼낼 때 읽는다)

선형광에 게인을 «곱»하는 방식이라 둘이 망가진다.
- 원본 양모가 품은 **색 폭**(코랄이면 주황~분홍~적갈)이 한 방향으로 눌려 균일해진다.
- 코랄 양모의 그림자는 갈색인데, 파랑으로 옮기면 **그림자까지 파래져** 플라스틱으로 읽힌다.
  진짜 라피스 양모는 그림자가 청회색이고 하이라이트가 연보라다 — 그건 그 색으로 찍어야 나온다.

## ④ 🔴 밟으면 다치는 것 — 09-05 에 다 물렸다

**굽기**
- 🔑 **«떠 있는» 이라고 써야 그림자가 안 온다.** 「no shadow」를 아무리 못 박아도 «바닥에 놓인» 상황이면
  모델이 그림자를 낸다. `floating in empty space, NOT resting on any surface` 로 쓴다.
  세 판(1,505원)을 태워 알았다 — 골무·실패가 크게 물렸다.
- 🔑 **흰 배경의 그림자는 «옮길 수 없다».** 알파를 낮추면 어두운 심지만 남고, 검정+알파로 바꿔도
  회색 얼룩이 남고, floodfill 임계를 125까지 올려도 버틴다. **구울 때 안 만드는 것이 유일한 길이다.**
- 🔑 **천은 «장면»으로 시킨다.** flat·seamless·even·no vignette 를 거듭 못 박으면
  `IMAGE_RECITATION` 으로 통째로 거절된다(모델이 「알려진 텍스처를 그대로 내라」로 읽는다).
  «작업대 위에 놓인 큰 천에 가까이 다가간 사진» 이라는 장면을 준다.
- 🔑 **429 는 두 가지다.** 「Resource exhausted」 = 분당 몫(기다리면 풀린다) ·
  「credits depleted」 = 크레딧(안 풀린다). 09-05 전에는 둘을 같이 «돈 벽»으로 세워
  23장 배치가 첫 장에서 통째로 섰다(0장 구움). 지금은 갈라 보고, 몫이면 **90초 뒤 한 번만** 다시 던진다.
  ⚠ 무한 재시도 금지 — 실패한 요청도 몫을 먹어 벽이 길어진다(기억 `retry-into-429-holds-the-wall`).
- **원본 PNG 를 git 에 안 넣는다**(한 장 5~9MB). 배경 걷어 1800px webp 로 쥔다.
  `.gitignore` 예외 = `!docs/Loom_자산/구움/공방_*.webp` (⚠ 폴더째 무시하면 안쪽 `!` 가 원리상 안 먹는다 — 규칙이 `구움/*` 여야 산다).

**쓰기**
- **부품은 전부 정사각으로 쓴다.** 칸이 가로로 길면 `contain` 이 세로에 맞춰 줄여 **점**이 된다.
  가로 띠가 필요하면 늘리지 말고 여러 개를 늘어놓는다.
- **작은 크기에서 갈린다.** 44px·24px 실크기 줄이 진짜 자다. 확대해서 판정하면 그림자가 배율만큼 커져 없는 결함이 보인다.
- **`background` 축약을 쓰지 않는다** — 그 한 줄이 `background-image:none` 을 품어 Loom 이 얹는 그림을 조용히 지운다.
- **쪽과 같은 크기 요소에 배경 그림을 직접 주지 않는다** — 인쇄에서 통째로 사라진다(화면 1.59% · PDF 0.00%).

**재기**
- 🔑 **자는 «종이»에 댄다.** 같은 그림이 재질 파일 1.70% → 화면 1.59% → 인쇄본 0.00% 로 달라졌다.
  인쇄본을 `pymupdf` 로 150dpi 렌더해 재는 것이 유일하게 참인 자다.
- 🔑 **「넘침 0」이 참인데 종이가 망가질 수 있다.** 층의 바닥은 **자손 중 가장 아래**로 잰다.
