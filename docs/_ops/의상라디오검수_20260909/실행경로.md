# 라디오 의상 실행 경로 — 수정 전 독립 감사

2026-09-09 · 확인 HEAD `9bb45381828d2522fb887635a243c77183546a69`.

범위: 저장소의 현재 송출·마스코트 코드, 관련 제작 도구, 현존 안전 시험. 방송 서버 접속·서비스 재시작·라이브 송출·새 이미지 생성·제품 코드 변경은 하지 않았다. 이 문서는 **수정 전 기준선**이다. 이후 주담당의 수정·화면 검증 결과를 대신하지 않는다.

## 결과

현재 라디오는 **까몽의 여름 델 + 전설의 팻말 1조합**에 대해 준비된 8개 표정 그림을 바꿔 보여 준다. 몽글·마린의 기본 표정 세트는 코드에 있지만, 장르마다 갈아입는 표는 모두 까몽 한 조합으로 고정되어 있다. 따라서 **세 캐릭터가 의상 1벌 + 악세서리 1개를 자유롭게 고르고, 이를 유지한 채 표정·동작을 하는 기능은 아직 없다.**

이는 과거 까몽 고정 결정 자체의 오류라는 뜻이 아니라, 이번 새 요청을 현재 구현이 아직 충족하지 못한다는 뜻이다.

## 실제 경로

1. `bots/오버레이/겹쳐송출.js:429`가 `방송층.html`에 층·캐릭터 크기·자리·바닥·부스 여부를 넘긴다. DJ·의상·악세서리 선택 옵션은 전달하지 않는다.
2. `bots/오버레이/방송층.html:43`은 마스코트·전광판 iframe을 만들고 URL 인자를 그대로 전달한다.
3. `bots/오버레이/마스코트.html:199`의 경로와 `:214`의 컷표가 이미지 세트를 고정한다. 까몽만 `docs/Loom_자산/라디오DJ/까몽_여름델+전설의팻말_*.webp`, 몽글·마린은 `docs/캐릭터/화면_1024/`이다.
4. `마스코트.html:419–451`의 9장르는 모두 `DJ:'까몽', 옷:[]`이다. 까몽 그림 안에 옷과 팻말이 이미 있으므로 별도 옷 조각을 얹지 않는 현재 구조는 이 특정 조합에는 일관적이다.
5. 장면 시계는 `겹쳐송출.js:378` 또는 `:401`에서 `{종류:'결', 결}`만 보낸다. 마스코트는 장르차림으로 DJ를 정한다.
6. 몸·옷은 `마스코트.html:710–711`의 공통 부모 변환으로 함께 이동·회전·늘어남을 받는다. 이는 **그림 전체의 움직임**이지 컷 안에서 기울어진 머리에 악세서리를 맞추는 기능은 아니다.

## 발견 사항과 재현

### P1 — 자유 의상 선택 입구와 소비 경로가 없음

- 근거: `마스코트.html:389–390,419–451,483–513,725–762`, `겹쳐송출.js:429–431`.
- URL `?DJ=몽글`은 몽글 맨몸을 보여 주지만 `?DJ=몽글&결=전자밤도시`를 주면 초기 장르 처리 `:309–313`이 까몽으로 덮는다. 마린 + 시티팝도 같다.
- `{종류:'의상', DJ:'몽글', 의상:'한복', 악세:'펠트헤드폰'}`은 허용 사건에 없어 경고 후 무시한다. 기존 `결` 사건도 의상·악세서리 필드를 읽지 않는다.
- 기존 옷층은 최대 3개(옷 1 + 악세 2)이며 현재 차림표의 빈 배열 때문에 실방송 기본 경로에서 비어 있다. 최신 요청의 1 + 1 선택 구현과는 다르다.
- 추천: 이미 준비된 통합 착용 세트를 캐릭터·의상·악세서리·표정으로 찾는 실제 선택 계약을 만들고, 없는 조합을 성공처럼 표시하지 않는다. 현재 만족한 까몽 기본 조합은 보존한다.

### P1 — 머리 악세서리를 유지한 마린의 인사·궁금함이 안 됨

- 근거: `마스코트.html:475,481,554,690–692,710`.
- 옛 옷층으로 마린에게 헤드폰을 입힌 뒤 인사하면 머리 악세서리는 1.2초간 `visibility:hidden`이 된다. 머리가 기우는 궁금함은 후보에서 제외한다.
- 지금 고정 차림은 이 레이어를 사용하지 않아 평소 노출되지 않지만, 이 코드를 자유조합으로 다시 쓰면 사용자가 고른 악세서리가 인사할 때 사라지는 제약이 그대로 드러난다.
- 추천: 선택한 착용 기준 그림의 몸·옷·악세서리를 고정하고 눈 영역만 교체하는 표정 세트를 우선 사용한다. 머리 자세를 바꾸는 특수 컷은 해당 착용 조합 전용 검증 컷이 있어야 한다. 단순히 가리는 코드를 없애는 것으로 해결되지 않는다.

### P2 — 미리보기 설명이 현재 실제 DJ와 다름

- 근거: `bots/오버레이/방송미리보기.html:86–96`은 몽글의 한복·마린 헤드폰 등을 안내하지만 현재 장르차림은 전부 까몽 통합판이다.
- 재현: 시티팝 또는 추석 단추의 안내와 실제 마스코트 결과를 대조한다.
- 추천: 새 선택 기능의 실제 카탈로그/상태를 화면에 표시하여 설명과 실행 값이 갈리지 않게 한다.

### 검증 공백 — 표정 안정성과 화질은 기존 시험만으로 보장 안 됨

- 모든 DJ의 `기쁨`은 눈웃음 파일의 별칭이다(`마스코트.html:226,239,253`). 별도 기쁨 컷까지 구현됐다고 셀 수 없다. 현재 긍정 표정 재사용 규칙이므로 이것만으로 기능 결함이라고 단정하지 않는다.
- `tools/마스코트층작게.py`의 `눈만컷`은 마린 6표정만 적용한다. 몽글은 전체 표정 그림 교체여서 얼굴 이외의 털·실루엣 안정성은 실제 픽셀과 화면 검사가 필요하다. 까몽 통합 의상은 별도 생산물이다.
- `tools/라디오DJ층작게.py`는 4096 정사각 의상 표정 PNG를 1024 정사각 WebP, quality 92로 줄인다. 전체 액자는 보존하되 WebP는 손실 압축이므로 원본과 픽셀 동일하다는 뜻은 아니다.
- 송출은 1920×1080 화면을 배율 2/3로 캡처해 1280×720으로 만들며(`겹쳐송출.js:442–444`), PNG 캡처 후 H.264 ultrafast / 2.5 Mbps / YUV420으로 재인코딩한다(`:207–222,467`). 따라서 원본 4K 파일이 훼손되지 않는 것과 최종 방송이 원본 4K 품질인 것은 다르다.
- 기본 층 캡처는 10 fps, 방송은 20 fps이나 조율 파일이 덮어쓸 수 있다(`:69–79`, `radio-live.service:30`). 실제 서버의 현재 프레임 값·YouTube 최종 화질·장시간 매끄러움은 이 감사에서 확인하지 않았다.

## 수행한 검증

`node --test tests/라디오오버레이층.test.js tests/옷경로.test.js` — 12개 통과, 실패 0.

이 시험은 장르 키·그림 존재·현재 까몽 고정·옷 경로 규칙을 검사한다. 의상 선택, 조합별 모든 표정의 자연스러움, 영상 압축 뒤 화질은 검사하지 않는다. 특히 라디오 시험 하나는 모든 장르의 까몽 고정을 명시적으로 요구하므로 새로운 선택 기능과 기본 방송 고정을 분리해 회귀 조건을 정해야 한다.

실제 `마스코트.html` 스크립트를 Node VM에서 DOM·이미지 로드만 모의하여 실행했다(픽셀/브라우저 검증 아님).

| 입력 | 준비 뒤 DJ | 차림 | 별도 옷층 |
|---|---|---|---|
| `?DJ=몽글` | 몽글 | 없음 | 0 |
| `?DJ=몽글&결=전자밤도시` | 까몽 | 전자밤도시 | 0 |
| `?DJ=마린&결=시티팝노을휴양지` | 까몽 | 시티팝노을휴양지 | 0 |

세 경우 모두 의상 사건은 `반응 없는 사건 무시: 의상`으로 기록되고 상태는 유지되었다. 이미지 로드 성공을 모의했으므로 이 결과를 실제 이미지 검증으로 사용하지 않는다.
