# 표정 전환의 털 불일치 수리

2026-09-09 · 로컬 검수 화면의 **까몽 / 여름 델 + 전설의 팻말 / 8표정** 수정. 다른 128차림과 몽글·마린 전체의 합격 보고가 아니다. 공개 push·방송 배포·새 이미지 모델 호출 없음.

## 결함과 놓친 검사

사용자가 지적한 털 변화는 실제 결함이다. 이전 검사는 넓은 눈 창 밖의 픽셀과 의상 유지 위주였고, 그 창 안의 털 교체를 충분히 검사하지 않았다. 구 라디오 DJ와 새 무손실 후보 모두 앞단 합성에서 표정별 얼굴 털이 유입됐다. 일부 컷에는 기본에 없던 코까지 나타났다. [독립 원인 감사](감사/판정.md).

| Before | After | Why |
|---|---|---|
| 표정별 얼굴 창 전체를 복사 | 기본 그림의 공통 털 바탕 + 좌우 눈·눈꺼풀만 합성 | 미간·볼·코·의상이 표정마다 교체되지 않도록 |
| 색으로 열린 눈 윤곽을 추정 | 검수한 원본의 8개 눈 윤곽을 명시 | 초승달 홍채 옆 검은 동공·반사광이 잘리지 않도록 |
| 응원 오른눈의 계단식 잘림 | 같은 표정 4K 정본을 기존 등록값으로 복구 | 다른 눈 복제·새 그림 생성 없이 온전한 흰자·윤곽 보존 |
| 첫 화면이 구 라디오 DJ | 수정된 대표 차림 8컷 자동 적용 | 사용자가 수정본을 직접 볼 수 있도록 |
| 정지 컷만 비교 | 수동 8표정 순환·중지, 실제 버튼 검사 | 전환 시 재질 일관성을 확인하도록 |

## 실제 수정 방식

정본 파일과 승인 의상 PNG는 보존했다. 라디오용 파생 기본의 두 눈 자리에는 기본 그림 자체의 볼 털을 사용해 작은 공통 바탕을 한 번 만들었다. **파생 기본도 이 바탕을 공유하므로 원래 기본과 눈가 12,772화소가 다르다.** 기본 그림 전체가 원본과 동일하다는 뜻은 아니다. 이 국소 바탕은 모든 표정에서 같고, 변하는 부분은 실제 두 눈 윤곽뿐이다. 도중의 이마 털 복사·넓은 색 연결성 후보는 이음매나 의상 유입이 있어 채택하지 않았다.

입력 1290×1219에서 실제 눈 변화 허용영역은 두 눈 마스크의 합집합 37,088화소다. 그 밖 **1,535,422화소는 8컷 모두 RGBA가 같다.** 눈 바탕을 수리한 넓은 구멍을 동적 변화 허용영역으로 세지 않았다. 전체 알파(투명도)도 같다. 눈 바탕 자체에 동공·초록 원형 잔상이 없는지는 수치와 별도로 확대 실물을 확인했다.

응원 오른눈은 정본 응원 컷을 기존 의상 등록값(k=0.39812854094155703, dx=-205.57734088840982, dy=-229.75186019771724)으로 축소·배치하여 RGB만 복구했다. 원본을 바꾸거나 반대쪽 눈을 복제한 것이 아니다. 이후 8컷은 동일한 위치·크기 변환으로 1024 라디오 WebP 무손실 형식에 담았다. 이는 4K 화질로 방송한다는 뜻이 아니다.

- [좁은 눈 영역·원본 SHA·8컷 검사](털고정검사.json).
- [검수 화면](../검수보기.html): 첫 로드 대표 차림 자동 적용, 0.75초 8표정 비교 시작/중지. 움직임 줄임 설정에서는 수동 표정만 제공.
- 실제 브라우저에서 기본·깜빡·눈웃음·궁금함·집중·안도·응원·놀람 전부 확인. 각 상태에 수정 버전 이미지 1장, 1024×1024, 불투명도 1, 필터 없음. 정적 확대판과 실제 표시 크기에서 털·동공·눈 잔상을 구분해 봤다.
- [브라우저 실측 기록](브라우저확인.json): 8표정과 순환/중지/자연 복귀. 실제 상태를 펼쳐도 650폭에서 가로 넘침 0. 수정 전 탭 오류와 수정 후 상태를 구분했다.
- 자동 시험 61개 통과: 눈 윤곽 9 + 공통 털 합성 9 + 라디오 파생 자산 15 + 검수 UI/런타임/층 28. 시험 숫자만으로 시각 자연스러움을 합격시키지 않았다.
- [독립 수정 후 검사](감사/수정후검수.json): 제작기의 합성/파생 함수를 호출하지 않고 8컷과 좁은 눈 마스크를 재구성했다. 원본 8개와 참고 3개 보존, 고정 얼굴 영역 RGBA 차이 0, 닫힌 눈 밖 초록 잔상 0, 최종 WebP 8개의 재계산 RGBA 차이 0. 1024에서 Lanczos 표본 범위를 포함한 좁은 눈 지원영역 17,800화소 밖도 차이 0이다. 다른 128차림의 1,024개 표정 입력·출력이 현재 개별 기록과 일치하며, 새싹 보존 후보 14개와 활성 버전도 유지된다. 이는 다른 차림 전체의 자연스러움 재검수는 아니다.
- 모델 호출 없음. GPT Image 2.5 정책은 유지하며 과거 그림을 2.5 결과로 소급 표시하지 않는다.

RGBA 후보: `후보_RGBA/f3ff384ff4523407/`. 라디오 후보: `docs/Loom_자산/라디오차림/까몽/_후보/여름델+전설의팻말/65f92a753bb5416b/`. `후보_RGBA` 바로 아래의 버전 없는 PNG는 작업 중 기각된 시제품이며 현재 목록에서 사용하지 않는다.

검사 도구는 `tools/라디오털고정.py`, `tools/라디오눈윤곽.py`. 후보 적용에는 기존 `tools/라디오차림굽기.py --차림 여름델+전설의팻말 --입력 <후보폴더>`를 사용했다. 한 벌 후보 갱신은 다른 128차림 연락판을 다시 쓰지 않도록 범위를 좁혔다.

수정 시작 기준 커밋 `798542a7e2049d37d4040d497b4b87dad5f43cb1`, 후보 연결 직전 `dd4b2087d5d21c63df0715ec569926ea09c13f99`. 공통 운영 원칙 SHA-256 `a09124dc8bde12512f11678ca35358b22ec8bceea1b44f06117ddf4c8827217f`. 원인 코드·의상8원본·눈윤곽 등록 정본·현재 표시 코드·검수 화면을 직접 읽었다. 다른 차림 원본 전부나 송출 서버는 이번 후속에서 다시 검사하지 않았다.

## 남은 범위

다른 차림은 고유한 눈 등록·악세 가림을 검수한 뒤 같은 공통 바탕 원칙으로 옮겨야 한다. 몽글·마린 통합 차림 미제작, 기존의 잘린 꼬리·일부 의상·흰 외곽 잔색, 실제 방송 압축 검증은 이전 보고의 미완료 상태 그대로다. 이번 대표 차림의 수정이 그 문제들을 완료시킨 것은 아니다.
