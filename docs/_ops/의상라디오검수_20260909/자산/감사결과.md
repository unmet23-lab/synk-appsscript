# 의상 자산 감사와 알파 보존 수정

2026-09-09 · 이 보고의 재고는 라디오 후속 수정 전 조회 결과다. 파일 존재·메타데이터와 실제 사용의 자연스러움은 별개의 확인이다.

## 재고: 캐릭터마다 준비 상태가 다르다

현재 규칙은 의상 최대 1벌 + 악세 최대 1개다. 맨몸은 아래 차림 수에 넣지 않았다. [전체 조합·누락 목록](재고감사.json)은 현재 `tools/lib/옷목록.js`에서 계산했다.

| 캐릭터 | 의상 / 악세 | 의상+악세 짝 | 단품 포함 차림 | GPT 원본 | 공식 표정 AVIF | 기존 라디오 옷층 |
|---|---:|---:|---:|---:|---:|---:|
| 까몽 | 9 / 12 | 108 | 129 | 129 / 129 | 1,806 / 1,806 = 129 × 14 | 21 / 21 |
| 몽글 | 10 / 12 | 120 | 142 | 15 / 142 · 단품만 | 0 / 2,130 = 142 × 15 | 22 / 22 |
| 마린 | 9 / 12 | 108 | 129 | 0 / 129 | 0 / 1,806 = 129 × 14 | 21 / 21 |

- 까몽 GPT 최종 폴더는 시험 차림 4개를 포함해 실제 133차림 × 14표정 = 1,862장이다. 공식 선택 규칙에 속한 것은 1,806장이다.
- 몽글 GPT 단품 누락: 저고리, 치마, 한복, 6개월 출석 화관, 첫 목소리 목도리, 돌 주머니, 창가 밀짚모자. 모든 의상+악세 짝 120개도 GPT 통로에는 없다.
- 마린은 GPT 통로에 단품·조합이 없다. 이것을 ‘마린 의상 자체가 없다’로 읽으면 안 된다. 기존 레이어 원본 21종은 있다.
- 기존 `층`·`얹음`은 셋 모두 4096² 투명 PNG다. 라디오용 `docs/Loom_자산/옷층`은 같은 품목의 1024² 투명 WebP 64종이 전부 있다. 레이어의 존재는 모든 겹침·표정·움직임의 합격 증거가 아니다.

## 전수로 확인한 것

옷 작업 폴더의 이미지 8,236장 + 라디오 옷층 64장 + 정본 50장, 합계 **8,350장**의 파일 헤더를 읽었다. 크기·형식·알파 채널 조회 실패는 0건이다. 모든 픽셀 디코딩이나 사람이 8,350장을 눈으로 봤다는 뜻이 아니다.

- 정본 50장: 4096² 투명 PNG. 정본 표정 창구에서 실제로 쓰는 정면 표정은 까몽 14·몽글 15·마린 14종이다.
- 까몽 최종 표정 1,862장: 모두 4096² 투명 AVIF. 원본은 2560² 또는 약 1254~1290픽셀이다. 큰 틀에 배치한 것을 새 4K 원본·무손실 원본으로 부르면 안 된다.
- GPT2.5 재굽기 보관본 4장과 현재 `GPT정액시험`의 해당 4장은 SHA-256이 같다. 각각의 표정·누끼·AVIF가 현재 원본 이후에 갱신됐고 중간 치수가 일치한다. 생성 모델의 실제 호출 증거를 이번 감사에서 새로 검증한 것은 아니다.
- 현재 `GPT_표정/_검사.json`은 최근 4차림 × 14표정 = 56장만 담고 있다. 이 파일 하나를 지금의 1,862장 전수 검사 보고로 인용할 수 없다.

## 현재 재현한 코드 결함과 수정

### 반투명 털의 색·투명이 두 번 곱해지는 결함: 수정

`tools/옷틀맞추기.py`는 빈 RGBA 캔버스에 `paste(그림, 위치, 그림)`으로 붙였다. 그림 자체를 마스크로 다시 쓰므로 `(200,100,50,128)` 픽셀이 `(100,50,25,64)`가 됐다. 색이 어두워지고 반투명 털이 더 투명해지는 계산 오류다.

- 빈 캔버스에 마스크 없이 RGBA를 복사하는 `투명틀에앉히기()`로 두 실행 분기를 통일했다.
- `--출력 <별도검수폴더>`를 추가했다. 입력 폴더와 같은 목적지·마스코트 정본 폴더는 거절한다. 기본 목적지는 기존과 같다.
- 무손실 화질이라고 단정하던 설명을 고쳤다. 크기 변경에는 리샘플링이 있고, AVIF 품질 62 저장도 별도의 손실 압축이다.
- 회귀시험 5개: 반투명 1픽셀, 7단계 가장자리, 음수 위치 잘림, 실제 저장 분기와 입력 파일 불변, 별도 출력/원본 경로 보호.

[실제 두 조합의 비교 수치](알파비교.json): 안경+여름델과 목도리+여름델, 각각 본체 표정 1장만 별도 후보로 냈다. 기존 4K 결과는 수정 전 계산과 픽셀 단위로 완전히 일치했다. 고친 판은 **완전 불투명 픽셀 변화 0**, 반투명 경계 259,285 / 316,248점의 원래 RGBA를 회복했다. 두 판 모두 4096², 프레임 가장자리 접촉 0이다. 정본·기존 원본·기존 가공본 SHA-256은 불변이다.

400픽셀 사용 크기에서 아래 두 비교판을 직접 보았다. 각 판은 왼쪽 기존 / 오른쪽 수정, 위 밝은 배경 / 아래 어두운 배경이다. 눈·옷 위치는 유지된다. **어두운 배경의 흰 외곽 잔색은 이 수정으로 해결되지 않았다.** 흰 배경을 제거한 원본의 가장자리 색 문제와 알파 이중 적용 문제를 구분한다.

- [목도리+여름델 비교](알파보존후보/목도리+여름델_기존왼쪽_수정오른쪽_400px.png)

### 몽글·마린 눈 정렬 통로: 지원 없음 확인, 이 작업에서 수정하지 않음

`옷표정얹기.py`의 눈 찾기는 까몽 초록 홍채만 찾는다. 현재 정본 3장에 실제 호출하니 까몽은 눈 좌표를 얻었지만 몽글·마린은 둘 다 `None`이었다. `--누구` 인자가 있다고 셋 모두 처리되는 것은 아니다. 기존 `마스코트치수재기.py`에는 캐릭터별 색 구분이 있으므로 그 기준을 빌려 일반화할 여지는 있지만, 옷 보호 마스크도 까몽 털 전용이라 눈 구분만 바꾸는 것으로 끝나지 않는다.

### 안경 표정: 현재 28장 수치 재검, 시각 전수 합격 아님

`옷표정검사.py`의 현재 함수를 호출하되 결과 경로는 [코드감사.json](코드감사.json)으로 분리했다. 안경 단품 14표정과 안경+여름델 14표정에서 서로 같은 표정쌍은 0이다. 계산상 옷 지움 최대는 각각 0.35%, 1.28%다. 이 검사는 정한 색·차이 문턱으로 옷 손실을 세며 흰 점 이중상·눈 테 잔상을 직접 판정하지 않는다. 따라서 알려진 흰 점 잔상 문제가 없어졌다고 보고하지 않는다.

## 새 생성 없이 할 수 있는 범위와 남은 것

기존 까몽의 원본에서 올바른 알파로 라디오 크기를 파생하고, 동일 차림의 모든 표정에 같은 정렬값을 적용할 수 있다. 기존 몽글·마린 레이어를 사용해 1+1 선택 상태와 그림을 함께 움직이는 기능도 구현·검증할 수 있다. 그러나 그것을 GPT 완성 조합 그림과 동일한 자연스러움이라고 단정할 수는 없다. 레이어끼리 겹치는 자리, 눈 가림, 흰 테, 현재 라디오의 실제 전환·움직임은 후속 담당의 실행 검증 대상이다.

의상 4K 원본·정본을 덮어쓰거나 새 GPT 생성·API 호출·전체 1,862장 재가공·커밋·배포는 하지 않았다. 이번 수정은 도구와 새 시험, 별도 검수 후보에만 반영됐다. SYNK 디자인 기준의 원본 보존·실제 사용 크기 비교·수치와 시각 판정 분리를 적용했다.

## 재현

```powershell
node docs/_ops/의상라디오검수_20260909/자산/재고감사.cjs
python docs/_ops/의상라디오검수_20260909/자산/코드감사.py

```

첫 두 명령은 원본을 읽고 보고서만 갱신한다. 마지막 명령은 별도 `알파보존후보` 폴더의 2장과 비교판만 갱신한다. 기존 정본이나 승인 가공본은 쓰지 않는다.
