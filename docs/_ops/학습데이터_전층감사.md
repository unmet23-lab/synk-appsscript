## 판정

**설계 골격은 엔진 학습 요건에 맞게 서 있다 — 방향을 바꾸지 마라.** 층간 정합(계약↔검증기↔서버↔DB)은 이 저장소 기준으로도 드물게 촘촘히 **기계로** 잠겨 있고, 감사에서 겉멋으로 판명된 초록은 없었다.

단 **빨강 1개**: 폐루프의 귀환 절반 — 학생이 교정을 **봤다·반응했다·다시 했다** — 가 이름(c8)·물리(열+FK+CHECK+트리거)·검증기·서버 INSERT 까지 전부 서 있는데 **생산자(내는 코드)가 0줄**이고, 그 부재를 빨갛게 만드는 장치도 0이었다. 계약 스스로 적어 둔 무게: `retry_of_event_id` = 「지금 설계의 필드가 거의 전부 입력·성향인데 **결과 변수는 이것 하나뿐** — 없으면 엔진이 상관만 배우고 처방을 못 배운다」(계약 c8 미구현_주의). 이번에 **생산자 장부**로 기계화했다(아래 처방).

## 겹 지도 — 화살표마다 어느 초록이 지는가

| 화살표 | 지는 검사 | 발화점 | 판정 |
|---|---|---|---|
| 계약 JSON ↔ 검증기(요구 조합) | talk `tests/이벤트검증.test.js` — 정방향(지어낸 이름 금지) + **반대방향 장부**(모든 계약 필드는 요구/서버칸/사유 중 하나) | CI | ✅ |
| 계약 JSON ↔ 계약 사본(두 저장소) | 양쪽 `tests/계약.test.js` — same-byte | 양쪽 CI | ✅ |
| 계약 값목록 ↔ DB CHECK | talk `tests/L0스키마.test.js` — **SQL 을 파싱해** deepEqual(event_type·task_type·task_format·verdict) + CHECK 이름에 판 접미(c7→c8 이름째 교체 규율) | CI | ✅ c4 사고의 회귀가 살아 있다 |
| lib 정본 → 배포 번들(.mjs) | 손사본이 아니라 **배포기가 파생** + `tests/원격배포.test.js` 가 번들을 실제 import | CI | ✅ 드리프트 원리상 차단 |
| 번들 ↔ 배포된 판 | `tools/배포대조.js`(오늘 신설·타 세션) | **수동** | ⚠발화점 없음 — 그 세션 보드의 「다음」, 내 몫 아님 |
| API → DB (필드 단위) | `tools/*왕복시험.js` 5종 — 진짜 Fn 을 태우고 **행을 SQL 로 재조회**해 필드 대조 | 수동(CI 밖 — 옳은 배치) | ✅ 0b3bd54 이후 통로 진실 |
| **화면(생산자) → API** | `오늘과제`·`말하기로직` 회귀가 검증기를 물고 돈다 — 단 **submission.created·session.abandoned 2종만** | CI | 🔴 나머지 10종은 지도 자체가 없었다 → **오늘 생산자 장부로 기계화** |

🔑 이 표의 교훈이 F201 과 같은 문장이다: **초록이 재는 겹을 물으면, 초록이 안 재는 겹이 나온다.** 왕복시험 초록은 전부 **합성 사건**으로 만든 초록이라 화면이 사건을 안 내도 아무것도 안 빨개진다.

## 발견 (반박 1패스 통과분만)

### A 🔴 결과축 생산자 0 — 그리고 부재가 초록이다
- **실측**: `correction.viewed`·`correction.responded`·`retry_of_event_id` 를 내는 앱 코드 0줄. src 전수에서 corrections **접촉 자체가 0**(읽기 화면 미구현 — S1-8 자리).
- 아래층은 전부 초록: 검증기 필수(c8) ✓ · DB 열+FK+CHECK+트리거 ✓ · 서버 INSERT(F179 수리) ✓ · 실왕복 ✓. **화면이 사건 발화 없이 서도 어떤 초록도 안 깨진다** — 새는 방향은 언제나 통과.
- 소급불가 성격: 개원 전 손실 **0**(교정 생산도 열람도 아직 없다). 손실은 **학생이 교정을 처음 보는 날** 시작되고, 그날 이후는 「봤는지」를 영영 못 되짚는다.
- **처방(반영함)**: `lib/이벤트검증.js` 에 **생산자 장부** — event_type 12종 전부 「누가 낸다(파일)」 xor 「왜 아직 없다(사유)」. 회귀가 ①전 사건 등재 ②파일 지목형은 그 파일에 그 문자열 실재 ③둘 다/둘 다 아님 금지를 강제. `문턱없음`·`선택필드`와 같은 무늬(이 저장소가 이미 검증한 형태)라 새 개념이 아니다. S1-8 화면을 짓는 사람이 이 장부의 사유를 파일로 바꾸는 순간이 곧 계약 이행 선언이 된다.

### B 소견 — 계약 JSON 필드 그룹에 `session_id`·`content_id` 가 없다
DDL 열 ✓ · 서버 INSERT ✓ · C0 예시·uuid 규칙 ✓ — **이름 정본(계약 JSON §필드)만 침묵**한다. 계약이 「필드명 = L0 컬럼명」을 자기 규약으로 걸었으니 이 둘도 실려야 맞다. c9 개정 때 한 줄(지금 단독 개정을 열 무게는 아니다).

### C 소견 — 철회 약속의 기계화는 runbook 정적 검사까지다
`data_use.revoked`·`audio_deleted_at` 의 생산자 = **수동 절차**(L0 문서의 SQL runbook). `tests/철회경로.test.js` 는 그 문서의 SQL 이 NOT NULL 전열을 채우는지·자리표시자인지·재실행 안전인지 잠근다(좋은 검사) — 단 **실행층(스토리지 실삭제)은 무검증**. 규모 전 수용 가능. 첫 철회 요청이 오기 전에 리허설 왕복 1회가 맞는 시점이다.

### D 소견 — `exam.result` 생산자 0 (강사 입력 도구 미구축)
첫 실성적(TOPIK/모의) 전까지 손실 0. 장부에 사유로 등재해 두면 도구를 지을 때 자리가 보인다.

## 폐루프 책상 시험 — 행에서 학습 신호를 복원할 수 있는가

무엇을 보여줬나(task.assigned+snapshot ✅) → 뭐라 했나(WAV+body·capture_meta 관측/요청 분리 ✅) → 무엇을 고쳐줬나(corrections+error_tags ✅ 도구 실재) → **봤나·반응했나·다시 했나(🔴 = 발견 A)** → AI 가 뭘 했나(intervention ✅ 정직한 null·degraded) → 어떻게 알았나(source_kind ✅ · 추정 프로필 저장은 ①-7 문서화된 미구현).

**입력축은 완비, 결과축이 발견 A 하나에 전부 걸려 있다** — A 를 닫으면 이 설계는 엔진 학습 요건을 채운다.

## 도전안

장부·게이트를 늘리는 방향 말고 반대쪽: **S1-8 을 「화면」이 아니라 「사건 먼저」로 짓는다** — 다음 S1 작업 첫 커밋을 corrections 화면 UI 가 아니라 `correction.viewed 발화 + 실왕복`으로 시작하면(화면은 그 사건 위에 입힌다), 생산자 장부의 사유가 가장 빨리 파일로 바뀌고 소급불가 창이 최소가 된다. 결과축이 「화면 미구현」에 인질로 잡히는 구조 자체를 푸는 수다.
