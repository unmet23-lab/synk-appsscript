## 함정(겪은 것)
- **배포 점검이 취소된다**: synk-policy의 「synk.im 배포 점검」은 뒤에 push가 오면 앞 점검을 취소한다(10-08 Care 세션이 몇 분 간격으로 올려 내 점검·재실행이 두 번 취소됨). 내 커밋을 품은 판의 점검 결과를 보고, 그 사이 `try/`가 바뀌지 않았는지 `git diff --name-only <내 커밋> origin/main -- try/`로 본다. GitHub Pages가 잠깐 503을 주면 점검이 실패하니, 그 주소가 지금 200인지 보고 실패한 점검만 다시 돌린다(`gh run rerun <id> --failed`).
- **`push_mine3.py`가 「바꿀 원래 줄을 origin 판에서 하나로 못 찾음」으로 멈출 때**: 로컬 master의 같은 줄에 다른 세션의 미푸시 변경이 있다는 뜻이다. origin 판을 새로 읽어 내 부분만 바꾼 커밋을 origin 위에 만들어 올리고, 로컬에는 트리 그대로인 병합 커밋을 둔다(`.tmp/batchim-check-20261008/push_record.sh`). push가 non-fast-forward로 거절되면 fetch해서 로컬이 새 origin을 품는지 보고 다시 만든다.
- 레이싱 `qa/play.cjs`는 RACING_URL과 상관없이 `/try/racing/**`를 **스크립트 폴더의 원본 파일**로 내준다. 공개 후보를 시험하려면 그 스크립트를 후보 폴더(`cand/try/racing/qa/`)에 복사해 돌리고, 공개 전에 그 `qa/`를 지운다. 로컬 원본을 볼 때는 experiences 폴더를 서버 뿌리로 띄운다(`/experiences/` 아래로 띄우면 「다른 게임 링크」가 걸린다).
