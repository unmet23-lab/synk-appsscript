# 원격 CI 되살리기 — 셀프호스티드 러너 설치 (유호님 몫)

> 유호 확정 2026-08-18 「2로 간다」. **저장소 쪽 배선은 전부 끝나 있다** — 유호님이 하실 것은
> ①노트북에 러너를 세우고 ②GitHub 화면에서 스위치 하나를 켜는 것, 둘뿐이다.
>
> ⛔ **러너 등록 토큰은 자격증명이다.** GitHub 화면에서 받아 노트북에서만 쓴다 — 채팅에 붙여넣지 않는다.

---

## 왜 이걸 하나 (한 줄)

무료 3,000분으로는 이 저장소를 못 버틴다. **실측**: 스위트 2.7분 × 하루 머지 PR 71건(08-17)
= **월 5,760분**. 하루 커밋은 792건이었다. 상한을 아끼는 게 아니라 **상한 자체를 없애야** 하는
자리라 GitHub 호스팅 러너로는 원리상 안 된다. 셀프호스티드는 분을 안 쓴다.

## 왜 하필 **리눅스**로 세우나 (이게 급소다)

노트북은 win32 다. 러너를 윈도우로 세우면 원격 CI 가 **로컬 검사와 같은 축**을 재게 된다 —
즉 원격을 켜도 새로 보이는 게 없다. 실제로 08-18 에 리눅스에서만 잡힌 결함이 3건 있었다
(F617: 「윈도우에서 초록이던 검사 3건이 리눅스에서 무너졌다」). 그 축을 지키려고 리눅스로 세운다.

워크플로가 `runs-on: [self-hosted, linux]` 로 **리눅스 라벨을 요구**하므로, 윈도우 러너를 세우면
그냥 안 잡힌다(조용히 잘못된 축을 재느니 안 잡히는 게 낫다).

---

## 1단계 — WSL2 확인 (노트북)

Windows 검색창에 `PowerShell` 을 치고 열어서 아래를 입력한다.

```
wsl -l -v
```

- **목록이 나오면** → 이미 있다. 2단계로.
- **아무것도 없거나 오류면** → 아래를 입력하고 노트북을 **재시작**한다.
  ```
  wsl --install
  ```
  재시작 뒤 Ubuntu 창이 뜨면 사용자 이름·비밀번호를 정하라고 한다(아무거나, 기억만 하면 된다).

## 2단계 — WSL 안에 준비물 넣기

시작 메뉴에서 **Ubuntu** 를 열고 아래 한 줄을 붙여넣는다. (비밀번호를 물으면 1단계에서 정한 것)

```
sudo apt update && sudo apt install -y git curl
```

## 3단계 — GitHub 에서 러너 만들기

1. 브라우저에서 저장소 `unmet23-lab/synk-appsscript` 를 연다.
2. 위쪽 탭에서 **Settings** 를 누른다.
3. 왼쪽 목록에서 **Actions** → 그 아래 **Runners** 를 누른다.
4. 오른쪽 위 **New self-hosted runner** 버튼을 누른다.
5. **Runner image** 에서 **Linux** 를 고른다. (Architecture 는 **x64** 그대로)
6. 화면에 명령어 뭉치가 세 덩이로 나온다 — **Download** / **Configure** / (마지막에 실행).
   그 명령들을 **Ubuntu 창에** 위에서부터 순서대로 붙여넣는다.

   ⚠ 화면의 토큰은 **1시간 뒤 만료**된다. 중간에 오래 쉬었으면 이 페이지를 새로 고쳐 다시 받는다.

7. `Configure` 중에 질문이 몇 개 나온다:
   - `Enter the name of the runner group` → 그냥 **엔터**
   - `Enter the name of runner` → 그냥 **엔터**
   - `Enter any additional labels` → **`linux`** 라고 치고 엔터  ← **이걸 꼭 넣는다**
   - `Enter name of work folder` → 그냥 **엔터**

8. 마지막 줄을 실행한다.
   ```
   ./run.sh
   ```
   `√ Connected to GitHub` 과 `Listening for Jobs` 가 뜨면 성공이다.
   **이 창은 켜 둔다** — 러너 프로그램이 살아 있어야 검사가 돈다.

## 4단계 — 스위치 켜기 (마지막)

1. 같은 저장소 **Settings** → 왼쪽 **Secrets and variables** → **Actions** 를 누른다.
2. 위쪽 탭에서 **Variables** 를 고른다.
3. **New repository variable** 버튼.
4. **Name** 칸에 `SYNK_SELFHOSTED`, **Value** 칸에 `on` 을 넣고 저장한다.

끝이다. 다음 푸시부터 검사가 돈다.

---

## 확인하는 법

- **Settings → Actions → Runners** 에 초록색 **Idle** 이 보이면 러너가 살아 있는 것이다.
- 저장소에서 `node tools/원격ci.js` 를 돌리면 지금 커밋이 원격에서 초록인지 말해 준다.
  - `✅ 초록` = 진짜로 검사가 돌고 통과했다.
  - `🔴 건너뜀` = 스위치가 꺼져 있다(4단계를 안 했거나 값이 `on` 이 아니다). **로그를 열 필요 없다 — 비어 있다.**
  - `⏳ 대기` = 러너가 잡아서 도는 중이거나, 러너가 꺼져 있어 줄 서 있는 것이다.

## 끄고 싶으면

4단계의 변수 `SYNK_SELFHOSTED` 값을 지우거나 변수를 삭제한다. 그러면 job 이 아예 안 떠서
**분도 안 쓰고 큐에도 안 쌓인다.** 워크플로 파일은 손댈 필요 없다.

---

## 알아 둘 대가

- **노트북이 꺼져 있으면** 검사는 줄을 선다. 켜면 밀린 것이 돈다(낡은 판은 자동 취소된다).
  줄 서 있는 동안은 「초록」이 아니라 **「대기」**로 나온다 — 미검증을 통과로 안 읽는다.
- **비용**: 지금 셀프호스티드는 무료다(GitHub 문서 기준). 다만 GitHub 가 2026-03-01 부터
  유료화하겠다고 예고했다가 **보류**한 이력이 있다. 지금은 무료지만 한 번 겨냥됐던 자리라,
  청구서에 뭔가 뜨면 그때 다시 판단한다.
- **보안**: GitHub 자신이 「셀프호스티드는 private 저장소에서만 쓰라」고 권한다. 이 저장소는
  private 이고 사용자가 유호님 1인이라 그 위험(포크해서 PR 여는 사람)은 사실상 0이다.
- **안 잰 것**: 「스위치가 꺼진 job 은 분을 안 쓴다」는 GitHub 문서의 동작이지 이 저장소에서
  실측하진 못했다(Actions 가 08-14 이후 죽어 있어 잴 대상이 없었다). 켠 뒤 첫 달 청구에서 본다.
