## ▶ 이거 하나

시작 메뉴에서 **Ubuntu** 를 열고, 저장소 폴더로 가서:

```
bash tools/러너설치.sh
```

끝이다. 스크립트가 준비물 확인 → 러너 최신판 확인 → 내려받기 → **체크섬 검증** →
등록 토큰 발급 → 러너 등록(라벨 `linux`) → 서비스 등록 → 스위치 켜기까지 다 한다.

막히면 **그 자리에서 멈추고 「무엇을 하면 되는지」를 그대로 찍는다**(조용히 넘어가지 않는다).
그 문구를 그대로 알려 주면 이어서 처리한다.

### 지금 상태만 보고 싶으면

```
bash tools/러너설치.sh --확인
```

아무것도 안 바꾸고 **러너가 섰는지 · 스위치가 켜졌는지**만 말해 준다.

## 처음이라 WSL 이 없다면 (한 번만)

Windows 검색창에 `PowerShell` 을 치고 열어서:

```
wsl -l -v
```

- 목록에 배포판이 나오면 → 이미 있다. 위 「이거 하나」로 간다. **`VERSION` 이 2인지 본다**
  (1이면 서비스 등록이 안 된다).
- 아무것도 없거나 오류면 → 아래를 실행하고 **노트북을 재시작**한다.
  ```
  wsl --install
  ```

### 🔴 재시작했는데 아무것도 안 뜨고 비밀번호도 안 물어본다면 (08-18 실측)

`wsl --install` 은 **두 가지**를 한다: ①WSL 기능 켜기 ②우분투 본체 내려받기.
실측에서 ①만 되고 ②가 조용히 빠졌다 — 그러면 **아무 창도 안 뜨고 아무것도 안 물어본다.**
비밀번호는 우분투를 처음 켤 때 묻는 것이라, 우분투가 없으면 물어볼 대상 자체가 없다.

⚠ 이 자리가 헷갈리는 이유: 「설치가 실패했다」가 아니라 **「조용히 절반만 됐다」**라서
화면상으로는 아무 일도 안 일어난 것과 같은 모양이다.

→ **Microsoft Store 에서 `Ubuntu`**(제작사 `Canonical Group Limited`)를 검색해 직접 설치한다.
   받아지면 **「열기」** → 검은 창이 뜨고 `Installing, this may take a few minutes...` 가
   몇 분 돈 뒤 사용자 이름·비밀번호를 묻는다.

🔑 **비밀번호를 칠 때 화면에 아무것도 안 나타난다** — 별표조차 안 뜬다. 안 쳐지는 게 아니라
   원래 안 보이는 것이다. 그냥 치고 Enter, 한 번 더 치고 Enter.
   (이 비밀번호는 `sudo` 를 쓸 때 다시 필요하다. 채팅·문서에 적지 않는다.)

### 준비물 (스크립트가 요구하는 것을 미리 깐다)

안 깔고 실행해도 스크립트가 멈춰서 알려 주지만, 그러면 왕복이 는다. Ubuntu 창에 통째로:

```
sudo apt update && sudo apt install -y curl tar git coreutils wget
sudo mkdir -p -m 755 /etc/apt/keyrings
wget -qO- https://cli.github.com/packages/githubcli-archive-keyring.gpg | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg >/dev/null
sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list >/dev/null
sudo apt update && sudo apt install -y gh
gh auth login
```

`gh auth login` 은 **GitHub.com → HTTPS → Yes → Login with a web browser** 로 답하고,
나오는 8자리 코드를 브라우저에 붙여 승인한다. `✓ Logged in as …` 가 뜨면 된다.

그 다음 Ubuntu 창에서 저장소 폴더로 이동한다. 윈도우의 `C:\Users\...\SYNK-appsscript` 는
WSL 에서 `/mnt/c/Users/.../SYNK-appsscript` 로 보인다. 경로를 모르면 찾게 한다:

```
find /mnt/c/Users -maxdepth 4 -iname "*synk*" -type d 2>/dev/null
```

## 왜 하필 리눅스로 세우나 (급소)

노트북은 win32 다. 러너를 **윈도우로 세우면 원격 CI 가 로컬 검사와 같은 축**을 재게 되어,
켜도 새로 보이는 게 없다. 실제로 08-18 에 리눅스에서만 잡힌 결함이 3건 있었다
(F617: 「윈도우에서 초록이던 검사 3건이 리눅스에서 무너졌다」).

그래서 워크플로가 `runs-on: [self-hosted, linux]` 로 **리눅스 라벨을 요구**한다 —
윈도우 러너를 세우면 job 이 아예 안 잡힌다. 조용히 잘못된 축을 재느니 안 잡히는 게 낫다.

## 왜 무료 3,000분으로는 안 되나

실측 2026-08-18: 스위트 2.7분 × 하루 머지 PR 71건 = **월 5,760분**. 하루 커밋은 792건이었다.
push 는커녕 **PR 단위로 줄여도 못 버틴다** — 상한을 아끼는 문제가 아니라 상한 자체를
없애야 하는 문제라 GitHub 호스팅 러너로는 원리상 안 닫힌다. 셀프호스티드는 분을 안 쓴다.

## 확인하는 법

| 명령 | 무엇을 말해 주나 |
|---|---|
| `bash tools/러너설치.sh --확인` | 러너가 섰나 · **켜져 있나** · 스위치가 켜졌나 (세 갈래) |
| `node tools/원격ci.js` | 지금 커밋이 원격에서 **초록인가** |

`원격ci.js` 가 내는 답 셋:

- **✅ 초록** — 진짜로 검사가 돌고 통과했다.
- **🔴 건너뜀** — 스위치가 꺼져 있다. **로그를 열 필요 없다(비어 있다).**
  `bash tools/러너설치.sh --스위치만` 으로 켠다.
- **⏳ 대기** — 러너가 잡아서 도는 중이거나, 러너가 꺼져 있어 줄 서 있는 것이다.

⚠ **`원격ci.js` 는 `gh` 가 있어야 돈다** — 클라우드 세션(웹 Claude Code)에는 `gh` 가 없어서
「❔ 모름」만 낸다. 초록으로 접지 않는 건 설계대로지만, 그 세션은 GitHub API 로 직접 봐야
한다(F646 · 아직 안 고쳤다).

### `--확인` 이 내는 세 갈래 (2026-08-19 부터)

- **🟢 셋 다 섰다** — 등록 + **온라인** + 스위치 on. 원격 CI 가 실제로 돈다.
- **⏸ 러너가 오프라인이다** — 등록·스위치는 서 있고 **기계가 꺼져 있을 뿐**이다.
  **다시 설치할 것이 없다.** 켜면 밀린 job 을 그때 잡는다(실측 08-19: 10시간 줄 섰던 job 을
  노트북을 켜자 4초 만에 잡았다). 그동안 검사는 「초록」이 아니라 **「대기」**다.
- **⬜ 아직이다** — 러너가 없거나 스위치가 꺼져 있다. 이때만 설치·스위치 처방이 나온다.

🔴 **왜 갈래를 나눴나 (F649 실측)**: 옛 판은 오프라인·미등록을 한 칸으로 뭉쳐 「없음 → 세우려면
설치하라」를 냈다. 게다가 라벨을 소문자 `linux` 로만 찾아 GitHub 가 붙인 **`Linux`**(대문자)를
못 봤고, **job 을 돌리는 중인 러너를 「없다」고 말했다.** 그 처방을 따랐으면 멀쩡한 러너를
215MB 다시 깔았다 — 따를수록 같은 자리로 돌아오는 처방이다(F103).

## 끄고 싶으면

GitHub → 저장소 **Settings → Secrets and variables → Actions → Variables** 에서
`SYNK_SELFHOSTED` 값을 지우거나 변수를 삭제한다. 그러면 job 이 아예 안 떠서
**분도 안 쓰고 큐에도 안 쌓인다.** 워크플로 파일은 손댈 필요 없다.

---

## 손으로 하고 싶을 때 (스크립트가 막혔을 때만)

1. 저장소 → **Settings** → 왼쪽 **Actions** → **Runners** → **New self-hosted runner**
2. **Linux** / x64 를 고르면 나오는 명령을 Ubuntu 창에 순서대로 붙여넣는다.
   ⚠ 화면의 토큰은 **1시간 뒤 만료**된다 — 오래 쉬었으면 페이지를 새로 고친다.
3. `Enter any additional labels` 를 물으면 **`linux`** 를 친다. ← 이걸 안 넣으면 job 이 안 잡힌다.
4. 마지막에 `./run.sh` — `√ Connected to GitHub` · `Listening for Jobs` 가 뜨면 성공이다.
5. **Settings → Secrets and variables → Actions → Variables → New repository variable**
   이름 `SYNK_SELFHOSTED` · 값 `on`.

## 알아 둘 대가

- **노트북이 꺼져 있으면** 검사는 줄을 선다. 켜면 밀린 것이 돈다(낡은 판은 자동 취소).
  줄 서 있는 동안은 「초록」이 아니라 **「대기」**로 나온다 — 미검증을 통과로 안 읽는다.
- **서비스 등록이 실패할 수 있다** — WSL 에 systemd 가 꺼져 있으면 그렇다. 그때 스크립트는
  `./run.sh` 로 띄우는 법을 안내하고 **스위치를 안 켠다**(러너 없이 켜면 검사가 줄만 선다).
- **비용**: 지금 셀프호스티드는 무료다(GitHub 문서 기준). 다만 GitHub 가 2026-03-01 부터
  유료화하겠다고 예고했다가 **보류**한 이력이 있다 — 청구서에 뭔가 뜨면 그때 다시 판단한다.
- **보안**: GitHub 자신이 「셀프호스티드는 private 저장소에서만 쓰라」고 권한다. 이 저장소는
  private 이고 사용자가 유호님 1인이라 그 위험(포크해서 PR 여는 사람)은 사실상 0이다.
- **첫 실행에서 실제로 터졌다 (F642 · 수리 완료)** — 이 스크립트는 짤 때 **끝까지 실행해
  보지 못했다**(클라우드 컨테이너엔 러너를 세울 수 없고 프록시가 릴리스 API 를 막는다).
  그래서 fail-closed 로 짰고, 08-18 첫 실행이 **3/7 검증에서 멈췄다**:
  릴리스에서 체크섬을 뽑을 때 **형제 파일(win-x64)의 값**을 집어, 멀쩡히 받은 215MB 를
  남의 값과 대조한 것이다(body 가 한 줄이라 `grep -A2` 가 안 좁혀지고 `head -1` 이 맨 위를
  집었다). 🔴 급소는 「안 돌았다」가 아니라 **돌면서 남의 값을 냈다**는 것 — 그리고 그때 낸
  처방이 「지우고 다시 받아라」여서, 따랐으면 215MB 를 다시 받고 똑같이 터졌다(F103).
  → 마커(`BEGIN SHA linux-x64`) 기준으로 고치고 회귀 4건을 붙였다(`tests/러너설치.test.js`).
  ⚠ 남은 교훈: **막힌 자리에서 스크립트가 낸 처방부터 의심한다** — 완주한 다운로드(`100 215M`)를
  보고도 「받다 만 파일」이라는 처방을 그대로 따르면 원인을 영영 못 만난다.
- **아직 못 잰 것**: 「스위치가 꺼진 job 은 분을 안 쓴다」는 GitHub 문서의 동작이고,
  0초 종료로 정황은 봤지만 **청구서로는 아직 못 쟀다**.
