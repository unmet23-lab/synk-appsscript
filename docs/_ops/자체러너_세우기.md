# 자체 리눅스 러너 세우기 — 전체 시험을 push마다 원격에서 돌리기 (2026-10-03)

> 2026-10-03에 작성한 선택 가능한 CI 설치안이다. 새 노트북의 필수 설정이나 이미 설치된 러너의 기록이 아니다. 단, 10-21에 실제로 세운 SYNK-talk Windows 실행기는 아래 「SYNK-talk Windows 자체 실행기」 절이 기록이다. 10-18 자동시험 복구 요청으로 `.github/workflows/syntax-check.yml`에 `SYNK_HOSTED_CI=on` 선택을 더했다. 공개 저장소 또는 이 변수가 켜진 저장소는 GitHub `ubuntu-latest`를, 그 밖에는 `SYNK_SELFHOSTED=on`일 때 `[self-hosted, linux]`를 사용한다. 구문·Atlas 사본·루트 JS 시험·저장소 보존·prism 검사를 수행하며 저장소 전체의 모든 시험을 뜻하지 않는다.
> 아래 10-03 기준 실행 수·요금제·사용량 계산은 당시 관측이다. 현재 한도나 이미 설치된 러너의 증거로 쓰지 않는다. 이 CI 러너는 작업용 LLM 실행기와 다르다.

10-18에는 GitHub 계정의 Actions 예산 $0, `Stop usage when budget limit is reached` 켜짐, 결제수단 없음을 로그인한 예산 화면에서 확인한 뒤 `SYNK_HOSTED_CI=on`을 설정했다. 예산·결제 설정은 변경하지 않았다. 무료 포함량을 다 쓰면 원격 시험은 제한될 수 있으며 예산 상향·결제수단 추가로 자동 우회하지 않는다. 실제 실행 결과는 [백엔드 검증 기록](qa/backend-upgrade-20261018/result.json)의 `integration`을 본다. 아래 WSL·자체 러너 설치는 선택 사항이다.

10-18 후속: `windows-specific` 잡은 희소 체크아웃과 Node만으로 Windows 전용 4건을 실행하고 통과 수·건너뜀0을 확인한다. 자격 어댑터는 메모리 mock이라 실제 Windows 자격 보관소를 읽거나 바꾸지 않는다. Linux의 해당 4건 건너뜀은 이 잡의 실제 결과와 함께 읽는다.

Strata 원문 재생성과 계약 교차 대조 2건에는 비공개 `SYNK-talk` 원문이 필요하다. 10-18 사용자는 이 원문을 GitHub 자동시험에서 읽도록 승인했다. GitHub 기본 토큰은 현재 저장소만 읽을 수 있으므로 Talk 한 저장소에 붙이는 전용 읽기 SSH 키를 쓴다([GitHub deploy key 범위](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys#deploy-keys)). 로컬 실제 원문 검사는 `SYNK_TALK_ROOT`를 지정해 실행한다.

10-18 Talk에 deploy key `read_only=true`를 등록하고 이 저장소의 암호화된 Actions secret `SYNK_TALK_READ_SSH_KEY`와 `SYNK_TALK_CI=on`을 연결했다. 개인 계정 토큰은 복사하지 않았다. CI는 Talk의 `package.json`·문항 팩·태그 표·`계약/`만 내려받고 엄격한 SSH 호스트 확인과 `persist-credentials: false`를 쓴다. 원문이 빠지면 `SYNK_REQUIRE_TALK_SOURCE=1`이 건너뜀 대신 실패시킨다. deploy key에는 자동 만료가 없으며, 폐기할 때 Talk Settings → Deploy keys의 해당 키와 이 저장소의 해당 secret을 함께 지우고 변수를 끈다. 키 ID·읽기 권한·두 검사의 실제 GitHub 통과 결과는 검증 원문의 `integration.ciSkipAudit`에 남겼다.

## SYNK-talk Windows 자체 실행기 (2026-10-21 설치 · 지금 돈다)

- 자리: 이 PC `C:\Users\q1212\actions-runner-talk`(공식 actions/runner v2.338.0 win-x64, 해시 대조), talk 저장소 하나에만 등록 — 이름 `synk-pc-talk`, 라벨 `self-hosted, Windows, X64, synk-pc`, 작업 폴더 `_w`.
- 켜 두기: 예약 작업 「SYNK talk CI 실행기」(로그온 때 · 배터리에서도 · 시간 제한 없음)가 `pythonw start_hidden.py`로 창 없이 `run.cmd`를 띄우고, 실행기가 죽으면 1분 뒤 다시 띄운다(등록이 지워지면 멈춤). 잡의 npm 캐시는 실행기 폴더 `_npm-cache`에 따로 둔다. 기록은 `_diag\run-hidden.log`·`_diag\Runner_*.log`.
- 맡는 잡: talk `ci.yml`의 verify와 `backend-release.yml`(codex/backend-* 가지). talk 저장소 변수 `SYNK_HOSTED_CI=on`이면 둘 다 호스팅(ubuntu-latest)으로 돌아간다 — PC를 오래 끌 때 쓴다. PC가 꺼져 있으면 잡은 최대 24시간 줄을 선다.

- 끄기: `Stop-ScheduledTask -TaskName 'SYNK talk CI 실행기'`(다시 켜기는 `Start-ScheduledTask`). 지우기: 예약 작업 지우기 → `gh api -X POST repos/unmet23-lab/SYNK-talk/actions/runners/remove-token`의 토큰으로 `config.cmd remove --token <토큰>` → 폴더 지우기 → talk 워크플로의 `runs-on`을 `ubuntu-latest`로.

## 1. WSL2 우분투 설치 (관리자 PowerShell, 한 번)

```
wsl --install -d Ubuntu-24.04
```

다시 시작한 뒤 우분투 창에서 사용자 이름·암호를 만든다. C 드라이브를 5GB 안팎 더 쓴다(저장소 체크아웃 약 3GB). 리눅스로 세우는 까닭: 이 PC(윈도우)에서 초록이던 검사가 리눅스에서 깨진 일이 있다(F617). 워크플로가 `linux` 레이블을 요구한다.

## 2. 러너 내려받고 등록 (우분투 창)

GitHub `unmet23-lab/synk-appsscript` → Settings → Actions → Runners → **New self-hosted runner** → Linux · x64 를 고르면 나오는 명령을 차례로 붙여 넣는다(`mkdir actions-runner && cd actions-runner` → 내려받기 → `./config.sh --url … --token …`). 레이블은 기본값(self-hosted, Linux, X64) 그대로 둔다. 토큰은 그 화면에만 쓰고 어디에도 적지 않는다.

## 3. 켜 두기 (우분투 창, `actions-runner` 폴더에서)

```
sudo ./svc.sh install
sudo ./svc.sh start
```

서비스로 두지 않으려면 필요할 때 `./run.sh`를 띄워 둔다.

## 4. 스위치 켜기 (GitHub)

Settings → Secrets and variables → Actions → **Variables** → New repository variable — 이름 `SYNK_SELFHOSTED`, 값 `on`. 끌 때는 이 변수를 지운다.

## 5. 확인

```
gh workflow run syntax-check.yml --ref master
gh run list --workflow syntax-check.yml --limit 1
```

첫 run이 초록이면 끝이다. 빨가면 로그 맨 끝 「깨진 검사만 다시」 묶음에 실패한 검사 이름이 모여 있다.
