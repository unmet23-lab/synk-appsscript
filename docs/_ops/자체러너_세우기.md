# 자체 리눅스 러너 세우기 — 전체 시험을 push마다 원격에서 돌리기 (2026-10-03)

> 2026-10-03에 작성한 선택 가능한 CI 설치안이다. 새 노트북의 필수 설정이나 이미 설치된 러너의 기록이 아니다. 현재 `.github/workflows/syntax-check.yml`은 공개 저장소에는 GitHub 러너를, 비공개 저장소에는 `SYNK_SELFHOSTED=on`일 때만 `[self-hosted, linux]`를 사용한다. 구문·Atlas 사본·시험·prism 검사를 수행한다.
> 당시 67개 run의 `skipped`와 요금제·월간 사용량 계산은 아래 날짜의 관측이다. 현재 저장소 변수·등록 러너·대기 작업·과금 조건은 이번 문서 정리에서 조회하지 않았다. 설치를 재개할 때 실제 상태와 기존 러너를 먼저 확인하고 중복 설치하지 않는다. 이 CI 러너는 폐기된 작업용 LLM 실행기와 다르다.

## 1. WSL2 우분투 설치 (관리자 PowerShell, 한 번)

```
wsl --install -d Ubuntu-24.04
```

다시 시작한 뒤 우분투 창에서 사용자 이름·암호를 만든다. C 드라이브를 5GB 안팎 더 쓴다(저장소 체크아웃 약 3GB). 리눅스로 세우는 까닭: 이 PC(윈도우)에서 초록이던 검사가 리눅스에서 깨진 일이 있다(F617). 워크플로가 `linux` 레이블을 요구한다.

## 2. 러너 내려받고 등록 (우분투 창)

GitHub `unmet23-lab/synk-appsscript` → Settings → Actions → Runners → **New self-hosted runner** → Linux · x64 를 고르면 나오는 명령을 차례로 붙여 넣는다(`mkdir actions-runner && cd actions-runner` → 내려받기 → `./config.sh --url … --token …`). 레이블은 기본값(self-hosted, Linux, X64) 그대로 둔다. 토큰은 그 화면에만 쓰고 어디에도 적지 않는다.

## 3. 켜 두기 (우분투 창, `actions-runner` 폴더에서)

```
sudo ./svc.sh install
sudo ./svc.sh start
```

서비스로 두지 않으려면 필요할 때 `./run.sh`를 띄워 둔다.

## 4. 스위치 켜기 (GitHub)

Settings → Secrets and variables → Actions → **Variables** → New repository variable — 이름 `SYNK_SELFHOSTED`, 값 `on`. 끌 때는 이 변수를 지운다.

## 5. 확인

```
gh workflow run syntax-check.yml --ref master
gh run list --workflow syntax-check.yml --limit 1
```

첫 run이 초록이면 끝이다. 빨가면 로그 맨 끝 「깨진 검사만 다시」 묶음에 실패한 검사 이름이 모여 있다.

## 10-03 기준 상태

- 깨끗한 체크아웃(git에 있는 파일만)에서 `node tools/test-ci.js`(UTC·빈 홈·`CI=true`, win32): 1,854개 중 통과 1,845 · **실패 0** · 건너뜀 9. 건너뜀마다 사유가 붙는다 — git 밖 자료(`_검토/` 기록·키트 사본·빌드 산출물 등, `tests/_git밖.js`), 등록 묶음이 없는 검수 꾸러미, 코덱스 자격·캐시 없음 같은 것들이다. 처음 돌렸을 때는 10개가 실패했고(모두 git 밖 자료) 같은 날 고쳤다.
- 이 PC 작업본 전체 시험: 1,862개 중 통과 1,857 · 실패 0 · 건너뜀 5.
- 리눅스에서는 아직 한 번도 안 돌았다 — 첫 원격 run이 그 판정이다. 플랫폼 차이로 깨지는 검사가 나오면 그때 고친다.
- 참고: SYNK-talk CI는 GitHub 호스팅 러너(`ubuntu-latest`)로 push·PR마다 3~5분 돈다. 10-03 속도(2.6일에 약 337분)로는 한 달 약 3,960분이라 무료 3,000분을 넘는다. 같은 러너를 talk 저장소에도 등록하고 talk 워크플로의 `runs-on`을 `[self-hosted, linux]`로 바꾸면 한도 걱정이 없어진다(talk 담당).
