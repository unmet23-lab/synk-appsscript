# 앱 예약 작업의 작업 자리

앱 예약 작업이 회차마다 지시문 머리말에서 이 문서를 읽는다. 이 문서는 예약 작업 전용이다. 바꾸면 다음 회차부터 적용된다. 결정 근거는 [결정 표](결정.md) 11-03 「앱 예약 작업은 회차마다 워크트리에서」, 함정은 [현장 노트 · git](../현장노트/git_줄끝_잠금.md).

## 왜

앱 예약 작업은 cwd가 공용 작업본으로 고정이다. 거기서 파일을 고치면 공용 작업본이 origin을 못 따라가고(10-22 122커밋 · 11-03 145커밋 뒤), 낡은 문서를 읽는다. 그래서 회차마다 origin 판 워크트리에서 일한다. 공용 작업본은 **git 밖 영상 창고**로만 쓴다.

## 시작

1. `EnterWorktree`(name `sched-<작업 id>-<MMDD>-<HHmm>`, 영문 · 숫자 · 대시만). 실패하면(이름 충돌 · 이미 다른 워크트리 안 등) 공용 작업본에 쓰지 말고 멈춰 보고한다.
2. `node tools/예약사본.js 들기 --실행` — 뿌리 `node_modules`를 잇고, 멈춘 회차의 git 밖 영상을 넘긴다. 출력에 남은 사본과 미커밋 파일이 보인다.
3. 미디어: `EnterWorktree` 사본에는 docs/캐릭터 · docs/홍보물 · docs/라디오와 docs/마케팅의 소리 · 그림 파일까지 모두 있다(git 훅을 타지 않는다, 제작 품질 때문에 그대로 둔다 — 결정 11-04). 혹시 빠져 있으면(`git config core.sparseCheckout`이 true) 필요한 폴더만 `node tools/바로올리기.js 가볍게 --되살림 <폴더…> --실행`(BGM `docs/홍보물/BGM`, 마스코트 정본 `docs/캐릭터/정본_4K`, 이어 만드는 편 · 본뜨는 옛 편은 그 편 폴더).
4. 지난 편의 git 밖 영상(remotion/out · 게시/*.mp4 · 장면)은 공용 작업본(`C:/Users/q1212/Documents/SYNK-appsscript`) 같은 경로에서 읽는다. 도구(예약큐 · 올리기 전 검사 · 낯선이시험 · 무대반복 · 오마주)는 저절로 거기까지 찾는다.
5. 새 편의 `remotion/node_modules`는 공용 작업본의 가장 최근 같은 브랜드 편(`C:/Users/q1212/Documents/SYNK-appsscript/docs/마케팅/<편>/remotion/node_modules`)으로 junction을 건다(`New-Item -ItemType Junction`). npm 설치를 다시 하지 않는다. `넘기기`와 `끝`이 공용 쪽 링크 · 끊기를 맡는다.
6. 지시문의 `synk-vendor/…`는 저장소 옆 폴더 `C:/Users/q1212/Documents/synk-vendor`다. 워크트리에 없다고 새로 만들지 않는다.
7. 공용 작업본에는 쓰지 않는다. 운영 사본(`C:/Users/q1212/AppData/Local/synk/ops/SYNK-appsscript`, 아래 `$OPS`)은 아래 도구로만 쓴다.

## 일하는 동안

- 임시 스크립트 · 메모는 scratchpad나 `.tmp/` 아래에 둔다. 끝의 `--모두`가 워크트리 안 새 파일을 그대로 공개 저장소에 올린다.
- 복잡한 한 줄 명령이 「isolated in the worktree」로 막히면 명령을 나누거나, 스크립트를 scratchpad에 Write해서 돌린다.
- 편을 만드는 작업은 단계 경계마다(기획 뒤 · 관문 통과 뒤 · 게시 묶음 뒤) `node tools/예약사본.js 넘기기 --실행` → `node tools/바로올리기.js --모두 -m "…" --실행`으로 올린다. 한도로 멈춰도 다음 회차가 origin에서 이어 받는다. 공개 저장소이므로 공개하면 안 되는 내용은 평소처럼 넣지 않는다.
- **「작업실등록」: true가 든 커밋을 올리기 전에 반드시 `넘기기 --실행`** — 30분마다 도는 예약큐가 공용 작업본에서 영상을 찾는다.
- 작업실등록 true를 올린 뒤 최종본을 다시 렌더하면 큐가 옛 판을 이미 등록했을 수 있다: `$OPS` 도구로 `취소` → 검사 → `넘기기 --실행` → 올리기.

## 작업실 등록 · 상태 · 취소

세션 워크트리의 편은 도구가 거절한다(같은 편을 두 번 등록하지 않으려고). 운영 사본의 도구와 편 경로로 부른다. 기록은 도구가 origin에 올린다.

```
node "$OPS/tools/작업실예약.js" "$OPS/docs/마케팅/<편>" --실행
node "$OPS/tools/작업실예약.js" 상태 "$OPS/docs/마케팅/<편>" --캐시
node "$OPS/tools/작업실예약.js" 취소 "$OPS/docs/마케팅/<편>"
```

부른 뒤 같은 편의 게시결과.json을 고치려면 먼저 `node tools/바로올리기.js 따라가기 --실행`으로 워크트리를 origin에 맞춘다. 준비.json을 고쳐 올린 뒤 등록하기 전에는 `node "$OPS/tools/운영사본.js" 갱신 --실행`으로 운영 사본을 맞춘다.

## 게시 성과

판정 기록을 쓰는 곳은 운영 사본 하나다(공용 작업본 · 워크트리에서 돌리면 3시간마다 도는 운영 사본 판정과 겹친 줄이 생긴다). `node "$OPS/tools/게시성과.js" --화면목록` · `--적기 … --실행` · `--실행`. 도구가 스스로 올린다.

## 끝

1. 바뀐 것을 `node tools/바로올리기.js --모두 -m "…" --실행`으로 올린다(미리 보기는 `--실행` 없이).
2. `node tools/예약사본.js 끝 --실행`
   - 「지워도 됨」이면 **그 출력 바로 다음에만** `ExitWorktree`(action `remove`, discard_changes true). 워크트리 가지의 커밋은 공용 로컬 master에 없어 discard_changes가 늘 필요하고, 잃는 것이 없는지는 `끝`이 본다.
   - 「남은 것 있음」이면 올리거나 고친 뒤 다시 돌린다. 끝내 못 끝내면 `ExitWorktree`(action `keep`)하고 보고 첫 줄에 남은 것과 워크트리 경로를 적는다.
   - 그 밖의 오류 · 거절은 모두 `keep`이다.

## 멈췄다 깨어난 회차

- `/이어서`로 깨어났는데 지금 폴더가 `.claude/worktrees/sched-…`가 아니면, 그 회차가 쓰던 워크트리(`git worktree list` · `들기` 출력)로 `EnterWorktree`(path)로 돌아가 잇는다. 새 워크트리를 파서 같은 칸을 또 만들지 않는다.
- 새 회차에서 장부에 「제작 중」 줄이 있는데 그 편 폴더가 내 워크트리에 없으면, `들기` 출력의 미커밋 목록에서 그 편을 찾아 그 워크트리 폴더에서 복사해 잇고 그 워크트리는 그대로 둔다(`ListAgents`로 그 줄을 만드는 세션이 도는 중이면 건드리지 않는다).
