## 1. 무엇을 고쳤는가

### Apps Script

- **오래 걸리는 정기 작업:** 아침·야간·10분 순회 작업을 150초 또는 최대 6단계 단위로 나눈다. 진행 위치를 저장하고 임시 이어하기 예약으로 계속한다. 긴 잠금을 하위 함수에 넘기지 않으며, 중단 뒤 결과가 불확실하면 자동 재실행으로 중복 발송하지 않는다.
- **부분 실패 표시:** 보호 중인 시트 헤더를 고치지 못했는데 완료로 기록하던 경우를 부분 실패로 남긴다. report_cards의 기존 H:L 등 원본 학생 칸을 보존한다.
- **월간 보고 전달:** 생성과 발송 완료를 구분한다. 발송 전 준비/한도 실패는 대기로 남겨 재시도하고, 발송 응답이 불확실한 경우는 자동 재발송하지 않는다. 기존 PNG·본문을 재사용할 때 학생·월·원본 연결을 확인한다.
- **누락된 순간 예약:** 전체 예약을 재설정하지 않고 momentSweepJob 하나만 추가했다. 사진·순간 폴더 처리→portfolio_moments→학생 걸어온 길/알림/운영판을 잇는 기존 기능이다.
- **소유자 전용 점검:** 실제 활성 계정·실행 계정·지정 관리자 세 값이 같을 때만 허용한다. 학생 행·키·메일 본문 없이 예약과 고정 진행 상태 집계만 반환한다. 원격 실행에서는 기존 ENGINE_SS_ID로 시트를 읽는 대체 경로도 검증했다.
- 같은 배포를 쓰는 Meta 담당의 최종 안전 수정을 함께 보존했다. 토큰 이상 시 유료 AI 호출 전 수동 인계, 실제 첫 전송 성공 기준 봇 고지, 민감 오류 노출 제한 등이 포함된다. 홈페이지/Meta 고객 왕복 검증은 [해당 담당 보고](Meta_상담앱_개통보고_20260911.txt)의 별도 범위다.

- service-role 전용 서버 실행 경로와 기존 사람 확정 절차를 유지한다. 학생/익명 토큰으로 자동 교정을 실행하지 못한다.

- HTTP 200/outcome 성공·시간 초과 없음·응답 해석 정상. 대기 0/적음 0인 빈 업무 결과다. needs_attention 필드가 없어 null이며 “주의 없음”으로 바꾸지 않는다. 교정·잡·접수 집계 0 유지.
- 관측은 읽기 전용이었다. 강제 발사/수확·실학생 사건 생성·추가 유료 요청 없이 확인했다. correct-nightly 신규 제출은 아직 다음 예정 시각 전으로 미관측이다.

## 5. 확인하지 못한 것과 남은 일

1. **정상 앱 실왕복:** 사용자는 시험 계정이 없거나 잘 모르겠다고 답했다. 인증 사용자 생성·로그인 초안은 중단·미실행·배포 제외다. 실제 학생을 대신 로그인하거나 학생 기록/메일을 시험으로 만들지 않았다.
2. **학생 품질:** 합성 한 문장 형식 통과는 받아쓰기 정확도·몽골어 해설 의미·개별 학습자 교정 품질의 비교 평가가 아니다.
3. **미래 업무:** 새로운 아침/야간/월간·순간 폴더 업무·Talk 야간 신규 제출의 자연 결과, 실제 학생/학부모 수신은 해당 실행 뒤 확인해야 한다.
4. **옛 전달/옛 키:** 월간 legacy_unknown은 실제 수신 근거가 있어야 해소할 수 있다. 옛 키 폐기는 소비자 확인 뒤 판단한다.
5. **비용:** 최종 Anthropic/OpenAI 청구 명세와 월 비용 상한, 서비스 계정·키 자동 교체는 별도다.
