- 모델·예약·생성 활성 게이트·학생 데이터는 보존했다. 남은 최신 품질판 배포와 실제 학생 업무 왕복은 별도 범위다.

이 밖에 메뉴·웹·편집기·연결 점검 실행이 포함되어 총합이 1,121건이다. 수동 `replaceContentType`의 09-07 00:47 실패 1건은 자동화 실패 수에 합치지 않았다.

표준 Cloud 전환 후 자연 실행을 확인한 자동화는 `parentSweep` **8회**(04:56~06:06)다. 다른 종류의 이전 실행 기록을 전환 후 검증으로 둔갑시키지 않는다. 월간·편집 이벤트는 검증 때문에 임의로 실행하지 않았다.

### 확인된 결함과 제한

1. **실제 시간 초과 2건.** `morningJobs` 09-10 08:58:48 / 361.172초, `parentSweep` 09-09 21:26:09 / 360.805초. 둘 다 Cloud 전환 전이다. `nightJobs` 09-08 23:20도 359.321초로 한계에 근접했지만 완료 상태였다.
2. v48 아침 작업은 19개 순차 `safeRun`이며 전체 시간 예산·체크포인트·이어하기가 없다. 전 시트 헤더 검사, `syncProfiles→calcAll→명부 전송`, 조건부 추가 계산, 발송·폼 동기화가 시간을 공유한다. 실패 실행을 펼쳤으나 “사용할 수 있는 로그가 없습니다”여서 **정확한 병목은 확인 불가**다.
3. **P1: 월보 미발송 재시도 차단.** `Code.js`의 경영 월보는 메일을 보내기 전에 `doneKey`를 기록한다. 쿼터 부족·발송 예외이면 미발송인데도 같은 달 재실행이 건너뛴다. 소스 확정, 라이브 발생 여부 미확인.
4. **P1: 카드 생성=전달 완료로 취급.** `엔진_폼리포트.js`의 월간 리포트카드는 생성 행 저장 후 메일을 보낸다. 발송 실패·이메일 부재 후에도 다음 실행은 그 생성 행을 보고 제외하므로 전달 재시도가 막힌다. 소스 확정, 라이브 발생 여부 미확인.
5. `safeRun`과 일부 하위 함수가 오류를 잡고 반환하므로 “완료됨”만으로 메일 수신·Drive 사본·교정 저장·폼 갱신까지 완료라고 판정할 수 없다. 민감 업무 원문·실제 수신자 확인 없이 이번에는 실행/코드 경계까지만 검증했다.
