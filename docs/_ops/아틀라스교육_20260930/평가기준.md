# Atlas 교육 연결의 독립 평가 기준

> 2026-09-30 · 구현 담당과 분리한 평가 담당 작성. 합성 입력·현행 코드·로컬 시험 기준이며 실학생 학습 효과, 원격 동작, 운영 배포를 입증하지 않는다. 기준을 통과했다는 사실과 실제 학습이 향상됐다는 주장은 구분한다.

## 2. 재현된 기존 문제와 새 연결의 위험

**확정 문제 E01: 도움 미상이 독립 성공으로 쓰인다.** 기준선 `atlas/engine.js:198`의 `o.assisted !== true`는 `null`과 생략을 허용한다. 모듈의 `session.outcome()`은 생략을 `null`로 저장한다. 동일한 필요 관측·회차에서 `measure:'independent', value:1, assisted:null`을 주면 `outcomeBasis:'performance'`가 되고 높임말 연습의 비중이 줄어 다음 대상이 바뀐다. 명시한 `assisted:true` 대조군에서는 같은 변화가 없다.

**확정 문제 E02: 수행이 아닌 측정값도 실력으로 쓰인다.** 같은 조건에서 `measure:'satisfaction', value:1, assisted:false`를 주어도 E01과 같은 학습 대상 변화가 생긴다. `improved()`가 측정 이름을 제한하지 않는다. `measure`가 있는 것만으로 그 값이 학습 성과가 되는 것은 아니다.

두 문제는 `baseline/probe-independent.cjs`와 `baseline/independent-probes.json`으로 재현했다. 입력 6건 중 잘못된 독립 수행 사용 3건(null·생략·만족도), 양성 대조 1건(명시적 독립 수행), 음성 대조 2건(도움받음·미도래)이다. 기존 83개 Atlas 시험이 통과해도 이 문제는 남아 있었다.

현재 Talk `atlas-session.js`는 도움 설정·완료·반응을 연결하며 교육 결과용 `observe/outcome` 공개 연결이 없다. 따라서 위는 **공통 모듈에서 확인된 잠재 오류**다. 현 운영 학생의 기록이 이미 오염됐다는 증거는 아니다. 새 교육 결과를 연결하기 전에 막아야 한다. 수정에서는 이름만 `independent`인 사건도 그대로 믿지 않고, 같은 범위·판단·학습 항목에 연결된 실제 시도 근거를 확인한다.

현재 G4는 채점기의 `맞음 / 축오답 / 모름`을 유지한다. 정답·해설을 보여 준 뒤 같은 칸으로 재도전할 수 있고, 최신 답은 화면 상태에서 이전 답을 대신한다. 이는 기존 연습 흐름으로 허용되지만, 새 교육 집계에서 최신 답만 읽으면 첫 오류와 답 노출을 잃을 수 있다. 이 위험을 현재의 확정 성과 오집계라고 단정하지 않는다.

## 4. 분모와 시간창

지표마다 분자·분모·제외 이유·판본·기준시각을 남긴다. 아래 정의를 섞어서 하나의 성공률로 만들지 않는다.

| 지표 | 분자 / 분모 | 반드시 따로 남길 것 |
|---|---|---|
| 오류 확정 정확성(합성 평가) | 정답 기준과 일치한 오류 판정 / 평가 가능한 확정 판정 사례 | 미판정의 잘못된 오류 승격 건수, 판정 보류 수 |
| 적절한 보류(합성 평가) | 확정하지 않아야 할 사례에서 실제 보류한 수 / 미판정·근거 부족 사례 수 | 보류 이유. 모든 답을 보류해 정확성을 높인 척하지 않도록 확정 가능 사례의 처리도 함께 제시 |
| 도움 뒤 같은 문항 재시도 | 도움 뒤 맞힌 재시도 / 도움 뒤 유효하게 낸 재시도 | 도움 단계·답 노출·첫 답·시도 번호. 독립 성공과 합산하지 않음 |
| 독립 전이 수행 | 처음 보는 문항에서 도움 없이 맞힌 유효 수행 / 해당 학습 항목의 도움 없는 유효 수행 기회 | 총 기회, 실제 제출, 미판정, 도움받음, 도움 미상, 건너뜀을 각각 제시 |
| 후행 유지 | 정해진 후행 창에서 조건에 맞는 독립 성공 / 같은 창의 유효 독립 수행 | `not_due`, `no_sample`, `unmeasurable`을 0점으로 바꾸지 않음 |

분모 0이면 비율은 `null`이다. 같은 event ID 재전송은 한 번만 세고, 같은 문항의 다른 attempt는 재시도 축에서 구분한다. 원문을 보지 않았는데 학습 항목을 쓸 기회가 있었다고 가정하지 않는다. 성과회수의 `겨냥개입/후속 교정 관측`은 **닿았나**이며 **실력이 늘었나**로 이름을 바꾸지 않는다.

시간창은 `immediate/d1/d7/d30` 이름만으로 완성되지 않는다. 도움 발생·실제 노출·수행 시각, 기준시각, 창의 시작·끝, 지연 도착을 구분한다. 기존 `성과회수.js`의 1·7·30일 창은 끝에 도달하기 전 `미도래`, 끝나는 정확한 시각부터 측정 가능이라는 경계를 유지한다. 기록이 없는 완성된 창은 `표본0`이고 실패가 아니다. 길이가 다른 전후 창의 비율을 단순 차감하거나, 미래 사건을 과거 기준시각의 결과에 넣지 않는다.

## 5. 독립 비교 절차와 최종 판정

1. **기준선 고정:** 보존한 소스·해시·기존 시험 로그와 같은 합성 입력·시각·규칙으로 변경 후 결과를 비교한다. 기존 실패와 새 실패를 나눈다.
2. **구현과 별도 반례:** 구현 담당이 만든 성공 예시 외에 A01~A12의 경계 사례를 평가 담당이 구성한다. 초기 실패를 보고 기준을 완화하지 않는다. 실패를 고친 뒤 그 사례는 회귀 시험으로 남기되 더 이상 미공개 평가라고 부르지 않는다.
3. **앱 소비 결과:** 실제 화면에서 확정 오류·미판정·도움 열기·답 노출·재시도·계정 전환을 확인한다. 모듈 단위 통과나 소스 문자열 검사만으로 학생 화면 검증을 대신하지 않는다.
4. **진전:** E01·E02가 해소되고, 맞는 오류에 더 적절한 도움을 주며, A01~A12의 기존 경계를 깨지 않은 것을 구체 사례로 제시한다. 새 파일·엔진 수·시험 개수 증가는 진전 지표가 아니다.
5. **후퇴 또는 보류:** 확정 오판·원문 손실·계정 혼합·거짓 독립 수행은 건수 하나라도 있으면 해당 경로를 수정하거나 끈다. 검증하지 않은 기능과 실제 전이·유지 효과는 보류로 남긴다. 미구현 후행 측정을 구현 완료처럼 보고하지 않는다.

이번 로컬 판정은 **교육 기능과 측정의 정직성이 개선됐는지**까지다. 실제 학습 향상·한국어 및 몽골어 교수 품질·실학생 부담 변화는 이후 별도 검토와 실제 관측이 필요하다. 실학생 효과를 확인할 때는 최초 시행 전에 지표·시간창·대조 조건·확대 기준을 정하며, 이 문서의 합성 시험 통과율을 학습 효과 수치로 사용하지 않는다.

## 6. 이번 독립 검증 결과

상세 값·해시·18개 반례의 확인 범위는 [전후검증.json](전후검증.json)에 기록했다.

- 정본 모듈·기존 Atlas·Strata·Trail·Temper·독립 교육 시험 **95/95**, Talk 기존 177개와 새 어댑터 4개 **181/181** 통과. 별도의 실제 G4 어댑터 대조는 **8/8** 통과했다. 소스·렌더 시험과 실제 상호작용 화면 검증은 별개다.
- 같은 6개 입력을 고정한 전후 비교에서 잘못된 독립 수행 사용은 **3건 → 0건**이다. 예전의 `assisted:false` 단독 표기도 이제 시도 근거가 없으면 보류한다. 대신 같은 범위·판단·학습 항목·시점의 새 문항 최초 시도와 도움 없음이 확인된 양성 사례는 실제로 다음 연습 대상을 바꾼다.
- 실제 팩 **15문항의 정답 16개·알려진 오답 45개** 판정을 보존했다. `g4t04.b3`의 `하고`는 여전히 미판정이다. 도움을 보거나 같은 문항을 재시도한 성공은 독립 수행 분모에 들어가지 않는다.
- 기록 쓰기가 한 번 실패한 뒤 복구되어도 과거 시도를 없었던 것처럼 처리하지 않는다. 문항 이름·판번호·해설만 고쳐서 이미 본 빈칸을 처음 보는 문제로 만들지 않는다. 노출의 동일성은 빈칸 문장과 힌트로 보수적으로 판단하고, 전체 질문·채점 자료의 판은 별도로 비교한다.
- 기존 제품은 도움 노출을 관측하지 않았으므로 변경 전 독립 성공률을 지어내지 않았다. 합성 변화 감지기의 `0/1 → 1/1` 양성 시험은 측정 코드가 차이를 포착하는지 확인하는 대조군이며, 제품이나 학생의 학습 향상 수치가 아니다.

G4 도움 흐름이 최초 해설 자동 노출에서 요청식 도움으로 바뀌었으므로 해당 구형 시험 기대 두 개를 새 계약으로 고쳤다. 정본 답·해설 접근, 재도전 입구, 미판정 보존은 계속 검사한다. 이 전환 중 기록된 `175/177` 결과와 최종 `181/181` 로그를 둘 다 보존했다.

새 교육 흐름의 1·7·30일 후행 유지 측정, 실제 기기에서의 계정 전환, 원격 저장·배포와 실학생 효과는 이 평가에서 완료하지 않았다. 기존 성과회수의 시간창·미도래·표본0 보호는 기존 시험으로 확인했다. 실제 화면 상호작용 검증은 통합 담당의 별도 결과를 따른다.
