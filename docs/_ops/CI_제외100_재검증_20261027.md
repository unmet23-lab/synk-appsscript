## 발견한 문제와 고침

Windows `core.autocrlf=true` 체크아웃이 Whisper 모델의 JSON·문서 파일을 CRLF로 바꿨다. 모델 공개 주소는 파일 SHA에서 계산하므로, 업로드된 모델과 같은 Git 원문인데도 다른 revision으로 판정해 Pages 준비가 실패했다. 해당 모델 폴더의 `.json`·`.txt`·`.md`만 `.gitattributes`에서 LF로 고정했다. 모델 내용·가중치·업로드 영수증은 바꾸지 않았다.

변환됐던 10개 파일을 Git blob 바이트로 되돌려 미디어·출시 사본·GPU 묶음29/29를 확인했다. 이어 `core.autocrlf=true`와 작업본 속성을 적용한 새 Git archive를 추출해 모델 텍스트11개가 전부 원래 Git blob과 바이트 일치함을 검증했다. 기존 Windows 작업본의 파일은 재체크아웃해야 새 줄끝 속성이 적용된다.

첫 실행의 다른 실패는 필요한 출시 사본1개와 Town GLB가 추가로 없던 준비 문제였다. 공용 원본의 해시를 기록해 복사한 뒤 각각 원래 시험을 재실행해 통과했다. 모형 파일이나 통과용 서버 대체물을 만들지 않았다. 첫 실패 TAP도 그대로 보존했다.
