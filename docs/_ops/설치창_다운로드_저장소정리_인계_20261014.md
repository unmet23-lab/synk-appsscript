## 4. 조심할 것

- **Codex 임시 폴더 안의 git 클론까지 지운 실수(10-14 14:38, 이 세션).** `clean_codex_misc.py`가 `~/.codex/tmp`의 맨 위 `.git`만 보고 워크트리를 걸러, 한 단계 안에 클론을 둔 `google-backend-release-20261009-180a10da`(10-09 GPT 구글 가입 백엔드 공개 작업 폴더)를 `rmtree`하다가 읽기 전용 git 객체에서 멈췄다. 사라진 것: `frozen-source`·`live-before`·`operational-diff`·`operational-payloads`·`payloads`, 같이 있던 `SYNK-appsscript` 사본의 내용, 안쪽 `SYNK-talk` 클론의 추적 파일 621개. 되살린 것: `SYNK-talk/.git`은 온전해(fsck 통과) 추적 파일 621개를 인덱스에서 되살렸고, 원격·본 클론에 없는 그 클론의 브랜치 `codex/google-account-release-20261009`(`d80fdfc`, origin/master 위 66커밋)를 `.tmp/cleanup-20261014/google-backend-release-20261009-SYNK-talk.bundle`로 남겼다. `frozen-source`는 그 커밋 내용이고, 맨 위 기록 파일(release-manifest·postdeploy-verification·final-validation 등)은 남았다. 되살릴 수 없는 것은 공개 직전 운영 상태 사본 `live-before`와 만든 payload다. 추적 문서가 이 폴더를 가리키는 곳은 없다. 같이 지운 나머지 22개 임시 항목(10-08~10-09 comment-dm·google-signup·native-logout-fix 등, 모두 3MB 이하)은 안에 git이 있었는지 확인하지 못했다. **폴더를 통째로 지울 때는 그 안 어디에든 `.git`이 있는지 먼저 본다**(`survey_tmp_old.py`는 그렇게 고쳤다).
- **앱에서 워크트리 세션을 지우면 비추적 파일이 사라진다(10-14 12:22).** 유호님이 앱에서 세션을 지울 때(11:42·12:18~12:22, 메인 저장소 세션 11개와 워크트리 세션 1개) 한강 워크트리 `focused-villani-09429b`에서 HEAD가 떼어지고(reflog `HEAD@{12:22:48}`) 무시 대상이 아닌 비추적 파일이 모두 지워졌다. mp4만 남았다. 브랜치 `claude/synk-ad-video-remake-ff1201`에는 한강 작업 커밋이 없었고, 휴지통에 없고, 파일 기록은 꺼져 있다. 메인 저장소 세션 삭제는 파일을 건드리지 않았다. 워크트리에서 오래 일하는 세션은 결과물을 커밋하거나 git 밖 폴더로 옮겨 두고, 그런 세션을 지우기 전에는 `git -C <워크트리> status`의 `??`를 먼저 본다.
- **회사 운영 배포.** workspace.synk.im은 세 서버 자동 장애 전환 구조라 배포는 GPT 회사 릴리스 절차로만 한다. 옛 단일 서버 도구(`workspace-signal-v6`·`v8`)는 쓰지 않는다. 화면 변경은 얹기 도구로 만들어 그 릴리스에 싣게 넘긴다.
- **플랫폼 공개 판.** 0.4.4부터 홈페이지·앱 feed는 0.4.4 세션의 공통 배포 절차로 바뀐다. 이 인계의 옛 signal.3 게시 방식으로 홈페이지 링크를 덮어쓰지 않는다.
- **정리 작업이 지운 추적 파일.** PC 공간 정리가 추적 파일을 거듭 지웠다(10-03·06·10·11, SYNK-appsscript 554개·synk-policy 201개). `git status`에 ` D`가 많으면 `Documents/PC_공간정리_*`의 removed·reclaimed 기록과 대조해 `git restore`로 되살린다. 삭제는 커밋하지 않는다. 정리가 끝나면 `git ls-files --deleted`가 0인지 본다.
- **줄 끝 검사.** CR을 모두 걷고 HEAD와 비교한다. `desktop/package.json`이 `\r\r\n`으로 망가져 있어 되돌렸다(`--ignore-cr-at-eol`은 CR 하나만 무시한다).
- **별도 인덱스 커밋.** autocrlf=true라 작업본 파일은 `update-index --add`로 담는다(git add와 같은 변환). `hash-object --no-filters`는 CRLF를 그대로 넣는다. 다른 파일의 패치를 얹을 때는 별도 인덱스에서 `git apply --cached` 뒤 `checkout-index -f`로 작업본에 쓰면 줄 끝이 작업본 방식(CRLF)으로 나온다.
- **명령 함정.** `git status`는 `--pathspec-from-file`을 받지 않는다(오류가 빈 결과처럼 보인다). heredoc은 역슬래시를 먹으니 스크립트는 Write로 쓴다. Bash에서 `cd`하면 세션 작업 폴더가 바뀌니 `git -C`와 절대 경로를 쓴다. 저장소 전체를 `grep -r`로 훑으면 2분 넘게 걸리니 추적 파일은 `git grep`으로 찾는다.
- **남길 유일본.** `.tmp/platform-performance-20261012/local-platform/dist/SYNK-Platform-PC-Local-0.4.3-win-x64.exe`(이 PC 전용 구성), `.tmp/world-tutor-native-20261012/SYNK-WORLD-Preview-0.4.2-win-x64.exe`, `desktop-preview/baseline/legacy-world-0.4.2`. synk-policy 본 저장소는 `Documents/synk-policy`이고 여러 `.tmp/*/policy`가 그 워크트리라, 워크트리 폴더는 `git worktree remove`로만 지운다(옛 판의 `.tmp/platform-download-20261011/policy`는 없다 — §1). 0.4.4 세션의 되돌리기 백업 `.tmp/platform-unified-20261014/rollback/platform-0.4.3-before-0.4.4.zip`도 그 세션 것이다.
- **디스크 조사 함정.** 「최근에 쓴 파일」로 재면 `.git/objects/pack`의 18GB가 잡힌다. git이 기존 객체를 만날 때 팩 파일의 수정 시각만 갱신하는 것이라 새 데이터가 아니다(`git count-objects -vH`의 느슨한 객체 크기로 본다). Temp·`.tmp`를 세 번 재귀하는 집계는 디스크 대기열이 높을 때 40분 넘게 안 끝나니 한 번 훑어 폴더별로 묶는다. 여유 공간은 한 번 잰 값을 기준으로 삼지 않는다.
- **세션 조율.** 일괄 커밋·정리 전에는 일하는 세션에 SendMessage로 묻는다. 10-14 WORLD 세션은 import로 잡히지 않는 새 파일 62개와 GPT의 `experiences/social-conversion.mjs`(두 게임이 정적 import)를 알려 줬고, 한강 세션은 이전 장면 폴더가 v31·v32 조립 원본이라고 알려 줬다.
