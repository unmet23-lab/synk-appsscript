- **폴더를 통째로 지우기 전에 안쪽 어디든 `.git`이 있는지 본다(10-14 14:38, 이 판의 실수).** `clean_codex_misc.py`가 `~/.codex/tmp`의 맨 위 `.git`만 보고 걸러, 한 단계 안에 SYNK-talk 클론을 둔 `google-backend-release-20261009-180a10da`(10-09 GPT 구글 가입 백엔드 공개 작업 폴더)를 `rmtree`하다 읽기 전용 git 객체에서 멈췄다. 잃은 것: `live-before`(공개 직전 운영 상태 사본)·`payloads`·`operational-payloads`·`operational-diff`, 같이 있던 `SYNK-appsscript` 사본의 내용. 되살린 것: 클론의 `.git`은 온전해(fsck 통과) 추적 파일 621개를 인덱스에서 되살렸고, 원격·본 클론에 없는 브랜치 `codex/google-account-release-20261009`(`d80fdfc`, origin/master 위 66커밋)를 `.tmp/cleanup-20261014/google-backend-release-20261009-SYNK-talk.bundle`로 남겼다. `frozen-source`는 그 커밋 내용이고 맨 위 기록 파일(release-manifest·postdeploy-verification·final-validation 등)은 남았다. 추적 문서가 이 폴더를 가리키는 곳은 없다. 같이 지운 나머지 22개 임시 항목(10-08~10-09, 모두 3MB 이하)은 안에 git이 있었는지 확인하지 못했다. 이 뒤의 정리(`survey_tmp_old.py`·`clean_tmp_old_and_apk.py`)는 파일마다 위 경로의 `.git`을 본다.
- **미추적 파일은 `git diff --quiet`에 안 나온다.** 다른 세션의 미추적 시험을 「안 바뀐 내 파일」로 알고 커밋했다가 push 전에 뺐다. 추적 여부는 `git cat-file -e HEAD:<경로>`로 보고, 커밋 뒤 `git diff --stat <부모> <새 커밋>`이 내가 바꾼 양과 맞는지 본다.
- **쓰는 프로세스 검사는 내 명령 줄도 잡는다.** 프로세스 명령 줄에서 폴더 이름을 찾는 검사는, 같은 Bash 호출에 그 경로를 넣으면 자기 셸을 「쓰는 프로세스」로 잡아 멈춘다. 경로는 다른 호출에서 본다.
- **앱에서 워크트리 세션을 지우면 비추적 파일이 사라진다(10-14 12:22).** 한강 워크트리에서 무시 대상이 아닌 비추적 파일이 모두 지워졌다. 워크트리에서 오래 일하는 세션은 결과물을 커밋하거나 git 밖으로 옮기고, 그런 세션을 지우기 전에는 `git -C <워크트리> status`의 `??`를 본다.
- **공개 묶음 `account/dist/platform.js`는 작업본 빌드와 다르다.** 작업본 `dist/platform.js`는 HEAD 원본보다도 낡았고(다른 세션이 원본만 커밋), 공개본은 그보다 오래된 묶음에 모듈을 덧대 왔다. 통째로 바꾸면 다른 세션의 미공개 코드가 나간다. 옮겨 심기 전에 옛 조각이 공개 묶음에 정확히 한 번 있는지 확인한다.
- **회사 운영 배포.** workspace.synk.im은 세 서버 자동 장애 전환이라 GPT 회사 릴리스 절차로만 한다. 옛 단일 서버 도구(`workspace-signal-v6`·`v8`)는 쓰지 않는다.
- **플랫폼 공개 판.** 홈페이지·앱 feed는 공통 배포 절차로만 바뀐다. 이 인계의 옛 signal.3 게시 방식으로 홈페이지 링크를 덮어쓰지 않는다.
- **정리 작업이 지운 추적 파일.** 10-03·06·10·11에 정리가 추적 파일을 지웠다. `git status`에 ` D`가 많으면 정리 기록과 대조해 `git restore`로 되살리고, 삭제는 커밋하지 않는다. 정리가 끝나면 `git ls-files --deleted`가 0인지 본다.
- **줄 끝.** autocrlf=true. 작업본 파일은 `update-index --add`로 담고(git add와 같은 변환), `hash-object --no-filters`는 바이트 그대로 넣는다. 공용 문서(결정·트랙)는 작업본에 CRLF가 섞여 있으니 고친 뒤 `tr -cd '\r' | wc -c`가 그대로인지 본다.
- **명령 함정.** `git status`·`git diff`는 `--pathspec-from-file`을 받지 않는다. heredoc은 역슬래시를 먹으니 스크립트는 Write로 쓴다. Bash에서 `cd`하면 세션 작업 폴더가 바뀌니 `git -C`와 절대 경로를 쓴다. 저장소 전체 `grep -r`는 느리니 `git grep`을 쓴다. 같은 주소로 hash만 바꾼 이동은 페이지를 다시 읽지 않으니 확인할 때는 `location.reload()`.
- **남길 유일본.** `.tmp/platform-performance-20261012/local-platform/dist/SYNK-Platform-PC-Local-0.4.3-win-x64.exe`, `.tmp/world-tutor-native-20261012/SYNK-WORLD-Preview-0.4.2-win-x64.exe`, `desktop-preview/baseline/legacy-world-0.4.2`, 공통 배포 세션의 되돌리기 백업 `.tmp/platform-unified-20261014/rollback/`. synk-policy 워크트리 폴더는 `git worktree remove`로만 지운다.
