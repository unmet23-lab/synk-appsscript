## 4. 조심할 것

- **회사 운영 배포.** workspace.synk.im은 세 서버 자동 장애 전환 구조라 배포는 GPT 회사 릴리스 절차로만 한다. 옛 단일 서버 도구(`workspace-signal-v6`·`v8`)는 쓰지 않는다. 화면 변경은 얹기 도구로 만들어 그 릴리스에 싣게 넘긴다.
- **정리 작업이 지운 추적 파일.** PC 공간 정리가 추적 파일을 거듭 지웠다(10-03·06·10·11, SYNK-appsscript 554개·synk-policy 201개). `git status`에 ` D`가 많으면 `Documents/PC_공간정리_*`의 removed·reclaimed 기록과 대조해 `git restore`로 되살린다. 삭제는 커밋하지 않는다.
- **줄 끝 검사.** CR을 모두 걷고 HEAD와 비교한다. `desktop/package.json`이 `\r\r\n`으로 망가져 있어 되돌렸다(`--ignore-cr-at-eol`은 CR 하나만 무시한다).
- **별도 인덱스 커밋.** autocrlf=true라 작업본 파일은 `update-index --add`로 담는다(git add와 같은 변환). `hash-object --no-filters`는 CRLF를 그대로 넣는다.
- **명령 함정.** `git status`는 `--pathspec-from-file`을 받지 않는다(오류가 빈 결과처럼 보인다). heredoc은 역슬래시를 먹으니 스크립트는 Write로 쓴다.
- **남길 유일본.** `.tmp/platform-performance-20261012/local-platform/dist/SYNK-Platform-PC-Local-0.4.3-win-x64.exe`(이 PC 전용 구성), `.tmp/world-tutor-native-20261012/SYNK-WORLD-Preview-0.4.2-win-x64.exe`, `desktop-preview/baseline/legacy-world-0.4.2`. `.tmp/platform-download-20261011/policy`는 여러 작업 공간이 연결된 본 저장소라 지우지 않는다.
- **디스크 조사 함정.** 「최근에 쓴 파일」로 재면 `.git/objects/pack`의 18GB가 잡힌다. git이 기존 객체를 만날 때 팩 파일의 수정 시각만 갱신하는 것이라 새 데이터가 아니다(`git count-objects -vH`의 느슨한 객체 크기로 본다). Temp·`.tmp`를 세 번 재귀하는 집계는 디스크 대기열이 높을 때 40분 넘게 안 끝나니 한 번 훑어 폴더별로 묶는다. 여유 공간은 다른 세션의 빌드로 분 단위로 수 GB씩 요동치므로 한 번 잰 값을 기준으로 삼지 않는다.
- **앱에서 워크트리 세션을 지우면 비추적 파일이 사라진다(10-14 12:22).** 유호님이 앱에서 세션을 지울 때(11:42·12:18~12:22, 메인 저장소 세션 11개와 워크트리 세션 1개) 한강 워크트리 `focused-villani-09429b`에서 HEAD가 떼어지고(reflog `HEAD@{12:22:48}`) 무시 대상이 아닌 비추적 파일이 모두 지워졌다. 브랜치 `claude/synk-ad-video-remake-ff1201`에는 한강 작업 커밋이 없었다. 휴지통에 없고 파일 기록은 꺼져 있다. 워크트리에서 오래 일하는 세션은 결과물을 커밋하거나 `.tmp/`로 옮겨 두고, 그런 세션을 지우기 전에는 `git -C <워크트리> status`의 `??`를 먼저 본다.
