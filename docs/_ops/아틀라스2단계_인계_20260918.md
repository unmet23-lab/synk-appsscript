# 아틀라스 2단계 인계 — 사용자에 맞춰 진화하는 구조

> 2026-09-18의 결정과 코드 조사 기록이다. 당시 제안과 확인 결과를 보존하며, 현재 설계는 [아틀라스 설계](../아틀라스_설계.md)와 [구현 명세](../아틀라스_구현명세.md)에 있다.
> **진행 기록(2026-09-18 같은 세션).** 사용자가 「그냥 여기서 할게 · 불변식 풀어도 돼」라고 해 같은 세션에서 이어 갔다. §5의 1번(설계 정본 반영)과 엔진 본체·편지 어댑터 2판을 이 저장소에 구현했다. 그 뒤 사용자가 「구현은 GPT가 할 것이니 설계만 제대로 · 필요하면 전면 재설계」라고 해(09-19) 설계 정본을 [아틀라스 설계](../아틀라스_설계.md)로 새로 쓰고 [아틀라스 구현 명세](../아틀라스_구현명세.md)를 더했다. 지금 상태와 남은 일은 [트랙](트랙.md) 맨 위 항목과 아틀라스 설계 §11이 최신이며, 이 문서 §4·§5는 그 두 문서로 대체됐다. 옛 금지의 **문서상 이유**는 「상수 문턱으로 고르는 규칙은 모델이 좋아져도 나아지지 않는다」였고(세션 첫 답의 설명은 부정확했다), 재검토 기록은 아틀라스 설계 §3에 있다.

## 0. 현재 상태를 확인할 곳

구현·검증 결과와 남은 일은 [트랙](트랙.md), 계정 간 기억 연결의 검증 범위는 [첫 지속 기억 기록](../아틀라스_첫지속기억_20260921.md)에 있다. 아래의 코드 상태와 제안은 9월 18일 기준이다.

## 1. 사용자가 채택한 것 (2026-09-18)

**목표(사용자 원문).** 아틀라스로 만든 한국어 게임·공부를 한 사람이 「와.. 나를 이렇게 잘 알고 이렇게 센스있고 이렇게 공부를 편하고 재밌게 쉽게 할수있구나」라고 느끼는 것. 사용자의 경험과 선택에 맞춰 자동으로 초개인화(진화)되는 엔진.

**적용 범위(사용자 원문 요지).** 이 방식은 주로 LAB에 쓴다. 다른 사업은 학습하고 진화할 것이 많지 않으므로 보통 Loom·Reed를 쓴다. 필요하면 일곱 엔진 중 일부만 골라 쓸 수 있어야 한다.

**채택한 제안.** 이 세션이 아래를 제안했고 사용자가 「니 추천대로 따를게」로 채택했다.

1. **자동 되먹임 금지를 셋으로 갈라 푼다.** 지금까지는 「학생 상태를 보고 자동으로 갈래를 나누지 않는다 · 결과를 다음 선택에 자동으로 되먹이지 않는다 · 되먹임은 사람이 시즌 회고에서 한다」가 규칙이었다(§3).
   - 경험의 모양(분량·순서·힌트·말·장면·소리·어떤 게임) → 자동으로 맞춘다.
   - 연습 내용(무슨 문법·낱말을 연습할지 — 약점 + 복습할 때가 된 것 + 본인 목표) → 자동으로 맞춘다.
   - 평가의 의미(급수 판정·점수·부모와 강사에게 가는 말) → 자동으로 바꾸지 않는다. 사람이 판단한다.
   - 약 10번에 1번은 일부러 맞춤 없이 기본 순서로 준다. 「맞춤이 정말 도움 됐나」를 비교할 상대를 남기기 위해서다. 옛 규칙이 지키려던 것(공정한 비교)을 버리지 않는 방법이다.
2. **구조를 「엔진 7개의 모음」에서 「고리 하나 + 거기에 꽂는 엔진 7개」로 바꾼다.** 고리 = 기억 → 결정 → 제공 → 확인 → 다시 기억(§4).
3. **진화는 3단이다.** 1단 규칙(지금) → 2단 그 사람 안에서 배우기 → 3단 여러 학생에게서 배우기(Prism · 학생이 쌓인 뒤). AI 모델은 「결정」이 아니라 정해진 방향대로 과제·대사를 「만드는」 데 쓴다. 왜 그렇게 줬는지 늘 설명하고 다시 계산할 수 있어야 한다.
4. **「나를 안다」를 보여 주는 자리를 만든다.** 과제 앞의 이유 한 줄 · 주 1회 「내가 알게 된 너」 카드와 맞아/아니야 · 틀린 이해는 본인이 바로 고치기.
5. **엔진마다 두 방식으로 돈다.** 단독(아틀라스 없이 기본값으로 완전히 동작 — PULSE·SHIFT의 Loom·Reed) · 연결(아틀라스가 있으면 「지금 이 사람」 정보를 받아 자기 손잡이만 조정 — LAB).
6. **작업 순서**는 §5다.

**아직 사용자 판단이 남은 것.** 비교 몫의 정확한 비율(「약 10번에 1번」은 출발값) · 「내가 알게 된 너」 카드의 실제 문구와 화면 · 운영 DB에 새 표를 적용하는 시점 · 라이브 배포 시점. 나머지는 위 채택 범위 안에서 진행한다.

## 4. 목표 구조 (이 세션의 제안 — 세부는 설계에서 확정)

### 4-1. 기억 — 한 사람당 하나

- 저장하는 것은 **사건**(덧붙이기만 하는 기록)이고, 「이해 한 줄」은 그때그때 **다시 계산**한다. 지금 `understand()`가 하는 방식 그대로다.
- 이해 한 줄의 모양(제안): 무엇(예: 높임말 `-시-` 누락이 잦다) · 출처 구분(본인이 말함 / 행동에서 봄 / 시스템 짐작) · 근거 사건 id들 · 표본 충분도(정확도가 아니다) · 유효기간 · 본인 확인 상태(미확인 / 맞다 / 아니다).
- 「아니다」로 답한 줄은 결정에서 뺀다(`lib/과제요약.js`의 부정 제외와 같은 규칙). 원관측은 지우지 않는다.
- 새로 필요한 사건(제안): 관측 신호(오류 태그·복습 시기·상태 축·수행 — 도움받은 것과 혼자 한 것을 구분) · 이해 확인 응답(기존 c13 `estimate.responded`와 같은 뜻) · 결과 관측(§4-4).
- 지킬 것([아틀라스 설계](../아틀라스_설계.md) §3·§6에서 그대로): 모르는 것을 고정 성향으로 만들지 않는다 · 오늘의 상황을 평생 성향으로 만들지 않는다 · 만료된 최신 선언 대신 옛 선언을 되살리지 않는다 · 사업 사이 프로필 자동 공유 없음 · PULSE 범위에서 개인 프로필 추정 없음 · 원본 계정·글·음성·학생 식별자는 엔진 입력이 아니다.

### 4-2. 결정 — 엔진이 등록한 손잡이를 한 번에 정한다

- 각 엔진(어댑터)이 「내가 바꿀 수 있는 것」을 등록한다. 기존 §4의 다섯 항목(받는 맥락 · 바꿀 수 있는 요소 · 바꾸면 안 되는 것 · 완료의 뜻 · 실패 시 기본 경험)을 경험 단위에서 **엔진 단위**로 넓힌다.

| 엔진 | 손잡이(예) | 바꾸면 안 되는 것 |
|---|---|---|
| Core | 무엇을 연습할지 · 난이도 · 분량 | 문항 조건 · 평가의 의미 · 원문과 수정본 |
| Vellum | 어떤 말로 · 얼마나 자주 · 힌트 방식 | 사실과 다른 성취·성향 말하기. 캐릭터가 직접 하는 대사는 [캐릭터 가이드 정본](../캐릭터/가이드_정본.md) |
| Loom | 장면 분위기 · 내 방에 쌓이는 흔적 · 축하 연출의 세기 | 승인 자산의 정체성. 움직임은 잔잔한 쪽이 기본이고 reducedMotion을 따른다 |
| Reed | 배경음 분위기 · 음량 · 무음 | 사용자가 끈 소리를 되살리지 않는다. 개인 청취 수집은 되살리지 않는다 |
| Trail | 지난 경험 되짚기(「지난번 그 표현이 오늘 다시 나와요」) | 과거 목표를 현재 목표로 덮지 않는다 |
| Temper | 방금 준 도움이 통했는지 확인하는 시점 | 미도래·표본 0을 실패나 효과 0으로 쓰지 않는다 |
| Prism | 새 학생의 출발값(비슷한 조건에서 통한 것) | 학생·부모에게 집단 비교를 전달하지 않는다. 동의와 최소 인원 |

- 순서는 지금과 같다: 실제 제약(시간·소리·본인이 정한 설정)으로 먼저 거르고 → 목표·선호 → 배운 비중. **본인이 직접 정한 설정은 어떤 학습 결과나 비교 몫보다 앞선다**(`tests/atlas.test.js` 「explicit time limits take precedence…」가 지키는 성질).
- 결정 기록에 더할 것: 손잡이별 선택과 이유 · 맞춤/기본 중 어느 쪽이었는지 · 그 선택이 뽑힐 확률 · 재현용 시드. 확률을 남겨야 나중에 맞춤과 기본을 공정하게 견줄 수 있다(엔진 v3 §9 U4 「배정 확률의 겹침이 없으면 인과 추정을 하지 않는다」의 조건을 채우는 방법).
- 비교 몫은 처음에는 **회차 단위**로 둔다(그 회차 전체를 기본 순서로). 손잡이마다 따로 두는 것보다 읽기 쉽다.

### 4-3. 그 사람 안에서 배우기 (2단)

- 같은 사람에게 선택지를 번갈아 줘 보고 결과에 따라 그 사람에게 통하는 쪽 비중을 올린다. 모델 재훈련이 아니라 선택지별 성공·실패 횟수를 세는 가벼운 계산이다(업계 말로 밴딧). 시드를 고정해 같은 입력이면 같은 선택이 나오게 한다.
- **무엇을 「결과」로 볼지가 핵심이다.** 클릭·체류만으로 교육 효과를 단정하지 않는다(엔진 v3 §0-1). 완료·만족을 실력으로 바꾸지 않는다(아틀라스 설계 §3).
  - 모양 손잡이(분량·힌트·말·장면·소리): 끝까지 했는지 + 본인 응답으로 배워도 된다. 「맞는 방식인가」의 문제이기 때문이다.
  - 내용 손잡이(무슨 문법·낱말): 수행으로만 배운다 — 혼자 해냈는지, 같은 오류가 7·30일 안에 다시 나왔는지(`lib/성과회수.js`의 창).
- 자료가 적을 때는 기본값에서 벗어나지 않는다 · 오래된 근거는 힘을 잃는다(지금 응답 참고 창 30일은 설계값) · 본인이 고치거나 빼면 즉시 반영.

### 4-4. 확인 — 결과를 고리로 되돌린다

- 판단 id → 완료 → 결과 관측을 잇는다. 결과 관측은 값과 함께 「아직 때가 안 됨 · 표본 없음」 같은 사유를 가진다(`lib/성과회수.js`의 null + 사유 방식).
- 앱에서는 실제 수행 자료가 서버(Supabase `learning_events`·교정)에 있다. 그래서 「기존 이해 연결」에는 **서버가 상태 요약을 내려 주고 앱이 그것을 아틀라스에 관측 신호로 넣는 다리**가 필요하다. 후보 자리는 `supabase/functions/progress`인데 이 세션에서 열어 보지 않았다.

### 4-5. 보여 주는 자리

- 이유 한 줄: 이미 `atlas/experiences.js`의 `guidance().reason`이 있다. 설정·응답 이유에서 내용 이유(「지난주에 막혔던 부탁 표현이 들어 있어요」)로 넓힌다.
- 「내가 알게 된 너」 카드: SYNK-talk `lib/성향확인.js`(맞아? 카드 · c13 `estimate.responded`)를 잇는다. 09-09 기록에 「같은 날 둘째 답을 버리는 그릇 제약」 결함이 적혀 있었다. 지금도 남아 있는지 확인한다.
- 안내 문장은 사실만 말한다(엔진 v3 §6 U4). 홈페이지·마케팅 말투 교본은 복원하지 않는다([AI 운영 원칙](../AI_운영원칙.md)).

### 4-6. 단독과 연결

- 엔진의 공개 입구가 **선택 입력** 하나(아틀라스의 맥락·결정 묶음)를 받는다. 없으면 기본값으로 완전히 동작하고, 있으면 등록한 손잡이만 조정한다.
- 단독으로 선다는 증거는 「아틀라스 없이 그 엔진의 시험이 통과한다」로 남긴다.
- 코드 자리(제안): `atlas/engine.js`는 고리 본체로 두고, 엔진별 어댑터를 `atlas/` 아래 따로 둔다. 소비 저장소 사본은 지금처럼 `tools/sync-atlas.js`로만 맞춘다.
