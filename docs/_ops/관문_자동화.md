# 관문·자동화 한 장

> push, 배포, CI, 훅, 예약처럼 사람 손 없이 도는 것을 이 한 장에 모은다. 칸마다 무엇을 하는지, 언제 도는지, 끄거나 건너뛰는 법, 담당 원문만 적는다. 도입 경과와 정정 이력은 [결정 표](결정.md)에 있고 `node tools/기록찾기.js <낱말>`로 찾는다. 새로 만들거나 바꾸거나 끄면 이 표도 같은 커밋에서 고친다([AGENTS](../../AGENTS.md)). 「AI가 정함」은 결정 표 근거에 유호님 말씀이 없어 유호님이 모르실 수 있는 것이다.

| 관련 시험 `tools/관련시험.js` | `--실행` 때 바뀐 파일과 이어진 시험을 CI 읽기 지도, 모듈 참조, 시험에 적힌 경로로 골라 돌린다. 시험 파일마다 `node --test`를 따로 돌린다(`tools/lib/관련시험몰이.cjs`). 일꾼 서버(`tools/일꾼시험.js`, 11-26)를 쓸 수 있으면 올릴 커밋 그대로 거기서 먼저 같은 몰이로 돌고, 이 PC와 같은 판정으로 가른다. 서버에서 통과하면, 서버에 없는 준비물(SYNK-talk · 크롬 · 윈도우 갈래 · git 밖 자료 — 불러오는 도구까지 본다)에 기대거나 서버에서 건너뛴 시험이 있는 파일만 이 PC에서 한 번 더 돈다. 서버에서 깨지거나 5분을 넘기면 고른 시험 전부를 이 PC에서 다시 돌려 그 결과를 따르고, 서버를 못 쓰면 이 PC에서 돈다. 서버에서 실제로 깨진 시험이 있으면 이 PC가 끝까지 통과해야만 올린다(시간 넘김 주의 · 미커밋 면제 없음). push가 거절돼 다시 쌓으면 일꾼을 쓴 판도 시험을 다시 돌지 않고 첫 판의 결과로 올린다(일꾼 이전과 같다). 이 PC에서는 두 묶음까지 같이 돌고 전체 한도는 15분이다. 한도에 끊기면 먼저 끝난 파일과 돌던 파일 TAP에 깨진 시험이 없을 때만 주의를 내고 올린다. 공용 작업본에서 깨진 시험이 모두 남의 미커밋을 읽었을 수 있으면 막지 않고 주의만 낸다. 기록을 믿을 수 없거나, 몰이가 죽어 못 본 파일이 있거나, TAP에 없는 실패(종료 코드만)가 있으면 막는다. 한도에 끊긴 실행은 보인 실패의 시험만 본다. 조건부 등록부를 바꾸면 `tests/conditional-qa.test.cjs`도 같이 돈다. | `--시험건너뜀 "<까닭>"`. 급할 때는 `SYNK_관련시험=끔`. 일꾼 서버만 끌 때는 `SYNK_일꾼=끔`. |
| OpenAI 크레딧 길 `tests/오픈AI크레딧길.test.mjs` | OpenAI 주소를 부르는 코드가 크레딧 문(`tools/lib/오픈AI키.mjs`)을 지나지 않으면 실패한다. 이 문은 받아쓰기와 승인된 사진에만 열린다. | 끄는 법은 없다. 새 길은 용도부터 정한다. |
| qa 화면 스크립트 시간 한도 `tools/lib/화면시험.cjs`(AI가 정함) | 화면 시험 스크립트는 전체 20분 안에서 돌고, 끝나거나 한도를 넘으면 자기 브라우저까지 끈다. 한도가 빠진 사본을 올리면 `tests/화면시험관문.test.js`가 막는다. CI에서는 진단만 남긴다. | 그 실행만 늘리려면 `SYNK_QA_LIMIT_SEC=<초>`. |
| master CI 빨간불 경고 | 경고만 보이고 막지 않는다. | 원인은 `node tools/ci빨간불.js`로 본다. |
| 올림 장부 `tools/lib/올림장부.cjs` | push 직전에 올릴 커밋을 그 작업본 git 폴더의 `바로올리기-올림.jsonl`에 덧붙인다. 검수 합침 고리가 이 장부로 내 커밋과 남의 커밋을 가른다. 적지 못하면 올리지 않는다. | 끄려면 두 도구의 `올림장부도구.적기(…)` 호출을 빼는 커밋을 낸다. 그러면 합침 고리가 자기 커밋을 가르지 못한다. |
| 공용 작업본 따라가기 `tools/lib/git-publish-core.cjs` | 워크트리에서 올린 뒤 공용 작업본을 origin으로 옮긴다. 겹친 파일은 바이트 그대로 두고 나머지만 옮긴다. 한 번에 하나만 돈다(`refs/synk/따라가기잠금`). | `--공용안따라감` |
| 낡은 곳 `tools/낡은곳.js` | 알림만 내는 것은 세 가지다. 결정 표에 더한 행의 주제가 다른 md에 옛 말로 남은 줄, 물러난 낱말(`tools/lib/물러난말.json`), 지우거나 옮긴 파일을 가리키는 줄이다. 막는 것은 하나다. 이 push가 닿은 설계 문서의 일정표나 「유호님 차례」 표에 「이 표는 ○월 ○일의 계획이다 … 트랙」 머리 줄이 없으면 막는다. 알림이 실제로 고쳐진 몫은 `node tools/낡은곳.js 재기`로 잰다. | `--계획표건너뜀 "<까닭>"`. 알림은 끄는 인자가 없다. |
| 크기 알림 | AGENTS를 12KB, 운영 원칙을 38KB 너머로 키우거나 결정과 트랙에 2KB 넘는 줄을 더하면 알림 줄만 보인다. 값과 까닭은 [크기 상한 한 장](크기_상한.md)에 있다. | 값은 `tools/lib/git-publish-core.cjs`에 있고 `tests/크기상한.test.js`가 표와 대조한다. |

절차와 함정은 [현장 노트 · git](../현장노트/git_줄끝_잠금.md)에 있다.

### SNS 올리기 전 검사 — `tools/올리기전검사.js`

「고칠 것」이 하나라도 있으면 예약큐와 14시 게시가 그 편을 걸지 않는다. 「확인할 것」은 걸되 보고에 남긴다. 검사는 돌 때마다 결과를 편 폴더 `게시/검사이력.jsonl`에 한 줄로 남기고 흠 장부가 이 줄을 읽는다(끄기 `SYNK_검사이력=끔`).

| 번호 | 보는 것 | 내리는 법·원문 |
|---|---|---|

### 검수 대조 범위 — 도구가 막는 곳과 막지 않는 곳

- 검수 정책은 `검수묶음 준비` 때 작성자와 필수 검수자로 고정한다.
- 검수를 보내지 않은 것은 막힘이 아니다. 필수 검수자의 실제 막힘 증거가 있을 때만 운영 원칙의 대체 규칙을 쓴다.
- 지적 0건은 정상이다. 다만 빈 답, 잘못된 꼴, 빠진 항목, 다른 입력에 대한 답, 끝까지 읽히지 않은 묶음의 0건은 통과가 아니다.
- 준비 중이나 검수 뒤 대상이 바뀌면 다시 검수한다. `반영` 표시만으로 새 파일이 검수된 것이 되지 않는다.
- 도구가 검수 ID로 최종 후보 전체(자동 토큰 변경, 삭제, 설정 포함)를 대조하는 길은 synk.im 공개(`tools/공개.js`)와 Apps Script 반영(`deploy-security-check.js`) 둘이다.
- 회사 서버, SYNK-talk, PC 앱의 검수 의무는 그대로다. 두 도구의 연결만으로 그 길까지 막힌다고 보고하지 않는다. 그 길과 도구 밖에서 받은 답은 진행 세션이 같은 기준으로 본다.

### 공간 지킴이가 하는 일

스위치는 모두 원본창고 `상태/공간지킴이/` 아래 파일이고, 지우면 그 일만 꺼진다. 막힌 회차와 예외는 `공간지킴이.py 상태` 줄에 보인다.

- **여유 감시.** C:나 D:가 선 아래이거나 D:가 안 보이면 텔레그램을 하루 한 번 보내고(막히면 Windows 알림), 「확보 가능」 장부 `상태/공간지킴이/확보가능.json`을 쓴다. D:가 선 아래면 Drive와 대조한 synk-vendor의 30일 넘은 원본을 D:에서 내려놓는다. 실제 자리가 D:인 파일과 쓰는 LoRA 가중치는 내려놓지 않는다.
- **바닥 모드(C: 여유 30GB 아래).** 점검이 일반 우선순위로 돌고 텔레그램 한 통을 보낸다. 점검마다 `%TEMP%`, Claude 세션 임시, `.tmp/.company-local-qa-*`를 24시간(10GB 아래는 12시간), 통과한 조건부 시험 회차를 3시간 기준으로 먼저 지운다([기록](qa/공간지킴이_20261104/README.md)).
- **임시 파일 정리.** 하루 한 번 `%TEMP%`는 이틀, Claude 세션 임시는 사흘 넘은 것을 지운다. 릴리스 설치 사본과 끝난 영상의 `node_modules`도 치운다.
- **사본과 마케팅 파일 정리(`사본정리_마케팅_켬`).** 끝난 GPT와 바깥 워크트리(3일 넘게 쉬고, 깨끗하고, origin에 있고, `.tmp` 도구가 부르지 않는 것)를 `git worktree remove`로 지우고 가지는 남긴다. 다시 못 만드는 무시 파일은 먼저 `.tmp/보존_작업트리_자동/`으로 옮긴다. 읽기만 하는 입력 사본은 `git worktree lock`으로 지킨다. 통과하고 하루 지난 조건부 시험 회차 임시와 이틀 지난 `.tmp/.company-local-qa-*`를 지운다. `~/security-audit-skill` 아래 끝난 조건부 시험 후보 사본은 `tools/conditional-qa/inputs.cjs release`로 푼다. docs/마케팅의 git 무시 파일은 7일 넘은 1MB 이상을 원본 단계로 넘긴다. 만족 사례 편, 게시 대기 편(가장 늦은 게시일이 3일 안, `마케팅AB_켬`을 지우면 14일), 「제작 중」 같은 진행 편, 게시 기록이 가리키는 판 파일, 판 무리마다 새 판 둘은 둔다.
- **조용한 임시 폴더 내려놓기(`임시자동_켬`).** `tools/tmp자동정리.js --실행`이 공용 작업본 `.tmp`에서 7일 넘게 조용하고 아무도 가리키지 않는 폴더와 검수 옛 묶음을 `D:\SYNK_정리대기`로 옮긴다. 살아 있는 문서(트랙, 이 한 장, AGENTS, 운영 원칙)가 가리키는 폴더는 남긴다. 영구 삭제는 없고, 되돌리기는 `node tools/tmp자동정리.js --되돌리기 <이름> --실행`이다([설계](qa/작업방식정리_20261110/2단계_설계.md)).
