## push 때 — `node tools/바로올리기.js` 안

제품 앱의 추천 백업은 최초 백업과 Windows 시작 등록 확인 뒤 하루 간격으로 실행한다(`experiences/solo-backup/src/recommended.cjs`). 사용자가 승인한 범위·용량이 달라지거나 오류가 나면 자동 실행을 멈춘다. 0.6.1 검증에서는 시험 모드만 사용해 이 PC의 새 시작 등록을 켜지 않았고 기존 0.5.0 등록은 유지했다. 2026-11-12 유호님 요청으로 0.5.0 등록도 지우고 앱을 닫아, 지금 이 PC에서 도는 업무 백업 자동화는 없다. 추천 클라우드는 보류 상태다. [범위와 끄기](../../experiences/solo-backup-rust/README.md#추천-자료-로컬-백업): 앱 종료 시 추천 일정도 멈춘다.

**검수 누락과 배포본 변경 차단(2026-10-23, 11-03 [운영 원칙](../AI_운영원칙.md#review-rules)에서 전문을 옮김):** 운영 원칙의 검수 정책은 `검수묶음` 준비 단계에서 작성자·필수 검수자로 고정한다. 검수를 보내지 않은 것은 한도·로그인 실패가 아니며, 필수 검수자의 실제 막힘 증거가 있을 때만 운영 원칙의 대체 규칙을 적용한다. 지적 0건은 정상 결과지만 빈 객체·잘못된 답 꼴·빠진 항목·다른 입력에 대한 답과 끝까지 읽히지 않은 묶음의 0건은 통과하지 않는다. 변경한 글과 곁자료는 중간을 생략하지 않고 묶음으로 나눠 전달하고, 원천·곁자료의 파일 내용을 검수 입력에 연결하고, 준비 중이나 검수 뒤 대상이 바뀌면 다시 검수한다. 배포본은 최종 검수의 상태와 맞아야 한다 — 화면의 아르곤 1차와 수정 뒤 Fable 최종 검수는 서로 다른 상태일 수 있고, `반영` 표시만으로 새 파일이 검수된 것이 되지는 않는다. synk.im 공개와 Apps Script 반영은 검수 ID를 받아 실제 최종 후보 전체(자동 토큰 변경·삭제·설정 포함)를 대조한다. 운영 원칙이 허용한 사후 검수·콘텐츠 정책은 유형·사유·대상을 명시하며, 증거가 없다는 이유로 자동 예외 처리하지 않는다. 회사 서버·SYNK-talk·PC 앱의 기존 검수 의무도 그대로이며, 이 두 도구의 연결만으로 그 경로까지 자동 차단된다고 보고하지 않는다.
