> **현재 판단은 아래 §1~§4를 따른다.** 같은 날 최초 검수는 맨 아래 접힌 「최초 검수 원문 — 당시 기록」에 보존했다. 최초 보고의 시험 수·배포 상태·Git 상태는 당시 관찰이며 현재 완료 증거가 아니다. 이번 후속은 사용자가 검수 개선과 진단 웹앱 배포를 승인한 작업이다. 기준은 현재 [AI 운영 원칙](../AI_운영원칙.md), [트랙](트랙.md), 해당 코드와 공개 실물이다.

## 1. 현재 판정

**엔진의 역할 구분과 일부 ‘입력 때문에 다음 산출이 달라지는’ 경로는 실제 코드에 있다. 학생이 사용하는 전체 흐름과 실제 효과의 검증은 별도로 남아 있다.** 최초 보고의 「Core는 실력 층만, 삶 층은 그릇」「Vellum은 그릇만」「걸음 0까지이므로 설계는 틀리지 않고 미실행일 뿐」이라는 포괄 판정은 철회한다. 구현된 소비자를 빠뜨렸고, 구현 현황만으로 설계 적합성을 확정할 수 없기 때문이다.

일곱 이름을 코드에서 찾는 것보다 **생산자 → 소비자 → 바뀌는 출력 → 실제 수신·후속 결과**를 각각 확인해야 한다. 역할을 일곱으로 나눈 설계가 일곱 독립 서비스의 존재를 뜻하지 않으며, 이름이 없다는 이유만으로 브랜딩뿐이라고 판정하지 않는다. 설계 v3의 전면 적합성 검토나 새 엔진 구현은 이번 진단 배포의 완료 범위로 묶지 않는다.

09-04의 구현 지연 결정은 당시 일정 이력이다. 현재 트랙 §0-재설계는 이미 승인된 첫 흐름부터 이어하고, 늦춤을 모든 후속 작업에 일괄 적용하지 않는다고 정한다. 이번 승인된 개선·배포를 다시 「착수는 유호 자리」로 돌리지 않는다.

## 3. 공개 진단 화면과 @44의 관계 — 직접 조회한 실물

- **@44는 배포 ID가 아니라 해당 배포가 가리키는 Apps Script 코드의 44번 버전이다.** 고정 배포 ID와 공개 URL은 같은 채로 새 코드 버전을 가리키게 할 수 있다.
- [공개 진단 화면](https://synk.im/diag/)을 GET 조회해 HTTP 200을 확인했다. HTML 안의 API 목적지는 `script.google.com`이며, `clasp deployments`가 @44로 표시한 고정 배포 ID와 정확히 일치했다. [화면 원본](C:/Users/q1212/Documents/synk-policy/diag/index.html)의 `var API`, `post`, `get`과 공개 HTML은 줄바꿈을 정규화하면 전체 내용이 같았다. 시작·답변·쓰기 등의 요청은 이 API를 사용하도록 구현돼 있다.
- [기업 홈페이지 루트](https://synk.im/)와 공개 `app.js`·`knowledge.json`·`knowledge-engine.js`도 GET으로 조회했다. 읽은 범위에 @44 호출이나 `/diag/` 링크는 없었다. 홈페이지 질문 기능은 정적 `knowledge.json`을 읽는다. **진단 화면이 @44를 사용하는 것과 기업 홈페이지 전체가 @44로 실행되는 것은 다르다.**
- 위 확인은 공개 HTML/JS와 배포 목록의 대응이다. 이 단계에서 진단 시작·제출을 누르거나 API를 통한 학생 데이터 쓰기를 실행하지 않았다. 실제 진단 응답·채점·저장·수신 성공은 이 조회만으로 확인된 것이 아니다.
