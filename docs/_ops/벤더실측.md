# 벤더 실측 기록

> 하네스·돌리는 법 = `tools/bench/README.md` · 제출물 원본 = `docs/_ops/벤더실측_제출물/`

## 2026-08-03 · 1회차 (파일럿)

**과제**: ARC-AGI-3-Agents 저장소에 `agents/recordings_summary.py` 신설 — 녹화 JSONL 파일들을
훑어 요약 dict를 반환. 명세는 자연어로만 주고(테스트 비공개), 규칙 6개(예외 금지·빈 줄 무시·
없는 디렉터리 방어·표준 라이브러리만·기존 `Recorder` 재사용·부분 실패 시 계속)를 채점했다.

### 결과

| | 기능 점수 | 코드 길이 | 소요 | 조건 |
|---|---|---|---|---|
| **Claude** (Claude Code 서브에이전트) | **13/13** | 112줄 | 93초 | SYNK 하네스 **있음** |
| **Codex** (`codex exec` · GPT) | **13/13** | 66줄 | 130초 | 하네스 **없음** |

**기능 정확도는 동점이다.** 13개 검사(정상 동작·집계 정확·에지 3종·정적 규칙 2종)를 둘 다 통과했다.

### 코드 리뷰 판정 — 갈린 지점

**Codex 우위**: 66줄로 요구된 것만 했다. 단일 함수, 읽기 쉽고 리뷰 부담이 작다.

**Claude 우위**: 정렬을 명시적으로 수행(명세를 코드로 표현 — Codex는 `os.listdir` 정렬에
암묵적으로 기댄다), 빈 문자열 방어, 읽기 실패한 파일을 `files` 집계에서 제외(Codex는 포함해
「처리한 파일 수」의 의미가 흐려진다), 함수 분리와 타입 힌트.

**🔴 Claude 열위 — 이게 이번 실측의 핵심 발견이다**: 112줄 중 **20줄이 3단 import 폴백**이다.
`agents/__init__.py`가 미설치 의존성을 import해 `from .recorder import`가 실패하자, Claude는
그것을 **코드로 우회**했다. 그런데 그 실패는 이 저장소의 정상 상태가 아니라 **채점 환경의
특수성**(`uv sync`를 안 한 상태)이다. 즉 **테스트 환경에 과적합했다.** 실무 리뷰라면
「왜 여기 3단 폴백이 있나」로 반려될 코드다.

구조적으로 말하면 — **실제로 실행해 검증하려 한 쪽이 그 대가로 코드를 부풀렸다.**
Codex는 그 벽을 만나지 않았고(또는 무시했고) 결과적으로 더 깔끔한 코드를 냈다.

### ⚠ 이 실측이 말하지 않는 것

- **1과제·1회 실행이다. 통계가 아니다.** 벤더 배치를 이걸로 확정하면 안 된다.
- **조건이 비대칭이다** — Claude는 SYNK 하네스(CLAUDE.md의 검증 규범 포함)를 컨텍스트에 두고
  돌았고 Codex는 맨몸이었다. 「모델 대 모델」이 아니라 **「하네스 있는 Claude 대 하네스 없는 Codex」**다.
  다만 그게 실사용 조건이기도 하다.
- 과제가 **Python·소규모·순수 함수**다. SYNK의 실제 일감(Apps Script·시트 연동·라이브 데이터)과
  성격이 다르다.

### 부수 확인 (실측 과정에서 나온 사실)

- **Codex는 ChatGPT 구독으로 이미 로그인돼 있다**(`auth mode: chatgpt`, API 키 아님) — 추가 비용 0.
- **Kimi·Gemini·DeepSeek CLI는 설치돼 있지 않다.** 「4벤더」는 현재 **2벤더**가 실측 가능 범위다.
- `uv`·`python`이 **Hermes 설치분에 딸려 있다**(`~\AppData\Local\hermes\`).
- ⚠ `ARC-AGI-3-Agents` 안에 **같은 이름의 중첩 clone이 하나 더 있다**(폴더 안에서 `git clone`을
  한 번 더 실행한 것으로 보인다). 유호님 배치라 **손대지 않았다** — 정리는 유호님 판단.
