> 유호 요청 09-11 「우리 기업 상담 챗봇을 만들어줬는데 평가해줘」. 대상 = 검토 꾸러미(자료판 2026-09-11-public-guide · 답변 49 · 근거 문서 6 · knowledge-engine.js · app.js · index.html). 자 = 꾸러미 §1 권장 검토 범위 아홉 + [철학 적용 기준](../철학_적용기준.md) + [마케팅 정본](../마케팅_정본.md)의 공개 표현 규칙 + 결정 원장 09-08·09-11(「기획자」 호칭 · 하단 사업자번호).

## 1. 한 줄 판정

**안전성은 통과, 표현은 대체로 정직, 고칠 것은 「거절이 너무 넓어 정상 질문을 막는 자리」와 「방문자가 실제로 묻는 기본 질문의 공백」, 그리고 「홈페이지 익명 ↔ 개인정보처리방침 실명·주소」 불일치다.** 내부 원문·학생 기록·접속 정보·재무는 JSON·코드 어디에도 없고, 주입·우회 시험 전부 제한 안내로 막혔으며, 입력을 서버로 보내거나 저장하는 코드는 없다. 숫자 약속·우월성 주장·미확정 가격도 0이다.

## 3. 고쳐야 할 것 — 중요도 높음

### 3-1. 정상 질문이 「개인정보 제공 안 함」으로 거절된다(거짓 제한)
- 실측: 「아이 상담 어디서 볼 수 있어요?」「상담 기록은 어디에 남나요?」「아이 성적은 부모가 볼 수 있나요?」 → `restricted` · guide-personal(「학생·보호자·고객의 개인정보와 사적인 답안·상담·기록은 이 안내에서 제공하지 않습니다」).
- 원인: `knowledge-engine.js` 의 개인정보 요청 정규식 `(학생|보호자|고객|회원|아이).*(명단|성적|답안|상담|연락처|전화번호|원문|원본|기록).*(보여|알려|열람|출력|뽑|다운|제공|볼수)` 와 낱말 `상담기록` 자체가 제한 신호다. 학부모의 첫 질문이 정확히 이 모양이다.
- 교체: 제한 조건에 «남의·실제 기록» 신호(실제·전체·모든·명단·다운로드·추출·다른 학생·이름 빼고)를 하나 이상 요구하고, 「부모가 볼 수 있나요 / 성적은 어떻게 알려주나요」는 lab-parent 로, 「상담 기록은 어디에 남나요」는 guide-privacy 로 보낸다. lab-parent 에 한 문단 추가 제안: **「보호자에게는 학생이 무엇을 말할 수 있게 됐고 어디에서 도움이 필요한지를 알리는 안내를 준비합니다. 다른 학생과의 비교 수치가 아니라 그 학생의 변화를 전합니다. 실제 전달 방식과 주기는 과정 안내에서 확인해 주세요.」**

### 3-2. 「상담 받고 싶어요」「무료 상담 있나요」가 근거 없음으로 끝난다
- 실측: 둘 다 `unanswered`(일반 「근거를 찾지 못했습니다」). 잠재 고객의 가장 흔한 문장이 막힌다. 「상담」이 제한 정규식에만 있고 긍정 경로에 없다.
- 교체: `/상담(을|을받|받|신청|하고|원해|가능)|무료상담/` → guide-contact(브랜드가 lab 이면 lab-availability 병기). 문장은 기존 guide-contact 로 충분하다.

### 3-3. 홈페이지는 「기획자」로 이름을 숨기는데 개인정보처리방침은 실명·상세 주소를 공개한다
- 실측: 챗봇 guide-privacy 가 링크하는 `synk.im/privacy/` 에 「책임자 / Data contact 양유호 · founder@synk.im」 · 「주소 서울특별시 용산구 우사단로2가길 23-2, 2층」 · 「몽골 울란바토르에서 수업합니다」(현재형 · 시행일 2026-08-04). 홈페이지·챗봇은 09-11 결정대로 이름 미노출·「개원 준비 중」이다. 한 번의 클릭으로 익명이 풀리고, 「수업합니다」는 준비 중을 운영 중으로 읽히게 한다(꾸러미 §1 셋째 범위).
- 판단 자리(유호): 실명·상세 주소를 그대로 둘지. 🔍 확인 필요(법률 검토 전 일반 상식 수준): 개인정보 처리방침에는 보호책임자의 «성명 또는 부서명»과 연락처가 있으면 되므로 「SYNK 개인정보 보호책임자(기획자) · founder@synk.im」 꼴로 갈 수 있고, 상세 주소는 처리방침의 필수 항목이 아니다(사이트에서 직접 판매·결제를 받으면 전자상거래 표시 의무로 상호·대표자·주소·전화가 필요해지는데, 그 순간 익명 정책과 다시 부딪힌다 → §6).
- 교체(처리방침 쪽): 「몽골 울란바토르에서 수업합니다」 → **「몽골 울란바토르 개원을 준비합니다. 개원 전에는 상담·체험·개원 전 온라인 과정에 이 방침을 적용합니다.」**

### 3-4. 24시간 라디오가 실제로 송출 중인데 챗봇은 「실시간 방송은 아닙니다」만 말한다
- 실측: 「라디오 24시간 방송 있나요?」「유튜브 라디오 링크 주세요」 → pulse-listening(곡 감상편 설명 · 「별도로 제작한 감상 영상으로, 실시간 방송은 아닙니다」). 방문자는 「라디오는 없다」로 읽는다. 곡 페이지 자체는 「라디오 열기 · K-LOFI24」를 링크하고, 09-11 실측으로 유튜브 방송(public · active)이 돌고 있다.
- 판단 자리(유호): 라디오를 홈페이지에서 공개할지. 트랙 §0-라디오 남은 일(OAuth 검증 제출 · 몽골어 설명·썸네일 · 장시간 무중단 미검증)이 있어 «지금 홍보»는 결정 뒤다.
- 교체(공개 전): pulse-listening 둘째 문단 끝에 **「24시간 라디오는 따로 준비 중이며, 열리면 이 안내에서 링크를 드립니다.」** 공개 후: 「라디오는 어디서 들어요」 항목 하나(유튜브 링크 · 「방송 상태는 유튜브에서 확인」).

## 4. 고치면 좋은 것 — 중간

### 4-1. 위치 공백
「학원이 어디에 있나요?」「몽골에서 하나요, 한국에서 하나요?」「울란바토르에 있어요?」「주소가 어디예요?」 → 전부 `unanswered`. 처리방침이 이미 「울란바토르 · 서울 사업자」를 공개하므로 항목 추가 제안(lab): **「LAB은 몽골 울란바토르에서 개원을 준비합니다. SYNK는 서울에 등록된 사업자입니다. 정확한 위치와 개원일은 확정 뒤 안내합니다.」** 검색어: 어디 · 위치 · 주소 · 울란바토르 · 몽골에서 · 한국에서.

### 4-2. 「수업」 제목이 운영 중 강의로 읽힌다
shift-audience 「SHIFT는 누구를 위한 수업인가요?」 · shift-takeaway 「SHIFT의 수업에서 무엇을 가져가나요?」. 본문은 「교육은 필요가 확인될 때 별도」로 정직한데 제목이 앞선다. 교체: **「SHIFT는 누구를 위한 이야기인가요?」 · 「SHIFT에서 무엇을 가져가나요?」**

### 4-3. 엉뚱한 답으로 가는 자연 질문(실측)
| 질문 | 지금 | 가야 할 곳 |
|---|---|---|
| 음악 만들어 줄 수 있어요? | pulse-listening | pulse-collaboration |
| 로고 만들어 줄 수 있어요? | shift-making(로고 이야기) | shift-scope(광고·브랜딩 제작) |
| 광고 만들어 주나요? | 없음 | shift-scope |
| 협력 대학이 어디예요? | guide-collaboration | guide-unpublished(확인 필요) |
| 다른 학원보다 얼마나 좋아요? | lab-availability | guide-evidence |
| 언제 만들었어요? | guide-availability | guide-unpublished |
| 카카오톡으로 문의해도 돼요? | guide-collaboration | guide-contact |
| 4급 못 따면 어떻게 돼요? · 6개월 무료 케어가 뭐예요? | 없음 | lab-topik(보장 조건은 모집 공개 뒤) |

### 4-4. 자기 예시 2건이 다른 답으로 간다
「작품의 사용 범위는 어디서 확인하나요?」(pulse-collaboration 예시 → pulse-rights) · 「매출이 몇 배 늘었나요?」(shift-results 예시 → guide-evidence). 답은 오히려 맞는 쪽이니 예시를 그 항목으로 옮긴다.

### 4-5. 몽골어·영어 입력이 한국어 「근거 없음」으로 끝난다
「Сайн байна уу? …」 · 「How much is the tuition?」 → `unanswered` · 한국어 메시지. 몽골 학생·학부모가 대상인 회사의 첫 접점이다. 마케팅 정본 규칙(감수 전 문안은 «감수 전» 표시 · 유료 광고 제외)에 따라 폴백 두 줄 제안: 영어 **「This guide answers in Korean. For questions in English or Mongolian, email hello@synk.im.」** + 몽골어 한 줄(기계 대조 통과 · «원어민 감수 전» 표시). 키릴 감지는 정규식 `[Ѐ-ӿ]` 하나면 된다.

### 4-6. 채널·채용 공백
「유튜브 채널 알려주세요」「인스타그램 있어요?」 → 없음. 공개 계정을 한 항목으로(현재 이름은 계정 상태 확인 뒤 · 09-08 확정: 틱톡 synk.mn 등). 「채용하나요?」 없음 · 「강사 모집하나요?」 availability → **「현재 공개 채용 공고는 없습니다. 관심 분야와 경력을 hello@synk.im 으로 보내주시면 필요할 때 연락드립니다.」** 하나로 통일.

## 5. 낮음 · 코드·문서 위생

- unknown·courtesy 두 문구가 코드에 박혀 있어 「답은 검수 문서에서만」 불변식 밖이다 → guide 문서에 넣고 엔진이 읽게.
- 캐시 태그가 셋(`app.js?v=20260911-guide` · 엔진·JSON `?v=20260911-public-guide`) — 다음 갱신 때 하나를 빠뜨리면 옛 자료가 남는다 → 태그 하나로.
- guide-privacy: 지원 브라우저의 `ask_synk`(브라우저 AI 에이전트)로 질문하면 그 브라우저·에이전트의 처리 방식을 따른다는 한 문장.
- 개인정보처리방침이 메신저 봇·앱만 다루고 홈페이지 질문창은 안 다룬다(질문창은 수집 0 이라 무해) → 「사이트 질문 기능은 입력을 저장·전송하지 않는다」 한 줄을 방침에도.
- 자료실·AI 업무 지도 링크가 `unmet23.chatgpt.site` 하위 도메인이다 — 계정 이름이 URL 에 노출되고 회사 도메인 밖이다. 비밀은 아니지만 익명 정책·명품 기준과 어긋난다 → 여유가 생기면 synk.im 아래로.

## 6. 앞으로 걸리는 것(지금 고칠 일 아님)

- 1기 개원 전 온라인 과정(11-30 · 15만원 · 첫 2주 환불)이 열리면 guide-availability·lab-availability 의 「확정된 모집 일정·수강료·환불 조건이 없습니다」가 거짓이 된다 → 모집 공개와 같은 날 갱신.
- 사이트가 결제·신청 창구가 되면 전자상거래 표시 의무(상호·대표자·주소·전화·통신판매업 신고)가 붙는다 → 「기획자」 익명과 충돌하므로 판매 창구를 사이트 밖(제안 봉투·계좌)으로 둘지 미리 정한다.
- 트랙 §0-라디오 남은 일이 닫히면 §3-4 를 공개 판으로.

## 7. 안 잰 것

호스팅 접속기록 · 법률 검토(§3-3 의 «성명 또는 부서명»은 일반 상식 수준이며 변호사 확인 전) · 실제 방문자 반응 · 몽골어 폴백 문안의 원어민 감수 · synk.im 진단 화면과 진단 웹앱의 연결(이 평가 범위 밖).
