# AI 계정 정리와 Talk 품질 재검토 · 2026-09-11

## 결론

현재 운영 모델은 Talk 받아쓰기 Whisper-1, 교정 Sonnet 5를 유지한다. 품질 문제가 전혀 없다는 인증이 아니라, SYNK의 학습자 음성·한국어 교정·몽골어 해설에서 새 모델의 확실한 우월성을 아직 측정하지 못했기 때문이다. 모델 교체 전에 확인된 신뢰도·교정 태그의 실제 결함을 먼저 수리했다.

사용자 확정은 Anthropic API 결제 계정 단일화다. 실제 선택 계정·조직 ID·잔액은 저장소 밖 개인 런타임 설정에만 기록한다. 이 기록은 계정 선택과 관측일을 남기는 자료이며 API 키를 물리적으로 가두는 기능이 아니다.

## 이번에 고친 품질 결함

1. 받아쓰기: `Number(null)` 등 암묵 변환 때문에 미제공 확률이 숫자 0으로 바뀌고, `exp(0)`으로 확실한 결과처럼 계산될 수 있었다. segment JSON 확률은 실제 유한 숫자만 받고 null·빈 문자열·boolean 등을 미측정으로 남긴다. 진짜 숫자 0의 의미는 보존한다.
2. 검수 확정: 같은 미측정 값을 낮은 신뢰도 숫자로 잘못 처리하던 소비자를 맞춘다. 기존 최소 청취·실제 재생 기록 게이트는 유지한다.
3. 교정: `오류없음`과 실제 오류 태그가 섞인 응답은 상충 판정으로 거부한다. 부분적으로 태그를 지워 정상 응답으로 꾸미지 않는다.
4. 평가: 기대 오류 태그를 포함했다는 이유로 `미검출=true`와 `통과=true`가 동시에 서던 모순을 막는다. 기존 20문항 보관 출력 4벌의 18/20 점수는 모두 그대로다.
5. 검수 화면: scalar `stt_confidence`의 null·빈칸·boolean은 기존 ‘전사 신뢰도 미측정’ 문구로 표시한다. 이 scalar는 DB가 십진 숫자 문자열로 반환할 수 있어 `"0.000"`은 정상 표시하고 자릿수를 보존한다. segment JSON 확률의 실제 숫자 계약과 구분한다. `synk-design` 기준에 따라 기존 스타일·배치를 유지했으며 로컬 렌더 107/107과 독립 합성 19/19를 확인했다. 실기기·라이브 화면의 픽셀 검증은 하지 않았다.

신뢰도는 음성 인식 토큰 확률에서 나온 참고값이며 실제 정답률·발음 점수가 아니다. 과거 DB에 잘못 저장된 값은 이번 코드 변경으로 소급 복구하지 않았다.

STT 4파일 독립 검토에서 새 P0/P1 회귀 없음, 관련 61/61 통과. STT 확장 회귀 175/175, 교정 태그 관련 91/91. 이 숫자는 서로 겹치는 시험을 포함하므로 합쳐 총 시험 수로 제시하지 않는다. 통합·리허설 최종 상태는 아래 실행 기록에 별도로 갱신한다.

`gpt-transcribe`는 공식 신규 권장 모델이지만 현재 Whisper용 `verbose_json`을 그대로 보낼 수 없다. `language`도 `languages[]`로 바뀌며 타임스탬프를 제공하지 않는다. 현재 코드의 400/422 영구 실패 분류와 구간 검수까지 포함해 별도 어댑터가 필요하다. [공식 전환 안내](https://developers.openai.com/cookbook/examples/migrating_from_whisper_to_gpt_transcribe), [전사 가이드](https://developers.openai.com/api/docs/guides/speech-to-text#timestamps).

Gemini는 학생이 한 실수·반복을 보존하는 `verbatim` 방식만 후보로 삼는다. `smart` 방식의 문법 정리·말 고침 제거는 한국어 학습자의 실제 오류를 지울 수 있다. 단어 타임스탬프는 정확도에 영향을 줄 수 있고 Cloud 버전은 Preview이며 크레딧 적격성도 확인되지 않았다. 무료 AI Studio 경로에 학생 음성을 보내지 않는다. [Gemini 가이드](https://ai.google.dev/gemini-api/docs/transcribe), [Cloud 모델 상태](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/3-5-transcribe).

저장소의 30개 합성 대본과 비교 도구만으로는 정확도를 측정할 수 없다. 대응 평가 음성이 없으며, 읽으라고 준 대본과 실제로 발화한 내용도 같다고 가정하면 안 된다. 아래 조건의 작은 비교시험을 먼저 권한다.

- 동의받은 비식별 음성 또는 별도 시험 음성, 사람이 실제 들은 그대로 적은 정답.
- 몽골인 한국어 발음·조사/어미 실수·한몽 혼용·반복·자기 수정·침묵/소음 포함.
- 문자 오류율뿐 아니라 학생 오류 보존, 없는 말 생성, 구간 시간, 미측정 처리, 지연을 따로 측정.
- 원본 음성과 사람이 확정한 transcript_verified 보존. 기존 시험 도구가 영구 행·암호·대기열을 바꾸는 경로는 이 평가에 사용하지 않음.

1,000분에서 월 US$1.50 차이이므로 지금은 비용보다 학습 오류를 보존하고 선생님이 정확한 구간을 들을 수 있는지가 더 중요하다.

예시는 건당 입력 2,000 + 가시 출력 500토큰, 사고·캐시·배치·세금 제외다. 실제 비용이나 예산 상한이 아니다. 사고 출력 1,000토큰을 추가하면 Sonnet은 US$19/1,000건, Opus는 US$47.50/1,000건이 된다. Sonnet의 9월 가격 인상 예정 정보는 취소됐으므로 현재 공식 US$2/10을 사용했다. Flash 단가는 현재 공식 한시 가격으로 이후 재확인해야 한다. [Anthropic 가격](https://platform.claude.com/docs/en/about-claude/pricing), [Google 가격](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [Fable 5.1](https://platform.claude.com/docs/en/models/fable-5-1/overview).

개선 우선순위는 모델명보다 다음 세 가지다.

1. 맞는 문장을 불필요하게 고치지 않고 학생 의도를 보존하는지 측정한다. 현재 엄격 문자열 정답에는 ‘제가/저는’처럼 문맥상 둘 다 가능한 답을 오답 처리할 여지가 있다.
2. 교정 문장·오류 태그·몽골어 설명을 각각 평가한다. 현재 몽골어 검사 통과는 문자/존재 조건이지 해설 의미가 맞다는 증거가 아니다.
3. 기존 합성 102문항(23태그)과 문맥 최소쌍을 동일 단건 요청으로 Sonnet/Opus에 대조한다. Sonnet 사고량도 대조해 더 비싼 모델만의 이득인지 분리한다. 몽골어 의미는 블라인드 사람 검토가 필요하다.

이 비교에서 반복적으로 분명한 우월성이 나올 때 Opus 전환 또는 어려운 사례의 선별 재검토를 권한다. 현재 18/20×4는 Gemini 구독 모델에 같은 20문항을 묶어 보낸 선별 결과로, Sonnet/Opus 제품 API 간 비교 성적이 아니다. 잔액 부족 무응답도 모델의 교정 오류율로 세지 않는다.
