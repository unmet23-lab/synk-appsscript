# 하네스 위임 1단계 — 구체안 판정 (2026-08-20)

> **무엇을 정하나**: 유호님이 방향 긍정한 도전안 — 「운영 시스템은 Claude Code 하네스 표준 기능에 단계 위임하고,
> SYNK 손 유지분은 **자산 정본 4벌 + 안전 가드 3 + 결정.md** 로 수렴한다」(결정.md 08-20) — 의 **1단계 실행 범위**.
> 원칙: AI가 발달할수록 하네스 기본 기능이 손수 지은 운영 시스템을 흡수한다. 우리가 손으로 유지할 것은
> **하네스가 대체할 수 없는 것**(브랜드·철학·엔진·마스코트라는 자산, 비가역을 막는 안전, 유호님 확정 기록)뿐이다.

## 2. 보드·인계문 — 단계안

지금 선 자리: **PR = 작업 목록**(유호 확정 08-15)이 보드의 「선언」 역할 절반을 이미 흡수했다.
보드에 남은 고유 가치는 master 직발 단발 작업의 선언·세션 상태 칸이고, 인계문은 계정 갈아타기 바통이다.
하네스는 세션 목록·전사 검색·백그라운드 태스크를 이미 제공하지만 **다중 세션 조율은 아직 얇다**
(오늘도 로컬+클라우드 세션 4개가 초 단위로 master 를 경합했다 — 이 층을 지금 걷으면 그 경합이 무방비가 된다).

- **1단계 (지금)** — 스킬 은퇴(§1) + 결정 큐 소멸(✅오늘 완료) + 보드는 유지하되 **완화**: PR 로 여는 트랙은 보드 줄 생략 허용(PR 본문이 선언이다).
- **2단계 (1~2주 실사용 관찰 뒤)** — 신규 트랙 선언을 PR 본문으로 일원화하는 실험. 보드 파일은 읽기 전용 아카이브로 강등.
- **3단계** — 인계문을 「세션 끝 보고 + 커밋 메시지」로 흡수할지 판정. 계정 갈아타기 실사용이 남아 있으면 유지.
- **앞당김 트리거**: 하네스가 세션 간 조율 기능을 더 내면 그 시점에 단계를 재판정한다(새 모델·하네스 업그레이드 재검토 관례와 같은 축).

## 3. 대가 — 이 방향이 틀릴 때의 모습

1. **하네스 종속** — Claude Code 기능 변경에 운영이 흔들린다. 완충: 자산 정본·결정.md·안전 가드는 전부 git 안이라 하네스와 무관하게 산다.
2. **한마디 트리거 상실** — afk·close 를 걷으면 「밥 먹고 올게」·「끊자」의 절차 보장이 약해진다(자연어로 알아듣긴 하나 순서 보장이 없다).
3. **조율 공백** — 보드를 너무 일찍 걷으면 다중 세션 경합(오늘 실측 4세션)이 무방비가 된다. 그래서 2단계를 관찰 뒤로 뒀다.

## 4. 도전안 병기 — 「단계 없이 한 번에」

운영 스킬 4개(evolve·afk·missed·close)를 **오늘 전부 삭제**하고 보드·인계문도 같이 걷는다.
문제가 생기면 git 이력에서 되살린다 — v10.0 「낡은 것은 남기지 않는다 · 보존은 git 이력」의 끝.
대가: 되살리는 날의 재작업 + 과도기 세션들이 조율 없이 경합. **권고하지 않는다** — 오늘 하루만도
반입 9건이 삭제 근거를 뒤집는 일이 있었다(실측 후 건별이 이 저장소에서 반복 검증된 속도다).
