# 주간 부패 점검 (rot-check) — 하네스의 트리거 층

> **정본 = `tools/rot-check.js`.** 이 문서는 왜 있고 어떻게 쓰는지만 적는다.
> 회귀 = `tests/부패점검.test.js`(12건).

## 왜 있나

2026-08-03 루프 진단의 실측 결과: **이 하네스에는 트리거 층이 통째로 없었다.**

훅 4종(clasp-guard·board-guard·git-scope-guard·doc-propagation)은 전부 `PreToolUse` —
**내 행동을 막는 게이트**지, 무언가를 **띄우는 트리거**가 아니다.
그래서 도구는 만들어졌는데 아무도 돌리지 않았다. 증거 두 개:

| 증상 | 실측 |
|---|---|
| 마찰 신호가 쌓여도 아무 일도 안 일어난다 | 살아있는 신호 **3건**(지침의 /evolve 발동 조건은 2건). 세는 도구는 있는데 아무도 안 봤다 |
| 정본이 올라가도 파생이 안 따라간다 | 급여 정본 **v1.3**인데 파생 3종이 **v1.1** 수치를 인용 중. 엣지는 멀쩡히 붙어 있었다 |

공통점은 **실패가 에러가 아니라 침묵으로 나타난다**는 것이다. 침묵은 아무도 안 읽으면 영원히 침묵이다.

## 왜 cron이 아니라 SessionStart인가

루프 담론의 표준 처방은 "cron으로 에이전트를 상시 돌려라"지만 여기선 두 번 틀린다.

1. **이 하네스엔 상주 프로세스가 없다.** 세션이 켜질 때만 존재한다. 세션 밖 cron이 리포트를 써도 읽는 사람이 없다 — 지금 문제를 파일 하나 옮겨 재현하는 꼴이다.
2. **유호님 병목은 「일감 발견」이 아니라 「결정 대기」다.** 일감을 더 찾아내는 자율 루프는 큐에 기름을 붓는다.

→ 그래서 **트리거 = SessionStart + 주기 스로틀**, **산출 = 새 일감이 아니라 부패와 결정 순위**.
세션이 열릴 때 딱 한 번, 주기가 지났을 때만 리포트가 컨텍스트에 붙는다.
병행 세션 6개가 동시에 돌아도 처음 하나만 찍고 나머지는 침묵한다(상태 파일 스로틀).

## 정지 조건은 무르지 않다

검사 결과가 0건이면 **한 글자도 출력하지 않는다.**
("코드를 개선하라"는 정지 조건이 될 수 없지만 "깨진 링크 0건"은 된다.)

## 무엇을 보나

| 층 | 도구 | 🔴 수리 필요 | ⚠ 주의 |
|---|---|---|---|
| 메모리 그래프 | `memory-graph.js` | 깨진 링크 · 인덱스 유령 | 미지 타입 · 인덱스 누락 · 고아 |
| 문서 그래프 | `doc-graph.js` | 깨진 참조 · **낡은 인용**(@버전) | 정본 버전 미상 |
| 마찰 장부 | `friction.js` | — | 살아있는 신호 ≥2 → /evolve 발동 조건 알림 |
| 결정 큐 | `memory-graph --decisions` | — | 위상정렬 상위 3 + **큐 밖의 ⏳** |

**「큐 밖의 ⏳」가 핵심 계기판이다.** 결정 큐는 `막힘>` 엣지로만 순위를 매기므로,
글로만 적힌 ⏳는 큐에 안 잡힌다. 그 수를 함께 찍지 않으면 "차단자 2개"가 "대기 2건"으로 읽힌다.
2026-08-03 실측 = 엣지로 잡힌 대기 3건 · **글로만 대기 20개 토픽**.

## 쓰는 법

```bash
node tools/rot-check.js            # 전체 리포트(0건이면 「부패 없음」 한 줄)
node tools/rot-check.js --quiet    # 0건이면 완전 침묵
node tools/rot-check.js --json     # 기계 판독 · 🔴 있으면 종료코드 1
node tools/rot-check.js --hook --force   # 훅이 뭘 붙일지 지금 확인
```

주기 기본 7일. `SYNK_ROT_INTERVAL_DAYS`로 바꾼다.
상태 파일 `.claude/state/rot-check.json`은 **git이 추적하지 않는다**(기기·워크트리마다 다르고
추적하면 병행 세션끼리 매 실행 충돌한다). 지워도 다음 세션에 한 번 더 도는 것뿐이다.

## 시간축 엣지 (`@버전`)

파생 문서의 선언 줄에 정본 버전을 함께 박는다:

```
<!-- 파생: docs/정본/SYNK LAB/SYNK LAB 급여 인센티브 정본.txt@v1.1 -->
```

정본이 v1.3으로 오르는 순간 이 엣지는 **저절로 낡음**이 된다. 사실이 모순되는 대신 **만료**한다.
정본의 현재 버전은 **정본 본문 머리 12줄**에서 읽는다 — 파일명이 아니다
(`반편성_정본_v2.md`의 본문은 실제로 v2.3이라, 파일명을 믿으면 0.3만큼 틀린다).

- 고친 뒤 최신으로 찍기: `node tools/doc-graph.js --stamp <파생문서>`
- **`--stamp`는 조회가 아니라 선언이다** — "이 파생을 지금 정본에 맞춰 읽었다". 확인 없이 찍으면
  낡은 문서가 최신이라고 거짓말하게 된다(도구가 잡던 사고를 도구로 만드는 셈).
- 버전이 없는 엣지는 '최신'이 아니라 **'모름'**으로 센다. 모름을 정상으로 바꾸지 않는다.

## 코드값 인용 — 문서가 코드의 값을 베낄 때

`@버전` 엣지가 문서→문서를 만료시킨다면, 이 규약은 **문서→코드**를 맡는다.

2026-08-11 검토 패스 **한 번에 드리프트 7건**이 나왔다(래칫 7·13 → 실물 0·5 · 참조 줄번호
2곳 · 시험지 26 → 102문항 · 계약 판 c3/c2 → c10 · 구성 60 → 62). 전부 **설계 당시엔 맞았던
숫자**다 — 틀린 게 아니라 **낡은 것**이고, 읽는 사람에게 그 둘은 같은 모양이다. 위 급여 정본
v1.1 사고와 같은 병이 문서→코드 방향에서 난 것이다.

- **코드가 정본인 값**(상수 · 줄번호 · 판 번호 · 문항 수 · 회귀 건수)은 **참조로 쓴다** —
  「`lib/멘탈게이지.js` 의 5칸 판정」처럼 **어디를 열면 되는지**를 적고 값은 안 박는다.
- 숫자를 박아야 뜻이 서는 자리면 **`(측정일 MM-DD)`** 를 붙인다. 그러면 그 숫자는 주장이
  아니라 **관측 기록**이 되고, 낡아도 거짓말이 되지 않는다 — `@버전` 이 모순되는 대신
  만료하는 것과 같은 축이다.
- 🚫 **스캐너·CI 회귀로 잡지 않는다**(기각 승계). 코드값의 「같음」은 표기마다 갈려
  검사기가 거짓양성을 쏟고, 거짓양성을 쏟는 검사는 사람이 끈다. 이 규약이 정하는 것은
  **다음 검토 패스가 무엇을 드리프트로 셀지**이지 자동 차단이 아니다.
- 이미 이 표기로 정정된 자리 = 설계문서 9종(2026-08-11 패스). 새 문서가 어기면 다음 패스가 잡는다.

## 이 장치가 죽으면 어떻게 아나

이 도구 자체가 침묵으로 죽으면 아무 의미가 없다. 그래서:

- 세 검사는 **독립적으로** 실패한다. 하나가 터져도 나머지는 계속 돈다.
- 검사기가 고장 나면 **고장 사실을 리포트에 올린다**(회귀 `검사기가 고장 나면 침묵하지 않고…`).
- `settings.json`에 훅이 실제로 등록돼 있는지를 **테스트가 검사한다** — 도구만 만들고 배선을 잊으면
  트리거 층이 다시 0이 되는데, 그게 이번에 고친 병이다.
