# 시트 → Supabase 이관 — 판정 재료 한 장

> 유호 지시 2026-09-01 「⑦ 재료 정리해줘」.
> 나온 자리 = 발음데이터 규격 심문 P0-⑦ + **엔진도달 심문 P0**(같은 날 · **독립으로 같은 곳을 짚었다**).
> ⚠ 이 문서는 **재료지 판정이 아니다.** 아래 §5 가 유호님이 고르실 자리다.

## 0. 한 줄 — 물음은 「언제 옮기나」가 아니었다

처음 이걸 「언제 옮길지 정해야 한다」로 올렸는데 **그건 이미 정해져 있었다.**
실제로 비어 있는 자리는 **「무엇이 무엇으로 가는지의 표가 낡았다」** 하나다.

| 물음 | 답이 있나 | 어디 |
|---|---|---|
| 시트에 쌓는 것이 어긋남인가 | ✅ **아니다** — 「라이브 시트는 범위 안이다」 | `엔진도달_설계.md` §7 |
| 어떻게 옮기나 | ✅ 규칙 있음 — C0 한 통로 · 이관 어댑터 · 멱등키 + manifest | 같은 곳 |
| **언제** 옮기나 | ✅ **L0 확정 뒤 단계식** | 같은 곳 |
| 무엇이 무엇으로 가나 | 🟡 **표는 있는데 낡았다** | talk `docs/L0_데이터계약.md` §5 |
| 그 규칙의 **코드** | ⏳ **0** — 「이관 트랙 몫」이라 명시돼 있다 | `엔진도달_설계.md` §7 |

---

## 1. 이미 정해진 것 — 건드리지 않는다

`엔진도달_설계.md` §7 이 세운 경계 셋:

1. **라이브 시트는 범위 «안»이다.** v1 이 시트 4종을 범위 밖으로 뺐다가, 그러면 §1(「모든 수집은
   자동으로 엔진까지」)이 **동결 즉시 거짓**이 되므로 되돌린 자리다.
2. **통로는 C0 하나.** 직접 역방향 쓰기가 아니라 **버전 관리된 이관 어댑터**가 같은 쓰기 통로를
   지난다(「시트가 기계의 원천이 되는 «시트-원본» 재림 금지」). 기존 행 ID 로 **결정론적 멱등키 +
   import manifest** 를 남겨 중복·누락·원천 대조가 되게 한다.
3. **시점 = L0 확정 뒤 단계식.**

그리고 **과거 행이 원리상 못 지나는 관문**까지 이미 적혀 있다(08-11 Fable 심문 P1):
`correlation_id` 와 `submission.created` 의 `task_snapshot` 은 server 주체에도 무조건이라 옛 시트
행은 못 지난다. **지어 넣는 것은 금지**(검증기가 지어낸 값을 못 가려낸다 — 비어 있지만 않으면 통과).
⇒ 처방도 서 있다: 검증기에 **「이관」 갈래**를 세워 «이관 표기 + manifest 결측 기재»로 지나게 한다.
갈래 규칙 셋 — ①이관 표기는 **서버칸**(앱이 실으면 거절) ②이관 행은 **소비자 분모에 기본 제외**
③갈래 수명은 **이관 창 1회**(상시 통로가 되는 순간 새 우회로).

## 2. 🔴 진짜 비어 있는 자리 — 대조표가 낡았다

talk `docs/L0_데이터계약.md` §5 에 **「라이브 필드 ↔ L0 대조」 표**가 있다. `voice_log` 행은 이렇다:

> `voice_log`: 파일URL·file_id / 전사·전사상태 → `submissions.audio_ref` / `.transcript`·`.transcript_state`

**그 표는 `voice_log` 가 12칸이던 시절 것이다.** 그 뒤 실물이 세 번 자랐고 **그 증분은 표에 없다**:

| 언제 | 무엇이 늘었나 | L0 자리 |
|---|---|---|
| `v9.277` | `목표발화` · `시즌` · `전사신뢰도` · `전사엔진판` · `발음태그` · `돌려준날` (6칸) | ❌ 없음 |
| `v9.278` | `voice_missions` 시트(설정표 — 수집 장부는 아니다) | ❌ 없음 |
| **`v9.289`**(오늘) | `voice_labels` · `voice_delivery` **사건 원장 둘** | ❌ 없음 |

⇒ 오늘 기준 **여덟 칸 + 시트 둘**이 「옮길 곳이 안 정해진」 상태다.
⚠ 이 중 **`발음태그`·`돌려준날` 두 칸은 폐지**라 옮길 것이 아니다(정본은 사건 원장) — 그 사실도
표가 알아야 한다. 안 그러면 이관 어댑터가 **폐지된 칸을 옮기려 든다.**

🔑 **이것이 엔진도달 심문 P0 이 짚은 그 자리다** — *「사건별 스키마·시간·식별자·소비자별 강제
제외가 없다」*. 필드 매핑(무엇이 무엇으로)은 있는데 **그것이 실물을 안 따라왔다.**

## 4. 그래서 이관하려면 실제로 필요한 것

1. **대조표 현행화** — 위 §2 의 여덟 칸 + 시트 둘. 폐지 둘은 「옮기지 않음」으로 명시.
2. **가름 규칙** — 26종 중 무엇이 L0 로 가고 무엇이 운영 시트로 남나(§3 의 그 차이).
3. **이관 갈래 코드** — 엔진도달 §7 이 규칙만 세우고 「지금 0」이라 밝힌 것.
4. **멱등키 규약** — 시트 행 ID → 결정론적 키. 시트마다 「행 ID」가 무엇인지가 다르다
   (`voice_log` 는 `file_id`, 다른 시트는 다르다 — ⚠ `file_id` 가 고유키인지는 **아직 안 쟀다**).
5. **manifest 형식** — 결측 칸을 지어내지 않고 기재하는 자리.

⏳ **1·2 는 문서 작업이고 3·4·5 는 코드다.** 그리고 **1·2 는 형제 저장소(talk) 문서를 고치는 일**이다
— 이 저장소 세션이 그쪽 정본을 고치면 두 곳이 갈린다.

## 5. 🔴 유호님이 고르실 자리 — 갈래 셋

> 셋 다 「지금 이관한다」가 아니다. 이관 시점은 §1 대로 **L0 확정 뒤**이고, 여기서 정하는 것은
> **「그 표를 언제 맞추나」**다.

| | 갈래 | 값 | 대가 |
|---|---|---|---|
| **ⓐ** | **지금 맞춘다** — talk 세션이 L0 §5 를 현행화(여덟 칸 + 시트 둘 + 폐지 둘 표기) | 새 칸이 선 «그날»이 제일 싸다. 지금은 실데이터 0행이라 무엇을 옮길지 정해도 잃는 것이 없다 | talk 세션 한 벌이 든다 · 이관 착수 전이라 **당장 쓰이지는 않는다** |
| **ⓑ** | **이관 착수 때 한 번에** — 그때 실물을 다시 읽어 표를 새로 쓴다 | 지금 일이 0 · 어차피 그때 전수로 대조한다 | 🔴 **그 사이에 또 자란다.** 이 표는 이미 세 판을 놓쳤다(v9.277·v9.278·v9.289) — 「나중에 한 번에」가 그 셋을 만든 방식이다 |
| **ⓒ** | **자를 세운다** — 시트 헤더가 바뀌면 L0 §5 가 낡았음을 기계가 운다 | 사람 기억에 안 걸린다 · 오늘 지은 `ai스택점검` 과 같은 꼴 | 형제 저장소를 가로질러 재야 한다(그 자가 아직 없다) · 자 하나가 더 는다 |

**내 판단 = ⓐ + ⓒ.**
ⓑ 는 이미 세 번 실패한 방식이다(표가 세 판을 놓친 것이 그 증거다). ⓐ 로 지금 맞추고, ⓒ 로 **다음에
또 벌어지는 것**을 막는 쪽이 값이 크다 — 다만 ⓒ 는 형제 저장소를 가로지르는 자라 오늘 지은 자들보다
비싸다. **ⓐ 만 먼저 하고 ⓒ 는 다음에 여는 것도 온전한 선택**이다.

⚠ **ⓐ 는 이 저장소 세션이 못 한다** — L0 는 talk 정본이라 그쪽 세션이 고쳐야 두 곳이 안 갈린다.
유호님이 ⓐ 를 고르시면 **talk 세션에 넘길 발주 한 줄**까지가 이 문서의 몫이다.

## 6. 안 잰 것

- **26종 중 무엇이 L0 대상인가**를 세지 않았다 — §3 의 「약 20종」은 두 목록의 산술 차이지 판정이 아니다.
- **`file_id` 가 고유키인가**는 안 쟀다(발음 심문 P0-⑥ 조건부 그대로).
- talk 저장소의 **C0 API 계약**은 안 열었다 — 이관 어댑터가 지날 통로의 실물 규격이 거기 있다.
- 이 문서는 **라이브 DB 를 안 봤다.** 위 전부 문서·코드를 읽어서 안 것이다.
