# 발주서 틀 — GPT 실행자에게 «닫힌 명세»를 주는 법

> 2026-09-04 세움(유호 확정 09-04 「기술실행자 역할 추가 · 자동으로 흘러가게」). 이 틀대로 쓴 발주서를 `node tools/codex-build.js --발주 <파일>` 에 주면 발주 검토 → 구현 → 시험 → 커밋 → 검수 → 수용 대조까지 사람 손 없이 돈다.
> 쓰는 사람 = 클로드(설계). 읽는 사람 = GPT 실행자(구현) · GPT 검토자(구현 전 구멍 찾기) · GPT 검수자(수용 대조 단계에 «수용 기준»만).
> 도구가 형식을 먼저 잰다 — 절이 빠지면 코덱스를 태우기 전에 멈춘다(`tools/codex-build.js` 의 `발주서검사`).

## 규격 — 절 넷은 필수, 둘은 선택

| 절(`## 제목`) | 무엇을 적나 | 도구가 어떻게 쓰나 |
|---|---|---|
| **목표** (필수) | 무엇을 왜 — 1~3줄. 「어디가 비어서 무엇을 채운다」 | 실행자·검토자 프롬프트에 전문 |
| **범위** (필수) | 실행자가 만져도 되는 **경로 목록**(`- \`경로\``). 폴더는 `/` 로 끝내고, 별표(`*` 한 마디 · `**` 여러 마디)도 된다 | 워크트리의 `git status` 를 이 목록에 댄다 — 밖이 하나라도 있으면 **커밋 안 함** |
| **수용 기준** (필수) | 번호 목록. **시험으로 판정할 수 있는 문장**으로(「빠르다」✗ · 「`subtract(5,3)` 이 2 다」○) | 검수자(다른 세션)가 기준마다 충족/미충족/확인불가 |
| **시험** (필수) | 도구가 **직접 돌릴 명령**(`- \`node --test tests/x.test.js\`` · talk 은 `npm test`) | 실행자가 돌린 것과 무관하게 도구가 다시 돌린다 — 종료코드가 자다 |
| 금지 (선택) | 이 발주에서 특히 하면 안 되는 것 | 실행자 프롬프트에 전문 |
| 맥락 (선택) | 먼저 읽을 문서·함수 경로(`- \`docs/x.md\``) | 실행자 프롬프트에 전문(내용은 실행자가 저장소에서 읽는다 — 본문을 베껴 넣지 않는다) |
| 시험 수정 허용 (선택) | **이미 있는 시험 파일** 중 이 발주가 고쳐도 되는 것(`- \`tests/x.test.js\``) | 이 절에 이름이 없으면 있던 시험은 못 고친다(아래) · 시험이 아닌 경로를 적으면 발주서가 **거절**된다 |

**어느 발주서도 범위에 넣을 수 없는 자리**(정본·가드·훅·장부·모델값 = 사람 몫 · 도구가 거절한다): `.claude/` · `.github/` · `.githooks/` · `AGENTS.md` · `CLAUDE.md` · `appsscript.json` · `docs/_ops/결정.md` · `docs/_ops/트랙.md` · `docs/SYNK_철학.md` · `docs/제품방향.md` · `docs/GPT_정본.md` · `tools/모델정책.js` · `tools/codex-review.js` · `tools/codex-build.js`. 전체 목록 = `tools/codex-build.js` 의 `금지경로들`.

**🔴 실행자는 저를 재는 시험을 못 고친다**(2026-09-04). ③의 자는 «시험 종료코드»인데, 시험 파일이 «범위» 안에 있으면 실행자가 그 자를 느슨하게 고쳐 초록을 만들 수 있다 — 코드가 아니라 자가 바뀐 것이라 종료코드는 참말처럼 보인다. 그래서 도구가 실행 «전»에 추적 중인 시험 파일의 지문을 떠 두고 라운드마다 대조한다.

- **있던 시험을 고치거나 지우면** 그 라운드는 커밋 없이 멈춘다(워크트리는 그대로 — 읽고 정한다).
- **새 시험 파일을 더하는 것은 자유다** — 발주가 시험을 붙이는 것이 정상이다.
- 깨진 시험 수리처럼 **정말 고쳐야 하는 발주**는 `## 시험 수정 허용` 절에 그 파일을 이름 대어 연다. 기본이 막힘이고, 연 자리는 장부에 남아 검수자가 본다.

## 쓰는 법 — 좋은 발주서의 조건 넷(SYNK-talk `docs/개발_분업.md` §4)

1. **입출력이 구체적인가** — 함수 이름·인자·반환·오류 모양까지. 「적당히」는 실행자가 짐작으로 메운다.
2. **빈 값·중복·네트워크 실패·재시도가 정의됐는가** — 안 정하면 실행자는 가장 보수적으로 짓고 «남긴것»에 적는다.
3. **완료 기준을 시험으로 판정할 수 있는가** — 수용 기준 한 줄에 시험 한 줄이 대응되게.
4. **구현 불가능하거나 모순된 요구가 없는가** — 발주 검토 단계(코덱스 · 읽기 전용)가 이것을 먼저 잰다. «막힘»이면 실행자를 안 태우고 돌려준다.

🔑 발주서는 **닫힌 명세**다 — 기억이 필요 없어야 한다. 실행자는 철학 전문·트랙·결정 이력을 못 받는다(`docs/GPT_정본.md` §0). 그래서 판단이 필요한 것은 발주서 안에서 끝낸다.

## 본보기

```markdown
# 발주 — 숙제 채점기에 「빈 답」 갈래를 더한다

## 목표
`엔진_숙제.js` 의 `채점_()` 이 빈 답(`""`·공백만)을 오답으로 세어 학생이 0점을 받는다. 빈 답은 «미제출»로 갈라 점수에서 뺀다.

## 범위
- `엔진_숙제.js`
- `tests/숙제채점.test.js`

## 수용 기준
1. `채점_({답: ""})` 과 `채점_({답: "   "})` 이 `{상태: "미제출", 점수: null}` 을 돌려준다.
2. 기존 오답(`{답: "틀린 문장"}`)의 결과는 바뀌지 않는다(회귀 시험이 그대로 통과).
3. 새 갈래를 재는 시험이 `tests/숙제채점.test.js` 에 있고 통과한다.

## 시험
- `node --test tests/숙제채점.test.js`

## 금지
- 시트의 열을 늘리지 않는다(라이브 시트 칸은 코드를 안 따라온다).

## 맥락
- `docs/_ops/트랙.md` §0-숙제 (왜 지금인가)
```

## 다음 — 도구가 돌린 뒤 사람이 하는 것

1. 도구 보고를 읽는다: 가지 이름 · 시험 결과 · 검수 지적 · 수용 대조 · 실행자가 남긴 것.
2. **클로드 의미·통합 확인** = 가지 diff 를 읽고(`git diff master...codex/<지문>`) 발주 의도·정본과 맞는지 본다. 맞으면 master 에 합치고 push. 아니면 발주서를 고쳐 같은 명령으로(같은 워크트리에서 이어 돈다).
3. **유호님 운영 승인** = 배포(`/deploy` · talk 은 `tools/원격배포.js`). 이 도구는 배포하지 않는다.
