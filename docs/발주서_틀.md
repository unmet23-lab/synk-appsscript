# 발주서 틀 — GPT 실행자에게 «닫힌 명세»를 주는 법

> 2026-09-04 세움(유호 확정 09-04 「기술실행자 역할 추가 · 자동으로 흘러가게」). 이 틀대로 쓴 발주서를 `node tools/codex-build.js --발주 <파일>` 에 주면 발주 검토 → 구현 → 시험 → 커밋 → 검수 → 수용 대조까지 사람 손 없이 돈다.
> 쓰는 사람 = 현재 라우터(GPT 또는 클로드). 전문 설계와 뜻 대조는 필요할 때 클로드에 맡긴다. 읽는 사람 = GPT 실행자(구현) · GPT 검토자(구현 전 구멍 찾기) · GPT 검수자(수용 대조 단계에 «수용 기준»만).
> 도구가 형식을 먼저 잰다 — 절이 빠지면 코덱스를 태우기 전에 멈춘다(`tools/codex-build.js` 의 `발주서검사`).

## 규격 — 필수·선택 절

| 절(`## 제목`) | 무엇을 적나 | 도구가 어떻게 쓰나 |
|---|---|---|
| **목표** (필수) | 무엇을 왜 — 1~3줄. 「어디가 비어서 무엇을 채운다」 | 실행자·검토자 프롬프트에 전문 |
| **범위** (필수) | 실행자가 만져도 되는 **경로 목록**(`- \`경로\``). 폴더는 `/` 로 끝내고, 별표(`*` 한 마디 · `**` 여러 마디)도 된다 | 워크트리의 `git status` 를 이 목록에 댄다 — 밖이 하나라도 있으면 **커밋 안 함** |
| **수용 기준** (필수) | 번호 목록. **시험으로 판정할 수 있는 문장**으로(「빠르다」✗ · 「`subtract(5,3)` 이 2 다」○) | 검수자(다른 세션)가 기준마다 충족/미충족/확인불가 |
| **시험** (필수) | 도구가 **직접 돌릴 명령**(`- \`node --test tests/x.test.js\`` · talk 은 `npm test`) | 실행자가 돌린 것과 무관하게 도구가 다시 돌린다 — 종료코드가 자다 |
| 금지 (선택) | 이 발주에서 특히 하면 안 되는 것 | 실행자 프롬프트에 전문 |
| 맥락 (선택) | 먼저 읽을 문서·함수 경로(`- \`docs/x.md\``) · **범위 안에 이미 알려진 결함이 있으면 여기 적는다**(아래 🔴) | 실행자 프롬프트에 전문(내용은 실행자가 저장소에서 읽는다 — 본문을 베껴 넣지 않는다) |
| 시험 수정 허용 (선택) | **이미 있는 시험 파일** 중 이 발주가 고쳐도 되는 것(`- \`tests/x.test.js\``) | 이 절에 이름이 없으면 있던 시험은 못 고친다(아래) · 시험이 아닌 경로를 적으면 발주서가 **거절**된다 |
| 부품 (선택) | 이 발주가 쓸 바깥 꾸러미. **이미 깔린 것만 적는다**(아래 🔴) | 실행자 프롬프트에 전문 — 「이것은 쓸 수 있다」는 목록이지 「깔아라」가 아니다 |

**어느 발주서도 범위에 넣을 수 없는 자리**(정본·가드·훅·장부·모델값 = 사람 몫 · 도구가 거절한다): `.claude/` · `.github/` · `.githooks/` · `AGENTS.md` · `CLAUDE.md` · `appsscript.json` · `docs/_ops/결정.md` · `docs/_ops/트랙.md` · `docs/SYNK_철학.md` · `docs/제품방향.md` · `docs/GPT_정본.md` · `tools/모델정책.js` · `tools/codex-review.js` · `tools/codex-build.js`. 전체 목록 = `tools/codex-build.js` 의 `금지경로들`.

**🔴 실행자는 저를 재는 시험을 못 고친다**(2026-09-04). ③의 자는 «시험 종료코드»인데, 시험 파일이 «범위» 안에 있으면 실행자가 그 자를 느슨하게 고쳐 초록을 만들 수 있다 — 코드가 아니라 자가 바뀐 것이라 종료코드는 참말처럼 보인다. 그래서 도구가 실행 «전»에 추적 중인 시험 파일의 지문을 떠 두고 라운드마다 대조한다.

- **있던 시험을 고치거나 지우면** 그 라운드는 커밋 없이 멈춘다(워크트리는 그대로 — 읽고 정한다).
- **새 시험 파일을 더하는 것은 자유다** — 발주가 시험을 붙이는 것이 정상이다.
- 깨진 시험 수리처럼 **정말 고쳐야 하는 발주**는 `## 시험 수정 허용` 절에 그 파일을 이름 대어 연다. 기본이 막힘이고, 연 자리는 장부에 남아 검수자가 본다.

## 쓰는 법 — 좋은 발주서의 조건 넷(SYNK-talk `docs/개발_분업.md` §4)

1. **입출력이 구체적인가** — 함수 이름·인자·반환·오류 모양까지. 「적당히」는 실행자가 짐작으로 메운다.
2. **빈 값·중복·네트워크 실패·재시도가 정의됐는가** — 안 정하면 실행자는 가장 보수적으로 짓고 «남긴것»에 적는다.
3. **완료 기준을 시험으로 판정할 수 있는가** — 수용 기준마다 증거 종류와 확인 방법을 같은 문장에 적는다. 함수는 시험 결과, 화면은 합성 자료로 실제 조작한 결과, 저장·연동은 저장 전후와 재조회 결과다. 코드가 있다는 설명만으로 실제 동작을 충족 처리하지 않는다. 도구는 기준 원문과 응답을 전수 대조해 누락·중복·항목별 확인불가를 차단한다.
4. **구현 불가능하거나 모순된 요구가 없는가** — 발주 검토 단계(코덱스 · 읽기 전용)가 이것을 먼저 잰다. «막힘»이면 실행자를 안 태우고 돌려준다.

🔑 발주서는 **닫힌 명세**다 — 기억이 필요 없어야 한다. 실행자는 철학 전문·트랙·결정 이력을 못 받는다(`docs/GPT_정본.md` §0). 그래서 판단이 필요한 것은 발주서 안에서 끝낸다.
  ↳ 09-08 부터 **철학 «게이트»는 받는다**(전문은 여전히 안 받는다 · 현행 의미 구간 다섯을 온전하게 받으며 잘림은 완료가 아니다 · 재는 자 `node tools/GPT철학대조.js`).

🔴 **실행자는 인터넷이 끊긴 채 돈다**(`sandbox_workspace_write.network_access=false` · `web_search="disabled"`). 울타리가 «쓰기»만 막고 «읽기»는 안 막아서 홈의 자격증명 파일이 읽히는데, **밖으로 나갈 길이 없다는 것이 지금 유일한 벽**이기 때문이다(`tools/codex-build.js` 머리말 ①). codex 는 «일부 주소만 열기»를 지원하지 않아 전부 열거나 전부 닫는 둘뿐이다(09-08 실측).
  ⇒ 그래서 **새 꾸러미를 «들여오는» 것은 실행자가 못 한다.** 이미 깔린 것을 «쓰는» 것은 된다(형제 저장소 `../SYNK-talk` 는 부품 17개가 `node_modules` 에 깔려 있어 인터넷 없이 돈다 · 09-08 실측).
  ⇒ 새 부품이 필요하면 **발주 «전»에 사람이 깔고**, `## 부품` 절에 이름을 적어 「이건 쓸 수 있다」를 알린다. 실행자가 스스로 필요를 발견하면 «발주밖발견»에 적게 하고(고치지 말고), 그 라운드 뒤에 사람이 깔아 다시 던진다.
  ⚠ 도구는 꾸러미를 **안 깐다.** 발주서에 적었다고 설치가 도는 것이 아니다 — 적는 것은 «쓸 수 있다»는 선언뿐이다.

🔴 **«이 저장소가 아는 미완»은 검수자만 받고 실행자는 못 받는다**(`tools/codex-review.js` 의 `아는미완블록` 이 검수 프롬프트에만 붙는다 · 09-08 실측). 그래서 범위 안에 이미 알려진 결함이 있으면 **발주서 §맥락에 그것을 적는 것이 유일한 통로다.** 안 적으면 실행자는 두 갈래로 샌다 — ⓐ 그 결함 위에 짓거나 ⓑ 그것을 «새로 찾은 문제»로 «발주밖발견»에 올려 라운드를 한 번 더 돌린다.
  ⚠ 저장소 전반의 미완을 통째로 주지는 않는다. 실행자에게 범위 밖 재료를 주면 「철학상 이것도 고쳐야 한다」로 범위가 새기 때문이다(그래서 철학 블록에도 「범위는 발주서가 정한다」가 박혀 있다).

## 본보기

```markdown
# 발주 — 숙제 채점기에 「빈 답」 갈래를 더한다

## 목표
`엔진_숙제.js` 의 `채점_()` 이 빈 답(`""`·공백만)을 오답으로 세어 학생이 0점을 받는다. 빈 답은 «미제출»로 갈라 점수에서 뺀다.

## 범위
- `엔진_숙제.js`
- `tests/숙제채점.test.js`

## 수용 기준
1. `채점_({답: ""})` 과 `채점_({답: "   "})` 이 `{상태: "미제출", 점수: null}` 을 돌려준다.
2. 기존 오답(`{답: "틀린 문장"}`)의 결과는 바뀌지 않는다(회귀 시험이 그대로 통과).
3. 새 갈래를 재는 시험이 `tests/숙제채점.test.js` 에 있고 통과한다.

## 시험
- `node --test tests/숙제채점.test.js`

## 금지
- 시트의 열을 늘리지 않는다(라이브 시트 칸은 코드를 안 따라온다).

## 맥락
- `docs/_ops/트랙.md` §0-숙제 (왜 지금인가)
```

## 다음 — 자동 기록과 라우터 인계

1. 도구 보고를 읽는다: 가지 이름 · 시험 결과 · 검수 지적 · 수용 대조 · 실행자가 남긴 것.
2. **라우터 의미·통합 확인** = 가지 diff 를 읽고(`git diff master...codex/<지문>`) 발주 의도·정본과 맞는지 본다. 긴 설계의 뜻 대조는 클로드에 쟁점과 관련 결정만 전달한다. 맞으면 master 에 합치고 push. 아니면 발주서를 고쳐 같은 명령으로(같은 워크트리에서 이어 돈다). 실제 권한은 각 역할의 `AGENTS.md`를 따른다.
3. **유호님 운영 승인** = 배포(`/deploy` · talk 은 `tools/원격배포.js`). 이 도구는 배포하지 않는다.

도구가 `실행기록.jsonl`에 발주 지문·대상 커밋·시험·수용 기준의 분모·검수 결과·다음 행동을 `인계`로 자동 기록한다. 수용 대조만 확인 불가로 남았고 같은 커밋·깨끗한 작업본·시험과 검수 완료가 확인되면, 같은 명령은 실행자를 생략하고 시험 재실행과 수용 대조를 이어간다. 확인 불가의 이유가 자료 부족이면 라우터가 그 자료부터 보완한다. `--검수안함`은 진단용이며 완주를 만들지 않는다.

`node tools/워크플로성과.js`는 기존 검수·처분·실행 기록을 읽어 채택/기각/대상 제외/미처분을 분리한다. `tools/브리핑.js`에서도 자동으로 출력한다. 과거에 시간이나 발견 벤더를 기록하지 않은 곳은 추정하지 않는다. 모델의 이름·효력·회차는 기존 정책을 따른다.

## 역할별 인계 재료

- GPT 실행자: 목표·범위·재현 입력·완료 증거·관련 문서 경로. 구현 방법은 범위 안에서 탐색한다.
- 독립 검수자: 검수 대상과 확인 가능한 증거. 작성자의 자기평가·추론·앞 검수자의 결론은 첫 판단에 넣지 않는다. 범위·재현 입력·깨지는 동작으로 지적한다.
- 클로드의 뜻 대조: 관련 결정의 이유·버린 대안·변경 쟁점. 의미가 달라진 위치와 수정안을 받는다. 기억 전문을 복사하지 않는다.
- Gemini의 언어·시각 판단: 기존 통로가 허용하는 비식별 원문·실물과 사용 목적. 원문 위치·화면 위치·영상 시점, 관측과 불확실성을 구분해 받는다. 코드 검수는 현재 변경분만 읽으므로 저장소 전체를 봤다고 간주하지 않는다. 영상 관측의 새 자동 호출은 아직 품질을 검증하지 않았으므로 이 설정에서 신설하지 않는다.
