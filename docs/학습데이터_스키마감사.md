## 어긋난 자리와 교정 (전부 이번에 반영 · 새 열은 전부 **끝에만**)

1. **[기능 결함] talk가 급수를 안 보내고 있었다** — `callClaudeTalk_`가 `stu`(급수 포함)를 받고도 본문에서 **한 번도 안 씀**.
   시스템 프롬프트는 「급수(1~6)에 맞춰 어휘·문장 길이를 조절한다」를 지시하는데 급수를 안 알려줘 죽은 지시였다.
   → 시스템 프롬프트 끝에 `[이 학생] 급수: N` 동적 접미(급수는 데이터라 prompt_ver 지문 밖 — 지문은 상수부만).
2. **[레벨 키 부재] 수집 4시트 전부 급수 열 0개** — 불변식 2 명문 위반. profiles BO67은 현재값(승급하면 과거 소실),
   `academic_log` 'level'은 강사 월 1회 입력이라 월 정밀도+입력 의존 — 소급 조인은 반쪽이다.
   → `hw_feedback`·`quiz_log`·`talk_log`·`voice_log` 맨 끝에 `급수`(0=미정), 적재 시점 profiles 스냅샷.
3. **[출처 부재] hw_feedback에 model·prompt_ver 없음** — 교정문은 모델 출력물. talk_log에 v9.145가 같은 이유로 넣었는데
   원문↔교정 병렬쌍인 본체가 빠져 있었다. → 시스템 프롬프트 상수화(`FB_SYSTEM_PROMPT`) + `fbPromptVer_()` 지문 + 2열.
4. **[자기 원칙 위반] hw_feedback이 숙제 문항 텍스트를 스냅샷 안 함** — 엔진_수집.js 머리의 원칙 2(「ID만 저장하면
   2년 뒤 해석 불능」)를 quiz_log만 지키고 있었다. → `숙제문항` 열, 배치가 contents에서 지연 1회 로드(재작성 행은 빈칸=원본 조인).
5. **[어휘 사본 갈라짐 위험] 오류태그 23종을 SYNK-talk와 「이름만」 공유** — 한쪽이 태그를 늘리면 저쪽 채점기가
   모르는 태그를 조용히 오답 처리. → 골든픽스처 문서에 `어휘: HW_ERROR_TAGS` 전량 동봉(받는 쪽이 diff로 그날 감지).
6. **[로직 2벌] 헤더 치유가 hw·talk 각자 구현** — 4시트 동시 증분을 계기로 공용 `헤더보정_(sh, HEADERS)` 하나로 통합
   (quiz·voice에도 배선 — 라이브 시트에서 새 칸이 조용히 버려지는 것을 막는 통로).

## 통과 확인 (감사에서 멀쩡했던 것)

- 원문 보존 원칙(수집이 채점보다 우선)이 전 경로에 살아 있다 — 채점·첨삭·답장 실패가 행을 버리지 않는다.
- 문항 스냅샷: quiz는 문제(보기 포함)·정답을 행에 복제 ✓. 시점 키: 제출일+created_at 전 시트 ✓.
- 시트 골격(SHEET_SKELETON)이 헤더 **상수를 참조**(단일 정본)라 이번 열 추가가 재건·preflight에 자동 전파.
