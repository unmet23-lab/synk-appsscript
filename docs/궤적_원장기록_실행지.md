## 0. 왜 급한가: 미루면 다시는 받을 수 없다

로드맵 ④(유학 집약 봇)에서 경쟁자가 따라 할 수 없는 자산은 하나뿐입니다.
**「몽골 학생이 무엇을 목표했고, 실제로 어디로 갔는가」를 짝지은 데이터입니다.**

목표(왼쪽)는 이미 충분히 쌓이고 있습니다(크루카드 100+문항). 결과(오른쪽)는 **사람을 통해서만 알 수 있습니다.**

> **주의: 학생이 떠나면 연락이 끊깁니다.** 코드를 나중에 만들어도 데이터는 돌아오지 않습니다.
> 소식을 들은 날 바로 한 줄 적는 것 말고는 방법이 없습니다.

**한 줄 적는 데 30초면 됩니다.** 완벽하게 적으려 하지 마세요. 학생ID와 단계만 있어도 의미가 있습니다.

## 1. 어디에 적나

**SYNK 메인 구글 시트 → 맨 아래 탭 목록에서 `outcome_log` 탭 → 데이터가 끝난 첫 빈 줄.**

- 탭이 안 보이면 시트 아래쪽 탭 목록 왼쪽 **`≡`(모든 시트)** 버튼을 눌러 이름으로 찾으세요.
- 줄 순서는 상관없습니다. **맨 아래에 그냥 이어 적으면 됩니다**(정렬하지 마세요).
- **탭 이름을 바꾸거나 지우지 마세요.** 지우면 시스템이 빈 탭을 새로 만들고, 적어 둔 소식은 사라집니다.

## 2. 12칸 중 **5칸만** 채운다

| 칸 | 이름 | 채우기 | 내용 |
|---|---|---|---|
| **A** | student_id | ✅ **필수** | `SYNK-001` 형식 (모르면 → 3번) |
| **B** | 이름 | ✅ 권장 | 나중에 사람이 읽기 위한 칸 |
| **C** | 관측일 | ✅ **필수** | **`2026-05`**처럼 연-월만. 「소식을 들은 달」이 아니라 **「그 일이 일어난 달」** |
| **D** | 단계 | ✅ **필수** | 드롭다운에서 고름 (어디까지 갔나) |
| **E** | 결과종류 | ✅ **필수** | 드롭다운에서 고름 (어느 길로 갔나) |
| F | 기관·회사명 | 선택 | 「건국대」·「현대중공업 협력사」 등 아는 만큼 |
| G | 비자종류 | 선택 | 드롭다운 |
| **H** | 출처 | ✅ **필수** | 드롭다운. **직접 확인한 것과 전해 들은 것을 구분하는 칸** |
| I | 활용동의 | 선택 | 드롭다운 2개 중 선택 (모르면 **비워 둠**) |
| J | 비고 | 선택 | 자유 메모 |
| **K** | 근거키 | ⛔ **비워 둠** | 자동 수집 전용 (적으면 중복 방지가 제대로 작동하지 않습니다) |
| **L** | created_at | ⛔ **비워 둠** | 자동 |

> **D·E·G·H·I 칸은 셀을 누르면 목록이 뜹니다.** 직접 입력하지 말고 **목록에서 고르세요.**
> 목록에 없는 값을 넣으면 셀에 빨간 삼각형이 뜨지만 저장은 됩니다. 그럴 때는 저에게 알려 주세요
> (같은 뜻의 값이 여러 표기로 나뉘면 2년 뒤 집계를 할 수 없습니다. 나중에 정리해도 지난 기록은 바로잡히지 않습니다).
> 주의: 드롭다운은 **501번째 줄까지** 미리 설정되어 있습니다. 졸업생이 500명을 넘으면 알려 주세요.

## 3. 학생ID를 모를 때: `trajectory` 탭에서 이름으로 찾기

앱은 학생에게도 원장에게도 학생ID를 화면에 보여 주지 않습니다. 대신 이렇게 찾습니다.

**`trajectory` 탭을 열면 A열=학생ID · B열=이름 · C열=반**이 모든 학생에 대해 있습니다.
**`Ctrl+F`로 이름을 검색**해서 A열 값을 복사해 오세요.

> **이 표에는 그만둔 학생도 남아 있습니다.** `profiles`(앱 로스터)는 퇴원한 학생을 지우는데,
> 진로 기록이 필요한 사람은 바로 그 그만둔 학생들입니다. 그래서 `trajectory`는 **상담시트**를 바탕으로 만듭니다.

## 5. 언제 반영되나: **다음 날 아침 7시에 자동으로**

적고 나서 아무것도 누르지 않아도 됩니다.

```
매일 07:00  →  상담시트 동기화  →  궤적 갱신  →  trajectory 탭 재작성
```

**다음 날 확인할 곳 2군데**

1. **`trajectory` 탭**: 그 학생 줄의 J~P열(최종단계·결과종류·…·**의도↔결과**)이 채워집니다.
2. **`app_state` 탭**: `궤적커버리지` 키. `3/57 (2026-08-04)`은 **57명 중 3명의 결과를 안다**는 뜻입니다.

**P열 `의도↔결과`가 이 기록의 최종 결과물입니다.** 읽는 법:

| 값 | 뜻 |
|---|---|
| `일치` | 목표한 길로 갔다 |
| `불일치(유학→취업)` | 유학을 목표했는데 취업으로 갔다 ← **가장 가치 있는 신호** |
| `진행중` | 아직 결과가 나오지 않았다(지원·대기·보류) |
| `좌절(재도전 가능)` | 거절당했다. **실패가 아니라 그 과정의 한 단계** |
| `의도 미정` | 학생이 목표를 「아직 미정」으로 답했다. **상담에서 먼저 물어볼 사람** |
| `미관측` | 결과를 아직 모른다 ← 이 문서가 줄이려는 숫자 |
| `분류 불가` | 결과가 「기타·미상」이라 목표와 비교할 수 없다 |

## 6. 하지 말 것 5가지

1. **`trajectory` 탭을 직접 고치지 마세요.** 매일 아침 전체가 다시 만들어지므로
   고친 내용은 **다음 날 알림 없이 사라집니다.** 고칠 곳은 **언제나 `outcome_log`**입니다.
2. **C열(관측일)에 `2026-05-15` 같은 날짜를 넣지 마세요.** 연-월(`2026-05`)만 적습니다.
   날짜를 넣으면 시트가 날짜 형식으로 바꿔 버려서, 최신 기록을 고르는 순서가 **날짜순이 아니라 요일 이름순**으로 뒤집힙니다
   (예전 합격이 최근 거절보다 앞서게 됩니다. 화면에 오류는 뜨지 않습니다).
3. **결과종류(E)에 「거절」·「불합격」을 넣지 마세요.** 그것은 D열(단계)에 들어갈 값입니다.
   섞어 쓰면 **거절당한 사람이 가려던 길의 기록이 통째로 사라집니다.**
4. **`outcome_log`·`trajectory`를 Glide 앱에 올리지 마세요.** 여기에는 **다른 학생의 결과까지** 모여 있습니다
   (핵심비전·⚠상담위험 열과 같은 보안 등급). 학생 본인의 목표는 앱에 이미 따로 있습니다.
5. **한 사람의 예전 줄을 지우거나 덮어쓰지 마세요.** 아래 7번을 보세요.

## 7. 한 사람에게 여러 줄이 있는 것이 정상입니다

`outcome_log`는 **일어난 일을 차례로 쌓는 기록**입니다. 한 학생이 다시 도전하면 **줄을 새로 추가**하세요.

```
SYNK-014 | 바트 | 2026-03 | 불합격·거절 | 유학(D-2·D-4) 비자 | 건국대  | 본인 제보
SYNK-014 | 바트 | 2026-09 | 합격·승인   | 한국 대학·대학원 입학 | 세종대 | 학원 서류 확인
```

`trajectory`에는 **가장 최근 기록 1건**만 표시됩니다(위 예시는 「합격·승인 / 세종대」).
예전 줄은 지우지 마세요. **「거절 뒤 재도전해서 붙었다」는 이 학원이 보여 줄 수 있는 가장 강력한 사례**이고,
두 줄이 모두 있어야만 남습니다.

## 개발 참고 — 생활 사건의 근거·인지·전달 연결 (2026-10-02)

Trail의 생활 영역 원본은 [`atlas/trail-life.js`](../atlas/trail-life.js)다. 기존 졸업생 `outcome_log`·학습 `practice.*`와 별도의 **게임 확정 사건 투영**을 읽으며, 생활 사실·소유·보상·인증·저장은 게임 서비스가 맡는다. 주민 이름이나 차양 규칙을 포함하지 않는 순수 CommonJS/UMD 모듈이고 브라우저 이름은 `SynkTrailLife`다. 새 중앙 엔진이나 LLM 실행기가 아니다.

- `append(events, event, options)`는 새 배열을 반환한다. 사건은 `schema/id/scope/seq/type`과 종류별 허용 필드만 사용한다. `life.fact`의 원인·직접 인지, `life.corrected`의 정정과 인과 무효화, `life.knowledge`의 원인 계보로 연결된 전달 사실에 의한 추가 인지/철회, `life.delivered`의 전달 이력을 검증한다. 시각 대신 증가하는 `seq`를 쓰며 정확 중복은 무시하고 ID 충돌·앞선 근거 누락·다른 scope는 거절한다.
- `summarize(events, {scope, complete})`는 현재 유효한 `facts`, NPC별 허용 사실 ID의 `knowledge`, 실제 과거 전달의 `deliveries`를 돌려준다. `complete:false`는 `status:'unknown'`으로 반환해 반응 선택을 막는다. 정정·철회는 이미 발생한 전달 이력을 삭제하지 않는다.
- `life.delivered`를 추가할 때 `options.currentRevisions`가 필수다. 게임이 현재 화면의 실제 `render_ack`를 확인한 뒤 투영하며 모듈은 revision과 인지 근거를 재검사한다. 동일 전달 ID 재전송은 원래 결과를 재사용한다. 이 검사는 서버 인증·화면 가시성 확인을 대신하지 않으며 전달을 학습 성공으로 바꾸지 않는다.

실제 필드와 증가 순서 예시는 [`tests/atlas-life.test.js`](../tests/atlas-life.test.js)의 `fixture`에 있다. 새 생활 합성 시험 15개와 기존 Trail·교육 연습 시험을 합쳐 **53개 통과**했다. 사건 중복·정정·NPC 인지/철회·낡은 ack·다른 계정·중단 후 재개·브라우저 전역을 검사했다. 두 번째 컵 전달 사례는 공통 계약의 합성 재사용 검사이며 두 번째 게임 화면 완성은 아니다. 첫 FT10 소비처는 [게임 상태](../experiences/synk-town/core.mjs)와 [로컬 서버](../experiences/synk-town/server.mjs)에 연결했다. 실제 화면·재방문 확인은 [검증 기록](../experiences/synk-town/qa/RESULTS.md), 개발 체험과 실제 계정의 경계는 [README](../experiences/synk-town/README.md)를 따른다. 운영 계정 연결은 아직 없다.

### 학습 기록 요약의 현재 경계

학습 원본 [`atlas/trail.js`](../atlas/trail.js)는 생활 기록과 분리된 `practice.*`를 읽고 [`game-learning.js`](../atlas/game-learning.js)의 요약·추천과 [`Temper`](../atlas/temper.js)에 전달한다. `motor/audio/unanswered/demo/visual/storage` 제외 사유가 있으면 정오답 값이 있어도 독립 수행·성장 근거로 세지 않는다. 실제 문항을 접한 사실은 남겨 재방문을 첫 노출로 만들지 않는다.

**2026-10-06 Core와의 책임 분리:** `createPracticeOutcomeIndex(summary)`는 검증된 `summarize()` 결과를 받아 학습 수행 근거를 색인한다. 반환한 `find(outcome, {targetLine, since, maxAgeMs})`는 같은 사람·사업·작업공간·결정·개념의 첫 노출 독립 정답인지, 도움·제외 사유가 없는지, 발생과 접수 시각이 요약 기준 및 관측 기간 안인지 확인한다. 통과하면 결과·시도·문항 제시의 사건 ID를 반환하고 아니면 `null`이다. 입력의 근거 필드를 복사해 이후 호출자 수정이 판정을 바꾸지 않게 한다. 이 API는 임의 객체를 인증된 학습 사실로 만드는 입구가 아니다.

점수 임계값·선택 옵션·가중치는 Core에 남는다. 업무 결과·사주 해석·게임 조작을 이 학습 판정에 끼워 넣지 않는다. 공통 결과 평가의 계약·정정·철회는 Temper의 선택 모듈이 맡는다. [경계 시험](../tests/atlas-practice-outcome-boundaries.test.js)은 도움·재노출·제외·범위·늦은 접수·입력 변경을 검사하며, [실제 제품 시험](../tests/atlas-cross-product-boundaries.test.mjs)은 LAB 입장 검사와 SHIFT 작업실의 성공 의미를 구분한다.

2026-10-02에는 사건·시도 순서·도움·음성을 인덱스로 읽도록 바꿔 시도마다 전체 로그를 다시 검색하던 중복을 줄였다. ID가 같은 재전송은 JSON 속성 순서와 무관하게 대조한다. [회귀 시험](../tests/atlas-provenance-review.test.js)은 제외 사유가 실제 게임 요약과 저장 후 복원까지 유지되는지, Temper에 잘못 합산되지 않는지 확인한다. 이 결과는 로컬 기능 검증이며 GAS 원장 배포·실학생 효과 확인은 아니다.
