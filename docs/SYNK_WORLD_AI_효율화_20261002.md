## 최신 모델과 가격을 적용하는 기준

현재 전사는 `whisper-1`의 `verbose_json`·세그먼트·저신뢰 검수 계약을 사용한다. **Whisper와 `gpt-4o-mini-transcribe` 모두 2026-08-26에 종료가 예고됐으며 종료일은 2027-02-26**이다. 앞서 제안했던 mini를 장기 기본 후보로 두는 안은 정정한다. 공식 후속은 파일 전사 `gpt-transcribe` 또는 실시간 전사 `gpt-live-transcribe`다. [종료 공지](https://developers.openai.com/api/docs/deprecations), [전사 가이드](https://developers.openai.com/api/docs/guides/speech-to-text)

새 모델은 요청·응답 형식과 원음 구간 검수 계약부터 맞춰야 한다. 이 수정에서 모델 이름만 바꾸지는 않았다. 몽골어권 등 실제 대상 학생의 짧은 발화·주저·조사 오류·배경 소음을 포함해 같은 원음을 사람이 듣고 전사한 기준과 대조한다. CER와 오류 보존, 되묻기율, 첫 응답 지연, 실제 청구를 함께 본다. 기존 `전사대조.js`는 온디바이스/클라우드 비교 도구이며 최신 모델 API 어댑터가 완성된 것은 아니다.

교정의 Sonnet 5를 일괄 저가 모델로 전환하거나 강사 지식 전체를 임의 절단하지 않았다. 현재 교사 QA는 10개 문서 약 13.4만 자를 고정 지식으로 넣는다. 선택된 근거만 넣는 검색·절 선별은 비용 절감 후보지만, 질문별 답변·인용 누락 평가가 먼저 필요하다. 이번 계측으로 실제 캐시 적중과 출력량을 확인할 수 있게 했다. 교정 프롬프트의 생성 뒤 사용하지 않는 칭찬·다음 미션 항목도 같은 문항 품질 대조 후 축소할 대상이다.

## 새 AI 선생님의 효율적인 수업 기준

아래는 이번 검토에서 정리한 구현 기준이며, 모델·목소리 선정이나 운영 출시 완료가 아니다.

1. **수업 시작은 준비된 콘텐츠에서 고른다.** Atlas의 기존 추천과 사용자가 고른 목표로 장면·난도·연습 표현을 정한다. 수업마다 전체 교재를 생성하지 않는다.
2. **발화가 끝났을 때 한 번 처리한다.** 초기 MVP는 말하고 듣는 순서를 분명히 한다. 녹음 중 UI 자막 갱신마다 모델을 부르지 않고, 전사 결과 수정·전송을 한 발화 ID에 묶는다. 상시 자연 통화는 별도 품질·원가 비교 대상으로 둔다.
3. **음성 인식 → 작은 대화 모델 → 음성 출력을 분리한다.** 단순 과제·정답 대조는 기존 규칙을 쓰고, AI에는 현재 발화에 필요한 수업 상태만 전달한다. 외부 요청이 실패했다고 모든 단계를 처음부터 다시 실행하지 않는다.
4. **대화 모델은 발화당 한 번이 기본이다.** 답변 1~2문장·다음 질문·필요한 교정 한 가지를 함께 받고, 상세 해설은 별도 요청이나 수업 종료 때 만든다. 상위 모델 자동 중복 호출은 기본값으로 두지 않는다.
5. **문맥은 한도 안에서 유지한다.** 수업 목표·현재 장면·최근 대화·누적 요약만 넣고, 전체 대화·개인 이력·교사 지식 문서를 매번 전송하지 않는다. 요약도 매 발화가 아니라 설정된 길이 경계 또는 수업 종료 때 갱신한다.
6. **공용 음성을 재사용한다.** 안내·예문·반복 질문은 미리 준비하고 같은 내용의 재생은 저장된 음원을 쓴다. 캐시 키는 문장·언어·목소리·속도·모델판을 포함하며 개인 이름·개인 발화는 다른 사람과 공유하지 않는다. 음성 캐시와 모델 프롬프트 캐시는 다른 비용 절감이다.
7. **서버가 시간과 비용을 함께 관리한다.** 세션 시간·실제 입력/출력 음성 길이·토큰·공급자 요청 ID를 기록하고 전송 전에 예상 최대액을 예약한다. 학생별 일별 안전 상한과 월별 임시 비용 상한을 확인하고 완료 시 정산한다. 전체 사용량은 회계용으로 집계하며 학생들의 호출 허용 예산을 합치지 않는다. 결과 불명은 예약을 유지한다. 기존 일부 교사 API의 하루 20회 예약을 이 학생별 금액 상한으로 오인하지 않는다.

수업 종료 복습에는 실제 발화·검증된 교정·연습할 표현을 남긴다. 회화 중 침묵·중단·STT 저신뢰를 학생의 능력 부족으로 자동 채점하지 않는다. TOPIK 읽기·듣기 대비와 회화 발화 연습은 구분하고 점수 향상 효과는 검증 뒤에 말한다.

STT `blocked`는 설정 원인을 고친 후 해당 `event_id/request_token`을 대조해 단건만 재개한다. `sent/uncertain`과 즉시 교정 미확정은 활성 요청·벤더 처리/청구를 확인하고 복구 가능한 응답을 먼저 저장한다. 불명확한 채로 원장을 지우거나 예약 작업에서 일괄 초기화하지 않는다. 확정 교정 결과 재검토는 `?회수=1&재검토=1`로 기존 결과만 읽으며 새 유료 평가와 함께 실행하지 않는다.

## 같은 날 추가 변경 검토

사용자의 관련 작업 검토·커밋·푸시 요청으로 현재 작업본과 앞선 커밋을 대조했다. Claude 공동 작성이 명시된 talk `de16e10`의 Atlas 사본은 `sync-atlas --consumer talk --check`와 사본·서버 연결 시험으로 일치를 확인했다. 작성자가 확인되지 않는 미커밋 변경은 Claude 작업이라고 단정하지 않았다.

- 교사 관찰 초안의 비용 예약·출시 중지·요청 식별자 연결을 함께 반영했다. 같은 화면에서 응답 유실 뒤 같은 입력을 재시도하면 요청 번호를 유지하고, 받은 초안은 메모리에서 재사용한다. 학생·원문을 바꾸면 새 요청을 만들며 원문·초안을 기기나 DB에 새로 저장하지 않는다.
- 관찰 초안의 200토큰 출력 예산에서 추론만 하다가 빈 결과로 끝나는 경로를 합성 응답으로 재현하고 `thinking: disabled`를 명시했다. 수정 전 회귀 시험 실패, 수정 후 통과를 확인했다. 실 API의 절감액·품질을 측정한 것은 아니다.
- BM-2의 남아 있던 100마디 130~250원·추가권 이익 계산을 §5의 토큰 가정과 맞추고 음성·서버 비용을 별도로 표시했다.
- 커밋 트리만 꺼낸 검증에서 출시 정책 서버 파일 누락과 Atlas 사본 해시의 CRLF/LF 불일치를 발견했다. 참조하는 서버 파일을 함께 포함하고 사본·서버 생성기의 텍스트 해시는 LF로 정규화했다. 원본 엔진 동작은 바꾸지 않았다. 동기화 도구 9/9와 줄바꿈 변환 회귀 시험을 통과했다.
