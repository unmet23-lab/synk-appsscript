# 출석 체크인 설계 — 2층 구조

> **지위**: SYNK-talk 출석 기능의 설계 정본.
> **개정**: 2026-08-08 유호님 판정 4건으로 **v1 의 PIN 축이 통째로 폐기**됐다. v1(2026-08-07)은 외부 원안(Wi-Fi BSSID + 4자리 PIN)을 검토·판정한 판이었고, 이 판은 **보상의 위치를 옮겨 인증 문제 자체를 없앤 판**이다.
> **구현 위치**: `unmet23-lab/SYNK-talk`(Expo + Supabase). 이 저장소(Apps Script)는 §9 시트 다리와 §8 알림 발송만 맡는다.
> **구현 시점**: 로그인·데이터 계약(P0/L0/C0) 공사 완료 뒤. 개원(파일럿 2027-02-11) 전 마일스톤.

## 1. 원칙 — 「왔다」와 「했다」는 다른 사건이다

v1 이 헤맨 이유는 **하나의 동작에 두 목적을 얹었기 때문**이다. 현장에 있었음을 증명하는 것과 학습했음을 증명하는 것은 다른 물건이고, 묶으면 학생이 네 종류인데 두 종류로 뭉개진다.

| 학생 | 한 버튼으로 보이는 것 | 실제 의미 |
|---|---|---|
| 왔다 + 했다 | 출석 | 정상 |
| **왔다 + 안 했다** | 출석 | **위험 — 이탈 예고** |
| **안 왔다 + 했다** | 결석 | **좋음 — 붙잡을 수 있다** |
| 안 왔다 + 안 했다 | 결석 | 이탈 직전 |

가운데 두 칸이 학원의 생사를 가르는데, 한 층으로 묶으면 그 둘이 사라진다.

- **운영 출석** — 수납·급여·학부모 알림·결석 경보의 근거. 물리적으로 교실에 왔는가.
- **학습 출석** — 스트릭·포인트·캐릭터·퀘스트. 집이든 교실이든 **했는가**.

🔑 **보상은 학습 층에만 건다**(유호 확정). 그 순간 출석을 조작할 이유가 사라지고, PIN·BSSID·GPS·기기 토큰·시도 제한이 **전부 불필요해진다**. v1 이 3절에 걸쳐 설계한 인증 장치는 문제를 푼 게 아니라 **문제를 만든 원인**이었다.

- 08-03 유호님 확정(「학생 출석 버튼 → 음성 숙제 제출로 전환」)이 이미 이 구조의 절반이다.
- 위성 수업(댄스·보컬·뷰티·원어민 회화·글로벌 영어)은 출석 체크 없음(유호님 기확정) — 범위 밖.

## 2. 구성 요소

| 구성 | 역할 | 물리 |
|---|---|---|
| 교실 문 **QR 포스터** | 운영 출석 입구 | **종이 1장** |
| SYNK-talk 앱 | QR 스캔 → 출석 · 퀘스트 수행 | Expo · Supabase Auth |
| Edge Function `attendance` | 출석 기록 · 퀘스트 발급 | Supabase |
| Postgres | `classrooms` · `attendance` | Supabase (L0 계약 편입) |
| 시트 다리 | Supabase → `attendance` 시트 | 이 저장소 Apps Script (§9) |
| 알림 발송 | 결석 · 주간 문장 | 이 저장소 (§8) |

`active_pins` · `classroom_devices` · `attendance_attempts` · Redis · 별도 서버 · 교실 디스플레이 기기는 **전부 없다**.

## 4. 운영 출석 — QR 포스터

### 4-1. 형태
- 교실 문(또는 입구 벽)에 **A4 한 장**. QR 안에는 교실 코드만 들어간다(비밀 값 없음).
- 학생이 자기 폰으로 스캔 → 앱이 열리며 그날 출석 1건 기록 → 끝. **유호님 손 0, 수업 시간 0.**
- 앱 미설치·폰 없음·배터리는 §10 폴백(강사 수동)으로 흡수한다.

### 4-2. 출석 순서 (유호 확정)
`checked_at` 정렬로 그날 **몇 번째로 왔는지**를 낸다. 저장 비용 0인데 두 곳에서 쓰인다.
- **성향 5축 ①리듬**의 **보조 축 후보**(⚠직접 재료가 아니다 — 정본 정의는 제출 시각·간격·마감 대비 여유(`created_at`)이고 도착 시각은 그 §10 에 없다 · `docs/코어엔진_설계.md`) — 수업 시작 대비 언제 오는가.
- 학생별 **평소 도착 시각**이 파생되고, 그것이 §8 결석 알림의 발송 시각을 정한다.
- "오늘 1등 입장" 연출이 공짜로 따라온다.
- ⚠ **순서는 학생 내부용이다.** 학부모 알림에 "3등으로 왔어요"를 싣지 않는다(부담이 되고 얻는 것이 없다).

### 4-3. 캐릭터 입장 연출 — 기기 없이
스캔 성공 시 **학생 자기 폰 화면에서** 캐릭터가 입장한다. 교실 화면도 태블릿도 필요 없다.
- 잃는 것: 다른 학생들이 그 연출을 못 본다. **순서만 미루는 것이고 §12 에서 되찾는다.**

### 4-4. 알려진 구멍 — 숨기지 않는다
고정 QR 이라 **포스터를 사진 찍어 집에서 열 수 있다.** 남는 동기는 하나뿐이다 — *학부모에게 결석을 숨기기*.

이것을 막는 것은 기술이 아니라 **유호님의 눈**이다. 16명 교실에서 안 온 학생이 출석 명단에 뜨면 보인다. 업계 표준도 같다(SwiftCheck 는 "PIN 도 카드도 없이" 를 강점으로 광고하고, 직원이 실시간 명단을 본다).

- 지원 장치: 수업 시작 시 앱이 **오늘 출석 명단 1화면**을 원장에게 띄운다. 유호님이 이미 하는 일(누가 왔나 보기)에 화면 하나를 맞추는 것뿐이다.
- **재검토 트리거**: ①실제로 원격 출석이 관측됨 ②반이 늘어 「유호님 눈」 전제가 깨짐. 그때의 수단은 크루카드 태깅(실물 제작 선행) 또는 §11 BSSID.

## 5. 학습 출석 — 퀘스트 (이 기능의 본체)

체크인 성공 응답이 **오늘의 개인화 퀘스트를 실어 보낸다.** 별도 화면 이동 없이 한 호흡. 교실에 못 온 날에도 앱에서 그대로 받는다.

### 5-1. 유호님 3축 배선 — 새 event_type 0
유호님 지시(「숙제는 당연히 게임이고, 수집설계 개인화 성향파악을 넣고, TOPIK 까지」)를 계약(`계약/수집_교정_계약.json`)의 **이미 있는 이름**에 붙인다.

| 축 | 배선 | 새로 만드는 것 |
|---|---|---|
| **게임(숙제)** | 퀘스트 발급 = `task.assigned` · 수행 = `submission.created`·`quiz.answered` | 없음 |
| **성향 파악** | ①리듬 = `attendance.checked_at`(§4-2 · ⚠**보조 축 후보** — ①리듬의 정본 정의는 **제출 시각·간격·마감 대비 여유**다, 코어엔진 §10) · ②~⑤ = 퀘스트 수행 로그 | **있다(08-11 실측)** — `attendance` 는 `learning_events` 밖이라 **엔진 도달 경로 0**(계약 13종에 출석 사건 없음 · 도달 장부 검문 밖). ⏳유호 택1: ㉠다음 계약 판에 출석 사건 1종 등재(⚠c11 아님 — c11 은 검수 물리 4자리 번호로 확정) ㉡도착 시각은 **운영 지표로만** 선언하고 ①리듬은 정본(제출 시각)대로 |
| **TOPIK** | `exam.result` + 퀘스트 문항의 급수·주제 태그 | 문항 태그만 |

- 발급 로직의 정본은 `docs/코어엔진_설계.md` — **이 문서는 인터페이스만 정의한다**: `발급(student_id, date) → quest`.
  ⚠ **v1 의 실측 결함**: 그 문서에 「퀘스트」가 0건이었다. 「본체로 채택」해 놓고 배선이 한 줄도 없었다. 구현 착수 전 그쪽에 발급 규칙을 먼저 적는다(§13-2).
- 수행 결과는 수집층 로그로 되돌아와 다음 날 개인화 재료가 된다. **출석·숙제·수집이 하나의 순환.**
- 스트릭·포인트·캐릭터·개근왕은 **전부 이 층에서 계산한다**(§1 원칙).

## 6. 데이터 모델 (L0 계약 편입 대상)

```sql
classrooms (
  id          uuid PK,
  name        text,              -- 'A강의실'
  qr_code     text UNIQUE,       -- 포스터 QR 안의 교실 코드. 비밀 값 아님
  created_at  timestamptz
)

attendance (                      -- 운영 출석 (원본)
  id            uuid PK,
  student_id    text,
  date          date,             -- 학원 시간대 기준
  method        text,             -- 'QR' | '수동' | (기존값 병존)
  classroom_id  uuid FK NULL,     -- 수동 기록은 NULL 허용
  checked_at    timestamptz,      -- §4-2 순서·평소 도착 시각의 유일한 재료
  UNIQUE (student_id, date)       -- 같은 날 2회 = 행 1개 (멱등)
)
```

`pin_secret` · `classroom_devices` · `attendance_attempts` · `allowed_bssids` 는 **넣지 않는다**.

열람 기록(§8-2·§14 게이트의 재료)의 자리 — **신규 이름 제안(현재 실물 0 · 두 저장소 어디에도 없는 표다)**: `parent_notifications (id uuid PK, student_id, channel, sent_at, opened_at null)`. §8-2 승격 판단과 §14 「열람 기록이 쌓인다」 게이트가 열어 볼 유일한 재료라, L0 편입 때 이 표(또는 동등물)를 함께 등재한다 — 등재 없이는 그 게이트가 무엇을 확인할지 정의되지 않는다.

## 7. API (C0 계약 편입 대상)

**체크인** — `POST /attendance/check-in`
- 인증: Supabase Auth 토큰. 바디: `{ "classroomCode": "..." }`
- 성공: `{ "success": true, "checkedAt": "...", "order": 3, "quest": { ... } }`
- 실패: `NO_SESSION_TODAY`(수업일 아님) · `ALREADY_CHECKED`는 **실패가 아니라 성공 응답**(멱등).

디스플레이용 PIN 엔드포인트는 **없다**(폐기).

## 8. 학부모 알림 (유호 확정 4안)

타 학원은 **왔을 때** 보낸다. 매일 오는 알림은 3주면 무시된다. 우리는 반대로 간다.

| 무엇 | 언제 | 왜 |
|---|---|---|
| **① 결석 알림** | 그 학생의 **평소 도착 시각 + 10분** | 절대 무시되지 않는 유일한 알림. 늘 늦는 학생에게 헛알림이 안 간다 |
| **② 주간 문장** | 주 1회 | 아이가 실제로 말한 한국어 1문장 + **몽골어 뜻**. 우리만 보낼 수 있다(음성 수집) |
| **③ 참여 요청** | ②에 동봉 | "집에서 한번 물어봐 주세요" — 학부모를 수신자가 아니라 **참여자**로 |
| **④ 등원 알림** | **안 보낸다** | 매일 알림은 피로만 남기고 ①의 무게를 깎는다 |

- ① 의 발송 시각 재료는 §4-2 출석 순서에서 공짜로 나온다. 추가 저장 0.
- ① 은 `checkNoShow` 의 재료를 쓰되 **판정 단위가 반→학생으로 바뀌므로 판정부는 새로 쓴다**(「방향만 바꾼 것」은 실측과 다르다 — `엔진_운영배치.js:2390`: 현행은 ㉠판정 **창**이 반 단위(수업 시작 +30~+90분) ㉡중복 키도 반 단위 ㉢**「그 반 당일 출석 0건이면 스킵」** 가드가 휴강·강사 미입력 오경보를 막는다). 이관할 것: ㉠그 가드를 학생별 시각에서는 **「그 반 첫 출석이 들어온 뒤에만 판정」**으로 옮긴다 — 안 옮기면 휴강일에 1등 학생 학부모부터 결석 문자가 나간다 ㉡중복 키를 (날짜·학생)으로 ㉢판정은 10분 주기 스위프에 편승하므로 「+10분」의 실제 발송 오차는 **±10분**이다(창과 주기는 다른 값이다).
- ② 는 **운영 출석이 아니라 학습 층**에서 재료를 얻는다(교실에 못 온 주에도 보낼 것이 있다).

### 8-1. 채널 = SMS + 링크 (유호 확정 08-08)

**문자로 보내고 링크로 데려온다.** 도달은 문자가, 브랜딩은 **링크 너머 화면**이 맡는다 — 학부모는 설치·가입·비밀번호가 0이고, 링크를 누르면 우리가 만든 화면이 그대로 열린다. 월 약 180건 = **9,000~18,000 MNT**.

🔴 **「리포트카드 공개링크 재사용 = 새로 짓는 화면 0」은 무효다(08-11 실측)** — 그 공개 링크는 v9.156 에서 폐지됐다(유호님 08-04 「B로 가자」 · 공개 공유 승인 목록 2→**0자리** · 회귀 6건이 지킨다 · `docs/버전_이력.md`). 되살리면 미성년 실명·급수·포인트가 다시 「링크를 아는 사람은 누구나」가 된다. **링크 대상 화면은 신설이고 §8-2 비용표의 「0원」 전제도 그만큼 무효다.** ⏳유호: 신설 화면의 조건 승인 — ①1회용·만료형 토큰 링크 ②실명 대신 호칭 ③공개 공유 승인 0자리 회귀를 깨지 않는 별도 통로.

**실측 근거 (2026-08-08)**
- Messenger 는 도달 64.3%(몽골 도시 지배적)이나 **자동 발송 통로가 닫혔다**: 정기 알림 2026-02-10 종료(몽골은 예외국 아님) · 레거시 메시지 태그 2026-04-27 폐지 · 24시간 창은 학부모가 **먼저 말을 걸어야** 열림 · Human Agent(7일)는 **사람이 직접 보낸 것만**.
- 몽골 SMS: 단방향 발송만 가능(양방향 미지원) · 국내 건당 50~100 MNT · MobiCom 번들 1,000건 20,000 MNT.
- 몽골 모바일 OS: **Android 55.11% / iOS 44.88%**(2026-07) — 앱으로 가면 **두 스토어가 다 필요하다**(한쪽만 내면 학부모 절반이 빠진다).
- 앱 방식의 결정적 약점: **가장 중요한 ①결석 알림이 설치율에 인질로 잡힌다** — 안 깐 집에는 영원히 안 가고, 그 집이 대체로 관심이 덜한 집이다.

**Messenger 는 버리지 않는다** — 알림은 SMS(단방향), **대화는 Messenger**(학부모가 먼저 물으면 24시간 창이 열린다 · 준비 중인 DM 상담 창구가 그 자리).

### 8-2. 앱 승격 — 기각이 아니라 계단이다 (유호 지시 08-08)

유호님 지시: *"상황 보고 앱으로 승격시킬 수도 있다."* 따라서 **학부모 앱은 기각이 아니고, 이 절이 그 통로다.**

| 단 | 무엇 | 유호님이 치를 비용 |
|---|---|---|
| **1단 (지금)** | SMS + 링크 | 문자 계약 1개 · 월 약 2만 MNT |
| **2단** | 링크 화면에서 **「홈 화면에 추가」** 안내 | **0원** — 스토어·심사·계정 전부 없음. 학부모 폰에 아이콘이 생겨 앱처럼 열린다 |
| **3단** | 학부모 앱 | 학부모 계정 체계 **신설**(지금 인증에는 학생만 있다) + Apple $99/년 + Google $25 + 개원기 설치 안내 |

위로만 올라가고 아래 단을 버리지 않는다 — 3단에 올라가도 앱을 안 깐 집에는 1단이 계속 간다.

**승격 판단 재료 = 링크 열람률.** 문자를 받은 학부모 중 몇 %가 링크를 눌렀는가 — 「앱을 깔 의사가 있는가」의 유일한 실측 대리값이다.

🔑 **재는 장치는 1단부터 넣는다.** 열람 기록은 그때 안 남기면 소급이 불가능하고, 그러면 승격 판단이 영원히 감으로만 남는다. 항목은 `발송 id · 대상 · 열람 시각` 셋이면 충분하다(**개인정보 새 항목 0** — 이미 가진 것들이다).

**기준선(몇 %면 올릴 것인가)은 지금 정하지 않는다** — 실측 없이 숫자를 지어내면 그 숫자가 판단을 대신한다. **첫 3개월 실측 뒤 유호님이 정한다.**

**되돌림 비용은 한 방향으로만 싸다**: 1단→3단은 쉽다(번호를 이미 갖고 있고 학부모가 이미 우리 화면을 연다). 3단→1단은 비싸다 — 설치를 설득한 학부모에게 철회를 다시 설득해야 하고, 그 비용은 돈이 아니라 **신뢰**로 지불된다.

## 9. 시트 다리 (이행기 — 이 저장소 몫)

- **진실 원천은 Supabase `attendance`**. 시트로 **단방향 동기화**만 한다(시트→원본 되쓰기 금지).
- ⚠ **이행기 동안 Supabase 는 QR 채널만의 원본이다** — 기존 폼·GPS·수동 출석은 시트에 직접 쓰이고(실측: `Code.js:580` GPS·`:678` 폼) 역방향 동기화는 없다. 따라서 §4-2 순서·평소 도착 시각·§8 ① 발송 시각의 재료는 **채널별로 결손**이다 — 결손을 0으로 채우지 말고 「미측정」으로 남긴다(폴백 채널 학생이 스트릭·성향·알림에서 조용히 빠지는 자리).
- 기존 소비처(스트릭·개근왕·달력·포인트·리포트·학부모 메일)는 attendance 시트의 **`student_id`·`date`·`method` 3열만** 읽는다 — 다리는 이 3열 계약만 지키면 된다.
- 구현: 시간 트리거가 마지막 동기 시각 이후의 Supabase 행을 끌어와 append. 기존 폼·GPS 출석 행과 병존, dedup 은 기존 Set 계산이 흡수.
- ⚠ **이중 기록 금지**: 앱 체크인은 Supabase 에만 쓰고 다리로만 시트에 온다.

## 10. 폴백 (필수 요건 — 부속 아님)

- **강사 수동 오버라이드**: 학생·날짜 지정 출석 기록(`method='수동'`). 폰 없음·배터리·앱 장애·QR 훼손 전부 이 경로로 흡수. ⚠ **기록 위치·입력 화면은 미정** — 시트에 적으면 §9 단방향 원칙의 명시적 예외로 적어야 하고, Supabase 에 적으려면 원장용 입력 화면 1개가 신설 대상이다(앱 인증은 학생 로그인 전용 · 구현 트랙에서 확정).
- **포스터 훼손·분실**: 재인쇄 전까지 그 교시는 수동. 종이라 복구가 분 단위다(디스플레이 장애보다 가볍다 — 이것이 종이를 고른 부수 이득).
- **오프라인 학생 기기**: 체크인은 온라인 필수. 실패 시 "선생님께 말씀드리세요" 안내 — 오프라인 큐는 만들지 않는다.
- 운영 출석은 보상과 무관하므로(§1) **폴백 실패가 학생 보상 손실로 이어지지 않는다** — v1 대비 위험이 한 단계 내려갔다.

## 11. BSSID — 유호 확정 보류

- **보류 근거**: 전 학생 Wi-Fi 접속 강제(미접속 = 정당 학생 거부) · **AP 교체·메시 다중 BSSID 를 유호님이 손으로 등록**해야 하고 잊으면 그날 전원 실패 · 업계 어느 학원관리 제품도 쓰지 않는다.
- **인정한 강점**: OS API 반환값이라 비루팅 기기에서 위조 사실상 불가 — 스푸핑 내성은 GPS·PIN 보다 강하다.
- **재검토 트리거**: §4-4 와 같다. 그때 `classrooms.allowed_bssids` + 체크인 바디 `bssid` 를 추가한다.

## 12. 교실 라이브 보드 — 순서만 미룸

안 쓰는 스마트폰 1대를 벽에 걸면 그날부터 교실 전체가 보는 화면이 된다(전용 장비 불필요 · 몽골 스마트폰 보급률 85%). 화면의 주인공은 **방금 체크인한 학생의 캐릭터 입장**(Supabase Realtime 구독). 출석이 통제 절차가 아니라 **입장 세리머니**가 된다.
v1 배포 후 별도 트랙 — **폐기가 아니라 순서다.**
