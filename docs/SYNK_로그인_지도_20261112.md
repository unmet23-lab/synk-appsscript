# SYNK 로그인 지도 — 전수조사와 정리 계획 (2026-11-12)

> 유호님(11-12): 「우리 synk 계정 로그인하면 (대표 Google로) 회사 계정(founder) 이름인데, 아이디로는 대표 Google 주소로 로그인해야 되더라고 … 내가 만들었지만 내가 로그인하는 게 헷갈릴 정도 … 지금부터 깔끔하고 탄탄하게 기본기 잡자.」
>
> 이 문서는 SYNK가 사람을 로그인시키는 모든 입구의 지도, 대표 계정이 꼬인 까닭, 앞으로 지킬 규칙 하나, 고칠 계획이다. 공개 저장소라 사람 주소는 역할 이름으로 적는다 — **대표 Google 계정**(처음 SYNK ID를 만든 개인 Google 주소), **회사 계정(founder)**(회사 도메인의 founder 주소 · 그 주소의 Google). 운영 자료는 10-14 운영 읽기 기록(`.tmp/workspace-google-login-20261014/`, 공용 작업본 · 비공개)과 코드로 확인했고, 유호님이 1안을 고르신 뒤(11-12 「1안을 내 손 안들게 니가 다 해줘」) 지금 상태를 다시 읽어 정리했다(6절 나.).

## 1. 신원은 넷이다

| 신원 | 어디에 있나 | 무엇으로 들어가나 | 화면의 이름 · 이메일 |
|---|---|---|---|
| **SYNK ID**(중앙 계정) | 중앙 계정 DB `engine.synk_accounts`의 계정 번호(`synk_user_id`). 이메일 칸이 없다 | 아래 「로그인 주인」을 거쳐서만 | 이름 = 계정 화면에서 정한 `profile.display_name`(Google 이름은 안 씀) |
| **로그인 주인**(Supabase Auth 사용자) | `auth.users` — 로그인 수단(이메일 + 비밀번호 · Google)이 여기 붙는다. `engine.synk_auth_links`가 로그인 주인 → SYNK ID를 잇는다. 이 표의 열쇠가 로그인 주인 쪽이라 **로그인 주인 여럿이 SYNK ID 하나를 가리킬 수 있다** | synk.im/id의 「Google로 로그인」 · 「이메일로 로그인」 | **로그인 이메일 = 이 로그인 주인의 이메일**(`auth.users.email`) — synk.im/id 「로그인과 보안」 · PC 앱 「내 계정」이 보이는 이메일 |
| **회사 직원 계정** | 회사 서버(workspace.synk.im) `users` 문서 — 이메일 · 이름 · 역할 · 회사 비밀번호. SYNK ID와는 `synk_identity_links`로 **번호끼리 1 : 1**(이메일 · 이름으로 잇지 않는다) | 워크스페이스 · PULSE 직원 화면의 아이디 칸 = **회사 계정 이메일 + 회사 비밀번호**, 또는 SYNK ID 단추 | 워크스페이스 · PULSE 직원 화면의 이름 · 「로그인 아이디」는 **어느 길로 들어와도 늘 이 계정 값** |
| **옛 메신저 아이디** | 메신저 DB `users.username` + `company_identity_links` | 위 아이디 칸 — 회사 비밀번호를 아직 정하지 않은 직원만 | 들어오면 회사 직원 계정 값 |

고객은 따로 신원을 만들지 않는다 — PULSE 「내 모델」 · 상담 화면은 SYNK ID로 고객 세션(`customer_identity_sessions`, `Path=/api/customer`)을 따로 연다. 회사 직원 계정과 섞이지 않고, 같은 사람이 직원이자 고객이면 두 세션이 나란히 산다. 고객 이름은 SYNK ID 표시 이름(없으면 「고객」)이다.

## 3. 대표 계정이 꼬인 까닭 — 증명

**정리 전 대표의 신원(10-14 운영 읽기 · 수리 기록, 11-12 다시 읽어 같음 — 정리 뒤는 6절 나.):**

- SYNK ID **하나**에 로그인 주인이 **둘** 붙어 있다.
  - ① **대표 Google 계정** 주소의 로그인 주인 — 이메일 + 비밀번호와 Google 둘 다(10-06 가입, SYNK ID를 처음 만든 주인).
  - ② **회사 계정(founder)** 주소의 로그인 주인 — Google만, 비밀번호 없음. 10-14에 워크스페이스에서 founder Google로 처음 눌렀을 때 SYNK ID에 연결되지 않은 새 로그인 주인이 생겨 가입 화면으로 갔고, 같은 날 운영 SQL로 이 로그인 주인을 기존 SYNK ID에 이었다(연결 1줄 + 감사 1줄 · 새 SYNK ID · 새 직원 없음 — [SYNK_ID.md](마케팅/온라인마케팅지도/engagement/company/SYNK_ID.md) 10-14 15:22 줄, [결정 보관](_ops/보관/결정_2026-10.md) 10-14).
- 회사 직원 계정 **하나** — 이름 「유호」 · 회사 계정 이메일 = **회사 계정(founder)** · 관리자 · 회사 비밀번호 따로 · 위 SYNK ID와 번호로 연결.

**말씀하신 두 증상의 까닭:**

1. **「대표 Google로 들어가면 회사 계정(founder)으로 보인다」** — 회사 서버는 SYNK ID **번호**로만 직원을 찾는다(`synk-identity.mjs` `complete()`의 `bySynk`). 중앙 계정 API가 회사 서버에 주는 것은 번호 · 상태 · 표시 이름뿐이고(`SYNK-talk` `synk-server.js` messenger 응답) Google 주소는 오지도 않는다. 그래서 대표 Google이든 founder Google이든 같은 SYNK ID → 같은 회사 직원 계정이고, 화면의 「로그인 아이디」는 늘 회사 계정(founder)이다(`public/app.js` 「로그인 정보」 = `users.email`). 연결은 정상이고, **어느 로그인으로 들어왔는지를 화면이 말하지 않는 것**이 헷갈림이다.
2. **「아이디로 로그인할 땐 대표 Google 주소여야 한다」** — synk.im/id의 「이메일로 로그인」은 로그인 주인의 이메일 + **SYNK ID 비밀번호**다. 비밀번호가 있는 로그인 주인은 ①뿐이라 이메일 칸에는 대표 Google 주소를 넣어야 하고, ②(founder)는 Google만 있어 이메일 칸에 founder를 넣으면 안 된다.
3. **그런데 반대쪽은 반대다** — 워크스페이스 · PULSE 직원 화면의 아이디 칸은 회사 계정 이메일(founder) + **회사 비밀번호**만 받는다. 10-23~24에 이 칸에 대표 Google 주소를 넣어 하루 넘게 막혔던 일이 이것이다.

**한 줄로:** 한 사람에게 「아이디 + 비밀번호」 쌍이 둘 있고(SYNK ID 쪽 = 대표 Google 주소 + SYNK ID 비밀번호, 회사 쪽 = founder + 회사 비밀번호) 이메일이 서로 엇갈린다. 게다가 로그인 주인이 둘이라 synk.im/id · PC 앱 「내 계정」의 로그인 이메일도 어느 Google로 들어왔느냐에 따라 바뀐다.

**왜 생겼나(구조):** ① 로그인 주인 여럿이 SYNK ID 하나를 가리킬 수 있다(`synk_auth_links` 열쇠가 로그인 주인 쪽). ② 다른 주소의 Google은 새 로그인 주인이 되고 SYNK ID 가입 화면(「가입을 마무리해요.」)으로 간다 — 이 화면에 「이미 SYNK ID가 있나요?」 길이 없다. ③ 10-14에는 이미 새 로그인 주인이 된 Google을 「로그인과 보안 → Google 더하기」로 옮길 수 없어(이미 다른 로그인 주인 소유) 운영 SQL로 이었다. ④ 회사 직원 계정은 SYNK ID보다 먼저 생긴 별도 아이디 · 비밀번호 체계이고 지금도 로그인 화면 맨 앞에 나란히 있다.

## 4. 그 밖에 헷갈리는 자리(전수)

1. **단추 이름이 입구마다 다르다** — 「Google · SYNK ID로 로그인」(워크스페이스) · 「SYNK ID로 로그인」(웹 앱 · PULSE 고객) · 「SYNK ID 로그인 열기 ↗」(PULSE 직원) · 「Google로 로그인 / 이메일로 로그인」(synk.im/id) · 「로그인」(PC). 같은 SYNK ID다.
2. **워크스페이스 · PULSE 직원 화면에 비밀번호 칸이 SYNK ID 단추와 나란히** 있고, 칸 이름(「이메일 또는 기존 메신저 아이디」 · 「이메일 또는 메신저 아이디」 — 두 화면이 서로도 다르다)이 어느 이메일 · 어느 비밀번호인지 말하지 않는다. SYNK ID 비밀번호를 넣으면 안 된다는 말이 없다.
3. **PULSE 직원 화면은 세 걸음**(새 탭 열기 → 워크스페이스에서 로그인 → 돌아와 「로그인 확인」). 같은 출처라 쿠키는 이미 공유되는데 돌아오는 길이 없다.
4. **「로그인 정보」 창**은 회사 계정 이메일만 「로그인 아이디」로 보이고 SYNK ID는 「연결돼 있어요」 한 줄 — 어느 SYNK ID · 어느 로그인으로 들어왔는지 모른다.
5. **이름이 셋** — 회사 직원 계정 이름(워크스페이스 · PULSE 직원), SYNK ID 표시 이름(synk.im/id · PC 앱 · PULSE 고객), Google 이름(어디에도 안 씀).
6. **회사 계정 이메일을 바꾸는 길이 없다**(초대 때 주소로 고정 — 역할 · 팀만 바뀜).
7. **Google 가입 화면에 「이미 SYNK ID가 있나요?」 길이 없다** — 다른 사람도 다른 주소의 Google을 누르면 둘째 SYNK ID를 만들 수 있다(대표가 10-14에 밟은 덫). **11-12 막음** — 6절 가4.
8. **옛 메신저 아이디 길**은 회사 비밀번호 없는 직원만 통하고 실패 글은 하나라, 왜 안 되는지 알 수 없다.
9. 문서의 메뉴 이름(「내 워크스페이스 → SYNK ID 연결」, [SYNK_ID.md](마케팅/온라인마케팅지도/engagement/company/SYNK_ID.md))이 실제(오른쪽 위 계정 단추 → 「SYNK ID」)와 다르다.

## 5. 규칙 하나

> **한 사람 = SYNK ID 하나 = 로그인 이메일 하나.** 어느 입구에서든 단추는 「SYNK ID로 로그인」 하나이고, 그 안(synk.im/id)에서 Google이나 그 로그인 이메일 + SYNK ID 비밀번호로 들어간다. 화면에 보이는 이메일은 그 로그인 이메일이다.

따르는 것:
- Google은 여러 개 더해도 되지만 모두 **같은 로그인 주인**에 「로그인과 보안 → Google 더하기」로만 붙인다. 로그인 주인을 하나 더 SYNK ID에 잇지 않는다. 이미 따로 생긴 로그인 주인은 그 로그인 수단을 원래 로그인 주인으로 옮기고 빈 주인을 지워 합친다(11-12 대표 계정에 한 방식 — 6절 나.). 가입을 마치지 않은 빈 주인은 본인이 가입 마무리 화면의 「기존 SYNK ID로 로그인」으로 지우고, 기존 SYNK ID에서 그 Google을 더한다(6절 가4).
- 회사 · PULSE 직원 화면은 따로 아이디 · 비밀번호를 앞에 두지 않는다. 회사 비밀번호 로그인은 SYNK ID를 아직 연결하지 않은 직원과 비상용으로 접어 두고, 그 칸은 「회사 계정 이메일 · 회사 비밀번호」라고 이름 붙인다.
- 직원을 초대할 때 회사 계정 이메일은 그 사람의 SYNK ID 로그인 이메일과 같은 주소로 한다. 다를 수밖에 없으면 화면이 둘에 따로 이름을 붙여 보인다.

## 6. 고친 것 · 남은 것

**나. 대표 계정 — 1안으로 정리 끝(11-12, 유호님 「1안을 내 손 안들게 니가 다 해줘」)**

유호님 손 없이 운영에서 했다(증거는 공용 작업본 `.tmp/synk-login-audit-20261112/` — 비공개 파일 · 역할 이름만 남긴 결과 파일).

1. **읽기:** 로그인 주인 둘(대표 Google = 이메일 · Google, founder = Google만)이 SYNK ID 하나에 붙어 있음을 다시 확인. founder 로그인 주인을 가리키는 기록(교사 · 학습자 · AI 몫 · 초대 · 비밀번호 변경 · 사진 작업)은 0, 열린 제품 세션 8(WORLD 2 · 플랫폼 3 · 메신저 3). SYNK ID에 붙은 기록 50개 표 · 700줄의 지문을 떴다.
2. **합치기(한 거래):** founder Google 로그인 수단을 원래 로그인 주인으로 옮기고, founder 로그인 주인으로 열렸던 제품 세션 8개를 끊고, 빈 founder 로그인 주인과 그 연결을 지우고, 감사 한 줄을 남겼다. 먼저 되돌리는 연습으로 모든 조건 · 결과 검사를 돌린 뒤 반영했다.
3. **로그인 이메일 바꾸기:** 남은 로그인 주인의 로그인 이메일을 대표 Google 주소 → 회사 계정(founder)으로(인증 관리 API, 확인된 주소로 — 이메일 로그인 수단의 주소도 함께 바뀜). SYNK ID 비밀번호는 그대로다.
4. **대조:** 로그인 주인 하나 · 로그인 수단 셋(이메일 + 비밀번호 · 대표 Google · founder Google) · 로그인 이메일 founder · SYNK ID 연결 1 · 로그인 주인이 둘 이상인 SYNK ID 0. 기록 지문은 50개 표 가운데 감사(+1) · 연결(2 → 1) · 세션(끊김 8)만 바뀌고 47개 표(학습 · 프로필 · 동의 · 마을 등)는 그대로. 회사 서버 연결(SYNK ID 번호 → 회사 직원 계정)은 손대지 않았다. ego 브라우저에서 synk.im/id가 「로그인 이메일 founder · 로그인 방법 이메일·비밀번호 · Google」로 보이고, 같은 SYNK ID로 워크스페이스 · PULSE 직원 화면에 「유호」(관리자)로 들어가는 것을 확인했다.
- **이제 들어가는 법:** 어느 입구든 「SYNK ID로 로그인」 → Google은 founder · 대표 Google 아무것이나, 이메일이면 **founder + SYNK ID 비밀번호**. 워크스페이스 회사 비밀번호 칸은 **founder + 회사 비밀번호**(비상용). founder Google로 열려 있던 PC 앱 · 브라우저 로그인은 한 번 다시 로그인해야 한다.
- **확인 못 한 것:** founder Google을 실제로 눌러 들어가는 것은 ego에 Google 로그인이 없어 해 보지 않았다 — 로그인 수단이 원래 로그인 주인에 옮겨진 것을 DB로 대조했다. 다음에 founder Google로 들어오시면 그 자체가 확인이다.
- **표시 이름도 「유호」로 채움(11-12 18:03 KST, 유호님 「「유호」로 채워」):** 비어 있던 SYNK ID 표시 이름을 채웠다 — 다른 프로필 값은 그대로 · 프로필 판 +1 · 감사 「profile-updated」 한 줄(바뀐 표는 계정 행 · 감사뿐). 이제 synk.im/id · PC 앱 「내 계정」 · PULSE 고객 화면도 「유호」, 워크스페이스는 회사 계정 이름 「유호」라 어느 길로 들어가도 같은 이름이다. 화면 확인은 ego의 SYNK ID 로그인이 풀려 있어 DB로만 했다.
