## 0. 🔴 v1 에서 내가 «문서를 보고» 틀린 것 셋 — 실물로 정정한다

세 번 다 같은 방식으로 틀렸다. **낡은 문서를 지금 상태로 읽었다.**

| v1 이 적은 것 | 실물 | 어디서 확인했나 |
|---|---|---|
| 「회고 표가 아직 없다」 | **있다.** 표·제약 4·동결 트리거까지 섰다 | `SYNK-talk/supabase/migrations/20260812170000_season_review_c11.sql:109` |
| 「소리 원본은 지울 수 없게 보호된다」 | **글자만 보호된다.** 파일 자체는 안 본다 | 트리거는 `audio_ref` 문자열만 검사 · 전사기가 `storage_404` 를 처리한다 |
| 「몽골어는 나중에 풀면 된다」 | **지금 자동으로 한국어 전사줄에 들어간다** | `SYNK-talk/lib/전사.js` 의 `전사대상()` 이 소리만 보고 `대기` 를 돌려준다 |

셋째가 특히 크다. `전사대상()` 은 이렇게 판정한다.

```js
if (typeof audio_ref !== 'string' || !audio_ref) return null;
const state = server && typeof server === 'object' ? server.state : null;
if (state === 'missing') return null;
return 상태.대기;
```

**소리가 있으면 무조건 대기다.** 예외는 「파일이 없다고 이미 못박은 행」 하나뿐이다.
그러므로 언어 표시를 다는 것만으로는 안 막힌다 — 이 함수가 그 표시를 **읽어야** 한다.

## 1. 한 줄

**새로 지을 것이 거의 없다.** 계약에 통로 이름 하나를 더하고, 이미 서 있는 사건·함수·자를
그대로 쓴다. 아래 §2 가 열한 자리를 하나씩 대조한다.

## 2. 심문 지적 ↔ 실물 ↔ 처방 — 열한 자리

| # | 심문이 짚은 것 | 실물이 어디까지 와 있나 | 처방 크기 |
|---|---|---|---|
| ① | 계약에 「일기」가 없다 | `task_type` 값록 9종에 없다 | **값 +1** |
| ② | 몽골어가 자동 전사된다 | `전사대상()` 이 소리만 본다 | **인자 +1** |
| ③ | 「봤는데 안 썼다」를 못 센다 | `content.viewed` 가 이미 있다 | **그대로 쓴다** |
| ④ | 몽골 현지 날짜가 없다 | `몽골날짜()` 가 시간대를 쥐고 있다 | **행에 굳힌다** |
| ⑤ | 과제 파이프라인이 오염된다 | 축 넷이 `submission.created` 를 읽는다 | **거르는 무늬가 이미 있다** |
| ⑥ | 엔진이 언제 읽는지 없다 | `학습자상태` v15 · 축 14개가 이미 읽는다 | **축 +1** |
| ⑦ | 어느 칸이 채워지는지 없다 | A-1 ㉡ 「돈다」 칸이 지금 🔴 비어 있다 | **그 칸의 첫 입주자** |
| ⑧ | 언어를 누가 채우나 | 판별하는 자가 없다 | 자판으로 스냅샷 |
| ⑨ | 소리 파일 보존 | 트리거는 글자만 지킨다 | 보관 정책을 따로 정한다 |
| ⑩ | 종이 4칸에 56일이 안 들어간다 | 시즌당 4칸 · 고정 2쪽 | 별도 조판기 |
| ⑪ | 자기설명이 없다 | 문안 0 | 문안을 쓴다 |

### ① 계약에 통로 하나를 더한다 — 선례가 그대로 있다

지금 값록(`SYNK-talk/계약/수집_교정_계약.json:99`):

```
숙제제출 · 다시쓰기 · 퀴즈응답 · 대화턴 · 발화녹음 · 출석발화 · 라디오퀴즈 · 목표선언 · 자습체크인
```

같은 파일이 이 축의 뜻을 못 박았다.

> `task_type` 은 **어느 통로로 들어왔나**(숙제제출·발화녹음), `task_format` 은 **그 과제가 무슨
> 형식이었나**(낭독·자유발화·모의면접)다.

🔑 **일기는 새 통로다.** 그리고 이 판단에는 **선례가 있다** — c11 이 라디오 셋을 더할 때 쓴 말이
그대로 우리 자리다.

> `task_type` +3 — '라디오퀴즈'(앱 퀴즈와 **통로 축**으로 가른다 — 같은 칸에 섞이면 영원히
> 못 가른다) · '목표선언'·'자습체크인'(기존 '출석발화' 재사용 금지: 앱 출석 발화와 라디오
> 자습 체크인이 한 칸에 섞인다)

⇒ **`task_type` +1 = `일기`.** 계약 판을 올리고, 살아 있는 CHECK 제약을 판 접미까지 함께 간다
(c11 이 14개를 이름째 교체한 그 절차 — 접미를 안 갈면 「새 계약 + 옛 물리」가 초록으로 보인다).

🚫 `발화녹음` 재사용은 금지다. 그러면 과제 발화와 일기가 첫 행부터 영원히 안 갈린다.

### ② 전사줄에서 빼는 자를 한 곳에 둔다

`전사대상(audio_ref, server)` 에 **언어 인자를 더한다.** 몽골어·섞임이면 `null` 을 돌려준다.

- 🔑 **판정을 한 곳에 둔다.** 그 함수는 이미 「분모를 여기서 만든다」고 적혀 있고, 통로를 두 곳에
  두면 「전사 대기」와 「전사 대상 아님」이 다시 섞인다.
- 🔴 값록은 셋 — `ko` · `mn` · `모름`. **`모름` 은 전사줄에 넣는다**(지금과 같다).
  안 넣으면 표시가 아직 없는 옛 행이 통째로 미전사가 된다.

### ③ 노출은 이미 있는 사건을 쓴다 — 새 사건 0

`SYNK-talk/lib/이벤트검증.js:210` 이 정한 필수 칸은 하나다.

```js
'content.viewed': ['parent_event_id'],
```

그리고 같은 파일이 이 사건의 성질을 적었다.

> 오프라인이어도 보낼 수 있다 — 값은 서버 `event_id` **또는 앞 항목의 `idempotency_key`** 이고
> 서버 `고리풀기` 가 푼다.

⇒ 일기 물음을 화면에 그린 순간 이 사건을 쌓는다. 그러면 「봤는데 안 썼다」와 「아예 못 봤다」가
갈린다. **새 사건도, 새 계약도 필요 없다.**

### ④ 몽골 현지 날짜를 행에 굳힌다

`SYNK-talk/lib/몽골날짜.js` 가 이미 쥐고 있다.

```js
const 시간대 = 'Asia/Ulaanbaatar';
```

그 파일이 이유도 적었다 — UTC 로 끊으면 몽골 오전 8시까지가 「어제」라 아침에 앱을 연 학생이
어제 것을 받는다.

⇒ 일기 행에 `몽골날짜()` 값을 **굳힌다.** 나중에 시간대 처리가 바뀌어도 그날의 날짜가 안 흔들린다.
과제가 이미 같은 무늬를 쓴다(`task_ref: task-{날짜}`).

### ⑤ 🔴 과제 축 넷이 오염된다 — 거르는 무늬가 이미 있다

`SYNK-talk/lib/학습자상태.js:297` 부터 축 열넷이 선다. 그중 **넷**이 `submission.created` 를 읽는다.

| 축 | 무엇을 세나 |
|---|---|
| 리듬 | 배정 대비 제출 |
| 끈기 | 제출 대 이탈 |
| 작성과정 | 제출 |
| 집중띠 | 같은 재료를 시간대로 갈라 |

일기를 그냥 `submission.created` 로 쌓으면 **네 축이 전부 부푼다.** 배정 없이 낸 것이 리듬축의
분자에 들어가고, 그러면 「배정한 것을 얼마나 냈나」가 100%를 넘는다.

🔑 **그런데 거르는 무늬가 이미 있다.** 그 파일이 라디오 행을 이렇게 거른다.

```js
리듬: 리듬축(골라('task.assigned'), 앱통로만(골라('submission.created')), 담아),
```

> 앱 통로만 세는 것도 끈기축과 같다 — 라디오 승격 행은 학생이 앉은 시각이 아니라 승격기가
> 돈 시각이다.

⇒ 같은 자리에서 `task_type === '일기'` 를 뺀다. **①의 값 +1 이 이 거르개를 가능하게 만든다** —
통로 이름이 없으면 거를 수가 없다.

### ⑥⑦ 엔진 도장 셋을 지금 채운다

판단 정본(`docs/SYNK_철학.md`)이 요구하는 세 칸이다.

| 칸 | 답 | 근거 |
|---|---|---|
| **모였나** | ✓ 예정 | `submissions` 에 `task_type='일기'` 로 쌓인다 |
| **닿았나** | ✓ 예정 | `학습자상태` 에 **자발발화축**을 더한다 — 읽는 층은 v15 로 이미 서 있다 |
| **늘었나** | ✓ 예정 | 이해 대장 **㉡ 사람 층의 「돈다」 칸** |

🔑 **㉡ 칸이 지금 비어 있고, 정본이 「가장 비어 있는 칸을 먼저 채우라」고 했다.**
`docs/SYNK_철학.md:252` 의 A-1 표가 ㉡ 「돈다」를 이렇게 적었다.

> 🔴 **없다** — 「성향으로 읽는 층이 없다」가 아니라 **읽는 층은 섰는데 먹일 행이 0**이다

> **읽는 법 ①** — ㉡ 행이 우리 회사가 존재하는 이유이고, 지금 「돈다」 칸이 비어 있다.
> 새 기능을 고를 때 이 표에서 **가장 비어 있는 칸을 먼저 채운다.**

그리고 같은 정본이 ㉡ 을 채우는 **방식**도 정했다.

> 학생이 노는 자리에서 저절로 모이는 것이 정답이고 … **재미없는 설문으로 성향을 캐는 것은
> 우리 방식이 아니다.**

⇒ 유호님의 「사소하고 일상적인 질문」이 이 조건과 맞는다. 설문이 아니라 자기 기록이다.

**자발발화축이 세는 것** — 어느 물음에 답했나 · 얼마나 자주 · 얼마나 길게 · 어느 시간대에 ·
말인가 글인가.

⚠ **「돈다」 승급은 첫 학생 뒤다.** 지금 적을 수 있는 것은 「배선이 섰다」까지이고, 재료 행이
0인 동안은 이 축도 0을 낸다. 정본이 그 규율을 이미 적었다(도달의 정의 = 읽힌 것).

🚫 **AI 가 성향을 판정하지 않는다.** 자발발화축은 **세는 자**다. 뜻을 읽는 것은 나중 일이고,
지금 그것까지 설계하면 다시 엔진 물건이 된다.

### ⑧ 언어 표시는 자판이 채운다

학생에게 안 묻는다. **글을 친 자판이 한글이면 `ko`, 키릴이면 `mn`.** 글 없이 소리만 낸 날은
`모름` 이고, `모름` 은 지금대로 전사줄에 들어간다(②).

- 🔑 학생은 아무것도 고르지 않는데 표시가 채워진다. v1 이 「학생에게 안 묻는다」고 써 놓고
  채울 자를 안 정한 구멍이 이걸로 막힌다(제미나이 대안 채택).
- ⚠ 자판이 두 언어를 오가는 학생은 섞인다. 그래서 이 값은 **판정이 아니라 힌트**이고,
  전사줄에서 빼는 데만 쓴다. 나중에 언어 감지가 붙으면 그때 덮는다.

### ⑨ 소리 보관은 따로 정한다 — 이 판에서 안 닫는다

트리거는 글자를 지키고 파일은 안 지킨다(§0). 그리고 지금 어디에도 보관 기간·용량 상한이 없다.

- 🔴 **매일 소리를 쌓기 전에** 이 정책이 서야 한다. 안 그러면 용량이 차는 날 업로드가
  조용히 실패한다.
- 필요한 최소 산식 = 평균 소리 크기 × 실제 낸 수 × 학생 수 × 시즌 일수 × 보관 시즌 수.
  **입력을 하나도 안 재봤다** — §4 의 첫 일이다.

### ⑩ 종이는 별도 조판기가 짓는다

`tools/기록장조판.js:60` 이 시즌당 4칸 고정이고, 같은 파일 227줄이 「사진이 몇 장이든 쪽수는
고정」이라고 못 박았다. 8주 최대 56일치가 4칸에 안 들어간다.

⇒ 기존 기록장을 안 건드리고 **일기 전용 조판기**를 짓는다. 기존 통로에 얹겠다던 v1 의 문장을 물린다.

### ⑪ 자기설명 — 첫 화면 문안

판단 정본 ⑤층이 요구하는 두 가지를 첫 화면에 둔다: **이게 뭔지** · **뭘 하면 되는지.**

| 자리 | 문안 갈래 |
|---|---|
| 자리 이름 | 「오늘 한 줄」 — 「일기」라는 낱말을 안 쓴다(부담이 그 이름에서 온다) |
| 첫 줄 | 그날의 물음 그대로 — 빈 칸을 안 보여준다 |
| 안내 한 줄 | 한 낱말도 괜찮다는 것과, 안 써도 된다는 것 |
| 낸 뒤 | 날짜 목록에 한 장이 쌓이는 것을 그 자리에서 보여준다 |

🚫 배지·연속 일수·달력 없음(유호 확정). 되돌아올 이유는 **자기 기록이 쌓이는 것** 하나다.

## 3. 그래서 짓는 것 — 실물 단위

| # | 무엇 | 어디 |
|---|---|---|
| 1 | `task_type` 값록 +1 (`일기`) + CHECK 제약 판 올리기 | 계약 · 마이그레이션 |
| 2 | `전사대상()` 에 언어 인자 | `SYNK-talk/lib/전사.js` |
| 3 | 축 넷의 거르개에 `일기` 제외 | `SYNK-talk/lib/학습자상태.js` |
| 4 | 자발발화축 신설 | 같은 파일 |
| 5 | 일기 배달·제출 통로 | 새 자리(과제 옆) |
| 6 | 물음 목록(고정) | 새 콘텐츠 파일 |
| 7 | 날짜 목록 화면 | 새 화면 |
| 8 | 일기 전용 조판기 | `tools/` |

**새 표 0 · 새 사건 0.** 늘어나는 것은 값 하나, 인자 하나, 축 하나다.

## 4. 🔴 순서 — 무엇을 먼저 하나

1. **소리 보관 정책**(⑨). 매일 쌓기 «전»에 서야 한다.
2. **계약 값 +1**(①). 이게 없으면 거르개도 축도 못 짓는다.
3. **전사줄 거르개**(②) + **축 거르개**(⑤). 둘 다 첫 행이 쌓이기 전에.
4. 그다음 화면·물음·조판기.

## 5. 소급이 안 되는 것 넷

| 무엇 | 왜 |
|---|---|
| 물음 안정 ID · 그날 물은 원문 · 목록 판 | 문구를 다듬는 순간 옛 답이 어느 물음 것인지 사라진다 |
| `task_type='일기'` | 과제와 섞여 쌓이면 첫 행부터 영원히 안 갈린다 |
| 몽골 현지 날짜 | 나중에 시간대 처리가 바뀌면 날짜가 밀린다 |
| 소리 언어 표시 | 없으면 되캘 때 한국어 행까지 다시 돌게 된다 |

## 6. 안 하는 것

AI 가 목표 후보 뽑기 · 확인 카드 · 회고에 얹기 · 강사 도장 · 판정 계약 개정 ·
**AI 성향 판정**(자발발화축은 세기만 한다) · 과제 ③에 삶 물음 섞기 · 달력 · 배지 · 연속 일수.

## 7. 안 잰 것 — 정직하게

1. **소리 크기·참여율.** §4 의 1번을 못 여는 상태다.
2. **몽골 학생의 한글 자판 실태.** ⑧의 판별이 얼마나 맞을지 모른다.
3. **별개 자리를 화면 어디에.** 탭인가 오늘 화면 안인가 — 유호님 판정 자리.
4. **최신 수단 정찰.** 학생 접점이라 판단 정본이 요구하는데 아직 안 했다.
5. **v1 이 「31건 중 21건 사라진다」고 쓴 장부.** 안정 ID 로 짝을 안 맺었다 — 이 판은
   그 주장을 반복하지 않고 §2 의 열한 자리로 대신한다.

## 8. 심문에 바라는 것

1. **§2 의 열한 자리가 실물과 맞나.** 특히 ⑤(축 넷 오염)와 ⑥(자발발화축)이 실제로
   그 파일에서 그렇게 서 있나.
2. **①의 계약 개정이 데리고 오는 것이 CHECK 제약뿐인가.** c11 선례가 14개를 갈았는데,
   이번 판이 건드릴 물리가 더 있나.
3. **⑧의 자판 판별이 「지어낸 값」인가 「정직한 힌트」인가.** 판정이 아니라 힌트로 두고
   전사줄에만 쓰는 것으로 충분한가.
4. **§4 의 순서에서 빠진 선행이 있나.**
5. **§6 에서 뺀 것 중, 빼면 안 되는 것이 있나.**
