## 무엇을 더하나

의뢰서는 아홉 화면 그대로다. 새 칸은 모두 눌러서 고르고, 고르지 않아도 넘어간다(메모 「손님에게 글로 더 묻지 않는다」 · 「사용자 관문은 엄격하게 막지 않기」).

| | 어느 화면 | 더하는 것 | 지금 | 답 칸(이름 · 값) |
|---|---|---|---|---|
| 하나 | 여섯째 「무엇으로 오래 남을까요?」 | 넷째 줄 「웃음으로 퍼지게」(예시 「매진 임박」 12초) + 칩 「정석대로 · 조금 다르게 · 확 다르게」 | 「이야기로 여운을」 · 「한 장면의 임팩트로」 둘 — 제작 규칙의 이기는 길은 셋(여운 · 공력 · 웃김)이다 | `win: 'laugh'` · `bold: 'safe' \| 'twist' \| 'wild'` |
| 둘 | 다섯째 「화면에 정확히 나와야 할 글자가 있나요?」 | 「광고에 꼭 붙여야 하는 표시가 있는 업종인가요?」 — 업종마다 꺼내는 칩 + 「해당 없어요」 · 「잘 모르겠어요」. 고르면 안내 한 줄과 선택 칸(쓰시는 고지 문구 · 심의 번호), 모니터의 광고 틀 아래에 「고지 문구가 들어갈 자리」 | 피할 말만 받는다 | `notice: '<업종 칩>' \| 'none' \| 'unsure'` · `noticeText` |
| 셋 | 일곱째 「누가 나올까요?」 · 셋째 「이것만 보내 주세요」 | 목소리 칩 「내레이션이 이끌어요 · 모델이 직접 말해요 · 말 없이 음악과 자막으로」(「사람 없이 제품만」이면 둘째 칩은 숨김) + 준비물의 「브랜드 음악 · 로고 소리」 칸(있으면) | 소리에 대해 아무것도 받지 않는다 | `voice: 'narration' \| 'model' \| 'none'` · 파일 칸 `sound` |

보내기 전 확인에는 「꼭 붙일 표시」 · 「얼마나 과감하게」 · 「목소리」 세 줄이 생기고, 비어 있으면 「저희가 제안해요」 · 「저희가 확인해요」가 적힌다. 손님에게 보이는 글 전문 · 업종별 칩 목록은 `시안/make.py`에 있다(그 글이 정본).

과감함이 제작에서 바꾸는 것(제안 — 방향 제안 두 안의 폭): 정석대로 = 두 안 모두 업종의 익숙한 문법 안 · 조금 다르게 = 한 안은 정석, 한 안은 한 군데를 비튼 안 · 확 다르게 = 컨셉 후보를 넓게 뽑고 두 안 모두 비튼 쪽. 무엇을 고르든 제품 사실 · 피할 말은 지킨다.

## 시안을 만든 법

그림판이 아니라 **실제 의뢰서 코드에 얹어 띄운 화면**이다. `시안/make.py`가 고객 앱의 `request-data.mjs` · `request-flow.mjs`를 `시안/over/`에 베껴 정확한 글자 바꾸기로 세 가지를 얹고(원본이 바뀌어 자리를 못 찾으면 멈춘다), `시안/serve.mjs`가 운영 서버 없이 의뢰서만 띄운다(`/before/` = 지금 코드 · `/after/` = 얹은 코드, 답은 화면 메모리에만).

```
python docs/마케팅/PULSE_의뢰서탭_20261113/시안/make.py
node docs/마케팅/PULSE_의뢰서탭_20261113/시안/serve.mjs 4871     # http://127.0.0.1:4871/after/harness.html?step=feel
node docs/마케팅/PULSE_의뢰서탭_20261113/시안/shots.mjs           # 전 · 후 캡처(PC 1680×970 · 휴대폰 390×844, 이 PC의 Edge)
node docs/마케팅/PULSE_의뢰서탭_20261113/시안/shots.mjs 재기      # 작은 창(1440×900)에서 물음 칸이 넘치는 높이
python docs/마케팅/PULSE_의뢰서탭_20261113/시안/page/build.py     # 캡처를 넣은 시안 쪽
```

웃음 예시 영상은 git 밖 완성본의 **자막 없는 화면 판**에서 자른다(자막 있는 판은 휴대폰에서 작품 설명 글과 자막이 겹친다). 처음엔 앱에 있던 640×360 판을 썼는데 큰 화면에서 두 배로 늘어나 버렸다.

```
ffmpeg -ss 5 -t 12 -i <synk-vendor>/homeshopping-horror-20261021/최종/화면.mp4 -an -vf "scale=1280:720:flags=lanczos,fps=24" -c:v libx264 -preset slow -crf 27 -pix_fmt yuv420p -movflags +faststart 시안/over/assets/request/film-maejin-laugh.mp4
ffmpeg -ss 12.6 -i <같은 파일> -frames:v 1 -vf "scale=960:540:flags=lanczos" -c:v libwebp -quality 82 시안/over/assets/request/w-maejin-laugh.webp
```

## 반영한 것(11-13 밤)

시안과 손님에게 보이는 글 · 자리는 같다. 달라진 것은 속뿐이다.

- **저장값은 ID다.** 표시 업종은 한국어 낱말이 아니라 `health-food` · `alcohol` · `functional-cosmetic` · `beauty-device` · `medical-device` · `sanitizer` · `kids` · `finance` · `game` · `clinic` · `academy` · `medical-pharma`(+ `none` · `unsure`)로 저장한다 — 영어 화면에서도 같은 값이다. 광고할 것의 종류를 바꾸기 전에 고른 갈래는 칩 맨 앞에 그대로 보인다(안 보이면 풀 수도 없다).
- **고객 앱:** `request-data.mjs`(SOUND 칸 · WIN laugh · BOLD · NOTICES · NOTICE_KINDS · VOICES · 빈 답 · `LATER_FIELDS` · 의뢰서 한 장의 세 줄) · `request-flow.mjs`(세 덩이 그리기 · 누르기 · 모니터의 고지 문구 자리) · `film.css` · `i18n/en.mjs`(영어 46줄) · `sw.js`(셸 v58) · 예시 `assets/request/w-maejin-laugh.webp` · `film-maejin-laugh.mp4`(영상은 다른 예시들처럼 git 밖 — 위 명령으로 다시 자른다). 새 글자 「독」 · 「융」 때문에 글꼴 조각도 다시 만들었다(`tools/build-pulse-fonts.py`).
- **회사 서버:** `pulse-requests.mjs` — 답 칸 넷과 `win: laugh`를 ID로만 받고(모르는 값은 거절, 옛 화면이 안 보내면 빈 값), 「사람 없이」 + 「모델이 직접 말해요」는 목소리를 비운다. 파일 칸 `sound`와 소리 형식(mp3 · wav · m4a · aac)을 **내려받기 전용**으로 받고 앞부분 서명을 본다(그 전에는 소리 파일을 받지 않았다). 고른 값은 제작 설계 메모에 「얼마나 과감하게」 · 「목소리」 · 「꼭 붙일 표시」 줄로 옮긴다(「해당 없어요」는 줄 없음, 「잘 모르겠어요」는 「확인 필요」). `server.mjs` 정적 목록에 예시 둘.
- **읽는 곳:** 의뢰서 한 장(손님 확인 화면 · 고객 방 · 직원 화면)은 `briefRows` 하나라 같이 보이고, PC의 1차 확인 지시문(`tools/크레딧작업/PULSE의뢰확인.js`)이 새 답을 읽어 표시 업종이면 「표시 · 심의 확인이 필요한 업종」을 걸리는 것 맨 앞에 둔다.
- **확인한 것:** 합성 자료로 띄운 실제 회사 서버에서 의뢰서를 처음부터 끝까지(1440 × 900 · 390 × 844 · 영어) — 소리 파일 받음, 받지 않는 형식은 안내, 새 답이 서버에 저장되고 직원 화면에 보임, 웃음 예시 영상 화소 배율 0.91, 가로 넘침 0. 영어 화면은 글이 길어 물음 칸이 더 넘친다(느낌 294 · 전할 말 322px — 스크롤).
- **검수에서 고친 것(11-13 밤 ~ 14 새벽):** 「사람 없이」 뒤 모델 카드를 고르면 「모델이 직접 말해요」 칩이 돌아오지 않던 것(카본) · 손님이 고지 문구에 줄바꿈을 넣어 직원 메모의 다른 줄을 흉내 낼 수 있던 것과 고르는 칸에 `false` · `0`이 그대로 저장되던 것(GPT — 뒤의 것은 예전부터 있던 틈) · 휴대폰 「전할 말」 모니터에서 고지 문구 자리와 밑줄 글이 겹치던 것, **사진 상품에도 목소리 · 소리 칸이 나오던 것**(사진 상품이면 목소리 물음 · 소리 파일 칸 · 「목소리」 줄을 그리지 않고 값도 보내지 않는다), 영어에서 심의를 review로만 옮긴 것(ad-approval · disclosure로), 고르기 전 설명 줄의 빈 간격(Fable 5.2). 셸은 v60.
- **글 두 곳(11-14, 유호님 「응, 바꿔」):** 권리 동의 줄을 「보내는 사진 · 로고 · 음악 · 문구를 쓸 권리가 있어요」로(영어 photos, logos, music and copy — 음악 파일을 받게 돼서, Fable 5.2 P2였던 것), 첫 화면 약속 넷째 줄을 「이야기로 여운을 남길지, 한 장면의 임팩트로 남길지, 웃음으로 퍼지게 할지 기획 첫 줄에 정해요.」로(영어 A story that lingers, one scene that hits, or a laugh that gets shared). 셸 v61. 동작 · 마크업 · 서버는 그대로(서버는 문장이 아니라 체크 여부만 받는다). 1440 · 390 · 영어에서 줄 넘침 0. 권리 동의 줄은 **모든 상품에 문장 하나**다 — 사진 상품에는 「음악」을 빼는 안(카본 P2)을 넣어 봤으나 체크값 하나가 두 문장을 오가게 되어 다시 검수에서 P2 → 그 고침에서 P1(음악 올리기가 늦게 끝나면 보내기 단추가 먹지 않음)이 나와 물렸다. 상품별 문장이 필요해지면 체크를 문장마다 따로 받는 설계부터 한다. 첫 화면 약속 글의 원문인 [소개글](../PULSE_소개글_20261103/README.md)의 같은 문장은 바꾸지 않았다(밖에 올린 글의 원고라 따로 정할 일).
- **아직 아닌 것:** 「들어갈 문구와 자리를 1차안에 함께 넣어 보여 드린다」는 약속을 제작 절차 문서에 걸음으로 넣기(첫 표시 업종 주문 전까지) · 방향 제안이 `bold`를 읽어 두 안의 폭을 맞추기(지금은 메모와 1차 확인 지시문만 읽는다) · 고객 방 「보내 주신 의뢰서」 요약 여덟 줄에서 새 세 줄 빼기(앞쪽 칸을 비운 손님은 새 줄이 「받고 싶은 날」 · 「최종 확인」을 밀어낸다 — `room-view.mjs` 한 줄, 다음 고객 방 변경에, Fable 5.2 P3) · 휴대폰 모델 화면에서 목소리 물음이 모델 사진 벽보다 먼저 오는 차례(깨진 것은 아님).
