## 한 문장 · 누가 무엇을 하려고 보나

- **한 문장:** 글이 대부분인 PDF는 크롬에서 전체 복사해 붙이면 클로드가 읽는 양이 절반 아래로 준다. 그래프 · 스캔본은 PDF 그대로.
- **누가 무엇을 하려고 보나:** 클로드를 쓰기 시작한 사람이, 긴 PDF(약관 · 계약서 · 보고서)를 올려 일을 시키기 전에 사용량을 덜 쓰려고 본다.
- **무엇으로 이기나:** 직접 잰 숫자 두 개의 차이. 0초부터 몽글이 옆 큰 더미(PDF 그대로 23,596)와 작은 더미(글로 바꾸면 10,917)가 서고 1.5초에 「2.2배」가 뜬다.
- **남는 것:** 「PDF 그대로는 2.2배」와 크롬 `Ctrl+A` · `Ctrl+C` · `Ctrl+V`.
- **가져갈 것:** [게시/자료_PDF사용량.md](게시/자료_PDF사용량.md)(준비물 · 고르는 표 · 바꾸는 두 길 · 확인 문장 · 잰 결과 · 안 되는 때). synk.im/prompts 항목은 초안만 [게시/프롬프트_초안.json](게시/프롬프트_초안.json)에 두었다.
- **받는 길:** 인스타는 댓글 「PDF」 → 키워드 DM(등록 전). 나머지 판은 게시글의 주소 하나(자료 공개 전).

## 실험 기록

### 재는 법

- **날짜 · 모델 · 요금제:** 2026-11-21. Claude Sonnet 5.5(약관 한 벌은 Haiku 5.5 · Opus 5.5로도). 유료 구독 계정의 개발자용 클로드(클로드 코드)다. 클로드 앱(claude.ai)의 사용량 표시는 유호님 계정 화면이라 보지 않았다.
- **한 번 재기:** 맥락 없는 새 하위 에이전트에게 파일 하나만 읽힌다. PDF는 「Call the Read tool exactly once on <파일>」(쪽 · 범위 인자 없이), 글은 「Call the Bash tool exactly once: cat <파일>」이다. 끝나면 「DONE」만 답하게 했다.
- **셈:** 그 에이전트 기록(jsonl)의 API 호출마다 입력 합(`input_tokens + cache_creation_input_tokens + cache_read_input_tokens`)을 읽는다. 덧붙은 양 = 둘째 호출 입력 − 첫 호출 입력 − 첫 호출 출력. 같은 모델 · 같은 길(Read · cat)로 한 글자짜리 파일을 읽힌 덧붙은 양(기준선 Read 4,387 · cat 4,385, 두 번씩 같음)을 빼서 문서의 몫으로 본다.
- **나눠 재기:** 읽기 도구가 10쪽 넘는 PDF에 쪽 범위를 요구해서 10쪽씩 나눠 재고 더했다. 글은 셸 출력 한도 때문에 26KB 아래 덩이로 줄 경계에서 나눴다(`결과/plan.json`).
- **복사한 글:** 설치된 크롬 158.0.8127.36의 PDF 보기에서 `Ctrl+A` · `Ctrl+C`를 실제로 눌러 클립보드 글을 저장했다(`viewer_copy.cjs`, Playwright). 스캔본은 미리 클립보드에 표시 글을 넣고 눌러 바뀌는지 봤다.
- **변환 도구 글:** MarkItDown 0.1.9(파이썬 3.14 가상 환경에 `uv pip install "markitdown[pdf]"`), `markitdown <pdf> -o <md>`.
- **자리:** 모두 git 밖 `.tmp/PDF사용량실험/`이다. 셈 스크립트 `usage.mjs` → `결과/잰값.json`, 질문과 답 `qa_dump.mjs` → `결과/질문답.json`, 문서 만들기 `mk_html.py` · `prep.py` · `mk_chart.py` · `setup_m.py`, 문서 정보 `info.py`.

- 자료의 숫자는 모두 `결과/잰값.json`과 같았다. 질문 답과 세 모델 재기는 하위 에이전트 대화 기록에만 남아 있어 `결과/질문답.json`으로 옮기고, `usage.mjs`를 다시 돌려 Haiku · Opus 줄까지 `결과/잰값.json`에 넣었다. 이때 이 실험을 다룬 제작 에이전트의 기록이 섞여 Opus 기준선이 틀어져서, 「Call the …」로 시작하는 재기 에이전트만 세게 고쳤다.

## 공식 근거(읽은 날 2026-11-21)

- [PDF support — 클로드 개발자 문서](https://platform.claude.com/docs/en/build-with-claude/pdf-support)(docs.claude.com 주소는 이리로 넘어간다): 쪽마다 그림으로 바꾸고, 쪽의 글을 뽑아 그 그림과 함께 준다. 쪽 그림 한 장은 「at most 1,568 visual tokens on every model」, 글은 보통 쪽마다 1,500~3,000토큰. 한 요청 600쪽(문맥 창이 100만 아래면 100쪽) · 첫 당사자 API 128MB.
- [Upload files to Claude — 클로드 도움말](https://support.claude.com/en/articles/8241126-what-kinds-of-documents-can-i-upload-to-claude-ai)(글에 보이는 날 2026-07-23): 대화 첨부는 파일당 500MB · 한 대화 20개. 100쪽 이하 PDF는 글과 그림(차트 · 그래픽)을 함께 분석하고, 101~1,000쪽은 글만 읽는다. 쪽을 가리킬 때는 보기 프로그램의 쪽 번호를 쓴다. 요금제별 차이는 적혀 있지 않다.
- [Usage limit best practices — 클로드 도움말](https://support.claude.com/en/articles/9797557-usage-limit-best-practices): 사용량에 드는 것에 「Message length」 · 「File attachment size」가 있다. 영상 11.6초 작은 글 「읽는 양(토큰)이 많을수록 사용량이 더 들어요」의 근거다. PDF를 따로 다루지는 않는다. 프로젝트에 올린 문서는 캐시되어 다시 쓸 때 덜 든다.
- [MarkItDown — GitHub](https://github.com/microsoft/markitdown): 「MarkItDown requires Python 3.10 through 3.14」, MIT 라이선스, `markitdown path-to-file.pdf -o document.md`.
- **확인 못 함:** 클로드 앱에서 PDF 한 쪽이 몇 토큰으로 들어가는지(도움말에 수치 없음), 무료 · 유료 요금제에 따라 다른지, 앱 대화창에 긴 글을 붙이면 어떻게 다루는지.
