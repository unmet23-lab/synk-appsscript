# Y29 실험 요청문(10-31 밤)

Y5(`../../../yuhobuilds_AI화면한줄_20261025/자료/실험/`)의 「기준」 · 「한줄B」 판(10-25, 같은 네 가게 일곱 판)에 이어서, 같은 방식으로 판 둘을 더 돌렸다. 하위 에이전트(클로드 sonnet, 판마다 새로 하나 · 대화 기록 없음)에 아래 조건 문단과 요청을 그대로 줬고, 결과 HTML을 `../찍기.mjs`로 1280×800 · 390×844(휴대폰, 2배) 첫 화면으로 찍었다. Y5 요청문 원문은 같은 폴더 `요청문_Y5.md`.

## 조건 문단(모든 판 같음 — Y5와 같다)

```
이건 실험이다. 조건:
- 어떤 파일도 읽지 말고, 검색하지 말고, 스킬·웹 도구도 쓰지 않는다. 이 컴퓨터의 저장소·문서·메모·디자인 규칙은 무시한다.
- 아래 「요청」을 일반 사용자가 처음 부탁했을 때 평소 하듯 그대로 해 준다.
- 결과 HTML 파일 하나를 Write 도구로 <임시 폴더>/y29/<판>/<업종>_s_<번째>.html 에 저장한다.
- 끝나면 저장한 경로만 한 줄로 답한다.
```

## 한줄D — 한줄B + 「종이 말고」(빵집 · 필라테스 · 세무사 두 번씩 + 꽃집 = 7판)

요청: `<업종> 홈페이지 첫 화면을 만들어 줘. HTML 파일 하나로. 먼저 이 가게에 어울리는 실제 물건 하나(간판, 포장지, 메뉴판 같은)를 정하고, 그 물건의 색과 글씨로 화면을 만들어 줘. 단, 종이·크라프트 느낌은 빼고.`

결과(`한줄D_폰.jpg`): 7판 가운데 **5판이 짙은 초록 바탕 + 금색 테두리 · 금색 글씨의 현판 · 간판**(꽃집 · 빵집 ①② · 세무사 ①②)으로 몰렸다. 필라테스 ①은 세이지 초록 유리 느낌, ②는 흰 바탕 + 네 색 띠(단계별 색). 한줄B에서 7판 중 6판이 종이 · 크라프트 갈색으로 몰린 것을 빼라고 하자, 이번엔 다른 한쪽으로 몰렸다.

## 한줄E — 물건을 가게 주인이 직접 정해 줌(같은 7판)

요청: 기준 요청 뒤에 `우리 가게(학원 · 사무실) <물건>의 색과 글씨로 화면을 만들어 줘.` 물건은 판마다 다르게 정해 줬다 — 빵집 ① 가게 앞 파란 줄무늬 차양 · ② 계산대 옆 노란 플라스틱 빵 바구니, 필라테스 ① 주황색 요가 매트 · ② 입구의 분홍 네온 간판, 세무사 ① 문 앞 빨간 우체통 · ② 회색 철제 서류함, 꽃집 하늘색 양철 물뿌리개.

결과(`한줄E_폰.jpg`): **7판 모두 준 물건을 그대로 따랐다** — 하늘색 물뿌리개 꽃집 · 파란 줄무늬 차양 빵집 · 노란 체크 바구니 빵집 · 빨간 우체통 세무사(「서류는 우체통에, 세금은 저에게.」) · 회색 철제 서류함 세무사 · 주황 매트 필라테스 · 분홍 네온 필라테스. 한줄D의 초록 바탕 + 금색 간판 몰림은 한 판도 없었다. 물건을 AI한테 고르게 하면(한줄B · D) 한쪽으로 몰리고, 가게 주인이 정해 주면 풀린다.

## 한계

- 클로드 한 모델(sonnet)만, 판마다 한 번씩. 한줄D · 한줄E는 10-31, 기준 · 한줄B는 10-25에 돌렸다(그사이 모델 판이 바뀌었을 수 있다).
- 하위 에이전트는 이 컴퓨터의 작업 환경 안에서 돌았다 — 「저장소 규칙은 무시」로 막았지만 완전히 빈 대화와 같다고 보장할 수는 없다.
- 한줄E는 물건을 판마다 다르게 줬으니 결과가 서로 다른 것은 어느 정도 당연하다 — 재는 것은 「물건을 주면 그 물건을 따르나, 아니면 여전히 초록 · 금색 같은 한쪽으로 돌아가나」다.
