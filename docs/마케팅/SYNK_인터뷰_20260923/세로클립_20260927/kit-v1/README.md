# 창업자 인터뷰 세로 클립 · SNS 키트판(kit-v1)

2026-10-01~02. 사용자가 새 SNS 키트를 보고 「전에 쓰던 양식 이걸로 전부 다 교체해줄래?」라고 했고, 영상은 애니메이션·장면 전환이 많아야 한다고 했다(「밋밋하고 재미없는 제작 컨텐츠는 아무도 안볼것같아」). 그래서 인터뷰 세로 클립 6편(A~F)을 [SNS 키트](../../../../디자인/SNS키트/README.md)의 모양과 모션으로 다시 만들었다.

- **상태: 렌더 전.** HyperFrames 컴포지션이 `check`를 통과했고 시점 스냅샷·확인 시트를 봤다. MP4는 사용자가 미리보기와 렌더 중 무엇을 먼저 할지 정한 뒤에 만든다.
- **원본:** [v2(이전 판)](../v2/README.md). v2는 사용자가 아직 보거나 게시 승인하지 않은 판이다. 화면과 소리의 바탕은 승인된 본편 인터뷰 v9의 4K 마스터다.
- v2와 v1 파일, v2 스크립트는 건드리지 않았다. 이 폴더만 새로 만들었다.

## v2와 무엇이 다른가

| 항목 | v2(이전 판) | 키트판 |
|---|---|---|
| 화면 | 4K 마스터에서 자른 세로 화면 위에 제목·자막을 구워 넣음 | **같은 구간·같은 자르기**(눈 추적 가로 따라가기, 900×1600 기본 ↔ 782×1390 펀치 하드 컷)를 글자 없이 다시 뽑고, 글자는 컴포지션이 얹는다 |
| 훅 제목 | SUIT 68px 두 줄, 둘째 줄 노랑 | 키트 `kv-hook` 두 줄(첫 줄 흰색, 둘째 줄 계정 강조색), 0초부터 보이며 크게 시작해 앉는다(`slam`). 둘째 줄과 같은 말이 들리는 순간 그 아래에 크레용 밑줄(`crayon`) |
| 시리즈·이름 | 이름표 3.5초(제목 아래) | 제목 위 한 행에 시리즈 칩(계속)과 이름표(처음 4초)를 나란히. 둘 다 펠트 단추처럼 눌리며 생긴다(`press`) |
| 말자막 | 조각 단위로 바뀜, 노랑 강조 | 같은 조각·같은 시각(v2 ASS)에서 **낱말 단위 키네틱 자막**(`M.caption`). 낱말은 조각 길이의 70%에 고르게 펼쳐 나온다(0.07~0.45초 간격). v2 노랑 낱말은 `<em>` 강조(계정색) |
| 박자 | 1.15배 하드 컷(첫 5초 1~3번) | 하드 컷은 원본 영상 안에 그대로 두고, 문장 시작·강조 순간마다 얼굴 감싸개 **펀치인 1.00→1.05→1.00**(`punch`, 흔들림 없음). 그래도 화면 변화가 1.5초(첫 3초는 1초) 넘게 없는 틈에는 가운데에 펀치인을 하나 더 둔다(키트 §9 템포) |
| 끝 | D만 3초 엔드카드, 나머지는 말이 끝나면 끝 | 모든 편에 **키트 끝 장**(`k-field` 계정 색 면, 실땀 네 모서리, 흰 펠트 synk 로고, 행동 하나)을 `paper`(종이 밀어 올리기) 또는 `patch`(펠트 덮개) 전환으로. D는 v2 엔드카드 자리(3초) 그대로, 나머지는 2.8초를 더했다(이 동안 소리 없음) |
| 소리 | 본편 믹스를 잘라 −14~−15.6 LUFS, 리미터, AAC 트루피크 보정 | **같은 처리를 무손실로 다시 만들었다**(48kHz 24bit WAV). v2 MP4 소리와 상관 0.9995, 차이 −30 dB(AAC 잡음 수준) |
| 첫 프레임 | A의 0프레임이 앞 장면(넓은 화면) 한 프레임이었다(표지가 되는 프레임) | 그 한 프레임을 다음 프레임으로 덮었다(프레임 수 같음) |
| 끝 장 아래 화면 | — | 끝 장 전환 동안 보이는 얼굴은 마지막 프레임을 멈춘 것이다. D·E는 끝 프레임이 눈 깜빡임이라 8·6프레임 앞을 멈췄다(`FREEZE_BACK`) |

키트판에서 따로 정한 것:

- **이름표 자리:** 키트 기본 `kv-name`(y 640)은 이 화면 구도에서 눈에 걸린다. v2처럼 눈썹 위에 두려고 제목 위 칩 옆으로 옮겼다(`template.html`의 `#hook .hk-top`).
- **위쪽 그늘:** 제목이 이마·머리 위에 앉아 둘째 줄(버터·청금석 옅음)이 피부 위에서 흐려진다. 위에서 y 700까지 옅어지는 검은 그늘(`#scrim`)을 깔았다. 눈높이(y≈620) 아래로는 거의 없다.
- **안전영역:** 9:16은 메타 통합 기준 **위 269 · 아래 672 · 좌우 65(오른쪽은 버튼 자리 160)**. 글자는 모두 y 269~1248 안이다. 말자막은 키트 자리(아래 끝 y≈1236)이고, 끝 장 본문은 y 1180까지, 발(로고·계정)은 y 1248 바로 위다.

## 폴더와 만드는 순서

| 파일 | 하는 일 |
|---|---|
| `make_clean_clips.py` | 4K 마스터 → 글자 없는 세로 원본 `media/<키>.mp4`(소리 없음, 끝 장 자리는 마지막 프레임 멈춤)·`media/<키>.wav`, 기록 `data/<키>.json`. v2의 `make_clips_v2.py`를 읽어 함수를 그대로 쓴다(원본 파일·폴더에는 쓰지 않음). ffmpeg 8부터 `-filter_script`가 없어져 샷 자르기만 `-/filter:v`로 바꿨다 |
| `clips.json` | 편별 자료: 훅 제목 두 줄과 크기, v2 ASS 경로, 끝 장 문구·행동, 전환, 만들 테마. 계정 테마(칩·머리줄·계정 이름·끝 장 기본값) |
| `template.html` | 공용 컴포지션 틀(인물 장면 + 끝 장, 타임라인 하나) |
| `build.mjs` | 틀 + `clips.json` + `data/<키>.json` + ASS → `clips/<키>[-<테마>]/index.html`과 프로젝트 파일, 미디어 하드 링크, 키트 사본(`tools/SNS키트_영상연결.js`) |
| `verify.mjs` | 편마다 `hyperframes check`와 시점 스냅샷, 결과 `clips/_verify.json` |
| `contact_sheet.py` | 스냅샷 PNG를 한 장짜리 확인 시트 `clips/<폴더>/snapshots/시트.jpg`로 묶는다(안전선 붉은 선 표시) |
| `data/<키>.json` | 깨끗한 원본의 기록: 길이, v2 하드 컷, 본편 자막 문장 시작, 소리 측정과 v2 대조, 파일 지문 |
| `clips/<폴더>/` | 편마다 HyperFrames 프로젝트 하나(`index.html`·`package.json`·`hyperframes.json`·`meta.json`). `assets/`는 저장소에 넣지 않는다 |

```bash
# 이 폴더에서
python make_clean_clips.py            # 4K 마스터가 있어야 한다(C:/Users/q1212/Videos/SYNK_Premium_Interview_20260925/). 6편 약 6분
node build.mjs                        # clips/A … F, B-synk
node verify.mjs                       # check + 스냅샷
python contact_sheet.py               # 확인 시트
```

`media/`·`.work/`·`clips/*/assets/`·스냅샷 PNG·HyperFrames 자동 시트(`contact-sheet-*.jpg`)는 `.gitignore`로 뺐다(원본 영상만 약 140MB). 저장소에는 스크립트, `clips.json`, `data/`, 편별 `index.html`·프로젝트 파일, `시트.jpg`만 남는다. 다른 컴퓨터에서는 위 네 줄로 다시 만든다.

다음 인터뷰에도 그대로 쓴다: v2식 클립 계획(`CLIPS` 구간·제목·노랑 문장)과 ASS가 있으면 `clips.json`에 편을 더하고 세 줄을 돌린다. `build.mjs`·`verify.mjs`·`template.html`은 인터뷰 고유 경로가 없어 나중에 `tools/`로 옮겨 공용 도구로 써도 된다(`make_clean_clips.py`는 이 인터뷰의 v2 스크립트에 기대므로 옮길 때 마스터·추적 경로를 인자로 받게 고친다).

## 계정 테마 바꾸기 (yuhobuilds ↔ SYNK 회사)

기본은 `builds`(검은 면, 버터 `#F5C445` 강조, `@yuhobuilds`)다. B·D·E는 링크드인 회사 페이지에도 올릴 계획이라 `synk`(검은 면, 청금석 옅음 `#C5D6F5` 강조, 회사 문구 끝 장, 행동 「synk.im에서 더 보기」) 판을 만들 수 있다.

```bash
node build.mjs D --theme synk && node verify.mjs D-synk     # → clips/D-synk/
```

늘 같이 만들려면 `clips.json`에서 그 편의 `"themes"`에 `"synk"`를 더한다(지금은 B만 `["builds","synk"]`). 테마별 문구는 `themes.<테마>`에, 편마다 다르게 할 것은 `clips.<키>.end.<테마>`에 둔다. 바뀌는 것은 `<body data-acc>`(키트 계정 색), 시리즈 칩, 끝 장 머리줄·문구·행동·계정 이름이다.

- 장면은 편마다 둘이다: **1 인물 장면**(0초 ~ 끝 장 시작)과 **2 끝 장**. 인물 장면 안의 컷은 v2 하드 컷(원본 영상)과 펀치인이다. 키트의 ‘한 영상에 전환 두 가지 이상’은 한 사람이 이어 말하는 클립이라 장면 전환이 끝 장 하나뿐이어서, v2 하드 컷(`cut`에 해당)과 끝 장 전환으로 채웠다. 편끼리는 `paper`·`patch`를 번갈아 써 연달아 올려도 같은 전환이 이어지지 않는다.
- synk 판은 링크드인 회사 페이지용이라 끝 장 발에 로고만 두고(행동 단추에 synk.im이 있다), 시리즈 칩은 「SYNK · 창업자 인터뷰」다.
- 끝 장 행동은 하나다. builds 판은 [v2 게시 문안](../v2/게시/게시문안.md)의 「○○ 친구에게 보내 주세요」를 끝 장 제목으로 옮기고 편지 펠트 스티커를 붙였다. D는 v2 엔드카드 문구(각자의 목표에 맞는 개인화 기술을 만듭니다)를 두고, 본인이 한 말(「저를 지켜봐 주셨으면」)에 맞춰 「팔로우 @yuhobuilds」를 행동으로 뒀다. D의 「감사합니다」 말자막은 끝 장 위에 남는다.
