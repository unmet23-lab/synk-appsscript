# 콘텐츠 제작에서 댓글 DM 등록까지

Claude와 GPT는 콘텐츠를 만들 때 게시 원고와 전달 자료를 함께 준비한다. 사용자가 등록 JSON을 따로 작성하지 않는다. 아래 명령은 제작 담당 AI가 실행한다. 로컬 구현·모의 시험과 운영 반영은 구분하며 현재 배포판은 [자료표](댓글DM_자료표.md)를 확인한다.

## 제작과 승인

게시 묶음의 `원고.json`에 자료 설정을 넣는 로컬 명령이다. 자료·키워드·문구·계정·기한·선택 FAQ·공개 안내는 발행 승인 해시에 함께 들어간다.

```text
node tools/sns-DM준비.js --원고 <원고.json> --계정ID <연결계정ID> --자료명 "내 일에 맞는 자료" --키워드 자료 --문구 "준비한 자료입니다." --자료URL https://synk.im/builds/manual/ --자료폴더 <게시물별Drive폴더ID> --자료함 <Drive자료함ID> --상시
```

PDF·ZIP·프롬프트 TXT는 `--자료URL` 대신 `--자료ID <승인할Drive파일ID> --자료원본 <최종로컬파일>`을 쓴다. 명령이 원본 SHA256을 계산한다. 최종 Drive 사본은 같은 바이트여야 한다. 원본·폴더는 비공개이며 최종 사본 공유는 승인 범위에서 준비한다. 이 명령은 업로드·공유·발송하지 않는다.

새 원고는 댓글만으로 첫 DM에 자료 링크를 전달하는 `opening_mode=resource`가 기본이다(10-18 승인). `--바로전달`도 같은 뜻으로 계속 쓸 수 있다. 전달 방식은 발행 승인 해시·Drive v2 등록본 지문·서버 등록 대조에 함께 들어간다. 기존 첫 안내 방식을 명시해야 할 때는 `--전달방식 text`를 쓴다. 이미 승인된 원고의 생략값은 바꾸지 않으며, 운영 중인 캠페인을 자동 전환하지 않는다. 기존 캠페인의 방식을 바꿀 때도 해당 캠페인과 같은 비공개 등록본의 승인을 함께 맞춘다. 새 실제 댓글·DM 시험은 별도 승인을 받은 뒤 확인한다.

상시 자료는 `--상시`, 행사는 `--종료 <시간대있는시각>`을 명시한다. `fixed`는 최대 30일, `evergreen`은 종료일 없는 별도 승인이다. 기존 캠페인을 자동 전환하지 않는다. 공개 댓글은 `--공개안내 "승인한 문구"`, FAQ는 `--FAQ <제작담당이준비한FAQ.json>`으로 포함한다. FAQ는 유료 AI 호출 없이 해당 자료의 승인 답변만 고른다. 생략하면 빈 설정이다.

```text
node tools/sns-발행.js --준비 --묶음 <게시묶음상위폴더> --출력 <계획.json>
node tools/sns-발행.js --승인 <계획.json> --항목 <게시항목ID> --근거 "사용자가 승인한 게시·자료·문구·공개범위"
```

`--승인`은 실제 사용자 승인 뒤 기록한다. 게시물에서 약속한 내용과 최종 자료를 대조한다. 승인 뒤 자료·문구·게시 이미지가 바뀌면 다시 검수한다. 개인화 웹 프로그램은 synk.im에 배포하고 실제 결과를 먼저 확인한다. 웹 빌드의 `*.manifest.json`은 파일 지문이며 댓글 DM 등록본이 아니다.

## 게시 주소를 받아 한 번에 연결

Instagram 게시 권한을 확대하지 않는다. 승인한 콘텐츠를 브라우저로 게시하고 실제 주소를 확인한 경우도 공식 완료 경로다. 선택적으로 게시 확인을 먼저 남길 수 있다.

```text
node tools/sns-발행.js --게시확인 <계획.json> --항목 <게시항목ID> --주소 <Instagram게시물URL> --근거 "승인한 계정·게시물 실제 확인"
```

backend `SYNK-talk`에서 아래 명령 하나로 승인·게시물 소유·최종 자료·비공개 등록본·서버 등록을 대조한다. 모든 파일 경로는 절대 경로다. 게시 확인을 따로 하지 않았다면 `--post-url <게시물URL> --receipt-note "실제 게시 확인 근거"`도 주면 된다.

```text
node tools/synkbrief-publication.js --publisher-root <SYNK-appsscript절대경로> --plan <계획.json절대경로> --item <게시항목ID> --registry <기존비공개Google연결registry절대경로> --journal <ignored폴더의등록기록.json절대경로> --apply --운영
```

`--apply` 없는 기본 실행은 준비 여부만 읽고 등록본을 올리지 않는다. `--apply`는 승인한 DM 설정으로 비공개 등록본을 올리고 해당 폴더를 즉시 등록한다. 게시 직후 등록 전에 달린 최근 7일 댓글도 조회해 승인 키워드와 일치하는 요청을 중복 방지 큐에 넣으므로 실제 DM·승인된 공개 답글이 발송될 수 있다. 공개 게시나 Drive 공유 변경은 실행하지 않는다.

기존 비공개 Google 연결 목록은 `SYNK-appsscript/tools/company-messenger/data/drive-storage.json`이다(10-18 실제 unmet23 Drive 인증 확인). `--registry`에는 이 파일의 절대 경로를 넘긴다. Git 무시 파일이며 본문·토큰을 문서나 로그에 복사하지 않는다.

명령은 현재 승인 해시를 검사하고 연결 계정의 Meta 본인 정보·소유 미디어 GET으로 게시 주소를 검증한다. Drive는 기존 OAuth로 최신 메타를 읽어 원본 SHA256·정확한 폴더를 대조한다. 웹 URL도 같은 비공개 등록본을 쓴다. 업로더가 파일 공유권한·비공개 폴더·등록본 본문을 검증한 뒤 `drive-register`로 이 폴더만 즉시 등록한다. 수백 개 자료의 전체 순회를 기다리지 않는다. 이어 서버 등록 대조와 `publication-check` 댓글 확인을 한 명령에서 수행한다.

**`state=registered`, D코드, `catchup_verified=true`가 나와야 등록 완료다.** DB의 계정·게시물·문구·기한·FAQ·자료 ID/판본/링크·활성 상태를 대조한다. 요청한 공개 답글·FAQ 기능이 계정에서 OFF면 완료로 보지 않는다. `ready`는 읽기 확인만 완료, `awaiting_sync`는 업로드했으나 등록 대조 미완료, `pending_catchup`은 등록 전 댓글 확인이 남음, `needs_reconciliation`은 업로드 결과 확인 필요다. 대기 상태의 같은 명령은 재업로드하지 않고 서버 결과부터 확인한다. 불명확한 업로드를 자동 재시도하거나 덮어쓰지 않는다.

일반 자료 변경 점검은 기존 5분 순회가 맡고 새 등록은 즉시 처리한다. 등록 확인 대기는 기본 최대 5분 30초다. 댓글 확인이 시간·조회량 한도에 닿으면 비공개 기록에 서버의 재개 커서만 보관하고 `pending_catchup`으로 남긴다. 같은 명령을 재실행하면 남은 댓글부터 이어가며, 이미 끝난 등록도 새 누락 확인을 거친다. 등록·큐 입고와 실제 자료 실수신은 별도 검증이다.

Drive 파일의 내용(SHA256)이 같고 메타데이터 version만 증가한 경우 최초 승인 version을 유지해 재실행한다. 구형 등록 기록은 같은 비공개 manifest의 승인 지문·폴더·소유권·공유 권한을 검증한 후 원래 version을 복원한다. 파일 ID·내용·승인 설정이 바뀌거나 version이 역행하면 멈춘다. 10-09 실제 A/B 등록본에 `--apply` 없는 읽기 재실행을 확인했으며 journal은 불변이었다.

## 변경과 종료

다른 자료는 새 파일·새 게시 묶음 또는 새 campaign ID로 승인한다. 게시 결과 주소를 다른 게시물로 덮어쓰지 않는다. 상시 자료도 캠페인 OFF·파일 이동·공유 해제·명시 중단으로 종료할 수 있다. 이미 전달한 링크를 소급 회수한 것으로 보고하지 않는다. 종료 조작과 파일 정리는 승인된 운영 범위에서 별도 수행한다.
