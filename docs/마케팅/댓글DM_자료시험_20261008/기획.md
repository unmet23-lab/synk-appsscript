# 댓글 DM 자료 전달 시험 A·B

> 아래는 10-08 제작 당시의 계획과 로컬 검사 기록이다. 이후 사용자 승인으로 공개 시험을 진행했고 10-09 실제 5통 수신과 정리를 완료했다. 현재 상태는 [결과](결과.md)를 따른다.

트리거: 사용자 요청·운영 실화, 2026-10-08. Google Drive 자료와 게시글의 연결을 구분해 전체 전달 과정을 시험하도록 허용했다. **공개 게시 승인은 아직 받지 않았다.**

이 카드는 마케팅 콘텐츠가 아닌 기능 점검용 fixture다. 보는 이유는 게시물 A·B와 실제로 받은 자료의 표식이 같은지 확인하는 것이다. 매력·효능 홍보, 무료 자료 약속, 댓글 유도, 실제 얼굴을 넣지 않는다. SYNK 콘텐츠 제작 방식의 일반 훅·개인화 프로그램·72시간 성과 판정은 이 운영 시험의 목적에 해당하지 않는다.

| 구분 | 카드 제목 | 받은 자료와 비교할 표식 | 계정 |
|---|---|---|---|
| A | 자료 전달 시험 A | 파란 우산 / A-20261008 | @yuhobuilds |
| B | 자료 전달 시험 B | 노란 연필 / B-20261008 | @yuhobuilds |

두 카드의 작은 글은 `자동 DM 연결 확인용 · 실제 배포 자료 아님`이다. 파란 우산·노란 연필은 서로 다른 합성 시험 자료의 이름이며 실제 상품이나 결과를 주장하지 않는다.

기존 `docs/디자인/SNS키트/kit.css`의 `data-acc="builds"`, `doc45`(1080×1350), 검정·흰색·버터 강조, 기존 흰 펠트 SYNK 로고와 실땀 모서리를 사용한다. 장식 이미지·실제 인물·새 생성 이미지는 추가하지 않는다. 색상으로만 구분하지 않고 제목 A·B와 표식 코드로 구분한다.

원고: `원고.html`. 캡션: `캡션_A.txt`, `캡션_B.txt`. 원고는 로컬 키트·로컬 자산만 읽으며 외부 연결·스크립트를 CSP로 차단한다.

굽기: 저장소 루트에서 `node tools/SNS키트굽기.js docs/마케팅/댓글DM_자료시험_20261008/원고.html --sheet`.

현재 범위는 제작·로컬 렌더·검사·검토용 시트까지다. 외부 업로드·공개 게시·실제 댓글·DM 발송은 이 제작 단계에서 실행하지 않는다. 기존 D0003 게시물과 캠페인은 수정하지 않는다.

## 제작 확인

SNS 키트 굽기로 두 장 모두 1080×1350 PNG를 생성했다. 오류·경고 0, 서체 SUIT Variable·Inter Tight·DM Mono 로드, 장식·유행 장치 0개, 글자 안전영역·넘침·깨진 그림 검사를 통과했다. 전체 크기 A·B PNG와 300px 폭 확인 시트를 실제로 열어 제목·표식·A/B 코드의 구분, 하단 점검 문구·펠트 로고, 겹침·잘림 없음을 확인했다. 캡션 두 파일은 요청된 정확한 문구와 일치한다.

- `out/01_doc45_시험-A.png`
- `out/02_doc45_시험-B.png`
- `out/_시트.png`
- 자동 검사: `out/검사.json`
- 파일 크기·해시·확인 범위: `검증.json`
