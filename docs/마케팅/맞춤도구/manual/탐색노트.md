2026-10-03. [제작 절차](../제작절차.md) 1단계의 결과다. 여기 적은 사실이 `content.js`의 팁·출처와 `rules.js`의 안내 문장이 된다. 표시는 **공식**(회사·정부·표준 문서 원문), **보도**, **SYNK 판단**, **실제 사례**(SYNK가 겪은 일)다. 원문은 조사 담당 에이전트 네 갈래(ChatGPT·Claude·Gemini·검수와 안전)가 2026-10-03에 직접 열어 문장을 대조했다. help.openai.com은 WebFetch가 403이라 헤드리스 크롬으로 읽었고, 로그인한 화면은 열지 않았다(로그인 금지).

## 1. 이 도구가 풀 질문

“AI에게 한 줄로 일을 맡기고 싶은데, 무엇을 미리 적어 두면 알아서 끝까지 하면서도 사고는 안 낼까?”
출발점은 yuhobuilds 「AI한테 한 줄 시켰더니」의 실화다(아래 §6). 한 줄로 맡길 수 있었던 건 긴 프롬프트가 아니라 미리 써 둔 문서(만드는 방식·검수 규칙·하면 안 되는 것) 덕분이었다. 도구는 그 문서의 첫 판을 사람마다 만든다.

결정 요소: 맡길 일 → 맡은 일·지킬 것 / 완성 기준 / 검수 항목별 확인 방법 / 사람 차례 / 보고 방식 / 넣는 곳(AI별 메뉴)과 요금제.

## 3. 흔한 오해 (팁으로 반드시 짚을 것)

1. “AI에게 잘 시키려면 긴 프롬프트가 필요하다” → 기준은 매뉴얼에 한 번 써 두고 지시는 한 줄로(manual-why).
2. “매뉴얼은 계정 전체 설정에 넣으면 된다” → 모든 대화에 섞인다. ChatGPT 사용자 지정 지침은 무료 1,500자 한도도 있다(manual-place).
3. “매뉴얼에 적어 두면 AI가 절대 안 한다” → 지침은 따르는 기준(맥락)이지 강제 장치가 아니다. 결제·삭제는 앱의 확인 설정으로 한 번 더 막는다(manual-place, stop-agent).
4. “꼼꼼히 검수해 줘면 된다” → 항목마다 확인 방법을 적어야 같은 기준으로 확인하고 보고한다(질문 3 팁, report-3).
5. “AI가 자신 있게 말하면 맞다” → 세 회사 모두 틀릴 수 있다고 안내한다. 지어낸 출처·링크가 대표적이다(check-facts, check-links).
6. “기계 번역 검수를 통과하면 끝” → 실제 사례도 원어민 확인은 남은 일이었다(check-lang).
7. “에이전트가 알아서 확인을 받으니 괜찮다” → 확인 장치가 있어도 프롬프트 인젝션 위험은 0이 아니다. 사람 차례와 숨은 지시 거절 줄을 둔다(stop-agent, stop-injection).
8. “한 줄 지시에 ‘올려 줘’가 있었으니 다 해도 된다” → 허락은 그 일 한 번에만. 사람이 쓴 글 수정은 따로(stop-mywords, 실제 사례).
9. “매뉴얼을 쓰려면 유료가 필요하다” → 프로젝트·Gem 모두 무료에서 된다(save-free).

## 5. 쓰지 않은 것과 이유

- **ChatGPT agent·Atlas**: 지금 제공되지 않거나 종료 공지가 있어 안내하지 않았다. 화면을 직접 누르는 ChatGPT 기능은 클라우드 브라우저로 적었다.
- **ChatGPT 프로젝트 설정 안의 칸 이름과 ‘저장’ 단추**: 문서에 없고 로그인 화면을 못 봐서 “프로젝트 지침 칸에 붙여 넣어 저장”까지만 적었다.
- **프로젝트·Gem 지침 글자 수 한도**: 공식 문서에 없다. 대신 이 도구의 매뉴얼은 모든 조합에서 1,389자 이하(무료 ChatGPT 사용자 지정 지침 1,500자보다 짧음)로 시험한다.
- **ChatGPT Work의 월 횟수, 요금의 부가세 포함 여부**: 확인하지 못했다.
- **Claude in Chrome 공격 성공률의 최신 시스템 카드 숫자**: 평가 세트가 달라 일반 사용자에게 비교해 보여 주지 않고, 2025 시범과 2026-08 도움말 두 숫자만 썼다.
