# 프롬프트 모음 · synk.im/prompts

2026-10-22 유호님: 「앞으로 유호빌드에서는 영상 속 문제를 해결하는 과정을 보여 주고 있는데, 마지막에 이걸 전달받아서 쉽게 적용할 수 있는 프롬프트 같은 걸 준비해서 같이 주면 사용자 입장에서 훨씬 쉽고 간편하지 않을까」 → 「프롬프트나 이런 거 쓰는 곳은 우리 홈페이지에 synk.im/뒤에 주소 뭐 하나 붙여서 이곳에 우리 프롬프트들 모아놓자. 간접적인 홈페이지 홍보도 되고 사람들이 도움받으려고 알아서 들어올 거 아니야」. 주소는 Claude가 `synk.im/prompts`로 정했다(공개본에 겹치는 경로 없음, [결정 표](../../../_ops/결정.md) 10-22). 제작 흐름은 [제작 방식 v2 §3-6](../../콘텐츠_제작방식_v2_20261002.md#take-away-prompts).

yuhobuilds 쇼츠에서 실제로 막혔다가 푼 방법을 보는 사람이 그대로 가져가는 프롬프트(맞지 않는 편은 명령 한 줄·체크리스트)로 모은 한 쪽짜리 페이지다. 질문에 답하면 결과가 나오는 [맞춤 프로그램](../README.md)(`/builds/`)과 달리, 여기는 복사해서 붙여 넣는 것이 전부다.

## 한 편이 닿는 길

1. 영상 끝 화면: 핵심 한 줄 + 「전체 프롬프트는 synk.im/prompts」.
2. 유튜브 설명란·고정 댓글, 티스토리 본문의 복사 상자: 전체 프롬프트 + `https://synk.im/prompts/#<id>`. 인스타 캡션은 핵심 한 줄 + 주소.
3. 이 페이지: 머리글 바로 밑 목차(제목 = 푸는 문제, 부제 = 본 영상 제목)에서 자기 항목으로 간다. 항목마다 넣는 곳(어떤 AI) · 빈칸 꼴 본문과 「복사」 · 빈칸 채우기(선택, 채운 대로 복사) · 우리가 직접 붙여 넣어 돌려 본 결과 · 영상·블로그 글 · 맞춤 프로그램과 synk.im 홈으로 가는 길.

벤치마킹(10-22, 웹 공개 자료 — AIPRM 크롬 스토어·Trustpilot, PromptBase·God of Prompt Trustpilot, r/ChatGPTPromptGenius·r/PromptEngineering, OpenAI Academy, 국내 프롬프트 공방): 가입·이메일 없이 탭 한 번 복사와 「복사됨」, 입력칸에 값을 넣으면 본문이 바뀌어 복사되는 것, 꾸미지 않은 결과 예시와 시험한 날짜가 호평이고, 범용 한 줄 팩·빽빽한 화면·빈칸을 그대로 보내는 실수·조용히 실패하는 복사(Safari·앱 안 브라우저)가 불만이다. 그래서 가입 없음 · 빈칸 채우기 · 「직접 돌려 봤어요」 · 영상에서 푼 것만 · 복사 실패 때 글을 골라 두고 안내하기로 했다.

## 파일

| 파일 | 담당 |
|---|---|
| `프롬프트.json` | 항목 목록 — **새 편은 여기에 항목 하나만 더한다** |
| `page.js` | 항목 검사(`checkPrompts`), 편 기록 읽기(`episodeOf`·`linksOf`), 페이지 그리기(`renderPage`). 그리기는 순수 함수 |
| `og.html` | 링크 미리보기 이미지 원고(빌드가 1200×630으로 찍는다) |
| `../build.mjs prompts` | `dist/prompts/`로 조립 — 검사 → 공개본에 있던 id가 빠졌는지 대조 → 편 기록에서 날짜·영상 제목·주소 → 쓰인 글자만 남긴 SUIT·라틴 글꼴 → og.png → 지문 |
| `tests/프롬프트모음.test.js` | 검사·그리기·편 기록 읽기 시험(CI) |

## 항목 꼴

```json
{
  "id": "still-time",
  "편": "yuhobuilds_멈춘시간재기_20261021",
  "제목": "내 쇼츠, 몇 초가 멈춰 있는지 재기",
  "설명": "영상에서 무슨 일이 있었고 이 프롬프트로 무엇을 얻는지 한두 문장",
  "블록": [
    { "종류": "프롬프트", "넣는 곳": "코딩 AI — 내 영상 파일을 열고 명령을 돌릴 수 있는 것", "본문": "【내 영상 파일】에서 …" },
    { "종류": "명령", "넣는 곳": "직접 — 터미널(ffmpeg가 깔려 있을 때)", "본문": "ffmpeg -i 【내 영상 파일】 …", "메모": "본문 아래 한 줄 설명" }
  ],
  "빈칸": { "내 영상 파일": "잴 영상 파일 이름(예: 쇼츠_최종.mp4)" },
  "확인": "우리가 직접 붙여 넣어 돌려 본 결과 한두 문장(날짜)"
}
```

- 쓸 수 있는 칸은 위와 `왜`(왜 되나 한 줄, 선택)·`영상제목`(준비.json 제목 대신 보일 이름, 선택)뿐이다. 블록은 `종류`·`넣는 곳`·`본문`·`메모`(선택). 모르는 칸은 검사가 막는다.
- `id`: 주소 `#id`. 영문 소문자·숫자·하이픈. **한 번 쓰면 바꾸거나 지우지 않는다** — 영상 설명·댓글이 가리킨다. 빌드가 공개본의 id가 빠지면 멈춘다.
- `편`: `docs/마케팅/` 아래 편 폴더. 빌드가 그 편 `게시/준비.json`의 `슬롯`을 영상 공개일로, `제목`의 「 — 」 앞을 영상 제목으로 쓴다(슬롯은 자주 밀려서 항목에 날짜를 따로 적지 않는다). 영상·블로그 주소는 `게시/게시결과.json`에서 `yuhobuilds-youtube`·`yuhobuilds-instagram`·`shift-tistory` 줄의 「게시됨」만 쓰고, 「예약됨」이면서 시각이 지난 유튜브·블로그는 빌드가 실제로 열어 보고(유튜브는 oEmbed) 열릴 때만 붙인다 — 예약이 풀리거나 놓칠 수 있다. 아직이면 「영상 10월 24일 공개」와 채널 링크. 작업실로 올라간 판은 `node tools/작업실예약.js 상태 <편> --캐시`로 게시결과.json이 맞춰진 뒤 다시 빌드하면 붙는다.
- 빌드 날(KST)보다 영상 날짜가 뒤인 항목은 아래 「곧 나올 영상의 프롬프트」 칸에 그린다(가까운 날부터). 보는 날 그 날짜가 지났으면 페이지 스크립트가 위로 옮긴다.
- `블록.종류`: `프롬프트`(AI에 붙여 넣기) · `명령`(터미널에 직접, 고정폭 글꼴, 채운 값에 띄어쓰기가 있으면 큰따옴표로 감싼다) · `체크리스트`(손으로 따라 하기, 번호 목록, 복사 없음).
- 빈칸은 본문 안 `【이름】`, 기본값이 있으면 `【이름=기본값】`이다. `빈칸`에 이름마다 한 줄 설명을 단다. 화면에는 기본값(없으면 【이름】)이 강조되어 보이고, 빈칸 채우기 칸에 적으면 본문과 복사되는 글이 그 값으로 바뀐다(저장·전송 없음). 기본값 없는 빈칸이 남은 채 복사하면 「붙여 넣은 뒤 바꿔 주세요」를 알린다. 페이지 밖 글(설명란·티스토리)에는 `【기본값】`으로 쓴다.
- 표지 썸네일은 싣지 않는다 — 편 표지에 도구 이름이 그려진 판이 있고, 영상 제목만으로 찾을 수 있다.

## 표기

- **AI 이름 대신 쓰임새로 적는다(10-22).** 「채팅 AI」(대화창에 붙여 넣는 AI 어디든), 「코딩 AI」(내 컴퓨터의 파일을 열고 명령을 돌릴 수 있는 AI). 사이트에 AI 도구 이름을 쓰지 않는다는 10-02 원칙은 「어떤 AI로 만들었는지」를 쓰지 않는 규칙이고 도구 사용법이 내용인 `/brief/`·`/builds/`는 예외지만, 이 페이지는 어느 AI에 붙여도 되는 프롬프트를 싣고 서비스 이름은 자주 바뀌므로 이름 없이 쓴다. `checkPrompts`가 `tools/lib/게시글규칙.js`의 AI·제작 도구 목록과 맨 gpt·openai·codex·anthropic을 막는다(GitHub·PowerShell·ffmpeg·gh는 AI가 아니라 둔다).
- 프롬프트는 실제로 붙여 넣어 같은 결과가 나온 것만 올리고 그 결과를 `확인`에 적는다(비면 빌드가 멈춘다).
- 내부 번호·저장소 경로·상대 날짜를 보이는 글에 쓰지 않는다(같은 검사, 상대 날짜는 설명 글만 — 프롬프트 본문의 「이번 달」은 붙여 넣는 사람의 때라 둔다).

## 새 편을 더할 때

1. `프롬프트.json` `항목` 맨 앞에 하나 더한다.
2. `node --test tests/프롬프트모음.test.js` → `node docs/마케팅/맞춤도구/build.mjs prompts`.
3. 미리 보기 `node docs/마케팅/맞춤도구/serve.mjs` → `http://127.0.0.1:4391/prompts/`.
4. 공개: `node tools/공개.js 올리기 --원본 docs/마케팅/맞춤도구/dist prompts --전부` 미리 보기 → `-m "…" --실행 --계획 <해시>`. 항목만 더한 날은 위 시험·검사와 배포 점검으로 공개하고, `page.js`의 화면(CSS·스크립트·틀)을 바꾼 날은 아르곤 → Fable 화면 검수 뒤 공개한다.
5. 공개가 된 뒤 편 글에 링크를 넣고, 편 `게시/준비.json`에 `"프롬프트": {"id": "<id>", "주소": "https://synk.im/prompts/#<id>", "본문": "docs/마케팅/맞춤도구/prompts/프롬프트.json"}`. `tools/올리기전검사.js` ⑧이 이 칸(슬롯 10-23부터 없으면 「확인할 것」), 프롬프트.json의 항목, 공개 페이지 응답 200과 그 항목이 공개본에 있는지 본다.
