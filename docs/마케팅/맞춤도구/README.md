# SYNK 맞춤 도구 · 댓글로 받는 개인화

2026-09-27 사용자 요청: 개인화 시스템을 지향하는 회사이니 정보를 전달할 때 늘 개인화된 형태로 전달하고 싶다. 인스타그램·페이스북·유튜브의 게시물 자체에는 개인화를 넣기 어렵다. 그래서 댓글을 달면 PDF·프롬프트와 함께, 그 콘텐츠가 다루는 문제를 풀어 주는 **개인화 추천 프로그램**을 보내 클릭만으로 쉽게 이해하고 쓰게 한다. 첫 예시는 synkbrief의 ‘AI 전용 컴퓨터 추천’이다. 용도·쓸 프로그램·쓰는 곳을 묻고 램이 몇 GB 필요한지 세밀하게 추천하며, 고르는 동안 램이 AI에 왜 필요한지도 팁으로 알려 준다. 이어서 데스크톱·노트북 결정, 가성비 우선(16GB 기준점, 여유는 따로, 무거운 작업이면 데스크톱), NPU가 의미 있는 경우와 차이 없는 경우, 그래픽카드와 램이 왜 필요하고 왜 비싼지까지 팁으로 알려 달라고 했다.

이 폴더는 그 프로그램들의 원고와 빌드 도구다. 첫 도구 [AI 컴퓨터 맞춤 추천](computer/)을 만들었고, 같은 틀로 다른 편의 도구를 추가한다.

**새 도구는 반드시 [제작 절차](제작절차.md)를 따른다.** 사전 탐색을 충분히 하고, 추천에 들어가는 부품마다 ‘무엇인가·왜 필요한가·왜 비싼가·필요 없는 경우·함정·확인법’ 팁을 채운다. 결과에서는 ‘나에게 의미 있는 것 / 신경 쓰지 않아도 되는 것’을 사람마다 보여 준다(2026-09-27 사용자 요청). 빌드 도구가 이를 검사한다.

## 한 편이 사람에게 닿는 네 겹

| 겹 | 무엇 | 개인화 |
|---|---|---|
| 1. 피드 | 캐러셀·영상. 훅과 핵심 정보 | 모두에게 같다 |
| 2. 댓글 → DM | 댓글 키워드(`synk`)를 남기면 링크가 간다. 인스타그램은 synkbrief 자동 DM 엔진이 관리표에 등록된 게시물만 보낸다 | 받는 사람만 받는다 |
| 3. 맞춤 도구 | 한 번에 하나씩 묻고, 고를 때마다 이유를 짧게 알려 준다. 결과는 내 답으로 계산한 결론(가성비·여유), 사람마다 고른 팁, 확인표, 프롬프트 | 내 답으로 계산한다 |
| 4. 가져가기 | 내 조건이 채워진 프롬프트, 매장·상담 문장, 결과 링크, 공통 설명서 PDF | 프롬프트·문장은 내 것, PDF는 공통 |

피드는 볼 이유를 만들고, 도구는 “그래서 나는?”에 답한다. 도구의 결과 화면이 곧 SYNK 개인화가 어떤 경험인지 보여 주는 가장 짧은 체험이다.

## 지키는 것

- **AI를 부르지 않는다.** 계산은 브라우저 안의 규칙으로 한다. 사용자가 늘어도 비용이 늘지 않는다. 오늘 가격·판매 모델처럼 매일 바뀌는 정보는 결과 프롬프트에 담아 사용자의 AI(ChatGPT·Claude·Gemini)가 찾게 넘긴다.
- **이 기기에만 저장한다.** 고른 답, 체크한 항목, Atlas 기록은 `localStorage`에만 둔다. 서버로 보내거나 방문을 추적하지 않는다. 화면 아래 ‘저장된 기록 지우기’로 모두 지운다.
- **Atlas로 기억한다.** 원본 엔진 `atlas/engine.js`(atlas-2)를 그대로 싣는다. 영역은 `SHIFT/synkbrief/visitor`다.
  - ‘팁 보기’ 스위치 = 도움 방식(`support`: step 켬, choose 끔). 같은 채널의 다른 도구에도 이어진다.
  - 결과 분량(간단히·기본·자세히)은 Atlas가 고른다. ‘너무 많아요’를 누르면 다음에 간단히, ‘더 자세히’를 누르면 자세히 연다. 결과 위에 그 이유를 한 줄로 밝힌다.
  - 질문을 끝내 결과에 도착했을 때와 공유 링크를 처음 열었을 때만 한 회차로 기록한다. 새로고침은 기억만 읽는다. 같은 탭에서 공유 링크를 새로고침해도 다시 기록하지 않는다(`sessionStorage`).
- **공식 자료와 SYNK 판단을 섞지 않는다.** 이유마다 `공식`·`SYNK 판단`·`커뮤니티`를 붙이고 출처와 확인 날짜를 밝힌다. 가격이나 제품 순위를 알려 주는 서비스로 소개하지 않는다.
- **디자인.** [펠트 스크랩북 양식](../../디자인/펠트스크랩북/README.md)(2026-09-29 사용자 확정, 이 도구들이 대표작). 흰 바탕·검정 글자, SHIFT 청금석, 실제 실땀 테두리(`thread-shift.webp`), synk.im의 승인 유리 선택 카드, SUIT(쓰인 글자만 남긴 약 140KB 파일). 움직임 감소 설정을 따르고 키보드·화면 낭독기로 쓸 수 있다.

## 디자인 근거 · v3 ‘펠트 스크랩북’ (2026-09-29)

사용자가 결과를 보고 “훨씬 좋다, 앞으로 이 양식으로 구성하고 싶다”고 해서 SYNK 공통 양식이 됐다. 규칙과 부품은 [양식 원문](../../디자인/펠트스크랩북/README.md)과 `scrapbook.css`로 옮겼고, 이 절은 조사 기록으로 남긴다.

사용자 요청: “전체 디자인이 나쁘진 않은데 완전 최신 트렌디함이 아쉽다. 레퍼런스 플랫폼을 전부 찾아보고 가장 최신 인기 디자인으로 리디자인해 달라.” 사용자가 보낸 릴스(@wavismm)의 일곱 키워드(웹코어, 마스킹 셰이프, 컨페티, 스케치북 콜라주, 엠보싱, 카메라 인터페이스, 나이브 디자인)와 2025~2026 트렌드 보고서·수상작을 조사해 정했다.

- **고른 조합**: 스케치북 콜라주 + 가벼운 엠보싱 + 나이브 드로잉. 셋 다 ‘손으로 만든 것’이고 2026 보고서들이 가장 많이 겹쳐 짚은 흐름이다(Kittl×Savee 2026-01, Canva 2025-12-10, Adobe Express 2025-12-12, Pinterest Predicts 2025-12-09, Creative Bloq 2025-12-23 ‘Anti-AI Crafting’). SYNK의 펠트·실땀은 흉내가 아니라 실제 재료라 설득력이 크다.
- **한 번만 쓰는 것**: 웹코어는 첫 요청문·프롬프트 창 하나, 카메라 인터페이스는 결과 머리의 실땀 모서리와 날짜 도장, 마스킹은 결과 대표 그림 하나, 컨페티는 청금석 계열 몇 점을 긍정적인 결과에만(멈춘 상태).
- **뺀 것**: ‘REC’ 표시(화면 낭독기가 읽고, ‘이 기기에만 저장·추적 없음’ 약속과 반대 신호), 창 제목줄의 가짜 단추, 칩 글자 기울임, 모든 카드의 검은 윤곽선(핵심 카드·요청문 창·하단 바에만 남김), 주 버튼의 검은 그림자(펠트 두께로 바꿈).
- **수상작·국내 서비스에서 가져온 것**: 바탕 한 색과 강조색 하나, 큰 연출은 결과 공개 한 번(Spotify Wrapped 2025, Squarespace Foundations·Why Zero Awwwards SOTD 2026-09), 하단 고정 주 행동과 “~했어요” 복사 알림(토스 TDS·앱인토스 가이드, 당근 SEED), 결과는 그림→제목→설명→버튼 순서.
- **브랜드 원칙 유지**: 바탕은 흰색·검정(DESIGN §2), 구분선은 실제 실땀, 조작부는 승인 유리(2026-09-19), 라틴은 Inter Tight·숫자와 라벨은 DM Mono(DESIGN §3), 스티커는 synk.im 승인 펠트 아이콘(`loom-*-20260918`)만 썼다.
- **접근성**: 초점 표시 색 `#edbd34`(흰 바탕 약 1.8:1) → `#24448c`, 흐린 글자 `#767b83`(약 4.3:1) → `#6f747c`. 하단 바는 불투명 흰 바탕, 초점이 가려지지 않게 `scroll-padding-bottom`, 체크 스티커의 톡 움직임은 ‘동작 줄이기’에서 멈춘다. 복사 알림은 화면용이고 낭독은 기존 알림 줄이 한다.

## 쓰는 법

```bash
node --test "docs/마케팅/맞춤도구/computer/rules.test.js"
node "docs/마케팅/맞춤도구/build.mjs"
node "docs/마케팅/맞춤도구/serve.mjs"
```

미리보기는 `http://127.0.0.1:4391/brief/computer/`. 결과 공유 링크(`#r=…`)에는 고른 선택지 ID만 들어가고 주소의 `#` 뒤라 서버로 가지 않는다.

**배포**는 synk.im 라이브 저장소(`synk-policy`의 `origin/main`) 기준 임시 작업 공간에 `dist/brief/<도구>/`만 복사해 올리고, 올라간 파일의 sha256을 `dist/<도구>.manifest.json`과 대조한다. 다른 사이트 파일은 건드리지 않는다. 사용자 승인 뒤에만 한다. 기록: 2026-09-29 컴퓨터 첫 배포 `fcc9c4f`, 같은 날 새 디자인 재배포와 회의 도구 배포 `1c7a166`(두 도구 53개 파일 라이브 바이트 일치).

## 새 도구 붙이기

[제작 절차](제작절차.md)의 순서대로 한다. 요약하면 이렇다.

1. **사전 탐색**을 가장 길게 한다. 결과는 `<도구>/탐색노트.md`에 남긴다(공식 자료, 최신 가격·변화, 값을 정하는 이유, 흔한 오해·광고 용어, 필요 없는 경우, 직접 확인하는 법).
2. `<도구>/추천기준.md`에 사용자 결정·원칙·결정표·기준표·시험 약속을 쓴다.
3. `<도구>/content.js`에 질문(질문마다 왜 묻는지, 선택지마다 한 줄)과 팁 은행(`TIPS`, 부품별 필수 종류 `COMPONENTS`)을 쓴다.
4. `<도구>/rules.js`에 계산과 사람마다 보여 줄 팁 고르기를 쓰고, `rules.test.js`로 약속과 검사기를 시험한다.
5. `<도구>/view.js`의 결과에는 늘 ①결론(가성비·여유) ②이유 ③나에게 필요한 팁 ④내 조건이 채워진 프롬프트 ⑤확인표 ⑥반응 버튼을 둔다.
6. `build.mjs`의 `TOOLS`에 올릴 경로를 더한다. 탐색노트·추천기준이 없거나 검사에서 빠진 곳이 있으면 빌드가 멈춘다.
7. 데스크톱·휴대폰 폭(375px)에서 가로 넘침 0, 전 단계 클릭, 새로고침 뒤 기억, 기록 지우기를 확인한다.
