# 맞춤 도구 제작 절차

2026-09-27 사용자 요청. 맞춤 도구를 만들 때마다 **사전 탐색을 충분히** 한다. NPU처럼 ‘누구에게는 의미가 있고 누구에게는 차이가 없는지’, 그래픽카드와 램이 **왜 필요하고 왜 비싼지**까지 아주 자세한 팁을 꼭 담아 개인화 추천을 한다. 다음 콘텐츠를 만들 때마다 항상 적용한다.

GPT와 Claude 모두 이 문서를 따른다. 첫 적용 사례는 [AI 컴퓨터 맞춤 추천](computer/)이다([탐색노트](computer/탐색노트.md) · [추천기준](computer/추천기준.md)).

## 0. 무엇을 만드는가

- 피드(캐러셀·영상)는 모두에게 같다. 맞춤 도구는 “그래서 나는?”에 답한다.
- 맞춤은 두 가지로 이뤄진다. 내 답으로 계산한 결론, 그리고 **내 경우에 맞는 팁**이다. 팁은 “나에게 의미 있는 것”과 “신경 쓰지 않아도 되는 것”을 나눠 보여 준다.
- 바꾸지 않는 조건: AI를 부르지 않는다(사용자가 늘어도 비용 0). 기록은 그 기기에만 남긴다. 공식 자료·보도·SYNK 판단을 구분해 표시한다.

## 1. 사전 탐색 · 가장 오래 쓰는 단계

목표는 이 주제에서 사람들이 **돈과 시간을 잘못 쓰는 지점**을 찾는 것이다. 결과는 `<도구>/탐색노트.md`에 남긴다. 빌드 도구는 이 파일이 없으면 빌드하지 않는다.

1. **결정 요소 목록**: 결과에 들어갈 부품·선택을 모두 적는다. 예: 형태, 램, 그래픽, 저장공간, CPU, NPU, 운영체제.
2. **공식 자료**: 회사·제조사 문서의 요구 사양, 기능, 지원 범위를 URL·날짜와 함께 적는다.
3. **최신 변화**: 제작일 기준으로 가격, 새 제품, 지원 종료, 정책 변화를 확인한다. 분기마다 바뀌는 것이다.
4. **값을 정하는 이유**: 부품마다 왜 비싸고 왜 싼지 적는다(공급, 수요, 원가 구조). 예: HBM이 일반 램 생산을 밀어냄, 그래픽 메모리 값 인상.
5. **흔한 오해와 광고 용어**: 이름과 실제 효과가 다른 것을 찾는다. 예: NPU·TOPS·‘AI PC’·‘게이밍’, 같은 이름의 노트북용 그래픽.
6. **필요 없는 경우**: 사람들이 괜히 돈을 쓰는 경우를 찾는다. 예: 웹 AI만 쓰는데 외장 그래픽.
7. **직접 확인하는 법**: 사용자가 자기 기기에서 확인하는 경로를 적는다.
8. **쓰지 않은 것과 이유**: 원문을 못 연 숫자, 매일 바뀌는 가격 등을 적는다.

기준:
- 숫자에는 출처가 있어야 한다. 우선순위는 공식 → 보도·커뮤니티 → 공개 숫자로 한 SYNK 계산이다. 공식이 없으면 그렇다고 표시하고 쓴다.
- 결정 요소마다 적어도 공식 자료 1개, 오해·함정 1개를 찾는다. 가격이 있는 주제라면 가격 요인도 1개 이상 찾는다.
- 검색은 제작일 날짜를 넣어 한다. 공식 문서는 원문을 열어 숫자를 대조한다. 요약 결과만 믿지 않는다.
- ‘이 기능은 새 부품이 필요하다’는 자료는 기능 전체인지 일부인지 원문으로 가른다. 예: 윈도우 실시간 자막은 모든 윈도우 11에서 되고, 번역만 코파일럿+ PC(NPU)가 필요하다(2026-09-28 확인).

## 2. 추천 기준 · `<도구>/추천기준.md`

- 사용자 결정(예: 가성비 우선, 무거우면 데스크톱)을 날짜와 함께 맨 위에 둔다.
- 원칙, 갈림길 결정표(예: 작업 무게 × 들고 다니는 정도), 부품별 기준표(공식 최소 / 가성비 / 여유), 실제로 살 수 있는 단계를 적는다.
- 결과 화면의 순서를 적는다.
- 시험으로 지킬 약속을 적는다. 대표 상황마다 기대 결과를 한 줄씩 쓴다.

## 3. 팁 은행 · `content.js`의 `TIPS`와 `COMPONENTS`

부품마다 아래 여섯 종류를 채운다. `COMPONENTS`에 부품별로 꼭 필요한 종류를 적고, 팁 카드의 `covers`로 채운다.

| 종류 | 담는 것 | 예(컴퓨터 추천) |
|---|---|---|
| 무엇인가 | 쉬운 비유 한 줄 | 램 = 작업 책상, 그래픽카드 = 단순 계산 일꾼 수천 명 |
| 왜 필요한가 | 내 용도에서 하는 일 | AI는 모델이 그래픽 메모리에 통째로 들어가야 빠르다 |
| 왜 비싼가 | 값을 정하는 원인과 최신 숫자 | HBM은 같은 1GB에 웨이퍼 약 3배, 그래픽카드 시세 대 출시가 |
| 필요 없는 경우 | 돈을 아끼는 판단 | 웹 AI만 쓰면 외장 그래픽 불필요 |
| 함정·광고 용어 | 이름과 실제가 다른 것 | NPU·TOPS, 번역 자막은 영어·중국어로만, 노트북용 RTX 5070 |
| 직접 확인하는 법 | 사용자가 따라 할 경로 | 작업 관리자 → 성능 → 메모리 |

쓰는 법:
- 한 카드는 2~4문단이다. 쉬운 비유, 출처가 있는 구체적인 숫자, “그래서 나는”으로 끝낸다.
- 질문마다 ‘왜 묻는지’ 팁을 붙이고, 선택지마다 고른 뒤 보일 한 줄을 붙인다.
- **개인화**: 계산 규칙이 사람마다 보여 줄 팁을 고른다. 외장 그래픽이 필요하면 ‘왜 필요·왜 비싼지’를, 필요 없으면 ‘아끼는 이유’를 보여 준다. 결과에는 부품마다 ‘의미 있음 / 차이 없음’을 그 사람 기준으로 적는다(NPU 카드처럼).

## 4. 계산 규칙 · `rules.js`

- 순수 함수로 쓴다. 네트워크·AI 호출·기록이 없다.
- 이유마다 출처 id를 단다. 결론은 ‘가성비 추천’과 ‘여유가 되면’ 두 줄로 낸다.
- 매일 바뀌는 정보(오늘 가격·판매 모델)는 계산하지 않는다. 결과 프롬프트에 담아 사용자의 AI에게 넘긴다.

## 5. 자동 검사

- `core/content-check.js`는 다섯 가지를 확인한다. 질문마다 팁이 있는지, 선택지마다 한 줄이 있는지, 부품별 필수 팁 종류가 다 있는지, 출처 형식이 맞는지, 숫자가 든 팁에 공식·보도 출처가 있는지다.
- `build.mjs`는 탐색노트·추천기준이 없거나 검사에서 빠진 곳이 있으면 **빌드를 멈춘다**.
- `<도구>/rules.test.js`는 추천기준의 약속과 ‘결과가 고른 팁이 은행에 있는지’를 시험한다.

## 6. 화면 확인

- 데스크톱과 휴대폰(375px)에서 가로 넘침이 없는지 본다.
- 처음부터 결과까지 모든 갈래를 눌러 본다.
- 새로고침 뒤 기억, 기록 지우기, 복사가 막힌 브라우저에서의 대비 상자를 확인한다.
- 캡처로 결과를 남기고, 확인하지 못한 것은 보고에 적는다.
- 화면 디자인은 [펠트 스크랩북 양식](../../디자인/펠트스크랩북/README.md)을 따른다(2026-09-29 사용자 확정). 공통 부품은 `docs/디자인/펠트스크랩북/scrapbook.css`, 도구 전용 화면은 `core/wizard.css`에 있고 빌드가 둘을 합친다. 새 도구는 첫 화면 콜라주(승인 펠트 그림 + `sticker-*` 스티커), 결과 머리(검은 화면·날짜 도장·대표 그림 하나), 요청문 창 하나(`copybox main`), 하단 바를 같은 방식으로 쓴다. 새 유행을 더할 때는 레퍼런스를 조사하고 양식 README ‘근거’에 근거와 날짜를 남긴다.
- 공통 부품을 고친 뒤에는 두 도구를 다시 빌드하고, 고치기 전 캡처와 픽셀로 비교한다.

## 7. 배포와 다시 확인

- synk.im 배포는 사용자 승인 뒤에만 한다. 절차는 [README](README.md#쓰는-법)에 있다.
- 탐색노트의 ‘다시 확인할 때’ 주기(보통 분기)에 가격·사양·정책을 다시 확인한다. 바뀌면 탐색노트 → content.js → rules.js → 시험 순서로 고친다.

## 8. 콘텐츠와 연결

- 피드의 마지막 장에서 도구로 이어 준다(댓글 키워드 → DM).
- 게시 문구·DM 문구·유튜브 고정 댓글은 `<도구>/게시연결.md`에 둔다.
- 도구 안의 팁은 다음 피드의 소재가 된다. 예: ‘NPU는 LLM에 차이 없음’은 그대로 한 편의 훅이 된다.

## 새 도구를 시작할 때 만드는 파일

```
<도구>/탐색노트.md   1단계 결과(사실 표 · 흔한 오해 · 팁으로 쓴 곳 · 쓰지 않은 것 · 다시 확인할 때)
<도구>/추천기준.md   2단계(사용자 결정 · 원칙 · 결정표 · 기준표 · 결과 순서 · 시험 약속)
<도구>/content.js    질문·선택지·팁 은행(TIPS·COMPONENTS)·출처(SOURCES)
<도구>/rules.js      계산 · 사람마다 고르는 팁 id
<도구>/view.js       결과 화면
<도구>/rules.test.js 약속 시험 + checkContent + checkTipIds
<도구>/게시연결.md   피드·DM·유튜브 연결
```
