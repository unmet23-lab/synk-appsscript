# 업종 반응 브리핑 도구 — 설계

> 2026-10-30 유호님 「도구 먼저」 — 10-30 견본([README](README.md))을 손으로 만든 과정을, 업종 설정 하나로 끝까지 도는 도구로 굳힌다. 큰 기능이라 만들기 전에 Fable 설계 검토를 받는다(운영 원칙 「큰 기능의 설계 검토」).

## 목적과 성공 기준

PULSE가 상담 전에 클라이언트 업종을 미리 알고 들어가고, 클라이언트에게 첫 선물로 주는 「업종 반응 브리핑」 한 장을 사람 손 없이 만든다. 회사 LLM은 따로 만들지 않는다 — 숫자는 코드가 세고, Claude(API 크레딧)는 나누기와 글만 한다.

1. (1a) 원자료와 나눈 결과(`나누기.json`)가 같으면 지표와 페이지가 바이트까지 같다 — `브리핑.js 검사`와 시험으로 고정. (1b) 여성 아우터로 새로 돌린 결론을 사람이 10-30 견본과 견준다.
2. 새 업종 하나가 설정만 바꿔 끝까지 나온다.
3. 페이지의 모든 숫자는 집계값에서 온다. Claude가 쓴 글에는 숫자를 직접 못 쓴다(자리표시자만, 검사로 막음).
4. 자료 한 갈래가 막혀도 나머지로 페이지가 나오고, 막힌 칸은 「이번엔 못 읽음」으로 보인다.

## 쓰는 법

```
node tools/업종브리핑/브리핑.js 새업종 "<업종 이름>"                     설정 초안(Claude) → .tmp/업종브리핑/_설정초안/(git 밖), 확인 뒤 설정/로 옮김
node tools/업종브리핑/브리핑.js 분류찾기 <낱말…>                          네이버 쇼핑 분류 id 찾기(ego, 처음 한 번 분류 나무를 받아 둔다)
node tools/업종브리핑/브리핑.js 돌리기 <설정 이름> [--받는사람 "…"] [--날짜 YYYY-MM-DD] [--다시 <단계>] [--건너뛰기 네이버,메타] [--한도무시]
node tools/업종브리핑/브리핑.js 검사 <설정 이름> [--날짜 …]                네트워크 없이 다시 세어 지표 · 글 · 페이지 대조
```

결과는 `<공용 작업본>/.tmp/업종브리핑/<설정 이름>/<날짜>/`(git 밖)에 단계마다 남고, 이미 끝난 단계는 건너뛴다. 마지막에 `브리핑.html` 한 장. 게시(아티팩트)나 클라이언트 전달은 도구 밖에서 한다 — 남에게 보내기는 유호님 승인.

## 단계

| 단계 | 하는 일 | 방법 | 출력 |
|---|---|---|---|
| 유튜브 | 검색어(12개 안쪽)로 기간 안 쇼츠를 찾고, 채널 평소 조회로 튄 편을 고르고, 상위 댓글을 받는다 | YouTube Data API — 수요 스캔의 `API부르개`(기록·한도 멈춤)와 `평소배수` 계산을 그대로 쓴다. search 100단위 × n, 나머지 1단위. 튄 편 판정은 수요 스캔 규칙(평소 30편 중앙값 3배 이상, 또는 구독 3만 이하 채널에서 조회 ≥ 구독). 설정의 제외 낱말(예: 남성)로 거른다 | `유튜브.json`, `댓글/<id>.json`(쓴 사람 없음) |
| 네이버 | 검색어 묶음(5개 안쪽)의 3년 검색 흐름, 쇼핑 분류의 인기 검색어(월·주·연령·하위 분야)와 연령·기기 비중, 하위 분야 주별 클릭 | ego에서 데이터랩 쪽을 열고 `page.fetch` · `qcHash` → 결과 그래프 점 읽기([현장 노트](../../현장노트/수집_yt-dlp.md#네이버-데이터랩)). 수요 스캔 `릴스.js`처럼 `ego-browser nodejs`에 일감을 넘긴다 | `네이버.json` |
| 메타 | 검색어(3개 안쪽)로 지금 도는 광고를 노출 순으로 | ego, 본문을 「라이브러리 ID」로 자른다 | `광고.json`(광고주·시작일·일수·문구 앞 200자) |
| 나누기 | 댓글 · 영상 제목 · 광고 문구를 주제로 나눈다 | Claude Opus 5.5, effort low, 구조화 출력(주제는 목록 안 값만). 100개씩. 주제 목록 = 업종 공통(정보 요청, 가격, 구매 의도, 품질 걱정, 나이, 비교, 이것만 사라 등) + 설정의 업종 고유 주제(옷이면 키·사이즈·핏) | `나누기.json` |
| 집계 | 위 셋으로 이름 붙은 숫자 꾸러미를 만든다 | 순수 함수: 각도별·길이별 튄 비율, 댓글 주제 비율·좋아요, 광고 주제 비율·테무 같은 묶음 비율·가장 오래 돈 광고, 연령 비중·40·50대 같은 합, 검색 정점 주·작년 같은 주 대비 | `지표.json` — `{이름: {값, 단위, 출처, 설명}}` |
| 글 | 한 줄 요약, 고객이 가려워하는 곳 셋(근거 지표 이름), PULSE 제안 셋, 언제·누가 문장, 댓글 예시 뜻 옮김 | Claude Opus 5.5, effort high, 구조화 출력. 숫자는 `{{지표이름}}` 자리표시자로만 쓴다. 아라비아 숫자가 글에 있거나 모르는 지표 이름을 쓰면 거부하고 까닭을 붙여 한 번 다시 받는다. 댓글 원문을 12자 넘게 그대로 옮기면 거부 | `글.json` |
| 그리기 | 지표와 글로 한 장짜리 페이지 | 순수 함수: 정적 HTML + 인라인 SVG(막대 · 선), 밝음 · 어둠 토큰, 칸마다 출처 줄. 자리표시자는 지표 값으로 채운다 | `브리핑.html` |

자료가 막히면(ego 없음 · 한도 · 로그인 벽) 그 단계는 `{상태: '못 읽음', 까닭}`을 남기고 다음으로 간다. 집계·글·그리기는 있는 지표만 쓴다 — 글 단계에는 쓸 수 있는 지표 목록만 넘기므로 없는 칸을 근거로 못 든다.

## 설정 한 장(예: 여성 겨울 아우터)

`이름` · `업종` · `유튜브.창일`(기준일에서 거꾸로 며칠) · `유튜브.검색어[]` · `유튜브.제외낱말[]` · `유튜브.최소조회` · `네이버.검색어묶음[{이름, 낱말[]}]` · `네이버.성별` · `네이버.분류{cid, 이름, 하위[{이름, cid}]}` · `메타.검색어[]` · `메타.플랫폼낱말[]` · `주제.댓글고유[{이름, 설명, 낱말?}]` · `주제.영상고유[]` · `제안관점`(PULSE가 이 업종에 줄 수 있는 것 — 예: 나이·체형별 AI 모델 착용).

`새업종`은 Claude가 업종 이름과 받는 사람으로 이 칸들의 초안을 쓰고(검색어 · 고유 주제 · 메타 검색어), 네이버 분류는 `분류찾기`로 찾은 후보를 붙여 둔다. 초안은 그대로 돌리지 않고 확인 뒤 `돌리기`.

## 시험 계획

- 단위(`node --test tests/업종브리핑.test.js`, 네트워크 없음): 튄 편 판정, 하루 값 → 주 평균 → 해마다 정점, 연령 비중 합, 주제 집계, 자리표시자 채우기와 숫자 · 모르는 이름 · 긴 인용 거부, SVG 막대 좌표가 칸 안인지, HTML이 모든 자리를 채우는지.
- 재현: 10-30 시험 원자료(git 밖 scratch)를 넣어 집계하면 견본과 같은 지표(73% · 84% · 18% · 1% 등)가 나오는지 — 나누기는 그때 정규식이었으니 주제 비율은 근사로 본다.
- 끝까지: 여성 아우터로 한 번, 새 업종(예: 스킨케어)으로 한 번. 페이지를 1440 · 390 폭으로 열어 넘침 · 깨진 그림을 본다.

## Fable 설계 검토(10-30) — 19건, 반영 17

판정 「고쳐서 만들기」(방향은 맞음). 반영한 것:

- **단계 무효화(P1):** 어느 단계든 새로 돌면 그 뒤 단계는 모두 다시 돈다 — 옛 지표·페이지와 섞이지 않는다. 나누기는 (모델·종류·주제 목록·글) 지문 캐시라 다시 돌려도 새 글만 부른다.
- **숫자 금지와 글 실패 뒤 길(P1):** 숫자가 든 이름표는 문자 지표로 준다(`쇼핑.주연령`=「40·50대」, `영상.잘튀는길이`=「30초 이하」, `영상.시작일`). 글이 세 번 검사에 걸리거나 거절되면 숫자만 담은 페이지를 내고 「까닭」을 적는다. 거절은 다시 보내지 않는다.
- **계절·연령 일반화(P1):** 정점은 기준일 앞뒤 반년 창을 세 해 거슬러 구하고(8~3월 같은 상수 없음), 작년 같은 주는 364일 전. 강조 연령은 비중 상위 둘(설정 `네이버.강조연령`으로 바꿀 수 있음), 연령별 순위는 10~60대 다.
- **유튜브 몫(P1):** 같은 날 검색 결과를 실행 폴더에 두어 다시 돌릴 때 search를 다시 안 부르고, 돌리기 전에 어림을 보이며, 이 도구 몫은 태평양 날짜 하루 3,000단위까지(장부 `.tmp/업종브리핑/_유튜브단위.jsonl`, `--한도무시`로만 넘김). 검색이 도중에 멈추면 「검색어 N개 가운데 M개」를 페이지에 적는다.
- **받는 사람은 git 밖(P1):** 설정에는 업종 몫만. 받는 사람은 `--받는사람`이나 `.tmp/업종브리핑/<이름>/받는사람.json`. `새업종` 초안도 `.tmp/업종브리핑/_설정초안/`에 쓰고 확인 뒤 옮긴다.
- **ego 멈춤(P1):** 단계마다 시간 상한(네이버 10분 · 메타 6분), 넘으면 프로세스 나무를 끝내고(taskkill /T) ego 스크립트가 갈래마다 바로 써 둔 만큼만 쓴다. 데이터랩 「접근 오류」 쪽은 첫 응답에서 못 읽음으로.
- **재현(P2):** 성공 기준 1을 둘로 — 1a 원자료와 나누기.json이 같으면 지표와 페이지가 바이트까지 같다(`브리핑.js 검사`와 시험), 1b 새로 돌린 결론은 사람이 견본과 견준다. 10-30 원자료는 git 밖 실행 폴더로 옮겨 두었다.
- **나누기 실패(P2):** 거절 · 잘림 · 형식 틀림은 반으로 쪼개 다시, 끝내 안 되면 낱말 규칙으로 나누고 그 수를 페이지에 밝힌다(키 소진 때도 페이지는 나온다).
- **예시 · 근거(P2·P3):** 예시는 댓글 키로만 고르고 좋아요 · 주소는 자료에서 붙인다(모르는 키는 버림). 가려운 곳마다 근거 지표를 값과 함께 보인다.
- **메타(P2):** 영어 화면 날짜도 읽고, 시작일을 절반 넘게 못 읽으면 기간 지표를 뺀다. 업종 판매 앱은 설정 `메타.플랫폼낱말`로 더한다.
- **검색 환산 · 성별(P2):** 눈금을 매번 읽어 환산하고 쓴 성별을 남긴다. 지표는 비율만(정점 범위 · 작년 대비).
- **평소 기준(P3):** 그 편을 뺀 채널 최근 쇼츠 30편의 중앙값(뜨는원본.js와 같다). 10-30 손 시험은 그 편을 넣었다.
- **페이지에 싣는 남의 자료(P3):** 영상 제목 · 채널명 · 구독 · 조회 · 주소 · 광고주 이름 · 게재 일수까지. 댓글 원문 · 광고 문구 · 쓴 사람 · 영상 설명은 페이지와 저장소 어디에도 싣지 않는다.
- **고객에게 줄 첫 페이지(P3):** 도구는 내부 도구라 시험 · 자기 점검으로 끝내되, 실제 고객에게 처음 보내는 페이지는 화면 검수(아르곤 → Fable 조건부)를 한 번 받는다.

반영하지 않은 것: 다른 도구와 함께 쓰는 유튜브 공용 장부(업로드 · 수요 스캔까지 고쳐야 해서 이 도구 몫 상한으로 대신), 근거 지표의 방향 대조(사람이 근거 줄을 본다).

## 위험

- 네이버 · 메타는 ego가 떠 있어야 한다 — 없으면 그 칸만 빠진다. 네이버 내부 주소가 바뀌면 깨진다(현장 노트로 고친다).
- 비용: 유튜브 하루 몫 1만 단위 가운데 1,500 안팎(같은 날 수요 스캔 300과 나눠 씀), Claude는 무료 크레딧 키 — 나누기 10번 안팎(low) + 글 1~2번(high).
- 남의 댓글 원문은 git 밖 실행 폴더에만 두고, 페이지에는 뜻 옮김만 싣는다.
- 클라이언트에게 보내는 일은 도구가 하지 않는다.
