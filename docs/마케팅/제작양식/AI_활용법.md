# AI 활용법 · 유형별 제작 양식

[전체 목차](../콘텐츠_제작양식.md) · 2026-09-22 분리 · 첫 편을 함께 다듬는 중.

**시각(2026-10-01):** 표지·카드·썸네일·설명 장면·영상 위 글자는 [SNS 제작 키트](../../디자인/SNS키트/README.md)에서 출발한다. 테마 `brief`(청금석), 견본 [광고 세 컷](../../디자인/SNS키트/견본/brief_광고세컷/). 흰 바탕에 파란 강조만 있던 기존 틀은 새 편부터 쓰지 않는다.

이 유형은 AI 도구로 자기 작업의 결과를 만드는 과정을 보여준다. 새 기능 소식이나 도구 비교가 주목적인 콘텐츠는 각각 별도 유형으로 발전시킨다. 채널 대상·언어는 [채널과 발행](../채널과_발행.md)이 담당한다.

## 1. 확정된 피드백과 현재 상태

| 항목 | 현재 기록 |
|---|---|
| 사용자가 정한 방향 | 콘텐츠 유형별 양식을 따로 설정하고, 한 편씩 함께 다듬어 다음 제작에 재사용한다. |
| 이 유형에 받은 피드백 | 처음에 시청자가 겪는 구체적인 상황을 알려준다. 처음 보는 사람도 이해하고 따라 할 수 있게 훨씬 상세히 설명한다. |
| 영상 품질 우선순위 | 2026-09-22 사용자는 영상 하나하나 최상위 품질을 원한다고 명시했다. 이해도·요약·임팩트·디자인·여백·모션·소리와 최종 편집을 함께 다듬고 실제 결과로 확인한다. |
| 자료·설명 이미지 | 매편 실제 제작일 기준으로 관련 자료·사례를 조사해 설명과 장면에 반영한다. 이해를 돕는 이미지는 GPT Image 2.5 활용을 우선 검토해 적극 제작한다. [공통 기준·실제 모델 확인](../채널과_발행.md#매편-자료-조사와-설명용-이미지)을 따른다. |
| 작업 중인 첫 편 | 두서없는 메모·음성 전사 기록을 읽기 쉬운 회의록으로 정리하기 |
| 제작 상태 | 2026-09-24 v18: 159.70초·23장면·자막 53개. 차분하고 부드러운 여성 내레이션(Typecast 은경), Suno BGM·효과음, 11쪽 PDF·자료 ZIP. 팔로우·댓글 엔딩과 공개 자료 페이지를 준비했으며 사용자 최종 검토 및 발행 전. |
| 아직 정하지 않은 것 | 목소리·BGM, 기본 길이·설명 속도, 출연 방식 등. 시각 디자인은 2026-10-01 확정된 SNS 제작 키트(`brief` 테마)를 따른다 |

사용자가 예로 든 ‘내 목소리를 AI로 만들 때 어떻게 해야 하는지 모르시나요?’는 구체적인 상황을 제시하는 도입 예시다. 이번 회차의 주제를 음성 복제로 바꾼 지시가 아니며, 모든 도입을 같은 질문 문장으로 고정하지 않는다.

### 2026-09-23 추가 확정: 저장 범위와 반복 사용

- 반복 업무는 지침을 어디에 저장하고 다음에 어떻게 다시 쓰는지까지 설명한다. 프로젝트별 규칙과 계정 전체 맞춤 지침을 구분한다.
- 이번 회의 지침은 각 프로젝트의 `⋯ → 프로젝트 설정 → 지침`에 저장한다. 계정 전체에 넣으면 글쓰기·여행 등 다른 대화에도 회의 전용 규칙이 영향을 줄 수 있으므로 넣지 말라고 이유와 가상 예시를 함께 설명한다. 계정 전체 지침 기능 자체를 일반적으로 금지하는 뜻은 아니다.
- 새 회의는 같은 프로젝트의 새 채팅, 같은 회의의 보완은 기존 채팅. 저장 확인·원문 대조·누락 시 짧은 보완 요청을 제공한다. 프로젝트 전용 메모리는 같은 프로젝트 내 채팅까지 격리하는 기능이 아니다.
- 사용자 후속 요청으로 템포와 설명을 돕는 애니메이션을 강화하고 보유 Suno BGM을 사용한다. 현재 v17은 사용자가 요청한 차분하고 부드러운 여성 내레이션·BGM·효과음을 포함한다. 과거 무음 결정은 이전 검토본 이력으로 남긴다.
- 현재 제작 파일: [v17 전체 배치 재디자인](../synkbrief_회의메모_20260921/video-v17/README.md), [11쪽 PDF와 복사용 파일](../synkbrief_회의메모_20260921/follow-along-v15/README.md). 159.47초·23장면은 이번 편의 구현이며 모든 회차에 강제하지 않는다.

## 2. 이 유형에서 개별 설정할 항목

아래 설정은 현재 작업에서 발전시키는 기준이다. 사용자 피드백과 검토 중인 구현을 구분하며, 첫 편의 숫자·디자인을 자동으로 기본값으로 삼지 않는다.

| 항목 | 현재 방향·구현 | 다음 편에서 확인하거나 바꿀 것 |
|---|---|---|
| 시청자와 상황 | 해당 도구를 처음 따라 쓰는 사람이 겪는 구체적인 작업 문제부터 설명 | 누구의 어떤 불편을 해결하는지, 사전 지식은 어느 정도인지 |
| 얻을 결과 | 같은 원본 메모가 요약·결정·할 일·확인할 내용으로 나뉜 모습 | 시청자가 무엇을 만들고 어디에 쓸 수 있는지 |
| 도입 | 메모는 있는데 누가 언제까지 무엇을 할지 다시 찾는 상황 | 소재에 맞는 상황과 표현. 질문형 문구 자체는 고정하지 않음 |
| 설명 순서 | 구체적인 불편과 결과 → 프로그램·준비 → 입력 위치·정확한 입력 → 단계별 필요한 이유 → 실행 → 결과 검증·업무 적용 → 제공 자료 | 처음 보는 사람이 각 행동을 그대로 재현하고 왜 필요한지 설명할 수 있는지 |
| 화면 | 실제 입력창 전체에서 위치를 짚고 필요한 부분을 확대 | 그 도구의 실제 화면·클릭 위치·입력 내용. 캡처 편집과 연속 녹화 구분 |
| 예시와 근거 | 직접 만든 가상 메모와 실제 AI 응답을 대조 | 회차별 예시·관찰한 결과·출처·날짜. 이전 결과를 새 시연으로 재사용하지 않음 |

| 자막과 리듬 | 불필요한 대기·전환을 줄여 약간 빠른 템포. 현재 행동과 그 이유를 같은 장면에서 설명 | 위치·입력·결과를 읽을 시간을 남기고 세부 재현은 제공 자료로 연결 |

| 마무리 | 실제 가이드 PDF·복사용 입력문·연습 메모를 보여주고 “필요하시면 팔로우하시고, 댓글에 synk를 남겨주세요”로 연결 | 효용·자료 구성·받는 행동, 다운로드/전달 경로가 실제로 준비됐는지 |
| 배포 | synkbrief의 YouTube·Instagram·TikTok용 공통 영상과 문안 | 매체별 제목·설명·표지·링크. 같은 내용을 채널마다 새 유형으로 나누지 않음 |

회차마다 새 주제·도구·메모·프롬프트·실제 결과를 준비한다. 유형 문서에는 재사용할 설정을, 해당 편의 원고와 폴더에는 구체적인 내용과 파일을 둔다.

## 3. 첫 편에서 검토 중인 전개

| 단계 | 시청자가 이해할 내용 | 현재 예시 |
|---|---|---|
| 상황 | 지금 내게 필요한 영상인지 | 메모를 다시 읽으며 누가 언제까지 뭘 하기로 했는지 찾는 상황 |
| 결과 | 끝까지 따라 하면 무엇을 얻는지 | 할 일·담당자·기한이 있는 표 |
| 준비 | 시작하기 전에 무엇이 필요한지 | 텍스트 회의 메모와 ChatGPT |
| 실행 | 어디에 무엇을 넣고 어떻게 보내는지 | 입력문 전체 붙이기 → 메모 자리만 교체 → 같은 입력창에서 한 번에 보내기 |
| 결과 이해 | 왜 이런 값이나 빈칸이 나왔는지 | 지수의 기한은 명시돼 있지만 민호의 마감은 아직 정하지 않았음 |
| 확인 | 그대로 쓰기 전에 무엇을 대조하는지 | 근거 문장과 원문. 다음 회의 날짜와 작업 마감, 제안과 확정된 일 구분 |
| 다음 행동 | 자기 일에 어떻게 적용하는지 | 복사용 입력문을 자신의 메모로 바꾸고 빠진 기한을 참여자에게 묻기 |

이 흐름 전체는 현재 검토 중이다. 후속 피드백이 들어오면 첫 편에 반영하고, 다른 활용법에도 유효한 요소만 이 양식에 남긴다.

2026-09-22 후속 확정: 매 단계에는 `보이는 실제 화면 / 따라 할 행동 / 필요한 이유 / 성공했을 때 모습`이 있어야 한다. 이번 편은 [수정 원고](../synkbrief_회의메모_20260921/원고.md)를 따른다. 기존 v3의 15초 상황·변환 모션만으로 활용법 설명이 완성됐다고 간주하지 않는다.

제공 자료는 [이번 편 패키지](../synkbrief_회의메모_20260921/follow-along/README.md)처럼 준비물, 단계, 복사용 입력, 예시, 결과 검토, 자주 막히는 지점과 해결법을 포함한다. 자료 실물의 미리보기를 엔딩에 쓰고 다음 회차도 실제 파일을 함께 완성한다.

## 4. 실제로 확인할 것

- 처음 보는 사람이 입력 위치, 넣을 내용, 보내는 순서를 알아볼 수 있는지.
- 예시 원문·실제 응답·설명 자막이 맞는지. 큰 요약 글자와 실제 UI·AI 응답을 구별할 수 있는지.
- 휴대폰 크기에서 중요한 글자와 화면을 읽을 수 있는지. 음성이 생기면 발화와 자막·화면이 맞는지.
- 안내한 입력문·자료를 게시 문안이나 연결한 파일에서 실제로 받을 수 있는지.

검수 통과·파일 완성·사용자 구성 확정·외부 게시는 서로 다른 상태로 기록한다. 새 소재의 사실과 사용 조건은 그때의 근거로 확인한다.

## 6. 다음 편에 이어 쓰기

확정된 설정과 대표작을 읽고 새 주제에 필요한 내용만 교체한다. 같은 유형의 기존 결정을 매번 되묻지 않는다. 진행 중인 회차에서 수정한 사항은 회차 원고에 먼저 반영하고, 이후 편에도 유지할 사항만 날짜·이유·예시 링크와 함께 이 문서에서 갱신한다.

## 2026-09-23 추가 확정 · 익숙한 행동부터 설명

초보자에게는 기능 이름보다 평소 하던 행동에서 시작한다. 이번 편은 컴퓨터·메모장에 회의 내용을 적는 상황 → 녹음을 글로 바꾼 기록과 직접 쓴 메모가 같은 정리 경로를 쓴다는 설명 → 복사·입력·메모 자리 교체·전송·결과 해석 → 반복 입력이 번거로워진 다음 프로젝트 저장 순서다. 지침은 정리 규칙, 프로젝트는 회의 전용 폴더처럼 설명하며 처음 쓰는 요청문과 저장용 지침 파일을 구분한다. 다른 유형에 이 회의 장면이나 길이를 강제하지 않는다.


## 2026-09-23 추가 확정 · 행동 지목과 같은 원문 전후 비교

- 시청자에게 AI가 할 정리를 미리 시키지 않는다. 기록은 그대로 넣고, 중요한 이름·날짜 확인은 결과 뒤에 배치한다.
- ‘이 칸’처럼 모호하게 말하지 않는다. 실제 화면의 클릭 위치를 테두리·화살표·커서로 직접 지목한다.
- 내부 파일명부터 소개하지 않는다. AI에게 보낼 문장을 화면에 바로 보여주고, 제공 파일 이름도 역할이 드러나는 한국어로 쓴다.
- 요청과 자료를 함께 보낼 때는 무엇을 어디에 넣는지 풀어 설명한다. 회의 편은 ‘AI에게 부탁할 문장 + 직접 쓴 메모 또는 녹음을 글로 옮긴 내용’이다.
- 효과 설명에는 같은 원본과 정리 결과를 함께 보여준다. 무엇이 바뀌었는지 항목·강조색으로 연결한다. 편집 요약과 실제 응답 원문을 구분하고 전체는 가이드에 담는다.
- 같은 흐름의 실제 PDF와 복사용 파일을 영상과 함께 갱신한다. 대표 영상의 최종 디자인 승인과 초보자 이해도 검증은 별도다.


## 2026-09-23 추가 확정 · 실제 UI의 위치부터 확대하기

ChatGPT 등 프로그램의 입력·설정 설명은 확대된 부분만 갑자기 보여주지 않는다. 전체 화면을 잠깐 보여줘 위치를 잡은 뒤 조작할 영역을 표시하고, 같은 화면을 부드럽게 확대한다. 커서가 실제 클릭할 곳으로 이동하고 클릭·붙여넣기 반응이 보이게 한다. 이어서 다른 버튼을 눌러야 하면 화면을 따라 이동하고 마지막에 전체 위치를 다시 확인한다. 효과 자체보다 어느 버튼·입력란·단락인지 이해하는 것이 목적이다. 검토본 v10에 8개 ChatGPT 조작 장면으로 구현했으며 최종 디자인 승인을 뜻하지 않는다.

## 2026-09-23 추가 확정: 기능의 뜻부터 설명하기

초보자가 처음 만나는 기능은 버튼 위치를 안내하기 전에 쉬운 정의, 익숙한 비유, 안에 들어가는 것, 쓰는 이유를 짧게 보여준다. 이번 편의 프로젝트는 같은 업무의 대화·자료·지침을 모아두는 작업 공간이며 ‘회의 전용 폴더’로 설명한다. 그 안의 채팅은 한 회의의 대화, 지침은 그 안에서 쓸 정리 규칙으로 구분한다. 개념 설명을 영상과 제공 가이드에 함께 반영한다. v11의 길이·화면 디자인을 모든 편의 고정 양식으로 삼지는 않는다.

## 2026-09-23 이번 편의 음성 방향

사용자는 차분하고 부드러운 여성 목소리를 요청했다. v12는 Typecast 은경 tonedown 0.5로 합성했다. 자연스러운 말하기 속도에 맞춰 장면을 늘리고 낭독 타이밍으로 자막과 클릭을 맞췄다. 음색의 최종 승인은 아직 받지 않았다. 2026-10-03 유호님이 여자 목소리를 Typecast 서현·혜리 둘로 정해(「여자는 컨텐츠 특성에 따라서 둘 중 하나」, 「서현이나 혜리로 바꿔」) 새 편부터는 은경 대신 이 둘 가운데 고른다 — 차분하고 부드러운 설명은 서현.

## 2026-09-23 이번 편에서 검토 중 · 문맥마다 행동 보여주기

‘같은 프로젝트를 열고 새 채팅에 새 메모를 보낸다’처럼 한 문장에 여러 행동을 압축하면 초보자는 다음 클릭을 놓치기 쉽다. v15 검토본에서는 `프로젝트 메뉴 누르기 → 저장한 프로젝트 열기 → 새 채팅 누르기 → 이번 기록 입력 → 보내기`를 화면·제목·클릭 반응이 각각 있는 다섯 장면으로 나눴다. 음성이 말하는 ‘부탁할 문장’과 ‘오늘 기록’도 입력창에 차례로 나타난다. 이후 다른 활용법에도 적용할지는 이번 편의 시청자 검토 뒤 결정한다.

## 2026-09-24 이번 편의 화면 마감 피드백

UI 확대 안내에서 두꺼운 테두리·그림자·클릭 색을 겹치지 않는다. 초점선은 얇게 유지하고, 다른 버튼으로 옮겨갈 때 선을 늘려 찌그러뜨리지 않고 해당 버튼 위치에 다시 표시한다. 확대 배율은 메뉴 글자가 거칠어지지 않을 만큼으로 제한한다. 반복하는 보조 문구는 짧게 줄이되, `전체 화면 → 위치 확대 → 누를 곳`의 순서와 시청자가 다음에 해야 할 행동은 남긴다. v16에서 검토 중이며 다른 편의 고정 규칙 여부는 사용자 검토 뒤 결정한다.

## 2026-09-24 이번 편에서 검토 중 · 불필요한 여백 줄이기

사용자는 v16의 설명·화면·자막 사이가 너무 멀어 부자연스럽다고 평가했다. v17은 23장면 전체를 다시 배치해 관련 설명과 예시를 같은 묶음에 넣는다. 짧은 설명에 큰 고정 높이를 강제하지 않고, 원본 메모와 정리 결과는 읽기 좋은 크기로 보여준다. 녹음 안내는 녹음 카드 안에, 클릭 행동은 실제 화면 바로 아래에 붙인다. 설명 도식·UI 시연·전후 비교·자료 안내에 각기 맞는 구성을 사용한다. 여백을 장식으로 채우거나 초보자가 필요한 단계를 생략하지 않는다. 구체적인 수치와 배치는 검토 중이며 다른 편의 고정 템플릿으로 확정하지 않는다.

## 2026-09-27 세팅 · 결과 먼저, 45~60초, 두 편 분할

[운영 체계](../콘텐츠_운영체계_20260927.md)의 라인 3 기준. 사용자의 “앞으로 어떻게 만들지 세팅” 요청에 따라 다음 편부터 적용한다. v19는 그대로 게시 후보로 두고, 이 기준은 다음 편과 v19 분할판에 쓴다.

- **첫 3초는 결과다.** 같은 기록의 전후 비교 카드를 첫 화면에 두고 한 문장으로 잇는다(“이 메모가, 붙여넣기 한 번에 이렇게 됩니다.”). 질문형 도입은 두 번째 문장 이후에.
- **한 편은 45~60초, 하나의 결과.** 회의록 편처럼 두 가지 일(정리하기·규칙 저장하기)이 있으면 두 편으로 나눈다. 같은 PDF·댓글 키워드로 연결한다.
- **구조:** 결과(0~3초) → 상황 한 줄(3~8초) → 준비·입력 위치(8~20초) → 실행·결과 확인(20~40초) → 내 업무 적용 한 줄(40~50초) → 자료·댓글 synk(50~60초).
- **음성·자료·엔딩·자동 DM**은 기존 확정 사항 유지(음성은 10-03부터 Typecast 서현이나 혜리 — 이전 편은 은경, 매편 PDF, 댓글 synk). 화면 안내 순서(위치→확대→클릭)도 유지하되, 판·글자·자막·전환은 2026-10-01부터 SNS 제작 키트 `brief` 테마와 모션 기준(낱말 단위 키네틱 자막, 장면 3~4초, 전환 두 가지 이상)으로 만든다.
- **측정:** 3초 홀드·완주율·저장·댓글 synk 수·DM 실수신. 4편이 쌓이면 “결과 먼저”와 길이의 효과를 확인해 이 절을 갱신한다.
