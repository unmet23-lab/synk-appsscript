# 만들고 고친 과정 1편 · 커버를 다시 배치한 이유

2026-09-22 제작본. `@yuhobuilds` YouTube·Instagram·TikTok·네이버 클립용 세로 영상 원고. 얼굴 촬영 없이 실제 수정 전후 원본과 자막, Typecast 내레이션으로 제작했다. 원고는 아래 7문장이며 영상 길이는 34.57초다. [재생 화면](preview.html)에서 확인한다. 외부 게시 전 검토본이다.

## 내레이션

커버를 다 만들었는데, 올리려니 오른쪽 소품이 잘렸어요.

비핸스 업로드 미리보기에서 보니, 원본보다 보이는 폭이 좁더라고요.

그림과 문구는 그대로 두고, 배치를 다시 잡았습니다.

로고와 글자, 소품을 조금 줄여서 가운데로 모았어요.

위쪽 메뉴에 가리지 않도록, 전체 위치도 조금 내렸고요.

다시 올린 뒤에는 실제 프로필에서 로고와 글자, 소품이 다 보이는지 확인했습니다.

이번 커버는, 만들고 나서 어디에 어떻게 보이는지까지 확인하고 마무리했어요.

## 자막과 화면

시간은 음성 길이에 맞춰 배정한다. 아래 자막의 `/`는 줄바꿈이며 낭독하지 않는다. 원본 비교 표기는 자막과 별개로 화면에서 읽히게 유지한다.

| 컷 | 표시 자막 | 실제 자료와 편집 |
|---|---|---|
| 1 | 커버를 다 만들었는데 / 오른쪽 소품이 잘렸어요 | 수정 전 소품 부분 확대. `수정 전 원본` 표시. |
| 2 | 업로드 미리보기에서는 / 보이는 폭이 더 좁았어요 | 수정 전 전체 원본에서 오른쪽 소품 위치 강조. 실제 업로드 UI로 보이게 합성하지 않는다. |
| 3 | 그림과 문구는 그대로 / 배치를 다시 잡았습니다 | 전후 원본을 같은 배율로 비교. 각각 `수정 전 원본`·`수정 후 원본` 표시. |
| 4 | 조금 줄여서 / 가운데로 모았어요 | 로고·글자·소품의 축소와 중앙 이동이 보이도록 전후 전환. 비교 부분을 같은 배율로 확대한다. |
| 5 | 메뉴에 가리지 않도록 / 위치도 조금 아래로 | 최종 묶음의 아래 이동을 설명한다. 화살표 등을 사용하면 설명용 표시로 구분한다. |
| 6 | 다시 올린 뒤 / 실제 프로필에서도 확인 | 최종 원본. 보조 표기 `9월 19일 공개 확인 기록 · 화면은 원본`. |
| 7 | 어디에 어떻게 보이는지까지 / 확인하고 마무리했어요 | 최종 커버와 `유호 · SYNK`·`@yuhobuilds`. |

전체 3200×410 원본은 세로 화면에서 작게 보이므로 전체 비교 뒤에 소품·글자 부분을 확대한다. 잘림 영역을 설명하기 위해 재현 화면을 추가한다면 `설명용 재현`으로 표시한다. 수정 전후를 실제 공개 페이지 캡처처럼 표현하지 않는다.

## 음성 제작 메모 · 내부

- 사용자 요청: **웬만하면 가장 상큼하고 감정이 들어간 보이스**. 밝고 생기 있는 한국어 프리셋을 후보로 듣고 선택한다. 단순히 속도와 높낮이만 올리기보다 문제를 발견한 반응과 수정 후의 가벼운 만족감이 자연스럽게 들리는지 확인한다.
- Typecast API Lite의 `하나 / ssfm-v30 / happy / 감정 강도 1.5`를 이번 시안에 사용했다. 원본 음성은 33.45초, 시작·마무리 여유를 포함한 영상은 34.57초다. [실제 음원](audio/narration-master.wav). 목소리의 최종 취향·발음 청음은 사용자 검토로 남긴다.
- 서비스가 제공하는 AI 프리셋 음성이다. 유호의 직접 녹음이나 본인 목소리 복제본으로 소개하지 않는다. 1인칭 문장은 실제 유호의 작업 기록을 읽는 구성이다.
- `Behance` 발음은 `비핸스`. 본문에 없는 인사나 회사 소개를 추가하지 않는다.
