# PULSE 고객 전용 인물 판 3 — 접수 · 직원 검토 · 승인 구현 설계(2026-11-10)

> [기획 12절](다국어와_고객전용인물_기획_20261108.md#12-구현-설계2026-11-09--이-절이-9·10절보다-앞선다)(11-09 Fable 설계 검토를 거친 설계)의 판 3 몫을 코드 단위로 굳힌 것이다. 새 설계 판단이 아니라 이미 검토한 설계를 잇는 일이라 따로 설계 검토를 받지 않는다(운영 원칙 「큰 기능의 설계 검토」 예외). 판 4([판 4 설계](판4_설계_20261110.md))가 기대는 꼴 — 인물 문서 · 승인 꼴 · 초대 경로 · 가드 — 은 이 문서를 따른다. 회사 코드 뿌리는 `docs/마케팅/온라인마케팅지도/engagement/company/`.
> 스위치 `pulseFeatures.personaRequest` · `personaReal`은 끈 채로 둔다. 인물 문서가 없으면 손님 응답 · 화면은 판 3 전과 바이트가 같다.

## 1. 상태와 전이(순수 함수 표 하나 — `pulse-personas.mjs` `PERSONA_FLOW`)

일곱 걸음(자료 제출 → 권한 · 제작 가능성 검토 → 견적 · 범위 확인 → 기준 얼굴 승인 → 제작 준비 → 동작 시안 승인 → 이번 광고 사용 확인)을 상태 하나씩으로 둔다. 손님 차례인 상태에는 그 승인 종류가 하나씩 붙는다.

| 상태 | 걸음 | 차례 | 손님에게 보이는 말 |
|---|---|---|---|
| `submitted` | 1 | 저희 | 보내 주신 자료를 보고 있어요 |
| `needs_materials` | 1 | 손님 | 자료를 조금 더 보내 주세요(직원의 「왜」 한 줄) |
| `rights_pending` | 2 | 저희 | 당사자 동의를 확인하고 있어요(실제 인물만) |
| `reviewing` | 2 | 저희 | 만들 수 있는지 검토하고 있어요 |
| `quote_review` | 3 | 손님 | 견적과 범위를 확인해 주세요 — 승인 `scope` |
| `reference_making` | 4 | 저희 | 기준 얼굴을 만들고 있어요 |
| `reference_review` | 4 | 손님 | 기준 얼굴을 확인해 주세요 — 승인 `reference` |
| `building` | 5 | 저희 | 인물을 준비하고 있어요(내부 학습 · 검증 · 동작 시안) |
| `motion_review` | 6 | 손님 | 움직이는 모습을 확인해 주세요 — 승인 `motion` |
| `ready` | 7 | 손님(사용 범위가 오면) | 이번 광고에 쓸지 확인해 주세요 — 승인 `usage` |
| `withdrawn` · `retired` | — | 끝 | 요청을 거뒀어요 · 사용을 마쳤어요 |

- `PERSONA_SETTLED`(판 1)는 그대로 `ready · retired · expired · withdrawn`. 판 4가 `paused` · `deleting`을 더한다.
- **직원 전이:** `request_materials{why}`(submitted · reviewing · rights_pending · needs_materials → needs_materials), `ask_rights{why}`(실제 인물만, submitted · reviewing · needs_materials → rights_pending), `start_review`(submitted · needs_materials · rights_pending → reviewing), `send_quote{price,days,revisions,scope}`(reviewing · quote_review → quote_review, 다시 보내면 견적이 바뀌어 옛 승인 대상이 사라진다), `publish_reference{revisionId,note}`(reference_making · reference_review · building · motion_review → reference_review), `publish_motion{revisionId,note}`(building · motion_review → motion_review), `withdraw{why}`(끝 아닌 상태 → withdrawn), `retire`(ready → retired). 상태를 바꾸지 않는 직원 일: `open_revision` · `remove_asset` · `set_method` · `set_name` · `note` · `set_usage`.
- **손님 승인이 넘기는 전이:** `scope` 승인 → reference_making, 고칠 점 → reviewing / `reference` 승인 → building, 고칠 점 → reference_making / `motion` 승인 → ready, 고칠 점 → building / `usage` 승인 → 상태 그대로(ready), 서버가 `castingSelection.personaRef`를 붙인다. `usage`에는 고칠 점이 없다(물음은 일지).
- 실제 인물 동의(`consent`)는 초대 세션으로 받지 않는다 — 당사자 확인 토큰의 목적 · 검증 함수만 두고 쪽은 `personaReal`을 켤 때 만든다.
- 「모두 승인」은 없다. 승인 종류마다 무엇을 확인하는지 한 문장을 카드에 둔다. 의견 칸에 글이 있으면 승인 단추가 그 의견을 먼저 보내라고 막는다(화면).

## 2. 문서(모두 `store.put` 문서 — 새 색인 · 표를 만들지 않는다: 사후 확인 스키마 관문)

- `pulsePersonas/<id>`: `{id, schemaVersion:1, workspaceId:null, originProjectId, kind:'virtual'|'real', status, revision(낙관적 잠금 정수), request:{look,use,keep,relation,consentWay}(손님 글 사본), displayName, why(손님에게 보일 한 줄), quote:{price,days,revisions,scope,at,by}|null, currentRevisionId, staffNote, createdAt, updatedAt, history:[{id,at,action,actorKind:'customer'|'staff'|'system',actor,from,to}](최근 200)}`. 프로젝트 하나에 열린 인물은 하나.
- `pulsePersonaRevisions/<id>`: `{id, personaId, number, status:'draft'|'published'|'superseded', assets:[{id,diskName,fileName,mimeType,byteSize,role:'reference'|'motion',at,by}], reference:{assetIds,note,publishedAt,publishedBy}|null, motion:{assetIds,note,publishedAt,publishedBy}|null, method:{kind:'reference'|'lora'|'other',base,note}(내부), createdAt, createdBy}`. 얼굴(정체성)이 바뀌면 새 판, 동작 시안 다시 찍기는 같은 판의 새 `motion` 묶음.
- `pulsePersonaSources/<id>`: 사진 하나에 문서 하나 `{id, personaId, projectId, purpose:'identity'|'mood', diskName, fileName, mimeType, byteSize, sha256, inline, at, by:'customer'}`. 원본은 초대 세션으로 열리지 않는다(개수 · 이름 · 목적만).
- `pulsePersonaConsents/<personaId>`: `clientRights`와 같은 틀(인물당 암호문 하나, 기록 수 = revision). 실제 인물만, 직원 편집 권한으로만 적고 읽는다.
- `pulsePersonaApprovals/<id>`: 덧붙이기만 `{id, personaId, projectId, revisionId|null, kind, decision:'approve'|'changes', note, viewedHash, shown:{assetIds}, at, actorKind:'invite', actorName, authMethod:'invite-link', locale, idempotencyKey}`.
- 프로젝트 쪽(참조와 사용 범위만): `studio.request.personaUsage={personaId,revisionId,brand,product,purpose,media,regions,period,fee,schedule,note,setAt,setBy,approvalId,approvedAt}`, 사용 승인 뒤 `studio.strategy.data.castingSelection.personaRef={personaId,revisionId}`(서버만 붙인다, 판 1 규칙).
- 파일은 `studio-media/<uuid>.<png|jpg|mp4|webm|intake>`(확장자를 늘리지 않는다). 판 1의 `PERSONA_MEDIA_KINDS`가 백업 · 복원 대조에 센다. `visibleAssetIds`에는 넣지 않는다.

## 3. `viewedHash` · 옛 판 · 중복 클릭

- 서버가 손님 보기를 만들 때 지금 손님 차례인 승인 하나에 `viewedHash = sha256({kind, personaId, revisionId, assets:[보여 준 자산 id 정렬], terms})`를 싣는다. terms: scope = 견적 넷, reference · motion = 그 묶음의 안내 글, usage = 사용 범위 칸 전부(+ 판 번호).
- 승인 요청 `{personaId, kind, revisionId, viewedHash, idempotencyKey, decision, note}`: 같은 인물 · 같은 `idempotencyKey`의 승인이 있으면 새로 쓰지 않고 지금 상태를 `duplicate:true`로 돌려준다(본문이 다르면 409). 상태 · 판 · 해시가 지금과 다르면 409 + 최신 손님 보기(`persona`). `idempotencyKey`는 화면이 카드를 그릴 때 만든 UUID다.
- 직원 쓰기는 `revision`(인물 문서 판)이 맞아야 한다 — 어긋나면 409. 모든 쓰기는 `store.transaction` 안이다.

## 4. 경로와 권한(길을 섞지 않는다)

- `/pulse/api/request/*`(초안 토큰): 초안 칸 `persona-identity` · `persona-mood`는 `personaRequest`가 켜져 있을 때만 받는다. `submit`이 칸으로 갈라 `modelChoice:'custom'`이면 인물 문서 · 출처 문서로(같은 트랜잭션, 파일은 앞으로만), 아니면 인물 칸 파일은 접수 뒤 지운다. 인물 칸 파일은 `studio.assets` · `intake.files`로 가지 않는다(초대 링크에 열리면 안 된다).
- 프로젝트 길 의뢰서(`request_save` · `request_submit`, 직원이 만든 프로젝트 · 보낸 의뢰서 고치기): 사진 칸을 두지 않고 고객 방 인물 카드에서 올리게 한다. `request_submit`에서 `custom`이고 열린 인물이 없으면 인물을 만든다(사진 없음). 모델 선택이 `custom`이 아니게 바뀌고 열린 인물이 `submitted` · `needs_materials`면 손님이 거둔 것으로 `withdrawn`.
- 스위치(서버 강제): `personaRequest`가 꺼져 있으면 `custom` 저장 · 보내기 · 인물 칸 업로드 · 새 인물 만들기를 409로 막는다. `personaReal`이 꺼져 있으면 `kind:'real'`을 막는다. 이미 있는 인물의 검토 · 승인은 스위치와 상관없이 이어진다.
- `/pulse/api/persona/*`(초대 세션 — `clientProjects.session` + CSRF + 같은 출처): `POST approve`, `POST source`(needs_materials · submitted · reviewing · rights_pending일 때만, 사진은 JPG · PNG 화면용 · HEIC · WebP는 내려받기 전용), `GET media/<id>`(그 프로젝트가 원 프로젝트인 인물의 지금 공개 판에서 보여 준 묶음의 자산만). 손님 보기는 `/pulse/api/project` 상태의 `project.persona`로 온다(인물이 없으면 키가 없다).
- `/api/personas/*`(직원 세션 · CSRF): `GET project/<projectId>`(그 프로젝트의 인물들), `GET <id>`, `POST <id>`(직원 전이 · 일), `POST <id>/revisions/<revisionId>/media`(그림 · 영상 올리기, 머리글 `X-Persona-Role`), `GET <id>/media/<assetId>`(출처 원본 · 판 자산), `GET|POST <id>/consent`(실제 인물, 편집 권한). 읽기는 원 프로젝트의 `allowed()`, 쓰기 · 동의는 `clientProjects.project(user,id,true)`의 규칙(담당자 · 관리자 · 같은 팀 매니저, 보관 아님).
- 업로드 · 승인 어느 것도 유료 생성 · GPU 학습을 부르지 않는다 — 인물 모듈은 네트워크 · 생성 도구를 import하지 않고, 시험이 import 목록과 `fetch` 부재를 지킨다.

## 5. 가드 · 90일 · 판 1 후속

- `createPersonaGuard`: 판 1 조건(원 프로젝트 · `ready` · 묘비 아님 · 공개 판)에 더해, 그 프로젝트 · 인물 · 판의 `usage` 승인이 있고 그 id가 `personaUsage.approvalId`와 같을 것. 방향 제안(모델 없이) · `approve_draft` · 사진 상품 결제 확인 때 본다.
- 인물 쪽 쓰기는 모두 원 프로젝트에 `clientProjects.commitWorkflow`로 기록 한 줄(revision · updatedAt)을 남겨 90일 시계를 돌린다. 열린 인물이 있는 프로젝트는 정리에서 빠진다(판 1).
- 판 1 후속: `openPersonaProjectIds`가 묘비를 건너뛴다(아르곤 A1), `chooseDirection`의 참조 떼기 조건을 `answer_model`과 같게(B1), 직원 방향 대화상자가 맞춤 · 전용 인물 의뢰를 「사람 없이」처럼 모델 없이 그린다(안내 글은 따로).

## 6. 화면

- 의뢰서 모델 단계(`personaRequest`가 켜져 있을 때만): 칩 「맞춤 인물 요청하기」. 고르면 인물 종류(새 가상 인물 / 실제 인물 출연 — 실제는 `personaReal`), 원하는 인상 · 나이대 · 헤어, 원하는 쓰임, 이번만 / 다음 광고에도, 사진 칸 둘(같은 사람 재현용 · 분위기 참고용), 사진 쓰임 한 줄, 「견적을 확인하시기 전에는 비용이 생기지 않아요」, 사진 몇 장으로 재현을 약속하지 않는 말. 「내 모델 다시 쓰기」는 `myModels`일 때의 자리만(판 4). 꺼져 있으면 지금 화면 그대로.
- 고객 방: 인물 차례면 왼쪽 「지금 차례」 카드가 인물 카드(자료 보완 · 견적 · 기준 얼굴 · 동작 시안 · 이번 광고 사용), 저희 차례면 작은 인물 상태 줄. 일지에 인물 일(보냄 · 도착 · 확인)이 한 줄씩. 1차안 모델 카드는 붙은 인물이면 그 인물의 기준 얼굴.
- 직원 데스크: 인물 칸(다음 행동 한 줄 → 손님 글 · 사진 · 견적 · 판 · 승인 기록 · 전이 단추 · 판 올리기 · 사용 범위). 내부 도구라 한국어.
- 새 손님 글은 `t()` 사전(빠진 키 0 · 죽은 키 0), 영어는 세 겹(Opus 역번역 → Fable → 아르곤). 용어: persona · reference look · motion test · usage.

## 7. 시험

- 전이 표(허용 · 거절 전부), 스위치 끔 · 켬, 초안 → 인물(가상 · 실제 막힘), 인물 칸 파일이 초대 링크에 안 열림, 시나리오 6(분위기 참고 사진 · 실존 재현 요청이 각자 절차로 — 실제는 `rights_pending` · 동의 토큰 목적), 시나리오 7(새 기준 얼굴 판 뒤 옛 판 승인 → 409 + 새 판, 같은 키 두 번 → 한 번, 직원 동시 수정 → 409 · 이력 온전), 사용 승인 → `personaRef` · 가드 통과 · 사용 범위 고치면 다시 막힘, 90일 정리 · 묘비, 직원 권한(남의 프로젝트 404 · 보기 전용 403 · 동의 암호문), 유료 연결 없음(import · fetch).
- 화면: 스위치 끈 한국어 화면이 판 3 직전과 같음(1440 · 390), 켠 합성 프로젝트로 접수 → 직원 검토 → 견적 → 기준 얼굴 → 동작 시안 → 사용 확인을 한국어 · 영어로 끝까지.
