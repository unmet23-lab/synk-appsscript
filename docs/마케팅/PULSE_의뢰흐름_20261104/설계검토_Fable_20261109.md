- **P2-1 오류 문구 통로** — `fail()`에 code가 없고(F5) 서버는 `SYNK_` 접두 code만 내린다(`server.mjs:1923`). 영어 화면에서 「이메일 주소를 확인해 주세요」가 한국어로 뜬다. 고침: 고객이 밟는 4xx `fail()`에 `code:'SYNK_PULSE_<이름>'`을 붙이고, `api.mjs:10`이 `result.code`를 받아 사전에서 찾고 없으면 message를 쓴다. 메시지 자체는 한국어로 둬 옛 화면·시험 59곳(F25)을 깨지 않는다.

## 4. 구현 순서와 공개 방식에 대한 판단

- 기획 10절의 순서(공통 구조 → ko·en → 인물 → 소유권 → 4명 → 공개)는 유지하되 **1단계에 네 가지를 먼저 넣는다**: ① 모델 `published` 깃발(서버 허용 목록·화면·캐스팅북 빌드 한 번에, P1-3) ② 인물 파일 소유 kind + `workspaceMediaNames`·정리 제외(P1-1·P1-2) ③ `castingSelection.personaRef`·`answers.modelKind` 서버 선반영(P1-4·P2-3) ④ 오류 code 통로(P2-1). 이 넷이 없으면 2~4단계가 그 위에 쌓이다 다시 설계로 돌아온다.
- **서버가 든 반영**이므로 회사 이미지 판(57 이후)에 실리고 백엔드 검수(GPT) + 고객 화면 배포 조건(P0·P1 0)을 받는다. 화면은 「새 화면 흐름」이라 Fable 최종 조건부에 해당한다. 서버 먼저, 화면 묶음 나중(P2-3).
- **영어 공개 조건**: 「그 흐름의 필수 문구가 다 있는 언어만 메뉴에」(기획 6절)를 CI 시험으로 — 사전 키 집합을 ko와 en이 같은지 `node --test`로 비교하고, 빠지면 en을 메뉴에서 뺀다. 역번역 Opus·Fable 교정·아르곤 채점 세 겹(정해진 것) 뒤 공개.
- **인물 기능 공개**: 3단계(접수·직원 검토·승인)까지는 합성 자료로 시험하고 고객 화면에는 기능 깃발로 열되, **4단계(내 모델·재사용)는 SYNK ID 연결 경로(P2-2)가 새 설계라 별도 설계 검토 묶음으로 나누기**를 권한다 — 큰 기능 ②(한 묶음에 P0·P1 반복이면 설계부터)의 위험을 줄인다.
- 글로벌 4명은 이번 작업에서 깃발·레코드 자리까지만, 끝 보고에 「공개 완료」로 적지 않는다(요청 7절).

### C2 번역 틀 — 한국어 문장을 키로 — 조건부 찬성
찬성 이유: ko 렌더 바이트가 그대로라 시험 수천 줄(A7)과 옛 설치본이 깨지지 않고, 서버가 이미 `public/pulse-app/casting-catalog.mjs`를 import하므로(F2) 공유 모듈이 관행에 맞다.
조건(수정):
1. **자리표는 이름 있는 `{name}`만**. 지금 화면은 템플릿 리터럴 안에 `${esc(item.name)} · ${esc(castLine(item))}` 꼴로 값이 박혀 있다(`request-flow.mjs:26·30·83`). 문장 단위로 끊고 값은 `t('…{name}…',{name})`로 넘겨야 영어 어순이 산다. 조사(은/는·을/를)가 값 뒤에 붙는 문장은 다시 쓴다.
2. **이스케이프 순서** — `esc(t(...))`로, `t(esc(...))`가 아니게. 영어 사전에 `&`·따옴표가 들어오면 지금처럼 번역 뒤에 escape해야 한다. `api.mjs:26 keepDots`는 「·」 기준이라 영어에서는 비활성.
3. **원문 수정 고아 방지는 CI로** — 손님 길 모듈의 `t('…')` 리터럴 전수 ↔ `en.mjs` 키 집합을 `node --test`로 대조하고, en이 공개 목록에 있으면 빠짐 0을 요구(구현자도 적음). 거기에 **원문이 바뀌면 옛 키를 `en.mjs`에서 지우는 실패**(죽은 키 0)도 넣어야 고아가 쌓이지 않는다.
4. **문맥 충돌은 미리 목록**: 「확인」(단추/상태/「확인 끝」), 「모델」(카탈로그/인물), 「보내기」, 「열기」, 「다음」 등은 `ctx`를 처음부터 붙인다.
5. 날짜·숫자는 `Intl`에 locale을 넘기는 포맷터로(지금 `api.mjs:23·25`는 ko-KR 고정). `fmtPrice` en 「KRW 390,000」 찬성 — 통화 변환 없음(요청 범위).
6. 언어 결정에서 「초대·공유 링크 lang」은 `app.mjs:41 replaceState` **앞에서** 읽어야 한다(F24). 「바꿔도 다시 그리기만」은 맞다 — 답은 ID라서(F2). 단 `avoid` 칩(WATCH_WORDS 한국어)과 `refs.points`(POINTS 한국어)는 **저장값이 한국어 문장**이므로 영어 화면에서는 `t(값)`으로 보이고 저장은 한국어 키 그대로 — 구현자 「저장값을 바꾸지 않는다」와 일치.

전이 표 순수 함수 + 시험, `{revisionId,viewedHash,idempotencyKey}`, 옛 판 409 + 최신 판 반환(현 규약 F19와 어울림), 제작 시작(`approve_draft`→producing, `pulse-requests.mjs:509`) 재검사 모두 찬성. 보탬: `viewedHash`는 **고객에게 내려간 published 자산 id 목록 + termsHash**로 서버가 계산해 응답에 실어 주고, 승인 때 같은 값을 돌려받아 비교한다(화면이 만든 해시를 믿지 않음).

### C10 스위치 — 수정 하나
`pulseFeatures` 서버 강제·기본 끔 찬성. 구멍: `locales:['ko']` 한 목록이 「공개 메뉴」와 「프로젝트별 허용」 두 뜻으로 쓰인다 — 영어 시험을 「합성 프로젝트 contactLocale=en + 초대 링크」로 하려면 공개 목록에 en이 없어도 그 프로젝트는 en으로 그려져야 한다. `publicLocales`(공개 의뢰서·캐스팅북 메뉴)와 `projectLocales`(contactLocale로 허용) 둘로 나눈다. 설정 변경은 admin + audit(`server.mjs:1586` 패턴). 화면은 `/pulse/api/project`·`/pulse/api/request` 응답에 실린 값만 믿고 셸 캐시에서 추론하지 않는다.

### C11 글로벌 4명 — 찬성
`roster-global-draft.json`(빌더가 안 읽음) + 「CASTING_MODELS·catalog.json·site·sw.js·server.mjs 정적 목록(`:1855`)에 없음」 시험 + 공개 전환 검사 스크립트. 1부 P1-3의 `published` 깃발보다 단순하고 같은 효과. 보탬: 공개 전환 검사에 `public/pulse-app/assets/request/model-scene-<id>.webp`·`assets/casting/<id>*.webp` 존재와 `MODEL_LINES`·`MODEL_PICKS` 반영, 인원수 글(F24 「21명」)을 넣는다.

### C12 보관·삭제 — 수정 하나
자동 영구 삭제 끔·묘비 문서·참조 확인 찬성. **「고객 인물은 금고 제외(결정 표에 기록)」는 구현자가 정할 수 없다** — 보존 규칙은 유호님 확정(운영 원칙 98행)이다. 선택안으로 올린다: (가) 고객 인물 데이터셋·가중치는 금고 제외, 보관 기간 뒤 삭제 (나) 고객 동의 범위 안에서만 금고 (다) 학습 파일은 금고, 원본 사진은 제외. 그리고 동의 문안 초안에 「백업은 최대 1년 보존(일 30·주 90·월 1년)이라 삭제 요청 뒤에도 그 기간 사본이 남는다」를 사실대로 적는다(GCS 30일 + 보존 규칙).

## D절 질문 여덟

**1. 한국어 문장 키가 이 코드에 맞는가.** 맞다, 조건부로(C2). 이 저장소는 시험이 한글 문장을 그대로 대조하고(수천 줄) 서버가 공개 모듈을 import하는 관행이라 다른 키 체계보다 비용이 작다. 지킬 것: 이름 있는 자리표만, `esc(t())` 순서, `ctx` 목록 선정, CI에서 빠진 키 0·죽은 키 0, 서버 오류는 동적 문장만 `code`. 템플릿 치환은 지금처럼 문장 조각을 `+`로 잇는 자리(`request-flow.mjs:26·30`)를 문장 단위로 다시 써야 하므로 「ko 바이트 동일」은 **그 자리에서는 깨진다** — 그 범위를 작은 시험(판 1 전)에서 재는 것이 맞다.

**2. 번역 지도 하나 vs 칸마다 두 언어.** 지도(C4). 직원 글이 든 구조가 다섯 가지 넘고 스키마마다 en 칸을 더하면 옛 판 호환·시험·보기 함수가 전부 바뀐다. 지도는 더하기만이고 `sourceHash`로 낡음을 잡는다. 단 직원이 직접 영어를 적어 reviewed로 두는 칸이 있어야 운영이 멈추지 않는다.

**3. `studio-media/` 공유 vs 별도 폴더.** 공유(C7). 이름 규칙·백업·hydrate·DR 검증·`client-materials` 패턴이 모두 그 폴더와 확장자 네 개에 박혀 있다(F10·F27). 별도 폴더는 백업 파이프라인 네 군데를 새로 뚫어야 하고 놓치면 고객 자산이 백업에서 빠진다(1부 P1-1). 지문은 이미 `sha256`을 받으므로(`pulse-requests.mjs:182`) 인물 소스에 그대로 저장. 접근은 경로(라우트)에서 막고 파일은 `visibleAssetIds`에 **넣지 않는다**(원본 사진이 초대 링크로 열리지 않게 — A3).

**4. 실제 인물을 뒤로 미루는 판단.** 맞다 — 재현 능력이 11-07·11-08에 두 번 실패로 적혀 있고, 요청도 「생성·학습 실행 안 함」이다. 구조에 **지금** 넣을 것: `kind:virtual|real`, 소스마다 `purpose:identity|mood`, 동의 레코드 종류와 `subject`(당사자) 확인 방법 칸, 당사자 확인 토큰 purpose. 이것들은 나중에 끼우면 기존 인물 레코드·승인 기록을 다 옮겨야 한다. 동의 쪽(링크 발급·발송)은 요청 범위 밖이니 구조만.

**5. 판 3 → 판 4 순서, workspaceId 없이 프로젝트에 묶이는 것.** 빚이 되지 않는다 — `originProjectId`와 `workspaceId|null`을 처음부터 두고, 연결은 직원의 명시적 행동(workspace 생성 + 인물에 workspaceId 기록 + history 한 줄)이면 된다. 초대 세션으로 남긴 승인(`actorKind:'invite'`)을 나중에 SYNK 사용자로 다시 귀속시키지 않는 것이 오히려 기획 7절(「초대 링크 접근을 신원 검증으로 표현하지 않음」)과 맞다. 순서 3 → 4 찬성; 4는 별도 설계 검토 묶음(1부 4절).

**6. 스위치·영어 시험 경로 구멍.** C10에 적은 「한 목록 두 뜻」이 가장 큰 구멍. 그 밖에: 영어 시험 프로젝트의 메일·푸시가 한국어 조립 그대로 나간다(메일은 지금 꺼진 채라 당장은 아님) → 판 2에 contactLocale 조립을 같이; `?demo=film` 체험은 fixture라 깃발과 무관하되 en에서 숨김(C1) 확인; 설치본 PWA는 셸만 캐시라 깃발 반영 즉시(F14). 깃발 저장 문서의 변경 경로는 admin·CSRF·audit.

**7. 평가(A)에서 틀린 것·부풀린 것·빠진 것.** 위 표: 부정확 1(BEGIN IMMEDIATE), 부풀림 1(SYNK ID 「유리한 점」), 근거 줄 어긋남 1(server.mjs:1855), 날짜 미확인 1(결정 11-07 크몽). 빠진 것 아홉은 A 표 아래 문단.
