## 할 일(순서대로, 판마다 회사 사슬로 운영 반영까지)

**판 1 — 1단계 + 2단계 화면 · 서버(메일 빼고).**
1. 뒷문 막기: `public/pulse-app/views.mjs:191` `roomExtras`가 새 방 손님을 옛 `strategy` 탭(입력 117개, 펼치면 7,284px)으로 보내는 길을 없앤다. 「담당자에게 묻기」가 영상 없이도 영상 확인 탭으로 가는 것(`app.mjs:109` 근처)을 문의 자리로.
2. 작은 조각(9절 5번 목록): 진행 표시 중복, 안 고른 「하린」, 「먼저 보여 드리는 컷 0」, 그림 위 검정 글자 상자, 「최신 내용 불러오기」, 글 콘티 「이어서 보기」, 1366×650에서 첫 단계 06 · 07번이 다음 단추 뒤로 숨음. 고치기 전에 운영 화면에서 지금도 그런지 먼저 본다(사슬 52~54에서 고친 것이 섞였을 수 있다).
3. 기간 · 수정 한 줄: `request-data.mjs:4` 주석의 「기간 · 수정 횟수는 공개하지 않기로 한 약속」을 결정 11-07로 바꾸고, 의뢰서 길이 · 구성 칸 · 보내기 전 확인 · 접수증 · 고객 방에 ①을 보인다. 날짜는 「받으실 날」로(시안처럼 접수일 + 기간, 평일 · 공휴일 계산은 지금 앱에 있는 방식을 따른다).
4. 방향과 모델(1/3 교체): 서버 `pulse-requests.mjs`의 `modelProposal`(직원 제안 → 손님 수락 · 다른 모델 · 말로) 옆에 `directionProposal`을 둔다 — 안 둘(기업 셋) · 추천 표시 · 안마다 이름 · 한 문장 · 흐름 석 줄 · 왜 이 제품인지 · 장면 그림(직원이 올린 자산) · 모델 · 선택적 움직임 견본, 아래 값 · 받으실 날 · 수정 횟수 · 「결제는 글 콘티를 보신 뒤」. 손님 답은 이 안으로 / 저 안으로 / 둘 다 아니에요 + 한 줄, 섞기 없음, 다시 제안은 한 번. 옛 프로젝트의 열린 `modelProposal`은 그대로 돈다(호환). `room-view.mjs` `roomState`에 `direction` 상태, `CONFIRM_OF.direction='1/3'`, 직원 화면(`desk-view.mjs`)에 제안 만들기. 옛 「콘셉트 비교」 자료(`studio.concepts` · `selectedConcept`)를 쓸지는 설계 때 정한다.
5. 해로운 형태는 만들지 않는다: 네 번째 확인 단계, 취향 보드 복원, 안 넷 이상, 안마다 모든 컷 렌더, 대화형 컨셉 도우미.

**판 2 — 메일 알림(③).** 지금 회사 서버에는 메일 보내는 길이 없다(검색 0건). Apps Script 엔진에는 `MailApp`이 있다(`엔진_synkbrief.js:355` 근처). 길을 고르는 것부터 설계한다(회사 서버 → 서명한 요청 → Apps Script `doPost` → `MailApp` 같은 중계 / Google 계정 OAuth에 보내기 권한 더하기 — 권한 동의 화면은 유호님 몫이라 그 길이면 한 단계만 넘긴다). 손님 연락처는 의뢰서 `email` 칸. 비밀값은 커밋하지 않는다(공개 저장소). 실주문 0건이라 켠 뒤 첫 메일은 시험 주문으로 founder@synk.im에 받아 확인한다.

**판 3 — 4단계(틀 넷을 고객 방 하나로, 담당자 말을 한 줄기 일지로, 영상 확인 + 납품 합침).** 큰 화면 개편 — 아르곤 → Fable.

**미룬 것 — 3단계(의뢰서 9 → 6화면)는 9절 계획대로 첫 실주문 뒤 숫자로 다시 본다.** 트랙에 그렇게 적는다.
