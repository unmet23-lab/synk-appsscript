## 목적

손님이 의뢰를 넣은 뒤 「제작사가 방향을 이끌어 준다」고 느끼게 하고, 안쪽에서 옛 화면 · 흩어진 말 · 작은 흠 때문에 「조잡 · 분산」으로 읽히는 곳을 걷는다. 새 단계를 더하지 않는다 — 영상 전 확인 1/3의 「모델 확인」 자리를 「방향과 모델」로 바꾼다.

## 1a — 뒷문 · 조각 · 기간 줄

**뒷문.** 고객 방(의뢰 흐름) 손님은 옛 `strategy` 탭의 제작 설계 큰 폼(모델 · 스타일 칩 포함)을 보지 않는다.
- `views.mjs` `roomExtras`에서 「제작 설계를 확인해 주세요」를 뺀다. 고객 방에서 `strategy` 탭은 납품 규격 확인 · 준비 자료 · 바뀐 내용 패널만 그리고, 제작 설계 폼은 확인 요청이 있어도 그리지 않는다(지금은 요청이 있으면 그린다).
- 직원 쪽에는 `deskChecks`에 한 줄: 고객 방 의뢰에서 제작 설계 확인을 요청했으면 「고객 방에는 제작 설계 확인이 보이지 않아요 — 물을 것은 빠진 것 다시 묻기로」.
- 「담당자에게 묻기」: 영상이 없을 때는 이미 고객 방 틀의 문의 화면(`askRoom`, `data-state=ask-only`, 폼 `feedback` · `support`)이 뜬다. 새 대화상자를 만들지 않고(옛 `app-dialog` 문법이라 틀이 하나 늘어난다 — 설계 검토 6) 그 화면에서 단계 줄이 「영상 확인」이 아니라 지금 단계 + 「담당자에게 묻기」를 지금 자리로 보이게 하고, 상시 「최신 내용 불러오기」를 뺀다. 문의를 보낸 알림 글은 「문의를 보냈어요」.

**작은 조각(9절 5번).** 고치기 전에 실제 서버 합성 프로젝트로 지금도 그런지 1440 · 1366×650 · 390에서 본다. 남아 있는 것만 고친다.
- 의뢰서 한 화면의 진행 표시 셋(휴대폰 넷)을 하나로.
- 음료 업종 그림 밑 「하린 · 상큼한 막내」가 고른 모델처럼 읽힘 → 「예시 장면 · 하린」 꼴로 예시임을 앞에.
- 「먼저 보여 드리는 컷 0」(0일 때 숫자를 감춤).
- 그림 위 검정 글자 상자 → 그림 밖 크레딧 줄(문법과 같게).
- 고객 화면의 상시 「최신 내용 불러오기」 링크를 뺀다(실시간 갱신이 있다). 충돌(409) 알림 안의 링크는 둔다.
- 글 콘티(그림 없는 판)의 「이어서 보기」를 뺀다(글을 시간 맞춰 넘기는 것은 읽기에 방해). 장면 이미지 판은 그대로.
- 1366×650 첫 단계 06 · 07번이 다음 단추 뒤로 숨음 → 낮은 노트북 규칙.

**기간 · 수정 한 줄(결정 ①).** `request-data.mjs` `PACKAGES`에 `days` · `revisions`를 더한다 — s15 10일 · 2회, s30 14일 · 3회, s60 21일 · 3회, 기업 협의(null), 사진 3일 · 2회(크몽 사진 상품과 같게). 머리 주석의 「공개하지 않기로 한 약속」을 결정 11-07로 바꾼다.
- 날은 달력 기준(주말 · 공휴일 포함, 크몽 FAQ와 같은 말)이다. 앱에 평일 계산은 없다 — 「평일 10~19시에 보고」는 답하는 시간이지 기간 계산이 아니다.
- **날짜는 하나만 약속한다(설계 검토 3).** 보내기 전 확인에만 조건을 붙인 날(「오늘 다 모이면 11월 17일이에요」)을 보이고, 접수증 · 고객 방은 「자료가 다 모인 날부터 10일 · 날짜는 방향을 보내 드릴 때 알려 드려요」로 둔다. 달력 날짜는 방향 제안의 `dueDate` 하나(직원이 자료 · 결제 시점을 보고 넣음)다. 주말 · 공휴일 포함 · 자료가 다 모인 날부터는 크몽 상품 글 FAQ(`ad_video.json` 「필수 자료가 다 모인 날부터 주말·공휴일을 포함한 달력 기준」)와 같은 말이다.
- 보이는 곳: 의뢰서 길이 · 구성 칸의 줄(값 아래 「10일 · 수정 2회」), 길이 단계 화면의 값 밑, 보내기 전 확인, 접수증(받으실 날 · 수정 줄), 고객 방 「보내 주신 의뢰서」(길이 · 구성 줄에 기간 · 수정, 그 아래 받으실 날 줄 — 직원 화면은 `briefRows`의 길이 · 구성 줄).
- 수정 낱말: 「영상이 나온 뒤 2번. 글 콘티 · 장면 이미지 의견은 세지 않아요」(크몽 수정 정책과 같은 말).

## 1b — 방향과 모델

**자료.** `studio.request.directionProposal`(모델 제안 `modelProposal` 옆, 같은 트랜잭션 · 판 검사). 옛 「콘셉트 비교」(`studio.concepts` · `selectedConcept`)는 쓰지 않는다 — 카드마다 판 · 댓글 · 공개 범위가 있는 자유 보드라, 「두세 안 · 섞기 없음 · 다시 제안은 한 번」을 서버가 지키기 어렵고 옛 탭 화면과 엮인다. 한 번의 결정이라 모델 제안과 같은 꼴이 맞다.

```
directionProposal = {
  round: 1|2, status: 'open'|'chosen'|'declined', at, by,
  lead,                         // 한 줄 안내(≤200) 예) 저녁 농구장과 한결은 요청하신 대로 두고, 무엇으로 기억에 남길지만 두 방향으로 나눴어요.
  options: [{ id, name(≤40), sentence(≤160), flow:[{at:'0:00', text(≤200)}]×1~4, why(≤300),
              assetId(그림, 필수), filmAssetId?(움직임 견본 영상), filmNote?(≤80), workId?(작품 id), recommended }]×2~3,
  modelId?(사람 없이 제품만 의뢰면 없음), price(원 — 손님이 실제로 내는 값), dueDate('YYYY-MM-DD'), revisions(0~9),
  chosenId?, answer?(≤300), answeredAt?, settledBy?, prior?: {round, names, answer}
}  // status에 'settled'(회차 2 거절 뒤 직원이 손님과 이야기해 정한 안)를 더한다
```

**액션.**
- `propose_direction`(직원만): 의뢰서 확인 끝(`confirmed`) · 판(`rounds`) 0개일 때. 안 2~3개, 추천은 하나까지, 그림은 이 프로젝트 이미지 자산, 견본은 영상 자산, 모델은 `MODEL_IDS`, 날짜 꼴 · 오늘 이후 120일 안. 열린 제안이 있으면 같은 회차를 갈아 끼운다(고객이 답하기 전 고침). 「둘 다 아니에요」 뒤에는 회차 2로 한 번 더(앞 회차 이름 · 답은 `prior`). 회차 2가 거절되면 더 받지 않는다(「다시 제안은 한 번이에요 — 고객과 직접 이야기해 주세요」). 고른 뒤에는 거절.
- `answer_direction`(고객만): 열렸거나 고른 상태 · 판 0개일 때. `optionId` + 선택 `modelId` · `note`(한마디, ≤200) → `chosen`. `neither:true` + `note` 필수(≤300) → `declined`. 고르면 `answers.models=[modelId]`, 제작 설계 `castingSelection.modelId`도 옮긴다(모델 답과 같은 길). 판이 나오기 전까지는 다시 고를 수 있다.
- `settle_direction`(직원만, 설계 검토 1): 회차 2가 거절된 뒤 손님과 직접 이야기해 정한 안 하나(`optionId`) + 한 줄 메모 → `settled`. 모델 · 제작 설계 옮김은 고를 때와 같다. 이 길이 없으면 회차 2 거절 뒤 직원도 손님도 앞으로 못 간다.
- `send_draft`: 방향 제안이 있으면 `chosen` · `settled`여야 보낸다(없으면 지금 모델 조건 그대로 — 옛 프로젝트 · 사진 상품 호환).
- 사진 상품(`photo`)에는 방향 제안을 받지 않는다(첫 장으로 방향을 맞추는 상품). 제안을 보내면 열린 `modelProposal`은 닫는다(`status:'replaced'`, 둘 다 열려 직원 화면이 「답을 기다려요」를 계속 띄우지 않게). 갈아 끼울 때 안 `id`는 새로 만들어, 밀린 화면이 옛 id로 다른 안을 고르지 못하게 한다. 날짜 비교는 KST 날짜만.
- 모델 없는 의뢰(`modelChoice:'none'`)는 `modelId` 없이 보내고, 고를 때 `answers.models`는 모델이 있을 때만 옮기며 `modelChoice`는 건드리지 않는다.
- 손님에게 보이는 자산(`visibleAssetIds`)에 제안의 그림 · 견본 영상을 더한다. 갈아 끼운 옛 제안의 자산은 다시 숨는다.
- 열린 `modelProposal`이 있는 옛 프로젝트는 그대로 돈다.

**고객 방(`room-view.mjs`).** `roomState`: 열린 제안 → `direction`(모델 확인보다 먼저), 거절 · 판 0개 → `redirect`(저희 차례 「새 방향을 준비하고 있어요」, 회차 2 거절이면 「담당자가 직접 연락드려 함께 정해요」), 고른 뒤 → 지금의 `prepare`. `CONFIRM_OF.direction='1/3'`, 단계는 1차안(`STAGE_OF` · 직원 목록 `DESK_STATE`에 `direction` · `redirect` 글을 더한다). `deskChecks`의 모델 경고는 방향을 고르면 꺼진다. `roomModel`에 `direction`(안 · 그림 · 견본 · 모델 카드 · 값 · 받으실 날 · 수정 · 상태 · 고른 안).

**화면.** 열린 제안은 시안 짜임 그대로(그림 둘이 양쪽 끝까지 · 가운데 설명 한 장 · 고른 쪽만 색, 휴대폰은 안내 → 두 그림 나란히 → 설명). 고객 방 틀 안에 둔다(`.sx-room[data-state=direction]` 히어로를 이 짜임으로, 아래 인화지 쪽은 같음) — 새 틀을 늘리지 않는다. 시안의 글 · 단추를 그대로 옮긴다: 「○○으로 정하고 글 콘티 받기」 · 한마디 덧붙이기 · 둘 다 아니에요(→ 한 줄 쓰고 「다시 제안받기」, 회차 2면 「담당자와 이야기하기」), 미리 움직여 보기(견본이 있을 때, 누른 순간 소리와 함께 한 번), 비슷한 작품 보기(작품 id가 있을 때), AI 모델 「다른 모델로」(업종마다 넷 — 지금 `MODEL_PICKS`, 맹검 6차 「격자는 판매 목록」), 값 · 받으실 날 · 수정 + 자세히(만드는 법 · 받으시는 것 · 쓸 수 있는 곳 · 받으실 날 · 수정 · 결제). 고른 뒤는 고객 방(`prepare`) 오른쪽에 고른 안 그림, 왼쪽에 「고르신 방향」 한 줄과 길(방향 → 글 콘티 → 장면 이미지 → 영상) · 「다시 고르기」(판이 오기 전까지).
- 결제 글(결정 ②): 「글 콘티를 보신 뒤, 장면 이미지 전에 결제해요. 글 콘티까지는 값을 받지 않아요. 결제 방법은 그때 담당자가 안내해 드려요.」 앱에서 결제를 받지 않는다.
- 메일 약속은 판 2가 켜진 뒤에만 쓴다. 판 1은 「도착하면 이 화면에서 알려 드려요」.
- 받으시는 것은 길이마다 다른 글(`PACKAGES`에 한 줄).

**손님이 보던 자리는 실시간 갱신에도 남는다(설계 검토 5).** 비교 중인 안 · 고른 모델 · 「다른 모델로」 열림 · 「다시 고르기」 열림은 앱 상태(`s.direction`)에 두고 그린 뒤 되살린다. 한마디 · 둘 다 아니에요 글은 이름 있는 칸을 가진 `form[data-form]` 안에 두어 지금의 폼 초안 복원 길을 탄다.

**값.** 제안의 `price`는 손님이 실제로 내는 값이다(직원이 넣음, 대화상자는 패키지 정가로 미리 채우고 「결제하실 곳의 값」으로 적어 둠 — 설계 검토 2). 결제 글은 「결제 방법은 그때 담당자가 안내해 드려요」.

**직원 화면(`desk-view.mjs`).** 확인 끝 · 판 0개이면 주 단추 「방향 제안 보내기」(대화상자: 안내 한 줄, 안 셋 칸 — 이름 · 한 문장 · 흐름 줄 · 왜 · 그림 파일 · 견본 영상 · 견본 설명 · 추천, 모델 · 값 · 받으실 날 · 수정은 패키지 값으로 미리 채움). 파일은 지금 자산 올리기 길(`/studio/media`)로 먼저 올리고 그 id로 제안한다. 옆 칸에 「방향 제안」 상태 · 고른 안 · 손님 말. 「모델 제안하기」는 줄 단추로 남긴다(사진 상품 · 옛 흐름).

**안 만드는 것(9절 해로운 형태).** 네 번째 확인 단계, 취향 보드 복원, 안 넷 이상(서버가 막음), 안마다 모든 컷 렌더, 대화형 컨셉 도우미, 안 섞기.

**예시(`?demo=film`)는 이번 판에서 바꾸지 않는다.** 예시 제품(霜の肌理)으로 방향 두 안 그림을 새로 구워야 해서 후속으로 둔다(트랙에 적음).
