# synk.im 방문 측정 현황 (2026-11-17 아침에 읽은 값)

유호님이 2026년 11월 17일 아침에 「그리고 저번에 넣었던 geo인가 seo인가 방문자 분석 프로그램도 더 치밀하게 구성해서 내가 솔리오에서 확인할수있게 만들어줬으면 좋겠어」라고 하셨다. 이 문서는 그 일을 시작하기 전에 지금 무엇이 깔려 있고 무엇이 재지고 있는지를 실제 값으로 읽은 기록이다. 기록에 적힌 말이 아니라 라이브 쪽, 장부 파일, 각 서비스 화면에서 직접 읽은 값만 적었다. 읽지 못한 것은 「확인 안 함」으로 적었다. 설계는 같은 폴더의 [설계.md](설계.md)에 있다.

## 1. Microsoft Clarity

- **깔린 곳:** 11-17에 라이브 쪽을 받아 찾아보니 측정 코드는 https://synk.im/pulse/ 한 쪽에만 있다. 홈, /lab/, /shift/, /path/, /atlas/, /founder/, /en/, /mn/, /world/, /account/에는 없다. 프로젝트는 `z67ez8kfp3`이다.
- **가림:** /pulse/의 질문창 두 곳(`#messages`, `#question-form`)에 `data-clarity-mask="True"`가 붙어 있다. 10-31에 시험 글이 밖으로 나가지 않는 것을 실측한 판 그대로다.
- **하루 장부:** 공용 작업본의 `.tmp/반응리포트/_clarity/z67ez8kfp3.jsonl`에 33줄(11일 × 세 번)이 쌓였다. 첫 줄은 11-06이다. 10-31부터 11-05까지가 비는 까닭은 확인 안 함. 예약 「SYNK 반응 리포트 랜딩 받기」의 마지막 기록은 「됨 · 줄 3」, 종료 0이다.
- **실제 값(11-06~11-16, 장부를 주소별로 나눠 셈):**

| 주소 | 사람 세션 | 로봇 세션 |
|---|---:|---:|
| https://synk.im/pulse/ (라이브) | 17 | 1,022 |
| 127.0.0.1, localhost (우리 시험 도구가 연 쪽) | 5 | 1,154 |
| `https://Electron` (PC 앱 안에서 열린 쪽으로 보임) | 4 | 0 |

- **문제 둘:** 첫째, 우리 시험 도구가 이 PC에서 /pulse/ 후보를 열 때마다 측정 코드가 진짜 프로젝트로 보낸다. 장부의 세션 가운데 절반 가까이가 그것이다. 둘째, 라이브 쪽에서도 로봇이 98%다. 사람으로 센 17번 가운데 들어온 곳이 「synk.im」인 8번과 꼬리표 `card_check`, `test` 2번은 우리 쪽 방문일 가능성이 크다(확인 안 함).
- **들어온 곳 분류:** Clarity는 2025년 8월부터 ChatGPT, Copilot, Gemini, Claude, Perplexity에서 온 방문을 「AI Platform」으로 따로 묶는다([Clarity 안내](https://learn.microsoft.com/en-za/clarity/insights/ai-channel-group)). 지금 받는 세 호출(`URL`, `URL+Device`, `URL+Source+Campaign`)에는 그 묶음(Channel)이 없다.
- **API 한도:** 프로젝트마다 하루 10번, 지난 1~3일만, 차원 셋까지다([Data Export API](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-data-export-api)). 문의 누름 같은 사용자 지정 이벤트와 나간 쪽은 내보내지 않는다.

## 3. 구글 서치콘솔

- ego 브라우저의 구글 계정 열 개를 차례로 열어 보니, unmet23 계정에 `https://synk.im/` 속성(주소 앞부분 방식)이 있다. 나머지 아홉 계정에는 속성이 없다. 홈의 `google-site-verification` 표시가 이 속성의 소유 확인으로 보인다.
- **지난 3개월(10-08~11-14) 웹 검색 실적:** 클릭 8, 노출 1,140, 클릭률 0.7%, 평균 게재순위 9.5.
  - 검색어: 「synk」 클릭 2 · 노출 681, 「synk ai」 노출 17, 「synk.to」 노출 13, 「synk lab」 노출 7. 37가지 가운데 앞 열 개만 읽었다.
  - 쪽: 홈 클릭 3 · 노출 317, /lab/ 클릭 3 · 노출 30, /en/ 클릭 0 · 노출 697, /en/path/ 노출 46.
- **색인:** 색인된 쪽 26, 안 된 쪽 3(찾을 수 없음 404가 2, 표준 태그가 다른 쪽을 가리킴 1). 마지막 갱신 11-13.
- **사이트맵:** 제출한 사이트맵이 없다. 라이브 `https://synk.im/sitemap.xml`에는 22개 주소가 있고 `robots.txt`가 그 주소를 알린다.
- **받아 오는 길:** 화면으로만 볼 수 있다. API 읽기 권한(서비스 계정이나 OAuth)은 없다.

## 4. 네이버 서치어드바이저

- 홈에 `naver-site-verification` 표시가 없다. 소유 확인 파일이 있는지는 확인 안 함(파일 이름을 알 수 없다).
- ego 브라우저에서 서치어드바이저를 열면 네이버 로그인 화면이 뜬다. ego에는 네이버 로그인이 없어서 등록 여부를 확인 안 함.

## 5. GA4와 그 밖의 측정

- 라이브 열한 쪽에서 `googletagmanager`가 0건이다. GA4는 없다.
- synk.im의 DNS는 Cloudflare이고 프록시는 꺼져 있다(응답 머리가 GitHub Pages). Cloudflare Web Analytics는 tips.synk.im에만 있다.
- PULSE와 체험 쪽 몇 곳에 SNS 클릭 꼬리표(`synk_ref`)를 회사 서버(workspace.synk.im)로 잇는 `social-conversion.js`가 있다. 체험 시작과 가입만 기록한다.

## 6. 문의와 앱 받기의 길

- **문의:** 모든 회사 쪽 아래에 메일(`mailto:hello@synk.im`), 「주소 복사」 단추, 웹 문의 양식(구글 설문지)이 있다. /pulse/는 「광고 의뢰하기」가 `workspace.synk.im/pulse-app/?start=request`로 간다. /shift/는 강의별로 미리 채운 문의 양식 링크가 있다. 어느 것도 누름을 세지 않는다.
- **앱 받기:** PC 앱 받기 단추는 홈(/, /en/)에만 있고, GitHub 릴리스 `platform-preview-0.4.95`의 Windows `.exe`와 Mac `.dmg` 둘로 간다. 모바일 스토어 링크는 없다.
- **GitHub 내려받기 수:** 릴리스마다 Mac 두 파일과 Windows 파일의 수가 거의 같다(0.4.95는 Mac 2 · 2, Windows 4, 0.4.87은 17 · 17 · 15). 우리 공개 검사기가 판마다 설치 파일을 받고 자동 업데이트도 같은 파일을 받으므로, 이 수를 사람이 받은 수로 쓸 수 없다.

## 8. 솔리오

- PC 앱의 솔리오에는 「AI 구독 관리」(그 안의 「모델별 토큰」)와 「백업(준비 중)」이 있다. 방문 숫자를 보이는 곳은 없다.

- 「AI 구독 관리」와 「모델별 토큰」은 이 PC의 파일을 앱의 본체 쪽 모듈이 읽어 화면으로 넘긴다(`desktop/src/ai-subscriptions.cjs`, `ai-tokens.cjs` → `preload.cjs` → `renderer/subscriptions.mjs`). 방문 숫자도 같은 길로 보일 수 있다.
