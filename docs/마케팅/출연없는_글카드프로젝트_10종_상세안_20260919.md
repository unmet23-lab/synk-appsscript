> 2026-09-19 원고 교체: 이 파일은 대상과 형식을 설명하는 기획 자료다. 사용자 요청으로 기존 제작 원고는 사용을 중단했으며 [새 원고 목록](첫콘텐츠_재작성_20260919/README.md)을 따른다. 아래 제목·문구 예시를 게시 원고로 복원하지 않는다.

2026-09-19 · 사용자가 요청한 계정별 상세 설명과 제작 제안. 기존 출연 없는 12종에서 **synkbrief 영상 S4 1종**과 **Threads·X 작업 기록 S2 1종**을 뺀 나머지 10종이다. 모든 항목은 유호의 얼굴·몸 촬영 없이 제작한다. 아래 제목·장수·구성은 제작을 시작하기 위한 예시이며 플랫폼의 의무 규격이나 확정 원고가 아니다. 이 문서는 콘텐츠 기획이며 원고·그래픽 제작 또는 외부 발행 완료를 뜻하지 않는다.

원래의 [첫 게시물 배치](첫게시물_타깃과_재사용_검토_20260919.md)와 [계정 전체 목록](SNS_계정_전체목록_20260919.md)을 함께 따른다. 10종은 10개의 독립적인 사건·작품을 새로 만들어야 한다는 뜻이 아니다. 같은 글·카드가 여러 역할에 맞으면 그대로 공유하고, 독자에게 필요한 내용이 부족할 때만 보충한다. 작업 기록의 배포 범위를 넓히는 논의도 이 원칙으로 적용한다.

## 먼저 함께 준비할 자료

- **LAB 학습 예시 1개**: 상황, 학습자가 해 볼 말이나 행동, 필요한 도움, 실제 사용할 학습 카드. 몽골어로 상황을 이해하고 한국어로 연습하도록 한다. 얼굴이 나오는 A 영상 완성은 필요하지 않다.
- **SYNK 실제 제작 사례 1개**: 만들려던 것, 발생한 문제, 시도, 선택·수정 이유, 확인된 결과, 전후 이미지. 최근 SNS 커버 디자인은 후보이며 구체 사례는 제작할 때 원본과 공개 가능한 결과를 대조해 고른다. B 영상 촬영은 필요하지 않다.
- **선정한 도구의 시연 자료**: synkbrief에서 별도 GitHub 스킬·도구를 다루기로 하면 공식 원문·설정·실행 화면·실제 결과를 별도로 확보한다. 그때 네이버 사용법 글도 같은 자료를 쓴다. 일반 제작 사례와 도구 시연이 같을 때는 공유한다.
- **회사·제공 범위의 사실 자료**: 현재 비전, 사업별 대상, 실제 완성물, 준비 중인 서비스, 공개 가능한 문의 통로. LAB·SHIFT·PULSE·PATH의 역할을 현재 정본에 맞춘다.

## 1. LAB Facebook — 학습 방식 소개 / L2

계정: [SYNK LAB · synkworld](https://www.facebook.com/synkworld)

**대상과 역할:** 몽골어권 한국어 학습자와 수업을 검토하는 성인·보호자가 자신에게 맞는 교육인지 판단하도록 돕는다. 학습자가 어떤 경험을 하게 되는지 실제 예시로 보여준다.

**첫 게시물 예시:** 「한국어로 말해야 하는 순간, LAB에서는 이렇게 연습합니다」. 실제 게시에서는 상황 설명과 안내를 몽골어권 독자가 이해할 수 있게 제공하고 한국어 연습 표현을 함께 둔다.

**카드 5장 구성 제안:**

1. 학습자가 겪는 구체적인 상황 하나. 예: 상대의 말을 잘 못 들었지만 다시 물어보기 어려운 순간.
2. LAB가 도울 사람과 목표. 자기 상황에서 한국어로 말을 꺼낼 수 있도록 연습한다는 설명.
3. 어떻게 연습하는지. 상황을 이해하고 먼저 시도한 뒤, 필요한 도움을 받아 다시 해 보는 흐름.
4. 같은 상황의 실제 학습 카드·화면. 수업 설명이 어떤 연습으로 이어지는지 보여준다.
5. 현재 확인 가능한 학습 자료·과정 안내와 다음 행동. 제공 중인 것과 준비 중인 것을 구분한다.

**만들 결과물:** 설명 글 1개 + 소개 카드 약 5장. 카드 장수가 발행본 수를 늘리지는 않는다.

**재사용과 추가 작업:** Telegram과 같은 학습 상황·이미지를 공유하고, 이 게시물에는 학습 방식과 대상 설명을 붙인다. A 영상에서 유호가 나오는 프레임을 가져올 필요는 없다.

**독자가 할 일:** 학습 예시를 살펴보고 수업 방식·현재 제공 범위를 확인한다. 실제로 연결할 자료·안내가 준비된 곳으로 연결한다.

## 2. LAB Telegram — 첫 연습 자료와 사용 안내 / L3

계정: [@synkmn](https://t.me/synkmn)

**대상과 역할:** 채널에 들어온 학습자가 무엇을 받아 볼 수 있고, 지금 무엇부터 하면 되는지 알게 한다.

**첫 게시물 예시:** 「환영합니다. 오늘은 다시 말해 달라고 부탁하는 상황을 연습해 봐요」. 제목·사용 안내는 몽골어로 이해할 수 있게 준비한다.

**구성 제안:**

1. 짧은 환영과 이 채널에서 받을 자료 안내.
2. 상황과 목표가 분명한 학습 카드. 누가 누구에게 무엇을 말하려는지 보여준다.
3. 먼저 직접 말해 보거나 적어 볼 과제 하나.
4. 필요할 때 도움을 찾는 실제 방법과 다시 시도할 안내. 아직 없는 힌트 버튼·자동 평가 기능을 약속하지 않는다.
5. 카드·자료를 다시 찾을 수 있는 위치 또는 실제 준비된 자료 링크.

**만들 결과물:** 환영·사용 안내 글 1개 + 학습 카드 1~2장. 다운로드 파일이 필요하면 같은 카드 원본으로 만든다. 실제 운영 방식이 정해지지 않은 제출·피드백 서비스는 약속하지 않는다.

**재사용과 추가 작업:** Facebook의 학습 상황과 자료를 공유하되, 여기서는 사용 순서와 직접 시도할 과제를 중심에 둔다. 얼굴 없는 구성에서는 A 출연 영상을 첨부하지 않는다. 실제 학습 자료가 준비돼 있다면 새 이미지 대신 그 자료를 사용할 수 있다.

**독자가 할 일:** 자료 열기 → 한 번 말하거나 적어 보기 → 필요할 때 도움을 보고 다시 시도하기.

## 3. LinkedIn 개인 — 유호의 역할과 문제 해결 사례 / S3

계정: [양유호](https://www.linkedin.com/in/유호-양-5800b8433/) · 현재 운영 개인 계정

**대상과 역할:** 기업·기관 담당자와 협업자가 유호가 무엇을 만들고, 어떤 판단을 하며, 어떤 일을 함께할 수 있는지 이해하도록 한다.

**첫 게시물 예시:** 「SYNK를 만들며, AI가 만든 결과를 실제로 쓸 수 있게 다듬고 있습니다」. 소재는 실제로 맡은 작업에서 고른다.

**구성 제안:**

1. 누구이며 무엇을 만드는지 짧게 소개한다. 유호의 범위를 SYNK 전체로 설명한다.
2. 실제 작업 하나와 그 작업에서 맡은 역할을 밝힌다.
3. 어떤 문제가 있었고 어떤 기준으로 수정했는지 보여준다.
4. 전후 이미지와 현재 확인된 결과를 붙인다. 실제 고객 성과나 시간 절감 수치가 없으면 만들어 넣지 않는다.
5. 지금 대화할 수 있는 협업 주제와 준비 중인 제공 범위를 짧게 연결한다.

**만들 결과물:** 사례 중심 글 1개 + 전후 비교 이미지 1~3개 정도. 이력서 전체나 별도 소개 영상은 필요하지 않다.

**재사용과 추가 작업:** Threads·X 작업 기록의 글·이미지를 기본으로 사용한다. 이미 역할과 결과가 충분히 설명돼 있으면 그대로 공유할 수 있고, 부족하면 담당 역할·협업 안내만 보충한다. 회사 소개 C1에서는 이 사례를 회사의 실제 결과로 다시 활용할 수 있다.

**독자가 할 일:** 결과물과 담당 역할을 확인하고 관련 협업 대화를 시작한다.

## 4. 네이버 블로그 — 실제로 따라 할 수 있는 방법 / S5

계정: [유호 · AI와 회사 만들기 / synkshift](https://blog.naver.com/synkshift)

**대상과 역할:** 특정 AI 도구·스킬·작업 방법을 찾는 사람이 글을 보고 실제로 한 번 해 볼 수 있게 한다. 제작 사례의 해결 방법을 자세히 설명하는 용도로도 쓴다.

**첫 게시물 예시:** 「[선정한 GitHub 스킬]로 [실제 작업] 해보기: 준비부터 결과 확인까지」. 대괄호는 기획상의 자리표시자이며 실제 게시 전 검증한 도구·작업명으로 바꾼다. 스킬을 별도로 선택하지 않으면 SNS 커버에서 발견한 문제를 고친 방법을 소재로 삼을 수 있다.

**구성 제안:**

1. 이 글로 할 수 있는 일과 실제 완성 예시를 먼저 보여준다.
2. 어떤 사람·작업에 맞는지와 필요한 도구·파일·이용 조건을 설명한다.
3. 공식 원문 위치와 준비·설정 방법을 실제 화면으로 안내한다.
4. 실행 순서를 단계별 화면과 함께 보여준다.
5. 결과가 제대로 나왔는지 확인하는 방법과 실제 겪은 문제·해결을 적는다.
6. 아직 안 되는 부분이나 다른 조건이 필요한 부분을 명확히 적고 관련 작업·원문으로 연결한다.

**만들 결과물:** 상세 글 1개 + 필요한 단계별 화면. 모든 클릭마다 새 이미지가 필요한 것은 아니며 따라 할 때 헷갈리는 부분을 우선 보여준다.

**재사용과 추가 작업:** synkbrief 시연 영상의 화면·실행 결과·설명을 가져온다. 영상에서 생략한 준비 조건과 정확한 순서를 글로 보충한다. S4가 별도 스킬을 다루면 그 스킬의 화면을 사용하며 다른 SYNK 작업 이미지를 억지로 연결하지 않는다.

**독자가 할 일:** 같은 작업을 직접 수행하고 자신의 결과를 확인한다. 검색 유입이나 상위 노출은 이 구성만으로 보장되는 결과가 아니다.

## 5. Tistory — 시도·판단·수정을 따라가는 제작기 / S6

계정: [유호 · AI와 회사 만들기](https://yuhobuilds.tistory.com/)

**대상과 역할:** SYNK를 만드는 과정에 관심 있는 사람이 유호가 문제를 어떻게 발견하고 어떤 이유로 결과를 바꿨는지 이해하도록 한다.

**첫 게시물 예시:** 「SYNK SNS 커버를 만들고, 어긋난 부분을 고쳐 간 과정」. 실제 전후 원본이 확보되는 사례로 구체화한다.

**구성 제안:**

1. 처음 무엇을 만들려 했는지와 중요하게 본 조건.
2. 첫 시도에서 나온 결과와 마음에 걸렸던 부분.
3. 문제를 어떻게 확인했고 어떤 수정 방법을 고려했는지.
4. 무엇을 선택·수정했고 왜 그렇게 정했는지.
5. 수정 전후의 같은 부분을 비교한 이미지와 현재 결과.
6. 이번에 배운 점과 아직 남아 있는 일.

**만들 결과물:** 제작기 1편 + 초기안·수정안·결과 이미지. 여러 날짜의 내부 이벤트는 독자가 이해할 수 있는 문제 하나의 흐름으로 묶는다. 사용하지 않은 시도나 확인하지 않은 성과를 추가하지 않는다.

**재사용과 추가 작업:** Threads·X의 짧은 기록을 더 자세히 풀 수 있다. 네이버 글이 사용법과 선택 이유를 함께 충분히 담고 있다면 같은 글을 재사용할 수 있다. 플랫폼 이름이 다르다는 이유만으로 두 이야기를 새로 만들지는 않는다.

**독자가 할 일:** 제작 과정을 읽고 관련 완성물이나 다음 작업으로 이어간다.

## 6. Behance — 디자인 프로젝트의 전체 결과 / S7

계정: [yuhobuilds](https://www.behance.net/yuhobuilds)

**대상과 역할:** 디자인 협업자나 발주 검토자가 실제 프로젝트의 목표·구성·디테일·적용 모습을 한 번에 살펴보도록 한다.

**첫 게시물 예시:** 「SYNK SNS Visual Identity — Felt & Glass」. 최근 SNS 커버 작업을 후보로 삼되 실제 승인 결과와 제작 범위를 확인해 제목을 정한다.

**프로젝트 구성 제안:**

1. 대표 완성 이미지와 프로젝트명.
2. 무엇을 위한 작업인지, 유호가 어느 부분을 맡았는지 설명.
3. 프로젝트의 핵심 시각 요소와 선택 이유.
4. 실제 계정별 적용 디자인을 전체 구성으로 보여주기.
5. 중요한 문제·수정 한두 가지를 전후 비교로 보여주기.
6. 재질·글자·배치 등 확인할 만한 디테일과 최종 결과.
7. 본인의 기여·사용한 도구·협업 정보를 실제 작업에 맞춰 표시.

**만들 결과물:** 프로젝트 1개 + 표지 + 본문 이미지·설명. 대표·전체 적용·전후 비교·디테일의 4~6개 구획 정도로 시작하고 확보된 결과에 맞게 조절한다. 이미지 여러 장이 들어가도 프로젝트는 1종이다. Behance는 프로젝트 안에 파일·미디어·텍스트를 조합할 수 있다. [공식 프로젝트 안내](https://help.behance.net/hc/en-us/articles/204483684-Guide-Create-Publish-A-Project)

**재사용과 추가 작업:** 기존 승인 디자인, Tistory에 쓰는 수정 이유, 다른 게시물의 전후 이미지를 공유한다. 필요한 추가 작업은 프로젝트의 순서·표지·디테일 편집이다. 짧은 수정 기록 하나만으로 전체 프로젝트가 충분히 설명되지 않으면 기존 완성물 자료를 보충한다.

**독자가 할 일:** 전체 작업을 검토하고 관련 포트폴리오·협업 안내를 확인한다.

## 7. Pinterest — 대표 디자인을 발견하는 입구 / S8

계정: [SYNK SHIFT · synkshift](https://www.pinterest.com/synkshift/)

**대상과 역할:** 디자인 아이디어나 작업 참고 자료를 찾는 사람이 대표 결과를 발견하고 저장하며 전체 프로젝트로 이동하게 한다.

**첫 게시물 예시:** 「펠트와 유리 질감을 활용한 SYNK SNS 커버 디자인」.

**구성 제안:**

1. 전체 프로젝트를 가장 잘 대표하는 완성 이미지 1장.
2. 무엇을 만든 디자인인지 구체적으로 알 수 있는 제목.
3. 적용 대상·주요 특징을 짧게 설명.
4. 실제 준비된 Behance 프로젝트나 상세 제작기 링크.

**만들 결과물:** 이미지 핀 1개 + 제목·설명·목적지 링크. 필요한 경우 대표 이미지를 읽기 쉬운 구도로 자른다. Pinterest는 핀에 제목·설명·링크를 붙일 수 있다. [공식 핀 안내](https://help.pinterest.com/en-gb/article/create-a-pin-from-an-image-or-video)

**재사용과 추가 작업:** Behance의 대표 이미지를 그대로 쓸 수 있으면 재사용한다. 새 디자인을 제작할 필요는 없으며, 추가 작업은 필요한 크롭과 게시 정보 정리다. 작은 화면에 프로젝트 전체 설명을 모두 넣을 필요는 없다.

**독자가 할 일:** 저장하거나 상세 프로젝트를 살펴본다. 아직 공개하지 않은 프로젝트는 향후 연결 대상으로 준비하고, 실제 발행 때 존재하는 도착지를 사용한다.

## 8. 카카오톡 채널 — 제공 범위와 문의 안내 / S9

계정: [SYNK SHIFT](https://pf.kakao.com/_kvlrX) · 검색용 ID `synkshift`

**대상과 역할:** 기업·기관 담당자나 협업 희망자가 어떤 도움을 준비하는 곳인지, 무엇을 알려주면 대화를 시작할 수 있는지 알게 한다.

**첫 게시물 예시:** 「AI 업무 활용·교육·브랜딩, 이런 이야기를 나누고 싶습니다」.

**구성 제안:**

1. 누구를 위한 곳인지와 현재 준비 중인 제공 범위.
2. 실제 작업 사례 1개를 보여주며 어떤 종류의 문제를 다뤘는지 설명.
3. 문의할 때 알려주면 좋은 내용: 하고 있는 업무, 현재 어려움, 원하는 결과.
4. 채널에서 대화를 시작하는 안내와 현재 확인 가능한 관련 자료.

**만들 결과물:** 공개 소식 글 1개 + 안내 카드 2~3장 정도. 대상·범위, 사례, 문의 방법을 나눌 수 있고 짧으면 카드 수를 줄여도 된다.

**재사용과 추가 작업:** 개인 LinkedIn의 협업 소개와 회사 소개의 SHIFT 설명, 실제 제작 사례 이미지를 공유한다. 해당 사례가 직접적인 도움이 되는 경우 Threads·X용 글·이미지도 사용할 수 있다. 추가로 필요한 것은 문의자가 이해할 제공 범위와 질문 안내다.

**독자가 할 일:** 자신의 업무·어려움·희망 결과를 설명하며 문의한다. 정해지지 않은 가격·교육 일정·납기·완료 실적을 만들어 넣지 않는다. 이번 계획은 공개 소식 제작이며 친구 대상 메시지 발송 작업이 아니다.

## 9. LinkedIn 회사 — SYNK의 가치·사업·실제 결과 / C1

계정: [SYNK · synk-im](https://www.linkedin.com/company/synk-im/)

**대상과 역할:** 회사·기관·협력사가 SYNK가 어떤 문제를 돕고 무엇을 만들며 어떤 협업을 준비하는지 이해하도록 한다.

**첫 게시물 예시:** 「각자의 목표와 상황에 맞는 도움을 만드는 SYNK입니다」.

**구성 제안:**

1. SYNK가 제공하려는 가치와 개인화 시스템의 방향을 짧게 소개.
2. LAB의 한국어 학습, SHIFT의 기업·기관 AI 활용과 브랜딩, PULSE의 콘텐츠·IP, PATH의 유학·취업 준비를 구분.
3. 현재 공개 가능한 실제 학습 자료·제작물·감상 콘텐츠 등 대표 결과 제시.
4. 제작물이 존재하는 상태와 교육·컨설팅·상담 등 서비스 준비 상태를 구분.
5. 관심 분야에 맞는 공식 정보·협업 문의로 연결.

**만들 결과물:** 회사 소개 글 1개 + 브랜드별 제공물과 실제 결과 이미지. 카드로 만들면 회사 방향·사업 구분·실제 사례·다음 행동의 4개 구획 정도로 시작한다.

**재사용과 추가 작업:** LAB 자료, SHIFT 작업 사례, 회사의 현재 설명을 공유한다. 개인 LinkedIn 사례를 회사의 실제 결과로 활용할 수 있고, 회사가 하는 일에 필요한 설명만 더한다. 한 사례를 활용할 때 해당 사례가 회사 전체의 모든 역량·성과를 증명하는 것처럼 확대하지 않는다.

**독자가 할 일:** 관심 사업과 실제 결과를 확인하고 협업 가능성을 판단한다.

## 10. Substack — 앞으로 받을 내용을 보여주는 첫 편지 / C2

계정: [SYNK · 한국어와 AI](https://synklab.substack.com/)

**대상과 역할:** 한국어 학습 자료를 원하는 사람과 AI 활용·제작 이야기를 읽으려는 사람이 자신에게 어떤 내용이 유용할지 이해하도록 한다. 공통 편지 안에서도 LAB·SHIFT 구획을 명확히 한다.

**첫 게시물 예시:** 「SYNK의 첫 편지: 한국어를 연습하고, AI로 만들어 가는 이야기」.

**구성 제안:**

1. 유호의 짧은 인사와 편지를 시작하는 이유.
2. LAB 구획: 받을 학습 자료의 성격과 이번에 바로 해 볼 얼굴 없는 학습 카드 1개.
3. SHIFT 구획: 실제 제작 과정·GitHub 스킬과 도구 추천·AI 소식 중 어떤 내용을 다룰지와 이번에 읽을 작업 사례 1개.
4. 해당 자료·글로 이어지는 실제 링크.
5. 독자가 자신에게 맞는 내용을 계속 읽고 구독할 수 있도록 안내.

**만들 결과물:** 첫 편지 1편 + LAB·SHIFT 샘플 이미지. LAB 독자가 이해할 수 있도록 인사·구획·자료 이용 안내에 필요한 몽골어를 제공하고 한국어 연습 표현은 유지한다. 자동 언어 분리나 선택 구독 기능이 이미 설정돼 있다고 가정하지 않는다.

**재사용과 추가 작업:** LAB Telegram 카드, Tistory 제작기의 요약, synkbrief의 검증된 도구·소식 자료를 공유한다. 회사 소개를 바탕으로 인사를 쓰되 실제 샘플을 함께 보여준다. 별도 촬영이나 새 사례는 필요하지 않다.

**독자가 할 일:** 자신에게 맞는 샘플을 열어 보고 이후 편지를 계속 읽을지 판단한다. 정해지지 않은 일간·주간 발행 빈도는 약속하지 않는다. 웹 게시와 이메일·앱 수신함 발송은 구분되며, 이번 상세안은 원고 기획이다. [Substack 공식 발행 안내](https://support.substack.com/hc/en-us/articles/360037831771-How-do-I-publish-a-new-post-on-Substack)

## 제작을 묶는 방법

| 함께 쓸 자료 | 재사용할 곳 | 필요한 추가 구성 |
|---|---|---|
| LAB 상황·학습 카드 | Facebook·Telegram·Substack, 회사 소개의 학습 사례 | 수업 방식 / 자료 사용 순서 / 편지의 소개 문맥 |
| 실제 제작 사례·문제·판단·전후 이미지 | Threads·X·개인 LinkedIn·Tistory·Behance·회사 LinkedIn·카카오톡, 관련될 때 synkbrief·네이버 | 대상 독자에게 빠진 설명만 보충; 같은 완성본으로 충족하면 그대로 공유 |
| GitHub 스킬·도구의 실제 시연 | synkbrief·네이버 블로그·Substack, 실제 SYNK 적용 경험이 있으면 유호 채널 | 짧은 시연 / 상세 실행 단계 / 선별 소개 |
| 대표 완성 디자인 | Behance·Pinterest·관련 SNS 작업 기록 | 전체 프로젝트 구성 / 대표 이미지와 상세 링크 |
| 회사·제공 범위 설명 | 회사 LinkedIn·개인 LinkedIn·카카오톡·Substack | 회사 소개 / 담당 역할 / 문의 방법 / 받을 콘텐츠 안내 |

우선 학습 예시와 실제 제작 사례를 고른 다음 공통 원본을 정리한다. 역할에 맞는 글·카드를 만들고, 그 결과를 프로젝트·핀·편지로 이어간다. 네이버 글이 다룰 도구가 별도이면 해당 시연을 먼저 확보한다. Pinterest의 상세 링크, Substack의 샘플 링크는 연결할 자료가 준비된 뒤 확정한다.

현재 첫 발행안의 수량은 **이 문서의 10종·10곳 + S2 작업 기록 1종·2곳 + S4 영상 1종·3곳 = 출연 없는 12종·15곳**이다. 콘텐츠를 실제로 합치거나 배포처를 추가하기로 하면 역할 충족 여부를 보고 완성본과 게시 수를 다시 계산한다. 현재 수량을 맞추려고 불필요한 별도 원고나 촬영을 추가하지 않는다.
