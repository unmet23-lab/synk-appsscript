# PULSE 고객 앱 「마케팅 성과」 — 화면과 서버가 함께 쓰는 약속 (v1 · 2026-11-16)

유호님이 11-16에 「프론트도 같이 새 세션에서 시작해 … 백엔드는 여기서 하자」로 시작한 일이다. 화면 세션과 서버 세션이 따로 짓기 때문에, 둘이 주고받는 자료의 꼴을 이 문서 한 곳에 둔다. 꼴을 바꾸려면 이 문서를 먼저 고치고 상대 세션에 알린다.

## 무엇을 짓나

PULSE 고객 앱(`docs/마케팅/온라인마케팅지도/engagement/company/public/pulse-app/`)의 고객 방에 「마케팅 성과」 칸 하나를 더한다. 고객은 SYNK가 재서 올린 리포트를 읽기만 한다. 고객이 쓰는 것은 없다. 리포트는 직원이 올린다. 재는 일은 서버가 하지 않는다(브라우저로 재는 일이라 이 PC에서 돈다).

배경은 [결정](../../_ops/결정.md) 11-16 「PULSE 제작 뒤 마케팅 라인업 판정」에 있다. 메인 상품은 월 묶음의 상위 등급(루프 엔진)이고, 이 칸이 그 등급의 고객이 보는 화면이다. 지금은 실제 고객이 없어서 SYNK 자신을 첫 고객처럼 넣어 본다.

## 스위치

- PULSE 손님 기능 스위치(`pulse-features.mjs`, DB 문서 `pulseFeatureSettings`)에 `marketing`을 더한다. 기본은 끔이고 관리자만 바꾼다.
- 꺼져 있으면 아래 고객 경로는 404를 낸다. 화면은 칸을 그리지 않는다.
- 화면은 `GET /pulse/api/features`의 `marketing` 값으로 칸을 그릴지 정한다.

## 고객 경로 (화면이 부른다)

고객 세션 쿠키(`synk_pulse_session`)로 그 고객의 프로젝트 하나만 본다. 둘 다 읽기다.

| 경로 | 답 |
|---|---|
| `GET /pulse/api/marketing` | `{ "reports": [ReportHead, …] }` 최신 회차가 앞이다. 없으면 빈 배열이다 |
| `GET /pulse/api/marketing/report?kind=<kind>&run=<runId>` | `Report` 한 건. 없으면 404다 |

`ReportHead`는 `{ kind, runId, title, measuredAt, summaryLine }`이다. `summaryLine`은 서버가 리포트에서 뽑은 한 문장이다.

직원 경로(올리기, 지우기, 직원 화면에서 보기)는 서버 세션이 짓는다. 화면 세션의 v1 범위가 아니다.

## 리포트의 꼴

모든 리포트에 있는 칸은 다음과 같다.

```json
{ "kind": "ai-search", "version": 1, "runId": "20261116-1", "title": "AI 검색 노출 1회차",
  "measuredAt": { "from": "2026-11-15T20:29:11Z", "to": "2026-11-15T21:33:06Z" },
  "notes": ["읽는 법이나 주의를 적은 평범한 문장"] }
```

### `ai-search` — AI 답변에 브랜드가 나오는가

```json
{ "subject": { "brand": "SYNK", "site": "synk.im" },
  "services": [{ "id": "perplexity", "name": "퍼플렉시티", "condition": "로그아웃" }],
  "questions": [{ "id": "K01", "group": "PULSE", "lang": "ko", "text": "…", "branded": false }],
  "cells": [{ "q": "K01", "s": "perplexity", "answered": true, "mentioned": false, "cited": false,
              "sources": ["kmong.com"], "aiBriefing": null, "excerpt": "답의 앞 400자", "ms": 16000 }],
  "summary": {
    "general": { "total": 120, "answered": 111, "mentioned": 0, "cited": 0 },
    "branded": { "total": 30, "answered": 29, "mentioned": 27, "cited": 8 },
    "byService": [{ "s": "perplexity", "generalTotal": 24, "generalMentioned": 0, "generalCited": 0,
                    "brandedTotal": 6, "brandedCited": 2, "avgMs": 16000 }],
    "topSources": [{ "host": "youtube.com", "count": 21 }] } }
```

- `branded`는 질문에 브랜드 이름이 든 질문이다. 언급률과 인용은 `branded`가 아닌 질문(일반 질문)으로 본다.
- `answered`가 `false`면 답을 받지 못한 건이다(가입을 요구했거나 답이 비었다). 화면은 그 칸을 「답 없음」으로 보이고, 비율을 보일 때는 `answered` 수를 분모로 쓴다. `byService`에도 `generalAnswered`와 `brandedAnswered`가 온다.
- `aiBriefing`은 네이버에서만 `true`나 `false`이고 다른 서비스는 `null`이다.
- 순위는 재지 않고 보이지 않는다. 같은 질문에도 답이 회차마다 달라서다.

### `competitor-ads` — 경쟁사가 켜 둔 광고

```json
{ "method": "메타 광고 라이브러리, 모든 나라, 켜진 광고",
  "competitors": [{ "name": "트이다", "query": "Teuida", "resultLabel": "약 65", "read": 57, "own": 54,
                    "reliable": true, "note": "",
                    "ads": [{ "id": "1234567890", "startedAt": "2026-11-02", "advertiser": "Teuida",
                              "text": "본문 앞머리", "multiVariant": false }] }],
  "changes": null }
```

- `reliable`이 `false`면 낱말이 흔해 다른 광고주가 섞인 것이다. 화면은 수를 크게 보이지 않고 `note`를 함께 보인다.
- `changes`는 첫 회차에 `null`이다. 둘째 회차부터 `{ "since": "<앞 runId>", "started": [광고…], "stopped": [광고…], "longRunning": [광고…] }`가 온다.

### `label-review` — 납품 영상의 표기와 규제 검수

```json
{ "checklist": [{ "id": 1, "title": "플랫폼 AI 표시" }],
  "items": [{ "title": "영상 이름", "venue": "올린 곳", "publishedAt": "2026-11-08",
              "verdicts": ["check", "na", "na", "na", "ok", "na", "ok", "check"],
              "findings": [{ "check": 1, "verdict": "check", "quote": "근거 문장", "why": "까닭" }] }],
  "summary": { "items": 20, "hit": 0, "check": 9, "norecord": 4, "unread": 13 } }
```

`verdicts`는 `checklist` 순서대로이고 값은 여섯 가지다. `hit`(걸림), `check`(확인 필요), `ok`(문제없음), `na`(해당 없음), `norecord`(기록 없음), `unread`(원고를 읽지 못함).

### `memo` — 이번 달 한 장

```json
{ "headline": "한 문장 결론", "body": ["문단", "문단"], "nextActions": ["다음 달 할 일은 셋까지"] }
```

## 지킬 것

- 모든 문자열은 평문이다. 화면은 `textContent`로만 넣는다. 서버도 올릴 때 길이와 꼴을 검사한다.
- 바깥 링크는 화면이 만든다. 광고는 `https://www.facebook.com/ads/library/?id=<id>`이고 `id`는 숫자만 받는다. 출처는 호스트 이름만 보이고 링크를 걸지 않는다.
- 리포트가 없으면 빈 상태를 보인다. 「아직 잰 것이 없습니다」처럼 무엇이 올지 한 줄로 적는다.
- 매출, 순위, 노출을 약속하는 글을 화면에 쓰지 않는다. 약속하는 것은 잰 횟수와 리포트다.
- 화면 글에 AI 서비스 이름이 나오는 것은 이 칸에서만 허용한다. 무엇을 쟀는지가 그 이름이기 때문이다.
