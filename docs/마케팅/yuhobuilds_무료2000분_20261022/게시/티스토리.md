**본문**

GitHub에 코드를 올릴 때마다 도는 자동 검사(Actions)가 빨간불인데 실패한 단계가 하나도 없다면, 코드보다 무료 분부터 보세요. 저는 2026년 10월 20일 19:20부터 하루 넘게 이 상태였고, 18번의 검사가 모두 「단계 0개 · 1~3초」로 끝났습니다. 아래에 빨간불 읽는 법과 돈 안 들이고 검사를 되살리는 길 둘을 적습니다.

〔유튜브 쇼츠〕

## 무슨 일이 있었나

AI로 코드를 쓰면서 비공개 저장소에 하루에도 여러 번 올립니다. GitHub Free 계정의 비공개 저장소는 Actions 무료 분이 한 달 2,000분이에요. 그걸 다 쓰자 검사가 시작도 못 하고 끝났습니다. 실행을 열면 이런 메시지가 붙어 있었어요.

```
The job was not started because recent account payments have failed or your spending limit needs to be increased.
```

「결제가 실패했거나 한도를 올리라」는 뜻인데, 저는 결제 수단을 넣은 적이 없었습니다. 결제 화면을 열어 보니 2,000분 중 2,000분을 썼고, 예산은 $0이라 막혀 있었어요. 뒤쪽 — 무료 분 소진이 원인이었습니다.

그사이에도 코드는 계속 올라갔습니다. 검사를 되살려 처음 전체를 돌렸을 때 4,451개 중 16개가 빨갰어요. 그중 3개는 제 PC에서 너무 많이 동시에 돌린 탓이었고, 나머지는 검사가 멈춘 사이 쌓인 진짜 회귀였습니다.

## 빨간불 읽는 법

- **단계에서 실패했다** → 코드부터 봅니다.
- **단계가 0개이고 몇 초 만에 끝났다** → 코드가 아니라 한도·결제부터 봅니다.

## AI에게 가르게 하려면

저장소 폴더에서 gh 명령(GitHub CLI)을 쓸 수 있는 코딩 AI에게 아래를 붙여 넣으면, 실패한 실행을 「코드 쪽」과 「한도·결제 쪽」으로 갈라 표로 줍니다. 【최근 30개】는 개수(최근 50개)나 기간(10월 20일부터 21일까지)으로 바꿔도 돼요. 10월 22일 제 저장소에 그 기간으로 붙여 넣어 보니, 위의 「단계 0개」 실행은 모두 한도·결제 쪽으로, 빨간 시험 16개가 난 실행은 코드 쪽으로 갈렸습니다.

```
이 저장소의 GitHub Actions 실행 가운데 【최근 30개】를 보고, 실패한 실행을 둘로 갈라 줘.
- 단계에서 실패한 실행: 코드 쪽 문제. 실패한 단계 이름과 오류 첫 줄을 적어 줘.
- 단계가 하나도 돌지 않았거나 몇 초 만에 끝난 실행: 한도·결제 쪽 문제. 그 실행에 붙은 안내 문구를 원문 그대로 적어 줘.
실행 번호 · 시각 · 걸린 시간 · 갈래 · 근거를 표로 보여 주고, 한도 쪽이 있으면 남은 무료 분을 GitHub 어디서 보는지도 알려 줘. 아무것도 다시 돌리거나 고치지는 마.
```

이 프롬프트와 다른 편의 프롬프트는 https://synk.im/prompts 에 모아 두었어요.

## 공짜로 다시 돌리는 길 둘

1. **감출 게 없는 저장소라면 공개로.** GitHub 문서에 「GitHub Actions usage is free for self-hosted runners and for public repositories that use standard GitHub-hosted runners.」라고 적혀 있습니다. 10월 19일 다른 저장소에서 같은 일이 났을 때 공개로 바꿨고, 첫 실행에서 시험 1,940개가 실패 없이 돌았어요. 공개하기 전에 비밀값·개인정보가 커밋에 없는지 꼭 먼저 보세요.
2. **비공개로 둬야 하면 내 PC를 자체 실행기(self-hosted runner)로.** 예산이 $0인데도 잡을 받아 돌았고, 4,451개를 실패 0으로 통과했습니다(10월 21일 23:25, 9분 44초). 공개 저장소에는 자체 실행기를 붙이지 마세요. 누구나 PR을 열 수 있어서 남의 코드가 내 PC에서 돌 수 있습니다(GitHub 보안 문서).

자체 실행기 무료는 2026년 10월 22일 GitHub 문서 기준입니다. GitHub가 자체 실행기에도 분당 요금을 받겠다고 예고했다가 미뤄 둔 상태라, 쓰기 전에 문서를 한 번 확인하세요.
