# 말하기·웃음에서 유호 얼굴을 유지하는 방법 검토

2026-09-27 · 기술 검토. 생성·업로드·설치·결제를 수행하지 않았다. 이 문서는 제작 완료나 얼굴 재현 합격 증거가 아니다.

## 결론

정면 사진 한 장에서 새로운 입·턱·눈 움직임을 생성하는 경로와, 실제 유호의 움직이는 얼굴을 그대로 보존하는 경로를 분리해야 한다. 현재 실패한 test-07에 얼굴 묘사를 더 붙이는 것만으로 해결됐다고 주장할 근거는 없다. 바로 다음 검증은 **실제 촬영의 말하기→웃음 6~10초를 입력 영상으로 삼아 배경만 바꾸는 실험**이다. 다만 원본과 다른 한국어 대사를 말하게 만드는 단계는 별도 문제이며, 배경 수정 성공만으로 카페 대사 재현이 완성되지 않는다.

브라우저가 끊긴 현재 상태에서는 실제 촬영 구간을 골라 정리하고, 원래 얼굴 픽셀을 유지하는 로컬 합성 시험을 준비할 수 있다. 새 대사를 정확히 말하는 얼굴까지 오프라인에서 만들 수 있다는 증거는 아직 없다.

## 직접 본 자료와 한계

- `google-vids/test-07-frame-1p5.jpg`: 발화 중 눈이 크게 떠지고 입을 오므린 상태. 한 장의 기준 사진에는 이 표정의 실제 모양이 담겨 있지 않다.
- `google-vids/test-07-frame-7p5.jpg`: 이가 드러나는 생성 미소. 실제 웃음 프레임과 같은 표정으로 비교하기 전에는 치아·입꼬리의 닮음을 판정할 수 없다.
- `yuho-interview-face/interview-75s.png`: 실제 얼굴 기준을 확인했다. 정지 상태와 발화/웃음은 각각 합격해야 한다.
- test-07 프롬프트는 이미 정확한 얼굴, 작은 자연스러운 움직임, 미화 금지, 감정·타임라인을 자세히 명시한다. 이 조건을 반복하거나 ‘정확히’만 강화하는 것은 새 입력 증거가 아니다.

## 현재 공식 기능으로 할 수 있는 것

Google Vids의 `수정(Edit)`은 촬영한 영상 업로드, 3~10초 출력, 이미지 참조 최대 3장을 지원한다. 10초가 넘는 입력은 마지막 10초만 사용한다. 생성 탭의 이미지 재료는 최대 7장이다. 공식 도움말에는 얼굴 영역을 픽셀 단위로 잠그거나 실제 표정을 1:1 전달한다는 보장이 없다. [Vids 생성·수정 도움말](https://support.google.com/docs/answer/16143507?hl=en)

Google은 2026-09-23 Vids의 Omni 1.1 무료 접근과 1080p를 발표했다. 개별 계정의 남은 생성량과 당장 접근 가능한지는 실제 UI 확인이 필요하다. 현재 브라우저 연결 실패를 무료 할당량 소진으로 해석해서는 안 된다. [공식 발표](https://blog.google/products-and-platforms/products/workspace/gemini-omni-in-google-vids/)

Personal avatar는 본인이 휴대전화/태블릿의 QR 절차로 얼굴과 목소리를 새로 기록하는 기능이며, 현재 영어 지원으로 명시되어 있다. Vids 도움말은 AI Pro/Ultra의 아바타 이용을 미국으로 제한한다. 과거 영상을 무더기로 넣어 한국어 전용 얼굴 모델을 즉시 만드는 기능으로 설명하면 안 된다. [개인 아바타 도움말](https://support.google.com/docs/answer/16970930?hl=en), [이용 가능 계정](https://support.google.com/docs/answer/16143507?hl=en)

Omni API의 영상 참조는 Vids 웹 UI와 별개다. 공식 API 문서상 참조 영상은 최대 3개·각 3초이며 참조 음성은 무시된다. 영상 입력이 있다고 정확한 발화 연기 전달 기능인 것은 아니다. API에서는 업로드 영상의 발화를 새로운 대사로 연장하는 것도 제한한다. API의 무료 사용 가능성은 확인되지 않았으므로 우회 경로로 실행하지 않는다. [API 제한](https://ai.google.dev/gemini-api/docs/omni#limitations)

## 원본 영상 선정 기준

원본을 전부 생성기에 넣는 방식이 아니라, 최근 촬영물에서 다음 표정이 선명한 구간을 찾는다. 파일명·촬영 시점·시작/끝 초·프레임을 함께 기록한다.

1. 정면 또는 3/4 각도에서 자연스럽게 말하는 연속 구간. 입을 다문 자음, 입을 벌린 모음, 오므린 입이 포함되어야 한다.
2. 말하다가 작은 미소가 생기는 구간. 입꼬리만이 아니라 볼과 눈가가 함께 변하는 시간을 포함한다.
3. 치아가 보이는 큰 미소·실제 웃음의 시작→정점→회복. 무표정으로 웃음을 대체하지 않는다.
4. 1인, 얼굴 가림 없음, 흔들림/모션 블러 적음, 중간 컷 없음. 좌우 반전 여부, 강한 보정·필터 여부를 기록한다.
5. 같은 날짜·머리·수염 상태를 우선하고 다른 외모 시기는 혼합 학습처럼 묶지 않는다. 서로 다른 조명은 확인용으로는 유용하지만 얼굴 변형의 근거로 삼지 않는다.

실제 웃음이 있는 6~10초 원본 1개를 먼저 고른다. 참고 영상 여러 개를 급히 이어 붙여 생성 입력으로 쓰면 컷 경계와 표정의 인과 관계가 섞이므로 피한다. 전체 자료는 검증과 추가 실험에 활용한다.

## 최소 생성 실험: 서로 다른 문제를 한 번에 바꾸지 않기

### A. 실제 연기 보존 시험

입력은 선정한 실제 말하기→웃음 영상이다. 원래 음성, 길이, 인물, 옷, 카메라, 머리 움직임은 유지하고 배경만 카페로 바꾼다. 처음에는 추가 이미지 없이 실험해 기존 생성 얼굴이 다시 섞이지 않게 한다. 기존 Vids 멤버십/무료 한도 UI가 확인될 때 한 번 수행한다.

프롬프트 예시:

> Change only the background to a softly lit cafe. Keep the man, his face, every speaking and laughing movement, the original speech and audio, clothing, framing, and timing unchanged. One continuous shot.

이것은 보존 요구를 명확히 하는 지시이며 보존을 강제하는 잠금 기능은 아니다. 출력의 미소를 줄이거나 입을 숨겨 합격시키지 않는다.

### B. 로컬 얼굴 보존 합성

A에서도 얼굴이 다시 만들어지면, 생성 결과 전체를 그대로 쓰지 않고 **원본 영상의 머리·얼굴·목 또는 인물 전체를 마스크로 분리해 카페 배경 위에 합성**한다. 얼굴 내부는 원본의 같은 시점 RGB를 사용한다. 양끝 정지 이미지를 워핑하거나 생성된 눈·치아를 혼합하지 않는다. 머리카락 경계와 목의 접합은 추적/수동 로토스코핑으로 다듬는다.

기존 저장소의 `tools/AI누끼.py`는 정지 이미지용 rembg 도구로, 영상의 시간적 일관성을 보장하는 도구가 아니다. 파일이 있다는 것만으로 현재 런타임/모델을 사용할 수 있다고 단정할 수 없다. 프레임별 마스크를 사용할 경우 경계 깜빡임을 따로 검사하고 얼굴 내부는 언제나 불투명하게 유지해야 한다.

무료 Resolve에서도 기본 Polygon 매트·추적을 이용하는 방법은 있다. Magic Mask는 Studio 기능이므로 무료 기능으로 잘못 안내하지 않는다. 이미 설치된 환경만 확인해 사용한다. [Blackmagic 공식 로토스코핑 안내](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-17-Fusion-Visual-Effects.pdf), [Magic Mask 제한](https://documents.blackmagicdesign.com/UserManuals/DaVinci-Resolve-20-Advanced-Visual-Effects.pdf)

이 방법은 원본의 말과 웃음을 그대로 남길 수 있으나 새 카페 문장을 만들어 주지는 않는다. 결과는 연기 보존 시험이다. 대본까지 완성했다는 상태로 기록하면 안 된다.

### C. 카페 대사 재현

선정/전사 자료에 필요한 문장이 실제로 있는지 확인한다. 온전한 발화가 있으면 그 원본 구간을 사용한다. 없는 경우 새 문장을 입에 맞추려면 얼굴 생성/재연 단계가 필요하고, 다시 동적 얼굴 닮음 검증을 받아야 한다. 낱음절을 무리하게 짜깁기해 ‘실제 연기 그대로’라고 부르지 않는다.

전용 연기 전달의 예로 Runway Act-Two는 연기 영상+캐릭터 이미지/영상을 받아 표정·발화를 전달한다. 그러나 Standard 이상과 초당 5크레딧이 요구되므로 현재 무결제 즉시 대안으로 제시할 수 없다. 이 모델도 과한 표정에서 오류 가능성을 공식적으로 알리며 원본 픽셀 보존 방식이 아니다. [Runway 공식 안내](https://help.runwayml.com/hc/en-us/articles/42311337895827-Performance-Capture-with-Act-Two)

## 합격 검증

- 입력과 출력의 **같은 시점**을 비교한다. 원본의 무표정과 결과의 미소를 비교한 ‘닮음’ 평가는 무효다.
- 1배속 전체 재생과 0.5배속을 둘 다 본다. 말 시작, 입 다문 자음, 열린 모음, 미소 시작, 웃음 정점, 표정 회복을 반드시 포함한다.
- 얼굴을 비슷한 크기로 정렬한 A/B 화면을 만든다. 눈꺼풀/눈썹 높이, 입꼬리 상승·좌우 비대칭, 볼 접힘, 치아 노출, 턱 윤곽의 연속 변화가 실제 촬영과 같은 인상이어야 한다. 각 항목을 ‘미확인/다름/일치’로 기록한다.
- 얼굴이 움직이는 모든 순간을 검사한다. 첫 프레임·끝 프레임·중립 프레임만 좋은 결과는 불합격이다. 큰 웃음을 작게 줄인 결과도 불합격이다.
- B 방식에서는 얼굴 내부 마스크가 1인지와 해당 RGB가 같은 시점 원본에서 왔는지 합성 전에 확인할 수 있다. 인코딩 후에는 압축 차이가 생기므로 단순 바이트 동일성을 요구하지 않고 시간 오프셋·크롭·경계·재생을 확인한다. 이 검증은 **원본 보존 증거**이지 임의 생성 얼굴의 생체 유사도 점수가 아니다.
- 새 대사가 있는 최종본은 발음과 입모양 동기, 음성 자연스러움, 실제 웃음 닮음을 추가로 확인한다. ASR 대사 일치나 ffprobe 성공은 닮음/감정의 증거가 아니다.
- 최종 판단은 유호가 말하기와 웃음을 포함한 완성된 구간에서 본인이라고 느끼는지 확인한다. 제작자가 ‘동일 얼굴’이라고 단정하는 것보다 이 요구가 우선한다.

## 현재 상태와 다음 행동

현재 정보로 성공 가능성이 가장 높은 방향은 **실제 영상의 얼굴 움직임을 생성기의 참고만이 아니라 최종 영상의 원재료로 사용**하는 것이다. 생성 입력을 바꾸는 시험과 원본 보존 합성을 순서대로 확인한다. 브라우저 복구 전에는 원본 선정·시간 기록·동적 A/B 검증 자료·로컬 합성 가능성 확인을 진행한다. 동적 참고자료 구축만 완료됐다고 전체 목표를 달성으로 표시하지 않는다.
