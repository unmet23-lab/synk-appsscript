## 이번 변경

- Work/스킬 초안을 프로젝트별 지침 저장과 반복 사용으로 전면 교체했다. 계정 전체 맞춤 지침에 회의 규칙을 넣지 않는 이유와 여행 질문 가상 예시를 13~21초 장면 및 PDF 2쪽에 넣었다.
- 실제 프로젝트 만들기 → 프로젝트 설정 → 지침 전체 복사·저장 → 이번 메모 실행 → 형식 누락 보완 → 다음 회의 새 채팅 → 검토 후 복사 순서다.
- 실제 첫 응답의 근거 열 누락을 숨기지 않았고 보완 요청 뒤 네 열 결과를 보여준다. 두 번째 새 채팅도 실제 실행했지만 열 제목과 회의 일정 행은 달랐다. 항상 동일한 결과를 보장하지 않는다.
- 프로젝트와 계정 전체 지침을 구분하는 후속 기준은 유형별 제작 양식에 저장했다. 계정 전체 맞춤 지침은 변경하지 않았다.
- 새 비공개 연습 프로젝트에 가상 메모 2개를 사용했고 쉽게 다시 찾도록 고정했다. 별도 파일 업로드·공개 링크·메시지 전송은 하지 않았다.

## 재생성

이 폴더에서 `python build-guide.py` → PDF를 pdftoppm으로 페이지 이미지 출력 → assets/guide-1.png 및 guide-3.png 갱신 → `node build.mjs` → `npx hyperframes check` → `npx hyperframes render --quality delivery --fps 30 --workers 2 --output synkbrief-meeting-v6.mp4` → WebM 프록시 변환 → `node build-preview.mjs` 순서로 실행한다. 기존 v4 및 v5 중간 초안은 보존했다.

검증 원문은 verification/에 있다. 공개 댓글 자동 전달·실제 발행·사용자 최종 승인은 아직이다.

## 재생 화면 수정 · 2026-09-23

사용자가 IAB에서 흰 화면만 보인다고 보고했다. 같은 앱에서 시간은 흐르고 readyState=4인데 영상 표면은 흰색인 현상을 재현했다. 해당 시점의 WebM 파일 프레임은 정상이었다. 미리보기에서 디코딩된 프레임을 canvas로 표시하도록 변경하니 IAB 실제 스크린샷에서 장면·텍스트가 나타났다. 시작 표지, 구간 이동 후 표시, 재생, 소리 토글, 390/1280px QA를 확인했다. 화면 픽셀 검사에서 15초 장면의 어두운 픽셀 41,970개로 비어 있지 않음을 검증했다. 이전의 시간 증가만을 이용한 재생 검사는 화면 표시를 보장하지 못했다. 영상 원본과 PDF 내용은 변경하지 않았다.
