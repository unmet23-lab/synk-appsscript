# synkbrief 제작 방식 재검토

2026-09-22 · 최초 조사는 공개 원문과 데모 열람으로 진행했다. 후속 사용자 지시에 따라 HyperFrames + Impeccable로 15초 v3 도입 샘플을 렌더·검사했다. 실제 제작 상태는 아래 ‘후속 적용’과 연결한 작업 기록을 따른다. 사용자 시각 품질 승인과 도구 간 품질 비교는 아직 하지 않았다.

## 출발점

사용자는 98초 2차본도 이해하기 어렵고 요약·임팩트·디자인·여백이 부족하다고 평가했다. 현재 영상을 승인된 양식이나 대표작으로 사용하지 않는다. 채널은 AI 활용법뿐 아니라 뉴스·최신 정보·스킬 팁도 다룬다. 초보자가 이해할 수 있는 콘텐츠도 가능하다는 최신 사용자 지시를 따른다.

이번 조사는 화면을 꾸미는 기능뿐 아니라 설명 순서, 시각적 우선순위, 장면 전환과 실제 시연을 함께 개선할 수 있는지를 기준으로 했다. 아래 추천은 공개 자료에 근거한 적합성 판단이며 우리 콘텐츠에서 입증된 품질 순위는 아니다.

## 우선 검토할 조합

**HyperFrames로 영상 구성을 만들고, Impeccable로 화면의 정보 우선순위와 디자인을 점검하는 조합**을 우선 시험할 만하다. UI UX Pro Max는 필요할 때 디자인 자료를 찾는 보조 후보다. 여러 스킬을 한꺼번에 추가하는 것을 해결책으로 삼지 않는다.

| 후보 | 확인한 기능과 이번 작업에 대한 판단 | 확인 범위·한계 |
|---|---|---|
| [HyperFrames](https://github.com/heygen-com/hyperframes) | HTML/CSS 기반 영상 제작. 기획·디자인·모션·미디어·렌더용 스킬이 연결됨. 실제 화면을 설명하는 이번 작업에는 [general-video](https://github.com/heygen-com/hyperframes/blob/main/skills/general-video/SKILL.md)가 우선 후보. | 공식 쇼케이스 일부 재생 후 이번 회차의 한국어 15초 도입을 로컬 렌더·검사했다. 전체 회차 완성·사용자 시각 품질 승인은 아직 아님. |
| [Impeccable](https://github.com/pbakaus/impeccable) | critique, distill, layout, typeset, bolder, animate 등으로 핵심 정리·여백·글자 위계·시각적 강조를 다룸. | 실제 웹 데모 확인. 웹 디자인 중심이며 영상의 이해도나 편집 리듬을 자동 보장하지 않음. |
| [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) | 색·서체·레이아웃·인터랙션 등의 검색 가능한 디자인 자료와 설계 지침. | 원문·스킬 확인. 이 스킬로 만든 결과물을 직접 생성·비교하지 않음. 영상 연출 도구는 아님. |
| [AnyCoder](https://huggingface.co/spaces/akhaliq/anycoder) | 설명·프로젝트·URL에서 웹 코드를 만들거나 재설계하는 후보. 현재 UI의 Import·Redesign 확인. | 로그인 안내가 있는 초기 화면 확인. 생성 결과 품질은 미검증. 완성 영상 도구로 확인한 것은 아님. |
| [Qwen3-Coder-WebDev](https://huggingface.co/spaces/Qwen/Qwen3-Coder-WebDev) | React/HTML 생성·미리보기·수정. 간단한 인터랙티브 설명 장면의 보조 후보. | 입력 UI와 예시 프롬프트 확인. 생성·완성 결과물의 시각 품질은 미검증. |

HyperFrames의 [product-launch-video 스킬](https://github.com/heygen-com/hyperframes/blob/main/skills/product-launch-video/SKILL.md)은 캡처·브랜드 정보·스토리보드·장면별 연출을 연결하지만 제품 홍보에 가깝다. 이번 실제 ChatGPT 시연에는 general-video가 더 적합하다는 판단이다. 창작 시각물을 전제로 하는 faceless-explainer를 실제 UI 시연에 그대로 대입하지 않는다.

## 직접 볼 수 있는 예시

- [HyperFrames 공식 영상 쇼케이스](https://hyperframes.heygen.com/showcase): Website → video의 일부 구간에서 사이트 카드 회전과 글자 위계를 직접 확인했다. [해당 예시 소스](https://github.com/heygen-com/hyperframes-launches/tree/main/website-to-hyperframes)도 공개돼 있다. 이 연출을 튜토리얼에 그대로 복제하는 것을 권하는 것은 아니다.
- [Impeccable NEO MIRAI 실제 웹 데모](https://impeccable.style/neo-mirai/): 큰 제목·일러스트·영역별 위계를 확인했다. [제작 사례](https://impeccable.style/cases/neo-mirai/)에는 이미지로 만든 디자인 시안·브랜드 자료와 브라우저 수정 과정이 설명돼 있다. 참고 자료 없이 한 번의 요청만으로 나온 결과라는 증거는 아니다.

## Hugging Face 및 다른 대안

[AnyCoder README](https://huggingface.co/spaces/akhaliq/anycoder/blob/main/README.md)와 [Qwen 데모 README](https://huggingface.co/spaces/Qwen/Qwen3-Coder-WebDev/blob/main/README.md)를 확인했다. 웹 코드 생성에는 맞지만, 현재 필요한 영상의 요약·장면 구성·시각적 이해도를 종합적으로 해결했다는 증거는 찾지 못했다.

[DeepSite](https://huggingface.co/deepsite)는 현재 접속 화면에 Hugging Face Chat으로 이전한다는 안내가 있어 즉시 도입 후보의 우선순위를 낮췄다. [Space 원문](https://huggingface.co/spaces/enzostvs/deepsite/blob/main/README.md)도 확인했다.

[Remotion의 제품 시연 사례](https://www.remotion.dev/prompts/product-demo-for-presscut)는 대안으로 볼 수 있다. 다만 현재 보유한 렌더·API 스킬만으로 기획과 디자인이 자동 해결되는 것은 아니다. [회사 규모별 라이선스 조건](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)은 도입 시 별도로 적용한다. [OpenScreen](https://github.com/getopenscreen/openscreen)은 실제 화면 촬영의 자동 줌·커서 표현을 보조하는 후보이며 전체 콘텐츠 기획 도구와는 역할이 다르다.

## 최초 조사 당시 설치 참고 정보

skills.sh 순위와 원본 저장소를 함께 확인했다. 아래 수치는 2026-09-22 페이지의 대략적인 설치 집계이며 품질 점수가 아니다. 서비스별 집계 시점 차이가 있다.

| 스킬 | skills.sh 설치 집계 | 설치 명령 |

이 명령은 스킬 설치용이며 그 자체로 영상 엔진 설치나 결과물 생성 완료를 뜻하지 않는다. HyperFrames는 Node.js 22+·FFmpeg를 요구하고 Apache-2.0이다. 로컬 Node.js v24.18.0 환경에서 후속 설치와 15초 도입 렌더를 완료했으며 정확한 구성은 [v3 작업 기록](video-v3/README.md)을 따른다. Impeccable은 Apache-2.0, UI UX Pro Max는 MIT다. 외부 모델·음성·클라우드 API의 사용 조건과 비용은 별도다.

도입할 때는 프로젝트에 필요한 범위만 적용하고 기존 SYNK 로고·서체·자산과 사용자 결정을 우선한다. 외부 스킬의 미감 규칙을 모든 콘텐츠에 적용하는 새 말투·스타일 규정으로 만들지 않는다. 프로젝트 문서·훅·선호 저장을 바꾸는 설치 기능은 실제 적용 전에 내용을 확인한다.

## 도입 비교 제작과 남은 검토

전체 98초를 다시 만들기 전에 같은 주제로 15초 v3 도입 샘플을 만들었다. 아래 비교 포인트는 사용자 시각 검토에 사용한다. 이 샘플은 전체 따라 하기 튜토리얼을 대체하지 않는다.

1. ‘회의는 끝났는데, 내가 뭘 맡았는지 다시 찾고 있나요?’처럼 구체적 상황을 짧게 제시한다. 문구 자체는 후속 제작에서 조정할 수 있다.
2. 메모의 관련 문장만 강조하고 할 일·담당자·기한이 표로 정리되는 변화를 크게 보여준다. 실제 응답의 내용과 편집 강조 요소를 구별한다.
3. 휴대폰 크기에서 상황·결과·다음 행동이 바로 잡히는지 본다. 글자 양, 화면 대비, 여백, 읽는 시간, 움직임의 목적을 함께 비교한다.

사용자가 확인한 장면에서 유효한 요소만 활용법 유형 양식에 반영한다. 뉴스·업데이트·팁의 전개와 디자인은 각각 따로 발전시킨다.

## 후속 적용 · 매편 최상위 품질 요청

사용자는 “영상 하나하나 정말 최상위 초고퀄리티”를 원하며, HyperFrames + Impeccable이 적합하면 적용하고 추가로 필요한 도구를 알려달라고 했다. 이 조합을 현재 설명 영상의 기본 제작·그래픽 검토 도구로 선택한다. 모든 장르에서 최상위라는 비교 실험 결과는 없으며, 채널의 다른 유형은 목적에 맞게 선택한다.

- **HyperFrames:** 장면·모션·자막·오디오 조립. 기본 프레임워크 자체에도 사운드 조절 기능이 있다. [공식 음성·오디오 가이드](https://hyperframes.heygen.com/guides/voice-and-audio).
- **Impeccable:** 화면 구성·여백·글자 위계·명료성 검토. 웹 UI를 전제로 한 지침을 영상에 무조건 대입하지 않는다.
- **추가 우선순위 1 — 기존 DaVinci Resolve:** 전체 편집과 최종 사운드 마감. [Fairlight](https://www.blackmagicdesign.com/products/davinciresolve/fairlight)는 오디오 처리·음량 측정, [Fusion](https://www.blackmagicdesign.com/products/davinciresolve/fusion)은 합성·타이틀·키프레임 작업을 제공한다. 로컬 Resolve.exe의 제품 버전 21.1.0.14를 확인했다. 이번 작업에서 앱 실행·Studio 라이선스·연동은 시험하지 않았다.
- **추가 우선순위 2 — 필요할 때 OpenScreen:** [실제 화면 촬영·커서 보정](https://github.com/getopenscreen/openscreen)용 보조 후보. [자동 줌은 촬영 때 기록한 커서 데이터가 필요](https://getopenscreen.com/features/auto-zoom/)하므로 기존 MP4만으로 같은 결과를 얻는다고 설명하지 않는다. 설치·시연은 미진행이다.

이번 회차는 [15초 v3 도입 샘플](video-v3/preview.html)을 1080×1920·30fps MP4로 렌더했다. 새 펠트 상황 이미지와 [공식 자료 조사](video-v3/research.md)를 반영해 메모 → 표 → 미지정 기한 ‘확인 필요’를 보여주고, 기존 승인 효과음 2개를 넣었다. Typecast 연결이 닫혀 있어 내레이션은 없다. HyperFrames 검사에서 레이아웃 오류·경고 0건·대비 70/70 통과·런타임 오류 0건, Impeccable 검출 0건을 확인했다. 상세는 [video-v3 작업 기록](video-v3/README.md)에 둔다. 2차본 파일과 미리보기는 보존한다. 전체 회차 완성·사용자 승인·외부 게시 상태는 아니며, 검사 통과와 사용자 기대 품질 달성은 구분한다.
