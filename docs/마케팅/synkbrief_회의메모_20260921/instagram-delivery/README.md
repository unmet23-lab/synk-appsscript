## 준비된 전송 방식

이번 편의 게시물 ID와 계정 ID가 일치하고, 댓글에 독립된 `synk` 단어가 있으면 자료 페이지를 비공개 답장 한 통으로 보낸다. 대소문자는 구분하지 않는다. 동일인이 여러 번 요청하거나 Meta가 같은 알림을 재전송해도 중복 발송을 막는다. 다른 게시물·다른 계정·자기 댓글·오래된 이벤트는 보내지 않는다. 원문 댓글과 이름은 저장하지 않는다. 전송 오류나 응답 유실은 자동 재발송하지 않아 중복 DM을 피한다.

팔로우 문구는 엔딩 안내에 반영한다. **팔로우 여부에 따른 자료 잠금은 이번 요청에서 별도로 확정하지 않았으므로 사용하지 않는다.** 기존 상담 엔진에 팔로우 조회 함수가 있다는 사실과 자료 전달 게이트가 운영된다는 것은 다르다.

핵심 구현: 루트 `엔진_synkbrief.js`, `상담AI.js`의 전용 분기. 로컬 기능 시험 7개 통과. 기존 Meta 관련 동작 시험도 통과했으나, 전체 Meta 시험의 문서 검사 1개는 기존 삭제 문서 `docs/상담AI_개통_지금할일.md`가 없어 실패한다. 이것을 이번 작업의 통과로 처리하지 않았다. 배포 보안 표면 검사는 통과했다.

## 현재 남은 순서

1. @synkbrief에 1편을 게시한다. 이 설정 작업은 게시 승인을 대신하지 않는다.
2. 관리표의 1편 행에 게시물 링크를 넣고 **사용** 체크 → **등록 내용 적용**을 누른다. 과거의 `SYNKBRIEF_MEDIA_IDS` 수동 입력 방식은 사용하지 않는다.
3. **자동 발송 켜기** 후 다른 계정의 새 `synk` 댓글로 실제 DM 도착·자료 열기·중복 방지를 확인한다. 등록·단위 시험·초대만으로 실제 수신 완료라고 쓰지 않는다.

`SYNKBRIEF_DM_KEYWORD_ENABLED`는 기본 비활성이다. 영상 게시 전 직접 DM 키워드 경로를 시험해야 할 때만 별도로 활성화하며, 들어온 사용자 요청에만 응답한다.
