# synkbrief 자료 DM · 2026-09-26 Apps Script 운영 이력

현재 자료 등록·발송은 [댓글 DM 자료표](../../댓글DM_자료표.md)와 [제작·게시 연결](../../댓글DM_제작게시연결.md)을 따른다. 운영 정본은 Supabase `synkbrief-dm`이며, 이 문서의 시트 등록·자동 발송 켜기·Meta 토큰 갱신 절차는 이전 Apps Script 경로의 기록이다. 새 자료를 이 경로로 등록하거나 구형 발송을 다시 켜지 않는다.

## 당시 운영 가이드 원문

2026-09-26 · 다음 편마다 코드를 고치지 않고, 관리표의 한 행으로 자료를 등록하는 방식.

[자료 등록 관리표 열기](https://docs.google.com/spreadsheets/d/1sv6cim9BET2oQqJFXQU9xgyEMlhxDAu0lrojQJwDx1M/edit) → 아래쪽 **synkbrief_자료등록** 탭을 선택한다.

현재 @synkbrief 계정 연결·비공개 인증 저장과 수동 인증 점검은 완료했다. 첫 영상은 게시 전이므로 자동 발송은 꺼져 있고 활성 게시물은 0개다. 1편 초안은 입력해 두었다. 게시물 링크를 넣고 아래 5~7단계를 진행하면 된다. 실제 DM 도착은 아직 시험하지 않았다.

## 다음 영상을 올릴 때

1. PDF나 가이드를 공개 자료 페이지에 준비한다. 실제로 링크가 열리는지 확인한다.
2. @synkbrief에 영상을 게시한 뒤 Instagram의 **공유 → 링크 복사**를 누른다.
3. 관리 스프레드시트에서 상단 **synkbrief 자료 DM → 자료 등록표 열기**를 누른다.
4. 새 행에 아래 내용을 넣는다.

| 칸 | 넣는 내용 |
|---|---|
| 캠페인ID | 편마다 다른 이름. 예: `meeting-20260924`, `faceswap-01`. 발송 후 변경하지 않는다. |
| 콘텐츠 이름 | 사람이 알아볼 수 있는 영상 제목 |
| Instagram 게시물 링크 | 방금 복사한 @synkbrief 게시물 주소 |
| 댓글 키워드 | 영상에서 안내한 단어. 예: `synk` |
| 보낼 자료 링크 | 해당 편의 PDF·가이드가 있는 공개 페이지 주소 |
| DM 안내 문구 | 받는 사람이 어떤 자료인지 알 수 있는 짧은 설명 |
| 사용 | 게시 후 확인을 마쳤을 때 체크 |
| 적용 상태 | 시스템이 표시하므로 직접 쓰지 않는다. |

5. 상단 메뉴의 **등록 내용 적용**을 누른다. 계정에 실제로 있는 게시물인지 확인하고 저장한다. 오류가 있으면 기존 운영 설정을 유지한다.
6. 처음 시작하거나 일시 중지한 상태라면 **자동 발송 켜기**를 누른다.
7. 다른 계정으로 그 게시물에 키워드 댓글을 남겨, DM 도착과 자료 링크를 확인한다. 첫 메시지는 요청함에 들어갈 수도 있다.

한 번 정상 운영을 시작한 뒤에는 다음 편의 행을 추가하고 적용하면 된다. 토큰을 매편 재발급하거나 코드를 다시 배포할 필요는 없다.

## 평소 확인하는 곳

- **연결 상태 확인**: 계정 설정, 전체 발송 상태, 등록 게시물 수, 마지막 인증 점검.
- **synkbrief_발송기록** 탭: 편별 발송 성공·실패·응답 확인 필요와 HTTP 상태. 댓글 원문·이름·받는 사람 ID·토큰은 기록하지 않는다.
- **자동 발송 일시 중지**: 전체 발송만 멈춘다. 등록표와 인증 정보는 남는다.
- 특정 편만 중지: 그 행의 사용 체크를 해제하고 **등록 내용 적용**을 누른다.

## 인증 관리

인증 정보는 Google Apps Script의 비공개 스크립트 속성에 저장한다. 관리표·코드·문서에는 적지 않는다. 교체할 때는 **인증 연결·교체**의 비밀번호 입력 칸을 이용한다. 저장 시 실제 계정이 @synkbrief인지 확인하고 발송은 꺼진 상태로 전환한다. 교체 후 상태를 확인하고 다시 켠다.

기존 매일 아침 운영 작업 `morningJobs`에 계정 확인을 연결했다. 발급·갱신 후 7일이 지나면 장기 토큰 갱신을 시도한다. 실패하면 기존 토큰을 보존하고 상태·발송기록에 남기며 기존 운영 오류 처리로 전달한다. 앱 권한 철회·계정 변경·이미 만료된 토큰은 재연결이 필요하다.

Meta 공식 문서에서 장기 토큰은 발급 24시간 후부터, 만료 전일 때 갱신할 수 있으며 갱신된 토큰은 60일 유효함을 2026-09-26 확인했다. [공식 갱신 문서](https://developers.facebook.com/documentation/instagram-platform/reference/refresh_access_token)

## 발송 기준과 현재 한계

- 사용으로 등록한 해당 게시물의 댓글만 처리한다. 빈 등록표는 모든 게시물 허용이 아니다.
- 같은 편의 동일인·같은 이벤트는 중복을 막고, 다음 편 자료는 별도로 제공한다. 중복 방지 기록은 30일 보관한다.
- 댓글 작성 후 7일 이내의 새 요청만 처리한다. 실패·응답 유실 시 무조건 재발송하지 않는다.
- 팔로우 요청은 영상의 안내 문구다. 팔로우 여부를 확인해 자료를 잠그는 기능은 사용하지 않는다.
- 직접 DM 키워드 응답은 기본 꺼져 있다. 영상 댓글 흐름과 혼동하지 않는다.
- 기본 시간당 발송 시도 상한은 100건이며, 저장 공간이 부족하면 추가 발송을 멈춘다. 대규모 운영 전에는 별도 저장소·처리량 확장이 필요하다.
- 관리표는 최대 300편, 게시물 링크 확인은 최근 최대 1,000개 게시물 범위다.
- 계정 연결·코드 배포와 실제 DM 도착 검증은 별개다. 아직 게시하지 않은 영상은 게시 후 링크 등록과 실수신 시험이 필요하다.

## 당시 복구 절차

관리표가 없을 때만 Apps Script 편집기에서 `synkbrief운영설치`를 실행하고 시트를 새로고침한다. 메뉴는 시트가 열릴 때 만들어지므로 편집기에서 메뉴 함수를 직접 실행하지 않는다. 재설치는 기존 자료 등록·인증·발송 상태를 바꾸지 않는다.
