# v7 정보·이해 흐름 검토 · 2026-09-23

## 이번 수정의 판단

기존 123초·17장면을 88초·14장면으로 재편했다. 35초(28.5%) 단축은 이번 편의 편집 결과이며 다른 회차의 고정 규칙이 아니다. 영상을 통째로 배속하지 않고 겹치는 설명을 합쳤다. 초보자가 어느 프로그램에서 무엇을 눌러 무엇을 입력할지, 그 조건이 왜 필요한지와 결과 확인·반복 사용까지 남겼다.

실제 초보자 대상 사용자 조사는 수행하지 않았다. 아래는 공식 정보·기존 실습 증거·원고·렌더의 제작자 검토다. 최상위 품질 달성이나 이해율을 수치로 단정하지 않는다.

## 공식 자료 재확인

2026-09-23에 아래 공식 도움말을 다시 열어 확인했다. 프로젝트 문서는 확인 시점에 3일 전 갱신으로 표시됐다.

| 확인 내용 | 근거 | 영상 반영 |
|---|---|---|
| 프로젝트는 관련 채팅·파일·지침을 모아 반복 업무에 쓰는 공간 | [Projects in ChatGPT](https://help.openai.com/en/articles/10169521-projects-in-chatgpt) | project, repeat |
| 프로젝트의 ⋯ → 프로젝트 설정에 지침 저장, 해당 프로젝트 안에만 적용 | 같은 문서 | settings, save |
| 계정 전체 맞춤 지침은 다른 대화에도 적용되므로 회의 전용 규칙은 프로젝트에 보관 | [Custom Instructions](https://help.openai.com/en/articles/8096356-custom-instructions-for-chatgpt)와 프로젝트 문서 | global |
| 프로젝트는 다른 내부 대화를 참고할 수 있음. 새 채팅만으로 독립된 기억을 보장하지 않음 | Projects in ChatGPT의 Project memory | separate |

이 용도에서는 프로젝트별 지침이 반복 입력을 줄이는 적절한 방법이다. 모든 도구보다 절대적으로 우월하거나 모든 계정의 화면이 같다는 주장은 하지 않는다. 계정 전체 맞춤 지침 기능 자체를 금지하지 않고 **회의 전용 규칙을 넣지 않는 이유**를 설명한다.

## 초보자에게 필요한 질문별 점검

| 시청자 질문 | 답이 있는 장면 |
|---|---|
| 이걸 왜 하나요? | hook/result: 메모를 담당자·기한이 있는 할 일 표로 바꾸기 |
| 무슨 프로그램인가요? | create: chatgpt.com에 로그인, 새 프로젝트 |
| 프로젝트가 뭔가요? | project: 지침서 하나를 오늘·다음 회의 채팅이 재사용하는 그림 |
| 어디를 누르나요? | create/settings/save: 실제 화면, 커서, 프로젝트 설정 메뉴 확대, 저장 버튼 |
| 뭘 입력하나요? | save: 제공 project-instructions.txt 전체 / memo: 짧은 요청과 이번 메모 |
| 이 조건이 왜 필요한가요? | rules: 없는 기한은 확인 필요, 근거로 원문 대조 |
| 답이 다르면요? | verify: 실제 누락 사례, 네 열 요청으로 보완 |
| 다음번에는요? | repeat/separate: 같은 프로젝트 새 채팅, 지침 재사용과 내용 혼입 확인 |
| 업무에 어떻게 쓰나요? | use: 미정 정보 질문·수정 후 팀 문서로 표 복사 |
| 혼자 따라 할 수 있나요? | ending/preview: 기존 8쪽 PDF, 지침서, 연습 2종과 보완 요청 파일 제공 |

첫 응답은 근거 열이 누락됐고 보완 후 네 열이 됐다. 두 번째 메모에서는 이전 인명·날짜 혼입은 없었으나 일부 열 이름과 섹션 형식이 달랐다. 이 실제 결과를 근거로 결과를 매번 검토하게 했다. 성공만 보장하는 편집으로 바꾸지 않았다. 자세한 실제 시연 기록과 응답은 [v6 연구 기록](../video-v6/research.md)을 따른다.

## 모션 변경

- 상황 질문 카드가 들어오고 결과 표로 전환한다.
- 메모의 할 일·담당자·기한을 토큰으로 분해해 표 위치로 모은다.
- 지침서에서 두 회의 채팅으로 연결선을 그려 재사용 관계를 보여준다.
- 계정 전체 범위와 프로젝트 범위를 단계적으로 대비한다.
- 실제 메뉴를 확대하고 클릭 위치에 커서·반응을 붙인다. 확대는 transform으로 처리해 프레임 렌더의 계단 현상을 줄인다.
- 파일 복사 → 지침 붙여넣기 → 저장 클릭 순서로 시간을 맞췄다.
- 근거 열이 없는 응답 → 보완 요청 → 실제 수정 표를 순차 공개한다.
- 실제 PDF 두 쪽을 입체적으로 등장시켜 제공 자료와 댓글 synk 엔딩을 연결한다.

HyperFrames registry의 simulated-cursor, ui-focus-zoom, line-by-line-slide 패턴을 참고해 이번 장면에 맞춰 조합했다. 88초 전체를 음악의 특정 BPM에 자동 동기화했다는 주장은 하지 않는다.
