## v19에서 바꾼 것

- **순서:** 첫 화면(0초 = 릴스 표지)에 제목과 실제 결과 화면이 이미 보인다. ①은 정리 결과 → 같은 기록 전후 비교 → 실제 답변(카메라 화면) → 따라 하기 순서다. ②는 저장한 규칙과 다음 회의 결과 → 실제 결과 → 프로젝트 세 단계 → 따라 하기 순서다.
- **소리:** v19에 쓴 Typecast 은경 구간 wav(`../audio/<구간>.wav`)를 문장 단위로 잘라 다시 이었다. 문장은 v19 시각표(`../audio/<구간>.json`)의 낱말 번호로 고르고, 장면이 바뀌는 자리에 0.2~0.36초를 띄웠다. 새 음성 합성이나 유료 생성은 하지 않았다. 내레이션 크기는 v19 믹스와 같게 맞췄다(구간 원본이 v19 narration.wav보다 3dB 커서 0.708배). BGM은 v19의 시티팝_147 앞부분, 0.43배다. 보이스오버 카브는 v19와 같은 세기 0.45로 다시 계산했다. 효과음은 v19의 효과음(스치는 소리·톡·클릭·차임)을 그대로 쓰고 전환·눌림·클릭에 붙였다.
- **자막:** 낱말 단위 키네틱 자막이다. 낱말마다 Typecast 원본 시각에 맞춰 튀어나온다. 화면 표기는 v19 자막과 같다(“에이아이가”는 “AI가”로 표기). 두 줄 안에서 끊고, 강조 낱말은 청금석 글자에 노란 형광펜을 쓴다.
- **화면:** 2026-09-23에 찍은 실제 ChatGPT 화면(v19 `assets/` 사본)을 배율과 위치만 바꿔 잘라 보여 준다. 증거 자리는 카메라 화면 하나에 `2026.09.23 · 실제 화면 · 가상 메모` 날짜 도장을 붙였다. 복사해 갈 문장은 옛 창 하나에 넣었다. ①은 [그대로 복사할 문장](../../follow-along-v15/그대로%20복사할%20문장.txt), ②는 [프로젝트에 저장할 규칙](../../follow-along-v15/프로젝트에%20저장할%20규칙.txt)의 앞부분이며 원문과 같다. 전후 비교는 `k-compare`, 순서는 `k-steps`로 만들었다.
- **끝 장면(개인화 틀 + 행동 하나):** 공개 자료와 같은 v15 따라 하기 PDF 쪽(①은 1·3·4쪽, ②는 7·8·11쪽)을 PyMuPDF로 그림으로 옮겨 보여 준다. 칩으로 복사할 문장·예시·연습 메모를 보여 주고, 행동은 **`자료 받기 synk.im/brief/meeting`** 하나만 둔다. 이 주소는 [업로드 전 점검](../../업로드전_최종점검_20260926.md)에서 응답 200과 PDF·ZIP 해시 일치를 확인한 공개 자료 페이지다. **댓글 → 자동 DM은 아직 실수신 검증 전이라([자료 전달 현황](../../instagram-delivery/README.md)) “댓글 달면 보내 드립니다”와 v19 엔딩 음성 “팔로우하시고, 댓글에 synk를 남겨주세요”는 쓰지 않았다.** 엔딩 구간은 그 문장이 시작되기 전(4.09초)에서 잘랐다.
- **안전 영역:** 메타 통합 9:16 안전 영역(위 269 · 아래 672 · 옆 65, 오른쪽 단추 자리 160)을 따랐다. 글자는 y 269~1248 안에 있다. 자막은 아래끝을 y 1236에 맞춰 위로 쌓이고(두 줄이면 y 1080~1236), 장면 내용은 y 1040 위에 둔다. 영상 장면에서는 자막과 겹치는 `k-foot`을 쓰지 않았다. 색 면 장면은 SHIFT 로고 라벨과 @synkbrief를 머리줄에 둔다.

## 다시 만들기 · 렌더

```bash
# kit-v1 폴더에서
node prep-media.mjs                                   # v19에서 소리(audio/, git 제외)·실제 화면·PDF 쪽(assets/ui/) 사본
node ../../../../../tools/SNS키트_영상연결.js split1-45s # 키트 사본(assets/synk-kit/, git 제외). split2-60s도 같이
node build-timing.mjs split1-45s                      # plan.json → 말 시각표·자막·<audio>를 index.html에 씀
node ~/.claude/skills/hyperframes-audio/scripts/carve.mjs --comp split1-45s/index.html --bed music --strength 0.45 --core ..   # build-timing 뒤에는 카브를 다시
cd split1-45s && npm run check
# 사용자가 미리보기·렌더를 정한 뒤에만:
npx --yes hyperframes@0.8.104 render --quality delivery --fps 30 --output renders/synkbrief-split1-45s.mp4
```

`build-timing.mjs`는 `index.html`의 표시 구역(`@audio`, `@cap 장면`, `/*@T*/`, 루트 길이)만 다시 쓴다. 장면 디자인과 움직임은 `index.html`에서 직접 고친다. 표지는 `node tools/SNS키트굽기.js <분할>/cover.html --out <분할>/cover-out`로 굽고 `cover.png`로 복사한다.

## 남은 것 · 사용자가 확인할 것

1. **음성에 없는 문장(화면 글자로만 넣음):** ①의 훅 “이 메모가, 붙여넣기 한 번에 이렇게 됩니다”(바이럴 검토 §7 1안)는 표지 제목으로만 넣었다. 음성은 “같은 기록인데 차이가 보이죠?”로 시작한다. 끝 장면의 행동 `자료 받기 synk.im/brief/meeting`에도 음성이 없다. 원래 엔딩 음성은 댓글 요청이라 잘라 냈다. 말로도 안내하려면 새 음성 한 줄이 필요하다(이번에는 만들지 않음). ②의 바이럴 훅 1·2안도 음성에 없어, 원래 음성 “정리 규칙을 한 번 저장하면, 다음 회의는 새 채팅에 기록만 넣으면 돼요”로 열었다. ②는 길이 때문에 v19의 “다음 회의가 끝나면 왼쪽 프로젝트 → 회의 정리 → 새 채팅” 음성(구간 repeat-find·repeat-new)을 뺐다. 그 내용은 세 단계 장면의 3단계와 화면 글자가 대신한다.
2. **②의 ‘실제 결과’ 화면:** `13-second-result.png`(09-23 17:01)는 같은 ‘회의 정리 · synkbrief 실습’ 프로젝트의 새 채팅에서 받은 실제 결과다. 다만 최종 규칙 문장(`06-instructions.png`, 20:03)으로 바꾸기 전의 지침이 들어 있던 때 찍었다. 화면 속 요청도 “이번 회의도 정리해줘.”가 아니라 “프로젝트 지침에 맞춰 이번 회의 메모를 정리해줘.”다. 파일 시각(20:08 입력, 20:11 결과)으로 보면 최종 규칙과 최종 문장으로 받은 첫 결과는 v19 `assets/current/project-first-result.txt`다. 이것도 같은 모양의 표(담당자·기한·확인 필요)였지만 그 화면 캡처는 없다. 이대로 쓸지, 최종 규칙으로 다시 캡처할지 정해야 한다. 화면이 거짓은 아니지만 한 번 확인해 달라.
3. **자료 전달 경로:** 끝 장면의 행동은 검증된 공개 페이지 주소다. 게시글 문안(`posts-v18`)은 아직 “팔로우하시고 댓글에 synk”라 이 두 편에 맞게 고쳐야 한다(이번 범위 밖, 고치지 않음). @synkbrief 프로필 링크가 이 주소인지도 확인하지 않았다. 댓글 → DM 자동 발송을 켜려면 [자료 전달 현황](../../instagram-delivery/README.md)의 남은 순서(게시물 등록 → 자동 발송 켜기 → 다른 계정으로 실수신 확인)가 먼저다.
4. 직접 청취, 휴대폰 실제 크기 확인, 사용자 판단과 렌더.

## 키트에 제안하는 것(키트 파일은 고치지 않았다)

- `motion.js`의 `seam`·`arch`·`paper`는 새 장면에 z-index 5·6·7을 고정으로 준다. 그래서 아치(6)나 종이(7) 다음에 실땀(5)이 오면 새 장면이 옛 장면 밑에 깔려 전환이 안 보인다. 이 두 편은 전환마다 옛 장면을 z-index 1로 내려서 피했다. 전환 함수 안에서 옛 장면을 내리면 좋겠다.
- 낱말 시각표가 있는 음성용으로 `M.captionAt(tl, sel, 낱말시각[], 사라질시각)` 같은 함수를 두면 좋겠다. 지금 `M.caption`은 같은 간격으로만 낱말을 띄운다. 이 두 편은 컴포지션 안에 같은 일을 하는 작은 함수를 두었다.
- 9:16에서 `.kv-cap`(아래끝 684)과 `.k-foot`(아래 676)이 같은 자리에 온다. 자막이 있는 영상 장면에서 발을 어떻게 할지 키트에 정해 두면 좋겠다. 이 두 편은 영상에서 발을 빼고 색 면 장면의 머리줄에 로고 라벨을 두었다.
- 키트 `.k-mark::after`의 `z-index:-1` 때문에 모든 영상 프로젝트에 `negative_z_index` 경고 2개가 뜬다.
- 키트 README §9가 말한 ‘톡’·천 스치는 소리는 아직 없어서 v19 효과음을 썼다.
