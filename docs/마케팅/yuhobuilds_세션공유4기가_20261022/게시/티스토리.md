# Tistory(yuhobuilds.tistory.com) 적용기 원고 — 윈도우 PC가 괜히 느릴 때, 뒤에서 계속 저장하는 프로그램 찾기(2026-10-22 만듦 · 10-23 보완 · 슬롯 10-23)

> 영상과 같은 한 문장(「PC가 괜히 느리면, 작업 관리자에서 뒤에서 계속 저장하는 프로그램을 찾자」)을 내 PC에서 따라 하는 순서로. 영상에서 뺀 단서(Windows 10, 정렬, 끄는 법, 네트워크도 섞임)와 우리 실화의 자세한 이야기는 여기에 둔다. 올리기는 유호님 「올려」 뒤(이 세션은 올리지 않음). 근거는 [기획](../기획.md) 「사실 대조」. 게시 세션이 `node tools/블로그붙여넣기.js <이 파일> --티스토리 --영상 <쇼츠 ID>`로 〔유튜브 쇼츠〕 자리를 채운다.

**제목**

윈도우 PC가 괜히 느릴 때 — 뒤에서 계속 저장하는 프로그램 찾는 법(작업 관리자 5단계)

**카테고리**

막힌 문제 해결

**본문**

PC가 괜히 느리고 버벅일 때, 작업 관리자에서 열 하나만 켜면 어떤 프로그램이 뒤에서 계속 저장하고 있는지 보입니다. 저는 2026년 10월 20일 밤, 프로그램마다 쓴 양을 PowerShell로 재다가 바쁠 때 한 시간 꼴로 4.3GB를 쓰는 프로그램을 봤는데, 제가 만든 프로그램이었어요. 고친 지금은 같은 방법으로 쟀을 때 한 시간 꼴 94MB입니다.

〔유튜브 쇼츠〕

## 찾는 법(다섯 단계)

1. `Ctrl + Shift + Esc`로 작업 관리자를 엽니다.
2. 「세부 정보」로 갑니다. Windows 11은 왼쪽 목록, Windows 10은 위쪽 탭에 있어요. 탭이 안 보이고 창이 작게 열리면 아래 「자세히」를 누르세요.
3. 표 맨 윗줄(이름 · PID · 상태 같은 열 이름이 있는 줄)을 오른쪽 클릭해 「열 선택」.
4. 「I/O 쓰기 바이트」를 체크합니다. 프로그램이 실행된 뒤 지금까지 쓴 양의 합이에요.
5. 그 열 이름을 눌러 큰 순서로 놓고(작은 순서로 놓이면 한 번 더) 몇 초 지켜봅니다.

## 무엇을 보면 되나

이 값은 켜진 뒤 쓴 양을 모두 더한 것이라, 오래 켜 둔 프로그램은 원래 큽니다. 숫자가 큰 줄보다 **빨리 느는 줄**이 지금 계속 쓰고 있는 프로그램이에요. 이 값에는 디스크뿐 아니라 네트워크로 보낸 양도 섞이고, 백업 · 동기화 · 업데이트처럼 원래 많이 쓰는 프로그램도 있습니다.

## 찾은 뒤에는

- 모르는 이름이면 끄기 전에 이름을 AI에게 먼저 물어보세요. 무슨 프로그램이고 왜 그만큼 쓰는지 짐작을 들을 수 있어요.
- 안 쓰는 프로그램이면 그 줄을 오른쪽 클릭 → 「작업 끝내기」. 지우는 게 아니라 지금 실행만 멈추는 거라, 다시 켜면 또 돕니다. 계속 그런다면 그 프로그램의 자동 실행 · 동기화 설정을 봅니다.
- 이름이 Windows 기본 구성 요소처럼 보이면 끄지 말고 먼저 알아보세요.

## AI에게 재 달라고 하려면

PowerShell을 돌릴 수 있는 코딩 AI에게 아래를 붙여 넣으면, 두 번 잰 차이로 1~5등 표를 받습니다. 【60】은 두 번 재는 사이의 초예요. 10월 22일 제 PC에 붙여 넣어 보니 다섯 개 표와 함께 1등이 왜 그만큼 쓰는지까지 짚었어요.

```
내 윈도우 PC에서 지금 가장 많이 쓰는(I/O 쓰기) 프로그램을 찾아 줘. PowerShell로 프로세스마다 지금까지 쓴 바이트(Win32_Process의 WriteTransferCount)를 재고, 【60】초 뒤에 한 번 더 재서 그 사이에 쓴 양을 구해 줘. 큰 순서로 다섯 개를 표로 보여 줘(이름 · 프로세스 ID · 쓴 MB · 한 시간으로 늘리면 몇 MB). 1등이 무슨 프로그램이고 왜 그만큼 쓰는지 짐작되는 까닭과 줄이는 방법도 알려 줘. 아무것도 끄거나 지우지는 마.
```

이 프롬프트와 다른 편에서 쓴 프롬프트는 https://synk.im/prompts 에 모아 두었어요.

## 제 경우 — 제가 만든 프로그램이 그랬어요

10월 18일 영상으로 나눠 드린 Claude 데스크톱 「세션 공유」 도구였습니다. 계정 · 조직 폴더 29곳을 맞추는 도구인데, 지금 계정의 세션 기록이 바뀌면 150밀리초 안에 나머지 28곳에 똑같이 복사했어요. 그런데 앱은 대화가 한 번 오갈 때마다 기록 파일(약 113KB)을 통째로 다시 씁니다. 그래서 바쁠 때 4분 재 보니 한 시간 꼴로 4,279MB를 쓰고, CPU 코어 하나의 23.6%를 쓰고 있었어요(PowerShell로 프로그램마다 쓴 바이트를 0.2초마다 잼). 계정이 둘셋인 분은 훨씬 적었을 거예요.

알고 보니 앱은 로그인할 때만 그 폴더에서 세션 목록을 읽어요. 그래서 셋을 고쳤습니다.

1. **고쳐 쓴 기록은 5분씩 모아서** 마지막 판만 옮깁니다. 새 파일 · 지운 파일은 지금도 바로 옮겨요.
2. **로그아웃이 보이면 그때 바로** 전부 맞춥니다. 10월 21일 00:10 실제 계정 전환에서 로그아웃 줄을 본 0.13초 뒤에 7곳을 맞췄어요.
3. **안 쓰는 폴더는 쉬게** 했습니다. 29곳 중 진짜 쓰는 곳은 7곳이었고, 쉬게 한 폴더는 지우지 않고 백업 폴더로 옮겨 둡니다.

| | 한 시간 꼴로 쓴 양 | CPU(코어 하나) | 잰 시간 |
|---|---|---|---|
| 고치기 전 | 4,279MB | 23.6% | 바쁠 때 4분 |
| 첫 고침 | 333MB | 0.93% | 45분 |
| 지금 판 | 94MB | 0.26% | 30분 |
