# Tistory(yuhobuilds.tistory.com) 적용기 원고 — 제가 나눠 드린 도구가 한 시간에 4.3GB를(2026-10-22 만듦 · 슬롯 10-23)

> 영상과 같은 실화를 「내 PC에서 따라 찾아보는 순서」로. 올리기는 유호님 「올려」 뒤(이 세션은 올리지 않음). 근거는 [기획](../기획.md) 「사실 대조」. 게시 세션이 `node tools/블로그붙여넣기.js <이 파일> --티스토리 --영상 <쇼츠 ID>`로 〔유튜브 쇼츠〕 자리를 채운다.

**제목**

내 PC에서 몰래 디스크를 쓰는 프로그램 찾기 — 제 도구가 한 시간에 4.3GB를 쓰던 이유

**카테고리**

막힌 문제 해결

**본문**

작업 관리자에서 열 하나만 켜면, 내 PC에서 어떤 프로그램이 디스크에 얼마나 쓰고 있는지 바로 보입니다. 저는 그걸 2026년 10월 20일 밤에 제가 만든 도구에서 봤습니다. 10월 18일 영상으로 나눠 드린 Claude 데스크톱 「세션 공유」 도구가, 바쁠 때 재 보니 한 시간에 4,279MB를 쓰고 CPU 코어 하나의 23.6%를 쓰고 있었어요. 고친 지금 판은 같은 방법으로 쟀을 때 한 시간에 94MB, CPU 0.26%입니다.

〔유튜브 쇼츠〕

## 먼저 조건부터

이 숫자는 제 PC 값입니다. 계정·조직 폴더가 29곳이었고, Claude 세션을 여럿 동시에 돌리던 바쁜 시간에 4분 잰 값을 한 시간으로 늘렸어요. 계정을 둘셋만 쓰는 분은 훨씬 적었을 거예요. 그래도 도구를 받으신 분은 새 판으로 바꾸시길 권합니다.

## 어디서 샜나

1. **바뀌면 0.15초 안에 28곳으로.** 도구는 지금 계정 폴더의 세션 기록이 바뀌면 150밀리초 안에 나머지 28곳에 똑같이 복사했습니다(`const WATCH_DEBOUNCE_MS = 150;`).
2. **앱은 기록을 통째로 다시 씁니다.** 세션 기록 파일 하나가 약 113KB인데, 그중 102KB가 도구 목록(`remoteMcpServersConfig`) 칸이에요. 대화가 한 번 오갈 때 바뀌는 건 `lastActivityAt` 같은 시각 몇 글자뿐인데, 파일은 통째로 다시 쓰입니다.
3. **그래서 한 시간에 복사 34,664번.** 상태 파일도 한 시간에 328번 다시 썼고요. 거기에 도구가 자기가 쓴 파일에 다시 깨어나 29곳을 또 훑는 버릇까지 있었습니다.

## 알고 보니

Claude 앱은 로그인할 때만 그 폴더에서 세션 목록을 읽습니다. 다른 계정 폴더에 0.15초 만에 옮겨 놓아도, 그 계정으로 로그인하기 전까지는 아무도 안 읽는 복사였어요.

## 고친 셋

1. **고쳐 쓴 기록은 5분씩 모아서** 마지막 판만 옮깁니다(`BATCH_MS` 300000). 새로 생긴 세션 파일과 지운 파일은 지금도 바로 옮깁니다.
2. **로그아웃이 보이면 그때 바로** 전부 맞춥니다. 앱 기록(main.log)에서 로그아웃 줄을 보면 기다리지 않아요. 10월 21일 00:10에 실제로 계정을 바꿨을 때 로그아웃 줄을 본 0.13초 뒤에 7곳을 맞췄고, 다음 계정이 세션 54개를 읽었습니다.
3. **안 쓰는 폴더는 쉬게** 합니다. 29곳 중 13곳은 앱이 한 번도 로그인하지 않은 폴더였고, 9곳은 계정을 바꾸는 사이 1~13초만 스친 폴더였어요. 진짜 쓰는 곳은 7곳. 쉬게 한 폴더는 지우지 않고 백업 폴더로 옮겨 둡니다.

| | 시간당 쓴 양 | CPU(코어 하나) |
|---|---|---|
| 고치기 전(바쁠 때 4분) | 4,279MB | 23.6% |
| 첫 고침(45분) | 333MB | 0.93% |
| 지금 판(30분) | 94MB | 0.26% |

## 내 PC에서 찾는 법

1. `Ctrl + Shift + Esc`로 작업 관리자를 엽니다.
2. 왼쪽 메뉴에서 「세부 정보」.
3. 열 이름 줄(이름·PID·상태…)을 오른쪽 클릭해 「열 선택」.
4. 「I/O 쓰기 바이트」를 체크합니다.
5. 그 열 이름을 눌러 큰 순서로 놓고, 잠깐 뒤 다시 봅니다. 이 값은 프로그램이 켜진 뒤 쓴 양의 합이라, 숫자가 큰 것보다 **빨리 느는 것**이 범인 후보예요.

## AI에게 맡기려면

PowerShell을 돌릴 수 있는 코딩 AI에게 아래를 붙여 넣으면, 두 번 잰 차이로 1~5등 표를 받습니다. 【60】은 두 번 재는 사이의 초예요. 10월 22일 제 PC에 붙여 넣어 보니 다섯 개 표와 함께 1등이 왜 그만큼 쓰는지까지 짚었어요. 이 값은 디스크뿐 아니라 모든 쓰기를 합친 것이라, 작업 관리자처럼 「빨리 느는 것」을 찾는 데 씁니다.

```
내 윈도우 PC에서 지금 가장 많이 쓰는(I/O 쓰기) 프로그램을 찾아 줘. PowerShell로 프로세스마다 지금까지 쓴 바이트(Win32_Process의 WriteTransferCount)를 재고, 【60】초 뒤에 한 번 더 재서 그 사이에 쓴 양을 구해 줘. 큰 순서로 다섯 개를 표로 보여 줘(이름 · 프로세스 ID · 쓴 MB · 한 시간으로 늘리면 몇 MB). 1등이 무슨 프로그램이고 왜 그만큼 쓰는지 짐작되는 까닭과 줄이는 방법도 알려 줘. 아무것도 끄거나 지우지는 마.
```

이 프롬프트와 다른 편에서 쓴 프롬프트는 https://synk.im/prompts 에 모아 두었어요.
