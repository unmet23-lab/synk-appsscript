## P1

1. **#11 카드 ⑤ · 약속한 「찾는 법」이 그대로 따라 하면 엉뚱한 프로그램을 가리킬 수 있다.** 「I/O 쓰기 바이트」는 그 프로그램이 켜진 뒤 쓴 양의 **합**이라, 「큰 순서로」만 놓으면 며칠 켜 둔 브라우저·시스템 프로세스가 맨 위에 오고 이 편의 node처럼 **빨리 느는** 것이 묻힌다. 근거: 기획.md 47행 스스로 「큰 순서로 놓고 빨리 느는 것을 본다」라고 적었는데 카드 ⑤에는 「빨리 느는 것」이 없다. 고침: ⑤ 「그 열을 눌러 큰 순서로 두고, 숫자가 빨리 느는 줄을 보기」. 말(c0)은 그대로 둬도 되고, 글자 여유가 있으면 끝을 「…열을 켜고, 빨리 느는 걸 보세요」로.

## P2

1. **h1 · #1 띠 · 「4.3GB씩 쓰고」가 무엇을 쓰는지 안 갈린다.** 귀로도 0초 글자로도 디스크·메모리·인터넷 데이터 가운데 어느 것인지 모르고(「메모리 4GB 먹어요」가 흔한 말), 디스크 쓰기라는 건 c0(I/O 쓰기 바이트)에서야 드러난다. v2 §2-1 「소리를 끄고 봐도 0초 글자로 이해」. 고침(둘 중 하나): #1 띠를 「디스크에 쓴 양 · 1시간 꼴 4,279MB」로(말은 그대로) / h1 「제가 나눠 드린 도구가, 한 시간에 디스크에 사 점 삼 기가씩 쓰고 있었어요.」
2. **h1 · 처음 보는 사람에게 「나눠 드린 도구」가 무엇인지 화면 어디에도 없다.** b1 「세션 기록」도 AI 완전 초보에겐 낯설다. 궁금증은 생기지만 「무슨 도구?」가 b1까지 안 풀린다. 고침: #1 머리띠 「제 PC · Claude 세션 공유 도구 · 폴더 29곳 · 바쁠 때 4분 잰 값」 또는 #3 판 아래 「지난 편 도구 · 고치기 전 코드 · 실제 기록」. 지난 편 표지는 쓰지 않기로 한 결정(기획 15행)과 어긋나지 않는 글 한 토막이다.
3. **b3 머리글 「34,664번」 ≠ 말 「삼만 사천 번」.** 머리글은 줄이되 다른 꼴로 바꾸지 않는다(10-17 원고 37행). 고침: 머리글 「한 시간에 / 복사 3만 4천 번」, 정확한 34,664는 #5 띠에만.
4. **f3 머리글 「29곳 중」 — 말에 없는 말.** 말은 「진짜 쓰는 곳은 일곱 곳뿐」이고 29는 어디서도 말하지 않는다(28곳만). 고침: 「셋, 안 쓰는 폴더는 쉬게 / 진짜 쓰는 곳은 7곳뿐」 — 「29곳 중 7곳」은 #9 판 아래에 이미 있다.
5. **b5 「사 점 삼 기가가, 구십사 메가가」 — 「기가가」·「메가가」 겹소리.** 귀로 걸리고 받아쓰기도 틀리기 쉽다(10-17 원고 121행 「한도가→한두가」). 고침: 「한 시간에 사 점 삼 기가 쓰던 게, 구십사 메가가 됐어요.」 머리글 「한 시간 4.3GB 쓰던 게 / 94MB로」.
6. **길이 — 14줄 490자(fo 포함)는 52~56초로 센다.** 10-21 두 편(같은 범수 설정·speed 1.05)이 382자→40.9초, 409자→46.9초였다(기획.md 각 31·36행). 기획의 「45~52초」보다 길고 10-17 형식 결정 「50초 안쪽」(원고 9행)을 넘는다. 고침(약 −46자 → 444자 ≈ 48~50초): b3를 빼고 34,664는 #4 띠로(−34, b2→b4 「통째로 다시 써요」→「알고 보니 로그인할 때만 읽더라고요」가 바로 이어진다), h2 「그리고」 빼기(−4), c0 「내 PC도 보고 싶으면,」→「내 PC는,」(−8).
7. **측정 조건 표시가 #1 머리띠에만 있다.** b3 판 아래 「제 PC에서 잰 값」엔 「4분 · 1시간 꼴」이 없고, #10 「같은 방법으로 잰 값」은 4분 / 45분 / 30분 잰 값을 같은 꼴로 세운다. 하루 평균은 훨씬 낮다(현장노트 윈도우_셸 331행 「그날 02~09시 UTC 87,556번」 ≈ 시간당 1.1만). 고침: #5 판 아래 「바쁠 때 4분 잰 값 · 1시간 꼴」, #10 판 아래 「같은 방법 · 4분 / 45분 / 30분 잰 값을 1시간 꼴로」.
8. **#1·#10 「CPU 23.6%」 — 코어 하나 기준인데 화면엔 「코어 하나」가 없다.** 작업 관리자의 전체 CPU %로 읽힌다(16스레드면 약 1.5%). 근거: 현장노트 331·334행 「CPU 코어 하나의 24%/23.6%」. 말에는 CPU가 없다. 고침: 띠에서 CPU를 빼거나 「CPU 코어 하나의 23.6%」.
9. **#10 막대 이름 「v3 · v3.1」 — 내부 판 번호.** 고침: 「고치기 전 · 첫 고침(1분씩 모음) · 지금(5분씩 모음)」.
10. **#4 칸 이름이 기획과 data.ts가 다르다.** 기획 41행·콘티 #4는 `lastActivityAt`·`completedTurns`, `remotion/src/p3/data.ts` 41행(10-22 실제 파일 확인)은 `lastActivityAt`·`lastTurnEdgeAt`. 화면은 data.ts를 쓸 테니 기획 두 곳을 data.ts에 맞춘다(현장노트 332행의 `completedTurns`는 「같은 활동 칸」 예시). 실제 파일은 이 검수에서 못 열었다(아래 「읽지 못한 범위」).
11. **#4 개인정보 — 「실제 기록 파일 … 값은 흐림」은 실제 값을 흐려서 보인다는 뜻으로 읽힌다.** 세션 기록엔 세션 제목·작업 폴더 경로·브랜치 이름이 들어 있고(10-17 원고 94행), 짧은 값은 7px 흐림으로도 글자 수·꼴이 비친다. data.ts 5행대로 **값은 아예 그리지 않고**(회색 막대) 칸 이름·크기만 실제로 한다. 판 아래 「실제 기록 파일의 칸 이름·크기 · 값은 안 보임」.
12. **#6 시간 막대 — 로그인 순간이 실제 기록인지 그림인지 안 정해져 있다.** v2 §2-2 「재구성을 실제 사용 결과처럼 말하지 않는다」. 고침: 그림이면 판 아래 「앱이 목록을 읽는 때 · 그림」, 실제로 하려면 main.log 로그인 줄이나 도구 기록 「로그인 줄을 봄」(ac13744 915행) 시각 둘을 쓰고 「실제 기록」. #7 아래쪽 막대도 같은 표시.
13. **#11~#13 한 카드 13~14초.** c0 49자(≈5.5초)+cta+q가 같은 카드에서 커서·타자·아이콘만 바뀐다. 10-21 「트렌디하게」 완성본 검수 P3 반영이 같은 꼴이었다(다섯 줄 카드 15.5초 거의 멈춤 38% → 줄마다 미는 컷으로 5%). 고침: ①~⑤를 말에 맞춰 한 줄씩 켜고, #12는 PowerShell 칸 쪽으로 미는 컷, #13은 말풍선 쪽으로 컷. 렌더 뒤 `정지구간.js`가 잡기 전에 콘티에서 나눈다.

## P3

1. f1 「바뀐 기록은 오 분씩」 — 새 세션·지운 세션도 늦는다고 들릴 수 있다(ac13744 52행 「새 세션·지운 세션은 바로 옮긴다」). f2가 계정 전환을 받쳐 실제 오해는 작다. 고치면 「하나, 고쳐 쓴 기록은 오 분씩 모아서 옮기기」 / 머리글 「하나, 고쳐 쓴 기록은 / 5분씩 모아서」(글자 수 같음).
2. b2·b4가 둘 다 「그런데」로 시작. b4 「알고 보니, 앱은 로그인할 때만 목록을 읽더라고요.」(−4자).
3. q 「뭐가 제일 많이 쓰던가요」 — 「쓰다」에 목적어가 없어 귀로 어색. 「어떤 프로그램이 제일 많이 쓰고 있던가요?」(+5자) 또는 「뭐가 제일 많이 쓰고 있던가요?」.
4. c0 머리글 「내 PC에서 찾기:」 — 말은 「보고 싶으면」. 「내 PC도 보려면: / I/O 쓰기 바이트」.
5. f2 「로그아웃이 보이면」 — 누구에게 보이는지 귀로 모른다. 「둘, 앱이 로그아웃하면 그때 바로 맞추기」(글자 수 같음), 머리글 「둘, 앱이 로그아웃하면 / 그때 바로」.
6. #1 「0.15초 간격, 박에 맞춰 빠르게」 — 122.863 BPM 한 박은 0.49초라 둘이 안 맞는다. 0.15초 간격(실제 값)으로 두고 「박에 맞춰」는 빼거나 첫 퍼짐만 박에 건다.
7. 테두리·밝힘 색이 안 적혀 있다(#2 「드릴게요」 테두리, #9 「남은 7칸만 밝게」). 10-21 멈춘 시간 편 Opus P2-3대로 테두리는 글색(흰), 7칸도 흰색 — 버터는 머리글 강조 + 복사 점 두 뜻뿐(기획 52행).
8. 콘티 #3·#7의 `d2d7ea0`·`ac13744`는 제작 참고로 읽히지만 코드 창 제목·탭에 해시·파일 경로가 나오지 않게 한 줄 명시. 줄 번호 39·571·54는 괜찮다.
9. 표지 계획이 없다. 10-21 두 편은 표지가 0초 약속을 들었고(Fable 「약속이 판 아래 글뿐」을 표지로 받음), 이 편도 0초 약속은 판 아래 작은 글뿐이다. 게시 묶음 때 표지(「한 시간 4.3GB → 94MB」 전후 + 작은 줄 「내 PC에서 찾는 법」)와 캡션에 설치 한 줄·찾는 법 다섯 단계 정본을 둔다(영상의 URL은 복사할 수 없다).
10. cta와 q 순서 — c0(찾는 법) → cta(도구 받은 분) → q(뭐가 많이 쓰던가요)라 q가 c0로 되돌아간다. c0 → q → cta → fo로 두면 질문이 방금 켠 열에 바로 붙고 cta는 팔로우 줄과 이어진다(콘티 #12·#13만 바뀜). 선택.
11. 기획 §2 읽기 표기 메모(37행)에 「PC → 피씨」가 빠져 있다(음성/계획.json엔 있음).
12. #3 「1초마다 한 줄씩」 — data.ts LOG_BEFORE의 21:56:31·21:56:48 두 줄은 17·23초 간격이고 「1초마다」는 21:57:11~13 세 줄에만 맞다. 시각을 보이면 그대로 둬도 되고, 「1초마다」를 지키려면 세 줄만.
