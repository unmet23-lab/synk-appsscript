# S4 · synkbrief 첫 세로영상

제작 제목: AI가 만든 PDF, 보내기 전에 이것부터

배포 대상: YouTube Shorts·Instagram Reels·TikTok `@synkbrief`에 핵심 완성본 공통 사용. 공개 업로드 전 상태.

주제: GitHub 공개 도구 Playwright로 HTML을 PDF로 내보내고, 내보낸 PDF 페이지를 이미지로 확인해 배치 오류를 수정하는 실제 시연.

## 내레이션

AI가 PDF를 다 만들었다고 했는데, 바로 보내도 될까요?

이 표를 보세요. 문장 끝이 잘렸죠.
설명을 위해 일부러 만든 예시예요.

이번에 쓴 도구는 깃허브에 공개된 플레이라이트.
HTML 문서를 브라우저에서 열고, PDF로 저장할 수 있어요.

여기서 한 단계 더 갑니다.
저장한 PDF를 페이지별 이미지로 펼쳐서, 글자와 표가 끝까지 보이는지 확인해요.

잘린 문장은 줄바꿈을 고치고, 다시 저장해서 한 번 더 봅니다.
이제 끝까지 읽히죠?

다음에 AI에게 문서를 부탁할 땐 이렇게 덧붙여 보세요.
“PDF로 저장한 뒤, 모든 페이지를 열어 보고 잘린 부분까지 고쳐 줘.”

## 게시 설명

PDF 파일이 생겼다고 문서가 제대로 보이는 것까지 확인된 건 아니에요.

이번에는 긴 문장이 잘리도록 만든 가상 안내문을 Playwright로 PDF로 저장하고, 페이지 이미지로 확인한 뒤 줄바꿈을 고쳤습니다. 원본과 수정본을 모두 실제로 내보내 비교했어요.

다음 문서 요청에는 “PDF로 저장한 뒤, 모든 페이지를 열어 보고 잘린 부분까지 고쳐 줘”를 덧붙여 보세요. 글자 잘림·표·페이지 끝을 확인하고, 내용의 사실성과 링크 동작도 따로 확인하면 좋아요.

사용 도구와 공식 설명:
- [Playwright GitHub](https://github.com/microsoft/playwright)
- [PDF 출력 API](https://playwright.dev/docs/api/class-page#page-pdf)

## 음성·사실·편집 메모

- 사용자 위임에 따라 상큼하고 맑은 설명형 목소리를 사용한다. 감정은 가벼운 호기심 → 차분한 설명 → 확인의 만족감. 뉴스 앵커처럼 과장하거나 긴장감을 부풀리지 않는다. 성별·캐릭터명은 실제 API 후보 청취 후 제작자가 결정한다.
- Playwright의 PDF 출력이 오류를 자동으로 찾아 고친다는 주장이 아니다. 생성, 렌더, 관찰, 원본 수정, 재출력의 작업 흐름을 보여준다.
- PDF를 PNG로 펼치는 도구는 실제 실행에서 Poppler `pdftoppm`을 사용했다. Playwright는 HTML → PDF를 맡았다. 두 역할을 하나의 기능처럼 설명하지 않는다.
- 수정 전 오류는 의도한 재현이다. “우리가 겪은 AI 실패”나 “이 도구를 쓰니 오류가 0%”로 바꾸지 않는다.
- 시간 절감·조회수·매출·최신 출시 주장은 넣지 않는다. 2026-09-19 실제 실행 및 공식 문서 확인.
- 앞서 검토한 `openai/skills`는 현재 폐기 안내가 있어 첫 편의 설치 추천에서 제외했다. 이 영상의 추천 도구는 현행 공식 자료를 확인하고 실제 실행한 Playwright다.
- 합성 오디오·BGM·최종 영상은 이 원고 작업에서 만들지 않았다.
