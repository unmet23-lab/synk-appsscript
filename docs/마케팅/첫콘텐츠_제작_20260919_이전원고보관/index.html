AI가 만든 PDF, 보내기 전에 확인하는 법

AI가 문서를 다 만들었다고 해서 파일을 보냈는데, 나중에 표 안의 글자가 잘린 걸 발견하면 난감하죠. PDF가 생성됐다는 것과 제대로 읽힌다는 것은 각각 확인해야 합니다.

이번에는 설명을 위한 가상 안내문으로 그 과정을 직접 만들어 봤습니다. 긴 문장이 표 안에서 잘리도록 설정한 뒤, PDF로 저장하고, 실제 페이지를 확인하고, 줄바꿈을 고쳐 다시 저장했습니다. 아래 수정 전 화면은 실제 업무에서 우연히 생긴 오류가 아니라 검수 방법을 보여주기 위한 재현 예시입니다.

02 검수 행을 보면 마지막 문장이 끝까지 보이지 않습니다. 파일은 정상적으로 만들어졌지만 읽는 사람에게 필요한 안내가 잘렸습니다.

줄바꿈을 허용하고 행이 내용만큼 늘어나도록 수정했습니다. 글자를 무작정 작게 만들지 않아도 마지막 문장까지 읽을 수 있습니다.

이번에 사용한 도구

Playwright는 Microsoft가 GitHub에 공개한 브라우저 자동화 도구입니다. 이번에는 HTML 문서를 브라우저로 열고 PDF로 저장하는 데 사용했습니다. PDF 출력에는 인쇄용 CSS가 적용되므로, 브라우저에서 본 화면과 저장한 PDF를 따로 확인하는 것이 좋습니다. 공식 GitHub · PDF 출력 API

저장된 PDF를 페이지별 이미지로 펼치는 데는 **Poppler의 pdftoppm**을 사용했습니다. Playwright가 PDF를 저장하고, PDF 렌더러가 그 결과를 이미지로 보여주는 구성입니다. 이미지로 펼치는 대신 PDF 뷰어에서 모든 페이지를 직접 열어봐도 이번 검수의 목적은 같습니다.

도구가 알아서 문서의 완성도를 보장하는 것은 아닙니다. 우리는 만들어진 화면을 보고, 원본을 고치고, 다시 내보냅니다.

1. 확인할 문서와 실행 환경을 준비합니다

이 방법은 AI와 함께 안내문·보고서·자료집을 HTML로 만들고 PDF로 전달할 때 어울립니다. 기존 Word 파일을 편집하는 글은 아닙니다.

직접 명령을 실행하려면 Node.js와 Playwright, Chromium 계열 브라우저가 필요합니다. Playwright가 아직 없다면 빈 작업 폴더에서 아래 명령으로 라이브러리와 브라우저를 준비할 수 있습니다. 기존 프로젝트라면 이미 설치된 도구를 먼저 확인하세요. 공식 라이브러리 설치 안내

npm install --save-dev playwright
npx playwright install chromium

이번 시연은 Windows에 이미 준비된 Playwright 1.62.1과 Chrome을 사용했습니다. 새 컴퓨터에서 설치부터 반복 검증한 사례는 아닙니다.

2. HTML 원본을 PDF로 저장합니다

AI에게 문서를 만들게 할 때 아래 요청을 함께 전달해 보세요.

이 안내문을 A4 PDF로 만들어 줘. HTML 원본도 남겨 줘. Playwright의 Chromium으로 PDF를 저장하고, 저장한 PDF를 모든 페이지가 보이도록 렌더해서 확인해 줘. 표 안의 긴 문장, 제목, 페이지 끝에서 잘리거나 겹치는 부분이 있으면 원본을 고친 뒤 다시 내보내 줘. 실제로 확인하지 못한 부분은 따로 알려 줘.

직접 실행하는 경우에는 document.html과 같은 폴더에 아래 내용을 export.cjs로 저장합니다. 이것은 로컬 HTML을 내보내는 최소 예시이고, 위 시연의 브랜드 서체·지면 전체를 재현하는 코드는 아닙니다.

const { chromium } = require('playwright');
const { pathToFileURL } = require('node:url');
const path = require('node:path');

(async () => {
  const browser = await chromium.launch();
  try {
    const page = await browser.newPage();
    await page.goto(pathToFileURL(path.resolve('document.html')).href);
    await page.evaluate(() => document.fonts.ready);
    await page.pdf({
      path: 'document.pdf',
      format: 'A4',
      printBackground: true,
      preferCSSPageSize: true,
    });
  } finally {
    await browser.close();
  }
})();

실행 명령은 node export.cjs입니다. HTML에 @page 크기를 따로 정했다면 위 코드의 preferCSSPageSize 설정에 따라 그 크기가 우선합니다. PDF의 인쇄 스타일과 용지를 의도한 대로 지정하세요. 설정별 공식 설명

3. 저장된 PDF를 실제로 봅니다

PDF 뷰어에서 첫 페이지부터 마지막 페이지까지 엽니다. 이미 Poppler가 설치되어 있다면 다음 명령으로 모든 페이지를 PNG로 펼칠 수도 있습니다.

pdftoppm -r 150 -png document.pdf page

생성된 페이지 이미지는 페이지 순서대로 확인합니다. 글자만 추출하거나 “파일 생성 성공” 메시지만 보는 것으로 이 단계를 대신하지 않습니다.

이번 예시에서는 02 검수 행의 긴 문장 끝이 잘렸습니다. 화면을 크게 보니 어디가 끊기는지 바로 확인할 수 있었습니다.

4. 원본을 고친 뒤 PDF도 다시 저장합니다

이 예시는 긴 문장을 한 줄로 고정한 설정이 원인이었습니다. 해당 셀의 white-space: nowrap을 해제하고, 아래처럼 내용에 맞게 줄이 바뀌도록 수정했습니다.

.bodycopy {
  white-space: normal;
  word-break: keep-all;
  overflow-wrap: anywhere;
}

행 높이를 작게 고정한 문서라면 그것도 함께 조정해야 합니다. 원본 HTML만 수정하고 예전 PDF를 보내지 않도록, 같은 방법으로 PDF를 다시 저장합니다.

5. 수정한 PDF의 마지막 페이지까지 다시 봅니다

줄바꿈을 고치면 표가 더 높아지고, 아래 문단이나 페이지 나눔도 달라질 수 있습니다. 고친 셀만 확인하고 끝내지 말고 제목·표·페이지 끝을 다시 확인합니다.

이번 수정본은 한 페이지로 저장됐고, 표의 문장 끝과 하단 안내·쪽번호까지 화면에서 확인했습니다. 텍스트 추출로도 수정한 문장이 끝까지 들어 있는지 함께 확인했습니다.

화면 검수는 문서에 적힌 사실이나 링크의 작동까지 보장하지는 않습니다. 숫자·출처·링크는 해당 내용에 맞춰 따로 확인해야 합니다.

다음에 AI에게 PDF를 부탁할 때는 이 문장을 추가해 보세요.

SYNK SNS 디자인을 만들고, 실제 페이지에서 다시 고친 것들

SYNK를 만들고 있는 유호입니다. 첫 제작 기록은 SNS 커버와 프로필을 정리한 이야기로 시작합니다.

펠트의 잔털과 실, 투명한 유리의 가장자리를 함께 쓰고 싶었습니다. 회사가 만드는 것을 처음 만나는 자리인 만큼, 그림의 인상과 함께 이 채널에서 무엇을 볼 수 있는지도 읽혀야 했습니다.

그래서 같은 재료를 쓰면서 배치와 문구를 달리했습니다. 유호 채널에는 회사를 만드는 과정, 브리핑에는 업무에서 AI를 쓰는 방법, 디자인 채널에는 브랜드·웹·콘텐츠 결과물을 담았습니다. 글자를 넣는 자리와 그림을 보여줄 자리를 나누고, 작은 화면에서 남아야 할 요소부터 정리했습니다.

그런데 파일을 완성하고 실제 페이지에 올리는 사이에 다시 손볼 일이 생겼습니다.

1. 바탕을 바꾸되, 캐릭터는 남기기

LAB의 프로필을 보면 몽글 뒤에 크림색 바탕이 있었습니다. 이미지 안에서는 자연스럽지만 흰 페이지에 놓으면 바탕의 경계가 보였습니다. 이번에는 페이지와 이미지의 바탕을 흰색으로 맞추기로 했습니다.

이때 캐릭터를 다시 생성하지는 않았습니다. 이미 쓰고 있던 몽글의 표정과 펠트 질감, 구도를 유지하고 싶었기 때문입니다. 기존 투명 원본과 배치로 바탕만 흰색인 파일을 다시 출력했습니다.

수정 전후를 같은 크기로 놓으면 달라진 범위가 분명합니다. 코랄색 몸과 눈웃음, 아래쪽 실은 남아 있고, 바깥 여백이 흰색으로 바뀌었습니다.

블로그도 확인했습니다. 네이버 PC 블로그의 바탕은 #FBF7F0에서 #FFFFFF로 바꿨습니다. 커버 이미지와 기존 배치는 그대로 두었습니다. 프로필 이미지의 배경과 페이지의 배경은 서로 다른 설정이라, 한쪽만 고쳐서는 끝나지 않았습니다.

2. Behance에서는 배치를 다시 잡기

Behance 커버는 다른 문제였습니다. 3200×410 원본에 글자와 소품을 넣었지만 실제 업로드 미리보기에서는 오른쪽 소품이 잘렸습니다. 상단 메뉴가 이미지 윗부분을 덮는 것도 고려해야 했습니다.

첫 업로드는 저장하지 않고 취소했습니다. 펠트 소품을 다시 만들기보다 이미 있는 소품과 문구를 중앙으로 모았습니다. 전체 크기를 줄이고, 묶음을 아래로 옮겨 실제 보이는 영역에 맞췄습니다.

다시 업로드한 뒤 공개 페이지를 새로고침해 로고와 글자, 소품이 함께 보이는지 확인했습니다. 원본의 여백은 더 넓어졌지만 이 파일이 쓰일 곳에서는 그 여백이 필요했습니다.

3. 생성과 마감을 나눠 보기

이번 커버의 펠트 장면과 유리 로고 응용에는 AI 이미지 생성을 활용했습니다. 최종 문구와 배치는 SVG로 구성했습니다. 정확한 문장을 넣고 채널마다 크기와 여백을 조정할 수 있게 하기 위해서입니다.

모든 수정에 새 이미지가 필요했던 것은 아닙니다. 몽글 바탕은 기존 원본의 재출력으로, Behance의 잘림은 배치 수정으로 해결했습니다. 좋아하는 질감까지 함께 달라지지 않도록, 먼저 고칠 부분을 좁히는 편이 이번 작업에는 맞았습니다.

현재 11개 계정에 12개 커버 파일을 적용했습니다. 티스토리는 PC와 모바일을 따로 구성했고, 모바일에서는 폭 390px의 실제 화면을 확인했습니다. 네이버 모바일의 독립 화면은 별도 확인이 남아 있습니다.

이번에 오래 남을 것은 펠트와 유리의 조합만은 아닐 것 같습니다. 이미지 파일을 보는 일과, 그 이미지가 놓인 페이지를 보는 일은 달랐습니다. 다음 작업에서도 결과물 옆에 실제 사용 화면을 같이 두고 보려 합니다.

이곳에는 SYNK를 만들면서 무엇이 걸렸고, 왜 바꾸었고, 어디까지 확인했는지 계속 남기겠습니다.

안녕하세요. SYNK를 만드는 유호입니다.

SYNK SHIFT는 기업과 기관이 AI를 자기 업무에 활용하고, 가진 가치를 고객에게 전달하도록 돕는 교육·컨설팅과 브랜딩을 준비하고 있습니다.

이 채널에는 직접 만들며 확인한 사례와 준비 소식을 올리겠습니다. 첫 사례는 SYNK의 SNS 디자인입니다. 펠트와 유리 질감을 활용해 커버를 만들고, 실제 페이지에서 소품이 잘리는 부분과 바탕이 어색하게 보이는 부분을 고쳤습니다. 어떤 결과가 필요한지 정하고, 만든 것을 쓰일 자리에 맞추는 과정이었습니다.

• 어떤 업무나 콘텐츠를 만들고 있나요? • 지금 어디에서 어려움을 겪고 있나요? • 어떤 결과를 얻고 싶나요?

채널 채팅으로 이야기를 남겨주시면 됩니다. 구체적인 진행 범위와 일정은 내용을 확인한 뒤 함께 정하겠습니다.

한국어로 말을 꺼내려는 사람과 AI를 업무에 쓰려는 회사에는 서로 다른 도움이 필요합니다. 같은 설명을 전하기 전에, 무엇을 하려는지부터 살피는 것. SYNK가 만드는 개인화 시스템의 출발점입니다.

SYNK는 네 분야에서 그 방향을 구체화하고 있습니다.

LAB은 한국어를 배우고 한국에서의 공부와 생활을 준비하는 교육을 만듭니다. 상황을 이해하고 먼저 말해 본 뒤, 필요한 도움을 받아 다시 시도하는 학습을 설계합니다.

SHIFT는 기업·기관의 실제 업무에 맞는 AI 교육과 컨설팅, 기업 브랜딩을 준비합니다. SYNK를 만드는 과정에서 직접 선택하고 수정한 방법도 공개합니다.

PULSE는 음악과 영상, 캐릭터의 이야기를 만듭니다. 온라인 콘텐츠와 자체 IP를 중심으로, 다시 찾고 싶은 작품을 쌓아 갑니다.

PATH는 외국인의 한국 유학부터 취업까지 이어지는 준비를 돕는 브랜드입니다. 전공과 진로에 맞춘 한국어 학습, 학교 선택, 서류·면접과 포트폴리오를 연결하는 교육·상담 및 기관 협력을 준비하고 있습니다.

첫 글에는 한국어 연습 카드와 LAB 프로필의 수정 전후를 함께 소개합니다. 몽글 프로필의 크림색 바탕이 흰 페이지 위에서 따로 보이는 것을 확인하고, 캐릭터 원본과 구도를 유지한 채 배경을 순백으로 맞췄습니다. 저장한 이미지에 그치지 않고 실제 프로필에 적용한 모습까지 확인했습니다.

학습 자료에서는 배우는 사람이 해 볼 일을, 디자인에서는 실제로 쓰일 화면을 살핍니다. 앞으로도 이렇게 만드는 과정과 실제 결과를 함께 보여드리겠습니다.

기업·기관 AI 교육·컨설팅과 PATH의 지원 서비스는 준비 단계입니다. 구체적인 협업은 필요한 업무와 목표를 먼저 듣고, 현재 가능한 범위부터 이야기하겠습니다.
