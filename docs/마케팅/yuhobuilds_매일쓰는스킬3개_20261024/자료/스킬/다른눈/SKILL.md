# 다른 눈 — 「다 했어요」 전에 새 눈으로 확인

만든 쪽은 자기가 한 일을 좋게 본다. 「다 했어요」라고 해 놓고 실제로는 빠진 데가 있는 일이 그래서 생긴다. 이 스킬은 이 대화를 전혀 모르는 새 하위 에이전트에게 확인을 맡긴다. 내 설명과 결론은 주지 않는다 — 주면 그 말을 믿고 「맞다」고 돌아온다.

## 순서

1. **확인할 것 모으기.** 셋만 모은다.
   - 원래 요청 — 사용자가 쓴 말 그대로. 내가 요약하거나 고쳐 쓰지 않는다.
   - 볼 곳 — 바꾼 파일·만든 결과물의 경로(전부).
   - 돌려 볼 것 — 시험·실행·열어 보기 명령. 명령이 없는 글 · 문서라도 셀 수 있는 조건(글자 수 · 날짜 · 개수)이 요청에 있으면 「○○를 세어 확인」이라고 적는다. 그것도 없으면 「없음」.

   내가 한 일의 설명, 「잘 된 것 같다」, 내가 이미 확인한 것은 넣지 않는다.

2. **새 하위 에이전트 부르기.** 하위 에이전트 도구(Agent 또는 Task)로 **새로** 부른다. 앞서 부른 에이전트를 이어 쓰거나 이 대화를 이어받는 갈래(포크)로 부르지 않는다. 아래 글의 【】만 채워 그대로 준다.

   ```
   너는 이 작업을 처음 보는 검수자다. 아래 요청이 실제로 이뤄졌는지 파일을 직접 열고 명령을 돌려 확인해라. 만든 쪽의 설명은 일부러 주지 않았다. 파일은 고치지 말고 읽기만 해라.

   요청: 【원래 요청 원문】
   볼 곳: 【바꾼 파일·결과물 경로】
   돌려 볼 것: 【시험·실행 명령, 없으면 "없음"】

   답 꼴:
   - 문제마다 한 줄: 심각도(막힘 / 틀림 / 다듬기) · 파일:줄 · 무엇이 깨지는지 · 어떻게 재현하는지
   - 확인했는데 문제없던 것: 한 줄씩
   - 못 본 범위: 한 줄씩
   재현하지 못한 것은 문제로 세지 말고 「의심」으로 따로 적어라.
   ```

3. **답 다루기.**
   - 먼저 문제마다 직접 재현해 본다. 재현되면 적힌 심각도대로, 안 되면 「의심」으로 다룬다(검수자가 「틀림」이라 적었어도).
   - 「막힘」·「틀림」은 고친다.
   - 「다듬기」와 재현된 「의심」은 요청 원문이 시킨 일에 닿으면 고치고, 요청에 없던 것이면 고치지 않고 보고에만 적는다.
   - 「못 본 범위」는 보고에 그대로 옮긴다. 요청이 꼭 시킨 일이 그 안에 있으면 직접 확인한다.
   - 고친 게 있으면 1~2단계를 한 번 더 한다 — 같은 글로 **또 새** 하위 에이전트를 부른다. 두 번째 답에 「다듬기」 · 「의심」만 남으면 더 돌지 않는다.
   - 두 번째에도 「막힘」·「틀림」이 남으면 더 돌지 말고 그대로 사용자에게 보고한다.

4. **보고.** 「다 했어요」 옆에 확인 결과를 한 줄로 붙인다. 예: 「다른 눈 확인: 문제 2개 찾아 고침 · 남은 것 없음 · 못 본 범위: 실제 결제 화면」.

## 지킬 것

- 검수자에게 내 결론·설명을 주지 않는다.
- 검수자에게 파일을 고치게 하지 않는다. 고치는 것은 이 대화가 한다.
- 하위 에이전트를 부를 수 없는 곳이면, 2단계 글을 채워 사용자에게 보여 주고 「새 대화창에 이 글을 붙여 넣어 주세요」라고 안내한다.
