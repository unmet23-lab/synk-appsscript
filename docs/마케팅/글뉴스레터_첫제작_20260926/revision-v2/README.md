Threads와 X의 각 3편은 독립 게시물이다. 한 게시물에 3편을 이어 붙이지 않는다. 기존 @synkbrief의 영상 계정이나 LinkedIn·Behance·카카오용 회사 소개 글은 이번 글·뉴스레터 범위에 포함하지 않는다.

## 독자가 얻을 것

- 첫 앱을 만들려는 사람: 모르는 도구 이름을 비교하기 전에, 자신이 누를 화면·기록이 저장될 곳·연결할 작업을 질문할 수 있다. 실제 초보 경험과 출석 목적을 놓친 반전에서 시작한다.
- 회의록을 정리하는 사람: 이름·기한·확정 여부를 직접 비교하고, 바로 복사할 요청문과 새 메모로 연습한다. 독자가 잘못 옮겨진 날짜를 먼저 찾도록 구성했다.
- 한국어 학습자: 선택 질문과 예·아니요 질문을 구분하고, ‘다시/천천히 말해 주세요’로 대화를 이어본다. ‘네!’부터 나오는 장면과 가리고 말하는 연습으로 연결했다.

이전 초안을 분량만 늘리지 않고 사건·문제 풀이·정답·자기 상황에 적용할 행동으로 다시 구성했다. 이번 개정본은 새 사용자 피드백 전이며 승인된 대표작이나 확정 제작 양식으로 표시하지 않는다.

## 파일 사용

- `index.html`: 서체와 이미지를 내장한 전체 검토 화면. 인터넷 없이 열어도 본문이 보인다. 복사가 차단되는 환경에서는 각 편의 **텍스트 받기**를 이용한다.
- `복사용/*.txt`: 관리 메모를 제거한 9편의 텍스트와 Substack 프리헤더 1개. 블로그·뉴스레터의 표는 텍스트에서도 내용을 보존하도록 Markdown 표 형식으로 둔다.
- `복사용/*.html`: 편별 본문과 이미지를 내장한 독립 HTML 9개. 실제 플랫폼 편집기에는 제목을 제목 칸에 넣고, 본문·표·캡션을 확인해 옮긴다. 복사한 이미지가 빠지면 원본 이미지를 직접 업로드한다.
- `../images/`: 기존 영상·실습에서 가져온 원본 이미지. 네이버는 `프로젝트_지침저장.png`, `보완후_실제응답.png`; Tistory는 `도구선택_재구성.jpg`를 사용한다.
- 원고 MD의 ‘편집 메모 · 게시 제외’는 내부 근거이며 게시 본문에 넣지 않는다.

Substack은 기존 결정대로 **한국어 원본 검토 → LAB 설명의 몽골어 번역·검수** 순서다. 한국어 학습 표현은 유지하고 SHIFT는 한국어 중심으로 둔다. 이번 파일은 몽골어권 독자에게 그대로 발송하는 완성본이 아니다.

## 확인 범위

2026-09-27에 사용자 회고·기존 시연 자료와 사실을 대조하고 별도 검토자가 짧은 글·Tistory를 교차 검토했다. 도구 선택에서 Claude Code가 필수 설치처럼 읽힐 수 있는 연결과 현재 조언을 과거 성과처럼 읽히게 하는 문장을 수정했다.

PC 1440px·모바일 390px에서 다섯 채널의 가로 넘침, 이미지 로드, SUIT 서체, 키보드 탭 전환을 확인했다. 복사 버튼으로 얻은 텍스트가 본문과 같고 편집 메모를 포함하지 않는지도 확인했다. 대표 PC·모바일 화면을 직접 보고 본문·표·요청문 배치를 검토했다. 수치와 캡처는 [검수결과](검수결과.json), `검토화면/`에 있다. 이 검수는 실제 플랫폼의 편집·공개 표시나 독자 반응을 검증한 것이 아니다.

프로젝트의 공통 지침과 채팅 맥락은 [OpenAI 공식 프로젝트 문서](https://learn.chatgpt.com/docs/projects)를 조회해 대조했다. 현재 계정의 세부 메뉴 위치를 새로 실습한 것은 아니며 기존 캡처에는 날짜와 성격을 표시했다. [공개 회의 자료](https://synk.im/brief/meeting/)·PDF·ZIP은 이번 작업에서 HTTP HEAD 200과 콘텐츠 유형을 확인했다. 자세한 근거는 [출처와 확인](출처와_확인.md)에 있다.
