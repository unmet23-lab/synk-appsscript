# PULSE AI 모델 캐스팅북 (2026-09-30)

클라이언트가 PULSE의 AI 모델을 보고 고를 수 있게 만드는 모델 전용 홈페이지다. 모델마다 대표 사진, 앞뒤좌우, 표정(기본·웃음·화남·놀람), 헤어 3가지, 전신·룩 2가지, 피부 근접·손·광고 장면, 목소리 3가지, 신체 정보를 한 창에서 보여 주고, 고른 모델·헤어·목소리를 복사해 크몽 메시지나 발주서에 붙이게 한다.

## 사용자가 정한 것

- 모델 한 명 한 명을 만들고, 남자·여자마다 얼굴 목록·신체 스펙·앞뒤좌우·웃음/화남/놀람·목소리 1~3·헤어 1~3을 보여 준다. 빠진 정보가 있으면 더한다.
- 질감은 Higgsfield 공개작 두 편(Seedance 2.5, 러닝머신·야전병원) 수준 이상으로, 진짜 사람처럼 보여야 한다.
- 모델 전용 프로그램이나 홈페이지로 만들어 클라이언트에게 전달한다.
- K팝 아이돌 스타일이거나 매력 있게 생긴 10대·20대·30대가 필요하다. 40대 이상은 이번 목록에 넣지 않는다.
- 후보는 상큼하거나 섹시하거나 지적이어야 한다. 10대(19세로 설정)에는 섹시 콘셉트를 쓰지 않는다(작업 기준).
- 확정 모델(2026-09-30~10-01 사용자 선택). 코드·이름은 `roster-v2.json`이 원본이다.
  - M01 이안: 20대 남 후보 b(`raw/M20-hero-b.png`, Soul 2.0)
  - F01 유나: 20대 여 후보 b(`raw/F20-hero-b.png`). 티셔츠 글자만 로컬로 지운 `raw/F20-hero-b-clean.png`를 쓴다
  - F02 하린: 20대 여 상큼 a(`raw/F20-fresh-v3-1.png`). 165cm·50kg은 가상 모델 설정이며, 몸무게 50kg은 2026-10-12 사용자가 확정했다.
  - F03 서진: 20대 여 지적 b(`raw/F20-smart-v3-2.png`)
  - M02 태준: 30대 남 섹시 a(`raw/M30-sexy-v3-1.png`). 사용자가 b(서양계 얼굴)에서 a로 바꿨다
  - F04 지유: 20대 여 상큼 b. a와 머리가 같아서 사용자 요청으로 머리만 긴 흑발로 바꿨다(`raw/F20-fresh-v3-2-hairA.png`). 앞머리 단발 시안은 헤어 2로 쓴다
  - M03 유호: SYNK 대표 본인. 사용자가 “나도 넣자”고 요청했다. 처음에는 인터뷰 영상(`OneDrive/Desktop/SYNK_창업자_인터뷰_v9_친구에게보내기_1080p.mp4`) 6장면을 참조한 후보 5(`raw/M-yuho-hero-5.png`)를 썼다. **2026-10-01 유호님이 확정한 얼굴로 모두 바꿨다.** 대표 사진은 `raw/M-yuho-hero-v5.png`(roster-v2 기준), 세트는 `raw/Myuho-*.png`, 옆얼굴 두 컷은 10-01 밤 시안 B 방식(실제 사진만)으로 다시 만든 90도 옆모습이다(「오 전부 나같아」, 이전 컷은 `raw/_old_M03_angles2_20261001/`). 웃음 컷은 10-01 밤 임시로 "B 방식 웃음 1을 부분 칠하기로 캐스팅북식으로 바꾼 컷"으로 바꿨다. 유호님 판정은 「전보다 훨씬낫다」이고, 승인한 컷은 아니다. 그 전 임시 컷은 캐스팅용 웃음2(「그나마 나랑 비슷해」, `raw/_old_M03_smile_temp2_20261001/`)와 B2(「쓰레기」, `raw/_old_M03_smile_tempB2_20261001/`)다. 10-02 목록 카드의 마우스 올림 웃음에는 같은 B 방식 웃음 1을 대표 사진 구도(머리·어깨)로 넓힌 컷을 쓴다(`raw/Myuho-smile-card.png` → `raw/Myuho-hover.png`). 처음 올린 판(12판)은 GPT Image 2가 사진을 멀리서 다시 그린 것을 1.44배 키워서 「화질이 너무 안좋다」였다. 13판은 검은 티 장면에 원본 잔결을 옮긴 합성본이었고 「그나마 비슷한데 조금 화질이 아직 문제」였다. 14판부터는 맨 처음 Nano Banana Pro 원본(붉은 벽·니트·턱에 손, 「이건 진짜 나같긴한데」)을 장면 그대로 쓴다. 대표 사진 구도에 모자란 위(정수리)·아래(니트·손목)만 GPT로 칠했고, 원본이 덮는 곳은 원본 픽셀 그대로다. 「지금 버전이 젤 낫다」. 15판에서 배경 색만 코랄에서 대표 사진 배경색으로 바꿨다. 다시 그리지 않고 벽 픽셀의 색만 옮겼고, 얼굴·니트·손은 그대로다. 만든 과정과 스크립트는 바탕화면 `HappyGangster_20260930/웃음_후보/B방식_웃음1_카드용/`에 있다. 이 컷도 승인한 컷은 아니다. 예전 사진은 `raw/_old_M03_20261001/`, `raw/_old_M03_angles_20261001/`, `raw/_old_M03_smile_20261001/`에 있다. 유호님 얼굴은 이 확정 얼굴만 쓴다. `Yuho-PULSE` 소울(`raw/yuho-train/` 20장)은 예전 얼굴이라 쓰지 않는다. 기준은 [고정 얼굴 세트](../제작양식/실제얼굴_화보_뮤직비디오.md#고정-얼굴-세트)다. 신체 정보(180cm, 110(XXL), 30, 270)는 본인이 알려 준 값이다(10-01 상의 105 → 110으로 고침, 「그냥 110으로 고쳐줘」). 같은 날 몸이 나오는 6컷(전신·정면 상반신·룩1·룩2·뒷모습·작업실)은 어깨가 실제보다 좁다는 지적에 따라, 얼굴은 두고 어깨·가슴·팔만 110 체격으로 다시 칠했다(예전 컷 `raw/_old_M03_body_20261001/`). 목소리 3가지는 같은 인터뷰의 원음 구간이다(배경음악 포함)
- 유호 대표 사진에서 확인한 것: 사용자는 사진 기준 왼쪽 눈만 쌍꺼풀이 있다. AI 편집으로 쌍꺼풀만 지우거나 넣은 수정본(`M-yuho-hero-7-fix*`, `-asym*`, `-one-lid`)과 조건을 넣어 새로 만든 12~15는 모두 “인위적”이라는 이유로 채택하지 않았다. 얼굴을 고칠 때는 부분 편집보다 처음 후보에서 고르는 편이 결과가 나았다.
- 구글 무료 크레딧(Vertex, 프로젝트 `synk-bake-unmet27`)으로 이어서 만든다.

## 만드는 방법과 확인한 것

| 단계 | 도구 | 확인 결과 |
|---|---|---|
| 대표 얼굴 | Higgsfield Soul 2.0(0.12크레딧/장), 크레딧이 떨어진 뒤 구글 Nano Banana Pro(`gemini-3-pro-image`, 2K 약 190원/장) | 같은 설명으로 비교했을 때 Soul이 가장 사람 같았다(`review/01_생성모델_비교_F01.jpg`) |
| 같은 얼굴의 다른 컷 | Nano Banana Pro에 대표 사진을 참조로 넣음 | 옆모습·웃음이 같은 사람으로 나왔다. Seedream은 얼굴이 바뀌고 Soul은 참조를 줘도 다른 사람이 됐다(`review/02_같은얼굴_유지시험_F01.jpg`). F01 서아 15컷 전체도 같은 사람으로 확인(`review/04_F01_전체세트.jpg`) |
| 목소리 | 구글 Gemini TTS(`gemini-2.5-flash-tts`). 유호만 인터뷰 원음 | 받아쓰기로 지시문을 소리 내 읽지 않은 것을 확인했고, 음높이 중앙값으로 성별을 확인했다(남 91~151Hz, 여 235~286Hz). 서진 2번은 대사를 두 번 읽어 다시 만들었다. 유호 원음은 로컬 faster-whisper(small)로 문장 경계를 찾았다. Gemini 받아쓰기의 시각은 부정확해서 자르기 기준으로 쓰지 않는다. `voice-check.cjs`, `transcribe-ts.cjs` |

주의할 것.
- 구글 무료 크레딧에서 생성할 때 분당 한도(429)가 자주 걸린다. `gen-gemini.cjs`는 기다렸다 다시 던지고, 크레딧 벽이면 멈춘다. 동시 실행은 2개가 알맞았다.
- 참조 사진으로 «사진 양식»만 따라 하게 하면 얼굴이 참조 인물을 닮는다(`review/07_v2시험.jpg`의 30대 남). 새 얼굴은 참조 없이 조명·색감을 글로 지정한다.
- 프롬프트에 필름 이름(Kodak Portra 400)을 쓰면 필름 테두리와 글자가 생긴다. 지금 계획 파일에서는 뺐다.
- 참조 사진의 점·티셔츠 글자가 다른 컷으로 옮겨 가거나 새 점이 생길 수 있다. 프롬프트에 “참조에 없는 점·자국을 더하지 말 것”을 넣었다.
- Higgsfield의 7일 무제한은 higgsfield.ai 웹에서 직접 누를 때만 적용되고 CLI·MCP·자동화에는 적용되지 않는다(공식 도움말).

## 모델 고르기 (2026-10-17)

유호님 「학습하고 나서 클라이언트가 이 모델 고르기 편하게 시스템도 하나 만들자」(하린 명세서 v1 작업 중). 새로 만들지 않고 이 캐스팅북을 키웠다. 모델 자료·빌드·목소리·문의 글 흐름이 이미 있었고, 빠진 것은 거르기 폭·비교·추천·명세서 자료·화면 틀이었다. 화면은 펠트 스크랩북 판을 버리고 PULSE 고객 화면의 10-17 밝은 스튜디오 판(결정 표 10-17) 토큰과 글자 단계(680·650·600·550·450, 한글 13px 이상)로 다시 짰다.

- 흐름: 첫 화면 키 눈금(7명을 정수리~신발 바닥 cm 그대로 세움) → 브리프 추천(업종·제품·분위기·성별·나이대 → 3명, 고른 이유와 그 업종 사진) → 거르기(성별·나이대·콘셉트·키 구간·업종) → 카드 → 상세(기본 정보·얼굴 각도·전신 각도·표정·헤어·룩·디테일·장면 사진·움직임·몸과 비율·얼굴과 색·어울리는 연출, 오른쪽에 헤어·목소리 고르기) → 비교(3명까지, 같은 컷 바꿔 보기, 같은 눈금 키 비교, 수치·사이즈·헤어·목소리·업종·브리프와 맞는 점) → 내 선택(크몽 메시지·발주서 메모 두 모양으로 복사, 함께 비교한 모델과 손댄 브리프도 들어감).
- 추천 규칙(`site-src/casting-logic.js`): 고른 업종 3점, 제품 설명 낱말로 찾은 업종 2점, 설명에 세부 분야(`catalog.json`의 `sub`, 예: 아이스크림 → 디저트)가 있으면 업종 문구에 그 분야가 든 모델 +1·없는 모델 -1, 고른 분위기 2점, 낱말로 찾은 분위기 1점, 그 업종 사진이 있으면 0.5점, 같은 점수는 명단 순. 성별·나이대는 거르기로만 쓰고, 성별을 안 골라도 설명에 「여성 니트」처럼 성별 낱말(`genderWords`)이 있으면 그 성별 안에서 찾는다. 확인한 예: 딸기 아이스크림 → 하린·지유·이안, 가계부 앱 → 서진·하린·이안, 남성 향수 → 이안·태준, 프리미엄 위스키 → 태준. 낱말은 긴 것부터 찾아 「아이스크림」 속 「크림」 같은 겹침을 막고, 영문은 낱말 경계에서만 찾는다. 모델 쪽 분류는 `roster-v2.json`의 `fits`·`impression`·`concept` 문구를 `catalog.json`의 분류 낱말에 맞춰 빌드 때 붙인다.
- 정보가 일부만 있는 모델: 있는 칸만 그린다(「준비 중」 빈 칸을 두지 않음). 비교 표의 빈 값은 「—」, 고른 컷이 없으면 대표 사진과 안내 한 줄. 명세서가 있는 모델만 카드에 「상세 프로필」 꼬리표.
