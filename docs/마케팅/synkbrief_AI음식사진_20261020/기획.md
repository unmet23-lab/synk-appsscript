# synkbrief 활용 · 메뉴판 AI 음식 사진, 만들지 말고 다듬기

> 2026-10-20 18시대 유호님 「오늘 다 올려야되는데. 지금 전부 각각 하나씩 제작준비하자. 우리 앞으로 1일 1 컨텐츠 업로드해야해. 준비된 모든 채널에 말이야」. 조율 세션 「예약된 게시물 확인」이 synkbrief 몫으로 이 편을 골랐다. 채널은 SHIFT 정보 `@synkbrief`(인스타 릴스 · 유튜브 쇼츠 「SYNK 브리핑」), 같은 내용을 SYNK SHIFT 네이버 블로그(synkshift) 상세 글로 푼다. 제작 기준은 [제작 방식 v2](../콘텐츠_제작방식_v2_20261002.md), 화면 틀은 지난 편 [AI 구독 계정판](../synkbrief_AI구독계정판_20261017/기획.md)의 Remotion 부품(청금석 무대·위로 밀기·크레용 밑줄·박 착지)을 그대로 쓴다.
> 오늘은 조율 세션 판단으로 콘티·이미지 콘티 단계에서 유호님 답을 기다리지 않고, Fable 검수를 거친 콘티로 바로 만들었다. 유호님이 고르는 자리는 최종본 확인 하나다.

## 볼 이유

메뉴 사진을 AI로 만들면 표시 의무는 없지만, 손님은 「막상 나온 음식이 다르면 속은 기분」이라고 한다. 이 편은 **없는 음식을 만들지 말고, 찍은 사진을 다듬는** 방법을 실제 사진 한 장으로 끝까지 보여 준다 — 요청문 한 번 → 결과 → 올리기 전 확인 셋(양·재료·색) → 실제로 국물이 빨개진 걸 잡아내 한 줄 더해 다시. 「AI가 알아서 해 주겠지」라는 흔한 오해를 결과로 깬다.

## 형식과 길이

- 시리즈 `synkbrief 활용`. 형식: 흔한 오해 깨기 + 결과 먼저(전후). 세로 1080×1920, 41.9초(배경음 80박 + 곡 끝맺음 2.8초).
- 훅 시험: 지난 편처럼 플랫폼으로 나눈다 — 인스타 **A(결과)**, 유튜브 쇼츠 **B(질문)**. 같은 계정에 같은 영상을 다시 올리지 않는다.

## 0초 훅(후보 6의 세 안에서)

| 안 | 스캔 원안 | 이 편 | 0초 화면 |
|---|---|---|---|
| ③ → **A(인스타)** | 「우리 가게 짜장면 사진, 진짜 음식 그대로 밝게만」 | 「진짜 라볶이 사진, / 양·재료는 그대로, / 빛·배경만 AI로」 | 원본 │ 결과 2 반반 카드(가운데 선이 0프레임부터) — 왼쪽 원본엔 찜기 뚜껑, 오른쪽엔 쇠그릇이 걷힌 빈 상 |
| ② → **B(유튜브)** | 「AI 음식 사진, 표시 의무는 없어요. 그런데 손님은…」 | 「메뉴판에 / AI로 만든 음식 사진, / 써도 될까요?」 | AI 생성 라볶이 + 「AI 생성 예시 · 실제 음식 아님」 도장 |

- 스톡 사진이라 「우리 가게」라고 하지 않는다. 짜장면은 상업 이용이 깨끗한 실제 사진을 못 찾아(아래 「사진 출처」) 라볶이로 바꿨다(Pexels 정보는 「서울」까지라 「분식집」이라고 하지 않는다).
- 결과에 대한 말은 확인한 것만 쓴다 — 「음식은 그대로」는 요청문 인용으로만, 결과는 「양·재료는 그대로」.

## Fable 콘티 검수(10-20) — 짚은 것과 반영

전체 메모는 scratchpad(7일 뒤 지워짐)라 요지만 옮긴다.

- **P1 반영 ①** 03에서 AI 생성 판을 「메뉴판」, 원본(다른 가게 스톡)을 「나온 음식」으로 맞바꾸면 보는 사람은 한 가게의 전후로 읽는다 → 맞바꾸기를 없애고 AI 생성 예시 위로 손님 말이 올라오게 했다.
- **P1 반영 ②** 05 말 「빛과 배경만」이 화면 요청문(「빛·색·배경만」·「색은 실제에 가깝게」)과 어긋남 → 말을 화면과 맞추고, 07에서 「실제에 가깝게라고만 썼더니」로 왜 빨개졌는지를 말한다.
- **P1 반영 ③** 08 「색 칩 ✓」는 실측(원본 36.4° · 결과 2 33.8°)과 어긋남 → ✓ 없이 「똑같진 않아도 훨씬 가까워졌어요」.
- P2 반영: 02 「지금은」(원문 「현행법상」), 06 「잡동사니만 사라졌어요」 단정 대신 「얼핏 보면 배치 그대로, 가장자리만 깨끗해졌죠」, AI 생성 판 도장에 「예시」, 03 화면 인용은 원문의 이어진 구절 「실제랑 다르면 속은 기분이 든다」, 09 질문은 O·X로 갈리는 「AI 메뉴 사진, 표시해야 할까요?」, 훅 A 화면 「양·재료는 그대로」.
- P3 반영: 05 카드는 타자 대신 한 장으로(밑칠만 움직임)하고 2박을 더 줬다(05 착지 32 → 30박).

## 맞춤 프로그램 · 끝 행동

- 10-20 확인: synkbrief 허브 `synk.im/brief/`는 404(공개 안 됨). 카타나 요청문 도구 `synk.im/brief/katana`에는 주인공 「음식·음료 — 재료와 양이 사진과 달라지지 않게 잠글게요」가 있지만 힉스필드 카타나로 **영상**을 만드는 요청문이고 체험에 카드 등록이 필요해, 사진 다듬기 끝 행동으로는 맞지 않는다. `synk.im/shift`의 써 보기는 「AI 컴퓨터 맞춤 추천」뿐.
- 그래서 끝 행동은 **요청문 전문을 글(인스타 캡션 · 유튜브 고정 댓글·설명란)에 그대로** 두는 것. 댓글 → DM 전달은 약속하지 않는다. 카타나 도구는 블로그 끝에 「짧은 메뉴 영상까지 만들고 싶다면」 한 줄로만, 체험 조건과 함께.
- 다음 할 일: synkbrief 편 설정 **「내 메뉴 사진 다듬기 요청문」**(메뉴 종류·사진 문제·쓸 곳·음식 색 → 이 편의 여섯 줄 + 확인 셋), 카타나 도구와 같은 틀. [제작 절차](../맞춤도구/제작절차.md)대로 만든다.
