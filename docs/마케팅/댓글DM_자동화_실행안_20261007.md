# 댓글 DM 자동화 도구 비교와 첫 캠페인 실행안

> **과거 조사·초안 보관:** 2026-10-08 자체 제작 시스템의 운영 배포·실제 자료 수신·중단·자동 감시 확인을 완료했다. 현재는 팔로우 조건 없이 답장 요청 후 자료를 전달한다. [댓글 DM 자료표](댓글DM_자료표.md)와 [운영 문서](../../../SYNK-talk/docs/synkbrief_DM.md)가 최신 기준이다. 아래 가격·추천·미실행·팔로우 조건은 10-07 당시 기록이며 지금 실행할 할 일이 아니다.

2026-10-07 후속: **사용자가 자체제작 진행을 선택했다.** 기존 talk 기반에서 팔로우 확인·다계정·중복 방지를 로컬 구현하고 관련 시험 40/40을 통과했다. [현재 운영 문서](../../../SYNK-talk/docs/synkbrief_DM.md)·[첫 캠페인 설정 초안](../../../SYNK-talk/docs/synkbrief-first-campaign.json)을 따른다. 아래 외부 도구 비교는 선택 전 조사 자료이며 외부 가입 추천은 보류한다. 가입·연결·결제·공개 게시·실제 DM 발송은 하지 않았다.

정책 확인: Meta 일반 스팸 규정의 상위 문맥과 이 private DM 흐름의 적용 관계는 확정하지 못했다. 사전 조건 고지를 허용 근거로 삼는 InstantDM의 설명은 업체 해석이다. 유료 도구만 특별히 허용됐다는 근거도 없다. 운영 문서에 공식 근거와 확인 한계를 정리했으며 공개 안내·문구 승인은 남아 있다.

요구사항은 댓글 → 첫 DM의 단추 → 팔로우 확인 → 자료 전달이다. 팔로우하지 않고 확인 단추만 눌러도 자료가 나오는 도구는 채택하지 않는다. 좋아요는 전달 조건으로 검사하지 않고 문구로만 부탁한다.

## 1. 공식 요금과 기능 비교

금액은 USD다. 세금·카드 환산액을 포함한 결제 금액은 가입 후 결제 화면에서 다시 확인한다. 월 납부액과 연간 결제의 월 환산액을 구분했다.

파트너 표시는 각사의 공식 공개 설명을 대조한 결과다. Meta 파트너 디렉토리에서 세 업체를 독립적으로 확인한 것은 아니며, 실제 계정 연결·DM 동작을 보장하는 표시는 아니다. 한국어 관리 화면 지원과 직접 작성한 한국어 DM의 전송도 구분한다.

**추천 이유:** 이번에는 계정 하나·릴스 하나·정해진 문구와 링크만 필요하다. InstantDM의 기본 유료 기능에 Welcome Message·Follow Gate·공개 답글이 포함되고, 월 결제액이 더 낮다. 복잡한 Flow Editor를 위해 Trendsetter에 가입할 필요는 없다. 체험에서 미팔로우 차단이나 중복 방지가 실패하면 유료 전환하지 않고 Manychat Essential을 다음 후보로 삼는다. Manychat을 쓰면 활동 연락처 초과 허용을 0으로 제한할 수 있는지 설정 화면에서 확인한다.

CreatorFlow는 후보에서 제외했다. 공식 도움말이 Follow Gate를 **자기 확인 방식**이라고 설명하며, 실제로 팔로우하지 않아도 확인 단추를 누르면 링크를 보낸다고 명시한다.

## 2. 첫 캠페인 설정 초안

게시물·키워드·자료 주소의 원장은 [댓글 DM 자료표](댓글DM_자료표.md)다. 첫 대상은 @yuhobuilds의 [AI한테 한 줄 시켰더니](https://www.instagram.com/reel/DeMSHfwK5Iz/)이며, 아래 문구는 모두 유호님 확인 전이다.

| 단계 | 문구 또는 동작 |
|---|---|
| 댓글 조건 | 해당 릴스에 `매뉴얼`. 전체 게시물·모든 댓글 대상 자동화는 끔 |
| 첫 DM | 댓글 남겨 주셔서 고마워요! 질문 다섯 개로 내 AI 직원 매뉴얼을 만드는 도구예요. @yuhobuilds 팔로우를 확인한 뒤 링크를 보내 드릴게요. |
| 첫 단추 | `자료 받기` — 웹 주소를 여는 단추가 아니라 다음 메시지로 이어지는 단추 |
| 미팔로우 안내 | 아직 @yuhobuilds 팔로우가 확인되지 않았어요. 팔로우한 뒤 아래 단추를 다시 눌러 주세요. |
| 미팔로우 단추 | `프로필 열기` / `팔로우 확인` |
| 팔로우 확인 후 DM | 팔로우 확인됐어요! 아래에서 내 일에 맞는 AI 직원 매뉴얼을 만들어 보세요. ChatGPT·Claude·Gemini에 붙여 쓸 수 있고, 로그인 없이 이용할 수 있어요. |
| 자료 단추 | `매뉴얼 만들기` → `https://synk.im/builds/` |
| 공개 답글 | 자료 받는 방법은 DM을 확인해 주세요 📩 요청함에 있을 수도 있어요. |
| 좋아요 부탁 | 최종 DM 끝에 선택적으로 `도움이 됐다면 영상 좋아요도 부탁드려요 😊` |

InstantDM에서 Instagram DM → 해당 릴스 → 키워드·DM·공개 답글을 입력하고, Welcome Message와 Ask Follow를 함께 구성한다. 첫 DM에는 자료 링크를 넣지 않는다. 같은 사람의 같은 게시물 중복 실행을 막는 One-Time Only 옵션은 기존 게시물 설정에서도 노출되는지 확인하고 켠다. 공식 문서에서 이 옵션을 명시한 곳은 다음 게시물 설정이므로 기존 릴스에서는 실수신 시험으로도 확인한다.

자동화 저장과 활성화가 분리돼 있으면 초안으로 저장한다. 저장 자체가 활성화라면 승인 전에는 저장하지 않는다. 자동 숨김·삭제, AI 답글, 이메일·전화 수집, 재촉 DM, 과거 댓글 일괄 재발송은 사용하지 않는다.

## 3. 승인 후 시험 순서

가입·OAuth는 유호님이 직접 한다. @yuhobuilds가 프로페셔널 계정인지 연결 화면에서 확인한다. 결제·카드 등록·자동 갱신 체험으로 바뀌면 실제 금액과 조건을 알리고 별도 승인을 받는다. **무료 가입 승인은 공개 댓글 작성이나 자동 발송 활성화 승인이 아니다.** 문구·대상 릴스·시험용 계정·활성화 범위를 보여 드린 뒤 실행한다.

새 시험 댓글도 공개 게시에 해당한다. 승인된 시험 계정으로, 승인된 시간에 해당 릴스만 잠깐 켜서 확인한다. 필요하면 시험 동안 키워드를 `매뉴얼시험1007`로 제한하고, 통과 뒤 승인된 `매뉴얼`로 바꾼다. 댓글을 이미 남긴 계정은 첫 댓글 제한 때문에 재시험에 적합하지 않을 수 있다.

| 확인할 동작 | 통과 조건 | 현재 |
|---|---|---|
| 미팔로우로 키워드 댓글 | 첫 DM과 안내 도착, 자료 링크 없음 | 미실행 |
| 팔로우 없이 확인 단추를 5회 누름 | 횟수와 관계없이 자료 링크 없음 | 미실행 |
| 팔로우한 뒤 같은 DM에서 다시 확인 | 자료 링크 1회 도착 | 미실행 |
| 이미 팔로우한 별도 계정 | 첫 단추 뒤 불필요한 팔로우 요청 없이 자료 도착 | 미실행 |
| 같은 계정으로 같은 게시물에 재댓글·단추 재클릭 | 같은 캠페인의 자료 DM이 중복되지 않음 | 미실행 |
| 다른 키워드·다른 게시물 | 이번 캠페인 발송 없음 | 미실행 |
| 한글·줄바꿈·단추·모바일 링크 | 깨짐 없이 읽히고 매뉴얼 도구가 열림 | 링크의 데스크톱 입구만 확인 |
| 확인 실패·연결 오류 | 팔로우 확인을 건너뛰어 자료를 보내지 않음 | 미실행 |

10-07 `https://synk.im/builds/`를 브라우저에서 열어 `/builds/manual/`로 이동하고 「질문 다섯 개로 만드는 내 AI 직원 매뉴얼」 화면과 「로그인 없음」을 확인했다. 이 확인은 Instagram DM 수신이나 휴대폰 사용 시험을 대신하지 않는다.

실제 수신 시각·단계·중복 여부를 원장에 기록한다. 타인의 계정명·DM 원문을 저장소에 남기지 않는다. 모두 통과한 뒤에만 후속 캡션에 댓글 DM 제공을 약속한다. 기존 공개 캡션·사용자 댓글은 바꾸지 않는다.

## 4. 자체 시스템 준비

인계 뒤 현재 코드를 읽어 보니 talk에 `synkbrief-dm` 함수와 `marketing.synkbrief_*` 표가 이미 있다. 새 웹훅을 Apps Script에 만들지 않고 **기존 talk 함수를 여러 계정·팔로우 확인 방식으로 확장**한다. 담당 설계는 [talk의 synkbrief DM 운영 문서](../../../SYNK-talk/docs/synkbrief_DM.md)에 남겼다.

- `Code.js`의 `doPost`는 이미 `synkbrief_웹훅_`에 연결되고, `doGet`은 확인 토큰이 맞으면 `hub.challenge`를 반환한다.
- Apps Script와 talk 발송 코드 모두 댓글에 `recipient.comment_id`를 사용한다. 이 부분은 새로 만들 일이 아니다.
- talk는 요청 원문에 대한 Meta 서명 검사와 직접 200 challenge 응답을 구현했다. Apps Script의 ContentService는 [Google 공식 문서](https://developers.google.com/apps-script/guides/content)상 리디렉션을 사용한다. Meta가 현재 Apps Script 주소의 리디렉션을 수락하는지는 시험하지 않았다.
- 현재 두 구현은 @synkbrief 하나에 묶여 있고, 첫 DM에서 자료 링크를 바로 보낸다. 여러 계정·단추 응답·팔로우 확인·단계별 중복 방지는 아직 구현 전이다.
- talk 운영 문서에는 10-02 함수 배포와 비밀값 미설정 기록이 있다. 이번에는 원격 비밀값·발송 스위치·웹훅 연결을 재조회하거나 변경하지 않았다.
