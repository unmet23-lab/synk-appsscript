## 9월 회차로 특히 좋은 사건

1. **9/5 옷을 만들어 붙였는데 실제로 입은 것처럼 보이지 않았다.** 실패 그림과 선택 이유가 선명하다. 9/9~10 표정·털 보존 작업으로 이어서 ‘생성 성공 → 자산 일관성 문제 → 사용처 반영’까지 보여 줄 수 있다.
2. **9/6과 9/13 움직이면 살아 보일 줄 알았는데 멀미가 났다.** 사용자의 반복 피드백이 전환점이다. 고정할 것과 움직일 것을 분리해 고친 실물 전후가 있다. 9/13의 `qa/grass-contour.png` 등은 Git에서 복구 가능한 당시 자료다.
3. **9/9 라디오가 끊기는 두 가지 이유.** 짧은 반복 틈과 송출 정체를 분리한 사례로, 미리보기 확인에서 실제 YouTube 수신 확인까지 넘어간다. 전문 용어는 화면 밖 설명으로 최소화하고 실제 들리는/보이는 차이를 중심으로 편집한다.
4. **9/16 테스트는 통과했는데 홈페이지 버튼이 안 보였다.** 답변 데이터와 화면의 허용 목록이 어긋났다. 기능 구현·테스트·공개 화면 확인이 서로 다르다는 경험을 설명하기 좋다.
5. **9/18 줄이려다 지워 버린 문서를 복구했다.** 도구를 정리한 성공담으로만 포장하지 않고 정리 과정의 손실과 복구를 함께 담을 수 있다.
6. **9/21 기억하는 앱을 만들기 시작했다.** 9/18의 실행 중 메모리 → 9/21의 명시적 도움 선호 저장·다른 콘텐츠 연결로 흐름이 이어진다. ‘사용자를 전부 기억하는 AI 완성’ 같은 표현은 근거 밖이다.

## 콘텐츠에 쓰기 전 확인할 것

- 사건별 선택·피드백은 당시 기록에 있는 범위만 사용한다. 모르는 감정, 매출, 시간 절감, 고객 반응, 학습 향상, 당시 작업 시간을 새로 만들지 않는다.
- Git 커밋 수·엔진 수·파일 수·계정 수는 조사 위치를 찾는 단서다. 성장·성공·운영 성과로 제시하지 않는다.
- 과거 기록에는 이제 폐기된 문체 규범·도구 고정·브랜드 배경색이 섞여 있다. 당시 사실을 설명하는 데 필요한 것만 쓰고 현재 지침으로 되살리지 않는다.
- 9/4 음악 길이 기록은 같은 절 안에서 표와 설명이 충돌한다. 단순히 ‘실험 결과 요청값과 실제 길이가 달랐다’까지만 채택한다.
- 9/3 시트 열 수정은 해당 커밋에서 실제 운영 실행 검증을 남겨 두었다. 날짜별 후속 실행 증거 없이 그날 라이브 수정 완료로 올리지 않는다.
- 9/18 문서 복구는 실제 사고와 복구 기록이다. 누가 일부러 망가뜨렸다는 동기나 사용자 피해를 추정하지 않는다.
