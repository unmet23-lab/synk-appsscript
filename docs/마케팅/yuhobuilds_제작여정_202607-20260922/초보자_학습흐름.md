# yuhobuilds — 이야기를 따라 배우는 AI 기본기

2026-09-22 사용자 방향. **AI 완전 초보부터 AI를 활용하는 1인 기업가까지**, 유호의 실제 제작·사업 여정을 친근하고 재미있게 따라오면서 필요한 팁과 정보를 쉽게 이해하고 자기 일에 적용할 수 있는 채널을 만든다. 초급에서 중급, 이후 고급으로 이어가되 앞에서 배운 것을 다음 시도에 사용한다. 자기 문제를 해결하는 데서 제품·서비스를 만들고 사람들에게 제공하며 사업을 운영하는 판단까지 연결한다. 아래 주제와 배치는 편집 제안이며 확정 편수·발행 일정이 아니다.

## 시청자가 가져갈 것

“나도 저기서 막혔는데” 하고 이입하고, 왜 막혔는지 이해하고, 자기 화면에서 다음 행동을 할 수 있게 한다. 완성 결과만 보여주지 않고 처음 켜는 화면·저장 위치·실행·오류·확인까지 필요한 장면을 보여준다. 설명을 들은 시청자가 무엇을 해보면 되는지, 무엇을 보면 잘된 것인지 알 수 있어야 한다.

실화와 각색이 이야기의 중심이다. 당시 상황과 기대, 시행착오, 선택의 결과를 따라가다가 필요한 개념을 설명한다. 개념을 모두 먼저 외우게 하거나 한 편에 여러 도구를 설치시키지 않는다. 정보가 많으면 같은 사건을 여러 회차로 나누고, 자세한 따라하기도 yuhobuilds 안에서 이어갈 수 있다. synkbrief에는 그중 독립적으로 써볼 방법을 파생할 수 있다.

## 장면과 설명을 연결하는 방식

예를 들어 파일 위치를 몰라 헤맨 실제 경험이 확인되면, 그 답답함을 장면으로 보여준 다음 파일·폴더·저장 위치를 설명하고 시청자가 자기 파일 하나를 찾아보게 할 수 있다. “AI가 됐다고 했는데 실제 화면은 안 뜬다”는 사건에서는 저장·실행·결과 확인을 구분해 보여준다. 파일 위치를 몰랐다는 구체적 사건은 아직 사용자 회고로 확인하지 않았으므로 현재는 연출 예시다.

이야기의 길이와 흐름에 따라 설명을 끼워 넣는다. 매 편 같은 대사·분량·순서를 강제하지 않는다. 도구 이름과 용어가 등장하면 그 장면에서 어떤 일을 맡는지 먼저 알 수 있게 하고, 다음 행동에 필요하지 않은 세부 사항은 뒤로 미룬다. 유머는 기대와 실제 작업 사이의 차이에서 살린다. 긴 작업시간은 경험으로 다루며 학습에 필요한 조건으로 제시하지 않는다.

## 초반에 쌓을 기본기

실제 사건은 [시간순 구성안](연재_구성안.md)을 따른다. 아래는 시청자가 이해하기 위한 선후관계이며 유호가 당시 이 순서로 배웠다는 주장이 아니다. 정확한 회차는 사건 자료와 현재 재현 화면을 보고 정한다.

| 학습 지점 | 이야기와 연결할 질문 | 시청자가 해볼 일과 확인할 결과 |
|---|---|---|
| 1. 해결할 일 정하기 | 번역에 쓰던 AI로 왜 출석 앱을 만들려 했나? | 누가 어떤 불편을 겪는지 한 문장으로 쓰고, AI와 가장 작은 첫 작업을 정한다 |
| 2. 도구의 역할과 첫 화면 | Claude, Claude Code, Gemini, Codex라는 이름이 나올 때 각각 무엇을 하려고 쓰는가? | 해당 회차에 필요한 도구 하나를 골라 현재 화면에서 열고 첫 요청의 결과를 확인한다. 모든 서비스를 결제·설치하는 과정으로 만들지 않는다 |
| 3. 작업이 남는 곳 | 대화에서 받은 결과와 내 작업 파일은 어디에 있는가? | 폴더 하나를 정하고 파일을 저장한 뒤 닫았다가 다시 찾아 연다. 필요한 시점에 경로·확장자·프로젝트 폴더·도구 설정 폴더를 구분한다 |
| 4. 파일의 역할과 실행 | `.md`, 코드, 데이터, 스크립트라는 말을 어디에서 만나는가? | 실제 예제의 파일 하나를 열어 용도를 알아보고, 설명을 읽는 것과 프로그램을 실행하는 것을 구분해 작은 결과를 만든다 |
| 5. 막힌 곳을 질문하기 | 스크린샷을 한 장씩 찍으며 어떤 도움을 받았나? | 하려던 일·실제로 보이는 결과·오류를 묶어 질문한다. 예제 오류 한 건을 해결하고 같은 행동으로 다시 확인한다 |
| 6. 하나씩 고치고 확인하기 | 기능을 고쳤는데 다른 곳이 깨지거나 실제 화면은 다르면? | 수정 전 상태를 남기고 한 가지를 바꾼 뒤, 원래 하려던 행동이 되는지 직접 확인한다 |

Claude Code를 켜는 법, Gemini 소개, Codex에서 폴더가 하는 역할 등은 실제 화면과 현재 공식 자료로 준비한다. 사용자가 말한 ‘jd 파일’은 어떤 확장자인지 아직 미확인이다. 해당 자료를 다룰 때 실제 파일명이나 사용자 확인으로 정하며 임의로 `.js`·`.json`이라고 확정하지 않는다. Codex 관련 ‘폴더’도 프로젝트 폴더인지 설정 폴더인지 구체적인 화면에서 구분한다.

## 난이도를 높이는 기준

| 단계 | 쌓을 능력 | 연결할 수 있는 실제 사건 |
|---|---|---|
| 초급 | 필요한 도구 열기, 요청하기, 파일 찾기, 실행·오류·결과 확인 | 첫 출석 앱, 설정에 헤맨 회고, 스크린샷 반복. 상세 화면·오류는 당시 자료가 없으면 현재 재현으로 만든다 |
| 중급 | 작은 기능을 나누기, 데이터의 흐름 이해, 수정 전후 비교, 기록과 복구, 필요한 외부 연결 | 7월 입력 방식 단순화, 8월 자체 앱 전환과 휴대폰 실행 문제, 9월 코드와 실제 시트 차이 |
| 고급 | 여러 기능·도구를 연결하며 비용·권한·운영 조건을 판단하고 실제 사용을 검증 | 이후 API·자동화·배포·개인화 사건. 용어를 앞당겨 소개하기보다 선수 개념과 재현 가능한 사례가 준비된 때 다룬다 |

초급·중급·고급은 월별 사건과 일대일로 대응하지 않는다. 9월의 복잡한 문제도 초보자가 이해할 기본기 한 가지로 풀 수 있다. 회차 소개에 필요한 사전 지식과 이어 볼 편을 연결한다.

### 1인 기업가의 일로 연결하기

기본기를 익히며 **내 일을 편하게 하기 → 누군가에게 필요한 것 만들기 → 실제 사용과 반응 확인하기 → 알리고 개선하며 운영하기**로 시야를 넓힌다. 아이디어와 작은 시제품, 고객의 불편, 콘텐츠와 마케팅, 반복 업무와 비용 같은 주제도 유호가 실제로 겪는 사건에서 꺼낸다. 필요한 고급 기술은 그 문제를 해결하는 과정에서 배운다. 시청자가 창업을 선택하기 전에도 자기 일에 적용할 수 있는 배움이 남게 한다.

이것은 채널이 다룰 성장 방향이다. 실제 고객 반응·판매·수익·운영 결과는 확보된 기록에 따라 이야기하고, 아직 시도하지 않은 일은 계획이나 예시로 구분한다.

## 1편에 바로 반영할 내용

이야기는 **6월 2일 번역용 Claude 첫 결제 → 학생 문의 증가 → 학생·학부모·동료 교사를 위한 출석 앱 구상 → 설정부터 헤맨 초보자의 첫 시도**다. 이 편의 작은 실습은 자신의 반복되는 불편을 하나 고르고, 누가 무엇을 할 수 있으면 좋겠는지 적어 AI에게 첫 단계를 물어보는 것이다.

출석 앱을 예로 든 현재의 요청 예시:

> 선생님이 학생의 출석을 기록하는 걸 만들고 싶어. 나는 개발을 처음 해. 가장 작은 첫 단계부터 설명해줘.

이 문장은 당시 채팅을 복원한 것이 아니다. 현재 시청자를 위해 쓴 예시다. 답을 읽고 **첫 작업이 무엇인지, 끝나면 무엇을 확인할지** 자기 말로 설명할 수 있으면 이번 단계의 결과다. 모르는 용어는 그 단계를 이해하는 데 필요한 만큼 다시 묻는다. 실제 제작까지 이어지는 회차에서는 가상 학생 자료와 검증된 실행 화면을 준비한다.

## 당시 이야기와 지금의 따라하기

과거에는 어떤 도구를 왜 골랐는지 이야기하고, 현재 따라하기 화면에는 촬영·확인 날짜와 환경을 붙인다. 과거 인터페이스나 요금·설정법을 오늘도 같다고 가정하지 않는다. 한 방법을 소개할 때 왜 그 방법을 쓰는지와 제대로 됐는지 보는 방법까지 보여준다. 다른 시점·운영체제의 차이는 시청자가 행동을 결정하는 데 필요한 범위로 설명한다.

현재 이 문서는 학습 구성안이다. 개별 도구의 설치·실행 안내를 검증한 상태가 아니다. 새 남성 음성과 영상도 아직 제작 전이다. 후속 회차를 준비할 때 필요한 당시 경험을 사용자에게 묻고, 현재 재현을 확인해 원고와 화면에 반영한다.
