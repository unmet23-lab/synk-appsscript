## 5. 무엇으로 이기나

> **화면의 주인공은 양식이 아니라 우리가 만든 작품들이다. 손님은 글을 읽기 전에 작품 여러 편으로 이 회사의 안목을 본다.**

1판은 유리결 한 편만 앞에 세웠다가 맹검에서 「그 제품 광고 페이지 같다」는 말을 들었다. 실제 제작사는 1초에 여러 작품을 보이고 사이트는 뒤로 물러난다. 그래서 쇼릴(자막 없는 구간을 이은 소리 없는 17.7초 · `media/works/build_reel.cjs`)을 만들어 세 방향 모두의 재료로 삼았다. 작품은 승인 원고대로 완성된 둘과 공모전 출품작이다. 대표작 유리결이 44%로 가장 길고, 코미디는 뒤쪽에 21%만 넣었다. 웃는 인물 컷은 「AI 스톡 얼굴」, 해안 도로 승합차는 「렌더 티」로 지적받아 뺐다.

**CSS 분리.** 첫 화면에서 옛 CSS 170KB를 안 읽게 `index.html`은 새 `film.css`만 싣는다. 옛 CSS(`app.css` · `casting.css` · `production.css` · `preview.css` · `slate*.css`)는 직원 화면과 프로젝트를 열 때 `app.mjs`가 한 번 불러 `film.css` 앞에 꽂은 뒤 그린다. 새 화면 클래스는 모두 `sx-` 접두어라 옛 규칙과 겹치지 않는다. 옛 탭에서는 `film-legacy.css`가 옛 토큰을 어두운 값으로 바꾸고 뼈대를 고친다.

**재그리기.** `render()`는 실시간 갱신마다 `main.innerHTML`을 다시 쓴다. 첫 화면은 다시 그리지 않고(`mountEntry`가 돌려준 핸들로 이어 쓰기 · 오류만 갱신), 영상 확인은 지금처럼 같은 영상 노드를 살리며(`#review-video`), 쓰던 의견은 `data-form` 초안 복원 경로를 그대로 쓴다. 창에 건 듣개는 `unmount`에서 뗀다.

**프레임 띠.** 실제 프로젝트에는 초별 그림이 없다. 넓은 화면에서만 숨은 영상을 순서대로 찾아가 캔버스에 그리고(같은 출처라 막히지 않음), 실패하면 선 하나 시간줄로 돌아간다. 휴대폰은 내려받기 부담 때문에 선만. 두 판의 길이가 같으면 작은 캔버스로 차이를 재서 달라진 곳을 표시하고, 못 재면 표시하지 않는다(말로 단정하지 않음). 판 바뀐 문장은 의견 수와 반영 수에서만 만든다.

**명조 글자.** 300 한 굵기 2,350자 한 파일(298KB)로 고정 글과 손님 글을 모두 그린다. SUIT · DM Mono는 있는 파일을 쓴다.

**새 파일 · 서버.** 화면 `film-home.mjs` · `film-review.mjs` · `film.css` · `film-legacy.css` · 글꼴 둘 · 그림(쇼릴 포스터 · 조각 · 끝 · 컷 12) · 영상(쇼릴 둘, mp4는 git 밖, 회사 후보로 옮김). `server.mjs` 공개 목록에 이것만 더하고 `sw.js` 판을 올린다. 지우는 파일은 없다. 서버 코드 변경이 공개 목록뿐이어도 회사 릴리스라 GPT 백엔드 검수를 받는다.

**움직임.** 시안과 같은 값. 움직임 줄이기면 쇼릴을 틀지 않고 첫 그림으로 두며 모든 전환을 없앤다. CSP(`style-src 'self'`) 안에서 style 속성 글자를 쓰지 않고 CSSOM만 쓴다.

**시험.** 뜻은 지키고 바뀐 마크업에 맞춰 고친다(`pulse-request-client` · `pulse-films-client` · `pulse-client-review-fixes` · `pulse-mobile-review` · `pulse-feedback-ui` · `pulse-demo` · `client-*-pulse` 등 51개 파일). 끝까지 눌러 보는 점검은 합성 프로젝트를 상태별로 띄운 실제 서버(CSP 포함)에서 1440 · 390으로 돌린다: 의뢰 → 접수 → 되묻기 답 → 모델 → 글 콘티 → 장면 이미지 → 의견 → 영상 의견 → 승인 → 납품 → 수령 확인.

**검수.** 이 설계 Fable → 구현 → 이름 가린 심사(사이트 평균과 나란히) → 아르곤 → Fable 최종 → 서버 쪽 GPT → 회사 사슬 52.

**설계 검토 반영(Fable 15건, P1 6건 모두 반영).** ① 영상 노드 보존이 실시간 갱신 때만이라 `render()`가 `#review-video`를 늘 살리게 바꿨다. ② 나란히 보기는 전역 재생 듣개와 싸우지 않게 `.compare-grid`로 묶고 동기화는 `wireCompare` 하나만 쓴다. ③ 의견 폼 세 개(`round-draft` · `round-submit` · `feedback`)의 이름 · 필드 · 체크를 그대로 두고 보이기만 바꿨다. 옛 판에서는 입력을 숨긴다. ④ 표에 없던 고객 화면을 더했다: 의뢰 흐름 손님의 제작 설계 · 규격표 · 준비 자료 · 바뀐 내용, 영상 없을 때의 문의 화면, 머리 막대 · 알림함 · 기기 기억. ⑤ 체험의 다른 자료 모양(`feedback` + 시간, 안내 띠)을 분기로 넣었다. ⑥ 옛 CSS는 화면마다 끄지 않고 프로젝트 · 직원 화면을 열 때 한 번 읽은 뒤 그린다(공통 뼈대는 `html.sx` 규칙이 늘 이긴다). 부분 글꼴은 2,350자 한 파일(298KB)로 줄여 `unicode-range` 위험을 없앴다.
