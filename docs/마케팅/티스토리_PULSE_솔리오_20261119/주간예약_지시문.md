# 주간 예약 작업 지시문 — PULSE · 솔리오 티스토리 다음 주 일곱 편씩

앱 예약 작업 `synk-tistory-pulse-solio-weekly`(매주 월요일 20:20)의 지시문 원문이다. 바꾸면 예약 작업도 같은 글로 고친다.

---

SYNK의 티스토리 블로그 둘(PULSE · 솔리오)에 다음 주 하루 한 편씩 나갈 글을 쓰고 예약 발행까지 건다. 한국어로 일하고 보고한다. 유호님 11-19 「웅 하루에 하나씩 올라가게 공개해도 돼」(결정 표 11-19 「티스토리 두 블로그 하루 한 편」 행)가 근거다.

**작업 자리:** 맨 먼저 `Get-Date`로 시각을 읽는다. `docs/_ops/예약작업_작업자리.md`의 「시작」대로 회차 워크트리(name `sched-synk-tistory-pulse-solio-weekly-<MMDD>-<HHmm>`)에서 일하고 origin을 따라간다. 공용 작업본에는 쓰지 않는다. 백그라운드로 띄운 명령은 같은 턴 안에서 끝을 기다린다.

1. `docs/마케팅/티스토리_PULSE_솔리오_20261119/README.md`의 「하루 한 편」 절을 처음부터 끝까지 읽고 따른다. 이 지시문과 어긋나면 README가 맞다.
2. **채울 날:** 블로그마다 이미 예약된 마지막 날을 찾는다. `일주일/` 폴더의 가장 최근 `<블로그>*.json`의 마지막 `날짜`와 관리 화면 글 목록의 「[예약]」 줄을 둘 다 보고 늦은 쪽을 쓴다. 그다음 날부터 7일을 채운다. 이미 채운 날은 다시 쓰지 않는다. 채울 날이 없으면 「채울 날 없음」 한 줄로 끝낸다.
3. **쓰기:** README 「하루 한 편」의 글 기준(사실만, 근거 경로, 가상 브랜드 밝힘, 값은 결정 표의 지금 값, AI 제작 도구 이름 안 씀, 검색 말은 제목과 첫 문단에, 앞 편들과 제목 · 첫 문단 · 틀이 겹치지 않게, 합니다체)대로 블로그마다 7편을 `일주일/<블로그>-<첫날 MMDD>.json`에 쓴다. PULSE 작품은 「다리가 기억하는 것」, 오팔린 「시스루」, 도담중공업 세 편만 소개하고 예로 든다(README 「하루 한 편」 글 기준, 유호님 11-25 · 11-26). 11-26에 비공개로 돌린 다섯 글은 다시 예약하지 않는다. 앞서 나간 편의 제목을 모두 읽고 같은 주제를 되풀이하지 않는다. 쓸 사실이 모자라면 편 수를 줄이고 빈 날을 보고에 적는다(지어서 채우지 않는다).
4. **검사:** 14편을 한 지시문으로 묶어 Fable 5.2(하위 에이전트, 모델 fable · 읽기만)와 카본(`node tools/lib/제미나이구독호출.js --model gemini-4-carbon --thinking high --timeout 1500000`)에 따로 보낸다. 지시문 꼴은 `검수/지시문.md`와 같다. 「막힘」은 고쳐서 그 검수자에게 한 번 더 보이고, 「고침」은 반영한다. 결과는 `검수/<첫날 MMDD>_fable.md` · `_카본.md`에 둔다. Fable 몫이 10% 아래면 운영 원칙 「한도」대로 지정 Opus로 넘긴다.
5. **예약:** README 「하루 한 편」의 Aside 절차(`C:/Users/q1212/aside/tistory-twoblogs-20261119/`의 `mcpd.cjs` · `send.cjs` · `gen-res.cjs` · `run-res.cjs`)로 건다. 세 스크립트는 회차 워크트리의 저장소 뿌리에서 실행하고 끝에 첫날 MMDD를 준다. 한 편을 먼저 `node <그 폴더>/gen-res.cjs pulse 0 dry <MMDD>`로 돌려 「채운 상태 … 맞음 true」와 「발행 전 … ok true」를 본 뒤 `node <그 폴더>/run-res.cjs pulse:0,solio:0,… <MMDD>`로 나머지를 건다. PULSE는 10:30, 솔리오는 13:30이다. 같은 Aside u0를 쓰는 다른 세션이 있으면 README의 번갈아 쓰기를 따른다. 티스토리 로그인이 풀려 비밀번호 칸이 뜨면 넣지 않고 멈춘 뒤 보고한다.
6. **확인:** 블로그마다 관리 화면 글 목록에서 새 「[예약]」 줄의 제목 · 날짜 · 시각이 원고와 같은지 읽는다. 다른 것은 그 글만 고친다.
7. **기록:** 원고 · 검수 파일과 README의 「예약 기록」 표 줄을 `node tools/바로올리기.js --모두 -m "…" --실행`으로 올린다.
8. **보고:** 블로그마다 예약한 날짜 · 제목 일곱 줄과 막힌 것만 짧게 쓴다.

지킬 것: 이미 공개된 글을 비공개로 돌리거나 지우지 않는다. 옛 글(PULSE 쪽 4편 · 솔리오 쪽 1편)은 그대로 둔다(유호님 11-19 「그대로 둬」). 다른 블로그(yuhobuilds 등)는 열지 않는다. 비밀번호 · 인증 코드는 넣지 않는다. 공개 저장소에 계정 메일이나 Aside 프로필 식별자를 적지 않는다.
