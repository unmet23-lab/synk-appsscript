# Tistory(yuhobuilds.tistory.com) 짧은 적용기 원고 — 42초 중 24초가 멈춰 있었다(2026-10-21 만듦 · 슬롯 10-22)

> 영상과 같은 실화를 「따라 재 보는 순서」로. 올리기는 유호님 「올려」 뒤(이 세션은 올리지 않음). 근거는 [기획](../기획.md) 「사실 대조」, 셈은 `tools/정지구간.js` 머리말. 첫머리에 유튜브 쇼츠를 넣는다(공개 뒤).

**제목:** 내 쇼츠, 몇 초가 멈춰 있을까 — 재는 법, 기준 둘, 고치는 셋

**본문**

42초짜리 쇼츠를 올리기 전에 마감 점검을 AI에게 맡겼습니다. 0.5초마다 화면이 얼마나 바뀌는지 재 보게 했더니, 화면이 거의 안 바뀐 시간이 24초(57%)였어요. 가장 길게 멈춘 곳은 6초. 만들 때는 몰랐습니다. 목소리가 계속 나오니까 화면도 움직이는 것처럼 느껴졌거든요.

## 재는 법

영상을 0.5초 칸으로 나누고, 칸마다 「앞 프레임과의 밝기 차이」를 평균 냅니다. 차이가 거의 없으면 그 0.5초는 화면이 멈춘 칸이에요. 그런 칸이 이어지는 구간과 그 합을 보면 됩니다.

영상 파일을 열 수 있는 AI(코딩 도구 같은 것)에게는 이렇게 보냈습니다.

```
이 영상을 0.5초 칸으로 나눠서 칸마다 앞 프레임과의 밝기 차이 평균을 재 줘. 차이가 거의 없는 칸이 이어지는 구간을 표로 보여 주고, 전체에서 그 시간이 몇 %인지, 1.5초 넘는 구간이 어디인지 알려 줘. 끝 화면은 따로 표시해 줘.
```

직접 재려면 ffmpeg 한 줄로 프레임 차이를 뽑을 수 있어요(영상을 270px 폭으로 줄여서 잽니다).

```
ffmpeg -i 내영상.mp4 -vf "scale=270:-1,tblend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=diff.txt" -an -f null -
```

diff.txt의 YAVG 값을 0.5초씩 평균 내서 0.15 아래면 「거의 멈춤」으로 봤습니다.

## 기준 둘

1. 화면이 거의 안 바뀐 시간은 전체의 15% 아래
2. 한 번에 1.5초 넘게 멈춘 곳은 없게(끝 화면은 빼고)

제 기준이라 다른 값을 써도 됩니다. 다만 한 번 정해 두면 「괜찮아 보이는데?」가 숫자로 바뀝니다.

## 고치는 셋

1. **멈춘 사진은 천천히 당긴다.** 사진 한 장을 보여 주는 장면도 카메라가 쉬지 않게.
2. **말하는 낱말마다 화면 한 곳이 바뀌게.** 「양」·「재료」·「색」을 말할 때마다 그 자리로 다가가는 식.
3. **장면 사이에 빈 화면을 남기지 않는다.** 다음 장면 글이 넘어가는 동안 이미 보이게.

말도 길이도 그대로 두고 화면만 이렇게 고쳤더니, 같은 셈으로 다시 쟀을 때 24초가 2초(5%)가 됐습니다.

하나 더 — 크롬 확장 같은 경로로 올리려고 용량을 줄인 판은 같은 영상이어도 멈춤이 조금 길게 잡혔어요. 압축이 작은 움직임을 지우기 때문이에요. 올릴 파일로 한 번 더 재 보세요.
