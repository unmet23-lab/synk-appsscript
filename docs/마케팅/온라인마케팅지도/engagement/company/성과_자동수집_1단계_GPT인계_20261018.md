유호님 10-18: 「설계안대로 1단계 진행해줘. 서버는 GPT에게 넘기고 화면은 네가 해.」 설계는 [성과_자동수집_설계_20261018.md](성과_자동수집_설계_20261018.md)(Fable 검수 반영). 이 문서는 **GPT가 맡는 서버·설정 일**과 Claude가 만든 화면이 기대는 **API 계약**이다. 화면은 10-18에 만들었고(아래 「Claude가 맡은 화면」), 아래 계약이 없어도 기존 API로 돌아간다 — S1이 없으면 사람이 게시 시각을 넣는 지금 방식 그대로다.

## 서버 할 일(GPT)

### S1. 게시 주소 확인 API(새)

`GET /api/post-performance/lookup?channelId=<id>&url=<게시 주소>` — 로그인 세션 필요, `canWriteChannel`(organization.mjs:10-19)이 참인 채널만.

응답(200):

```json
{
  "platform": "youtube | instagram | facebook | tiktok | threads | x | …",
  "externalId": "R3zPsNM6a2c",
  "url": "정규화한 주소(post-performance.mjs의 canonical)",
  "publishedAt": "2026-10-18T07:13:00.000Z 또는 null",
  "suggestedFormat": "youtube-shorts | youtube-video | instagram-reels | null",
  "title": "플랫폼 제목·캡션 첫 줄 또는 null",
  "ownerMatch": true,
  "existingEntryId": "이미 등록돼 있으면 그 id, 아니면 null",
  "checkpoints": { "24": { "dueAt": "…", "closesAt": "…", "missed": false }, "72": { "dueAt": "…", "closesAt": "…", "missed": false } },
  "reason": "ownerMatch가 false·null이거나 publishedAt이 null일 때 사람이 읽을 이유(해요체)"
}
```

- 유튜브: 채널 자격으로 Data API `videos.list?part=snippet,contentDetails&id=` → `snippet.publishedAt`·`snippet.title`. **`snippet.channelId === channel.externalId`일 때만 `ownerMatch: true`.** 형식 제안: 주소가 `/shorts/`이면 `youtube-shorts`, 아니면 길이로 제안(사람이 확인).
- 인스타: 연결 계정 미디어 목록(`fields=id,permalink,timestamp,media_product_type,caption`)에서 shortcode가 같은 항목. 있으면 `ownerMatch: true`, `media_product_type === 'REELS'`이면 `instagram-reels`.
- 손 입력 플랫폼(스레드·X 등)이나 자격이 없을 때: `ownerMatch: null`, `publishedAt: null`, `reason`에 이유. 스레드·X 등은 게시 시각 손 입력을 안내한다. 유튜브·인스타는 채널 연결·주소를 확인하고 다시 조회하도록 안내하며, S2가 플랫폼 소유·게시 시각을 확인해야 등록할 수 있다.
- 주소를 못 읽으면 400 + 해요체 메시지(기존 `post-performance.mjs:28-58` 규칙 그대로).
- **화면을 켜는 신호:** S1을 배포할 때 `GET /api/publication-workspace`의 `performance`(post-performance.mjs `list()`)에 `lookupAvailable: true`를 넣는다. 화면은 이 값이 참일 때만 「주소 확인」을 보이고 S1을 부른다. 없으면 지금처럼 사람이 게시 시각을 넣는다.
- 플랫폼에서 게시물을 못 찾으면 200 + `ownerMatch: false`(남의 것) 또는 `null`(확인 불가)과 `reason`으로 준다. 채널이 없거나 쓰기 권한이 없으면 **403** + 해요체 메시지 — 기존 `channelFor(user,id,'write')`(server.mjs:423)는 404를 던지니 이 경로에서는 403으로 바꿔 준다. 화면은 오류 메시지를 그대로 보여 주고 입력은 막지 않지만, 유튜브·인스타는 S2의 소유·게시 시각 확인 없이는 등록되지 않는다.

### S2. 등록 API 보강(`POST /api/post-performance`, server.mjs:1139-1150)

- 유튜브·인스타는 서버가 S1과 같은 확인을 다시 해서 **`ownerMatch !== true`면 거부**한다(화면 값을 믿지 않는다). 지금은 유튜브 주소에 채널 정보가 없어 남의 영상도 받는다(post-performance.mjs:146).
- 확인된 게시물은 **플랫폼 `publishedAt`으로 저장**한다(사람이 넣은 값과 5분 넘게 다르면 플랫폼 값을 쓰고 응답에 `publishedAtAdjusted: true`를 넣는다 — 화면은 이때 「게시 시각은 플랫폼에 나온 시각으로 맞췄어요.」를 덧붙인다. 지금은 수집 때 `PUBLISHED_AT_MISMATCH`로 거부되고 재시도도 없다, post-performance.mjs:283, 289-292).
- **게시 묶음 없이도 `publicationFormat`을 받는다**: 소유가 확인된 경우에 한해 `origin: 'external'`과 함께 저장. 지금은 형식에 묶음이 필요하다(server.mjs:1148, post-performance.mjs:144).
- 이미 등록된 주소면 지금처럼 같은 id를 돌려준다(중복 없음).

### S3. 72시간 비교(publication-learning.mjs)

- `formatFor()`(39-43)가 `origin: 'external'` 항목의 `publicationFormat`도 쓰게 한다. 나머지 표본 규칙(같은 채널·플랫폼·형식·출처·단위, 6시간 창, 지연 15분, 3편)은 그대로.

### S4. 관측 놓침 예방

- `dueAt`이 지났는데 그 뒤 `performanceRuntime.lastSuccessAt`(server.mjs:367, 389-391)이 없으면 운영 현황(자동화 상태)에 경고 항목을 낸다. 화면은 Claude가 붙인다 — 기존 자동화 상태 응답에 항목 하나(`code: 'post-performance-collector-stale'`, `since`, `affectedEntries`)로 주면 된다.
- 세 번 실패(5분·15분 뒤)면 `manual-required`로 넘기는 규칙(post-performance.mjs:246, 289-291)을 **`closesAt`까지 간격을 두고 다시 시도**하는 쪽으로 바꾸는 안을 검토한다(35분 넘는 장애에서 6시간 창을 통째로 잃지 않게).

### S5. 유튜브 Analytics 실패 원인 가리기

- 「YouTube Analytics 공유 수치 일부 또는 전부를 받지 못했습니다」(collectors.mjs:289-293)는 호출을 시도했다 실패한 분기다. 서버 로그의 Analytics 응답 코드로 원인을 가린다: GCP 프로젝트의 YouTube Analytics API 미사용 / 권한이 빈 자격 / 채널 소유 불일치.

### S6. 운영 수집 스위치와 문서

- 운영의 `SYNK_COMPANY_WORKROOM_SCHEDULE_ENABLED`·`SYNK_COMPANY_BACKGROUND_JOBS_ENABLED` 값을 확인한다. 10-18 운영 화면에는 72시간 관측이 API로 자동 기록돼 있는데 WORKSPACE.md 「게시 후 기록」(632-636행)은 「운영은 자동 수집을 실행하지 않는다」고 적어 서로 다르다 → 실제에 맞춰 고친다.

### S7. 인스타 통계 권한 재연결 준비

- 통계 연결이 `instagram_business_manage_insights`를 묻는지 확인(oauth.mjs:7-24). @yuhobuilds는 댓글용 금고 토큰 재사용(10-14)·발행 연결(10-15)이라 통계 권한 기록이 없다.
- 유호님이 다시 연결한 뒤 기존 자동 갱신(oauth.mjs:274-283, 만료 7일 전)이 운영에서 예약 호출되는지 본다. 10-14 금고 토큰은 갱신 대상이 아니다.
