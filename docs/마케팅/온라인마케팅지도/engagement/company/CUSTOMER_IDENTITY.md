# 고객 상담 로그인 유지

2026-10-09 구현. 실제 공개 반영과 인수 상태는 [운영 기록](CLOUD-OPERATIONS.md)과 `.tmp/customer-session-restart-20261009/`의 검증 결과에서 구분한다.

고객 상담은 별도 OAuth 클라이언트와 기존 중앙 `platform` 계약을 사용한다. 고객 세션은 직원 `users`·`tokens`·SYNK 연결과 분리하며 쿠키 경로는 `/api/customer`다. 고객 쿠키로 회사·메신저 권한을 얻을 수 없다.

`customer_identity_sessions(session_hash, expires_at, ciphertext)`에 쿠키 해시·절대 만료와 암호화 자격 정보를 저장한다. 원래 `encryption.key`의 AES-256-GCM을 사용하며 쿠키 원문은 저장하지 않는다. CSRF·access·refresh·검증 대기 access·사용자·생성/만료 시각은 암호문 안에 저장하고 세션 해시·회사 origin·인증 설정과 묶는다. DB와 원래 키를 함께 백업한다.

재시작 후 같은 쿠키·CSRF를 사용할 수 있지만 모든 고객 API 요청은 중앙 계정·현재 세션·클라이언트·제품을 다시 확인한다. 저장된 과거 인증 성공은 권한으로 복원하지 않는다. 최초 로그인부터 8시간인 만료는 갱신·재시작으로 연장하지 않는다. 중앙 장애에서는 상담 자료·변경·유료 호출을 차단하면서 암호화 자격 정보는 보존한다. 중앙 복구 후 같은 세션으로 이어진다. 중앙 철회·계정 비활성·잘못된 바인딩·만료·로그아웃은 세션을 폐기한다.

갱신된 refresh는 access 형식 검사나 중앙 확인 전에 즉시 저장한다. 검증 대기 access도 저장해 중앙의 일시 장애 뒤 다시 확인한다. 정상 종료는 진행 중 갱신을 기다리며 새 로그인·권한 행사를 차단한다. 이미 시작한 HTTP 로그아웃이 끝난 뒤 메모리와 DB를 닫는다. 값이 바뀌지 않은 중앙 확인은 SQLite 암호문을 불필요하게 다시 쓰지 않는다. 원격 제공자의 토큰 회전과 로컬 저장 사이에 갑작스러운 전원 종료가 일어나는 경우까지 보장하지는 않는다.

이전 버전의 고객 세션은 메모리에만 있으므로 최초 업그레이드 직후에는 한 번 정상 로그인해야 한다. 이후 정상 재시작부터 유지된다. 저장한 상담·사용량·직원 기록·기기 등록 상태는 변경하지 않는다. 유료 AI를 활성화하는 변경은 포함하지 않는다.

검사는 `customer-identity.test.mjs`의 암호화·복원·철회·만료·경합과 `server-customer.test.mjs`의 실제 HTTP 재시작·초안·권한·한도·종료 처리를 사용한다. 합성 인증 시험, 실제 클라우드 이미지 시험, 실제 계정 브라우저 인수는 각각 별도 근거로 기록한다. 실물 휴대폰·PC 종료 시험은 사용자 보류다.
