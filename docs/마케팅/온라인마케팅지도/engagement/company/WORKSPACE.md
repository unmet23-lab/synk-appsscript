# SYNK Workspace · 싱크 워크스페이스

회사 업무·대화와 교사의 담당 반 관리를 SYNK Workspace(싱크 워크스페이스)에서 함께 사용합니다. 공용 주소는 [workspace.synk.im](https://workspace.synk.im/)이며 기존 메신저 바로가기도 이 주소를 엽니다. 교사와 회사 직원 권한은 각각 서버에서 확인합니다. PC의 기존 로컬 데이터는 이전 원본으로 보존합니다.

Google Cloud 서버 배포·데이터 이전·직원과 고객의 실제 SYNK ID 로그인·저장 복원은 확인했습니다. 고객용 `/consultation/`은 회사 직원 권한과 분리되어 있습니다. 현재 릴리스와 검증 근거는 [CLOUD-OPERATIONS.md](CLOUD-OPERATIONS.md)를 따릅니다. PC를 끈 실물 휴대폰 시험은 사용자 요청으로 후속 보류 상태입니다.

예전 `127.0.0.1:4191` 주소가 열리지 않으면 공용 주소 또는 위 바로가기로 접속하세요. 공용 서버 연결 문제의 확인 위치는 [운영 기록](CLOUD-OPERATIONS.md)입니다. 현재 사용 입구를 복구하려고 이전용 로컬 서버를 다시 시작하지 않습니다. 로그인 시작 링크는 로그에 저장하지 않습니다.

## 사용하는 순서

### 담당 반과 학생 케어

**내 수업 → 담당 반 → 학생 선택 → 학습 근거·활동·케어**로 이어집니다. 교사당 기본 2반, 반당 16명을 기준으로 실제 담당 명부 전체를 표시하며 정원을 넘는 학생을 잘라 숨기지 않습니다.

- WORLD의 공유된 학습 근거·배정 과제·결과와 학생별 케어 담당·기한·상태를 확인합니다. 미연결·미공유·기록 없음·연결 실패를 구분하며 근거가 없다는 이유로 부족하다고 판정하지 않습니다.
- 반별 공식 TOWN 소속과 서버가 수락한 활동을 같은 학생 계정으로 연결합니다. 이동·접속을 학습 성취로 집계하지 않으며 개인 대화는 교사 요약에 보내지 않습니다.
- 개인 학습 저장, 반에 학습 공유, TOWN 활동 공유는 각각 학생이 선택합니다. 동의를 자동으로 켜지 않으며 철회 뒤 이전 활동을 다시 노출하지 않습니다.
- 미연결 학생은 교사가 발급한 일회용 코드를 WORLD에서 미리 확인한 뒤 본인 계정에 연결합니다. 반·학생·교사 권한은 서버가 검증합니다.

교사 전용 계정은 [내 수업](https://workspace.synk.im/?tab=teaching)만 이용할 수 있습니다. 회사 직원 기능으로 권한을 확장하지 않습니다. 기존 teacher·messenger 제품 식별자와 인증 저장소는 호환을 위해 유지합니다.

공통 API·DB·공개 화면과 PC 세 앱의 적용·설치 검증은 [운영 인수 기록](../../../../_ops/qa/workspace-connect-20261009/README.md), 소스 검수·빌드 보존과 종료는 [마감 기록](../../../../_ops/qa/workspace-connect-close-20261010/README.md)에 있습니다. 실제 교사·학생의 본인 계정 연결·동의·활동 왕복은 별도 인수로 남았습니다. 16명 실시간 동시접속과 라이브 수업·공개방송 송출은 아직 이 통합의 완료 범위가 아닙니다.



1. 바탕화면 실행기로 열거나 회사 계정으로 로그인합니다. 명시적으로 연결한 기존 메신저 계정은 기존 아이디·비밀번호도 사용할 수 있습니다. 회사 비밀번호를 새로 설정하면 회사 이메일·새 비밀번호로 로그인합니다.
2. 기본 첫 화면은 **홈**입니다. 필요한 일을 입력하거나 주요 메뉴의 **내 작업실 · 회사 안내 · 마케팅 · 메신저**를 누릅니다. 주요 메뉴는 PC 왼쪽, 모바일 하단에 한 번만 표시합니다. 마케팅 안에서 **내 현황 / 팀 현황 / 전체 현황 / 콘텐츠 기획 / 채널·수집**을 전환합니다. 메신저 안에서 다시 로그인할 필요가 없습니다.
3. 업무 화면의 **대화로 공유**는 화면 제목과 링크를 채팅 초안에 넣습니다. 받는 대화를 선택하고 직접 전송합니다. 링크를 받더라도 원래 업무 자료의 열람 권한이 있어야 내용을 볼 수 있습니다.
4. 크루 초대·팀·역할·이용 중지는 **팀·크루**에서 관리합니다. 별도의 메신저 초대 코드는 통합 모드에서 발급하지 않습니다.

메뉴의 읽지 않은 메시지 수는 실제 대화 기록에서 가져옵니다. 메신저를 열었다가 다른 업무 화면으로 이동해도 입력 중인 초안과 대화 연결을 유지합니다. 로그아웃하면 화면과 연결을 정리합니다.

## 홈 · 2026-10-02

홈은 작은 마린 업무 도우미와 질문 입력창으로 구성합니다. 본문의 업무 공간 카드·이어서 하기·흰 세부 메뉴를 제거하고 **내 작업실 · 회사 안내 · 마케팅 · 메신저**는 공통 주요 메뉴 한 곳에만 표시합니다. 모바일 하단에도 같은 네 공간만 표시합니다. 홈 복귀는 왼쪽 위 **싱ㅋ 로고** 한 곳에 모았으며 기존 대화·초안을 유지합니다. 작업실·회사 안내·마케팅의 세부 기능은 해당 공간의 사이드바에서 선택하고 모바일에서는 상단 메뉴 버튼으로 엽니다. 메신저는 자체 대화 목록을 사용합니다. 질문 예시는 입력창에 내용을 넣으며 보내기 전에는 조회하지 않습니다. 계정·팀 관리·설정·로그아웃은 오른쪽 위 계정 버튼에 모았습니다. 명시적인 메신저 주소나 기획 공유 링크는 해당 화면으로 바로 연결됩니다.

“이번 주 내 조회수”, “크루 이름과 대화하고 싶어”, “기획서 파일 찾아줘”, “내 할 일 보여줘”처럼 입력하면 현재 권한으로 확인할 수 있는 자료와 바로가기를 답합니다. 크루를 누르면 개인 대화, 파일·할 일을 누르면 해당 원문, 콘텐츠 기획을 누르면 기존 기획함을 엽니다. 대화방·DM·팀 자료는 기존 열람 권한을 유지합니다. 홈을 오가도 메신저 초안과 마린 대화를 유지하며 마린 대화는 이 브라우저 탭의 계정별 세션에만 보관합니다. **대화 비우기**나 로그아웃으로 지울 수 있습니다.

현재 마린은 외부 모델 호출·추가 비용 없이 동작하는 **업무 조회와 화면 안내**입니다. 자유로운 생성형 AI 대화나 자동 실행은 연결하지 않았습니다. 질문만으로 메시지를 전송하거나 자료를 삭제하지 않으며, 범위가 불분명하거나 자료가 없으면 그 상태를 안내합니다. 수치는 기존 성장 집계와 같은 기준을 사용하고 미확인 값과 실제 0을 구분합니다.

## 메신저 업무 연결 · 2026-10-08

메신저의 **내 업무 → 오늘**에서 내가 답할 요청, 오늘·지난 마감, 내가 검토할 결과, 내가 기다리는 일을 모아 봅니다. 처리할 항목이 있는 구역과 고객 업무를 먼저 보여 주고 빈 구역은 아래에 짧게 표시합니다. 읽음·공지 확인·변경 목록 확인은 업무 완료와 별개입니다.

- **요청과 결과물:** 메시지의 **할 일로 만들기**에서 담당 크루·검토 크루·기한을 정합니다. 담당자가 수락 → 작업 → 결과물 메시지 선택 → 검토 요청으로 진행하고 검토자가 수정 요청 또는 완료를 선택합니다. 수정 의견은 원문 답글에 남길 수 있습니다. 결과물은 같은 방의 메시지를 검색해 고르며 첨부·공유 링크도 연결됩니다. 지정 검토가 있는 업무는 담당자가 임의로 완료하거나 검토자를 제거해 승인을 건너뛸 수 없습니다. 승인 이후 결과물을 바꾸려면 업무를 다시 시작해야 합니다. 동시에 바뀐 업무는 덮어쓰지 않고 최신 상태를 다시 확인합니다.
- **고객 의견:** PULSE 고객의 시안 의견·문의는 현재 담당자의 오늘 업무함에, 내부 검토는 지정 검토자에게 표시합니다. **고객 의견·시안 열기**에서 해당 프로젝트·버전·영상 장면으로 이동합니다. 수정본 연결 → 내부 검토 → 고객 확인 대기를 거치며, 실제 고객 승인과 미해결 수정 요청 해소를 확인해야 최종 납품 단계로 넘어갑니다. 내부 검토 통과는 고객 승인이 아니며 내부 메모는 고객 화면으로 내보내지 않습니다. 담당자 변경·이용 중지·접근 철회는 목록과 원문 양쪽에 적용합니다.
- **결정·최종본:** 원문 메시지의 **결정·최종본으로 기록**에서 확정 내용·적용일·결과물을 정합니다. 확정자·시각·원문을 함께 저장하고 현재 기록을 검색합니다. 이전 기록을 대체하면 이전·후속 기록으로 이동할 수 있습니다. 논의 중인 의견을 자동으로 확정하지 않습니다. 최종본 기록에는 결과물 메시지가 필수입니다.
- **바뀐 것:** 마지막으로 직접 확인한 이후의 새 요청, 담당·기한·진행 변경, 결정 변경을 실제 기록과 원문으로 보여 줍니다. 열기만 해서는 확인 위치가 바뀌지 않으며 **이 목록 확인했어요**로 표시된 묶음만 확인합니다. 일반 채팅 전체를 생성형 AI로 요약하지 않으며, 원문 접근이 사라지면 요약에서도 제외합니다.
- **마린:** 홈에서 **오늘 처리할 일**, **내가 기다리는 일**, **확정된 결정 찾아줘**, **최종 파일 어디 있어?**, **자리 비운 동안 바뀐 것**으로 같은 권한의 업무와 원문을 조회하고 해당 화면으로 이동합니다. 실제 기록을 구조화하며 추가 모델 호출·AI 비용·자동 전송은 없습니다.

고객 가치는 재입력·진행 재질문·최종본 찾기를 줄이는 데 있습니다. 기존 메시지·업무·고객 프로젝트·승인 자산을 재사용하며 별도 업무 앱이나 고객 데이터 사본을 만들지 않습니다. PULSE 제작과 내부 협업을 연결하되 고객 승인·납품의 의미와 접근 경계를 유지합니다. 실제 효과는 업무 전후 자료 찾는 시간, 진행 재질문 횟수, 놓친 요청 수로 확인해야 하며 아래 검증은 생산성 향상률의 증거가 아닙니다.

처음 검토자를 정하지 않은 업무는 담당자가 검토 요청 전에 지정할 수 있습니다. 검토 중·완료된 결과물 메시지는 원문에서도 바로 수정·삭제할 수 없으며 수정 요청이나 작업 재개가 먼저입니다. 현재 최종본으로 기록된 결과물은 새 최종본으로 대체한 뒤 수정·삭제할 수 있습니다.

## 업무 카드와 직접 팀 구성 · 2026-09-30

마린에게 **내 업무 카드** 또는 **팀 구성 살펴보기**를 요청합니다. 홈 오른쪽 위 계정 메뉴에서도 열 수 있고, 내 업무 카드는 **내 작업실**에서도 엽니다.

**내 업무 카드**에는 본인이 선택한 업무 분야·선호 업무·소통 방식·일하는 방식·주당 참여 가능 시간을 담습니다. 마린에게 명시적으로 말한 업무 정보는 확인할 초안으로 제안할 수 있으며, 확인하고 저장하기 전에는 카드에 쓰지 않습니다. 공란은 미확인, 0시간은 현재 여유가 없는 상태로 구분합니다. 성격 유형·심리 상태·사적인 대화나 접속 시간을 추정 자료로 사용하지 않습니다.

기본은 본인만 보관합니다. **업무 카드 공유 동의**를 직접 켜면 관리자와 현재 소속 팀의 팀장이 볼 수 있습니다. **공유 철회**는 카드를 개인 보관으로 바꾸고, **카드 삭제**는 저장한 업무 정보를 지웁니다. 관리자가 타인의 카드를 대신 수정할 수 없습니다. 두 창에서 수정하면 오래된 내용으로 덮어쓰지 않고 현재 카드를 다시 확인하도록 안내합니다.

**팀 구성 살펴보기**는 관리자가 회사 전체, 팀장이 자기 활성 팀의 업무 카드를 보고 크루를 직접 고르는 화면입니다. 미등록·미공유 상태는 구분해 추측하지 않고 업무 내용도 보여주지 않습니다. 필요한 역할과 한 사람당 주간 필요 시간을 정하고 **선택한 구성 확인**을 누르면 기재된 역할별 크루, 아직 확인되지 않은 역할, 가능 시간, 협업 방식의 차이를 대조합니다. 정보를 적지 않았다는 이유로 능력이 없다고 판정하지 않으며, 사람 점수나 순위를 만들지 않습니다. 실제 소속 변경은 기존 팀 관리에서 사용자가 직접 진행합니다.

공통 원본은 [`atlas/work.js`](../../../../../atlas/work.js)의 `atlas-work-1` 모듈입니다. 회사 앱은 이 원본을 직접 호출하며 저장·로그인·공유 동의·현재 조직 권한은 회사 서비스가 처리합니다. 별도 모델 비용이나 자동 선발을 추가하지 않았습니다. 기존 Atlas 학습 기록이나 다른 사업의 정보를 가져오지 않습니다. 본인이 확인한 정보와 선택한 구성의 조건 대조를 다른 업무 기능에서도 재사용할 수 있는 첫 적용입니다.

## 메뉴 통합 · 2026-09-29

왼쪽 공통 메뉴는 기본으로 접혀 있으며, 마케팅·메신저로 이동할 때 자동으로 접혀 본문을 넓게 보여 줍니다. 가장자리 **›** 버튼으로 메뉴를 열고 **‹**로 다시 접습니다. 메뉴를 수동으로 펼친 뒤 같은 화면의 수치가 갱신될 때는 펼침 상태를 유지합니다. 휴대폰에서는 상단의 열기 버튼으로 메뉴를 띄우고, 메뉴 선택·바깥 영역·Escape로 닫을 수 있습니다. 메신저 안의 대화 목록은 별도로 유지합니다.

- **마케팅**: **내 현황 / 팀 현황 / 전체 현황 / 콘텐츠 기획 / 채널·수집**으로 구분합니다. 내 현황은 내 담당 채널, 팀 현황은 선택한 활성 팀, 전체 현황은 현재 권한으로 열람 가능한 모든 채널을 집계합니다. 각 현황의 **이번 주 비교 / 전체 추이 / 상세 분석**에서 같은 범위의 지표·추이·일별 기록·콘텐츠를 봅니다. 관리자는 팀을 선택할 수 있으며 팀이 없으면 설정 안내를 표시합니다. 메신저를 다녀오면 마지막 마케팅 화면과 선택 팀으로 돌아옵니다. 새로고침·공유 링크에도 현황 범위와 팀을 유지합니다. **채널·수집**에서 채널 등록·연결·담당자·수집·재시도 상태·기록을 함께 확인합니다. 기존 화면 주소와 공유 링크도 유지합니다.
- **성장과 상세 비교**: 내·팀·전체 현황의 첫 화면은 이번 주·지난주 누적과 전주 대비 성장 곡선으로 정리하며, 전월 비교를 별도 카드로 표시합니다. **상세 분석**에서 팀·담당자·채널·플랫폼·콘텐츠의 비교 막대와 선택 기간 분석을 봅니다. 막대를 누르면 해당 상세로 이동합니다. 기존 열람 권한을 유지하며 팀 미배정 채널도 전체 집계에 포함합니다. 감소값·확인된 0·미확인 값은 구분해서 표시합니다.
- **콘텐츠 기획**: 기본 화면은 **기획함 / 좋은 콘텐츠**이며 새 기획은 상단 버튼 하나로 시작합니다. 작성 내용이 있으면 **작성 중**, 저장된 기획을 열면 **기획안** 탭으로 복귀합니다. 새 기획의 상세 조건은 필요할 때 펼칩니다. 좋은 콘텐츠에서 팀 예시·벤치마크·개인 참고를 모읍니다. 기존 제작 스튜디오 주소는 좋은 콘텐츠로 연결되며 제작 상황판·소재함·검토실 진입은 메뉴에서 제외합니다. 저장 자료와 기존 예시의 재생 파일은 보존합니다.
- **메신저**: 상단 **개인채팅 / 팀채팅 / 전체채팅** 탭에서 종류를 고르고 해당 대화 목록만 봅니다. 개인채팅에는 나에게·1:1 대화, 팀채팅에는 소속 팀 전용방을 모읍니다. 전체채팅은 **공지 / 정보방 / 수다방** 순서로 표시하고 기존 공개 프로젝트·추가 대화방도 유지합니다. 공지는 회사 일정·결정·필수 안내, 정보방은 업무 자료·링크·사례, 수다방은 자유로운 소통을 위한 공간입니다. 분류별로 안 읽은 메시지와 마지막 대화를 기억합니다. 크루 목록에서 전체·내 팀·특정 팀을 골라 보거나 이름을 검색하고, 이름을 누르면 개인채팅으로 이동해 바로 1:1 대화를 엽니다. 원문에 연결한 답글, 중요 메시지 고정, 안 읽은 대화, 파일 검색과 형식 필터도 유지합니다.
- **공지 작성 권한**: 공지방의 글·답글·첨부·수정·고정은 회사 관리자(독립 메신저에서는 소유자)만 할 수 있습니다. 일반 크루는 읽기·반응을 사용할 수 있고, 조회 전용 계정은 기존처럼 읽기만 가능합니다. 정보방과 수다방은 작성 가능한 크루 모두가 이용합니다. 기본 세 방은 이름·용도가 고정됩니다. 기존 기본 공지사항과 팀 라운지는 같은 방 ID와 기록을 유지해 공지·수다방으로 연결하며, 사용자가 별도로 만들거나 수정한 방은 보존합니다.
- **팀 대화 권한**: 새 팀 전용방은 회사에 등록된 활성 팀의 실제 소속원만 사용합니다. 다른 팀 관리자에게도 자동 공개되지 않으며, 팀 이동·이용 중지 시 접근을 철회합니다. 기존 공용방에 붙인 팀·프로젝트 분류는 계속 공용입니다. 1:1 대화와 개인 메모는 해당 참여자만 접근합니다.
- **관리**: 팀·크루 및 설정은 별도 하단 관리 영역으로 옮깁니다. 휴대폰에서는 상단 관리 버튼으로 엽니다. 기존 역할별 접근 권한을 유지합니다.

처음에는 실제 등록한 크루와 팀만 보입니다. 관리자는 **팀·크루 → 새 팀 → 내 팀 설정**으로 자신의 소속을 정할 수 있습니다. 크루 초대 시 팀을 지정하면 디렉토리와 팀 메신저에 반영됩니다. 팀 미배정 상태에서도 전체 대화와 개인 메모를 사용할 수 있습니다.

## 프로젝트에 크루 초대하기 · 2026-09-30

프로젝트방의 대화 탭 아래에서 **참여 크루 N명**을 눌러 명단을 봅니다. 선택한 크루만 참여하는 방은 같은 줄의 **크루 초대 → 이름·팀 검색 → 크루 선택 → 선택 N명 초대**로 추가합니다. 추가된 크루는 그 방의 이전 대화와 파일도 볼 수 있습니다. 초대는 방을 만든 크루 또는 방에 참여 중인 관리자가 할 수 있습니다.

새 프로젝트를 만들 때 **함께할 크루**를 고릅니다. 기본값은 **선택한 크루만 참여**이고 본인은 자동 포함됩니다. 혼자 만든 다음 크루를 추가해도 됩니다. 회사에 아직 등록되지 않은 사람은 초대 화면의 **팀·크루 관리**에서 먼저 회사 크루로 등록합니다. 현재 등록된 사람이 본인뿐이면 이 안내를 바로 표시합니다.

기존에 만든 프로젝트방은 **전체 크루 참여 중**으로 표시하며 모든 활성 크루가 자동 참여합니다. 개별 초대가 필요하지 않습니다. 기존 대화의 공개 범위를 자동으로 바꾸지는 않습니다. 특정 크루와 대화하려면 명단 화면의 **선택한 크루와 새 프로젝트 시작**을 이용합니다. 새 방도 **전체 크루가 참여하는 공개 프로젝트**를 명시적으로 선택하면 전원 참여형으로 만들 수 있습니다.

선택 참여형 방은 초대되지 않은 크루나 관리자에게 노출되지 않습니다. 이용 중지된 크루의 접근은 철회하며, 다시 활성화돼도 재초대가 필요합니다. 기존 기획 검토 카드의 원문을 볼 수 없는 크루가 포함되면 초대를 완료하지 않고 안내합니다.

프로젝트방의 참여 안내 줄에서 **대화방 설정 → 대화방 삭제**를 누릅니다. 삭제 확인창에서 방 이름과 적용 범위를 확인한 뒤 삭제하면 모든 참여자의 대화 목록에서 사라집니다. 이름·설명 수정도 같은 설정에서 할 수 있습니다. 버튼은 PC와 휴대폰에서 모두 보입니다.

삭제는 방을 만든 크루 또는 그 방에 참여 중인 관리자가 할 수 있습니다. 공지·정보방·수다방, 소속 팀방, 개인 대화는 이 기능의 대상이 아닙니다. 기존에 만든 공개 프로젝트도 삭제할 수 있습니다.

잘못 삭제했다면 **전체채팅 → 삭제된 대화방 → 복원**을 누릅니다. 복원 권한이 있는 방만 목록에 표시합니다. 삭제 중에는 대화·첨부·검색·알림·할 일·저장함에서 해당 방에 접근할 수 없습니다. 대화와 파일 자체는 보존하므로 복원하면 다시 이어 쓸 수 있으며, Drive 파일을 즉시 휴지통으로 옮기거나 영구 삭제하지 않습니다. 삭제된 기간에 이용 중지된 크루는 선택 참여형 방에 자동 복귀하지 않습니다.

## 메신저 업무 기능 · 2026-09-30

대화방 상단의 **내 업무**에서 **알림 / 할 일 / 저장**을 한 패널로 확인합니다. 기본 대화 목록과 세 가지 채팅 분류는 그대로 유지합니다.

- **멘션·알림**: 입력창에서 `@`를 쓰고 참여 크루를 선택합니다. 개인 대화·나를 부른 멘션·답글·담당 할 일 변경을 알림함에서 확인하고 원문으로 이동합니다. 대화방의 종 버튼으로 **모든 메시지 / 나와 관련된 알림 / 끄기**를 선택합니다.
- **공지 확인**: 공지 작성 시 확인 여부를 요청할 수 있습니다. 크루가 직접 **확인했어요**를 누르면 확인한 크루와 아직 확인하지 않은 크루를 구분합니다. 대화를 열어 읽는 것과 공지 확인은 별개이며, 공지 내용이 수정되면 이전 확인을 초기화합니다.
- **메시지를 할 일로**: 메시지 메뉴에서 담당 크루·기한·할 일/진행 중/완료 상태를 지정합니다. 내 할 일·현재 대화·내가 볼 수 있는 전체 대화 범위와 상태로 걸러 볼 수 있습니다. 담당자는 해당 대화에 참여하며 작성 가능한 크루만 지정합니다.
- **콘텐츠 검토 요청**: 저장된 콘텐츠 기획에서 **검토 요청**을 눌러 받을 대화를 고릅니다. 제목·원문 링크가 카드 초안으로 들어가고 사용자가 직접 전송합니다. 카드의 **열기**는 그 기획으로 연결됩니다. 수신자 전원에게 기존 열람 권한이 있는 대화만 허용하며, 전송 직전에도 권한을 다시 확인합니다. 공유가 기획 권한을 새로 부여하지 않습니다.
- **상세 검색**: 작성 크루·기간·첨부 형식과 현재 대화 여부로 검색합니다. 검색어 없이 조건만 적용할 수도 있습니다. 날짜 범위는 한국 시간 기준이며 결과는 더 불러올 수 있습니다.
- **개인 저장·다시 알림**: 메시지를 내 저장함에 모으거나 다시 볼 시간을 정합니다. 저장한 메시지와 예약한 알림은 본인에게만 보이며 수정·취소할 수 있습니다. 알림은 앱 안의 알림함에 도착합니다. 업무 알림 실행이 다시 켜지면 지난 예약을 현재 권한으로 확인해 한 번 전달합니다. 기기 푸시는 아래 **이 기기의 알림 설정**에서 별도로 동의한 기기에만 적용됩니다.

팀 이동·이용 중지로 대화 권한을 잃으면 알림·할 일·검색·저장함에서도 해당 원문을 열 수 없습니다. 조회 전용 크루는 메시지 작성·할 일 변경은 할 수 없지만, 본인 알림 설정·읽음·저장·다시 알림·공지 확인은 사용할 수 있습니다. 좁은 화면에서 패널을 열면 뒤쪽 대화의 클릭·키보드 접근과 읽음 처리를 중단하며, 닫으면 복원합니다.

### 내 팀과 다른 팀의 추이 · 2026-09-30

**마케팅 → 팀 현황**에서 소속 팀을 기본으로 표시합니다. **추이를 볼 팀**에서 다른 팀을 고르고 **내 팀 보기**로 돌아올 수 있습니다. 팀 미배정 계정은 첫 활성 팀부터 보며, 등록된 팀이 없으면 팀·채널 배정 안내를 표시합니다.

- **조회수 / 좋아요 / 공유 / 댓글 / 저장 / 도달 / 팔로워·구독자**를 첫 화면에서 선택합니다.
- **비교할 팀**은 모든 팀, 선택한 팀만, 특정 팀 중 하나를 고릅니다. 선택 팀과 비교 팀은 같은 날짜·0 기준·눈금을 사용합니다.
- 기간은 **1주 / 1개월 / 3개월 / 전체** 또는 날짜 직접 선택입니다. 전체는 보존된 기록의 첫날부터 최근366일까지이며, 더 오래된 기록은 직접 날짜를 선택해 조회할 수 있습니다.
- **누적 / 하루 증감**을 전환하고 날짜 슬라이더나 ← → 키로 팀별 일별 수치를 확인합니다. 일별 수치 표도 펼칠 수 있습니다. 기간 증감은 시작 전날과 종료일의 같은 대상을 비교하며, 날짜별 누적값을 더하지 않습니다.
- 모든 활성 크루가 활성 팀의 **팀 단위 집계**를 볼 수 있습니다. 개별 채널·콘텐츠·담당자·파일·대화의 열람 권한은 그대로입니다. 팀 이름과 집계값 이외의 원문·식별자·연결 자격증명을 공유하지 않습니다.

미확인은 —, 확인한0은0으로 표시합니다. 점선은 이전 기록 유지, 빈 점은 일부 기록이며 수집하지 않은 구간을 연결하지 않습니다. 도달·팔로워는 게시물·계정별 보고값 합계로, 같은 사람의 중복을 제거한 수치가 아닙니다. 화면의 **DEMO** 표시는 실제 성과와 구분하며 기존 데모 파일을 수정하지 않습니다.

### 내 현황과 전체 현황의 주간 비교

**내 현황 / 전체 현황**의 첫 화면은 주간 성장에 집중합니다. 조회수·좋아요·팔로워 중 하나를 고르면 **이번 주 누적 / 지난주 누적 / 전주 대비 / 전월 동기 대비** 네 수치와 이번 주·지난주의 성장 곡선 하나가 함께 바뀝니다. 전월 비교는 독립된 보조 카드이며, 오늘 누적과 어제 대비는 작은 보조 정보로 유지합니다. 그 밖의 지표와 콘텐츠·운영 현황은 필요할 때 펼칩니다. 팀 현황은 아래의 팀별 추이 비교 화면을 사용합니다.

주간 비교는 **월요일 시작**입니다. 이번 주 월요일부터 오늘까지와 지난주 월요일부터 같은 요일까지를 나란히 봅니다. 예를 들어 수요일에는 양쪽 모두 월~수 3일입니다. 주 누적 조회수는 그 기간에 새로 늘어난 조회수이며, 날짜별 누적 스냅샷을 다시 더하지 않습니다. 팔로워는 주간 순증으로 표시합니다. 그래프도 같은 요일·같은 0 기준에서 비교합니다.

오늘 누적은 **오늘 실제 관측한 누적값**입니다. 과거의 마지막 기록을 오늘 값으로 대신 표시하지 않습니다. 어제 대비는 같은 대상의 어제·오늘 관측값 차이이며, 전월 동기 대비는 이번 달 1일부터 오늘까지의 증가와 지난달 같은 날짜까지의 증가를 비교합니다. 수집이 부족하거나 두 달의 일수가 맞지 않으면 비교율을 만들지 않고 이유를 표시합니다. 플랫폼이 제공하지 않는 수치는 0이 아닌 —입니다.

**전체 추이**를 누르면 첫 유효 기록부터 현재까지의 누적 그래프를 봅니다. 1주·1개월·3개월·전체 또는 직접 고른 기간으로 좁히고 일·주·월 단위로 확인합니다. 그래프에서 날짜를 선택하면 당시 누적값·변화·채널별 내역을 확인합니다. 주·월 누적은 기간 끝의 관측값이며, 매일의 누적 수치를 더하지 않습니다. 미수집과 이전 기록을 포함한 수치는 확인 상태를 따로 표시합니다. 증감은 선택 시작일의 기록 대비이며 일평균은 두 날짜 사이 일수로 나눕니다. 팀이나 현황 범위를 바꾸면 전체 기간으로 다시 시작합니다.

**상세 분석**에서 팀/크루/채널/게시글 비교·CSV·일별 기록을 이용할 수 있습니다. 첫 화면으로 돌아오면 이번 주 월요일~오늘 기준으로 복귀합니다. 다른 사람과의 순위 비교는 상세 분석에 두고, 기본 그래프는 선택한 나/팀/전체의 이전 주 기록과 비교합니다.

**날짜별 콘텐츠 TOP 3**: 상세 분석의 성장 추이와 전체 추이에서 날짜를 가리키면 콘텐츠 제목·크루 이름·해당 지표 수치를 표시합니다. 하루 증감은 전일과 당일의 비교 가능한 변화량, 누적은 그날 실제 확인한 수치로 순위를 정합니다. 키보드로 날짜를 선택해도 표시하며, 모바일은 한 번 눌러 순위, 같은 점을 다시 눌러 상세를 엽니다. 콘텐츠가 3개 미만이면 있는 만큼만 표시합니다. 팔로워·구독자는 계정 지표이므로 콘텐츠 순위를 만들지 않습니다. 실제 제작자 정보가 없는 자료는 관측 당시 담당 기록을 근거로 **당시 담당 크루**, 담당 기록도 없으면 **제작자 미등록**으로 표시합니다. 데모 제작 크루는 가상 데이터입니다.

## 그래프 확인용 임시 데이터 · 2026-09-30

데모에서도 왼쪽 **메신저**를 누를 수 있습니다. 누르면 그래프 데모를 나가 실제 로그인 계정의 메신저로 이동합니다. 가상 크루 신원·팀 선택은 전달하지 않으며 임시 그래프 자료는 보존됩니다. 메신저에서 **마케팅 → 그래프 데모 보기**로 다시 확인할 수 있습니다.

관리자는 상단 **그래프 데모 보기**로 임시 현황을 엽니다. [데모 내 현황](http://127.0.0.1:4191/?tab=overview&section=mine&demo=1)에서 상단 크루를 바꾸고 내 현황·팀 현황·전체 현황을 비교할 수 있습니다. 민지·준호·서연 3명, 그로스팀·콘텐츠팀 2팀, YouTube·Instagram·TikTok 6개 채널과 게시글 24개를 가정했습니다. 기준일은 2026-09-30이며 전월 동기 비교에 필요한 이전 관측과 시작 전 기준값도 별도로 준비합니다. 데모 안내는 작게 표시하고 자세한 조건은 **예시 정보**에 접어 둡니다.

실제 계정 생성·SNS 업로드·수집 없이 별도 `data/demo/marketing-demo.json`에서 읽습니다. 실제 관리자로 로그인한 경우만 볼 수 있고 데모 안에서는 수정·게시 기능을 막습니다. **실제 데이터로 돌아가기**로 기존 현황에 복귀합니다. 새로고침·서버 재시작 후에도 데모를 보관하며, **사용자의 삭제 요청 전에는 제거하지 않습니다.**

개발용 생성 명령은 `node docs/마케팅/온라인마케팅지도/engagement/company/demo-service.mjs --data-dir docs/마케팅/온라인마케팅지도/engagement/company/data/demo`입니다. 기존 파일이 있으면 덮어쓰지 않습니다. 향후 삭제 요청을 받으면 이 데모 파일만 별도로 처리하며 실제 회사·메신저 DB는 대상이 아닙니다.

## 계정과 자료 보존

- 회사의 크루 ID·활성 상태·역할이 공통 인증 기준입니다. 조회 전용 크루는 채팅도 읽기 전용입니다.
- 메신저의 기존 사용자·대화·첨부 ID는 변경하지 않습니다. 기존 크루와 메신저 계정은 명시적인 ID 연결로만 합칩니다. 이름이 같다는 이유로 계정을 합치지 않습니다.
- 관리자의 마케팅 관리 권한이 다른 사람의 DM·개인 메모 열람 권한으로 확장되지 않습니다. 제작 스튜디오의 비공개 소재·검토 권한도 유지합니다.
- 회사 DB와 메신저 DB는 각 기능의 저장소로 유지합니다. 인증과 화면은 통합하지만 기존 기록을 새 DB 형식으로 강제 변환하지 않습니다.
- 채팅 첨부는 기존 Google Drive 연결과 파일별 저장 계정을 유지합니다. 제작 스튜디오의 재생용 파일은 기존 로컬 저장소에 유지합니다. 기존 파일 자동 이관·자동 삭제는 하지 않습니다.

로컬 설정은 `data/workspace-integration.json`에 있으며 Git에서 제외됩니다. `messengerDataDir`는 기존 메신저 데이터 폴더의 절대 경로, `identityLinks`는 `{companyUserId,messengerUserId}` 목록입니다. 필요하면 `legacyMessengerPort:4197`로 이전 주소를 공통 프로그램으로 안내합니다. 테스트용 `dataDir`는 독립 메신저 저장소를 사용합니다.

## 실행 범위

### 기기 알림 준비 · 2026-10-08

메신저의 **알림 → 이 기기의 알림 설정**에서 브라우저별로 알림을 켜고 끕니다. HTTPS 서버에서 기기 알림을 활성화한 뒤 사용할 수 있습니다. 푸시는 자동 수집·Drive 삭제·예약 알림과 독립적으로 켤 수 있고, 해당 작업을 중지한 서버에서는 새로 발생한 직접 알림만 전달합니다. 페이지를 여는 것만으로 권한을 요청하거나 구독하지 않습니다.

아이폰·아이패드는 Safari에서 회사 주소를 열고 공유 메뉴의 **홈 화면에 추가**를 선택한 다음, 추가한 아이콘으로 다시 열어 로그인합니다(iOS·iPadOS 16.4 이상). 안드로이드는 Chrome에서 회사 주소를 열어 로그인하고 기기 알림을 켭니다. 홈 화면에 설치하면 다시 찾기 쉽습니다. 두 기기의 권한은 각각 허용해야 합니다. 권한이 차단됐으면 기기/브라우저 설정에서 변경합니다.

알림에는 고객 이름이나 대화 내용 대신 ‘확인할 새 업무가 있어요’가 표시됩니다. 누르면 알림함이 열리고, 원문을 직접 열어야 읽음 처리됩니다. 로그아웃하면 그 로그인에 연결된 기기 알림을 중단합니다. 다시 로그인한 뒤에는 기기 알림에서 재연결 여부를 확인합니다. 운영체제의 절전·집중 모드나 네트워크에 따라 도착이 늦어질 수 있으므로 앱의 알림함을 함께 확인합니다.

인수 예시는 **SYNK 홍보 영상 수정**입니다. 담당자는12초 장면 의견을 확인하고 수정본을 제출하며, 별도 검토자가 수정/승인한 뒤 고객 승인과 납품 확인을 이어갑니다. 현재 자동 검증은 합성 계정과 격리 DB의 결과입니다. 실제 아이폰·안드로이드에서는 화면을 닫은 뒤 새 알림 수신 → 알림 클릭 → 올바른 계정의 원문 → 명시적 읽음 → 로그아웃 후 추가 알림 차단을 확인해야 합니다. [검증과 공개 반영 상태](../../../../../tools/company-messenger/QA.md#기기-푸시-알림--2026-10-08)를 따릅니다.

실제 수신 시험에는 **다른 계정에서 보낸 새 직접 멘션**을 사용합니다. 자기 메시지·자기 멘션은 알림을 만들지 않습니다. 두 휴대폰에 같은 계정을 연결했다면 별도 발신 계정이 필요하고, 두 기기의 수신을 확인하기 전에는 어느 쪽에서도 원문을 읽지 않습니다. 등록 전에 있던 알림과 중지된 예약·마감 알림은 시험 대상으로 쓰지 않습니다.

현재 회사 공용 주소는 [workspace.synk.im](https://workspace.synk.im)입니다. 2026-10-08 공개 접속과 클라우드 서버 재부팅 후 복구를 확인했으며, 기기 푸시의 배포·실물 수신은 별도 검증 상태를 따릅니다. SNS 자동 수집은 별도 플랫폼 계정 연결이 필요한 기존 상태를 유지합니다. 화면 통합이 외부 서비스 연결·게시 완료를 의미하지 않습니다.

통합 검증 결과와 실제 적용 상태는 [WORKSPACE_QA.md](WORKSPACE_QA.md)에 기록합니다.
