# 계정 분류와 성과 수집

계정 확보, 브라우저 로그인, 통계 API 연결, 게시·예약은 서로 다른 상태다. 지도에서 같은 계정 ID로 합치며, 로그인 확인이 오래됐다는 이유로 로그아웃이라고 표시하지 않는다. 최신 로그인 관측이 72시간을 넘으면 당시 확인 기록으로 표시한다. 게시 시각이 지났다는 이유로 예약을 게시 성공으로 바꾸지 않는다.

- `docs/마케팅/계정_사업속성.json`: 주 사업(LAB·SHIFT·PULSE·PATH·SYNK), 보조 사업, 콘텐츠 트랙, 계정 목적, 분류 근거. 새 계정의 속성이 빠지면 지도 생성이 멈춘다.

- PATH는 기존 독립 SNS 계정을 만들지 않는 방침을 유지한다. LAB·회사 공통 계정의 유학·취업·정착 연결을 연계 계정으로 보여 준다. 이를 PATH 자체 계정이나 게시 실적으로 세지 않는다.
- 계정 행 89개: 관리 71, 개설 계획 15, 제외·보류 3. 별도 장기 개설 계획 16개는 실제 계정 수에 더하지 않는다. 공개 지도에는 로그인 경로·운영 관측·이메일을 싣지 않는다. 관리자의 `/api/social/simple`에서 운영 상태를 ID로 합친다.

## 숫자의 뜻

1. **최근 30일 게시물 누적 조회**: 지난 30일에 게시한 콘텐츠의 마지막 관측값 합이다. 그 기간에 발생한 조회와 다르다. 기존 「나라별 LAB 22개 · 18,562회」는 본 LAB 계정 4개를 뺀 나라 계정 하위 집합이었다. 2026-11-13 20:13 같은 계산으로 본 계정까지 더한 LAB 26개는 266,485회였다. 둘 모두 전체 기간 조회수로 부르면 안 된다.
2. **기간 증가량**: 시작 전날과 끝날에 모두 숫자가 있는 같은 게시물의 누적값 차이. 그 기간에 새로 게시한 글만 게시 전 0을 기준으로 쓴다. 오래된 글을 처음 관측한 값은 증가량으로 넣지 않는다.
3. **직전 같은 기간 대비**: 이번 증가량과 바로 앞 같은 길이 기간의 증가량을 비교한다. 세 경계일에 같은 대상·같은 담당 귀속으로 비교한다. 전체 비교율 `rate`와 일부 대상 비교율 `matchedRate`를 구분하고 일부만이면 N/M개 기준임을 표시한다. 이전 증가량 0, 기준 기록 없음, 음수 보정에는 퍼센트를 만들지 않는다.
4. **누적값**: 종료일까지 지표별 마지막 관측값을 한 번씩 더한다. 여러 날의 누적값을 다시 더하지 않는다. 빠진 지표는 0이 아니다. 오래된 관측, 전체 대상 중 관측한 비율을 함께 표시한다.
5. **도달·팔로워**: 게시물 또는 계정 보고값의 합이다. 서로 겹치는 사람을 제거한 전체 인원이 아니다. 콘텐츠별 도달 증가도 플랫폼의 기간별 고유 도달과 다르다.

수집 이전 날짜의 실적을 누적값으로 역산하지 않는다. 첫 확인 당시 저장된 일별 관측은 10월 18일부터였다. 30/60/90일과 그 이전 비교 기간이 부족하면 자료 부족으로 표시한다. 소유자 Analytics 등에서 실제 과거 기간 자료를 받았을 때만 그 출처와 기간을 구분해 넣는다.

공개 통계로만 연결한 YouTube는 기존 30일 API 보존 기준 때문에 60/90일 원시 관측 비교를 계속 쌓을 수 없다. 채널 소유자 인증과 재확인이 있는 기록과 구분한다. 화면에서 기간을 고를 수 있다고 모든 계정에 그 기간 데이터가 있는 것은 아니다. 90일 대 이전 90일에는 세 경계 관측과 최대 180일의 비교 범위가 필요하다.

## 하루 두 번 수집

회사 서버의 기존 수집 루프가 한국 시각 **09:00·21:00**에 전체 수집한다. PC를 켜 두거나 AI 세션을 깨울 필요가 없다. 기존 최근 게시물 수집 주기는 유지한다. 기존 운영 DB는 배포 후 관리자 설정에 `hoursKst:[9,21]`을 저장해야 켜진다. 화면에서 설정한 시각과 다음 실행 시각을 확인한다.

- 같은 시각의 성공을 중복 실행하지 않는다. 인증 실패는 재연결 전까지, 요청 제한은 다음 재시도 시각까지 기다린다. 둘째 회차가 제한을 우회하지 않는다.
- 공식 API의 페이지·요청 상한과 기존 수집 순서를 유지한다. 일부 실패는 마지막 성공 기록을 지우지 않는다.
- YouTube 공개 통계 리더는 명시한 채널에만 붙인다. 기존 조회가 진행 중이면 allowlist 변경을 미루며, 같은 연결을 다시 요청해도 진행 중인 인증 버전을 바꾸지 않는다.
- 지원하지 않는 플랫폼은 자동 수집 성공으로 표시하지 않는다. 브라우저·CAPTCHA를 무한 재시도하거나 비공개 API·유료 중개 서비스를 임의로 붙이지 않는다.
- 게시·예약 장부는 기존 30분 편 요약으로 최신 관측을 합친다. 최근 게시 근거 최대 60개와 예약 전체를 보내고, 서버 취소 상태를 우선한다. 과거 게시 근거를 생략한 수는 따로 밝힌다.
