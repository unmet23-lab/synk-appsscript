계정 확보, 브라우저 로그인, 통계 API 연결, 게시·예약은 서로 다른 상태다. 지도에서 같은 계정 ID로 합치며, 로그인 확인이 오래됐다는 이유로 로그아웃이라고 표시하지 않는다. 최신 로그인 관측이 72시간을 넘으면 당시 확인 기록으로 표시한다. 게시 시각이 지났다는 이유로 예약을 게시 성공으로 바꾸지 않는다.

## 현황판에서 모두 수집하기

‘모두 수집’을 누르면 현재 범위에서 수집 권한이 있는 계정의 요청을 등록한다. 계정이 연결되어 있으면 공식 API를 먼저 실행한다. 수집 PC는 남은 지표를 계정에 지정된 브라우저 화면이나 공식 파일에서 확인한다. 계정별 진행 상태에는 이번 요청에서 실제로 기록한 조회수, 좋아요, 공유와 출처가 표시된다. 플랫폼이 제공하는 다른 지표는 별도로 보존한다. 조회수 0도 실제로 확인한 값일 때만 기록한다.

PC가 꺼져 있으면 화면과 파일 확인이 대기한다. 수집 PC는 다시 실행되면 대기 중인 계정을 이어받는다. 이미 진행 중인 범위에서 버튼을 다시 눌러도 동일한 계정 요청이 중복되지 않는다.

## 보완 수집의 반복 작업 줄이기

YouTube API에서 조회수가 빠지면 PC가 해당 채널의 공개 정보창을 연다. 등록한 주소와 화면의 핸들, 채널 고유 번호를 대조한 뒤 정확한 정수로 보이는 채널 누적 조회수를 저장한다. 기간 비교에는 같은 기준으로 관측한 두 시점이 필요하다. API가 조회수를 이미 수집했다면 공유만 확인하려고 정보창을 다시 열지 않는다.

매일 한국 시각 09시 40분과 21시 40분에 공식 API를 먼저 확인한다. 필요한 지표를 API로 가져올 수 없으면 같은 회차에 계정 관리 화면이나 공식 내보내기를 읽는다. 러시아 LAB의 [RUTUBE 운영 수집기](../../../../../tools/계정통계예약/rutube-public.cjs)는 공개 일반 영상 목록을 확인한다. 목록이 비면 영상 수만 기록한다. X와 LinkedIn이 재게시로 표시한 숫자는 공유 합계에서 제외한다.

2026-11-15에 기존 Codex 예약 `synk-2`의 지시문을 갱신했다. 09:40와 21:40 KST 실행을 유지하며, 매 회차에 `tools/계정성과점검.js`로 현재 원장과 실제 수집 상태를 한 번 대조한다. 같은 회차에 성공한 지표는 출처와 기간 및 종류가 같을 때만 건너뛴다. 조회수가 있다는 이유로 부족한 좋아요나 공유를 생략하지 않는다. 누적 통계와 일별 기간 통계도 각각 확인한다.

공식 일별 내보내기는 처음에 비교에 필요한 최대 180일을 제공 범위 안에서 확보한다. 이후에는 최근 7개 완료일을 겹쳐 갱신한다. 플랫폼의 마지막 완료일이 같으면 같은 날 두 번째 장기 내보내기를 생략한다. 새 날짜나 정정 표시가 있거나 앞선 회차가 실패했으면 다시 확인한다. 매주 일요일의 첫 성공 회차에는 제공되는 최대 180일을 다시 대조한다. 기간을 선택할 수 없는 플랫폼은 원본 파일과 기간으로 중복을 확인한다. 누적 게시물 수치는 같더라도 새 회차의 관측으로 남겨 비교 기준일을 보존한다.

계정별 제한과 재개 조건은 비공개 `~/.synk/account-metrics/collection-policy.json`에 둔다. 막힌 API 연결만 중단하고 접근 가능한 기존 통계 화면과 공식 내보내기는 계속 이용한다. 사용자 제어로 넘어간 브라우저 공간은 확인 답을 받기 전 다시 조작하거나 다른 공간으로 우회하지 않는다. 앱 제한과 재인증을 현재 계정의 로그아웃으로 바꾸어 기록하지 않는다.

회차별 결과는 기존 `browser-runs` 폴더에 저장한다. 계정별 성공 지표, 실제 완료일, 전체 기간 대조일, 원본 해시, 건너뛴 이유, 남은 대상과 소요 시간을 남긴다. 수치가 없는 계정을 먼저 확인한 뒤 마지막 성공이 오래된 순서로 진행한다. 한 회차는 45분 안에 정리하며 미처 확인하지 못한 계정은 다음 대상으로 보존한다. 같은 프로필은 순서대로 사용한다. Windows 루틴이 이미 맡은 Telegram과 성공한 공식 파일 입력은 반복하지 않는다.

예약 도구의 갱신 성공과 저장된 지시문 및 재개 조건의 일치를 확인했다. 이 변경 뒤 첫 정시 실행은 아직 도래하지 않아 시간 절감률은 측정하지 않았다. 기존 Windows 수집의 실제 첫 실행은 약 5초였으며, 중복 실행 방지 설정과 종료 코드 0을 다시 확인했다.

## 숫자의 뜻

1. **최근 30일 게시물 누적 조회**: 지난 30일에 게시한 콘텐츠의 마지막 관측값 합이다. 그 기간에 발생한 조회와 다르다. 기존 「나라별 LAB 22개 · 18,562회」는 본 LAB 계정 4개를 뺀 나라 계정 하위 집합이었다. 2026-11-13 20:13 같은 계산으로 본 계정까지 더한 LAB 26개는 266,485회였다. 둘 모두 전체 기간 조회수로 부르면 안 된다.
2. **기간 증가량**: 시작 전날과 끝날에 모두 숫자가 있는 같은 게시물의 누적값 차이. 그 기간에 새로 게시한 글만 게시 전 0을 기준으로 쓴다. 오래된 글을 처음 관측한 값은 증가량으로 넣지 않는다.
3. **직전 같은 기간 대비**: 이번 증가량과 바로 앞 같은 길이 기간의 증가량을 비교한다. 세 경계일에 같은 대상·같은 담당 귀속으로 비교한다. 전체 비교율 `rate`와 일부 대상 비교율 `matchedRate`를 구분하고 일부만이면 N/M개 기준임을 표시한다. 이전 증가량 0, 기준 기록 없음, 음수 보정에는 퍼센트를 만들지 않는다.
4. **누적값**: 종료일까지 지표별 마지막 관측값을 한 번씩 더한다. 여러 날의 누적값을 다시 더하지 않는다. 빠진 지표는 0이 아니다. 오래된 관측, 전체 대상 중 관측한 비율을 함께 표시한다.
5. **도달·팔로워**: 게시물 또는 계정 보고값의 합이다. 서로 겹치는 사람을 제거한 전체 인원이 아니다. 콘텐츠별 도달 증가도 플랫폼의 기간별 고유 도달과 다르다.

수집 이전 날짜의 실적을 누적값으로 역산하지 않는다. 첫 확인 당시 저장된 일별 관측은 10월 18일부터였다. 30/60/90일과 그 이전 비교 기간이 부족하면 자료 부족으로 표시한다. 소유자 Analytics 등에서 실제 과거 기간 자료를 받았을 때만 그 출처와 기간을 구분해 넣는다.
