# 제작 스튜디오

2026-09-28에 구현한 회사 프로그램의 제작 기능이다. 현재 공개 운영·반영 범위는 [클라우드 운영 기록](CLOUD-OPERATIONS.md)에서 확인한다. 혼자 운영할 때는 자신이 제작 담당자가 되고, 직원이 합류하면 담당자·검토자·팀을 지정해 같은 흐름을 사용한다.

사용자가 좋다고 한 완성본 검토실, 좋은 콘텐츠 예시함, 경험·소재 보관함, 제작 상황판을 연결했다. 제작자의 경험·판단·실험을 남기는 기능이며 새 자동 제작 패키지를 추가하지 않았다. 기존 양식 기반 기획은 선택해서 연결할 수 있다.

## 사용하는 순서

1. **경험·소재 보관함:** 실제 경험, 받은 질문, 발견, 참고 자료를 제목과 짧은 메모로 남긴다. 출처·태그·공유 범위는 선택 입력이다. ‘이 소재로 기획’은 개인 기획 화면에 초안을 옮기며 자동 저장·공유하지 않는다.
2. **제작 상황판:** 작업 제목, 담당자, 다음 할 일, 막힌 점, 목표 날짜를 기록한다. 혼자 쓸 때는 자신을 담당자로 두면 된다. 기존 기획안의 ‘제작 상황판에 연결’로 제목과 기획 링크만 가져올 수도 있다.
3. **완성본 검토실:** 영상·이미지 파일, 글 원고, 외부 원문 링크를 버전별로 등록한다. 두 버전을 나란히 보고, 재미·도움·진정성·개인화 관점의 의견을 남긴다. 영상은 현재 시간을 의견에 붙이고 해당 의견을 눌러 그 장면으로 이동할 수 있다. 의견의 해결 표시와 버전별 이력은 보존된다.
4. **좋은 콘텐츠 예시함:** 작업이 ‘완성’ 또는 ‘게시 기록’일 때 관리자·담당 팀장이 선택한 한 버전과 좋은 이유·다음에 활용할 점을 회사 전체에 공유한다. 원래 검토 의견이나 다른 버전은 함께 공개하지 않는다.

준비·제작 중·검토 요청·완성·게시 기록·보관은 사람이 남기는 작업 상태다. SNS에 자동 게시하거나 실제 게시 여부를 인증하는 상태가 아니다. 품질은 실제 파일과 설명을 사람이 검토하며 자동 점수로 합격시키지 않는다.

## 공개 범위

| 자료 | 읽을 수 있는 사람 | 변경할 수 있는 사람 |
| --- | --- | --- |
| 팀 미지정 작업 | 작성자·지정 담당자·지정 검토자·관리자 | 작성자·담당자·관리자. 검토자는 의견 작성 |
| 팀 지정 작업 | 위 참여자 + 현재 해당 팀의 직원 | 위 편집자 + 현재 해당 팀장 |
| 개인 소재 | 작성자·관리자 | 작성자·관리자 |
| 팀 소재 | 작성자·관리자·현재 해당 팀 | 작성자·관리자·현재 해당 팀장 |
| 회사 소재 | 활성 회사 계정 모두 | 작성자·관리자 |
| 좋은 예시 | 활성 회사 계정 모두 | 관리자·권한 있는 팀장이 등록, 관리자·등록 팀장이 보관 |

조회 전용 계정은 읽기만 가능하다. 비활성 계정은 접근하지 못한다. 새 회사 공유에는 화면의 명시적인 공유 확인이 필요하다. 작업에 기획안을 연결해도 기존 개인 기획안의 공개 범위는 확대되지 않는다. 기획을 볼 수 없는 참여자에게는 연결 ID도 제공하지 않는다. 보관한 예시는 일반 예시함에서 제외되고, 원래 작업 권한이 없는 사람은 그 파일에 접근할 수 없다.

## 파일과 저장

- 파일 한 개는 최대 **100MiB**, MP4·WebM·PNG·JPEG만 지원한다. 회사 서버가 파일 형식의 기본 서명을 검사하고, 업로드 종료 후에도 현재 세션과 작업 권한을 재확인한다.
- 실제 데이터 폴더의 `studio-media/`에 임의 파일명으로 저장한다. 버전 원본을 덮어쓰지 않는다. 파일 자체의 정확한 재생 가능 여부는 브라우저에서 확인해야 한다.
- 재생 요청은 로그인·현재 작업 권한 또는 명시적으로 공유된 예시 권한을 검사한다. 영상 탐색을 위해 HTTP Range를 지원하고 응답을 공용 캐시에 저장하지 않는다.
- 외부 링크는 서버에서 수집하지 않고 원문을 새 탭에서 연다. 현재 화면에서는 소셜 사이트를 자동 재생·임베드하지 않는다.
- 회사 데이터만 백업할 때는 `backup.mjs`를 사용한다. SQLite 백업 시점의 제작 자료와 고객 프로젝트 시안·최종본·접수 원문에 연결된 불변 파일을 함께 복사하며, 진행 중 업로드는 제외한다. 복구할 때 `company.sqlite`, `encryption.key`, `studio-media/`를 함께 복원한다. 메신저까지 포함한 통합 워크스페이스 이전·복원은 `workspace-backup.mjs`를 사용한다.

## 구현과 확인

- `studio-service.mjs`: 작업·버전·의견·소재·예시와 현재 권한.
- `studio-media.mjs`: 업로드 크기·서명 검사, 파일 확정·실패 정리, 인증된 재생.
- `public/studio.js`: 공통 화면, 작업 등록, 기획 연결, 계정 전환 보호.
- `public/studio-board.js/css`: 상황판과 소재 보관함.
- `public/studio-review.js/css`: 파일 검토와 좋은 예시함.
- `studio.test.mjs`, `studio-state.test.mjs`, `backup.test.mjs`: 권한·자료 보존·지연 응답·백업 회귀 검사.
- `verify-studio-browser.mjs`: 임시 회사 DB에서 4개 기능과 계정별 동선.
- `verify-studio-media-browser.mjs`: 별도 임시 DB와 테스트 패턴 영상으로 실제 업로드·재생·시간 메모·Range 검증.

검증 파일의 `fixture`는 테스트 자료다. 실제 회사 자료나 승인된 좋은 콘텐츠를 뜻하지 않는다. 실제 작업·소재·예시는 사용자가 등록할 때부터 축적된다. 새 기능은 외부 AI API와 자동 SNS 발행을 호출하지 않는다.
