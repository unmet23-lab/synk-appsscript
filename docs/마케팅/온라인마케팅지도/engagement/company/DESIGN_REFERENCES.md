# 프런트 디자인 개편 — 2026-09-27

사용자가 지정한 Recent(recent.design)의 현재 Interface 목록과 상세 화면을 조사했다. 기존 개인 기록장과 실제 회사 데이터는 변경하지 않고 회사 프로그램의 프런트를 개편한다.

## 두 번째 개편 — 사용자 시각 피드백 반영

사용자가 기존 화면의 카드·테두리·설명 밀도를 지적하여 색상 변경을 넘어 레이아웃과 공통 스타일을 재작성했다.

- 홈페이지 `SYNK-website/compose-sites.mjs`의 한글 워드마크 SVG를 `public/wordmark.svg`로 분리했다. 첨부와 같은 4개 path이며 viewBox 560:328과 검정색을 유지한다. 홈페이지 원문은 수정하지 않았다.
- 떠 있는 사이드바·중복 영문 머리말·6개 개별 지표 카드를 없애고 고정 사이드바, 하나의 기간 도구모음, 구분선으로 나눈 6개 총합 영역으로 재구성했다.
- 대시보드는 합계 → 성장 추이/운영 현황 → 하나의 짙은 하이라이트 영역 → 플랫폼/콘텐츠 목록 순서다. 실제 관측값과 미수집 표시를 보존한다.
- 채널·수집·팀/직원은 목록·행 중심, 설정은 구분선과 폼 중심으로 바꿨다. 로그인·검색·모달·상세 서랍까지 같은 스타일을 적용했다.
- 이번에 Recent 현재 목록/설명에서 추가 확인한 사례: [Browser UI Concept](https://recent.design/i/c3ahryt-browser-ui-concept)의 고정 탐색과 문맥별 화면, [Pressure Monitor Interface](https://recent.design/i/ycdnfr7-pressure-monitor-interface)의 수치와 그래프 위계, [Fluid Event Blocks](https://recent.design/i/kyvq0kl-fluid-event-blocks)의 열 정렬과 타이포그래피. 새 사례의 이미지 화면은 CUA 브라우저 연결 오류로 직접 확인하지 못했으며 설명에서 확인한 원리만 참고했다. 아래 첫 개편에서 실제 화면을 확인한 3개 사례와 함께 적용했다.
- 검증: 기존 21개+하이라이트 8개 브라우저 항목 통과, 콘솔 오류 0. 실제 DB의 34개 채널을 보존했고 6개 메뉴, 320~1440px 화면, 로고 실제 로드/비율, 로그인·검색·연결 안내·담당 이력·상세 모달을 확인했다. 실적을 주입하지 않았다.

## 첫 개편에서 직접 확인한 레퍼런스

| 사례 | 사이트 표시 | 적용한 원리 |

상대 날짜는 조사 시 사이트에 표시된 값이다. 실제 제작일을 뜻한다고 단정하지 않는다. 참고 작품의 이미지나 코드를 제품에 복사하지 않고 정보 위계·선택 상태·동작 원리를 구현했다. Recent에 소개된 모든 기법을 한 화면에 넣는 대신 SNS 운영자가 합계와 해야 할 일을 빨리 파악하도록 선택했다.

## 구현

- 최근 누적을 큰 숫자로, 선택 기간 증감을 그 아래에 표시하는 6개 핵심 지표. 0과 미수집 `—`의 차이를 보존한다.
- 실제 일별 관측값으로만 그리는 작은 추이선. 누락일은 연결하지 않는다.
- 차트·플랫폼 요약과 수집 상태·할 일을 나란히 배치해 첫 화면의 읽기 순서를 정리한다.
- 그래프 날짜의 마우스·키보드 선택, 정확한 값 표시, 콘텐츠 상세로 이동. 방향키로 날짜 이동, Enter로 상세 열기.
- Ctrl/Cmd+K 빠른 검색. 허용된 채널·메뉴만 검색하며 팀·역할 권한은 서버의 기존 계약을 유지한다.
- 실제 SUIT·Inter Tight·DM Mono 폰트, 공통 간격·색·크기, 미세한 선택·입장 동작, 움직임 감소 설정 지원.
- 회사 계정·수집 API·원본 기록·공용 서버 배포 상태는 기존과 같다.

## 확인

`verify-browser.mjs`의 격리 데이터로 총합, 주·월·분기, 직원 초대·권한·인계, 빠른 검색과 차트 상세를 확인한다. 실제 4191 화면은 샘플 실적을 넣지 않고 별도로 확인한다. 캡처는 `verification/`에 보관하며 `fixture`는 실제 회사 실적이 아니다.

최종 결과: 자동 시험 114개와 브라우저 21개 검증 항목 통과. 실제 34개 채널 화면의 320·390·768·1024·1280·1440px 폭, 가로 넘침 없음, 콘솔 오류 0건을 확인했다. 상세 근거는 [검증 기록](검증_20260927.md)에 남겼다.

## 전체 워크스페이스의 Slack 참고 개편 · 2026-10-02

사용자의 요청에 따라 모든 업무 화면의 탐색 구조와 화면 밀도를 다시 정리했다. 이전 펠트 콜라주 구성은 이번 요청의 작업 중심 UI에 맞춰 축소했다. 승인 로고·서체·청금석 색과 작은 마린 원본은 유지한다.

- [A more focused, productive Slack](https://slack.design/articles/a-more-focused-productive-slack/): 고정된 주요 탐색과 현재 작업의 세부 메뉴, 선명한 검색 위치, PC·모바일을 함께 설계하는 원리를 참고했다.
- [A new visual language for Slack](https://slack.design/articles/a-new-visual-language-for-slack/): 업무 정보의 밀도와 읽기 위계를 유지하면서 표면·경계·조작을 일관되게 정리하는 접근을 참고했다.
- [Organize your sidebar with custom sections](https://slack.com/help/articles/360043207674-Organize-your-sidebar-with-custom-sections): 기능별 메뉴 묶음과 개인 업무 바로가기의 배치를 참고했다.

공통 상단 바·주요 공간 메뉴·세부 메뉴·본문의 역할을 통일했다. 모바일에는 고정 하단 탐색을 두고 세부 메뉴는 닫을 수 있는 메뉴로 제공한다. 대화 목록·작성창·검색·개인 보관함은 기존 기능과 권한을 사용하며, 크루 목록과 추가 메시지 작업은 필요한 때 펼친다. Slack의 이미지·로고·소스 코드를 복사하지 않았다. 사용 반응의 우열이나 실제 직원 사용성을 입증한 결과는 아니며, 구현과 화면 검증은 [현재 검증 기록](WORKSPACE_QA.md)의 2026-10-02 전체 개편 항목에서 확인한다.

## 전체 워크스페이스의 펠트 브랜드 강화 · 2026-10-02

사용자가 앞선 개편을 확인한 뒤 전체 디자인에 회사 브랜드킷의 펠트를 더 넣어 달라고 요청했다. 고정 탐색·화면 밀도는 유지하면서 만지는 부품과 큰 색 면에 실제 승인 펠트 사진을 적용했다. 기준은 [펠트 부품](../../../../디자인/펠트부품/README.md)의 재질·글자·가장자리·모바일 마감 점검표다.

- `docs/디자인/펠트부품/assets/ui/`의 코랄·연코랄 판, 칩, 체크·크림·코랄 배지를 주 행동·선택 상태·검토 체크에 재사용했다. 글자는 화면 글자로 얹어 선명도와 접근성을 유지한다.
- `docs/캐릭터/펠트패치_0815/LapisDeep.png`를 상단 바와 PC 주요 메뉴의 청금석 섬유 배경에 사용했다. 홈과 작업실의 안내 면에는 승인된 옅은 펠트 결을 국소적으로 넣었다.
- `docs/마케팅/맞춤도구/assets/`의 노트북·책·편지·돋보기·시간·크루 스티커와 기존 승인 마린을 주요 메뉴·제목·홈·대화 목록·개인 도구에 배치했다. 자산은 원본 색·비율·알파를 보존해 복사했다.
- 메시지·문서·차트·입력 본문은 흰 바탕으로 둔다. 실제 화면에서 작은 실땀 사진 선이 점선처럼 보여 일반 경계로 정리했다.

홈·작업실·회사 안내·마케팅·메신저와 로그인·공통 대화창에 같은 부품을 적용했다. 새 자산 생성·유료 호출 없이 기존 승인 파일을 사용했으며, 로컬 UI 적용과 실제 직원 사용·원격 팀 운영은 구분한다. 구현별 자산 출처는 메신저의 `public/assets/SOURCES.md`, 확인 범위는 [현재 검증 기록](WORKSPACE_QA.md)에 남긴다.
