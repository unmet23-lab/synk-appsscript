# PULSE 고객 문의 자동 안내 — 설계와 구현 (2026-10-19, Claude)

유호님 요청(10-19): 「고객에게 답변 시각을 약속한다기보다 우리 클로드 맥스 무료 크레딧 많이있는데 그걸로 자동으로 답변처리를 노트북이 꺼져있어도 24시간 양질의 답변을 하도록 하면 안될까?」 → 같은 세션에서 「여기서 진행」.

## 무엇을 하나

1. 고객이 PULSE 앱 05에서 문의(「문의 보내기」, `action:'support'`)를 남긴다.
2. 회사 서버(HA, 24시간)가 1.5초 뒤 한 번, 그 밖에는 15초마다 답하지 않은 문의를 찾는다.
3. 그 프로젝트에서 **고객에게 이미 보이는 사실**(고객용 프로젝트 보기 + 고객에게 공개된 스튜디오: 단계·합의한 전달일·고객이 지금 확인할 일·제작 범위와 수정 조건·시안 목록·납품 규격·수정 의견 정리·최근 대화 12개)과 문의를 Claude Opus 5.5에 보낸다. 내부 메모·연락처·내부 대화·일정 계획·접수 원문·파일 주소·내부 ID는 보내지 않는다.
4. Claude는 구조화 출력(JSON)으로 `decision`(answer/handoff)·`reply`·`handoffReason`을 돌려준다.
5. 서버가 답을 검사(길이 700자, 제어 문자, 내부 ID 모양, 사실에 없는 링크)한 뒤 같은 대화에 **「자동 안내」**로 남긴다(작성자 `staff` + `automated:true`, 이름 「자동 안내」, `replyTo`). 고객 알림은 새 종류 `auto_reply` — 「문의에 자동 안내가 왔어요」.
6. 문의는 **미해결로 남는다.** 담당자 할 일(「답하기 시작」·「답변 끝내기」)과 마감 전 확인(미답 문의는 마무리를 막음)은 그대로다. 담당자는 대화에서 자동 안내를 보고 덧붙이거나 끝낸다.

사람이 정할 일 — 가격·견적·추가 비용, 범위 변경, 전달일 변경, 환불·취소, 계약·약관, 불만·사과, 개인정보, 그 밖에 판단이 필요한 요청 — 은 약속하지 않고 `handoff`로 「담당자에게 전달했어요」와 지금 화면에서 확인할 수 있는 사실만 알린다(답에 「담당자」가 없으면 서버가 한 문장 붙인다).

## 안전장치

- **한 문의에 한 번:** 호출 전에 `pulseAutoReplies` 기록(프로젝트:문의 ID)을 트랜잭션으로 만든다. 기록이 있으면 다시 하지 않는다. 장애 전환 뒤 새 주 노드도 같은 기록(복제)을 본다.
- **결과 모르는 호출은 다시 보내지 않는다:** 5xx·429·시간 초과(90초)·연결 끊김은 `charged:'unknown'`으로 남기고 고정 안내로 끝낸다. 4xx는 처리 전 거절이라 청구 0으로 본다. 서버가 호출 중에 꺼져 `sending`이 10분 넘게 남으면 다시 보내지 않고 고정 안내로 끝낸다.
- **AI 없는 고정 안내:** 「문의 잘 받았어요. 담당자에게 바로 전달했고, 확인하는 대로 이 화면에서 답을 드릴게요.」 — 호출 실패·거절(`refusal`)·출력 이상·하루/한 달 한도·프로젝트당 하루 수 초과·크레딧 부족 때. 서버 쪽 거절 대체 모델(fallbacks)은 쓰지 않았다: 거절된 문의는 사람이 보는 편이 맞아서다.
- **크레딧 부족·키 거절**(`credit balance is too low` / 401·403): 키를 `credit-low`·`key-invalid`로 표시하고 이후 문의는 호출 없이 고정 안내. 관리자가 키를 다시 저장하면 풀린다. 설정 화면에 경고와 최근 처리 5건(결과·이유·금액)이 보인다.
- **켠 뒤의 문의만:** 켜는 순간(`enabledAt`) 이후에 들어온 문의만 답한다. 그 전에 쌓인 문의를 한꺼번에 답하지 않는다. 담당자가 이미 고객에게 답한 문의, 처리된 문의, 보관한 프로젝트는 부르지 않는다.
- **꺼져 있으면 아무 글도 남기지 않는다.**
- **문의 안의 지시는 따르지 않는다**(시스템 지시 7). 모델이 보는 것은 고객이 이미 볼 수 있는 사실뿐이라 새어 나갈 비밀이 없다.

## 비용과 한도

- 모델 `claude-opus-5-5`, 생각 깊이 `medium`(Opus 5.5는 생각을 끌 수 없고 생각 토큰이 출력 상한에 들어감), 출력 상한 12,000토큰, 시간 초과 90초. 공시 단가 입력 $4·출력 $20 / 100만 토큰. 사실과 문의는 서로 다른 블록으로 보낸다.
- 1건 추정 $0.02~0.05(시험 가정: 입력 3,000·출력 500토큰 = $0.022). 호출 전 예약값(입력 추정 + 출력 6,000토큰 ≈ $0.13)을 더해 한도를 넘으면 부르지 않는다. 실제 금액은 응답 사용량으로 적는다(상한 12,000까지 쓰면 예약보다 최대 $0.12 더 나올 수 있음).
- 기본 한도: 하루 $3 · 한 달 $30 · 프로젝트당 하루 10건(관리자가 설정 화면에서 바꿈; 하루 $0.1~50, 한 달 $1~500, 1~50건). 날짜는 한국 시간 기준.

## 키와 운영

- 키는 관리자가 워크스페이스 **설정 → PULSE 고객 문의 자동 안내**에 붙여 넣는다. 서버 DB의 암호화 저장소(`credentials`, Exa 검색 키와 같은 방식)에 두고 다시 보여 주지 않는다(끝 네 글자만).
- 회사 서버 설정 파일(`/etc/synk/company.env`)과 환경 변수는 바꾸지 않는다 → HA의 설정 해시 고정(`ENV_CHANGED`)과 복원 계약을 건드리지 않고 일반 회사 릴리스로 배포된다.
- 실행 스위치는 업무실 예약 작업과 같다(`SYNK_COMPANY_WORKROOM_SCHEDULE_ENABLED`, 없으면 배경 작업 스위치를 따름). 격리 복원 시험(배경 작업 0)에서는 돌지 않는다.
- 관리자 설정 화면에 상태(켜짐/꺼짐, 키 끝 네 글자, 오늘 자동 답·고정 안내 건수와 금액, 이번 달 금액/한도)와 최근 처리 5건이 보인다(`/api/settings/pulse-auto-reply`는 10건). 설정을 바꾸면 감사 기록(`audit`, 키 값 없이)을 남긴다.

## 유호님이 정할 것

1. **어느 Max 계정의 API 크레딧 키를 쓸지.** 「공자」 조직 키는 인스타 DM 자동 답, synk.yuh 조직 키는 talk 강사 도우미에 쓰고 있다(결정 10-19). 새 계정 키를 주시면 설정 화면에 넣고 1건 시험 뒤 켠다.
2. 한도 기본값(하루 $3·한 달 $30·프로젝트당 하루 10건)이 괜찮은지.

## 파일

- `pulse-auto-reply.mjs`(새) — 서비스·지시문·사실 고르기·검사·한도·기록.
- `client-projects.mjs` — `customerSnapshot`(서버 안 전용 고객 보기), `postAutoReply`(문의 하나에 자동 안내 한 개).
- `pulse-studio.mjs` — `customerSnapshot`(고객에게 공개된 스튜디오 포함).
- `client-notifications.mjs`·`pulse-live.mjs` — 알림 종류 `auto_reply`와 본문.
- `public/pulse-app/views.mjs` — 소식 줄 「자동 안내」, 기록 「자동 안내 · 문의 답변」.
- `server.mjs` — 서비스 연결, 15초 주기·문의 직후 1.5초 깨우기, 종료, 관리자 경로 `GET/POST /api/settings/pulse-auto-reply`, 관리자 상태의 `pulseAutoReply`.
- `public/app.js` — 설정 화면 「PULSE 고객 문의 자동 안내」 칸.
- 고객 앱 `public/pulse-app/app.mjs` — 저장 충돌(409) 안내를 원인에 중립으로(「그사이 새 소식이 생겼어요(답이 도착했거나 담당자가 내용을 바꿨어요)…」). 자동 안내가 바로 붙으면 이어서 쓰던 고객이 이 안내를 볼 수 있다(쓰던 글은 그대로).
- 시험: `pulse-auto-reply.test.mjs`(10), `server-pulse-auto-reply.test.mjs`(3: 흐름·운영 스위치 조합 둘), `server-background-jobs.test.mjs`(주기 이름 추가), `server-work-notifications.test.mjs`(업무 알림 주기만 세도록 자동 안내 주기 끔).
