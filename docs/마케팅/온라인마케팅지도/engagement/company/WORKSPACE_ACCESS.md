# 회사·역할에 따른 Workspace

2026-11-13 사용자 요청: 현재 메뉴를 전사 공통·회사별·담당자 전용으로 나누고, 관리자가 회사와 역할을 지정해 초대한다. SHIFT·PULSE 겸임을 지원한다. 처음에는 단독 구현·검증을 요청했고, 이후 Opus 5.5 검수를 허용했다. 최신 검수·배포 상태는 [트랙](../../../../_ops/트랙.md)의 이 작업 줄에서 확인한다.

| 분류 | 기존 메뉴 / 제공 범위 |
|---|---|
| 전사 공통 | 오늘 할 일, 메신저·통화·공유 파일, 내 업무 카드, 회사 안내 |
| LAB | 원장·교사의 수업. 기존 교사 인증·반별 권한도 계속 필요하다. |
| PATH | 담당 상담·정착 업무를 보는 회사 업무 화면 |
| SHIFT | 강의 제목·일정·준비 내용·진행 상태. LAB 학생·반 화면과 분리한다. |
| PULSE | 제작 데스크·제작 도구·트렌드·고객 관리 |
| 별도 담당 | SNS·마케팅, 콘텐츠 제작, 제작 고객 관리, 내 관리 페이지, 체험 의견 확인 |
| 운영 권한 | 팀·크루는 관리자·팀장, 회사 설정·문의 접수는 관리자 |

회사별 업무 역할과 기존 관리자/팀장/실무자/보기 전용 권한은 서로 다른 값이다. 회사 역할은 기능을 고르고 기존 권한과 원본 담당자 검사는 자료 접근을 제한한다. 겸임은 회사별 역할을 여러 개 저장하고 그 기능의 합집합을 제공한다. 화면에서 회사를 골라도 서버의 허용 범위를 넓히지 않는다.

초대는 관리자만 만든다. 회사·회사별 역할·별도 담당·기존 접근 권한을 발급 시 확정하고 수락자는 바꿀 수 없다. 초대 링크와 직접 입력하는 코드는 같은 일회용 입장권이다. 3일 만료, 취소, 중복 수락 방지, 기존 계정의 임의 덮어쓰기 방지를 검증한다. 기존 SYNK ID 연결과 직원 로그인은 보존한다.

기존 직원의 소속을 이름·이메일·팀 이름으로 추정하지 않는다. 프로필이 없는 기존 계정은 관리자 화면에서 미지정으로 표시하고, 기존 자료와 권한을 유지하다가 관리자가 회사·역할을 저장한 시점부터 새 정책을 적용한다. 설정 변경은 동시 편집 버전을 대조하고 기존 세션을 종료해 오래된 화면의 접근을 막는다. 새 초대는 프로필 없는 계정을 만들 수 없다.

구현 검증: 신규 초대·수락·취소·만료·재사용, 회사별 메뉴·직접 주소/API 거절, SHIFT·PULSE 겸임, 역할 변경·세션 철회, 관리자 유지, 기존 계정 보존, PC·모바일·낮은 창 화면. 외부 발송이나 실운영 직원 정보 변경은 시험에 사용하지 않는다.

## 데이터와 사용 흐름

- 직원의 `workspaceProfile`: `version:1`, `memberships:[{company,role}]`, `duties:[]`, `revision`, 수정 시각·관리자 ID. 회사 ID는 LAB/PATH/SHIFT/PULSE이며 직무와 담당 목록의 정본은 `workspace-access.mjs`다.
- 접근 권한인 `user.role`과 팀 `teamId`는 그대로 둔다. 회사 직무를 책임자로 지정해도 시스템 관리자가 되지 않는다. PATH/SHIFT 회사 책임자는 그 회사 업무 기록을 볼 수 있고, 다른 직원은 본인 기록만 본다. 기존 고객·채널·반별 자료 권한은 별도로 적용된다.
- 관리자는 **계정 → 팀·크루 → 직원 초대**에서 회사 여러 개와 각각의 직무·담당 업무를 고른다. 생성된 코드나 링크를 직접 전달한다. **초대 관리**에서 대기·입장 완료·만료·취소를 보고 취소할 수 있다. 원문 초대 코드는 발급 응답에만 있고 목록에는 다시 표시하지 않는다.
- 기존 직원은 **회사·직무 지정**에서 변경한다. 회사와 담당을 전부 비우면 전사 공통 기능만 남는다. 관리자는 관리 기능을 유지한다.
- 입구의 **초대 코드로 입장**은 코드와 초대 링크 둘 다 받는다. 회사/직무는 발급한 값을 사용하고 수락 요청의 권한 필드는 무시한다. 이전에 발급된 프로필 없는 초대는 원래의 3일 유효기간 동안만 기존 계약을 유지한다.
- PATH/SHIFT 기록은 기존 documents 저장소의 `companyWork`에 회사·작성자·버전과 함께 저장한다. 제목·날짜·메모·진행/완료를 지원하는 업무 기록이며, LAB 수업 데이터나 PULSE 고객 데이터를 옮기지 않는다.
- 회사별 보기 선택은 메뉴를 좁힌다. 겸임한 다른 회사의 허용된 원본 링크를 열면 전체 겸임 보기로 돌아간다. 기존 메신저 방·파일 공개 범위를 소속 변경만으로 자동 확대하지 않는다.
- 고객 업무 담당자·검토자는 현재 고객 관리 권한이 있어야 한다. 공개 의뢰의 지정 담당자가 권한을 잃었으면 활성 관리자가 새 의뢰를 받는다. 소속 변경 시 기존 의뢰의 담당자는 그대로 두고 관리자에게 재지정 안내를 보인다.
- PATH/SHIFT 목록은 진행 중 기록을 먼저, 완료 기록을 뒤에 표시한다.

## 새 진입 화면의 연결 계약 · 2026-11-14

디자인 인계의 배정 작업 우선 흐름은 기존 운영 API에 연결한다. Workspace·Pulse 화면 통합과 웹·PC 공통 진입은 각각 기존 담당 세션이 이어가며, 이번 직원 명부 수정에서 별도 진입 화면을 만들지 않는다. 로컬 시안의 로그인·초대·프로젝트·역할은 운영 인증이나 배정 자료가 아니다.

| 연결할 값·동작 | 현재 정본과 경계 |
|---|---|
| 로그인 후 상태 복원 | `GET /api/state`의 `user.workspaceAccess`·`permissions`를 현재 유효 권한으로, `workspaceCatalog`를 회사·직무 목록으로 읽는다. `GET /api/workspace-access`도 같은 카탈로그를 반환한다. 이름·팀·로컬 저장값으로 소속이나 역할을 추정하지 않는다. |
| 직원 소속·설명 | `members[].organization`은 표시할 소속·업무 설명이며 권한을 부여하지 않는다. 저장된 배정은 `workspaceProfileState`, 실제 허용은 `workspaceAccess`로 구분한다([원천](workspace-access.mjs)). 비활성 직원의 배정이 보인다고 해당 직원의 접근이 허용되는 것은 아니다. |
| 회사별 진입·겸임 | 화면의 `waViewAllowed`·`waNavigationAllowed`와 서버의 `workspaceRouteFeature`·`requireWorkspaceFeature`를 함께 유지한다. 회사 선택은 겸임 권한의 표시 범위만 좁힌다. 선택한 회사 밖의 허용된 원본 링크는 전체 겸임 보기로 돌아가며, 허용되지 않는 화면은 기존 홈으로 복귀한다([화면 원천](public/workspace-access.js)). |
| 실제 배정 목적지 | 카탈로그의 기능 목록은 프로젝트 배정 목록이 아니다. PATH·SHIFT는 `/api/company-work/PATH`·`/api/company-work/SHIFT`, PULSE는 `/api/client-projects`의 현재 사용자에게 허용된 자료와 기존 작업실 라우트, LAB는 기존 교사 인증·반별 권한을 따른다. 새 화면은 실제 자료로 목적지를 고르고 여러 배정·미배정·권한 오류를 구분한다. 공통 도구 배치 변경만으로 현재 SNS·자료 권한을 확대하지 않는다. |
| 초대와 소속 변경 | 발급 `/api/members/invite`, 확인 `/api/workspace-invite/inspect`, 수락 `/api/join`, 변경 `/api/members/:id/workspace-profile`, 취소 `/api/workspace-invites/:id/revoke`의 기존 서버 경로를 재사용한다. 초대는 발급자가 정한 역할·3일 만료·일회용/취소·중복 수락 거절을 유지하며, 소속 변경은 revision과 세션 철회를 유지한다([서비스](workspace-access-service.mjs), [HTTP 연결](server.mjs)). |

로그인·초대 직후 바로 작업을 열더라도 본문 수신 뒤의 세션 재검사, 늦게 도착한 응답의 무효화, 로그아웃 후 화면 재노출 차단, 편집 초안과 충돌 선택 보존을 유지한다. 미배정과 거절을 로컬 모의 계정이나 가짜 프로젝트로 대신하지 않는다. 실제 통합 후보는 기존 화면·인증 검수와 배포 절차로 별도 확인한다.

## 11-14 통합 검수 보완

첫 검수의 실제 재현을 바탕으로 다음 경로를 고쳤다. 이전 시간 초과나 아래 시험 통과를 최종 독립 검수·운영 완료로 대신하지 않는다.

- 중지 계정도 저장된 회사·직무·변경 번호로 소속을 수정한다. 실제 기능 권한은 계속 거부하며 같은 revision의 동시 수정 둘 중 하나만 성공한다.
- 유효한 구형 초대도 이메일 중복 검사와 관리자 목록에 포함한다. 원문 토큰이나 저장 해시를 목록에 내보내지 않고, 정확한 초대 하나를 기존 취소 경로로 취소하며 이력을 남긴다. 무관한 초대와 기존3일 만료·가입 계약은 유지한다.
- 대기 초대는 모두 표시하고 종료·만료 이력만 최근100개로 제한한다. 원본 이력을 삭제하지 않는다.
- SNS 기능이 회수되면 기존 팀장이어도 채널 담당자 인계와 발행을 할 수 없다. 새 공개 통계 연결은 수집 중인 대상에서 거절하고, 정상 연결 시 이전 인증·재시도 실패 상태를 초기화해 자동 수집을 재개한다. 마지막 성공 수집 시각은 보존한다.
- 회사 업무 저장은 잘못된 타입을 거절하고, 생략한 칸은 보존하며 명시적 빈 문자열만 지운다. 직원 업무 설명 저장은 현재 활성 관리자를 다시 확인하고 계정 권한을 변경하지 않는다.
- 공유 채널 동료의 회사 직무·업무 설명은 명부 계약에 따라 표시하지만 불필요한 유효 기능·추가 담당·변경 번호는 응답에서 뺀다.

실제 Store·HTTP·모의 발행과 수집·권한 회귀 최종135/135, 종료0·실패/건너뜀0, 원천·시험25파일 실행 전후 지문 일치. 구형 링크 취소 후 LAB 초대 수락, 100개를 넘는 대기 초대, 비활성 발급자의 실제 가입·변경 거절, 겸임자의 회사별 업무 경계, 실제 채널을 넣은 가시성 대조를 포함한다. 운영 직원·초대·외부 게시를 시험 값으로 바꾸지 않았다.

## 11-15 공통 초대 조회의 별도 후속

공통 진입 담당이 직원과 고객을 다시 묻지 않고 코드를 확인할 수 있도록 `POST /api/invite/inspect`를 원천에 추가했다. 이 후속은 직원판 67 후보에 포함하지 않았으며, 원천 게시를 운영 API의 반영으로 보지 않는다. 회사의 수신 문서와 웹 메시지 전달, PC 초대 전달 및 수신 ACK는 별도 설계와 구현으로 이어간다.

조회는 회사와 정확히 같은 origin의 JSON 요청에서 `token` 하나만 받는다. 로그인을 요구하지 않으며 기존 직원 초대 검증과 고객 초대 검증을 모두 읽기로 확인한다. 정확히 한 종류만 유효하면 `{version:1,kind:"employee",destination:"/"}` 또는 `{version:1,kind:"customer",destination:"/pulse-app/"}`를 반환한다. 코드, 이메일, 프로젝트 자료와 인증 정보를 응답에 넣지 않는다. 양쪽 모두 무효이거나 양쪽 모두 유효하면 같은 403으로 거절한다. 저장소 오류를 다른 종류의 초대로 처리하지 않는다.

직원 `inspect`와 실제 `join`, 고객 `checkInvite`와 실제 `open`은 각각 같은 기존 검증을 재사용한다. 분류 조회는 초대를 소비하거나 세션·쿠키·기기·알림·DB를 바꾸지 않는다. 실패 요청의 시도 제한은 메모리에서만 센다. 실제 수락은 기존 API가 다시 검증하며, 고객 `open`은 세션을 만드는 동작이므로 분류 조회에 쓰지 않는다.

Claude Opus 5.5가 원래 다섯 파일을 작성했다. 최초 공식 검수와 서비스 끝판을 마친 뒤, 최신 공개 원천을 보존한 합성판의 `server.mjs` 문맥 변경만 `company-invite-inspection-followup-20261114-r2`에서 다시 확인했다. 이 변경분의 공식 GPT와 현재판의 서비스 끝판 Carbon은 모두 지적이 없었다. 기존 두 시험 파일은 네트워크와 환경을 분리한 상태에서 40/40을 통과했다. 반복 조회 전후의 DB와 쿠키 보존, 만료·취소·잘못된 입력·중복 분류·저장소 오류 및 조회 뒤 실제 수락의 재검증을 포함한다. 초기 검수의 품질 후속은 기존 처리 기록을 유지한다.
