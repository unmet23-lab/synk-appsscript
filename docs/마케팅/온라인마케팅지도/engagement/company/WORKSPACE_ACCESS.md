# 회사·역할에 따른 Workspace

2026-11-13 사용자 요청: 현재 메뉴를 전사 공통·회사별·담당자 전용으로 나누고, 관리자가 회사와 역할을 지정해 초대한다. SHIFT·PULSE 겸임을 지원한다. 처음에는 단독 구현·검증을 요청했고, 이후 Opus 5.5 검수를 허용했다. 최신 검수·배포 상태는 [트랙](../../../../_ops/트랙.md)의 이 작업 줄에서 확인한다.

## 관리자 회원 검색

2026년 11월 16일 중앙 SYNK ID 회원 조회 API를 운영 v104에 반영했고 해당 소스의 GitHub CI도 통과했다. 현재 중앙 계정 화면과 Workspace 관리자의 SYNK ID를 대조해 일치한 관리자 한 계정에 명부 열람권을 부여했다. 2026년 11월 17일 회사 서버 운영판 74에 Workspace 화면과 조회 API를 반영했다. 승인된 같은 관리자 계정에서 두 명부를 검색하고 직원 초대코드를 발급한 뒤 취소했다. 자세한 결과는 [실제 운영 확인](#workspace-member-directory-live-20261117)에 있다.

관리자 화면에서 **Workspace 회원**을 열면 직원과 PULSE 브랜드 회원을 조회한다. 이름, 로그인 아이디, 직원 ID, SYNK ID 또는 브랜드 이름으로 검색할 수 있다. 회사와 이용 상태를 함께 고를 수 있다. 같은 SYNK ID로 확인된 직원과 고객은 한 줄에 표시한다. 직원 이름을 누르면 그 직원의 소속과 역할을 편집하는 화면으로 간다.

**전체 SYNK ID**에는 Workspace를 이용한 적이 없는 가입자도 나온다. 본인의 SYNK ID로 Workspace에 로그인한 관리자 가운데 중앙 명부 열람권을 받은 사람만 볼 수 있다. 가입일과 이용 상태를 확인할 수 있고 이름, 로그인 이메일, SYNK ID로 찾을 수 있다. 가입을 완료하지 않은 로그인과 삭제가 끝난 계정은 명부에서 제외한다. 두 명부 모두 한 번에 최대 25명을 보여준다.

**초대코드 발급**에서 직원이 소속할 회사와 역할을 정한다. **초대 관리**에서는 대기 중인 초대의 상태를 확인하고 취소할 수 있다.

검색은 서버에서 조건을 적용하며 한 번에 25명까지 돌려준다. 합성 회원 8,000명을 넣고 전체 조회, 숫자 검색, 결과 없는 검색을 실행한 마지막 관측은 각각 50ms, 53ms, 43ms였다. 운영 응답 시간의 보장은 아니다. 관련 서버 시험 111개와 1440px·390px 화면의 브라우저 확인 37개가 통과했다. 화면을 연 뒤에 합류한 직원도 이름을 누르면 최신 명부를 받아 상세에 표시하며, 두 목록은 각자의 검색어와 필터와 페이지를 유지한다.

## 관리자 사용과 첫 운영 확인 · 2026-11-15

회사 판 71을 11월 15일 운영에 반영했다. 21:09에 실제 관리자 계정으로 직원 명부, 채널 성과, SHIFT와 PULSE 겸임 초대 설정, 홈을 PC와 모바일 폭에서 확인했다. 발급 화면은 저장하지 않고 닫았다. Windows와 운영 이미지의 Linux에서 제품 시험 4,607개가 각각 통과했다. Linux 호환성 시험 2개가 통과했고 공개 파일 494개가 배포본과 일치했다.

후속 원천에는 홈 이름과 추천 버튼 모양을 정리했다. PULSE 고객 작업실은 재생할 수 있는 최종 영상을 먼저 표시하고 이름이 비어 있는 기존 최종 이미지에는 설명을 표시한다. 이 세부 보완은 다음 정기 배포에서 검수한다.

[Workspace 관리자](https://workspace.synk.im/?tab=admin)에서 직원을 관리한다. 홈의 관리자 단추와 도구 메뉴에서도 같은 화면을 연다. 관리자 권한이 없는 직원에게는 이 메뉴와 API 접근을 허용하지 않는다.

초대코드 발급을 누르고 이름과 로그인 이메일, 팀, 접근 권한을 정한다. 소속 회사는 여러 곳을 함께 선택할 수 있다. SHIFT 강사와 PULSE 제작 담당처럼 회사마다 다른 직무를 지정하고 SNS·마케팅 같은 별도 담당 업무도 선택한다. 초대를 만들면 일회용 코드와 링크가 나오며 수락한 실제 직원 계정에 연결된다. 초대 탭에서 수락 여부와 만료 상태를 보고 대기 중인 초대를 취소한다.

직원 탭에서는 회사와 이용 상태로 명부를 걸러 본다. 각 직원의 회사와 직무, 팀과 접근 권한을 관리한다. 직원의 성과와 업무를 누르면 담당 채널의 조회수, 좋아요, 댓글 등과 회사별 등록 업무를 확인한다. 채널 담당자 지정과 인계 기록은 같은 상세 화면에서 이어서 관리한다.

성과는 수집된 담당 채널의 관측을 기준으로 집계한다. 최신 누적값과 선택 기간의 증감, 실제 자료가 있는 범위, 관측 기준일을 구분한다. 자료가 없는 지표는 미확인으로 표시한다. 업무 완료 건수는 현재 저장된 누적 상태이며 기간 실적으로 해석하지 않는다. 직원이 초대만 수락했다고 모든 외부 채널의 통계가 자동으로 생기는 것은 아니며 담당 채널과 수집 자료가 연결되어야 한다.

회사 판 70을 2026-11-15 14:18 KST에 운영 반영했다. manifest는 `69e8a54616ccc8efeab9f16680e7c13fa2e3bfe266e289c01c8457aad65ef977`다. 실제 69 완료본 위에 검수된 159개 변경만 합쳤다. 로컬과 Linux의 제품 시험은 각각 4,577개가 통과했고 Linux 호환성 시험 2개도 통과했다. 공개 파일 494개가 실제 응답과 모두 일치했다. Linux 결과 회수 중 연결 오류가 있었으나 이미 통과한 원격 결과를 다시 읽었으며 시험을 재실행하지 않았다.

실제 관리자 계정의 기존 로그인을 유지한 채 홈, 직원 명부, 상세 성과, SHIFT·PULSE 겸임 초대 설정을 1440과 390 폭에서 확인했다. 가로 넘침, 깨진 그림, 실행 오류와 실패 요청은 없었다. 실제 직원 정보와 초대를 바꾸지 않았고 초대 발급·수락의 전체 흐름은 격리 서버의 합성 계정으로 검증했다. 설치 PC 앱의 실제 연결 성공을 이 확인에 포함하지 않는다.

홈의 관리자 진입과 회사 메뉴, SNS 탐색과 대비, PULSE 시안·자료 우선순위, 계정 불일치 안내를 다듬은 후속은 별도 후보로 관리한다. 통합 회귀 419개와 캡처 40장을 준비했으며 `workspace-followup-final-20261115-r1`의 독립 검수와 다음 회사 판의 전체 QA·배포를 이어간다. 아래의 과거 검증 기록에서 운영 대기로 적힌 첫 개편본은 이 판에서 반영됐다.

후속 소스의 첫 올리기에서는 연관 시험 다섯 개가 실패해 게시하지 않았다. 네 건은 가벼운 작업 사본에서 빠진 기존 PULSE 이미지 때문이어서 공식 복원 도구로 되살렸다. 한 건은 안전한 이미지 주소를 절대 주소로 정규화한 결과를 옛 상대 주소 단언이 거부한 경우였다. 화면 코드를 다시 바꾸지 않고 같은 서비스의 정확한 이미지 경로, 질의와 조각이 유지되는지 검사하도록 시험을 보완했다. 해당 세 파일의 재검사 49개가 모두 통과했으며 첫 실패 원문을 보존했다.

| 운영 권한 | 팀·크루는 관리자·팀장, 회사 설정·문의 접수는 관리자 |

회사별 업무 역할과 기존 관리자/팀장/실무자/보기 전용 권한은 서로 다른 값이다. 회사 역할은 기능을 고르고 기존 권한과 원본 담당자 검사는 자료 접근을 제한한다. 겸임은 회사별 역할을 여러 개 저장하고 그 기능의 합집합을 제공한다. 화면에서 회사를 골라도 서버의 허용 범위를 넓히지 않는다.

LAB 운영 담당에게는 교사 수업 화면을, SHIFT 자동화 담당에게는 강의 화면을 자동으로 주지 않는다. 별도 페이지·채널 관리 담당은 페이지 관리만 받고 SNS 게시·분석 권한은 별도 SNS·마케팅 담당에서 정한다. PULSE 제작 자료의 기존 담당자·팀 ACL은 SNS 권한과 독립적으로 유지한다.

초대는 관리자만 만든다. 회사·회사별 역할·별도 담당·기존 접근 권한을 발급 시 확정하고 수락자는 바꿀 수 없다. 초대 링크와 직접 입력하는 코드는 같은 일회용 입장권이다. 3일 만료, 취소, 중복 수락 방지, 기존 계정의 임의 덮어쓰기 방지를 검증한다. 기존 SYNK ID 연결과 직원 로그인은 보존한다.

기존 직원의 소속을 이름·이메일·팀 이름으로 추정하지 않는다. 프로필이 없는 기존 계정은 관리자 화면에서 미지정으로 표시하고, 기존 자료와 권한을 유지하다가 관리자가 회사·역할을 저장한 시점부터 새 정책을 적용한다. 설정 변경은 동시 편집 버전을 대조하고 기존 세션을 종료해 오래된 화면의 접근을 막는다. 새 초대는 프로필 없는 계정을 만들 수 없다.

구현 검증: 신규 초대·수락·취소·만료·재사용, 회사별 메뉴·직접 주소/API 거절, SHIFT·PULSE 겸임, 역할 변경·세션 철회, 관리자 유지, 기존 계정 보존, PC·모바일·낮은 창 화면. 외부 발송이나 실운영 직원 정보 변경은 시험에 사용하지 않는다.

## 직원 글감과 문의

직원은 **내 업무 → 내 글감**에서 수업이나 상담에서 겪은 일을 비공개로 적는다. 작성자는 공개할 제목, 본문과 표시 이름을 확인하고 게시한다. 개인 메모는 작성자만 읽는다. 편집 창을 실수로 닫아도 계속 쓸 수 있다.

글마다 공유 주소가 생긴다. 방문자가 그 주소에서 문의하면 작성자의 글 목록 위에 표시된다. 글과 문의는 다섯 건씩 더 볼 수 있다.

직원 계정이 중지되면 그 글의 공개 화면과 새 문의 접수가 닫힌다. 관리자는 **내 업무**에서 인계된 문의와 미처리 건수를 보고 목록을 펼쳐 확인한다. 연락처와 문의 내용은 접수일부터 90일간 보관한다. 방문자는 글이 내려간 뒤에도 접수 번호와 삭제 코드로 자기 문의를 확인하거나 지울 수 있다. [문의 접수증](https://workspace.synk.im/story/receipt)

## 데이터와 사용 흐름

- 직원의 `workspaceProfile`: `version:1`, `memberships:[{company,role}]`, `duties:[]`, `revision`, 수정 시각·관리자 ID. 회사 ID는 LAB/PATH/SHIFT/PULSE이며 직무와 담당 목록의 정본은 `workspace-access.mjs`다.
- 접근 권한인 `user.role`과 팀 `teamId`는 그대로 둔다. 회사 직무를 책임자로 지정해도 시스템 관리자가 되지 않는다. PATH/SHIFT 회사 책임자는 그 회사 업무 기록을 볼 수 있고, 다른 직원은 본인 기록만 본다. 기존 고객·채널·반별 자료 권한은 별도로 적용된다.
- 관리자는 **사람·조직 → 직원 초대**에서 회사 여러 개와 각각의 직무·담당 업무를 고른다. 생성된 코드나 링크를 직접 전달한다. **초대 관리**에서 대기·입장 완료·만료·취소를 보고 취소할 수 있다. 아직 유효한 대기 초대는 전부 표시하고, 끝난 이력은 최근 100건을 표시한다. 원문 초대 코드는 발급 응답에만 있고 목록에는 다시 표시하지 않는다.
- 기존 직원은 **회사·직무 지정**에서 변경한다. 회사와 담당을 전부 비우면 전사 공통 기능만 남는다. 관리자는 관리 기능을 유지한다.
- 입구의 **초대 코드로 입장**은 코드와 초대 링크 둘 다 받는다. 회사/직무는 발급한 값을 사용하고 수락 요청의 권한 필드는 무시한다. 이전에 발급된 프로필 없는 초대는 원래의 3일 유효기간 동안만 기존 계약을 유지한다.
- 이전 초대도 수락하면 같은 초대 ID에 가입한 직원의 계정 ID를 기록한다. 이 기록은 가입과 한 번에 저장되므로 저장에 실패하면 가입과 코드 사용도 취소된다. 발급 시각을 알 수 없는 이전 초대는 그 값을 비워 둔다. 초대 이력은 발급 시각순으로 정렬하고, 발급 시각이 없으면 수락 또는 취소 시각을 쓴다.
- PATH/SHIFT 기록은 기존 documents 저장소의 `companyWork`에 회사·작성자·버전과 함께 저장한다. 제목·날짜·메모·진행/완료를 지원하는 업무 기록이며, LAB 수업 데이터나 PULSE 고객 데이터를 옮기지 않는다.
- 회사별 보기 선택은 메뉴를 좁힌다. 겸임한 다른 회사의 허용된 원본 링크를 열면 전체 겸임 보기로 돌아간다. 기존 메신저 방·파일 공개 범위를 소속 변경만으로 자동 확대하지 않는다.
- 고객 업무 담당자·검토자는 현재 고객 관리 권한이 있어야 한다. 공개 의뢰의 지정 담당자가 권한을 잃었으면 활성 관리자가 새 의뢰를 받는다. 소속 변경 시 기존 의뢰의 담당자는 그대로 두고 관리자에게 재지정 안내를 보인다.
- PATH/SHIFT 목록은 진행 중 기록을 먼저, 완료 기록을 뒤에 표시한다.
- 새 PATH/SHIFT 업무 폼은 같은 요청 식별자를 재시도 동안 유지한다. 서버는 회사·작성자·요청 식별자와 내용 해시를 함께 대조해 같은 저장 응답이 유실돼도 한 건만 만든다. 같은 식별자로 내용을 바꿔 보내면 충돌로 안내한다. 목록의 오래된 조회 응답과 이미 닫힌 폼의 저장 응답은 새 목록이나 다른 입력창을 덮지 않아야 한다.
- 이용 중지 계정의 소속·직무·편집 버전은 관리자가 확인할 기록으로 보존한다. 실제 접근 권한은 여전히 없고, 오래된 편집 버전으로 소속을 덮을 수 없다. 프로필 없는 기존 계정에도 새 PATH/SHIFT 기록 권한을 자동으로 주지 않는다.

## 전면 화면 개편 진행 · 2026-11-14

## 새 진입 화면의 연결 계약 · 2026-11-14

디자인 인계의 배정 작업 우선 흐름은 기존 운영 API에 연결한다. Workspace·Pulse 화면 통합과 웹·PC 공통 진입은 각각 기존 담당 세션이 이어가며, 이번 직원 명부 수정에서 별도 진입 화면을 만들지 않는다. 로컬 시안의 로그인·초대·프로젝트·역할은 운영 인증이나 배정 자료가 아니다.

| 연결할 값·동작 | 현재 정본과 경계 |
|---|---|
| 로그인 후 상태 복원 | `GET /api/state`의 `user.workspaceAccess`·`permissions`를 현재 유효 권한으로, `workspaceCatalog`를 회사·직무 목록으로 읽는다. `GET /api/workspace-access`도 같은 카탈로그를 반환한다. 이름·팀·로컬 저장값으로 소속이나 역할을 추정하지 않는다. |
| 직원 소속·설명 | `members[].organization`은 표시할 소속·업무 설명이며 권한을 부여하지 않는다. 저장된 배정은 `workspaceProfileState`, 실제 허용은 `workspaceAccess`로 구분한다([원천](workspace-access.mjs)). 비활성 직원의 배정이 보인다고 해당 직원의 접근이 허용되는 것은 아니다. |
| 회사별 진입·겸임 | 화면의 `waViewAllowed`·`waNavigationAllowed`와 서버의 `workspaceRouteFeature`·`requireWorkspaceFeature`를 함께 유지한다. 회사 선택은 겸임 권한의 표시 범위만 좁힌다. 선택한 회사 밖의 허용된 원본 링크는 전체 겸임 보기로 돌아가며, 허용되지 않는 화면은 기존 홈으로 복귀한다([화면 원천](public/workspace-access.js)). |
| 실제 배정 목적지 | 카탈로그의 기능 목록은 프로젝트 배정 목록이 아니다. PATH·SHIFT는 `/api/company-work/PATH`·`/api/company-work/SHIFT`, PULSE는 `/api/client-projects`의 현재 사용자에게 허용된 자료와 기존 작업실 라우트, LAB는 기존 교사 인증·반별 권한을 따른다. 새 화면은 실제 자료로 목적지를 고르고 여러 배정·미배정·권한 오류를 구분한다. 공통 도구 배치 변경만으로 현재 SNS·자료 권한을 확대하지 않는다. |
| 초대와 소속 변경 | 발급 `/api/members/invite`, 확인 `/api/workspace-invite/inspect`, 수락 `/api/join`, 변경 `/api/members/:id/workspace-profile`, 취소 `/api/workspace-invites/:id/revoke`의 기존 서버 경로를 재사용한다. 초대는 발급자가 정한 역할·3일 만료·일회용/취소·중복 수락 거절을 유지하며, 소속 변경은 revision과 세션 철회를 유지한다([서비스](workspace-access-service.mjs), [HTTP 연결](server.mjs)). |

로그인·초대 직후 바로 작업을 열더라도 본문 수신 뒤의 세션 재검사, 늦게 도착한 응답의 무효화, 로그아웃 후 화면 재노출 차단, 편집 초안과 충돌 선택 보존을 유지한다. 미배정과 거절을 로컬 모의 계정이나 가짜 프로젝트로 대신하지 않는다. 실제 통합 후보는 기존 화면·인증 검수와 배포 절차로 별도 확인한다.

## 11-15 공통 초대 조회의 별도 후속

공통 진입 담당이 직원과 고객을 다시 묻지 않고 코드를 확인할 수 있도록 `POST /api/invite/inspect`를 원천에 추가했다. 이 후속은 직원판 67 후보에 포함하지 않았다. 원천 게시 뒤 필요한 다섯 파일의 의존성을 별도로 대조했고, 회사판 70에서 공통 수신 문서 및 본인 배정 조회와 함께 운영에 반영했다. PC 발신과 실제 계정 연결의 최종 확인은 Solio 담당의 결과로 구분한다.

조회는 회사와 정확히 같은 origin의 JSON 요청에서 `token` 하나만 받는다. 로그인을 요구하지 않으며 기존 직원 초대 검증과 고객 초대 검증을 모두 읽기로 확인한다. 정확히 한 종류만 유효하면 `{version:1,kind:"employee",destination:"/"}` 또는 `{version:1,kind:"customer",destination:"/pulse-app/"}`를 반환한다. 코드, 이메일, 프로젝트 자료와 인증 정보를 응답에 넣지 않는다. 양쪽 모두 무효이거나 양쪽 모두 유효하면 같은 403으로 거절한다. 저장소 오류를 다른 종류의 초대로 처리하지 않는다.

직원 `inspect`와 실제 `join`, 고객 `checkInvite`와 실제 `open`은 각각 같은 기존 검증을 재사용한다. 분류 조회는 초대를 소비하거나 세션·쿠키·기기·알림·DB를 바꾸지 않는다. 실패 요청의 시도 제한은 메모리에서만 센다. 실제 수락은 기존 API가 다시 검증하며, 고객 `open`은 세션을 만드는 동작이므로 분류 조회에 쓰지 않는다.

Claude Opus 5.5가 원래 다섯 파일을 작성했다. 최초 공식 검수와 서비스 끝판을 마친 뒤, 최신 공개 원천을 보존한 합성판의 `server.mjs` 문맥 변경만 `company-invite-inspection-followup-20261114-r2`에서 다시 확인했다. 이 변경분의 공식 GPT와 현재판의 서비스 끝판 Carbon은 모두 지적이 없었다. 기존 두 시험 파일은 네트워크와 환경을 분리한 상태에서 40/40을 통과했다. 반복 조회 전후의 DB와 쿠키 보존, 만료·취소·잘못된 입력·중복 분류·저장소 오류 및 조회 뒤 실제 수락의 재검증을 포함한다. 초기 검수의 품질 후속은 기존 처리 기록을 유지한다.


## 관리자 화면과 공통 진입 연결 · 2026-11-14

관리자 화면의 주소는 `https://workspace.synk.im/?tab=admin`이다. 관리자에게만 홈과 도구 메뉴에서 입구를 보여 준다. 일반 직원과 팀장이 주소를 직접 열면 허용된 화면으로 돌아가며 관리자 집계 API를 요청하지 않는다. 서버도 현재 활성 관리자 여부를 다시 확인한다. 이 절은 구현 계약이며 운영 배포 완료는 해당 릴리스 증거로 확인한다.

직원 보기에서는 이름과 이메일을 검색하고 회사와 이용 상태를 고른다. SHIFT와 PULSE를 겸임하는 직원은 전체 명부에서 한 번만 표시하며 두 회사 필터에 모두 포함한다. 소속이 없는 기존 계정, 전사 접근 관리자, 이용 중지 직원은 구분해서 표시한다. 직원 설명 수정, 회사별 직무와 추가 담당 업무, 팀과 접근 역할, 이용 중지와 재개는 기존 편집 경로를 사용한다. 중지와 재개는 영향 안내 후 확정한다.

성과 보기의 조회수, 좋아요, 댓글, 공유, 저장, 도달, 팔로워는 기존 채널 관측 자료를 사용한다. 누적값과 선택 기간의 증감은 다른 칸에 표시한다. 확인한 0과 확인하지 못한 값은 구분한다. 공동 담당 채널은 직원별로 중복될 수 있으므로 직원 수치를 더해 전사 합계로 만들지 않는다. 현재 담당이 없어도 과거에 담당했던 기간의 관측 기록은 유지한다. 채널 미배정, 연결 전, 첫 관측 대기, 보관된 채널도 구분한다.

PATH와 SHIFT의 진행·완료 건수와 PULSE의 담당·검토 단계는 조회 시점의 등록 상태다. 선택한 기간의 실적이나 직원 종합 점수로 표시하지 않는다. LAB 수업 지표는 아직 관리자 집계에 연결하지 않았으며 미연결 상태를 표시한다. 관리자는 직원별 상세 성과로 이동할 때 해당 계정과 선택한 날짜를 그대로 전달한다.

다른 작업의 원천을 지우지 않고 선택 기능의 설치 경계를 분리했다. 기능 모듈과 전용 화면 자산이 모두 없는 경우에는 해당 기능을 연결하지 않는다. 일부만 있거나 끊어진 링크이거나 읽을 수 없거나 모듈이 깨진 경우에는 서버 기동을 거절한다. AI 마켓은 기존 기본 꺼짐을 유지하며, 파일이 없는데 명시적으로 켜면 거절한다. 직원 명부와 인증은 필수 모듈이므로 이 선택 기능 처리로 빠지지 않는다.

기존 수집 정리를 원천에 복원한 뒤 삭제 범위를 더 좁혔다. 오래된 기록 가운데 수집기가 종료 상태로 기록한 것만 정리하고, 상태가 없거나 알 수 없는 기록은 보존한다. 대기·진행 중 기록과 잘못된 날짜 형식도 보존한다. 작업실 예약만 켜진 경우에는 이 삭제가 돌지 않는다. 실패를 고정 코드로 기록하고 성공한 뒤에만 정리 시각을 갱신해 다음 회차에 다시 시도할 수 있게 했다. 중앙 명부 응답은 총원과 페이지의 행 수가 맞는지도 검증한다.

관련 시험 70개가 모두 통과했다. 운영 73의 실제 후보를 복사한 분석 사본에 수정한 백엔드와 관리자 화면만 얹은 격리 서버에서 검색·초대 HTTP 7개와 화면 검사 37개도 통과했다. 분석 사본의 이전 manifest를 운영 증거로 쓰지 않는다. 운영판 74는 검수한 소스 커밋과 제품 경로로 정식 합성한 뒤 전체 QA와 Linux QA 및 운영 사후 확인을 통과했다. 필수 검수 사슬은 workspace-member-directory-runtime-package-r3-20261116이다.

같은 묶음에 실을 공유 게시물과 명부의 서버는 한 검수본으로 공급하고, 공유 게시물의 나머지 12파일은 원 담당의 검수 바이트와 증명을 보존했다. 운영 73에 네 항목의 제품 27파일을 합친 분석 사본에서 관련 시험 144개와 화면 37개 및 검색·초대·공유 게시물 HTTP 10개가 통과했다. 추가 점검에서는 기존 자산 목록 정규식 시험 둘의 실패를 재현했다. 목록을 등록한 뒤 미설치 마케팅 자산을 제외하는 형태로 맞춘 새 사본은 해당 시험 30개와 백엔드 시험 70개를 모두 통과했고 HTTP 10개도 통과했다. 배포용 후보는 이 분석 사본과 별도로 정식 절차에서 만들었다.

검수에서 제안된 별도의 선택 기능 설치 선언과 물리적인 패키지 누락을 저장소 CI에서 자동 조립하는 회귀는 배포 기반의 후속이다. 현재의 기능 설치 목록은 검수된 제품 경로와 배포 manifest로 관리하며, 운영 패키지와 생성자 모의 시험에서 확인한 범위를 구분한다. 실제 관리자 계정의 운영 확인은 위 11월 17일 기록에서 마쳤다.
