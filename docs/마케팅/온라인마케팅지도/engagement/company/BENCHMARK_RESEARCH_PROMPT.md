# 최신 콘텐츠 조사 · 관리자 업로드 안내

2026-09-27 · 직원이 자기 시청자와 소재에 맞는 기획을 고르는 데 쓰는 공동 참고 자료다. 관리자 제출 자료이며 회사 프로그램이 원문 사실이나 인기를 자동 인증한 보고서가 아니다.

## 사용하는 순서

1. 관리자가 본인 Google 계정으로 Gemini의 Deep Research를 열고 아래 **복사할 조사 지시문**을 붙여 넣는다. 필요하면 조사 주제·대상·언어를 바꾼다.
2. 원문 링크, 게시일, 반응 수치의 확인 근거를 검토한다. 원문을 못 보거나 날짜·반응을 확인하지 못한 항목은 선정 목록에서 뺀다.
3. 결과를 UTF-8 `.json` 파일로 저장한다. Markdown 코드 표시, 설명 문장, 주석은 JSON 파일 밖에 둔다. 파일 다운로드가 제공되지 않으면 JSON 본문만 텍스트 파일에 복사해 `.json`으로 저장한다.
4. 관리자가 회사 콘텐츠 기획 화면에서 파일을 올리고 내용과 조사 날짜를 확인한다. 이후 직원은 회사 계정으로 참고 자료를 보고 자기 기획에 연결한다.
5. 다음 조사에서는 최신 원문을 다시 확인해 새 보고서를 만든다. 과거 관측 수치를 오늘의 수치로 바꾸거나 과거 보고서의 날짜만 갱신하지 않는다.

이 흐름은 관리자의 수동 조사·업로드다. 회사 프로그램의 검색 API 연결, 직원에게 Google 로그인 공유, 자동 게시를 포함하지 않는다. Gemini 구독의 실제 이용 가능 범위는 관리자 계정 화면에서 확인한다.

## 복사할 조사 지시문

당신은 SYNK의 콘텐츠 기획을 돕는 리서처다. 실제 공개 원문을 조사해 직원들이 참고할 콘텐츠를 최대 5개 선정하라. 조사한 범위 안의 편집 선정이며, 전 세계 최고·전체 플랫폼 순위·알고리즘 성공 사례로 부르지 않는다.

### 이번 조사 범위

- 조사 주제: [선택 입력. 기본: 실무 AI 활용, 실제 제작 여정, 한국어 학습]
- 시청자: [선택 입력. 기본: AI 초보자와 자기 업무에 적용하려는 사람, 한국어를 배우고 생활에서 쓰려는 사람]
- 조사 언어·지역: [선택 입력. 기본: 한국어와 영어의 공개 콘텐츠. 특정 지역 전체를 대표한다고 주장하지 않음]
- 우선 매체: Instagram Reels. 주제에 맞는 근거가 부족하면 YouTube Shorts, TikTok, Facebook Reels로 넓히되 실제 플랫폼과 형식을 구분한다.
- 기간: 조사일의 한국 시간 날짜를 끝으로 최근 7일을 먼저 조사한다. 자료가 부족하면 최대 30일까지 넓힌다. 최종 periodStart·periodEnd는 실제 조사 범위의 한국 시간 날짜이며 양 끝을 포함해 7~30일이다. 오늘 날짜와 실제 조사 시각을 먼저 확인한다.
- 목표: 원문·게시일·공개 반응을 확인할 수 있고 SYNK 시청자에게 도움이 되는 1~5개. 수량을 맞추려고 근거가 약한 사례를 채우지 않는다.

### SYNK의 목적과 편집 기준

SYNK는 각자의 목표와 상황에 맞는 도움을 제공하는 개인화 시스템을 만든다. 교육, 기업의 AI 활용, 콘텐츠, 유학·취업 준비에 적용한다.

- LAB: 한국어와 한국에서의 공부·생활 준비. 실제 생활 대화는 AI 실사 인물 상황극, 표현·유행어 소개는 마스코트 형식으로 변형할 수 있다.
- SHIFT: 기업·기관이 AI를 자기 일에 활용하고 가진 가치를 고객에게 전달하도록 돕는다.
- PULSE: 음악·영상·캐릭터 이야기로 다시 찾고 싶은 작품을 만든다.
- PATH: 한국 유학부터 대학 생활·취업 준비까지 돕는 방향이다. 계획·준비를 실제 서비스 운영·기관 협력 실적으로 만들지 않는다.

모든 선정과 변형은 먼저 “시청자 입장에서 이걸 볼 이유가 무엇인가?”에 답한다. 아래 원칙은 SYNK의 편집 기준이며 플랫폼 추천·조회수 상승을 보장하는 공식 알고리즘 규칙이 아니다.

1. 정보와 재미를 함께 준다. 정보는 판단 근거·따라 할 행동·줄일 시행착오다. 재미는 웃음뿐 아니라 공감, 기대와 해소, 발견, 참여, 성취감, 쉽게 이해하고 배우는 즐거움이다. 실제 어느 장면에서 각각 얻는지 설명한다.
2. 진정성을 확인한다. 직접 경험, 조사·인터뷰·실험, 설명용 재구성을 구분한다. 직접 겪지 않은 일을 경험담으로 쓰지 않는다. 선택 이유와 우리 관점, 적용 조건과 실패·한계, 출처·AI 생성·협찬 표시를 남긴다. 진정성을 수치 점수로 인증하지 않는다.
3. 개인화는 시청자의 상황→선택→다음 행동으로 구체화한다. 예를 들어 처음 시작하는 사람과 이미 사용 중인 사람에게 준비물·설명 깊이·연습을 다르게 제안한다. 시청자의 성격·민감정보·배경을 임의 추정하지 않는다. 장기 개인화 기능이 이미 운영 중이라고 주장하지 않는다.
4. 친절하고 직관적으로 전달한다. 배경지식이 없는 사람이 어디를 보고 무엇을 하며 왜 필요한지 이해할 수 있게 한다. 읽는 시간, 설명과 화면 강조의 일치, 결과 확인을 함께 살핀다.
5. 참고작의 문장·음원·장면·타인의 경험을 우리 것으로 복제하지 않는다. 도입, 정보 공개 순서, 질문과 해소, 전환 리듬 같은 원리를 분석하고 우리 실제 소재로 변형한다. 가상의 적용안은 앞으로 해볼 제안으로 쓴다.

### 원문과 반응 조사 방법

1. 검색 결과는 후보를 찾는 데 사용하고 원문 개별 게시물로 이동한다. 실제 영상 형식을 확인한다. 일반 게시물·이미지·YouTube 영상을 Instagram Reels로 표기하지 않는다.
2. 게시물의 제목·제작자·원문 URL·실제 게시일·반응 관측 시각을 확인한다. 검색 색인 날짜, 캡션 속 행사 날짜, 화면 아래의 관련 게시물 날짜를 대상 게시일로 쓰지 않는다. 캐시의 “몇 시간 전”을 오늘 날짜에서 역산하지 않는다.
3. 가능하면 실제 영상을 재생한다. 재생하지 못했으면 캡션·대체텍스트·썸네일 중 무엇을 봤는지 evidenceNote에 쓰고 소리·컷·전환·시청 유지 효과를 본 것처럼 분석하지 않는다. 확인한 부분만 hook·structure·payoff에 기록한다.
4. views·likes·comments·shares·saves·followers는 원문 또는 공식 공개 자료에서 실제 확인한 0 이상의 정수만 입력한다. 미공개·접근 불가·불명은 null이다. 화면에 실제 0으로 표시된 경우에만 0을 쓴다. “6.1K” 같은 반올림 표시는 정밀 정수 6100으로 바꾸지 말고 해당 metric을 null로 두고 evidenceNote에 원문 표기와 한계를 적는다.
5. 최종 items에는 게시일과 확인 시각이 있으며, 게시물 반응인 views·likes·comments·shares·saves 중 적어도 하나의 양수 정수를 확인한 사례만 넣는다. 팔로워 수만 확인한 것은 게시물 반응 근거가 아니다. 조건을 충족하지 못하면 제외하고 selectionBasis에 부족한 이유를 쓴다.
6. 누적 반응을 같은 길이의 관측 구간에서 생긴 증가량으로 표현하지 않는다. 관측 시점의 계정 규모와 게시 후 경과 시간을 함께 해석한다. 팔로워·정확한 게시 시각을 모르면 그 한계를 적는다. 현재 팔로워를 게시 당시 팔로워로 보거나 조회수를 고유 시청자로 단정하지 않는다.
7. 서로 다른 플랫폼의 조회수·반복 재생·공유 지표를 같은 기준의 점수로 합치지 않는다. 반응 수만으로 구매·학습 효과·완시율·알고리즘 노출 원인을 증명하지 않는다. 유료 광고·협찬·재게시 여부가 확인되면 표시하고 확인되지 않으면 미확인으로 쓴다.
8. 게시 계정과 실제 원작자가 다른지 확인한다. 출처 없는 재게시와 원저작자 논란이 있는 콘텐츠는 우선 제외한다. 실험·제품 기능에 대한 캡션 주장을 별도로 검증하지 못하면 주장으로 표시한다.

### 비교와 선정

- candidateCount는 기간·매체 조건을 확인하고 실제 비교한 중복 없는 후보 게시물 수다. 검색 결과 개수나 검색엔진의 추정 건수를 넣지 않는다. items는 그 후보 중 1~5개다.
- selectionBasis에는 검색 범위·주요 검색어, 비교한 후보 수, 선정 기준, 제외·접근 제한, 반응 수치와 계정 규모·게시 후 시간의 비교 한계를 간단히 적는다. 전수 조사나 객관적 인기 순위라는 표현을 쓰지 않는다.
- 단순 누적 조회수 순서보다 우리 시청자의 필요, 전달 정보와 즐거움, 확인된 반응, 실제 소재로 바꿀 수 있는 정도를 함께 본다. 배열 순서는 이번 조사 안에서 직원이 먼저 검토하면 좋을 순서다. 인과관계나 플랫폼 전체 순위가 아니다.
- 유효 사례가 1~4개면 그 개수만 출력한다. 0개이면 “자료 부족: 원문·게시일·공개 반응 조건을 충족한 사례 없음”과 확인 범위를 설명하고 보고서 JSON을 만들지 않는다. 빈 항목이나 가짜 사례로 5개를 채우지 않는다.

### 각 항목에 담을 직원 기획 도움

- hook: 시청자가 계속 볼 이유와 도입 질문·갈등·결과 예고. 확인하지 못한 정확한 초 단위 타임코드는 만들지 않는다.
- structure: 확인한 정보 공개 순서, 질문과 해소, 예시·결과·한계, 화면·나레이션의 관계. 영상 미재생이면 캡션 기준임을 표시한다.
- payoff: 얻는 정보와 재미·감정적 보상을 각각 구체화한다. 둘 중 부족한 것이 있으면 솔직하게 적는다.
- brandFit: 맞는 SYNK 브랜드·시리즈와 대상, 우리가 다룰 이유, 맞지 않는 부분을 적는다.
- adaptation: 우리 실제 소재로 바꿀 도입과 전개, 필요한 경험·증거, 시청자 상황별 선택, 보고 난 뒤의 행동, 필요한 자료·검증을 적는다. 만들어진 성과 대신 앞으로 확인할 제안으로 쓴다.
- evidenceNote: 날짜·수치의 출처와 관측 방식, 영상 재생 여부, 계정 규모·경과 시간, 협찬·원작자·불확실성을 1,000자 안에 적는다. 출처 URL이 추가로 필요하면 이 문자열 안에 쓴다.

### 출력 계약

최종 결과는 다음 키의 JSON 객체 한 개다. JSON 앞뒤 설명·Markdown 코드 표시·주석·NaN·Infinity를 넣지 않는다. UTF-8 파일 100KiB 이하. 각 문자열은 아래 최대 길이를 지킨다.

- version: 숫자 1.
- title: 이번 조사 제목, 160자 이하.
- scope: 실제 주제·시청자·언어·지역·매체 범위를 나타내는 문자열, 300자 이하.
- periodStart, periodEnd: YYYY-MM-DD. 한국 시간 날짜 기준, 양 끝 포함 7~30일. 선정 항목의 실제 게시일은 이 범위 안에 있어야 한다.
- researchedAt: 실제 조사 완료 시각, 시간대를 포함한 ISO 8601. 예: YYYY-MM-DDTHH:mm:ss+09:00. 이 형식 설명을 실제 값으로 쓰지 않는다.
- candidateCount: 양의 정수이며 items.length 이상. 실제 비교한 수를 모르면 숫자를 만들지 말고 자료 부족을 보고한다.
- selectionBasis: 실제 조사 범위 안의 선정 이유·한계를 담은 문자열, 1,000자 이하.
- items: 1~5개의 객체. id나 rank는 만들 필요 없다.

각 item의 키:

- title: 제목 또는 내용 요약, 200자 이하. 원문과 다른 요약 제목이면 요약임을 알 수 있게 쓴다.
- url: 확인한 개별 게시물의 원문 HTTPS URL. 검색 결과·프로필·단축주소를 쓰지 않는다.
- platform: instagram, youtube, tiktok, facebook 중 정확히 하나.
- creator: 원문에 표시된 게시자, 100자 이하. 실제 원작자가 다르면 evidenceNote에 구분한다.
- publishedAt: 원문 게시일 YYYY-MM-DD 또는 정확한 시각을 확인했다면 시간대 포함 ISO 8601. 날짜만 알 때 시각을 지어내지 않는다.
- checkedAt: 반응을 실제 확인한 시각, 시간대 포함 ISO 8601. 검색 추출본 확인 시각과 원문 수치 관측 시각을 혼동하지 않는다.
- metrics: views, likes, comments, shares, saves, followers 여섯 키. 각 값은 확인한 0 이상의 정수 또는 null. 누락된 지표를 0으로 채우지 않는다.
- evidenceNote: 문자열, 1,000자 이하.
- hook: 문자열, 1,000자 이하.
- structure: 문자열, 2,000자 이하.
- payoff: 문자열, 1,000자 이하.
- brandFit: 문자열, 1,000자 이하.
- adaptation: 문자열, 2,000자 이하.
- seriesIds: 관련 있는 아래 ID의 배열. 맞는 시리즈가 없으면 [].

## 업로드 템플릿

[benchmark-upload-template.json](benchmark-upload-template.json)은 전체 필드를 보여주는 **미완성 작성용 틀**이다. 제목에 템플릿 표시가 있고 날짜·URL·설명은 비어 있으며 수치는 null이다. JSON 문법은 유효하지만 조사 보고서로 등록할 수 없다. 실제 조사 후 필수 값을 채우고 빈 항목을 제거해야 한다.

최종 업로드 파일은 items 1~5개, 확인 시각과 원문, 최소 하나 이상의 확인된 양수 지표가 필요하다. 위 조사 지시문은 더 엄격하게 게시물 반응 지표를 요구한다. 팔로워만 있는 항목은 인기 근거가 부족하다. 숫자와 날짜의 형식 검사를 통과했다는 사실은 원문 사실 검증 완료를 뜻하지 않는다.
