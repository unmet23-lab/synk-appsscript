# 싱ㅋ 워크스페이스 · 마케팅과 제작

직원마다 관리하는 SNS 주소를 등록하고 회사·담당 채널의 성장 기록을 함께 보는 내부 프로그램입니다. 사내 메신저와 통합한 실행·계정·파일 안내는 [WORKSPACE.md](WORKSPACE.md), 운영과 복구 절차는 [클라우드 운영](CLOUD-OPERATIONS.md)·[데이터 이전](CLOUD-DATA-MIGRATION.md)을 참고하세요.

2026-10-09 01:44 KST 기준 회사·고객 상담·업무 알림 v2가 공개 운영 중입니다. 기존 계정·메모·첨부·상담·키 보존, 브라우저를 비운 동안의 예약 알림1건 생성, HTTPS/TLS 경보 메일2건과 원복을 확인했습니다. 01:10 수동 백업도 독립 다운로드 후 현재 이미지에서 격리 복구했습니다. 상세 시험·해시·한계는 [릴리스 검증 요약](../../../../_ops/qa/company-cloud-release-20261009/README.md)에 있습니다.

**업무 알림·Web Push는 켜져 있고 유료 AI·SNS 자동 수집·Drive 삭제 outbox는 꺼져 있습니다.** 실제 기기 등록·푸시 발송은0입니다. 첫 정기 백업은03:30~03:46 실행 후03:50 서버 확인·03:55 공식1회 후속이 예정돼 있으며 아직 미확인입니다. 후속에는 로컬 PC·앱이 필요하지만 백업은 독립적으로 실행됩니다. 실제 휴대폰·PC 종료 시험과 회사 클라우드 전체 Claude 재검수는 사용자 지정 후행이며, 업무 알림 v2 수정분의 별도 공식 검수와 구분합니다.

회사 원본과 옛 백업을 보존한 채 클라우드 영구 볼륨에서 운영합니다. 본인 확인된 SYNK ID를 기존 관리자에 연결해 실제 로그인했으며 새 계정·비밀번호 변경은 없었습니다. 외부 SNS 개발자 앱 심사·직원 계정 연결·자동 수집 재개는 별도입니다.

## 운영 서버에서 열기

직원은 [회사 워크스페이스](https://workspace.synk.im), 고객은 [고객 상담](https://workspace.synk.im/consultation/)을 이용합니다. PC 바로가기 2개도 공개 주소로 전환했습니다. 기존 로컬 데이터·실행기는 보존하지만 실제 운영 기록은 클라우드에 쌓이므로 이전 PC 서버를 함께 켜서 별도 기록을 만들지 않습니다.

## 로컬 개발·독립 시험에서 열기

Node.js 24 이상이 필요합니다. 데이터베이스는 Node에 포함된 SQLite를 사용하므로 별도 DB 설치나 패키지 설치는 필요하지 않습니다.

Windows에서는 이 폴더의 `start-company.ps1`을 실행합니다. 저장소 폴더에서 실행할 때는 다음과 같습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "docs/마케팅/온라인마케팅지도/engagement/company/start-company.ps1"
```

서버가 켜지고 `http://127.0.0.1:4191`의 관리자 화면이 열립니다. 로컬 실행기는 이 컴퓨터의 일회용 시작 링크를 사용합니다. 로그아웃했거나 시작 링크가 만료되면 실행기를 다시 열면 됩니다.

**`localhost`와 `127.0.0.1`은 현재 컴퓨터에서만 접속할 수 있는 주소입니다. 직원에게 이 주소를 보내도 직원의 다른 컴퓨터에서는 열리지 않습니다.** 이 컴퓨터가 꺼지거나 서버가 종료되면 수집도 중단됩니다.

처음 로컬 실행할 때 기존 SYNK 채널 목록과 수동 성장 기록을 회사 프로그램으로 복사해 가져옵니다. 지원하지 않는 주소는 원래 기록장에 남습니다. 기존 기록 파일이나 기존 프로그램을 덮어쓰지 않습니다.

## 직원이 사용하는 순서

**제작 스튜디오**에는 경험·소재 보관함, 제작 상황판, 완성본 검토실, 좋은 콘텐츠 예시함이 있습니다. 혼자서는 자신을 담당자로 두고, 함께 일할 때는 담당자·검토자·팀을 지정합니다. 실제 영상·이미지·원고의 버전을 비교하고 장면별 의견을 남기며, 선정한 예시와 배울 점을 회사에 공유합니다. [제작 스튜디오 안내](STUDIO.md)

**콘텐츠 기획**은 관리자가 조사해 공유한 **벤치마크 TOP 5 → 우리 소재로 구성 → 재미·도움·진정성·개인화 검토**로 이어집니다. 관리자는 `조사 자료 업데이트`에서 Gemini 조사 지시문을 복사하고, 본인 Google AI Pro에서 조사한 JSON을 업로드·미리보기·공유합니다. 직원은 참고 구조와 제작 양식 10개를 바탕으로 구성안 3개를 만들고 기획함에 저장·내보낼 수 있습니다. 직원의 열람·기획은 API를 호출하지 않습니다. 보고서는 원문·게시일·관찰 수치·선정 범위를 표시하고 이전 조사본을 보관합니다. 첫 실제 조사 자료는 아직 등록 전입니다. [기획 엔진 안내](CONTENT_ENGINE.md), [조사 지시문](BENCHMARK_RESEARCH_PROMPT.md)

1. 관리자가 **팀·직원**에서 팀을 만들고, 소속 팀과 역할을 정해 초대 링크를 만듭니다. 링크를 직원에게 직접 전달하며 이메일을 자동 발송하지는 않습니다.
2. 직원은 초대 링크에서 이름과 비밀번호를 정하고 로그인합니다.
3. **채널 → 채널 등록**에서 페이지 주소를 한 줄에 하나씩 붙여넣습니다. 한 번에 100개까지 등록할 수 있고 이후 추가 등록을 계속할 수 있습니다.
4. 각 채널의 **계정 연결**을 눌러 해당 플랫폼의 공식 로그인 화면에서 조회 권한을 승인합니다. SNS 비밀번호를 회사 프로그램에 입력하지 않습니다.
5. 첫 수집이 완료되면 **대시보드**에서 전체 성장과 처리할 일을 확인합니다. **성과 분석 → 일별 기록**의 날짜를 누르면 콘텐츠별 상세가 열립니다.

일반 직원은 배정된 채널만 조회·연결·수집할 수 있습니다. 관리자는 전체 채널과 직원, 담당자 배정, 플랫폼 연결 설정, 자동 수집 시각을 관리합니다. 여러 직원이 공동 관리하는 채널은 회사 합계에서 한 번만 집계합니다. 직원별 합계를 다시 더하면 공동 관리 채널이 중복될 수 있습니다.

## 조직 관리와 담당 인계

| 역할 | 접근 범위와 업무 |
|---|---|
| 관리자 | 회사 전체, 팀 생성·편집, 직원 초대·팀·역할 배정, 연결 설정 |
| 팀장 | 소속 팀과 직접 배정된 채널 조회·관리, 같은 팀 담당자 배정 |
| 실무자 | 직접 배정된 채널 조회·연결·수집 |
| 조회 전용 | 소속 팀 또는 직접 배정된 채널 조회. 등록·설정·수집 변경 불가 |

관리자가 직원의 팀이나 역할을 변경하면 그 직원의 기존 로그인 세션은 종료됩니다. 다시 로그인해야 새 권한으로 접근합니다. 기존 관리자 계정을 일반 역할로 바꾸거나 직원에게 관리자 권한을 부여하는 기능은 제공하지 않습니다.

채널의 **담당자·이관**에서 담당자·소속 팀·변경 사유를 저장하며 **이력**에서 변경 시점과 이전·새 담당자를 확인합니다. 기존 OAuth 연결 담당자가 새 담당 목록에 없으면, 기존 연결과 기록을 유지한 채 새 담당자의 재연결을 기다립니다. 새 담당자가 같은 계정의 연결·첫 수집을 마치면 담당 변경을 확정합니다. 이관 취소 시 기존 담당과 연결을 유지합니다. 퇴사 계정을 먼저 중지하면 그 사람이 연결한 API 데이터가 해제 정책에 따라 삭제되므로, 기록을 이어갈 채널은 인계를 먼저 완료합니다.

담당자별 실적은 **관측 당시 담당자**를 기준으로 계산합니다. 이 기능을 도입하기 이전의 담당자는 추정하지 않습니다. 담당 변경을 가로지르는 증가분은 새 담당자에게 몰아주지 않으며, 새 담당자의 첫 기록 이후 비교 가능한 기록부터 증가분을 계산합니다. 회사 전체·채널별 집계는 기록을 이어서 보여줍니다. 팀 필터의 채널 범위는 현재 소속 팀 기준입니다.

## 대시보드와 수집 센터

- **대시보드**: 전사·팀·내 담당 선택, 조회·좋아요·팔로워·공유·댓글·저장의 최근 누적과 기간 증감, 플랫폼 요약, 수집 상태와 오늘 확인할 일.
- **성과 분석**: 주·월·분기·직접 기간, 일별 기록, 콘텐츠·채널·담당자별 비교, CSV 저장, 상세 서랍 화면.
- **수집 센터**: 연결 필요, 인증 재연결, 오류·일부 수집, 재시도 예약과 최근 실행 이력.

**빠른 검색** 버튼 또는 **Ctrl/Cmd+K**로 채널과 메뉴를 찾습니다. 그래프의 날짜를 누르면 해당 날짜의 콘텐츠 상세가 열리며, 키보드 방향키로 날짜를 이동하고 Enter로 선택할 수도 있습니다. 대시보드의 지표 화살표는 현재 전사·팀·내 담당 범위의 상세 분석으로 연결합니다. 플랫폼 행을 누르면 해당 플랫폼으로 분석 범위를 좁힙니다.

프런트는 사용자가 지정한 Recent의 인터페이스 사례를 조사해 개편했습니다. 참고 링크와 실제 적용 범위는 [디자인 참고 기록](./DESIGN_REFERENCES.md)에 있습니다. 누적 100만 이상의 큰 숫자는 요약 표기를 사용하며 마우스를 올리거나 상세 분석에서 정확한 값을 확인할 수 있습니다. 화면의 작은 추이선도 실제 관측값만 표시합니다.

일시적인 통신·서버 오류는 5분, 20분, 60분 후 최대 세 번 자동 재시도합니다. 사용량 제한은 보수적으로 24시간 뒤에 재시도합니다. 권한 만료나 계정 불일치는 재연결이 필요하며 반복 요청하지 않습니다. 서버 재시작으로 중단된 수집도 제한된 횟수 안에서 복구합니다. 자동 수집을 끄거나 채널 관리를 중지·연결 해제하면 예약 재시도도 실행되지 않습니다. 이 시간은 실제 서버가 실행 중일 때 적용됩니다.

## 숫자를 읽는 기준

| 화면의 숫자 | 의미 |
|---|---|
| 최근 기록 합계 | 선택 종료일까지 각 콘텐츠·채널에서 마지막으로 확인한 누적값의 합계입니다. 서로 다른 날짜의 마지막 기록이 함께 포함될 수 있습니다. |
| 당일 기록 | 한국 시간 기준 그날 실제로 수집한 값입니다. 같은 날 다시 수집하면 그날의 최신 값으로 갱신됩니다. |
| 전일 대비 | 같은 대상의 오늘 누적값에서 어제 누적값을 뺀 값입니다. 양쪽 날짜에 비교 가능한 기록이 있어야 합니다. |
| 최근 7일·이번 달·이번 분기 | 선택 기간의 시작 전날과 종료일을 비교합니다. 날짜별 누적값을 모두 더하지 않습니다. 직접 기간을 선택할 수도 있습니다. |
| `—` | 아직 수집하지 않았거나, 플랫폼이 제공하지 않거나, 비교 기준이 없는 값입니다. 0이라는 뜻이 아닙니다. |
| 팔로워·구독자 | 콘텐츠별 수치가 아닌 채널별 수치입니다. 여러 채널을 구독한 사람의 중복은 제거하지 않습니다. |
| 도달 합계 | 콘텐츠별 보고값의 합입니다. 여러 콘텐츠를 본 같은 사람을 중복 제거한 회사 전체 고유 도달 수가 아닙니다. |

예를 들어 어제 조회수 200, 오늘 260이면 오늘 증가는 60입니다. 오래된 게시물을 오늘 처음 수집해 조회수 260을 확인했다면, 그 260을 오늘의 증가로 계산하지 않습니다. **첫 관측은 이후 비교를 위한 기준선**이며, 등록 이전 날짜별 성과는 현재 누적값으로 복원하지 않습니다. 기준일 이후 실제로 게시된 새 콘텐츠는 게시 전 0을 기준으로 비교할 수 있습니다.

수집하지 못한 날짜를 임의로 채우지 않습니다. 플랫폼의 집계 정정이나 좋아요 취소 등으로 누적값이 줄어들면 감소도 표시합니다. 비교 대상 수와 미수집 여부를 함께 확인해야 합니다. 조회 기간은 한 번에 최대 366일입니다.

화면의 콘텐츠 조회수 합계는 수집한 콘텐츠만 포함합니다. YouTube의 채널 전체 누적 조회수와는 삭제·비공개 콘텐츠 등의 영향으로 다를 수 있습니다. YouTube Analytics의 공유 수치는 최근 며칠이 늦게 반영될 수 있어 다른 지표와 갱신 시점이 다릅니다.

## 30분마다 팀 하이라이트

대시보드의 **지금, 우리 팀에 반응이 오고 있어요**에서 최근 7일 게시물 중 최대 3개를 소개합니다. 관리자는 전사·팀·내 담당, 직원은 기존 조회 권한 안에서만 확인합니다. 원문 게시물과 관리 담당자, 실제 관측 시각을 함께 보여주며 **왜 주목했나요?**에서 선정 이유를 확인할 수 있습니다. **표현 미리보기**의 이름·제목·수치는 예시로 명시하며 실제 집계에는 저장하지 않습니다.

- 연결된 YouTube·Instagram·Facebook·TikTok 계정의 최근 게시물을 **30분 간격**으로 수집합니다. 서버는 1분마다 실행할 작업을 확인하고 계정별로 순서대로 처리합니다. 실행 중인 수집·요청 제한·인증 문제에 따라 실제 수집 시각은 늦어질 수 있습니다.
- 최근 수집은 최대 **100개 게시물·3개 목록 페이지**, Instagram 개별 인사이트는 최대 **25개 게시물**까지 확인합니다. 상한이나 목록 순서 제약으로 전부 확인하지 못하면 일부 확인으로 표시합니다. 플랫폼이 제공하지 않는 수치는 추정하지 않습니다.
- **반응 가속**: 최신 관측이 90분 안에 있고, 15~90분 간격의 실제 증가량을 30분 기준으로 환산합니다. 같은 채널의 이전 관측 구간 최소 3개의 중앙값보다 1.5배 이상이며 실제 증가·환산 증가 모두 조회수 50회, 좋아요 5개, 댓글·공유·저장 2개 이상인 지표를 고릅니다. 비교는 관측된 콘텐츠를 기준으로 하며 게시 후 경과 시간이나 광고 여부를 통제한 인과 분석은 아닙니다.
- **눈에 띄는 기록**: 비교가 부족해도 조회수 1,000회·좋아요 100개·댓글/공유/저장 10개 이상처럼 확인된 누적 기록을 소개할 수 있습니다. 새로 돌파했거나 반응이 가속했다는 주장은 하지 않습니다.
- 같은 게시물은 중복 노출하지 않고 채널과 담당자가 다양하게 보이도록 선정합니다. 임의 인기 수치·외부 좋아요·댓글·공유를 만들지 않으며 알림은 이 프로그램 안에 표시합니다.
- 일별 집계는 기존 전체 수집 기록을 유지합니다. 30분 관측은 별도로 저장하여 같은 날 여러 관측을 구분하고, 일부 지표를 못 받은 최근 수집이 기존 일별 수치를 지우지 않도록 했습니다. 30분 관측은 최대 8일 보관하며 연결 해제 시 해당 API 기록과 함께 제거합니다.
- 브라우저를 열어 두면 1분마다 최신 선정 결과를 읽습니다. SNS 수집은 서버에서 수행하며 브라우저를 닫아도 서버가 켜져 있으면 계속됩니다. 설정에서 자동 수집을 끄면 일별·30분 자동 수집 모두 중지됩니다.

실계정 연결이 없는 현재 로컬 환경에서는 하이라이트 수집·추천 결과가 아직 없습니다. 실제 운영 검증은 계정 연결 후 연속 관측으로 진행합니다.

## 실제 자동 수집을 켜려면

주소 등록 후 플랫폼이 허용하는 조회 권한을 연결해야 합니다. 관리자가 먼저 개발자 앱을 준비하고, 이후 직원이 자신의 계정을 연결합니다. 필요한 앱·권한·콜백 주소는 [플랫폼 연결 안내](./PLATFORM_SETUP.md)에 정리되어 있습니다.

| 플랫폼 | 현재 연결 기능 | 주요 제한 |
|---|---|---|
| YouTube | 채널 팔로워·조회, 콘텐츠 조회·좋아요·댓글, 소유자 Analytics 권한의 공유 | API 키만 사용하면 공유를 제공하지 않습니다. 구독자는 공개 표시 정책에 따라 반올림될 수 있습니다. |
| Instagram | 프로페셔널 계정의 팔로워, 콘텐츠 조회·좋아요·댓글·공유·저장·도달 | 비즈니스·크리에이터 계정과 인사이트 권한이 필요합니다. 콘텐츠 종류에 따라 일부 수치가 없습니다. |
| Facebook | 관리 페이지의 팔로워, 게시물 좋아요·댓글·공유 | 개인 프로필은 대상이 아닙니다. 현재 조회·저장·도달은 제공하지 않습니다. 게시물 목록에 없는 콘텐츠는 포함되지 않을 수 있습니다. |
| TikTok | 승인한 계정의 팔로워, 공개 영상 조회·좋아요·댓글·공유 | 승인된 앱과 조회 권한이 필요합니다. 저장·도달과 채널 전체 조회수는 제공하지 않습니다. |
| 그 외 지원 주소 | 주소 등록 및 기존 수동 기록 보존 | 자동 수집 연결은 아직 제공하지 않습니다. |

연결한 계정과 등록한 주소가 다르면 다른 계정의 실적을 저장하지 않습니다. 연결 정보 저장만으로 수집 성공을 의미하지 않으므로 채널의 마지막 수집 결과를 확인해야 합니다.

전체 게시물 수집은 기본적으로 매일 한국 시간 오전 9시 이후 실행하며 관리자가 시각을 바꿀 수 있습니다. 서버가 켜져 있어야 실행됩니다. 꺼져 있던 기간의 누적값을 날짜별로 나누어 생성하지는 않습니다. 필요할 때 **새로 수집**으로 현재 값을 다시 확인할 수 있습니다.

일별 전체 수집은 각 채널에서 기본적으로 한 번에 콘텐츠 10,000개 또는 목록 1,000페이지까지 조회합니다. 한도에 도달하거나 일부 수치를 받지 못하면 **일부 수집**과 그 이유를 표시합니다. 이는 채널 주소 등록 개수 제한이 아닙니다. 대규모 채널은 플랫폼 사용량과 수집 시간을 확인해 운영자가 한도를 조정해야 합니다.

## 회사 직원들이 함께 쓰는 운영 방식

운영 서버는 **Google Compute Engine 한 대와 [workspace.synk.im](https://workspace.synk.im) HTTPS 주소**입니다. 공개 서비스가 켜져 있으며 직원은 기존 초대·계정·연결 권한을 거쳐 브라우저로 이용합니다. 직원 계정 연결·실제 로그인은 확인했고 두 기기 인수는 남아 있습니다.

현재 구성은 하나의 Node.js 서버, SQLite 데이터베이스, 서버 내부의 수집 작업으로 이루어져 있습니다. 서버 한 대에서 실행하는 구성이며 여러 서버가 같은 데이터 폴더를 동시에 공유하는 방식으로 늘리지 않습니다. HTTPS는 앞단의 리버스 프록시에서 처리합니다.

### 서버 환경값

| 환경값 | 역할 |
|---|---|
| `SYNK_COMPANY_ORIGIN` | 직원들이 접속할 실제 주소. 예: `https://sns.example.com`. 경로를 덧붙이지 않습니다. |
| `SYNK_COMPANY_HOST` | 기본은 `127.0.0.1`. 컨테이너 내부에서는 `0.0.0.0`을 사용합니다. |
| `SYNK_COMPANY_PORT` | 기본 `4191`. 내부 서버 포트입니다. |
| `SYNK_COMPANY_DATA` | 데이터 저장 폴더. 기본은 이 폴더의 `data`, Docker에서는 `/data`입니다. |
| `MESSENGER_DATA_DIR` | 통합 메신저 데이터 폴더. 준비한 Docker 구성은 `/data/messenger`로 지정해 회사 DB와 같은 영구 볼륨에 보관합니다. 명시적 실행 옵션·기존 통합 설정이 있으면 그 설정이 우선합니다. |

외부에서 접속할 수 있게 실행할 때는 HTTPS 회사 주소를 지정해야 합니다. 리버스 프록시는 요청의 **Host를 회사 주소 그대로 보존**해야 합니다. 브라우저 주소, 서버의 `SYNK_COMPANY_ORIGIN`, 플랫폼에 등록한 OAuth 콜백 주소가 일치해야 로그인·계정 연결이 동작합니다.

### Docker 실행 예시

아래는 새 독립 시험 환경의 일반 예시입니다. 실제 회사 클라우드 이전에는 [고정 릴리스와 Compose/systemd 실행 계약](CLOUD-OPERATIONS.md)을 사용하며 공용 작업본 재빌드나 빈 볼륨으로 대체하지 않습니다. 일반 예시를 실행할 때는 저장소 최상위 `SYNK-appsscript`에서 이미지를 만들고 주소를 바꿉니다.

```sh
docker build -t synk-company-sns -f "docs/마케팅/온라인마케팅지도/engagement/company/Dockerfile" .
docker volume create synk-company-data
docker run -d --name synk-company-sns --restart unless-stopped -p 127.0.0.1:4191:4191 -e SYNK_COMPANY_ORIGIN=https://sns.example.com -v synk-company-data:/data synk-company-sns
```

`/data`는 반드시 영구 볼륨에 연결합니다. 컨테이너를 바꿔도 계정·채널·기록과 암호화 키가 같은 볼륨에 남아 있어야 합니다. 이 예시는 같은 서버의 HTTPS 프록시가 `127.0.0.1:4191`으로 전달하는 구성입니다.

기존 DB의 원래 암호화 키가 없으면 새 키 생성·DB 변경 전에 시작을 거부합니다. 복구 도구는 별도 최신 기준과 두 DB·키·수정/삭제·계정 연결·등록 파일을 대조하지만 도구 통과만으로 최종 최신성이나 공개 접속 승인이 확보되지는 않습니다. 자세한 절차는 [데이터 이전·복구](CLOUD-DATA-MIGRATION.md), 실제 검증 이력은 [릴리스 검증 요약](../../../../_ops/qa/company-cloud-release-20261009/README.md)에 있습니다.

Nginx를 사용하는 경우, 인증서가 설정된 회사 HTTPS 서버 블록의 전달 설정은 다음과 같습니다.

```nginx
location / {
    proxy_pass http://127.0.0.1:4191;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

새 독립 설치의 빈 데이터베이스에만 관리자 설정 링크를 다음 명령으로 만듭니다. 기존 회사 이전은 원래 계정을 복구하며 `SYNK_COMPANY_REQUIRE_EXISTING_DATA=1`을 유지하므로 이 초기 설정을 사용하지 않습니다.

```sh
docker exec synk-company-sns node docs/마케팅/온라인마케팅지도/engagement/company/admin.mjs setup
```

출력된 일회용 링크에서 회사 이름과 관리자 계정을 설정한 다음, 관리자 화면에서 플랫폼 앱을 등록하고 직원을 초대합니다. 서버에 Node.js로 직접 설치한 경우에도 같은 환경값을 지정한 상태에서 `node docs/마케팅/온라인마케팅지도/engagement/company/server.mjs`를 실행하고, 별도 터미널에서 `node docs/마케팅/온라인마케팅지도/engagement/company/admin.mjs setup`을 사용합니다.

로컬 실행기는 이 컴퓨터용 관리자 시작 기능입니다. 공용 서버에서는 위의 초기 설정과 직원별 로그인 절차를 사용합니다.

## 보관·연결 해제·백업

채널의 **관리 중지**는 앞으로의 수집을 멈추는 기능입니다. 기존 기록은 보존하지만 플랫폼 보존 정책에 따른 만료는 계속 적용됩니다. **계정 연결 해제**는 저장된 연결 정보와 해당 채널의 API 수집 데이터를 삭제합니다. 원래 사용자가 직접 입력했거나 기존 기록장에서 가져온 수동 기록은 별도로 보존합니다.

YouTube 공개 API 데이터는 30일 보존 기준을 적용합니다. 소유자 인증 상태에서 계속 수집하면 재확인된 콘텐츠의 기록에 보존 기간을 갱신합니다. 연결이 만료되거나 콘텐츠를 더 이상 확인하지 못하면 오래된 기록이 만료될 수 있습니다. 정책과 API 데이터 사용 범위는 [플랫폼 연결 안내의 기록과 보관](./PLATFORM_SETUP.md#기록과-보관)을 참고합니다.

실제 저장 파일은 데이터 폴더의 `company.sqlite`와 `encryption.key`입니다. 암호화 키가 없으면 저장된 플랫폼 연결 정보를 복구할 수 없습니다. 데이터베이스와 키를 함께 보관하고 접근 가능한 운영자를 제한해야 합니다. 비밀값을 문서나 소스 저장소에 올리지 않습니다.

실행 중인 데이터베이스는 다음 백업 도구로 복사합니다. `SYNK_COMPANY_DATA`는 실제 데이터 폴더와 같아야 합니다. `$env:SYNK_BACKUP_TARGET`에는 원본 밖의 새 백업 대상 절대경로를 먼저 지정합니다.

```powershell
node "docs/마케팅/온라인마케팅지도/engagement/company/backup.mjs" "$env:SYNK_BACKUP_TARGET"
```

위 백업은 **회사 데이터만** 보관합니다. 데이터베이스, 암호화 키와 제작 스튜디오·고객 프로젝트의 시안·최종본·접수 원문 파일(`studio-media/`)을 함께 포함합니다. 메신저까지 옮기거나 복원할 때는 [통합 백업](WORKSPACE.md)의 `workspace-backup.mjs`를 사용합니다. 복구할 때는 서버를 멈춘 후 원래 운영 데이터를 별도 보존하고 세 항목을 데이터 폴더에 함께 복원합니다. 다시 시작한 뒤 관리자 로그인, 채널 목록, 날짜별 기록, 계정 연결과 제작 파일 재생을 확인합니다. 연결 해제로 삭제된 API 데이터가 오래된 백업에서 되살아나지 않도록 백업 보존·폐기에도 삭제 요청을 반영해야 합니다.

기존 개인용 기록장은 [기존 성장 기록장 안내](../README.md)에 남아 있습니다. 회사 프로그램으로 가져오기는 복사이며 원본을 삭제하지 않습니다.

## 구현 파일과 검증

| 파일 | 역할 |
|---|---|
| `public/` | 직원·관리자가 사용하는 화면 |
| `server.mjs` | 로그인, 직원 초대, 담당 채널 권한, 집계와 수집 실행 |
| `store.mjs` | SQLite 저장, 비밀번호 해시, 연결 정보 암호화 |
| `oauth.mjs` | 공식 플랫폼 로그인·토큰 교환과 갱신 |
