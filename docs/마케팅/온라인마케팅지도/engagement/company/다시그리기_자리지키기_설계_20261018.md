# 워크스페이스 다시 그리기 때 보던 자리 지키기 · 설계·구현 · 2026-10-18

유호님 10-18 「이 작업을 여기에서 진행해 주세요: 워크스페이스 전체 다시 그리기 때 스크롤·초점 지키기 검토」 → 조사·설계 → 「A(폴링은 바뀔 때만 다시 그리기)와 B(배경 다시 그리기는 자리 지키기) 모두 설계대로 진행해 줘.」 → 구현했다(맨 아래 「구현」, 커밋 전).

## 한 줄 결론

수집이 도는 동안 **7초마다 화면이 맨 위로 튀고 치던 글의 초점이 빠지던 것**을 멈춘다. 메뉴를 누르거나 다른 화면으로 갈 때는 지금처럼 맨 위로 간다. 두 단계로 한다 — A. 수집 폴링은 바뀐 것이 있을 때만 다시 그린다. B. 폴링·늦게 오는 자료처럼 **배경이라고 표시한 다시 그리기만** 보던 자리(스크롤·초점·쓰던 글)를 지킨다.

## 1. 지금 무슨 일이 생기나(실측)

격리 서버(`verify-workspace-fixture.mjs`, 가짜 계정)와 headless Chrome에서 `<main>`을 600까지 내린 뒤 16초 동안 지켜봤다. 「수집 실행 중」은 `/api/state` 응답에 `running` 실행 하나를 끼워 흉내 냈다(`busyRuns()`가 참이 되어 7초 폴링이 돈다).

| 화면 | 평소 | 수집 실행 중 |
|---|---|---|
| 작업실 · 제작 도구(게시 준비·성과) | 다시 그리기 0, 600 유지 | 첫 폴링(약 4초)에서 600 → 0 |
| SNS · 캠페인·성과 | 0, 600 유지 | 600 → 0 |
| 개요 | 0, 유지 | 426 → 0, 16초에 6번(폴링 2번 × `loadState`·`loadReport` 앞뒤) |
| 작업실 · 데스크 | 0, 유지 | 362 → 0 |

- 휴대폰 폭(390, 터치)도 스크롤 칸은 `<main>`이고(workspace.css:323·348 `overflow:auto`) 똑같이 600 → 0.
- SNS 결과의 검색 칸(「제목·문구·콘텐츠 종류 검색」, `name="query"`뿐)에 「검증」을 친 뒤 폴링이 오면 초점이 BODY로 빠진다.
- 첫 로딩: `loadWorkroom` 끝(`workroom.js:33`)의 늦은 다시 그리기가 깊은 링크의 초점·스크롤을 지웠다(게시 도구는 10-18에 따로 막음, [현장 노트](../../../../현장노트/시험_화면확인.md)).
- 「수집」 단추(app.js:611)를 누르면 실행이 끝날 때까지 폴링 때마다 맨 위로 튄다.
- 원인: `shell()`(app.js:237-270)이 `app.innerHTML`을 통째로 갈아 끼워 `<main id="main">`(workspace.js:41)이 새로 생긴다. 초점은 data 속성 25개 목록(app.js:254)에 있는 칸만 되돌린다.
- 운영에서 수집 실행이 얼마나 자주 `running`·`queued`인지는 재지 않았다. 실행이 있는 동안에는 7초마다 위 일이 생긴다(`pollCollectionState`, app.js:197-203).
- 측정 스크립트는 저장소 뿌리 `.tmp/workspace-repaint-20261018/`(git 무시)에 있다 — 고칠 때 `qa/verify-workspace-repaint.mjs`로 옮긴다.

## 2. 지금 각자 막고 있는 곳

- `shell()` 안: 홈(마린 대화 기록 스크롤·입력 선택), 연습 모듈(`wpCaptureEdit`, 한글 조합 중이면 그 다시 그리기를 버린다 — app.js:240), `details[id]` 열림, data 속성 25개 초점.
- 모듈: 트렌드·레퍼런스(`crRenderPreserving` — 조합 중이면 미뤘다가 끝나면 다시 그림, creative-research.js:79-86·333-334), SNS(#main 저장·복원), 고객 화면(main), 주간 요약·자동화 상태(위치 복원), 게시 도구(부분 갱신·깊은 링크 목표), 고객 데스크(`targetNavigation`).
- 같은 문제를 모듈마다 따로 막고 있고, 수집 폴링의 다시 그리기는 아무도 막지 않는다.
- 참고: `render();window.scrollTo(0,0)` 같은 「맨 위로」 호출 34곳(12파일)은 window만 움직여 `<main>`에는 효과가 없다. 지금 맨 위로 가는 것은 새 `<main>`이 0에서 시작하기 때문이다(`main.scrollTop=0`을 직접 넣는 곳은 company-guide.js:98 하나).

## 3. 규칙(제안)

### A. 수집 폴링은 바뀐 것이 있을 때만 다시 그린다(작은 변경)

- `pollCollectionState`가 `loadState`를 조용히(다시 그리지 않고) 부르고, 실행 상태·수집 요약·채널 상태가 바뀌었을 때만 다시 그린다. 폴링 때는 `loadReport`의 「불러오는 중」 중간 그리기(app.js:183)도 건너뛴다.
- 이것만으로 실행이 도는 동안 7초마다 튀던 대부분이 사라진다. 실행이 끝나거나 숫자가 바뀌는 순간에는 한 번 다시 그린다.

### B. 「배경」 표시가 붙은 다시 그리기만 자리를 지킨다

- **누가 배경인가:** 시간으로 짐작하지 않고, 부르는 쪽이 표시한다. 처음에는 수집 폴링(A에서 남는 다시 그리기), 작업실 일일 폴링(workroom.js:134), 작업실 자료가 늦게 도착한 다시 그리기(workroom.js:33)만 표시한다. 표시 없는 다시 그리기(클릭·키·저장 응답 등)는 지금 그대로다 — 「맨 위로」를 기대하던 곳을 하나씩 찾을 필요가 없다.
- **같은 화면일 때만:** 화면 열쇠(상태에서 만든다 — tab·section·tool·teamId·draftId에 URL에 없는 하위 화면 `pf.view`·`clientDesk.id`·`socialWorkspaceState.editId`)가 다시 그리기 전과 같을 때만 지킨다. 배경 그리기 사이에 사람이 다른 화면으로 옮겼으면 지금처럼 맨 위.
- **지키는 것과 순서:** `innerHTML` → `details` 열기 → `<main>` 스크롤과 id 있는 안쪽 스크롤 칸 → 초점(`preventScroll`) → 그다음 기존 사이드바·메신저·교육 슬롯 처리(교육 슬롯이 위치를 재므로 스크롤이 먼저).
- **초점 칸 찾기:** tag·id·name·data-* 전부로 만든 선택자에 맞는 요소들 중, 다시 그리기 전과 **같은 순번**을 고른다(같은 name이 여러 폼에 되풀이되기 때문).
- **쓰던 글 되돌리기:** 맞는 요소가 하나뿐이고, 글 칸(text·search·url·tel·password·textarea)이고, 폼이 `disabled`·`readonly`·`aria-busy`가 아니고, 다시 그리기 전 화면 값이 새 값과 다를 때만 값과 커서를 되돌린다. 그 밖에는 초점만 되돌린다.
- **한글 조합 중:** 그 칸에서 조합하는 중이면 배경 다시 그리기를 미뤘다가 `compositionend` 뒤 다음 차례(`setTimeout(0)`)에 한 번 그린다 — 트렌드·레퍼런스와 같은 방식. 조합 상태는 칸 단위로 기억하고 칸이 화면에서 떨어지면 버리며, 3초 안에 안 끝나면 그냥 그린다(영영 막히지 않게). 연습 모듈의 「버림」(app.js:240)은 그대로 둔다.

## 4. 영향 범위와 위험

- **바뀌는 것:** 수집이 도는 동안·작업실 자료가 늦게 올 때 맨 위로 튀지 않고, 치던 칸의 초점과 글이 남는다. 「수집」 단추를 누른 뒤 실행이 끝날 때까지 튀던 것도 멈춘다.
- **바뀌지 않는 것:** 클릭·키·제출·저장 응답 뒤 다시 그리기, 화면·하위 화면 이동, 홈 화면, 모달(#overlay, `#app` 밖이고 폴링은 모달이 열려 있으면 건너뜀 — app.js:198), 메신저(iframe).
- **위험 1 — 배경 표시를 붙인 곳이 「맨 위로」를 기대하는 경우:** 처음 표시하는 세 곳(폴링 둘·작업실 늦은 자료)은 맨 위를 기대하지 않는다. 나중에 표시를 늘릴 때는 그 자리마다 확인한다.
- **위험 2 — 값 되돌리기가 서버 값을 덮는 경우:** 배경 다시 그리기가 사람이 초점을 둔 칸의 값을 일부러 바꾸면 사람이 친 글이 이긴다. 폴링이 칸 값을 바꾸는 곳은 찾지 못했다.
- **위험 3 — 모듈 자체 복원과 겹침:** 모듈 복원이 셸 뒤에 돌아 모듈 값이 남는다(트렌드는 기준 항목 위치로 보정, 고객 데스크는 rAF에서 넣음). 결과는 지금과 같다.
- **같이 쓰는 파일:** app.js·workspace.js·workroom.js는 공통 코드다. 고치기 전에 GPT 쪽 커밋 전 변경과 겹치는지 보고, 겹치면 3방향으로 얹는다.

1. A(폴링은 바뀔 때만 다시 그리기)를 할지 — 위험이 작고 효과가 크다.

## 구현(10-18, 통합 브랜치 `5d67040c1`)

- **A(app.js):** `pollCollectionState`가 `loadState({quiet:true})`를 부른다. `/api/state` 답의 JSON이 `state.dataSignature`와 같으면 아무것도 하지 않고, 다르면 적용한 뒤 배경으로 그린다. 바뀌었을 때만 `loadReport({quiet:true})`를 부른다(중간 「불러오는 중」 그리기 생략, 상세 분석의 `loadTeamOverview(false,{quiet:true})`도 같게). 「수집」 단추 1.8초 뒤 재조회도 같은 조용한 방식이다. 옵션은 `arguments[0]`로 받는다 — 기존 시험이 `async function loadState()` 같은 글자로 소스를 잘라 쓰기 때문이다.
- **B(workspace.js `workspaceRepaint*`, app.js `shell()` 훅, workroom.js 33·134행):** `renderBackground()`로 표시한 다시 그리기만 같은 화면 열쇠일 때 `<main>`·id 있는 안쪽 스크롤·초점(같은 선택자 안 순번)·커서를 되돌린다.
- **설계에서 바꾼 점:** 「쓰던 글 되돌리기」를 뺐다. 대신 배경 다시 그리기는 사람이 무언가 하는 중이면 기다렸다가 2초마다 다시 본다. 기다리는 때는 셋이다. ① 화면의 칸에 사람이 친 글(input·change로 기록)이 아직 화면 값과 다를 때. 칸을 벗어나도 같다. ② 마우스·손가락을 누르고 있을 때. ③ 한글을 조합하는 중일 때. 그 사이 다른 그리기가 한 번이라도 있으면 기다림을 푼다.
  - 이유 하나: 실측에서 값을 고친 채 초점이 있던 칸이 교체로 떨어지면 Chrome이 `change`를 보내 SNS 검색이 제출됐다(social-workspace.js:372 `requestSubmit`).
  - 이유 둘: 처음 판의 「칸을 벗어나면 바로 그리기」는 Fable 검수에서 저장 단추를 누르는 동안 화면을 바꿔 친 글이 지워지고 클릭이 사라졌다(P1).

## 팀 현황 후속(10-18, 유호님 「고쳐주고」)

- **원인 둘:** 개요 탭 팀 범위의 「팀 현황」만 폴링 때 맨 위로 갔다.
  - `loadState`가 바뀐 답마다 `resetTeamTrends()`로 그래프 결과를 지웠다. 그래서 배경 그리기가 「불러오고 있어요」 상자만 있는 짧은 화면을 그렸고, 스크롤이 잘렸다.
  - `loadReport`의 팀 경로가 quiet을 넘기지 않았다. 그래서 `loadTeamTrends()`가 로딩 그리기와 끝 그리기를 일반 `render()`로 했다.
- **고침:**
  - `team-trends.js` `resetTeamTrends(keep)`: 그래프가 화면에 있으면 지우지 않고 「오래됨(stale)」만 표시한다. 화면 밖이면 지금처럼 지운다.
  - `team-trends.js` `loadTeamTrends(force,{quiet})`: 같은 그래프를 둔 채 다시 받아 배경으로 바꿔 그린다. 고른 날짜가 새 결과에도 있으면 그대로 둔다. 일반 열기는 지금처럼 로딩부터 그린다.
  - 조용한 새로고침이 실패하면 오류 상자 대신 기존 그래프를 두고, 기간 줄에 「최신 기록을 불러오지 못해 이전 숫자를 보여 주고 있어요 · 다시 불러오기」를 낸다. 다음 폴링이나 일반 열기에서도 다시 받는다. 새로고침 중에 다른 화면으로 가면 「오래됨」을 다시 걸어 돌아올 때 새로 받는다.
  - 날짜 슬라이더: 고른 날짜는 `teamTrends`에 저장되므로 `defaultValue`도 함께 맞춘다. 안 그러면 「사람이 고친 칸」으로 잡혀 배경 그리기가 끝없이 밀린다. 일별 수치 표의 가로 스크롤 영역에는 id를 붙여 안쪽 스크롤도 지킨다.
  - `workspace.js`: 배경 그리기는 `<details>` 열림 상태(선택자+class+순번)를 저장했다가 스크롤보다 먼저 되돌린다. 펼친 「일별 수치」 표가 닫히면 화면이 짧아져 스크롤이 잘리기 때문이다. 같은 이름의 상자는 개수가 그대로일 때만 순번으로 맞춘다(목록이 늘거나 줄면 이웃 상자를 여닫지 않게). 일반 그리기는 그대로다.
  - `app.js`: `loadState`가 `resetTeamTrends(quiet)`를 부르고, `loadReport`가 팀 경로에도 quiet을 넘긴다.
