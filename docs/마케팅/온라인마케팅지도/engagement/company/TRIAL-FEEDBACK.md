# 말 랠리 체험 의견

2026-11-09. 기존 LAB 말 랠리에서 한 판을 마친 뒤, 선택적으로 재미·막힌 점·다시 할 마음을 받는다. WORLD·계정·Atlas 학습 기록에는 연결하지 않는다. 외부 AI에 응답을 보내지 않는다.

## 연결

- 게임: `https://synk.im/try/talk-rally/`. 모집 묶음은 `?trial=<소문자·숫자·하이픈 1~24자>`, 기본 `open`이다. `all`은 결과 필터 전용이다.
- 운영 화면: 회사 앱의 `/trial-feedback/`, 결과 API `GET /api/trial-feedback/summary`. 기존 활성 직원 로그인으로 조회한다. `viewer`는 숫자만, `admin`·`manager`·`member`는 자유 글도 본다.
- 공개 쓰기: `POST /trial-feedback/enroll`, `/event`, `/withdraw`. 허용 출처는 `https://synk.im` 하나이며 JSON 본문 최대 4KiB다. 쿠키·직원 세션을 수집 인증으로 쓰지 않는다. 로그아웃 상태에서도 자신의 무작위 참여 번호로 의견을 내고 철회한다.
- 개발 중 로컬 출처는 `createTrialFeedback({origins})` 또는 `createCompanyApp({trialFeedbackOptions:{origins}})` 주입으로만 허용한다. 운영 환경 변수로 출처를 넓히지 않는다.

## 숫자의 뜻

참여 수는 사람 수가 아니라 이 브라우저의 익명 참여 번호 수다. 참여하지 않은 방문과 WORLD 이용은 수집하지 않으므로 전체 앱 방문→완료 전환율을 내지 않는다. 익명 브라우저가 보낸 기록이며 신원이나 실제 인간 참여를 서버가 증명하지 않는다.

첫 동의 날을 서울 날짜 D로 잡는다. 같은 참여 번호·날짜의 방문은 사건 종류와 무관하게 한 번만 센다. 첫 판의 시작·완료를 의견과 함께 저장하고 이후 판은 `roundId`로 연결한다. 첫 판이 자정을 넘겼더라도 동의 전날 방문을 만들어 내지 않는다. 이전 날짜에 시작만 남은 판과 시작 없이 완료만 도착한 판은 따로 표시한다. 중도 종료와 전송 누락을 추정으로 구분하지 않는다.

다음 날 재방문은 D+1의 기록이며 D+2부터, 일주일 재방문은 D+1~D+7이며 D+8부터 평가한다. 그 전에는 판정 전이다. 자기 보고한 재방문 의향과 실제 기록은 다른 값이다. 정답 비율·도움 사용은 첫 판 안 수행이며 학습 효과가 아니다. 응답하지 않은 질문은 그 질문 분모에 넣지 않는다. 응답이 없으면 비율은 `null`이다.

`qa-`로 시작한 모집 코드는 합성 시험 자료다. 모든 후속 사건도 같은 구분을 물려받는다. 결과의 기본 `data=real`과 `data=synthetic`은 섞이지 않는다. 시험은 임시 DB에서 한다.

후속 사건은 기기 시각 그대로 기록하며, 수신 시각보다 최대 3일 오래되거나 5분 빠른 범위를 허용한다. 동의 직후 시계가 맞춰질 때를 위해 동의 시각보다 최대 5분 이른 값도 허용한다. 범위 밖 시각을 새 날짜로 보정하지 않고 400으로 제외한다. 동의 시각 자체가 서버보다 5분 넘게 빠르면 등록을 받지 않아 서로 다른 날짜 기준이 섞이지 않는다. 이미 저장한 사건의 같은 ID·본문 재시도는 시간이 지나도 중복으로 응답한다. 늦은 전송이 재방문 날짜를 만들어 내지 않는다. 자정을 걸쳐 계속 이용한 경우도 다음 날짜의 이용으로 세며, 기기 시계 차이 때문에 서버 오늘보다 다음 날짜 행이 잠깐 보일 수 있다.

## 저장과 삭제

기존 SQLite 문서 kind `trialParticipants`·`trialEvents`·`trialWithdrawn`만 쓴다. 참여 번호 원문 대신 서비스 범위 HMAC을 저장한다. IP는 메모리 속 속도 제한용 해시로만 쓰고 이 세 kind에 쓰지 않는다. 자유 글은 `credentials`의 `trial-note:<참여 해시>`에 기존 `Store.setSecret/secret/deleteSecret` 암호화로 보관하며 문서에는 존재 여부만 둔다. 번호·해시·원시 사건은 운영 화면에 내보내지 않는다.

행동 수집은 서버가 확정한 동의 시각부터 30일, 운영 DB 의견·사건·자유 글은 90일이다. 기존 회사 유지 루프와 요청 시 `maintain()`이 만료 자료를 함께 지운다. 철회는 자신의 자료·비밀값을 원자적으로 지운다. 지연된 접수를 막는 HMAC 흔적만 90일 남기며 답·사건·모집 코드는 남기지 않는다. 철회 성공 응답은 존재 여부와 관계없이 같다. 기존 회사 백업 정책은 유지하므로 복구용 백업에는 삭제 뒤에도 사본이 남을 수 있다. 백업까지 특정 날짜에 완전 삭제된다고 안내하지 않는다.

## 한도와 운영

분당 접속 주소별 30건·전체 600건, 참여 번호별 하루 60개 사건, 참여 번호 5,000개·사건 1,200,000개다. 한도는 기존 의견을 밀어내지 않고 새 접수에 오류를 반환한다. 알려지지 않은 번호의 철회 흔적은 50,000개에서 추가를 보류하며 기존 참여자의 철회는 계속 처리한다. 집계는 SQLite에서 날짜·판별로 묶어 큰 사건 목록을 JS 메모리에 모두 올리지 않는다.

브라우저 밖 요청의 Origin 위조와 무작위 번호로 반복 등록하는 행위를 이 기능만으로 신원 검증하지는 못한다. 묶음별 건수와 응답을 보고 이상치를 판단한다. 운영자 임의 대량 삭제 기능은 이 판에 없다. 실제 자료의 임의 삭제나 원시 DB 변경을 자동 실행하지 않는다.
