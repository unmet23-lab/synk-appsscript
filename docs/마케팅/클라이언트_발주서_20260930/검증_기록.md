### HtmlService 화면 오류와 @4 실제 접수

- OAuth 복구 뒤 온라인 페이지는 외곽 화면만 표시하고 단계·본문이 비었으며 `SyntaxError: Invalid or unexpected token`이 발생했다. 라이브 inline JS 292행에서 정상 `'https://'` 문자열의 `//')+` 5문자가 사라져 있었다. 로컬 HTML과 당시 원격용 HTML은 동일하고 원본 JS 88,656문자는 구문 검사를 통과했으나, 전달된 라이브 JS는 88,651문자였다. HtmlService 처리 후 원문 손상을 확인한 것이다.
- `receiver/build.cjs`에서 온라인 전용 JS를 UTF-8 base64url로 담고, 짧은 부트스트랩이 원문을 복원해 `script.textContent`로 실행하도록 변경했다. `eval`·외부 스크립트는 쓰지 않고 고객 답변을 실행 코드로 변환하지 않는다. 오프라인 HTML·ZIP은 변경하지 않았다. UTF-8 왕복·구문·실행 순서·URL 보존 회귀시험 4개를 추가했다.
- **같은 배포 ID의 @4 배포 완료** 후 실제 온라인 화면의 6단계 초기화, `https://` 플레이스홀더 보존, 온라인 전송 문구를 확인했다. 이 단계에서는 화면을 직접 확인했고, 최종 원격 소스 대조는 이후 @5에서 수행했다.

## 확인의 한계

- 자동화 브라우저의 URL 정책이 file:// 접근을 차단하므로 로컬 HTML을 직접 여는 경로는 자동화로 검증하지 못함. 동일 빌드의 로컬 HTTP 실행과 자체 포함 구조를 확인함.
- PDF 버튼은 브라우저 인쇄를 호출하며 인쇄용 스타일을 포함함. PDF 저장 대화상자와 출력된 PDF 파일 자체는 검증하지 않음.
- 실제 크몽 전송·등록·게시를 하지 않았음. 30MB·80MB·30개는 프로그램 자체 첨부 제한이고 크몽 제한이 아님.
- 파일 입력 원본은 메모리에만 유지됨. 새로고침·재실행·JSON 불러오기 시 원본을 다시 선택해야 함. 답변과 파일 메타데이터만 현재 브라우저에 임시저장됨.
