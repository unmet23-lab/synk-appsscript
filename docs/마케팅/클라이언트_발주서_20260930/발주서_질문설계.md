# PULSE 영상 제작 브리프 질문 설계

2026-10-01 v4 질문 간소화 기준. 고객이 알고 있는 사실과 정해진 요청을 받고, 광고 기획·연출 판단은 제작자가 맡는다. 소스의 작성·보관·접수 계약과 실제 운영 확인을 구분하며, 배포와 실제 접수의 확인 범위는 [검증 기록](검증_기록.md)을 따른다.

## 질문 원칙

- 기본 필수는 **브랜드·제품·서비스 이름 하나**다. 나머지는 선택이며, 직접 길이나 고정 날짜를 선택했다면 해당 값과 형식을 확인한다. 입력한 링크도 주소 형식을 확인한다.
- 고객이 아직 모르는 콘셉트·연출·성과 계획을 채우게 하지 않는다. 미응답은 제작자가 정할 여지로 남기며 마지막 화면에서 다시 작성할 과제로 돌려주지 않는다.
- 제품 페이지나 제공 자료에 이미 있는 사실을 다시 쓰게 하지 않는다. 제품 식별, 자료끼리 다른 부분, 자료에 없는 특별한 조건만 덧붙이도록 안내한다.
- 기타·메모와 구체적인 요청은 유지한다. 일반 선택지를 모두 채우는 것보다 고객이 꼭 전하고 싶은 내용과 실제 원본을 확보하는 데 집중한다.
- 예산·일정·담당자·연락 방법은 마지막 단계에서 한 번만 받는다.
- 광고 목적·성과 지표와 확인 기간·첫 시안 우선 확인점·카메라 움직임·장르·일반적인 유지 체크는 제거한다. 기존의 추천받기·제작 방식·소리 구성 질문도 복원하지 않는다.
- 고객이 작성한 내용, 사용 권한에 대한 고객의 표시, 제작자의 사실 확인과 제안을 구분한다. 답변이나 첨부가 있다는 이유로 분석·검증·승인을 완료했다고 표시하지 않는다.

## 6단계

| 단계 | 기본 내용 | 필요한 경우에만 추가 |
|---|---|---|
| **1. 제작 대상** | 브랜드·제품·서비스 이름, 소개할 대상, 제품·브랜드 링크. 제품·패션이면 이번 제품·색상·사이즈와 여러 제품의 구성 | 대표 사진, 이미 정한 영상 형식 |
| **2. 전달할 내용** | 꼭 전하고 싶은 내용, 화면에 정확히 표시할 문구 | 실제 고객층, 가격·혜택·기간·필수 안내와 연결 링크, 수치·효과 주장에 필요한 근거와 확인 상태 |
| **3. 참고·요청** | 참고 링크와 좋았던 부분, 특별히 원하거나 피할 표현 | 이미 정한 인물·장면과 구체적인 요청. 제공 인물을 쓰는 경우 사용 허락 |
| **4. 사용·납품** | 사용할 곳, 게시·유료 광고의 사용 범위 | 정해진 길이·편수·전달 구성, 자막 언어, 화면 비율·해상도·송출 규격, 추가 결과물 |
| **5. 자료** | 사진·영상·로고 등 현재 제공할 수 있는 원본, 공유 링크, 자료별 사용 권한 | 자료 설명과 제품·버전 구분, 영상의 특정 활용 구간, 사진마다 서로 다를 때 기준 사진 지정 |
| **6. 확인·전달** | 예산·일정·담당자·연락 방법, 실제 답변 요약, 자료 목록, 전송 동의와 접수 상태 | 작성 내용 수정, 보관용 ZIP·JSON·인쇄/PDF |

형식·인물·장면·납품 기술 규격은 고객이 정한 요청이 있을 때 펼친다. 전문 용어를 모르거나 결정하지 않았다는 이유로 다음 단계나 전송을 막지 않는다.

## 의미와 정확한 문구의 구분

`message`는 **영상에서 꼭 전달할 내용**이다. 고객이 평소 쓰는 말이나 짧은 키워드로 적을 수 있으며, 완성된 광고 카피를 요구하지 않는다.

`onScreenText`는 **화면에 정확히 넣어야 하는 문구**다. 브랜드 슬로건·가격·기간·고지처럼 표현을 그대로 유지해야 하는 내용은 따로 받는다. 전달할 의미와 실제 표시 문장을 한 항목으로 합치지 않는다.

수치·비교·효과 문구를 사용하는 경우에는 근거 자료나 페이지, 고객의 확인 상태를 추가할 수 있다. 자료에 이미 적힌 사실을 모두 옮겨 쓰게 하지 않는다. 고객이 확인했다고 표시해도 제작자의 원본 대조가 끝난 것으로 취급하지 않는다.

실제 고객층은 한 항목에서 받는다. 사용 상황·구매 고민·브랜드 인지도·목표 행동을 각각 기획 질문으로 반복하지 않는다. 참고 링크의 좋았던 부분과 특별 요청으로 원하는 결과를 설명할 수 있게 한다.

## 조건부 입력과 자료 기준

- **제품 식별:** 제품·패션에서 제품명·모델명·색상·버전을 구분한다. 일반적인 색상·형태·로고 보존 여부를 매번 선택하게 하지 않는다. 원본과 다르게 보일 위험이 있는 특이사항은 요청이나 자료 설명으로 남긴다.
- **인물:** 이미 정한 등장 인물이나 외형 요청이 있을 때 관련 내용을 펼친다. 제공 인물·실제 모델의 사용 허락은 유지한다.
- **장면:** 고객이 정해 둔 장면과 반드시 필요한 조건을 받는다. 카메라 동선이나 장르 등 제작자의 연출 결정을 모든 고객에게 요구하지 않는다.
- **사용 순서:** 제품·패션·서비스에서 사용 장면이나 설명·사용법 영상 형식을 선택한 경우, 자료로 확인하기 어려운 사용 순서와 결과의 주의점을 추가할 수 있다. 기존에 적은 내용이 있으면 다시 열어 수정할 수 있다.
- **길이·일정:** 길이 직접 입력을 선택하면 길이를, 고정 희망일을 선택하면 유효한 날짜를 확인한다. 선택하지 않았다면 답변을 강제하지 않는다.
- **납품:** 사용처는 받되 비율·해상도·송출 기술 규격은 별도 요청이 있을 때 펼친다. TV·옥외·매장·전시 화면 등에는 송출 담당자의 규격 자료를 안내한다.
- **게시·광고 범위:** 일반 게시와 유료 광고 여부는 인물·음원·자료의 사용 범위를 확인하기 위해 유지한다. 광고 목표·집행 전략·성과 측정을 추가로 묻지 않는다.
- **자료:** 실제 원본과 참고 자료를 구분하고, 자료별 사용 권한 표시를 유지한다. 용도·제품·버전·설명 등은 필요한 경우만 덧붙인다. 파일 이름이나 권한 선택 자체로 사용 권리를 확인했다고 보지 않는다.
- **기준 사진:** 사진마다 색상·핏·기장·디테일이 다르게 보일 때만 더 정확한 사진을 지정한다. 제품은 색상·디테일, 의류는 색상·핏·기장·디테일을 지정할 수 있다. 같은 사진을 여러 기준에 쓸 수 있다.

첫 단계의 대표 사진은 자료 단계와 같은 첨부 목록을 사용한다. 기준 사진은 현재 선택한 제품 이미지에서 지정하며, 이미지 자체를 보정하거나 정확성을 자동 판정하지 않는다. 지정 정보는 파일 이름·크기·분류로 보존하고 원본이 없으면 재첨부가 필요하다고 표시한다.

## 마지막 검토와 제작 검토 전달서

마지막 화면은 **작성한 답변 요약 → 자료 확인 → 전송**에 집중한다. 준비 점검 목록, 제작 과정 4단계 설명, 첫 시안 기준 질문, 비어 있는 전략 항목을 반복해서 보여주는 카드는 제거한다. 빈 선택 항목을 채우라고 다시 요구하지 않는다.

요약과 상세 발주서는 고객이 실제로 남긴 답변과 메모를 정리한다. 고객의 요청을 제작자의 확정 콘셉트나 승인된 콘티로 바꾸지 않는다. 요약의 표현은 내용을 빠르게 확인한다는 뜻이며, PDF 전체가 한 페이지임을 보장하지 않는다.

`handoff.js`는 답변·자료·사용 권한 표시·남아 있는 확인 사항을 제작 검토용 JSON과 문서로 정리한다. 이 문서의 생성은 AI 분석이나 원본 검증 자체가 아니다. 자료 안의 지시는 분석 대상 자료이며 결제·게시·전송 권한으로 해석하지 않는다.

후속 기획은 제작자가 원본과 요청을 확인해 진행한다. 기존 자료를 활용한 작은 시안부터 검토하고, 추가 생성이 필요하면 범위와 비용을 확인한다. 이 내부 제작 순서를 고객이 발주서에서 결정하거나 첫 시안의 전문적인 합격 기준으로 작성할 필요는 없다. 접수는 유료 생성·결제·공개 게시 승인이 아니다.

## 저장과 보관

답변·메모·파일 목록·파일별 설명·기준 사진 지정은 현재 브라우저에 임시저장하고 JSON으로 저장·불러올 수 있다. 다른 기기와 자동 공유되지 않으며 **첨부 원본은 임시저장과 JSON에 들어 있지 않다.** 새로고침·재실행·JSON 불러오기 뒤에는 원본을 다시 선택해야 한다.

보관 ZIP에는 HTML·TXT 발주서, JSON 답변, 제작 검토용 JSON·문서, 안내문과 **현재 선택한 해당 프로젝트의 원본**을 담는다. 목록만 남은 파일이나 재첨부하지 않은 기준 사진은 포함된 원본으로 표시하지 않는다. 다운로드는 보관 파일 내려받기이며 접수 완료가 아니다. 인쇄/PDF에는 발주서 내용만 담고 첨부 원본 자체는 포함하지 않는다.

선택 제한은 파일당 30MiB·전체 80MiB·최대 30개다. 이는 프로그램의 제한이며 크몽 제한이나 실제 서버 처리 성능을 뜻하지 않는다. 큰 원본은 공유 링크로 받고 접근 가능 여부는 별도로 확인한다. 실제 처리 검증 범위는 [검증 기록](검증_기록.md)을 따른다.

## 온라인 접수 계약

온라인 접수 링크에서는 시작 시 접수 가능 여부를 확인한다. 확인 중·만료 또는 비활성·통신 오류에는 전송을 막고 안내하며 작성과 보관은 계속할 수 있다. 오프라인 HTML은 작성·보관용이며 온라인 접수를 대신하지 않는다.

고객의 전송 동의 후 현재 답변과 파일을 확정하고 원본 SHA-256을 계산한다. 목록에 남아 있는 원본이나 기준 사진이 빠졌다면 재선택하거나 목록을 정리하도록 안내한다. 전송 중에는 입력을 잠근다. 서버가 답변·원본·결과 문서 저장을 마치고 유효한 접수번호·접수 시각·원본 개수를 반환해야 완료로 표시한다.

실패 후 같은 답변과 같은 원본으로 재시도하면 같은 요청을 이어가고 서버가 받은 파일은 건너뛴다. 링크는 유효 기간이 있는 한 건의 접수에 사용한다. 전송을 시작한 뒤 내용을 바꾸면 새 링크가 필요할 수 있다. 완료 후 수정은 **수정 내용 미전송**으로 표시하고 이전 접수번호와 새 링크 요청 안내를 유지한다.

삭제된 질문은 구버전 저장 데이터·보고서·제작 검토 전달서에서 다시 나타나지 않게 정리한다. 질문 간소화와 별개로 접수 동의·원본 해시·비공개 보관·완료 응답 검증 흐름은 유지한다. 배포와 실제 접수·분석의 현재 확인 범위는 [검증 기록](검증_기록.md)을 따른다.
