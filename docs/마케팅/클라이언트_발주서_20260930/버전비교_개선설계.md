# PULSE 발주서 버전 비교와 개선 설계

> 2026-10-01 v3 비교·설계 이력이다. 이후 v4에서 목적·전략·준비 점검 질문을 더 줄였으므로 현재 질문·접수 계약은 [발주서 질문설계](발주서_질문설계.md)를 따른다. 아래 비교표와 제작 단계는 당시 판단 근거로 보존하며 삭제한 질문을 복원하는 지시가 아니다. 배포·실제 접수 결과는 [검증 기록](검증_기록.md)에서 확인한다.

## 이전 버전과 재구성 버전의 비교

| 관점 | 이전 버전 | 고객 중심 재구성 버전 | 이번 통합 결정 |
|---|---|---|---|
| 처음 시작하기 | 형식·모델·장면 카드로 바로 고를 수 있다. 고객이 선택할 수 있는 범위가 눈에 보인다. | 이름과 목적부터 묻고 작성 부담을 덜어주는 설명이 있다. | 이름·목적과 간단한 카드 선택을 앞에 두고, 자료·링크가 있으면 먼저 활용한다. |
| 고객과 제품 이해 | 제작할 영상의 모습은 알 수 있지만 고객이 구매할 이유와 망설임은 부족하다. | 사용 상황·구매 장벽·차별점·근거·메시지·행동이 연결된다. | 전략 정보를 유지하되 고객에게 기획 문장 작성을 강요하지 않는다. 짧은 답변과 실제 자료로 시작한다. |
| 작성 부담 | 구체적 선택 중심이라 답을 고르기 쉽다. 전문 제작 선택까지 물으면 피로가 생긴다. | 첫 두 단계에서 여러 자유 입력이 기본 노출되고 상세 화면이 길어진다. | 기본 질문과 상세 정보를 나누고, 정하지 않은 내용을 허용한다. 부족한 것만 후속 질문으로 받는다. |
| 필요한 결과물 | 형식·길이·채널·편수 등 제작 요청을 받기 쉽다. | 일부 형식·규격이 접혀 있어 핵심 조건을 뒤늦게 확인할 수 있다. | 용도와 핵심 결과물을 먼저 파악하고 세부 규격은 조건부로 연다. |
| 실사풍 표현의 정확성 | 제품과 인물 원본을 받을 수 있다. 어느 사진을 기준으로 삼을지는 모호하다. | 색상·핏·기장·디테일 기준과 장면 중요도를 지정한다. | 기준 사진을 유지하고 개별 파일의 용도·최종본 여부, 변경하면 안 되는 요소를 함께 연결한다. |
| 신뢰할 수 있는 문구 | 자유 입력·자료에서 주장과 근거를 따로 찾는다. | 강점과 근거를 묻지만 특정 문구와 첨부가 직접 연결되지는 않는다. | 알릴 장점마다 고객 설명과 근거 자료를 연결한다. 확인된 사실과 제안을 구분한다. |
| 결과를 확인하는 만족감 | 자세한 발주서와 첨부 파일을 받을 수 있다. | 고객 → 궁금증 → 메시지 → 근거 → 행동의 핵심 요약을 볼 수 있다. | 핵심 요약과 상세 답변을 모두 유지한다. 자료 준비 상태와 다음에 확인할 일을 함께 보여준다. |
| 저장과 전달 | 기기 임시저장과 ZIP 수동 전달이다. | 같은 방식이며 기준 사진과 새 답변도 보존한다. | v3에는 전용 링크 확인·동의·답변과 원본 전송·서버 접수 확인 소스를 구현했다. 오프라인은 ZIP 보관을 유지한다. 실제 배포·Drive 수신·운영 여부는 검증 기록을 따른다. |

두 기존 버전 모두 브라우저에 답변과 파일 목록을 저장하고 ZIP을 직접 전달하는 구조다. 현재 v3는 이 보관 경로에 온라인 접수 소스를 더했다. 핵심 요약과 제작 검토 전달서는 입력 답변·자료 목록을 정리한 것이며, 사진·상품 페이지를 해석한 AI 분석 결과가 아니다. 문구·사용 권한에 고객이 확인했다고 표시해도 제작자의 검증 완료로 바꾸지 않는다.

## 고객이 답하기 쉬운 순서

1. **어떤 광고가 필요한지 빠르게 고르기:** 이름·목적·광고할 대상과 핵심 결과물부터 파악한다. 제품 링크나 대표 자료가 있으면 함께 받는다.
2. **정확히 지킬 사실 확인하기:** 제품·색상·버전, 유지할 외형, 실제 자료와 분위기 참고를 구분한다.
3. **고객에게 전할 이유 정리하기:** 고객의 궁금증과 장점, 이를 보여줄 근거를 짧게 받는다. 표현이 어려우면 미정으로 남긴다.
4. **느낌과 꼭 필요한 장면 고르기:** 기존 카드 선택과 장면별 중요도를 유지한다. 전문 촬영·생성 방식·소리 결정은 제작자가 맡는다.
5. **자료 준비 상태를 확인하기:** 현재 첨부된 자료, 나중에 받을 자료, 첫 시안 전에 필요한 자료를 구분한다.
6. **정리된 방향을 확인하고 전달하기:** 핵심 요약·상세 답변을 수정할 수 있게 하고 실제 전달 경로와 다음 단계를 안내한다.

예산과 희망 일정은 고객이 정한 범위에서 받는다. 필수 답변을 무조건 늘리기보다 지금 단계의 진행에 영향을 주는 정보부터 확인한다. 정지 이미지로 방향을 볼 수 있는 단계에서 최종 영상에 필요한 모든 규격과 자료를 요구하지 않는다.

## 실사풍 광고 자료를 조건부로 받는 원칙

### 대상에 맞는 사실

| 광고 대상 | 필요한 기준 정보 | 자료로 확인할 내용 |
|---|---|---|
| 제품 | 정확한 제품·버전·색상·크기·구성, 실제 사용 방식 | 정면·후면·측면, 라벨·로고, 질감·상세, 사용 순서 |
| 의류·패션 | 제품·색상·사이즈, 소재, 착장 조합, 유지할 핏·기장 | 앞·뒤·디테일, 정면 착장, 실제 색상 기준, 옷의 구조 |
| 공간 | 실제 위치와 배치, 소개할 구역, 달라지면 안 되는 모습 | 전체와 구역별 사진, 현장 특징, 사용 가능한 장면 |
| 서비스·앱 | 실제 기능, 화면과 사용 순서, 안내할 혜택 | 화면 캡처·시연 자료, 검토된 기능 설명 |
| 회사·브랜드 | 브랜드가 말하고자 하는 내용, 승인된 비주얼·문구 | 로고·색·서체 가이드, 소개 자료, 기존 캠페인 |

고객에게 모든 업종의 질문을 보여주지 않는다. 선택한 대상에 필요한 설명과 예시만 바꾼다. 입력과 자료에서 알 수 없는 사실을 AI가 채워서 확정하지 않는다.

### 파일 하나마다 구분할 것

- **역할:** 실제 상품 기준, 유지할 인물, 분위기 참고, 최종 로고, 기존 영상 등
- **연결 대상:** 어떤 상품·색상·장면을 위한 파일인지
- **상태:** 최종본인지 임시 자료인지, 나중에 바뀔 예정인지
- **유지 기준:** 반드시 같아야 할 부분과 바꿔도 되는 부분
- **사용 가능 범위:** 고객이 제공할 수 있는 원본과 인물 사용 허락 상태

자료를 많이 받는 것보다 제작할 대상과 자료의 관계가 분명한 것이 중요하다. 참고 사진을 실제 상품의 구조·라벨·인물로 오인하지 않도록 역할을 분리한다. 파일 설명은 필요할 때 펼치는 구조로 두고 업로드 동작을 방해하지 않는다.

### 장점과 근거

“구김이 적다”, “조작이 쉽다”처럼 광고에서 말할 장점과 이를 보여줄 자료를 함께 묶는다. 고객이 적은 내용, 원본에서 관찰한 내용, 제작자가 제안한 표현은 구별한다. 자료가 없는 주장에는 확인이 필요하다는 상태를 남기고 입증된 사실로 승격하지 않는다.

## 비용을 아끼면서 발전시키는 제작 순서

낮은 비용은 화면 해상도를 무조건 줄이는 것보다, 비싼 생성 전에 중요한 오류를 빨리 확인해서 얻는다. 현재 자료와 제작 도구의 실제 비용에 따라 첫 시안의 범위를 정하며, 아래 순서를 기본으로 한다.

| 단계 | 고객이 확인하는 것 | 다음 단계로 넘기기 전에 확인할 것 |
|---|---|---|
| **1. 접수 내용·자료 확인** | 받은 답변, 자료 목록, 빠진 기준 | 실제 제품·인물·참고 자료의 구분과 필요한 추가 질문 |
| **2. 글 콘티·원본 활용 시안** | 기존 사진·영상으로 어떤 이야기를 어떤 순서로 보여줄지 | 추가 생성 없이 확인할 수 있는 범위, 고객에게 전달할 이유, 꼭 필요한 장면, 사실과 제안의 구분 |
| **3. 필요한 대표 정지 이미지** | 제품 정확성, 인물 인상, 분위기, 구도 | 기존 자료로 부족한지, 새 생성이 필요하다면 현재 비용·범위와 제품·색·라벨·핏 유지 기준 |
| **4. 필요한 짧은 움직임 시안** | 동작과 장면의 자연스러움 | 기존 영상의 재사용 가능 구간, 승인한 이미지와 일관성, 움직임에서 생긴 문제 |
| **5. 장면 확장·편집·최종 확인** | 전체 흐름과 납품 결과물 | 사용 채널의 규격, 문구, 장면 연결과 최종 수정 |

고객이 사진·방향을 승인하기 전에 긴 영상부터 반복 제작하지 않는다. 단계별 비용·진행 범위는 실제 견적과 승인된 한도로 관리한다. 특정 도구가 항상 최저가라고 표시하거나 예상 비용을 확정 금액처럼 보여주지 않는다.

현재 전달서는 기존 자료 재사용을 우선하고 분석 대기로 생성한다. 유료 자동 생성은 꺼져 있으며 승인된 사용 한도는 미설정이다. 추가 생성 없는 시안도 전체 제작이 무료라는 뜻은 아니다. 접수·자료 동의는 유료 생성·결제·게시 승인으로 확대하지 않는다.

## 화면에서 상태를 설명하는 기준

- 준비 확인 카드는 **무엇이 있고 무엇을 더 받아야 하는지** 설명한다. 임의 점수나 ‘완벽한 브리프’ 등급을 만들지 않는다.
- 준비 확인 화면은 다음 확인 항목을 최대 3개 먼저 보여주고, 전체 미정·누락 목록은 제작 검토 전달서에 남긴다. 답변이 채워졌다는 표시와 실제 내용 검토를 구분한다.
- 온라인 소스는 시작할 때 접수 링크를 확인한다. 확인 중·만료 또는 비활성·통신 오류이면 전송을 막고 재확인·새 링크·파일 보관을 안내한다. 접수 가능 상태에서 목적과 대상 자료를 설명하고 고객의 전송 동의를 받는다.
- 오프라인 파일형 도구에서는 ‘접수하기’처럼 오해할 버튼을 표시하지 않고 ZIP 보관을 안내한다.
- 전송 진행, 서버 접수, AI 분석, 시안 제작, 고객 확인은 서로 다른 상태다. 전송 성공만으로 AI 분석·시안 제작이 끝났다고 표시하지 않는다.
- 서버의 유효한 접수 확인 전에는 완료로 표시하지 않는다. 같은 답변·원본의 실패 재시도는 이어서 전송하고, 완료 후 수정한 답변은 미전송으로 표시해 이전 접수번호와 새 링크 요청 안내를 유지한다.
- 업로드 실패나 추가 자료 필요 상태에서도 작성 내용과 보관 경로를 보존한다. 원본은 기기 임시저장·JSON에 담지 않으므로 다시 열 때 재선택해야 한다.
- ‘한 장 요약’은 핵심 방향 다섯 항목의 요약이다. 상세 발주서와 PDF 전체가 한 페이지라는 뜻이 아니다.

비공개 Google Drive 접수함에 답변·원본·제작 검토 전달서를 저장하고 접수번호를 반환하는 소스는 구현돼 있다. 별도 Apps Script 프로젝트 생성은 원격 소스 반영·인증·배포·실제 Drive 수신 완료와 다르다. 실운영 여부와 용량·수신·복구의 확인 범위는 [검증 기록](검증_기록.md)을 따른다.

현재 제작 검토 전달서의 상태는 분석 대기이며, 검증한 사실·AI 제안·시안 결과를 만들어낸 것으로 표시하지 않는다. 실제 AI 분석 실행, 외부 제작 도구 연결, 비용 확인과 승인 후 시안 제작은 별도의 후속 작업이다. 이 문서는 접수나 제작의 운영 증거를 대신하지 않는다.
