## 2. v8 움직임 규칙 — [모션조사](모션조사_20261020.md)대로(코드 `remotion/src/v8/`)

조사에서 많이 본 영상 네 편(Notion 3.0 1,575만 · Cursor 2.0 946만 · Linear Diffs · Varun Mayya 쇼츠 39만)과 실무자 평(r/MotionDesign 「If every word moves, none of the words feel important」, Emil Kowalski)은 같은 결론이었다: **글자는 조용히 두고, 움직임은 화면 속 실제 동작과 카메라가 맡는다.** v7c(글자마다 팝)도, 그 전 판(마스크 등장만, 화면은 멈춤)도 이 반대였다.

| 규칙 | v8에서 한 것 |
|---|---|
| 글자 등장 | 머리글은 **줄 단위**로만: 마스크 안 y +28px → 0, 불투명도 0 → 1, 10프레임, `cubic-bezier(0.23,1,0.32,1)`, 둘째 줄 3프레임 늦게. 말보다 2~3프레임 먼저. 다음 머리글로는 컷, 끝에서만 7프레임 불투명도(`Type.tsx`) |
| 강조 | 한 벌에 낱말 하나, **처음부터 버터로 칠한 채** 들어온다(쓸기·밑줄·튐 없음). 판 안에서는 지금 말하는 자리 하나에만 버터 테두리(2.5px)+옅은 바탕이 6프레임에 켜지고 다음 자리로 옮겨 간다 |
| 전환 | 판(창) 자리는 한 편 내내 같고 **내용은 컷**으로 바뀐다(15장면, 1.4~4초마다). 크로스페이드 없음. 끝 카드만 8프레임 검정 페이드 |
| 카메라 | 판 전체(테두리째)가 장면 내내 1.00 → 1.035로 거의 일정하게 밀리고, 누를 때 +0.015. 판 안 줌은 **입력하는 두 곳**(「올려」 1.32배, 「이어서 해」 1.4배)만, 글 첫머리가 잘리지 않게 왼쪽·아래 끝에 붙여서. 첫 렌더에서 1.5~1.7배 줌이 글 왼쪽을 잘라(「된 작업」, 「ilds」) 판 안 줌을 이렇게 줄였다 |
| 실제 동작 | 「올려」·「이어서 해」를 한글 조합 그대로 친다(ㅇ→오→올→올ㄹ→올려), 보내면 오늘 칸이 하나씩 찬다 / 세션이 다시 돈다. 커서가 다섯 번 누른다(월요일 스캔 작업, 후보 둘, 14:00 작업, 책갈피). 체크리스트는 말에 맞춰 한 줄씩 체크 |
| 소리 | 컷은 배경음 박이 맡는다. 효과음은 누름·입력·보냄·체크에만, 「휙」은 큰 카메라 이동 넷에만 아주 작게(0.1) |
| 뺀 것 | 낱말 팝·흐림 등장·튕김·형광펜·숫자 세기·장식 칩·펄스·크로스페이드·장면마다 휙 소리 |

## 3. 확인

- 원본 크기 정지 화면을 두 번 뽑아(49장 → 고친 뒤 18장) 직접 봤다. 첫 번째에서 판 안 줌이 글 왼쪽을 자르고 입력한 글이 화면 밖에 있는 것, 끝 카드가 비어 나오는 것(Sequence 안 프레임)을 찾아 고쳤다.
- `tools/정지구간.js`: 첫 렌더 38%(가장 긴 3.5초) → 판 전체 밀기를 프레임마다 0.07%로, 체크리스트를 같은 판 컷으로 나누고, 어두운 예약 큐 판을 밝은 판으로(어두운 판은 검정 무대와 테두리가 붙어 밀어도 변화가 안 잡혔다) → **4%(끝 화면만) 통과**. 0.5초마다 88장을 네 번 넘겨 봤다.
- Fable 최종본 검수([완성본검수_v8_fable](완성본검수_v8_fable_20261020.md)): **「작은 수정 뒤 게시」, P0 없음**. 반영한 것:
  - P1: 후보 고르기 클릭이 한 줄 위(머리줄 높이 누락) → 2행·6행 가운데
  - P1: 틱톡·rednote 캡처가 흰 판 가운데 작게 뜸 → 웹 페이지처럼 왼쪽 위에 붙여 크게
  - P2: 「올ㄹ」 상태가 뒤 커서와 붙어 「올리」로 읽힘 → 그 상태 뺌
  - P2: 출처 줄 한글이 고정폭이라 띄어쓰기가 벌어짐 → 산세리프
- 다음 편으로 미룬 Fable P2:
  - 「4일 치」 판 강조가 겹침(채움 상자 + 점선 + 점) → 하나만
  - 긴 장면 판 배율이 1.07까지 가서 여백이 32px까지 줄어듦
  - 줌이 들어갈 때 판 머리줄 글자가 반 잘림
  - 인스타 캡처 왼쪽 가장자리의 반 잘린 칩
