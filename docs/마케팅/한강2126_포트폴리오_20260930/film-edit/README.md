# SYNK 2126 · 실제 생성 영상 편집 준비

HyperFrames **0.8.96**으로 만든 독립 편집 프로젝트다. 이번 산출물은 편집 구성과 로컬 자산 연결 준비이며, 완성 영상이나 렌더 결과가 아니다.

**현재 상태: 중단.** 사용자가 2.5 LAB 파일럿의 속도·재미·품질·AI 티를 이유로 거절했다. `edit-manifest.json`의 `editorialHold`와 LAB의 `qa: rejected-by-user`를 유지한다. 기존 방향 전체를 최종 조립하지 않으며, 새 시네마틱 파일럿의 방향을 정한 뒤 이 편집 구성을 재검토한다. 거절된 LAB은 보존만 하고 타임라인 재생에서 제외했다.

## 편집 순서

| 구간 | 시작–끝 | 파일 길이 | 장면 |
|---|---:|---:|---|
| opening | 0–10초 | 10초 | VR 레이싱·사고·진입 |
| pulse | 10–22초 | 12초 | PULSE |
| shift | 22–34초 | 12초 | SHIFT |
| river | 34–48초 | 14초 | 유람선·아기 수달·3층 접근 |
| lab | 48–58초 | 10초 | LAB+PATH·배우 반응으로 끝 |

- 출력 잠정값: **1080×1920, 24fps, 58초**.
- `edit-manifest.json`이 소스 경로·순서·시작·길이·source in을 정한다. 구간을 자를 때 `mediaStart`와 `duration`을 수정하고, 뒤 구간 `start`와 `totalDuration`도 함께 맞춘다.
- 전환은 hard cut이다. 재생 속도는 1배이며, 추가 시각 효과·끝카드는 없다.
- 각 원본의 소리는 동일한 source in과 길이로 별도 오디오 트랙에 연결한다. 아직 전체 듣기·음량·음악 연속성 검토는 하지 않았다.

## 자산 연결

`npm run sync`는 manifest가 지정한 상위 `video/`의 실제 파일을 확인하고 `assets/video/`에 로컬 복사한다. 원본은 수정하지 않는다. ffprobe로 해상도·재생 길이·오디오 유무를 읽고 다음 파일을 갱신한다.

- `edit-status.json`: 파일 도착, 오류, 실제 길이와 코덱. `renderReady`는 파일/범위 준비만 의미하며 창작 품질 승인과 다르다.
- `index.html`: 58초의 순서와 별도 원본 오디오 트랙.
- `compositions/*.html`: 실제 MP4를 담는 다섯 장면.

미도착 소스 구간은 **비어 있는 검은 준비 슬롯**이다. 검은 화면은 의도된 영상 장면이나 최종 결과가 아니다. 가짜 MP4·정지 이미지·2.0 대체본을 넣지 않는다.

```powershell
npm run sync
npm run adopt
npm run check
```

`adopt`는 이미 복사된 로컬 자산을 `.media/` 목록에 등록한다. 외부 미디어 검색·유료 생성은 하지 않는다.

## 이어서 할 일

1. 생성 결과 네 파일을 manifest의 경로에 저장한 후 `sync`와 `adopt`를 실행한다.
2. 주 작업자가 실제 영상 재생·소리·장면 접합을 검토하고 trim 값을 확정한다.
3. `check` 통과 후 주 작업자의 렌더 지시를 따른다. 사용자에게 새 렌더 승인을 요청할 필요는 없다.

`npm run render`는 `prerender`에서 누락·길이 오류·현재 편집 중단 상태를 확인한다. 중단 사유를 주 작업자가 해결하기 전에는 렌더를 진행하지 않는다. 이 준비 작업에서는 렌더 명령을 실행하지 않았다.

중단 시점 확인 범위: init 성공, sync 스크립트 문법·실행 확인, 실제 LAB 파일 ffprobe 확인. 전체 HyperFrames `check`, media-use adopt, 재생·청취, MP4 렌더는 시행하지 않았다.

소스를 바꾸거나 trim을 수정할 때 HTML을 직접 고치지 말고 manifest를 수정한 뒤 `sync`한다. 생성된 HTML을 직접 고치면 다음 sync에서 덮어쓴다.
