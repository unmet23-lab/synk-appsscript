2026-10-09 작성. **사용자에게 공개·발송 범위를 보여 주기 위한 미승인 검수안이다.** 이 문서 작성은 게시·보관 해제·공유·댓글·DM 또는 승인 기록이 아니다. 구현의 로컬 시험과 운영 실수신 결과를 구분한다.

사용자 요청에 따른 운영 기능 점검이다. 마케팅 효능·매력·성과를 홍보하는 콘텐츠가 아니므로 기존 SNS 키트 카드 A/B를 재사용한다. 새 이미지나 새 게시물을 만들지 않는다. 이미 보관된 게시물을 다시 보이게 하는 조작도 공개 범위 변경이므로 사용자 승인 범위에 포함해야 한다.

## 승인받을 작업 범위

- 기존 시험 게시물 A/B 두 개의 보관 해제와 종료 후 재보관. 기존 게시물 본문·이미지는 그대로 둔다.
- unmet23 자료함의 새 A PDF·B TXT 배포 사본 두 개만 링크 열람 가능하게 하고, 원본·폴더·등록본은 비공개 유지. 종료 후 두 사본의 공개 공유를 해제하고 보관한다.
- 새 A/B 캠페인 두 개를 등록·활성화하고 시험 종료 시 OFF. 운영 기한은 승인 시 정한 짧은 고정 기한으로 기록한다. 상시 운용으로 몰래 전환하지 않는다.
- @1101yuh로 A·B·기존 릴스에 공개 댓글 각 1개, 합계 최대 3개. 이에 대한 자동 공개 답글 최대 3개. 승인 범위에 포함된 이번 댓글·답글만 시험 후 삭제한다. 기존 댓글·안내·다른 사용자의 댓글은 유지한다.
- @1101yuh에 자동 DM 예상 13통, 절대 추가 진행 상한 15통. 각 단계에서 실제 건수를 확인하고 15통에 도달하면 더 이상 입력하지 않는다. 이 숫자는 시험 진행의 한도이며 도구 자체에 15통 하드 제한이 생겼다는 뜻이 아니다.
- 아래의 검증된 본인 공통 억제 3개만 잠깐 해제하고 정확히 복원한다. 다른 수신자·과거 발송·옛 세션·unknown 상태는 변경하지 않는다.

D0003는 기존 프로그램·자료 코드·게시물 연결을 보존한다. 최종 운영 제안은 기존 11월 7일 기한을 명시적 상시 자료로 전환하고, 위 공개 답글과 [운영 FAQ](FAQ_매뉴얼.json)를 켜 두는 것이다. 이는 시험 후에도 새 요청에 적용되는 별도 공개 자동응답 승인 범위다. 시험만 승인하면 시험에 필요한 동안만 적용하고 원래 상태로 복구한다. 공개 답글을 켜기 전에 D0003의 기존 댓글을 일괄 회수하지 않으며 이번 새 댓글의 처리만 시험한다.

## 사전 상태와 복원 조건

시험 직전 읽기 조회로 원래 D0003 설정, 계정 기능·발송 한도, 기존 발송·세션·미처리 건수와 A/B 옛 캠페인 OFF 상태를 보관한다. 기존 @1101yuh 기록에서 `sender`, `commenter`, `username`에 해당하는 공통 억제가 정확히 한 개씩, 총 3개인지 확인한다. 원본 식별값과 해시는 ignored 비공개 기록에만 저장하고 이 문서·공유 결과에 쓰지 않는다.

억제 해제는 저장한 정확한 계정·종류·값 3개와 현재 값이 일치할 때만 한 트랜잭션으로 수행한다. 새 시험 세션이 이미 있거나 값이 다르거나 3개가 아니면 실행하지 않는다. 기존 `source` 억제, 옛 세션의 중단 표시, 기존 완료·unknown 발송은 그대로 둔다. 종료할 때는 같은 3개의 원래 억제를 복원하며 기존 행의 시각·상태를 임의로 새로 쓰지 않는다.

기존 A/B 공개 댓글에는 옛 키워드 `자료시험1008`이 있다. 새 캠페인은 `자료시험1009`만 받는다. 게시 완료 후 자동 등록·최근 댓글 확인을 검증하려면 사용자 승인 뒤 새 A/B 댓글을 정확히 한 번씩 단 다음 등록 명령을 실행한다. 미등록 기간의 댓글은 최근 댓글 확인에서 회수해야 하며, 기존 키워드 댓글은 대상에 넣지 않는다. 정상 웹훅과 최근 댓글 확인이 겹쳐도 첫 안내·공개 답글을 추가로 보내지 않아야 한다.

## 종료와 완료 증거

1. 정확한 새 A/B 캠페인 두 개를 먼저 OFF로 확정해 새 요청을 막는다. 이미 sending이거나 예상 밖 행이 있어도 OFF가 정리 오류로 롤백되지 않게 한다.
2. 이번 본인 시험 세션의 아직 보내지 않은 pending만 취소한다. 이미 보내는 요청을 취소 완료로 표시하거나 옛 기록을 지우지 않는다. sending이 있으면 최종 결과를 관측한다.
3. 원래 공통 억제 3개를 복원하고 중단 후 추가 DM 0·시험 대기 0을 확인한다. 계정 기능과 D0003 설정은 승인 전 기준 또는 사용자가 별도로 승인한 최종 상태와 정확히 일치해야 한다.
4. 승인받은 A/B 배포 사본 두 개의 공개 공유를 해제하고 비공개 보관, A/B 게시물 재보관, 이번 댓글·공개 답글만 정리한다. 기존 D0003 릴스·프로그램·과거 이력은 보존한다.
5. 실제 받은함에서 PDF/TXT/프로그램을 각각 열어 본 증거와 서버 단계별 건수·정리 결과를 남긴다. 공개 결과에는 단계·건수·시각·성공/실패 이유만 적고 비밀번호·토큰·수신자 ID/해시·전체 대화 원문을 넣지 않는다. HTTP 200이나 큐 done만으로 파일 열림·프로그램 사용까지 성공했다고 보고하지 않는다.

이 계획의 완료 기준은 새 코드 두 개와 기존 D0003의 자료 구분, 공개 답글, 승인 FAQ, 명시적 재전달, 모르는 질문의 제한 응답, 중단, 원상 복원을 각각 실제 확인한 상태다. 일반 시청자 모든 계정이나 장기간 무오류를 입증하는 시험은 아니다.

## 앞으로 콘텐츠를 만들 때 남는 최소 작업

Claude/GPT가 콘텐츠 묶음과 자료·키워드·문구·FAQ·기한을 함께 준비하고 사용자는 최종 콘텐츠와 공개·전달 범위를 승인한다. 게시가 끝나면 AI가 실제 게시 주소를 receipt로 기록하고 [제작·게시 연결 명령](../댓글DM_제작게시연결.md)을 한 번 실행한다. 명령이 파일 메타·게시 소유권 검증, 비공개 등록본 생성, 즉시 등록, 최근 댓글 확인까지 처리한다. 사용자가 등록 JSON이나 자료 코드를 직접 만들지 않는다. `registered`와 `catchup_verified=true`가 확인되면 이후 승인 범위의 댓글·DM 처리는 서버가 맡는다. 게시 URL·자료 확정·공개 승인 없이 파일을 올리는 것만으로 AI가 관계를 추측하여 등록하지 않는다.
