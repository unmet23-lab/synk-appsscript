# v4 검증·패키징 실행 안내

전체 렌더가 완성되기 전에는 계획 검사만 실행한다. 아래 스크립트는 원본과 이전 완성본을 변경하지 않으며, 다른 내용의 기존 출력 파일을 덮어쓰지 않는다.

1. `python validate_final.py --plans-only` — 편집/화면의 연속 프레임, 질문 카드 4개, 자막 69개, 질문 구간의 대사 자막·인터뷰 오버레이 부재를 확인한다. 오디오와 최종 영상이 없어도 실행할 수 있다.
2. `python validate_final.py --prepare-only` — 완성된 v4 mix_report와 PCM master/stem 해시까지 확인한다. 최종 영상 전체 분석은 하지 않는다.
3. 최종 4K MP4가 완성되고 실행 허가를 받은 뒤 `python validate_final.py` — 4K 전 프레임 디코드, 질문 구간 밖 검은 화면, 유지된 연결부의 화면 차이, 컷 경계와 질문 타이핑/완성 상태의 프레임 사진을 만든다. 이어 17개 대사 구간의 음성 지연, 최종 믹스 상관, 대사 보존, 세 오디오 stem 합을 확인한다.
4. 생성된 `validation_runs/<시각>/`의 컷 경계·질문 카드·자막 사진을 실제로 검토한다. 짧은 장면 후보는 자동 실패가 아닌 검토 대상이다. 질문 안의 글자 변화는 짧은 장면으로 세지 않는다. 새로운 why 끝의 짧은 정지 화면은 기존 연결부 연속성 검사 대상이 아니며 컷 경계 사진으로 확인한다.
5. Resolve의 DRP/DRT 내보내기와 화면 검토를 마친 뒤 `python package_delivery.py` — 검증된 파일의 해시가 유지되는지 재확인하고, 1080p 감상용 MP4, 같은 영상 비트스트림+PCM24 MOV, PCM24 WAV, 한국어 SRT, Bright A/B LUT, 읽어주세요 문서를 구성한다.

저장 공간 때문에 추가 MOV를 제외하기로 결정한 경우에만 `python package_delivery.py --skip-mov`를 사용한다. 4K MP4와 변경 없는 PCM24 WAV, 1080p 미리보기, 프로젝트·타임라인, 자막·LUT는 그대로 제공한다. 이 경우 패키지 기록의 `lossless_mov`는 `null`이며 읽어주세요 문서에도 제공하지 않은 MOV를 적지 않는다. 기본 실행은 계속 MOV를 포함한다.

패키징 시작 전과 미리보기/MOV 생성 직전에 필요한 공간을 계산하고 256MiB 여유 공간을 확보한다. 인코딩 중에도 남은 PCM·자막·LUT 복사량과 128MiB 여유 공간을 지키며, 부족해지면 중단한다. 중간 출력이나 이전 파일을 자동 삭제하지 않는다.

총길이·질문 위치·오디오 샘플 수는 `edit_plan.json`에서 읽는다. why 끝 경계가 바뀌면 계획/오디오/렌더를 다시 일치시킨 뒤 실행한다. `final_validation.json`과 패키지 검증 기록이 생긴 뒤 입력이 바뀌면 패키징을 중단한다. 검은 화면은 질문 카드 안에서만 허용하며 인터뷰 시작·끝에도 별도 예외를 두지 않는다.

대사 보존 검사는 모든 speech cut의 `prior_first`/`prior_last`를 v3 PCM에 대조한다. 새 절단 경계의 8ms fade를 허용하기 위해 각 컷 양끝 20ms만 제외한다. AAC의 자연스러움과 타이핑 효과음의 적절함은 수치 검사와 별도로 실제 청취해야 한다.
