# yuhobuilds 2편 V3 — AI 추천이 다를 때, 선택은 내가

2026-09-25 사용자 피드백에 따른 수정. [원고](원고.md) · [복사할 질문](따라_물어볼_질문.md)

## 이번 변경

- ‘AI 두 명’은 ‘두 AI 모델’. 초보에게 불필요한 ‘프론티어 LLM’ 설명은 넣지 않는다.
- Claude와 GPT의 말을 직접 인용하듯 읽던 대사를 ‘…만들라고 추천해 줬다’는 회고형 문장으로 변경한다. 실제 원문 인용이 아니라 사용자가 들려준 당시 제안의 요지다.
- 기존 ‘출석 기록 한 개를 남기는 첫 단계’ 질문은 사용자 예시에 맞춰 통째로 교체한다. 다른 모델에 상황과 두 방법을 함께 주고, 비용·난이도·관리 편의와 추천 이유까지 묻는다.
- Gemini는 다른 모델의 예시다. ‘독립적이고 객관적인 정답을 보장한다’고 표현하지 않는다. 다른 답도 참고 자료이며 최종 선택은 자신의 예산·시간·필요 기능으로 판단한다.
- 무료 이용은 가능하지만 한도와 기능 조건이 있으므로 ‘이용 한도 안에서’라는 표현을 음성·화면에 함께 둔다.
- 폴더와 Claude Desktop 세팅 본문은 이번 편에서 빼고 다음 편 예고로 남긴다. 비교와 판단이라는 한 가지 팁에 집중한다.
- ‘Glide Pro’는 현행 요금제 안내로 오해할 수 있어 사용자의 예시 질문과 동일하게 제품명 ‘Glide’로 표기한다. 실제 유료 가입 이력을 추가로 추정하지 않는다.

## 이어 만드는 순서

`voice-connection.cjs`를 실행해 기존 키를 임시 연결 → `synthesize.cjs` → `prepare-audio.cjs` → `make-builder.cjs` → `build-video.cjs` → HyperFrames 검수·장면 확인·렌더 → `finish-delivery.cjs` → 실제 화면과 브라우저 재생 확인.

최종 출력 위치는 상위 편 폴더의 `yuhobuilds_EP02_v3.mp4`다. `finish-delivery.cjs`는 실제 음성 시간표와 출력 길이 대조, 전체 디코딩·검은 화면·음량 검사, 36개 장면 이미지 추출을 수행한다. 검사를 통과한 경우에만 `preview-v3.html`을 생성한다. 브라우저 재생과 추출 화면의 직접 확인은 별도로 해야 하며 자동 검사가 그 확인을 대신하지 않는다. 출력 파일과 실제 `timeline.json`이 없으면 실행을 중단한다.

키는 로컬 프로세스 메모리에만 두고 합성 완료 후 연결을 종료한다. 새로운 구독·자동충전은 하지 않는다.

## 연결 복구 — 2026-09-25

사용자가 연결 불가를 보고하여 확인한 결과 4371·4375 모두 `ECONNREFUSED`였다. 두 서버가 종료된 상태로, 키 검증에 도달하기 전의 문제였다. 검토한 기존 Node 서버를 `Start-Process -WindowStyle Hidden`으로 별도 실행한 뒤 응답을 확인하고 브라우저에서 음성 입력 화면을 다시 열었다. 이후 최종 영상 상태 확인 때 음성 서버가 다시 종료되어, 입력 화면 자체의 2시간 종료를 없앴다. 이제 연결한 키만 연결 시점부터 2시간 뒤 메모리에서 지우고 입력 화면은 유지한다. 키를 파일에 저장하지 않는다. 정상 화면 표시와 Typecast 키 검증 성공은 별개이며, 실제 키 입력 이후 `/status.connected`를 확인한다.

음성 연결 전 확인 기록: 음성 `/status`와 장면 시안은 HTTP 200이었으나 `connected:false`여서 추가 합성 477자가 대기했다. 이후 사용자가 키를 연결하여 Lite 계정 연결 성공을 확인했고, 누락 11개 음성을 모두 합성했다. 합성 완료 후 키 연결을 해제했다. 키는 파일에 저장하지 않았다.

초기 준비용 `prepare-revision.cjs`는 수정된 음성 연결 서버가 이미 있으면 덮어쓰지 않는다. 재개할 때 서버 응답을 먼저 확인해 같은 포트의 중복 실행을 피한다.
