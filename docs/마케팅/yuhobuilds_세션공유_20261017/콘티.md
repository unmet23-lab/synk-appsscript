# yuhobuilds 「계정 바꿔도 Claude 세션이 안 사라지게」 — 콘티 v1 (Fable 검수 반영)

> 2026-10-17. [원고](원고.md)의 대사를 장면으로 나눴다. 형식은 쇼츠·릴스다(10-17 유호님 「형식은 쇼츠·릴스로 가자」). 글 콘티, Achird 테이크, 이미지 콘티 v1(장면별 정지컷 14장)까지 했고 셋 다 Fable 검수를 반영했다. 이미지 콘티는 「ai티가 좀 많이 나는데 ?」를 들어, 벤치마킹부터 다시 해 [움직임 시험판](움직임_시험판.md)(01A·06·09, 12.5초)을 새 방식으로 만들었다. 목소리는 결정 표 10-17에 따라 범수로 바꿨다(아래 초는 Achird 테이크 기준 기록이고, 범수로 다시 잡은 본편 장면 초는 [본편](본편.md) 표에 있다). 찍을 화면은 [캡처 목록](캡처목록.md)의 번호(⓪~⑨)로 가리킨다. 검수에서 짚은 것과 반영 여부는 맨 아래 「Fable 검수」와 「이미지 콘티 v1」.

## 만드는 방식

- **시작 사례:** [만족 사례 S20](../제작양식/만족사례_장부.md) — 실제 화면을 휴대폰 폭으로 찍고, 장면마다 짧은 제목 한 줄(형광펜 한 곳) + 실제 화면 하나 + 말자막 한 줄. 유호님이 S20 콘티를 보고 「모션그래픽을 정말 더 잘 활용해볼수있을까」라고 하셔서, 처음부터 S20 「모션 v2」(화면을 CSS로 다시 그려 숫자·줄·칩을 하나씩 움직임)와 S16의 결(키네틱 타이포, 강조색 하나, 박자 격자, 카드 한 장이 이어서 변형)을 넣는다.
- **S20과 달리 바꾸는 것:**
  1. 채널이 yuhobuilds라 키트 `builds` 테마다. 검정 `#0A0A0A` 면, 흰 글자, 버터 `#F5C445` 형광펜 한 곳, 끝 화면에 실제 얼굴 아치 창과 날짜 도장, 흰 펠트 synk 로고.
  2. 기능 소개가 아니라 실패담 순서다(사라짐 → 원인 → 꼼수 → 막힘 → 되살림 → 해결 → 결과).
  3. 주인공 화면이 Claude 앱 사이드바, 앱 로그, 공유 도구의 상태 출력이다.
  4. 빈 사이드바는 지금 찍을 수 없다(미러가 짝 폴더를 늘 채운다). 실제 사이드바 캡처에서 줄이 빠지는 움직임으로 보이고 「재현」 칩을 단다.
- **실제 줄은 글자 그대로:** 로그·상태 출력은 실제 줄을 그대로 옮겨 고정폭 글꼴로 다시 그린다(휴대폰에서 읽히게, 키트 모노 26px 이상). 긴 줄은 가운데를 `…`로 줄일 수 있지만 낱말을 바꾸거나 숫자를 고치지 않는다. 사용자 이름은 `…`, 계정·조직·세션 ID는 앞 4자 + `····`로 가린다. 원문은 `.tmp/yuhobuilds-세션공유-20261017/로그발췌.txt`(git 밖).
- **강조는 장마다 한 곳:** 형광펜은 제목에만 쓰고, 화면 속 줄·숫자는 크레용 밑줄·괄호·타원으로 짚는다(S20과 같게).
- **그림:** 폴더·링크·카드는 설명 그림(도형)이다. 마스코트·AI 그림·AI로 그린 앱 화면은 넣지 않는다.
- **순서(소리 먼저):** 내레이션 테이크 → 배경음 → 테이크의 낱말 시각에 장면·자막을 붙인다. 아래 초는 Achird 테이크(인스타 A판, 56.0초)의 실제 줄 시각이다(장면은 첫 말소리 0.25초 앞에서 시작). 유튜브 E판은 훅이 1.53초 길어 02부터 1.53초씩 밀린다. 10b는 테이크 안에서는 짧은 쉼뿐이라 편집에서 음악만 1.2초 넣고, 11은 그만큼 뒤로 간다.
- **도구:** Remotion, S20 `remotion/` 시험판 구조. 움직임 이름은 [SNS 키트 §9](../../디자인/SNS키트/README.md) 프리셋 말로 적는다.
- **배치:** 9:16 1080×1920, `.k-center` 배치. 자막은 아래끝 y 1236(내린 뒤 1416)에 붙여 위로 쌓고, 내용은 y 1040까지, 오른쪽 x 960~ 단추 열은 비운다. 칩·숫자는 제목 아래 왼쪽에 둔다. 제목 한 줄은 14자 안팎.
- **소리:** 내레이션 한 명(원고 「정할 것」 2), 배경음은 yuhobuilds 지난 두 편과 같은 시티팝_147 결(박자 격자는 실측 BPM), 효과음은 사건마다 하나.
