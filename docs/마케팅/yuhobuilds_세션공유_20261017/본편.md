# 세션 공유 편 · 본편(54.2초, 인스타·유튜브 같은 판)

유호님 10-18: 12.5초 [움직임 시험판](움직임_시험판.md)을 보고 「이 방향 좋아. 본편 전체를 이 방식으로 만들어줘.」(만족 사례 S22). 본편은 시험판 문법을 그대로 넓혔다. 장면 내용은 [콘티](콘티.md)의 「장면」 표, 대사는 [원고](원고.md).

같은 날 첫 완성본(A v7·E v6)을 보고 「구성은 좋아. 그런데 요약한 내용을 처음에 보여줘야 좋을것같아. 클로드 5시간 한도차서 다른 아이디로 이어할때 계정 교체해도 세션 공유되는게 주 장점인데 이게 잘 안보여. 그리고 마무리가 너무 아쉬워. 마무리할때 내 사진도 다른거로 바꿔줘 머리 길때 잘생긴버전프로필같은거있잔항. 그걸로」 → A판을 **결과 먼저**(00 요약 → 01 처음엔)로 열고, 끝을 실제 프로필 사진의 **프로필 카드**로 바꿨다. 요약이 맨 앞에 오면 훅이 둘이 되므로 유튜브 E판(「1,086번 거절」 훅)은 만들지 않고 A판 하나를 같이 쓴다(E 컴포지션 코드는 옛 판 그대로 남아 있다).

그 판에 「웅 전보다 상당히 좋아졌는데 마지막에 댓글이랑 팔로우 이거로 변경하는거 어떻게 생각해 ?」 → 「좋아. 끝을 댓글 「세션」 + 팔로우로 바꿔줘.」 → 끝 말을 「링크는 프로필에 있어요」에서 「댓글에 세션 남기면 링크 보내 드려요. 팔로우하면 다음 도구도 보여 드릴게요.」로 바꾸고(범수 cta), 프로필 카드에 댓글칸·팔로우 단추를 넣었다. 인스타는 댓글 DM, 유튜브는 고정 댓글 링크로 받는다(원고 「댓글 DM 전달 설정 초안」).

배경음 키운 판(v11)에 「메세지는 확실히 더 좋게 전달되는것같은데 후킹능력이 좀 떨어져. 조금 더 궁금하게 시작이나 썸네일을 제작하면 좋을것같다는 생각이야」 → 결과 먼저로 여는 판은 긴장이 없다고 보고 「0~3초 문제, 3~6초 해결」을 제안 → 「제안한 대로 사라짐 → 그대로 3초 오프닝으로 바꾸고, 전후 비교 표지도 만들어줘.」 → 여는 8초를 **00 훅(시험판 01A 그대로: 누르자마자 다 사라짐) → 01 그대로(되감겨 같은 동작을 다시, 이번엔 그대로)**로 바꾸고(새 범수 줄 sum2, 03부터는 v11과 같은 프레임), 표지를 0:03 정지컷에서 **전·후 두 판을 나란히 둔 표지**로 바꿨다.

## 짜임

- **화면 하나가 끝까지 이어진다.** 1막의 메인 판이 사이드바 → 지금 계정 폴더 → 로그 창 → 세션 줄 자리로 변한다. 2막은 폴더 셋 → 상태 창 → 25곳 칸 → 지금 계정 칸이 그대로 사이드바 → 로그 창. 3막은 README 종이가 그대로 도구 저장소 카드가 된다.
- **전환:** 장면 사이는 변형이 기본이다. 막이 바뀌는 두 곳(07 → 08 「결국」, 10b → 11 「방법만」)만 두 장면을 한 장으로 이어 위로 넘긴다. 08 → 09는 ★ 줄로 붙었다가 박에 하드 컷. 밝은 판 → 어두운 창은 어두운 창이 아래(또는 위)에서 덮고, 다 덮은 뒤에야 밝은 판을 내린다(같이 흐리면 회색이 비친다). 흐리게 사라지는 판은 없다.
- **머리글이 곧 내레이션:** 낱말마다 범수 목소리의 실제 시각(`음성/범수/*.json` → `remotion/src/full/vo.generated.ts`)에 맞춰 마스크로 올라온다. 화면 글은 말한 낱말 안에서만 고른다(줄일 수는 있어도 말과 다른 꼴로 바꾸지 않는다). 크기 두 단계(머리글 88px · 모노 기록) + 큰 숫자·시각 하나.
- **값은 실제만:** 로그 줄(거절 1,086줄, 첫 줄 10:37:47, 끝 줄 12:41:23, Loaded 54, Loaded 76 넷), 공개판 상태(25곳, 공통 파일 3430개, 101개 세션 기록), 공유 도구 기록(1곳 확인, 24개 복사, 0개 삭제), README 문장. ID는 앞 4자 + ····, 세션 제목은 흐림, 긴 경로 앞(C:\Users\…\AppData\Roaming\Claude)은 …로 줄인다. 폴더 셋·링크 선·25곳 칸은 설명 그림이라 화면 아래에 「재현 화면 · 숫자는 실제」를 두고, 끝 화면(실제 얼굴·핸들)이 나올 때만 뺀다.
- **배경음:** 시험판과 같은 「Building Momentum」을 이야기에 맞춰 두 마디 잘라 붙였다(`remotion/음악.mjs`). 12박 드럼 빠짐(02 「목록이 비어」), 16박 다시 터짐(03), 44~55박 조용한 구간(06 거절 1,086번), 56박 다시 터짐(「저장 안 됨」), 68박 드럼 빠짐(08 상태 창), 72박 다시 터짐(파일 수), 88~92박 한 마디(10b 말 없이), 100박 끝맺음(11 「공개했어요」). 박 격자는 끊기지 않는다.
- **목소리:** 범수(Typecast, ssfm-v30·보통·1.12배). 10-18에 유튜브판 훅 h1e(33크레딧), 결과 먼저로 여는 두 줄 sum·h1b(64크레딧), 끝 댓글·팔로우 줄 cta(43크레딧), 「사라짐 → 그대로」의 되살린 줄 sum2(38크레딧)를 새로 구웠다. 지금 A판은 h1 · sum2 · c1~e1 · f1a(f1을 「공개했어요.」에서 자른 것, `준비.mjs`) · cta를 쓰고 sum·h1b·s1·f1 통째는 쓰지 않는다.
- **여는 소리:** 텅 비는 5박부터 되감기 박 직전까지 배경음을 0.4배로 비우고(원곡도 그 자리가 박 사이 빈자리라 0.2초쯤 거의 조용해진다), 되감기는 목록이 빠질 때 쓴 whoosh_down을 거꾸로 튼 `sfx/whoosh_rev.wav`(`준비.mjs`가 만든다). 6박에 배경음이 다 돌아온다.
- **배경음 끝:** 10-18 끝 말이 4초 늘어 끝맺음 앞 마디를 한 번 더 넣었다(`음악.mjs`). 끝맺음이 104박(50.8초) 「(링크) 보내」에 오고, 여운은 53.2초에 끝난다.

## 다시 만들기

`remotion/`에서:

```
npm ci
node 준비.mjs        # 서체·효과음(+거꾸로 튼 whoosh_rev)·범수 목소리·배경음 원곡·끝 화면 자산을 public/에
node 음악.mjs        # public/bgm_a.wav · bgm_e.wav (두 마디 잘라 붙임, E판은 앞에 2박)
node 음성시각.mjs    # src/full/vo.generated.ts (낱말 시각)
npx remotion render src/index.ts full-a out/full-a-vN.mp4
npx remotion render src/index.ts full-e out/full-e-vN.mp4
node 마감.mjs out/full-a-vN.mp4   # −14 LUFS, 피크 막기
# full-a 기본은 배경음 키운 판. 비교용: full-a-music-up(같음) · full-a-no-music(배경음 없음)
npx remotion still src/index.ts cover out/cover.png --frame=0   # 표지(PNG) → 게시/표지_1080x1920.jpg로 JPG(품질 92) 저장
```

렌더는 판마다 1분 안팎. 결과는 git 밖 `remotion/out/`.
