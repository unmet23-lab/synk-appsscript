## 유호님

- 사용자는 유호님이다. 항상 "유호님"으로 호칭하고 기본 응답은 한국어로 한다.
- 몽골 울란바토르에서 SYNK를 구축하는 비개발자 1인 기업가다.
- 자연어로 지시하면 AI가 파일 수정·검증·원격 실행·배포까지 완료하는 **자동화 시스템 구축을 가장 선호**하고, 요구 충족 지점에서 멈추지 않고 꼬리에 꼬리를 무는 집요한 최상을 추구한다(07-31 직접 선언).
- 효율과 퀄리티를 모두 중시한다. 유료 도구는 가격 자체가 아니라 작업 스타일 적합성과 확실한 성과·능률 상승으로 판단한다.
- "트렌디"는 유행을 좇는 것이 아니라 성능·효율이 앞서 사람들이 따라오게 만드는 것이다.

## SYNK

- SYNK 조직계보(2026-07-17 확정 · 07-29 v1.1 표기 전환 · **08-16 v1.4 제품 라인 철회**, 정본=`docs/조직계보_정본_v1.md`): 고객 브랜드 2개(SYNK LAB·SYNK STUDIO) + 전사 레이어 2개(SYNK IP·SYNK COMMON SYSTEM). 구 6부문 계보(FASHION·F&C·ABROAD·PUBLISH 포함)는 폐기·흡수됨.
- **조직 표기는 조직도가 아니라 로드맵이다(v1.1)**: 지금 여는 것 = LAB / 지금 쌓는 것 = STUDIO·IP·COMMON SYSTEM. 세로로 읽으면 시간, 꼬리표(브랜드·레이어)를 읽으면 성격. 조직·브랜드를 언급하는 문서를 쓸 때는 이 축을 먼저 쓴다.
- 🚫 **제품 라인 철회(v1.4 · 유호님 확정 2026-08-16)**: 의류·굿즈·식품(구 SYNK Wear·SYNK Pantry와 그 구 우산명)은 **철회**됐다 — 브랜드도, 「준비 중인 것」 칸도, 로드맵의 다음 칸도 아니다. 어느 문서·덱·대면물에도 쓰지 않으며 「준비중」 라벨을 붙일 대상도 없다. 되살리는 판정은 유호님만 한다. **재제안 금지.**
- **방향 확정(2026-08-16 유호님)**: 앞으로는 **교육 시스템과 엔진 개발에만 몰두**하고, 엔진 시스템과 디자인 디테일을 **최상급으로 명품화**한다. 넓히는 제안(새 브랜드·새 제품군·새 사업 축)은 내기 전에 이 줄에서 걸린다. ⚠ 경계: **앱 포인트 상점의 의류·굿즈·간식 품목은 그대로 간다** — 학생 동기부여 장치이지 제품 라인이 아니다(철회된 것은 그것을 브랜드로 세우던 층).
- 현재 핵심은 SYNK LAB: 몽골 학생 대상 게임화 한국어 학원이며 영어 교육도 포함한다. **일정 확정(2026-08-04 유호님)**: 시즌·2주 무료 파일럿 시작 **2027-02-11(목)** → 정식 개원 **2027-02-25(목)**. `app_state`의 `시즌시작일` = `2027-02-11`(파일럿 포함). ⚠첫 시즌은 유료가 6주다(파일럿 2주 무료) — 매출·BEP를 정상 시즌과 같게 잡지 말 것. 정본 = memory `opening-roadmap-2027feb`.
- 몽골어 최종 감수는 AI가 아니라 현지 원어민 사람이 담당한다.
- 디자인 최종 조립은 Canva, 운영·콘텐츠 검수는 Notion을 주로 사용한다.

## AI 운영 원칙

- 구 「Claude 단일」(07-31)·cowork 병용은 폐기됨 — cowork 사본(`docs/COWORK_지침.md`)은 **⛔동결**(재사용 통보 전까지 갱신·전파 대상 아님).
- 한 작업은 한 세션이 처음부터 끝까지 소유한다. 같은 시간에 두 세션이 같은 코드 구역을 수정하지 않는다(선언 = 열린 PR · 누가 도는지는 하네스 `list_sessions` — 멀티 세션 규약은 `CLAUDE.md`).
- 기본 작업 위치는 로컬 `master`; worktree·PR·클라우드 코딩은 특별한 필요가 있을 때만 쓴다. 코드를 수정한 세션에서만 `/deploy`를 실행한다.
- 되돌릴 수 있는 작업은 가볍게 검증하고, 돈·계약·외부 발행처럼 되돌리기 어려운 일만 컨텍스트 독립 리뷰(구현 대화를 안 본 검증자)를 깊게 붙인다.
- 대화 전체를 다른 세션에 복사하지 않는다. 코드 인계는 `git diff`, 업무 인계는 **열린 PR 본문 + 커밋 메시지 + memory/docs 정본 링크**를 쓴다(세션 찾기는 하네스 `list_sessions`·`search_session_transcripts`).

## 작업·모델 원칙

- 단순하고 가역적인 작업에는 과도한 심층검증을 돌리지 않는다.
- 복잡한 코드·핵심 판정에만 최상위 모델과 높은 추론을 사용한다.
- 모르면 지어내지 말고 모른다고 말한다. 결론은 먼저, 근거는 뒤에 둔다.
