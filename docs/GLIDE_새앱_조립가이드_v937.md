## 0. 시작 전에 — 반드시 읽기

### 0-1. 왜 새로 만드나 / 무엇을 지키나
- **앱만 새로 만듭니다. 구글시트(SYNK_앱데이터)는 절대 유지** — 시트가 엔진의 심장입니다(스크립트가 매일 여기에 계산 결과를 씁니다). 앱은 그 결과를 **읽어서 보여주는 껍데기**일 뿐입니다.
- 기존 반쯤 만든 SYNK CORE 앱은 **새 앱 완성·검증 후 삭제**합니다. 그 전엔 두 앱이 같은 시트를 봐도 무해합니다(둘 다 읽기 위주).

### 0-2. 원격 조립 방식 — "AI가 눈, 유호님이 손"
- AI(저 또는 GPT)는 Glide 화면을 **직접 클릭할 수 없습니다**(브라우저 자동화가 Glide 도메인에서 막힘 — 이 세션에서 실증). 대신 **유호님이 화면 스크린샷을 주시면 제가 "여기 이 버튼 → 이렇게" 짚어드리고, 클릭은 유호님이** 합니다.
- **데이터 접근권한 변경(공유·Row Owner 등)은 안전 규칙상 AI가 대행하지 않습니다** — 유호님이 직접.
- 진행 단위: 아래 PHASE를 **하나씩** 하고, 끝날 때마다 스크린샷으로 확인 → 다음 PHASE. 한꺼번에 몰아서 하지 마세요(실수 추적 어려움).

### 0-3. 계정 주의

### 0-4. 조립 전 실행할 스크립트 (Apps Script 편집기에서 1회씩) — ★폼 만들기 전에 반드시

## PHASE 1 · 데이터 소스 + 로그인 + 권한 5건 (기초 — 여기가 제일 중요)

### 1-1. 새 앱 생성
- go.glideapps.com → New app → **Google Sheets** → **SYNK_앱데이터** 선택.
- 앱 종류는 앱(App). 시트의 여러 탭이 자동으로 데이터 테이블로 잡힙니다.

### 1-2. Users table = profiles (로그인 매핑)
- Settings(⚙) → **Users** → User profiles table = **profiles**.
- Email column = `email` · Name = `이름` · Role(있으면) = `role`.
- 이렇게 하면 로그인한 사람의 profiles 행이 "현재 사용자"로 연결됩니다.

### 1-3. 권한 5건 (★ 하나라도 빠지면 학생이 남의 정보를 보거나 편집할 수 있음)
1. **이메일 로그인 강제** — Settings → Privacy → "Users must sign in" ON. (profiles에 이메일이 있어야 로그인됨)
2. **Users table 매핑** — 위 1-2 완료.
3. **Row Owners** — profiles 테이블에서 `email` 열을 **Row Owner**로 지정. → 각 사용자는 **자기 행만 다운로드**받습니다(남의 데이터가 기기로 아예 안 감 = 개인정보 보호의 핵심).
4. **역할 Visibility** — 모든 탭·컴포넌트에 role 조건. ★**실제 역할값 = student / parent / teacher / `director`** (원장은 admin이 아니라 **director**). 특히:
   - 원장 콕핏·리텐션신호(BK) = `role is director` 전용
   - **핵심비전(BA53)·⚠상담위험은 앱에 아예 노출 금지**(원장 내부 케어용)
   - student_errors·mastery_log = 학생에게 **미노출**
5. **드라이브 폴더 공개** — `SYNK_리포트카드` 폴더 → 공유 → "링크가 있는 모든 사용자 · 뷰어". (리포트카드 이미지가 앱에 뜨려면 필수) — **이건 유호님이 직접**.

> ⚠ **프라이버시 한계 (알아두기)**: 민감 열 **핵심비전(BA53)·⚠상담위험(AZ52)·리텐션신호(BK63)** 는 학생 본인 profiles 행에 있습니다. Row Owner(행 단위)는 학생 기기에 그 행 전체를 내려보내므로, Visibility=director로 **화면만 가려도 기기 안엔 값이 남습니다**(온디바이스 유출). 지금은 이 열들을 **어느 화면에도 바인딩하지 말고 비워두는 것**으로 회피하고, 실제 민감정보를 넣기 전(개원 전)에 이 열들을 **원장 전용 별도 시트로 분리**하는 후속이 필요합니다.

### 1-4. 언어 설정 확인 (몽골어 고착 우려 지점)
- Settings → **Languages** 상태를 스크린샷으로 확인 → 저에게 주세요. "한번 몽골어로 뜨면 계속 몽골어" 우려의 실제 지점이라, 언어정책(아래 6장)과 함께 판정합니다.

#### ⓪ ★반 선택 네비게이션 (유호님 요구 — 이 구조가 정본)
강사는 **자기 반 목록을 보고 → 반을 골라 들어가면 → 그 반 학생 리스트가 뜨고 → 멀티체크로 숙제·출석·문법을 처리**합니다. 아래 ①~④ 폼은 전부 **이 "반 선택 → 학생 리스트" 안에서** 열려야 합니다(플랫 폼 금지).
- **1단계 탭 = 반 목록** (소스: `schedule` 또는 `class_stats`의 반 리스트 · Collection). 필요시 강사 반만 필터.
- **2단계 = 반 상세 화면** — 탭한 반의 **학생 리스트**(소스: profiles, Filter **class_name = 이 반** · role = student). ← 학생들이 리스트로 뜨는 지점.
- **3단계 = 그 화면 안의 액션**: 아래 출석/마감/숙제 폼을 열되, 학생 멀티선택은 **이 반 학생으로 필터**됨.
- ⚠ **멀티체크 = 멀티선택 Choice(체크 여러 개 → 저장 1회 = update 1회)**. 학생마다 개별 토글(Set Column)로 만들면 30명=30 update로 쿼터 파산 — 반드시 "리스트에서 여럿 체크 → 한 번 저장" 방식.
- ⚠ **필터는 "로그인 강사의 class_name"이 아니라 "선택한 반"** 기준. (강사가 여러 반이면 자기 class_name 고정 필터로는 반 선택이 안 됨)

**① 오늘의 반 탭** (소스: class_stats, 내 반 필터) — 전부 읽기(Rich Text):
- ⚠ **`calcAll`을 1회 실행해야 이 열(9~13)이 생깁니다**(0-4의 4번). 안 돌리면 class_stats가 8열까지만이라 아래를 바인딩할 수 없습니다.
- 수업전브리핑(9열) — 수업 전에 확인 (여기에 "오늘 결석 예정"·생일·케어사각도 자동으로 뜸)
- 오늘체크(11열)·격파찬스(10열)·왕관밸런스(12열)
- **레이드카드HTML(13열, 신규)** — 이번 주 레이드 진행

**② 수업 시작 · 출석 탭** (소스: **attendance_batch** ← `setupClassroomInputs`가 생성, **Form**) — ★신규:
- ⚠ **출석 폼은 `attendance` 시트가 아니라 `attendance_batch` 시트에** 만드세요. `attendance`는 스크립트가 개별 행으로 채우는 결과 시트라 여기에 폼을 걸면 학생 1명=1저장=쿼터 파산입니다. attendance_batch에 멀티선택 1저장 → 10분 뒤 스크립트(expandAttendanceBatch_)가 attendance로 전개합니다.
- 폼 필드: 날짜(자동) · **class_name**(내 반) · **출석자목록 = Choice(멀티, 반 학생, value=user_id)** · 입력자(자동)
- created_at은 **폼이 자동 기록**되게(Glide 폼은 기본으로 timestamp 열 지원 — 없으면 스크립트 전개가 안 되니 반드시 확인).
- 저장 1탭 → 10분 내 스크립트가 attendance로 전개 → 등원 알림·출결 보드 자동.
- ※ **학생당 개별 체크 금지**(월 쿼터 파산). 반드시 멀티선택 1저장.

**③ 수업 마감 탭** (소스: weekly_topics, **Form**) — ★신규·핵심:
- ⚠ 먼저 `setupClassroomInputs` 실행(0-4)으로 **weekly_topics에 F~L 열이 생성돼 있어야** 아래 필드를 바인딩할 수 있습니다. 열이 class_name·배운내용·배운내용_mn 3개(또는 5개)만 보이면 아직 실행 전입니다.
- 폼 필드(A~J):
  - **배운내용**(B, Text)
  - **문법태그(F) = Choice(멀티)** → display = contents.문형(C열), value = contents.콘텐츠ID(A열, **G2xx~G7xx** 6단계). ※Filter contents 유형 = grammar. **value(ID)로 저장**(문형 문자열로 저장하면 매칭 깨짐).
  - **전체도달도(G) = Choice** 2택: `도달` / `더연습`
  - **예외학생(H) = Choice(멀티, 반 학생)** — "아직인 학생"
  - **숙제완료자(I) = Choice(멀티, 반 학생)** — 밤에 +10P 자동. ★이게 유호님이 말한 "학생 리스트 멀티체크 숙제"입니다. Choice 소스를 **이 반 학생으로 필터**하면 그 반 학생만 체크 목록에 뜹니다.
  - 연료미션(J, Text, 선택)

> **숙제만 빠르게 체크하고 싶으면** — ③ 마감폼 전체 대신 **hw_batch 시트**에 별도 "숙제 체크" 버튼을 둬도 됩니다(hw_batch: date·class_name·완료자목록·입력자·created_at·처리상태). 완료자목록 = 반 학생 멀티선택, 저장 1회 → 밤에 expandHwBatch가 +10 전개. weekly_topics 숙제완료자(I)와 병존·중복지급 안전(둘 다 재조회 dedup). 유호님이 원한 "반 → 학생 리스트 → 숙제 멀티체크"에는 이 hw_batch 전용 버튼이 제일 단순합니다.
  - created_at 자동.
- 저장 1탭 → 밤 배치가 숙제 포인트·문법 도달(mastery)·연료로 전개. **이게 진화 게이트를 움직이는 입력**입니다.

**④ 포인트 주기 탭** (소스: point_logs, **Add Row 버튼**):
- 버튼 2종만: **오늘의 MVP +10** / **오늘의 시냅스 +10**. (수업 중 발표 순간 즉시 반영용)

- **★ "생일축하 +20" 버튼은 만들지 마세요** — 아침 7시에 시스템이 자동 지급하는데 강사가 또 누르면 밤에 정정+메일이 갑니다(v9.34 판정).

**⑤ 출퇴근 탭** (소스: **teacher_checkins** ← `setupClassroomInputs`가 헤더 정규화, **Form/Add Row**) — ★신규:
