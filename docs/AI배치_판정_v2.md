# 기존 AI 실행 도구의 배치값과 해석

> 현행 안내 · 2026-09-10. 파일명은 기존 도구·시험의 연결을 유지한다. 직접 채팅하는 AI의 책임·권한·모델 선택은 [AI 운영 원칙](AI_운영원칙.md)을 따른다. 아래 자동 표는 `tools/모델정책.js`가 반환하는 기존 실행 도구·제품 API의 설정이며, 전사 업무의 강제 역할표가 아니다.

## 읽는 기준

- **직접 작업:** 현재 하네스 선택과 요청 범위가 기준이다. 특정 제공자만 기획·문안·코드·보고를 할 수 있다는 제한을 이 표에서 만들지 않는다.
- **기존 도구·제품 API:** 모델·효력·회차·호출 경로는 실제 코드에서 확인한다. 문서 편집만으로 제품의 모델·과금·데이터 계약을 바꾸지 않는다.
- **실제 상태:** 표의 `돈다`·`미배선`·`재판정대기`와 날짜가 붙은 쪽지는 코드에 저장된 메타데이터다. 현재 계정·브라우저·학생 수·실행 성공을 다시 확인한 결과가 아니다. 표의 현재성과 실제 운영의 현재성은 구분한다.
- **담당 이름:** `과제글`·`발음채점` 같은 이름표가 안정된 조회 키다. 번호는 표시 순서라 구현·인계의 식별자로 쓰지 않는다.

`node tools/모델정책.js --배치 <이름표>`로 해당 항목을 읽는다. 표를 갱신할 때는 원천 코드의 변경을 확인한 뒤 `node tools/모델정책.js --문서심기 docs/AI배치_판정_v2.md`를 실행한다. `tests/배치문서.test.js`가 코드와 아래 표의 일치를 검사한다. 이 검사는 실제 호출과 결과의 품질을 증명하지 않는다.

## 배치·변경 판단

우리 대표 과제의 품질·오류·소요 시간을 비교하고, 성능이 사실상 동등할 때 비용·포함량을 비교한다. 모델 이름·옛 벤치마크·제공자별 자리 수 균형만으로 배치하지 않는다. 독립 검토는 필요한 위험과 완료 조건에 맞추고 모든 작업의 고정 회차로 확대하지 않는다.

학생이 읽는 글은 작성 제공자보다 브랜드 말투·수준·경험의 일관성이 기준이다. [학생 일기](학생일기_설계.md)의 맞장구를 교정·평가로 바꾸지 않는 등 기능별 계약을 유지한다.

학생의 기록을 다루는 기능은 입력, 남기는 사건, 소비자와 전달 결과를 연결한다. 홍보물·회사 보고·번역 검문에 학생 원장 기록을 억지로 요구하지 않는다. 운영용 결과와 학습용 데이터를 섞지 않는다. 담당자 설정, 코드 연결, 실제 사용, 고객 효과는 각각 확인한다.

발음·성향·삶 이해처럼 시간에 따라 비교하는 판정은 출력 규격·기준 사례·모델 및 기준판·유효 범위를 먼저 확인한다. 모델 교체로 척도가 달라진 것을 학생의 변화로 해석하지 않는다. 상세 계약은 [발음 데이터](발음데이터_규격.md), [성향 추출](성향추출_설계_v1.md), [삶 이해 현황](삶이해_현황.md), [엔진 설계](엔진7종_상향설계_v3.md)에 둔다.

삶·목표 판정은 AI 초안과 강사 확정을 구분하며, 확정 없는 판정을 학생에게 전달하지 않는 계약을 지킨다. 첨삭의 자동 공개 설정을 삶 이해에 그대로 적용하지 않는다. 이 안내가 해당 기능의 구현·실사용 완료를 선언하지 않는다.

구독 포함량과 제품 API·DB·배포 비용은 별개다. 과거의 충전 약속·무료 요청 수·크레딧 만료일을 현재 잔액이나 새 지출 허가로 읽지 않는다. 이미 허용된 통로의 실행과 실제 인증·과금·결과를 확인한다.
