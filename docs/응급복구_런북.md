# 🆘 SYNK 응급복구 런북 (비개발자용)

> **v1.0 · 2026-07-11** — 새벽에 앱이 이상하거나 자동 알림이 멈췄을 때, AI 없이 유호님 혼자 복구하는 1페이지.
> 데이터 손상은 매달 오는 `복구 리허설` 메일이 3단계로 안내한다. 이 문서는 **코드/트리거 장애**를 다룬다.

---

## 0. 먼저 — 어떤 문제인가?

| 증상 | 아마도 이것 | 가는 곳 |
|---|---|---|
| 아침 8시 브리핑 메일이 **안 옴** | 트리거 전체 멈춤(재인증 만료 등) | §1 트리거 되살리기 |
| `[SYNK] ⚠️ 신선도 경고` 메일이 옴 | 야간/월간 배치가 중도 증발 | §1 트리거 되살리기 |
| `[SYNK] ❗ 자동 작업 실패: XXX` 메일 | 특정 작업 1개만 실패 | §4 증상별 표 |
| 방금 **배포한 뒤** 앱이 이상해짐 | 코드가 잘못 올라감 | §2 코드 되돌리기 |
| 학생 포인트·이력이 사라짐/틀어짐 | 데이터 손상 | §3 데이터 복원 |
| **노트북을 잃어버렸다 / 안 켜진다** | 이 문서가 아니라 **이어하기 꾸러미**가 맡는다 | 구글드라이브 또는 원드라이브의 `SYNK_이어하기/0_먼저읽기.md` |

## 1. 트리거 되살리기 (알림이 멈췄을 때)

Apps Script는 가끔 **재인증**을 요구하며 모든 자동 작업을 멈춘다. 아침 브리핑이 안 오면 90%는 이것.

1. 브라우저에서 **script.google.com** 접속 → **SYNK** 프로젝트 클릭
2. 왼쪽 **⏰ 트리거**(시계 아이콘) 클릭 → 빨간 오류 표시가 있으면 재인증이 필요한 상태
3. 왼쪽 **</> 편집기** → 함수 목록에서 **`resetAllTriggers`** 선택 → **▶ 실행**
4. "권한 검토" 창이 뜨면 → 내 계정 선택 → **고급 → SYNK(으)로 이동 → 허용**
5. 실행 로그에 `✅ 트리거 통합 재설치 완료: 11개`가 보이면 끝 — 교재연동을 개통한 뒤라면(목소리 폼·AI 문법 판정, v9.58~) `12개 · 23시 교재연동`이 정상(2026-08-06 코드 실측 `엔진_셋업확장.js`). 몇 개가 정상인지는 로그 문구가 스스로 알려주니 그 문구대로면 된다(v9.67)

> 매월 1일 새벽이라면 `resetAllTriggers` 대신 **`resetAllTriggers`에 `true`를 넣어 실행**해야 할 수 있다(리포트카드 배치 보호 때문). 편집기 위쪽 함수 인자 칸이 없으면, 그냥 오전 늦게 다시 시도해도 된다.

## 2. 코드 되돌리기 (방금 배포가 잘못됐을 때)

`clasp`나 명령어 없이 **GitHub 웹 + 붙여넣기**만으로 직전 정상 코드로 되돌린다.

1. **github.com/[내 저장소]/SYNK-appsscript** → **커밋(commits)** 목록 열기
2. 문제를 일으킨 배포 **직전** 커밋을 클릭 → **어떤 파일이 바뀌었는지** 확인
   - ⚠️ 바뀐 파일이 여러 개일 수 있다(`Code.js` 외에 `contents_*.js`·`appsscript.json`). **바뀐 파일 전부**를 되돌려야 한다 — 하나만 되돌리면 반쪽 복구로 더 위험.
3. 되돌릴 각 파일마다: 그 직전 커밋에서 파일 열기 → 오른쪽 위 **Raw** → 전체 선택(Ctrl+A) → 복사(Ctrl+C)
4. **script.google.com → SYNK → 편집기**에서 같은 이름 파일 열기 → 전체 선택 → 붙여넣기 → **💾 저장**
5. 앱/알림이 정상으로 돌아오는지 확인

> **끝나고 꼭:** 편집기에 직접 붙여넣으면 라이브와 GitHub 기록이 어긋난다(`/deploy`가 막으려는 바로 그 상태). **다음 AI 세션에서 "응급 롤백 했다"고 말해** git 동기화를 맡길 것. 안 그러면 다음 배포가 되돌린 걸 다시 덮어쓴다.

## 3. 데이터 복원 (포인트·이력이 손상됐을 때)

매일 새벽 3시에 전체 사본이 **Drive → SYNK_백업** 폴더에 30일 보관된다(앱 데이터 + 상담시트 각각).

1. **drive.google.com → SYNK_백업** 폴더 열기
2. `SYNK_앱데이터_백업_[날짜]`(앱) 또는 `SYNK_상담백업_[날짜]`(로스터·납입) 중 **손상 전 날짜** 파일 열기
3. 손상된 **시트 탭만** 전체 선택 → 복사
4. 원본 스프레드시트의 같은 이름 시트에 붙여넣기 (스크립트·트리거는 원본에 그대로 살아있음)

## 4. 증상별 빠른 표

| 메일/증상 | 뜻 | 할 일 |
|---|---|---|
| `❗ 자동 작업 실패: calcAll` | 야간 계산 1회 실패 | 대개 일시적. 다음 날도 오면 §2 최근 배포 의심 |
| `❗ 자동 작업 실패: importFormResponses` | 상담폼 편입 실패 | 상담시트 권한/구조 확인. 반복되면 AI에 문의 |
| `⚠️ 메일 쿼터 부족` | 하루 발송량(100통) 초과 | 그날 알림 일부 누락. 잦으면 Workspace 계정 전환 검토 |
| `⚠️ 상담시트 백업 실패` | 상담 사본 생성 실패 | Drive 용량·상담시트 권한 확인 (앱 백업은 정상) |
| `⚠️ 백업 멈춤 의심` | 2일+ 백업 없음 | §1 트리거 확인 + Drive 용량 확인 |
| 아침 브리핑 **자체가 안 옴** | 트리거 전체 사망 | §1 |

## 응급 연락 순서

1. 위 표/절차로 5분 안에 해결 안 되면 → 무리하게 만지지 말 것(더 큰 손상 위험)
2. 데이터는 매일 백업되고 있으니 하루 정도는 안전 — 급하면 트리거만 멈춰두고(§1의 트리거 화면에서 일시중지) AI 세션에서 함께 진단
