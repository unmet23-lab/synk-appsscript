# SYNK Loom — 그래픽 엔진 설계

2026-09-13 · 현재 구조와 제작 진입로. 값·승인 자산은 [DESIGN](../DESIGN.md), 엔진 간 계약은 [엔진 7종](엔진7종_상향설계_v3.md)에서 읽는다. 완료된 실험·옛 도입 순서는 [정리 전 원문](https://github.com/unmet23-lab/synk-appsscript/blob/8b80a507168d/docs/Loom_엔진_설계.md)에 남긴다.

## 0. 한 문장

Loom은 재질·빛·배치·움직임을 연결해 서로 다른 매체에서도 같은 SYNK의 세계를 만드는 그래픽 엔진이다. 재현 가능한 원본과 제작 조건을 공유하고 장면에 필요한 표현은 발전시킨다.

**애니메이션을 지원하는 모든 결과물에는 [움직임 지원 매체 표현 기준](Loom_실시간장면_표현기준.md)을 기본 적용한다.** 실시간·영상은 각 매체 통로로 만들고 정적 전용 위치에는 같은 표현의 정지 컷을 쓴다. 정원의 바람 주기나 풀 개수를 모든 UI에 강제하지 않는다.

## 1. 현재 기준

재질·색·서체·로고·마스코트는 DESIGN에서 해당 용도의 승인 원천을 선택한다. 새 부품·모델·렌더러는 현재 요청과 실제 품질에 맞게 확장한다. 과거 후보의 실패·당시 구현 없음·특정 작업의 보류를 새 표현의 영구 금지로 삼지 않는다.

의상처럼 별도 사용자 지정이 있는 제작은 [담당 정본](캐릭터/의상제작_정본.md)을 따른다. 도구 선택이 승인 원본 교체나 신규 지출까지 뜻하지는 않는다.

## 2. 층 구조

| 층 | 역할 | 현재 원천·통로 |
|---|---|---|
| L0 값 | 색·서체·재질·간격·감각 값 | [디자인 토큰](디자인_토큰.json) |
| L1 재질 시스템 | Felt·Resin·Glass의 참조·빛·질감 | [Felt 프로필](펠트엔진_설계.md), [룸장면.py](../tools/룸장면.py) |
| L1b 굽기 | 렌더·생성 결과를 배치 자산으로 변환 | [굽기 규약](Loom_굽기규약.md) |
| L2 부품 | 번호·불릿·칩·표지 등 재사용 요소 | [loom.js](../tools/lib/loom.js), 공방 자산 |
| L3 율 | 위계·간격·광학 정렬 | 토큰 → loom.js의 `--율` |
| L4 지면 | 문서·웹·인쇄 등의 조립 | loom.js의 `지면들`, 매체별 제작기 |
| L4.5 조판 | 구조 있는 원고를 문서로 변환 | [배치 판단층](Loom_배치판단층_설계_v1.md), [룸조판.js](../tools/룸조판.js) |
| L5 점검 | 기존 관리 지면의 분류·재현 확인 | [지면방.js](../tools/lib/지면방.js), 기존 시험 |

L1은 재질 시스템이며 Felt·Resin·Glass는 그 안의 프로필이다. 기존 `펠트엔진_설계.md` 파일명은 참조 호환을 위해 유지한다. 실시간 공통 움직임은 [loom-scene.mjs](../tools/lib/loom-scene.mjs), 웹 표시는 [loom-scene-webgl.mjs](../tools/lib/loom-scene-webgl.mjs)에 분리되어 있다.

## 3. 재질·부품·움직임

### 3-1. 부품

목적에 맞는 기존 부품은 재사용한다. 새 행동·읽힘에 필요한 부품은 승인 재질·타이포에 맞춰 만들고 소비 위치에 연결한다. 목록 밖이라는 이유로 제작을 중단하지 않는다. 현재 목록은 `node tools/lib/loom.js --분모`에서 확인한다.

### 3-2. 율

간격·광학 보정은 토큰과 공통 코드에서 가져온다. 숫자를 여러 문서에 복제하지 않고 실제 글자·창 크기로 줄바꿈과 위계를 확인한다.

### 3-3. 재질

Felt의 섬유·두께·접촉 그림자, Glass의 투과·반사, Resin의 내부 깊이를 보존한다. 적용 위치는 DESIGN의 현재 역할과 승인 실물을 따른다. 옛 유리 번호·레진 불릿을 최근 펠트 단추·매듭점 대신 복원하지 않는다.

### 3-4. 품질

실제 사용 크기에서 형태·색·빛·접지·읽힘을 함께 본다. 수치와 자동 검사는 원인을 좁히는 근거이며 자연스러운 실물 확인을 대신하지 않는다.

### 3-4b. 표현 확장

반사·모따기·공간감·그레인은 해당 장면에서 이득을 확인해 선택한다. 예전 단품 실험의 조명값·기각 모델·효과 상한을 모든 장면의 불변값으로 두지 않는다.

### 3-5. 굽는 층

사진 패치·승인 참조 이미지 생성·3D 렌더·실시간 표시를 목적에 맞게 조합한다. 도구 이름보다 승인 정체성·재질과 최종 결과를 확인한다. 당시 장비·속도·가격을 현재 실행 조건으로 재사용하지 않는다.

### 3-6. 굽는 통로

- 기존 렌더 부품: `룸굽기.js → 룸장면.py → 룸자산화.py → docs/Loom_자산/구운재질.json`.
- 생성 자산·의상: 용도별 제작기 → 누끼·표정·치수 처리 → 실제 자산 소비자.
- 살아 있는 장면: [정원 실물](../experiences/loom-living/README.md)과 공통 움직임 → 매체별 표시·출력.

세부 명령은 [굽기 규약](Loom_굽기규약.md), 앱은 [앱 연결](Loom_앱반입_설계_v1.md)을 따른다.

## 4. 자동 적용

공통 CSS 지면은 `node tools/lib/loom.js --css 문서` 등 실제 지원 프리셋을 사용한다. HTML 원고는 `펠트문서.js`, 마크다운 문서는 `룸조판.js`로 재생성한다. 웹·앱·영상의 고유 구성까지 한 CSS 파일 안에서만 만들라는 제한은 두지 않는다. 공통 값·자산은 매체의 소비자로 연결한다.

## 5. 전파와 점검

현재 관리 대상은 `node tools/lib/지면방.js --분모`와 각 생성기가 정한다. 기존 분류·재현 검사는 유지하고 과거 지면 수를 현재 분모로 복제하지 않는다. 새 중앙 큐·추가 승인 절차를 만들지 않는다.

공통 원본·코드 변경 때 실제 영향을 받는 원고·생성기·자산·관리 산출물을 함께 갱신한다. 생성 결과만 고치면 다음 빌드에서 되돌아간다. 통로와 사본 관계는 굽기 규약에서 확인한다.

## 6. 재현과 자연스러움

몸·그림자는 같은 좌표·크롭으로 다루고 공통 조명과 지면의 결을 보존한다. 투명 경계·이중 알파·원본과 이동본의 겹침·반복 이음매를 실제 배경에서 확인한다. 표정 변경은 좁은 변화 영역 밖 재질을 고정한다. 실행 성공·파일 생성·화면 확인·게시·학생 반응을 구분한다.

## 7. 현재 움직임의 기준

고정 카메라·지면, 절제된 평소 움직임, 사건 때 짧고 분명한 반응, 원래 불빛의 은은한 변화, 접지와 재질 말풍선을 함께 쓴다. 바람·깜빡임·정지·복귀의 수치와 범위는 [표현 기준](Loom_실시간장면_표현기준.md) 한 곳에서 읽는다.

## 8. 다음 발전

새 장면·표정·감각·도구는 현재 요청의 필요와 실제 결과로 발전시킨다. 옛 도입 순서나 다른 트랙 종료 대기를 선행 조건으로 두지 않는다. 제안·자산 보유·연결·실기기 확인을 구분하며 문서 정리를 새 표정이나 앱 반영 완료로 세지 않는다.
