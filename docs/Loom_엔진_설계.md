# SYNK Loom

## 1. 층 구조와 공통 부품

| 층 | 역할 | 현재 원천·통로 |
|---|---|---|
| L0 값 | 색·서체·재질·간격·감각 값 | [디자인 토큰](디자인_토큰.json) |
| L1 재질 시스템 | Felt·Resin·Glass의 참조·빛·질감 | [Felt 프로필](#material-profile), [룸장면.py](../tools/룸장면.py) |
| L1b 굽기 | 렌더·생성 결과를 배치 자산으로 변환 | [굽기 규약](#build-contract) |
| L2 부품 | 번호·불릿·칩·표지 등 재사용 요소 | [loom.js](../tools/lib/loom.js), 공방 자산 |
| L3 율 | 위계·간격·광학 정렬 | 토큰 → loom.js의 `--율` |
| L4 지면 | 문서·웹·인쇄 등의 조립 | loom.js의 `지면들`, 매체별 제작기 |
| L4.5 조판 | 구조 있는 원고를 문서로 변환 | [배치 판단층](#composition), [룸조판.js](../tools/룸조판.js) |
| L5 점검 | 기존 관리 지면의 분류·재현 확인 | [지면방.js](../tools/lib/지면방.js), 기존 시험 |

L1은 재질 시스템이며 Felt·Resin·Glass는 그 안의 프로필이다. 실시간 공통 움직임은 [loom-scene.mjs](../tools/lib/loom-scene.mjs), 웹 표시는 [loom-scene-webgl.mjs](../tools/lib/loom-scene-webgl.mjs)에 분리되어 있다.

### 부품과 율

목적에 맞는 기존 부품은 재사용한다. 새 행동·읽힘에 필요한 부품은 승인 재질·타이포에 맞춰 만들고 소비 위치에 연결한다. 목록 밖이라는 이유로 제작을 중단하지 않는다. 현재 목록은 `node tools/lib/loom.js --분모`에서 확인한다.

간격·광학 보정은 토큰과 공통 코드에서 가져온다. 숫자를 여러 문서에 복제하지 않고 실제 글자·창 크기로 줄바꿈과 위계를 확인한다.

## 2. 승인 원본과 재현

- 승인 원본·색·재질·로고는 [DESIGN](../DESIGN.md), 의상 생성의 사용자 지정 모델은 [의상 제작 정본](캐릭터/의상제작_정본.md)을 따른다.
- 표정만 바꿀 때 공통 몸·옷·털·알파를 유지하고 변화 영역만 처리한다. [표정 기준](캐릭터/캐릭터_생명감_설계.md#1-a-표정-전환의-재질-고정)과 실제 크기 반복 재생으로 확인한다.
- 기존 결과를 먼저 확인하고 필요한 원인만 고친다. 재생성이 승인 원본보다 나을 것이라고 가정하지 않는다.
- 배경 제거는 몸·의상·잔털을 보존한다. [AI누끼.py](../tools/AI누끼.py) 등 현재 도구를 쓰되 밝은 몸 소실·이중 알파·잘림을 확인한다.
- 색 변환·조명·렌더는 대상의 승인 레시피와 비교한다. 옛 AgX·PBR Neutral 실험의 판정을 모든 새 재질의 영구 금지로 확대하지 않는다.

원본·참조·레시피·파생본·소비 위치를 남긴다. 기준 자산을 교체하면 패치 좌표·색·알파·치수와 소비자를 대조한다. 원천 값만 바꾸고 소비 코드가 옛 값을 읽는 상태를 피한다.

직접 제작하거나 사용 권리를 확인한 자료를 원천으로 쓴다. 타인의 작품 참고와 반입 권한은 다르다. 학생 관찰 사실과 AI 해석을 구분하며 없는 성취·관계를 만들지 않는다. 승인 원본 교체와 새 용도 장면 제작을 구분한다.

색차를 인용할 때 조명·색 변환·측정 조건을 함께 기록한다. 한 실험의 오차 범위·조명값·회전각을 다른 자산의 면책이나 상한으로 복제하지 않는다.

<a id="material-profile"></a>

### 실행 원천

| 구분 | 원천 |
|---|---|
| 값·참조 | 디자인 토큰, 마스코트 자산 모듈, 해당 용도 정본 |
| 사진 패치·재염색 | [펠트패치.py](../tools/펠트패치.py), [펠트색갈이.py](../tools/펠트색갈이.py), 패치 장부 |
| 3D 부품·자산화 | [룸장면.py](../tools/룸장면.py), [룸굽기.js](../tools/룸굽기.js), [룸자산화.py](../tools/룸자산화.py) |
| 살아 있는 장면 | [현재 표현 기준](Loom_실시간장면_표현기준.md), 공통 움직임·표시기 |
| 만짐·재질음 | [감각 프로필](#sensory-profile), [소리 합성](../tools/감각층소리합성.js) |
| 적용·확인 | [굽기 규약](#build-contract), [앱 연결](#app-import), 관련 검사 |

패치의 원료·공용·마스코트 전용 역할은 실제 장부와 도구를 따른다. 원료 크롭을 공용 완성 재질로 노출하지 않는다. 옛 F0~F5는 프로필 내부 구분이며 별도 엔진이나 필수 개발 순서가 아니다.

사진 패치·승인 참조 생성·3D 렌더·실시간 표시를 목적에 맞게 조합한다. 재질·캐릭터·렌더러·감각은 분리해 발전시키며 보류된 리깅 시제품을 새 실시간 방식의 유일한 경로로 삼지 않는다.

<a id="build-contract"></a>

### 변환 명령

```powershell
python tools/룸자산화.py
python tools/룸자산화.py --이름 <키>
```

지원 키와 출력 대상은 현재 코드에서 확인한다. `--이름`은 해당 키만 변환하고 다른 부품의 기존 값을 보존한다.

배치용 투명 자산은 실제 알파가 남아야 한다. 몸·그림자는 같은 좌표·틀을 쓰고 받침 배경이 크롭을 방해하는지 확인한다. 제작기 옵션은 현재 코드를 읽고 고른다. 필요 없는 두 층 출력을 모든 자산에 강제하지 않는다.
