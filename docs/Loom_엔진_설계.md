# SYNK Loom — 그래픽 엔진과 제작 계약

2026-09-13 · 재질·매체 연결·조판·앱 반입·감각·굽기 규약을 통합한 정본이다. 값·승인 자산은 [DESIGN](../DESIGN.md), 엔진 간 데이터 계약은 [엔진 7종](엔진7종_상향설계_v3.md)을 따른다. 상세 동작과 수치는 [움직임 지원 매체 표현 기준](Loom_실시간장면_표현기준.md) 한 곳에서 유지한다.

<a id="purpose"></a>
## 0. 역할과 현재 기준

Loom은 재질·빛·배치·움직임을 연결해 서로 다른 매체에서도 같은 SYNK의 세계를 만드는 그래픽 엔진이다. 재현 가능한 원본과 제작 조건을 공유하고 장면에 필요한 표현은 발전시킨다.

**애니메이션을 지원하는 모든 결과물에는 [움직임 지원 매체 표현 기준](Loom_실시간장면_표현기준.md)을 기본 적용한다.** 실시간·영상은 각 매체 통로로 만들고 정적 전용 위치에는 같은 표현의 정지 컷을 쓴다. 정원의 바람 주기나 풀 개수를 모든 UI에 강제하지 않는다.

재질·색·서체·로고·마스코트는 DESIGN에서 해당 용도의 승인 원천을 선택한다. 새 부품·모델·렌더러는 현재 요청과 실제 품질에 맞게 확장한다. 과거 후보의 실패·당시 구현 없음·특정 작업의 보류를 새 표현의 영구 금지로 삼지 않는다.

의상처럼 별도 사용자 지정이 있는 제작은 [담당 정본](캐릭터/의상제작_정본.md)을 따른다. 도구 선택이 승인 원본 교체나 신규 지출까지 뜻하지는 않는다.

이번 요청에 필요한 장면·행동을 완성하고 공통 개선은 담당 원천에 반영한다. 재질·조판·반입·제작 계약은 이 문서, 상세 동작·수치는 움직임 표현 기준, 값·자산은 코드·장부에서 갱신한다. 같은 규칙을 별도 MD에 재복제하지 않는다. 작업별 시도·판정·증거는 기존 결과에 남기며, 옛 트랙·시제품 순번·고정 도입 순서를 선행 조건으로 만들지 않는다.

<a id="architecture"></a>
## 1. 층 구조와 공통 부품

| 층 | 역할 | 현재 원천·통로 |
|---|---|---|
| L0 값 | 색·서체·재질·간격·감각 값 | [디자인 토큰](디자인_토큰.json) |
| L1 재질 시스템 | Felt·Resin·Glass의 참조·빛·질감 | [Felt 프로필](#material-profile), [룸장면.py](../tools/룸장면.py) |
| L1b 굽기 | 렌더·생성 결과를 배치 자산으로 변환 | [굽기 규약](#build-contract) |
| L2 부품 | 번호·불릿·칩·표지 등 재사용 요소 | [loom.js](../tools/lib/loom.js), 공방 자산 |
| L3 율 | 위계·간격·광학 정렬 | 토큰 → loom.js의 `--율` |
| L4 지면 | 문서·웹·인쇄 등의 조립 | loom.js의 `지면들`, 매체별 제작기 |
| L4.5 조판 | 구조 있는 원고를 문서로 변환 | [배치 판단층](#composition), [룸조판.js](../tools/룸조판.js) |
| L5 점검 | 기존 관리 지면의 분류·재현 확인 | [지면방.js](../tools/lib/지면방.js), 기존 시험 |

L1은 재질 시스템이며 Felt·Resin·Glass는 그 안의 프로필이다. 실시간 공통 움직임은 [loom-scene.mjs](../tools/lib/loom-scene.mjs), 웹 표시는 [loom-scene-webgl.mjs](../tools/lib/loom-scene-webgl.mjs)에 분리되어 있다.

### 부품과 율

목적에 맞는 기존 부품은 재사용한다. 새 행동·읽힘에 필요한 부품은 승인 재질·타이포에 맞춰 만들고 소비 위치에 연결한다. 목록 밖이라는 이유로 제작을 중단하지 않는다. 현재 목록은 `node tools/lib/loom.js --분모`에서 확인한다.

간격·광학 보정은 토큰과 공통 코드에서 가져온다. 숫자를 여러 문서에 복제하지 않고 실제 글자·창 크기로 줄바꿈과 위계를 확인한다.

<a id="source-protection"></a>
## 2. 승인 원본과 재현

- 승인 원본·색·재질·로고는 [DESIGN](../DESIGN.md), 의상 생성의 사용자 지정 모델은 [의상 제작 정본](캐릭터/의상제작_정본.md)을 따른다.
- 표정만 바꿀 때 공통 몸·옷·털·알파를 유지하고 변화 영역만 처리한다. [표정 기준](캐릭터/캐릭터_생명감_설계.md#1-a-표정-전환의-재질-고정)과 실제 크기 반복 재생으로 확인한다.
- 기존 결과를 먼저 확인하고 필요한 원인만 고친다. 재생성이 승인 원본보다 나을 것이라고 가정하지 않는다.
- 배경 제거는 몸·의상·잔털을 보존한다. [AI누끼.py](../tools/AI누끼.py) 등 현재 도구를 쓰되 밝은 몸 소실·이중 알파·잘림을 확인한다.
- 색 변환·조명·렌더는 대상의 승인 레시피와 비교한다. 옛 AgX·PBR Neutral 실험의 판정을 모든 새 재질의 영구 금지로 확대하지 않는다.

원본·참조·레시피·파생본·소비 위치를 남긴다. 기준 자산을 교체하면 패치 좌표·색·알파·치수와 소비자를 대조한다. 원천 값만 바꾸고 소비 코드가 옛 값을 읽는 상태를 피한다.

직접 제작하거나 사용 권리를 확인한 자료를 원천으로 쓴다. 타인의 작품 참고와 반입 권한은 다르다. 학생 관찰 사실과 AI 해석을 구분하며 없는 성취·관계를 만들지 않는다. 승인 원본 교체와 새 용도 장면 제작을 구분한다.

색차를 인용할 때 조명·색 변환·측정 조건을 함께 기록한다. 한 실험의 오차 범위·조명값·회전각을 다른 자산의 면책이나 상한으로 복제하지 않는다.

<a id="material-profile"></a>
## 3. 재질 프로필

승인된 색·잔섬유·두께·바느질·빛을 매체가 달라도 같은 세계로 표현한다. 수공의 미세한 불균일을 유지하고 매끈한 왁스·플라스틱처럼 변하지 않게 한다. 값은 [디자인 토큰](디자인_토큰.json), 승인 자산 선택은 [DESIGN](../DESIGN.md)이 담당한다.

Felt의 섬유·두께·접촉 그림자, Glass의 투과·반사, Resin의 내부 깊이를 보존한다. 적용 위치는 DESIGN의 현재 역할과 승인 실물을 따른다. 옛 유리 번호·레진 불릿을 최근 펠트 단추·매듭점 대신 복원하지 않는다.

반사·모따기·공간감·그레인은 해당 장면에서 이득을 확인해 선택한다. 예전 단품 실험의 조명값·기각 모델·효과 상한을 모든 장면의 불변값으로 두지 않는다.

### 실행 원천

| 구분 | 원천 |
|---|---|
| 값·참조 | 디자인 토큰, 마스코트 자산 모듈, 해당 용도 정본 |
| 사진 패치·재염색 | [펠트패치.py](../tools/펠트패치.py), [펠트색갈이.py](../tools/펠트색갈이.py), 패치 장부 |
| 3D 부품·자산화 | [룸장면.py](../tools/룸장면.py), [룸굽기.js](../tools/룸굽기.js), [룸자산화.py](../tools/룸자산화.py) |
| 살아 있는 장면 | [현재 표현 기준](Loom_실시간장면_표현기준.md), 공통 움직임·표시기 |
| 만짐·재질음 | [감각 프로필](#sensory-profile), [소리 합성](../tools/감각층소리합성.js) |
| 적용·확인 | [굽기 규약](#build-contract), [앱 연결](#app-import), 관련 검사 |

패치의 원료·공용·마스코트 전용 역할은 실제 장부와 도구를 따른다. 원료 크롭을 공용 완성 재질로 노출하지 않는다. 옛 F0~F5는 프로필 내부 구분이며 별도 엔진이나 필수 개발 순서가 아니다.

사진 패치·승인 참조 생성·3D 렌더·실시간 표시를 목적에 맞게 조합한다. 재질·캐릭터·렌더러·감각은 분리해 발전시키며 보류된 리깅 시제품을 새 실시간 방식의 유일한 경로로 삼지 않는다.

<a id="build-contract"></a>
## 4. 제작·재생성 계약

- 기존 렌더 부품: `룸굽기.js → 룸장면.py → 룸자산화.py → docs/Loom_자산/구운재질.json`.
- 생성 자산·의상: 용도별 제작기 → 누끼·표정·치수 처리 → 실제 자산 소비자.
- 살아 있는 장면: [정원 실물](../experiences/loom-living/README.md)과 공통 움직임 → 매체별 표시·출력.

기존 3D 부품은 `룸굽기.js`·`룸장면.py`, 공방은 `요소굽기.py` 등 담당 제작기를 쓴다. 필요하면 `재굽기값.js`로 해당 원천 변경을 확인한다. 지원 플래그·출력 대상은 실행 코드에서 읽는다.

배치 변환은 `python tools/룸자산화.py`, 해당 키만 바꿀 때는 `--이름 <키>`를 쓴다. 몸·그림자의 공통 좌표·크롭, 실제 크기의 선명도·무게를 확인한다. 원본과 배치용 크기를 구분하고 옛 해상도·샘플 수를 전 자산의 고정값으로 쓰지 않는다.

번호·불릿의 자산·숫자 처리 범위는 `룸자산화.py`·`loom.js`가 정한다. 자수 숫자와 CSS 숫자를 중복하지 않는다. 유채 신호·칩·반복 부품의 역할은 DESIGN을 따른다.

<a id="build-cli"></a>

### 변환 명령

```powershell
python tools/룸자산화.py
python tools/룸자산화.py --이름 <키>
```

지원 키와 출력 대상은 현재 코드에서 확인한다. `--이름`은 해당 키만 변환하고 다른 부품의 기존 값을 보존한다.

배치용 투명 자산은 실제 알파가 남아야 한다. 몸·그림자는 같은 좌표·틀을 쓰고 받침 배경이 크롭을 방해하는지 확인한다. 제작기 옵션은 현재 코드를 읽고 고른다. 필요 없는 두 층 출력을 모든 자산에 강제하지 않는다.

<a id="managed-outputs"></a>

### 생성기와 관리 산출물

공통 소스 변경 때 실제 소비 생성기·관리 출력을 갱신한다. 아래는 통로의 위치이며 매 작업마다 모두 실행하는 고정 순서가 아니다.

| 원천·산출물 | 재생성 통로 |
|---|---|
| HTML 원고·엔진 소개서 | `펠트문서.js --굽기 <원고> <출력>`, 해당 전량 작업은 `--전량` |
| 마크다운 문서 | `룸조판.js <원고> --지면 문서 --내놔 <출력>` |
| 기존 손 지면 | `지면얹기.js --적용` — Loom 구간만 갱신·고유 CSS 보존 |
| Loom 시연 | `tools/lib/loom.js --시연` |
| 부품·요소·화면·히어로 시안 | 해당 `*시안.js` |
| NPC·까몽 시트, 앱 감사·이해·작동 대장 | 해당 시트·대장 생성기 |
| 크루카드 | `크루카드굽기.js` 후 `크루카드사본.js`, 정본 → 사본 일치 |
| 발표·인쇄 PDF | `발표물빌드.js --pdf`와 관련 인쇄 검사 |
| 영상 공방 요소 | `영상/자산모으기.js` 후 해당 영상 출력 |
| 실시간 장면 | [현재 표현 기준](Loom_실시간장면_표현기준.md)과 장면별 빌더 |

`지면얹기.js` 쓰기 플래그는 `--적용`이고 `--제자리`는 없다. 관리 대상은 `지면방.js --분모`와 생성기의 실제 목록에서 확인하며 통로·지면 수를 문서에 고정하지 않는다. 스타일 생성과 이미지 생성의 영향 범위를 구분한다.

공통 CSS 지면은 `node tools/lib/loom.js --css 문서` 등 실제 지원 프리셋을 사용한다. 웹·앱·영상의 고유 구성까지 한 CSS 파일로 제한하지 않는다. 공통 코드 변경 때 실제로 영향을 받는 원고·생성기·자산·관리 산출물을 함께 갱신한다. 출력만 고치면 다음 빌드에서 되돌아간다. 기존 분류·재현 검사를 이용하며 새 중앙 큐·추가 승인 절차를 만들지 않는다.

<a id="composition"></a>
## 5. 배치 판단층과 조판 계약

구현은 [룸조판.js](../tools/룸조판.js), 관련 검사는 [룸조판.test.js](../tests/룸조판.test.js)다.

원고의 제목·목록·인용·표와 배치 의도를 읽어 재현 가능한 문서 지면을 만든다. 모든 매체의 디자인 판단을 자동화한 도구는 아니다.

L4 지면과 L5 기존 점검 사이의 L4.5다. 재질·간격은 Loom, HTML 골격은 `펠트문서.js`, 대비는 `룸잉크.js`, 사용 확인은 `loom훅.js`, 관리 지면은 `지면방.js`가 담당한다.

<a id="composition-cli"></a>

### 입력·명령

요청에 맞는 형식·출력 위치를 원고 머리말 또는 CLI에 기록하고 마크다운을 블록으로 바꾼다. 지원 힌트로 배치한 뒤 원고 구조·누락·대비·자립형 출력을 검사하고 필요한 등록과 산출물을 만든다.

사용자가 형식을 생략했어도 맥락에서 합리적으로 선택할 수 있으면 진행한다. CLI가 형식·출력 경로 누락을 오류로 내는 것은 호출자가 인자를 채워야 하는 계약이며 사용자 재승인 조건이 아니다.

```powershell
node tools/룸조판.js --규격
node tools/룸조판.js docs/_원고/원고.md --지면 문서 --내놔 docs/완성.html
node tools/룸조판.js --재현
```

예시 경로는 실제 작업 파일로 바꾼다. `--등재안함`은 기존 일회성 출력 옵션이다. 관리 산출물 여부와 기존 등록 계약을 따른다.

### 지원 형식과 확장

현재 `규격들`의 구현은 `문서`다. 덱16x9·캐러셀·인쇄A4의 미구현 표시는 이 변환기의 지원 범위다. 필요한 발표·SNS·앱 작업은 DESIGN의 해당 통로를 쓰거나 도구를 확장한다. 지원하지 않는 형식을 조용히 다른 형식으로 출력하지 않는다.

웹·앱·자유 배치·데이터 시각화는 해당 매체 제작기를 사용할 수 있다. 새 힌트는 의미·변환·오류 처리를 함께 정의한다. 임의의 힌트 개수 상한이나 기존 통로 밖 제작 금지를 두지 않는다.

원고 수정 뒤 생성물을 다시 만든다. HTML 원고는 엔진 소개서처럼 `펠트문서.js`를 사용한다. 지원 형식을 늘리면 실제 입력·출력과 관련 시험으로 확인한다.

현재 힌트 어휘는 `--규격`으로 조회한다. 새 힌트·지원 형식은 실제 입력·변환·오류 처리·출력과 관련 시험을 함께 갱신한다.

<a id="app-import"></a>
## 6. SYNK-talk 앱 반입 계약

앱 계약은 SYNK-talk의 `AGENTS.md → docs/이_저장소_규약.md`에서 읽는다.

공방 정적 부품은 `tools/요소굽기.py` 등 제작기 → SYNK-talk `tools/부품변환.py` → `assets/부품/치수.json`·이미지 → `src/부품.js` → 화면으로 이어진다. 마스코트·NPC·소리·움직임은 해당 소비자를 확인한다. 정적 통로가 있다는 이유로 새 실시간 연결까지 완료됐다고 판단하지 않는다.

### 화면·자산 판단

- 어느 화면의 행동·정보를 돕는지 정하고 사용하는 자산을 연결한다.
- 현재 테마·대비·신호 역할은 [DESIGN](../DESIGN.md)을 따른다.
- 동적 수·상태는 코드가 표현하고 고정된 그림의 값을 실제 데이터처럼 쓰지 않는다.
- 원본과 앱용 크기·치수·투명 여백·무게를 구분해 확인한다.

화면과 부품을 함께 만드는 요청도 가능하다. 과거 Modal·toast 등이 없었다는 조사값을 새 기능의 금지로 삼지 않는다.

변환기의 치수와 현재 자산 모듈을 읽고 옛 부품 수·KB·화면 줄번호를 복제하지 않는다. 필요한 자산을 연결하며 승인 원본·파생본·실제 화면을 함께 최신화한다.

### 제품 경계

NPC 멘탈처럼 숨은 게임 상태의 수치·게이지 비노출은 해당 게임의 계약이다. 업로드·녹음·재생의 필요한 진행 안내까지 금지하지 않는다. 축하·표정·소리의 위치는 현재 화면의 의미와 최신 결정을 따른다. 옛 도입 대기를 모든 요청의 선행 승인으로 쓰지 않는다.

### 이름과 소비자

공방 이름과 앱 화면 이름은 다를 수 있다. `src/부품.js`의 자산 키·화면 import·라우팅을 확인하며 대응표를 이 문서에 중복 유지하지 않는다. 옛 주석보다 실제 소비 코드가 기준이다.

### 움직임 반입

[현재 표현 기준](Loom_실시간장면_표현기준.md)을 앱의 모션·마스코트·녹음 상태 처리에 연결한다. 웹 코드가 네이티브에서 그대로 실행된다고 가정하지 않는다. 빛·접지·표정·풀을 공유 시간과 이벤트로 연결하고 실제 앱에서 확인한다.

변환, 화면의 실제 자산 사용, 정지·복귀·움직임 줄이기, 실기기 표현·성능, 배포를 구분한다. 문서 정리를 앱 반영 완료나 학생 만족으로 세지 않는다.

## 7. 살아 있는 재질과 매체 연결

| 출력 | 연결 |
|---|---|
| 웹 실시간 | [공통 시간·움직임](../tools/lib/loom-scene.mjs) → [웹 표시기](../tools/lib/loom-scene-webgl.mjs) |
| 앱 | SYNK-talk의 현재 화면·마스코트·모션·자산 변환기. [앱 반입](#app-import) 참조 |
| 영상 | 기존 Remotion 통로 또는 실제 장면 녹화 |
| 정적 전용 | 같은 자산·빛·구성의 대표 정지 컷 |

[몽글과 바람의 정원](../experiences/loom-living/README.md)은 현재 로컬 웹 실물이다. 앱·영상 전체가 같은 구현으로 교체됐다는 뜻은 아니다.

평소에는 카메라·지면을 고정하고 사건 때 필요한 부위·접점이 짧고 분명하게 반응한다. 식물은 바람에, 표정은 상황에 맞춘다. 원본 전체 왜곡으로 생명감을 대신하지 않는다. 상세 동작은 별도 움직임 표현 기준을 따른다. 공통 시간·이벤트와 매체별 표시기를 재사용하며 새 모델·프레임 애니메이션·렌더러·앱 모션 도구가 필요하면 승인 원본과 실제 품질·성능을 대조한다.

### 시간의 흔적

Patina는 사용의 흔적을 재질에 남기는 설계 방향이다. 실제 기록과 소비 화면이 연결됐는지 확인하며, 달력이 지났다는 이유로 성취·관계를 만들지 않는다. 학생 간 비교나 쉬었다 돌아온 학생의 손해로 바꾸지 않는다. 새 사용처는 현재 제품 요청에 맞춰 정한다.

옛 장기 RPG 구상은 자동 착수 의무나 새 요청 금지의 근거가 아니다.

### 영상 연결

공방 요소는 이미 [영상/src/킷/공방.ts](../영상/src/킷/공방.ts)가 소비한다. `node 영상/자산모으기.js`가 원천을 영상 목록으로 변환하므로 자산 변경 뒤 필요한 목록·출력을 갱신한다. “영상에는 색·폰트만 갈 수 있다”는 옛 제한은 제거한다. 생성 영상은 정체성·재질·이음매·권리·실제 출력 품질을 확인하며 재생 영상과 실시간 상호작용을 구분한다.

## 8. Felt 감각 상호작용 프로필

눌림·소리·진동이 같은 접촉에 반응해 포근한 재질감을 돕는다. 시각 반응만으로도 의미를 전달하고 소리·촉각은 이를 보완한다.

높은 품질을 목표로 하며 기기를 임의로 저가로 단정해 상한을 낮추지 않는다. 실제 장치의 지원·설정·성능에 맞춰 출력하고 소리·촉각이 꺼져 있어도 기능이 완결되어야 한다.

| 층 | 역할 |
|---|---|
| 시각 | 접촉 부위의 눌림·복귀와 상황에 맞는 몸짓·표정 |
| 청각 | 부드러운 재질음·캐릭터의 짧은 비언어 반응 |
| 촉각 | 접촉·쓰다듬기·해제에 맞는 진동 |

### 같은 접촉과 시간

같은 접촉·상태로 세 출력을 연결한다. 평소에는 절제하고 사건 때 짧고 분명하게 반응한다. 카메라·지면을 흔들지 않고 크기와 빈도를 함께 확인한다.

과거 시제품의 타이머 방식은 해당 구현의 선택이다. `requestAnimationFrame`을 상태 기계 전체에서 금지하지 않는다. 현재 공통 장면은 시간 누적·정지·복귀를 따로 처리하므로 새 소비자에서도 그 계약과 장치 수명주기를 확인한다.

### 층별 출력

- 시각: 승인 몸·털을 보존하고 접촉 부위·그림자·눈이 함께 반응한다. 현재 깜빡임·바람 값은 표현 기준을 따른다. 옛 반응 목록의 전량 구현을 모든 화면에 요구하지 않는다.
- 청각: 변주·재생 간격으로 기계적인 반복을 줄인다. 승인 방향은 A의 부드러운 재질음과 차분하고 귀여운 고유 생명체 음색이다. 옹알이는 낱말·TTS를 대신하지 않는다. 시제품의 현재 값은 [합성 코드](../tools/감각층소리합성.js)에 있다.
- 촉각: 접촉 정보를 돕는 강도·빈도를 장치에서 확인한다. 설계의 플랫폼 기능을 실제 지원으로 단정하지 않는다.
- 무음·오디오 설정과 다른 재생 소리를 존중한다. 조작 없는 배경음·옹알이 자동 재생을 새 기본 규칙으로 만들지 않는다.

각 재질은 현재 승인 용도에 맞춘다. 캐릭터 고유 목소리·몸과 재질 효과를 구분하고 옛 후보·혼합 금지를 현재 DESIGN보다 우선하지 않는다.

<a id="sensory-cli"></a>

### 소리 자산과 시제품 명령

`node tools/감각층소리합성.js --out <디렉터리>`는 기존 시제품 통로다. 원본·합성 조건·청취 결과를 구분하고 채택 자산은 소리킷과 소비자로 연결한다. 직접 제작하거나 사용 권리를 확인한 소스를 쓴다. 시제품 생성은 앱 채택·실기기 검증 완료가 아니다.

### 부착점과 제품 경계

홈·결과 화면·녹음 중 상태 등 실제 장면의 의미를 따른다. 학습·녹음을 방해하거나 없는 성공·평가·학생 간 비교를 소리·몸짓으로 만들지 않는다. 결과 화면 도장 등 별도 제품 계약을 일반 재질 반응으로 덮지 않는다.

문서·합성 도구의 존재가 네이티브 촉각이나 모든 화면의 동기화 완료를 뜻하지 않는다. 새 연결은 실제 코드·기기에서 확인하고 남은 범위를 해당 결과에 적는다.

<a id="quality"></a>
## 9. 품질·실행·완료 확인

타일 반복·조명 얼룩·암부 섬유 소실·스미어·누끼 구멍·표정 전환의 털 교체·접지 분리를 실제 출력에서 확인한다. 과거 특정 회전각·조명값을 다른 자산·도구의 상한으로 복제하지 않는다.

몸·그림자는 같은 좌표·크롭으로 다루고 공통 조명과 지면의 결을 보존한다. 투명 경계·이중 알파·원본과 이동본의 겹침·반복 이음매를 실제 배경에서 확인한다. 표정 변경은 좁은 변화 영역 밖 재질을 고정한다. 실행 성공·파일 생성·화면 확인·게시·학생 반응을 구분한다.

실제 크기에서 정지·최대 동작·복귀·깜빡임을 비교한다. 원본과 이동본의 겹침·윤곽 뭉개짐·접지 분리·배경 전체 이동을 확인한다. 정지·화면 숨김·움직임 줄이기·긴 중단 후 복귀를 검증한다. 목적 있는 사건 반응은 분명하게 보이고 평소에는 편안해야 한다.

글의 누락, 표·중첩 목록의 의미, 실제 창 크기·인쇄에서 잘림을 확인한다. 코드 검사와 읽기 좋은 배치의 완성을 구분한다.

실제 장치에서 접촉과 출력의 지연·반복 청취·무음·움직임 줄이기·백그라운드 복귀를 확인한다. 포근함·자연스러움은 실제 눈·귀·손으로 판단하고 구현 시험과 사용자 지각·교육 효과를 구분한다.

로컬·기존 클라우드는 품질·현재 사용 조건에 맞춰 고른다. 과거 계정 버킷·장비·비용·무료 쿼터를 현재 조건으로 복사하지 않는다. 신규 지출·보호 절차는 [AI 운영 원칙](AI_운영원칙.md)을 따른다.

출력·원본/파생 관계·소비 위치를 확인한다. 종료 상태만으로 결과를 판정하지 않고 실패 시 부분 출력도 확인한다. 실행 성공·재현 검사·화면·배포·실사용은 구분한다.

제안·검수 후보를 승인·전량 적용으로 기록하지 않는다. 새 장면·표정·감각·도구는 이번 요청의 필요와 실제 결과로 발전시키며 문서 통합 자체를 새 표정 제작·앱 반영·학생 만족으로 세지 않는다.
