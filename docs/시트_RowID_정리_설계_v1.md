# 옛 Glide Row ID 정리 — 결정과 복구 근거

> 2026-10-17 정리. 09-07~08의 학원 시트 정리 설계·실행 기록이다. 10-02 학원 Apps Script가 제거됐고 온라인 1기도 취소됐으므로 ‘11월 첫 주 전 필수 실행’과 옛 배치 명령을 현재 할 일로 적용하지 않는다. 이번 문서 정리는 실제 시트·값·헤더를 변경하지 않았다.

## 유지하는 사용자 결정

09-07 사용자는 안 C, 즉 **옛 값을 복구할 수 있게 기록한 뒤 확인된 데모 행과 헤더를 정리하는 방식**을 선택했다. 이는 당시 확인한 시트·데모에 대한 결정이며 현재 원격 자료의 일괄 삭제·이관 허가가 아니다.

당시 관찰한 대상은 teacher_gold·hw_feedback·point_logs로 추정한 탭·contents였다. 실제 충돌은 hw_feedback의 12열 Row ID와 숙제ID였고, 옮길 값이 있는 행은 당시 데모 FBDEMO-01 하나였다. 이 수·탭 이름·행 번호를 오늘의 사실로 재사용하지 않는다. contents는 이름으로 읽는 자료여서 당시 정리 대상에서 제외했다.

## 재사용할 기술적 교훈

- 이름이 찬 열 수와 실제 시트 폭을 구분한다. 당시 헤더 12개였지만 시트 폭은31열이었다.
- 열 이동은 뒤 열의 값 위치도 바꾼다. 헤더만 다시 쓰면 값이 다른 이름을 가질 수 있으므로 실제 값 행을 포함해 검증한다.
- 한 배치의 보호 설정만으로 다른 쓰기 경로가 보호되는 것은 아니다. 당시 아침 정리와 야간 첨삭 경로를 함께 대조했다.
- 가짜 API의 성공과 실제 제공자 API의 동작은 다르다. 당시 moveColumns의 범위 오류는 합성 splice 대역에서 잡히지 않았다.
- 저장소 수정·배포·예약 실행·실제 데이터 결과를 구분한다. 옛 배포 성공을 현재 복구 근거로 사용하지 않는다.
