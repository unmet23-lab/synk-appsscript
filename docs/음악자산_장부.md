# 음악 자산 장부 — 어떤 곡이 어디에 있고 어떻게 다시 만드나

> 정본. 곡을 굽거나 고를 때 여기부터 연다. (2026-09-04 신설 · 유호 「폴더 하나 만들어서 모아놓으면 관리가 편할 것 같은데」)

## 🗂 실물은 git 밖에 산다 · 장부만 git 이 쥔다

| | |
|---|---|
| 원본 곡 | 바탕화면 **`SYNK 자산\음악\<장르>\`**(OneDrive 밑 · [[desktop-path-onedrive]]) |
| 이 장부 | 저장소 안 (지금 이 파일) |

### 🔀 곡이 흐르는 차례 — 폴더 순서가 곧 공정이다

`SYNK 자산` 안에서 곡은 세 자리를 지난다. 유호님이 09-04 에 사진으로 보여 주신 실물 구조다.

| 자리 | 무엇이 | 크기(09-04) |
|---|---|---|
| **`음악\<장르>\`** | 만든 곡 **원본 창고** | 10벌 · 173MB |
| **`라디오팩\`** | 그중 방송에 뽑힌 곡 · **소리만**(mp3) | 9벌 · 118MB |
| **`라디오팩_ts\`** | 거기에 **화면을 박은 판** + `playlist.txt` | 9벌 · 334MB |

🔑 **`.ts` 가 2.8배 큰 까닭 = 화면이 곡 안에 들어 있다.** 인코딩 대본(`bots/송출/인코딩.sh`) 원문:
> 곡 이름에서 장르를 읽어 그 장르의 배경을 고른다 … 화면이 곡에 «박혀» 있어 송출은 `-c copy` 그대로다(재인코딩 0). 곡이 넘어가면 마스코트도 넘어간다.

미리 합쳐 두면 송출 서버가 실시간으로 소리·그림을 합칠 일이 없다. 24시간 켜 두는 방송이라 그 차이가 크다.
⚠ 그래서 **파일 이름의 장르 조각이 배경을 고르는 열쇠**다 — `synk-radio-01-**citypop**-air.mp3` → `citypop.png`.
우리 장르 폴더 이름을 이 규칙에 맞춘 것도 그 때문이다(다른 이름을 쓰면 배경이 안 붙는다).

**왜 갈랐나** — 곡 한 벌이 wav 로 **20MB** 다. 방송용 8시간치를 채우면 수 GB 이고, 물량은 다시 구울 때마다
또 생긴다. git 은 한번 담은 바이너리를 **이력에서 못 지운다** ⇒ 저장소가 되돌릴 수 없게 부푼다.
🔑 그래서 **곡은 밖에, 「그 곡을 다시 만드는 법」은 안에** 둔다. 장부가 있으면 원본이 사라져도 되살릴 수 있다.
⚠ 이미 `docs/캐릭터` 가 1.2GB 다 — 같은 실수를 소리 쪽에서 반복하지 않는다.

### 🗂 장르 폴더 셋 (유호 지시 09-04 「장르별로 세분화」)

이름은 **내가 지은 것이 아니라** 라디오 정본에서 가져왔다 — talk `lib/라디오곡차례.js` 의
`결ascii = { 시티팝: 'citypop', 차분: 'calm', 전자: 'house' }`. 그 로마자가 실제 방송 파일 이름에 박히므로
폴더 이름을 거기 맞춰야 곡을 편성에 넣을 때 그대로 이어진다.

| 폴더 | 지금 | 무엇이 들어가나 |
|---|---|---|
| `시티팝_citypop` | 7벌 · 132MB | 아침·저녁·낮 편성 |
| `차분_calm` | 1벌 · 11MB | 새벽 편성 |
| `전자_house` | 2벌 · 28MB | 낮·밤 편성 |

### 🔴 장르 이름이 세 곳에서 갈렸다 (09-04 발견 · 아직 안 고쳤다)

| 파일 | 셋째 장르를 뭐라 부르나 |
|---|---|
| talk `lib/라디오곡차례.js` — 곡을 **만들 때** | **차분**(`calm`) |
| talk `lib/곡장부.js` — 곡을 **적을 때** | **자연** |
| talk `lib/곡편성.js` — 곡을 **고를 때** | **자연**(새벽·밤) |

`곡편성.js` 는 곡의 장르 칸으로 거른다(`겨눔.장르.includes(c.장르)`).
⇒ **「차분」으로 구운 곡이 장부에 「자연」으로 안 적히면 새벽·밤에 영원히 안 잡힌다.**
⏳ 그 사이를 잇는 다리가 있는지는 **안 재봤다** — 곡을 실제로 편성에 넣는 날 이 줄부터 연다.
🔑 이건 [[constant-known-in-two-places]] 무늬다(트랙 §0-라디오 의 「결이 두 뜻으로 갈렸다」와는 **다른** 자리 —
그건 «결 = 시간대냐 장르냐»였고, 이건 «장르 이름 자체»가 어긋난 것이다).

## 🔴🔴 가장 큰 함정 — 「작곡 도우미」가 **한국어 가사를 영어로 갈아치운다** (09-04 · 유호님이 잡으셨다)

`/compose_assist` 는 이름이 「도우미」인데 실제로는 **가사를 통째로 다시 쓴다.** 09-04 실측:

```
내가 넣은 것   → 파도 소리가 창을 두드려 / 그해 여름이 아직 여기 있어
도우미가 낸 것 → Sunlight on the highway, we're heading to the coast
```

🔴 **그래서 09-04 에 구운 곡은 전부 영어로 불렸다.** 나는 그것을 모른 채 「한국어 가사가 붙습니다」로
여러 번 보고했고, 유호님이 「지금 영어가사야」로 잡으셨다. `description`·`title` 은 그대로 두면서
**`lyrics` 만** 갈아치우므로 되돌아온 state 를 들여다보지 않으면 안 보인다.

### 🔴 09-04 처방은 틀렸다 — `/simple_generate` **도** 가사를 다시 쓴다 (09-05 소스 확인)

09-04 에 「state 를 dict 로 곧바로 넘기면 도우미 없이 그대로 된다」고 적었다. Space 소스를 읽어 보니 아니다.
`app.py` 1566~1577줄 원문:

```python
def simple_generate(state, duration, seed, randomize_seed, headroom, steps, guidance):
    state = _normalize_state(state)
    description = _composed_description(state)
    ...
    lyr, gm, vd, arr = compose_song(description, duration)   # ← 여기서 가사를 새로 짓는다
    state.update(lyrics=lyr, global_meta=gm, vocals=vd, arrangement=arr)
    for audio, status, wav, used_seed in generate(
        description, lyr, gm, vd, arr, duration, seed, randomize_seed, headroom, steps, guidance):
```

`state["lyrics"]` 를 **읽지도 않는다.** 우리가 넣은 가사는 버려지고, `compose_song` 이 설명(description)만 보고
가사를 새로 짓는다. 도우미 `/compose_assist` 는 건너뛴 것이 맞지만, **같은 일이 안쪽에서 한 번 더 일어난다.**

### ✅ 가사를 지키는 통로는 `/studio_generate` 하나다

같은 파일 1581~1589줄. `compose_song` 을 아예 안 부르고 state 의 다섯 칸을 그대로 넘긴다:

```python
def studio_generate(state, duration, seed, randomize_seed, headroom, steps, guidance):
    state = _normalize_state(state)
    for audio, status, wav, used_seed in generate(
        state["description"], state["lyrics"], state["global_meta"], state["vocals"],
        state["arrangement"], duration, seed, randomize_seed, headroom, steps, guidance):
```

⏳ **아직 안 재봤다** — 09-05 새벽에 만든 한국어 가사 곡들이 «우리 가사»로 불렸는지는 확인하지 않았다.
설명 칸에 한국어를 넣었으니 `compose_song` 이 한국어로 **다시** 지었을 수 있다(비슷하되 우리 것이 아닌 가사).
🔑 **곡을 받으면 가사가 내 것인지 먼저 확인한다.** 안 들어 보고 「한국어가 붙었다」고 말하지 않는다.

## 📏 곡 «길이»는 무엇이 정하나 — 씨앗이다 (09-04 실측 · 내 가설이 틀렸다)

`duration` 을 240 으로 줘도 그대로 안 나온다. 처음엔 「가사 분량이 정한다」로 읽었는데 **틀렸다**:

| 판 | 가사 | duration | 실제 길이 |
|---|---|---|---|
| 씨앗777 | 짧은 판 | 240 | 2분 44초 |
| **씨앗1234** | **같은 짧은 판** | 240 | **3분 24초** |
| 씨앗8888 | **두 배로 늘린 판**(절 2·후렴 3·브리지 1) | 240 | 2분 59초 |

⇒ 가사를 두 배로 늘려도 **15초**만 늘었는데, 같은 가사에 씨앗만 바꾸니 **40초**가 갈렸다.

🔴 **그런데 이 표는 자가 틀린 자리에서 쟀다** (09-05 확인). 셋 다 `/simple_generate` 로 구웠고, 위 절에서 보듯
그 통로는 **우리 가사를 버리고 스스로 짓는다.** 「가사를 두 배로 늘렸다」는 칸은 실제로 모델에 안 닿았다.
⇒ 「길이는 씨앗이 정한다」는 결론은 **아직 서지 않았다.** 가사가 실제로 닿는 `/studio_generate` 로 다시 재야 갈린다.

### 🔴 상한은 3분이 아니라 5분이다 (09-05 소스 확인 · 앞 판은 틀렸다)

`app.py` 1631줄이 길이 손잡이의 상한을 못 박는다:

```python
duration = gr.Slider(5, 300, value=60, step=5, label="Maximum song duration (seconds)")
```

**300초(5분)까지 받는다.** 09-04 에 셋 다 3분을 못 넘긴 것은 통로의 상한이 아니라 위의 «가사가 안 닿는» 문제로 보인다.

📏 가사 분량이 길이를 정한다는 규칙이 소스에 박혀 있다(`_LYRICS_RULES` · 481줄 원문):
> "Size the structure to the duration: <=30s: one verse + one chorus; ~60s: verse/pre-chorus/chorus/verse/chorus;
> **>=120s: full structure with bridge and outro**" · "Roughly **12-16 sung words per 10 seconds**"

⇒ 5분 곡을 노리면 가사를 **360~480 낱말**로 짜고 구역 표시를 충분히 넣는다.
쓸 수 있는 표시는 `[intro] [verse] [pre-chorus] [chorus] [post-chorus] [bridge] [instrumental] [solo] [outro]`
(각 표시는 **제 줄에 혼자** 있어야 하고, 같은 줄에 노랫말을 붙이면 안 된다).

⚠ `duration 290` 실패(`Expired ZeroGPU proxy token`)는 여전하다. 남의 실행 자리를 예약하는 시간이
소스(1101·1105줄)에는 `duration × (0.75 + 0.20 × steps/30) + 15` 초로 적혀 있다(상한 600초).
⇒ steps 를 30에서 낮추면 예약 시간이 줄어 더 긴 곡이 통과할 수 있다. ⏳ 안 재봤다(steps 는 음질도 건드린다).

🔴 **09-05 실측 — 서버가 실제로 요구하는 몫은 그 공식의 «정확히 2배»다.** 거절 메시지가 요구량을 말해 줘서 두 점으로 풀었다:

| 곡 길이 | 서버가 요구한 몫 | 소스 공식이 낸 값 |
|---:|---:|---:|
| 120초 | **258초** | 129초 |
| 60초 | **144초** | 72초 |

⇒ **몫(초) = 곡 길이 × 1.9 + 30** (steps 30 기준). 몫이 얼마 남았는지 셈할 때는 이 자를 쓴다.
🔑 거절 메시지가 «요구량 · 남은 양 · 회복 시각»을 다 준다(`258s requested vs. -55s left. Try again in 5:28:47`)
 ⇒ 굽기 전에 남은 몫을 따로 물을 자리가 없어도, 한 번 거절당하면 그 답이 전부 나온다(거절은 몫을 안 먹는다).

### ⇒ 4분 넘는 판은 «이어 붙여» 만든다

원래 라디오 공정이 그랬다(Lyria 때도 생성물 셋을 이었다 · `tools/라디오곡생산.js` 머리말).

```

  -filter_complex "[0][1]acrossfade=d=4:c1=tri:c2=tri[a];[a][2]acrossfade=d=4:c1=tri:c2=tri" \

```

- 🔑 **서로 다른 곡 셋을 이으면** 반복이 아예 안 들린다(같은 곡 반복보다 낫다).
- ⚠ 방송 판 규격이 **최소 360초**라 5분 52초(352초)는 8초 모자란다 — 넷을 잇거나 한 곡을 더 길게 고른다.
- 🔴 **같은 곡을 통째로 세 번 잇는 것은 티가 난다** (09-05 유호 「그냥 2분짜리 계속 반복만 하네」).

### 🧩 씨앗 없는 곡을 «마디를 안 깨고» 늘리는 법 (09-05 실측 · ⚠ 새 소리는 안 생긴다)

같은 곡을 반복해도 티가 안 나게 하려면 **덩이를 나눠 순서를 바꾸고 변주를 섞는다.**
`_씨앗없음_citypop_vocal_고친판` 으로 실제로 해서 2분 → **4분 17초**를 만들었다.

| 걸음 | 무엇을 | 값 |
|---|---|---|
| ① 마디 길이를 구한다 | `60 ÷ BPM × 4` | 112 BPM → 한 마디 **2.142857초** |
| ② 8마디 덩이로 자른다 | `17.142857초` | 120초 곡 = **정확히 7덩이** |
| ③ 덩이별 음량을 재 구조를 읽는다 | `volumedetect` | 큰 덩이 = 후렴 |
| ④ 변주 덩이를 만든다 | 아래 두 줄 | |
| ⑤ 순서를 짜 `concat` 으로 잇는다 | 마디가 맞으면 크로스페이드가 필요 없다 | |

```
# 반음 위로 (피치만 · 속도 유지) — R=1.059463
#   🔴 넉넉히 잘라 넣고 atrim 으로 못 박는다. 안 그러면 13ms 짧아져 마디가 밀린다
ffmpeg -ss <시작> -t 18.4 -i <원본> \
  -af "asetrate=44100*1.059463,atempo=1/1.059463,aresample=44100,atrim=0:17.142857,asetpts=N/SR/TB" <덩이>

# 보컬을 줄여 «연주 구간»처럼 (가운데 소리 빼기)
ffmpeg -i <덩이> -af "pan=stereo|c0=0.9*c0-0.55*c1|c1=0.9*c1-0.55*c0,volume=2.0" <덩이>
```

🔑 **마지막 후렴을 반음 올리는 것이 핵심이다** — 시티팝·J-POP 의 정석 수법이라 같은 소리인데 «전개»로 들린다.
실제로 쓴 차례 = `원곡 7덩이 → 연주 2덩이 → 절부터 3덩이 → 후렴 3덩이(반음 위)` = 15덩이 · 257초.

## 🩹 잘린 곡은 «고칠 수 있다» — 다시 못 굽는 곡을 살리는 길 (09-04 실측)

씨앗을 안 남긴 곡은 다시 못 만든다. 그런데 **음질만 나쁜 것이라면 그 파일 자체를 고칠 수 있다.**
유호님이 「너무 좋은데??」 하신 `_씨앗없음_citypop_vocal` 이 잘림 3,385곳짜리였고, 그것을 이렇게 살렸다:

```
ffmpeg -i <원본> -af "adeclip=window=55:overlap=75:arorder=8:threshold=10:hsize=1000:method=add,
                       loudnorm=I=-14:TP=-1.5:LRA=11" -ar 44100 -c:a pcm_s16le <고친판>
```

| | 원본 | 고친 판 |
|---|---|---|
| 꼭대기 | 0.000000(천장에 붙음) | **−1.48**(떨어졌다) |
| 천장 친 수 | **3,385곳** | **1곳** |
| 평평함(잘림) | **26.8** | **0.0** |
| 음량 | −11.4 LUFS | **−13.9 LUFS**(방송 규격 −14) |

- 🔑 `adeclip` 이 잘려 나간 파형을 앞뒤 소리로 **추정해 메운다**. ⚠ «되살리는» 것이 아니라 «추정»이므로
  숫자가 좋아져도 **귀로 한 번 더 확인**한다.
- 🔴 **`-ar 44100` 을 빼면 안 된다** — `loudnorm` 이 표본율을 192kHz 로 올려 파일이 4배가 된다(09-04 실측 88MB).
- 🔑 원본은 **지우지 않는다.** 고친 판은 원본에서 파생되므로, 원본이 사라지면 다시 고칠 수도 없다.
