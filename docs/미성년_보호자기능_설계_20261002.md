# 미성년 보호자 기능 · 나라별로 켜는 모듈 (2026-10-02 · 설계)

> **읽기 기준 · 2026-10-17:** 10-02의 법률 조사·제품 제안·열린 질문을 보존한 문서다. 이번 문서 정리에서 법령·스토어 API·현지 적용 범위를 재확인하지 않았으며 아래 표를 최신 법률 확인이나 구현 완료로 쓰지 않는다. 일반 가입·계정 연결의 후속 상태는 [플랫폼 계정](SYNK_플랫폼_계정과_연결_설계.md), WORLD 현재 범위는 [앱 README](../experiences/synk-world-app/README.md)를 따른다. 일반 계정 가입이 구현됐다는 사실과 미성년 보호자 모듈의 구현·검증은 별개다.

> 2026-10-02 사용자 결정 「응 둘 다 넣고 가입 까지 전부 진행해줘」로 브라질이 앱 출시 목록에 들어갔다. 브라질은 미성년 보호법 ECA Digital을 지키는 보호자 기능을 출시 전에 만든다([결정 표](_ops/결정.md) 10-02). 같은 날 「다 니가 알아서 해줘」로 범위는 Claude가 정했다. **나라별로 켜는 모듈 하나로 만들고 처음에는 브라질에서만 켠다.** 다른 나라는 그 나라 법이 요구할 때 켠다.
>
> 이 문서는 설계다. 앱(talk)·서버·웹 코드는 바꾸지 않았다. 이 세션은 법률가가 아니다. 공개 출시 전에 브라질 현지 법률 확인을 받는다.

## 1. 지키는 원칙

- **나이를 묻지 않는다(09-19 확정)는 그대로다.** 브라질에서도 생년월일이나 나이 입력 화면을 새로 두지 않는다. 앱스토어가 넘기는 나이 신호(ECA Digital 12조가 스토어에 의무로 둔 API)로만 판단한다. 신호를 받을 수 없을 때의 대안은 §6의 열린 질문이다.
- **나이는 법을 지키는 데만 쓴다.** 받은 나이 구간은 Atlas의 맞춤 입력에 넣지 않는다([철학 v3.0](SYNK_철학.md): 맞춤 입력에 나이·성별·국적을 넣지 않는다). 생년월일은 받지 않고 구간과 받은 때만 둔다. 계정을 지우면 함께 지운다.
- **보호는 막는 것보다 기본값으로 한다.** 미성년의 기본값을 안전하게 두고, 보호자가 풀 수 있게 한다. 학습(한글 단계·초급 학습·미니게임)은 막지 않는다.
- **AI를 부르지 않는다.** 이 모듈의 판단·화면·기록은 모두 규칙으로 처리한다. 늘어나는 비용은 서버 저장 약간뿐이다.

| 24조 | 16세 이하 계정은 보호자 계정과 연결한다(「소셜 네트워크」 장 — 학습 앱 적용 범위는 현지 확인) | **B. 보호자 연결** |

## 3. 흐름

### A. 나이 신호 받기

1. 앱을 처음 열 때와 로그인할 때, 기기의 나라가 모듈이 켜진 나라(처음에는 브라질)이면 스토어의 나이 신호를 요청한다. 나라는 지금처럼 기기에서 읽는다(공개판 §2).
2. 결과를 넷으로 나눈다: `아동(12세 미만)` · `청소년 16세 이하` · `청소년 17세` · `성인`, 그리고 `알 수 없음`.
3. 서버에는 `나이구간`, `받은 때`, `출처(스토어)`만 남긴다. 다시 받으면 덮어쓴다.
4. `성인`이면 지금 앱 그대로다. 나머지는 B·D로 간다.

### B. 보호자 연결 (아동·16세 이하 청소년)

1. 앱이 포르투갈어로 「보호자와 연결하면 모든 기능을 쓸 수 있어요」라고 보여 주고, 보호자에게 보낼 링크·QR을 만든다(유효 7일, 한 번만 쓰임).
2. 보호자는 자기 기기에서 링크를 열고, 구글·애플로 로그인해 보호자 계정을 만든다. 보호자 계정은 학습 계정이 아니라 보호자 화면(C)만 있는 계정이다.
3. 보호자가 포르투갈어로 된 동의 글(무엇을 모으나·왜·얼마나 두나·지우는 법)을 읽고 동의한다. 12세 미만은 이것이 LGPD 14조의 부모 동의다.
4. 서버가 `보호자 연결 기록`을 만든다: 두 계정, 동의 문안의 판과 언어, 때. 연결을 끊거나 다시 맺으면 기록을 더한다.
5. **연결 전에 쓸 수 있는 것** [제안 · 현지 확인]: 한글 단계·초급 학습·미니게임(학습은 막지 않는다). 연결 전에는 구매, 마을의 사용자 간 소통, 알림이 꺼져 있다.

`청소년 17세`는 보호자 연결을 요구하지 않는다(24조는 16세 이하). 다만 D의 기본값 중 구매 확인은 같게 둔다 [제안].

### C. 보호자 화면 (웹, 포르투갈어)

| 화면 | 할 수 있는 것 |
|---|---|
| 계정·개인정보 | 자녀 계정의 설정·개인정보 선택 동의 보기·바꾸기, 계정 지우기 요청 |
| 구매 | 앱 안 구매 켜기·끄기(기본 꺼짐). 켜도 스토어 쪽 부모 통제(구매 승인)는 그대로 겹친다 |
| 사용 시간 | 하루·주 합계 보기, 하루 한도 정하기(기본 없음). 한도에 닿으면 앱은 「오늘은 여기까지」 한 줄로 부드럽게 멈춘다. 재촉·보상은 없다 |
| 마을 소통 | 사용자 간 이모티콘 소통 켜기·끄기(기본 꺼짐). 다른 주민의 나이는 알 수 없다는 것을 함께 알린다 |
| 알림 | 켜기·끄기(기본 꺼짐) |
| 보호 상태 표시 | 지금 켜진 보호 장치 목록. 자녀 앱에도 「보호자 설정이 켜져 있어요」가 보인다(17조 III) |

- 보호를 끄는 쪽으로 이끄는 문구·색·순서를 쓰지 않는다(18조 §2).
- 보호자 화면은 synk.im 아래 웹에 둔다. 앱을 깔지 않은 보호자도 쓸 수 있어야 한다.

## 5. 만들 곳과 순서

- **작업 묶음:** [공개판 설계 §10](공개판_설계.md)의 PW18. 앞선 조건은 PW1(공개 가입)·PW6(약관·동의 첫 판)이다. 공개 가입이 없었던 10-02에는 가입과 함께 만들도록 계획했다. 이후 일반 계정 구현을 다시 미완료로 돌리지 않고, 현재 가입·동의 계약에 이 모듈의 별도 보호자 연결과 기본값을 붙여 검증한다.
- **순서:** ① A 나이 신호(브라질 스토어의 실제 제공 상태 확인부터) → ② D 미성년 기본값(앱 설정의 기본값 분기) → ③ B 보호자 연결(링크·보호자 계정·동의 기록) → ④ C 보호자 웹 → ⑤ 포르투갈어 글 전부와 심사용 설명.
- **인수 기준:**
  1. 브라질 기기에서 스토어 신호가 16세 이하이면, 연결 전에는 구매·마을 소통·알림이 열리지 않는다. 학습은 된다.
  2. 보호자가 연결하고 켠 것만 열린다.
  3. 나이 구간이 Atlas의 어떤 맞춤 계산에도 들어가지 않는다(시험으로 확인).
  4. 모듈이 꺼진 나라에서는 지금 흐름과 한 화면도 달라지지 않는다.
  5. 계정을 지우면 나이 구간·연결 기록 사본·사용 시간이 함께 지워진다(법정 보관분은 따로).
- **E. 회사 쪽 준비(코드 아님):** 브라질 법정 대리인 계약(현지 대리 서비스·법무법인), 개인정보 처리방침에 대리인 표기, 포르투갈어 약관·처리방침, 브라질 스토어 연령 등급 신고(소액결제가 등급 요소다 — 에이전트 조사, 시행령 원문은 미대조).

## 6. 열린 질문 · 현지 법률 확인

1. 24조(16세 이하 보호자 연결)가 소셜 네트워크가 아닌 학습 앱에 어디까지 걸리는가. 걸리지 않으면 B는 아동(12세 미만)과 LGPD 동의에만 둔다.
2. 스토어 나이 신호를 받을 수 없을 때(기기·스토어가 아직 제공하지 않을 때) 무엇으로 대신하는가. 후보는 브라질에서만 나이 구간(생년월일 아님)을 한 번 고르게 하는 것이다. 이 경우 09-19의 「나이를 묻지 않는다」에 브라질 예외가 생기므로 **[사용자]** 확인이 필요하다.
3. 마을의 이모티콘 소통이 21조의 「사용자 간 상호작용」에 드는가. 들면 D의 기본값(닫힘)으로 충분한가.
4. ANPD 시행령의 세부 기준(보호자 도구의 최소 기준, 보관 기간).
5. 다른 출시국에도 비슷한 법이 있는가. 있으면 그 나라에서 이 모듈을 켠다. 이번에는 조사하지 않았다.
