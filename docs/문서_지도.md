## 작업에 맞게 더 읽기

- **기업 홈페이지:** [현재 제작 기준](홈페이지_설계_v1.md). 챗봇 중심 구조와 공개 문서로 답할 범위, 실제 구현·미구현을 구분합니다.
- **홍보 실행:** [마케팅 정본](마케팅_정본.md) → 해당 회사·채널·행사·광고 문서. 옛 편수·발행 일정·폐기된 시안을 현재 작업 기준으로 되살리지 않습니다.
- **보존할 세부:** 교육·계약·데이터 규격과 승인 원본은 해당 상세 문서에 둡니다. 과거 검토·완료된 설계 조각·중복 요약은 현재 읽기 경로에서 제거하며, 필요한 당시 증거는 Git의 고정된 판으로 연결합니다.

- GPT [AGENTS.md](../AGENTS.md) · Claude [CLAUDE.md](../CLAUDE.md) · Gemini [GEMINI.md](../GEMINI.md)는 각각의 진입 지침입니다. [공통 운영 원칙](AI_운영원칙.md)을 읽고 이번 작업의 관련 자료를 고릅니다.
- [결정](./_ops/결정.md) · [남은 일](./_ops/트랙.md)은 현재 파일·작업 사본·PR의 증거와 대조합니다. 후속 작업에서는 [최신 상태 확인](AI_운영원칙.md#세션-사이-최신-상태) 뒤 실제 사용할 원문·자산을 다시 읽고, 결과가 사용한 원본과 지금 원본의 차이를 확인합니다. 바탕화면·Drive 공유 사본을 제작 정본으로 삼지 않습니다.
- 전체 최상위 문서 이름이 필요할 때만 [상세 문서 색인](자료안내/상세_색인.md)을 엽니다. 파일명의 날짜·v숫자만으로 현행 여부를 정하지 않습니다.
- 큰 정본은 목차를 먼저 찾고 관련 절·연결 계약을 읽습니다. 예: `rg -n "^#{1,3} " docs/엔진7종_상향설계_v3.md`. 요약은 원본의 계약·예외를 대신하지 않습니다.

## 원본과 공유 사본

바탕화면·OneDrive·Google Drive의 회사별 자료는 공유 사본입니다. 요청받아 갱신할 때 기존 `tools/이어하기꾸러미.js`를 사용하며, 실행 전 복사 대상과 외부 전달 범위를 확인합니다. 개인 기억·저장소 전체·인증 정보를 꾸러미에 넣지 않습니다.

확정 4K PNG·앱용 AVIF·편집 원본은 서로 역할이 다릅니다. 완성작·원본·진행 중 사본을 폴더 이름이나 크기만으로 지우지 않습니다. 관련 정본·코드의 참조와 복원 수단을 확인한 뒤 정리합니다. 코드·추적 문서의 이전 판은 Git 이력에서 찾되, 무시된 파일은 Git만으로 복구되지 않습니다.
