같은 날짜와 시각의 양쪽 원본이 도착하면 비교한다. 한쪽에서만 찾은 공고와 AI 허용·조건, 마감, 필수 제출물이 다른 공고는 기존 구독의 카본이 공식 원문으로 확인한다. 같은 회차에서 반복한 공고는 따로 센다. 주최사 원문과 일치하는 인용을 찾지 못한 항목은 확인 필요로 둔다. 원본 도착 전, 출처 접근 실패, 조사 결과 0건을 구분한다.

## 읽고 갱신하는 순서

1. `통합현황.md`에서 적용 조건과 마지막 확인일을 읽고 `신청현황.md`로 이미 제출한 것과 보류된 것을 확인한다.
2. 같은 공고는 연도·회차·주관기관·공고번호로 맞춘다. 과거 추천판정, 최신 공고 검증, 실제 신청 상태는 따로 유지한다.
   **결과 제외 기준(2026-11-10 사용자 확정): AI 사용·주요 창작의 AI 제작이 금지된 공모, 현재 신청자 자격 미달이 확인된 공고는 조사 결과·후보 목록·추천·건수에 포함하지 않는다.** 제외 근거는 내부 중복 방지 기록으로만 보존하고 별도 후보표로 다시 보여 주지 않는다. 자격·AI 허용 여부가 미확인이면 신청 가능으로 확정하지 않고 조건 확인으로만 둔다. 실제 신청·선정 기록은 보존한다. **자격 거르기 장치(2026-11-20):** 그록 · Gemini 조사와 공모 지도가 자격을 보지 않아 제천시민만 낼 수 있는 공모가 후보로 올라왔다(유호님 「그런것들은 아예 리스트업에서 뺴줘」). 그래서 `tools/공모자격.js`가 열린 공고의 원문에서 응모 자격 문장을 카본으로 인용하고, 비공개 보관함의 `신청자조건.json`과 맞대어 `자격판정.json`에 「됨 · 안 됨 · 확인 필요」를 쌓는다. 카본에는 공고 글만 보내고 개인 조건은 보내지 않는다. 공모 지도는 「안 됨」을 빼고, 「됨」이 아닌 공고에 「자격 확인 필요」를 단다. 사람이 확인한 자격 미달은 `node tools/공모자격.js --제외 "<제목 조각>" --까닭 "…"`로 넣는다. 유호님께 후보를 보고할 때는 「안 됨」을 빼고, 「확인 필요」는 원문 자격을 확인한 뒤에만 낼 후보로 올린다.
   **바우처 하청(2026-11-17 사용자 확정):** 남의 수행기관 밑에서 바우처 대금으로 받는 하청 제안은 받지 않는다. SYNK가 직접 공급기업으로 등록하는 길은 별개다([결정](../_ops/결정.md) 11-17).
3. 새 확인은 정본에 날짜·출처·변경 이유를 남긴다. 조사 날짜가 지난 마감·예산·사업자등록·중복수혜 조건은 실제 신청 전에 공식 공고로 다시 확인한다.
   목록 수집, 상세 검토, 현재 자격 충족을 같은 건수로 세지 않는다. 이전 원자료에서 정본으로 편입한 항목과 처음 확인한 후보도 구분하고, 이번에 원문을 다시 읽지 않은 항목의 확인일을 갱신하지 않는다.
4. **결과 발표 전 공개 금지 공모(2026-11-18):** 공모지침이 결과 발표 전에 참가 사실, 공모안 내용, PIN 같은 응모 번호를 공개하지 말라고 하면, 이 공개 저장소(트랙, 결정 표, 현장 노트, 커밋 메시지)에는 공모 이름을 쓰지 않고 「결과 발표 전 공개 금지 공모」로만 적는다. 이름, 상태, 번호는 비공개 보관함의 신청현황과 그 공모의 제출기록에만 둔다. 공고를 처음 읽을 때 이 조항이 있는지 보고 신청현황 `next`에 적는다.
5. 상금·사업화자금·투자·현물·서비스, 접수·선정·지급을 구분한다. 조사나 저장 요청을 기관 문의·신청서 제출·게시 승인으로 바꾸지 않는다.

기존 제출본·증빙 원본은 해당 작업 폴더를 유지하고, 정본에서 그 위치를 연결한다. 이 문서와 [문서 지도](../문서_지도.md)는 공통 입구이며 개별 후보·개인 상태를 별도 사본으로 반복 기록하지 않는다.
