## 책임과 완료 확인표

Atlas는 기존 8개 엔진의 총칭이다. 제품은 목적, 입력 의미, 후보, 필수 제약, 결과 측정법을 제공한다. 담당 엔진은 공통 이해·선택·기록·평가 절차를 제공한다. 인증·동의·저장·모델 호출은 기존 호스트와 공식 경로를 쓴다. 다른 사업의 개인정보를 합칠 권한은 생기지 않는다.

## Core: 분야별 의미와 근거 해석의 분리

원본 [`atlas/domain.js`](../atlas/domain.js)는 Core의 선택적 능력이다. 기존 어댑터의 `Personalization.domain`으로 접근한다. Node에서는 필요한 때 모듈을 읽고, 브라우저의 사용 소비처만 `domain.js`를 명시적으로 싣는다.

- 계약은 `id/version/purpose/fields/criteria`. 제품이 enum·boolean·number 속성, 근거 수명·독립 표본·합의 기준, 숫자 범위와 선택 조건을 정한다. 이 값은 명시 정책이며 성향 정확도 확률이 아니다.
- 범위는 기존 Core의 `{domain, workspace, subject}`. 관측마다 계약의 `{id,version,purpose}`도 확인한다. 같은 속성 이름을 다른 목적으로 재해석할 수 없다.
- `declared/observed/inferred`를 구분한다. 반복·재전송은 독립 근거를 늘리지 않는다. 미확인 추정은 유효 원천을 참조한 제안으로 남고 사실처럼 추천에 쓰이지 않는다.
- 사건 시각과 알려진 시각을 모두 적용한다. 정정은 실제 이전 근거를 참조하고 순환 정정은 거절한다. 최신 선언의 철회·만료 또는 관측의 품질 하락 뒤에 옛 값을 되살리지 않는다.
- 결과는 선언·근거 충족·부족·모순·미확인·사용 불가·만료·철회를 구분한다. 필요한 재확인 항목도 반환한다.
- 제품의 적격 후보에 필수 조건을 적용한 다음 정책 가치로 정렬한다. 필수 근거가 없으면 억지 후보를 만들지 않는다. 선택·탈락 이유, 실제 근거와 당시 계약·후보 사본을 반환한다.
- 관측의 외부 원문 참조와 인증·동의는 호스트가 확인한다. 이 모듈에는 구조화 값과 참조만 보낸다. 원문이나 모델의 자유문장을 자동으로 사실로 승격하지 않는다.

검증: [`atlas-domain.test.js`](../tests/atlas-domain.test.js). 업무·구매 합성 사례의 재사용과 계약 오용을 검사하며 실제 고객 추천 효과의 증거는 아니다.

## Core: 다음 질문의 기대 가치

`Ask.rank/choose/fromAtlas`는 선택적으로 `evaluate({decision,answers,question,option}) → {utility?,loss?}`를 받는다. 같은 가정 아래 기존 결정과 새 결정을 비교한다. `value = responseProbability × expectedGain − cost`이며 실제 결정이 달라지고 가치가 양수일 때만 묻는다. 평가값과 비용의 단위는 제품이 일치시킨다. `impact`는 변화량, `value`는 선언된 정책 기대 가치로 구분한다.

평가기를 넘기지 않은 기존 소비처의 동작은 유지한다. 선택지 `p`는 전부 생략하거나 모두 명시하여 합이 1이어야 한다. 이전의 혼합·비정규 가중치는 거절한다. 확인한 기존 소비처는 `p`를 생략한다. 검증은 [`atlas-ask-value.test.js`](../tests/atlas-ask-value.test.js)와 기존 Ask 시험이다.

실제 소비는 [`atlas-lab/consultation.mjs`](../experiences/atlas-lab/consultation.mjs)다. 기존 컴퓨터 도구의 규칙을 재사용해 작업 메모리·저장·그래픽 메모리 부족, 불필요한 사양, 명시한 휴대·OS 조건, 기존 기기 확인과 예산 경고 누락을 비교한다. 가중치와 균등 응답 시나리오는 제품 정책이며 실측 확률·가격·만족도 예측이 아니다. 복수 작업은 실제 화면에서 함께 선택·해제·확정할 수 있으며, 원본이 허용하는 63개 조합을 내부 시나리오로 비교한다. Core의 보기 상한은 64개로 제한한다. 행동·OS 충돌은 원본 규칙의 의미 코드로 전달해, 문장이나 출처 이름만 보고 중요 조건을 생략하지 않는다. 별도 영구 캐시는 추가하지 않았다.

## Temper: 실제 전달과 미관측의 구분

[`atlas/temper-outcomes.js`](../atlas/temper-outcomes.js)의 `evaluateOutcomes`는 제품 결과 계약, 승인된 사람 목록, 결정·전달·결과를 받는다. 결과는 binary 0/1 또는 허용 범위의 숫자다. 개선 방향과 관측 기간은 제품이 정한다. 계약·정책판, 선택 후보, 사람·목적·작업공간·시간이 고리 전체에서 일치해야 한다. 선택적 `recordedAt`은 실제 접수 시각이며, 늦게 받은 결과를 과거 평가에 소급 삽입하지 않는다.

미선택·미전달·관측 대기·누락·늦은 응답을 구분한다. 종료된 관측 기간만 평균에 사용하고 반복 사용은 사람당 평균으로 묶는다. 비용·지연의 기록 누락을 밝히고 비용 단위를 자동 환산하지 않는다. 최소 인원은 비교 준비 기준이며 검정력이나 효과 증명이 아니다.

현재 비교는 공급된 관측의 기술통계다. 무작위 배정이나 선택 확률이 없는 기록으로 인과·유의성·자동 정책 승격을 선언하지 않는다. 정책·모델 교체 시 관측 품질과 회귀를 비교하는 공통 기반이다. 검증: [`atlas-outcomes.test.js`](../tests/atlas-outcomes.test.js). 기존 학습용 API는 유지한다.

### 계약 판본과 결과 정정·철회 — 2026-10-06

`evaluateOutcomes`에 선택적 `strictProvenance`와 추가 기록 배열 `revisions`를 연결했다. 엄격 모드 또는 정정·철회 기록이 있으면 전달과 결과에도 `{id, version}` 계약 참조가 필요하다. 명시한 계약이 다르면 일반 모드에서도 거부한다. 기존 호출은 선택 항목을 생략할 수 있고 반환 형식도 유지한다.

정정·철회 기록은 `id/subject/scope/contract/at/targetId/action/sourceRef`와 선택적 `recordedAt`, 정정 시의 `value`를 가진다. `targetId`는 원결과나 직전 정정 기록을 가리키며 `action`은 `correct` 또는 `withdraw`다. 사람·범위·계약·발생/접수 순서, 분기·순환·ID 충돌을 검사한다. 정정은 이미 보고한 값만 바로잡고 원응답의 시점·관측창을 연장하지 않는다. 철회한 결과는 되살리지 않으며 새 행동·의향은 새 관측으로 기록한다. `sourceRef`에 해당하는 원사건의 실제 권한·동의는 호스트가 확인한다.

엄격 모드의 `provenance`에는 결정→전달→원결과→정정·철회 이력이 남는다. 철회해도 실제 전달은 유지하며 결과 평균에서만 제외한다. 관측창이 끝난 철회 결과는 유효 응답이 없는 `missing`에 포함하되 계보 상태는 `withdrawn`으로 구별한다. 이를 실패나 부정 응답으로 바꾸지 않는다.

실제 소비처인 [SHIFT 작업실](../experiences/shift-workbench/model.mjs)은 새 전달·결과에 계약판을 기록하고, Core의 완료 제외 원사건을 철회 기록으로 투영한다. 구형 저장은 범위·결정·완료 계보를 검사한 뒤 평가 사본에만 계약 참조를 보충하며 저장 원문은 바꾸지 않는다. LAB은 기존 교육용 Core·Trail·Temper API를 유지한다. [LAB·SHIFT 관통시험](../tests/atlas-cross-product-boundaries.test.mjs)은 실제 제품 어댑터와 생성된 LAB 번들을 실행한다. SHIFT의 가상 업무 연습 결과는 실제 고객 업무 성과나 첫 유료 고객 적용의 증거가 아니다.

## 기존 정책과 학습 근거 정리

Core `atlas-2.4.0`은 완료 후 무응답에 주던 약한 긍정 가중치를 제거한다. 제외한 결정의 파생 완료·피드백도 판단에서 제외하며 실제 경험 회차 이력은 남긴다. 이전 1.0~2.3 사건은 읽고 새 판단만 새 정책판으로 기록한다. 검증은 [`atlas-no-feedback.test.js`](../tests/atlas-no-feedback.test.js)와 기존 회귀다.

Trail의 제외된 음성 전달 근거가 독립 듣기 수행으로 남는 문제는 배치·증분 경로를 함께 수정했다. 도움·첫 노출의 실제 발생 이력과 분석 근거 자격을 구분하며, 저장 복원·장부 접기 이후에도 음성 근거 제외가 적용된다. 검증: [`atlas-delivery-exclusion.test.js`](../tests/atlas-delivery-exclusion.test.js).

추가 검토로 Ask의 `__proto__` 보기 결과가 사라지는 문제와 Temper가 동일 관측의 입력 순서만으로 극소 차이를 ‘개선’으로 표시하는 문제도 수정했다. 결과 사전은 프로토타입 없는 객체를 쓰고, 평균은 정렬된 입력으로 재현한다. 실질적 효과의 판정 기준을 새로 주장하는 변경은 아니다.

## 제품 채택과 효율

새 제품은 목적·동의 범위, 판단 속성, 후보의 필수 제약, 질문 가치의 단위, 실제 전달·결과의 측정법을 정한다. 필요한 능력만 로딩하고 제품 코드에서 호출한다. 화면·저장·인증은 기존 호스트가 맡으며 엔진마다 별도 실행기나 모델 호출 계층을 만들지 않는다. 의미·허용 값·결과 정의를 바꿀 때는 계약판을 올리고, 추천 가중치·모델을 바꿀 때는 정책판과 당시 후보·근거를 남긴다. `snapshot`은 당시 계약·후보 사본과 관측 ID를 담으므로 재현에 필요한 원관측 보관은 호스트 책임이다.

- **SHIFT:** 문항별 마지막 판단·근거 일치를 독립 관측으로 투영하고, 공통 Domain은 전체 관측의 일치·충돌을 해석한다. [제품 복습 정책](../experiences/shift-workbench/README.md#review-order)은 최근 30일의 미해결 문항을 앞에 두고 같은 우선순위의 다음 실습은 미경험·실제 노출/완료가 가장 오래전·등록 순서로 고른다. 전체 해석이 보류돼도 특정 문항의 복습 근거는 구분해 표시한다. 안내 사용 여부를 표시하며 수행하지 않은 문항을 성공으로 보충하지 않는다. 실제 첫 문항과 Temper 선택·DOM 노출을 일치시키고, 새 근거 순서 정책 `evidence-check-order@2`의 평가를 구형 `@1`과 구분한다. 결과 지표는 실습 전체의 최초 검토 일치율 `initial-review-match-ratio`다. 만료·제외된 근거를 현재 설명에서 빼며 최신 결과를 제외해도 구결과를 되살리지 않는다. 같은 날 제품 모델에서 [세대 변경 뒤 기록 이행](../experiences/shift-workbench/README.md#record-migration)도 보완했다. 이전 분석은 제외하고 요청문·초안은 별도 작성물로 보존한다. 두 변경 모두 공통 Atlas 원본 변경 없이 제품 책임에서 처리했다. [추천 검증](_ops/qa/shift-recommendation-20261007/report.json). 후속에서 [제품 판본 변경 시 작성물 복구와 평가 보관](../experiences/shift-workbench/README.md#storage-upgrade)을 보완했다. v1 저장/현재 Core 원로그 범위에서 분석과 작성물을 구분하고, 완료·중단·미노출 최근20시도를 같은 표본으로 보관하며 노출 경험은 따로 유지한다. [후속 검증](_ops/qa/shift-storage-retention-20261007/report.json). 실고객 업무 성과 검증은 남아 있다.
- **컴퓨터 상담:** 질문 선택은 Core Ask, 분야 지식은 기존 컴퓨터 규칙, 표시·공유는 기존 상담 화면이 맡는다. [단위 시험](../tests/atlas-lab-consultation.test.js)과 [실제 브라우저·공유판 결과](../experiences/atlas-lab/qa/question-value/result.json)로 연결을 확인했다.
- **필요한 코드만 포함:** Core domain과 Temper outcomes는 사용 소비처만 로딩한다. 기존 게임 9개의 공통 묶음에는 두 신규 모듈이 들어가지 않는다. 일반 평가를 기존 Temper 파일에 합친 시험 묶음 약 460KB에서 분리 후 약 448KB로 줄였다. 새 모듈 포함 여부와 원본 일치는 빌드 결과로 확인한다.
- **계산 낭비 제거:** 숫자 관측별로 전체 목록을 다시 세던 계산을 한 번의 빈도 집계로 바꿨다. 동일 로컬 환경, 숫자 관측 10,000건·서로 다른 값 10,000개·4회에서 452~507ms → 52~64ms였다. 운영 지연이나 모든 입력에서 같은 배율을 보장하는 측정은 아니다. 10,000건 회귀는 정확한 빈도·독립 건수·모순 상태도 확인한다.

새 AI 모델은 원관측을 근거로 한 구조화 제안을 이 계약에 맞춰 낼 수 있다. 제안은 확인 전까지 미확인으로 남는다. 모델명 변경만으로 사람 이해가 좋아졌다고 보지 않고, 같은 사례의 회귀·실제 결과·비용·지연을 비교한다. 이번 구현에는 모델 호출·자동 모델 교체·성향 추정 학습을 추가하지 않았다.
