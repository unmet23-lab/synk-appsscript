## 0. 한 장 요약 — 세 문장

1. **왕복의 데이터 탭은 서클이 아니라 «그날 밤 숙제 화면»에 앉는다.** 결정문이 「오늘 목표 → **그날** 지켰나」이고, 서클 정본의 변경불가(폰 0 · ⑥ 종이 확인은 데이터 아님 · 새 수집 채널 금지)는 한 글자도 안 건드린다 — 학생이 어차피 여는 숙제 화면 머리에 카드 하나, 탭 하나다.
2. **v1 은 과녁 텍스트 없는 자기 신고다** — 「오늘 아침 서클에서 말한 목표, 해냈어요?」 [해냈어요 / 아직]. 인쇄물의 학생별 과녁(「다음에 맞힐 문제」)은 조립 순간 파생되고 **저장되지 않아서**(조립기 「쓰기 0」 규약), 밤에 재파생하면 낮 제출로 값이 바뀐 «다른 과녁»을 물을 수 있다 — 거짓 왕복을 설계로 두지 않는다. 과녁 스냅샷 동봉은 v2 슬롯이다(§6).
3. **사건은 새 계약 값 하나(`goal.responded` · explicit)이고, 소비자를 같은 커밋에 세운다** — talk 도달 래칫(`생산자섰는데도달0상한 = 0`)이 소비자 없는 사건을 막는 것은 결함이 아니라 이 트랙의 안전선이다(exam.result 가 그 자리에서 1년 굳은 실측). 소비자 = `학습자상태.js` 자기주도 신호 + 철학 Ⅱ-8 「빛」 축의 지정 재료.

## 1. 자리 — 언제 · 어디 · 몇 탭

| | 확정 | 까닭 |
|---|---|---|
| 때 | **그날 밤, 학생이 숙제 화면을 여는 순간** (하루 1회) | 결정문 「그날 지켰나」 · 서클 20분과 ⑥ 마무리는 폰 0(유호 08-13 변경불가) — 그 의식은 종이 그대로 |
| 곳 | 숙제 화면 **머리 카드 하나** — 새 화면 0 | 결정문 「새 화면 0」 · Ⅱ-8 「새 화면을 늘려서 풀지 않는다」 |
| 손 | **학생 1탭** (해냈어요 / 아직) · 강사 0 · 유호님 0 | 결정문 그대로 · 「번거로움 절대 금지」(유호 08-13) — 탭 하나를 넘으면 이 안은 죽는다 |
| 안 누르면 | **무사건** — 재촉·잠금·배지 0 | 함께한날 「셋 다 안 떨어진다 · 재촉 장치를 안 만든다」 동형 · 못 누른 날도 화면은 잘한 날과 같다 |
| 「아직」이면 | 같은 값의 사건이다 — 벌·표정 변화 0, 카드 반응은 케어 한 줄 | ㉢ 비교 금지 · Ⅱ-2 「케어받고 있다고 느끼게」 · 정직한 자기 신고가 제일 비싼 데이터다 |

카드 문안(초안 · synk-brand 검수 대상): 「오늘 아침에 말한 목표, 해냈어요?」 / [해냈어요] [아직이에요] · 답하면 카드가 한 줄로 접힌다(답장화면 「답했어요」 패턴 상속). 서클이 없던 날(결석·휴일)은 카드 자체가 안 뜬다 — 출석 사실은 엔진이 안다.

## 2. 사건 — 계약 c14 증분 (유호님 판정 자리 · ①과 한 벌)

**`goal.responded`** — 학생이 그날 목표의 이행을 자기 신고한 사건.
- `source_kind = explicit` (사건출처 표에 한 값 등록 — 「지켰다」가 아니라 **「지켰다고 말했다」**를 적는다. §4-E 처방 ① 그대로: 사실 축과 안 섞고, 관측 짝은 mastery 파이프라인이 이미 쥔 그 문형의 실제 변화다 — 말한 것과 실제의 «차이»가 ㉡③자기인식 계열의 재료가 된다)
- payload: `answered('done'|'not_yet')` · `class_date` · (v2 예약) `target_ref` — v1 에서는 비운다, 지어내지 않는다
- 멱등: 학생·class_date 당 1행 (estimate.responded 의 하루 1회 규약 상속)
- 동의: **동의 게이트를 지난다**(학생 산출 — events Fn 의 `CONSENT_MISSING` 403 경로 그대로 · 「조용히 버려짐」 없음)
- RLS: 학생 self-select **허용**(자기 신고는 자기 것)

**`observation.noted`** — ①의 사건(정본 = `관찰태그_자동화_설계.md` §5 그대로 · 여기선 묶음만 명시).
- `source_kind = teacher` · 물리칸 2(관찰자 staff_id · `draft_modified` — 서버 대조 ㉡안) · **RLS 개정 동반**(§3) · 동의 = **운영 기록 계열로 계약에 명문**(exam.result 계열 — 지금 그 규약이 어디에도 명문화돼 있지 않다는 실측을 여기서 닫는다)
- teach 경로 이름은 판정과 함께 확정(후보 `note/save`·`note/queue` — `observe` 낱말은 기계 잠금(`tests/강사통로.test.js:352`)이 판정 전 사용을 막고 있고, 그 잠금은 이 순서의 «장치»라 유지한다)

**래칫 대응 — 같은 커밋에 서는 소비자**:
- `goal.responded` → `lib/학습자상태.js` 자기주도 신호(새 축 신설이 아니라 ㉡ 끈기·자기인식 계열 확장) · **철학 Ⅱ-8 「빛」 축의 지정 재료로 등재**(「아이가 자기 목표를 말하고, 그 목표가 실린 과제를 스스로 낸 날 수」 — 함께한날 후속 판이 소비)
- `observation.noted` → `학습자상태.js` 오류축(설계 v1 §5 그대로) + 반 브리핑 「연습 포인트」 합류는 후속(라이브 폼 통로와의 이관 판정 별건)

## 3. RLS 개정 — 관찰만 가리고, 자기 신고는 연다

현행(실측 · `20260806150000_engine_c6.sql:676`): `learner_self_events` 는 조건이 `learner_id` 하나뿐 — `observation.noted` 가 서는 순간 강사 관찰 원문이 학생에게 그대로 열린다. 개정안(판정 동반 · 원문은 계약 세션이 확정):

```sql
create policy learner_self_events on engine.learning_events for select to authenticated
  using (learner_id = engine.current_learner_id() and event_type <> 'observation.noted');
```

학생에게 무엇을 어떤 문장으로 되돌려줄지는 개인 코치 카드 계열의 몫이지 원문 노출이 아니다(설계 v1 §5 그대로). `goal.responded` 는 제외 목록에 **안 넣는다**.

## 4. ④완결 네 칸 + ⑤ 자기설명 — 계획을 미리 적는다

- **모였나**: `learning_events` 에 `goal.responded` 행 (동의 게이트 통과분)
- **닿았나**: `학습자상태.js` 가 사람 손 없이 읽는다 (같은 커밋 — 래칫이 강제)
- **늘었나**: ㉡ 끈기·자기인식 계열 보강 — 이해 대장의 그 칸에 이름을 댄다. ⚠「학생이 실제로 더 잘하게 됐나」는 안 넣는다(실학생 0 — 철학 ④ 규약)
- **누구에게**: 학생 본인 — 탭 즉시 카드 반응 한 줄(수집이 가져가는 일이 아니라 주는 일 · Ⅱ-8) · Ⅲ-6 「성장을 매주」의 첫 재료
- **⑤ 자기설명**: 카드가 스스로 「아침에 말한 그 목표예요」를 말한다 — 처음 본 학생이 안내 없이 ①이게 뭔지 ②뭘 하면 되는지 알아야 완성

## 5. 짓는 순서 — 판정 하나가 문이다

1. ⏳ **유호님 판정 1건(= 계약 c14 증분 한 벌)**: 사건 둘 + 물리칸 2 + RLS 개정 + 동의 명문 + teach 경로 이름. 재료는 이 문서 §2·§3 + 관찰태그 정본 §5 — 완성형이라 「예 / 고쳐서」만 하시면 된다.
2. 판정 뒤 talk 한 벌: 계약 c14 + 사건출처 표 + 검증기 + RLS 마이그 + 카드(숙제 화면 머리) + `학습자상태.js` 소비 + 회귀 — **한 커밋 안에 생산자와 소비자**(래칫 규약).
3. ① M2 강사 화면은 같은 판정의 다른 반쪽 — 로스터는 실측대로 이미 선 3단 조인(`learners.class_id → classes → staff_classes → staff`)을 쓴다. ⚠ `staff_classes` 생산자(§8-3 원장 화면)는 별도 트랙 — 그전까지 실사용자는 원장뿐이라는 설계 v1 문장은 유효하다.
4. 검증은 실렌더까지 · talk 커밋 전 `npm test` 전체(형제 저장소 규율).

## 6. v2 슬롯 — 지어 두고 안 짓는 것 (정직하게)

- **과녁 스냅샷 동봉**: 서클 조립기가 인쇄 순간 학생별 「다음에 맞힐 문제」를 스냅샷으로 남겨 talk 로 동봉하면(조·좌석 동봉과 같은 통로) 「말한 목표 ↔ 그 문형의 실제 변화」 대조가 정밀해진다. ⚠ 조립기의 「쓰기 0」 규약(서클 설계 §7 · 유호 08-13 변경불가와 한 몸)을 건드리는 일이라 **그 판정 없이 v1 에 안 넣었다** — v2 를 여는 날 유호님 자리다.
- **⑥ 종이 확인의 데이터화**: 안 한다 — 「데이터 아님·회수 안 함」이 설계 확정 문구다. 종이 의식과 밤 탭은 서로 다른 자리고, 겹치지 않는다.
- **크루/무대(③그 순간)**: 크루 운영 결정 선행 — 이 문서 범위 밖.
