# 교실 수집 ② 오늘 목표 왕복 — 현재 계약과 확장 v1.1

> 2026-09-13 · c14의 승인 대기와 과거 미구현 서사를 현재 코드로 정리했다. 현재 계약은 [수집·교정 계약](../계약/수집_교정_계약.json), 확장은 [엔진 추천 목표](엔진추천목표_설계_v1.md)와 [엔진 7종](엔진7종_상향설계_v3.md) Core U2·D6이 맡는다. 문서 정리는 운영 배포·실사용 확인이 아니다.

## 0. 목적과 현재 범위

현재 목표 카드는 밤에 학생이 그날 목표의 이행을 자기 신고하는 통로다. `goal.responded`는 “해냈다고 말했다”는 사실이며 독립 수행이나 학생 목표의 내용 자체를 기록하지 않는다.

아침 추천 내용과 학생의 실제 선언을 잇는 확장은 이미 채택된 방향이다. 현재 밤 응답 통로가 있다는 이유로 추천 스냅샷·`goal.stated`까지 구현됐다고 표시하지 않는다.

## 1. 자리와 반응

숙제 흐름의 기존 카드에서 학생이 한 번 답하고 한 줄 반응을 받는다. 답하지 않으면 사건이 없으며 “아직”에 벌·잠금·재촉을 붙이지 않는다. 수업 중 폰과 마무리 종이 확인의 회수 금지는 수업 범위에 유지한다. 수업 뒤 앱에서 목표를 말하는 통로를 이 금지로 막지 않는다.

노출의 현재 구현은 talk `lib/목표확인.js`다. 하루 한 번, 몽골 날짜 월~금 근사를 사용한다. 실제 출석·수업일·주말반을 정확히 아는 구현은 아니므로 결석·휴일에 자동으로 숨겨진다고 설명하지 않는다. 문안은 talk `contents/문구_목표확인.js`를 따른다.

## 2. 실제 사건과 소비자

`goal.responded`는 c14에서 이미 채택·구현된 학생 사건이다.

| 항목 | 현재 계약 |
|---|---|
| 출처 | 서버가 `source_kind=explicit`로 기록 |
| payload | `response` = `해냈다` 또는 `아직`, `class_date`, `card_version` |
| 멱등 | 학생과 해당 몽골 날짜당 한 번; API의 중복·충돌 규약 적용 |
| 동의 | 학생 산출의 기존 동의 게이트 적용 |
| 열람 | 자기 신고는 학생 자신의 읽기 범위에 포함 |
| 생산자 | talk `lib/목표확인.js`·`src/목표카드.js`·`functions/progress` |
| 소비자 | talk `lib/학습자상태.js` ⑬목표축 |

표시한 카드의 날짜·판을 그대로 되싣는다. 앱이 날짜나 목표 내용을 지어 넣지 않는다. 최초 제안의 `answered=done|not_yet`는 현재 값목록이 아니며 복원하지 않는다.

## 3. 강사 관찰은 다른 사실

`observation.noted`는 [관찰태그 설계](관찰태그_자동화_설계.md)가 맡는다. 강사의 실제 관찰과 학생의 자기 신고를 합치지 않는다. 관찰 원문·교실 태도는 학생 자기 열람에서 제외하는 현재 RLS(행별 접근 규칙)를 유지하고, 학생에게 돌려줄 표현은 별도로 구성한다. 교실 운영 기록과 학생 산출의 동의 적용 구분도 해당 계약을 따른다.

## 4. 완성에서 확인할 것

- **모였나:** 카드에 대한 실제 답이 올바른 날짜·판과 함께 저장되는가.
- **닿았나:** 상태 계산과 후속 도움에서 자동으로 읽는가.
- **달라졌나:** 자기 신고를 관측과 구분하면서 다음 도움에 의미 있는 변화를 만드는가.
- **누구에게:** 학생이 반응과 이어지는 도움을 실제로 받는가.

현재 코드·합성 검증으로 확인할 수 있는 단계와 실제 학생 효과는 구분한다. 카드가 무엇을 묻는지 처음 보는 학생이 이해할 수 있어야 한다.

## 5. 이어서 구현할 순서

c14 사건·RLS·기본 카드를 다시 승인 대기로 올리지 않는다. 현재 계약과 코드를 보존하며 아래 확장을 연결한다.

1. 실제 나간 추천의 ID·문장·선택판·시각을 인쇄 성공 뒤 저장한다.
2. 강사 중계와 학생 앱에서 실제 말한 목표를 `goal.stated`로 구분하는 활성 계약·생산자를 세운다.
3. `goal.responded`를 당시 목표와 연결하고 과제·답장·관측 소비자까지 함께 갱신한다.
4. 날짜·재전송·출석/시간표·서버 저장·실제 출력 변화를 관련 시험과 화면으로 확인한다.

## 6. 확장의 경계

아침 스냅샷을 금지하던 옛 “조립기 쓰기 0”는 인쇄 조립의 순수 계산과 별도 저장을 혼동하지 않도록 정리했다. 조립 자체는 재사용 가능하게 두고 실제 인쇄 성공 뒤 저장 경로를 붙인다. 밤에 다시 계산한 목표를 아침의 기록으로 소급하지 않는다.

종이 확인 동그라미는 계속 학생의 종이 의식으로 둔다. 목표 원문과 응답을 실제로 연결하기 전에는 같은 문형의 수행과 정밀 비교할 수 있다고 하지 않는다. 새로운 학생 기록은 현행 원본·동의·접근 계약을 따른다.

## 7. 남은 확인

추천 스냅샷과 `goal.stated`의 실제 왕복, 목표별 후속 관측, 노출의 시간표·출석 반영, 몽골어 문구, 실제 카드 도달과 학습 효과가 남아 있다. 첫 코호트의 오래된 예정 날짜를 구현 시작 금지로 삼지 않는다.
