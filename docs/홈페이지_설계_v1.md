# SYNK 기업 홈페이지 — 현재 제작 계약

> 2026-09-10. 사용자의 최신 방향과 현재 별도 저장소의 구현을 연결한다. 과거 LAB 시안·배치·게시 관찰을 신규 기업 홈페이지의 고정 정본으로 쓰지 않는다.

## 1. 무엇을 만드는가

**SYNK에 궁금한 것을 물으면 준비된 공개 자료 안에서 답하고, 아래로 내려가면 사업과 실제 작업을 직관적으로 만나는 기업 홈페이지다.**

- SYNK가 입구이며 LAB·SHIFT·PULSE의 역할과 현재 제공 범위를 한 사이트에서 구분한다.
- 챗봇을 첫 화면의 중심에 둔다. 추천 질문과 직접 입력으로 시작하고, 메뉴는 간소하게 구성한다.
- 스크롤 뒤의 사업 소개·실제 작업·문의 안내는 대화 없이도 이해할 수 있게 한다. 기존의 긴 메뉴를 그대로 반복하지 않는다.
- 현재 [마케팅 정본](마케팅_정본.md)과 [기업 철학](기업철학_홈페이지_v1.md)에서 공개할 사실을 고른다. 운영 중·구현·준비·계획을 구분한다.

## 2. 화면과 브랜드

사용자 피드백의 적용 범위는 현재 기업 홈페이지다. 다른 모든 산출물에 동일한 배치를 강제하는 규칙은 아니다.

| 요소 | 현재 방향 |
|---|---|
| 첫 화면 | 질문창·추천 질문이 가장 먼저 읽히고 화면 크기가 달라도 첫 행동을 찾기 쉬워야 함 |
| 마스코트 | 몽글이 가운데 앞, 까몽·마린은 양옆 뒤에서 까꿍하는 구도. 몸·털·표정 원본을 유지하고 겹침·광학 크기·접지로 해결 |
| 로고 | [현재 승인 로고](로고_중립색_정본_v1.md)의 사진형 펠트·스티치 완성 조합. 헤더·사업·답변·사례·푸터까지 대조하고 작은 파비콘은 정밀 SVG |
| 타이포 | 승인 서체 안에서 제목 크기·굵기·행간·강조의 위계를 분명히 함. 로고 사업명을 일반 글자로 재조립하지 않음 |
| 내용 밀도 | 비어 보이는 선언을 늘리기보다 사업별 대상·경험·현재 범위·실물을 구체적으로 보여줌. 성과를 만들거나 설명을 과밀하게 반복하지 않음 |
| 브랜드 사례 | 실제 SYNK 완성 조합과 선택 이유를 보여줌. 회사 내부 브랜드 작업을 고객 성과 사례로 포장하지 않음 |

값·자산·완성도는 [DESIGN](../DESIGN.md)과 [명품 기준](명품_기준_v1.md)을 따른다. ‘기존 병합판의 얼굴과 블록 순서를 고정한다’는 과거 설계는 이 기업 홈페이지에 적용하지 않는다.

## 3. 질문 답변의 계약과 현재 구현

**요구:** 회사가 준비한 공개 가능 문서 안의 내용만 답한다. 문서에 없거나 공개할 수 없는 질문에는 근거 없이 답을 만들지 않는다. 답변의 출처를 볼 수 있게 한다.

**현재 구현:** [SYNK-website README](../../SYNK-website/README.md)와 [검증 기록](../../SYNK-website/qa/RESULTS.md)을 2026-09-10 읽어 확인했다.

- 6개 공개 문서·26개 준비 답변에서 관련 문단을 검색·선택한다. 생성형 AI API나 모델 재학습을 사용하지 않는다.
- 질문·추천 질문·후속 주제·새 대화·답변 복사·출처 문서 열기·사업 이동을 제공한다.
- 질문은 현재 페이지 메모리에만 있고 질문의 서버 전송·브라우저 저장소·분석 추적은 없다.
- 내부 정보·출처 없는 구체 사실·문서 범위 밖의 질문은 미확인으로 안내한다.
- 생성형 문서 검색·생성, 문서 업로드/관리 운영, 다국어 응답, 이메일 전송·신청·결제는 현재 구현 범위가 아니다. 문서를 모델에 학습시켜 운영 중이라고 설명하지 않는다.

공개 문서와 답변 데이터의 실제 원천은 `SYNK-website/dist/knowledge.json`이다. 지금은 이 데이터를 편집해 문서와 답변을 함께 갱신한다. 원자료를 수정했다고 이 파일이나 게시 답변까지 자동 갱신되는 구조는 아니다.

생성형 AI로 확장할 때도 공개 지식만 전달하고 문서 밖 답변 거절·출처·미확인 응답을 확인해야 한다. 현재 검색 구현의 시험 통과를 미래 생성형 답변의 정확성으로 대신하지 않는다. Apps Script 상담봇과 기업 웹 질문창은 서로 다른 구현이며 한쪽의 지식 갱신을 다른 쪽 반영으로 세지 않는다.

## 5. 회사 도메인과 과거 관찰의 경계

`synk.im`은 기존 회사 도메인이다. 2026-09-02 기록에서는 별도 `synk-policy` 저장소의 3개 언어 소개 지면을 제공했고, 당시의 `홈페이지_시안/병합판.html`과도 달랐다. 이는 **당시의 관찰**이며 오늘의 라이브 상태를 증명하지 않는다.

현재 기업 웹 구현은 SYNK-website에 있고, 기존 도메인 교체는 README의 구현 범위에 포함되어 있지 않다. 도메인 전환 작업에서는 대상 저장소·DNS·게시 버전·공개 범위·방침 주소를 그때 직접 확인한다. 옛 시안 파일을 어느 저장소의 `index.html`에 복사하면 끝이라는 지시는 사용하지 않는다.

## 6. LAB 언어·신청·개인정보·약속

기업 홈페이지와 LAB의 학생 모집 조건을 한 문서에서 새로 정하지 않는다.

| 항목 | 담당 원천과 적용 |
|---|---|
| 대상별 언어 | [몽골어 검수 발주](몽골어_검수_발주서.md)와 현재 학생 문안 기준. 몽골 학부모의 필수 안내는 읽을 수 있는 언어로 제공 |
| 수강료·공개 가능한 답변 | [FAQ 운영 기준](자주묻는질문_정본.md)과 연결된 대외 FAQ·가격 원천. 기준 기간·구성·왜 달라지는지를 함께 설명 |
| 추천·사전등록 | [추천·사전등록 정본](추천_사전등록_정본_v1.md). 제도 승인·접수 준비·대외 발표 조건을 구분하며 현재 공개 잠금을 직접 확인 |
| 체험·개원 경험 | [파일럿·체험 설계](파일럿_체험2주_설계_v1.md). 날짜·운영 조건을 이 페이지에 독립 복제하지 않음 |
| 지원·환불·마무리 | [끝의 설계](끝의설계_v1.md). 현재 가능한 지원만 약속 |
| 개인정보 | [방침 원문](개인정보처리방침_초안_v1.md), [게시용 방침](개인정보처리방침_게시용.html), 실제 접수 구현의 수집·보관·동의 범위 |

- 현재 기업 웹은 한국어 안내이며 언어 버튼만으로 번역·감수가 완료된 것처럼 보이게 하지 않는다. 감수 전 초안을 검수 완료본으로 게시하지 않는다.
- 사전등록은 기존 크루카드 접수 통로를 연결하는 설계다. 현재 기업 웹에 이미 접수 폼·저장·자동 회신이 있다는 뜻은 아니다. 새 폼을 연결할 때 최소 수집 항목, 실제 저장, 접수 확인, 담당자 전달·응답까지 확인한다.
- 폼을 붙이면 질문창의 현재 ‘수집 없음’과 달라진다. 수집 목적·항목·보관·동의·방침의 사전등록 범위와 실제 구현을 함께 맞춘다. 학생 식별정보·사진·내부 기록을 홍보 증거로 노출하지 않는다.
- 가격 답변·문의 링크·신청 버튼이 넘기는 상대쪽 동작까지 확인한다. 홈페이지 문안만 바뀌고 상담봇·접수 창구가 다른 말을 하는 상태를 남기지 않는다.
- Meta 심사·법률·플랫폼 요건은 제출 직전 현재 공식 자료와 필요한 전문 검토로 확인한다. 과거 예상 심사 기간·번역비·미실행 일정은 현재 확정 조건으로 쓰지 않는다.

## 7. 다음 변경의 완료 조건

현재 원본 선택→코드·공개 답변 반영→실제 화면과 동작 확인→요청 범위의 게시 확인을 잇는다. 새 로고를 확인한 것만으로 헤더·답변·푸터 전체 반영을 완료했다고 하지 않는다.

남은 범위는 최종 공개 지식 확정, 생성형 AI·문서 운영 도입 여부, 다국어 검수, 모집 기능 연결, 회사 도메인 전환이다. 실제 구현·게시가 확인될 때 해당 기록을 갱신하고, 단순 디자인 문서 개정을 서비스 완성으로 세지 않는다.
