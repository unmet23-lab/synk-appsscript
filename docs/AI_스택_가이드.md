| 시기 | 무엇 | 스택에 요구하는 것 |
|---|---|---|

## 0-1. 제품 스택 — 앱이 서는 곳 (2026-08-05 유호님 확정)

> 유호님 원문: **핵심 원본 데이터 = Supabase + Postgres** · **운영·리포트·수동 검토 = Google Sheets** · **자동화 = n8n 또는 Apps Script** · **앱 = Expo**.

| 층 | 부품 | 상태 · 요점 |
|---|---|---|
| **원본 데이터 (정본)** | **Supabase (Postgres)** | 🆕 필수 신규. 데이터 정본은 **여기 하나**. L0 데이터 계약 = Postgres DDL(스키마 감사 v9.187 산출물이 씨앗) · 엔진 이름공간 `engine.*` 예약 |
| ├ 인증 | Supabase Auth | **기본후보**(무료 5만 MAU) — Glide가 대신하던 로그인의 빈자리. ⚠유호님 명시 확정은 아직(3택: 자체 토큰/Supabase Auth/구글 계정) |
| └ 서버 함수 | Supabase Edge Functions | **AI 게이트웨이 권장 자리**(코어 엔진 A-2: 모델 호출은 서버측만 · 앱 번들에 API 키 금지) |
| **운영·리포트·수동 검토** | Google Sheets | 가동 중 · **파생 층**(정본 아님). 동기화는 단방향(Supabase→시트) — 시트→원본 되쓰기는 **L0 계약에 규격 있을 때만**(P0 계약 조항) |
| **자동화** | Apps Script · n8n | AS = 가동 중(엔진 23,746줄 자동화층으로 존속 · 실측 천장: 실행 6분·트리거 90분/일·메일 100/일) · **n8n = ⚠새 부품, 호스팅·비용 미확정**(설계 시 건별 확정) |
| **앱** | **Expo (SYNK-talk) + EAS** | repo `Documents\SYNK-talk`(PRIVATE) · CI 초록 · EAS projectId 연결·첫 빌드 트리거·`EXPO_TOKEN` 완비. **푸시 무료·초당 600건** → 알림 86곳 메일→푸시 이전(네이티브 전환의 숨은 배당) |
| **코어 엔진** | 4부품: 지식 그래프 · 학습자 모델 · 오류/교정 말뭉치 · AI 게이트웨이 | **E0(지금) = 계약 조항만** → E1 지식층+RAG(상담AI 로그 쌓인 뒤) → E2 학습자 모델 → E3 봇 팩토리(3~4년차). 정본 = `docs/코어엔진_설계.md` |

**제품 스택 원칙**
1. **데이터는 AI가 아니라 저장소에.** 모델·벤더는 갈아끼우고 데이터는 안 움직인다 — 3년차 봇의 훈련 재료는 지금 Supabase에 쌓이는 행이다.
2. **화면은 백엔드를 모른다** — `계약/` + 어댑터 1층으로 교체 비용 격리. C0 계약은 Codex **소비자 승인** 후 동결.
3. **전환은 단계식, 빅뱅 ✗.** 현행 AS+시트 운영은 새 앱 파일럿 게이트까지 그대로 돌고, Glide는 신규 투자 0의 비상 낙하산(실물 제거는 게이트 뒤 별도 승인).
4. 지식 주입 = **RAG**(파인튜닝 ✗ — 틀린 지식을 못 지운다) · 벡터 RAG ✗(지식 총량이 컨텍스트 상한 안일 동안 — 넘는 시점이 자동 재판정 조건).
5. **엔진이 죽어도 앱은 돈다** — AI 기능마다 강등 경로를 P0 기능표에 명시(단일 장애점 금지).

📌 **빈자리 1건(제안 기록 — 미확정)**: 네이티브 앱의 **런타임 오류 감시**(Sentry류·Expo 표준 통합·무료 티어)가 스택에 없다 — AS 쪽은 crewcard 오류감시를 지었지만 talk 앱은 자리 자체가 비어 있다. P0 계약 때 판정 요청 예정.

**층이 5개다** — 도구를 늘릴 때 「어느 층인가」부터 묻는다. 같은 층에 둘을 두면 정본이 갈라진다.

| 층 | 하는 일 | 누구 |
|---|---|---|
| **지휘** | 유호님 ↔ 시스템 (결정만) | 결정 큐 봇(클라우드) · 헤르메스(PC 켤 때) |
| **두뇌** | 기획·판정·정본·배포 + 코딩 L0·L1·L3·L4 | 클로드 ×3 |
| **구현 파트너** | **L2 Expo 화면 주력**(닫힌 명세 발주 — 발주·리뷰·병합은 클로드) | GPT 코덱스 |
| **검사** | 백지 적대 리뷰(설계·코드) + 배포 검수 파이프라인 + 몽골어 검문 | GPT 코덱스 · 제미나이 API |
| **감각·정찰** | 밖에서 재료를 물어온다 · **클로드의 결손을 메운다** | 제미나이·NotebookLM · **Manus** |

**원칙 5 — 전부 여기서 나온다**
1. **만드는 곳은 병렬, 라이브는 한 줄.** 배포·정본(메모리·문서) 쓰기는 클로드 계정1만.
2. **이종(GPT)은 비교가 아니라 검사.** 결과 둘을 놓고 고르는 게 아니라, 기억·테스트·가드를 기준으로 공격시킨다. 구현을 나눠도 **심판은 기계 3겹**(pre-commit·CI·교차 검수)이다.
3. **지휘층(헤르메스)은 읽기 전용** — 프로즈가 아니라 **기계로** 그렇게 만들었다(§1-4).
4. **정찰층이 물어온 것은 재료지 판정이 아니다.** Manus가 만든 경쟁사 표는 클로드가 기억·수치와 대조한 뒤에야 결정 재료가 된다.
5. **기억이 어디 사느냐가 배치를 정한다.** 기획·판정은 기억(재제안 금지 목록·실측치)이 사는 클로드에, 백지가 무기인 검증은 GPT에, 클로드가 원천적으로 못 하는 것만 제미나이에.

**월 비용**: 유료 = 클로드 맥스 ×2 + Pro ×1 + GPT **Plus($20)** + **Google AI Pro($19.99)** + Manus(쓴 만큼). **제품 스택 신규분은 전부 무료 시작** — Supabase Free·EAS Free·시트·AS 0원(n8n만 ⚠미정 — 셀프=서버비/클라우드=구독, 설계 시 확정). 유료 전환은 사용량이 실측으로 요구할 때만.

## 0-3. 코딩 레인 분할 (2026-08-05 유호님 채택 "나눠서 하자")

기획 = 유호님 1인 · 설계 = 정본 1곳·펜은 클로드·Codex 적대 검수·확정은 유호님 · 코딩 = 레인 분할. 실행 정본 = SYNK-talk `docs/개발_분업.md` v2.

| 레인 | 내용 | 담당 |
|---|---|---|
| L0 | 데이터 계약(Postgres DDL·수집_교정_계약) | 클로드 |
| L1 | 백엔드(Supabase·AS 연동) | 클로드 |
| **L2** | **Expo 화면** | **Codex 주력** — 공통 앱 기반(F0: 내비·상태·API층·토큰)은 Codex 단일 소유 선행, 토큰 값은 브랜드 킷 정본 구속 |
| L3 | 교정 프롬프트·콘텐츠 | 클로드 정본 + 제미나이 몽골어 검문(기존 배선) |
| L4 | 통합·배포·CI | 클로드 |

- 완성 단위 = 층이 아니라 **기능별 수직 슬라이스**(P0 제품계약 → F0 기반 1회 → C0 계약 동결 → S1~Sn 관통·즉시 통합). S1 = 실측 게이트 겸임.
- 검수는 전수가 아니라 **위험도 기반**(계약·인증·전역상태·배포설정만 전수 교차) · 발주서는 구현 전 Codex 검수(작성자·검수자 분리).
- **첫 사이클 = 실측 게이트**: 리뷰 반려 횟수·재작업 왕복·완성 시간·한도 잔량 → 레인 재배치. 같은 기능 2회 제작 ✗.
- ⛔ **라이브 repo(SYNK-appsscript)에 Codex 불입 금지 유지**(훅 무효 + 라이브 시트 접근). Codex의 일터는 SYNK-talk뿐(AGENTS.md·pre-commit 완비).
- ⚠ 「효율 2배」는 기대치 — 병렬 이득은 화면 구간 한정, 상류(계약·설계)는 직렬 + 이종 왕복 +5~8분/사이클 실측 · GPT 한도 정책 변동성 주의.

- **Supabase**: ⏳ **계정·프로젝트 생성 = 유호님 1회**(polite: supabase.com → GitHub 로그인 → New project — Apple·Google 개발자 계정과 함께 SYNK-talk ⏳ 묶음). 그 뒤 클로드가 L0 DDL(Postgres)로 스키마를 세운다. **Free 티어로 시작**(DB 500MB·Auth 5만 MAU — 개발·설계 단계엔 충분) · **⚠유료(Pro $25/월) 전환 시점은 「사용량」이 아니라 「실학생 데이터가 처음 들어가는 날 전」**(2026-08-05 정정) — 근거는 용량이 아니라 **Free엔 다운로드 가능한 자동 백업이 없다**는 것이고, 학생 데이터는 날아가면 복구가 안 된다. 복구 시험 1회가 파일럿 게이트 조건(코어엔진 부록 A-9 · 지출 승인=유호님).
  - ⚠ **학생 데이터가 사는 곳이 된다** — 관할권·백업·동의(v18.9 개정 트랙)와 한 몸. RLS(행 단위 권한)는 L0 계약 항목.
- **Expo + EAS**: ✅ repo·CI 초록·EAS projectId·첫 빌드·`EXPO_TOKEN` 완비. ☠️「액세스 토큰」 화면이 둘(F112) · 로그인 없이 본 빌드 페이지를 실패로 읽지 말 것. ⏳빌드 눈 = Expo MCP 승인(유호님).
- **n8n**: 미착수 — **자동화가 AS 천장(실행 6분·트리거 90분/일)이나 외부 SaaS 연동 폭에 막힐 때** 건별로 켠다. 호스팅(셀프=서버비/클라우드=구독)·비용은 그 설계 세션에서 확정. **AS로 되는 일을 n8n으로 옮기지 않는다**(부품 수 = 유지비).

## 2. 역할 — 왜 이렇게 나눴는가

축은 **능력 비교가 아니라 "기억이 어디 사느냐"**다. 이 시스템의 기획·판정 품질은 모델 지능이 아니라 축적된 기억(재제안 금지 목록·실측치·판정 이력)에서 나오고, 그 기억은 전부 클로드 쪽에 산다.

| 일의 성질 | 가는 곳 | 이유 |
|---|---|---|
| 기억이 필요한 일 (기획·판정·정본·배포·데이터 계약) | 클로드 계정1 | 기억이 여기 산다 |
| 손이 많이 가는 병렬 생산 | 클로드 계정2 | 같은 기억·같은 하네스 |
| **닫힌 명세의 화면 구현 (L2)** | **GPT 코덱스** | 명세가 닫혀 있으면 기억이 필요 없다 — 발주서가 지침이다 |
| 기억이 **없어야** 잘하는 일 (백지 검증) | GPT 코덱스 | 백지는 심문자의 무기 |
| 기억을 유호님 눈에 보이게 | 옵시디언 | 이미 옵시디언 문법(`[[링크]]` 노트) |
| 클로드가 **못 하는 것** (라이브 시트·오디오·영상 생성·한도) | 제미나이·NotebookLM | 능력 경쟁이 아니라 **결손 보전** |
| 몽골어가 맞는지 기계로 재기 | 제미나이 API (3.6-flash) | 유호님이 못 읽는 언어로 나가는 것 자체가 위협 모델 |
| 유호님 폰과 시스템 사이의 문 | 결정큐 봇·헤르메스 | 지휘층은 읽기 전용 |
| (조건부) 병렬 레인의 교통정리 | 오르카 | SYNK-talk 「일감 대기」부터 |

**금지선 — 이것만 안 넘으면 시스템은 안 깨진다**
- ❌ GPT에 기획 **초안**을 맡기기 (기억이 없어 기각안을 재생산 → 큐만 증가)
- ❌ GPT에 상시 지침·커스텀 인스트럭션 심기 (사본은 스스로 낡는다)
- ❌ GPT 검증을 이어지던 대화에서 하기 → **매번 새 대화**
- ❌ Codex를 라이브 repo(SYNK-appsscript)에 들이기 (훅 무효 + 라이브 시트)
- ❌ 헤르메스에게 코드·파일 수정 시키기 (가드 0인 층)
- ❌ 제미나이·NotebookLM·Veo에 학생 데이터 넣기 · 무료 API 티어에 학생 개인정보
- ❌ **NotebookLM 답을 그대로 결정 근거로 쓰기** (사본은 낡는다 — 재료지 판정이 아니다)
- ❌ 옵시디언에서 memory 폴더 이동·개명·대량 편집
- ❌ **시트를 데이터 정본으로 되돌리기** (A안 기각 — 정본은 Supabase 하나, 시트는 파생 층)
- ❌ 시트→원본 역방향 쓰기를 계약 규격 없이 열기 (정본이 갈라진다 — P0 조항)

## 3. 사용법 — 유호님의 라우팅 규칙

**기본값: 무엇이든 일단 클로드.** 예외만 외우면 된다:

| 이런 순간 | 여는 곳 |
|---|---|
| **라이브 시트에 뭐가 들었는지 궁금하다** | **시트 안 `Ask Gemini`** — 클로드는 이걸 못 본다 |
| **클로드 한도가 찼는데 더 하고 싶다** | **NotebookLM**(조회) · 또는 계정을 바꾼다 |
| 유튜브·영상·이미지를 판독하고 싶다 | 제미나이 |
| 짧은 영상 소재가 필요하다 | 제미나이 **Veo** |
| 자료를 통독·듣고 싶다 (교재·정본) | NotebookLM |
| 경쟁사가 뭘 하는지 알고 싶다 | Manus (범위를 좁혀서 · §1-6) |
| 넓고 빠른 웹 조사 | 제미나이 Deep Research ／ **정확도가 걸리면 GPT** |
| 몽골어 문안이 맞는지 재고 싶다 | 클로드에게 "몽골어 검문 돌려줘" (`tools/몽골어대조.js`) |
| SYNK-talk 화면을 만들고 싶다 | 클로드에게 말하면 **클로드가 Codex에 발주**한다 (유호님 몫 0) |
| "예전에 뭐라고 정했더라?" | 옵시디언 `Ctrl+Shift+F` (또는 클로드에게 질문) |
| 폰으로 결정 처리 | **`@synk_queue_bot`** (매일 9시 · 그 방에 답하면 끝) |

### GPT 검증 흐름 — 유호님 몫 0이 기본

굵직한 확정 전 "이거 GPT 검증 받자" 한마디면 클로드가 브리핑 1장을 만들어 **자동으로** 돌리고(배포 파이프라인은 이미 자동), 공격을 반영/기각으로 갈라 최종안을 낸다. 적용 급 = 되돌리기 어려운 결정·외부 공개물·계약/인증/전역상태/배포설정 코드.
