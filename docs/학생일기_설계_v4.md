## 0. 🔴 v3 에서 내가 틀린 넷 — 철회한다

### ㉠ 「거르개 0」은 거짓이었다. 실제로 **셋** 남는다

실물을 다시 열어 소비자마다 «무엇으로 거르는가»를 봤다.

| 소비자 | 거르는 자 | 이름을 갈랐을 때 |
|---|---|---|
| 교정 엔진 | `e.event_type = 'submission.created'` 조인 | ✅ 안 집는다 |
| 소리 변환기 | `transcript_state = 대기` | ✅ 안 집는다 |
| 학습자상태 축 넷 | `골라('submission.created')` | ✅ 안 집는다 |
| 진행률 «제출 수» | `e.event_type = 'submission.created'` | ✅ 안 집는다 |
| 🔴 **처리 대기표** | **`submissions` 표 INSERT 트리거** | ❌ 표에 넣으면 줄이 선다 |
| 🔴 **진행률 «첫날인가»** | **거르지 않는다** | ❌ 그 학생의 «모든» 사건을 본다 |
| 🔴 **성과 회수** | **`학습자상태.쓰는사건` 을 그대로 가져다 쓴다** | ❌ 목록에 더하면 딸려 간다 |

⇒ 일곱(v2) 도 0(v3) 도 아니고 **셋**이다. §3 이 셋을 각각 처분한다.

### ㉡ 「두 집안이 같은 말을 했다」는 내 과장이었다

GPT 안은 **표 재사용 + 통로 가르기**, 제미나이 안은 **새 표**였다. 서로 다른데 뭉쳤다.
그리고 GPT 가 이번에 근거를 댔는데 **절반이 맞다** — 교정 엔진은 표가 아니라 사건으로 거른다.
표를 새로 파야 하는 이유는 이제 **처리 대기표 트리거 하나**로 좁혀진다(§4 가 다시 센다).

### ㉢ 🔴 「물음을 띄웠다」를 «자발 발화» 목록에 넣은 것은 자기모순이다

v3 §0㉢ 은 「화면에 띄운 것을 들은 것으로 둔갑시키면 오염」이라고 v2 를 쳤다.
그래 놓고 §2 에서 `diary.opened` 를 `쓰는사건` 에 그냥 더했다. 그대로 두면 **일기 화면을
열었다 닫기만 한 학생의 자발 발화 수가 부풀어 오른다.** §6 이 이 자리를 가른다.

### ㉣ 완결 도장의 「배선까지」는 내가 지어낸 값이다

판단 정본은 ✓ 와 ✗ 둘뿐이다. 표도 통로도 화면도 아직 없으므로 지금 정직한 표기는
**모였나 ✗ · 닿았나 ✗ · 늘었나 ✗** 다(§7).

## 1. 한 줄

**일기를 제 표에 앉히고, 기존 표가 지고 있던 규율을 그 표로 옮겨 심는다.**
새로 짓는 값은 「거르개를 안 달아도 된다」가 아니라 **「거르개가 셋으로 준다」**이다.

## 2. 유호님이 정하신 여섯 (결정.md · 09-05)

| | 확정 |
|---|---|
| 빈도 | 강제 없이 열어둔다. 안 쓴 날은 아무 일도 안 일어난다 |
| 물음 | 사소한 일상 — 「오늘 점심은 뭐 먹었어요?」 |
| 목적 | 학생 자신의 기록. 성향은 덤 |
| 자리 | **앱 아래 탭 하나** |
| 쓴 뒤 | **쌓이는 것 보여주기 + AI 맞장구.** 🔴 고치지 않는다 · 🚫 평가도 안 한다 |
| 다시 보기 | 날짜 목록 + 시즌 끝 종이 |

🚫 배지 · 연속 일수 · 달력 없음.

## 3. 가르는 자리와, 남는 거르개 셋

```
engine.learning_events  (기존 표)
  ├─ submission.created   ← 과제
  ├─ diary.written        ← 🆕 일기를 썼다
  └─ diary.opened         ← 🆕 물음을 띄웠다

engine.diary_entries    (🆕 새 표 — 본문·소리·물음이 여기 산다)
```

**거르개 셋을 각각 이렇게 처분한다.**

| 자리 | 처분 |
|---|---|
| 처리 대기표 | **본문을 `submissions` 에 안 넣는다** ⇒ 트리거가 안 뜬다. 과제 쪽 트리거는 안 건드린다 |
| 진행률 「첫날인가」 | 그 질의에 `event_type not like 'diary.%'` 한 줄 |
| 성과 회수 | `쓰는사건` 을 그대로 쓰지 않고 **제 목록으로 좁힌다**(일기 둘 제외) |

🔑 셋 다 **한 줄짜리**이고, 셋 다 «빠뜨리면 보이는» 자리다. v2 의 일곱은 빠뜨려도 조용했다.

## 4. 새 표 — 스키마와, 옮겨 심어야 할 규율

### ㉠ 왜 새 표인가 (정직하게 다시 센다)

1. 🔴 **처리 대기표 트리거가 표 INSERT 로 뜬다.** 기존 표에 넣으면 소비되지 않을 잡이 매일 쌓인다.
   (트리거를 고쳐도 풀리지만, 그건 과제 통로 한복판을 건드리는 일이다.)
2. **일기 전용 칸이 열이다.** 기존 제출 표에 넣으면 그 칸들이 자유 JSON 안에 묻히고,
   묻히면 유일성·조회·인덱스를 못 건다.
3. 날짜 목록과 종이 조판이 **이 표 하나만 읽으면 된다.**

### ㉡ 스키마

```sql
create table engine.diary_entries (
  diary_entry_id    uuid primary key default gen_random_uuid(),
  event_id          uuid not null unique references engine.learning_events(event_id),
  learner_id        uuid not null references engine.learners(learner_id),
  opened_event_id   uuid references engine.learning_events(event_id),  -- diary.opened 고리

  diary_date        date not null,          -- 🔴 «물음을 띄운 순간»의 몽골 달력 날짜
  prompt_id         text not null,
  prompt_text       text not null,          -- 그날 학생이 «본» 원문 그대로
  prompt_pack_ver   text not null,

  body_original     text,
  audio_ref         text,
  capture_meta      jsonb,                  -- 음성헤더가 잰 봉투(코덱·표본률·채널)
  audio_duration_ms integer,                -- 🔴 없으면 「얼마나 길게」를 질의로 못 센다

  input_lang        text not null default 'unknown',   -- ko|mn|mixed|unknown
  lang_source       text not null,                     -- text_script|none
  transcript        text,
  transcript_state  text,                   -- null=대상아님 · 대기 · 완료 · 실패
  transcript_lang   text,

  occurred_at       timestamptz not null,   -- 학생이 낸 시각
  ingested_at       timestamptz not null default now(),
  schema_ver        text not null,

  constraint diary_has_content
    check (body_original is not null or audio_ref is not null)
);
create index diary_by_learner_date on engine.diary_entries (learner_id, diary_date desc);
```

🔴 **하루 한 장 제약을 뺐다.** v3 는 `(learner_id, diary_date)` 유일 제약을 걸었는데,
그러면 낮에 한 줄 쓴 학생이 밤에 덧붙이려 할 때 조용히 막힌다. 유호님 확정은
「매일 하나씩 쓸 수 있게」이지 「하루에 하나만」이 아니다.
⇒ 하루 여러 장을 허용하고, 두 기기 중복은 기존 멱등키가 접는다.

### ㉢ 🔴 옮겨 심어야 할 규율 — 기존 표가 공짜로 주던 것들

GPT 지적 그대로다. 새 표는 `submissions` 의 보호를 **상속하지 않는다.**

| 규율 | 어떻게 |
|---|---|
| 원문 불변 | `prompt_text` · `body_original` · `audio_ref` · `capture_meta` 를 UPDATE 못 하게 트리거 |
| 삭제 방지 | 행 DELETE 금지(동의 철회 경로만 예외) |
| 사건 연결 | `event_id` 에 유일 제약 — 한 사건에 한 행 |
| 음성 봉투 검사 | 넣기 전에 `음성헤더` 로 재고 그 결과를 `capture_meta` 에 |
| 파일 실재 확인 | `audio_ref` 가 가리키는 파일이 실제로 있나 |

## 5. 전사와 언어

### ㉠ 전사는 기본값이 「안 함」이다

`transcript_state` 를 **비워 둔다**(`null` = 대상 아님). 소리 변환기는 `대기` 만 집으므로
일기 소리는 그 줄에 안 선다.

🔑 되는 이유 = **소리를 무기한 보관**하기 때문이다. 형제 저장소 규약이 이미 정했다.

> 🔴 학생 원본 음성은 반드시 보관한다. … 전사는 다시 돌릴 수 있지만 원본은 소급 불가.

⚠ **값을 버리는 것이 아니라 미루는 것이다.** 다만 미루는 동안 한국어로 «말한» 학생의
발음·어휘가 엔진에 안 닿는다는 것은 사실이고, §8 이 그 값을 다시 잰다.

### ㉡ 언어는 «글자»로 정하되, 못 정하면 못 정했다고 적는다

| 무엇 | `input_lang` | `lang_source` |
|---|---|---|
| 한글 자모가 주면 | `ko` | `text_script` |
| 키릴이 주면 | `mn` | `text_script` |
| 둘이 섞이면 | `mixed` | `text_script` |
| 🔴 **로마자면** | `unknown` | `none` |
| 글 없이 소리만 | `unknown` | `none` |

🔴 **로마자 몽골어를 판정하지 않는다**(제미나이가 알려준 자리 · 나는 몰랐다).
몽골 학습자는 자판 바꾸기가 번거로우면 로마자로 몽골어를 쓴다. 글자만으로는 영어와 못 가른다.
지어내느니 `unknown` 이 정직하다 — **없는 칸과 「모른다」는 다르다.**

## 6. 축 — 무엇을 세고 무엇을 «안» 세나

`쓰는사건` 목록에 두 줄을 더한다(그래야 조회가 실어 준다). 그러나 **축이 그 둘을 같이 세지 않는다.**

| 사건 | 자발발화축에서 |
|---|---|
| `diary.written` | **분자** — 실제로 남긴 것 |
| `diary.opened` | **분모** — 열어는 봤다 |

🔴 v3 은 이 구분을 안 적어서 「열어보기」가 「발화」로 셀 수 있었다. 그것이 §0㉢ 의 자기모순이다.

**축이 세는 것 넷** — 남긴 수 ÷ 연 수 · 길이(글=글자 수 · 소리=`audio_duration_ms`) ·
시각대 · 매체(말/글). 창과 판은 기존 `학습자상태` 규약을 그대로 쓴다.

🔴 **집중띠를 채운다는 v3 의 주장을 물린다.** 집중띠는 「시간대별 착석 대비 완료율」이지
「제출 시각 빈도」가 아니다(심문 지적 · 실물 확인). 일기 시각은 **생활 리듬**이지 집중 상승의
증거가 아니므로, 자발발화축의 제 칸으로 두고 집중띠에 섞지 않는다.

## 7. 완결 도장 — 지금은 전부 ✗

| 칸 | 지금 | 언제 ✓ 가 되나 |
|---|---|---|
| 모였나 | **✗** | 표와 통로가 서고 첫 행이 실제로 쌓일 때 |
| 닿았나 | **✗** | 자발발화축이 그 행을 읽고 값을 낼 때 |
| 늘었나 | **✗** | 이해 대장 ㉡ 칸에 «무엇을 알게 됐는지» 이름을 댈 수 있을 때 |
| 누구에게 | 학생 (예정) | 날짜 목록·시즌 종이가 실제로 돌 때 |

정본이 「나중에 쓸 수 있는 모양은 통과가 아니다」라고 못 박았다. v3 의 「✓ 예정」과
「배선까지」는 그 규정을 피해 간 표기였다.

## 8. 안 정한 것 · 안 잰 것

1. **맞장구를 무슨 말로 하나.** 초급이 몽골어로 쓰면 몽골어로 답해야 읽는다. 그런데
   몽골어 문구는 감수자가 한 분뿐이라 검수 전에는 화면에 못 올린다.
   ⇒ 후보 = ⓐ쉬운 한국어만 ⓑ한국어 + 몽골어 병기(검수 뒤) ⓒ학생이 쓴 말로.
2. **소리를 안 캐는 동안 잃는 값.** 한국어로 «말한» 학생의 발음·어휘가 그동안 엔진에 안 닿는다.
   그 값이 얼마인지 안 재봤다.
3. **참여율과 녹음 길이.** 용량 계산의 두 입력(초당 32킬로바이트만 실측).
4. **날짜 목록 상한.** 형제 규약이 「새 화면은 목록 상한을 머리말에 적으라」고 한다.
5. **소리만 남긴 날을 종이에 어떻게 그리나.**
6. **최신 수단 정찰.** 학생 접점이라 판단 정본이 요구하는데 아직 안 했다.

## 9. 심문에 바라는 것

1. **§0 의 철회 넷이 충분한가.** v3 에서 내가 틀린 것 중 안 잡은 다섯째가 있나.
2. **§3 의 거르개 셋이 전부인가.** 사건 이름으로 거르지 «않는» 소비자가 더 있나.
3. **§4㉢ 의 「옮겨 심을 규율」이 전부인가.** 기존 표가 공짜로 주던 것 중 빠뜨린 것이 있나.
4. **§5㉠ 의 미루기가 옳은가.** 한국어로 말한 학생의 값을 미루는 것과, 몽골어를 잘못 굳히는 것
   중 어느 쪽이 큰가.
5. **§6 의 분자·분모 가르기가 축 계산으로 성립하는가.**
