# 라디오24 — 송출·화면·채팅 운영 설계

> 현행 기준 · 2026-09-13. 유튜브 라디오의 송출·화면·채팅·수집 경계를 정한다. 곡 제작·편성은 [Reed](Reed_설계_v0.1.md), 새 시각 장면은 [Loom 표현 기준](Loom_실시간장면_표현기준.md)을 따른다. 옛 단계별 발주와 심문 경위를 현재 실행 조건으로 복제하지 않는다.

## 0. 현재 범위와 확인된 실물

라디오는 음악을 편안하게 감상하고 곁에 둘 수 있는 자리다. 감상을 모두 한국어 과제나 학생 데이터 수집으로 끝내지 않는다. 학습 명령을 제공하는 부분은 그 기능의 저장·엔진 소비·출력 변화·수혜자까지 확인한다.

- **실제 송출:** [09-09 생동·연속 소리 반영](_ops/라디오생동_20260909/v2/완료보고.md)과 [09-10 13번 반딧불 들판·잎망토 까몽 반영](라디오/선정무대_20260910/라이브13/반영보고.md)에 실제 유튜브 수신 증거가 있다. 채널 개설·VPS 구매·첫 송출 대기를 현재 상태로 다시 쓰지 않는다.
- **앱 경계:** 09-06 확정대로 앱 안 자습 재생기·개인 청취 수집은 접었다. 앱에는 유튜브 라디오 링크·안내를 두며, 곡 수·학생 수를 이유로 앱 재생기를 자동 재개하지 않는다.
- **현재 곡 선택:** 09-08 확정 Suno 승인곡과 [음악 자산 장부](음악자산_장부.md)를 따른다. 과거 합성·Minimax 곡 생산 계획은 현재 지시가 아니다.
- **현재 관측:** 위 보고는 당시 반영 증거다. 지금의 정상 송출·계정 상태는 현재 도구로 다시 확인한다. 장시간 청취·무중단은 아직 별도 검증 대상이다.

## 1. 설계 원칙

감상·홍보·학습 명령의 목적을 구별한다. 모든 버튼에 답 입력이나 엔진 수집을 강제하지 않는다. 수집하기로 한 원문·동의·링크·당시 문항·표시 사건은 해당 계약대로 보존하며, 수집된 사실과 추정·파생을 구분한다. 공개 라디오에서 학생 개인 약점·성적·순위를 드러내지 않는다.

채팅 원문은 라디오 원장에, 허용된 학습 사건은 승격기를 통해 `learning_events`에 넣는다. 정본 원문·동의·학생 귀속을 우회하는 별도 학습 입력 통로를 만들지 않는다. 날짜·사건 출처·명령 어휘는 SYNK-talk의 담당 모듈에서 읽고 문서의 옛 값목록을 복사하지 않는다.

## 2. 채팅 기능과 실행 원천

| 기능 | 현재 코드 원천 | 계약상 구분 |
|---|---|---|
| 명령 파싱·인자 | SYNK-talk `lib/라디오채팅파서.js` | 원문과 파생을 나누고 `parser_ver` 유지 |
| 수집·맥박·API 호출 | `lib/라디오수집.js`, `bots/라디오수집봇.js` | 조용한 방송과 수집 실패 구분 |
| 문항·라운드·낭독 | `lib/라디오출제.js`, `lib/라디오라운드.js`, `lib/라디오낭독.js` | 당시 문항·보기·게시 상태와 시간 경계 |
| 원장→학습 사건 | `lib/라디오승격.js`, `supabase/functions/radio-promote` | 링크·동의·중복·마감·귀속 검사 |
| 집단 퀴즈 추첨 | `lib/라디오편성.js` | 음악 순서 모듈과 구별 |

### 2-1. 수집과 실제 도달

파서가 받는다는 사실, 원장에 저장된 사실, 엔진이 소비해 출력이 달라진 사실은 각각 확인한다. `!문의`·`!상담`·`!공지`·`!축하`는 리드·운영 기능이며 학습 사건 승격을 공통 의무로 붙이지 않는다. 학습 기능의 관련 시험과 실제 실행 결과로 도달을 확인하며 과거 ‘전부 0’ 표를 현황으로 재사용하지 않는다.

### 2-2. 현재 승격 계약

`lib/라디오승격.js`의 승격표는 `답→quiz.answered`, `빗소리/asmr→preference.stated`, `슬럼프→affect.reported`, `출석/목표→submission.created`를 담는다. 정서·선호는 해당 계약의 자기보고이며 추측한 개인 성향과 구별한다. 구체 payload·인자·중복 규칙은 그 코드와 이벤트 검증기를 따른다.

**`asmr`는 현재 코드에 남은 호환 범위다.** 개인 ASMR 페이지와 앱 자습 재생기를 다시 짓는 지시가 아니다. 변경할 때 실제 생산자·소비자·기존 사건을 함께 확인한다. 질문 다이제스트·자발 채팅 승격·공개 AI 답변은 코드에 없다는 이유만으로 필수 후속 사업이 되지 않으며 현재 요청과 계약 범위에서 판단한다.

## 3. 신원 설계 — 유튜브 시청자와 학생

- 공개 채팅·오버레이에 학생 코드·실명·급수를 올리지 않는다. 표시 가능한 닉네임도 실명·학생 식별정보가 섞였는지 기존 필터로 확인한다.
- YouTube 채널 ID는 외부 가명 식별자이고 표시명은 스냅샷이다. 닉네임만으로 학생을 자동 확정하지 않는다.
- 학생 연결은 내부 운영 화면의 확인·링크 이력으로 관리한다. `!연동`은 인자를 받지 않는 요청 신호이며 공개 코드 제출 통로가 아니다.
- 여러 채널을 써도 학생×라운드 첫 응답만 승격한다. 링크가 없거나 겹치거나 동의가 유효하지 않으면 학습 승격에서 제외하고 원장·제외 근거를 보존한다.
- 링크·원문 보존은 동의 철회·적법한 파기를 막는 규칙이 아니다. 목적별 허용 범위와 현재 데이터 계약을 따른다.

## 4. 스키마와 학습 사건 계약

실제 DDL과 값목록은 SYNK-talk의 마이그레이션·합본·이벤트 검증기가 정본이다. 이 문서에 실행용 DDL을 복제하지 않는다. `radio`는 내부 수집·운영 범위이며 RLS·허용 역할·서비스 시크릿 경계를 유지한다. VPS 봇에 넓은 데이터베이스 쓰기 권한을 주지 않는다.

### 4-1. 원장과 보호 장치

실제 기반은 `supabase/migrations/20260811160000_radio_c10.sql`, `20260812130000_cron_radio_c11.sql`, 보강은 `20260902000000_radio_hardening_c15.sql`과 이후 마이그레이션 체인이다.

| 보존할 것 | 의미 |
|---|---|
| 메시지 ID·body·raw·sent_at·ingested_at·parser_ver | 중복 없이 원문과 파생을 구분하고 재파싱 |
| video_id·라운드 문항/보기 스냅샷·게시 상태 | 실제 방송과 그때 제시된 문항에 귀속 |
| 맥박 ok·error_kind·페이지 커서·pages_fetched | 조용한 0건과 수집 실패·누락 구간 구분 |
| 라운드 idempotency_key·posted_message_ids·post_status | 재시작·부분 게시·중복 출제 판별 |
| 학생×라운드 유일 제약 | 동시 실행에서도 첫 응답 중복 방지 |
| 링크·동의 이력 | 메시지가 발생한 당시 허용된 학생 귀속 |

### 4-2. 원장의 한계

원장에 없는 관측은 재파싱으로 만들 수 없다. 학생이 말하지 않은 이유·개인 청취·실제 감정을 추정해 원문처럼 채우지 않는다. 데이터베이스 파일의 존재와 운영 DB 적용 상태는 구별하고, 실제 변경 시 마이그레이션 체인과 런타임을 대조한다.

### 4-3. 정본 승격 규격

- `sent_at` 시점의 활성 링크·유효 동의를 확인한다. 겹친 링크는 임의로 고르지 않는다. 링크 전 메시지를 자동 소급 승격하지 않는다.
- 멱등키는 메시지 ID, 발생 시각은 원문 시각이다. 현재 승격기는 학생×몽골날짜의 결정적 correlation ID를 사용한다. 무작위 새 ID나 라운드 ID로 바꾸지 않는다.
- 퀴즈는 학생×라운드 첫 응답을 쓰고 당시 보기의 위치를 실제 `option_id`로 해석한다. `skill_ids`·문항·보기 스냅샷·답 원문·확신도는 현재 계약을 따른다. `source_kind`와 날짜는 담당 모듈에서 읽는다.
- 선호·정서의 하루 접힘, 제출의 메시지 멱등, 마감·후속 정정 제외는 승격기 규칙을 따른다. 제외 건수와 이유를 드러내되 원문을 삭제하지 않는다.
- 방송 지연이 섞인 응답 시간을 앱의 선택 지연 `latency_ms`로 쓰지 않는다. 남의 공개 답을 본 조건도 독립 실력과 구별한다.

### 4-4. 계약 변경

새 명령·사건은 실제 생산·소비·권한·기존 데이터 영향을 확인하고 현재 계약 절차로 변경한다. 완료된 c10/c11 발주를 재실행하거나 ‘다음 판은 c16’ 같은 옛 번호를 새 변경의 조건으로 쓰지 않는다. 원장 삭제 메시지 반영·승격 판 고정 등 잔여를 다룰 때는 현재 구현과 최신 트랙에서 상태를 먼저 확인한다.

### 4-5. 집단 되돌림

라디오 퀴즈를 운영한다면 허용된 학습 사건을 집단 단위로 합산해 문항 추첨에 쓸 수 있다. 개인의 약점을 공개 화면에 놓지 않는다. 표본이 적거나 없을 때 기본값으로 돌아가며, 창 길이·표본 하한·가중치는 `lib/라디오편성.js`의 현재 설정과 실제 근거로 관리한다. Reed 음악의 집단 관측과 퀴즈 추첨을 같은 지표로 합치지 않는다.

## 5. 방송 파이프라인

현재 실물은 브라우저에서 장면·표정·오버레이를 그리고 FFmpeg로 곡과 합성해 송출한다. 배경은 매체·자산에 따라 영상 또는 실시간 장면을 사용한다. 09-09 연속 소리는 FLAC 원본을 연속 디코딩해 반복 경계 틈을 줄였다. 사전 인코딩 `-c copy`만 허용하던 옛 발주와 고정 팩 길이는 현재 방식의 개선을 막는 조건이 아니다.

현재 배치·설정·서버 파일은 해당 반영보고와 좁은 반영 도구에서 확인한다. 자격증명 파일을 덮어쓰지 않고 필요한 칸만 갱신하며 값은 출력·기록하지 않는다. 방송 재발견·채팅 ID 재연결·수집 간격·출제량은 실제 API 응답과 한도를 고려하는 기존 코드로 관리한다. 옛 60초 고정과 날짜별 가격을 새 구현의 정본으로 사용하지 않는다.

## 6. 운영에서 확인할 것

송출 프로세스가 살아 있는 것과 유튜브가 수신·공개 재생하는 것을 함께 확인한다. 방송 출력 시간의 전진, 캡처 오류·연결·수집 맥박을 본다. 실패 회차를 조용한 0건으로 숨기지 않고 기존 복구 장치를 사용한다. 새 중앙 감시 체계·강제 훅을 이 문서 정리의 일부로 만들지 않는다.

학생 얼굴 실황·학생 개인 데이터 공개·자동 공개 AI 답변은 현재 라디오 범위로 자동 추가하지 않는다. 감상·채팅 참여를 학생 집중·감정·교육 효과로 단정하지 않는다. 실제 플랫폼·계정·비용 조건이 필요한 변경은 실행 시 현재 상태로 확인한다.

## 7. 결정과 남은 일

남은 일은 [트랙](_ops/트랙.md)의 라디오 항목에서 유지한다. 계정 개설·VPS 구매·완료된 화면 적용을 미승인 대기로 되돌리지 않는다. 09-10 보고의 자동 회복 두 차례는 원인 미확정이며, 장시간 무중단·곡 전체 청취·OAuth 검증·실제 문안 검수는 각각 현재 증거로 확인한다.

## 8. 화면의 목적

음악과 무대·마스코트가 편안하게 함께 보이게 한다. 퀴즈·합산 수치·타이머·광고를 화면에 전부 상시 붙이지 않는다. 기능을 제공할 때 현재 목적에 필요한 안내를 읽히게 하고 결과는 실제 재생으로 판단한다.

### 8-2. 표면 규격

기본은 음악·빛·무대·마스코트와 작은 출처 표기다. 승인 자산·로고·문면은 현재 디자인 원천과 실제 제작 코드에서 읽는다. 모든 지원 매체에 [Loom 표현 기준](Loom_실시간장면_표현기준.md)을 적용하되 모든 요소를 상시 흔들지는 않는다.

#### 8-2-1. 마스코트와 배경

라디오 DJ는 현재 무언이 기본이며 필요 순간의 기존 효과음을 드물게 쓴다. 표정 전환은 [공통 털 바탕·눈 영역 기준](캐릭터/캐릭터_생명감_설계.md#1-a-표정-전환의-재질-고정)을 따른다. 09-10 실물은 기본·눈감음·눈웃음 세 그림으로 여러 사건 표정을 연결했다. 이것을 모든 캐릭터의 표정 수 제한으로 쓰지 않는다.

#### 8-2-2. 사건 연출

인사·DJ 교대·축하는 읽기와 감상을 방해하지 않게 짧게 나타났다 돌아온다. 같은 영역의 연출이 겹치면 기존 순서 처리로 정리한다. 특정 초·큐 크기·트랜스폼 전용 규칙은 담당 코드의 현재 선택이며 다른 매체의 금지가 아니다.

#### 8-2-3. 채팅 안내

채팅에서 제공하는 명령과 화면에서 권하는 명령을 구별한다. 현재 목적에 맞는 안내를 적게 제시한다. 공개적으로 민감한 감정·개인 사정을 말하도록 압박하지 않는다. 명령 개수 자체를 고정하거나 무용한 기능을 남기는 이유로 쓰지 않는다.

## 9. 검증

관련 변경에 맞춰 파서·수집·승격·라운드·곡 순서 시험을 실행하고, 출력 변경은 실제 브라우저와 유튜브 수신을 확인한다. 원문·중복·링크/동의 시점·마감·부분 게시·실패 맥박을 실제 계약으로 검증한다. 설계 문서만 압축한 작업을 실서비스 변경·학생 사용 검증으로 보고하지 않는다.
