# 라디오24 — 24시간 유튜브 라이브 라디오 「학원화」 설계도 (v1)

> **원안** = 유호님 제공 「SYNK LAB 학원 운영·마케팅 & 24시간 유튜브 라이브 라디오 통합 구축 마스터 계획서」(2026-08-07).
> **이 문서가 하는 일**: 원안의 기능 전부에 「왜 수집 → 엔진 어디에 → 몇 년차 회수」를 붙이고, 수집 스키마를
> 확정 계약(c9)·확정 스택(원본=Supabase) 위에 세운다. 방송 인프라는 원안 구조를 승계한다.
> **만든 절차**: 초안 → 컨텍스트 독립 심문 3갈래(계약·스키마 27건 / 외부사실·현실성 / 방향·학원화) → 대조 판정 → 이 최종본. 심문 이력 = §10.

## 0. 판정 요약 (비개발자용)

1. **원안 채택** — 방송 인프라(VPS·FFmpeg 무한 루프·오버레이·텔레그램 봇)는 그대로 간다. 단 **수집 기반(P0)이 송출 개시보다 먼저** 선다 — 첫날 채팅부터 원문이 남아야 하고, 나중에 붙이면 그 사이는 영원히 빈칸이다(소급 불가).
2. **원안 §1의 전제 교정** — 「Google Form→시트→Glide/Notion 동기화」는 낡은 전제다. Glide는 08-05 유호님 확정으로 폐기, 정본 데이터층은 **Supabase 하나**, 시트는 운영·리포트 파생층. 라디오 수집도 전부 Supabase로 들어간다.
3. **수집의 등뼈** — 채팅창이 곧 수집면이다. 명령(!출석·!목표·!질문…)과 퀴즈 = **수집기**, BGM·오버레이 연출 = 그 수집기를 매일 돌게 하는 **트래픽 엔진**(제품방향 등식 그대로).
4. **두 레인 구조** — ⓐ**라디오 원장**(raw · 모든 채팅·라운드·노출을 원문 그대로, 송출 첫날부터) ⓑ**정본 승격**(링크 확정 학생의 퀴즈 응답 → `learning_events`). **v1 송출 개시 시점에는 ⓐ만 돈다** — ⓑ는 c10 소개정+승격기 검증 게이트를 통과한 뒤 켠다. 원장이 승격 재료를 전부 담고 있음을 §9가 검증하므로, ⓑ가 늦어도 데이터 손실은 0이다.
5. **핵심 추가 — 정시 TOPIK 미니퀴즈(+60초 재도전)**: 화면에 문항이 뜨고 `!답 2`로 응답, 정답 공개 60초 뒤 같은 스킬의 다른 문항으로 재도전을 받아 `retry_of_event_id`(계약이 「유일한 결과 변수」로 지목한 자리)를 라디오가 만든다 — **앱은 하루 단위로만 만들 수 있는 「배움이 일어났는가」 쌍을 라디오는 60초 안에 만든다.** 라디오를 「상시 숙제 표면」으로 만드는 축.
6. **선행 비용 정직 고지** — 「문항은 콘텐츠 팩 재사용」이라던 초안 문장은 실측으로 깨졌다: 기존 quiz 100행에는 **보기(option_id)·문항버전이 없다**. 보기 id를 갖춘 TOPIK 문항 팩이 P0 산출물이다(새 앱 퀴즈도 어차피 같은 규격이 필요해 이중 투자가 아니다).

## 3. 신원 설계 — 유튜브 시청자 ↔ 학생

**철칙: 공개 채팅·오버레이에 학생 코드·실명·급수는 영원히 오르지 않는다. 표시 가능한 것은 유튜브 닉네임뿐이다.**
(근거 셋이 한 자리에 모인다: 제품방향 불변식 4「식별자는 안 나간다」 · student_code는 공개 아이디라 사칭 가능 · 유효 코드를 채팅에 치게 하면 **명단 존재 여부가 방송으로 새고**, L0 §4-1-1이 오류 메시지 통일로 지키던 것이 무너지며 로그인 5회 잠금이 대량 시도 DoS 표면이 된다.)

- **수집은 채널 id로**: YouTube `channel_id` = 외부 가명 식별자. 표시명은 행마다 스냅샷만(식별 근거 아님).
- **링크 절차(v1 · 오프라인 학원의 이점을 그대로 쓴다)**: 학생이 **교실에서** 유튜브 닉네임을 신고(종이/운영 화면 — 원장은 학생을 직접 안다) → 원장이 운영 화면(시트 운영층)에서 채널↔학생 매칭 확정. 보조 통로: 학생이 채팅에 **인자 없는 `!연동`**을 치면 그 채널이 승인 대기 큐에 오르고, 텔레그램에는 「대기 1건」 익명 알림만 간다 — 매칭·확정은 언제나 운영 화면에서(학생 정보가 텔레그램을 통과하지 않는다).
- **오버레이 확인도 닉네임만**(「연동 완료 — 닉네임」). 코드·이름 없음.
- C0의 🚫`learners/link`(앱 내 계정 결합 금지)와 다른 것 — 이것은 앱 밖 운영자 확정의 외부 식별자 매핑이고 앱·C0 계약은 불변.
- **다중 채널 허용**(폰·PC) — 학생 단위 집계는 뷰에서 합산, 승격은 「학생×라운드 첫 응답 1건」이라 채널 수와 무관(§4-3).
- **오승인·양도 대비**: 링크 이력은 append-only(protect 트리거) + 학기 단위 재확인 1회. 채널 소유자가 조용히 바뀌는 것은 감지 수단이 없다 — §6-8에 리스크로 명시.
- 비학생 시청자 = 잠재고객(마케팅 축). 학습 승격 없음. **코퍼스 승격 대상은 링크 확정 학생 행뿐**임을 승격기가 강제.

### 4-2. 원장이 보증하는 것 (소급불가 절단)

송출 첫날부터 원장에 남아 **나중에 승격·재파싱이 가능한** 재료: 메시지 원문+원 API 항목(raw)·시각 2종·채널 id·라운드 문항 스냅샷(보기 id·문구·버전)·노출 실적·그때 시청자 수·수집 맥박. **남지 않는 것**(그날 못 담으면 영원히 없는 것)이 생기면 그것이 설계 결함이다 — §9의 왕복 검증이 이 보증을 잰다.

### 4-3. 정본 승격 규격 (Lane A — c10 게이트 뒤에 켠다)

**승격기 = talk `supabase/functions/` 안의 내부 생산자**(서비스 시크릿 Edge Function — C0 앱 API 밖, `intervention.delivered`를 서버가 만드는 것과 같은 자리). VPS 봇은 원장 전달자일 뿐 **service_role을 들지 않는다** — 단일 인제스트 Fn 호출용 좁은 시크릿만. 생산자 장부(`이벤트검증.js`)는 승격기 파일 경로로 갱신(같은 커밋).

| 항목 | 규격 |
|---|---|
| 대상 | **`sent_at` 시점 활성 링크** 학생 × 라운드 **첫 응답 1건**(마감 후·중복·후속 정정은 원장 보존·승격 제외) |
| 소급 승격 | **v1 없음** — 링크 이후 사건만. `learning_events`는 불변(append-only 트리거)이라 오귀속은 지울 수 없다. 소급은 무효화 절차가 계약에 생긴 뒤에만 |
| event_type | `quiz.answered` · `task_type='라디오퀴즈'`(**c10 신값** — 통로 축의 정공. 앱 퀴즈와 같은 칸에 섞이면 영원히 못 가른다) · `task_format='응답'` |
| source_kind | `사건출처('quiz.answered')` 호출(손값 금지 — 원칙 13) |
| 봉투 | `idempotency_key=message_id` · `occurred_at=sent_at` · `correlation_id=`학생별 uuid 신규 발급(라운드 키 아님 — 「한 앉음=한 학생」 전제 보호) · `schema_ver` 스탬프 |
| 내용 | `task_ref`/`task_snapshot`=라운드 것 · `options_shown=[{option_id,label}]` · `selected_option=option_id` · **`submission.body_original`=`!답` 뒤 원문 그대로**(정답 파생의 반쪽) · `confidence`(`?` 표기 매핑) · 재도전 2차는 `retry_of_event_id`=1차 승격 행 |
| latency_ms | **싣지 않는다** — 라디오의 시차는 스트림 지연·채팅 왕복이 섞여 앱의 「선택까지 걸린 시간」과 다른 물건. 원장 `sent_at·shown_at`에서 「보정 불가 지표」로만 파생 |
| 급수·동의 | 실시간 승격이므로 `level_snapshot`=그 시점 `level_current` · `consent_ver`+`consent_id`=**`occurred_at` 시점 유효 동의 조회**(철회 구간·무동의면 승격하지 않고 원장에 사유 기록) |
| 파생 참고 | 공개 채팅이라 「내 응답 전에 화면에 있던 답 수」(`prior_answers_visible`)를 원장에서 파생해 승격 뷰에 병기(오염도 표시) |

### 4-4. c10 후보 목록 (⏳유호 — 원장 보존 중이라 결정이 늦어도 손실 0)

① **`task_type` +'라디오퀴즈'** — 승격 게이트의 차단자(이것 없이는 Lane A를 켜지 않는다) ② '자습 체크인'·`!목표` 산출의 승격 규격 ③ 자발 발화(일반 채팅 한국어)의 학습사건화 — 과제 유도 발화만 쌓이면 분포가 편향되는데 자발 발화는 3년차 회화 봇에 가장 값진 표본 ④ 방송 노출 관측 사건(자막 카드 — `content.viewed`는 `parent_event_id` 필수라 배달 없는 방송 노출에 못 쓴다 · §10 기각 3) ⑤ 유튜브에서 삭제된 메시지의 원장 반영 규칙 ⑥ 환경 투표의 `preference.stated` 재사용(개정 불필요할 수도 — 검증기 payload 대조 선행). 값 추가는 하위호환·안전이며 절차는 기존 그대로(계약 버전 올림+두 저장소 동기화+CHECK ALTER).

## 6. 리스크 (미리 말한다)

1. **BGM 저작권 = 채널 사활.** 24/7 음악 방송의 1번 사고 유형이고, **합법 채널도 허위 클레임으로 죽는다**(Lofi Girl 2022 — 허위 DMCA로 전 스트림 삭제·복구에 24~48h·원본 스트림 URL 사망). 처방: 안전 소스만(YouTube 오디오 라이브러리는 라이브 포함 명시 안전) + **전용 채널 분리**(본채널 = 6개월 마케팅 계획의 본진이라 격리 필수) ⏳§7-2. ASMR 자연음도 같은 정책 안.
2. **자습실 실황 동시 송출** — 학생 얼굴 상시 공개. v1 제외 권고 ⏳§7-3.
3. **OAuth·API 수명** — P0에 프로덕션 게시를 안 하면 봇이 7일마다 죽는다(§5). 수집 맥박(`ingest_heartbeat`)이 죽은 구간을 데이터로 드러낸다.
4. **AI 공개 오답** — 언어 학원이 틀린 한국어 설명을 공개 화면에 내보내는 것은 브랜드 사고. v1은 질문 수집+다이제스트+라이브 코너, AI 자동 응답은 검수 표본+비식별(`redaction_ver`) 뒤 2단계.
5. **VPS 단일 장애점** — systemd 자동 복구+텔레그램 경보(원안 유지). 새벽 장애는 아침 복구가 기본 기대치(1인 운영 — 무중단 SLA를 약속하지 않는다).
6. **공개 채팅의 신호 오염** — 먼저 온 답이 전원에게 보인다. 승격 행에 `prior_answers_visible` 병기(§4-3) · 비공개 응답 통로는 앱 몫으로 2단계.
7. **「새벽 자습 수요」는 가정** — 관측 이력 0(개원 전). 첫 2주 실측으로 라운드 편성·24/7 유지 여부를 판정(§5-P6).
8. **채널 소유자 변경 감지 불가** — 가족 공용·양도는 데이터로 안 보인다. 학기 단위 재확인(§3)이 유일한 완충.
9. **12시간 초과 스트림은 VOD가 안 남는다** — 라디오 본체는 감수(A안이면 수업 VOD는 별도 방송으로 보존).

## 7. ⏳유호님 판정 대기 (8건)

1. **강사 라이브 통합** — **A안 권고**: 별도 방송+배너(스위칭 자작 코드 삭제·수업 VOD 자동 보존·새벽 장애 표면 축소). B안(원안 그대로 자동 스위칭)은 「한 채널 한 화면」을 고집할 때만.
2. **라디오 전용 채널 분리** — 권고: 분리(저작권 사고를 본채널에서 격리).
3. **자습실 실황 포함** — 권고: v1 제외.
4. **BGM·ASMR 소스 정책** — 권고: 무료 안전 소스(월 0원)로 시작.
5. **c10 소개정 승인**(§4-4 — 최소 `task_type` +'라디오퀴즈') — 이 설계도 승인과 함께 확정하면 승격 게이트 지연 0.
6. **VPS 예산 승인**(월 $6~12 · VPS 봇=확정 스택 밖 세 번째 런타임임을 함께 승인) — **4주 뒤 재승인 지표 2개**: 평균 동시 시청자 · `!문의` 건수.
7. **해상도** — 권고: 720p 사전 인코딩+copy 송출(예산 안). 1080p 재인코딩은 $15~30 사양.
8. **도전안 채택 여부**(§8).

## 8. 도전안 (방향의 대안 1)

**「데이터가 방송을 만든다」 — 오버레이 기본 화면을 학원의 오늘로 채운다.**
통념(원안)은 BGM 배경+부가 명령이다. 도전안은 **학원 전체 합산 지표**(오늘 학원 전체가 맞힌 문제 수·전 학생 몬스터 진화 합산 레벨·이번 주 자습 체크인 총량)를 방송의 기본 연출로 쓴다 — 수집층이 연출 콘텐츠를 만들면 방송이 곧 살아있는 학원 증명이 되어 유입(마케팅)과 참여(수집)가 한 화면에서 맞물린다. ⚠**개인 순위·개인 성적은 넣지 않는다** — 월간 개인 랭킹은 이미 「미이식」으로 기각된 장치(학20 · 남과 비교는 도달제 축과 어긋난다)이고, 소수 인원 구간에선 순위표가 곧 개인 성적 공개다. 개인 단위는 본인 닉네임의 리워드 연출(출석 확인·정답 축하)까지만.

## 9. 검증 계획

- **왕복시험**(사상 재사용): 픽스처 채팅 세트(정상·중복 id·전각 숫자·`!답 2번` 변형·마감 후 응답·비링크 학생·키릴 혼입) → 봇 파서 → 원장 행 대조 — **분모 명시**(몇 건 넣어 몇 건 나왔나).
- **원장 보증 검증**(§4-2): 승격기가 요구하는 전 필드가 원장·라운드 스냅샷에서 재구성되는지를 픽스처로 못박는다 — 「승격을 늦춰도 손실 0」 주장의 기계 증거.
- **승격 왕복**(c10 뒤): 원장 픽스처 → 승격기 → `learning_events` 행 대조(동의 시점·링크 시점·중복·마감 경계 사례 포함).
- 오버레이·자막 문안 = 브랜드 킷(DESIGN.md) 구속 + 몽골어 병기 검수 발주 목록에 등재. 원안의 `🌧️ [OO학생 신청 모드]` 표기는 **닉네임 원칙(§3)과 이모지 절제** 기준으로 재작성.

## 10. 심문 이력 (초안 → 최종 사이에 바뀐 것)

**컨텍스트 독립 심문 3갈래**(계약·스키마 27건 / 외부사실 검증표 10항+공격 10건 / 방향·학원화 20건) → 전 건 대조 판정. 초안에서 바뀐 굵은 것:

- **승격을 P0에서 뺐다**(계약 심문 종합 처방) — 오귀속이 불변 테이블에 굳는 문제·동의 시점·급수 스냅샷·source_kind 손값·correlation_id 오용·body_original 누락이 전부 승격 게이트 뒤 규격(§4-3)으로 정리됐다.
- **`!연동 <코드>` 폐기**(3갈래 합류) — 사칭(②)·식별자 공개(③)·명단 스캔+잠금 DoS(①)가 같은 자리를 쐈다. §3의 무코드 절차로 교체.
- **「계약 개정 0」 주장 정정**(①) — 문항 팩에 보기 id가 실측 0건. c10 소개정+문항팩 선행이 정직한 그림(§0-6).
- **`!출석` 재설계**(③) — 「누르면 끝」은 §12-1 확정의 반례 예시 그대로였다. 한 문장 인자 필수로.
- **도전안에서 개인 순위 제거**(③) — 학20 「미이식」 확정의 부활이었다.
- **운영 사망 2종 편입**(②) — OAuth 7일 만료·liveChatId 수명. 초안이 쓴 리스크보다 안 쓴 이 둘이 치명적이었다.
- **원장 강화**(①) — raw jsonb·ingested_at·수집 맥박·parser_ver·RLS 명문·FK·protect 트리거·segment 물리 귀속 제거.
- **latency_ms 제외**(①③ 합류) — 방송 지연을 흡수해 앱 값과 한 칸에서 못 가른다(c9 금지 축과 같은 형태).

**기각 4건(재제안 방지 기록)**: ⑴ `capture_meta.surface` 표면 스탬프 — 녹음 조건 필드의 뜻 넓히기(정공은 `task_type` 통로 축) ⑵ `!목표`를 `learners.goal_track`에 반영 — 일일 목표와 장기 학습 목적은 다른 축(스냅샷 오염) ⑶ 자막 노출을 `content.viewed`로 승격 — c9가 `parent_event_id`(배달 사건)를 필수로 못박아 배달 없는 방송 노출에 못 쓴다(c10 ④로) ⑷ `task_ref` 접두로 라디오 출처 구분 — 같은 문항의 앱·라디오 정체성이 갈라져 문항 단위 통계가 죽는다.
