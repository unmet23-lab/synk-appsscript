## 1. 한 앱, 권한으로 갈린다

현재 앱은 학생·강사·검수자·원장이 하나의 앱을 쓰고 권한에 따라 기능을 구분하는 구조다(talk `docs/P0_제품계약.md` §1 **[확인]**). 공개 사용자는 **학원에 연결되지 않은 학생**으로 처리한다. 새 앱이나 다섯째 역할을 만들지 않는다. 학원 기능은 같은 앱에 두고, 해당 권한을 가진 사용자에게만 보여 준다.

| | 공개 사용자 | 학원에 연결된 학생 |
|---|---|---|
| 들어오는 길 | 구글 · 애플(이메일 로그인은 뒤에 — §2 · 로그인 없이 먼저 해 볼 수도 있다) | 같은 로그인 + 학원이 준 코드로 **한 번 연결**(§3) |
| 배움 | 한글 단계 · 초급 풀 · 매일 말하기 · 게임 · 아틀라스의 맞춤과 소통 | 같다 |
| 교정 | AI가 본 교정(그렇게 표시한다 — §5) | 사람이 확정한 교정이 더해진다 |
| 소속과 마을 | 정원 16명의 온라인 반·마을. 일반 사용자 주 1회 활성 마을 이동 | 실제 학원 반의 정원 16명이 고정된 마을. 자율 이동 없음 |
| 학원의 것 | 없음 | 교사 출석 관리 · 실제 수업의 반과 조 편성 · 선생님 배정과 케어 · 수업 차시에 맞춘 진도 · 시즌 회고와 나침반 · 부모에게 가는 소식 |
| 아틀라스의 기억 | 쌓인다 | **같은 기억이 이어진다** — 연결해도, 학원을 그만둬도 |

학원의 것 목록은 사용자가 든 예(출석·반 설정·선생님 배정과 케어)와 문서에서 본 것을 합친 **[제안]**이며 실물과 대조한다.

마을은 양쪽의 공통 경험이고, 학원 출석·교사 권한을 일반 마을에 자동 부여하지 않는다. 16명은 소속 정원이며 활동 시작 인원이 아니다. 주간 이동 기준·공용 공간 편집 권한 등은 [마을 코어 인계](../experiences/dokkaebi-express/art-direction/village-20260919/CORE-HANDOFF.md)의 미정 항목을 따른다.

### 1-1. 역할마다 들어오는 길 — 코드로는 내 자리만 열린다 (2026-09-19 사용자 확정)

**지금의 실물 [확인]** (talk `App.js` · `src/도착확인.js` · `lib/학생계정.js` · `tools/직원세우기.js` · `docs/P0_제품계약.md` §2·§7-1)

- 강사 · 검수자 · 원장의 화면은 **같은 앱 안에 이미 있다.** 말하기 화면 오른쪽 위의 「SYSTEM」 → 설정 화면(제목 「배포 도착 확인」) 안에 직원 메뉴들이 줄로 서 있다 — 학생 비밀번호 초기화(원장) · 발화 검수 · AI 교정 채점 · 반 피드백 · 나침반 세션 · 시즌 회고 · 교실 관찰 · 학생 기록 보기 · 몽글에게 묻기 · 몽골어 문구 감수. 같은 화면에 비밀번호 바꾸기 · 이 기기에서 나가기와 빌드 정보(판 · 커밋 · 업데이트 채널 · 관측 상태)가 함께 있다.
- **그 줄들은 지금 모든 로그인 사용자에게 보인다.** 일부러 숨기지 않았다 — 「권한은 화면이 아니라 서버가 정한다」. 직원이 아닌 토큰으로 열면 서버가 403 `NOT_STAFF`를 준다. 앱은 누가 원장인지 모른다.
- 직원 계정은 가입으로 생기지 않는다. 운영자 도구(`tools/직원세우기.js`)가 세운다. 번호는 글자가 든 꼴(`SYNK-L01`)이라 학생 번호의 채번기가 만들 수 없고, 첫 비밀번호는 한 번만 보여 사람에게 직접 전한다. 그만두면 지우지 않고 **해임**한다 — 문만 닫히고 감사 기록은 남는다. 역할은 토큰의 클레임이 아니라 서버의 직원 표(`engine.staff`)에서 요청마다 읽힌다(P0 §7-1 · 사용자 확정 08-06).
- 계약의 네 역할은 학생 · 강사 · 검수자 · 원장이다. **학부모는 다섯째이고 「1년차 밖」**이다 — 읽기 전용이고 개별 발화의 원본은 보이지 않는다(P0 §2-5). 앱에 부모의 화면은 아직 없다.

**공개판에서**

| 누구 | 들어오는 길 | 학원의 화면 |
|---|---|---|
| 일반 학습자 | 구글 · 애플(§2) | 보이지 않는다 |
| 학원생 | 같은 로그인 + 학원 코드 한 번(§2 · §3) · 또는 기존 학생번호 로그인 | 코드를 넣은 그 자리에서 보인다 |
| 강사 · 검수자 · 원장 · 문구 감수자 | **학원(운영자)이 직접 세워 준 직원 계정** — 지금 그대로 | 직원 자격이 있을 때만 설정 안의 직원 메뉴이 보인다 |
| 부모 | 아직 없다(1년차 밖) | 세울 때 같은 구조에 얹는다 — 학원이 준 부모 코드로 **자기 아이의 소식만 읽는** 자리 |

- **코드로 열리는 것은 「내 자리」뿐이다.** 학원 코드는 그 사람 자신의 학원 자리만 연다. 강사 · 검수자 · 원장의 권한은 **다른 학생들의 녹음과 기록**을 연다 — 위험의 크기가 다르다. 누구나 가입하는 앱에서 그 권한을 코드 한 줄로 얻게 하면, 코드가 새거나 맞혀지는 순간 학생의 자료가 열린다.
- 그래서 **직원 자격을 주는 코드 · 초대 링크 · 앱 안의 「직원으로 가입」을 만들지 않는다.** `POST /v1/academy/link`는 어떤 입력에도 직원 표를 건드리지 않는다. 공개 가입으로 만든 계정은 직원이 되지 않는다 — 직원은 운영자 도구가 세운 직원 번호 계정뿐이다. 직원도 구글 로그인을 쓰게 하려면 그때 따로 설계한다.
- `GET /v1/me`(§3)는 직원 표를 **읽기만** 한다. 자격을 만드는 통로가 아니다.
- **설정 안의 직원 메뉴을 가린다 [제안].** 설정(비밀번호 바꾸기 · 나가기 · 계정 지우기 · 「학원 코드가 있어요」)은 모든 사용자의 것이라 남는다. **직원 메뉴는 내 자격이 직원일 때만, 그 역할이 열 수 있는 것만 그린다.** 공개 앱에서 일반 사용자가 「학생 비밀번호 초기화(원장)」를 보는 일이 없게 한다. 빌드 정보는 공개 빌드에서 직원에게만 보이거나 한 줄(앱의 판)로 줄인다. 가리는 것은 편의이고 **서버는 계속 403 응답으로 접근을 차단한다** — 지금 코드가 지키는 원칙은 바뀌지 않는다.
- 가려서 생기는 고장을 막는다. 지금 코드가 줄을 숨기지 않은 이유는 「줄이 없으면 화면이 서 있어도 아무도 못 연다」였다. 직원 계정에는 그 역할의 메뉴가 **전부** 보여야 하고, 자격을 새로 받지 못한 때(오프라인 · 서버 오류)에는 마지막으로 받은 자격으로 그린다(§3).
- **직원 메뉴가 닿는 범위 [제안 · 첫 확인 자리].** 공개 가입이 열리면 제출이 학원 밖에서도 들어온다. 공개 학습자에게 알린 것은 「녹음은 교정을 위해 AI가 처리해요」뿐이다(§8-1) — 사람이 듣는다고 말하지 않았다. 그래서 **학원에 연결되지 않은 학습자의 녹음과 기록은 직원의 대기 목록 · 학생 기록에 오르지 않는다.** 선택 동의(엔진을 좋게 하는 데 내 기록을 쓰기)를 켠 사람의 것을 사람이 보게 할지와 그 범위는 **[사용자]**가 정한다. 지금의 직원 API가 어느 범위의 학습자를 돌려주는지는 서버 함수에서 확인한다(§12).

### 1-2. 앱을 둘로 나누지 않는다 (2026-09-19 검토 · 사용자 확정 「한 앱으로 가자」)

사용자의 물음: 일반 사용자용과 「일반 + 학원 오프라인 기능」용을 따로 내면 덜 복잡하지 않은가 — 앱을 하나 더 내는 데 돈이 따로 들지 않는다면.

| | 한 앱 | 두 앱 |
|---|---|---|
| 스토어 등록비 | 개발자 계정에 드는 값이고 앱 수와 무관하다(§8-2) | 같다 |
| 출시할 때마다 | 빌드 · 심사 · 확인이 두 벌(구글 · 애플) | 네 벌. 두 앱의 판을 계속 맞춰야 한다 |
| 구글의 12명 · 14일 비공개 테스트 | 한 번 | **앱마다 따로**(구글 도움말 원문 확인 09-19) |
| 애플 심사 | 코드로 열리는 기능을 심사 메모에 적고 심사용 길을 준다(§8-3) | 거의 같은 앱 둘은 「같은 앱을 묶음 ID만 바꿔 여럿 내지 말라」(심사 지침 4.3 · 원문 확인 09-19)에 걸릴 수 있다 |
| 무료로 쓰다가 학원에 등록한 사람 | 코드 한 번 | 앱을 새로 받아 갈아탄다. 그만두면 또 갈아탄다 |
| 일반 사용자가 보는 화면 | 학원의 것이 보이지 않는다 | 같다 |
| 서버가 자격을 가리는 일 | 필요하다 | **똑같이 필요하다** — 앱이 몇 개든 학원 기능의 주소는 직접 부를 수 있다 |

- 한 앱에서 학원 기능 때문에 생기는 복잡함은 둘뿐이다 — ① 앱이 내 자격을 한 번 받아 화면을 가른다 ② 서버가 자격을 검사한다. 앱을 나누면 ①만 없어지고 ②는 남는다. 그 대신 출시 · 심사 · 검증 · 판 맞추기가 두 배가 된다. 코드도 결국 하나에서 두 앱을 만들어 내야 한다.
- 코드를 연결 열쇠로 정한 이유(§2) — 무료로 쓰던 사람의 기록과 아틀라스의 이해가 학원 등록과 그만두기에도 이어진다 — 가 두 앱에서는 앱을 갈아타는 마찰로 되돌아온다.
- 앱은 이미 그렇게 서 있다(P0 §1 「나뉘는 것은 앱이 아니라 권한」). 새로 짓는 구조가 아니다.
- 이 문서는 직원 도구의 자리를 새로 정하지 않는다 — 지금의 확정(P0: 원장 화면은 앱에 만든다 · 검수 화면은 Expo 한 코드베이스이고 PC에서는 웹 빌드)을 그대로 따른다.

## 2. 계정

**지금의 실물 [확인]** (talk `docs/C0_API계약.md` §2·§4-4)

- 아이디는 학생번호(`SYNK-042` — 비밀이 아니다), 비밀번호는 학생이 첫 로그인에서 직접 정한다. 합성 이메일(`synk042@synk.invalid`)로 Supabase Auth의 비밀번호 로그인을 쓴다.
- 계정을 만드는 유일한 경로는 `POST /v1/auth/first-login`이다 — 학생번호와 전화 뒷자리를 서버가 명부와 대조하는 **게이트**다. 없는 번호·불일치·잠김의 응답을 가르지 않는다.
- 앱은 `signUp`을 부르지 않는다. 서버는 학생을 **토큰에서** 확정하고, 본문에 `learner_id`·`student_code`를 실으면 400이다.
- `/v1/learners/link`는 재제안 금지다. 근거 — 「결합은 앱이 주장할 일이 아니다. 앱이 『나는 이 learner다』라고 말하는 순간 `service_role`이 RLS를 우회해 남의 계정을 만든다.」

**공개 가입 [제안]**

- Supabase Auth의 **구글 로그인과 애플 로그인**으로 연다. 아이폰 앱에 구글 로그인을 두면 애플은 그에 맞먹는 로그인(이름과 이메일만 받고 이메일을 가릴 수 있는 것 — 사실상 애플 로그인)을 함께 두기를 요구한다(심사 지침 4.8 · 원문 확인 09-19).
- **이메일 로그인은 미룬다(2026-09-19 사용자 확정).** 서버의 기본 메일 발송은 프로젝트 팀원의 주소로만 나가고 운영용이 아니다(Supabase 문서 원문 확인 09-19) — 일반 가입자에게 보내려면 메일 발송 서비스를 따로 열고 보내는 도메인을 설정해야 한다. 스토어에서 앱을 받는 사람은 구글이나 애플 계정이 있다. 그래서 구글 · 애플 · 기존 학생번호 로그인으로 열고, 이메일은 필요가 확인되면 더한다(그때는 링크가 아니라 **여섯 자리 코드** 쪽 — 앱으로 돌아오는 링크의 설정이 필요 없다).
- **이전 로그인 방식을 기억한다 [제안].** 구글로 가입한 사람이 다음에 애플로 들어오면 새 계정이 만들어지고 「내 기록이 사라졌다」가 된다 — 애플은 이메일을 가릴 수 있어 같은 사람인지 서버가 알 수 없다. 기기에 마지막으로 쓴 로그인 방식만 적어 두고 로그인 화면에 한 줄로 보인다 — 「지난번에는 구글로 들어왔어요」. 계정을 합치는 기능은 만들지 않는다.
- **로그인 없이 먼저 해 본다(WORLD 범위 2026-10-19 사용자 확정).** 공개 WORLD에서는 한글 만나기 전부가 손님(로그인 전)에게 열린다. 바람길·말의 리듬은 손님이 한 판씩 해 볼 수 있고 기록·코인 저장만 로그인 뒤다. 손님 판의 결과는 계정에 쓰지 않고, 손님 추천은 손님이 열 수 있는 활동만 고른다([결정 표](_ops/결정.md) 10-19 「WORLD 손님」). 처음 제안은 「한글 단계의 첫 단원은 로그인 없이 열린다」였다. 기억은 그 기기에만 남는다 — Core 판단 모듈과 공통 세션은 계정 없이도 실행할 수 있다([아틀라스 설계](아틀라스_설계.md) §2). 이어 가려면 로그인하고, 그때 기기의 기억을 계정으로 옮길지 묻는다. **옮기는 것은 지나간 사건이 아니라 지금의 현재 상태의 스냅샷이다**(익힌 글자의 상태 · 모은 것) — 동의 앞의 사건은 학습 기록에 실을 수 없다(동의 게이트의 「그때 유효」 **[확인]**). 계정에 이미 기록이 있으면 합치지 않는다 — 이해와 학습 기록은 계정의 것을 쓰고, 기기에서 모은 것(글자 자수 · 퀼트 · 간판)만 더한다. 첫 화면이 가입 양식이 아니라 첫 글자가 된다. 애플이 「꼭 필요하지 않으면 로그인을 강제하지 말라」고 보는 자리이기도 하다.
- 로그인 직후 앱이 `POST /v1/auth/register`를 **세션 토큰으로** 부르고, 서버가 그 토큰의 사용자로 학습자 행을 만든다(`origin: public`). 앱은 자기가 누구인지 본문에 적지 않는다 — 기존 원칙 그대로다. 이미 있으면 `already`다.
- **학습자 표는 지금 학생번호를 필수로 요구한다**(`engine.learners.student_code text unique not null` **[확인]**). 공개 가입의 학습자 행을 만들려면 표와 계약의 개정이 필요하다. 학생번호의 꼴을 흉내 낸 값을 채워 넣지 않는다 — 학생 번호의 채번기와 부딪히지 않게 한다(직원 번호가 글자 꼴인 이유와 같다 — §1-1).
- **가입의 동의가 곧 동의 기록이다 [확인 + 제안].** 과제 배정 · 녹음 올리기 · 사건 적재는 모두 「유효한 동의 기록」을 전제로 한다(talk `lib/동의게이트.js` — `지금유효` · `그때유효`). 지금 그 기록은 운영자 도구(`tools/동의발급.js`)가 만든다. 공개 가입에서는 가입 화면의 동의(§8-1)가 **서버에서 같은 동의 기록을 만든다** — `POST /v1/auth/register`와 한 흐름으로, 보인 언어와 문안의 판을 함께 남긴다. 이것이 없으면 가입한 사람이 과제를 받지 못하고 녹음도 올리지 못한다. 그래서 PW1 · PW13과 같은 묶음에서 세우고, 문안의 확정은 PW6에서 잇는다. 규율을 풀어서 과제가 나오게 하지 않는다.
- 가입 문항은 짧게: 화면 언어(§6, 10-19 도움 언어에서 바꿈) · 한글을 읽을 수 있는지 · (읽을 수 있으면) **연습 수준 고르기**(§4-2) · 배우는 이유. 지역(아이막)과 성별 같은 학원의 문항은 학원 연결 때 묻는다. 나라와 시간대는 묻지 않고 기기에서 읽는다(§4-1). **지금의 실물 [확인]:** 가입 문항은 `home_aimag` · `gender` · `goal_track` 셋으로 고정돼 있고 「문항 추가는 계약 개정 자리」다(talk `lib/가입문항.js`). 배우는 이유의 보기는 유학 · 취업(EPS) · K컬처 — 첫 학원의 기준이다. 일반 학습자를 위한 보기는 아래 [「배우는 이유」](#learn-reasons)로 넓혔다(2026-10-02 사용자 「배우는 이유를 잘 넓혀줘」).

**가입의 「배우는 이유」 — 2026-10-02 사용자 위임으로 정함.** 첫 학원 기준의 세 보기를 20대부터 60대까지 여러 삶의 이유로 넓힌다. 근거: 세종학당 2024 학습자 만족도 조사(2024-11~2025-01, 88개국 17,622명)의 학습 주목적은 한국문화 관심 39.8% · 학문 32.8% · 취업 14.5%였다([세종학당재단 보도](https://www.ksif.or.kr/cop/bbs/selectBoardArticle.do?nttId=9220000006915&bbsId=BBSMSTR_000000000071&pageIndex=1)). 한국어능력시험은 대학 입학·취업·결혼이민 비자·장학 등에 쓰이고([국립국제교육원](https://www.niied.go.kr/web/niied/contents/niied_topik)), 결혼이민·장기 체류·영주·귀화에는 사회통합프로그램 평가가 쓰인다([사회통합프로그램 평가](https://www.kiiptest.org/guide/compre-evaluation)). 언어 앱의 첫 설정도 재미·사람과의 연결·일·공부·여행·시간 활용처럼 여러 이유를 고르게 한다(듀오링고 첫 설정 사례, [정리 글](https://prodfolks.substack.com/p/tpf-nl-25th-april-2025)). 2026-10-02 원문 확인.

- **최대 3개를 고른다.** 순서는 매기지 않는다. 가장 큰 이유가 다음 선택을 크게 바꿀 때만 Core가 「오늘 물어볼 한 가지」([아틀라스 §5-1](아틀라스_설계.md#5-1-묻기--오늘-물어볼-한-가지))로 나중에 묻는다. 고르지 않고 넘어갈 수 있고 「나」에서 언제든 바꾼다. 바꾸면 이전 답을 덮지 않고 새 답을 더한다 — 목적은 나중에 되살릴 수 없는 기록이다(talk `lib/가입문항.js` 머리말).
- **보기가 바꾸는 것은 연습의 상황과 예문, 시험 안내다.** 실력·성향·급수의 근거로 쓰지 않고 나이·성별을 짐작하는 데 쓰지 않는다. 라벨은 1인칭의 쉬운 말로 써서 나이와 상관없이 고를 수 있게 한다.
- **민감정보가 될 이유는 보기로 두지 않는다.** 종교·건강·민족(계승어) 같은 이유는 보기에 없다. 본인이 「다른 이유」에 적을 수는 있지만, 그 글은 본인 화면에만 보이고 맞춤에 쓰거나 외부 AI로 보내지 않는다.
- **학원 문항과의 관계.** `study`·`work`·`culture`는 학원 1회 문항 `goal_track`과 같은 값이지만, 공개 가입의 답을 학원 연결 때 자동으로 `goal_track`에 옮기지 않는다(연결 전 기록은 본인 허락). 학원 문항은 학원 연결 때 따로 묻는다.
- **저장 [제안].** 값 목록(최대 3)·고른 시각·「다른 이유」 글을 남기고, 바꾸면 새 기록을 더한다. 화면 라벨은 값과 나눠 도움 언어로 옮긴다(값은 바꾸지 않는다 — `가입문항.js`의 규약). 계약 개정과 구현은 PW1 묶음에서 시험과 같은 커밋으로 한다.
- **Atlas 연결 [제안].** Core는 배우는 이유를 본인이 선언한 목표로 읽고, Strata는 이유마다 위 표의 상황 묶음을 잇고, Vellum은 「여행에 자주 쓰는 표현이라 골랐어요」처럼 이유 한 줄에 쓴다. 공통 첫 설정(`atlas/personalization.js`)의 넓은 목표와는 study → study, work·career → work, exam → prepare, culture·hobby → explore, travel·people·life → expression으로 맞추는 것을 제안한다. 대응은 엔진 담당이 구현 때 확인한다. **2026-10-03 구현:** Strata가 이유마다 상황을 잇고(`links.goals`, [Strata 설계](Strata_설계.md)), 계정 요약(synk-account `?view=atlas`)이 밝힌 이유마다 상황과 Vellum 한 줄(「주문할 때 쓰는 말이라 골랐어요.」)을 `forReasons`로 싣는다. SYNK ID의 WORLD 화면은 자기 연습이 곧 그 상황인 게임(주문 폭주 = 주문, 입장 검사 = 공공 안내문 읽기, 바람길 = 길 묻기·작업 지시 듣기, 교원 검수 전 초안)으로 「이 이유로 고른 연습」을 보이고, 고를 게임이 없는 이유에는 아무것도 주장하지 않는다. **2026-10-05 예문:** 「상황과 예문」에서 예문 쪽도 넣었다. 계정 요약이 상황마다 그 자리에서 쓰는 말 세 개([Strata 예문 층](Strata_설계.md), 교원 검수 전 초안이며 문장마다 `reviewed`를 싣는다)를 `examples`로 싣고, SYNK ID는 밝힌 이유마다 한 줄을 「이 이유로 고른 말 · 안부 — “오랜만이에요!”」처럼 보인다. 그래서 고를 게임이 없는 이유(문화·사람·공부·지금 하는 일)도 이유가 어디로 이어지는지 보이고, 게임이 있는 이유는 그 게임이 맡지 않은 다른 상황의 말을 보인다. 장면이 없는 이유(시험·배우는 즐거움·다른 이유)에는 여전히 아무 줄도 없다.
- **구현 상태(2026-10-02, 운영 적용).** 사용자 「배우는 이유랑 선택 응답 구현 시작해줘」. 값·라벨·안내의 정본은 두 저장소가 같은 바이트로 나눠 쓰는 [`계약/배우는이유_선택응답_계약.json`](../계약/배우는이유_선택응답_계약.json)(r1)이다. Core 공통 첫 설정은 `reasons`(1~3개, 계약 순서로 저장)와 `primaryReason`을 본인 선언으로 받아 위 대응대로 넓은 목표 하나로만 읽는다. 이유들이 서로 다른 목표를 가리키면 목표를 짐작하지 않고, 「가장 큰 이유」가 이번 추천을 실제로 바꿀 때만 `reasons.primary` 물음(atlas/ask.js의 「오늘 물어볼 한 가지」)을 내놓는다. 이유를 바꾸면 남은 `primaryReason`은 잊는다. talk는 synk-account에 `learn-reasons`·`learn-reasons-skip`을 두고, 이유는 덧붙이기만 하는 표에, 「다른 이유」 글과 건너뛰기 표시는 본인이 지울 수 있는 칸에 따로 둔다(마이그레이션 `20261002160000_learner_reasons_evaluation_c16`). 화면은 일반 회원 홈의 처음 한 번 묻기와 「내 SYNK 계정 › 내 정보」다. Strata의 `links.goals` 연결과 Vellum의 이유 한 줄, 도움 언어 라벨(감수 뒤 계약에 더함)은 다음 단계다.

**나이대·성별 선택 응답 — 평가에만 쓴다(2026-10-02 사용자 확정).** 사용자 「웅 받아」. [철학 v3.0 §2](SYNK_철학.md#help-evidence)의 「어느 쪽 사람들에게도 나빠지지 않을 때만 새 방법을 넓힌다」를 나이대·성별로도 확인하기 위해, 본인이 원할 때만 나이대와 성별을 받는다. §8-1의 「나이를 묻는 화면과 생년월일 수집은 두지 않는다」(09-19)는 그대로다 — 이것은 나이 확인이 아니라 건너뛸 수 있는 선택 응답이고, 생년월일과 정확한 나이는 받지 않는다.

- **언제 묻나 [제안].** 가입 화면에는 두지 않는다(가입 문항은 짧게). 첫 연습을 마친 뒤 한 번, 건너뛰기를 기본으로 둔 카드로 묻는다. 건너뛰면 다시 묻지 않는다([아틀라스 §8-9](아틀라스_설계.md#8-9-소통의-선--센스와-감시-사이)). 「나 > 내 정보」에서 언제든 답하고 바꾸고 지운다. 학원을 통해 들어온 만 14세 미만 계정에는 묻지 않는다.
- **보기.** 나이대: 14~19세 · 20대 · 30대 · 40대 · 50대 · 60대 이상 · 답하지 않음. 성별: 여성 · 남성 · 다른 답 · 답하지 않음.
- **안내와 동의 [제안].** 「SYNK가 모든 나이와 성별에 고르게 도움이 되는지 확인하는 통계에만 씁니다. 연습을 고르는 데에는 쓰지 않고, 답하지 않아도 쓰는 데 아무 차이가 없습니다.」 별도의 선택 동의로 받고 목적·항목·보관 기간(지우거나 계정을 지울 때까지)·거부해도 불이익이 없음을 함께 보인다. 개인정보 처리방침에도 같은 항목을 적는다(PW6).
- **쓰는 곳.** 맞춤의 입력이 아니다. Core의 공통 첫 설정은 나이·성별을 입력으로 받지 않는다(`atlas/personalization.js`). 맞춤 기록과 다른 곳에 두고 집계 작업만 읽는다. Temper가 새 방법을 넓힐 때 기존 집단(일반·학원·모국어의 큰 집단)에 더해 나이대·성별 집단에서도 나빠지지 않는지 본다([아틀라스 §7-4](아틀라스_설계.md#7-4-진화의-방향--늘었나--맞았나--편했나)). 한 칸의 인원이 정해 둔 수(초기값 30명)보다 적으면 비교하지 않고 기다린다. 결과는 집단 단위로만 남긴다.
- **하지 않는 것.** 강사·학원·다른 이용자에게 보이지 않는다. 광고·홍보 대상 고르기에 쓰지 않는다. 외부 AI에 보내지 않는다. 학원 1회 문항의 `gender`(분포 점검 전용)와 합치지 않는다.
- **지우면** 이후 집계에서 빠진다. 이미 만든 집단 단위 숫자는 개인을 알아볼 수 없어 남는다.
- 최초 계획은 PW1(공개 가입)·PW6(약관·동의 문안) 묶음이었다. 계정 응답 기능은 아래 10-02 운영 적용 기록으로 갱신됐으며, 개인정보 처리방침 문안은 별도 남은 일이다.
- **구현 상태(2026-10-02, 운영 적용).** 공개 가입보다 먼저, 지금 있는 SYNK 계정에 붙였다. talk synk-account가 `evaluation-answer`(동의판 `eval-demographics-1`과 같을 때만)·`evaluation-skip`·`evaluation-delete`를 받고, 응답은 맞춤 기록과 다른 표(`engine.synk_evaluation_responses`)에 둔다. 지우면 값 칸이 비워지고, 건너뛰거나 지운 뒤에는 먼저 묻지 않는다. 카드는 맞춤 읽기에서 연습 하나를 마친 뒤 한 번 보이고 「답하지 않고 넘어가기」가 기본 단추다. **학원 소속 계정에는 묻지 않는다** — 위 원칙은 「만 14세 미만 학원 계정」이지만 지금은 나이를 가를 수 없어 학원 소속 전체를 뺐다(미성년 보호자 모듈 PW18이 나이 신호를 주면 좁힌다). Temper `groups()`가 집단별 비교를 맡는다: 사람마다 한 번 세고(새 문항 혼자 푼 정확도의 평균), 칸이 30명보다 적으면 비교하지 않으며 그 인원수도 내지 않는다. 유의성 검정도 승격 판정도 아니다. 함수가 마이그레이션보다 먼저 배포돼도 계정 화면은 그대로 서고 내 정보만 꺼진다. 운영 DB 적용과 synk-account·synk-learning 배포는 같은 날 마쳤다(talk `73846bd`, 리허설 → 운영). 개인정보 처리방침 문안(PW6)은 남았다.
- 「앱은 `signUp`을 부르지 않는다」는 문장은 개정이 필요하다. 지키려던 것 — **학습자 행은 서버만 만든다** — 은 그대로 남는다(09-19 사용자 허가 — 아래의 개정문).

**학원 연결 — 코드는 로그인 수단이 아니라 연결 열쇠다 (2026-09-19 사용자 확정)**

- 사용자의 원안은 「학원생은 코드로 로그인」이었고, 이 설계의 권고 — **로그인은 모두 같게, 코드는 로그인 뒤에 한 번 넣는 연결 열쇠로** — 를 사용자가 받았다(「코드는 연결 열쇠로 가자. 계약 두 문장도 고쳐도 돼」). 이유: 무료로 쓰다가 학원에 등록한 사람이 새 계정으로 처음부터 시작하면 아틀라스가 쌓은 이해가 사라진다. 학원을 그만둔 뒤에도 계정과 기록이 남아야 한다(졸업 뒤 케어). 지킬 로그인 경로가 하나가 된다.
- 연결은 게이트다: `POST /v1/academy/link { code, phone_last4 }`를 세션 토큰으로 부른다. 서버가 코드(한 번만 쓰임 · 유효기간 · 시도 제한)와 뒷자리를 명부와 대조해, **그 토큰의 학습자**를 명부의 그 학생에 묶는다. 실패의 응답은 가르지 않는다(first-login과 같은 규율). 앱은 어느 학생인지 주장하지 않는다.
- 명부의 학생과 학습자는 1:1이다. 이미 다른 계정에 묶인 학생의 코드는 같은 실패 응답이다. 옮겨 묶기는 학원(운영자)의 절차로만 한다.
- 구글·애플 계정을 쓰지 않는 학생을 위해 **기존 학생번호 로그인은 그대로 둔다**(이미 서 있다). 두 경로 모두 「명부의 학생 ↔ 학습자 1:1」로 모인다.
- **연결 해제.** 학원을 그만두면 묶음이 풀리고 학원의 자리가 사라진다. 학습 기록과 아틀라스의 이해는 본인 계정에 남는다. 학원의 운영 기록(출석 등)은 학원 쪽의 보관 규칙을 따른다.
- **연결 전의 기록은 본인이 허락해야 학원에 보인다 [제안].** 직원 메뉴는 학원에 연결된 학생에게만 닿는다(§1-1). 그런데 무료로 쓰던 사람이 연결하면 그 사람의 **연결 전** 녹음과 기록까지 선생님의 화면에 오를 수 있다 — 그 기록은 「AI가 처리한다」는 말만 듣고 남긴 것이다. 그래서 연결하는 자리에서 한 번 묻는다: 「지금까지의 기록도 선생님이 볼 수 있게 할까요?」 기본은 **아니요**다. 직원 API는 연결된 때부터의 기록과 본인이 허락한 그 전의 기록만 돌려주고, 해제하면 그 학습자를 더는 돌려주지 않는다. 아틀라스의 이해(맞춤)는 허락과 무관하게 본인에게 이어진다 — 그것은 본인의 것이다.
- 지금은 실제 학원생 계정이 0개다. 구조를 바꾸는 비용이 가장 적은 때다. 코드 기능은 공개 출시의 조건이 아니며 첫 학원생 전에 서면 된다(§9).

**계약의 개정문 [제안] — 문서만 먼저 고치지 않는다.** talk의 시험 넷(`tests/C0계약.test.js`·`tests/계약역방향.test.js`·`tests/사건위조.test.js`·`tests/철회경로.test.js`)이 그 문서를 읽고, `tests/인증API.test.js`가 「앱은 `signUp`을 부르지 않는다」를 지킨다 **[확인]**. 그래서 아래 문장은 구현·시험과 **같은 커밋**에서 고친다(PW1·PW8).

| 자리(talk `docs/C0_API계약.md`) | 지금 | 고친 문장 |
|---|---|---|
| §2의 3번 · §10의 표 | 앱은 `signUp`을 절대 부르지 않는다. 계정 생성은 서버만 한다 | **학습자 행은 서버만 만든다.** 공개 가입(구글·애플 — 이메일은 뒤에)의 인증 계정은 Supabase Auth가 만들고, 학습자 행은 `POST /v1/auth/register`가 **토큰의 사용자로** 만든다. 앱은 학습자·학생번호를 본문에 싣지 않는다. 학생번호 계정은 지금처럼 first-login만이 만든다 |
| §2의 🚫 문단 | `/v1/learners/link` 재제안 금지 | **결합은 앱이 주장하지 않는다 — 게이트가 확정한다.** 학원 연결은 `POST /v1/academy/link`(코드와 전화 뒷자리 · 한 번만 쓰이는 코드 · 시도 제한 · 실패 응답을 가르지 않음)로만 하며, 서버가 **토큰의 학습자**를 명부의 학생에 묶는다. 본문에 `learner_id`·`student_code`를 실으면 400이다. 게이트 없는 결합 통로는 계속 만들지 않는다 |

## 3. 코드를 넣으면 — 다시 켜지 않는다

1. 「나」 자리의 「학원 코드가 있어요」에 코드와 전화 뒷자리를 넣는다(연결이 필요하다).
2. 서버가 확인해 묶는다.
3. 앱이 **내 자격**을 다시 받는다 — `GET /v1/me`(제안): 역할 · 연결된 학원과 반 · 선생님 · 켜진 기능 묶음.
4. 화면 구성이 **그 자리에서** 바뀐다. 앱을 다시 켜거나 새로 받지 않는다. 학원의 화면은 처음부터 앱 안에 들어 있고 자격으로 가려져 있었을 뿐이다 — 새 코드를 내려받는 것이 아니다.
5. 환영 장면 한 번 — 방에 반의 표식이 걸리고 선생님 소개 카드가 놓인다.

- 앱은 시작할 때마다, 그리고 코드를 넣은 직후에 자격을 받는다. 내비게이션은 그 값 하나로 갈린다. 화면마다 따로 판정하지 않는다(갈라지면 어떤 화면만 보이는 고장이 난다).
- **보이는 것과 되는 것은 따로 지킨다.** 화면을 가리는 것은 편의이고, 막는 것은 서버다(RLS와 함수의 권한 검사). 자격 없는 사람이 학원 기능의 주소를 알아도 서버가 거절한다.
- **2026-10-02 싱크 타운 BM 반영:** 마을은 일부 체험 무료 + 정액제 + 선택 상품으로 제공한다([BM-10](BM_목록.md#synk-town-bm)). TOPIK 1급+ 통과와 체험·정액 이용권, 선택 상품 소유를 별도로 확인하는 설계다. 구매만으로 학습 통과나 직원 자격을 얻을 수 없다. 기존 구독·학원 좌석의 포함 범위, 저장 필드와 권한 조회·복원 계약은 상품 정리와 구현 때 확정하며 이번에 C0 계약이나 앱 코드를 변경하지 않는다.
- 직원 메뉴도 같은 값으로 갈린다(§1-1). **코드를 넣는 일은 학원생의 자리만 연다 — 직원 자격을 만들지 않는다.**
- 권한을 DB의 묶음에서 읽으면 토큰을 바꿀 필요가 없다. 역할을 토큰의 클레임에 싣는 구현이라면 세션을 한 번 새로 받는다 — 어느 쪽이든 다시 켜지 않는다.
- 자격은 기기에 남겨 두어 오프라인에서도 학원의 자리가 보인다. 해제는 다음 동기화 때 반영되고, 그동안의 학원 기능 호출은 서버가 거절한다.
- 실패하면 한 문장만 보인다(「코드를 확인해 주세요」). 시도 제한에 걸려도 같은 문장이다.

## 4. 사람 없이 도는 것이 기본이다

공개 사용자는 강사나 검수자의 확인 없이 앱을 이용한다. 따라서 [아틀라스 설계](아틀라스_설계.md) §3의 자동 개인화가 기본 동작이어야 한다. 학원에 연결되면 강사나 검수자의 입력을 더 강한 근거로 추가한다.

| 경험 | AI 호출 | 공개 사용자 |
|---|---|---|
| 한글 단계([설계](한글단계_설계.md)) | 0 | 그대로 |
| 초급 풀(구현 명세 §4-15) | 0 | 그대로 |
| 게임 | 0(검수가 확정된 팩) | 자동 채점되는 것만. 마을 게임은 학습 해금과 BM-10의 무료 체험·정액 권한 범위 안에서 제공한다. 사람의 검수가 필요한 게임(G1의 글)은 AI가 본 피드백으로 표시하거나 뒤로 미룬다 **[사용자]** |
| 매일 말하기(Lv3~6)의 과제 생성 | 있음 | 하루 상한 안에서(§7). 넘으면 풀의 과제 |
| 교정 | 있음 | §5 |
| Core 판단·공통 세션 모듈 | 0(순수 계산) | 그대로 |

**호출이 없는 경험이 공개판의 바탕이다.** 비용이 사람 수에 비례해 늘지 않는 것부터 세운다.

### 4-1. 공개 학습자의 하루 과제 — 열 때 배정한다 [제안]

**지금 [확인: 코드의 주석].** 매일의 배정은 밤 배치(talk `supabase/functions/deliver/index.ts`)가 `engine.learners` 전체를 배치로 처리해 만든다. 같은 파일은 재적 800 안팎에서 Edge 함수의 실행 시간 제한에 도달한 기록을 적는다(2026-08-22 수리). 배치의 날짜는 몽골 달력의 문자열이다(`lib/게임배정.js`).

- 공개 학습자는 **앱을 연 때** 그날의 과제를 배정한다. 서버 함수가 그 학습자의 시간대로 「오늘」을 정하고, 같은 학습자·같은 날이면 같은 결과를 낸다(멱등키 = 학습자와 그 사람의 날짜). 조립기(`lib/오늘과제.js`)와 Core 판단 모듈은 순수 함수라 밤 배치와 같은 코드를 부를 수 있다.
- 밤 배치는 학원에 연결된 학생의 것으로 남긴다 — 교정문의 우선순위와 검수의 흐름이 밤의 리듬에 맞춰져 있다. 공개 학습자를 밤 배치에 넣지 않는다. 사람 수에 비례해 배치가 길어지고, 나라마다 밤이 다르다.
- 시간대는 가입 때 기기에서 받아 학습자의 설정으로 서버에 둔다. 요청마다 본문으로 받지 않는다 — 날짜를 앱이 주장하지 않게 한다.
- **시간대와 나라가 바뀔 때 [제안].** 몽골에서 배우던 학생이 한국으로 유학을 가면 「오늘」이 한 시간 어긋난다 — 이 앱의 학생에게는 흔한 길이다. 기기의 시간대가 서버에 둔 값과 사흘 이어서 다르면 앱이 한 번 묻는다(「지금 계신 곳의 시간으로 바꿀까요?」). 바꾸는 일은 본인의 설정 변경으로 남고, 바뀐 시간대는 **다음 날부터** 쓴다 — 같은 날에 과제가 둘 나오거나 하루가 비지 않게 한다. 나라(두 나라의 달력의 「내 나라」)는 가입 때 기기의 지역 설정에서 읽어 기본값으로 두고 설정에서 바꾼다. 나라를 모르면 한국의 날만 보인다.
- **사람 수에 비례하는 아틀라스의 일도 열 때 한다 [제안].** 이해 요약의 계산 · 낮은 난이도에 고정되는 문제 해소 · 지난 회차의 결과 확정처럼 학습자마다 도는 일은 일반 학습자에게는 앱을 열 때(그 사람 · 그 사람의 날짜로 한 번) 돈다. 밤 배치에는 전체를 보는 일(후보 만들기 · 몫의 집계 · 급락 되돌림)만 둔다.
- `task.assigned`가 서버 이벤트이라는 계약은 그대로다. 쓰는 주체가 밤 배치에서 「열 때 부르는 서버 함수」로 하나 늘 뿐이다.
- **이것이 없으면 비공개 테스트의 테스터가 과제를 받지 못할 수 있다** — 지금의 배정은 명부의 학생을 전제로 한다. 첫 확인 자리다(§12).
- **인수 기준.** ① 같은 학습자가 같은 날 여러 번 열어도 과제는 하나다. ② 시간대가 다른 두 학습자가 자정 앞뒤에 각자의 날짜로 받는다. ③ 공개 학습자 수가 늘어도 밤 배치의 시간이 늘지 않는다. ④ 오프라인에서 열면 마지막으로 받은 과제와 호출 없는 경험이 보인다.

### 4-2. 일반 학습자의 연습 수준 — 본인이 고르고, 올리기는 확실할 때만 (2026-09-19 사용자 확정)

**지금의 실물 [확인].** 수준(`learners.level_current`)은 강사가 명부 시트에 한 달에 한 번 적는 값이다(talk `lib/명부규칙.js`). 값이 없으면 앱은 **초급으로 본다**(`lib/오늘과제.js` 「모르면 초급으로 본다」). 초급은 AI가 과제를 짓는 갈래에 들지 못하고(Lv3~6만), 검증된 초급 문장은 아직 0개다 — 그래서 수준이 없는 사람은 **매일 같은 도입 문장**을 받는다. 일반 가입자에게는 수준을 적어 줄 사람이 없다. 이대로 비공개 테스트를 열면 테스터 전원이 14일 동안 같은 문장을 보고, AI 교정이 돌지 않아 회차당 단가(§7)도 잴 수 없다.

**연습 수준.** 일반 학습자의 수준은 **본인이 고르는 설정**이다. 평가가 아니다 — 학원의 공식 급수(강사가 정한다)와 이름을 가른다.

- **고르는 법(가입 때 · 30초 · AI 호출 0).** 한글을 읽을 수 있다고 답한 사람에게 수준이 다른 문장 넷을 쉬운 것부터 보여 주고 「편하게 읽히는 데까지」 고르게 한다. 하나도 편하지 않으면 Lv1에서, 아니면 고른 문장의 수준에서 시작한다(문장과 수준의 짝은 설계값 · 문장은 커리큘럼에서 고른 검증된 것 **[사용자: 문장 확인]**). 시험이 아니다 — 맞고 틀림을 매기지 않는다. 소리는 목소리가 확정된 뒤에 곁들인다.
- **시작은 낮은 쪽에서.** 고른 수준 안에서 작업 난이도([아틀라스 설계](아틀라스_설계.md) §5-2)는 「한 단계 아래」에서 출발한다. 쉬우면 개인화 과정이 며칠 안에 스스로 올린다 — 첫날의 「너무 어렵다」가 「너무 쉽다」보다 비싸다.
- 본인은 설정에서 언제든 바꿀 수 있다. **내리는 길은 넓고, 올리기를 권하는 일은 드물다**(아래).
- 서버는 이 값을 본인의 선언으로 남기고(누가 · 언제 · 어느 화면에서 · 권유에 답한 것인지), 과제 생성과 초급 풀은 이 값을 수준으로 읽는다. 학원에 연결되면 학원의 공식 급수가 앞서고, 해제하면 마지막 값이 연습 수준으로 남는다.

**올리기는 확실할 때만 권한다**(사용자 09-19: 「너무 쉽게 단계를 올리지 않도록 보수적으로 접근해야 해. 확실히 레벨업했을 때만 한 단계 올리도록 제안하자」). 아틀라스는 수준을 스스로 바꾸지 않는다. 아래가 **전부** 찼을 때에만 「한 단계 올려 볼까요?」를 한 번 묻고, 정하는 것은 본인이다(수치는 설계값 · 매개변수).

| 조건 | 뜻 |
|---|---|
| 작업 난이도가 그 수준의 **맨 위**에 있다 | 지금 수준에서 낼 수 있는 가장 길고 복잡한 과제를 이미 받고 있다 — 최근 10회차 이상 |
| **혼자 해낸** 결과가 충분하다 | 최근 20회차 가운데 18회차 이상. 도움받은 회차는 세지 않는다. 사람이 확정하지 않은 AI의 교정은 약한 근거라 30회차 가운데 27회차 이상으로 본다 |
| **여러 날에 걸쳐** 그렇다 | 서로 다른 14일 이상에 걸친 회차여야 하고, 하루에 세는 회차는 둘까지다 — 하루에 몰아 한 것으로 오르지 않는다 |
| 그 수준을 **고르게** 해냈다 | 그 수준의 배울 학습 항목(Strata) 가운데 일곱 할 이상을 혼자 해낸 적이 있다 — 잘하는 것만 되풀이해서는 오르지 않는다 |
| **시간이 지나도** 남아 있다 | 7일 넘게 지나 다시 만난 학습 항목을 혼자 해낸 비율이 여덟 할 이상 |
| **윗수준의 맛보기**를 해냈다 | 윗수준의 학습 항목(선행이 다 찬 것)를 연습 대상으로 정한 과제를 서로 다른 날에 세 번 받아 세 번 다 혼자 해냈다. 맛보기는 위 다섯이 찬 뒤에만 나가고(하루 하나 · 연습 대상 하나만), 한 번이라도 막히면 조용히 거둔다 |
| 최근에 바뀐 적이 없다 | 마지막 수준 변경 · 권유 · 거절에서 30일이 지났다 |

- **한 번에 한 단계.** 건너뛰지 않는다. 받아들이면 첫 다섯 회차는 분량을 줄이고 도움을 넉넉히 연다.
- Lv2에서 Lv3으로 가는 자리는 과제의 꼴이 바뀐다(고르기 → 내 말로 답하기). 맛보기는 그 꼴의 과제로 하고, 권유의 말도 그것을 알려 준다.
- **되돌아가는 길은 넓다.** 올린 뒤 첫 열 회차의 혼자 해냄이 절반에 못 미치면 「예전 수준으로 돌아가도 좋아요」를 한 번 묻는다. 탓하는 말은 없다. 돌아가면 60일 동안 다시 권하지 않는다.
- 말은 판정이 아니다. 「이제 중급이에요」가 아니라 「요즘 문장이 편해 보였어요. 한 단계 위 문장을 해 볼까요?」 — 측정의 한계(구현 명세 §6-1: 오류가 보이지 않았다는 것이지 익혔다는 뜻이 아니다)를 말에서도 지킨다.
- 하루에 먼저 말 거는 것은 하나다(소통의 선). 이 질문도 그 하나에 든다.
- 학원에 연결된 학생에게는 이 질문을 하지 않는다. 같은 근거를 강사 제안 카드에 「수준을 올려 볼 만해요」로 곁들이고, 급수는 강사가 정한다 — 「평가의 의미는 자동으로 바꾸지 않는다」는 그대로다.
- 비교용 기본 회차는 이 권유를 하지 않는다. 권유의 조건 · 받아들임 · 그 뒤의 결과는 학습 기록에 남아, 조건의 수치가 맞았는지를 나중에 읽을 수 있다. 조건의 수치를 자동 경로가 느슨하게 하지 못한다 — 평가의 의미에 닿는 값이다.
- 수준 고르기는 비공개 테스트 전에 선다(PW14). 올리기 권유는 아틀라스의 결과 반영 · Strata · 묻기 · 작업 난이도가 선 뒤에 선다(구현 명세 §4-17 · WP32). 그 전에는 본인이 설정에서 바꾼다.

**인수 기준.** ① 수준이 없는 일반 학습자는 가입 흐름에서 수준을 고르기 전에는 과제 배정으로 넘어가지 않는다(한글을 못 읽는 사람은 한글 단계로). ② 하루에 40회차를 다 맞혀도 권유가 나오지 않는다. ③ 한두 학습 항목만 되풀이해 맞힌 합성 학습자에게 권유가 나오지 않는다. ④ 맛보기에서 한 번이라도 막히면 권유가 나오지 않고 맛보기는 거둬진다. ⑤ 거절 뒤 30일 · 되돌아간 뒤 60일 안에는 다시 묻지 않는다. ⑥ 어떤 경우에도 수준이 본인의 확인 없이 바뀌지 않는다. ⑦ 학원에 연결된 학생에게는 질문이 나가지 않고 강사 제안 카드에만 실린다. ⑧ 시뮬레이션에서 「천천히 느는 학생」은 권유를 받고 「운 좋은 하루」 학생은 받지 않는다.

### 4-3. 엔진의 배움에 세지 않는 계정 [제안]

공개 가입을 시작하면 테스터, 스토어 심사용 합성 계정(§8-3), 직원, 개발·시연용 계정도 운영 서버를 사용한다. 이들의 사용은 실제 학습 목적의 사용과 다르므로, 새 정책의 적용을 확대하거나 집단별 초기값을 정하는 통계에서 제외한다. 나중에 정확히 구분하기 어려우므로 첫 테스터가 가입하기 전에 계정 종류를 기록해야 한다.

- **지금의 실물 [확인].** 학습자 표에 시험 계정 표식이 이미 있다(`engine.learners.is_test` — 2026-09-02 · 도구가 만드는 시험 학습자에 쓴다). 집계에서 이것을 빼는 규칙은 아직 없다.
- 학습자마다 **종류**를 둔다: 일반 · 학원 · 테스터 · 합성(심사 · 리허설 · 도구) · 직원. 만들 때 서버가 정하고 앱이 주장하지 않는다. 비공개 테스트 동안 가입한 계정은 테스터다. 공개 출시 뒤에도 계속 쓰는 테스터를 일반으로 바꾸는 것은 운영자의 절차다(기록에 남긴다).

| | 일반 · 학원 | 테스터 | 합성 · 직원 |
|---|---|---|---|
| 그 사람 안의 맞춤(이해 · 묶음) | 돈다 | 돈다 | 돈다 — 심사자도 아틀라스를 본다 |
| 새 버전의 승격 · 비교 회차 집계 · Prism의 분포 | 센다 | **세지 않는다** | **세지 않는다** |
| 학생별 비용 한도·회계용 전체 집계 | 센다 | 센다 | 센다 — 돈은 실제로 나간다 |
| 회차당 단가의 실측(§7) | 센다 | 센다 | 세지 않는다 |

- 속도 제한에 걸리거나 이상 사용으로 보류된 계정의 회차도 승격과 분포의 집계에서 뺀다. 자동 채점 문항의 맞고 틀림은 앱이 보낸 값이다 — 한 사람 안의 맞춤에는 그대로 쓰되(자기를 속이면 자기 과제가 어긋날 뿐이다), 여러 사람에게서 배우는 집계는 위 규칙과 이상 거름을 거친 것만 쓴다.
- **집단을 섞어 승격하지 않는다.** 새 버전이 넓혀 가는 조건(구현 명세 §6-4)에 「일반과 학원 · 모국어의 큰 집단 어느 쪽에서도 나빠지지 않았다」를 성능 저하 방지 지표로 더한다. 집단을 갈라 따로 최적화하는 것이 아니라 **한쪽이 나빠지는 승격을 막는 것**이다. 표본이 모자란 집단은 「모자라다」로 두고 막지 않는다 — 학원생이 0명인 동안 단계별 적용 확대가 멈추지 않게 한다.

## 5. 사람 없는 교정

**지금 [확인]:** 학생 화면에 돌아오는 교정은 사람이 확정한 것이다(talk P0 §4의 관통 확인 5 · 확정 통로 §7-2). 검수자 한 명의 용량은 가정 위의 어림이다(같은 문서 §2-3).

**공개 사용자 [제안]**

- AI의 교정을 **「AI가 본 것」이라고 표시해** 바로 돌려준다. 사람이 확정한 교정과 같은 모양으로 보이지 않게 한다.
- 확신이 낮은 교정은 보여 주지 않는다. 틀린 교정보다 침묵이 낫다. 어떤 오류 유형을 단정하고 어떤 것을 「이렇게도 말해요」로 낼지는 유형별 실측으로 정한다 **[사용자: 기준]**.
- 아틀라스에서는 **약한 근거**다 — 서로 다른 제출에서 거듭 나와야 이해 항목이 생긴다(구현 명세 §3-2). 이미 설계된 등급 그대로다.
- 학원에 연결되면 같은 제출에 사람의 확정이 더해질 수 있고, 그 판정이 앞선다.

## 6. 모든 사람을 위한 앱 — 말

- 앱의 말은 한국어다. 읽히게 하는 방법은 다른 나라 말이 아니라 **눈높이**다([아틀라스 설계](아틀라스_설계.md) §8-2). 2026-10-19부터 이 말은 **배우는 내용**에 해당한다. 기능 글과 안내는 아래 「화면 언어」대로 학습자가 고른 말로 보인다.
- **도움 언어**(학습자가 고른 자기 말)는 글자를 처음 배우는 한글 단계에서 쓴다는 기존 원칙을 유지한다. 09-19의 영어·몽골어 두 언어 출발안은 **09-20의 약 20개국 동시 공개 출시 방향에 맞춰 지원 언어 표를 다시 정한다.** 국가 수와 언어 수는 같지 않다. 국적만으로 언어를 정하거나 영어를 모든 사람이 이해한다고 가정하지 않는다. 영어·몽골어 기존 자료는 보존한다. **2026-10-02 사용자 결정:** 브라질·멕시코를 출시 목록에 넣었다. 그래서 스페인어(멕시코·파라과이, 중남미 공통 tú)와 포르투갈어(브라질)가 지원 언어에 들어간다([결정 표](_ops/결정.md) 10-02, [브라질·멕시코 전략](마케팅/LAB_브라질_멕시코_전략_20261002.md)).
- 도움 언어가 아직 없는 나라의 사람도 시작할 수 있어야 한다. 한글 단계의 안내는 **보여 주는 안내**가 먼저다 — 몽글의 시범과 그림과 소리. 글은 곁들임이다.
- **화면 언어를 하나 고른다(2026-10-19 사용자 확정).** 09-19의 「글자를 읽지 못하는 동안 기능 글에 도움 언어를 작게 곁들이고, 졸업하면 함께 사라진다」를 이렇게 바꿨다. 한글 단계에 있는 사람은 「설정」 · 「나가기」 · 「오늘의 AI 교정은 다 썼어요」 · 연결이 끊겼다는 말도 읽지 못한다는 출발점은 같다. 다만 두 언어를 함께 보여 주면 휴대폰 한 화면의 글이 두 배가 되고, 문제의 보기까지 옮기면 답이 보이고 안 옮기면 규칙이 섞인다. 선도 앱도 화면 언어 하나에 배우는 언어의 내용을 얹는 구조다.
  - **한 자리에 한 언어.** 기능 글(메뉴 · 단추 · 설정 · 로그인 · 계정 연결 · 오류와 한도의 안내 · 권한을 청하는 말 · 목표 창)과 안내 · 설명(튜터 말 · 문제 지시 · 오답 해설)은 고른 화면 언어로 보인다. 학습 내용(표현 · 보기 · 이야기 대사 · 포스터의 큰 한글)은 늘 한국어이고, 뜻은 답한 뒤 눌러서 본다.
  - **첫 실행 순서.** 언어 고르기 → 「한글을 읽을 수 있어요?」 → 튜터 고르기. 언어 이름은 그 언어 글자로 쓰고(English · Монгол …), 지원 언어 중 기기 설정을 미리 고른다. 미지원 언어를 조용히 영어로 간주하지 않는다.
  - **1판**은 영어 · 몽골어 둘로, 막히는 화면부터 옮긴다: 첫 화면 · 튜터 고르기 · 목표 창 · 로그인과 계정 연결 · 설정 · 오류 · 메뉴, 한글 만나기 안내, 첫 레슨들의 문제 지시와 해설. 몽골어 문장은 기존 몽골어 검문 길로 확인한다.
  - **2판**은 튜터 대사(언어마다 캐릭터 말투 지침을 만든 뒤) · 게임 화면 전체와 **한글 졸업 뒤 안내를 한국어로 옮겨 가기**다. 졸업 때 한 번 권하고 언제든 되돌릴 수 있다. 09-19의 「졸업하면 없앤다」를 이것이 대신한다. 스페인어 · 포르투갈어는 1판 뒤에 더한다.
  - **구현(10-19, 10-20 공개):** 1판을 끝내 synk.im/world에 공개했다(origin `52ec157ab`, synk-policy `c3bb1ab`). 첫 화면·언어 고르기·「한글을 읽을 수 있어요?」·튜터 고르기·목표 창·로그인과 계정 연결(체험 판 뒤 안내·「한글 기록 이어 가기」 포함)·설정·오류와 상태·아래 메뉴·배우기와 놀이 시트, 한글 만나기 안내·이유 한 줄·마무리, 인사 팩의 문제 지시·해설·결과와 답한 뒤 「뜻 보기」가 영어·몽골어로 보인다. 고른 언어는 손님은 기기, 계정은 생활 진도 기록에 둔다. 튜터 대사·게임 화면·다른 팩의 문제 글·「우리 반 수업」은 2판까지 한국어다. 몽골어는 세 겹 확인(역번역 대조·Fable 교정·아르곤 문법)을 거쳤다.
  - 그림 기호와 보여 주는 안내가 먼저라는 원칙은 그대로다. 근거: [결정 표](_ops/결정.md) 2026-10-19 「WORLD 화면 언어」.
- 「두 나라의 달력」은 한국의 날과 **그 학생이 선택한 나라의 날**이다. 몽골의 기존 달력은 여러 국가별 자료 중 하나로 유지한다.
- 여러 학생에게서 배우는 일(Prism)은 모국어별로 가른다 — 헷갈리는 글자의 짝은 모국어마다 다르다.
- 동의·개인정보·계정 지우기처럼 **뜻을 정확히 알아야 권리를 쓸 수 있는 글**은 학습용 글이 아니다. 그 사람이 읽을 수 있는 말로 보여야 한다. 출시 대상 국가와 지원 언어에 맞춰 준비하며, 영어·몽골어·한국어만으로 모두 준비됐다고 판단하지 않는다.

### 7-1. 녹음의 보관 — 일반 학습자는 30일 (2026-09-19 사용자 확정)

- 일반 학습자의 녹음 원본은 **올린 지 30일 뒤에 지운다.** 받아쓴 글 · 교정 · 학습 사건은 남는다(계정을 지우면 함께 지워진다 — §8). 편지는 남고 녹음의 소리만 지워진다.
- **이정표 녹음은 남긴다.** 첫 녹음과, 달마다 하나(그달에 처음 혼자 해낸 학습 항목의 녹음 — 없으면 그달의 첫 녹음)는 지우지 않는다. 「한 달 전의 나와 나란히 듣기」([아틀라스 설계](아틀라스_설계.md) §8-6)가 이 녹음을 사용한다. 이정표도 본인이 지울 수 있고, 계정을 지우면 전부 지워진다.
- 지우는 일은 서버의 예약 작업이 한다. 지운 뒤에 늦게 끝난 계산이 되살리지 않는다. 편지함에서는 지워진 녹음의 자리에 「글만 남아 있어요」가 보인다 — 없는 파일을 재생하려다 오류가 나지 않게 한다.
- 기간은 개인정보 처리방침에 적는다(§8-1). 기간을 바꾸면 방침의 판이 바뀐다.
- 선택 동의(엔진을 좋게 하는 데 내 기록을 쓰기)를 켠 사람의 녹음을 더 오래 둘지는 그 동의의 문안과 함께 정한다 **[사용자]**.
- 학원에 연결된 학생의 녹음은 학원의 동의와 보관 규칙을 따른다 — 이 30일의 대상이 아니다.
- **크기의 어림.** 녹음 정본은 16kHz · 16비트 · 한 채널의 WAV다(talk `src/온디바이스전사.js` 머리말 **[확인]**) — 1초에 32KB, 30초에 약 1MB. 하루 두 번이면 한 사람에 하루 1.5MB 안팎이고, 테스터 서른 명의 14일이 0.6GB쯤이다. 서버 요금제의 저장 한도를 비공개 테스트 전에 확인한다(§12).

### 8-1. 약관과 동의 — 꼭 필요한 것만 (2026-09-19 사용자 지시)

| 둘 것 | 왜 빠질 수 없나 |
|---|---|
| **개인정보 처리방침** — 공개된 주소 하나 | 두 스토어가 등록 때 요구한다. 무엇을 모으나(계정 · 학습 기록 · 음성) · 왜 · 어디로 가나(AI 처리를 맡기는 곳과 서버의 나라) · 얼마나 두나(일반 학습자의 녹음은 30일 · 이정표 녹음만 남는다 — §7-1) · 어떻게 지우나 |
| **이용약관** — 짧게 | 서비스의 범위 · AI가 본 교정은 틀릴 수 있다는 것 · 해서는 안 되는 쓰임 · 그만두기 |
| **가입 화면의 동의 한 번** | 위 둘에 대한 동의. 동의 문장에 **「만 14세 이상입니다」**가 들어간다. 체크 하나와 버튼 하나. 이 동의가 서버의 동의 기록이 된다 — 보인 언어와 문안의 판을 함께 남긴다(§2) |
| **녹음 앞의 동의** | 마이크 권한을 청하기 전에 한 번 — **녹음이 어느 회사의 AI로 가는지 이름을 밝히고 허락을 받는다**(「녹음은 교정을 위해 ○○의 AI가 처리해요」와 허락 버튼). 애플은 개인 자료를 제3자 AI와 나누려면 어디로 가는지 밝히고 명시적 허락을 받으라고 한다(심사 지침 5.1.2(i) · 원문 확인 09-19) — 「AI가 처리해요」 한 줄로는 모자란다. 회사 이름은 코드에서 실제로 부르는 곳 그대로 적고, 부르는 곳이 바뀌면 다시 묻는다. 권한 창의 이유 문장과 같은 뜻이어야 한다 |
| (선택 하나) 엔진을 좋게 하는 데 내 기록을 쓰는 동의 | **따로, 꺼 둔 채로 시작한다.** 나중에 소급해 받을 수 없으므로 자리만은 첫날부터 있어야 한다 |

- 그 밖의 것(마케팅 수신 · 맞춤 광고 · 제3자 제공)은 **하지 않으므로 묻지 않는다.** 하지 않는 일을 늘리지 않는 것이 문서를 줄이는 길이다.
- **출시 나라.** 09-19의 한국·몽골 비공개 테스트 계획과 별도로, **09-20 사용자 방향은 약 20개국 동시 공개 출시**다. 정확한 대상 목록·국가별 출시 준비·지원 언어를 맞춘다. 특정 국가를 뒤로 미루는 것을 자동 기본안으로 적용하지 않는다. 2026-10-02 사용자 결정으로 브라질·멕시코가 출시 목록에 들어갔다.
- **가입 나이(2026-09-19 사용자 확정).** 나이를 묻는 화면과 생년월일 수집은 두지 않는다. 대신 두 줄을 넣는다 — 가입 화면의 동의 문장에 **「만 14세 이상입니다」**(체크는 그대로 하나), 약관에 **「만 14세 미만은 학원을 통해 보호자 동의를 받고 가입합니다」**. 한국에서는 만 14세 미만의 개인정보를 모으려면 법정대리인의 동의가 필요하기 때문이다. 더 어린 학원생은 학원이 보호자 동의를 받고 학생번호 길로 들어온다. 화면도 문서도 늘지 않는다. 2026-10-02에 확정한 [나이대·성별 선택 응답](#evaluation-demographics)은 나이 확인이 아니라 평가에만 쓰는 건너뛸 수 있는 문항이며, 이 원칙(생년월일·나이 확인 화면 없음)을 바꾸지 않는다. 다만 그 선택 동의와 항목은 이 절의 개인정보 처리방침·선택 동의에 함께 적는다.
- <a id="brazil-eca-digital"></a>**브라질 — 미성년 보호법 ECA Digital(2026-10-02 사용자 결정: 출시 전에 대비한다).** Lei 15.211/2025는 2026-03-17부터 시행 중이다. 아동·청소년이 쓸 가능성이 큰 서비스라면 회사가 어디 있든 적용되고, 위반하면 브라질 매출의 최대 10%까지 벌금을 낸다. 위의 「나이를 묻지 않는다」만으로는 브라질에서 모자라다. 조항 원문 대조는 [브라질·멕시코 전략 §5-1](마케팅/LAB_브라질_멕시코_전략_20261002.md#eca-digital)에 있다.
  - 필요한 것: 스토어가 넘기는 나이 신호 받기(12·14조), 16세 이하 계정의 보호자 연결(24조, 「소셜 네트워크」 장이라 학습 앱 적용 범위는 현지 확인), 보호자 도구(구매·결제 제한, 사용 시간 보기·제한, 계정·개인정보 관리, 포르투갈어 안내 — 17·18조), 브라질 안 법정 대리인(40조), 포르투갈어 동의 글.
  - 이미 맞는 것: 루트박스가 없고(20조, BM 「하지 않는 것」), 광고·맞춤 광고용 프로파일링이 없고, 알림은 주 최대 2회이며 연속 기록 알림이 없다.
  - 설계: 나이를 묻는 화면을 새로 두지 않는다. 브라질에서는 스토어 나이 신호를 받아, 신호가 16세 이하이면 보호자 연결 흐름을 연다. **범위(10-02, 사용자가 Claude에게 맡김):** 나라별로 켜는 모듈 하나로 만들고 처음에는 브라질에서만 켠다. 상세는 [미성년 보호자 기능 설계](미성년_보호자기능_설계_20261002.md), 작업 묶음은 §10의 PW18이다.
- 문서의 말은 출시 대상과 지원 언어 표에 맞춘다. 기존 영어·한국어·몽골어 원문을 보존하며, 동의처럼 뜻을 알아야 하는 글은 그 사람이 읽을 수 있는 말로 보인다(§6).
- 이 세션은 법률가가 아니다. 위 목록은 스토어의 요구와 흔한 실무에 따른 최소이며, 공개 출시 전에 한 번 확인받기를 권한다.

### 8-2. 개발자 계정 — 개인인가 회사인가

| | 개인 계정 | 회사(조직) 계정 |
|---|---|---|
| 만드는 데 필요한 것 | 본인 신분 확인 | **등록된 법인** + D-U-N-S 번호(무료 · 받는 데 1~4주) + 회사 웹사이트와 연락처 확인 |
| 값 | 구글 25달러(한 번) · 애플 연 99달러 | 같다 |
| 스토어에 보이는 이름 | **본인의 법적 이름**(구글은 나라도 함께 · 유료 상품이 있으면 주소도) | 회사 이름(구글은 회사 주소와 연락처도 공개) |
| 구글의 정식 출시 조건 | 2023-11-13 뒤에 만든 개인 계정은 **12명이 14일 동안 끊기지 않고 비공개 테스트**에 참여해야 정식 출시를 신청할 수 있다 — **앱마다**(구글 도움말 원문 확인 09-19) | 그 조건이 없다 |
| 믿음 · 책임 | 음성을 다루는 앱을 개인 이름으로 낸다 · 책임도 개인 | 회사 이름과 책임 |
| 나중에 바꾸기 | 애플은 개인 → 회사 전환을 받아 준다 · 구글은 새 회사 계정으로 **앱을 옮긴다**(사용자와 평가가 따라온다) | — |

- **권고 — 지금은 개인 계정으로 비공개 테스트를 시작하고, 법인이 서면 회사 계정으로 옮겨 그 이름으로 공개 출시한다.** 이 세션의 기억 기록(09-07)으로는 한국 법인이 아직 없고 9월 말 설립을 보고 있었다 — 회사 계정은 법인 등기 → D-U-N-S → 계정 확인을 거쳐야 해서 2~3주 안에는 열리지 않는다. 개인 계정의 「12명·14일」 조건은 어차피 하려던 비공개 테스트와 겹친다. 공개 출시의 네 조건(§9)이 서는 데 걸리는 동안 회사 계정을 준비할 수 있다.
- 법인이 서는 날 **D-U-N-S부터 신청한다** — 구글과 애플의 회사 계정이 둘 다 이 번호를 요구하고, 가장 오래 걸리는 단계다.
- 계정을 만들고 값을 치르는 일은 사용자가 직접 한다.

### 8-3. 스토어 심사를 위한 준비 — 심사 메모와 심사용 길

두 스토어는 로그인이나 코드 뒤에 있는 기능을 심사자가 **직접 볼 수 있게** 해 달라고 한다(원문 확인 09-19). 애플 — 로그인이 있는 앱은 심사용 계정 정보를 넣는다(심사 지침 2.1) · 숨은 기능이나 적어 두지 않은 기능을 두지 않으며 새 기능은 심사 메모에 구체적으로 적는다(2.3.1). 구글 — 앱의 일부가 로그인 · 회원 자격 같은 인증으로 막혀 있으면 「앱 액세스」에 들어갈 길을 모두 적는다. 비공개 테스트(구글 비공개 테스트 · 애플 TestFlight의 외부 테스터)에도 심사가 있다.

| 준비물 | 어떻게 | 언제부터 |
|---|---|---|
| **심사용 계정** | 합성 학생의 **학생번호 계정**(번호 + 비밀번호 — 기존 로그인 그대로 §2)으로 준다. 구글 · 애플 로그인은 남에게 넘겨줄 수 있는 계정이 아니기 때문이다. 새로 만들 통로가 없다. 일반 사용자의 경험은 심사자가 자기 애플 · 구글 계정으로 들어와 본다고 메모에 적는다. 이 계정의 종류는 합성이다(§4-3) | 비공개 테스트 제출(PW10) |
| **심사 메모** | ① 로그인하는 법 ② 「이 앱에는 학원 직원용 도구가 들어 있고, 학원이 세운 직원 계정에서만 보인다」 ③ 학원 연결이 실린 뒤에는 「학원 코드를 넣으면 학원의 자리가 더해진다」와 해 보는 법 ④ 마이크를 쓰는 이유와 AI 처리. 영어로 쓰고 제출마다 고친다 | 같다 |
| **심사용 학원 자리** | 그 합성 학생을 합성 학급에 넣어 둔다 — **이미 학원에 연결된 상태**라 코드 없이도 학원의 자리가 보인다. 주된 길이다 | 학원의 자리가 앱에 실리는 제출(PW8) |
| **심사용 학원 코드** | 코드 연결을 직접 해 보려는 심사자를 위해, 다른 합성 학생에 묶인 코드와 그 전화 뒷자리를 **제출 때마다 새로 발급해** 메모에 적는다. 한 번 쓰이면 끝나는 규칙은 그대로다 — 심사용이라고 다시 쓰이는 코드를 만들지 않는다 | 같다 |

- 심사용 계정과 코드가 여는 것은 **합성 학급뿐**이다. 실제 학생의 자료가 없는 자리다 — 「코드로는 내 자리만 열린다」(§1-1)와 같은 선이라, 메모가 새어도 열리는 것이 없다.
- **심사용 직원 계정은 서둘러 만들지 않는다.** 직원 메뉴가 합성 학급에만 닿게 가를 수 있을 때에만 만든다. 그 전에 심사자가 직원 화면을 보자고 하면 심사 메모의 설명과 화면 녹화로 답한다 **[사용자]**. 실제 테스터의 녹음이 심사자에게 보이는 일을 만들지 않는다.
- 심사용 계정의 비밀번호와 코드는 저장소 · 문서 · 로그에 적지 않는다. 스토어의 심사 정보 칸에만 넣고, 넣는 일은 사용자가 한다.
- 같은 앱을 묶음 ID만 바꿔 여럿 내지 않는다(§1-2).

### 8-4. 스토어에 내기 전에 맞출 것 — 앱의 설정과 등록 글

**지금의 실물 [확인]** (talk `app.json` · `eas.json` · `package.json`)과 맞출 것.

| 자리 | 지금 | 맞출 것 |
|---|---|---|
| 아이패드 | `ios.supportsTablet: true` — 아이패드에서도 심사를 받고 아이패드 화면 사진이 필요하다 | 첫 출시는 **아이폰 전용**(`false`). 아이패드 화면을 따로 다듬기 전에는 열지 않는다 |
| 배경 오디오 | `UIBackgroundModes: ["audio"]`와 배경 녹음 허용이 켜져 있다 | 애플은 배경 기능을 **그 쓰임대로만** 쓰게 한다(심사 지침 2.5.4 · 원문 확인 09-19). 화면이 꺼진 채로 소리가 이어지는 기능이 출시판에 실제로 있으면 심사 메모에 적고, 없으면 끈다. 배경 **녹음**은 쓰는 자리가 없으면 끈다 |

**구글의 정식 출시 신청서가 묻는 것(원문 확인 09-19).** 테스터를 모으기가 얼마나 쉬웠나 · 테스터가 앱의 모든 기능을 썼나 · 쓰임이 실제 사용자의 쓰임과 같았나 · **어떤 의견을 받았고 어떻게 모았나** · **비공개 테스트에서 배운 것으로 무엇을 고쳤나** · 출시할 준비가 됐다고 어떻게 판단했나. 그래서 비공개 테스트에는 아래가 함께 선다.

- **의견을 받는 길 하나.** 설정 안의 「의견 보내기」(글 한 칸 — 서버에 남긴다). 받은 의견과 고친 것을 날짜와 함께 적어 둔다 — 신청서의 답이 된다.
- **테스터 안내 한 장**(한국어 · 영어 · 몽골어): 14일 동안 테스트에서 빠지지 않기(12명이 끊기지 않고 14일 참여해야 한다) · 하루 한 번 2분 · 의견 보내는 법 · 지우는 법.
- 테스터는 **실제로 한국어를 배우는 사람**을 수준이 다르게 섞는다. 한국어가 모국어인 테스터는 가장 높은 수준을 고르게 한다. 테스터 계정은 엔진의 배움에 세지 않는다(§4-3).

## 9. 순서

아래 일정은 09-19에 정리한 비공개 시험 계획이다. 09-20에는 온라인 학습자 경험을 우선하고 약 20개국 동시 공개 출시를 목표로 하도록 방향을 갱신했다. 마스코트의 지속 기억·대화, 혼자 가능한 마을 활동, 실제 16인 연결, 지원 언어와 비용 검증의 순서는 [후속 제안](온라인학습자_20개국_확장방향_20260920.md) §7을 함께 본다. 기존 네 항목만으로 확장 제품 전체의 출시 준비가 끝났다고 판단하지 않는다.

| 때 | 하는 일 | 끝났다는 증거 |
|---|---|---|
| **2~3주 뒤 — 비공개 테스트 출시** | 구글의 비공개 테스트와 애플의 TestFlight로, **한국과 몽골에서**(09-19 사용자). 공개 가입(구글·애플)과 가입의 동의 기록 · **연습 수준 고르기(§4-2)** · 열 때 배정(§4-1) · 계정의 종류(§4-3) · 내 자격 · 계정 지우기 · 비용 상한 · 운영 서버 · 약관과 동의(§8-1). 경험은 지금 서 있는 것 그대로이되 **수준을 고른 사람은 자기 수준의 과제를 받는다** — 그러지 않으면 테스터 전원이 매일 같은 도입 문장만 본다(§4-2). 의견을 받는 길과 테스터 안내(§8-4). 테스터 12~30명 · 끊기지 않는 14일 이상 | 테스터가 가입 → 과제 → 지우기를 실제 기기에서 끝까지 한다 · 상한에 닿으면 호출이 멈춘다 · 다른 사람의 자료가 보이지 않는다 · 수준이 다른 테스터 둘이 같은 날 다른 과제를 받는다 · 의견이 들어오고 고친 것이 적힌다 |

- 비공개 테스트가 시작되면 **첫 실제 사용자의 자료가 그날부터 쌓인다.** 소급할 수 없는 것 — 동의의 범위, 가입 때의 문항, 기본 사건 기록 — 은 그 전에 서야 한다. 아틀라스의 기록 부분(시드·확률·정책 버전)이 서기 전의 회차는 맞춤 이력으로 되살릴 수 없다는 것을 알고 간다.
- 공개 사용자는 아틀라스가 스스로 나아지는 데 필요한 **회차 수**를 만든다(구현 명세 §6-4의 단계별 적용 확대). 학원생 스무 명으로는 돌지 않던 자리다.

## 12. 확인하지 못한 것

- **학급·명부가 없는 학습자에게 지금의 배정 통로가 과제를 주는지**(§4-1). 밤 배치의 본문은 주석만 읽었다.
- 학원의 기능(출석·반·선생님 배정·케어)이 지금 어느 저장소의 어떤 화면·표로 구현돼 있는지. 이 문서의 목록은 사용자의 말과 문서에서 본 이름이다.
- **직원 API(검수 · 채점 · 학생 기록 등)가 지금 어느 범위의 학습자를 돌려주는지** — 공개 가입이 열리면 학원 밖 학습자의 제출이 직원의 대기 목록에 섞이는지(§1-1). 화면이 갈리는 자리는 봤다(설정 화면의 메뉴들 · 서버의 403) · 서버 함수의 본문은 읽지 않았다.
- 교정이 학생에게 돌아가는 실제 코드 경로와, 확정 전의 AI 교정이 지금 어디에 남는지.
- 운영용 Supabase 프로젝트는 빌드 설정에 따로 있다(talk `eas.json`의 `production` **[확인]**). 그 프로젝트에 무엇이 적용돼 있는지 · 지역 · 요금제의 한도(저장 한도 — §7-1)는 확인하지 않았다.
- 구글 · 애플 로그인을 Expo 앱에 붙일 때의 빌드 설정. 구글 로그인의 서명 지문과 암호화 신고(§8-4)는 이 세션이 아는 바이며 원문을 확인하지 않았다.
- 직원 계정이 학습자 표에도 행을 갖는지(직원이 말하기 화면을 쓰면 그 사건이 어디에 남는지) · 밤 배치가 시험 계정(`is_test`)에도 배정하는지(§4-3).
- 과제 생성이 본인이 고른 수준을 읽게 하려면 어디를 고쳐야 하는지(§4-2 — `level_snapshot`이 굳는 자리).
- 구글·애플의 정책 문장 가운데 **원문을 확인한 것(2026-09-19)**: 구글의 12명 · 14일(2023-11-13 뒤에 만든 개인 계정 · 끊기지 않는 14일 · 앱마다 · 회사 계정은 해당 없음) · 구글의 앱 액세스 · 애플 심사 지침 2.1(심사용 계정) · 2.3.1(숨은 기능) · 4.3(같은 앱을 여럿 내지 말 것) · 4.8(다른 회사의 로그인을 쓰면 그에 맞먹는 로그인도) · 5.1.1(v)(꼭 필요할 때만 로그인 · 앱 안에서 계정 지우기). 같은 날 더 확인한 것: 애플 5.1.2(i)(제3자 AI와 나눌 때의 고지와 명시적 허락) · 2.5.4(배경 기능은 그 쓰임대로만) · 2.5.2(기능을 바꾸는 코드를 내려받지 않는다) · 5.1.4(b)와 2.3.8(어린이 부문이 아닌 앱의 등록 글) · 애플의 계정 지우기 안내(찾기 쉬운 자리 · 비활성화만으로는 안 됨 · 애플 로그인의 토큰 폐기) · 구글의 정식 출시 신청서가 묻는 것 · Supabase 기본 메일 발송의 제한. 정책은 바뀐다 — 제출할 때 화면에서 다시 본다. **확인하지 않은 것**: 등록비의 값 · 스토어에 보이는 이름과 주소 · 개인 계정에서 회사 계정으로 옮기는 절차 · TestFlight 외부 테스터 심사의 범위.
