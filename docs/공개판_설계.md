# 공개판 — 누구나 쓰는 앱, 코드로 열리는 학원

> 2026-09-19 · 사용자 결정: ① **이 앱은 몽골인 전용이 아니다. 한국어를 배우고 싶은 모든 사람을 위한 앱이다**(첫 오프라인 학원의 출발이 몽골일 뿐이다) ② 학원생이 아니어도 구글·이메일 로그인으로 쓰고, 학원생은 발급받은 코드로 학원 기능(출석·반·선생님 배정과 케어 등)이 더해진다 ③ 순서는 「2~3주 뒤 비공개 테스트 출시 → 조건이 서면 공개 출시」를 따른다 ④ **코드는 로그인 수단이 아니라 연결 열쇠로 하고, API 계약의 두 문장은 고쳐도 된다** ⑤ **아이폰에도 낸다** ⑥ 출시 때의 도움 언어는 **영어와 몽골어**다 ⑦ 약관과 동의는 **꼭 필요한 것만** 둔다 ⑧ 비용 상한의 출발값은 **한 사람에 한 달 1,000원**의 AI 비용이고 **하루 몫으로 나눠 준다**(§7) ⑨ 비공개 테스트는 **한국과 몽골**에서 한다. 구현은 GPT가 맡는다.
> 표시: **[확인]** = 2026-09-19에 코드·문서 원문에서 직접 본 사실 · **[제안]** = 이 설계의 제안 · **[사용자]** = 사용자 확인 없이는 진행하지 않는 자리. 앱 쪽 사실은 talk 원격 master 기준의 작업 사본에서 봤다.

## 1. 한 앱, 권한으로 갈린다

앱은 이미 그렇게 서 있다 — 「한 앱에 역할이 넷 들어간다(학생·강사·검수자·원장). 나뉘는 것은 앱이 아니라 **권한**이다」(talk `docs/P0_제품계약.md` §1 **[확인]**). 공개판은 새 앱도 다섯째 역할도 아니다. **학원에 연결되지 않은 학생**이다. 학원 기능은 같은 앱 안에 들어 있고 자격이 있을 때만 보인다.

| | 공개 사용자 | 학원에 연결된 학생 |
|---|---|---|
| 들어오는 길 | 구글 · 애플 · 이메일(로그인 없이 먼저 해 볼 수도 있다 — §2) | 같은 로그인 + 학원이 준 코드로 **한 번 연결**(§3) |
| 배움 | 한글 단계 · 초급 풀 · 매일 말하기 · 게임 · 아틀라스의 맞춤과 소통 | 같다 |
| 교정 | AI가 본 교정(그렇게 표시한다 — §5) | 사람이 확정한 교정이 더해진다 |
| 학원의 것 | 없음 | 출석 · 반과 조 · 선생님 배정과 케어 · 수업 차시에 맞춘 진도 · 시즌 회고와 나침반 · 부모에게 가는 소식 · 반이 함께하는 장면(다 낸 날) |
| 아틀라스의 기억 | 쌓인다 | **같은 기억이 이어진다** — 연결해도, 학원을 그만둬도 |

학원의 것 목록은 사용자가 든 예(출석·반 설정·선생님 배정과 케어)와 문서에서 본 것을 합친 **[제안]**이며 실물과 대조한다.

## 2. 계정

**지금의 실물 [확인]** (talk `docs/C0_API계약.md` §2·§4-4)

- 아이디는 학생번호(`SYNK-042` — 비밀이 아니다), 비밀번호는 학생이 첫 로그인에서 직접 정한다. 합성 이메일(`synk042@synk.invalid`)로 Supabase Auth의 비밀번호 로그인을 쓴다.
- 계정이 서는 유일한 통로는 `POST /v1/auth/first-login`이다 — 학생번호와 전화 뒷자리를 서버가 명부와 대조하는 **게이트**다. 없는 번호·불일치·잠김의 응답을 가르지 않는다.
- 앱은 `signUp`을 부르지 않는다. 서버는 학생을 **토큰에서** 확정하고, 본문에 `learner_id`·`student_code`를 실으면 400이다.
- `/v1/learners/link`는 재제안 금지다. 근거 — 「결합은 앱이 주장할 일이 아니다. 앱이 『나는 이 learner다』라고 말하는 순간 `service_role`이 RLS를 우회해 남의 계정을 만든다.」

**공개 가입 [제안]**

- Supabase Auth의 구글 로그인 · **애플 로그인** · 이메일 로그인(비밀번호 없는 한 번 쓰는 코드·링크 쪽 — 잊은 비밀번호 지원이 없어진다). 아이폰 앱에 구글 로그인을 두면 애플은 애플 로그인도 함께 두기를 요구한다.
- **로그인 없이 먼저 해 본다 [제안].** 한글 단계의 첫 단원은 로그인 없이 열린다. 기억은 그 기기에만 남는다 — 아틀라스 본체는 계정 없이도 돈다([아틀라스 설계](아틀라스_설계.md) §2). 이어 가려면 로그인하고, 그때 기기의 기억을 계정으로 옮길지 묻는다. 첫 화면이 가입 양식이 아니라 첫 글자가 된다. 애플이 「꼭 필요하지 않으면 로그인을 강제하지 말라」고 보는 자리이기도 하다.
- 로그인 직후 앱이 `POST /v1/auth/register`를 **세션 토큰으로** 부르고, 서버가 그 토큰의 사용자로 학습자 행을 만든다(`origin: public`). 앱은 자기가 누구인지 본문에 적지 않는다 — 기존 원칙 그대로다. 이미 있으면 `already`다.
- 가입 문항은 짧게: 도움 언어(§6) · 배우는 이유 · (선택) 한글을 읽을 수 있는지. 지역(아이막) 같은 학원의 문항은 학원 연결 때 묻는다.
- 「앱은 `signUp`을 부르지 않는다」는 문장은 개정이 필요하다. 지키려던 것 — **학습자 행은 서버만 만든다** — 은 그대로 남는다(09-19 사용자 허가 — 아래의 개정문).

**학원 연결 — 코드는 로그인 수단이 아니라 연결 열쇠다 (2026-09-19 사용자 확정)**

- 사용자의 원안은 「학원생은 코드로 로그인」이었고, 이 설계의 권고 — **로그인은 모두 같게, 코드는 로그인 뒤에 한 번 넣는 연결 열쇠로** — 를 사용자가 받았다(「코드는 연결 열쇠로 가자. 계약 두 문장도 고쳐도 돼」). 이유: 무료로 쓰다가 학원에 등록한 사람이 새 계정으로 처음부터 시작하면 아틀라스가 쌓은 이해가 사라진다. 학원을 그만둔 뒤에도 계정과 기록이 남아야 한다(졸업 뒤 케어). 지킬 로그인 통로가 하나가 된다.
- 연결은 게이트다: `POST /v1/academy/link { code, phone_last4 }`를 세션 토큰으로 부른다. 서버가 코드(한 번만 쓰임 · 유효기간 · 시도 제한)와 뒷자리를 명부와 대조해, **그 토큰의 학습자**를 명부의 그 학생에 묶는다. 실패의 응답은 가르지 않는다(first-login과 같은 규율). 앱은 어느 학생인지 주장하지 않는다.
- 명부의 학생과 학습자는 1:1이다. 이미 다른 계정에 묶인 학생의 코드는 같은 실패 응답이다. 옮겨 묶기는 학원(운영자)의 절차로만 한다.
- 구글·애플·이메일이 없는 학생을 위해 **기존 학생번호 로그인은 그대로 둔다**(이미 서 있다). 두 길 모두 「명부의 학생 ↔ 학습자 1:1」로 모인다.
- **연결 해제.** 학원을 그만두면 묶음이 풀리고 학원의 자리가 사라진다. 학습 기록과 아틀라스의 이해는 본인 계정에 남는다. 학원의 운영 기록(출석 등)은 학원 쪽의 보관 규칙을 따른다.
- 지금은 실제 학원생 계정이 0개다. 구조를 바꾸는 비용이 가장 적은 때다. 코드 기능은 공개 출시의 조건이 아니며 첫 학원생 전에 서면 된다(§9).

**계약의 개정문 [제안] — 문서만 먼저 고치지 않는다.** talk의 시험 넷(`tests/C0계약.test.js`·`tests/계약역방향.test.js`·`tests/사건위조.test.js`·`tests/철회경로.test.js`)이 그 문서를 읽고, `tests/인증API.test.js`가 「앱은 `signUp`을 부르지 않는다」를 지킨다 **[확인]**. 그래서 아래 문장은 구현·시험과 **같은 커밋**에서 고친다(PW1·PW8).

| 자리(talk `docs/C0_API계약.md`) | 지금 | 고친 문장 |
|---|---|---|
| §2의 3번 · §10의 표 | 앱은 `signUp`을 절대 부르지 않는다. 계정 생성은 서버만 한다 | **학습자 행은 서버만 만든다.** 공개 가입(구글·애플·이메일)의 인증 계정은 Supabase Auth가 만들고, 학습자 행은 `POST /v1/auth/register`가 **토큰의 사용자로** 만든다. 앱은 학습자·학생번호를 본문에 싣지 않는다. 학생번호 계정은 지금처럼 first-login만이 만든다 |
| §2의 🚫 문단 | `/v1/learners/link` 재제안 금지 | **결합은 앱이 주장하지 않는다 — 게이트가 확정한다.** 학원 연결은 `POST /v1/academy/link`(코드와 전화 뒷자리 · 한 번만 쓰이는 코드 · 시도 제한 · 실패 응답을 가르지 않음)로만 하며, 서버가 **토큰의 학습자**를 명부의 학생에 묶는다. 본문에 `learner_id`·`student_code`를 실으면 400이다. 게이트 없는 결합 통로는 계속 만들지 않는다 |

## 3. 코드를 넣으면 — 다시 켜지 않는다

1. 「나」 자리의 「학원 코드가 있어요」에 코드와 전화 뒷자리를 넣는다(연결이 필요하다).
2. 서버가 확인해 묶는다.
3. 앱이 **내 자격**을 다시 받는다 — `GET /v1/me`(제안): 역할 · 연결된 학원과 반 · 선생님 · 켜진 기능 묶음.
4. 화면 구성이 **그 자리에서** 바뀐다. 앱을 다시 켜거나 새로 받지 않는다. 학원의 화면은 처음부터 앱 안에 들어 있고 자격으로 가려져 있었을 뿐이다 — 새 코드를 내려받는 것이 아니다.
5. 환영 장면 한 번 — 방에 반의 표식이 걸리고 선생님 소개 카드가 놓인다.

- 앱은 시작할 때마다, 그리고 코드를 넣은 직후에 자격을 받는다. 내비게이션은 그 값 하나로 갈린다. 화면마다 따로 판정하지 않는다(갈라지면 어떤 화면만 보이는 고장이 난다).
- **보이는 것과 되는 것은 따로 지킨다.** 화면을 가리는 것은 편의이고, 막는 것은 서버다(RLS와 함수의 권한 검사). 자격 없는 사람이 학원 기능의 주소를 알아도 서버가 거절한다.
- 권한을 DB의 묶음에서 읽으면 토큰을 바꿀 필요가 없다. 역할을 토큰의 클레임에 싣는 구현이라면 세션을 한 번 새로 받는다 — 어느 쪽이든 다시 켜지 않는다.
- 자격은 기기에 남겨 두어 오프라인에서도 학원의 자리가 보인다. 해제는 다음 동기화 때 반영되고, 그동안의 학원 기능 호출은 서버가 거절한다.
- 실패하면 한 문장만 보인다(「코드를 확인해 주세요」). 시도 제한에 걸려도 같은 문장이다.

## 4. 사람 없이 도는 것이 기본이다

공개 사용자에게는 강사도 검수자도 없다. 아틀라스가 「사람 손 없이 돈다」를 원칙으로 세운 이유와 같은 자리다([아틀라스 설계](아틀라스_설계.md) §3) — 공개판의 평소 상태가 곧 **무인 고리**다. 학원에 연결되면 사람의 입력이 더 강한 근거로 **더해질** 뿐이다.

| 경험 | AI 호출 | 공개 사용자 |
|---|---|---|
| 한글 단계([설계](한글단계_설계.md)) | 0 | 그대로 |
| 초급 풀(구현 명세 §4-15) | 0 | 그대로 |
| 게임 | 0(검수가 확정된 팩) | 자동 채점되는 것만. 사람의 검수가 필요한 게임(G1의 글)은 AI가 본 피드백으로 표시하거나 뒤로 미룬다 **[사용자]** |
| 매일 말하기(Lv3~6)의 과제 생성 | 있음 | 하루 상한 안에서(§7). 넘으면 풀의 과제 |
| 교정 | 있음 | §5 |
| 아틀라스의 본체 | 0(순수 계산) | 그대로 |

**호출이 없는 경험이 공개판의 바탕이다.** 비용이 사람 수에 비례해 늘지 않는 것부터 세운다.

## 5. 사람 없는 교정

**지금 [확인]:** 학생 화면에 돌아오는 교정은 사람이 확정한 것이다(talk P0 §4의 관통 확인 5 · 확정 통로 §7-2). 검수자 한 명의 용량은 가정 위의 어림이다(같은 문서 §2-3).

**공개 사용자 [제안]**

- AI의 교정을 **「AI가 본 것」이라고 표시해** 바로 돌려준다. 사람이 확정한 교정과 같은 모양으로 보이지 않게 한다.
- 확신이 낮은 교정은 보여 주지 않는다. 틀린 교정보다 침묵이 낫다. 어떤 오류 유형을 단정하고 어떤 것을 「이렇게도 말해요」로 낼지는 유형별 실측으로 정한다 **[사용자: 기준]**.
- 아틀라스에서는 **약한 근거**다 — 서로 다른 제출에서 거듭 나와야 이해 줄이 선다(구현 명세 §3-2). 이미 설계된 등급 그대로다.
- 학원에 연결되면 같은 제출에 사람의 확정이 더해질 수 있고, 그 판정이 앞선다.

## 6. 모든 사람을 위한 앱 — 말

- 앱의 말은 한국어다. 읽히게 하는 방법은 다른 나라 말이 아니라 **눈높이**다([아틀라스 설계](아틀라스_설계.md) §8-2).
- **도움 언어**(학습자가 고른 자기 말)는 글자를 처음 배우는 한글 단계에서만 쓴다(09-19 사용자 결정 「몽골어는 한글 단계에서만」의 일반화). 출시 때의 도움 언어는 **영어와 몽골어**다(09-19 사용자). 영어는 어느 나라 사람에게나 열린 기본이고, 몽골어는 첫 학원을 위한 것이다. 그 뒤의 언어는 사용자가 늘린다.
- 도움 언어가 아직 없는 나라의 사람도 시작할 수 있어야 한다. 한글 단계의 안내는 **보여 주는 안내**가 먼저다 — 몽글의 시범과 그림과 소리. 글은 곁들임이다.
- 「두 나라의 달력」은 한국의 날과 **그 학생의 나라의 날**이다. 첫 나라는 몽골이다.
- 여러 학생에게서 배우는 일(Prism)은 모국어별로 가른다 — 헷갈리는 글자의 짝은 모국어마다 다르다.
- 동의·개인정보·계정 지우기처럼 **뜻을 정확히 알아야 권리를 쓸 수 있는 글**은 학습용 글이 아니다. 그 사람이 읽을 수 있는 말로 보여야 한다 — 출시 때는 영어 · 몽골어 · 한국어다.

## 7. 비용과 남용

지금의 시스템은 「명부에 있는 학생만 쓴다」는 전제로 서 있다. 누구나 가입하면 AI 호출의 비용을 남이 늘릴 수 있다.

**출발값 — 한 사람에 한 달 1,000원의 AI 비용(2026-09-19 사용자 제안).** 이 설계는 그 수를 받되 아래처럼 쓴다.

- **한 달 몫을 하루 몫으로 나눠 준다(2026-09-19 사용자 확정).** 한 달 1,000원을 통으로 주면 이틀에 다 쓰고 스무여드레를 비울 수 있다 — 매일 조금씩 하는 배움의 리듬과도, 남용을 막는 데에도 맞지 않는다. 하루 몫은 약 33원이고 안 쓴 몫은 사흘 치(약 100원)까지만 이월한다(설계값).
- **안에서는 원으로 세고, 학생에게는 횟수로 보인다.** 호출마다 실제 단가로 쓴 원을 적는다 — 더 싼 모델로 바꾸면 같은 돈으로 더 많이 할 수 있게 된다. 화면에는 돈이 아니라 「오늘의 AI 교정 n번」처럼 보인다.
- **이 세션의 어림(실측 아님).** 아는 공개 단가로 셈하면 말하기 한 회차(받아쓰기 + AI 교정 + 읽어 주는 소리)는 싼 구성에서 약 15원, 중간 구성에서 약 40원, 비싼 목소리를 쓰면 60~100원이다. 1,000원은 중간 구성으로 **하루 한 번꼴**이다. 비공개 테스트에서 회차당 실제 단가를 재서 이 수를 확정한다. 목소리의 선택([한글 단계 설계](한글단계_설계.md) §10)이 단가를 가장 크게 움직인다.
- **초급은 거의 들지 않는다.** 한글 단계 · 초급 풀 · 자동 채점 게임은 호출이 0이다. 공개 사용자의 다수일 초급에게 1,000원은 남는다.
- **전체의 천장을 따로 둔다.** 한 사람의 상한만으로는 사람 수에 비례해 는다(1,000명이 다 쓰면 한 달 100만 원). 전체의 하루·한 달 천장을 두고, 넘으면 새 호출을 쉬며 풀·한글 단계·게임으로 돈다. 학원에 연결된 학생의 과제 흐름이 먼저 지켜진다. 비공개 테스트 동안의 천장은 **한 달 5만 원**을 출발값으로 둔다(테스터 서른 명 × 1,000원에 여유를 더한 값 — 이 세션의 제안). 공개 출시 때의 천장은 실제 단가를 잰 뒤에 정한다 **[사용자]**.
- 학원에 연결된 학생은 이 상한의 대상이 아니다(수강료 안의 일 — 엔진 v3 D28).
- 상한에 닿으면 호출 없는 경험으로 부드럽게 넘어가고, 탓하지 않는 한 줄로 말한다 — 「오늘의 AI 교정은 다 썼어요. 내일 다시 열려요.」
- 가입과 호출의 속도 제한 · 이메일 확인 · 이상 사용의 자동 보류. 계정을 여럿 만들어 몫을 늘리는 일은 전체의 천장과 가입 속도 제한이 막는다. 아틀라스 지킴이의 비용 한도(구현 명세 §6-3)와 같은 자리에 둔다.
- 새 결제·구독·자동충전으로 상한을 넘기지 않는다([AI 운영 원칙](AI_운영원칙.md)). 상한을 올려 주는 유료 상품은 이 문서 밖의 결정이다 **[사용자]**.

### 8-1. 약관과 동의 — 꼭 필요한 것만 (2026-09-19 사용자 지시)

| 둘 것 | 왜 빠질 수 없나 |
|---|---|
| **개인정보 처리방침** — 공개된 주소 하나 | 두 스토어가 등록 때 요구한다. 무엇을 모으나(계정 · 학습 기록 · 음성) · 왜 · 어디로 가나(AI 처리를 맡기는 곳과 서버의 나라) · 얼마나 두나 · 어떻게 지우나 |
| **이용약관** — 짧게 | 서비스의 범위 · AI가 본 교정은 틀릴 수 있다는 것 · 해서는 안 되는 쓰임 · 그만두기 |
| **가입 화면의 동의 한 번** | 위 둘에 대한 동의. 체크 하나와 버튼 하나(나이 문구는 아래 「가입 나이」) |
| **녹음 앞의 한 줄** | 마이크 권한을 청하기 전에 — 「녹음은 교정을 위해 AI가 처리해요」. 권한 창의 이유 문장과 같은 뜻이어야 한다 |
| (선택 하나) 엔진을 좋게 하는 데 내 기록을 쓰는 동의 | **따로, 꺼 둔 채로 시작한다.** 나중에 소급해 받을 수 없으므로 자리만은 첫날부터 있어야 한다 |

- 그 밖의 것(마케팅 수신 · 맞춤 광고 · 제3자 제공)은 **하지 않으므로 묻지 않는다.** 하지 않는 일을 늘리지 않는 것이 문서를 줄이는 길이다.
- **출시 나라.** 비공개 테스트는 **한국과 몽골**에서 한다(2026-09-19 사용자). 공개 출시의 나라는 그때 정하며, 개인정보 규칙이 무거운 지역은 뒤로 미룰 수 있다.
- **가입 나이.** 사용자는 나이 제한을 두지 않는 쪽이다(09-19 「가입 나이는 없어도 될 것 같고」). **이 세션의 주의:** 한국에서는 만 14세 미만의 개인정보를 모으려면 법정대리인의 동의가 필요하다. 나이를 묻는 화면이나 생년월일 수집 없이 할 수 있는 가장 작은 대응은 둘이다 — 가입 화면의 동의 문장에 「만 14세 이상입니다」를 넣는 것(체크는 그대로 하나), 그리고 약관에 「만 14세 미만은 학원을 통해 보호자 동의를 받고 가입한다」는 한 줄. 문서도 화면도 늘지 않는다 **[사용자 재확인]**.
- 문서의 말은 영어와 한국어, 그리고 첫 학원을 위한 몽골어다. 동의처럼 뜻을 알아야 하는 글은 그 사람이 읽을 수 있는 말로 보인다(§6).
- 이 세션은 법률가가 아니다. 위 목록은 스토어의 요구와 흔한 실무에 따른 최소이며, 공개 출시 전에 한 번 확인받기를 권한다.

### 8-2. 개발자 계정 — 개인인가 회사인가

| | 개인 계정 | 회사(조직) 계정 |
|---|---|---|
| 만드는 데 필요한 것 | 본인 신분 확인 | **등록된 법인** + D-U-N-S 번호(무료 · 받는 데 1~4주) + 회사 웹사이트와 연락처 확인 |
| 값 | 구글 25달러(한 번) · 애플 연 99달러 | 같다 |
| 스토어에 보이는 이름 | **본인의 법적 이름**(구글은 나라도 함께 · 유료 상품이 있으면 주소도) | 회사 이름(구글은 회사 주소와 연락처도 공개) |
| 구글의 정식 출시 조건 | 최근에 만든 개인 계정은 **12명이 14일 동안 비공개 테스트**를 해야 정식 출시를 신청할 수 있다 | 그 조건이 없다 |
| 믿음 · 책임 | 음성을 다루는 앱을 개인 이름으로 낸다 · 책임도 개인 | 회사 이름과 책임 |
| 나중에 바꾸기 | 애플은 개인 → 회사 전환을 받아 준다 · 구글은 새 회사 계정으로 **앱을 옮긴다**(사용자와 평가가 따라온다) | — |

- **권고 — 지금은 개인 계정으로 비공개 테스트를 시작하고, 법인이 서면 회사 계정으로 옮겨 그 이름으로 공개 출시한다.** 이 세션의 기억 기록(09-07)으로는 한국 법인이 아직 없고 9월 말 설립을 보고 있었다 — 회사 계정은 법인 등기 → D-U-N-S → 계정 확인을 거쳐야 해서 2~3주 안에는 열리지 않는다. 개인 계정의 「12명·14일」 조건은 어차피 하려던 비공개 테스트와 겹친다. 공개 출시의 네 조건(§9)이 서는 데 걸리는 동안 회사 계정을 준비할 수 있다.
- 법인이 서는 날 **D-U-N-S부터 신청한다** — 구글과 애플의 회사 계정이 둘 다 이 번호를 요구하고, 가장 오래 걸리는 단계다.
- 계정을 만들고 값을 치르는 일은 사용자가 직접 한다.

## 9. 순서

| 때 | 하는 일 | 끝났다는 증거 |
|---|---|---|
| **2~3주 뒤 — 비공개 테스트 출시** | 구글의 비공개 테스트와 애플의 TestFlight로, **한국과 몽골에서**(09-19 사용자). 공개 가입(구글·애플·이메일) · 내 자격 · 계정 지우기 · 비용 상한 · 운영 서버 · 약관과 동의(§8-1). 경험은 지금 서 있는 것 그대로. 테스터 12~30명 · 14일 이상 | 테스터가 가입 → 과제 → 지우기를 실제 기기에서 끝까지 한다 · 상한에 닿으면 호출이 멈춘다 · 다른 사람의 자료가 보이지 않는다 |
| 그동안 | 한글 단계 첫 판 · 초급 풀 첫 판 · 목소리 확정 · 사람 없는 교정의 표시와 기준 · 아틀라스의 가장 얇은 첫 고리(구현 명세 §9-0) | 각 문서의 인수 기준 |
| **공개 출시** — 아래 넷이 서면 | ① 초급 사용자가 첫날 할 것이 있다 ② 사람 없는 교정의 길이 있다 ③ 비용 상한이 걸려 있다 ④ 약관·동의·지우기가 서 있다 | 네 항목의 증거 + 스토어 요건 |
| 첫 학원생 전 | 학원 연결(§2·§3)과 학원의 자리 | 합성 학생 리허설에서 코드 연결 → 학원의 자리 → 해제까지 |

- 비공개 테스트가 시작되면 **첫 실제 사용자의 자료가 그날부터 쌓인다.** 소급할 수 없는 것 — 동의의 범위, 가입 때의 문항, 기본 사건 기록 — 은 그 전에 서야 한다. 아틀라스의 기록 부분(시드·확률·정책 판)이 서기 전의 회차는 맞춤 이력으로 되살릴 수 없다는 것을 알고 간다.
- 공개 사용자는 아틀라스가 스스로 나아지는 데 필요한 **회차 수**를 만든다(구현 명세 §6-4의 사다리). 학원생 스무 명으로는 돌지 않던 자리다.

## 11. 사용자 확인이 필요한 자리
