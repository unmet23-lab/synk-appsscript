## 원인과 수정

원곡은 61.6초인데 이전 방송 블록은 시작 6초를 순환 접합에 사용하고 끝 6초를 다음 곡과 섞어 단독 구간이 49.6초였다. 다음 곡 역시 앞뒤 크로스페이드가 있었고, 블록의 마지막도 첫 곡과 접합되어 있었다. 다른 블록 사이에 이 순환 블록을 넣으면 첫 곡이 잘린 채 시작하고 블록 끝에서 다시 섞인다. 최근 서비스 로그에 해당 곡 구간의 재시작은 없었다.

보관 WAV 두 곡을 기존 음량과 맞춘 일정 이득으로 온전히 연결했다. 이후 9곡은 기존 FLAC의 205.94425초부터 그대로 사용했다. 기존 블록 안에 이미 제작된 다른 노래의 전환을 새로 편집하지 않았다. 재발을 막기 위해 09-09 제작기에서도 크로스페이드와 순환 앞뒤 절단을 제거했다.

복구 FLAC은 44.1kHz·스테레오·24비트·4608 샘플 블록이다. 첫 제작 때 인코더 기본값이 3747 블록으로 나와 서버 연결 시험이 실패한 것을 공개 시작 전에 발견했으며, 명시적으로 4608로 고친 후 전체 순환을 재검사했다. 단순히 비트 깊이와 채널만 맞추면 충분하지 않다.

현재 순서는 복구 11곡 → 시티팝 3곡 → 새 8곡이며 전체 4201.863356초이다. 기존 22곡의 순환 순서에서 시작점을 복구한 곡으로 옮겼다. 현재곡 시간표와 재생목록의 해시도 함께 갱신했다.

## 검수와 보존

AI 운영 원칙에 따른 Claude 공식 CLI 검수를 시도했으나 사용 한도 429(23시 재설정)로 실행되지 않았다(`claude-review.json`). 사용자가 이번 복구에 한해 GPT 검증으로 즉시 재시작하도록 명시적으로 승인했다.

서버 지면은 저장소와 차이가 있어 전체 업로드를 실행하지 않았다. 현재곡 검사 모듈·라디오 소개·음악 목록/시간표·무대 목록/영상·썸네일만 교체했다. 수정 전 파일은 서버의 `.before-sourcecomplete-20261005` 백업과 `stop.json`, `server-before/`에 보존했다. 기존 오디오와 무대 영상도 유지했다. 스냅샷과 일지에는 방송 열쇠 값을 출력하지 않는다.

`restart.cjs`는 특정 이전 방송을 종료하는 단회 복구 스크립트이며 다시 실행하는 상시 관리 도구가 아니다. `stage.cjs`도 수정 전 해시를 확인하므로 적용 후 무심코 덮어쓰지 않는다. 향후 재제작은 `audio.py --build` → `verify-audio.py` → `prepare.cjs`로 만들되, 현재 서버 파일을 먼저 대조하고 백업해야 한다.
