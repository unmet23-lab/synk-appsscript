## 0. 핵심 판정 (결론 먼저)

1. **새 시트는 2장만 만든다: `mastery_log` + `student_errors`. `lesson_log`는 신설하지 않는다** — 기존 `weekly_topics`(class_name·배운내용·입력자·created_at·배운내용_mn, 스켈레톤 7971)가 이미 "수업 단위 1행 로그"이므로 열 4개를 붙여 **제자리 승격**한다. 중복 입력 0, Glide 추가 update 0 (같은 Add Row 폼에 열만 늘어남 — Add Row는 열 수와 무관하게 1 update).
2. **강사 입력은 "수업 1행 + 예외 학생만 표기" 방식으로 확정, 학생별 체크 방식은 기각.** 학생별 체크는 수업당 update N건(학생 수만큼)·강사 탭 N회 — 유호님 최대 관심사(강사 앱 시간)와 Glide 500 쿼터를 정면으로 위반. 예외 표기 방식은 hw_batch(2947~2999)의 "멀티선택 1탭 → 밤 전개" 검증된 패턴 재사용.
3. **게이트 삽입점은 calcAll의 monsterOf(1103~1116) 단 한 곳.** S/T열이 게이트 반영값이 되어 앱 게이지·checkEvolution·리포트·Notion이 전부 자동 일관(c06 지도 §9의 설계 메모와 동일 결론). checkEvolution에는 게이트 로직을 넣지 않고 "게이트 대기 알림"만 추가.
4. **신규생 보호 + 강등 금지 + 신선도 가드 3중 안전장치**: mastery 데이터가 없는 학생 = 기존 포인트 진화 그대로 / 이미 도달한 단계 아래로는 절대 안 내려감 / 반의 태그 입력이 60일+ 끊기면 게이트 자동 해제(강사가 태깅을 관두면 시스템이 조용히 포인트 방식으로 퇴행 — 학생 인질 방지).
5. **STORY_GRAMMAR(4896~4921) 재활용은 부적합 판정** — TOPIK 3~4급 문형 96개(24슬롯×4)로 월간 소설 서사용이며, 게이트가 요구하는 TOPIK 1~2급 기초 커리큘럼과 급수·용도·구조(월 로테이션 vs 단계 누적)가 전부 다르다. GRAMMAR_BANK는 별도 상수로 신설한다. 단 최상위 게이트(플로우→싱크마스터)의 일부 항목이 STORY_GRAMMAR와 자연히 겹치는 건 무방(용도가 다른 두 정본).
6. **mastery_log는 Glide에 바인딩하지 않는다** — 노출은 profiles 요약 열(CC·CD)과 기존 HTML 카드(나의여정 BY·몬스터한마디 BF·축하배너 BN)에 굽는다. Glide 테이블 미등록 시트는 sync를 소비하지 않으므로 쿼터 비용 0.

## ① GRAMMAR_BANK — 문법 커리큘럼 정본 (코드 내장)

### 저장 구조
- **콘텐츠 정본 = 코드 상수 `GRAMMAR_BANK` → `setupGrammarBank()`가 contents 시트 type='grammar'로 재건** (replaceContentType 5431 재사용, 단일 파일 복구 철학 준수).
- contents 8열 매핑: A=ID(G201~G712), B='grammar', C=문형(표시명), D=짧은 설명, E=(미사용), **F=게이트단계×100+순번**(setupHomework의 요일코드×100+순번 패턴 재사용), G=몽골어(translateContents 대상), H=영어.
- **게이트단계 = 도착 단계 번호(2~7)**. 예: "스파키(2)→링커(3)" 게이트의 문법은 F=3xx. 즉 "링커가 되려면 3xx 문법 12개 중 9개".
- lesson_log(승격된 weekly_topics)의 문법태그는 **문형 문자열이 아니라 ID(G3xx)로 저장** — fuel·lore에서 확인된 "문자열 정확일치 연성 결합" 냄새(c12 지도)를 원천 회피. Glide Choice는 display=C열, value=A열로 분리 바인딩.

### STORY_GRAMMAR 재활용 판정 근거
STORY_GRAMMAR(4896)는 [문형, 뉘앙스] 96쌍의 **월 슬롯 로테이션**(스토리북 챕터 골격). 게이트는 **단계 누적 집합**. 구조·급수(3~4급 vs 1~2급)·소비자(소설 생성기 vs 진화 판정기)가 전부 다르다. 억지로 합치면 스토리북 로테이션을 깨거나 게이트에 3~4급이 섞인다. **각자 정본 유지가 옳다.** synk_stories의 "문법포인트" 열은 현행 유지.

## ② 강사 입력 플로우 — weekly_topics 승격 (판정 상세)

### 현행 확인
weekly_topics는 강사가 Glide Add Row로 수업마다 기록(반·배운내용·입력자·날짜) — class_stats '오늘체크'의 "배운내용입력✅" 항목(c03 §10)이 이미 수업일 단위 입력을 전제한다. 즉 **"주간"이라는 이름과 달리 실질은 수업 로그**다. 여기에 lesson_log를 따로 만들면 강사가 같은 내용을 두 번 쓰게 된다 — 브리프의 "중복 입력 금지"에 정면 위배. → **승격 확정**.

### 열 확장 (시트명은 유지 — Glide 재바인딩·코드 5곳 수정 회피. 새 Glide 앱 조립 때 개명 여부만 선택지로)
| 열 | 이름 | 입력 주체 | Glide 컴포넌트 |
|---|---|---|---|
| A~E | (기존 5열) | 기존 그대로 | 기존 폼 |
| F | 문법태그 | 강사 (Choice 멀티, display=문형/value=ID, 쉼표 join) | Choice(multi) — contents grammar 행 소스 |
| G | 전체도달도 | 강사 ('도달함' / '더 연습' 2택) | Choice(single) |
| H | 예외학생 | 강사 (선택 — "이 학생들은 아직" 멀티선택) | Choice(multi, profiles 반 필터) |
| I | 처리상태 | 스크립트 ('전개완료') | 미노출 |

- **구현 필수 주의**: ensureSheet(628)는 기존 시트 헤더를 보정하지 않으므로(c02 지도), 승격 시 `ensureLessonCols_()`로 F1~I1 헤더를 setValue로 직접 보정. translateTopics_(6148~6160)와 calcAll(1270~1281)은 5열까지만 읽어 **무수정 호환**(직접 Read로 확인).
- **쿼터 계산**: 기존 폼에 열 3개 추가 = Add Row 여전히 1 update/수업 → **추가 비용 0**. 학생별 체크 방식은 반 8명 기준 수업당 +8 update, 월 ~180수업이면 ~1,440 update로 쿼터 약 3배 초과 — 기각 근거 수치.
- **강사 시간**: 태그 2~3개 + 도달도 1탭 + (가끔) 예외 선택 = +5~10초/수업. 자유 서술 의존을 줄여 배운내용 데이터 품질이 오히려 상승.
- 태그를 안 채운 행은 기존과 100% 동일 동작(전개 스킵) — **하위호환**. 도입 초기 강사 적응 실패가 시스템을 깨지 않는다.

## ⑤ 진화 게이트 — monsterOf 삽입 + checkEvolution 수정안

### calcAll 쪽 (단일 삽입점)
```js
// 사전 1패스(초기화 블록에 mastery_log 읽기 추가):
//   masteryCnt[sid][gate] = '도달' 수
//   hasMastery[sid] = 행 1개라도 있으면 true          ← 신규생 보호
//   classTagFresh[cls] = weekly_topics에 문법태그 행이 최근 60일 내 존재  ← 신선도 가드

function gatedIdx(sid, pointIdx, prevIdx, cls) {
  if (!hasMastery[sid] || !classTagFresh[cls]) return pointIdx;   // 데이터 없으면 기존 포인트 진화 유지
  let idx = pointIdx;
  while (idx > 1 && idx > prevIdx) {                              // prevIdx(AP열) 아래로는 절대 안 내려감 — 강등·소급 박탈 금지
    const need = Math.min(GRAMMAR_GATE_NEED[idx] || 0, bankCount[idx] || 0);
    if (!need || ((masteryCnt[sid]||{})[idx] || 0) >= need) break;
    idx--;
  }
  return idx;
}
// 학생 루프(1422~): const m = monsterOf(total[id]); const gIdx = gatedIdx(id, m.idx, prevAP, cls);
// gIdx < m.idx (게이트 대기): S열 = stages[gIdx-1].name, T열 = 100(포인트 게이지 가득),
//   AG(다음진화까지) = 0, CC(81) = need - got (남은 문법 수),
//   CD(82) = '⚡ 진화 에너지 충전 완료! ' + 남은문형 + ' — ' + n + '개만 익히면 ' + 다음단계 + '!'
// gIdx === m.idx: 기존 그대로 + CC/CD = 다음 게이트 진행 수치('다음 진화 문법 x/12')
```
- **T열 의미 유지**(포인트 게이지 그대로 — Glide Progress 재바인딩 불필요). 게이트 대기는 T=100 + CD 문구로 표현: "게이지 가득 + 문법 몇 개만" = 임박감을 주는 긍정 프레임.
