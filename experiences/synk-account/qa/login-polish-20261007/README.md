# SYNK ID 로그인 흐름과 화면 마감

2026-10-07 KST. 사용자가 로그인 적용이 이상하고 가입 결과 문구가 작다고 보고한 뒤 점검했다.

## 수정

- SDK 초기화의 확인 링크 오류와 처리되지 않은 인증 코드를 검사한다. 기존의 유효한 계정은 보존하고 잘못된 링크에서 자동으로 앱 연결을 진행하지 않는다.
- 초기화가 12초를 넘겨도 콜백의 최종 결과를 계속 기다린다. 늦게 복원된 기존 계정만으로 앱 연결을 진행하지 않으며, SDK 초기화가 성공한 뒤에만 연결 화면을 연다. 최종 실패에는 링크를 정리하고 전용 안내를 표시한다.
- 같은 계정의 SIGNED_IN/TOKEN_REFRESHED 이벤트가 계정 화면·진행 중 안내를 다시 만들지 않게 한다. 세션 복원 중 새 로그인/로그아웃 이벤트가 더 오래된 조회보다 우선한다.
- 오류·대기·성공을 한국어로 주알림과 요청 버튼 옆에 표시한다. 알림 영역은 하나이며 대기 중 중복 요청을 차단한다.
- 주알림 17~18px, 버튼 옆 안내와 본문 16px, 입력 18px, 연결 버튼 높이 60px. 소개와 여백을 줄이고 필수·선택 가입 안내를 보존한다.
- 직접 계정 화면에 들어온 검증된 로그인에는 플레저 수첩/홈 링크를 보여 준다. 운영에서 platform으로 등록된 Care의 검증된 공개 도착 주소에는 SYNK 플레저라는 이름을 표시한다.
- 재설정 세션이 없는 오래된 주소는 새 메일 요청으로 안내한다. 비밀번호 저장 후 재설정 화면이 다시 뜨지 않도록 view만 제거하고 원래 OAuth 연결 맥락은 보존한다.
- CSS와 JS의 버전 주소를 갱신해 이전 화면 캐시를 구분한다.

## 검증

root 관련 시험 85/85, 공개 원본 6개와 수정 portal로 만든 격리 시험 70/70. 두 결과의 원문은 tests-root.txt와 tests-public.txt에 보관한다. 격리 전체 시험의 초기 시도는 esbuild 모듈 위치 때문에 실행되지 않아, logout 시험은 root에서 실행하고 portal/core는 실제 공개 원본에서 별도로 실행했다.

마지막으로 추가한 늦은 콜백 회귀 7개는 합성 SDK와 가짜 시계로 검증했다.

- 초기화 시간초과 뒤 코드 교환 실패 또는 미소비 코드가 확정되면, INITIAL_SESSION으로 복원된 다른 기존 계정의 자동 연결·기존 승인 도착 주소 이동을 막는다(2개).
- 시간초과 전에 기존 계정 이벤트가 먼저 도착해도, 초기 화면 표시가 미확정 콜백을 우회하지 않는다(1개).
- 실패 뒤 기존 계정 화면을 불러오는 도중 같은 사용자 TOKEN_REFRESHED가 와도 오류 안내를 지우지 않는다(1개).
- URL 정리 전의 이른 SIGNED_IN과 중복 이벤트는 최종 SDK 성공을 기다리고, 가장 최근 계정으로 연결 화면을 한 번만 연다(1개).
- 기다리는 동안 로그아웃하거나 페이지를 이탈하면 이전 계정의 화면·자동 이동·늦은 URL 정리를 적용하지 않는다(2개).

추가 3개 회귀는 미확정 콜백의 제출 잠금과 직접 호출 방어, 초기화 성공·실패 뒤 해제와 수동 요청 재개, 다른 탭의 계정 변경 뒤 중립적인 안내를 검증한다. 로그인·가입·복구 모드를 전환해도 잠금을 우회하지 않는다.

추가 실제 순서 회귀 2개는 초기화가 끝난 뒤 INITIAL_SESSION(null)이 오는 일반·재설정 경로다. 수정 전 실패를 확인한 뒤, 미확정 콜백 때문에 미뤘던 화면 진입을 한 번 마치는 상태로 보완했다. 실패 안내·recover 전환·중복 null 이벤트 무시·후속 수동 요청을 확인한다.

candidate-proof.json에는 공개 원본과 동일한 6개 모듈 및 최종 후보 해시를 기록한다. portal SHA256은 `e97ef3515905deaa8c5294e830fe82b517b3e0e9586c1e7ff0ddadb2289b3b4e`, 공개 후보 bundle은 `94b68b085193ab2d2282b388d7ac3ae17d0719e68dfadfc16ea3f6ca035b85c7`다. release-newlines.json은 공개 후보 HTML/CSS의 CRLF→LF 변경만 있었음을 구분한다.

실제 IAB 브라우저의 합성 SDK로 375×812·1280×900을 확인했다. 로그인 오류, 가입 성공/대기, 선택 보존, 기존 계정을 유지하는 링크 오류, 계정 CTA, 같은 사용자 이벤트에서 조회 한 번 유지, 정확한 플레저 동의 이름과 재설정 안내를 확인했다. 가로 넘침과 콘솔 오류는 없었다. 실제 자격증명 입력이나 새 계정 생성·메일 발송은 하지 않았다. browser-result.json과 화면 PNG에 범위를 기록한다.

최종 제출 잠금도 375×812 브라우저에서 12초가 지난 뒤 확인했다. 처리 중 안내 17px, 제출 비활성, 가입 화면 전환 뒤에도 요청 0회, SDK 최종 실패 뒤 코드 제거·로그인 버튼 활성 복귀를 확인했다. 가로 넘침·콘솔 오류 0건이며 callback-submit-guard-browser.json과 callback-pending-mobile.png / callback-completed-mobile.png에 기록했다.

물리 휴대폰 왕복은 사용자의 요청으로 후속 보류 상태다. 기존 ‘동기화 확인용’ 계정 기록은 유지한다.

## 검수와 운영

늦은 콜백 수정과 제출 잠금·중립 문구는 공식 Claude Code Opus 5.5 / max에서 P0~P2 없음과 해당 P3 해소 판정을 받았다(claude-late-callback-resolved.json, claude-submit-guard-resolved.json). 마지막 실제 null 이벤트 순서 보완도 최종 통과했다(claude-final.json, claude-model-proof.json). 모든 검수는 공식 Claude Code에서 실제 claude-opus-5-5, --effort max, exit 0 / success / is_error false를 확인했다.

운영 커밋 `8239752c7626012502b0e287e1c96b312af5d712`를 main에 게시했다. 공개 정규 URL의 HTML·CSS·JS 3개 모두 HTTP 200, MIME·SHA256이 검수 후보와 정확히 일치했다(publication-fetch.json). Pages 배포 37554431041과 같은 커밋의 전체 사이트 자동 점검 37554431147 모두 성공했다(publication-actions.json).

실제 로그인된 IAB에서 공개 SYNK ID를 새로고침해 계정 복원·로그인 칸 숨김·새 성공 안내·플레저/홈 이동 버튼을 확인했다(public-browser.json). 375px에서 안내 17px·버튼 18px/60px, 가로 넘침·콘솔 오류 0건이다. public-account-mobile.png는 계정 식별정보 앞까지 캡처했다.

플레저 버튼으로 이동한 뒤 기존 승인 범위의 ‘SYNK 계정 연결’을 눌러 실제 SSO 복귀도 확인했다. 새 자격증명 입력이나 새 권한 부여 없이 계정 수첩의 ‘동기화 확인용’ 기록과 계정 저장 상태가 복원됐다(public-care-return.json, public-care-mobile.png). 기록을 수정하거나 추가로 저장하지 않았다.

이전에 남긴 늦은 이벤트 순서의 SDK 업데이트 위험도 마지막 미완료 진입 상태 보존으로 해소됐다는 판정을 받았다. 운영 서버의 실제 만료 OAuth 응답과 물리 휴대폰 왕복은 이번 검증에 포함하지 않았다.
