## 공개 및 설치 결과

플랫폼은 공개 커밋 `84daceb0ca63ce5bc08890086d7cf724df75f567`에 반영했다. 실제 웹의 파일 4개가 후보와 일치했다.

한영 SHIFT는 공개 커밋 `775dbbad861701c7ad27f680776e5dcb08e4b16b`에 반영했다. 실제 웹의 파일 18개가 후보와 일치했다. 배포 점검 `43502959726`은 성공했으며 새 axe 위반은 없었다.

PC 0.4.90의 빌드는 `20261114.2`다. 동결 원천은 211개 파일이며 SHA는 `d034fde7f6febd82772ee77e429dfdb09512daf8230f6e9161bcad9fa3fcb5a2`다. 공개된 0.4.89 원천과 달라진 파일은 런처와 `member-home.mjs`다. 회원 홈에는 설정이 없는 경우를 처리하는 기존 수정도 포함돼 있다. 인증과 구독 계정판의 저장 코드는 바뀌지 않았다.

Windows와 두 Mac 설치판의 CI `43499745051`은 모두 성공했다. 세 설치 파일은 GitHub prerelease로 공개했다. 익명 공개 주소에서 전체 파일의 크기와 SHA가 일치함을 다시 확인했다. 홈페이지 원천과 서명 피드는 `a88ba344f6a07f9286249a7d874d495fd0359dfc`에 올렸다.

피드 공개 커밋은 `c0582ccefacc6ba3391640655404c2742b096a40`이다. 실제 웹의 파일 20개가 일치했다. 첫 배포 점검 `43518605900`은 다음 공개로 취소됐다. 이를 통과로 세지 않았다. 이 커밋을 포함한 다음 점검 `43520104342`는 성공했다. 새 axe 위반은 모든 등급에서 0건이었다. 사이트 전체 기준 이미지 102장 중 19장은 달랐고 26장은 기준이 없었다. 이 차이를 이번 변경만의 결과로 해석하지 않는다. 공개 뒤 영상 캐시 14개도 HTTP 200과 HIT를 확인했다.

현재 PC의 실행 파일과 실제 HKCU 등록은 모두 0.4.90이다. 설치기의 기록은 11월 14일 07시 26분에 0.4.89에서 정상 업데이트가 끝났음을 보여 준다. 미완료 설치나 복구 대기 항목은 없다. 원천을 올린 뒤 실행 파일 75개와 원천 파일 211개가 동결 배포판과 일치함을 확인했다. 설치된 업데이트 모듈도 공개 피드의 서명을 검증했다. 인증 설정 지문은 이전 판과 같다. 앱을 종료하거나 다시 설치하지 않았다.

이전 설치 때 남긴 보관 자료 네 파일은 모두 현재 존재한다. 기본 설정 파일은 이전 SHA와 같지만 구독 계정판, 암호화된 인증 세션, 창 위치 파일은 다르다. 세 파일의 마지막 저장 시각은 모두 자동 업데이트 이후다. 이전 스냅샷이 업데이트 직전 자료가 아니므로 이 차이를 설치 중 손실이나 완전한 보존의 증거로 해석하지 않는다. 실제 내용을 출력하거나 현재 자료를 덮지 않았다. 대조 원문은 `pc-release/native-update/installed-auto-update-verification.json`과 `preservation-follow-up.json`에 있다.

## 검증과 독립 검수

계정과 게시 관련 시험은 121개를 통과했다. SHIFT 검색 관련 시험은 209개를 통과했다. 홈페이지 전체 검사는 각각 384개와 152개를 통과했다. PC 릴리스 관련 시험은 98개를 통과했다. 실제 Electron 검사는 개발 원천과 공개 동결 원천에서 각각 141개를 통과했다. 이 검사에서 콘솔 오류와 외부 요청은 없었다.

검수 도구는 앞 전체 판에서 79개 시험을 통과했다. 이후 지적을 고친 집중 시험 `backend-committed-v1.tap`은 실제 Chrome에서 2개를 통과했다. 다른 담당의 변경을 합친 뒤에는 `tests/검수묶음.test.js` 전체 52개를 다시 통과했다. 실패와 건너뛴 시험은 없다. 이 실행은 1,722초가 걸렸으며 원본은 `backend-after-merge-full.tap`에 보존했다. 각 시험은 여러 성공 경로와 거절 경로를 포함한다. 서로 다른 판의 시험 수를 하나로 합산하지 않는다.

플랫폼의 카본 검수는 0건이었다. 최종 Opus는 10월 18일 소식에 대한 P3를 제시했다. 해당 소식은 당시 발표 기록이므로 본문을 보존했고, 현재 위치는 최근 소식에서 안내했다. SHIFT의 카본과 Opus가 지적한 갱신일은 수정했다. 변경분을 다시 본 Opus는 0건이었다. PC 피드의 마지막 후보는 카본 0건과 Opus 5.5 0건으로 공식 확인을 통과했다. Fable 주간 사용량이 100%였으므로 승인된 Opus 5.5 대체를 사용했다.

검수 도구의 GPT가 두 회차 연속 중대 문제를 발견해 독립 설계 검토를 먼저 받았다. 확정된 문서의 loaderId와 실제 응답 해시를 묶는 설계를 구현했다. 다운로드 요청을 정상 문서로 오인하는 문제를 고쳤다. 인증 쿼리를 검수 기록에 남기는 문제도 고쳤다. Claude의 끝 판은 앞 중대 지적 3건과 자기 앞 지적이 해결됐음을 확인했다.

마지막 GPT 검수는 Sol Max에서 두 차례 45분 제한으로 끝났다. 응답 전에 종료된 실행 두 번도 보존했으며 통과로 세지 않았다. 내부 파일 읽기 도구의 registered Core launch 오류는 관찰했지만 시간 초과 전체의 원인으로 확정하지 않았다. 사용자가 이번 검수에 한해 Astra Max를 승인했다. 같은 공식 자료를 읽은 Astra는 P1 1건과 P2 2건을 냈다. 새 결제나 추가 크레딧은 사용하지 않았다. 잔여 구독 예외를 사용한 마지막 시험 교정 회차는 아래에 따로 기록한다.

P1은 리다이렉트 뒤 HTML 소스를 글자로 보여 주는 응답도 후보로 인정하는 문제였다. 실제 Chrome에서 재현했고 응답 MIME과 문자셋을 후보의 형식에 대조하도록 고쳤다. 독립 Opus 설계 검토를 받았으며 이후 Astra는 앞 P1 해결과 새 지적 0건을 확인했다. 실제 HTML 및 CSS 회귀 시험은 7/7 통과했다. 전체 공개 자산 위에서 실제 솔리오 후보를 다시 찍은 결과, 1440px와 390px 모두 후보 네 파일이 증명됐다. 두 화면의 콘솔 오류와 실패 요청은 없었다.

캡처 시험을 나눈 첫 판은 16건이 통과했고 준비 자료 충돌 1건과 120초 초과 1건이 남았다. 이를 통과로 세지 않았다. Claude도 같은 준비 자료 문제를 P2로 확인했다. 후보가 없는 시험의 준비 순서를 바로잡고 최종 재캡처를 주소별로 나눴다. 교정한 네 시험은 기존 120초 제한에서 모두 통과했다. 시험 교정과 원격 합침을 포함한 마지막 delta인 solio-quality-backend-tests-20261114는 Astra 0건과 Claude 0건으로 끝났다. Claude는 자기 앞 P2도 해결됐다고 확인했다. 공식 확인의 통과 값은 true이고 배포 조건을 충족했다. 이후 남의 커밋만 들어온 변경은 같은 사슬의 합침 대조로 잇는다.

새 P2 두 건은 스크롤 중 생기는 iframe과 UTF-8 BOM이 있는 후보를 잘못 거절하는 제한이다. 이번 후보에는 해당하지 않으며 잘못된 화면을 통과시키지는 않는다. 기존 문서 안정성과 본문 해시 조건을 완화하지 않고 후속으로 기록했다.

Claude 끝 판의 새 P3는 UTF-8 BOM이 있는 후보를 과도하게 거절하는 제한이다. 실제 Chrome 157에서 HTML과 CSS의 BOM 3바이트가 응답 본문에서 제거됨을 확인했다. 이번 피드 후보의 글 파일 21개에는 BOM이 없다. 잘못된 후보를 통과시키는 문제가 아니므로 운영 원칙에 따라 다음 도구 판의 후속으로 남겼다.

검증 원본은 이 작업본의 `.tmp/solio-quality-20261114/`에 보존한다. Ego의 좁은 창 시도는 실제 폭이 1036px였으므로 390px 증거로 세지 않았다. 1440px와 390px 확인에는 공식 검수 캡처와 실제 Electron 결과를 사용했다. 홈페이지 전체 빌드는 경량 작업본에서 무관한 라디오 원본이 없어 완료하지 못했다. 이번 변경에 필요한 자료 생성과 관련 시험은 완료했다.

## 이어지는 공통 진입 화면

사용자는 별도 디자인 채팅에서 승인한 공통 진입 시안도 실제 플랫폼에 적용해 달라고 요청했다. 첫 장면은 검정 배경과 구 하나로 구성한다. 저장된 로그인은 서버 확인을 거쳐 자동으로 이어진다. 비로그인 사용자는 기존 인증 경로로 들어간다. 기존 계정과 초대 사용자는 목적을 다시 선택하지 않는다.

이 작업은 기존 계정 화면과 PC 런처의 진입을 담당한다. Workspace와 PULSE 본문은 기존 담당이 구현한다. 회사 API의 카탈로그를 실제 프로젝트 배정으로 표시하지 않는다. 직원 초대와 외부 고객 초대도 서로 구분한다. 중앙 로그인 주소 `/id/`와 등록된 플랫폼 콜백은 유지한다. 짧은 `/account/` 주소는 별도 진입으로 연결한다.

카본의 연결 설계는 독립 Opus 검토를 받았다. 저장된 계정의 자동 진입과 기존 계정에 목적을 다시 묻지 않는 조건을 보완했다. 명시적 로그인 선택은 기존 OAuth 요청에 묶이며, 이미 승인된 계정의 자동 이동도 확인 단계를 거쳐야 한다. 초대코드만 넣어도 목적지가 정해지는 서버 계약과 기존 메뉴 홈을 대신할 배정 작업 연결은 기존 담당에게 요청했다. 카본은 기존 대화에서 공통 구 화면 모듈부터 구현한다. 이 작업은 0.4.90 품질 후보와 분리된 다음 후보다. 실제 구현과 필수 검수를 마친 뒤 웹 공개와 새 PC 릴리스 및 설치 확인까지 진행한다. 시안 인계나 설계 완료를 운영 적용 완료로 세지 않는다.

공통 진입 모듈 네 파일을 작성했다. 구문 검사와 상태 및 초대 형식 시험 8개를 통과했다. 실제 Chrome의 모듈 검사 11개도 통과했다. 1440×900, 390×844, 1024×560, 568×320에서 입력과 버튼을 확인했다. 저장 세션의 자동 진입, 숨겨진 창, WebGL 미지원, 계정 변경 뒤 늦은 응답, 진입 실패 후 재시도, 초대 입력값 제거와 기존 초안 보존을 확인했다. 이 검사는 합성 상태를 사용하는 모듈 검사이며 실제 OAuth나 회사의 배정 작업 연결을 검증한 것은 아니다. 무인 카본 CLI에서 검사 권한이 자동 거절된 기록은 보존했다. 사용자가 해당 구문 검사 실행을 승인한 뒤 진행 세션에서 실제 검사를 마쳤다.

공통 도구는 다른 담당이 올린 변경을 공식 따라가기로 보존했다. 겹침 없는 합침은 공식 합침 검증으로 사슬을 잇는다. 손으로 코드 충돌을 해결했다면 변경분을 다시 검수한다.

소스 올리기의 관련 시험 148개는 15분 제한과 실패 2개로 중단됐다. 인증 시험은 옆 저장소의 자격증명 검사 원천을 찾지 못했다. 실제 SYNK-talk 경로를 지정한 재실행은 9개가 모두 통과했다. 캡처 시험은 단독 재실행에서 84.7초에 통과했다. 처음 실패의 상세 TAP은 기존 도구가 삭제했으므로 실패 유형은 확정하지 않는다. 한 시험에 모인 일반 캡처와 Fable 재촬영 및 장면 검사를 네 시험으로 나눈 뒤 같은 120초 제한에서 4개가 모두 통과했다. 원래 실패 출력과 재실행 TAP은 작업 증거 폴더에 보존했다.

시험 분리의 마지막 검수는 `solio-quality-backend-push-tests-20261114`다. Astra Max는 91초에 지적 0건으로 끝났다. 자동 계정 선택은 90% 제한으로 막혔으나, 사용자가 승인한 이번 사슬의 잔여 구독 사용 범위에서 실제 잔액 0을 확인하고 공식 실행 함수를 사용했다. 전역 정책은 바꾸지 않았다. Claude Opus 5.5는 437초에 P2 1건과 P3 1건을 남겼으며 P0·P1은 없다. P2는 서로 다른 주소를 같은 장면에서 연속 촬영하는 회귀를 분리 과정에서 놓친 점이다. 검수한 판을 먼저 반영한 뒤 해당 회귀를 보완한다. P3는 바쁜 PC에서 첫 시험의 120초 제한까지 여유가 적다는 확인 사항이다. 실제 올리기 결과로 확인한다.

공통 진입 모듈의 실제 목적 선택 콜백과 실패 뒤 취소를 추가로 확인했다. 합성 상태를 사용하는 Chrome 모듈 검사는 13개가 모두 통과했다. OAuth 복귀 보조 모듈은 이전 요청의 늦은 응답이 새 로그인 의도를 지우지 않도록 보완했고 관련 시험 7개를 통과했다. 호스트 연결은 아직 남아 있다.

품질 후속 원천은 `8efa2ac9a58ecb3ac1989b1b45052788e1f93943`으로 올렸다. 공개 검사와 계정 묶음 검사를 통과했다. 관련 시험 148개 파일은 15분 안에 끝나지 않았지만 종료 시점까지 실패가 없어서 공식 올리기 도구가 시간 초과 안내와 함께 반영했다. 전체 통과로 보고하지 않는다. 이 실행의 삭제 전 TAP을 보존했으며 검수 도구 시험 43개는 통과했다. 남은 38개를 별도로 실행한 결과 37개가 통과했고 가져온 캡처 시험 하나가 시간 초과로 취소됐다. 같은 시험의 단독 재실행은 2.8초에 통과했다. 원래 취소 기록은 보존했고 원인은 확정하지 않는다. 원격 구문 검사와 기록 검사는 성공했지만 해당 커밋의 넓은 시험과 조건부 QA는 다음 커밋으로 취소됐다.

Opus의 P2였던 서로 다른 주소를 연속 촬영하는 회귀도 복원했다. 한 장면에서 404 문서를 찍은 뒤 정상 문서를 찍고 두 번째 주소가 정상 문서인지 검사한다. 기존 120초 제한에서 22.1초에 통과했다. 이 보완은 검수한 제품 원천을 먼저 올린 뒤 시험만 고친 변경이다.
