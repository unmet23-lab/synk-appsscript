# 웹 플랫폼 내 홈 · 2026-10-08

## 반영

- `platform.html#home`을 실제 내 홈 도착점과 기본 화면으로 연결했다. 내 홈 메뉴·로고·계정 화면의 복귀 링크가 같은 곳을 가리킨다.
- 기존 계정 확인 모듈이 서버에서 확인한 이름과 연결 상태를 보여 준다. 확인 중·로그아웃·설정 미완료·오류 상태에서도 앱 바로가기를 사용할 수 있고, 계정 오류는 같은 자리에서 재시도한다.
- 기기 즐겨찾기와 최근 선택에서 현재 카탈로그의 앱/웹 입구를 바로 연다. 저장된 URL은 사용하지 않으며, 설치가 없어졌거나 공개 입구가 없으면 웹 체험 또는 이용 방법으로 안내한다.
- 클라이언트 열기 중에는 중복 요청을 막고, 실패한 바로가기에서 다시 연다. 실행 응답이 `ok:true`일 때만 최근 기록에 넣는다. 웹은 링크 선택까지만 알 수 있으므로 완료·성과·진행 복원으로 표시하지 않는다.
- 검색어는 `#discover?q=…` 또는 `#library?q=…`에 보관해 상세 진입 후 브라우저 뒤로가기·새로고침에서 복구한다. 모바일 검색을 유지하며 라이브러리의 검색 지우기는 라이브러리에 머문다.
- 기존 싱ㅋ 시그널 디자인·승인 그림·기기 보관 설정을 유지했다. 새로운 개인 기록 수집·계정 동기화·자동 진행 위치 복원은 없다.

## 검증

- 관련 단위/회귀 46개 통과: `platform-home`, `platform`, `platform-account`, `platform-lifecycle`, `member-benefits`.
- `node tools/build-synk-account.js` 및 `--check`: 6번들·자산·생성물 일치.
- `node experiences/synk-account/qa/platform-home-smoke.cjs`: 격리된 Chrome에서 37개 확인. 상세 결과는 [result.json](result.json).
- 320/390/1440px 첫 방문, 즐겨찾기 직접 새 탭 열기, 검색→상세→뒤로가기, 실패 후 계정 재확인, 클라이언트 열기 대기/실패/재시도와 실패시 최근 미기록을 확인했다.
- 캡처에서 모바일·데스크톱 글자/단추/간격과 가로 넘침·이미지 로드를 확인했다. 외부 요청과 런타임 오류 0개. 테스트는 합성 HTTP와 합성 native bridge만 사용했다.

## 범위

로컬 구현·합성 브라우저 검증이다. 실제 회원 로그인·실물 기기·설치 파일 갱신·공개 배포는 이번 결과가 아니다. 홈페이지 담당이 `https://synk.im/account/platform.html`의 HTTP 404 및 빌드의 account 복사 부재를 확인했으므로, 홈페이지에 해당 공개 경로를 연결하지 않았다. 웹 내 홈을 공개할 때는 실제 호스팅 경로와 등록된 OAuth 도착 경로를 먼저 맞춰야 한다.
