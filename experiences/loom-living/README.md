# 몽글과 바람의 정원 — Loom 실시간 장면

2026-09-13 · 몽글 한 명과 기존 배경 한 장으로 검증하는 로컬 장면이다. 사용자가 요청한 Loom 업그레이드의 첫 구현이며, SYNK-talk 학생 앱 배포나 1년 스토리 기능 구현은 포함하지 않는다.

## 실행

완성된 자산이 들어 있으므로 다음 명령으로 바로 시작할 수 있다. 서버는 숨김 창으로 실행되며 이미 실행 중이면 재사용한다.

```powershell
powershell -File experiences/loom-living/start.ps1
```

원본에서 자산을 다시 준비하거나 터미널에서 서버를 직접 실행할 때는 저장소 루트에서 실행한다.

```powershell
node tools/loom-living-build.cjs
node tools/loom-living-server.cjs
```

[로컬 장면 열기](http://127.0.0.1:4319). 서버는 `127.0.0.1`에만 연결한다. 빌더는 형제 `SYNK-talk`의 `sharp`, 눈감음 자산과 눈 영역 자료를 사용한다. 새 이미지·영상 생성이나 외부 모델/API 호출은 하지 않는다. 패키징을 다시 하면 자산·색 토큰·깊이 정보·출처 지문이 갱신된다.

원본은 `docs/캐릭터/정본_4K/몽글_본체.png`와 `docs/라디오/무대/dream_field.png`다. 눈감음은 SYNK-talk의 기존 표정에서 지정된 눈 영역만 잘라 합성한다. 원본 파일은 수정하지 않으며, 출력은 크기 조정·압축·화면의 미세한 조명 보정을 거친다. 따라서 원본 파일의 바이트나 화면 픽셀 전체가 같다는 뜻은 아니다. 눈 영역 밖 합성 변화와 알파 변화는 실행 중 `eyeAudit`에 별도로 기록한다.

현재 방식은 **2.5D**다. 그림에 깊이와 변형 가능한 격자를 붙여 입체감을 내며, 실제 옆면·뒷면과 뼈대를 가진 3D 모델은 만들지 않았다. 깊이는 기존 `tools/lib/깊이격자.js`의 형태 근사다. 모든 나무·소품을 자동으로 분리하거나 임의의 이미지를 완전한 움직이는 캐릭터로 변환하는 기능도 아니다.

카메라·수평선·땅·나무 몸통·광원 위치와 전체 노출은 고정한다. 한 장면의 바람을 몽글의 상체와 작은 씨앗, 선택된 풀 5곳이 공유한다. 눈은 관심 대상을 먼저 따라가고 몸은 작게 따라간다. 바람 버튼은 씨앗 사건도 시작하며, 자연 발생 간격은 20~32초다. 시선은 다시 쉬는 자세로 돌아온다. 독립된 나뭇가지 관절이나 실제 공기·광선 물리 시뮬레이션은 없다.

현재 사용자 요청에 따라 **이미 그림에 있는 불빛 14개**의 고정 중심에서 원본 색을 읽고, 밝은 중심과 부드러운 빛 번짐을 screen 방식(배경을 어둡게 하지 않고 빛을 겹치는 합성)으로 더한다. 번짐 범위는 설정 반경의 **2.65배**이며 위치와 범위는 고정한다. 느리고 서로 다른 주기의 **0.18~1 계수**로 이 효과의 세기를 바꾼다. 이 계수는 화면 밝기의 ±변화율이 아니며, 이전 ±10% 제한은 현재 구현에 적용되지 않는다. 새로운 광원 위치나 이미지 자산은 추가하지 않았다.

전경 풀은 **5개**다. 좌우의 큰 풀 3개는 각 5개, 모바일 화면에도 남는 중앙 하단의 짧은 풀 2개는 각 2개 캡슐 영역(줄기를 따라 이어진 좁은 마스크)만 변형한다. 뿌리의 변위는 0이고 끝으로 갈수록 커지며, 최대 변위는 **1.3CSSpx**다. 넓은 땅이나 배경 전체를 휘게 하지 않는다. 이 풀은 원본 이미지의 지정 영역을 다시 읽어 표시하는 2D 국소 변형이며, 배경에서 완전히 분리된 풀 자산이나 진짜 3D 풀은 아니다.

적용 경로는 `environment.json` → `tools/loom-living-build.cjs` → `scene.json`의 환경 설정 → `loom-scene-webgl.mjs`의 `renderEnvironment`다. 빌더가 원본 자산과 좌표를 묶고, 표시기는 같은 배경 텍스처를 불빛과 풀의 좁은 영역에 재사용한다. 정지 시 공통 시간과 바람이 고정되므로 반짝임과 풀도 멈춘다.

2026-09-13 사용자의 「살짝 멀미날 것 같은 느낌」과 「배경이랑 몽글이 따로 노는 느낌」에 따라 수정했다. 기존 배경 변형·시선에 따른 배경 이동·전체 밝기 진동·17개 상시 부유 입자를 제거했다. 회전 상한 .12→.055라디안, 기울기 .035→.012, 호흡 .004→.0012로 줄였다. 바닥 좌표는 유지하고 UV y=.83 아래를 고정했다. 몽글의 화면 색에는 고정된 주변광·하단 음영을 적용한다. 수정 사실과 사용자가 편안하다고 느끼는지는 별개이며 후자는 아직 확인되지 않았다.

이후 「그림자가 어색하다」는 피드백에 따라 밑단 위에 밝은 원본 땅을 덮던 패치(type 4)를 제거했다. 현재 그림자는 본체 알파 윤곽을 높이 h에 비례해 오른쪽 +0.40h·아래 +0.27h로 투영하고, 9개 표본과 거리에 따른 퍼짐으로 부드럽게 만든다. 여기에 실측 접점 세 곳 (.237,.8444), (.488,.8515625), (.737,.84049)의 좁은 음영과 바닥의 부드러운 음영을 합쳐 **한 번의 곱셈 합성**으로 표시한다. 밝은 바닥 패치로 그림자를 지우지 않으며 원래 땅의 질감을 남긴다. 이는 원본 그림의 윤곽을 이용한 2D 그림자 근사이며, 진짜 3D 광선 물리 계산은 아니다.

정지·화면 숨김·운영체제의 움직임 줄이기 설정은 현재 자세를 멈춘다. 복귀 직후의 긴 시간 간격은 버린다. 공통 코어의 `reading` 입력은 읽는 동안 바람·호흡을 낮추고 시선을 중립으로 돌리는 통로이며, 이 장면에는 별도 읽기 화면이 없다. 소리는 기본 꺼짐이고, 사용자가 켰을 때 브라우저에서 만든 합성 바람 소리를 재생한다. 녹음 파일이나 외부 음성 서비스는 사용하지 않는다.

2026-09-13 말풍선 디테일 요청을 반영했다. `가이드_정본.md` §2-6의 몽글 구름형·즉시 반응과 기존 SUIT 서체를 유지하고, Paper·Oat·Stitch 토큰으로 천의 두께, 잔결, 실의 그림자·밝은 결, 매듭을 표현한다. 새싹과 이름은 작은 자수 표식으로 배치한 이번 장면의 디자인이며 전역 로고 정본이 아니다. 표시 시간은 문장 길이에 따라 4.2~6.5초이며 대사 교체 시 다시 센다. 작은 등장 반동은 240ms 이내, 키보드 조작·움직임 줄이기에서는 즉시 표시한다. 짧은 휴대폰에서 제목과 겹칠 때는 제목만 잠시 숨겼다가 복원한다. 기술 오류의 화자는 ‘안내’로 구분한다. 화면과 별도로 항상 존재하는 `role=status` 영역에 같은 대사를 전달하며, 실제 스크린리더 청취는 미확인이다.

## 검증

```powershell
node --test tests/loom-scene.test.mjs
```

2026-09-13 코어 시험 6/6 통과: 30·60·120Hz 입력에 같은 결과, 큰 시간 간격과 비정상 입력 방어, 정지 및 복귀, 공유 돌풍, 시선과 몸의 지연·눌림 복원, 깜빡임 간격과 휴식. 이는 장면 수학과 상태 전환 확인이며 실제 화면 품질·휴대전화 성능을 입증하지 않는다.

현재 구현의 브라우저 검증 결과는 [qa/report.json](qa/report.json)에서 확인한다. 이번 그림자·빛 번짐 수정 후에는 **불빛 반경 2.65배의 번짐·풀·그림자 영역 밖 배경의 고정**, 광원 위치 유지, 풀 뿌리 고정과 변위 상한, 본체와 바닥 접점의 합성, 정지 동작이 검증 대상이다. 보고서가 해당 변경을 확인하지 않았거나 증거가 없는 항목은 미확인이다. 실제 관찰 상태와 프레임 간격을 사용자의 편안함을 입증하는 값으로 해석하지 않는다.

Git `cecc424f3` 당시의 QA는 기존 불빛 14곳의 ±10% 국소 밝기와 풀 5곳, 이전 그림자 구현을 대상으로 했다. 그 결과를 현재 그림자·빛 번짐의 검증으로 이어 쓰지 않는다. 최신 캡처·영상과 수치는 보고서의 대상 버전·파일 정보를 따른다.

과거 Git `e71997513`의 강한 시선·눌림·돌풍 입력 전후 배경 세 영역 약 82만 픽셀 변화 0, 눈 영역 밖 합성 변화·알파 변화 0, 430×932 화면과 영상 재생 확인은 불빛·풀을 추가하기 전 결과다. 현재 배경 전체 픽셀이 변하지 않는다는 주장은 하지 않는다. 최초 구현의 전체 화면·움직임 줄이기·그래픽 복구 확인도 Git `507b64f06` 당시 검증이다.

## 다른 자산으로 확장할 때

먼저 이 장면의 실제 재생과 상호작용을 확인한다. 다음 자산은 같은 공통 코어를 쓰되 원본·깊이·눈 영역·고정점과 움직임 상한을 그 자산에 맞춰 준비한다. 색·질감·큰 회전에서의 찌그러짐을 다시 확인하며, 현재 몽글의 눈 좌표나 깊이를 다른 캐릭터에 그대로 적용하지 않는다. 큰 회전·손발 동작이 필요한 주요 캐릭터의 진짜 3D는 별도 검증 단계다.
