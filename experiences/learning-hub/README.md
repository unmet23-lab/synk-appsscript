# SYNK 맞춤 학습 — 공통 게임 입구

2026-10-02 로컬 구현. 게임의 관측이 다음 게임과 실제 출제를 바꾸는지 확인하는 기기 체험 입구다. 후속으로 상단에 WORLD 공통 계정 입구를 연결했다. 계정 연결은 별도 공개 설정과 서버 준비가 필요하며, 이 체험 화면의 기기 기록을 자동 이관하지 않는다. 운영 배포·두 실기기 SSO·학생 효과 검증은 포함하지 않는다.

```powershell
node tools/build-game-learning.js
node tools/build-synk-account.js
node experiences/learning-hub/server.mjs
# 플랫폼 개발 홈: http://127.0.0.1:4280/
# 기존 맞춤 학습: http://127.0.0.1:4280/learning-hub/
```

일곱 게임을 위 맞춤 학습 주소의 링크로 연다. 각 게임을 별도 포트에서 열면 브라우저 저장소가 달라 공통 기록이 이어지지 않는다. localhost 서버는 이 PC에서만 듣는다. 외부에 공개하는 배포 서버가 아니다. 플랫폼 후속 요청에 따라 `/`는 설치형 런처 화면의 웹 미리보기로 이동하며, 학습 허브와 기존 게임 경로·기록은 유지한다.

## 실제 흐름

추천 이유 → 추천 게임의 실제 후보/코스 → 문항 제시 → 음성 전달·도움·의미 응답 → 다음 추천. 듣기/읽기·언어 난도·응답 방식에 맞는 최근 관측을 사용한다. 기록이 없는 능력은 약점으로 표시하지 않는다. 소리 사용 불가를 선택하면 읽기 코스로 이어진다. 원하는 게임은 언제든 직접 고를 수 있다.

공통 원본은 `atlas/`와 `strata/`다. 게임의 `atlas-learning.js`는 빌드 산출물이므로 직접 수정하지 않는다. `node tools/build-game-learning.js --check`로 여덟 소비처(일곱 게임과 허브)의 지도 일치를 확인한다. 앱은 `node tools/sync-atlas.js --consumer talk`로 같은 원본을 사용한다.

기록은 하나의 브라우저 기기에 저장하며 계정 로그인은 없다. 함께 쓰는 기기에서는 학생을 구별할 수 없으므로 별도 브라우저 프로필을 사용하거나 다음 사람이 시작하기 전에 공통 학습 기록을 지운다. 이 기록을 앱 학생 계정으로 자동 옮기지 않는다. 저장 실패/손상/표본 부족은 기본 연습을 열고 해당 능력을 확정하지 않는다.

## 실제 적용 범위

- 레이싱: 기록에 맞는 5문항과 듣기·읽기 선택. 링크의 `?learning=reading|listening`이 첫 추천 코스에 적용된다.
- 리듬: 듣기 문항의 학습 항목에 맞는 다음 곡. 리듬 점수는 언어 정오와 분리한다.
- 주문 폭주: 다음 주문 선택, 글/재청취/정답 공개와 첫 응답·재시도 기록.
- 바람길: 노출·반복 이력을 읽어 다음 지시를 고른다. 액션 결과는 조작 영향 때문에 언어 실력의 독립 근거가 되지 않는다. 다른 형식의 정오를 행동 능력으로 옮기지 않으므로 현재는 약점 진단 기반 액션 조정이 아니다.
- 입장 검사(2026-10-02 추가): 읽기 `single-choice`. 기록에 맞춰 근무지 안의 손님 6명을 고르고, 결과에서 세 읽기 항목의 상태와 다음 근무지를 추천한다. 돋보기 뒤 정답은 도움으로 남긴다. [입장 검사 README](../entry-check/README.md)
- 선생님이 돌아왔다(2026-10-02 추가): 읽기 `action`. 글/음성 도움·최초 응답·같은 글/새 글을 기록하고 지금 할 수 있는 부탁 중 다음 추천을 소비한다. 기본 한국어 음성 또는 글로만 연습을 제공한다. WORLD 목록의 기존 호스트를 사용하며 실계정 운영은 미확인이다. [이야기 README](../story-classroom/README.md)
- 빈칸 베기(2026-10-02 추가, MVP): 읽기 `single-choice`. 문장 하나 = 문항 하나(낱말 뜻 읽기·조사·문형 읽기). 기록에 맞춰 한 판 12문장을 고르고 결과에서 두 항목의 상태와 다음 판 이유를 보여 준다. 벤 말이 답이고, 두 번 던져도 못 벤 문장은 정답을 보이기 전에 멈춘 보기에서 답한다(10-03). [빈칸 베기 README](../blank-slice/README.md)
- **후보의 문항 계열(2026-10-03):** 후보마다 그 칸에 실제로 있는 문항 계열(`families`)을 넘긴다. 계열을 모두 낸 게임은 아직 첫 시도를 줄 수 있는 게임 뒤로 간다. 전에는 계열이 없어, 예컨대 이야기 교실의 읽기 세부 문항 4개를 다 쓴 뒤에도 같은 게임을 계속 추천했다. `catalog.test.mjs`가 목록을 게임 문항과 같게 묶는다.
- 앱: 같은 엔진을 쓰는 맞춤 읽기 화면과 공통 SYNK 계정별 저장·서버 동기화 코드. WORLD 계정 입구에서 연 웹 게임과 같은 수행 사건 계약을 쓰며, 운영 연결·두 실기기 왕복은 미검증이다.
- Town: 공통 관측을 소비하는 언어 장면 어댑터와 별도 [FT10·FT51 생활 제작판](../synk-town/README.md)이 있다. 생활 장면의 행동 기록을 언어 수행으로 바꾸지 않으며, 실제 계정·TOPIK 권한과 언어 과제의 생활 화면 연결은 후속이다.

자세한 기준과 남은 필수 연결은 [공통 학습 기준 §9](../../docs/미니게임_TOPIK_I_학습기준.md#9-실제-개인화-연결--2026-10-02-후속-구현)에 둔다.

계정 로그인·공개 설정·브라우저 합성 미리보기는 [공통 계정 입구](../synk-account/README.md), 앱/서버/운영 보호 장치의 구현과 한계는 [공통 계정 구현검증](../../docs/SYNK_공통계정_구현검증_20261002.md)에 있다. 로컬 서버는 계정 폴더의 검토한 공개 파일만 제공하고 소스·node_modules·설정 예시는 제공하지 않는다.

## 오늘 컨디션과 순간 맞춤 (2026-10-02)

추천 카드 아래의 "오늘은 어때요?"(좋아요·보통이에요·피곤해요·시간이 없어요)는 본인이 누를 때만 쓰인다. 그날이 끝날 때까지 이 브라우저의 게임들이 함께 읽고, "피곤해요"면 그날 게임은 더 어려워지지 않고 힌트를 줄이자는 권유도 쉰다(필요하면 한 칸 가볍게 시작한다). 2026-10-03 확인: 판 안에서 어려워지는 게임(주문 폭주·말의 리듬·바람길·빈칸 베기·입장 검사)은 모두 순간 맞춤으로 이 약속을 지키고, 레이싱·이야기 교실은 판 안에서 어려워지지 않는다. "도움은 어떻게 받을까요?"는 도움이 저절로 나오는 두 게임(입장 검사 돋보기·이야기 교실 읽어 주기)에 적용되고, 다른 게임의 도움은 누를 때만 나온다고 화면에 적는다. 쌓아서 성향으로 만들거나 다른 사람에게 보이지 않는다. 단추는 실제 펠트 판(`assets/slab-*-long.webp`, 펠트 부품 원본을 720px로 줄인 무손실 사본)이다. 게임 안에서 사람에 맞춰 바뀌는 것은 [순간 맞춤](../../docs/아틀라스_순간맞춤_20261002.md)과 [실험실](../atlas-lab/index.html)(`/atlas-lab/`)에서 볼 수 있다. 실험실의 상담 시연을 위해 서버는 맞춤 도구의 `rules.js`·`content.js` 두 파일만 `/consult/computer/`로 읽기 전용 제공한다.

## 검증
