# 한국어 공부 · WORLD 밖에서 바로 하는 AI 튜터 학습(2026-10-28 설계)

**현재 반영 상태(10-28 의미 튜터 작업):** 의미 분석·원인별 확인/연습·계정 로그인이 `/study/`에 공개됐다(`578135b2`, 파일 6/6 대조). 서버 `world-writing` v11은 모듈 13/13·앵커 5/5가 검수한 원천과 일치한다. 실제 공개 화면에서 합성 글로 로그인 → AI 확인 → 설명·연습 → 자기 글 수정 → 다음 자료까지 확인했다. 사용자 직접 승인 “이번 작업만 GPT 구현·아르곤 검수로 진행”에 따라 기존 Claude 담당·필수 Fable만 이번 작업에서 대체하며 아르곤 검수·최종 후보 대조는 유지했다. 실제 학생의 학습 효과는 아직 검증하지 않았다(§9).

유호님 10-28: 「AI가 선생님이야」 · 「지금 이건 synk world랑 아예 별개인거지? synk world 입장하기 전에 제공하는 것들이어야 해」. 학생은 SYNK에서 AI 튜터와 바로 한국어 공부를 시작하고, WORLD는 따로 골라서 들어간다. 이 폴더가 그 독립 학습의 원문이다. 개발 기준은 [AI 튜터의 책임](../synk-world-app/README.md#ai-teacher-topik4-20261028)이다.

**이름과 역할:** Study는 `/study/` 주소의 「한국어 공부」 화면이다. Atlas는 공통 학습 판단·기록 엔진, WORLD는 마을·캐릭터·게임 학습 화면, Study는 AI 튜터와 바로 공부하는 독립 학습 입구다. 현재 학습 범위는 TOPIK II 쓰기 중심이며, 별도 엔진을 뜻하는 이름이 아니다.

WORLD 쪽 상태(구분): WORLD 쓰기 연습 51~54와 자동 피드백은 10-21 synk.im/world에 공개됐다. 그 위의 53번 「한 가지 고치기」 고도화(커밋 `ad409b96`·`20234254`, [설계](../synk-world-app/qa/writing-focus-20261027/설계.md))는 `writing-focus-s2` Fable 최종 검수가 끝나지 않아 **라이브 미공개**다. 이 폴더는 그 코드의 화면 없는 순수 판정만 빌려 쓴다.

**한 줄:** 학생 글에서 한 가지 근거 있는 문제를 찾고 → 짧은 확인으로 도움을 조절하고 → 이해했으면 적용으로, 헷갈리면 예문으로 → 자기 글을 고치고 → 새로운 자료로 이어진다. 로그인하면 의미 AI가 이를 맡고, 연결할 수 없으면 기기 안의 제한된 끝맺음 연습을 명확히 안내한다.

## 2. 학습 장면(학생에게는 한 번에 하나)

학생이 하는 선택은 답하기·계속·쉬기뿐이다. 장면마다 주 단추 하나(+ 「오늘은 그만」).

| 장면 | 학생이 보는 것 | 언제 |
|---|---|---|
| **A 써 보기** | 검수 통과 53번 자료 + 「이 자료를 세 문장 이상으로 설명해 보세요(시험은 200~300자)」. 지원 단계: L0 아무것도 없음 · L1 「다 썼어요」 뒤 「끝만 위에서 아래로 다시 읽었나요?」 한 장(고칠 기회, 단추 「점검하기」) · L2 위에 바꾸는 꼴 네 줄 | 처음 · 근거가 오래됨 · 방법 뒤 |
| **B 본 것** | 사실 한 줄(「문장 5개 가운데 2개가 「-습니다」로 끝났어요」)과 그 문장 표시. 다음 장면 이름이 붙은 주 단추 하나 | A 뒤 |

| **D3 내 글에 옮기기** | 「끝 찾기」 짧은 글 1편(`use:learn` — 섞인 문장 고르기, 고른 뒤 해설) → 「내 문장 바꿔 보기」(방금 잡힌 내 문장 최대 3개). 확인은 끝 꼴뿐이고, 흔한 틀린 꼴(「많는다」류 상태+는다, 「증가하다.」류 사전형)만 규칙으로 짚는다 — 맞았다는 말은 「끝이 「-다」 꼴이에요」까지(학생 문장의 정답을 판정하지 않음, P2-5). 근거로 쓰지 않는다 | 가설 「적용」 |
| **E 고쳐 쓰기 → 새 자료로** | 방법 뒤에는 방금 쓴 글을 고쳐 쓴다(내 글이 채워지고 고칠 문장 표시, 도움 L2/L1 — 새 근거 아님). 맞으면 그 자리에서 처음 보는 자료로 혼자 한 번(L0) | 방법 뒤 |

| 9 | 그 밖 | 구별 흔들림 → 구별, 형태 틀림 → 형태, 아니면 적용(재료가 없는 방법은 건너뜀) | D1·D2·D3 |

**쓰기 한 편에서 나오는 근거 셋(섞지 않는다).** ① **끝맺음 KC**(`study.ko2.ending-plain`) — 문장 끝 하나하나를 `endCheck`로 ok·wrong·unknown으로 가른다. 목록을 늘리는 대신 형태 규칙으로 확실한 것만 판정한다: 「-습니다/-아요」, 「는다」 앞이 받침 없음·ㄹ받침(「빠르는다」), 과거·「-겠-」·「없」 뒤 「는다」(「증가했는다」), 「-은다」(「많은다」), 「-아/어지다」·「-되다」 사전형(「높아지다」·「예상되다」), 검수 목록의 상태어 + 는다/ㄴ다(「많는다」·「필요한다」), 자료 설명 동사 사전형(「증가하다」)은 wrong. ㅆ·ㅄ 받침 + 다(「늘었다」·「없다」), 「-이다」, 그 밖의 「ㄴ다/는다」, 검수 형용사 목록의 「-다」(「중요하다」)는 ok. 품사를 알아야만 갈리는 「-다」(「급증하다」)와 알아볼 수 없는 끝(오타·의문·「-음」)은 unknown — 성공으로도 실패로도 세지 않는다. 틀린 끝이 하나라도 있으면 incorrect, 확인된 끝 ≥ 3 · 확인 못 한 끝 ≤ 1 · 자료와 이어짐이면 correct, 그 밖은 unassessed. ② **과제 이행**(자료 설명) — 규칙으로 채점하지 않는다. 언제나 미판정이고, 숫자·글자 수로 과제 성공을 주지 않는다. ③ **자료와의 연결**은 차단 보조일 뿐이다 — 자료 낱말 하나 + (자료 숫자 하나 또는 낱말 하나 더)가 글에 없으면 끝맺음 근거로도 쓰지 않고 「이번 글이 이 문제와 이어지는지는 확인하지 못했어요」라고만 말한다(낱말이 일부 있어도·54번이어도 맞는 말). 문제·지문을 열 글자 넘게 옮긴 문장(54 지문은 「-다」 문장이다)은 unknown, 붙여 넣은 글자가 글의 절반 이상이면 점검·원인 확인·연습은 글에서 본 사실 그대로 이어 가되 Trail 독립 근거에서만 뺀다(막지 않는다 · 글을 다 지우면 셈도 처음부터). ok는 「끝이 「-다」 꼴로 확인됨」까지다 — 목록 밖 하다 형용사 + 「ㄴ다」(「편리한다」)와 「큰다·싼다·긴다」(같은 꼴의 움직임 낱말이 있음)는 ok로 잘못 셀 수 있어 활용이 맞았다고 말하지 않는다.

**원인 근거는 Trail이 독립이라 한 확인(C) 답만**이다. 연습(D1·D2)은 설명이 화면에 나온 뒤라 Trail에 도움(explanation)으로 남아 독립이 아니고, 연습에서 본 카드가 확인으로 와도 Trail이 반복으로 뺀다. 확인 카드는 풀에서 키로 고정한 몫(약 1/3)만 쓰고 한 번 쓰면 다시 확인으로 쓰지 않으며, D1 소개 예시와 연습 카드는 나머지 몫에서만 나온다. C의 형태 확인은 정답·해설을 보이지 않는다. 형태 문항 채점: 인정 범위와 같거나 띄어쓰기만 다르면 맞음, 알아볼 수 있는 다른 꼴(「증가했다」·「증가하다」)은 틀림, 알아볼 수 없는 꼴인데 인정 답과 자모 두 개 안쪽(「공부한댜」·「증거한다」)은 「입력한 꼴을 확인하지 못했어요」 — 형태 흔들림으로 세지 않는다(다른 서비스 규칙을 옮긴 것이 아니라 우리 판정 범위 설계).

**도움·첫 시도:** 독립 여부는 `tutor.mjs`가 따로 판정하지 않고 Trail `summarize()`의 independent만 읽는다(같은 자료 두 번째 시도·고쳐 쓰기 = 반복, L2 바꾸는 꼴 표·L1 끝 다시 읽기 = cue 도움, 연습 형태의 정답 공개 = answer). 설명 직후 같은 날의 혼자 성공은 독립이지만 「끝」에는 하루 뒤 성공이 하나 필요하다. 반복 정답·설명 직후 성공으로 능력·성향을 말하지 않는다.

**판정 안 함:** 세 문장 미만, 같은 문장 반복, 빈 글·공백만. 그때는 「세 문장 이상 써 보세요」 한 줄만 보이고 기록하지 않는다. 오타·의문 문장 하나는 그 문장만 unknown이다(예전에는 글 전체가 판정 안 함이 되어 「세 문장 이상」이라는 틀린 안내가 나왔다).

**중단·재개:** 장면이 바뀔 때마다·입력마다 기기에 저장. 다시 열면 마지막 장면. 카드·문항 중간에 닫으면 이미 답한 것은 남고 다음부터. 저장이 막히면 화면은 돌고 「이 기기에 저장하지 못했어요」 한 줄.

## 3. 데이터(`synk.study.v2:<owner>`, 기기 기록과 계정의 최소 진도)

`{v:2, seq, obs:[…최대 240], trail:[Trail 사건…최대 1200], scene:{…, did}, drafts:{itemId|r:itemId:{text,updatedAt,checkedAt,pasted?}}, seen:{문항ID|card:키:처음 본 시각}, recentCards:[…12]}`.
- **trail** — Atlas Trail 사건(scope `LAB/study/device`): 장면마다 `decision.made`(plan: 장면·이유·방법·자료·도움 단계 — 원인 가설 → 처치 → 새 자료 결과 → 지연 확인을 따라갈 수 있다), 답마다 `practice.presented`(itemKey, conceptIds `study.ko2.ending-plain`·`.distinguish`·`.verb/.adj/.noun/.past`, `firstExposure`는 `seen`으로) → `practice.helped` → `practice.attempted`(verdict, errorTags `ending.off`·`form.*`·`task.unlinked`·`input.copied`·`input.pasted`·`input.typo`). 60일·1200건을 넘으면 결정 묶음 통째로 자르되 카드·형태 묶음부터. 읽을 때 Trail 계약(필드·부모·시각 순서·첫 시도)을 어긴 묶음은 통째로 버리고, 요약이 실패하면 독립 근거 0으로 읽는다(화면은 계속). 기록 시각은 직전 사건보다 앞서지 않게 맞춘다(기기 시계 되감기).
- **obs** — 제품 사실(쓰기 `{itemId,support,mode,plain,off,total,formal,polite,flags,axes,verdict,unknown,linked,first,pasted,ev}` · sort · form(ok 참·거짓·null) · find · method · probe · cycle). 순서는 기록 차례 `n`(같은 시각·시계 되감기에도 앞뒤가 그대로). 사건 id(`ev`)가 없거나 원장에서 잘린 obs는 근거가 아니다. 상한을 넘으면 쓰기 아닌 관측부터 던다. 미래 시각 obs는 지우지 않고 근거에서만 뺀다.
- 학생 문장 원문은 `drafts`에만. 고쳐 쓰기 초안은 `r:<자료>`로 따로 둬 처음 쓴 글이 남는다. 모르는 종류·깨진 값은 읽을 때 버린다. 10-28 Atlas 보완은 기존 계정 행에 최소 진도와 버전만 추가한다. 원문은 이 동기화에 들어가지 않는다.

### 3-1. 계정 이어하기 — Atlas 보완(2026-10-28)

기존 `feedback-client` 인증을 재사용하며 AI 사용 가능 여부와 진도 저장 가능 여부를 분리한다. `learningSession()`이 확인한 계정·동의 판으로 `progress-sync.mjs`가 먼저 읽은 뒤 다음 학습을 시작한다. 읽기 실패를 빈 서버 기록으로 취급하지 않는다. 서버 `view=study`는 계정 잠금 안에서 동의·현재 버전·스냅샷 크기/형식을 다시 검사한다. 같은 요청의 응답만 잃은 재시도는 성공을 돌려주지만 다른 버전의 기록을 덮지 않는다.

두 기기의 진도가 충돌하면 자동 병합하지 않는다. 기기 기록 내려받기와 서버 기록 이어하기를 보여 주며, 서버 기록을 고르기 전에 현재 기기 기록을 별도 키에 보존한다. 저장 공간 오류 때는 선택을 중단한다. 「처음부터」는 새 기기 칸이며 원 계정 기록으로 돌아가는 길을 제공한다. 인증 만료·계정 전환은 진행 중 AI/동기화를 무효화하고 앞 계정 초안을 새 칸에 표시하지 않는다.

로컬 브라우저에서 실제 작성 → PostgreSQL 저장 → 별도 기기 저장소의 진도 복원을 확인했다. 이 시험은 합성 계정과 실제 API/DB 계약을 사용했으며 운영 OAuth와 실제 학습자 성과를 검증한 것은 아니다. 독립 GPT가 동기화 인증 만료 후 앞 초안이 남던 P1을 찾아 고쳤다. 구현·검수·운영 반영 결과는 [작업 검증 기록](../../docs/_ops/qa/atlas-world-learning-20261028/README.md)에 둔다.
- **이관(v1 → v2):** v2 칸이 없을 때만 옛 `synk.study.v1:<칸>`을 읽어 옮기고, **옛 칸은 지우지도 덮지도 않는다**(배포 중 열린 옛 탭이 v1에 써도 v2가 지워지지 않게). v2가 깨져 읽을 수 없어도 「있음」으로 보고 다시 옮기지 않는다. 옛 관측은 원본 그대로(`source:'legacy'`) 두고 새 판정 범위로 다시 채점하지 않는다 — 옛 「-습니다/-아요」·목록 틀린 꼴은 실제로 본 틀린 끝이라 incorrect, 옛 성공은 unassessed(새 독립 성공으로 올리지 않음). 옛 카드·형태 답은 확인용만 첫 노출로, 연습은 설명 뒤로. 옛 D1 소개 예시(바구니마다 풀 첫 카드)와 최근 카드는 본 것으로 둔다. 처음 본 시각은 그대로.

## 6. 계정과 의미 AI 연결

- 기존 등록 콜백 '/account/client.html?product=world'를 같은 탭 PKCE state·clientId·redirectUri·10분 만료에 묶어 쓴다. 토큰은 공부 전용 sessionStorage 칸에 두고 고정 '/study/'로 돌아온다. WORLD 화면·반 연결을 열지 않는다. OAuth 허용 목록이나 접근 설정을 바꾸지 않는다.
- 기존 world-writing에 'mode: study'와 'study: {stage, focusSkill}'만 추가한다. 기존 인증·eligibility·문항 해시·매번 전송 동의·하루 3회·금액 원장·모델을 공유한다. AI가 꺼짐/한도/오류/형식 불일치이면 재발송하지 않고 제한된 기기 내 연습으로 안내한다.
- 53 자료 설명과 54 도입 세 문장: 의미 요약, 한 가지 관찰, 학생 글·공개 과제의 정확한 인용, 원인 가설, 확인, 설명/예문, 서로 다른 적용 연습, 자기 글 수정 요청을 반환한다. 틀린 이유를 확정하지 않으며 근거 없는 인용·중복 선택지·점수/급수·깨진 언어 응답을 거른다.
- 확인을 맞히면 긴 설명 없이 적용 연습으로, 틀리면 짧은 예문을 거쳐 적용한다. 마지막에는 원래 자기 글을 채워 고쳐 쓴다. 한 자리 쓰기 최대 3회·새 자료 최대 2개. AI 확인/연습 결과는 Trail에 도움 받은 'ai-reference/unassessed'로 남고 독립 성공·숙련으로 승격하지 않는다.
- 서버는 학생 글/피드백 원문을 저장하지 않는다. 브라우저에는 계정별 초안·현재 피드백 장면을 저장한다. 계정의 최소 진도만 §3-1로 동기화하며 기존 손님 칸을 자동으로 계정에 합치지 않는다. 계정 변경·이 탭 연결 닫기·늦은 응답은 앞 계정 결과를 새 칸에 쓰지 못한다.
- 시험은 합성 데이터다. 실제 학생의 학습 향상·재미·장기 원인 추론은 아직 측정하지 않았다. AI가 고른 문제/설명/선택지도 오류가 있을 수 있으며 검수된 고정 문항과 동일한 독립 평가로 취급하지 않는다.

## 12. 학생이 체감하는 의미 튜터 보강(10-28)

이미 검토한 의미 튜터 설계를 잇는 보강이다. 사용자 직접 승인한 GPT 구현·아르곤 검수 범위를 유지한다. 새 엔진·모델 선택기·세계 입장·교사 개입·추가 AI 호출은 만들지 않는다.

1. **확인 전에 답을 노출하지 않는다.** 오답 지적과 수정 예문을 먼저 보여주던 순서를 바꾼다. 학생은 중립적인 질문 하나와 두 보기만 보고, 필요하면 전체 과제를 펼쳐 본다. AI 생성 질문이므로 이 답을 독립적인 실력 증거로 올리지는 않는다.
2. **이해했으면 바로 자기 글로 돌아간다.** 확인 정답 → 짧은 해설 → 자기 글 수정. 확인 오답 → 해설과 예문 → 작은 적용 연습 → 자기 글 수정. 적용도 막히면 수정란에 예문을 함께 둔다. 같은 문제를 고쳐 썼는데 같은 어려움이 남으면 확인 질문을 되풀이하지 않고 새 도움부터 이어간다.
3. **앞서 고른 답을 다음 AI가 참고한다.** 기존 Trail에 선택을 미판정·도움 있음으로 남기며, 계정별 기기 기록에서 최근 14일·최대 4개의 질문/선택/AI 정답/해설만 다음 글 요청에 함께 보낸다. 학생에게는 글과 최근 선택을 보낸다는 안내만 한다. 초안 전체·계정 정보·기록 시각은 추가하지 않는다. 새 칸/다른 계정/오래된 기록은 섞지 않는다. 서버가 `studyContextVersion:1`을 알릴 때만 새 문맥을 보내므로 옛 서버에도 연결된다. 계정 진도와 합칠 때 이 문구(`semantic.detail`)는 동기화 직렬화에서 빼고 기기에만 둔다. 다른 기기에는 이 문구를 복원하거나 추정하지 않는다.
4. **다음 자료에 같은 학습 목표가 있게 한다.** 53번은 변화 방향·수치 단위·집단 비교 중 AI가 골라 준 목표를 기존 검수 통과 과제의 자료 구조와 맞춘다. 예: 중고 거래 이용자 변화 → 언어 교환 참가자 변화. 맞는 미노출 자료가 소진되면 같은 유형, 그다음 남은 자료로 가며 없으면 쉰다. 재고 선택은 편집 표이며 학생 능력/난이도 측정값이 아니다. 이번 글이 clear여도 앞서 연습한 목표는 다음 과제까지 보존한다.

검증 범위: 기존 끝맺음·저장/이관·로그인·취소 회귀, 확인 정오답의 서로 다른 흐름, 새로고침 이후 선택 반응 전송, 같은 오류 반복 시 도움 전환, 목표별 다음 과제와 재고 소진. 390/1440 폭·ko/en/mn 화면에서 넘침·버튼 크기·콘솔 오류를 재고, 실제 모델에는 합성 글만 보낸다. 실제 학생의 흥미·학습 향상·유료 전환은 이 시험으로 증명하지 않는다. 결과/공개/CI는 [트랙](../../docs/_ops/트랙.md)의 이 작업 행에 남긴다.
