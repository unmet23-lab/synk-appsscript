# SYNK PATH · 첫날의 연습

한국 유학·학교생활·진로 탐색의 첫 행동을 가상 캠퍼스에서 연습하는 MVP다. **3인 실사 면접실은 공개 HTTPS로 제공하며**, 이전 가상 캠퍼스·3D 시제품은 로컬에 보존한다. 실제 학교·기업 소개, 입학·채용 보장, 한국어 능력 평가 서비스가 아니다.

## 공개 이용과 플랫폼 연결 · 2026-10-12

[실사 면접실](https://synk.im/path/interview/film/rehearsal.html)을 공개했다. [PATH 소개](https://synk.im/path/#vr)의 면접 시작 또는 [웹 플랫폼 PATH](https://synk.im/account/platform.html#app/path)의 ‘실사 면접실 열기’로 접속한다. 로컬 서버·PC USB 연결 없이 같은 HTTPS 주소를 Quest 브라우저에서도 열 수 있다. 음성 모델 준비→마이크 확인→VR 입장 순서이며, 실물 Quest·마이크·멀미 개선 효과는 아직 미검증이다.

현재 PC의 Platform0.4.3도 PATH 연결 네 파일만 갱신하고 나머지113파일·프로필·WORLD/Workspace를 보존했다. 네이티브 앱 UI는 미확인이고 실제 공개 웹 플랫폼의 버튼→새 면접실 탭은 확인했다. 새 공개 다운로드 설치파일 출시는 아니다. 공개59파일 전체 SHA·영상/모델15개 Range206, 면접실 Node135/135, 실제 공개 음성 모델 준비와4K 경험 분기 전체 완료·방 둘러보기 조작을 확인했다. 새 영상 생성·유료 크레딧0. [배포와 검증 범위](qa/public-release-20261012/README.md).

최종 공개 재생기 `96d4c10`는 준비 프레임과 취소·재개 소유권을 보정했다. 실제 공개4K의 경험 후속·무응답 재시도·전체 완료와 재생기40개 검사를 확인했다. 기존 탭이 이전 코드를 유지하면 강력 새로고침 후 이용한다.

**방 둘러보기 회색 화면 보정:** 면접 완료 후 처음 열거나 닫았다 다시 열 때 정지 프레임을 즉시 표시하며, 완료 후 화질 변경으로 영상이 비워지면 시작 이미지를 복원한다. 공개 `aa0af0e`, 관련39/39·실제 공개 세 경로 확인. [재현과 수정 근거](qa/public-release-20261012/README.md#방-둘러보기-회색-화면-수정).

**면접 중 둘러보기 전환 보정:** 둘러보기의 Esc는 면접을 멈추지 않고 화면만 닫는다. 공개 `3288953`, 관련63/63 통과와 실제 재생 중 열기·닫기·좌우 회전·후속 질문·완주를 확인했다. 멀미 완화 조작과 영상은 유지한다. [검증 근거](qa/public-release-20261012/README.md#면접-중-둘러보기-전환-검수).

**음성·둘러보기 자동 검증:** 실제 인식기에 합성음성을 넣어 둘러보기 전환 중 입력 유지, 준비/경험 후속 질문과 두 답변 완료를 확인했다. 별도로 찾은 질문 영상 재시작 오류는 공개 `8ea6823`에서 보정했다. 음성 관련59/59·재생기42/42 통과. 일부 단어 오인식이 있으며 실제 마이크·Quest·멀미 효과는 미검증이다. [검증 범위](qa/public-release-20261012/README.md#음성-답변과-둘러보기-연속-검증).

**음성 인식문 확인:** 공개 `26baad2`. 음성 답변은 원문 확인→수정 또는 다시 말하기→확정 후 진행하며 확인 시간은 별도다. VR에서도 원문 전체를 나눠 읽고 확인한다. 부정·타인 경험·정정·추측은 보수적으로 분기한다. 기존 인식 모델의 오타 자체는 남아 있으며 정확도 향상을 입증한 변경은 아니다. [검증과 한계](qa/public-release-20261012/README.md#음성-인식문-확인과-후속-질문-보호).

**음성 엔진 개선 · 공개 반영:** 실사 면접실의 인식기를 Whisper Base q8로 교체했다(실행 코드 공개 `c2d4e98`, 출처 문서 보정까지 최종 `dcd3cfb`). 최초 모델·런타임 다운로드는 약103MB이며, 기기 내 단일 worker에서 처리한다. 분기에 필요한 본인·행동·부정 표현이 명확하고 해당 단어의 인식 근거가 충분하면 자동 진행하고, 애매한 구간만 확인·수정·다시 말하기로 연결한다. 같은 AudioWorklet 입력 경로의 합성10문장 비교에서 문자 오류율(CER)은 Vosk21.35%(79/370)→Base q8 2.16%(8/370)였다. 소규모 합성 표본의 로컬 결과이며 실사용 정확도는 아니다. 관련205/205·패키지20/20 검사, 로컬 합성음성의 자동 진행/부분 확인 전체 흐름과 둘러보기 중 동일 입력 유지, 공개 모델 준비·방 둘러보기를 확인했다. 공개 변경28파일의 HTTP SHA·MIME 및 모델/WASM3파일 Range206도 일치했다. 실제 마이크·Quest 실기·멀미 효과는 미검증이다. [비교 근거와 한계](qa/public-release-20261012/README.md#whisper-base-q8-음성-개선--공개-반영).

**소음·경험 유무 보호:** 기기 내 같은 음성 인식기로 합성32개(팬/타이핑/혼합 소음, 고정 휴지·머뭇거림)를 검사했다. ‘경험 없음’ 원문16개에서 자동 경험 오분기는0개였지만 실제로 부정이 긍정으로 전사된1개가 있어 단어 오류가 없다는 뜻은 아니다. ‘경험이 있다/없다·한 적/해 본 적’처럼 의미를 뒤집는 짧은 표현은 인식 점수가 높아도 해당 구간만 확인한다. 후행 정정·불명확한 부정은 경험으로 확정하지 않고, 구체적인 본인 행동의 자동 진행은 유지한다. 같은 모델·추론량·영상·방·편안한 조작을 유지한다. 현재 공개 상태와 합성 시험의 한계는 [최신 검증](qa/public-release-20261012/README.md#소음과-경험-유무-검증)을 따른다.

## 현재 상태 · Quest 착석형 음성 면접 · 2026-10-12

사용자의 후속 요청에 따라 [면접실](http://127.0.0.1:4293/interview/film/rehearsal.html)을 **60~90초 목표의 착석형 공간**으로 확장하고, Seedance 720p 영상 네 편의 4K 확대본을 기본 적용했다. 시작 화면·주변 공간의 4K 확대 뒤, 좌우 벽·후벽·천장의 실사 재질을 새로 생성해 기존 영상의 색과 조명에 맞추는 보강을 적용했다. 사용자는 PC 둘러보기와 헤드셋에서 모두 멀미가 심하다고 답했다. 조작·입장 보정을 유지하며 실제 착용 시 개선 효과는 별도 확인한다. 당시에는 로컬 상태였으며, 현재 공개 연결은 위 항목을 따른다.

- **영상과 비용:** 같은 세 인물·복장·기준 이미지로 질문 1편, 무음 경청 1편, 후속 질문 2편을 각각 한 번 생성했다. 실제 원본은 1280×720·24fps·약10.04~10.08초다. 승인된 견적은 편당70·총 **280크레딧**이며 신규 구독·충전·추가 유료 생성은 없다. 로컬 FFmpeg Lanczos로 3840×2160으로 확대했으며 추가 제공자 크레딧은0이다. **네이티브 4K 생성이나 AI 세부 복원은 아니다.** 면접 시작 전 ‘4K · 720p 확대’와 ‘720p 원본’을 선택하며 진행 중에는 화질을 바꿀 수 없다. [실행 목록](interview/film/strict-manifest.json), [생성·비용 기록](interview/production/strict-interview-hd.json), [원본 메타데이터·ASR](qa/interview-film/strict-720-verification.json).
- **공간:** PC의 ‘방 둘러보기’와 Quest가 같은 착석형 공간을 사용한다. 방 폭4.53m·정면거리4.12m로 원본 사진 모서리에 맞췄으며, 좌우 벽 사진은 실제 벽 좌표에, 천장·바닥은 고정 평면 좌표에 매핑했다. 정면 사진을 옆/뒤까지 늘리던 계산을 제거하고 창틀·문 끝에서 연결한다. 후벽도 원근이 겹치던 사진에서 정사영 벽 사진으로 교체했다. 상판 깊이를1.7m로 확보하고 영상 아래쪽을 책상에 맞춰 접되, 화면 좌표를 셰이더에서 다시 계산해 컵·서류가 삼각형 경계에서 찌그러지는 문제를 보정했다. 영상 가장자리의 빈 배경만 기준 사진과 혼합하며 얼굴·손·필기는 움직이는 영상을 유지한다. [정면 확장 기록](interview/production/front-room-extension.json), [측면 자산·프롬프트](interview/production/side-wall-photographs.json), [후벽 정사영 기록](interview/production/back-wall-elevation.json). 사진 재질은 내장 image_gen 제작이며 특정 실제 건물의 스캔·복원이 아니다.
- **시작 화면·주변 4K 확대 이력:** 실제 기본 질문 영상의 첫 프레임을 시작 화면으로 쓰고, 영상과 같은 배경 혼합을 적용한다. 정합용 기준 사진은 별도로 보존한다. 처음 주변을 4K로 맞출 때는 정면 확장·벽·창문·천장·후벽·책상·바닥용 9개 JPG를 기존 픽셀의 긴 변 3840 확대본으로 만들었고 천장은 넓은 정면 사진을 사용했다. 이는 새 세부를 만드는 작업이 아니었다. [당시 원본·크기·해시·검증](interview/production/room-surfaces-4k.json)과 재현 도구 `tools/build-path-room-surfaces.mjs`는 보존한다.
- **현재 벽·창문·천장 재질:** 내장 imagegen으로 좌우 벽·후벽·천장 4개 이미지를 새로 생성했다. 창틀·블라인드·유리, 벽 패널의 미세 결·이음새, 천장 흡음판·등의 재질을 보강하고 영상 첫 프레임의 차분한 회색빛·노출을 기준으로 제작했다. 좌우 벽의 기존 배치와 물리 좌표를 유지하며 천장은 전용 사진을 고정 평면에 연결한다. 천장 파일 로드 실패 때만 이전 넓은 정면 사진으로 돌아간다. 현재 정적 텍스처는 10개다. 생성 결과를 긴 변 3840의 배포용 JPG로 정규화했으며 **네이티브 4K 생성이나 실제 촬영 세부의 복원이 아니다.** 정확한 생성 모델은 도구가 공개하지 않는다. [프롬프트·생성 크기·배포 크기·해시](interview/production/room-detail-generation.json). 기존 얼굴·필기 영상과 둘러보기 조작은 유지했고 별도 유료 API 호출은 0회다.
- **둘러보기와 입장:** PC는 화면 바깥의 고정 테두리를 남기고 30도 버튼·좌우 방향키 회전을 기본으로 제공한다. 정면 복귀와 선택형 저감도 드래그를 제공하며 드래그의 상하 각도를 제한하고 관성 회전을 사용하지 않는다. Quest는 실제 고개 움직임을 1:1로 추적하며, 첫 유효 양눈 중심 자세로 방의 초기 위치를 맞춘다. 이번 변경에서도 카메라 수치는 유지했다. 유효 자세가 나오기 전에는 방을 숨기고 정적 재질 업로드를 입장 전에 나눠 준비한다. 영상 텍스처와 셰이더도 질문 시작 전에 준비하며, 첫 영상 프레임이 준비되기 전까지 인물이 보이는 시작 화면을 유지한다. PC 둘러보기는 스크롤 없이 캔버스에 초점을 맞추고 닫으면 원래 초점으로 돌아간다. 이 구현만으로 멀미 감소나 실제 기기의 프레임 성능을 확인했다고 보고하지 않는다.
- **분위기와 연결:** 친근한 미소·맞장구 대신 차분한 평가 시선, 독립적인 문서 확인과 짧은 필기를 요청했다. 새 영상의 질문 종료·필기 종료 구간을 따로 검수해 질문 후에도 같은 인물의 경청을 이어 가며150ms로 전환한다. 새 원본의 모든 대사는 로컬 ASR로 확인했고 표본 동작·시작/끝 프레임을 검토했다. 미세한 얼굴·자세 변화는 남아 있어 완전히 감지되지 않는 연결이나 사람의 자연스러움 승인을 뜻하지 않는다.
- **음성:** ‘한국어 음성 준비’에서 Whisper Base q8 모델·런타임 약103MB를 준비한 뒤 별도의 ‘마이크 확인’으로 발화와 입력 음량을 확인한다. 실제로 인식된 말이 있어야 VR 진입이 열린다. 답변은30초/25초이며 인식된 말 뒤5.5초간 발화가 없고 답변 시작 후10초 이상이면 입력을 마감한다. 분기에 필요한 표현과 인식 근거가 충분한 답변은 자동 진행하고 애매한 구간만 확인·수정·다시 말하기를 요청하며, 확인 시간은 별도다. 높은 신뢰도만으로 정확성을 보장하거나 단어를 강제 치환하지 않는다. 무음·배경 소리만으로 답변을 가정하지 않는다. 컨트롤러의 답변 완료·일시정지·재질문·종료, 취소·탭 이탈 때 스트림 종료와 재시도 시 직전 인식 종료 대기를 유지한다. 이전 공개 `26baad2`의 Vosk·전체 인식문 확인 방식에서 갱신했다.
- **경청 반복과 자세 연결(10-12 추가 보정):** 기존 네 구간의 고정 순환을 바꾸어, 질문 뒤 조용한 응시를 먼저 두고 정상 답변마다 추가 필기는 최대 한 번만 배치한다. 첫 질문에서 이미 나온 필기 꼬리는 같은 답변 중 다시 쓰지 않으며, 두 답변에 걸쳐 마지막 필기 선택을 기억한다. 남은 답변 시간이 짧으면 긴 필기를 새로 시작하지 않는다. 중립 구간은 준비 영상의0.5초·경험 영상의0.75초부터 재생해 각각2.5초·2.25초를 사용한다. 고개가 돌아오는 앞부분을 제외한 것이며 원본 파일·얼굴·재생 속도를 바꾸지 않았다. 새 생성·재인코딩·역재생·보간·인물 합성은 없다. 조용한 두 장면은 반복될 수 있어 반복을 완전히 없앤 것은 아니다. [현재 실행 목록](interview/film/strict-manifest.json), [자세·필기 원본 분석](qa/interview-film/continuity-source-audit.json), [기존 무음 구간 편집 이력](interview/production/listening-tail-variants.json).

## 앞선 Seedance 짧은 면접 연결 · 2026-10-12 이력

사용자가 채택한 Seedance로 **첫 질문 → 답변 중 경청 → 답변에 따른 후속 질문 → 두 번째 답변**을 먼저 연결했다. 기존 안경 쓴 면접관의 필기를 기준으로, 친근한 미소·맞장구 대신 무표정한 평가, 짧은 메모·서류 확인·시선 복귀가 서로 다른 타이밍에 나타나도록 제작했다. 아래는 “일단 테스트용으로 짧게” 요청 당시의 범위이며, 이후 공간·음성 확장은 위 현재 상태를 따른다.

- **실제 영상 4개:** 같은 기준 이미지의 Seedance 2.5·480p·10초 요청으로 질문 1개, 경청 1개, 후속 질문 2개를 각각 생성했다. 실측 854×480·24fps·약10.04~10.08초이며 질문은 원본 음성, 경청은 무음이다. [당시 실행 목록](interview/production/strict-manifest-480p.json), [생성 기록](interview/production/strict-interview.json), [검증 기록](qa/interview-film/strict-verification.json). 사전 견적은 편당30·총 **120크레딧**이다. 공유 계정 잔액 변동134크레딧 전체를 이번 생성 비용으로 단정하지 않는다. 신규 구독·충전은 하지 않았다.
- **답변과 연결:** 질문 음성이 끝난 뒤의 검수 시점(첫 질문3.75초, 후속4.85/4.8초)에 입력과 마이크를 열고, 같은 영상의 경청 부분을 계속 보여 준다. 답변은20초·15초이며 일찍 완료할 수 있다. 경험 표현이면 직접 맡은 일·결과를, 그 외에는 현장 투입 전 준비 계획을 묻는 두 규칙 분기다. 빈 답변·재질문·음성 인식 실패는 임의 분기 없이 수정/다시 답변으로 돌린다. 자유대화 AI나 채용 평가가 아니다.
- **동작 연속성:** 완료를 누르면 마이크부터 닫고 진행 중인 필기가 끝나는 구간까지 기다린 뒤150ms 전환한다. 같은 인물·복장·구도와 시작/끝 자세를 표본 프레임으로 확인했지만 미세한 표정·질감 차이는 남아 있어 완전히 감지되지 않는 연결을 보장하지 않는다. 일시 정지·종료·화면 이탈은 마이크를 닫으며 답변과 음성을 서버에 전송하거나 저장하지 않는다.
- **현재 검증 범위:** 관련 Node58개(영상/세션30·VR/음성20·서버/패키지8) 통과. PC에서 두 후속 질문의 실제 재생, 답변 수정·일시 정지·재질문·종료를 확인했다. 최신 화면별 근거는 [검증 기록](qa/interview-film/strict-verification.json)에 이어 쓴다. 사람의 실제 마이크 발화와 Quest 실기기 착용·화질·편안함은 미확인이다.
- **VR 범위:** `rectilinear-mono`, `stereo:false` 원본을 WebXR의 정면 영상 패널로 보여 주고 음성 답변·컨트롤러 조작을 연결했다. 360 공간·VR180·입체 영상이 아니며, 공개 배포도 하지 않았다. 아래 기존3D 시제품은 이 영상 방식과 구분해 보존한다.

## 기존 3D 3인 면접실 · 2026-10-11 구현 기록

`/interview/`에 **요양기관 첫 지원 면접**의 실행 가능한 시제품을 추가했다. 사용자 요청은 3인 면접관·60~90초·Quest 단독 실행·답변에 따른 후속 질문이다. 사진 재질의 가상 사무실, 질감이 있는 3D 면접관 3명, 한국어 음성 입력과 2회 답변을 구현했다. **실사 영상 품질, Quest 실기기 성능·착용감, 현장 전문가의 면접 내용 검토는 미확인**이다. 특정 기관을 촬영·복제한 공간은 아니다.

- 남성 2명·여성 1명. 말하는 사람의 입 움직임, 서로 다른 눈 깜박임·호흡·시선·끄덕임·필기. 머리 위치를 보며 경청하고 화자 쪽으로 시선을 옮긴다. 눈동자 추적이나 정확한 음소 립싱크는 아니다.
- 3인 음색의 사전 생성 대사 14개, 각 인물 위치에서 재생하는 공간 음향. 일반 경험 분기의 음성 33.879초 + 답변 25초씩으로 약 84초. 일찍 답을 마치면 짧아지고 재질문·일시정지는 길이를 늘린다.
- 경험을 말하면 맡은 일, 경험이 없으면 준비할 일, 동기를 말하면 구체적인 행동을 묻는다. Vosk식 띄어쓰기·부정 경험·모름·무응답·다시 듣기를 구분한다. **준비된 질문을 키워드 규칙으로 선택하며 자유 대화 LLM은 호출하지 않는다.** 답변을 정확히 이해했다고 보장하지 않는다.
- 한국어 Vosk 모델 약 89.1MB를 첫 준비 때 받고 이 기기의 WASM worker에서 인식한다. 공개 모델만 캐시하며 음성·답변은 업로드하거나 저장하지 않는다. 종료·재시작 시 답변을 지운다. 글 입력 미리보기도 제공한다.
- WebXR 안에서 질문·인식문·완료/다시 듣기/일시정지/종료 판과 두 컨트롤러 선택을 제공한다. 헤드셋 숨김·VR 종료 시 진행과 마이크를 중단한다. 텍스트 연습 중에는 VR 진입을 막아 보이지 않는 입력창에 갇히지 않게 한다.
- 기존 캠퍼스와 SYNK ID 기록은 유지한다. 새 면접은 로그인·계정 저장과 연결하지 않는다. 유료 API 호출 0회.

### Quest 실행 패키지와 기기 연결 · 2026-10-12

```powershell
node tools/package-path-interview.mjs
node experiences/path-vr/server.mjs --port 4293
```

PC 미리보기와 새 패키지 기본 입구는 `http://127.0.0.1:4293/interview/film/rehearsal.html`이다. 생성된 `.tmp/path-interview-quest/`는 Node 서버 없이 제공할 수 있는 독립 정적 묶음이며, 루트 `index.html`도 실사 면접으로 연결한다. 기존3D 시제품은 `/interview/`에 보존했다. `_headers`, 실행 안내 `HOSTING.txt`, 자산·모델·음성·라이선스와 파일별 해시 `_package-manifest.json`을 포함한다. WAV 원본·검증 fixture·개인 설정·서버 원문은 제외한다.

**USB로 먼저 확인할 때:** Quest의 개발자 모드와 USB 디버깅을 준비하고 PC에 연결한 뒤 헤드셋에서 연결을 허용한다. Meta는 `adb reverse`로 PC 서버 포트를 기기의 `localhost`에 연결하는 방법을 공식 안내한다. 서버가 실행 중인 터미널은 열어 두고 아래 명령은 별도 PowerShell에서 실행한다. 기존 PC 서버4293을 그대로 사용하며 LAN 서버를 열지 않는다. [Meta 개발 테스트 안내](https://developers.meta.com/vr/documentation/web/browser-remote-debugging/).

```powershell
$questAdb = 'C:\Users\q1212\AppData\Local\Android\Sdk\platform-tools\adb.exe'
& $questAdb devices
& $questAdb reverse tcp:4293 tcp:4293
```

`devices`에 상태가 `device`인 Quest가 나타나면 Quest Browser에서 `http://localhost:4293/interview/film/rehearsal.html`을 연다. 음성 입력 준비와 마이크 권한 허용을 마친 뒤 VR로 진입한다. Whisper 모델·런타임 약103MB 첫 준비 시간은 면접 시간에 포함하지 않는다. 테스트를 끝내면 `& $questAdb reverse --remove tcp:4293`으로 이 포트 매핑만 해제한다. PC 서버·USB 연결이 유지되어야 하는 개발 경로이며 독립 호스팅은 아니다. 실행 경로를 준비할 당시 PC에서 ADB1.0.41 / Platform Tools37.0.1을 확인했고 연결된 기기는0대였으며 기기 설정이나 매핑은 실행하지 않았다. 이는 당시 연결 상태이며 현재 사용자의 기기 보유·사용 상태를 뜻하지 않는다.

WebXR과 마이크는 보안 컨텍스트에서 제공된다. USB 매핑의 `http://localhost`는 일반 LAN IP의 HTTP와 달리 신뢰 가능한 로컬 출처로 취급되는 경로다. [W3C WebXR](https://www.w3.org/TR/webxr/#dom-navigator-xr), [W3C 마이크 API](https://www.w3.org/TR/mediacapture-streams/#navigator-mediadevices), [W3C localhost 기준](https://www.w3.org/TR/secure-contexts/#is-origin-trustworthy), [Android 공식 localhost 포트 연결](https://developer.android.com/develop/ui/views/layout/webapps/access-local-server).

**USB 없이 제공할 때:** 생성 폴더 전체를 신뢰되는 인증서의 HTTPS 정적 사이트 **루트**에 배치한다. Whisper 모델·런타임 약103MB와 기존3D 시제품용 Vosk 약89MB를 제공할 수 있고 MP4·모델의 Range 요청을 지원하는 호스트를 사용한다. 두 음성 모델을 면접 시작 때 모두 내려받는 것은 아니다. `.wasm`은 `application/wasm`, `.onnx`는 `application/octet-stream`, 설정 JSON은 `application/json`으로 제공한다. `_headers`를 지원하지 않는 서버에는 같은 MIME·경로별 CSP·`microphone`/`xr-spatial-tracking` 권한 정책을 적용한다. `.tar.gz`에는 별도 `Content-Encoding: gzip`을 붙이지 않고, 누락 파일에 HTML을 반환하는 SPA 경로 대체를 두지 않는다. 게시 후 루트가 새 면접으로 이동하고 음성 준비·영상 부분 전송·VR 진입이 동작하는지 기기에서 확인한다. 이 절은 별도 호스트용 개발 안내이며, 현재 공개 서비스는 위 HTTPS 주소를 사용한다.

LAN 서버는 기기가 이미 신뢰하는 인증서를 사용할 때만 `--host 0.0.0.0 --tls-key <키> --tls-cert <인증서> --allowed-hosts <접속호스트>`로 제공한다. HTTP LAN 허용·브라우저 보안 해제·인증서 경고 무시는 적용하지 않는다. Quest 실물에서 사람 크기, 고개를 돌렸을 때 주변 공간, 영상 전환, 두 컨트롤러, 마이크 권한·발화 인식·긴 침묵, 프레임율과 편안함을 확인해야 한다.

기존3D 시제품의 검증 이력: 당시 Node38개, Chrome 화면·WebAudio 흐름27개, 독립 정적 패키지의 합성 마이크18개를 통과했다. 결과는 `qa/interview-flow/`, `qa/interview-microphone/verification.json`, `qa/interview-actors/`, `models/fixtures/verification.json`에 있다. 생성한5개 마이크 트랙은 종료 때 모두 ended였으며 외부 요청·브라우저 오류·누락 자산은0이었다. 이 합성 음성·데스크톱 결과를 실제 사용자 발화나 Quest 검증으로 간주하지 않는다. 최신 실사 면접 검증은 위의 현재 상태와 해당 QA 기록을 따른다.

출처·라이선스·한계: [`interview/credits.json`](interview/credits.json). 자산 재현 도구는 저장소 `tools/prepare-interview-{actors,audio,room,speech}.*`. 조사와 후속 직업체험/비자 설계는 [기존 설계](../../docs/SHIFT/VR직업체험_설계_v1.md#path-vr-mvp-20261011)에 이어 쓴다.

- 모바일/PC 화면에서 전 상황을 완료할 수 있다. WebGL 실패 시에도 장소 선택과 텍스트 연습은 유지된다.
- 지원되는 브라우저와 연결된 VR 기기에서는 실제 `isSessionSupported('immersive-vr')` → 사용자 클릭 → `requestSession` → Three `setSession`을 수행한다. VR 안에 질문·선택·도움·장소 이동·종료 판이 나타나고 두 컨트롤러의 광선 선택을 받는다. 종료·권한 거절·재입장·지연 응답 정리를 구현했다.
- SYNK 네이티브 클라이언트는 PC 3D 미리보기로 표시한다. 사용자가 누르면 `synkProduct.openInBrowser()`를 통해 이 PC의 VR 지원 브라우저로 연다.

Atlas를 새로 만든 것이 아니다. 여기서는 기존 Core 선택/표시 계약을 재사용한다. 직접 고르지 않은 오디오·움직임 설정이나 학습 능력·고정 성향을 선언하지 않는다. 선택 기록은 이 MVP의 관찰 사실이며 Trail 학습 평가, WORLD 학습 기록, 교사 과제와 연결하지 않는다. SYNK ID의 PATH 개인 기록 저장은 아래 별도 계약을 따른다.

## 실행

저장소 루트에서:

```powershell
node experiences/path-vr/server.mjs --port 4292
```

`http://127.0.0.1:4292/`에서 연다. 서버는 127.0.0.1에만 바인딩하며 명시적인 정적 파일 목록, 공통 계정 모듈과 공개 `/api/account-config`, `/api/health`를 제공한다. POST, 외부 Host, 원문 문서·시험·QA·개인 기록 경로는 제공하지 않는다. 외부 CDN·오디오·분석 전송은 없다. 유효한 계정 연결 설정이 있을 때만 지정된 SYNK 인증·개인 기록 API에 연결한다. `createServer({port:0})` 후 `await server.start()`를 사용하면 격리 시험이 가능하다.

## VR과 운영 범위

- **헤드셋 실기기 시험은 하지 않았다.** PC Chrome의 실제 렌더링/비지원 동작과 모의 XR 세션 수명만 검증했다. 기기별 화면 가독성·컨트롤러·편안함·프레임율은 후속 검증 대상이다.
- 기본 실행은 로컬 PC 전용이다. 독립형 헤드셋에는 위의 USB 개발 연결 또는 HTTPS 제공 경로와 기기 시험이 필요하다.
- 기존 캠퍼스는 컨트롤러로 선택하는 VR 구현이며 손 추적·시선 자동 선택·음성 인식은 없다. 새 면접실의 음성 입력 범위는 위와 같다. 기존 공간 이동은 장소 단위 즉시 이동이며 강제 자동 보행·소리는 없다.
- 로그인 전 기기 저장은 같은 브라우저를 공유하면 함께 보일 수 있다. 로그인 후에는 SYNK ID별 PATH 기록과 임시 저장을 분리한다. 운영 설정·배포, 실제 사용자 로그인과 기기 간 왕복, Windows/macOS 설치 패키지·모바일 앱 배포는 미검증이다.
- 같은 상황의 반복 성공을 실력 향상으로 계산하지 않는다. 최근 선택, 도움 여부, 반복 수와 미수행 항목만 표시한다. 실제 진로 적합성·한국어 등급·입학 및 취업 가능성은 판단하지 않는다.


## SYNK ID 개인 기록 연결 · 2026-10-06

공통 `product-account.mjs`·`document-sync.mjs`·`account-notebook.mjs`를 사용한다. 유효한 공개 계정 설정 또는 네이티브 SYNK 계정 연결이 있어야 로그인·서버 저장이 가능하며, 설정이 없으면 기존 기기 연습을 계속한다. 별도 계정을 만들거나 회사·학원 권한을 공유하지 않는다.

- `synk-personal`의 `resource=path`에 목적·시간·도움 방식·장소·커서·최근 60개 선택을 보관한다. 기존 `validateState`로 검사하며 문서는 64 KiB 이하다. 기기 저장 선택인 `consent`는 계정 문서에 넣지 않고 복원 시 기기 저장을 자동으로 켜지 않는다.
- 로그인 전 기록은 자동으로 올리지 않는다. **기기 기록을 계정으로 옮기기**에서 교체를 확인한 경우에만 옮긴다. 로그아웃·계정 전환은 원래 기기 기록을 보존하며, 다른 계정의 기록을 합치지 않는다.
- 저장 대기·오프라인·실패를 구분한다. 다른 기기의 revision과 충돌하면 계정 기록을 불러오거나 현재 화면으로 바꾸는 선택을 직접 한다. 저장 확인 응답은 현재 답·폼·장소를 다시 그리지 않는다. 다른 기기에서 바뀐 내용은 **다시 불러오기**로 확인한다.
- 운영 전환과 실제 사용자·실기기 검증은 아직 완료하지 않았다. 2026-10-07 리허설의 public OAuth client 18개 등록·포털 반영, care/personal 배포와 합성 공급자 왕복은 [공통 QA](../synk-account/qa/unified-account-20261006.md)에서 범위를 구분한다. 로컬 합성 브라우저와 실제 Electron 시작 검증을 운영 성공으로 표시하지 않는다.

계정에 보내지 못한 변경(`pending=true`)만 이 앱의 계정별 임시기록으로 기기에 보관한다. 저장 완료·다시 불러오기·로그아웃 때 완료 사본은 제거한다. 로그아웃 뒤에는 남은 기록의 존재만 알리고, 기록을 남긴 계정으로 로그인해야 **계정 임시기록 복구 파일 내보내기** 또는 확인을 거친 **이 기기의 계정 임시기록 지우기**를 쓸 수 있다. 현재 편집·전송 중에는 지우지 못하며 삭제 범위는 로그인한 계정의 이 앱 임시기록뿐이다. 계정 서버 자료·다른 계정·다른 앱·로그인 전 기기 기록은 그대로 둔다. 탭마다 수정할 수 없는 별도 초안 키로 보관하고 저장 응답은 해당 요청의 초안만 정리한다. 이전 초안은 하나여도 직접 골라 열며 선택하지 않은 기록은 보존한다. 소유 계정을 확인할 수 없는 손상 원문은 그대로 보존하고 이 화면에서는 내보내거나 지우지 않는다.

검증: `node --test tests/synk-personal-data.test.mjs`, `node experiences/synk-account/qa/personal-apps-smoke.cjs`, `node desktop/tools/personal-native-smoke.cjs`. 공통 계약 12개와 기존 모델·저장 회귀를 합한 46개가 통과했다. 합성 브라우저 결과·375/1440px 화면은 [공통 QA](../synk-account/qa/personal-apps-20261006/results.json), 실제 Electron 3앱 시작 결과는 [native 결과](../../desktop/artifacts/personal-native-20261006.json)에 있다.
