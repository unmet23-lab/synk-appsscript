# PATH 일터 체험 진행기 — 구현 설계

> 2026-11-21, Claude. 만들기 전 Fable 설계 검토용이다. 무엇을 왜 만드는지는 [PATH 일터 체험 설계](../../../../docs/PATH_일터체험_설계.md) 4절이 정했고, 이 글은 그것을 어떤 파일과 자료 구조로 만드는지를 정한다.
> 유호님 결정(2026-11-21): 계획서의 「서비스가 준비되어 있다」가 사실이 되게 발표 전까지 만든다. 그림은 Seedream 5.5, 영상은 Google Flow의 Omni 최신 판으로 만든다. Quest 실기 확인은 유호님이 하신다.

## 1. 목적과 끝난 모습

- 한국 일터에 가 볼 수 없는 유학생이 휴대폰이나 PC로 「요양보호사의 하루」을 처음부터 끝까지 하고, 점수 없는 「체험 기록 한 장」을 PDF로 받는다.
- 같은 주소를 Quest 브라우저로 열면 앉은 자리에서 같은 장면을 본다.
- 직업 하나는 장면표 자료 한 벌(`job.json`, 영상 목록, 그림, 영상)이다. 직업을 더할 때 코드를 고치지 않는다.
- 공개 주소는 `synk.im/path/workday/`(직업 고르기)와 `synk.im/path/workday/play.html?job=care-home`(체험)이다.

성공 기준: ① 휴대폰 390폭과 PC 1440폭에서 다섯 장면과 맺음을 끝내고 PDF를 받는다. ② 영상이 하나도 없어도(전송이 막혀도) 사진과 글로 끝까지 간다. ③ 둘째 직업을 자료만 더해 연다(코드 diff 0).

## 2. 사용자 흐름

```
직업 고르기(index.html)
  └ 요양보호사의 하루(play.html?job=care-home)
       준비: 보는 방식(화면 / Quest) · 말하는 방식(글 / 음성) · 자막(한국어 / 한국어+힌트 언어) · 장면 고르기
       장면 1 출근 → 2 아침 인계 → 3 아침 인사와 식사 → 4 오후 → 5 저녁 인계   (장면마다 2~3분, 따로 열 수 있다)
       맺음: 오늘 고른 것과 원칙 나란히 → 실제 조건 → 내 답(더 알아보겠다 / 아직 모르겠다 / 맞지 않는다)
       체험 기록 한 장: 이름과 준비 사다리를 본인이 적음 → 미리 보기 → PDF 받기
       다음 칸: 요양보호사 면접 연습(지금 면접실)
```

장면 안의 걸음(step)은 여섯 가지다.

| 걸음 | 화면에서 일어나는 일 | 학생이 하는 일 |
|---|---|---|
| `line` 인물의 말 | 인물 영상이 말한다. 아래에 한국어 자막, 켜 두면 힌트 언어 자막 | 듣는다. 「다시 듣기」를 누를 수 있다 |
| `say` 말하기 | 인물이 기다린다(경청 영상이 있으면 그것, 없으면 마지막 장면 그대로) | 갈림길이 있으면 먼저 행동을 고른다. 그다음 그 뜻을 한국어로 말하거나 쓴다. 「예시 문장」과 「힌트」를 열 수 있다 |
| `tour` 둘러보기 | 안내판에서 자리를 고르면 화면이 어두워졌다 밝아지고 그 자리에 있다 | 가리킬 곳(점)을 누르면 이름이 뜨고 소리로 듣는다. 「둘러보기 마치기」 |
| `note` 알림 글 | 선배의 말이나 일과표를 글 카드로 보인다(배설과 목욕 도움은 화면 없이 여기서만) | 읽고 넘긴다 |
| `move` 자리 옮기기 | 0.4초 어두워졌다 밝아진다. 가는 길은 보이지 않는다 | 없음 |
| `report` 보고 | 오늘 본 일의 목록이 뜬다(앞에서 고른 것에 따라 문장이 달라진다) | 보고할 일을 고르고 말하거나 쓴다 |
| `work` 일의 도구(상향판) | 업무 화면, 서류, 전화, 채팅을 장면표의 글로 그린 카드가 뜬다 | 보고 고른다. 동료가 고른 것에 사실대로 답한다. 맞고 틀림을 표시하지 않고 기록에는 다룬 도구만 적는다 |
| `relay` 모국어로 잇기(상향판) | 외국인 손님의 말이 학생이 고른 힌트 언어로 말풍선에 뜬다(고르지 않았으면 영어) | 그 말을 한국어로 동료에게 전한다(말하거나 쓴다) |
| `relay` `direction: out`(상향판) | 손님께 전할 한국어(선배의 답)가 말풍선에 뜬다. 예시는 학생이 고른 힌트 언어로 열린다 | 그 말을 모국어로 손님께 전한다. 소리 내어 말하고 「말로 전했어요」를 누르거나 어떤 글자로든 쓴다. 받아쓰지 않고, 기록에는 「모국어로 전한 것」으로 따로 적는다 |

- 대사 걸음에 `"channel": "phone"`을 적으면 자막이 전화 통화로, `"chat"`을 적으면 채팅 말풍선으로 보인다. 채팅 줄에는 영상이 없다. relay에도 `"channel": "phone"`을 적을 수 있다.
- 대사 걸음의 `clip`은 빼도 된다. 빼면 사진과 자막으로 돈다.
- 대사 걸음에 `foreign`(힌트 언어마다와 en)을 적으면 자막 본문이 학생이 고른 말로 보이고, `text`의 한국어는 그 아래 「뜻」으로 보인다. 이때 `hint`는 빼도 된다.
- 인물에 `names`(힌트 언어마다와 en)를 적으면 화면, 말풍선, Quest 안내판이 학생이 고른 말의 이름을 보인다. 도구 카드의 `rows` 값과 `lines` 줄도 같은 꼴의 객체로 적을 수 있다.
- 인물의 `language`(어느 학생에게나 한 언어로 말하는 사람), work 보기의 `retry`, 맺음 항목의 `hint`도 있다. 상향판 걸음의 꼴은 [상향판 기준](상향판_기준.md)에 있다.

- **갈림길은 누르기로 정하고, 말은 그 뜻을 직접 한다.** 음성 인식이 틀려도 고른 것이 바뀌지 않는다. 답은 한글 한 음절이나 두 글자 이상이면 받고 내용은 보지 않는다. 보기는 어느 쪽도 그럴 만한 까닭을 담아 쓴다(「힘들어 보이시니 제가 떠 드린다」). 좋은 말이 든 보기를 찾는 문제가 되지 않게 하려는 것이다.
- **답의 갈래는 넷이다.** 말로 답함, 글로 답함, 예시 문장을 고름, 기기가 알아듣지 못해 넘어감. 소리는 들렸는데 인식한 글이 없으면 「기기가 말을 알아듣지 못했어요」와 함께 다시 말하기와 「이대로 넘어가기」를 낸다. 넷째는 어디에도 세지 않는다.
- **도움은 세 가지.** 「다시 듣기」, 「예시 문장」(갈림길에서는 「이 선택의 말」), 「힌트」(고른 언어의 뜻풀이). 연 횟수만 기록에 적는다.
- **말 끝내기.** 주 단추가 「말하기」에서 「말 끝내기」로 바뀐다. 말소리 뒤 1.8초 조용하면 저절로 끝난다(음량만 본다. 인식한 글을 기다리지 않는다).
- **언제든 멈추기, 그만하기.** 장면 끝마다 쉬는 카드가 뜬다(다음 장면 / 여기까지). 앞 장면의 고름을 쓰는 장면은 그 장면을 마친 뒤에 열린다(`requires`).
- **Quest는 한 번에 10분 안쪽.** 장면을 시작하기 전에 센다. 헤드셋에 들어간 시간에 다음 장면의 예상 분을 더해 10분을 넘으면 그 장면을 헤드셋에서 열지 않고, 주 단추는 「헤드셋을 벗고 쉬어요」 하나다. 이 기기에서 헤드셋이 처음이면 한 장면 뒤에 내보낸다(`engine/comfort.mjs`의 `questScenePlan`).
- **이어 하기.** 진행과 고른 것은 이 창의 `sessionStorage`에만 둔다(`synk.path.workday.v2`). 같은 창의 새로 고침은 버티고 창을 닫으면 사라진다. 진행이 남아 있으면 시작 화면이 「이어서 하기」와 「처음부터 새로 하기」를 함께 낸다. 이름, 까닭, 소감, 준비 사다리는 저장하지 않는다. 기록을 받는 자리 옆에 「이 기기에서 지우기」가 있다. 기기에 남는 것은 「이 기기에서 헤드셋을 쓴 적이 있다」는 표시 하나다.

## 3. 자료 구조

### 3-1. 직업 목록 `workday/jobs/index.json`

```json
{ "schemaVersion": 1, "jobs": [
  { "id": "care-home", "status": "open", "title": "요양보호사의 하루", "role": "요양보호사",
    "minutes": 15, "scenes": 5, "poster": "care-home/places/office-senior.jpg", "posterAlt": "…",
    "summary": "어르신 두 분을 맡아 하루를 보내요." },
  { "id": "hotel-front", "status": "making", "title": "호텔 프런트의 하루", "role": "호텔 접수사무원", "summary": "…" }
] }
```

`status`는 `open`(열림)과 `making`(만드는 중) 둘이다. `making`은 카드만 보이고 들어가지 못한다. 카드의 제목, 직업, 분, 장면 수는 장면표와 같아야 한다(시험이 맞춘다).

### 3-2. 장면표 `workday/jobs/<id>/job.json`

실제 꼴은 `jobs/care-home/job.json`이 본보기다. 뼈대만 적는다.

- 갈림길 뒤의 걸음(`then`)은 그 보기 안에 적는다. 앞의 고름에 따라 달라지는 것은 `when`으로 가른다. `when`은 걸음과 보고 항목에 모두 쓸 수 있고, 값은 보기 id 하나나 여럿(`{"handover": ["ask", "confirm"]}`)이다. 맞지 않는 걸음은 없는 것으로 지나간다. 조건문은 이것 하나뿐이다.
- 다른 장면의 고름을 `when`으로 쓰는 장면은 그 장면을 `requires`에 적어야 한다(검증이 요구한다). 그래서 `when`이 가리키는 갈림길은 늘 고른 뒤다. 같은 id의 보고 항목들은 한 갈림길의 보기마다 꼭 하나씩 맞아야 한다.
- 장면마다 `minutes`(예상 분, 9 이하)를 적는다. Quest의 10분 셈에 쓴다.
- `live`는 그 자리 사진에서 사람이 있는 사각형(왼쪽, 위, 오른쪽, 아래, 0~1)이다. Quest 무대는 이 안만 영상으로 바꾸고 밖은 정지 사진을 둔다. 없으면 무대는 사진만 보인다.
- `line`의 `action: true`는 말이 아니라 눈앞에서 일어난 일이다(「다시 듣기」가 없다).
- 말하기의 `record`는 기록에 적을 차례 이름이다(「자기소개 차례」). 무엇을 말했다고 적지 않는다. 갈림길 보기에는 `record`가 없고 보기 글이 그대로 기록에 들어간다.
- 맺음의 갈림길마다 `say`(「이렇게 말해요」 한 문장)를 적는다. 무엇을 골랐든 보인다. 보기에 맞고 틀림 표시를 달지 않는다.
- 어긋나는 쪽을 골라도 막지 않는다. 인물의 반응이 달라지고, 맺음에서 원칙과 나란히 보인다. 화면에 「정답」, 「오답」, 점수를 쓰지 않는다.
- 문장은 모두 직접 쓴다. 표준교재의 문장과 그림을 옮기지 않는다. 쪽수 근거는 설계 문서 4-3에만 둔다.
- 불러올 때 `job-schema.mjs`가 검증한다(모르는 걸음 종류, 없는 자리와 인물, 빠진 힌트 언어, 점 좌표 범위, 갈림길 보기 2~3개, `when`과 `requires`의 짝, 같은 id 항목의 덮음, 맺음의 갈림길 목록, 학생이 읽는 모든 글의 금칙 낱말). 일터 용어에 금칙 낱말이 들어가면 그 용어를 `allowedTerms`에 통째로 적는다. 검증에 걸리면 그 직업을 열지 않고 까닭을 화면과 콘솔에 보인다.

### 3-3. 영상 목록 `workday/jobs/<id>/manifest.json`

면접실 재생기 `interview/film-player.mjs`의 목록 형식을 그대로 쓴다(평면 단안, `speaking`은 원본 소리, `listening`은 무음, 시작과 끝 중립 구간 검수, 버킷 주소와 `fallbackSrc`).

- 목록 전체의 `status`는 첫 영상을 검수한 뒤 `ready`로 두고, 영상마다 `status`와 `reviewed`로 가른다. 걸음은 제 영상이 준비됐을 때만 재생하고, 아니면 사진과 자막으로 진행한다. 그래서 영상이 만들어지는 만큼 열린다.
- 재생이 실패하면(시작 5초, 멈춤 5초를 넘기거나 브라우저가 막음) 그 회차는 사진과 자막으로 바꾸고 「영상 다시 받기」를 둔다. 재생기가 내는 글은 화면에 쓰지 않는다.
- `src`와 `fallbackSrc`는 직업 폴더 기준으로 적는다(`clips/senior-welcome.mp4`). 진행 제어가 절대 주소로 바꿔 재생기에 넘긴다. 로컬 서버와 공개 묶음은 `file` 칸이 가리키는 파일만 내보낸다.
- 영상마다 `answerStartSeconds`(말이 끝나는 때)를 적는다. 그때 다음 걸음이 열리고 같은 영상의 남은 부분이 이어진다.
- 영상마다 `still`(배경 고정을 잰 값: 사람 영역 밖의 평균 차이 `outside`, 전체 이동량 `shift`)을 적는다. `clipHoldsStill`을 넘지 못한 영상은 Quest 무대에 그리지 않고 소리만 들려준다.

### 3-4. 체험 기록

```
record = { job: {id, edition, title, role}, issuedAt, serial, view: "화면"|"Quest", speak: "음성"|"글"|"음성과 글",
  completed: { scenes: 5, of: 5, minutes: 11, replayedScenes: 1 },
  korean:    { voice: 5, text: 1, example: 1, unaided: 4, replays: 3, hints: 2, turns: ["자기소개 차례 · 말로 답함"] },
  choices:   [ { scene: "아침 인계", text: "모르는 말을 되묻는다", how: "말로 답함", reason: "(본인이 쓴 까닭)" }, … ],
  reflection:{ hard: "(본인이 쓴 글, 모국어 가능)", decision: "아직 모르겠다" },
  ladder:    [ { label: "TOPIK 급수와 성적 날짜", value: "…" } ],                 // 본인 입력, 증빙 없음
  name: "(본인이 적은 이름)", notice: [ … ] }
```

- 점수, 등급, 추천 문구, 적합 판정이 없다. 맨 아래에 「이 기록은 체험에서 일어난 일을 적은 것입니다. 한국어 실력이나 일하는 기술을 재지 않았고, 채용 여부를 판단하는 자료가 아닙니다」, 「본인이 자기 기기에서 만들었습니다. SYNK는 이 기록을 받거나 보관하지 않고, 고용주에게 보내지 않습니다」, 그리고 장면표의 `reviewNote`를 넣는다.
- **확인된 것만 적는다.** 갈림길은 누른 보기의 글과 답한 갈래(「모르는 말을 되묻는다 · 말로 답함」)를 적고, 「되물었다」처럼 말한 내용을 단정하지 않는다. 횟수는 일어난 대로 적는다(「말로 답한 것 5번 · 예시 문장으로 답한 것 1번」, 「힌트나 예시를 열지 않고 답한 것 4번」). 「몇 개 가운데 몇 개」로 적지 않는다. 기기가 알아듣지 못해 넘어간 차례는 적지 않는다. 상위 설계 4-4의 예시 줄(「7개 가운데 N개」)과 달라진 점이다.
- 음성은 기기 안 Whisper로만 글로 바꾸고 저장하지 않는다. 기록에 들어가는 글은 본인이 화면에서 본 글이다(고른 보기, 직접 쓴 까닭과 소감, 준비 사다리).
- 번호는 「기록 번호(본인 기기에서 만듦)」로 적는다. 기기에서 만든 날짜+무작위 값이고 SYNK가 내준 증명이 아니다. 설계 4-4의 「확인 주소」는 서버가 있어야 해서 이번에 넣지 않는다(남은 일).
- PDF는 서버 없이 만든다. A4 종이를 캔버스에 그리고 JPEG로 묶어 최소 PDF를 손으로 쓴다(외부 라이브러리 0). 여러 문자의 글꼴을 PDF에 넣을 수 없어 글자는 그림으로 들어간다. 보통은 한 장이고, 본인이 쓴 글이 길면 글자를 읽기 어렵게 줄이지 않고 둘째 장으로 잇는다. 「인쇄하기」는 화면의 종이를 인쇄하므로 글자를 복사할 수 있는 PDF가 된다. 휴대폰은 「보내기 · 저장하기」로 같은 파일을 기기의 공유 창에 넘긴다(본인이 보낼 곳을 고른다).

## 5. 화면

- **한 화면에 그림 한 장과 문장 하나**(참고 사이트 장부 5-2절: 토스, 당근). 준비 화면은 선배가 사무실 앞에서 맞이하는 그림이 화면을 채우고, 글과 단추는 그림 아래에 둔다. 얼굴 위에 글과 단추를 얹지 않는다.
- **체험 중**에는 자리 그림(16:9), 자막, 지금 할 일 하나만 남긴다. 주 단추는 한 화면에 하나(흰 알약)다. 갈림길 보기는 같은 크기의 판 두세 개다.
- **진행 표시**는 장면 다섯 칸과 맺음 한 칸이다(장부 5-2절 Duolingo의 「한 주를 칸으로」). 칸마다 위에 채운 막대가 있고 끝낸 칸은 초록으로 찬다. 줄어드는 막대와 깜빡임이 없다.
- **체험 기록**은 밝은 종이 한 장이다(장부 5-2절 「기록 · 증명은 종이 한 장으로」). 위에 직업과 판, 가운데 다섯 묶음, 아래 절취선과 기록 번호.
- **가리킬 곳**은 꽉 찬 작은 점 하나와 가는 선 이름표다. 고리, 구멍, 빽빽한 점 무늬를 쓰지 않는다. 낱개로는 이렇다. 점은 테두리 없이 그림자로 사진에서 띄운다. 고르기는 판의 채움색으로 보인다(속 빈 라디오 단추 없음). 보고 항목의 네모도 채운 네모다. 안내판 단추는 모두 채운 모양이다. 불러오는 표시로 도는 고리를 쓰지 않는다. `workday.css`에 `@keyframes`와 `animation`이 없다(시험이 본다).
- **움직임**: 자리 옮기기(0.4초 어두워졌다 밝아짐)와 인물 영상, 누를 때의 짧은 전환뿐이다. 저절로 움직이는 장식이 없다. `prefers-reduced-motion`이면 어두워지는 전환도 바로 바꾼다.
- 휴대폰은 3D 방을 만들지 않는다. PC는 「앉은 자리로 보기」를 누를 때만 Quest와 같은 무대를 창으로 연다(30도씩 끊어 돌기, 관성 없음).

## 6. Quest 무대

- 앉은 눈높이 1.18m. 앞 1.79m에 가로 2.82m의 평면(가로 시야 약 76도)에 자리 그림과 인물 영상을 올린다. 면접실 영상 평면과 같은 치수다.
- 둘레는 같은 그림을 흐리고 어둡게 한 색으로 채운다(앞은 또렷하고 둘레는 흐리다). 없는 벽을 지어내 붙이지 않는다. 고용주판에서 실제 360도 정지 사진이 오면 `place.surround`로 둘레를 바꾼다.
- 책상 위 안내판 하나에 자막, 힌트, 단추(갈림길 보기, 자리 고르기, 다음, 멈춤, 나가기)를 그린다. 고개를 따라다니는 글자가 없다.
- 자리 옮기기는 눈앞 전체가 0.4초 어두워졌다 밝아진다. 책상 안내판은 어두운 동안에도 보인다.
- Quest에서는 말로만 답한다(글 입력 없음). 음성 준비와 마이크 확인을 화면에서 마쳐야 입장 단추가 켜진다(면접실과 같다).
- 맺음과 체험 기록은 글을 읽는 화면이라 헤드셋 무대에 넣지 않는다. 열 장면이 더 없으면 「VR에서 나가 화면에서 맺음과 체험 기록을 봐요」로 내보낸다.
- 헤드셋 브라우저가 아니면 무대를 미리 짓지 않는다. 「VR 기기인지 확인」을 누른 뒤에만 확인한다(VR을 지원한다고 답하는 휴대폰에서 3D 무대를 괜히 짓지 않게).

`place-stage.mjs`가 맡는 일(면접실 무대를 통째로 바꿔 끼우므로 다시 지은 것): ① 장면이 쓸 자리 사진을 미리 받아 그래픽 장치에 올려 둔다(`preload`, `renderer.initTexture`). ② 자리 옮기기는 어두운 동안 다음 사진이 올라간 뒤에만 밝힌다. 1.5초를 넘기면 어두운 채 안내판이 「다음 자리를 준비하고 있어요」라고 알린다. ③ 고개 위치가 잡히기 전에는 무대를 숨긴다. ④ PC 창은 30도씩 끊어 돈다(`previewLookAfter`). ⑤ 인물 영상은 자리의 `live` 사각형 안에만 그리고 밖은 정지 사진을 둔다. 생성 영상의 배경이 조금 흐르더라도 눈앞 전체가 움직이지 않게 하려는 것이다.

멀미 규칙(설계 4-8의 아홉 가지)의 자리: 1·2·3·8은 `place-stage.mjs`와 영상 지시문, 4·9는 `place-stage.mjs`(위 ①~④), 5·7은 `hud.mjs`와 점 그리기, 6은 `comfort.mjs`의 `questScenePlan`. Quest 실기는 아직 확인하지 않았다. 유호님이 점검표로 보신다.

## 7. 그림과 영상을 만드는 길

- 자리 사진(사람 없음) 다섯 장을 Seedream 5.5로 먼저 굽는다. 인물이 있는 시작 그림은 그 사진을 참조로 넣어 같은 방에 인물을 세운다. 같은 인물은 인물 기준 그림 하나를 계속 참조로 넣는다.
- 영상은 Google Flow의 Omni 최신 판, 시작 그림 하나에서 10초 안쪽, 카메라 고정이다. 첫 컷 하나로 한국어 대사의 소리와 입 모양, 고정 틀을 확인한 뒤 묶음을 낸다. 안 되면 말 없는 영상에 목소리를 따로 얹는다.
- 받은 영상마다 대사 받아쓰기와 배경 고정(시작 그림과 첫, 끝, 사이 프레임의 사람 영역 밖 차이와 전체 이동량)을 재서 목록의 `still`에 적는다.
- 묶음을 내기 전에 Flow 잔액과 컷당 값을 읽어 예상 합계를 [제작 기록](제작기록.md)에 적고, 낸 뒤 쓴 양과 남은 양을 적는다.
- 「요양보호사의 하루」은 말하는 영상 21편, 경청 영상 7편까지다. 경청 영상이 없으면 마지막 장면을 그대로 두므로, 크레딧이 모자라면 말하는 영상을 먼저 낸다.
- 가리킬 점의 이름 소리는 12월 1일 판에서 따로 굽지 않는다. 이름은 늘 글로 보이고, 기기에 한국어 음성이 있으면 그 음성으로 읽는다. 장면표에 `audio`를 적으면 그 파일을 쓴다.

## 8. 시험 계획

- **순수 함수 시험(node --test, 18개)**: 장면표 검증(올바른 표 통과, 어긋난 표 스물여덟 가지 거절), 진행 상태 기계(모든 갈림길 조합으로 끝에 닿음, `when`과 `requires`, 도움 횟수와 새로 고침 뒤, 멈춤, 기기가 알아듣지 못한 차례), 체험 기록(금칙 낱말, 분수 표기와 단정 문장 없음), 기록 종이(보통은 한 장, 한도까지 쓰면 둘째 장, 글자 크기 아래 한도), PDF 바이트, Quest 10분 셈, 말 끝 알아채기, 둘째 직업의 가짜 장면표로 처음부터 기록까지(엔진과 화면 코드에 직업 낱말 없음).
- **자료 시험**: 열린 직업의 장면표가 검증을 통과하고, 직업 목록의 값과 같고, 가리키는 사진 파일이 있다. 로컬 서버가 장면표가 가리키는 파일만 내보내고 `production/`은 내보내지 않는다. 표준교재 문장 옮김을 막는 시험은 없고 검수에서 본다.
- **현지어 힌트**: 몽골어는 `tools/몽골어대조.js --구독`, 베트남어와 영어는 `tools/현지어대조.js`로 역번역 대조와 문법 채점을 받는다(검수 판정표의 현지어 절차). 시간이 모자라면 베트남어를 빼고 몽골어와 영어로 연다.
- **화면 시험(내장 브라우저)**: 1440과 390에서 처음부터 PDF까지, 넘침과 깨진 그림과 콘솔 오류와 실패 요청 0, 영상 없는 길, 글로 답하기, 이어 하기와 새로 하기, 「앉은 자리로 보기」.
- **기존 시험**: 면접실 시험 전체를 다시 돌려 그대로 통과하는지 본다.
- **확인하지 못하는 것**: 실제 Quest 착용과 헤드셋 마이크, 실제 휴대폰(iPhone Safari의 소리 있는 영상 시작, 메신저 앱 안 브라우저). Quest와 휴대폰은 유호님이 점검표로 보신다.

## 10. 정해 두는 것과 남기는 것

- 직업소개 등록 전의 선(설계 4-10): 화면과 기록에 추천, 적합, 검증, 취업 보장 낱말을 쓰지 않는다. SYNK로 보내는 단추가 없다.
- 남기는 일: 확인 주소(서버), SYNK ID 저장과 기기 사이 옮기기, WORLD 복습 묶음으로 보내기(어긋나는 쪽 예시는 뺀다), 고용주판, 현장 전문가 대본 검토, 실제 Quest와 휴대폰 확인, PATH 소개 쪽 입구, 가리킬 점 이름 소리 굽기.

## 11. 설계 검토 결과

설계 검토 Fable 24건(반영 23, 유호님 차례 1). 검토 답 원문은 `.tmp/workday-design-review/fable-설계검토-1.md`(git 밖)다.

| 번호 | 지적 | 처리 |
|---|---|---|
| D1 | Quest 「8분 넘으면 권한다」가 10분을 넘긴다 | 반영. 장면 시작 전에 세고 넘으면 열지 않는다. 처음 쓰는 날은 한 장면(2절, `comfort.mjs`, 시험) |
| D2 | 무대를 바꿔 끼우면 사진 미리 올리기가 빠진다 | 반영. `preload`, 올린 뒤에만 밝히기, 어두울 때 보이는 안내판(6절) |
| D3 | 목록은 준비됐는데 재생이 실패하는 길이 없다 | 반영. 실패하면 그 회차는 사진과 자막, 「영상 다시 받기」, 짧은 제한 시간(3-3) |
| D4 | 인식 실패가 「0개」로 적히고 분수로 읽힌다 | 반영. 답 갈래 넷, 횟수만 적기(2절, 3-4). 상위 4-4 예시 줄과 달라진 점은 유호님께 알린다 |
| D5 | 기기에 하나인 저장이 다음 사람 기록에 섞인다 | 반영. `sessionStorage`, 「처음부터 새로 하기」, 「이 기기에서 지우기」, 이름과 소감은 저장 안 함(2절) |
| D6 | `when`이 보고 항목에서만 돈다 | 반영. 걸음에도 허용, 여러 값, 덮음 검사, `requires`(3-2) |
| D7 | 3-2 예시가 실제와 다르고 `aligned`가 있다 | 반영. 3-2를 실제 꼴로 고치고 검증기에 꼴 방어를 넣음 |
| D8 | 영상 주소 기준과 허용 목록이 직업마다 코드를 고치게 한다 | 반영. 직업 폴더 기준 주소, 직업 목록을 따라가는 허용 목록(3-3, 4절). 올리기 도구는 공개 준비 때 고친다 |
| D9 | 공개 묶음이 면접실 바닥글을 통째로 바꾼다 | 반영 예정(공개 준비). `/path/` 입구는 남은 일 |
| D10 | VR 상태 글이 면접 말이다 | 반영. 상태 값마다 제 글을 내고 면접실 글은 쓰지 않음(4절) |
| D11 | 짧은 답이 15초 뒤에야 넘어간다 | 반영. 「말 끝내기」 주 단추, 음량만 보는 1.8초 판(2절, `comfort.mjs`). 실제 휴대폰 인식 시간은 점검표로 잰다 |

| D13 | 그림 PDF는 글자를 고를 수 없다 | 반영. 「인쇄하기」 안내, 휴대폰 「보내기 · 저장하기」(3-4) |
| D14 | 캔버스 글꼴이 섞인다 | 반영. 그리기 전에 글꼴 받기, 힌트는 기기 글꼴과 `lang`. 화면 조각을 따로 굽지 않고 통짜 조각을 쓴다 |
| D15 | 생성 영상의 배경이 흐르면 눈앞 전체가 움직인다 | 반영. `live` 사각형 안만 영상, `still`을 못 넘은 영상은 무대에 그리지 않음(3-2, 3-3, 6절). 점검표 첫 항목 |
| D16 | 기록이 말한 내용을 단정한다 | 반영. 보기 글과 답한 갈래만, 「기록 번호(본인 기기에서 만듦)」(3-4) |
| D17 | 현지어 절차와 전문가 검토가 빠졌다 | 현지어 절차는 반영(8절). 전문가 검토는 유호님 차례: 화면과 기록에 「검토 전」을 적고 섭외를 보고한다 |
