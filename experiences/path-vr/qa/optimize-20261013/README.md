# PATH 면접실 최적화 · 2026-10-13

유호님 「이 작업 전부 마치면 최적화도 진행해줘, 자율주행으로 최적화까지 마무리해줘」(10-12). 10-12에 공개한 시그널 디자인([기록](../signal-redesign-20261012/README.md)) 위에서 첫 화면 무게, 면접 시작까지 걸리는 시간, 시작 직후 메인 스레드 막힘을 줄였다. 면접 흐름·영상·음성 판정·카메라 수치·ID는 그대로다. 새 영상·음성 생성과 유료 크레딧은 0이다.

## 바꾼 것

- **글꼴 두 조각:** SUIT Variable 한 파일(610KB)을 면접실 원문 글자 645자 조각(131KB)과 나머지 2,288자 조각(509KB)으로 나눴다. 나머지 조각은 사용자가 입력하거나 말한 글자가 첫 조각에 없을 때만 받는다. OFL의 예약 이름(SUIT) 때문에 줄인 수정본의 글꼴 이름은 PATH Sans로 바꿨고, 저작권 고지(Sun)·라이선스 문구·주소는 그대로 둔다. 만드는 법은 `tools/build-path-fonts.py`(같은 입력이면 같은 바이트, CSS 두 범위도 함께 맞춘다). **면접실 글이나 `tools/package-path-interview.mjs`가 공개 묶음에 넣는 머리글·바닥글 문구를 바꾸면 이 도구를 다시 돌린다.** 안 돌리면 새 글자 때문에 첫 화면에서 나머지 조각을 받는다(글자는 그대로 PATH Sans로 나온다).
  - 나머지 조각의 CSS 범위에는 첫 조각 글자를 넣지 않는다. 넣으면 크롬이 첫 조각을 받는 동안 같은 글자를 나머지 조각에서도 찾아 첫 화면에 둘 다 받는다. 한글 음절 칸은 원본에 없는 드문 음절까지 이어 붙여 범위를 줄였다.
  - 첫 조각의 CSS 범위는 한글 음절 칸을 통째로 잡는다(`e9264a9`, 목록 3.5KB→0.2KB). 첫 조각에 없는 음절은 이미 받은 첫 조각에서 글자를 못 찾고 나머지 조각으로 넘어간다. 빠른 망·느린 망 모두 첫 화면은 첫 조각만 받고, 나머지 글자가 화면에 나오면 그때 나머지 조각을 받아 PATH Sans로 그리는 것을 확인했다(`font-split-check.mjs`).
  - 계기판 「60–90」의 줄표(–)는 SUIT에 없는 글자라 다른 글꼴로 그려지고 있었다. 같은 화면 아래 안내문과 같은 「60~90」으로 맞췄다.
  - 처음에는 첫 조각을 미리 받게(`preload`) 했으나 같은 조건 측정에서 CSS·시작 그림과 대역을 나눠 오히려 느려져 뺐다(`129f235`, 아래 표).
- **그림 크기:** 시작 그림을 화면 폭에 맞춰 1280/1920/4K 중에서 고른다(`srcset`). 머리글 로고는 폭 320px, 포스터 펠트 고글은 480px 사본을 쓰고 고글은 지연 로드한다(휴대폰에서는 포스터가 숨어 받지 않는다).
- **흐림 효과:** 영상 위 칩·자막·둘러보기 조작 단추의 `backdrop-filter`를 걷고 불투명에 가까운 면으로 바꿨다. 남은 흐림은 머리글 캡슐과 영상 위 덮개뿐이다.
- **면접 시작 때 3D 방:** 일반 화면(PC·휴대폰)은 면접 시작 때 3D 방(three.js 2MB + 4K 방 사진 10장 5.9MB, 큰 텍스처 업로드)을 더 이상 만들지 않는다. 이 단계가 영상 준비보다 앞에 있어 모두가 7.9MB를 받은 뒤에야 첫 질문이 나왔다.
  - Quest처럼 VR이 되는 기기는 페이지를 열 때 방을 만드는 기존 흐름 그대로이고, 면접 시작은 진행 중인 지원 확인·방 만들기가 끝나기를 기다린다(`prepareRoom({ onlyIfStarted: true })`).
  - 「방 둘러보기」를 면접 전에 열었으면 그 방을 그대로 쓴다. 면접 중에 처음 열면 면접을 먼저 일시정지한 뒤 방을 만든다. 이 면접실은 영상 시작·전환을 0.25초 단위로 검사하므로 4K 업로드가 영상 재생과 겹치지 않게 하기 위해서다. 「계속하기」로 이어 간다. 이미 만든 방은 면접 중에도 멈추지 않고 열린다.
- **화질 기본값:** 휴대폰 화면(세로 760px 이하, 가로 높이 500px 이하+터치), 데이터 절약, 2G/3G는 720p로 시작하고 나머지는 지금처럼 4K로 시작한다. 크롬의 속도 추정값(`downlink`)은 쓰지 않는다. 새 프로필에서는 측정 전 1.45Mbps 같은 고정 추정값을 보고해 빠른 PC도 720p로 떨어졌기 때문이다. 사용자가 고른 화질은 그대로 둔다.
