## 실제 브라우저

Codex 내장 Chromium, 로컬 `127.0.0.1:4273`. PC에서 크기를 바꾼 검증이며 실제 휴대폰은 아니다.

- 1280×720, 390×844, 320×668, 844×390: 첫 화면·메뉴·제목·시작 버튼·터치 버튼의 표시 확인. 320px에서 문서 가로 폭 320 / scrollWidth 320, 시작과 모드 버튼이 화면 안에 있음. 작은 화면 제목의 마지막 글자가 홀로 줄바꿈되던 부분을 교정. 가로844px에서 scrollWidth844, 시작 버튼하단320 / 시연 버튼하단343 / 화면높이390으로 잘림 없음.
- 키보드 좌우·점프·일시정지, 터치 우측 이동·점프·일시정지 확인. 점프 직후 실제 `y=.936`, 우측 레인 `lane=2`, `x=2.35`의 수행 상태를 읽었다.
- 문제 그림, 세 보기, 선택 레인 강조, 문제 통로의 실제 단어 간판, 정답 보호막/가속, 오답 피드백, 뒤에서 같은 어휘 재출제 확인.
- 직접 조작과 무입력 구간을 포함한 테스트 회차: 77.61초 / 1252.88m에서 충돌 종료, 한국어 5/8, 별 38개. 종료 화면·오답 복습·재시작·처음 화면·최고 기록 저장 확인. 새로고침 후 최고 1252m 유지. 테스트 기록이며 학생 성과가 아니다.
- 균형 / 경험 전환과 카메라 흔들림 감소 체크 확인.
- 한국어 OS 음성 발견 여부 확인. 없을 때 듣기 선택을 거절하고 안내, 있을 때 선택과 음성 실행 경로 제공. 최초 음성 목록이 비동기로 도착하여 첫 클릭에서 잘못 ‘없음’으로 안내할 수 있는 문제를 발견해 시작 시 목록을 준비하고 선택 시 최대1.6초 기다리도록 고쳤다. 직접 음질 청취는 미검증.

## 범위

### 2026-10-01 가운데 레인 입력 보완

- 사용자가 양쪽 끝만 갈 수 있고 가운데로 돌아오지 못한다고 보고했다. 브라우저의 단일 키 입력으로는 가운데 복귀가 가능했으므로 사용자의 실제 입력 환경에서 원인을 확정하지는 않았다.
- 기존 처리는 `repeat` 표시가 없는 중복 keydown을 모두 받아 두 칸 이동할 수 있었다. 눌린 키를 keyup까지 기억하여 한 번의 누름에 한 칸만 이동하게 수정했다. 화살표/A·D의 같은 방향 중복도 막고, 창 포커스를 잃거나 일시정지하면 상태를 초기화한다. 빠른 두 번의 정상적인 누름은 그대로 두 칸 이동한다.
- 핵심 7개 + 입력 회귀 4개, 총 11개 시험 통과. 양쪽 끝→가운데, 중복 keydown, 반복 입력, 키 별칭, 정상적인 연속 누름, 포커스 초기화를 검사했다.
- 실제 브라우저에서 `가운데→오른쪽→가운데→왼쪽→가운데`를 키보드로 수행했다. 오른쪽 복귀는 `lane=1,x=.0057`, 왼쪽 복귀는 `lane=1,x=-.0278`로 가운데 위치를 확인했다. `center-lane-fix.json`과 `center-lane-fix.jpg`에 저장했다.

1280×720에서 90초 자동 시연을 실제 브라우저에서 끝까지 재생했다. `elapsed=90.0109`, `reason=tour`, 1529.796m, 정답10/10, 별56, 아슬아슬 회피5, 보호3을 유지하고 완료 화면이 표시됐다. 최고 기록은 직접 테스트에서 만든1252m 그대로 유지되어 시연의1529m가 기록되지 않음을 확인했다. 시연은 정답 위치를 알고 자동으로 조작하며 실제 사람의 이해·학습 성과를 뜻하지 않는다.
