## 실제 브라우저

Codex 내장 Chromium. PC에서 뷰포트를 바꾼 검증으로 실제 휴대폰 시험은 아니다.

- 최신 화면의90초 자동 시연: `elapsed=90.0138`, `distance=1393.0391`, 부탁10/10, 수행한 표시선13개, 보호3회·바람막1회 유지, `reason=tour`. `v3-demo-result.json`과 `v3-demo-result.jpg`. 시연은 정답 동작을 미리 아는 자동 조작이며 한국어 학습 성과가 아니다. 시연 전후 테스트 최고455m를 유지해 기록 제외를 확인했다. 종료 시 미완료 부탁은 수행 수에 포함하지 않는다.
- 직접 테스트: 읽기 모드에서 시작 직후 왼쪽 키 입력 → 첫 부탁 `done`, 등불1 확인. 이후 입력하지 않은 부탁들은 미수행으로 남고 일반 충돌로 종료했다. 키보드 가운데 복귀와 점프 상승(`lane=1`, `y=.1405`), 모바일 버튼의 좌→가운데 복귀(`x=-.00005`)와 슬라이딩(`slide=.67`)을 확인. `v3-touch-state.json`, `v3-mobile-controls.jpg`. 이것은 조작 QA이며 학습자 평가가 아니다.
- 듣기 도전의 지시문이 ‘어떤 부탁을 들었나요?’로 가려지고 `voiceId=left`, `voiceClips=16`이 나타남. 듣기 도전 중 음소거하면 `learning=read`, 지시문 표시, 다시 듣기 숨김, 안내 토스트로 전환됨. 결과 복습의 다시 듣기로16음성을 준비하는 것도 확인.
- 일시정지/재개/처음 화면/재시작, 끝없는 바람길 선택과 타이머, 그래픽 균형↔경험·흔들림 감소 설정 확인. 자동 브라우저 제어의 키 누름1회는 도구 시간 초과로 실패했으며 이를 앱 입력 실패나 성공으로 집계하지 않았다.
- 1280×720,390×844,320×668,844×390 화면 확인. 320px의 scrollWidth320, 시작 버튼하단551.5/시연버튼하단578로 잘림 없음. 390px 결과창하단762.59/재시작694.59/처음734.59로844px 안에 있음. 가로 화면 결과는 요약/복습 두 열로 배치하고 행동 버튼을 유지했다. 뷰포트 임시 설정은 종료 전에 해제했다.
- 좁은 세로 화면에서 끝 레인의 몽글이 화면 밖으로 잘리던 것을 발견해 가로 시야를 확보하도록 카메라 FOV를 조정했다. 최신320px 화면 `v3-play-320.jpg`에서 왼쪽 몽글 전체·표시선·버튼을 확인했다.
- 결과의 첫 복습 버튼 자동 초점이 설명을 위로 밀던 문제는 재시작 버튼 초점 뒤 복습 스크롤을 초기화하도록 교정했다. 현재 결과에서 설명과 버튼을 확인했다. `v3-result-mobile.jpg`, `v3-result-landscape.jpg`.
- 최종 콘솔 오류/경고 없음. 관찰 중 통상60fps, 시작/크기 전환에는36~53fps도 보였다. 실기기·지속 성능 보장은 아니다.
