# 바람길 v6 · 풍경·찜·누적 여행 목표

2026-10-02 · 사용자 승인한 세 후속 작업과 「큰 불편은 없고 더 풍성했으면 좋겠어」를 반영했다. 속도·조작·상품 가격은 유지하고, 코스마다 실제 장식 물체와 다음 수집 목표를 추가했다. 로컬 구현이며 학생 학습 효과·실제 휴대폰 플레이·공개 배포의 증거와 구분한다.

## 구현

- `scenery-details.mjs`: 벚꽃 가지 터널·길가 꽃, 한옥 지붕의 눈·강가 눈더미·눈사람, 축제 등주·머리 위 등불줄. 기존 울타리·표지판·전차·표시선과 판정은 유지한다. 미리보기·구매·장착·실제 코스에서 같은 물체를 사용한다.
- `shop.mjs`: 갖고 싶은 구매 상품 하나를 찜하고 교체·해제할 수 있다. 해당 상품 구매 시 찜을 지운다. 찜에는 별을 쓰지 않는다. 기존 `synk.windrun.shop.v1` 지갑·소유·장착·정산 이력을 보존하고 새 찜/누적 진행을 추가한다. 과거 거리를 추정하거나 환영 별을 다시 지급하지 않는다.
- 누적 목표: 150m +10별, 수집 10별 +10별, 90초 여행 1회 완주 +15별, 1500m +15별, 수집 30별 +15별, 3회 완주 +20별. 각 목표를 한 번만 보상한다. 수집 목표에는 환영 별·완주·목표 보너스를 넣지 않는다. 시연은 진행·별·완주 수를 늘리지 않는다. 저장 실패 시 거래 전체를 롤백한다.
- `goals-ui.mjs`: 첫 화면에는 다음 누적 목표와 찜 상품의 부족한 별, 결과에는 이번에 달성한 목표와 다음 구매까지 남은 별을 표시한다. 달리는 화면에는 목표 글·지시문·보기·다시 듣기를 넣지 않는다. 실제 승인 펠트 부품과 기존 상품 아이콘을 사용한다.

**48개 시험 통과**: 기존 37개, 찜·v1 호환·누적 정산·저장 실패 등 8개, 풍경 물체/배치/버퍼 3개. 앱·상점 UI·여행 UI·월드·풍경·서버 문법과 공통 학습 번들 대조도 통과했다. Node의 기존 Three.js 패키지 형식 경고는 시험 실패와 구분한다.

신규 풍경은 인스턴스 메시 풀을 재사용하며 장식만의 메시 호출은 벚꽃 8·눈 9·축제 8개(그림자 패스 별도)다. 모든 실제 정점은 길 중심에서 좌우 4.1m 밖 또는 높이 5.4m 이상에 있다. 1,200회 테마 변경·장거리 재배치에서도 버퍼와 객체 수가 늘지 않는 것을 검사했다. 균형·동작 감소에서 장식 수를 줄인다. PC 브라우저 390×844 균형 그래픽의 벚꽃 시연에서 관측한 FPS 표시는 59~61이었다. 이는 측정한 순간의 로컬 PC 값이며 휴대폰·최저 성능·평균 프레임 보증이 아니다.

[v6-http.json](v6-http.json): 로컬 QA 서버에서 모듈·이미지·음성·폰트·vendor 등 96개 파일의 HTTP 200과 현재 파일 바이트 일치. 전달 ZIP의 CRC/바이트 확인은 [v6-package.json](v6-package.json)에 별도로 남긴다.

## 실제 브라우저 확인

기존 사용자 출처 `127.0.0.1:4273`의 기록을 보존하고 별도 QA 출처 `127.0.0.1:4274`에서 테스트했다. 폰 화면 크기는 PC in-app browser의 viewport 검사다.

- 3개 풍경을 UI로 미리 보고 찜 선택·교체, 재접속 유지, 첫 화면의 상품별 상점 이동을 확인했다. 미리보기와 찜 선택은 지갑을 바꾸지 않았다.
- 직접 UI 입력: 키보드 왼쪽→가운데 `0→1`, 화면 버튼 오른쪽→가운데 `2→1`, 점프 높이 1.48m, 착지 뒤 슬라이딩 잔여 0.69초, 일시정지에서 시간·모델 고정을 확인했다. 입력 확인용 실행이며 사람이 한국어를 듣고 완주한 증거는 아니다.
- 직접 달리다 홈 복귀: 546.07m·수집 12별, 첫 거리/수집 목표 보너스 20별 → 60에서 **92별**. 새로고침 뒤 유지했다. 벚꽃길을 찜한 뒤 UI 구매 80별 → **12별**, 소유·장착 추가 및 찜 해제를 확인했다. [v6-ui-checks.json](v6-ui-checks.json).
- 벚꽃길 실제 90초 자동 시연: 90.0101초·1392m·부탁10/10·표시선13·보호3. 시연 전후 상점 기록 전체가 같아 별·목표·완주 수가 증가하지 않았다. [v6-demo-complete.json](v6-demo-complete.json). 시연은 동작과 정답을 미리 알고 움직인다.
- 여러 목표 달성 안내는 **QA 전용 누적 값(1490m·수집29별)**을 준비한 뒤 직접 실행으로 확인했다. 종료 시 18별 수집 + 두 목표30별 =48별, 결과에 목표 두 개와 찜의 부족한 별을 표시했다. 결과→상점→닫기→홈 왕복 후 같은 기록으로 중복 지급이 없었다. [v6-multi-goal-fixture.json](v6-multi-goal-fixture.json). 이 값은 실제 플레이 누적이나 사람의 구매 속도 자료가 아니다. 시험 후 QA 지갑/누적 값을 복구하고 임시 탭을 닫았다.
- 1280×720·390×844·320×668·844×390에서 상점과 결과를 확인했다. 작은 화면에서도 구매/찜 단추, 복습 스크롤, 재시작·홈·상점 이동을 사용할 수 있다. PC 첫 화면에서 목표와 찜을 함께 볼 수 있게 여백을 줄였고 휴대폰 첫 화면의 글 배경을 밝게 했다. 추가 기록은 첫 화면 내부 스크롤로 확인한다.
- IAB가 실제 `Input.dispatchTouchEvent`를 지원하지 않아 스와이프는 테스트용 PointerEvent로 `0→1` 연결만 확인했다. 활성 포인터가 없는 인공 이벤트 때문에 `setPointerCapture` 오류 2개가 시험 로그에 남았다. 실제 손가락 입력·포인터 캡처 검증으로 보고하지 않는다. 정상 UI와 최종 사용자 탭 오류/경고는 0개다.

## 재화와 남은 실제 기기 확인

[v6-balance.json](v6-balance.json)은 3개 코드 전략×10시드×3회 = **90회 엔진 시뮬레이션**이다. 꽃잎 자취 구매 뒤 25별에서 참새70별을 목표로 비교했다. 무조작 전략은 v6에서 2~3회에 도달했고, 같은 수집량에서 목표 보상을 뺀 v5 계산은 10시드 중 7개가 3회 안에 도달하지 못했다. 일반 장애물을 완벽히 피하는 나머지 두 전략은 1회에 도달했다. 한국어 청취·사람 반응·입력 지연·Atlas 순서·실기기 프레임은 시뮬레이션하지 않았다. 초보자 평균·학습 효과·구매 의욕 근거로 사용하지 않는다. 결과를 이유로 가격·속도를 임의 변경하지 않았다.

실제 휴대폰은 연결되지 않아 직접 청취·스와이프·기기 회전·복합 장식 성능을 확인하지 못했다. 기본 서버는 loopback을 유지하며, 같은 Wi-Fi에서 직접 열 수 있는 선택 옵션 `--lan`과 [MOBILE-CHECK.md](MOBILE-CHECK.md)를 준비했다. 방화벽 설정이나 공개 배포는 변경하지 않았다. TOPIK 연결은 기존 짧은 한국어 지시 듣기(방향·동작·부정·순서) 보조 연습으로 유지한다.
