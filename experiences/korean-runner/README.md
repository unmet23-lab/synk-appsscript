# 바람길 · SYNK LAB PLAY

2026-10-07 · v7 LAB PLAY 키트 판(로컬 구현). 바람이 들려주는 짧은 한국어 부탁(방향·동작·하지 말라는 말·두 동작의 순서)을 듣고 **세 칸 길에서 90초 동안 몸으로 따라 하는** 듣기 액션 게임이다. 말 랠리·이야기 교실·말의 리듬과 같은 SYNK LAB PLAY 키트(`kit/`)로 입구·게임 바·멈춤·결과·코인 줄을 그리고, 3D 길과 마을은 실제 펠트 사진을 곱한 펠트 풍경으로 다시 만들었다(유호님 「니 방식대로 싹다 리디자인 및 재설계 해도 좋으니까 제대로 부탁해」).

공통 목표: [TOPIK I 1~2급 준비](../../docs/미니게임_TOPIK_I_학습기준.md). 바람길은 짧은 지시의 방향·동작·부정·순서 이해를 듣기로 연습한다. 장면·조작·타이밍이 수행에 영향을 주므로 성공 수와 별을 공식 급수·합격 판정으로 쓰지 않는다.

## 한 판

- **90초 한 판.** 바람이 부탁하면 표시선(크림 펠트 줄과 등불 문)을 지나기 전에 그대로 움직인다. 왼쪽·오른쪽으로 한 칸씩 옮기기, 점프(울타리), 숙이기(표지판), ‘하지 말라’면 그대로 달리기, 두 동작이면 27m 떨어진 두 표시선에서 차례로.
- **듣기 전용.** 달리는 중에는 부탁의 글을 보이지 않는다. 바람의 말 카드에는 ‘바람’ 꼬리표와 듣는 중 점 셋(밝기만 바뀜), 표시선까지 남은 거리 줄만 있다. 꼭 필요하면 **‘글로 보기’**를 눌러 그 부탁만 글로 보고, 이는 Atlas에 도움(`help: text`)으로 남는다. 다음 부탁은 다시 글 없이 시작한다.
- **해냄:** 카드에 펠트 체크 배지와 ‘좋아요!’, 몽글 머리 위 점수 글자와 펠트 반짝이, 그 표시선의 등불이 켜진다. **놓침:** 카드가 ‘이렇게 부탁했어요’ 종이 쪽지로 바뀌어 부탁의 글과 해야 했던 동작(또는 ‘동작은 맞았어요. 표시선 가까이에서 해 봐요’)을 보여 준다. 빨간 X·실패음은 없다. 놓친 부탁은 판 뒤쪽에 다시 나온다.
- **보호 셋 · 바람막.** 위 막대 ‘보호’ 알약의 코랄 펠트 구슬 셋(잃으면 크림 구슬). 부탁 사이의 일반 장애물(울타리·표지판·전차)에 부딪히면 하나를 잃고, 다 잃으면 90초 전에 멈춘다. 부탁 셋을 연속으로 해내면 바람막이 한 번 막아 준다(알약에 반짝이). 부딪혀도 카메라는 흔들리지 않고, 장애물이 작아지며 비켜 주고 몽글이 잠깐 옅어진다(깜빡임 없음).
- **조작:** 휴대폰은 아래 코랄 펠트 받침의 크림 펠트 단추 넷(왼쪽·점프·숙이기·오른쪽, 누르면 3px 내려앉음)이나 화면 밀기, 컴퓨터는 ←/A, →/D, ↑/W/Space, ↓/S. 양쪽 끝에서 반대쪽을 한 번 누르면 가운데로 돌아온다. Esc·⏸ 멈춤, 창이 가려지거나 포커스를 잃어도 멈춘다(시간과 목소리를 함께 멈추고, 이어 하면 같은 곳부터 듣는다).
- **목소리가 없으면 달리지 않는다.** MP3 16개를 모두 준비하지 못하거나 재생할 수 없으면 ‘목소리를 준비하지 못했어요’ 창을 띄우고 멈춘다. 읽기·OS TTS로 바꾸지 않는다. 소리를 끄면 달리기도 멈추고, ‘소리 켜고 이어 하기’로 돌아온다.
- 별 줍기·바람상점·여행 목표·자동 시연(먼저 구경하기)·끝없는 바람길·소리·동작 익히기 창·그래픽 설정은 이 판의 화면에 없다. `core.mjs`의 끝없는 길과 시연 운전(`driveDemo`)은 판정 시험이 그대로 쓴다.

## 보상은 공통 코인 하나

90초를 끝까지 달린 판에만 결과 화면에서 공통 코인을 받는다(`collection.js`, game id `runner`, 다른 게임과 같은 규칙: 완주 15 + 해낸 비율 × 10, 하루 10판). 그만두거나 보호를 다 써서 멈춘 판은 받지 않는다(「한 판을 끝까지 마치면 공통 코인이 모여요.」). 코인은 학습 기록에 쓰지 않는다.

예전 바람상점·찜·여행 목표(별 지갑)는 열지도 읽지도 않는다. 이 브라우저에 남은 `synk.windrun.shop.v1` 기록은 지우지 않고 그대로 둔다. 최고 거리 `synk.windrun.best`는 계속 쓴다. 등불은 화폐가 아니라 해낸 표시선에서 켜지는 장면 속 보상이다.

## 펠트 풍경(world.mjs · scenery.mjs)

- 크림 펠트 땅, 모래빛 펠트 길(칸 사이 크림 점선), 코랄 펠트 연석. 펠트 결은 `kit/felt/tex-cream.webp`·`tex-coral.webp`(코랄은 키트 머리 면처럼 같은 색을 옅게 덮음)를 곱하고 오프셋을 옮겨 흐르게 한다. 먼 곳은 판 뒤 크림 펠트 벽 색 안개(`FOG_COLOR`)로 녹는다.
- 길가: 펠트 덤불·꽃, 둥근 잎 나무(풀빛·꽃빛), 크림 벽에 라피스·코랄·풀빛·버터 지붕의 집(꽃집·책방·빵집·찻집 간판), 먼 펠트 언덕. 여덟 칸(200m)을 칸마다 한 덩어리(정점 색 × 크림 펠트 결 재질 하나)로 묶어 그린다.
- 지나가는 것: 버터 펠트 울타리(점프), 라피스 표지판(숙이기), 풀빛 전차(옆으로 피하기), 표시선의 크림 줄과 높은 등불 문(해내면 등불이 켜짐). 부탁이 아닌 장애물에만 할 일 배지(↑·↓)를 단다. 방향 부탁의 표시선은 세 칸이 같아 답을 드러내지 않는다.
- 몽글: 팔 없는 종 모양·물결 밑단(이전 바람길 형상), 코랄 펠트 결 + 크림 밑단 + 검은 구슬 눈. **움직임은 게임에 필요한 것만:** 옆 길로 옮기기·뛰기·숙이기. 출렁임·흔들림·찌그러뜨림을 더하지 않았고, 카메라는 화면 크기가 바뀔 때만 자리를 잡고 흔들거나 따라가지 않는다(유호님 멀미).
- 빛은 부드러운 하늘빛 + 왼쪽 옆 햇빛 하나, 거칠기 1(반들거림 없음), 부드러운 그림자. 세로 화면은 길 세 칸이 폭에 들게 카메라가 물러나고, 몽글은 화면 아래쪽(약 79%)에 오게 화면 창만 옮긴다.

## 별도 듣기 확인과 교사 목표 (2026-10-02, 새 확인 문장 2026-10-03)

입구의 ‘듣기 확인 3문제’나 결과의 ‘듣기 확인’으로 연다. 움직이는 코스와 장애물 없이 MP3를 끝까지 듣고, 들은 행동을 보기에서 고른다. 지시문은 답한 뒤 공개한다. 실행 중에는 OS TTS를 쓰지 않고 미리 만든 MP3만 재생한다.

- 확인 문장 12개는 달리기에서 나오지 않는 새 문장이다. 세부 4개, 부정 4개, 순서 4개(순서는 난도 2). 정답 자리는 첫째·둘째·셋째 보기에 고루 나뉜다. 음성은 달리기와 같은 Windows 음성(Microsoft Heami Desktop)이고 `assets/voice/jobs.json` → `scripts/build-voice.ps1` → `scripts/build-voice-manifest.py`로 만든다. 열두 개 모두 로컬 Whisper로 받아 적어 문장과 일치함을 확인했다. 사람의 직접 청취 검수는 아직이다.
- 각 확인은 자기 계열 `korean-runner.listening-check.<id>.v1`을 가져 달린 뒤 푼 첫 응답도 독립 근거다. 문장의 TOPIK I 문형(`CHECK_GRAMMAR`)을 conceptIds로 남기고 시험이 Strata `grammarIn`과 같게 지킨다.
- `coach.assignment()`가 있으면(WORLD 안) 서버가 정한 영역·난도·응답 형식·문항/계열 목록 안에서만 최대 3개(또는 `requiredAttempts`)를 고른다. 자유 연습은 Core 추천과 노출 기록으로 고른다.
- 끝까지 듣기 전에는 답을 막는다. 끝까지 들은 뒤의 재생만 재청취(도움)로 남기고, 그 재생이 끊겨도 답은 열려 있다. 불러오기에 실패한 뒤의 첫 재생은 첫 청취다. 들은 뒤 닫으면 ‘응답 없음’, 소리가 끊기면 다시 들은 뒤 답한다. WORLD 확인 도구가 쓰는 요소 이름(`#listening-check`·`#listening-check-dialog`·`#check-choices button`·`#check-replay`·`#check-next`·`#check-status`·`#check-feedback`·`#sound`)은 그대로 두었다.

### 오답을 확인하고 다른 문장으로 이어가기 · 2026-10-07 로컬 구현

답한 뒤에는 원문·고른 행동·맞는 행동과 기존 문항 해설을 함께 보여 준다. 오답일 때는 실제 고른 보기의 차이(반대 방향, 하지 않아도 되는 동작, 반대 순서, 빠진 두 번째 동작 등)를 짧게 짚는다. 학생이 왜 그렇게 생각했는지 추측하지 않는다. 설명은 자동으로 접히지 않고 ‘다음 지시 듣기’를 누를 때까지 남는다.

답한 뒤 ‘다시 듣기’는 해설을 보며 복습하는 기능이다. 첫 답의 판정·독립 수행 자격·점수를 바꾸지 않고 추가 응답·도움·전달 이벤트도 기록하지 않는다. 답하기 전 다시 듣기는 기존처럼 도움으로 구분한다. 답변 기록에는 문항별 기계 ID 두 개(`choice.selectedId`·`choice.correctId`)만 선택 정보로 남기며 자유 입력이나 학생 식별 정보는 넣지 않는다. 전에 화면에 나오기만 했던 문항도 새 문항으로 표시하지 않는다. 실제 첫 평가 응답의 독립 자격은 기존 Core 규칙이 판단하며, 화면 노출 표시로 그 규칙을 바꾸지 않는다.

확인판을 열 때 3문항 전부를 정하지 않고, 답한 뒤 다음 단추를 누르면 기존 Core로 다음 문항을 고른다. 오답 또는 도움 받은 정답 뒤에는 같은 영역·난도·응답 형식의 다른 미노출 문항을 우선한다. WORLD 안에서는 지정된 정확한 문항·계열 목록과 최대 총수를 지킨다. 같은 목표의 새 문항이 없으면 남은 연습 또는 지정 문항을 이어간다고 안내하고, 이미 만난 문항은 복습으로 표시한다. 과거 노출을 확인하지 못하면 새 문항이라고 표시하지 않는다. 문항을 생성하거나 같은 문항의 복습을 새 독립 정답으로 바꾸지 않는다. 현재 보유 문항은 12개 그대로이며 학습효과나 TOPIK 급수를 입증한 것은 아니다.

의도적으로 고른 같은 목표의 새 후속 문항에 답하면, 직전 오답·도움 받은 답과 이번 답의 실제 기록 ID를 `coach.recheck()`로 확인해 결과줄을 붙인다. 도움 없는 정답·오답, 도움 받은 정답·오답, 기록 부족을 구분하는 이번 회차의 사실이며 교정의 효과나 학습효과를 입증하지 않는다. 일반 정답 뒤의 다음 문항에는 이 쌍을 재사용하지 않고 확인판을 닫으면 연결을 버린다. API가 없거나 읽기를 거절하면 줄을 숨기고 원래 판정은 유지한다.

이 변경은 별도 듣기 확인판에 적용된다. 90초 달리기의 동작 카드·타이밍·복습 큐는 유지한다. 무료 Node 검증은 `node --test experiences/korean-runner/listening-check.test.mjs experiences/korean-runner/listening-feedback.test.mjs experiences/korean-runner/listening-recheck.test.mjs`이며, 실제 화면·소리·휴대폰에서 설명을 읽기 충분한지는 별도 브라우저 확인 대상이다.

`listening-check.mjs`/`listening-check-ui.mjs`가 별도 이해 확인을 담당한다. 기존 Atlas 학습 API의 재사용이며 별도 판단 엔진이 아니다. 공식 TOPIK 채점·학생 학습효과 입증은 아니다.

## Atlas의 다음 부탁 선택

`learning.mjs`는 16개 부탁을 듣기 세부 정보·부정·행동 순서와 `action` 응답 형식에 연결한다. `RunnerModel`이 지시를 만들 때 공통 `SynkLearning.recommend`의 선택을 쓰고, 덜 만난 표현을 우선한다. 입구·결과에 그 이유를 보여 준다.

장애물을 보고도 행동할 수 있고 타이밍이 결과에 영향을 주므로 **부탁 성공·실패는 모두 언어 평가 불가로 저장**한다. 음성 완료는 실제 재생 종료 이벤트로 기록하고, 글로 보기는 도움으로 남기며, 끝나기 전에 그만두거나 시간이 끝난 부탁은 ‘응답 없음’으로 닫는다. 결과의 ‘듣기 능력 기록’ 세 줄(방향·동작 듣기 / 하지 말라는 말 / 두 동작의 순서)은 이번 달리기의 해낸 수와 함께, 공통 기록 가운데 **듣기 확인(보기 하나 고르기) 응답만** 읽어 상태를 보여 준다(`report.mjs`). 다른 게임의 O/X·객관식 정오답을 바람길 능력으로 옮기지 않는다.

‘이 브라우저의 모든 게임 학습 기록 지우기’는 같은 출처의 공통 기록을 지운다(최고 거리는 남는다). WORLD 안에서는 계정 기록이라 이 단추를 숨기고 WORLD 계정 설정을 안내한다. `atlas-learning.js`는 공통 원본에서 생성한 번들이다(`node tools/build-game-learning.js`, 직접 고치지 않는다).

## 나에게 맞춘 바람 · Atlas 순간 맞춤 (2026-10-03)

달리기 속도만 그 사람에 맞춘다(`learning.mjs`의 `FLOW_RUN`, Core `flow.js`). 처음 속도(11·12·**13**·14·15)와 갈수록 빨라지는 정도(0·0.025·0.04·**0.055**·0.07), 굵은 값이 원래 게임이다. 최고 속도 19에서도 지시 음성이 첫 동작 전에 끝난다. 놓치면 느긋해지고(“바람이 조금 느긋해져요.” 안내), 연달아 해내면 한 칸씩 빨라진다. 「피곤해요」를 고른 날은 판 안 가속을 0으로 둔다. 이 관측은 속도에만 쓰고 언어 기록으로 쓰지 않는다.

## 목소리와 소리

16개 로컬 MP3(Windows `System.Speech`의 Microsoft Heami Desktop, rate 0)를 시작 단추 뒤 Web Audio로 준비하고, 말하는 동안 배경 가락을 낮춘다. 원고 `instructions.mjs`, 생성 작업 `assets/voice/jobs.json`, 길이·해시 `assets/voice/manifest.json`, 안내 시점 `voice-timing.mjs`. WAV 원본은 로컬 보존용이고 공개 묶음에서 빠진다. 효과음과 배경 가락은 그 자리에서 합성하며 사운드킷 규칙(사인·트라이앵글, 400ms 이하, C 펜타토닉, 실패음 없음)을 따른다. 음질 직접 청취·학생 검수는 별도다.

## 실행

정적 서버로 이 폴더를 열면 된다. 저장소에서 `node experiences/korean-runner/server.mjs` → <http://127.0.0.1:4273/>(`--lan`이면 같은 Wi-Fi 휴대폰 주소도 찍는다, 포트는 `SYNK_RUNNER_PORT`). Node.js만 필요하고 외부 CDN 호출은 없다. `file://`는 ES 모듈 제약으로 지원하지 않는다. 공통 코인·학습 기록은 브라우저 저장소를 쓰므로 출처(주소·포트)가 다르면 따로 남는다.
