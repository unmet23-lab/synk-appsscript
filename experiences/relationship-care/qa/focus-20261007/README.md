## 자동 시험

[최종 출력](tests-final.txt): **179/179 통과**, 실패·취소·건너뜀 0. V3에는 다음 챙김 날 이전의 일반 안부 보류와 명시 일정 유지 회귀를 추가했다. [변경 목록](scoped-build.json)은 비교 기준과 후보의 변경 파일 5개·유지 파일 35개를 기록한다. 이 목록은 공개 반영 증거가 아니다. [합성 수첩](synthetic-backup.json)은 브라우저 확인용 자료이며 실제 사용자 기록이 아니다.

계정 화면 시험은 실제 `document-sync` 전환을 포함해 **15/15**이며 위 전체 179개에 포함한다. 받은 수첩의 `revision: 0`과 직접 선택한 유효 미저장 초안, 첫 조회 실패·재시도, 저장 중 재수정, 손상 캐시·저장소 거부를 구분한다. V4 이후 V5의 추가 보완은 손상 캐시를 지운 뒤 `synced`가 와도 `revision: null`이면 최초 수첩을 받은 것으로 취급하지 않고 입력 잠금·재시도를 유지하는 한 건이다. 마지막 보완에서는 `local-conflict`로 미저장 수첩을 고르는 중 같은 계정의 `restoring`이 와도 가림·잠금·기기 이전 차단을 유지한다. 이 회귀 한 건을 더한 최종 원문으로 공식 검수를 완료했다.

## 브라우저 수동 확인

[관찰 기록](manual-browser.json)은 담당자가 격리 브라우저에서 확인한 `manual-browser` 결과다. 자동 UI 시험 수로 환산하지 않았다.

- 첫 계정 로딩 동안 수첩·합계·입력 가림과 복원 후 표시를 확인했다.
- 추천에서 일정의 마음 전하기, 후속 챙김의 우리의 기록, 날짜 없는 오늘 안부로 연결했다.
- 복사만으로 추천이 사라지지 않았고, 직접 챙김 기록에 따라 다시 제안했다.
- V2에서 후속 **직접 챙겼어요** 직후 홈 추천이 하늘로 바뀌었다. 다른 사람 보기에서도 완료한 민서를 일반 안부로 다시 제안하지 않았다. 일정 완료 뒤 지우로 바뀌었고, 안부 완료 뒤에는 제안 보류 안내와 수동 선택이 남았다.
- 375/320px 가로 넘침이 없고 이유 본문 17px·주행동 단추 높이 56px를 확인했다. V2 확인 중 콘솔 warning/error는 0이었다.
- V2에서 **다음에 → 10월 8일**로 미룬 민서를 일반 안부로 즉시 다시 제안하는 문제를 발견했다. V3는 직접 정한 다음 챙김 날 전에는 일반 안부를 보류하며, 명시적인 생일·일정 제안은 유지한다. 실제 브라우저에서 미룬 뒤 다른 사람 보기가 **하늘 → 지우 → 하늘**로 돌아 민서를 제외했다. 375px 넘침 없음·본문 17px·주행동 56px·콘솔 warning/error 0을 다시 확인했다.

추천의 대표 화면은 [V3 375px](focus-final-375.png)다. 이전 화면도 보존한다: [첫 로딩](loading.png), [320px](focus-320.png), [V1 375px](focus-375.png), [1280px](focus-1280.png), [제안 보류 375px](caught-up-375.png). 추천 UI 스타일은 동일하며, 이후 계정 상태 전환 보완은 아래 V4 기록과 구분한다.

## 계정 상태 전환 보완 · V4 브라우저와 V5 단위 시험

공식 검수에서 저장 대기 `idle`을 첫 로딩으로 오인해 수첩을 숨기던 P1과, 첫 조회 실패 때 빈 계정 수첩·기기 이전이 열리던 P2를 확인해 수정했다. [V4 수동 관찰 원본](account-manual-v4.json)은 합성 계정 어댑터·HTTP 응답과 **실제 공개 앱·document-sync**를 사용했다. 이번 브라우저 확인은 운영 OAuth 또는 실물 휴대폰 시험이 아니다.

- 최초 조회 중에는 수첩을 가리고 입력과 기기 이전을 잠근다.
- 최초 오프라인 실패 뒤에도 가림·입력·기기 이전 잠금을 유지한다. `aria-busy=false`로 무한 대기를 끝내고 **계정 자료 다시 불러오기**를 활성화한다. [375px 실패 안내](account-failure-375.png).
- 재시도 뒤 합성 계정 수첩을 받으면 화면과 입력을 연다. 사람 추가 직후 저장 대기 `idle`에서도 새 사람 화면에 바로 진입한다.
- 앞선 저장이 진행되는 동안 다른 사람을 추가해도 그 사람 화면에 진입하며, 저장 응답 뒤 최신 선택을 유지한다.

이미 받은 수첩의 새로고침은 화면을 유지하고 입력만 잠근다. 계정 연결 복원도 앱·인증 상태·동기화 상태의 계정 ID가 명확히 일치하고 미저장 수첩을 선택 중이 아닐 때만 기존 수첩을 보이며 입력을 잠근다. 계정이 미확정이거나 다르거나 미저장 수첩 선택 중이면 계속 가린다.

BFCache로 로그인 이동 전 페이지가 복원되는 경로에는 세션을 삭제하거나 로그인·로그아웃을 단정하지 않고 표시만 `login-returned`로 풀어 재연결할 수 있게 했다. 이는 **소스 확인·단위 시험 범위이며 실제 Chrome BFCache 복귀는 재현하지 않았다.** 공식 최종 Opus 5.5 / max 검수는 완료했으며 게시 push 이후 CI·공개 반영 확인은 대기 중이다.

정책과 제한은 [제품 README](../../README.md), 초기 공개본과 재실행 방법은 [공개 웹 QA](../PUBLIC-WEB.md)를 따른다. 복사·준비 계획을 실제 연락으로 세지 않고, 직접 기록한 활동·일정 완료·완료 후속 기록을 사용한다. 직접 정한 다음 챙김 날 전과 조심스러운 날 주변의 일반 안부는 보류하며, 임의의 기억을 메시지에 자동 삽입하지 않는다. 앱 종료 후 자체 예약 푸시는 제공하지 않는다.
