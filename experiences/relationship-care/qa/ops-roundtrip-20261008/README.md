# 플레저 · 운영 두 세션과 알림 시간 경계 · 2026-10-08

## 완료한 범위

운영 `Synk Core`의 실제 Auth·DB·서버 함수를 합성 계정으로 검증했다. 같은 계정의 서로 다른 로그인 세션 2개와 별도 계정 1개를 사용했다. 배포 전 **36/36**, 배포 후 **36/36**을 각각 통과했고, 매 실행의 합성 계정 2개·연결 자료·구독을 삭제한 뒤 남지 않았음을 확인했다. 물리 PC↔휴대폰이나 브라우저 OAuth 왕복으로 표시하지 않는다.

- A 저장 → B의 한글·이모지 포함 정확한 조회와 수정 → 오래된 A 저장의 충돌.
- 같은 revision의 동시 쓰기는 하나만 성공하고 다른 하나는 409. 승자의 내용과 revision을 보존한다.
- 계정 간 격리, 개별 인물 삭제의 다른 세션 반영, 오래된 기록으로 삭제된 인물 복원 차단.
- 완료한 후속과 7일 뒤로 미룬 후속은 실제 분 단위 cron에서 각각 `settled/skipped`. 기기 등록 전에 로컬 판단도 발송 대상 없음으로 확인했다.
- 수첩 삭제 tombstone과 오래된 저장 차단, 구독 제거, 수첩 없는 구독 거절, 명시적 새 저장 허용.
- 현재 세션 해제 후 해당 토큰은 401이고 다른 세션은 유지. 해제된 세션의 알림 구독도 제거.

[배포 전 결과](production-roundtrip.json)·[정리 증거](synthetic-cleanup-journal.json), [배포 후 결과](postdeploy/production-roundtrip.json)·[정리 증거](postdeploy/synthetic-cleanup-journal.json). 시험 비밀번호·토큰·서비스 키는 결과물에 저장하지 않았다. 기존 사용자의 수첩과 ‘동기화 확인용’ 기록은 변경하지 않았다. 전체 발송 작업을 수동 실행하지 않고 정규 cron의 합성 구독 건너뛰기만 관찰했다. 합성 endpoint를 사용했으며 외부 푸시 수신 증거는 아니다.

## 수정과 검수

워커가 시작할 때 한 번만 잡은 시각을 뒤 기기에 재사용하던 오류를 수정했다. 첫 기기 송신이 지연되면 다음 기기의 자정 또는 90분 처리 창이 지났는데도 발송할 수 있었다. 계정 잠금 획득 후, 최신 수첩 확인 후, 실제 송신 직전에 현재 시각을 확인한다. 만료된 claim은 송신하지 않고 `settled/skipped`로 마친다. 재시도는 거절 응답 시각부터 5분 뒤이며 원래 한국 날짜와 처리 창 안에서만 잡는다.

새 회귀 5개를 포함한 서버 **51/51**과 생성 런타임 `--check`가 통과했다. 지연된 첫 송신, 잠금 지연, claim 이후 지연, 비동기 판단 지연, 재시도 응답 지연을 다룬다. 기존 claim 확정·소유 계정 잠금·세션 철회·중복 방지·정확한 서비스 키 검사는 유지한다. [시험 출력](tests-backend.txt), [변경](clock-delta.diff).

공식 Claude Code `claude-opus-5-5 --effort max` 검수가 완료됐고 남은 P0~P2는 없었다. 실제 모델과 종료 상태, 검수한 네 파일의 SHA를 [검수 증거](claude-model-proof.json)·[소스 목록](claude-source-inventory.json)·[검수 원문](claude-review.json)에 남겼다. 검수에 없는 실행을 완료로 세지 않는다.

## 운영 반영

서버 커밋 **`9b68b62a6bea4ca23777d6519690c446c1bf5a9e`**를 `SYNK-talk-care-release-20261006`의 기존 배포 도구로 반영했다. `synk-care-push`와 `synk-care-push-send`는 각각 **v5 / ACTIVE / verify_jwt=true**다. 스키마·키·계정 등록·프런트 파일은 이번에 바꾸지 않았다. [배포 전 상태](release-preflight.json), [배포 결과](release-deploy.json), [배포 후 확인](release-verify.json).

같은 커밋을 원격 `codex/synk-care-personal-20261006`에 push하고 원격 ref를 다시 확인했다. SSH 전송은 GitHub 내부 오류로 실패했고 HTTPS 전송으로 완료했다. 이 브랜치에 실행된 GitHub Actions는 조회 결과 없었으므로 CI 통과로 표시하지 않는다. 로컬 회귀·운영 배포·배포 후 동작 증거를 각각 사용한다.

원격 두 함수의 변경된 런타임 전체가 커밋된 생성 코드와 일치한다. 기존 대조 도구는 한국어 주석 앵커가 없는 `index.ts`의 정적 일치를 판정하지 못해 exit 2를 냈다. 이를 전체 일치로 바꾸어 기록하지 않았다. 두 진입점의 실제 동작은 배포 후 36개 운영 검사에서 인증된 설정·해제와 정규 cron 실행으로 별도 확인했으며 무인증 요청은 두 함수 모두 401이었다. [설정 함수 대조](compare-synk-care-push.txt), [송신 함수 대조](compare-synk-care-push-send.txt).

## 아직 확인하지 않은 범위

- 사용자가 연기한 실물 PC↔휴대폰의 로그인·수정·새로고침·삭제 왕복. 앱은 다른 기기 변경을 **계정 자료 새로고침**으로 확인한다.
- 설치·브라우저 권한·OS 설정을 포함한 닫힌 앱의 실제 푸시 수신과 알림 클릭 이동. 서버가 창 안에서 송신을 시작해도 네트워크·OS·gateway TTL 때문에 수신 시각이 더 늦을 수 있다.
- 이번 합성 계정 정리는 개인 원본의 보관 기간 만료 후 자동 cleanup/purge 증거가 아니다. 이후 [별도 개인자료 정리 QA](../../../synk-account/qa/cleanup-20261008/README.md)에서 운영 만료/보존·공식 purge와 기존 dispatcher 경로, 과거 staging의 실제 만료 뒤 부재를 확인했다.
- 현재 분당 최대 10개 기기, 90분 처리 창의 MVP 처리량은 유지한다.
