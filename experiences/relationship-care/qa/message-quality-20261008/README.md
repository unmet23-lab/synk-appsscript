# 플레저 문구와 맥락 마감 · 2026-10-08

이번 작업은 사용자가 직접 고른 안부 목적과 확인한 표현 설정이 실제 초안에 이어지도록 보완한다. LLM 의미 이해나 사용자 만족도 향상을 측정한 결과가 아니라, **규칙·문장 틀의 품질과 화면 동작을 점검한 기록**이다. 합성 인물·일정만 사용했으며 개인자료 조회와 유료 API 호출은 하지 않았다.

## 문구 비교

[scenarios.json](scenarios.json)은 이전 공개 배포 작업본의 `care/model.mjs`와 수정한 로컬 `model.mjs`를 실제로 불러 같은 합성 입력으로 실행한 **9개 시나리오**다. 파일 경로·SHA-256·실행 시각·전체 입력과 출력·설명 및 주의 문구를 함께 기록했다. 공개 URL에서 다시 받아 비교한 증거는 아니다.

| 상황 | 이전 출력 또는 동작 | 수정 결과 |
| --- | --- | --- |
| 10월 15일 기일을 미리 준비 | “오늘 고인을 기억하며…” | “고인을 기억하며…”로 보내는 날을 단정하지 않음 |
| 평소 밝은 맺음말이 있는 사람의 조문 | “민수야”와 “맛있는 거 먹고 즐거운 하루 보내!”까지 연결 | 평소 호칭·맺음말 자동 연결을 보류하고 위로문만 준비 |
| 답장 배려가 이미 있는 저장 반말 문구 | 별도 존댓말 답장 문장을 추가 | 사용자가 기억한 문구를 유지하고 중복 문장은 추가하지 않음 |
| 사용자가 평소 맺음말을 빼고 기억한 문구 | 꺼내 쓸 때 평소 맺음말을 다시 추가 | 직접 기억한 문구를 유지하며 평소 맺음말은 새 문장 틀에만 연결 |
| 짧게 쓰기로 확인한 친구의 생일 | 첫 진입에서 `warm`을 고정 선택 | 확인한 `short`를 선택해 “민수야, 생일 축하해!”로 시작 |
| 업무 관계의 존댓말 | 직접 정한 “김민수 팀장님”과 존댓말 | 동일하게 유지 |
| 평소 안부 | “오늘 편안한 하루…” | 전송일을 단정하지 않는 평소 안부 |
| 직접 고른 오랜만의 연락 | 목적 선택을 반영하지 않는 일반 안부 | “오랜만이야. 잘 지내?”로 시작 |
| 직접 고른 감사 인사 | 목적 선택을 반영하지 않는 일반 안부 | “고마워. 이 말은 꼭 전하고 싶었어.” |

친구 생일 비교는 같은 사람·일정에 **이전 앱 첫 진입의 `warm` 고정**과 **새 `defaultDraftApproach()`의 결과**를 각각 적용했다. 이 경우의 옵션 차이는 JSON의 `invokedOptions`에 명시되어 있다. 나머지는 같은 옵션으로 두 모듈을 호출했다.

## 검증 상태

최종 수정본 v4를 검수하고 공개 커밋 `0f0c9a7`로 반영했다. 아래 범위와 실제 결과를 구분한다.

- [현재 Care 테스트 기록](tests-care.txt): **254개 통과, 실패 0**. 실제 앱 함수·핸들러를 실행하는 UI 상태 회귀 10개와 문구·설정·저장 계약 검사를 포함한다.
- 신규 모델 품질 행렬은 안부 목적 3종 × 길이 2종 × 반말/존댓말, 명시 선택과 기본값, 미래 날짜 표현, 조문·기일의 일반 설정 분리, 저장 문구 재사용, 금지 표현·답장 압박 처리, 같은 사람·같은 종류 격리, 기억 철회 및 v1 백업 유지를 확인한다. [전용 테스트](../../tests/message-quality.test.mjs)
- 로컬 합성 화면에서는 안부 목적 선택, 수정한 문구 덮어쓰기 취소, 복사 없이 문구 기억, 기억만으로 복사·실제 챙김 기록이 생기지 않는 점을 확인했다. 최종 후보 v3에서 기억 적용·해제·말투 설정 저장 뒤 감사 목적 유지, 저장 문구의 맺음말 미추가, 데스크톱과 375px 폭(본문 16px·가로 넘침 없음)을 확인했다. 320px 폭은 v2와 공개 v4에서 확인했다. 최종 v4에서는 일정 없는 합성 인물을 사람 목록에서 직접 열어 만든 감사 초안도 설정 저장 후 유지되는지 확인했다. [브라우저 증거](browser-verification.json)
- 공식 Claude Opus 5.5 · 최대 추론 초기 검수가 찾아낸 목적 초기화·첫 비길이 설정의 길이 변경 P2 두 건과 관련 저장 오류를 수정했다. 동일 세션·동일 모델·최대 추론으로 두 차례 재검수했고, 일정 없는 사람 목록에서 직접 안부를 작성하는 추가 경로도 수정했다. 남은 P0~P2가 없다는 최종 결과와 실제 `claude-opus-5-5`·완료 응답을 확인했다. 주 에이전트가 검수 파일 10개의 SHA-256 일치를 직접 검증했다. [모델·완료 증거](claude-model-proof.json), [최종 결과](claude-final-review.json)
- 공개 커밋 `0f0c9a7`과 Pages 배포는 완료했다. [공개 48개 파일 SHA-256·MIME 대조](public-verification.json) 모두 통과. 공개 예시 수첩에서 안부 목적 변경·기억·교체 확인·동일 문구 재사용, 320px 폭 가로 넘침 없음·초안 16px을 실제 조작으로 확인했다. [공개 화면 검증](public-browser.json). 동일 커밋의 [Pages 배포](https://github.com/unmet23-lab/synk-policy/actions/runs/37665950683)와 [전체 사이트 CI](https://github.com/unmet23-lab/synk-policy/actions/runs/37665952977) 모두 성공했다. [배포 기록](release.json), [CI 결과](ci.json).
- 휴대폰 왕복 동기화와 실제 PC 알림 수신 시험은 사용자의 요청에 따라 계속 보류한다.

## 유지한 범위와 한계

- 안부 목적은 이번 초안에서 직접 선택하며 연락 이력·상대 기분·고마웠던 이유를 추정하지 않는다. 사람별 v1 수첩 저장 형식은 바꾸지 않는다.
- 직접 기억한 문구는 사람과 종류별 한 개다. 안부 목적을 새로 골라도 저장 문구를 그 목적에 맞춰 자동으로 고쳐 쓰지 않으며, 이 점을 화면 안내로 밝힌다.
- 조문 기본 틀은 종교를 전제하지 않는 위로문이다. 사용자가 같은 종류에 직접 기억한 호칭·종교 표현은 임의로 바꾸지 않고, 기존 이모지·웃음 표지·피할 표현 검사를 유지한다. 자유 문장의 뜻이나 상황 적합성을 판별하는 기능은 아니다.
- 약속 검사는 일부 직접 미래형과 업무 존댓말의 표면 표현만 확인한다. 인용문의 화자, 간접 표현, 복합 부정, 약속 이행 가능성까지 판단하지 못한다. “표시 없음”이 오류 없는 문구라는 뜻은 아니며 직접 검토가 필요하다.
- 사용자가 문구를 기억하거나 복사한 것과 실제로 연락한 것을 구분한다. 메시지 자동 발송과 상대 반응 측정은 하지 않는다.
