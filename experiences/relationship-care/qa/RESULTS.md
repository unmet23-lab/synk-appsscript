# SYNK 플레저 검증

> 10월 5~6일 초기·로컬 고도화 검증의 이력이다. 아래 운영 계정·공개·푸시 미실행과 검수 한도는 당시 상태이며, 이후 [공개 웹·실제 계정 결과](PUBLIC-WEB.md)와 [운영 왕복·시간 경계 검증](ops-roundtrip-20261008/README.md)에서 이어 본다. 현행 제품 범위는 [제품 README](../README.md)를 따른다.


## 2026-10-06 후속 · 대화에서 다음 챙김까지와 계정 저장

새 기능의 브라우저 검증은 [26개 결과](account-upgrade-20261006/result.json), 합성 두 기기의 계정 저장 검증은 [39개 결과](account-sync-20261006/result.json)에 있다. 실제 Chrome의 375/1440px에서 원문 근거와 후보 수정·선택, 기억 삭제, 사람 분류·검색, 달력·지난 미처리 회차, 경조금·연락 기록과 계획 예산의 구분, 준비 화면의 관계 맥락을 확인했다. 후속 검사에는 임시기록의 내보내기·명시 삭제, 여러 초안 선택, 저장 실패와 미보관 입력의 로그아웃·이탈 경고를 포함한다. 실제 운영 사용자 로그인 시험은 아니다.

공통 SYNK ID 브라우저 모듈과 revision 동기화 모듈을 추출한 뒤, 플레저·PATH·리허설·가족 앨범의 관련 모델/HTTP/계정/원본 파일 회귀 **201개가 통과**했다. 계정 전환 후 늦은 응답, 기기 수첩의 명시적 이전, 오프라인 대기본, 두 기기의 충돌 선택, 삭제 tombstone, 편집 중 저장 응답이 폼을 재설정하지 않는 동작을 포함한다. 후속 공통 캐시 23개는 저장 완료된 계정 사본 제거, 손상 원문 보존·복구 내보내기·로그아웃 뒤 명시 삭제, 실패 표시와 같은 계정 여러 탭의 독립 초안을 검증한다. [실제 Chrome 두 탭 검증 24개](../../synk-account/qa/shared-cache-20261006/result.json)도 통과했다.

저장 서버는 같은 스키마 검증기를 사용한다. care/personal 서버·공급자 시험 도구 39개와 스키마 시험 26개, 최신 번들 일치 검사를 통과했다. 서버 시험에는 실제 postgres JSONB serializer와 격리 DB를 사용했고, Storage와 로그인 계정은 합성값이다. 운영 등록·마이그레이션·함수 배포·실제 사용자 왕복은 미실행이다. Claude 지적 수정 뒤 재검수는 사용량 한도로 남아 있으며, [통합 계정 현황](../../synk-account/qa/unified-account-20261006.md)에 정확한 중단 지점과 근거를 남겼다.

아래 초기 검증의 ‘원문을 보관하지 않음’은 초기 구현에 대한 기록이다. 현재는 사용자가 후보를 선택하고 보관할 때 해당 대화 **텍스트 원문**도 백업·계정 수첩에 포함한다. 플레저의 녹음 파일은 계속 보관하지 않는다.

브라우저 검사는 별도 합성 프로필에서 사람 등록→본인/상대 발화 분리→관찰→직접 선호 설정→일정→다음 회차 ICS→초안 수정과 실제 클립보드 복사→회차 완료→선택 저장/새로고침→JSON→삭제를 실행했다. 기본 자료가 비어 있고 명시적 예시만 추가됨, 원문/음성이 영구 저장 상태에 포함되지 않음도 확인했다.

실제 UI에서 기존 합성 MP3를 선택하고 받아쓰기 버튼을 눌러 문장을 받았다. 이 결과는 인식 결과이며 자동 화자 구분·개인 말투 이해가 아니다. 원문은 `experiences/korean-rhythm/audio-source/jobs.json`의 `t0q0r`, 음성은 같은 폴더 `raw/t0q0r.mp3`다. 물음표가 마침표로 인식되어 문장부호까지 동일하지는 않다. 재현 명령은 `node experiences/relationship-care/qa/transcription-smoke.mjs`이며 로컬 모델만 사용한다.

삭제 중 늦게 끝난 클립보드 요청이 이전 사람/초안을 복원하지 않는지, 숨겨진 대화 입력란도 비워지는지, 저장한 알림이 새로고침 후 중복되지 않는지, 저장 용량 실패를 고정 안내하는지를 브라우저에서 확인했다. 알림 재전송 시험은 Notification 대체 객체를 쓴 기능 검증이며 실제 OS 알림 도착 증거가 아니다. 자정에 낡은 회차가 다음 해 완료로 바뀌는 오류는 실제 이벤트 핸들러에 한국 시간 23:59→00:01을 주는 별도 재현으로 차단을 확인했다.

네이티브 검사는 실제 숨김 Electron에서 별도 세션, Node 접근 차단, 고정 브리지, 합성 계정의 `library.care` 노출·계정 전환을 검사했다. 동일 출처 Blob으로 생성한 `synk-care.ics`와 `synk-care.json`은 실제 DownloadItem의 `completed` 및 파일 내용 일치를 확인했다. 운영 계정 이용권을 새로 부여한 검증은 아니다.

## 아직 확인하지 않은 범위

실제 개인 통화의 인식 품질·다화자/긴 녹음, LLM의 의미 기반 말투 분석·개인화, 운영 계정 격리/동기화, 앱이 닫힌 상태의 예약 푸시, 달력 앱에서 실제 알림 도착, 카카오톡·문자 자동 발송, 새 설치본·공개 배포, macOS·Android·iOS 실기기는 미실행이다. 웹과 PC 개발판은 같은 앱 소스를 사용하지만 각자의 선택 저장 공간을 공유하지 않는다.
