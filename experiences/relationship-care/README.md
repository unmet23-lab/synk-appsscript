## 2026-10-08 · 상황별 내 문구 보관함 · 운영·공개 반영 완료

사람·일정 종류별로 여러 문구를 보관하고, 안부는 일상·오랜만·감사로 나눠 꺼내 쓴다. 기존 문장 틀과 Vellum 표현 검사, SYNK 계정 저장을 재사용한다. 유료 AI 호출이나 개인 모델 학습은 추가하지 않았다.

- 새 문구를 기억하면 이전 문구를 남긴다. 같은 목적·같은 글은 중복으로 쌓지 않으며 즐겨찾기를 먼저 표시한다. 이전 문구는 미리 본 뒤 **이 문구로 다시 준비**로 가져온다. 직접 고친 초안이 있으면 교체를 확인한다.

- 새 앱은 실제 계정 연결기를 통해 저장 요청에 `messageLibraryVersion:1`을 보낸다. 서버는 계정 잠금 안에서 기존/새 보관함이 있는 자료를 구버전이 덮는 요청을 차단한다. 옛 임시 수첩 복구는 같은 revision이어도 새 보관함을 자동으로 덮지 않으며, 조회 실패 뒤에는 다시 원격 상태부터 확인한다. 충돌·백업과 원본 보존 경로를 유지한다.

## 2026-10-06 · 대화에서 다음 챙김까지, SYNK 계정 수첩

후속 요청에 따라 **입력 → 확인 → 보관 → 다음 일정에서 다시 꺼내 보기**를 연결했다.

- 홈에 대화·청첩장·녹취 텍스트를 넣고 사람을 고른다. 글에 적힌 날짜·시간·장소와 명시적인 취향 표현을 규칙으로 추려 원문과 나란히 보여 준다. 연도 생략·상대 날짜·오전/오후·음력/윤달은 확인 안내를 표시한다. 필요한 항목을 직접 고치고 선택한 뒤에만 일정·기억과 원문을 함께 보관한다. 자동 의미 분석이나 확정 사실 추출로 표시하지 않는다.
- 기억의 근거와 보관한 원문을 사람 수첩에서 다시 읽고 삭제한다. 직접 남긴 기억도 원문에 연결한다. 사람 검색은 이름·관계·메모·확인한 기억을 함께 찾으며 가족/친구/직장/기타 분류는 직접 고른 값만 사용한다.
- 월별 달력은 완료된 날짜도 표시한다. 지난 1년의 미처리 일정에서 실제 챙긴 날을 기록하면 해당 회차만 완료된다.
- 일정에는 연락/참석/선물/조용히 기억의 **계획과 예산**, 기록에는 실제 연락/참석/선물/경조금/기억의 **주고받은 방향·날짜·금액**을 구분한다. 실제 기록에는 미래 날짜를 허용하지 않는다.
- 마음 전하기의 **연락 전에, 우리 이야기**에서 최근 연락, 지난 선물·경조금, 확인한 기억, 이번 계획과 예산, 같은 종류의 지난 복사 문구를 꺼내 본다. 말투 문구는 기존 직접 확인한 표현과 명시 저장 문구를 재사용한다.
- 계정 모드에서는 기존 SYNK ID로 인증한 `synk_user_id`의 `synk-care` 수첩을 읽고 자동 저장한다. 비회원 기기 수첩은 자동 업로드하지 않으며 직접 가져오기로 추가한다. 로그아웃하면 원래 비회원 수첩으로 돌아오고 이전 계정의 늦은 응답은 버린다.
- 기기별 수정은 revision으로 비교한다. 오프라인 대기본은 계정별로 보관하며 다른 기기와 충돌하면 **계정 자료 선택 / 내 변경 저장** 중 직접 선택한다. 삭제도 revision을 증가시켜 오래된 기기의 저장이 삭제본을 자동 복원하지 못한다.

계정에 보내지 못한 변경(`pending=true`)만 이 앱의 계정별 임시기록으로 기기에 보관한다. 저장 완료·다시 불러오기·로그아웃 때 완료 사본은 제거한다. 로그아웃 뒤에는 남은 기록의 존재만 알리고, 기록을 남긴 계정으로 로그인해야 **계정 임시기록 복구 파일 내보내기** 또는 확인을 거친 **이 기기의 계정 임시기록 지우기**를 쓸 수 있다. 삭제는 현재 편집·전송이 없는 때 그 계정의 이 앱 임시기록에만 적용하며 계정 서버 자료·다른 계정·다른 앱·로그인 전 기기 기록은 그대로 둔다. 탭마다 수정할 수 없는 별도 초안 키로 보관하고 저장 응답은 해당 요청의 초안만 정리한다. 이전 미저장 기록은 한 개여도 직접 골라 열며 선택하지 않은 기록은 보존한다. 읽지 못한 임시기록은 같은 키의 원문을 보존하고, 소유 계정을 확인할 수 없는 원문은 이 화면에서 내보내거나 지우지 않는다.

브라우저 공개 설정은 `SYNK_CARE_ACCOUNT_CONFIG`가 가리키는 파일 또는 공통 `experiences/synk-account/config.json`에서 읽는다. 전용 `clients.care`는 공통 중앙 계정의 public OAuth client이며 API 제품은 `platform`이다. 네이티브는 기존 PKCE·OS 암호화 보관함을 재사용하는 `care` 전용 연결로 같은 SYNK ID를 확인한다. 서로 다른 계정을 만들거나 앱 간 토큰을 복사하지 않는다.

저장 서버 정본은 형제 `SYNK-talk/lib/synk-care-{server,store}.js`, migration `20261006100000_synk_care_c16.sql`, `supabase/functions/synk-care`다. 인증된 활성 계정 소유권·세션 철회·4MiB UTF-8·정확한 상태 스키마를 검사하고 JSONB는 typed JSON으로 저장한다. 앱의 `importBackup`을 서버 번들에도 포함해 같은 스키마로 검증한다. 운영 설정과 배포의 현재 상태는 [통합 계정 도구](../../tools/synk-id/UNIFIED-CONFIG.md)와 QA에 구분해 기록한다.

## 2026-10-06 · 기록에서 다음 행동으로

사용자 승인으로 아래 기능을 로컬 앱에 연결했다. 화면의 **마음 전하기**에서 준비 → 문구 수정 → 점검 → 표현 기억으로 이어지고, **우리의 기록**에서 후속 챙김과 기억 카드를 만든다.

- **이번에는 어떻게 챙길까요?** 참석 여부·지금 준비할 시간·직접 정한 예산으로 준비 순서를 고른다. 기존 Core Domain과 Ask를 실제 호출하고, 답에 따라 행동이 달라질 질문만 하나씩 표시한다. 준비 시간은 제품의 안내 기준이며 이동 시간·상대 기대 금액을 추정하지 않는다. 적용은 계획 저장이고 실제 연락/전달은 별도로 기록한다.
- **고친 표현을 다음에도:** 길이를 줄이거나 이모지·표현을 뺀 수정에서 후보를 제시한다. 사용자가 명시적으로 기억 버튼을 눌렀을 때만 기존 사람별 표현 설정에 반영한다. 원문과 수정문이 달라지면 후보를 다시 확인한다. 관계나 상대 마음을 추론한 개인 모델이 아니다.
- **보내기 전 한 번 더:** 현재 양력 회차와 문구의 명시 날짜, 다른 사람 이름, 확인한 금지 표현, 제한된 약속 표현을 찾아 근거와 수정 방향을 표시한다. 음력·윤달·상대날짜는 수동 확인으로 남기고 실제 발송을 막거나 대신하지 않는다. 점검 항목이 없다는 결과도 전체 문맥의 정확성을 보장하지 않는다.
- **후속 챙김:** 직접 날짜를 정하거나 선택한 원문의 날짜 후보를 확인해 저장한다. 지금 챙기기는 챙길 내용과 근거가 있는 안부 준비를 열고, 다음에는 날짜를 변경하며, 직접 챙겼어요/이제 그만은 각각 완료/중단이다. 앱을 닫은 뒤 자체 알림을 보내는 기능은 아니다.
- **기억 카드:** 같은 사람의 기억·활동에서 1~3개를 직접 고르고 발췌문·한 줄 마음·선택 사진을 확인해 PNG로 저장한다. 사진은 브라우저 메모리에서 처리하며 계정에 업로드하지 않는다. 내보낸 카드에는 선택한 내용만 담고 근거 원문 전체·경조금 액수는 넣지 않는다. 가족 앨범 자동 조회는 아직 연결하지 않았다.

## 2026-10-06 · 기억을 이번 안부에 연결

위 엔진 연결에 이어, 보관한 기억을 이번 준비에 직접 쓰고 일정 없이도 시작할 수 있게 했다.

- **이번에 쓸 기억 하나:** 기억과 원문 근거를 읽고 용도를 **함께한 기억 / 선물 취향**으로 직접 확인한다. 함께한 기억은 Core의 행동 선택과 준비 순서, 실제 문구에 반영한다. 선물 취향은 선물 준비 순서에 쓰며 선물하겠다는 약속 문구를 자동으로 만들지 않는다. 선택하지 않으면 기존 준비 방식을 유지한다. 기억의 자유 텍스트에서 용도를 추론하지 않는다.
- **오늘 그냥 안부:** 사람만 등록해도 준비·문구 수정·복사·명시적 문구 기억·실제 연락 기록으로 이어진다. 가짜 일정이나 날짜를 만들지 않는다. 복사와 실제 연락은 계속 별개의 기록이다.
- **후속 챙김을 달력으로:** 아직 남은 후속 챙김을 다음 한 번의 `.ics`로 내보낸다. 기본은 종일·알림 없음이며, 사용자가 시각과 알림을 직접 고른다. 완료·중단한 챙김과 지난 날짜는 내보내지 않는다. 내보내기 자체가 챙김 완료를 뜻하지 않는다.

기억 선택은 이번 화면에만 적용한다. 사람·계정 전환, 선택한 기억의 변경·삭제 때는 다시 확인하며 생성·복사·문구 기억 시에도 현재 소유자와 원문 근거를 검사한다. 확인한 금지 표현과 부고·기일의 표현 제한으로 반영할 수 없으면 이유를 표시한다. 초안은 최종 5,000자 안에서 완전한 인용만 추가하고, 이미 기억한 내 문구에 같은 인용이 있으면 중복으로 붙이지 않는다. 단순한 선택 해제는 별도로 저장한 내 문구를 지우지 않지만, **기억·원문 삭제**는 삭제한 기억의 문장이 들어간 그 사람의 다시 쓸 문구와 복사 기록도 확인 후 함께 지운다. 실제 연락 기록·별도 일정·다른 사람의 문구는 유지한다.

v1 백업과 전체 4MiB 제한을 유지한다. `savedMessages.checkin`과 `eventId: ''`인 안부 복사·준비 기록을 추가했으며 기존 일정 종류와 연간 회차는 바꾸지 않았다. [care-personalization.mjs](care-personalization.mjs)가 선택 검증을 맡고, 기존 Core/Ask 및 계정 동기화 경로를 재사용한다. [이번 검증과 현재 제한](qa/PERSONALIZATION.md)에 수정 전후 시험 시점과 운영 상태를 구분했다.

## 2026-10-06 · 관계 수첩으로 발전

사용자 요청 「좋아. 발전시켜줘」에 따라 오늘 챙길 사람 → 사람별 기록 → 문구 준비를 로컬 앱에 반영했다. 흰 바탕과 기존 펠트 자산을 유지하고, 축하와 부고·기일의 색·행동을 구분한다. 기존 `care` 식별자와 v1 저장 키는 유지한다.

1. **이름과 날짜로 시작:** 첫 사람을 등록하면서 양력 날짜를 함께 넣으면 일정과 첫 초안까지 바로 열린다. 날짜는 나중에 넣을 수도 있다.
2. **오늘의 홈:** 모든 사람의 7일 안 일정과 그다음 가까운 일정 6개를 날짜순으로 본다. 인사 준비·사람 수첩·달력 저장으로 바로 이어진다.
3. **사람별 수첩:** 직접 남긴 기억, 복사한 문구, 챙김 완료, 연락 없이 조용히 기억한 날을 구분한다. 복사는 발송 증거로 기록하지 않는다. 기록은 당시 행사 이름·종류를 보존한다.
4. **표현을 실제 초안에 반영:** 확인한 호칭, 피할 표현, 답장 부담을 덜어 주는 문장, 직접 쓴 덧붙일 말을 적용한다. 짧게·마음을 더 담아·기억한 내 문구를 고를 수 있다. 다시 쓸 문구는 복사할 때 사용자가 명시적으로 선택한 경우에만 사람·행사 종류별로 기억한다. 홈 왕복 중 작성하던 초안은 유지한다.
5. **음력 일정:** 생일·기일 등에서 양력/음력을 선택한다. 원본 음력 날짜를 보존하고 홈·알림·달력 파일에는 실제 양력 회차를 쓴다. 윤달이 없는 해에는 평달로 챙기기/윤달 해만, 30일이 없는 달에는 말일/그 해 건너뛰기를 선택한다.
6. **백업 복원:** 기존 v1 JSON을 검증한 뒤 현재 자료를 대체한다. 중복 ID·끊긴 참조·잘못된 회차·4MB 초과 파일은 거부한다. 복원 확인 전이나 기기 저장 실패 때는 기존 자료를 유지한다. 저장을 꺼 둔 사용자의 복원은 기기 저장을 임의로 켜지 않는다.

대화·녹음 가져오기는 사람 수첩의 ‘대화와 말투’에서 추가로 쓴다. 원문을 확인하고 **자신이 한 말만** 말투 자료로 선택하며, 관찰한 말투와 확인한 상대 선호를 구분한다. 녹음은 이 PC의 Whisper로 받아쓰고 화자는 자동 구분하지 않는다.

현재 텍스트 관찰은 **규칙 기반**, 새 초안은 **문장 틀과 명시적으로 확인한 표현**의 조합이다. 사용자가 기억한 문구는 그대로 재사용하되 현재 금지 표현을 다시 확인한다. 금지 표현이 포함된 문장은 제외하며 모두 제외되면 빈 초안에서 직접 작성하게 한다. 부고·기일에서는 이모지·웃음·농담 표지가 있는 문장을 제외하지만 숨은 뜻과 유머를 이해하는 분석은 아니다. 자유 메모도 자동 해석하지 않는다. 사람의 성격·감정·선호를 확정하는 LLM 분석이나 학습된 개인 모델로 설명하지 않는다.

### 음력의 범위와 원천

- 입력 음력: **1900-01-01~2050-11-18**, 변환 양력: **1900-01-31~2050-12-31**. 범위를 넘는 회차를 추정하지 않는다.
- `lunar.mjs`는 [korean_lunar_calendar_js](https://github.com/usingsky/korean_lunar_calendar_js)의 한국 음력표 일부와 MIT 라이선스를 포함한다. 원본 커밋은 모듈 머리에 고정했다. 실행 중 외부 요청이나 패키지 설치가 없다.
- [한국천문연구원 월별 음양력](https://astro.kasi.re.kr/kor/life/pageView/5)과 원본 검증값을 대조한다. 윤달과 작은달 정책은 집안에서 실제 챙기는 방식을 사용자가 확인해 정한다.

## 실행

저장소 루트에서:

```powershell
node experiences/relationship-care/server.mjs
```

- 웹 개발 화면: `http://127.0.0.1:4296/`
- 별도 PC 클라이언트: `npm --prefix desktop run dev:care`
- 소스 플랫폼: `npm --prefix desktop run dev:platform`. 서버에서 `library.care` 메뉴 이용권을 받은 계정에만 플레저가 나타난다. 기존 운영 권한을 새로 부여하지 않는다.
- 이 개발 앱은 별도 `im.synk.care.preview` 프로필/세션을 사용한다. 플랫폼과 다른 앱의 로그인·학습·회사 자료를 가져오지 않는다.

플랫폼 등록은 `desktop/renderer/state.mjs`, 메뉴 범위는 `desktop/src/library-access.cjs`, 고정 개발 입구는 `desktop/src/product-preview.cjs`가 담당한다. 이전 `synk-account/platform.html` 2앱 웹 미리보기는 현재 PC 런처가 아니다.

## 자료와 음성 처리

- 앱의 기본 자료는 열린 화면 안에만 존재한다. 사용자가 기기 저장을 선택하면 해당 브라우저/앱 프로필의 `synk.care.local.v1`에 보관한다. 사람·확인한 표현·일정·복사/완료 기록·명시적으로 기억한 문구가 포함된다. 비회원 기기 저장은 서버 동기화가 아니다. 계정 모드는 위 SYNK ID 연결을 사용한다. 보관을 선택한 대화 원문은 JSON 백업과 계정 수첩에 포함하며 녹음 파일은 제외한다.
- 녹음 파일은 이 PC의 loopback 서버로만 전송한다. 서버는 음성을 디스크에 쓰지 않으며 서버가 받은 입력 버퍼를 요청 종료 시 비운다. 작업자 내부의 복사본까지 즉시 메모리에서 지웠다는 뜻은 아니다. 브라우저의 선택 파일/재생 주소는 사용자 조작과 페이지 수명에 따른다. 녹음이 JSON 자료 내보내기에 포함되는 기능은 없다.
- `tools/patent-studio/local-transcriber.cjs`의 기존 독립 로컬 작업자와 기기에 설치된 Whisper small 설정을 재사용한다. `.runtime/local-stt.json`은 Git 밖의 기기별 실행·모델 경로다. 모델 지문 확인, Python 작업자의 외부 네트워크 차단을 유지한다. 새 모델 설치·유료 API·외부 파일 업로드는 수행하지 않는다.
- `GET /api/capabilities`의 `available`은 런타임 경로 확인이며, 실제 인식 성공은 해당 요청 결과로 확인한다. 다른 PC에서 준비되지 않았다면 녹취 텍스트로 진행할 수 있다.
- 녹음 최대 20MiB, 동시에 한 건, 작업자 기본 제한 90초. 긴 통화 전체의 성공·다화자 분리·억양 분석·목소리 복제는 구현 범위가 아니다.
- 선택한 원음은 받아쓰기와 구분해 들어볼 수 있다. 인식 결과는 수정 가능한 원문이며 날짜·화자·선호에 관한 사실로 자동 저장하지 않는다.

## 알림과 연락의 범위

- 앱 내부의 다가오는 일정과 열린 화면의 알림, 계정에서 직접 켜는 웹 예약 알림을 구분한다. 웹 알림은 브라우저의 지원·사용자 권한·OS 설정에 따른다. 웹 예약 알림의 실제 배포/검증은 위 10월 7일 알림 절을 따른다. 네이티브 개발 클라이언트는 OS 알림 권한을 아직 열지 않았다.
- `.ics`는 **다음 한 번의 일정과 미리 알림**을 달력 앱에 가져올 수 있게 한다. 앱을 닫아 둔 상태의 실제 알림은 사용자가 가져온 달력 앱과 그 알림 설정에 달려 있으며 모든 환경에서 도착했다고 보장하지 않는다.
- 후속 챙김의 시각은 한국 시간(`Asia/Seoul`)으로 내보낸다. 파일에는 사람 이름·챙길 제목을 담고 기억의 근거 원문은 넣지 않는다. 가져온 뒤 앱에서 날짜를 미루거나 완료·중단해도 외부 달력은 자동 갱신되지 않는다.
- 양력·음력 연간 반복과 해당 회차 완료는 앱 안에서 처리한다. 양력 윤일은 선택한 2/28 또는 3/1 정책, 음력은 위의 윤달·작은달 정책을 따른다. 달력 내보내기는 계산한 다음 1회 양력 날짜이며 연간 반복 규칙을 붙이지 않는다. 다음 해의 음력 일정은 다시 내보내야 한다.
- 문구 복사는 사용자가 직접 한다. 카카오톡·문자 자동 발송, 선물 구매·송금, 전화 발신은 없다.
