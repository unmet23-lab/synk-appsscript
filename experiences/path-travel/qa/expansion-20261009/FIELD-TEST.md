# PATH 실제 이용자 검증 준비 · 2026-10-09

**준비 문서이며 실시 결과가 아니다.** 참가자 모집·연락·실제 여행·인터뷰는 아직 하지 않았다. 자동 검사, 개발자의 브라우저 조작, 가상 방문 입력은 실제 여행자의 사용이나 만족도 증거로 세지 않는다. 이 문서는 [이전 반나절 테스트 안내](../../../../../SYNK-website/qa/travel-halfday-20261007/field-test-guide.md)를 현재 [여행 앱](../../README.md)의 취향·도보·진행·저장 흐름에 맞춰 확장한다.

## 실행 전 준비

- 참여 의사가 확인된 성인 5명을 목표로 한다. 아래 다섯 상황 중 본인과 가까운 상황을 한 사람에게 하나씩 배정한다. 실제 동행이나 건강 정보를 증명하게 하지 않는다. 아동 동반 상황도 성인 보호자가 조작한다.
- 참가자별 20~25분의 화면 사용성 관찰을 먼저 한다. 실제 여행은 별도의 자발적 사용이 있었을 때만 추가 기록한다. 화면 테스트 날짜, 기기·화면 너비, 정확한 앱 주소와 빌드/커밋, 관찰자, 배정 상황을 기록한다.
- 자유 출발점·추천 실패 후 대안은 이번 확장 작업이다. 시작 전에 최종 빌드의 지원 입력과 적용/취소 동작을 확인한다. 준비되지 않은 기능은 `미지원`으로 기록하고 존재하는 것처럼 안내하지 않는다. 현재 공개 주소가 이전 판이면 로컬 최신판과 혼동하지 않는다.
- 이름·연락처·계정 ID·정확한 거주지·건강/장애 정보는 기록지에 적지 않는다. P01~P05만 사용하고 출발지는 공개 역·시설 등으로 선택한다. 연락 명단은 이 문서에 만들지 않는다.
- “제품을 검사하는 것이고 참가자를 평가하지 않는다. 언제든 멈추거나 답하지 않아도 된다”라고 알린다. 관찰 메모 동의를 먼저 받으며 화면/음성 녹화는 각각 별도 동의가 있을 때만 한다. 기본은 녹화 없이 관찰한다.
- 참가자 기기의 기존 여행·개인자료를 지우거나 가져오지 않는다. 별도 브라우저 프로필/비공개 창에서 게스트로 시작한다. 파일 이동은 이 테스트에서 새로 만든 여행만 본인이 다루며, 관찰자에게 파일 제출이나 실제 계정 로그인을 요구하지 않는다.

## 공통 진행과 관찰 기준

시나리오의 목표만 말하고 버튼 위치나 정답 장소는 알려주지 않는다. 참가자가 생각을 말하면 그대로 기록한다. 60초 넘게 막히면 “지금 무엇을 하려는 중인가요?”라고만 묻고, 조작을 알려줬다면 `도움 후 완료`로 구분한다. 계획 생성 자체보다 **조건을 이해하고, 확인이 필요한 사실을 알아보고, 스스로 선택을 바꿀 수 있는지**를 본다.

각 행동은 `스스로 완료 / 도움 후 완료 / 미완료 / 미지원 / 본인 선택으로 건너뜀` 중 하나와 실제 소요 시간, 처음 막힌 곳, 도움 내용으로 기록한다. 추천이 없더라도 이유를 이해하고 조건을 명시적으로 바꾸거나 그대로 두면 올바른 결과일 수 있다. 앱이 조건을 몰래 완화하거나 모르는 정보를 확정으로 보이면 실패다.

## 다섯 여행자 상황

### S1 · 취향이 분명한 혼자 여행하는 사람

“종로에서 식사와 차를 즐기고 싶다. 면은 좋아하지만 만두는 오늘 피하고 싶고, 카페는 커피보다 전통차 쪽이 좋다.” 실제 참가자의 취향이 다르면 세부 선호 두 가지와 회피 한 가지를 본인이 골라 바꾼다.

- 관찰 행동: 현재 여행의 취향을 입력하고 추천 이유를 본다. 한 장소를 유지한 뒤 다른 한 곳을 교체한다. 오늘의 선택을 평소 취향으로 자동 보관한다고 오해하는지 확인한다. 원한다면 명시적으로 평소 취향 하나를 확인한 뒤 철회해 본다.
- 성공 판정: 추천에서 자기 조건 두 가지 이상이 어디에 반영됐는지 설명한다. 회피 관련 정보가 미확인인 장소를 “회피 조건 충족”으로 단정하지 않는다. 유지/교체와 평소 취향 철회가 본인 의도대로 동작한다. 특정 상호가 반드시 나와야 성공인 것은 아니다.
- 사후 질문: “이 추천이 나를 이해했다고 느낀 부분과 못 이해한 부분은 무엇인가요?” “오늘의 취향과 다음 여행에도 기억할 취향을 구분할 수 있었나요?”

### S2 · 오래 걷기 힘든 동행과 함께하는 사람

“동행이 오래 걷는 일정을 원하지 않는다. 총 도보는 35분, 한 번에 걷기는 15분 정도로 정하고, 약 60분마다 10분 쉬고 싶다.” 숫자는 참가자가 현실적인 범위에서 직접 조정한다.

- 관찰 행동: 총 도보·한 구간 도보·휴식 간격을 서로 다르게 입력하고 시간표와 지도를 본다. 휴식 시간이 추가됐는지, 쉬는 좌석·무단차 동선이 확인됐는지 찾아본다. 조건이 빡빡해 결과가 없으면 대안 설명을 읽고 바꿀 조건을 직접 결정한다.
- 성공 판정: 도보 추정치와 실측을 구분한다. 휴식 계획을 “좌석이 보장된 쉼터”로, 접근성 미확인을 “휠체어 이동 가능”으로 이해하지 않는다. 조건 변경 미리보기를 취소하면 원래 일정이 보존되고, 수락했을 때만 새 일정이 반영된다. 건강상 요구가 충족되지 않으면 사용하지 않기로 판단해도 성공이다.
- 사후 질문: “동행에게 무엇을 약속할 수 있고 무엇은 직접 확인해야 하나요?” “걷기와 쉬기 중 다시 조정하고 싶은 것은 무엇인가요?”

### S3 · 아이와 정해진 예산으로 나가는 보호자

“성인 2명과 아이 1명이 문화 장소와 식사를 포함해 오후를 보내려 한다. 전체 표시 예산은 6만 원이고 끝나는 시간은 바꾸기 어렵다.” 실제 인원과 예산으로 바꾸되 아동의 이름·나이는 수집하지 않는다.

- 관찰 행동: 인원·예산·마감 시각·필수 분야를 설정한다. 표시 비용의 포함/미포함, 아동 요금 미확인, 메뉴 선택에 따른 추가 비용을 확인한다. 예산이나 시간 때문에 결과가 없을 때 제시된 대안이 무엇을 바꾸는지 비교하고 하나를 수락하거나 원조건을 유지한다.
- 성공 판정: 알려진 금액을 최종 결제액으로 말하지 않는다. 미확인 아동 요금·식사 선택 금액을 0원으로 해석하지 않는다. 필수 분야나 종료 시각이 동의 없이 사라지지 않는다. 적용 전후 바뀐 조건을 본인이 설명한다.
- 사후 질문: “오늘 얼마를 준비해야 한다고 이해했나요? 아직 모르는 비용은 무엇인가요?” “이 일정으로 출발하기 전에 어디를 확인하겠어요?”

### S4 · 이 지역을 처음 방문해 출발지가 익숙하지 않은 사람

“대표 역이 아닌 공개 시설 근처에서 출발하려 한다. 지도에서 위치를 확인하고 식사와 문화 장소를 골라 달라.” 자유 출발 입력은 최종판에서 실제 지원하는 방식으로만 한다. 검증을 위해 집이나 숙소의 정확한 위치를 요구하지 않는다.

- 관찰 행동: 출발점을 입력/선택하고 지도 표시와 장소명을 대조한다. 잘못되거나 지원 구역 밖인 위치도 한 번 확인한다. 첫 이동 경로의 추정·길망 지원 범위를 읽고, 추천이 불가능하면 이유와 가능한 다음 행동을 찾는다. 다시 지원 구역 안의 공개 위치로 고친다.
- 성공 판정: 엉뚱한 역이나 좌표로 조용히 대체되지 않는다. 범위 밖 도보를 실제 검증한 길처럼 믿지 않는다. 잘못된 입력을 본인이 수정하고 이전 일정/입력이 의도치 않게 사라지지 않는다. 지원되는 출발 위치와 확인이 필요한 경로 범위를 설명한다.
- 사후 질문: “지도에서 지금 어디서 출발한다고 이해했나요?” “이 길 안내만 보고 걸어도 된다고 느꼈나요? 추가 확인이 필요한 부분은 무엇인가요?”

### S5 · 여행 중 지쳐서 남은 한 곳만 다녀오려는 사람

“처음 계획에서 한 곳은 다녀왔고 한 곳은 건너뛰려 한다. 다시 출발할 시각·현재 장소·남은 예산·도보 여유를 직접 정하고 남은 한 곳을 보고 싶다.” 화면 테스트의 완료 표시는 가상 자기보고라고 명시한다. 실제 방문 후기나 별점을 만들지 않는다.

- 관찰 행동: 완료/건너뜀과 새 출발 조건으로 남은 1곳을 비교한다. 첫 미리보기는 취소하고 원래 일정이 남는지 확인한 뒤 다시 적용한다. 여행을 마친 후 완료 표시를 정정하고 재개한다. 보관은 선택적으로 동의하며, 새 여행 파일만 내보내 다른 빈 브라우저/기기에서 가져온다. 저장 동의를 철회하거나 테스트 기록을 정리한다.
- 성공 판정: 완료와 건너뜀이 새 일정에서 빠지고 직접 정정하면 다시 후보가 된다. 취소는 기존 계획/진행을 보존한다. 남은 예산이 예상 비용에서 자동 차감된 값이라고 오해하지 않는다. 완료 표시와 만족도 후기를 구분한다. 파일로 여행·진행이 복원되며 가져온 기기의 보관 동의는 다시 선택한다. 두 번째 기기가 없으면 파일 이동은 `미실시`로 남긴다.
- 사후 질문: “완료 표시를 누르면 무엇이 기록된다고 생각했나요?” “다시 여행할 때 어디서 이어갈 수 있나요?” “취소와 적용 중 어느 순간 내 일정이 바뀌었나요?”

## 짧은 공통 사후 질문

1. “이 일정으로 실제 출발하고 싶나요?” 1~5점과 이유. 이는 화면을 본 직후의 **사용 의향**이며 여행 만족도가 아니다.
2. “내 조건을 반영했다고 느끼나요?” 1~5점과 반영되지 않은 한 가지.
3. “가장 불안하거나 이해하기 어려운 정보가 무엇이었나요?”
4. “다음에도 쓸 이유가 있나요? 없다면 무엇이 먼저 바뀌어야 하나요?”

## 실제 여행 후에만 추가할 내용

자발적으로 실제 사용한 참가자에게만 별도 동의를 받아 짧게 묻는다. 실제 방문 여부·방문 순서·대략적인 이동/대기 시간·표시 정보와 달랐던 내용·일정 변경 이유·추천 만족도 1~5점을 분리한다. 정확한 위치 이력, 영수증, 계정 자료 제출은 요구하지 않는다. 자기보고와 관찰/공식 정보로 확인한 사실도 구분한다. 기억에 의한 걷기 시간을 GPS 실측이라고 적지 않는다.

현장 휴무·입장 제한·가격 차이를 알게 되면 [기존 정보 갱신 안내](../../../../../SYNK-website/qa/travel-halfday-20261007/source-maintenance.md)에 따라 공식 출처와 다시 대조한다. 참가자의 “시끄러웠다/계단이 있었다/맛있었다”를 모든 날짜의 업체 특성이나 평소 취향으로 자동 확정하지 않는다.

## 판정과 다음 수정

개별 시나리오는 위 필수 행동을 스스로 마치고 핵심 오해가 없을 때 통과로 적는다. 저장 동의, 돈, 도보/접근성, 위치, 완료/만족도 구분에서 중요한 오해가 한 번이라도 관찰되면 그 문제를 먼저 고친 뒤 해당 흐름을 다시 검사한다. 도움 후 완료와 미실시는 스스로 완료한 수에 넣지 않는다.

5명 중 몇 명이 성공했는지는 정확한 분모와 함께 탐색 결과로만 적는다. 이 작은 관찰이나 자동 검사 통과만으로 “개인화 만족도 향상”, “안전한 이동”, “실제 운영 성과”를 주장하지 않는다. 실제 여행 자료가 없으면 여행 만족도 판정은 계속 **미확인**이다. 기준선과 실제 결과가 없는 Temper 비교도 `insufficient evidence`를 유지한다.
