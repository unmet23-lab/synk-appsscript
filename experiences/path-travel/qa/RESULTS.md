## v3 — 문장 제안과 본인 확인의 추천 연결 (2026-10-06)

현재 대상은 **path-travel-local-3**다. 가상 QA 문장·후보로 기능과 정보 전달을 검사했으며 유료 AI·외부 API 호출은 0이다. 제한된 한국어 명시 조건의 로컬 해석이고, 일반 자유 대화 AI·실제 여행 만족도·공개 운영을 검증한 결과가 아니다.

### 실제 연결과 발견한 문제

기존 Core Interpretation의 prepare/review/resolve를 사용한다. 입력 문장 → 원문 인용을 가진 조건 제안 → 본인 확인/값 정정/제외 → Core 선호 사건 → Domain 관측/판단 → 추천 근거와 원문 화면으로 연결했다. 새 Atlas 엔진과 LLM 실행 하네스는 만들지 않았다.

- 입력·읽기·거절은 선호 사건 0건. 확인한 조건만 추천에 들어가며 기본값과 미확인 제안은 선언으로 승격하지 않는다.
- 원문을 그대로 확인한 값은 원문 시각+30일을 유지한다. 값을 직접 정정하면 확인 시각의 새 선언이다. 기간·강도·중요도도 직접 검토한다.
- 평소와 이번 여행의 원문 계보는 각각 유지한다. 새 여행·철회·수동 수정 시 활성 선호 사건에 연결된 근거만 사용한다.
- ‘25만 원, 아니 40만 원’에서 앞의 숫자만 제안하던 문제를 고쳐 정정 문장 전체를 재입력하도록 보류한다.
- 타인에서 ‘저는 지금’으로 돌아온 문장을 놓치던 문제를 고쳐 동일 항목의 두 값은 충돌로 표시한다.
- 45분 같은 직접 수치를 편집할 때 기본 30분으로 바꾸지 않는다. 제안 하나를 승인해도 다른 제안의 편집값을 유지한다. 고친 값은 ‘직접 고친 조건’으로 표시한다.
- 저장 동의는 해석 검증용 입력 원문(한 번에 최대 4,000자)을 포함한다. 미확인 draft는 저장하지 않는다. 복원 가능한 크기를 넘는 기록은 덮어쓰기 전에 저장을 거부한다.

[실제 엔진 전달 재현](engine-handoff-v3.json)은 제안만 읽음 A/117,300원/선언0 → 소음만 확인 B/187,600원 → 예산 거절 후 동일 → 걷기45를60으로 정정 → 새 여행에서 평소 소음만 복귀를 기록한다. 모두 가상 업체·가격이다.

## 남은 확인과 경계

- 내장 브라우저에서 파일 다운로드 완료 이벤트를 얻지 못했다. 메모 보기와 전체 선택은 확인했지만 TXT/JSON 파일이 기기에 저장된 결과는 미확인이다. UI는 저장 완료 대신 요청으로 안내한다.
- 기기 저장의 여러 탭 충돌·동의 철회 전파는 후속이다. 한 탭에서 해제한 뒤 다른 탭이 계속 동의 상태면 다시 저장될 수 있다. 계정 연결 전 해결할 항목이며 현재 저장 범위는 [README](../README.md)를 따른다.
- 실제 업체·날짜별 객실/가격·교통·예약·여행 품질, 자연어 성향 분석, 48개 조건 전체, 계정/장기기억, 공개 배포를 검증하지 않았다.
- 사업 정본 연결 점검 중 기존 `tests/비전동기화.test.js`는 3/5 통과했다. 이전 SHIFT 문구 기대값과 서브텍스트 제거 검사 2건은 여행 문단을 포함/제외한 비전 파싱 결과와 실패 조건이 동일한 기존 문제로 구분했으며 이 작업에서 수정하지 않았다.
