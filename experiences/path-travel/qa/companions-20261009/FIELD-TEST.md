# PATH 동행별 취향 관찰 준비 · 2026-10-09

**준비 문서이며 실제 참가자 검증은 미실시다.** 모집·연락·인터뷰·실제 동행 여행은 하지 않았다. 자동 검사·개발자의 화면 조작·가상 프로필은 사용자 만족도 근거가 아니다. [기존 이용자 검증 안내](../expansion-20261009/FIELD-TEST.md)와 [예약·식사·도착점 관찰](../schedule-20261009/FIELD-TEST.md)에 아래 상황을 선택적으로 추가한다. 실제 검사할 빌드·주소·기기·화면 너비를 기록하고 미구현 기능은 `미지원`으로 표시한다.

기본은 성인 참가자가 ‘나’, ‘동행 A’, ‘동행 B’ 같은 가상 별칭으로 조작하는 화면 관찰이다. 실명·연락처·건강 정보·정확한 숙소·실제 계정 로그인을 요구하지 않는다. 실제 동행자의 취향을 적을 때도 본인이 동의한 내용만 사용한다. 접근성·채식·조용함은 상황 예시이며 참가자의 건강·신념을 추측하거나 설명하게 하지 않는다. 기록 동의와 중단 권리는 기존 안내를 따른다.

## S9 · 서로 다른 취향을 넣고 누구의 조건이 반영됐는지 읽기

**목표:** “나와 동행 A는 가고 싶은 곳이 다르다. 둘의 취향을 각각 넣고, 무엇을 반영하거나 못 반영했는지 확인하고 싶다.” 예를 들어 한쪽은 커피를 좋아하고 다른 쪽은 전통차를 좋아한다. 양쪽 모두 음식·카페 정보가 충분하지 않은 항목도 하나 골라 본다.

- 관찰: 별칭 두 개와 각자의 선호·회피를 입력한다. 모바일에서 다른 사람의 카드를 잘못 수정하지 않는지, 펼친 취향 목록과 사람 이름을 구분하는지 본다. 결과의 사람별 반영·미반영·미확인·회피 충돌을 읽고 어느 장소에 대한 설명인지 찾는다. 한 사람의 선호를 바꾼 뒤 새 안을 비교하고 첫 변경은 취소한다.
- 판정: 누구의 어떤 조건이 반영됐는지와 아직 모르는 조건을 본인이 설명한다. 미확인을 충족이나 회피 성공으로, 계획 적합도 표시를 실제 만족도로 오해하지 않는다. 두 사람을 만족시킬 안이 없으면 한쪽을 숨기지 않고 그 이유를 보여 준다. 취소하면 적용 전 일정과 두 사람의 조건이 보존된다.
- 질문: “누구에게 무엇이 맞고 무엇은 아직 모른다고 이해했나요?” “어느 조건을 바꾸고 싶나요? 바꾸기 전에는 어떤 안이 적용돼 있었나요?”

## S10 · 한 사람의 필수 조건과 다른 사람의 선호가 충돌하기

**목표:** “동행 A에게 꼭 지켜야 할 조건 하나가 있다. 다른 사람의 취향이 강해도 그 조건을 지키는 자료가 없으면 알고 싶다.” 예시는 채식 확인·계단 없는 접근 확인·조용함 확인 중 하나다. 실제 참가자의 민감한 필요를 공개할 필요가 없다.

- 관찰: 선호와 필수 조건을 구분해 입력한다. 자료가 부족해 추천이 없거나 확인이 필요한 경우 설명을 찾는다. 시간·예산·도보 변경안이 나타나면 무엇을 바꾸고 필수 조건은 어떻게 처리하는지 비교한다. 한 사람이 조건을 직접 해제했을 때만 새 결과가 가능한지 확인한다.
- 판정: 다수의 선호 때문에 한 사람의 필수 조건이 몰래 풀리지 않는다. ‘알 수 없음’을 접근 가능·채식 가능·조용함 보장으로 표시하지 않는다. 사진·분위기나 다른 방문자의 자기보고를 시설 전체의 확정 특성으로 이해하지 않는다. 추천이 없더라도 이유를 이해하고 원조건을 유지하거나 직접 변경하면 올바른 사용일 수 있다.
- 질문: “꼭 지킬 조건을 누가 정했고, 어디에서 바꿀 수 있나요?” “이 결과만으로 동행에게 약속해도 되는 것과 직접 확인할 것은 무엇인가요?”

## S11 · 동행 정보 수정·삭제와 저장 후 이어쓰기

**목표:** “함께 갈 사람이 바뀌었다. 일부 취향과 별칭을 고치거나 한 사람을 빼고, 적용한 여행을 다른 빈 화면에서 이어보고 싶다.” 최대 6개 프로필 입력은 선택 사항이며 실제 인원·요금 입력과의 관계를 해당 빌드의 안내대로 확인한다.

- 관찰: 별칭 수정, 취향 선택 해제, 프로필 삭제를 한 번씩 수행한다. 변경한 조건을 적용하기 전후의 차이를 읽게 한다. 성인·아이 인원과 동행 프로필 수를 비교해 비용이 어느 입력으로 계산되는지 설명하게 한다. 이 테스트에서 새로 만든 여행만 선택적으로 파일로 내보내 빈 게스트 화면에서 가져온다. 되돌린 파일이나 초기화 뒤 옛 프로필·미리보기가 재등장하는지도 확인한다.
- 판정: 남은 사람의 조건이 다른 별칭으로 옮겨 붙지 않는다. 삭제한 프로필을 새 추천의 근거로 쓰지 않는다. 동행 입력을 본인 평소 취향이나 실제 방문 평가로 자동 저장하지 않는다. 적용한 동행 조건은 파일 복원에서 유지되고 가져온 기기의 저장 동의는 새로 선택한다. 파일에 별칭·취향이 포함되는지 사용자가 알고 공유를 결정한다. 두 기기 이동을 하지 못했다면 그 행동은 `미실시`로 남긴다.
- 질문: “지금 비용 계산에 사용된 인원과 취향을 적은 사람은 각각 누구인가요?” “파일을 다른 사람에게 주면 무엇이 전달된다고 이해했나요?” “동행 A를 지운 뒤에도 남는 정보가 있나요?”
