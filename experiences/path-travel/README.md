# SYNK PATH 서울 개인화 여행

서울의 하루 일정과 숙박 1박을 취향·예산에 따라 바꾸어 보는 로컬 시제품이다. **모든 업체·요금·시간·좌표는 가상 자료**이며 실제 추천·예약·길안내에 쓸 수 없다. 실제 지명은 서울역과 종로·서촌, 성수·서울숲, 이태원·한강 권역뿐이다.

2026-10-06 사용자의 여행 사업 강화 요청과 후속 “이어서 해”, 첫 도시 “서울부터” 선택에 따라 구현했다. 개인화 v2에서 **기본 10개와 세부 16개, 총 26개 조건**을 평소·이번 여행으로 구분하고 실제 Core 판단에 연결했다. 후속 v3는 명시적인 한국어 여행 문장을 조건 제안으로 읽고, 본인이 확인·수정한 것만 같은 추천 경로로 보낸다. 사업·48개 조건 전체 설계는 [PATH 원문](../../docs/PATH_개인화여행_설계.md)에 있다.

## 실행

저장소 루트에서 `node experiences/path-travel/server.mjs`를 실행하고 [서울 여행 시제품](http://127.0.0.1:4303/)을 연다. `--port`로 다른 로컬 포트를 선택할 수 있다. 추가 설치·계정·유료 AI·외부 API 키가 필요 없다.

서버는 `127.0.0.1`에만 바인딩하고 허용 목록에 있는 정적 파일과 Core 진입점·관련 모듈만 제공한다. 화면은 외부 네트워크·위치·카메라·마이크를 사용하지 않는다. 사용자 자료가 서버에 저장되는 API는 없다.

## 실제 구현 범위

- **말로 알려주기:** “평소 숙소는 아주 조용해야 해요. 이번 여행 총예산은 30만 원이에요.”처럼 한 조건씩 적는다. 원문과 읽은 값·강도·중요도·기간을 나란히 검토하고 개별 확인 또는 수정 후 반영한다. 입력·해석·거절만으로 취향 기록을 만들지 않는다. 타인·과거·가정·불확실·충돌은 바로 승인할 수 없다. 명확히 읽지 못한 문장은 그대로 남겨 다시 묻는다.
- **기본 10개 조건:** 총예산, 시작 시간, 지출 우선순위, 식사 취향, 밤 활동, 일정 속도, 이동수단, 숙소 선호, 우천, 음주 포함 여부. 첫 화면은 핵심 3개를 보여 주고 나머지는 펼쳐 고른다.
- **세부 16개 조건:** 숙소 소음·청결·접근성·숙박비 상한, 매운맛·채식 메뉴·새로운 음식 탐색·대기 상한·한 끼 상한, 혼잡·실내/야외, 밤 에너지·음악·대화, 도보 상한·귀가 시각. 분야별 취향 카드에서 필요한 조건만 추가한다.
- **6개 실행 조건과 20개 취향:** 총예산·시작 시간·일정 속도·이동수단·우천·음주 허용은 일정을 구성하는 실행 조건으로 적용하며 필수 모드와 내부 중요도 3을 고정한다. 화면에서 선호 강도로 조절하지 않는다. 나머지 20개 취향은 필수/선호/상관없음과 중요도 1~5를 고른다. 모든 조건은 이번 여행만/평소에도 적용을 구분하고, ‘아직 모름’은 ‘상관없음’과 별도로 남긴다. 기본 폼에서는 사용자가 수정한 항목만 제출할 때 선언으로 기록한다.
- **네 가지 여행 예시:** 미식·숙면·밤 문화·실속의 예시로 가상 후보와 비용 배분을 비교한다. 기본값과 예시 설정은 사용자 선언이 아니며 시작 시 `declared` 조건은 0개다. 예시를 누르면 기존 취향 기록이 초기화된다는 안내를 화면에 둔다.
- **여행 묶음:** 호텔 3, 점심 4, 오후 활동 4, 저녁 4, 야간 활동 3과 밤 일정 없음으로 최대 768개 조합을 구성한다. 카탈로그에는 숙소별 휴식 예시 3개가 추가돼 전체 21개이며, 휴식 예시는 조합에서 별도 업체로 넣지 않는다.
- **필수 검증:** 합계 예산·시간 비겹침·가상 영업시간·하루 종료·도보 상한·우천 실내·음주 제외·고정한 숙소 ID와 직접 지정한 필수 취향을 검사한다. 선호 조건의 후보 자료가 없으면 미확인으로 설명하고, 필수 자료가 없거나 조건을 어기면 가능한 추천에서 제외한다. 불가능하면 막힌 조건과 수정 입구를 보여 준다.
- **설명과 교정:** 직접 알려준 값·적용 기간·중요도, 맞춘 조건·타협·미확인, 원선언과 연결된 근거, 이전 결과와 달라진 점을 보여 준다. Core Ask는 기본 조건과 세부 취향의 답변을 각각 시험해 실제 결과를 바꾸는 질문을 고른다. 사용자는 적용 기간을 정하거나 질문을 건너뛸 수 있다.
- **사용자 제어:** 취향 수정·철회, 이번 조건을 지우고 평소로 복귀, 평소 취향을 남기고 새 여행 시작, 숙소 선택 고정/해제, 비 조건, 덜 걷기와 택시 전환, 동의 후 브라우저 저장·복원·삭제, JSON 및 일정 메모 내보내기.

비용은 **성인 1명·숙소 1객실 1박·KRW·세금/필수 수수료 포함이라는 가정**이다. 항공·서울 도착/출발 교통·다음 날 식사·자유시간 소비는 제외한다. 0원은 카탈로그에 명시된 무료 항목에만 쓰며 미확인 비용을 0원으로 바꾸지 않는다.

‘숙소 고정’은 같은 가상 숙소 후보를 유지하는 기능이다. 실제 예약의 날짜·객실·요금·취소 조건을 고정한 것이 아니다. 전체 일정 최적해를 보장하지 않으며 한 활동과 두 끼를 넣는 제한된 조합을 비교한다. 빈 시간은 자유시간으로 표시한다.

## Atlas 연결

| 원본 | 제품에서 하는 일 |
|---|---|
| [Core Interpretation](../../atlas/interpretation.js) · [문장 연결](conversation.mjs) · [로컬 해석](extractor.mjs) | 기존 prepare/review/resolve를 재사용한다. 인용 위치·원문·본인/현재·충돌·승인 내역을 검증하고 확인된 값만 선호 장부와 연결. 일반 언어 모델이나 별도 Atlas 엔진은 추가하지 않음 |
| [Core preferences](../../atlas/personalization.js) · [PATH 취향 계약](profile.mjs) | 기존 평소/이번 사건 기록을 사용하고, v2에서 `preferences.toDomain` 연결을 추가했다. 원시값·원선언 ID·시각·출처·기간을 보존해 Domain 관측으로 전달 |
| [Core travel](../../atlas/travel.js) | 초기판에서 추가한 순수 함수. 비용·시간·필수조건·잠금·제외·자료 시점의 묶음 적격성을 `feasible/pending/rejected`로 구분 |
| [Core Domain](../../atlas/domain.js) | v2에서 `objectives`를 추가해 제품의 예산·이동·예시 정렬 정책을 사용자 선언과 분리했다. 직접 알려준 원시 조건은 필수 여부·중요도·비교 방향과 함께 판단 |
| [Core Ask](../../atlas/ask.js) | 기존 질문 가치 계산을 재사용한다. 기본 조건과 16개 세부 취향의 각 답변으로 실제 추천을 다시 계산해 결과를 바꾸는 질문 선택 |
| [제품 모델](model.mjs) | 가상 장소·운영시간·이동·대기를 일정으로 만들고 엔진에 전달. 선언 사건 → 엔진 관측 → 판단 근거 → 화면 설명을 연결하고 예산표·변경 비교를 생성 |

`any`로 직접 고른 ‘아직 모름’은 평소 값을 덮는 마스크로 남긴다. 이 값과 연결된 mode/importance는 엔진용 관측에서 제외하며, ‘안다’거나 ‘좋아한다’는 선언으로 바꾸지 않는다. 명시적 조건 삭제는 이 마스크와 달리 평소 취향을 다시 드러낼 수 있다.

순위 점수는 설계된 선호 비교값이며 성격·만족 확률이 아니다. 가상 장소 자료의 기준시각과 사용자가 취향을 선언한 시각은 구분한다. 문장 해석은 제한된 한국어 표현을 비교하는 로컬 규칙이며 모든 자유 대화를 이해하지 않는다. 복합 부정·다인·알레르기·범위형 예산 등 지원 밖 표현은 보류하고, 직업·거주지로 소득이나 재산을 추정하지 않는다. 26개 입력 항목 모두의 자유문장 이해를 구현한 것은 아니다. 별도 ‘지금 상황’ 층, Trail 여행 사건 연결, Temper 실사용 효과 검증은 아직 없다. 설명은 원선언과 후보 자료에 연결한 로컬 템플릿이며 Vellum을 실제 호출한 결과가 아니다.

## 저장 범위

기본은 탭 메모리다. 체크박스에 동의하면 계산을 마친 여행 조건·숙소 잠금 ID·평소/이번 취향 사건 장부를 `synk-path-travel-local-v1` 키에 저장하고 이후 계산 때 갱신한다. 확인한 문장 조건에는 해석 검증용 입력 원문(한 번에 최대 4,000자)·인용·승인/수정 기록도 포함된다. 아직 확인하지 않은 제안은 저장하지 않는다. key 이름은 이전판과 호환하며 내용은 v3 버전으로 검증한다. v1 기록은 새 취향 장부를 비워 두고 v2의 직접 선택 장부는 유지한다. 옛 기본값이나 예시 값을 자동으로 사용자 선언으로 만들지 않는다.

평소와 이번 여행의 값에는 원선언 시각을 기준으로 30일 시효를 적용한다. 재계산·복원·새 여행 시작만으로 오래된 선언의 시각을 갱신하지 않는다. 이번 조건은 교정·철회하거나 ‘새 여행 시작’으로 종료할 수 있고, 여전히 유효한 평소 취향은 남는다. 평소 조건도 직접 바꾸거나 삭제할 수 있다. 평소 기준을 새로 지정하면 해당 조건의 이번 여행 예외를 끝내고 새 기준을 이번 여행에도 적용한다.

문장을 그대로 확인한 값은 원문 시각+30일을 넘지 않는다. 사용자가 값을 직접 정정하면 그 정정 시각의 새 선언으로 취급한다. 원문·해석·확인·선호 사건의 연결과 실제 만료시각을 저장 복원 때도 검사한다. 조건 삭제는 추천에서 철회하는 동작이며 과거 확인 기록까지 지우려면 전체 초기화로 저장된 조건을 삭제한다.

동의 해제와 전체 초기화는 해당 저장 키를 지운다. 다른 탭의 삭제 `storage` 이벤트를 받으면 현재 화면은 유지하고 저장 동의를 끄므로 후속 계산으로 자동 재저장하지 않는다. 다만 원자적인 다중 탭 revision/충돌 조정, 운영 계정의 동의·삭제 체계는 구현하지 않았다. 계정 동기화·다른 제품 자료 합류·방문 후 학습도 후속 범위다.

JSON은 사용자가 내보내기를 누를 때 원시 취향 장부·엔진 관측/판단 기록·현재 보고 있는 여행안과 최초 추천안의 구분을 포함한다. 일반 일정 메모는 읽을 수 있는 조건·일정·가상 자료 안내를 담고 내부 엔진 ID를 노출하지 않는다. 메모 보기와 전체 선택은 브라우저에서 제공하며 파일 저장 완료 여부는 브라우저의 다운로드에서 확인한다.

## 검증과 다음 범위

검사 실행 명령, 자동 검사, 직접 브라우저 확인과 캡처는 [검증 기록](qa/RESULTS.md)에 둔다. 로컬 합성 검증은 실제 여행 적합도·최저가·실제 휴대폰 성능·공개 운영의 증거가 아니다.

다음 범위는 첫 도시의 실제 데이터 검수, 날짜/다인 여행/객실 조건, 이동·시간 자료 갱신, 복합 자유 대화의 의미 해석과 실제 추출 품질 평가, ‘지금 상황’의 별도 만료, 운영 계정과 다중 탭 동시성, 여행 후 자기보고와 재추천이다. 48개 사업 조건 전체, 실시간 데이터 공급자 계약·유료 API/AI 검증·계정 연결·플랫폼 런처 편성·공개 배포는 이번에 수행하지 않았다.
