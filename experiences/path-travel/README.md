### 2026-10-09 후속: 여행 중 남은 일정 이어가기

여행 날짜부터 ‘여행 중 조정’에서 다녀온 장소와 건너뛸 장소를 직접 표시하고, 다시 출발할 시각·현재 출발 위치·앞으로 쓸 일행 전체 예산·남은 도보 상한을 입력한다. 위치는 역이나 장소의 대표 위치를 직접 고르며 GPS·실제 방문·지출을 자동 확인하지 않는다. 이전 계획의 예상 비용을 이미 쓴 돈으로 차감하지 않는다.

완료·건너뛴 곳을 제외한 **1~5곳의 남은 일정**을 미리 비교하고, 수락할 때만 현재 계획과 진행 기록을 바꾼다. 취소하거나 가능한 안을 찾지 못하면 이전 계획을 유지한다. 이미 다녀온 분야는 필수 포함을 충족한 것으로 처리하고, 유지한 나머지 장소·시간·예산·걷기·휴식·필수조건은 다시 검사한다. 일반 하루 계획은 계속 2~5곳이다.

‘오늘은 여기서 마치기’는 남은 계획을 끝내고 진행 기록을 남긴다. 완료·건너뜀 표시는 정정하거나 다시 후보에 넣을 수 있으며, 같은 날짜의 남은 시간을 새로 정해 여행을 이어갈 수 있다. 완료 시각은 입력한 시각까지 방문했다는 **자기보고**다. 방문 평가·평소 취향·여행 만족도는 자동 생성하지 않고 별도로 묻는다.

진행 기록에는 날짜·보고 시각·완료 장소/시각·건너뛴 장소·원래 필수 분야·마침 여부를 보관한다. 명시 동의한 브라우저 저장과 검증한 JSON 파일 전달에 포함하며 기존 v4 파일도 계속 연다. 중복·잘못된 장소/시각·완료 장소의 남은 일정 재등장·마친 여행의 남은 계획을 거부한다. [여행 중 검증과 화면](qa/progress-20261009/README.md), [자동 검사 246/246](qa/progress-20261009/tests.log)를 따른다. 서버 개인자료 계약 21/21과 생성본 검사도 통과했으며 원격 적용·실계정 호출은 하지 않았다.

### 2026-10-09 후속: 예약·식사 시간과 마지막 도착점

등록된 당일 장소에 최대 3개의 약속 시작 시각을 정할 수 있다. 일찍 도착하면 기다리고 늦는 코스는 제외한다. 실제 예약을 대신 진행하거나 업체의 예약 가능 여부를 확인하는 기능은 아니다. 방문은 장소의 계획용 체류시간을 사용한다.

식사는 취향대로 고르기·식당 방문 생략·정한 시간대에 식사 시작으로 나눈다. 시간대는 식사 종료 제한이 아니다. 약속·필수 음식 조건과 충돌하면 자동 삭제하지 않고 수정할 항목을 알린다. 완료한 식당이 있더라도 식사 생략은 사용자가 직접 선택한다.

출발점으로 돌아오거나 종로 지도·등록 숙소에서 마지막 도착점을 고르면 최종 이동까지 종료 시각과 전체/구간 도보 상한에 포함한다. 택시·대중교통이나 마지막 도착 시설의 이용은 포함하지 않는다. 쉬는 간격에 걸린 경우 예약·식사 시작 전에 필요한 휴식을 먼저 잡고, 기다리는 시간 안의 휴식을 이중 부과하지 않는다. 좌석·쉼터는 계속 미확인이다.

새 조건은 비교 후 적용, 여행 중 남은 일정, 브라우저 저장·여행 파일·계정 자료 계약과 공유용 일정에 연결했다. 완료·건너뛴 약속만 제거하며 미래 약속과 최종 도착점은 유지한다. 진행을 정정해 이미 제거한 약속을 되살릴 때에는 직접 다시 입력한다. 모바일 시간 요약 분리·지도 누름 영역 확대·위치 선택 적용 단추 고정을 반영했다. ### 2026-10-09 후속: 동행별 취향을 함께 반영하기

나를 포함해 최대 6명의 별칭·좋아함/회피·필수 조건을 이번 여행에 따로 넣는다. 프로필 수는 성인+아이 총인원을 넘을 수 없지만 전원 입력을 강제하지 않는다. 입력한 사람 수와 전체 인원을 함께 표시하고 빈 사람의 취향·성향·관계를 추정하지 않는다. 공통 취향과 각자의 취향은 별도로 유지한다.

모든 필수 조건을 먼저 검사하고, 자료가 없거나 반대 조건이면 제외한다. 필수끼리 충돌하면 누구의 어떤 조건인지 알리고 자동으로 풀지 않는다. 계산한 후보 안에서 사람마다 입력 항목 수로 정규화한 뒤 가장 덜 반영된 사람, 평균 반영, 기존 이동·공통 취향 기준 순으로 Core Domain이 비교한다. 제한된 후보 탐색이며 전역 최적이나 실제 만족도 확률은 아니다.

결과·변경 비교·복구·남은 일정에는 사람마다 반영 장소·회피 충돌·미반영·정보 부족을 구분해 보여 준다. 미확인 특성은 회피 성공으로 처리하지 않는다. 해당 분야 방문이 없어서 회피한 경우와 확인된 특성으로 회피한 경우도 구분한다. 남은 일정 설명은 앞으로 방문할 곳만 계산하며 일행이 계속 함께 간다는 전제다. 분리 동선은 지원하지 않는다.

동행별 조건은 동의한 기기 저장·여행 JSON·계정 자료 계약에 포함하지만 내 평소 선호나 방문 후기와 자동 합치지 않는다. 새 여행은 동행 프로필을 자동 이월하지 않는다. 공유용 TXT에는 개인별 별칭·취향을 넣지 않는다. 사람 추가·삭제·수정은 다시 계획을 적용하기 전까지 기존 여행을 바꾸지 않는다. [검증·소스·화면](qa/companions-20261009/README.md)과 [이용자 관찰 준비](qa/companions-20261009/FIELD-TEST.md)를 따른다. 실제 참가자·현장 만족도·운영 계정·공개 배포는 별도다.

## 이전 판: 실제 장소 구현 범위

- **공식 안내 11곳:** 식당 2곳, 차·카페 2곳, 호텔 2곳, 문화시설 5곳을 2026-10-07 확인 자료로 제공한다. 각 카드에 설명·주소·비용 안내·방문 전 확인 사항·공식 출처와 확인일을 표시한다. 호텔 요금은 날짜·객실·인원별 확인으로 안내하고 임의 고정 가격을 만들지 않는다. 문화시설의 무료 안내는 일반 관람 범위다.

- **후보 순서와 방문 목록:** 한식·차와 카페·전시와 문화·숙소 분야를 복수 선택하고, 남긴 반응을 반영한 후보 순서와 기본 순서를 전환한다. 원하는 장소를 직접 담고 방문 목록의 순서를 바꾸거나 뺄 수 있다. 필터·후보 순위가 바뀌어도 담은 목록은 유지하며 목록의 순서는 사용자가 정한다. 담기·삭제·순서 변경만으로 좋아함이나 실제 방문을 추론하지 않는다. 두 순서 모두 최적 이동 경로를 뜻하지 않는다.
- **직접 남기는 반응:** 장소별 ‘관심 있어요/덜 보고 싶어요’, 방문 후 ‘좋았어요/아쉬웠어요’를 수정하거나 철회한다. 방문 이유는 ‘즐긴 경험’, ‘분위기’, ‘비용 대비 만족’, ‘이동·접근’, ‘대기·혼잡’의 5개 라벨 중 선택하며 자유 텍스트는 수집하지 않는다. 이유는 개인 의견으로 남고 업체의 객관적인 특성이 되지 않는다. 같은 응답을 반복해도 점수·기록 수·시각이 누적되지 않는다. 부정 반응을 남긴 후보도 필터 안에서 낮은 순위로 계속 확인할 수 있다.
- **분야 선호:** 사용자가 별도로 ‘이 분야를 더/덜 보고 싶다’를 고른 경우에만 해당 분야 전체의 순서에 적용한다. 한 장소에 대한 반응이나 방문 이유로 다른 장소·분야의 성향을 추론하지 않는다. 장소 기록 삭제는 그 장소의 반응과 방문 평가만 지우며, 별도로 명시한 분야 선호는 별도 입구에서 지운다. 취향 기록 전체 삭제는 세 종류를 모두 지우고 새 기록 저장 동의도 해제한다.
- **확인과 가져가기:** 공식 안내와 장소명·전체 주소를 담은 지도 검색으로 연결한다. TXT에는 직접 담은 순서·설명·주소·비용·운영/휴관·찾아가기·각 공식 출처·확인일·지도 검색과 한국 시간의 메모 생성 시각을 넣는다. 개인 반응·방문 의견은 이 방문 목록 메모에 포함하지 않는다. 공식 안내 링크는 영업·객실 확보나 예약 완료를 뜻하지 않는다.
- **가상 모드와의 경계:** 아래 26개 조건과 문장으로 확인한 취향은 가상 일정에만 적용한다. 실제 후보에는 관심 분야 필터·별도 입력한 이번 비교 조건·직접 남긴 실제 장소 반응을 적용하며 가상 가격·조용함·청결·걷는 시간 등을 실제 업체 속성으로 옮기지 않는다. 화면 전환이나 한쪽 초기화가 다른 모드의 저장 기록을 지우지 않는다.

### 실제 장소의 Core 재사용

[real-guide.mjs](real-guide.mjs)는 기존 [Core Domain의 `decide`](../../atlas/domain.js)를 그대로 호출한다. 현재 장소 반응 11개·방문 평가 11개·분야 선호 4개, 최대 **26개 명시 반응 필드**을 사용한다. 후보 특성은 장소 ID와 분야의 일치 여부뿐이며 반응은 사용자의 선언(`declared`)으로 전달한다. 장소 반응 2·방문 평가 3·분야 선호 1의 제품 가중치를 합치고, 동점은 기존 후보 순서를 보존한다. 이유는 실제로 남긴 해당 장소·분야의 기록과 시각을 연결하며 상충하는 반응도 함께 남긴다. 숫자 점수를 만족 확률이나 업체 품질로 표시하지 않는다.

이번 작업은 **기존 Core의 제품 재사용**이며 엔진 코드의 발전·새 Atlas 엔진·별도 AI 판단 하네스 추가가 아니다. 실제 반응에는 가상 조건의 30일 만료를 적용하지 않으며 직접 수정·철회할 때까지 유지한다. 현장 방문 사실을 외부에서 검증하거나 실제 추천 만족도 향상을 측정한 결과도 아니다.

- **설명과 교정:** 직접 알려준 값·적용 기간·중요도, 맞춘 조건·타협·미확인, 원선언과 연결된 근거, 이전 결과와 달라진 점을 보여 준다. Core Ask는 기본 조건과 세부 취향의 답변을 각각 시험해 실제 결과를 바꾸는 질문을 고른다. 사용자는 적용 기간을 정하거나 질문을 건너뛸 수 있다.
- **사용자 제어:** 취향 수정·철회, 이번 조건을 지우고 평소로 복귀, 평소 취향을 남기고 새 여행 시작, 숙소 선택 고정/해제, 비 조건, 덜 걷기와 택시 전환, 동의 후 브라우저 저장·복원·삭제, JSON 및 일정 메모 내보내기.

비용은 **성인 1명·숙소 1객실 1박·KRW·세금/필수 수수료 포함이라는 가정**이다. 항공·서울 도착/출발 교통·다음 날 식사·자유시간 소비는 제외한다. 0원은 카탈로그에 명시된 무료 항목에만 쓰며 미확인 비용을 0원으로 바꾸지 않는다.

‘숙소 고정’은 같은 가상 숙소 후보를 유지하는 기능이다. 실제 예약의 날짜·객실·요금·취소 조건을 고정한 것이 아니다. 전체 일정 최적해를 보장하지 않으며 한 활동과 두 끼를 넣는 제한된 조합을 비교한다. 빈 시간은 자유시간으로 표시한다.

`any`로 직접 고른 ‘아직 모름’은 평소 값을 덮는 마스크로 남긴다. 이 값과 연결된 mode/importance는 엔진용 관측에서 제외하며, ‘안다’거나 ‘좋아한다’는 선언으로 바꾸지 않는다. 명시적 조건 삭제는 이 마스크와 달리 평소 취향을 다시 드러낼 수 있다.

순위 점수는 설계된 선호 비교값이며 성격·만족 확률이 아니다. 가상 장소 자료의 기준시각과 사용자가 취향을 선언한 시각은 구분한다. 문장 해석은 제한된 한국어 표현을 비교하는 로컬 규칙이며 모든 자유 대화를 이해하지 않는다. 복합 부정·다인·알레르기·범위형 예산 등 지원 밖 표현은 보류하고, 직업·거주지로 소득이나 재산을 추정하지 않는다. 26개 입력 항목 모두의 자유문장 이해를 구현한 것은 아니다. 별도 ‘지금 상황’ 층, Trail 여행 사건 연결, Temper 실사용 효과 검증은 아직 없다. 설명은 원선언과 후보 자료에 연결한 로컬 템플릿이며 Vellum을 실제 호출한 결과가 아니다.

## 이전 판: 저장 범위

두 모드 모두 기본은 탭 메모리다. **실제 장소**는 기존 `synk-path-real-places-v1` 키를 유지하고 내용은 v2로 검증한다. 기본 저장 동의는 관심 분야와 직접 담은 장소 ID·순서를 대상으로 한다. 기존 v1 기록을 복원해도 새 취향 기록 동의를 자동으로 켜지 않는다. 장소 반응·방문 평가와 이유·분야 선호·각 기록 시각은 별도 `feedbackConsent`에 동의했을 때만 같은 키에 저장한다. 새 동의 없이도 현재 화면의 반응은 후보 순서에 반영되지만 새로고침하면 남지 않는다.

저장 자료는 UTF-8 16KiB를 넘지 않으며 버전·허용 키·등록 ID·응답과 이유·유효한 ISO 시각을 검사한다. 미래 시각·비유한 값·원형 오염 키·손상된 기록은 복원하지 않는다. 같은 기록을 반복 선택하거나 복원한다고 원시각을 갱신하지 않는다. 새 취향 저장 동의만 해제하면 저장된 반응은 제거하고 관심 분야·방문 목록 저장은 유지한다. 기본 저장 동의 해제는 저장 키를 지우면서 현재 화면 선택과 반응을 유지하고, 전체 초기화는 실제 모드의 화면·메모·저장 키를 함께 지운다.

다른 탭이 저장 기록을 삭제하거나 취향 기록·취향 저장 동의를 바꿨다는 알림을 받으면 현재 화면은 유지하고 자동 저장 동의를 끈다. 최신 저장 내용을 보려면 새로고침한다. 같은 브라우저의 저장 안전장치이며 원자적 동시 편집·여러 기기 동기화·운영 계정 연결이 아니다.

**가상 일정**은 별도 체크박스에 동의하면 계산을 마친 여행 조건·숙소 잠금 ID·평소/이번 취향 사건 장부를 `synk-path-travel-local-v1` 키에 저장하고 이후 계산 때 갱신한다. 확인한 문장 조건에는 해석 검증용 입력 원문(한 번에 최대 4,000자)·인용·승인/수정 기록도 포함된다. 아직 확인하지 않은 제안은 저장하지 않는다. key 이름은 이전판과 호환하며 내용은 v3 버전으로 검증한다. v1 기록은 새 취향 장부를 비워 두고 v2의 직접 선택 장부는 유지한다. 옛 기본값이나 예시 값을 자동으로 사용자 선언으로 만들지 않는다. 아래 시효·취향 장부·JSON 내보내기 설명은 가상 일정에 해당한다.

평소와 이번 여행의 값에는 원선언 시각을 기준으로 30일 시효를 적용한다. 재계산·복원·새 여행 시작만으로 오래된 선언의 시각을 갱신하지 않는다. 이번 조건은 교정·철회하거나 ‘새 여행 시작’으로 종료할 수 있고, 여전히 유효한 평소 취향은 남는다. 평소 조건도 직접 바꾸거나 삭제할 수 있다. 평소 기준을 새로 지정하면 해당 조건의 이번 여행 예외를 끝내고 새 기준을 이번 여행에도 적용한다.

문장을 그대로 확인한 값은 원문 시각+30일을 넘지 않는다. 사용자가 값을 직접 정정하면 그 정정 시각의 새 선언으로 취급한다. 원문·해석·확인·선호 사건의 연결과 실제 만료시각을 저장 복원 때도 검사한다. 조건 삭제는 추천에서 철회하는 동작이며 과거 확인 기록까지 지우려면 전체 초기화로 저장된 조건을 삭제한다.

가상 모드의 동의 해제와 전체 초기화는 해당 저장 키를 지운다. 다른 탭의 삭제 `storage` 이벤트를 받으면 현재 화면은 유지하고 저장 동의를 끄므로 후속 계산으로 자동 재저장하지 않는다. 다만 원자적인 다중 탭 revision/충돌 조정, 운영 계정의 동의·삭제 체계는 구현하지 않았다. 계정 동기화·다른 제품 자료 합류·방문 후 Trail/Temper의 사건 및 성과 연결도 후속 범위다. 실제 장소에 직접 남긴 방문 평가로 후보 순서를 바꾸는 현재 기능과 구분한다.

JSON은 사용자가 내보내기를 누를 때 원시 취향 장부·엔진 관측/판단 기록·현재 보고 있는 여행안과 최초 추천안의 구분을 포함한다. 일반 일정 메모는 읽을 수 있는 조건·일정·가상 자료 안내를 담고 내부 엔진 ID를 노출하지 않는다. 메모 보기와 전체 선택은 브라우저에서 제공하며 파일 저장 완료 여부는 브라우저의 다운로드에서 확인한다.

시작 시간 조건은 화면 설명과 일정 메모에서 `시작 시간: 9시`·`시작 시간: 11시`로 표시한다. 이전 메모의 ‘시’ 단위 누락을 보완하고 두 값 모두 실제 TXT 내보내기 경로로 검사했다. 귀가 시각·걷는 시간·소음·불리언 조건도 변환된 한국어 라벨로 출력된다.

## 이전 판: 검증과 다음 범위

검사 실행 명령, 자동 검사, 직접 브라우저 확인과 캡처는 [검증 기록](qa/RESULTS.md)에 둔다. 로컬 합성 검증은 실제 여행 적합도·최저가·실제 휴대폰 성능·공개 운영의 증거가 아니다.

다음 범위는 실제 장소 정보의 지속적인 갱신과 조건 적용 범위 확대, 다인 여행/날짜별 객실 조건, 실제 이동·시간 자료, 복합 자유 대화의 의미 해석과 실제 추출 품질 평가, ‘지금 상황’의 별도 만료, 운영 계정과 다중 탭 동시성, 여행 후 자기보고의 Trail/Temper 연결과 실제 추천 만족도 검증이다. 공식 안내 11곳과 검증한 비교 조건·명시 반응으로 후보를 정렬하고 직접 방문 목록을 만드는 기능을 실제 여행 일정 최적화와 구분한다. 48개 사업 조건 전체, 실시간 데이터 공급자 계약·유료 API/AI 검증·계정 연결·플랫폼 런처 편성은 이번에 수행하지 않았다. 무료 체험의 공개 상태는 위 공개 검증 기록에서 별도로 확인한다.
