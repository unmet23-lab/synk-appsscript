# 업무 백업 · Windows 시험판 0.5.0

> **2026-11-12 꺼짐 · 동결.** 유호님 요청으로 이 PC의 0.5.0 자동 백업과 Windows 시작 등록(`SoloWorkBackup`)을 껐다. B2 사본과 Google 복구 정보는 그대로 있다. 이 Electron 판은 더 고치지 않는다. 새 기능은 [Rust 판](../solo-backup-rust/README.md)에서 [상품화 로드맵](../solo-backup-rust/ROADMAP.md) 순서대로 만든다.

선택한 작업 폴더를 암호화해 외장 드라이브 또는 Backblaze B2 클라우드에 자동 백업하고, 최신 완료본을 새 폴더에 복구하는 운영자 시험판입니다. Windows x64용이며 Node.js나 별도 백업 프로그램을 설치할 필요가 없습니다. 외장·로컬과 클라우드는 각자의 설정과 복구 키를 사용하며 동시에 켤 수 있습니다.

## 시작하기

1. 배포 폴더 전체를 보관하고 `WorkBackup.exe`를 실행합니다. exe만 옮기면 실행되지 않습니다.
2. 외장·로컬 탭에서는 작업 폴더와 백업 보관 폴더를 선택합니다. 분실·디스크 고장에 대비하려면 PC와 분리된 외장 드라이브를 사용하세요. 같은 PC 안의 폴더는 기능 시험용입니다. 클라우드는 아래 연결 절차를 따릅니다.
3. 클라우드 복구 연결이 준비된 시험판은 Google에 처음 한 번 로그인하고 `보관 확인됨`을 확인합니다. 복구 정보를 앱이 외부에 보관하므로 키 파일을 직접 챙기지 않아도 됩니다. 외장·로컬 백업이나 자동 보관이 준비되지 않은 연결은 복구 키 파일을 PC와 분리된 장소에 저장합니다. 이 파일로 백업을 열 수 있으므로 다른 사람에게 보내지 마세요.
4. **보호 시작**을 한 번 누릅니다. 연결·작업 폴더를 확인하고 Windows 로그인 시 실행, 정기 백업, 지금 백업을 이어서 진행합니다. 시작 등록이 실패하면 별도로 표시하며 백업은 시도합니다. 처음 연결·로그인·복구 정보 보관이 필요한 경우에는 그 단계를 먼저 안내합니다.
5. PC가 켜져 있고 앱이 실행 중일 때 로컬은 15분, 클라우드는 60분마다 시도합니다. 화면에서 마지막 완료본과 다음 예약을 확인합니다. 자동 백업 중 창을 닫으면 트레이에서 계속 실행합니다. 트레이 메뉴로 종료하면 현재 작업을 마친 뒤 앱이 종료되고 자동 백업도 멈춥니다. 휴대용 시험판이므로 앱 폴더를 옮기면 시작 등록을 다시 설정해야 합니다. 잠든 PC를 깨우거나 종료된 앱을 서버가 대신 실행하지 않습니다.

작업에 집중할 때는 **1시간·4시간·12시간 일시정지**를 고릅니다. 앱을 껐다 켜도 기한을 기억하고 앱 실행 중 기한이 지나면 재개합니다. 진행 중인 백업을 강제 종료하지 않습니다. 일시정지 중 `지금 백업`은 한 번만 실행하고 정지 기한을 유지합니다. 내부 24시간 이력의 시간은 정지 중에도 흐릅니다. 자동 백업을 완전히 끄려면 상세 설정을 사용합니다.

복구는 저장할 상위 폴더를 선택하면 새 하위 폴더를 만들고 내용을 검증합니다. 원래 작업 폴더·백업 저장소를 복구 대상으로 선택할 수 없습니다. 선택한 작업 폴더별로 `01-폴더이름` 형태로 복구하며 원래 위치는 `복구경로.json`에 기록합니다. 새 PC에서는 `기존 백업 복구하기`로 복구 키 파일과 실제 `work-backup-…` 저장소를 선택합니다. 이 연결은 복구 전용이며 기존 백업을 지우지 않습니다.

복구할 파일을 저장할 여유 공간이 필요합니다. 중간 압축파일을 디스크에 만들지 않습니다. 기존 Windows 계정의 권한을 새 PC에 강제로 적용하지 않고, 현재 사용자가 읽을 수 있는 새 파일로 만듭니다. 파일 내용·일반 폴더 구조·기본 수정 시각을 복구하며 원래 소유자·접근 권한·링크 관계·NTFS 확장 메타데이터는 복원 범위에서 제외합니다. 하드링크는 각각 독립 파일로 복구합니다. 심볼릭 링크나 특수 파일이 있으면 쓰기 전에 해당 경로를 알리고 중단합니다.

## 필요한 파일만 골라 복구

**파일 골라 복구 → 파일 이름·폴더 검색 → 파일 선택 → 선택한 파일 복구** 순서로 진행합니다. 저장할 상위 폴더를 한 번 고르면 새 하위 폴더에 고른 파일만 복구하고, 크기와 저장 후 SHA-256을 확인합니다. 기존 전체 복구도 그대로 사용할 수 있으며 두 복구 결과를 따로 표시합니다. 복구 시작 안내는 완료 표시가 아닙니다.

- 목록을 열 때의 **최신 완료본 하나**를 사용합니다. 열린 뒤 새 백업이 끝나도 목록의 기준은 바뀌지 않습니다. 이전 시점 선택은 아직 제공하지 않습니다.
- 검색은 파일 경로의 부분 문자열을 찾습니다. 대소문자·한글 조합을 정규화하지만 `[` 같은 기호도 문자 그대로 찾으며 와일드카드가 아닙니다. 검색어나 페이지를 바꿔도 이미 고른 파일은 유지합니다.
- 한 페이지는100개, 한 번에 고를 수 있는 파일은 **최대1,000개**입니다. `검색 결과 전체 선택`은 모든 페이지의 결과를 기존 선택에 더합니다. 합계가 한도를 넘으면 일부만 추가하지 않고 기존 선택을 유지합니다. 선택한 개수와 내용 용량을 함께 표시합니다.
- 목록은 메모리에만 보관하며 연 뒤30분이 지나거나 연결을 바꾸면 만료됩니다. `새로 불러오기`는 선택을 비웁니다. 저장 위치를 고르는 동안 만료되면 복구를 시작하지 않습니다. 이미 시작한 작업은 고정된 선택으로 계속합니다.
- 모든 작업 폴더를 합쳐 파일·폴더 등20만 항목, 원시 목록128MiB, 한 줄1MiB까지 읽습니다. 목록 한도를 넘으면 전체 복구를 이용합니다. 안전하지 않은 경로·중복 이름은 거절합니다. 심볼릭 링크·특수 파일은 이 시험판의 선택·전체 복구 모두 지원하지 않습니다.
- 파일별로 내려받으므로 많은 작은 파일은 전체 복구보다 느리고 API 호출·다운로드가 늘 수 있습니다. 표시한 내용 용량은 전체 전송량·요금의 상한이 아닙니다. 현재 파일별 실행 제한은6시간이며 전체 작업시간을 보장하지 않습니다.
- 실패하면 미완료 표시와 이미 받은 파일을 새 폴더에 남기고, 이전 성공 결과·원본·백업 오류 기록을 보존합니다. 자동 재시도·이어받기는 아직 없으며 다시 실행하면 별도의 새 폴더를 만듭니다. 복구 전용 연결도 지원하지만 원격 배타 잠금이 남으면 진행하지 않습니다. 앱이 잠금을 강제로 풀지 않습니다.

## B2 클라우드 연결

클라우드 탭에서 **연결 정보가 준비되어 있습니다**가 보이면 작업 폴더 선택→연결 준비→Google 복구 정보 보관 확인(또는 별도 장소에 복구 키 저장)→보호 시작 순서로 진행합니다. 저장된 연결을 사용할 때 두 키 입력칸은 비워 둡니다. 연결 준비만으로는 작업 파일을 업로드하거나 자동 백업을 켜지 않습니다. 클라우드만 연결된 PC는 앱을 열 때 해당 연결부터 보여 줍니다. 정상 연결의 상세 설정·키 입력은 접어 두며 오류가 있는 복구 연결은 펼쳐 안내합니다.

수동으로 연결할 때는 B2 버킷 화면의 S3 Endpoint, 버킷 이름, 그 버킷에만 접근하는 Read and Write 애플리케이션 키를 입력합니다. HTTPS B2 공식 Endpoint만 허용하며 master key나 공통 고객 키를 사용하지 않습니다. 키는 앱 설정 폴더의 Windows 암호 보관 기능으로 저장하고 화면·로그·복구 키 파일에 포함하지 않습니다. 키 변경은 새 키로 같은 저장소인지 확인한 뒤 적용됩니다.

- 버킷은 **Private**, 기본 암호화 활성화, **Keep only the last version**, Object Lock 비활성화로 준비합니다. 업로드 후 일정 일수가 지났다는 이유로 파일을 지우는 규칙은 사용하지 않습니다. 앱의 암호화 저장소는 서로 연결된 객체를 오래 재사용합니다. [restic B2 준비 안내](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html#backblaze-b2)
- 앱은 버킷·시간·접속 권한을 확인하지만 보관 규칙을 자동 조회하거나 변경하지 않습니다. 연결 전 B2 콘솔에서 확인합니다. 계정 지역은 생성 후 바꿀 수 없으며 US East·US West 등 해당 계정의 실제 Endpoint를 사용합니다. [B2 지역 안내](https://www.backblaze.com/docs/cloud-storage-data-regions)
- Google 자동 보관을 완료했다면 새 PC에서 같은 Google 계정으로 로그인해 아래 순서로 복구합니다. 수동 복구에는 **복구 키 파일과 B2 접근 키**가 모두 필요합니다. 접근 키는 계정에서 다시 발급할 수 있지만 복구 키의 암호와 외부 사본을 모두 잃으면 백업을 해독할 수 없습니다. 클라우드 복구 연결은 복구 전용이며 자동 백업·과거 정리를 수행하지 않습니다.
- 저장·다운로드·API 한도는 B2 계정 조건을 따릅니다. 무료 한도를 무제한으로 간주하지 않습니다. 전체 점검과 복구는 다운로드를 사용합니다. 비용 한도 오류가 명확하면 다음 UTC 날짜까지 자동 시도를 보류합니다. [B2 한도와 알림](https://www.backblaze.com/docs/cloud-storage-data-caps-and-alerts)

## Google 계정으로 자동 복구

소유자 시험판은 복구 전용 B2 연결을 운영자가 준비합니다. 이 준비가 끝난 앱에서 **Google 연결**을 누르고 처음 한 번 로그인·권한을 허용하면 복구 키와 읽기 전용 접근 정보가 Google Drive의 앱 전용 공간에 저장됩니다. 작업 파일은 계속 B2에 있고, Google에는 작은 복구 정보만 보관합니다. 일반 Drive 파일 목록에는 이 앱 전용 정보가 보이지 않습니다. [Google 앱 데이터 안내](https://developers.google.com/workspace/drive/api/guides/appdata)

새 PC에서는 앱 폴더 전체를 설치한 뒤 **클라우드 → Google 연결 → 내 백업 찾기 → 복구할 백업 선택 → 복구 연결 → 최신본 복구** 순서로 진행합니다. 이전 PC의 설정 파일·B2 키·복구 키 파일을 옮길 필요가 없습니다. 기존 클라우드 연결이 있는 앱에 다른 저장소를 덮어쓰지는 않습니다. Google에서 가져온 연결은 읽기 전용이며, 새 PC에서 백업을 계속하는 연결 전환은 후속 범위입니다.

- 자동 보관은 업로드 뒤 다시 내려받아 내용·계정·해시를 확인한 경우에만 완료로 표시합니다. 앱 실행 중 시작 후와 하루 한 번 재확인하고, 인터넷 오류는 간격을 늘려 재시도합니다. 확인된 원격 사본이 사라지면 현재 키로 다시 만듭니다. 이전 복구 사본을 앱이 자동 삭제하지 않습니다.
- 복구 정보에는 백업을 해독할 암호와 해당 버킷의 **Read Only** 키가 함께 있습니다. Google 계정 접근 권한이 곧 백업 읽기 권한입니다. Google 계정과 앱 프로젝트를 신뢰하는 방식이며, Google 계정이 침해되어도 내용을 숨기는 독립적인 종단간 암호화라고 부르지 않습니다. Google 계정의 2단계 인증과 계정 복구 수단도 유지해야 합니다.
- B2 복구 키는 쓰기·삭제·관리 권한을 거절합니다. B2 기본 Read Only 권한에는 다운로드 권한 위임(`shareFiles`)이 포함됩니다. 복구 앱은 저장소를 변경하지 않는 명령만 허용하며, 다른 작업의 배타적 잠금이 있으면 복구를 멈춥니다. [B2 키 권한](https://www.backblaze.com/docs/cloud-storage-application-keys)
- 이 시험판의 Google 등록 이름은 **SYNK**입니다. 기존 SYNK 계정 프로젝트에 별도의 데스크톱 OAuth 클라이언트를 만들었으며, 같은 프로젝트의 다른 클라이언트와 앱 데이터 신뢰 범위를 공유합니다. 프로젝트·클라이언트를 지우면 복구 연속성이 깨질 수 있습니다. OAuth 클라이언트 설정은 설치본에 포함되지만 사용자 토큰·B2 키·복구 암호는 포함되지 않습니다.
- 앱의 **연결 해제**는 해당 PC의 Google 토큰만 지웁니다. 외부 사본이나 다른 PC의 연결을 지우지 않습니다. 분실 PC의 접근을 끊으려면 Google 계정의 SYNK 연결과 B2 키를 계정에서 관리해야 하며, Google 연결 해제는 같은 프로젝트의 다른 SYNK 앱에도 영향을 줄 수 있습니다. 이미 내려받은 정보까지 회수할 수는 없습니다.
- 소유자 시험에서는 프로젝트와 별개로 찾을 수 있는 비공개 Drive 폴더에도 수동 복구 키를 한 벌 보관하고 원격 재다운로드를 검증했습니다. 이 보조 사본에는 B2 키가 없으며, 필요하면 B2 계정에서 접근 키를 다시 발급합니다. 앱이 일반 Drive 폴더 사본을 계속 동기화하는 기능은 아닙니다.

## 보관·검증 기준

- 화면의 기본 복구 지점은 **가장 최근에 완전히 읽고 저장 구조까지 확인한 백업**입니다. 파일을 읽지 못한 부분 백업은 완료본을 대체하지 않습니다. 오류에 나온 프로그램을 닫고 재시도합니다.
- 첫 성공 백업 후 전체 데이터를 읽어 점검합니다. 이후 로컬은 하루, 클라우드는 30일마다 실행합니다. 각 백업의 구조 점검은 매번 수행합니다. 화면은 마지막 전체 점검 시각과 최신 백업 시각을 구분합니다.
- **작은 파일 확인**은 완료된 백업에서 비어 있지 않은 일반 파일 한 개(8MiB 이하)를 골라 실제로 내려받고 인증·해독·크기를 확인합니다. 평문은 메모리에서만 처리하며 임시 파일·원본 파일명·내용 해시를 기록하지 않습니다. 첫 백업 후와 이후 7일마다 시도하고 상세 화면에서 직접 다시 확인할 수도 있습니다. 목록이 너무 크면 건너뛰고 30일 후 재시도합니다. 대상 없음·건너뜀·연결 실패는 성공으로 표시하지 않습니다.
- 표본의 크기 불일치가 확인되면 이전 백업 정리를 보류합니다. 단순 연결 중단과 구분하며, 문제가 있던 스냅샷의 같은 표본을 재확인하거나 사용자가 실행한 전체 점검이 성공해야 보류가 풀립니다. 다른 파일의 성공으로 보류를 풀지 않습니다. 작은 파일 한 개의 성공은 전체 파일 복구·원본과의 내용 일치·새 PC 로그인·Windows 부팅 복구의 증명이 아닙니다. 8MiB는 표본 내용의 한도이며 목록·색인·pack·재시도 등 실제 다운로드는 더 클 수 있습니다.
- 최근 24시간 스냅샷은 실수에 대비해 내부적으로 유지합니다. 이후 성공한 백업과 정상 점검이 있을 때 이전 기록을 정리합니다. 저장소를 만든 앱만 정리하며 최신 완료본은 남깁니다. 24시간 내 변경량만큼 용량이 추가로 필요합니다.
- 클라우드 자동 정리는 다운로드를 줄이기 위해 일부만 쓰는 pack을 다시 묶지 않습니다. 따라서 실제 보관 용량은 최신 파일 크기보다 클 수 있으며, 최신본 하나와 정확히 같은 용량을 보장하지 않습니다. B2에서 숨겨진 이전 객체는 keep-last 수명 주기 적용 후 약 하루 뒤 정리됩니다. 장기 이력 상품·용량 자동 최적화는 후속입니다.
- 암호화·중복 제거·복구는 restic 0.19.1이 담당합니다. 이 PC의 암호는 Windows DPAPI로 보관합니다. 같은 Windows 사용자 권한의 악성 프로그램으로부터 모든 데이터를 보호하는 기능은 아닙니다.
- 복구 전에 파일 목록·유형·크기를 확인합니다. restic이 인증·복호화한 내용을 스트림으로 받아 새 경로에 쓰고, 목록의 모든 파일·폴더와 저장 후 SHA-256을 대조합니다. 쓰기·검증 실패 시 미완료 폴더를 남기고 전체 점검 전에는 과거 백업을 정리하지 않습니다.
- 점검 실패 시 이전 성공 시각은 이력으로 남습니다. 그 이력이 현재 저장소의 무결성을 보장하지는 않습니다. 오류를 해결하고 다시 점검합니다. 저장소가 손상되었을 때 자동으로 잠금을 강제 해제하거나 수리·삭제하지 않습니다.

## 이번 시험판의 범위

회원가입·결제, 고객별 용량 관리, Windows 전체 이미지 복구, 열린 데이터베이스의 일관된 백업, 랜섬웨어 불변 보관, 원격 장치 제어는 아직 제공하지 않습니다. 네트워크 공유 경로·연결 폴더·정션은 지원하지 않습니다. 로컬·클라우드 프로필마다 하나의 저장소와 처음 선택한 폴더 목록을 사용합니다. 복구 목록은 작업 폴더 하나당 파일·폴더 100만 개까지 확인합니다. 온라인 전용 파일은 공급자 상태에 따라 다운로드가 필요하거나 읽기에 실패할 수 있습니다. 파일 하나가 4GiB 이상이면 FAT32 드라이브에는 저장할 수 없습니다.

미서명 운영자 시험판이어서 Windows가 게시자를 확인하지 못했다는 안내를 표시할 수 있습니다. 외부 고객 배포 전 코드 서명·업데이트 검증·고객별 접근 분리·실물 새 PC와 큰 데이터 시험이 필요합니다. `build-manifest.json`은 배포 파일의 SHA-256 목록이며 서명을 대신하지 않습니다.

## 운영자가 준비할 것

로컬 시험에는 새 계정·서버·유료 개발 프로그램이 필요하지 않습니다. 클라우드는 운영자 B2 계정으로 연결합니다. 물리 서버나 TB 디스크를 선구매할 필요는 없습니다.

- **운영자용 Backblaze B2 계정 1개**: 비공개 버킷, 지출 알림, 시험 버킷에만 접근하는 백업용 키와 별도의 Read Only 복구 키를 준비합니다. 사용자 승인 자료로 실제 백업·복구를 확인했습니다. 계정 정보와 키는 공개 소스에 넣지 않습니다. [공식 키 관리 안내](https://www.backblaze.com/docs/cloud-storage-create-and-manage-app-keys)
- **Google OAuth 데스크톱 클라이언트**: Drive API와 `openid email drive.appdata` 범위를 사용합니다. 프로젝트·클라이언트를 유지하고 계정 연결을 먼저 검증합니다. `RecoveryService.prepareReadKey()`는 운영자 준비용이며 화면에서 공통 키를 받거나 고객에게 나눠 주는 기능이 아닙니다. 현재 소유자 연결은 준비를 마쳤고, 일반 고객의 무설정 가입·복구 키 발급은 서버 단계에서 구현합니다.
- 고객은 B2 계정을 만들지 않도록 앱 계정·고객별 저장소·단기 접근 권한을 서버에서 발급하는 구조로 확장합니다. 공통 운영자 키를 고객 앱에 포함하지 않습니다.
- 도메인·구독 결제 계정·Windows 코드 서명은 고객 배포 단계에서 준비합니다. 물리 서버나 TB 디스크를 선구매할 필요는 없습니다.

## 개발·재현

외부 의존성은 공식 Windows x64 restic 0.19.1과 Electron 44.10.0 런타임입니다. 바이너리는 git에 넣지 않습니다. restic ZIP SHA-256은 `da948ad707ed690426473aaba2046cd61f8f90f6f0e7dab6be0d5796531de67d`, EXE는 `b0dd1fd21eea5d8fe1325f55f7118213c21f36de8a261e04c0624a5ab9fd7830`입니다. [공식 릴리스](https://github.com/restic/restic/releases/tag/v0.19.1)에서 받고 해시를 대조합니다.

```powershell
$env:SOLO_BACKUP_RESTIC = 'C:\개발도구\restic.exe'
node --test experiences/solo-backup/tests/*.test.cjs
node experiences/solo-backup/scripts/package.cjs 'C:\개발도구\electron-dist' $env:SOLO_BACKUP_RESTIC 'C:\배포\새폴더' 'C:\보안\google-desktop-client.json'
```

개발 실행은 Electron에 이 패키지 경로를 전달합니다. `--test-mode`와 `SOLO_BACKUP_TEST_STATE`를 함께 주면 시험 상태를 별도로 보관하고 Windows 시작 등록을 금지합니다. 기능 시험은 임시 폴더에 만든 자료만 사용하며 원래 작업 파일·실제 클라우드·시작 레지스트리를 바꾸지 않습니다.

소스에서 개발·포장할 때에는 이 패키지 폴더에서 `npm ci --ignore-scripts`로 tar-stream 3.2.2와 jose 6.2.16 및 고정 의존성을 준비합니다(각 MIT). 배포본에는 포함되므로 사용자가 설치할 것은 없습니다. 네 번째 포장 인자는 Google Console에서 받은 데스크톱 클라이언트 설정이며, 생략하면 Google 연결을 제공하지 않습니다. 개발에서는 `SOLO_BACKUP_GOOGLE_CLIENT`에 설정 파일 경로를 전달합니다. 토큰·앱 비밀 보관 파일은 포장 입력으로 넣지 않습니다.

Windows 암호 보관함이나 Electron의 Local State를 잃으면 새 앱 상태에서 Google으로 복구하거나 수동 복구 키와 B2 접근 키로 연결합니다. 기존 저장소가 있는 상태의 손상된 계정 연결 기록은 다른 계정에 자동 게시하지 않도록 차단합니다. 클라우드 초기화가 중단되면 기존 UUID·암호·폴더를 유지해 같은 연결로 재시도하며 다른 저장소를 자동으로 만들지 않습니다.

설계·검토와 확인 결과는 소스 패키지의 [QA](QA.md)에, 비교 제품 20개군의 기능·사용 후기·채택 근거와 후속 우선순위는 [조사 기록](RESEARCH.md)에 기록합니다.
