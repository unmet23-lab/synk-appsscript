# 업무 백업 · Windows 시험판 0.1.0

선택한 작업 폴더를 암호화해 별도 폴더·외장 드라이브에 자동 백업하고, 최신 완료본을 새 폴더에 복구하는 첫 시험판입니다. Windows x64용이며 Node.js나 별도 백업 프로그램을 설치할 필요가 없습니다.

## 시작하기

1. 배포 폴더 전체를 보관하고 `WorkBackup.exe`를 실행합니다. exe만 옮기면 실행되지 않습니다.
2. 작업 폴더와 백업 보관 폴더를 선택합니다. 분실·디스크 고장에 대비하려면 PC와 분리된 외장 드라이브를 사용하세요. 같은 PC 안의 폴더는 기능 시험용입니다.
3. `백업 준비` 후 복구 키 파일을 별도 장소에 저장합니다. 이 파일로 백업을 열 수 있으므로 다른 사람에게 보내지 마세요. PC 및 백업 드라이브와 따로 보관해야 합니다.
4. 자동 백업을 시작합니다. PC가 켜져 있고 앱이 실행 중일 때 15분마다 시도합니다. 자동 백업 중 창을 닫으면 트레이에서 계속 실행합니다. 트레이 메뉴로 종료하면 현재 작업을 마친 뒤 앱이 종료되고 자동 백업도 멈춥니다.
5. 필요하면 `Windows 로그인 시 시작`을 직접 켭니다. 휴대용 시험판이므로 앱 폴더를 옮기면 시작 등록을 다시 설정해야 합니다. 잠든 PC를 깨우거나 종료된 앱을 서버가 대신 실행하지 않습니다.

복구는 저장할 상위 폴더를 선택하면 새 하위 폴더를 만들고 내용을 검증합니다. 원래 작업 폴더·백업 저장소를 복구 대상으로 선택할 수 없습니다. 선택한 작업 폴더별로 `01-폴더이름` 형태로 복구하며 원래 위치는 `복구경로.json`에 기록합니다. 새 PC에서는 `기존 백업 복구하기`로 복구 키 파일과 실제 `work-backup-…` 저장소를 선택합니다. 이 연결은 복구 전용이며 기존 백업을 지우지 않습니다.

복구할 파일을 저장할 여유 공간이 필요합니다. 중간 압축파일을 디스크에 만들지 않습니다. 기존 Windows 계정의 권한을 새 PC에 강제로 적용하지 않고, 현재 사용자가 읽을 수 있는 새 파일로 만듭니다. 파일 내용·일반 폴더 구조·기본 수정 시각을 복구하며 원래 소유자·접근 권한·링크 관계·NTFS 확장 메타데이터는 복원 범위에서 제외합니다. 하드링크는 각각 독립 파일로 복구합니다. 심볼릭 링크나 특수 파일이 있으면 쓰기 전에 해당 경로를 알리고 중단합니다.

## 보관·검증 기준

- 화면의 기본 복구 지점은 **가장 최근에 완전히 읽고 저장 구조까지 확인한 백업**입니다. 파일을 읽지 못한 부분 백업은 완료본을 대체하지 않습니다. 오류에 나온 프로그램을 닫고 재시도합니다.
- 첫 성공 백업 후와 하루 한 번 전체 데이터를 읽어 점검합니다. 큰 외장 드라이브에서는 오래 걸릴 수 있습니다. 각 백업마다 전체 데이터를 다시 읽지는 않습니다.
- 최근 24시간 스냅샷은 실수에 대비해 내부적으로 유지합니다. 이후 성공한 백업과 정상 점검이 있을 때 이전 기록을 정리합니다. 저장소를 만든 앱만 정리하며 최신 완료본은 남깁니다. 24시간 내 변경량만큼 용량이 추가로 필요합니다.
- 암호화·중복 제거·복구는 restic 0.19.1이 담당합니다. 이 PC의 암호는 Windows DPAPI로 보관합니다. 같은 Windows 사용자 권한의 악성 프로그램으로부터 모든 데이터를 보호하는 기능은 아닙니다.
- 복구 전에 파일 목록·유형·크기를 확인합니다. restic이 인증·복호화한 내용을 스트림으로 받아 새 경로에 쓰고, 목록의 모든 파일·폴더와 저장 후 SHA-256을 대조합니다. 쓰기·검증 실패 시 미완료 폴더를 남기고 전체 점검 전에는 과거 백업을 정리하지 않습니다.
- 점검 실패 시 이전 성공 시각은 이력으로 남습니다. 그 이력이 현재 저장소의 무결성을 보장하지는 않습니다. 오류를 해결하고 다시 점검합니다. 저장소가 손상되었을 때 자동으로 잠금을 강제 해제하거나 수리·삭제하지 않습니다.

## 이번 시험판의 범위

클라우드 업로드, 회원가입·결제, 고객별 용량 관리, Windows 전체 이미지 복구, 열린 데이터베이스의 일관된 백업, 랜섬웨어 불변 보관, 원격 장치 제어는 아직 제공하지 않습니다. 네트워크 공유 경로·연결 폴더·정션은 지원하지 않습니다. 한 앱 설정에는 하나의 저장소와 처음 선택한 폴더 목록을 사용합니다. 복구 목록은 작업 폴더 하나당 파일·폴더 100만 개까지 확인합니다. 온라인 전용 파일은 공급자 상태에 따라 다운로드가 필요하거나 읽기에 실패할 수 있습니다. 파일 하나가 4GiB 이상이면 FAT32 드라이브에는 저장할 수 없습니다.

미서명 내부 시험판이어서 Windows가 게시자를 확인하지 못했다는 안내를 표시할 수 있습니다. 외부 고객 배포 전 코드 서명·업데이트 검증과 실제 클라우드 복구 시험이 필요합니다. `build-manifest.json`은 배포 파일의 SHA-256 목록이며 서명을 대신하지 않습니다.

## 운영자가 준비할 것

지금 로컬 시험에는 새 계정·서버·유료 개발 프로그램이 필요하지 않습니다. 외장 저장장치가 있다면 그것으로 시작할 수 있습니다. 실제 고객의 PC 분실까지 앱 하나로 보호하려면 다음 단계에서 클라우드를 연결합니다.

- **운영자용 Backblaze B2 계정 1개**: 비공개 버킷, 지출 알림, 시험용 버킷에만 접근하는 애플리케이션 키를 준비합니다. 실제 업로드·유료 결제는 아직 하지 않았습니다. 키는 채팅이나 공개 저장소에 넣지 않습니다. [공식 키 관리 안내](https://www.backblaze.com/docs/cloud-storage-create-and-manage-app-keys)
- 고객은 B2 계정을 만들지 않도록 앱 계정·고객별 저장소·단기 접근 권한을 서버에서 발급하는 구조로 확장합니다. 공통 운영자 키를 고객 앱에 포함하지 않습니다.
- 도메인·구독 결제 계정·Windows 코드 서명은 고객 배포 단계에서 준비합니다. 물리 서버나 TB 디스크를 선구매할 필요는 없습니다.

## 개발·재현

외부 의존성은 공식 Windows x64 restic 0.19.1과 Electron 44.10.0 런타임입니다. 바이너리는 git에 넣지 않습니다. restic ZIP SHA-256은 `da948ad707ed690426473aaba2046cd61f8f90f6f0e7dab6be0d5796531de67d`, EXE는 `b0dd1fd21eea5d8fe1325f55f7118213c21f36de8a261e04c0624a5ab9fd7830`입니다. [공식 릴리스](https://github.com/restic/restic/releases/tag/v0.19.1)에서 받고 해시를 대조합니다.

```powershell
$env:SOLO_BACKUP_RESTIC = 'C:\개발도구\restic.exe'
node --test experiences/solo-backup/tests/engine.test.cjs
node experiences/solo-backup/scripts/package.cjs 'C:\개발도구\electron-dist' $env:SOLO_BACKUP_RESTIC 'C:\배포\새폴더'
```

개발 실행은 Electron에 이 패키지 경로를 전달합니다. `--test-mode`와 `SOLO_BACKUP_TEST_STATE`를 함께 주면 시험 상태를 별도로 보관하고 Windows 시작 등록을 금지합니다. 기능 시험은 임시 폴더에 만든 자료만 사용하며 원래 작업 파일·실제 클라우드·시작 레지스트리를 바꾸지 않습니다.

소스에서 개발·포장할 때에는 이 패키지 폴더에서 `npm ci --ignore-scripts`로 고정된 스트림 읽기 라이브러리(tar-stream 3.2.2, MIT)와 의존성을 준비합니다. 배포본에는 포함되므로 사용자가 설치할 것은 없습니다. Windows 암호 보관함이 손상되면 시작 화면에서 원래 복구 키를 선택해 다시 연결할 수 있습니다. 초기화가 실패한 저장소는 지우지 않고 이전 설정·암호화 키를 보존한 뒤 저장 위치를 다시 선택할 수 있습니다.

설계·검토와 확인 결과는 소스 패키지의 `QA.md`에 기록합니다.
