# 한글 단계 · SYNK WORLD (MVP)

한글을 한 글자도 모르는 사람이 혼자 가·나·다를 배우는 WORLD 콘텐츠다. 2026-10-03 유호님 방향 「20개국 정도에 출시할 예정이라 많은 국가들이 필요해. 그래서 일단 한국어로 mvp만 만들어도 괜찮을 것 같아」에 따라 **도움 언어 없이 한국어로만** 만들었다. 글을 못 읽어도 할 수 있게 시범·그림·소리로 이끈다(설계 §2 「보여 주는 안내가 먼저다」). 설계 정본은 [한글 단계 설계](../../docs/한글단계_설계.md)다.

**둘째 판(10-03):** 받침 두 단원(U6 ㄴㄹㅁㅇ · U7 ㄱㄷㅂ과 [ㄷ]으로 나는 ㅅㅈ), 헷갈리는 짝 고르기, 몽글에게 가르쳐 주기, 졸업과 졸업 뒤 몸풀기를 더해 「처음 → 받침까지 읽기 → 졸업 → 미니게임」이 한 바퀴 이어진다.

이 판은 **로컬 MVP**다. 학습 허브(4280)에는 붙였고, 운영 배포·WORLD 자유 연습 단추·학생 효과 확인·사람 귀로 한 소리 확인은 아직 하지 않았다.

```powershell
node experiences/hangul-stage/server.mjs      # http://127.0.0.1:5240/
node --test experiences/hangul-stage/core.test.mjs
node experiences/hangul-stage/qa/flow.cjs     # 서버를 띄운 뒤, 헤드리스 크롬 화면 점검
node tools/build-hangul-stage.js [--check]    # 한글 층 지도와 학습 묶음 만들기
```

## 아틀라스 연결

- **Strata 한글 층:** [strata/hangul.json](../../strata/hangul.json)(글자·단원·헷갈리는 짝·닮은 모양)을 [tools/build-hangul-stage.js](../../tools/build-hangul-stage.js)가 [strata/maps/hangul.json](../../strata/maps/hangul.json)으로 만든다. 글자 31개(받침은 `role: final`, 이름 「받침 ㄴ」)는 `letter` 마디, 단원 순서는 `prerequisite`, 짝은 `contrasts_with`(소리·모양, `by_ear` — 받침 ㄷ·ㅅ·ㅈ끼리는 `false`)다. 지도 판은 `hangul-2-62539127c8b3`(마디 33, 선행 129, 짝 31). 능력은 `ko.hangul.sound`(듣기)·`ko.hangul.read`(읽기) 둘이다. 같은 도구가 이 지도와 기존 Atlas 게임 어댑터를 묶어 `atlas-learning.js`를 만든다([learning-entry.cjs](learning-entry.cjs)).
- **기록:** 문항 하나 = 아틀라스 문항 하나(`present → delivery → help → answer`, [learning.mjs](learning.mjs)). 다른 게임과 같은 학습 기록(`synk.atlas.learning.v1.*`)에 남고, WORLD 계정 호스트 안에서 열면 그 계정 기록으로 동기화된다. 소리가 끝까지 난 뒤의 답만 소리 문항의 근거가 되고, 다시 듣기·천천히 듣기·시범은 도움으로 남는다. 짝 맞추기는 짝 하나가 문항 하나다. 짝 고르기·가르쳐 주기도 보기 고르기 문항(보기 둘이면 `binary-choice`)으로 남는다.
- **글자 진도는 따로 둔다:** 아틀라스의 증거 규칙은 문항 묶음의 첫 시도를 세는데, 글자 익히기는 같은 글자를 되풀이하는 일이라 글자별 상태·다음 복습은 이 경험의 판단([core.mjs](core.mjs))으로 둔다. 혼자 열면 이 기기(`synk.hangul-stage.v1`), WORLD 안에서는 그 계정·학습 동의 판의 구역(`synk.account.{id}.r{revision}.hangul-stage.v1`, WORLD 저장소와 같은 접두)이다. 계정을 알 수 없으면 저장하지 않는다. 기기를 넘는 글자 진도 동기화는 아직 없다(아래 남은 일).
- AI·서버 호출은 없다. 사용자 수에 비례해 드는 비용이 없다.

## 소리

2026-09-19 결정은 「글자 소리는 정한 목소리 하나만, 귀로 확인한 파일만」이다. **10-03 목소리는 Typecast로 정했다**(유호님 「다이브 말고 타입캐스트로 바꿨어」 — Typecast API Lite가 결제돼 있다. DIVE는 결제 기록이 없다). **쓸 목소리는 혜리다**(10-03 유호님: 비교한 일곱 목소리 가운데 「혜리랑 우리가 고른 서현이 제일 낫네. 여자는 컨텐츠 특성에 따라서 둘 중 하나 사용하면 될것같아」 — 한글 단계는 상큼한 목소리를 찾던 자리라 혜리).

- **목소리 고르기:** 같은 도구의 http://127.0.0.1:5241/compare 에서 후보 7명(하나·정희·미리내·혜리·다솜·가희, 기준 서현)의 공식 미리듣기를 듣고, 연결 뒤 `POST /generate {"compare":true}`로 만든 같은 글자 8개(아·어·오·으·애·에·가·나무)를 목소리마다 나란히 듣는다. 후보는 Typecast 한국어 여자 목소리 66개의 공식 미리듣기에서 음높이·밝기·억양 폭·빠르기를 재서 밝은 쪽을 고르고 아이·캐릭터처럼 높은 쪽을 뺐다([qa/voice-candidates.json](qa/voice-candidates.json), 10-03 유호님 「서현 괜찮은데 다른 상큼한 목소리 없을까?」). 비교용 소리는 저장소 밖(`Documents/synk-vendor/hangul-voice/compare`)에 둔다. 고른 목소리는 `POST /voice {"id":"tc_…"}`로 바꾼다. 10-03 비교 결과 혜리(`tc_62e8f21e979b3860fe2f6a24`)로 정했고 도구의 기본값도 혜리다.
- **만들기:** `node tools/한글단계_목소리.cjs`(목소리를 바꾸려면 `--voice tc_… --name 이름`) → http://127.0.0.1:5241 에서 유호님이 기존 Typecast API 키를 붙여 넣는다(키는 메모리에만 2시간, 결제·충전 기능 없음). 그 뒤 이 컴퓨터의 명령으로 `POST /generate {"sample":true}`가 8개를 만들어 한 개당 크레딧 쓰임을 재고, `{"all":true}`가 [pack.mjs](pack.mjs)의 `audioManifest()` 목록(392개 · 484자: 글자 소리·음절·받침 음절 180·낱말·간판·명패)의 나머지를 만든다. 어림 쓰임이 남은 월 크레딧의 10%를 넘으면 멈추고 묻는다. 감정 normal·빠르기 0.9·ssfm-v30, 앞뒤 무음을 걷은 64k mp3가 `assets/voice/`에, 원본 wav는 저장소 밖 `Documents/synk-vendor/hangul-voice/raw`에 남는다.
- **확인과 승인:** 만든 목록은 `assets/voice/voices.candidate.json`이다. 유호님이 [voice-check.html](voice-check.html)(글자 31 · 음절 표 120 · 받침 음절 9 × 20 · 낱말)에서 귀로 확인한 뒤 `node tools/한글단계_목소리.cjs --approve "유호님 10-0X 귀 확인"`으로 [voices.json](assets/voice/voices.json)에 옮긴다. 앱은 `approved: true`인 목록만 먼저 튼다.
- 그전과 목록에 없는 소리는 기기의 한국어 음성(브라우저 `speechSynthesis`, 기기 안 음성 우선)으로 낸다. 기기마다 목소리가 달라 들리는 소리가 다를 수 있다. 한국어 음성도 승인된 파일도 없는 기기는 시작 단추를 잠그고 안내한다.
