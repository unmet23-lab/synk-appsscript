# 빈칸 베기 · SYNK LAB PLAY

문장을 읽고, 튀어 오르는 펠트 낱말 조각 넷 중 **빈칸에 맞는 것만 그어 베는** 3D 한국어 읽기 액션 게임. 2026-10-02 MVP.

사용자 요청(2026-10-02): 레이싱·리듬처럼 3D로 속도감·액션을 살린 학습 게임 아이디어 다섯 개 중 「3번 재미있어보인다. 3번 만들어봐」. 같은 날 정한 방향 「일단 mvp만 만들고 나레이션이나 디테일한거는 mvp 나오고나서 잡자」에 따라 **핵심 놀이·학습 연결·아틀라스 기록**부터 만들었다. MVP를 본 뒤 「타격감이나 사운드가 정말 중요한 게임이니까 제대로 신경 써줘야」에 따라 **타격감과 소리는 핵심 놀이로 함께 만들었다**(아래 ‘손맛’·‘소리’). 나레이션·배경 장면은 MVP 뒤.

## 실행

```powershell
node experiences/blank-slice/server.mjs        # http://127.0.0.1:5217/
```

다른 SYNK 게임과 기기 내 학습 기록을 이으려면 공통 입구 서버로 연다: `node experiences/learning-hub/server.mjs` → `http://127.0.0.1:4280/blank-slice/`(허브 7번 카드). 교사 과제와 연결하려면 [WORLD·교사 연결 로컬 MVP](../teacher-world/README.md)의 WORLD에서 빈칸 베기를 연다. Node.js만 필요하고 외부 요청·유료 호출은 없다.

## 플레이

1. **연습 한 문장**(처음 한 번, 기록 안 함): 정답 조각에 노랗게 빛나는 테두리가 숨 쉬듯 밝아졌다 어두워지고, 천천히 떠오른다. 연습 던지기에는 버터색 조각을 쓰지 않아 ‘노란 조각’과 헷갈리지 않는다. 그어 베면 시작.
2. **한 판 12문장**: 위에 빈칸 문장이 나오고, 읽을 시간(글자 수에 비례, 최대 2.6초) 뒤 낱말 조각 넷이 튀어 오른다.
3. **베기**: 손가락·마우스로 맞는 조각을 그어 벤다. 한 번 그으면 먼저 닿은 조각 하나만 베인다(천천히 끄는 것은 베기가 아니다). 넓은 화면에서는 조각의 번호(1~4) 키로도 벤다.
   - 맞히면 세상이 잠깐 멈칫한 뒤 조각이 두 쪽으로 갈라지고, 낱말이 곡선을 그리며 빈칸으로 날아가 끼워진다. 100점 + 연속 보너스(최대 +100), 연속일수록 조각이 조금씩 빨라진다(체공 3.6초 → 최소 2.6초).
   - 틀리면 정답 조각에 빛나는 테두리가 생겨 천천히 떨어지고, 아래에 정답·벤 말·이유가 나온다(실패음 없음).
   - 두 번 던져도 못 베면 ‘놓침’: 정답을 보이기 전에 멈춘 보기(읽기 확인, 시간 제한 없음)에서 답을 고르고, 그다음 정답과 이유를 본다. 손이 늦어 놓친 것과 몰라서 놓친 것을 가르려는 단계라 점수·연속은 주지 않는다(10-03 유호님 「3번」: 벨 때의 손맛은 그대로, 읽기 확인은 놓친 문장에만).
4. **결과**: 맞힌 수·별·점수·최고 연속, 12문장 복습(○ 맞음 · × 다시 볼 것 · – 놓침과 멈춘 보기에서 고른 답), 두 읽기 능력의 기록, 아틀라스가 고른 다음 판의 이유.

천천히 모드(입구·쉬기 창): 읽을 시간과 체공 시간이 1.4배. Esc는 쉬기, 탭을 떠나면 저절로 쉰다.

## TOPIK I 연결

공통 목표는 [TOPIK I 1~2급 준비](../../docs/미니게임_TOPIK_I_학습기준.md). 이 게임은 **읽기 34~39번(빈칸에 알맞은 낱말·조사·문형 고르기)** 과 같은 능력을 맡는다. 시험의 4지선다를 그대로 액션으로 옮겼다.

| 학습 항목(Strata) | 문장 예 | 수 |
|---|---|---|
| 낱말 뜻 읽기 `ko.reading.vocabulary` | 목이 말라요. (물)을 마시고 싶어요 · 사과 세 (개) · 도서관에서는 (조용히) · (별로/전혀)+안 | 15 |
| 조사·문형 읽기 `ko.reading.grammar` | 학교(에서) · 동생(이) 있어요 · 영화를 (보러) · 시간이 (있으면) 같이 · (아직) 안 했어요 · 사진을 (찍으면) 안 돼요 | 21 |

- 원고 [`content.mjs`](content.mjs): 36문장(난도 1: 28, 난도 2: 8) + 연습 1. 자체 창작한 초급 문장이며 공식 기출이나 교원 검수 문항이 아니다.
- 보기 넷 중 맞는 것은 하나뿐이 되게 썼다. ‘그래서/그리고’처럼 둘 다 말이 되는 보기는 넣지 않았고, ‘(  )을’처럼 빈칸 뒤 조사가 붙으면 보기를 모두 받침이 맞는 낱말로 맞춰 **조사 모양으로 답이 드러나지 않게** 했다(시험으로 지킨다).
- 별·점수는 게임 진행 기준이다. TOPIK 급수·합격 판정으로 바꾸지 않는다.

## 아틀라스 개인화

공통 원본 `atlas/`·`strata/`를 빌드한 `atlas-learning.js`(직접 고치지 않는다, `node tools/build-game-learning.js`)를 쓴다. 연결은 [`learning.mjs`](learning.mjs).

| 때 | 아틀라스가 하는 일 | 화면에서 달라지는 것 |
|---|---|---|
| 문장이 나올 때 | `present`: 문장 하나 = 읽기 문항 하나(`single-choice`, 보기 4, 음성 없음) | 기록에 남는다 |
| 벨 때 | `answer`: 처음 벤 조각의 정오 | 같은 문장을 다시 맞혀도 새 근거로 세지 않는다 |
| 놓쳤을 때 | 멈춘 보기에서 고른 답으로 `answer`(정답을 보이기 전의 독립 응답). 확인 중에 그만두면 `answer(correct: null, assessable: false, reason: 'unanswered')` | 놓친 문장도 읽기 기록이 남는다. 문장마다 답은 한 번만(벤 말 또는 멈춘 보기의 답) |
| 한 판 구성 | `recommend`로 36문장의 필요 순서를 받아 12문장을 고른다. 두 항목을 4문장 이상씩 넣고, 고른 뒤에는 쉬운 것부터 | 놓친 항목의 문장이 다음 판에 들어간다(한 판은 쉬운 문장부터 늘어놓아 맨 앞이라고는 하지 않는다). 입구·결과에 이유가 나온다 |
| 결과 | 두 항목의 상태(최근 혼자 해냄·조금 더 연습·확인하는 중 등) | ‘다음 연습’ 표시. 공통 입구(허브)의 추천도 이 기록을 읽는다 |

- 판단은 학습 항목 × 언어 난도 × 응답 형식별이다. 다른 게임의 O/X·주문 조합 정답률을 섞지 않는다.
- 처음 하는 사람은 아틀라스 순서 대신 난도 1 문장부터.
- 실제 확인(2026-10-02): 첫 판을 10/12로 마치자(1 틀림·1 놓침) 아틀라스가 「조사·문형 읽기는 아직 기록이 적어요」를 이유로 두 번째 판을 조사·문형 8문장 + 새 낱말 4문장(난도 2 포함)으로 바꿨다.
- 단독 실행·학습 허브는 기기(브라우저) 기록이다. WORLD 연결 로컬 MVP에서는 기존 계정 호스트가 학생별 기록과 교사 과제 수행을 동기화한다. 정식 SYNK 로그인·운영 서버 연결은 별도 단계다.
- **체공 시간 맞춤(순간 맞춤, `FLOW_SLICE`, 2026-10-03):** 조각이 떠 있는 시간 배율(1.3·1.2·1.1·**1**·0.95·0.9, 굵은 값이 원래 게임)을 그 사람에 맞춘다. 맞는 조각을 베면 성공(쓴 체공 시간 비율이 압박), 다른 조각은 시간 안의 실수, 놓치면 시간 부족이다. 놓치면 "조각이 조금 더 오래 떠 있어요", 일찍 바르게 베면 한 칸씩 빨라진다. 연속 가속(콤보마다 −0.12초)은 그대로 두되, 맞춤 학습 입구에서 「피곤해요」를 고른 날은 콤보 가속을 끄고 순간 맞춤도 올리지 않는다. 연습 문장은 맞춤 없음. 쉬는 동안은 시간을 재지 않는다. 시험: `flow.test.mjs`.
- **문항 판:** 문장·보기·정답을 바꾸면 그 문항의 판을 올린다(`ITEM_VERSION`). 같은 빈칸·같은 정답을 다듬은 판은 같은 계열로 두어 예전 판을 본 사람에게는 반복으로 남는다. 10-03 단서 문장을 더한 v06·v07·e01·e08이 2판이다. 내용이 바뀌었는데 판을 안 올리면 `learning.test.mjs`의 내용 지문 표가 잡는다.
- 기록이 거절돼도(다른 탭에서 기록을 지움, WORLD 수행이 끝남) 확인 창이 멈추지 않고 그 답은 기록 없이 지나간다.

### WORLD의 개인화 목표와 교사 과제

- 교사·WORLD 카탈로그의 `blank-reading`은 실제 36문장의 영역·난도·응답 형식을 사용한다. 학생의 목표 문항을 최대 3개 확정하고, 게임은 `coach.assignment()`의 문항·계열 쌍과 영역·난도를 모두 대조해 그 문장만 출제한다.
- 난도 2 조사·문형 과제를 쉬운 낱말 문제로 끝낼 수 없다. 틀린 응답도 과제 수행에는 남지만, 맞힘·도움·반복과 독립 수행은 서버에서 구분한다. 두 번 놓친 것은 오답으로 세지 않으며, 정답 공개 전 시간 제한 없는 보기에서 실제로 고른 답을 읽기 수행에 기록한다. 이 답으로 베기 점수나 콤보를 주지 않는다.
- 목표 연습은 일반 12문장 플레이의 판 수·최고 점수를 덮어쓰지 않는다. WORLD에서는 계정 연결 안내가 나오고, 기기 전체 기록을 지우는 단추 대신 WORLD 계정 설정에서 기록을 관리한다. 과제 판인지는 판을 시작할 때 정한다(2026-10-03). 판 중에 WORLD 과제가 닫혀도(다른 과제를 열었거나 끝남) 그 판이 자유 연습의 판 수·최고 점수가 되지 않고, 결과 화면이 '이 WORLD 과제는 끝났어요'라고 알리며 다시 하기 단추를 막는다.
- 확인 스크립트: `node experiences/blank-slice/qa/linked-targets.cjs`(headless Chrome, 설치된 Playwright 사용). 격리한 교사 과제 작성 → WORLD의 실제 입력 → 교사 결과를 검사하며 실제 학생 효과·공개 운영을 입증하지 않는다. 숨긴 Electron의 그리기 억제를 피하도록 시험 실행 환경을 바꿨으며 게임 시간·점수·학습 사건을 주입하지 않는다.
- 최신 확인 결과(2026-10-03): 실제 UI **32/32**. 난도 1은 자연 낙하 뒤 정적 보기로 3문항 응답(베기 점수 0), 난도 2는 실제 키보드 베기 3회로 완료했다. 각각 교사 결과 3/3·새로고침 유지·390px 배치를 확인했다. 결과: `qa/linked-target-verification.json`. 예전 40개 Node·25개 UI 기록과 실행 범위를 구분한다.
- 문항 판이 바뀐 오래된 과제는 고정 목표 전체를 실행할 수 있는지 먼저 확인한다. 하나라도 없어지면 일부만 출제하지 않고 새 과제 배정을 요청한다. 기존 결과의 문항 판은 보존한다.

## 화면 · 3D

- Three.js r180(`vendor/`, 바람길과 같은 판). 카메라는 고정이다(흔들기·기울이기·확대 없음). 움직이는 것은 조각뿐이고, 글자가 늘 읽히도록 회전은 작은 흔들림(±0.1~0.18라디안)으로만 둔다.
- 낱말 조각: 둥근 모서리에 두께가 있는 펠트 판. 앞면은 실제 펠트 사진(`tex-cream`)을 펠트 색에 곱한 그림에 SUIT 굵은 글씨. 색(버터·라피스·크림·코랄·연코랄·초록)은 던질 때마다 섞어서 **색이 답을 알려 주지 않는다**.
- 베기: 그은 방향에 수직인 면으로 판을 잘라(클리핑 면) 두 쪽이 갈라지고, 단면은 펠트 속 색으로 보인다. 손맛은 아래 ‘손맛’.
- 배치: 좁은 화면은 2열 × 위아래 두 줄, 넓은 화면은 4열. 같은 열의 두 조각은 같은 순간·같은 체공 시간으로 던져 공중에서 늘 위아래로 떨어져 있다(겹치지 않게).
- 판 바탕은 키트의 넓은 크림 펠트 판(`wide-cream`, 반복 무늬 없음)과 아래 코랄 펠트 받침, 조각 그림자는 벽에 옅게 떨어진다. 단추·배지·칩은 [펠트 부품](../../docs/디자인/펠트부품/README.md)(입장 검사에서 흰 띠를 걷은 판). 입구 그림의 조각은 게임 무대를 실제로 찍은 그림(`qa/bake-hero.cjs` → `assets/hero-pieces.webp`).
- 움직임 줄이기: 부스러기·반짝이·충격파·화면 번쩍임·느린 화면·낱말 날아가기·빈칸 눌림을 끄고, 화면 전환 애니메이션을 없앤다. 조각 던지기·두 쪽 갈라짐·멈칫·베인 선은 놀이 자체라 남긴다.

## 손맛(타격감)

카메라는 흔들지 않는다(멀미). 타격감은 멈칫·빛·조각의 움직임·소리·진동으로 낸다. 수치는 `stage.mjs`의 `FEEL`.

| 순간 | 화면 | 소리·진동 |
|---|---|---|
| 손을 휘두름 | 손끝은 굵고 꼬리는 뾰족한 칼날 자취(코랄 빛·흰 심 세 겹). 프레임 사이의 손 움직임까지 받는다(`getCoalescedEvents`) | 빠르게 휘두르면 ‘휙’(빠를수록 크고 밝게, 손 방향으로 좌우 이동) |
| 조각이 튀어 오름 | 바닥 펠트에서 먼지가 일고, 조각이 잠깐 길쭉해졌다 펴진다 | ‘뽁’(한 번 던질 때 한 번 — 넓은 화면은 넷을 0.12초 간격으로 던지는데 조각마다 울리면 베는 소리를 흐린다) |
| 벤 순간(0ms) | 세상이 멈칫한다(히트스톱: 맞힘 85ms·틀림 55ms). 두 쪽이 하얗게 번쩍이고 베인 선이 칼빛처럼 뻗는다 | ‘딱·사각·퉁·톡’ + 맞히면 ‘팅’. 진동 18ms(틀림 10ms) |
| 멈칫 뒤 | 두 쪽이 벌어지며 돌고, 펠트 부스러기(겉색·속색)와 털이 튄다. 충격파 고리 | |
| 맞힘만 | 화면이 아주 옅게 한 번 번쩍, 금빛 칼빛·고리·반짝이 열 개, 0.25배 느린 화면에서 0.52초 동안 제 속도로 | 연속할수록 ‘팅’이 C 펜타토닉 계단을 오른다(4연속부터 두 칸 위 음 겹침), 4연속마다 몽글 기쁨 |
| 낱말이 빈칸에 끼워짐(약 0.47초) | 빈칸이 납작하게 눌렸다 튀어 오르고, 펠트 반짝이가 튄다. 점수가 0.42초 동안 올라간다 | ‘톡’ 15ms 뒤 사운드킷 ‘획득’(픽). 진동 8ms |
| 틀림 | 같은 칼빛(코랄)·고리, 반짝이·느린 화면 없음. 정답 조각에 빛나는 테두리 | 같은 베는 소리에서 ‘팅’만 빠짐, 0.24초 뒤 몽글 ‘괜찮아’ |
| 결과 | 별이 하나씩 튀어나온다 | 사운드킷 ‘성취’ 뒤 별마다 도·미·솔 |

- 손 빠르기는 최근 50ms 자취로 잰다(화면 주사율과 상관없음). 0.14 px/ms보다 느리게 끌거나 50ms에 8px 미만으로 움직이면(조각 위에 얹은 손가락의 떨림) 베지 않는다. 첫 손가락 하나만 따라간다(두 번째 손가락이 닿아도 두 손가락 사이를 그은 선으로 보지 않는다).
- 진동은 되는 기기(안드로이드 등)에서만, 소리를 끄면 함께 쉰다. 키보드(1~4)로 벨 때도 칼자국·‘휙’이 난다.
- 멈칫은 계산한 85ms여야 한다. 처음 만든 판은 벨 때마다 셰이더를 새로 컴파일해 화면이 50~600ms 굳었다(실측). 그래서 무대를 만들 때 베기에 쓰는 재질(잘린 앞·옆면, 속살, 빛 테두리, 부스러기, 털, 그림자, 진짜 낱말 조각)을 1픽셀 영역에 미리 그려 두고 버리지 않는다(`stage.mjs` `warmUp`). 무대는 입구 화면에서 브라우저가 한가할 때 미리 만든다. 지금은 벨 때 새로 만드는 셰이더가 0개이고, 벤 앞뒤 프레임은 16.7ms다(`qa/frames.cjs`).

## 소리

- 사운드킷 파일(획득·성취·몽글 목소리)은 크기를 바꾸지 않고 그대로 튼다.
- 손맛 소리(휘두르기·베기·던지기·끼워짐·별)는 `sfx.mjs`가 Web Audio로 그 자리에서 합성한다(파일 0개). 사운드킷의 셋째 가족 **‘게임 효과음’**이다([사운드킷 문서](../../docs/브랜드_사운드킷/_사운드킷.md), 토큰 `사운드.게임효과음`). **2026-10-02 유호님 확정: A 「펠트 사각」, 크기 알맞게(아래 값 그대로), 손맛 그대로** — 「A로 하고 크기는 알맞게 해줘 아냐 과하거나 약하지않아. 전체적으로 훌륭해」.
- 사운드킷 규칙 네 가지를 시험으로 지킨다(`sfx.test.mjs`): ① 한 소리 400ms 이하 ② 실패음 없음 — 틀려도 같은 베는 소리에서 ‘팅’만 빠짐 ③ 음은 사인·트라이앵글만 ④ 음높이는 C 펜타토닉 안(미끄럼은 시작·끝음).
- **A · 펠트 사각**(확정, 바람·펠트 결에 짧고 넓은 잡음). 고르지 않은 **B · 맑은 사인**(잡음 없음)은 비교용으로 시청 페이지에만 남긴다. 좁은 대역 잡음은 쓰지 않는다(무전 잡음처럼 들린다는 08-28 귀 검수).
- 시청 페이지: `http://127.0.0.1:5217/sound-lab.html` — 한 번 베기 흐름, 연속 여섯 번, 틀리게 베기, 하나씩 듣기. 게임은 늘 A로 나고, 주소에 `?sfx=clean`이 있을 때만 그 접속에서 B가 난다(기억하지 않는다).
- 크기: 오프라인으로 구워(`qa/sound.cjs`) K 가중 순간 음량(BS.1770)을 재고 맞췄다. 기준은 사운드킷(몽글 목소리 −11.6, 성취 −15.6, 획득 −20.8). 베기 맞힘 −17.8(꼭대기 −3.3dBFS), 틀림 −23.7, 휘두르기 −23~−29, 던지기 −26.6.
- 끝에 부드러운 리미터(곡선)를 둔다. −3dBFS까지는 손대지 않고(사운드킷 파일은 원본 그대로 지나감), 소리가 겹칠 때만 눌러 −0.6dBFS를 넘지 않는다. 브라우저 압축기(DynamicsCompressor)는 한계 아래 소리까지 줄여서(획득 −4.3 → −8.2dBFS 실측) 쓰지 않는다.
- 나레이션은 MVP 뒤.

## MVP 뒤에 잡을 것

- 사용자 확인: 문장 난도, 조각 크기·속도(손맛·소리는 2026-10-02 확정).
- 교원 검수: 36문장의 자연스러움·난도·학습 항목 태그.
- 디테일(MVP 뒤로 미룬 것): 나레이션, 근무지 같은 배경 장면, 조각 종류(과일·도시락 등), 콤보 연출, 하루 도전·순위.
- 문항 수: 같은 항목·난도의 새 문장이 더 있어야 ‘보충’ 상태에서 벗어날 수 있다.
- 공통 코인(`play-common`)·공개 사이트·정식 계정 운영 연결은 하지 않았다. WORLD·교사의 로컬 계정 연결은 위 범위에 포함한다.
