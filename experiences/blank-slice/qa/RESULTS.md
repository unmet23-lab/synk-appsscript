- 클리핑 0(전체 27개). 하나씩 울리는 소리는 화면 가장자리·4연속 겹음인 가장 큰 베기(−1.8dBFS)만 리미터에 0.2dB 미만으로 닿는다.
- 고친 것: 처음에는 베기가 −26으로 몽글 목소리보다 16 작았다(목소리에 묻힘). 브라우저 압축기(DynamicsCompressor)는 한계 아래 소리까지 줄여(획득 −4.3 → −8.2dBFS) 곡선 리미터로 바꿨다. 곡선 리미터의 4배 과표본은 날카로운 순간음에서 꼭대기를 넘어(1.002) 껐다. 베기의 층(딱·사각·퉁·톡)을 1~3ms씩 엇갈려 시작해 꼭대기가 한꺼번에 겹치지 않게 했다. 던지기는 넓은 화면에서 조각마다 울려 판 하나에 40번 가까이 났다 → 한 번 던질 때 한 번.

| 한 판 구성 | 12문장·두 항목 4문장 이상·처음엔 난도 1만·쉬운 것부터·겹침 없음, 아틀라스가 어려운 문법 문장을 앞에 두면 그 문장들이 들어옴 |
| 점수·속도·배치·베기 | 별 기준·연속·놓침 집계 / 연속일수록 빨라지되 2.6초 아래로 안 감·천천히 1.4배 / 좁은 화면은 같은 열의 두 조각을 같은 순간에 던짐 / 그은 선이 먼저 닿는 조각 하나만 |
| 실제 엔진 5개 | 문항 정보가 Strata 지도·형식 검사 통과 / 벤 정답은 혼자 해낸 기록·놓침은 아님 / 같은 난도의 조사·문형을 세 번 틀리면 다음 판 첫 순위가 조사·문형이고 결과에 ‘다음 연습’ / 기록이 반대인 두 학생은 첫 문장 항목이 다름 / 아틀라스 없음·오류에서 원고 순서 |

## 브라우저 · 실제 손동작으로 한 판 끝까지

`node experiences/blank-slice/qa/capture.cjs` (설치된 Chrome, 임시 프로필). 원문 [`capture-results.json`](capture-results.json).

- 휴대폰은 **실제 터치 이벤트로 긋기**(CDP `Input.dispatchTouchEvent`), 데스크톱은 마우스로 긋기 + 5번 문장부터 숫자 키.
- 계획: 연습(노란 조각 베기) → 1번 맞힘 → 2번 일부러 틀림 → 3번 놓침(두 번 떨어뜨림) → 나머지 맞힘 → 결과 → 다음 판.

## 만들며 고친 것

| 본 것 | 고친 것 |
|---|---|
| 조각이 계속 돌아 ‘을’처럼 짧은 글자가 옆으로 눌려 보임 | 회전을 작은 흔들림(±0.1~0.18라디안)으로 — 글자가 늘 읽히게 |
| 그림자가 조각보다 한 칸 아래로 진하게 떨어져 무거워 보임 | 그림자 벽을 가깝게(z −0.9), 빛을 정면 쪽으로, 진하기 0.1 |
| 판 바탕의 펠트 결이 바둑판처럼 반복돼 보임 | 키트의 넓은 크림 펠트 판(`wide-cream`)으로 |
| 채운 낱말과 뒤 조사 사이가 띄어 쓴 것처럼 벌어짐(‘우유 를’) | 채운 빈칸의 여백을 줄여 ‘우유를’로 붙음 |
| 입구 그림의 작은 낱말 조각에 펠트 판의 실땀 무늬(작은 부품의 실땀은 점선처럼 보임 — 마감 점검표) | 게임 무대의 실제 3D 펠트 조각을 찍은 그림으로 교체 |
| 입구 그림 굽기 때 게임 흐름이 자기 조각을 던져 엉뚱한 낱말이 찍힘 | 확인용 훅 `hold()`로 흐름을 멈추고 굽기 |
| 틀린 뒤 정답 조각을 천천히 떨어뜨리면 위치가 튈 수 있음(닫힌 식) | 한 걸음씩 움직이는 방식으로 |
| 좁은 화면에서 긴 말일 때 두 열의 조각이 가로로 겹칠 수 있음 | 열 가운데 배치 + 열 폭 안으로 크기 조절 |
