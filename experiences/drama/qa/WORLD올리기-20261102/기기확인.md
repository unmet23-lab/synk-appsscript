# 기기 확인 — 드라마 시범판 WORLD 판 (2026-11-02 · 웹툰 그림 시안 세션 요청 · 유호님 「덧붙여 보내」)

장면 화면을 시네마 자막 · Orbloom 음성 구로 바꾼 판(origin 69229795a)에 덧붙여 달라고 한 확인 셋. 틀 시험(`틀시험.mjs`)과 앱 안 브라우저로 잰 것과 아직 못 잰 것을 나눈다.

| 확인 | 결과 | 어떻게 |
|---|---|---|
| ① 실제 휴대폰 세로(iOS Safari · Android Chrome) — 자막 · 대사 카드 · 음성 구가 잘리지 않고 아래 안전 영역에 가리지 않음 | **못 잼(실기 없음).** 390×844 흉내에서는 새 상황 카드 · 구 · 라벨이 다 보이고 잘림 없음(캡처는 검수 묶음 `drama-world-20261102/캡처/후/390`). 노치 · 홈 막대의 안전 영역은 흉내로 확인되지 않는다 | 앱 안 브라우저 390×844 |
| ② 실제 마이크 — 권한 요청이 사용자 동작 뒤에만 · 녹음 → 받아쓰기(talk take) → 되묻기 · 통과 · 구 상태 바뀜 | **일부.** 권한 요청(getUserMedia)은 음성 구를 누른 뒤에만 불렸다(누르기 전 0회 → 누른 뒤 1회). 구 상태는 Tap to speak → Speaking · N초(대사별 상한 — 6번 줄 약 16초) → Transcribing → (되묻기) → Tap to speak / Nice로 바뀌었다. 녹음 → talk와 같은 판정기 → 되묻기 · 통과는 합성 마이크로 한 바퀴 돌았다. **공개 뒤 실제 계정(ego · 실제 마우스 입력, 마이크는 승인 모범 녹음을 합성 스트림으로)에서 운영 talk take까지 보냈으나 talk가 `unavailable`(받아 적기 실패)이라 「지금은 받아쓰기를 못 해요」 길로 이어졌다 — 받아 적기 키 쪽이 풀린 뒤 다시 잰다. 실제 하드웨어 마이크는 아직.** | 틀 시험 · 합성 마이크 |
| ③ WebGL 없음 · 움직임 줄이기 — Orbloom이 실패해도 녹음 단추와 흐름이 그대로 | **WebGL 없음: 통과.** canvas의 webgl 문맥을 막은 판(`?nowebgl=1`)에서 구가 정지된 공으로 보이고(104px, 누를 수 있음) 녹음 → 보내기 → 되묻기가 그대로 돈다. **움직임 줄이기: JS 쪽만 확인**(matchMedia를 reduce로 바꿔도 흐름 그대로). CSS `@media (prefers-reduced-motion)`은 앱 안 브라우저에서 흉내 낼 수 없어 못 쟀다 | 틀 시험 `?nowebgl=1` |

남은 것: ① 실기 두 대, ② 실제 하드웨어 마이크 + 운영 talk 받아쓰기(talk 받아 적기가 풀린 뒤), ③ CSS 움직임 줄이기(실기 설정 또는 CDP 흉내).
