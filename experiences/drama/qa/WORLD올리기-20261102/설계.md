# 드라마 말하기 1화 시범판 → WORLD 안에 올리기 — 설계 (2026-11-02, Claude)

> 범위: 이PC 루프백 시범판(`experiences/drama/pilot`, `tools/drama-pilot.mjs`)을 실제 학생이 SYNK ID로 로그인하는 WORLD(`synk.im/world/`) 안에서 열리게 한다. 목적은 12월 성인 코호트(5~10명) 전에 [TOPIK 3→4급 뼈대](../../../../docs/TOPIK_3to4급_뼈대_시안_20261102.md) 7절 순서 1 — 드라마 화면 → Trail 기록 — 을 실제 계정에서 닫아, 단원 측정 B를 잴 수 있게 하는 것이다. 서버(talk synk-learning v80 · synk-account v89가 spoken을 받음)와 화면의 기록 쪽(`learning-entry.cjs` → `atlas-learning.js`, [리허설 26건](../학습기록-20261102/README.md))은 11-02에 끝났다. 이 문서는 그 위에 「어디서 열리나 · 받아쓰기를 어디로 보내나 · 혼자 해 봄을 누가 정하나」만 더한다.

## 1. 지금과 바뀌는 것 한눈에

| | 지금(이PC 시범) | WORLD 안 |
|---|---|---|
| 주소 | `http://127.0.0.1:8794/` | `synk.im/world/?drama=1` → WORLD 게임 틀(iframe) 안에 `synk.im/world/drama/` |
| 로그인 | 없음 | WORLD가 SYNK ID로 로그인을 먼저 받는다(다른 게임과 같은 `launchGame`) |
| 학습 기록 호스트 | 없음(리허설만 합성 계정) | WORLD `account.prepareGame({target:window})`가 세운 `SYNKLearningHost` — 화면은 같은 출처 부모 창의 것을 그대로 쓴다(이미 그렇게 짜 둠) |
| 받아쓰기 | 시범 서버가 OpenAI 키로 직접(크레딧 소진 429) | talk `world-speaking` `take`(운영 v18 · 드라마 스위치 켬 · 하루 30번) — 부모 창의 `account.speakingRequest`로만 부른다(iframe은 토큰을 모른다) |
| 판정 | 시범 서버의 `observeTranscript`(드라마판정 + 닻 규칙) | talk의 `judgeLine`(drama-judge-5, 운영 판정 그대로) |
| 「혼자 해 봄」 | 시범 서버 `trailOf` | 화면이 같은 `trailOf`로 정한다 — talk의 verdict/sure + 대사 은행 검수 여부 + 이번 판 상태. 첫 노출(다른 날 본 적 있음)은 Atlas가 계정 이력으로 따로 거른다 |
| 새 상황 | 편의점(검수 전 예시 — 혼자 해 봄 0) | talk 은행의 검수 통과 처음 보는 대사 `s1e01-t4`(복사실 위치 묻기 — 장면 7번 줄과 같은 목적) |

## 2. 사용자 흐름

1. 코호트에게 `synk.im/world/?drama=1` 링크를 준다. WORLD 첫 실행(튜터 고르기 등)을 마친 뒤 그 바로가기가 `launchGame('drama')`를 부른다(`?cafe=1`과 같은 자리 · 한 번만).
2. 로그인 전이면 다른 게임처럼 로그인 창부터. 손님 체험으로는 열지 않는다(기획 §7 「자동 판정은 로그인한 계정만」).
3. `prepareGame`이 학습 호스트를 세우고(동의가 꺼진 계정이면 기기 안에만 — WORLD 게임과 같다), 부모 창이 드라마 전용 통로 `SYNKDramaHost`를 그 패널이 열린 동안만 둔다. 틀은 `allow="autoplay; fullscreen; microphone"`(드라마만 마이크).
4. 화면은 시범판 그대로: 장면 시작 → 받아쓰기 사용 여부 묻기(지금 시트에 처리방침 링크를 더함) → 장면 세 줄 → 노트 하나 → 테이크 2 → 새 상황 → 모범 보기 → 마침. 받아쓰기를 거절하거나 talk가 꺼짐 · 한도 · 판 다름이면 녹음 · 듣기 · 스스로 확인으로 이어 간다(시범판의 기존 「받아쓰기 끔」 길).
5. 패널을 닫으면 `SYNKDramaHost`를 지우고 `session.closeGame()`(다른 게임과 같다).
6. `synk.im/world/drama/`를 바로 열면(부모 호스트 없음) 첫 화면에 「WORLD에서 열어 주세요」와 `../?drama=1` 링크만 보인다 — 계정 · 기록 · 받아쓰기 없음.

첫 화면 줄(배우기 판 줄 · 마을 입구)은 이번에 더하지 않는다. `/world` 입구는 다른 세션이 다시 짜는 중이고(11-02 `beb3a509d`), 코호트는 링크로 들어온다. 줄을 둘 자리는 입구 작업과 함께 정한다(후속).

## 3. 받아쓰기 — talk `take` 계약에 맞추기

`pilot.mjs`의 서버 호출(`/api/bootstrap · take · reveal · reset`)을 통로 하나로 감싼다: **시범 서버 통로**(지금 그대로 — 이PC 시범 · 리허설)와 **WORLD 통로**. WORLD 통로는 부모 창 `SYNKDramaHost`가 있을 때만 고른다(같은 출처 확인은 `learning-entry.cjs findHost`와 같게).

- **bootstrap:** 정적 `world-lesson.json`(빌드 생성물)을 읽고, `host.status()`(= talk `{action:'status'}`)로 `dramaEnabled && linesVersion === lesson.linesVersion`일 때만 받아쓰기를 켠다. 아니면 받아쓰기 칩이 「지금은 받아쓰기를 쓸 수 없어요」로 스스로 확인.
- **take 요청:** `{action:'take', request_id:uuid, consent:'send-once', lang:'ko'|'en'|'mn'(화면 언어, 아니면 'ko'), audio:{mime, data:base64}, seconds, lines_version, line_id, take:{judged, unheard}}`. `judged · unheard`는 그 대사에서 앞서 판정된 수 · 잇달아 안 들린 수(talk의 다음 걸음만 바꾼다). `speech_seconds`는 보내지 않는다(talk가 녹음 길이로 보수적으로 본다).
- **녹음 길이:** talk는 대사별 `answerSec + 5`초를 넘으면 `too_long`이다(6번 줄 17초 · 7번 20 · 8번 16 · t4 18). 지금 시범판은 20초 고정이라, 대사마다 `answerSec + 5 − 0.6`초에서 저절로 멈추게 한다(`answerSec`는 빌드가 talk와 같은 `answerSecOf`로 넣는다).
- **응답 → 시범판 응답 꼴:**

| talk | 화면이 받던 꼴 |
|---|---|
| `ok` + `take.status:'ok'` | `status:'ok'`, `transcript: take.heard`, `observation.kind`: verdict `note` → note(노트 그대로) · `pass`+sure → pass · 그 밖 → pending |
| `ok` + `take.status:'no_speech'` | `status:'no_speech'` |
| `ok` + `take.status:'not_korean' · 'too_fast' · 'unclear'` | `status:'unclear'`(되묻기 · 세 번이면 스스로 확인 — 지금 길) |
| `too_long` | `kind:'input'`(짧게 다시) |
| `limit` | 받아쓰기를 이번 판 끔 + 「오늘 받아쓰기는 여기까지예요」 → 스스로 확인 |
| `off` · `unavailable` · `budget` · `busy` · `done_before` · 네트워크 · 409(`ITEM_CHANGED`·`ITEM_NOT_OPEN`) · 400 | `kind:'down'`(지금 길). 409는 이번 판 받아쓰기를 끈다(판이 바뀜) |

- 시범 서버의 닻 규칙(받아 적은 글에 핵심말이 하나도 없거나 끝말이 애매하면 보류)은 WORLD에서 쓰지 않는다 — talk 판정이 운영 정본이고, 새 상황 명세(정답)를 화면에 내리지 않으려면 화면에서 다시 판정할 수 없다. 차이는 「엉뚱한 말에 노트가 붙을 수 있음」인데, 장면에서는 되묻기로만 보이고 장면 뒤 노트는 마지막 판정 테이크의 것 하나다.
- 금액 · 횟수는 talk가 진다(말하기 통 · `world.drama.take` 하루 30). 시범 서버의 `ProcessBudget`은 WORLD 통로에 없다.
- 부모 통로 `SYNKDramaHost`: `Object.freeze({status(), take(payload)})` — 안에서 `account.speakingRequest`를 부르고, 만든 때의 계정(owner · generation)과 지금이 다르면 던진다(`ACCOUNT_CHANGED`). PC 앱(native)은 `supportsSpeaking`이 거짓이라 통로를 두지 않는다 → 받아쓰기 없이 스스로 확인.

## 4. 「혼자 해 봄」을 정하는 곳

- 순수 함수 `newAttemptState · beginTake · trailOf`를 `experiences/drama/pilot/takes.mjs`(브라우저 · Node 둘 다)로 옮기고, `tools/lib/drama-pilot-service.mjs`는 그것을 다시 내보낸다(시범 서버 · 시험 그대로).
- WORLD 통로는 화면 메모리의 같은 상태로 정한다: `assessable = 새 상황 && 이번 판에서 모범을 보기 전 && 이 대사의 첫 판정 테이크 && 대사 은행 review.status === 'passed' && (노트 || 통과+sure)`. `correct`는 pass → true · note → false · 그 밖 null, 안 들림은 `reason:'unanswered'`.
- 판 사이(다른 날 다시 함)는 화면이 모른다 — Atlas `present`가 계정 이력의 `met(itemKey)`로 `firstExposure:false`를 매기고, 그 시도는 `independent:false`가 된다(이미 엔진 동작). 화면이 「처음」을 주장하지 않는다.
- 「다시 시작」은 시범 서버의 `/api/reset`처럼 이번 판 상태를 비운다 — 다만 모범을 이미 본 판에서 다시 시작해도 Atlas가 그 대사를 본 것으로 기억하므로 혼자 해 봄이 되살아나지 않는다.
- 기록되는 것은 지금과 같다(대사 id · 능력 · 판정 · 도움 종류 · 시도 순서 · 시각). 받아 적은 글 · 소리는 사건 · 기기 저장에 없다.

## 5. 새 상황을 검수 통과 문항으로

- 새 상황을 편의점 예시에서 **`s1e01-t4`**(「선생님, 혹시 복사실이 어디에 있는지 아세요?」, 상대 교직원 · 능력 `ko.speaking.ask` · 검수 passed · 검수지문 일치)로 바꾼다. 장면 7번 줄(도서관 위치 묻기)과 같은 목적의 다른 문항이라 기획 §3-5의 B 조건(미리 검수한 같은 목적의 새 문항 · 첫 응답 전에 한국어 답 · 첫 글자 · 빈칸 없음)에 맞는다. 이PC 시범판도 같은 새 상황을 쓴다(한 체험).
- 상황 카드(도움 언어)는 대본 `상황`을 옮긴 영어 한 줄 + 한국어 한 줄: 「You can't find the copy room. Politely ask a staff member you've never met where it is.」 / 「복사실을 못 찾았어요. 처음 본 교직원께 공손하게 어디 있는지 물어보세요.」 — 필요한 정보(복사실 · 처음 본 교직원 · 공손하게)만, 한국어 답 · 첫 글자 없음. 한국어 줄은 처음 화면에 「복사실」 낱말을 드러내므로 **영어 판에서는 한국어 줄을 보이지 않고**(지금 시범판의 promptKo는 도움 언어가 한국어일 때만), 한국어 판의 카드 글은 「복사실」을 그대로 쓴다 — 장소 이름은 필요한 정보이고 정답의 핵심은 「어디에 있는지 아세요」 꼴이다. 카드 글은 이 설계 검토에서 Fable이 함께 본다.
- 판정 명세는 talk 대사 은행 그대로(`dramaSpecOf` — 처음 보는 대사는 `free`라 빠진 말 노트 없음, sure는 핵심 말이 모두 들릴 때만). 화면에 명세를 내리지 않는다.
- 모범 보기는 `world-lesson.json`의 `transfer.reveal.text`(모범 소리 없음 — 승인 녹음이 없다). 정적 파일이라 개발자 도구로는 처음부터 볼 수 있다 — 코호트 시범의 알려진 한계로 적고, 제품판에서 모범을 talk 쪽으로 옮길지는 후속.
- C(6~9일 뒤 같은 목적 · 다른 문항 — 후보 `s1e01-t6` 정문 위치)는 이번 범위 밖.

## 6. 동의 · 나이 · 처리방침

- **학습 기록:** 계정의 학습 기록 동의(`preferences().enabled`)가 켜져야 서버로 간다 — 호스트 동작 그대로. 꺼져 있으면 기기 안에만.
- **녹음 보내기:** 판마다 받아쓰기 사용을 묻는 지금 시트를 그대로 두고, 「외부 서비스로 보내 글로 옮기고 저장하지 않음」 문장 옆에 처리방침 링크(`/privacy/` — 10-31에 수탁자 표 OpenAI 줄에 「드라마 말하기의 자동 피드백」을 게시)를 더한다. 요청마다 `consent:'send-once'`(talk가 요구).
- **나이:** SYNK ID 가입은 만 14세 이상 확인(결정 09-19)이고 계정에 나이 칸이 없다. 운영 중인 WORLD 말하기 연습과 같은 조건이며 새 나이 관문은 두지 않는다. 코호트는 성인이다. 학원이 만든 만 14세 미만 계정의 자동 판정 범위는 기획 §7의 출시 전 확인 항목으로 남긴다.
- 화면 글에 도구 이름 · 「AI로 만든」 없음(지금 시범판 그대로 「인물은 지어냈고, 목소리는 모두 합성했어요.」).

## 7. 공개 묶음

- `tools/build-drama-world.mjs`(새): `content.mjs`의 PILOT에서 화면용 강의(`publicLesson` 꼴) + 대사별 `answerSec` · `linesVersion`(`build-world-speaking-talk.mjs`의 `dramaLines`/`linesHash` — talk 운영 `e668961843825080`과 같은지 시험이 본다) + 새 상황 카드 · 모범 글을 `experiences/drama/pilot/world-lesson.json`(생성물, 커밋)으로. 미디어 주소는 `media/…` 상대 주소.
- `index.html`의 `/pilot.css` 같은 절대 주소를 `./pilot.css` 상대 주소로(시범 서버에서도 같게 풀린다). WORLD 쪽 문서에는 CSP meta(스크립트 self만).
- `tools/build-world-app-public.mjs`가 `drama/`에 `index.html · pilot.css · pilot.mjs · strings.mjs · takes.mjs · orbloom.mjs · atlas-learning.js · world-lesson.json · media/(manifest의 파일만)`을 싣는다. `content.mjs`(서버 전용 · 정답 명세) · `README` · `qa`는 싣지 않는다. 미디어는 git 밖(`build-drama-pilot-assets.mjs`가 승인 원천에서 만듦)이라, 빌드는 manifest의 sha256과 대조해 하나라도 없거나 다르면 멈춘다. 제작 도구 이름 검사(`publicToolName`)를 그대로 받는다 — `pilot.mjs` 머리 주석의 「GPT 서버」 같은 말은 고친다.
- 공개는 `tools/공개.js`의 WORLD 경로(현장노트 「WORLD 공개」 절 — origin 사본에서 빌드, 바뀐 파일만 얹기).

## 9. 시험 계획
