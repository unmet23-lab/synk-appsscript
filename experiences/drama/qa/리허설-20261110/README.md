## 어떻게 쟀나

- **같은 코드 로컬 왕복만** 돌렸다 — talk 함수의 실제 코드에 진짜 받아 적기(OpenAI `gpt-transcribe`)를 붙이고 원장 · 로그인만 가짜로 둔 [`로컬왕복.mjs`](../리허설-20261031/로컬왕복.mjs). 이번에 `--초안닫기`를 더해 운영처럼 검수 전 대사를 닫고 돌렸다. PC의 SYNK-talk 작업본은 origin보다 273커밋 뒤라 쓰지 않고, `origin/master`에서 필요한 파일만 임시 폴더로 꺼내 git blob 해시로 대조한 뒤 썼다. 운영의 리허설 함수(합성 계정이지만 실제 원장을 쓴다)는 부르지 않았다.
- **기대를 먼저 적었다.** 테이크마다 기대와 그 근거(기획 절 · 결정 행)를 [`테이크목록.mjs`](테이크목록.mjs)에 적어 받아 적기 전에 올렸다(커밋 `641544c65`, 11-10 07:04). 새 소리 굽기는 07:05, 왕복은 07:06이다. 스크립트는 받아 적기 없이 글 그대로의 판정이 그 기대와 같은지만 먼저 본다(15/15 — 다르면 멈춘다. 한국어 아님 하나는 소리 관문이 정해 글로는 건너뛴다. 목록 커밋 메시지의 「16/16」은 건너뛴 하나까지 센 잘못이다).
- **소리:** 모범 읽기 9는 저장소의 일레븐 v4 Hana, 앞 목록에서 그대로 온 12개는 10-31 · 11-01에 구운 그 소리(OpenAI Realtime 2.1 `marin`)를 사본으로 다시 썼다 — 판정 판과 대사 은행만 바뀐 비교가 되게. 새 테이크 넷만 일레븐랩스 공식 `eleven_v4`(공유 목소리 Jjeong)로 구웠다. OpenAI 월 API 크레딧은 받아 적기 몫이라(결정 11-03 · 11-05) 소리 굽기에 쓰지 않았다.
- 소리 · 목록 · 결과는 git 밖(공용 작업본 `.tmp/drama-rehearsal-20261110/` — `takes.json` · `local-results-judge7.json` · `contract-results.json`)에 있다.

## 이 값이 말하지 않는 것

- 합성 소리 25개다. 또박또박 읽은 기계 음성이라 받아 적기가 거의 틀리지 않는다 — 몽골 억양 실제 학습자 녹음에서의 받아 적기 정확도, 오노트 비율은 이 값으로 알 수 없다(기획 §8 시범에서 실제 학습자 말로 잴 몫).
- 「기대와 같다」는 판정 규칙이 설계대로 움직였다는 뜻이다. 기대도 판정도 같은 설계에서 나왔으니, 설계가 학습자에게 맞는지는 재지 않는다.
- 21개는 앞 회차와 같은 소리이고 그 결과는 11-01에 이미 본 것이다. 「기대를 먼저 적었다」가 지키는 것은 새 테이크 넷의 받아 적기까지다 — 글 그대로의 판정과는 올리기 전에 맞춰 봤다. 새 소리로 다시 구우면 받아 적은 글이 달라질 수 있다.
- 부정 규칙은 낱낱 검사 길만 쟀고(위 표), 숫자 규칙은 재지 않았다.
- 운영 함수 왕복(실제 계정 · 실제 원장)은 이 기록에 없다 — 받아 적기 크레딧 복구 뒤 실제 계정 왕복은 [트랙](../../../../docs/_ops/트랙.md) 몫이다.
