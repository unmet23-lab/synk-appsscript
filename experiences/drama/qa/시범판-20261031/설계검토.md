## 받은 응답(원문 그대로)

## 드라마 말하기 로컬 시범판 화면 설계 검토 (Fable)

읽은 것: `fable-design-request.md` 전체, 기획 §3-1~§4-3·§7·§8, `ep01.mjs` 식당 장면(s1e01-6·7·8)·되묻기·감독말버릇·t4, `드라마판정.mjs` 전체(judgeLine·nextTake·sure 정의). 읽지 않은 것: 기획 §2·§6·§11, `공개판_설계.md`, `말하기피드백.mjs`, 시험 파일, 부모가 만드는 서버 코드(아직 없음).

### 1. 필수 지적

**P1-1. 감독 노트 선택 조건이 공집합이다.** 설계 3항 「note가 있고 sure인 것」— `드라마판정.mjs` 173행 `const sure=!note&&…`: 노트가 있으면 sure는 항상 false다. 이대로면 감독 노트는 한 번도 안 나오고 늘 「다른 말로 한번 더」로 빠진다. 고침: 선택 기준을 `observation.kind==='note' && note!=null`로(라이브러리가 확신 없는 노트는 애초에 안 낸다). `sure`는 「혼자 해냄 통과」 표시에만 쓴다.

**P1-2. 어느 테이크의 노트인지가 없다.** 같은 줄을 장면 안에서 2~3번 녹음하면 1번째 어긋남의 노트가 그대로 후보로 남는다. 학생이 재시도에서 이미 고쳤는데 테이크2를 시키면 「테이크에 대해서만」 원칙과 어긋나고 「지난번엔 끝이 빠졌는데 이번엔 다 붙었어요」 칭찬 mp3도 조건 없이 틀 위험이 있다. 고침: 줄마다 **마지막 판정 테이크**의 노트만 후보. 앞 테이크에 ending 노트가 있고 마지막 테이크가 pass면 노트 대신 그 칭찬 mp3(종류가 ending일 때만 — 다른 종류 노트 뒤엔 틀지 않음). 테이크1/2 나란히 듣기는 「노트가 난 테이크」와 테이크2.

**P1-3. 소리 관문(unclear·no_speech)과 판정 어긋남(note)을 한 계수기로 센다.** 설계 2항은 셋을 합쳐 1→되묻기, 2→카드 자동 펼침(도움 표시), 3→통과다. 기획 §3-4 첫 줄과 `nextTake`는 안 들린 테이크를 세지 않고 3번 잇달아 안 들리면 `self_check`(내 녹음 듣기·따라 말하기)로 보낸다. 마이크가 나쁜 학생이 「도움 받음」으로 찍히고 인식 문제가 학습 기록이 된다. 고침: 계수기 둘 — `unheard`(unclear/no_speech, 되묻기만, 3회면 API 실패 경로와 같은 자기 확인 화면)와 `attempt`(note만, 되묻기→카드→통과). 서버 `take.attempt`가 어느 쪽인지 부모와 맞춘다.

**P1-4. `observation.kind==='pending'` 처리가 없다.** 설계는 pass/note만 가른다. pending이 else 가지로 떨어지면 판정 보류 테이크에 되묻기·카드가 나간다(§3-5 「보류는 실패로 단정하거나 오노트를 주지 않음」). 고침: pending은 진행하되 세지 않고 노트 후보에서 뺀다. `status:'unavailable'`도 429/503과 같은 경로로.

**P1-5. 녹음 중 모범 소리가 「내 대답」이 될 수 있다.** 「모범 듣기」 Hana mp3는 누를 때만이지만 녹음 중에 누를 수 있다. 스피커 소리가 마이크로 들어가 받아쓰기가 모범을 받아 적으면 가짜 통과다(영상 분할로 막은 것과 같은 구멍). 고침: 녹음 중엔 모범 듣기·되묻기·모든 소리 재생 단추를 막고, 재생 중엔 녹음 시작을 막는다. 테이크2·새 상황도 같다.

**P1-6. 마이크 거절·MediaRecorder 미지원 경로가 흐름에 없다.** 요구 조건과 §3-4 끝 줄(이유 한 줄 + 설정 길 + 「녹음 없이 따라 읽기」, 권한 창 반복 금지)인데 설계엔 API 실패 경로만 있다. 「다음 녹음 때 다시 getUserMedia」는 거절 뒤 줄마다 실패 창을 만들 수 있다. 고침: 거절·미지원이면 세션 플래그를 세우고 이후 getUserMedia를 부르지 않으며, 줄마다 카드 전체 + 모범 듣기 + [다음으로]로 진행. 마침 화면은 「녹음 없이 따라 읽음」으로 구분.

### 2. 권고

- 테이크1/2 Blob·ObjectURL은 단계 정리 묶음이 아니라 **세션 묶음**에 두고 reset·비우기·동의 철회 때만 해제(단계 묶음에 두면 감독·마침 화면에서 이미 revoke됨).
- 「보내지 않고 연습만」·철회 뒤 흐름을 한 줄로 못 박기: `/api/take`를 아예 부르지 않고 녹음 끝→[내 녹음 듣기]→다음. 되묻기·카드 자동 펼침 없음. 마침은 「받아쓰기 없이 연습」.
- 되묻기 mp3는 입 다문 듣기 고리 위에서 틀면 어색하다 — 정지 사진으로 잠깐 전환하거나 화면을 어둡게.
- 테이크2에서 s1e01-7의 직전 대사는 `taeo-reply.mp4` 전체(웃음 참기 포함)보다 6.3초쯤부터 재생이 맞는다.
- 자산 도구에 시험 하나: `taeo-listen.mp4`에 오디오 스트림이 없고 `taeo-reply.mp4` 시작이 4.2초 이상임을 ffprobe로 확인.
- 최대 녹음 길이는 20 고정이 아니라 `limits.maxSeconds`를 읽는다.
- reveal 응답 `modelAudio`는 없을 수 있다(편의점 줄의 Hana 녹음은 승인 자산에 없음) — 글만으로도 동작.
- 노트가 있을 때 장면 끝 감독 소리는 「컷! 좋아요」 대신 「컷!」+「한 번만 더 갈게요」.
- 모바일 390에서 아래 시트가 자막 자리를 덮는다 — 자막은 시트 위 가장자리에.

### 3. 문제 없다고 본 핵심 결정

- 영상을 무음 듣기 고리(0.3~4.3)와 소리 있는 응답(4.3~)으로 분할 — 구워진 Hana 소리가 구조적으로 재생 불가.
- 감독은 장면 밖에서 노트 하나, 장면 안은 되묻기·카드·통과만.
- 새 상황은 영어 상황만, 힌트는 `/api/reveal` 먼저 → 응답으로만 표시.
- 마침 화면에 점수·등급·TOPIK·성공 확정 없음, 「연습」과 「노트」 구분.
- 녹음은 메모리 배열만, epoch·AbortController·requestId, 녹음마다 트랙 stop.
- 첫 화면의 합성 인물 안내와 AI 도구 이름 비노출(§7).
