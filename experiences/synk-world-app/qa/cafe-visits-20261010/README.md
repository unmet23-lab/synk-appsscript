시험 간 반복된 항목은 고유 총수로 합산하지 않는다. 실제 휴대폰 대신 390×844 ↔ 844×390, 320×740 ↔ 740×320의 터치 브라우저를 사용했다. 복습 때 브라우저 시계만 65초 앞당겼다. 계정 브라우저의 공급자 응답은 모의했고, 실제 SQL 기록/새 공식 저장 포트/A·B 분리는 별도 로컬 PGlite 시험으로 확인했다. 지갑은 그대로이며 진도 전송의 기존 per-key CAS 계약을 사용한다.

## 확인한 동작

- 기존 18레슨의 내용·보기·정답·복습/문항 ID를 추가 전 SHA256과 대조했다([이전 레슨 서명](previous-lessons.json)). 저장 키/스키마 판도 유지한다.
- 첫 방문 완료 후 인사 팩의 처음으로 돌아가지 않고 다음 카페 방문으로 이어진다. 다른 학습의 중간 진도는 우선하고, 여러 방문을 중단한 경우 최근에 연 방문이 카페 입구에서 이어진다.
- 품절 음료는 컵 0개, 더하기/빼기는 실제 잔 수, 포장은 뚜껑 있는 컵으로 표시한다. 매장 이용 방문만 자리를 선택한다.
- 잘못 골라도 주문을 고칠 수 있고 처음 오답/도움 기록은 남는다. 답 세 개만으로 완료하지 않으며 마지막 컵을 받아야 방문 기록이 완성된다.
- 각 방문의 단계·선택·수량·자리·시도 ID는 회전/새로고침에서 유지된다. 서로 다른 방문과 계정 기록이 섞이지 않는다.
- 새 방문의 오답/도움은 독립적인 변형 문항으로 복습한다. 이전 카페의 재플레이는 완료를 중복 집계하거나 복습을 미루지 않는다.
- 패널 경계·가로 넘침·44px 조작부·하단 행동의 클릭 위치와 장면 안의 컵 경계를 검사했다. 승인된 얼굴과 실제 펠트 부품은 재사용했다.

## 수정과 검증의 한계

`source-r1`은 행동 시험을 통과했지만 직접 이미지 검수에서 작은 화면의 세 컵 잘림을 발견했다. 장면 폭에 맞춰 컵을 축소하고 장면 경계 검사를 추가해 `source-r2`부터 확인했다. 마지막으로 여러 미완료 방문 중 최근 방문 우선 재개를 더해 `source-r3`/`standalone-r2`에서 확인했다. 이전 캡처는 보존했다.

첫 고정 빌드 `r1`은 동시에 추가된 기존 게임 튜터의 모듈 5개가 배포 목록에 없어 실패했다. 해당 의존 파일을 포함하고 `r2`/`r3`의 참조 검사를 통과했다. 튜터 구현은 보존했고 카페 기능으로 수정하지 않았다.

공개 배포, 운영 OAuth/원격 저장, 실제 설치본·실물 휴대폰 성능, 교원 난도·학생 재미/학습 효과는 미검증이다. 새 방문은 읽기·선택이며 듣기/발음/말하기 평가가 아니다.
