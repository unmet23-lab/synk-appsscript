# 「놓친 곳 카드」 설계 (2026-11-14, WORLD 「내 위치」 · 읽기 전용)

유호님 11-14 밤: 「학생의 부족한점을 파악해서 이 부분을 어떻게 해소해주는지에대한 세분화 그리고 탁월함이 필요할것같아 아직 좀 조잡하고 이해가 잘 안가거든 산만한 느낌이 커」 · 「개발방향을 추가하더라도 조금 더 어필할수있는 엔진 그리고 우리 앱 시스템을 만들어나가고싶어」 → 페이블 계획 검수의 B2-lite(시안 2안).

## 무엇을 하나

「내 위치」 판 맨 위(칸 수 아래 · 「먼저 볼 항목」 위)에 카드 한 장. 놓친 곳 하나를 좁혀 짚고(층 셋), 그 뒤 앱이 언제 무엇으로 다시 만나게 하는지(사다리 넷)를 「한 일 ●」과 「앱이 잡아 둔 다음 ○」로 나눠 보인다.

- **새 판정 · 새 저장 · 새 엔진 상태 없음.** Core 요약(칸 상태 · 근거 id) · Trail 사건(정오 · 고른 답 · 시각) · 게임 원고(안내문 규칙)만 읽는다. 급수 · 합격 · 점수 환산 없음(`grade:null`).
- 앱 말은 「약점」이 아니라 「놓친 곳 · 다음에 볼 자리」(학습기준 §7-3 — 학생의 영구 특성으로 만들지 않는다). 카드도 「놓친 곳」.
- 계산은 `world-missed-spot.mjs`(순수 함수), 그림은 `world-position-ui.mjs`, 값 모으기는 `world-learning-ui.mjs` showBoard.

## 카드 뼈대(두 종류 공용)

```
{ version, kind: 'topik' | 'speaking', target,
  narrow: [ { layer, count, of, ... } ],          // 좁혀 짚기 — 위에서 아래로 좁아진다
  again:  [ { step, state, ... } ],                // 다시 만나기 — state: done ● 기록에 있는 일 · planned ○ 다음 차례
  evidence: [eventId…], grade: null, abilityClaim: false }
```

- `kind:'topik'` = TOPIK 항목(이번 판에서 채움). `kind:'speaking'` = 드라마 말하기 기록(드라마 실수 복습 세션의 `planRevisit` 결과 `{lineId, kind: ending|length|missing, at, fixed, due}`를 같은 뼈대로 옮김 — 화면 이름 「말하기 기록」, TOPIK 항목 이름 · 칸을 쓰지 않는다). 말하기 종류는 드라마 쪽 기록 읽기가 WORLD 「내 위치」에 아직 없어 이번 판에서는 뼈대만 맞춘다.

## TOPIK 항목 카드 — 고르기와 층

**고르기:** 판의 「먼저 볼 항목」(Core 우선순위 순서) 가운데, Core 근거에 **도움 없이 처음 본 문항에 낸 첫 답의 틀림**이 하나 이상 있는 첫 항목. 없으면 카드 없음(도움으로만 해냄 · 다시 볼 때만 있는 항목은 「놓친 곳」이 아니다). 한 번만 놓쳤으면 항목 층만 「한 번 놓침 · 확인 중」으로 두고 좁혀 짚지 않는다.

| 층 | 원천 | 보이는 꼴(입장 검사 재생 기록) |
|---|---|---|
| 항목 | 판 항목 줄(Core n · incorrect — 판 칸 아래 줄과 같은 수) | TOPIK I 읽기 · 읽고 부정·변경 이해하기 — 손님 4명 중 2명 놓침 (근거가 모두 입장 검사 손님이면 「손님 n명」, 아니면 「n번」) |
| 안내문 줄 | 놓친 근거 가운데 입장 검사 문항(itemKey → 원고 `VENUES` 손님) → 정답 규칙(정답이 통과면 근거 규칙 첫째) → 그 시각의 안내문 줄(`activeRules`) — 같은 글끼리 묶어 가장 많은 줄 | 「음식은 가지고 들어갈 수 없습니다. 물은 괜찮습니다.」 — 놓친 2번 모두 |
| 놓친 방향 | 놓친 근거의 Trail `choice`(selectedId · correctId, `app.mjs` 472줄) — 통과/거절-규칙 꼴만 | 막아야 할 손님을 들여보냄 — 2번 모두. choice가 없는 근거(접힌 기록 · 옛 기록)는 세지 않고, 하나도 없으면 층을 뺀다 |

방향 셋은 `correction.mjs` 18~25줄과 같은 가름: 통과를 골랐는데 정답이 거절 → 「막아야 할 손님을 들여보냄」 · 거절을 골랐는데 정답이 통과 → 「들어갈 수 있는 손님을 막음」 · 둘 다 거절인데 규칙이 다름 → 「다른 규칙으로 막음」.

## 다시 만나기 — 사다리 넷(Fable 설계 검토 11-14 반영)

칸은 **기록에 남은 일(●)과 지금 기록 · 계획에 잡혀 있는 다음(○)만** 쓴다. 「앱이 알렸다 · 넣었다 · 올 것이다」는 쓰지 않는다 — 근무 · 입구 안내는 Trail에 남지 않고, 재방문 맞춤 손님은 과제 · 근무지 · 잠금에 따라 안 올 수 있다(검토 P1 ①②). 조건 안내 줄 · 내부 문턱(「3명 중 2명」)은 화면에 두지 않는다(P2 ⑨).

**자리 가르기:** Trail에는 근무 경계가 없다(손님마다 결정 하나). 입장 검사 게임(experienceId `entry-check`) 제시를 기록 순서로 읽어, 근무지가 같고 · 손님 도착 시각(원고 `at`)이 늘고 · 실제 시각이 30분 안에 이어진 묶음을 한 「자리」로 본다(화면은 「근무」라 부르지 않는다 — P2 ④).

| 단계 | ● 기록에 있는 일 | ○ 다음 차례 |
|---|---|---|
| 그 자리 | 입장 검사에서 놓친 손님 **바로 다음** 손님이 같은 자리 · 같은 항목이면 그 사실(바로잡기가 확인 손님을 그 자리에 넣는다). 또 놓치면 그 뒤도 잇는다. 「바로 다음 같은 규칙 손님 n명 · m명 혼자 맞힘」(근거 규칙이 다르면 「같은 종류」) | — |
| 나중에 다시 | 놓친 마지막 자리 **뒤의 다른 자리**에서 처음 만난 같은 항목의 정규 손님(확인용 아님)의 첫 답 — 「같은 종류 새 손님을 혼자 막음/맞힘 · 다시 놓침 · 도움 받아 맞힘」 | 원고에 아직 안 본 같은 항목 정규 손님 수(「남아 있어요」 — 올 것이라 하지 않는다) |
| 짧은 연습 / 이번 주 숙제 | 놓친 뒤 짧은 연습(world-practice)에서 그 항목 새 문항에 혼자 낸 첫 답 수 · 맞힌 수(숙제였는지 가르지 않는다 — P2 ⑦) | 없으면 이번 주 계획 숙제에 그 항목이 있을 때만(시험 목표를 넣은 학생) |
| 1 · 7 · 30일 | Temper 다시 확인 투영(`followups().items`, 짧은 연습 답만 — 12줄로 자른 `followupRows`가 아니라 투영을 직접 · P2 ⑤)에서 가장 최근 기준 답의 세 창: 확인한 수 · 지금 확인 · 다음 날짜(아래 「시간을 두고 다시 확인」 카드를 가리킴) | 기준 답이 아직 없고 그 항목 짧은 연습을 열 수 있으면 「짧은 연습 첫 답부터 새 문항으로 다시 확인」(창은 놓친 날이 아니라 그 칸의 첫 답 기준) |

- 좁혀 짚기(안내문 줄 · 놓친 방향)는 **서로 다른 문항 2번 이상 · 놓친 수의 과반**일 때만(검토 P1 ③). 분모는 놓친 근거 수 그대로(입장 검사 밖 · 고른 답 없는 근거도 분모에 남음 — P2 ⑥), 같으면 가장 최근 쪽.
- 기록을 다 받지 못한 판(`evidenceComplete:false`)은 카드를 세우지 않는다(P2 ⑧). 입장 검사 밖에서 놓친 항목은 항목 층 + 짧은 연습 + 1 · 7 · 30일만.
- 고른 항목은 바로 아래 「먼저 볼 항목」에서 뺀다(P2 ⑨).
- 카드 아래 단추 하나: 그 항목에 지금 낼 새 문항이 있으면 판의 「이 항목 연습하기」와 같은 단추.

## 두 종류 공용 뼈대 — 드라마 「말하기 기록」과 맞물리기(P2 ⑩)

- `narrow[].count/of`는 선택 칸이다 — 말하기 기록은 줄마다 실수 하나(`planRevisit` `{lineId, kind, at, fixed, due}`)라 수가 없다.
- `again[].step`은 종류마다 열거가 다르다: TOPIK 항목 `spot · again · practice · homework · delayed`, 말하기 기록은 드라마 쪽(3일 뒤 다시 · C 지연 관측)이 정한다. 칸마다 `at` · `dueAt`을 둘 수 있다.
- `again[].state`는 `done · planned`에 말하기 쪽 `fixed`(고쳤지만 3일 뒤 다시) · `unknown`(접혀 못 읽음)을 더할 수 있다. 화면은 `again` 배열 길이대로 그린다.
- 화면 이름은 「말하기 기록」으로, TOPIK 항목 이름 · 칸을 쓰지 않는다. 드라마 기록 읽기는 WORLD 「내 위치」에 아직 없어 이번 판은 뼈대만 맞춘다.

## 한계(화면에 쓰지 않음, 검수용)

- 자리 가르기는 원고 시각 · 근무지 · 30분으로 다시 읽은 것이다. 근무 중 30분 넘게 쉬면 확인 손님이 「그 자리」에서 빠지고, 첫 손님 뒤 나갔다 곧바로 다시 열면 두 근무가 붙어 정규 손님이 「바로 다음」으로 읽힐 수 있다(그래도 「바로 다음에 같은 종류 손님을 만났다」는 사실 그대로다).
- 접힌 기록(learning-ledger folded)은 판과 같이 개수로만 세고 층 · 사다리에서 뺀다.
