## ③ 놓친 문제

추가로 재현 경로가 성립하는 것은 **P2 두 건**이다. 새 P0는 찾지 못했다.

### N1. 도움을 받고 틀린 시도가 ‘내 위치’에서 무기록과 같아진다 — P2

- **파일·줄:** `atlas/learning.js:13–30,44–52`, `experiences/synk-world-app/world-position.mjs:50–57`
- **깨지는 동작:** 도움을 받은 오답은 독립 수행에도, 도움 받은 성공에도, 평가 불가에도 포함되지 않아 위치판에서 시도 사실과 근거를 찾을 수 없다.
- **재현 입력 → 결과:**
  1. 다른 기록이 없는 항목에 오늘의 유효 시도 하나를 준다. `independent:false`, `assisted:true`, `verdict:'incorrect'`, 제외 사유 없음.
  2. 독립 근거에서는 빠진다(`learning.js:13`).
  3. `helped`는 정답만 모으므로 여기서도 빠진다(`:18`).
  4. `unassessed`는 평가 불가·건너뜀만 세므로 0이다(`:30`).
  5. 결과는 `unseen`, `n:0`, `incorrect:0`, `assisted:0`, 근거 빈 목록이다. WORLD에서는 **‘아직’, 펼칠 근거 없음**이 된다.
- **고칠 방향:** 독립 오답 분모에 넣거나 보충 상태로 강제하지 않는다. **‘도움과 함께 시도했음·결과·날짜’는 별도 사실로 보존해 표시**한다. 원래 Trail 로그가 삭제된다는 지적은 아니다.

### N2. 높은 난도에서 맞혔는데 기존 성공 근거가 위치판에서 가려진다 — P2

- **파일·줄:** `atlas/learning.js:21–23,37–52`, `experiences/synk-world-app/world-position.mjs:9,50–57`
- **깨지는 동작:** 추천에 사용할 현재 초점을 항목 전체의 성취 표시로 사용하면서, 새 난도에서 성공한 직후 ‘혼자 해냄’ 합계가 줄고 이전 성공 근거도 위치판 반환값에서 빠진다.
- **재현 입력 → 결과:**
  1. 한 항목의 **난도 1·단일 선택**에서 서로 다른 새 계열 네 개를 모두 독립 정답으로 준다. 상태는 `recent-independent`, 우선순위 `.15`, 위치판은 혼자 해냄 1이다.
  2. 같은 날 **난도 2·단일 선택**의 새 계열 하나를 독립 정답으로 추가한다.
  3. 난도 2는 `checking`, 우선순위 `.55`다. Core가 이를 항목의 대표 초점으로 고른다(`learning.js:50–52`).
  4. 위치판은 **혼자 해냄 0·연습 중 1**, 대표 근거는 난도 2의 정답 하나가 된다. 오답도 시간 경과도 없었다.
- **고칠 방향:** 난도를 합쳐 숙달률을 만들지 않는다. **‘난도 1에서 혼자 수행한 기록’과 ‘현재 난도 2 확인 중’을 함께 보여 준다.** 추천용 초점 선택을 바꾸기보다 위치판에서 조건별 이력을 보존하는 문제다.

- **수정:** 진단 실행기를 재사용할 수는 있지만, 현재 `selectDiagnostic`은 항목마다 하나를 고른다(`world-position.mjs:89–100`). 이것만 재사용해서 특정 약점의 5문항 연습이 완성되지는 않는다.
- **추가:** 새 읽기 후보에 `exam`만 붙여 충분한지 확인한다. 설정에 `exam`과 `prepare`가 함께 들어가면 두 게임은 목표를 두 개 맞춘 것으로 계산된다(`world-learning-plan.mjs:72–74,135–138`, `learning.js:191,198`). **한 목표의 두 표현이 순위를 이중으로 올리는지** 검증해야 한다.
- **유지:** 예상 급수 막대를 숨기고 지원 상태를 정직하게 알린다. 단, ‘준비 중’도 공개 일정이나 출시를 보장하는 표현으로 만들지 않는다.

완료 기준은 ‘캡처에서 칸이 바뀜’보다 다음처럼 구체적이어야 한다.

| 검증 입력 | 통과 결과 |
|---|---|
| 같은 이용 조건에서 듣기 강·읽기 보충 / 읽기 강·듣기 보충 | 추천뿐 아니라 **첫 실제 출제 영역·항목이 달라지고**, 이유가 해당 근거를 가리킨다. |
| 첫 진단의 정답 하나 / 오답 하나 | 맞음·틀림과 다음 행동은 구별하되, 둘 다 표본 부족이라는 사실을 유지한다. |
| 도움·반복·음성 실패 | 독립 성공으로 올라가지 않으며, 시도 사실과 제외 이유는 확인할 수 있다. |
| 해당 항목의 새 문항 소진 | 다른 항목을 해당 약점 연습인 것처럼 내지 않고, 부족한 범위와 대안을 알린다. |
| 학습 뒤 재시작·계정 전환 | 정해진 저장 범위에서 기록과 다음 추천이 복원된다. |

손님 기록 이전은 **무조건 복사**로 처리하면 안 된다. 출처·동의 범위, 다른 학생 로그인, 사건 ID와 참조 관계, 중복 이전을 다뤄야 한다. 이것은 현재 P0가 있다는 뜻이 아니라 이관 구현의 완료 조건이다.

### 다음 묶음: 진단 문항 수와 예상 급수 개방 조건을 다시 써야 한다

**‘오답마다 한 문항 더’에는 두 문제가 있다.**

1. 15문항 모두 틀리면 15개가 추가돼 **최대 30문항**이다. 2차의 최대 22문항은 별도 상한과 선택 규칙이 있어야 성립한다.
2. 같은 칸에서 두 번 틀려도 `n=2`이므로 Core의 보충 조건 `n≥3·오답≥2`에 못 미친다(`learning.js:22`). 더 쉬운 난도로 추가하면 아예 다른 칸에 쌓인다(`:37–42`).

따라서 추가 문항의 목적을 **첫 결과 보충 확인**으로 명시해야 한다. 이를 보충 상태 확정이나 숙달 판정으로 약속하면 안 된다. 화면을 바꾸려고 Core 문턱을 낮추는 것도 부적절하다.

**‘유형별 10문항’도 충분한 재고 기준이 아니다.**

현재 기준은 능력·난도·응답 형식·새 계열별로 작동한다. 예를 들어 같은 칸에서 첫 세 문항 중 두 개를 틀렸다면, 이후 새 일곱 문항을 모두 맞혀야 `8/10=.8`이 된다. 진단에서 이미 소비한 계열도 고려해야 한다. 완료 기준은 총량보다 **해당 칸의 확인·보충·재확인 시나리오를 실제 재고로 끝낼 수 있는가**여야 한다. 새 ID만 붙여 익숙한 문항을 새 문항으로 취급해서는 안 된다.

**듣기 10 + 읽기 10 미니 모의는 급수 개방 조건을 충족하지 않는다.**

- 한 번은 20문항으로 30문항 문턱에 못 미친다.
- 같은 세트를 다시 풀면 처음 보는 문항 조건을 충족하지 못한다.
- 10+10을 공식 구성·배점·시간과 어떻게 대응시킬지 정의하지 않았다.
- 30문항을 충족해도 현재 코드는 `no-estimator`다.

미니 모의, 근거 집계, 급수 추정 방법의 검증을 **세 작업으로 분리**해야 한다. 문항 교원 검수와 학생 10명의 화면 체험은 필요하지만, 그것만으로 급수 범위의 타당성을 검증한 것은 아니다.

듣기 재생 변경도 허용 횟수·실제 재생·규칙의 판을 추적할 방법이 필요하다. **도움 이벤트를 생략하는 것만으로 관측 조건 관리가 끝났다고 볼 수 없다.** 기존 필드를 쓸 수 있는지는 Trail 전체를 보지 못해 판단할 수 없다.

### 그다음: TOPIK II 범위를 정하고, 쓰기 과제별로 평가해야 한다

- 온라인 반 읽기 40·쓰기 8은 작업본이며 대상도 제한돼 있다. WORLD 공개 공급량으로 먼저 세지 않는다.
- B-1-4에서 **51·52는 빈칸별 문맥 적합성**, **53·54는 세 범주별 배점**으로 나뉜다. 모든 과제에 같은 3요소 루브릭이나 같은 감점 규칙을 적용하는 안은 빼야 한다.
- 글자 수·시간 등 사실 확인과 점수 판정을 구분한다. 문체·베끼기 등의 자동 검출은 과제별 검수 없이 확정 감점으로 연결하지 않는다.
- IBT 쓰기 사양은 미확인이므로 PBT 51~54 지원을 IBT 지원으로 표현하지 않는다.
- 말하기는 별도 범위 결정으로 남긴다. 코인 확장도 읽기·쓰기 처방보다 뒤다. 알림은 확정된 주 1~2회 원칙을 따르되, 미완성 처방으로 돌아오게 만드는 것이 우선은 아니다.
