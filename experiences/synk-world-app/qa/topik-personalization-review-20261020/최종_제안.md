# SYNK WORLD TOPIK 맞춤 학습 — 최종 제안

> 2026-10-20. 1차 Claude([1차_Claude.md](1차_Claude.md)) → 2차 페이블([2차_페이블.md](2차_페이블.md)) → 3차 아스트라([3차_아스트라.md](3차_아스트라.md))를 합친 판이다. 근거는 공개판 synk.im/world(손님 체험), origin/master 코드, 실제 함수 시뮬레이션, 콘텐츠 실측, 외부 조사([외부조사_요약.md](외부조사_요약.md))다. 학생의 실제 학습 효과와 만족도는 아직 측정하지 않았다.

## 0. 결론

**WORLD의 엔진은 약점을 「잴」 준비가 되어 있다. 그런데 「메우는」 고리가 읽기에서 끊겨 있고, 학생 화면은 잰 결과를 접어서 보여 준다. 콘텐츠는 TOPIK I 입문 일부에 머문다.**

1. **측정은 믿을 만하다.**
   - 처음 보는 문항인지, 도움을 받았는지, 소리가 제대로 나갔는지, 응답 형식이 무엇인지를 갈라서 「혼자 맞힌 답」만 근거로 쓴다.
   - 짧은 진단 결과도 추천 순위에 실제로 들어간다. 한 번 틀린 항목은 .85, 한 번 맞힌 항목은 .55로 매긴다.
2. **처방 고리가 반쪽이다.**
   - 학습 항목이 연결된 활동은 듣기 게임 둘(바람길·말의 리듬)뿐이다. 그래서 TOPIK I 배점의 절반인 읽기 약점은 실제 연습으로 이어지지 않는다.
   - 「TOPIK 기초」를 고른 학생이 처음 받는 연습은 달리기 게임이다.
3. **화면이 엔진의 판단을 감춘다.**
   - 진단 뒤 「내 위치」는 맞힌 항목과 틀린 항목을 똑같이 「연습 중」으로 보인다.
   - 홈의 추천 이유는 숨겨져 있다.
   - 틀린 문항의 해설과 「이 항목 연습하기」 단추가 없다.
   - 「예상 급수」는 열릴 길이 없는데 「30문항 쌓이면 보여 드려요」라고 약속한다.
4. **콘텐츠가 TOPIK의 일부만 덮는다.** 공개판에서 쓰기·TOPIK II·모의시험·두 사람 대화 음성이 모두 0이다. 진단 듣기 문항은 대부분 게임 지시문이다.
5. **화면의 손맛은 강점이다.** 펠트 장면, 튜터, 이야기 레슨, 「맞아요 · 이유」, 새 장면 복습이 그렇다. 학생 만족에서 모자란 것은 겉모습이 아니라 다음 세 가지가 이어지는 고리다.
   - 내 약점이 보인다.
   - 그 약점에 맞는 연습이 온다.
   - 나아진 것이 보인다.

## 2. 최종 실행안

순서는 아스트라의 상위 10을 뼈대로 잡았다. 화면 설계는 페이블 안을, 지킬 선은 세 검수를 모두 따른다.

### 2-1 지금 묶음 — 「약점이 보이고, 맞는 연습이 오게」

계약·결정을 바꾸지 않고 기존 엔진과 재고로 한다.

1. **읽기 처방 고리 잇기(#1·#3·#13).**
   - 진단 전용 읽기 문항(빈칸 베기·입장 검사 글 사례·타운 읽기) 가운데 적합성·정답·계열 확인을 마친 것만 「읽기 짧은 연습」 후보로 넣는다. 그 문항들에 학습 항목(`targets`)을 잇는다.
   - 약점 항목에서 새 문항 몇 개를 고르는 선택기를 둔다. 진단 선택기는 항목마다 하나를 고르는 것이라 그대로 쓰지 않는다.
   - 답은 학습 기록으로 남기고 다음 추천에 다시 들어가게 한다.
   - 새 후보의 목표 토큰은 `exam`과 `prepare`가 함께 있을 때 순위를 두 번 올리지 않는지 확인한다.
2. **예상 급수 칸을 정직하게(#4).** 「0 / 30」 막대를 숨기고, 지금 할 수 있는 것만 쓴다. 예: 「시험 형식 연습이 생기면 그 답으로 범위를 알려 드려요」. 일정은 약속하지 않는다.
3. **진단 결과 구별·해설·바로 연습(#2·#7).**
   - 칸 3개는 유지하고 부제로 구별한다: 「한 번 틀림 · 확인 중」 「한 번 맞음 · 확인 중」.
   - 끝 화면에서 틀린 문항의 해설을 보인다.
   - 출제할 문항이 연결된 항목에만 「이 항목 연습하기」를 단다.
   - 첫 오답을 약점으로 못박지 않는다.
4. **위치판이 이력을 지키게(N1·N2·C).** 다음을 부제로 보인다.
   - 도움과 함께 한 시도
   - 난도별 「혼자 해냄」 이력
   - 7일이 지난 「다시 확인할 때 · 10월 10일 혼자 해냄」
   - 엔진 판정은 그대로 둔다.
5. **홈 추천 이유 한 줄(#6·#17).** 튜터 말 아래에 실제 근거 항목과 조건이 맞는 한 줄을 보인다. 예: 「읽고 이유 이해하기를 어제 2번 놓쳐서 오늘은 여기부터」. 기록이 많은데 「적다」고 말하는 이유문도 고친다.
6. **목표 이름과 저장 흐름(A·#15).**
   - 「TOPIK 기초」를 다른 이름으로 바꾼다(안: 「시험·자격 준비」, 유호님 결정).
   - 저장 스위치를 저장 단추 바로 위에 두고, 안내 문구를 스위치 이름과 맞춘다.

**완료 기준**(공개 전 시험과 손님·계정 리허설로 확인)

| 검증 입력 | 통과 결과 |
|---|---|
| 같은 조건에서 「듣기 강 · 읽기 약」과 「읽기 강 · 듣기 약」 두 학생 | 추천뿐 아니라 **첫 실제 출제 영역·항목**이 다르고, 이유 한 줄이 그 근거를 가리킨다 |
| 첫 진단에서 정답 하나 / 오답 하나 | 화면의 부제와 다음 행동이 다르다. 둘 다 「확인 중」(표본 부족)이라는 사실은 유지한다 |
| 도움·반복 재생·소리 실패 | 「혼자 해냄」으로 오르지 않는다. 시도 사실과 이유는 펼쳐서 보인다 |
| 그 항목의 새 문항 소진 | 다른 항목을 그 약점 연습인 척 내지 않고, 부족을 알리며 대안을 낸다 |
| 학습 뒤 새로고침·재시작·계정 전환 | 정해진 저장 범위에서 기록과 다음 추천이 돌아온다 |

### 2-2 다음 묶음 — TOPIK I 완성(교원 검수 포함)

7. **문항 매핑 교정과 칸별 재고(#10·#11·#18·D).**
   - 공식 문항 유형 ↔ 학습 항목 대응표를 만든다. 실제로 표현하지 못하는 능력만 Strata에 더한다.
   - 레이싱 c04 연결을 바로잡는다.
   - 얇은 칸에는 난도 1·2 새 문항을 보탠다.
   - 생활 66문항을 학습 항목과 학습 기록에 잇는다.
   - 기준은 총량이 아니다. 「그 칸의 확인 → 보충 → 다시 확인이 실제 재고로 끝나는가」다.
8. **듣기 진단 교체와 모드별 재생 규칙(#5·#20).**
   - 진단 듣기는 말 랠리·카페 응답·새 대화형 초안으로 바꾼다.
   - 시험형 문항은 공식 재생 횟수까지 기본으로 준다. TOPIK I은 두 번, TOPIK II는 1~20번 한 번·21~50번 두 번이다.
   - 허용 횟수·실제 재생·규칙 판을 기록한다. IBT 재생 규칙은 확인 전이라 쓰지 않는다.
9. **두 사람 대화 듣기 음성.** 합성 두 목소리로 장소·화제·그림·중심 생각·세트 문항을 만든다(자체 창작, 교원 검수).
10. **손님 → 계정 기록 이관(B).** 동의 범위, 다른 학생 로그인, 사건 ID·중복 이관, 학생 간 격리까지 시험한다.
11. **시험 종류·목표 급·시험일(#9·E).**
    - 제품이 가질 정보로 설계하고, Core에는 추천에 필요한 입력만 넘긴다.
    - PBT·IBT를 화면과 정책에서 가른다.
    - 영역 진행은 「확인한 학습 항목 수」로만 보인다. 점수·합격 준비도로 읽히면 안 된다.
12. **시험 형식 연습 · 근거 집계 · 급수 추정 검증을 세 작업으로 나눈다.**
    - 미니 모의(예: 듣기 10 + 읽기 10)는 연습으로 연다.
    - 예상 급수는 근거 30문항(영역별 10)이 처음 보는 문항으로 쌓이고, 범위를 읽는 방법이 교원·자료로 검증된 뒤에만 연다.

### 2-3 그다음 — 범위를 정한 뒤

13. **TOPIK II.** 듣기·읽기 지도를 만들고, 온라인 반 읽기 40·쓰기 8을 학습 기록에 잇는다. 공개 WORLD에 열지 반 학생만 쓸지는 유호님이 정한다.
14. **쓰기 51~54.**
    - 과제별로 다르게 평가한다. 51·52는 빈칸마다 문맥에 맞는지, 53·54는 내용 및 과제 수행·글의 전개 구조·언어 사용 세 범주다.
    - 글자 수·시간 같은 사실 확인과 점수 판정을 나눈다. 종결형·개조식 같은 자동 검출은 확정 감점이 아니라 「확인해 보세요」로 둔다.
    - 교사 첨삭이 기준이다. 자동 참고 피드백은 비용 승인 뒤에 붙인다.
    - PBT 기준이며, IBT 지원으로 표현하지 않는다.
15. **말하기.** TOPIK 말하기 평가는 별도 시험이라 따로 범위를 정한다.
16. **주 1~2회 학습 알림(10-19 결정).** 처방 고리가 선 뒤에 켠다.
17. **코인·옷장 보상 경로.**

## 3. 학생 만족을 위한 화면 원칙

| 화면 | 할 일 | 문구 원칙과 예 |
|---|---|---|
| 목표 | 이유 + (시험을 고르면) 시험 종류·목표 급·시험일·방식. 저장 스위치는 단추 바로 위 | 「목표는 연습을 고르는 길잡이예요. 급수를 매기지 않아요.」 「TOPIK I 2급 · 1월 11일 시험」(D-n 세기 없음) |
| 진단 | 진행 막대·항목 이름. 시험형 듣기는 「두 번까지 들을 수 있어요」. 답마다 「답을 기록했어요」 | 끝 화면: 항목별 맞음·틀림, 「해설 보기」, 연결된 항목만 「이 항목 연습하기」. 「틀린 건 다음에 볼 자리예요.」 |
| 내 위치 | 칸 3개 합계 → 「먼저 볼 항목」(최대 3) → 항목 행(칩 + 부제) → 근거 펼침 → 예상 급수 칸(정직한 상태) | 부제: 「한 번 틀림 · 확인 중」 「도움과 함께 시도 · 10월 20일」 「난도 1 혼자 해냄 · 난도 2 확인 중」 「다시 확인할 때 · 10월 10일 혼자 해냄」 |
| 홈 | 튜터 한마디 + **이유 한 줄** + 「맞춤 연습 시작」 + 다른 고르기 2개(하나는 다른 영역) + 「5문항 · 3분」 | 「소리를 못 쓰는 날이라 읽기로 골랐어요. 듣기가 약하다는 뜻은 아니에요.」 |
| 결과 | 혼자 맞힘·도움·틀림 → 바뀐 것 한 줄 → 틀린 것 해설 → 다음 한 걸음 → 보상 | 바뀐 것은 실제로 달라진 관측만 말한다. 「한 칸 올라왔어요」처럼 보장되지 않는 단계 표현은 쓰지 않는다 |
| 다시 오게 | 주 1~2회 학습 일만(결정대로). 앱 안에서는 「어제/지난번」 인사와 「바뀐 것 하나」 | 「다시 만날 표현이 돌아왔어요」. 연속 기록·죄책감·잠금 화면의 약점·점수 없음 |

**선도 서비스에서 가져올 것**(외부조사 §2·§3)
- 「내 답 설명」을 무료 기본 기능으로(Duolingo 2026-01 무료화, LingoDeer)

- 예상 점수는 범위로만(DET)
- 입문 결과는 공식 「TOPIK 기초」의 영역별 성취 구간처럼 설명한다(그 시험과 수준이 같다고 말하지는 않는다)

- 문제를 풀 때마다 바뀌는 예상 점수(산타의 대표 불만)

4. 새 문항·대화 음성 제작: 자체 창작 초안 + 교원 검수를 누가·어떤 비용으로 할지, 합성 두 목소리를 쓸지.

## 5. 지킬 선

- 게임 점수·정답률을 급수로 바꾸지 않는다. 공식 점수 환산·합격 판정을 하지 않는다(학습기준 §1·§7-3). 예상 급수는 검증된 방법과 근거 뒤에만 범위·근거 수·날짜로 보인다.
- Core가 추천 순위를 정한다. WORLD는 입력과 설정을 넘긴다(`world-learning-plan.mjs:5-6`). 화면 사정으로 Core 문턱을 낮추지 않는다.
- 연속 기록·죄책감 알림 없음. 알림은 주 1~2회, 학습 일만 말한다.
- 펠트·월드 시그널 디자인을 유지한다. 마스코트는 장면과 함께 새로 굽는다.
- 공식 기출은 앱 문항으로 쓰지 않는다. 한 자리에는 한 언어만 둔다. 화면에 AI 도구 이름을 쓰지 않는다. 새 문항은 교원 검수 전 초안으로 표시한다.
