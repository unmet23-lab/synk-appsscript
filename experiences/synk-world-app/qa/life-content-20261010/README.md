# 생활 한국어와 세 친구 이야기 · 브라우저 검수

2026년 10월 10일. 실제 앱의 `http://127.0.0.1:4312/mobile.html`에서 분리 DB `.local/life-content-20261010`와 합성 A/B 계정을 사용했다. 외부 요청은 차단했다. 학습 완료·복습 정답은 모두 화면의 보기와 다음 버튼을 눌러 기록했다. 완료 API나 저장값으로 결과를 만들어 넣지 않았다.

## 결과

- `source-r2/report.json`: **기능 검사 189개 통과**. 마지막 자산 검사에서 잘못된 분홍 펠트 경로의 HTTP 500을 발견했다. JavaScript 오류 0, 외부 요청 0.
- 수정 후 `source-r3/report.json`: **67개 통과**, 예상하지 않은 자산/API 오류 0, JavaScript 오류 0, 외부 요청 0. 네 펠트 변수의 절대 URL, 실제 분홍 펠트 HTTP 200·선택 보기 표시, 네 화면 크기의 보기·피드백·다음 동작을 재검사했다.
- r3은 r2의 기능 검사를 일부 반복한 재검수다. 두 숫자를 고유 검사의 합계로 더하지 않는다. 전체 기능 결과는 r2, 수정한 자산과 관련 화면의 최종 결과는 r3으로 읽는다.

## 실제 완료한 콘텐츠와 연결

- 생활 팩 6개가 홈의 생활 팩 메뉴에서 열린다. 각 팩에는 표현 → 이야기 → 생활 적용의 세 학습이 있다. 이야기 모음에도 실제 여섯 에피소드가 열린다.
- **18개 학습·본문항 54개·이야기 6개**를 실제 화면으로 완료했다. 이야기 여섯 개는 18개 학습 안에 포함된다.
- 표현 완료 뒤 같은 팩의 세 친구 이야기, 이야기 뒤 생활 적용, 팩 완료 뒤 다음 팩이 이어진다. 홈에는 실제 다음 진도와 완료 수가 반영된다.
- 오답은 첫 판정을 유지하고, 정답으로 다시 바꾸어 점수를 올릴 수 없다. 도움을 받은 정답도 도움 없이 고른 정답과 따로 기록한다. 한 문제의 도움 기록은 다음 문제로 번지지 않는다.
- 문제에서 쉬기 → 새로고침 → 다음 미응답 문제부터 이어 하기, 도움 보기 → 쉬기·새로고침 → 도움 흔적 유지, 이야기 중 닫기 → 새로고침 → 같은 컷 복원을 확인했다.
- 완료한 학습을 다시 열면 표현 소개부터 새 시도를 시작하며 곧바로 완료 화면으로 건너뛰지 않는다.

## 복습

- 복습 예정 시간이 오기 전에는 실제 다음 날짜와 시간을 보여 주고 시작 버튼을 만들지 않는다.
- 브라우저의 `Date.now`만 미래로 고정해 예정 시각 도래를 재현했다. 타이머·영상 재생은 계속 실행했고 진도 데이터는 수정하지 않았다.
- 오답·도움 받은 표현은 1분 뒤 새 상황으로 돌아오고, 도움 없는 정답은 다음 날 이후에 돌아온다.
- **변형 복습 54개**를 모두 실제 선택으로 완료했다. 같은 답을 다시 외우도록 본문을 복제한 화면이 아니라 별도의 prompt/context/choices를 사용했다.
- 복습의 도움 표시 → 쉬기·새로고침 → 같은 복습 세션과 도움 흔적 복원을 확인했다. 정답을 고른 표현의 다음 복습은 미래 간격으로 옮겨졌다.

## 화면과 계정

- 모든 보기·닫기·다음 목표는 44px 이상이다. 스크롤이 필요한 내용은 실제로 해당 보기까지 스크롤한 뒤 중앙이 다른 요소에 가리지 않는지 확인했다.

- A/B 계정은 이번 전용 로컬 서버의 인증·진도 GET/POST를 사용했다. 자격증명은 localStorage에 저장되지 않았다.

## 실행과 보존한 앞선 시도

전체 시나리오는 `../life-content-browser.cjs`, 자산 수정 재검사는 `source-r3/targeted-assets.cjs`다. 전체 시나리오의 합성 A/B 최초 진도 검사에는 새 전용 DB가 필요하다.

`source-r1`은 라이브러리의 홈/대화상자 선택자를 구분하지 않아 테스트 자체가 멈춘 기록이다. `source-r3/initial-report.json`과 `initial-failure.jpg`는 브라우저 이미지 응답 이벤트 대기가 이미 읽힌 이미지를 놓친 첫 재검수 기록이다. 실제 자산 오류가 재발한 기록은 아니며, 최종 재검사는 실제 표시된 background URL의 GET 200과 화면으로 확인했다.

이 검수는 격리된 Edge 브라우저와 로컬 앱에 관한 결과다. 운영 OAuth·공개 배포·실물 휴대폰·네이티브 앱·실제 학생의 학습 효과를 검증한 결과로 확대하지 않는다. 준비한 콘텐츠는 읽고 선택하는 연습이며 새 음성이나 듣기 기능을 생성했다고 보고하지 않는다.

## 최종 정적 출력물과 account 모드

최종 동결 출력물 `.tmp/world-app-life-20261010-r4/world`를 별도 임시 HTTP 서버의 `/world/`에서 실제로 열었다. `../account-browser.test.mjs`는 브라우저 시나리오 한 개에서 기존 **16개 검수 범주와 새 생활 콘텐츠 7개 범주**를 함께 확인했다. `account-static-r4/report.json`은 `ok:true`, JavaScript 오류 0, 자산 오류 0, 실제 외부 요청 0이다. 이 23개 범주를 앞선 189·67개 검사 수에 더하지 않는다.

- 실제 account 모드에서 생활 학습은 앱 내부 player로 열리고 iframe을 만들지 않는다. 세 친구의 새 자산은 `/world/` 아래에서 정상 표시된다.
- 첫 문항을 화면으로 고른 뒤 공식 PlayHost의 `synk.life-korean.progress.v1` 기록을 모의 계정 서버가 저장했다. 쉬기·새로고침 뒤 같은 시도의 다음 미응답 문항이 복원됐다.
- 나머지 두 답도 실제로 골라 완료한 뒤 새로고침해도 홈의 1/18과 다음 이야기가 남았다. 이야기 두 컷은 가로·세로 회전 중 동일한 문서와 컷을 유지했다.
- 타운, 명시적 학습 동의, 반 연결 확인·승인, BFCache 재검증, runner/rhythm의 같은 iframe 회전·보상·중복 방지·진도 충돌 복구, 한글 복귀, 게임 계정 host 종료를 함께 확인했다.
- 로그아웃 후 계정 생활 진도 연결이 해제되고 guest 연결로 바뀐다. guest가 실제 홈 학습을 열어 첫 정답을 고르고 피드백을 받았다. guest의 답은 기기에 남으며 A의 계정 진도 원본과 계정 API 호출은 바뀌지 않았다.

이 모드의 인증·계정·저장 응답은 정확히 지정한 fixture URL에 대한 브라우저 route로 모의했다. 운영 OAuth나 실제 원격 계정을 사용한 결과는 아니다. 정적 출력물을 검사한 것이며 공개 배포가 아니다.

앞선 r3 정적 검사에서 account 로그아웃 시 owner는 guest로 같지만 client 세대가 두 번 바뀌어 생활 진도 guard가 끊기는 문제를 발견했다. 당시 실행의 `account-static-r3/failure-observation.md`를 보존했다. root가 owner와 세대 모두를 연결 초기화 기준으로 수정한 후 r4에서 **guest의 실제 학습 선택까지** 다시 확인했다. 최종 정적 파일 해시·검수 위치는 `verification.json`의 `finalAccountStatic`에 기록했다.

최종 대표 화면은 `account-static-r4/life-story-account-mobile.png`다. 계정 저장 표시를 포함한 실제 모바일 이야기 화면이다.

### 브라우저 검수 도구의 종료 정리

최종 r4의 제품 시나리오는 23개 범주를 모두 통과했고 `report.json`에 보존했다. 첫 실행과 브라우저 connect client의 `close()`를 추가한 재실행 모두 같은 제품 조건을 통과했다. 재실행 전 첫 보고서는 `initial-report-before-client-teardown.json`으로 남겼다.

이 환경에서 Playwright `launchServer`/`connect` 종료 Promise와 Node runner 참조가 남아, 전체 CLI의 정상 종료를 제품 PASS와 별도로 확정하지 못했다. command line·부모/자식 관계를 확인한 이 검수의 Node 프로세스만 종료했다. 사용자 서버 4312·4307은 유지되고 health 응답을 확인했다.

앱·계정에 접속하지 않는 빈 브라우저의 보조 transport 검사에서는 종료 응답 timeout, SDK listener의 늦은 해제, 종료 상태 property의 미확정을 확인했다. 세 보조 실행은 각각 exit 1이었으며 **제품 23개 조건의 실패로 합치지 않는다.** 정리 도구의 정상 종료나 graceful 종료를 성공했다고 보고하지 않는다. 더 넓은 SDK 조사는 이번 요청 범위에서 종료했다. 당시 보조 코드만 `transport-close-smoke.source.txt`에 보존하고 자동 제품 시험으로 실행되지 않도록 했다.

최종 확인한 이 검수의 Node 작업자 잔여 수는 0이다. 제품 코드·최종 동결 출력물 해시는 정리 과정에서 수정하지 않았다.
