# 코스튬 방 편의성 후속 마감 — 2026-10-10

사용자의 「이어서 해」 요청으로 [기존 22개 구현](../costume-convenience-20261009/README.md) 다음에 실제 사용 동선을 점검했다. 작은 PC 창의 첫 의상 노출, 저장 재시도 이후 편집 폼, 기존 코디의 이름·조합 수정 세 부분을 보강했다. 공개 배포나 운영 DB 변경은 하지 않았다.

[현재 코스튬 방](http://127.0.0.1:4296/desktop.html?wardrobe=1&opening=off&atelier=8)

## 달라진 동작

- **첫 옷을 바로 고르기:** PC 코디 행거를 한 행으로 줄이고 탐색 간격을 정리했다. 낮은 창에서는 검색과 종류·상세 필터를 조밀하게 배치해, 1265×712에서도 첫 옷의 그림과 이름이 하단 고정 버튼 위에 보인다. 44px 조작 높이를 유지하며, 상세 필터를 펼치면 전체 폭으로 사용한다.
- **재시도 성공도 같은 완료 처리:** 같은 요청의 저장 재시도가 성공하면 완료 메시지·폼 정리·마지막 변경 되돌리기를 적용한다. 폐기·계정 변경은 오래된 완료 처리를 취소한다. 기다리는 동안 새로 고친 이름·초안·다른 편집 대상은 지우지 않는다.
- **원본 수정과 시착 구분:** 관리의 「이름·조합 수정」으로 연 코디는 옷·염색·Undo 편집 뒤에도 같은 ID에 저장된다. 12개를 채웠어도 기존 코디 수정은 가능하다. 다른 코디의 그림을 눌러 시착하거나 새 조합·복제를 선택하면 원본 수정 상태를 푼다.
- **다른 화면의 최신 기록 보존:** 편집 대상이 다른 화면에서 삭제되면 이름·초안을 남기고 저장을 막는다. 명시적으로 새 조합을 선택해야 새 ID로 보관한다. 재전송 응답의 최신 룩북이 보낸 목록과 다르면 과거 목록 Undo를 연결하지 않는다.

## 검사 기록의 오류와 보존

콜백 검사의 첫 실행은 수정 전 경로가 수정 후 모듈을 읽는 설정 오류와 숨겨진 행거 선택 오류가 있었다. [첫 실행 원본](callback-browser-attempt1-result.json)과 callback-browser-result.json은 그 제외 기록이다. 교정 실행의 전체 JSON이 늦게 종료된 첫 실행에 덮여, 정상 실행의 원문 출력·exit0·SHA 확인을 별도 보존했다. 정상 실행의 상세 관측값을 덮인 JSON에서 가져오지 않았다. 재현기는 이제 실행별 결과 파일명을 사용한다.

배치 전 비교의 about:blank localStorage 초기화 오류도 원자료에 남겼다. 초기화 대상을 HTTP 문서로 제한한 후 마감/최종 배치에서는 오류 0이다. 기존 4296 계정에는 저장 요청을 보내지 않았고, 본인 콜백 시험 서버 두 개의 종료·포트 해제를 확인했다. 실제 휴대폰·컨트롤러·운영 계정·공개 결과와 구분한다.
