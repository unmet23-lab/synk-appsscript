# SYNK 가족 이야기 앨범

사진 밖의 이야기와 원래의 목소리를 한 페이지에 남기는 **로컬 MVP**다. SYNK 회원 혜택의 개발 미리보기이며, 공통 SYNK ID의 개인 앨범 저장 연결을 구현했다. 운영 계정 설정·배포와 실제 사용자 왕복은 미검증이며 가족 초대·다른 사람에게 공유하는 기능은 없다.

```powershell
node experiences/family-album/server.mjs
npm --prefix experiences/family-album test
```

고정 주소는 `http://127.0.0.1:4298/`다. 서버는 이 기기의 loopback 주소에만 열리며 GET/HEAD와 정확히 선언된 공개 파일·Core 원본·공통 계정 모듈 및 공개 `/api/account-config`를 제공한다. 계정 연결 설정이 유효할 때만 지정된 SYNK 인증·개인 문서·비공개 원본 저장소에 연결한다. 로컬 서버 자체는 업로드나 개인 자료를 공개하지 않는다.

## 지금 되는 경험

- 제목·이야기·기록하는 이름만으로 첫 장을 만든다. 날짜·함께한 사람·사진·목소리는 선택이다.
- JPG/PNG/WebP 사진과 MP3/WAV/M4A/OGG/WebM 음성을 가져온다. 브라우저가 실제 디코딩할 수 있는지 확인하고, 원음은 변경 없이 보관한다. 사진은 2,000만 화소까지다.
- 일반 브라우저는 직접 누른 뒤 마이크 권한을 얻어 최대 5분 녹음할 수 있다. 실제 지원되는 MediaRecorder 형식만 쓴다. 설치형 앱은 파일로 원음을 추가하며 마이크 권한을 우회하지 않는다.
- 앨범 목록에서 사진·이야기·원음을 보고 듣고, 내용을 수정한다. 가족의 기억은 이름 또는 전해 준 출처와 함께 앨범에 덧붙인다. 실제 다른 계정의 접속이나 초대 기능으로 표시하지 않는다.
- 아직 답하지 않은 후속 질문 하나를 보여 준다. 답은 페이지에 남고 답한/건너뛴 질문은 다시 묻지 않는다. 입력한 인물·제목을 수정하면 질문 문구에도 반영한다. 세부 답을 지우면 그 항목은 다시 비어 있는 것으로 취급한다.
- 페이지와 가족의 기억 삭제는 바로 전 앨범 상태로 되돌릴 수 있다.
- 로그인 전 기본은 탭 메모리다. **이 기기에 보관**을 켜야 IndexedDB에 저장한다. 끄면 디스크의 사본을 지우고 탭의 앨범은 유지한다. 저장 트랜잭션 실패는 성공으로 표시하지 않고 이전 앨범을 유지한다.
- `synk-family-album.json` 파일로 원래 사진·음성을 포함해 내보내고 다시 불러온다. 가져온 파일은 형식·크기·미디어 헤더·브라우저 디코딩 검사 후 교체 내용을 확인한다. 이름·원문·날짜·추가 기억·질문 답/건너뜀과 미디어 바이트를 보존한다.


## SYNK ID와 원본 보관 · 2026-10-06

공통 `product-account.mjs`·`document-sync.mjs`·`account-notebook.mjs`를 사용한다. 계정 연결 설정 또는 네이티브 연결이 있어야 로그인 후 서버 저장을 한다. `synk-personal`의 `resource=family-album`은 계정 소유 문서이며, 가족 이름이나 회사·학원 역할로 다른 사람에게 권한을 주지 않는다.

- 로그인 전 앨범은 자동 업로드하지 않는다. **기기 기록을 계정으로 옮기기**에서 교체를 확인한 경우에만 옮긴다. 로그아웃·계정 전환 때 원래 기기 앨범과 저장 설정을 복원한다.
- 문서는 `synk-family-album-manifest` version 1이다. `photo`·`audio`에는 파일 이름과 서버가 발급·확인한 `mediaRef {assetId,sha256,mime,size,kind}`만 저장한다. 계정 DB 문서에 base64 원본을 넣지 않는다. URL·Storage 경로를 문서에 보관하지 않는다.
- 원본은 한 파일씩 비공개 저장소에 올리고 서버의 소유·크기·SHA-256 확인이 끝난 참조만 문서에 넣는다. 읽을 때도 크기·SHA-256과 기존 앨범 미디어 헤더를 검사해 원래 바이트로 복원한다. 사진 6 MiB·음성 8 MiB·원본 합계 20 MiB·30페이지, 기존 JSON 복원/내보내기 32 MiB 한도를 유지한다. 텍스트만 큰 기존 앨범도 2 MiB로 임의 축소하지 않는다.
- 원본 읽기 실패 중에는 불완전한 앨범을 편집하지 않도록 막고 **다시 불러오기**로 같은 문서의 원본만 다시 읽는다. 일시적인 읽기 실패 때문에 미저장 대기 문서를 자동으로 버리지 않는다. 늦게 도착한 이전 계정의 파일·문서는 현재 화면에 적용하지 않는다. 미완료 업로드는 저장 완료로 표시하지 않으며 창을 닫기 전에 내보내거나 다시 저장할 수 있다.
- 앨범에 한 번도 저장되지 않은 업로드 원본만 7일 유예 후 정리 대상이 될 수 있다. 정상 저장된 앨범 원본은 이 기한으로 만료되지 않는다. 저장 대기 안내에 저장 완료 또는 JSON 내보내기로 보관하도록 표시한다. `ASSET_NOT_FOUND`·`ASSET_NOT_CONFIRMED` 뒤 **저장 다시 시도**는 서버가 지정한 원본 하나만 현재 화면의 바이트로 다시 업로드하며 정상 참조는 유지한다. 저장 성공 때 빠진 참조만 캐시에서도 제거하므로 페이지 삭제 되돌리기나 같은 사진 다시 넣기가 지워진 참조를 재사용하지 않는다.
- 원본 없이 오래된 미저장 문서만 남은 경우 **미저장 기록 남기고 저장본 열기**를 제공한다. 현재 화면을 바꾼다는 확인 뒤에만 마지막 정상 계정 저장본으로 돌아간다. 미저장 글과 파일 참조는 복구용 기기 기록으로 보존하고, 완전 삭제는 해당 계정으로 로그인한 상태에서 별도 확인한다.
- 다른 기기의 수정은 다시 불러오기로 확인한다. 충돌 시 서버본을 쓰거나 현재 화면으로 바꾸는 선택을 직접 확인한다. 저장 ACK는 작성 중인 폼을 초기화하지 않는다.

**계정의 앨범 전체 삭제**는 사진·음성 원본까지 삭제한다는 확인 뒤 계정의 삭제 요청을 보낸다. 20MiB 또는 파일 수 한도에 닿으면 기존 사진·음성을 제거하고 저장을 마친 뒤 새 원본을 추가한다. 용량·형식·원본 거절은 연결 대기와 구분해 수정할 내용을 표시한다.

계정에 보내지 못한 변경(`pending=true`)만 이 앱의 계정별 임시기록으로 기기에 보관한다. 저장 완료·다시 불러오기·로그아웃 때 완료 사본은 제거한다. 로그아웃 뒤에는 남은 기록의 존재만 알리고 해당 계정으로 로그인해야 복구 파일 내보내기·명시 삭제를 쓸 수 있다. 현재 편집·전송 중에는 삭제하지 못하며 다른 계정·서버·다른 앱·로그인 전 기기 기록은 그대로 둔다. 탭별 독립 초안과 요청별 정리를 유지하고 이전 초안은 하나여도 직접 골라 연다. 소유 계정을 확인할 수 없는 손상 원문은 보존하고 이 화면에서는 내보내거나 지우지 않는다.

운영 전환과 실제 사용자·실기기 검증은 아직 완료하지 않았다. 2026-10-07 리허설의 public OAuth client 18개 등록·포털 반영, care/personal 배포 및 합성 공급자 원본 왕복은 [공통 QA](../synk-account/qa/unified-account-20261006.md)에서 범위와 정리 결과를 구분한다. [합성 브라우저 QA](../synk-account/qa/personal-apps-20261006/results.json)는 사진 저장→새 브라우저 context에서 정확한 원본 복원, 로그아웃 중 늦은 읽기 무시, 375/1440px 화면을 검사한다. 명령은 `node experiences/synk-account/qa/personal-apps-smoke.cjs`다. 공통 계약·기존 모델·저장 회귀 46개와 [실제 Electron 시작 검사](../../desktop/artifacts/personal-native-20261006.json)는 통과했으며 운영 성공의 증거는 아니다.

후속 코어 검수의 캐시·용량 문제는 [원본 참조 회귀 기록](../synk-account/qa/family-media-cache-20261006.md)에서 확인했다. 실제 Chrome 개인 3앱 76/76에는 5MiB 사진 세 장의 삭제·되돌리기·동일 파일 재추가·원본 하나만 재시도·앨범 전체 삭제 후 재저장을 포함한다. mock도 서버와 같이 제거된 원본을 즉시 삭제하고 20MiB/60개 한도를 적용한다.

## 내가 가져가는 한 권 · 2026-10-06

앨범의 **소장본 만들기**에서 현재 저장한 모든 이야기와 손맛 기록을 책으로 펼친다. 표지·목차·사진·본문·직접 답한 세부 내용·출처가 있는 가족의 기억을 담으며, 목차를 누르면 해당 이야기로 이동한다. **인쇄 / PDF로 저장**은 브라우저 인쇄 창을 연다. 실물 제작·제본·배송 주문을 제공하는 것은 아니다.

**소장용 묶음 내려받기**는 `synk-family-album.zip`을 만든다. 먼저 압축을 해제하고 `index.html`을 열면 SYNK 로그인이나 인터넷 연결 없이 책과 원음을 열 수 있다.

| 묶음 안의 파일 | 용도 |
|---|---|
| `index.html` | SUIT·Inter Tight와 인쇄용 스타일을 내장한 이야기책. 스크립트·외부 요청 없이 읽으며 원음 재생은 브라우저가 지원하는 형식을 따른다. |
| `originals/page-001-photo.webp` 등의 생성 파일명 | 사용자가 넣은 사진·음성을 원본 바이트 그대로 보관. 확장자는 확인된 형식에 맞추고 원래 파일명은 책과 복원 JSON에 남긴다. |
| `synk-family-album.json` | 다시 불러와 편집할 앨범. 사진·음성·질문 기록·가족의 기억·손맛과 시도 기록을 포함한다. |
| `읽어주세요.txt`, `FONT-LICENSE.txt` | 압축 해제·재생·인쇄·복원 안내와 서체 라이선스. |

`index.html`과 `originals`는 같은 폴더 안에 함께 보관해야 한다. 종이와 PDF에는 음성이 재생되지 않으므로 원음 파일도 함께 간직한다. 긴 본문·조리 순서·가족의 기억은 인쇄 시 여러 쪽으로 이어지며 사진은 비율을 유지한다. 작성 중인 미저장 내용은 소장본에 포함되지 않는다.

## 우리 집 손맛과 시도 기록

- 별도 **우리 집 손맛** 입구에서 음식 이름, 음식에 얽힌 이야기, 기록하는 이름, 배운 곳, 재료, 만드는 순서를 남긴다. 인분과 기존 날짜·사진·원음은 선택이다. 기존 이야기 페이지와 함께 같은 앨범·책·복원 파일에 보관한다.
- 배운 표현은 그대로 남긴다. “적당히”를 임의의 수치로 바꾸지 않는다. Core는 사용자가 직접 확인한 양, 불 세기와 시간, 완성의 기준 중 아직 남기지 않은 것을 묻는다.
- 직접 만들어 본 날짜와 결과 메모를 추가·삭제할 수 있다. 실제 시도를 기록하기 전에는 **아직 직접 만들어 본 기록이 없어요**로 표시한다. 시도 횟수는 사용자의 기록이며 현재 레시피의 완성도·안전성 검증을 뜻하지 않는다.
- 배운 곳·인분·재료·순서를 바꾸면 `recipe.revisedAt`을 갱신한다. 최근 시도 **기록 작성 시각**보다 수정이 늦으면 **마지막 기록 뒤 레시피를 수정했어요**라고 표시한다. 과거에 요리한 날짜와 기록을 작성한 시각을 구분한다.
- 기존 버전 1 이야기 파일은 `recipe` 필드를 추가하지 않고 그대로 읽고 쓴다. 손맛 페이지에만 선택 필드로 레시피를 보관한다.

상세 화면의 질문 답, 만들어 본 기록, 가족의 기억 입력은 각각 탭 안에서 초안을 유지한다. 한 입력을 저장하거나 같은 화면을 다시 그려도 다른 입력의 미완성 글은 보존한다. 작성 중 이동·가져오기는 버릴 내용을 확인하며, 이 초안은 새로고침 후 복원을 보장하는 영구 저장이나 앨범에 저장한 기록과는 다르다.

## Core 재사용과 경계

원본 [Core Domain](../../atlas/domain.js)의 `understand`는 이 페이지에 직접 입력한 세부 답을 `SYNK / family-album / page-id`, 목적 `next-story-detail`의 선언으로 처리한다. [Core Ask](../../atlas/ask.js)의 `choose`가 그 선언과 질문 건너뜀을 받아 아직 페이지 내용을 바꿀 수 있는 질문을 고른다. 일반 이야기의 장소·계기·한마디·남은 마음, 손맛의 직접 확인한 양·불 세기와 시간·완성 기준 후보와 문구는 제품이 제공한다.

자유롭게 쓴 글·사진·음성의 의미를 분석하거나 가족의 성격·감정을 추론하지 않는다. 유료 모델·전사·음성 합성은 부르지 않는다. 이 구현은 기존 Core의 **재사용**이며 엔진 전체 발전·사람의 효과 검증으로 보고하지 않는다.

## 보관·호스트 계약

| 항목 | 한도 |
|---|---|
| 한 장의 사진 / 음성 | 6 MiB / 8 MiB |
| 앨범 전체 미디어 | 20 MiB |
| JSON 내보내기·가져오기 | 32 MiB, `application/json`, 정확한 파일명 `synk-family-album.json` |
| 소장 묶음 내보내기 | ZIP 실제 크기 64 MiB, `application/zip`, 정확한 파일명 `synk-family-album.zip` |
| 페이지 / 페이지당 덧붙인 기억 | 30장 / 40개 |
| 이야기 / 추가 기억 / 질문 답 | 10,000 / 2,000 / 1,000자 |
| 레시피 배운 곳·인분 / 재료 / 순서 | 각각 120 / 6,000 / 10,000자 |
| 레시피당 시도 기록 / 시도 메모 | 20번 / 2,000자 |

UTF-8 글과 base64 원음까지 포함한 직렬화 크기를 **모든 저장 전** 검사한다. 허용한 앨범이 JSON 내보내기 한도를 넘는 상태는 받아들이지 않는다. ZIP은 책·원본·복원 JSON을 함께 담기 때문에 따로 실제 크기를 검사하며, 64 MiB를 넘으면 앨범을 나누도록 안내한다. 음성 재생·검사용 URL은 Blob URL이며 교체·페이지 이동 때 해제한다. 실제 저장·JSON 내보내기에는 원음 base64가 그대로 남는다.

소장 묶음은 사용자 파일명을 경로로 쓰지 않으며 개인 입력을 HTML로 이스케이프한다. 독립 책의 CSP는 스크립트·네트워크 연결·프레임·폼을 차단하고 내장 글꼴 및 로컬 사진·음성만 허용한다. 앱 미리보기는 기존 고정 공개 파일과 네트워크 차단 계약 안에서 동작한다.

준비 완료 표시는 `document.documentElement.dataset.ready = 'true'`다. 이 표시만으로 사진/원음 재생이나 실사용 검증이 끝난 것은 아니다.
