# 게임의 튜터 교체 확인 · 2026-10-11

로컬 `http://127.0.0.1:4314`의 한 격리 게스트 브라우저에서 실제 설정을 눌러 **마린 → 까몽 → 몽글 → 마린**으로 확정했다. 앱을 새로고침하거나 선택 저장소를 직접 바꾸지 않았다. 제품 파일 수정은 없었다.

## 결과

- [최종 결과](report.json): **210개 확인 통과**, 콘솔 오류·누락 자산·외부 요청·서버 쓰기 0.
- 네 선택 단계마다 한글 만나기·바람길·말의 리듬에 진입했다. 총 12개 게임 진입에서 새 튜터 ID가 실제 iframe까지 전달되고 조작법의 세 대사와 캐릭터 이미지가 정본과 일치했다.
- 세 캐릭터 × 세 게임의 신규 조작연습을 실제 단추 입력으로 완료했다. 각 단계의 말투와 성공 표정이 선택한 튜터와 일치했다. 마지막 마린 복귀에서는 기존 마린의 연습 완료 상태를 재사용했다.
- 실제 피드백은 처음 마린의 한글, 까몽의 바람길, 몽글의 리듬, 돌아온 마린의 한글에서 확인했다. 오답·정답, 캐릭터별 정확한 대사·얼굴 SRC, 누적 힌트의 캐릭터 대사, 기본 얼굴 복귀를 검사했다.
- 닫힌 게임의 DOM을 계속 관찰했으며 다음 선택과 게임이 진행되는 동안 얼굴·대사 변동과 반응음 잔류가 없었다. 게임 메시지 리스너는 실행 중 1개, 닫은 뒤 0개였다.
- 기록한 마스코트 반응음 46개가 선택 튜터의 정본 `sounds` 목록과 일치했다. 실제 게임 진행 중 반응음 시작은 없었다. 재생 객체 상태와 요청 검증이며 실제 청취 품질 검수는 아니다.
- 브라우저 컨텍스트와 브라우저를 종료했다. 실계정 로그인·외부 쓰기·배포는 하지 않았다.

## 재현과 범위

[실행 스크립트](../verify-games.cjs)는 기존 `practice-browser-helpers.cjs`를 재사용한다.

```powershell
node experiences/brand-opening/qa/tutor-switch-20261011/verify-games.cjs
```

바람길과 리듬의 기존 `?qa` 보조는 대기 시간을 줄이고 실제 게임 입력/판정 경로로 진행한다. 튜터 반응 이벤트를 만들어 보내지 않는다. 한글은 `?qa=silent`에서 실제 선택지를 클릭하며, MP3 청취 검수는 이 실행의 범위가 아니다. 390×844, 움직임 감소 상태에서 교체 기능을 확인했다. 전체 시각 반응·다른 화면 크기 검수는 기존 표정 검수와 홈 담당 결과를 참고한다.

## QA 비교식 보정

초기 짧은 시도에서는 한글 이미지 파일명의 URL 인코딩을 풀지 않고 비교해 실패했다. 비교를 고친 뒤 전체 브라우저 흐름을 다시 실행했다.

전체 흐름의 마지막 오디오 비교식은 파일명이 항상 튜터 ID로 시작한다고 잘못 가정했다. 정본에는 `marine-*`, `myang.wav`, `mu.wav`, `ppuu.wav`처럼 별도 이름이 있으므로 스크립트를 정확한 `profile.sounds` 목록 비교로 수정했다. 이미 기록한 46개 재생 이벤트와 오류/요청 기록을 이 기준으로 다시 검증했다. 통과한 브라우저 흐름을 다시 실행한 것으로 보고하지 않는다. [원시 브라우저 실행 기록](recorded-browser-run.json)은 이 QA 비교식 실패까지 그대로 보존했다.
