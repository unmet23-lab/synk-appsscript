# 플레이 중 가로·세로 회전 검수

2026-10-10. 사용자 「가로세로 둘 다 지원 … 게임 중에 돌려도 진행 안 끊기고 화면 안 깨지도록」 확정에 따른 로컬 수정·검증이다. 홈 설정의 자동·세로·가로 선택을 유지하고, 실제 홈에서 여는 세 게임을 플레이하며 검사했다.

## 확인한 문제와 수정

- 바람길: 회전 전 누른 좌표와 회전 뒤 뗀 좌표가 비교돼 의도하지 않은 점프가 들어갔다. resize·lostpointercapture에서 미완성 제스처만 취소한다. 다음 새 터치·스와이프·키보드는 정상 처리한다.
- 바람길: 740×320에서 계정 안내와 상하 조작판 때문에 무대가 약 40px만 남았다. 가로에서는 2×2 조작판을 오른쪽에 두고, 체험 상태 안내를 간결하게 유지해 무대 155px를 확보했다.
- 리듬: 같은 작은 가로 화면에서 문제 카드가 O/X 버튼을 덮었다. 문항은 왼쪽, 노트 무대와 답 버튼은 오른쪽에 두고 캔버스의 실제 위치에 판정선을 맞췄다. 일시정지 창도 짧은 높이에 맞췄다.
- 한글: 가로에서 고정된 다음 버튼이 문제·노래를 덮었다. 학습 영역과 다음/확인을 좌우로 나누고 긴 설명·결과는 자기 영역에서 스크롤하게 했다. 필기와 선택한 답의 DOM은 유지한다. 320px 세로에서 받침 노래의 조각이 23px 넘치던 것도 고쳤다.
- 한글 필기의 회전 뒤 좌표/획 보존은 앞선 v3 수정이며 이번에는 손을 누른 채 회전, 작은 화면 왕복, 지우기까지 다시 확인했다.

실제 파일 음원을 사용했다. 한글은 소리 없는 QA 모드 대신 승인 MP3 경로와 HTMLAudioElement의 재생 시각을 확인했다. 바람길과 리듬은 게임 시간·음성 시각이 함께 멈추고 이어지는지 확인했다. 세 게임 모두 회전으로 완료 기록이나 보상이 중복되지 않았다. 최종 위 검사에서 JavaScript·HTTP 오류와 외부/변경 요청 시도는 0이다.

브라우저는 격리된 Edge다. 390×844↔844×390 및 320×740↔740×320을 반복하며 DPR·캔버스 좌표·화면 가림·실제 버튼 입력을 확인했다. 바람길은 기존 QA 자동입력으로 시간을 가속하지 않고 완주했으며, 리듬과 한글은 테스트가 읽은 정답을 실제 화면 버튼으로 입력했다. 인위적으로 곡 끝으로 이동하거나 실제 사용자/학생의 수행을 기록한 것이 아니다. 받침 진도 fixture는 격리 localStorage에만 저장했다.
