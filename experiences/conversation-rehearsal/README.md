## 실행

```powershell
node experiences/conversation-rehearsal/server.mjs
node --test experiences/conversation-rehearsal/tests/*.test.mjs
```

주소는 `http://127.0.0.1:4297/`이며 서버는 `127.0.0.1`에만 바인딩한다. `createServer()`를 내보내므로 포트 0으로 독립 시험할 수 있다. 저장소 안의 승인 자산과 Core 원본을 읽는다. 별도 설치·번들·유료 API는 없다. 유효한 계정 연결 설정이 있을 때 지정된 SYNK 인증·개인 기록 API를 사용한다.

## 구현된 흐름

1. 면접·부탁·거절 선택 → 상대 유형 2개와 목표 2개 중 각각 선택 → 대화 상대와 오늘의 목표를 자유롭게 보충. 고른 유형은 준비된 대사와 힌트를 바꾸며, 자유 입력은 자동 분석하지 않는다. 선택을 바꿔도 직접 쓴 메모는 보존한다.
2. 첫 번째 연습용 대사에 텍스트로 답하고 `말할 수 있었어요 / 조금 망설였어요 / 말이 막혔어요`를 직접 선택.
3. `내용을 구체적으로 / 짧고 분명하게 / 부담스러운 반응에 답하기` 중 하나를 선택하면 두 번째 상대 대사가 실제로 달라진다. 마지막에는 대화를 마무리하는 대사에 답한다.
4. 세 번을 마치면 첫 답변을 편집 가능한 첫 문장에 담는다. 사용자가 첫 문장과 기억할 한 가지를 직접 다듬고 복사할 수 있다.
5. 각 대화를 다시 연습하면 처음 작성한 답변과 재작성, 각 시점의 자기평가를 함께 보여 준다. 최초 답변을 덮어쓰지 않는다.
6. 같은 상황의 지난 기록에서 아직 막힘·망설임으로 남은 턴이 있으면 처음 화면에서 그 턴으로 바로 이어 간다. 다른 상황의 기록을 섞지 않는다. 재작성 후 직접 편해졌다고 고르면 해당 턴을 막힌 부분으로 추천하지 않는다.
7. 완료한 연습이 한 번이라도 있으면 **내 성장 작품집**을 연다. 실제로 남긴 최근 최대 10회 기록을 오래된 순서대로 모아 상대 대사·처음 쓴 말·가장 최근에 다시 쓴 말·각 시점에 직접 고른 느낌·내 첫 문장·기억할 한 가지를 함께 보여 준다. 결과에서 수정한 첫 문장과 메모는 작품집으로 이동할 때 반영하고, 처음 화면에서 적던 다음 연습의 목표는 돌아왔을 때 보존한다.

답변 내용은 분석하지 않는다. 기본 대사 15개는 기존 기록 재생용으로 보존하고, 새 연습은 상대·목표의 12개 조합과 각 3가지 연습 방향을 사용한다. 목표마다 첫 질문·구체화·짧게 말하기·압박 반응·마무리의 대사와 실행 힌트를 작성했으며, 상대 유형에 따라 도입·압박 반응과 말할 때의 주의점이 달라진다.  생성형 AI 대화·음성 인식·음성 생성·능력 점수·실제 대화 성과 평가는 구현 범위가 아니다. SYNK ID 개인 기록 연결은 아래 별도 계약을 따른다. 플랫폼이 연결한 미리보기이며 회원 권한 부여나 공개 서비스 출시는 별도다.

## Core 재사용과 근거

담당 원본은 [`atlas/ask.js`](../../atlas/ask.js)다. 서버가 `/core/ask.js`로 원본 바이트를 그대로 제공한다. 별도 엔진이나 복제된 판단 모듈을 만들지 않았다.

`domain.mjs`의 `followupQuestion()`은 제품의 작성된 분기 후보를 Core `Ask.choose()`에 넘긴다. 연습 방향의 답은 실제 두 번째 대사를 바꾸므로 질문으로 선택되고, 텍스트 연습의 내용을 바꾸지 않는 속도 질문은 건너뛴다. 자기평가·선택·목표는 사용자의 명시 입력이고 성격·능력의 추정 근거로 승격하지 않는다. 이 작업은 기존 Core 기능의 제품 적용이며 Core 자체 능력 향상이나 사용자 효과의 검증으로 보고하지 않는다.

## 저장과 내보내기

- 로그인 전 기본은 현재 창의 메모리만 사용한다. 새로고침·창 닫기 때 저장하지 않은 기록은 사라진다. 브랜드 홈 버튼은 내부 이동으로 구현해 완료한 메모리 기록을 보존한다.
- 로그인 전 사용자가 `완료한 연습을 이 기기에 저장하기`를 켠 경우에만 `localStorage`의 `synk-rehearsal-v1`에 저장한다. 완료한 최근 10회까지 보관하며 진행 중 답변은 저장하지 않는다. 켜진 설정과 유효한 기록은 다음 방문에 복원된다.
- 설정을 끄면 기기의 사본을 삭제하고 현재 창의 기록은 유지한다. `모든 연습 기록 지우기`는 확인 후 기기와 현재 창의 사본을 지운다. 이미 내보낸 파일은 지우지 않는다.
- JSON 내보내기: 파일명 **`synk-rehearsal.json`**, MIME **`application/json`**, 최대 **500000 bytes**. `schema: 1`, `savedAt`, `sessions`로 구성한다. 각 세션의 원문·재작성·첫 문장·목표를 포함한다. 새 세션은 선택 필드 `practice: {counterpart, goal}`에 상황별 허용 ID를 보관한다. 이 필드가 없는 기존 schema 1 기록은 기존 대사를 그대로 재생한다. 선택값은 결과·재연습·작품집에도 동일하게 반영한다.
- 성장 작품집 소장: 파일명 **`synk-rehearsal-book.html`**, Blob MIME **`text/html`**, 최대 **2 MiB (2097152 bytes)**. `book.mjs`의 순수 함수 `createBook(sessions)`로 생성한다. 독립 HTML에 SUIT·InterTight 글꼴과 해당 OFL을 포함해 서버나 인터넷 없이 읽을 수 있다. 실행 스크립트·외부 링크·원격 자산이 없으며 개인 입력은 HTML 텍스트로 이스케이프한다. 데이터 글꼴과 내부 스타일만 허용하는 CSP를 문서에 포함한다. 원본 글의 줄바꿈을 유지하며 날짜는 연습 시작 시각을 한국 시간으로 표시한다. 재작성 시각·성장 점수·검증되지 않은 성과를 만들지 않는다. 글꼴 원본은 공유 생성 파일 `experiences/member-book-assets.mjs`에 있다.
- 작품집의 `인쇄 / PDF로 저장`은 명시 클릭 때만 `window.print()`를 호출한다. A4 여백, 회차별 새 페이지, 긴 답변의 페이지 흐름을 갖춘 인쇄 CSS를 제공한다. 실제 PDF 저장이나 종이 출력은 사용자의 인쇄 창에서 선택한다. HTML은 읽기용이며 앱으로 다시 가져와 편집할 때는 기존 JSON 백업을 쓴다. 작품집 내보내기는 기기 저장 설정을 바꾸지 않는다.
- 가져오기는 파일 크기와 모든 필드·상황·분기·자기평가·문자 수를 검증한 뒤 합치기 확인을 받는다. 현재 ID와 겹치면 현재 기록을 보존한다. 로그인 전 기기 저장을 켜지 않았으면 가져온 기록도 메모리에만 둔다. 계정 사용 중에는 확인해 합친 완료 기록을 계정에 저장한다.
- 세션 10개, 원문·재작성 각각 턴당 2000자, 첫 문장·메모 각 600자, 상대 80자, 목표 240자. 허용된 최악의 UTF-8 문자량과 JSON 들여쓰기까지 내보내기 한도 안에서 다시 가져올 수 있음을 시험한다. 제어 문자·깨진 surrogate·추가 필드·prototype 키·낯선 상황·잘못 연결된 분기는 거부한다.
- 저장 공간 부족·저장 차단·삭제 실패는 성공으로 표시하지 않는다. 기록을 읽지 못하면 새 연습은 메모리 모드로 시작한다.


## SYNK ID 개인 기록 연결 · 2026-10-06

공통 `product-account.mjs`·`document-sync.mjs`·`account-notebook.mjs`와 `synk-personal`의 `resource=rehearsal`을 사용한다. 공개 설정 또는 네이티브 계정 연결이 준비된 경우에만 로그인·서버 저장을 한다. 기존 `validateArchive`의 schema 1과 500000 bytes 제한을 그대로 적용하며 완료한 3턴·최근 10회 기록만 저장한다. 진행 중 답변이나 AI 평가를 새로 수집하지 않는다.

로그인 전 기록은 자동 업로드하지 않고 **기기 기록을 계정으로 옮기기**에서 직접 교체를 확인한다. 계정별 임시 기록·보내기 대기 자료를 분리하고, 계정 전환·로그아웃 뒤에는 원래 기기 기록과 저장 선택을 복원한다. 저장 확인 응답은 작성 중인 첫 문장·폼을 초기화하지 않는다. 다른 기기 변경은 **다시 불러오기**로 확인하며 충돌은 계정 기록 또는 현재 화면 중 하나를 직접 고른다. 오프라인·저장 실패는 완료로 표시하지 않고 재시도를 제공한다.

계정에 보내지 못한 변경(`pending=true`)만 이 앱의 계정별 임시기록으로 기기에 보관한다. 저장 완료·다시 불러오기·로그아웃 때 완료 사본은 제거한다. 로그아웃 뒤에는 남은 기록의 존재만 알리고, 기록을 남긴 계정으로 로그인해야 **계정 임시기록 복구 파일 내보내기** 또는 확인을 거친 **이 기기의 계정 임시기록 지우기**를 쓸 수 있다. 현재 편집·전송 중에는 지우지 못하며 삭제 범위는 로그인한 계정의 이 앱 임시기록뿐이다. 계정 서버 자료·다른 계정·다른 앱·로그인 전 기기 기록은 그대로 둔다. 탭마다 수정할 수 없는 별도 초안 키로 보관하고 저장 응답은 해당 요청의 초안만 정리한다. 이전 초안은 하나여도 직접 골라 열며 선택하지 않은 기록은 보존한다. 소유 계정을 확인할 수 없는 손상 원문은 그대로 보존하고 이 화면에서는 내보내거나 지우지 않는다.

운영 전환과 실제 사용자·실기기 검증은 아직 완료하지 않았다. 2026-10-07 리허설의 public OAuth client 18개 등록·포털 반영, care/personal 배포와 합성 공급자 왕복은 [공통 QA](../synk-account/qa/unified-account-20261006.md)에서 확인하며 운영 완료와 구분한다. `node experiences/synk-account/qa/personal-apps-smoke.cjs`는 실제 브라우저의 합성 계정 경로를 검증한다. 원래 기기 기록 보존·명시 이전·저장 뒤 편집 유지·계정 전환 격리와 375/1440px 화면은 [결과](../synk-account/qa/personal-apps-20261006/results.json)에 있다. 공통 계약·기존 모델·저장 회귀 46개와 [실제 Electron 3앱 시작 검사](../../desktop/artifacts/personal-native-20261006.json)도 통과했으며 실제 인증 제공자 호출을 뜻하지 않는다.

## 서버·자산

GET/HEAD만 허용하며 공개 경로는 `index.html`, `app.css`, `app.mjs`, `domain.mjs`, `storage.mjs`, `book.mjs`, `member-book-assets.mjs`, Core Ask, 지정 자산과 `book.css`, 공통 계정 모듈·계약·펠트 자산 및 공개 `/api/account-config`다. `/book.css`는 `book.mjs`의 `BOOK_STYLES`를 CSS로 제공하며 미리보기와 소장 파일의 본문·인쇄 스타일을 공유한다. 서버 원본·시험·문서·임의 저장소 파일은 제공하지 않는다. CSP는 지정한 SYNK 계정 서버 외의 외부 연결과 프레임·미디어·폼 전송을 막는다.

승인 자산은 `desktop/assets/launcher/`의 SYNK 로고, SUIT·Inter Tight·DM Mono, 펠트 연단/보드 `teacher-cover.png`, 실제 펠트 버튼·칩·크림/청금석 배경을 사용한다. 그림 자체를 변형하지 않고 원본의 흰 배경은 밝은 펠트 위 `multiply`로 표시한다.

- 실제 HTTP의 공개 자산·Core 원본 일치·HEAD·비공개 파일 404·쓰기 405.
- 작품집의 선택 분기 대사 일치, 최초·재작성·자기평가·첫 문장·메모·시각 보존, 날짜 정렬과 원본 불변.
- 비어 있거나 미완료인 기록의 작품집 생성 거부, XSS처럼 보이는 입력의 텍스트 이스케이프, 외부 자산·실행 코드 없는 CSP 문서, 내장 글꼴 라이선스 보존.
- 최대 10회 한국어 및 이스케이프가 가장 길어지는 입력을 포함해 2MiB 이내 소장, 회차별 페이지 나눔과 긴 글의 연속 인쇄 스타일.

브라우저·설치형 실제 화면과 사용 흐름 검증은 상위 플랫폼 작업의 `experiences/synk-account/qa/member-mvp-20261005/`에 별도 기록한다. 이 README의 자동 시험 결과는 실제 사람의 연습 효과나 운영 배포를 뜻하지 않는다.

## 상대·목표별 연습 확장 · 2026-10-08

바로 앞둔 대화의 상대와 목적에 맞는 질문을 받아 보고, 실제로 할 말을 준비하는 기능이다. 기존 Core Ask의 연습 방향 선택, 개인 기록, 작품집을 그대로 연결했다. 유형은 사용자가 직접 선택하며 글을 읽고 상대·의도·능력을 추정하지 않는다.

| 상황 | 상대 유형 | 연습 목표 |

| 면접 | 채용 담당자 / 실무 팀장 | 경험으로 강점 전하기 / 새 역할에 도전하는 이유 |
| 부탁 | 함께 일하는 동료 / 일정을 결정하는 상사 | 작은 도움 구하기 / 일정 조정 부탁하기 |
