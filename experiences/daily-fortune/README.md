## 실행

```powershell
node experiences/daily-fortune/server.mjs
node --test experiences/daily-fortune/tests/*.test.mjs
node experiences/daily-fortune/qa/browser-smoke.mjs
node experiences/daily-fortune/qa/reflection-browser-smoke.mjs
```

주소는 `http://127.0.0.1:4299/`. 서버는 `127.0.0.1`에만 바인딩하며 `createServer()`를 내보내 독립 시험에서는 포트 0을 쓴다. 비회원 화면은 설치·번들·API 키 없이 저장소의 Node.js로 실행한다. 계정 저장에는 아래 공개 로그인 설정이 필요하다. 브라우저 검사는 Codex의 번들 Playwright와 설치된 Chrome을 쓰며 다른 환경은 `PLAYWRIGHT_MODULE`에 Playwright `index.mjs` 경로를 지정한다. 앱 시작 시 `document.documentElement.dataset.ready = 'true'`로 네이티브 셸에 준비 상태를 알린다.

## 사용 흐름과 결과

- 첫 화면에서 **별자리 운세 / 한국 사주**를 선택한다. 기존 한국 12띠 선택을 사주 입력·계산으로 바꾼다.
- 별자리 12궁은 한국어·영어 이름과 일반적인 생일 구간을 함께 보여 준다. 직접 고르거나 양력 생일로 일반적인 별자리를 찾으면 총운·관계·일상과 집중·오늘의 작은 행동·행운의 색과 숫자가 열린다. 한국 날짜(`Asia/Seoul`)와 별자리가 같으면 같은 결과이며, 다음 날 총운 주제가 바뀐다.
- 한국 사주는 **양력 생년월일 + 24시간제 출생시각**을 입력한다. `시간 모름`을 선택하면 시주를 비워 두며, 같은 날 절기가 바뀌어 연주·월주 등이 확정되지 않는 경우에는 해당 기둥도 유보한다. 모르는 출생시간을 확정값으로 채우지 않는다.
- 출생시각은 **한국 표준시(UTC+9)** 기준이다. 만세력으로 연주·월주·일주·시주, 일간과 겉글자 오행 분포를 계산한다. 해외 출생자는 한국 표준시로 환산한 날짜·시각을 사용하며, 진태양시·과거 서머타임 보정은 하지 않는다.
- 별자리의 날짜와 사주의 오늘 풀이 기준은 한국 자정에 바뀌며, 화면 복귀·선택·복사 직전에도 날짜를 확인한다. 사주의 출생 기둥은 오늘 날짜가 바뀌어도 동일하다. 오늘 풀이는 출생 일간과 오늘 일간의 오행 관계를 전통 상징으로 읽는 문구이며 길흉을 단정하지 않는다.
- 결과 복사는 사용자가 단추를 눌렀을 때만 실행한다. 권한이나 브라우저 제약으로 자동 복사가 막히면 직접 선택해 복사할 상자를 연다. 복사가 성공하지 않았는데 성공으로 표시하지 않는다.
- **이번 주**는 선택한 별자리·사주의 월요일부터 일요일까지 일곱 날짜를 펼친다. 날짜별 풀이와 작은 행동을 살펴보고 원하는 날을 다시 연다. 미래의 사실이나 성공 확률을 예측하는 기능은 아니다.
- **최근 7일 돌아보기**는 오늘부터 6일 전까지의 운세 날짜에 저장한 메모 또는 실천 완료 행동을 모은다. 뒤늦게 저장·수정한 기록도 원래 운세 날짜에 놓으며 미래 날짜와 저장 전 초안은 포함하지 않는다. 날짜별 원문을 그대로 읽고 **다시 보기 · 메모 수정**으로 기존 결과를 연다. 별자리·사주와 같은 날의 여러 기록을 함께 보여 주고, 기록이 없는 날은 비워 둔다. 점수·성향 분석·완료율을 만들지 않고 계정에 별도 통계를 저장하지 않는다.
- 별자리 안내에는 원소·활동 양식·문화적 상징과 돌아볼 질문을, 사주 안내에는 네 기둥·일간·알려진 겉글자 오행을 읽는 법을 담는다. 모르는 기둥은 안내에서도 확정하지 않는다.
- **계정에 내 정보 저장**은 출생정보와 선호 방식을, **내 보관함에 저장**은 해당 결과·작은 행동·실천 여부·한 줄 메모를 저장한다. 자동 저장은 하지 않는다. 저장한 기록은 전체·별자리·한국 사주·실천한 기록으로 걸러 다시 열고, 개별 삭제·JSON 내보내기·운세 정보 전체 삭제를 할 수 있다. 보관함은 최대 90개, 메모는 기록당 1,000자다.
- 비회원 입력·결과와 저장 전 메모는 브라우저 메모리에만 둔다. 출생정보·기록을 localStorage나 sessionStorage에 복제하지 않는다. 웹 로그인 토큰만 운세 전용 sessionStorage에서 관리하며, 네이티브 토큰은 별도 암호화 저장소에 두고 화면에 넘기지 않는다. 계정 저장은 사용자가 저장 단추를 누를 때만 서버로 보낸다.
- 화면 입력 초기화와 계정 기록 삭제는 별도다. 입력 초기화는 현재 화면을 비우고, 계정의 운세 정보 전체 삭제는 확인 후 저장된 프로필·선호 방식·보관함을 비운다. SYNK 계정 자체를 삭제하지 않는다. 복사 결과에는 네 기둥과 풀이를 담으며 입력한 생년월일·시각은 넣지 않는다. JSON 내보내기에는 저장한 출생정보와 메모가 포함된다.

사주의 **역법 계산**과 **풀이**는 구분한다. 계산에는 MIT 라이선스의 `lunar-javascript@1.7.7`를 `vendor/lunar-javascript-1.7.7/lunar.mjs`에 고정하여 사용하며 원격 API를 호출하지 않는다. 절기 시각은 라이브러리의 UTC+8에서 KST로 한 시간 보정한다. 연주는 입춘 시각, 월주는 절입 시각을 경계로 하고, 일주는 00시에 바뀌는 `sect2`를 사용한다. 시주의 자시는 23시에 시작하며 23시의 시간 천간은 다음 날 자시 규칙을 따른다.

풀이는 일간과 겉글자 오행의 전통 상징을 바탕으로 준비한 규칙형 문구다. 오행 분포는 알려진 기둥의 천간·지지 대표 오행만 세며 지장간·합충·신강신약·용신·대운은 계산하지 않는다. 겉글자 개수만으로 강약·성격이나 미래를 확정하지 않는다. 별자리 날짜는 직접 선택을 돕는 일반적인 구간으로, 경계일의 정확한 태양 별자리나 천체 위치를 계산하지 않는다. 건강·투자·금전 결정이나 불안을 유도하는 문구를 넣지 않는다.

## 계정 연결과 서버

로컬 서버는 화면·스크립트·CSS·지정 자산과 공개 계정 설정만 제공하며 서버 원문·테스트·문서·임의 저장소 파일은 제공하지 않는다. 공개 계정 설정이 없으면 로그인·서버 저장을 준비 중으로 표시하고 비회원 운세를 그대로 제공한다. 공개 설정 파일에 비밀키를 넣지 않는다.

브라우저는 운세 출처의 공개 OAuth 설정으로 로그인하고, 네이티브는 고유 OAuth 클라이언트 키 `fortune`·콜백 예시 `http://127.0.0.1:43825/synk/oauth/fortune/callback`·독립 세션 `im.synk.fortune.preview`를 사용한다. API 제품은 `platform`이며 플랫폼의 토큰을 복사하지 않는다. 네이티브 화면에는 인증 상태와 정해진 요청만 노출하며 토큰은 main 프로세스에 둔다.

중앙 계정의 `synk-fortune`은 인증된 계정 소유자를 서버에서 정한다. 서버가 확인한 OAuth client ID는 운세 전용 `SYNK_FORTUNE_CLIENT_IDS`와 공통 제품 매핑을 모두 통과해야 하며, 다른 platform 클라이언트나 client ID가 없는 토큰을 허용하지 않는다. GET으로 상태와 revision을 읽고, POST `save`/`delete`에 `expected_revision`을 보내 동시 수정을 감지한다. 다른 기기의 변경과 충돌하면 덮어쓰지 않고 다시 불러오도록 안내한다. 요청은 64KiB 이내다. 출생정보·운세 기록은 학습용 Atlas 개인 메모리에 섞지 않고 운세 전용 상태로 분리한다. 로그인 계정이 바뀌거나 로그아웃하면 화면의 이전 계정 상태와 진행 중 응답을 폐기한다.

원격 준비 전 상태는 `FORTUNE_UNAVAILABLE`, revision 충돌은 `REVISION_CONFLICT`로 구분한다. `ACCOUNT_UNAVAILABLE/403`은 계정 상태·삭제 요청 확인을 안내하고 다시 불러오기 전 추가 쓰기를 막는다. 로컬 합성 시험과 실제 원격 OAuth 검증은 서로 다른 증거로 기록한다. `synk-fortune.json` 내보내기는 사용자가 요청할 때만 실행하며 네이티브는 현재 운세 출처의 해당 파일명·JSON 형식·128KiB 이하 다운로드만 허용한다. 중앙의 연습 기록 내보내기와 분리하며 운세 프로필·선호·메모·기록 전체를 담는다.
