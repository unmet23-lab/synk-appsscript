# SYNK 내 작업실 · AI 업무 연습 공유 모듈

가상 업무를 근거로 AI 요청문을 쓰고, 미리 준비된 AI 결과의 오류·누락을 확인한 뒤 사람이 직접 수정하는 실습 모듈이다. 2026-10-02 사용자 승인으로 **회사 메신저 → 내 작업실 → AI 업무 연습**에 통합했다. `model.mjs`를 회사 화면과 기존 시험 화면에서 함께 사용한다. 실제 AI 생성, 기업 자료 업로드, API 키, 결제는 없다. 회사 화면에서 [계정 동기화](#account-sync)를 직접 켜면 실습 조건·요청문·수정한 결과·검토 기록을 기존 회사 서버에 전송한다. 유료 AI 공급자에게 보내거나 회사 공유 자료에 추가하지 않는다.

## 회사 작업실에서 사용

`Core.domain`이 현재 범위의 유효한 관측을 해석하고 목적·세대·제외·만료·모순을 확인한다. 2026-10-07에는 SHIFT 제품 모델에 [문항별 복습 정책](#review-order)을 두어 전체 해석과 실제 다음 연습의 선택을 구분했다. 업무 능력으로 일반화하지 않는다. `temper-outcomes.js`는 별도 로딩해 실제 화면 노출과 최초 검토 결과를 연결한다. [계약·검수·운영 경계](../../docs/아틀라스_공통능력_고도화_20261005.md), [최초 Domain 연결 화면 검사](qa/20261005-domain/report.json).

회사의 기존 로그인으로 `http://127.0.0.1:4191/?tab=workroom&section=practice`를 연다. 회사 클라이언트는 `docs/마케팅/온라인마케팅지도/engagement/company/public/workroom-practice.js`와 `.css`를 사용한다. iframe이나 별도 SHIFT 클라이언트를 열지 않는다. 제작 데스크·게시 전 점검으로 바로 이어갈 수 있으며, 실습이 회사 공유 자료를 자동으로 작성하거나 권한을 바꾸지 않는다.

- 기존 `/api/me`에서 확인한 `state.user.id`를 scope의 personId로 사용한다. productId는 `company`, contextId는 `workroom-practice`, domain은 `SHIFT`다. 기존 Core를 재사용하며 새로운 엔진은 없다.
- localStorage 키는 `synk-workroom:ai-practice:v1:{companyUserId}`다. 기기 저장과 계정 동기화는 독립 선택이며 둘 다 기본 꺼짐이다. 기기 저장은 같은 브라우저의 실습 사본을 보관하고, 계정 동기화는 본인 회사 계정에 보관한다. 기존 익명 `synk.shift.workbench.v1` 기록은 가져오지 않는다.
- 로그아웃·계정 전환은 메모리를 비우고, 명시적으로 저장한 계정별 자료는 유지한다. 복원 시 현재 계정의 전체 scope를 확인한다. 다른 브라우저에서는 같은 회사 계정으로 로그인하고 동기화를 직접 켜야 이어 쓸 수 있다. 계정 간 기록은 합치지 않는다.
- 비동기 화면 갱신 시 초안·선택·커서 위치를 보존하고 한글 조합 중 화면 교체를 보류한다. 저장 접근 거부·용량 부족·손상 기록은 화면에 표시하고 메모리 실습을 계속할 수 있다.
- 공유 모델의 `startRun`·`completeRun`·`giveFeedback`은 마지막 `scope` 인자를, `restore`는 세 번째 `scope` 인자를 받는다. 생략 시 기존 시험 화면 scope를 유지한다. `persist`의 세 번째 인자는 호스트가 결정한 저장 키다.

관련 검증: `node --test experiences/shift-workbench/model.test.mjs docs/마케팅/온라인마케팅지도/engagement/company/workroom-practice-client.test.mjs docs/마케팅/온라인마케팅지도/engagement/company/workroom-client.test.mjs` **68/68 통과**(2026-10-06 검수 시점). 실제로 놓친 유형이 있는 다음 업무 제안과, 직접 고른 업무에 없는 유형을 연습한다고 표시하지 않는 회귀를 포함한다. 회사 통합 화면의 브라우저 검사는 회사 QA 기록을 따른다.

## 회사 계정으로 이어가기 — 2026-10-07 로컬 구현

회사 작업실의 **‘회사 계정에 저장하고 다른 기기에서 이어가기’**를 직접 켜면 같은 회사 계정의 실습을 보관한다. 이 선택은 기기 저장과 별개다. 동기화를 끄면 이후 작성은 올리지 않고 이미 저장한 계정 기록은 유지한다. 익명 독립 시험 화면과 회사 체험 모드는 이 서버 저장을 사용하지 않는다.

`GET/POST /api/workroom-practice/state`는 기존 회사 세션의 사용자로 소유자를 정하고 기존 인증·권한·CSRF 검사를 적용한다. 요청문에서 계정 ID나 제품 범위를 선택할 수 없다. 소유 범위는 `company / workroom-practice / SHIFT`이며 기존 중앙 SYNK ID에 연결된 경우도 회사 서버의 세션 확인을 먼저 통과해야 한다. 별도 가입 서버나 외부 고객 공간을 만들거나 다른 제품의 기록·권한을 가져오는 기능이 아니다.

회사의 `workroom-practice-sync-service.mjs`가 비공개 보관을 맡는다. 계정별 실습 본문은 기존 회사 저장소의 암호화 기능으로 저장하고 공유 자료 목록에는 추가하지 않는다. 서버는 공유 모델의 `restore`로 현재 계정·제품·맥락·세대와 Core 원결정·완료·노출·결과의 계보를 검증한다. 저장 본문 한도는 문자열 길이(UTF-16) 100만·UTF-8 300만 바이트이며 둘 중 하나를 넘으면 거절한다. SHIFT의 저장 호환·작성물 복구 규칙은 서버에서도 같은 원문을 사용한다. 공통 Atlas 엔진을 변경한 작업이 아니다.

문서 전체의 revision을 하나의 트랜잭션 안에서 비교하여 저장한다. 다른 브라우저에서 바뀌면 409 응답과 최신 계정 내용을 보여 주고, **이 기기 내용 / 계정에 저장된 내용**을 사용자가 직접 선택한다. 양쪽 요청문·초안을 볼 수 있고 현재 작성물을 TXT로 내려받을 수 있다. 문장을 자동 병합하지 않으며 선택한 쪽이 진행 기록을 대체한다. 선택 이후 다시 바뀐 revision은 재충돌로 확인한다.

동기화가 켜진 상태의 **‘내 실습 기록 비우기’**는 확인 후 계정 삭제 성공을 먼저 확인하고 기기 사본과 화면을 비운다. 삭제를 기다리는 동안 새로 작성한 내용은 창에 보존하고 재업로드하지 않는다. 삭제된 본문 대신 내용 없는 revision·삭제 시각만 남겨 늦게 온 저장을 거절한다. 다른 기기의 오래된 사본은 자동 재업로드하지 않으며, 본인이 다시 켜거나 새로 저장을 선택해야 한다. 동기화가 꺼진 상태의 비우기는 기기 기록에만 적용한다. 계정 삭제 실패·새 revision 충돌은 작성물을 유지하고 안내한다.

연결 실패·오프라인에서는 현재 창의 작성물을 유지하고 재연결·창 재진입 시 계정 기록을 다시 확인한다. 기기 저장까지 꺼져 있으면 창을 닫은 뒤 미전송 내용을 복구할 수 없으므로, 필요한 작성물은 기기 저장이나 TXT 내보내기로 보관해야 한다. 한글 조합·본문 작성 중 외부 갱신은 자동 적용하지 않고 선택을 기다린다. 로그아웃·계정 전환·세션 변경 후 늦게 도착한 응답은 이전 실습을 현재 계정에 적용하지 않는다.

관련 자동시험 **222/222**, 두 격리 Chromium 브라우저의 실제 화면 검사 **31/31** 통과. [서버·클라이언트 검증과 한계](../../docs/_ops/qa/shift-account-sync-20261007/report.json), [두 격리 브라우저의 실제 화면 왕복](../../docs/_ops/qa/shift-account-sync-20261007/browser/report.json)에 실행 범위를 둔다. 물리적인 두 기기 사용, 운영 서버 배포·백업·실제 회사 계정 왕복, 공개 배포와 유료 AI 호출은 이번 로컬 검증에 포함하지 않는다.

2026-10-07 후속 [운영 반영 준비](../../docs/_ops/qa/shift-release-preparation-20261007/README.md)에서 합성 DB의 백업·새 폴더 복구·HTTP 조회/저장/삭제를 검증했다. 현재 배포 묶음의 실행 파일 누락과 메신저 영구 데이터 경로도 보완했다. 실제 Docker 실행·운영 DB 복구·실계정·물리적 두 기기 검증은 남아 있다. 코드 롤백은 최신 DB를 유지하며 삭제 전 과거 스냅샷을 복원하는 절차와 구분한다.

같은 날 [운영 인수·고객 실증 후속](../../docs/_ops/qa/shift-operational-acceptance-20261007/README.md)에서는 회사 DB의 원래 키 누락 시 시작을 거부하는 보호와 복구 후보의 읽기 전용 대조를 추가했다. 현재 후보의 관련 회귀 153개·배포 묶음 71항목을 통과했고, 첫·두 번째 고객의 효과·전체 원가·재사용 측정표를 준비했다. 회사 호스트와 SHIFT 실증 자료의 책임이며 공통 Atlas 원본은 유지한다. 사용자가 실제 운영 환경과 두 고객을 미정으로 답했으므로 이 결과를 실제 배포·고객 효과로 보고하지 않는다.

## 개인화 기록 이행 — 2026-10-07 로컬 보완

동의 철회·재동의, 설정 삭제 또는 구형 `audio/experience` 설정 제거로 Core의 프로필 세대가 바뀌면 공유 모델의 `reconcileRecords`가 기록을 정리한다. 먼저 계정·제품·맥락·원결정·완료 계보를 확인하고, 이전 추천·피드백·노출·평가를 새 세대에서 제외한다. 과거 개인화 기록을 현재 세대로 다시 붙이거나 공통 Atlas의 세대 규칙을 바꾸지 않는다.

사용자가 작성한 요청문·초안은 `history`의 `kind:'saved-work'`로 보존한다. 보관 필드는 소유 범위·출처 세대·업무 종류·시각·요청문·초안·완료/작성 중 상태뿐이다. 점수·답안·도움 설정·추천 이유·결정 ID는 보관본에 복사하지 않는다. 두 화면은 **이전 조건에서 작성한 내용 · 추천·평가에 사용하지 않음**을 표시하며 보관본을 새 추천의 근거로 세지 않는다. 후속 저장 보완으로 정상 완료 최근 20개와 분석 제외 작성물 최근 21개를 따로 보관한다. `exportSavedWork(state,index)`는 평가 문구 없이 작성물을 텍스트로 반환한다.

진행 중에 세대가 바뀌었다면 작성물만 보관하고 새 조건에서 다시 시작한다. 옛 실습을 새 세대의 완료·피드백으로 확정하지 않는다. 단순 설정값 수정으로 revision만 바뀔 때는 진행과 분석 이력을 유지한다. `save`는 기기 저장 선택이므로 개인화 동의와 독립적이다. 저장 끄기는 디스크 사본만 지우고 현재 창의 내용을 유지하며, 기존 전체 초기화는 작성물까지 지운다. 저장 실패도 계속 안내한다.

`restore`는 이행 전에 이전 세대의 평가·완료 계보도 검증한다. 외부 계정·미래 세대·잘못된 계약·후보·정정 주입·변조된 결과를 정리 과정으로 숨기지 않는다. [제품 판본 변경](#storage-upgrade)은 아래 별도 작성물 복구 경로를 따른다. 원결정·완료 계보가 사라진 손상 기록이나 지원하지 않는 바깥 저장 형식은 자동 복구하지 않는다. 구형 저장이 기기에서 정상 복원되고 다음 저장을 할 때 이행된 사본으로 기록되며 운영 서버 자료를 직접 변경하지 않는다.

관련 **자동시험 142/142**, 격리된 실제 Chromium의 독립 화면·회사 화면 **29/29** 통과. 320/390px 가로 넘침, 원문 HTML 비실행, 이행→새 실습→저장·재복원을 확인했다. 이전 재현의 예외 8건은 0건이 됐다. [실행·파일·해시·한계](../../docs/_ops/qa/shift-record-migration-20261006/report.json), [브라우저 기록](../../docs/_ops/qa/shift-record-migration-20261006/browser/report.json). 공개 배포·실제 회사 계정·운영 DB 변경·유료 AI 호출은 하지 않았다.

<a id="review-order"></a>
## 최근 문항 결과와 다음 실습 — 2026-10-07 로컬 보완

SHIFT의 `practicePlan` 정책 `shift-review-order@2`가 복습 순서와 다음 실습을 정한다. 최근 20개 보관 기록 중 현재 소유 범위·세대에 속한 완료에서 문항별 마지막 결과를 읽고, 30일 이내에 아직 다시 확인할 문항을 우선한다. 독립 단위는 완료 횟수가 아니라 `업무.문항.v1`이다. 같은 문항을 여러 번 풀어도 독립 근거가 늘지 않으며, 마지막 정답은 그 문항의 앞선 오답을 해소한다. 마지막 결과를 제외했을 때 과거 오답을 다시 꺼내지 않는다. 문항 ID가 없는 구형 요약은 확인된 유형 관측만 유지하고 특정 문항의 복습 근거를 만들어 넣지 않는다.

`Core.domain`의 전체 해석은 그대로 보존한다. 다른 문항들의 결과가 엇갈리면 전체 판단을 보류하면서도, 실제로 다시 확인할 문항의 마지막 결과를 제품 복습 순서에 사용할 수 있다. 화면은 이 둘을 구분하고 업무·날짜·문항·안내 사용 여부를 근거로 보여 준다. 한 문항의 실수로 전체 업무 능력이나 성향을 정하지 않는다. 저장된 설명의 근거가 만료되거나 제외되면 현재 설명·다음 제안에서 빼며, 다음 제안은 현재 유효한 기록으로 다시 정한다.

사용자가 고른 업무 안에서는 다시 확인할 유형을 앞에 두고, 그 업무에 해당 유형의 미해결 문항이 있으면 그 문항부터 표시한다. 다음 업무는 현재 업무를 제외한 후보 중 같은 복습 우선순위를 가진 실습끼리 **현재 기록에서 미경험 → 실제 노출·완료가 가장 오래전 → 등록 순서**로 고른다. 단순히 추천되거나 시작이 결정된 사실만으로 경험했다고 세지 않는다. 두 화면 모두 다음 업무와 이 선택 이유를 표시한다.

실제 첫 문항과 Temper의 선택·노출 기록을 일치시킨다. 새 근거 기반 순서 정책은 `evidence-check-order@2`이며, 이미 저장된 `evidence-check-order@1`은 당시 문항 순서와 계보로 검증·보존하되 현행 평가 집계와 분리한다. 고정 순서 정책 `fixed-check-order@1`은 유지한다. 결과 지표는 여전히 실습 전체의 최초 검토 일치율이며, 제품 정책 변경으로 실제 생산성·학습 효과를 입증한 것은 아니다.

공통 Atlas 원본은 수정하지 않았다. 이 단계의 자동시험 **165/165**, 독립·회사 화면의 실제 Chromium 검사 **67/67**을 통과했다. [당시 검증](../../docs/_ops/qa/shift-recommendation-20261007/report.json), [당시 화면 검증](../../docs/_ops/qa/shift-recommendation-20261007/browser/report.json)에 확인 범위를 둔다. 남겼던 저장 판본 이행과 평가 보관 기준은 아래 후속 보완에서 처리했다. 공개 배포·운영 DB 변경·유료 AI 호출은 하지 않았다.

<a id="storage-upgrade"></a>
## 업데이트 뒤 작성물 보존 — 2026-10-07

`storage-upgrade.mjs`는 SHIFT 제품 저장 호환만 맡는다. 새 저장의 `manifest`는 문항·자료의 내용 지문과 검토 계약·결과 계약·순서 정책의 판본을 남긴다. 문항·자료는 자동으로 지문이 달라지고 규칙 변경은 해당 판본을 올린다. 메타데이터가 없는 기존 v1 저장은 고정된 당시 판본으로 해석한다. 지문은 호환 판별용이며 인증 서명이 아니다.

판본이 같으면 기존의 엄격한 복원 검사를 유지한다. 판본이 달라 현재 분석을 이어 쓸 수 없으면 Core 원로그, 모든 세대의 소유 범위와 링크, 원결정·완료·노출·결과의 시간·수치 연결을 확인한 뒤 요청문·초안만 `kind:'recovered-work'`로 보관한다. 예외를 잡아 아무 기록이나 복구하지 않으며 다른 계정·맥락·미래 세대·깨진 원기록은 거절한다. 구형 점수·답안·추천·피드백·평가·경험 표시는 현재 분석에 재사용하지 않는다.

보관본은 소유 범위·출처 세대/제품 판본·원래 업무 ID/이름·시각·본문·완료/작성 중 상태·복구 시각만 갖는다. 삭제된 업무도 이름과 텍스트를 읽고 내보낼 수 있다. 변경되지 않은 예시 초안은 작성물로 만들지 않는다. 정상 완료 최근 20개와 보관 작성물 최근 21개를 분리해, 기존 완료 20개와 실제 작성 중 초안 하나가 함께 이행된다. 두 화면은 복구 사실과 분석 제외를 알리고 다음 사용자 저장에서 새 사본을 기록한다.

지원 경계는 v1 저장 바깥 형식·제품 manifest 형식 1과 현재 Core가 읽을 수 있는 원로그다. 임의의 미래 저장 형식·Core 판본까지 읽는다는 뜻은 아니다. 원문을 바꾸거나 운영 계정·서버 DB를 이행하지 않는다.

<a id="evaluation-retention"></a>
## 평가 보관 — 완료 여부와 무관한 최근 20회

`retention.version:'attempts-20-1'`은 원결정 시각 순 최근 20번의 실습 시도를 먼저 정한 뒤 결정→실제 노출→결과 전체를 함께 보관한다. 완료·보고 중단·미노출이 같은 범위를 사용하며 현재 정책판 필터는 그 뒤에 적용한다. 중단을 오답이나 0점으로 만들지 않는다. 작성물 보관 20/21개와 평가 표본 20회는 별도 목적이다.

예전 저장에서 이미 완료 평가 체인이 빠져 최근 20회 표본을 온전히 만들 수 없으면 평가값을 추정하지 않는다. 작성물과 확인 가능한 실제 경험은 유지하고 `resetReason:'legacy-incomplete'`와 시작 시각을 남겨 새 실습부터 집계한다. 결과의 `coverage`에 보관 한도·범위·재설정 사유를 표시하며, 남은 저장 범위 밖의 과거 통계를 재현했다고 주장하지 않는다.

실제로 본 실습은 별도 `visits`에 업무별 마지막 화면 노출 1건만 남긴다. 원래 Core 결정·계정·세대·시각과 연결하고 평가 체인이 20회 밖으로 나가도 추천의 경험 순서를 유지한다. 화면을 보지 않은 시작은 경험으로 세지 않으며 원결정 제외·개인화 세대 변경은 경험 기록도 제외한다. 공통 Core·Domain·Temper의 원본은 수정하지 않았다. 관련 자동시험 **188/188**, 실제 Chromium의 독립·회사 화면 검사 **31/31** 통과. [전체 검증과 한계](../../docs/_ops/qa/shift-storage-retention-20261007/report.json), [실제 화면](../../docs/_ops/qa/shift-storage-retention-20261007/browser/report.json). 실제 사용자 학습·생산성 효과는 별도 검증 대상이다.

## 구현 범위

- 회의 정리·자료 검토·기획 3종 가상 업무. 실제 고른 목적·5/10/15분·도움 선택만 `atlas/personalization.js`에 전달하여 기존 Core가 2개 확인/3개 확인/후속 적용 포함 중 분량을 추천한다. 도움 선택으로 경험을 추정하거나 미선택 음성 조건을 선언하지 않는다. 시간 여유만으로 심화를 강제하지 않으며, ‘더 해보기’ 피드백과 15분 조건이 함께 있으면 심화가 가능하다.
- 초보 도움에서는 요청문 구조·가져오기 예시를 제공하며 독립 수행에서는 숨긴다. 요청문 단어 점검은 의미를 채점하는 AI가 아님을 명시한다.
- 검토 판단과 근거 자료 번호가 모두 맞아야 확인 항목을 맞힌 것으로 기록한다. 첫 판단 뒤 정답·근거를 알려 주고 원래 판단은 유지한다.
- 학습자가 결과를 직접 바꾸고 검토 확인을 해야 완료한다. 자유 문장 정확성은 자동 채점하지 않으며 정해진 확인 항목 결과와 구분한다.
- [문항별 마지막 결과](#review-order)에서 아직 다시 확인할 항목을 앞에 제시하고, 같은 우선순위의 다음 실습은 미경험·가장 오래전 경험 순으로 고른다. 완료·명시적 피드백은 기존 Core 이벤트로 기록한다. 원시 답을 능력·성향으로 추론하거나 다른 도메인과 합치지 않는다.
- 선택 조건의 실습 내 사용은 ‘이 조건으로 실습 시작’으로 동의받는다. 기기 저장을 고른 경우에만 선택 조건·요청문·답·직접 수정한 결과·최근 20회 기록을 이 기기 localStorage에 저장한다. 회사 화면의 계정 동기화는 별도 선택이며 [저장·충돌·삭제 계약](#account-sync)을 따른다. 공용 기기에서는 기기 저장을 끄고 이용 후 로그아웃하도록 안내한다. 저장 실패·복원 실패·초기화 실패를 표시한다.
- 수정 결과와 검토 근거를 `synk-shift-practice.txt`로 내려받는다. MIME `text/plain;charset=utf-8`, 최대 64 KiB. 파일 생성은 사용자 클릭 시 브라우저에서만 실행한다.
