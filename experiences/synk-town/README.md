## 2026-10-09 · 움직임과 정원 그래픽 v6

기본 렌더링 제한을 30에서 **60fps 목표**로 바꿨다. 해상도와 접촉 음영으로 품질 모드를 나누며 휴대폰 기본 모드의 추가 후처리 버퍼 0개 정책은 유지한다. 플레이어 위치와 카메라는 입력에 바로 반응하고 즉시 멈춘다. 몸의 방향만 짧은 최단각 전환으로 잇고, 걷기 동작은 실제 이동 거리를 따라 이어진다. 몸의 들썩임과 기울기를 줄이고 주민의 걸음·앉기 전환·머리카락 정지 동작도 연결했다.

입력 시간의 정수 반올림을 없애 주사율에 따른 이동 속도 차이를 줄였다. 같은 방향 입력은 충돌 재실행 결과가 같은 경우에만 합치고, 남은 예측 시간을 부분 사용한다. 예측 240ms·패킷당 입력 구간 32개·서버 이동 예산은 그대로다. 실제로 이동하지 못하면 걷기 동작을 멈추고, HUD는 의미가 바뀔 때 갱신한다. 주민 의뢰·관람 결과의 자동 확인이 generic busy를 통해 누르고 있던 이동 키를 지우는 경로를 재현해, 입력이 활성화된 동안 수동 결정이 아닌 자동 확인만 유예했다. 벽에 막혀 이동 거리가 0이어도 누른 입력은 보호한다.

앞 정원은 장미빛·크림·라벤더의 넓은 비대칭 꽃 군락과 꽃나무로 바꿨다. 포장 모서리와 작은 자갈 전이, 따뜻한 석회석·차분한 잔디·차양색, 따뜻한 햇빛과 차가운 하늘빛을 다듬었다. 잎 뒷면의 투과광은 기존 셰이더 안에서 처리하며 새 렌더 타깃이나 광원을 추가하지 않는다. 환경 삼각형은 839,865→869,047(+3.47%), 재질 수는 32개다.

[같은 위치의 전후 화면·실제 연속 걷기·검증 범위](qa/graphics-v6/README.md). 넓은 잔디와 반복되는 집·직선 길은 더 큰 공간 미술 개편이 필요한 부분이다. 실물 휴대폰의 지속 성능·사용자의 멀미 체감·최종 미술 승인은 아직 확인하지 않았다.

목재와 석재의 중복 착색을 정리하고 표면 정보는 256px 밉맵으로 묶었다. 홈 v6의 접촉 음영 방식을 타운에 맞게 적용해 **휴대폰 균형 모드와 동네 전체 보기는 추가 후처리 버퍼 없이 직접 렌더**한다. PC 균형은 8샘플, 경험 모드는 12샘플 음영을 사용하고 모드 변경 때 버퍼를 반환한다. 렌더 오류가 나도 장면·그림자·화면 상태를 복원하며 하늘에 톤매핑을 두 번 적용하지 않는다.

재검 중 입장 명령 거절을 한 번 발견해 느린 초기 연결을 추가 검사했다. 서버가 처리한 뒤 응답만 3.5초 늦게 도착하면 만료된 전경 연결을 새것으로 취급하던 경로를 재현했다. 클라이언트의 갱신 시각을 요청 시작 기준으로 바꾸고 오래된 응답은 최대 두 번만 새로 확인한다. 생활 명령 자체를 자동 재전송하지 않으며, 계속 늦으면 안내를 보이고 사용자가 다시 연결했을 때 걷기 진입까지 복구한다.

[동일 시점의 전후 화면과 검증](qa/graphics-v5/README.md). 기존 네 장소의 생활·이동·충돌, 주민 여섯 명과 공용 몽글은 유지한다. 실물 휴대폰의 지속 성능·실제 사용자의 멀미·최종 미술 승인은 별도 확인이 필요하다.

## 2026-10-09 · 읽기 도움과 두 손님 추가

## 2026-10-09 · 집에서 출발하는 3D 첫 하루

현재 입구는 **[day.html](day.html)**이다. 집의 방석을 미리 놓거나 그대로 두고 → 문 앞에서 나가기를 확정 → 찻집 자리·안내판 → 공방의 도움과 준비 → 온실의 그림·쉼 조율 → 귀가·다음 외출까지 같은 가상 기록으로 연결했다. 기존 `preview.html`의 찻집 생활과 저장 자료도 유지한다.

- 찻집·공방·연구원은 각자 물건을 정리하고, 공방 주인이 찻집을 찾아 받침을 살핀 뒤 돌아간다. 사용자의 기여로 기록하지 않는 주민끼리의 행동이다. 같은 몸이 찻집 이용·다른 생활·준비 작업에 중복 배정되지 않게 조정한다.
- 차와 그림의 순서/분리, 조용한 쉼/말 없는 그림/별도 자리, 공방 도움 뒤 받침 방향을 직접 정한다. 관람·위임도 가능하고 실제 역할을 다르게 기억한다. 유효한 조율은 다음 일과의 자리·그림 사용으로 이어진다.
- 시범·협력·기획을 직접 선택하면 **시범 후 기다림 / 역할 분담과 확정 / 동선 리허설 후 최종 확인**으로 진행이 달라진다. 아직 학습자의 실제 숙련도와 자동 연결한 것은 아니며, 선택으로 능력·호감도 점수를 만들지 않는다.
- 준비를 부탁한 받침 하나는 서버의 30초가 지난 뒤 준비된다. 부재 중에도 그 한 건만 완료되고 공방에서 확인해야 사용 상태로 바뀐다. 재화·판매 재고를 무한 생성하거나 부재를 벌주지 않는다.
- WORLD 홈의 승인된 3D 방향을 재사용한 실제 메시 장면이다. 플레이어는 팔 없는 몽글이며 주민은 개별 사람형·교수 계열로 교체했다. 나무·석재·도자기·유리 재질을 구분했다. **임시 역할 모형이며 최종 캐릭터 마스터는 아니다.** [출처·표현 범위](qa/DAY-3D-ASSETS.md).

새 화면의 FT10/51은 서버 전경 시간으로 실제 이용을 마친 뒤 완료 사실을 기록하고, 이후 보이는 장면의 관람을 별도로 남긴다. 자리에서 벗어나거나 미완성 배치를 바꾸면 옛 이용을 그대로 완료하지 않는다. 바깥 재료는 ‘밖이 좋아요’ 미리보기에서 지급하지 않고 **‘만들기’ 수락**에서 한 번 지급한다. 기존 `preview.html`은 호환을 위해 종전 턴 방식 이용을 유지한다.

## 개발용 WORLD 연결과 읽기 목표

local-linked WORLD에서 `linked.html`을 연다. 이 입구는 같은 출처의 검증된 WORLD 호스트만 사용하며 토큰을 Town에 넘기지 않는다. 일반 입구 해금과 독립 preview 서버는 그대로 유지한다. [town-bridge.mjs](../teacher-world/town-bridge.mjs)가 반 소속·동의·철회·공유 revision과 학생 소유를 확인하고, 생활 상태를 학생별 `learner.town`에 보관한다. 인증과 원자적 저장은 연결 서버가 담당한다.

생활의 만들기·이동·판 따라가기와 별도로 **안내문 읽기 확인**을 선택한다. `understanding.mjs`에는 세부정보·부정·순서 각 6개, 총 18개의 자체 지문과 문항이 있다. 기존 3개 family는 보존하고 새 상황의 지문 15개를 추가했다. 각 영역은 첫 3문항 뒤 다른 지문 3문항으로 후속 확인할 수 있다. 공식 TOPIK 기출 문항이나 검증된 난도 표준은 아니다.

읽기 시작 전에 이전 학습 기록의 동기화를 확인한다. `coach.assignment()`가 있으면 서버의 영역·난도·형식·family/item 목록에 맞는 문항만 낸다. 목표가 없으면 기존 Core가 실제 노출 이력과 학습 기록으로 최대 3개를 고른다. 힌트·반복은 독립 수행과 구분하며, 생활 facts는 학습 정답으로 바꾸지 않는다. 연결 확인 실패·호스트 교체·공유 철회 때는 화면과 응답을 막는다.

## 플레이와 복원

- 바깥: 나무 2·천 1을 한 번 지급 → 초록/노랑 → 제작 확정 → 자리 미리보기 → 배치 → 이용 표현 → 첫 반응.

- 취소/미리보기는 소비하지 않는다. 제작 뒤 종료하면 가진 지붕과 제작 단계가 남는다.
- 미관람 결과로 돌아오면 기존 이용 사실을 표현한다. 차를 또 제공한 사건을 만들지 않는다. 이미 본 뒤 실제로 나갔다 재방문하면 새로운 일상 이용을 확정한다.
- 지붕을 회수하면 장면에서 사라지고 보관함으로 돌아간다. 과거 성취는 남고 현재 지붕 대사는 사라진다. 다시 놓아도 재료 지급·제작·첫 감사를 중복하지 않는다.
- 저장 실패는 진행으로 표시하지 않는다. 다른 창의 낡은 명령/ACK는 거절하고 현재 기록을 다시 읽는다. 손상된 저장은 보존하고 진행을 막는다.

## FT51 · 길을 알려 주는 그림

쉼터를 완성한 뒤 **길 알려 주기**를 직접 선택한다. FT10 연출을 끝까지 봤는지는 다음 활동의 조건이 아니다.

- 의자/차 그림 → 입구 왼쪽/오른쪽 미리보기 → 놓기. 기본 안내판 하나를 재사용하며 재료나 보상을 추가 발급하지 않는다.
- 그림은 취향이고 두 선택의 결과는 동등하다. 위치는 손님이 판을 확인하는 실제 동선을 바꾼다. 손님이 판 앞에 와서 보고, 현재 의자까지 걸어가 앉는다.
- 미리보기·취소는 기존 판을 바꾸지 않는다. 중간에 나갔다 돌아오면 같은 선택 단계로 이어진다. 확정 직후 재접속은 새 판과 미관람 이용을 복원한다.
- 다음 방문에도 같은 그림과 위치를 쓴다. 의자를 옮기면 화살표와 손님의 목적지가 함께 바뀐다. 자리가 없어지면 판의 안내는 쉬고 빈 곳으로 보내지 않는다.
- 첫 성취는 한 번만 수첩에 남고, 재방문의 실제 이용은 별도 사건이다. 설치를 본 주인과 실제 판을 읽은 손님의 인지를 구분한다. FT10·FT51 전달 영수증도 분리한다.
- 도움의 판→자리 경로를 봐도 결과가 줄지 않는다. 진행 중 **자리 보기/앉기**는 같은 주민 동작을 처음부터 재시작하지 않는다.

기존 FT10 저장은 기록·소유·명령을 보존하고 새 안내판 상태만 추가해 읽는다. 공통 엔진의 이번 개선은 Loom의 서버 계획→JSON→브라우저 전달에서 초기 소품 자세를 보존하는 수정이다. Trail·Vellum은 같은 계약을 두 번째 생활 경로에서 재사용한다.

## 해금·학습·미구현 범위

실제 입장 조건은 메인 화면의 **내부 TOPIK 1급+ 통과**다. 현재 WORLD 계정 호스트에는 이를 검증한 Town 권한 API가 없어 [일반 입구](index.html)는 기본 잠금이다. URL의 `passed=true`, 개발 가상 기록, 미니게임 점수나 결제로 해금하지 않는다. 개발 체험은 실제 입장 검증의 대체물이 아니다.

쉬운 생활 어휘 ‘안/밖/옮기기/만들기’와 짧은 지시를 접하는 장면이다. 이 생활 행동 자체는 이해 응답이 아니므로 **TOPIK 성취·급수 상승·학습효과를 주장하거나 학습 프로필에 점수를 쓰지 않는다.** 연결된 WORLD의 별도 안내문 읽기 확인은 아래처럼 분리한다. 자유 선택·시간·NPC 친절함도 능력 근거로 사용하지 않는다.

현재 구현은 FT10·FT51·GOAL-C1과 새 첫 하루의 H00 방석/문·세 주민 자기 일·주민쌍·LS 조율/보답 일부·한 건의 시간 준비다. **H00/LS 전체와 열 가지 콘텐츠 전체가 완성된 것은 아니다.** 실제 숙련도와 생활 지원의 자동 연결, 정식 계정·TOPIK 통과 API, 상품 권한, 전체 NPC 일정·공유 마을·실시간 예약/물리, 최종 3D 주민·음성, 실제 학생 체감·학습효과 검증은 후속이다. 공개 배포는 하지 않았다.
