# 싱크타운 · 쉼터와 안내판 실행 연결

2026-10-02. FT10 ‘찻집 앞 자리 만들기’와 FT51 ‘길을 알려 주는 그림’을 실제 게임 상태와 화면에 연결한 **로컬 개발 체험**이다. 쉼터의 자리와 안내판의 그림·위치를 고르면 손님이 판을 확인하고 현재 자리까지 이동한다. 다음 방문·회수·재배치는 저장한 현재 배치와 전달 기록을 사용한다.

## 실행

```powershell
node experiences/synk-town/server.mjs --preview
# http://127.0.0.1:4288/preview.html
```

Node.js만 사용한다. 유료 호출·외부 모델 요청·추가 패키지가 없다. 기본 포트는 4288(`SYNK_TOWN_PORT`로 변경). `--preview`를 빼면 일반 입구만 제공하며 체험 API는 닫힌다. 일반 입구는 개발 모드에서도 잠겨 있다.

**위 독립 preview 서버에서는 가상 기록 한 개**를 `%LOCALAPPDATA%/SYNK/town-preview/ft10-v1.json`에 저장한다. 브라우저 새로고침과 서버 재시작 뒤에도 복원하며 동일 서버의 여러 창이 이 가상 기록을 공유한다. 실제 학생 계정, 개인별 클라우드 저장, 다른 기기 동기화 기능은 아니다. 같은 저장 파일을 여러 프로세스에서 열지 않는다. 개발 체험 안내에서 가상 기록만 초기화할 수 있다.

## 개발용 WORLD 연결과 읽기 목표

local-linked WORLD에서 `linked.html`을 연다. 이 입구는 같은 출처의 검증된 WORLD 호스트만 사용하며 토큰을 Town에 넘기지 않는다. 일반 입구 해금과 독립 preview 서버는 그대로 유지한다. [town-bridge.mjs](../teacher-world/town-bridge.mjs)가 반 소속·동의·철회·공유 revision과 학생 소유를 확인하고, 생활 상태를 학생별 `learner.town`에 보관한다. 인증과 원자적 저장은 연결 서버가 담당한다.

생활의 만들기·이동·판 따라가기와 별도로 **안내문 읽기 확인**을 선택한다. `understanding.mjs`에는 세부정보·부정·순서 각 6개, 총 18개의 자체 지문과 문항이 있다. 기존 3개 family는 보존하고 새 상황의 지문 15개를 추가했다. 각 영역은 첫 3문항 뒤 다른 지문 3문항으로 후속 확인할 수 있다. 공식 TOPIK 기출 문항이나 검증된 난도 표준은 아니다.

읽기 시작 전에 이전 학습 기록의 동기화를 확인한다. `coach.assignment()`가 있으면 서버의 영역·난도·형식·family/item 목록에 맞는 문항만 낸다. 목표가 없으면 기존 Core가 실제 노출 이력과 학습 기록으로 최대 3개를 고른다. 힌트·반복은 독립 수행과 구분하며, 생활 facts는 학습 정답으로 바꾸지 않는다. 연결 확인 실패·호스트 교체·공유 철회 때는 화면과 응답을 막는다.

`node --test experiences/teacher-world/town-bridge.test.mjs experiences/synk-town/*.test.mjs experiences/korean-runner/*.test.mjs` **99/99** 통과. 독립 학생 공간·오래된 동의·호스트 교체·기존 FT10/FT51 회귀와 목표 문항 선정을 포함한다. [실제 목표 UI 검증](qa/targeted-content-ui.json) **50/50**에서는 Town 세 영역의 첫 3오답→새 지문 3정답과 바람길 목표 수행을 실제 버튼으로 실행해, 9개 과제·27개 응답이 교사 제출로 이어지는 것을 확인했다. [별도 화면 검증](qa/linked-content-ui.json) **14/14**에서는 FT10/FT51 생활 점수 분리·읽기 힌트·MP3 실패/재청취·390px 폭을 확인했다. 모두 임시 포트·임시 계정 자료이며 운영 학생 데이터나 공개 배포 검증이 아니다.

## 담당 엔진과 실제 소비

| 담당 | 개선한 원본 | 이 장면에서 사용하는 기능 |
|---|---|---|
| Trail | [trail-life.js](../../atlas/trail-life.js) | 확정 사건의 원인·순서·범위, NPC의 직접/전달 인지와 철회, 반응 전달 이력 |
| Vellum | [vellum-life.js](../../atlas/vellum-life.js) | 현재 배치·인지 근거에 맞는 검수 대사/행동 후보, 같은 원인에 대한 첫 감사 중복 억제 |
| Loom | [loom-life.js](../../tools/lib/loom-life.js) | 순차 좌표/자세 표현, 배치 변경에 따른 옛 계획 취소, 정지 대안, 화면 적용 후 전달 전 검사 |
| Loom 재사용 | [loom-motion.js](../../tools/lib/loom-motion.js) | 숨김·정지 중 진행 시간을 멈추고 복귀 시 밀린 시간을 버리는 시계 |

[core.mjs](core.mjs)는 콘텐츠별 게임 규칙이다. 재료·제작·배치·방문과 NPC의 순차 이용을 한 명령 안에서 검증하고 확정한다. 이 작은 턴 방식 장면은 미리 검수한 네 자리만 허용하며 통로 등 임의 좌표는 거절한다. 실시간 물리/경로 탐색·여러 NPC의 예약 경쟁 실행기는 아직 아니다.

[server.mjs](server.mjs)는 명령 ID·이전 revision을 검사하고 원자적 파일 저장이 성공한 뒤 새 상태를 공개한다. 생활 사실은 이 서버의 게임 상태가 맡고, 애니메이션 완료가 재료·보상·학습 정답을 만들지 않는다. [app.mjs](app.mjs)는 Loom 표현과 대사가 실제 보이는 화면에 적용된 뒤 별도 ACK를 보낸다. 정지 대안도 대사를 바로 지우지 않으며 숨김·도움 대화창·화면 밖에서는 관람 시간을 진행하지 않는다.

별도의 Atlas 판단 엔진이나 GPT/Claude 실행 하네스를 추가하지 않았다. Core·Prism·Temper·Reed·Strata는 이번 장면에서 발전시킨 엔진으로 보고하지 않는다.

## 플레이와 복원

- 바깥: 나무 2·천 1을 한 번 지급 → 초록/노랑 → 제작 확정 → 자리 미리보기 → 배치 → 이용 표현 → 첫 반응.
- 안쪽: 재료 없이 기존 의자의 두 자리 중 선택 → 이동 확정 → 이용 표현 → ‘옮긴 의자예요’.
- 취소/미리보기는 소비하지 않는다. 제작 뒤 종료하면 가진 지붕과 제작 단계가 남는다.
- 미관람 결과로 돌아오면 기존 이용 사실을 표현한다. 차를 또 제공한 사건을 만들지 않는다. 이미 본 뒤 실제로 나갔다 재방문하면 새로운 일상 이용을 확정한다.
- 지붕을 회수하면 장면에서 사라지고 보관함으로 돌아간다. 과거 성취는 남고 현재 지붕 대사는 사라진다. 다시 놓아도 재료 지급·제작·첫 감사를 중복하지 않는다.
- 저장 실패는 진행으로 표시하지 않는다. 다른 창의 낡은 명령/ACK는 거절하고 현재 기록을 다시 읽는다. 손상된 저장은 보존하고 진행을 막는다.

## FT51 · 길을 알려 주는 그림

쉼터를 완성한 뒤 **길 알려 주기**를 직접 선택한다. FT10 연출을 끝까지 봤는지는 다음 활동의 조건이 아니다.

- 의자/차 그림 → 입구 왼쪽/오른쪽 미리보기 → 놓기. 기본 안내판 하나를 재사용하며 재료나 보상을 추가 발급하지 않는다.
- 그림은 취향이고 두 선택의 결과는 동등하다. 위치는 손님이 판을 확인하는 실제 동선을 바꾼다. 손님이 판 앞에 와서 보고, 현재 의자까지 걸어가 앉는다.
- 미리보기·취소는 기존 판을 바꾸지 않는다. 중간에 나갔다 돌아오면 같은 선택 단계로 이어진다. 확정 직후 재접속은 새 판과 미관람 이용을 복원한다.
- 다음 방문에도 같은 그림과 위치를 쓴다. 의자를 옮기면 화살표와 손님의 목적지가 함께 바뀐다. 자리가 없어지면 판의 안내는 쉬고 빈 곳으로 보내지 않는다.
- 첫 성취는 한 번만 수첩에 남고, 재방문의 실제 이용은 별도 사건이다. 설치를 본 주인과 실제 판을 읽은 손님의 인지를 구분한다. FT10·FT51 전달 영수증도 분리한다.
- 도움의 판→자리 경로를 봐도 결과가 줄지 않는다. 진행 중 **자리 보기/앉기**는 같은 주민 동작을 처음부터 재시작하지 않는다.

기존 FT10 저장은 기록·소유·명령을 보존하고 새 안내판 상태만 추가해 읽는다. 공통 엔진의 이번 개선은 Loom의 서버 계획→JSON→브라우저 전달에서 초기 소품 자세를 보존하는 수정이다. Trail·Vellum은 같은 계약을 두 번째 생활 경로에서 재사용한다.

## 해금·학습·미구현 범위

실제 입장 조건은 메인 화면의 **내부 TOPIK 1급+ 통과**다. 현재 WORLD 계정 호스트에는 이를 검증한 Town 권한 API가 없어 [일반 입구](index.html)는 기본 잠금이다. URL의 `passed=true`, 개발 가상 기록, 미니게임 점수나 결제로 해금하지 않는다. 개발 체험은 실제 입장 검증의 대체물이 아니다.

쉬운 생활 어휘 ‘안/밖/옮기기/만들기’와 짧은 지시를 접하는 장면이다. 이 생활 행동 자체는 이해 응답이 아니므로 **TOPIK 성취·급수 상승·학습효과를 주장하거나 학습 프로필에 점수를 쓰지 않는다.** 연결된 WORLD의 별도 안내문 읽기 확인은 아래처럼 분리한다. 자유 선택·시간·NPC 친절함도 능력 근거로 사용하지 않는다.

이번 구현 범위는 FT10·FT51이다. 다른 생활 경로, 생활 퀘스트 자체의 학습 개인화, 정식 계정·TOPIK 통과 API, 무료/정액/선택상품 권한, NPC 일정·공유 마을·실시간 예약/물리, 최종 주민 모델·앉기/제공 전용 동작·음성, 실제 학생 체감·학습효과 검증은 후속이다. 화면의 기존 펠트 주민과 단순 자세 전환은 개발용이다. 공개 배포는 하지 않았다.
