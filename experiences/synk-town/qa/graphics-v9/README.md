## 실제로 바뀐 큰 형태

- **집:** 큰 둥근 창과 두꺼운 목재 창틀, 깊이 들어간 유리와 면 커튼을 만들었다. 작은 지붕은 왼쪽 문 위로 옮겨 둥근 창 전체가 보이게 했다.
- **찻집:** 폭넓은 곡선 처마 아래 전폭 창과 연속 목재 구조를 놓고 따뜻한 나무 마루를 중심 면으로 삼았다. 창은 실제 회벽 구멍, 깊이 있는 프레임과 유리로 구성했다. 면 차양의 지지대를 기존 기둥 상단에 연결하고 늘어짐과 가장자리 두께를 표현했다.
- **공방:** 다른 두 건물과 구별되는 비대칭 경사 지붕, 높은 작업창과 상부 채광창을 만들었다. 지붕의 길게 이어진 세로 리브에 실제 얕은 겹침이 있는 가로 기와 7단을 추가했다.
- **광장:** 사각 바둑판 포장을 넓은 곡선 석재 면과 드문 곡선 이음으로 교체했다. 온실 접근로는 연속 바탕 위의 큰 연결 돌로 정리했다.
- **식재와 나무:** 흩어진 잔풀을 줄이고 큰 꽃군락과 여백을 사용했다. 노출된 큰 흙 리본을 없애고 꽃 아래 작은 원형 면에서 실제 잔디 색으로 부드럽게 연결했다. 돌 경계는 낮고 작게 줄였다. 기존 여섯 나무의 위치를 유지하면서 작은 완만한 잎 1,536장과 연결 가지로 수관을 구성했다.
- **배경:** 여덟 집을 낮고 긴 처마, 높은 비대칭 지붕, 둥근 지붕의 서로 다른 실루엣으로 분화했다. 밝은 회벽·기와·따뜻한 목재와 기존 브랜드 색 역할은 유지한다.

목재는 밝은 기름 마감과 짙은 호두색을 나누고, 인스턴스 부재의 실제 긴 축에 결의 방향과 반복을 맞춘다. 기와는 비금속 표면으로 바꾸고 유리·도자기·면 천의 빛 반응을 구분한다. 햇빛을 높이되 하늘·간접 보조광을 줄여 밝은 면과 깊은 그늘을 만든다. 잎의 요철 강도는 0.28, 발광 강도는 0으로 정리했다. 광원·렌더 타깃·루프와 텍스처 업로드 예산은 늘리지 않았다.

주민·플레이어의 외형, 기본 먼 카메라와 조작법, 실제 장소 좌표와 걸음 판정은 변경하지 않았다. 장소가 한 줄로 놓인 기존 배치도 유지하므로 마을 전체 위치를 새로 설계한 결과는 아니다.

| 실제 연속 걷기 | 평균 fps | 프레임 간격 p95 | 최대 간격 | 50ms 초과 |

55fps 기준과 기존 RAF 계측을 유지했다. 별도 동영상 GPU 렌더가 종료된 뒤 마지막 전체 실행을 했으며, [실행 전 관측](readiness-observation.json)에 남은 다른 프로세스도 기록했다. 완전 무부하 측정이나 일정한 60fps를 주장하지 않는다. 현재 기록은 호스트 Edge의 화면 크기 검사이며 실물 휴대폰 성능이 아니다.

키 목표 이동 보조 함수만 실제 keydown→keyup의 관측 지연을 차감하고 최소 펄스를 35ms에서 1ms로 조정했다. 실제 키 입력·같은 동선·0.10m 허용 오차를 유지했으며 좌표·상태·권한·충돌을 주입하지 않았다. 성능 기준 미달은 지연 실패로 남기고 다른 동선도 수집하도록 하여 실패를 숨기지 않는다. 제품 이동 코드는 바꾸지 않았다.

자원 검사는 표시 전용 테이블·쿠션·기억 fixture를 사용하므로 생활 완료의 사실 근거로 삼지 않는다. 실제 완료 사실은 위의 버튼·명령·재입장 검사에서 확인한다. 인스턴스 버퍼와 컨텍스트 해제, 자산이 늦게 도착해도 해제 이후 새 버퍼를 만들지 않는 것을 확인했다.

## 보존한 중간 결과

검사 기준을 낮추지 않았다. 중간 결과는 현재 미술의 최종 기능·성능 통과를 대신하지 않는다.

1. **첫 미술 제출:** [첫 GPU 결과](first-pass/after.json)는 기능 검사 65/65였지만, [미술 반려](first-pass/review.json)에 기록한 큰 접힌 잎, 찻집 창을 가리는 차양, 둥근 집 창을 자르는 작은 지붕, 각진 흙 면 때문에 다시 교정했다. 당시 소스·이미지도 `first-pass`에 보존했다.
2. **둘째 미술의 첫 실행:** [attempt1](second-pass-attempt1/after.json)는 44개 검사를 통과한 뒤 390폭 이동 목표 `x=-3`에 수렴하지 못해 중단됐다. [사실 기록](second-pass-attempt1/facts.json)에는 종료 위치 `x=-3.34`, shader/page/API 오류 0개와 왕복 이동 입력을 기록했다. 발생 원인은 분리하지 못했으며 제품 충돌 코드를 수정한 결과가 아니다.
3. **이동 진단:** [독립 진단](route-diagnosis/report.json)에서 원래 이동 보조 함수와 적응형 보조 함수가 기존 허용 오차 0.10m 안에 도달했다. 관측한 실제 키 유지 시간의 초과는 7.5~104.3ms였다. 이 관측만으로 첫 이동 실패의 원인을 확정하지 않는다.
4. **둘째 실행:** [attempt2](second-pass-attempt2/after.json)는 9개 통과·1개 실패로, 실제 PC 연속 걷기 40.69fps가 기준 55fps에 미달했다. [기록](second-pass-attempt2/facts.json)은 최대 간격 606.1ms와 원인 미분리 상태를 보존한다. [공유 호스트 관측](second-pass-attempt2/concurrent-load-observation.json)에 다른 GPU 렌더·CPU 작업이 함께 실행 중이었지만 그것이 실패 원인이라는 증거로 확정하지 않는다. 다른 작업을 중단하거나 기준을 낮춰 통과시키지 않았다.

자동 플레이는 별도 임시 포트와 일시 저장소를 사용한다. 기존 4288 사용자 저장을 읽거나 초기화하거나 변경하는 검사가 아니다. 실물 휴대폰의 지속 성능·발열, 게임패드, 실제 사용자 멀미와 미술 만족, 실제 WORLD 계정/두 기기, 공개 배포는 이번 확인 범위 밖이다.

## 사용자 미리보기 전달

꺼져 있던 4288은 기존 `server.mjs --preview`와 기본 저장 경로로 다시 실행했다. 저장 파일 삭제·초기화나 상태/명령 API를 이용한 자동 검사는 하지 않았다. 이후 [v9 앱 브라우저 열기 시도](preview-handoff.json)는 Browser webview 연결 시간 초과로 실제 탭의 표시를 확인하지 못했다. 탭이 열렸다고 보고하지 않으며 위 로컬 링크와 실제 GPU 캡처로 검토 결과를 전달한다.
