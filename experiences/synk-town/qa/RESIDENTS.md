기존 생활·저장·연결 코드 검사도 [209/209 통과](residents-runtime.txt). 새 모듈은 개발 체험에서만 제공하고 주인/손님 PNG는 올바른 MIME으로 제공하는 [서버 검사](residents-server.txt)도 통과했다. 4288 서버에 새 주민 및 공유 몽글의 `avatar-textiles.mjs` 경로를 반영해 재시작했으며 가상 생활 저장은 유지했다.

- 실제 사용자 입력으로 집에서 찻집까지 WASD 이동 → 대화 → 안쪽 자리 선택 → 손님이 앉고 차를 받는 과정 → 동작 줄이기 상태의 걷기를 1280×900과 390×900에서 확인했다.
- 여섯 주민 모두 서로 다른 identity와 실루엣을 제공한다. 모델의 `head.getWorldPosition()`과 선언한 `headHeight`를 실제 `.56` 크기에서 대조했다.
- 모바일 대화창 아래에 플레이어와 대화하는 주민의 얼굴이 남는지 화면 좌표로 확인했다.
- 실제 `createDayScene`에 여섯 주민을 모두 배치한 별도 fixture를 렌더했다. 인스턴스 134/134개가 해제되고 WebGL 컨텍스트도 해제됐다.
- 별도 WebGL 대안 검사에서 텍스트 대체 화면이 열리고 같은 손님 PNG가 정상 로드됨을 확인했다. 정적 생활 장면을 끝까지 완료한 검사는 아니다.
- 구형 `preview.html`의 주인·손님·대화 아이콘을 직접 확인했고 새 PNG 6종 모두 HTTP 200이었다. `linked.html`은 같은 자산 경로를 사용하는 원문 검사까지만 했으며 실제 계정 연결 검증으로 세지 않는다.

## 직접 본 모습

[교수 원본](../../../docs/캐릭터/교수연구실/research.png)을 직접 보고 비교했다. 연구원의 연보라 타원 몸, 둥근 검정 안경, 크림색 두 갈래 콧수염, 봉제선이 원본의 식별 요소를 따른다. 원본 2D 이미지를 교체하거나 그대로 복제한 최종 마스터라는 뜻은 아니다.

초기 검사에서 발견한 교수 몸 중앙의 세로 음영 이음선, 안경 아래쪽이 몸에 묻히는 현상, 찻집 주인의 상의에 가려진 앞치마, 책과 손의 틈을 수정한 뒤 다시 봤다. 최신 캡처에서는 해당 문제가 보이지 않았다. 머리 모양·체격·옷·안경·책·가방으로 다섯 사람형 주민도 구별된다.

## 자산과 재현

`assets/residents/`의 PNG 6개는 `day-residents.mjs`의 실제 메시를 Three.js `alpha:true`로 렌더한 512×640 출력이다. 투명 픽셀과 불투명 픽셀을 모두 검사했다. 생성형 이미지 서비스, 외부 원격 자산, 픽셀 리터치는 쓰지 않았다. 캐스트 비교와 게임 사진도 실제 브라우저 출력이다.

[자산 출처와 SHA-256](../assets/residents/provenance.json)에 모델·여섯 PNG·변경하지 않은 교수 원본을 기록했다. 원본 픽셀과 최종 모델/PNG 해시의 일치를 별도로 확인했다.

```powershell
node experiences/synk-town/qa-residents-ui.cjs --portraits-only
node experiences/synk-town/qa-residents-ui.cjs --game-only
```

첫 명령은 모델 PNG와 라인업을 재생성한다. 두 번째는 이를 건드리지 않고 게임과 해제를 다시 검사한다. 옵션 없이 실행하면 두 범위와 WebGL 대안·구형 화면을 함께 검사한다.

모든 실행은 별도 포트의 메모리 저장소를 썼다. 사용자 4288 저장, 실제 계정, 운영 서버를 읽거나 수정하지 않았다. Headless Edge의 모바일 화면 크기 검사는 실제 휴대폰의 장시간 성능이나 사용성 평가를 대신하지 않는다.
