# 싱크타운 그래픽 v10 · 최적화와 생활 공간 디테일

사용자 「최적화 제대로 하고 디테일 더 잡고 그래픽 한단계 업그레이드 해줘」에 따른 로컬 구현·검증이다. 먼 고정 시점·직접 걷기·승인 캐릭터와 주민·생활/저장 계약을 유지하면서 환경 기하와 재질 비용을 줄이고 창·마루·식재·도자기 디테일을 교정했다. 실제 이동·생활·재입장과 자원 해제 검사를 완료했으며 최종 사용자 미술 만족이나 공개 배포를 뜻하지 않는다.

## 실제 구현

- 큰 나무는 96삼각형의 큰 타원 잎 대신 24삼각형의 작은 비대칭 잎 3,072개로 수관을 구성한다. 원경 숲은 상세 잎 4,900개 대신 12삼각형 잎 2,800개와 연결 가지 군락을 사용한다. 첫 후보의 둥근 구형 수관은 실제 화면에서 반려하여 교정했다.
- 작은 꽃망울·경계 돌·원경 목재의 불필요한 세분화를 줄인다. 지형은 실제 보행 가까이의 표면 해상도를 유지하고 원경에 더 넓은 격자를 쓰며 기존 `terrainHeight`와 월드 UV를 보존한다.
- 집·찻집·공방의 창 안쪽에 얕은 벽/창턱/접힌 커튼 층을 넣고 가짜 흰 사선 반사를 제거한다. 마루의 15개 보드 이음을 엇갈리게 배치하고 기둥의 돌 받침과 목재 연결부, 둥근 탁자와 찻잔의 벽·안쪽·가장자리를 보강한다. 창은 실제 방 내부 전체나 실시간 굴절 구현이 아닌 얕은 층 표현이다.
- 목재의 일정한 줄을 불규칙한 긴 결과 연한 옹이로 바꾸고 기와의 소성/유약 변화, 석재의 광물 무늬와 작은 구멍, 얕은 잎맥을 다듬는다. normal RGBA의 알파에 선형 roughness를 저장하여 해당 16개 표면 재질의 표면 텍스처 읽기를 3→2회로 줄인다. 원본·clone·2차 clone의 목재 UV와 셰이더/캐시 키를 유지한다.
- 렌더의 임시 Color/Viewport/Scissor를 재사용한다. beauty·햇빛 그림자·접촉 음영 로직은 보존한다. 35m 밖의 완전한 경계를 normal 패스에서 제외하는 후보는 실제 8개 구도에서 제외 수가 모두 0개여서 추가 연산을 최종 제품에서 제거했다. 이를 drawcall 절감으로 주장하지 않는다.
- 고정 환경 248개의 로컬 행렬 재계산을 멈추되 부모의 이동·회전은 그대로 전파한다. 프레임마다 크기가 바뀌는 장면 라벨은 자동 행렬을 유지한다. 광원·렌더 타깃·프레임 제한·픽셀 비율·AO 해상도와 샘플을 늘리거나 낮추지 않는다.

[환경 CPU](architecture-cpu.json)는 실제 Three 기하/행렬을 사용했다. 비유한 값 0개, 기하 108/108와 인스턴스 메시 139/139의 해제, 장소/지형 원문 동일, 타깃 7개·환경 루트 15개·가림 루트 14개, 고정 행렬의 부모 변환 전파를 확인했다. 재질과 캔버스는 대체 입력이므로 화면/실제 GPU 검사로 해석하지 않는다.

[재질 CPU](materials-model.json)는 270/270, [렌더 상태 CPU](rendering-cpu.json)는 11/11 통과했다. 렌더 상태 검사는 실제 Three Color/Vector와 mock 직접 렌더러를 사용해 임시 객체 재사용·일반/예외 복구·컨텍스트 손실·해제 상태를 검사한 범위이며 GPU 검사와 다르다. 고유 데이터 크기는 RGBA 기본 레벨의 추정치이며 mipmap·드라이버 내부 할당·후처리 버퍼·다른 자산을 포함하지 않는다. 과거 `uploadedBytes`의 9,502,720→6,356,992B는 복제 Texture 객체의 중복 합계이므로 실제 GPU 메모리 절감으로 보고하지 않는다. 실제 renderer의 texture 카운트도 별도로 비교한다. 한 번의 CPU 질감 생성 시간은 301.88→305.47ms여서 생성 시간 개선은 주장하지 않는다.

[범위 검사](guard.json)는 74/74 통과했다. 타운의 미술/렌더 네 파일과 공용 캐릭터 새 의상 모듈 두 개를 제공하는 `server.mjs`의 정적 경로 한 줄을 변경했다. 공용 avatar/textiles는 이 작업 종료 중 외부 작업에서 갱신되어 그 원본을 보존하고 현재 해시를 따로 확인한다. 나머지 20개 기준 소스·생활 핵심 9개·승인 UI/초상 자산을 유지한다. 서버 전체 AST는 새 preview 전용 정적 경로 한 줄 외 동일하다. `day-scene`은 버전 두 값과 외부에서 갱신한 의상 카탈로그 import/허용 목록 두 연결 외 전체 AST가 동일하며 카메라/프레임/배우/입력을 유지한다. 기존 4개 차림·현재 카탈로그·미확인 호스트 차림 거절·해제 뒤 무반응은 [현재 외형 검증 6개](appearance-cpu.json)로 확인한다. 렌더러는 [직접 검토한 정확한 5구간](rendering-scope-review.cjs) 외 전체 AST가 동일하다.

## 이번에 새로 측정한 기준선

`before.json`과 20장의 `before-*.png`는 이번 작업에서 v9 소스를 동결한 뒤 새로 실행한 실제 GPU 결과다. 이전 v9 스크린샷을 복사한 자료가 아니다. [출처](baseline-provenance.json), [종료 후 소스 검사](before-source-audit.json)에 27개 소스·10개 핵심 로직·9개 자산과 촬영 당시 QA 원문을 대조했다. 종료 후 8개 무결성 검사를 통과했으며 이는 아래 기능/성능 실패를 지우지 않는다.

원본 before는 **56개 수집·54개 통과·2개 실패**다. PC 실제 걷기 46.47fps가 유지 기준 55fps에 미달했고, 과거 v9의 0m와 비교한 release-travel 값 0.03968m가 허용 차이 0.025m를 넘었다. 뒤의 마지막 취합 9개 항목은 수집하지 못했다. 실제 동선·터치·생활 완료/재입장과 100/300/600ms 카메라 정지 검사는 수집·통과했고 JS/GLSL/자산/API 오류는 없었다. 두 실패는 원보고서에 그대로 남기며 원인을 단정하지 않는다.

before와 최종 after의 전체 QA 원문은 공용 모듈 연결/소스 목록 갱신으로 달라졌다. [입력·프레임·카메라·정지 관측·생활 함수 16개 AST](qa-protocol-review.json)는 완전히 동일하며 실제 키/터치·동선·화면 크기·품질·계측을 유지한다. 공용 avatar/textiles 외부 갱신도 최종본에 포함되므로 성능 변화의 원인을 타운 미술만으로 확정하지 않는다. 집/찻집/근접 찻집/온실에서 각각 7.2초 정지 관측을 하고 실제 drawcall/삼각형/geometry/texture/타깃 바이트와 제품 CPU p50/p95를 기록한다. CPU는 최근 최대 360프레임 창이며 각 창이 현재 정지 관측 안에 들어오는지도 공개한다. 모든 작은 플레이어 위치 차이와 카운트 범위를 남긴다. CPU 타이머는 GPU 실행 시간이 아니다.

공유 호스트에 일반 Edge·CPU 작업이 남아 있으며 전후의 완전한 무부하를 보장하지 않는다. 첫 after 준비에서 별도 영상 렌더를 발견해 종료를 기다렸고, 최종 실행 전 읽기 전용 관측을 남긴다. 다른 작업을 중단하거나 통과 기준을 낮추지 않았다. before 종료 뒤 adapter 진단 요청이 도착하여 전후 동일 adapter는 확인하지 못했다.


공용 캐릭터 갱신 전 당시 검증한 48/48 묶음은 [pre-shared-update](pre-shared-update/verification.json)에 보존한다. [외부 갱신과 두 import 404](shared-update.json)를 발견한 뒤 공용 원본을 되돌리지 않고 preview 전용 두 정적 경로만 연결했다. 이때 `server.test.mjs`의 기존 검사에 허용/비허용 경로 검증을 추가했고 148/148 회귀를 재실행했다. 최종 실제 브라우저는 현재 avatar/textiles와 새 wardrobe/catalog 모듈을 포함한 29개 소스 해시를 시작/종료에 대조해 65/65와 자원 2/2를 통과했다.

60fps 목표와 계측 방식을 유지했다. 최종 모바일 평균 FPS는 before보다 낮아 FPS 개선을 주장하지 않는다. 50ms 넘는 간격과 최대 지연도 표에 남겨 끊김이 없다고 보고하지 않는다. 공유 호스트에서의 측정치이므로 다른 컴퓨터·실제 휴대폰의 지속 성능을 보장하지 않는다.

실제 8개 구도에서 삼각형 제출은 약 29.25~33.08% 줄고 renderer texture 카운트는 PC 58→52, 390폭 51→45다. drawcall은 PC 집/찻집 기본 구도에서 동일하며 다른 구도도 증가 1회~감소 4회 수준의 차이여서 의미 있는 drawcall 최적화로 주장하지 않는다. 후처리 타깃 바이트는 PC 51,840,000B, 390폭 0B로 유지한다.

현재 최종 실행의 8개 정지 구도는 CPU p50/p95가 새 before보다 낮았고 각 360프레임 창이 현재 관측 안에 포함됐다. 다만 앞서 [공용 파일 갱신 전 전체 실행](pre-shared-update/render-comparison.json)의 모바일 찻집 두 구도는 CPU 시간이 증가했다(기본 8.1/11.1→12.2/20.6ms, 근접 6.8/9.7→9.4/22.9ms). 불리한 원본을 교체하지 않는다. [별도 조사](cpu-profile-diagnosis/report.json)는 before 두 구도를 수집한 뒤 공용 캐릭터의 새 의상 import 404로 after를 끝내지 못했다. 이 호환 경로를 보완한 현재 전체 검증에서는 기본 6.3/10.8ms, 근접 4.6/7.3ms를 기록했다. 이전 증가 원인은 분리하지 못했으며 공유 호스트의 부하와 공용 소스 변화도 있어 일률적인 CPU 향상이나 단일 원인으로 확정하지 않는다. CPU 타이머는 GPU 실행 시간이 아니다.

[직접 시각 검수](visual-review.json)는 PC 집의 먼 시점, PC 찻집 근접, 390폭 찻집 먼 시점 세 장을 원본 PNG로 확인한 결과다. 첫 후보의 원경 구형 덩어리가 제거됐고 창턱·커튼·마루 이음·컵 가장자리와 HUD 읽힘을 확인했다. 이 세 이미지에서 새 부유 접합/큰 지형 틈을 발견하지 못한 범위이며 사용자 미술 만족을 대신하지 않는다.

첫 after는 실제 65/65 검사를 통과했지만 원경 구형 수관을 미술 검수에서 반려했다. 당시 네 제품 소스·보고서·20개 화면을 [first-pass](first-pass/first-art-review.json)에 보존했다.

원경 교정 후 [거리 가림 후보](normal-range-attempt/decision.json)의 실제 플레이 65/65와 자원 2/2는 통과했지만, normal 제외 수가 0개여서 기대한 효과를 얻지 못했다. 해당 최종 취합은 47/48이며 실제 제외를 요구한 1개 항목이 실패한 원본을 보존한다. 최종 제품은 이 후보를 제거하고 기존 접촉 음영을 그대로 유지하므로 최종 취합에서는 실제 AO 품질/샘플·모바일 버퍼 정책을 확인한다. 성능 기준 55fps, 환경 기하 감소 기준, 소스/자산 보존 기준은 낮추지 않았다.

이전 UI 47개·주민 모델 CPU 20개·초상 18개는 해당 UI/주민 원문과 이미지 해시를 확인하여 기존 범위의 증거로 재사용한다. 공용 textile 외부 갱신 뒤 실제 조명/표면은 현재 GPU 화면에서 별도로 확인한다. 생활/저장/걷기/서버 회귀 148개는 정적 경로 수정 뒤 이번에 새로 실행했다. 실제 생활 완료의 근거는 독립 저장소에서 누른 버튼과 호스트 명령·재입장이다. 표시 전용 기억/테이블/쿠션 자원 fixture를 완료 사실로 사용하지 않는다.

자동 플레이는 별도 임시 포트와 일시 저장소만 쓰며 사용자 4288 저장·상태/명령 API에 접근하지 않는다. 4288은 공개 정적 파일 GET만 확인한다. 최종 미술 만족·사람의 멀미 체감·실물 휴대폰 지속 성능/발열·게임패드·WORLD 실계정 두 기기·공개 배포는 확인되지 않았다. 원경 집의 반복, 절차형 식물, 얕은 창 내부는 앞으로 개선할 여지가 있다.
