같은 날 추가한 읽기 설명 제안·두 손님·음식 없는 그림 가판의 현재 범위와 Node 189개 통합 결과는 [후속 검증 기록](SUPPORT-BAZAAR.md)에 있다. 아래 141개 코드 검사는 첫 하루 최초 통합 시점의 기록이다.

## 실제 연결한 범위

| 생활 | 구현한 변화 | 보존하는 경계 |
|---|---|---|
| 집과 외출 | 방석 두 자리 미리보기/확정, 문 앞 선택/명시적 나가기, 귀가와 다음 외출 | 장식은 외출 조건이 아니고 기본 물건을 추가 지급하지 않음 |
| 찻집 자리·안내판 | 현재 자리로 실제 이동·차 제공·그림을 따라 자리 이용 | day 화면은 서버 실행 뒤 완료, 관람은 별도. 옛 preview 턴 방식은 호환 유지 |
| 세 주민 일과 | 찻집 쟁반·공방 도구·연구원 그림 준비, 공방→찻집 받침 확인→복귀 | 주민끼리 한 일을 사용자 공로로 만들지 않음. 같은 몸의 이용·준비·생활 예약 충돌 방지 |
| 차와 그림 | 그림 뒤 명시적으로 차 이어가기 / 두 자리로 나누기, 관람·위임 | 미결정을 시간으로 대신 확정하지 않으며 관람을 기획 공로로 만들지 않음 |
| 쉼과 전시 조율 | 먼저 쉼 / 별도 자리 / 말 없는 그림 / 주민에게 분담 맡기기 | 유효한 합의가 다음 일과의 실제 자리·그림 사용으로 이어짐. 철거는 현재 합의만 무효화 |
| 공방의 도움 | 받침 잡기/자리 준비/혼자 하기, 실제 도움 뒤 최종 방향 선택 | 역할과 도움은 별도, 누구에게나 기본 요청 가능. 선택 방향은 닫기·귀가 뒤 물건과 수첩에 남음 |
| 지원 방식 | 시범 2초 뒤 사용자 기다림 / 협력 확인 / 기획 리허설 3초 뒤 최종 확인 | 다음 선택에 적용하고 이미 수락한 방식은 바꾸지 않음. 실제 숙련도 자동 판정은 아직 없음 |
| 시간 준비 | 부탁한 받침 한 건이 서버 시간 30초 뒤 준비, 공방에서 명시적으로 사용 확인 | 부재 중 허용된 한 건만 완료. 중복 수령·재화·판매 재고·벌점 없음 |
| 표현 | 작은 실제 3D 동네, 동일 NPC 몸, 자세·그림·소품 방향, 넓게/가까이와 두 품질 | 최종 마스터·물리 경로 탐색·공유 마을·실폰 성능을 뜻하지 않음 |

자동 접근은 기존 C1의 조용히/보통/활기차게 원장을 재사용한다. 새 공방·연구원 자동 의뢰 원장은 추가하지 않았다. ‘여기서 쉬기’ 중 새 C1 접근은 억제하고 직접 도움은 열어 둔다. 전체 열 가지 생활 콘텐츠와 LS 장편을 완료한 기록이 아니다.

## 코드 검사

[day-runtime.json](day-runtime.json), [전체 실행 출력](day-runtime.txt): **141/141 통과**. 모든 Town Node 검사와 teacher-world Town bridge 회귀를 포함한다.

핵심 추가 검사는 첫 문·재료 지급 시점, 실제 FT10/51 실행 전 완료 금지, 떠나기/회수 중단, C1과 첫 하루의 동일 몸 예약, 시범 대기/역할·관람 분리, 최종 방향 보존, 준비 작업 저장 실패의 전체 되돌림, 실제 파일 재시작, 한 번 수령, 두 창 fence, 일반 입구/연결 학생의 새 capability 차단이다. 테스트는 임시 상태·파일만 사용한다.

전경 시간은 한 프로세스의 창 합집합과 3초 임대 상한을 사용한다. 일반 행동은 오프라인 시간을 따라잡지 않는다. 준비 한 건만 승인된 시작/완료 서버 시각을 사용하며 역행 시계로 중복 완료하지 않는다. 이는 실계정 두 기기나 악성 클라이언트의 실제 전경 증명까지 검증한 것이 아니다.

휴대폰 폭에서 별도 아래 문단까지 동시에 보여야 하던 관람 조건을 장면 안의 실제 반응 자막으로 고쳤다. WebGL 대안에서는 텍스트와 주민 목록을 덮던 중복 자막을 숨겼다. 그림을 나타내는 관찰판과 받침 방향, 선택 미리보기는 실제 소품으로 구별한다.

수집한 최근 프레임 간격·CPU 렌더 시간은 해당 데스크톱 브라우저 측정이다. 균형 30/경험 60은 렌더 목표 상한이며 실폰 보장 FPS가 아니다. Galaxy S25·iPhone 15, 장시간 발열/배터리 검사는 하지 않았다.

## 사람에게 확인해야 할 부분

실제 플레이 관찰 **0명**, 실제 휴대폰 **0대**, 공개 배포 **없음**. 자동 UI 성공을 재미·자율성 체감·학습효과 성공으로 보고하지 않는다. 화면의 자기 점검 메모는 이 브라우저 저장과 JSON 내려받기까지만 제공하고 외부 전송은 없다. [관찰표](DAY-PLAYTEST.md)로 서로 다른 도움 요구의 사용자가 선택 변화·주민의 이유·복귀할 이유를 이해하는지 확인한다.

이 첫 하루 이후의 필수 작업은 실제 관찰로 동선·문장·지원 강도를 조정하기, 학습 프로필과 지원 방식을 검증 가능한 계약으로 연결하기, 실제 기기 최적화, 최종 캐릭터·공간 자산, LS 장편·열 가지 콘텐츠의 제작 분량 확장이다. 정식 계정·입장 권한과 생활/학습 기록 분리도 별도 통합이 필요하다.
