## 1단계 시험 버킷 실측 M1~M7 — 2026-11-12

유호님 승인(11-12 「승인, B2 시험 진행」)으로 0.5.0을 올렸던 운영자 B2 계정(US East)에 1단계 시험 버킷 하나를 만들었다. 비공개 · 서버 쪽 암호화(SSE-B2)이고, 수명 규칙은 접두사 `t/`에 「숨긴 지 30일 뒤 삭제」, `ci/`에 「올린 지 7일 뒤 숨김 · 숨긴 지 1일 뒤 삭제」, 두 접두사 모두 끝나지 않은 큰 파일은 1일 뒤 취소다. B2 콘솔은 출입증 권한을 「읽기와 쓰기 · 읽기만 · 쓰기만」으로만 고르게 해서 삭제 권한 없는 출입증을 만들 수 없었다. 그래서 마스터 출입증을 새로 만드는 대신 콘솔에서 **1시간 뒤 저절로 만료되는 임시 관리 출입증**(모든 버킷 · 읽기와 쓰기 — 출입증 만들기 권한이 들어 있음을 콘솔 목록에서 확인)을 만들어 API(v4)로 시험 출입증을 만들고, 실측 뒤 지웠다(지운 뒤 인증 401). 비밀값은 화면에서 읽자마자 DPAPI로 감싸 저장소 밖(`%LOCALAPPDATA%\SynkWorkBackupStage1`)에 두고 출력 · 기록에 남기지 않았다. 0.5.0 버킷 · 출입증 둘 · Google 복구 정보는 건드리지 않았다.

남은 시험 출입증: 실측 쓰기(`t/`, 삭제 없음) · 읽기(`t/`) · 서버 흉내(시험 버킷 전체, 삭제 있음 — 되살리기 도구 · 연습용) · CI 쓰기(`ci/`, 삭제 없음) · CI 읽기(`ci/`). listBuckets 없는 실측 출입증 하나는 M7에서 지웠다.

도구: [`server/tools/b2-setup.mjs`](server/tools/b2-setup.mjs) · [`b2-measure.mjs`](server/tools/b2-measure.mjs), restic 0.19.1(고정 해시 대조), 씨앗 고정 합성 자료 272개 · 26,768,003바이트(한글 이름 · 빈 폴더 포함). 실행마다 새 하위 접두사(`t/r…/`)를 쓴다. 아래는 두 번째 실행(`rc1d394`)의 값이다. 첫 실행(`re2ad0f`)은 같은 값으로 M4까지 돌다가 M5의 목록 읽기에서 B2가 유휴 연결을 끊어(`other side closed`) 멈췄다 — B2 기본 API · S3 요청에 재시도를 넣고 처음부터 다시 돌렸다.

## 실패와 재검증

- 최초 Windows 경로 정규화는 `\\?\` 형식이 기존 엔진의 로컬 드라이브 검사에서 거부됐다. 네이티브에서 검증한 로컬 드라이브 경로로 바꿔 전체·선택 복구 통과.
- 두 시험 인스턴스가 기본 WebView2 폴더를 공유하고 서로 다른 브라우저 옵션으로 실행되면 `0x8007139F`로 창 생성이 실패했다. 상태별 `webview` 폴더를 지정한 최종 후보에서 동시 로컬·B2 시험과 화면 시험을 다시 통과했다. [Microsoft의 폴더·세션 규칙](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/user-data-folder)을 대조했다.
- 첫 Fable 화면 응답은 출력/예산 제한으로 JSON이 잘려 통과로 세지 않았다. 32,000 토큰 출력 여유와 보수적 비용 예약을 둔 최종 호출은 전체 입력·4장 캡처·끝 표식 대조를 통과했다.
- `backend-verified` GPT 응답은 제공 범위를 모두 읽었다고 했지만 요청하지 않은 targets를 추가해 형식 검증에 실패했다. 원문을 보존하고 통과로 세지 않았다. 마지막 유효 사슬에서 실제 변경 diff만 `backend-release`로 다시 보냈다.
- rfd 취소 버튼 지적은 실제 고정 버전 0.18.0이 사용하는 custom ID 1000/1001과 native IDCANCEL=2가 구분됨을 원문으로 확인했다. Enter 기본은 첫 취소 버튼이고 Esc/닫기는 `Cancel`이므로 확인으로 매핑되지 않는다. OS 마우스·키보드로 직접 누른 시험은 하지 않았다.
- 실패한 이전 임시 사본은 자동 삭제하지 않는다. DPAPI로 암호화된 읽기 키를 가진 비운영 형제 폴더이며 자동 실행 대상이 아니다. 실패 증거와 경합한 기존 폴더를 보존하는 정책이다.
- 첫 소스 업로드 전 관련 시험은 워크트리의 홍보 자료·루트 `parse5` 의존성 누락으로 멈췄다. 해당 자료를 `가볍게 --되살림`으로 복원하고 고정 잠금 파일로 `npm ci --ignore-scripts`를 실행했다. 재현한 웹 배포 4개·SNS 발행 2개는 모두 통과했으며 처음 실패 로그는 보존했다. Rust 앱이나 관련 없는 배포 코드를 고치거나 시험 관문을 끄지 않았다.

## 배포 범위와 남은 일

실행 파일과 리소스를 `Documents/업무백업-시험판/0.6.0-rust-beta.1/`에 설치했다. 설치된 EXE·리소스 291개 해시가 최종 후보와 일치하고, 한글 설치 경로에서도 로컬 전체·선택 복구 시험을 통과했다(`native-smoke-tNb7dk`). 두 필수 검수의 현재 후보 대조도 통과했다.

기본 Rust 상태에 B2 읽기 키를 암호화 복사하고 바탕화면 바로가기를 만드는 마지막 설정은 사용자에게 명시적으로 승인받았다. 승인 뒤 동일 명령을 다시 실행했지만 자동 승인 검토가 또 `blocked by policy`로 차단했다. 두 번 모두 명령은 실행되지 않았고 기본 상태·바로가기는 아직 없다. 다른 경로로 우회하지 않고 설치 폴더의 `연결 안내.txt`에 사용자가 직접 실행할 기존 이전 명령을 적었다. 실제 B2 복구 검증은 별도 격리 사본에서 완료했다. Rust 시험판 자동 시작은 켜지 않았고 기존 0.5.0이 정기 백업을 계속 맡는다.

이번 시험으로 확인한 것은 이 PC의 파일 백업·복구와 호환 경계다. Rust판의 실제 Windows 재로그인 자동 실행, 새 Google 로그인, 다른 PC·OS 조합, 장시간/대용량 작업, 재개 가능한 복구, VSS/전체 Windows 이미지 복구, 서명 설치·자동 업데이트는 완료로 주장하지 않는다. 웹뷰와 Node가 함께 있으므로 메모리·속도 향상도 측정 전에는 주장하지 않는다. 엔진 전체 Rust 이식과 운영 백업 전환은 다음 단계다.

## 0.6.1 추천 자료 로컬 백업과 새 상태 복구 — 2026-11-10

사용자가 클라우드 과금을 보류하고 앱·로컬 검증만 선택했다. 추천 클라우드는 화면과 `start`·`initialize`·`backupPlan`에서 비활성화했다. 기존 0.5.0 B2 저장소·설정·시작 등록은 변경하지 않았으며 이 작업에서 B2 업로드·결제·권한 변경은 실행하지 않았다. 이전에 차단된 기본 Rust 자격 이전과 바로가기도 재시도하지 않았다.
