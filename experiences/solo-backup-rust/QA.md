## 1단계 시험 버킷 실측 M1~M7 — 2026-11-12

유호님 승인(11-12 「승인, B2 시험 진행」)으로 0.5.0을 올렸던 운영자 B2 계정(US East)에 1단계 시험 버킷 하나를 만들었다. 비공개 · 서버 쪽 암호화(SSE-B2)이고, 수명 규칙은 접두사 `t/`에 「숨긴 지 30일 뒤 삭제」, `ci/`에 「올린 지 7일 뒤 숨김 · 숨긴 지 1일 뒤 삭제」, 두 접두사 모두 끝나지 않은 큰 파일은 1일 뒤 취소다. B2 콘솔은 출입증 권한을 「읽기와 쓰기 · 읽기만 · 쓰기만」으로만 고르게 해서 삭제 권한 없는 출입증을 만들 수 없었다. 그래서 마스터 출입증을 새로 만드는 대신 콘솔에서 **1시간 뒤 저절로 만료되는 임시 관리 출입증**(모든 버킷 · 읽기와 쓰기 — 출입증 만들기 권한이 들어 있음을 콘솔 목록에서 확인)을 만들어 API(v4)로 시험 출입증을 만들고, 실측 뒤 지웠다(지운 뒤 인증 401). 비밀값은 화면에서 읽자마자 DPAPI로 감싸 저장소 밖(`%LOCALAPPDATA%\SynkWorkBackupStage1`)에 두고 출력 · 기록에 남기지 않았다. 0.5.0 버킷 · 출입증 둘 · Google 복구 정보는 건드리지 않았다.

남은 시험 출입증: 실측 쓰기(`t/`, 삭제 없음) · 읽기(`t/`) · 서버 흉내(시험 버킷 전체, 삭제 있음 — 되살리기 도구 · 연습용) · CI 쓰기(`ci/`, 삭제 없음) · CI 읽기(`ci/`). listBuckets 없는 실측 출입증 하나는 M7에서 지웠다.

도구: [`server/tools/b2-setup.mjs`](server/tools/b2-setup.mjs) · [`b2-measure.mjs`](server/tools/b2-measure.mjs), restic 0.19.1(고정 해시 대조), 씨앗 고정 합성 자료 272개 · 26,768,003바이트(한글 이름 · 빈 폴더 포함). 실행마다 새 하위 접두사(`t/r…/`)를 쓴다. 아래는 두 번째 실행(`rc1d394`)의 값이다. 첫 실행(`re2ad0f`)은 같은 값으로 M4까지 돌다가 M5의 목록 읽기에서 B2가 유휴 연결을 끊어(`other side closed`) 멈췄다 — B2 기본 API · S3 요청에 재시도를 넣고 처음부터 다시 돌렸다.

## 1단계 회차 실행기와 T7 — 2026-11-12

[설계 4.2](STAGE1_DESIGN.md#42-앱과-따로-도는-예약-로드맵-2)의 회차 실행기를 첫 증분으로 만들었다. `WorkBackupRun.exe --run hourly|logon|wake|unlock|manual`이 상태 잠금을 잡고(못 잡으면 「바쁨(화면)」만 적고 끝, 화면 앱을 깨우지 않음), 실행하는 파일만 확인하고(restic.exe는 크기만 — 해시는 엔진이 고정 값으로 워커마다), 쉼(배터리 30% 아래 · 절전 · 종량 회선, 직접 누른 회차는 쉬지 않음)을 판단한 뒤, 워커를 회차 모드(`SWB_MODE=run`, [`worker/runner.cjs`](worker/runner.cjs))로 띄워 `$run` 한 번 하고 끝난다. 엔진의 회차(`runOnce`)는 할 때가 됐는지(55분) 보고, 오래된 잠금을 `unlock`으로 풀고(M3b), 종료 11은 「바쁨」(점검 실패로 안 적음), 종료 3은 「부분」으로 돌려준다. 회차마다 `runs.jsonl` 한 줄(정해 둔 칸만), 도는 동안 `progress.json`(종류 · 단계 · 퍼센트만). 잠금 둘(`engine.lock` · `ui.lock`)과 작업 스케줄러 등록은 다음 증분이다 — 그 전까지는 실행기를 예약에 걸지 않는다(지금 잠금은 화면 앱과 같은 `native.lock`이라, 회차 중에 화면 앱을 열면 조용히 안 열린다).

- **작업 폴더:** 설치 뒤 `--install`이 회차 작업 폴더를 관리자 소유 · T2 권한으로 만든다(설치기가 만든 폴더면 권한을 다시 놓는다). 표준 사용자가 먼저 같은 이름으로 만든 폴더는 넘겨받지 못한다 — 깨끗한 Windows에서 잰 아래 표대로 작업 스케줄러가 상승된 관리자에게도 모두 거절한다. 그래서 회차는 Administrators나 SYSTEM이 소유한 폴더에만 등록하고 아니면 뿌리 폴더에 두며, `--install`은 그 폴더를 건드리지 않고 `SCHEDULE_FOLDER_NOT_OURS`로 알리고(설치는 계속), `--uninstall`은 그 폴더를 건너뛰고 나머지를 지우며 지우지 못한 것은 세어 알린다(전에는 첫 실패에서 멈춰 뿌리 폴더의 작업까지 남겼다).

[설계 4.2 「도우미」의 「먼저 잴 것」](STAGE1_DESIGN.md#도우미--섀도-복사본만-만든다): 관리자 확인이 켜진 이 PC에서, 관리자가 만든 섀도 복사본 연결을 지나 보통 권한이 다른 프로그램이 쥔 파일을 읽고 restic으로 백업할 수 있는지. 측정 스크립트는 `test-support/t5-vss-measure.ps1`이다(보통 권한으로 띄우면 관리자 확인 한 번 · 관리자 쪽은 C: 복사본 하나와 관리자만 쓰는 폴더 안 연결 하나만 만들고, 끝나면 그 둘을 번호로 지운다).

- **세 번째 시도(17:48):** 한가할 때 띄웠는데, 그 사이 Windows가 C:에 새 복원 지점(약 2GB)을 만들어 두었다. 새 조건대로 스크립트가 복사본을 만들지 않았다(아무것도 바뀌지 않음). C:에는 앞으로도 복원 지점이 생기므로 측정은 D:로 옮겼다(스크립트에 `-Drive` · 묻는 방식은 같다).

- **되살리기에서 본 것:** `restic restore`로 되살리면 그 파일이 돌아온다. 다만 연결 폴더(`snap-D`)는 숨김 · 시스템 폴더로 돌아오고, 관리자 폴더의 권한(보통 권한은 읽기만)이 되살린 폴더에도 붙는다. 스크립트는 숨김 폴더를 안 찾아 「not found」로 적었고, 그 권한 때문에 시험 폴더를 못 지웠다(되살린 쪽의 소유자는 보통 사용자라 권한을 되돌린 뒤 지움 · 스크립트도 고침). 앱의 되살리기는 `restic restore`를 쓰지 않고 `dump`로 파일을 꺼내 자체로 풀므로 권한을 붙이지 않는다. 연결(정션)과 읽기만 되는 중간 폴더를 끼운 재현에서도 `dump`는 내용을 그대로 돌려줬다. 이 회차에서 백업 안 내용을 해시로 견주지는 못했다(되살린 파일 3MB는 있었다) — 다음에 스크립트를 돌리면 `dump` 해시와 판 안 폴더 종류까지 함께 적는다.

## 1단계 채움 판 · 도우미 · 연결 건너뛰기 — 2026-11-16

## 배포 범위와 남은 일

실행 파일과 리소스를 `Documents/업무백업-시험판/0.6.0-rust-beta.1/`에 설치했다. 설치된 EXE·리소스 291개 해시가 최종 후보와 일치하고, 한글 설치 경로에서도 로컬 전체·선택 복구 시험을 통과했다(`native-smoke-tNb7dk`). 두 필수 검수의 현재 후보 대조도 통과했다.

기본 Rust 상태에 B2 읽기 키를 암호화 복사하고 바탕화면 바로가기를 만드는 마지막 설정은 사용자에게 명시적으로 승인받았다. 승인 뒤 동일 명령을 다시 실행했지만 자동 승인 검토가 또 `blocked by policy`로 차단했다. 두 번 모두 명령은 실행되지 않았고 기본 상태·바로가기는 아직 없다. 다른 경로로 우회하지 않고 설치 폴더의 `연결 안내.txt`에 사용자가 직접 실행할 기존 이전 명령을 적었다. 실제 B2 복구 검증은 별도 격리 사본에서 완료했다. Rust 시험판 자동 시작은 켜지 않았고 기존 0.5.0이 정기 백업을 계속 맡는다.

이번 시험으로 확인한 것은 이 PC의 파일 백업·복구와 호환 경계다. Rust판의 실제 Windows 재로그인 자동 실행, 새 Google 로그인, 다른 PC·OS 조합, 장시간/대용량 작업, 재개 가능한 복구, VSS/전체 Windows 이미지 복구, 서명 설치·자동 업데이트는 완료로 주장하지 않는다. 웹뷰와 Node가 함께 있으므로 메모리·속도 향상도 측정 전에는 주장하지 않는다. 엔진 전체 Rust 이식과 운영 백업 전환은 다음 단계다.

## 0.6.1 추천 자료 로컬 백업과 새 상태 복구 — 2026-11-10

사용자가 클라우드 과금을 보류하고 앱·로컬 검증만 선택했다. 추천 클라우드는 화면과 `start`·`initialize`·`backupPlan`에서 비활성화했다. 기존 0.5.0 B2 저장소·설정·시작 등록은 변경하지 않았으며 이 작업에서 B2 업로드·결제·권한 변경은 실행하지 않았다. 이전에 차단된 기본 Rust 자격 이전과 바로가기도 재시도하지 않았다.

### 실제 파일 검증

최종 후보 `candidate-v3`의 실제 숨김 WebView2에서 범위 확인 후 시작을 한 번 눌러 별도 로컬 저장소를 만들었다. 원래 문서·개발 설정·완료된 AI 대화 기록·LoRA 데이터셋·모델의 5개 묶음, **기존 72개 파일**과 프로그램 **258개 목록을 담은 새 JSON 1개**를 백업했다. 합계 **73개·481,448,761바이트**다.

앱을 종료한 뒤 **새 프로세스·빈 앱 상태**에서 외부 복구 키 파일과 로컬 저장소만으로 가져와 73개를 새 폴더에 복구했다. 모든 복구본 SHA-256이 시험 전 원본과 같고, 원본도 시험 뒤 모두 같았다. 운영 앱 상태나 기존 자격은 읽어 재사용하지 않았다. 새 상태의 DPAPI 형식은 `SWBR1`이며 시험 모드는 시작 등록을 바꾸지 않는다. 이 검증은 **같은 Windows 계정**에서 했으며 다른 물리 PC·새 OS를 시험한 것은 아니다.
