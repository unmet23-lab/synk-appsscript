> 2026-11-12 Claude(Opus) 초안. **Fable 5.2 설계 검토 전이다.** 단계 순서와 관문 숫자의 정본은 [로드맵](ROADMAP.md)이고, 이 문서는 로드맵 4장 1단계의 1~12를 **어떻게** 만들지 정한다. 실측은 [QA](QA.md), 결정은 [결정 표](../../docs/_ops/결정.md)에 적는다.
>
> 근거: [로드맵](ROADMAP.md) · [Rust 판 설명](README.md) · [Rust 판 설계](DESIGN.md) · [Rust 검증](QA.md) · [작업 환경 진단](inventory/README.md) · [0.5.0 설명](../solo-backup/README.md) · [경쟁 20개군 조사](../solo-backup/RESEARCH.md) · [0.5.0 검증](../solo-backup/QA.md) · 8장의 1단계 벤치마킹(11-12 수집) · B2 공식 문서(출입증 권한 · 수명 규칙, 11-12 확인) · restic 0.15 변경 기록.

이 문서의 낱말. **복구 암호** · **클라우드 출입증**은 로드맵 머리와 같다. **회차**는 예약이 백업 프로그램을 한 번 띄워 할 일을 하고 끝내는 한 번이다. **도우미**는 잠긴 파일을 읽으려고 관리자 권한으로 한 번 도는 회차다. **개통 서버**는 손님별 클라우드 자리와 출입증을 만들고 끊는 작은 서버다. **봉투**는 Google 앱 전용 공간에 넣는 복구 정보다.

## 0. 한눈에

1단계가 끝나면 이렇게 된다.

- 처음 쓰는 사람이 설치 → Google 로그인 → 「보호 시작」만으로 클라우드 백업을 시작한다. 입력 칸이 없다.
- 앱 창을 닫아도, 트레이가 없어도 Windows 작업 스케줄러가 매시간 · 로그인 직후 · 깨어난 직후 회차를 띄운다. 회차 사이에는 아무 프로그램도 떠 있지 않다.
- PC에 있는 출입증으로는 백업을 영구 삭제할 수 없다. 지워지거나 덮인 것은 30일 숨겨지고(11-12 유호님 「30일로 넣기」), 손님이 앱에서 「이 시각으로 되돌리기」를 누르면 서버가 되살린다.
- 새 PC에서는 설치 → Google 로그인 → 「이 PC로 옮겨 오기」로 원래 자리(또는 OneDrive 밖 새 폴더)에 되살리고, 옛 PC 출입증을 끊고, 같은 저장소에 이어서 백업한다.
- 컴퓨터 전체용 설치 파일 하나와 자동 업데이트가 있고, 깨끗한 Windows에서 같은 흐름을 GitHub Actions가 고칠 때마다 돌린다.

끝난 기준은 로드맵의 **관문 1** 그대로다. 시험 하나하나를 관문과 7장에서 짝지었다. 유호님 손은 화면 시안 고르기 한 번과 [11장의 한 번에 여쭐 것](#11-유호님께-한-번에-여쭐-것)뿐이다.

## 2. 사용자 흐름

### 2.1 처음 시작

| 차례 | 사람이 하는 것 | 전체 누름 | 앱 안 누름 |
|---|---|---|---|
| 1 | 내려받은 설치 파일 열기 | 1 | |
| 2 | SmartScreen 「추가 정보 → 실행」(서명 전 시범판) | 2 | |
| 3 | 관리자 확인 「예」 — 설치 창 없이 설치하고 끝나면 앱을 연다 | 1 | |
| 4 | 「Google로 시작」 | 1 | 1 |
| 5 | 브라우저에서 계정 고르기 · 「계속」(로그인돼 있지 않으면 입력이 더해진다) | 2 | |
| 6 | 「보호 시작」 — 보호할 폴더(문서 · 바탕화면 · 사진 + 진단이 찾은 작업 폴더 제안)와 예상 용량이 보이고, 이 단추가 곧 범위 동의다 | 1 | 1 |
| | 합 | 8 | 2 |

- SmartScreen 두 번은 OS 코드 서명(3단계) 뒤 빠진다. Smart App Control이 켜진 PC는 설치가 아예 막히므로 이 표에 넣지 않고 2단계에서 따로 센다.
- 보호 시작 뒤 앱이 혼자 하는 것: 개통(서버) → 저장소 만들기 → 봉투 보관 · 다시 받아 확인 → 예약 작업 등록 → 첫 백업. 첫 백업이 도는 동안 「창을 닫아도 됩니다」 한 줄, 끝나면 알림 한 번.
- 두 번째 복구 수단(복구 코드)은 첫 화면에 넣지 않고 첫 주 안에 한 번 권한다(로드맵 3장). 첫 복구 수단은 자동으로 만들어지는 봉투다.
- 첫 화면에 「Google 2단계 인증을 켜 두세요」 한 줄(Google 계정에 들어갈 수 있는 사람은 백업도 읽을 수 있다 — 로드맵 6장).

### 2.2 평소

앱을 열 일이 없다. 알림은 「문제 + 할 일 하나」일 때만 뜨고, 같은 문제는 하루 한 번이다.

| 알림 | 할 일 하나 |
|---|---|
| 첫 백업이 끝남(한 번) | 없음 — 「이제 매시간 저절로 지킵니다」 |
| 사흘 넘게 백업을 못 함 | 원인별(회선 · 용량 · 재로그인). PC가 꺼져 있으면 서버가 메일로 |
| 잠긴 파일 때문에 백업을 못 끝냄(도우미 없는 계정) | 「그 프로그램을 닫으면 다음 회차에 끝납니다」 |
| 되살리기 증명 실패 | 「확인하기」 — 그날 |
| 많은 파일이 한꺼번에 지워지거나 바뀜 | 「확인하기」 — 확인 전까지 이전 판을 지우지 않는다 |
| 새 기기가 이 계정에 연결됨 | 「내가 한 게 아니면 끊기」 |
| 용량 상한에 가까움 · 넘음 | 「폴더 줄이기」 |
| Google 봉투 재확인 실패 | 「다시 로그인」 |
| 업데이트 준비됨 | 「설치」(관리자 확인이 뜬다 — 4.10) |

### 2.3 새 PC로 옮겨 오기

설치 → 「Google로 시작」 → 「이 계정에 백업이 있습니다」 → 「이 PC로 옮겨 오기」 → 되살릴 자리 고르기(원래 자리 / OneDrive 밖 새 폴더, 용량과 함께) → 시작 → 진행(내려받는 기다림은 따로 「약 N분」) → 해시 대조 → 결과(되살린 수 · 이미 있던 같은 파일 수 · 「(복구본)」으로 나란히 둔 수) → 다시 깔 프로그램 목록(winget 명령) · 다시 로그인할 곳 체크리스트 → 「옛 PC 연결 끊기」(기본 예) → 이 PC가 같은 저장소에 이어서 백업한다.

### 2.4 분실 · 탈취

- 다른 PC의 앱 → Google 로그인 → 설정 서랍 「내 기기」 → 「분실 신고」.
- 휴대폰만 있을 때: 기기를 연결할 때 받은 메일의 「이 기기 끊기」 링크 → 확인 쪽에서 한 번 더 누른다.
- 끊으면: 그 기기의 쓰기 출입증을 지우고, 손님 읽기 출입증을 새로 만들어 봉투를 바꾸고, 「복구 코드를 새로 받아 두세요」를 남은 기기에 알린다.

### 2.5 사고 뒤 되돌리기

설정 서랍 「사고가 났을 때 되돌리기」 → 시각 고르기 → 서버가 먼저 세어 보여 준다(되살릴 것 · 되돌릴 것 · 숨길 것) → 「되돌리기」 → 서버가 실행 → 앱이 저장소를 다시 점검하고 최신 완료본을 다시 고른다 → 결과.

## 3. 구조와 권한 경계

| 부분 | 하는 일 | 권한 | 떠 있는 때 |
|---|---|---|---|
| 화면 앱 `WorkBackup.exe`(Tauri) | 창, (설정에서 켤 때만) 트레이 | 사용자 보통 권한 | 사용자가 열었을 때만. 창을 닫으면 웹 화면을 내리고, 하던 작업이 끝나면 프로세스도 끝난다 |
| 회차 실행기 `WorkBackupRun.exe --run <계기>` | 백업 · 점검 · 정리 · 증명 · 봉투 재확인 · 측정 보내기 · 알림 | 사용자 보통 권한(작업 스케줄러, 로그인한 동안) | 회차 동안만 |
| 잠긴 파일 도우미 `WorkBackupRun.exe --vss-helper` | 종료 코드 3 회차만 VSS로 다시 읽기 | 같은 사용자의 관리자 권한(관리자 계정일 때만) | 그 회차 동안만 |
| 엔진(Node 워커 + restic 0.19.1) | 지금 엔진 + 1단계 고침 | 띄운 쪽의 권한 | 회차 · 화면 작업 동안 |
| 개통 서버 | 초대 명단 · 출입증 발급과 끊기 · 되살리기 도구 · 회차 기록 · 메일 · 매일 대조 | 회사 서버 안 따로 둔 컨테이너 · 실행 사용자 | 늘 |
| B2 손님용 계정 · 버킷 | 손님별 접두사 저장소 | — | — |
| Google 앱 전용 공간 | 봉투(복구 암호 + 읽기 출입증) | 손님 Google 계정 | — |

권한 경계:

- **기기 쓰기 출입증**(그 PC, DPAPI): 자기 손님 접두사 안의 목록 · 읽기 · 올리기 · 숨기기. 영구 삭제 · 출입증 만들기 · 버킷 설정은 못 한다.
- **손님 읽기 출입증**(봉투 · 복구 코드): 목록 · 읽기.
- **서버 운영 출입증**(개통 서버만): 출입증 만들기(B2 문서상 계정 전체 권한과 같다)와 영구 삭제. 복구 암호는 서버에 없으므로 서버는 백업 내용을 읽지 못한다.
- **도우미**: 관리자 권한이지만 Program Files의 고정 실행 파일만 쓰고, 정해진 폴더 규칙 안에서만 읽는다(4.2).

## 4. 항목별 설계

### 4.1 한 줄기 · 엔진 갈래 · 창 닫기 (로드맵 1)

- **Electron 0.5.0 동결.** `experiences/solo-backup/`은 고치지 않는다. 그런데 지금 Rust 판은 엔진을 `../solo-backup/src`에서 가져온다(`scripts/stage-resources.cjs`). 1단계 고침을 넣으려면 엔진을 `experiences/solo-backup-rust/engine/`으로 **갈라 온다**: 첫 커밋은 `src` · `tests` · `package.json` · lock · 고지문을 바이트 그대로 복사하고 두 쪽 시험 결과가 같은지 보인다(T1). 고침은 그 위에만 한다. 화면 원천도 같은 까닭으로 `experiences/solo-backup-rust/ui/`로 옮긴다(지금은 `stage-ui.cjs`가 0.5.0 화면을 바이트째 복사한다).
- **새 상태 폴더** `%APPDATA%\SynkWorkBackup`. 0.5.0(`SoloWorkBackup`) · 시험판(`SoloWorkBackupRustBeta`)과 따로이며 그 둘을 읽지도 쓰지도 않는다. Windows Run 시작 등록은 쓰지 않는다(작업 스케줄러로 바뀐다). 시험판의 옛 Run 등록이 있으면 건드리지 않는다.
- 판 이름 0.7.0, 식별자 `im.synk.workbackup`.
- **창 닫기:** 지금은 자동 백업이 켜져 있으면 창을 숨기고 프로세스가 남는다. 바꾼다 — 닫으면 웹 화면을 없애고(WebView2 프로세스 0), 하던 작업이 있으면 화면 없이 마친 뒤 끝난다. 화면 앱 안의 30초 타이머 예약(`startScheduler`)은 끈다. 예약은 작업 스케줄러 하나다.
- **트레이(설정에서 켤 때만):** Rust 프로세스와 아이콘만 남기고 워커는 내린다(목표 30MB 이하). 아이콘을 누르면 워커와 창을 다시 띄운다.

### 4.2 앱과 따로 도는 예약 (로드맵 2)

#### 회차 작업

- 사용자마다 작업 하나: `\SYNK 업무 백업\회차 - <사용자 이름>`. 보안 주체는 그 사용자, 「사용자가 로그온한 경우에만 실행」(InteractiveToken), 가장 낮은 권한 수준.
- 계기 셋: 로그온(2분 늦춤), 매시간(무기한 반복), 깨어남(System 로그 `Microsoft-Windows-Power-Troubleshooter` 이벤트 1, 2분 늦춤).
- 설정: 배터리에서도 시작 · 배터리로 바뀌어도 멈추지 않음, 놓친 회차는 가능해지면 바로(StartWhenAvailable), 겹치면 새 것을 버림(IgnoreNew — 「앞 회차가 돌고 있어 건너뜀」은 그 시간이 앞 회차 기록에 덮여 있는 것으로 따로 센다), 우선순위 7(보통 아래), 최대 12시간.
- 동작: 설치 폴더 절대 경로의 `WorkBackupRun.exe --run hourly|logon|wake`.
- 만드는 때: 보호 시작 때 앱(보통 권한)이 작업 스케줄러 COM API로 만든다. 폴더 `\SYNK 업무 백업\`은 설치기(관리자)가 만들고 보통 사용자가 그 안에 자기 작업을 만들 수 있게 폴더 권한을 준다. 이것이 안 되면 뿌리 폴더에 사용자 이름을 붙인 작업으로 한다 — 이벤트 계기를 보통 권한으로 만들 수 있는지와 함께 실측한다(T2).

#### 회차가 하는 일

1. 상태 잠금(`native.lock`)을 잡는다. 화면 앱이 잡고 있으면 이름 있는 이벤트(`Local\SynkWorkBackup-tick-<해시>`)로 화면 앱에 회차를 넘기고 「넘김」으로 기록한 뒤 끝난다. 화면 앱이 그 회차를 엔진에서 돌린다.
2. 쉼 판단: 배터리로 돌고 30% 아래 · 절전 모드 · 종량 회선(Windows 연결 비용이 「무제한」이 아님)이면 클라우드 올리기 · 구조 점검 · 증명을 쉬고 쉼 사유를 기록한다. 직접 누른 「지금 백업」은 예외다.
3. 할 때가 됐나: 마지막 시도가 55분 안이면 「아직」으로 바로 끝난다. 일시정지 · 시계 이상은 지금 규칙(`protection.cjs`) 그대로다.
4. 엔진 백업(지금 `backupBody` + 1단계 고침).
5. 종료 코드 3(일부 못 읽음)이고 restic 오류가 공유 위반(다른 프로세스가 사용 중)이면 도우미를 부른다(아래).
6. 날마다 할 일: 캐시 없는 구조 점검(하루 한 번 — 회차마다는 `check --with-cache`로 내려받는 양을 줄인다), 증명(매주), 봉투 재확인(하루), 측정 보내기.
7. 회차 기록 한 줄 → 알림 판단 → 끝.

실행기 · 워커 · restic은 모두 「보통 아래」 우선순위로 돈다. I/O 우선순위를 더 낮출지는 처음 백업 속도 기준(70%)을 재고 정한다.

#### 회차 기록

`runs.jsonl` 한 줄에 계기, 시작 · 끝, 결과(ok · partial · skipped · failed · delegated · not-due), 쉼 사유, 종료 코드, 새로 · 바뀐 · 그대로인 파일 수, 더한 바이트, 처리한 바이트, 워커 준비까지 ms, restic 시작까지 ms, 작업 객체의 최대 메모리(`PeakJobMemoryUsed`), 측정 판에서는 주고받은 바이트를 적는다. 1MB마다 돌려 쓴다. 파일 이름 · 경로는 넣지 않는다.

주고받은 바이트는 restic에 `HTTPS_PROXY`로 실행기 안의 작은 CONNECT 프록시를 주고 양쪽 바이트만 세어 잰다(TLS는 끝까지 그대로). 측정 판 설정에서만 켠다.

「회차 빠짐」은 PC가 깨어 있고 사용자가 로그인한 시간마다 회차 기록이 하나 이상 있는지로 센다. 잠든 시간은 System 로그(Kernel-Power 42 잠들기, Power-Troubleshooter 1 깨어남)로 빼고, 앞 회차가 돌고 있던 시간은 따로 센다. Task Scheduler 운영 로그는 켜지 않는다(시스템 설정 변경).

#### 알림

- Windows 알림(토스트). 앱 식별자(AUMID)는 설치기가 시작 메뉴 바로 가기에 붙인다.
- 누르면 `synk-workbackup:open?topic=<정해진 낱말>`로 화면 앱이 그 화면을 연다. 이 주소는 화면만 열고 아무 동작도 하지 않는다(웹 페이지가 불러도 결과가 같다).
- 같은 문제는 하루 한 번(`notify.json`). 해결되면 그 문제의 기록을 지운다.
- 실측: 보통 권한 회차의 알림이 실제로 떴는지는 `ToastNotificationManager.History`로 우리 앱 알림이 알림 센터에 있는지 읽어 센다. 화면 조작은 하지 않는다(T4).

#### 잠긴 파일 도우미 (관리자 VSS)

- **언제:** 회차가 종료 코드 3으로 끝났고 restic 오류가 공유 위반일 때만.
- **무엇:** 같은 프로필 백업을 `restic backup --use-fs-snapshot`으로 한 번 더 하고, 그 판이 완전하면 완료본으로 승격한다.
- **등록:** 설치기(관리자)가 설치 끝에 `WorkBackupRun.exe --register-helper`를 부른다. 관리자 확인을 한 계정이 지금 로그인한 계정과 같을 때만(관리자 계정 사용자) 그 사용자의 도우미 작업 `\SYNK 업무 백업\잠긴 파일 도우미 - <사용자 이름>`을 「가장 높은 수준의 권한으로 실행」 · 계기 없이(요청 때만) 만든다. 작업 보안 설명자는 관리자 · SYSTEM 전체, 그 사용자는 읽기 · 실행만이다. 그래서 그 사용자의 보통 권한 회차는 이 작업을 실행만 할 수 있고 바꾸지 못한다. 동작은 고정 인자(`--vss-helper`)뿐이고 `$(Arg)` 치환을 쓰지 않는다.
- 다른 사람이 관리자 암호를 넣어 준 표준 사용자에게는 도우미가 없다. 화면에 「이 계정은 표준 사용자라, 켜진 프로그램이 잡고 있는 파일은 그 프로그램을 닫았을 때 백업됩니다」라고 적는다.
- **도우미가 시작할 때 확인한다.** 하나라도 어긋나면 백업하지 않고 까닭을 기록한다.
  1. 자기 실행 파일 · `resources` 폴더와 그 위 폴더(Program Files까지)의 소유자가 관리자 · SYSTEM · TrustedInstaller이고, 그 밖의 누구에게도 쓰기 · 고치기 · 지우기 · 권한 바꾸기 · 소유자 바꾸기가 없다. 보통 사용자가 고칠 수 있으면 권한 상승 통로가 되기 때문이다.
  2. 리소스 목록 해시(지금 `verify_resources`).
  3. 경로를 환경 변수에서 읽지 않는다. 실행 파일 위치는 `GetModuleFileName`, Windows · 사용자 폴더는 API로 얻는다. 워커 · restic의 환경은 빈 데서 새로 만든다. 작업 스케줄러는 사용자 환경 변수를 물려주므로, 예전 SilentCleanup 우회처럼 `%windir%`를 바꿔치기하는 길을 막는다.
  4. 요청 파일(`vss-request.json`, 10분 안)과 프로필 설정을 **자료로만** 읽는다. 실행할 경로는 받지 않는다.
  5. **폴더 규칙.** 백업할 폴더마다 고정 로컬 NTFS이고, 경로 어디에도 연결점(junction · symlink)이 없고, 드라이브 뿌리가 아니고, Windows · Program Files · ProgramData · 다른 사용자 폴더 · 휴지통 · System Volume Information 아래가 아니고, 그 사용자 프로필 안이거나 폴더 소유자가 그 사용자여야 한다. 규칙 밖 폴더가 하나라도 있으면 도우미는 하지 않는다. 관리자 권한 restic은 파일 접근 권한을 넘어 읽을 수 있어서, 사용자가 원래 못 읽는 파일을 백업으로 빼내는 통로를 막으려는 것이다(설계 검토 Q4).
- 도우미가 쓴 파일(설정 · 캐시 · 기록)을 다음 보통 권한 회차가 다시 쓸 수 있는지는 실측한다(T5).
- **도우미가 없거나 실패한 부분 백업(종료 코드 3)은 지금처럼 완료본으로 올리지 않는다.** 이전 완료본을 그대로 둔다. 못 읽은 파일이 빠진 판을 「최신」으로 올리면 그 파일의 예전 판이 24시간 정리에서 사라질 수 있기 때문이다. 대신 알림과 서버의 사흘 메일이 잡는다(설계 검토 Q3).

#### 컴퓨터 전체 설치

- Tauri 묶음의 NSIS 설치기를 `perMachine`으로 만든다: `C:\Program Files\SYNK WorkBackup\`. 설치 창 쪽은 빼고(바로 설치 → 앱 열기) 관리자 확인은 한 번이다.
- 설치기가 하는 일: 파일 복사, 시작 메뉴 바로 가기(AUMID 포함), `synk-workbackup:` 주소 처리기(HKLM, 화면 열기만), 작업 폴더 만들기와 그 권한, 도우미 등록(위 조건).
- 지우기: 작업 · 바로 가기 · 주소 처리기를 지운다. 사용자 상태와 클라우드 백업은 지우지 않는다.

### 4.3 Node 워커 — 재고 나서 옮긴다 (로드맵 3)

- 4.2를 만든 뒤 같은 합성 자료(D1, 7장)로 잰다: 회차 시작(작업 시작 → restic 시작), 회차 최대 메모리(작업 객체 Peak), 설치 크기.
- 비교 기준은 같은 회차를 Rust가 restic을 바로 부르는 시험 실행기(백업 · 구조 점검만)로 돌린 값이다.
- 옮기는 문턱: 회차 시작이 3초를 넘거나, 회차 메모리가 Rust만 쓸 때보다 100MB 넘게 크면 회차가 쓰는 부분(예약 · 백업 · 점검 · 정리 · 증명)부터 Rust로 옮긴다. 옮길 때는 엔진 시험 전부를 Rust 시험으로 옮겨 같은 결과를 내게 한다. 복구 · 검색은 다음 단계다.
- 문턱 안이면 1단계에서는 옮기지 않는다(지금 설치 크기 143MB도 150MB 안이다). 판단과 숫자를 QA에 남긴다.
- 실행기는 워커를 화면 앱과 같은 통신(표준 입출력 프레임)으로 부른다. 옮기게 되면 워커 자리에 Rust 엔진을 끼우면 된다.

### 4.4 사고 대비 안전망 (로드맵 4)

#### 출입증 권한

| 출입증 | 가진 곳 | 범위 | 권한 |
|---|---|---|---|
| 기기 쓰기 | 그 PC(DPAPI) | 버킷 + `c/<손님 번호>/` | listBuckets · listFiles · readFiles · writeFiles. deleteFiles · shareFiles · 출입증 · 버킷 권한 없음 |
| 손님 읽기 | 봉투 · 복구 코드 | 같음 | listBuckets · listFiles · readFiles |
| 서버 운영 | 개통 서버만 | 계정 | writeKeys · listKeys · deleteKeys + 손님 버킷의 listFiles · readFiles · writeFiles · deleteFiles |
| CI 쓰기 · 읽기 | Actions 비밀값 | 시험 버킷 `ci/` | 기기 쓰기 · 손님 읽기와 같은 꼴 |

B2 문서(11-12 확인): writeFiles에 숨기기(`b2_hide_file`)가 들어 있고, deleteFiles는 판 하나를 영구 삭제하는 권한이다. 접두사 출입증의 목록 읽기는 요청에 같은 접두사를 넣어야 한다. restic 0.15 변경 기록은 삭제 권한이 없는 B2 출입증이면 b2 통로와 S3 통로 모두 지우는 대신 숨긴다고 적는다. B2의 S3 판 지정 없는 삭제는 숨김 표시를 만든다(S3 Delete Object 문서). 그 요청에 어떤 권한이 필요한지는 문서에 없어 11-12 시험 버킷에서 쟀다(M1~M3, 숫자는 [QA](QA.md#1단계-시험-버킷-실측-m1m7--2026-11-12)): listBuckets가 없으면 버킷 확인이 403이고 restic이 저장소 설정 파일조차 못 읽어 만들 수 없다(그래서 위 둘 모두 listBuckets를 둔다). 삭제 권한 없는 출입증의 판 지정 없는 삭제는 204 + 숨김 표시로 끝나고, 판 지정 삭제는 403이다. forget · prune도 그 출입증으로 끝까지 돌며 영구 삭제는 0건이었다. 그래서 S3 통로 그대로 안전망이 된다.

#### 수명 규칙 (손님 버킷)

- 접두사 ""(버킷 전체): 숨긴 지 30일 뒤 삭제(11-12 유호님 「30일로 넣기」), 올린 뒤 숨기기는 없음, 끝나지 않은 큰 파일은 1일 뒤 취소.
- B2 수명 규칙은 하루 한 번 돈다. 새 판이 올라와 덮인 옛 판도 「숨김」으로 세어 30일 뒤 지운다(공식 문서). 그래서 덮어쓰기 공격도 30일 안에는 되돌릴 수 있다.
- 비용: 숨긴 판은 30일 동안 저장비가 든다. 내부 24시간 정리로 날마다 숨겨지는 양(변경량)이 30일 쌓인다. 72시간 시험과 합성 자료로 「원본 대비 늘어나는 비율」을 재서 QA에 적는다(M5).

#### 되살리기 도구 — 「이 시각으로 되돌리기」

서버가 그 손님 접두사 안에서만 한다(B2 기본 API).

1. 접두사의 모든 판을 읽는다(`b2_list_file_versions`).
2. 이름마다 「T 시각의 상태」(T 전 마지막 판이 올리기면 그 판, 숨김이거나 없으면 없음)와 「지금 상태」를 견준다.
3. 차이에 따라 처리한다.
   - T에 있었는데 지금 숨겨져 있고 T 뒤 판이 숨김 표시뿐이면 → T 뒤 숨김 표시를 지운다. 자료는 그대로이고 표시만 걷힌다.
   - T에 있었는데 T 뒤에 같은 이름으로 다른 내용이 올라왔으면(덮어쓰기) → T의 판을 서버 안에서 복사해 새 최신 판으로 만든다(`b2_copy_file`). 덮어쓴 판은 옛 판이 되어 30일 뒤 지워진다.
   - T에 없었는데 지금 있으면(T 뒤에 생김) → 숨긴다(되돌릴 수 있다).
   - 그 밖(같음 · T에도 지금도 없음)은 그대로 둔다.
4. 먼저 세기만 하는 미리 보기를 손님 앱에 보이고, 손님이 누르면 실행한다. 한 일은 서버 기록에 남겨 되돌릴 수 있게 한다.
5. 끝나면 앱이 저장소를 다시 열어 점검(`check`)하고 최신 완료본을 다시 고른다.

- T가 30일보다 오래면 거절한다. 그 전 것은 이미 지워졌을 수 있다.
- 대표가 손으로 하지 않는다. 손님 앱 → 서버 API다(설계 검토 Q5).

#### 대량 삭제 · 변경 멈춤 (조사 문서 「다음 3」)

- 정리(forget · prune) 전에 새 완료본과 바로 앞 완료본을 `restic diff --json`으로 견준다.
- 처음 문턱(시험으로 맞춘다): 지워진 파일이 앞 판의 30% 이상이면서 200개 이상, 또는 내용이 바뀐 파일이 50% 이상이면서 200개 이상, 또는 지워진 바이트가 30% 이상이면서 1GB 이상.
- 걸리면 정리를 멈추고 이전 판을 둔다(지금 `probeHold`와 같은 꼴). 알림 「많은 파일이 한꺼번에 지워지거나 바뀌었습니다. 확인하기 전까지 이전 판을 지우지 않습니다」 → 화면에서 「내가 한 일이 맞음」 · 「바뀌기 전 판으로 되살리기」.
- 이름 바꾸기 · 폴더 옮기기는 diff에 지움과 더함으로 나와 잘못 걸릴 수 있다. 시험 자료로 문턱을 맞추고(T17), 「랜섬웨어 감지」라고 부르지 않는다(설계 검토 Q8).

#### 시험 버킷에서 먼저 확인할 것 (B2 무료 10GB 안)

로드맵이 정한 셋(M1~M3)에 되살리기 도구 시제품과 비용 · 연습 준비를 더했다. 모두 시험 버킷의 `t/` 아래 1GB 안이다. 시험 버킷 · 출입증 · 수명 규칙을 만드는 일은 [11장](#11-유호님께-한-번에-여쭐-것) 승인 뒤에 한다.

| | 확인 | 방법 | 결과로 바꿀 것 |
|---|---|---|---|
| M1 | 접두사 출입증으로 버킷 확인과 저장소 만들기 | 출입증 A(listBuckets 있음) · B(없음)로 S3 HeadBucket, `restic init`(S3 통로) · backup · snapshots · check | `b2.cjs`의 사전 확인(지금 HEAD bucket, 문구는 버킷 전체 권한을 요구) · 출입증 권한표 |
| M2 | S3 통로에서 삭제 권한 없는 출입증의 삭제 | A로 판 지정 없는 DeleteObject(숨김 표시가 생기나, 거절되나) · 판 지정 DeleteObject(거절돼야 한다) · 같은 이름 다시 올리기(옛 판이 남나) | 안전망이 S3 통로로 되는지, 안 되면 restic b2 통로로 |
| M3 | 정리가 그 출입증으로 끝까지 도는가 | A로 백업 둘 → forget · prune(`--max-repack-size 0`) → check, 잠금 파일 정리, 서버 출입증으로 숨김 표시 확인 | 엔진 정리 규칙 · 잠금 처리 |
| M4 | 되살리기 도구 시제품 | M3 뒤 「공격」(전부 forget · prune · 직접 삭제 · pack 덮어쓰기) → 도구로 T 되돌림 → snapshots · restore 해시 | 도구 알고리즘 |
| M5 | 숨긴 양 | 위 과정의 보이는 바이트 · 숨긴 바이트 | 안전망 비용 추정 |
| M6 | 날짜 지난 판 | `restic backup --time`으로 만든 판이 정리 규칙에서 어떻게 보이는가 | 출입증 탈취 연습(T9) 준비 |
| M7 | 지운 출입증 | 출입증을 지운 뒤 목록 · 읽기 거부 | 분실 연습(T10) 준비 |

### 4.5 Google 로그인 하나로 시작 — 시범 규모 개통 (로드맵 5)

#### 흐름

앱 Google 로그인(지금의 PKCE · 데스크톱 클라이언트, 범위 `openid email drive.appdata`) → ID 토큰을 개통 서버에 보낸다 → 서버가 Google 공개 열쇠로 서명 · 대상(우리 클라이언트) · 발급자 · `email_verified`를 확인한다 → 초대 명단에 있으면 세션을 준다 → 「기기 개통」: 손님 자리(처음이면 손님 번호와 접두사 `c/<무작위 16자>/`)와 기기 쓰기 출입증 · 손님 읽기 출입증을 만들어 한 번 돌려준다 → 앱이 저장소를 만들고(`restic init`), 복구 암호와 읽기 출입증을 봉투에 넣고 다시 내려받아 확인한다 → 예약 등록 → 첫 백업.

#### 제한

- 초대 명단(시범자 메일)에만 개통한다. 명단은 서버 관리 명령으로 넣는다. 메일 주소는 저장소에 적지 않는다.
- 손님당 살아 있는 기기 3, 출입증 만들기 하루 5번, 요청 속도 제한.
- 앱: 올리기 전에 원본 크기로 상한(시범 100GB)을 막는다. 첫 백업 전에는 폴더 크기를 훑고, 그 뒤에는 직전 판의 처리 바이트로 판단한다.
- 서버: 접두사별 저장량(보이는 것 · 숨긴 것)을 매일 센다. 상한의 1.5배를 넘으면 그 손님 앱에 「용량 초과」를 알리고 올리기를 멈춘다. 출입증은 끊지 않는다.
- B2 계정에는 지출 상한(저장 · 내려받기 · 거래)을 건다(11장).

#### 계정 분리와 운영 탈취 대비

- 손님 자료는 시험 · 0.5.0과 **다른 B2 계정**에 둔다(가입은 유호님).
- 개통 서버는 회사 서버 안 **따로 둔 컨테이너와 실행 사용자**로 돈다. 자기 볼륨(SQLite)과 자기 비밀값 파일만 붙는다. 다른 회사 서비스 컨테이너에는 B2 운영 출입증이 없다. 회사 Caddy가 `/backup-api/`만 이 컨테이너로 넘긴다(지금 Caddy는 회사 앱 하나로만 넘긴다 — 길 하나를 더한다).
- 매일 출입증 목록을 대조한다: 서버가 만들지 않은 출입증, 삭제 · 출입증 · 버킷 권한이 있는 출입증(서버 자기 것 제외), 접두사 없는 손님 출입증이 보이면 운영자에게 메일을 보낸다.
- GitHub Actions 비밀값에는 시험 버킷의 쓰기(삭제 없음) · 읽기 출입증만 넣는다. 운영 출입증은 넣지 않는다.
- 서버까지 털렸을 때 쓸 사본(다른 계정 복제 또는 객체 잠금 사본)은 3단계 전에 정한다. 1단계에서는 후보와 값만 9장에 적는다(Q10).

#### 봉투 v3

복구 암호 + 그 손님 접두사의 읽기 출입증 + 저장소 위치 · 번호다. 서버가 멈추거나 사업을 접어도 새 PC 복구와 「통째로 받기」가 된다. 서버는 백업을 다시 시작할 때(기기 쓰기 출입증)만 필요하다. 올린 뒤 다시 받아 내용 · 계정 · 해시를 대조하고 하루 한 번 재확인하는 지금 방식을 그대로 쓴다.

#### Google 프로젝트

손님을 받기 전에 백업 전용 프로젝트로 나누고 운영 게시로 바꾼다. 「시험 중」이면 시험 사용자 100명 등록제이고 갱신 토큰이 7일에 끊겨 하루 재확인이 멈춘다. `drive.appdata`는 민감 범위 검증 대상이 아니다. 0.3.0 때 계정의 프로젝트 수 한도로 새 프로젝트를 못 만들었으니, 안 쓰는 프로젝트를 정리하거나 한도를 요청해야 할 수 있다(11장). 앱 전용 공간은 프로젝트마다 따로라 새 봉투가 0.5.0 봉투와 섞이지 않는다.

### 4.6 새 PC로 옮겨 오기 v1 (로드맵 6)

#### 기존 경계를 바꾸는 일 — 따로 짚는다

지금(0.5.0 · Rust 시험판)은 원래 작업 폴더와 백업 저장소를 복구 대상으로 고를 수 없고, 늘 새 하위 폴더(`01-폴더이름`)에 쓴다. 그 덕에 복구가 지금 쓰는 파일을 덮을 일이 없었다.

1단계에서 바꾸는 것: **「옮겨 오기」 흐름에서만** 원래 자리에 쓴다. 지키는 것은 이렇다.

- 덮어쓰지 않는다. 그 자리에 파일이 있으면 내용(SHA-256)이 같을 때 「이미 있음」으로 세고 건너뛰고, 다르면 `이름 (복구본).확장자`(있으면 `(복구본 2)` …)로 나란히 둔다. 폴더는 만들기만 한다.
- 쓰기는 임시 이름에 쓴 뒤 덮어쓰기 없는 이름 바꾸기로 한다. 끝나면 쓴 파일마다 SHA-256을 대조한다.
- 쓴 파일 목록(장부)을 상태 폴더에 남긴다. 앱은 원래 자리의 파일을 지우는 기능을 갖지 않는다.
- 평소 「파일 되살리기」(골라 복구 · 전체 복구)는 지금처럼 새 폴더로만 쓴다.
- 백업 중인 기기 자신에서는 이 흐름을 열지 않는다(같은 기기 번호면 「옮겨 오기」 대신 「되살리기」).

이 경계 변경은 설계 검토 Q1로 따로 올린다.

#### 자리 맞추기

- 백업할 때마다 그 PC의 알려진 폴더 위치(문서 · 바탕화면 · 사진 · 음악 · 동영상 · 다운로드, OneDrive로 옮겨졌는지)를 작은 JSON으로 함께 넣는다(`새-PC-준비.json`과 같은 길).
- 새 PC에서: 옛 알려진 폴더 아래 경로 → 새 PC의 같은 알려진 폴더(`SHGetKnownFolderPath` — OneDrive로 옮겨졌으면 그 자리). 옛 사용자 프로필 아래 다른 경로 → 새 프로필 아래 같은 상대 경로. 그 밖(D 드라이브 프로젝트 폴더 등) → 같은 드라이브가 있으면 같은 경로, 없으면 사용자가 고른다.
- OneDrive: 알려진 폴더가 OneDrive 안이면 되살릴 용량과 함께 알리고 「OneDrive 밖 새 폴더」를 나란히 내놓는다. OneDrive 남은 공간은 로컬에서 읽을 수 없다 — 11-12 이 PC에서 OneDrive 계정 레지스트리와 설정 파일을 읽어 보니 용량 알림을 띄운 시각만 있고 남은 · 쓴 용량 숫자는 없었다. 그래서 「OneDrive 무료 공간(5GB)을 넘으면 동기화가 멈출 수 있습니다」로 적는다(로드맵 문구와 다르다 — Q2).
- 기다림: 내려받을 양 ÷ 지난 회차에서 잰 회선 속도로 「약 N분」을 따로 보인다(50GB · 100Mbps면 이론상 약 67분).

#### 다시 깔 것 · 다시 로그인할 곳

- 진단(inventory)이 찾은 프로그램 목록을 보여 주고, winget에 있는 것은 이름 · 명령까지 보인다. 설치는 하지 않는다(4단계).
- 다시 로그인할 곳은 진단이 찾은 앱 종류에서 만든 고정 체크리스트다(브라우저 · 메신저 · 클라우드 드라이브 · AI 도구 · 공동인증서 안내). 설문을 하면 그 결과로 2단계 전에 고친다.

#### 옛 PC 끊기와 저장소 잇기

- 저장소는 손님당 하나이고, restic 호스트 이름을 **기기 번호**로 바꾼다(지금은 보관함 번호). 새 PC는 같은 저장소에 이어서 백업한다. 되살린 파일과 내용이 같아 첫 백업에 올라갈 것이 거의 없다(중복 제거).
- 옮겨 오기가 끝나고 대조가 통과하면 「옛 PC 연결 끊기」(기본 예) → 서버가 옛 기기의 쓰기 출입증을 지운다.
- **정리 규칙이 바뀐다.** 지금 `retain`은 자기 호스트 판만 정리한다. 새 규칙: 자기 기기 판은 지금처럼(최신 완료본 + 24시간), 끊긴 기기 판은 끊긴 지 30일 뒤 새 기기가 정리한다. 그동안은 옛 PC의 마지막 판으로 돌아갈 수 있다. 엔진 정리 규칙 변경이라 GPT 2차 검수를 받는다(Q9).

### 4.7 되살리기 증명 v2 (로드맵 7)

- 매주 최신 완료본에서 백업한 폴더마다 무작위 파일을 고른다(합 64MiB 안, 폴더마다 적어도 하나, 큰 파일은 건너뜀).
- `restic dump`로 받아 메모리에서 SHA-256만 계산한다. 평문을 디스크에 쓰지 않는다(지금 표본과 같은 원칙).
- 원본 대조: 원본 파일의 크기와 수정 시각이 그 판의 기록과 같으면(그 뒤 안 바뀜) 원본을 읽어 SHA-256을 견준다. 바뀐 파일은 「원본이 바뀌어 대조 못 함」으로 따로 센다.
- 결과: 고른 수 · 대조한 수 · 일치한 수 · 바이트. 하나라도 어긋나면 그날 알리고 정리를 보류한다(지금 `probeHold`).
- 화면 첫 줄의 「증명 날짜」는 마지막 통과 날짜다.
- 일부러 깨뜨린 저장소 시험: 시험 저장소의 pack 하나를 바꿔치기해 증명이 먼저 찾는지 본다(T15, 「손님보다 먼저 찾아낸 비율」의 시작 값).

### 4.8 분실 · 탈취 (로드맵 8)

- **두 번째 복구 수단 「복구 코드」:** 저장소 위치 · 번호, 복구 암호, 손님 읽기 출입증을 담은 한 장이다. 인쇄용 쪽(브라우저로 열어 인쇄 · PDF 저장)과 USB에 담는 파일 둘로 준다. 첫 주 안에 한 번 권하고 건너뛸 수 있다. 새 PC의 「복구 코드로 되살리기」에서 파일을 열거나 글을 붙여 넣으면 Google 없이 된다.
- **분실 신고:** 다른 PC의 앱(「내 기기」) 또는 기기 연결 메일의 「이 기기 끊기」 링크. 링크는 확인 쪽을 열고 거기서 한 번 더 눌러야 실행된다(메일 검사기가 링크를 미리 열어도 끊기지 않게). 끊으면 서버가 그 기기 쓰기 출입증을 지우고, 손님 읽기 출입증을 새로 만들어 남은 기기가 봉투를 바꾸게 하고, 옛 읽기 출입증을 지운다. 남은 기기에 「복구 코드를 새로 받아 두세요」를 알린다.
- **새 기기 개통 · (3단계) 해지 요청:** 기존 기기에 알리고(다음 회차 알림) 메일을 보낸다. 해지는 재확인 없이 지우지 않는다. 1단계에는 3단계가 쓸 틀만 둔다.

### 4.9 시범 측정 통로 (로드맵 9)

- **모으는 것:** 회차 기록(5.5의 칸), 알림 표시 · 누름(종류 · 시각), 설치 단계(단계 · 걸린 시간 · 성공). 파일 이름 · 경로 · 폴더 이름 · 내용은 보내지 않는다.
- **보내는 때:** 회차 끝에 기기 토큰으로 보낸다. 못 보내면 7일까지 모았다가 보낸다.
- **시범자에게:** 첫 화면 아래 한 줄 「시범 동안 백업 결과 숫자(파일 이름 없이)를 SYNK로 보냅니다」.
- **도움 요청:** 앱 안 단추 → 보낼 내용(판 · Windows 판 · 최근 회차 50줄 · 오류 번호 · 경로 없는 설정 요약)을 먼저 보이고 → 손님 글과 함께 서버로 보낸다. 답은 Claude가 쓰고, 시범 동안은 유호님이 확인한 뒤 보낸다(2단계 운영).

### 4.10 설치 프로그램과 자동 업데이트 (로드맵 10)

- 4.2의 NSIS perMachine 설치기 하나다.
- **Tauri 업데이터:** 업데이트 묶음을 Tauri 자체 서명 열쇠로 서명하고, 앱에 박은 공개 열쇠로 검증한다. OS 코드 서명과는 따로다.
- **업데이트 자리:** 공개 저장소의 GitHub Releases에는 두지 않는다(저장소가 비공개로 돌아가면 끊긴다). 회사 서버의 정적 경로나 synk.im 내려받기 쪽에 두고, 기존 PC 앱 피드의 방식을 따른다(Q6).
- 컴퓨터 전체 설치라 업데이트 설치에도 관리자 확인이 뜬다. 1단계는 그대로 둔다(알림 「업데이트 준비됨 — 누르면 설치」). 관리자 확인 없는 업데이트(권한 있는 도우미가 서명을 다시 확인하고 설치)는 3단계 후보다.
- **열쇠 보관:** 만들 때 암호를 걸고, 이 PC의 열쇠 층(`SYNK_보안`)에 둔다. 그 층은 [복원 체계](../../docs/컴퓨터를%20잃어버렸을%20때.md)가 암호문으로 비공개 저장소와 Drive에 올린다. 공개 저장소 · Actions 비밀값에는 넣지 않는다(서명은 이 PC에서만). 열쇠를 잃으면 이미 깔린 판을 갱신할 수 없으므로(Tauri 문서), 만든 날 복원 시험 도구로 암호문에서 되살려 보는 것까지 한다(T19).

### 4.11 깨끗한 Windows 자동 연습 (로드맵 11)

- 작업 흐름: `.github/workflows/workbackup-clean-windows.yml`. 계기는 손으로(workflow_dispatch), 이 두 폴더를 바꾼 push, 매주다. [관문 · 자동화 한 장](../../docs/_ops/관문_자동화.md)에 같은 커밋으로 적는다.
- 저장소가 크므로 필요한 폴더만 성기게 받는다(sparse checkout, blob 거르기).
- **1번 실행기:** 빌드(restic은 공식 판을 받아 고정 해시 대조) → 설치(관리자, 조용히) → 합성 자료 D1 → 작업 스케줄러로 회차 한 번 → 잠긴 파일 시험(파일을 독점으로 연 채 회차 → 종료 3 → 도우미 → 완전한 판) → 해시 목록을 산출물로 올린다(합성 자료뿐이라 공개돼도 된다).
- **2번 실행기(깨끗한 새 VM):** 설치 → 「옮겨 오기」를 복구 코드 길로(Google 없음) → 원래 자리와 새 폴더 둘 다 → 해시 전수 대조.
- **3번:** 표준 사용자 계정을 만들어 그 사용자 작업(암호 로그온 — DPAPI가 돌아야 하므로)으로 회차를 돌려 VSS 없는 길과 도우미 없음을 확인한다.
- **비밀값:** 시험 버킷 `ci/`의 쓰기(삭제 없음) · 읽기 출입증, 저장소 암호 씨앗(실행 번호와 섞어 실행마다 다른 저장소). 복구 암호 · 출입증은 산출물 · 로그에 남기지 않는다. 공개 저장소의 산출물은 남도 받을 수 있다.
- **청소:** CI 쓰기 출입증은 못 지우므로 시험 버킷 수명 규칙(접두사 `ci/`: 올린 지 7일 뒤 숨김, 숨긴 지 1일 뒤 삭제)이 치운다. 한 번에 약 300MB라 무료 10GB 안이다.
- 포크에서 온 PR에는 비밀값이 가지 않으므로 PR에서는 빌드 · 단위 시험만 돈다. `pull_request_target`으로 바꾸지 않는다.
- **못 재는 것:** 실행기는 Windows Server · 관리자 · 관리자 확인 꺼짐이라 관리자 확인 창 · Smart App Control · OneDrive 폴더 이동 · Google 동의 · 알림 표시가 재현되지 않는다. 그 부분은 사람 한 번(T13)과 이 PC 72시간(T14)에서 잰다. 실행기에서 「로그온한 경우에만」 작업이 도는지(대화형 세션이 있는지)는 첫 실행에서 확인하고, 안 돌면 CI에서만 암호 로그온으로 돌린다.
- **화면 시험:** 화면 조작(컴퓨터 유즈) 대신 tauri-driver(WebView2 + msedgedriver)로 웹 화면 안쪽 흐름만 본다. 서버 · Google은 시험 대역으로 둔다.
- 3연속 통과가 관문이다.
- **이 PC 측정:** 같은 D1로 메모리 · CPU · 처음 백업 속도 · 증분 시간 · 회차당 주고받는 양을 잰다. 휴대폰 핫스팟일 때는 큰 올리기를 미룬다.

### 4.12 화면 다시 (로드맵 12)

- 뼈대부터 다시 짠다: [디자인 참고 장부](../../docs/디자인/참고사이트/README.md) → 최신 사이트 크롤링 → 시안 둘(정적 HTML, 1440 · 390) → 유호님이 고른다 → Claude가 Tauri 화면으로 옮긴다 → 카본 + Fable 검수.
- 한 화면에 「안전함 · 마지막 확인 · 증명 날짜」, 「파일 되살리기」, 「새 PC로 옮겨 오기」만 둔다. 나머지(폴더 · 외장 드라이브 · 잠긴 파일 도우미 상태 · 복구 코드 · 내 기기 · 사고 되돌리기 · 트레이 · 측정 안내 · 업데이트)는 설정 서랍에 넣는다.
- 1단계에 새로 생기는 화면: 첫 시작 둘(Google로 시작 · 보호 범위 확인), 옮겨 오기 넷(자리 고르기 · 진행 · 결과 · 다시 깔 것), 사고 되돌리기 둘(시각 · 미리 보기), 복구 코드 인쇄 쪽, 기기 끊기 확인 웹 쪽, 알림 문구.
- 화면 글 검사: 기본 화면에 restic · 스냅샷 · 버킷 · 출입증 · 저장소 · pack · prune 같은 말이 나오면 시험이 실패한다.

## 8. 벤치마킹 근거

[경쟁 20개군 조사](../solo-backup/RESEARCH.md)(11-09)의 결론 — 적은 평상시 조작, 마지막 확인된 완료 시각, 복구 증명, 범위를 숨기지 않기 — 를 그대로 기준으로 쓴다. 1단계의 새 기능은 11-12에 따로 모았다. 공식 문서로 기능을, 사용자 글로 좋거나 불편한 까닭을 나눴고, 검색 요약으로만 본 것은 그렇게 적었다. 전수조사가 아니다.

## 9. 설계 검토에 따로 짚을 것

- **Q1 원래 자리 복구.** 0.5.0이 지켜 온 「원래 작업 폴더에는 복구하지 않는다」를 「옮겨 오기에서만, 덮지 않고, 장부를 남기고」로 바꾼다(4.6). 빠진 위험이 있는가 — 예: 옛 PC가 아직 살아 있는데 새 PC에서 옮겨 오기를 누른 경우, 같은 PC를 초기화해 다시 깐 경우(기기 번호가 새로 생김).
- **Q2 OneDrive 남은 공간.** 로드맵은 「OneDrive 남은 공간을 보여 주고」인데, 로컬에서 믿을 만한 숫자를 못 읽으면 경고 문구로 바꾼다. 괜찮은가.
- **Q3 표준 사용자의 부분 백업.** 잠긴 파일 때문에 종료 코드 3이 계속 나는 표준 사용자는 완료본이 오래 갱신되지 않는다. 지금처럼 올리지 않고 알림 · 메일로만 잡을지, 「못 읽은 파일은 앞 완료본에서 이어 붙인 판」을 만들지.
- **Q4 도우미.** 폴더 규칙(프로필 안 또는 소유자 = 사용자)과 등록 방식(작업 보안 설명자로 그 사용자에게 실행만)이 권한 상승 · UAC 우회 통로를 충분히 막는가. 도우미가 쓴 파일의 소유자 · 무결성 수준 문제.
- **Q5 되살리기 도구.** 숨김 표시를 지우는 길(싸고 빠름, 「언제 숨겨졌나」 기록은 사라짐)과 늘 복사하는 길(기록은 남음, 저장비 · 시간) 중 섞어 쓰는 지금 안이 맞는가. T 뒤 새로 생긴 파일을 숨기는 것이 restic 저장소를 늘 일관되게 두는가.
- **Q6 업데이트 자리와 관리자 확인.** 업데이트마다 관리자 확인이 뜨는 것을 1단계에서 받아들일지.
- **Q7 개통 서버 반영 길.** 회사 이미지 판 사슬(봉인 · 재무장 · HA)에 컨테이너를 더할지, 같은 VM의 별도 compose로 둘지. 개통 서버 SQLite를 회사 백업에 넣는 법.
- **Q8 대량 변경 문턱.** 처음 값과 오탐 처리.
- **Q9 손님당 저장소 하나 + 기기별 호스트.** 끊긴 기기 판을 30일 뒤 새 기기가 정리하는 규칙, 한 저장소에 두 기기가 동시에 쓰는 순간(옮겨 오기 중)의 잠금.
- **Q10 서버 탈취 대비 사본 후보.** 다른 B2 계정 복제(복제 규칙) · 객체 잠금 사본 · 다른 회사 저장소. 1단계는 값과 한계만 적는다.
