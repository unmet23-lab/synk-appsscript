# 작업 환경 자동 진단 검증

2026-11-10, Windows x64, Rust 1.99.1 MSVC. 공개 문서에는 실제 장치의 경로·프로그램 전체 목록·키·보고서를 넣지 않는다. 실제 보고서는 사용자 LocalAppData의 새 폴더에 보관한다.

## 확인한 것

- 기존 0.5.0 자동 백업과 0.6.0 Rust 앱을 수정하지 않는 독립 라이브러리·실행 파일.
- 네이티브 시험 20개 통과(프로세스 단위 3·통합 17): 원본 유지·내용 비수집, 겹치는 경로 집계, 제한/제외 구분, 문맥별 제외, junction/조상 차단, 출력 충돌, 클라우드 속성, 잘못된 루트, 설정 안전 투영, 표시 문자열, 실제 자식 프로세스 시간/출력 상한·비정상 종료·파이프 수신, MSIX family 검증·null 위치, 보고서 재실행 보존.
- 시험 fixture는 새 폴더에 만들며 삭제하지 않는다. 실제 사용자 원본에 시험 자료를 쓰지 않는다.
- 첫 실제 탐색은 설치 레지스트리 140건·현재 사용자 MSIX 114건·실행하지 않는 PATH 힌트 4건을 수집했다. 등록 항목에는 구성요소·복수 버전이 포함되므로 서로 다른 프로그램 수가 아니다.
- 기본 40만 항목 상한을 실제로 만났으며 결과를 부분 탐색으로 표시했다. 합계는 샘플의 논리 크기이며 필요한 요금제나 전체 보호 비율로 제시하지 않는다.
- 실제 앱의 고정 설정에서 `sources`와 `automatic` 투영에 성공했다. 세 차례 실행 모두 기존 설정 파일 SHA-256이 실행 전후 동일했다. 원격 B2 보관·최신성이나 다른 GitHub/Drive 보관 상태는 이번 진단으로 검증하지 않는다.
- 긴 목록과 짧은 백업 계획을 분리했다. JSON과 자세한 목록에는 알려진 위치 부재·권한·링크·클라우드·상한 등 미확인 이유를 남긴다.
- 최종 EXE 실제 실행: 후보 598곳·관찰 파일 325,047개, 기본 40만 메타데이터 항목 상한에서 부분 결과. MSIX AI 앱의 현재 사용자 데이터 위치도 찾아 수동 내보내기 후보로 기록했다. 원본 내용은 읽지 않았다.
- 같은 EXE를 `%LOCALAPPDATA%/WorkBackupInventory-0.1.0/`에 새로 설치하고 복사 전후 SHA-256과 `--help` 실행을 확인했다. 크기 787,968 bytes, SHA-256 `6d13bf602fc9c5083e3da58de33cf578751e687a7cc92d4640870357e6605b4e`.

- 설계 검토 Fable 8건(반영 8).
- 최초 백엔드 검수 `solo-backup-rust-inventory-20261110`: GPT 2건(반영 2) · Claude 7건(반영 7), P0/P1 없음.
- 최종 변경 검수 `solo-backup-rust-inventory-20261110-final`: GPT 0건 · Claude 2건(후속 2), P0/P1 없음. 도구의 사슬·입력 SHA·끝 표식·필수 검수 조건 통과.
- 후속 P2 두 건: 캐시 추정 조상 때문에 **명시한** 하위 루트가 제외될 때 `scan_complete`와 요약의 표시를 더 분명히 할 것(현재 상세에는 제외 사유가 남는다); 후보 수천 개에서 요약 정렬 키를 캐시할 것. 현재 기본 자동 진단은 명시 루트 없이 실행했고 상한 도달을 부분 상태로 보고했다.
- 첫 Claude 설계 응답과 첫 백엔드 응답의 출력 한도 종료는 실패 증거·사용량을 보존하고 검수 통과로 세지 않았다. 최종 Claude 응답의 limitations 배열은 원문·지적·표식 그대로 줄바꿈 문자열로만 정규화해 도구 스키마에 맞췄다.
- 이번 작업 무료 Claude 크레딧 추정 사용 **$2.029642**(실패 응답 포함). 앞선 Rust 작업과 합계 **$9.0265025**, 기존 승인 상한 $15 이내. 새 결제·충전 없음.
- 소스 반영 전 공유 master CI에서 일부 GitHub Actions가 스텝 시작 없이 실패한 상태를 확인했다(`ci빨간불.js`, 기존 커밋의 실행들). 이 작업의 네이티브 시험·필수 검수와 구분하며, 원격 CI 전체가 통과했다고 주장하지 않는다.

## 범위와 한계

이 판은 발견과 추천 준비까지다. 고객 UI 통합·자동 백업 대상 추가·계정 자동 개통·앱별 DB 일관성·프로그램 재설치·자격 이전·다른 물리 PC 전체 복구는 실행하지 않는다. 탐색 중 다른 앱의 파일 변화는 가능하며 원자적 스냅샷이 아니다. 원본 보존은 쓰기 없는 코드 경로와 격리 fixture, 실제 기존 앱 설정의 전후 대조로 확인했다. 실제 전체 파일의 전후 해시 검증을 했다는 뜻은 아니다.

기본 상한을 넘긴 작업 PC의 전체 용량 산정에는 추가 탐색이 필요하다. 링크·온라인 전용 자료·WSL/Docker·SaaS 자료는 별도 내보내기나 연결이 필요하다. 대소문자를 구별하는 디렉터리는 완전 지원하지 않는다. 일반 설정 안에도 인증정보가 들어갈 수 있으므로 후속 백업은 암호화·복구 본인 확인을 함께 적용해야 한다.

기존 Rust 시험판의 B2 읽기 연결·바로가기 적용이 정책에 막힌 기록은 그대로 유지한다. 이 진단 작업은 그 설정 명령을 재시도하거나 대신 수행하지 않았다.

증거: 공용 작업본 `.tmp/solo-backup-inventory-20261109/`의 기획·Fable 설계 검토·native-tests 로그·live-run 전후 대조. 장치 보고서 자체는 공개 저장소와 검수 입력에서 제외한다. 시험 TAP는 원본 Rust 시험 로그에서 성공한 시험 이름·결과를 변환한 것으로, 별도 Node 기능 시험을 돌렸다는 뜻이 아니다.
