# 업무 백업을 솔리오 하나로 — 설계 (2026-11-26)

유호님 11-26: 「백업하는 클라이언트? 이게 솔리오랑 따로 구분되어서 하나가 더 있던데 이거말고 솔리오 하나로 전부 가능하게 클라이언트 통합해줄수있어? 백업프로그램 따로 관리하면 조잡하잖아.」 조율 세션이 「겉은 솔리오 하나로 합치고, 속의 백업 부품만 보이지 않게 남긴다」를 권했고, 유호님이 「응, 그렇게 해」라고 하셨다.

이 문서는 그 일의 설계다. 로드맵의 [솔리오와의 관계](ROADMAP.md#solio-relation)에서 미뤄 둔 「화면까지 합칠지」를 합치는 쪽으로 정한다. 엔진과 솔리오 사이의 파일 계약([1단계 설계 4.13](STAGE1_DESIGN.md))은 그대로 쓰고, 그 위에 화면 통로 하나를 더한다. Fable 5.2 설계 검토(「고쳐서 짓기」, P1 5 · P2 9 · P3 3)를 반영한 둘째 판이다(10절).

## 0. 한눈에

- 손님 눈에는 솔리오 하나만 있다. 바탕화면, 시작 메뉴, 설치된 앱 목록, 알림이 모두 솔리오다.
- 엔진 창이 하던 일(보호 시작, Google 로그인, 되살리기, 옮겨 오기, 설정)은 솔리오 백업 방 안에서 한다. 엔진의 화면 파일을 솔리오 창 안에 그대로 띄운다.
- 엔진의 창 앱 `WorkBackup.exe`는 평소에 창을 띄우지 않는다. 솔리오가 창 없는 「호스트」로 띄우고 표준 입출력으로만 말한다. 솔리오가 없거나 고장 났을 때만 지금 창이 비상 길로 열린다.
- 매시간 회차(`WorkBackupRun.exe`), 관리자 도우미, restic, 작업 스케줄러, 상태 폴더 `%APPDATA%\SynkWorkBackup`는 그대로다. 솔리오가 꺼져 있어도 백업은 돈다.
- 엔진의 「업데이트 준비됨」 알림은 없애고 솔리오 「할 일」 한 장으로 묶는다. 설치는 엔진의 업데이터(`--update-install`)가 지금처럼 엔진 잠금을 쥐고 한다.
- 이미 엔진을 깐 PC는 엔진을 새 판으로 올리기만 한다. 다시 보호를 시작하지 않는다.

## 1. 지금 따로 보이는 것과 바꾸는 법

| 따로 보이는 것 | 바꾸는 법 |
|---|---|
| 시작 메뉴 `SYNK 업무 백업.lnk` | 엔진 설치기가 만들지 않고, 올릴 때 옛 것을 지운다. 이 바로 가기가 맡던 알림 이름표(AUMID)를 다른 길로 옮긴 뒤에만 지운다(2.7, T-한몸1) |
| 바탕화면 `업무 백업.lnk` | 엔진은 바탕화면 바로 가기를 만든 적이 없다. 이 PC의 것은 0.5.0(Electron 시험판, `Documents\업무백업-시험판\0.5.0`)을 가리키는 바로 가기라, 넘어오는 날 이 PC에서만 지운다. 0.5.0 폴더와 `%APPDATA%\SoloWorkBackup`는 건드리지 않는다 |
| 설치된 앱 목록의 「SYNK 업무 백업」 | 제거 등록에 `SystemComponent=1`을 적어 숨긴다(설치할 때마다 다시 적음). 솔리오는 레지스트리를 직접 읽어 엔진을 찾으므로 영향이 없다. 엔진만 지울 길은 방의 설정 「백업 부품 지우기」로 옮긴다 |
| 따로 뜨는 엔진 창 | 엔진 화면을 솔리오 백업 방 안에 띄운다(2장). 창은 비상 길로만 남는다(2.5) |
| 엔진의 「업데이트 준비됨」 알림 | 회차가 띄우지 않는다. 솔리오 「할 일」 한 장으로 보인다. 꼭 올려야 하는 판과 2주 넘게 안 올린 판만 회차가 솔리오 이름으로 알린다(3.2) |

## 2. 구조

```
솔리오(PC 앱 본체) ── 표준 입출력(JSON 줄) ── WorkBackup.exe --solio (창 없음, 솔리오와 따로 삶)
   │                                              ├─ Node 워커(지금과 같음)
   ├─ 백업 방(솔리오 렌더러: 원클릭 판)            ├─ 네이티브 일(DPAPI, 작업 스케줄러, 다시 깔기, 파일)
   └─ 엔진 화면 자리(WebContentsView)              └─ 확인 대화 상자(주인 창 = 솔리오 창)
        화면 파일: 깔린 엔진의 resources\ui\(워커와 같은 판)

작업 스케줄러 ── WorkBackupRun.exe(매시간 · 로그인 · 깨어남 · 요청) ── 그대로
```

### 2.1 엔진 쪽: 호스트 모드 `WorkBackup.exe --solio`

- 지금 창 앱에서 창, 웹 화면, 트레이만 뺀다. 창 잠금(`ui.lock`)을 쥐고, Node 워커를 띄우고, 네이티브 일을 맡는다. Tauri 앱은 만들지 않는다.
- **부모 확인(F1).** 호스트는 시작하자마자 부모 프로세스의 실행 파일을 본다. 이 Windows 사용자의 PC 앱 설치 자리(HKCU 제거 등록의 PC 앱 항목 `InstallLocation`, `%LOCALAPPDATA%\Programs\` 아래) 안의 PC 앱 실행 파일이 아니면 아무것도 쓰지 않고 끝난다. 셸이나 다른 프로그램이 `--solio`를 띄워도 바꾸는 메서드에 닿지 못한다. PC 앱은 아직 코드 서명이 없어 서명 대조는 하지 않고 경로까지만 본다.
- 통로: 부모의 표준 입출력이다. 줄의 꼴은 2.6이 정본이다. 알림 낱말은 솔리오가 직접 받아 화면 자리에 넘기므로 호스트를 거치지 않는다.
  - `hello.v`를 솔리오가 모르면(엔진이 새 판) 방은 「솔리오를 업데이트해 주세요」를 보이고 엔진 화면을 열지 않는다. 솔리오가 아는 것보다 낮으면(엔진이 옛 판) 「백업 부품 업데이트」 카드를 보인다(4장).
- 메서드 검사는 지금 `backup_call`과 같다. `contract/methods.json`의 이름만, 인자 둘 이하 · 64KB 이하, 복구 전용 연결이면 `allowedReadOnly`만.
- **대화 상자는 호스트가 직접 띄운다(F11).** 워커가 부르는 `dialog.open` · `dialog.save` · `dialog.message`는 지금처럼 호스트의 네이티브 쪽이 띄우고, 주인 창으로 솔리오 창 핸들을 준다. 그래서 확인 창이 솔리오 창 위에 뜨고, 파이프 너머에서 「예」를 대신 답할 수 없다. 메시지 창은 지금처럼 취소가 기본이고 Esc가 취소다.
- **열기만 솔리오가 한다.** `openExternal` · `openPath`는 호스트가 지금의 허용 목록으로 거른 뒤 `ask`로 넘기고, 솔리오가 같은 목록으로 한 번 더 거른 뒤 연다. 백그라운드 프로세스가 연 브라우저는 앞으로 오지 않을 수 있어서다. `bye`가 오거나 입력이 닫히면 기다리던 `ask`는 모두 「열지 못함」으로 끝난다.
- **솔리오와 따로 산다(F2).** 솔리오는 호스트를 `detached`로 띄운다. Node는 그렇지 않은 자식을 닫히면 모두 끝나는 작업 개체에 넣기 때문이다. 부모가 끝난 뒤 표준 출력 쓰기가 실패해도 호스트는 멈추지 않는다(`println!` 대신 실패를 무시하는 쓰기).
- **끝(F6).** `bye`가 오거나 입력이 닫히면:
  - 일이 없으면 워커를 멈추고 바로 끝난다.
  - 작업(첫 백업, 되살리기, 옮겨 오기, 다시 깔기)이 돌고 있으면 끝까지 마친 뒤 끝난다. 그동안 다시 켠 솔리오가 띄운 호스트는 `{"hello":{"v":1,"busy":true}}`를 쓰고 끝난다.
  - 첫 백업을 멈추고 회차 실행기에 넘기는 길(Fable F6)은 워커에 백업을 멈추는 메서드가 아직 없어 첫 판에 넣지 않는다. 그동안 첫 백업이 도는 사이 솔리오를 다시 켜면 진행만 보인다(8장).
- 배포 판의 다른 시작(2.5 표).

### 2.2 솔리오 쪽: 엔진 화면 자리

- 자리: PULSE · Workspace를 띄우는 `space-view.cjs`의 짜임 그대로 WebContentsView 하나다. 솔리오 띠(SOLIO · 방 이름 줄)는 솔리오가 그리고, 그 아래를 엔진 화면이 채운다.
- 화면 파일: 깔린 엔진의 `resources\ui\`다. 엔진 빌드가 `dist/`를 실행 파일에 묻는 데 더해 같은 파일을 `resources\ui\`에 두고 자원 목록(`resources\manifest.json`)에 SHA-256을 적는다. 솔리오는 그 목록의 이름만, 해시가 맞을 때만 내준다. 무결성의 바탕은 Program Files의 관리자 전용 쓰기와 HKLM의 `InstallLocation`이고, 목록 해시는 섞인 설치를 잡는다.
- 내주는 규칙(F12): `workbackup-ui`를 앱 준비 전에 `registerSchemesAsPrivileged`(standard · secure)로 등록한다. 확장자별 MIME을 맞춘다. 설치 폴더에 새 `.installing` 표식이 있으면 내주지 않는다. 호스트를 새로 띄울 때마다 화면 파일을 다시 읽고, `hello.version`과 목록의 판이 다르면 열지 않는다.
- 자리의 웹 설정: 따로 된 세션(`persist:workbackup-ui`), 샌드박스, 문맥 격리, Node 없음. 바깥 주소 요청과 쪽 옮기기는 막고 새 창은 거절한다. 엔진 화면의 CSP는 그대로 쓴다.
- **다리(F7).** 이 자리 전용 preload는 작은 통로 넷만 내놓는다: `call(method, args)`, `onState`, `onOpen`, `close`. 메서드 목록은 들고 있지 않다. `window.backup`은 엔진이 싣는 `bridge.js`가 이 통로 위에 만든다(`window.synkBackupHost`가 있으면 Tauri 대신 그것을 쓴다). 엔진이 메서드를 더해도 솔리오를 고칠 일이 없다.
- `ui/app.js`: 알림 낱말을 `onOpen`으로도 받는다. `closeWindow`는 화면 자리에서 `close`(원클릭 판으로 돌아가기)를 부른다. 지금은 `window.close()`로 떨어져 자리가 닫힌다.
- 본체 중계: 솔리오 본체는 이 자리의 webContents · 주 프레임 · `workbackup-ui://app/` 주소에서 온 부름만 호스트에 넘긴다. 솔리오의 다른 화면(구 얼굴, 원클릭 판)은 지금처럼 상태 파일과 요청 파일로만 엔진과 말한다.
- 누구에게: 방이 열리는 계정에만 자리를 만든다. 로그아웃하거나 다른 SYNK 계정으로 바뀌면 자리를 닫고 `bye`를 보낸다.
- 엔진의 머리 줄: 솔리오 띠와 겹치는 「SOLIO 백업·복구」와 작은 구는 이 자리에서 숨긴다. 「설정」의 자리는 시안에서 고르신다(5장).

### 2.3 신뢰 경계

- 지금 엔진의 바꾸는 메서드(폴더 더하기 · 빼기, 기기 끊기, 되돌리기, 지우기 범위)에 닿는 길은 엔진 창의 웹 화면 하나다. 바뀐 뒤에는 「솔리오 본체가 띄운 호스트」를 거치는 길이 더해진다.
- 그 길에 같은 급의 문을 둔다.
  - 호스트의 부모 확인(2.1). 명령 한 줄로는 열리지 않는다.
  - PC 앱의 Electron 퓨즈를 끈다: `RunAsNode`, `EnableNodeOptionsEnvironmentVariable`, `EnableNodeCliInspectArguments`. 포장된 판은 `--remote-debugging-port`로 켜지면 바로 끝난다. 그래야 PC 앱 실행 파일로 임의 스크립트를 돌려 부모 확인을 넘지 못한다.
  - 엔진 쪽 네이티브 확인 창(폴더 빼기, 점검, 전체 되살리기)은 호스트가 직접 띄운다(2.1).
- 이 문들로 지금 Tauri 창과 같은 급이 된다. 같은 사용자 권한의 악성 프로그램은 지금도 웹뷰 원격 디버깅이나 워커 직접 띄우기로 같은 일을 할 수 있어, 그들에게 새 힘은 아니다. 막으려는 것은 셸을 쓰는 AI 도구가 문서화된 한 줄로 바꾸는 메서드에 닿는 길이다(4.13).
- 이름 있는 파이프나 로컬 주소는 열지 않는다. 듣는 입구가 생기기 때문이다.

### 2.4 수명

- 띄우는 때: 손님이 방에서 엔진 화면이 드는 일(파일 되살리기, 옮겨 오기, 설정, 보호 시작 뒤의 Google 로그인과 범위 확인)을 처음 누를 때. 원클릭 판만 보는 동안은 띄우지 않는다. 방을 떠나도 5분은 두고, 그 뒤 일이 없으면 `bye`.
- 솔리오가 끝나거나 업데이트될 때: 2.1의 「끝」대로 한다. 다시 켠 솔리오는 `busy` 동안 상태 파일의 단계와 진행(「하던 되살리기를 마무리하는 중 · 37%」)을 보이고 5초마다 다시 띄워 본다.
- 호스트가 죽으면: 방은 「백업 화면이 멈췄습니다 — 다시 열기」를 보인다. 매시간 회차는 따로라 백업은 멈추지 않는다.
- 엔진이 바뀌면(솔리오 밖 길의 설치 포함): 설치기의 Restart Manager가 호스트를 닫는다. 방은 「다시 열기」로 가고, 다시 열 때 새 화면 파일을 읽는다(F12 시험).

### 2.5 배포 판 `WorkBackup.exe`의 시작마다 하는 일(F3 · F14)

| 시작 | 솔리오가 있음(`synk-solio:` 등록 + 그 실행 파일 있음) | 솔리오가 없음 |
|---|---|---|
| 인자 없음(옛 바로 가기, 탐색기, 설치기 끝의 열기) | `synk-solio:backup?topic=status`를 열고 끝남 | 지금 창(비상 창) |
| 열기 주소 `synk-workbackup:open?topic=<낱말>`(알림 누름) | `synk-solio:backup?topic=<낱말>`을 열고 끝남 | 비상 창, 그 낱말의 화면 |
| `--solio` | 부모 확인 뒤 호스트 | 부모 확인에서 끝남 |
| `--window` | 비상 창(솔리오가 「백업 창 따로 열기」로 부를 때만) | 같음 |
| `--background` | 아무것도 하지 않음 | 같음 |
| `--update-check` · `--update-check-due` · `--update-install` | 지금과 같음. `--update-install --quiet`(새 인자)는 설치기를 창 없이(`/S`) 띄우고 끝나도 창을 열지 않음 | 같음 |
| 설치 미완 · 시작 실패 | 지금의 대화 상자를 남긴다(드문 비상) | 같음 |

- 「창을 열 때 먼저 업데이트를 묻기」(`asks_before_open`, 4.10 11-25)는 비상 창에만 남는다. 솔리오로 넘기는 시작은 묻지 않는다.
- 비상 창이 있는 까닭: 솔리오가 지워졌거나 고장 났을 때도 파일을 되살릴 수 있어야 한다(로드맵 「솔리오가 고장 나도」). 옛 솔리오(`synk-solio:` 없음)와 새 엔진이 만나는 넘어오는 동안에도 이 길로 지금처럼 쓸 수 있다. 엔진은 판 내림이 막혀 있어 이 창이 되돌리기 수단이기도 하다.
- 솔리오가 받은 낱말로 방을 열 수 없을 때(로그아웃, 방이 없는 계정): 로그인 화면 위에 「백업 창 따로 열기」 한 줄을 두고, 누르면 `--window`를 띄운다(F13).
- 솔리오 쪽: 포장된 판은 `app.setAsDefaultProtocolClient('synk-solio', process.execPath, ['--'])`로 등록한다. `second-instance`와 첫 실행에서 마지막 인자가 `synk-solio:backup?topic=<아홉 낱말>`과 글자 그대로 같을 때만 받는다. 지금 `second-instance`는 platform이면 인자를 보지 않으므로 인자 읽기를 더한다.

### 2.6 호스트 통로의 꼴(엔진과 솔리오가 함께 지키는 정본)

한 줄에 JSON 하나, UTF-8, 줄 끝은 `\n`이다. 솔리오 → 호스트 한 줄은 128KB, 호스트 → 솔리오 한 줄은 2MB를 넘지 않는다. 모르는 칸이 있는 줄은 버린다.

| 쪽 | 줄 | 뜻 |
|---|---|---|
| 호스트 → | `{"hello":{"v":1,"version":"0.8.0"}}` | 첫 줄. 이 줄 전에는 아무것도 쓰지 않는다 |
| 호스트 → | `{"hello":{"v":1,"busy":true}}` | 다른 호스트나 창이 창 잠금을 쥐고 있음. 쓰고 바로 끝남(종료 0) |
| 호스트 → | (아무것도 쓰지 않음, 종료 77) | 부모 확인에서 거절 |
| 호스트 → | `{"id":<수>,"result":<봉투>}` | 부름의 답. 봉투는 지금 `backup_call`과 같다(`{"ok":true,"value":…}` 또는 `{"ok":false,"error":"…","code":"…"}`) |
| 호스트 → | `{"state":<값>}` | 워커의 상태(지금 `backup:state`와 같은 값) |
| 호스트 → | `{"ask":<수>,"native":"openExternal"|"openPath","arg":"<글>"}` | 호스트가 허용 목록으로 거른 열기. 솔리오가 다시 거르고 연다 |
| 호스트 → | `{"failed":"<부호>"}` | 워커가 죽음. 쓰고 종료 1 |
| 솔리오 → | `{"id":<수>,"call":"<메서드>","args":[…]}` | 부름. `id`는 1 이상 정수, 같은 때 64개까지 |
| 솔리오 → | `{"answer":<수>,"ok":true|false}` | `ask`의 답 |
| 솔리오 → | `{"window":"<창 핸들 10진 글>"}` | 대화 상자의 주인 창. 호스트는 그 창이 부모 프로세스의 것일 때만 쓴다 |
| 솔리오 → | `{"bye":true}` | 끝내기. 입력이 닫힌 것과 같다 |

- 호스트의 부름 처리는 지금 `backup_call`과 같다. 메서드 검사 → 복구 전용 검사 → 워커 → 봉투.
- `ask`는 30초 안에 답이 없거나 `bye` · 입력 닫힘이 오면 「열지 못함」(`OPEN_FAILED`)으로 끝난다.
- 부모 확인: 부모 프로세스의 실행 파일이 `%LOCALAPPDATA%\Programs\<폴더 하나>\SYNKPlatform.exe` 또는 `SYNKPlatformPreview.exe`이고(대소문자 무시), 부모가 이 호스트보다 먼저 시작했어야 한다. 디버그 판의 `--test-mode`만 이 확인을 건너뛴다.
- 솔리오는 호스트를 `detached`, 창 숨김, 표준 입출력 셋 다 파이프로 띄운다. 호스트의 표준 오류는 읽지 않는다.

### 2.7 알림

- 엔진의 알림(「문제 + 할 일 하나」, 첫 백업 끝남)은 회차 실행기가 지금처럼 띄운다. 솔리오가 꺼져 있을 때도 보여야 하기 때문이다.
- 이름표는 둘 가운데 T-한몸1(7장)에서 Windows 10 22H2와 11 모두 통하는 쪽으로 정한다. 통한 것을 확인하기 전에는 시작 메뉴 바로 가기를 지우지 않는다(F8).
  - 가: PC 앱의 이름표를 그대로 쓴다. 알림이 PC 앱 알림과 한 무리로 묶인다. 그 이름표가 이 사용자에게 등록돼 있어야 한다.
  - 나: 엔진 이름표 `im.synk.workbackup`을 HKCU `Software\Classes\AppUserModelId`에 `DisplayName` · `IconUri`로 등록한다(Microsoft가 포장 안 된 앱에 안내하는 길). 이름과 그림은 PC 앱과 같게 한다. Windows 알림 설정에 같은 이름이 두 줄 생긴다.
- 머리에 보이는 이름은 PC 앱의 실제 이름이다. 지금 PC 앱은 「SYNK Platform Preview」다(`desktop/src/catalog.cjs`). 손님 판의 이름은 PC 판 이름을 따른다.
- 누르면 2.5 표대로 솔리오 백업 방의 그 화면이 열린다. 옛 판(0.7.x)이 남긴 알림도 같다.

## 3. 설치 · 업데이트 · 지우기

### 3.1 처음 설치

- 「백업 부품이 솔리오와 함께 깔린다」는 솔리오가 방 안에서 엔진을 깐다는 뜻으로 정한다. 솔리오 설치 때 함께 깔지 않는 까닭은 둘이다. 엔진은 컴퓨터 전체 설치라 관리자 확인이 드는데 솔리오 설치에는 관리자 확인이 없다. 백업을 쓰지 않는 솔리오 손님에게 관리자 확인과 37MB를 더할 까닭이 없다.
- 길은 지금(4.13 「화면 쪽 구현」)과 같다. 피드 → 받기 → 쥔 핸들로 크기 · SHA-256 · 서명 확인 → 관리자 권한으로 설치기 실행. 바뀌는 것:
  - 설치기를 `/S`(창 없음)로 띄운다. 지금의 `/P /R`은 진행 창을 띄우고 끝나면 엔진 창을 연다.
  - 진행은 방 안에 보인다: 받기 · 확인 · Windows 확인 기다림 · 까는 중. 관리자 확인 직전에 「Windows가 'SYNK 업무 백업'을 바꿔도 되는지 물으면 '예'를 눌러 주세요」라고 미리 말한다.
  - 끝나면 솔리오가 호스트를 띄워 엔진 화면 자리에 첫 시작 화면을 연다. 호스트가 있는 엔진에는 `setup` 요청 파일과 취소 표식을 쓰지 않는다. 옛 엔진에는 지금 길을 남긴다(4장).
  - Google 로그인은 엔진 화면의 「Google로 시작」을 한 번 누른다. 브라우저에서 동의를 마치면 방이 범위 확인으로 이어진다. 힌트는 11-21 결정대로 넘기지 않는다.
- 관문 1의 누름 셈: 「보호 시작」 1 · 관리자 확인 1 · 「Google로 시작」 1 · 계정 고르기와 「계속」 2 · 범위의 「보호 시작」 1 = 전체 6, 앱 안 3. 상품 기준(앱 안 3 이하, 전체 10 이하) 안이다.

### 3.2 업데이트(F4 · F9)

- 회차 실행기는 피드 확인(`--update-check-due` → `update.json`)을 지금처럼 한다. 날마다의 「업데이트 준비됨」과 주 1회 「관리자에게 부탁」 알림은 뺀다. 확인 결과(`available`, 관리자 확인을 스스로 할 수 있는지 `canApprove`)를 상태 파일에 더한다. 솔리오는 모르는 칸을 무시하므로 꼴 번호는 그대로다.
- 솔리오: 상태 파일에 새 판이 보이면 「할 일」에 한 장을 둔다. 「백업 부품 새 판 0.8.1 — Windows 확인 한 번」. 방 맨 아래에도 한 줄을 둔다. `canApprove`가 거짓이면 글을 「이 PC의 관리자에게 업데이트를 부탁해 주세요」로 바꾸고 일주일에 한 번만 올린다.
- 누르면 솔리오가 호스트에 `bye`를 보내고 `WorkBackup.exe --update-install --quiet`를 띄운다. 엔진 잠금, 서명과 판 확인, 판 내림 막기, 설치기 넘겨받기를 엔진 업데이터가 지금처럼 한 길에서 한다. 회차나 되살리기가 돌고 있으면 `RUN_ACTIVE`로 물러나고, 방은 「백업이 끝난 뒤 다시 눌러 주세요」를 보인다. 솔리오가 따로 받아 두는 일(미리 받기)은 하지 않는다.
- 회차가 알리는 경우는 둘만 남긴다. 피드의 `minimum`보다 낮은 판(4.10 「이 판 아래는 더 못 씀」)과, 새 판이 나온 지 14일이 넘었는데 안 올린 판이다. 머리는 솔리오이고(2.7), 누르면 솔리오 「할 일」이 열린다(낱말 `update`). 솔리오를 열지 않는 PC도 권한 코드 고침이 남지 않게 하려는 것이다.

### 3.3 지우기(F5 · F10)

- 「솔리오를 지우면 백업 부품도 지운다」로 정한다. 4.13의 「솔리오를 지워도 엔진은 남는다」를 바꾼다.
- PC 앱 지우기(electron-builder NSIS)에 platform 앱만 `customUnInstall`을 더한다(`package.cjs`의 world · messenger에는 넣지 않음). 하는 일:
  1. 업데이트가 부른 지우기(`${isUpdated}`)면 아무것도 하지 않는다.
  2. `HKCU\Software\Classes\synk-solio`를 지운다.
  3. 다른 PC 앱(Preview와 release는 다른 앱이다)이 이 사용자에게 남아 있으면 엔진은 두고 끝난다.
  4. 다른 Windows 사용자의 회차 작업이 있으면 엔진은 두고 「이 PC의 다른 Windows 사용자도 백업을 쓰고 있어 백업 부품은 남겨 두었습니다」를 보인다(`--uninstall`은 모든 사용자의 작업을 지우기 때문이다).
  5. 아니면 HKLM 제거 등록의 `UninstallString`을 관리자 권한으로 `/S _?=<설치 폴더>`로 부르고 끝나기를 기다린다.
- 지우기 화면의 한 줄: 「솔리오를 지우면 이 PC의 자동 백업도 멈추고 백업 부품을 함께 지웁니다. 클라우드의 백업과 Google 복구 정보는 그대로 남습니다.」
- 엔진 지우기가 하는 일은 지금과 같다. 회차 작업과 작업 폴더를 거두고, 사용자 상태 폴더와 클라우드 백업은 남긴다.
- 관리자 확인을 거절하거나 실패했을 때: 엔진은 숨은 채 남는다. 회차 실행기는 「이 사용자에게 솔리오가 한때 있었는데(상태 폴더에 본 적 있음 표시) 지금은 `synk-solio:` 키나 그 실행 파일이 없음」이면 하루 한 번 알린다: 「솔리오를 지웠는데 백업 부품이 남아 있습니다」 → 누르면 비상 창의 「백업 부품 지우기」. 그동안 백업은 계속 돈다. 소스 실행 PC처럼 솔리오가 한 번도 등록되지 않은 PC에는 알리지 않는다.
- 다시 깔 때: 상태 폴더는 남아 있고 엔진과 회차 작업은 없다. 방은 「백업이 멈춰 있습니다 — 다시 켜기」를 보이고, 누르면 엔진을 깐 뒤 호스트가 회차 작업을 다시 등록한다(`startup.set`). 다시 보호를 시작하지 않는다.
- 엔진만 지우기: 방의 설정에 「백업 부품 지우기」를 둔다(F15). 위 1 ~ 5의 3 · 4 · 5와 같다.

### 3.4 목록 · 바로 가기 · 이름

- 엔진 설치기(`nsis-template.cjs`, `hooks.nsh`): 시작 메뉴 바로 가기를 만들지 않고 옛 것을 지운다(T-한몸1 통과 뒤). 제거 등록에 `SystemComponent=1`을 적는다.
- 설치 파일 이름 `SynkWorkBackup-<판>-setup.exe`는 바꾸지 않는다(피드 · 릴리스 규칙과 묶여 있다). Windows 확인 창에 보이는 「SYNK 업무 백업」은 방이 미리 말한다.
- 화면 글에서 「엔진」, 「엔진 창」을 뺀다. 손님 말은 설치 · 업데이트 · 지우기 때만 「백업 부품」이고, 나머지는 솔리오 화면 이름(파일 되살리기, 새 PC로 옮겨 오기, 설정)이다.

## 4. 이미 깐 PC가 넘어오는 길 (유호님 노트북 포함)

1. 새 PC 앱 판이 먼저 나간다. 이 판은 호스트가 없는 엔진(0.7.x)을 보면 방에 「백업 부품을 새 판으로 올리면 이 방에서 모두 할 수 있습니다」와 「업데이트」를 둔다. 올리기 전까지는 지금처럼 엔진 창을 연다.
2. 엔진 새 판을 피드에 낸다. 「업데이트」를 누르면 0.7.x의 `WorkBackup.exe --update-install`을 띄운다(0.7.x에는 `--quiet`가 없어 진행 창이 한 번 보인다). 0.7.x 회차가 그사이 「업데이트 준비됨」을 한 번 띄울 수 있고, 그 알림으로 올려도 결과는 같다.
3. 새 판 설치기는 엔진 파일만 바꾼다. 상태 폴더, 회차 작업 다섯, 도우미 작업, 클라우드 설정은 그대로라 다시 보호를 시작하지 않는다. 목록에서 숨기고, 이름표를 옮긴 뒤 시작 메뉴 바로 가기를 지운다. 설치기 끝의 열기는 2.5 표대로 솔리오 방을 연다.
4. 이 PC에서만: 바탕화면의 0.5.0 바로 가기를 지운다(유호님께 보고한 뒤).
5. 확인: 올린 뒤 첫 매시간 회차가 완료인지, 방에서 파일 되살리기가 열리는지, 알림 머리가 PC 앱 이름인지 본다.

옛 솔리오와 새 엔진이 만나면(PC 앱을 올리지 않은 PC): 2.5 표의 「솔리오가 없음」 갈래로 비상 창이 열리고, 옛 솔리오의 `/P /R` + `setup` 요청 길도 그 창이 받는다. 이 조합은 시험에 넣는다(7장).

## 5. 화면 — 시안에서 고르실 것

엔진 화면의 문구 · 흐름 · 숫자는 11-16 검정 말씨 그대로 둔다. 고르실 것은 두 화면을 한 방에 어떻게 놓을지다. 시안은 [솔리오 백업 한 몸 시안](../../docs/디자인/솔리오_백업한몸_20261126/README.md)에 있다.

- 가: 방 이름 「원클릭」. 원클릭 판이 첫 화면이고, 조용한 단추(파일 되살리기 · 새 PC로 옮겨 오기 · 설정)가 같은 방 안에서 엔진 화면을 연다. 띠 아래에 「← 원클릭 › 파일 되살리기」가 보인다.
- 나: 방 이름 「백업」. 첫 화면이 엔진의 「안전합니다」 판이고, 원클릭은 그 판의 흰 알약이 된다. 누르면 네 줄(마지막 확인, 지키는 폴더, 되살려 본 날, C: 남은 자리)이 네 차례 줄로 바뀌었다 돌아온다. 「설정」은 띠 오른쪽에 둔다.

## 7. 시험

- 엔진: 호스트 통로 단위 시험(메서드 검사, 부모 확인 거절, `ask` 왕복과 끊김 때 취소, `bye` · 입력 닫힘에서 백업 종류 넘기기와 되살리기 마치기, `busy`), 2.5 표의 시작 갈래마다, 업데이트 알림 두 경우만, `--update-install --quiet`, 설치기 시험(`installer-check.ps1`)에 바로 가기 없음 · `SystemComponent` · 이름표.
- 솔리오: 호스트 대역으로 중계 시험(다른 webContents · 다른 주소 거절), 화면 파일 내주기(목록 밖 · 해시 다름 · `.installing` · 판 다름 거절), 조용한 설치 갈래, 업데이트 카드와 `RUN_ACTIVE`, 계정 바뀜에서 자리 닫기, `synk-solio:` 낱말 거르기와 `second-instance` 인자, 퓨즈가 꺼졌는지(포장 판). 실제 Electron 창 QA(`orb-face-browser-qa.cjs`)에 엔진 화면 자리를 더한다.
- 깨끗한 Windows 연습(`workbackup-clean-windows`): 설치 뒤 목록에 엔진이 없음, 호스트 모드로 워커 시작, 0.7.5 → 새 판에서 상태와 회차 작업이 남음, 옛 솔리오 흐름(`/P /R` + `setup`)이 비상 창으로 끝까지 감.
- 이 PC 실측(먼저 보고): T-한몸1 알림 이름표 가 · 나(Windows 11, 10 22H2는 CI나 2단계 노트북), T-한몸2 솔리오를 끈 동안 회차, T-한몸3 0.7.4 → 새 판 넘어오기, T-한몸4 솔리오를 작업 관리자로 끝냄 · 업데이트로 끝냄 · 트레이에서 끝냄 셋에서 호스트가 살아 남아 되살리기를 마침, T-한몸5 지우기 묶음(시험 Windows 계정에서), T-한몸6 솔리오 창을 주인으로 한 호스트의 확인 창이 앞에 뜨고 키보드를 받는지.

## 8. 받아들이는 한계와 남는 일

- 솔리오를 다시 켠 직후, 앞 호스트가 되살리기 · 옮겨 오기 · 다시 깔기를 마치는 동안에는 엔진 화면을 열 수 없고 진행만 보인다. 백업은 회차로 넘어가므로 잠기지 않는다.
- 비상 창은 남는다. 솔리오가 없거나 고장 났을 때, 옛 솔리오와 새 엔진이 만날 때, 방이 없는 계정에서 「따로 열기」를 눌렀을 때만 뜬다.
- 부모 확인은 경로까지다. PC 앱에 코드 서명이 생기면 서명 대조를 더한다.
- 같은 PC의 다른 Windows 사용자가 백업을 쓰면 지우기가 엔진을 남긴다. 그 PC에서는 「설치된 앱」에 엔진이 보이지 않으므로 방의 「백업 부품 지우기」로 지운다.
- Google 로그인 힌트는 넘기지 않는다(11-21). 호스트가 생겨 누르는 순간의 로그인으로 직접 넘길 수 있으니 다음 판에서 다시 본다.
- 엔진 화면의 실제 창 시험(`ui-driver.cjs`)은 시험 판의 창으로 남는다. 손님이 쓰는 길은 솔리오 창 QA가 본다.

## 9. 일정 — 관문 1 「사람 한 번」(12월 셋째 주)

관문 1에 넣을 것과 뒤로 미룰 것을 나눈다(F16).

- 관문 1 전에: 호스트(부모 확인 · 따로 삶 · 비상 창 · 끝의 처리), 엔진 화면 자리, 조용한 설치, Electron 퓨즈, 목록 숨김과 바로 가기(T-한몸1 통과 뒤), 업데이트는 카드가 `--update-install --quiet`만 부르는 판.
- 관문 1 뒤(12월 넷째 주, 2단계 노트북 시험 전): 지우기 묶음, 업데이트 알림 두 경우, 「백업 부품 지우기」, 문서 고침(4.13 · 로드맵 · 계약 README · 현장 노트).

| 때 | 일 |
|---|---|
| 11-27 ~ 11-28 | 시안 고르기 |
| 11-29 ~ 12-07 | 관문 1 전 몫 짓기, 시험 |
| 12-08 ~ 12-11 | GPT(본체) · 카본 + Fable(화면) 검수 |
| 12-12 ~ 12-13 | 엔진 판 게시(설치 세션 도구), PC 판 게시(PC 판 절차), 이 PC 넘어오기 |
| 12-14 ~ 12-20 | 관문 1 「사람 한 번」을 솔리오 방에서 |

맞출 수 있다. 조건은 11-28까지 시안을 고르시는 것과, 권한 경계를 바꾸는 검수가 나흘 안에 배포 조건을 채우는 것이다. 지난 솔리오 입구 검수는 열 회차를 넘겼으므로 검수가 늘어지면 관문 1을 「엔진 창을 솔리오에서 여는 지금 길」로 하고, 한 몸 판은 2단계 노트북 시험 시작(12-21)에 맞춘다. 관문 1의 「사람 한 번」은 설치와 첫 보호의 길이라 지우기와 무관하다.
