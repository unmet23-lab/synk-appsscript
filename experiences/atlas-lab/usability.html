나를 이해하는 추천인지
직접 써 보고 확인해요.

처음 사용하는 성인 5~8명에게 한 명씩 보여주는 탐색용 사용성 확인 자료입니다. 추천을 이해하고 정정할 수 있는지, 소개와 첫 약속을 준비하면서 어디서 어려워하는지 관찰합니다.

현재 실제 참가자는 0명입니다. 아래는 준비된 과제와 빈 관찰지예요. 자동시험 결과를 사용자 만족도로 옮겨 적지 않습니다.

브라우저 인쇄를 사용하면 참가자 과제와 관찰지를 출력할 수 있습니다. 진행자 참고는 화면에서 별도로 펼쳐 확인하세요.

참가자에게 읽어 주세요

오늘은 서비스 화면을 확인하는 시간이에요. 가상 인물과 가상의 약속으로 사용해 주세요. 실제 연애 경험이나 개인정보를 말할 필요는 없어요. 잘 모르겠거나 하고 싶지 않은 과제는 건너뛰어도 괜찮아요. 화면을 보며 어떤 생각이 드는지 편하게 말해 주세요.

진행자가 상대 역할을 조작할 때는 알려 드릴게요. 상대는 실제 소개팅 상대가 아니며, 일정이나 응답도 체험용이에요.

참가자 과제

1. 추천을 이해해 보기

가상 인물의 기준으로 추천 화면을 살펴보세요. 가장 먼저 살펴보고 싶은 사람 한 명을 고르고, 왜 이 사람이 추천된 것 같은지 자기 말로 설명해 주세요. 아직 알 수 없는 점도 있다면 말해 주세요.

2. 잘못 이해한 기준 고치기

이 가상 인물은 연락 횟수 자체보다 바쁠 때 미리 알려주는 것을 중요하게 생각해요. 화면이 이 뜻을 잘못 이해했다고 느낀다면 원하는 방향으로 바꿔 보세요. 무엇을 바꿨고, 추천에 무엇이 달라졌는지 설명해 주세요.

3. 소개와 첫 약속 준비하기

살펴보고 싶은 가상 인물과 소개받고, 두 사람이 가능한 날을 골라 30분 동안 가상 카페에서 만나는 약속을 준비해 보세요. 지금 어느 단계까지 된 것인지, 상대의 확인이 더 필요한지 말해 주세요.

4. 서로 다른 방식 맞춰 보기

두 사람의 만남 준비 방식이 다르게 보입니다. 화면에 나온 방식보다 내가 편한 다른 방식이 있다면 상대에게 전해 보세요. 상대가 아직 답하지 않았을 때와 답한 뒤, 지금 무엇이 정해졌다고 이해하는지 설명해 주세요. 이후 생각이 바뀌었다면 내 뜻을 다시 전해 보세요.

5. 상황에 따라 괜찮은 범위 표현하기

새 가상 인물은 평소 매일 연락하는 사람을 더 선호해요. 다만 상대가 바빠지기 전에 알려주는 편이라면 며칠 간격으로 연락해도 괜찮다고 생각합니다. 원래 바람은 유지하면서 이 뜻이 추천에 반영되게 해 보세요. 무엇이 달라졌는지, 이 생각을 상대도 볼 수 있다고 이해하는지 말해 주세요.

6. 실수로 넘긴 사람 다시 살펴보기 · 선택

이번 추천에서 한 사람을 실수로 넘겼습니다. 다른 기준과 나머지 선택은 유지하면서 그 사람을 다시 비교해 보고 싶어요. 어떻게 할지 시도하고, 그 사람이 다시 보이지 않는다면 어떤 이유일 수 있는지 설명해 주세요.

7. 허용해 본 조건 돌아보기 · 선택

조건을 붙여 허용한 연락 방식이 사용된 추천을 살펴봤어요. 이 조건에 대한 지금 느낌을 나만 보게 남겨 보세요. 이후 허용 조건을 빼고 싶다면 달라지는 점을 확인한 뒤 결정해 주세요. 느낌을 남긴 것과 추천 기준이 바뀐 것을 어떻게 구분하는지 말해 주세요.

추가로 살펴볼 화면 · 선택

기본 과제 1~5는 그대로 진행합니다. 아래 8~10은 참가자의 여유와 확인하려는 화면에 따라 한 가지만 골라도 됩니다. 고르지 않은 과제는 건너뜀으로 남깁니다. 8은 별도 가상 환경에서 첫 설정부터, 9·10은 기본 과제 뒤에 진행합니다.

8. 작성하던 첫 설정 이어가기 · 선택

새 가상 인물의 이름과 짧은 소개를 적고, 공개·초대·계정 저장 범위를 원하는 대로 골라 보세요. 아직 첫 설정을 마치지는 마세요. 서비스 안의 다른 화면을 잠깐 둘러본 뒤 돌아와 작성을 이어가 보세요. 무엇이 저장됐고 무엇이 아직 작성 중인지, 지금 새로고침하면 어떻게 될 것 같은지 말해 주세요. 선택을 다시 확인한 뒤 첫 설정을 마쳐 주세요.

9. 저장된 공개 내용과 작성 중인 내용 구분하기 · 선택

가상 인물의 소개와 답 가운데 현재 공개하도록 설정한 내용을 찾아보세요. 그중 답 하나를 바꾸다가, 저장하기 전에 공개 내용을 다시 확인해 보세요. 지금 보이는 내용은 어느 쪽인가요? 다시 수정하던 곳으로 돌아가 바뀐 답을 저장한 뒤, 공개 내용에 무엇이 반영됐는지 설명해 주세요.

10. 나중에 볼 두 사람 보관하고 비교하기 · 선택

아직 소개를 요청하지 않고, 눈에 들어온 가상 인물 두 명을 나중에 다시 보고 싶어요. 두 사람을 보관한 뒤 다른 화면을 다녀와 찾아보세요. 내가 중요하게 보는 기준으로 둘을 나란히 비교하고, 보관했을 때와 비교했을 때 각각 무엇이 달라졌다고 이해하는지 말해 주세요.

독립된 가상 환경 시작

참가자마다 새 PowerShell 창에서 아래 명령을 실행합니다. 기본 체험 DB를 지정하지 않고 참가자용 임시 경로를 따로 만들어요. 출력된 주소를 참가자용 브라우저에 엽니다. 끝나면 이 창에서 Ctrl+C로 이 서버만 종료하세요.

Set-Location -LiteralPath 'C:\Users\q1212\Documents\SYNK-appsscript'
$env:SYNK_DATING_MODE = 'demo'
$env:SYNK_DATING_PORT = '0'
$env:SYNK_DATING_DB = Join-Path ([System.IO.Path]::GetTempPath()) ('synk-usability-' + [guid]::NewGuid().ToString() + '\demo.sqlite')
node experiences/atlas-lab/dating-server.mjs

실제 계정과 기존 ~/.synk/atlas-dating/demo.sqlite는 사용하지 않습니다. 임시 파일을 지우는 자동 작업은 없습니다. 관찰 자료에는 파일 경로·토큰·실명 대신 참가자 코드만 남겨 주세요.

가상 인물과 시작 상태

  1. 준비 단계에서 참가자 계정으로 /atlas-lab/dating.html?demo=sample-1을 엽니다. 추천에 필요한 확인을 가상 인물의 답으로 채웁니다: 주말 가능, 먼저 대화를 열고, 미리 계획함. 과제 2의 정정 전후를 비교할 수 있도록 본인 선호 wants.contact=daily를 일반 선호로 준비하고 필수 체크는 끕니다. 사전 예고 선호 wants.notice는 미확인으로 둡니다. 이 답들은 과제용 가상 설정이며 참가자의 실제 성향으로 기록하지 않습니다. 추천 화면으로 돌아온 뒤 참가자에게 넘깁니다.
  2. 별도 브라우저 프로필에서 상대 역할 ?demo=sample-3을 준비합니다. 상대는 주말 가능, 먼저 대화를 열고, 그때그때 계획하는 공개 답을 갖고 있습니다. 상대의 저장된 개인 답이나 회고는 참가자에게 보여주지 않습니다.
  3. 조율 확인에서는 서로 소개를 수락한 뒤 시작합니다. 이 단계까지 진행자가 도와줬다면 과제 3의 독립 완료로 세지 않고 도움 제공을 적습니다.

과제 5는 과제 2에서 바꾼 답의 영향을 받지 않도록 위 명령으로 별도 임시 서버를 하나 더 열고, 별도 브라우저 프로필의 ?demo=adult-a에서 시작합니다. 성인·저장·공개 등의 체험 동의와 추천에 필요한 답을 가상 설정으로 확인하고, 본인 선호 wants.contact=daily를 일반 선호로 준비합니다. 필수 체크는 끄고 다른 필수 선호를 추가하지 않습니다. 기존 예시 민서(sample-1)의 공개 답 self.contact=few-days, self.notice=advance를 비교에 사용합니다. 준비가 끝나면 참가자에게 기능 위치를 알려주지 않고 과제만 읽어 주세요.

진행 원칙

  • 첫 시도에는 버튼 이름이나 정답 절차를 알려주지 않습니다. 막히면 먼저 “지금 어떻게 이해했나요?”라고 묻습니다. 직접 도움을 줬다면 무엇을 알려줬는지 기록합니다.
  • 과제별 5분을 관찰용 종료 기준으로 제안합니다. 참가자가 중단하면 즉시 멈추고, 중단과 시스템 오류를 각각 기록합니다. 빠른 완료를 압박하지 않습니다.
  • 과제 2에는 여러 타당한 정정 경로가 있습니다. 연락을 “상관없음”으로 바꾸고 사전 예고 기준을 선택하는 등 본인 의도를 설명하는지 확인합니다. 진행자가 생각한 버튼을 누르는지만 채점하지 않습니다.
  • 과제 3에서 진행자가 상대의 소개·일정 응답을 직접 조작했다고 알립니다. 실제 상대의 자율 행동이나 두 기기 동작을 검증한 것으로 기록하지 않습니다.
  • 과제 4에서는 참가자가 고른 대안에 상대가 아직 답하지 않은 상태부터 관찰합니다. 상대 역할 조작을 알리고, 다른 방식이 필요하다는 답과 같은 대안을 확인한 답을 차례로 보여 주세요. 대안을 보내는 행위 자체나 이전 방식에 대한 동의를 새 대안의 양쪽 확인으로 세지 않습니다. 최신의 같은 대안을 두 사람이 각각 확인해야 합의이며, 약속 수락은 여전히 별개입니다.
  • 과제 5는 매일 연락한다는 원답을 지우거나 모든 연락 빈도를 허용하는 정정과 구별합니다. 참가자의 말과 행동에서 “사전에 알리는 공개 답이 확인될 때만 며칠 간격도 괜찮음”이 표현되는지 봅니다. 미리보기만 보거나 취소한 상태를 적용 완료로 세지 않습니다. 상대가 그 조건부 선호를 볼 수 있다고 오해하는지도 묻습니다.

화면에서 확인할 결과

과제 6은 현재 회차에서 직접 제외한 공개 후보 하나를 준비합니다. 다른 후보의 제외나 기간 숨김이 있다면 그대로 남는지 확인하고, 제외 취소가 소개·약속 수락을 복원했다고 이해하는지 관찰합니다. 상대가 공개를 철회했거나 필수조건이 달라졌다면 다시 비교할 수 없을 수 있으며 복구 성공으로 꾸미지 않습니다.

과제 7은 실제 선두 후보의 추천 이유에 조건부 연락 허용이 충족되었다고 표시되는 경우에만 시작합니다. 본인이 지금 추천을 돌아보는 행동으로 만든 기록을 사용하며, 옛 기록에 현재 조건을 소급해 붙이지 않습니다. 해당 후보가 없으면 이 선택 과제는 건너뜀으로 기록합니다. 회고 저장·철회는 비공개 느낌만 바꾸고, 허용 조건은 미리보기와 별도 적용 이후에만 바뀝니다. “괜찮음”은 현재 범위와 기한을 유지하며 이를 늘리거나 평소 선호로 승격하지 않습니다. 후보를 본 느낌과 상대의 실제 행동·만남 경험을 혼동하지 않는지 관찰합니다.

추천 이유는 선언된 조건의 비교이며 호감·연애 성공 확률을 뜻하지 않습니다. 개인 기준과 공개 답은 따로 바뀝니다. 첫 만남 조율은 현재 공개한 계획·대화·사전 예고 방식 중 확실한 차이 하나가 있을 때만 표시합니다. 현재 공개 근거가 같거나 미확인이면 질문을 억지로 만들지 않습니다.

조율은 건너뛰어도 약속을 정할 수 있습니다. 내 답은 상대에게 공유되며 다른 방식이 필요하다는 답도 남길 수 있습니다. 공개 답·쉬기·소개 세대가 바뀌면 옛 합의는 복원되지 않습니다. 첫 수락된 약속의 시작 이후에는 조율을 다시 사용하지 않습니다. 시작 시각은 실제 만남 여부의 증거가 아닙니다.

새 대안이 오면 그 대안에 대한 양쪽 응답을 새로 확인합니다. 이미 보낸 일정·장소·수락은 대안 변경 때문에 자동으로 고쳐지지 않습니다. 상대가 답하지 않거나 서로 다른 생각을 남긴 상태에서 화면을 합의로 이해했다면 그대로 기록합니다.

조건부 선호는 본인만 사용하는 추천 기준입니다. wants.contact=daily 원답은 유지하고, 현재 공개된 self.notice=advance가 확인되는 후보에게만 few-days를 추가로 허용합니다. 공개하지 않은 답·미확인 답으로 조건을 충족했다고 채우지 않으며, 조건부 선호 저장이 본인 공개 프로필을 바꾸지 않아야 합니다. 참가자 관찰 뒤 진행자가 별도로 “매일 연락”을 필수로 바꿔 확인할 때에는 그 필수조건이 우선합니다. 이 추가 검사는 참가자 독립 완료에 합산하지 않습니다.

선택 과제 8 · 첫 설정 준비와 확인

준비: 위 명령으로 새 임시 서버를 열고 별도 브라우저 프로필의 /atlas-lab/dating.html?demo=adult-a에서 시작합니다. 소개·성인 여부·동의가 저장되지 않은 첫 화면인지 확인합니다. 기능 위치를 먼저 안내하지 말고 참가자에게 가상 인물만 사용하도록 다시 알립니다. 기존 기본 과제의 준비 계정과 섞지 않습니다.

확인: 같은 브라우저 탭에서 설정 화면에 들렀다가 첫 설정을 이어갈 때 이름·소개·직접 고른 체크 상태가 남는지 봅니다. 작성 중인 입력과 ‘저장된 설정’ 요약을 구분하는지, 필요할 때 ‘자세히 보기’를 펼쳐 저장된 항목과 남은 선택을 확인할 수 있는지 관찰합니다. 화면 이동이나 설명 펼치기만으로 저장하거나 동의한 것으로 세지 않습니다. 공개·초대·계정 저장은 모두 선택 사항이므로 켜도록 유도하지 않으며, 참가자가 고른 상태로 ‘첫 설정 마치기’를 완료했는지 확인합니다. 성인 여부 체크는 본인 진술이며 인증 완료가 아닙니다.

복구 범위: 보내지 않은 내용은 현재 탭의 메모리에만 남아 새로고침·탭 종료 뒤에는 복원되지 않습니다. 과제 중 새로고침은 요구하지 않고 예상만 묻습니다. 다른 곳에서 저장한 원본이나 계정 접근 상태가 바뀌면 기존 초안이 사라질 수 있습니다. 전송 뒤 응답을 잃어 저장 여부를 확인하는 절차는 별개이며, 이번 과제의 화면 이동 복구와 합쳐 기록하지 않습니다.

선택 과제 9 · 공개 미리보기 준비와 확인

준비: 첫 설정이 끝난 가상 계정에서 프로필 공개가 켜져 있고 유효한 공개 답 하나가 저장되어 있는지 확인합니다. 예를 들어 공개 연락 방식 self.contact=daily를 저장하고, 참가자에게는 가상 인물의 현재 뜻이 ‘며칠에 한 번’으로 바뀌었다고 알려 주세요. 시작 시 저장된 답과 공개 상태를 관찰지에 남깁니다.

확인: 미리보기의 수정 동작에서 해당 입력으로 이동하고, 저장 전에 돌아오면 이전에 저장한 답이 보이는지 확인합니다. 같은 항목을 다시 수정할 때 작성 중인 답을 이어가고, 별도 확인·저장 뒤 원래 미리보기의 바뀐 항목으로 돌아오는지 봅니다. 참가자가 초안·저장된 공개용 내용·현재 공개 여부를 구분해야 하며, 비공개 추천 답이나 회고가 자동 공개됐다고 이해하면 그대로 기록합니다. 미리보기는 상대별 추천 순서나 실제 노출의 증거가 아닙니다. 준비 중 공개를 껐다면 ‘저장한 공개용 내용’으로 표시되는 상태를 공개 중으로 채점하지 않습니다.

선택 과제 10 · 보관과 두 후보 비교 준비와 확인

준비: 참가자용 가상 계정의 계정 저장이 켜져 있고 현재 비교 가능한 공개 후보가 두 명 이상인지 확인합니다. 현재 추천 중요도와 소개 요청 상태를 적어 두고, 두 후보의 선택·보관은 참가자에게 맡깁니다. 후보가 부족하면 필수조건을 낮추도록 유도하지 말고 준비 조건 미충족으로 건너뜁니다.

확인: ‘나중에 다시 보기’로 보관한 두 사람을 다시 찾고, 정확히 두 명을 골라 실제 비교 화면으로 이어가는지 봅니다. 정해 둔 추천 중요도가 없으면 비교할 기준을 한두 개 고르는 단계까지 관찰합니다. 보관은 본인만 보는 목록이며, 보관·비교는 소개 요청이나 추천 중요도 변경이 아닙니다. 비교는 현재 공개 답의 차이이므로 호감이나 사람 전체의 우열로 해석하면 기록합니다. 상대가 공개를 철회하는 등 현재 비교할 수 없게 되면 옛 소개·답을 복원하지 않습니다. 이 경우 중단 원인을 따로 적고 두 사람 비교 완료로 세지 않습니다.
