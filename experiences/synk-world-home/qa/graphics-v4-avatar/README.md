# 몽글 재질·코스튬 마감 v4

2026-10-09. `avatar-v3.mjs`의 공유 API와 캐릭터 ID를 유지하며 재질 revision을 4로 높였다. 최종 승인 모델이나 실기기 성능 결과가 아니다.

## 실제 변경

- 승인 `assets/felt-coral.webp`를 색 원본으로 유지하고 사진을 bump 높이로 쓰던 연결을 제거했다. 작은 양모 표면의 normal·roughness를 독립적으로 만들고 몸의 UV를 높이 기준으로 정돈했다. 미세 기모 선은 길이·개수를 줄였다.
- 두 검은 눈의 크기·위치를 유지하며 강한 파란 환경 반사를 낮췄다. 종형 몸, 정면 다섯 물결 밑단, 입과 팔 없는 형태는 바꾸지 않았다. 몸체 bounds도 기존과 같다.
- 니트는 둥근 V자 실고리, 면은 더 가는 교차 조직을 사용한다. 표면 높이·색·거칠기를 분리하고 AO와 roughness는 R/G 채널을 공유한다. 신체·주머니·목도리 접촉부는 약한 vertex colour 음영을 가진다.
- 목도리 끝을 몸의 곡면에 맞춰 붙이고, 앞치마 끈이 몸속을 직선으로 통과하던 경로를 외곽으로 수정했다. 주머니는 본체 곡면에 맞춘 볼륨, 안쪽 면, 접힌 윗단을 가진다. 모든 의상 면의 두께와 슬롯 이름은 유지한다.
- 색 정점이 없는 실·장식 메시에도 흰 COLOR0를 넣어 vertex-colour 재질에서 검게 표시되던 작은 프린지·음표를 바로잡았다.

- [렌더 기록](capture.json): PC 900×850 및 휴대폰 **뷰포트** 390×500, 네 차림×낮·노을 16장과 측면 2장. 콘솔·런타임 오류 0. 마지막 packed map 변경 후 PC·390 대표 동시착용 이미지를 직접 확인했다.
- [공유 계약 검사](avatar-contract-check.json): 20개 통과. 네 차림 표시, 알 수 없는 아이템 차단, 유한 정점, 발바닥 원점, 움직임 줄이기, 자원 단일 해제 확인.
- [로딩 검사](loading-checks.json): 6개 통과. 색 이미지 실패 시 표면 대체·실패 metrics, 사진/normal 분리, packed map 공유, 정점 색 누락 방지, 12초 로딩 기한, 늦게 도착한 텍스처 해제. 기한 분기는 테스트에서 타이머만 짧게 바꿔 검사했다.
- factory 생성은 이 PC의 headless Edge에서 PC 뷰포트 558ms, 휴대폰 뷰포트 422ms였다. 캔버스 표면 제작과 색 이미지 로딩을 포함하고, 이후 셰이더 컴파일·앱 전체 시작 시간은 포함하지 않는다. S25·iPhone 15 측정이 아니다.
- 검토 스튜디오 전체 GPU 텍스처는 packed map 적용 전 16개에서 13개로 감소했다. 동시착용은 바닥 포함 55 draw calls / 44,942 triangles. FPS·발열·배터리 수치를 뜻하지 않는다.

## 소비처와 내보내기

`createMongleAvatar()`는 같은 `{group,setOutfit,update,getOutfit,metrics,dispose}`를 반환한다. `metrics`에 `materialRevision:4`, `assetFailures`가 추가됐다. 유일한 외부 텍스처 요청은 기존 펠트 색 이미지이며 12초 기한 뒤에는 절차형 대체 표면을 사용한다. 이미지가 늦게 도착하면 즉시 해제한다.

새 로컬 모듈 `avatar-textiles.mjs`를 함께 제공해야 한다. 독립 Town 서버의 파일 허용 목록도 이 모듈을 포함해야 한다. 새 이미지 생성·다운로드·유료 API를 사용하지 않았다.

후속 GLB는 COLOR0·normalMap/normalScale·AO(R)/roughness(G)·텍스처별 repeat·sheen·clearcoat를 보존해야 한다. 새 내보내기와 Blender 확인은 별도 담당 결과를 따른다. 본·실시간 천 시뮬레이션·Unity 가져오기·네이티브 렌더를 이번 재질 수정으로 완료했다고 해석하지 않는다.
