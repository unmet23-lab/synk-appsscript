# 강변 원경 v5 검수

2026-10-09. `scene-v3-garden.mjs`의 `makeLandscape`만 바꿨다. 근경 정원 함수는 작업 시작 시점과 동일하며, 별도 라이브러리·온라인 이미지·후처리 패스는 추가하지 않았다.

## 달라진 풍경

- 70개 건물을 세 깊이로 배치했다. 낮은 강변 건물, 뒤로 물러선 중층 테라스, 가느다란 유리 탑이 서로 다른 높이를 만든다. 옥상 녹지와 전망대도 추가했다.
- 원경 창문 2,872개는 얇은 입체 상자 대신 삼각형 두 개의 면이다. 정면과 측면은 실제 건물 면을 따른다.
- 강변 수목과 옥상 수목은 비대칭 수관 185개를 한 번에 그린다. 창문·구조체·테라스·난간도 재질별로 합쳐 그린다.
- 산은 세 겹의 불규칙한 능선, 계곡, 수목 색 변화를 정점 데이터에 담았다. 이를 위해 픽셀마다 노이즈를 계산하지 않는다.
- 강변 산책로, 물가 계단, 교각·난간·완만한 아치를 더했다. 물은 기존 공통 수면 재질을 그대로 사용한다.
- 기존 `group`, `ridgeMaterials`, `buildingMaterials` 반환과 재질·텍스처 소유 방식은 유지했다.

## 실제 비교

`node experiences/synk-world-home/qa/graphics-v5-landscape/compare.cjs`

`before-garden.mjs`는 이 작업 시작 시점의 비교용 소스다. 두 풍경을 **같은 현재 scene 소스·같은 아바타**로 번갈아 렌더하므로 조명이나 캐릭터의 병행 변경과 원경 비용을 분리한다. 실제 사용한 소스 SHA는 `comparison.json`에 기록했다. 캡처는 PC 1400×720과 휴대폰 크기 390×465, 낮/노을 네 구성이며 이미지 8개를 보존한다.

| 고정 조건 비교 | 이전 원경 | v5 원경 |
|---|---:|---:|
| PC 전체 삼각형 | 252,776 | 258,724 |
| PC draw calls | 168 | 166 |
| 휴대폰 크기 전체 삼각형 | 203,792 | 209,740 |
| 휴대폰 크기 draw calls | 134 | 132 |

총 삼각형은 PC 2.35%, 휴대폰 크기 2.92% 증가했고 draw call은 두 개 줄었다. 초기 시안의 다각형 수관과 단순 구형 수관을 실제 캡처로 확인한 뒤 비대칭 수관과 얇은 창문 면으로 다시 마감했다.

13개 검사가 통과했다. 런타임·셰이더 오류 0, 생존 캔버스 하나, 정점·노멀·인스턴스 행렬의 유효값, 동일 seed의 동일 배치, 공통 물 재질, 삼각형·draw call 예산을 확인했다. CPU render submission 중앙값은 해당 실행에서 PC 3.7→4.2ms, 휴대폰 크기 3.7→4.0ms였다. **이는 GPU 시간·실제 FPS·Galaxy S25/iPhone 15의 지속 성능 측정이 아니다.** 병행 개발·헤드리스 브라우저의 영향을 받을 수 있는 진단값이다.

`node --check`와 범위 지정 `git diff --check`를 통과했다. 근경 함수가 비교용 소스와 같음을 확인했다. 휴대폰 크기에서 몽글의 얼굴과 코스튬을 가리지 않으며 낮/노을에 공간이 같은 광원을 따르는지 캡처를 직접 확인했다. 이후 공통 조명·시점이 바뀌면 루트 작업의 최종 화면 검수가 이 비교 캡처보다 우선한다.

본 원경은 절차적 시제품 미술이다. 정식 환경 자산·거리별 LOD·Unity 재질 이식·실제 휴대폰의 발열과 장시간 성능은 별도 작업이다.
