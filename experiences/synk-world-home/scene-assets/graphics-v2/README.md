# WORLD 그래픽 2차 검토

2026-10-09. 사용자가 현재 홈보다 큰 폭의 향상과 최소 레이싱 미니게임 이상의 품질을 요청했다. 기존 홈은 보존하고 비교용 장면을 별도로 제작했다. 이번 결과를 최종 품질 달성이나 최종 몽글 모델 승인으로 해석하지 않는다.

## 보는 곳

기존 WORLD 로컬 서버를 `node experiences/synk-world-app/server.mjs`로 실행한다.

- 비교: http://127.0.0.1:4296/graphics.html — 이전/개선안, 낮/노을, 기본/목도리/앞치마/동시 착용.
- 휴대폰 홈: http://127.0.0.1:4296/mobile.html?graphics=2
- PC 홈: http://127.0.0.1:4296/desktop.html?graphics=2
- 쿼리 없는 기존 홈과 `scene.mjs`는 유지했다.

## 왜 현재 홈이 부족한가

현재 레이싱의 실제 저장 화면과 소스를 비교했다. 레이싱은 완성 차량 메시·재료별 표면·하늘과 일치하는 환경 반사·지형/수면·전경부터 원경까지의 공간으로 화면을 만든다. 기존 홈은 기본 몸체와 소품 메시, 단순한 원경, 넓고 고른 조명으로 구성되어 확대했을 때 모형 같은 인상이 강하다. 엔진 이름이나 해상도만 바꿔 해결할 차이가 아니다.

사용한 현행 근거: `experiences/korean-racing/README.md`, `qa/GRAPHICS-V9.md`, `qa/한판_컴퓨터.jpg`, `qa/graphics-v9-homes-4k-20261004.png`. 레이싱의 옛 기록만으로 현재 공개 상태나 실기기 성능을 추정하지 않았다.

## 이번 비교안

`scene-v2.mjs`, `scene-v2-garden.mjs`를 추가해 고정된 정원·집 전면·목재 구조·석재 바닥·식생과 실제 하늘 파노라마의 빛 반응을 연결했다. 몽글의 승인된 종형 몸·물결 밑단·두 눈·팔 없는 형태는 유지하고 목도리/앞치마 표현을 보완한다. 배경과 PMREM 환경 반사는 낮/노을별로 일치시킨다.

새 잎과 반복 부품은 인스턴스로 묶고, 휴대폰 해상도 상한·30Hz 홈 움직임·화면 밖 정지·움직임 줄이기·자원 해제를 유지한다. 이는 효율을 위한 구현이며 S25/iPhone 15의 실제 지속 프레임·발열을 측정했다는 뜻은 아니다.

하늘과 지형 노멀은 레이싱의 기존 자산을 바이트 그대로 재사용했다. 새 생성·유료 API 호출·이미지 리터칭은 없다. 파일별 SHA와 출처는 [provenance.json](provenance.json)에 있다. 맑은 낮/노을 파노라마는 당시 SYNK 생성 자산이며, 돌·지형 노멀은 기존 Poly Haven CC0 자산이다.

## 한 단계 더 올리기 위한 본 제작

| 우선순위 | 제작할 것 | 화면에서 확인할 차이 |
|---|---|---|
| 1 | 승인 몽글의 정식 3D 마스터·표정/변형·옷 슬롯 | 확대해도 얼굴·몸 비율과 밑단·봉제선이 자연스럽다 |
| 2 | 옷의 안팎 두께·주름·재봉·니트/면별 표면 및 조합 가림 | 목도리가 튜브처럼, 앞치마가 딱딱한 판처럼 보이지 않는다 |
| 3 | 재료별 색·요철·거칠기·접촉 어둠을 구분한 텍스처 | 표면에 무늬를 얹은 느낌을 줄이고 빛에 맞춰 재료가 반응한다 |
| 4 | 집 한 채와 정원 한 구역의 완성 조명·소품·생활 흔적 | 공간과 캐릭터가 같은 빛 아래 실제로 접지된다 |
| 5 | 눈 깜박임·시선·몸의 눌림/회복·옷의 제한된 움직임 | 정지 모델을 넘어 살아 있는 캐릭터로 느껴진다 |

Blender에서 고해상도 조형과 게임용 메시·UV·뼈대·거리별 모델을 만들고, 미세 표면을 텍스처로 구워 Unity URP의 공통 자산으로 가져간다. 홈·옷장·타운·사진마다 다른 캐릭터를 새로 만들지 않는다. 의상마다 실시간 천 물리를 필수로 하지 않고 작은 뼈대/변형과 가림 규칙으로 먼저 해결한다.

휴대폰은 고정된 공간의 간접광과 반사를 미리 계산하고, 몽글·의상과 핵심 그림자에 실시간 계산을 집중한다. PC는 같은 모델에서 그림자·식생·해상도·효과를 확장한다. Unity 공식 [URP 성능 설정](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/configure-for-better-performance.html)은 그림자·추가 패스·반사 등의 비용을 실제 프로파일러로 확인하도록 안내한다. [SSAO 설정](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/ssao-renderer-feature-reference.html)도 비용과 품질을 함께 조절해야 하므로 모든 효과를 켠 상태를 기본 목표로 삼지 않는다.

## 완료 기준

1. 실제 움직이는 화면을 레이싱과 같은 기기·해상도에서 비교한다. 해상도만 높은 정지 이미지로 통과시키지 않는다.
2. 몽글 접사, 홈 전체, 낮/노을, 기본 차림과 두 아이템 동시 착용을 모두 본다.
3. S25/iPhone 15에서 20분 실행 후 홈 30fps 안정성을 우선 목표로 측정한다. 이 값은 다음 검증 목표이며 현재 달성 기록이 아니다.
4. 로그인·보상·차림 저장·접근성·낮은 품질 복원도 유지한다.
5. 한 구역이 목표 미감에 도달하면 같은 자산·빛 기준을 타운과 콘텐츠에 확장한다.

브라우저 검사 43항목 통과, 오류·누락 자산 0건. [검수와 수정 내용](../../qa/graphics-v2/README.md), [검사 결과](../../qa/graphics-v2/verification.json), 같은 폴더의 PC·390·320 캡처를 확인한다. 작은 휴대폰의 시작 버튼 가림과 반복 전환 시 GPU 자원 해제 누락도 수정했다. Unity 앱·네이티브 GPU·실기기·최종 마스터 검증과 구분한다.
