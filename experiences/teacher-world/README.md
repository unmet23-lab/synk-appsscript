# SYNK WORLD · 교사 — WORLD 수업 연결 MVP

학생 WORLD와 별도 창·세션을 사용하는 교사 앱이다. 제품 이름은 기능을 설명하는 현재 표기이며 새로운 브랜드명은 확정하지 않았다. 플랫폼 라이브러리의 교사 항목에서 독립 개발 클라이언트를 연다.

## SYNK ID로 연결하는 독립 교사 앱 · 2026-10-04

`desktop`에서 `npm run dev:teacher` 또는 소스 개발 플랫폼의 **교사 앱 미리보기**를 실행한다. WORLD와 별도 프로세스·세션·암호화 저장소를 사용하고, `synk-account/teacher.html`에서 로그인한 교사의 실제 담당 반만 연다. 교사 앱의 OAuth 클라이언트는 `clients.teacher`이며 수업 API 제품은 기존 `world`다. 학생 WORLD의 토큰을 복사하거나 교사 역할을 화면에서 선택하지 않는다. 로그인 설정이 없으면 준비 화면을 보여 준다.

WORLD의 개인 학습 저장 동의와 반 공유 동의를 분리했다. 고른 도움 방식·표시 설정·게임별 순간 맞춤 기억은 개인 계정에 저장해 수업과 개인 연습에서 이어 쓴다. 교사에게는 공유한 학습 근거만 제공하며 개인 맞춤 설정은 자동 공유하지 않는다. **오늘 컨디션은 해당 기기에만 남긴다.** 반 공유를 꺼도 개인 저장 동의가 켜져 있으면 개인화 설정을 계속 동기화한다.

수업·계정 변경, 로그아웃, 권한 철회는 기존 화면의 접근도 막는다. 일시적인 네트워크 오류 때는 이미 시작한 게임과 전송 대기 기록을 보존하고 연결 후 재시도한다. 서버가 권한·동의를 거절하면 이 보존 경로를 쓰지 않는다.

현재 검증에는 합성 계정과 임시 DB만 사용한다. 공개 OAuth 등록, 신규 수업 서비스의 운영 배포, 서명·설치·업데이트, Mac·모바일 실기기는 사용자가 미룬 출시 단계에 남겨 두었다.

## 별도로 유지하는 로컬 연결 체험 · 2026-10-02

`desktop`에서 `npm run dev:classroom`을 실행한다. 로컬 연결 서버(4295)와 별도 세션의 교사·WORLD 창을 함께 연다. 이 체험은 위 SYNK ID 교사 앱과 다른 진입이며 일회용 연결 코드를 사용한다. 창 하나만 닫은 뒤 다시 실행해도 닫은 창을 복구한다. 설치 패키지는 다시 만들지 않았다.

1. 교사 창에서 학생 이름을 입력해 10분짜리 일회용 연결 코드를 만든다.
2. WORLD 창에서 코드와 공유 범위를 확인하고 연결한다. 가상 학습 기록은 미리 넣지 않는다.
3. **기존 WORLD `account-view`와 `world-learning-host`**가 실제 미니게임을 연다. 새 읽기 연습과 교사 과제함도 같은 WORLD 화면에 있다. 교사 데모의 `/student` 화면을 WORLD로 대체 표기하지 않는다.
4. WORLD의 실제 문항 수행 → 교사 학습 근거·추천 → 교사 승인 과제 → WORLD 과제함 → 서버 채점·교사 결과까지 연결한다. 두 화면은 5초마다 상태를 갱신하며 새로고침도 지원한다.

읽기 활동은 **4개/13문항**이다. 읽기 오답 뒤에는 같은 영역의 다른 지문 또는 입장 검사 등 실제 연결 가능한 콘텐츠를 제안한다. 같은 문항의 재풀이를 새 독립 표본으로 세지 않는다. TOPIK I 읽기 중 세부 정보·부정 표현·조건 이해 연습이며 급수나 학습 향상을 입증한 결과는 아니다. 신규 문항의 교육 현장 검수는 별도다.

게임 자유 연습 사건은 기존 Core·Trail·Strata를 거쳐 교사 근거로 전달한다. **게임 보고 정오와 서버 채점을 구분**하고 조작 점수·음성 실패·도움 받은 수행을 독립 언어 숙달로 바꾸지 않는다. **7게임과 Town 읽기 확인을 교사 과제로 배정할 수 있다.** 레이싱은 듣기·읽기를 별도 진입으로 제공하며 빈칸 베기를 포함해 총 9개 게임 활동이다. `game-catalog.mjs`는 실제 콘텐츠의 난도·응답 형식·문항군을 읽어 추천 후보를 구성하며, `learning-runs.mjs`는 학생/공유판/배정판에 묶인 수행을 관리한다.

### 전체 콘텐츠의 로컬 학습 왕복

- 과제/자유 연습 시작 → 서버가 고정한 목표·수행 ID → 기존 게임 실제 실행 → 제시·도움·응답 사건 전달 → 지정 영역·난도·응답 형식과 실제 문항이 일치하는 응답 확인 → 교사 결과·다음 추천. 목표 문항은 실제 보유량 안에서 최대 3개이며 다른 유형으로 부족분을 채우지 않는다. 완료는 정답률 통과나 급수 판정이 아니다.
- 사건이 발생할 때 수행 ID를 기기 저장소에 고정한다. 전송 지연·다른 게임 전환·재시도 때문에 옛 기록이 새 과제에 붙지 않는다. 다른 계정·동의판·콘텐츠·수행의 사건 연결을 서버에서 거절한다. 중단한 과제는 기존 진행을 이어 쓴다.
- 과제 수정·취소·공유 철회·계정 종료 시 열린 게임을 닫는다. 취소된 수행의 뒤늦은 기록은 허용된 개인 연습 근거로 보존하지만 취소한 과제를 완료로 되살리지 않는다.
- 읽기 서버 채점도 공통 Atlas 사건으로 내려보낸다. 교사뿐 아니라 다음 게임의 Core 추천이 같은 읽기 근거를 사용하며, 교사 집계에는 한 번만 센다.
- 바람길은 기존 주행과 별도 MP3 듣기 확인을 분리한다. 장애물·조작 결과는 평가 제외, 같은 음성 재노출은 반복, 다시 듣기는 도움이다.
- Town은 local-linked 학생별로 FT10/FT51 생활 상태를 분리한다. 일반 Town의 입장 검증 잠금은 유지한다. 별도 안내 읽기 18문항 중 목표에 맞게 고른 문항만 학습 근거이며 생활 행동·취향·호감도는 평가하지 않는다.
- WORLD의 ‘오늘의 과제’에는 교사가 배정한 읽기/게임을 함께 표시하고, ‘오늘의 학습 안내’는 공유된 실제 근거와 같은 Core 추천을 사용한다. **이 안내를 외부 모델의 AI 대화·평가로 표시하지 않는다.** 운영 synk-account·synk-learning, 음성/쓰기 교정·AI 대화의 연결은 운영 인증/자료 매핑과 함께 별도 단계다.
- 각 게임의 자유 플레이 결과는 `game-reported`, 읽기는 `server-scored`로 구분한다. 게임은 브라우저가 보고한 정오를 서버가 독립 재채점한 것으로 과장하지 않는다.

- `linked-server.mjs`의 `.local/linked-state.json`은 예전 `.local/demo-state.json`과 분리한다. 시작 시 기존 합성 데모 상태를 거부한다.
- 로컬 교사 키는 `.local/linked-owner.key`, 세션은 역할별 무작위 토큰으로 분리하며 서버에는 해시만 저장한다. 학생 ID·교사 역할을 요청 본문이나 URL로 선택할 수 없다. 창 저장소에는 현재 연결 토큰만 둔다.
- 공유 철회·재동의마다 revision을 바꾼다. 이전 근거·과제·관찰을 새 동의로 되살리지 않으며 다른 학생 제출, 만료·재사용 코드, 오래된 배정판을 거절한다. 읽기 과제의 지문·문항·정답은 배정 당시 서버 스냅샷으로 고정하고 제출 전에는 정답·해설을 보내지 않는다.
- 중복 요청은 한 번만 반영하고 저장 실패는 성공으로 응답하지 않는다. 초기 연결 후 조회 장애는 일회용 코드를 버리지 않고 기존 토큰으로 재시도한다. 로그아웃·교사 연결 해제는 열린 게임과 과제 화면도 정리한다.
- 이 일회용 코드 체험은 SYNK ID 앱의 정식 인증 대용이 아니다. SYNK ID 수업 연결은 위 독립 교사 앱과 아래 계정 경로를 사용하며, 원격 기관·실학생 운영은 배포 후 별도로 검증한다.

서버만 실행하려면 `node experiences/teacher-world/linked-server.mjs`를 사용한다. WORLD는 `http://127.0.0.1:4295/synk-account/local-world.html`, 교사는 `http://127.0.0.1:4295/`이며 직접 접속한 교사 화면에는 로컬 교사 키가 필요하다.

### 학생별 목표를 실제 출제로 연결 · 2026-10-02 후속

- `model.mjs`의 `gameTargetFor`는 기존 Core 추천에서 고른 영역·난도·응답 형식과 해당 콘텐츠의 **실제 문항군/문항 쌍**을 고정한다. 교사는 배정 전에 목표·문항 수·새 문항/복습 수를 확인한다. 교사 화면의 자동 갱신도 작성 중인 목표를 바꾸지 않는다. 한 과제를 여러 학생에게 보낼 때도 `targets[learnerId]`를 분리한다.
- `learning-runs.mjs`의 `run.target` → 공통 WORLD 호스트의 `coach.assignment()` → 각 게임의 기존 출제 경로로 이어진다. 레이싱은 목표 코스, 리듬은 목표 문항이 있는 곡, 주문은 목표 주문 묶음, 입장 검사는 목표 손님과 근무지, 스토리는 목표 부탁과 필요한 앞 행동, 바람길/Town은 목표 확인 문항을 사용한다. 일반 자유 플레이의 기존 게임 동작은 유지한다.
- 서버는 지정 skill/difficulty/modality/responseFormat과 실제 family/item 쌍이 모두 맞아야 완료 수에 넣는다. 다른 곡·다른 영역·임의 문항 이름·같은 문항 반복으로 완료할 수 없다. 출제가 한 문항뿐인 리듬의 특정 목표는 1문항임을 표시하며 세 문항으로 과장하지 않는다. 수정·취소·공유판 변경·계정 종료 경계는 유지한다. 목표가 없던 구판 미완료 수행은 새 목표로 시작하고 과거 완료 기록은 보존한다.

## 작동하는 흐름

1. 반·학생 선택 → 독립 문항 수·정답 수, 최근 기록, 도움 받은 수행, 판단할 자료 부족을 구분한다.
2. 기존 `atlas/learning.js`의 Core와 `strata/index.js`의 TOPIK I 지도를 직접 호출해 다음 연습과 근거를 표시한다. Vellum의 학습 이유 문구는 Core를 통해 재사용한다. 별도 아홉 번째 엔진이나 AI 실행기는 만들지 않았다.
3. 교사는 추천을 검토·변경하고 마감일·안내를 정해 과제를 배정한다. 제목·안내·마감 수정과 취소도 가능하다. 최초 추천 근거와 교사의 변경 이유를 보관한다.
4. 학생 과제 체험에서 실제 지문을 읽고 답한다. 서버가 채점해 교사 결과와 다음 추천에 반영한다. 공통 읽기 카탈로그는 현재 **4개/13문항**이다.
5. 교사는 학습 영역을 선택해 관찰을 남긴다. 관찰은 정답률이나 실력 판정으로 자동 변환하지 않는다.

나래는 읽기 세부 정보, 보라는 듣기, 다미는 오래된 부정 표현 기록의 재확인, 로안은 도움 받은 조건 읽기 뒤의 확인을 제안받는다. 게임 조작 점수는 언어 수행 근거에서 제외하고 같은 문항 재배정으로 독립 표본을 늘리지 않는다. 추천은 연습 우선순위이며 TOPIK 급수·성격·학습 효과 판정이 아니다.

이전 합성 데모는 읽기 네 가지를 배정한다. 새 local-linked 연결판은 읽기와 게임 과제를 모두 지원한다.

## 저장과 접근 경계

- `.local/demo-state.json`에 과제·체험 답안·관찰·감사 이력을 저장한다(Git 제외). 요청을 직렬 처리하고 임시 파일 저장 후 교체하며 디스크 실패 시 성공이나 메모리 반영으로 처리하지 않는다.
- 생성·제출·관찰 재시도는 요청 식별자로 중복을 막는다. 모델이 교사 소속 반과 학생 배정 범위를 확인한다. 제출 전에는 정답·해설을 보내지 않는다.
- 데모의 교사는 고정 예시 계정이고 학생 선택기는 **체험용 역할 전환**이다. 운영 인증을 완성했다는 뜻이 아니다. `synthetic:true`, `mode:demo`가 아닌 자료·호출을 거절한다.
- 정적 파일은 화면·승인 자산만 제공하며 모델·정답·서버·저장 파일은 노출하지 않는다. 외부 Origin/Host를 거절하고 쓰기에 로컬 체험 토큰을 요구한다.
- PC 앱은 `im.synk.teacher.preview` 별도 프로세스·프로필·세션이다. 계정 토큰과 플랫폼 설치·회사 자료 IPC를 받지 않는다. 기존 OAuth·3제품 배포 계약에 교사 권한을 끼워 넣지 않았다.

## 실제 WORLD 연결 단계

2026-10-02의 [연결 설계안](../../docs/아틀라스_구현명세.md#world-teacher-learning-loop) 이후 로컬 연결판을 구현했고, 10-03에는 아래 SYNK ID 기반 연결을 추가했다. 폐기된 talk 과제 API를 복원하지 않는다.

기존 4290은 **교사 MVP의 합성 학생 체험**, 4295는 **WORLD·교사 간 로컬 연결 체험**이다. SYNK ID 연결은 별도의 `account-linked` 경로이며 다음 계약을 구현했다. 새 서버 함수와 DB 변경은 아직 배포하지 않았다.

- SYNK ID → 교사 기관·반 / 학생 `learner_id` 매핑. 직원 역할만으로 학생 자료 접근을 허용하지 않는다.
- 동의와 조회 범위를 확인한 뒤 콘텐츠 출처·문항 ID·응답 방식·도움·시각을 보존한 학습 자료를 제공한다.
- 배정을 기존 WORLD 과제함으로 보내고 실제 콘텐츠의 제출 사건을 같은 배정 ID로 회수한다. 조작 점수와 언어 문항 수행을 구분한다.
- 데모 역할 선택기를 제거하고 제품별 SYNK ID 세션·서버 검증으로 대체한다. WORLD 토큰·원본 기록을 다른 앱 저장 공간에 복사하지 않는다.

정식 로그인, 공개 업데이트, 추가 배포 패키지·실제 설치 검증은 사용자 결정대로 **MVP 이후**다. Windows 개발 창과 320·390px 반응형 화면을 검사했으며 macOS·Android·iOS 실제 기기·스토어 설치는 미검증이다.

### SYNK ID 연결 구현·로컬 검증 — 2026-10-03

- WORLD 계정 화면은 서버가 확인한 수업만 보여 준다. 교사는 `staff_classes`에 배정된 반만, 학생은 현재 `learners.class_id`의 자기 기록만 이용한다. 별도 교사 화면을 같은 로그인 호스트 안에서 열며 iframe에 인증 토큰을 넘기지 않는다. 데스크톱은 기존 인증 IPC의 고정 작업 목록을 사용한다.

`personalization-ui.mjs`와 Core의 `atlas/personalization.js`를 연결했다. 교사는 목표·반/개별·수업/준비 시간·원하는 도움을 고르면 단계별 수업안과 실제 과제 작성창의 안내·마감이 바뀐다. 학생은 시간·소리 환경에 맞는 후보와 단계별/혼자 풀기 방법을 받고 큰 글자·설명량·적은 움직임을 선택한다. 승인 LAB 코럴과 실제 펠트 색면도 적용했다.

응답하지 않은 값은 답변·자기보고 출처로 저장하지 않고 계산에서만 기본값을 사용한다. 선택 없이 이용·끄기·삭제가 가능하다. 프로필은 역할/사용자/제품별로 분리하고, 사용 확인 후 의견이 다음 제안에 반영된다. 개인화 삭제는 수업·과제·제출 기록을 지우지 않는다. 정식 가입이나 운영 계정 연결은 아니다.

- `node --test experiences/teacher-world/*.test.mjs`: 기존 흐름 32개와 개인화 모델/HTTP 14개, 46개.
