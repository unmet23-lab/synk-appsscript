# Atlas 맞춤 출제 확인 · 2026-10-02

## 변경

`personalization.js`가 기존 60문항의 듣기/읽기·세부 능력·제작 난이도를 공통 Atlas API에 전달한다. 실제 추천은 공통 엔진이 결정하고 반환 문항으로 맞춤 5문항 코스를 만든다. 기존 수동 코스와 메달은 별도로 유지한다. 음소거에서는 읽기 후보만 사용하고, 허브의 `?learning=reading|listening` 선택은 첫 맞춤 코스에 적용한다.

문항 제시·음성 완료/실패·자막/지문·다시 듣기·최초 응답·정답 공개를 기록한다. 조작 의도가 불분명한 차선 통과, 미완료 음성, 도움 사용, 같은 문항군 반복을 독립 능력 근거와 분리한다. 자동 시연은 공통 학습 기록을 만들지 않는다. 읽기 문항은 지문을 자동으로 펼치며 제출 전에 지문을 음성으로 읽어 주지 않는다.

응답 형식은 실제 세 보기 선택인 `single-choice`로 후보와 문항 양쪽에 전달하여 O/X 응답과 구분한다.

## 자동 확인

응답 형식별 근거를 분리한 최신 공통 엔진으로 다음 두 게임 통합 명령을 재실행하여 43개 검사가 통과했다.

```powershell
node --test experiences/korean-racing/tests/*.test.mjs experiences/korean-rhythm/core.test.mjs experiences/korean-rhythm/audio.test.mjs experiences/korean-rhythm/personalization.test.mjs
```

레이싱 검사는 19개다. 실제 공통 API에 독립 듣기 응답을 넣으면 다음 코스의 첫 문항이 읽기로 바뀌는 것, 음소거와 허브 선택이 실제 5문항에 반영되는 것, 도움·음성 누락·조작 불명 응답이 독립 듣기 근거가 되지 않는 것, 음성 재생의 완료·실패·중단을 확인했다. 이는 구성한 입력에 대한 소프트웨어 검사이며 실제 학생 효과의 증거가 아니다.

## 실제 브라우저 확인

Chrome에서 공용 서버 `http://127.0.0.1:4280/korean-racing/?learning=reading`을 열었다. 읽기 추천 이유가 표시되고 추천 시작 뒤 실제 코스가 `personalized`, 첫 문항이 `c03q1`이 되는 것을 실행 화면과 앱 진단으로 확인했다. “저는 도서관(　) 책을 읽어요.” 지문과 `에서 / 에게 / 까지` 보기가 자동으로 열렸으며 다시 듣기 버튼은 비활성, 음성 상태는 “지문을 읽고 길을 골라요”였다. WebGL 차량·해안 배경도 실제 표시됐다. 별도 실행에서 소리 끄기 뒤 추천 이유가 읽기로 바뀌는 것을 확인했다.

초기 공용 서버의 HDR 경로 404는 허용 확장자 수정 뒤 재실행하여 해결됐다. 이 기록은 현재 오류가 없다는 확인과 과거 콘솔 로그를 구분한다. 이번 브라우저 실행은 첫 읽기 문항까지이며 맞춤 코스 전체 완주·최종 결과·음성의 직접 청취·실제 휴대폰·프레임 성능을 검증하지 않았다. 정답 공개의 `help(answer)` 추가는 소스와 구문 확인 범위이며 최종 코드로 브라우저 완주를 반복하지 않았다.

## 전달 범위

응답 형식 분리 policy 2의 최신 `atlas-learning.js`와 원본 코드를 포함한 `site-package/`를 갱신했다. `app.js`, `personalization.js`, `atlas-learning.js`, `index.html`, `narration.js`, `style.css` 6파일의 원본·패키지 SHA256이 모두 일치했다. 공통 런타임 SHA256은 `BE2EDEED3B9369F72CF93693D0F8FE23DBAB1B2386CAFBD95289D19A20BDBA81`이다.

공개 홈페이지와 ZIP은 갱신하지 않았다. 같은 origin의 로컬 브라우저 기록이며 학생 로그인, 다른 기기 동기화, 교사 보고, TOPIK 점수·급수·실제 학습 향상 검증은 포함하지 않는다. 서로 다른 포트로 실행한 게임은 기록이 공유되지 않는다.
