# 레이싱 첫 실행 대기 측정 · 2026-10-03

synk.im에서 캐시 없이 `/try/racing/`을 열면 시작 단추(`#watch`)가 **컴퓨터 18.4초, 휴대폰 19.0초** 뒤에 풀린다.
그사이 화면이 한 번에 **7초 넘게 멈춘다**(50ms 넘는 긴 작업 하나가 7.3~7.6초). 유호님이 「레이싱 첫 실행 대기」를 보라고 해서 쟀다.

- 측정: 공개판(10-02 21시 게임 코드, three.js r180), 헤드리스 Chrome(GPU, ANGLE D3D11), CDP 샘플링 프로파일(1ms)·longtask·네트워크 타이밍.
  휴대폰은 390×844 터치 흉내라 CPU·GPU는 이 PC다. 실제 휴대폰은 더 느릴 수 있다.
- 다시 재기: `PLAYWRIGHT_MODULE=<플레이라이트 경로> node qa/first-run-profile.cjs https://synk.im desktop` (또는 `phone`).

## 원인과 고칠 곳(큰 것부터)

1. **셰이더 컴파일 약 7초.** `onFirstUse`는 three.js `WebGLProgram`이 첫 렌더에서 프로그램 링크를 동기로 확인하는 곳이다. 첫 그림을 그릴 때 모든 재질의 셰이더가 메인 스레드를 막고 차례로 컴파일된다.
   `init()`에서 장면을 다 만든 뒤 `await renderer.compileAsync(scene, camera)`(r158부터, `KHR_parallel_shader_compile`)로 미리 컴파일하면 메인 스레드가 멈추지 않고 병렬로 컴파일된다.
   운영에서는 `renderer.debug.checkShaderErrors = false`. 재질(프로그램) 가짓수를 줄이면 더 짧아진다(`renderer.info.programs.length`로 센다).
2. **자동차 모델을 맨 마지막에 받는다.** `car.glb`(1.54MB)는 텍스처·도시·나무·하늘 굽기·길 풍경이 다 끝난 뒤(약 9초) 받기 시작해 10초쯤 끝난다.
   텍스처와 같이 처음에 받기 시작해 두면(약속만 먼저 만들고 나중에 await) 빠른 망에서 1~2초, 느린 망에서는 더 줄어든다.
3. **휴대폰 `coins()` 1.7초.** `toLocaleString('ko-KR')` 첫 호출이 국제화 데이터를 준비하느라 오래 걸린다. `Intl.NumberFormat('ko-KR')` 하나를 만들어 다시 쓰거나 쉼표를 직접 넣는다.
4. **지형 계산 약 1.3초.** landscape.js의 `hash`·`mix`·`height`·`noise`. 미리 구운 높이 지도나 워커로 옮길 수 있다.
5. **하늘 조명 세 가지를 처음에 다 굽는다.** `bloom`·`coast`·`sunset` PMREM을 모두 만든다. 처음 쓰는 하나만 굽고 나머지는 바꿀 때 굽는다.

1번과 2번을 고치면 화면이 멈추지 않고 단추가 훨씬 일찍 풀릴 것으로 보인다. 고친 뒤 같은 스크립트로 다시 재서 확인한다.
