# 차량 v9 — 가벼움 품질과 그림자 비용

2026-10-04 로컬 소스 검증. 통합 담당자의 실제 브라우저 재로드에서도 아래 앱 수치와 선명 → 가벼움 → 선명 복원, 차고 외관·휠 원형을 확인했다. 실제 휴대폰 장시간 성능은 별도 확인이 남아 있다.

## 반영

- `setVehicleQuality(car, quality, {preview:false})`를 내보낸다. `low`에서만 GT의 조밀한 실내·브레이크·스티어링 일부를 줄인다. `balanced`·`high`·`preview:true`는 같은 원본 지오메트리 객체로 돌아간다.
- 원본 GLB·차체·유리·타이어·림과 휠 회전 그룹은 유지한다. 품질 변경 때 원본을 덮어쓰거나 다른 차량이 공유하는 버퍼를 해제하지 않는다.
- 첫 `low` 전환 때 필요한 지오메트리만 만든다. 같은 원본은 WeakMap 캐시를 공유하며, 반복 전환은 이미 만든 버퍼를 다시 쓴다. 매 프레임 호출이나 재생성은 필요 없다.
- 6 mm 격자의 점 병합이며 **최대 6 mm 오차라는 뜻은 아니다**. 실제 원본의 최대 점 이동은 7.829 mm이고, 이론적 격자 대각선 한도는 10.393 mm이다. 급격한 법선·UV 경계는 분리하고 뒤집히는 면은 원래 면을 사용한다.
- 타이어 안쪽 휠 배럴의 그림자 제출을 제거한다. 바깥 타이어·림·차체 그림자는 유지한다.
- 실제 GLTFLoader가 중복 이름을 `wheel_1`·`brake_2`로 바꾸는 것을 반영했다. `userData.name`의 원래 이름으로 분류하며, 처음 한 바퀴만 적용되던 그림자·재질·LOD 누락을 수정했다.
- 별도 제작된 로드스터·랠리·피날레는 이미 가벼워 추가 감축하지 않는다.

## 실제 자산 수치

`node qa/measure-vehicle-v9.mjs`가 번들 Draco 디코더와 **실제 번들 GLTFLoader**로 `assets/car.glb`를 직접 읽어 `vehicle-v9-measurements.json`에 저장한다. QA helper도 손으로 노드를 복원하던 방식을 고쳐 실제 로더의 중복 이름·userData·재질을 검사한다.

아래 첫 표는 마스코트·추가 램프·부스터·접촉 그림자를 제외한 GLB 원본만의 수치다.

| 항목 | 이전/선명 | 변경/가벼움 |
|---|---:|---:|
| 차체 포함 GLB 삼각형 | 358,788 | 327,929 |
| 차이 | | -30,859 (-8.60%) |

두 번째 표는 앱의 실제 `prepareCar`와 재질 지정·숨겨진 컬렉션 배지를 실행한 결과다. 마스코트·나중에 추가되는 실드 효과는 제외한다. 이전 상태는 원래 이름을 읽지 않던 조건만 메모리 안에서 재현해 비교했다.

| 앱 차량 | 이름 누락 수정 전 | 수정 후 |
|---|---:|---:|
| 선명 삼각형 | 359,302 | 359,302 |
| 가벼움 삼각형 | 330,903 | 328,443 |
| 선명 draw calls | 43 | 42 |
| 그림자 삼각형 | 194,880 | 156,504 |
| 그림자 draw calls | 26 | 22 |

그림자 차이 38,376은 누락된 배럴 3개의 27,360 + 브레이크 3개의 11,016과 정확히 일치한다. 오래된 카운터 때문이 아니라 실제 최적화 누락이었다. 앞선 192,984 → 156,504 수치는 손으로 노드를 복원한 QA 모델에서 나온 값이라 실제 앱 전후 수치로 사용하지 않는다.

새 선명 품질도 그림자 비용 절감은 적용한다. 저품질 실내 감축은 그림자를 이미 만들지 않는 영역이므로 그림자 수치가 추가로 줄지는 않는다. 스냅샷에 나중에 생성된 실드 640 삼각형 등이 포함될 수 있으므로 같은 차량 구성끼리 비교해야 한다. 위 수치는 프레임 속도 개선율이나 휴대폰 발열 검증을 뜻하지 않는다.

## 검사

`node --test tests/vehicles.test.mjs`: **8/8 통과**.

- 기존 차량 3종의 크기·열린 운전석·휠 회전·재질·차고 소유권 검사를 유지.
- 실제 GLB의 원본 버퍼, 외형 경계, 휠 축, 바깥 그림자 지오메트리 보존 확인.
- 실제 GLTFLoader가 휠 배럴 네 개의 이름을 서로 다르게 바꾸고 원래 이름을 보존하는 상황에서 전부 최적화되는지 확인.
- 낮은 품질의 모든 인덱스·좌표·법선 유효성 및 감축량 확인.
- 선명/자동/차고 복원 후 원본 참조 일치, 다시 가벼움으로 바꿀 때 캐시 참조 일치.
- 두 차량의 같은 원본 감축 공유, 다른 차량과 차고 버퍼의 조기 dispose 없음 확인.

## 앱 연결

`app.js`의 품질 변경과 장착 차량 변경에서 `setVehicleQuality(car, mode)`를 호출한다. `mode`는 실제 적용 중인 `low`·`balanced`·`high`이다. 차고에는 `setVehicleQuality(previewCar, mode, {preview:true})`를 적용한다. 생성·품질 변경 시만 호출하고 프레임 루프에는 넣지 않는다. `car.userData.modelStats.geometryLevel`이 적용 결과다.
