# 그래픽 v9·완주 후 해안선 드라이브

2026-10-04. 로컬 구현, 실제 브라우저 동작·화면, 자동 검사 및 전달 패키지 검증 기록이다. 공개 홈페이지 배포와 실제 휴대폰 장시간 검증은 포함하지 않는다.

## 완주 뒤에도 이어지는 드라이브

- 마지막 학습 문항과 마무리 주행을 마치면 결과창으로 시야를 가리지 않고 해안 드라이브로 이어진다. 상단에는 “모든 문제를 마쳤어요. 드라이브하며 쉬었다가 다음 코스로 넘어가요.”, 하단에는 결과·다음 코스 버튼을 표시한다.
- 기본 목표 속도는 부스터와 같은 42m/s(약 151km/h)이며 기존 개인별 주행 속도 배율을 따른다. 직접 조향과 차량 접촉 피드백을 유지한다. 갓길·접촉 중에는 감속하고 회복한다.
- 하단 버튼을 눌러 기존 결과·복습·다음 코스를 열고, “드라이브로 돌아가기”로 다시 달릴 수 있다. 드라이브와 결과창 왕복은 새 문항·완주 기록·코인 보상을 추가하지 않는다. 자동 시연은 기존과 같이 학습 기록·보상에 포함하지 않는다.
- 유한한 기존 도로 끝에 도달하면 짧은 화면 전환으로 시작 구간에 돌아와 계속 달린다. 끝없이 이어지는 새 지형을 생성하는 방식은 아니다. 일시정지와 감소 모션 정책은 기존 동작을 유지한다.
- SYNK 시티팝 **〈해안선〉**을 사용한다. 기존 리듬 게임 음원을 바이트 그대로 복사했으며 새 음악 생성·결제를 하지 않았다. 231.6초, MP3 4,633,256bytes. 출처·원본 제목·SHA256은 [음원 기록](../assets/music/sources.json)에 있다.
- 초기 화면에서 곡을 다운로드하지 않고, 소리가 켜진 마지막 문항에서 준비한다. 완주 후 스트리밍 재생·반복·페이드 인을 사용하며 전체 곡을 Web Audio 버퍼로 풀지 않는다. 나레이션 중에는 볼륨을 낮춘다. 음소거·일시정지·탭 숨김·결과 화면에서는 음악을 멈추고, 브라우저가 재생을 거부하면 직접 누르는 음악 버튼으로 복구한다. 음원 오류가 주행을 멈추게 하지 않는다.

관련 소스: `coast-drive.js`, `coast-radio.js`, `coast-drive.css`, `app.js`, `index.html`.

## 건물·해안·사람

- **주택 근경:** 기존 3채의 위치·지붕·발코니를 유지하고 창/문 18곳을 실제 벽 개구부로 구성했다. 유리 앞면은 외벽보다 21.25cm 안쪽이다. 목재 프레임과 창턱, 연속된 미장 외벽으로 상업 건물의 패널 벽과 구분한다. 기존 하늘 반사를 사용하며 켜진 창의 비율을 줄여 밝은 격자의 반복감을 완화한다.
- **정원 접지:** 지형을 따르는 진입로 9구간·낮은 담 9구간·관목 9군을 추가했다. 계단에서 담의 출입구를 지나 길이 이어지고, 식생 제외 영역도 확장했다. 담은 경사를 따라 연속되며 중복 내부면·묻힌 바닥면을 줄였다. 도로 및 기존 NPC 활동 앵커는 보존한다. 상세: [city-v9-notes.md](city-v9-notes.md).
- **관중 반응:** 44명 중 31명은 기존 활동을 유지하고 8명은 고개, 5명은 손 인사로 차량에 반응한다. 감지 거리 41–54m와 지연 0.12–0.64초를 개인별로 다르게 두고 접근당 한 번만 반응한다. 110m 이상 벗어나야 다시 인사한다. 발 고정점·컵과 입의 접촉·걷기 궤도를 보존하며 정지/감소 모션에서 반응 시간을 동결한다. 새 반응 동시 시작 한도는 high 4명 / balanced 3명 / low 2명이다. 상세: [crowd-v9-notes.md](crowd-v9-notes.md).
- **바다 수심:** 실제 지형의 해안선 바깥 4/12/30m 지점 수심을 512개 구간에서 계산한다. 기존 2,048byte 해안선 텍스처의 남은 채널에 1,536개 수심 표본을 넣어 얕은 청록색·깊은 물색과 근거리 수면 빛 무늬에 반영한다. 추가 텍스처 읽기·수심 렌더 패스·매 프레임 지형 조회 없이 기존 물 2triangles·1pass를 유지한다. 이는 표본 보간 기반의 수심 표현이며 실시간 유체·굴절 시뮬레이션은 아니다.

도시 예산은 카메라 없는 s0–2250/5m 전수 샘플이다. 차량 수치는 마스코트·부스터 등의 부품을 제외한 실제 GLB 범위다. 저품질 차량 기하는 최초 필요할 때만 만들고 공유 캐시를 사용하며 선명·차고로 돌아가면 원본 객체를 복원한다. 6mm 격자는 최대 점 이동 한도가 아니다. 원본 측정 최대 이동은 7.829mm다. 상세: [vehicle-v9-notes.md](vehicle-v9-notes.md), [차량 측정](vehicle-v9-measurements.json).

지형의 같은 프로세스 교대 생성 측정은 이전 749.676/738.553ms, 변경 492.489/414.426ms였다. 머신 부하·JIT 영향을 받는 초기 생성 미세 측정이며 게임 프레임 개선율이 아니다. 지형은 양쪽 모두 209,472 triangles / 115,288 vertices로 동일하다. [측정 원본](terrain-v9-measurements.json), [재현 스크립트](measure-terrain-v9.mjs).

## 검사와 남은 확인

[graphics-v9-tests.txt](graphics-v9-tests.txt)에 저장된 `node --test tests/*.test.mjs` 결과는 **176/176 통과**, 실패·건너뜀 없음이다. 실제 지형·차량 자산·도로 경계·개구부 raycast·보행자 접촉·품질 복원·완주 중복 방지·10분 드라이브 순환 및 음악의 지연 재생/취소/오류 생명주기를 포함한다. 음악 단위 검사는 mock media이며 사람이 들은 결과를 대신하지 않는다.

## 실제 브라우저 확인

- 개발 화면의 「어디에서, 어디로」 자동 시연에서 실제 보기 버튼으로 5문제를 선택해 완주했다. 마지막 정답 해설이 끝난 뒤 결과창은 숨겨진 채 `phase=drive`, 질문 게이트 `null`, 답안 5개, 기본 속도 42m/s(표시151km/h)를 유지했다. 코스 끝을 지나 세 번 순환했고 첫 완주의 음악 시계가38.78→118.53초로 진행했고, 최종 수정본 재검사에서도3.09초와186.85초의 재생 상태를 확인했다. 정지 화면이나 연출용 상태 주입이 아니다.
- 하단 「결과 · 다음 코스」를 클릭하면 `phase=results`, 주행 정지, 음악 gain0·playing=false가 됐다. 「드라이브로 돌아가기」로 음악 위치를 이어 재생했다. 일시정지·음소거·음악 버튼 재개, 다음 코스03→04 이동 시 phase= race / 답안0 / 음악 정지·0초도 확인했다. UI 왕복과 순환 후 기존 rounds1/cleared1/coins0을 유지했다. 직접 플레이 보상 중복 방지는 별도 실제 모듈 통합 검사로 확인했다.
- 최종 차량 이름 수정 후 다시 로드해 high359,302tri/42calls → low328,443/42 → high359,302/42 복원을 확인했다. 그림자156,504tri/22calls도 측정 스크립트와 일치했다. 차고에서 네 휠과 차체 외관을 확인하고, 수정본에서도 완주·시티팝 재생을 다시 확인했다.
- UI 캡처와 게임 캔버스는 구분한다. [최종 완주 UI](coast-drive-v9-final-ui-20261004.jpg)와 [최종 드라이브4K](coast-drive-v9-final-4k-20261004.png), [모바일 세로](coast-drive-v9-mobile-20261004.jpg), [모바일 가로](coast-drive-v9-landscape-20261004.jpg), [주택·바다 실제4K](graphics-v9-homes-4k-20261004.png). PC 브라우저390×844/844×390에서 문서 폭375/829로 가로 넘침이 없고, 안내·다음 코스·방향 버튼이 차량을 덮지 않는 것을 확인했다. 실제 캔버스4K는3840×2160이며 업스케일/합성하지 않았다. 모바일·주택 첫 캡처는 마지막 차량 이름 누락 보정 전 이미지다. 최종 완주 UI와 드라이브4K는 보정 후 다시 저장해 파일을 열어 확인했다.
- 인물 근접 검사 페이지에서 실제 보행 자세 변화와 주변 반응 카운터를 확인했다. 동작의 접촉·반응 회수·품질 예산은11개 수치 검사로 보완했다. 이 페이지는 게임과 같은 모듈을 쓰는 검사 장면이며 실제 플레이 캡처로 소개하지 않는다.
- 최종 앱 콘솔 조회의 GPU/JavaScript 오류·경고는0건이었다. 첫 자동 탭 열기 실패는 사용자가 미리보기를 연 뒤 복구했다. 캡처 지점 대기 중 DevTools 명령 시간이 만료된 것은 앱 오류와 구분한다.

## 남은 확인 범위

음악 파일 로드·실제 media 재생 시계·gain·정지/재개는 확인했으나 스피커를 통한 직접 청취와 최종 음량 균형은 검증하지 않았다. iPhone/Android의 자동 재생 정책·장시간 FPS·메모리·발열·실제 터치도 미확인이다. PC의 모바일 크기 확인으로 대체하지 않는다. 그래픽·주행 기능 추가가 TOPIK 점수나 학생 학습 효과를 검증한 것은 아니다.
