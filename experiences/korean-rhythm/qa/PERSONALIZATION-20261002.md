# Atlas 맞춤 추천 확인 · 2026-10-02

## 변경

`personalization.mjs`가 곡별 듣기 능력·제작 난이도와 문항 식별자를 공통 Atlas API에 전달한다. 공통 추천 결과가 실제 선택 곡에 반영되고 수동 곡 선택도 유지한다. 박자 점수는 언어 능력 근거로 사용하지 않는다. 음성 완료 뒤 최초 O/X 응답과 새 문장 확인을 기록하며 미응답을 오답으로 단정하지 않는다.

곡·문항·O/X 변형 ID를 구분하되 같은 원문의 질문만 바뀌면 같은 문항군으로 처리한다. 즉시 새 문장 확인은 별도 문항군이며 이후 반복까지 새로운 독립 근거로 세지 않는다. 화면에 정답이 공개되는 시점에 `help(answer)`를 남긴다. 이 게임은 듣기만 다루고 읽기 근거를 만들지 않는다.

본편과 새 문장 확인 모두 실제 O/X 두 보기다. 따라서 후보와 두 종류 문항의 응답 형식을 모두 `binary-choice`로 전달하여 세 보기 선택 근거와 구분한다.

## 자동 확인

응답 형식별 근거를 분리한 최신 공통 엔진으로 다음 두 게임 통합 명령을 재실행하여 43개 검사가 통과했다.

```powershell
node --test experiences/korean-racing/tests/*.test.mjs experiences/korean-rhythm/core.test.mjs experiences/korean-rhythm/audio.test.mjs experiences/korean-rhythm/personalization.test.mjs
```

리듬 검사는 24개다. 실제 공통 API에 첫 곡의 독립 응답·새 문장 확인을 넣으면 추천 곡이 달라지는 것, 문항군 반복 정답은 독립 근거가 아닌 것, 곡 ID 충돌이 없는 것, 기존 음악·나레이션 시계와 판정 분리를 확인했다. 구성한 입력에 대한 소프트웨어 검사이며 실제 학생 효과를 확인한 결과가 아니다.

## 실제 브라우저 확인

Chrome에서 `http://127.0.0.1:4280/korean-rhythm/`을 열었다. 추천 이유·저장 범위·추천 곡 선택 버튼이 나타나고 버튼을 누른 뒤 해당 곡을 실제 시작했다. 첫 음성 구간에서는 O/X 입력이 비활성이고 이후 문제를 표시했다. 약 39초에서 일시정지한 뒤 로비로 돌아왔다.

이 실행의 공통 저장 이벤트에서 `practice.presented`, `practice.delivery(audio: completed)`, `practice.attempted(verdict: unassessed, reason: unanswered)`, `experience.completed`를 확인했다. 사용자가 응답하지 않은 문제는 오답으로 저장되지 않았다. 이 저장은 개발 QA 기록이며 학생 기록이나 향상 증거가 아니다.

이번에는 새 구현으로 전체 곡 완주·새 문장 확인 전체·음성 출력의 직접 청취·실제 휴대폰·프레임 성능을 검증하지 않았다. 정답 공개의 `help(answer)`와 화면이 건너뛰어진 문항의 안전 처리는 이후 추가한 소스·구문 확인 범위이며 브라우저 완주로 재검증하지 않았다. 기존 기능의 과거 검증은 별도 `listening-20261001/RESULTS.md` 기록을 따른다.

## 전달 범위

로컬 소스와 공통 런타임만 갱신했다. 공개 홈페이지는 갱신하지 않았다. `server.mjs`의 JavaScript MIME을 수정했으므로 이미 실행 중이던 구버전 5201 서버는 재시작이 필요하다. 해당 서버를 강제 종료하지 않았고 이번 브라우저 검증은 공용 4280 서버에서 수행했다.

같은 origin의 로컬 브라우저 기록이며 학생 로그인, 다른 기기 동기화, 교사 보고, TOPIK 점수·급수·학습 향상 검증은 포함하지 않는다. 서로 다른 포트로 실행한 게임은 기록이 공유되지 않는다.
