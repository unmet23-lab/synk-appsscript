# PULSE 독립 기능 검수

2026-09-09. 생성자와 별도의 검수자가 실제 Chrome 브라우저를 조작했다. 제품 소스는 편집하지 않았으며 이 폴더의 검수 스크립트와 증거만 만들었다. 서버는 정본 작업본의 `server.cjs` factory를 새로 읽어 임시 로컬 포트에서 시작하고 검사 뒤 종료했다. 실제 사용자 서버나 방을 변경하지 않았다.

## 확인한 결과

- 독립 Chrome 컨텍스트 두 개: 방 만들기 → 합류 → 시작 → 각 역할의 개인 단서 격리 → 명시적 공유 네 개 → 서로 다른 투표일 때 결말 확정 차단 → 새로고침 후 같은 역할과 선택 복구 → 재투표 → 같은 결말 → 방장 리셋.
- 390px와 320px 화면에서 한 기기로 두 역할을 전환하여 결말까지 도달. 가로 넘침 없음. 결말 진입 시 이전 투표 화면의 스크롤 위치를 초기화하는 수정 확인.
- 시작·탐색·투표·결말·모바일 결말 두 종, 총 6개 상태의 axe 자동 검사에서 WCAG A/AA 태그 위반 0. 전문 접근성 인증이나 장애 당사자 검사를 뜻하지 않는다.
- 키보드 Tab과 Enter만으로 390px 대체 화면에서 시작, 조사, 단서 네 개 공유, 역할 전환, 합의, `서로의 창문` 결말까지 도달.
- 시작 화면의 숨은 조사 버튼이 Tab 순서에서 제외됨. 캔버스 포커스 스타일 보완을 소스에서 확인. 움직임 줄이기 선택이 공통 접근성 속성에 반영됨.
- 방 접기 → 같은 방으로 돌아오기에서 개인 단서 유지. 새로고침 후 같은 역할로 복귀.
- WebGL을 사용할 수 없는 브라우저 조건을 강제했을 때 정지 이미지 대체와 장소 버튼으로 개인 단서를 읽을 수 있었음.
- 일시 네트워크 장애는 자격을 보존하고, 재연결 후 같은 방으로 복귀. 검수 서버의 방 정보 소실(404) 또는 자격 무효화(401)는 구체적인 안내와 `새 방으로 시작`을 제공하며 새로운 방 시작까지 확인.

## 발견하고 수정 확인한 문제

1. 이탈 시 자격을 지워 기존 방으로 돌아올 수 없던 문제: 방 접기와 재개로 수정 확인.
2. 모바일 결말이 이전 투표 화면의 스크롤 위치에서 열리던 문제: 결말 상단으로 초기화 확인.
3. 숨은 조사 버튼 네 개가 Tab 순서를 차지하던 문제: 초기 비활성 영역 처리와 시작 후 해제 확인.
4. 서버 방 소실 뒤 재연결만 반복하던 복구 문제: 실제 401/404 판별 후 새 방 시작 경로 확인.

## 증거와 재현

- `review.cjs` / `review.json`: 두 브라우저·모바일 전체 흐름, 검사 시 소스 지문, 6개 axe 결과.
- `recovery.cjs` / `recovery.json`: 키보드 진입 순서, 방 접기·재개, 모션 선택, WebGL 대체.
- `keyboard.cjs` / `keyboard.json`: 키보드로만 완결한 13개 사용자 동작.
- `lost-room.cjs` / `lost-room.json`: 일시 통신 장애, 방 정보 소실, 자격 무효화, 새 방 시작.
- `ending-desktop.png`, `ending-mobile-390.png`, `ending-mobile-320.png`: 실제 런타임의 결말 화면. 미술 기준 이미지와 구분한다.

스크립트는 현재 기계의 Chrome/Playwright 설치 경로를 사용한다. 제품 실행에는 Playwright가 필요하지 않다. 제품 정본이나 폴더가 이동하면 검수 스크립트의 경로를 갱신해야 한다.

## 확인하지 않은 범위

서로 다른 실제 기기와 외부 네트워크, 장애 당사자·스크린리더 실사용, 음성의 청취 품질, 장시간 서비스 안정성, 상업적 재미·재방문·지불 의사, 최종 3D 미술 품질은 이 기능 검수의 완료 주장에 포함하지 않는다. 3D 시각 감수와 최종 통합은 주담당이 진행한다.
