기준 커밋 `a1d64fb04f8766dbef1cd3607c99577062f30f18`, 브랜치 `codex/pulse-story-20260910`. 현재 작업본의 `AGENTS.md`, `docs/AI_운영원칙.md`, `DESIGN.md`, `docs/사업발전_정본.md` §3과 `docs/명품_기준_v1.md` §3·§4를 읽고 적용했다. 색과 서체는 기존 PULSE의 Loom 소비와 브랜드 변수 위에서 확장했다.

## 사용자 피드백과 적용

주담당이 전달한 이번 대화 원문에서 「최소한의 가이드가 있어야하는데 전혀 없어서 뭘 해야하지?」, 「그냥 누를수있는거 대충 누르게되더라고」라는 지적을 확인했다. 이를 사용자가 정한 구체적인 퍼즐 디자인으로 확대하지 않는다. 아래 장비와 진행 구조는 이 문제를 풀기 위한 제작 판단이다.

- **첫 화면:** 도시에서 무엇을 왜 하는지와 `살피기 → 전원·방송 복원 → 불빛 보내기`를 보여 준다. 혼자 시작과 친구와 시작을 구분했다.
- **과정:** 단서 네 개의 공유 버튼을 누르는 문턱을 걷었다. 전차 연결부 세 개를 실제 연속된 회로로 잇고, 방송국 다이얼을 맞춰 목소리를 복원해야 최종 선택으로 넘어간다. 두 장치는 어느 순서로든, 어느 역할로든 조작한다. 회로 실패는 끊긴 지점을 알려 주며 전력이나 시간이 소모되지 않는다.
- **협력:** 정비사와 기록원의 메모가 서로 다른 정보(장비 구조·눈금 단위 / 수신 위치)를 제공한다. 말로 전달해도 되며 필요한 메모만 공유할 수 있다. 혼자일 때는 두 역할을 전환한다. 기존 2~4인 합의와 방장 확정은 유지한다.
- **힌트:** 한 문장의 현재 목표와 두 복원 상태가 먼저 보인다. 플레이어가 원하면 단서 방향 → 더 구체적인 방법 → 직접적인 도움 순서로 힌트를 펼친다. 마지막 도움을 써도 도덕 점수나 실패 낙인은 없다.
- **마무리:** 세 결말의 구체적인 후속 장면, 실제 복원 순서, 각 역할이 선택적으로 남긴 한 문장을 묶어 로컬 텍스트 기록으로 내려받는다. 플레이어의 능력·성격 평가로 사용하지 않는다.

## 통합 계약

`server/story.cjs`는 `createRestorationState`, `applyRestorationAction`, `restorationReady`, `restorationObjective`, `buildEnding`을 제공한다. `restore` 액션은 연결부 하나 또는 수신 주파수를 갱신한다. 마지막 `mark`는 참여 역할별로 문장 한 개를 추가·수정한다. 서버 단계·참여 권한 검사는 주담당 소유 `server.cjs`가 맡는다.

장면의 `setCameraMode`, `updateRestoration`, `onStatus(zone,moving,step)`와 연결한다. 발걸음은 장면 이벤트 하나에서 재생하고 오디오의 자동 발걸음은 꺼서 중복하지 않는다. 음악·효과 음량과 음소거는 별도 오디오 모듈이 보존하며, 게임 재개가 기존 음소거 선택을 임의 해제하지 않는다.

AI 대화는 독립 `#npc-dialogue` 영역을 사용한다. `pulse:session`과 `pulse:state` 이벤트로 메모리 안의 현재 문맥을 전달하고, 역할 전환·방 접기·자격 정리에서는 연결을 비운다. 외부 모듈은 `pulse:request-context`로 초기 문맥을 재요청할 수 있다. 대화 입력은 전체 이야기 렌더의 대상이 아니다. 토큰은 DOM·기록 다운로드·검수 로그에 넣지 않는다.

## 경계

서사 검수의 브라우저는 별도 담당 AI 모듈 정적 파일만 제외했다. 실시간 AI 대화, 새 WASD 장면의 최종 미술·음향과 전체 통합은 주담당이 별도로 확인한다. 현재 조작은 두 개의 짧은 장비 퍼즐이며 상업적 재미·난이도·재방문이 검증되었다는 뜻은 아니다. 실제 다른 기기·외부 네트워크, 장애 당사자와 스크린리더 검토, 사람의 청취 검수도 이 기록의 완료 범위가 아니다.
