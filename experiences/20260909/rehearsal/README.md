# 첫 제안의 리허설 · SYNK SHIFT

1인 기업 수강생이 가상 고객의 목적을 묻고, 제안을 만들고, 바뀐 조건에 맞게 고친 다음 다른 고객에게 적용하는 연습입니다. 작성한 질문·제안·이유와 강사 메모를 이 브라우저에서 보관하거나 파일로 전달할 수 있습니다.

## 실제 동작

1. 가상 공방의 의뢰를 읽고 목적·범위·일정에 대한 질문을 직접 작성합니다.
2. 미리 작성된 예시 고객 답장을 읽고 첫 제안을 만듭니다. 답장 생성 API나 자동 채점은 없습니다.
3. 예산 감소와 영상 추가 요청을 받고 수정 제안과 이유를 작성합니다. 최초 제출 원문은 남습니다.
4. 다른 상황의 가상 책방 의뢰에 질문·제안·다음에도 쓸 기준을 적용합니다.
5. 실제 입력을 함께 검토하고, 선택 사항인 강사 메모를 남긴 뒤 JSON 또는 텍스트를 내려받습니다.

강사는 같은 페이지의 **기록 관리 → 저장 파일 열기**에서 받은 JSON을 열고 메모를 이어 쓸 수 있습니다. 파일 열기와 초기화는 현재 브라우저 기록을 바꾸므로 확인 창을 거칩니다. 자동 전송·계정 로그인·강사 본인 확인은 없습니다.

## 실행과 연결

공통 Node 서버가 이 폴더를 `/rehearsal/`에 매핑하면 됩니다. 모든 실행 자원은 상대 경로이며 외부 API·유료 호출이 없습니다. `index.html` 파일을 직접 더블클릭하면 브라우저의 모듈 보안 정책으로 동작하지 않을 수 있으므로 HTTP 미리보기를 사용합니다.

```text
node experiences/20260909/rehearsal/serve.cjs 4177
```

접속: `http://127.0.0.1:4177/rehearsal/`

- 실행 파일: `index.html`, `app.mjs`, `state.mjs`, `styles.css`, `assets/`.
- localStorage 키: `synk.rehearsal.v1`. 같은 브라우저·같은 주소와 포트에서 복구됩니다. 다른 기기·브라우저·주소로 옮길 때는 JSON을 사용합니다.
- JSON 형식: `format: synk-rehearsal-export`, `record.schemaVersion: 1`, `record.scenarioId: shift-first-brief-v1`.
- `record.fields`는 현재 입력 원문, `record.history`는 다음 버튼으로 남긴 단계별 제출 원문입니다. 학습자 답과 강사 메모는 다른 항목으로 보존합니다.
- 비어 있거나 공백만 있는 필수 항목은 단계 진행을 막고, 첫 빈 입력으로 포커스를 옮깁니다. 답의 품질·등급을 키워드로 판단하지 않습니다.
- 저장 실패는 화면에 알립니다. 손상된 기존 저장본은 자동 덮어쓰지 않으며 원본 파일 내려받기를 제공합니다. 다른 탭에서 기록이 바뀌면 현재 탭의 자동 저장을 멈추고 내보내기를 안내합니다.
- 기록에는 이름·실제 고객 자료가 필요 없습니다. 모든 고객·조건·금액은 이 연습의 허구입니다.

## 디자인 판단

| 비교 | 장점 | 한계 | 적용 |
|---|---|---|---|
| A · 고객 의뢰서 중심 | 조건과 약속 범위를 한눈에 확인하며 앞뒤 제안을 비교하기 좋음 | 모든 단계와 입력을 한 페이지에 쌓으면 양식처럼 느껴짐 | 시작 화면의 고객 의뢰와 최종 검토의 원문 구조 |
| B · 짧은 대화형 현장 중심 | 지금 받은 메시지와 해야 할 일에 집중하고 변경 요청이 자연스럽게 이어짐 | 메신저를 흉내내면 긴 입력과 판단 근거가 뒤로 밀릴 수 있음 | 현재 장면 하나씩 전개하고 앞선 답은 펼쳐 보기 |

최종은 B의 장면 흐름에 A의 의뢰서·원문 보존 구조를 결합했습니다. 대시보드·점수판·가짜 채팅 입력 표시를 추가하지 않았습니다. 작은 화면에서는 현재 단계 이름과 단계 번호를 함께 보여 줍니다.

브랜드 지면은 현행 `tools/lib/loom.js`의 `계정컬렉션()`·`마케팅실행()`에서 생성하며 폰트·색·간격은 `docs/디자인_토큰.json`을 소비합니다. `styles.css`는 단계·폼·접근성·기록 검토 레이아웃을 담당합니다. SYNK 표식은 `로고정본.js`의 밝은 바탕 단색 민판, SHIFT는 승인된 Lapis Deep입니다. 고빈도 입력과 단계 이동에는 모션을 넣지 않았습니다.

비교 출발점으로 현행 소개서 표지 PNG와 중립색 로고 실물을 열어 봤습니다. `synk-design`, `make-interfaces-feel-better`, `명품_기준_v1.md` §3~4를 적용했습니다. 색·서체를 새로운 스타일로 갈아입히거나 마스코트를 장식으로 반복하지 않았습니다.
