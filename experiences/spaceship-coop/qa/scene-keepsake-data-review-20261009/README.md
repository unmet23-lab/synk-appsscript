# 마법 보관함 저장 경계 독립 검토 · 2026-10-09

공개 전 읽기 검토에서 확인한 P1을 수정 전·후로 나눈 증거다. 최신 계정 기록을 읽으면 account-host의 관찰한 `previous`도 최신으로 바뀐다. 이전 화면의 모험 진도에 최신 `keepsakes`만 붙이고 전체 값을 쓰던 분기는 다른 기기의 완료 6개를 조용히 덮었다.

- [수정 전 재현](before-reproduction.json): 완료 6개를 관찰한 뒤 옛 완료 0개를 저장한 요청이 합성 서버에서 받아들여졌다. 실제 당시 `persist` 함수 본문을 도구 출력에서 보존했다. 수정 전 전체 WIP 앱의 별도 SHA는 없으므로 주장하지 않는다.
- [수정 후 재현](after-reproduction.json): 다른 진도 변경은 저장 요청 0개로 거부하고 완료 6개를 유지한다. 보관 장면만 바뀐 경우는 최신 장면을 합쳐 정상 저장한다. 두 결과 모두 실제 현재 앱 함수·계정 host·병합 함수로 확인했다.
- [실행 코드](review.cjs): 확정된 app/core/keepsakes/view 네 파일의 SHA를 먼저 검사한다. 로컬 메모리 storage와 합성 서버 상태만 사용한다. 정상 저장 사례도 확인하므로 누락된 VM 변수에 따른 catch를 수정 성공으로 세지 않는다.

최종 읽기 범위: 기존 계정 JSON 키와 버전 호환, 계정 종료·주인 변경 시 DOM/초안 제거, 오프라인·충돌 저장 안내, 새 지갑 조회를 통한 소풍 미보유 차단, 닫은 보관함의 늦은 재생 요청 취소, canonical 자산·좌표 재구성과 공유 그림 원본 불변. 현재 확정 원문에서 미해결 P1/P2는 찾지 못했다. 공개 후보의 조립·라이브 byte 대조는 root가 별도 확인한다.

운영·실계정·DB 쓰기, 제품 변경, 새 음원·외부 모델 호출은 0이다. 실제 학습자·물리 휴대폰 복원 증거가 아니다.
