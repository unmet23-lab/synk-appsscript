# 둘이서 우주선 고치기 · SYNK WORLD

한국어를 처음 배우는 두 사람이 **서로 다른 화면에서 소리를 주고받아 실제로 같은 우주선을 고치는** 협동 게임이다. 한 사람에게만 그림 설명서가, 다른 사람에게만 조종판이 보인다. 역할을 장치마다 바꾸며, 모든 장치를 고치면 둘이 함께 이륙한다.

## 플레이

1. 탐험을 만든 사람이 초대 링크 또는 6자리 방 코드를 보낸다. 각자 다른 브라우저 프로필/기기를 사용한다.
2. 두 사람 모두 소리를 켜고 준비한다. 마이크·음성 인식은 필요 없다.
3. 매 단계에서 그림과 실제 한국어 음성을 먼저 만난다. 모든 표현을 끝까지 들은 뒤 두 사람이 준비해야 수리가 열린다.
4. 설명서 담당은 자기에게만 보이는 그림을 보고 한국어 음성 버튼을 고른다. 조종사는 그 음성을 끝까지 들은 뒤 색 단추, 위/아래 안테나, 연료 펌프를 조작한다.
5. 틀려도 시간이 줄거나 생명을 잃지 않는다. 비눗방울과 우주선 회전 반응 뒤 다시 듣고 시도한다. 선택한 조작은 피드백 뒤에도 남는다.
6. 장치 하나를 고칠 때마다 역할을 바꾼다. 총 18개를 고치고 두 사람이 이륙 버튼을 누르면 공동 결과와 혼자 하는 3문항 소리 회상으로 이어진다.

| 단계 | 먼저 배우는 소리 | 실제 조작 | 수리 |
|---|---|---|---:|
| 엔진 | 빨간색 · 파란색 | 서로 다른 색/기호의 실제 펠트 단추 | 6 |
| 안테나 | 위 · 아래 | 위/아래 조종판 | 6 |
| 연료 | 한 번 · 두 번 · 세 번 | 펌프를 필요한 횟수만큼 누르고 확인 | 6 |

각 단계의 목표 순서는 새 탐험마다 섞인다. 두 참가자 모두 모든 표현을 설명서 담당으로 만날 수 있게 구성했다. 첫 플레이의 시간 제한은 없다. 숫자 1/2/3은 신호·색/위치 조작, R은 조종사의 다시 듣기다. Tab/Enter도 모든 행동에 쓸 수 있다. 색에는 ▲/●를 함께 사용한다. 움직임 감소 설정을 존중한다.

입장 전부터 두 화면·소리·마이크 불필요·로컬 주소의 범위를 한국어와 영어로 안내한다. 복사 권한이 막히면 누른 코드 또는 초대 링크 자체를 선택한 창을 연다. 진행 중 입문 허브로 나갈 때는 둘의 탐험 종료를 확인하며 취소하면 그대로 계속한다. 완료 뒤 한 사람의 새 탐험은 친구가 보고 있는 결과·혼자 복습을 닫지 않는다. 결과와 복습에는 다른 입문 놀이로 가는 링크가 있다.

키보드로 소리를 듣거나 화면이 갱신되어도 조작 초점이 이어진다. 수리 성공 뒤에는 다음 장치, 연습장 닫기 뒤에는 연습장 단추, 혼자 회상에서는 듣기→보기→다음→탐험으로 돌아가기로 이어진다. 탭을 숨기거나 페이지를 떠나면 음성을 중단하고 끝까지 다시 듣기 전에는 답을 열지 않는다. 페이지 복원 시 같은 참가자로 다시 연결한다.

## 실행과 연결

```powershell
node experiences/spaceship-coop/server.mjs
# http://127.0.0.1:4318/experiences/spaceship-coop/

# 운영자가 같은 네트워크의 실제 기기 두 대를 연결할 때만 선택
node experiences/spaceship-coop/server.mjs --host 0.0.0.0 --port 4318
# 초대할 때는 0.0.0.0 대신 서버 컴퓨터의 실제 LAN IP를 쓴다.
```

기본 서버는 **127.0.0.1에만** 바인딩한다. 다른 기기와의 실제 연결에는 해당 기기가 접근할 수 있는 서버 주소와 방화벽 설정이 필요하다. localhost 링크는 다른 휴대폰으로 보내도 연결되지 않는다. LAN HTTP에서도 요청 ID와 음성 무결성 검사가 동작한다. HTTPS 전용 `crypto.randomUUID`나 `crypto.subtle`에 의존하지 않는다. 외부 서비스/DB/결제는 없다.

공통 서버에는 다음 계약으로 연결한다.

```js
import { createRoomHandler } from './spaceship-coop/server.mjs';
const spaceship = createRoomHandler({ prefix: '/api/spaceship', serveStatic: false });
// 기존 request handler 안: if (await spaceship(req, res)) return;
// 서버 종료: spaceship.close();
```

`createRequestHandler`는 같은 함수이고, `createServer(options)`는 독립 Node HTTP 서버를 돌려준다. API 경로를 바꾸면 HTML의 `meta[name="spaceship-api"]` content도 맞춘다. 로컬 IP/localhost 이외의 도메인 사용은 서버 `allowedHosts`에 명시한다.

정적 공개 허용: `index.html`, `style.css`, `app.mjs`, `audio.mjs`, `collection.js`, `shop.mjs`, `shop.css`, `starbook.mjs`, `assets/**`만. **`core.mjs`, `server.mjs`, 테스트, `qa/**`는 공개하지 않는다.**

### 인터넷 협동 API 후보 · 2026-10-09

기존 회사 VM의 별도 컨테이너로 `https://workspace.synk.im/api/spaceship`를 제공하고, 정적 게임은 `https://synk.im/try/spaceship-coop/`에서 불러오는 구성이다. **이 절은 로컬 구현·배포 준비 기록이며 운영 반영 증거가 아니다.** 공개 게임 HTML에는 배포 준비 도구가 다음 항목을 넣는다. 로컬 HTML은 기존 상대 경로를 유지한다.

```html
<meta name="spaceship-api" content="https://workspace.synk.im/api/spaceship">
```

- 방 입장은 기존 익명 체험과 24바이트 난수 방 토큰을 유지한다. 토큰은 해당 기기의 sessionStorage와 Authorization 헤더에만 쓰고 URL·초대 링크·계정 저장에는 넣지 않는다. SYNK ID 토큰을 iframe이나 협동 서버로 전달하지 않는다. 코인·보유품·완료한 탐험 수집 기록은 기존 부모 창의 계정 저장 경로를 사용한다.
- 방은 단일 프로세스의 임시 메모리에 둔다. 동시 방 50개, 주소별 진행 방 12개, 비활동 30분·최대 2시간 뒤 닫는다. 서버를 다시 시작하면 진행 방이 닫히고 새 탐험을 만들어야 한다. 계정에 이미 저장한 코인·보유품·수집 기록은 방과 별개다. 다중 인스턴스·자동 확장은 하지 않는다.
- 공개 API는 정확한 `workspace.synk.im` Host와 `https://synk.im` Origin만 허용한다. OPTIONS의 GET/POST·Authorization/Content-Type만 열고 credential CORS는 사용하지 않는다. 두 fetch 경로는 `credentials: 'omit'`이며 프록시는 Cookie를 지운다.
- 기존 Caddy의 고정 주소 `172.30.77.3`만 단일 X-Forwarded-For를 주장할 수 있다. IP 목록·프록시 체인은 거절한다. 다른 peer의 전달 헤더는 무시한다. 요청·방·rate 저장 수와 느린 SSE 연결의 버퍼에 상한을 둔다. 컨테이너는 `172.30.77.4`, 내부 4318만 쓰며 host 포트를 공개하지 않는다.
- `deploy/Dockerfile`은 서버·core·runtime 세 파일만 담는다. 정적 게임 파일·계정 설정·회사 volume·토큰·DB를 컨테이너에 넣지 않는다. `deploy/compose.yaml`은 기존 `synk-company_edge`에 연결하되 별도 프로젝트를 사용한다. 메모리 256MB·CPU 0.5·PID 64, 읽기 전용 파일 시스템, 권한 제거, 종료 유예 10초다.

검수한 고정 파일로 이미지를 만든 뒤 `SYNK_SPACESHIP_IMAGE`를 비밀 없는 `/etc/synk/spaceship.env`에 지정한다. `deploy/synk-spaceship.service`는 Docker와 회사 network 준비 뒤 시작하며, 회사 unit과 함께 재시작되도록 묶지 않는다. 후보 파일은 `/opt/synk/spaceship/current/deploy`에 두는 계약이다. 이미지 빌드는 이 게임 폴더를 context로 사용한다.

```sh
docker build --file deploy/Dockerfile --tag "$SYNK_SPACESHIP_IMAGE" .
docker compose --env-file /etc/synk/spaceship.env --file deploy/compose.yaml config --quiet
```

`deploy/Caddyfile.route`는 기존 사이트 블록에 추가할 경로 조각이다. **운영 회사 릴리스의 불변 Caddy 원문을 직접 고치지 않는다.** 현재 boot/배포 경로에 맞는 새 검수 후보에서 기존 회사 reverse_proxy·TLS·영구 volume을 보존하고 Caddy 설정 검사 후 반영한다. admin API reload만 한 결과는 컨테이너 재시작 뒤 유지되는 배포가 아니다. 실제 적용 담당은 회사 컨테이너 ID·시작 시각·이미지·원문 SHA를 전후 대조하고 회사 health와 협동 API의 Origin·권한 경계를 함께 확인해야 한다.

로컬 서버 검사는 `node --test experiences/spaceship-coop/server.test.mjs experiences/spaceship-coop/production.test.mjs`의 16개다. 기존 두 클라이언트 18장치 완주와 역할·정답 분리·재연결 검사를 포함하며, 새 8개는 공개 CORS·내부 health·전달 IP 위조·방/요청 상한·쿠키/계정 토큰 비수용·SSE 응답 헤더·정상 종료를 검사한다. 실제 Linux 이미지 기동·인터넷 SSE 두 클라이언트·실물 두 기기 로그인은 별도 증거가 필요하다.

## 내 우주선 상점

말 랠리의 공통 지갑·장착 흐름과 레이싱 차고의 구매 전 미리보기를 비교해, 같은 코인·가격·구매·저장 규칙을 연결했다. 입구·친구 대기실·완료 화면에서 `내 우주선 / Customize`를 연다. `?shop=1` 주소는 상점을 바로 연다. 함께 소리를 듣고 수리하는 동안에는 상점을 숨기며, 대기 중 상점을 열었더라도 두 사람이 준비해 수리가 시작되면 닫는다.

| 꾸미기 | 무료 기본 | 두 번째 | 세 번째 |
|---|---|---|---|
| 내 화면의 하늘 | 첫 별하늘 | 노을 하늘 · 15코인 | 밤하늘 · 35코인 |
| 우주선 몸체의 배지 | 반짝별 | 행성 고리 · 20코인 | 하트 · 40코인 |

카드를 고르면 실제 우주선 미리보기만 바뀌고, `사서 장착 / Buy & equip` 또는 `장착 / Equip`을 눌러야 본 게임에 적용된다. 무료 기본 꾸미기로 언제든 돌아갈 수 있다. 로그인한 WORLD에서는 복원한 계정의 공통 지갑으로 구매·장착하고 서버 응답 뒤 확정한다. 비로그인 체험은 브라우저 저장이며 로그인 안내를 제공한다. 저장 실패 시 코인과 기존 장착을 보존하며, 구매만 저장되고 장착이 실패한 경우는 따로 알린다. 코인 부족분·보유·장착 상태, 한국어/영어 안내, 모달 키보드 초점 복귀를 제공한다. 계정 저장의 실제 운영 반영 여부는 [계정 검증 기록](../beginner-games/qa/account-sync/README.md)에서 확인한다.

꾸미기는 **개인 화면의 우주선 그림에만** 적용된다. 친구의 모습과 색·위치·수량 문제의 조작/정답 그림은 바꾸지 않는다. 모든 탐험은 구매 없이 할 수 있다. 배경은 승인된 실제 펠트 `wide-lapis`, `wide-coral`, `wide-black`, 배지는 `sparkle`, `ring-butter`, `heart`를 그대로 재사용했다.

18개 장치 수리 후 **두 사람 모두 이륙한 경우에만** 각 브라우저 공통 지갑에 완주 코인 15개를 요청한다. 공통 하루 코인 보상 10회 제한을 따른다. 서버가 새 탐험마다 생성한 128비트 `expeditionId`로 중복 지급을 막아 같은 완료 화면 새로고침/재입장은 코인을 늘리지 않는다. `correct:0`으로 요청해 협동 수리 결과를 독립 학습 정답 보상으로 바꾸지 않는다. 코인 저장 실패는 결과 화면에서 다시 받을 수 있다. 코인은 브라우저의 놀이 기록이며 계정 간 동기화나 서버 결제 지갑은 아니다.

### 갖고 싶은 목표와 탐험 별지도 · 2026-10-09

기존 꾸미기 여섯 개에 **우리의 탐험 별지도 / Expedition starbook** 한 개를 더했다. `ship-keepsake-starbook`, 30코인, 영구 소유 수집품이며 장착 슬롯을 차지하지 않는다. 상점에서 상품을 이번 목표로 정하고 바꾸거나 해제할 수 있다. 현재 잔액으로 부족분을 계산하며, 구매 뒤에도 목표를 보존해 결과 화면에서 **모았어요 → 바로 사용하기**로 이어진다. 구매 전 별자리 모형에는 `예시 / Example`를 명시한다.

별지도를 사면 즉시 연다. 아직 완주가 없으면 빈 화면에서 친구와 탐험 준비로 안내한다. 완료한 탐험이 있으면 엔진·안테나·연료의 각 여섯 수리를 세 별자리로 보여 준다. 점의 높이는 실제 수리 순서의 표현에 따라 달라지고, 날짜·각 표현을 사용한 횟수·함께 쓴 일곱 표현이 남는다. **1200×1050 PNG 기념사진 저장**과 다음 탐험 준비를 제공한다. 반복 완주를 학습 향상이나 독립 정답으로 표시하지 않는다.

기본 탐험 기록과 일곱 표현의 실제 소리 듣기, 결과의 세 문항 회상은 구매하지 않아도 쓸 수 있다. 미소유 친구의 협동 진행에도 차이가 없다. 판매되는 것은 같은 기록을 꾸며 모으고 사진으로 저장하는 기념 방식이다.

`SYNK_SHIP_STARBOOK_V1`에는 공동 완주의 `expeditionId`, 완료 시각, 18개의 `{round,stage,word}`만 최근 여섯 탐험까지 저장한다. **소중한 기록으로 보관**한 탐험은 별도 키 `SYNK_SHIP_STARBOOK_V1:kept:<expeditionId>`에 같은 실제 기록을 저장하므로 일곱 번째 이후 완주에도 남는다. 기존 V1 배열은 읽을 때 다시 쓰거나 자르지 않는 추가 방식으로 이관한다. 참가자 토큰·방 코드·친구 이름은 넣지 않는다. 같은 탐험 재진입은 한 건으로 유지되며 손상된 항목만 제외한다. 기록 저장 실패는 완료 화면에서 다시 시도하고, PNG 실패도 원래 기록을 지우지 않는다. 서버/계정 저장이나 동기화는 아니다.

보관 해제는 원래 완료 날짜 그대로 최근 목록에 먼저 남긴 뒤 보관 표시를 지운다. 따라서 해제 직후·재로드·같은 완료 재수신 때 사라지지 않고, 다음 새 완료 저장에서만 최근 여섯 개 정책을 적용한다. 새 완주와 보관 변경은 지원 브라우저의 Web Locks로 직렬화하며, 보관 기록을 개별 키로 분리해 다른 탭의 최근 배열 저장이 덮어쓰지 못하게 했다. 저장 실패 시 상태를 거짓으로 바꾸지 않고 재시도를 안내한다. 다른 탭 변경을 읽어도 선택한 탐험과 키보드 초점을 유지한다. 무료 사용자도 보관 기능·기본 기록·일곱 소리를 쓰며, 구매 소유자는 같은 기록을 별지도와 PNG로 사용한다.

`?collection=starbook`은 기록 모달을 바로 연다. 소유자는 실제 별지도, 미소유자는 무료 기록이며 자동 음성을 시작하지 않는다. 저장된 현재 방 세션은 유지하고 닫은 뒤 같은 방을 이어 할 수 있다. `collection=starbook`과 `shop=1`이 함께 있으면 기록 바로가기가 우선이다.

현재 검증: Node 24검사, 실제 음성 두 사람 전체 UI 95체크, 기존 상점 18체크, 별지도 목표·빈 화면·실패 UI 12체크, 소중한 기록·두 탭·바로가기 UI 25체크. 범위와 테스트 지갑 구분은 `qa/STARBOOK-20261009.md`를 따른다.

## 서버가 책임지는 것

- 방/토큰 생성, 두 자리 배정, 단계·목표·판정·역할 교대·공동 이륙은 서버 권위다. 화면 분할로 협동을 흉내 내지 않는다.
- 서버가 각 참가자에게 다른 상태를 투영한다. 설명서 참가자만 현재 목표를 받는다. 조종사에게는 친구가 선택해서 보낸 소리와 본인 조작 결과만 간다. 전체 정답열·상대 토큰·상대 개인 통계는 나가지 않는다.
- 24바이트 무작위 참가자 토큰은 `Authorization` 헤더로만 보낸다. 초대 URL에는 토큰이 없다. 입장 정보는 기기의 `sessionStorage`에 둔다.
- 한 토큰은 동시에 하나의 SSE 연결만 유지한다. 다른 창이 같은 자리를 이어받으면 기존 창에 명시하고 자동 재접속을 중단한다. 참여자 둘은 각자 별도의 토큰이다.
- 실제 disconnect가 감지되면 조작을 멈추고 새로 연결한 같은 토큰은 같은 단계/자리로 돌아온다. 새로고침 시 소리를 다시 준비한 뒤 이어 한다.
- 요청 스키마/역할/단계/허용 표현을 검사한다. 변경 요청의 revision이 오래되면 거절하고, 완료된 요청 ID의 재전송은 중복 반영하지 않는다. 최근 300개 ID를 참가자별로 보관한다.
- 방 만들기/입장의 재시도 ID도 중복 생성·중복 자리 차지를 막는다. 세 번째 사용자의 입장은 거절한다.
- 입장 요청을 서버가 처리한 뒤 응답만 유실돼도 같은 요청 ID를 다시 쓴다. 성공 응답 전의 요청 종류·방 코드·ID를 sessionStorage에 남겨 재클릭·새로고침이 원래 방과 자리로 복구되게 한다. 다른 방/새 탐험으로 바꾸거나 확정적인 방·입력 거절을 받으면 이전 요청을 이어 쓰지 않는다. 요청 제한·서버 장애처럼 일시적인 거절은 이미 수락된 자리가 있을 수 있어 같은 ID를 보존한다. 그만두기 요청이 실패하면 입장 정보를 보존해 다시 종료할 수 있다. 다음 요청에서 서버의 `CLOSED` 410 또는 `ROOM_MISSING` 404를 확인한 경우에는 종료할 수 있으며, 인증·Origin 거절은 종료 확인으로 취급하지 않는다. [통신 복구 r2 검증](qa/nonvoice-recovery-20261009-r2/README.md).
- WORLD로 나가는 확인 창이 열린 동안 서버가 방을 만료/종료했더라도 확인을 누르면 선택한 WORLD 목적지로 이동한다. [실제 dialog/SSE r3 검증](qa/nonvoice-recovery-20261009-r3/README.md).
- 아무도 조작하지 않은 방은 30분, 전체 방 수명은 2시간이다. SSE heartbeat만으로 방을 연장하지 않는다. 누구든 그만두면 두 사람의 탐험을 종료한다. 서버 재시작 뒤에는 메모리 방이 사라진다.
- 최대 200방, 본문 4KB, IP별 요청·생성·입장 제한. 같은 origin 검사, 로컬 호스트/DNS 재바인딩 방어, 정적 경로 제한. 인터넷 공개 서비스에 필요한 인증·영속 저장·운영 모니터링은 이 로컬 서버가 제공하지 않는다.

## 소리와 학습 기록

`assets/audio/manifest.json`의 `approved:true`, `provider:typecast`, 정확한 한국어 문구, 각 MP3의 SHA-256 무결성, 브라우저 디코드, 길이와 실제 음량을 모두 확인한 뒤 입장을 연다. 승인되지 않거나 빠지거나 손상되거나 무음이면 시작할 수 없다. OS TTS나 무음으로 대체하지 않는다. 음성 파일은 루트의 승인된 Typecast 서현 경로에서 준비했다. 효과음은 낮은 음량의 Web Audio 오실레이터이며 한국어 음성을 대신하지 않는다.

조종사의 답 조작은 받은 음성의 **정상 재생 완료 후** 열린다. 다른 소리로 중단되거나 재생에 실패하면 다시 듣기가 필요하다. 단계 학습도 한 소리를 끝까지 들은 경우에만 완료로 표시한다.

학습 연습 영역: 기초 색·위치·수량 표현의 소리-의미 연결, 듣고 조작하기, 상황에 맞는 표현 선택, 다시 듣고 확인하기. **TOPIK I 듣기에 필요한 기초 표현을 준비하는 놀이**이며 실제 시험 문제와 동일하지 않다.

서버는 다음을 구분한다.

- 친구가 보낸 말과 내가 누른 조작이 같은지: `listeningCorrect / listeningAttempts`.
- 친구가 목표 그림과 같은 뜻의 말을 보냈는지: `matchingSignals / signals`.
- 공동 수리: 목표와 전달한 말과 조작이 함께 맞아야 성공.
- 다시 듣기 `replays`, 연습장 열기 `help`, 해당 장치의 첫 시도 해결 여부.

따라서 친구가 잘못 보낸 말을 정확히 듣고 행동했을 때는 조종사의 듣기와 설명서 선택을 구분해 알려준다. 협동 수리 성공을 **독립 학습 정답이나 학생의 학습 향상**으로 저장하지 않는다. 별도 Atlas 학습 정답은 호출하지 않으며, 상점에 연결된 코인은 함께 끝낸 탐험의 완주 보상만 요청한다. 결과의 3문항 단독 회상은 로컬 즉시 복습이며 인증된 학습 성적이 아니다. 사용자 학습 향상·재미·재방문은 실제 학생 플레이로 확인해야 한다.

## 다시 방문했을 때의 짧은 복습 · 2026-10-09

완주 기록이 있으면 로비와 무료 탐험 기록에서 소리 3개를 혼자 다시 골라 볼 수 있다. 선택한 탐험에서 실제 사용한 색·위치·횟수 표현을 하나씩 가져오며 기존 승인 MP3를 그대로 쓴다. 음성의 정상 재생이 끝나야 그림 선택이 열리고 첫 답 뒤에만 뜻과 교정을 보여 준다. 놓친 표현은 세 소리 뒤에 한 번 더 듣고 행동한다. 첫 답 결과와 재시도는 구분하며 코인·새 완주·기존 협동 성적·학습 숙달 기록으로 합산하지 않는다.

복습은 선택 사항이며 시간 제한이 없다. 현재 친구 탐험을 유지한 채 열고 닫을 수 있고, 둘의 탐험이 시작되면 복습 소리를 멈추고 원래 게임으로 돌아간다. 같은 문서에서 닫았다 다시 열면 복습 위치와 고른 답을 유지한다. 복습 기록을 새로운 브라우저 전용 저장소나 계정 스키마에 추가하지 않았다. 완주 직후의 기존 단독 회상도 유지한다.

별지도 사진은 준비 완료와 실제 기기 저장을 구분한다. PNG 미리보기와 직접 다운로드 링크를 제공하고, 기록을 바꾸거나 닫으면 Blob URL을 해제한다. 닫힌 화면·다른 기록에서 늦게 끝난 사진은 안내나 초점을 바꾸지 않는다. 상점의 부족 코인과 미달 목표에는 공통 `beginnerRewardRoute`가 고른 다음 입문 연습을 연결하고, 지급이 불가능하거나 예전 API이면 무료 놀이 입구를 안내한다. 방이 열려 있을 때 다른 놀이로 이동하면 기존 탐험 종료 확인을 거친다.
