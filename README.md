# SYNK — 회사 기준·교육 엔진·제작 운영

SYNK·LAB·SHIFT·PULSE가 함께 쓰는 회사 기준, 교육 엔진과 제작 원본을 관리합니다. Apps Script 실행 코드와 회사 문서는 이곳에, 학생 앱은 형제 SYNK-talk, 기업 웹 제작은 형제 SYNK-website에 있습니다. 구현·게시·실제 운영 성과는 구분합니다.

## 처음 열면

- AI 작업: [공통 운영 원칙](docs/AI_운영원칙.md)을 먼저 읽습니다. 모델별 진입점은 [Codex](AGENTS.md) · [Claude](CLAUDE.md) · [Gemini/Antigravity](GEMINI.md)입니다.
- 회사·교육·브랜드 자료: [자료 지도](docs/문서_지도.md)에서 이번 일에 필요한 정본만 찾습니다.
- 현재 일: [결정 기록](docs/_ops/결정.md) · [남은 일](docs/_ops/트랙.md)과 실제 파일·작업 사본·최근 변경을 대조합니다.
- 적용 구조와 확인 범위: [작업 연결 구조](docs/AI_워크플로우_아키텍처.md).

세 모델의 지침 파일은 자료를 찾는 출발점입니다. 한 모델을 열었다고 다른 모델도 자동 실행되거나 모든 정본을 읽는 것은 아닙니다. 자세한 읽기·인계 방식은 공통 운영 원칙을 따릅니다.

## 어디에 무엇이 있나

| 자리 | 역할 |
|---|---|
| 루트 `Code.js`·`엔진_*.js`·기타 업무 코드 | Apps Script 실행 코드. 경로·전역 이름공간을 보존 |
| 루트 `contents_*.js` | 엔진이 함께 쓰는 콘텐츠 |
| `docs/` · `계약/` | 정본·설계·기록·브랜드 원본. 지도에서 필요한 자료로 이동 |
| `tools/` · `tests/` | 제작·조회·검사 도구와 시험 |
| `영상/` · `캐러셀/` · `crewcard/` | 별도 제작 원본·빌드·결과물 |
| `.claude/` · `.agents/` · `.codex/` | 모델별 설정·스킬·공용 함수. 링크된 원본을 중복 파일로 오인하지 않음 |
| `.claude/worktrees/` | 다른 작업의 별도 사본. 오래됐다는 이유로 삭제하지 않음 |

배포 파일은 [`.claspignore`](.claspignore)의 실제 허용 패턴이 정합니다. 파일 수를 안내문에 고정하지 않습니다. 학생 접점 앱의 별도 저장소 `SYNK-talk`는 그 자리의 지침을 따릅니다.

## 확인하고 작업하기

```text
node tools/session-freshness.js --repo C:/Users/q1212/Documents/SYNK-appsscript --repo C:/Users/q1212/Documents/SYNK-talk --json
node --test tests/<관련 파일>.test.js     # 바꾼 기능의 관련 시험
```

명령은 현재 작업 폴더를 검사합니다. 다른 기계에서는 두 기준 작업본의 실제 경로로 바꿉니다. 뒤처짐 0도 미커밋 원본과 내용이 다를 수 있습니다. 이번 일의 원문·자산을 실제로 읽고 필요하면 `--files docs/AI_운영원칙.md`처럼 관련 파일을 대조합니다. 자세한 후속 작업 방식은 [공통 원칙의 최신 상태 절](docs/AI_운영원칙.md#세션-사이-최신-상태)을 따릅니다.

독립 작업은 기본 하네스의 병렬 기능을 쓰고, 자기 변경만 커밋합니다. 커밋·원격 반영·실제 배포는 서로 다른 단계입니다. 배포가 요청 범위에 있을 때 배포 스킬로 검증합니다.

옛 강제 Git/Claude 훅이 현재 작업을 막아 준다고 가정하지 않습니다. `.claude/hooks/`에는 비활성 훅뿐 아니라 지금도 도구·시험이 참조하는 함수가 있습니다. 현재 자동 연결과 신뢰 승인 상태는 위 보고서에서 확인합니다.

## 정리와 보존

현재 원본과 필요한 상세 자료는 남기고, 낡은 설명은 현행 정본으로 연결합니다. Git에서 무시된 파일도 원본·완성작·미완성 작업일 수 있으므로 무시 여부만으로 지우지 않습니다. 자격증명과 학생 식별 데이터는 게시·인계하지 않습니다. 공개 저장소에 올릴 범위는 실제 권한과 게시 조건을 따릅니다.
