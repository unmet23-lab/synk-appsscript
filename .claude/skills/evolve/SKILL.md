# 지침 진화 (evolve)

> **v1.1 · 2026-07-31** — 이 파일이 지침 진화 절차의 **정본**이다. 공용 지침(`CLAUDE.md`)의 '지침 진화' 섹션에는 요약만 두고 절차를 복제하지 않는다. (v1.1: GPT·Codex 스택 하차로 사본 3종→1종, `.agents/` 미러 폐지 — 유호님 07-31 지시.)

공용 작업 지침을 "완성품"이 아니라 계속 진화하는 시스템으로 다룬다. 목표는 완벽에 가깝도록 진단 → 수정 → **압축** → 상호발전을 한 사이클 도는 것 — 이게 유호님이 정의한 "트렌디"의 운영형이다. **한 번에 지침 전체를 다시 쓰지 않는다. 근거 있는 조항만 최소로 손댄다**(전면 압축은 유호님 명시 지시가 있을 때만 — v5.0·v6.0 전례).

## 실행 순서 (순서 엄수)

1. **신호 수집** — 개정 재료를 모은다.
   - **`node tools/friction.js` 를 먼저 돌린다**(장부=`docs/_ops/장부/` 의 F*.md 조각들). 살아있는 신호 목록과 "해소 수단별" 집계가 나온다 — 후자가 **어느 조항·훅이 실제로 작동했는지**의 유일한 실측치다. 기억이나 인상으로 세지 않는다(2026-08-03 이전에는 신호가 기록만 되고 세어지지 않아, 버전 충돌 횟수조차 "관측 합집합이라 하한"으로만 알았다).
   - 메모리의 `feedback` 타입 항목(유호님의 교정·거절·승인)과 지침 관련 메모리(master-directive 등) 훑기.
   - `node tools/memory-graph.js` — 고아 노드·깨진 링크·인덱스 불일치는 그 자체가 압축 후보다.
   - `git log`로 `CLAUDE.md`·`.claude/skills/`·`docs/지침_이력.md` 최근 변경 이력 확인.
   - 최근 세션의 마찰(유호님 교정·거절·불만·내 반복 실수)과 유호님이 직접 준 개정 입력.
   - **신호가 하나도 없으면 여기서 멈추고 "개정할 근거 없음"을 보고한다**(억지 개정 금지).

2. **개정 후보 진단** — 조항 단위로 추가/수정/삭제/압축 후보를 만든다.
   - **후보마다 실제 사건·유호님 발언 근거를 붙인다. 근거 없으면 후보 자격 없음**("항상 최선을 다한다" 류 일반론 조항 금지).
   - 추가만큼 **압축**을 본다: 값어치 못하는 조항·중복을 잘라낼 후보도 함께 올린다. 단 진짜 낭비는 문서 길이가 아니라 과잉 검증 습관이니(실측: 지침 52줄을 20% 줄여야 360토큰, 같은 날 심층감사 하나가 600만 토큰), **문구를 줄이려 전투검증 조항(검증 결정표·분리 반박·판독 인용·비가역 게이트 등)의 뉘앙스를 깎지 않는다.** 압축 대상엔 지침 본문만 아니라 **메모리 인덱스·세션보드**도 포함한다.
   - `docs/지침_이력.md`의 "재론 금지" 목록과 대조해, 이미 정착·거절된 결정을 새 근거 없이 되살리지 않는다.

3. **분리 반박 패스** — 후보를 공격한다.
   - 생성(2단계)과 **분리된 적대 패스**로 돌린다 — 방어가 아니라 공격만. "애매하면 통과"를 기본값으로 두지 않는다(게이트가 열려 헛돈다).
   - 단 지침·스킬은 **git으로 되돌릴 수 있는 문서**다. CLAUDE.md 검증 결정표에 따라 **가벼운 반박 1패스면 충분** — 다중 에이전트 심층 검증은 쓰지 않는다(가역 문서에 과잉).

4. **반영** — 살아남은 후보만 적용한다.
   - `CLAUDE.md`를 수정하고 상단 **버전 스탬프를 범프**한다(`vX.Y · 날짜`).
   - `docs/지침_이력.md`에 이번 변경을 **1줄** 추가한다(무엇을 · 왜 = 근거 사건).

5. **사본 동기화 — 현재 ⛔동결이라 이 단계는 건너뛴다.**
   - 유일한 사본 `docs/COWORK_지침.md`는 **2026-08-03 동결**(유호님이 cowork 미사용). 전파하지 말고, 재복붙을 대기 항목으로 올리지도 말라 — 안 쓰는 도구의 사본을 8판째 추적하던 것이 v7.0에서 닫은 비용이다. 갱신 절차는 그 파일 머리말에 자기완결로 들어 있다.
   - **되살아나는 조건 = 유호님의 cowork 재사용 통보뿐이다**(GPT 사본 폐기와 같은 판정 축). 그때 이 단계를 복원한다.

6. **기록·마감**
   - 이번 개정이 막은 신호를 **장부에 닫는다**: `node tools/friction.js resolve F0NN "무엇이 막았나"`. 닫지 않으면 다음 사이클이 같은 신호를 또 재료로 집어 든다.
   - 이번 사이클에서 새로 발견한 마찰은 `node tools/friction.js add <교정|거절|실수|마찰> "설명"` 으로 남긴다.
   - 새로 확정된 결정·마찰 신호를 메모리에 갱신한다(다음 진화의 연료 — CLAUDE.md '마찰 신호' 조항과 짝).
   - 멀티세션 중이면 내 보드 줄(`docs/_ops/보드/<내 지문 8자리>.md`)을 갱신한다.
   - 문서 변경이므로 `git add`(지침 관련 파일만 명시 지정) → 커밋 → `git push origin master`로 백업한다. **`/deploy`·`clasp push`는 쓰지 않는다** — 지침은 라이브 Apps Script 코드가 아니다.

## 적용 판단 (트리거)
- **기본은 유호님 호출**("지침 진화"·"지침 다듬어줘"·"/evolve").
- AI는 마찰 신호가 쌓였을 때 **실행을 제안만** 한다 — 자동 실행하지 않는다. 유호님 승인 후 진행.

## 의도적으로 배제한 것 (다시 넣지 말 것)
- **매 세션 자동 실행** — 소음이다. 진화는 신호가 쌓였을 때만 돈다.
- **근거 없는 조항 추가** — 실제 사건 없이 "좋아 보이는" 규칙은 토큰만 먹고 행동을 안 바꾼다(2단계 근거 게이트로 차단).
- **무한 순증가** — 추가만 하고 압축을 안 하면 지침이 비대해진다. 매 사이클 압축 후보를 반드시 검토한다.
- **다중 에이전트 심층 검증** — 지침은 git 가역 문서라 과잉. 되돌림 비용에 안 맞는다.
- **지침 전면 재작성** — 매 사이클 뜯어고치면 정착된 결정이 흔들린다. 근거 있는 조항만 최소로 손댄다.
