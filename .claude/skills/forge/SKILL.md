# 결과물 도출 (forge)

> **v3.2 · 2026-07-10** — 이 파일이 forge 절차의 **정본**이다. 다른 문서에는 요약만 두고, 절차를 다시 복제하지 않는다.

중요 산출물 1건을 "서로 다른 접근 2개 → 하드 게이트 → 병합"으로 도출한다. **이 스킬 실행 자체가 검증 구조이므로, 공용 지침의 자기검증 루프는 중복으로 돌리지 않는다.**

## 실행 순서

0. **애매성 사전 확인 (조건부)** — 요청 방향이 여러 갈래로 갈릴 만큼 애매할 때만, 버전 제작 전에 확인 질문 **1개**를 딱 한 번 던진다. 애매하지 않으면 건너뛰고 바로 1단계로.
1. **의도 파악** — 요청의 목적·톤·제약(SYNK 철학·브랜드 톤 등)을 명확히 정리한다. 이후 모든 단계(생성·채점·병합)가 이 이해를 기준으로 움직인다.
2. **서로 다른 접근으로 2버전 병렬 생성** — 복제 금지. 의도적으로 다른 각도로 만들되 둘 다 요청 의도는 100% 반영.
   - **A안 — 안전·보수**: 검증된 톤, 리스크 최소화, 원본 요청 밀착
   - **B안 — 임팩트·과감**: 더 강한 훅, 다른 구조·표현
   - 순차가 아니라 **동시 생성**. 서브에이전트 사용 가능 환경에서는 병렬로 내린다 — 모델은 지정하지 않는다(세션 모델 상속 · 유호 확정 08-13 「모델은 유호님이 고른다」).
3. **하드 게이트 — 점수를 넘어 통과/탈락** — 버전마다 ① 사실관계 오류(근거 없는 통계·틀린 인용) ② 법적·평판 리스크(과장된 보장, 지킬 수 없는 약속)를 검사해, 하나라도 걸리면 그 버전은 병합 후보에서 자동 탈락.
   - 검사는 **생성과 분리된 별도 패스**로 수행한다(서브에이전트 가능 환경에선 별도 검증 에이전트 — 생성자가 자기 산출물을 검사하는 자기확증 방지).
   - **둘 다 탈락 시**: 탈락 사유를 반영해 **1회만** 재생성 → 그래도 실패면 실패 사실과 사유를 그대로 보고한다(억지 통과 금지).
4. **소프트 채점 (고정 루브릭)** — 게이트 통과 버전만: ① 목적 부합도 ② SYNK 톤·철학 정렬 ③ 완성도·디테일. 고정 기준이므로 판단 근거가 그때그때 감으로 바뀌지 않는다.
5. **수렴 체크** — 두 버전이 실질적으로 의미 있게 다르지 않으면 병합을 건너뛰고 "두 접근이 수렴해 하나로 정리함"이라고 있는 그대로 보고한다. 작업 부풀림 금지.
6. **하이브리드 병합** — 각 버전의 가장 좋은 요소를 재조합한다(예: A의 안전한 구조 + B의 강한 훅). 병합 불가이거나 한쪽이 압도적일 때만 단일 채택.
7. **창의적 대안 (선택)** — "의도대로보다 다르게 접근하면 더 낫다"고 판단될 때만 별도 대안 1개. 톤 차이가 아니라 **형식·구조 전환**(예: 텍스트 카피 → 표 비교)까지 검토. **창의적 대안도 3단계 하드 게이트를 통과해야 제시 가능**(게이트 우회로 금지). 판단 안 되면 생략.
8. **최종 보고**
   - **최종안** — 전체 결과물(병합 결과 또는 수렴 시 단일안)
   - **판단 근거 1줄** — 어떤 기준에서 어떻게 결정했는지, 탈락한 요소가 있으면 함께
   - **창의적 대안** (있는 경우만) — 결과물 + 다르게 접근한 이유 1줄. 없으면 섹션 자체를 생략.

## 적용 판단 (자동 적용은 이 경우만)

외부 공개물(광고·공지·발행 콘텐츠)의 확정본, 굵직한 기획·제안 산출물, 유호님이 중요하다고 표시한 것. **자동 적용 시 보고 첫머리에 "forge 적용" 1줄을 명시한다.** 그 외에는 유호님 명시 호출만.

## 의도적으로 배제한 것 (다시 넣지 말 것)

- 같은 접근으로 단순 재생성 2회 — 표현 차이만 나고 품질 향상 없음
- 모든 질문에 기본 적용 — 단순 질문엔 낭비
- 탈락 요소 완전 숨김 — 선택권 상실, 최소 1줄 요약 유지
- 매번 사전 확인 질문 — 애매성이 임계치를 넘을 때만
