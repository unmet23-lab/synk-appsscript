# SYNK 디자인 작업 순서

1. **루트 `DESIGN.md`부터 읽는다** — 킷 요약(색·타이포·로고·철칙)과 정본 링크·산출물별 통로가 전부 거기 있다.
   값이 필요한 층은 정본을 연다: 색 값 = `docs/디자인_토큰.json`(기계 원천 · 빌드 = `node tools/토큰빌드.js`) · 컨셉·표현 모드 = `docs/디자인_컨셉_정본_v1.md` · 폰트 = `docs/브랜드_폰트_정본.md` · 인쇄물 = `docs/발표물/_브랜드킷.md`.
2. **킷 먼저, 스킬 나중** — 골격·색·타이포를 킷으로 세운 뒤, 디테일(모서리·그림자·아이콘·히트 영역·모션)은
   `make-interfaces-feel-better` · `emil-design-eng` 원칙으로 다듬는다.
3. **충돌은 킷이 이긴다** — 외부 스킬 조언이 킷 규칙(순백·순검정 금지 · 신호 1점 · 폰트 3종 배타 등)과
   부딪히면 킷을 따른다. 외부 스킬은 킷이 침묵하는 디테일만 채운다.
4. **검수** — 발표물·인쇄물이면 `node tools/발표물린트.js docs/발표물/*.html`. 모션이 든 화면이면
   `emil-design-eng` 원칙(빈도→목적→이징→시간)으로 되짚는다. 라이브 화면은 코드가 아니라 **렌더 픽셀**로 증명한다.
5. 레퍼런스가 필요하면 DESIGN.md §7 사이트를 **브라우저로** 연다 — 상시 MCP 연결 금지(이미지 토큰 예산).
