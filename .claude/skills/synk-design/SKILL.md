# SYNK 디자인 작업 순서

0. **🎨 먼저 가른다 — 「이건 누구 손이 마지막에 닿나」** (2026-09-03 신설 · 유호 지시 「클로드 디자인을 못 쓰고 있다」)
   - **유호님 손**이 마지막에 닿을 물건(시안·포스터·전단·카드·한 장짜리·목업·「나란히 보고 고를 것」)이면
     → 스킬 **`synk-canvas`** 로 간다. 클로드 디자인 캔버스를 킷 그대로 열어 주는 절차가 거기 있다.
     값은 「내가 더 잘 그린다」가 아니라 **유호님이 나 없이 고치실 수 있다**는 것 하나다.
   - **기계 손**이 마지막에 닿을 물건(인쇄물 정본 `docs/발표물/`·홈페이지·앱 화면·문서 지면)이면
     → 아래 1번부터 그대로. 저장소가 정본을 쥐고 검사가 지킨다.
   - **애매하면 캔버스가 아니다.** 정본이 두 곳에 있으면 반드시 갈린다.

1. **루트 `DESIGN.md`부터 읽는다** — 킷 요약(색·타이포·로고·철칙)과 정본 링크·산출물별 통로가 전부 거기 있다.
   값이 필요한 층은 정본을 연다: 색 값 = `docs/디자인_토큰.json`(기계 원천 · 빌드 = `node tools/토큰빌드.js`) · 컨셉·표현 모드 = `docs/디자인_컨셉_정본_v1.md` · 폰트 = `docs/브랜드_폰트_정본.md` · 인쇄물 = `docs/발표물/_브랜드킷.md`.
2. **킷 먼저, 스킬 나중** — 골격·색·타이포를 킷으로 세운 뒤, 디테일(모서리·그림자·아이콘·히트 영역·모션)은
   `make-interfaces-feel-better` · `emil-design-eng` 원칙으로 다듬는다.
2-b. **겹치면 이 순서다.**
   - **① 색·폰트·율·재질은 킷만 본다.** 예외 없다. 외부킷(uupm)에는 팔레트·폰트 층을 들여놓지 않았으므로
     `--domain color`·`--domain typography` 는 「File not found」로 죽는다 — **막히는 게 정상이다.**
     🚫 `--design-system`·`--persist` 플래그는 **영구 금지** — 팔레트 파일이 없어도 `#2563EB`/`Inter` 를
     지어내서 검색 결과인 척 찍는다. 파일을 안 들이는 것으로는 안 막히고 플래그 금지로만 막힌다.
   - **② 모션 «값»**(시간·이징·스태거·눌림 스케일)은 `docs/디자인_토큰.json` 「감각.규칙」(300ms 상한 · transform/opacity만 ·
     눌림 scale 0.96 · reduced-motion)이 1순위, 규칙에 없는 숫자는 `emil-design-eng` 표.
     ⚠ 토큰 「감각.가안」은 **값이 아니다** — Expo 첫 화면 실물 확정 전까지 새 산출물이 인용하지 않는다(DESIGN.md §8 · 유호 확정 08-06).
     ⚠ uupm `--domain gsap` 은 값을 꺼내는 자리가 아니다 — 대부분 GSAP 코드인데 SYNK 지면은 `tools/lib/loom.js` 의 CSS 이고
     앱은 Expo 다. 거기서 읽을 것은 «어떤 패턴이 있고 언제 쓰나»뿐이다.
   - **③ 정적 디테일**(모서리·광학 정렬·그림자·tabular-nums·히트 영역·아이콘 획)은 `make-interfaces-feel-better`.
   - **④ 폼·내비게이션·접근성(WCAG 2.2)·반응형·성능·콘텐츠 잘림** — 이 여섯은 **SYNK 정본이 «없는» 자리**라
     바깥이 이긴다: `python docs/외부킷/uupm/scripts/search.py "<두세 낱말>" --domain ux`.
     ⚠ `--domain` 을 생략하지 않는다 — 자동 감지가 엉뚱한 데이터로 떨어진다.
   - **⑤ 차트**는 하네스 `dataviz` 스킬을 **먼저** 연다(브랜드 팔레트 교체를 전제로 설계돼 킷과 안 싸운다).
     `--domain chart` 는 «언제 쓰지 마라»와 «접근성 폴백»만 읽는다 — 색 값은 반입 때 `〈킷색〉` 으로 갈아 놨다.
   - **⑥ 영상**(Remotion)은 `remotion-markup`(API 를 맞게 쓰는 법) → `remotion-motion-graphics`(보기 좋게 만드는 판단)
     → `remotion-captions`(자막) 순. 색·폰트는 **`영상/src/킷/`** 을 지나서만 화면에 닿는다.
     `remotion-best-practices` 는 일부러 안 받았다(다른 스킬의 사본을 대량으로 끌고 온다) — 재반입하지 않는다.

3. **충돌은 킷이 이긴다** — 외부 스킬 조언이 킷 규칙(순백·순검정 금지 · 신호 1점 · 폰트 3종 배타 등)과
   부딪히면 킷을 따른다. 외부 스킬은 킷이 침묵하는 디테일만 채운다.
4. **검수** — 발표물·인쇄물이면 `node tools/발표물린트.js docs/발표물/*.html`. 모션이 든 화면이면
   `emil-design-eng` 원칙(빈도→목적→이징→시간)으로 되짚는다. 라이브 화면은 코드가 아니라 **렌더 픽셀**로 증명한다.
5. 레퍼런스가 필요하면 DESIGN.md §7 사이트를 **브라우저로** 연다 — 상시 MCP 연결 금지(이미지 토큰 예산).
