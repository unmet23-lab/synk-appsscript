# SYNK 세션 정리

사용자가 “지금 끊자”, “세션 정리”, “끊고 새로 열자”처럼 종료를 정한 뒤에만 쓴다. 현행 기준은 `docs/AI_운영원칙.md`와 각 저장소의 `AGENTS.md`다.

## 1. 현재 상태를 다시 읽는다

- `git status`, 관련 diff, 최근 커밋을 확인하고 merge/rebase 진행 여부를 본다.
- 현재 하네스가 제공하는 네이티브 작업·에이전트 목록과 메시지 기능으로 겹치는 파일만 조율한다. 특정 제품의 옛 도구 이름을 가정하지 않는다.
- 이 대화에서 실제로 만든 변경, 다른 작업의 미커밋·스테이징, 미완료 작업을 구분한다. 저장소 전체의 미커밋을 0으로 만드는 것은 완료 조건이 아니다.

## 2. 이번 작업만 마무리한다

- 요청된 산출물과 관련 검증을 끝낸다. Apps Script 라이브 반영이 이미 요청된 범위라면 `$deploy`를 사용하고, 그렇지 않으면 로컬·GitHub·라이브 상태를 구분해 남긴다.
- 커밋·push가 현재 요청에 포함되거나 정상 인수에 필요한 경우에만 자기 변경을 경로로 지정해 처리한다. 남의 변경을 stage, stash, reset, 삭제하지 않는다.
- 열린 PR이나 worktree는 이번 작업이 실제로 끝났고 그 정리가 현재 권한 안일 때만 네이티브 기능으로 닫거나 정리한다. 미완료면 작업 사본·브랜치·시험·다음 행동을 해당 작업에 남긴다.
- 공용 `docs/_ops/트랙.md`는 이번 작업이 소유한 현행 항목만 갱신한다. 끝낸 항목은 정리하되 다른 작업의 기록이나 장부를 종료 의식처럼 전수 수정하지 않는다.

## 3. 기억 경계

- 개인 기억은 사용자가 이번 대화에서 **명시적으로 기억 갱신을 요청한 경우에만** 해당 환경의 공식 갱신 절차를 사용한다.
- `MEMORY.md`나 기존 기억 파일을 직접 수정하지 않는다. 종료 자체, 칭찬, 추정, 오래된 결정을 기억 승인으로 확대하지 않는다.
- `docs/_ops/결정.md`도 현재 요청에서 확정된 결정과 근거가 있고 이번 작업이 그 기록을 맡았을 때만 기존 도구로 갱신한다.

## 4. 종료 보고

다음을 짧게 구분한다.

- 실제 완료한 것과 확인 증거
- 커밋·push·배포 여부
- 남아 있는 다른 작업의 미커밋과 손대지 않은 이유
- 열린 작업/PR/worktree와 다음 행동
- 기억 갱신 여부와 사용자 요청 근거

현재 앱이 제목 변경 기능을 제공하면 네이티브 기능으로 알아보기 쉬운 제목을 붙일 수 있다. 사용 가능한 기능 이름을 추측하거나 사용자가 창을 닫고 다시 열도록 강제하지 않는다.

세션 종료를 자동 훅이 기록하거나 다음 시작에 경고한다고 가정하지 않는다. 필요한 인계는 위 보고와 실제 작업 상태가 맡는다.
