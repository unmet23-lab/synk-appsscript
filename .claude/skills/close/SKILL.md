# /close — 세션 끊기 파이프라인

목적: **끊는 비용을 0으로 만든다.** 2026-08-04 실측 — context-budget 경고가 8번 떴는데도 세션은 786k까지 갔다. 부족한 건 알림이 아니라 실행이었다: 커밋·기록·메모리를 손으로 하려니 매번 「나중에」가 됐다.

**끊을지 말지는 유호님이 정한다. 이 스킬은 「끊기로 했다」 다음부터를 맡는다.**

## 전제 — 세션 간에 넘어가는 건 셋뿐

계정을 갈아타면 대화 맥락은 안 넘어간다. 넘어가는 것은 ①커밋 ②PR 본문(안 끝난 트랙의 다음 할 일) ③메모리. 이 스킬은 그 셋을 순서대로 채운다. **하나라도 비면 다음 세션이 처음부터 다시 판단한다.**

## 절차 (순서 엄수)

### 1. 상태 실측 — `--short` 금지
```bash
git status
```
**전문을 본다.** `--short`는 rebase 진행 중을 감춘다(F035·F038). rebase·merge 중이면 **멈추고 유호님께 보고** — 끊으면 안 되는 상태다.

이어서 `git log --oneline -10`으로 다른 세션이 그 사이 밀어넣은 커밋을 본다.

### 2. 내 것과 남의 것을 가른다
미커밋을 전부 내 것으로 가정하지 않는다. 판별 순서:
- `list_sessions` 로 **지금 도는 다른 세션**을 본다(`isRunning` · 제목 · `prNumber`) — 그 세션이 만지는 자리면 남의 것, 손대지 않는다
- 이 대화에서 내가 편집한 파일인가 → 내 것
- 애매하면 `git diff <파일>`로 내용을 보고 판단하고, 그래도 애매하면 **유호님께 묻는다**

남의 미커밋은 **그대로 두고 보고에 1줄로 명시한다.**

### 3. 커밋 — 범위를 못 박는다
```bash
git commit -F <메시지파일> -- 경로1 경로2
```
- `git add -A`·`git commit -a`는 `git-scope-guard`가 기계 차단한다. `add`/`commit`을 나누지 않는다 — 그 틈에 남의 스테이징이 얹힌다.
- **커밋 메시지는 스크래치패드에 파일로 쓰고 `-F`로 넘긴다**(여러 줄·따옴표를 셸에 맡기지 않는다).
- 성격이 다른 변경이 섞였으면 `git diff --stat` **전량**을 보고 **분리 커밋**한다.
- Code.js·contents_*.js 등 **Apps Script 코드를 고쳤으면 여기서 멈추고 `/deploy`를 먼저 돌린다** — 커밋만 하면 GitHub과 라이브가 어긋난다.
- 커밋 뒤 **`git log -1`로 내 것이 실제로 들어갔는지 확인한다.** 동시 세션이 있으면 커밋이 조용히 no-op이 될 수 있다(F071).
- 커밋·push 뒤 **`node tools/원격ci.js`** — 내 커밋이 원격에서 초록인지 본다. 결과(초록·적색·대기·미검증)를 **마지막 보고에** 그대로 적는다. **초록이 아닌 채 닫으면 그 상태를 다음 세션이 물려받는다**(F175: 웹훅이 끊겨 run 이 0건이면 화면에서 초록과 같은 모양이다).

### 3-b. 배포와 갈렸나 — 「종결」을 적기 **전에** 잰다
이 세션이 SYNK-talk 의 **Edge Function 소스**(`supabase/functions/**`)나 **동봉으로 나가는 것**(`lib/*.js`·`계약/*.json`)을 커밋했으면:
```bash
cd ../SYNK-talk && node tools/배포빚.js      # ← 먼저. 두 판(리허설·운영)을 «장부»로 · 네트워크 0
```
- 🔴 **두 판을 다 본다 — 「낡음 0」은 그 판 하나의 0이다.** 2026-08-17 실측(`local_1399fe5a` · 같은 순간·같은 트리): `배포대조.js` 를 **인자 없이** 돌리면 과녁이 `.env` 의 리허설로 잡혀 「다름 0 · 미측정 0 · 전체 16」 **완벽한 초록**이 나오는데, 그 순간 운영은 낡음 1 이었다. 한 판의 초록을 두 판의 초록으로 읽으면 그 「종결」이 거짓이 된다. 이제 그 도구가 **안 본 판을 스스로 지목**하니(`⚠ 이 실행이 안 본 판: …`) 그 줄까지 읽는다 — 초록은 분모와 함께만 읽는다(F207).
- 낡은 판이 **있을 때만** 그 판을 바이트로 실측한다(비싸다 — 네트워크 16회):
  ```bash
  node tools/배포대조.js                                   # 리허설
  SUPABASE_PROJECT_REF=<운영REF> node tools/배포대조.js     # 운영 — 읽기에 `--운영`(쓰기 승인 키)을 붙이지 않는다(F462)
  ```
- 종료코드 **0=같다 · 1=다르다(배포가 소스보다 낡았다) · 2=미측정**. 셋이 갈려 있으니 그대로 읽는다.
- ❔ **「모름」은 최신이 아니고, 그 안이 또 갈린다**(F579): 「안 쟀다」는 다시 재면 풀리지만 「**라이브에 없다**」(HTTP 404 · 배포된 적 없음)는 다시 재도 같다 — 후자의 처방은 대조가 아니라 **배포**다. 도구가 갈라서 낸다.
- **다르면 그건 「종결」이 아니다** — 철학 게이트 ④의 「닿았나」가 ✗다. 재배포하거나, 못 하면 **마지막 보고와 열린 PR 본문에 「⛔배포 0」을 그대로 적는다.** 적지 않으면 다음 세션이 그 낡은 판을 「방금 고친 것」으로 읽는다.
- **못 쟀으면(2) 「초록」이라 적지 않는다** — 「못 쟀다」로 적는다(미실행과 통과는 같은 모양이다).
- 배포가 막히면 **왜 막혔는지까지 적는다.** DB 판이 소스보다 뒤처지면 `원격배포` 가 스스로 거부한다 — 그건 함수가 아니라 **마이그레이션이 밀린 것**이고, `--적용` 은 유호님 명시 승인 자리다.

> **왜 이 자리인가** — 2026-08-12 실측(`local_57ec0a96`): 리허설 14종 중 **6종이 소스와 달랐고 2종은 아예 없었다.** 빠진 것이 전부 그날 「✅종결」로 적힌 것들이었다(`학습자상태.mjs` v7 · `꼬리.mjs` · `회고.mjs`). 장부는 종결인데 배관이 안 섰다 — F302 의 재발 경로다. 급소는 도구가 없던 게 아니다: **`배포대조.js` 는 그때도 있었고, 아무도 안 돌렸다.** 장치는 스스로 발화하지 않으면 안 돈다(CLAUDE.md 신뢰성) — 이 단계가 그 발화다.
>
> ⚠ **2026-08-17 갱신(#Q109)** — 그 발화가 **한 판만 재고 있었다.** 그 뒤 F455 로 장부 층(`배포빚.js`)이 생겨 두 판을 네트워크 없이 한 번에 내게 됐는데, **그것을 부르는 이 자리가 안 바뀌어** 분모가 낡은 채 남았다. 도구가 자라도 호출부가 안 따라가면 그 차이는 「초록」의 얼굴로 온다(CLAUDE.md 맹점 ④ = 맞는 얼굴로 틀린 값 · 이 저장소에서 장치가 새는 가장 잦은 방향이다). ⚠ 안 잰 것을 밝힌다: 그날 배포 없이 끝난 세션이 **이 구멍을 통과한 것인지는 못 쟀다**(3-b 를 돌렸다는 기록이 없다). 참으로 확인된 것은 「명령이 두 판 중 하나만 본다」 하나다.

### 3-c. 워크트리에서 일했으면 **열린 PR 을 닫는다**

이 세션이 `EnterWorktree` 로 워크트리를 떠서 일했으면(CLAUDE.md 세션 규약 「코드 트랙은 워크트리+PR」):

```bash
node tools/작업가지.js --닫기
```

- 이게 **머지까지** 한다(push → `--merge` → 원격 가지 거둠). 그 다음에 `ExitWorktree(remove)` 로 로컬을 정리한다.
- **미커밋이 있으면 도구가 거절한다** — 머지해도 그 바이트는 안 따라가기 때문이다. 그게 정확히 F403(워크트리 갇힘)이라, 여기서 막는 것이 맞다. 3단계로 돌아가 커밋한다.
- **트랙이 안 끝났으면 닫지 않는다.** 열린 PR 은 「진행 중」이라는 뜻이고, 다음 세션이 그것을 보고 이어받을지 비켜날지 정한다 — 그게 이 층의 존재 이유다. 대신 **PR 본문 첫 줄에 다음 할 일 1줄**을 적는다.

> **왜 이 자리인가** — 안 닫고 세션이 끝나면 PR 은 **영원히 열린 채** 남고, 하루가 지나면 SessionStart 훅이 그것을 적색으로 낸다(「주인 세션이 죽었을 수 있다」). 그 적색이 잦아지면 목록 전체가 무시당하고, 그러면 진짜 갇힌 작업이 있는 날에 아무도 안 본다. 열린 PR 목록의 값은 **거기 있는 것이 전부 진짜일 때만** 산다.

### 4. 트랙 선언 — PR 본문 하나가 진다

> **2026-08-20 위임 2단계** (유호 확정 「메인은 클로드 하네스」 · 원칙 = «엔진은 빌리고, 기록은 소유한다»).
> 여기엔 `docs/_ops/보드/<지문>.md` 를 열어 고치고 `board-move.js` 로 아카이브하는 절차가 있었다.
> 보드 층은 그 커밋으로 걷었다 — 08-19 철거로 board-guard 와 SessionStart 훅이 0 이 된 뒤
> 보드는 **아무것도 강제하지 않는 선언 파일**이었고, 실측 08-20 에 살아 있던 세션 3개 중
> 보드 줄을 가진 세션은 **0개**였다. 즉 기능 제거가 아니라 잔해 정리다.

- **코드 트랙**은 PR 이 선언이다(유호 확정 08-15 「PR = 작업 목록」). 안 끝났으면 PR 을 열어 둔 채
  **본문 첫 줄에 다음 할 일 1줄**을 적는다 — 다음 세션은 `gh pr list` 와 `list_sessions` 의 `prNumber` 로 그것을 본다.
- **단발 편집**(master 직발)은 선언할 자리가 없다 — 그게 맞다. 끝난 일은 **커밋 메시지가** 기록이고,
  안 끝난 일은 마지막 보고(아래 6단계)에 1줄로 남긴다.
- **남이 무엇을 잡고 있나**는 `list_sessions`(제목 · `isRunning` · `prNumber` · `prState`)로 본다 — 파일이 아니라 하네스가 안다.

### 5. 메모리 — 굵직한 판정만
이 세션에서 **유호님이 확정한 결정**, **재제안하면 안 되는 기각**, **방향을 바꾼 발견**이 있으면 메모리 파일에 쓰고 `MEMORY.md`에 한 줄 추가한다. 없으면 건너뛴다 — 대화에서만 의미 있는 것은 쓰지 않는다.

이미 있는 토픽이면 **새 파일을 만들지 말고 그 파일을 갱신**한다.

### 5-b. 답을 받았으면 **물어본 줄**을 닫는다
5단계는 **새 파일**을 쓰는 칸이고 이건 **옛 줄**을 닫는 칸이다 — 둘이 갈라져 있는 것이 F115(「왜 끝난 게 계속 떠」)의 나머지 절반이다.

이 세션에서 유호님 답을 받았거나 대기 하나가 끝났으면, 새 절에만 적지 말고 **그 `⏳` 줄을 제자리에서 `⏳`→`✅` 로 고친다.** 파일 순서는 시간순이 아니라 앞 절이 낡은 채 남고, 큐는 줄 하나만 보고 그걸 매일 「승인 대기」로 배달한다(F108 실사고).

이번에 만진 메모리 파일에서 살아 있는 `⏳` 를 눈으로 훑어(검사 훅은 압축 08-20으로 철거) **그중 이번에 끝난 것만** 닫는다. 아는 것은 답을 받은 이 세션뿐이다 — 다음 세션은 그 줄이 낡았다는 걸 알 방법이 없다.

- 🚫 자동 판별(나이 만료·키워드 겹침·「✅ 있으면 무시」)로 대체 재제안 금지 — memory `cleanup` 기각 3회. 여기가 **묻는 자리**인 이유가 그것이다.
- 옛 결정 큐는 08-20 소멸했다 — 유호님 답이 필요한 것은 큐가 아니라 **세션 끝 보고에 직접** 싣고, 정해지면 `docs/_ops/결정.md`에 `node tools/결정.js --추가`로 적는다.

### 5-c. 고쳐놓고 **장부를 안 닫은 행**이 없나
```bash
node tools/friction.js --이세션
```
종료코드 **0=겹치는 행 없음 · 1=판정할 행 있음 · 2=못 쟀다**(git 을 못 불렀다 — 0건이 아니다).

**1이면 그 행마다 셋 중 하나로 판정하고 넘어간다** — 「나중에」는 답이 아니다:
- **다 고쳤다** → 닫기 전 F083: 신고 원문의 결함을 되넣어 회귀가 빨개지는지 본다(`node tools/변이.js <계획>`). 통과하면 `node tools/friction.js resolve F0NN "무엇이 실제로 막았나"`.
- **안 고쳤지만 지금 안 닫기로 판정했다** → `node tools/friction.js defer F0NN "왜 지금 안 닫나"`
- **파일만 겹쳤지 내 일이 아니다** → 그냥 지나간다(이 통로는 알림이지 차단이 아니다).

> **왜 이 자리인가** — 2026-08-16 실측(F496): 열림 6건 중 **3건이 이미 고쳐진 것**이었고, 그중 둘은 **같은 세션이 같은 날 고치고 둘 다 안 닫았다**. `friction-close-guard` 는 커밋 시점에 한 번 알리고 끝이라 ①번호를 안 단 커밋에는 **원리상 눈이 멀고** ②번호를 달아 짖어도 그대로 세션이 끝나면 아무도 다시 안 본다. 그 훅 머리말이 스스로 「위험한 건 그 상태로 세션이 끝나는 것이다」라 적어 뒀는데 **끝나는 자리에 검사가 없었다.** 5-b 와 같은 병이다 — 신고(새 행)는 커밋마다 도는데 닫기(옛 행)가 아무 데도 안 걸려 있었다.
>
> ⚠ **이 통로가 못 보는 것**: 신고문이 파일을 하나도 안 적은 행은 원리상 안 걸린다 — 그래서 출력이 늘 **분모**를 함께 낸다(「안 지목한 N」). 그 N 이 크면 `--open` 으로 직접 본다.

### 5-d. 내가 만든 낡음이 없나 — 15초
```bash
node tools/rot-check.js
```
「수리 필요 N건」이 **세션 시작 때보다 늘었으면** 늘어난 것만 그 자리에서 걷는다(깨진 링크·낡은 인용 — 대부분 내가 지운 파일을 가리키는 채 남은 문서다). 기존분은 내 것이 아니다 — 세지 말고 넘어간다.

> **왜 이 자리인가** — 2026-08-20 실측: 낡음 탐지는 자동(rot-check)인데 **발화 자리가 0이었다**(부르던 afk·missed 스킬이 은퇴하면서). 그날 처음 읽었더니 깨진 링크 203건이 쌓여 있었다 — 전부 「파일을 지운 세션이 그 파일을 가리키던 문서를 안 고친」 잔해다. 지운 사람이 그 세션에 있을 때 걷는 것이 유일하게 싼 시점이고, 세션 끝이 그 마지막 기회다.

### 6. 인계는 **하네스가 진다** — 손 인계문을 만들지 않는다

> **2026-08-20 위임 1단계** (유호 확정 「메인은 클로드 하네스」 · 원칙 = «엔진은 빌리고, 기록은 소유한다»).
> 여기엔 `tools/인계문.js`·`tools/인계문수거.js` 를 부르는 두 줄이 있었다. 그 층을 걷은 이유는
> **이미 죽어 있었기 때문**이다 — 08-19 철거로 SessionStart 훅이 0개가 되면서 인계문은 아무 데도
> 자동 주입되지 않았고, 도구는 **아무도 안 읽는 파일만 쓰고** 있었다(실측 08-20).
> 그리고 그 자동 주입은 애초에 결함으로 지목됐다: 「유호님이 말하기 전에 다음 세션의 방향을
> 미리 정해버렸다」(철거 커밋 `e75fc7fc`).

**세션을 끊을 때 인계로 할 일은 이제 이것뿐이다:**

1. **제목을 지금 트랙에 맞춘다** — 다음 세션이 `list_sessions` 로 이 세션을 찾는 유일한 단서다.
   `set_session_title` 로 짧고 특정적인 이름을 단다(예: 「마스코트 정본 경로 수렴」).
2. **끝났다는 사실은 git 이 진다** — 4단계까지의 커밋과 PR 본문이 그 기록이다. 별도 인계문을 안 만든다.

**다음 세션은 «받는» 게 아니라 «찾는다».** 필요할 때 이렇게 연다:
- `list_sessions` — 지금 어떤 세션이 있고 무엇이 살아 있나(`isRunning`·`prNumber`·`prState`)
- `search_session_transcripts` — 「그 얘기 어느 세션에서 했지」를 본문으로 검색
- `send_message` — 특정 세션에 맥락을 직접 넘김

🔑 **왜 이게 나은가**: 옛 인계문은 세션 생사를 **파일 접촉으로 추정**했고 그게 F315 의 원인이었다
(긴 외부 프로세스를 도는 세션은 살아서도 박동이 식는다). 하네스의 `isRunning` 은 추정이 아니라 **안다**.

⚠ **대가 (숨기지 않는다)**: 하네스는 세션을 **전부 보지는 못한다** — 실측 08-20 에 `list_sessions` 가
3 개를 냈는데 그 셋 중 보드 줄을 가진 세션은 **하나도 없었다**(선언 층이 이미 안 돌고 있었다). 세션 기록은 저장소 밖
(`~/.claude/projects/…` · 2.8GB)에 살아 **git 으로 안 따라온다.** 그래서 **잃으면 안 되는 것은 여전히
git 이 쥔다** — 유호님 확정은 `docs/_ops/결정.md`, 판정 근거는 커밋 메시지, 트랙은 PR 본문이다.
인계문을 걷은 것은 「오늘 지나면 값이 0인 것」만 놓은 것이지 기록을 놓은 것이 아니다.

유호님께 마지막으로 보고한다:
- 커밋한 것 (해시 + 한 줄)
- 트랙 상태 (PR 을 닫았는지 · 열어 뒀으면 다음 할 일 1줄을 어디에 남겼는지)
- 메모리 저장 여부
- 남의 미커밋이 남아 있으면 그 사실
- **「이제 창을 닫고 새로 여세요(또는 `/clear`)」** — 붙여넣을 블록은 없다. 새 세션이 필요하면
  `list_sessions`·`search_session_transcripts` 로 직접 찾는다.

(자동 입력 훅(SessionStart/End)은 압축 08-20으로 철거됐다 — 위 블록을 손으로 붙이는 것이 유일한 바통이다.)

## 금지
- 미커밋을 남긴 채 "끊어도 된다"고 말하기 — 미추적 파일은 이력·stash·reflog 어디에도 없는 유일한 무보호 상태다(F025).
- 남의 미커밋 변경을 내 커밋에 쓸어담기.
- 끝난 트랙을 **말로만** 끝내기 — 커밋 메시지나 PR 본문에 안 남은 종결은 다음 세션에게 없는 일이다.
- **세션을 자동으로 끄려 시도하기** — 훅도 AI도 세션을 못 끈다(`continue:false`도 턴만 멈춘다). 마지막은 유호님이 창을 닫는다.

## 왜 컴팩트가 아니라 종료인가
실측(08-04 · 압축 전 세계)으로 컴팩트 도달점이 새 세션 시작점보다 컸고 요약 손실까지 붙었다. 압축(08-20)으로 상주분이 더 줄어 새 세션 시작점은 더 낮아졌다 — 이 저장소에서 컴팩트는 세션 재시작보다 열등하다.
