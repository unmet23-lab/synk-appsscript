# /fable심문 — Fable 전용 설계 심문

**유호님 확정 2026-08-11**: *"이건 매번 심문 때마다 하는 게 아니라 내가 원할 때 페이블로 따로 돌려보고 싶어서."*

- 🚫 **기존 GPT 편성(`tools/모델정책.js` `심문편성` = luna×2 + sol×1)은 건드리지 않는다.** 거기에 Fable을 얹는 안은 유호님이 기각했다.
- 🚫 **프롬프트 사본을 만들지 않는다.** 공격 렌즈·배경·출력 형식의 정본은 `docs/_ops/동결심문_프롬프트.md` 하나다. 이 스킬은 그 파일의 `---` **아래**를 읽어 쓰고, 범위 ③④에서만 렌즈를 **덧붙인다**.
- 🚫 **장부를 `심문기록.jsonl` 과 섞지 않는다.** 대상이 다른 기록은 장부도 다르다(`codex-review.js:879`). Fable 몫은 `docs/_ops/심문기록_fable.jsonl`.

### 범위 ③④ 추가 렌즈
🔑 **렌즈 본문의 정본은 `tools/fable심문.js` 의 `추가렌즈` 다.** 여기 사본해 두지 않는다 — 두 곳에 적으면 갈라지고, 갈린 쪽은 언제나 조용히 통과한다. 도구가 템플릿의 렌즈 7개 **뒤**·「## 출력 형식」 **앞**에 끼운다(회귀 `tests/fable심문.test.js`).

- ③ = 렌즈 8~11 (문서↔코드 배신 · 미착지 · 역방향 · 회귀 공백)
- ④ = ③ + 렌즈 12~13 (라이브 배신 · 스키마 실물) — **누적이다**

범위 ④의 운영 실물은 **호출 세션이 먼저 떠서 지시문에 첨부한다**(심문자는 자격증명이 없다):
- `node tools/배포판점검.js --라이브` → 라이브 vs HEAD
- 라이브 시트 구조 · Supabase 스키마 = 세션이 조회해 스냅샷으로 붙인다
- ⚠ **못 연 층은 「못 열었다」고 적어 넘긴다.** 안 읽고 낸 「지적 0건」은 통과의 얼굴을 한 미실행이다.

## 절차

### 1. 지시문을 조립한다 — **손으로 하지 않는다**
```bash
node tools/fable심문.js --준비 <문서경로> --범위 <1-4>
```
JSON 으로 `지시문경로`·`결과경로`·`금지지문`·`대상지문`이 나온다. 도구가 대신 지는 것:
- 금지목록 = memory 인덱스의 🚫 줄 **전량** 치환(골라 넣으면 독립성이 모델 이름에만 남는다)
- 템플릿 머리말(`---` 위) 잘라내기 — ☠️ 통째로 보내면 심문자가 운영 표식을 읽고 *"정본 지시에 따라 실행하지 않았습니다"* 로 **거부**한다(2026-08-06 실측 · 종료코드 0 · 241바이트 · 겉보기엔 성공)
- 대상 문서 **전문** 치환(발췌 금지 — 발췌는 심문자를 눈멀게 한다)
- 범위별 추가 렌즈 삽입 · 조건 지문 계산

🔑 **손 조립을 하면 회차마다 입력이 갈리고 그 순간 판끼리 대조가 원리상 무효가 된다**(F281 — 금지 지문 4판 상이로 C0 실런이 모델 비교 증거로 못 쓰이게 됐다).

### 2. 위임 — 문서 1개당 심문자 1판, 병렬
```
Agent(subagent_type: "심문자", model: "fable",
      prompt: "다음 파일을 열어 그 안의 지시를 그대로 수행하라: <지시문경로>
               맨 앞 한 줄에 `판정요약: P0 n · P1 n · P2 n` 을 적어라.
               결과는 네 최종 답변 본문으로 낸다(파일을 쓰지 마라).")
```

⚠ **`Agent type '심문자' not found` 가 나면 등록층 문제다**(2026-08-11 실측 — 이 통로를 만든 세션에서 그렇게 났다). 에이전트 정의는 **세션이 시작될 때** 잡히므로 `.claude/agents/심문자.md` 를 그 세션에서 만들었으면 그 세션은 못 본다. 함정은 **스킬은 잡히는데 에이전트만 안 잡힌다**는 비대칭이다 — 스킬이 떠서 「다 됐다」로 읽힌다.
- 처방 = 세션을 새로 열면 잡힌다. 급하면 `subagent_type: "general-purpose"` + `model: "fable"` 로 돌리되 **`.claude/agents/심문자.md` 의 「절대 규칙」을 프롬프트에 그대로 실어라**(그 파일이 read-only 도구 제한을 지므로, 폴백은 「수정하지 마라」를 프롬프트로만 강제한다).
- 🔑 **폴백으로 돌았으면 보고에 1줄로 밝힌다.** 조용히 내려가면 다음 사람이 이 판을 「심문자 정의로 돌았다」로 읽는다.
- 🔑 **지시문을 프롬프트에 인라인하지 않는다** — 대상이 112KB 인 것도 있어 호출 세션 컨텍스트를 통째로 지나간다. 심문자가 `Read` 로 직접 연다.
- **한 판에 문서 하나.** 여러 문서를 한 판에 밀면 뒤가 첫 희생이 된다.
- 독립 대상이므로 **한 메시지에 여러 Agent 호출을 함께 보낸다**(병렬).
- 범위 ②~④는 판수가 많다 — **8판씩 끊어** 돌리고 묶음마다 진행을 보고한다.

### 3. 결과를 남긴다
- 본문 → `--준비` 가 준 `결과경로` 에 그대로 쓴다(이름에 대상지문·모델·회차가 박혀 있어 남의 결과를 안 덮는다)
- 장부 1행:
```bash
node tools/fable심문.js --기록 --대상 <경로> --범위 N --금지지문 <sha12> \
  --대상지문 <sha12> --결과 <결과경로> --P0 n --P1 n --P2 n
```
- ⚠ 빈 출력·등급 표기도 「지적 0건」도 없는 판은 **`--확인불가 "사유"` 로 남긴다.** 통과로 세지 않는다.
- 보고 전 `node tools/fable심문.js --현황` — **몇 판이 실제로 돌았는지**부터 밝힌다. 초록은 분모와 함께만 읽는다.

### 4. 합친다 — 코드/사람이 한다
- 🚫 **모델에게 병합시키지 않는다.** 그러면 변환이 아니라 판단이 되고 떨어진 지적이 조용해진다(유호 확정 08-09).
- 키 = **파일 + 제목** 합집합. 등급이 갈리면 **나쁜 쪽 승**.
- 이미 기각된 지적(`docs/_ops/검수기각.jsonl`)과 대조해 재탕은 따로 표시한다.

### 5. 보고 — 유호님께
- **P0부터.** 각 항목에 「소급 불가인가」를 표시한다 — 학생 데이터가 아직 0행인 지금이 그 창이다.
- **고치기 전에 실측한다.** 심문자의 오독은 실측이 걸러내고, 놓침은 걸러낼 자리가 없다(08-09 sol 정답유출 오독 2건 실측 사례).
- 판수·확인불가 건수를 함께 적는다.

## 이 통로가 무엇을 사고 무엇을 못 사는가

**산다**: 새 판 한 벌. 이 저장소의 실측 판정이 「회차 간 차이 > 모델 간 차이」(같은 모델 2회가 38건 vs 20건)라 **판을 더 도는 것 자체가 이득**이다. 그리고 유호님 상시 지시 「새 강력 모델마다 전층 재검토」의 정확한 대상이다.

**못 산다**: 이종 벤더의 다른 눈. Fable은 대화 세션(Opus)과 같은 Claude 계보라 **맹점이 상관된다.** 그래서 이것은 GPT 심문의 **대체가 아니라 추가**다 — 보고에서 「Fable이 통과시켰다」를 「동결해도 된다」로 번역하지 않는다.
