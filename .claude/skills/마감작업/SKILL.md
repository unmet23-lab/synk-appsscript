# 마감작업 — 보이기 전 최종본 울트라 관문

광고 · 공모전 · 포트폴리오 편의 최종본이 나온 뒤(synk-video 7단계) 유호님께 보이기 전에 돈다. 제작 규칙 「검수」의 컷 전수 다섯(배역별 얼굴판 · 시작 그림 엔진 표 · 8장 띠 · 원본 대조 · 서로 답을 모르는 교차 검수)을 검수자 여럿이 나눠 맡고, 한 사람이 컷마다만 보다 놓친 「컷 사이」를 따로 본다(11-12 서울로 — 제 목록을 모르는 검수자 한 명이 전수를 보자 열 몇 가지가 더 나왔다). 2026-11-12 유호님 「둘 다 세팅」, [결정](../../../docs/_ops/결정.md).

만드는 손은 제작 세션(Opus) 하나다. 이 스킬은 보는 일만 한다 — 고칠 표를 넘기고, 고치기 · 다시 굽기는 제작 세션이 한다.

## 0. 이 세션이 맞나
- 세션 모델 id가 `claude-fable-5-2`가 아니면 아무것도 돌리지 않고 한 줄로 알린다: 「이 세션은 <모델>이라 관문을 돌리지 않았습니다 — 모델을 Fable 5.2로 바꾸고 다시 불러 주세요」. 워크플로 검수자는 세션 모델을 물려받으므로 이 세션의 모델이 곧 검수자 모델이다. 예외는 아래 Fable 한도 대체 하나다.
- **관문을 시작할 때마다** `mcp__ccd_session_mgmt__get_usage`로 주간 Fable 몫을 지금 값으로 잰다 — 앞 관문 때의 값이나 첫 글에 적힌 옛 근거를 다시 쓰지 않는다. **남은 몫이 10% 아래거나 한도 오류가 나면 초기화를 기다리거나 여쭙지 않고 Opus 5.5로 같은 관문을 돈다**(2026-11-13 · 11-14 유호님, [운영 원칙 「한도」](../../../docs/AI_운영원칙.md#quota-handoff)).
  - 이 세션이 Fable 5.2이고 남은 몫이 10% 아래거나 이번 관문에서 한도 오류가 났으면 워크플로를 돌리지 않고 제작 세션(첫 글의 id)에 「Fable 한도 — 근거 <지금 get_usage 값 · 잰 시각 · 오류 원문> — Opus 5.5로 바꿔 다시 맡겨 주세요」를 보내고 멈춘다(제작 세션이 `set_session_model claude-opus-5-5`로 바꾼다).
  - 이 세션이 Opus 5.5면 워크플로 args의 `한도대체: "<근거>"`에 **지금 근거가 있을 때만** 글을 넣어 돈다. 근거는 셋뿐이다 — ① 지금 잰 값이 10% 아래(값 · 잰 시각) ② 제작 세션이 이번 맡김 글에 적은, 이번 관문에서 Fable이 낸 한도 오류(오류 원문 · 난 시각 — 주간 몫이 10% 넘게 남았어도 근거다) ③ 대체 검수자가 낸 지적을 그 검수자가 확인하는 `다시`(「대체 검수자 수정 확인」 + 앞결과의 「Opus 5.5 대체 검수」 글 — 몫이 돌아와 있어도 이 `다시`는 Opus 5.5가 본다). 셋 다 아니면 넣지 않는다 — 그러면 워크플로가 Opus 답을 받지 않으니, 제작 세션에 「Fable 몫 회복 — claude-fable-5-2로 되돌려 주세요」를 보내고 멈춘다.
  - 결과 · 보고에는 실제로 Opus 5.5가 답한 판에만 「Opus 5.5 대체 검수 — 한도 근거」가 남는다.
- 다른 편의 울트라 관문이 도는 중이면 그것이 끝난 뒤에 돈다(한 번에 한 편).

## 1. 판 만들기
인자 `<편 폴더>`, 최종본(없으면 `<편>/최종.mp4`), 리메이크면 `--원본 <원본.mp4>`(컷표 detail에 `"원본": [시작초, 끝초]`가 있는 컷만 원본 대조 판이 생긴다). 출력 = `<편>/검수/마감_<YYYYMMDD-HHmm>`(`Get-Date -Format yyyyMMdd-HHmm`).

```
python -I -X utf8 tools/영상관문판.py <편>/컷표.json --관문 마감 --최종 <최종.mp4> [--원본 <원본.mp4>] --출력 <출력>/판
```

11컷 편이 3분쯤 걸렸다(11-12 실측) — 10분을 넘길 것 같으면 `run_in_background`로 돌리고 끝 알림을 기다린다.
- 끝 줄의 「컷연속성검사 걸림」이 1 이상이면 관문을 돌리지 않는다. 편집 단계(6) 검사 걸림이 남은 것이니 제작 세션이 먼저 고친다(Fable 몫을 쓰지 않는다) — `<출력>/판/연속성/결과.json`의 걸림 줄을 넘기고 끝.
- 「못함」(시각을 못 정한 컷 · 기준 그림 없음 등)은 그대로 잇되 보고에 남는다.

## 2. 관문 워크플로
```
Workflow({ scriptPath: ".claude/workflows/video-gate.js",
           args: { 관문: '마감', 편, 컷표, 최종, 출력, 판폴더: "<출력>/판", 한도대체? } })
```
경로는 모두 절대 경로다. 관점은 판목록이 정한다 — 컷 전수(컷마다 8장 띠 · 원본 판, 검수자 하나에 그림 30장 안쪽) · 컷 사이(장면별 가운데 장 판) · 얼굴(배역별 얼굴판) · 이야기와 끝(판만 보고 먼저 읽은 뒤 컷표와 견줌, 끝 3초 판) → P0 · P1만 반박(「아님」은 다른 검수자가 한 번 더, 두 번 「아님」이면 기각, 갈리면 확인) → 빠진 것 찾기 → 기록(`<출력>/결과.json` · `보고.md`).

## 3. 받은 뒤 — 이 세션이 직접 하는 것
- 반환 `모델확인.맞음`이 거짓이면 결과를 쓰지 않는다. 워크플로 기록 폴더(결과에 나온 journal.jsonl 자리)의 `agent-*.jsonl`에서 `"model":"claude-…"`를 세어 준비 · 기록(Sonnet) 말고는 모두 `claude-fable-5-2`인지 본다(한도대체로 돌았으면 `claude-opus-5-5`도 받는다).
- `기록맞음`이 거짓이면 반환의 `결과`로 결과.json · 보고.md를 직접 쓴다.
- **움직임은 검수자 눈에 맡기지 않았다.** 반환 `살펴볼움직임` 컷마다 `<출력>/판/움직임_<컷>.jpg`(1/8초 8장)를 직접 열고 숫자(`숫자.json`의 사람움직임)와 함께 굳음 · 살아 있음을 정해 보고.md에 적는다 — 굳었으면 「영상만」(11-07 Fable이 8장 띠를 받고도 멈춘 손을 두 번 놓쳤다).
- 상태 「확인」 지적은 근거 그림을 직접 열어 유지 · 기각을 정한다. 실제 사람 얼굴(승인 얼굴 세트 배역)은 정하지 않고 배역별 얼굴판을 유호님께 보인다.
- **교차 검수를 합친다.** 제작 세션이 돌린 카본 영상 심사(`<편>/검수/카본심사*.md` 가운데 최종본보다 새 것)와 카본 그림 맹검(`<편>/게시/미학맹검.json`)의 꼭 고칠 것을 보고.md 「교차 검수」에 옮긴다. 없거나 최종본보다 오래됐으면 「카본 심사 없음」으로 적고 「통과」라 쓰지 않는다.
- 결과.json · 보고.md는 편과 함께 올린다. 판/ · 메모/는 다시 만들 수 있어 .gitignore가 뺀다.

## 4. 넘기기
- 제작 세션(이 세션을 연 세션 — 첫 글에 id가 있다)에 SendMessage: 보고.md 경로 · 판정별 컷 수 · 고칠 컷과 고칠곳. 다시 굽기에 크레딧이 들면 제작 세션이 견적을 보이고 받는다.
- 유호님께는 한 단락: 판정별 컷 수, 유지한 P0 · P1, 유호님이 보실 것(배역별 얼굴판 · 실제 얼굴 「확인」 칸). 다섯(얼굴판 · 엔진 표 · 8장 띠 · 원본 대조 — 리메이크만 · 교차 검수) 가운데 못 한 것을 적고, 유지 0 · 확인 0 · 다섯을 다 한 뒤에만 「통과」라 쓴다.

## 5. 고친 뒤 — 다시
`/마감작업 다시 <편> <컷…>`: 판 도구에 `--컷 C3,C7`(고친 컷과 앞뒤 이웃만 판을 만든다), 워크플로 args에 `다시: true, 컷: ['C3', 'C7'], 앞결과: "<지난 출력>/결과.json"`. 지난 지적마다 고쳐짐 / 그대로를 보고 고치며 생긴 새 문제만 반박한다(운영 원칙 「재검수와 배포 후보」 — 이야기 · 빠진 것은 돌지 않는다). 다시 렌더한 최종본이면 카본 심사도 제작 세션이 바뀐 자리만 다시 받는다.

## 제작 세션이 하는 일
synk-video 3단계 끝(굽기 전)과 7단계(마감)에서 제작 세션(Opus)이 한다.
1. 컷연속성검사 걸림 0을 먼저 본다(굽기 전 `--그림지시문 · --그림 · --지시문`, 마감 `--영상`).
2. 마감이면 소리를 켜고 처음부터 끝까지 본 뒤, 카본 영상 심사(슬롭 점검표 「심사 지시문」 그대로)와 `node tools/미학맹검.js --영상 …`을 먼저 돌리고 카본 답을 `<편>/검수/카본심사_<YYYYMMDD-HHmm>.md`에 둔다.
3. 검수 세션을 연다: `start_session`(fresh) → 받은 id로 `set_session_model` `claude-fable-5-2` · `set_session_effort` `xhigh`. **세션을 열 때와 다음 관문 · 다시 검수를 맡길 때마다 제작 세션이 먼저 `get_usage`를 잰다** — 주간 Fable 몫이 10% 아래면 그 세션을 `claude-opus-5-5`로 두고 맡기는 글에 지금 잰 근거(값 · 잰 시각)를 적으며, 몫이 돌아와 있으면 새 관문부터 `claude-fable-5-2`로 되돌린다(운영 원칙 「한도」). 대체 검수자가 낸 지적을 확인하는 `다시`는 몫이 돌아와도 `claude-opus-5-5` 그대로 맡긴다. Fable 검수 세션이 한도 오류로 답도 알림도 못 하고 멈춰 있으면 기다리지 않고 제작 세션이 그 세션의 오류와 사용량을 확인해 같은 전환을 하고, 맡기는 글에 그 오류 원문 · 난 시각을 적는다(주간 몫이 10% 넘게 남았어도 이번 관문의 한도 오류면 대체 근거다). 첫 글은 「모델이 claude-fable-5-2(한도 대체면 claude-opus-5-5)가 아니면 「기다림」 한 줄만 답한다. 유호님이 /마감작업(또는 /굽기전검수) <편 절대 경로>를 치시면 시작한다. 제작 세션 id: <id>」. 편마다 검수 세션 하나를 두고 두 관문과 다시 검수를 모두 거기서 한다.
4. 유호님께 그 세션 링크와 칠 한 줄을 드린다 — 울트라는 유호님 말로만 켜져서 이 한 줄은 대신 칠 수 없다.
5. 고칠 표가 오면 고치고(다시 굽기에 크레딧이 들면 견적부터), 고친 컷을 넣은 「다시」 한 줄을 다시 부탁드린다.

## 쓰지 않는 곳
매일 SNS 편 · 짧은 시험 판은 지금처럼 자체검수와 카본 맹검으로 간다. 울트라 관문은 Fable 몫을 한 번에 많이 쓴다(50컷 한 편에 검수자 7~9, 어림 200만~300만 토큰).
