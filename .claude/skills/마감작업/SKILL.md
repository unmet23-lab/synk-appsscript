# 마감작업 — 보이기 전 최종본 울트라 관문

광고 · 공모전 · 포트폴리오 편의 최종본이 나온 뒤(synk-video 7단계) 유호님께 보이기 전에 돈다. 제작 규칙 「검수」의 컷 전수 다섯(배역별 얼굴판 · 시작 그림 엔진 표 · 8장 띠 · 원본 대조 · 서로 답을 모르는 교차 검수)을 검수자 여럿이 나눠 맡고, 한 사람이 컷마다만 보다 놓친 「컷 사이」를 따로 본다(11-12 서울로 — 제 목록을 모르는 검수자 한 명이 전수를 보자 열 몇 가지가 더 나왔다). 2026-11-12 유호님 「둘 다 세팅」, [결정](../../../docs/_ops/결정.md).

만드는 손은 제작 세션(Opus) 하나다. 이 스킬은 보는 일만 한다 — 고칠 표를 넘기고, 고치기 · 다시 굽기는 제작 세션이 한다.

## 0. 이 세션이 맞나
- 세션 모델 id가 `claude-fable-5-2`가 아니면 아무것도 돌리지 않고 한 줄로 알린다: 「이 세션은 <모델>이라 관문을 돌리지 않았습니다 — 모델을 Fable 5.2로 바꾸고 다시 불러 주세요」. 워크플로 검수자는 세션 모델을 물려받으므로 이 세션의 모델이 곧 검수자 모델이다. 예외는 아래 Fable 한도 대체 하나다.
- **관문을 시작할 때마다** `mcp__ccd_session_mgmt__get_usage`로 주간 Fable 몫을 지금 값으로 잰다 — 앞 관문 때의 값이나 첫 글에 적힌 옛 근거를 다시 쓰지 않는다. **남은 몫이 10% 아래거나 한도 오류가 나면 초기화를 기다리거나 여쭙지 않고 Opus 5.5로 같은 관문을 돈다**(2026-11-13 · 11-14 유호님, [운영 원칙 「한도」](../../../docs/AI_운영원칙.md#quota-handoff)).
  - 이 세션이 Fable 5.2이고 남은 몫이 10% 아래거나 이번 관문에서 한도 오류가 났으면 워크플로를 돌리지 않고 제작 세션(첫 글의 id)에 「Fable 한도 — 근거 <지금 get_usage 값 · 잰 시각 · 오류 원문> — Opus 5.5로 바꿔 다시 맡겨 주세요」를 보내고 멈춘다(제작 세션이 `set_session_model claude-opus-5-5`로 바꾼다).
  - 이 세션이 Opus 5.5면 워크플로 args의 `한도대체: "<근거>"`에 **지금 근거가 있을 때만** 글을 넣어 돈다. 근거는 셋뿐이다 — ① 지금 잰 값이 10% 아래(값 · 잰 시각) ② 제작 세션이 이번 맡김 글에 적은, 이번 관문에서 Fable이 낸 한도 오류(오류 원문 · 난 시각 — 주간 몫이 10% 넘게 남았어도 근거다) ③ 대체 검수자가 낸 지적을 그 검수자가 확인하는 `다시`(「대체 검수자 수정 확인」 + 앞결과의 「Opus 5.5 대체 검수」 글 — 몫이 돌아와 있어도 이 `다시`는 Opus 5.5가 본다). 셋 다 아니면 넣지 않는다 — 그러면 워크플로가 Opus 답을 받지 않으니, 제작 세션에 「Fable 몫 회복 — claude-fable-5-2로 되돌려 주세요」를 보내고 멈춘다.
  - 결과 · 보고에는 실제로 Opus 5.5가 답한 판에만 「Opus 5.5 대체 검수 — 한도 근거」가 남는다.
- 다른 편의 울트라 관문이 도는 중이면 그것이 끝난 뒤에 돈다(한 번에 한 편).

## 1. 판 만들기
인자 `<편 폴더>`, 최종본(없으면 `<편>/최종.mp4`), 리메이크면 `--원본 <원본.mp4>`(컷표 detail에 `"원본": [시작초, 끝초]`가 있는 컷만 원본 대조 판이 생긴다). 출력 = `<편>/검수/마감_<YYYYMMDD-HHmm>`(`Get-Date -Format yyyyMMdd-HHmm`).

```
python -I -X utf8 tools/영상관문판.py <편>/컷표.json --관문 마감 --최종 <최종.mp4> [--원본 <원본.mp4>] --출력 <출력>/판
```

한 회차에서 마감 판은 한 번 만든다. 11컷 편에서는 약 3분이 걸렸다(11-12 실측). 오래 걸리는 경우 다른 준비를 진행하면서 완료를 기다린다.
- 끝 줄의 「컷연속성검사 걸림」이 1 이상이면 관문을 돌리지 않는다. 편집 단계(6) 검사 걸림이 남은 것이니 제작 세션이 먼저 고친다(Fable 몫을 쓰지 않는다) — `<출력>/판/연속성/결과.json`의 걸림 줄을 넘기고 끝.
- 「못함」(시각을 못 정한 컷 · 기준 그림 없음 등)은 그대로 잇되 보고에 남는다.
- 세 편 시험 또는 해당 편에 별도 요청이 있으면 출력한 판목록 경로를 제작 세션에 전달한다. 독립 검수자는 카본의 답을 보기 전에 같은 판으로 자신의 검수를 진행한다.

## 2. 관문 워크플로
```
Workflow({ scriptPath: ".claude/workflows/video-gate.js",
           args: { 관문: '마감', 편, 컷표, 최종, 출력, 판폴더: "<출력>/판", 한도대체? } })
```
경로는 모두 절대 경로다. 관점은 판목록이 정한다 — 컷 전수(컷마다 8장 띠 · 원본 판, 검수자 하나에 그림 30장 안쪽) · 컷 사이(장면별 가운데 장 판) · 얼굴(배역별 얼굴판) · 이야기와 끝(판만 보고 먼저 읽은 뒤 컷표와 견줌, 끝 3초 판) → P0 · P1만 반박(「아님」은 다른 검수자가 한 번 더, 두 번 「아님」이면 기각, 갈리면 확인) → 빠진 것 찾기 → 기록(`<출력>/결과.json` · `보고.md`).

## 3. 받은 뒤 — 이 세션이 직접 하는 것
- 반환 `모델확인.맞음`이 거짓이면 결과를 쓰지 않는다. 워크플로 기록 폴더(결과에 나온 journal.jsonl 자리)의 `agent-*.jsonl`에서 `"model":"claude-…"`를 세어 준비 · 기록(Sonnet) 말고는 모두 `claude-fable-5-2`인지 본다(한도대체로 돌았으면 `claude-opus-5-5`도 받는다).
- `기록맞음`이 거짓이면 반환의 `결과`로 결과.json · 보고.md를 직접 쓴다.
- **움직임은 검수자 눈에 맡기지 않았다.** 반환 `살펴볼움직임` 컷마다 `<출력>/판/움직임_<컷>.jpg`(1/8초 8장)를 직접 열고 숫자(`숫자.json`의 사람움직임)와 함께 굳음 · 살아 있음을 정해 보고.md에 적는다 — 굳었으면 「영상만」(11-07 Fable이 8장 띠를 받고도 멈춘 손을 두 번 놓쳤다).
- **컷 안 탈것 · 배경 움직임도 같다.** `숫자.json` 컷 줄의 「최종본」에 흐름갈림 · 멈췄다감 · 제자리바퀴가 있으면 `<출력>/판/흐름_<컷>.jpg`(시간띠 — 곧은 세로 줄은 멈춤, 기운 줄은 움직임)를 열고 최종 영상의 그 초를 직접 틀어 본다. 흠이면 「영상만」, 아니면 까닭을 보고.md에 적는다(11-15 서울로 시험에서 카본과 Fable 관문이 움직임 흠 여섯을 하나도 못 봤다).
- 상태 「확인」 지적은 근거 그림을 직접 열어 유지 · 기각을 정한다. 실제 사람 얼굴(승인 얼굴 세트 배역)은 정하지 않고 배역별 얼굴판을 유호님께 보인다.
- **교차 검수.** 제작 세션이 이번 회차에 남긴 카본 원문과 맞음·틀림 판정, 카본 그림 맹검(`<편>/게시/미학맹검.json`)을 각 검수자의 독립 판단이 끝난 뒤 대조한다. 지난 편의 기록은 `<편>/검수/카본판_*/카본/`에 있다(11-16 전에는 `<편>/검수/카본심사*.md`). 이번 판에서 확인한 흠과 미확인 범위를 마감 보고에 적는다. 의뢰한 검수가 빠졌으면 그 항목은 미확인이다.
- 결과.json · 보고.md는 편과 함께 올린다. 판/ · 메모/는 다시 만들 수 있어 .gitignore가 뺀다.

## 4. 넘기기
- 제작 세션(이 세션을 연 세션 — 첫 글에 id가 있다)에 SendMessage: 보고.md 경로 · 판정별 컷 수 · 고칠 컷과 고칠곳. 다시 굽기에 크레딧이 들면 제작 세션이 견적을 보이고 받는다.
- 유호님께는 한 단락: 판정별 컷 수, 유지한 P0 · P1, 유호님이 보실 것(배역별 얼굴판 · 실제 얼굴 「확인」 칸). 다섯(얼굴판 · 엔진 표 · 8장 띠 · 원본 대조 — 리메이크만 · 교차 검수)과 2026-11-18에 더한 둘 — 최상급 대조(`python -I -X utf8 tools/최상급대조.py 보기 <편> --최종 <최종.mp4>` 끝 코드 0 = 이 최종본으로 서로 답을 모르는 눈 둘이 모두 「꼴찌 아님 · 우리만 AI로 꼽히지 않음」) · 회상 셋(낯선이시험 1 · 12 · 13 — 시험관 둘이 모두 브랜드 이름을 대고 「이야기에 붙음」, 한 문장이 컷표 「한문장」과 같은 뜻) — 가운데 못 한 것을 적고, 유지 0 · 확인 0 · 모두 한 뒤에만 「통과」라 쓴다. 최상급 대조에서 못 넘으면 눈들이 적은 「가장 모자란 것」(답 4번)을 고칠 것 후보로 함께 보인다.

## 5. 고친 뒤 — 다시
`/마감작업 다시 <편> <컷…>`: 판 도구에 `--컷 C3,C7`(고친 컷과 앞뒤 이웃만 판을 만든다), 워크플로 args에 `다시: true, 컷: ['C3', 'C7'], 앞결과: "<지난 출력>/결과.json"`. 지난 지적마다 고쳐짐 / 그대로를 보고 고치며 생긴 새 문제만 반박한다(운영 원칙 「재검수와 배포 후보」 — 이야기 · 빠진 것은 돌지 않는다). 다시 렌더한 최종본이면 카본 심사도 제작 세션이 바뀐 자리만 다시 받는다. 다시 검수의 표에서는 「지난 F12」(지난 관문의 지적)와 「F12」(이번에 새로 나온 지적)가 서로 다른 지적이고, 컷 판정에는 지난 P0 · P1 「그대로」만 들어간다. 표 읽는 법과 워크플로 뒤의 대조(`node tools/영상관문대조.js <출력>/결과.json`)는 [굽기전검수 스킬 5절](../굽기전검수/SKILL.md#5-고친-뒤--다시)과 같다.

## 제작 세션이 하는 일
synk-video 3단계 끝(굽기 전)과 7단계(마감)에서 제작 세션(Opus)이 한다.
1. 컷연속성검사 걸림 0을 먼저 본다(굽기 전 `--그림지시문 · --그림 · --지시문`, 마감 `--영상`).
2. 검수 세션을 연다: `start_session`(fresh) → 받은 id로 `set_session_model` `claude-fable-5-2` · `set_session_effort` `xhigh`. **세션을 열 때와 다음 관문 · 다시 검수를 맡길 때마다 제작 세션이 먼저 `get_usage`를 잰다** — 주간 Fable 몫이 10% 아래면 그 세션을 `claude-opus-5-5`로 두고 맡기는 글에 지금 잰 근거(값 · 잰 시각)를 적으며, 몫이 돌아와 있으면 새 관문부터 `claude-fable-5-2`로 되돌린다(운영 원칙 「한도」). 대체 검수자가 낸 지적을 확인하는 `다시`는 몫이 돌아와도 `claude-opus-5-5` 그대로 맡긴다. Fable 검수 세션이 한도 오류로 답도 알림도 못 하고 멈춰 있으면 기다리지 않고 제작 세션이 그 세션의 오류와 사용량을 확인해 같은 전환을 하고, 맡기는 글에 그 오류 원문 · 난 시각을 적는다(주간 몫이 10% 넘게 남았어도 이번 관문의 한도 오류면 대체 근거다). 첫 글은 「모델이 claude-fable-5-2(한도 대체면 claude-opus-5-5)가 아니면 「기다림」 한 줄만 답한다. 제작 세션이 /마감작업(또는 /굽기전검수) <편 절대 경로> 한 줄을 넘기면 유호님의 부름으로 받아 시작한다. 제작 세션 id: <id>」. 편마다 검수 세션 하나를 두고 두 관문과 다시 검수를 모두 거기서 한다.
3. 그 세션에 관문 한 줄(「/마감작업 <편 절대 경로> <최종.mp4>」 또는 「/굽기전검수 <편 절대 경로>」)을 `SendMessage`로 넘기고, 같은 글에 이 일을 맡긴 유호님 말씀과 [결정 표](../../../docs/_ops/결정.md) 2026-11-17 「울트라 관문 한 줄」 행을 적는다. 유호님께 치시라고 하지 않는다(유호님 11-17 「니가 그냥 전달하면 되는거잔항」). 유호님께는 넘겼다는 것과 세션 링크만 알린다. 검수 세션의 도구 규칙이 그래도 막을 때만 유호님께 한 번 여쭙는다.
4. 마감이면 제작자가 소리를 켜고 최종본을 끝까지 보고 `node tools/미학맹검.js --영상 …`을 진행한다. 카본 판 심사는 [세 편 시험](../../../docs/마케팅/PULSE_AI모델_캐스팅_20260930/검수방식_시험_완성영상_카본과Fable_20261115.md#next-three) 또는 이 편에 따로 요청받은 경우에 진행한다. 같은 최종본으로 두 가지를 더 받는다(2026-11-18 유호님 「최상급과 겨룰만한지 검수도 추가하자」 · 「브랜드 회상 … 고정 질문 셋으로 넣자」).
   - **최상급 대조:** `python -I -X utf8 tools/최상급대조.py 판 <편> --우리 <최종.mp4>`(기준 광고는 컷표 「최상급」의 「파일」 — 없으면 받기 전에 파일 이름 · 출처 · 크기를 유호님께 여쭙고 저장소 밖에 둔다). 회차 폴더의 `카본작업.json`을 `node tools/아르곤웹.js 보내기 … --여러줄`로 카본에게, 같은 `질문.md` · `판_*.jpg`만 이 대화 맥락이 없는 하위 에이전트 하나에게 준다(정답.json은 주지 않는다). 답마다 `적기 <회차> --누가 <눈> --답 <답.md>`.
   - **회상 셋:** `node tools/낯선이시험.js <최종.mp4> --말 <말> --브랜드 pulse|공모전`의 질문을 시험관 둘(서로 답을 모르게)에게 주고 1 · 12 · 13번을 컷표와 견준다.

   - 마감 세션이 보낸 **이번 회차 전체 판**의 경로로 `node tools/카본판심사.js <편> --판 <이번 판 폴더> --최종 <현재 최종.mp4> --미리보기`를 실행한다. 도구가 확인한 작업 파일을 그대로 쓴다. 파일이 바뀌었다는 안내가 나오면 현재 자료로 판을 다시 만든다.
   - 이 편에서 이미 의뢰한 묶음인지 기존 대화·보낸 기록과 대조한다. 신규 의뢰는 해당 편의 제작 세션 한 곳에서만 `node tools/아르곤웹.js 보내기 <작업 파일…> --여러줄`로 진행한다. 이후 답이 늦거나 발송 여부가 모호하면 기존 대화를 찾고 `node tools/아르곤웹.js 읽기 <기존 작업 파일…> --여러줄`만 사용한다. 기다리는 동안 독립 검수를 이어간다.
   - 제작자가 응답 원문에서 자막과 그림, 컷 사이 연결, 인물 혼동, 컷표와 다른 점을 확인한다. 정지 판에서 볼 수 없었던 것도 따로 적는다. 답 일부만 왔으면 남은 항목은 미확인이다. 지적마다 실제 최종 프레임을 보고 맞음·틀림과 이유를 `<이번 마감 출력>/카본판정.md`에 추가한다. 원문은 보존한다. 세 편 시험에서는 첫 마감의 주요 지적, 재검 횟수와 제출 뒤 유호님이 짚은 문제까지 비교표에 적는다.
5. 고칠 표가 오면 고치고(다시 굽기에 크레딧이 들면 견적부터), 고친 컷을 넣은 「다시」 한 줄을 같은 방법으로 검수 세션에 넘긴다.

## 쓰지 않는 곳
매일 SNS 편과 판 둘 이하의 첫 시험은 지금처럼 자체검수와 카본 맹검으로 간다. 광고 · 공모전 · 포트폴리오 편이 판 셋 이상을 낼 때는 「시험 묶음」이어도 굽기 전 검수를 거친다 — 내기 도구가 그 컷을 검수가 「그대로」로 봤는지 보고 막는다(11-18 7번 「사랑 한 칸」: 「짧은 시험 판」이라며 건너뛰고 21판 1,892크레딧을 낸 뒤 컷 사이 순간이동으로 다 버렸다). 울트라 관문은 Fable 몫을 한 번에 많이 쓴다(50컷 한 편에 검수자 7~9, 어림 200만~300만 토큰).
