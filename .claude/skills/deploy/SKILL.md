# /deploy — SYNK 배포 파이프라인

목적: **GitHub(백업)과 Google Apps Script(라이브)가 어긋나는 사고 방지.** 구문 깨진 코드가 라이브에 올라가는 것 차단.

## 도구 경로 (PATH에 없음 — 전체 경로 사용)
- node: `"/c/Program Files/nodejs/node.exe"` (Bash) / `& "C:\Program Files\nodejs\node.exe"` (PowerShell)
- clasp: `"/c/Users/q1212/AppData/Roaming/npm/clasp.cmd"`
- 작업 디렉토리: `C:\Users\q1212\Documents\SYNK-appsscript`

## 절차 (순서 엄수 — 하나라도 실패하면 다음 단계 진행 금지)

1. **오염 확인**: `git status --short` — 내 작업이 아닌 변경(다른 세션 흔적)이 섞여 있으면 멈추고 유호님께 보고. `list_sessions` 로 지금 도는 세션(`isRunning`)이 같은 파일을 잡고 있으면 조율 먼저.
2. **구문 검사**: 저장소 루트의 모든 `.js` 파일에 `node --check` 실행. **하나라도 실패 → 배포 중단**, 원인 수정 먼저.
   ```bash
   for f in *.js; do "/c/Program Files/nodejs/node.exe" --check "$f" || exit 1; done
   ```
   이어서 **안전 불변식 테스트**를 돌린다 — 구문은 멀쩡해도 실데이터를 지키는 불변식(야간작업 순서·브리핑 큐 보존·아카이브 8열·리포트 PNG 첨부 등)을 깨는 변경을 라이브 반영 전에 잡는다.
   ```bash
   "/c/Program Files/nodejs/node.exe" tools/test-ci.js
   ```
   **`fail` 0이 아니면 배포 중단**(`todo`는 미구현 후속 과제 표시라 무시). 정상 리팩터로 마커 문자열이 바뀌어 실패하면 테스트를 함께 갱신하고 재실행한다.
   > **적색이라고 곧바로 접지 않는다 — 층을 먼저 가른다(F240 축 B).** 나갈 바이트는 작업본이 아니라 **HEAD** 다(5단계가 배포집합을 커밋시키고 6단계가 push 한다). `node tools/원격ci.js` 가 **초록**이면 그 적색은 정의상 **커밋 안 된 작업**이라 라이브와 무관하다 — 계속 진행하고, 보고에 「로컬 작업본 적색 N건(배포집합 밖) · HEAD 는 원격 초록」이라고 층을 밝힌다. clasp-guard 도 같은 판정으로 통과시킨다(우회가 아니라 재는 대상을 바로잡은 것). 원격이 적색·미검증이면 그건 진짜 중단 사유다. 이 저장소는 세션이 10개 넘게 도는 시간대가 있어 「저장소 전체 초록」은 상시 조건이 아니라 가끔 열리는 창이고, 규칙을 지키는 쪽이 밀려 라이브가 조용히 뒤처졌다(08-08 하루 세 번 · 하나는 소급 불가 칸).
   > `node --test tests/*.test.js`가 아니라 **`tools/test-ci.js`를 쓴다.** 같은 스위트를 **빈 HOME·TZ=UTC**로 돌려 CI를 모사한다 — 로컬 머신에는 CI에 없는 것(로컬 시간대·홈의 메모리 정본·자격증명)이 있어서 **로컬 초록이 CI 초록을 뜻하지 않는다.** 2026-08-04에 두 세션이 각각 이 함정을 밟았고(F036·F039), 한 번은 **빨간 CI 위에서 라이브 배포가 나갔다** — clasp-guard는 로컬 스위트만 보므로 이 층은 게이트가 아니라 여기서 잡아야 한다. 급할 때 평소 러너로 돌렸다면 **보고에 "로컬 기준"이라고 층을 밝힌다.**
3. **appsscript.json 검증**: `node -e "JSON.parse(require('fs').readFileSync('appsscript.json','utf8'))"` — 임시 webapp 설정 등 검증 잔재가 남아있지 않은지 눈으로도 확인.
4. **보안 검토** — **반드시 커밋 전에.** `/security-review`는 *미커밋 변경분*을 읽으므로 커밋한 뒤엔 볼 것이 없다.
   ```bash
   node tools/deploy-security-check.js
   ```
   기계 검사 3종: ①소스에 박힌 고정 인증 토큰 ②`doGet` 안의 파괴적 연산 ③임시 배포 잔존. **exit 1이면 배포 중단.**
   이어서 **판단 층 검토**. 기계 검사는 아는 패턴만 보고, `/security-review`는 처음 보는 결함을 본다 — 둘은 대체재가 아니다.
   ```bash
   node tools/보안검토과녁.js            # ㉠ 과녁을 명시로 뽑는다 (미커밋 ∪ 커밋됐지만 미배포)
   ```
   출력된 목록을 **그대로 붙여** 채팅에 **`/security-review`** 를 부른다 — 변경분을 읽어 주입·권한 경계·PII 노출을 검토한다. **HIGH가 나오면 배포 중단.**
   받은 보고서를 스크래치패드에 저장하고 대조한다:
   ```bash
   node tools/보안검토과녁.js --대조 <보고서 경로>   # ㉡ 0 돌았다 · 2 못 쟀다 · 3 미실행
   ```
   **종료 3이면 「취약점 0건」이 아니라 미실행이다** — 배포 보고에 「보안 검토 통과」라고 적지 않는다. 2도 통과가 아니다.
   > 🔴 왜 과녁이 **두 갈래**인가 (F449 → #Q82 · 2026-08-15): 옛 과녁은 `배포집합 ∩ 미커밋` 뿐이라, **고쳐서 커밋해 두고 배포 전에 끊긴** 배포에서 0건이 나오고도 「라이브에 새로 내보낼 바이트가 없다」고 **단언**했다 — 재지 않은 축에 대한 주장이라 거짓이고, 그대로 「검토 대상 없음 = 통과」로 기록된다. 커밋과 배포 사이가 끊기는 것은 상시 동선이라(F444·F447·컨텍스트 인계) **끊긴 뒤 이어받은 세션에게는 과녁이 언제나 0건으로 보였다.** 지금은 `미커밋 ∪ 커밋됐지만 미배포` 이고 출력이 **분모를 쪼개 낸다**(`0건 = 미커밋 0 + 안 나간 변경 0`) — 합계만 읽지 말고 갈래를 본다. ⚠ ㉡ 은 간접 증거다(F244): 「마지막 채번보다 저장소가 앞섰다」까지만 보고 「그 채번이 라이브에 닿았나」는 못 잰다 — **여기서 재지 마라**(같은 판정을 두 곳에 적으면 갈라진다). 기준선(`Code.js` 의 `SYNK_VERSION` 줄)이 없으면 0건이 아니라 **종료 2**다.
   > 🔴 왜 과녁을 명시로 주나 (F306 · 2026-08-10 실측): `/security-review` 가 **내 변경이 아니라 옆 세션의 문서를 읽고** 판정하려 했다. 내 배포 대상은 `Code.js`·`엔진_두뇌.js`·`상담AI.js` 의 미커밋 3줄이었는데 스킬이 넘긴 DIFF CONTENT 엔 그 셋이 **한 줄도 없었고**, 대신 `local_ed0a2064` 가 방금 커밋한 마크다운 5벌이 들어 있었다. 그 통로는 「origin 보다 앞선 커밋」을 대상으로 잡는데 내 앞선 트랙은 이미 push 됐고 그 사이 남이 3커밋을 얹어 **「내 앞선 커밋 = 남의 것」**이 됐다 — 정작 내 대상은 unstaged 라 본문 밖. `git status` 절엔 내 파일이 보이므로 **겉보기엔 정상 실행**이다. 세션이 10개 도는 시간대엔 우연이 아니라 상시 조건이라 브랜치 추론에 안 맡긴다.
   > 2026-08-02 이 단계가 없어서 생긴 일: 임시 doGet 러너가 고정 토큰 하나로 익명 공개 엔드포인트(ANYONE_ANONYMOUS·소유자 권한 실행)를 열고 GET 한 번에 `deleteRow`를 돌렸는데, **구문검사·안전 테스트는 전부 초록이었다.** 재는 층이 달랐다.

4-B. **①배포 검수 (GPT/Codex) — 3단 파이프라인(유호님 설계 2026-08-05).** **커밋 전에.** 대상이 미커밋 변경이라 커밋한 뒤엔 볼 것이 달라진다.
   > 🔑 GPT 역할은 셋이고 이게 **①번**이다(08-06 이름 분리) — ②설계 심문(✅켜짐 · `--심문 <문서>` · luna/high ×2)·③물리 작성과 **다른 일**이다. 지도 = `docs/AI_스택_가이드.md` §1-2.
   ```bash
   node tools/codex-review.js --제안      # ① 설계 선파악 — 기능지도 + 업그레이드 제안(방향 정본을 먹는다)
   node tools/codex-review.js --제안판정 <키> --채택        # ② 제안마다 판정: 채택이면 구현 후 ③으로
   node tools/codex-review.js --제안판정 <키> --기각 --사유 "왜"   #    기각이면 원래 방향 그대로 ③으로
   node tools/codex-review.js            # ③ 최종 검수 = 버그 사냥 + 기능 전수 체크
   ```
   > ⚠ **대상 diff 에 배포 파일이 0건이면 도구가 돌기 전에 멈추고 과녁(`--commit <sha>`)을 준다** — 그대로 따른다.
   > 태워도 배포 게이트가 안 열리는 대상이기 때문이다(F314 · 08-10 실측 22분). 배포와 무관한 코드 검수면 `--범위밖`.
   ② 판정 규칙: 크기 **소·중** = 클로드가 SYNK 축(자동화·데이터 수집·방향 정본)으로 판정하고 장부에 남긴다 ·
   크기 **대** 또는 방향을 바꾸는 제안 = 유호님께 선택지로 올린다. 제안·미판정은 **배포를 막지 않는다**(F103 방지).
   픽 전환 `--검수 sol`(**기본 luna** — 유호님 확정 08-05 "sol 쓰니까 너무 비싸다" · 둘 다 `high` · 정본=`tools/모델정책.js`) · 유호님 「빠르게」 = ① 생략+`--버그만`+`--회차 1`.
   > ⏱ **판단 패스는 기본 2회 돈다**(유호님 확정 08-15 「심문 검수 모두 luna high x2」 · 합집합). 그래서 ③ 이 옛날보다 **약 2배** 걸린다 — 콘솔이 `회차별 지적: 1회 N건 · 2회 M건 → 합집합 K건` 으로 값했는지 보여준다. 급하면 `--회차 1`.
   ChatGPT 구독 로그인으로 돌아 **추가 비용 0**, 읽기 전용 샌드박스(쓰기 차단은 2026-08-05 실측), 패스당 xhigh 실측 5~8분(max 는 더 걸릴 수 있다).
   종료 코드: **0**=차단급 0건 / **1**=P0·P1 지적 있음 / **2**=**확인 불가**(codex 없음·로그인 만료·타임아웃).
   **2를 0으로 읽지 말 것** — 안 돈 것이지 통과가 아니다.
   > 왜 이 단계가 있나: 같은 벤더끼리는 **블라인드스팟이 상관된다.** 내가 내 코드를 리뷰하면 내가
   > 못 보는 것은 리뷰에서도 안 보인다. 2026-08-05 실측이 두 번 증명했다 — ①내가 **변이 테스트로
   > 내 회귀의 구멍을 찾아 고친** 커밋에서 Codex가 테스트 격리 결함을 하나 더 찾았다 ②이 검수 도구
   > 자신을 이 도구로 검수하자 첫 지적이 **지문 결속 P1**이었다(검수 안 된 바이트가 「검수됨」으로

   지적을 받으면 **고치거나 기각하거나** 둘 중 하나로 끝낸다(그대로 두면 배포가 막힌다):
   ```bash
   node tools/codex-review.js --기각 <키> --사유 "왜 틀렸는지"
   ```
   기각 이력은 `docs/_ops/검수기각.jsonl`에 쌓여 다음 회차에 같은 지적을 **내 앞에서 걸러낸다** —
   검수가 상시 세금이 아니라 감가하는 비용이 되게 하는 장치다. 사유 없는 기각은 도구가 거부한다.

5. **버전 채번 → 커밋**
   - Code.js·contents_*.js를 고쳤으면 **번호를 직접 고르지 말고 채번기를 쓴다**:
     ```bash
     node tools/bump-version.js --desc "한 줄 요약" --종류 수리
     ```
     `--종류`는 시스템 대장 게이트라 없으면 채번이 거부된다 — 수리(버그·오류)=`--종류 수리` · 보강(기존에 살 붙임)=`--종류 보강 --시스템 "대장의 그 이름"` · 신설(새 시스템)=`--종류 신설 --시스템 "이름" --한줄 "대외 한 줄" --구역 "접수·상담"`.
     origin/master·로컬 브랜치 전부·예약 태그를 훑어 다음 번호를 정하고, **그 번호를 태그로 origin에 push해 원자적으로 예약**한 뒤 `SYNK_VERSION`에 기입한다. 두 세션이 같은 순간에 돌려도 한쪽만 성공한다(2026-08-01 하루 6회 동시 발번의 근본 대책 — 사람이 고르는 한 충돌은 반복된다). 조회만 하려면 `--dry`.
   - **짜는 동안 헤더에 버전을 박지 않는다 — `[vNEXT]`라고 적는다.** 채번기가 같은 실행에서 엔진 파일 전체의 `[vNEXT]`를 확정 번호로 바꾼다. 진짜 번호를 먼저 박으면 채번까지의 사이에 CI가 빨개지고(safety `[v9.55]`) **그 적색이 남의 배포 게이트까지 막는다**(2026-08-04 하루 두 번). `--desc` 없이는 채번 자체가 거부된다(상수만 오르는 상태가 곧 적색이라).
   - 커밋 직전 **`node tools/bump-version.js --check`** — 상수·엔진 태그 일치와 `[vNEXT]` 잔존 0을 확인한다. exit 1이면 커밋하지 않는다. (잊어도 pre-commit 의 `tools/자리표검사.js` 가 **커밋될 blob** 에서 자리표를 막는다 — F450. 하지만 `--check` 는 이력·상수 다리까지 보므로 여전히 먼저 돈다.)
   - 그 다음 `git diff --stat`으로 내 작업만 들어있는지 확인하고 커밋. 메시지 형식: `[v9.xx] 제목 — 요약`(채번기가 알려준 번호 그대로) + `Co-Authored-By: Claude <모델명> <noreply@anthropic.com>`.
   - `docs/버전_이력.md` 맨 아래에 같은 번호로 한 줄 추가.
6. **GitHub 백업**: `git push origin master`.
7. **라이브 배포**: `clasp push --force`.
   - ⚠ **push 는 라이브를 바꾸지 않는 프로젝트가 있다.** 웹앱이 **고정 버전 배포**를 서빙하면 push 는 프로젝트 파일만 갱신하고 접수 URL 은 옛 스냅샷을 계속 준다. 2026-08-05 실사고: 브랜드 키트 수리를 push 하고 「라이브 반영」이라 말할 뻔했는데, crewcard `@16` 이 v9.186 시점 카드를 그대로 서빙하고 있었다. (루트 프로젝트는 `@HEAD` 서빙이라 push 가 곧 라이브다 — **프로젝트마다 다르다**.)
   - 그래서 push 뒤 **`node tools/배포판점검.js --라이브`** 로 확인한다. **`--라이브` 를 뺀 판은 라이브를 읽지 않는다** — 고정 배포가 없는 프로젝트(@HEAD)에서 「안 쟀다」를 초록으로 내고 끝난다. 그리고 이 갈래만 **도장을 남긴다**(유호 승인 08-15 「배포한 자가 그 자리에서 찍는다」 · #Q97): 안 찍으면 다음 세션의 「배포집합이 마지막 배포보다 앞서 있다」가 **라이브=HEAD 인 날에도 계속 뜬다**(F482 실측 — 그러면 진짜 밀린 날에 그 문장이 이미 무시당하고 있다). 출력 끝의 `🖈 도장 n/m` 이 몇 개를 남겼는지 말한다. 낡았으면 그 도구가 **명령을 통째로** 준다:
     ```bash
     cd <프로젝트> && clasp deploy --deploymentId <기존ID> --description "<설명> #fp:<지문>"
     ```
     **⛔ `--deploymentId` 를 빼면 새 배포가 생겨 접수 주소가 둘로 갈린다**(메모리 `crewcard-fork-handoff` 의 실사고). 실행 후 `clasp deployments` 로 **개수가 그대로**인지 본다.
   - `#fp:` 는 배포된 내용의 지문이다. `clasp` 이 배포 시각을 안 주기 때문에(실측) 설명에 심어 라이브가 스스로 「어느 코드인지」 말하게 한 것 — 지우지 말 것.
8. **보고**: 커밋 해시 + "GitHub·라이브 동기화 완료"를 1줄로. 트리거가 코드를 쓰는 시각(07시 morning, 14/22시 calc, 월 07시 weekly)을 감안해 첫 실전 작동 시점을 알려줄 것.

## 금지
- 구문 검사 없이 clasp push 단독 실행 금지.
- 커밋 없이 clasp push 금지 (라이브와 git 이력 어긋남).
- 다른 세션의 미커밋 변경을 내 커밋에 쓸어담기 금지.

## 기계 게이트 (clasp-guard 훅 — 2026-07-20 도입)
Claude Code 세션에서는 위 순서를 어긴 `clasp push`/`clasp deploy`를 `.claude/hooks/clasp-guard.js`(PreToolUse 훅)가 **자동 차단**한다 — 루트 .js 구문·`tests/*.test.js`·배포 파일 미커밋·GitHub 미push·**배포 표면**(4단계 기계 검사와 같은 모듈) 5가지 불변식을 실시간 검사. 차단 사유가 뜨면 우회하려 들지 말고 사유를 해소한 뒤 재시도한다. 훅 수정 시 회귀 점검: `node tests/clasp-guard.check.js`.

> **테스트 불변식이 재는 것은 HEAD 다**(F240 축 B · 08-08). 원격 CI 가 이 HEAD 를 초록으로 통과시켰으면 게이트는 로컬 스위트를 **안 돌리고** 그 사실을 알림으로 밝힌다 — 배포집합 미커밋 0·origin push 완료를 같은 훅이 강제하므로 나갈 바이트는 이미 검증된 것이고, 작업본에 남은 적색은 커밋 안 된 남의 작업이다. 못 재면(gh 없음·run 0건·원격 적색) 오늘까지처럼 작업본 전체를 돈다. 곁들여 실측: 작업본 전량 실행은 **5분 20초**로 훅 타임아웃 120초를 2.7배 넘겼다 — 원격초록 경로는 몇 초다.

즉 4단계를 건너뛰어도 `clasp push`에서 다시 막힌다 — **절차를 기억하는 책임이 사람에게 없다.** 4단계는 "일찍 알기 위해" 있는 것이지 유일한 방어선이 아니다.

### ①배포 검수 게이트 (4-B의 기계 층 — 2026-08-05 도입 · 옛 이름 「이종 검수」)
같은 훅이 **배포 내용 지문**(`배포판점검.지문()`과 같은 것)으로 검수 기록을 대조한다. 셋으로 갈린다:

| 상태 | 훅 | 왜 |
|---|---|---|
| 차단급(P0·P1) 미해결 | **차단** | 지적을 받고도 안 고치고 배포하는 것 — 처방이 둘 다 실행 가능하다(고치기·기각) |
| 검수 기록 없음 | 알림 | **자격증명이 없는 환경은 늘 있다**(CI 러너·새 기계·키 만료 직후). 「검수 없으면 차단」으로 짜면 그 환경이 통째로 죽는다 — 따를 수 없는 처방은 우회를 정상 통로로 만든다(F103) |
| 이 프로젝트가 검수 범위 밖 | 알림 | 「모름」과 「정상」이 같은 모양이면 안 된다 |

파일이 한 바이트라도 바뀌면 지문이 바뀌어 **옛 검수 기록은 자동으로 무효**가 된다 — 고친 뒤 다시 돌리면 된다.

## 라이브 함수 검증이 필요할 때 (선택)
`clasp run`은 GCP 불일치로 불가. 검증된 우회법(임시 토큰 doGet 러너 → create-deployment → HTTP 호출 → **러너 제거 + delete-deployment + 404 확인**)은 메모리 `synk-tooling-paths` 참조. 러너를 남긴 채 종료 금지. 이 절차의 push는 임시 코드가 미커밋이라 게이트에 걸린다 — 명령 앞에 `CLASP_GUARD_BYPASS=1`을 붙여 의식적으로 우회한다(이 절차 외 우회 금지). 이 우회는 4단계 보안 검토까지 함께 건너뛴다는 뜻이므로, 러너 자체의 안전은 아래 3가지를 손으로 지킨다.

- **토큰을 소스에 박지 않는다.** `PropertiesService.getScriptProperties()`에서 읽는다 — 쿼리스트링 토큰은 Stackdriver 로그·브라우저 히스토리·붙여넣은 채팅에 전부 남고 만료가 없다.
- **파괴적 연산은 `doGet`에 넣지 않는다.** GET은 링크 미리보기 봇·prefetch가 임의로 부른다 — URL을 채팅에 붙여넣는 것만으로 실행된다. 공격자가 필요 없다.
- **코드를 지워도 라이브는 안 닫힌다.** versioned 배포는 그 시점 코드를 영구 고정해 계속 서빙하므로, 원복 push 뒤에도 그 URL은 살아서 러너를 그대로 응답한다. **`clasp undeploy <배포ID>` + URL 404 확인까지 해야 끝난다.** 2026-08-02 실측: 러너 4개(@28~@31)가 이렇게 살아남았다.

정리를 잊어도 다음 `clasp push`에서 배포 표면 검사가 잡는다(설명에 `temp`·`임시`·`runner`가 들어간 배포를 찾는다) — **그러니 임시 배포 이름에 `temp-`를 붙인다.** 이름이 감시의 손잡이다.
