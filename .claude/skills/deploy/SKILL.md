# /deploy — SYNK 배포 파이프라인

> 2026-09-02 현행화 — 판정 규칙은 전량 보존, 실측 서사는 걷었다(전문 = git 이력). 도구 플래그·가드 동작은 09-02 에 실물(`tools/*.js`·`.claude/hooks/clasp-guard.js`)과 대조했다.

목적: **GitHub(백업)과 Apps Script(라이브)의 어긋남 방지** + 구문 깨진 코드의 라이브 반입 차단.

## 도구 경로 (PATH에 없음 — 전체 경로)
- node: `"/c/Program Files/nodejs/node.exe"` (Bash) / `& "C:\Program Files\nodejs\node.exe"` (PowerShell)
- clasp: `"/c/Users/q1212/AppData/Roaming/npm/clasp.cmd"` · 작업 디렉토리: **지금 이 저장소**(`$CLAUDE_PROJECT_DIR`)
  🔴 절대경로를 박지 않는다 — 워크트리 세션이 그 지시를 따르면 2·3·4단계가 **남의 트리 바이트**를 재고 그 초록으로 자기 코드를 민다. 배포 자체는 **메인 트리에서만** 한다(clasp-guard 0번이 워크트리 배포를 막는다). 워크트리에서 지었으면 master 로 합친 뒤 메인 트리에서 이 절차를 돈다.

## 절차 (순서 엄수 — 하나라도 실패하면 다음 단계 금지)

1. **오염 확인**: `git status` **전문**(`--short` 금지 — rebase·merge 진행 중을 감춘다 · /close 1단계와 같은 규칙). 내 작업이 아닌 변경(다른 세션 흔적)이 섞여 있으면 멈추고 유호님께 보고. 지금 도는 세션은 `ListAgents` 로 본다 — 같은 파일을 잡고 있으면 `SendMessage` 로 조율 먼저(`list_sessions` 는 제목·PR 번호를 찾을 때).

2. **구문 검사 + 안전 테스트**:
   ```bash
   for f in *.js; do "/c/Program Files/nodejs/node.exe" --check "$f" || exit 1; done
   "/c/Program Files/nodejs/node.exe" tools/test-ci.js
   ```
   - `node --test`가 아니라 **test-ci.js** — 같은 스위트를 빈 HOME·TZ=UTC로 돌려 CI를 모사한다. **로컬 초록 ≠ CI 초록.** 급해서 평소 러너로 돌렸으면 보고에 「로컬 기준」이라 층을 밝힌다.
   - **`fail` 0이 아니면 중단**(`todo`는 무시). 정상 리팩터로 마커가 바뀐 실패면 테스트를 함께 갱신 후 재실행.
   - **적색이면 층부터 가른다**: 나갈 바이트는 작업본이 아니라 **HEAD**다. `node tools/원격ci.js`가 **초록**이면 그 적색은 커밋 안 된 작업이라 라이브와 무관 — 진행하되 보고에 「로컬 작업본 적색 N건(배포집합 밖) · HEAD는 원격 초록」이라 밝힌다. clasp-guard도 같은 판정으로 통과시킨다. 원격이 적색·미검증이면 진짜 중단 사유다. (세션 여럿이 도는 시간대에 「저장소 전체 초록」은 상시 조건이 아니다 — 규칙을 지키는 쪽이 밀리면 라이브가 조용히 뒤처진다.)

3. **appsscript.json 검증**: `node -e "JSON.parse(require('fs').readFileSync('appsscript.json','utf8'))"` — 임시 webapp 설정 등 잔재가 없는지 눈으로도 확인.

4. **보안 검토 — 반드시 커밋 전에** (`/security-review`는 *미커밋 변경분*을 읽는다):
   ```bash
   node tools/deploy-security-check.js      # 기계 3종: 고정 토큰·doGet 파괴 연산·임시 배포 잔존 — exit 1 중단
   node tools/보안검토과녁.js               # 과녁 명시로 추출 (미커밋 ∪ 커밋됐지만 미배포)
   ```
   출력 목록을 **그대로 붙여** `/security-review`를 부른다 — **HIGH가 나오면 중단.** 보고서를 스크래치패드에 저장하고 대조:
   ```bash
   node tools/보안검토과녁.js --대조 <보고서 경로>   # 종료 0=돌았다 · 2=못 쟀다 · 3=미실행
   ```
   **종료 3은 「취약점 0건」이 아니라 미실행**이다 — 「보안 검토 통과」라 적지 않는다. 2도 통과가 아니다. 기준선(`Code.js` 의 `SYNK_VERSION` 줄)이 없으면 0건이 아니라 종료 2.
   - 기계 검사와 `/security-review`는 대체재가 아니다 — 기계는 아는 패턴만, 판단 층은 처음 보는 결함을 본다(익명 공개 + GET 한 번에 deleteRow 하던 임시 doGet 러너가 구문·테스트 전부 초록으로 통과한 적이 있다).
   - 과녁이 **두 갈래**(미커밋 ∪ 미배포)인 이유: 커밋과 배포 사이에 끊긴 세션에게 「미커밋만」은 언제나 0건이다. 출력은 분모를 쪼개 낸다(`0건 = 미커밋 0 + 안 나간 변경 0`) — 합계가 아니라 갈래를 읽는다. ⚠ 대조는 간접 증거다 — 「라이브에 닿았나」는 7단계 배포판점검이 잰다.
   - 과녁을 **명시로** 주는 이유: 세션이 여럿 돌면 「origin보다 앞선 커밋 = 남의 것」이 상시 조건이라, 브랜치 추론에 맡기면 남의 파일을 검토하고 내 것을 빠뜨린다 — 겉보기엔 정상 실행이라 더 위험하다.

4-B. **①배포 검수 (GPT/Codex)** — **커밋 전에.** GPT 역할 넷 중 ①번이다(②설계 심문 `--심문 <문서>` · ③기술 실행자 `tools/codex-build.js` · ④발주 검토 — 지도 = `docs/AI_스택_가이드.md` §1-2). 🔑 **코드를 보는 자리는 코덱스가 기본이다**(유호 확정 09-04 「코드 리뷰는 gpt 에게」 — 클로드 쪽 `/code-review` 는 기본 통로에서 뺐다). 실행자 레인(codex-build)이 워크트리에서 이미 검수를 돌렸어도 **배포 게이트 도장은 여기서 다시 찍는다**(그 검수는 워크트리 기준이라 배포 지문이 안 붙는다 · 대가는 코덱스 한 번 더 · 5~8분).
   ```bash
   node tools/codex-review.js --제안                              # ① 기능지도 + 업그레이드 제안
   node tools/codex-review.js --제안판정 <키> --채택               # ② 채택 → 구현 후 ③
   node tools/codex-review.js --제안판정 <키> --기각 --사유 "왜"    #    기각 → 원래 방향대로 ③
   node tools/codex-review.js                                     # ③ 최종 검수 = 버그 사냥 + 기능 전수
   ```
   - 대상 diff에 배포 파일이 0건이면 도구가 멈추고 과녁(`--commit <sha>`)을 준다 — 그대로 따른다. 배포와 무관한 검수면 `--범위밖`.
   - ② 판정: 크기 **소·중** = 클로드가 SYNK 축으로 판정하고 장부에 남긴다 · **대**·방향 전환 = 유호님께 선택지로. 제안·미판정은 **배포를 막지 않는다.**
   - 픽: **값은 여기 안 적는다** — 모델·효력·회차의 정본은 `tools/모델정책.js` 하나다(`검수기본`·`검수선택지`). 이 문서에 값을 박았다가 정본이 세 번 바뀌는 동안(08-31 luna → 09-04 sol → 09-05 astra) 옛 값이 남아 있었다(09-05 실측). 그날만 넓게 `--회차 2` · 전환 `--검수 <선택지 키>` · 유호님 「빠르게」 = ① 생략 + `--버그만`. 구독 로그인이라 추가 비용 0 · 읽기 전용 샌드박스 · 가장 빠른 조합도 5~8분.
   - 종료: **0**=차단급 없음 · **1**=P0·P1 있음 · **2**=확인 불가(codex 없음·로그인 만료·타임아웃). **2를 0으로 읽지 않는다.**
   - 왜 있나: 같은 벤더끼리는 블라인드스팟이 상관된다 — 내 자기검증을 통과한 결함을 Codex가 잡은 실측이 있다.
   - 지적은 **고치거나 기각하거나**로 끝낸다(방치하면 배포가 막힌다): `--기각 <키> --사유 "왜"`. 기각은 `docs/_ops/검수기각.jsonl`에 쌓여 다음 회차에 같은 지적을 걸러낸다 — 사유 없는 기각은 도구가 거부.

4-C. **전체 눈 검수 (`/code-review ultra`) — 판정만 하고 넘어간다.** 🔴 **내가 못 돌린다**(사용자 트리거·과금). 유호님이 직접 치셔야 한다.
   4-B(codex = **다른 벤더의 눈**)와 축이 다르다 — 이쪽은 클라우드에서 에이전트 여럿이 나눠 훑고 **서로 반박해** 걸러낸다. 대체가 아니라 겹쳐 쓰는 것이다.
   **이번 배포가 아래 넷 중 하나에 걸리면** 커밋 전에 유호님께 한 줄로 여쭙는다. **걸리지 않으면 묻지 않는다** — 매번 물으면 소음이 되어 곧 무시당한다.
   - ㉠ **세션 여럿이 만든 것이 합류했다** — 워크트리 둘 이상이 master 로 들어온 뒤. 각 세션은 제 조각만 알아서 「A 의 고침이 B 가 기댄 것을 무너뜨렸나」를 **구조적으로 못 본다.**
   - ㉡ **소급 불가한 것을 처음 박는다** — 학생 ID 체계 · DB 스키마 · 발음으로 「무엇을 말하게 하느냐」. 학생이 온 뒤엔 못 고치므로 **개원 전이 유일한 창**이다.
   - ㉢ **굽기나 앱 빌드가 램을 물고 있다** — 품질이 아니라 **기계** 이유다(16GB 온보드가 유일 병목). 검토를 남의 기계로 밀어내 로컬을 비운다.
   - ㉣ **엔진 파일 여럿**이 바뀌었거나 **학생이 바로 보는 화면**이 바뀐다.
   🚫 걸지 않는 자리: 문서·콘텐츠만 바뀐 배포 · **CI 가 빨간 상태**(빨간 위에 얹으면 진짜 문제가 노이즈에 묻힌다 — 초록부터 만든다) · 급한 핫픽스(클라우드 왕복이 붙는다).
   📏 **대상은 «`origin/master` 대비 diff»다** — 인자 없이 치면 그것만 본다. 그래서 **master 위에서 push 까지 끝난 상태면 항상 「No changes to review」로 빈다.** 그때는 베이스를 명시한다: `/code-review ultra <가지>` 또는 `/code-review ultra HEAD~N`. ⇒ 🔑 **㉠(합류) 자리에서는 «합치기 전»에 걸어야 값이 난다.**
   ⏳ **비용은 아직 안 쟀다** — 일반 `/code-review` 보다 한 번에 훨씬 많이 쓴다(별도 결제가 아니라 구독 사용량)까지가 아는 전부다. **첫 실행 때 유호님께 `/usage` 를 전후로 봐 두시라 하고, 잰 값으로 이 줄을 갈아라.**
   ✅ **이 절은 배포를 막지 않는다**(4-B 와 같은 규칙). 유호님이 「그냥 가」 하시면 그대로 5단계로 넘어가고, 보고에 「ultra 미실행」이라 층을 밝힌다.

5. **버전 채번 → 커밋**
   - Code.js·엔진_*.js·contents_*.js를 고쳤으면 번호를 직접 고르지 말고 채번기:
     ```bash
     node tools/bump-version.js --desc "한 줄 요약" --종류 수리
     ```
     `--종류`는 시스템 대장 게이트(없으면 거부) — 수리 / 보강(`--시스템 "이름"`) / 신설(`--시스템 --한줄 --구역`). 태그를 origin에 push해 **원자 예약**하므로 두 세션이 동시에 돌려도 한쪽만 성공한다. 조회만 = `--dry`.
   - **짜는 동안 헤더는 `[vNEXT]`** — 채번기가 같은 실행에서 확정 번호로 바꾼다. 진짜 번호를 먼저 박으면 채번 전까지 CI가 빨개져 **남의 배포 게이트까지 막는다**.
   - 커밋 직전 `node tools/bump-version.js --check` — 상수·태그 일치와 `[vNEXT]` 잔존 0 확인. exit 1이면 커밋 금지. (잊어도 pre-commit 의 `tools/자리표검사.js --cached` 가 커밋 blob에서 막는다 — 그래도 `--check`가 이력·상수 다리까지 보므로 먼저 돈다.)
   - `git diff --stat`으로 내 작업만인지 확인 후 **경로를 못박아** 커밋(`git commit -m "..." -- 경로들` · `add -A`·`commit -a` 금지). 메시지: `[v9.xx] 제목 — 요약` + `Co-Authored-By: Claude <모델명> <noreply@anthropic.com>`.
   - `docs/버전_이력.md` 맨 아래에 같은 번호로 한 줄.

6. **GitHub 백업**: `git push origin HEAD:master`.
   🔴 `push origin master` 로 적지 않는다 — 워크트리에서는 로컬 `master` 가 안 움직여 **"Everything up-to-date"** 로 조용히 통과한다(백업이 안 된 채 초록). `HEAD:master` 는 지금 가지를 민다. push 가 0줄로 즉사하면 schannel 회귀다(메모리 `git-push-silent-death-tls13-fix`).

7. **라이브 배포**: `clasp push --force`.
   - ⚠ **push가 라이브를 안 바꾸는 프로젝트가 있다** — 고정 버전 배포를 서빙하면 push는 프로젝트 파일만 갱신한다(crewcard 가 `@16` 옛 스냅샷을 계속 서빙한 실사고). 루트는 `@HEAD`라 push가 곧 라이브 — **프로젝트마다 다르다.**
   - 그래서 push 뒤 **`node tools/배포판점검.js --라이브`**. `--라이브`를 빼면 라이브를 안 읽고 「안 쟀다」를 초록으로 낸다. 이 갈래만 **도장을 남긴다**(유호 승인 「배포한 자가 그 자리에서 찍는다」) — 안 찍으면 「배포집합이 앞서 있다」 경보가 라이브=HEAD인 날에도 계속 떠서 진짜 밀린 날에 무시당한다. 출력 끝 `🖈 도장 n/m` 확인.
   - 낡았으면 도구가 주는 명령 그대로: `clasp deploy --deploymentId <기존ID> --description "<설명> #fp:<지문>"`. **⛔ `--deploymentId`를 빼면 새 배포가 생겨 접수 주소가 둘로 갈린다.** 실행 후 `clasp deployments`로 개수 불변 확인.
   - `#fp:`는 배포 내용의 지문이다(clasp이 배포 시각을 안 줘서 라이브가 스스로 「어느 코드인지」 말하게 한 것) — 지우지 말 것.

8. **보고**: 커밋 해시 + 「GitHub·라이브 동기화 완료」 1줄. 쓰기 트리거 시각(`morningJobs` 07시 · `calcAllJob` 14시 · `nightJobs` 22시 · `weeklyJobs` 월 07시 — 함수·시각 정본 = `엔진_셋업확장.js` 의 트리거 매니페스트, 실설치 상태 = Apps Script 트리거 화면)을 감안해 첫 실전 작동 시점을 알려줄 것.

## 금지
- 구문 검사 없이 clasp push 단독 실행.
- 커밋 없이 clasp push (라이브와 git 이력 어긋남).
- 다른 세션의 미커밋 변경을 내 커밋에 쓸어담기.
- `clasp pull` — 읽기처럼 생겼지만 작업본을 라이브로 덮어쓴다(가드가 막는다).

## 기계 게이트 (clasp-guard 훅)
절차를 어긴 `clasp push`/`clasp deploy`는 `.claude/hooks/clasp-guard.js`(PreToolUse)가 자동 차단한다 — 워크트리 배포·루트 구문·테스트·배포 파일 미커밋·GitHub 미push·배포 표면을 실시간 검사. **차단 사유가 뜨면 우회하지 말고 해소 후 재시도.** 4단계는 「일찍 알기 위해」 있는 것이지 유일한 방어선이 아니다. 훅 수정 시 회귀 = `node tests/clasp-guard.check.js`.
- **원격 초록 경로**: 원격 CI가 이 HEAD를 통과시켰으면 게이트가 로컬 스위트를 생략하고 그 사실을 알린다(로컬 전량은 훅 타임아웃을 넘긴다 — 원격 경로는 몇 초).
- **BYPASS로 끌 수 없는 것이 있다**: 기계 보안 검사(고정 토큰·doGet 파괴 연산·임시 배포)는 BYPASS 판정보다 **앞**에서 돈다. `clasp pull`도 차단된다 — 라이브 편집을 정말로 회수하는 절차에만 가드가 주는 안내대로 BYPASS를 쓴다.

### ①배포 검수 게이트 (4-B의 기계 층)
같은 훅이 **배포 내용 지문**으로 검수 기록(`docs/_ops/검수기록.jsonl`)을 대조한다:

| 상태 | 훅 | 왜 |
|---|---|---|
| 차단급(P0·P1) 미해결 | **차단** | 처방이 둘 다 실행 가능하다(고치기·기각) |
| 검수 기록 없음 | 알림 | 자격증명 없는 환경은 늘 있다 — 따를 수 없는 처방은 우회를 정상 통로로 만든다 |
| 검수 범위 밖 프로젝트 | 알림 | 「모름」과 「정상」이 같은 모양이면 안 된다 |

파일이 한 바이트라도 바뀌면 지문이 바뀌어 옛 검수 기록은 자동 무효 — 고친 뒤 다시 돌린다.

## 라이브 함수 검증이 필요할 때 (선택)
`clasp run`은 GCP 불일치로 불가. 검증된 우회법(임시 토큰 doGet 러너 → create-deployment → HTTP 호출 → **러너 제거 + delete-deployment + 404 확인**)은 메모리 `synk-tooling-paths`. 러너를 남긴 채 종료 금지. 이 절차의 push는 임시 코드가 미커밋이라 게이트에 걸린다 — `CLASP_GUARD_BYPASS=1`로 **의식적으로** 우회한다(이 절차 외 우회 금지). ⚠ 우회가 건너뛰는 것은 **판단 층**(4단계 `/security-review`)이다 — 기계 보안 검사 3종은 BYPASS 앞이라 그대로 돈다. 러너 안전 3수칙은 손으로 지킨다:
- **토큰을 소스에 박지 않는다** — `PropertiesService.getScriptProperties()`에서 읽는다(쿼리스트링 토큰은 로그·히스토리·채팅에 남고 만료가 없다).
- **파괴적 연산은 `doGet`에 넣지 않는다** — GET은 미리보기 봇·prefetch가 임의로 부른다. 공격자가 필요 없다.
- **코드를 지워도 라이브는 안 닫힌다** — versioned 배포는 그 시점 코드를 영구 서빙한다. **`clasp undeploy <배포ID>` + URL 404 확인까지가 끝이다.**

정리를 잊어도 다음 push의 배포 표면 검사가 잡는다(설명에 `temp`·`tmp`·`임시`·`runner`·`러너`가 든 배포를 찾는다) — **그러니 임시 배포 이름에 `temp-`를 붙인다.** 이름이 감시의 손잡이다.
