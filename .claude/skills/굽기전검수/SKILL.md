# 굽기 전 검수 — 영상 크레딧을 쓰기 직전의 울트라 관문

광고 · 공모전 · 포트폴리오 편의 시작 그림이 다 나온 뒤, 영상을 굽기(synk-video 4단계) 직전에 돈다. 로맨스 · 서울로에서 유호님이 찾으신 문제 대부분(엔진 섞임 · 얼굴 흔들림 · 버스 색 · 같은 시작 그림 두 번 · 낮밤 · 시대 섞임)은 이 단계 그림에서 이미 보였다 — 여기서 잡으면 다시 굽기 크레딧이 들지 않는다(2026-11-12 유호님 「둘 다 세팅」, [결정](../../../docs/_ops/결정.md)).

만드는 손은 제작 세션(Opus) 하나다. 이 스킬은 보는 일만 한다 — 고칠 표를 넘기고, 고치기 · 다시 굽기는 제작 세션이 한다. 검수 세션을 여는 일은 [마감작업 스킬 「제작 세션이 하는 일」](../마감작업/SKILL.md#제작-세션이-하는-일)과 같다(카본 영상 심사만 뺀다).

## 0. 이 세션이 맞나
- 세션 모델 id가 `claude-fable-5-2`가 아니면 아무것도 돌리지 않고 한 줄로 알린다: 「이 세션은 <모델>이라 관문을 돌리지 않았습니다 — 모델을 Fable 5.2로 바꾸고 다시 불러 주세요」. 워크플로 검수자는 세션 모델을 물려받으므로 이 세션의 모델이 곧 검수자 모델이다. 예외는 아래 Fable 한도 대체 하나다.
- **관문을 시작할 때마다** `mcp__ccd_session_mgmt__get_usage`로 주간 Fable 몫을 지금 값으로 잰다 — 앞 관문 때의 값이나 첫 글에 적힌 옛 근거를 다시 쓰지 않는다. **남은 몫이 10% 아래거나 한도 오류가 나면 초기화를 기다리거나 여쭙지 않고 Opus 5.5로 같은 관문을 돈다**(2026-11-13 · 11-14 유호님, [운영 원칙 「한도」](../../../docs/AI_운영원칙.md#quota-handoff)).
  - 이 세션이 Fable 5.2이고 남은 몫이 10% 아래거나 이번 관문에서 한도 오류가 났으면 워크플로를 돌리지 않고 제작 세션(첫 글의 id)에 「Fable 한도 — 근거 <지금 get_usage 값 · 잰 시각 · 오류 원문> — Opus 5.5로 바꿔 다시 맡겨 주세요」를 보내고 멈춘다(제작 세션이 `set_session_model claude-opus-5-5`로 바꾼다).
  - 이 세션이 Opus 5.5면 워크플로 args의 `한도대체: "<근거>"`에 **지금 근거가 있을 때만** 글을 넣어 돈다. 근거는 셋뿐이다 — ① 지금 잰 값이 10% 아래(값 · 잰 시각) ② 제작 세션이 이번 맡김 글에 적은, 이번 관문에서 Fable이 낸 한도 오류(오류 원문 · 난 시각 — 주간 몫이 10% 넘게 남았어도 근거다) ③ 대체 검수자가 낸 지적을 그 검수자가 확인하는 `다시`(「대체 검수자 수정 확인」 + 앞결과의 「Opus 5.5 대체 검수」 글 — 몫이 돌아와 있어도 이 `다시`는 Opus 5.5가 본다). 셋 다 아니면 넣지 않는다 — 그러면 워크플로가 Opus 답을 받지 않으니, 제작 세션에 「Fable 몫 회복 — claude-fable-5-2로 되돌려 주세요」를 보내고 멈춘다.
  - 결과 · 보고에는 실제로 Opus 5.5가 답한 판에만 「Opus 5.5 대체 검수 — 한도 근거」가 남는다.
- 다른 편의 울트라 관문이 도는 중이면 그것이 끝난 뒤에 돈다(한 번에 한 편).

## 1. 판 만들기
인자 `<편 폴더>` = 컷표.json · 정지/ · 이미지지시문/ · 꾸러미/가 있는 곳. 출력 = `<편>/검수/굽기전_<YYYYMMDD-HHmm>`(`Get-Date -Format yyyyMMdd-HHmm`).

```
python -I -X utf8 tools/영상관문판.py <편>/컷표.json --관문 굽기전 --출력 <출력>/판
```

정지 · 그림 지시문 · 꾸러미가 기본 자리와 다르면 `--그림` · `--그림지시문` · `--꾸러미`. 50컷이면 몇 분 걸린다 — 10분을 넘길 것 같으면 `run_in_background`로 돌리고 끝 알림을 기다린다.
- 끝 줄의 「컷연속성검사 걸림」이 1 이상이면 관문을 돌리지 않는다. 기계 검사 걸림은 제작 세션이 먼저 고친다(Fable 몫을 쓰지 않는다) — `<출력>/판/연속성/결과.json`의 걸림 줄을 제작 세션에 넘기고 끝.
- 「못함」(시작 그림 없음 · 폴더 없음 · 기준 그림 없음)은 그대로 잇되 보고에 남는다.

## 2. 관문 워크플로
```
Workflow({ scriptPath: ".claude/workflows/video-gate.js",
           args: { 관문: '굽기전', 편, 컷표, 출력, 판폴더: "<출력>/판", 그림지시문?, 꾸러미?, 한도대체? } })
```
경로는 모두 절대 경로다. 관점은 판목록이 정한다 — 컷 전수(검수자 하나에 그림 30장 안쪽) · 컷 사이 · 얼굴 · 이야기(컷표를 열기 전에 판만 보고 먼저 읽기) → P0 · P1만 반박(「아님」은 다른 검수자가 한 번 더, 두 번 「아님」이면 기각, 갈리면 확인) → 빠진 것 찾기 → 기록(`<출력>/결과.json` · `보고.md`).

## 3. 받은 뒤
- 반환 `모델확인.맞음`이 거짓이면 결과를 쓰지 않는다. 워크플로 기록 폴더(결과에 나온 journal.jsonl 자리)의 `agent-*.jsonl`에서 `"model":"claude-…"`를 세어 준비 · 기록(Sonnet) 말고는 모두 `claude-fable-5-2`인지 본다(한도대체로 돌았으면 `claude-opus-5-5`도 받는다).
- `기록맞음`이 거짓이면 반환의 `결과`로 결과.json · 보고.md를 직접 쓴다.
- 상태 「확인」 지적은 이 세션이 근거 그림을 직접 열어 유지 · 기각을 정하고 보고.md 「확인할 것」에 적는다. 실제 사람 얼굴(승인 얼굴 세트 배역)은 정하지 않고 유호님 몫으로 남긴다.
- 결과.json · 보고.md는 편과 함께 올린다. 판/ · 메모/는 다시 만들 수 있어 .gitignore가 뺀다.

## 4. 넘기기
- 제작 세션(이 세션을 연 세션 — 첫 글에 id가 있다)에 SendMessage: 보고.md 경로 · 판정별 컷 수 · 고칠 컷과 고칠곳(그림 다시 / 그림 지시문 / 영상 지시문 / 컷표). 다시 굽기에 크레딧이 들면 제작 세션이 견적을 보이고 받는다.
- 유호님께는 한 단락: 판정별 컷 수, 유지한 P0 · P1, 유호님이 보실 것(실제 얼굴 「확인」 칸). 「통과」는 유지 0 · 확인 0일 때만 쓴다.

## 5. 고친 뒤 — 다시
`/굽기전검수 다시 <편> <컷…>`: 판 도구에 `--컷 C3,C7`(고친 컷과 앞뒤 이웃만 판을 만든다), 워크플로 args에 `다시: true, 컷: ['C3', 'C7'], 앞결과: "<지난 출력>/결과.json"`. 지난 지적마다 고쳐짐 / 그대로를 보고 고치며 생긴 새 문제만 반박한다(운영 원칙 「재검수와 배포 후보」 — 이야기 · 빠진 것은 돌지 않는다).

다시 검수의 표는 이렇게 읽는다(2026-11-17).
- 번호가 두 벌이다. 「F12」는 이번 다시 검수에서 새로 나온 지적이고 「지난 F12」는 지난 관문의 지적이다. 번호가 같아도 서로 다른 지적이다. 「지난 F12」의 내용은 결과.json 「다시결과」에서 「번호」가 같은 줄에 있다. 다시 검수를 거듭해 지난 결과에서도 못 고친 채 넘어온 지적은 「지난 지난 F12」로 적힌다(한 번 더 앞 관문의 지적이다).
- 컷 판정에는 이번에 유지한 지적과 지난 지적 가운데 P0 · P1 「그대로」만 들어간다. 지난 P2 · P3 「그대로」는 「P2 · P3」 칸에 있고 컷 판정을 바꾸지 않는다. 결과.json 「다시결과」의 「그대로」 줄마다 「컷판정에」 칸에 「들어감」 / 「안 들어감」이 적혀 있다.
- 지난 지적의 등급은 다시 본 검수자가 지난 결과에서 옮겨 적은 값이다(워크플로는 파일을 읽지 못한다). 같은 지난 지적을 두 관점이 다른 등급으로 적었으면 무거운 쪽으로 센다.
- **워크플로가 끝나면 `node tools/영상관문대조.js <출력>/결과.json`을 돌린다.** 「앞결과」를 따라 첫 관문까지의 결과 파일을 읽어, 옮겨 적은 등급과 번호가 맞는지와 열려 있던 P0 · P1이 확인 없이 사라지지 않았는지 본다. 끝 코드 0이면 볼 것이 없고 2면 있다(11-17 두 편의 다시 검수 세 번에서 100줄 가운데 4줄이 지난 결과와 달랐다).
  - 「넣을 것」은 낮춰 적혀 컷 판정에서 빠진 열린 P0 · P1이다. 「다시 보지 않은 것」은 이번 판의 컷에 걸려 있는데 검수자가 답하지 않은 열린 P0 · P1이다. 둘 다 이 세션이 그 컷의 그림을 직접 열어 보고 결과.json에 남긴다: `node tools/영상관문대조.js <출력>/결과.json --적기 "<도구가 찍은 이름>=그대로:<본 것>"`(고쳐졌으면 `=고쳐짐:<본 것>`). 「그대로」로 적은 줄은 다음 다시 검수자가 넘겨받는다. 적지 않고 두면 「고쳐짐」 줄이 생길 때까지 회차마다 대조가 다시 알린다.
  - 「따져 볼 것」은 올려 적혀 반박 없이 컷 판정에 들어간 줄이다. 근거 그림을 열어 P1이 맞는지 정하고, 아니면 그 컷의 할 일에서 뺀다. 「번호를 확인할 것」은 보고.md에서 번호를 바로잡는다.
  - 「이번 판에 없는 열린 지적」은 아직 고쳐졌다는 확인이 없는 P0 · P1인데 그 컷이 이번 판에 없던 것이다. 남은 일이니 제작 세션에 함께 넘긴다. 컷을 나눠 다시 검수해도 이 목록에서 빠지지 않는다.
  - 바로잡은 것은 보고.md 맨 위에 적고, 제작 세션에는 바로잡은 표를 넘긴다.
- 컷 줄의 「할일」에 번호 · 등급 · 고칠곳 · 고칠법이 함께 들어 있다. 지난 지적의 고칠곳 · 고칠법은 다시 본 검수자가 적은 것이다. 제작 세션에 넘길 때 번호로 지적 목록을 다시 찾지 않고 이 목록을 그대로 넘긴다.
- 요약의 「지난」은 지난 지적을 번호로 센 수다(본 것 · 고쳐짐 · 그대로 P0 · P1 · 그대로 P2 · P3). 꼭 고칠 것은 「상태」의 유지와 「지난」의 「그대로 P0 · P1」을 더한 수다.
- 2026-11-17 전에 나온 다시 검수 보고서는 두 번호를 한 칸에 섞어 적었고 지난 P2 · P3 때문에도 컷을 「다시」로 셌다. 그 보고서의 컷 수는 꼭 고칠 컷 수가 아니다.

## 쓰지 않는 곳
매일 SNS 편 · 컷 몇 개짜리 시험 묶음은 지금처럼 Fable 콘티 검수 한 번과 자체검수로 간다. 울트라 관문은 Fable 몫을 한 번에 많이 쓴다(50컷 한 편에 검수자 7~9).
