# 굽기 전 검수 — 영상 크레딧을 쓰기 직전의 울트라 관문

광고 · 공모전 · 포트폴리오 편의 시작 그림이 다 나온 뒤, 영상을 굽기(synk-video 4단계) 직전에 돈다. 로맨스 · 서울로에서 유호님이 찾으신 문제 대부분(엔진 섞임 · 얼굴 흔들림 · 버스 색 · 같은 시작 그림 두 번 · 낮밤 · 시대 섞임)은 이 단계 그림에서 이미 보였다 — 여기서 잡으면 다시 굽기 크레딧이 들지 않는다(2026-11-12 유호님 「둘 다 세팅」, [결정](../../../docs/_ops/결정.md)).

만드는 손은 제작 세션(Opus) 하나다. 이 스킬은 보는 일만 한다 — 고칠 표를 넘기고, 고치기 · 다시 굽기는 제작 세션이 한다. 검수 세션을 여는 일은 [마감작업 스킬 「제작 세션이 하는 일」](../마감작업/SKILL.md#제작-세션이-하는-일)과 같다(카본 영상 심사만 뺀다).

## 0. 이 세션이 맞나
- 세션 모델 id가 `claude-fable-5-2`가 아니면 아무것도 돌리지 않고 한 줄로 알린다: 「이 세션은 <모델>이라 관문을 돌리지 않았습니다 — 모델을 Fable 5.2로 바꾸고 다시 불러 주세요」. 워크플로 검수자는 세션 모델을 물려받는다. Agent의 `fable`은 5.1로 가서 쓰지 않는다([현장 노트](../../../docs/현장노트/AI_CLI.md)).
- `mcp__ccd_session_mgmt__get_usage`의 주간 Fable 몫을 적어 둔다. 한도에 걸려 멈추면 「Fable 몫 초기화해 주세요」 한 줄만 여쭌다 — 계정 전환 · 기다리기를 권하지 않는다.
- 다른 편의 울트라 관문이 도는 중이면 그것이 끝난 뒤에 돈다(한 번에 한 편).

## 1. 판 만들기
인자 `<편 폴더>` = 컷표.json · 정지/ · 이미지지시문/ · 꾸러미/가 있는 곳. 출력 = `<편>/검수/굽기전_<YYYYMMDD-HHmm>`(`Get-Date -Format yyyyMMdd-HHmm`).

```
python -I -X utf8 tools/영상관문판.py <편>/컷표.json --관문 굽기전 --출력 <출력>/판
```

정지 · 그림 지시문 · 꾸러미가 기본 자리와 다르면 `--그림` · `--그림지시문` · `--꾸러미`. 50컷이면 몇 분 걸린다 — 10분을 넘길 것 같으면 `run_in_background`로 돌리고 끝 알림을 기다린다.
- 끝 줄의 「컷연속성검사 걸림」이 1 이상이면 관문을 돌리지 않는다. 기계 검사 걸림은 제작 세션이 먼저 고친다(Fable 몫을 쓰지 않는다) — `<출력>/판/연속성/결과.json`의 걸림 줄을 제작 세션에 넘기고 끝.
- 「못함」(시작 그림 없음 · 폴더 없음 · 기준 그림 없음)은 그대로 잇되 보고에 남는다.

## 2. 관문 워크플로
```
Workflow({ scriptPath: ".claude/workflows/video-gate.js",
           args: { 관문: '굽기전', 편, 컷표, 출력, 판폴더: "<출력>/판", 그림지시문?, 꾸러미? } })
```
경로는 모두 절대 경로다. 관점은 판목록이 정한다 — 컷 전수(검수자 하나에 그림 30장 안쪽) · 컷 사이 · 얼굴 · 이야기(컷표를 열기 전에 판만 보고 먼저 읽기) → P0 · P1만 반박(「아님」은 다른 검수자가 한 번 더, 두 번 「아님」이면 기각, 갈리면 확인) → 빠진 것 찾기 → 기록(`<출력>/결과.json` · `보고.md`).

## 3. 받은 뒤
- 반환 `모델확인.맞음`이 거짓이면 결과를 쓰지 않는다. 워크플로 기록 폴더(결과에 나온 journal.jsonl 자리)의 `agent-*.jsonl`에서 `"model":"claude-…"`를 세어 준비 · 기록(Sonnet) 말고는 모두 `claude-fable-5-2`인지 본다.
- `기록맞음`이 거짓이면 반환의 `결과`로 결과.json · 보고.md를 직접 쓴다.
- 상태 「확인」 지적은 이 세션이 근거 그림을 직접 열어 유지 · 기각을 정하고 보고.md 「확인할 것」에 적는다. 실제 사람 얼굴(승인 얼굴 세트 배역)은 정하지 않고 유호님 몫으로 남긴다.
- 결과.json · 보고.md는 편과 함께 올린다. 판/ · 메모/는 다시 만들 수 있어 .gitignore가 뺀다.

## 4. 넘기기
- 제작 세션(이 세션을 연 세션 — 첫 글에 id가 있다)에 SendMessage: 보고.md 경로 · 판정별 컷 수 · 고칠 컷과 고칠곳(그림 다시 / 그림 지시문 / 영상 지시문 / 컷표). 다시 굽기에 크레딧이 들면 제작 세션이 견적을 보이고 받는다.
- 유호님께는 한 단락: 판정별 컷 수, 유지한 P0 · P1, 유호님이 보실 것(실제 얼굴 「확인」 칸). 「통과」는 유지 0 · 확인 0일 때만 쓴다.

## 5. 고친 뒤 — 다시
`/굽기전검수 다시 <편> <컷…>`: 판 도구에 `--컷 C3,C7`(고친 컷과 앞뒤 이웃만 판을 만든다), 워크플로 args에 `다시: true, 컷: ['C3', 'C7'], 앞결과: "<지난 출력>/결과.json"`. 지난 지적마다 고쳐짐 / 그대로를 보고 고치며 생긴 새 문제만 반박한다(운영 원칙 검수 ② — 이야기 · 빠진 것은 돌지 않는다).

## 쓰지 않는 곳
매일 SNS 편 · 컷 몇 개짜리 시험 묶음은 지금처럼 Fable 콘티 검수 한 번과 자체검수로 간다. 울트라 관문은 Fable 몫을 한 번에 많이 쓴다(50컷 한 편에 검수자 7~9).
