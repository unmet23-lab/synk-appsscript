# 수집 한 장

SYNK가 바깥 정보를 모으는 일을 한곳에서 관리한다(2026-11-25 유호님 「한곳에 통합 관리하기 좋게」 → 「응, 지어」).

- **정본은 `목록.json`이다.** 일마다 무엇을, 누가, 언제 모으는지, 결과를 어디에 두고 누가 읽는지 적는다. 새 수집은 여기에 한 줄을 더한다. 「읽는곳」을 채우지 못하면 걸지 않는다.
- **돌리는 곳은 하나다.** Windows 예약 「SYNK 수집」이 30분마다 `돌리기.js`를 부른다. 종류가 「수집 예약」인 일 가운데 때가 된 것만 돌리고, 할 일이 없으면 AI 없이 바로 끝난다. 다른 종류(Windows 예약 · Claude 예약 · 그록봇)는 적힌 예약이 돌리고, 목록은 상태만 모은다.
- **상태는 `node tools/수집/상태.js`로 본다.** 일마다 마지막으로 돈 때, 결과, 다음 차례가 나온다. `--찾은수 14`는 최근 14일 공모 지도에 처음 들어온 공고를 AI마다 세고 혼자만 찾은 수를 보인다.
- **관문 문서의 표는 목록에서 만든다.** 목록을 고친 뒤 `node tools/수집/상태.js --표 --쓰기`를 돌린다. 시험(`tests/수집.test.js`)이 표와 목록이 같은지 본다.

## 공모전 찾기 넷

Opus(08:30), Sol(14:30), Gemini(20:00)가 같은 요청문 `공모요청문.md`로 매일 찾고, 그록은 맹꽁이 봇의 08:30 회차가 이틀에 한 번(홀수 날) 찾는다. 비교해 보니 그록과 Gemini가 찾는 공고가 거의 겹치지 않아 넷으로 늘렸다(11-19~21 아홉 회차에서 둘 다 찾은 공고 1건).

- `node tools/수집/공모찾기.js <opus|sol|gemini>`가 한 번 찾는다. 요청문 끝에 지도에 이미 있는 열린 공고 이름(120개까지)을 붙여 같은 공고를 다시 내지 않게 한다.
- 받은 답은 그록 공모 보고서 꼴로 바꿔 `SYNK-보관함/지원사업/그록공모전/`에 넣는다. 넣을 때 공식 원문을 열어 인용을 대조하므로 그록 공고와 같은 검증을 거친다. 받은 답 원문은 `공모수집/<날짜>/<누가>-<시각>.json`에 남는다.
- 공모 지도 갱신 예약(09:30 · 15:30 · 21:00)이 이 보고서를 읽어 지도 · 자격 확인 · 급한 공고 알림으로 넘긴다. 지도 카드에는 「찾음 Opus · 그록」처럼 찾은 AI가 붙는다.
- 통로: Opus는 `claude -p`(구독, WebSearch · WebFetch만), Sol은 `tools/codex계정.js exec`(굽기 계정을 돌려 쓰고 `web_search="live"`), Gemini는 `agy -p`(구독, `search_web`). 한도에 걸리면 그 회차는 「못 부름」으로 적고 다음 날 다시 돈다.
- 12-09에 `--찾은수 14`로 AI마다 혼자 찾은 공고 수를 보고, 혼자 찾은 공고가 없는 AI는 뺀다.
