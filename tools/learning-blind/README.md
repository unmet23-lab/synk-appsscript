# 다음 한국어 연습 선택 비교

현재 제품의 학습 기록과 실제 연습 후보를 같은 입력으로 고정하고, GPT·Claude·Jev의 **다음 연습 하나와 주요 관측 하나**를 비교하기 위한 오프라인 도구다. 요청 JSON을 준비하고 이미 저장된 응답을 평가한다. 에이전트 실행·도구 호출·모델 선택·재시도·자동 대체 기능은 없다. 제품 추천이나 학습 기록을 변경하지 않는다.

2026-10-07 사용자 승인 범위인 **개발 사례 18개 × 첫 번째 보기 순서 × 고정 모델 3개 = 실제 API 요청 54개**를 실행했다. 54개 모두 HTTP 200·응답 정규화·후보 및 실행 조건 계약을 통과했다. 응답 토큰과 일반 단가로 계산한 비용은 **$0.262154028**이며 제공자 청구서 대조는 하지 않았다. 원래 준비한 108개 중 두 번째 보기 순서 54개는 미실행이다. 이것은 승인한 54개 시험의 실패나 누락이 아니다. 인간 블라인드 평가와 실제 학생 학습 효과는 아직 미검증이다.

## 입력과 비교 범위

`cases.mjs`는 현재 Game/Core 코드와 교실 게임 카탈로그의 실제 문항으로 가상 학습 이력 6개를 구성하고, 각 이력의 연속된 세 시점을 저장한다. 입력에는 관측 요약, 현재 소리 사용 가능 여부, 실제 다음 연습 후보만 들어간다. 학생 계정이나 실학생 식별 정보는 사용하지 않는다.

개발 사례는 읽기·듣기 오류, 도움 받은 정답, 같은 문항의 반복 정답, 새로운 문항의 독립 정답, 소리 사용 불가·재생 실패를 포함한다. 급수·숙련도·학습 효과를 자동 판정하는 시험이 아니다. 세 시점과 두 순서, 세 모델을 독립 학생 수로 세지 않는다.

모든 모델의 출력 계약은 `candidateId`와 `evidenceId` 두 필드다. 후보 ID는 제공된 목록에서 고르고, 근거는 실제 관측 ID 하나 또는 `none`이다. Jev의 두 Choice 질문은 같은 입력을 각각 판단하므로 근거 선택을 다른 질문의 답에 대한 생성 설명으로 해석하지 않는다.

| 제공자 | 고정 모델 | 요청 설정 |
| --- | --- | --- |
| OpenAI | `gpt-6.1-sol` | Responses JSON schema, 추론 `low`, 출력 한도 3,000토큰 |
| Anthropic | `claude-sonnet-5-5` | Messages JSON schema, `between_tools`·`low`, 출력 한도 3,000토큰, 도구 없음 |
| TypeSafe | `jev-1.13.0` | 후보·관측 ID를 보기로 둔 Choice 질문 2개 |

모델·API 계약의 공식 출처는 `providers.mjs`의 주석에 있다. 자유 설명문을 채점하거나 모델 이름을 동적으로 고르는 비교는 포함하지 않는다.

## 요청 준비

저장소 루트에서 실행한다. `--out`에는 **아직 존재하지 않는 새 디렉터리**를 지정한다. 다음은 경로 예시다.

```powershell
node tools/learning-blind-test.mjs prepare --out output/learning-blind/example-packet
```

준비 명령은 외부 API를 호출하거나 키를 읽지 않는다. 첫 순서는 고정 seed로 섞고, 두 번째는 후보·관측 순서를 뒤집는다. 같은 사례·같은 순서의 세 모델에는 같은 후보·관측 순서가 적용된다.

| 준비 파일 | 의미 |
| --- | --- |
| `manifest.json` | 사례·모델·순서·요청 경로·SHA-256·원본 코드 스냅샷 정보. `packetSha256`는 결과 묶음의 식별값 |
| `requests/*.json` | 제공자 API의 요청 본문. 키, 현재 규칙의 답, 개발 채점 기준은 들어가지 않음 |
| `private/cases.json` | 고정 입력과 현재 제품 정책의 선택, 작성자가 정한 개발 기준. **모델에 보내지 않는 평가 자료** |
| `results-template.json` | 108개 요청의 결과 자리. 처음에는 모두 `status: "not_run"` |
| `cost-estimate.json` | 요청별·모델별·전체 계획 비용. 실측 사용량과 실제 청구는 `null` |

금액은 해당 묶음의 `cost-estimate.json` 계산치를 참조한다. 전체 요청 JSON의 UTF-8 바이트 수에 입력 여유 4,096을 더하고, 설정된 최대 출력과 일반 API 단가를 적용한 계획 추정이다. 실제 토큰 측정이나 제공자가 보장한 비용 상한이 아니며 캐시·배치 할인, 재시도·실패 청구와 인건비도 확정하지 않는다. Jev의 출력 비용 계산값 0은 출력 무료 단가를 뜻하며 실제 출력 토큰이 0이라는 뜻이 아니다.

이 도구에는 유료 실행 명령이 없다. 실제 호출은 비용·범위 확인과 별도 연결 작업이 필요한 단계다. 자격증명은 요청 묶음과 저장소에 포함하지 않는다. 외부 키 저장·연결의 성공 여부는 이 오프라인 준비 완료만으로 확인되지 않는다.

## 저장된 응답 평가

실제 응답이 있을 때 `results-template.json`을 별도 파일로 복사해 각 행을 기록한다. `packetSha256`, `caseId`, `trial`, `provider`, `requestSha256`는 유지한다. 원본 준비 묶음의 요청이나 사례를 바꾸지 않는다.

- `not_run`: 아직 저장된 결과 없음. `body`와 `error`를 넣지 않는다.
- `completed`: `body`에 **제공자가 반환한 전체 JSON 응답**을 저장한다. 선택 두 필드만 복사한 JSON은 모델·완료 상태·사용량을 확인할 수 없어 거부된다.
- `failed`: `error`를 저장하고 `body`는 넣지 않는다. 실패를 성공 답으로 채우지 않는다.

일부 행만 저장할 수 있다. 누락된 행도 예정된 전체 108개 분모에 남는다. 저장된 결과가 없다는 사실만으로 이전 외부 호출이나 청구가 없었다고 증명할 수는 없다.

```powershell
node tools/learning-blind-test.mjs evaluate --packet output/learning-blind/example-packet --results output/learning-blind/saved-results.json --out output/learning-blind/example-evaluation
```

`evaluate`도 외부 API를 호출하지 않는다. 묶음·요청·결과 식별값과 해시를 확인하고 저장된 본문을 정규화한다. 다른 묶음 결과, 중복 행, 알 수 없는 제공자·요청, 본문 형식 오류, 미완료·거절·누락된 사용량은 정상 결과로 바꾸지 않는다.

외부 호출 전 준비 상태만 확인하려면 `--results`에 원래 `results-template.json`을 지정할 수 있다. 이때 완료 0개, 미실행 108개이며 블라인드 비교 카드는 생성되지 않는다.

| 평가 파일 | 의미 |
| --- | --- |
| `summary.json` | 전체 예정 수, 미실행·실패·완료 수, 계약 통과, 현재 정책 일치, 확인된 토큰 기반 비용 추정 |
| `private/evaluation.json` | 응답별 정규화·계약·작성 기준·정책 일치 결과와 두 순서 간 변화 |
| `private/results-original.json` | 평가에 사용한 저장 결과 원본 |
| `blind-review.json`, `blind-review.md` | 현재 제품 정책과 실제 저장된 완료 응답을 익명 A·B·C·D로 제시하는 교사 검토 자료 |
| `human-ratings-template.json` | 과제 적절성·근거 지지·과잉단정 위험을 각각 0~2로 기록하는 빈 평가표 |
| `private/reveal.json` | 익명 선택과 제공자의 대응표. 블라인드 검토가 끝날 때까지 검토자에게 전달하지 않음 |

완료된 일부 모델만 있으면 검토 자료에 일부 결과라는 범위가 표시된다. 결과가 없는 모델의 답은 생성하지 않는다. 교사에게는 `private/` 자료를 제외한 블라인드 검토 자료와 평가표를 전달한다. 이 도구는 작성된 교사 평가표를 자동 합산하거나 모델 우승을 선언하지 않는다.

## 결과 해석과 남은 검증

현재 Core 정책과의 일치는 기존 동작을 재현했는지를 보여준다. **일치율은 추천 품질이나 정답률이 아니다.** 작성자의 개발 허용 후보도 독립 정답지가 아니며, 관측이 부족하거나 다음 선택이 여러 개 가능한 사례는 사람 판단으로 남긴다. 같은 측정 영역의 근거인지와 실제 선택을 교육적으로 지지하는지는 따로 검토한다. 보기 순서에 따라 선택이 달라도 교육적으로 동등한 대안이면 자동 오답 처리하지 않는다.

독립 heldout 사례, 교사 블라인드 평가, 실제 학생의 다음 행동·체감·학습 효과는 아직 검증하지 않았다. `teachingQuality`, `learningEffect`, `modelWinner`, `actualBilling`의 `null`을 0이나 확인 완료로 바꾸어 읽지 않는다. 응답의 사용량에 일반 단가를 적용한 추정도 제공자의 실제 청구서 대조를 대신하지 않는다.

오프라인 계약 시험은 다음과 같이 실행한다. 가상 응답으로 파일·순서·해시·오류 처리 계약을 검증하며 실제 제공자 정확도나 API 연결 성공을 증명하지 않는다.

```powershell
node --test tests/learning-blind-cases.test.mjs tests/learning-blind-providers.test.mjs tests/learning-blind-evaluation.test.mjs
```

## 이번 실행에서 확인한 기능과 한계

세 모델 모두 읽기·듣기 오류가 있는 사례에서 해당 영역의 후보를 선택했고, 같은 문항을 여러 번 맞힌 사례에서는 같은 영역의 확인 연습을 유지했다. 소리를 사용할 수 없는 두 시점에서는 세 모델 모두 읽기 후보를 선택했다. 새 읽기 문항 여덟 개를 독립적으로 맞힌 뒤에는 세 모델 모두 과거의 읽기 세부 정보 확인 후보에서 다른 영역 후보로 이동했다. 이는 저장된 선택의 관찰이며 학습 효과나 변화의 원인을 검증한 결과가 아니다. 각 시점의 후보·근거 표시 순서도 달라졌으므로 기록 변화만의 인과 효과를 분리하지 못한다.

이번 동결 사례의 기존 Core 선택도 소리 조건과 기록에 따라 추천을 바꾸며, 작성 기준이 정해진 16개 사례에서는 모두 허용 후보를 고른다. 나머지 2개 사례는 처음부터 정답을 확정하지 않았다. **이번 결과로 AI가 기존 규칙보다 더 좋은 추천을 한다고 결론 내릴 수 없다.** Jev는 이 고정 후보 선택 과제를 낮은 비용과 짧은 응답 시간으로 수행했지만, 사용자가 체감하는 추가 이득은 아직 입증되지 않았다.

선택한 근거 ID가 존재하는 것과 충분한 학습 근거가 있는 것은 다르다. 응답이 전혀 없는 영역의 관측 요약을 근거로 고르거나, 선택 영역과 다른 영역의 기록을 근거로 고른 결과도 있으므로 사람이 적절성을 확인해야 한다. Jev의 두 Choice 답은 독립 질문의 결과라 후보와 근거의 논리적 연결을 자동 보장하지 않는다.

새 문항 여유도 따로 비교해야 한다. 실제 응답에는 새 문항이 1개 남은 게임을 고른 선택과 같은 영역에서 새 문항이 4개 또는 10개 남은 게임을 고른 선택이 함께 있다. 후보가 달라지는 것만으로 개선으로 세지 않는다. 이번 시험은 과제 ID와 관측 ID를 고르는 데서 끝나며 새 문항을 생성하거나 사용자가 그 과제를 실제로 수행한 결과를 포함하지 않는다.

익명 화면에서는 현재 정책과 세 모델을 매 사례마다 다시 섞어 A~D로 표시한다. **A가 모든 사례에서 같은 모델을 뜻하지 않는다.** 점수는 전부 미평가로 시작하며 사람만 입력한다. 모델 대응표·토큰·기계 점수는 화면에 넣지 않았다. 동결 요청의 해시와 입력 동일성, 계약 시험 36/36을 다시 확인했다. 원본 코드 중 `atlas/trail.js`는 준비 후 해시가 달라졌지만 현재 사례 생성 결과 전체는 동결 사례와 같았고 이번 요청은 동결본을 사용했다.

비교 화면은 HTML 한 파일로 열 수 있다. 이번 실행의 로컬 화면 주소는 `http://127.0.0.1:53647/`이며 서버가 종료되면 `review.html` 파일을 브라우저에서 열면 된다. 필요하면 `node output/learning-blind/evaluation-20261007-v1/serve-review.mjs`가 새 로컬 주소를 출력한다. 서버는 이 비교 HTML만 제공하며 평가를 수집하거나 모델을 호출하지 않는다. 점수는 현재 페이지에만 남으므로 닫기 전에 평가 JSON을 보관한다. 파일 다운로드가 작동하지 않는 브라우저에서는 **평가 JSON 내용 보기 → 내용 모두 선택**으로 같은 내용을 복사해 `.json` 파일로 보관할 수 있다.

실제 브라우저에서 사례 이동·임시 점수/메모 입력·JSON 내용 보기의 72행과 미평가 보존을 확인했다. 파일 다운로드 단추의 요청 발생은 확인했지만 앱 내 브라우저의 파일 수신은 도구 대기 시간 초과로 미확인이다. 검증용 임시 평가 파일은 `qa-export-not-human-rating.json`으로 분리했으며 사람 평가나 추천 품질 점수에 포함하지 않는다. 최종 사용자 탭은 216항목 모두 미평가다.

남은 검증은 교사·사용자의 익명 평가, 별도 사례에서의 추천 품질, 보기 순서·반복 실행 안정성, 그리고 실제 앱에서 추천을 누른 뒤 새 문항 수행·완료·도움 요청이 어떻게 달라지는지다. 이 단계들은 이번 54회 실행에 포함하지 않았다. 제품 추천 연결·실학생 기록 전송·공개 배포는 하지 않았다.

## 2026-10-07 작성형 교정과 새 문항 확인 구현

사용자의 전체 반영 요청으로 바람길 **별도 듣기 확인**, 입장 검사, Town 읽기, 레이싱에 다음 세 가지를 연결했다. 유료 모델 호출을 추가하지 않았다.

1. **고른 답을 설명에 연결**: 바람길의 기존 해설을 실제로 표시하고, 네 활동에 고른 오답과 정답의 차이를 짧게 설명한다. 한 번 틀린 것으로 오개념을 확정하지 않는다. 바람길은 채점 뒤 다시 듣기를 허용하되 첫 답을 다시 채점하지 않는다. 레이싱은 오답·도움 후 설명을 읽는 동안 주행과 시간을 멈추고 계속 버튼을 기다린다.
2. **선택 정보 보존**: Core→Trail 공통 입력의 선택적 `choice: { selectedId, correctId }`에 검증된 기계 ID만 저장한다. 문항 버전·도움·반복·독립 응답 판정은 기존 계약을 유지한다. 최근 원본 이벤트에는 선택 정보가 남고, 오래된 기록을 접은 원장에는 기존 정오·노출 요약만 남는다. 영구적인 모든 선택 이력 보관으로 해석하지 않는다.
3. **같은 목표의 새 문항으로 확인**: 오답·도움 뒤 아직 노출하지 않은 같은 영역·난도의 실제 문항을 남은 순서 안에서 선택한다. 과제에 허용된 문항·문항군과 회차 총수를 지킨다. 새 문항이 없거나 이력을 확인할 수 없으면 새 문항이라고 표시하지 않는다. 입장 검사에는 세 가지 목표에 대응하는 글 전용 후속 손님 3명을 더했고, 기본 여섯 손님과 기존 음성 제작 목록은 유지했다.

담당 원문은 [공통 교육 계약](../../docs/아틀라스_교육업그레이드_20260930.md), [바람길](../../experiences/korean-runner/README.md), [입장 검사](../../experiences/entry-check/README.md), [Town](../../experiences/synk-town/README.md), [레이싱](../../experiences/korean-racing/README.md)이다. 실제 source에서 게임 공통 묶음·계정 웹 묶음을 다시 만들었고 SYNK-talk의 Atlas 사본·서버 묶음까지 로컬로 동기화했다. 운영 반영 때는 새로운 선택 정보 계약을 받는 서버와 클라이언트 버전을 함께 맞춰야 한다.

관련 Node 검사 다섯 묶음은 131 + 60 + 40 + 215 + 47 = **493/493** 통과했다. 가상 저장소·시험용 오디오·로컬 서버를 포함하는 자동 검사이며, 뒤에 반복 실행한 검사는 합계에 다시 넣지 않았다. 생성물 세 종류의 최신 원본 일치 검사도 통과했다. 실제 브라우저 조작·캡처와 각 검증의 범위는 [구현 검증 기록](../../output/learning-feedback-implementation-20261007/verification.json)에 남긴다.
