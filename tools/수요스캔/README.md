# 수요 스캔

매일 저녁(10-23부터, 그전엔 매주 월요일), 브랜드(LAB 영어 `lab-en` · LAB 몽골 `lab-mn` · `synkbrief` · `yuhobuilds`)마다 같은 시청자를 노린 짧은 영상 가운데 **채널 평소보다 크게 튄 편**과 그 댓글을 모은다. 정본 제안은 [시청자 수요 조사 10-22](../../docs/마케팅/시청자수요조사_20261022.md) 6-7, 시드 채널·검색어는 그 조사의 원자료와 수집 스크립트에서 옮겼다. 읽기만 한다 — 로그인·게시·좋아요·댓글 쓰기·구독을 하지 않고 영상 파일은 받지 않는다.

## 쓰는 법

```
node tools/수요스캔/스캔.js 전부                    # 네 브랜드
node tools/수요스캔/스캔.js lab-en synkbrief        # 고른 브랜드
node tools/수요스캔/스캔.js lab-en --채널 5 --검색 1 --틱톡 2 --댓글 2 --누적안씀   # 작게 시험
node tools/수요스캔/스캔.js 전부 --유튜브 ytdlp       # 유튜브 채널도 yt-dlp(쇼츠 탭·RSS)로만 — 옛 길
node tools/수요스캔/스캔.js --설정검사              # 설정 넷만 검사(네트워크 없음)
node tools/수요스캔/스캔.js --도움                  # 선택 전부
node --test tests/수요스캔.test.js                  # 시험(네트워크 없음)
```

유튜브 채널 숫자는 YouTube Data API로 읽으므로 LAB YouTube 자격이 있어야 한다(`tools/sns-자격.ps1`, 읽기만 — 없으면 쇼츠 탭·RSS로 읽는다). 검색·틱톡·댓글 본문은 yt-dlp라 PATH에 있어야 하고(다른 곳이면 `SYNK_YTDLP`), 틱톡은 흉내내기가 든 판이어야 덜 막힌다(`pip install "yt-dlp[curl-cffi]"`). 네 브랜드 한 회차는 8분 안팎이다(10-25 실측 459초 — Data API 293번·yt-dlp 75번. yt-dlp만이던 10-24는 369번·18.6분).

## 판정과 읽는 방식

- **튄 편** — 그 채널 최근 쇼츠 30편 조회 중앙값의 3배 이상이고 브랜드 최소 조회(lab-en 3천 · lab-mn 1천 · synkbrief·yuhobuilds 5천) 이상, 또는 작은 채널(구독 3만 이하)에서 조회 ≥ 구독(최소 조회 이상). 쇼츠가 5편 안 되면 판정하지 않는다. 틱톡은 최근 30편 중앙값의 3배 이상(구독을 못 읽어 작은 채널 규칙 없음). 중앙값·배수는 `tools/lib/평소배수.js` 계산 그대로다(우리 계정 판정 `tools/게시성과.js`는 12편 기준이라 숫자가 다를 수 있다).
- **창** — 올린 지 28일 안(`--창`). 지난 회차에 평소 수준이던 편이 이번에 3배를 넘으면 그것도 새 튄 편이다. 이미 보고한 편은 다시 내지 않는다. 누적은 창 + 7일 안의 편과 지금 쇼츠 탭에 있는 편의 날짜만 기억한다 — 브랜드마다 수십 KB 안쪽.
- **조회·길이** — 쇼츠 탭 조회는 반올림 수라, RSS나 영상 정보의 정확한 수가 있으면 그것으로 판정한다(턱걸이로 3배를 넘은 반올림 수를 튄 편으로 잡지 않게). 3분 넘는 영상은 유튜브·틱톡 모두 튄 편으로 싣지 않는다.
- **Data API(10-25부터 기본)** — 유튜브 채널은 YouTube Data API로 읽는다(LAB YouTube 자격, 읽기만): 채널마다 쇼츠 목록(UUSH) 최신 30편 + 그 편들의 숫자(50편 묶음) + 구독(50곳 묶음), 각 1단위. 조회·좋아요·댓글 수·길이·올린 날이 모두 정확한 수라 쇼츠 탭·RSS·영상 정보 호출을 대신하고, 상세 상한(`--상세`)은 yt-dlp로 읽는 편에만 건다. 지난 회차의 「다시볼」·「보충」 편도 묶음으로 채운다. 댓글 본문만 yt-dlp로 받는다(전체 댓글 수는 API 값). 토큰을 못 받거나 한도·사용 설정 403이 오거나 연달아 세 번 실패하면 그 회차에서 API를 멈추고, 그 뒤 채널은 아래 쇼츠 탭·RSS 길로 읽고 요약 「못 잰 곳」에 적는다. 쇼츠 목록이 없는(404) 채널도 쇼츠 탭으로 확인한다. 실측과 까닭은 [서버](서버.md).
- **증분(yt-dlp 길)** — 쇼츠 탭(기준선·구독·최근 30편 조회)은 회차마다 읽고(`--기준선` 기본 7일), RSS(최신 쇼츠 15편의 정확한 날짜·조회)로 새 편 날짜를 안다. 탭을 건너뛰면 RSS 밖으로 밀린 편이 뒤늦게 튀어도 못 보므로 기본은 매주 읽는다 — 막힘이 잦으면 `--기준선 14`로 늘린다. 쇼츠가 5편이 안 돼 기준선을 못 만든 채널은 다음 회차에 다시 읽는다. 영상 정보(길이·날짜·좋아요)와 댓글은 새 튄 편에만, 조회 많은 순으로 상한(`--상세` 40 · `--댓글` 5편 × 30개)까지 읽는다. 댓글은 창 안이고 조회가 정확한 수로 확정된 편에만 같이 부르고, 댓글이 0개면 그 몫을 뒤 편에 넘긴다.
- **보고와 다시 보기** — 새 튄 편은 날짜가 확정된 때 한 번만 싣고 그때 보고한 편으로 적는다(다음 회차에 새 튄 편으로 또 내지 않는다). 길이를 못 읽었으면(상한·막힘·응답에 길이 없음) 다음 회차에 영상 정보를 마저 읽어 「지난 목록 보충」에 적는다 — 정확한 숫자로 다시 보니 튄 편이 아니면 「고침」으로 적는다. 날짜를 모르는 편은 근거로 쓰지 않고 「다시볼」에 두었다가(21일까지) 날짜가 확인되면 그때 처음 싣는다.
- **검색** — 회차마다 검색어 6개를 돌려 가며(관련순 첫 쪽 20편), 아직 모르는 채널 가운데 3분 이하·최소 조회를 넘긴 편이 있는 채널을 다섯 곳까지 더 읽어 「찾은 채널」로 둔다. 찾은 채널은 30곳까지 — 최근에 실은 편이 있는 채널(마지막튐)과 최근에 찾은 채널을 남기고, 밀린 채널은 누적에서 지워 다음에 검색에 걸리면 다시 찾는다. 검색 차례는 실제로 돈 검색어만큼만 넘어간다. 핸들만 적은 시드가 검색에 먼저 잡혀도 찾은 채널로 따로 두지 않는다.
- **막힘** — 호출은 하나씩, 2.5초(RSS 2초) 넘게 띄운다. 403·429·봇 확인이면(앞쪽 결과를 일부 받았어도) 그 대상은 「못 잼」 또는 「일부만 읽음」으로 적고 30초 쉰 뒤 다음으로 가며, 연달아 셋이면 그 서비스는 그 회차에서 멈춘다. RSS가 채널 셋을 연달아 실패하면 남은 채널은 쇼츠 탭으로만 읽는다. 브랜드에서 한 곳도 못 읽은 회차는 누적을 덮지 않는다.
- **쓰는 차례와 잠금** — 요약·원자료를 다 쓴 뒤에 누적을 쓴다. 같은 누적 폴더를 두 회차가 함께 돌지 못하게 `%TEMP%`에 잠금 파일을 두고(내용을 다 쓴 파일을 한 번에 걸어 빈 잠금이 생기지 않게, 그래도 빈 잠금이면 1분 동안은 산 것으로 본다), 끝나면 푼다(죽은 회차나 12시간 넘은 잠금은 걷어 낸다).

## 한계(10-23 실측)

- 유튜브 검색의 「이번 주·이번 달」 거르기는 조회 수십 회짜리 새 영상만 주고 조회순 정렬은 듣지 않는다. 관련순 결과도 대부분 롱폼이라 검색으로 찾는 새 채널은 적다 — 시드 채널이 주력이다.
- 해시태그 쇼츠 피드는 채널·길이를 안 줘서 쓰지 않는다. 인스타·페이스북은 로그인 벽이라 「못 잼」으로만 적는다. 틱톡은 댓글을 모으지 않는다.
- 유튜브 RSS는 같은 채널에서도 회차마다 404·500을 냈다(몇십 번 부른 뒤 더 잦았다, 10-24부터는 대부분). Data API 길에서는 RSS를 부르지 않는다 — yt-dlp 길로 돌 때 RSS가 막히면 새 편 날짜를 영상 정보로 확인해야 해 「날짜를 확인 못 한 후보」가 늘 수 있다.
- 쇼츠 탭 조회는 「26만」 같은 반올림 수다(RSS·영상 정보는 정확한 수). 댓글을 받으면 yt-dlp가 댓글 수를 받은 개수로 덮어서, 전체 댓글 수는 `--verbose` 줄에서 읽는다.
- 회사 서버(GCE)에서 돌리면 유튜브 영상 정보의 길이가 빈다 — 서버 IP의 재생 응답이 봇 확인에 걸린다(10-25 실측, 탭·검색·댓글·조회·날짜는 됨). 틱톡은 curl_cffi가 든 판이어야 서버에서 읽힌다. 그래서 서버로 옮기지 않고 유튜브 숫자를 Data API로 읽게 바꿨다(10-25) — 실측과 까닭은 [서버](서버.md).
- Data API 길이는 yt-dlp보다 1초 길게(올림) 온다 — 3분 검사는 API 길이에 1초를 봐준다. 한 회차에 어림 300단위(10-25 293번)를 쓰고, LAB 프로젝트 하루 한도 10,000단위를 업로드와 나눠 쓴다.
- 틱톡 공개 프로필은 흉내내기를 써도 회차마다 몇 곳이 「Unable to extract secondary user ID」로 실패한다(10-25 27곳 중 6곳, 같은 계정이 다른 회차엔 읽힌다) — 「실패」로 적고 다음 회차에 다시 읽는다.
