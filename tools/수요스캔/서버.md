# 수요 스캔 · 서버에서 미리 돌리기 — 10-25 실측과 결론

> **결론(10-25):** 서버에서도 길이 하나만 빼고 읽힌다. 다만 서버로 옮기지 않고 **PC에서 유튜브 숫자를 YouTube Data API로 읽어 호출 수를 줄이는 쪽**을 권한다 — 설계 검토(Fable)의 제안을 같은 날 실측으로 확인했다. 서버 안은 아래 「서버 안」에 검토 지적을 반영한 꼴로 남긴다. 서버 주소·키는 적지 않는다(접속은 [`scan-read.cjs`](../argon-schedules/scan-read.cjs)의 주소 조회·고정 호스트 키 방식). 쓰는 법은 [README](README.md).

## 왜

10-19 유호님은 느린 웹 서치를 PC·Claude 세션 밖에서, PC가 꺼져 있어도 돌리려고 서버 수집 셋을 더했다([Argon 예약 운영](../argon-schedules/README.md) 「2026-10-25」). 지금 느린 서치는 매일 19:30 「수요 스캔 + 기획 후보」 1단계의 `스캔.js 전부`(yt-dlp)다 — PC에서 10-23 449번·18.1분, 10-24 369번·18.6분. 같은 회선에서 큰 수집을 돌리면 Gemini 웹이 구글 「sorry」로 막힌 적도 있다([수집 노트](../../docs/현장노트/수집_yt-dlp.md)).

standby(`synk-company-2`, GCE 서울, e2-medium, Debian 12)에서 로그인·쿠키 없이 읽기만, 호출 사이 2.5~8초. 모두 54번이고 403·429는 0번이었다. 서버에 둔 임시 폴더는 끝나고 지웠다.

- 걸린 시간(중앙값): 탭 2.6초(PC 1.0) · 영상 3.2초(2.1) · 검색 12.6초(2.5, 한 번) · 틱톡 9.4초(3.0). 단독 실행판 한 파일 꼴은 부를 때마다 몸을 풀어 시작에 1.5초, 풀어 둔 꼴(`yt-dlp_linux.zip`)은 0.8초.
- 스캔 도구를 그대로 작게(lab-en 시드 6 + 찾은 채널 2 · 검색 1 · 틱톡 3 · `--상세 10 --기준선 0 --누적안씀`): 32번 117초, 막힘 0, 새 튄 편 1편 — 그 길이가 「못 잼」. 도구는 `--no-warnings`로 부르므로 봇 확인이 안 보이고 「됨」으로 센다.
- **같은 날 PC에서 Data API:** `node tools/평소배수.js <채널 둘> --편수 30 --json`이 2.95초에 채널마다 쇼츠 30편을 줬다 — 쇼츠 목록(UUSH)이 API로 읽히고, 편마다 정확한 조회 · 올린 시각 · 길이가 있다(서버 탭의 반올림 14,000 · 290,000 · 45,000이 API로 14,478 · 290,885 · 45,253).
- **못 잰 것:** 네 브랜드 전체 회차(400번 안팎)는 서버에서 돌리지 못했다 — 서버에 떼어 돌리는 명령을 이 세션의 권한 판정기가 「원격 셸 쓰기」로 막았다. 많이 부르면 막힘이 느는지는 모른다. 다른 회사 VM(라디오 e2-micro 등)은 방송에 부담을 줄 수 있어 재지 않았다.

## 판정 — 서버에서도 길이 하나만 빼고 된다. 그래도 옮기지 않는다

- **까닭:** 유튜브가 이 서버 IP의 재생 응답(player)에만 봇 확인을 건다. 탭 · 검색 · 댓글 · 첫 화면 자료는 막지 않는다. [PO 토큰 안내](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide)에서 토큰이 필요 없다는 `tv` · `web_embedded` · `android_vr`도 막혔으니 토큰이 아니라 IP 평판이다. 토큰 제공 플러그인(bgutil)이 이런 IP에서 봇 확인을 비킨 적이 있다고 적혀 있지만 「IP 기반 로그인 제한은 못 비킨다」고도 적혀 있고, 회사 서버에 Docker나 Node 서버와 플러그인을 더 깔아야 해서 쓰지 않는다.
- **옮겨도 얻는 게 적다:** 18분의 바닥은 「호출 수 × 2.5초 간격」(10-24 369번)이라 서버에서도 25분 안팎이다. 19:30 작업 자체가 PC 예약이라 「PC가 꺼져 있어도」도 얻지 못한다 — 서버가 17:30에 모아도 PC가 켜져야 기획이 나온다. 그 위에 서버 사용자 · systemd · 자료 받기 · node · yt-dlp 판 고정 · SSH 읽기 · 받은 자료 검증 · GPT 백엔드 검수 · 서버 설치 권한이 얹힌다.
- **호출 수를 줄이면 PC에서 끝난다:** 아래 길이면 1단계가 어림 4~5분이고, 반올림 조회 · RSS 실패 · 「날짜 모름」 · 「보충」이 함께 사라진다.

## 권하는 길 — PC에서 유튜브 숫자는 Data API로

예약 지시문은 바뀌지 않는다(명령이 그대로 `스캔.js 전부`). 서버를 쓰지 않으니 새 기계 · 새 비밀값 · 서버 검수 길이 없다 — 내부 도구라 [운영 원칙](../../docs/AI_운영원칙.md#review-rules) ④대로 시험과 자기 점검으로 끝난다.

- **API로 바꾸는 것**(인증은 `tools/평소배수.js` `토큰()` — LAB YouTube 자격, 읽기만):
  - 쇼츠 탭 + RSS → `playlistItems.list`(쇼츠 목록 UUSH, 30편, 1단위). 최신순이라 지금 탭과 같은 30편이다.
  - 영상 정보 → `videos.list`(snippet · statistics · contentDetails, 50편에 1단위). 정확한 조회 · 좋아요 · 댓글 수 · 길이 · 올린 시각을 한 번에 — 후보만이 아니라 기준선 30편 모두.
  - 구독 → `channels.list`(50곳에 1단위). 핸들만 적은 시드는 `forHandle`로 한 번 ID를 찾고 누적에 둔다(지금도 ID를 둔다).
  - 쌓인 「보충」(10-24 회차 뒤 누적에 lab-en 54 · synkbrief 48 · yuhobuilds 53, 모두 155편 — 상세 상한 40을 넘친 편)과 「다시볼」(96편)의 날짜 · 길이도 첫 회차의 `videos.list` 몇 번으로 채운다. 3분 넘는 편은 지금 5단계처럼 튄편 칸을 보고한 편으로 남기고 「보충」만 지운 뒤 「고침」으로 적는다 — 판정은 `상세반영` 한 길로.
- **yt-dlp에 남기는 것:** 검색(하루 24번 — `search.list`는 한 번에 100단위라 비싸다), 틱톡(27곳), 댓글 본문(브랜드마다 5편 — `commentThreads.list` 1단위로 바꿔도 된다. 쓴 사람 칸은 지금처럼 버린다). 틱톡은 curl_cffi가 들어간 판(`pip install curl_cffi` 또는 공식 단독 실행판)으로 부른다 — 10-24 PC의 8번 실패가 같은 오류다.
- **한도:** 하루 어림 350~450단위(채널 160~200곳 × 2 + 구독 · 댓글). 프로젝트 기본 한도 10,000 안이지만 LAB 업로드와 같은 프로젝트 몫인지 만들 때 한 번 본다.
- **API가 안 될 때:** 토큰 · 한도 오류면 그 회차의 유튜브는 지금 yt-dlp 길로 돌리고 요약 「못 잰 곳」에 적는다. 지금 코드는 그대로 대체 길로 남긴다.
- **시간:** API 몫 1~2분(호출 간격이 필요 없다) + yt-dlp 50~80번 × 3초 ≈ 4~5분. 지금 18~19분.
- **바꾸는 첫날:** 같은 누적의 사본 둘로 옛 길과 새 길을 `--누적안씀`으로 나란히 돌려 새 튄 편 · 못 잼 · 날짜 모름 수를 맞춰 본다. 반올림이 아니라 정확한 수로 판정하니 턱걸이 편 몇은 달라지는 게 맞다.
- **바꿀 파일:** `tools/수요스캔/수요수집.js`(API 부르개 · `실패갈래`의 「Unable to extract secondary user ID」는 「없음」이 아니라 「실패」), `스캔.js`(유튜브 채널 읽기를 API로 · 실패 때 옛 길), `수요판정.js`(필요하면 API 숫자를 정확한 수로 넣는 칸), `tests/수요스캔.test.js`(가짜 API 응답 · 한도 오류 때 옛 길 · 보충 채우기 · 3분 고침), `README.md`.

## 서버 안 — 다시 꺼낼 때(10-25 설계, 만들지 않음)

꺼낼 까닭: PC 회선의 유튜브 부담을 아예 빼야 하거나, API 길이 막혀 PC가 다시 18분이 될 때. 그때는 서버가 17:30에 `스캔.js 전부`를 돌리고, PC 19:30 1단계는 `스캔.js 전부 --서버먼저`로 서버 결과를 받아 길이만 Data API로 채우고, 못 쓰면 지금처럼 PC에서 돈다(지시문 한 낱말 — 유호님 승인 뒤, 결정 10-23 「매일 게시 · 이해 관문」). 설계 검토(Fable 10-25)에서 나온 것을 지킨다.

- **서버 짜임:** 사용자 `synk-demand-scan`(sudo · docker 없음), 상태 `/var/lib/synk-demand-scan`(0700). 검수한 판의 스캔 코드를 `app/tools/수요스캔/*.js` · `app/tools/lib/*.js` 꼴로 둔다(상대 경로 require). 설정 · 누적만 공개 저장소 origin/master에서 받으므로 `스캔.js`에 `--설정 <폴더>`를 더한다(지금은 코드 옆 `설정/`만 읽어, 없으면 매 회차 종료 1이다). 받기 실패는 회차 실패다 — 저장소가 비공개로 돌아가면 서버에만 둔 읽기 전용 deploy key로 받는다.
- **회차 스크립트:** 폴더 이름은 `TZ=Asia/Seoul date +%F`. `base.json`에는 git 목록이 아니라 회차 폴더에 실제로 놓인 누적 넷의 sha256과 브랜드마다 「첫 스캔 아님」을 적는다 — 한 파일이 빠지면 빈 누적으로 창 안 튄 편을 다 새로 내기 때문이다. `status.json`은 `trap EXIT`로 늘 쓴다(시간 초과 · 메모리 초과로 죽어도). 서버 모드는 5단계 보충을 건너뛴다(길이가 영영 안 온다). HA 역할이 standby가 아니면 건너뛴다. node는 아르곤 검증용 v24.21.0을 복사하고, yt-dlp는 `yt-dlp_linux.zip`의 기대 sha256을 저장소 설치 스크립트에 박아 두고 판 올리기 때 탭 · 영상 · 틱톡 한 번씩 연기 시험을 돌린다 — 유튜브 변경으로 몇 주마다 올려야 하는 반복 일이다.
- **systemd:** `NoNewPrivileges` · `ProtectSystem=strict` · `ProtectHome` · `PrivateTmp` · `ReadWritePaths=/var/lib/synk-demand-scan` · 회사 자료와 아르곤 폴더 `InaccessiblePaths` · `CapabilityBoundingSet=` · `Nice=10` · `CPUQuota=80%` · `MemoryMax=1G` · `RuntimeMaxSec=75min`, timer 17:30 · `Persistent=false`. 이름 `synk-demand-scan`은 HA 단계가 멈추는 이름 낱말(backup · restore · release · deploy 등)을 피한다.
- **PC가 받는 조건(하나라도 어긋나면 PC에서 돈다):** 오늘 회차 · 종료 0 · 멈춘 서비스 없음 — 스캔은 한 곳만 읽어도 종료 0이라(`스캔.js:610`) 그것만으론 안 된다. 브랜드마다 유튜브 읽음/대상 0.9 이상 · 막힘 몇 번 이하 · 검색어를 돌렸으면 결과가 있음. base 누적 sha256 = PC가 막 받은 origin/master = 공용 작업본 파일. 판정 코드 셋(`스캔.js` · `수요수집.js` · `수요판정.js`)이 PC 자기 파일과 같음. 오늘 폴더가 아직 없음(`mkdirSync`·기록 쓰기보다 먼저 본다).
- **PC가 받는 법:** `--서버먼저` 분기 전체를 누적 잠금(`잠그기`) 안에서 돈다. `scan-read.cjs`는 그 분기 안에서만 require한다(파일 머리에서 부르면 다섯 파일만 둔 서버 사본이 로드부터 실패). tar는 셸로 풀지 않고 항목을 읽어 허용 목록(요약 · 기록 · 원자료/<브랜드> · 댓글/<브랜드>/<11자> · 누적/수요_<브랜드> · 서버/*.json) · 일반 파일 · 크기 상한(하루 결과가 1.5MB 안팎이니 20MB)만 받는다. 누적은 엄격한 꼴(채널 `^UC[\w-]{22}$` · 편 `^[\w-]{11}$` · 틱톡 `^\d{6,}$` · 값은 숫자 · 날짜 · 핸들)을 지나야 한다 — 지금 `누적검사`는 판 · 브랜드 · 칸 종류만 보고, 받은 누적은 공개 저장소에 커밋된다. 임시 폴더에서 검증 · 길이 채우기를 끝내고 요약을 오늘 폴더에 둔 뒤 **맨 마지막에** 누적을 쓴다(GB1과 같은 차례). 채우기가 실패한 날은 길이 없는 줄에 「쇼츠 확인 전」을 붙인다.
- **들이는 차례:** 만들기 · 시험(서버 결과 수락 뒤 같은 날 다시 돌리기 · API 실패 때 보충 남음 · 3분 고침 · 다섯 파일만으로 로드 · tar 허용 목록) → GPT 백엔드 검수 → 서버 설치(서버 쓰기가 권한 판정기에 막히니 설치 명령의 허용 줄이나 유호님 터미널 한 번을 먼저 받는다) → 3~5일 그림자(받아서 PC 회차와 새 튄 편 · 못 잼 · 검색 결과 수만 대조하고 PC 결과를 쓴다) → 지시문 고침 → 「서버 결과 씀/버림(까닭)」 셈을 트랙에 남긴다(IP가 바뀌거나 SSH가 막혀 늘 PC로만 도는지 보이게).
