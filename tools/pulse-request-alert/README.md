# PULSE 새 의뢰 텔레그램 알림

손님이 PULSE 의뢰서를 보내면 1분 안에 유호님 텔레그램으로 「새 의뢰」 한 줄이 간다. 회사 주 노드(`synk-company-1`)의 systemd 타이머가 보내므로 PC가 꺼져 있어도 간다(2026-11-14).

## 왜 서버로 옮겼나

이 알림은 원래 Windows 예약 작업 「SYNK PULSE 의뢰 확인」(10분마다, `tools/크레딧작업/PULSE의뢰확인.js`)이 보냈다. 그 작업은 PC에서만 돌아서 PC가 꺼져 있으면 알림이 늦었다. 의뢰서는 처음부터 회사 DB에 저장되므로 같은 서버가 바로 읽고 알리는 편이 맞다. PC 작업은 의뢰서 받기, 1차 확인 메모, 손님이 적은 주소 읽기만 계속하고, 「새 의뢰」 한 줄은 다시 보내지 않는다. 메모를 남겼다는 줄과 1차 확인을 멈췄다는 줄은 지금처럼 PC 작업이 보낸다.

## 무엇을 읽고 무엇을 보내나

- 회사 DB(`company.sqlite`)를 읽기만 한다. 앱 컨테이너가 돌고 있고 `-wal` · `-shm`이 이미 있을 때만 읽기 전용(`mode=ro` · `query_only`)으로 연다. 읽는 것은 `clientProjects` 문서의 다섯 칸(의뢰 번호, 상태, 접수 시각, 단계, 제목)뿐이다. 연락처, 답, 파일, 인증 표는 읽지 않는다.
- 의뢰 번호마다 한 번만 보낸다. 접수한 지 72시간이 지난 의뢰와 보관(archived)된 의뢰는 보내지 않는다.
- 글은 `PULSE 새 의뢰 P-1114-AB12 · 제목` 한 줄과 안내 한 줄이다. 링크와 손님 연락처는 넣지 않는다. 제목(손님이 적은 제품 · 브랜드 이름)에 숫자가 일곱 개 이상이거나 주소 · 메일 꼴이 하나라도 있으면 제목을 통째로 빼고 의뢰 번호만 보낸다. 전화번호는 어느 나라 꼴이든 숫자가 일곱 개를 넘기 때문이다. 처음에는 전화번호 꼴을 찾아 지웠는데, 구분자와 나라마다 새어 나가 이렇게 바꿨다.
- 보내지 못하면 장부에 적지 않고 다음 회차(1분 뒤)에 다시 보낸다. 한 회차에 다섯 건까지 보내고, 한 건이라도 실패하면 그 회차는 거기서 멈춘다. 한 건을 보낼 때마다 장부를 바로 쓰므로, 회차가 중간에 끊겨도 보낸 번호를 다시 보내지 않는다. 한 회차는 40초가 지나면 새 보내기를 시작하지 않는다(서비스 제한 90초 안에서 끝나게). 그래도 첫 건은 늘 시도한다.
- 의뢰 목록을 20분 넘게 못 읽으면(앱이 멈춤, DB를 못 엶 따위) 그 사실을 한 번 알리고, 다시 읽히면 한 번 더 알린다. 배포 때 앱이 몇 분 멈추는 것은 알리지 않는다.
- 손님에게는 아무것도 보내지 않는다. 운영 데이터는 바꾸지 않는다. 서버 장부에는 의뢰 번호와 시각만 남는다.
- 봇은 헤르메스와 같은 봇이고, 보내는 곳은 유호님 개인 대화(`6017495834`)다. 서버는 `sendMessage`만 부르므로 헤르메스가 메시지를 받는 일과 겹치지 않는다.

## 설치 위치

| 자리 | 무엇 |
|---|---|
| `/opt/synk-pulse-request-alert/alert.py` | 이 폴더의 `alert.py`(root 0644) |
| `/etc/systemd/system/synk-pulse-request-alert.service` · `.timer` | 매분 20초에 한 번 도는 단위 |
| `/etc/synk-pulse-request-alert/telegram.env` | 봇 열쇠와 대화방 번호(root 전용 0600). 저장소에는 없다 |
| `/var/lib/synk-pulse-request-alert/` | `state.json`(알린 번호), `latest.json`(마지막 회차 요약), 잠금 |

## 명령

PC의 저장소에서 부른다. 접속은 `tools/lib/작업실읽기.cjs`와 같은 고정 서버 신원(Compute 메타데이터와 고정 호스트 키)이다.

```bash
node tools/pulse-request-alert/install.cjs
```

미리 보기다. 깔 파일의 해시, PC 장부의 번호 수, 헤르메스 열쇠가 있는지만 보이고 원격에는 닿지 않는다.

처음 깔 때는 아래 순서로 한다. 이렇게 하면 서버와 PC가 같은 의뢰를 두 번 알리지 않고, 그 사이 들어온 의뢰도 빠지지 않는다.

1. `--설치 --타이머끔`으로 파일 · 단위 · 열쇠만 넣는다. 타이머는 끈 채로 두고 장부도 열지 않는다.
2. `--시험`으로 시험 한 줄이 오는지 본다.
3. PC 작업에서 「새 의뢰」 알림을 뺀 판을 올리고, 운영 사본이 따라갔는지 `node tools/운영사본.js`로 본다.
4. `--설치`로 타이머를 켠다. 이때 PC 장부로 서버 장부를 연다. PC가 알림을 멈춘 뒤 들어온 의뢰는 PC 장부에 없으므로, 서버가 첫 회차에 알린다.

```bash
node tools/pulse-request-alert/install.cjs --설치 --타이머끔
```

```bash
node tools/pulse-request-alert/install.cjs --설치
```

원격에 쓴다. 파일과 단위를 넣고, 열쇠 파일은 없을 때만 헤르메스 설정에서 옮겨 쓴다. 서버 장부가 없으면 PC 장부(`output/크레딧작업/PULSE의뢰확인/알린의뢰.json`, 이미 알린 번호)로 연다. 그다음 지금 알릴 번호를 미리 보고 타이머를 켠다. 열쇠는 SSH 표준 입력으로만 넘기고 화면이나 인자에 찍지 않는다.

```bash
node tools/pulse-request-alert/install.cjs --시험
```

서버에서 시험 한 줄(「PULSE 새 의뢰 알림 시험이에요…」)을 보낸다. 의뢰나 장부와는 상관없다.

```bash
node tools/pulse-request-alert/install.cjs --상태
```

읽기만 한다. 타이머 상태, 깔린 파일이 저장소와 같은지, 열쇠 파일 권한, 마지막 회차, 지금 알릴 번호를 보인다.

```bash
node tools/pulse-request-alert/install.cjs --끄기
```

타이머만 끈다. 파일, 장부, 열쇠는 남긴다. 다시 켜려면 `--설치`를 부른다. 끈 동안에는 「새 의뢰」 알림이 아무 데서도 가지 않으므로, 오래 끌 때는 PC 작업의 옛 알림을 되살려야 한다(`git log -- tools/크레딧작업/PULSE의뢰확인.js`의 11-14 커밋을 되돌린다).

## 알아 둘 것

- 헤르메스 봇 열쇠를 바꾸면 서버 열쇠 파일도 바꿔야 한다: `node tools/pulse-request-alert/install.cjs --설치 --열쇠바꿈`. 바꾸지 않으면 보내기가 401로 막히고, 그동안 「새 의뢰」 알림이 가지 않는다(헤르메스도 같은 열쇠라 함께 알아챌 수 있다).
- 서버 장부가 없거나 깨지면 다시 연 시각을 적은 빈 장부로 시작한다. 그 시각 전에 접수된 의뢰는 보내지 않고 알린 것으로 적는다. 옛 의뢰를 한꺼번에 다시 보내지 않으려는 것이다. 그 시각 뒤에 들어온 의뢰는 보통처럼 보낸다. 장부를 잃은 순간과 다시 연 순간 사이(1분 안)에 들어온 의뢰는 알림이 빠질 수 있다. 목록을 못 읽는 동안에도 20분 장애 알림은 돈다.
- 설치할 때 PC 장부가 없거나 깨졌거나 번호가 하나도 없으면 서버 장부를 PC 장부로 열지 않고, 위 「다시 열기」로 둔다. `--장부`로 준 파일을 못 읽으면 설치를 멈춘다. PC 장부로 서버 장부를 열지 못하면 타이머를 켜지 않는다.
- 지금은 HA가 쉬고 있어 주 노드에만 깔았다. HA를 다시 켜서 예비 노드(`synk-company-2`)가 쓰기 노드가 될 수 있게 되면, 이 알림도 그 노드에 깔고 장부를 어떻게 나눌지 정해야 한다. 그러지 않으면 예비 노드가 일하는 동안 주 노드가 「20분째 읽지 못하고 있어요」를 한 번 알린 뒤 조용해진다.
- 회사 릴리스가 앱 컨테이너 이름(`synk-company-company-1`)이나 DB 꼴(`documents` 표)을 바꾸면 이 알림이 읽지 못한다. 그때도 20분 뒤 텔레그램으로 한 번 알린다.

## 시험

```bash
node --test tests/pulse-request-alert.test.js
```

파이썬 시험(`alert.test.py` — 임시 SQLite, 가짜 docker, 가짜 텔레그램)과 설치 도구의 짐 싸기 · 열쇠 숨기기를 함께 본다. 서버, 텔레그램, 헤르메스에는 닿지 않는다.
