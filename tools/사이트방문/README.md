# synk.im 방문자 분석 모으기

유호님이 PC 앱의 솔리오에서 「지금 사이트가 일을 하고 있나」를 한눈에 보게 하는 숫자를 하루 한 번 모은다. 설계는 [설계](../../docs/마케팅/사이트방문_분석/설계.md), 시작할 때의 실제 값은 [현황](../../docs/마케팅/사이트방문_분석/현황_20261117.md)에 있다.

## 쓰는 법

```
node tools/사이트방문/모으기.js 돌리기 [--강제] [--AI강제] [--건너뛰기 방문,목적,검색,AI]
node tools/사이트방문/모으기.js 보기
node tools/사이트방문/모으기.js AI재기 [--질문 K01,B01] [--서비스 Claude,Gemini] [--시험]
node tools/사이트방문/모으기.js 보는계정 [--받기 <번호> | --버리기]
node tools/사이트방문/모으기.js 급증 [--풀기]
node tools/사이트방문/브라우저확인.mjs <SYNK-website의 dist 폴더>
node --test tests/사이트방문.test.js
```

- `돌리기`는 23시간 안에 돌았으면 건너뛴다. 다른 `돌리기`가 돌고 있으면(2시간 안의 잠금) 건너뛴다.
- `AI재기 --시험`은 보관함에 원문을 남기지 않고 센 값만 찍는다. 장부에는 어느 쪽도 남기지 않는다.
- `보는계정`은 솔리오에서 「방문자 분석」을 볼 SYNK 계정과, PC 앱이 남긴 물은 계정(`viewer-pending.json`, 계정마다 한 줄, 최근 5개)의 이름 · 시각 · 번호를 보인다. 유호님께 이름과 시각을 보여 유호님 계정이 맞다고 하시면 그 줄의 번호를 붙여 `--받기 <번호>`로 `viewers.json`에 옮긴다. 번호가 목록에 없으면 옮기지 않는다. 받으면 대기 파일은 지워지고, `--버리기`는 대기 파일만 지운다. `viewers.json`이 없거나 깨졌으면 아무에게도 보이지 않고, 깨진 파일은 덮어쓰지 않고 멈춘다.
- 방문 기록 시트의 줄은 칸마다 허용 목록으로 다시 거른다(공개 설문지라 누구나 줄을 넣을 수 있다). 목록 밖 줄은 버린 수만 요약에 남는다. 어느 날의 줄 수가 다른 13일의 가운데값보다 크게 뛰면(5배와 20줄), 솔리오가 그것을 먼저 말한다. 처음 본 날과 그때의 평소 값은 장부의 `급증.json`에 남아, 가짜 줄이 여러 날 이어져도 `급증 --풀기`로 풀기 전까지 결론 첫 문장에 남는다. `급증`만 부르면 남은 급증을 보인다.
- `브라우저확인.mjs`는 빌드한 쪽을 synk.im 이름으로 로컬에서 열어, 바깥으로 아무것도 보내지 않고 기록 줄을 확인한다(이 PC는 `SYNK_PLAYWRIGHT_CHROMIUM`에 브라우저 경로를 준다).

## 단계와 받는 곳

| 단계 | 읽는 것 | 막히면 |
|---|---|---|
| 방문 기록 | 구글 설문지 「synk.im 방문 기록(익명)」의 연결 시트(사이트 전체의 익명 세기) | `설정.json`의 시트가 null이면 「측정 전」, 열쇠가 없으면 「권한을 기다립니다」 |
| 홈 방문 목적 | 구글 설문지 「synk.im 방문 목적(익명)」의 연결 시트(홈 「어떤 일로 오셨어요?」) | 위와 같다 |
| 서치콘솔 | `https://synk.im/` 속성(unmet23 계정)의 웹 검색 실적. 끝은 오늘에서 3일 앞, 지난 28일과 그 앞 28일 | 위와 같다 |
| 네이버 | `설정.json`의 상태 글(서치어드바이저는 숫자를 내보내는 API가 없다) | — |
| AI 재기 | 6.5일마다 한 회차. 질문 세트는 보관함 `PULSE_마케팅_내부검증/AI검색_기준선/질문세트_v1.json` | 서비스가 연달아 세 번 실패하거나 429면 그 서비스만 멈춘다 |

한 단계가 막혀도 나머지는 돈다. 막힌 칸은 3일 안의 앞 값이 있으면 「오늘은 읽지 못해 M월 D일 값을 보입니다.」와 함께 이어 쓴다.

## AI 재기의 두 서비스

- **Claude:** 웹 검색 도구(기본 판 `web_search_20250305`)를 켠 `claude-opus-5-5`를 결제 수단 없는 조직의 무료 크레딧 키로 부른다(`tools/lib/클로드키.js`). 새 판(`web_search_20260209`)은 답 글에 인용을 달지 않아 쓰지 않는다(11-17 실측). 거절되면 다른 모델로 넘기지 않고 「답 없음」으로 센다.
- **Gemini:** 구독 통로(`tools/lib/제미나이구독호출.js`, agy · Ultra 계정)로 `gemini-3.8-flash`에 묻는다. 그 통로는 도구 없이 답하게 부르므로 웹 검색 없이 기억으로 답한 값이다. 무료 API 키는 구글 검색 근거를 켜면 429로 막혔고(11-17 실측) 유료 키는 만들지 않기로 했다(11-15 결정).
- 브라우저로 ChatGPT, 구글, 네이버의 화면을 자동으로 묻지 않는다. OpenAI 이용약관은 출력의 자동 추출을 막고, 구글은 robots.txt에서 `/search`를 막는다. 11-16 기준선처럼 브라우저로 재는 회차는 사람이 필요할 때 세션에서 한다.
- 세는 법은 11-16 기준선과 같다. 일반 질문 답의 SYNK 언급, 답이 단 출처의 synk.im(인용), 브랜드 질문의 synk.im 인용이다. 답이 200바이트 아래거나 거절되면 「답 없음」으로 분모에서 뺀다. 재는 길이 달라 11-16 기준선의 숫자와 직접 견주지 않는다.

## 자리

- 요약(솔리오가 읽음): `%LOCALAPPDATA%\synk\site-visits\summary.json`(바꾸려면 `SYNK_SITE_VISITS_SUMMARY`). 꼴은 `요약.js` 머리 주석에 있다.
- 장부(git 밖): `<공용 작업본>/.tmp/사이트방문/` — `하루.jsonl`(날마다 숫자 한 줄), `AI재기.jsonl`(회차마다 센 값), `마지막.json`, `돌는중.json`(잠금).
- AI 답 원문: 비공개 보관함 `PULSE_마케팅_내부검증/AI검색_기준선/정기/<날짜>/<서비스>/<질문>.txt`.
- 볼 계정: 요약과 같은 폴더의 `viewers.json`, PC 앱이 남기는 `viewer-pending.json`(저장소 밖).
- 구글 열쇠: `~/SYNK_보안/구글_사이트방문_읽기.json`(서비스 계정, 읽기 전용, 값은 출력하지 않는다. 바꾸려면 `SYNK_SITE_VISITS_GOOGLE_KEY`).

## 안전

- 요약과 장부에는 집계 숫자와 상태만 둔다. 방문 기록 시트에는 사람을 잇는 값이 없다(사이트 쪽 세기 코드가 보내지 않는다).
- 웹 문의 양식의 응답 시트는 개인정보가 들어 있어 읽지 않는다.
