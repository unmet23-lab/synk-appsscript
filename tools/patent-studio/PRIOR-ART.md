# 근거 작업실: 독립 선행 반론과 공정한 비교 설계

2026-09-11 KST · 선행기술 상세 검토 · 대상: 판단 코어 0.4.0. 이 문서는 기술 구성과 근거의 강도를 검토한다. 출원 청구범위 확정이나 등록 가능성 수치의 산정은 하지 않는다.

**가장 강한 반론은 이미 알려진 음성 튜터의 도움 처리·녹음 품질 관리에, 목적별 조건 검사와 의존성 갱신을 붙인 통상적 결합이라는 주장이다.** 추가 조사에서 도움과 다음 질문 선택이 맞물리는 특허, 음성 따라 읽기와 지속 지식을 구분하는 논문, 학습 중 얻은 녹음을 별도 품질 조건으로 재사용하는 특허를 확인했다. 따라서 ‘관측이 상태를 바꾼다’, ‘힌트를 평가에 반영한다’, ‘판단이 다음 행동을 고르고 행동이 판단을 갱신한다’는 설명만으로 차이를 주장하기 어렵다.

이번에 읽은 단일 자료에서 아래 C1~C6의 **정확한 관계 전체**를 확인하지는 못했다. 이것은 신규성·진보성 충족을 확인했다는 뜻이 아니다. 남는 검토 후보는 **동일 발화의 용도×능력×평가대상발화별 자격 셀, 복수 해석 효과값의 일치, 대상 발화 보존 여부에 따른 확인행동 적격성, 늦은 능력별 답 노출 사건에 따른 특정 기여 철회와 다른 용도 유지**를 연결하는 구체 처리다.

## 1. 검토 범위와 실제 원천

## 2. C1~C6: 독립항에서 검토할 필수 관계

‘자격’은 어떤 기록을 특정 용도의 근거로 사용할 조건을 충족했는지다. ‘셀’은 그 조건을 따로 판단하는 한 칸이며, 일반적인 지식 추적 모델의 내부 숫자와 같다는 뜻이 아니다.

| 관계 | 필요한 입력→처리→출력 | 현재 코드의 근거와 설명 한계 |
|---|---|---|
| C1. 발생 사건과 수신 사건의 구분 | 원음 참조·발화 식별자·발화 구간 또는 확인된 상대 순서·도움 사건을 연결. 같은 파일이어도 다른 발화 사건일 수 있음 | `captureInterval`, `confirmPerformanceTime`, `applyEvent`. 파일 업로드 시각을 발화 시각으로 자동 치환하지 않음. 이 기록 자체가 외부의 모든 사건이나 정확한 절대시각을 인증하는 것은 아님 |
| C2. 복수 해석과 관련 불명 유지 | 발화별 지원 해석 집합과 전사·의미·답 노출의 관련 미확인 범위를 보존 | `alternativesFrom`, `unknownAffects`, `makeCell`. 사람 확인과 제한된 문장 규칙에 의존. 모든 자연어 해석의 자동 발견·완전성 검사는 구현되어 있지 않음 |
| C3. 용도×능력×평가대상발화별 부분 인정 | 비어 있지 않은 해석 집합에서 효과값이 같고, 관련 불명과 용도별 자격 문제가 없는 셀만 반영 | `makeCell` 260행, `projectWithPolicy`. 원음–전사 자격과 수행 자격을 별도 계산. 현 구현은 발화·능력 공통 조건 검사 후 각 대안의 효과값을 비교하며 임의의 해석별 자격 규칙 언어는 아님 |
| C4. 목표 셀에 적합한 확인행동 선택 | 보류 이유와 대상 발화에 연결되는 행동만 후보로 삼고, 새 수행을 얻는 행동을 원래 수행의 직접 확인에서 제외 | `observationCandidates` 333행, `planObservations` 365행. 현재는 고정 후보·이유 코드 연결·가정 비용 오름차순. 학습된 정보이득 최적화나 모든 행동의 자동 설계는 아님 |
| C5. 예상과 실제, 재해석과 새 수행 구분 | 원음 재청취는 기존 발화의 해석 변경, 모범 답안 뒤 응답은 별도 발화 사건으로 수신. 예상 분기는 실제 근거로 승격하지 않음 | `review-original`, `review-response`, `help-presented`, `response-added`, `earlierBoundary`. 같은 정답이어도 평가대상발화가 달라지는 문제를 처리 |
| C6. 실제 사건에 의한 자격 재판정·선택 철회 | 늦은 도움 사건의 능력 범위와 발화 선후·겹침을 계산해 종전 반영을 철회·보류하고 영향 없는 용도는 유지. 전후 기여와 원인 저장 | `timingFor` 226행, `makeCell`, `projection.cjs`의 `buildLedgerEntry`. 현재 작업실 셀과 원장의 기여 변화. 운영 학생 DB·장기 숙련 모델에 대한 실제 역전파는 검증 범위 밖 |

핵심 연결은 **C3이 C4의 대상·허용 조건을 제공하고 → C4의 실행 결과를 C5에서 별도로 수신하고 → C1의 발생 관계와 C2의 불명을 적용하여 C3을 다시 계산하고 → C6에서 달라진 기여를 처리하는 것**이다. 기능 여섯 개의 병렬 나열과는 구분해야 한다.

## 4. 추가 엄선 5건: 더 가까운 반론

### P6. 음성 도움과 수행·지식을 함께 모델링한 연구

Beck·Chang·Mostow·Corbett, **Does Help Help? Introducing the Bayesian Evaluation and Assessment Methodology** (ITS 2008), pp.383~394. [저자 제공 원문](https://www.cs.cmu.edu/~kkchang/paper/BeckChangMostowCorbett.2008.ITS.DoesHelpHelp.pdf).

- 읽은 위치: §1~3, pp.384~389, Fig.3와 Eq.3. 음성 인식으로 어린이 낭독을 평가하는 Reading Tutor에서 도움의 **현재 수행에 대한 임시 지원**과 **뒤 시점까지 이어지는 지식 변화**를 구분한다. 답 발음을 듣고 즉시 따라 하는 성공을 지속 학습으로 계산하는 문제를 직접 지적한다.
- 반론: ‘모범 답 뒤 정답을 원래 실력으로 보지 않는다’, ‘도움과 수행을 시간에 따라 함께 다룬다’는 원리는 이 연구와 가깝다. 일반 쓰기 동적 평가보다 음성이라는 점에서도 가까운 추가 자료다.
- 차이 후보: 이 연구의 잠재 지식 확률 추정과, C3의 **특정 발화 자료를 특정 용도에 쓸 자격**은 출력 의미가 다르다. 읽은 범위에서는 복수 전사 효과값의 공통성, 자료용 자격 유지와 특정 과거 수행 기여 철회, 늦은 사건으로 그 자격을 되돌리는 C6까지 확인 못 했다. 출력 의미가 다르다는 사실만으로 결합의 비자명성이 입증되지는 않는다.

### P7. 판단→도움 선택→실제 도움에 따른 갱신을 청구한 특허

**US10943497B2**, *Personalized e-learning using a deep-learning-based knowledge tracing and hint-taking propensity model* (Adobe). [청구항·설명 원문](https://patents.google.com/patent/US10943497B2/en).

- 읽은 위치: 독립항 1·8·15, 종속항 5~7·12~14·19~20, Fig.2의 읽기/갱신 단계 및 Fig.3~4. 정답 확률과 힌트 사용 확률을 공동 예측하고 학습 계획에 사용한다. 실제 상호작용에 포함된 도움 사용을 지식 갱신에 반영하며 오답과 힌트 사용을 달리 처리한다. 힌트 보류와 다음 문제 유형 선택도 있다.

- 차이 후보: C3의 동일 발화 다중 용도 자격, C4의 과거 평가대상발화 보존을 위한 행동 부적격 처리, C6의 늦은 능력별 노출 사건에 따른 특정 자료 기여 철회까지는 읽은 청구항·실시예에서 확인 못 했다. 이 특허의 확률 모델을 일부러 무기능 비교군으로 치환하면 안 된다.

### P8. 같은 음성 입력의 평가와 재사용 품질 관리를 결합한 읽기 튜터

**EP0986802B1**, *Reading and pronunciation tutor*. [청구항·설명 원문](https://patents.google.com/patent/EP0986802B1/en).

### P9. 음성 품질을 근거로 모델 갱신을 허용·보류하는 특허

**EP3627497A1**, *Methods and systems for assessing and improving the performance of a speech recognition system*. [청구항·설명 원문](https://patents.google.com/patent/EP3627497A1/en).

- 읽은 위치: 청구항 1~9, Fig.2의 adaptation control 및 Fig.6~7. 인식 성능 평가와 기준 비교로 모델 적응을 수행하거나 보류하며, 어떤 발화를 갱신에 쓸지도 설명한다. 청구항 1에는 동적 수집 기간과 서로 다른 환경 등 구체 한정이 있다.
- 반론: ‘음성 자료를 무조건 학습에 넣지 않고 품질을 보고 허용한다’는 기술은 독립적인 새 기능으로 보기 어렵다.
- 차이 후보: 평가 대상은 인식기의 성능이며 C3의 학생 수행 자격은 아니다. 도움에 따른 과거 수행 기여 철회와 음성 자료 자격 유지의 연결까지 확인 못 했다. 현재 작업실도 ASR 자료 자격을 표시할 뿐 해당 인식 모델을 실제 재학습한 것은 아니다.

### P10. 최근의 ‘응답 증거를 조건에 따라 상태에 반영’ 연구

Fuzheng Zhao, **Correctness Is Not Homogeneous Evidence: A Correctness-conditioned Evidence-aware Knowledge Tracing Model**, arXiv:2608.22267v1 (2026-08-23, 사전논문). [원문 PDF](https://arxiv.org/pdf/2608.22267), [서지·버전](https://arxiv.org/abs/2608.22267).

- 읽은 위치: §3.1~3.5, §4.3. 힌트 수·마지막 힌트·시도 횟수·반응 시간 등의 행동 신호가 정오답 관측을 순환 상태에 반영하는 정도를 조절한다. 따라서 ‘정답이라도 근거의 무게가 다르다’는 표현도 충분한 차이가 아니다.
- 중요한 한계: §3.2.1은 문항 단위 로그로는 힌트가 정답보다 먼저였는지 입증할 수 없다고 명시한다. 이 특징들은 행동 대리지표이고 실제 숙련·인과·정확한 사건 순서를 인증하지 않는다. 사전논문임을 보존하며 심사된 학계 합의로 소개하지 않는다.
- 차이 후보: C1의 개별 발화/도움 사건 순서와 C3의 범주형 사용 자격, C6의 특정 기여 철회는 다른 처리 목표다. 이 차이가 특허성 있는 구성 관계인지 여부는 미확인이다.

## 6. 차이 후보를 검증 가능한 형태로 좁히기

| 이미 알려진 것 | 남는 차이 후보 | 아직 필요한 설명·증거 |
|---|---|---|
| 도움 사용에 따른 지식 확률 갱신 | 특정 발화가 특정 소비처에 기여할 자격을 명시한 셀 | 확률 추정과 자격 판정의 정확한 입력·출력 계약. 이분법 자체의 새로움을 주장하지 않음 |
| 불확실한 부분만 질문 | 원래 발화를 보존하는 확인과 새 발화를 생성하는 행동을 구분하고, 목표 발화 때문에 선택 자격을 제한 | 행동 타입·대상 발화·답 노출 능력 범위·비용·가능한 결과의 자료구조와 판정 순서. 현재 고정 후보 밖의 일반화는 미확인 |
| 도움 전후 수행을 구분 | 늦게 수신한 과거 도움 때문에 이미 반영한 특정 능력의 기여를 철회하고 음성 자료는 유지 | 사건 발생/수신 시각, 도움 범위, 발화 구간 겹침, 순서 불명, 정정된 전후 셀과 원인 연결 |
| 의존 결과의 부분 재계산 | 위 자격 변경에서 어떤 셀의 의미 기여가 바뀌는지 검출 | 전체 계산과 같은 결과, 무관한 셀 유지, 필요한 셀 누락 없음. 일반 캐시·해시·원장 자체는 기존 기술 |

현재 코어의 설명 가능한 예는 다음과 같다. 하나의 원음을 사람이 확인한 뒤 원음–전사 셀, 조사 역할 수행 셀, 과거형 수행 셀이 인정됐다고 하자. 발화보다 앞서 **조사 능력만 답을 노출한 사건**이 나중에 들어오면, 시간 관계가 확인되는 조건에서 조사 수행을 처음 독립 수행의 기여에서 제외한다. 전사 자체가 틀린 것은 아니므로 원음–전사 셀을 유지한다. 과거형의 독립성이 확인되고 해당 도움의 범위 밖이면 그 셀도 유지한다. 도움 시점이 발화와 겹치거나 순서를 모르면 관련 수행은 보류한다. **이것은 코드에 준 조건 아래의 자료 처리 예이고, 사람의 실제 지식 상태를 알아냈다는 예가 아니다.**

명세서에서 비어 있으면 안 되는 부분은 다음과 같다.

1. ‘관련 불명’과 ‘능력별 도움 범위’를 누가 어떤 입력으로 정하는지. 현재 사람 확인값이 필요한 부분과 자동 계산을 구분한다.
2. 복수 대안의 동치 기준. 현재 ASR은 정규화한 단어열 일치, 의미 효과는 제한된 조사·과거형 규칙이다. 일반 자연어 의미 동일 판정이라고 확대하지 않는다.
3. 대상 발화와 증거 발화가 다른 경우의 처리. 재청취와 재녹음, 같은 바이트의 별도 발화 사건, 파일 업로드 지연, 녹음 중 답 표시를 각각 제시한다.
4. 실제 반영한 셀의 취소와 학습 모델의 재학습·언러닝을 구분한다. 현재 원장은 셀 기여의 전후 변화를 보존하며 훈련된 모델 파라미터에서 해당 데이터 영향을 제거했다고 주장할 수 없다.
5. 범용 엔진을 청구하려면 제한된 예문 바깥에서 효과 함수·자격 함수·사건 관계를 설정할 실시 방법을 설명한다. 선언적인 ‘AI가 판단’ 문장으로 빈칸을 메우지 않는다.
6. C4의 관측 적격성이 C3/C6와 어떤 데이터 키로 연결되는지와, 보류 이유가 여러 개인 경우의 순서. 현 코어는 첫 보류 이유를 반환하고 고정 이유 코드로 후보를 연결하므로 다중 원인·다단계 최적 관측의 구현을 주장하면 안 된다.

## 7. 현재 비교가 입증하지 못하는 것

| 현재 비교 | 코드에서 실제 한 일 | 그 결과로 말할 수 없는 것 |
|---|---|---|
| `no-target` | 같은 후보를 쓰지만 목표 연결 제한을 끄고 가정 비용 1초인 ‘관계없는 선호 질문’을 최저 비용으로 고름 (`core.cjs` 356·365행) | 유능한 능동 질문 정책보다 우수함. 관련성 없는 후보를 거르는 상식적인 기준도 상대편에 허용해야 함 |
| `no-purpose` | 한 발화의 모든 용도가 통과해야 인정하는 전역 AND 조건 | 모든 기존 시스템은 전체 승인 또는 전체 보류만 함. 선행 P8은 품질 조건별 재사용을 이미 구분 |
| `no-epoch` | 마지막 새 응답을 최초 수행 근거에 쓰도록 강제 | 기존 지식 추적 모델이 모두 도움 뒤 정답을 원래 독립 수행으로 확정함. P6/P7은 그 전제를 약화시킴 |
| `predicted-response` | 작성된 첫 조건 분기를 사람 확인처럼 사용 | 실제 선행 모델의 환각률 또는 관측 전 오판율 |
| `comparedWithMain` | 본 규칙과 다른 셀을 세어 승격·손실 표시 (`core.cjs` 438행) | 외부 정답에 대한 오반영률·정확도. 본 규칙을 정답으로 놓은 내부 구성 비교임 |
| 증분 효과 계산 | 같은 코어의 전체 계산과 입력 지문 재사용 계산을 비교 | 선행 특허 구현보다 빠름, 전체 처리 복잡도 개선, 음성 정확도 향상, 특허성 입증 |

이 비교들은 **연결을 제거하면 어떤 계약이 깨지는지 보여주는 진단 시연**으로 유용하다. 논문/특허의 구현 성능 비교라는 표제를 붙이면 안 된다.

## 8. 공정한 비교 실험: 두 문제를 따로 평가

### 실험 A: 어떤 자료를 어느 용도에 반영하는가

모든 정책에 동일한 원음·전사 대안·문항·도움 문안·능력 범위·발화 구간·실제 수신 사건을 제공한다. 원음·전사 자격과 원래/새 수행의 자격을 각각 출력하게 한다. 사람 확인 비용도 동일하게 집계한다.

| 정책 | 구체 기준 | 비교 목적 |
|---|---|---|
| A0 전체 코어 | 현재 C1~C6 | 제안 처리의 실제 출력 |
| A1 별도 소비처별 규칙 | 음성 자료는 확인 전사/품질 기준, 수행은 도움 표시와 시점을 보는 별도 평가기. 두 평가기는 같은 사건 저장소를 읽지만 관측 계획·기여 원장을 공유하지 않음 | 단순히 용도 분리만으로 같은 오류를 피하는지. P8·P6에서 영감을 받은 자체 기준이며 원문 재현 아님 |
| A2 불완전 정보+의존 갱신 | 용도별 규칙을 일반 규칙 엔진 또는 명시적 의존표로 작성하고 변경 입력의 관련 결과를 재계산 | 일반적인 조건 검사·의존 갱신으로 충분한지. 동일 결과면 그 사실도 보고 |
| A3 보수적 승인/보류 | 모든 자료 승인과 모든 불명 보류를 각각 대조 | 오반영과 보존의 극단을 확인. 주력 성능 비교군으로 사용하지 않음 |
| A4 보조 확률 모델 | 도움 조건을 반영하는 지식 추적 모델의 예측을 별도 출력 | 지식 예측과 자료 자격은 다른 과제임을 확인. 자격 출력이 없으면 '미출력'으로 두며 오반영으로 강제 환산하지 않음 |

실험 정답표는 현재 코어를 호출해 만들지 않는다. 별도의 명시 규격에서, ① 원음이 어떤 발화 사건에 속하는지, ② 청취로 무엇을 확인할 수 있는지, ③ 어떤 문항 요구인지, ④ 어떤 답 정보가 언제 제공됐는지, ⑤ 어떤 자료 사용 규칙을 적용할지 각각 확정한다. 생성된 통제 사례에서는 숨긴 사건표를 별도 정답 원천으로 삼고, 실제 음성에서는 정책 이름을 모르는 독립 청취자 두 명과 불일치 조정을 사용한다. 판단이 불가능한 사례는 정답도 ‘불명’으로 남긴다.

**중요한 구분:** 실제 세계의 정답과 현재 관측 가능한 근거를 따로 표시한다. 예를 들어 녹음 전에 실제 힌트가 있었지만 아직 시스템에 기록이 없고 순서도 모르면, 시스템이 학생의 진짜 상태를 알아맞혔는지와 주어진 관측 아래 보류했는지는 다른 평가다. 문제 규격 자체의 타당성과 실제 학생 실력의 정확도도 분리한다.

### 실험 B: 같은 비용으로 어떤 확인을 먼저 하는가

원음의 모호한 구간 재청취, 답 정보를 포함하지 않는 문항/상황 확인, 기록된 도움 시점 확인, 같은 요청에 대한 반복 발화, 답 제시 후 새 발화, 독립된 새 문항을 **모든 정책에 동일하게 제공**한다. 원래 발화의 전사, 원래 독립 수행, 현재 새 수행 중 무엇을 알아보려는지 목표를 사전에 고정한다. 독립된 새 문항도 과거 발화 자체를 입증하지는 않으므로 목표별 성공을 구분한다.

| 정책 | 실제 선택 규칙 |
|---|---|
| B0 현재 코어 | 목표 이유 코드에 연결된 적격 후보 중 가정 비용 최소. 실측 비용 버전은 별도로 구성 |
| B1 관련성 필터+최저 비용 | 질문이 현재 알려지지 않은 변수 하나라도 직접 묻는지 확인한 다음 비용 최소. 무관한 선호 질문 제외 |
| B2 정보이득/비용 | 동일한 사전 확률과 결과 분포를 사용해 전사·의미 가설의 기대 불확실성 감소를 비용으로 나눠 선택. 결과 분포를 별도 자료로 추정하지 못하면 통제된 가정 실험으로 표시 |
| B3 자격 확인/비용 | 목표 셀을 인정·제외·보류 중 정확한 상태로 결정할 기대 수와 오반영 비용을 평가. 대상 발화 보존·답 노출 제약도 포함. 이는 제안 방향의 강한 비교 정책이고 현 코어에 구현되어 있지 않음 |
| B4 도움·시점 관계만 제거 | B3의 동일 후보·분포·비용에서 해당 관계만 제외. 실제 제거 효과를 보되 다른 정보까지 상대편에서 빼지 않음 |

정책이 다른 질문을 고르면 그 결과를 같은 실제 사실인 것처럼 재사용할 수 없다. 통제 시뮬레이션은 행동별 결과표를 미리 고정한 뒤 정책에 숨기고, 실제 사용자 실험은 조건을 무작위 배정한다. 전후 반복만 하면 앞선 답 노출의 학습 효과가 다음 조건에 남을 수 있다. 도움을 요청한 사람과 요청하지 않은 사람의 원래 지식 차이도 통제해야 한다. 이 문제는 P6가 실제로 지적한 비교의 함정이다.

### 필요한 사례와 지표

- 사례 축: 정확/모호/지원 밖 전사, 국소/전역 불명, 도움 없음/능력 일부/전체, 도움 전/후/겹침/순서 불명, 제때/늦은 도움 수신, 재청취/새 발화, 같은 바이트의 다른 사건, 무응답/예상과 다른 실제 응답. 핵심 축의 조합과 반례를 사전에 고정한다.
- 자료를 반영할 때 틀린 셀 수 / 반영 셀 수와 틀린 셀 수 / 전체 대상 셀 수를 모두 보고한다. 전자는 위험, 후자는 전체 영향 범위다.
- 정답상 사용할 수 있는 셀 중 보존한 비율을 함께 보고해 ‘전부 보류’ 전략을 드러낸다.
- 정확하게 해소된 **원래 발화 목표 셀**과 새로 얻은 **새 발화 셀**을 별도로 센다. 새 시점 성공을 원래 시점 해소로 세지 않는다.
- 늦은 정정에서 철회해야 할 셀 누락, 불필요한 철회, 영향 없는 용도 유지, 원장 전후 기여의 일치를 평가한다.
- 시간·청취 횟수·질문 수·실제 API 호출·JSON 크기를 따로 측정한다. 현재 1·5·8초는 실측값으로 사용할 수 없다. 같은 PC에서 반복한 중앙값과 상위 지연, 사례별 결과를 보존한다.
- 실제 음성 표본은 화자·문항별로 분리하여 같은 원음의 변형이 학습/평가에 동시에 들어가는 누출을 방지한다. 교사 불일치와 지원 밖 사례를 제외하고 성공률만 올리지 않는다.
- 선행 구현을 재현하지 않았다면 정책 이름에 문헌/제품 이름을 붙여 그 성능으로 보고하지 않는다. 문헌에서 영감을 얻은 자체 기준, 동일 코어의 구성 제거, 실제 원문 재현을 명확히 구분한다.

## 9. 주장에 대한 판정

| 주장 | 현재 판정 |
|---|---|
| ‘같은 음성의 사용처마다 자격을 구분하는 실제 코드를 만들었다’ | 가능. 제한된 처리 범위와 사람 확인 입력을 함께 명시 |
| ‘도움을 받은 정답을 그대로 독립 수행으로 소급하지 않는다’ | 코드 동작으로 설명 가능. 그 원리 자체의 최초성은 부정확 |
| ‘평가와 관측의 폐루프가 새 발명이다’ | 불충분. P4·P5·P7과 강하게 겹침 |
| ‘용도별 품질 분리가 새롭다’ | 불충분. P8·P9와 구체 비교 필요 |
| ‘복수 해석의 공통 결과만 인정하므로 최초다’ | 불충분. P1·P5와 비교 필요 |
| ‘늦은 정정 때 관련 결과만 철회하므로 특허성이 높다’ | 불충분. P5 및 일반 의존 갱신과 정확한 관계를 구별해야 함 |
| ‘현재 구현이 선행 전체보다 정확하고 빠르다’ | 확인 불가. 선행 재현·공정한 정책 비교·외부 정답 실험이 없음 |
| ‘C1~C6의 좁은 결합은 등록된다’ | 확인 불가. 읽은 자료에서 전체 동일 관계를 못 찾은 상태이며 결합 용이성·명세 지원 검토가 남음 |
| ‘시험 수·해시·로컬 전사·원장이 특허성을 보장한다’ | 사용할 수 없음. 실시 구체성·재현성의 근거와 특허 요건 판단은 별개 |

현재 미팅에서 가장 생산적인 논점은 **“P6/P7/P8과 P1/P5를 결합하면 위 사건·자격·목표발화·기여철회의 정확한 관계가 통상적으로 나오느냐, 아니면 어떤 필수 수단과 측정 효과가 남느냐”**다. 답을 정해 놓고 문헌과 비교군을 약하게 만들지 말고, 단순한 대안 구현도 같은 결과를 낸다면 그 사실을 반영해 보호 범위를 조정해야 한다.

## 10. 확인 범위의 종료점

추가 조사로 기존 5건보다 강한 반론을 확보했으며, 현재 구현에서 주장 가능한 부분과 미충족·미확인 부분을 구분했다. 여기서 제안한 강한 비교 정책·독립 정답표·자연음성 실험은 **설계안**이고 실행 완료가 아니다. 외부 학생 자료를 수집·전송하거나 새 과금 작업을 하지 않았다.
