# 등록 우선 전략 · 반영과 검증

2026-09-12. 현재 목표는 실제 사업 기술과 연결된 등록특허 1건의 마케팅 신뢰 확보다.

## 반영

- forge 방식의 A/B 독립 검토와 별도 사실·표현 검토를 통합했다. Core 선택 정정을 주안, Loom 의상 보존형 표정 집합 합성을 예비안으로 정했다. 다른 모든 후보보다 등록 확률이 높다고 확정하지 않았다.
- content.cjs → 16쪽 PDF·목차/사례 선택 가능한 HTML·STRATEGY.md를 생성했다. 승인 로고·마스코트·서체·토큰·Loom CSS를 지문 대조해 사용했다.
- 현재 미팅 진입 화면·진행 가이드·최상위 안내·파일 지문을 갱신했다. 새 전략이 먼저 열리고 이전 1쪽·10쪽·31쪽·영상은 원리 참고로 표시된다.
- PATENT-EVIDENCE, PATENT-REQUIREMENTS, EXPLAINED, README, HANDOFF, PRIOR-ART에서 새 전략으로 연결했다. 전체 C1~C6를 최종 독립항으로 고정하지 않는다.

## 실제 실행

reproduce.cjs가 기존 Core/Store/Projection을 호출했다. 네 사례 전부 통과했다. 수행 전 도움: 조사 제외·기존 기여 철회. 수행 중 도움: 조사 보류·기존 기여 철회. 수행 후 도움: 세 기여 유지. 새 응답: 도움 뒤 수행으로 반영하되 최초 수행으로 소급 제외.

원음 불변 4건, 전체 재계산과 이전 계산 재사용의 의미 출력 일치 4건, 사건 재생으로 저장 판본 22개 일치. 실제 전사·학생 입력·실제 마이크를 사용한 시험이 아니다. 합성 WAV와 합성 시간/사람 확인 조건을 주입했고 신규 OS 임시 SQLite를 사용했다. 운영 DB·전사 API 호출은 없었다. 원본 코어 로직은 변경하지 않았다.

A 작성자는 기존 관련 시험 5개도 실행해 모두 통과했다. 4개 시나리오와 기존 시험 5개를 특허 등록 가능성 수치로 합산하지 않는다.

## 문서·화면 검증

- PDF 16쪽, 1,659,226 bytes. 16쪽 전체 렌더 이미지의 조판을 확인하고, 선행 비교 표가 있는 9쪽을 별도 확대 확인했다. 글자/표/페이지 하단의 잘림·겹침 없음.
- PDF 한글 본문 추출 16쪽 성공, 대체 문자 없음. 표준 글꼴 파일 또는 Type3 글자 윤곽이 포함되어 외부 글꼴 설치에 의존하지 않음. Type3를 FontFile 존재 여부만으로 검사한 초기 검사는 잘못 실패해 CharProcs의 실제 글자 스트림 확인으로 바로잡았다.
- 1440px 화면과 390px 모바일: 가로 넘침 없음, 이미지 로딩 정상, 목차 열기/닫기 정상, 네 사례 선택 정상. 자료 자동 열람 중 외부 HTTP 요청 0.
- 현재 첫 화면에서 새 전략 링크를 클릭해 16쪽 문서가 열림을 확인했다. 로컬 링크 7개 존재. 기존 승인 화면의 디자인을 보존하며 새 전략 경로를 앞에 배치했다.
- 두 자료 묶음 26개 파일의 크기·SHA-256을 매니페스트와 대조했고 현재 PDF 사본 일치를 확인했다. 실행 근거의 소스 지문 4개가 현재 코드와 일치한다.
- 출력의 검수/verification.json, final-verification.json, pdf-verification.json 및 렌더 이미지에 상세 결과를 남겼다. PDF 본문은 재출력 없이 링크·레이아웃을 반복 검증할 수 있다.

## 최종 근거와 남은 것

특허법 제29·42조, 공식 2026 심사자료의 기존 해당 절, 우선심사·설정등록 안내를 현재 전략과 대조했다. 제47조는 일반 웹 추출이 실패한 뒤 국가법령정보센터의 해당 조문을 직접 HTTP로 읽어 최초 기재 범위의 보정 조건을 확인했다. A에는 추가 학습 사건·첫 시도 도움 기록 선행, B에는 표정 합성·비동기 처리 선행이 연결된다.

남음: 국내 대응·심사 경과 등을 포함한 최종 선행 대조, 독립항 R1/R2 선택과 최종 명세서, 미지원 능력 코드의 입력 처리 보강, 지원 범위·명의·심사 대응 비용/기한 확정, 실제 출원·심사·설정등록. 등록 보장·주관적 확률·전 엔진 특허성 전수 확인·실제 학생 효과를 완료로 보고하지 않는다.

## 재제작

1. 현재 지원 문장·소스·합성 원음이 동일한지 확인한다. 입력·코드가 바뀌면 reproduce.cjs로 실행 근거를 다시 만든다.
2. content.cjs를 수정하고 build.cjs를 실행한다. 새 PDF 제작 전 PDF 스킬의 작업 시작 기록을 따른다.
3. integrate.cjs로 현재 진입 자료·매니페스트를 갱신한다.
4. verify.cjs와 verify_pdf.py 및 실제 렌더로 변경 부분을 확인한다. 검증 결과 숫자는 새 산출물에 맞춘다.

생성기·재현기는 현재 이 PC의 기존 자산·런타임·저장소 구조를 사용한다. 동봉 파일만 다른 PC로 옮겨 실행 가능한 배포 패키지로 주장하지 않는다. 로컬 커밋만 하며 원격 push·운영 배포는 하지 않는다.
