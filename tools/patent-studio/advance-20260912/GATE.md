# Core 발전 구현 — 독립 선행·사실 검토

2026-09-12 · 등록 우선 목적 · 작성·구현 A/B와 분리된 검토

## 현재 결론

시간이 불확실한 도움 사건을 범위로 다루고, 원래 발화를 보존할 수 있는 확인만 골라 실제 확인 뒤 자격을 갱신하는 개발은 **기존 제품의 실제 빈틈을 메우는 유의미한 개발**이다. 현재 작성 중인 코드를 완성하고 그 효과를 검증할 이유가 있다. 다만 시간 구간, 출처 기록, 조건부 관측 계획, 선택 정정은 각각 강한 선행이 있는 수단이다. 기능을 추가했다는 사실만으로 등록 가능성이 높아졌다고 판정하지 않는다.

최종 기술 후보는 **“확정할 원래 발화·용도를 지정하고, 시간·범위 불명 때문에 보류된 자격에 대해 원래 증거를 보존하는 관측을 제한된 계산으로 선택하며, 실제 시간 근거 정밀화 뒤 해당 능력 기여만 갱신하는 연결”**로 대조할 가치가 있다. 이 문장의 전체 관계가 선행에 없다는 결론은 아직 아니다.

최종 A/B 문서와 두 독립 모듈, Core의 관련 연결을 대조했다. 아래 범위에서 기술 설명과 구현 계약은 일치한다. API·화면·저장소를 포함한 전체 통합 시험과 실물 검수는 root의 별도 최종 검증을 따른다. 이번 독립 검토는 공유 코드나 제품 파일을 수정하지 않았다.

## 2. 개발에서 남겨야 할 구체 관계

1. 같은 원음 식별자와 별도로 평가대상 발화의 식별자·발생 구간을 유지한다. 용도는 전사 자료와 원래 독립 수행을 구분하고 능력별 자격과 기여를 저장한다.
2. 도움 사건의 발생 가능 범위, 대상 능력 코드, 답 노출 여부, 범위의 출처를 기록한다. 수신 시각은 사건이 저장된 시각으로 별도 보존한다.
3. 도움 시간 범위의 모든 가능 시각이 녹음 시작보다 앞인지, 종료보다 뒤인지, 녹음 안인지, 경계를 걸치는지를 계산한다. 경계 불명은 수신 시각이나 대표값으로 임의 확정하지 않는다.
4. 자격의 보류 이유를 데이터와 연결해 기록하고, **그 원래 발화·용도의 증거를 보존할 수 있는 행동만** 그 목표를 확인하는 후보로 삼는다. 답을 알려 주고 새 응답을 받는 행동은 새 수행을 만들 뿐 원래 수행을 확인하는 증거로 바꾸지 않는다.
5. 지지 근거가 확인된다는 가정 아래의 자격 투영은 계획 결과에만 넣는다. 이 투영은 실제 확인 사건이 아니며, 투영 결과만으로 저장된 기여를 승격하지 않는다.
6. 실제로 수신된 시간·도움 범위 정밀화 사건을 원래 도움 사건에 연결한다. 선언 범위의 일관성 검사와 출처 기록은 필요하지만, 외부 자료의 진실성 인증으로 소개하지 않는다.
7. 실제 확인 뒤 용도·능력별 자격을 다시 계산하고 원인 사건·전후 판본·기여 변화를 함께 보존한다. 관련 조건이 유지된 전사와 범위 밖 독립 능력은 유지하며, 새 응답은 별도 발화의 자격으로 관리한다.

이는 **기술 초안의 관계 목록**이다. 모든 항목을 무조건 한 청구항에 넣거나 모두 새롭다고 주장하지 않는다. 실제 완성 코드와 선행 대조에서 차이를 만드는 필수 연결을 고르고, 나머지는 실시예·종속 구성에 배치한다. 무관한 구현 제약을 늘리는 것을 등록 전략으로 삼지 않는다.

## 3A. 관측 계획의 정확한 의미

`observation-planner.cjs`와 root가 연결한 `core.cjs`의 `collectBlockers`·`evidencePlan`을 읽었다. 현재 B는 가능한 결과를 모두 갈라 계산하는 POMDP나 AND-OR 정책 구현이 아니다. **선언된 보류 이유가 자격을 지지하는 실제 확인으로 해소된다는 조건 아래, 예산·행동 수·상태 수를 제한하여 유효한 행동 부분집합과 실행 순서를 고르는 검색**이다. 하나를 실행해 실제 결과를 받은 뒤 다시 계획한다.

보류 이유를 모두 확인하는 것과 자료를 반영할 자격이 생기는 것도 다르다. 도움 시간 불명을 확인한 결과 녹음 전 도움으로 밝혀지면 자격은 제외로 결정될 수 있다. 검토 의견을 반영해 B는 `assumption=all-declared-blockers-cleared-by-supporting-observations`, `requiresSupportingOutcomes=true`, `inspectionAloneIsInsufficient=true`를 명시하고, 모호한 `complete`를 입력 평가 여부와 조건부 목표 충족 여부로 나눴다. 이 보정은 확인만으로 자동 승인된다는 표현 위험을 해소한다. 화면·보고서에서도 이 유리한 결과 가정을 유지하고 실제 상태는 Core가 실제 관측 뒤에 결정한다.

원래 발화의 수행 자격에 대해 답 노출·새 시점 생성·원래 목적 부적격인 행동과 그 의존 후속 행동을 배제하는 계산은 읽은 코드에 있다. 이 속성은 행동 제작자가 입력한 선언값을 소비하는 것이며, 행동 문안을 의미 분석해 실제 증거 보존을 자동 인증하는 기능은 아니다.

현재 Core 연결은 원래 발화의 현 사용 목적에서 보류된 자격을 대상으로 하며, 발화 ID가 포함된 보류 ID와 문항 공통 조건을 구분한다. 일반 호출자가 서로 다른 발화에 같은 보류 ID를 사용하면 행동 하나가 여러 발화를 함께 확인한다고 계산할 수 있으므로, 외부에 범용 API로 사용할 때도 목표·발화 범위가 맞는 ID 계약이 필요하다. 후보가 일반 문장·임의 학생 전체에 대해 생성된다고 설명하지 않는다.

## 4. 최종 구현에서 확인할 증거

- 같은 합성 원음에서 시간 범위가 녹음 경계를 걸쳐 관련 수행만 보류되는 경우.
- 실제 근거 정밀화 뒤 모든 가능 시간이 녹음 전으로 좁혀져 해당 기여만 제외·철회되는 경우.
- 반대로 모든 가능 시간이 녹음 후로 좁혀져 이전 수행의 적격 자격이 회복되는 경우. 회복은 입력된 범위·다른 조건의 타당성에 의존한다.
- 정밀화가 기존 범위를 벗어나면 기존 사건을 조용히 덮지 않는 경우.
- 알려지지 않은 도움 능력 코드가 무관한 도움으로 사라지지 않고 해당 수행을 불명으로 남기는 경우.
- 보류 이유가 여럿이면 하나의 확인으로 전부 해소했다고 계산하지 않는 경우.
- 조건부 계획 투영과 실제 확인 사건을 분리하고, 관측 전에는 원장의 기여가 바뀌지 않는 경우.
- 답 제시·새 발화 행동이 원래 발화의 확정 수단에서 제외되고 새 수행은 별도 보존되는 경우.
- 탐색 깊이·노드·결과 수 제한 도달을 기록하고, 제한된 계획을 전역 최적·완전 계획으로 표시하지 않는 경우.
- 전체 계산과 재사용 계산의 의미 결과 일치, 원인 사건·판본·기여 원장 재현, 서버 재시작 뒤 조회 일치.

비교 목적은 추가한 연결이 어떤 입력 오류와 불필요한 자료 손실을 줄이는지 확인하는 것이다. 비교 정책에도 동일한 사건 정보·지원 범위·입력 비용을 주고, 현 코어를 정답 생성기로 사용한 내부 비교만으로 외부 우월성을 주장하지 않는다.

## 5. 법적 판단과 남은 조사

2026-09-12에 확인한 [특허법 제29조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1030488663)는 산업상 이용·신규성·진보성 판단의 근거이며, [제42조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0042&lsiSeq=279827&urlMode=lsScJoRltInfoR)는 실시할 수 있는 설명과 뒷받침되고 명확한 청구항을 요구한다. 실제 개발과 재현 자료는 설명의 구체성을 보강하지만 신규성·진보성의 판단을 대신하지 않는다.

남은 조사 범위는 최종 청구항의 구성별 국내 문헌 검색, 각 근접 특허의 국내 대응·동족·인용과 심사 경과, 비특허문헌, 한 문헌의 전체 구성 개시와 복수 문헌의 결합 동기다. 이 리뷰에서 한국 대응 청구항을 모두 조사했다거나 등록 심사 결과를 확정했다고 보고하지 않는다.

## 7. 결합 출원 후보의 조건 문언

다음은 A의 시간 구간과 B의 계획을 각각 독립적으로 새롭다고 주장하지 않고, 실제 공통 연결을 변리사에게 전달하는 **기술 초안**이다. 최종 청구범위는 아니다.

> 컴퓨터가 동일 원음에 대응하는 평가대상 발화의 식별자·녹음 구간과, 원음–전사 자료 및 능력별 독립 수행의 사용 자격을 구분하여 저장하고;
>
> 도움 사건의 대상 능력 범위와 발생 가능시각 범위 및 그 출처를 수신하여, 수신 시각으로 발생 순서를 대체하지 않고 해당 가능범위와 녹음 구간의 관계를 계산하고;
>
> 관련 전사·문항·관측 조건과 함께 각 자격의 보류 사유를 생성하되, 시각 관계가 확정되지 않은 수행 자격을 임의로 반영하지 않으며;
>
> 상기 평가대상 발화와 사용 목적에 대응하는 보류 사유를 확인할 행동 후보 중, 새 발화를 만드는 행동을 원래 원음의 전사 확인 수단에서 제외하고, 답을 노출하거나 새 수행을 만드는 행동 및 그 선행 영향을 받는 후속 행동을 원래 독립 수행의 확인 수단에서 제외하고;
>
> 적격 후보와 선언된 선행 관계·비용·탐색 상한 안에서, 보류 사유가 자격을 지지하는 실제 관측으로 해소된다는 조건부 계획을 계산하되 그 계획만으로 실제 사용 자격을 변경하지 않고;
>
> 원래 도움 사건에 연결되는 실제 확인 입력으로, 기존 범위를 벗어나지 않는 시간 정밀화 또는 확인된 도움 범위를 취득한 뒤 해당 자격을 다시 판정하고, 관련 조건이 유지된 다른 용도의 기여를 보존하면서 원인 사건·전후 판본·기여 변경을 기록하는 처리.

이 초안은 첫 판본에서 반드시 모든 자격이 반영되었다고 가정하지 않는다. 보류에서 제외·반영으로 결정되는 경로와, 이미 반영된 기여를 보류·제외로 철회하는 경로는 각각 실시예로 구분한다. 시간 범위의 정밀화만으로 반영을 보장하지 않으며, 전사 불명·지원 범위 밖·관측 조건 미확인 등 다른 사유가 남으면 실제 자격은 계속 보류될 수 있다.

남는 가장 중요한 질문은 위 연결에서 **사용 자격의 대상·근거 보존 제약·실제 확인 후 기여 정정 사이의 관계가 선행의 통상적 결합으로 쉽게 도출되는가**다. 현재 문서와 코드는 이 질문을 더 구체적으로 비교할 수 있게 만들었으며, 그 질문의 법적 결론을 미리 정하지 않는다.
