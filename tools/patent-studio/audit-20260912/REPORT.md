# SYNK · 특허 후보 선행 대조와 종합 검수

2026-09-12 · Core 0.5.0 / 78628146a875 · 기술 감사 및 출원 상담용

## Core를 주안으로 유지합니다. 등록성 판단은 아직 남았습니다.

SYNK Core에 구현한 처리 방식과 회사의 실제 후보 8개를 대조했습니다. 등록특허 한 건을 위한 현재 준비 우선순위를 정리합니다.

**지금 추천하는 방향**

늦게 확인된 도움의 발생 관계와 대상 능력에 따라, 동일 원음의 관련 수행 기여를 갱신하고 다른 유효한 용도는 유지하는 처리 관계를 먼저 검토합니다.

| 질문 | 이번 판정 |
| --- | --- |
| 중복되지 않았나요? | 개별 수단은 상당 부분 겹칩니다. 검토 범위에서 좁은 전체 관계와 동일한 단일 문헌은 특정하지 못했습니다. |
| 회사에서 가장 등록하기 쉬운가요? | 현재 비교한 후보 중 미팅 주안으로 유지할 근거가 있습니다. 기업 전체의 최고 등록 확률은 확인할 수 없습니다. |
| 0.5를 크게 개발해 더 유리해졌나요? | 실행과 설명 근거는 늘었습니다. 시간 구간·확인 계획을 추가한 것만으로 진보성이 높아졌다고 판단하지 않습니다. |

Loom 표정 합성은 별도 예비안입니다. Core 0.5 전체의 기능 수나 엔진 이름을 발명의 새로움으로 설명하지 않습니다. 이번 자료는 기술 감사와 출원 상담을 위한 것으로, 최종 청구범위의 법적 판단은 아직 남아 있습니다.

## 가장 큰 미해결은 진보성입니다.

진보성은 해당 분야 기술자가 기존 기술로부터 쉽게 만들 수 있는지를 판단하는 요건입니다. 잘 작동하는 것과 별도로 검토해야 합니다.

| 요건 | 현재 근거 | 남은 판단 |
| --- | --- | --- |
| 발명의 성립·산업상 이용 | 레코드 저장 → 시간·조건 연산 → 자격·기여 원장 출력이 실제 작동 | 교육 판단 규칙만 적지 않고 컴퓨터의 구체 처리 관계를 청구항에 특정 |
| 신규성 | 읽은 단일 문헌 중 좁은 전체 관계의 완전 동일 개시는 미확인 | 최종 청구 문장에 대해 명세서·도면까지 단일 문헌별 대조 |
| 진보성 | 지연 사건·도움 해석·용도 분리·부분 철회에 가까운 선행 존재 | 같은 교육 문제에 알려진 수단을 결합하는 통상 설계인지 판단 |
| 실시 가능·명확성·뒷받침 | 실제 코드·입출력·예외·재현 자료 보유 | 목적·능력·시도·도움·기여 정의와 보호 범위 전체의 실시 설명 |

**판단 순서**

보호받을 기술 문장인 청구항을 정한 뒤, 가장 가까운 문헌과 차이를 찾고 그 차이를 쉽게 만들 수 있는지 판단합니다. 한정을 많이 넣거나 무관한 숫자를 추가하는 방식으로 대체할 수 없습니다.

마케팅 목적은 넓은 권리보다 설명 가능한 한 건에 집중하는 데 반영됩니다. 법정 등록 요건이 낮아지지는 않습니다.

## “무엇을 말했나”와 “혼자 말했나”를 구분합니다.

같은 원음에 “친구를 만나서 카페에 갔어요”가 있습니다. 원래 발화 구간은 10:00:00~10:00:10입니다. 조사 표현의 도움 기록이 나중에 도착합니다.

| 저장된 근거 변화 | 조사 수행의 기여 | 함께 확인할 것 |
| --- | --- | --- |
| 도움 시간 09:59~10:01 | 순서가 불명확하여 보류 | 원음·확인된 전사는 그대로 |
| 같은 범위를 10:00:20~10:00:40으로 정밀화 | 이 도움은 발화 뒤이므로, 다른 조건 충족 시 반영 | 독립 과거형의 유효한 기여도 유지 |
| 별도 새 사례에서 09:59:20~09:59:40으로 정밀화 | 도움이 발화보다 먼저이므로 해당 독립 수행 제외 | 영향받지 않은 용도는 자기 조건으로 유지 |
| 답을 보여준 후 다시 말함 | 새 시도의 근거로 취급 | 새 응답을 원래 수행·원래 원음 전사로 소급하지 않음 |

1. **원본과 시도를 연결한다**: audioRef는 파일 내용의 식별, utteranceId·epoch는 어느 수행인지의 식별입니다. 같은 바이트라도 수행 귀속을 구별합니다.
2. **새 도움의 실제 발생 관계를 계산한다**: 수신·저장시각은 이력으로 남기고, 도움 발생 범위를 원래 발화 구간과 비교합니다.
3. **기여 변화와 원인을 남긴다**: 사용 목적·능력별 반영·보류·제외 및 전후 기여를 기록합니다. 원음 바이트는 바꾸지 않습니다.

현재는 통제된 한국어 예제와 입력된 조건에 대한 로컬 구현입니다. 도움의 실제 내용·시각을 자동으로 진실 인증하거나 모든 언어를 판정하는 시스템은 아닙니다.

같은 자료의 목적별 접근을 나누고 한 목적만 철회하는 선행을 확인했습니다. 접근 허락과 학습 증거 자격의 차이까지 구체적으로 대조해야 합니다.

2. **시간·확인을 붙일 동기도 따로 검토한다**: 시간이 불명확하면 구간으로 다루고, 근거가 부족하면 검사 후 갱신하는 방법군도 알려져 있습니다.

기존 기술과 겹치는 수단을 빼고 무엇이 남는지 확인했습니다. 이 관계 전체를 청구 문장으로 정한 뒤 다시 대조해야 합니다.

준비도·사업 관련성·구체적 처리·가까운 선행을 비교했습니다. 회사 전체 발명의 전수 조사나 등록 확률 순위는 아닙니다.

## 기능을 모두 넣기 전에 두 청구 구조를 대조합니다.

현재의 좁은 관계를 주안으로 가져가되, 차이를 만들던 연결까지 덜어내지 않도록 두 구조를 함께 검토합니다.

| 청구 구조 후보 | 장점 / 남은 반론 |
| --- | --- |
| A · 용도별 자격 정정 / 원음·시도 연결 → 늦은 도움의 능력/시간 판단 → 기여 변화·원장 | 실시예가 명료합니다. 그러나 사건 재처리와 목적별 조건 관리의 통상 결합에 가까워질 수 있습니다. |
| B · 자격 정정과 원래 근거 확인 연결 / A + 원래/새 수행별 행동 제한 → 복수 보류 확인 → 실제 결과 갱신 | 상호 관계를 더 특정합니다. 일반 계획법과의 결합 반론 및 문언 복잡성도 커집니다. |

1. **먼저 최인접 문헌을 하나 정한다**: 읽기 튜터 또는 지연 학습 사건 중 실제 청구항과 가장 가까운 출발점을 선택하고 차이를 문장으로 씁니다.
2. **차이가 쉽게 도출되는지 답한다**: 도움 사용 해석·목적별 일부 철회 등을 결합할 동기와, 그때 반드시 달라져야 하는 데이터 관계를 검토합니다.
3. **등록 판단을 바꾸는 한정만 남긴다**: 시간 범위·원래 수행 행동 제한이 반론을 해결하는 데 필요한지 정합니다. 숫자·제품명·일반 저장 수단은 그 자체로 보강책이 아닙니다.

**Loom으로 바꿀 조건**

Core의 남은 관계가 통상 결합으로 정리되고, Loom의 공통 표정 창과 의상 보호 연결에 더 명확한 비통상적 처리·재현 근거가 남는 경우입니다. 현재 그 우위를 확인하지는 못했습니다.

## 시연 뒤에는 이 세 가지 결정을 받아옵니다.

미팅 주안은 등록특허 한 건입니다. 회사 소개 다음에 아래 순서로 기술과 대조표를 보여 주면 논점이 선명해집니다.

1. **1분 · 문제와 원본**: 같은 원음을 전사 자료와 최초 독립 수행에 쓰는 이유, 늦은 도움이 두 용도에 다른 영향을 주는 예를 설명합니다.
2. **3분 · 실제 판정 전후**: 새 시간 예제에서 조사 보류 → 발화 뒤 확인 → 반영을 보입니다. 별도 새 사례에서 발화 전 확인 → 제외를 보이고 원음·다른 유효 자격의 유지와 기록 재현을 확인합니다.
3. **2분 · 가까운 선행과 차이**: 이 자료 4~6쪽을 펼쳐 겹치는 수단을 인정하고, 남는 전체 관계와 가장 강한 결합 반론을 제시합니다.
4. **마무리 · 결정 세 가지**: ① 최인접 문헌과 정확한 차이 ② A/B 중 독립항으로 삼을 관계와 이유 ③ 보정에 쓸 추가 한정·도면·필요한 보강 증거를 정리해 받습니다.
