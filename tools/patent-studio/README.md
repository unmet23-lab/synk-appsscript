# SYNK 근거 작업실

원음 → 해석 후보 → 사용처별 반영·보류 → 실제 도움 제시 → 새 응답 → 재판정·저장 → 같은 입력 비교를 직접 실행한다.

## 열기

저장소 루트에서 `node tools/patent-studio/server.cjs`를 실행하고 http://127.0.0.1:4318 을 연다. Windows에서는 `tools/patent-studio/start.ps1`을 실행하면 숨김 서버와 브라우저가 열린다. Node.js 24 이상이 필요하다. 승인 자산은 시작 시 현재 원천에서 준비한다.

## 미팅에서 따라갈 순서

1. **예제로 보기 → 조사는 보류, 과거형은 보존 → 이 예제로 시작.** 처음 세 칸에서 왜 판정이 갈리는지 확인한다. 합성된 해석·조건임을 화면에서 구분한다.
2. **처음 원음 재확인.** 청취 결과를 입력하고 확인하면 그 근거에 의존한 기록이 다시 계산된다. 예제의 조건 확인과 실제 원음 청취 확인은 다른 증거다.
3. **모범 문장 보여주기.** 실제 화면에 문장이 표시된 뒤 사건을 저장한다. 그 뒤 **새 응답 녹음/파일 선택**으로 실제 음성을 추가한다.
4. **새 응답의 청취 확인.** 음성–전사 쌍은 자격에 맞게 반영되지만, 이 새 응답으로 처음 독립 수행을 확정하는 칸은 제외된다.
5. **연결 제거 비교.** 동일 사건 입력에서 사용처·시점·관측 목표·실제 응답 조건을 각각 바꾼 결과를 확인한다. 이 수치는 외부 정답표에 따른 정확도나 등록 가능성이 아니다.
6. **기록 내려받기.** 원음의 원래 바이트, SHA-256, 실제 전사 요청·응답, 사건, 판정, 비교를 JSON으로 가져간다. 새로고침·재실행 뒤 이전 시연을 다시 읽는다.

## 실제 녹음

‘직접 녹음’에서 새 기록을 만들고 마이크 또는 파일을 사용한다. 마이크 권한은 해당 버튼을 눌렀을 때 브라우저가 요청한다. 전사 모델의 결과는 기계 전사로만 저장하고, 사람이 원음을 듣고 확인한 전사와 구분한다. 자동 전사 연결이 실패해도 원음은 보존되며 직접 청취·입력을 진행할 수 있다.

기존 Gemini 또는 명시 설정한 Vertex 경로를 사용하며 자격증명을 화면·내려받기에 넣지 않는다. 실제 음성을 외부 전사에 보내는 경로이므로 학생 운영 데이터의 기존 계약은 [제품 연결](INTEGRATION.md)을 따른다. 새 결제·구독·자동 과금 전환을 구현하지 않는다. `SYNK_PATENT_STT_PROVIDER=manual`이면 외부 요청 없이 사람 청취로 진행한다.

로컬 합성 샘플은 `tools/patent-studio/make-samples.ps1`로 생성한다. Windows Heami 음성, 고정된 시연 문장과 SHA-256을 samples/manifest.json에 함께 남긴다. 학생·마이크 음성을 사용하지 않는다.

마이크 녹음은 시작·종료 구간을 별도로 보존한다. 가져온 파일은 업로드 시각을 발화 시각으로 쓰지 않는다. 파일의 최초 시도·도움 이후 여부를 확인하지 않으면 수행 칸을 보류하며, 청취 전사 자료의 자격은 별도로 판단한다. 사람의 시점 확인도 실제 촬영 시각을 만들어 넣지는 않는다.

## 저장과 적용 범위

기본 저장 위치는 `%LOCALAPPDATA%/SYNK/patent-studio/studio.sqlite`다. `SYNK_STUDIO_DATA`로 별도 폴더를 지정할 수 있다. 원음과 실제 사건은 서버에 저장하고, 판본 검사·중복 사건 방지·판정 갱신을 SQLite 트랜잭션으로 함께 처리한다. 이 로컬 DB가 제품의 학생 DB를 변경하지 않는다.

현재 의미 판정은 화면에 적힌 한국어 통제 문항의 조사·역할·과거형 범위다. 다른 자연스러운 문장을 자동으로 틀렸다고 판단하지 않는다. 임의 음성의 자동 해석 완결성, 모든 언어의 문법 판정, 외부 도움 전체의 부재를 보증하지 않는다. 정확한 전사 자료의 자격과 문법 수행의 자격은 별도로 계산한다.

현재는 사건이 바뀔 때 세션 전체와 네 가지 비교를 다시 계산한다. 파생 결과만 골라 갱신하는 증분 계산이나 제품 전체의 장기 상태 취소를 구현한 것은 아니다. 로컬 계산 규모는 `node tools/patent-studio/benchmark.cjs`로 재현한다. 처음 실행할 다른 환경에서는 이 저장소의 현재 승인 자산과 Node 24, `tools/patent-studio`에서 설치한 package.json 의존성이 필요하다. 현재 기계에서는 기존 번들 런타임을 재사용했다.

## 파일 역할

| 파일 | 책임 |
|---|---|
| core.cjs | 순수 판단·실제 사건 반영·관측 후보·규칙 비교 |
| store.cjs | 원음 불변 참조·영구 저장·판본·사건 중복 방지·내려받기 |
| transcriber.cjs | 기존 모델 정책을 따른 실제 음성 전사·입출력 근거 |
| server.cjs | 로컬 HTTP API·파일 형식 검사·재생·화면 연결 |
| public/ | 녹음·파일·사람 확인·도움 제시·결과·기록 화면 |
| API.md / INTEGRATION.md | 실행 계약 / 기존 제품의 연결 위치와 남은 범위 |

검증: `node --test tools/patent-studio/core.test.cjs tools/patent-studio/store.test.cjs tools/patent-studio/integration-review.test.cjs tests/patent-studio-transcriber.test.cjs`. 브라우저 검증은 `node tools/patent-studio/browser-qa.cjs`다. 실물 검증 결과와 실제 전사 연결 여부는 `VERIFICATION.md`에 남긴다.

기술 구현 참고: [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder), [Node.js SQLite](https://nodejs.org/api/sqlite.html). 서체·재질·마스코트의 원천은 저장소 DESIGN.md와 public/assets/manifest.json에 연결한다.
