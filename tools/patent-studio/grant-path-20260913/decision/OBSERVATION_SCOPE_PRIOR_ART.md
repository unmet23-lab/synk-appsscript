# 도움 관측 범위의 수신 완결 조건 — 표적 선행 대조

2026-09-13 · 표적 특허 원문 3건·순번 누락 보충 원문 1건 · 구현 결정 전 한정 검토

**수동 확인값을 실제 사건 수신 상태로 바꾸는 개발 가치는 있지만, ‘시간 대신 순번을 쓰고 빠진 사건이 오면 평가한다’는 설명만으로 결합 반론을 넘기는 어렵다.** 이번 가장 가까운 원문은 사건 개수에 따른 진행값, 미확정 선행 사건 때문에 제한되는 읽기, 기록 완결 여부에 따른 결과 생성, 학생의 힌트·응답 순서와 능력별 분석을 이미 설명한다. 남는 대조 대상은 단순 순번 자체가 아니라 **어떤 사건 범위를 해당 녹음의 평가 조건으로 닫고, 그 완결 여부와 도움의 적용 범위가 같은 녹음의 목적·능력별 기여에 어떻게 결합되는가**다. 아래 3건에서 이 전체 관계를 그대로 확인하지 못했지만, 그것이 신규성·진보성 인정의 증거는 아니다.

## 1. 현재 입력과 검토할 전체 관계

현재 `core.cjs`의 `exposureScopeConfirmed`는 외부 입력으로 설정되고(152·164·203·210행), 수행 평가에서 321행의 보류 조건으로 사용된다. 482행은 ASR 자료 목적에 이 값을 적용하지 않는다. 130행의 기존 `sequence = session.eventLog.length + 1`은 사건 적용 시 원장 길이에서 정한 값이므로, 다른 경로로 지연 수신한 사건의 실제 앱 내 발생 순서를 증명하는 로컬 순번과 같지 않다.

이번 후보를 다음 관계로 고정해 대조했다. 이 항목은 요구한 발전 가설이며, 구현 완료나 사람의 창작 사실을 주장하지 않는다.

1. 같은 앱 세션·판본 안에서 도움 표시와 녹음 시작·종료에 단조 증가 순번을 부여한다.
2. 제출이 자신에게 필요한 관측 범위의 시작·끝, 녹음 식별자와 시도를 참조한다.
3. 서버는 그 범위 안의 빠진 순번·충돌을 검사하고, 완결되지 않았으면 해당 범위의 부재를 전제로 하는 독립 수행 판단을 보류한다.
4. 누락 사건이 도착하면 수신 시각이 아닌 로컬 발생 순서와 도움의 적용 능력을 대조한다.
5. 같은 원음의 전사 자료 자격과 능력별 독립 수행 기여를 각각 다시 계산한다.

## 2. 새로 직접 읽은 원문 3건

### W1. Watermarking of events of an ordered event stream — 가장 가까운 완결 조건

- **읽은 원문:** [US11360992B2](https://patents.google.com/patent/US11360992B2/en), 등록공보 **2022-06-14**. 목록상 A1 공개 **2021-12-30**(US20210406273A1). 이번 본문 대조는 B2 기준이며, A1 본문과의 문구 일치는 별도 대조하지 않았다.
- **위치:** 청구항 **1·9·14~17**, 상세설명의 도1 직전 ‘progress … metrics other than time’ 문단, 도1의 단일 segment·(K+1) 사건·transaction·progress 설명, 도2의 지연 commit 예. HTML 본문 읽기 위치 540~613행, 청구항 788~825행.
- **개시 내용:** 미확정 transaction의 사건 상태에서 effective progress를 계산하고, 그 watermark로 다른 사건의 읽기 허용을 정한다. 진행값은 시간에 제한되지 않으며 **사건 개수**도 청구한다. 단조 진행, 처음부터 경계까지의 committed 사건 수신, 나중에 확정되는 앞선 사건 문제를 설명한다.
- **직접 겹침:** 늦은 앞선 기록을 빼고 뒤의 자료를 사용하면 불완전하다는 문제와, 이를 막는 수신·사용 경계. ‘클록 동기화 대신 숫자 순서’라는 차이만으로는 부족하다.
- **남는 차이:** 저장 transaction의 commit 상태와 읽기 권한을 다룬다. 앱 표시·녹음 시도의 귀속, 도움의 능력 범위, 같은 녹음의 ASR/독립 수행 분리 자체는 해당 독해 범위에서 확인하지 못했다.

### W2. Offset-based watermarks for data stream processing — 순서·완결과 결과 생성

- **읽은 원문:** [US20240289385A1](https://patents.google.com/patent/US20240289385A1/en), 공개 **2024-08-29**. 관련 B1의 공개일 2024-08-13은 목록에서만 확인.
- **위치:** Background의 지연·비순차 입력 문제, Detailed Description의 completeness 및 offset 정의, 도4~6과 Interface of Vertices, 청구항 **1~7**. HTML 369~405·424~489·524~555행.
- **개시 내용:** timestamp와 offset을 함께 전달하고 처리 단위별 진행값을 모아 유효 watermark를 계산한다. 앞선 요소가 모두 처리되어야 해당 값이 유효하다고 설명하며, 순서 혼동에 따른 부정확한 결과 생성 문제를 명시한다. offset의 예로 동기화 barrier도 든다.
- **직접 겹침:** 이미 도착한 뒤쪽 기록만 보고 완결이라 하지 않고, 위치 정보를 사용해 처리 경계와 출력 가능 여부를 정하는 관계.
- **남는 차이:** 시간 정보도 사용하며, 여러 처리 노드·pod의 watermark 전파가 중심이다. 단일 앱에서 실제 표시와 녹음을 같은 순번에 편입하는 캡처 계약이나 학습 기여 분리를 그대로 보여 주지는 않는다.

### W3. Analytical tools for evaluating student learning and performance — 교육 측 결합 동기

- **읽은 원문:** [US9558675B2](https://patents.google.com/patent/US9558675B2/en), 등록공보 **2017-01-31**. 목록상 A1 공개 **2014-06-19**, WO 공개 **2013-02-21**. 이번 본문 대조는 B2 기준.
- **위치:** 도1의 student-learning data·knowledge component 설명, clickstream 예, 청구항 **1·6·10·21**. HTML 419~447·595~620·656~676행.
- **개시 내용:** 힌트 요청과 학습 자료 시작·정지 등의 상호작용을 기록하며, 같은 문제의 여러 응답을 구분하고 문제→힌트→문제 재방문 순서를 보존한다. 문항·활동을 능력 요소에 대응시키며, 청구항 21은 여러 기기의 복수 데이터 스트림 자동 처리를 포함한다.
- **직접 겹침:** 단순 정답 이외에 도움·시도 순서를 분석해야 하는 이유, 그 기록과 능력별 해석을 연결하는 인터페이스.
- **남는 차이:** 베이지안 학습 상태 추정이 중심이다. 사건 누락 완결 경계를 독립 수행의 자격에 직접 적용하거나, 늦은 도움 때문에 같은 녹음의 특정 기여만 철회하는 처리는 직접 확인하지 못했다. 힌트 순서 기록을 ‘독립 수행 제외’와 동일하다고 쓰지 않는다.

## 3. 결합 반론과 재반론

**순번 누락의 더 직접적인 보충 원문:** [US20150341422A1](https://patents.google.com/patent/US20150341422A1/en), 공개 2015-11-26, 도 7의 stream validation·logical clock ordering 설명은 단조 논리 시계의 번호가 비면 재전송을 요청하고, 빈 번호가 채워질 때까지 뒤의 메시지 전달을 보류한다고 명시한다. 주담당이 해당 본문과 공개일을 직접 확인했다. 이는 전역 순서 배포에 관한 기술이며 앱의 실제 표시 완료나 학습 기여를 다루는 동일 발명이라는 뜻은 아니다. 다만 번호 누락 검사·채움 대기를 새 수단으로 내세울 수 없다는 판단을 더 직접 뒷받침한다.

**강한 반론:** W3와 같은 학습 분석은 이미 상호작용 순서에 의존하고 복수 스트림을 받는다. 따라서 늦게 도착한 도움 기록으로 입력 순서와 완결성이 깨지는 문제를 해결하려고 W1의 사용 경계나 W2의 처리 완결 조건을 적용할 동기가 있다. 단일 앱 세션별로 나누고 사건 개수를 쓰는 변경도 W1의 단일 segment·count 범위와 크게 멀지 않다. 완결된 입력에 기존 학습 평가 함수를 실행한다면 기대되는 데이터 일관성 개선으로 설명될 수 있다.

**재반론:** 서버가 저장한 사건의 정렬과 실제로 앱이 표시·녹음한 사건의 닫힌 관측 범위는 동일하지 않다. 결합에는 최소한 세션/재시작 식별자, 실제 표시와 녹음의 공동 순번 생산자, 제출의 범위 참조, 빠진 사건 검사, 도움 범위와 평가 소비자의 대응이 필요하다. W3의 통계 상태 추정을 그대로 연결한 결과가 원음별·목적별 자격 원장과 같다고 할 수도 없다. 전체 관계의 차이를 설명할 여지는 있다.

**재재반론 및 판단:** 위 인터페이스를 추가해야 한다는 사실만으로 구현이 어렵거나 창작적이라고 결론낼 수 없다. 상당 부분은 순서를 보장하는 입력 어댑터와 분야별 평가 규칙의 조합으로 읽힌다. 반대로 우리의 완성된 계약을 대조 구현에 모두 미리 넣어 같은 출력을 얻었다는 사실만으로 결합의 용이성을 확정해서도 안 된다. **현재 범위에서는 실무 결함을 보완하는 구체화이지만, 등록성을 결정적으로 보강했다고 보고할 근거는 부족하다.** 전체 독립항 후보의 필수 관계와 그 관계 때문에 생기는 효과를 추가로 대조해야 한다.

## 4. 구현 전에 해결해야 할 논리적 빈틈

아래는 이번 후보 자체의 설계 분석이며, 선행문헌이 그 해결을 모두 개시했다는 주장이 아니다.

| 반례 | 필요한 정의·동작 |
|---|---|
| 녹음 시작 순번부터만 검사하면 바로 전에 표시한 힌트가 범위 밖으로 빠짐 | 범위 시작점은 문항 진입 등 실제로 정당한 기준이어야 한다. 이전부터 유지되는 도움 상태가 있다면 그 기준 상태도 참조해야 한다. |
| 순번 12가 비었는데 11과 13이 도착 | 12의 내용을 모르면 어떤 능력을 도왔는지도 모른다. 누락 도움을 임의로 ‘조사만 관련’이라 가정해 과거형 독립 수행을 허용할 수 없다. 별도의 신뢰 가능한 범위 정보가 없다면 관련 독립 수행은 보류한다. |
| 동일 순번을 서로 다른 내용으로 재전송, 앱 재시작 후 순번 재사용 | 세션·재시작 식별과 같은 순번의 동일성 검사가 필요하다. 충돌 상태를 완결로 처리하지 않는다. |
| 힌트를 표시했지만 사건 생성 자체가 빠짐 | 연속 수신은 만들어진 기록의 빈칸을 검사할 뿐이다. 표시 경로와 기록 생성의 결합을 별도로 검증해야 한다. 단조 순번만으로 실제 표시 사실·모든 도움 부재를 보증하지 않는다. |
| 화면 표시 직후 녹음이 시작됐지만 비동기 콜백이 반대로 도착 | 순번을 어떤 실제 동작 시점에 부여하는지 정의해야 한다. 콜백 수신 순서만 붙인 값은 원래 문제를 되풀이한다. 녹음 중 표시도 별도 보류·구간 처리 규칙이 필요하다. |
| 범위는 다 도착했으나 ‘이 힌트는 조사에만 영향’이라는 태그가 틀림 | 수신 완결과 의미 범위 정확성은 별개다. 도움 내용·판본과 영향 범위 계약의 근거가 필요하다. |
| 사건이 영구 소실됨 | 서버는 스스로 ‘없었던 도움’으로 확정하지 못한다. 끝없는 대기 대신 보여 줄 상태와 재확인 경로는 제품 문제로 정하되, 시간 초과를 독립 수행 증명으로 바꾸지 않는다. |
| 다른 앱 세션·외부에서 도움을 받음 | 이 후보의 관측 경계 밖이다. 같은 앱 세션의 기록 완결을 사람의 모든 독립 수행 보증으로 확대하지 않는다. |

**보류와 철회의 충돌도 분리해야 한다.** 엄격한 수신 완결 조건을 처음부터 적용했다면, 닫힌 범위의 늦은 도움은 ‘보류→도움받은 수행 제외’ 전환이다. 그 범위가 불완전한데 이미 확정했던 기여를 같은 정상 경로에서 철회한다는 설명은 모순이다. 확정 후 철회를 유지하려면 과거 판본의 잠정 결과, 평가 범위 확장, 의미 정정 등 별도의 재평가 원인을 구체적으로 정의해야 한다. 새 경계 이후 순번의 도움만으로 이미 끝난 녹음을 소급 오염시키지 않는다.

## 5. 개발 효과를 확인할 유한 대조

추가 개발 여부는 이 문서에서 결정하지 않는다. 구현한다면 아래 대조는 등록성 입증이 아니라 결함 방지 효과와 작동 가능성을 검증한다.

- 동일 실제 이력을 정상·역순·누락 후 도착으로 공급: 범위 완결 후 목적·능력별 결과가 같아야 한다.
- 늦은 앞선 도움 대 녹음 종료 뒤 도움: 앞선 도움만 관련 수행의 독립성에 영향을 주어야 한다.
- 같은 원음·같은 시도의 전사 자료와 수행 기여: 관측 범위 누락만으로 원음의 모든 자료 자격을 함께 없애서는 안 되며, 각 목적의 다른 필수 조건은 계속 검사해야 한다.
- 엄격한 범위 완결을 수행하는 일반 대조 구현에 같은 평가 규칙을 연결: 동일·차이 모두 기록한다. 동일 결과는 특수 알고리즘의 필요성 주장을 약화하지만 법적 진보성 기각과 같은 말이 아니다.
- 표시 후 기록 누락, 세션 재시작, 순번 충돌, 녹음 중 도움, 의미 범위 오류: 단순 순번 검사로 검출 가능한 경우와 불가능한 경우를 구분한다.
