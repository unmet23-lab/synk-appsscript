# LOOM 예비안 — 같은 입력을 받은 합성과의 비교 판단

2026-09-13 · 제한된 독립 재검토 · 코드/승인 출력 읽기 및 고립된 기록만 생성

**현재 근거로 LOOM을 회사의 첫 등록 우선 후보로 승격하지 않는다. 예비안으로 보류한다.** 같은 공통 바탕·눈 윤곽·경계 가중치를 주면 현재 RGB 합성식은 통상적인 가중 합성과 같다. 그러나 역사적 입력 일부가 없거나 바뀌어, 이번에 동일 입력의 8컷 재합성 결과까지 확인한 것은 아니다. 기존 승인 출력의 보존·국소 불변성은 다시 확인했다.

이 결론은 회사 전체 후보의 등록 우위를 확정하거나 LOOM의 등록 불가를 판정한 것이 아니다. 입력 복원 문제도 특허성 판단과 구분한다.

## 1. 사용한 현재 기준과 코드

`AGENTS.md`, `docs/AI_운영원칙.md`, `DESIGN.md`의 표정 전환 규칙, `docs/캐릭터/캐릭터_생명감_설계.md` §1-a, 대표 수정 보고와 `B_ALTERNATIVE.md`를 대조했다. 현재 기준은 공통 바탕·좁은 눈 변화 영역·전체 알파 고정이다. 넓은 얼굴 창을 복사하는 과거 방법을 현행 대표 합성으로 재사용하지 않았다.

현행 프로필은 까몽 / 여름 델+전설의 팻말 / 8표정이다. 다른 차림과 캐릭터 전체가 수정·승인되었다고 확대하지 않는다. 대표 승인의 과거 기록은 수정 보고에 있으며 이번에 사용자 승인 대화 자체를 새로 확인하지는 않았다.

## 2. 식으로 확인되는 것

현재 `라디오털고정.py:81`의 `feather`는 이동한 눈 마스크의 안쪽 거리 `d`로 `a=clip(d/1.6,0,1)`을 만든다. `:87`의 `blend`는 바탕 P와 눈 소스 S를 다음과 같이 섞는다.

`C_RGB = round((1-a) × P_RGB + a × S_RGB)`

`C_alpha = P_alpha`

좌우 눈을 순서대로 적용하고, 모든 표정에서 같은 복원 바탕 P를 사용한다. 마스크 밖은 `a=0`이므로 P가 유지된다. 모든 이동된 눈 마스크의 합집합 밖에서는 각 표정의 RGB가 같으며 전체 알파도 같다. 이는 **같은 입력·가중치·좌표·연산 순서·반올림 규약을 받았을 때의 식 수준 관계**다. 임의 합성 프로그램의 기본 설정까지 같은 결과라는 뜻은 아니다. 예컨대 8비트 가중치 양자화나 다른 부동소수점 정밀도는 경계 반올림을 달리할 수 있다.

기존 근접 문헌 [WO2014088871A1](https://patents.google.com/patent/WO2014088871A1/en)의 [0072]~[0078]을 이번에 다시 읽었다. 이 문헌은 소스/타깃에서 직접 가져올 화소와 혼합 영역을 나누고, [0077] 식(3)에서 `Ic = a Is + (1-a) It`를 제시한다. 공개일은 2014-06-12다. [0068]~[0069]에는 부분 영상 정렬, [0073]에는 눈 등의 일부 특징만 포함하는 마스크도 있다.

따라서 “눈 소스와 바탕을 가중 합성하고 마스크 밖을 보존한다”는 연산 자체를 새 차이로 삼기 어렵다. 다만 그 문헌의 그래프 컷/혼합 영역과 현행의 수동 윤곽·안쪽 거리 가중치는 같다고 단정하지 않는다. **기본 표정까지 공통 복원 바탕을 공유하고, 복원 구멍과 실제 변화 영역을 구분하는 전체 관계**를 그 문헌 하나가 직접 개시하는지는 이 식 비교만으로 판정할 수 없다. 기존 문헌 전체 구현을 재현한 비교라고도 표시하지 않는다.

이번 추가 검색에서 별도의 더 가까운 문헌을 확정하지 않았다. 위 D1의 구체 식과 기존 구현을 우선 대조했으며 검색 제목만으로 새 문헌 수를 늘리지 않았다.

## 3. 공정 비교군의 조건

비교군에는 LOOM과 같은 다음 입력을 준다.

- 동일한 공통 복원 바탕과 동일한 전체 알파.
- 동일한 표정 소스와 응원 오른눈 복구용 참고 원본·등록값.
- 열린 눈의 동일 수동 윤곽, 닫힌 눈의 동일 색·연결성 선택 조건.
- 동일한 눈 정렬 기준과 안쪽 feather 폭 1.6, 합성 순서·수치 정밀도.
- 동일한 출력 크기 변환과 무손실 출력 조건.

이때 다른 합성 계산이 같은 결과를 만들 수 있는지를 보는 것은 **주어진 재료의 처리 효과를 비교하는 실험**이다. 공통 복원 바탕과 윤곽이라는 중요한 입력 관계를 이미 비교군에 제공한다. 그 관계를 선행기술로부터 독립적으로 고안해 냈는지 조사하는 실험이 아니다.

현재 바탕 자체를 입력으로 주므로 바탕을 생성하는 과정의 우월성은 비교하지 않는다. 바탕 복원부터 별도로 비교하려면 같은 역사적 원본과 동일한 복원 영역/털 표본을 먼저 확보해야 한다. 불리한 넓은 얼굴 창만 비교군으로 삼거나, 비교군에만 정확한 눈 윤곽을 주지 않는 실험은 채택하지 않았다.

처음 두 실행은 각각 누락 파일, 참고 원본 지문 불일치에서 종료됐다. 이 실행들은 성공한 합성 실험으로 세지 않는다. 이후 입력 문제를 모두 기록하는 preflight로 정리하여 결과 JSON을 남겼다. 그 실행의 종료 코드 0은 진단 기록 저장의 성공이며 **`comparisonExecuted:false`**다. 비교용 8컷 생성 경로는 실행되지 않았고, 그 경로의 결과 정확성을 검증했다고 보고하지 않는다.

현행 `ensure_files`는 누락 원본을 Drive에서 운영 원래 경로로 복원할 수 있으나 이번에는 호출하지 않았다. Drive 다운로드, 기존 원본 복원, 자산 갱신, 운영 생성기 실행으로 범위를 확대하지 않았다. 저장된 최종 출력에서 눈을 다시 떼어 비교 입력으로 삼는 방식도 채택하지 않았다. 그러면 독립 비교가 순환 확인이 되기 때문이다.

## 6. 첫 출원 후보로 승격할지의 결정

| 질문 | 현재 답 |
|---|---|
| 실제 사업에서 쓴 구현·산출물이 있는가? | 예. 대표 8컷과 현재 코드/참조 경로가 있음 |
| 현 합성식이 통상적인 가중 합성과 다르다는 근거가 있는가? | 현재 식 비교에서는 없음. 같은 가중치·입력이라면 식 수준에서 같음 |
| 같은 조건의 독립 재합성으로 현 결과와 동일함을 실측했는가? | 아니오. 역사적 입력 누락·지문 불일치로 비교 미완료 |
| 출력이 같으면 전체 구성의 자명성이 입증되는가? | 아니오. 제공한 입력 관계의 도출 동기·필요 변경·사후적 고찰은 별도 판단 |
| 다른 회사 후보보다 등록하기 유리하다는 현재 비교 근거가 있는가? | 없음 |
| 이번 결정 | **등록 우선 후보로 승격 보류. 기술 설명이 가능한 예비안으로 유지** |

남는 상담 질문은 하나다. **“기본 표정까지 공통 복원 바탕을 공유하고, 복원용 구멍과 실제 표정 변화 영역을 분리하는 구체 관계가, 기존 부분 표정 교체·마스크·통상 합성으로부터 쉽게 도출되지 않는가?”** 답을 뒷받침하는 선행 대조가 없으면 합성 기능을 추가하여 우선 후보를 억지로 만들지 않는다.

이번 유한 범위의 결과는 코드 지문 대조, 식의 관계 확인, 입력 재현 제약 확인, 승인 출력 보존 확인 및 승격 보류 판단이다. 원본 누락 복구·새 합성 비교·운영 반영·새 디자인 제작·최종 등록성 판단은 수행하지 않았다.
