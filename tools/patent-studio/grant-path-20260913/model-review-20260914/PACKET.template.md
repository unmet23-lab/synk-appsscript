SYNK CORE에서 준비한 **음성 학습 기록의 기여 정정 방식**을 주안으로 검토한다. 같은 녹음이라도 사용할 목적과 능력별로 자격을 나누고, 뒤늦게 확인된 도움의 발생 시점·범위에 따라 잘못 반영한 기여를 정정하는 방식이다. 이 문서는 발명 설명, 현재 청구 문안, 구현·실험 근거, 가까운 선행, 발전 가설과 검토 질문을 한곳에 모은다.

목표는 **실제 사업에 쓰는 기술로 특허 등록 한 건을 확보할 수 있는 경로를 찾는 것**이다. 사업상 우선 가치는 마케팅과 기업 신뢰다. 넓은 독점 범위보다 등록 요건을 충족하는 구체적인 처리 관계를 우선한다. 등록을 보장하거나 성공 확률을 측정한 문서는 아니다.

## 01. 검토의 기준과 고정된 사실

**SYNK ATLAS는 엔진 전체를 묶어 부르는 이름이며, 이 문서의 주안은 CORE의 기록 처리다. LOOM의 시각·표정 합성은 별도 예비 후보다.** 회사 전체 시스템이 이 문서의 실험 모듈과 동일하거나 모두 운영에 통합됐다는 뜻은 아니다. 엔진명과 기술적 발명의 명칭도 구분한다.

| 구분 | 검토에 사용할 사실 |
|---|---|
| 사업 목표 | 한국 특허 등록 한 건을 통한 마케팅·기업 신뢰. 실제 사업과 연결되는 좁은 청구도 검토 가능 |
| 개발 허용 | 효과가 있는 추가 개발은 규모를 크게 제한하지 않음. 개발량 자체를 등록 가능성의 대리 지표로 삼지 않음 |
| 전문가 의견 | 담당 변리사로부터 구체적인 청구 방향·선행 검토 의견을 아직 받지 않았다는 사용자 답변이 있음 |
| 설계 경위 | 사용자는 혼자 작업했다고 답함. 모든 후속 AI 제안을 사용자의 과거 직접 설계로 소급하지 않음. 구체 현장 사례는 제공되지 않았으므로 아래 사례는 설명용 또는 합성 입력으로 표시 |

## 02. 현재 P1을 쉬운 사례로 이해한다

**힌트를 실제로 본 시각과, 그 사실을 서버가 알게 된 시각은 다를 수 있다.** 이 두 시각을 혼동해서는 안 된다. 다음은 작성한 합성 입력이며 실제 학생·마이크·교사의 관측이 아니다.

| 시각 | 작성한 사건 | 처리상 의미 |
|---|---|---|
| 09:59:30 | 조사 답 ‘친구를’을 보여줬다고 기록 | 도움의 발생 시각. 대상은 조사로 제공 |
| 10:00:00-10:00:10 | ‘친구를 만나서 카페에 갔어요’ 녹음 구간 | 평가대상 원래 발화의 고정 구간 |
| 10:00:21까지 | 원음·전사·범위·문항 조건을 확인했다고 입력 | 아직 늦은 도움 사건은 반영되지 않은 기준 상태. 세 기록 모두 반영 |
| 10:05:00 | 09:59:30 도움 사건을 뒤늦게 처리 | ‘발화 전 조사 도움’을 계산하여 조사 기여 철회. 다른 조건을 만족하는 과거형과 원음–전사 기여 유지 |

현재 처리 흐름은 **기록 수신 → 시도·시간·범위 대조 → 목적/능력별 사유 수집 → 자격·관측값 결정 → 전후 기여 비교 → 원인과 판본 저장**이다.

‘조사 도움’이라는 입력만으로 과거형을 자동 인정하지 않는다. 저장된 독립 확인값, 전사 후보별 과거형 관측값의 일치, 다른 보류·제외 사유의 부재 등을 함께 요구한다. 시각이 불명확하거나 발화 구간과 겹치면 보류하는 경로가 있다. 발화가 끝난 뒤에 실제로 처음 제시한 도움을 과거의 도움으로 만들어 넣어서는 안 된다.

### 논리 기록과 책임

| 기록 | 현재 주요 값 | 생성·소비의 책임 |
|---|---|---|
| 발화·시도 | 원음 참조, 발화 ID, epoch, 수행 구간, 전사 후보, 확인값 | 녹음·전사·확인 입력 → Core의 평가 대상 |
| 도움 | 사건 ID, 명시된 발생 시각/범위, 답 노출 여부, 대상 능력 | 해당 시간정보를 받은 경로에서 시간·범위 판정. 아래의 시각 기본값 한계를 함께 검토 |
| 판정 셀 | 목적, 능력, 상태, 값, 후보별 효과, 사유, 의존 입력 | Core 평가 → 화면·전이 기록 |

**시각 계약의 구현 한계:** Studio 저장 계층은 `event.at`이 주어지면 보존하지만, 없으면 서버 현재 시각을 기본값으로 넣는다. 이 기본값은 실제 도움 발생 시각의 확인을 대신하지 않는다. 세션 조회의 `recordedAt`은 평가 후 서버에 저장한 시각이며 정밀한 네트워크 도착 측정값이 아니다. 위 10:05 수신은 합성 시험에서 지정한 처리 순서·표시용 시각이다. 실제 전송 계층의 수신 시각 측정까지 시험한 것으로 해석하지 않는다. P1-03의 시간정보 계약과 이 누락 경로의 차이도 Q05·Q14에서 검토한다.

### 현재 코드 위치와 기존 연결

`tools/patent-studio/core.cjs`는 사건 적용, 제한 문장 해석, 사유 수집과 판정을 수행한다. `temporal-evidence.cjs`는 시간구간 관계를 분류한다. `projection.cjs`는 입력 기반 재사용과 기여 전이·원장 재현을 담당한다. `store.cjs`는 전체 사건 payload와 판본 등을 SQLite에 저장한다. `public/app.js`와 `server.cjs`는 녹음·전사·확인·도움 표시의 로컬 UI/API를 연결한다.

기존 연결 검토에서 도움 표시 모달, 마이크 시작·종료, 원음 재생, 원음/응답 확인 경로를 확인했다. 다만 사람의 실제 청취·인지, 모든 화면의 답 노출, 관측 계획과 실행·반환 결과를 한 묶음으로 검사하는 전체 연결은 별도다. 형제 학습 앱에는 원음 참조·시도 번호·부모 사건을 다루는 기존 경로가 있지만 이 특허 실험 모듈의 운영 통합 완료를 의미하지 않는다.

이 문서의 구현 근거는 부록의 현재 코드 발췌와 아래 실행 자료다. 파일명만 제시된 미첨부 파일의 전체 내용을 읽었다고 답해서는 안 된다. 연결 검토의 당시 원문은 자료 목록 S06에 기록한다.

## 05. 실제 실행 근거와 한계

### E01 · P1의 세 가지 합성 입력

{{P1_CASES}}

이 실행은 기존 Core API와 기여 전이 함수를 호출한 것이다. 원음 파일을 읽거나 실제 마이크·청취·도움 표시·운영 DB 수신을 시험한 것이 아니다. 전사 후보는 세 사례 모두 하나다. 도움의 능력 범위와 독립 확인값 역시 작성한 입력이다.

### E02 · 복수 후보의 관측값

기존 두 후보 ‘친구를/친구가 … 갔어요’는 조사 관측값이 다르고 과거형 관측값이 같다. 기존 `third-candidate` 실험에서 ‘친구를 … 가요’를 추가하면, 독립 확인값이 참이어도 최초 과거형 판정은 **보류 / effect-disagreement**다. 이후 결과가 같은 것은 부족한 원음 확인 구간의 결과를 거절했기 때문이다. 세 후보를 성공적으로 검토·확정한 시험으로 세지 않는다.

### E03 · P2 계약 어댑터 검증

기존 저장 결과: **22개 관련 테스트 통과, 6개 합성 시나리오, 일반 검사/표지 라우팅 9쌍의 결과 일치**. 같은 입력과 정책을 제공한 이 비교에서 출력 우월성은 입증되지 않았다. 실행 방식의 동일 출력이 입력 계약 자체의 자명성까지 증명하는 것은 아니다. 이번 문서 제작에서 22개 테스트 전체를 새로 실행한 횟수로 보고하지 않는다.

### E04 · 목적 변경 검사

기존 2후보·3후보 사례에서 목적만 바꾸면 Core의 대상은 바뀔 수 있지만, 현재 P2 어댑터의 **원음 확인 범위·결과 종류는 같았다**. 목적별로 서로 다른 최적 확인 범위를 찾아냈다는 효과를 주장하지 않는다.

### E05 · 원음–전사 기여 유지와 계산 생략의 차이

{{CACHE_PROBE}}

### E06 · 음성 연결과 비용 자료의 경계

## 06. P2 대안과 현재 청구 문안

P2는 **전사 후보에 따라 판정이 달라지는 경우, 확인할 원음 구간과 반환 결과의 적용 조건을 함께 만드는 방식**이다. P1의 모든 요소를 포함하는 하위 청구범위가 아니라 다른 문제를 다루는 대안이다.

현 어댑터는 모든 확인 대상·후보 쌍을 고려하며, 단어-원음 대응이 유효하지 않으면 전체 원음 확인으로 돌아간다. 허용 결과 종류는 **source-audio-review로 고정**이다. 제출된 원음·시도·판본·후보 집합·확인 범위를 대조하지만 실제 청취나 의미의 진실성을 인증하지 않는다. 해시만으로 서버의 진짜 계약임을 인증할 수도 없다. 신뢰할 수 있는 저장 상태와 대조하는 연결이 필요하다.

가칭: **음성 후보의 목적별 평가 차이에 따른 원음 재검토 계약 생성 및 결과 적용 방법**

하나 이상의 프로세서와 저장장치를 이용하여 음성 기록을 갱신하는 방법으로서,

{{P2_CLAIMS}}

를 포함하는 원음 재검토 계약 생성 및 결과 적용 방법.

현재 상한은 후보 H≤40, 후보 단어 W≤512, 정렬 항목≤200이다. 후보 쌍의 차이 비교에 O(H²W²) 성격의 비용이 있다. 이는 전체 운영 처리량이나 더 빠름을 뜻하지 않는다. 앱 UI·계약 지속 저장·실행 결과 수신과의 전체 통합은 미완료다. 기존 직접 원음 확인 경로가 새 계약을 통과했다고 설명해서는 안 된다.

## 07. P3·LOOM·관측 범위 보강 후보

### P3 · 확인 행동 자체가 새 증거를 만드는 문제

‘예전 녹음을 다시 듣기’, ‘정답을 보여준 뒤 새로 말하게 하기’, ‘교사에게만 자료 보여주기’는 반환 결과의 뜻이 다르다. 원음 청취 결과는 과거 발화를 확인할 수 있지만, 정답을 본 뒤의 새 응답은 과거의 독립 수행을 소급해서 입증하지 않는다. 교사에게만 보인 내용과 학생이 본 내용도 구분해야 한다.

발전 가설은 확인 행동의 정보 가치·답 노출·대상자·새 수행 발생을 함께 보고 행동과 결과 사용 조건을 정하는 것이다. **실제 실행 이력으로 이러한 조건을 공동 산출하는 전체 연결은 미구현**이다. 현재 planner의 행동 표지와 P2의 고정 결과 종류를 그 구현이라고 포장하지 않는다. 학습에 영향을 주는 행동 선택에는 이미 가까운 POMDP 교수 연구가 있으므로 ‘관측이 증거를 바꾼다’는 철학만으로 새롭다고 판단하지 않는다.

### LOOM · 공통 바탕을 보존하는 표정 합성

현재 대표 검토 범위는 공통 복원 바탕과 좁은 눈 변화 영역을 사용하는 8표정이다. 안쪽 경계 가중치 `a=clip(d/1.6,0,1)`, `C_RGB=round((1-a)P_RGB+aS_RGB)`, `C_alpha=P_alpha` 관계를 쓴다. 같은 입력·수치 규약을 준 가중 합성과 식 수준에서 같다. 여러 표정의 공통 바탕·복원 구멍·실제 변화 영역의 관계를 별도로 검토해야 한다.

저장된 승인 출력 8컷의 지문과 변화 영역 밖 RGBA·전체 알파 보존은 확인됐다. 역사적 입력 8장과 의상 원본이 없고 참고 2장의 지문이 달라 **동일 입력 독립 재합성은 실행되지 않았다**. 이 상태는 LOOM 전체가 미구현이라는 뜻도, 첫 등록 후보로 더 유리하다는 뜻도 아니다. 현재 결과를 잘라 다시 입력으로 쓰는 순환 비교는 피한다.

### 관측 범위의 수신 완결 조건

수동 범위 확인값을 실제 사건 수신 상태와 연결하는 보강안은 세션·재시작 판본, 단조 순번, 표시/녹음 단계, 시도, 대상자, 제출이 요구하는 끝 순번 등을 함께 다루는 설계다. **현재 구현 확정안은 아니다.** 빠진 순번 대기·watermark 자체에는 가까운 선행이 있다.

엄격하게 모든 도움 기록이 올 때까지 반영을 미루면, 같은 범위의 정상 경로는 ‘반영 후 철회’가 아니라 ‘보류 후 반영/제외’가 된다. 이를 P1과 결합할 때는 왜 나중의 정정이 필요한지 별도 사건·범위를 설명해야 한다. 연속 번호가 있다는 사실만으로 생산자가 현실의 모든 표시를 기록했다는 증명이 되지 않는다.

## 08. 가장 가까운 선행과 남는 질문

아래는 이전 원문 조사와 09.14 추가 검토의 **출발점**이다. 검토자는 관련 원문을 직접 열고 기재 내용·읽은 위치·문헌 발행 시점을 다시 확인한다. B2를 읽은 항목의 같은 계열 A1 문구가 동일하다고 자동 가정하지 않는다. 한 문헌의 부분 대응을 전체 동일성으로 확대하지 않는다.

### D01 · 학습 사건의 지연·재처리

[US20180315330A1](https://patents.google.com/patent/US20180315330A1/en), 2018.11.01. **도13 Learning Event Processing**, 이후 부분집합·스냅샷 설명, 청구항 1-5·12-14. 사건을 일부/전체 처리 경로로 보내고 필터링·분할한다. 가장 이른 신규 사건 이후 구간을 재처리하며 상태 스냅샷도 설명한다.

따라서 ‘선행은 항상 전체 이력 재계산, 우리는 일부만’이라는 대비는 부정확하다. 남는 질문은 원음·시도·도움의 능력 범위와 개별 기여 정정 조건의 결합이 통상적인 분석 처리기로부터 도출되는가다.

### D02 · 힌트와 지식 추적

[US10943497B2](https://patents.google.com/patent/US10943497B2/en), B2 2021.03.09. **도2, 식(2)-(10), 식(10) 바로 뒤 학습 손실 설명**, 청구항 1·4·5·8·11·12·15·18·19. 개념별 메모리와 관련 가중치, 삭제·추가 갱신을 다룬다. 힌트 사용 시 힌트 예측 손실만 전파하고 지식 추적 손실은 0으로 둔다. 출력층을 제외한 가중치를 공유한다.

따라서 한 작업의 손실 0을 다른 출력의 완전한 불변성이나 과거 관측 기여의 철회와 동일시할 수 없다. 동시에 ‘용도별로 다르게 쓴다’는 넓은 주장만으로도 부족하다.

### D03 · 목적별 접근 철회·유지

[US11144665B2](https://patents.google.com/patent/US11144665B2/en), **청구항 1·2·5·6, 도2B 260-280**. 한 목적의 접근 경로를 철회하면서 다른 목적의 접근을 유지한다. 이미 반영한 개별 음성 관측값의 정정과는 다르지만, 접근 정책을 평가 자격에 연결하는 변경이 통상적일 수 있다는 반론을 검토해야 한다.

### D04 · 실제 발화·최종 전사의 분리와 원음 확인

[US20030004724A1](https://patents.google.com/patent/US20030004724A1/en), 2003.01.02. **[0010]-[0011], [0098]-[0109]**. 실제 발화의 전사와 최종 문장을 분리하고, 전사 차이에 대응하는 원음을 확인하며, 수정 결과를 연동하거나 따로 갱신한다. P2의 원음 확인·용도 분리와 특히 가깝다. 결과가 어떤 목적에 쓰이는지의 태그·계약 객체 추가만으로 차이가 성립하는지 심문한다.

### D05 · 변경 입력에 따른 선택적 재계산

[Acar·Blelloch·Harper, Adaptive Functional Programming](https://www.cs.cmu.edu/-guyb/papers/popl02.pdf), POPL 2002. **§4, 그림 5, PDF 4-6쪽**. 의존 관계를 따라 변경 입력의 관련 계산을 다시 실행하고, 대상 값이 바뀔 때 후속 변경을 전파한다. 순서·포함 관계를 관리한다.

일반적인 의존 그래프, 관계 있음/없음의 0·1 표시, 무관한 계산 생략 자체를 새 기법으로 주장하지 않는다. 학습 도움의 범위에서 필요한 의존 관계를 도출하는 구체 규칙과 보존·정정 정확성에 차이가 있는지가 질문이다.

검토자는 선행의 원래 목적·입력에서 시작해 필요한 변경을 적어야 한다. 우리 완성안을 이미 알고 부품을 역으로 모으는 사후적 설명도 피한다. 반대로 구성 요소가 많거나 같은 긴 문장이 검색되지 않는다는 이유로 등록성을 인정하지 않는다.

## 10. Gemini 추가 제안의 정확한 검토 대상

검토받은 제안은 다음 관계다. **단일 음성의 토큰을 능력별 세션 배열에 매핑 → 지연 힌트와 노드의 시간/의미 관계를 0·1 가중치로 계산 → 임계치를 넘는 노드만 이전 스냅샷으로 복원 → 나머지 노드는 계산을 생략하고 확정.** 제안에는 등록 가능성 40-50% 및 단순 결합을 완벽히 방어한다는 표현이 있었으나, 이를 뒷받침할 확률 산출·선행 대조·실행 증거는 제공되지 않았다.

이는 **추가 설계 가설 G1**이다. 아래 지적도 검토자가 반박할 수 있으나, 반박에는 원문이나 실행 가능한 관계가 필요하다.

- D01은 전체 재처리만 하지 않으며, D02에는 이미 개념 메모리·가중 갱신이 있다. ‘메모리·벡터·가중치’라는 표현 추가 자체를 차별점으로 삼기 어렵다.
- 0·1이 단지 도움 대상 포함 여부라면 기존 조건문의 재표현이다. 의미상 관계를 새로 연산한다면 그 알고리즘·입력·불확실성·평가 근거가 필요하다.
- A 반영 후 유효한 B가 쌓였는데 A 이전으로 복원하면 B까지 지울 수 있다. 복원 뒤 재적용 또는 안전한 기여 분해·취소 관계가 필요하다.
- 조사 도움 확인 중 전사가 ‘갔어요→가요’로 수정되면 과거형도 바뀐다. 직접 도움 대상과 모든 계산 의존 입력은 다르다.
- 시간·대상 범위가 불명확할 때 0 또는 1만으로 독립 수행을 확정해서는 안 된다. 영향과 불확실성을 분리해야 한다.
- 별도 메모리 배열이 계산·학습의 독립성을 보장하지 않는다. 공유 가중치·전사·집계·후속 이력의 영향 범위를 밝혀야 한다.
- 전체 노드 검사·의존 그래프 유지·복사·재적용 비용까지 합쳐야 자원 절감 여부를 판단할 수 있다. 최악의 경우 전체 재계산이 필요할 수 있다.

**G1 채택을 가를 질문:** 기존 선택 재계산기보다 다른 의존 관계를 어떤 입력에서 도출하는가? 같은 유효 입력을 전부 재평가한 결과와 같아지는 조건은 무엇인가? 그 정확성을 위해 필요한 최소 구성은 무엇이며, 그 구성에 선행 대비 차이가 남는가?

## 11. 검수·심문 질문 Q01-Q18

각 질문은 **결론 → 정확한 근거 위치 → 가장 강한 반론 → 그 반론에 대한 답 → 다음 결정을 바꿀 자료** 순서로 답한다. 확인 불가를 공란이나 긍정으로 대체하지 않는다.

### Q01-Q06 · 법적·기술적 거절 논리

**Q01 / 청구의 실체.** P1이 처리하는 구체적 기술 문제·입력·저장 구조·연산·출력을 5문장으로 재구성하라. 단순 교육 정책으로 읽히는 부분과 컴퓨터 처리 관계를 나누고, 하드웨어 협동을 위해 실제로 필요한 내용을 특정하라. ‘프로세서’라는 단어를 추가하는 것만으로 답하지 말라.

**Q02 / 신규성.** P1-01-07이 하나의 선행에 함께 있는지 문헌별로 대조하라. 각 칸은 직접 기재·내재적 기재·부분 기재·미확인으로 구분하고, 내재적이라면 필연적인 이유를 설명하라. 여러 문헌을 섞은 표를 단일 문헌의 동일성으로 결론내리지 말라.

**Q03 / 진보성.** 가장 강한 선행 조합 하나를 주공격으로 선정하라. 시작 문헌의 원래 문제, 추가 문헌을 볼 동기, 수정해야 할 구조·알고리즘, 결합의 어려움이나 저해 요인, 예측 가능한 효과와 남는 차이를 적어라. 가능한 강한 보조 공격이 있으면 하나만 더 제시하라.

**Q04 / 남은 차이의 가치.** 긴 사유 목록·세 상태·전후 값 비교·후보별 효과 일치·독립 확인 입력 중 무엇이 새 처리 관계이고 무엇이 통상적 정책인가? 각각을 제거한 대조 입력을 제시하고, 오류가 없으면 그 사실도 적어라. 필요조건임을 보여주는 것과 비자명함을 보여주는 것을 구별하라.

**Q05 / 기재요건.** ‘독립’, ‘범위 확인’, ‘능력’, ‘기여’, ‘고정 구간’의 정의·입력 생산자·판정 규칙·예외가 충분한가? 현 청구가 코드보다 넓거나 모호한 문장을 정확히 인용하고, 보완할 명세서 문장 및 필요한 도면·실시예를 제안하라. 완성 코드와 벤치마크가 모든 출원의 일률적인 필수조건이라고 만들지 말라.

**Q06 / 최소 한정.** P1을 유지할 근거가 있으면 독립항에 남길 최소 관계와 종속항으로 옮길 요소를 나누라. 기본안·한정안은 실제 포함관계를 설명하고, 좁혔을 때 해결되는 거절 이유와 여전히 남는 이유를 적어라. 글이 길어지는 것만으로 강화라고 하지 말라.

### Q07-Q12 · 대안과 실제 동작의 공격

**Q07 / P2.** D04·D06에 후보 평가·식별자·판본 검사·계약 객체를 붙인 정도로 읽히는가? 목적을 바꿔도 확인 범위가 같았던 E04를 반영하라. P2가 P1보다 우선될 조건 또는 보류할 이유를 문헌·구성 단위로 제시하라.

**Q08 / P3.** 원음 재검토, 정답 노출 후 새 응답, 교사만 보는 자료를 구분하는 현재 설계가 D11-D14와 어떻게 다른가? 정보 획득과 학습 변화의 공동 계획이라는 넓은 표현을 넘는 데이터·행동·결과 귀속 관계가 없다면 그렇게 결론내려라.

**Q09 / G1 부분 롤백.** D01·D02·D05를 함께 보면 무엇이 남는가? 후속 유효 기록, 공유 입력, 간접 의존성, 시간/범위 불명, 중복 이벤트를 포함한 대조 입력과 필요하면 수정 알고리즘을 적어라. 실제 결과와 예상 결과·미실행 여부를 구분하고, 실패하지 않으면 그 사실을 적어라. ‘노드를 분리한다’는 선언으로 독립성을 증명하지 말라.

**Q10 / 관측 범위.** D07-D10 이후에도 완결 조건 보강의 차이가 남는가? 처음부터 보류하는 정책과 반영 후 철회하는 P1을 연결하는 트리거를 설명하라. 단조 순번이 실제 표시 사건의 완전성을 증명하는지 공격하라.

**Q11 / LOOM.** 동일 공통 바탕·윤곽·가중치를 준 일반 합성과 무엇이 다른가? 공통 복원 바탕과 변화 영역의 관계를 D15와 대조하라. 재합성 미완료를 감안하여 우선 후보로 바꿀 조건을 적고, 현재 증거로 비교 불가하면 순위를 억지로 만들지 말라.

**Q12 / 사업 연관성과 선택.** P1·P2·P3·G1·LOOM 중 주안 하나와 예비안 하나 이하를 고르되 ‘현재 구현 증거’와 ‘특허요건상 차이’의 근거를 따로 적어라. 이 자료에 없는 회사 기능을 발명하지 말라. 다섯 후보 중 우열을 정할 수 없으면 어떤 사실 하나가 선택을 바꿀지 답하라.

### Q13-Q18 · 추가 개발과 최종 판단

**Q13 / 최대 세 가지 변경.** 등록 검토에 실질적으로 도움될 가능성이 있는 추가 변경을 최대 세 가지 제시하라. 각 변경마다 현재 한계 또는 실패를 드러내는 입력(실제 확인·예상·미실행 구분), 기존 선행으로 해결 가능한지, 최소 새 관계, 생산자→저장→소비자→출력, 구현/미구현, 예상 부담, 필요한 원문·시험을 적어라. 추천할 새 변경이 없으면 0개라고 답하라.

**Q14 / 정확성.** 제안 알고리즘이 반드시 지켜야 할 조건을 적어라. 예: 유효한 후속 기록 보존, 원래/새 시도 분리, unknown의 자동 인정 금지, 중복 정정 방지, 동일 유효 입력의 전체 재평가와 결과 일치. 반례를 통과할 수 있는 의사코드와 종료·실패·전체 재계산 복귀 조건을 제시하라.

**Q15 / 공정한 효과 검증.** 기준선, 동일 입력·정책·정밀도, 비용에 포함할 항목, 크기 변화, 실패 판정 기준을 제시하라. 기존 방식을 일부러 약하게 만들지 말라. 동일 결과는 정확성 비교이며 그 입력 관계의 자명성을 자동 증명하지 않는다. 성능 차이가 없거나 더 느린 경우의 의사결정도 적어라.

**Q16 / 최초 명세서.** 선택한 관계와 한정안을 설명하기 위해 출원 전에 추가할 도면·레코드·예외·실시예의 목록을 적어라. 기존에 명세서로 제출되지 않은 내부 코드가 있다고 나중의 보정 근거가 자동 확보되는 것으로 설명하지 말라. 별개 발명의 병합·분할은 단일성과 기재 근거를 검토한 경우에만 제안하라.

**Q17 / 확정할 수 없는 사실.** 사람의 실제 도움·청취, 입력 태그의 정확성, 법적 발명자/권리관계, 운영 통합 등 기술자료로 확정할 수 없는 항목을 짧게 분리하라. 이미 혼자 작업했다는 답변을 다시 요구하지 말고, 없는 현장 경험이나 인간의 구체 창작 사실을 만들어 빈칸을 채우지 말라.

**Q18 / 결론과 중단 기준.** 유지·한정·재설계·보류 중 하나를 현재 주안에 부여하고, 결론을 바꿀 조건 3개 이하와 지금 하지 않아도 되는 개발을 적어라. 등록 확률 숫자 대신 입증된 관계·강한 반론·미확인 항목으로 설명하라. 심사 통과가 보장되는 문안이라는 표현은 쓰지 말라.

## 12. 두 모델이 반환해야 하는 형식

**첫 페이지 / 결정 요약:** 검토일·모델 표기·실제 접근한 자료 범위, 우선 결론, 가장 강한 거절 논리, 남는 차이, 주안/예비안, 다음 행동 3개 이하. 이 문서의 모든 가설을 존중해야 한다는 전제는 없다.

**표 A / 선행 대조:** `청구 요소 | 원문·정확 위치 | 짧은 발췌 또는 충실한 요약 | 직접/내재/부분/미확인 | 기술적 차이 | 판단`. 명세서 전체의 기재와 청구항의 보호 범위를 혼동하지 않는다.

**표 B / 결합 공격:** `시작 문헌 | 결합 동기 | 필요한 변경 | 장애/반대 근거 | 예측 가능 효과 | 남는 차이 | 가장 강한 재반론`. 신규성 표와 분리한다.

**표 C / 문언·지원:** `문안 ID | 모호하거나 과도한 표현 | 현재 코드/시험 근거 | 제안 문언 | 추가 설명 | 독립/종속/실시예 후보`. 정확한 문장 대체안을 제공하되 현재 구현 여부를 표시한다.

**표 D / 개발 후보:** `변경 ID | 겨냥한 거절 이유 | 최소 기술 관계 | 직접 선행 | 데이터·알고리즘·연결 | 시험과 기각 조건 | 미구현 범위`. 도메인 이름·용어만 바꾼 제안은 제외 사유를 적는다.

**표 E / 불일치·미확인:** `쟁점 ID | 현재 판단 | 확인된 근거 | 없는 근거 | 판단을 가를 한 가지 자료 | 담당`. 지식 부족과 기술 결함을 구분한다.

**끝 / 의사결정:** 이번 상담에서 검토받을 주안 한 개, 예비안 한 개 이하, 변리사에게 전달할 핵심 질문 5개 이하. 채택할 근거가 부족하면 선택 불가도 완결된 답이다. 사람이 읽을 설명을 먼저 쓰고 코드·기호는 필요한 부분에만 둔다.

## 13. 답변 완결 기준과 교차 심문

답변은 다음을 만족해야 검토 결과로 사용할 수 있다. 관련 법과 사실을 확인하는 기준이며 등록 가능성을 점수화한 표가 아니다.

- 실제 읽은 자료와 읽지 못한 자료를 구분한다. 출처 번호·문단·수식을 확인하지 못한 직접 인용은 넣지 않는다.
- 구현·선언 입력·실행 출력·미구현 제안·법적 추론을 구분한다. 합성 입력을 학생 실증으로 바꾸지 않는다.
- ‘상대가 그렇게 말했으므로’ 또는 ‘두 모델이 동의하므로’를 근거로 쓰지 않는다.
- 불리한 동일 결과·누락 입력·미완료 비교도 유지한다. 현재 안을 지지하기 위한 시험을 만들지 않는다.
- 제안은 문제→처리 관계→결과→선행 대비 차이로 연결한다. 데이터 구조의 이름만 바꾼 제안은 채택하지 않는다.

### 교차 심문 요청문 · 상대의 첫 답변과 함께 복사

> 아래는 같은 종합자료로 받은 다른 모델의 독립 답변입니다. 당신의 첫 결론과 상대의 결론을 각각 유지한 상태에서 검토를 시작해 주세요. 상대의 주장 중 결론에 가장 큰 영향을 주는 다섯 가지 이하를 골라, 가장 강한 형태로 재구성한 뒤 직접 원문·청구 요소·코드·시험으로 심문해 주세요. 쟁점마다 동의/기각/판단유보, 정확한 근거, 구체 반례, 상대에게 묻는 답변 가능한 질문 하나, 결론을 가를 자료 하나를 남겨 주세요. 상대의 지적이 맞으면 당신의 기존 답변 중 무엇을 철회하거나 수정하는지 정확히 써 주세요. 새로운 미구현 관계를 기존 구현처럼 끼워 넣지 마세요. 단순 동의나 더 강한 표현으로 답하지 말고, 문서의 표 E 형식으로 차이를 남겨 주세요.

### 반박 답변 요청문 · 나에게 온 심문과 함께 복사

> 상대 모델이 당신의 답변에 제기한 아래 쟁점에 하나씩 답해 주세요. 각 항목을 수용/부분수용/반박/확인불가로 구분하고, 원문 또는 실행 가능한 반례를 제시해 주세요. 수용하면 청구 문안·개발 제안·결론 중 바뀌는 부분을 수정 전→수정 후로 보여 주세요. 새로운 가정을 사용했다면 표시하세요. 실제 추가 근거가 없으면 표현만 바꿔 기존 결론을 유지하지 마세요.

### 최종 결정 요청문 · 두 검토와 심문 결과를 모아 복사

> 두 모델의 독립 검토와 교차 심문 결과를 통합해 주세요. 다수결·평균 점수·평균 등록 확률을 쓰지 마세요. 확인된 원문과 구현 근거만으로 주안 한 개와 예비안 한 개 이하, 또는 선택 불가를 결정하세요. 채택/보류/기각된 주장과 이유를 남기고, 남은 불일치는 결론을 가를 구체 자료로 바꿔 주세요. 권고 문안은 현행 문안과 차이를 표시하고 추가 설계는 별도로 표시하세요. 이번 미팅에서 설명할 60초 문장, 가져갈 자료, 변리사에게 받을 결정 5개 이하, 개발을 시작하기 전 확인할 조건을 작성해 주세요. 실제 심사·등록·전문가 승인을 받았다고 표현하지 마세요.

1. 기준선 A는 같은 유효 원천과 같은 평가 규칙으로 전체를 재평가한다. 정확성 비교에 사용한다.

5. 재평가 결과, 새/철회/유지 기여, 전체 경과 시간, CPU 시간, 최대 메모리, 입력 탐색·해시·그래프 관리·저장 비용을 함께 기록한다. 워밍업과 반복 횟수·환경·원본 지문을 적는다.
6. 한 건이라도 잘못 유지·철회하거나 전체 기준과 의미상 불일치하면 정확성 주장을 보류한다. 비용이 줄지 않으면 절감 주장을 제거한다. 정확성·성능 통과 자체를 진보성 판정으로 바꾸지 않는다.

## 17. 부록 · 근거 자료와 판본

문서 본문은 현재 청구 문안·저장된 실행 결과·기존 조사 기록을 종합했다. 부록 파일명은 출처 식별용이며 외부 모델이 자동 접근할 수 있는 링크가 아니다. 본문 밖의 상세 자료가 필요하면 파일명과 필요한 절을 특정한다. 모든 원자료를 통째로 첨부하지 않아도 검토의 출발점·현 문안·핵심 코드·불리한 결과를 이 문서에서 읽을 수 있도록 구성했다.

**이번 제작의 범위:** 종합 문서·복사 요청문·원문 대조·페이지 검수. 외부 모델의 실제 답변 수령, 변리사 검토, 출원·심사는 이 문서 제작의 완료 범위가 아니다. 다음 판단은 돌아온 답변의 근거를 대조한 뒤 갱신한다.
