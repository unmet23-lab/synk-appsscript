# SYNK 특허 검토 · Gemini와 Claude의 2차 교차 심문

2026.09.14 · 사용자가 전달한 두 독립 답변을 현재 청구 문안·코드·원문·합성 실행에 대조한 보충 자료

## 사용 방법

Gemini와 Claude가 첫 답변을 작성한 기존 대화에 이 문서 전체를 각각 첨부한다. 가능하면 상대의 첫 답변 전문도 함께 첨부한다. 아래 마지막 요청문을 보내면 된다. 이 문서에 적힌 Codex의 판단도 검증 대상이다. 어느 모델의 결론을 유지하도록 강요하지 않는다.

현재 주안 P1은 지연 수신한 도움 사건에 따라 같은 음성 기록의 목적·능력별 기여를 정정하는 방식이다. 최초 27쪽 종합자료의 현행 P1-01부터 P1-07까지가 비교 기준이다. Gemini의 교체 문안과 Claude의 N-01부터 N-05까지는 아직 반영하지 않은 제안이다.

## 1. 이번에 확인한 사실

### E1. 사유의 순서는 상태를 실제로 바꾼다

Claude Q04·표 C·표 E의 “순서는 표시용이며 상태는 바뀌지 않는다”는 설명은 현 구현과 다르다.

현재 `core.cjs` 364-366행의 상태 선택은 다음과 같다.

```javascript
const first = cell.blockers[0];
return Object.assign(cell, {
  status: first.status, reasonCode: first.code, reason: first.reason
});
```

합성 입력: 도움 관측 범위 확인값은 거짓이고, 알려진 조사 도움 사건의 발생 시각은 발화 전이며, 나머지 조건은 충족한다. 사유 배열은 `exposure-scope-unconfirmed(held)` 다음 `original-was-assisted(excluded)`다.

| 같은 입력에서의 상태 선택 | 결과 |
|---|---|
| 현행 첫 사유 선택 | held / 보류 |
| 메모리 사본에서 제외 사유를 우선하도록 바꾼 선택 | excluded / 제외 |

원본 파일을 고치지 않은 메모리 실행에서 차이를 확인했다. Claude Q14의 “제외 사유가 하나라도 있으면 제외”는 현 구현과 다른 정책이다. 순서가 결과를 바꾼다는 사실은 진보성의 증명이 아니다. 순서가 기술적으로 필요한지, 임의 정책인지의 판단은 별도로 남는다.

### E2. 보류 상태와 기여 철회는 동시에 성립한다

자격 상태는 현재 기록을 사용할 수 있는지를 나타낸다. 전이는 이전 기여가 어떻게 바뀌었는지를 나타낸다. 현재 `projection.cjs` 69행은 이전 반영 상태가 보류 또는 제외로 바뀌면 `withdrawn`을 기록한다.

```javascript
if (before.status === 'accepted' && after?.status !== 'accepted')
  return 'withdrawn';
```

발화 구간 `[10:00:00, 10:00:10]`의 조사 자격이 이미 반영된 합성 입력으로 확인했다.

| 뒤늦게 처리한 도움 발생 가능 구간 | 시간 관계 | 새 자격 상태 | 기존 기여 전이 |
|---|---|---|---|
| `[10:00:04, 10:00:06]` | overlap / 발화 중 | held | withdrawn |
| `[09:59:59, 10:00:01]` | unknown / 경계 걸침 | held | withdrawn |

두 경우 모두 기존 조사 관측값이 철회 기록에 포함됐다. 따라서 “보류는 철회도 유지도 아니다”, “발화 전일 때만 철회한다”는 설명을 현 구현의 설명으로 사용할 수 없다. 제외를 영구 상태로 만드는 별도 처리가 없는 한 “제외로 합치면 영구 복구 불가”도 자동으로 성립하지 않는다.

### E3. 시각 누락 경로는 문제이며, 명시된 시각까지 버릴 이유는 없다

실제 `StudioStore.apply`를 SQLite `:memory:`와 고정 시계로 실행했다. 학생 데이터·운영 DB·원음 파일은 사용하지 않았다.

| 도움 사건 입력 | 계산 결과 | 자격 / 전이 |
|---|---|---|
| `at`, `timeBounds` 모두 없음. 서버 시각은 10:01 | 서버 시각이 발생 시각처럼 들어가 after | accepted / retained |
| 명시적 `at=09:59`, `timeBounds` 없음 | before | excluded / withdrawn |
| `at` 없음, 유효한 `timeBounds=[09:58:59,09:59:01]` | before | excluded / withdrawn |

발생 시각을 모르는 입력에 서버 시각을 넣어 순서를 확정하는 경로가 재현됐다. 현실에서 그 도움이 실제로 발화 전이었다는 사실을 이 시험이 입증한 것은 아니다. 올바른 처리 방향은 실제 발생 정보와 저장·수신 시각을 구별하고, 발생 정보가 없는 경우 판정 불가로 유지하는 것이다.

기본값 경로는 `store.cjs` 165행과 `core.cjs` 101행 모두에 있다. 저장 계층 한 곳만 바꾸는 것으로 범위가 끝나지 않는다. 반대로 `timeBounds`가 없다는 이유만으로 모두 unknown 처리하면 명시된 유효한 `at`까지 버린다. 유효한 점 시각, 유효한 구간, 둘 다 없음, 잘못된 형식, 두 정보가 충돌하는 경우의 입력 계약을 먼저 정의해야 한다. 실제 표시 시각을 어느 정확도로 안다고 주장할지도 생산자에 맞춰 정해야 한다.

현재 UI의 도움 표시 경로는 표시 후 `at`을 제공한다. 이번 결과를 모든 UI 사용이 오분류됐다는 주장으로 확대하지 않는다. 이 검토에서 제품 코드를 수정하지는 않았다.

### E4. 두 모델의 축약안은 단순한 범위 축소가 아니다

Gemini P1-06과 Claude N-04에는 다음 현행 조건의 전부 또는 일부가 빠져 있다.

- 도움의 답 노출 여부와 대상 능력의 관계.
- 다른 보류·제외 사유가 없다는 조건.
- 독립 확인값 및 그 적용 대상.
- 변경 전후 모두 반영 상태이고, 변경 전후 관측값도 같다는 조건.
- 원음-전사 용도와 독립 수행 용도를 다르게 취급하는 관계.

논리적 예: 변경 전 후보가 `친구를 만나서 카페에 갔어요`, 변경 후 후보가 `친구를 만나서 카페에 가요` 하나씩이면 두 시점 모두 후보 내부 일치는 참이다. 그러나 전후 과거형 관측값은 다르므로 현행 `projection.cjs` 71행의 전이는 retained가 아니라 replaced다. 후보 내부 일치와 전후 값 동일은 다른 조건이다.

특정 조건을 추가한 부분과 기존 조건을 삭제한 부분이 섞인 안을 “대폭 한정”이라고 이름만 붙여서는 안 된다. 현행 처리의 표현을 간결하게 한 것인지, 권리 범위를 넓힌 것인지, 처리 정책을 바꾼 새 설계인지 문단별로 분리해야 한다. 한 조건을 종속항으로 옮겼다는 사실이 그 조건 없는 독립항의 정확성을 보장하지 않는다.

### E5. 기존 무작위 동치시험은 실제로 존재하고 통과했다

27쪽 자료는 저장소 전체 시험 목록을 첨부한 자료가 아니었다. Claude의 접근 한계를 고려해야 하지만, “전부 미구현”이라는 판정은 저장소 기준으로 맞지 않는다.

이번에 기존 `projection.test.cjs`의 다음 두 시험을 선택 실행했다.

| 기존 시험 | 이번 결과 |
|---|---|
| 16개 seed × 80회, 총 1,280개 합성 사건 전이의 캐시 사용 / 전체 재평가 비교 | 통과 |
| 40개 응답 중 하나 정정 후 전체 결과 비교·관련 평가 재사용 검사 | 통과 |

실행: `node --test --test-name-pattern='1,280|40 recorded|40 response|forty|40-response' tools/patent-studio/projection.test.cjs`. 결과는 tests 2, pass 2, fail 0이다. 합성 입력의 판정 동치 확인이며 실제 학생 효과·전체 성능 우월성·모든 시간 경계의 검증은 아니다.

동치시험은 두 계산이 같은 잘못된 시간 입력을 받는 문제까지 자동으로 발견하지 않는다. E3처럼 입력의 의미를 독립적으로 고정한 경계 시험이 추가로 필요하다. 새 생성기를 전부 다시 만들기 전에 기존 시험의 미포함 입력만 특정해야 한다.

## 2. 원문에서 다시 확인한 근거

### R1. D01은 접근 가능한 원문이 있다

[US20180315330A1 원문](https://patents.google.com/patent/US20180315330A1/en)을 이번 검토에서도 직접 열었다. 도13 관련 설명에는 경로별 사건 필터링·부분집합·분할, 지연 사건 이후 재처리, 스냅샷, 지식 추적 등의 분석기가 있다. 청구항 14와 설명 속 스냅샷 기재는 구별해야 한다. 특정 도구에서 못 열었다는 사실은 원문이 없거나 유료 DB가 필수라는 뜻이 아니다.

“부분집합 처리가 있다면 P1을 버리고 P2로 이동”이라는 단일 조건만으로 후보를 바꾸지 않는다. 그 부분은 기존 자료에서도 이미 알려진 선행이다. 남은 청구 관계 전체의 동일성·결합 용이성을 다시 대조해야 한다.

### R2. TMS/ATMS 원논문은 보충 조사에 포함해야 한다

TMS는 판단을 지지하는 근거와 그 변화를 관리하는 추론 시스템이다. Claude가 추가한 이 연구 계열은 기존 후보를 더 엄격하게 검토할 유효한 조사 방향이다. 하지만 아래 두 논문을 단순한 “IN/OUT 두 상태”로 설명해서는 안 된다.

- [de Kleer, An Assumption-based TMS](https://www.dekleer.org/Publications/An%20Assumption-Based%20TMS.pdf), 1986. §4.3, 인쇄 145쪽 / PDF 19쪽은 문맥에서 반드시 성립, 반드시 부재, 현재 부재하나 후속 근거로 바뀔 수 있는 범주를 구별하며 true/in/out/false 집합을 설명한다. §4.4, 인쇄 147쪽 / PDF 21쪽은 한 정당화 안의 여러 조건과 복수 정당화 사이의 논리 관계를 구별한다.
- [Doyle, A Truth Maintenance System 재수록본](https://cse.buffalo.edu/~rapaport/Papers/Papers.by.Others/NONMONOTONIC/doyle79.pdf), 원논문 1979·열람본 1987 재수록. §2.1, 열람본 인쇄 262쪽 / PDF 7쪽은 IN/OUT과 true/false를 구별하고 판단과 그 부정에 관한 믿음 및 unknown을 논한다.

이 범주들이 SYNK의 보류 상태와 곧바로 같은 기술 관계라는 결론도 아직 아니다. 다만 상태 개수만으로 새 차이를 주장하는 근거는 부족하다. 또한 “여러 정당화 중 하나가 유효”를 P1의 복수 필수 조건·모든 지원 후보의 관측값 일치와 단순히 동일시할 수 없다. ATMS도 정당화 내부의 복수 조건을 표현하므로 AND/OR 용어 차이만으로 SYNK가 새롭다는 반박도 성립하지 않는다.

de Kleer §3.2, 인쇄 139-141쪽 / PDF 13-15쪽은 이전 계산의 재활성화, 작업 큐 스냅샷, 계산 결과 저장을 구분해 다룬다. 따라서 근거를 다시 유효하게 만드는 복원, 이전 스냅샷으로 되돌리기, 입력 지문이 같은 계산 결과 재사용을 각각 대응시켜야 한다.

### R3. 주지관용기술이라고 전체 결합 검토가 사라지지는 않는다

[공식 심사기준 PDF](https://www.kipo.go.kr/ko/kpoContFileDown.do?seq=4&fileNum=1), 제3부 제3장 §7, 책쪽 3324-3326 / PDF 322-324쪽을 이번에 다시 읽었다. 주지관용기술과의 결합은 통상 용이하게 보지만, 기술적 특징들의 유기적 결합과 그 효과도 고려한다. 당시 기술상식·과제 등에서 결합의 용이성을 인정할 수 있으며 문헌 수 자체에는 특별한 제한이 없다.

따라서 “주지관용이면 결합 이유 검토가 필요 없다”와 “여러 문헌을 썼으므로 사후적 고찰이다”는 양쪽 모두 과도한 단정이다. 어떤 기술이 그 분야의 당시 기술상식이었는지, 그 기술을 이 입력·상태·전이에 적용할 이유와 필요한 변경을 구체화해야 한다.

## 3. 현재 판단과 남은 결정

P1은 계속 비교할 주안이다. 두 모델의 새 문안을 그대로 교체하지 않는다. 시각 누락 경로는 실제 개선 대상이지만, 그 수정 자체를 신규 발명이나 등록성 상승의 증거로 계산하지 않는다. TMS/ATMS를 포함한 대조 범위는 확대한다. “보류 3상태”만을 중심으로 전략을 확정하지 않는다.

기존 사유 순서와 유지 조건에 기술적으로 필요한 관계가 있는지, 임의 정책을 제거한 뒤 무엇이 남는지 다시 판단해야 한다. P2도 별도 과제의 대안이며 일반적인 판본 검사·계약 객체를 추가했다고 더 유리하다고 판정하지 않는다. 한 코드 오류의 존재, 시험 통과, AI의 일치된 의견 각각은 청구항 전체의 특허요건 판단을 대신하지 않는다.

## 4. 두 모델에게 동일하게 보낼 2차 요청문

> 첨부한 2차 교차 심문 자료와 상대의 첫 답변을 검토해 주세요. 자신의 첫 결론을 그대로 전제로 삼지 말고, 아래 항목마다 유지·수정·철회·판단유보 중 하나를 선택해 주세요. 실제 원문을 열지 못한 부분은 미확인으로 남기고 문서 제목이나 상태 이름만으로 동일성을 단정하지 마세요. 새 청구 문안을 먼저 쓰기보다 사실관계와 비교 논리를 먼저 바로잡아 주세요.
>
