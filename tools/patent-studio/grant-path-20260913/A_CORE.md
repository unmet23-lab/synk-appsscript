# A안 — SYNK Core를 살리는 보수적 등록성 보강 검토

2026-09-13 · 독립 조사 1차안 · 현재 구현과 추가 설계를 구분한 검토 자료

## 결론

**기존 Core를 유지하되, ‘늦은 도움 기록 정정’에 기능을 계속 붙이는 방향은 추천하지 않는다.** 기술적 연결을 더 구체화할 후보는 있다. 그러나 이번 추가 원문 대조에서도 정보흐름 표지 전파, 음성 후보의 시간 구간 대응, 관측 계획은 알려진 수단이었다. ‘시도·능력·목적별 표지를 붙인다’만으로 결합 반론을 넘었다고 말할 수 없다.

Core 안에서 먼저 검증할 한 가지 후보는 **평가 결과가 갈리는 음성 후보 쌍에서 원음 확인 구간과 결과 사용 조건을 함께 만들고, 실제 확인 결과를 그 조건으로 검사하여 해당 기록에만 반영하는 처리 관계**다. 아래 독립항은 출원 확정안이 아니라 이 관계를 반증하기 위한 최소 초안이다. 기존 강한 방식이 동일한 결과를 내면 그 실험만으로 우월한 기술 효과를 주장하지 않는다. 동일 출력과 법적 진보성 판단은 구분한다.

이 방향은 현재 상담 후보를 구체화하는 데 유용하지만, 회사 전체 후보보다 등록성이 높다거나 등록 확률이 실질적으로 상승했다고 아직 판단할 수 없다.

## 먼저 써야 할 가장 강한 결합 반론

### 반론 1: 늦은 사건 + 힌트 + 부분 철회

US20180315330A1은 순서가 바뀐 학습 사건의 재처리, US10943497B2와 US10490096B2는 도움 사용·첫 시도 기록을 이미 다룬다. 같은 데이터를 여러 소비자에게 주고 목적에 따라 일부 사용을 막는 수단도 US11144665B2와 일반 정보흐름 제어에 있다. 정확한 분석을 유지하면서 재사용 자료를 보존하려는 결합 동기는 자연스럽다. 필드 수나 이벤트 종류를 늘려도 이 반론은 유지된다.

### 반론 2: 효과가 갈리는 원음 부분만 확인

US9953644B2는 불확실한 개념을 겨냥한 확인 질문을, 새로 읽은 US9779724B2는 여러 음성 가설의 단어 시작·종료 시각을 이용한 대체 후보 추출을 설명한다. 평가기가 조사의 종류에 따라 다른 결과를 내면 그 단어 구간을 확인 대상으로 삼는 것은 통상의 데이터 연결이라는 반론이 가능하다. ‘과거형은 같고 조사는 다르다’라는 사례 하나는 비자명성 증명이 아니다.

### 반론 3: 확인 행동의 영향을 전파하고 결과 사용을 제한

1998년 정보흐름 연구는 입력의 정책 표지를 계산 결과에 결합하고, 출력 채널에 맞는 허용 조건을 검사한다. 2023년 특허는 사건 기록에서 출처 그래프를 만들고 민감 출처의 후손을 추적한다. 이 구조에서 출처를 ‘힌트’, 출력 채널을 ‘최초 독립 수행’, 식별 범위를 ‘원음·시도·능력’으로 바꾸는 것은 도메인별 정책 설정에 불과할 수 있다. 계획 시점과 저장 시점에 같은 조건을 검사한다는 것만으로 기술적 도약을 주장할 수 없다.

## 일반적인 기존 방식도 같은 결과를 내는 반례

표지와 라우팅만 추가한 구성이 충분한 차별점인지 먼저 검사했다. 학생 자료 없이 Node 인메모리 합성 입력만 사용했다. 모든 다른 판정 조건은 충족한다고 두고 **결과 귀속 허용 여부만** 비교했다.

- 목표 3개: 원음 A/시도 e0의 전사 자료, A/e0의 조사 독립 수행, 원음 B/시도 e1의 전사 자료.
- 확인 결과 3개: A 재청취, 조사 힌트 뒤 B 새 녹음, B 재청취 결과.
- 기준선: `원음 일치 && 시도 일치 && 해당 목적·능력에 대한 금지 정책 없음`이라는 일반적인 식별자/정책 검사.
- 후보: 결과의 출처·시도 표지와 목적·능력별 금지 집합을 생성한 뒤 목적지와 비교.

| 확인 결과 | A/e0 전사 | A/e0 조사 | B/e1 전사 |
|---|---:|---:|---:|
| A 재청취 | 허용 | 허용 | 불허 |
| 힌트 뒤 B 새 녹음 | 불허 | 불허 | 허용 |
| B 재청취 | 불허 | 불허 | 허용 |

**실제 실행 결과 9쌍 모두 기준선과 후보가 같았다.** 이것은 9쌍의 기초 귀속 검사에 대한 반례이며 산업 제품 전체 비교가 아니다. ‘원래 답변과 새 답변이 섞이지 않는다’는 시연 하나만으로 일반 식별자/정책 검사보다 우월한 효과를 입증하려던 주장은 지지하지 못한다. **동일한 우리 계약을 이미 넘겨받은 기준선이 같은 답을 냈다는 사실은, 그 계약과 연결 구조를 선행기술로부터 쉽게 만들 수 있다는 법적 판단과 다르다.** 뒤의 진보성 분석에는 결합 동기·실제 인터페이스 변경·선행 원문이 별도로 필요하다. 기존 플랫폼이 일부러 이 오류를 내는 것처럼 비교하면 안 된다.

## D2 + D3 + D5를 실제로 잇는 데 필요한 변경

여기서 D2는 기존 감사의 지연 학습 사건 처리, D3는 힌트 사용을 반영한 학습 상태 추적, D5는 부분 확인 질문 기술이다. 아래는 원문에 직접 적힌 우리 계약이 아니라 **통합 담당자의 기술 분석**이다.

| 연결 지점 | 원문에서 출발 가능한 기능 | 우리 좁은 사슬을 만들려면 필요한 변경 |
|---|---|---|
| D2 사건 → D3 상태 갱신 | 자원·시각·사건 종류를 정렬/필터하고 학습 이력 입력으로 사용할 수 있음 | 완료된 응답 하나로만 묶지 않고 원음·시도·후보 판본·소비자 목적을 수신 계약에 유지해야 함 |
| D3 상태 입력 → 후보별 효과 비교 | 문항·응답·힌트 사용을 입력으로 상태를 갱신 | 동일 원음의 후보들을 대안으로 평가하는 함수와, 능력 소비자별 출력 값의 일치/불일치 집합이 필요함. 전체 지식 상태 벡터의 변화와 특정 자료 자격은 구별해야 함 |
| D5 확인 질문 → 원음 확인 | 불확실한 개념을 특정해 사용자에게 확인할 수 있음 | `사용자가 의도한 의미를 확인`하는 결과와 `기존 원음에 실제 포함된 단어열을 확인`하는 결과의 타입을 나누어야 함. 새 음성의 식별자와 원래 음성의 식별자를 동시에 보존해야 함 |
| 효과 차이 → 실제 확인 | 전사 대체 후보를 원음 구간에 연결하는 선행도 존재 | 평가가 달라지는 후보 쌍에서 확인 구간 및 허용 수신 자료를 공동 산출해야 함. 이 공동 산출이 필요/용이한지 추가 대조 대상 |
| 실제 확인 → 복수 소비자 | 이벤트 재처리·타입/정책 검사 자체는 알려짐 | 확인된 현재 의도는 대화용 소비자에게, 새 녹음의 단어열은 그 새 원음의 전사 자료에게, 기존 원음의 청취 결과는 원래 음성 자료에게 보내도록 분리하고 관련 효과만 갱신해야 함 |

강한 반론은 이렇다. 음성 서비스를 운영하는 기술자는 평가 기록과 음성 자료의 목적이 다른 것을 알고 있고, 기존 원음 보존 및 첫 시도 기록도 선행에 있으므로, 원음·시도 ID와 확인 유형을 전달하여 각 소비자의 계약을 지키는 것은 흔한 시스템 통합이라는 주장이다. 이를 뒷받침하려면 단순히 서로 다른 문헌을 나열하지 말고, 원음–전사 자료를 함께 운영할 동기와 계약 변환의 통상성을 원문에서 연결해야 한다.

가능한 재반론은 ‘각 부품이 없다’가 아니다. D5에서 새 응답으로 **의도**를 해명하는 것은 정상 기능이고, D2에서 그 사건을 다시 처리하거나 D3에서 힌트를 반영해도 **원래 파형과 맞는 단어열인지**라는 별도 문제는 자동으로 해결되지 않는다. 평가 효과가 같은 후보는 전사 자료 관점에서는 여전히 다를 수 있다. 따라서 효과 비교→불일치 후보 쌍→원음 확인과 새 응답 분기→목적별 반영을 공동 설계하는 구체 관계가 선행 결합의 통상 결과인지 검토할 여지가 있다. 이 재반론이 유효하다고 확정한 것은 아니다.

구체 예: 원음 A가 ‘친구가/친구를’로 불명이고, 새 응답 B가 ‘네, 친구를요’라면 B는 학생이 **말하려던 의미**를 확인하는 대화 자료가 될 수 있다. 그러나 B만을 근거로 A를 ‘친구를’이라고 전사하여 A 파형과 학습용 정답을 짝짓는 것은 근거가 다르다. 후보 사슬은 현재 의도 확인은 허용하면서 A의 학습용 단어열 승격은 보류하고, A의 실제 청취나 다른 적격한 원음 확인 결과가 들어온 뒤에만 그 쌍을 만든다. 이 사례는 실제 발생 사례가 아니라 비교 입력이다.

그때 주장할 수 있는 기술 효과의 후보는 **잘못 귀속된 파형–전사 쌍을 줄이는 것, 관련 없는 소비자의 유효한 관측값을 유지하는 것, 확인해야 할 원음 구간을 계산하는 것**이다. 학생의 실력 추정 정확도 향상은 별도 검증 없이는 주장하지 않는다. 비교 대상 D5가 애초 음성 모델 학습자료를 만들지 않는다면 그 제품이 잘못된 학습쌍을 만들었다고 평가하지 말고, 동일한 두 소비자를 갖추도록 확장한 기준선의 실제 연결을 비교한다.

## 그래도 남겨 볼 최소 처리 관계 하나

가칭: **원음 후보의 평가 차이를 이용한 확인 구간 생성 및 목적별 결과 귀속 방법**.

기술적 과제는 학생의 실력을 자동으로 정확히 알아내는 것이 아니다. **한 음성에서 복수 전사 후보가 있을 때 여러 소비자가 요구하는 결과가 서로 다르고, 확인 과정에서 새로 생성된 음성까지 입력되는 상황에서, 확인 대상 선택과 결과 갱신이 서로 다른 원음/시도 기준을 사용하는 오류를 막는 것**으로 제한한다.

### 추가 설계할 데이터 계약

| 레코드 | 필수 내용 | 이유 |
|---|---|---|
| 확인 목표 `Target` | 원음 내용 식별자, 발화/시도 ID, 목적, 능력, 평가 규칙 판본, 현재 후보 집합 판본 | ‘무엇을 확인하는가’를 고정 |
| 후보 `Hypothesis` | 원음 ID, 후보 ID, 단어열, 단어별 시간구간, 지원 범위 | 결과 차이를 원음에 대응 |
| 차이 증거 `Witness` | 서로 다른 효과를 내는 후보 쌍, 목표 ID, 관련 단어/구간 참조 | 불확실하다는 표지 대신 확인 대상의 계산 근거 |
| 확인 계약 `ObservationContract` | 목표·차이 증거 ID, 허용 원음 구간, 입력 자료 종류, 결과 원음/시도/목적 제한, 선행 행동의 영향, 생성에 사용한 판본 | 계획과 저장을 연결하는 동일 객체 |
| 실제 결과 `ObservationReceipt` | 실제 재생한 원음 ID·구간, 실제 결과 원음/시도 ID, 결과 종류, 관측 내용, 실제 노출·새 수행 사건 참조 | 예정과 다르게 실행된 경우 재검사 |

원음 해시는 신원을 보장하지 않고 내용 동일성을 검사하는 데 쓴다. 실제 들은 것/학생이 도움을 인지한 것까지 해시로 증명할 수 없다. ‘원음 구간 재생 기록’은 UI가 재생 명령을 실행한 증거이지 사람의 청취 정확도 보장이 아니다.

### 독립항 검토용 최소 문언

하나 이상의 프로세서가 음성 기록을 확인하는 방법으로서,

1. 동일 원음에 대응하는 복수 전사 후보의 단어별 발생 구간과, 상기 원음을 사용하는 복수 목표 각각의 발화 식별자·시도 식별자·사용 목적·평가 함수를 저장하고;
2. 각 목표의 평가 함수를 상기 후보들에 적용하여 후보별 효과가 일치하는 목표와 일치하지 않는 목표를 구분하고, 불일치 목표에 대하여 서로 다른 효과를 내는 후보 쌍 및 그 차이에 대응하는 원음 구간을 연관하며;
3. 상기 연관에서 원음 구간을 확인하는 행동의 입력 자료와 출력 자료의 귀속 조건을 함께 생성하되, 귀속 조건은 목표의 원음·시도·사용 목적과 상기 행동 및 선행 행동이 새 응답을 생성하는지 또는 해당 능력의 답을 노출하는지에 따라 정하고;
4. 상기 조건에 적합한 확인 행동을 실행한 뒤 수신한 실제 결과의 원음·시도·자료 종류와 실제 행동 이력을 상기 동일한 귀속 조건과 비교하며;
5. 조건을 충족하는 실제 결과에 의해서만 관련 후보 집합을 정밀화하고 관련 목표의 효과를 갱신하고, 조건을 충족하지 않는 새 응답은 별도 원음·시도에 저장하며 원래 목표의 효과 갱신 근거에서 제외하는;

음성 기록의 확인 및 목적별 결과 귀속 방법.

이 문언에서 ‘그 차이에 대응하는 구간’을 어떻게 계산하는지, 여러 구간일 때 선택 기준, 시점별 영향의 정확한 정의가 아직 부족하다. 원문 기재 없이 ‘최소 구간’·‘최적’·‘모든 경우’를 넣지 않는다. 작성 완료된 법률 문안이 아니다.

### 각 단계가 함께 있어야 하는 이유와 반대 검증

- 2가 없으면 평가에 필요하지 않은 전사 차이까지 확인할 수 있다. 그러나 일반 평가 의존 분석을 넣은 기준선도 이를 피할 수 있는지 검사한다.
- 3이 없으면 계획의 확인 대상을 결과 저장기가 다르게 해석할 수 있다. 그러나 정적 스키마/타입 검사도 같은 오류를 막을 수 있다.
- 4가 없으면 원음 재청취를 계획해 놓고 실제로는 새 응답을 받았을 때 계획의 허용을 그대로 사용할 수 있다. 그러나 일반적인 실행 후 조건 확인과 판본 검사가 해결할 수 있다.
- 5의 부분 갱신은 무관한 소비자의 유효 자료를 유지하지만, 일반적인 의존 그래프 기반 증분 갱신에도 있는 효과다.

따라서 이 관계를 구현해도 알려진 모듈의 정상 연결에 그치면 등록성 근거로 채택하지 않는다. 구성 수가 많다는 이유로 채택하지 않는다.

## 현재 구현과 추가 개발의 정확한 경계

| 항목 | 현재 | 필요한 추가 검증/개발 |
|---|---|---|
| 목적별 후보 효과 비교 | `effectsFor`, `makeCell`에 존재. 조사의 사용·과거형 통제 규칙 | 지원 범위 밖의 의미 추론으로 확장했다는 주장 금지 |
| 효과가 다른 후보 쌍 | `makeCell`의 `witness` 존재 | 단어 정렬·원음 실제 시간구간 연결 없음 |
| 원음/새 응답 귀속 | `earlierBoundary`, `locate`, 별도 응답 저장 등 존재 | 계획 생성 판본과 실제 관측 결과의 계약 일치 검사 전체는 별도 필요 |
| 확인 행동의 영향 | Core가 정한 몇 가지 후보와 `exposesAnswer`, `createsEpoch`, `eligibleForOriginal` | 대상 능력·시도·목적별 영향 및 실행 중 일어난 실제 사건으로 재판정 |
| 선행 영향 | planner의 `originalSafe`가 `requires`를 재귀 확인 | 일반 planner에는 원음 ID·능력 필드가 없고 ASR 목표에는 동일 안전 조건을 적용하지 않음. Core의 제한 후보가 보완하는 범위와 혼동 금지 |
| 계획 상태 | 예산·깊이·상태 수 한도, 실행 하나→관측→재계획 | 결과 확률 최적화나 전역 최소 비용 보장 없음 |

## 실험을 한다면 통과해야 할 비교

기준선을 약하게 만들지 않는다. 입력 후보·원음·행동·예산·평가 함수는 동일하게 둔다.

| 기준선 | 반드시 넣을 능력 | 해석 |
|---|---|---|
| B0 현행 Core 0.5 | 실제 현행 기능 전부 | 새 개발이 해결하는 실제 빈틈 확인 |
| B1 일반 강한 방식 | 원음/시도 키, 목적별 금지 표지, 실제 사건 후 조건 재확인, 후보별 평가 계산, 단어 시간 정렬 | 우리 계약을 주입한 일반적 실행 구성이 같은 결과를 내는지. 계약 도출의 용이성은 별도 판단 |
| B2 일반 그래프/계획 방식 | B1 + 출처·의존 그래프, 선행 영향 전파, 조건부 계획 | 그래프 이름 변경 수준인지 |
| 후보 A | 동일 입력에 위 확인 계약 연결 | 출력·계산비용·귀속 관계의 차이와 동일성을 함께 분석. 동일 출력만으로 진보성 기각하지 않음 |

합성 반례 세트에는 원음 A 재청취 계획 뒤 B 녹음 수신, 계획 뒤 후보 판본 변경, 힌트가 학생에게만 노출된 경우와 교사 화면에만 제시된 경우, 특정 능력의 도움과 독립 조건이 확인된 다른 능력, 동일 과거형/상이 조사 후보, 해당 구간 청취 불명, 정렬 구간 누락, 중복·역순 실제 결과를 넣는다.

측정값은 잘못된 원음/시도/목적으로 반영된 기록 수, 정당하게 유지 가능한 기록 수, 실제 재생 구간 길이, 행동 횟수, 후보 평가 호출 수, 메모리·시간이다. ‘학습 효과’와 ‘등록 확률’은 이 실험의 측정값이 아니다. 보류만 늘려 오류를 0으로 만들면 유효 기록 유지와 확인 비용에서 드러나야 한다. 시간 감소는 실제 측정 전에는 수치로 쓰지 않는다.

단어 정렬 후보 H개, 목표 T개, 한 후보의 최대 단어 W개라면 단순 후보 효과 계산은 대략 H×T번이고 후보 쌍을 전부 비교하면 H²쌍까지 증가한다. 후보를 효과별로 묶는 압축을 쓰더라도 서로 다른 정렬·맥락 의존성이 같은 효과 그룹 안에 있을 수 있으므로 임의 대표 하나로 전체를 대체해서는 안 된다. 비용 개선의 정확성과 한계는 별도 실험이 필요하다.

## 채택·보류 판단

**개발 후보로 채택할 조건:** 실제 입력에서 기존 현재 흐름의 부족한 계약이나 귀속 오류가 재현되고, 위 사슬로 그 범위를 명확히 해결해야 한다. 등록성 검토에서는 추가로 선행의 결합 동기·변경 필요성·그 결과 효과의 예측 가능성을 판단한다. B1/B2와 출력이 다르다는 것 자체가 필수 법률 조건은 아니며, 출력이 같다고 즉시 진보성이 부정되는 것도 아니다. 단순 버그 수정과 특허성 판단을 구분한다.

**기술 효과 우월성 주장을 보류/기각할 조건:** 일반적인 식별자 일치·권한 검사·정렬·의존 갱신으로 동일 결과가 나오거나, 새 방식의 효과가 사람이 붙여 준 전제 표지를 더 많이 사용해서 생기는 경우다. 현재 9쌍 귀속 실험은 ‘표지 라우팅만으로 새로운 우월 효과를 보였다’는 주장을 지지하지 않는다. 전체 좁은 결합의 진보성은 위 인터페이스 변경과 동기를 선행 원문에 대조하여 별도로 판단해야 한다.

부모 통합안에는 이 후보를 ‘등록 가능성이 높은 확정 기술’ 대신 **기존안을 살릴 수 있는지 빠르게 반증할 구체 후보**로 전달한다. 등록 1건이 사업 목적이라면 이 경로에만 개발비·시간을 집중하기보다 다른 기업 내 후보와 같은 강도로 대조해야 한다.

## 수행 증거와 남은 일

직접 수행: 현재 코드/문안 독해, 신규 1차 문헌 4개 표적 조사, 귀속 검사 9쌍 인메모리 비교, 이 문서 작성. 기존 엔진 파일·학생 자료·라이브 서비스·계정 변경은 없다. 커밋하지 않았다.

미수행: 위 추가 처리 구현, 실제 원음 구간 정렬 시연, 강한 B1/B2 전체 비교, 국내 동족 추가 검색, 전문 변리사 청구항 의견. 따라서 ‘반론 극복’이나 ‘확률 상승 확인’으로 보고하지 않는다.
