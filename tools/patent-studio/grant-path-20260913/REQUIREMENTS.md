# 등록 1건을 위한 요건·명세서·심사 대응 설계

작성·원문 확인: 2026-09-13 KST. 한국 특허 출원 상담용 조사이며, 등록성 확정 의견은 아니다.

## 이번 조사에서 바뀌어야 하는 판단

**개별 부품이 알려져 있다는 이유만으로 후보를 탈락시키지 않는다. 그렇다고 부품을 많이 연결했다는 이유로 등록성이 높아졌다고 판단하지도 않는다.** 현재 목표는 회사의 전 기능을 넓게 묶는 것이 아니라, 실제 사업에 쓰는 구체적인 처리 관계 중 등록 요건을 충족하는 한 건을 확보하는 것이다. 마케팅 목적은 청구범위를 선택하는 사업 판단에 반영하며 법정 요건을 낮추지는 않는다.

현재 가장 중요한 실무 작업은 다음 세 가지다.

1. 선행 문헌을 출발점으로 삼았을 때 **어떤 입력 관계와 처리 순서를 추가·변경해야 현재 후보에 도달하는지** 대조한다.
2. 출원 전 명세서에 핵심 결합과 좁은 대안의 실제 동작을 충분히 설명한다. 문서 분량보다 보정할 수 있는 기술 내용이 중요하다.
3. 변리사가 가장 가까운 문헌에 대해 주안과 한정안을 각각 평가할 수 있도록 청구항·명세서 위치·실행 사례를 일대일로 연결한다.

이 방향은 등록 가능성을 검토하고 거절 대응의 선택지를 만드는 방법이다. 현재 자료만으로 확률의 수치나 개선 폭을 산출할 수는 없다.

## 2. 법정 요건을 SYNK 작업에 적용한다

### 소프트웨어 발명으로서의 구체성

AI 심사 가이드는 소프트웨어 정보처리가 하드웨어와 협동하여 구체적으로 실현되는지 본다. ‘프로세서를 사용한다’는 머리말이나 ‘AI가 판단한다’라는 결과만으로 그 전체 판단을 대신하지 않는다. 장치·동작 방법·기록매체 등의 청구 형식도 실제 기술 내용을 따라 선택한다. [AI 가이드 제1부 3.1.1~3.1.2, 책쪽 1301~1302](https://www.kipo.go.kr/ko/kpoContFileDown.do?seq=5&fileNum=1#page=37)

**이번 적용 제안:** 원음 내용 식별자, 원래 시도 식별자, 용도·능력별 자격, 확인 행동의 대상과 결과 유형이 어떤 저장 레코드로 연결되는지 명시한다. 프로세서가 어떤 입력을 읽고 어떤 조건을 비교하며, 허용·보류·제외 결과가 어느 레코드에 기록되는지 쓴다. ‘잘못된 학습을 막는다’는 효과를 그 과정으로 설명한다.

Core의 중심을 새 학습모델 발명으로 바꾸어 표현할 필요는 없다. 전사 API가 입력 생성에 쓰이는 부분과, 그 뒤의 결정 규칙·데이터 처리 관계를 구별한다. 만약 모델 자체를 차이점으로 청구한다면 학습데이터·전처리·모델·입출력의 관계 등 해당 구현 설명을 추가 검토해야 한다. [공식 AI 발명 기재요건 안내](https://kipo.go.kr/ko/kpoContentView.do?menuCd=SCD0201244)

### 신규성과 진보성은 다른 질문이다

신규성은 청구한 기술이 기존 기술과 실질적으로 같은지, 진보성은 차이가 있어도 해당 분야의 통상적인 기술자가 쉽게 도출할 수 있는지의 문제다. 산업상 이용 가능성도 필요하다. 한 번의 성공 데모나 개발량은 이 판단을 대체하지 않는다. [특허법 제29조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0029&lsiSeq=279827&urlMode=lsScJoRltInfoR)

**이번 적용 제안:** 문헌별 구성 대조와 복수 문헌 결합 대조를 별도 표로 만든다. ‘한 문헌에서 전부 못 찾음’을 ‘진보성 있음’으로 바꾸지 않는다. 반대로 여러 문헌에서 각각 찾은 부품을 합해 ‘동일한 발명 발견’이라고 적지 않는다.

### 결합 반론에 대응하는 정확한 기준

2026 심사기준의 직접 확인 위치:

- 제3부 제3장 §5.1, 책쪽 3304 / PDF 302: 가장 가까운 선행과 차이를 특정하고 유기적 관계를 고려한다.
- 같은 장 §7(1)~(5), 책쪽 3324~3326 / PDF 322~324: 부품별 공지성만으로 결론을 내리지 않으며 전체 결합의 곤란성과 효과를 본다. 결합 동기는 문헌의 명시적 시사 외에 당시 기술상식·과제·발전경향에서도 찾을 수 있다.
- 같은 장 §9(1), 책쪽 3329 / PDF 327: 출원 내용을 이미 알고 거꾸로 판단하는 사후적 고찰을 경계한다.
- 같은 장의 균등물 치환 설명, 책쪽 3311 / PDF 309: 같은 기능을 한다는 사실만으로 충분하지 않고 당시 치환의 자명성을 검토한다.

[공식 심사기준 제3부 제3장](https://www.kipo.go.kr/ko/kpoContFileDown.do?seq=4&fileNum=1#page=299)

**이번 실험의 해석 원칙:** 우리 엔진의 완성된 입력계약과 자격 조건을 일반 재계산기에도 제공했더니 같은 답이 나온 경우, 그 시험은 ‘동일한 규칙을 실행하는 방식 자체의 출력 우월성’을 뒷받침하지 않는다. 그러나 그 결과 하나로 ‘기존 기술자가 그 입력계약과 조건의 연결을 쉽게 설계할 수 있었다’고 결론 내리지도 않는다. 후자는 선행 자료와 당시 기술상식으로 판단해야 한다.

따라서 일반 재계산기는 유용한 비교 대상이다. 단, **실행 결과 비교**와 **그 처리 관계를 도출하는 것이 쉬웠는지에 대한 판단**을 분리한다. 반례를 만들려고 기존 방식에 불리한 입력을 빼거나, 우리가 만든 조건을 모두 제공한 뒤 ‘기존 기술도 이미 갖고 있었다’고 간주해서는 안 된다.

**반론 대응표에 필요한 칸:** 가까운 선행의 원래 입력과 목적 / 추가 문헌을 참조할 이유 / 바꿔야 하는 저장·연산·귀속 관계 / 기존 작동 원리와의 충돌 여부 / 결합 후 예측 가능한 결과 / 실제 관측한 차이 / 아직 증거가 없는 주장.

### 효과 자료는 무엇을 입증해야 하나

‘AI이므로 빠르다·대량 처리한다·오류가 줄어든다’ 같은 일반적인 효과는 그것만으로 강한 차이가 되기 어렵다. 단순 결합으로 보이는 구성에서는 기술적 저해 요인이나 더 나은 효과 등의 사정이 특히 중요해질 수 있다. [AI 가이드 3.2.1(5)~(6), 책쪽 1312 / PDF 48](https://www.kipo.go.kr/ko/kpoContFileDown.do?seq=5&fileNum=1#page=48)

다만 예상 밖 효과나 정량 벤치마크가 모든 소프트웨어 발명의 별도 필수조건이라는 뜻은 아니다. 이 조사에서는 시험을 법정 요건의 대체물로 삼지 않는다.

**이번 적용 제안:** 학생 실력 향상처럼 아직 측정하지 않은 효과 대신, 현재 처리 구조가 직접 만든 결과를 기록한다. 예를 들면 잘못된 원래 시도 연결의 발생 여부, 유효한 다른 용도의 보존, 필요한 원음 확인 구간, 추가 질문 수, 재계산 비용이다. 속도가 같거나 느리면 그 결과도 포함한다. 실험 시나리오가 실제 운영 관측인지 합성 입력인지 명시한다. 어느 구성요소를 제거했을 때 무슨 결과가 바뀌는지는 원인 설명에 도움이 되지만, 그 시험 자체가 진보성 판정은 아니다.

### 명확성·뒷받침·실시 가능성

명세서는 통상적인 기술자가 실행할 수 있을 만큼 명확하고 상세해야 하고, 청구범위는 설명에 뒷받침되며 명확·간결해야 한다. 필요한 구조·방법·기능·결합관계를 특정한다. 발명자와 출원인도 신청서에 적는 실제 사항이다. [특허법 제42조 제1~4항·제6항](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0042&lsiSeq=279827&urlMode=lsScJoRltInfoR)

**이번 문안에서 채울 내용:**

| 항목 | 명세서에 들어갈 실물 |
|---|---|
| ‘능력의 근거’ | 어느 시도의 어떤 표현 관측을 어떤 용도에 반영한다는 것인지, 데이터 필드와 예시로 정의 |
| 독립 조건 | 누가 입력하고 어떤 조건을 비교하는지. 외부 도움 부재를 자동 인증하는 것처럼 쓰지 않음 |
| 확인 행동 | 원음 재검토와 새 발화를 만드는 행동의 입력·대상·출력·금지되는 연결 |
| 불확실성 | 다수 해석·시간 구간을 어떻게 유지하고 어떤 실제 결과에서 해소하는지 |
| 효과 적용 | 상태 계산과 실제 저장·집계 변경의 연결. 예상 결과만으로 승인하지 않는 과정 |
| 범위의 한계 | 지정된 규칙과 입력에 대한 구현을 전 언어·전 능력 자동 추론으로 넓히지 않음 |
| 구현 대안 | 파일·DB, 동기·비동기 등 차이점에 영향을 주는 대안을 각각 실행 순서로 설명 |

실제 발명자의 판단·설계 기여와 AI가 제안·구현한 부분을 사실대로 정리한다. 사용자가 혼자 작업했다는 진술을 모든 후속 구체 설계의 법적 발명자 판단이 이미 끝났다는 의미로 확장하지 않는다. 출원인과 권리 승계는 최종 법적 명칭·관계에 따라 작성한다. [특허법 제33조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0033&lsiSeq=279827&urlMode=lsScJoRltInfoR)

## 3. 한 건의 등록을 위한 청구·보정 준비

### 출원 전에 한정안의 내용까지 명세서에 넣는다

보정은 최초 제출 명세서·도면에 있는 사항의 범위 안에서 해야 한다. 거절 통지 후에는 보정 기간이 제한되고, 최후 통지 대응·재심사 단계에는 청구범위 감축 등 추가 제한이 있다. [특허법 제47조 제1~3항](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0047&lsiSeq=279827&urlMode=lsScJoRltInfoR)

따라서 **나중에 좁히면 된다**는 계획만으로는 부족하다. 좁힐 구성 자체와 그 연결이 최초 명세서에 설명되어야 한다. 보고서나 코드가 컴퓨터에 있다는 것과 그 내용이 출원 명세서에 실렸다는 것은 다르다.

**상담용 한정안 구성 제안 — 등록성 순위가 아니라 비교할 설계안이다.**

| 안 | 상담에서 확인할 기술 범위 | 출원 전 준비 |
|---|---|---|
| A | 현재 같은 원음의 용도·능력·원래 시도별 자격과 기여 정정 | 기존 청구항 1의 조건과 선행 차이가 남는지 먼저 대조 |
| B | A에 원래 자료 확인과 새 수행의 결과 귀속 제어가 연결된 범위 | 행동 선택 조건과 실제 결과 저장 조건이 어떻게 같은 제약을 공유하는지 상세 실시예 |
| C | B 중 특정 해석 차이→원음 구간→허용 확인 행동→자격 갱신이 결합된 범위 | 실제 구현·입출력과 예외를 갖춘 뒤 선행 대조. 계획만 있는 기능을 구현 완료로 표시하지 않음 |

마케팅 목적의 등록 한 건이 우선이면, 변리사 판단상 A가 지나치게 일반적이고 B 또는 C의 구체 관계가 더 방어 가능할 때 그 관계를 초기 독립항에 넣는 선택을 검토한다. 단순히 길어진 안을 더 등록하기 쉬운 안으로 간주하지 않는다. 서로 다른 조합의 예비 문안은 내부 검토용이며, 여러 상충하는 청구범위를 동시에 심사해 달라는 절차로 오해하지 않는다.

불필요하게 회사명·마스코트·임의 숫자·개발 도구명을 한정으로 끼우지 않는다. 그 한정이 실제 과제를 해결하는 데 어떤 역할을 하는지 답할 수 있어야 한다. 장치와 기록매체 항은 보호 형식을 보완하는 방안이며 새로운 발명성을 자동으로 추가하지 않는다.

### 종속항과 명세서에 남길 의미 있는 대안

주안에서 꼭 필요한 결합을 유지하면서, 더 구체적인 입력 범위·귀속 제한·정밀화 처리 등을 종속항으로 준비한다. 각 대안은 최초 설명의 어느 문단·도면에 근거하는지 표로 연결한다. 독립항의 진보성이 부정되어도 종속항은 별도로 판단한다. 심사기준의 보정방향 제시 제도도 종속항이나 설명 속 구체 구성을 이용한 한정 방향을 다룬다. [심사기준 책쪽 3330 / PDF 328, 책쪽 8101~8103 / PDF 785~787](https://www.kipo.go.kr/ko/kpoContFileDown.do?seq=4&fileNum=1#page=785)

### 한 출원에 담는 범위와 분할의 한계

하나의 발명 또는 하나의 총괄적 발명 개념을 이루는 발명군이 한 출원의 기본 범위다. Core와 LOOM을 같은 회사 엔진이라는 이유만으로 한 청구범위에 모으는 전략은 이 요건의 근거가 되지 않는다. [특허법 제45조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0045&lsiSeq=279827&urlMode=lsScJoRltInfoR)

분할은 원출원의 최초 명세서·도면에 기재된 발명의 일부를 법정 기간에 별도 출원하는 제도다. 허용되는 기간에는 보정 가능 기간, 거절결정 송달 후 3개월 등, 특허결정 송달 후 3개월 이내이면서 설정등록 전인 기간 등이 있다. 실제 기한은 사건 상태별로 계산해야 한다. **나중에 새로 개발한 내용을 원래 날짜로 넣는 수단이 아니며**, 분할했다고 신규성·진보성이 생기는 것도 아니다. [특허법 제52조 제1~2항](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0052&lsiSeq=279827&urlMode=lsScJoRltInfoR)

## 4. 상담과 심사를 실제로 유리하게 쓰는 방법

### IP 디딤돌 미팅에서 받아올 판단

IP 디딤돌은 아이디어 컨설팅과 권리화·창업 연계 지원이다. 지원 선정이나 상담 통과를 특허 등록 심사 통과로 보지 않는다. [공식 IP 디딤돌 사업 안내, 2026.09.08 수정](https://www.kipo.go.kr/ko/kpoContentView.do?menuCd=SCD0200313)

이 미팅에서는 회사 소개를 반복하기보다 다음 결과를 요청하는 것이 실익이 있다.

1. **가장 가까운 문헌 번호와 실제 대조한 청구·설명 위치.** 현재 대조 자료를 출발점으로 하되 최종 선행 조사를 요청한다.
2. **독립항에 반드시 들어가야 할 관계.** 어떤 관계를 빼면 거절 반론이 강해지는지 확인한다.
3. **한정안 B/C의 채택·기각 이유.** 문헌 두세 개의 결합 동기, 필요한 변경, 기대 효과를 근거로 비교한다.
4. **최초 명세서에 빠지면 안 되는 실시 내용.** 구현된 것과 추가 설계 단계인 것을 구분한 문단·도면 목록을 확정한다.
5. **출원·중간 사건 대응의 담당과 지원 범위.** 의견서·보정 대응, 필요시 면담과 보정안 리뷰 준비를 누가 맡는지 정한다.

### 거절 이유를 받으면 보정안 리뷰를 활용한다

공식 안내의 보정안 리뷰는 최종 보정 전 심사관과 보정 방향을 논의하는 절차다. 거절이유가 통지된 출원에서 보정서 제출기간 만료일 1개월 전까지 보정안을 제출하는 등 신청 요건을 확인한다. 합의 가능성을 검토하는 수단이며 등록 보장은 아니다. [공식 보정안 리뷰 안내, 2026.07.30 수정](https://www.kipo.go.kr/ko/kpoContentView.do?menuCd=SCD0200117)

현재 안내 페이지는 자세한 기준을 제8부 제5장이라고 안내하지만, 내려받은 2026.03.12 PDF의 실제 목차와 본문은 **제8부 제4장, 책쪽 8401부터 / PDF 803부터**다. 실제 원문의 절명을 우선해 상담 자료에 표기한다. PDF에는 이미 면담을 실시한 출원의 재신청 등에 대한 추가 제한이 있어 신청 전 사건별 적합성을 확인해야 한다.

### 우선심사는 속도의 도구다

우선심사는 요건에 해당하는 출원을 다른 출원보다 먼저 심사하는 제도다. 출원의 심사 순서를 바꾸며 신규성·진보성·기재 요건을 완화하는 내용은 아니다. 현재 사용·실시 준비, 기술 분야 등 신청 사유는 별도 증빙을 통해 판단해야 한다. [특허법 제61조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0061&lsiSeq=279827&urlMode=lsScJoRltInfoR), [공식 우선심사 FAQ, 2026.07.31 수정](https://www.kipo.go.kr/ko/kpoContentView.do?menuCd=SCD0200226)
