# 실제 행동과 결과 귀속의 연결 — 현재 위치와 최소 설계 경계

2026-09-13 · 독립 기술 확인 · 설계만 작성 · 운영 코드/DB 변경 없음

**현재 Studio는 원음·새 응답·도움 사건을 저장하지만, 관측 계획 이후 실제로 실행된 재생·표시·녹음을 한 묶음으로 검사하여 결과의 사용처를 정하는 연결은 완성되지 않았다.** 아래는 그 빈자리와 기존 연결 위치다. 선행기술 대조가 우선으로 바뀌었으므로 추가 구현을 발주하는 문서가 아니다. 이를 구현하면 특허 등록 가능성이 높아진다는 판단도 포함하지 않는다.

## 5. 종류 하나의 허용 목록 대신 검사해야 하는 관계

최소 검사 순서는 다음과 같다. 이것은 신규성·진보성이 인정된 알고리즘이라는 주장이 아니다.

1. **기준 일치:** 계획의 원음·첨부 사건·시도·후보·엔진 판본이 현재 요청 대상과 일치하는지 검사한다. 텍스트가 같아도 다른 시도의 기록이면 통과시키지 않는다.
2. **실행 연속성:** 계획 이후의 실제 관련 사건과 반환 결과를 연결한다. 조회한 이력이 완전한지 모르면 “도움 없음”으로 바꾸지 않는다. 계획 뒤 다른 탭/사건이 상태를 바꾸었으면 새 상태에서 다시 계획한다.
3. **관측 범위:** 반환 결과가 주장하는 구간이 실제 원음 참조 및 필요한 후보 차이 구간들과 맞는지 검사한다. 3개 이상의 후보도 모든 관련 차이를 포함한다. 정렬이 불확실하면 전체 원음 확인 요구 등 보수적 범위를 쓰고, 그 비용을 숨기지 않는다.
4. **출처와 영향:** 자료가 누구에게 제시됐는지, 어느 수행 전·중·후인지, 어느 기술과 관련되는지를 조회한다. 원음 확인 결과와 새 수행 결과의 도착 순서가 뒤바뀌어도 실제 출처를 유지한다.
5. **목적별 적용:** 일치한 결과만 해당 원음/시도의 해당 목적에 반영한다. 관련 없는 문항 조건, 시간 미확인, 도움 범위 미확인 등 다른 보류 사유를 지우지 않는다. 사람이 새로 말한 답을 과거 원음의 후보 정답으로 자동 편입하지 않는다.

| 실제 실행과 결과 | 가능한 적용 경계 |
|---|---|
| 교사가 기존 원음을 재생하고 그 음성의 문자를 확인 | 원음·시도·범위·후보 등 나머지 조건이 맞으면 해당 원음 전사 확인에 사용 가능하다. 교사 화면 표시를 학생 도움으로 오인하지 않는다. |
| 학생이 기존 원음을 재생하고 그 원음의 내용을 확인 | 출처가 같은 원음이면 전사 확인 후보가 될 수 있다. 학생이 응답했다는 이유만으로 새 발화의 원음과 같다고 보지 않는다. 확인 정확도를 자동 보장하지 않는다. |
| 기존 원음 뒤 학생에게 정답을 표시하고 새로 녹음 | 새 녹음의 전사 및 해당 새 수행에만 귀속한다. 도움의 기술·시점이 관련되면 새 수행의 독립성 판단에 반영한다. 과거 원음의 독립성을 소급 삭제하지 않는다. |
| “현재 의도”를 새로 답했으나 기존 원음의 소리를 확인하지 않음 | 현재 의도/새 응답에만 사용한다. 그 문장을 과거 원음의 문자 정답으로 대체하지 않는다. |
| 대상이 불명확한 화면에서 답이 표시됨 | 학생에게 도달했는지 확인되지 않은 사실을 유지한다. 원음 전사와 독립 수행 각각의 규칙에 따라 보류할 수 있으며 모든 목적을 일괄 제외하지 않는다. |
| 필요한 원음 구간을 seek로 건너뛴 뒤 확인 버튼만 누름 | 버튼 선언과 구간 재생 근거를 분리한다. 구간 관측 조건이 필요한 경로에서 이를 충족했다고 표시하지 않는다. |

교사가 후보 문장을 보았다는 사실만으로 원음 전사가 자동 무효가 되는 규칙도 여기서 도출하지 않는다. 검토자 편향의 측정과 정책은 별도 문제이며 “학생에게 답을 주었는가”와 같은 조건으로 취급하면 안 된다.

## 6. 기존 연결을 이용할 때의 제한

- **저장:** Studio의 전체 사건 저장·멱등성·판본 검사·export를 재사용할 수 있다. 새로운 실행 사건 종류는 현재 Core가 처리하지 않으므로 이름을 추가해 POST하는 것만으로 연결되지 않는다. 처리할 어댑터와 재실행 계약을 함께 정의해야 한다.
- **Core 판본:** 새 사건 또는 의미를 추가한다면 해당 판본의 전체 저장/재현 경로도 맞춰야 한다. 기존 코드 묶음으로 새 사건을 재생할 수 있다고 가정하면 안 된다.
- **계획 판본:** 현재 실험 계약은 전체 세션 지문과 revision을 묶는다. 실제 도움 저장처럼 상태가 바뀌면 기존 계약은 낡는다. 행동 사건을 무조건 지문에서 빼는 우회는 금지하고 새 상태에서 계약을 다시 계산하는 것이 최소 경계다. 재생 진행 로그처럼 의미 상태를 바꾸지 않는 기록을 별도로 보유하더라도, 종료 시 서버 상태와 전체 실행 이력을 함께 확인해야 한다.
- **재시도:** 현재 `saveEvent`는 사건 객체를 유지하면서 최신 revision으로 재시도할 수 있다. 새 계획에 묶인 결과는 충돌 뒤 같은 본문을 최신 revision만 붙여 재사용하면 안 된다. 출처와 계획이 여전히 유효한지 다시 검사해야 한다.
- **직접 확인 경로:** 현재 일반 `review-original` 입력은 별도의 수동 선언 경로다. 새 계약을 검사한 결과와 증거 수준을 구분해야 한다. 모든 수동 확인이 재생 추적으로 인증됐다고 출력하면 안 된다.
- **Talk 연결:** 기존 `audio_ref`·부모 사건·시도·멱등성은 보존한다. 새로운 운영 계약, DB, 중앙 큐, 소리 게이트 훅을 이번 설계로 도입하지 않는다. Studio 안의 합성 시연 결과가 Talk의 기기 실행이나 학습 성과를 증명하지도 않는다.

## 7. 현재 결론과 남은 검증

현재 코드에는 이 설계에 필요한 입력의 일부와 전체 사건을 보존하는 저장 통로가 있다. 대상 구분, 계획별 재생 구간, 실행 이력과 반환 결과의 검증은 신규 연결이 필요하다. 그 추가 개발의 크기는 특허의 진보성을 나타내지 않는다.

부모 작업에서 새로 확인한 근접 선행 원문과 먼저 구성별로 대조해야 한다. 이 문서는 해당 원문의 청구항·문단을 독립 재검증한 선행 분석서가 아니다. 이미 알려진 복수 전사·원음 재생·결과 의미/학습 사용 구분을 이 기록 구조의 설명만 바꾸어 새 차이라고 제시하지 않는다.

추후 연결을 실제 구현하기로 한다면 최소 재현 입력은 다른 학생 대상/교사 대상, 같은 파일의 다른 시도, 필요한 구간 건너뜀, 3개 이상 후보, 계획 뒤 도움 사건, 새 녹음의 과거 원음 사칭, 중복/순서 역전, 전체 payload 재생이다. 통과는 그 입력에서의 동작 확인이며, 등록성·인지적 노출 인증·현장 정확도 향상은 별도 근거가 필요하다.
