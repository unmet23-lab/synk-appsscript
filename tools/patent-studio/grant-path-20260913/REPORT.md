# 결합 반론에 대응할 다음 구성

2026.09.13 · SYNK Core 추가 설계·검증 · 출원 상담용

**현재 먼저 검토할 구성은 ‘판정 차이 → 원음 확인 구간 → 결과 사용 조건 → 실제 결과 검사’를 연결하는 방식입니다.** 등록 우위가 확인된 확정안은 아닙니다. 기존 원음의 내용을 확인하는 일과 학생에게 다시 말하게 하는 일이 서로 다른 증거를 만든다는 점을 기술 구조에 반영하는 후보입니다.

이번에는 이 관계 중 **원음 재검토 한 종류를 대상으로, 확인 범위와 결과 귀속 조건을 묶고 검사하는 부분**을 실험 코드로 만들었습니다. 구현 검증, 선행 대비 기술 분석, 법적 등록 판단을 구분합니다. 기존 공보형 초안과 Core 0.5 원본은 보존했고, 추가 관계는 별도 검토안으로 작성했습니다.

## 1. 결합 반론에서 실제로 다투는 것

‘A 문헌에는 기록 정정, B에는 힌트 기록, C에는 확인 질문이 있으니 합치면 된다’는 주장이 결합 반론입니다. 중요한 것은 부품의 존재 외에 **그렇게 연결할 이유와 연결의 어려움**입니다. 공식 심사기준은 개별 구성의 공지성만으로 전체 결합의 진보성을 부정하지 않으며, 완성된 발명을 알고 거꾸로 판단하는 사후적 고찰도 경계합니다. [공식 심사기준 제3부 제3장 §7·§9, 책쪽 3324~3326·3329](https://www.kipo.go.kr/ko/kpoContFileDown.do?seq=4&fileNum=1#page=322)

따라서 ‘기존 기능을 쓴다’는 사실은 탈락 사유 자체가 아닙니다. 반대로 기능을 연결하거나 이름을 새로 붙인 사실도 진보성의 증거가 아닙니다. **가장 가까운 기존 기술에서 출발하여, 어떤 입력·처리·저장 관계를 바꿔야 이 구성에 도달하는지** 설명해야 합니다.

등록 한 건이 우선인 사업 목적에는, 방어 근거가 있는 구체적인 관계를 초기 독립항, 즉 다른 항을 인용하지 않고 발명의 필수 구성을 적는 청구항에 포함시키는 선택이 맞을 수 있습니다. 범위를 좁힌다는 이유만으로 등록이 쉬워지는 것은 아닙니다. 한정의 기술적 역할이 필요합니다.

## 2. 누구나 이해할 수 있는 한 장면

학생의 처음 녹음 A에 대해 받아쓰기 후보가 두 개 있다고 가정합니다.

| 후보 | 받아쓴 문장 | 조사 기록 | 과거형 기록 |
|---|---|---|---|
| H1 | 친구를 만나서 카페에 갔어요 | 문항에서 요구한 목적격 사용 | 과거형 사용 |
| H2 | 친구가 만나서 카페에 갔어요 | 목적격 사용과 다른 결과 | 과거형 사용 |

과거형 결과는 두 후보에서 같습니다. 조사 결과와 정확한 전사 문장은 다릅니다. 다른 문항·도움·범위 조건까지 충족하는 통제 사례라면, 과거형 기록은 유지하면서 나머지는 보류할 수 있습니다. 이것은 ‘학생이 과거형을 완전히 숙달했다’는 판정이 아닙니다.

여기서 학생에게 정답을 알려 주고 다시 말하게 하면 새 녹음 B를 얻습니다. B가 ‘친구를’이라고 분명히 말해도 **A에 실제로 ‘친구를’이 녹음되었다는 사실이 되지는 않습니다.** 학생의 현재 의도를 확인한 답변도 원래 파형의 정확한 전사와는 다른 자료입니다.

새 후보는 이 차이를 처리 관계로 만듭니다. A에 관한 판정 차이에서 A의 확인 구간을 정하고, 같은 순간에 ‘A의 원음을 검토한 결과만 이 확인의 답으로 사용한다’는 조건을 만듭니다. 실제로 B가 오거나 조건이 바뀌면 A의 확인 결과로 적용하지 않습니다.

## 3. 세 연결을 한 사슬로 묶는다

### 연결 1 — 판정 차이가 확인할 원음을 결정한다

여러 후보를 각 사용 목적의 평가 규칙에 넣어 봅니다. 결과가 같은 목적과 다른 목적을 나누고, 다른 경우에는 그 차이를 보여 주는 후보 쌍을 남깁니다. 이 후보 쌍을 여기서는 ‘차이 근거’라고 부릅니다.

차이 근거와 후보의 단어별 원음 위치를 연결해 확인 범위를 만듭니다. 현재 실험은 단어 시각을 입력으로 받습니다. 시각이 없거나 삽입·삭제 때문에 대응이 모호하면 전체 원음으로 돌아갑니다. 가장 짧거나 최적인 구간을 보장하는 알고리즘은 아닙니다.

음성 후보를 원음 시간 구간에 대응시키는 기술은 이미 존재합니다. 그러므로 짧은 구간만 재생한다는 설명을 새 발명의 중심으로 내세우지 않습니다. [US9779724B2, 설명 도3·4 및 원음 구간 대응](https://patents.google.com/patent/US9779724B2/en)

### 연결 2 — 확인 방법을 정할 때 결과를 쓸 곳도 함께 정한다

확인 대상과 결과 사용 조건을 별개의 느슨한 설정으로 두지 않고 같은 계약 객체에 넣습니다. ‘계약’은 법률 계약서가 아니라 **프로그램의 입력·출력 조건을 적은 데이터 묶음**입니다.

계약에는 원음 식별자, 시도 식별자, 대상 기록, 후보 집합, 확인 범위, 상태 판본, 허용 결과 종류를 담습니다. 현재 실험의 허용 결과 종류는 `source-audio-review`로 고정돼 있습니다. **행동의 실제 답 노출·새 수행 이력을 읽어 목적별 허용 조건을 공동 계산하는 부분은 아직 구현하지 않았습니다.** 현재는 제출된 원음·시도·구간·후보·상태 판본과 초기화 시 고정한 평가 코드 식별을 검사합니다.

관측 행동과 그 영향을 따져 계획하거나 데이터의 출처·사용 정책을 전파하는 일반 기술은 기존입니다. 차별점 후보는 이름이나 표지 자체가 아니라 **판정 차이에서 확인 행동과 결과의 사용 제한이 함께 도출되는 관계**입니다. [정보흐름 정책 연구, §2~4](https://www.cs.cornell.edu/andru/papers/sp98/paper.html)

### 연결 3 — 계획과 실제 결과를 같은 조건으로 대조한다

계획만 세웠을 때 기록을 반영하지 않습니다. 확인 결과가 온 뒤 계약의 원음·시도·구간·후보·판본과 비교합니다. 실제 결과가 조건을 만족할 때 후보를 줄이고, 변경된 입력으로 Core가 기록별 조건을 다시 판단합니다.

다시 말한 답은 새 시도로 저장할 자료입니다. 원래 녹음의 확인 계약에서 거절됐다는 이유로 새 응답 자체를 버리면 안 됩니다. 현재 실험 어댑터는 원래 계약에 대한 거절까지만 담당하고, 새 응답 저장은 기존 작업실의 별도 경로가 담당합니다. 두 경로의 실제 UI·저장 통합은 아직 하지 않았습니다.

출처 식별자와 재검사 자체도 흔한 수단입니다. 따라서 이 세 연결을 모두 갖춘 구성이 선행의 정상적인 연결 결과인지, 추가적인 기술적 판단을 요구하는지 검토해야 합니다.

## 4. 심사에서 예상할 반론과 답변의 근거

| 예상 결합 | 반론의 힘 | 우리가 구체적으로 설명할 차이 | 아직 필요한 증거 |
|---|---|---|---|
| 지연 사건 재처리 + 힌트 사용 기록 | 학습 기록을 정확히 유지하려는 결합 동기가 자연스러움 | 사건 순서를 바로잡는 것에서 더 나아가 같은 파형의 복수 후보를 사용 목적별로 평가하고 확인 입력을 정함 | 가까운 문헌의 실제 입력·출력과 우리 연결의 변경표 |
| 부분 확인 질문 + 음성 대체 후보 | 불확실한 부분을 질문하고 원음에 대응시키는 수단이 모두 존재 | 현재 의도를 확인한 답과 원래 파형을 검토한 결과의 종류를 구분하고, 평가 차이에서 확인 범위와 사용 조건을 함께 생성 | 그 구분·공동 생성이 기존 기술에서 쉽게 도출되는지 추가 표적 조사 |
| 출처 표지 + 목적별 사용 제한 + 판본 검사 | 데이터 처리 시스템에서 알려진 수단이며 강한 반론 | 계획의 대상과 실제 결과의 귀속을 같은 차이 근거에서 연결; 제공된 모든 후보를 반영한 확인 범위 | 독립항의 전체 연결에 대한 결합 동기·필요 변경·예측 효과 검토 |

첫 행의 문헌은 [US20180315330A1](https://patents.google.com/patent/US20180315330A1/en), [US10943497B2](https://patents.google.com/patent/US10943497B2/en)입니다. 두 번째 행은 [US9953644B2](https://patents.google.com/patent/US9953644B2/en), [US9779724B2](https://patents.google.com/patent/US9779724B2/en)입니다. 세 번째 행은 [US20230289460A1](https://patents.google.com/patent/US20230289460A1/en), 위 정보흐름 논문과 일반 판본 검사 기술을 고려한 분석입니다. 표는 문헌의 동일성을 확정한 법적 판단이 아니라 예상 반론과 검토할 차이를 정리한 것입니다.

‘질문 기술은 학생의 의도를 알아낸다. 우리는 원래 파형에 대응하는 자료가 필요한 경우를 따로 처리한다’는 설명에는 의미가 있습니다. 그러나 음성 학습자료와 평가자료를 함께 다루는 기술자가 같은 분리를 자연스럽게 설계할 수 있다는 재반론도 가능합니다. 그 재반론까지 조사하기 전에는 ‘극복했다’고 표현하지 않습니다.

## 5. 독립항과 좁은 대안을 준비하는 방법

새 주안 가칭은 **‘음성 후보의 평가 차이에 따른 원음 확인 및 결과 귀속 제어 방법’**입니다. 엔진 이름을 정하는 일과 발명의 기술적 명칭을 정하는 일은 구별합니다.

| 문안 | 꼭 들어갈 관계 | 현재 취급 |
|---|---|---|
| 기존안 | 늦게 받은 도움 사건에 따른 원음·목적·능력별 기여 갱신 | 09.12 공보형 초안 보존. 새 구성 전체가 이미 들어 있다고 보지 않음 |
| 새 결합안 | 후보별 평가 차이 → 확인 구간과 결과 사용 조건 공동 생성 → 실제 결과 대조 → 후보 정밀화와 기록 재판정 | 다음 선행 대조·명세서 구체화의 주안 후보 |
| 더 구체적인 대안 | 모든 현재 후보의 차이 구간을 포괄하고 불충분한 정렬은 전체 원음으로 복귀; 원음·시도·후보·평가 규칙 판본 불일치 결과를 재계획 대상으로 처리 | 그 한정이 필요한 기술적 이유와 실시예를 최초 문안에 준비 |

한정한 문언을 길게 적는 것이 목적이 아닙니다. **한 구성을 뺐을 때 어떤 입력에서 무엇이 달라지는지** 설명할 수 있어야 합니다. 회사명·마스코트·임의 숫자·개발 도구 이름을 붙여 차별점처럼 만들지 않습니다.

최초 명세서에는 기본 구성뿐 아니라 실제 쓸 수 있는 한정안의 연결까지 써야 합니다. 나중의 보정으로 최초 내용에 없던 새 기술을 원래부터 있던 것처럼 넣을 수는 없습니다. [특허법 제47조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0047&lsiSeq=279827&urlMode=lsScJoRltInfoR)

## 6. 이번에 만든 구현과 실제 시험

실험 모듈은 기존 Core에서 차이 근거를 가져와 확인 계약을 만들고, 결과를 검사한 뒤 실제 Core의 검토 사건으로 반영합니다. 기존 엔진 파일과 운영 저장소는 변경하지 않았습니다. 실험 화면은 이 실행 결과를 재생하며, 버튼을 누를 때 운영 엔진에 요청하는 화면은 아닙니다.

| 합성 시험 | 확인한 결과 |
|---|---|
| 올바른 원음 확인 결과 | 전사·조사 기록 반영, 이미 유효한 과거형 유지 |
| 같은 바이트지만 다른 시도의 결과 | 원래 계약에 적용하지 않음 |
| 계약 생성 뒤 도움 사건 추가 | 낡은 상태 판본 계약 거절 |
| 원래 시도 전에 조사 도움 존재 | 전사는 확인 후 사용 가능, 조사 독립 수행은 계속 제외 |
| 세 번째 후보가 문장 끝에서도 다름 | 첫 단어만 확인했다는 결과로 세 번째 후보까지 제거하지 않음 |
| 정렬 자료 없음 | 원음 전체 확인 범위로 복귀 |

별도의 독립 테스트는 계획의 상태 불변, 부족한 구간, 후보 밖 답, 복수 후보 유지, 다른 보류 조건 보존, 중복 재송신, 재생 결과를 검사합니다. 최신 개수와 입력·코드 지문은 `lab/VERIFICATION.json` 및 `lab/RESULTS.json`을 봅니다. 개수는 특허 심사의 점수가 아닙니다.

기존에 직접 만든 합성 음성 `original.wav`의 실제 파일은 **131,196바이트, 약 2.974초**이고 알려진 SHA-256과 일치했습니다. 후보 문장·단어별 시각·문항·도움 조건은 수동 시험 입력입니다. 0~550ms 같은 좁은 구간은 이 입력에서 나온 계산 결과이며, 실제 단어 경계를 측정하거나 청취 정확성을 입증한 값이 아닙니다.

## 7. 비교 실험에서 불리한 결과도 남겼다

원음·시도·정책을 검사하는 일반 방식에도 같은 조건을 주고, 목적지 3개와 결과 3개를 교차한 9쌍의 귀속 결과를 비교했습니다. **9쌍 모두 같았습니다.** 따라서 표지를 세분화한 것만으로 더 나은 결과가 나왔다고 주장하지 않습니다.

이 비교는 일반 방식에 이미 주어진 조건을 실행하는 시험입니다. 그 조건의 연결 자체를 선행으로부터 쉽게 설계할 수 있었는지에 대한 답은 아닙니다. 약한 비교군의 실수를 만들어 차별점이라고 하거나, 우리 설계를 미리 넣은 비교군을 보고 ‘선행도 이미 갖고 있었다’고 해석하지 않습니다.

현재 실험은 거절할 자료를 거절하고 사용할 자료를 보존하는 처리 관계의 구현 증거입니다. 경쟁 시스템 대비 우월성, 실제 학생 효과, 등록 확률은 측정하지 않았습니다. 새로운 관계의 진보성은 가장 가까운 선행과 별도 검토해야 합니다.

## 8. 데이터·책임·계산 범위

| 구성 | 입력과 출력 | 책임과 한계 |
|---|---|---|
| Core 평가 | 원음 후보·문항·도움 조건 → 기록별 상태·차이 근거 | 지원하는 통제 문장·조사·과거형 규칙. 일반 한국어 전 능력 추론 아님 |
| 계약 생성기 | 위 상태 + 단어 정렬 → 원음·시도·범위·후보·판본 조건 | 후보 집합의 완전성과 외부 정렬의 진실을 자동 인증하지 않음 |
| 결과 검사기 | 계약 + 확인 결과 → 적용 또는 거절 | 제출된 필드의 관계를 검사. 사람이 실제로 정확히 들었다는 사실까지 보장하지 않음 |
| Core 반영 | 검증된 검토 사건 → 후보·기록 재계산 | 기존 문항·범위·도움 보류를 임의로 없애지 않음 |
| 저장·UI 연결 | 계약 저장·원음 재생·실제 결과 수집 | 새 어댑터와의 운영 통합은 미구현. 저장할 때 계약은 신뢰되는 서버 원본에서 조회해야 함 |

내용 지문은 바이트나 데이터가 같은지 확인하는 값입니다. 누구나 다시 계산할 수 있는 해시를 전자서명이나 실제 행동의 증명으로 설명하지 않습니다. 계약 ID만 클라이언트에서 받아 서버가 보관한 계약을 찾고, 실제 원음 재생 및 결과 기록을 연결하는 운영 단계가 필요합니다.

현재 구간 계산은 후보 수 H, 후보당 단어 수 W에 대해 후보 쌍 전체를 비교하고 삽입·삭제의 모호성을 동적 계획법으로 검사합니다. 최악의 구간 계산량은 대략 **O(H²W²)**이며 후보 쌍 기록도 늘어납니다. Core 전체 평가·관측 계획·지문 계산 비용은 별도입니다. 현재 한도는 후보 40개·후보당 단어 512개·정렬 행 200개이며, 대용량 성능 우위는 입증하지 않았습니다.

기존 Core만으로 결과 사건을 재생하면 평가 기록은 같지만 상세 사건 payload를 로그에서 버립니다. 새 계약의 감사 정보와 재송신 처리를 유지하려면 원래 이벤트 본문을 보존하는 저장·재생 연결이 필요합니다. 이 경계를 ‘재생 전체 완료’로 보고하지 않습니다.

## 9. 회사의 다른 후보와의 비교도 바로잡았다

별도 LOOM 후보는 표정 전환에서 털 바탕이 흔들리는 문제를 다룹니다. 이번에 현재 승인 코드까지 다시 확인하니, 예전의 넓은 얼굴 영역 복사는 현재 방식이 아니었습니다. 현재는 공통 털 바탕을 한 번 만들고 좁은 눈 변화 영역을 합성하며 알파와 바탕을 유지하는 방식입니다.

대표 한 차림의 저장된 8컷에서 변화 영역 밖 RGBA 동일성과 전체 알파 동일성을 확인했습니다. 이는 해당 출력의 일관성 증거이며 모든 캐릭터의 자연스러움·범용 자동화·특허성의 증거는 아닙니다. 과거 회사 후보 표를 현행 코드의 확정 평가처럼 쓰지 않도록 이 정정을 붙입니다.

LOOM은 독립 예비안으로 유지합니다. Core보다 등록하기 쉽다고 판정할 근거는 아직 없습니다. 회사 엔진이라는 이유로 두 발명을 하나의 청구항에 섞지 않습니다. 서로 다른 기술적 과제는 별도 후보로 대조합니다.

## 10. 미팅에서 이렇게 보여 준다

**첫 30초:** “이번 원음 재검토 실험에서는 한 녹음에서 여러 해석이 나올 때, 판정 차이에서 확인할 원음과 결과의 사용 조건을 함께 만듭니다. 실제 결과가 그 조건에 맞을 때만 기록을 갱신합니다.” 전체 행동 선택까지 구현했다는 뜻으로 설명하지 않습니다.

**다음 1분:** H1/H2 표를 보여 줍니다. 조사와 전사는 보류되고 과거형은 유지되는 이유를 설명합니다. 학생에게 다시 답하게 하면 새 자료를 얻는다는 점을 원음 A와 새 녹음 B로 구분합니다.

**다음 2분:** 실험 결과 재생에서 ‘처음 원음 확인’, ‘같은 문장을 새로 말함’, ‘세 번째 후보’, ‘정렬 없음’을 차례로 고릅니다. 바뀐 기록과 유지된 기록을 같이 보여 줍니다. 합성 조건을 사용한 로컬 실험임을 표시합니다.

**다음 2분:** 선행 결합표와 9쌍 동일 결과를 보여 줍니다. “식별자 검사 자체가 새롭다는 주장은 하지 않습니다. 이 입력·출력의 공동 생성 관계가 가까운 선행에서 쉽게 나오는지 봐 주세요”라고 요청합니다.

**마지막에 받아올 판단:** 가까운 선행 문헌·차이 위치, 새 결합을 독립항에 넣을 실익, 한정안의 기술적 근거, 최초 명세서에 필요한 구현 설명, 출원 및 거절 대응의 담당·지원 범위를 확정합니다. IP 디딤돌 지원 상담과 특허청의 등록 심사는 다른 단계입니다. [공식 IP 디딤돌 안내](https://www.kipo.go.kr/ko/kpoContentView.do?menuCd=SCD0200313)
