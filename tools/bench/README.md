# 선택형 코딩 비교시험 — 과거 실측 자료

**무엇**: 같은 코딩 과제를 여러 AI 벤더에 주고 **기계 채점**으로 비교한다.
**왜**: 창고(새 코드베이스) 착수 때 「어느 벤더에 뭘 맡길지」를 감이 아니라 실측으로 정하려고.

## ARC 폴더의 역할과 현재 보관 상태

이 비교시험은 공개 코드베이스의 같은 과제를 모델마다 따로 수행시켜 결과를 비교하는 선택 도구다. 회사 엔진이나 기본 AI 작업의 필수 구성품이 아니며, 폴더만 두어도 모델 지능이 올라가는 기능은 아니다. 모델별 작업 권한은 이 과거 실험이 아니라 `docs/AI_운영원칙.md`를 따른다.

2026-09-09 정리에서 루트의 `ARC-AGI-3-Agents`는 별도 Git 이력까지 포함해 로컬 보관함의 `저장소정리.zip`에 검증 보관하고 활성 작업 폴더에서 제거했다. 경로·검증 수·복원 방법은 [정리 보고서](../../docs/저장소_정리_2026-09-09.md)의 보관 항목을 본다. 아래 실측을 다시 하기로 했을 때만 복원하거나 [공식 저장소](https://github.com/arcprize/ARC-AGI-3-Agents)를 별도 작업장에 준비한다. 설치·실행의 API 비용은 개인 구독과 구분한다.

실측 원본은 읽기만 하고 모델별 작업장은 각각의 clone으로 분리한다. 옛 Claude 전용 훅이 현재 작업을 막는다고 가정하거나 그 훅을 복원하지 않는다.

## 돌리는 법

```
# 1. 작업장 준비 (벤더당 하나, 스크래치패드에)
git clone <ARC 저장소 경로> <작업장>/<벤더명>

# 2. 각 벤더에게 tools/bench/과제.md 를 그대로 준다 (프롬프트 동일이 공정성의 전부다)
#    Codex 예:  codex exec -C <작업장> -s workspace-write -c approval_policy="never" - < 과제.md

# 3. 채점
python tools/bench/채점.py <작업장>/<벤더명>
```

## 채점기 자기검증 — 먼저 이것부터

**채점기가 틀리면 실측 전체가 무의미하다.** 벤더를 돌리기 전에 항상:

```
python tools/bench/채점.py tools/bench/_ref    # 정답 → 13/13 이어야 한다
python tools/bench/채점.py tools/bench/_bad    # 오답 →  4/13 이어야 한다
```

`_ref`가 만점이 아니면 **거짓양성**(멀쩡한 제출을 감점), `_bad`가 만점이면 **거짓음성**(틀린 제출을 통과).
2026-08-03 실측에서 이 자기검증이 채점기 결함을 **두 개** 잡았다:

1. `"Recorder" in src` 문자열 매칭 → **docstring에 단어만 있어도 통과**했다. AST 파싱으로 교체.
2. 손으로 적은 표준 라이브러리 화이트리스트 → `importlib`가 목록에 없어 **멀쩡한 제출을 감점**했다.
   추측하지 말고 `sys.stdlib_module_names`(인터프리터가 아는 진짜 목록)를 쓴다.

`_ref/_bad`의 `agents/recorder.py`는 **스텁**이다(남의 저장소 코드를 복사하지 않기 위한 것).
실제 채점은 각 작업장의 진짜 `recorder.py`를 로드한다.

## 설계 원칙 (바꾸기 전에 읽을 것)

- **테스트를 벤더에게 주지 않는다.** 주면 「명세 준수」가 아니라 「테스트 맞추기」를 재게 된다.
  유호님 실사용이 자연어 명세이므로 명세도 자연어로만 준다.
- **`agents/__init__.py`를 실행하지 않는다.** 그 파일이 langgraph·smolagents·arcengine을 전부
  import하므로, 그대로 로드하면 벤더 능력이 아니라 `uv sync` 성공 여부를 재게 된다.
- **과제는 외부 의존 0인 소재로 고른다**(`recorder.py`는 순수 표준 라이브러리다).
  환경 구축이 벤치의 절반을 먹으면 그건 벤더 비교가 아니다.

## 언제 다시 돌리나

- **창고(새 코드베이스) 착수 직전** — 그때가 벤더 배치를 실제로 정하는 시점이다.
- 새 벤더를 스택에 넣을지 판단할 때.
- ⚠ 과제 1개·1회 실행은 **통계가 아니다.** 판정에 쓰려면 과제를 늘리고 각 벤더를 여러 번 돌린다.

예전 결과 기록 경로 `docs/_ops/벤더실측.md`는 현재 파일이 없다. 필요할 때 Git 이력을 확인하되, 이 안내만으로 실제 실측 완료를 주장하지 않는다. 새 비교시험을 명시적으로 요청받으면 해당 결과와 실행 조건을 함께 남긴다.
