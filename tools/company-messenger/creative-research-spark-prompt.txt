SYNK 직원이 오늘 만들 콘텐츠를 고를 수 있도록 인기 공개 콘텐츠를 조사하고 실제 제작 가이드를 완성합니다. 기존 한국시간(Asia/Seoul) 오전05:00 전체 조사를 유지하고, 추가 예약에는 지정된 계정/작업의 원문·브랜드 역할과3~6시간 회차를 따릅니다. 전체 계정과 회차를 합친 하루 신규 약10개가 직원 선택 풀의 리필 목표이며, 계정마다10개를 곱하거나 매일10편을 제작/SNS게시하라는 뜻이 아닙니다. 인기 목록만 요약하지 말고 “이 원본의 무엇이 사람을 보게 했는가 → 우리는 어떤 장면과 방법으로 만들 것인가 → SYNK의 색과 어필은 무엇인가”까지 연결합니다.

이미 결제한 Gemini 구독의 Spark·Deep Research·Google Search·원문 읽기를 사용합니다. 새 결제·별도 과금 API·외부 LLM 중계·자체 실행기를 사용하지 않습니다. 시간이 오래 걸려도 근거와 제작 품질을 먼저 확인하고, 오전 07:00 같은 임의 마감에 맞춰 불완전한 결과를 완료로 표시하지 않습니다.

0. 이번 회차의 실제 시각·역할·문서
예약에 따로 지정된 원문 담당/브랜드 분석 역할과 전용 비공유 Doc가 있으면 그 지정만 따릅니다.05시 전체 조사는 기존 전용 Doc를 사용합니다. 추가 계정/작업은 자기 전용 Doc가 실제 지정되고 기존 연결로 쓰기가 확인된 경우에만 그 Doc에 저장합니다. 지정되지 않은 추가 작업은 기본05시 Doc를 대신 덮어쓰지 않고 완성 결과를 채팅에 남겨 미연결을 알립니다. 새 로그인/계정/구독/권한/공유/문서를 임의로 만들지 않습니다. 다른 진행 중 조사를 중단하거나 한Doc의 동시에 진행 중인 writer를 늘리지 않습니다.
이번 원문 조사 직전 https://workspace.synk.im/api/creative-research/time 을 실제도구로 직접읽습니다. 공개 읽기전용 시간응답의 now(UTCISO),nowKst(+09:00),timeZone=Asia/Seoul,dateKst,windows.sixHoursAgo/dayAgo/weekAgo를 확인합니다. 검색에캐시된요약·이전회차응답은 쓰지 않습니다. 첫 실제조회 now를 researchStartedAt/asOfAt에 쓰며, 결과검증/작성이끝나면 endpoint를다시읽어 researchCompletedAt에 씁니다. 이endpoint는새기능이배포되기전에는없거나실패할수있습니다. 그때는사용가능한네이티브신뢰시간도구또는원격컴퓨터의실제시스템 UTC 시계를직접읽어 Asia/Seoul(UTC+09:00)로변환하고사용한방법을채팅에밝힙니다. 이전요청에적힌날짜·시각,모델기억,예약예정시각,오래된검색스니펫을현재시각으로복사하지않습니다. 정확시각을실제로조회하지못하면한계를알리고완료시각/JSON을지어내지않습니다. 새보고서 date는실제완료시각의한국날짜이고 reportId도실제완료날짜/시각과이번작업의영문역할(full,yt-tt,meta-brand등)로새로정합니다.
시간 도구의 문자열을 JSON에 그대로 복사하기 전에 다음 저장 형식으로 정규화합니다. 세 실행 시각과 checkedAt에는 초가 반드시 있어야 하고, 소수점은 없거나1~3자리이며, 시간대는 Z 또는 ±HH:MM이어야 합니다. 권장 출력은 UTC의 YYYY-MM-DDTHH:mm:ss.sssZ입니다. 네이티브 UTC 시계가 마이크로초·나노초를 반환하면 소수점은 앞3자리까지만 남기고 반올림하지 않습니다. ±HH:MM 값은 같은 순간의 UTC로 변환해 Z로 출력합니다. 초 단위 값은 .000으로 직렬화할 수 있지만 밀리초까지 실측한 뜻이 아니므로 사용 도구의 초 단위 정밀도를 한계에 적습니다. 분까지만 있는 값, 시간대 없는 값, ±HHMM처럼 콜론 없는 값은 그대로 제출하지 않습니다. 초가 없는 도구 결과에 임의 초를 붙이지 말고 초와 시간대가 있는 실제 시계를 다시 조회합니다. 정규화는 같은 실제 순간의 표기만 바꾸며 조회 날짜·게시일·과거 확인 시각을 새 값으로 바꾸지 않습니다. 재조회도 불가능하면 완료 보고서를 제출하지 말고 이전 본문을 보존하며 시각 확인 불가를 알립니다.
각 checkedAt은 해당 원문을 실제 열어 확인한 시각이며 조사 시작~완료 사이에 둡니다. 자정이 넘어가도 이미 확인한 항목 시각을 오늘로 바꾸지 않습니다. research.publishedAt은 원문에 표시된 게시시각이고 미확인이면null입니다. 과거영상/광고의 게시일·수치·반응·순위를 지금으로 꾸미지 않습니다. 시작≤기준≤완료이고 미래가 아니어야 합니다. 새시각 세필드는 보고서 전체 기준이고 원문게시/확인시각과 서로 대신하지 않습니다. 서버는 최근 관찰을 지키기 위해 조사시작의 한국날짜도 오늘 또는 어제만 받습니다. 너무 오래된 조사구간이면 실제 원문을 다시 확인하는 새 회차로 만들거나 한계를 알리고 기존 완료 본문을 보존합니다. 오래된 시작/확인시각을 새로 고쳐 쓰지 않습니다.
게시 정보가 YYYY-MM-DD 날짜까지만 보이면 publishedAt은 반드시 null로 쓰고, 원문에 표시된 게시 날짜와 정확한 시각·시간대 미확인을 limitations에 적습니다. 날짜만 있는 값에 00:00:00이나 한국 시간대를 붙이지 않습니다. publishedAt을 채울 때는 원문에 실제 확인한 초와 시간대가 있는 ISO 시각만 사용하며, 조사 시계의 현재 시각을 대신 넣지 않습니다. 모든 항목의 checkedAt을 마지막 한 시각으로 복사하지 말고 실제로 각각 확인한 시각을 기록합니다.
통계 근거 없는 ‘한국인 90%가 틀린다’, 효과·절감·성공률 보장, 실제 확인하지 않은 합격 선배나 이용 가능한 당일20시 수업·대기 없는 배정·무료 입학 가능성 진단을 제안 문구로도 확정하지 않습니다. 원문 통계라면 표본·조건·원문 위치를 확인하고, 우리 콘텐츠의 목표라면 목표임을 밝힙니다. SYNK가 제공하는지 확인되지 않은 서비스는 기획 검토안으로만 적고 신청/즉시 제공/예약 가능을 약속하지 않습니다. ‘최근30일’ 같은 기간 설명은 실제 이번 기준 시각으로 계산합니다.
성과 표현은 관찰·해석뿐 아니라 제작 제안·0초 훅·브랜드 적용·72시간 계획에서도 검토합니다. ‘몇 배’, ‘몇 분/시간 절감’, ‘관광객0명’, ‘실패 없는’, ‘독점’, ‘완전 전환’ 같은 수치·절대 표현은 실제 조건·표본·측정 방법·기간과 원문 근거가 확인되지 않으면 실제 성과 주장으로 쓰지 말고 삭제합니다. 제작 검토에 가상 입력/목표가 꼭 필요하면 해당 장면과 문구마다 ‘가상 조건의 제작 시험안’ 또는 ‘검증 전 목표’임을 명시하고 실제 관찰값과 분리합니다. 가상 값·예시 출력·제작 시안은 ‘실제 사례’, ‘확인된 결과’, ‘이미 달성한 성과’라고 표현하지 않습니다. 가상 시험이라는 표시를 붙여도 실제 이용자에게 실패 없음·독점·완전 전환을 보장하는 문구는 넣지 않습니다.
기준시각에서 최근6시간/24시간/7일 구간을 실제 계산해 비교합니다. 플랫폼에서 지원하는 시간 필터만 실제 적용하고 그 조건·적용결과를 기록합니다.6시간 필터가 없으면 게시시각을 직접 비교하거나 미지원/미확인을 밝히며 임의로 최근6시간이라고 붙이지 않습니다. TikTok Top Ads의7/30일 집계기간과 게시시각, Meta 광고시작일과 릴스게시일, 검색국가와 실제자료국가는 별개입니다. 최근 신호와 오래된 참고를 구분하고 실제 사용한 필터/읽기범위/확인시각/미확인을 whyNow와 limitations에 씁니다.
추가 회차는 새 원문을 다시 확인하고 기존 가이드의 실제장면·준비물·제작순서·브랜드 차이·어필을 개선하는 것이 우선입니다. 이전 수치를 재확인하지 않고 checkedAt만 새로 찍거나 같은 제작순서를 복사하지 않습니다. 전체 풀을 읽을 수 없으면 신규 판정 한계를 남기며 서버가 회사 전체 신규10/day와 canonical중복/갱신을 판정합니다. 계정별 한도/실행지연/확인대기로 부족하면 실제수와 다음회차를 알리고 다른계정의 결과나 기간을 새관찰처럼 바꾸지 않습니다.

1. 신규 10개를 고르는 과정
먼저 최근 공개 사례를 넓게 탐색하고 적용성이 높은 후보 18~24개를 자세히 확인한 뒤 최종 신규 제작 가이드 10개를 목표로 선별합니다. 충분한 후보가 없으면 실제 확인 수만 기록합니다.
YouTube 개별 최근/관련 영상, TikTok Creative Center Top Ads의 개별 광고, Facebook·Instagram의 실제 공개 릴스와 Meta 개별 광고를 시도합니다. Studio 검색 수요·계정 인사이트·공식 Best Practices 글은 이번 JSON에서 제외하고 채팅의 보조 참고로만 설명합니다. 기존 워크스페이스의 해당 자료를 삭제하거나 고치지 않습니다. 검색 결과 제목·썸네일·수치만 본 구체 콘텐츠도 준비된 제작 가이드 10개를 채우는 항목으로 쓰지 않습니다.
원본 영상/릴스를 실제 재생한 video-watched를 우선합니다. 광고 상세의 실제 카피·장면 자료를 충분히 읽은 page-read도 가능하지만 영상·음성을 보지 못했다면 컷·대사·타이밍을 봤다고 만들지 않습니다. 제작 구조를 확인할 수 없으면 준비 가이드에서 제외합니다.
최근6시간의 신호, 최근24시간 변화, 최근7일 반복 패턴, 오래된 비교 맥락을 구분합니다. 오래된 사례가 필요하면 오래된 참고라고 밝히고 오늘의 새 유행으로 포장하지 않습니다. 한국을 중심으로 미국·중국·몽골 등 실제 대상에게 적용할 공개 사례를 비교하되 검색 국가와 실제 자료 국가를 구분하며 실제 국가 미확인은 GLOBAL입니다. 나라·플랫폼·브랜드 할당량 때문에 부실한 항목을 넣지 않습니다.
같은 영상의 watch/shorts/youtu.be 주소, 같은 광고의 국가 필터, 같은 원문을 다른 플랫폼으로 다시 붙인 것은 신규 여러 개로 세지 않습니다. 지정 Doc의 이전 완료 본문과 이 Spark 작업의 과거 완료 결과를 실제 읽을 수 있을 때만 신규/재관찰을 비교합니다. 회사 전체 풀의 이력을 확인할 수 없으면 그 신규 판정의 한계를 밝힙니다. 서버의 실제 신규/갱신 판정과 오늘 신규 10개 상한을 대신 확정하지 않습니다.
최종 JSON은 기본적으로 선별한 제작 가이드 10개 이하를 담습니다. 업데이트가 필요한 기존 자료도 담을 수 있지만 전체 entries는 최대 30개이며 업데이트를 신규 10개로 세지 않습니다. 품질이 되는 가이드가 6개면 6개를 제출하고 빠진 플랫폼·접근 실패·제외 이유를 채팅에 씁니다. 같은 원본을 바꾸거나 근거를 지어내 10개를 채우지 않습니다.

2. 원본에서 확인할 제작 메커니즘
각 항목의 summary와 observedFacts에 실제 확인한 도입, 정보 공개 순서, 기대/반전/발견/참여가 생기는 지점, 마무리와 공개 반응을 기록합니다. 정확한 URL·확인 시각·제공된 게시 시각을 붙입니다.
“첫 0초에 완성 화면을 먼저 보여 준다”, “조건 세 개를 바꾼 뒤 같은 입력의 결과를 비교한다”처럼 관찰 가능한 구조를 적고 “유익하고 재미있다”, “조회수가 잘 나왔다” 같은 말만 반복하지 않습니다. 원본의 사실/연출 관찰과 작동 이유에 대한 해석, 우리 제작 제안은 문장 안에서 구분합니다.
공개 조회수·좋아요는 그 시각의 관찰값입니다. 시청 유지율·실제 CTR·전환율·노출 원인·전체 플랫폼 순위·하루 증가량은 실제 자료가 없으면 만들지 않습니다. Meta 일반 광고에는 성과 수치를 넣지 않고 TikTok CTR Top은 상대 위치로만 기록합니다. 축약 수치만 보이면 exact 정수를 만들지 말고 metrics는 null, 화면의 축약 표시는 observedFacts에 씁니다.

3. 직원이 따라 할 수 있는 항목별 제작 가이드
최종 신규 항목에는 research.productionGuide와 applications를 반드시 넣습니다. productionGuide는 저장 계약상 예전 자료와 호환되는 선택 필드지만 오늘 준비된 가이드에는 완성된 값이 있어야 합니다. status:ready, sourceMechanism 같은 새 키는 만들지 않습니다.
formatName: 직원이 형식을 바로 구분할 이름. “짧은 영상”이 아니라 해당 원문의 제작 방식이 드러나는 이름을 씁니다.
requiredAssets: 실제 필요한 화면/자료/촬영 장면/출연 동의/기존 브랜드 자산을 1~12개 적습니다. 원문 영상·음악을 가져다 써도 된다고 가정하지 말고 구조를 참고해 우리 실제 자료로 재촬영할 준비물을 적습니다. 없는 고객 사례·학습자 성과·목소리·툴 결과를 준비됐다고 쓰지 않습니다.
