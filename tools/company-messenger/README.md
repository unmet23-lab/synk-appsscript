회사 현황판과 통합해 사용하는 경우 [워크스페이스 안내](../../docs/마케팅/온라인마케팅지도/engagement/company/WORKSPACE.md)를 참고하세요. 기존 바로가기는 공통 프로그램으로 연결되며 로그인과 직원 관리는 한곳에서 처리합니다. 아래의 독립 실행 설정·초대 코드는 통합 설정이 없는 개발·시험 환경용입니다.

## 직원 음성 통화 백엔드 · 2026-10-17 로컬

기존 개인·팀·프로젝트 대화방에 음성 통화를 연결할 백엔드를 추가했다. 회사 로그인·현재 대화방 권한과 참가/나가기 기반에 실제 미디어 상태 조회·서명 웹훅 대조·같은 참가의 재접속, 방별 입장/발언/관리 정책, UTC 월 사용량 추정·한도를 추가했다. 2차로 동료 초대·수락/거절/취소/45초 만료, 개인 통화 알림·무음·기간 지정 방해 금지와 재호출 제한을 기존 개인 알림함/선택형 푸시에 연결했다. 초대는 현재 통화 참여자가 보내며 상대의 수락 없이 자동 참가하지 않는다. 3차로 전체 화면 공유1명·화면 소리 별도 허용/철회와 E2EE 필수 준비·RAM 키 관리·참가자 변경 시 키 교체를 추가했다. 키는 SYNK 서버가 관리하며 SDK Room/worker를 새로 준비하는 동안 통화가 잠시 중단될 수 있다. 실제 암호화 미디어를 검증한 상태는 아니다. 기본 전체 동시4명·계정당 참가1건·1회 최대2시간, 월1000참가자분·1GB 추정 다운스트림이다. 자리 예약·관측된 미디어 상태·미확인 시간·공급자 청구를 구분한다. 운영 기능은 기본 꺼짐이며 운영 배포는 하지 않았다. 별도 테스트 프로젝트·HTTPS 연결과 실제 관측은 아래에 구분했다.

화면·SDK 연결은 Claude가 추가했고 한 PC의 두 브라우저 세션으로 실제 Cloud 미디어를 확인한 기록이 있다. 서로 다른 두 실제 기기 검증은 남았다. 연결할 API·서버 설정·철회 경계는 [API 계약](API.md#직원-음성-통화-백엔드--2026-10-17-로컬), 관측 범위와 한계는 [검증 기록](QA.md#통화화면-공유-화면과-sdk-연결--2026-10-17)에 있다.

통화·화면 공유의 격리 시험 실행과 계정/방·23개 시나리오는 [검증 환경 준비](QA.md#실제-통화화면-공유-검증-환경-준비)를 따른다. `node tools/company-messenger/qa/voice-fixture.mjs --check`는 저장소 루트에서 실행하는 외부 미디어 없는 제어 검사다.

테스트 키와 ngrok HTTPS 연결을 묶는 [통합 실행 준비](QA.md#voice-live-https-setup)는 `qa/voice-live.mjs`를 사용한다. 자격증명은 저장소 밖의 시험 파일에서만 읽는다. 10-17 토큰 교체·Cloud 읽기 인증·공개 HTTPS 실행 후 Chrome 로그인과 메신저 직접 주소의 실시간 메시지 수신을 확인했다. 웹훅은 저장/공급자 시험 전송까지 확인했으며 수신 상태·두 기기 미디어는 남았다. 워크스페이스 iframe이 현재 HTTPS Chrome에서 빈 화면으로 남는 관측과 직접 주소의 접속 순서는 위 절에 기록했다. 회사 통합/격리/HTTPS 회귀30/30.

## 현재 운영 · 2026-10-09

실사용 직원 메신저는 [회사 워크스페이스](https://workspace.synk.im/?tab=messenger)에서 엽니다. 회사 서버의 SYNK ID 연결과 직원의 서버 재시작 후 로그인 유지는 공개 반영·실계정 확인을 마쳤습니다. 설치형 앱과 고객 상담은 각 담당 안내를 따르며, 실제 휴대폰 푸시 수신 시험은 보류 중입니다. 최신 반영 범위와 증거는 [검증 기록](QA.md)·[인증 안내](../../docs/마케팅/온라인마케팅지도/engagement/company/SYNK_ID.md)를 확인하세요. 아래 로컬 실행 절차는 독립 개발·시험 환경용입니다.

1. 공개 워크스페이스에 로그인하고 **메신저**를 엽니다. SYNK ID는 연결된 활성 직원 계정으로만 들어갈 수 있습니다.
2. **개인채팅 / 팀채팅 / 전체채팅**에서 대화를 고릅니다. 개인 메모와 파일은 **나에게**에 보관합니다.
3. **내 업무**에서 알림·할 일·저장한 메시지를 확인합니다. 메시지 메뉴에서 담당자와 기한을 정해 할 일로 연결할 수 있습니다.
4. 연결이 끊겼다면 아래 [전송 복구 안내](#전송이-끊겼을-때)를 따릅니다. 휴대폰 알림은 **알림 → 이 기기의 알림 설정**에서 각 기기로 직접 켭니다.

### 오늘 할 일의 게시 진행 연결 · 2026-10-11 로컬 미리보기

회사에 연결된 **내 업무 → 오늘 할 일**에서 본인 소유·담당 제작 건의 완성본 확인과 형식별 게시 주소 기록, 본인 담당 채널의 24·72시간 성과 보완을 함께 표시합니다. **게시의 다음 할 일**에서 원본으로 이동해 처리하면 목록도 바뀝니다. 별도 메신저 할 일을 생성하지 않고 현재 원본 상태와 권한을 조회하므로, 같은 버전·형식의 게시 묶음을 다시 만들어도 중복 집계하지 않습니다. 확인 시각 전·수집 중지한 게시물은 성과 보완 대상에서 제외하며 기록한 **0**은 완료입니다. 조회 실패는 ‘없음’ 대신 **확인 필요**로 표시합니다.

오늘 할 일 화면이 보일 때 **10초 간격**으로 동기화하며 변경이 없으면 화면과 스크롤을 유지합니다. 개인 메시지 초안은 보존하고 업무 입력·선택·열린 창 확인 중에는 배경 갱신을 미룹니다. 독립 메신저에는 회사 게시 API를 연결하지 않습니다. 현재는 [로컬 작업실 미리보기](../../docs/마케팅/온라인마케팅지도/engagement/company/WORKSPACE.md#게시-진행--오늘-할-일--2026-10-11-로컬) 범위이며 운영 반영·게시 업무 푸시 알림은 아직 없습니다.

## SYNK 플랫폼 연결

SYNK 플랫폼은 설치형 런처이고 **SYNK 사내 메신저 / SYNK WORLD**는 각각 별도로 설치·실행·업데이트하는 클라이언트입니다. 공개 회사 워크스페이스는 브라우저에서도 사용할 수 있습니다. 메신저 이름 **SYNK WORK**는 제안이며 아직 확정하지 않았습니다. 로컬 개발용 회사 입구 `http://127.0.0.1:4191/?tab=messenger`와 독립 메신저4197은 공개 서버와 별도 환경입니다.

회사 공통 상단의 **플랫폼**, 독립 메신저의 **SYNK 플랫폼**으로 웹 미리보기를 엽니다. 서버 환경변수 `SYNK_PLATFORM_URL`로 전체 HTTPS 주소를 지정합니다. 검색 값·해시·사용자정보가 있는 주소는 거부하며 토큰을 URL로 전달하지 않습니다. loopback 회사 origin에서만 기본값 `http://127.0.0.1:4280/synk-account/platform.html`을 제공합니다. 외부 운영 origin에서 미설정이면 링크가 나타나지 않으며, 빈 값은 로컬에서도 링크를 숨깁니다.

회사 계정은 `synk_company_session`과 활성 회사 크루 권한을 검사합니다. 기존 회사 계정에서 현재 비밀번호와 SYNK ID를 직접 확인해 연결합니다. **공개 서버의 인증 제공자·콜백 설정과 실계정 연결, 서버 재시작 뒤 기존 로그인 유지를 확인했습니다.** 플랫폼 링크는 회사 접근 권한을 주지 않으며, 학원 교사·학생·같은 이메일을 직원으로 자동 연결하지 않습니다. 브라우저·모바일은 서버 PKCE, 데스크톱은 main 프로세스 인증을 같은 회사 세션 계약에 연결합니다. [구현·설정 안내](../../docs/마케팅/온라인마케팅지도/engagement/company/SYNK_ID.md)를 참고하세요.

독립 개발·시험 환경에서는 채팅 화면과 API 서버, 계정, SQLite 데이터베이스를 이 PC에서 실행하고 새 첨부파일은 선택한 저장소에 보관합니다. 공개 회사 서버의 자료는 서버에서 관리합니다. 로컬 앱 실행에는 새 유료 서비스 가입이나 npm 설치가 필요 없으며 Node.js 24 이상이 필요합니다.

## 독립 개발·시험 환경 열기

1. 이 폴더의 `start.cmd`를 더블클릭한다. 브라우저가 `http://127.0.0.1:4197`을 연다.
2. 처음 한 번 회사 이름과 관리자 이름·아이디·비밀번호를 직접 정한다. 기본 계정과 비밀번호는 없다.
3. **전체채팅 → 수다방**에서 메시지를 보내거나 **나에게**에 파일과 메모를 모은다.
4. 종료할 때는 `stop.cmd`를 실행한다. 브라우저만 닫으면 서버는 계속 실행된다.

PowerShell이나 터미널에서도 실행할 수 있다.

```powershell
cd C:\Users\q1212\Documents\SYNK-appsscript\tools\company-messenger
node server.mjs
```

터미널 실행은 Ctrl+C로 종료한다. 포트는 `MESSENGER_PORT`, 데이터 폴더는 `MESSENGER_DATA_DIR` 환경변수로 바꿀 수 있다. Windows 런처는 프로젝트의 `data/`를 사용한다.

## 전송이 끊겼을 때

메시지 전송 도중 연결이 끊기면 입력창 위에서 **전송 확인**, **같은 내용 다시 보내기**, **전송 취소**를 선택합니다. 이미 저장된 메시지는 다시 만들지 않습니다. 확인하는 사이에 고친 초안·답글·멘션은 보존하며, 앞선 전송을 해결한 뒤 새 메시지를 보낼 수 있습니다. 재접속하거나 새로고침했다고 자동으로 보내지는 않습니다.

첨부파일 업로드가 실패하면 파일 옆의 **다시 시도**를 누릅니다. 같은 창에서는 원래 고른 파일로 다시 시도하고, 서버가 이미 저장했다면 그 파일을 찾아 이어갑니다. 새로고침으로 원본 파일이 사라진 경우에는 **업로드 확인**으로 저장 결과를 먼저 확인하고, 저장되지 않았다면 파일을 다시 선택합니다. 취소 결과를 받지 못하면 **취소 확인**으로 마무리할 수 있습니다.

느린 연결에서도 전송량이 계속 늘면 브라우저가 2분 만에 업로드를 끊지 않습니다. 2분 동안 전송 진전이 없거나 본문 전송 뒤 5분 동안 저장 결과를 받지 못하면 복구 버튼을 표시합니다. 서버의 기존 요청 제한은 유지됩니다.

서버가 파일을 저장하던 중 종료돼 결과가 불명확하면, 중복 파일을 만들지 않도록 재업로드를 보류합니다. 파일을 취소하면 뒤늦게 저장되는 것도 막고 첨부 칸에서 제거합니다. 이때 Drive의 남은 임시 파일 정리는 서버의 대기 기록으로 따로 이어지므로 원격 파일이 즉시 모두 지워졌다는 뜻은 아닙니다. 다른 탭에서 이미 전송한 첨부는 대화에 남기고 현재 입력창의 중복 첨부만 정리합니다. 실제 공개 반영 여부는 [최신 검증 기록](QA.md)을 따릅니다.

## 사용할 수 있는 기능

2026-09-27 화면 개편은 홈페이지 시안의 ‘싱ㅋ’ 워드마크와 Recent에서 확인한 UI 사례를 바탕으로 한다. 로그인·채널·파일·검색·설정을 같은 타이포그래피와 조작 규칙으로 정리했다. 원본 자산과 참고 근거는 [DESIGN.md](DESIGN.md)에 있다.

- 공개 채널 만들기, 개인 메모, 멤버별 1:1 대화
- 실시간 메시지 수신, 재연결 시 최신 대화 갱신, 읽지 않은 대화 표시
- 메시지 수정·삭제, 이모지 반응, 이전 대화 불러오기, 대화 검색
- 파일 선택/끌어놓기, 업로드 진행률, 파일 목록과 원본 다운로드
- 관리자 초대 코드 발급·취소, 초대 코드로 회원 가입, 로그인·로그아웃
- 계정별 채널 작성 초안과 미전송 첨부 복구, 모바일 화면과 키보드 조작
- Google Drive 파일 저장, 계정 용량·연결 상태 확인, 등록된 저장 계정 전환

파일은 종류에 관계없이 건당 최대 **100MiB**, 메시지당 최대 5개다. HTML 등의 첨부파일도 브라우저에서 실행하지 않고 다운로드한다. 업로드할 때 PC 디스크에 잠시 저장한 뒤 Drive 업로드와 원본 검증을 끝내면 임시 파일을 지운다. Drive 연결이나 용량에 문제가 있으면 오류를 표시하며, 몰래 로컬 저장으로 바꾸지 않는다.

자동삭제는 없다. 메시지 삭제나 미전송 첨부 취소 시 로컬 파일은 디스크에서 지우고, Drive 파일은 메신저가 만든 해당 파일만 휴지통으로 옮긴다. **Drive 휴지통의 파일도 계정 용량을 차지한다.** Drive 정리에 실패하면 삭제 요청을 DB에 보관해 재시도하고, 설정 화면에 대기 건수를 표시한다.

독립 환경의 초대 코드는 7일 동안 한 번 사용할 수 있습니다. 기본 로컬 서버는 이 PC의 loopback 주소에서 접속하며, 다른 브라우저 프로필이나 시크릿 창에서 가입과 계정 간 대화를 시험할 수 있습니다. 다른 기기에서 실사용할 때는 위 공개 워크스페이스 주소를 엽니다. `127.0.0.1`은 각 기기 자신을 가리키므로 다른 PC에 공유하는 접속 주소로 사용하지 않습니다.

## 독립 환경에서 Google Drive 연결

2026-09-27에 **unmet23@gmail.com** 계정의 **5TB(5,497,558,138,880바이트)** 한도를 실제로 확인하고 연결했다. 파일은 [메신저 전용 비공개 폴더](https://drive.google.com/drive/folders/1t9EzZO-JJLTDkOamtKhd0xUbvHqUEraL)에 저장한다. 설정 화면의 용량은 Google 계정 전체의 공유 저장 공간이며, 메신저만을 위해 예약된 용량은 아니다. 폴더나 첨부파일을 공개 공유하지 않는다.

다른 계정을 추가할 때는 그 계정으로 발급·승인받은 OAuth 인증 JSON을 별도로 준비하고 다음 CLI로 등록한다. `client_id`, `client_secret`, `refresh_token`이 있는 `authorized_user` 또는 clasp의 `tokens.default` 형식을 지원한다. 브라우저에는 인증 파일을 올리는 기능이 없다.

```powershell
node connect-drive.mjs --credentials "C:\private\new-google-credentials.json" --email "new-account@example.com"
node connect-drive.mjs --status
```

첫 명령은 계정 확인 후 연결을 등록·활성화한다. 이후 관리자 설정 화면에서 등록된 계정을 선택하거나 로컬 저장으로 전환할 수 있다. **전환 이후 시작한 새 업로드만** 선택한 저장소를 사용한다. 기존 첨부파일은 원래 계정과 연결을 계속 사용하며 자동 이관하지 않는다. 기존 로컬 파일도 그대로 열 수 있다. 같은 이메일이라도 OAuth 클라이언트가 다르면 별도 연결로 보관해 이전 파일의 접근 정보를 유지한다.

## 독립 환경의 데이터와 백업

공개 회사 서버의 백업·자료 보존·복구는 [운영 안내](../../docs/마케팅/온라인마케팅지도/engagement/company/CLOUD-OPERATIONS.md)를 따릅니다. 아래 `data/`와 `stop.cmd` 절차는 이 PC에서 별도로 실행한 독립 환경에 적용합니다.

`data/`에는 계정·대화·파일 연결 정보가 담긴 SQLite DB, 기존 로컬 첨부파일, Google 연결 정보가 저장된다. 이 폴더는 Git에서 제외한다. `data/drive-storage.json`에는 OAuth 비밀 정보가 있으므로 DB와 백업을 개인적으로 안전하게 보관하고 공유하거나 커밋하지 않는다.

백업할 때는 `stop.cmd`로 서버를 멈춘 다음 **data 폴더 전체**를 안전한 별도 위치에 복사한다. 복원은 서버가 멈춘 상태에서 그 폴더를 되돌린다. 서버가 쓰고 있는 DB 파일 하나만 복사하지 않는다. **Drive에 저장된 파일 본문은 이 백업에 포함되지 않는다.** 원격 파일과 해당 Google 계정 접근 권한을 별도로 유지해야 하며, 소스 코드 커밋도 사용 데이터 백업을 대신하지 않는다.

독립 환경의 계정 비밀번호는 scrypt 해시로 저장하지만, 대화·로컬 파일·Drive 연결 파일은 앱에서 디스크 암호화를 하지 않습니다. 이 PC의 로그인 계정과 백업 보관 권한을 기준으로 보호됩니다. 독립 환경에는 비밀번호 찾기 메일이나 자동 복구 기능이 없으므로 처음 정한 관리자 아이디·비밀번호를 보관합니다. 공개 원격 접속과 선택형 기기 알림은 회사 서버 안내를 따르며, 파일 자동 만료 정책은 제공하지 않습니다.

## 구성과 검증

- `server.mjs`: Node 내장 HTTP, SQLite, scrypt 인증, 세션 쿠키, SSE, 파일 스트리밍
- `drive-storage.mjs`, `connect-drive.mjs`: Google Drive 저장·원본 검증·계정 연결과 전환
- `public/`: 외부 CDN 없이 동작하는 화면·서체·승인 로고
- `tests/`: 실제 HTTP 요청과 임시 데이터베이스를 쓰는 통합 검사
- `API.md`, `DRIVE.md`: 프론트·백엔드 및 Drive 저장소의 공통 계약

```powershell
npm test
```

검증 결과는 [QA.md](QA.md)에 있다. 브라우저 검사는 `node qa/ui-smoke.mjs`로 실행한다. 이 검사는 설치된 Chrome과 개발 도구인 Playwright가 필요하다. Codex 번들 경로를 기본으로 찾고, 다른 환경에서는 `MESSENGER_PLAYWRIGHT`에 Playwright 패키지 경로, `MESSENGER_CHROME`에 브라우저 실행 파일 경로를 지정한다. 앱 자체 실행에는 이 도구가 필요 없다. 브라우저 검사는 임시 데이터만 사용하고 `qa-output/`에 화면을 남긴다.

비밀번호·초대 코드 원문을 DB에 저장하지 않는다. 현재 통합 회사 세션과 SYNK ID 확인 쿠키는 HttpOnly/SameSite=Lax이며 HTTPS에서 Secure를 붙인다. 기존 독립4197 메신저 세션은 HttpOnly/SameSite=Strict를 유지한다. 회사 API는 Origin과 CSRF, SYNK ID 로그인은 추가로 브라우저에 묶인 일회용 확인을 검사한다. 로그인·채널 멤버십을 확인하고 임의 Host를 거부하며 개인 대화/메모의 파일과 검색 결과도 참여자에게만 보인다. 공통 로그인 계약은 [SYNK ID 안내](../../docs/마케팅/온라인마케팅지도/engagement/company/SYNK_ID.md), 현재 확인 범위는 [2026-10-02 검증 기록](QA.md#synk-id와-모바일-입구--2026-10-02)에 있다.

공개 회사 워크스페이스는 HTTPS 서버에서 운영하며, 배포·백업·복구 확인 범위와 남은 일은 [운영 안내](../../docs/마케팅/온라인마케팅지도/engagement/company/CLOUD-OPERATIONS.md)를 따릅니다. 실제 휴대폰 알림 수신은 아직 시험하지 않았으며, 직원 수를 늘릴 때는 동시 접속 부하와 접근 권한·퇴사자 처리를 확인합니다. 독립 로컬 앱 실행에는 별도 메신저 서비스 가입비가 없지만, 공개 서버 운영비와 기존 Google 구독료·저장 공간 비용은 별도입니다.
