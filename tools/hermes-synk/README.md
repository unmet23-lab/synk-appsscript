# 휴대폰 SYNK 작업 연결

기존 Hermes 텔레그램 팁 봇을 유지하면서 **자료 → 적용, 요청 → 완료, 오늘 확인** 세 흐름으로 연결한다. 역할·비용·배포·게시 권한은 [AI 운영 원칙](../../docs/AI_운영원칙.md), 팁의 원래 절차는 [참고 카드](../../docs/참고카드/README.md)를 따른다. 상태 조회와 결과 전달에는 별도 AI 요약을 붙이지 않는다.

## 사용

등록된 사용자와 봇의 텔레그램 개인 대화에서 요청한다.

- `SYNK 오늘 확인할 것 알려줘`
- `백엔드 상태 알려줘`
- `클로드한테 WORLD 첫 화면의 다음 개선점을 검토해 달라고 해줘`
- `코덱스한테 백엔드 관련 시험 실패 원인을 확인해 달라고 해줘`
- `팁 장부 7행 적용해줘`
- `맡긴 작업 결과 알려줘`

자연어 요청은 기존 접수 Claude가 구분한다. 코드 작업은 문서 지도·파일 목록에서 대상 경로를 확인한 뒤 필요한 저장소 상대 경로를 `scope`로 전달한다. 사용자가 경로를 직접 외울 필요는 없다. 필요한 범위가 확인되지 않으면 파일이 없는 상태로 작업을 완료했다고 하지 않는다.

직접 명령은 접수 모델을 호출하지 않는다.

| 명령 | 동작 |
|---|---|
| `/synk` | 사용법 |
| `/synk_today` | 팁·맡긴 일·판단 대기·명시한 기한·기존 조사 결과를 함께 조회 |
| `/synk_attention` | 지금 판단이 필요한 일만 보여 준다. 감시가 잡은 사건은 알림 번호와 함께 보인다. 7일 안의 이어 가기 대기와 작업 판단 대기, 실행 상태가 미확인인 작업도 보인다. 오래된 시작 실패와 기한이 지난 기록은 건수로만 알린다. |
| `/synk_attention <알림 번호>` | 그 감시 알림에 묶인 사건마다 지금 상태와 다음에 볼 곳을 보여 준다. 알림에 「자세히」나 「진단해줘」라고 답장해도 같다. |
| `/synk 팁 [접수ID]` | 모델 없이 이 대화의 팁 접수를 보여 준다. 목록은 「접수 당시 기록」과 「지금 조회한 결과」를 나눠 보인다. 접수 당시 기록은 접수하거나 「팁 확인」을 했을 때 저장한 대조이고, 지금 조회한 결과는 장부 사본과 카드 원문을 방금 읽은 것이다. 접수 ID를 붙이면 접수, 장부 행, 참고 카드, 적용 기록, 배포와 효과 검증을 단계별로 보인다. 배포와 효과 검증은 기록을 모으지 않아 「없음」으로 보인다. |
| `/synk 팁 확인 <접수ID>` | 기존 장부를 읽어 해당 접수와 대조. 장부 쓰기·모델 호출 없음 |
| `/synk_status 백엔드` | 트랙·카드 기록과 실행 메타데이터 조회 |
| `/synk_claude <요청>` | 새 공식 Claude Code CLI 세션에 요청 |
| `/synk_codex <요청>` | 새 공식 Codex CLI 세션에 요청 |
| `/synk_tasks [작업ID]` | 이 연결에서 맡긴 작업의 실행 상태 |
| `/synk_release <작업ID> 종료확인` | PC에서 종료를 확인한 미확인 작업의 접수 잠금 정리 |
| `/synk_recover` | 미전달 결과의 확인·전달 재개. 작업을 새로 실행하지 않음 |

직접 코드 작업을 맡길 때는 다음 형식으로 범위를 지정할 수 있다. 공백이 있는 경로는 따옴표로 감싼다.

```text
/synk_claude --scope 상대/파일.md 상대/폴더 -- 요청
/synk_codex --scope 상대/파일.js 상대/시험.test.js -- 요청
```

명시한 상대 파일명도 범위로 인식한다. 범위를 생략한 직접 명령은 기본 문서 조회 범위만 준비하므로 코드 작업은 자연어로 맡겨 경로를 구체화하거나 `--scope`를 사용한다. 누락된 코드·검사·의존성이 있으면 범위를 임의로 넓히지 않고 필요한 경로를 알린다.

## 자료 → 적용

2026-10-28 접수·처리 상태 연결: 등록된 사용자의 텔레그램 개인 공유는 모델 호출 전에 `%LOCALAPPDATA%/hermes/runtime/synk-tip-intake/`에 최소 접수 영수증을 남긴다. 원문 대화는 Hermes 기존 저장을 사용하며, 영수증은 메시지 식별 해시와 안전한 공개 참조만 보존한다. 접수됨은 장부 등록·적용안 작성·실제 적용 완료를 뜻하지 않는다. 같은 메시지의 재전달은 중복 접수하지 않으며 승인 답·명령·다른 채널은 접수 대상에서 제외한다.

11-14부터 인스타그램 게시물은 주소 경로 `/p|reel|tv/<ID>/`의 ID로 식별한다. 공유하거나 추적할 때 붙는 꼬리표는 게시물을 바꾸지 않는다. 11-14에 실제로 본 꼬리표는 `cplk`, `exln`, `mdxt`, `rpxt`, `srtk`, `vrfl`, `obrf`, `psln`이다. 이런 꼬리표는 이름만 `ignoredQueryKeys`에 남기고 값은 저장하지 않는다. 개인 키처럼 보이는 꼬리표가 있으면 지금처럼 참조 전체를 버린다. 판정 정규식 `PRIVATE_QUERY`는 Python과 JS가 같다. 그래서 `design`이나 `monkey` 같은 낱말은 통과하고, `key`, `sig`, `api_key`, `token`, `secret`, `x-amz-*`는 거절한다. `l.instagram.com` 같은 넘겨주기 주소는 게시물로 식별하지 않는다. `plugin/tip_intake.py`와 `tip-intake-status.cjs`가 같은 규칙을 쓰고, `tests/fixtures/hermes-tip-url-cases.json`이 두 쪽을 함께 시험한다. 영수증 형식 번호는 1 그대로다. 그 전에 받은 접수는 다시 쓰지 않는다. 저장된 주소가 게시물 경로 꼴이면 읽을 때만 「복원 후보」로 장부와 카드에 잇는다. 감시 사건 판정과 `/synk 팁 확인`은 접수할 때 확정한 식별만 쓴다.

`/synk 팁 <ID>`는 `tip-trace.cjs`로 단계를 하나씩 따로 보인다. 장부 행은 마지막으로 조회한 사본의 최근 50행에서 찾는다. 50행이 다 차 있으면 「더 오래된 행에 있을 수 있다」고 적는다. 참고 카드는 카드의 `게시물ID`로 찾고, 적용 기록은 카드의 `상태`를 읽는다. 배포와 사용자 효과는 검증 기록을 모으지 않으므로 늘 「검증 기록 없음」이다. 장부에 같은 게시물이 여러 행 있거나, 같은 게시물의 카드가 여러 장이거나, 카드에 적힌 장부 행이나 상태가 장부와 다르면 「확인 필요」로만 적고 고치지 않는다. 맡긴 작업과의 연결은 명시 기록이 없어 「없음」으로 둔다. `/synk_today`는 접수 당시 기록의 건수와 지금 다시 읽은 단계별 건수를 서로 다른 줄로 보인다. 목록이 접수 파일 100개 상한을 넘으면 그 사실과 확인하지 않은 건수를 적는다.

장부의 정확한 공개 참조가 한 행으로 확인된 경우에만 장부 연결을 표시한다. 부분 일치·중복 후보·오래된 캐시·읽기 실패는 완료로 처리하지 않는다. 상태 조회와 장부 대조는 모델·장부 쓰기·새 예약 없이 기존 읽기 경로를 사용한다. 이전 대화를 일괄 복사하거나 과거 공유를 모두 복구했다고 보고하지 않는다.

접수 파일 2,000개 상한에 도달하면 기존 감시에 새 접수 저장 중단을 한 번 표시한다. 반복 조회는 다시 알리지 않고, 실제로 상한 아래임이 확인돼야 해소한다. 오래된 영수증을 자동 삭제하지 않는다. 일반 목록은 최근 100건을 조회해 10건까지 보여 주며, ID를 지정하면 해당 영수증을 직접 읽고 대화 소유자를 확인한다.

`/synk_today`는 팁 적용안 처리기의 마지막 확인과 구독 한도를 함께 읽는다. `할일없음`·`한도쉼`·`키없음`·`실패`·`끝`과 미확인·오래됨을 구분하며, 성공한 크레딧 실행을 남아 있는 구독 한도 파일로 가리지 않는다. `크레딧실행.js`는 사전 확인·사후 처리 예외까지 최신 상태를 원자적으로 교체하고, 오류 원문·키·모델 응답은 이 상태에 싣지 않는다.

11-01 보안 후속: 승인 안내를 복사해 답하면 원문이 하나만 일치하는 안내를 먼저 고른다. 정규화한 문장도 하나일 때만 쓰고, 여러 안내가 겹치면 해당 안내에 직접 답장하도록 요청한다. 작업 결과와 크레딧 실행 알림은 첨부 표식을 공백으로 바꾼 뒤 미디어 지시를 중화해 글로만 전달한다. 팁 적용안은 요청한 행과 게시물 ID가 함께 맞는 결과를 한 번만 처리하며, 장부 기록이 성공한 자료만 후처리한다. 크레딧 소진 전환은 실제 오류와 실패 종료, 명시된 첫 턴을 함께 확인한다.

상태 파일을 쓰지 못하면 고정 경고를 남기며, 이미 끝난 작업 결과나 원래 실패 알림을 바꾸지 않는다. 잠금은 프로세스 종료 시 운영체제가 해제하므로 중간 종료 뒤 같은 접수를 다시 확인할 수 있다.

기존 처리기가 직접 실패 알림을 시도한 상태와 과거의 알림 여부 미확인 상태는 새 감시가 다시 보내지 않는다. `directNotificationAttempted`는 도착 확인이 아니며, 명시적으로 직접 알림을 하지 않은 예외 실패만 기존 사건 중복 방지 흐름으로 알린다. 한도 대기와 정상 처리 상태는 조회로 보여 준다.

- 링크·사진·영상만 공유하면 기존 `synk-tip-review`가 받기·재료 정리·장부 기록을 맡는다. 공유한 자료를 실행 지시로 취급하지 않는다. Claude 적용안 검토는 10-21부터 정해진 시각(09:00·21:00) 대신 Windows 작업 스케줄러 「SYNK 팁 적용안」이 15분마다 AI 없이 장부를 보고 새 줄이 있을 때만 돌린다(`node tools/크레딧실행.js 작업 팁적용안`, [참고 카드](../../docs/참고카드/README.md)).
- 적용 상태는 `docs/참고카드/카드/*.md`의 원문을 우선한다. 장부의 수동 상태를 덮어쓰지 않는다. 10-18 감사에서는 장부 6행이 모두 `새로`였고 카드 2장은 `적용함`이었다. 개요는 이 불일치를 보여 주며 자동 수정하지 않는다. `적용함` 기록과 실제 배포·사용자 효과는 구분한다.
- Argon은 [기존 예약과 결과 문서](../argon-schedules/README.md)를 재사용한다. 개요 갱신은 기존 SSH 핀·인증으로 지정 서버의 `docs.json` 역할(10-25 일곱) 후처리 영수증과 systemd 상태만 읽는다. 새 조사·문서 쓰기·예약 실행·로그인·토큰 본문 조회는 하지 않는다. 서버의 완료 영수증 조회는 Docs 본문과 회사 가져오기의 현재 상태를 다시 검증한 결과가 아니다. 꺼 둔 역할(`configuration/paused.json`, 10-25 월요일 스캔 셋)은 「꺼 둠」으로 보이고 timer 상태로는 알리지 않는다 — 실패는 그대로 알린다.
- `overview.cjs` 기본 조회는 로컬 사본만 읽는다. `--refresh`에서 장부 `recent 50`과 Argon 역할을 읽기 전용으로 갱신한다. 마지막 성공 사본의 유효 기간은 6시간이며, 갱신 실패 시 기존 사본과 확인 시각을 보존하고 오래됨·미확인을 표시한다. 장부 50행 상한과 읽지 못한 범위를 전체 조회로 보고하지 않는다.
- `status.cjs`는 기존 운영 홈의 원문 parser·Claude 공식 조회를 재사용한다. 전체 변경 비교용 snapshot을 제공하며, Codex 운영 홈 사본이 없거나 오래되면 미확인으로 표시한다. 읽지 못한 기록이 사라졌다는 이유로 삭제·완료라고 판정하지 않는다. 개인 대화·세션·인증값은 개요에서 제외한다.

## 요청 → 완료

- 같은 수신 메시지는 중복 실행하지 않는다. 한 번에 하나의 휴대폰 작업을 시작하며, 진행 중이거나 실행 상태가 미확인인 일이 있으면 새 요청을 보류한다. 다른 앱의 작업을 강제로 잠그거나 종료하지 않는다.
- 대상은 기존 `SYNK-appsscript`, `SYNK-talk`, `SYNK-website` 중 요청한 저장소 하나다. 접수 시 지정 범위의 현재 수정본·삭제·안전한 미추적 소스를 담은 별도 detached sparse Git worktree를 만든다. 공식 CLI는 이 작업본에서 실행한다. 10-18 추가 승인 이후 새 요청에는 `auto_verified_v1`을 기록하고, 작업 종료 뒤 최신 원본과 합친 후보를 검증해 통과한 변경만 원본 작업 파일에 자동 반영한다. 기존 종료 작업에는 소급 적용하지 않는다. 원본 Git HEAD·인덱스·가지·설정은 보존한다.
- 11-14부터 기본 범위는 운영 원칙, 문서 지도, 트랙, 결정, 참고 카드, 현장 노트 **색인**(`docs/현장노트/README.md`)이다. 현장 노트 본문이 필요하면 `--scope`로 연다. 비밀 검사와 내장 미디어 검사는 그대로 둔다. 다만 `data:…;base64,` 뒤에 실제 base64가 16자 이상 이어질 때만 막는다. 설명 글이나 `${…}`로 조립하는 코드는 통과한다. 이 기준은 11-11에 고친 백업 검사기와 같다. 막히면 영수증(`request.json`의 `failure_path`, `failure_rule`)과 답장에 저장소 상대 경로와 규칙 이름만 싣는다. 파일 내용은 싣지 않는다. PC에서 미리 보려면 `node tools/hermes-synk/workspace.cjs inspect --repo <저장소> [--scope-json '["상대경로"]']`를 쓴다. 이 명령은 읽기만 한다.

## 자동 검증 선언

검사 선언은 `.synk-completion.json`의 `checks`에 `node_test`, `typescript`, `json_schema`, `python_unittest`, `python_pytest`, `browser` 중 해당 항목을 적는다. TypeScript는 `path`에 tsconfig, `tests`에 emit된 `.js/.mjs/.cjs`를 상대 import하는 Node 시험을 적는다. JSON은 `path`·`schema`·`tests`가 필요하고 기존 데이터의 스키마를 함께 약화하면 보류한다. Python은 실제 unittest 또는 이미 설치된 pytest 환경이 있어야 한다. 새 패키지를 자동 설치하지 않는다.

`browser`는 `path`의 정적 HTML과 `steps`의 `assert_visible`, `assert_text`, `assert_style`, `assert_count`, `click`, `fill`만 실행한다. 1440×1000·390×844에서 각각 실제 Chrome을 사용하며 `viewport: desktop/mobile`로 반응형 기대값을 나눌 수 있다. CSS는 변경 선언마다 같은 selector/property의 단언과 해당 선언을 잠시 뺄 때의 계산 스타일 변화가 필요하다. 미사용 규칙·속성, 삭제·중복·shorthand·해석이 모호한 조건은 자동 통과하지 않는다. 외부 네트워크·다른 로컬 서버·로그인이 필요한 화면과 주관적 디자인 판단은 이 정적 검사 범위 밖이다.

TypeScript의 컴파일·실행 의존성은 링크 없이 필요한 패키지의 제한된 사본으로 만들며, 테스트 중 사본 변경도 실패로 처리한다. 복사 한도나 동적 의존성을 확정하지 못하면 `TYPESCRIPT_DEPENDENCY_ISOLATION_REQUIRED`로 보존한다. 타입 전용 변경·project references·미지원 schema·관찰할 수 없는 JSON 소비 방식 등도 검증 근거가 충분하지 않으면 보류한다. 기존 JSON 스키마 비교는 CRLF/LF만 같게 보고 내용·공백·제약 변경은 계속 보류한다. Chrome에는 경계·용량 검사를 통과한 후보 바이트를 Playwright 제어 통로로 공급하며 외부 통신 차단을 유지한다. 일반 수정·검사 오류는 공식 세션의 사전 검사에서 해결하고, 남은 판단·권한·검증 환경 문제가 있을 때만 텔레그램으로 알린다.

## 설치·확인

Hermes 홈은 `%LOCALAPPDATA%/hermes`다. 비밀값을 저장소로 복사하지 않는다. 아래 명령은 설치·검증 방법이며 실행 결과 자체를 대신하지 않는다.

```powershell
node tools/hermes-synk/install.cjs
node tools/hermes-synk/install.cjs --apply
# 기존 설정을 보존하고 플러그인 코드만 갱신하는 유지보수 배포
node tools/hermes-synk/install.cjs --plugin-only --apply
hermes plugins enable synk-work --no-allow-tool-override
hermes plugins doctor synk-work --ci
node tools/hermes-synk/status.cjs 백엔드
node tools/hermes-synk/overview.cjs
node tools/hermes-synk/overview.cjs --refresh --json

node tools/hermes-synk/install-automation.cjs
node tools/hermes-synk/install-automation.cjs --apply
# 처음 만드는 예약은 일시중지 상태다. 검증 뒤 같은 예약을 활성화한다.
node tools/hermes-synk/install-automation.cjs --apply --enable
```

기존 팁 파일 4개의 SHA-256을 대조하고 설정은 Hermes의 `backups/synk-work-*` 아래 보존한다. 자동 모델 대체는 비우며 기존 팁 수집·Claude 검토 예약·승인된 로그인은 유지한다. 같은 이름 예약을 중복 생성하지 않고, 소유·실행 계약이 다른 예약은 덮어쓰지 않는다.

```powershell
$synkTests = Get-ChildItem tests/hermes-synk-*.test.cjs | ForEach-Object { $_.FullName }
node --test $synkTests
python -X utf8 tests/hermes-synk-plugin.test.py
python -X utf8 tests/hermes-synk-delivery-hook.test.py
python -X utf8 tests/hermes-synk-automation.test.py
python -X utf8 tests/hermes-synk-tip-intake.test.py
```

11-14 변경만 확인할 때는 `node --test tests/hermes-synk-attention.test.cjs tests/hermes-synk-tip-trace.test.cjs tests/hermes-synk-workspace.test.cjs tests/hermes-synk-monitor.test.cjs tests/hermes-synk-overview.test.cjs tests/hermes-synk-status.test.cjs tests/hermes-synk-install-automation.test.cjs`를 돌린다. Python은 위의 플러그인 시험과 팁 접수 시험 두 개를 돌린다.

11-14 판은 다음 순서로 반영한다. 먼저 `install.cjs --plugin-only --apply`로 플러그인만 바꾼다. 이 명령은 설정과 인증을 보존한다. 다음으로 `install-automation.cjs --apply`로 감시 계약을 다시 잡는다. 이때 `monitor.cjs`와 새 `attention.cjs`, `tip-trace.cjs`의 지문이 갱신된다. 마지막으로 처리 중인 작업이 없을 때 아래 절차로 게이트웨이를 재시작한다.

확인은 텔레그램 개인 대화에서 한다. `/synk_attention`과 `/synk 팁 <접수ID>`를 보낸다. 작은 읽기 전용 작업으로 `/synk_codex 파일은 바꾸지 말고 docs/AI_운영원칙.md에서 GPT 담당만 한 줄로 알려줘.`도 보낸다. 이 작업은 `request.json`에서 준비가 성공하고, `native.exit`가 0이 되고, `native-result.json`과 `finalization.json`(`completed`, `no_changes`)이 생긴 뒤 `delivery.json`이 `suppressed_success`로 끝나야 한다. 조용한 성공이라 결과 알림은 오지 않는다. 결과는 `/synk_tasks <작업ID>`로 본다. 다음 감시 알림이 오면 끝의 번호 안내와 「자세히」 답장을 확인한다.

설정·플러그인 변경은 처리 중인 작업이 없을 때 공식 `hermes gateway restart`로 반영한다. 이때 `SYNK_Hermes_Gateway_Recovery`를 잠시 Disable한 뒤 반드시 다시 Enable한다. 공식 drain을 사용하며 프로세스를 강제로 죽이지 않는다. 실행 복구와 전원 설정은 [runtime/README.md](runtime/README.md)를 따른다.

현재 연결은 Hermes 0.22.2를 기준으로 하며 `gateway.session_context`의 두 accessor를 사용한다. 플러그인은 `<0.23.0`으로 제한한다. Hermes·Claude·Codex가 업데이트되면 소스 검사만 믿지 말고 공식 상태·관련 시험·실제 결과 전달을 다시 확인한다. core 재정의나 승인 우회 플래그를 사용하지 않는다.
