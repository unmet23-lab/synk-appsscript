# 교실 촬영·라이브·자동 복습 세팅

공간 배치와 카메라 위치의 현재 통합안은 [공간과 촬영 통합 설계](../../docs/오프라인_공간설계/평면도_20260929/공간과_촬영_통합설계.md)를 따른다. 강의실4곳에서 교재·전자판서는 디지털 원본으로 받고, 카메라는 교사 얼굴·상반신을 담는 구성이다. 실제 위치·연결·시청은 아직 검증하지 않았다.

2026-09-27 기준. 사용자 확인: **몽골 학원 설치, 반당 예산 약 200만원, 장비와 촬영 거리 미정, 원격 학생은 영상과 소리만 시청, 추가 유료 영상 서비스는 사용하지 않는다.** 아래는 장비 선정·설치 기준이다. 실제 장비 연결·4교실 송출 시험·앱 운영 배포는 아직 하지 않았다.

**2026-09-29 사용자 승인 방향:** 교재·전자판서의 디지털 원본을 메인으로, 교사 상반신을 작은 사각형 창으로 합성한다. 발음 설명 때는 교사를 크게, 글씨·도표를 자세히 볼 때는 판서를 전체 화면으로 전환한다. 아래는 이 방향을 반영한 설치 설계이며, 특정 TV·전자칠판·카메라 구매나 실제 OBS 설정 완료를 뜻하지 않는다.

**2026-10-09 보완·서버 반영:** 수업 전 설정·폴더·디스크 사전검사, 스트림 health 확인, 일시 장애 시 재생 차단과 복구, 녹화 완료 오류 격리, 종료된 복습 영상의 명시적 완본 교체와 지연 동기화 요청 순번 보호를 보완했다. 재생 차단·요청 순번 DB 조각과 수업 API는 리허설·운영에 반영하고 사후 검사까지 마쳤다. 반·이용권·전용 비밀 설정과 학생 앱/교실 프로그램의 현장 설치, OBS 실기기·학생 시청은 아직 남았다. 합성 API·Lua 시험을 실제 교실 운영의 증거로 대신하지 않는다. [배포·검증 기록](../../docs/_ops/qa/classroom-release-20261009/README.md)과 [어댑터 안내](README.md)를 따른다.

## 권장 구성

교실마다 교사용 카메라 1대, PC 1대, 교사용 무선 핀마이크 1세트, 유선 인터넷과 현장 학생이 볼 TV 또는 전자칠판을 둔다. **PC의 교재·판서 앱 화면과 교사 카메라를 OBS의 별도 소스로 합성**한다. OBS와 YouTube를 사용하며 Meet·Zoom은 이번 운영에 필요 없다. 앱의 `meeting_url`은 비워 둔다.

| 항목 | 교실 1개 기준 | 선택 기준 |
|---|---|---|
| 카메라 | 기존 스마트폰 또는 USB 카메라 1대 | 교사 얼굴·입 모양·상반신 촬영용. 기존 폰이 있으면 먼저 재사용 시험. 모두 새로 마련한다면 상시 전원·USB 연결이 간단한 고정 카메라를 우선 검토 |
| 송출 PC | 기존 PC/노트북 우선, 없으면 소형 PC 검토 | 유선 LAN, 카메라·마이크·필요 시 터치용 USB, 교실 화면과 운영 모니터 연결, H.264 하드웨어 인코더 지원. 메모리 16GB·SSD 1TB는 초기 기준이며 교재 앱·화면 캡처·카메라 합성·1080p 송출/녹화 동시 부하 시험으로 결정 |
| 교실 화면·필기 입력 | TV + PC 입력 도구 또는 전자칠판 + PC 판서 앱 | 화면 크기·뒷자리 가독성·펜 입력·연결 방식을 현장에서 확인. 아래 촬영 장비 예산에 TV·전자칠판·펜 입력 도구 가격은 포함하지 않음 |
| 마이크 | 착용 송신기 1개 + PC에 연결할 수신기 1개 | USB 오디오 출력 지원, 수업 시간 이상 배터리, 물리적 음소거·연결 표시. 송신기만 파는 제품과 구분 |
| 고정·전원 | 거치대, 데이터 케이블, 전원 | 화면 옆 교사 설명 위치와 카메라 시선을 맞추고 상반신 동선을 확인. 매 수업 케이블을 다시 연결하지 않는 배치 |
| 네트워크 | 교실 PC 유선 LAN | 네 교실 동시 업로드 속도 실측. 스마트폰 무선 입력을 쓰면 가까운 5GHz AP와 별도 부하 시험 |

4교실이면 위 구성을 4세트로 복제한다. 처음에는 1세트를 실제 교실에서 한 수업 길이로 시험한 뒤 같은 구성으로 늘린다. 하드웨어 구매·인터넷·전기·저장공간까지 무료라는 뜻은 아니다. 특정 제품 구매나 유료 구독은 실행하지 않았다.

## 교재·전자판서 원본을 받는 세 가지 연결

기본 경로는 `PC 교재/판서 앱 → 교실 TV·전자칠판`과 `같은 앱의 창 캡처 → OBS`를 함께 사용하는 것이다. **교실 화면에는 교재·판서 원본을, 온라인 학생에게는 OBS 합성 화면을 보낸다.** PC의 확장 화면을 활용하고 교사 운영 모니터에 OBS를 둔다. OBS 합성 출력을 교실 화면에 띄운 뒤 그 화면을 다시 캡처하는 반복 화면은 만들지 않는다.

| 구성 | 교실에서 보고 쓰기 | OBS가 받는 화면 | 설치 전 확인 |
|---|---|---|---|
| TV + PC | PC 교재를 TV에 표시. 필기는 PC에 연결한 펜 태블릿 등 입력 도구로 PC 판서 앱에 작성 | 교재와 필기가 함께 들어 있는 PC 앱 창 | TV는 표시 장치이며 펜 입력 기능을 자동으로 갖는 것이 아님. 글씨 크기·입력 도구·교사 조작 동선을 확인 |
| 전자칠판 + PC 판서 앱 | PC 영상을 전자칠판에 표시하고 전자칠판의 터치 입력을 PC로 전달 | 필기를 포함한 PC 판서 앱 창 | HDMI 영상 연결과 모델에 맞는 USB 터치 연결, 또는 영상·터치를 모두 지원하는 USB-C 경로. HDMI 케이블만 연결하고 터치가 된다고 가정하지 않음 |
| 전자칠판 자체 OS/필기 앱 | 전자칠판 내부에서 교재·필기 실행 | 검증된 화면 공유 경로 또는 실제 영상 출력 → 캡처 장치 → PC/OBS | 모델별 HDMI OUT 등 영상 출력 존재, 자체 OS·필기·주석 레이어가 실제 출력되는지, 지연·해상도·오디오를 확인. PC 화면 캡처만으로 내부 필기가 잡힌다고 가정하지 않음 |

**HDMI IN은 화면이 영상을 받는 입력이고 HDMI OUT은 외부로 내보내는 출력이다.** TV·전자칠판에 HDMI 단자가 있다는 이유만으로 영상을 PC로 가져올 수 있는 것은 아니다. 전자칠판 출력을 받는 경우 PC의 영상 출력 단자에 다시 연결하지 않고 호환 캡처 장치 등 입력 경로를 설계한다. 전자칠판 위에 자체 도구로 얹은 주석은 PC 앱의 원본과 다를 수 있으므로, 실제 사용할 방식으로 쓰기·지우기·페이지 넘김을 수행해 온라인 화면까지 비교한다. [BenQ의 HDMI·터치·영상 출력 연결 예시](https://www.benq.com/en-us/education/user-manual/benq-board-interactive-displays/re04a-essential-series-board/basic-operations.html)는 한 모델의 예시이며 모든 전자칠판에 같은 출력 기능을 보장하지 않는다.

OBS는 **창 캡처를 우선**해 필요한 교재·판서 창만 받는다. 실제 앱의 펜·팝업·전체 화면 모드가 빠지거나 검게 나오면 캡처 방식을 바꿔 재시험하고, 전체 디스플레이 캡처가 필요할 때는 수업용 화면을 분리해 알림·OBS·다른 학생 정보를 제외한다. 앱 창이 바뀌거나 재실행될 때 올바른 창을 다시 잡는지도 확인한다. [OBS 창 캡처](https://obsproject.com/kb/window-capture-sources), [OBS 소스 안내](https://obsproject.com/kb/sources-guide)

현재 기본안은 첫 두 경로이며 TV와 전자칠판 중 제품·가격은 아직 확정하지 않았다. 전자칠판 자체 OS 방식은 전체 필기 출력 시험을 통과한 경우에만 채택한다.

## 반당 200만원 참고 견적 — 몽골 설치

사용자는 품질과 가성비를 함께 원한다. 새로운 촬영용 스마트폰을 사는 비용 대신 고정 USB 카메라·착용 마이크·유선 송출 PC·조명에 배분한다. 아래 표는 **2026-09-27 촬영·송출 장비의 참고 견적**을 보존한 것이다. 09-29의 디지털 원본+교사 합성 방향에서 카메라 거리는 교사 상반신 구도로 다시 정하며, 옛 칠판 앞2~3m 가정을 그대로 적용하지 않는다.

한국 판매 페이지의 가격을 2026-09-27 확인했다. 카메라·마이크는 표시 판매가, PC는 기본가와 옵션 추가금 합산이다. 부속은 확보 예산이고 실제 구매 견적이 아니다. 몽골 운송·통관·설치 견적은 미확정이며 아래 여유금으로 모두 충당된다고 보장하지 않는다.

PC는 다른 부품을 빠뜨리지 않은 비교 기준이다. 실제 구매는 몽골에서 같은 사양·정품 OS·현지 보증을 포함한 견적과 비교한다. 한국의 국내 A/S를 몽골 현장 A/S로 계산하지 않는다. 기존 PC가 있다면 하드웨어 인코더·포트·저장공간·연속 시험을 확인하고 재사용한다. 65~75만원의 16GB/1TB/정품 Windows 포함 신품 미니PC를 현재 구매 가능한 확정 상품으로 확인하지 못했으므로 그 금액을 판매가로 쓰지 않았다. RAM·SSD·OS 없는 베어본 가격과 완제품 가격을 섞지 않는다.

Tiny 2 Lite는 당시 확인한 참고 모델로 1/2인치 센서·4K30·2축 짐벌·4배 디지털줌을 지원한다. 처음에는 자동 추적·자동 줌·제스처·뷰티·배경 흐림을 끄고 **교사 얼굴·상반신이 보이는 설명 구역**을 고정한다. 교재·판서는 별도 디지털 소스이므로 카메라가 칠판까지 함께 담아야 하는 구성은 아니다. 4K 입력은 구도 조정과 1080p 축소에 활용할 수 있지만 PC 부하와 발음 장면의 얼굴 가독성을 먼저 시험한다. 새 방향에서 제품 선정이나 재견적을 완료한 것은 아니다. [공식 설명서](https://resource-cdn.obsbothk.com/download/obsbot-tiny-2-lite/manual/OBSBOTTiny2LiteUserManual_ENv1.1.pdf)

마이크 송신기는 한 개를 착용하고 다른 하나는 충전·교대용으로 둔다. Mini 2는 내부 녹음이 없으므로 OBS 로컬 녹화가 백업이다. 네 교실에서 동시에 켜서 끊김·교실별 연결·음량을 시험한다. 수신기를 PC에 USB로 연결하고 카메라 내장 마이크는 끈다.

### 예산이 절약됐을 때의 업그레이드

- **카메라: Insta360 Link 2 Pro**. 공식 사양 1/1.3인치 센서·4K30·수평화각 71.4도. 표준 번들 기본 표시 402,000원이며 공식 프로모션 링크에는 321,000원이 노출됐다. 조회 경로에 따라 표시가 달라 **32.1만원을 확정 결제 가격으로 쓰지 않는다**. 보수적으로 40.2만원을 잡으면 Tiny 2 Lite보다 133,000원 추가다. 새 방향에서는 교사 얼굴·입 모양·현장 조명에서의 차이를 비교하며 디지털 교재의 글씨 품질을 카메라 업그레이드 효과로 계산하지 않는다. [가격](https://store.insta360.com/kr/product/link-2-pro?c=6524&from=homepage), [공식 사양](https://www.insta360.com/product/insta360-link2-pro)
- **마이크: DJI Mic Mini 2S, 2 TX + 표준 RX + 케이스**. 표시가 229,000원으로 Mini 2보다 114,300원 추가다. 송신기 내부 녹음이 있어 무선 음성 누락 시 복구 자료를 남길 수 있다. 32bit float 설정과 내부 녹음을 실제로 켜야 하며, 이 음성 파일을 강의 영상에 자동 합치는 기능은 현재 도구에 없다. [가격](https://store.dji.com/kr/product/dji-mic-mini-2s?from=site-nav&set_region=KR&vid=241731), [공식 사용 안내](https://repair.dji.com/help/content?customId=01700043679&lang=en&paperDocType=ARTICLE&re=US&spaceId=17)

둘을 동시에 올리면 당시 신품 PC 견적 기준 소계가 2,091,000원으로 운송 전부터 목표를 넘는다. 기존 PC 재사용이나 현지 PC 견적으로 예산이 줄었을 때 업그레이드한다. 교실 거리 미정 상태에서 네 세트를 먼저 구매하지 않는다.

### 몽골 설치와 품질 확인

- 카메라는 교실 앞쪽에서 교사가 설명할 자리의 얼굴·상반신을 받도록 배치한다. TV·전자칠판과 교사의 위치를 먼저 정하고, 교사가 필기 뒤 학생·카메라 쪽으로 돌아 설명할 동선을 시험한다. 눈높이에 가까운 구도를 우선 검토하되 높이·거리·브래킷은 현장 시험 전 확정하지 않는다. 옛 천장 고정·칠판과 평면거리2.5m 위치는 현재 기본안이 아니다.
- **일반 칠판을 촬영해야 하는 대안**에서는 칠판 앞2~3m 가정을 별도로 시험한다. 교실 뒤4~6m에서만 찍을 수 있다면 디지털 줌으로 해결된다고 보지 않고 광학줌 PTZ·칠판 별도 카메라 등을 다시 검토한다. 이 대안은 기본 디지털 판서 화면에 자동으로 포함되지 않으며 카메라1대의 교사 구도와 동시에 만족한다고 보장하지 않는다.
- 가능한 한 PC도 카메라 근처에 두고 LAN을 길게 배선해 불필요하게 긴 USB 전송 구간을 줄인다. 긴 USB 케이블은 카메라의 실제 해상도에서 검증한다. 케이블이 끼이거나 학생 동선을 가리지 않는 고정 위치를 선택한다.
- 몽골 전원은 참고 자료상 220V/50Hz다. 전원 어댑터·UPS의 입력 표기와 실제 콘센트를 확인하고 현지 조명에서 카메라의 50Hz 플리커 방지 설정을 시험한다. 전원 규격만으로 모든 LED 조명의 깜빡임이 사라진다고 보지 않는다. [미국 상무부 전원 참고](https://legacy.trade.gov/mas/ian/ECW/mg.html)
- TV·전자칠판은 현장 학생의 반사·눈부심·뒷자리 가독성을 확인하고, 교사 얼굴은 별도 조명·커튼으로 맞춘다. 온라인 판서는 카메라 조명으로 개선하는 대신 원본 글씨·펜 굵기·배율을 조정한다. 강의 전체를 녹화하고 학생 휴대전화의 실제 YouTube 1080p 재생에서 디지털 글씨·교사 얼굴·음성·동기화를 판정한다.
- 구매 전에 실제 배송·세금·현지 설치·수리 조건을 합산한다. 1세트 시험 후 복제하며, 이번에 주문·결제·판매자 문의·장비 설치를 실행한 것은 아니다.

## 스마트폰을 사용하는 경우

스마트폰은 교사 얼굴·상반신 카메라 역할, PC는 교재 캡처·화면 합성·녹화·송출·자동 반영 역할을 맡는다. 후면 카메라를 가로로 고정하고 화면 방향과 구도를 고정한다. 수업 중 전화·알림·화면 잠금에 방해받지 않는 전용 기기를 사용하고 충전·발열·포커스 변화를 긴 시험에서 확인한다.

- **USB 웹캠 기능을 지원하는 Android**: USB 데이터 케이블 연결 → 휴대전화 USB 설정의 웹캠 선택 → OBS의 비디오 캡처 장치로 추가. Android 버전만으로 모든 기기에 지원되는 것은 아니다. [Android 공식 설명](https://source.android.com/docs/core/camera/webcam), [Pixel 설정](https://support.google.com/pixelcamera/answer/14274129?hl=en)
- **그 외 Android/iPhone**: 무료 [VDO.Ninja](https://docs.vdo.ninja/)에서 카메라를 공유하고 해당 OBS 링크를 브라우저 소스로 받는 경로가 있다. 링크와 비밀번호는 운영자만 보관하고 매번 공개 링크를 만들지 않는다. 기종·브라우저에 따라 잠금·네트워크·마이크 제약이 있어 실제 폰에서 확인한다. 계속 켜 둘 장비를 새로 산다면 유선 USB 카메라가 관리 단계를 줄일 수 있다는 것이 이번 구성의 판단이다.
- **폰의 YouTube 앱으로 직접 방송**도 가능하지만 구독자 50명 이상 등 모바일 조건이 있으며 현재 OBS 완료 이벤트·방송 준비 도구와는 다른 경로다. 50~999명 채널은 시청자 수 제한 가능성과 비공개 기본 아카이브도 확인해야 한다. 휴대폰 단독 방송을 이 자동화에 연결 완료했다고 보지 않는다. [공식 모바일 조건](https://support.google.com/youtube/answer/9228390?hl=en-gb)

## 마이크와 화면

`선생님 옷깃의 송신기 → 교실 전용 수신기 → PC USB → OBS 오디오 입력 캡처`

수신기는 PC에 고정한다. 휴대전화의 충전·영상 포트와 마이크 연결을 경쟁시키지 않는다. Bluetooth 직접 연결은 앱·OS별 지원 차이가 있으므로 기본안으로 쓰지 않는다. 예를 들어 [DJI의 공식 안내](https://www.dji.com/mic-mini/faq)도 Bluetooth 라이브 녹음의 호환성 조건을 명시한다. 이는 제품 선정 확정이 아니다.

1. 교실 번호를 마이크·수신기·충전 위치에 같은 색으로 표시한다. 교사가 이동하면 해당 교실의 이미 연결된 마이크를 착용한다.
2. 옷깃에 붙이고 머리를 돌리거나 칠판에 쓰면서 말해 본다. 옷 쓸림·음소거·배터리를 확인한다. 일상 발화 피크가 대략 −12~−6dBFS에 오게 조절하고 빨간 과부하가 생기지 않게 한다. 이 수치는 시작점이며 실제 청취로 조정한다.
3. OBS에서 핀마이크를 한 번만 입력한다. 카메라 내장 마이크·노트북 내장 마이크·중복 전역 입력은 끈다. 교재 듣기 음원은 앱 또는 캡처 장치 중 선택한 한 경로로만 받으며 같은 소리를 데스크톱 오디오에서도 중복 수집하지 않는다. 알림 소리는 제외한다. 교실 TV에서 재생되는 교재 소리가 핀마이크에 다시 들어가는지도 듣고 위치·스피커 음량을 조정한다. 교사 목소리를 TV로 모니터링해 되먹임이 생기는 구성은 피한다. [OBS 오디오 입력](https://obsproject.com/kb/audio-sources)
4. 폰 영상과 USB 마이크의 지연이 다를 수 있다. 박수 장면을 시험 녹화해 입 모양·소리가 맞도록 OBS 동기화 오프셋을 조정한다. 임의의 고정 보정값을 모든 기기에 적용하지 않는다.
5. 핀마이크는 선생님 음성을 위한 장비다. 교실 학생의 작은 질문은 선생님이 반복해서 말해 원격 학생에게 전달한다. 질문까지 직접 녹음해야 하면 별도 교실 마이크를 시험한다.
6. 교재·필기를 OBS 창 캡처로 받고 학생 휴대전화에서 최소 글씨·펜 선이 읽히는지 확인한다. 작은 교사 창은 글자·정답·자막을 가리지 않도록 교재의 빈 구역에 두거나 교사 전용 여백을 만든다. 세로 교재나 복잡한 표는 글씨를 억지로 줄이지 말고 확대·페이지 분할 또는 판서 전체 장면을 사용한다.

## OBS 설치 기준

색보정과 음성 정리를 기본값으로 저장해 라이브·녹화에 함께 적용하는 방법은 [실시간 보정 안내](실시간보정.md)를 따른다. 무료 내장 필터부터 사용하며 교실·장비를 실제로 본 뒤 수치를 맞춘다. 현재는 설정안이고 실장비 적용 전이다.

교실별 장면 모음에 다음 **3개 장면**을 둔다. 세 장면은 한 교실의 한 방송 안에서 전환하며 각각 새 방송을 만들지 않는다.

| 장면 | 온라인 화면 | 쓰는 때 |
|---|---|---|
| 기본 — 교재+교사 | 교재·전자판서 디지털 원본을 크게, 교사 상반신을 작은 사각형 창으로 배치 | 설명·문제 풀이. 교사 창의 위치는 내용과 겹치지 않게 정함 |
| 발음 — 교사 크게 | 교사 카메라를 크게 보여 얼굴·입 모양을 확인. 필요한 발음 표기만 남김 | 발음·입 모양·표정 설명 |
| 판서 전체 | 디지털 교재·판서를 전체 화면으로 표시하고 교사 창은 숨김. 교사 음성은 유지 | 작은 글씨·도표·전체 풀이 확인. 일반 칠판 촬영을 뜻하지 않음 |

- 교실마다 독립 OBS를 사용한다. 교재 창·교사 카메라·오디오를 소스로 만들고 다른 장면에서는 기존 소스를 참조해 재사용한다. 소스 위치를 잠그고 실제 운영자가 세 장면 선택과 기본 장면 복귀를 연습한다. OBS 장면 선택이나 설정한 단축키로 사람이 전환하며, 발음을 알아듣고 자동 전환하는 기능은 구현하지 않았다. 네 교실을 한 OBS 장면에서 전환하는 구성은 네 개의 동시 방송을 만들지 않는다. [OBS 소스 안내](https://obsproject.com/kb/sources-guide)
- 교사 카메라의 색보정·LUT는 **카메라 소스에만** 적용한다. 교재·판서 원본과 최종 합성 장면 전체에는 피부색용 필터를 적용하지 않는다. 세 장면 모두 같은 교사 마이크·교재 음원 경로를 유지해 화면 전환 때 음성이 빠지거나 두 번 들리지 않도록 한다.
- 1920×1080, 30fps, H.264 하드웨어 인코더, CBR 10,000Kbps, 키프레임 2초, AAC 128Kbps를 첫 시험값으로 쓴다. 현재 [YouTube 공식 인코더 안내](https://support.google.com/youtube/answer/2853702?hl=en)의 1080p30 H.264 권장값이다. 부족한 회선에서는 우선 720p30/4,000Kbps로 시험하고 칠판 가독성을 다시 판단한다.
- 교실마다 별개의 YouTube 재사용 스트림과 키를 저장한다. 같은 교실의 다음 반에는 같은 키를 사용하고 방송의 반·재생목록 매핑만 바꾼다. `verify`가 스트림 소유권·재사용 가능 여부·상태를 확인하며 방송 중에는 현재 입력과 health를 계속 확인한다. 키를 문서나 학생 화면에 넣지 않는다.
- 일반 → 출력의 **방송 시 자동 녹화**를 켜고 **방송 종료 후 녹화 유지**는 끈다. 정상 수업은 방송 시작·방송 종료가 로컬 녹화 시작·종료도 처리한다. [OBS 공식 옵션 원문](https://github.com/obsproject/obs-studio/blob/master/frontend/data/locale/en-US.ini)
- 녹화 형식 MKV, 녹화 인코더는 송출 인코더 공유로 시작한다. **자동 remux·자동 파일 분할은 끈다.** [OBS 녹화 안내](https://obsproject.com/kb/standard-recording-output-guide)
- [obs-completed.lua](obs-completed.lua)에 해당 교실의 고정 active JSON과 완료 폴더를 지정한다. 서버·인증·폴더 설정은 [README](README.md)를 따른다.
- 교실마다 자기 config·state·inbox·녹화 폴더와 worker를 둔다. 다른 PC의 `D:/...` 파일은 중앙 worker에서 읽을 수 없다. 한 중앙 worker로 통합하려면 공유 경로·접근 권한·완료 파일 전달을 별도로 검증해야 한다.

네 교실을 위 1080p 설정으로 보내면 영상·음성 합계 약 40.5Mbps다. 전송 여유 1.5~2배를 적용하면 약 61~81Mbps이며, 다른 사용량까지 고려해 **안정적인 실측 업로드 100Mbps 이상**을 초기 회선 목표로 삼는다. 광고상의 다운로드 속도가 아니다. 이는 [YouTube의 전송 여유 안내](https://support.google.com/youtube/answer/16404722?hl=en)를 네 스트림에 적용한 계산이다.

같은 비트레이트로 녹화하면 교실당 시간당 약 4.6GB, 하루 8시간 약 37GB, 4교실 약 146GB가 쌓인다. 저장기간은 별도 확정하며 도구는 원본을 자동 삭제하지 않는다.

`check CONFIG`는 폴더 존재·접근 권한과 녹화 디스크 여유를 읽기 전용으로 확인한다. 기본 **20GiB는 준비를 막을지 판단하는 잠정 안전선**이며 하루 8시간 보존 용량이 아니다. 실제 수업 길이·녹화량·백업 주기에 맞춰 `minimumFreeBytes`를 정하고 원본을 지우지 않은 상태로 여유를 확보한다. 자동 검사가 통과해도 실제 한 수업 길이의 녹화·재생·발열·전원 시험을 생략하지 않는다.

## 매 수업 운영

### 공간의 장비 자리와 안내 — 2026-10-01 설계 반영

[오프라인 방별 설계 §18~20](../../docs/오프라인_공간설계/방별_인테리어_디자인_20260929.md)의 교실별 장비 구역에 수신기·마이크 충전/보관·예비 케이블과 간단한 운영 카드를 모은다. PC/장비함은 열 배출과 손 접근을 남기고 가습기·급수 동선과 분리한다. 아래 안내는 실물 운영안이며 자동화 기능 추가가 아니다.

- 시작 카드: **로컬 check → 반 준비·비공개 초대 완료 → 마이크 연결/배터리 → 자료·필기 화면 → 기본 장면/음량 → 방송·녹화 상태 → 문 표시** 순서. `prepare/arm`도 사전검사를 하며 성공 전에는 방송·녹화를 시작하지 않는다. 자동 검사와 교사의 화면·청취 확인은 각각 필요하다.
- 종료 카드: **방송·녹화 실제 종료 → 문 표시 복귀 → 마이크 전원/충전 → 다음 반 준비** 순서. 충전기에 놓았다는 사실과 실제 충전 표시를 구분해 확인한다.
- 문에는 수업 상태와 촬영 상태를 구분해 표시한다. 초기안은 담당자가 실제 OBS 상태를 확인해 바꾸는 수동 표식이며, 예약 시간만으로 ‘녹화 중’을 자동 표시하지 않는다.
- 최종 퇴근 마감은 [방별 운영 §22](../../docs/오프라인_공간설계/방별_인테리어_디자인_20260929.md#22-직원-출근부터-퇴근까지--근무표와-공간을-연결)와 연결한다. 남은 학생/예약·사용 금지 장비·미완료 작업을 인계하고, 방송/녹화가 끝나도 업로드/백업 중이면 완료 확인 또는 다음 담당 인계 후 전원을 처리한다. 실제 장비별 ‘상시 유지 / 작업 완료 후 종료 / 퇴근 시 종료’ 라벨을 정해 일괄 차단을 피한다. 실제 무인 마감 자동화가 아니다.
- A의 수업/댄스 전환은 커튼·이동 TV·가구·케이블을 실제로 바꾸는 과정이다. 학생이 퇴실한 뒤 담당자가 전환하고, 실제16세트로 측정한 시간을 수업 사이에 확보한다. 조명이나 OBS 장면 버튼이 가구를 자동으로 바꾼다는 의미가 아니다.

| 담당/시점 | 동작 | 이후 자동 처리 |
|---|---|---|
| 운영자 / 수업 전 | `check`·`verify` 후 교실·반·수업 일시를 지정해 `prepare`. 성공 출력 확인. 비공개는 학생 계정 초대와 앱의 초대 확인도 완료 | 로컬 준비와 스트림 검사, 방송 생성, 해당 반 목록 연결, OBS가 읽을 교실 수업 파일 준비 |
| 선생님 / 시작 | 마이크 착용, 교재·필기 캡처와 기본 장면·음량 확인, OBS **방송 시작** | 라이브 시작, 로컬 녹화, 앱의 해당 반 라이브 상태 반영 |
| 선생님 / 수업 중 | 필요할 때 기본·발음·판서 전체 장면을 직접 전환 | 선택한 합성 화면을 같은 방송과 로컬 녹화에 반영 |
| 선생님 / 종료 | OBS **방송 종료**, 녹화 종료까지 확인, 마이크 충전 | YouTube 아카이브 처리, 처리 성공 후 앱에서 복습 제공. 로컬 파일은 백업 |
| 운영자 / 녹화만 할 수업 | `prepare` 대신 `arm`, OBS 녹화 시작·종료 | 파일이 닫힌 이벤트 후 백그라운드 업로드, 반별 목록·앱 반영 |

**교사가 매번 파일을 선택하거나 업로드 버튼을 누를 필요는 없다.** 다만 현재 도구가 시간표를 읽고 OBS를 무인 시작·종료시키는 것은 아니다. `prepare/arm` 성공 전에 시작하면 올바른 반 지정이 보장되지 않는다. worker와 준비 명령의 잠금이 겹쳐 준비 명령이 실패하면 완료를 확인하고 재실행한다. 하루치 무인 예약·교사용 원클릭 관리 화면은 미구현이다.

교실(room)은 카메라·마이크·스트림, 반(class)은 수강생·재생목록, 수업(session)은 특정 시간의 room+class 조합이다. 수업마다 방송을 나누되 수업 중에는 방송을 나누지 않는다. 이전 방송이 종료되었는지 확인하고 다음 반을 준비한다. 수업 시간은 12시간 미만으로 운영한다. 라이브의 자동 아카이브를 쓰므로 평상시에는 로컬 녹화 전체를 다시 업로드하지 않는다. [YouTube 아카이브](https://support.google.com/youtube/answer/6247592?hl=en)

### 송출·녹화 장애가 나면

1. 먼저 OBS와 YouTube Studio에서 실제 방송·녹화 상태를 확인하고 로컬 원본을 보존한다. 공개설정·교실 매핑·입력/health 이상은 앱 재생만 차단하며 수업의 진행 상태를 종결시키지 않는다. 정상으로 돌아오면 다음 성공 조회에서 차단이 해제된다. `status CONFIG --human`에 **동기화 일시정지**가 보이면 담당자가 서버·로컬·Studio의 반·수업·영상 연결을 대조해 충돌 원인을 해결한 뒤 `retry-sync CONFIG SESSION --confirmed-resolved`로 재개한다. 이 명령은 로컬 일시정지만 해제하므로 `once/watch`의 소유권 재확인·정상 동기화·서버 차단 해제까지 확인한다. 기록을 삭제하거나 순서를 초기화하지 않는다. 일시정지는 OBS 송출·녹화를 중지하지 않으며, 카메라 검은 화면·마이크 음소거는 health가 정상이어도 사람이 확인해야 한다.
2. `enableAutoStop`으로 YouTube 방송이 이미 종료됐으면 같은 수업을 다시 준비해 이어지는 것으로 보지 않는다. 기존 로컬 녹화도 정상 종료·완료 처리한 뒤 운영자가 새 `sessionKey`로 이어송출 방송을 준비한다. 새 영상의 비공개 학생 초대·앱 확인을 끝내고 새 입구를 안내한다. 자동 이어송출·학생 이동은 미구현이다.
3. 녹화 완료 파일 등록에 실패했으면 다음 수업을 시작하지 않는다. 원본과 `.in-use`를 확인해 올바른 수업으로 수동 `seal`하고 점유 파일을 보관한 뒤 **OBS 스크립트를 재로드**한다. 그다음 새 수업을 `prepare/arm`한다. 정상 완료 파일에는 예정 시간이 아닌 OBS의 실제 녹화 시작·종료 시각이 들어간다. 완료 폴더 오류가 사라졌다고 다음 녹화를 이전 수업의 완료로 대신 등록하지 않는다.
4. 아카이브와 로컬 녹화의 처음·중간·끝, 장애 전후 구간을 직접 보고 들어 전체 수업인지 판단한다. 파일이 나뉘면 모두 보존한다. 파일 병합·누락 복원은 자동화되어 있지 않다. 완본 파일이 준비되면 종료된 `processing/ready/failed` live 수업에 `replace-replay CONFIG SESSION RECORDING --confirmed-complete`를 사용하고 `once/watch`의 업로드·처리 결과를 확인한다. 기존 `seal ... --fallback`은 `failed` 전용으로 유지한다.
5. 완본은 새 영상이므로 학생 Google 계정을 다시 초대하고 앱의 초대 확인을 다시 완료한다. 실제 학생 계정으로 처음·중간·끝을 재생해 확인할 때까지 원본과 기존 아카이브를 보존한다.

## 무료 보호 방식의 남는 수동 작업

기본은 비공개다. 초대한 Google 계정만 재생하지만 **매 수업 영상에 학생 초대가 필요**하고 영상당 최대 50개 이메일이다. 반별 목록에 한 번 초대해 모든 새 영상을 자동 허용하는 기능은 없다. 공식 API로 초대를 자동화할 수 없으므로 4교실×교시 수만큼 운영 작업이 남는다. [YouTube 비공개 안내](https://support.google.com/youtube/answer/9230970?hl=en)

일부공개를 선택하면 수업별 초대 없이 자동 제공할 수 있지만 외부로 공유된 링크의 재생을 막을 수 없다. 사용자가 무료 보호를 선호했으므로 일부공개로 임의 전환하지 않는다. 자동 업로드와 수강생만 재생되는 권한 관리의 자동화는 별개다.

TOPIK 4급 온라인 반(10-19 다시 열기, 교실 하나·원격 학생만)에 비공개를 그대로 쓰면 남는 사람 손은 수업마다 두 번이다. Studio에서 그 영상에 수강생 계정을 초대하고, `private_access_confirmed_at` 확인 SQL을 실행한다. 8주 한 기수면 8번이고, 이어송출·완본 교체로 영상 ID가 바뀌면 그 영상만큼 다시 한다. 초대를 화면 자동 조작으로 대신하는 길은 Studio 화면이 바뀔 때마다 깨지고 채널 계정 로그인을 PC에 두어야 해서 쓰지 않는다. 사람 손을 없애는 길은 일부공개로 바꾸는 것뿐이다. 이는 위의 「무료 보호」 선택을 바꾸는 일이라 유호님이 정한다([트랙 §1](../../docs/_ops/트랙.md#1-유호님-차례--한곳에-모음)).

## 실제 운영 전 통과할 시험

한 교실에서 최소 실제 한 수업 길이로 화면·소리·발열·전원·PC 부하를 확인한 뒤, 네 교실 동시 시험을 한다. 실제 장비 확보 후 수행할 항목이며 현재 통과한 것으로 보지 않는다.

1. TV+PC 또는 전자칠판의 실제 연결에서 교재·필기·지우기·페이지 넘김을 실행한다. 전자칠판 자체 주석을 쓰면 그 레이어도 온라인 영상에 들어오는지 확인한다. 교실 화면과 온라인 합성 화면의 분리, 재연결·앱 재실행 후 캡처 복귀를 확인한다.
2. 외부 인터넷에 연결한 학생 폰에서 기본·발음·판서 전체 세 장면의 글씨·입 모양·가림·교사 음성·교재 소리·동기화·라이브 되감기를 확인한다. 장면 전환으로 음성이 끊기거나 중복되지 않는지도 듣는다.
3. 네 교실이 서로 다른 화면·목소리·반 목록에 도착하는지 확인한다. 같은 교실에서 A반 종료→B반 시작을 실행해 A반 영상이 B반 목록에 섞이지 않는지 확인한다.
4. 종료 후 같은 영상으로 처음·중간·끝 복습, 초대 계정 재생·미초대 차단을 확인한다. 녹화 전용 수업의 자동 업로드도 별도 확인한다.
5. 인터넷 단절·OBS 종료·마이크 배터리 부족을 시험한다. 라이브 자동 종료가 작동하면 짧게 잘린 영상도 YouTube에서 처리 성공할 수 있다. **완전성 판단과 교체 시작은 운영자 책임이며 자동 판정·자동 이어송출은 없다.** 새 세션 준비·학생 초대·완본 검토·명시적 `replace-replay`·새 영상 재초대까지 실제 흐름으로 확인한다. `--fallback`은 failed 상태만 허용하며 ready에 억지로 적용하지 않는다. 완료 폴더 쓰기 실패 뒤 다음 녹화가 다른 반에 연결되지 않는지, 수동 복구·스크립트 재로드 뒤 새 반이 정상 등록되는지도 실기기에서 확인한다.
6. PC 재부팅 후 worker·OBS·카메라 복귀, 기록 폴더 여유, 백업 재생을 확인한다. 실파일과 실제 학생 계정의 확인 전까지는 설치 완료로 보고하지 않는다.
7. 같은 학생 계정으로 SYNK WORLD에서도 확인한다. 웹 synk.im/world와 PC 설치본 0.4.32 이상에서 내 계정 시트의 「우리 반 수업」을 연다.
   - 방송을 켜고 동기화가 들어오면 「지금 수업 중」과 「실시간 수업 보기」가 나타난다. 이 단추가 유튜브를 여는지 본다(PC는 시스템 브라우저).
   - 끝난 뒤에는 「복습 영상 준비 중」을 거쳐 「다시 보기」·「복습하기」로 바뀐다.
   - 비공개 영상은 초대 확인 전까지 「학생 계정 초대 준비 중」에 머문다.
   - 이용권을 거두면 30초 안에 「아직 연결된 수업이 없어요」로 바뀐다. 반을 연결하지 않은 계정은 처음부터 이 안내만 보인다.
   - 10-20까지 확인한 것은 운영 classroom 함수의 synk.im 출처 사전 요청(204)과 토큰 없는 요청의 `AUTH_REQUIRED` 응답, PC 설치본 0.4.32 안의 수업 경로·링크 허용 코드뿐이다.
